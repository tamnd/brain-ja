#1. CPython とは

CPython は、Python プログラミング言語の主要な実装です。これは、Python を python.org、パッケージ マネージャー、Linux ディストリビューション、Homebrew、pyenv、Docker イメージ、またはほとんどのクラウド ランタイムからインストールするときにほとんどの人が使用する実装です。

CPython には 2 つの役割があります。

まず、Python 言語を実装します。これは、Python ソース コードがどのように解析、コンパイル、実行され、標準ライブラリに接続されるかを定義します。

2 番目に、Python エコシステムの実用的な参照ポイントとして機能します。他の実装は言語仕様に従う場合がありますが、CPython は、ほとんどのパッケージ、ツール、デバッガー、プロファイラー、および C 拡張機能がテストされる実装です。

CPython ソース ツリーには、インタープリター、コンパイラー、オブジェクト システム、ランタイム、C API、標準ライブラリ、テスト スイート、ドキュメント、およびビルド機構が含まれています。公式開発者ガイドでは、CPython を、ソース ツリーで維持される内部ドキュメントを持つ変化するコード ベースとして説明しています。 ([Python 開発者ガイド][1])

## 1.1 言語としての Python と実装としての CPython

言語はPythonです。

CPython はその言語の実装の 1 つです。

Python 言語では、構文、名前、式、ステートメント、オブジェクト、モジュール、例外、反復、非同期動作、インポートなどの目に見える動作が記述されるため、この区別は重要です。

CPython では、その動作を実際のマシンで実行する具体的な方法の 1 つについて説明します。

次のような Python プログラム:```python
def add(a, b):
    return a + b

print(add(2, 3))
```言語レベルの Python です。言語は私たちにそれを伝えます`def`関数オブジェクトを作成します。`return`値を返します。`+`加算セマンティクスを呼び出し、`print`テキスト表現を書き込みます。

CPython は、下位レベルのメカニズムを通じてこれらの操作を実装します。```text
source text
    ↓
tokens
    ↓
parser
    ↓
abstract syntax tree
    ↓
symbol table
    ↓
code object
    ↓
bytecode
    ↓
evaluation loop
    ↓
object operations
    ↓
C functions and machine code
```プログラマは通常、このパイプラインの先頭だけを見ます。 CPython 開発者はパイプライン全体で作業します。

## 1.2 CPython はコンパイラでもありインタプリタでもあります

CPython はインタプリタと呼ばれることがよくあります。それは正しいですが、不完全です。

CPython は、まず Python ソース コードをバイトコードにコンパイルします。次に、そのバイトコードを解釈します。

コンパイル段階では、通常の事前コンパイラの意味でのネイティブ マシン コードは生成されません。それは生成します`code`バイトコード命令、定数、名前、変数レイアウト情報、例外テーブル、行番号情報、ランタイムに必要なメタデータを含むオブジェクト。

次のようなファイル:```python
x = 10
y = 20
print(x + y)
```は、おおよそ次のような形式のバイトコードに変換されます。```text
load constant 10
store name x
load constant 20
store name y
load name print
load name x
load name y
binary add
call
```実際のバイトコードは Python のバージョンによって異なりますが、モデルは変わりません。CPython はソース コードをコンパクトな命令ストリームに落とし込み、そのストリームを仮想マシンで実行します。

バイトコードを検査するには、`dis`:

```python
import dis

def add(a, b):
    return a + b

dis.dis(add)
```これにより、CPython の実行モデルを Python レベルで見ることができます。

## 1.3 CPython 仮想マシン

CPython 仮想マシンは、スタックベースのバイトコード インタープリターです。

ほとんどのバイトコード命令は評価スタック上で動作します。命令は、値のプッシュ、値のポップ、関数の呼び出し、コンテナーの作成、分岐、例外の発生、結果の返しを行います。

たとえば、以下を評価します。```python
a + b
```ロードするには CPython が必要です`a`、 負荷`b`、バイナリ加算を適用します。概念的には:```text
LOAD_FAST a      push local variable a
LOAD_FAST b      push local variable b
BINARY_OP +      pop two values, add them, push result
```このスタックマシンは現在実行中のフレーム内に存在します。フレームには、関数呼び出しの実行状態 (ローカル変数、値スタック、命令ポインター、コード オブジェクト、グローバル、組み込み、例外状態) が格納されます。

実行時に、CPython はこのパターンを繰り返し実行します。```text
fetch next bytecode instruction
decode instruction and operand
dispatch to implementation
operate on Python objects
update frame state
continue or return
```コア インタプリタ ループは、CPython の最も重要な部分の 1 つです。バイトコードをオブジェクトの動作に結び付けます。

## 1.4 CPython は主に C と Python で書かれています

CPython は主に C で実装されており、標準ライブラリには大量の Python コードが含まれています。

C コードはコア ランタイムを実装します。```text
object representation
reference counting
garbage collector
interpreter loop
compiler
parser support
built-in types
C API
threading primitives
import machinery support
memory allocators
```Python コードは、標準ライブラリの大部分を実装しています。```text
collections
pathlib
asyncio
typing
unittest
importlib portions
dataclasses
logging
email
venv
many utility modules
```一部のモジュールには Python と C の両方が実装されています。通常、C バージョンはパフォーマンスのために使用されますが、Python バージョンは明確さ、移植性、テスト、またはフォールバック動作のために存在する場合があります。

この混合デザインが重要です。 CPython は、Python ファイルを実行する単なる C プログラムではありません。これは、C レベルと Python レベルのコンポーネントが連携するランタイムです。

## 1.5 CPython はメモリ内のオブジェクト モデルを定義します

Python のすべての値はオブジェクトです。

CPython では、すべてのオブジェクトは C レベルのオブジェクト ヘッダーで始まります。少なくとも、そのヘッダーには参照カウントとオブジェクトの型へのポインターが格納されます。

概念的には:```c
typedef struct {
    Py_ssize_t ob_refcnt;
    PyTypeObject *ob_type;
} PyObject;
```可変サイズのオブジェクトでは、より大きなヘッダーが使用されます。```c
typedef struct {
    PyObject ob_base;
    Py_ssize_t ob_size;
} PyVarObject;
```これは、Python の整数、文字列、リスト、タプル、関数、クラス、モジュール、例外、フレーム、ジェネレーターはすべて型ポインターを持つことを意味します。タイプ オブジェクトは、オブジェクトがサポートする操作を記述します。

例えば：```python
x = 42
```Python 整数オブジェクトを作成または参照します。 CPython は保存しません`x`通常の Python コードの生の CPU 整数として。への参照を保存します。`PyLongObject`。

この違いにより、Python の多くの動作が説明されます。```python
x = 42
y = x
```ここ、`x`そして`y`同じオブジェクトを参照します。割り当ては名前をオブジェクトにバインドします。デフォルトではオブジェクトはコピーされません。

## 1.6 型もオブジェクトです

CPython では、型もオブジェクトです。

表現:```python
type(42)
```を表すオブジェクトを返します`int`。

式:```python
type(int)
```返品`type`。

これは単なる言語トリックではありません。 CPython は次を使用して型を表します`PyTypeObject`、型メタデータとスロットと呼ばれる関数ポインターを格納する大きな C 構造体。

type オブジェクトは次のような質問に答えます。```text
How large is each instance?
How should instances be deallocated?
How is attribute lookup performed?
How is the object called?
How does addition work?
How does indexing work?
How does iteration work?
How is the object represented as text?
```リストの場合、型オブジェクトはリスト固有の実装を指します。

dict の場合は、dict 固有の実装を指します。

ユーザー定義クラスの場合、CPython は型オブジェクトを動的に構築します。

これが、Python のデータ モデルが CPython の内部構造にきれいにマッピングされる理由です。などの方法`__len__`、`__getitem__`、`__call__`、`__iter__`、 そして`__add__`内部操作スロットに対応します。

## 1.7 名前は参照です

Python 変数はオブジェクトにバインドされた名前です。

CPython は参照を通じてこれを実装します。

Python の場合:```python
a = [1, 2, 3]
b = a
b.append(4)
print(a)
```出力は次のとおりです。```text
[1, 2, 3, 4]
```両方`a`そして`b`同じリストオブジェクトを参照します。

CPython レベルでは、割り当ては`b = a`リストオブジェクトの参照カウントをインクリメントします。リストは複製されません。

このモデルはパフォーマンスと正確性に影響します。リストを関数に渡すと、オブジェクトへの参照が渡されます。```python
def push(xs):
    xs.append(4)

items = [1, 2, 3]
push(items)
```関数は同じリストへの別の参照を受け取ります。

## 1.8 参照カウントは主要なメモリ管理メカニズムです

CPython は主に参照カウントを使用してオブジェクトを再利用します。

各オブジェクトは、それを指す強参照の数を記録します。カウントがゼロに達すると、CPython はオブジェクトの割り当てを直ちに解除します。 Python のドキュメントでは、ガベージ コレクターは参照カウントの補足として、主に到達不能な参照サイクルを検出するために説明されています。 ([Python ドキュメント][2])

概念的には:```text
create object         refcount = 1
bind another name     refcount += 1
delete a name         refcount -= 1
refcount reaches 0    destroy object
```例：```python
x = []
y = x
del x
del y
```リストはその後も存続します`del x`なぜなら`y`今でもそれを指します。後`del y`、参照カウントがゼロになる可能性があるため、CPython はリストを解放できます。

参照カウントにより、多くの場合、CPython でオブジェクトの終了が予測可能になります。たとえば、ファイル オブジェクトは、最後の参照が消えるとすぐに閉じることがあります。ただし、参照カウントだけではサイクルを処理できません。```python
a = []
b = []
a.append(b)
b.append(a)
```ここ、`a`そして`b`お互いを参照します。外部の名前がそれらを指していなくても、それらの参照カウントはゼロ以外のままである可​​能性があります。 CPython の循環ガベージ コレクターは、そのようなサイクルを見つけてクリーンアップするために存在します。サイクルに参加できるコンテナー タイプには、明示的な GC サポートが必要です。 ([Python ドキュメント][3])

## 1.9 CPython には循環ガベージ コレクターがあります

循環ガベージ コレクターは、相互に参照しているがライブ プログラム ルートからは到達できないオブジェクトのグループを処理します。

主にコンテナ オブジェクト (参照を含むリスト、辞書、セット、タプル、関数、クラス、フレーム、および他のオブジェクトを指すことができるその他のオブジェクト) を追跡します。

多くの整数や文字列などのアトミック オブジェクトには、他の Python オブジェクトへの参照が含まれていないため、通常、循環 GC 追跡は必要ありません。

コレクターは参照カウントと並行して動作します。```text
reference counting handles most objects immediately
cyclic GC handles unreachable reference cycles
```このハイブリッド設計により、CPython の動作が形成されます。メモリは多くの場合すぐに解放されますが、一部の循環構造は後で収集されます。

の`gc`モジュールはこの機構の一部を公開します。```python
import gc

gc.collect()
print(gc.get_count())
print(gc.isenabled())
```このモジュールは、オブジェクトの有効期間、リーク、ファイナライザー、およびサイクル動作を調査する場合に役立ちます。

## 1.10 CPython はグローバル インタプリタ ロックを使用します

従来の CPython は、通常 GIL と呼ばれるグローバル インタプリタ ロックを使用します。

GIL では、1 つのインタープリター内で Python バイトコードを実行できるのは、一度に 1 つのスレッドのみです。これにより、メモリ管理が簡素化され、内部インタープリタの状態、特に参照カウントの更新が保護されます。

これは、CPython がスレッドを使用できないという意味ではありません。これは、CPU バウンドの Python バイトコードが、通常、同じインタープリター内の複数の OS スレッド間で並行して実行されないことを意味します。

スレッドは引き続き次の用途に役立ちます。```text
I/O-bound programs
network clients
file operations
concurrent waiting
C extensions that release the GIL
```CPU に依存した並列処理の場合、Python プログラムでは次のものがよく使用されます。```text
multiprocessing
native extensions
vectorized libraries
subinterpreters in newer designs
free-threaded builds in modern CPython work
```GIL は、言語レベルの影響を伴う実装の詳細です。 Python レベルで同時実行されているように見えるコードは、バイトコードの実行中にシリアル化される場合があります。

## 1.11 CPython にはパブリック C API があります

CPython は、拡張モジュールと埋め込み用の C API を公開します。

これは CPython の最も重要なエコシステム機能の 1 つです。 NumPy、pandas、lxml、暗号化、Pillow などのライブラリ、および多くのデータベース ドライバーは、ネイティブ拡張メカニズムに依存しています。

最小限の拡張関数が受け取る可能性があるのは、`PyObject *`値、引数を解析し、C コードを呼び出し、新しい値を返します。`PyObject *`。

この境界では、参照の所有権が重要です。 CPython は、借用された参照、新しい参照、盗まれた参照を区別します。所有権の処理が正しくないと、メモリ リーク、解放後の使用のバグ、クラッシュ、インタープリタ状態の破損が発生する可能性があります。

概念の例:```text
Py_INCREF     take another strong reference
Py_DECREF     release a strong reference
Py_XDECREF    release if pointer may be NULL
PyObject      base object pointer
PyTypeObject  type object structure
PyModuleDef   extension module definition
```C API は CPython を非常に拡張可能にしますが、エコシステムの多くを CPython のオブジェクト表現と実行時の動作に結び付けます。

## 1.12 CPython は Python のセマンティクスと同じではありません

一部の CPython 動作は実装の詳細です。

たとえば、参照カウントによるオブジェクトの即時破棄は CPython の動作です。 Python コードは通常、言語またはコンテキスト マネージャーによって動作が明示的に保証されていない限り、正確な破棄タイミングに依存することを避ける必要があります。

これは移植可能です:```python
with open("data.txt") as f:
    data = f.read()
```これはタイミングにおいて CPython 固有です。```python
f = open("data.txt")
data = f.read()
f = None
```CPython では、代入`None`最後の参照を削除すると、ファイルがすぐに閉じられることがあります。別の Python 実装では、クリーンアップが後で行われる場合があります。

優れた CPython 内部リーダーは、次の 3 つのレイヤーを常に分離する必要があります。

|レイヤー |例 |安定性 |
| ----------------------- | -------------------------------------- | ---------------------------------- |
|言語意味論 |`for`ループは反復プロトコルを呼び出します。非常に安定しています |
| CPython の動作 |オブジェクトは参照カウントを使用します。安定しているが実装に固有 |
| CPython の内部レイアウト |正確な構造体フィールドとバイトコード オペコード |バージョン間で変更可能 |

## 1.13 CPython およびその他の Python 実装

CPython だけが Python 実装ではありません。

一般的な代替案は次のとおりです。

|実装 |ランタイムベース |主な違い |
| -------------- | ------------ | -------------------------------------------------------------- |
| CPython | C |リファレンス実装と最強の C 拡張互換性 |
|ピピ | RPython | JIT 指向の実装 |
|ジソン | JVM | Java プラットフォーム上の Python |
|アイアンパイソン | .NET | .NET ランタイム上の Python |
|マイクロパイソン | C |マイクロコントローラーと制約のあるデバイス用の Python サブセット |

ほとんどの Python ユーザーは CPython を実行します。ほとんどの Python パッケージは、最初に CPython でテストされます。ほとんどのネイティブ拡張ライブラリは CPython の C API をターゲットとしています。

これにより、言語として Python を学習する場合でも CPython が中心となります。

## 1.14 CPython が実行する内容

CPython はソース テキストを直接実行しません。

コードオブジェクトを実行します。

コード オブジェクトには、コンパイルされたバイトコードとメタデータが含まれます。```text
bytecode instruction stream
constants
names
local variable names
free variables
cell variables
argument counts
stack size
filename
function name
line number table
exception table
flags
```関数のコード オブジェクトを検査できます。```python
def f(x):
    y = x + 1
    return y

code = f.__code__

print(code.co_name)
print(code.co_varnames)
print(code.co_consts)
print(code.co_names)
```関数オブジェクトは、コード オブジェクトを実行時コンテキストとともにラップします。```text
code object
globals dictionary
defaults
keyword defaults
closure cells
annotations
qualname
module
```この区別が重要です。同じコード オブジェクトを、さまざまな関数オブジェクト、グローバル、デフォルト、またはクロージャで再利用できます。

## 1.15 CPython の主な実行ユニット

実行中の CPython プロセスには、いくつかの重要な実行ユニットが含まれています。

|単位 |意味 |
| ------------ | -------------------------------------------------------------------------------- |
|プロセス | CPython を実行しているオペレーティング システム プロセス |
|ランタイム |グローバル CPython ランタイム状態 |
|通訳 |モジュール、組み込み、インポート状態、および実行コンテキストを含むインタープリター状態 |
|スレッドの状態 |スレッドごとの実行状態 |
|フレーム | 1 つのアクティブな関数/モジュール/クラスの実行 |
|コードオブジェクト |コンパイルされたバイトコードとメタデータ |
|オブジェクト |バイトコードによって操作されるランタイム値 |

単純な関数呼び出しでフレームを作成または再利用します。そのフレームはコード オブジェクトを実行します。フレームはスレッド状態に属します。スレッドの状態はインタープリタに属します。インタプリタはランタイムに属します。

概念的には:```text
CPython process
    runtime
        interpreter
            thread state
                frame
                    code object
                    value stack
                    locals
```この階層は CPython C コード全体に現れます。

## 1.16 CPython の標準ライブラリは実装の一部です

実際には、標準ライブラリは CPython から分離されていません。

などのモジュール`sys`、`types`、`gc`、`inspect`、`dis`、`importlib`、 そして`ctypes`ランタイムの内部構造を公開または操作します。

例:```python
import sys
print(sys.getrefcount(object()))

import dis
dis.dis(lambda x: x + 1)

import gc
print(gc.get_objects())

import inspect
print(inspect.currentframe())
```一部のモジュールは純粋な Python です。 C で実装されているものもあれば、両方を使用しているものもあります。

インタプリタと標準ライブラリ間の境界は、意図的に実用的なものになっています。 CPython では、必要に応じて低レベルの操作を C で実行し、可能な場合は高レベルのオーケストレーションを Python で実行します。

## 1.17 CPython には大規模なテストスイートがある

CPython には大規模な回帰テスト スイートが含まれています。

テスト スイートにはいくつかの目的があります。```text
protect language behavior
protect standard library behavior
catch platform-specific bugs
test C API behavior
test compiler and parser behavior
test memory management behavior
test edge cases from historical bugs

## 1.19 本書の残りの部分のメンタルモデル

CPython ソース コードを読むときにこのモデルを使用します。```text
Python code is compiled into code objects.
Code objects contain bytecode.
Frames execute code objects.
The evaluation loop executes bytecode instructions.
Bytecode instructions manipulate PyObject pointers.
Objects point to type objects.
Type objects define behavior through slots.
Memory is managed mainly through reference counts.
The cyclic GC cleans up unreachable cycles.
The C API exposes much of this machinery to extensions.
```このモデルは、ほぼすべての CPython サブシステムを方向付けるのに十分です。

## 1.20 章の概要

CPython は Python の主要な実装です。 Python ソース コードをバイトコードにコンパイルし、そのバイトコードをスタック ベースの仮想マシンで実行し、すべてのランタイム値をオブジェクトとして表し、主に参照カウントを通じてメモリを管理し、循環ガベージ コレクションでそれを補完し、強力な C API を公開します。

この本の残りの部分では、CPython を具体的なシステム (コンパイラ、仮想マシン、オブジェクト ランタイム、メモリ マネージャー、拡張プラットフォーム、および標準ライブラリの実装) として扱います。
