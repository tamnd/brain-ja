## 11.4 停止問題

 **停止問題**は、チューリング マシンが最終的に停止するかどうかを尋ねます。 

機械を与えられた$M$そして入力された単語$w$、私たちは尋ねます：$$
\text{Does } M \text{ halt on input } w?
$$ここでの「停止」は、次のような計算が最終的に停止状態に達することを意味します。$$
q_{\mathrm{accept}}
$$または：$$
q_{\mathrm{reject}}
$$もし$M$有限回のステップを経て、これらの状態のいずれかに到達すると、$M$止まる$w$。 計算が永遠に続く場合、$M$止まらない$w$。 

### 停止する言語

 停止問題を言語として定義できます。$$
\mathrm{HALT}_{\mathrm{TM}}
===========================
{\langle M,w\rangle : M \text{ halts on input } w}
$$入力はエンコーディングです。$$
\langle M,w\rangle
$$どこ$M$チューリングマシンであり、$w$は入力単語です。 

問題は、このエンコードされたペアが次のものに属するかどうかです。$\mathrm{HALT}_{\mathrm{TM}}$。 

### 認識可能だが決定不可能

 停止の問題は**認識可能**です。 

を認識するチューリングマシンがあります$\mathrm{HALT}_{\mathrm{TM}}$:

 1.与えられた$\langle M,w\rangle$、シミュレートする$M$の上$w$。 
2. もし$M$停止、受け入れます。 
3. もし$M$永遠に実行され、永遠にシミュレーションを続けます。 

したがって、陽性のケースが見つかる可能性があります。 もし$M$本当に停止しますが、シミュレーションは最終的にそれを確認します。 

しかし、問題はネガティブなケースです。 もし$M$が実行され続けると、安全に次のように言える有限の瞬間は存在しないかもしれません。$$
M \text{ will never halt}
$$主定理によれば、すべてのマシンと入力に対してこれを解決できるアルゴリズムは存在しません。 

### 定理

 以下を決定するチューリングマシンはありません。$$
\mathrm{HALT}_{\mathrm{TM}}
$$同様に、任意のマシンが任意の入力で停止するかどうかを常に判断できるアルゴリズムもありません。 

決定者になるためには、マシンはすべての入力で停止し、正しく答える必要があります。 

| ケース | 正解 |
 | ------------------------ | -------------- |
 |$M$止まる$w$| 受け入れる |
 |$M$止まらない$w$| 拒否 |

 定理は、そのような決定者は存在しないと言っています。 

### アイデアの証明

 矛盾しますが、決定者があると仮定します。$$
H
$$停止問題については。 

それから$H$入力を受け取ります:$$
\langle M,w\rangle
$$そしていつも止まってしまう。 

それは次のように答えます。$$
H(\langle M,w\rangle)=
\begin{cases}
\mathrm{accept}, & \text{if } M \text{ halts on } w,\
\mathrm{reject}, & \text{if } M \text{ does not halt on } w.
\end{cases}
$$今度は新しいマシンを構築します$D$それは使用します$H$サブルーチンとして。 

入力時$\langle M\rangle$、機械$D$これを行います:

 1. 走る$H$の上$\langle M,\langle M\rangle\rangle$。 
2. もし$H$そう言う$M$独自のコードで停止し、永久にループします。 
3. もし$H$そう言う$M$独自のコードで停止せず、その後停止します。 

それで$D$何に対して反対に行動するか$H$自己申請について予測します。 

記号の場合:$$
D(\langle M\rangle)=
\begin{cases}
\text{loop forever}, & \text{if } H(\langle M,\langle M\rangle\rangle)=\mathrm{accept},\
\text{halt}, & \text{if } H(\langle M,\langle M\rangle\rangle)=\mathrm{reject}.
\end{cases}
$$さあ、いつ何が起こるかを尋ねてください$D$独自のコードで実行されます。$$
D(\langle D\rangle)
$$2つのケースがあります。 

まず、仮定します$D$止まる$\langle D\rangle$。 

それから$H$そう言わなければなりません$D$止まる$\langle D\rangle$。 

しかし、の定義によれば、$D$、 もし$H$そう言うと、$D$永遠にループします。 

矛盾。 

次に、次のように仮定します。$D$止まらない$\langle D\rangle$。 

それから$H$そう言わなければなりません$D$止まらない$\langle D\rangle$。 

しかし、の定義によれば、$D$、 もし$H$そう言うと、$D$停止します。 

また矛盾。 

どちらの可能性も矛盾につながります。 したがって、想定される決定者は$H$存在できない。 

### 証明で使用されるもの

 この証明は、以前の 2 つのアイデアに基づいています。 

まず、マシンは文字列としてエンコードできます。$$
\langle M\rangle
$$2 番目に、マシンは別のマシンのエンコードでも、それ自体のエンコードでも実行できます。$$
M(\langle M\rangle)
$$これにより自己言及が可能になります。 

矛盾はデザインから生まれる$D$同意しない$H$特別な入力について:$$
\langle D\rangle
$$これは対角線上の議論です。 これはカントールの対角証明と精神的に似ていますが、計算に適用されます。 

### 結果の意味

 停止問題は、特定のプログラムが停止することを決して証明できないというわけではありません。 

多くの特定のプログラムを分析できます。 たとえば、有限リストに対する単純なループを含むプログラムは明らかに停止します。 

この定理は、より強力かつ正確なことを示しています。$$
\text{There is no single algorithm that works for all programs and all inputs.}
$$したがって、障害はローカルではなくグローバルに発生します。 

いくつかの個別のマシンの場合$M$そして入力$w$、私たちはそれを証明するかもしれません$M$停止するか、停止しないことを証明する。 しかし、これを常に自動的に実行できる普遍的な決定手順はありません。 

### プログラム解析との関連

 停止問題は、完璧なプログラム解析が不可能である理由を説明します。 

ツールは多くの無限ループを検出する可能性がありますが、常に正しい答えを返しながらすべてを検出することはできません。 

コンパイラは多くのプログラムが終了することを証明することはできますが、すべての終了プログラムの終了を証明したり、すべての非終了プログラムを拒否したりすることはできません。 

これは現在のテクノロジーの制限ではありません。 それは数学的な限界です。 

### 受け入れるか停止するか

 関連する 2 つの質問を区別すると便利です。 

受け入れ問題では次のことが問われます。$$
\text{Does } M \text{ accept } w?
$$停止問題では次のことが問われます。$$
\text{Does } M \text{ halt on } w?
$$マシンは、承認または拒否することによって停止する場合があります。 したがって、停止することは受け入れることよりも広い意味を持ちます。 

言語は次のとおりです。$$
A_{\mathrm{TM}}
===============
{\langle M,w\rangle : M \text{ accepts } w}
$$そして$$
\mathrm{HALT}_{\mathrm{TM}}
===========================
{\langle M,w\rangle : M \text{ halts on } w}
$$どちらも決定不可能な中心的な問題です。 

停止した問題は、計算の境界を示します。 質問によっては、明確に尋ねることができ、正確にエンコードできても、アルゴリズムによる解決策がまだありません。
