## 3.5 インターフェースとしての表記法

 表記は飾りではありません。 それはアイデアと推論の間のインターフェイスです。 適切に設計された記譜法は、構造を明らかにし、無関係な詳細を隠し、構成をサポートします。 

インターフェースは 3 つの質問に答えます。 

| 質問 | 表記の役割 |
 | ---------------------------- | -------------------------------------- |
 | オブジェクトとは何ですか? | 名前、記号、種類 |
 | どのような操作が許可されますか? | 関数の適用、代数演算子 |
 | どのようなプロパティが表示されますか? | 等式、関係、不変式 |

 表記法が有効な場合、各ステップで定義を再取得することなく式を操作できます。 

### 1. データと操作

 構造は多くの場合、データと操作として表現されます。 表記では両方を明示する必要があります。 

関数の場合:$$
f : X \to Y
$$表記は名前、ドメイン、およびコドメインを示します。 書き込み$f(x)$応用を表します。 

二項演算の場合:$$
\ast : G \times G \to G
$$中置記法$a \ast b$よりも優先されます$\ast(a,b)$それは代数の使用を反映しており、連鎖をサポートしているためです。$$
a \ast b \ast c
$$結合性により括弧を省略できます。 

### 2. 構成

 優れた記譜法は作曲を直接サポートします。 

関数の場合:$$
(g \circ f)(x) = g(f(x))
$$この表記法により、合成が連想的に行われます。$$
h \circ (g \circ f) = (h \circ g) \circ f
$$多くの状況において、合成は主要な操作です。 この表記法により、チェーン接続が簡単かつ明確になるはずです。 

代数では:$$
a \cdot b \cdot c
$$行列の場合:$$
ABC
$$カテゴリでは、構成は記号なし、または記号付きで書かれることがよくあります。$\circ$、透明度に応じて。 

### 3. 表現の隠蔽

 インターフェイスは内部表現を隠します。 たとえば、ベクトル空間要素は次のように記述できます。$v \in V$座標タプルとしてではなく。 これにより、根拠に依存しない推論が可能になります。 

座標形式:$$
v = (x_1, x_2, \dots, x_n)
$$抽象的な形式:$$
v \in V
$$抽象表記は座標を隠し、線形性などの構造を明らかにします。$$
T(\lambda v + w) = \lambda T(v) + T(w)
$$これにより、基準が変更されても結果が不変になります。 

### 4. 不変条件の公開

 表記では、許可された変換の下で変更されないプロパティを強調表示する必要があります。 

たとえば、固有値を次のように書きます。$$
\lambda \in \operatorname{Spec}(T)
$$線形演算子に依存することを強調します$T$、特定の行列表現ではありません。 

同様に、次のように書きます。$$
|x|
$$ノルムは座標を公開せずに大きさを強調するためです。 

| 表記法 | 露出されたコンセプト |
 | ------------------------ | ------------------ |
 |$\det(A)$| ボリュームスケーリング |
 |$\operatorname{rank}(A)$| 画像の寸法 |
 |$\ker(T)$| 空白 |
 |$\operatorname{Im}(T)$| 画像 |

 これらの表記は、構造に対するクエリとして機能します。 

### 5. オーバーロードとポリモーフィズム

 数学的表記は意図的にオーバーロードされています。 同じ記号が異なるタイプに適用される場合があります。$$
a + b,\quad u + v,\quad f + g
$$操作はコンテキストによって異なります。 これはプログラミングにおけるポリモーフィズムに似ています。 リーダーは型から正しい操作を推測します。 

オーバーロードは次の場合に機能します。 

* 操作は重要なプロパティを共有します
 * タイプは文脈から明らかです
 ※表現に曖昧さは生じません

 混合型が強制なしで出現する場合、または複数の解釈が可能な場合は失敗します。 

### 6. 強制と暗黙の変換

 数学では、関連するオブジェクト間の暗黙的な変換が許可されることがよくあります。$$
3 \in \mathbb{Z} \subset \mathbb{Q} \subset \mathbb{R}
$$同じシンボル$3$構造全体で再利用されます。 これにより表記のオーバーヘッドが軽減されますが、読み手が埋め込みを理解することに依存します。 

より明示的なバージョンでは次のように区別されます。$$
3_{\mathbb{Z}},\quad 3_{\mathbb{Q}},\quad 3_{\mathbb{R}}
$$このような詳細は、曖昧さが問題にならない限り、通常は抑制されます。 

### 7. 階層化された記譜法

 複雑なシステムは階層化された表記の恩恵を受けます。 下位層はプリミティブを定義します。 上位層は抽象化を構築します。 

例:

 | レイヤー | 表記法 |
 | ---------- | ------------------------ |
 | 要素 |$x \in X$|
 | 機能 |$f : X \to Y$|
 | オペレーター |$T(v)$|
 | 家族 |$(x_i)_{i \in I}$|
 | 集計 |$\sum_i x_i,\ \prod_i x_i$|

 各レイヤーは前のレイヤーの上に構築されます。 

階層化により、局所的な推論が可能になります。 必要な場合を除き、要素ごとの演算に拡張することなく、合計のレベルで作業できます。 

### 8. インターフェースとしての図

 図は、関係をエンコードする表記形式です。 

可換図は組成の等価性を表現します。 地図用$f, g, h, k$:$$
k \circ f = h \circ g
$$図は、この方程式を視覚的なレイアウトに置き換えます。 ダイアグラムは構成を可視化するインターフェースです。 

図は、複数の構成が相互作用する場合に特に効果的です。 

### 9. 書き換え時の安定性

 表記法は代数操作をサポートする必要があります。 式は、既知のルールを使用して簡単に書き換えられる必要があります。 

例えば：$$
(a+b)^2 = a^2 + 2ab + b^2
$$この表記法では、展開、因数分解、置換がサポートされています。 

表記が冗長すぎると書き直すのが難しくなります。 圧縮しすぎるとルールが不明確になってしまいます。 

優れたインターフェイスでは、ローカルな変換が可能です。 

### 10. 設計ガイドライン

 | ガイドライン | 目的 |
 | ---------------------- | ------------------------- |
 | ご使用前にご紹介 | 未定義のシンボルを避ける |
 | ドメインをアタッチして | と入力します。 無効な式を防ぐ |
 | 標準の記号を使用する | 認知的負荷を軽減する |
 | 無関係な詳細を隠す | 構造に焦点を当てる |
 | 不変条件を公開する | 一般的な推論をサポート |
 | サポート構成 | チェーンを有効にする |
 | スコープをローカルに保つ | シンボルの競合を避ける |
 | 安定した名前を好む | 読みやすさの向上 |

 ### 11. 例: 線形マップ

 ベクトル空間間の線形マップを考えてみましょう。 

私たちはこう書きます：$$
T : V \to W
$$応用：$$
T(v)
$$構成：$$
(S \circ T)(v) = S(T(v))
$$カーネルとイメージ:$$
\ker(T),\quad \operatorname{Im}(T)
$$これらの表記法は小さなインターフェイスを形成します。 次のようなステートメントが許可されます。 

*$T$場合によっては単射です$\ker(T) = {0}$*$T$全射的です$\operatorname{Im}(T) = W$座標は必要ありません。 この表記は、必要な構造を正確に示しています。 

### 12. 表記と考え方

 表記法は推論を形作ります。 表記が不十分だと、読者は無関係な詳細を追跡することになります。 適切な表記法により、意図した操作が自然になります。 

数学は表記法を改良することで進歩します。 新しいシンボル、慣例、および図表システムは、多くの場合、既存の理論を単純化します。 

実際的なルール: 証明に従うのが難しい場合、問題は論理ではなく表記にある可能性があります。 表記法を再設計すると、引数を透明にすることができます。 

記法は数学の作業面です。 そこではアイデアが操作され、比較され、構成されます。 適切に設計された記法は、安定したインターフェイスのように動作します。つまり、最小限で表現力があり、それが表す構造と一致しています。
