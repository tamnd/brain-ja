## 3.2 公式言語と非公式言語

 数学では公式言語と非公式言語の両方が使用されます。 形式的な言語は正確さを与えます。 カジュアルな言葉遣いが読みやすさをもたらします。 優れた数学テキストは通常​​、これらを組み合わせたものです。 

形式言語には正確な構文があります。 どの式が有効であるか、およびステートメントがどのように形成されるかを指定します。 たとえば、一次論理には、変数、量指定子、述語、接続詞、および形成規則があります。```text
∀x (P(x) → Q(x))
```この表現は形式的なものです。 その構造は明白です。 数量指定子はバインドします`x`。 含意は 2 つの述語を接続します。 意味は解釈によって異なりますが、構文は固定されています。 

非公式な数学的言語は、書籍、論文、講義、メモなどで使用される言語です。 普通の散文と記号が混在しています。```text
Every continuous function on a compact interval is bounded.
```この文は非公式ですが、正確な数学的内容を含んでいます。 完全に正式な設定では、ドメイン、コドメイン、トポロジー、連続性の定義、および有界性の定義を指定します。 

| 言語 | 強さ | コスト |
 | ------------------- | ------------------------- | -------------------- |
 | フォーマル | 正確かつ確認可能 | 詳細 |
 | 非公式 | 読みやすく効率的 | 慣例に依存する |
 | 構造化された非公式 | 人間にとって十分な精度 | 規律が必要 |

 ほとんどの数学は構造化された非公式言語で書かれています。 これは完全に正式なものではありませんが、定義、表記法、証明基準によって制約されます。 

定理の完全に正式なバージョンは、教科書バージョンよりもはるかに長くなる場合があります。 例えば：```text
If f is continuous on [a,b], then f is bounded.
```形式化されたバージョンでは、実数、間隔、関数、連続性、順序、コンパクト性または完全性、および有界性をエンコードする必要があります。 非公式な文は、共有された数学的コンテキストを使用してこれらすべてを圧縮します。 

この圧縮は便利です。 これにより、読者は主要なアイデアに集中できます。 しかし、圧縮すると仮定が隠れてしまう可能性があります。 

| カジュアルなフレーズ | 隠されたコンテキスト |
 | ----------------- | -------------------------------------------------- |
 |`f is continuous`| ドメイン、コドメイン、トポロジ |
 |`G is simple`| グループ？ グラフ？ モジュール？ |
 |`x is small`| 何の境界と比較して? |
 |`almost all`| 有限の例外？ 対策1? 確率は1？ |
 |`canonical`| どのような普遍的な性質や慣習によって定義されていますか? |

 隠された文脈によって発言の真実が変わると、くだけた言葉は危険になります。 

例えば：```text
Every polynomial has a root.
```これは実数では偽ですが、複素数では非定数多項式の場合は真実です。 ステートメントにはフィールドが必要です。 

より良い：```text
Every nonconstant polynomial over C has a root in C.
```改良版ではアンビエント構造が記載されています。 

形式言語は、すべてのオブジェクトを定義されたコンテキストに強制的に組み込むことで、この曖昧さを回避します。 校正アシスタントはこれを厳密に行います。 用語にはタイプが必要です。 定理ではすべての仮定を述べなければなりません。 証明には有効なルールを使用する必要があります。 

非公式数学は読者の推論に依存します。 これは、聴衆が慣習を共有している場合に効率的です。 規約が不明確な場合は失敗します。 

優れた数学的文章は、推論負荷を適切なものにします。 すべての基本的な詳細を記述する必要はありませんが、結果に影響を与えるすべての仮定を記述する必要があります。 

貧しい：```text
The function has an inverse.
```より良い：```text
The function f : X → Y has an inverse because it is bijective.
```さらに良いのは、構造が重要な場合です。```text
The continuous bijection f : X → Y has a continuous inverse, since X is compact and Y is Hausdorff.
```最終バージョンには、トポロジカルな結論に必要な仮定が含まれています。 

公式言語と非公式言語では、証明のスタイルも異なります。 

正式な証明は、一連の有効な推論ステップです。 各ステップは、規則、公理、定義、または以前に証明された定理によって正当化される必要があります。 

非公式な証明は、訓練された読者向けに書かれた議論です。 日常的な手順を省略したり、いくつかの論理的な動きを組み合わせたり、「明確に」、「構造的に」、「一般性を失わずに」などのフレーズを使用したりする場合があります。 

これらのフレーズは慎重に使用する必要があります。 

| フレーズ | | の場合に許容されます。 リスク |
 | ------------------------ | ------------------------------------------------ | ------------------------------ |
 | 明らかに | ステップは本当に即時です | 難しい議論を隠す |
 | 構造による | オブジェクトはプロパティ | を満たすように定義されました。 工事により保証できない場合がございます。 
| 一般性を失うことなく | 対称性または縮小は明示的です | ケースを誤って破棄する可能性があります。 
| 次のようになります | 前の結果が直接適用されます | 前提条件が欠落している |
 | 正規 | 選択は自然かつ不変です。 任意の選択肢が隠される可能性がある |

 非公式証明はデフォルトで弱いわけではありません。 それは異なる表現です。 省略されたすべてのステップが復元可能であれば、よく書かれた非公式証明は厳密になります。 

重要な基準は再構築可能性です。 有能な読者がその意味を変えることなく正式な証明に拡張できる場合、証明は受け入れられます。 

| 標準 | 質問 |
 | ------------- | ------------------------------------------ |
 | 地元の意味 | すべてのシンボルは近くで定義されていますか? |
 | 仮定 | 必要な仮説が述べられていますか? |
 | 推論 | それぞれのステップは正当化できるでしょうか? |
 | 範囲 | 変数とケースは制御されていますか? |
 | 拡張 | 原理的に証明は形式化できるのでしょうか？ |

 形式化は、エッジケースをチェックするのに役立ちます。 これにより、ドメイン、強制、平等、終了、依存関係の明示的な処理が強制されます。 非公式エラーの多くは、タイプ エラーや前提条件の欠落です。 

たとえば、証明ではマップを定義できます。```text
f : A → B
```でも後で申請する`f`外側の要素に`A`。 非公式な表記ではこれが隠れている可能性があります。 正式なシステムはそれを拒否します。 

同様に、証明では除算を使用することもできます。`x`証明せずに`x ≠ 0`。 正式な証明には欠落条件が必要です。 

カジュアルな文章を書く場合には、この規律を活用する必要があります。 操作を使用する前に、操作が定義されていることを確認してください。 定理を援用する前に、その仮説を確認してください。 一意性を主張する前に、等価関係を指定してください。 

最高の数学言語はレベル間を移動します。 

| レベル | 例 | 使用 |
 | -------- | ---------------------------------- | ---------------- |
 | 散文 | 「地図は距離を保ちます。」 | アイデアを説明します |
 | 象徴的な |`d(f(x), f(y)) = d(x,y)`| 状態のプロパティ |
 | フォーマル | 証明アシスタントでの定理の入力 | チェックを有効にします |

 これらのレベルは相互にサポートし合う必要があります。 その理由を散文で説明します。 記号は何を表しますか。 形式化はどのようにチェックしますか。 

便利な書き方のパターンは次のとおりです。```text
Introduce the objects.
State the claim.
Give the idea.
Write the proof.
Record the dependencies.
```例えば：```text
Let V be a finite-dimensional vector space over a field k, and let T : V → V be linear. We show that T has an invariant subspace under the stated hypotheses. The idea is to use the factorization of the characteristic polynomial. ...
```このスタイルは、シンボリック操作を開始する前に十分な構造を提供します。 

数学的言語は、あいまいさが意味を変える場合には形式的であるべきであり、形式的な詳細が議論を曖昧にする場合には非公式であるべきです。 精度と読みやすさは敵ではありません。 これらは、同じ設計問題に対する 2 つの制約です。
