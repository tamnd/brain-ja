## 3.3 定義と命名規則

 定義では、固定された意味を持つ新しい用語が導入されます。 パターンを再利用可能な思考の対象に変えます。 定義がなければ、数学は体系ではなく、繰り返される記述の集合になってしまいます。 

適切な定義には 3 つの効果があります。 

| 機能 | 意味 |
 | ----------------------- | --------------------------------------------------- |
 | コンセプトに名前を付けます | コンセプトに安定したハンドルを与える |
 | 正確な条件を示します。 用語がいつ適用されるかを指定します |
 | 再利用をサポート | 概念を定理と証明に表示できるようにします。 

例えば：```text
A function f : X → Y is injective if for all x1, x2 ∈ X,
f(x1) = f(x2) implies x1 = x2.
```この定義はプロパティに名前を付けます。 導入後は、次のように書くことができます。`f`毎回完全な条件を繰り返すのではなく、単射的であること。 

定義はローカル契約です。 用語を定義したら、その後の使用はすべて契約を尊重する必要があります。 定義が変われば、それに依存する定理も変わる可能性があります。 

数学的定義は通常、次の形式になります。```text
An object X is called [name] if it satisfies [conditions].
```または：```text
We say that X has property P if [conditions].
```条件は必要かつ十分でなければなりません。 読者は、オブジェクトが定義を満たすかどうかを判断できる必要があります。 

貧しい：```text
A good function is one that behaves nicely.
```より良い：```text
A function f : X → Y between metric spaces is continuous at x ∈ X
if for every ε > 0 there exists δ > 0 such that
d_X(x,y) < δ implies d_Y(f(x), f(y)) < ε.
```改良された定義によりテストが行​​われます。 オブジェクト、量指定子、および入力と出力の関係を指定します。 

定義では、条件の前にコンテキストを記述する必要があります。 「連続関数」という表現は、計量空間、位相空間、順序理論、領域理論ではさまざまなものを意味します。 明確な定義により、アンビエント構造に名前が付けられます。 

| 用語 | 必要なコンテキスト |
 | ---------- | -------------------------------------- |
 | 連続 | トポロジまたはメトリック |
 | シンプル | グループ、グラフ、モジュール、代数 |
 | 通常 | サブグループ、拡張子、演算子、スペース |
 | レギュラー | グラフ、言語、メジャー、スキーム |
 | 完了 | 計量空間、格子、理論、カテゴリ |

 数学は名前を再利用します。 これはコンテキストが明確な場合には効率的ですが、そうでない場合には混乱を招きます。 「普通」という言葉にはさまざまな意味があります。 通常の部分群、通常の演算子、および通常の位相空間は異なる概念です。 

命名規則により曖昧さが軽減されます。 特定の種類の名前は、特定の役割を示します。 

| フォーム | 一般的な使用法 |
 | ---------- | ----------------------------------------------- |
 |`-ness`| プロパティ: コンパクトさ、接続性 |
 |`-ity`| 特性: 連続性、直線性 |
 |`-ism`| 視点: 構成主義、形式主義 |
 |`-ization`| プロセス: 完成、ローカリゼーション |
 |`co-`| 二重概念: 余積、コリミット |
 |`pre-`| 弱い予備概念: プレオーダー、プレシーフ |
 |`semi-`| 部分的な弱化: セミグループ、セミリング |
 |`quasi-`| 近似または弱化された形式 |
 |`pseudo-`| 同様の表面挙動、より弱い構造 |

 これらのパターンは正式なルールではありませんが、読者が概念間の関係を推測するのに役立ちます。 

定義は広すぎても狭すぎてもいけません。 範囲が広すぎると、有用な定理をサポートしないオブジェクトが取り込まれてしまいます。 狭すぎる場合は、自然な例が除外されます。 

たとえば、グループの定義は、加算対象の整数、可逆行列、順列、対称性を含むほど広範です。 これは、恒等、逆群、部分群、および準同型性に関する強力な定理をサポートするのに十分狭いものです。 

有用な定義は、後の結果に必要な正確な構造を特定します。 

| 定義スタイル | 結果 |
 | ---------------- | -------------------------------------- |
 | 具体的すぎる | 定理は一般化できない |
 | 抽象的すぎる | 例が認識しにくくなる |
 | よく選ばれました | 定理は広く意味のある形で適用されます。 

定義は平等性も制御します。 数学的オブジェクトを定義するときは、何が同じオブジェクトとしてカウントされるかを知っておく必要があります。 

たとえば、グラフは次のように定義できます。```text
G = (V, E)
```どこ`V`は頂点の集合であり、`E`エッジのセットです。 ただし、頂点名が異なる 2 つのグラフは、構造的には同じである可能性があります。 これはグラフの同型性をもたらします。 

定義は生のオブジェクトを与えます。 等価性の概念は、それらを分類する方法を教えてくれます。 

適切な定義では、マップが公開されることがよくあります。 多くの分野では、構造を保持するマップが自然なものが正しい定義となります。 

| 構造 | 構造保存マップ |
 | ----------------- | ------------------------------------------ |
 | グループ | 準同型性 |
 | リング | リング準同型 |
 | ベクトル空間 | 線形マップ |
 | 位相空間 | 連続マップ |
 | メートル空間 | 非拡張マップ、連続マップ、または等角マップ |
 | カテゴリー | ファンクター |

 マップは、定義が何を保持するように設計されているかを明らかにします。 

定義は明示的または暗黙的である場合があります。 

明示的な定義は直接的な条件を与えます。```text
A group is a set G with a binary operation satisfying associativity,
identity, and inverse laws.
```暗黙的な定義は、オブジェクトのクラスを特徴付ける公理を与えます。```text
A field is a structure satisfying the field axioms.
```実際には、ほとんどの数学的定義は両方を組み合わせています。 データを説明し、法律をリストします。```text
A ring consists of a set R with operations + and * such that ...
```この「データと法律」の形式が一般的です。 

| パート | 例 |
 | --------------- | -------------------------------------- |
 | データ | セット`R`、操作`+`そして`*`|
 | 法律 | 結合性、分配性、恒等性 |
 | 派生概念 | 単位、理想、モジュール |
 | 地図 | 環準同型性 | 環準同型性

 定義では隠れた選択肢を避ける必要があります。 オブジェクトが選択に依存する場合、定義でそのように示す必要があります。 

たとえば、「次の基準を選択してください」`V`” では非標準データが導入されています。選択した基準に依存する結果は、本質的にはそうではない可能性があります。`V`。 基礎から独立した結果は構造的なものです。 

「標準的」のような用語は、構造が与えられたデータによって自然に決定される場合にのみ使用する必要があります。 複数の選択肢が可能な場合、その構造は標準的ではなく、「選択された」、「固定された」、または「選択された」と呼ばれるべきです。 

定義には例と非例も必要です。 定義は、読者が定義を満たしているものと満たしていないものを区別できる場合に使用可能になります。 

「グループ」の場合:

 | オブジェクト | グループ？ | 理由 |
 | -------------------------------------- | --------- | -------------------------------------- |
 | 加算中の整数 | はい | 連想、アイデンティティ`0`、逆数 |
 | 加算される自然数 | いいえ | 加法逆関数はありません |
 | 乗算時のゼロ以外の実数 | はい | 連想、アイデンティティ`1`、逆数 |
 | 乗算中の行列 | 時々 | 可逆正方行列がグループを形成する |

 非例は、どの条件が重要かを示すため重要です。 

定義は、意図した操作の下で安定している必要があります。 オブジェクトのクラスが有用である場合、多くの場合、それは自然な構造の下で閉じられるべきです。 

たとえば、グループのサブグループはグループです。 グループの積はグループです。 グループの同型コピーはグループです。 これらのクロージャ プロパティにより、定義が堅牢になります。 

定義のための実践的なチェックリスト:

 | 質問 | 目的 |
 | ---------------------------------- | ----------------------------- |
 | どのようなデータが必要ですか? | オブジェクトを識別します |
 | どのような法律が必要ですか? | 構造を修正します |
 | それを満たす例は何ですか? | 関連性を示す |
 | 失敗する非例は何ですか? | 境界を示す |
 | どの地図がそれを保存しているのでしょうか? | 自然な変換を示します |
 | どのような等価関係が適用されますか? | 分類をサポート |
 | 後のどの定理でそれが使用されますか? | 有用性をテストする |

 命名も同じ規律に従う必要があります。 名前は短く、安定しており、可能な限り既存の規則に沿ったものにする必要があります。 新しい名前は、繰り返しの説明を減らす場合、または頻繁に使用される概念を特定する場合にのみ導入する必要があります。 

悪い名前は構造を隠します。 適切な名前は、オブジェクトの役割を示します。 

| 弱い名前 | より良い名前 |
 | ------------- | ----------------------------------- |
 | 嬉しい機能 | 連続関数 |
 | 良いセット | コンパクトセット |
 | スペシャルマップ | プロジェクションマップ |
 | もの | オブジェクト、要素、射、演算子 |
 | 大きな財産 | 完全性、境界性、密度 |

 数学的記述では、定義はインフラストラクチャです。 定理以前の飾りではありません。 それらは定理が何を意味するかを決定します。 

強力な定義は曖昧さを最小限に抑え、例をサポートし、構造を明らかにし、後の推論を短くします。
