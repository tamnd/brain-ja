 # 数学的分析

 重要な観察は、これは基本的に **最短パス/残りの BFS** 問題であるということです。 

---

 ## 1. 条件を再定式化する

 数字を考えてみましょう$x$数字のみを使用する$0,1,2$。 

私たちが望んでいるのは:$$x \equiv 0 \pmod n.$$巨大な整数を直接構築する代わりに、モジュロを計算します。$n$。 

現在余りがある数値がある場合$r$、次に数字を追加します$d\in\{0,1,2\}$新しい剰余を生成します$$r'=(10r+d)\bmod n.$$したがって、各剰余はグラフ内のノードになります。 

- 頂点:$0,1,\dots,n-1$、
 - エッジ:$$r \to (10r+d)\bmod n,\qquad d\in\{0,1,2\}.$$**最小の 10 進数** (辞書順/長さ順) を求め、剰余に達します。$0$。 

---

 ## 2. BFS が最小値を与える理由

 幅優先検索では、次の方法で州を探索します。 

1. 最短の長さが最初に、
 2. 同じ長さ内で、桁順。 

注文に数字をエンキューする場合$$0,1,2,$$から始めた後$1$そして$2$、初めて残りに達したとき$0$まさに最小の有効な数値が得られます。 

これが機能するのは、10 進比較が以下と同等であるためです。 

1. 桁数が少ない、
 2. 同じ長さの数の中で辞書編集的に小さい。 

---

 ## 3. 数値の再構築

 BFS 中に次のものを保存します。 

- 前回の残り、
 - 追加される数字。 

それから残りのとき$0$に達すると、バックトラックして 10 進数の文字列を再構築します。 

ついに：$$\frac{f(n)}{n}$$は整数なので、直接計算して合計します。 

---

 # Pythonの実装```python
from collections import deque

def quotient(n):
    """
    Returns f(n) / n, where f(n) is the smallest positive
    multiple of n using only digits 0,1,2.
    """

    # Special case
    if n == 1:
        return 1

    # parent[r] = previous remainder used to reach r
    # digit[r]  = digit appended to reach r
    parent = [-2] * n
    digit = [''] * n

    q = deque()

    # Starting numbers: 1 and 2
    for d in [1, 2]:
        r = d % n

        if parent[r] == -2:
            parent[r] = -1
            digit[r] = str(d)
            q.append(r)

    # BFS over remainders
    while q:
        r = q.popleft()

        # Found divisible number
        if r == 0:
            break

        # Append digits 0,1,2
        for d in [0, 1, 2]:
            nr = (10 * r + d) % n

            if parent[nr] == -2:
                parent[nr] = r
                digit[nr] = str(d)
                q.append(nr)

    # Reconstruct the minimal number
    chars = []
    cur = 0

    while cur != -1:
        chars.append(digit[cur])
        cur = parent[cur]

    s = ''.join(reversed(chars))

    # Return f(n)/n
    return int(s) // n

# Compute the required sum
total = sum(quotient(n) for n in range(1, 10001))

print(total)
```---

 ## これが効率的な理由

 それぞれについて$n$:

 - あるだけです$n$可能な残り、
 - 残りの部分はそれぞれ 1 回ずつアクセスされます。 
- 各訪問では 3 桁の数字が試行されます。 

したがって、複雑さはおよそ次のようになります。$$O(n)$$の値ごとに$n$。 

のために$n\le 10000$、これは快適に高速に実行されます。
