 ## 解決策

 **答え:**`56098610614277014`させて$G(n)=1+G\bigl(n-G(G(n-1))\bigr)$Golomb シーケンスの標準再発であること (次の場合に有効)$n>1$）、 と$G(1)=1$。 

計算したい$$\sum_{1 \le n < 10^6} G(n^3).$$課題は、$n^3$ほぼ到達する$10^{18}$したがって、そのインデックスまでのシーケンスを直接生成することは不可能です。 

## 1. 数学的分析

 ### ステップ 1: ゴロム数列を理解する

 定義プロパティは次のように述べています。 

> 整数$k$正確に表示されます$G(k)$回。 

それで、もし$G(k)=4$、次に値$k$シーケンス内で 4 回発生します。 

累積エンドポイント関数を定義する$$S(k)=\sum_{i=1}^{k} G(i).$$それから：

-$k$地位を占める$$S(k-1)+1,\dots,S(k),$$- したがって$$G(n)=k \quad\Longleftrightarrow\quad S(k-1)<n\le S(k).$$だからコンピューティング$G(n^3)$最初のものを見つけることに帰着する$k$と$$S(k)\ge n^3.$$---

 ### ステップ 2: 以下の生成を避ける$10^{18}$単純なアプローチでは、すべてを計算してしまいます。$S(k)$それまで$10^{18}$、しかしそれには約$10^{11}$価値観 — 不可能です。 

重要な所見は次のとおりです。 

もし$G(r)=L$、次に値$r$正確に起こる$L$指数の中での倍$k$。 

つまり、**ブロック**全体が存在するということです。$L$連続した$k$-値$$G(k)=r.$$そのブロック内:

 -$S(k)$ちょうど増加します$r$それぞれのステップ、
 - したがって、累積値は等差数列を形成します。 

したがって、1つのブロックではなくブロック全体を一度に処理できます。$k$一度に。 

以来$G(r)$数百万程度までしか増加しないため、$G(r)$必要なサイズまで完全に実現可能です。 

---

 ### ステップ 3: 効率的なブロック処理

 次のブロックにいるとします。 

-$G(k)=r$、
 - ブロックの長さは$L=G(r)$。 

それから：$$S(k)$$の増分で進みます$r$。 

ブロックの前に累積和がすでにわかっている場合は、次のようにします。$S_0$、ブロックの終わりは$$S_0 + Lr.$$キューブの場合$c=n^3$この範囲内の正しいインデックスは次のとおりです。$$k = k_0 + \left\lceil \frac{c-S_0}{r} \right\rceil,$$どこ$k_0$ブロックが開始される前のインデックスです。 

しかないので、$999{,}999$立方体であれば、それらを一度掃引することができます。

 ## 2. Python の実装```python
def solve(limit=10**6):
    """
    Compute:
        sum(G(n^3)) for 1 <= n < limit
    where G is Golomb's self-describing sequence.
    """

    # Golomb values, 1-indexed
    G = [0, 1]  # G(1) = 1

    total = 0

    # Current cube pointer: n^3
    n = 1
    cube = 1

    # We have already processed k = 1
    # S(1) = 1
    current_k = 1
    current_S = 1

    # Handle cubes <= S(1)
    while n < limit and cube <= 1:
        total += 1
        n += 1
        cube = n**3

    r = 2

    while n < limit:
        # Generate G(r)
        g_r = 1 + G[r - G[G[r - 1]]]
        G.append(g_r)

        # This block has length G(r)
        block_length = g_r

        # End of cumulative range for this block
        block_end_S = current_S + block_length * r

        # Process all cubes that fall in this block
        while n < limit and cube <= block_end_S:
            # Ceiling division:
            # j = ceil((cube - current_S) / r)
            j = (cube - current_S + r - 1) // r

            # Corresponding k-value
            total += current_k + j

            n += 1
            cube = n**3

        # Move to next block
        current_k += block_length
        current_S = block_end_S
        r += 1

    return total

# Verification checks
print(solve(1000))     # should be 153506976
print(solve(10**6))
```---

 ## 3. コードのチュートリアル

 ### Golomb 値の構築```python
g_r = 1 + G[r - G[G[r - 1]]]
```これは古典的な Golomb の繰り返しです。$$G(r) = 1 + G(r - G(G(r-1))).$$必要な数の用語のみが生成されます。 

---

 ### 処理ブロック

 もし$G(r)=L$、次に値$r$繰り返す$L$連続するインデックス間の時間$k$。 

すべてを繰り返すのではなく、$k$、ブロック全体を処理します。```python
block_end_S = current_S + block_length * r
```ステップごとに増えていくので$S(k)$まさに$r$。 

---

 ### キューブが着地する場所を見つける

 もし$c=n^3$現在のブロックにあります:```python
j = (cube - current_S + r - 1) // r
```計算する$$\left\lceil \frac{c-S_0}{r} \right\rceil,$$ブロック内のオフセット。 

それから：```python
total += current_k + j
```正しい Golomb 値を追加します。
