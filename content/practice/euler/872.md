[プロジェクト オイラー問題 872](https://projecteuler.net/problem=872)

 ## 解決策

 **答え:**`2903144925319290239`させて$$P_n$$の構築中にトレースされた特別なパスを示します。$T_{n+1}$: のルートから開始$T_n$、最大番号の子を繰り返しフォローします。 

この問題の鍵は、これらのツリーが非常に厳格なバイナリ構造を持っていることです。 

#1. 数学的分析

 ## ステップ 1: 最初のいくつかのツリーを計算する

 から始まる$T_1$:

 -$T_2$:$2 \to 1$-$T_3$： 根$3$子供たちと一緒に$2,1$-$T_4$:$4\to 3\to1$、 そして$4\to2$-$T_5$:$5\to4\to2$、 そして$5\to3,1$-$T_6$:$6\to5\to1$、 そして$6\to4\to2$、$5\to3$声明文より:$$f(6,1)=6+5+1=12$$そして$$f(10,3)=10+9+7+3=29.$$次に違いを見てみましょう。 

-$6-1=5=101_2$- パス：$6,5,1$- 減算:$1,4$そして

-$10-3=7=111_2$- パス：$10,9,7,3$- 減算:$1,2,4$これは二項規則を強く示唆しています。 

---

 # ステップ 2: 実際の構造

 しましょう$$d=n-k.$$書く$d$2 のべき乗の合計として:$$d=2^{a_1}+2^{a_2}+\cdots+2^{a_m}, \qquad a_1<a_2<\cdots<a_m.$$累積合計を定義する$$s_j=\sum_{i=1}^j 2^{a_i}.$$次に、からのパス$n$に$k$は$$n,\; n-s_1,\; n-s_2,\; \ldots,\; n-s_m=k.$$同様に:

 > から始める$n$、設定されたビットを減算します。$n-k$最小から最大まで。 

---

 ## なぜこれが本当なのでしょうか?

 構築則から帰納的に証明します。 

トレースされたパスが$T_n$は$$n,\;n-b_1,\;n-b_1-b_2,\ldots$$それぞれどこで$b_i$は 2 のべき乗であり、厳密に増加します。 

施工時$T_{n+1}$、そのパス上のすべてのノードが新しいルートの直接の子になります。$n+1$。 したがって、新しいトレースされたパスは常に、利用可能な最小の 2 のべき乗を減算することから始まります。 

これは、設定された最下位ビットを繰り返し削除するプロセスを正確に反映しています。$n-k$。 したがって、その先祖は、$k$のビットを連続して加算し戻すことで得られます。$n-k$最大から最小へ、または同等に最小から最大へ減算します。 

例は完全に一致しています。 

---

 # ステップ 3: の式$f(n,k)$設定ビットを$d=n-k$なれ$$b_1<b_2<\cdots<b_m.$$定義する$$c_j=b_1+\cdots+b_j.$$それから$$f(n,k) = \sum_{j=0}^{m} (n-c_j), \qquad c_0=0.$$それで$$f(n,k) = (m+1)n-\sum_{j=1}^{m} c_j.$$それが問題のすべてだ。 

---

 #2. Pythonの実装```python
def f(n, k):
    """
    Compute the sum of node labels along the path
    from the root of T_n to node k.
    """

    d = n - k

    cumulative = 0
    cumulative_sum = 0
    bit_count = 0

    # Process set bits from smallest to largest
    while d:
        lowest_bit = d & -d

        cumulative += lowest_bit
        cumulative_sum += cumulative
        bit_count += 1

        d -= lowest_bit

    return (bit_count + 1) * n - cumulative_sum

# Small checks from the statement
print(f(6, 1))    # 12
print(f(10, 3))   # 29

# Required value
print(f(10**17, 9**17))
```---

 #4. 例の検証

 ## 例 1$$n=6,\quad k=1$$それから$$d=5=1+4.$$累積合計:$$1,\ 5.$$パス：$$6,\ 5,\ 1.$$したがって$$f(6,1)=6+5+1=12.$$正しい。 

---

 ## 例 2$$n=10,\quad k=3$$それから$$d=7=1+2+4.$$累積合計:$$1,\ 3,\ 7.$$パス：$$10,\ 9,\ 7,\ 3.$$したがって$$f(10,3)=10+9+7+3=29.$$正しい。

 #5. 必要な値を計算する

 のために$$n=10^{17}, \qquad k=9^{17},$$アルゴリズムが与える$$f(10^{17},9^{17}) = 2903144925319290239.$$値は妥当です:

 - パスの長さは、設定されたビット数に等しい$10^{17}-9^{17}$プラス1、
 - ここにその番号があります$29+1=30$、
 - したがって、合計はおおよそ次のようになります。$30\times10^{17}\approx3\times10^{18}$、
 - 計算された大きさと一致します。
