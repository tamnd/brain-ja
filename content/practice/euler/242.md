 ## 解決策

 **答え:**`997104142249036713`させて$$f(n,k)=\#\left\{A\subseteq \{1,2,\dots,n\}:\ |A|=k,\ \sum_{a\in A} a \text{ is odd}\right\}.$$トリプルの数を求めます$$[n,k,f(n,k)]$$3 つの量がすべて奇数になるように、$n\le 10^{12}$。 

---

 # ステップ 1 — エクスプレス$f(n,k)$の間で$1,2,\dots,n$:

 - 奇数は奇数パリティに寄与します。 
- 偶数は偶数パリティに寄与します。 

サブセットに奇数の奇数の要素が含まれている場合、サブセットの合計は奇数になります。 

---

 ## ケース分析について$n$書く：

-$o=\#\text{odd numbers}$、
 -$e=\#\text{even numbers}$。 

それから$$f(n,k)=\sum_{\substack{j\ \text{odd}}} \binom{o}{j}\binom{e}{k-j}.$$パリティ (奇数/偶数) のみを考慮します。 

---

 # ステップ 2 — 剰余 2 を削減します

 モジュロで動作するようになりました$2$。 

標準的なアイデンティティは$$(1+x)^{2m}\equiv (1+x^2)^m \pmod 2,$$すべての中間二項係数が偶数であるためです。 

同様に、$$(1+x)^{2m+1}\equiv (1+x)(1+x^2)^m \pmod 2.$$---

 # ステップ 3 — の 2 つの合同クラスを分離します。$n$以来$n$それ自体は奇数である必要があります。どちらかを書きます$$n=4r+1 \quad\text{or}\quad n=4r+3.$$また$k$奇妙でなければなりません。 

---

 ## ケース A:$n=4r+1$次に:

 - 奇数の整数の数 =$2r+1$、
 - 偶数の整数の数 =$2r$。 

書く$$k=4s+1 \quad\text{or}\quad k=4s+3.$$の奇数係数部分$$(1+x)^{2r+1}$$モジュロ$2$は$$x(1+x^2)^r.$$偶数生成多項式は次のようになります。$$(1+x)^{2r}\equiv (1+x^2)^r.$$したがって、$$f(4r+1,k) \equiv [x^k]\, x(1+x^2)^{2r} \pmod 2.$$しかし$$(1+x^2)^{2r}\equiv (1+x^4)^r \pmod2.$$したがって、$$f(4r+1,k) \equiv [x^{k-1}](1+x^4)^r.$$この係数は次の場合にのみ非ゼロになります。$k-1$で割り切れます$4$、つまり$$k=4s+1.$$それから$$f(4r+1,4s+1) \equiv \binom{r}{s} \pmod2.$$それで：$$f(4r+1,4s+1)\text{ is odd} \iff \binom{r}{s}\text{ is odd}.$$---

 ## ケース B:$n=4r+3$今:

 - オッズ =$2r+2$、
 - 偶数 =$2r+1$。 

同様の計算により、$$f(4r+3,k)\equiv 0 \pmod2$$あらゆる奇数に対して$k$。 

したがって、 **次の場合には奇数の 3 連符は発生しません。$n\equiv 3\pmod4$**。 

---

 # ステップ 4 — 奇数の二項係数をカウントする

 したがって、すべての奇数トリプレットは次のものに正確に対応します。$$n=4r+1,\qquad k=4s+1,$$と$$\binom{r}{s}\ \text{odd}.$$---

 ## ルーカスの定理

 二項係数は、次のすべての 2 進数が一致する場合、奇数になります。$s$は最大でも次の対応する桁です$r$。 

同様に:$$s \subseteq r \quad\text{bitwise}.$$もし$r$もっている$t$バイナリの 1 の場合、各 1 ビットは独立して次のようになります。 

- で使用される$s$、
 - または使用されていません。 

したがって、行内の奇数係数の数は$r$は$$2^{\operatorname{popcount}(r)}.$$---

 # ステップ 5 — 最終的な合計

 必要です$$4r+1\le 10^{12}.$$したがって、$$r\le \frac{10^{12}-1}{4}=249999999999.$$したがって、答えは次のとおりです$$\sum_{r=0}^{249999999999} 2^{\operatorname{popcount}(r)}.$$---

 # ステップ 6 — 合計を評価する

 定義する$$S(N)=\sum_{r=0}^{N}2^{\operatorname{popcount}(r)}.$$標準のバイナリ DP は次のようになります。 

残りの最上位ビット位置が$m$の場合、より小さい数値はすべて寄与します$$(1+2)^m = 3^m.$$のビットを処理しています$N$上から下まで正確な値が得られます。 

---

 # Pythonの実装```python
def count_odd_triplets(limit):
    # Largest r such that 4r + 1 <= limit
    R = (limit - 1) // 4

    # Computes:
    # S(R) = sum_{r=0}^R 2^(popcount(r))
    ans = 0

    bits = bin(R)[2:]

    # Number of 1-bits already fixed in the prefix
    ones_so_far = 0

    for i, b in enumerate(bits):
        remaining = len(bits) - i - 1

        if b == '1':
            # Put 0 here instead of 1.
            # Remaining bits are arbitrary.
            #
            # Each remaining bit contributes factor:
            #   1 (bit = 0)
            #   2 (bit = 1)
            #
            # so total factor is 3^remaining.
            ans += (2 ** ones_so_far) * (3 ** remaining)

            # Continue along the actual prefix with this bit = 1
            ones_so_far += 1

    # Include R itself
    ans += 2 ** ones_so_far

    return ans

print(count_odd_triplets(10))       # should be 5
print(count_odd_triplets(10**12))
```---

 # コードのチュートリアル

 ### 1. 問題を変換する

 私たちは答えが等しいことを証明しました$$\sum_{r=0}^{R}2^{\operatorname{popcount}(r)},$$どこ$$R=\frac{10^{12}-1}{4}.$$---

 ### 2. 2進数のDP

 ビットを左から右に処理するとします。 

現在のビットが$R$は 1:

 - そこに 0 を置くこともできますが、
 - 残りのビットは空きます。 

各空きビットについて:

 - 0 を選択すると係数が寄与します$1$、
 - 1 を選択すると要因が寄与します$2$。 

したがって、各空きビットが貢献します$1+2=3$。 

したがって、次のブロック$m$フリービットが貢献する$3^m$。 

---

 ### 3. 複雑さ

 このアルゴリズムは、バイナリの長さのみを使用します。$R$:$$O(\log R).$$のために$R<2^{38}$、これは小さいです。
