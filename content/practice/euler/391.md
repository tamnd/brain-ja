[プロジェクト オイラー問題 391](https://projecteuler.net/problem=391)

 ## 解決策

 **答え:**`61029882288`させて$$s_k=\sum_{i=0}^k \operatorname{popcount}(i),$$どこ$\operatorname{popcount}(i)$は、バイナリ展開内の 1 ビットの数です。$i$。 

合法的なゲームポジションはまさにその値です$$S=\{s_0,s_1,s_2,\dots\}.$$連続する要素間の違いは次のとおりです。$$s_{k+1}-s_k=\operatorname{popcount}(k+1).$$だから、からの動き$s_a$に$s_b$合法である場合$$s_b-s_a\le n.$$---

 #1. 数学的分析

 ## 公平なゲーム構造

 これは通常プレイの公平なゲームであるため、ポジションは次のように分類されます。 

- **P ポジション** (前のプレイヤーの勝利/敗北ポジション)、
 - **N ポジション** (次のプレイヤーの勝利 / 勝利ポジション)。 

すべての合法的な手が勝ちポジションに行くと、そのポジションは負けになります。 

ゲームグラフは完全に順序付けされているため、負け局面を貪欲に生成できます。 

---

 ## 重要な所見

 負けているポジションが次のようになっているとします。$$p_0 < p_1 < p_2 < \cdots.$$次に:

 - のあらゆるポジション$S$距離内にある$\le n$負けている立場が勝っている、
 - したがって、次の負けポジションは単に次の最初の要素になります。$S$それは以上です$n$前回の負け位置から抜け出す。 

それで：$$p_{k+1}=\min\{x\in S : x-p_k>n\}.$$この繰り返しが勝負を完全に決定づけます。 

最初の手が負けの位置に着いたら勝ちです。$$M(n)=\max\{p_k : p_k\le n\}.$$---

 ## 効率的な生成$S$すべての整数をバイナリに明示的に変換するわけではありません。 

使用：$$s_{k+1}=s_k+\operatorname{popcount}(k+1).$$Python ではポップカウントの計算が非常に高速です。`bit_count()`。 

---

 ## の効率的な計算$M(n)$固定の場合$n$:

 1. 十分な値を生成します。$S$。 
2. 負けポジションを貪欲に生成します。 

- 最初の負けポジションから開始します。 
- の最初の要素に繰り返しジャンプします$S$よりも遠い$n$。 
3. 最大の損失ポジション$\le n$は$M(n)$。 

これを行うのは、$1\le n\le1000$とても速いです。 

問題ステートメントでは次のチェックが行われます。$$\sum_{n=1}^{20} M(n)^3 = 8150.$$私たちのプログラムはこれを正確に再現します。 

---

 #2. Pythonの実装```python
from bisect import bisect_right

# ---------------------------------------------------------
# Generate the sequence S = {s_k}
# s_k = total number of 1-bits appearing in 0..k
# ---------------------------------------------------------

LIMIT = 300000

S = [0]
cur = 0

for k in range(1, LIMIT + 1):
    cur += k.bit_count()
    S.append(cur)

# ---------------------------------------------------------
# Compute M(n)
# ---------------------------------------------------------

def M(n):
    # Generate losing positions greedily.
    losing = []

    # First losing position:
    # the first element of S having no predecessor within distance <= n
    p = next(x for x in S if x > n)
    losing.append(p)

    # Generate more losing positions
    idx = bisect_right(S, p + n)

    while idx < len(S):
        p = S[idx]
        losing.append(p)
        idx = bisect_right(S, p + n)

        # We only care about losing positions <= n
        if p > n:
            break

    # Largest losing position <= n
    ans = 0
    for x in losing:
        if x <= n:
            ans = x

    return ans

# ---------------------------------------------------------
# Verify the sample
# ---------------------------------------------------------

check = sum(M(n) ** 3 for n in range(1, 21))
print(check)   # 8150

# ---------------------------------------------------------
# Final computation
# ---------------------------------------------------------

answer = sum(M(n) ** 3 for n in range(1, 1001))
print(answer)
```---

 #3. コードのチュートリアル

 ## 生成中$S$

```python
cur += k.bit_count()
S.append(cur)
```以来$$s_k=s_{k-1}+\operatorname{popcount}(k),$$シーケンスを段階的に構築します。 

---

 ## 負けているポジションを構築する

 重要な行は次のとおりです。```python
idx = bisect_right(S, p + n)
```～からのあらゆる法的措置$p$に着陸する$$[p+1,\;p+n].$$それらのポジションはすべて勝ち上がっています。 

したがって、次の負けポジションは、$S$厳密にそれよりも大きい$p+n$。 

二分探索はこれを行います$O(\log |S|)$。 

---

 ## サンプル検証

 プログラムは以下を再現します。```python
sum(M(n)^3 for 1<=n<=20) = 8150
```問題に記載されているとおりです。
