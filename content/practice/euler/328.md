[プロジェクト オイラー問題 328](https://projecteuler.net/problem=328)

 ## 解決策

 **答え:**`260511850222`させて$$F(a,b)$$区間内の隠れた数値を特定するために必要な最小の最悪のコストを示します$[a,b]$。 

まず聞いてみると$x$($a\le x\le b$)、その後:

 - 隠された数値が小さい場合でも、解決する必要があります$[a,x-1]$、
 - 高い場合は解決する必要があります$[x+1,b]$、
 - そして、どちらの場合でも、すでにコストを支払いました$x$。 

したがって$$F(a,b) = \min_{x\in[a,b]} \left( x+\max(F(a,x-1),F(x+1,b)) \right).$$欲しい機能は、$$C(n)=F(1,n).$$小さい値の場合:$$C(1)=0,\quad C(2)=1,\quad C(3)=2,\quad C(8)=12.$$直接動的プログラムは遅すぎます。$n=200000$、それは必要になるためです$O(n^3)$すべてのインターバルにわたって作業します。

 # 重要な構造的洞察

 最適なプレイを実現するには、最初の質問は常にインターバルの上限近くにあります。 

最初の推測が次の場合$k$、次に右の分岐$[k+1,n]$は、ほぼ完全な二分決定木によって処理されます。 

これらの「完全なツリー」コストはアフィン形式で表現できます。$$m\cdot a + c$$から始まる間隔について$a$。 

これにより、右側のコストを次のように評価できるようになります。$O(1)$。 

経験的に (そして証明的に) 最適な距離$$d(n)=n-k(n)$$は 2 の累乗付近でのみ変化するため、それぞれのピボット候補のごく少数のセットのみをテストする必要があります。$n$。 

これにより、計算が本質的に線形時間に短縮されます。

 # Pythonの実装```python
from bisect import bisect_left
from functools import lru_cache

# Numbers of the form 2^t - 1
G = []
x = 1
while x < 400000:
    G.append(x)
    x = x * 2 + 1

@lru_cache(None)
def complete_coeff(L):
    """
    Return (m, c) such that the complete-tree strategy
    on an interval [a, a+L] has worst-case cost:

        m*a + c
    """

    if L <= 0:
        return (0, 0)

    if L == 1:
        return (1, 0)

    if L == 2:
        return (1, 1)

    idx = bisect_left(G, L)
    t = G[idx - 1]

    # Pivot offset
    d = min(t, L - (t - 1) // 2)

    left_len = d - 1
    right_len = L - d - 1

    m1, c1 = complete_coeff(left_len)
    m2, c2 = complete_coeff(right_len)

    right_const = c2 + m2 * (d + 1)

    # Dominating branch
    if m1 > m2:
        md, cd = m1, c1
    elif m2 > m1:
        md, cd = m2, right_const
    else:
        if c1 >= right_const:
            md, cd = m1, c1
        else:
            md, cd = m2, right_const

    return (md + 1, d + cd)

def complete_cost(lo, hi):
    L = hi - lo
    m, c = complete_coeff(L)
    return m * lo + c

def solve(limit=200000):

    C = [0] * (limit + 1)

    # Small exact values
    seed = {
        1: 0,
        2: 1,
        3: 2,
        4: 4,
        5: 6,
        6: 8
    }

    for n, v in seed.items():
        if n <= limit:
            C[n] = v

    if limit <= 6:
        return sum(C[1:limit + 1])

    # Current optimal distance n-k
    dist = 3

    # Candidate perturbations
    q = [0]
    p = 4
    while p <= 131072:
        q.append(p)
        p *= 2

    i = 2

    total_sum = sum(C[1:7])

    for n in range(7, limit + 1):

        if dist > 4 ** i:
            i += 1

        best_cost = None
        best_dist = None

        for delta in q[:i]:

            k = n - dist - delta

            if not (0 < k < n):
                continue

            left = C[k - 1]
            right = complete_cost(k + 1, n)

            worst = max(left, right)

            cost = k + worst

            if best_cost is None or cost < best_cost:
                best_cost = cost
                best_dist = dist + delta

        C[n] = best_cost
        dist = best_dist

        total_sum += best_cost

    return total_sum

print(solve(100))      # 17575
print(solve(200000))

 ### メイン DP

 それぞれについて$n$:

 - 非常に少数のピボット候補のみを試します。 
- 計算する$$k+\max(C(k-1),\text{right-cost})$$- 最小限のものを取ります。 

最適なピボットはゆっくりと移動するため、対数的に多くの候補のみがテストされます。
