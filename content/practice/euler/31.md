[プロジェクト オイラー問題 31](https://projecteuler.net/problem=31)

 ## 解決策

 **答え:**`73682`この問題を解決するには、合計が 200 ペンスになる、イギリスの硬貨の順序のない組み合わせの数を数えなければなりません。 

利用可能なコインの種類は次のとおりです。$$1,2,5,10,20,50,100,200$$非負の整数解の数が必要です。$$1a+2b+5c+10d+20e+50f+100g+200h=200$$ここで、各変数はそのコインが何枚使用されるかを表します。 

---

 # 数学的分析

 これは古典的な **整数分割/コイン変更** の問題です。 

重要な洞察は次のとおりです。 

- 順序は**重要ではありません**。 
- 順列ではなく、組み合わせをカウントします。 

例えば：

-$1p + 2p + 2p$-$2p + 1p + 2p$同じ組み合わせです。 

総当りの順列検索では、膨大な数が過剰にカウントされてしまいます。 

---

 ## 動的プログラミングのアプローチ

 定義:$$dp[n]$$意味:

 > 形成方法の数$n$これまでに処理されたコインを使用したペンス。 

最初に:$$dp[0]=1$$なぜなら、0p を作る方法はただ 1 つしかないからです。それは、コインを使用しないことです。 

他のすべての値は 0 から始まります。 

---

 ## 移行ルール

 コインを一度に 1 枚ずつ処理するとします。 

コインの価値については$c$、あらゆる金額$n \ge c$以下によって形成できます。 

- ワンコインを取る$c$、
 - プラス、有効なフォーム方法$n-c$。 

したがって：$$dp[n] \leftarrow dp[n] + dp[n-c]$$コインを昇順に処理することで、組み合わせが正確に 1 回カウントされることが保証されます。 

---

 ## これにより過剰カウントが回避される理由

 7pの形成を検討してください。 

処理する場合:

 1. 1ペンスコイン、
 2.次に2ペンスコイン、
 3.次に5ペンスコイン、

 その後、すべての組み合わせが正規の順序で生成されます。 

例えば：$$5+2$$5pコインの処理時にカウントされます。 

しかし：$$2+5$$アルゴリズムは後で小さいコインの種類を再検討することはないため、後で個別に生成されることはありません。 

したがって、順序付けされていない各組み合わせは 1 回だけ出現します。 

---

 # Pythonの実装```python
# Coin denominations in pence
coins = [1, 2, 5, 10, 20, 50, 100, 200]

# Target amount (£2 = 200p)
target = 200

# dp[n] = number of ways to make n pence
dp = [0] * (target + 1)

# Base case:
# There is exactly one way to make 0p
dp[0] = 1

# Process each coin
for coin in coins:
    # Update all reachable amounts
    for amount in range(coin, target + 1):
        dp[amount] += dp[amount - coin]

# Final answer
print(dp[target])
```---
