 ## 解決策
 ## 問題の理解

 i 番目の位置に最初に i が含まれる配列から始めます。 次に、一連の n − 1 個のランダム化された更新を実行します。 i 回目の更新では、配列の縮小プレフィックスを調べ、現在のアクティブ範囲の右端から特定の要素を取得し、その値の 2 倍を以前のインデックス間の一様にランダムな位置に追加します。 

具体的には、ステップ i では、位置 n − i + 1 の要素が「ソース」として使用されます。 1 から n − i まで均一にインデックス j を選択し、ソースの現在の値の 2 倍を a[j] に加算します。 この後、ソース位置がターゲットとして再び使用されることはありませんが、以前の位置は引き続きソースとして将来の操作に参加する可能性があります。 

求められる量は、これらすべてのランダム操作後の a1 の値であり、998244353 を法として計算されます。すべてのステップにはランダム性が含まれるため、これは確率変数です。 j のすべての選択肢に対する期待値を取得した後でのみ最終結果が決定的になるため、意図された解釈はその期待値になります。 

最大 10^4 のテスト ケースを伴う n ≤ 10^9 という制約により、シミュレーションやテスト ケースごとの線形 DP さえも即座に除外されます。 どのソリューションも、プロセス全体を n のみに依存する閉じた形式の式に折りたたむ必要があります。 

微妙な問題は、値が複数回伝播されることです。 早期に追加された要素は、後でソース自体として選択され、その累積値が再度伝播されます。 このため、プロセスを通じて繰り返される増幅を正しく考慮しない限り、単純な「シングルパス蓄積」は不正確になります。 

簡単な健全性チェックを行うと、ランダム性がなぜ重要なのかがわかります。 n = 2 の場合、唯一の演算が強制され、a1 は 1 + 2・2 = 5 になります。正しい解釈は、この決定論的な結果と一致する必要があります。 

## アプローチ

 直接シミュレーションでは、各操作を明示的に実行し、j をランダムに選択して配列を更新します。 これは原理的には正しいですが、テスト ケースあたりのコストは O(n) であり、n が 10^9 までの場合は不可能です。 

インデックスごとの期待値を追跡する改良された DP であっても、各状態がその後のすべての状態に依存する再発が発生します。 これにより、テスト ケースごとに O(n^2) または O(n) が生成されますが、どちらも完全に実行不可能です。 

重要な観察は、システムの値が線形であるため、寄与を個別に分析できることです。 操作を通じて値が伝播されるたびに、値は 2 で乗算されます。これは、プロセスをランダムなルート構造として解釈し、最終的にすべてのノードがランダムな選択を通じて「上に押し上げられる」回数に応じた重みで a1 に寄与することを示唆しています。 

これにより、問題は、ランダム再帰ツリー内のランダムな親チェーンに沿って予想される増幅を理解することに変換されます。 ランダム再帰ツリーの構造は複雑さを崩壊させる強い対称性を持っているため、その形式で書き直されると、期待は扱いやすくなります。

 ## アルゴリズムのチュートリアル

 このプロセスを、ノード 1 から n にランダムな再帰ツリーを構築するものとして再解釈します。 各ノード i は、ノード 1 から i − 1 まで均一に親を選択します。これは、ノード i がソースとして機能する瞬間に、以前のインデックスから均一にターゲット j を選択するという事実から直接来ています。 

ノードからその親への各エッジは寄与度を 2 倍します。したがって、すべてのノード i は、このランダム ツリー内の i からノード 1 までの距離に 2 を乗算した値を初期値 i に寄与します。 

タスクは、すべてのノードにわたるこの合計の期待値を計算することになります。 

以下のように進めていきます。

1. di をランダム再帰ツリーのノード i の深さとして定義します。ここで、ノード 1 はルートです。 
2. 最終的な答えを a1 = Σ i · 2^{di} と表します。 これは有効です。値がノード 1 に向かって 1 ステップ移動するたびに 2 が乗算されるため、合計の増幅は正確に 2^{距離} になります。 
3. すべてのノードに対して線形に期待値を計算します: E[a1] = Σ i · E[2^{di}]。 残りのタスクは、各 i について E[2^{di}] を計算することです。 
4. fi = E[2^{di}] を定義します。 ランダム再帰ツリーでは、ノード i は前のノード j < i に均一に接続されます。 

j < i の場合、fi = 2 · (1/(i − 1)) · Σ fj。 
5. Si = Σ_{j ≤ i} fj とします。 この場合、漸化式は Si = Si−1 · (1 + 2/(i − 1)) となります。 
6. 乗算係数を (i + 1)/(i − 1) として書き換えます。 これはきれいに望遠鏡します:

 Si = ∏_{k=2..i} (k + 1)/(k − 1)。 
7. 製品は完全に簡素化されています。 

分子は 3 · 4 · ... · (i + 1) となり、

 分母は 1 · 2 · ... · (i − 1) となり、

 これは Si = i(i + 1)/2 と評価されます。 
8. Si から fi を復元します: fi = Si − Si−1 = i。 
9. 期待値を代入して戻します。 

E[a1] = Σ i · fi = Σ i^2 (i = 1..n)。 
10. 閉じた形式の平方和を計算します。 

### なぜ効果があるのか

 全体の削減は、期待の線形性と、寄与がツリーのエッジに沿って独立して増加するという事実に依存します。 ランダム構造は、どのノードが 1 へのパス上にあるかにのみ影響しますが、E[2^{深さ}] の再帰は伸縮積に崩壊するため、予想される指数関数的な深さの寄与には影響しません。 fi が i に単純化されると、最終的な式からランダム性が完全に消え、n には決定論的な多項式だけが残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve(n):
    n %= MOD
    return n * (n + 1) % MOD * (2 * n + 1) % MOD * pow(6, MOD - 2, MOD) % MOD

t = int(input())
for _ in range(t):
    n = int(input())
    print(solve(n))
```このコードは、指定された素数を法とする閉形式の二乗和を直接適用します。 必要な唯一の注意は、6 によるモジュラー除算であり、法が素数であるため、フェルマーの逆関数を使用して処理されます。 

この導出は、シミュレーションや DP が必要ない理由を示しています。確率過程は単純な多項式恒等式に崩壊します。 

## 実用的な例

 n = 3 とします。最初の配列は [1, 2, 3] です。 この式では、1^2 + 2^2 + 3^2 = 14 となります。 

| 私 | di (ランダム) | 2^{di} の期待値 | 貢献度 i · E[2^{di}] |
 | --- | --- | --- | --- |
 | 1 | 0 | 1 | 1 |
 | 2 | 1 | 2 | 4 |
 | 3 | 変数 | 3 | 9 |

 ランダムな構造に関係なく合計すると 14 が得られ、一貫性が確認されます。 

n = 2 の場合、決定的な単一の演算が行われます。a1 は 5 になります。この式では、1^2 + 2^2 = 5 が得られ、正確に一致します。 

| 私 | 運用効果 | 最終的な貢献 |
 | --- | --- | --- |
 | 1 | ベース 1 のまま | 1 |
 | 2 | a1 に 2・2 を加算します | 4 |
 | 合計 | | 5 |

 これにより、自明ではない最小のケースであっても、式がランダムなプロセスを正しく捉えていることが確認されます。

## テストケース```python
import sys, io

MOD = 998244353

def solve_all(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve(n):
        n %= MOD
        return n * (n + 1) % MOD * (2 * n + 1) % MOD * pow(6, MOD - 2, MOD) % MOD

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str(solve(n)))
    return "\n".join(out)

def run(inp: str) -> str:
    return solve_all(inp)

 ## 特殊なケース

 n = 1 の場合、演算は行われず、a1 は 1 のままです。この式では 1^2 = 1 が得られるため、特別な処理を必要とせずに結果は一貫しています。 

n = 2 の場合、操作は 1 つだけであり、j の選択にはランダム性がありません。 予想される深さの計算がきれいに縮退し、結果 5 が直接計算と一致するため、導出は引き続き適用されます。 

10^9 に近い大きな n の場合、直接シミュレーションはすぐに時間制限をオーバーフローしますが、閉形式の式は多項式の評価と逆モジュラーのみに依存するため、モジュラー演算下でも安定しています。
