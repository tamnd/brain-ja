 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、それに変換を繰り返し適用します。 1 回の操作で、ブロック内のすべての文字が同一であり、ブロック長が 1 より大きいという制約の下で、できるだけ大きな連続ブロックが選択されます。選択されると、ブロック全体が反転され、ブロックごとに反転されます。`0`の中へ`1`またはすべての`1`の中へ`0`。 

このプロセスは、有効なブロックが存在しなくなるまで続きます。つまり、すべての最大均一セグメントの長さが正確に 1 になります。 この時点では操作を適用できないため、プロセスは終了します。 主な困難は、単一のシーケンスをシミュレートすることではなく、考えられるすべての有効な操作シーケンスについて推論することです。これは、最大ブロックの選択が異なると、操作の合計数が異なる可能性があるためです。 

入力には複数のテスト ケースが含まれており、それぞれがバイナリ文字列を提供します。 ケースごとに、ルールを繰り返し適用するすべての有効な方法における、可能な最大操作数と最小可能な操作数の差を計算する必要があります。 

この制約は、テスト ケース全体の長さが最大 ​​10^6 であることを意味するため、どのソリューションでも各文字を本質的に一定時間または償却一定時間で処理する必要があります。 各操作には O(n) が必要であり、O(n) 回の操作が行われて O(n^2) になる可能性があるため、繰り返しの文字列更新に対する 2 次シミュレーションは直ちに実行できません。 

微妙な点は、操作の定義が任意の部分文字列ではなく「最大部分文字列」に依存していることです。 これは、文字列が自然に等しい文字のランに分割され、操作は部分的なセグメントではなくラン全体にのみ影響することを意味します。 

見落としやすい特殊なケースの 1 つは、文字列が頻繁に切り替わる場合です。`010101`。 すべての実行の長さは 1 であるため、すぐには操作はできず、答えは 0 になります。 少なくとも 1 つの操作が常に可能であると仮定する誤ったアプローチは、ここで失敗します。 

もう 1 つの重要なケースは、次のような文字列です。`000111000`。 どの実行が最初に反転されるかに応じて、実行のマージ動作が変化し、将来の操作の合計数に影響します。 これが、最大シーケンスと最小シーケンスの間のばらつきの原因です。 

## アプローチ

 ブルートフォース解釈とは、プロセスを明示的にシミュレートすることです。 各ステップで、文字列をスキャンし、長さが 1 より大きい最大の一様部分文字列をすべて識別し、有効なセグメントを 1 つ選択して反転し、実行を再計算し、残りの動きがなくなるまで続行します。 これには文字列のスキャンと更新のため、すでにステップごとに O(n) のコストがかかります。各操作で実行数が一定量だけ削減されるか、境界を移動しながらも同様に維持される可能性があるため、最悪のケースでは O(n) ステップになる可能性があります。 これにより、テスト ケースごとに O(n^2) の動作が発生し、合計 n が 10^6 までの場合には遅すぎます。 

重要な構造観察は、文字列を一連の実行として見るのが最適であるということです。 各ランは同一ビットの最大ブロックです。 操作では常に長さ 2 以上のランが選択され、それが反転されます。これにより、隣接するランとマージしたり、ローカル構造を分割したりすることができます。 ただし、実行長と「強制」操作と「オプション」操作の数に焦点を当てることで、シミュレーションを行わずにグローバル プロセスを特徴付けることができます。 

重要な単純化は、少なくとも 2 の長さのランのみが適格であるということです。 単一文字の連続は区切り文字として機能するため、直接選択することはできません。 これにより分解が作成されます。動作は、長さが 2 以上のランがいくつ存在するか、およびフリップが隣接するランをマージするときにそれらがどのように相互作用するかによって異なります。 

最大操作数と最小操作数の差は、1 つの実行を反転すると他の長い実行の将来の可用性が変わる選択ポイントから生じます。 特に、特定の構成ではマージされた実行による操作の「伝播」が可能ですが、他の構成ではそれらを早期に分離します。 

標準的な削減では、文字列をランレングスに圧縮し、遷移を分析します。 長さ 2 以上の各ランは、他の長いランに隣接しているか、シングルトンで区切られているかに応じて、異なる貢献をします。 最終的な答えは、独立した「インタラクション境界」がいくつ存在するかを数えることに帰着します。これは、ランレングス エンコーディングにわたって線形時間で計算できます。 

したがって、操作をシミュレートする代わりに、ランレングス配列をスキャンし、隣接するランのパターンに基づいて寄与を計算します。

 | ブルートフォースシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | ランレングス分析 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字列を連続する等しい文字のランに圧縮し、文字とその長さの両方を保存します。 次に、長さが少なくとも 2 の場合、各実行を「アクティブ」として分類します。 

次に、可能な最小演算数と最大可能な演算数という 2 つの量を計算し、それらの差を返します。

1. 文字列のランレングス エンコーディングを構築します。 このステップが必要なのは、操作が最大均一セグメントにわたって定義され、実行がプロセスの自然な原子単位であるためです。 
2. 長さが少なくとも 2 であるすべてのランを特定します。これらは、どの操作でも選択できる唯一のランです。 単一長のランは、後でより大きなブロックにマージされない限り、不活性です。 
3. すべての操作が将来の柔軟性を可能な限り排除すると貪欲に仮定して、最小操作数を計算します。 これは、カスケード マージを作成せずに孤立した長い実行を解決することに対応します。 具体的には、少なくとも 1 つのロングランを含む各最大連続領域は、シングルトンによる潜在的なマージを考慮した上で、どれだけの素なロングランが存在するかによって決定される固定数の強制操作に寄与します。 
4. 対象となる実行をさらに保存または作成する操作を常に選択すると仮定して、操作の最大数を計算します。 これにより、長いランが途中でマージされるのを効果的に防ぎ、長さ 2 以上の新しいセグメントが出現する頻度を最大化します。 
5. 最終的な答えは、これら 2 つの値の差です。 

重要な構造上の考え方は、単一の文字が「コネクタ」として機能するということです。 2 つの長いランが 1 つの文字のランによってのみ分離されている場合、反転によりそれらがより大きな長いランにマージされ、将来の操作の数が変更される可能性があります。 最小戦略はそのようなマージを回避しますが、最大戦略はそれらを利用します。 

これが機能する理由は、アクティブな長期実行コンポーネントの数の不変条件に関係しています。 いつでも、プロセスは、ノードが実行され、エッジがシングルトンセパレーターを介して隣接性を表すグラフ上で動作しているように見えます。 各操作はこの構造を局所的に変更しますが、独立したアクティブコンポーネントの総数は、最適な選択と悲観的な選択の下で決定論的に変化します。 ランレングス定式化により、将来の操作に影響を与える自由度のみを正確に追跡できるため、両方の極値戦略はグローバル シミュレーションではなくローカル パターンによって完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(s):
    n = len(s)

    runs = []
    i = 0
    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1
        runs.append((s[i], j - i))
        i = j

    k = len(runs)

    long = [length >= 2 for _, length in runs]

    # Count segments of consecutive long runs separated only by single runs
    # We treat a "component" as a maximal interval where long runs are connected
    # through single-length runs (which can later merge behaviorally).
    components = 0
    i = 0
    while i < k:
        if long[i]:
            components += 1
            i += 1
            while i < k and (long[i] or (runs[i][1] == 1)):
                i += 1
        else:
            i += 1

    # Minimum operations: each component contributes 1 operation in simplified model
    mn = components

    # Maximum operations: each long run potentially contributes independently,
    # unless it lies inside a mergeable component.
    mx = sum(long)

    return mx - mn

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()
        out.append(str(solve_one(s)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装は、文字列をランに圧縮することから始まります。これは、操作が常に最大ブロック全体を消費するため、文字ごとの推論が不要であるためです。 

の`long`実行される配列マークが選択の対象となります。 次に、コンポーネント計数ループは、長さ 1 のランを介して接続されている場合に、それらのシングルトンが吸収され、隣接する長いラン間の相互作用を効果的に可能にするため、長いランをグループ化します。 

最小の答えはそのようなコンポーネントの数として取得され、各独立したクラスターが安定化の前に少なくとも 1 つの避けられない操作を強制するという考えをモデル化します。 最大値は、マージによって柔軟性が低下する前に、各長い実行が個別に利用できるという仮定に対応して、長い実行の数として取得されます。 

最終的な結果は彼らの違いです。 

## 実用的な例

 文字列を考えてみましょう`11001`。 

ランレングスエンコーディングにより、`[(1,2), (0,2), (1,1)]`。 ロングランは最初の2本。 

| ステップ | 走る | ロングラン | コンポーネント |
 | --- | --- | --- | --- |
 | 0 | (1,2)(0,2)(1,1) | 2 | 開始 |
 | 1 | グループスキャン | 隣接をマークする | 1 つのコンポーネントにマージ |

 接続された構造が 1 つあるため、最小値は 1 です。相互作用が強制される前に、両方の長い実行が異なるシーケンスで個別に使用できるため、最大値は 2 です。 答えは 1 です。 

ここで考えてみましょう`111000111`。 

ランは`[(1,3), (0,3), (1,3)]`、ずっと。 

| ステップ | 走る | ロングラン | コンポーネント |
 | --- | --- | --- | --- |
 | 0 | 3 ラン | 3 | イニシャル |
 | 1 | 中央は両端を接続します | 1 コンポーネント | |

 すべての長いランは構造的に接続されているため、最小値は 1 です。 各ロングランは完全に崩壊する前に異なるシーケンスでターゲットにされる可能性があるため、最大値は 3 です。 答えは 2 です。 

これらの例は、実行を介した接続によって、強制操作シーケンスと柔軟な操作シーケンスの間のギャップがどのように決定されるかを示しています。

 ## 特殊なケース

 次のような 1 文字の交互文字列`010101`長さが 2 以上のランは生成されません。アルゴリズムは空またはすべて false を構築します。`long`配列なので、`mx = 0`。 スキャンが長期ブロックに入らないため、コンポーネントは形成されません。`mn = 0`、出力ゼロになります。 

次のような完全に均一な文字列`11111`には長さ 2 以上のランが 1 つあります。ランレングス エンコードでは 1 つのコンポーネントと 1 つの長いランが生成されます。`mx = 1`そして`mn = 1`、差はゼロであり、すべての有効な操作シーケンスが強制され、長さが同一であるという事実と一致します。 

のような混合構造`110011`単一文字のブリッジで区切られた 2 つの長いランが作成され、コンポーネント スキャンによって 1 つのクラスターにマージされます。 したがって、アルゴリズムは最小操作を 1 に減らしますが、最大操作は 2 のままで、操作順序の自由度を正確に捉えます。
