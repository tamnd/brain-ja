 ## 解決策
 ## 問題の理解

 まず、柱 A に配置された個別のディスクの単一のスタックから始めます。ディスクは下から上に順序付けされており、各ディスクは固有のサイズを持ち、1 から n の順列を形成します。 空の柱 B と C が 2 つあります。 

移動ルールはハノイ塔に似ていますが、非対称です。 柱 B と柱 C は古典的なハノイのように動作します。小さな円盤の上に大きな円盤を置くことはできません。 ピラー A は異なります。ピラー A では、小さいディスクの上に大きいディスクを配置できます。これは、事実上、スタック バック時に順序制限なしで A が一時的なワークスペースとして使用されることを意味します。 

目標は、最小限の正当な移動数を使用してスタック全体を A から B に移動することです。 

入力により複数のテスト ケースが提供されます。 各テスト ケースは、A 上で下から上へのディスクの初期配置を提供します。 出力はテスト ケースごとに 1 つの整数、つまりすべてのディスクを B に転送するために必要な最小移動数です。 

この制約は、すべてのテスト ケースで n が最大 200000 になる可能性があることを意味します。 サイズ 100000 の 1 つのテストでも O(n^2) の動作にはすでに大きすぎるため、テスト ケースごとに 2 次的な解はすぐに失敗します。 これにより、テスト ケースごとに線形または線形算術的なソリューションが求められます。 

微妙な点は、ディスクが最初は並べ替えられていないことです。 これにより、ディスクがサイズによって自然に順序付けされる古典的な再帰的ハノイ構造が削除されます。 代わりに、最初の並べ替えにより、大きなディスクが小さなディスクを非標準的な方法でブロックする「ブレークポイント」が導入されます。 

単純な間違いは、これを n 個のディスク上の標準的なハノイ問題として直接扱うことができ、2^n - 1 個の手が得られると仮定することです。 これは、初期状態が空のピラーではなくすでに完全なスタックであり、ピラー A が他のピラーと同じスタッキング制限を課していないため、これは不正確です。 

もう 1 つの誤った直感は、貪欲に動きをシミュレートしようとすることです。可能であれば、上のディスクを B または C に繰り返し移動させます。 これは、ローカルの合法性が、最終的にソートされた構成要件によって作成されたグローバルな依存関係構造を捕捉しないため、失敗します。 

トラップを示す小さな例は、スタック [2, 1, 3] を持つ n = 3 です。 貪欲なアプローチでは最初に 2 を動かすかもしれませんが、最適なプレイはディスク 3 が構造を固定していることを理解することに依存しており、正しい戦略は現在の順序で小さなディスクが大きなディスクによって「ブロック」されているかどうかを考慮する必要があります。 

## アプローチ

 主な問題点は、ディスクがすでに任意の順列でスタックされているのに、ターゲット構成はピラー B できれいに増加するスタックであることです。移動できるのは最上位のディスクのみであるため、すべてのディスクの移動は、現在のスタック内でその上にあるすべてのディスクに依存し、また、最終的に B 上でディスクをどのように順序付けする必要があるかにも依存します。 

この強引なアイデアは、3 つの柱すべての状態全体をモデル化し、構成全体にわたって最短パス検索を実行することです。 各状態は 3 つのスタックをエンコードし、各移動により 1 つのスタックの最上位ディスクが別の正当なスタックに転送されます。 これは正しいですが、まったく実行不可能です。 状態空間は巨大で、n が増加すると指数関数的に増加し、n が 10 付近を超えるとごく一部の部分を探索することさえ不可能になります。 

重要な点は、この問題では完全な構成を追跡する必要がないということです。 代わりに、各ディスクには 2 つの意味のある役割しかありません。それは、最終ターゲット スタックに対して現在「順序どおり」であるか、それとも最初の並べ替えによって引き起こされる中断に参加するかです。 ディスクを移動するプロセスは、古典的なハノイ再帰と同様の制約された方法で、これらの混乱を下から上に解決するものとして解釈できます。

これをより正確に確認する方法は、サイズの大きい順にディスクを処理することです。 ディスク i を考慮すると、i より小さいものはすべて論理的に解決されています。 重要なのは、ディスク i が、これまでに形成された最終的なスタック構造と一致する位置に現れるかどうかです。 隣接するディスク間の相対的な順序が目標の単調構造に矛盾するたびに、ハノイでの追加の転送フェーズに相当する追加コストを支払います。 

これにより、正しい方向に解釈された場合に順列が何個の「セグメント」に分割されるかによって答えが導出される、線形スキャンベースの定式化が導き出されます。 各セグメントは独立したハノイ部分問題のように動作し、総コストは 2 のべき乗のような寄与の合計として累積しますが、実際には、構造がローカルな隣接性の比較によって決定されるため、線形再帰に崩壊します。 

重要な単純化は、動きをシミュレートする代わりに、B と C によって課せられるサイズ順序の制約に関連して順列がどのように単調チェーンに分割されるかを追跡するだけであることです。

 ## アルゴリズムのチュートリアル

 スタックを下から上に解釈します。 重要な観察は、現在の円盤が次の円盤より大きい位置に遭遇するたびに、動きの複雑さの追加層を強制する構造的な境界を導入するということです。 

1. スタックを説明する順列を下から上に読んでください。 
2. アレイをスキャンし、隣接するディスク間の順序条件が B 上の最終スタックの予想される単調構造を壊す位置を特定します。具体的には、シーケンスが有効な増加チェーンのように動作しなくなる場所を検出します。 
3. これらの不連続点で分割したときに、配列が連続するセグメントの数に分割されるカウンタを維持します。 各セグメントは、他のセグメントのディスクに干渉することなく転送できるディスクのグループに対応します。 
4. 各セグメントについて、この制約付きハノイ バリアントでのサイズ k のブロックの移動は、内部順序ではなくセグメント境界のみに依存する固定コスト変換のように動作するという事実を使用して、総移動数への寄与を計算します。 
5. すべてのセグメントにわたる貢献を蓄積します。 最終的な答えはこれらのコストの合計であり、B と C のスタック制限により各セグメントを個別に解決する必要があることを反映しています。 

セグメンテーションが機能する理由は、B と C の単調制約に違反せずに、異なるセグメントに属するディスクを正当な移動中にインターリーブできないためです。このため、問題はこれらの境界に沿ってきれいに分解されます。 

### なぜ効果があるのか

 このアルゴリズムは、セグメント境界を特定すると、B または C の順序制約に一時的に違反することなく、いかなる法的な移動シーケンスもその境界を越えてディスクをマージできないという不変条件に依存しています。その結果、各セグメントは、小規模なハノイ インスタンスと同等の独立した部分問題のように動作します。 ハノイの最適なソリューションは独立したスタック全体で構成されているため、セグメントのコストを合計すると全体的な最適なソリューションが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        # Count "breaks" in structure
        segments = 1
        for i in range(n - 1):
            if p[i] > p[i + 1]:
                segments += 1

        # Each segment contributes a fixed linear cost
        # In this reduced form, answer depends only on segments and n
        # Derived recurrence collapses to:
        # moves = 2*n - segments
        print(2 * n - segments)

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを読み取り、下から上に移動するときに順列が何回減少するかをカウントします。 それぞれの減少は、新しい構造セグメントを示します。 

最終的な式`2 * n - segments`これは、最悪の場合の伝播では各ディスクが少なくとも 2 つの移動を必要とするという事実をエンコードしていますが、セグメントが追加されるたびにディスク間の結合が減少し、必要な転送の総量が減少します。 

微妙な実装の詳細が初期化されています`segments = 1`。 ブレークポイントが存在しないため、完全に増加するシーケンスでもセグメントが 1 つだけ存在します。 

The loop only checks`p[i] > p[i + 1]`、単調構造が失敗する場所を正確に捉えます。

 ## 特殊なケース

 次のような厳密に増加するスタックの場合`1 2 3 4 5`の場合、アルゴリズムは切れ目を検出せず、単一のセグメントを保持します。 スキャンでは更新は実行されず、結果は次のようになります。`2n - 1`、すべてのディスクが単一のグローバル転送プロセスに寄与する、完全に接続された依存関係構造と一致します。 

次のような厳密に減少するスタックの場合`5 4 3 2 1`、すべての隣接するペアがセグメント境界を作成します。 アルゴリズムはステップごとにセグメント数を増加させ、n 個のセグメントを生成します。 式は次のようになります。`2n - n = n`これは、隣接する 2 つのディスクがターゲット方向に安定したチェーンを形成しないため、各ディスクを最小限の干渉で移動できることを反映しています。
