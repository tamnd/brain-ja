 ## 解決策
 ## 問題の理解

 カード タイプの有限のコレクションが与えられています。 各タイプは、1 から n までの範囲の色と数値のペアの属性によって決定されるため、合計で n² 個のタイプがあります。 タイプごとに、そのタイプの物理カードがデッキ内に何枚存在するか、および各カードが寄与する価値がわかります。 

ゲームは k ラウンドにわたって行われます。 各ラウンドでは、複数のカードセット全体から 1 枚のカードが均一にランダムに引き出されます。 重要なのは、各ドローの後、カードは手札に追加されるか、あるいはすでに手札にある他のカードと一緒にすぐに戻されるということです。 

手には動的に強制される構造上の制限があります。 新たに引いたカードが、その色または番号を共有することにより既に手札にあるカードと競合する場合、手札にあるすべての競合するカードは、引いたカードと一緒にデッキに戻されます。 それ以外の場合は、引かれたカードが単純に手札に追加されます。 

各ラウンドの後、現在手札にあるすべてのカードの値の合計に等しいスコアを獲得します。 タスクは、k ラウンド後の予想合計スコアを計算することです。 

重要な問題は、k が最大 10^9 と非常に大きくなる可能性があるため、ラウンドにわたる段階的なシミュレーションが不可能であることです。 入力のうち大きい部分はラウンド数のみです。 構造状態空間は完全に n (最大 4) によって制御されます。この小さな n が重要な制約です。これは、プロセスが確率的で長いにもかかわらず、可能なハンド構成の数がシステムを有限マルコフ連鎖として扱うのに十分小さいことを示唆しています。 

微妙なエッジケースは、ハンドがカードの任意のサブセットではないということです。 たとえば、同じ色または番号を共有する 2 枚のカードを同時に保持することはできません。 この不変条件を慎重に適用せずに単純な実装でカードのセットを格納した場合、同じ行または列の 2 枚のカードが共存するなどの無効な状態が生成される可能性があります。 正しい解釈は、手は常に色と数字の部分的な一致を形成するということです。 

もう 1 つの特殊なケースは、「リセット」動作から生じます。 手にすでに一連のカードが含まれており、その構造内のどこかに単一の色または数字と一致するカードを引くとします。 このルールでは、1 枚だけではなく、その色または番号を共有するすべてのカードが削除されます。 これにより、移行はローカルな隣接関係だけでなく、現在の一致のグローバル プロパティに依存するようになります。 

## アプローチ

 直接シミュレーションでは、ハンドを維持し、確率に従ってカードを繰り返しサンプリングします。 各ステップのコストは O(1) ですが、k は 10^9 になる可能性があるため、このアプローチは直ちに実行不可能になります。 

デッキを確率に圧縮したとしても、システムは依然として確率プロセスとして進化し、その状態はハンド構造全体に依存します。 重要な観察は、手は常に色と数字を一致させているということです。 各色と数字は手の中に最大 1 回しか出現しないため、その手は各側に n 個のノードを持つ 2 部グラフの部分一致に対応します。 

n が最大 4 の場合、部分一致の数は非常に少なくなります。 状態の数は、C(n,k)² k! の k にわたる合計であり、n = 4 の場合、209 と評価されます。これにより、すべての状態を明示的に列挙することが可能になります。 

プロセスをこれらの状態にわたるマルコフ連鎖として見ると、各タイプ (色 x、数値 y) が決定論的な遷移を引き起こします。エッジを追加するか (現在のエンドポイントと競合しない場合)、競合が存在する場合は x または y に付随するすべてのエッジを削除します。 カードの抽選は独立しており、均等に分配されるため、移行確率は固定されます。 

残りの課題は、最終的な分布だけでなく、k ステップにわたる値の予想合計が必要であることです。 これには、実行中の報酬の蓄積によってマルコフ プロセスを強化する必要があります。

ステップ全体にわたるブルートフォース動的プログラミングには依然として O(k · S²) が必要ですが、これは不可能です。 重要なのは、遷移が線形であるため、状態遷移と報酬の累積の両方を単一の行列にエンコードし、高速累乗を適用できることです。 

州全体の分布と累積スコアの両方を同時に更新する行列を構築します。 これにより、問題はおよそ 210 × 210 のサイズの行列の累乗に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(k) | お(1) | 遅すぎる |
 | ステップごとのマルコフ DP | O(k · S²) | O(S²) | 遅すぎる |
 | 状態に対する行列の累乗 | O(S3 log k) | O(S²) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、有効なハンド構成をすべて列挙します。 各構成は互いに素なペア (色、番号) のセットであるため、部分一致となります。 各状態にインデックスを割り当てます。 

また、各タイプを引く確率も事前に計算します。 カードの総数が T の場合、タイプ t は確率 p[t] = a[t] / T で出現します。 

状態間の遷移を次のように定義します。 各状態および各タイプについて、そのタイプの追加が現在の一致と競合するかどうかを判断します。 矛盾しない場合はエッジを追加します。 競合する場合は、そのタイプの色または番号に関連するすべてのエッジが削除され、エッジは追加されません。 

また、状態の報酬を、マッチング内のすべてのカードの値の合計として定義します。 

これを分布上の線形システムに変換します。 P を状態の遷移行列とする。 r を報酬ベクトルとします。 

k ステップにわたる累積的な期待報酬が必要です。 私たちは、分配と蓄積された報酬の両方を追跡する拡張システムを構築します。 累積は各遷移後の分布に依存するため、状態の進化と報酬の寄与を組み合わせたブロック行列にそれを組み込みます。 

累積スコアがゼロの空のマッチング状態から開始して、この拡張行列を k 乗します。 最後に蓄積された成分が答えになります。 

これが機能する理由は、分布の更新と報酬の更新の両方が現在の分布の線形関数であるためです。 これにより、遷移の合成が関連する行列の乗算に正確に対応することが保証されます。 行列の乗算は線形変換の構成を保存するため、べき乗はシミュレーションなしで k 回繰り返されるステップを正確に表します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def mat_mul(A, B):
    n = len(A)
    m = len(B[0])
    p = len(B)
    res = [[0] * m for _ in range(n)]
    for i in range(n):
        Ai = A[i]
        for k in range(p):
            if Ai[k]:
                aik = Ai[k]
                Bk = B[k]
                for j in range(m):
                    res[i][j] = (res[i][j] + aik * Bk[j]) % MOD
    return res

def mat_pow(M, e):
    n = len(M)
    res = [[0] * n for _ in range(n)]
    for i in range(n):
        res[i][i] = 1
    while e:
        if e & 1:
            res = mat_mul(res, M)
        M = mat_mul(M, M)
        e >>= 1
    return res

def build_states(n):
    from itertools import combinations

    states = []
    idx = {}

    def gen(col_used, row_used, pairs, start_c, start_r):
        state_id = len(states)
        states.append((tuple(sorted(pairs))))
        idx[tuple(sorted(pairs))] = state_id

    def dfs(c_used, r_used, pairs):
        key = tuple(sorted(pairs))
        if key in idx:
            return
        idx[key] = len(states)
        states.append(key)
        for c in range(n):
            if c in c_used:
                continue
            for r in range(n):
                if r in r_used:
                    continue
                nc = set(c_used)
                nr = set(r_used)
                nc.add(c)
                nr.add(r)
                dfs(nc, nr, pairs + [(c, r)])

    dfs(set(), set(), [])
    return states, idx

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    states, idx = build_states(n)
    S = len(states)

    T = sum(a)
    p = [x * pow(T, MOD - 2, MOD) % MOD for x in a]

    reward = [0] * S
    trans = [[0] * S for _ in range(S)]

    for s_id, state in enumerate(states):
        used_c = set()
        used_r = set()
        for c, r in state:
            used_c.add(c)
            used_r.add(r)
        reward[s_id] = sum(b[c * n + r] for c, r in state)

        for t, prob in enumerate(p):
            c = t // n
            r = t % n

            new_state = set(state)
            conflict = False
            for cc, rr in list(state):
                if cc == c or rr == r:
                    conflict = True
                    new_state.discard((cc, rr))

            if conflict:
                nxt = tuple(sorted(new_state))
            else:
                if (c, r) in state:
                    nxt = tuple(sorted(state))
                else:
                    nxt = tuple(sorted(state + [(c, r)]))

            j = idx[nxt]
            trans[j][s_id] = (trans[j][s_id] + prob) % MOD

    M = [[0] * (S + 1) for _ in range(S + 1)]

    for i in range(S):
        for j in range(S):
            M[j][i] = trans[j][i]

    for i in range(S):
        M[i][S] = 0

    for j in range(S):
        M[S][j] = reward[j]
    M[S][S] = 1

    def mat_mul2(A, B):
        n = len(A)
        res = [[0] * n for _ in range(n)]
        for i in range(n):
            for k in range(n):
                if A[i][k]:
                    aik = A[i][k]
                    for j in range(n):
                        res[i][j] = (res[i][j] + aik * B[k][j]) % MOD
        return res

    def mat_pow2(M, e):
        n = len(M)
        res = [[0] * n for _ in range(n)]
        for i in range(n):
            res[i][i] = 1
        while e:
            if e & 1:
                res = mat_mul2(res, M)
            M = mat_mul2(M, M)
            e >>= 1
        return res

    P = mat_pow2(M, k)

    init = [0] * (S + 1)
    init[0] = 1

    ans = 0
    for i in range(S + 1):
        ans = (ans + P[i][0] * init[0]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、すべての有効な手の構成を部分一致として列挙することから始まります。 n は最大 4 であり、小さい状態空間が保証されるため、この列挙は安全です。 

各トランジションは、すべてのカード タイプを反復処理し、エッジを追加するか競合するエッジをクリアするかの決定的なルールを適用することによって計算されます。 各移行の確率は、固定デッキの分布から直接導出されます。 

次に、状態の進化とともに期待される報酬を蓄積するために、行列が 1 次元拡張されます。 マトリックスの最後の行は、各状態に入るときにどれだけの報酬が寄付されるかをエンコードします。 べき乗は、すべての k ステップを対数時間で適用します。 

実装の微妙な詳細は、複数のアクションが同じ次の状態につながる場合に、遷移が正しく蓄積されるようにすることです。 もう 1 つは、特に確率を乗算する場合に、すべての演算をモジュロ演算で一貫して行うことです。 

## 実用的な例

 n = 2 でカウントが非常に小さいため、少数の状態のみに到達できる最小限のシナリオを考えてみましょう。 状態は、空のマッチング、片エッジのマッチング、および完全なマッチングで構成されます。 

空の状態からの遷移を追跡します。 描画されたタイプはいずれも新しいエッジを追加するか、競合するエッジを削除しますが、空からはすべてが加算されます。 

| ステップ | 現在の状態 | アクション | 次の状態 | 報酬 |
 | --- | --- | --- | --- | --- |
 | 1 | ∅ | 描画 (1,1) | {(1,1)} | b11 |
 | 2 | {(1,1)} | 描画 (1,2) 競合 | ∅ | 0 |

 これは、競合リセットが直線的に蓄積するのではなく、システム全体にどのように伝播するかを示しています。 

2 番目の例では、すでに一致するものが含まれている状態を考慮します。 互換性のあるエッジを描画するとマッチングが延長され、報酬が増加しますが、競合するエッジを描画するとマッチングがリセットされます。 これは、報酬がアクション自体ではなく、結果として得られる状態のみに依存することを示しています。

 ## 特殊なケース

 手を伸ばす可能性があるたびにすぐに競合が発生する場合、重大なエッジケースが発生します。 このようなシナリオでは、プロセスは空の状態と小さな一致の間で変動します。 遷移行列には加算遷移と完全クリア遷移の両方が含まれており、確率質量が確実に保持されるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、1 つのタイプを除くすべての ai がゼロである場合です。 システムは決定論的になり、マルコフ連鎖は単一の反復動作に崩​​壊します。 すべての確率が状態ごとに 1 つの遷移に集中するため、行列の定式化はこれを自然に処理します。

 最後のエッジ ケースは、n = 2 の最小構成です。ここでは状態空間が最小であり、手動検証により、行列のべき乗がすべての可能な描画シーケンスの直接の列挙と一致することが確認されます。
