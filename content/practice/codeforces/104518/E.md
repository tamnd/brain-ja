 ## 解決策
 ## 問題の理解

 各店舗が固定サイズのパッケージを販売している場合に、正確なジャガイモの合計数を達成できるさまざまな購入計画が何通りあるかを数えるように求められます。 ストア i の場合、すべてのパッケージが 2 つのポテトを提供し、各ストアから負でない数のパッケージを選択します。 面白いのは、ストア 1 は制限されているということです。ストア 1 からは t 個を超える荷物を受け取ることができませんが、他のすべてのストアでは無制限に利用可能です。 

プランは、パッケージ数のベクトル (店舗ごとに 1 つ) によって完全に決定されます。 たとえジャガイモの合計数が同じであっても、店舗によって使用されるパッケージの数が異なる場合、2 つのプランは異なります。 

ターゲットの合計 B は最大 10^18 と非常に大きくなる可能性がありますが、各パッケージ サイズ bi は小さく、すべての bi の合計は最大 500 です。この組み合わせが重要な構造上のヒントです。ターゲットの合計は巨大ですが、それを構築する「ステップ サイズ」は小さいです。 

単純な動的プログラミングのアプローチでは、f[x] を x 個のポテトを形成する方法の数として定義し、B までのすべての値を計算しようとします。B は反復処理するには大きすぎるため、これはすぐに失敗します。 

2 番目の単純なアイデアは、これを制限付きコイン変更問題として扱い、パッケージ数のすべての組み合わせを列挙しようとすることです。 店舗ごとの適度な数でも天文学的に多くの状態が生成されるため、これは組み合わせ的に爆発的に増加します。 

bi または何らかの小さなキャップの合計までしか計算しようとしない場合、より微妙な失敗のケースが発生します。 有効な組み合わせでは、多くのパッケージを使用すると非常に大きな合計が蓄積される可能性があるため、これは正確性を失います。 

本当の難しさは、答えが非常に高次の母関数の係数に依存する一方で、それを定義する漸化式の局所性が非常に小さいことです。 

## アプローチ

 この問題は当然、固定重みを持つ無制限の数のアイテムに対する計数問題です。 ストア 1 の制限をしばらく無視すると、各ストアは生成関数で等比級数に寄与します。 

1 + x^{bi} + x^{2bi} + ...

 これらをすべてのストアに対して乗算すると、x^B の係数が答えとなる有理生成関数が得られます。 

ストア 1 の制限を含めると、その寄与は切り捨てられた幾何級数になります。 

1 + x^{b1} + x^{2b1} + ... + x^{t b1}

 したがって、完全な母関数は、1 つの切り詰められた幾何級数といくつかの無限幾何級数の積になります。 

ブルートフォース手法では、この畳み込みを明示的に拡張し、B までの係数を計算します。問題は、B が最大 10^18 であるため、DP 配列を保存することさえ不可能であることです。 必要な作業は B の N 倍に比例しますが、これはまったく実行不可能です。 

重要な観察は、線形再発の観点から問題を書き直すことから得られます。 各係数 f[s] は値 f[s - bi] のみに依存します。ストア i からパッケージをもう 1 つ追加すると、合計が bi だけ増加するためです。 これは、f のシーケンスが最大でも max(bi) 個の前項 (max(bi) ≤ 500) を持つ漸化式によって支配されることを意味します。 

これにより、問題は「B まで計算する」から「最大 500 次の線形漸化式の B 番目の項を計算する」に変換されます。 

ストア 1 の制限により、漸化式がわずかに変更されます。つまり、無限の幾何級数に寄与する代わりに、有限の畳み込みウィンドウに寄与します。 これにより、t パッケージを超える寄与を差し引く補正項が導入されます。 

漸化式が確立されると、問題は古典的なタスクになります。北政アルゴリズムや 500 次元状態の行列累乗などの方法を使用して、線形漸化式の遠項を効率的に計算するというものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DP 最大 B | O(N・B) | O(B) | 遅すぎる |
 | 線形回帰 + 北正 | O(N·M^2 log B) ただし、M ≤ 500 | O(M^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 合計 s を形成する方法の数である f[s] の漸化式を構築します。

1. f[0] = 1 と定義します。これは、ゼロを形成する方法が 1 つだけあるためです。それは、何も選択しないことです。 
2. すべての合計 s について、 s の構築で使用された最後のパッケージを考慮します。 最後のパッケージがストア i からのものである場合、前の状態は s - bi でなければなりません。 これにより、各ストアが f[s - bi] を f[s] に寄与する基本反復が得られます。 
3. ストア 1 を慎重に組み込みます。 ストア 1 は通常、b1 の倍数すべてを提供しますが、t 個を超えるパッケージは許可されません。 これは、ストア 1 を t 回以上使用するシーケンスは除外する必要があることを意味します。 関数を生成するという点では、無限の幾何級数を有限の幾何級数に置き換えます。これは、ストア 1 の (t+1) 回以上の使用を含む寄与を差し引くことと同等です。 
4. この減算は、再帰式の補正項に変換されます。(t+1)*b1 を超えると、ストア 1 の許可された使用量を事実上「ロールオーバー」した構成を削除する必要があります。これは、f[s - (t+1)b1] を含む追加の減算としてエンコードできます。 
5. 単純化した後、すべての依存関係が最大 max(bi) のサイズのシフト内にあり、すべての補正も制限されたシフトであるため、次数が最大 500 の固定線形再帰が得られます。 
6. この範囲は小さいため、標準の有界ナップザック DP を使用して M = max(bi) まで直接初期値 f[0..M-1] を計算します。 
7. 次に、線形再帰に対する高速累乗法を使用して f[B] を計算します。 状態遷移は対数ステップで繰り返し適用されるため、B ステップから log B 遷移までの計算が削減されます。 

### なぜ効果があるのか

 すべての構成はパッケージ選択のマルチセットに対応し、そのようなマルチセットはすべて、反復を通る 1 つのパスにのみ寄与します。 sum の有効な構成はすべて、最後のパッケージ選択 1 つで終了する必要があり、ストア 1 に対する制限が補正項を通じてグローバルに適用されるため、反復は完了します。 すべての遷移は、境界付きオフセット内の以前の値にのみ依存するため、システムは有限線形漸化式によって完全に捕捉され、固定された初期セグメントから将来のすべての項を一意に決定します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

# We will build a linear recurrence of order M = max(bi)
# f[s] depends on f[s - bi] and a correction for store 1.
#
# Then we compute f[B] using Kitamasa (linear recurrence exponentiation).

def add(a, b):
    return (a + b) % MOD

def sub(a, b):
    return (a - b) % MOD

def main():
    N, B = map(int, input().split())
    b = list(map(int, input().split()))
    t = int(input())

    b1 = b[0]

    M = max(b)

    # dp up to M to initialize recurrence
    dp = [0] * (M)
    dp[0] = 1

    for i in range(N):
        w = b[i]
        for s in range(w, M):
            dp[s] = (dp[s] + dp[s - w]) % MOD

    # apply restriction on store 1 using inclusion-exclusion idea
    # subtract sequences using (t+1) copies of store 1
    if t >= 0:
        shift = (t + 1) * b1
        if shift < M:
            for s in range(shift, M):
                dp[s] = (dp[s] - dp[s - shift]) % MOD

    # linear recurrence coefficients
    # f[s] = sum f[s - bi] - correction already encoded in base DP
    coeff = [0] * M
    for w in b:
        coeff[w - 1] += 1

    # Kitamasa implementation
    def combine(a, bvec):
        res = [0] * (2 * M)
        for i in range(M):
            for j in range(M):
                res[i + j] = (res[i + j] + a[i] * bvec[j]) % MOD

        for i in range(2 * M - 1, M - 1, -1):
            if res[i]:
                for j in range(1, M + 1):
                    res[i - j] = (res[i - j] + res[i] * coeff[j - 1]) % MOD
        return res[:M]

    def kitamasa(n):
        if n < M:
            return dp[n]

        base = [0] * M
        base[0] = 1

        trans = [0] * M
        trans[1] = 1

        def power(n):
            if n == 1:
                return trans
            half = power(n // 2)
            half = combine(half, half)
            if n % 2:
                half = combine(half, trans)
            return half

        v = power(n)
        ans = 0
        for i in range(M):
            ans = (ans + v[i] * dp[i]) % MOD
        return ans

    print(kitamasa(B))

if __name__ == "__main__":
    main()
```この解決策は、再発構造を決定するのに十分な M までのすべての状態を構築することから始まります。 このプレフィックスは、各状態が以前の状態にどのように依存するかをエンコードします。 

ストア 1 の修正は、この初期化フェーズ内で包含除外調整として直接適用され、繰り返しが抽出される前に t use を超える無効なシーケンスが確実に削除されます。 

北正パートは問題を線形漸化システムとして扱い、B まで反復せずに B 番目の項を計算します。重要な詳細は、サイズが最大 500 のベクトルのみを操作するため、すべての遷移が実行可能な範囲内に留まるということです。 

よくある落とし穴は、標準のナップザック DP を実行してから「拡張」しようとすることですが、B が大きすぎるためにすぐに失敗します。 もう 1 つは、反復内のストア 1 制限を無視することです。これにより、制約に違反するシーケンスが過剰にカウントされます。

1
```サイズ 1 を製造する同一の店舗が 2 つあり、店舗 1 からのパッケージは最大 1 つです。 

| ステップ | dp[0] | dp[1] | dp[2] | dp[3] |
 | --- | --- | --- | --- | --- |
 | イニシャル | 1 | 0 | 0 | 0 |

 これは、制限のない増加がどのようにオーバーカウントされるか、また制約によってより高い組み合わせがどのように減少するかを示しています。 

### 例 2

 入力:```
3 10
1 2 3
2
```ストア 1 (重み 1) の使用は最大 2 回まで許可され、その他の使用は無制限になります。 

すべての重みが小さく、M = 3 までの dp が完全な依存構造を捕捉するため、再帰はすぐに安定します。 最終計算では、すべての中間合計を展開するのではなく、漸化式を使用して B = 10 に直接ジャンプします。 

これは、アルゴリズムが B に直接依存することはなく、遷移の構造にのみ依存することを示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、t = 0 の場合です。その状況では、ストア 1 はまったく使用できません。 この繰り返しにより、そのコインは完全に無視され、ストア 2..N のみが貢献します。 包含/除外減算によってストア 1 に関係するすべての寄与が削除されるため、初期化によってこれが処理されます。 

もう 1 つのエッジ ケースは、すべての bi が 1 に等しい場合です。この場合、すべての状態に到達可能ですが、ストア 1 の制限が唯一の制限要因になります。 有界幾何級数が最初のストアからの寄与を直接制限するため、反復は引き続き機能します。 

3 番目のエッジ ケースは、B がすべての bi より小さい場合です。 この場合、答えは B = 0 の場合は 1、そうでない場合は 0 のいずれかであり、DP の初期化では再帰機構を呼び出すことなくすでにこれを取得しています。
