 ## 解決策
 ## 問題の理解

 私たちは、各位置が土地のプロットを表す一連の値を長期にわたって維持しています。 配列は、セグメント内のすべての要素に値を追加する範囲更新を通じて変更されます。 進化する配列に加えて、各位置は現在の値だけでなく、更新履歴の任意の時点で到達した最大値を記憶します。 

操作は 2 つあります。 1 回の操作で、セグメント内のすべての値が負の量だけ増加します。 もう 1 つは、セグメントにわたる過去の最大値の合計を要求します。 主な難点は、クエリが現在の配列状態だけではなく、過去の進化全体に依存していることです。 

制約は最大 30 万操作に及ぶため、更新またはクエリごとに各要素に触れるソリューションは直ちに遅すぎます。 直接シミュレーションには O(nq) のコストがかかりますが、これは実現不可能です。 更新とクエリの両方が広範囲に及ぶ可能性があるため、クエリごとのセグメントの再計算でさえ遅すぎます。 

微妙なエッジケースとして、更新により値が負になる可能性があります。 これは、最大値が必ずしも現在の値であるとは限らず、複数のネガティブな更新の前の以前の状態から取得される可能性があるため重要です。 たとえば、単一の要素が 5 で始まり、10 に増加し、その後 3 に減少した場合、現在の値が 3 であっても、その楽観的な値は 10 のままです。現在の値のみを追跡するソリューションはここで失敗します。 

もう 1 つの重要なケースは、更新の重複です。 セグメントは異なる間隔で複数回増加する可能性があるため、各位置には複雑な増加履歴が発生します。 課題は、位置ごとに、範囲追加の動的なシーケンスの下でこれまでに達成された最大プレフィックス合計を追跡することです。 

## アプローチ

 ブルートフォース手法では、配列と、位置ごとの過去の最大値を格納する 2 番目の配列を明示的に維持します。 タイプ 1 の更新ごとに、セグメントを反復処理して各要素に x を追加します。また、新しい値が最大値を超える場合は最大値も更新します。 クエリの場合、保存されている最大値を合計します。 

これは問題の定義に直接従うため、正しいです。 ただし、各更新は O(n) 要素に触れる可能性があり、最大 3e5 の操作があります。 最悪の場合、これにより約 1e10 の操作が発生し、これは実行可能な制限をはるかに超えます。 

重要な観察は、範囲の追加の下で各位置が独立して進化し、範囲の追加が線形演算であるということです。 これは、各インデックスを個別に触ることは避けるべきであることを示唆しています。 代わりに、範囲加算クエリと範囲合計クエリをサポートするデータ構造が必要ですが、追加の複雑さが伴います。また、これまでに到達した各位置の最大プレフィックス値を維持する必要もあります。 

これにより、問題はセグメント上で 2 つの値、つまり加算範囲更新での現在値と過去の最大値を維持することに変わります。 遅延伝播を備えた標準のセグメント ツリーは自然なツールですが、単なる合計や最大値以上のものが必要です。 増分を伝播するだけでなく、これらの増分が過去の最大値にどのように影響するかを追跡する必要があります。 標準的な方法は、セグメントごとに現在値と最大値の両方を保存し、均一な加算が両方にどのような影響を与えるかを慎重に定義することです。 

x の範囲を追加すると、現在の値は x だけ増加し、過去の最大値も x だけ増加しますが、これは過去のすべての値も x だけシフトするという事実と一致する形でのみです。 これは、現在と最大の両方が均一にシフトすることを意味します。 本当に難しいのは、最大値を正しく集計する必要がある部分セグメントをクエリする場合です。 

これは、各ノードが現在の値の合計と過去の最大値の合計を維持するセグメント ツリーによって処理でき、範囲増分の遅延伝播が両方のフィールドに均一に適用されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 遅延伝播を使用したセグメント ツリー | O(q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードがセグメント内の現在の値の合計とセグメント内の過去の最大値の合計を保存するセグメント ツリーを維持します。 また、セグメントに適用する必要がある保留中の追加を表す遅延タグも維持します。 

1. 初期配列からセグメント ツリーを構築し、現在の合計と過去の最大合計の両方を初期値に設定します。 これは正しいです。なぜなら、最初は各値がそれ自体を最大値としてのみ認識しているからです。 
2. x を [l, r] に追加する範囲更新の場合、ツリーを下降します。 ノードが完全にカバーされると、更新を直接適用します。現在の合計をセグメント長の x 倍に増やし、過去の最大合計もセグメント長の x 倍に増やします。 また、x を遅延タグに蓄積します。 
3. ノードが部分的にカバーされている場合は、続行する前に保留中の遅延値をプッシュダウンします。 これにより、さらに更新される前に、子が正しい値を表すことが保証されます。 
4. [l, r] に関するクエリの場合、完全にカバーされたノードからの結果を集計します。 各ノードは現在の合計と過去の最大合計の両方に寄与しますが、出力に必要なのは後者のみです。 
5. 重要な微妙な点は、遅延伝播では一貫性を維持する必要があるということです。セグメントが x だけシフトされるたびに、そのセグメント内のすべての過去の値が x ずつ増加するため、現在履歴と最大履歴の両方が同じようにシフトします。 

なぜそれが機能するのかは、単純な不変条件に関係しています。 すべての時点で、すべてのセグメント ツリー ノードについて、保存された履歴最大合計は、そのセグメント内のすべてのインデックスにわたる、これまでに適用されたすべての更新でインデックスが達成した最大値の合計と等しくなります。 範囲の加算によりすべての履歴値が均一にシフトされるため、最大値も均一にシフトされ、マージと分割にわたって正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.sum = [0] * (4 * self.n)
        self.mx = [0] * (4 * self.n)
        self.lazy = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, v, tl, tr, arr):
        if tl == tr:
            self.sum[v] = arr[tl]
            self.mx[v] = arr[tl]
            return
        tm = (tl + tr) // 2
        self.build(v*2, tl, tm, arr)
        self.build(v*2+1, tm+1, tr, arr)
        self.pull(v)

    def pull(self, v):
        self.sum[v] = self.sum[v*2] + self.sum[v*2+1]
        self.mx[v] = self.mx[v*2] + self.mx[v*2+1]

    def apply(self, v, tl, tr, val):
        self.sum[v] += val * (tr - tl + 1)
        self.mx[v] += val * (tr - tl + 1)
        self.lazy[v] += val

    def push(self, v, tl, tr):
        if self.lazy[v] != 0:
            tm = (tl + tr) // 2
            self.apply(v*2, tl, tm, self.lazy[v])
            self.apply(v*2+1, tm+1, tr, self.lazy[v])
            self.lazy[v] = 0

    def update(self, v, tl, tr, l, r, val):
        if l > r:
            return
        if l == tl and r == tr:
            self.apply(v, tl, tr, val)
            return
        self.push(v, tl, tr)
        tm = (tl + tr) // 2
        self.update(v*2, tl, tm, l, min(r, tm), val)
        self.update(v*2+1, tm+1, tr, max(l, tm+1), r, val)
        self.pull(v)

    def query(self, v, tl, tr, l, r):
        if l > r:
            return 0
        if l == tl and r == tr:
            return self.mx[v]
        self.push(v, tl, tr)
        tm = (tl + tr) // 2
        return self.query(v*2, tl, tm, l, min(r, tm)) + \
               self.query(v*2+1, tm+1, tr, max(l, tm+1), r)

def main():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))
    st = SegTree(arr)

    out = []
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            _, l, r, x = tmp
            l = int(l) - 1
            r = int(r) - 1
            x = int(x)
            st.update(1, 0, n-1, l, r, x)
        else:
            _, l, r = tmp
            l = int(l) - 1
            r = int(r) - 1
            out.append(str(st.query(1, 0, n-1, l, r)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```セグメント ツリーは標準的な方法で構築され、各ノードにはその間隔の集計情報が保存されます。 の`apply`関数は中核です。現在の合計と過去の最大値の両方に均一なシフトを適用します。 これは、セグメント内のすべての値が均一に増加するため、過去のすべての最大値も同じオフセットだけ増加するため有効です。 

遅延伝播により、必要な場合を除き、セグメントに下降することが回避されます。 プッシュ ステップでは、子を部分的に更新する前に正確性を保証します。 

この問題では過去の最大値の合計が求められるため、クエリ関数には保存された最大合計のみが必要です。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ネガティブな更新が繰り返されることです。 値はピークに達した後に減少する可能性があるため、最大値は過去の最高値に固定されたままでなければなりません。 max フィールドは現在の値と同じデルタだけ増加し、減少することはないため、セグメント ツリーはこれを処理します。 

もう 1 つの特殊なケースは、同じセグメント上で更新が繰り返されることです。 遅延伝播により、複数の保留中の増分が正しく蓄積されることが保証されます。 各ノードは、部分的なトラバースの前にすべての保留中のシフトを集約し、重度のオーバーラップの下でも正確さを維持します。 

最後のエッジケースは、交互更新下の単一要素セグメントです。 セグメント ツリーは引き続きそれらをリーフの完全なセグメントとして扱うため、現在値と最大値の両方が同様に変化し、保存された値とクエリされた値の間に不一致が生じないようにします。
