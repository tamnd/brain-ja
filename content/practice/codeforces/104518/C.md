 ## 解決策
 ## 問題の理解

 一連の月次売上値と固定ウィンドウ サイズが与えられます。$K$。 連続する長さのセグメントごとに$K$、その平均売上を計算します。 すべてのウィンドウの長さは同じであるため、平均を比較することは合計を比較することと同じです。 

タスクは、最小合計を持つウィンドウの最も早い開始インデックスと最大合計を持つウィンドウの最も早い開始インデックスの 2 つの位置を識別することです。 

ここでの重要な構造は、値だけで単一の最適なウィンドウを選択するのではなく、最も早い出現に基づいて同点分割ルールも適用するということです。 これにより、等しい和の扱い方が変わります。同じ値が再び表示されたときに、以前のインデックスを上書きしてはなりません。 

制約は以下に達します$10^5$これにより、すべてのウィンドウの合計を最初から再計算することが排除されます。 各ウィンドウを個別に合計する単純なアプローチでは、$O(NK)$、両方の場合に大きすぎます。$N$そして$K$大きいです。 

複数のウィンドウが同じ最小値または最大値の合計を共有する場合、エッジ ケースが発生します。 インデックスを更新する不注意な実装`<=`または`>=`厳しいのではなく`<`または`>`最初に出現した位置ではなく、後の位置が誤って選択されます。 

もう一つの微妙なケースは次のような場合です。$K = 1$。 この場合、すべての要素は独自のウィンドウとなり、答えは配列の最小値と最大値の最初の出現に帰着します。 

## アプローチ

 ブルートフォース手法は、ウィンドウを反復処理することにより、すべてのウィンドウの合計を計算します。$K$要素。 これは正しいですが、繰り返しは非常に負荷がかかります。$N-K+1$窓のコスト$O(K)$、につながる$O(NK)$。 で$10^5$、これでは遅すぎます。 

改善は重複を観察することで実現します。 隣接する窓の共有$K-1$したがって、出力要素を減算し、入力要素を加算することで、一定時間で合計を更新できます。 このスライディング ウィンドウ手法により、複雑さが線形時間に軽減されます。 

各ウィンドウの合計を取得したら、$O(1)$、最小値と最大値の追跡は、慎重なタイブレークを使用した単一パスになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(NK)$|$O(1)$| 遅すぎる |
 | スライディングウィンドウ |$O(N)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 最初のウィンドウの合計を維持し、最小値と最大値を更新しながら配列全体でそれをスライドさせます。 

1. 最初の合計を計算します。$K$要素。 これにより、現在のウィンドウと比較用のベースラインの両方が初期化されます。 
2. 最良の最小値と最良の最大値の両方をこの最初の合計に設定し、両方のインデックス 1 を記録します。 
3. ウィンドウを左から右に 1 ステップずつ移動します。 
4. ステップごとに、ウィンドウから出ていく要素を減算し、入ってくる新しい要素を加算することにより、現在の合計を更新します。 
5. 新しい合計が最良の最小値よりも厳密に小さい場合は、最小値を更新し、現在のインデックスを保存します。 
6. 新しい合計が厳密に最良の最大値よりも大きい場合は、最大値を更新し、現在のインデックスを保存します。 

厳密な比較が不可欠です。 非厳密な比較を使用すると、以前の有効な回答が上書きされ、最初に出現したものを返すという要件に違反することになります。 

### なぜ効果があるのか

 考えられるすべてのウィンドウが順番に 1 回だけ検査されます。 スライディングサムにより各ウィンドウ値の正確さが保証され、単調更新により、厳密に優れた候補のみが現在の最良の候補と置き換わることが保証されます。 同点を上書きすることはないため、最初の出現は構築によって保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    v = list(map(int, input().split()))

    window_sum = sum(v[:k])

    min_sum = window_sum
    max_sum = window_sum
    min_idx = 1
    max_idx = 1

    for i in range(k, n):
        window_sum += v[i] - v[i - k]
        start_idx = i - k + 2

        if window_sum < min_sum:
            min_sum = window_sum
            min_idx = start_idx

        if window_sum > max_sum:
            max_sum = window_sum
            max_idx = start_idx

    print(min_idx, max_idx)

if __name__ == "__main__":
    solve()
```実装は、入力を読み取り、最初のウィンドウ合計を明示的に計算することから始まります。 その後、ループはスライディング ウィンドウを不変に維持します。 インデックスの計算`i - k + 2`ゼロベースの右端点を 1 ベースのウィンドウ開始点に変換します。 

比較では、最初の出現要件を維持するために厳密な不等式が使用されます。 これは、この問題における最も一般的なバグの原因です。`<=`または`>=`同点の正しさを静かに破ります。

 ## 特殊なケース

 すべてのウィンドウの合計が同じである場合、アルゴリズムは最小値と最大値の両方の最初のインデックスを保存する必要があります。 これは、厳密な改善が行われた場合にのみ更新が行われるため、初期インデックスは変更されないままであることが保証されています。 

いつ$K = 1$、各要素は独自のウィンドウです。 スライディング メカニズムは引き続き機能します。更新のたびに前の合計が新しい要素に置き換えられ、比較により最初に出現した最小値と最大値が正確に識別されます。 

すべての値が等しい場合、すべてのウィンドウ合計は同一であるため、更新はトリガーされません。 出力はそのまま残ります`(1, 1)`、これは最初の出現の選択の要件に一致します。
