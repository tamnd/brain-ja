 ## 解決策
 ## 問題の理解

 一列に配置された 2N 個のコインの値のシーケンスが与えられます。 2 人のプレーヤーが交互に 1 手ごとに 1 枚のコインを取り除き、残ったコインの左端または右端のいずれかを選択します。 Technoblade が最初に動き、Skeppy が 2 番目に動き、すべてのコインが取られるまで続きます。 各プレイヤーは、自分が選んだコインの価値を合計します。 Technoblade は、最終スコアに +1 のアドバンテージを追加した状態でゲームを開始します。 

ひねりは相手がどう行動するかにあります。 スケッピーは戦略的ではありません。彼は常に利用可能な 2 つの端のうち大きい方を選択し、両方の端が等しい場合は正しい方を選択します。 対照的に、テクノブレードは最適なプレーをしており、私たちは彼から完璧なプレーの下で何が起こるかを評価するよう求められています。 

出力は勝者の分類だけでなく、Technoblade が勝つことができる場合、N ターンごとに左からとるべきか右からとるべきかを説明する一連の動きの完全なシーケンスでもあります。 すべての勝利戦略の中で、辞書編集的に最小のシーケンスを出力する必要があります。これは、両方が同等に優れている場合、「R」よりも早い「L」が優先されることを意味します。 

N ≤ 2500 という制約は、コインの総数が最大 5000 であることを意味します。区間にわたる 3 次解法では遅すぎる可能性がありますが、2 次動的計画法のアプローチは実現可能です。 O(N^2) 個の状態遷移よりも悪いものは生き残れません。 

Technoblade で考えられるすべての移動シーケンスを試す単純なシミュレーションは不可能です。これは、分岐係数が N ステップで 2 であり、2^N 通りの可能性があるためです。 スケッピーの決定論的だが価値主導の行動により、将来の状態が早期の決定に大きく依存するため、貪欲な推論も失敗します。 

Technoblade による貪欲な選択が局所的には最適に見えても、将来の柔軟性が低下する場合、微妙なエッジ ケースが発生します。 たとえば、早い段階で大きなコインを手に入れると、スケッピーは将来の最適な利益を破壊するパターンに強制される可能性があります。 もう 1 つのエッジ ケースは、辞書編集順のタイブレークがスコア最適化の選択肢と競合する場合に発生し、DP 状態がスコアだけでなく再構成の優先順位も追跡する必要がある場合です。 

## アプローチ

 この強引なアイデアは、Technoblade の N 個の選択肢のすべての可能なシーケンスをシミュレートすることです。 各シーケンスについて、Skeppy の貪欲なポリシーに対してゲームを完全にシミュレートし、最終スコアを計算します。 これは、考えられるすべての決定を検討するため正しいですが、シーケンスの数は 2^N であり、各シミュレーションのコストは O(N) であるため、O(N・2^N) となり、実現可能な限界をはるかに超えています。 

重要な観察は、各手の後のゲームの状態は、現在の残りのコインの間隔と誰のターンであるかによって完全に決定されるということです。 スケッピーの行動は決定的であるため、テクノブレードの観点から見ると、実際の決定点は彼自身のターンだけですが、それらの決定は構造化された方法で将来の間隔に影響を与えます。 これにより、問題は区間動的計画法に変わります。ここでは、状態が部分配列を表し、次にその順番が決まります。 

決定的な問題は、Skeppy の貪欲な動作はエンドポイントのみに依存するため、すべての遷移が現在の間隔に対してローカルであることです。 これにより、Skeppy の固定ルールを除いて、両方のプレイヤーが最適に行動した場合のすべての間隔の結果を事前計算できます。 次に、各状態で Technoblade の 2 つの可能な動きをシミュレートし、最良の結果を伝播します。 

間隔 [l, r] にわたる DP を定義し、Technoblade のターンであると仮定して、その状態からのゲームの結果を保存します。これには、結果として生じるスコアの差と決定を再構築する方法が含まれます。 トランジションは、左または右への移動をシミュレートし、再度 Technoblade の番になるか、間隔が予測可能な方法で変化するまで、Skeppy の貪欲な応答を繰り返し適用します。 

各間隔は 1 回処理され、遷移は O(1) で償却されるため、全体の複雑さは O(N^2) になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N · 2^N) | O(N) | 遅すぎる |
 | インターバルDP | O(N^2) | O(N^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 各状態を、Technoblade の順番となる残りの配列のセグメントとして扱います。 その状態から、彼は一番左または一番右のコインを選択し、制御がテクノブレードに戻るまでスケッピーは貪欲に反応します。 DP は、結果として生じる最終スコア差をエンコードし、最良の動きシーケンスの再構築も可能にする必要があります。 

1. l から r までのコインが残っている Technoblade のターンであると仮定して、dp[l][r] を可能な限り最良の結果 (Technoblade のスコア差から Skeppy を差し引いた、+1 アドバンテージを含む) として定義します。 
2. 固定間隔 [l, r] について、左ピックまたは右ピックという 2 つの候補の動きをシミュレートします。 各選択は、テクノブレードにそのコインの価値とその後の結果を即座に与えます。 
3. Technoblade がピックした後、Skeppy の動きに切り替えます。 Skeppy は a[l] と a[r] を比較し、等しい場合には大きい方または右側を採用します。 このステップにより、間隔が 1 つ減少します。 
4. 再びテクノブレードのターンになるまで、スケッピーの強制貪欲な動きを交互に続けます。これは、より短い間隔で dp を評価する状態に到達するのと同じです。 
5. 各候補 (左または右) について、以前に計算されたより小さい間隔を使用して結果の dp 値を計算します。 反復は、厳密に短い長さの部分問題の dp にのみ依存します。 
6. Technoblade の最終的なスコア差を最大化する手を選択します。 両方が等しい場合は、辞書編集的に移動が小さい方を選択します。これは、「R」よりも「L」を優先することを意味します。 

構造上の重要な点は、Skeppy が分岐を導入しないことです。 Skeppy のすべての動きは決定的であるため、Technoblade の各決定は次のインターバルに正確に 1 つつながり、DP 移行が明確になります。 

### なぜ効果があるのか

 両方のプレーヤーの動作は履歴ではなくエンドポイントのみに依存するため、すべての状態は残りのインターバルによって完全に特徴付けられます。 Skeppy の貪欲なルールにより決定論が保証されるため、任意の (l、r) から、考えられるテクノブレードのアクションはそれぞれ 1 つの次の状態につながります。 したがって、DP は最適な下部構造を捕捉します。つまり、Technoblade がサイドを選択すると、ゲームの残りの部分は以前の決定とは独立しており、すでに解決されたサブインターバルの結果は有効なままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def simulate_after_first_take(a, l, r, take_left):
    if take_left:
        l += 1
    else:
        r -= 1

    skeppy_turn = True

    while l <= r:
        if skeppy_turn:
            if a[l] > a[r]:
                l += 1
            elif a[l] < a[r]:
                r -= 1
            else:
                r -= 1
        else:
            break
        skeppy_turn = not skeppy_turn

    return l, r

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    N = n
    dp = [[0] * (2 * N) for _ in range(2 * N)]
    nxt = [[None] * (2 * N) for _ in range(2 * N)]

    for length in range(1, 2 * N + 1):
        for l in range(0, 2 * N - length + 1):
            r = l + length - 1

            if length == 1:
                dp[l][r] = a[l] + 1
                nxt[l][r] = 'L'
                continue

            best_val = -10**18
            best_move = 'L'

            nl, nr = simulate_after_first_take(a, l, r, True)
            val_left = a[l] + (dp[nl][nr] if nl <= nr else 0)

            if val_left > best_val:
                best_val = val_left
                best_move = 'L'

            nl, nr = simulate_after_first_take(a, l, r, False)
            val_right = a[r] + (dp[nl][nr] if nl <= nr else 0)

            if val_right > best_val:
                best_val = val_right
                best_move = 'R'

            dp[l][r] = best_val
            nxt[l][r] = best_move

    total = dp[0][2 * N - 1]

    if total <= 0:
        if total == 0:
            print("tie")
        else:
            print(":(")
        return

    print("TECHNOBLADE NEVER DIES!")

    l, r = 0, 2 * N - 1
    res = []

    for _ in range(N):
        move = nxt[l][r]
        res.append(move)

        if move == 'L':
            l += 1
        else:
            r -= 1

        l, r = simulate_after_first_take(a, l, r, True)

    print("".join(res))

if __name__ == "__main__":
    solve()
```DP テーブル dp[l][r] には、その間隔で Technoblade が達成可能な最高のスコア差が保存されます。 nxt テーブルは、左を取るか右を取るかがその最適値につながるかを記録し、後で辞書編集上最小の勝利戦略を再構築するために使用されます。 

ヘルパー関数 Simulate_after_first_take は、Skeppy の強制的な貪欲な応答をすべて 1 つの結果の間隔に圧縮します。 これは、DP 遷移中に交互の各ステップを明示的にシミュレートすることを回避し、遷移 O(1) の償却を維持するため、非常に重要です。 

再構築ループは選択された動きを再生し、Skeppy の決定論的応答を繰り返し適用して DP モデルとの一貫性を維持します。 

微妙な点の 1 つは、長さ 1 の間隔に対する dp の初期化です。 その時点で Technoblade は唯一のコインを獲得し、すぐに +1 アドバンテージを獲得するため、値は a[l] + 1 となります。

 ## 特殊なケース

 すべてのコインの価値が等しい場合、1 つのエッジ ケースが発生します。 この状況では、スケッピーのルールは常に右側を優先し、区間の展開に一貫した方向への偏りを与えます。 DP は引き続き Technoblade の両方の選択を対称的に評価し、辞書編集的な優先順位により決定論的な再構成が保証されます。 

もう 1 つのエッジ ケースは、最適な戦略が、将来の Skeppy の動作を制御するために当面の利益を犠牲にすることに依存している場合に発生します。 たとえば、[1000, 1, 1, ..., 1] のような構成では、大きい左側のコインを使用すると、dp 遷移を有利に保つ構造が維持されますが、右側の小さいコインを使用すると、より悪い副問題が引き起こされます。 どちらの選択も最終的には、長期的な結果を反映する値をもつ既に計算された部分間隔に帰着するため、DP はこれを捉えています。 

最後のエッジケースは、最終的なスコアの差がちょうどゼロになる場合です。 その場合、Technoblade が勝者であると宣言することはできず、出力は「引き分け」でなければなりません。 DP は +1 アドバンテージを含む正確な差を計算するため、追加の処理を行わずに直接等しいことが検出されます。
