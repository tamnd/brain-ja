 ## 解決策
 ## 問題の理解

 2 人のプレイヤーはそれぞれ、固定数のジャガイモから始めて、毎日一定の割合でさらに多くのジャガイモを栽培します。 テクノブレードは次から始まります$X_1$ジャガイモとゲイン$Y_1$1日当たりのジャガイモ。 彼のライバルは次から始まります$X_2$ジャガイモとゲイン$Y_2$1日当たりのジャガイモ。 時間は丸一日かけて進み、両方の成長プロセスは同じペースで起こります。 

課題は、Technoblade の合計がライバルの合計を厳密に上回る最も早い日を決定することです。 そのような瞬間が決して到来しない場合、答えは -1 です。 

後$d$日の場合、合計は一次式です。$$T(d) = X_1 + d \cdot Y_1, \quad S(d) = X_2 + d \cdot Y_2$$最小の非負の整数を見つけるように求められます$d$そのような$T(d) > S(d)$、またはそのようなものはないと判断します$d$存在します。 

制約は小さく、すべての値が最大 1000 であるため、時間をかけて直接シミュレーションすることも可能です。 ただし、線形成長の問題には微妙な問題が隠れていることがよくあります。競合他社がより速く成長したり、先にスタートしたりしても、不平等は決して反転しないか、または 1 回しか反転しない可能性があります。 そのため、やみくもに反復するのではなく、単調性について推論することが重要になります。 

よくある失敗例は、Technoblade が遅れてスタートしたものの、急速に成長した場合に発生します。 単純な解決策は、あまりにも早く中止されたり、考慮に入れられなかったりする可能性があります。$d = 0$。 もう 1 つのエッジ ケースは、両方が同じ速度で成長するが、一方が先に開始する場合です。この場合、答えは初期値に応じて 0 になるか、永久に不可能になります。 

## アプローチ

 ブルートフォース手法では、毎日シミュレーションが行われます。 から始まる$d = 0$、両方の値を計算し、Technoblade が厳密により多くのポテトを持っているかどうかを確認します。 そうでない場合は、日を増やして繰り返します。 値は直線的に増加するため、このプロセスにより、最終的には交差点が見つかるか、合理的な範囲内では交差点が決して起こらないことが検出されることが保証されます。 

これは、2 人のプレーヤー間の差も直線的に変化するため機能します。 しかし、無限にシミュレーションを続けると、テクノブレードが追いつかないという最悪のケースが発生します。 そのような状況では、単純なループが永久に実行されるか、任意のカットオフに依存することになり、安全ではありません。 

重要な観察は、成長率を直接比較できることです。 違いを定義します。$$D(d) = (X_1 - X_2) + d (Y_1 - Y_2)$$これは一次関数です。 もし$Y_1 \le Y_2$、関数は非増加または一定です。 その場合、Technoblade がまだ先を行っていない場合は、$d = 0$、彼は後々出世することはありません。 もし$Y_1 > Y_2$、厳密には時間の経過とともに差が増加するため、交差ポイントは最大 1 つになります。 シミュレーションする代わりに、単純な不等式を解くことができます。 

から：$$X_1 + dY_1 > X_2 + dY_2$$得られるもの:$$X_1 - X_2 > d (Y_2 - Y_1)$$もし$Y_1 = Y_2$それ以外の場合は、整数演算を使用してしきい値を直接計算できます。

 ## アルゴリズムのチュートリアル

 1. 初期の差を計算します$diff = X_1 - X_2$。 これにより、成長が起こる前に誰が先を行っているかが把握できます。 
2. もし$diff > 0$, Technoblade は厳密には 0 日目にすでに進んでいるので、答えは 0 です。要件はすでに満たされているため、将来のシミュレーションは必要ありません。 
3. もし$Y_1 = Y_2$、両方のプレイヤーは同じ速度で成長するため、その差は決して変わりません。 Technoblade がまだ先行していない場合、彼が先行することは不可能なので、-1 を返します。 
4. もし$Y_1 < Y_2$, テクノブレードの成長はより遅く、時間の経過とともに差はさらに広がることになります。 最初は近くても追い越せないので-1を返す。 
5. もし$Y_1 > Y_2$、差は毎日一定のプラスの量ずつ増加します。 最小のものが必要です$d$次のような:$$X_1 + dY_1 > X_2 + dY_2$$並べ替え:$$diff + d (Y_1 - Y_2) > 0$$を解決します$d$:$$d > \frac{X_2 - X_1}{Y_1 - Y_2}$$最小の整数$d$これを満たすのは次のとおりです。$$d = \left\lfloor \frac{X_2 - X_1}{Y_1 - Y_2} \right\rfloor + 1$$6. 計算結果を出力します。$d$。 

### なぜ効果があるのか

 重要な不変条件は、2 人のプレーヤー間の差が一定の傾きを持つ時間の一次関数であるということです。$Y_1 - Y_2$。 整数上の線形関数は、傾きがゼロでない限り、ゼロと交差するのは最大 1 回です。 これは、2 人のプレーヤーの順序が変更できるのは最大 1 回だけであり、正確な交差点は検索する代わりに代数的に計算できることを意味します。 このアルゴリズムは、動的プロセスを単一の不等式解決に変換することでこれを利用し、反復なしで正確さを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x1, y1, x2, y2 = map(int, input().split())
    
    diff = x1 - x2
    
    if diff > 0:
        print(0)
        return
    
    if y1 == y2:
        print(-1)
        return
    
    if y1 < y2:
        print(-1)
        return
    
    # y1 > y2
    gap = x2 - x1
    gain = y1 - y2
    
    d = gap // gain
    if gap % gain != 0:
        d += 1
    
    print(d)

if __name__ == "__main__":
    solve()
```このコードは、ゼロ日目に Technoblade がすでに先行しているかどうかを確認することから始まり、これによりすぐに答えが決まります。 次に、相対成長率が好ましくないケースを扱います。これは、成長シナリオが同等であっても小規模であっても、不平等が有利に反転することは決してないからです。 

厳密に増加する場合にのみ、正確な交差点が計算されます。 厳密な不等式が成立する最初の整数日が必要であるため、除算は上限ロジックを使用して慎重に処理されます。 整数演算を使用すると、浮動小数点の精度の問題が回避され、解の決定性が維持されます。

 ## 特殊なケース

 両方のプレイヤーが同じ速度で成長すると、システムは順序付けに関して静的になります。 入力用`10 3 5 3`、差は常に 5 であるため、答えは 0 です。アルゴリズムは、成長率の等価性チェックを通じてこれを直ちに処理します。 

Technoblade が遅れてスタートしても、より速く成長する場合、答えは線形関数が整数点でゼロと交差するかどうかに完全に依存します。 のために`0 2 5 1`、差は -5 から始まり 1 日あたり 1 ずつ増加するため、累積ゲインが最初の不足を相殺したときにちょうど交差が発生します。 計算された値$d = 5$直接シミュレーションと一致します。 

Technoblade の成長が遅くなったとき、たとえば`10 1 100 5`、そのギャップは日に日に悪化します。 アルゴリズムはこれを次のように検出します。$Y_1 < Y_2$不必要な計算を試行せずに -1 を返します。これは、線形差分が負の傾きを持ち、正の方向にゼロを横切ることがないという事実と一致します。
