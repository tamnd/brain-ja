 ## 解決策
 ## 問題の理解

 数直線上のセグメントの集合が与えられ、各セグメントは区間を表します$[l_i, r_i]$。 これらの間隔から、選択されたすべての間隔が少なくとも 1 つの共通点を共有するように、できるだけ多くの間隔を選択したいと考えています。 間隔が閉じているため、端点での接触は依然として交差としてカウントされます。 

タスクを表示する別の方法は、点を探すことです。$x$できるだけ多くの間隔がその点をカバーするようにして、その間隔を正確に選択します。 選択したすべての間隔がペアごとに交差する場合、すべての間隔に何らかの共有点が含まれている必要があるため、問題は間隔の最大数内にある点を見つけることになります。 

入力サイズは最大です$2 \cdot 10^5$これにより、二次関数のアプローチが除外されます。 すべてのサブセットを試行したり、すべての間隔グループの交差をチェックしたりするソリューションは、すべてのペアをチェックするだけでもすでに大きすぎるため、すぐに失敗します。$O(n^2)$。 周りに何かが必要です$O(n \log n)$または$O(n)$。 

微妙なエッジ ケースは、最適なポイントが複数の間隔が交わる端点に正確に存在する可能性があるという事実から生じます。 たとえば、1 つの間隔が次の時点で終了する場合、$5$そしてもう一つはから始まります$5$、両方ともその点をカバーしているとみなされるはずです。 単純な半開間隔の処理では、そのような重複を誤って見逃してしまいます。 

もう 1 つの落とし穴は、間隔の最適なサブセットを明示的に検索する必要があると想定していることです。 それは不必要であり、費用がかかりすぎます。 条件の構造により、選択されたすべての間隔が 1 つの点で重なり合うよう強制されるため、問題全体が 1D カバレッジ最大化問題に分解されます。 

## アプローチ

 強引な解釈では、すべての間隔を潜在的な「コア」として試し、その間隔と交差する間隔の数を確認し、最良の結果を取得します。 一定の間隔について、他の間隔が何個重なっているかを数えることができます。$O(n)$、につながる$O(n^2)$全体。 これでは遅すぎる$n$大きいので、$n = 2 \cdot 10^5$までを意味します$4 \cdot 10^{10}$比較。 

重要な観察は、一連の間隔がすべて互いに交差する場合、それらすべてに含まれる単一の点が存在する必要があるということです。 したがって、間隔のサブセットについて推論する代わりに、線上の点について推論することができます。 問題は、最大数の間隔でカバーされる点を見つけることになります。 

これにより、問題は古典的なスイープ ライン タスクに変換されます。数直線に沿って移動しながら、現在アクティブな間隔の数を追跡します。 このアクティブ数の最大値がまさに答えです$k$、そしてそれを達成する任意の位置は最適なサブセットを与えます。 

そのような点がわかれば、答えを構築するのは簡単です。単にその点をカバーするすべての間隔を収集するだけです。

 ## アルゴリズムのチュートリアル

 各間隔を 1 行上の 2 つのイベントに変換します。 間隔$[l, r]$から始まるアクティブ数が増加します$l$、その後貢献を停止します$r$。 エンドポイントは包括的なものであるため、終了イベントは次の時点で慎重に処理されます。$r + 1$。 

次に、すべてのイベントをソートされた順序で処理し、アクティブな間隔の実行カウントを維持します。 スキャン中に最大カウントを追跡し、それが発生した位置を記憶します。 

最適な位置を見つけた後、すべての間隔で 2 回目のパスを実行し、このポイントを含むパスを収集します。 

### ステップ

 1. 各区間を変換する$[l_i, r_i]$2 つのイベントに分割: +1 で$l_i$そして -1$r_i + 1$。 これにより、閉じた間隔が正しく処理されるようになります。これは、間隔がいつまでもアクティブのままであるためです。$r_i$。 
2. すべてのイベントを数直線上の位置に基づいて並べ替えます。 正しい順序で左から右へのスイープをシミュレートするには、並べ替えが必要です。 
3. 実行中の変数を維持しながら、イベントを順番に走査します。`cur`これは、スイープ位置を現在カバーしている間隔の数を表します。 +1 イベントを処理するときにインクリメントします`cur`、-1 イベントを処理するときに、それをデクリメントします。 
4. 毎回`cur`これまでに確認された最良の値を超えている場合は、最良の値を更新し、現在位置を最適点の候補として記録します。 この点はまさに内側にあります`cur`間隔。 
5. スイープが終了すると、ポイントが得られます$x$それは間隔の最大数にあります。 
6. すべての間隔を繰り返し、満足のいく間隔を選択します。$l_i \le x \le r_i$。 これらの間隔は、有効な最適な答えを形成します。 

### なぜ効果があるのか

 数直線上のどの位置でも、スイープ ラインの数はその位置をカバーする間隔の数と正確に等しくなります。 すべての間隔は、開始から終了まで +1 の影響力の連続セグメントに寄与します。 このランニングカウントの最大値は、オーバーラップが最大となる点に対応する。 有効な解法では、選択されたすべての間隔が共通の点を共有する必要があり、最大のカバレッジを持つ点を明示的に選択するため、結果のセットは最適である必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    intervals = []
    events = []

    for i in range(n):
        l, r = map(int, input().split())
        intervals.append((l, r))
        events.append((l, 1))
        events.append((r + 1, -1))

    events.sort()

    cur = 0
    best = 0
    best_pos = 0

    for x, delta in events:
        cur += delta
        if cur > best:
            best = cur
            best_pos = x

    ans = []
    for i, (l, r) in enumerate(intervals, start=1):
        if l <= best_pos <= r:
            ans.append(i)

    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```実装は、各間隔をイベント形式に変換することから始まります。 使用する$r+1$デクリメント イベントの場合、ポイントが正確に$r$は引き続き間隔内でカウントされます。 イベントを並べ替えることで、座標の昇順でスイープ ラインをシミュレートできるようになります。 掃討中、`cur`現在アクティブなポイントをカバーしている間隔の数を追跡し、この値が以前の最良値を超えて増加するたびに、対応する座標を記録します。 

スイープでは実際のセットではなく最適な位置が得られるだけなので、2 番目のパスが必要です。 選択した点に対して各間隔のメンバーシップを確認することは線形であり、十分です。

 ## 特殊なケース

 主なエッジケースは、間隔が 1 つの点でのみ交差する場合です。 例えば、$[1,2], [2,3], [2,2]$。 正解には、2 を含むすべての間隔が含まれます。スイープ ラインはこれを正しく処理します。これは、2 での +1 と 3 での -1 により、正確にエンドポイントでカウントがアクティブに保たれるためです。 

もう 1 つの微妙なケースは、複数のイベントが同じ位置を共有する大きな座標です。 ソートされたイベントは順番に処理されるため、座標でのすべての更新が一貫して適用され、次に進む前にその正確な時点でアクティブな間隔の完全なセットがカウントに反映されることが保証されます。
