 ## 問題の理解

 円形構造の色を数えています。 固定長の場合$K$、 想像する$K$リング状に配置された位置。 各ポジションは次のいずれかを受け取ります。$M$宝石の種類が異なり、異なる種類の 2 つの宝石は常に区別できますが、同じ種類の宝石は区別できません。 重要な問題は、一方を回転して他方を取得できる場合、2 つの色が同じであるとみなされることです。つまり、円の開始点は重要ではありません。 

それぞれの長さごとに$K$を使用して、異なる円形のネックレスの数が必要です。$M$回転等価性の下で色を計算し、この値をすべて合計します。$K$から$1$に$N$。 最終的な答えはモジュロで計算されます$10^9+7$。 

制約$N, M \le 10^6$除数の列挙またはすべての回転の明示的な反復に依存する長さごとの組み合わせを除外します。 それぞれの完全な循環カウントを再計算するアプローチ$K$遅すぎるでしょう。$O(N \sqrt{N})$または$O(N \log N)$重度の演算を繰り返すと、100 万スケールでは厳しくなります。 理想的には、ほぼ線形時間で累積できる式が必要です。$O(N)$または$O(N \log N)$簡単な事前計算を使用します。 

微妙なエッジ ケースは、「回転の等価性」が、次のすべての約数にわたるバーンサイドの補題を必要とするものとして誤解されやすいことです。$K$、これは合計につながります$\varphi(d)$そして約数ごとの指数関数。 これは数学的には正しいですが、それぞれに対して直接実行すると遅すぎます。$K$。 

もう一つの落とし穴は忘れ物です$K=1$。 この場合、回転間の区別はなく、答えは単純です。$M$。 サイクルに基づく派生はすべて、きれいに縮退する必要があります。 

## アプローチ

 回転を無視すると、それぞれの長さは$K$まさに$M^K$可能なシーケンス。 難しいのは回転による商です。 ネックレスを数える標準的な方法は、バーンサイドの補題です。つまり、すべての回転を平均し、固定された色を数えるというものです。 

固定の場合$K$、による回転$d$位置は、色が周期的に周期的である場合にのみ色を修正します。$\gcd(K,d)$。 シフト付き回転で固定される色の数$d$は$M^{\gcd(K,d)}$。 すべての回転を合計すると、除数の合計に折りたたまれる古典的な恒等式が得られます。$$\text{necklace}(K) = \frac{1}{K} \sum_{d \mid K} \varphi(d)\, M^{K/d}.$$これは正しく標準ですが、次のように直接計算します。$K$約数を列挙し、オイラーの合計寄与を繰り返し計算する必要があります。 が鈍くなるにもほどがあります。$K$まで$10^6$素朴にやれば。 

重要な観察は、私たちは単一のものを求められていないということです。$K$、しかし全体の合計としては$K \le N$。 合計の順序を入れ替えたり、約数ごとに再構成したりできます。 各学期$M^{K/d}$の複数にわたって構造化された方法で表示されます。$d$、ふるい式の蓄積が可能になります。 

除数の合計を再計算する代わりに、$K$、事前計算します$\varphi$まで$N$、そして各約数からの寄与を累積します$d$すべての倍数にわたって$d$。 これにより、ネストされた除数構造が倍数にわたる調和系列に変わり、次のように管理できます。$O(N \log N)$。

 ## アルゴリズムのチュートリアル

 合計を次のように書き換えます。$$\sum_{K=1}^N \frac{1}{K} \sum_{d \mid K} \varphi(d) M^{K/d}.$$変数を変更するには、$K = d \cdot t$。 それから：$$\sum_{d=1}^N \varphi(d) \sum_{t=1}^{\lfloor N/d \rfloor} \frac{M^t}{d t}.$$これにより、構造が除数部分と次の累乗にわたる接頭辞の合計に分離されます。$M$。 

### ステップ

 1. モジュラー逆関数を最大で事前計算します。$N$。 

各項に除算が含まれるため、これが必要です。$K$、逆モジュラーによる乗算になります。 事前計算により定数時間除算が保証されます。 
2. オイラーの合計関数を事前計算する$\varphi(1), \dots, \varphi(N)$直線ふるいを使用します。 

これは、各約数が共素構造に応じて重み付けされたカウントに寄与するため必要です。 
3. 事前計算能力$M^i \bmod (10^9+7)$みんなのために$i \le N$。 

すべての貢献は次の累乗に依存します。$M$、高速なべき乗を繰り返すと遅すぎます。 
4. 配列を維持する$S[i]$どこ$S[i]$で終わるすべての長さのプレフィックスの寄与です。$i$。 

これにより、内部和を繰り返し再計算することが回避されます。 
5. 各約数について$d$から$1$に$N$、複数回繰り返します$K = d, 2d, 3d, \dots$。 

そういったそれぞれに対して$K$、 追加：$$\varphi(d) \cdot M^{K/d} \cdot K^{-1}.$$これは、再編成されたバーンサイドの公式と直接一致します。 
6. すべての貢献を最終的な回答に累積します。 

### なぜ効果があるのか

 核となる不変条件は、すべてのネックレス構成がその最小回転周期を通じて正確に 1 回カウントされるということです。 トーティエント関数$\varphi(d)$プリミティブサイクルの長さを保証します$d$ローテーション クラスごとに 1 回だけカウントされます。 の乗算$M^{K/d}$はプリミティブ ブロックの有効な詰め物を列挙し、倍数にわたる合計により重複することなくすべての長さを再構築します。 

バーンサイド和の各項は、それぞれ独立して再計算されるのではなく、除数構造によって再分配されるためです。$K$、構成が欠落したり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    N, M = map(int, input().split())

    # powers of M
    powM = [1] * (N + 1)
    for i in range(1, N + 1):
        powM[i] = powM[i - 1] * M % MOD

    # inverse array
    inv = [1] * (N + 1)
    for i in range(2, N + 1):
        inv[i] = MOD - MOD // i * inv[MOD % i] % MOD

    # phi sieve
    phi = list(range(N + 1))
    for i in range(2, N + 1):
        if phi[i] == i:
            for j in range(i, N + 1, i):
                phi[j] -= phi[j] // i

    ans = 0

    for d in range(1, N + 1):
        fd = phi[d]
        if fd == 0:
            continue
        for k in range(d, N + 1, d):
            t = k // d
            ans += fd * powM[t] % MOD * inv[k]
            ans %= MOD

    print(ans)

if __name__ == "__main__":
    solve()
```解決策は、次のべき乗を事前計算することから始まります。$M$すべての寄与は指数にのみ依存するため$K/d$、それらを保存することで累乗の繰り返しを避けることができます。 

モジュラー逆配列は、標準の線形再帰を使用して計算されます。これにより、次の除算が可能になります。$K$バーンサイド平均を形成するとき。 

完全なふるいが構築されます$\varphi$値を効率的に計算し、各除数が基本的な循環カウントに正しい重みを与えるようにします。 

ネストされたループオーバー$d$そしてその倍数は、除数で再構成されたバーンサイド和を直接実装したものです。 乗算の順序は、オーバーフローを回避し、各中間値が確実に剰余化されるように慎重に選択されます。$10^9+7$。

        powM[i] = powM[i - 1] * M % MOD
