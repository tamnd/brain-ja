 ## 解決策
 ## 問題の理解

 複数のカードのセットが与えられ、各カードには数字の 0 または数字の 5 が表示されます。これらのカードから任意のサブセットを選択し、選択した数字を 1 行に書かれた数字に配置できます。 私たちの目標は、90 で割り切れる可能な限り最大の数を構築することです。 

90で割り切れる数は、2つの条件を同時に満たさなければなりません。 まず、10 で割り切れる必要があり、最後の桁は 0 になります。第 2 に、9 で割り切れる必要があり、その数字の合計が 9 で割り切れる必要があります。数字は 0 と 5 しかないため、これらの制約により、可能なことが強く制限されます。 

出力は、辞書編集上の数値の最大値である必要があります。先行ゼロのない数値の場合、桁数を最大化し、より大きな桁を最初に配置することと同じです。 有効な数値を形成できない場合は、-1 が出力されます。 特別な解釈が 1 つあります。つまり、数値 0 は許可され、先行ゼロなしで有効であると見なされます。 

制約は小さく、カードは最大 1000 枚であるため、線形カウントと単純な算術決定で十分です。 順列やサブセットの列挙を伴うものは不要です。 

主なエッジ ケースは、割り算の制約が限られた桁の種類とどのように相互作用するかによって発生します。 単純な間違いは、すべての 0 と 5 を使用しようとしたり、9 で割り切れることを保証せずに 10 で割り切れるかどうかだけを確認したりすることです。もう 1 つのよくある失敗は、有効な数値は 0 で終わる必要があること、つまり、答えが正確に「0」である退化した場合を除いて、少なくとも 1 つのゼロが存在する必要があることを忘れることです。 

たとえば、入力のように 5 だけがあり、0 がなかったとします。`[5, 5, 5]`、10 で割り切れる数を作ることはできないので、答えは次のようになります。`-1`。 ゼロが 1 つと 5 が 1 つのように、ゼロはあるが 5 が少なすぎて合計を 9 で割り切れない場合、候補は「0」だけになります。 

## アプローチ

 ブルートフォースアプローチでは、カードのすべてのサブセットと各サブセットのすべての順列を試して数字を形成し、90 で割り切れるかどうかを確認して最大値を維持します。 これはあらゆる可能性を検討するので正しいですが、実行不可能です。 最大 1000 枚のカードの場合、サブセットの数は次のとおりです。$2^{1000}$、サブセットを無視しても、選択した要素を並べ替えると階乗増加が生じます。 このアプローチは、制約が適用されるとすぐに崩壊します。 

重要な観察は、問題の構造がほとんどすべての自由を奪っているということです。 数字の 0 と 5 のみが存在するため、構築される数値は、5 と 0 がいくつ含まれるかによって完全に決まります。 10 で割り切れると、少なくとも 1 つのゼロが必要になります。 9 で割り切れるかどうかは、桁の合計にのみ依存します。$5 \cdot k$どこ$k$は選択された 5 の数です。 だから必要なのです$5k \equiv 0 \pmod{9}$、これは以下と同等です$k \equiv 0 \pmod{9}$5と9は互いに素だからです。 

したがって、解決策は次のようになります。9 で割り切れる最大の 5 を選択し、利用可能なすべてのゼロを使用します。 そのような 5 が存在しない場合、考えられる唯一の答えは 0 (少なくとも 1 つのゼロが存在する場合) または不可能です。 

次に、多くの 5 の後にすべて 0 を出力して数値を作成します。これにより、最初に大きな桁を配置すると数値が最大化されるため、最大値が保証されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n・n!) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力に 0 と 5 がいくつあるかを数えます。 これにより、問題は個々のカードではなく頻度に関する推論に集約されます。 
2. 少なくとも 1 つのゼロがあるかどうかを確認します。 そうでない場合は、10 で割り切れる数を形成できないため、答えはすぐに -1 になります。 
3. カウントが 9 で割り切れるように、使用できる 5 の数を決定します。5 の合計数以下の最大の 9 の倍数を採用します。 これにより、9 で割り切れる範囲を維持しながら、先頭の桁数が最大になります。 
4. この計算された 5 の数が 0 の場合、9 で割り切れる 5 を含む数を作成することはできません。この場合、できる最善のことは 1 つのゼロを出力することです。 
5. それ以外の場合は、多数の 5 の後にすべて 0 を出力して結果を作成します。 この順序により、すべての有効数字が 5 で、すべての末尾数字が 0 になるため、数値ができるだけ大きくなります。 

### なぜ効果があるのか

 有効な数値はすべてゼロで終わる必要があるため、少なくとも 1 つのゼロが必須です。 この制約が満たされると、残りの要件は 9 で割り切れるかどうかであり、これは桁の合計にのみ依存します。 ゼロは合計に影響を与えないため、唯一意味のある決定は、5 をいくつ含めるかということです。 5 の数を 9 で割り切れる範囲に保ちながら、その数を最大化すると、数字の長さと辞書編集上の値の両方が最大になります。 同じマルチセットを持つすべての有効な順列は、降順にソートされた場合に同じ最適な順序付けを生成するため、再配置によって結果が改善されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    cnt0 = arr.count(0)
    cnt5 = arr.count(5)
    
    if cnt0 == 0:
        print(-1)
        return
    
    use5 = (cnt5 // 9) * 9
    
    if use5 == 0:
        print(0)
        return
    
    print("5" * use5 + "0" * cnt0)

if __name__ == "__main__":
    solve()
```コードは、1 回のパスで 0 と 5 を数えることから始まります。 次に、少なくとも 1 つのゼロが存在することを確認して、10 で割り切れる要件を強制します。 その後、最も近い 9 の倍数に切り捨てて、使用可能な 5 の数を計算します。これにより、9 で割り切れる可能性が直接強制されます。最終的な構成では、選択されたすべての 5 が最初に出力され、次にすべて 0 が出力され、最大の数値が保証されます。 

微妙な点は、最適な構造が強制されるため、数字をインターリーブしたり、順列をテストしたりすることは決してないことです。最大値の配置では、すべての 5 がゼロの前に来なければなりません。

 | ステップ | cnt0 | cnt5 | 使用5 | 決定 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    arr = list(map(int, input().split()))
    cnt0 = arr.count(0)
    cnt5 = arr.count(5)

    if cnt0 == 0:
        return "-1"
    use5 = (cnt5 // 9) * 9
    if use5 == 0:
        return "0"
    return "5" * use5 + "0" * cnt0

# provided sample
assert run("4\n5 0 5 0\n") == "0"

# all zeros minimum case
assert run("1\n0\n") == "0"

# no zeros impossible

# enough fives for multiple of 9
assert run("10\n" + "5 "*9 + "0\n") == "5555555550"

# extra fives beyond multiple of 9
assert run("11\n" + "5 "*10 + "0\n") == "5555555550"

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ゼロは存在するが、5 が 9 の倍数を形成できない場合です。入力の場合`0 5`、ゼロが 1 つと 5 が 1 つあります。 このアルゴリズムは、使用可能な 5 を 0 に設定し、「0」だけを出力します。 5 を含めると 9 で割り切れないため、これは正しいです。 

もう 1 つのエッジ ケースは、ゼロがまったくない場合です。たとえば、`5 5 5 5 5`。 5 から大きな数を作ることはできますが、ゼロで終わるものはないため、10 で割り切れるとすぐに失敗します。 アルゴリズムは、それ以上の推論を試行する前に、正しく -1 を返します。
