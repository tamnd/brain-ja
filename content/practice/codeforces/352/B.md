 ## 解決策
 ## 問題の理解

 一連の整数が与えられており、それぞれの個別の値について、その値が配列内でどのように配置されているかを理解したいと考えています。 あらゆる値に対して$x$、すべてのインデックスを調べます。$x$が表示されます。 これらのインデックスが一定の差を持つシーケンスを形成する場合、$x$is considered valid, and we also report that difference. もし$x$出現が 1 回のみの場合、差はゼロとして定義されます。 

したがって、課題は価値そのものに関するものではなく、その立場の構造に関するものです。 出現パターンが等間隔かどうかに基づいて、個別の数値を効果的に分類しています。 

入力サイズは最大です$10^5$。 これにより、値ごとに配列全体を繰り返しスキャンするものは即座に除外されます。これは、単純なグループ化とチェックのアプローチでは劣化してしまうためです。$O(n^2)$最悪の場合、多くの値が繰り返される場合があります。 各要素を一定の回数だけ処理するソリューションが必要です。 

値がちょうど 2 回出現する場合、微妙なエッジ ケースが発生します。 2 つの位置は常に等差数列を形成するため、答えは単純にそれらの差になります。 もう 1 つの特殊なケースは、出現箇所が等間隔ではないものの、位置など、ほぼ規則的に見える場合です。$[1, 3, 4]$。 不注意なアプローチでは、連続した差異をローカルで確認するだけで、後でパターンが崩れることを見逃す可能性があります。 

## アプローチ

 ブルートフォース戦略は、最初に個別の値ごとにすべてのポジションを収集し、次に連続するポジション間の差が一定であるかどうかを検証することです。 これは論理的には正しいです。すべてのギャップが等しい場合、位置は等差数列を形成します。 

ただし、コストはデータの整理方法によって異なります。 個別の値ごとに配列全体を繰り返しスキャンすると、最終的には次のようになります。$O(n)$値ごとの仕事量は次のようになります$O(n^2)$最悪の場合、すべての要素が異なる場合。 最初に辞書内の位置をグループ化したとしても、リストを作成するための総コストは次のとおりです。$O(n)$ただし、各グループの検証はその頻度に比例するため、全体的なチェックは残ります。$O(n)$。 その部分は大丈夫です。 

本当の問題は、値ごとの処理における不必要なオーバーヘッドを回避し、グループごとのソートを導入しないようにする必要があることです。これにより、追加の処理が追加されます。$\log n$個別の要素ごとの係数。 

重要な観察は、入力がすでに適切に行われているため、位置を収集するために 1 回のパス以外には何も特別なことは必要ないということです。 スキャン時にインデックスを保存すると、各リストは本質的にソートされます。 その後、保存されているインデックス全体で 1 つの共通の違いをチェックすることで、各値を検証できます。 

これにより、問題は線形簿記に集約されます。つまり、ポジションを蓄積し、各リストを 1 回スキャンします。

 | グループ化 + 値ごとに 1 回検証 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、各値をそれが出現するインデックスのリストにマッピングする辞書を維持します。 

1. 配列を左から右にスキャンし、各インデックスを対応する値のリストに追加します。 これにより、余分な作業を行わずに位置が自動的にソートされます。 
2. 個別の値ごとに$x$, inspect its list of positions. 要素が 1 つだけ含まれている場合、間隔のあいまいさが存在しないため、その値の答えはすぐにゼロになります。 
3. 少なくとも 2 つの出現がある場合は、最初の 2 つの位置を使用して最初の差を計算します。 
4. 残りの位置を調べて、連続するすべての差異が最初の差異と一致することを確認します。 不一致が見つかった場合は、値を完全に破棄します。 
5. すべての有効な値とその差異を収集し、値自体でソートして出力します。 並べ替えは、配列全体ではなく、個別のキーに対してのみ行われます。 

### なぜ効果があるのか

 任意の有効な値に対して$x$、「位置が等差数列を形成する」という条件は、「すべての連続する差が等しい」と同等です。 インデックスはすでに構造ごとにソートされているため、隣接する差異をチェックするだけで十分であり、必要です。 ギャップが 1 つでも異なる場合は、進行特性に違反します。 逆に、すべてのギャップが一致する場合は、等差数列の定義が満たされ、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    pos = {}
    
    for i, x in enumerate(a, start=1):
        if x not in pos:
            pos[x] = []
        pos[x].append(i)
    
    res = []
    
    for x in pos:
        p = pos[x]
        if len(p) == 1:
            res.append((x, 0))
            continue
        
        d = p[1] - p[0]
        ok = True
        
        for i in range(2, len(p)):
            if p[i] - p[i - 1] != d:
                ok = False
                break
        
        if ok:
            res.append((x, d))
    
    res.sort()
    
    out = []
    out.append(str(len(res)))
    for x, d in res:
        out.append(f"{x} {d}")
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、値をキーとする辞書に依存しており、各エントリには増加するインデックスのリストが格納されます。 左から右に繰り返すため、これらのリストを並べ替える必要はありません。 等差数列のチェックは、値ごとに 1 つの線形パスで行われます。 

よくある間違いは、参照差分を早期に修正せずに差分を再計算することです。これにより、不必要な比較や誤った早期終了が発生します。 もう 1 つの微妙な点は、単一出現値が明示的に処理されるようにすることです。そうしないと、値が誤ってスキップされる可能性があります。

 ## 特殊なケース

 値が 1 回だけ現れるのは最も単純なケースですが、差分を計算する前に実装が少なくとも 2 つの位置を想定している場合、誤った処理が行われやすくなります。 この場合、アルゴリズムは隣接する要素にアクセスする前に明示的にゼロを割り当て、範囲外エラーを防ぎます。 

もう 1 つの特殊なケースは、値が 2 回出現する場合です。 たとえば、次のように入力します。```
4
5 1 5 1
```値 5 の場合、位置は [1, 3] であるため、差は 2 です。アルゴリズムはこれを最初のペアから直接計算し、それ以上の検証を必要とせずに受け入れます。 

より微妙なケースは、シーケンスが有効な差異で始まったが、後で中断される場合です。```
5
2 1 2 2 1
```値 2 の場合、位置は [1, 3, 4] です。 最初の差は 2 ですが、次の差は 1 なので拒否されます。 スキャンは最初の不一致を即座に検出し、値を破棄して、部分的なパターンが誤って受け入れられないことを保証します。
