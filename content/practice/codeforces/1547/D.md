 ## 解決策
 ## 問題の理解

 私たちには順序が与えられています$x_1, x_2, \dots, x_n$。 私たちの仕事は別のシーケンスを構築することです$y_1, y_2, \dots, y_n$それらを要素ごとに XOR すると、結果のシーケンスは次のようになります。$$a_i = x_i \oplus y_i$$単調なビット構造を持っています: に設定されているすべてのビット$a_i$にも設定する必要があります$a_{i+1}$。 ビット単位で言えば、これは次のことを意味します$$a_i \& a_{i+1} = a_i.$$それでシーケンスは$a_i$設定されたビットという意味では非減少です。ビットが一度 1 になると、その後は 0 になることはありません。 

弊社では施工しておりません$a_i$直接。 代わりに、私たちは選択しなければなりません$y_i$、すべての有効な選択肢の中で、辞書順にシーケンスを最小化する必要があります。 

重要な相互作用は、それぞれが$y_i$コントロール$a_i$XOR を介して。 XOR はビットを独立して反転するため、各位置$i$選択するものと考えることができます$a_i$、そして導出$y_i = a_i \oplus x_i$ただし、結果として生じる制約があります。$a$-シーケンスは成長条件を満たさなければなりません。 

制約は大きいです: 合計$n$テスト全体での上限は$2 \cdot 10^5$。 これにより、テストごとに線形または線形に近い解決策が強制されます。 考えられるすべてのビット パターンを考慮したり、選択を後戻りしようとすると、すぐに遅すぎます。 

素朴なアプローチでは、$y_i$貪欲に、毎回完全なプレフィックスの有効性をチェックしたり、一貫性を維持しながら各ビットを個別に選択したりすることもできます。 問題は、制約がビット永続性を通じてすべての位置を結合するため、ローカルな決定によって将来の実現可能性が損なわれる可能性があることです。 

貪欲に最小化すると単純な失敗例が現れる$y_i$独立して:```
x = [1, 2]
```選ぶとしたら$y_1 = 0$、 それから$a_1 = 1$。 で$i=2$、もう一度選ぶと$y_2 = 0$、 それから$a_2 = 2$、そして私たちは得ます$1 \& 2 = 0 \neq 1$、 無効。 これを修正するには、将来のポジションからの制約を予測する必要があります。 

したがって、主な困難は、それぞれが$a_i$以前のスーパーセット (ビット単位の意味で) である必要がありますが、$y_i$辞書編集的には小さい。 

## アプローチ

 強引な考えは、あらゆる可能性を試すことです$y_1$、計算する$a_1$、その後、後続の各$a_i$以前のすべてのスーパーセットである必要があります$a$さんの。 ステップで$i$、すべて試してみます$y_i$そのような$a_i = x_i \oplus y_i$増大する制約を次のように満たします$a_{i-1}$。 これは、各位置のすべてのビットマスクを列挙し、各候補の互換性をチェックすることを意味します。 

それぞれなので$x_i < 2^{30}$、 それぞれ$y_i$も 30 ビット空間に存在し、$2^{30}$ポジションごとの可能性。 制約による枝刈りでも依然として指数関数的な検索が残ります。 これは明らかに実行不可能です。 

重要な観察点は、$a_i$ビットの包含という点では単調です: あるビットが 1 になると$a_i$、永久に 1 のままでなければなりません。 これは、グローバル ビットマスクを維持することを示唆しています。$S$、前の手順ですでに 1 に強制されているすべてのビットを表します。$a$-価値観。 

位置で$i$を確保する必要があります。$a_i$のすべてのビットが含まれています$S$。 辞書編集上最小限の選択肢$y_i$作ることに相当する$a_i$を含めながらできるだけ小さくする$S$。 以来$a_i = x_i \oplus y_i$、代わりに決定することができます$a_i$として:

 - すべてのビットが入っています$S$1でなければなりません
 - 追加のビットは、将来の制約に役立つ場合はオプションで 1 にすることができますが、追加の 1 は辞書編集上、後の選択に悪影響を与えるだけです。 

したがって、最適な戦略は、$a_i = x_i \,|\, S$。 前のステップですでに必要なビットはすべて出現する必要があり、新しいビットを導入すると増加するだけです$S$、これは将来の制約を悪化させ、辞書編集順でより大きな値を強制する可能性があります。$y$。 

一度$a_i$修正されたら回復します$y_i = a_i \oplus x_i$、更新します$S = S \,|\, a_i$。 

これにより、問題はビットマスクを維持する単一の左から右へのパスに縮小されます。

 ## アルゴリズムのチュートリアル

 1. ビットマスクを初期化する$S = 0$。 これは、将来にわたって存在し続ける必要があるビットを表します。$a_i$。 
2. シーケンスを左から右に繰り返します。 位置で$i$、候補を計算します$$a_i = x_i \,|\, S.$$これにより、以前に必要なすべてのビットが確実に保持されます。 
3. コンピューティング$y_i = a_i \oplus x_i$。 これは次の最小値です。$y_i$それは変身する$x_i$の中へ$a_i$、XOR はビットを正確に反転するため、$x_i$そして$a_i$異なる。 
4. グローバル制約を更新します。$$S = S \,|\, a_i.$$これにより、今後も存在し続ける必要があるビットのセットが拡張されます。 
5. 出力$y_i$将来の決定は過去の価値に影響を与えないため、すぐに実行できます。 

### なぜ効果があるのか

 不変条件は、処理後の位置です。$i$、現在のセット$S$構築されたすべてのビット単位の和集合に等しい$a_1, \dots, a_i$。 有効な未来$a_j$すべてのビットを含める必要があります$S$そうでない場合は、そのビットが最初に出現した以前のインデックスによる成長条件に違反します。 

それぞれのステップで選択することで、$a_i = x_i | S$可能な限り最小の有効な値を返します$a_i$この制約の下では。 小さい選択肢を選択すると、少しミスが発生します$S$そして有効性を破ります。 選択を大きくすると不要なビットが導入され、ビット数が増加します。$y_i$または、辞書編集上の順序を増やすだけの今後の更新を強制します。 辞書編集上の比較は最も古い異なる位置に依存するため、それぞれの比較を最小限に抑えることができます。$y_i$最も厳しい有効な制約の下では、グローバル最小値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        x = list(map(int, input().split()))
        
        S = 0
        res = []
        
        for xi in x:
            ai = xi | S
            yi = ai ^ xi
            res.append(str(yi))
            S |= ai
        
        out.append(" ".join(res))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では、進化する制約マスクが維持されます。`S`。 各ステップで、最小の有効な値を構築します。$a_i$とのOR演算により`S`を導出します。$y_i$XOR経由。 アップデート`S |= a_i`これまでに出現したすべてのビットが$a_i$シーケンスの残りの部分では保持されます。 

微妙な点は、成長状態を明示的にチェックする必要がないことです。`S`帰納的にそれを保証します。 それぞれ`a_i`すでに以前のビットがすべて含まれているため、`a_{i-1} & a_i = a_{i-1}`自動的に保持されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、最初にすべてのビットが 0 である場合です。 入力用`x = [0, 0, 0]`、アルゴリズムは維持します`S = 0`、だからすべての`a_i = 0`そしてすべての`y_i = 0`。 すべてのマスクが同一であるため、成長条件は自明に当てはまります。 

もう 1 つのエッジ ケースは、後の要素には含まれていない上位ビットが初期の要素に導入されるときに発生します。 のために`x = [1, 2, 4]`、最初のステップの後、マ​​スクは次のように成長します。`S = 1`、2番目を強制します`a_2 = 3`、 それから`S = 3`、そして最後に`a_3 = 7`。 このアルゴリズムは、前のビットを保存するために後の値を正しくインフレートし、元の値が減少した場合でも単調なビットの包含を保証します。 

最後の微妙なケースは、単一要素シーケンスです。 要素間には制約がないため、答えは単純です。$y_1 = 0$を選択しているため、$a_1 = x_1$は常に有効であり、XOR を最小化します。
