[CF 1547G - パスはいくつありますか?](https://codeforces.com/problemset/problem/1547/G)

 **評価:** 2100
 **タグ:** dfs および類似の、dp、グラフ、ツリー
 **解決時間:** 8 分 54 秒
 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 与えられた有向グラフでは、ノード 1 から開始して、各頂点で終了するすべての可能な有向ウォークを考慮します。 ウォークでは、ノードとエッジを任意に何度でも再訪できます。 すべての頂点について、そのようなウォークの正確な数を計算することは求められませんが、その数を 4 つのカテゴリ (到達可能性なし、厳密に 1 つのウォーク、複数だが有限のウォーク、または無限に多いウォーク) に分類することだけが求められます。 

重要な点は、サイクルによって「パスの数」の意味が完全に変わることです。 サイクルはパスを追加するだけでなく、任意に何度でも繰り返すことができ、最初から到達可能でターゲットにも到達できる限り、すぐに無限に多くの個別のウォークを作成します。 

入力サイズにより、テスト ケースごとに線形または線形に近い解決策が求められます。 すべてのテスト ケースにわたる頂点とエッジの合計数は 4e5 によって制限されるため、テスト ケースあたり O(n + m) を超えるアルゴリズムやエッジを過剰に再訪するアルゴリズムは合格しません。 これにより、明示的なパスのカウント、すべてのウォークにわたる指数関数的な DFS、サイクルを崩壊させない単純な動的プログラミングはすでに除外されています。 

単純な試みで発生するいくつかの失敗モードがあります。 パスをカウントする単純な DFS は、ノード 1 から到達可能な単一の有向サイクルのように、グラフ上で即座に爆発します。これは、サイクルの反復トラバースにより個別のウォークの数が無限になるためです。 もう 1 つのよくある間違いは、到達可能性を DAG 問題として扱い、DP を任意の順序で実行することです。 DP は非周期性と有限の伝播順序を想定しているため、サイクルが存在する場合は失敗します。 最後に、ノードを一度「訪問済み」としてマークするだけでは不十分です。再訪問すると、まさに複数のパスと無限のカウントが作成されます。 

失敗例としては、1 → 2 → 3 → 2 など、1 から到達可能なサイクルが挙げられます。単純なパス カウンタでは 1-2-3-2-3-2-... を無限に列挙し続けることになりますが、正解はノード 2 と 3 の「無限パス」になります。 

## アプローチ

 制約を無視する場合、最も直接的なアイデアは、DFS を使用してノード 1 からのすべてのウォークを列挙し、各ノードに到達する個別の方法の数をカウントすることです。 各パスは有限であり、パスの数は DAG 構造の組み合わせによって制限されるため、これは非巡回グラフでは正しいです。 ただし、サイクルが存在するとすぐに、このアプローチは失敗します。サイクルは何度でも横断できるため、到達可能性のパターンだけを気にしていても、無限に多くの個別のウォークが生成されるからです。 

重要な構造的観察は、サイクルが無限の唯一の源であるということです。 すべての強く接続されたコンポーネントを単一のノードに縮小できた場合、結果のグラフは DAG になります。 強く接続されたコンポーネントの内部では、一度そこに入ると、そのコンポーネント内のすべてのノードに到達し、複数の方法で離れることができます。 そのコンポーネントがまだ外側に到達できるサイクルからも到達可能である場合、下流のすべてのノードは無限になります。 

これは 2 段階の推論を示唆しています。 まず、ノード 1 から到達可能なサイクルの一部であるか、サイクルから到達可能なすべてのノードを特定します。続行する前または戻った後に無限にループする可能性があるため、これらのノードは自動的に応答 -1 を取得します。 次に、残りのグラフ (「不良」ノードを削除した後の実質的な DAG) では、トポロジカル DP を使用してノード 1 からウェイの数を計算できますが、区別する必要があるのは 0、1、2 だけです。ノードが複数のウェイを蓄積した瞬間に、その上限を 2 に設定します。

サイクルを効率的に検出するために、再帰状態追跡または SCC 分解を備えた DFS を使用します。 標準の CF ソリューションでは、DFS カラー (未訪問、訪問中、終了) が使用されます。 「訪問」ノードへのエッジはサイクルを示します。 1 から到達可能なサイクル ノードが見つかったら、元のグラフ内のそのサイクルから到達可能なすべてのノードを介して「無限」前方に伝播します。 

無限ノードをマークした後、DP でそれらを無視し、残りのグラフに対して 1 から始まるトポロジスタイルの走査を実行します。サイクルが削除されるため、このサブグラフは DAG となり、パスのカウントは線形伝播になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート DFS パス列挙 | 指数関数 | O(n) | 遅すぎる |
 | サイクルを意識した DFS + DAG DP | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフの隣接リストを作成し、逆の隣接リストも計算します。 逆グラフは、後で、検出されたサイクルから「無限の到達可能性」を逆方向に伝播するのに役立ちます。 
2. ノード 1 から DFS を実行して、どのノードが到達可能であるかを判断します。 ここにアクセスしていないノードは、1 からのパスが存在しないため、即座に応答 0 を取得します。 
3. DFS 中に、バック エッジを検出するために再帰スタックの状態を維持します。 現在再帰スタック内でノードから別のノードへのエッジを見つけると、有向サイクルが特定されます。 そのようなサイクルに関与する、またはそのようなサイクルから到達可能なすべてのノードを「不良」としてマークします。 

これが機能するのは、サイクル上のどのノードでも反復的なトラバースが可能であり、無限に多くの個別のウォークが生成されるためです。 
4. 最初のサイクル検出後、「不良」ステータスを前方に伝播します。ノードが不良ノードに到達できる場合、そのノードも不良です。 これは、すべてのサイクル ノードから始まる元のグラフに対して BFS/DFS を使用して行われます。 

この伝播が必要な理由は、パスがサイクルに入り、さらに先に進むことができると、すべての下流ノードが無限の多重度を継承するためです。 
5. 次に、すべての不良ノードを考慮から削除します。 残りのグラフでは、ノード 1 からのすべてのパスが有限であることが保証されます。 
6. DFS メモ化またはトポロジカル DP を使用して、この縮小されたグラフ内のパスの数を計算します。 不良ノードを削除した後はグラフが非循環になるため、各ノードの値は以前に計算されたノードのみに依存します。 

ノードごとに 3 つの状態のみを保存します: 0 (到達不能)、1 (正確に 1 つのパス)、2 (複数のパス)。 合計が 2 を超えるとクランプされます。 
7. 出力結果: 不良ノードは -1、到達不能ノードは 0、残りのノードは DP 値を取得します。 

### なぜ効果があるのか

 正しさは、分岐による多重性とサイクルによる無限性という 2 つの現象を区別するかどうかにかかっています。 強く接続されたコンポーネントは、まさにサイクルが存在する最大の構造であり、再訪できるノード 1 から到達可能な SCC は、無制限のウォークの繰り返しを意味します。 これらが分離されて前方に伝播されると、残りのグラフは非循環になるため、パス カウントは標準の DAG DP と同様に動作します。 2 にクランプすると、一意のパスと複数の有限パスの区別のみが保持され、DAG 内の DP 遷移下で安定します。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    rg = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b = map(int, input().split())
        g[a].append(b)
        rg[b].append(a)

    # 1. reachable from 1
    vis = [False] * (n + 1)
    stack = [1]
    vis[1] = True
    order = []
    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if not vis[v]:
                vis[v] = True
                stack.append(v)

    if not vis[1]:
        vis[1] = True

    # 2. detect cycles via DFS colors
    color = [0] * (n + 1)
    bad = [False] * (n + 1)

    def dfs(u):
        color[u] = 1
        for v in g[u]:
            if not vis[v]:
                continue
            if color[v] == 0:
                if dfs(v):
                    bad[u] = True
            elif color[v] == 1:
                bad[v] = True
                bad[u] = True
        color[u] = 2
        return bad[u]

    for i in range(1, n + 1):
        if vis[i] and color[i] == 0:
            dfs(i)

    # 3. propagate bad forward
    from collections import deque
    q = deque([i for i in range(1, n + 1) if bad[i]])
    while q:
        u = q.popleft()
        for v in g[u]:
            if vis[v] and not bad[v]:
                bad[v] = True
                q.append(v)

    # 4. DP on remaining graph
    dp = [-1] * (n + 1)

    def solve_dp(u):
        if bad[u]:
            return 0
        if dp[u] != -1:
            return dp[u]
        total = 1 if u == 1 else 0
        for v in g[u]:
            if not vis[v] or bad[v]:
                continue
            total += solve_dp(v)
            if total > 2:
                total = 2
        dp[u] = total
        return dp[u]

    for i in range(1, n + 1):
        if vis[i] and not bad[i]:
            solve_dp(i)

    res = []
    for i in range(1, n + 1):
        if not vis[i]:
            res.append("0")
        elif bad[i]:
            res.append("-1")
        else:
            res.append(str(dp[i]))

    print(" ".join(res))

t = int(input())
for _ in range(t):
    input()
    solve()
```この実装では、他のすべては自明のことながら 0 であるため、最初に 1 から到達可能なノードに注目が制限されます。次に、DFS カラーリングを使用してサイクルを検出し、関係するすべてのノードにマークを付けます。 追加の伝播ステップにより、サイクルの下流にあるノードも無限として扱われるようになります。これは、サイクルが自身のノードだけでなく、その後に到達可能なすべてのノードに影響を与えるため、不可欠です。 

DP ステージは、値を 2 にクランプすることで二重カウントを注意深く回避します。グラフには複数の結合パスが存在する可能性があり、正確なカウントは必要ないため、これは重要です。 

## 実用的な例

 1 が 2 つのパス、1 → 2 → 4 および 1 → 3 → 4 に分割される小さなグラフを考えてみましょう。ノード 4 は 2 つの有限パスを持つものとしてマークされる必要があります。 

| ステップ | 到達可能 | ノードを循環する | DP(2) | DP(3) | DP(4) |
 | --- | --- | --- | --- | --- | --- |
 | 到達可能性の後 | {1,2,3,4} | なし | - | - | - |
 | DP 初期化後 | 同じ | なし | 1 | 1 | - |
 | DP後 | 同じ | なし | 1 | 1 | 2 |

 これは、パスを結合するとカウントが増加するものの、制限されたままであることが確認できます。 

ここで、サイクル 1 → 2 → 3 → 2 と 3 → 4 を考えてみましょう。サイクル後にノード 4 に到達可能になります。 

| ステップ | 到達可能 | サイクルが検出されました | 不良ノード | DP(4) |
 | --- | --- | --- | --- | --- |
 | DFS後 | {1,2,3,4} | {2,3} | {2,3} | - |
 | 伝播 | 同じ | 同じ | {2,3,4} | - |
 | 最終 | 同じ | 同じ | 2,3,4 = -1 | - |

 これは、サイクル到達可能性によって下流ノードが無限分類に強制される仕組みを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各ノードとエッジは、DFS、サイクル検出、伝播、DP を通じて一定回数処理されます。 
| スペース | O(n + m) | 隣接リスト、状態配列、再帰/DP ストレージ |

 この制約では合計 4e5 のノードとエッジが許可されるため、テスト ケースごとの線形時間処理で十分です。 すべてのフェーズが厳密に線形であり、再計算が回避されるため、アルゴリズムはこの範囲内に留まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    def solve():
        n, m = map(int, input().split())
        g = [[] for _ in range(n + 1)]
        vis = [False]*(n+1)
        for _ in range(m):
            a,b = map(int,input().split())
            g[a].append(b)

        vis[1]=True
        stack=[1]
        while stack:
            u=stack.pop()
            for v in g[u]:
                if not vis[v]:
                    vis[v]=True
                    stack.append(v)

        color=[0]*(n+1)
        bad=[False]*(n+1)

        def dfs(u):
            color[u]=1
            for v in g[u]:
                if not vis[v]:
                    continue
                if color[v]==0:
                    dfs(v)
                elif color[v]==1:
                    bad[u]=bad[v]=True
            color[u]=2

        for i in range(1,n+1):
            if vis[i] and color[i]==0:
                dfs(i)

        from collections import deque
        q=deque([i for i in range(1,n+1) if bad[i]])
        while q:
            u=q.popleft()
            for v in g[u]:
                if vis[v] and not bad[v]:
                    bad[v]=True
                    q.append(v)

        dp=[-1]*(n+1)
        def f(u):
            if bad[u]: return 0
            if dp[u]!=-1: return dp[u]
            res = 1 if u==1 else 0
            for v in g[u]:
                if vis[v] and not bad[v]:
                    res += f(v)
                    if res>2: res=2
            dp[u]=res
            return res

        for i in range(1,n+1):
            if vis[i] and not bad[i]:
                f(i)

        out=[]
        for i in range(1,n+1):
            if not vis[i]:
                out.append("0")
            elif bad[i]:
                out.append("-1")
            else:
                out.append(str(dp[i]))
        return " ".join(out)

    return solve()

 ## 特殊なケース

 1 から到達可能なノードでの自己ループは、終了する前にループを任意に繰り返すことができるため、そのノードを即座に無限に変えます。 アルゴリズムは、DFS 中にこれをサイクルとしてマークし、そのステータスを前方に伝播して、正確さを保証します。 

ノード 1 に直接接続されていないより深いサイクルは、ノード 1 から到達可能にならない限り無視されます。最初のフェーズでは処理が到達可能なノードのみに制限され、誤検知が防止されるため、これは正しく処理されます。 

2 つの異なる着信 DAG パスを持つノードは、サイクルが 2 を返す必要があります。DP の上限が 2 であるため、一意性と多重性を区別しながら、完全なカウントを試行しないことが保証されます。 

1 による到達可能性はパスが存在するが多重度が無限であることを意味するため、サイクルを経由しない限り到達できないノードは 0 ではなく -1 である必要があります。 伝播フェーズでは、そのようなノードが無限マーカーを確実に継承します。
