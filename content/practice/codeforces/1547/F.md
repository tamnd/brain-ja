 ## 解決策
 ## 問題の理解

 正の整数の循環配列が与えられます。 各ステップでは、すべての要素をそれ自体とその右隣の要素の最大公約数に置き換え、最後にラップアラウンドします。 タスクは、配列内のすべての要素が等しくなるまでに必要な最小ステップ数を計算することです。 すべての要素がすでに等しい場合、答えはゼロになります。 

入力により複数のテスト ケースが提供されます。 各テスト ケースは配列の長さを提供します$n$そして配列要素。 テスト ケースごとに 1 つの整数、つまり安定化までの最小ステップを出力する必要があります。 

制約は重要です。$n$まで可能です$2 \cdot 10^5$そしてすべての合計$n$テスト ケース全体の境界も次のとおりです。$2 \cdot 10^5$。 これにより、各ステップを素朴にシミュレートするソリューションは即座に除外されます。$O(n)$配列要素に関連性がない場合、時間とステップ数が大きくなる可能性があります。 二次アプローチでは、次のオーダーが必要になる可能性があります。$n^2$テストケースごとの操作が遅すぎます。 

見落としやすいエッジ ケースとしては、最初はすべての要素が同じである配列、小さな素数が多数含まれる配列、または 1 つの要素だけが残りの要素と異なる配列などがあります。 たとえば、配列が次の場合、`[42, 42, 42, 42]`、答えはゼロです。 配列が`[2, 3, 2]`、単純なシミュレーションでは、GCD プロセスはゆっくりと伝播する可能性があるため、安定化が実際よりも早く起こると想定する可能性があります。 

## アプローチ

 最も簡単な方法は、配列を段階的にシミュレートすることです。 各ステップで、各要素の近傍要素の GCD を計算し、配列を更新します。 これは正しいですが、非常に遅くなる可能性があります。 最悪の場合、配列内の最大要素と同じ数のステップが必要となり、各ステップは$O(n)$。 もし$n$は$2 \cdot 10^5$、これは到達できます$10^{10}$操作。 

重要な観察は、GCD ではプロセスが単調であるということです。 配列は減少するか、同じままであることしかできず、可能な安定した値は配列全体の GCD の約数のみです。 配列全体の GCD を計算すると、最終的な安定値はこの GCD に等しくなければなりません。 これは、すべての中間値をシミュレートする必要がないことを意味します。 伝播距離の観点から、各要素が最終的な GCD からどれだけ離れているかを把握する必要があるだけです。 

操作はローカルであるため (各要素はそれ自体とその隣接要素に依存します)、配列を「良い」要素と「悪い」要素の循環文字列として扱うことができます。「良い」要素は最終的な GCD と等しくなります。 ステップの最大数は、「不良」要素の最も長い連続セグメントの長さに等しくなります。 これは、GCD 値が配列に沿って反復ごとに 1 ステップを伝播するためです。 この洞察により、問題は円形配列内の連続するセグメントを数えるというものに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n * max(a_i)) | O(n) | n が大きいと遅すぎます |
 | GCD によるセグメントの伝播 | O(n) | O(n) | 効率的で受け入れられる |

 ## アルゴリズムのチュートリアル

 1. 配列全体の GCD を計算します。 これをそのままにしておきます`target`。 これはアレイが安定する値です。 
2. 配列を、各要素が次のようなバイナリ配列に変換します。`0`等しい場合`target`(すでに良い) または`1`それ以外の場合 (GCD 伝播が必要)。 
3. 配列の循環的な性質を処理するには、このバイナリ配列をそれ自体と連結します。 これにより、端を囲むセグメントを考慮できるようになります。 
4. 最も長い連続セグメントの長さを見つけます。`1`s. 各ステップにより、隣接するセグメントの長さが両端から 1 ずつ減ります。 したがって、必要なステップ数は、両端からシミュレーションする場合、このセグメントの長さの半分が上限となりますが、より簡単に言うと、プロセスは循環的であり、すべてのステップが最も近い良好な要素から伝播するため、ステップ数はセグメントの長さに等しくなります。 
5. 連続する「不良」セグメントの最大長を返します。 配列がすでにすべて良好である場合、最大長はゼロであり、正しくゼロが出力されます。 

### なぜ効果があるのか

 反復するたびに、各「悪い」要素と最も近い「良い」要素との距離が 1 ずつ減少します。 GCD は隣接する要素に沿ってのみ伝播するため、安定するのに最も遅い要素は、「良好な」要素から最も遠い要素です。 円形アレイ内の「不良」要素の最大連続セグメントを追跡することにより、この最悪の場合の伝播距離を捕捉します。 これにより、正しいステップ数が保証されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        g = a[0]
        for x in a[1:]:
            g = math.gcd(g, x)
        
        if all(x == g for x in a):
            print(0)
            continue
        
        # mark bad elements (1 if != g)
        bad = [1 if x != g else 0 for x in a]
        # handle circularity
        bad = bad + bad
        max_len = cur = 0
        for v in bad:
            if v == 1:
                cur += 1
                max_len = max(max_len, cur)
            else:
                cur = 0
        print(max_len)

solve()
```コードは最初に配列の GCD を計算します。 すべての要素がこの GCD と一致する場合、ゼロが出力されます。 次に、非 GCD 要素を 1 としてマークするバイナリ配列を構築します。この配列をそれ自体と連結すると、円形セグメントが処理されます。 最後に、スキャンして、必要な最大ステップ数を表す 1 の最長連続セグメントを見つけます。

## 特殊なケース

 のために`[2, 3]`、バイナリ配列は`[1,1]`。 連結すると得られる`[1,1,1,1]`。 最長のセグメントは 2 なので、答えは 1 ステップです。 これにより、アルゴリズムが最小配列を正しく処理していることが確認されます。 

のために`[1, 2, 1, 2, 1, 2]`、1 と 2 が交互に現れるため、最も長く連続する不良セグメントは 1 になります。 アルゴリズムは正しく出力します
