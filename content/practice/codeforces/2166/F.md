 ## 解決策
 ## 問題の理解

 整数のシーケンスが与えられ、その要素をいくつかのサブシーケンスに分割したいと考えています。 各要素は 1 つのサブシーケンスに属している必要があり、各サブシーケンス内で、連続して選択された要素の値が 1 つだけ異なっていなければなりません。 

サブシーケンスは元の配列内で連続している必要はなく、相対的な順序のみを保持する必要があります。 したがって、各サブシーケンスは、要素をインデックスの昇順に選択することによって形成されますが、値は整数の線に沿ってステップごとに移動し、毎回 ±1 だけ移動する必要があるという制限があります。 

タスクは、すべての要素をカバーするために必要なそのようなサブシーケンスの数を最小限に抑えることです。 

すべてのテスト ケースの全長が最大 10^6 であるという制約により、シーケンス全体の二次構築が即座に除外されます。 多くの要素のペア間の遷移を明示的にテストしようとするソリューションは、遅すぎます。 問題の構造は、「現在アクティブなサブシーケンス」のコンパクトな概要を維持しながら、要素を線形または線形に近い時間でオンラインで処理する必要があることを示唆しています。 

複数のサブシーケンスが同じ値を吸収する可能性がある場合、微妙な問題が発生します。 たとえば、値 5 と値 7 で終わるシーケンスがすでにある場合、新しい要素 6 はどちらかの側に拡張できます。 選択を誤ると、現在の選択が無害であるように見えても、将来の拡張がブロックされ、後でサブシーケンスの数が増加する可能性があります。 

この問題を小さな例で説明します。 

入力:```
1
5
5 6 5 6 5
```最適な答えは 2 ですが、構造を考慮せずに常に最初に利用可能な近傍にアタッチする貪欲型は、有用なエンドポイントを途中で消費することにより、簡単に 3 つ以上のシーケンスを作成する可能性があります。 

したがって、中心的な課題は、単に一致するものを見つけるだけではなく、将来の柔軟性を維持する方法で拡張機能を選択することです。 

## アプローチ

 この問題を直接考える方法は、サブシーケンスを 1 つずつ構築することです。 未使用の要素を繰り返し取得し、±1 異なる要素を前方検索することで貪欲にチェーンを拡張しようとします。 これは概念的には機能しますが、すべての拡張スキャンは残りの多くの要素に影響を与える可能性があり、最悪の場合、これは 10^6 要素にわたる二次関数の動作に変質します。 

重要な変化は、完全なサブシーケンスを構築するという観点から考えるのをやめ、代わりに配列を左から右に処理し、サブシーケンスの現在の「開いた端」のみを維持することです。 いつでも、各サブシーケンスには最後の値があり、新しい要素は新しいサブシーケンスを開始することも、1 つだけ異なる既存のオープン エンドの 1 つに追加することもできます。 

したがって、問題はストリーミング割り当ての問題になります。値 v ごとに、それを v−1 または v+1 で終わる既存のサブシーケンスに付加するか、どちらも使用できない場合は新しいサブシーケンスを開始するかを決定する必要があります。 

重要な観察は、サブシーケンスに関して重要な情報はその最後の値だけであるということです。 完全なチェーンは必要ありません。各値で終了するアクティブなチェーンの数だけが必要です。 これにより、状態が値の周波数マップに還元され、各整数で現在「待機」しているサブシーケンスの数を表します。 

新しい値 v を処理するとき、v−1 または v+1 で終わる既存のチェーンを拡張しようとします。 両方のオプションが存在する場合、任意に選択することは安全ではありません。 より「制約された」側の無駄を避けるルールが必要です。 一貫した貪欲な戦略は、現在利用可能なエンドポイントがより多くある近隣の値に常に接続することです。これは、より大きなプールから消費することで、将来の強制一致に備えてより小さなプールの柔軟性が維持されるためです。 

これにより、問題全体が、アクティブなエンドポイントの数を維持し、可能であれば各受信値を互換性のあるエンドポイントに貪欲に一致させることに軽減されます。

 ## アルゴリズムのチュートリアル

 私たちは度数表を管理しています`cnt[x]`、 どこ`cnt[x]`最後の要素が現在存在するサブシーケンスの数です。`x`。 

私たちは答えも維持します`ans`、これまでに作成されたサブシーケンスの数。 

1. 要素を左から右に処理します。 
2. 各値について`v`、既存のサブシーケンスを拡張できるかどうかを確認します。 

もし`cnt[v-1] > 0`または`cnt[v+1] > 0`の場合、少なくとも 1 つの有効なサブシーケンスがこの要素を吸収できます。 

どちらも存在しない場合は、新しいサブシーケンスを開始して、増加させなければなりません。`ans`1ずつ増加`cnt[v]`。 
3. 少なくとも 1 つの近隣が存在する場合は、どちら側を拡張するかを選択します。 

両方の場合`cnt[v-1]`そして`cnt[v+1]`が正の場合、カウントが大きい側を選択します。 直感的には、より豊富なエンドポイント プールから最初に消費し、代替手段がない可能性のある将来の要素のために不足している側を利用できるようにしておきたいと考えます。 

選択した近隣カウントをデクリメントしてインクリメントします。`cnt[v]`、サブシーケンスのエンドポイントを効果的に前方に移動します。 
4. 近隣が 1 つだけ存在する場合は、それを使用する必要があります。 それに応じてカウントを更新します。 

すべての要素を処理した後、`ans`は形成される部分列の数です。 

### なぜ効果があるのか

 アクティブなサブシーケンスの構造は、各値で終了するサブシーケンスの数によって常に完全に把握されます。 各ステップは、新しいサブシーケンスを作成するか、既存のサブシーケンスを 1 つだけ拡張します。拡張は有効な ±1 遷移に沿ってのみ可能です。 

貪欲な選択では、グローバルな最適化は試みられませんが、重要な不変条件が保持されます。これまでにエンドポイントを割り当てる有効な方法の中で、このアルゴリズムは、将来的に一意に必要となる値の可用性を必要以上に減らすことはありません。 両方が可能な場合には、より豊富な隣接クラスから常に消費することで、希少なエンドポイント タイプが早期に無駄になり、豊富なエンドポイント タイプは未使用のまま残りますが、後で使用できなくなるという状況の発生を回避します。 

これにより、将来の要素が到着するたびに、その要素に可能性のある先行要素がある場合、アルゴリズムが最適ではない以前の選択によってその可能性を人為的にブロックしていないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # frequency of subsequences ending at value x
        cnt = {}
        ans = 0
        
        for v in a:
            left = cnt.get(v - 1, 0)
            right = cnt.get(v + 1, 0)
            
            if left == 0 and right == 0:
                ans += 1
                cnt[v] = cnt.get(v, 0) + 1
                continue
            
            # choose better side to extend
            if left >= right:
                if left > 0:
                    cnt[v - 1] -= 1
                    if cnt[v - 1] == 0:
                        del cnt[v - 1]
                else:
                    cnt[v + 1] -= 1
                    if cnt[v + 1] == 0:
                        del cnt[v + 1]
            else:
                cnt[v + 1] -= 1
                if cnt[v + 1] == 0:
                    del cnt[v + 1]
            
            cnt[v] = cnt.get(v, 0) + 1
        
        print(ans)

if __name__ == "__main__":
    solve()

分岐ロジックにより、両方の近隣が存在する場合は常に、より人口の多い側から優先的に消費されることが保証されます。 これは、貪欲な選択が重要となる唯一の部分です。 それ以外はすべて、エンドポイントの一貫性を維持することの直接の結果です。

 ## 特殊なケース

 最小の単一要素入力は、近傍が存在しない場合にアルゴリズムが新しいサブシーケンスを正しく初期化することを示しています。
