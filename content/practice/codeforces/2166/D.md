 ## 解決策
 ## 問題の理解

 整数のマルチセットが与えられていますが、これは要素が繰り返される単なるコレクションです。 The task is to count how many different multisets can be generated by repeatedly partitioning the original multiset into any number of non-empty groups and then taking one mode from each group. グループのモードは、最も頻繁に出現する任意の要素です。 複数の要素が最大頻度で同点の場合、それらのいずれかを選択できます。 出力は、この手順で作成できるすべての個別のマルチセットの数 (モジュロ 998244353) です。 

The input size per test case is up to 5000 elements, and the total sum of elements over all test cases is bounded by 5000. This indicates that an algorithm with complexity roughly O(n²) per test case is acceptable, but anything cubic would likely be too slow. また、要素は繰り返すことができるため、すべてのパーティションを単純に列挙すると、組み合わせが爆発的に増加します。 たとえば、10 個の要素を 115,000 通り以上の方法で分割できますが、これは明らかに実行不可能です。 

Edge cases to watch for include when all elements are identical, when all elements are distinct, or when there is a small number of repeated elements that could generate many different partitions with identical modes. たとえば、入力の場合`[1,2,2]`、生成できる可能なマルチセットは次のとおりです。`{2}`、`{1,2}`、`{2,2}`、 そして`{1,2,2}`。 パーティショニングではなくサブセットのみを調べる単純なアプローチでは、一部のマルチセットが見逃されてしまいます。 

## アプローチ

 ブルート フォース アプローチでは、配列のすべてのパーティションを生成し、各パーティションのモードを計算して、結果のマルチセットを列挙します。 これは原理的には正しいですが、セットのパーティション数は n の指数関数的増加よりも速く増加するため、現実的ではありません。 n=10 の場合でも、100,000 を超えるパーティションがあり、n=5000 の場合、これはまったく実行不可能です。 

重要な洞察は、周波数の観点から問題を検討することです。 パーティションの正確な構造ではなく、各パーティションのモードのみを考慮しているため、問題を動的プログラミングのアプローチに帰着させることができます。 主な観察は、マルチセットを選択する方法の数が、繰り返される要素の数の畳み込みとして表現できることです。 値と頻度で要素を並べ替え、各要素を新しいサブセットにモードとして含める回数を考慮してマルチセットの数を繰り返し構築できます。 組み合わせ論を使用して繰り返し要素を処理することにより、パーティションを直接列挙することを回避します。 これにより、問題は指数関数的なものから O(n²) 動的計画法に軽減されます。

 ## アルゴリズムのチュートリアル

 1. マルチセット内の各固有の要素の頻度を数えます。 これにより、問題は n 個の要素を扱うことから、最大でも n 個の個別の値とそのカウントを扱うことに変わります。 させて`freq[x]`要素 x が出現する回数になります。 
2. DP 配列を初期化する`dp[i]`どこ`dp[i]`は、合計サイズ i のマルチセットを作成する方法の数を表します。 から始める`dp[0] = 1`なぜなら、空のマルチセットを作成する方法は 1 つだけだからです。 
3. それぞれの一意の要素を反復処理します。`val`で`freq`注文。 その要素の可能な数ごとに`k`1から`freq[val]`、DP 配列を更新して、次のようにして形成された新しいマルチセットを含めます。`k`のコピー`val`。 これは古典的な組み合わせステップです。以前にサイズのマルチセットを作成できた場合`i`、サイズのマルチセットを作成できるようになりました`i+k`追加することで`k`のコピー`val`。 
4. すべての要素を処理した後、すべてを合計します。`dp[i]`のために`i >= 1`空ではないすべてのマルチセットをカウントします。 和を剰余998244353とします。 
5. この合計をテスト ケースの答えとして返します。 

機能する理由: DP 配列は、達成可能なすべての個別のマルチセット サイズを効果的に追跡します。 各要素を反復処理してすべてのカウントを考慮するため、モード選択手順を使用して形成できるすべての可能なマルチセットをカウントすることが保証されます。 このアプローチでは、パーティションの明示的な列挙を回避しますが、頻度カウントに対応するステップで DP 配列をインクリメントすることで、複数のモードの組み合わせの可能性を考慮します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        from collections import Counter
        freq = list(Counter(a).values())
        
        dp = [0]*(n+1)
        dp[0] = 1
        
        for f in freq:
            ndp = dp[:]
            for i in range(n+1):
                if dp[i]:
                    for k in range(1, f+1):
                        if i+k <= n:
                            ndp[i+k] = (ndp[i+k] + dp[i]) % MOD
            dp = ndp
        
        ans = sum(dp[1:]) % MOD
        print(ans)

solve()
```このソリューションでは、カウンターは各固有の要素の頻度を収集します。 の`dp`配列はサイズのマルチセットの数を追跡します`i`。 要素周波数ごとに、一時的な配列を作成します`ndp`更新中に既存の DP 状態が上書きされないようにします。 内側のループにより、1 を次の値まで考慮することが保証されます。`f`要素のコピー。 合計する`dp[1:]`空ではないマルチセットの総数を示します。 

## 実用的な例

 入力用`[1,2,3]`、周波数リストは次のとおりです。`[1,1,1]`。 DP アレイは次のように進化します。 

| ステップ | DP 配列 (ゼロ以外のエントリのみ) |
 | --- | --- |
 | イニシャル | dp[0]=1 |
 | プロセス1 | dp[1]=1 |
 | プロセス2 | dp[1]=2、dp[2]=1 |
 | プロセス3 | dp[1]=3、dp[2]=3、dp[3]=1 |

 合計する`dp[1:]`7 が得られ、予想される出力と一致します。 

入力用`[1,2,2]`、周波数リストは`[1,2]`:

 | ステップ | DP 配列 |
 | --- | --- |
 | イニシャル | dp[0]=1 |
 | プロセス1 | dp[1]=1 |
 | プロセス2 | dp[1]=2、dp[2]=1、dp[3]=1 |

 の合計`dp[1:]`は 4 で、予想される出力と一致します。 

これらのトレースは、グループ間で要素を分割する必要があるものを含む、モード選択手順によって形成されたすべてのマルチセットを DP が正しくカウントしていることを示しています。
