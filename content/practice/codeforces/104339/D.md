 ## 解決策
 ## 問題の理解

 すでに 16 進値として提供されているバイトのストリームが与えられているので、その生のバイナリ データを、標準のアルファベットを使用して Base64 でエンコードされた文字列に変換する必要があります。`ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/`。 

エンコードは、入力バイトを 3 つのチャンクにグループ化することで機能します。 3 バイトの各グループは 24 ビット整数を形成します。 次に、その 24 ビット ブロックが 4 つの 6 ビット セグメントに分割され、各セグメントが Base64 アルファベットへのインデックスとして使用されて 4 つの文字が生成されます。 最後のグループのバイト数が 3 バイト未満の場合でも、概念的には欠落したバイトを 0 ビットで埋めて 24 ビット ブロックを構築しますが、出力は切り捨てられて埋め込まれます。`=`最終的な長さが 4 文字の倍数になるようにします。 

出力は、入力全体を表す単一の連続した Base64 文字列です。 

The constraints allow up to 50,000 bytes. 作業は入力サイズに対して線形であるため、バイトごとまたはビットごとの直接シミュレーションはまったく問題ありません。 O(n) よりも悪いものは不要です。Python では、数百万の原始的な操作でも簡単に十分に高速です。 

入力長が 3 で割り切れない場合、微妙なエッジ ケースが発生します。 たとえば、次のようなシングルバイト入力`0F`2 つの Base64 文字とその後に続く文字を生成する必要があります。`==`、パディング ビットが正しく解釈されない 4 つの計算文字ではありません。 不注意な実装では、余分な出力を抑制することを忘れたり、パディング シフトを誤って処理したりすることがよくあります。 

もう 1 つの問題は、境界でのバイトのグループ化です。 たとえば、2 バイトの場合でも、アルゴリズムはゼロをシフトインすることによって 24 ビット ブロックを形成しますが、パディング前に有効な Base64 文字は 3 つだけです。 マスキングが正しくない場合、または「実際の」バイトと「埋め込まれた」バイトの区別に失敗すると、末尾のシンボルが正しくなくなります。 

## アプローチ

 ブルートフォース解釈では、各バイトのビット操作を直接シミュレートし、ビットを連結して増加する文字列または整数にし、それを 6 ビットのチャンクにスライスします。 Base64 は基本的にビットパッキング変換であるため、これが機能します。 ただし、ビット文字列の構築とスライスを繰り返し行うと、定数係数が大きくビットの総数に比例するオーバーヘッドが発生し、ループ内の単純な文字列連結により 50,000 バイトのパフォーマンスが大幅に低下する可能性があります。 

重要な観察は、Base64 が固定サイズのブロックで動作するということです。 3 バイトごとに 4 つの文字が独立して生成されます。 これにより、増加するビット バッファーを維持することなく、入力をチャンクで処理できるようになります。 ビットを明示的にシミュレートする代わりに、シフトとビットごとの OR 演算を使用して 24 ビット整数を直接計算し、シフトを使用して 4 つの 6 ビット インデックスを抽出します。 

最後の部分ブロックについても、同じ方法で 24 ビット値を計算しますが、1 バイトか 2 バイトかに応じて最初の 2 文字または 3 文字のみを出力し、その後に必要なパディングが続きます。 

これにより、問題は、ブロックごとの定数処理によるバイト配列に対する単純な線形スキャンに縮小されます。

 ## アルゴリズムのチュートリアル

 入力バイトを 3 つのグループに分けて処理します。 

1. 16 進文字列からすべてのバイトを整数として読み取ります。 これにより直接数値が得られ、後で解析を繰り返す必要がなくなります。 
2. バイト配列を 3 つのステップで繰り返します。 完全なグループごとに:

 最初のバイトを 16 ビット左にシフトし、2 番目のバイトを 8 ビット左にシフトし、3 番目のバイトをそのまま加算することにより、24 ビット整数を構築します。 これにより、元の順序が単一のパックされた値に保存されます。 
3. この 24 ビット整数から 4 つの 6 ビット セグメントを抽出します。 これを行うには、それぞれ 18、12、6、0 ビットずつ右にシフトし、次でマスクします。`63`最後の 6 ビットを分離します。 各値は Base64 アルファベットにインデックス付けされます。 
4. 出力文字列に 4 つの文字を追加します。 
5. 残っているバイト数が 3 バイト未満の場合は、同じ 24 ビット バッファを構築しますが、不足しているバイトはゼロとして扱います。 1 バイトだけが残っている場合は、2 つの有効な Base64 文字を生成し、追加します。`==`。 2 バイトが残っている場合は、3 つの文字を生成して追加します。`=`。 

### なぜ効果があるのか

 正確さは、Base64 が 24 ビット ブロックと 4 つの 6 ビット シンボル間の全単射であるという事実から得られます。 3 バイトの完全なグループはすべて正確に 24 ビットを構成し、それらを固定の 6 ビット ウィンドウに分割すると、重複することなく元のバイナリ構造が保存されます。 欠落ビットはエンコード定義と実装の両方で一貫してゼロで埋められるため、パディングによってエンコードされたプレフィックスは変更されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

ALPHABET = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/"

def encode_base64(n, data):
    out = []

    i = 0
    while i < n:
        b1 = data[i]
        i += 1

        b2 = data[i] if i < n else None
        i += 1 if i < n else 0

        b3 = data[i] if i < n else None
        i += 1 if i < n else 0

        # build 24-bit buffer
        x = b1 << 16
        if b2 is not None:
            x |= b2 << 8
        if b3 is not None:
            x |= b3

        # always compute full 4 indices
        c1 = ALPHABET[(x >> 18) & 63]
        c2 = ALPHABET[(x >> 12) & 63]
        c3 = ALPHABET[(x >> 6) & 63]
        c4 = ALPHABET[x & 63]

        if b2 is None:
            out.append(c1 + c2 + "==")
        elif b3 is None:
            out.append(c1 + c2 + c3 + "=")
        else:
            out.append(c1 + c2 + c3 + c4)

    return "".join(out)

def main():
    n = int(input().strip())
    data = list(map(lambda x: int(x, 16), input().split()))
    print(encode_base64(n, data))

if __name__ == "__main__":
    main()
```この実装では、厳密に最大 3 バイトのブロック単位で処理が行われます。 シフトを使用したビット パッキング ステップにより、バイナリ文字列を明示的に管理する必要がなくなりました。 でマスキング`& 63`抽出された各セグメントが有効な Base64 インデックスであることを保証します。 

最後のブロックの取り扱いには注意が必要です。 このロジックは、2 番目または 3 番目のバイトが存在するかどうかを明示的にチェックし、それに基づいてパディングを決定します。 よくある間違いは、常に 4 文字を出力してからパディングを追加することです。これにより、短い最終ブロックに対して不正なエンコードが生成されます。

 ## 特殊なケース

 のような半角入力`00`パディングロジックを直接実行します。 アルゴリズムは 24 ビット ブロックを構築します`0x000000`、すべてゼロに等しいインデックスを抽出し、`AAAA`, and then truncates to `AA==`。 これにより、余分な文字の抑制が抽出前ではなく抽出後に行われることが確認されます。

 A two-byte input like`FF FF`完全な 24 ビット値を生成します`0xFFFF00`。 最初の 3 つの Base64 文字は有効ですが、4 番目の文字は破棄され、次の文字に置き換えられます。`=`。 シフトアンドマスクのアプローチにより、ビット計算を特殊化することなく、出力の長さが異なるだけで正しい中間値が計算されます。
