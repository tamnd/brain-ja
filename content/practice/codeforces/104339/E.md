 ## 解決策
 ## 問題の理解

 10 進形式の実数の 2 つのテキスト表現が与えられており、どちらが大きいか、または等しいかどうかを判断する必要があります。 問題は、書式設定が非常に緩いことです。 数値には、オプションの整数部分、オプションの小数部分、またはその両方を含めることができますが、両方が欠落することはありません。 小数部分がない場合は小数点が存在しない可能性があり、小数点のどちらかの側も欠落している可能性があり、事実上ゼロのように動作します。 先頭のゼロと末尾のゼロは無関係であり、任意の量で表示されます。 

概念的には、各入力文字列は非負の実数を基数 10 でエンコードしますが、正規形式ではエンコードしません。 このタスクは純粋に数値の比較であり、文字列の順序ではありません。 

制約は、各入力文字列の長さによって決まります (最大 100,000 文字)。 これにより、精度とパフォーマンスの両方が低下するため、数値を浮動小数点型または Python 10 進数に変換して正規化する戦略は即座に除外されます。 小数部は整数部と同じくらい大きくなる可能性があるため、大きな整数の算術演算であっても慎重に扱う必要があります。 

主な難点は、表現が整数と分数の 2 つの独立した要素に分割されており、正規化後に巨大な中間数値を構築せずに両方を辞書編集的に比較する必要があることです。 

いくつかのエッジケースでは、単純なソリューションがサイレントに失敗する原因となります。 

最初の例は、整数部分の先頭のゼロが異なることです。 考慮する`00012.3`対`12.3`。 文字列の比較では、辞書編集上の順序により最初の文字列が誤って小さいものとして扱われますが、数値的には整数の大きさが同じです。 

2 番目の例は、整数部分が欠落している場合です。 のように入力してください`.15`を表します`0.15`、次のようなものと正しく比較する必要があります`0.149999`。 

3 番目の例は、1 つの数値の小数部分が長い場合の分数比較です。 例えば、`1.2300`そして`1.23`たとえ生の文字列が異なっていても、等しくなります。 小数文字列を直接比較する単純な比較では、余分な文字により最初の文字列が大きいと誤って判断してしまいます。 

これらの問題は、数値を計算するのではなく、構造を正規化する必要があることを示しています。 

## アプローチ

 ブルートフォースアプローチは、各文字列を高精度の 10 進数オブジェクトに解析するか、数値全体を 10 の最大小数部長の乗でスケールされた単一の整数に変換することで任意精度の算術演算をシミュレートすることです。 それぞれの数値について、小数部の長さを決定し、それに応じて整数部分を埋め込み、連結し、大きな整数として比較する必要があります。 

両方の数値が同等の整数表現に変換されるため、これは原理的には正しく機能します。 ただし、コストが問題になります。 両方の数値が最大 100,000 桁で、それらを 1 つの大きな整数文字列に連結する場合、比較自体は O(n) で、変換と正規化にも O(n) が必要です。 実際にはこれは境界線にとどまりますが、慎重に実装された場合にのみ Python で許容されます。 ただし、割り当てとパディングを繰り返すと脆弱になります。 

もっと良い観察は、結合された数値を構築する必要がないということです。 最初に整数部分のみを比較する必要があり、それらが等しい場合にのみ小数部分を比較します。 各部分内での正規化は、純粋に先頭または末尾のゼロを無視することです。 

したがって、問題は、制御された正規化規則の下での文字列比較に帰着します。つまり、整数部分の先頭のゼロを取り除き、小数部分の末尾のゼロを取り除き、長さと辞書編集上の順序を比較します。 

これにより、数値の構築から 2 つのクリーンな文字列ペアの比較までの問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (大きな整数の正規化) | 数値ごとに O(n)、重い定数 | O(n) | 危険 |
 | 最適化 (パーツの分割と正規化) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各入力文字列をドットの前後で整数部分と小数部分に分割します。 ドットが存在しない場合は、小数部を空として扱います。 文字列がドットで始まる場合は、整数部分を空として扱います。 
2. 先頭のゼロを削除して整数部分を正規化します。 結果が空になった場合は、次のように置き換えます。`"0"`。 これにより、次のような値が保証されます。`"000"`そして`""`どちらもゼロを表します。 
3. 末尾のゼロを削除して小数部分を正規化します。 空になった場合は次のように扱います。`""`。 私たちはそれを強制しません`"0"`分数の等価性は長さと内容に依存するためです。 
4. まず整数部分を比較します。 一方の桁数が他方よりも多い場合、長い方が大きな数値を表します。 同じ長さで辞書順が異なる場合、それによって結果が決まります。 
5. 整数部分が等しい場合は、小数部分を比較します。 まず小数文字列の長さで比較します。 小数部分が長いほど、等価性を超える精度が高くなるため、`1.2300`になる`1.23`トリミング後、それらは等しくなります。 
6. 長さが等しい場合は、辞書順に桁ごとに比較します。 
7. 両方の部分が正確に一致する場合、数値は等しくなります。 

### なぜ効果があるのか

 この問題におけるすべての実数は、冗長なゼロを削除した後の整数の大きさと小数部の拡張によって一意に決定されます。 正規化により、各値が正準形式にマップされることが保証され、整数の比較では大きさが反映され、分数の比較では整数部分が一致する場合にのみ詳細な順序付けが反映されます。 両方の部分が重要度の降順で比較されるため、常に整数の優位性が最初に決定され、分数比較は同点のみを解決します。 この構造は、実数との順序の等価性を保持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def split_num(s: str):
    if '.' in s:
        a, b = s.split('.')
    else:
        a, b = s, ""

    a = a.lstrip('0')
    if a == "":
        a = "0"

    b = b.rstrip('0')
    return a, b

def cmp(a1, b1, a2, b2):
    if len(a1) != len(a2):
        return 1 if len(a1) > len(a2) else -1
    if a1 != a2:
        return 1 if a1 > a2 else -1

    if b1 == b2:
        return 0

    if len(b1) != len(b2):
        return 1 if len(b1) > len(b2) else -1

    if b1 > b2:
        return 1
    return -1

s1 = input().strip()
s2 = input().strip()

a1, b1 = split_num(s1)
a2, b2 = split_num(s2)

print(cmp(a1, b1, a2, b2))
```分割関数は、各数値を正規表現に変換する役割を果たします。 整数部分から先頭のゼロが取り除かれ、正しい大きさの比較が保証されます。 小数部分から末尾のゼロが取り除かれ、等価な 10 進展開が発散しないことが保証されます。 

比較関数は、文字列を数値型に変換することを慎重に回避します。 整数部分は、最も重要な決定要因である長さを使用して最初に比較されます。 長さが一致する場合にのみ、辞書編集的な比較に戻ります。 

分数比較は、タイブレーカーとしてのみ使用されます。 長さの比較が最初に使用されます。`"123"`対`"1230"`そうしないと、正規化せずに辞書順に処理すると、誤った比較が行われてしまいます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各文字列は、分割およびトリミングのために一定の回数スキャンされます。 
| スペース | O(n) | 最悪の場合の正規化された文字列を保存 |

 各文字が一定の回数処理され、大きな中間数値オブジェクトが構築されないため、この解は制約内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def split_num(s: str):
        if '.' in s:
            a, b = s.split('.')
        else:
            a, b = s, ""
        a = a.lstrip('0')
        if a == "":
            a = "0"
        b = b.rstrip('0')
        return a, b

    def cmp(a1, b1, a2, b2):
        if len(a1) != len(a2):
            return 1 if len(a1) > len(a2) else -1
        if a1 != a2:
            return 1 if a1 > a2 else -1
        if b1 == b2:
            return 0
        if len(b1) != len(b2):
            return 1 if len(b1) > len(b2) else -1
        return 1 if b1 > b2 else -1

    s1 = input().strip()
    s2 = input().strip()
    a1, b1 = split_num(s1)
    a2, b2 = split_num(s2)
    return str(cmp(a1, b1, a2, b2))

# provided samples
assert run("211.000000000000000001\n211\n") == "1", "sample 1"
assert run("15\n00000000015.00000000\n") == "0", "sample 2"
assert run(".15\n00000000015.00000000\n") == "-1", "sample 3"

# custom cases
assert run("0.0\n0") == "0", "both zero forms"
assert run("000.0001\n0.0001000") == "0", "fraction normalization"
assert run("1.1\n1.10") == "0", "trailing zero fraction equality"
assert run("2\n10") == "-1", "integer length dominance"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`0.0 vs 0`| 0 | 完全なゼロ正規化 |
 |`000.0001 vs 0.0001000`| 0 | 分数トリミングの正確性 |
 |`1.1 vs 1.10`| 0 | 末尾の小数点ゼロは無視されます。 
|`2 vs 10`| -1 | 整数の長さ比較の正確性 |

 ## 特殊なケース

 微妙なケースの 1 つは、ゼロを削除した後に両方の整数部分が空になる場合です。 例えば、`0000.5`そして`.5`両方とも同じ整数値を表します`0`。 正規化ステップでは、空の整数文字列を強制的に`"0"`, したがって、小数部の比較の前には両方が同一になります。 

もう 1 つのケースは、トリミング後に小数部分が空になる場合です。 例えば、`1.2300`整数になる`1`そして分数`23`、 その間`1.23`同じになります。 分数比較では、空の文字列が両方とも空であるか、両方が一致する場合にのみ等しいものとして扱われるため、等価性は維持されます。 

最後のエッジ ケースは、長さは同じだが辞書編集上の値が異なる大きな整数部分です。`999`そして`100`。 辞書順にしても`"999" > "100"`、長さの比較は同一であるため、辞書編集的な比較により、数値変換を行わずに順序が正しく解決されます。
