 ## 解決策
 ## 問題の理解

 4 つの正の整数の重みが与えられ、システムのバランスが完全に取れるように、それらすべてを天秤に乗せることが可能かどうかを判断することが課題となります。 各重りは左の皿または右の皿のいずれかに置くことができ、すべての重りは 1 回だけ使用する必要があります。 

主な要件は、4 つのケトルベルすべてを割り当てた後、左側のパンの合計重量が右側のパンの合計重量と等しくなることです。 すべてを使用する以外に、各サイドに移動するアイテムの数に制限はありません。 

常に正確に 4 つの数値があるため、入力サイズは非常に小さくなります。 これにより、漸近最適化の必要がなくなります。 各ケトルベルには左または右の 2 つの選択肢があり、構成は 2⁴ = 16 しかないため、すべての割り当てを完全に列挙することも可能です。 

このタイプの問題における単純な間違いは、隣接する値を並べ替えたりペアにしたりすれば十分だと考えることです。 バランスは順序ではなく組み合わせに依存するため、これは失敗します。 たとえば、重みが 1 2 3 4 の場合、(1 + 4) 対 (2 + 3) のような貪欲なペアリングは機能しますが、ソートされたペアリングが常に唯一の意味のある構造であるという保証はありません。 唯一信頼できる基準は、セットを 2 つのグループに分割したものの合計が等しいかどうかです。 

もう 1 つの微妙な落とし穴は、合計が 2 で割り切れる必要があると仮定して、すぐに実現可能であると結論づけることです。 その条件は必要ですが、十分ではありません。 たとえば、1 1 1 3 の合計は 6 で、2 で割り切れますが、部分集合の合計が 3 になることはありません。 

## アプローチ

 強引なアイデアは、各ケトルベルを左側または右側に割り当てるあらゆる方法を試すことです。 割り当てごとに、両側の差を計算し、それがゼロになるかどうかを確認します。 4 つのアイテムのそれぞれが独立してサイドを選択するため、2⁴ = 16 の可能性があります。 各構成を評価するには継続的な作業が必要なため、これは非常に高速です。 

これは n = 4 に対してすでに最適ですが、一般化は不十分です。 項目が n 個ある場合、総当りアプローチは 2ⁿ に増加しますが、一般的な制約で n が約 25 ～ 30 を超えると、これは実行不可能になります。 この問題における重要な観察点は、n が固定で小さいため、列挙やサブセット推論を超えて漸近的な改善を探す必要がないということです。 

この問題は、配列を合計が等しい 2 つのサブセットに分割するものであると解釈することもできます。 これは古典的なサブセット合計パーティション チェックです。 4 つの要素を使用すると、サイズ 0 ～ 4 のすべてのサブセットを単純にチェックし、合計が合計の半分に等しいサブセットがあるかどうかを検証できます。

 ## アルゴリズムのチュートリアル

 問題を、4 つの重みが等しい合計で 2 つのグループに分割できるかどうかを確認することに縮小します。 

1. 4 つの重みすべての合計を計算します。 この合計が奇数の場合は、直ちに停止し、NO を出力します。 奇数の合計を 2 つの等しい整数に分割することはできません。 
2. 目標を総額の半分とする。 次に、4 つの数値の一部の合計がこの目標に正確に一致するかどうかを判断する必要があります。 
3. 4 つのインデックスのすべてのサブセットを繰り返します。 各サブセットは、どの重みを左パンに入れるかの選択を表します。 残りの重みは暗黙的に右のパンに移動します。 
4. サブセットごとに、選択した要素の合計を計算します。 それがターゲットと等しい場合、有効なパーティションが存在すると直ちに結論付けることができます。 
5. すべての可能性をチェックした後、ターゲットに一致するサブセットがない場合は、NO を出力します。 

サブセットを反復する背後にある理由は、バランスのすべての有効な配置が、一方の側のサブセットの選択に一意に対応するということです。 この表現には重複した構成や欠落している構成はありません。 

### なぜ効果があるのか

スケールの有効な構成は、4 つの重みを 2 つの互いに素なグループに分割することに対応します。 このようなパーティションはすべて、インデックスのサブセットによって 1 回だけ表されます。 したがって、すべてのサブセットをチェックすると、考えられるすべての物理的配置が網羅されます。 各パーティションの合計が等しいかどうかを直接テストするため、一致が成功した場合は有効なバランス配置が保証され、すべてのサブセットにわたって失敗した場合は存在しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    p = list(map(int, input().split()))
    total = sum(p)

    if total % 2:
        print("NO")
        return

    target = total // 2
    n = 4

    for mask in range(1 << n):
        s = 0
        for i in range(n):
            if mask & (1 << i):
                s += p[i]
        if s == target:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```この実装では、まず 4 つの整数を読み取り、それらの合計を計算します。 パリティ チェックにより、合計が奇数の場合に不必要な列挙が回避されます。 

ビットマスク ループは、4 つの重みのすべてのサブセットを列挙します。 各ビットは、左側のパンに重みが置かれているかどうかを表します。 内側のループはサブセットの合計を累積します。 いずれかのサブセットがターゲット合計に一致する場合、直ちに YES が出力されます。 

必要な有効なパーティションは 1 つだけであるため、早期に返すことが重要です。 16 のサブセットのどれも機能しない場合、最終的な答えは「いいえ」です。 

## 実用的な例

 ### 例 1:`7 3 5 5`合計は20なので目標は10です。

 | 0000 | {} | 0 | いいえ |

 サブセット {7, 3} は合計が 10 の片側を形成し、残りの {5, 5} も合計が 10 になります。これにより、有効なバランスが存在することが確認されます。 

### 例 2:`7 3 5 6`合計は 21 で奇数です。 アルゴリズムは列挙せずに直ちに拒否します。 

これは、検索前に不可能なケースをフィルタリングするパリティ チェックの有用性を示しています。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    import io as sysio

        return

        for i in range(n):

                s += p[i]
        if s == target:
            print("YES")
            return

    print("NO")

assert run("7 3 5 6") == "NO", "sample 2"

# custom cases
assert run("1 1 1 1") == "YES", "two pairs"
assert run("1 2 3 4") == "YES", "classic partition"
assert run("1 1 1 3") == "NO", "sum even but impossible"
assert run("10 10 10 10") == "YES", "all equal"

 ## 特殊なケース

 エッジケースの 1 つは、すべての数値が同一である場合です。`10 10 10 10`。 このアルゴリズムはサブセットを列挙し、両側の 2 つの要素などの有効な分割をすばやく見つけます。 多くのマスクは同じ合計構造を生成しますが、少なくとも 1 つはちょうど半分に達するため、サブセット列挙によって正確さが保証されます。 

もう 1 つのケースは、次のように合計が奇数の場合です。`7 3 5 6`。 アルゴリズムはパリティ チェックの直後に終了します。 これは安全です。合計が奇数の場合、2 つの等しい合計に分割される整数は存在しないため、サブセット検索をスキップしても有効な構成が見逃されることはありません。 

より微妙なケースは、`1 1 1 3`。 合計が偶数であっても、サブセット列挙では合計が 3 になるグループを見つけることができません。アルゴリズムは 16 個のマスクをすべて使い果たした後に正しく拒否し、パリティだけでは十分ではなく、小さなインスタンスであっても完全なサブセット チェックが必要であることを確認します。
