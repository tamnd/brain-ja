 ## 解決策
 ## 問題の理解

 重み付き有向グラフとしてモデル化されたネットワークが与えられます。 各エッジには、その接続に沿ってフローの単位を送信するのにどれだけのコストがかかるかを表すコストがあります。 

グラフの横に、独立した「商品」のコレクションがあります。 各コモディティはソース ノードとターゲット ノードを指定し、そのコモディティのタスクは、フローの 1 単位をソースから宛先に送信することです。 コモディティ間には相互作用はありません。各コモディティは容量の制約を共有せず、あるコモディティのルーティングの選択が他のコモディティのコストや実現可能性に影響を与えることはありません。 それぞれがネットワーク内で単独であるかのように動作します。 

すべての商品について、グラフ内の有効なパスに沿ってそのユニット フローをソースから宛先に送るために必要な最小コストを決定する必要があります。 最終出力では、通常は合計することによって、これらの個々の最小コストが 1 つの回答に集約されます。 

したがって、入力の構造は、グラフ定義とそれに続く複数の独立した最短パス クエリで構成されます。 

複雑さの観点から見ると、支配的な要因はノード、エッジ、コモディティの数です。 ノード数を次のように表すと、$n$、エッジとして$m$、および商品として$k$の場合、商品ごとに最短経路を単純に再計算するソリューションには、グラフ最短経路アルゴリズムを最大で実行することが含まれます。$k$回。 ダイクストラのアルゴリズムを使用すると、$O(m \log n)$、これは次のようになります$O(k \cdot m \log n)$の場合にのみ許容されます。$k$が小さいか、グラフが十分にまばらです。 

主なエッジケースは、グラフの構造と到達可能性に由来します。 商品の供給元が目的地に到達できない場合、最短経路のコストは事実上無限になります。 不用意に実装すると、これをゼロとして扱うか、完全に無視する可能性があります。 

たとえば、ノードを含むグラフを考えてみましょう。$1 \rightarrow 2$からの発信エッジはありません$2$、からの商品$2$に$1$。 有効なパスがないため、正解の寄与は不可能性を反映する必要があります (多くの場合、大きな値として扱われるか、ステートメントに応じて明示的に処理されます)。 もう 1 つの一般的な問題は、同じノード間に異なる重みを持つ複数のエッジがあり、最小エッジの重みを維持できないと最短パスが歪む可能性があります。 

## アプローチ

 この問題に対処する最も直接的な方法は、各商品を個別に扱うことです。 特定のソース ノードに対して、ダイクストラのアルゴリズムなどの最短パス アルゴリズムを実行して、他のすべてのノードまでの最小距離を計算し、必要な宛先までの距離を読み取ります。 

これが機能するのは、各商品が完全に独立しているためです。つまり、フロー間に結合がないため、1 つのフローを解決しても他のフローには影響を与えません。 正しさは、非負の重みをもつ重み付きグラフの最短経路の定義からすぐにわかります。 

ただし、このアプローチでは、基本的に同じ計算が何度も繰り返されます。 あれば$k$コモディティ、我々は最終的にダイクストラを実行することになるかもしれない$k$回。 各実行コスト$O(m \log n)$、したがって、合計コストは次のようになります$O(k \cdot m \log n)$。 両方のとき$k$そして$m$が大きい場合、これでは遅くなりすぎます。 

重要な観察は、グラフ構造がすべての商品にわたって再利用されていることです。 「多くのフローの問題」という観点から考えるのではなく、タスクを「多くの最短経路クエリ」に落とし込みます。 これにより、単一ソースの最短パス計算を繰り返すか、ソースごとにクエリをグループ化し、個別のソースごとにダイクストラを 1 回実行するなど、より最適化された戦略が必要になります。 これにより、複数の商品が同じ開始ノードを共有する場合の冗長な作業が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (商品ごとのダイクストラ) |$O(k \cdot m \log n)$|$O(n + m)$| 最悪の場合遅すぎる |
 | 最適化 (ソース + ダイクストラによるグループ化) |$O(s \cdot m \log n)$、 どこ$s$| は個別のソースの数です。$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフを読み取り、隣接リストとして保存します。最短パスを繰り返しクエリするため、すべてのエッジを保持します。 この表現により、出力エッジを効率的に緩和できます。 
2. それぞれがペアで定義されているすべての商品を収集する$(s, t)$。 ソース ノードから最短パスの計算を実行するだけでよいため、それらを読み取るときに、どのソース ノードが表示されるかも記録します。 
3. コモディティをソース ノードごとにグループ化します。 これにより、単純なアプローチにおける冗長性の主な原因である、同じ開始点から最短パスを複数回再計算することが回避されます。 
4. 個別のソース ノードごとに、グラフ全体に対してダイクストラのアルゴリズムを 1 回実行します。 距離を無限大で初期化し、ソース距離をゼロに設定します。 
5. ダイクストラ中に、既知の最小距離を持つノードを繰り返し抽出し、その出力エッジを緩和します。 各緩和は、近隣に対する既知の最良のコストを改善しようとします。 これにより、ノードが最小限の距離でポップされると、その最短パスが確定されます。 
6. ソースの完全な距離配列を計算した後、各宛先ノードまでの事前計算された距離を読み取ることによって、そのソースに由来するすべての商品を答えます。 
7. 目的地に到達できない場合 (距離が無限大のまま)、問題に必要な規則に従って処理します。多くの場合、それを寄与度ゼロまたは大きなセンチネル値として扱います。 

これが機能する主な理由は、ダイクストラを実行するたびに、ソースをルートとする正しい最短パス ツリーが生成されるためです。 コモディティは相互作用しないため、各クエリは、そのツリーによって定義された事前計算された計量空間への単純な検索にすぎません。 

### なぜ効果があるのか

 ダイクストラの実行中のどの時点でも、アルゴリズムは、未訪問のノード間の最小の暫定距離がすでにソースからの真の最短パス距離であるという不変条件を維持します。 すべてのエッジの重みは負ではないため、後で緩和しても最終的なノードの距離を改善することはできません。 これにより、アルゴリズムが終了すると、保存されたすべての距離が最小になることが保証されるため、各商品クエリは直接検索によって最適に回答されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq
from collections import defaultdict

INF = 10**30

def dijkstra(start, adj, n):
    dist = [INF] * (n + 1)
    dist[start] = 0
    pq = [(0, start)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

def solve():
    n, m, k = map(int, input().split())

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        adj[u].append((v, w))

    queries = defaultdict(list)
    sources = set()

    for _ in range(k):
        s, t = map(int, input().split())
        queries[s].append(t)
        sources.add(s)

    total = 0

    for s in sources:
        dist = dijkstra(s, adj, n)
        for t in queries[s]:
            if dist[t] < INF:
                total += dist[t]

    print(total)

if __name__ == "__main__":
    solve()
```グラフは隣接リストとして保存されるため、各ダイクストラ実行は出力エッジを効率的に通過できます。 優先キューにより、常に最も近い未処理のノードが最初に拡張されます。 

クエリは辞書を使用してソースごとにグループ化され、同一の開始点からダイクストラが繰り返し実行されるのを防ぎます。 これは、単純なクエリごとのアプローチに対する主な最適化です。 

距離配列では、到達不能なノードに対して大きなセンチネル値が使用され、結果を合計するときにそれらのケースは無視され、到達不能な商品は何も貢献しないか、解釈に応じて除外されるという考えと一致します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf
    import heapq
    from collections import defaultdict

    INF = 10**30

    def dijkstra(start, adj, n):
        dist = [INF] * (n + 1)
        dist[start] = 0
        pq = [(0, start)]
        while pq:
            d, u = heapq.heappop(pq)
            if d != dist[u]:
                continue
            for v, w in adj[u]:
                nd = d + w
                if nd < dist[v]:
                    dist[v] = nd
                    heapq.heappush(pq, (nd, v))
        return dist

    n, m, k = map(int, sys.stdin.readline().split())
    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, w = map(int, sys.stdin.readline().split())
        adj[u].append((v, w))

    queries = defaultdict(list)
    sources = set()

    for _ in range(k):
        s, t = map(int, sys.stdin.readline().split())
        queries[s].append(t)
        sources.add(s)

    ans = 0
    for s in sources:
        dist = dijkstra(s, adj, n)
        for t in queries[s]:
            if dist[t] < INF:
                ans += dist[t]

    return str(ans)

 ## 特殊なケース

 微妙なケースの 1 つは、商品の供給源がその目的地と等しい場合です。 クエリ (1 → 1) を含む単一ノード グラフのような入力の場合、ダイクストラはソースで距離をゼロに初期化し、すぐにゼロのコストを生成します。 アルゴリズムは、これを有効な長さゼロのフローとして正しくカウントします。 

もう 1 つのケースには、到達できない宛先が含まれます。 エッジ 1 → 2 および 3 → 4 を持つグラフの場合、クエリ (1 → 4) は 1 からのダイクストラ後の距離を無限大に残します。実装ではこれを明示的にチェックし、合計への追加を回避し、オーバーフローや不正な寄与がないことを保証します。 

3 番目のケースは、異なる重みを持つノードの同じペア間に複数のエッジがある場合です。 たとえば、重み 5 と 2 のエッジ 1 → 2。緩和中は、すべての改善チェックが距離配列内の現在最もよく知られている値と比較されるため、より小さい仮の距離を生成するエッジのみが保持されます。
