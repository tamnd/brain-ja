 ## 解決策
 ## 問題の理解

 それぞれが正の整数の高さで表される垂直塔のコレクションが与えられます。 1 回の操作で目標の高さを選択します$H$、そしてそれよりも高いすべての塔$H$正確にカットされています$H$、短い塔は変更されません。 この操作のコストは、すべてのタワーから削除されたキューブの総数であるため、選択した高さとタワーの現在の構成の両方によって異なります。 

このような操作を複数実行することができます。 操作は、コストが指定された制限を超えない場合にのみ有効とみなされます。$k$。 目標は、すべてのタワーが最終的に同じ高さになるまで、最小限の有効な操作を実行することです。 

ここで重要な構造は、すべての操作で高さのみが減少し、各操作ですべてのタワーに適用されるグローバルしきい値が選択されるということです。 これは、プロセスが一連の降順な「レベル」であることを意味し、最終状態はシステム内にすでに存在する高さ、または繰り返しの削減によって到達できる高さでなければなりません。 

制約は大きく、最大で$2 \cdot 10^5$塔。 これにより、考えられるそれぞれの高さをシミュレートし、二次時間で単純にコストを再計算するソリューションは除外されます。 スライスを繰り返す直接シミュレーションでは、操作ごとにすべてのタワーを繰り返しスキャンすることになり、$O(n^2)$最悪の場合、動作が遅すぎます。 

多くのタワーが同じような高さを共有している場合、微妙な問題が発生します。 次の異なる高さまで繰り返し切断するという素朴な貪欲な選択は、コストの制約を常に尊重するとは限りません。1 つのスライスにあまりにも多くの削減をグループ化すると、コストの制約を超える可能性があるからです。$k$一方、あまりにも積極的に分割すると、操作の数が増加します。 

小さな例でその難しさを説明します。 高さがあるとします。$[100, 99, 98]$そして$k = 3$。 コストを 98 に直接削減$(100-98) + (99-98) = 3$、これは有効です。 ただし、最初に 99 にカットしてから 98 にカットすることも有効ですが、より多くの操作が必要になります。 常に次の明確な高さにカットする不用意な戦略は、操作を不必要にカウントしすぎる可能性があります。 

重要な問題は、スライスの数を最小限に抑えながら、各スライスが「十分に安価」になるようにスライスの高さをどこに配置するかを決定することです。 

## アプローチ

 ブルートフォース戦略では、有効なスライスの考えられるすべてのシーケンスをシミュレートしようとします。 現在の高さのセットから、可能なすべての目標高さを試すことができます。$H$有効なスライスを生成し、そのコストを計算し、再帰的に続行します。 各スライスが可能なしきい値の数に等しい分岐係数を作成するため、これはすぐに指数関数的になります。 固有の高さに制限したとしても、各ステップではすべてのタワーにわたる計算コストが必要となり、$O(n^2)$パスごとに実行されるため、全体的な検索が不可能になります。 

重要な観察は、意味のあるスライスの高さの候補は、降順に並べ替えられたタワーの個別の高さだけであるということです。 存在しない中間の高さへの切断は常に次の既存のレベルへの切断によって支配され、将来の操作で追加の利益は得られないため、最適な戦略はこれらの値にのみ「着地」します。 

個別の高さを分類したら、逆に考えることができます。つまり、最上位レベルから下に向かって徐々に高さを減らしていきます。 ある高さレベルから次の低い高さレベルに移動するたびに、そのレベルより上にあるタワーの数に比例したコストが発生します。 

スライスを前方にシミュレートする代わりに、高さを高いものから低いものまで処理し、削減を貪欲にグループ化することができます。次のレベルに削減した場合に削除されるキューブの数を累積し、この累積コストが超過するたびに計算します。$k$、スライスを「閉じ」、新しいスライスを開始します。 

これにより、問題は、ソートされた一意の高さに関するセグメンテーションの問題に変わります。ここで、各セグメントは 1 つのスライスに対応し、セグメントのコストは、その範囲内のすべてのタワーが寄与する垂直降下の合計になります。

 | ブルートフォース | 指数関数 /$O(n^2)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、高さを周波数マップに圧縮して、それぞれの異なる高さに何本の塔が存在するかを知ることから始めます。 次に、これらの高さを降順に並べ替えます。 

1. すべての高さの頻度マップを作成します。これにより、各レベルに現在いくつの塔が存在するかがわかります。 これが必要なのは、コストが各ステップで影響を受けるタワーの数に依存するためです。 
2. 固有の高さを降順に並べ替えます。 スライスの決定は各しきい値をどれだけ質量が上回るかによって決まるため、上から下に処理します。 
3. 現在のレベルを超えて現在「アクティブ」になっているタワーの数を継続的にカウントします。 最初は、まだ何も切断されていないため、すべてのタワーがアクティブになっています。 
4. 現在のスライスのランニング累積コストを維持します。 高所から移動する場合$h_i$に$h_{i+1}$、アクティブなタワーごとに 1 滴の寄付が行われます。$h_i - h_{i+1}$, そこで追加します$(h_i - h_{i+1}) \times \text{active}$コストに。 
5. この費用を追加すると超過する場合$k$、現在のスライスを高さで完成させます$h_i$、答えをインクリメントし、コストアキュムレーターをリセットします。 また、スライス境界が配置されているため、このレベルから現在のセグメントを再評価します。 
6. スライスを完成させた後、アクティブなタワーを追跡しながら下方向に処理を続けます。新しい高さレベルに遭遇するたびに高さが増加します (下降するにつれてこれらのタワーがアクティブなセットに加わるため)。 
7. すべてのレベルを処理した後、未完了のスライスがある場合は、それを 1 つの最後の操作としてカウントします。 

再起動ステップの背後にある理由は、一度超過すると、$k$、現在の高さ削減のグループ化はコストが高すぎるため、最後の有効なカットは前の境界で発生する必要があります。 

### なぜ効果があるのか

 いつでも、現在のレベルを超えるすべてのタワーが均一にさらなる削減に寄与します。 これにより、2 つの連続する異なる高さの間を降下するコストが、アクティブなタワーの数に比例します。 コストは高さの間隔全体で加算され、各間隔内では独立しているため、問題は、各セグメントの合計が最大で以下になるようにソートされたシーケンスをセグメントに分割することになります。$k$。 セグメントが超過するたびに切断するという貪欲な選択$k$切断を遅らせても、将来の単位高さあたりのコストは削減されず、コストがさらに増加するだけであるため、最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    h = list(map(int, input().split()))
    
    freq = {}
    for x in h:
        freq[x] = freq.get(x, 0) + 1

    heights = sorted(freq.keys(), reverse=True)

    active = 0
    cost = 0
    ans = 0

    i = 0
    while i < len(heights):
        if active == 0:
            active = freq[heights[i]]
            i += 1
            continue

        if i < len(heights):
            dh = heights[i-1] - heights[i]
            add_cost = dh * active

            if cost + add_cost <= k:
                cost += add_cost
                active += freq[heights[i]]
                i += 1
            else:
                ans += 1
                cost = 0
                active = 0
        else:
            break

    if active > 0:
        ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、同じ高さの繰り返し処理を避けるために、周波数をカウントすることから始まります。 降順で並べ替えると、高さ空間が常に下に移動します。 

変数`active`そして`cost`現在のスライスの状態を表します。`active`現在のしきい値をまだ上回っているタワーの数を追跡し、`cost`現在のスライスで削除されたキューブの数を追跡します。 

重要な移行は計算です`dh * active`これは、アクティブなすべてのタワーが 2 つの隣接する高さレベル間を移動するときに均一に減少するという事実をエンコードしています。 

次の間隔を追加すると超過するたびに$k$、スライスを完成させて状態をリセットします。これは、最後の有効な高さの境界にカットを配置することに対応します。

 ## 特殊なケース

 すべてのタワーがすでに同じ高さである場合、重要なエッジ ケースが発生します。 その状況では、アルゴリズムは単一のアクティブなグループを初期化し、コストを決して蓄積しないため、正確に 1 つのスライスを生成します。これは、削減が必要ないため正しいですが、それでも最終操作をカウントします。 

もう一つの微妙なケースは次のような場合です。$k$は非常に小さいため、すべての高さの遷移が強制的に独自のスライスになります。 アルゴリズムはこれを処理します。`add_cost`を超える$k$、すぐにリセットされ、どのセグメントも制約に違反しないことが保証されます。
