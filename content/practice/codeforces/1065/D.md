 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$N \times N$すべてのセルに一意の番号が含まれるグリッド$1$に$N^2$。 これらの数字は、強制的な訪問順序を定義します。1 を含むセルから開始し、最終的に 2、3 を含むセルに到達し、次の順序で昇順に続行する必要があります。$N^2$。 

動きはチェスの駒を使用して行われますが、さらにひねりが加えられています。 いつでも、私たちはナイト、ビショップ、またはルークの中から選ばれた駒を持ったセルの上に立っているのです。 1 回の操作で、ルールに従ってそのピースを移動するか、移動せずに別のピースと置き換えます。 コストは操作の合計数です。 操作を最小限に抑えるあらゆる方法の中で、交換の数も最小限に抑えますが、それは最短経路距離が固定された後でのみです。 

したがって、実際の構造はグリッド自体に関するものではなく、番号が付けられたセル間の遷移に関するものです。 各数値はシーケンス内のノードを定義し、連続する数値の間で、移動ルールの切り替えを許可しながら、ある固定正方形から次の固定正方形に移動する最も安価な方法を計算する必要があります。 

なぜなら$N \le 10$の場合、グリッドには最大 100 個のセルが含まれるため、この強制パスには最大 100 個のノードが含まれます。 これは、ポジションとピースの種類に応じてかなり重い状態グラフを作成できることをすぐに示唆しています。$100 \times 3 = 300$州は小さいです。 

単純な間違いは、各部分に対して個別にグリッド上の最短パスのみが必要であると仮定し、各セグメントに最適な部分を個別に選択することです。 これは失敗します。セグメントを終了するのに最適な部分は、次のセグメントをどの部分で開始するかによって異なり、置き換えにはコストがかかるためです。 もう 1 つの微妙な失敗は、ステップを最小限に抑えた後でのみピースの変更が優先されることを無視して、最短パスを計算しようとすることです。 これにより、単純な重み付きエッジではなく、辞書編集的な最適化が強制されます。 

## アプローチ

 ブルートフォース解釈では、連続する数値間の各セグメントを別個の問題として扱います。セルからの最短パスを計算します。$i$セルへ$i+1$それぞれの部分について、結果をステッチしてみます。 しかし、これは、途中でピースを変更できること、そしてさらに重要なことに、どのピースで終了するかを追跡する必要があることを無視しています。 すべてのパスとすべての部分変更パターンを列挙しようとすると、可能な状態シーケンスの数は指数関数的に増加します。 

重要な観察は、これが拡張されたグラフ上の最短経路問題であるということです。 各状態は、現在のセル、現在のターゲット セル インデックス、および現在のピース タイプの 3 つの要素によって定義されます。 ただし、ターゲット インデックスを状態グラフに明示的に保存する必要はありません。 代わりに、ターゲットを順番に処理し、最短パスの計算を再利用します。 

番号からの各遷移について$k$に$k+1$、ノードが次のようなグラフ上で複数ソースの最短パスを実行します。$(cell, piece)$。 数値の開始セルに対応するすべての状態を初期化します。$k$、3 つの部分すべてで、それらの状態のみが前のセグメントの最終結果と一致します。 次に、数値の目的のセルに到達するための最短パスを計算します。$k+1$、距離と置換数の両方を辞書順に追跡します。 

各移動エッジには 1 ステップのコストがかかります。 ピースの交換にも 1 ステップのコストがかかりますが、二次的な目的 (交換数) に貢献します。 これにより、各状態がペアを格納する、辞書編集的に重み付けされた最短パスが得られます。$(steps, replacements)$、それに応じてトランジションが更新されます。 

グラフには最大 300 の状態があり、各セグメントには状態空間が小さい標準ダイクストラまたは BFS が含まれるため、全体の複雑さは容易に許容できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | セグメントごとの (セル、ピース) 状態に対する最適な DP |$O(N^2 \cdot 3 \cdot \log(N^2))$|$O(N^2 \cdot 3)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1 から 2 までの各数値の位置を事前に計算します。$N^2$。 これにより、現在および次のターゲット セルの定時間ルックアップが可能になります。 

番号からのセグメントごとに$k$に$k+1$、次の手順を実行します。 

1. 状態を次のように定義します。$(r, c, p)$、 どこ$(r, c)$ボードセルであり、$p$3つの作品のうちの1つです。 各駒には独自の動きが設定されているため、この状態では次にどのような動きが可能であるかが完全に把握されます。 
2. すべての状態の距離テーブルを初期化します。 最初のセグメントでは、番号 1 の位置から任意の部分を開始できるようにするため、3 つの開始状態すべてを distance に設定します。$(0, 0)$。 後のセグメントでは、前のセグメントの宛先から最良の終了状態のみを引き継ぎます。 
3. この状態空間に対して最短パス アルゴリズムを実行します。 州から$(r, c, p)$, 2種類のトランジションを行うことができます。 ピースを別のピースに切り替えることができます$p'$実費で$(1, 1)$、1 つの操作と 1 つの置換を表します。 ピースに応じて移動することもできます$p$、新しい細胞につながります$(r', c')$費用がかかる$(1, 0)$。 
4. 辞書編集的な比較を使用してエッジを緩和します。最初にステップを最小限に抑え、次に置換を最小限に抑えます。 これにより、同じ長さのパスの中で、ピースの変更が少なくなることが確実になります。 
5. このセグメントの宛先は数字を含むセルです$k+1$。 そのセルの 3 つの部分すべての中で最良の状態を記録し、それを次のセグメントの初期化として使用します。 
6. セグメント全体にわたる合計ステップと合計置換の両方を蓄積します。 

これが機能する理由は、すべての有効なトラバースが連続する番号間の独立したセグメントに分解され、各セグメント内で状態空間が移動とピースの切り替えに関するすべての決定を完全にキャプチャするためです。 遷移はマルコフ関数であるため、$(cell, piece)$、最良の到着州を超えて、以前の歴史を思い出す必要はありません。 辞書編集的な最短パスは、セグメント境界が固定されており避けられないため、セグメントごとの局所的な最適性がグローバルに構成されることを保証します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

# piece encoding: 0 knight, 1 bishop, 2 rook

N = int(input())
board = [list(map(int, input().split())) for _ in range(N)]

pos = [None] * (N * N + 1)
for i in range(N):
    for j in range(N):
        pos[board[i][j]] = (i, j)

knight_moves = [(2, 1), (2, -1), (-2, 1), (-2, -1),
                (1, 2), (1, -2), (-1, 2), (-1, -2)]

def bishop_moves(r, c):
    res = []
    for dr, dc in [(1,1),(1,-1),(-1,1),(-1,-1)]:
        nr, nc = r + dr, c + dc
        while 0 <= nr < N and 0 <= nc < N:
            res.append((nr, nc))
            nr += dr
            nc += dc
    return res

def rook_moves(r, c):
    res = []
    for dr, dc in [(1,0),(-1,0),(0,1),(0,-1)]:
        nr, nc = r + dr, c + dc
        while 0 <= nr < N and 0 <= nc < N:
            res.append((nr, nc))
            nr += dr
            nc += dc
    return res

moves = [None] * 3
moves[0] = lambda r, c: [(r+dr, c+dc) for dr, dc in knight_moves if 0 <= r+dr < N and 0 <= c+dc < N]
moves[1] = bishop_moves
moves[2] = rook_moves

INF = (10**18, 10**18)

def dijkstra(sr, sc):
    dist = [[[INF for _ in range(3)] for _ in range(N)] for _ in range(N)]
    pq = []

    for p in range(3):
        dist[sr][sc][p] = (0, 0)
        heapq.heappush(pq, (0, 0, sr, sc, p))

    while pq:
        d, rch, r, c, p = heapq.heappop(pq)
        if (d, rch) != dist[r][c][p]:
            continue

        # move
        for nr, nc in moves[p](r, c):
            nd = (d + 1, rch)
            if nd < dist[nr][nc][p]:
                dist[nr][nc][p] = nd
                heapq.heappush(pq, (nd[0], nd[1], nr, nc, p))

        # switch piece
        for np in range(3):
            if np != p:
                nd = (d + 1, rch + 1)
                if nd < dist[r][c][np]:
                    dist[r][c][np] = nd
                    heapq.heappush(pq, (nd[0], nd[1], r, c, np))

    return dist

start_r, start_c = pos[1]
current_dist = None

total_steps = 0
total_rep = 0

for target in range(2, N * N + 1):
    sr, sc = pos[target - 1]
    tr, tc = pos[target]

    dist = dijkstra(sr, sc)

    best = INF
    for p in range(3):
        best = min(best, dist[tr][tc][p])

    total_steps += best[0]
    total_rep += best[1]

print(total_steps, total_rep)
```コア構造は、各層がピースに対応する層状グリッド上で実行されるダイクストラです。 各状態遷移は、固定ルールに従って移動するか、レイヤーを切り替えます。 辞書編集上のペアにより、ステップ後の置換が最小限に抑えられます。 

微妙な点の 1 つは、ビショップとルークの手の生成が動的に拡張されることです。 以来$N \le 10$、州ごとに到達可能なすべての正方形を列挙するのは安価です。 もう 1 つの重要な詳細は、置換は二次的なものにすぎないため、距離を単一の重み付けされた値としてではなくペアとして保存することです。

 ## 特殊なケース

 エッジケースの 1 つは、現在の作品を継続するよりも作品を切り替えることが常に有益である場合です。 このような場合でも、各状態に現在のピースが明示的に含まれており、切り替えが標準エッジとして表されるため、アルゴリズムは引き続き両方のオプションを評価します。 辞書編集的な比較により、2 つのパスのステップ数が等しい場合でも、スイッチの少ない方が確実に選択されます。 

もう 1 つのエッジ ケースは、最短パスでセルを複数回再訪問する必要がある場合です。 状態はグローバルに訪問済みとしてマークされるのではなく、距離ペアごとにマークされるため、再訪問は自然に許可され、ダイクストラはサイクルを正しく処理します。 

最後の微妙なケースは、複数のピースが同じコストで同じセルに到達する場合です。 状態テーブルは 3 つの可能性をすべて個別に保持するため、将来のセグメントは最適性を失うことなく最も便利な開始部分を選択できます。
