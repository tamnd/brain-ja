 ## 解決策
 ## 問題の理解

 ツリーは、頂点のペア間の可能なすべてのルートを記述します。 ルートだけでは十分ではありません。そのルート上のすべての頂点は、独立してアクティブまたは非アクティブにできます。 値に必要な答え`k`はルートとアクティベーションの選択肢の数です。`k`頂点がアクティブになっています。 

有用な再定式化は、最初は個々のアクティベーションを無視することです。 を含むパス`len`頂点は多項式に寄与します`(1+x)^len`なぜなら、各頂点を個別に選択すると、1 つのアクティブな頂点に寄与するか、何も寄与しないかのいずれかになるからです。 全体の問題は、次の合計を求めることになります。`(1+x)^len`順序のない頂点のペアすべてにわたって。 

と`N`まで`100000`、すべてのパスを列挙することは不可能です。 木には約`N^2/2`頂点ペアは、最大入力に対してすでに約 50 億です。 すべてのペアを保存または処理するアプローチでは、制限時間内に収まりません。 線形に近い、または`N log N`方法。 

厄介なケースは、長さがゼロのパスや非常にバランスの悪いツリーです。 単一の頂点は有効なパスであるため、`(1+x)`、 ない`1`。 例えば：```
1
```答えは次のとおりです。```
1 1
```エッジのみをカウントするか、単一の頂点を無視するソリューションでは、この場合はゼロが出力されます。 

もう 1 つのよくある間違いは、パスを二重に数えることです。 例えば：```
2
1 2
```2 つのパスは、単一の頂点と両方の頂点を含むパスです。 多項式は次のとおりです。```
2(1+x)+(1+x)^2
```これは次のようになります:```
3 4 1
```有向ペアをカウントするとパスがカウントされます`1 -> 2`そして`2 -> 1`別々に考えて間違った答えを生み出します。 

## アプローチ

 直接的な解決策では、すべての開始頂点を反復し、DFS を実行し、そこから始まるすべてのパスの長さを記録できます。 これは正しいです。開始エンドポイントの制限が注意深く処理されていれば、順序付けされていないパスはすべて 1 回だけ検出されるからです。 ただし、`O(N^2)`ツリー内のパスが増えると、作業量は二次関数になります。 星型のツリーには、パスの数がすでに約 50 億本あります。 

重要な観察は、アクティベーションの選択肢はパスの長さのみに依存するということです。 パス上の実際の頂点を知る必要はありません。 必要なのは、可能なすべての長さのパスの数だけです。 

重心分解はまさにこの情報を効率的に提供します。 重心が削除されると、その重心を通過するすべてのパスは、重心で結合された 2 つの分岐で構成されます。 各ブランチの重心からノードまでの距離を収集できます。 1 つのブランチを以前に処理されたブランチと組み合わせると、分解における最高の重心が現在の重心であるすべてのパスがカウントされます。 

取得後`cnt[d]`、パスの数`d`エッジの場合、答えの多項式は次のようになります。```
sum(cnt[d] * (1+x)^(d+1))
```の力からの最終的な変換`(1+x)`通常の係数への変換は、多項式の 1 によるテイラー シフトです。 これは、NTT を使用すると 1 回の畳み込みで実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) | O(N) | 遅すぎる |
 | 最適 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを構築し、重心分解を実行します。 分解中に、現在のコンポーネントの重心を見つけて、削除されたことをマークします。 
2. 選択した重心について、残りのすべての子コンポーネントの重心からすべての頂点までの距離を収集します。 重心自体の距離はゼロです。 
3. 重心を通過するパスを数えます。 前の子コンポーネントからすでに認識されている距離を維持します。 離れたところにあるノード`a`現在のコンポーネントと遠くにあるノード内`b`前のコンポーネントでパスを作成します`a+b`エッジ。 これらの組み合わせを距離頻度配列に追加します。 
4. 子を処理する前に重心距離ゼロを挿入することにより、重心から現在のコンポーネント内のすべてのノードへのパスを追加します。 これは、1 つのエンドポイントが重心であるすべてのパスを考慮します。 
5. 重心を削除した後、残りのすべてのコンポーネントに重心分解を再帰的に適用します。 
6. 距離頻度配列を最終的な答えに変換します。 もし`cnt[d]`はパスの数です`d`エッジで多項式を作成します。```
F(t) = sum(cnt[d] * t^(d+1))
```必要な答えは、`F(1+x)`。 テイラー シフト公式と NTT を使用して計算します。`O(N log N)`時間。 

機能する理由: すべてのツリー パスには、パスがそのコンポーネントの重心によって分割される固有の重心分解レベルがあります。 カウント フェーズでは、そのレベルのパスのみがカウントされるため、パスが見逃されることはなく、パスが 2 回カウントされることもありません。 次のパスがあるため、多項式変換は正確です。`d+1`頂点が寄与する`(1+x)^(d+1)`アクティブな頂点を独立して選択することによって。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
G = 3

def modpow(a, b):
    r = 1
    while b:
        if b & 1:
            r = r * a % MOD
        a = a * a % MOD
        b >>= 1
    return r

def ntt(a, invert):
    n = len(a)
    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            a[i], a[j] = a[j], a[i]
    length = 2
    while length <= n:
        wlen = modpow(G, (MOD - 1) // length)
        if invert:
            wlen = modpow(wlen, MOD - 2)
        for i in range(0, n, length):
            w = 1
            half = length >> 1
            for j in range(i, i + half):
                u = a[j]
                v = a[j + half] * w % MOD
                a[j] = (u + v) % MOD
                a[j + half] = (u - v) % MOD
                w = w * wlen % MOD
        length <<= 1
    if invert:
        inv = modpow(n, MOD - 2)
        for i in range(n):
            a[i] = a[i] * inv % MOD

def convolution(a, b):
    if not a or not b:
        return []
    n = 1
    while n < len(a) + len(b) - 1:
        n <<= 1
    a = a + [0] * (n - len(a))
    b = b + [0] * (n - len(b))
    ntt(a, False)
    ntt(b, False)
    for i in range(n):
        a[i] = a[i] * b[i] % MOD
    ntt(a, True)
    return a[:len(a) + len(b) - 1]

def main():
    n = int(input())
    tree = [[] for _ in range(n)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        tree[a].append(b)
        tree[b].append(a)

    size = [0] * n
    dead = [False] * n
    cnt = [0] * n

    def dfs_size(v, p):
        size[v] = 1
        for u in tree[v]:
            if u != p and not dead[u]:
                size[v] += dfs_size(u, v)
        return size[v]

    def get_centroid(v, p, total):
        for u in tree[v]:
            if u != p and not dead[u] and size[u] > total // 2:
                return get_centroid(u, v, total)
        return v

    def collect(v, p, d, arr):
        arr.append(d)
        for u in tree[v]:
            if u != p and not dead[u]:
                collect(u, v, d + 1, arr)

    def decompose(v):
        total = dfs_size(v, -1)
        c = get_centroid(v, -1, total)
        dead[c] = True

        seen = [0]
        cnt[0] += 1

        for u in tree[c]:
            if not dead[u]:
                cur = []
                collect(u, c, 1, cur)
                for d in cur:
                    cnt[d] += 1
                    for x in seen:
                        cnt[d + x] += 1
                seen.extend(cur)

        for u in tree[c]:
            if not dead[u]:
                decompose(u)

    decompose(0)

    fact = [1] * (n + 2)
    for i in range(1, n + 2):
        fact[i] = fact[i - 1] * i % MOD
    invfact = [1] * (n + 2)
    invfact[-1] = modpow(fact[-1], MOD - 2)
    for i in range(n + 1, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    f = [0] * (n + 1)
    for d in range(n):
        f[d + 1] = cnt[d]

    a = [f[i] * fact[i] % MOD for i in range(n + 1)][::-1]
    b = invfact[:n + 1]
    conv = convolution(a, b)

    ans = [0] * (n + 1)
    for k in range(n + 1):
        ans[k] = conv[n - k] * invfact[k] % MOD

    print(*ans)

if __name__ == "__main__":
    main()
```重心部分では、まず組み合わせ問題を多項式問題から分離します。 配列`cnt`はパスの長さのみを保存します。これは、後で必要になる正確な情報です。 

重心のカウントには、以前の子コンポーネントですでに見つかった距離のリストが使用されます。 新しい子コンポーネントが処理されるとき、それをそのリストと組み合わせると、両側が異なる分岐にあるパスのみがカウントされます。 重心自体は、距離ゼロを挿入することによって個別に処理されます。 

テイラー シフト セクションは、多くの実装でインデックス付けの間違いが発生する箇所です。 多項式インデックスは頂点の数であり、エッジの数ではないため、`cnt[d]`度に配置されます`d+1`。 テイラー シフト式には、元のインデックスがターゲット インデックス以上である項が必要であるため、畳み込み前の反転が必要です。

 ## 特殊なケース

 単一ノード入力の場合:```
1
```重心が唯一のノードです。 距離配列には、長さ 0 のパスが 1 つ含まれています。 最終的な多項式には次の 1 つの因数があります。`(1+x)`、生産:```
1 1
```2 ノード ツリーの場合:```
2
1 2
```セントロイド処理では、長さ 0 のパスが 2 つと、長さ 1 のパスが 1 つカウントされます。 結果の多項式は次のようになります。```
2(1+x)+(1+x)^2
```これは次のようになります。```
3 4 1
```長いチェーンの場合、重心分解により、再帰の深さが元のツリーの高さに依存することがなくなります。 各重心は現在のコンポーネントの中央を削除するため、すべての頂点は対数的に多くの分解レベルにのみ参加します。
