 ## 解決策
 ## 問題の理解

 N×Nのグリッドがあります。 フラッシュは左上のセルから始まります。 1 から 2N-2 までのすべての距離値 d について、下または右のみに移動することを繰り返して到達できるすべてのセルを考慮します。このような移動はすべて、前のセルからのマンハッタン距離をちょうど d だけ増加させる必要があります。 d のすべての値にわたって各セルがマークされた回数を数えます。最終カウントが奇数であるセルの数が必要です。 

最初に注意すべきことは、N が 10^9 まで大きくなる可能性があるということです。 グリッドには最大 10^18 のセルが含まれるため、グリッド上のシミュレーションは不可能です。 1 行または 1 つの対角線を反復処理するだけでもコストがかかりすぎます。 解は座標の数学的性質のみに依存する必要があります。 

座標 (i, j) のセルは、値 i + j - 2 によってのみ影響を受けます。これは、許可されるすべての移動によって i + j がそのマンハッタン距離とまったく同じ量だけ増加するためです。 これにより、問題が 2 次元のプロセスから対角線上の値のカウントに変換されます。 

主なエッジ ケースは、非常に小さなグリッドと最初と最後の対角線から得られます。 N = 1 の場合、開始セルはカウントされないため、答えは 0 になります。入力 1 の場合、実行する移動がないため、出力は 0 になります。 開始セルを到達可能なセルとしてカウントする不注意な実装では、1 が返されます。 

N = 2 の場合、マークされたセルは (1,2) と (2,1) だけです。 対角値 i + j - 2 は両方のセルで 1 であり、1 には約数が 1 つあるため、出力は 2 になります。これにより、ゼロ以外の最小の対角線を誤って無視する解が捕捉されます。 

N が大きい場合、可能な最大の対角値は 2N-2 です。 N が 10 億になる可能性があるため、実装ではすべてのセルまたはすべての対角線に対する反復を回避する必要があります。 

## アプローチ

 直接的なアプローチでは、d のすべての値がシミュレートされます。 各 d について、現在到達可能なセルのセットを保持し、遷移を繰り返し適用できます。 これは定義に正確に従っているので正しいですが、グリッド サイズのせいでそれは不可能です。 最悪の場合は 10^18 個のセルが含まれるため、すべてのセルを 1 回タッチすることさえできません。 

重要な観察は、すべての動きが単調であるということです。 ゼロベースの座標 x = i - 1 および y = j - 1 を使用すると、距離 d を 1 回移動すると、x + y がちょうど d だけ増加します。 x + y = 0 から開始して、長さ d を数回移動した後、x + y が d の倍数であるセルにのみ到達できます。 

逆方向も同様です。 x + y = k * d の場合、必要な k * d の合計動作を k 個の動作に分割し、それぞれに合計 d のステップが含まれます。 必要な下方向と右方向のステップをこれらの動きに分散させて、そのような対角線上のすべてのセルに到達できるようにします。 

したがって、値 s = i + j - 2 を持つセルは、s の正の約数ごとに 1 回マークされます。 正の整数の約数は、整数が完全な平方である場合、奇数になります。 これにより、数え方の問題が残ります。インデックスが完全な正方形である対角線上にあるセルは何個あるでしょうか?

 | 最適 | O(sqrt(N)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 対角インデックスとして表示されるすべての完全二乗値を反復処理します。 可能な最大値は 2N-2 であるため、その制限までの正方形のみが必要です。 
2. このような正方形 s ごとに、i + j - 2 = s を満たすセルの数を数えます。 これらのセルは、グリッドの 1 つの対角線を形成します。 
3. これらすべての対角線のサイズを加算します。 これらの対角線には奇数のマークがあるため、合計が最終的な答えとなります。 

対角値 s の場合、ゼロ ベースの座標 x および y を使用すると、x + y = s (0 ≤ x、y < N) が必要です。有効な x 値の数は、この対角線と正方形グリッドの間の交点の長さです。 

なぜ効果があるのか​​:

セルは、その対角インデックスの約数ごとに 1 回カウントされます。 通常、約数は平方根の下と上に 1 つずつペアで表示されます。 約数に別のパートナーが存在しないのは、数値自体が正方形の場合だけです。 したがって、セルの対角インデックスが完全な正方形である場合、セルは正確に寄与します。 正方形のインデックス付き対角線をカウントすると、奇数のマーキング カウントを持つすべてのセルのみがカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    ans = 0
    limit = 2 * n - 2

    s = 1
    while s * s <= limit:
        d = s * s

        left = max(0, d - (n - 1))
        right = min(n - 1, d)

        if right >= left:
            ans += right - left + 1

        s += 1

    print(ans)

if __name__ == "__main__":
    solve()
```このループは、可能なすべての正方形の対角インデックスを生成します。 値`d`は、ゼロから始まる対角線 x + y を表します。 

変数`left`そして`right`x 座標の有効な範囲を記述します。 x が固定されている場合、y = d - x となるため、x は 0 と N-1 の間に留まり、y も同じ範囲内に保つ必要があります。 これら 2 つの範囲を交差させると、対角線の長さが求められます。 

コードでは Python 整数を使用しているため、答えが大きくなる可能性があってもオーバーフローの問題は発生しません。 境界の計算は包括的であるため、対角線のサイズは次のようになります。`right - left + 1`。 

## 実用的な例

 N = 4 の場合、最大の対角インデックスは 6 です。正方形のインデックスは 1 と 4 です。 

| 正方形の対角線 | 有効な x 値 | カウントされた細胞 |
 | --- | --- | --- |
 | 1 | 0から1 | 2 |
 | 4 | 1 ～ 3 | 3 |

 合計は 5 で、サンプルと一致します。 カウントされるセルは、正確に最初の対角線上の 2 つのセルと 4 番目の対角線上の 3 つのセルです。 

N = 5 の場合、最大の対角インデックスは 8 です。正方形のインデックスは 1 と 4 です。 

| 正方形の対角線 | 有効な x 値 | カウントされた細胞 |
 | --- | --- | --- |
 | 1 | 0から1 | 2 |
 | 4 | 0から4 | 5 |

 答えは 7 です。この例は、正方形の対角線が中心に近い場合、グリッドの幅全体に触れる可能性があることを示しています。

 ## 特殊なケース

 N = 1 の場合、正の対角インデックスはありません。 アルゴリズムはループに入らず、0 を返します。これは、最初のセルが距離によってマークされていないという事実と一致します。 

N = 2 の場合、利用可能な正方形の対角インデックスは 1 だけです。対角には 2 つのセルが含まれるため、どちらも 1 つの約数を持ち、両方とも答えに寄与します。 

N が非常に大きい場合、アルゴリズムはグリッドを構築しません。 最大 2N-2 の平方数のみを訪問するため、実行時間はセルの数ではなく入力の平方根に依存します。 

また、コンテスト形式の短い編集バージョンや、除数の議論を拡張したより証明に重点を置いたバージョンを提供することもできます。
