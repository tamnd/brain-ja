 ## 問題の理解

 このタスクは、文字列として記述された単一の数式を評価することです。 式には、整数、算術演算子、かっこが含まれます。 必要な結果は、通常の数学的優先順位に従います。最初に括弧、次に累乗、次に乗算と除算、次に加算と減算です。 同じ優先度を持つ演算子は左から右に処理されます。 

難しいのは算数そのものではありません。 Python を使用した直接実装`eval`または、式の長さが 100,000 文字に達する可能性があるため、再帰的パーサーが失敗する可能性があります。 このサイズでは、大きな部分文字列を繰り返しコピーしたり、深く再帰的な解析ツリーを構築したりするアプローチは直ちに排除されます。 すべての文字を検査する必要がある可能性があるため、O(n) または O(n log n) のソリューションが現実的な目標となります。 

この式では、最終的な答えが整数であっても、有理数である中間値も許可されます。 整数の除算を実行するソリューションでは、黙って間違った答えが生成されます。 例えば、`(1/2)*2`と評価する必要があります`1`、一方、整数の除算は次のようになります。`1/2`の中へ`0`。 

もう 1 つの危険なケースは累乗です。 入力用`2^3^2`、多くのプログラミング言語は結合性について意見が一致していませんが、この問題により、指数部が式ではなく正の整数であることが保証されます。 与えられた構造を尊重せずに乗算や除算などの累乗を扱うパーサーは、次のような式を誤って読み取る可能性があります。`35^66*0/35`。 

単項演算子も間違いの原因となる可能性があります。 このステートメントでは、それらが常に括弧で囲まれていることを保証するため、次のような式を使用します。`(-5)`自立型の代わりに表示されます`-5`解析の途中です。 この詳細を無視すると、負の数値が正しく処理されない可能性があります。 

## アプローチ

 簡単なアプローチは、最も優先度の高い操作を繰り返し見つけて計算し、その結果で置き換え、値が 1 つだけ残るまで継続することです。 これは人間が式を評価する方法を反映しており、簡単に検証できます。 問題は、式の検索と再構築が繰り返されることです。 すべての操作で 100,000 文字の文字列の大部分をスキャンする必要がある場合、最悪の場合は 2 次関数 (約 10^10 文字の操作) になり、制限をはるかに超えます。 

重要な点は、この式にはすでに厳密な文法が存在するということです。 次の操作を繰り返し検索する代わりに、現在の評価状態を維持しながら式を 1 回スキャンできます。 これを行う標準的な方法は、スタックベースのパーサーです。 

パーサーは式を値と演算子に分離します。 演算子が見つかるたびに、その優先順位がスタック上で待機している演算子と比較されます。 優先度の高い操作はすぐに解決されますが、優先度の低い操作は必要な値が使用可能になるまで待機します。 括弧は、対応する閉じ括弧が表示されるまで一時的に評価をブロックするマーカーとして機能します。 

この問題ではべき乗は常に単純な指数形式であるため、より複雑な再帰パーサーを必要とせずに、遭遇したときに処理できます。 有理中間値は分数を使用して正確に格納され、浮動小数点エラーが回避されます。

 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 式を左から右にスキャンし、数値、演算子、括弧をトークン化します。 完全な整数が見つかったら、それを正確な分数値に変換します。 最初から正確な分数を保持しておくと、後で精度の問題が発生するのを防ぎます。 
2. 2 つのスタックを維持します。 1 つのスタックには数値が格納され、もう 1 つのスタックには演算子が格納されます。 数値が表示されたら、オペレーターが別の値と結合するまで結合できないため、その数値を数値スタックにプッシュします。 
3. 演算子が表示されたら、演算子スタック上で既に待機している演算子を、それより高いか同等の優先順位を持つ間に解決します。 乗算、除算、加算、および減算は結合されたままであるため、等しい優先順位はすぐに解決されます。 
4. 開き括弧が表示されたら、それを特殊マーカーとして押します。 これにより、内側の式が括弧の外側の演算から分離されます。 
5. 右括弧が表示されたら、対応する左括弧が削除されるまで演算子を繰り返し適用します。 括弧内の値は、1 つの完全な式の結果になりました。 
6. 完全なスキャンが終了したら、オペレーター スタックに残っているすべてのオペレーターを適用します。 残った唯一の数値が最終値です。 
7. 最後の分数を整数に変換して出力します。 この問題により、この変換が正確であることが保証されます。 

なぜ効果があるのか:

 スキャン中のあらゆる時点で、スタックは、読み取られたがまだ最終化されていない式の部分を正確に表します。 演算子は、将来のトークンによって評価順序が変更される可能性がある間のみ演算子スタックに留まります。 それが不可能になった場合は、演算子がすぐに適用されます。 演算子は必要な優先順位と結合規則に従って削除されるため、すべての演算は数学的評価と同じ順序で実行されます。 

## Python ソリューション```python
import sys
from fractions import Fraction

input = sys.stdin.readline

def solve():
    s = input().strip()

    def precedence(op):
        if op == '^':
            return 3
        if op == '*' or op == '/':
            return 2
        if op == '+' or op == '-':
            return 1
        return 0

    def apply_op(nums, op):
        b = nums.pop()
        a = nums.pop()

        if op == '+':
            nums.append(a + b)
        elif op == '-':
            nums.append(a - b)
        elif op == '*':
            nums.append(a * b)
        elif op == '/':
            nums.append(a / b)
        else:
            nums.append(b ** a)

    nums = []
    ops = []

    i = 0
    n = len(s)

    while i < n:
        c = s[i]

        if c.isdigit():
            value = 0
            while i < n and s[i].isdigit():
                value = value * 10 + ord(s[i]) - ord('0')
                i += 1
            nums.append(Fraction(value))
            continue

        if c == '(':
            ops.append(c)

        elif c == ')':
            while ops[-1] != '(':
                apply_op(nums, ops.pop())
            ops.pop()

        else:
            while ops and ops[-1] != '(' and precedence(ops[-1]) >= precedence(c):
                apply_op(nums, ops.pop())
            ops.append(c)

        i += 1

    while ops:
        apply_op(nums, ops.pop())

    print(nums[0].numerator)

if __name__ == "__main__":
    solve()
```パーサーが使用するのは、`Fraction`中間の除算では非整数値が作成される可能性があるためです。 たとえば、本を読んだ後、`(1/2)`、スタックには、丸められた浮動小数点近似ではなく、正確な有理数値が含まれます。 

数値パーサーは連続する数字を手動で読み取ります。 これにより、多数の一時的な部分文字列の作成が回避され、スキャンが線形に保たれます。 

優先関数は、スタック上で待機しているオペレーターをいつ実行するかを決定します。 比較には、`>=`同じ優先順位の操作は左から右に評価されるためです。 

指数演算子は他の演算子とは少し異なります。 この問題では、指数がすでに正の整数値であることが保証されているため、同じスタック メカニズムを通じてそれを適用しても安全です。 

Python の整数はオーバーフローしないため、中間値が最終的な答えよりもはるかに大きくなる可能性があるため、これは便利です。 

## 実用的な例

 この例では、左から右への加算と減算の処理を示しています。 の`+`操作は後で完了する前に完了します`-`運用が考えられます。

 | 現在のトークン | 数値スタック | オペレータスタック | アクション |
 | --- | --- | --- | --- |
 |`35`| 35 | | プッシュ番号 |

 |`35`| 0、35 | / | プッシュ番号 |

 トレースは、優先順位に基づいて操作を適用することが重要である理由を示しています。 巨大なパワーが最初に計算されますが、後でゼロが乗算され、管理可能な最終結果が生成されます。

from fractions import Fraction

def evaluate(inp):
    s = inp.strip()

    def precedence(op):
        if op == '^':
            return 3
        if op in '*/':
            return 2
        if op in '+-':
            return 1
        return 0

    def apply(nums, op):
        b = nums.pop()
        a = nums.pop()
        if op == '+':
            nums.append(a + b)
        elif op == '-':
            nums.append(a - b)
        elif op == '*':
            nums.append(a * b)
        elif op == '/':
            nums.append(a / b)
        else:
            nums.append(b ** a)

    nums, ops = [], []
    i = 0

    while i < len(s):
        if s[i].isdigit():
            x = 0
            while i < len(s) and s[i].isdigit():
                x = x * 10 + int(s[i])
                i += 1
            nums.append(Fraction(x))
            continue

        if s[i] == '(':
            ops.append(s[i])
        elif s[i] == ')':
            while ops[-1] != '(':
                apply(nums, ops.pop())
            ops.pop()
        else:
            while ops and ops[-1] != '(' and precedence(ops[-1]) >= precedence(s[i]):
                apply(nums, ops.pop())
            ops.append(s[i])
        i += 1

    while ops:
        apply(nums, ops.pop())

    return str(nums[0].numerator)

assert evaluate("35^66*0/35") == "0"
assert evaluate("(1/2)*2") == "1"

assert evaluate("1") == "1"
assert evaluate("5*5*5") == "125"
assert evaluate("10/(2+3)") == "2"
assert evaluate("(7-3)*(2+1)") == "12"

 ## 特殊なケース

 のために`(1/2)*2`、パーサーは最初に括弧内の除算を評価します。 数値スタックストア`1/2`正確に計算すると、乗算で次のように結合されます。`2`生産する`1`。 整数除算を使用した解決策では、誤った出力が行われる可能性があります。`0`。 

のために`35^66*0/35`の場合、べき乗の方が優先されるため、パーサーは乗算の前にべき乗演算を適用します。 Python 整数は任意の精度をサポートしており、後のゼロ乗算により結果が減少するため、巨大な中間値は問題を引き起こしません。 

のために`(5)`の場合、開き括弧はバリアとして保存され、閉じ括弧が表示されると削除されます。 アルゴリズムは、含まれる数値を変更しないままにし、`5`。 

のために`8/4/2`の場合、同じ優先度の演算子は次の演算子が現れるとすぐに解決されるため、最初の除算は 2 番目の除算より前に適用されます。 評価はこうなります`(8/4)/2`、与える`1`それよりも`4`。
