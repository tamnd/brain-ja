 ## 解決策
 ## 問題の理解

 博物館を表す接続された無向グラフがあります。 各頂点はギャラリーであり、値を持っています。 訪問者は選択したギャラリーから開始し、廊下に沿ってのみ移動できます。 チケットの価格は、散策中に訪れたすべてのギャラリーの中で最高額です。 

クエリごとに`(X, K)`、訪問者がギャラリーから始められるように、可能な限り最小のチケット価格が必要です。`X`少なくとも到達するために`K`さまざまなギャラリー。 ギャラリーに複数回アクセスしてもカウントは増加しません。 

重要な観察事項は、最大許容価格が固定されている場合です。`T`、訪問者は、最大でも次の値を持つギャラリーのみを使用できます。`T`。 クエリに対する答えは最小です`T`の連結成分`X`この制限されたグラフには少なくともサイズがあります`K`。 

グラフには最大で`100000`ギャラリーと`200000`廊下。 クエリごとにグラフを個別に調査するソリューションは、クエリごとに何十万ものエッジに触れる可能性があるため、不可能です。`100000`クエリ、周囲に到達`10^10`操作。 対数係数のみを使用して、線形時間に近い前処理が必要です。 

見落としやすいケースがいくつかあります。 開始ギャラリー自体が必要な唯一のギャラリーである場合、答えはそれ自体の値になります。 例えば：```

7

1 1
```答えは次のとおりです。```

```エッジだけをチェックして開始ギャラリーを忘れるソリューションは、ここでは失敗します。 

価値観が等しいことも重要です。 考慮する：```

5 5 5

2 1
```答えは次のとおりです。```
5
5
5
```すべてのギャラリーがまとめてお買い得に利用可能になります`5`。 等しい値を別々の増加レベルとして扱うと、誤った中間状態が作成される可能性があります。 

最後の厄介なケースは、価値の低いギャラリーが高価なギャラリーに囲まれている場合です。```

```価値のあるギャラリー`1`グラフ全体が安くなるわけではありません。 しきい値は、そのしきい値以下で実際に到達可能なギャラリーの中での最大値によって決定されます。 

## アプローチ

 直接的な解決策は、各クエリに個別に答えることになります。 答えの値をバイナリ検索して、チェックごとに DFS または BFS を実行できます。`X`現在の制限を超えるギャラリーは無視します。 これは正解です。訪問者は、許可されたギャラリーの接続されたコンポーネントを正確に使用できるからです。 

ただし、1 つのクエリでグラフ全体を数回スキャンする必要がある場合があります。 と`Q = 100000`、クエリごとに単一のグラフ走査でも、次のように実行できます。`3 * 10^10`最悪の場合はエッジチェックを行います。 強引なアプローチは限界をはるかに超えています。 

便利な構造は、すべてのクエリが同じ種類の質問をするということです。許容値を徐々に増やすと、コンポーネントはどのくらいの大きさになりますか? 各クエリを個別に検索する代わりに、考えられるすべての回答をまとめて処理できます。 

個別のギャラリー値を並べ替えます。 バイナリ検索の反復中に、各クエリはこれらの値のいずれかを推測します。 推定値を昇順に処理します。 値を上に移動しながら、現在許可されている値を持つすべてのギャラリーをアクティブ化し、素の集合結合構造を使用してすでにアクティブな隣接ギャラリーとマージします。 その時点で、DSU コンポーネントのサイズは、そのしきい値を使用したクエリで到達可能なギャラリーの数と正確に一致します。 

並列二分探索により、すべてのクエリで同じ一連の DSU 計算を共有できます。 各反復で各クエリの残りの検索範囲が半分になるため、約`log2(100000)`すべての答えは決まっています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(Q(N+M)) | O(N) | 遅すぎる |
 | 並列二分探索 + DSU | O((N+M+Q) log N) | O(N+M+Q) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのギャラリー値を個別の値のソート済みリストに圧縮します。 考えられる各回答は、このリストの 1 つのインデックスに対応します。 
2. すべてのクエリについて、圧縮された値に対してバイナリ検索間隔を維持します。 最初は、考えられるすべての答えが含まれています。 
3. 各二分探索ラウンドで、現在の中間点に従ってすべてのクエリをバケットに配置します。 同じバケット内のクエリでは、特定の値のしきい値が十分であるかどうかが尋ねられます。 
4. DSU をリセットし、ギャラリー値を昇順にアクティブにします。 ギャラリーがアクティブになると、そのギャラリーをすべてのアクティブな隣接ギャラリーとマージします。 DSU コンポーネントのサイズは、アクティブなギャラリーのみを使用して訪問できるギャラリーの数を表します。 
5. バケットの値インデックスに到達したら、そこに保存されている各クエリを確認します。 開始ギャラリーを含むコンポーネントのサイズが少なくとも`K`、推定値は十分に大きいため、クエリの上限を下に移動します。 それ以外の場合は、下限を上に移動します。 
6. すべてのクエリ間隔に 1 つの値が含まれるまで繰り返します。 この値は、可能な最低チケット価格です。 

機能する理由: 二分探索ラウンドごとに、DSU は、値が現在処理されているしきい値を超えないギャラリーのみを保持することによって取得された正確なグラフを表します。 したがって、開始ギャラリーのコンポーネント サイズは、そのチケット価格で到達可能なギャラリーの最大数となります。 二分探索では要件を満たす最小のしきい値が維持されるため、最終的な値が最適な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    values = list(map(int, input().split()))

    graph = [[] for _ in range(n)]
    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        graph[a].append(b)
        graph[b].append(a)

    q = int(input())
    queries = []
    for _ in range(q):
        x, k = map(int, input().split())
        queries.append((x - 1, k))

    vals = sorted(set(values))
    pos = {v: i for i, v in enumerate(vals)}
    groups = [[] for _ in vals]

    queries_by_mid = [[] for _ in vals]
    lo = [0] * q
    hi = [len(vals) - 1] * q
    ans = [0] * q

    active = [False] * n

    while True:
        changed = False
        queries_by_mid = [[] for _ in vals]

        for i in range(q):
            if lo[i] <= hi[i]:
                changed = True
                mid = (lo[i] + hi[i]) // 2
                queries_by_mid[mid].append(i)

        if not changed:
            break

        parent = list(range(n))
        size = [1] * n

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def union(a, b):
            ra = find(a)
            rb = find(b)
            if ra == rb:
                return
            if size[ra] < size[rb]:
                ra, rb = rb, ra
            parent[rb] = ra
            size[ra] += size[rb]

        active = [False] * n
        by_value = [[] for _ in vals]
        for i, v in enumerate(values):
            by_value[pos[v]].append(i)

        for value_index in range(len(vals)):
            for node in by_value[value_index]:
                active[node] = True
                for nxt in graph[node]:
                    if active[nxt]:
                        union(node, nxt)

            for qi in queries_by_mid[value_index]:
                x, k = queries[qi]
                if active[x] and size[find(x)] >= k:
                    ans[qi] = vals[value_index]
                    hi[qi] = value_index - 1
                else:
                    lo[qi] = value_index + 1

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```この実装では、クエリを現在の中間点ごとに保存します。 これにより、クエリごとに個別の検索を再構築する必要がなくなり、1 つの DSU スイープですべてのクエリに同じ推定しきい値で応答できるようになります。 

DSU は並列二分探索ラウンドごとに再作成されます。これは、各ラウンドでしきい値を介して新たにスイープを増加させる必要があるためです。 ギャラリーは、その値に達したときにアクティブとしてマークされ、しきい値の定義に一致する他のアクティブなギャラリーとの結合のみが発生します。 

の`find`関数はパス圧縮を使用し、`union`コンポーネント サイズを使用し、すべての DSU 動作をほぼ一定の時間を保ちます。 Python の整数には制限がないため、大きなギャラリー値を特別に処理する必要はありません。 

## 実用的な例

 小さなグラフの場合:```
3 2
2 5 7
1 2
2 3
```クエリ処理は次のようになります。 

| しきい値 | アクティブなギャラリー | 1 の成分 | クエリ (1,3) |
 | --- | --- | --- | --- |
 | 2 | {1} | サイズ1 | 小さすぎる |
 | 5 | {1,2} | サイズ2 | 小さすぎる |
 | 7 | {1,2,3} | サイズ3 | 答え 7 |

 DSU サイズは、新しい値が手頃な価格になると正確に変更されます。 

のために：```
4 3
1 10 10 10
1 2
1 3
1 4
```そしてクエリ`(1,4)`:

 | しきい値 | アクティブなギャラリー | 1 の成分 | 結果 |
 | --- | --- | --- | --- |
 | 1 | {1} | 1 | 失敗 |
 | 10 | {1,2,3,4} | 4 | 成功 |

 これは、答えが利用可能な最小値ではなく、十分なギャラリーを接続するために必要な最大値に基づいている理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((N + M + Q) log N) | 各二分探索ラウンドでは 1 つの DSU スイープが実行され、各クエリが 1 回チェックされます。 
| スペース | O(N + M + Q) | グラフ、DSU 配列、およびクエリを保存します。 

ラウンド数は多くても17程度です。`100000`異なる価値観。 合計作業量は、指定された制限に対して十分小さいです。

 ## 特殊なケース

 単一ギャラリーの場合、DSU は値が処理されると 1 つのアクティブなギャラリーから開始します。 コンポーネントのサイズは 1 であるため、1 つのギャラリーを要求するクエリはそのしきい値をすぐに受け入れます。 

値が等しい場合、その値を持つすべてのギャラリーが同じスイープ位置でアクティブになります。 DSU は、それらがすべて追加された後でのみ応答するため、人為的な中間しきい値は存在しません。 

安価なセンターの例では、センターのみをアクティブ化すると、サイズ 1 のコンポーネントが作成されます。 他のギャラリーは、より大きな値が処理される場合にのみ参加するため、美術館全体を必要とするクエリはより大きな値を正しく返します。
