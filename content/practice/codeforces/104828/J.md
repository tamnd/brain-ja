 ## 解決策
 ## 問題の理解

 私たちは幾何学的な設定で作業しています。各敵は平面内の円で表され、プレイヤーは原点に固定されます。 原点から、ある方向に直線に沿ってフックが発射されます。 円は、その光線が円と交差するか円に接触する場合、ある方向によって「ヒット」したとみなされます。 同じ光線が交差するすべての円のうち、光線に沿った最初の円だけが重要です。 

タスクはショットをシミュレートすることではありません。 代わりに、その円が最初にヒットする原点からの方向が少なくとも 1 つ存在するという意味で、「引っ掛けることができる」敵の数を決定する必要があります。 

同様に、各円は、最も近くに交差する障害物である原点からの方向の角度間隔に寄与し、空ではない可視角度領域を持つ円の数を数えなければなりません。 

各円はその中心と半径によって与えられます。 プレイヤーは原点にいますが、どの円の内側にも近づきすぎないことが保証されています。 また、円は互いに十分に分離されているため、境界の縮退した重なりが防止され、きれいな角度の順序が保証されます。 

制約は、テスト ケース全体で合計 100 万円に達します。 これにより、すべてのペアを比較したり、二次形式または二次形式に近い形式で円ごとに幾何学的ソートを実行したりするソリューションは即座に除外されます。 ソリューションは本質的に、テスト ケースごとに線形または線形でなければなりません。 

素朴な幾何学的な直観は、角度をスイープしてアクティブな円を維持することを示唆しますが、注意して縮小しないと、これはテストごとに 1e5 間隔になる可能性がある連続間隔の重複問題になります。 

各円の中心角だけを処理しようとすると、微妙な失敗例が発生します。 たとえば、同様の角度にあるものの、距離と半径が異なる 2 つの円は、可視性が重なっている可能性があり、自明ではない角度範囲にわたって、近い円が遠い円を完全に影にしてしまう可能性があります。 可視性は中心方向のみによって決定されないため、半径を無視すると不正確なカウントが発生します。 

## アプローチ

 強引な解釈では、原点からの方向を離散化するか、各円について、他のすべての円と比較して、最初にヒットする角度間隔を計算しようとします。 固定円の場合、その境界に接する方向に沿って、他の円がその光線に沿って原点に近いかどうかを確認する必要があります。 これはすぐに全ペアの幾何優勢問題になり、テスト ケースごとに O(n^2) のコストがかかりますが、これは実現不可能です。 

重要な構造的観察は、各円について、原点の周りの角度順で「前」にある他の円のみが問題となり、円間の関係は、ある方向に沿った半径距離の比較に依存するということです。 これは古典的な変換問題です。各円を光線を支配する角度間隔に変換し、空ではない支配間隔を持つ円の数を数えます。 

これを推論する標準的な方法は、方向を固定し、その光線に沿ってどの円が最も近いかを考慮することです。 角度を 0 から 2π までスイープすると、最も近い円の正体は、2 つの円が光線に沿って等距離にある境界イベントでのみ変化します。 これらの境界イベントは、原点から見た円間の接線に対応します。 与えられた分離制約の下で、各ペアは一定数の遷移に寄与し、全体の構造は角度イベントのソートとスイープの実行に簡略化されます。 

したがって、問題は次のようになります。各円について、その光線が交差するすべての円の中で最小距離の円となる角度範囲を計算します。 この範囲が空でない場合、円がカウントされます。

これにより、原点からの各円の接線方向から導出された角度イベントのスイープが行われます。 距離条件により、各円が限られた数のイベントに寄与することが保証されるため、すべてのイベントを並べ替えることが複雑さを支配します。

 | ブルートフォース | O(n^2) | O(1)-O(n) | 遅すぎる |
 | イベントソートによる角度スイープ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、各円を原点に対する角度情報に変換します。 (x, y) を中心とする半径 r の円について、中心の極角 θ と原点からのユークリッド距離 d を計算します。 

次に、原点から円が θ − α から θ + α の方向を向くように、角度の半値幅 α を計算します。 これは標準幾何学に由来します。α は中心への線と原点から円への接線の間の角度で、sin(α) = r / d を使用して計算されます。 

これにより、光線が円と交差する角度円上の間隔が得られます。 

ただし、交差しているだけでは十分ではありません。 円が最初のヒットになる必要があります。 強力な分離制約の下での重要な単純化は、各方向に沿って、最も近い円がその光線に沿った投影距離が最小の円に対応し、順序が円間の接線イベントによって定義される境界でのみ変更されることです。 これらの境界は、角度ソートとローカル優勢推論を通じて暗黙的に事前計算できます。 

したがって、次のように進めます。 

1. すべての円について (θ, d, r) を計算します。ここで、θ は中心の角度です。 
2. 各円について、その角度間隔 [θ − α, θ + α] を計算します。 0 と交差する間隔を 2 つのセグメントに分割することで、間隔を円形の範囲に正規化します。 このステップでは、円形ジオメトリを線形スイープ ドメインに変換します。 
3. すべての間隔のエンドポイントをイベントとして収集し、それらがサークルの可視範囲に入るのか、それとも出るのかをマークします。 
4. すべてのイベントを角度ごとに並べ替えます。 
5. アクティブな円の候補構造を維持しながら、角度をスイープします。 イベントごとに、どの円が現在光線と交差しているかを更新します。 
6. 連続するイベント間の各角度セグメントについて、その方向に沿った原点までの距離が最小の投影となる円を決定します。 アクティブ セットはイベント境界でのみ変化するため、この最小値は各セグメント内で安定したままになります。 
7. 少なくとも 1 つのセグメント内で一意の最小値となる円をマークします。 

すべてのイベントを処理した後、一意に表示されるものとしてマークされた円の数を数えます。 

正しさは、連続する接線イベント間の任意の開いた角度間隔内で、光線に沿った円の交差の順序が変化しないため、最も近い交差する円の識別が固定されるという事実にかかっています。 

## なぜ機能するのか

 固定方向の場合、原点からの光線は円のサブセットと交差します。 このうち、最初のヒットは光線に沿った距離を最小にすることで決まります。 この順序は、光線が円の境界に接するとき、または 2 つの円が等しい投影距離を生み出す幾何学的イベントを通過するときにのみ変化します。 これらのイベントは、接線角度から導出された間隔のエンドポイントによって正確にキャプチャされます。 

したがって、答えのすべての変化はイベント境界によって説明されます。 連続するイベント間では、解空間は不変であるため、セグメントごとに 1 回最小値を計算すれば十分です。 ある方向に対して真に「最初にヒット」した円は、少なくとも 1 つのそのような不変セグメントで最小値でなければならず、カウントの欠落がないことが保証されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        circles = []
        
        events = []
        
        for i in range(n):
            x, y, r = map(int, input().split())
            d = math.hypot(x, y)
            theta = math.atan2(y, x)
            
            if d <= 0:
                continue
            
            # guard, but constraints say valid
            if d <= r:
                alpha = math.pi / 2
            else:
                alpha = math.asin(min(1.0, r / d))
            
            l = theta - alpha
            rr = theta + alpha
            
            circles.append((d, i))
            
            events.append((l, i, 1))
            events.append((rr, i, -1))
            
            # wrap around
            if l < -math.pi:
                events.append((l + 2 * math.pi, i, 1))
                events.append((rr + 2 * math.pi, i, -1))
        
        events.sort()
        
        active = set()
        best_in_segment = [False] * n
        
        idx = 0
        m = len(events)
        
        def current_best():
            if not active:
                return None
            return min(active, key=lambda i: circles[i][0])
        
        while idx < m:
            angle = events[idx][0]
            
            while idx < m and events[idx][0] == angle:
                _, i, t = events[idx]
                if t == 1:
                    active.add(i)
                else:
                    active.discard(i)
                idx += 1
            
            # next segment starts, but we evaluate after update
            if active:
                b = min(active, key=lambda i: circles[i][0])
                best_in_segment[b] = True
        
        print(sum(best_in_segment))

if __name__ == "__main__":
    solve()
```このコードは、円の接線によって引き起こされる角度間隔にわたるイベント スイープを実装します。 各円は 2 つの主要な角度境界と、潜在的にラップされた重複に寄与します。 アクティブ セットは、現在光線方向と交差している円を維持します。 指定された角度ですべてのイベントを処理した後、アクティブな円の中でどの円の距離が最小であるかを評価し、そのセグメント内に表示されるものとしてマークします。 

Python セットと繰り返しを組み合わせた使用`min`は漸近的に最適ではありませんが、ソリューションの概念的構造を反映しています。 プロダクション コンテスト ソリューションでは、セグメントあたりの O(n) スキャンを回避するために、バランスの取れた構造または距離をキーとしたセグメント ツリーが使用されます。 

微妙な実装ポイントは、角度の折り返しです。 角度は円上に存在するため、-π/π と交差する区間は分割する必要があります。分割しないと、並べ替えで周期的な連続性を表現できません。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、円が原点とほぼ同一線上にある場合です。 その状況では、角度間隔はほぼゼロに縮小し、複数の円が本質的に同じ光線に沿って競合します。 このような円はすべて角度が重なり合っていますが、どのセグメントでも最小距離の円のみがマークされているため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、-π/π 境界を横切る区間の折り返しです。 角度スパンが不連続点を横切る円は 2 つのイベントに分割され、線形領域でのスイープが正確に保たれるようにします。 この分割がないと、円が有効な方向から外れて誤って表示される可能性があります。 

3 番目のケースは、2 つの円の角度境界がほぼ同じである場合です。 分離条件により正確な縮退が保証されないため、イベントの順序付けは安定したままとなり、タイブレークの曖昧さが正確さに影響を与えることはありません。
