 ## 解決策
 ## 問題の理解

 私たちには数枚のカードの山が与えられます。 各スタックにはいくつかの個別の整数が含まれており、グローバルにすべてのカード値が順列を形成するため、すべての値がすべてのスタックで 1 回だけ出現します。 

ゲームは複数のラウンドで構成されます。 1ラウンドで正確に選択しなければなりません`k`インデックスが厳密に増加しているさまざまなスタック。 選択した各スタックから、未使用のカードを 1 枚だけ選びます。 ラウンド内で、選択された`k`カードの値は、スタック インデックスの順序でリストされる場合、厳密に増加する必要があります。 

連続するラウンドの間に、ゲームはグローバル制約を課します。次のラウンドで選択されるすべての値は、前のラウンドで選択されるすべての値より大きくなければなりません。 したがって、選択したすべての値を時間順に書き込むと、シーケンスは厳密に増加し、各ラウンドはサイズの連続したブロックになります。`k`。 

別の有効なラウンドを形成できなくなるとすぐにプロセスが停止します。タスクは、完全なラウンドを何回完了できるかを計算することです。 

制約は大きく、カードの総数は最大約 100 万枚、スタックは最大 20 万枚です。 すべてのスタックを単純にスキャンしてラウンドの構築を繰り返し試行するソリューションでは、単一のラウンドでも線形の時間がかかる可能性があり、最悪の場合は最大数十万ラウンドが発生する可能性があるため、遅すぎます。 

重要な構造上のエッジケースは、スタックのインデックスと値が「ずれている」場合です。 たとえば、スタックの順序を考慮せずに、使用可能な最小値を貪欲に選択するとします。 のセットを選ぶかもしれません`k`スタック インデックスが値と同じ順序で増加していない値は、有効な組み合わせが存在する場合でもラウンドを無効にします。 

スタック内の値が固定順序で取得されない場合、別の障害モードが発生します。 スタックから常に最小の残りの値を取得しなければならないという素朴な仮定は間違っています。他のスタックでの将来の実現可能性を維持するために、小さな値をスキップすることが必要な場合があるからです。 

## アプローチ

 ブルートフォースの解釈は簡単です。ゲームをシミュレートします。 各ラウンドであらゆる選択方法を検討する`k`スタックした場合、ラウンド内の順序制約と全体的な増加制約の両方を満たすカードをそれぞれ 1 枚ずつ選んでみて、ゲームを継続できる最善の選択肢を選択します。 これはすぐに組み合わせになります。 単一のラウンドを選択する場合でも、制約の下でスタックの有効な増加サブシーケンスを選択するようなことが必要となり、選択肢は指数関数的に多くなります。 

値を昇順にスキャンしてスタックの増加シーケンスを貪欲に構築するなど、単一ラウンドの戦略を修正したとしても、スタック全体で動的な可用性を維持する必要があります。 各カードは一度使用されるため、構造を繰り返し更新し、最大で`n + m`これは簡単にできる操作です`O(mn)`最悪の場合。 

重要な観察は、グローバル制約により、値の昇順で順列を消費しているかのようにプロセス全体が動作することを強制していることです。 一度値が使用されると、それより小さい値は今後のラウンドで再び現れることはありません。 したがって、現時点で意味のある唯一の状態は、各スタックでどの値が未使用のままであり、その中で使用可能な最小の値はどれであるかということです。これは、将来の選択では値の増加のみが考慮されるためです。 

これにより、問題は、グループを繰り返し抽出することになります。`k`スタック全体の「利用可能な次の候補」の現在のセットからの要素。グループ内ではインデックスが値の順序と一致する必要があるという互換性制約があります。 

重要な洞察は、単一ラウンド内では、値が厳密にグローバルに増加しているため、値を昇順にスキャンし、スタック インデックスがシーケンスの増加を維持するものを選択することで、貪欲にラウンドを構築できるということです。 これにより、各ラウンドは現在アクティブな候補に対する最長増加部分列問題になりますが、長さは切り詰められます。`k`。 

ラウンド全体で効率を維持するために、スタックごとに次の未使用の値を常に維持し、貪欲な選択をサポートするために値で順序付けされたグローバル構造を使用します。

 ## アルゴリズムのチュートリアル

 各スタックについて、未使用の最小値へのポインタを維持します。 スタック内の値は順序を除いて無関係であるため、値が取得されるときは常にこのポインタを進めます。 

1. 各スタックについて、現在の最小の未使用カードを格納する構造を初期化します。 これらは、値をキーとした候補のグローバル プールを形成します。 
2. 新しいラウンドを形成することは可能ですが、私たちはラウンドを構築しようとします。 
3. ラウンドを構築するために、値の昇順に候補をスキャンします。 変数を維持します`last_index = 0`。 
4. 候補者に出会ったとき`(value v, stack i)`、次の場合にのみ現在のラウンドに持ち込むことができます。`i > last_index`。 取れたら更新します`last_index = i`そして、このカードを使用済みとしてマークし、そのスタックのポインタを次の未使用の値に進めます。 
5. 収集するまでこのプロセスを継続します。`k`カード。 無事に回収できたら`k`カードを使ってラウンドを完了すると、答えが 1 つ増えます。 そうしないと、それ以上のフルラウンドは不可能となり、停止します。 
6. 残りのすべての未使用の値は、ポインタによってすでに保持されている新しい「次の候補」を超える将来のラウンドには無関係です。 

微妙な点は、ラウンド内での貪欲な選択がなぜ有効なのかということです。 値は常に昇順で処理されるため、インデックスが小さすぎるためにスキップされた選択は、後でインデックスの増加制約に違反することなく、より適切な小さい値に置き換えることはできません。 有効なセットの場合、`k`スタックが存在する場合、貪欲スキャンは互換性のある増加シーケンスを見つけます。これは、常に最初に利用可能な最小値を保持し、同じラウンド内の将来の選択に最大限の柔軟性を残すためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    stacks = []
    total = 0

    # store each stack as list of values
    for _ in range(n):
        arr = list(map(int, input().split()))
        a = arr[0]
        vals = arr[1:]
        stacks.append(vals)
        total += a

    # sort values inside each stack for deterministic "next unused"
    for i in range(n):
        stacks[i].sort()

    ptr = [0] * n

    # we maintain current candidates (value, stack)
    import heapq

    heap = []
    for i in range(n):
        if ptr[i] < len(stacks[i]):
            heapq.heappush(heap, (stacks[i][ptr[i]], i))

    ans = 0

    # helper: rebuild heap top lazily when stack advances
    while True:
        picked = []
        last_idx = 0

        used_this_round = []

        # we need a working copy of heap
        tmp = heap[:]
        heapq.heapify(tmp)

        while tmp and len(picked) < k:
            v, i = heapq.heappop(tmp)

            if i <= last_idx:
                continue

            # accept this card
            picked.append((v, i))
            last_idx = i
            used_this_round.append(i)

        if len(picked) < k:
            break

        ans += 1

        # apply updates: advance pointers for used stacks
        for i in used_this_round:
            ptr[i] += 1
            if ptr[i] < len(stacks[i]):
                heapq.heappush(heap, (stacks[i][ptr[i]], i))

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、スタックごとに、次に使用可能な値へのポインターを保持します。 ヒープには、これらの現在のヘッドのみが保存されます。 各ラウンドはヒープの一時コピーから貪欲に抽出することによって構築されるため、グローバルな状態を損なうことなく実現可能性をテストできます。 

微妙な点は、ラウンドのテスト中にメイン ヒープを直接変更できないことです。これは、ラウンドが早期に失敗するとロールバックが必要になるためです。 代わりに、コピーされたヒープを使用して選択をシミュレートし、ラウンドが成功した場合にのみ更新をコミットします。 

インデックス制約は次のように適用されます。`last_idx`ラウンド内で、スタック インデックスが選択された値の順序で厳密に増加するようにします。

 ## 特殊なケース

 1 つ目の微妙なケースは、スタックに個別に多くの値があるが、インデックスの制約によりその最小値が初期には使用できない場合です。 アルゴリズムは常に次のことを考慮するため、これを処理します。`last_idx`選択中に、無効な候補を消費せずにスキップします。 

もう 1 つのケースは、スタックが異なるラウンドにわたって複数の値を提供する場合です。 各スタックは現在のヘッドが使用されている場合にのみポインターを進めるため、以前の未使用の値が後のラウンドに干渉することはありません。 

最後に、いつ`k = n`、各ラウンドはすべてのスタックを使用する必要があります。 このアルゴリズムは依然として機能します。各スキャン内ですべてのインデックスにわたって完全な増加チェーンが強制され、インデックスが以下の場合に正確に失敗が発生するためです。`k`互換ヘッドは残ります。
