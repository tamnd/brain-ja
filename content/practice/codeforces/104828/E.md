 ## 解決策
 ## 問題の理解

 私たちには、駅がノードであり、各地下鉄線がこれらの駅のいくつかを通過する固定パスである地下鉄システムが与えられています。 各路線には、路線上の隣接する駅のペアごとに旅行時間が設定されています。 重要な点は、路線上の列車は連続的に運行するのではなく、毎時間ごとに路線の両端点から定期的に出発することです。`d`units of time, and then move along the line with fixed segment travel times.

 列車が時刻に終点から出発する場合`k·d`, it will pass through every station on that line in order, so each station sees trains arriving from both directions at predictable times. これは、駅が静的なエッジを持つ単純なグラフ ノードではなく、「特定の方向に向かう列車が利用可能になったとき」という繰り返しスケジュールを持つノードであることを意味します。 

リンクは現在自宅にいます。 彼が時間通りに起きたら`s`、彼は必要です`t3`駅に着くまでの時間`1`。 駅から`n`、到着後、彼は別のものが必要です`t4`目的地のビットに到着するまでの時間。 彼は駅に着かなければならない`n`遅くとも時間までに`t2 - t4`。 目標は、可能な限り遅い起床時刻を選択することです`s`(それより早くない`t1`) 彼はまだ駅に着くことができるように`n`地下鉄システムを使って時間通りに到着します。 

重要な隠れた構造は、地下鉄の移動時間は各駅での次の電車の待ち時間に依存し、それらの待ち時間はグラフ構造だけでなく絶対的な到着時間に依存するということです。 これにより、この問題は、最適な開始時間の探索と組み合わされた時間依存の最短経路問題になります。 

制約により、最大で次のことが許可されます。`2 × 10^5`駅まで`10^5`最大の大きな時間値を含む行`10^9`。 これにより、時間の経過に伴うシミュレーションや状態の単純な拡張が除外されます。 最短パスの計算は、グラフ サイズが線形対数に近い必要があり、時間への依存はエッジごとに一定時間で計算する必要があります。 

微妙な失敗のケースは、列車は存在するが到着時刻と一致しない場合に発生します。 たとえば、ある時刻に駅を訪れた場合、`7`でも次の電車は～に到着します`8`、「電車は毎日存在する」という素朴な仮定は、`d`「いつでもすぐに続行できるように」という考えは、移動時間を過小評価することにつながります。別の失敗例は、早く開始することが常に良いと仮定していることです。定期的なシステムでは、早く開始すると実際に適切な調整を逃し、スケジュールが遅くなる可能性があります。 

## アプローチ

 ブルートフォース戦略では、可能なすべてのウェイクアップ時間を試します。`s`、旅行全体をシミュレーションし、到着が期限内にあるかどうかを確認します。 各シミュレーションでは、時間依存のグラフ上で最短パスを実行し、各緩和がライン上で次に利用可能な出発を計算します。 各シミュレーションにダイクストラを使用したとしても、これは非常に遅くなります。`s`までの範囲`10^9`、各実行コストは約`O((n + m) log n)`。 これは限界をはるかに超えています。 

重要な観察は、起床時間に依存するのはステーションでの開始タイムスタンプだけであるということです。`1`。 開始時刻を決定すると、残りの移動は時間に依存する最短経路によって決定されます。 これは関数を定義します`f(s)`開始時刻を駅への最も早い到着時刻にマッピングします`n`。 重要なのは、開始を遅らせても、単調性を壊すような単純な方法で到着時間を改善することはできません。開始を遅らせると、同じスケジュールの調整が維持されるか、到達可能なすべての出発が前倒しされます。`f(s)`減っていない。 

この単調性により、実行可能な最新のウェイクアップ時刻を二分探索することができます。 確定候補者の場合`s`では、各エッジが路線期間にわたるモジュラー演算を使用して次の列車の出発時刻を計算する、修正されたダイクストラを使用して最も早い到着を計算します。 結果が期限内であれば、後で試します。 それ以外の場合は削減します`s`。 

残る唯一の困難は、ラインに沿った遷移を効率的に計算することです。 回線上の各ステーションには、各エンドポイントから 1 つずつ、合計 2 つの定期的な到着パターンがあります。 駅から`u`オンラインで`i`、その線に沿った両方の端点からの距離を事前計算します。 それから、ある時に、`t`、次に利用可能な列車が通過します`u`特定の方向からの角度は次のように決定されます。`k = ceil((t - offset) / d)`、出発時間を指定します`k·d + offset`、次に、隣接する駅へのエッジ移動時間を追加します。 

これにより各緩和が O(1) に保たれるため、各ダイクストラの実行が効率的になります。

 ## アルゴリズムのチュートリアル

 まず、各路線の各駅の構造情報を事前計算します。 各路線について、左端点からのプレフィックス距離を計算するため、路線の始点から任意の駅までの移動時間がわかります。 また、線を反転して右端点からの対称距離を計算します。 

このステップが必要なのは、線路に沿った移動をシミュレートする代わりに、O(1) 内の任意の駅での列車の到着スケジュールを計算できるためです。 

次に、固定ウェイクアップ時間の実現可能性チェックを定義します。`s`。 

1. 駅で出発時刻を設定します`1`として`s + t3`。 これは、リンクがメトロ ネットワークの使用を開始できる最も早い瞬間を表します。 
2.ステーションから修正されたダイクストラを実行します`1`ここで、各ノードの状態はステーションと現在時刻です。 初期状態は`(station 1, time s + t3)`。 
3. 駅からの端を緩める場合`u`隣の駅まで`v`ある線に沿って、次に通過する利用可能な列車を計算します。`u`その方向に。 事前に計算されたオフセットと期間を使用します`d`現在時刻以降の最小の出発時刻を検索します。 
4. 到着時間`v`この出発時間に区間の移動時間を加えたものです`(u, v)`。 の最もよく知られている到着時間を更新します`v`これの方が良かったら。 
5. ダイクストラ終了後、駅への最も早い到着時刻を確認します。`n`せいぜい`t2 - t4`。 「はい」の場合、この起床時間は実現可能です。 

最後に二分探索をします`s`範囲内で`[t1, t2]`。 中間点ごとに実現可能性チェックを実行します。 実現可能な最大値が答えになります。 たとえさえあれば`s = t1`失敗した場合は出力します`-1`。 

### なぜ効果があるのか

 正しさは 2 つの特性に基づいています。 まず、最短パスの計算は、時間依存のエッジ コストの下で有効です。これは、すべての緩和では常に到着後の可能な限り早い出発が使用されるため、将来のより良い機会を逃すことがないためです。 第二に、実現可能性はウェイクアップ時間において単調である: 増加する`s`以前にルートが存在しなかった場合、新しい有効なルートを作成できない方法で、すべての到着時刻を前にずらします。 これにより、バイナリ検索が実行可能な最大スリープ時間を正しく分離できるようになります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def ceil_div(a, b):
    if a <= 0:
        return 0
    return (a + b - 1) // b

def check(s, t1, t2, t3, t4, n, adj, line_info):
    start_time = s + t3
    dist = [INF] * (n + 1)
    dist[1] = start_time
    pq = [(start_time, 1)]

    while pq:
        t, u = heapq.heappop(pq)
        if t != dist[u]:
            continue
        if u == n:
            return t <= t2 - t4

        for (v, d, off, w) in adj[u]:
            if t < off:
                k = 0
            else:
                k = (t - off + d - 1) // d
            depart = off + k * d
            arrive = depart + w

            if arrive < dist[v]:
                dist[v] = arrive
                heapq.heappush(pq, (arrive, v))

    return dist[n] <= t2 - t4

def solve():
    t1, t2, t3, t4 = map(int, input().split())
    n, m = map(int, input().split())

    adj = [[] for _ in range(n + 1)]

    for _ in range(m):
        k, d = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        pref = [0] * k
        for i in range(1, k):
            pref[i] = pref[i - 1] + b[i - 1]

        total = pref[-1]

        for i in range(k - 1):
            u = a[i]
            v = a[i + 1]

            off_f = pref[i]
            off_b = total - pref[i]

            adj[u].append((v, d, off_f, b[i]))
            adj[v].append((u, d, off_b, b[i]))

    def ok(s):
        return check(s, t1, t2, t3, t4, n, adj, None)

    if not ok(t1):
        print(-1)
        return

    lo, hi = t1, t2
    ans = t1

    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans - t1)

if __name__ == "__main__":
    solve()
```隣接構築により、各地下鉄路線が定期的なスケジュールを持つ有向エッジに変わります。 各エッジには周期が格納されます`d`、位相オフセット`off`列車がその終点を順方向または逆方向にいつ通過するか、およびセグメントの移動時間を記述します。 

ダイクストラ ルーチンは、エッジ緩和で固定重みではなく計算された出発時間を使用することを除いて標準です。 表現`(t - off + d - 1) // d`列車のスケジュールに合わせて次の期間の倍数を検索します。 これは、時間依存性が処理される唯一の場所です。 

二分探索はこの実現可能性チェックをラップし、最大追加スリープ時間を返します。

 ## 特殊なケース

 重要なケースの 1 つは、ステーションの場合です。`n`構造的には到達可能ですが、スケジュールの調整により不可能になります。 このような場合でも、ダイクストラはノードを探索しますが、到達するパスを緩和することはありません。`n`締め切り前に。 基礎となるグラフが接続されている場合でも、チェック関数は正しく false を返します。 

もう 1 つのケースは、待ち時間が移動時間の大半を占める場合です。 リンクが駅の出発直後に到着した場合、アルゴリズムは全期間待機することを強制します。 次の出発は天井分割を使用して計算されるため、これは正しく処理され、違法な「即時搭乗」が発生しないことが保証されます。 

3 番目のケースは、最適な起床時刻が正確に次のとおりである場合です。`t1`。 二分探索では、答えを次のように初期化することで、これを正しく処理する必要があります。`t1`より高い値を検索する前に実現可能性を検証します。
