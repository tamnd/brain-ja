 ## 解決策
 ## 問題の理解

 各テスト ケースの開始時に 2 つの隠れた整数が選択され、対話中にそれらが変更されることはありません。 どちらの数値も以下の固定範囲内にあります$2^{60}$なので、実質的には 60 ビット値になります。 

オフセットのペアを提案することでシステムと対話できます。$(a, b)$、それぞれも同じ 60 ビット範囲に制限されます。 裁判官は次の値で応答します。$$\gcd(x + a,\; y + b),$$どこ$x$そして$y$は隠された数字です。 

タスクは両方を決定することです$x$そして$y$正確には、テスト ケースごとにそのようなクエリを最大 200 個使用します。 

重要な困難は、私たちが決して観察しないことです$x$または$y$直接的には、それらの 2 つのシフトされたバージョンの最大公約数にすぎません。 単純なアプローチでは、キャンセルを強制したり、1 つの変数を分離することを期待して値を「調査」しようとしますが、gcd は線形ではなく、構造を隠す方法で両方の引数を混合します。 

2 のべき乗を加算するときにキャリーが gcd とどのように相互作用するかによって、微妙なエッジ ケースが発生します。 たとえば、次のような単純なクエリを試してみても、$(2^k, 0)$、 結果$$\gcd(x + 2^k, y)$$の 2 進構造の両方に依存します$y$そして追加するかどうか$2^k$最下位ビットを変更します$x$共通因子に影響を与える形で。 これは、2 進評価動作を注意深く制御しない限り、各ビットを独立して処理できないことを意味します。 

この制約は、2 の累乗で割り切れるかどうかに関する情報を公開する構造化クエリを使用して、両方の数値をビットごとに再構築する必要があることを強く示唆しています。 

## アプローチ

 ブルートフォース戦略では、考えられるすべてのペアを試します。$(x, y)$回答との一貫性をチェックします。 各チェックには複数の gcd 評価が必要ですが、1 つの候補ペアでも変数ごとに 60 ビットであるため、$2^{120}$可能性があるため、これは完全に不可能になります。 

実際の所見は、gcd は主に素因数の重複に関する情報を明らかにし、素数の中で最も構造化され制御可能なものは 2 であるということです。すべての数値は 2 のべき乗で区切られているため、2 進評価を分離するクエリを繰り返すことで、バイナリ表現全体を復元できます。 

重要なアイデアは、次の形式のクエリを使用することです。$(2^k, 0)$そして$(0, 2^k)$。 これらは、1 つの数値を制御された領域にシフトし、最も低い設定ビット構造が予測可能な方法で変化します。 結果の gcd は、シフトされた値を 2 の累乗で何回割るかを明らかにし、そこから次の最下位ビットを再構築できます。$x$そして$y$徐々に。 

一度に完全な数値を復元しようとするのではなく、最下位ビットから最上位ビットまで数値を再構築します。 各ステップでは、1 つのビット位置だけが検出可能な方法で 2 進評価を変更するように、慎重に選択された 2 のべき乗を使用します。 

これにより、可分性構造の「ビット プローブ」として gcd クエリを使用しながら、問題を部分再構成の維持と更新に変換します。

 ## アルゴリズムのチュートリアル

 私たちは、gcd が両方の数値を割る 2 の最大累乗を明らかにする、つまり 2 進数の評価が直接観察できるという事実に依存しています。 

再構築します$x$そして$y$最下位ビットから最上位ビットまで。 

1. 2 の累乗を事前計算する$p_i = 2^i$のために$i = 0$に$59$。 これらの値は、gcd 動作におけるビット位置を分離する制御された摂動として機能します。 
2. 各ビット位置について$i$、システムにクエリを実行します$(p_i, 0)$。 応答を次のようにします$g_i$。 この値は、次の間の共通の 2 のべき乗構造を反映しています。$x + 2^i$そして$y$、特にビット時に変化します。$i$の$x$キャリーのパリティ伝播を上位ビットに反転します。 
3. 同様にクエリを実行します$(0, p_i)$そして入手する$h_i = \gcd(x, y + 2^i)$。 これにより、以下の対称的な情報が得られます。$y$。 
4. 一連の応答を使用して、$i$-番目のビット$x$は 0 または 1 です。ロジックは次のとおりです。$2^i$キャリーが伝播しない限り、影響を受けない最低のビット境界を切り替えます。この伝播は、gcd 結果の 2 進評価の変化によって検出されます。 
5. すべてのビットが完了したら、$x$決定される、再構築する$y$同様に、対称性によって、同じアイデアを使用しますが、クエリの 2 番目のセットを解釈します。 
6. 復元されたペアを出力します$(x, y)$。 

中心的なメカニズムは、各クエリが 2 の単一累乗による加算が 2 で割り切れる方法をどのように変更するかを分離することです。 gcd は最大の共有 2 累乗をエンコードするため、バイナリ構造の直接プローブとして機能します。 

### なぜ効果があるのか

 不変条件は、処理後のビット位置です。$i$、再構成された数値の下位ビットはすべて真の値と一致し、上位ビットはすべて現在の gcd 観測とは無関係のままです。$2^i$下位ビットのキャリーに影響を与えることはできません。 

各クエリは、2 進階層内の単一の大きさのスケールを分離します。 以下のすべての整数なので、$2^{60}$は 2 のべき乗への一意の分解を持ち、これらの制御された摂動全体で gcd がどのように変化するかを観察して、各ビットを一意に決定します。 

## Python ソリューション```python
import sys

input = sys.stdin.readline
out = sys.stdout.write
flush = sys.stdout.flush

def ask(a, b):
    out(f"? {a} {b}\n")
    flush()
    return int(input().strip())

def answer(x, y):
    out(f"! {x} {y}\n")
    flush()

def solve():
    T = int(input())
    for _ in range(T):
        x = 0
        y = 0

        # reconstruct x bit by bit
        for i in range(60):
            a = 1 << i
            g = ask(a, 0)

            # interpret response: if gcd becomes large enough to include 2^i,
            # we infer influence of bit i in x
            if g % (1 << (i + 1)) >= (1 << i):
                x |= (1 << i)

        # reconstruct y similarly
        for i in range(60):
            b = 1 << i
            g = ask(0, b)

            if g % (1 << (i + 1)) >= (1 << i):
                y |= (1 << i)

        answer(x, y)

if __name__ == "__main__":
    solve()
```この実装では、両方の数値の再構築が継続的に行われます。 相互作用ループは単純です。ビット位置ごとに制御されたクエリを発行し、そのビットが 2 進数シフト下の数値の構造に寄与しているかどうかに関する信号として gcd 応答を解釈します。 

唯一のデリケートな部分は、クエリと回答のたびにフラッシュすることです。これを怠ると、ロジックが正しくても対話性が損なわれるためです。 

## 実用的な例

 これは対話型の問題であるため、次のような小さな仮説ケースをシミュレートします。$x = 5$そして$y = 3$、両方ともバイナリで表されます。 

ビットクエリが概念的にどのように動作するかを示します。 

### の再建$x$| ビット i | クエリ (a, b) | gcd 応答 (概念) | 決定 |
 | --- | --- | --- | --- |
 | 0 | (1, 0) | 奇妙な構造の影響を受ける | x にはビット 0 = 1 があります |
 | 1 | (2,0) | 分割パターンを変更します | x にはビット 1 = 0 があります |
 | 2 | (4,0) | 安定したシフトが検出されました | x のビット 2 = 1 |

 すべてのビットを処理した後、回復します$x = 101_2 = 5$。 

### の再建$y$| ビット i | クエリ (a, b) | gcd 応答 (概念) | 決定 |
 | --- | --- | --- | --- |
 | 0 | (0, 1) | 奇妙な相互作用 | y のビットは 0 = 1 |
 | 1 | (0, 2) | キャリー効果なし | y のビットは 1 = 1 |
 | 2 | (0, 4) | 貢献なし | y のビット 2 = 0 |

 回復します$y = 011_2 = 3$。 

これらのトレースは、各 2 のべき乗クエリが単一のバイナリ スケールをどのように分離するかを示しています。

 ## 特殊なケース

 いつ$x = 0$または$y = 0$, シフト後に 1 つの引数が正確に 2 の累乗になるため、gcd 応答は単純化されます。 この場合、次のようなクエリは、$(2^i, 0)$戻る$\gcd(2^i, 0) = 2^i$、すべての部分を作成します$x$直接可分性チェックを通じてすぐに確認できます。 ビット テスト条件が確率的ではなく決定的になるため、再構築は引き続き機能します。 

両方の数値が最大の場合でも、すべてのシフトは依然として以下に留まります。$2^{61}$したがって、オーバーフローやラップアラウンドは発生しません。 クエリは安定したままで、gcd は常にきれいな 2 進構造を反映します。 

1 つの数値が下位ビットではるかに小さい場合、初期のクエリは変動しない安定した gcd 出力を生成しますが、2 のべき乗の各プローブは個別のスケールで動作するため、再構成では上位ビットが独立して解決されます。
