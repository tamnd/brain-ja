 ## 解決策
 ## 問題の理解

 整数のリストと係数値が与えられます。 このタスクは、リスト内のすべての数値の積を計算し、その積を指定された係数で割った余りを出力することです。 

このステートメントでは、これをデータ型とオーバーフローに関する「魔法のトレーニング」レッスンのように見せかけていますが、実際の計算は単純です。すべての要素を掛け合わせますが、すべての中間ステップは安全な数値範囲内に収まる必要があり、最終結果は剰余として取得される必要があります。$p$。 

重要な制約は、$n$と同じ大きさにすることができます$10^5$。 これにより、積を繰り返し再計算したり、ネストされたループを使用したりするアプローチは即座に除外されます。$O(n^2)$作業が遅すぎるでしょう。 単一の直線パスが唯一の合理的な構造です。 

微妙な数値制約もあります。 までの製品$10^5$それぞれの数値は次の値に近い可能性があります$10^9$、不注意だと 64 ビット整数が簡単にオーバーフローしてしまう可能性があります。 それぞれですが、$a_i < p$、 そして$p \le 10^9$、モジュラーリダクションなしでそのような値を多数乗算すると、$2^{63}-1$とても早く。 したがって、モジュロを最後まで遅らせる単純な実装では、不正確な結果や実行時の問題が発生します。 

エッジケースは主にモジュラー算術動作を中心としています。 

いずれかの要素がゼロの場合、積全体が直ちにゼロになるため、継続的な乗算は不要です。 もう 1 つの例外的なケースは次のような場合です。$p = 1$。 この場合、1 を法とするすべての数値は 0 であるため、配列に関係なく、答えは常に 0 になります。 

## アプローチ

 ブルートフォース解釈では、積を直接計算し、モジュロを適用します。$p$。 概念的にはこれは正しいです。乗算は結合的であるため、計算は$a_1 \cdot a_2 \cdots a_n$最初に削減し、最後に削減すると正しい剰余が生成されます。 

失敗点は数値の増加です。 64 ビット整数であっても、乗算を繰り返すと表現可能な範囲をすぐに超えてしまいます。 のために$n = 10^5$、最悪の場合の増加は指数関数的であり、オーバーフローは最終ステップのかなり前に発生します。 このため、標準の固定幅整数環境ではブルート フォース手法の信頼性が低くなります。 

重要な観察は、モジュラー演算により、最終結果を変えることなくすべてのステップでリダクションが可能であるということです。 以来$$(x \cdot y) \bmod p = ((x \bmod p) \cdot (y \bmod p)) \bmod p,$$実行中の積モジュロを維持できます$p$を超えないようにします。$p$。 これにより、問題は一定時間の更新を伴う単一の線形スキャンに変換されます。

 ## アルゴリズムのチュートリアル

 実行中の変数を維持します`ans`すべての処理された要素のモジュロの積を格納します$p$。 

1.初期化`ans = 1`。 これは空の積を表し、乗算の中立要素です。 1 を乗算しても値は変わらないため、1 を選択します。 
2. 各要素を反復処理する`a_i`配列内で。 
3. 乗算する前に、要素の剰余を削減します。$p$ご希望に応じて。 この問題ではオプションです。$a_i < p$ただし、習慣を維持することで、一般的な設定の正確性が保証されます。 
4. 実行中の製品を次のように更新します。`ans = (ans * a_i) % p`。 このステップはソリューションの中核です。 オーバーフローを防止し、値の境界を維持するために、乗算後すぐに減算します。$p$。 
5. すべての要素を処理した後、出力します`ans`。 

このロジックでは以前の要素を再検討する必要がないため、計算は厳密に 1 パスで行われます。 

### なぜ効果があるのか

 反復ごとに、`ans`前のすべての要素の積を法で表します$p$。 次の要素を掛けて剰余を減らすと、$p$、モジュラー演算の分配特性により、この不変式を保存します。 不変式は最初の要素から最後の要素まで保持されるため、最終値は正確にすべての要素の積を法にしたものになります。$p$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, p = map(int, input().split())
    arr = list(map(int, input().split()))
    
    ans = 1 % p
    for x in arr:
        ans = (ans * (x % p)) % p
    
    print(ans)

if __name__ == "__main__":
    main()
```コードは不変条件に直接続きます。 変数`ans`常に縮小剰余を維持します`p`、決して大きくならないようにします。 Python の整数の乗算はオーバーフローしませんが、この構造は C++ などの言語では依然として不可欠であり、意図した問題の制約と一致します。 

初期化`1 % p`次の場合に正確性を保証します$p = 1$なぜなら、入力に関係なく答えはゼロでなければならないからです。

 ## 特殊なケース

 いつ$p = 1$、すべての乗算ステップはゼロになります。 アルゴリズムが初期化されます`ans = 1 % p`、すぐに0になります。 反復が始まるとすぐに、`ans`入力に関係なくゼロのままとなり、正しい結果が生成されます。 

ゼロを含む入力の場合、次のようになります。`3 10 / 4 0 7`、最初の乗算でゼロが生成されると、実行中の積がゼロに折りたたまれます。 後続のステップでは変更されないままになります。`0 * x % p = 0`したがって、最終出力は予想どおりゼロのままです。 

単一要素の配列の場合、ループは 1 回実行され、結果は単純にその要素のモジュロになります。$p$。 初期化は空の積に対応し、1 回の乗算によって正しい最終値に遷移するため、不変式は依然として保持されます。
