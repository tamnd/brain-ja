 ## 解決策
 ## 問題の理解

 私たちには、最大でも 7 つの同一の敵ミニオンがいる小さな戦場が与えられます。 各ミニオンは、最初に受けるダメージを完全にブロックする保護シールドから始まります。 シールドが壊れた後、ミニオンの体力は 4 になり、さらに 4 回の個別の単一点攻撃を受けた後にのみ死亡します。 したがって、各ミニオンはゲームから削除される前に実質的に 5 回のヒットが成功する必要があります。 

スペルカードは番号 a で表されます。 再生すると、独立したトライアルが実行されます。 各トライアルでは、現在生きている敵のミニオンを 1 体ランダムに一様に選択し、それに 1 ダメージを与えます。 ミニオンがシールドを失った場合、その最初のダメージは体力を減らすことはありませんが、シールドを取り除きます。 ミニオンの体力がゼロになると消滅し、その後のトライアルで選ばれる資格がなくなります。 

各カードについて、すべてのランダムなヒットの後、すべての敵ミニオンが殺される確率を計算する必要があります。 

重要な構造は、ミニオンが死ぬたびに有効なターゲットのセットが縮小するため、ランダム性が時間の経過とともに進化するということです。 これにより、プロセスは残りのヘルス状態とシールド状態の構成にわたるマルコフ チェーンになります。 

この制約は、ミニオンの数という点では非常に少なく (最大 7 つ)、クエリあたりのステップ数という点では中程度 (最大 400 クエリ) です。 これは、状態空間が a ではなく n にのみ指数関数的に依存する限り、状態の数に負荷がかかる何かを実行できることをすぐに示唆しています。 

主な難点は、選択が現在生きているミニオン間でのみ均一であるため、確率が単純な多項イベントではないことです。したがって、死亡が発生すると確率は動的に変化します。 

多くの場合、解決策を壊す単純な誤解は、各ヒットを最初の n ミニオンにわたる独立した均一なものとして扱うことです。 ミニオンが死ぬとプールから削除されるため、これは不正確です。 もう 1 つの微妙なエッジ ケースは、すべてのヒットが使用される前にすべてのミニオンが死亡する場合です。 このプロセスは、空になるまで、より小さなセットに対して事実上継続されます。 一度空になると、それ以上意味のあるランダムな選択はできなくなりますが、完全にクリアされる可能性に関しては、これによってイベントの定義が変更されることはありません。 

2 番目によくある間違いは、ヒットの合計数のみが重要であると想定することです。 たとえば、n = 2 および a = 10 の場合、10 件のヒットが発生したことを知るだけでは十分ではありません。 死亡するたびにターゲットプールが縮小し、将来の確率が変化するため、正確な順序を知る必要があります。 

## アプローチ

 ブルート フォース ビューでは、ランダム プロセス全体を段階的にシミュレートします。 各ステップで、すべてのミニオンの現在のヘルスとシールドのステータスを維持し、考えられる次のターゲットをすべて列挙し、それに応じて確率を伝播します。 これは概念的には簡単です。すべての状態は最大 n 個の遷移に分岐し、生きているミニオンの数に対して確率を 1 倍します。 

このシミュレーションはプロセスの定義を正確に反映しているため、その正確性はすぐにわかります。 問題は規模だ。 各カードには最大 400 のステップが必要で、各ステップは 6 つの可能な状態 (デッド、シールド、またはシールドなし、体力 1 ～ 4) を持つ 7 つのミニオンのすべての構成まで成長できる状態空間を反復します。 これはおよそ 6^7、約 280,000 州に相当します。 ステップごとの単純な動的プログラムでは、クエリごとに数億回のトランジションが必要となり、これに最大 400 クエリを乗算することは不可能になります。

重要な観察は、プロセスは残りのミニオンの現在の構成によって完全に決定され、この構成空間は DP 状態空間自体として扱えるほど十分に小さいということです。 カードごとに個別のシミュレーションを考える代わりに、すべての構成にわたってグローバルな遷移システムを計算し、すべてのカードにわたって最大 a までの時間発展 DP を実行します。 すべてのクエリは同じ初期状態から始まるため、同じ DP 進行を再利用し、異なるタイム ステップで単純に回答を読み取ります。 

これにより、問題は有限状態空間上での固定マルコフ遷移演算子の繰り返し適用に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのステップバイステップのシミュレーション | O(m · a · 状態 · n) | O(状態) | 遅すぎる |
 | すべての州および時間にわたるグローバル DP | O(maxA · 状態 · n) | O(状態) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ミニオンの状態を個別にエンコードします。 各ミニオンは 6 つの状態のいずれかになります。すでに死亡しているか、シールドがありシールドブレイク後に体力が 1 ～ 4 残っている状態、またはシールドが無傷で生きている状態です。 便利な表現は、各ミニオンを 5 から 1 までの「有効ヒット数」の値が残っているものとして扱い、0 は死亡を意味します。 初期状態は、すべてのエントリが 5 である長さ n のベクトルです。 

次に、動的プログラミング テーブルを構築します。ここで、 dp[t][state] は、t 回のヒット後にその正確な構成になる確率です。 

1. すべてのミニオンが値 5 を持つ状態で dp[0] を確率 1 で初期化します。他のすべての状態は確率 0 になります。これは決定的な開始ボードを反映します。 
2. 0 から maxA − 1 までのタイム ステップ t ごとに、ゼロ以外の確率ですべての状態を反復します。 
3. それぞれの状態について、まだ生きているミニオンの数を数えます。 ミニオンの値が 0 より大きい場合、ミニオンは生きています。 
4. この状態から、生きているミニオンを 1 つ均等に選択することによって、その確率質量を次のすべての状態に分配します。 各生きているミニオンの確率は 1 を生きているミニオンの数で割った値になります。 
5. ミニオンを選択すると、その残りの値が 1 減ります。 ゼロになると、将来のターゲットのセットから削除されたとみなされます。 
6. 寄与分を dp[t + 1] に累積します。 

dp を maxA まで満たした後、パラメータ a を持つカードの答えは単純に dp[a][terminal_state] になります。terminal_state は、すべてのエントリがゼロである構成です。 

これが機能する理由は、DP 状態が関連するすべての履歴を完全にキャプチャしているためです。 同じ構成に至る 2 つの履歴は、同じ将来の動作を生成します。これは、選択はどのミニオンがまだ生きているかのみに依存し、ミニオンがその状態にどのように到達したかには依存しないためです。 このマルコフ特性は、情報を失わずに確率質量を状態ごとに安全にマージできることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def encode(state):
    # base-6 encoding of vector, each value in [0..5]
    x = 0
    for v in state:
        x = x * 6 + v
    return x

def decode(x, n):
    state = [0] * n
    for i in range(n - 1, -1, -1):
        state[i] = x % 6
        x //= 6
    return state

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    maxA = max(a)

    S = 6 ** n

    dp = [0.0] * S
    ndp = [0.0] * S

    init = (5,) * n
    dp[encode(init)] = 1.0

    terminal_mask = encode((0,) * n)

    for t in range(maxA):
        for i in range(S):
            if dp[i] == 0.0:
                continue

            state = decode(i, n)

            alive = []
            for j in range(n):
                if state[j] > 0:
                    alive.append(j)

            if not alive:
                ndp[i] += dp[i]
                continue

            p = dp[i] / len(alive)

            for j in alive:
                ns = state[:]
                ns[j] -= 1
                ni = encode(ns)
                ndp[ni] += p

        dp, ndp = ndp, [0.0] * S

    for x in a:
        print(f"{dp[terminal_mask]:.12f}")

if __name__ == "__main__":
    solve()
```このコードは、前述の状態遷移を直接反映しています。 最もデリケートな部分は、状態のエンコードとデコードです。 n が小さいため、各構成を基数 6 で安全にエンコードすることで、DP 配列をフラットな構造に格納できます。 

もう 1 つの微妙な点は、ミニオンが生き残っていない状態の処理です。 その場合、それ以上の遷移は不可能であるため、確率質量は単純に端末構成に留まります。 

時間ステップにわたる外側のループにより、すべてのクエリに対して中間ディストリビューションが再利用されます。 

## 実用的な例

 1 つのミニオンと a = 5 の 1 枚のカードを持つ小さなケースを考えてみましょう。状態空間には 5 から 0 までの値のみが含まれます。 

| ステップ | 状態 | 確率 |
 | --- | --- | --- |
 | 0 | [5] | 1 |
 | 1 | [4] | 1 |
 | 2 | [3] | 1 |
 | 3 | [2] | 1 |
 | 4 | [1] | 1 |
 | 5 | [0] | 1 |

 これは、ターゲットが 1 つである場合、分岐がないためプロセスが決定的になることを示しています。 

次に、2 つのミニオンと a = 10 について考えます。最初は両方とも 5 です。プロセスはそれらの間でヒットをランダムに割り当てますが、一方が 0 に達すると、後続のヒットはすべて残りのミニオンに割り当てられます。 DP は、生きているミニオンの数に応じて各ステップで確率質量を分割することで、これを正確に捉えます。 

| ステップ | 一般的な構成 | 解釈 |
 | --- | --- | --- |
 | 0 | (5,5) | 開始 |
 | 3 | (2,5)、(3,4)、(4,3)、(5,2)の混合物 | 両方ともまだ生きています |
 | 5 | (0,4)、(1,3)、(2,2) | のような状態 一人は死んでいるかもしれない |
 | 10 | (0,0) ある確率で | 両方とも死亡しました |

 このトレースは、ミニオンが死ぬにつれて状態空間がどのように自然に縮小するのか、またカウントのみの追跡が失敗する理由を示しています。

 ## 特殊なケース

 重要なエッジケースの 1 つは、すべてのステップが使用される前にすべてのミニオンが死亡した場合です。 (0,0,...,0) のような状態では、生きているターゲットは存在しないため、DP 遷移により確率質量が同じ状態に保たれます。 これは、ゲームが早期に終了すると、追加の手順によって結果が変わらないという事実を正しくモデル化しています。 

もう 1 つの微妙なケースは、ミニオンが死にそうになり、移行直後に使用できなくなる場合です。 たとえば、状態 (1,5) から最初のミニオンをヒットすると (0,5) になり、次のステップでそれを再度選択してはなりません。 生きているミニオンは暗黙的に追跡されるのではなく、すべての状態で再計算されるため、DP はこれを強制します。 

最後のデリケートな状況は、エンコードとデコードの順序です。 Base-6 変換が遷移間で一貫性がない場合、2 つの異なる状態が衝突したり、誤って分岐したりする可能性があります。 固定長表現を使用すると、すべての構成が単一の整数に一意にマッピングされ、DP 全体にわたって正確さが維持されます。
