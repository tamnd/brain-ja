 ## 問題の理解

 この問題では正の整数が得られます`n`を使用すると、1 回以上繰り返された数字 9 だけで構成される任意の数値を加算する演算を実行できます。 私たちの目標は、`n`少なくとも 1 つの数字が含まれる`7`このような操作を最小限に抑えます。 たとえば、次の場合`n = 80`、追加できます`9`繰り返しまたは直接追加`99`のような数字に達する`179`、数字が含まれています`7`。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは単一の整数です`n`、制約付き`10 ≤ n ≤ 10^9`。 最大 10,000 のテスト ケースを含めることができます。 以来`n`は非常に大きくなる可能性があり、多くのテスト ケースを処理する必要があるため、考えられるすべての加算シーケンスを単純に試行するソリューションは遅すぎます。 

微妙な点としては、`n`すでに数字が含まれている可能性があります`7`。 その場合、操作は必要ありません。 もう 1 つの微妙な点は、すべて 9 で構成される数字を加算すると、制御された方法でモジュロ 10 の周囲に数字を「ラップ」できることです。 たとえば、追加`9`数値に最後の桁を追加して追加します。`99`最後の 2 桁が増分されます。 不用意にブルートフォース手法を使用すると、このキャリーオーバー効果が無視され、不要な操作や誤ったカウントが発生する可能性があります。 

## アプローチ

 ブルートフォース手法は、次のような数値の可能なすべての加算をシミュレートすることです。`9, 99, 999...`番号に が含まれるまで`7`。 操作セットが明確に定義されているため、これは機能しますが、最悪の場合、`n`多数の連続する数字を含む数値のすぐ下にある場合もあります`7`、何百もの操作が必要です。 10^4 のテスト ケースでは、これは非常に遅すぎます。 

重要な観察は、9 で構成されるすべての数字を任意の順序で考慮する必要はないということです。 フォームはいくつでも追加できるので、`9`、`99`、`999`など、次の数字で終わる数字はいつでも達成できます。`7`繰り返し追加することで`9`。 これにより、問題は単純な貪欲なシミュレーションに縮小されます。追加を続ける`9`数字が入るまで`7`。 それぞれの追加`9`数値が増加するため、`9`に一致します`-1`10 を法として計算すると、桁が予測どおりに変化するため、ある桁に達することができます。`7`効率的に。 

事実上、最小の演算数は最小の整数にすぎません。`k`そのような`n + 9 * k`が含まれています`7`。 数値が最大 10^9 であることを考えると、テスト ケースごとに数十以上の操作が必要になることはありません。`9`最後の桁を繰り返しローテーションし、最終的にヒットします`7`。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. テスト ケースごとに、整数を読み取ります。`n`。 
3. 次のことを確認します。`n`すでに数字が含まれています`7`。 存在する場合は出力します`0`そして続けます。 
4. カウンタの初期化`ops = 0`。 
5. ながら`n`数字が含まれていません`7`:

 1. インクリメント`n`による`9`。 
2. インクリメント`ops`による`1`。 
6. 1回`n`が含まれています`7`の値を出力します。`ops`。 

機能する理由: 貪欲なアプローチでは、常に数値が増加します。`9`、予測可能な方法で数字を変更します。 10進法は10桁しかないので、繰り返し足し算すると、`9`最終的には`7`何かの桁に表示されます。 9 で構成される数字の組み合わせほど、より少ない加算を生成できる高速な組み合わせはありません。`99`または`999`複数でシミュレートできます`9`s; したがって、次を使用したシミュレーションは`9`最小限の操作数を取得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        ops = 0
        while '7' not in str(n):
            n += 9
            ops += 1
        print(ops)

if __name__ == "__main__":
    main()
```このソリューションは、上記のアルゴリズムを直接実装します。 実装の微妙な選択は変換です`n`毎回文字列に変換して数字をチェックする`7`。 使用する`'7' in str(n)`ヒットする前にいくつかの追加のみを期待するため、シンプルで効率的です。`7`。 文字列に変換すると、各桁を手動でチェックしたり桁上げを処理したりする必要がなくなります。
