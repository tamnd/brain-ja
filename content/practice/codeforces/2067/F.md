 ## 解決策
 ## 問題の理解

 整数の配列と 3 つの変数が与えられます。`P`、`Q`、`R`最初はゼロに設定されます。 配列の各要素について、3 つの変数のうちの 1 つと XOR することを選択する必要があります。 主な制限は、すべてのステップで 3 つの変数をすべて区別できないことです。 つまり、何らかの操作の後、少なくとも 2 つの`P`、`Q`、`R`等しくなければなりません。 

タスクは、このルールに従う有効な操作シーケンスの数をカウントすることです。 答えは非常に大きくなる可能性があるため、結果のモジュロが必要です$10^9 + 7$。 

制約は強力です: まで$2 \cdot 10^5$すべてのテスト ケースにわたる要素と最大数$10^9$。 これにより、すべてを試すという強引な解決策が即座に排除されます。$3^n$シーケンス$3^{20}$およそ30億です。 XOR の構造と非区別条件を利用するアプローチが必要です。 

微妙な点は、「ペアごとに区別しない」では 2 つの変数が等しいことを許可しますが、3 つすべてが等しいことも許可されることです。 これにより、ルールに違反することなくシーケンスが伝播できる特定のパターンが作成されます。 同一の操作をカウントするだけ、または最終的な等価性だけを調べる単純なアプローチは、値が繰り返される配列では失敗します。 

たとえば、次の場合`a = [1,1,1]`、不用意なアプローチは意味があるだけかもしれません`PPP`、`QQQ`、`RRR`、しかし次のようなシーケンス`PPQ`2 番目の要素の後に、`P=1, Q=0, R=0`、ゼロが 2 つあるため、ルールを満たします。 

## アプローチ

 ブルート フォース アプローチは概念的には単純です。要素ごとに選択肢のシーケンスをすべて生成し、追跡します。`P`、`Q`、`R`それぞれの選択の後。 いずれかの時点でそれらがすべて異なる場合は、シーケンスを破棄します。 これは原理的には正しいですが、時間計算量が次のとおりであるため実行不可能です。$O(3^n)$。 たとえ$n = 20$、これは妥当な時間制限を超えています。 

重要な観察は、「3 つの数値すべてがペアごとに区別できない」という主な制約が、各ステップで 3 つすべてが等しいか、2 つが等しく 3 つ目が異なるかのいずれかを意味していることです。 追跡する必要がある州はほんのわずかであり、考えられるすべての数値の組み合わせを追跡する必要はありません。 これにより、一連の状態に対する動的プログラミングが可能になります。 

具体的には、現在の値の複数セットに基づいて状態を定義します。`(P, Q, R)`。 P、Q、R の正確な順序を覚える必要はなく、どの値が等しいかだけを覚えておく必要があります。 XOR を可逆演算と考えると、すべてのシーケンスを列挙することなく、これらの状態間の遷移をカウントできます。 より深い代数的性質は、XOR が結合的で可換であるということです。これにより、「2 つは等しく、1 つは異なる」という状態を、特定の数値ではなく一般的なカテゴリーとして扱うことができます。 

結果として得られる最適なソリューションは、各配列要素を処理するときにカウントを前方に伝播する少数の状態を使用した動的プログラミング アプローチを使用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^n) | お(1) | 遅すぎる |
 | マルチセット状態に対する DP | テスト ケースあたり O(n) | テスト ケースごとに O(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 3 つの変数を初期化します。`all_equal = 1`3 つの変数がすべて等しいシーケンスの数を表し、`two_equal = 0`正確に 2 つが等しいシーケンスを表します。 最初は状態のみ`(0,0,0)`存在するので、`all_equal = 1`。 
2. 各要素を反復処理する`x`配列内で。 それぞれについて`x`、新しい状態を計算します。 

- 以前の状態が`all_equal`、XOR できます`x`3 つの変数のいずれかに代入します。 1 つの変数の XOR を実行すると、確率の等価性が破られ、次のようになります。`two_equal`。 3 つすべてを XOR する (または実質的に何もしない) と、`all_equal`。 注意深く数えてみると、`all_equal_new = all_equal * 1 + two_equal * 1`そして`two_equal_new = all_equal * 3 + two_equal * 2`。 
- オーバーフローを避けるためにモジュラー演算を使用します。 
3. すべての要素を処理すると、答えは次のようになります。`all_equal + two_equal`モジュロ$10^9 + 7$。 

重要な洞察は、実際の数値を追跡する必要がまったくないということです。`P, Q, R`、等価パターンのみ。 各配列要素はルールに従ってシーケンスの数を増やします。これはテスト ケースごとに線形時間で実行できます。 

**機能する理由:** 各ステップで、状態は「ペアごとに区別できない」制約を尊重するすべての有効なシーケンスをキャプチャします。 XOR は可逆であるため、要素の XOR 演算により状態が正しく更新され、有効なシーケンスが省略されたり、無効なシーケンスがカウントされたりすることはありません。 DP の不変条件は、i 個の要素を処理した後、`all_equal`そして`two_equal`そのパターンで終わる有効なシーケンスの数を正確に数えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        all_equal = 1
        two_equal = 0
        
        for x in a:
            new_all_equal = (all_equal + two_equal) % MOD
            new_two_equal = (all_equal * 3 + two_equal * 2) % MOD
            all_equal, two_equal = new_all_equal, new_two_equal
        
        print((all_equal + two_equal) % MOD)

if __name__ == "__main__":
    solve()
```解決策では、`all_equal`そして`two_equal`これらの等価パターンで終わる有効なシーケンスの数を追跡します。 更新式は、非区別条件を維持する XOR 選択肢の組み合わせカウントから派生します。 モジュラー演算により、整数がオーバーフローすることがなくなります。
