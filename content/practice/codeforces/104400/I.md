 ## 問題の理解

 正の整数が与えられます$n$この条件により、 の 10 進展開が確実に行われます。$\frac{1}{n}$小数点以降は単純に繰り返され、終了プレフィックスはありません。 これに加えて、インデックスが与えられます$m$、これは非常に大きくなる可能性があり、$m$の無限繰り返し展開の小数点以下の - 桁目$\frac{1}{n}$。 

概念的には、1をで割ります$n$周期的な 10 進数シーケンスを生成します。 展開全体を計算する代わりに、この繰り返し構造の奥深くにある 1 桁だけを考慮します。これは、実現可能な直接シミュレーションをはるかに超えている可能性があります。 

制約$n \le 10^5$前処理が次のものに依存していることを示唆しています$n$許容されますが、それに比例するものは何でも$m$、次のように大きくすることができます$10^9$、直接シミュレートすることは不可能です。 位置までの数字を 1 つずつ生成するソリューション$m$まで必要になります$10^9$最悪の場合、制限時間をはるかに超えて繰り返しが行われます。 

重要な構造特性は、$n$は 10 と互いに素であり、次の 10 進展開です。$\frac{1}{n}$純粋に周期的です。 これは、数字のシーケンスが一定の周期で繰り返されることを意味し、タスクは周期を見つけてそれにインデックスを付けるだけになります。 

期間が常に一定であると仮定すると、微妙なエッジケースが発生します。$n-1$。 これは、10 が原始根モジュロである場合にのみ当てはまります。$n$保証されていません。 たとえば、$n = 21$、の期間$1/21$ここでの単純な仮定は、存在しない完全なサイクルへの誤ったインデックス付けにつながります。 

剰余を追跡せずに長い除算をシミュレートするときに、別の間違いが発生します。 同じ余りが再び現れると、その時点から数字が繰り返され、このサイクルを検出できないと、大規模な計算では不必要で不可能な計算が発生します。$m$。 

## アプローチ

 長い除算の直接シミュレーションは、剰余 1 から始まり、10 倍を繰り返し、数字を 1 つずつ抽出します。 各ステップで計算します$\text{digit} = \frac{10 \cdot r}{n}$そしてアップデート$r = (10 \cdot r) \bmod n$。 これにより、10 進展開が正しく生成されます。 ただし、以来、$m$まで可能です$10^9$、生成$m$数字は不可能です。 

重要な観察は、プロセスが剰余モジュロに対する決定論的な状態マシンであるということです。$n$。 あるのは$n$残りの可能性があるため、シーケンスは最終的に繰り返され、サイクルを形成する必要があります。 なぜなら$n$が 10 と互いに素である場合、展開には終了プレフィックスがないため、サイクルは小数点の後の最初の桁からすぐに始まります。 

これは、剰余が繰り返されるまですべての桁を事前計算して保存し、サイクル長のモジュラー演算を使用してクエリに答えることができることを意味します。 サイクルがわかれば、$m$-th 桁は単にインデックスの桁です$(m-1) \bmod L$、 どこ$L$サイクルの長さです。 

以来$n \le 10^5$、せいぜいシミュレーション$n$剰余が繰り返されると停止するため、steps で十分です。

 ## アルゴリズムのチュートリアル

 余りと桁を追跡しながら、長い除算をシミュレートします。 

1. 剰余を次のように初期化します。$r = 1$。 これは、次の 10 進展開を計算することに対応します。$1/n$。 
2. 生成順に数字を格納する配列を維持します。 
3. シーケンス内の残りの部分から最初の位置までマップを維持します。 
4. 各ステップで、現在の残りが以前に確認されている場合は停止します。 これは、繰り返しサイクルの開始を示します。 
5. それ以外の場合は、残りの位置を記録します。 
6. 余りを 10 で乗算し、次の桁を抽出します。$\text{digit} = (10r) // n$。 
7. 残りを次のように更新します。$(10r) \bmod n$そして続けます。 
8. 前処理後、回答インデックスを次のように計算します。$(m-1) \bmod L$、 どこ$L$生成される桁数です。 
9. そのインデックスの数字を出力します。 

これが機能する理由は、剰余が長い除算の状態を一意に定義するためです。 剰余が繰り返されると、後続のすべての数字が同じように繰り返されるため、その時点からシーケンスは周期的になります。 この問題では 2 または 5 の係数が保証されていないため、プレピリオドはありません。つまり、繰り返しはすぐに始まる完全なサイクルを形成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

seen = {}
digits = []

r = 1 % n

while r not in seen:
    seen[r] = len(digits)
    r *= 10
    digit = r // n
    r %= n
    digits.append(digit)

L = len(digits)

idx = (m - 1) % L
print(digits[idx])
```この実装は、long 除算を正確に反映しています。 残りの追跡`seen`プロセスが繰り返し開始されたらすぐに停止するようにします。 数字の抽出では整数の除算が使用されますが、剰余の更新では次のステップで状態の一貫性が維持されます。 最初の桁が次の値に対応するため、最終的なインデックス作成ではゼロベースの調整が使用されます。$m = 1$。 

よくある落とし穴は、初期剰余モジュロを減らすのを忘れることです。$n$。 この問題では常に 1 ですが、次のように書きます。`1 % n`ロジックを堅牢にします。 もう 1 つの微妙な問題は、マッピング時のインデックス作成が 1 つずつずれていることです。$m$数字配列へ。 正しい変換は常に$m-1$。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    n, m = map(int, input().split())

    seen = {}
    digits = []

    r = 1 % n

    while r not in seen:
        seen[r] = len(digits)
        r *= 10
        digits.append(r // n)
        r %= n

    L = len(digits)
    print(digits[(m - 1) % L])

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out.strip()

assert run("3 5") == "3", "sample 1"
assert run("7 5") == "5", "sample 2"

assert run("1 100") == "0", "n = 1 edge"
assert run("2 10") == "0", "should always 0 (though invalid per constraint)"
assert run("9 8") == "8", "cycle length 1 digit 1"
assert run("11 1") == "0", "first digit case check"

 ## 特殊なケース

 のために$n = 3$、1 桁を生成した後、剰余がすぐに繰り返されます。 から始まる$r = 1$、計算します$10 \to 3$、また余りが1になります。 アルゴリズムはサイクルを記録します`[3]`。 あらゆるクエリ$m$インデックスにマップします$(m-1) \bmod 1 = 0$、正しく 3 を返します。 

のために$n = 7$、残りのシーケンスは 6 ステップ後にのみ循環します。 このアルゴリズムは、剰余 1 での繰り返しを再度検出する前に 6 桁を保存します。 モジュロインデックスにより、非常に大規模な場合でも、$m$、再計算することなく、この 6 つの長さのサイクルに正しくラップされます。 

のために$n = 11$、展開は数字 0 から始まります。$10/11 = 0.\ldots$。 数字の抽出では剰余の更新の前に整数の除算が使用されるため、アルゴリズムは先頭のゼロを正しくキャプチャします。 サイクルは依然として剰余遷移から純粋にキャプチャされ、初期の桁がゼロの場合でも正確性が保証されます。
