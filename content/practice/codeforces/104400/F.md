 ## 解決策
 ## 問題の理解

 私たちは石積みの列を与えられました。 プレイヤーはアリスから順番に順番を変えていきます。 1 回のターンで、プレイヤーは次のシーケンスを実行します。$k$連続移動。 各移動は、現在の左端の空ではない山から少なくとも 1 つの石を取り除きます。 同じターン内であっても、山が空になるとその山は消え、すぐに次の山が左端の山になります。 

いずれかの時点ですべての石が取り除かれ、何も行動することが残っていないプレイヤーが次の手を実行した場合、そのプレイヤーは即座に負けとなるため、対戦相手が勝ちます。 両方のプレイヤーが最適なプレーをします。 

重要な難点は、「ターン」が 1 つのアクションではなく、最大で 1 つのアクションのバッチであることです。$k$連続的な除去を行うと、そのようなバッチ内でゲームが終了する可能性があります。 

入力は複数のテスト ケースを与え、それぞれが杭の数を記述します。$n$、バッチサイズ$k$、およびパイルのサイズ$a_i$。 最適なプレイの下でアリスとボブのどちらが勝つかを判断する必要があります。 

制約により、最大で$10^5$テストケースと杭の合計サイズが十分に大きいため、個々の石のレベルでのシミュレーションは不可能です。 潜在的な操作の数が膨大になる可能性があるため、各動きをシミュレートするだけでも遅すぎます。$\sum a_i$までです$10^{14}$最悪の場合の推論で。 これにより、プレイをシミュレートするのではなく、ゲームを構造的に不変なものに折りたたむ必要があります。 

微妙なエッジケースは、1 つの手で複数の石を削除すると、その後の手の数が変化するという事実から生じます。 たとえば、山のサイズが 3 の場合、プレイヤーは 1 回の移動で 3 つすべてを削除することも、複数の移動に分割して削除することもできます。 これらの選択により、ゲーム内の合計の手数が変化し、最終的に誰が最終的に手を打つかが変わります。 

杭のサイズが相対的に大きい場合、別の自明ではない状況が発生します。$k$プレイヤーは 1 回のバッチ内でパイルを完成できる場合とできない場合があるため、$k$移動し、ターン境界の制御方法が進化します。 

## アプローチ

 ブルートフォースのアイデアは単純です。ゲームを正確にシミュレートします。 現在の山へのポインタを維持し、選択した数の石を減算して各動きをシミュレートし、毎ターンを切り替えます。$k$動く。 各手ごとに正の数の石を削除できるため、完全な検索では、各ステップで削除する石の数を決定する必要があります。 これにより、線形の移動数に加えて指数関数的な分岐係数が作成され、入力が小さい場合でもこのアプローチは実行不可能になります。 

重要な簡素化は、最適なプレイでは、ターン境界に影響を与えない限り、複数の動きにパイルを分割する必要がないという観察から来ています。 各手は依然として「左端の山を消費する」だけであり、実際の構造は石ではなく、固定予算を消費しながらプレイヤーが何回山の変更を強制するかです。$k$ターンごとに移動します。 

石の観点から考えるのではなく、最適なプレイの下で各パイルがどれだけの「効果的な移動セグメント」に貢献するかに圧縮します。 それぞれのサイズの山$a_i$貢献する$\lceil a_i / k \rceil$セグメントは 1 回転以内なので、$k$プレイヤーが完全に消費できるのは最大でも$k$ターン境界が再び関連するようになる前の単一石の作業単位。 これにより、ゲームはターン制約の下で交互に消費される単純なセグメントのシーケンスに変わり、勝者はそのようなセグメントの総数の同等性のみに依存します。

 ## アルゴリズムのチュートリアル

 ### 1. 各パイルを有効なセグメントに圧縮します。 

すべての山ごとに$a_i$、それを使い果たすために必要な完全な「k-move チャンク」の数を計算します。 これは$\lceil a_i / k \rceil$。 アイデアは、各チャンクが、ターンがブロック単位で測定されるという制約の下で、パイルが継続的な消費を維持できる時間を表すということです。$k$動く。 

これにより、正確なストーンごとのプレーへの依存がなくなり、大まかではあるが十分な進歩の尺度に置き換えられます。 

### 2. パイル全体のすべてのセグメントを合計する

 しましょう$S = \sum \lceil a_i / k \rceil$。 これは、最適な圧縮下ですべてのパイルを空にするために必要な有効消費フェーズの合計数を表します。 

このレベルでは、ゲームはこれらのセグメントで完全に直線的であるため、山の順序はもう重要ではありません。 

### 3. のパリティから勝者を決定します。$S$各セグメントは固定ターン構造で制御が交互に切り替わる強制的なプレイ進行に対応するため、最終セグメントを実行するプレイヤーは次の条件によって決定されます。$S$交互のアリス側またはボブ側に当てはまります。 アリスが先にスタートするので、次の場合はアリスが勝ちます。$S$奇数である場合、ボブが勝ちます。 

### なぜ効果があるのか

 各移動は常に左端の空ではない山から消費を進め、最適な戦略は最終的には最大 2 個のブロックを繰り返し消費するように動作します。$k$ターン境界前の最小限の作業単位が重要です。 変革$\lceil a_i / k \rceil$各パイルが適用するブロックの数を正確に把握します。 

圧縮されると、ゲームは内部の柔軟性をすべて失います。プレーヤーは、セグメント全体の同等性を超えて最終状態に影響を与える意味のある分岐の選択肢を持てなくなります。 不変条件は、すべての有効な再生シーケンスが正確に消費されることです。$S$抽象ユニットは厳密に交互に配置されるため、勝者はどのプレイヤーが最後のユニットを実行するかによって完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        s = 0
        for x in a:
            s += (x + k - 1) // k
        
        if s % 2 == 1:
            print("Alice")
        else:
            print("Bob")

if __name__ == "__main__":
    solve()
```実装は圧縮ステップの直後に行われます。 唯一の微妙な点は、次のように実装された整数の上限除算を使用することです。$(x + k - 1) // k$、浮動小数点エラーを回避し、大きなサイズのエラーを処理します。$a_i$安全に。 

各テスト ケースは線形時間で独立して処理され、動きのシミュレーションは必要ありません。

 ## 特殊なケース

 主なエッジケースは、パイルのサイズが以下よりも小さい場合です。$k$。 その状況では、杭はそのサイズに関係なく、正確に 1 つのセグメントに寄与します。$\lceil a_i / k \rceil = 1$。 アルゴリズムはそのようなパイルを原子単位として扱いますが、パイル内には追加の内部構造が存在しないため、最終的なパリティは結果を正確に反映します。 

すべての杭がそれよりはるかに大きい場合、別のエッジ ケースが発生します。$k$。 ここでは、各パイルが複数のセグメントに寄与し、ゲームは強制消費フェーズが長く交互に繰り返されることになります。 計算は依然としてセグメント全体のパリティまできれいに減少し、中間状態は分布に依存しません。 

最後に、いつ$k = 1$、すべてのパイルが正確に寄与します$a_i$セグメント。 ゲームは石の合計に対する純粋なパリティ チェックに縮小されます。これは公式によって自然に処理されます。$\lceil a_i / 1 \rceil = a_i$。
