 ## 解決策
 ## 問題の理解

 プログラミング コンテストのログが与えられ、ICPC のようなルールに基づいて参加者の最終ランキングを再構築し、メダル セパレーターを使用してランキングを印刷する必要があります。 

各参加者は、最大 20 個の問題にわたって一連の提出を行います。 すべての送信にはタイムスタンプと結果があります。 各問題に対して最も早く成功した提出のみが採点の対象となります。 問題が決して解決されなければ、それは何の役にも立ちません。 

解決済みの問題の場合、スコア寄与は、コンテストの開始から最初に受理された提出物までの分数に、同じ問題に対する以前の CE 以外の不正確な提出物ごとに 20 分を加えたものとなります。 コンパイル エラーは特別であり、他のすべての間違った結果にはペナルティが追加されませんが、ペナルティが追加されません。 

参加者は、最初に解決した問題の数によってランク付けされ、次に合計ペナルティによって、最後に辞書編集上のユーザー名の順序によってランク付けされます。 

ランキング後は、単にリストを印刷するだけではありません。 GOLD、SILVER、BRONZE というラベルの付いた 3 本の分割線を正確に挿入する必要があります。 これらの行は、ランキングの連続したセグメントを定義します。 一番上のセグメントは金メダリストで、次に銀、銅、そして最後に非メダリストが続きます。 

メダリストの数は、参加者全体に占める割合によって制限されます。 少なくとも 10 パーセントは金、少なくとも 30 パーセントは金または銀の組み合わせ、少なくとも 60 パーセントは金、銀、または青銅の組み合わせでなければなりません。 カット位置を選択する有効な方法の中で、最初にゴールド、次にシルバー、次にブロンズを最小限に抑えることを好みます。 

この制約により、完全なシミュレーションが必要であることは明らかですが、m は最大 2000、t は最大 200000 であるため、高度に最適化された作業は不要です。複雑さの大半を占めるのは送信の並べ替えですが、これは完全に管理可能です。 

実際にはいくつかの落とし穴が重要です。 まず、送信は順序付けされていないため、入力順に処理すると、間違った試行は時系列で最初の AC の前にのみカウントされる必要があるため、ペナルティのカウントを誤る可能性があります。 第二に、CE の提出はペナルティに寄与しないため、誤って含めてしまう可能性があります。 第三に、フロア分割を使用して時間を慎重に分に変換する必要があります。 最後に、メダルのセグメント化は、グループ サイズの辞書編集的な最小化によって一意に決定されます。これは貪欲なしきい値問題として誤解されやすいですが、制約が正しく解釈されれば実際には決定的です。 

## アプローチ

 ブルート フォース シミュレーションでは、各提出物を参加者ごと、問題ごとに処理しようとし、以前の提出物を繰り返しスキャンして、AC が最初のものであるかどうか、およびその前に何回間違った試行が発生したかを判断します。 これにより、参加者と問題のペアごとにログの並べ替えや再スキャンが繰り返し行われるようになり、最悪の場合、およそ O(m · t²) の動作が発生する可能性があります。 参加者は 2,000 人、投稿数は 200,000 件と、これは必要な数をはるかに超えています。 

重要な観察は、各参加者と問題のペアが独立して進化し、最も初期の AC のみが重要であるということです。 すべての送信を一度時間順に並べ替えると、それらを時系列で処理し、段階的に状態を維持できます。 各ペアは、すでに解決されているかどうか、および解決前にペナルティ関連の間違った送信が何回発生したかを保存します。 これにより、システム全体が、ソートされた送信に対する単一のリニア スキャンに削減されます。 

スコアが計算されると、ランキングは参加者を固定キーで並べ替えるだけです。 メダルの割り当ては決定論的なパーティションの問題になります。パーセンテージ制約を満たす最小の有効なプレフィックス サイズを計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 繰り返しスキャンシミュレーション | O(m · t²) | O(mn) | 遅すぎる |
 | ソート + シングルパス シミュレーション | O(t log t + t + m log m) | O(mn) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての提出物を解析し、タイムスタンプをコンテスト時間の開始からの合計秒数に変換します。 これにより、入力順序に関係なく、正しい時系列順に並べることができます。 
2. 提出物をタイムスタンプで並べ替えます。 タイムスタンプが等しい場合、参加者ごとに同じ秒での送信が繰り返し送信されても​​競合することはないため、タイムスタンプ間の順序は正確さに影響しません。 
3. 各参加者および各問題について、その問題がすでに解決されているかどうか、および解決する前にペナルティにつながる間違った提出が何回発生したかで構成される状態を維持します。 
4. 提出物を時系列にスキャンします。 各提出物について、その参加者の問題がすでに解決されている場合は無視してください。 
5. 提出物がコンパイルエラーである場合は、ペナルティには影響しないため、完全にスキップしてください。 
6. 提出物が間違った答え、時間制限、メモリ制限、または実行時エラーの場合、その参加者と問題のペアに対する間違った試行カウンタをインクリメントします。 
7. 提出が受け入れられ、問題がまだ解決されていない場合は、解決済みとしてマークします。 解決時間を分単位で記録し、以前にカウントした誤った試行回数の 20 倍を加えたものとしてペナルティを計算します。 
8. すべての提出物を処理した後、参加者ごとに結果を集計します。解決された問題をカウントし、解決されたすべての問題に対するペナルティを合計します。 
9. 解決数の減少、ペナルティの増加、辞書編集上のユーザー名の順に参加者を並べ替えます。 
10. メダルのカットサイズを計算します。 g が少なくとも ceil(0.1m) となるゴールドの最小参加者数とします。 s を、g + s が少なくとも ceil(0.3m) となるような最小の数としましょう。 b を g + s + b が少なくとも ceil(0.6m) となるような最小の数とする。 これらの選択により、辞書編集上のメダル割り当てが最小限に抑えられます。 
11. 参加者を順番に出力します。g 番目の後に GOLD、次の s の後に SILVER、次の b の後に BRONZE を挿入します。 

### なぜ効果があるのか

 ソートされた順序で送信を処理すると、問題に対する最初の AC が発生したときに、ペナルティに影響を与える以前のすべての送信がすでにカウントされていることが保証されます。 これにより、解決の瞬間に誤試行カウンターが正確になります。 以前のイベントを再度検討することはないため、各提出物は 1 回処理され、各問題は参加者ごとに 1 回最終処理され、正確性と効率性が同時に維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def to_seconds(t):
    h = int(t[0:2])
    m = int(t[3:5])
    s = int(t[6:8])
    return h * 3600 + m * 60 + s

def main():
    n, m, t = map(int, input().split())
    users = []
    idx = {}
    for i in range(m):
        name = input().strip()
        users.append(name)
        idx[name] = i

    subs = []
    for _ in range(t):
        u, tm, prob, st = input().split()
        subs.append((to_seconds(tm), u, ord(prob) - ord('A'), st))

    subs.sort(key=lambda x: x[0])

    solved = [[False] * n for _ in range(m)]
    wrong = [[0] * n for _ in range(m)]
    solve_time = [[0] * n for _ in range(m)]

    for time, u, p, st in subs:
        i = idx[u]
        if solved[i][p]:
            continue
        if st == "CE":
            continue
        if st == "AC":
            solved[i][p] = True
            solve_time[i][p] = time
        else:
            wrong[i][p] += 1

    res = []
    for i in range(m):
        cnt = 0
        pen = 0
        for p in range(n):
            if solved[i][p]:
                cnt += 1
                pen += solve_time[i][p] // 60 + wrong[i][p] * 20
        res.append(( -cnt, pen, users[i], cnt))

    res.sort()

    def ceil_div(x, y):
        return (x + y - 1) // y

    need_g = ceil_div(m, 10)
    need_s = ceil_div(3 * m, 10)
    need_b = ceil_div(6 * m, 10)

    g = need_g
    s = max(0, need_s - g)
    b = max(0, need_b - g - s)

    out = []
    gold_end = g
    silver_end = g + s
    bronze_end = g + s + b

    for i, (_, __, name, cnt) in enumerate(res):
        if i == gold_end:
            out.append("GOLD")
        if i == silver_end:
            out.append("SILVER")
        if i == bronze_end:
            out.append("BRONZE")
        out.append(f"{name} {cnt} {sum(0 for _ in [])}")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装の中核は、並べ替えられた提出物を時系列にスイープすることです。 2 つの 2D 配列により、送信ごとに状態が一定時間更新されるため、履歴を再スキャンする必要がなくなります。 

ランキング ステップでは、すべての順序付けロジックが 1 つのタプルにパックされ、負の解決済みカウントによって降順が保証されます。 ペナルティとユーザー名は自然に関係を解決します。 

メダルの境界は比例制約から直接計算され、ソートされたランキングのプレフィックスカット位置に変換されます。 

## 実用的な例

 3 人のユーザーと 2 つの問題がある単純化されたケースを考えてみましょう。 提出物を分類した結果、アリスは間違った試行をすることなく両方の問題を早期に解決し、ボブは数回間違った試行を行った後に 1 つの問題を解決し、キャロルは何も解決しなかったことが示されたとします。 

| イベント | アリスA | アリスB | ボブA | ボブB | キャロル・A キャロル・B
 | --- | --- | --- | --- | --- | --- | --- |
 | WA/その他 | 0 | 0 | 2 | 0 | 0 | 0 |
 | 交流時間 | 10分 | 15分 | 30分 | - | - | - |

 処理後、アリスは 2 件解決し、25 ペナルティを持ち、ボブは 1 件解決し、70 ペナルティを持ち、キャロルは 0 件解決し、0 ペナルティを持ちます。 

ソート順はアリス、ボブ、キャロルになります。 m = 3 の場合、金は少なくとも 1 つ、銀は 30 パーセントに達するために少なくとも 1 つの追加が必要で、ブロンズは合計 60 パーセントに達するために少なくとも 2 つ必要となり、1、1、1 に分割されます。 

このトレースは、ペナルティが AC 前の間違った送信にのみ依存することと、ランキングが AC 後のノイズをすべて無視する方法を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t log t + m · n) | 送信のソートが優先され、次に単一のスイープと集計が行われます。 
| スペース | O(mn) | 問題の状態ごとに参加者ごとに保存 |

 この制限では、最大 200,000 件の送信と 2,000 人の参加者が許可されるため、並べ替えと線形処理は制約内に快適に収まります。
