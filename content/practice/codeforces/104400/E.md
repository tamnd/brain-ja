 ## 解決策
 ## 問題の理解

 私たちは石積みの列を与えられました。 ゲームはアリスから順番に交互に進みます。 各ターンで、現在のプレイヤーは石がまだ含まれている一番左の山にのみ注目し、そこから少なくとも 1 つの石を取り除きます。 これは簡単バージョンなので、$k = 1$、ターンはそのような除去 1 つだけで構成され、選択した山が空になった後、次のターンの右にある次の山でプレイが続行されます。 

すべての山が空になるとゲームは終了します。 石がなくなったときに移動しようとしているプレイヤーには正当な手はなく、すぐに負けとなるため、前のプレイヤーが勝者となります。 

各山には任意の数の石がありますが、プレイヤーは制約された方法で複数のターンにわたって山を分割することを強制されることはありません。 「少なくとも 1 つの任意の数」を削除することにはすべての石を取得することが含まれるため、必要に応じてどの手でも残りの山全体を削除することができます。 

制約は大きく、最大で$10^5$テスト ケースとテスト全体の合計入力サイズは最大$10^5$。 これにより、テスト ケースごとに一定以上の作業を行うシミュレーションが即座に除外されます。 たとえ$O(n)$テストごとのアプローチは、慎重に管理しないと全体として遅すぎる可能性がありますが、ここでは構造が問題をケースごとの定数時間推論に崩壊させることがわかります。 

素朴なアプローチをしばしば混乱させる微妙なエッジケースは、杭のサイズの役割です。 石の数が重要であると考える人もいるかもしれませんが、各山は 1 回の移動で空にすることができるため、実際の値はシーケンスの長さに影響しません。 

たとえば、次の 1 つのテスト ケースを考えてみましょう。 

入力:```
n = 1
a = [1000000000]
```山は巨大ですが、アリスは 1 回の動きですべての石を奪うことができ、ボブは何も動かず、すぐに負けてしまいます。 したがって、結果は、山のサイズではなく、山の数が奇数か偶数かによって完全に決まります。 

もう 1 つの誤解を招くケースは次のとおりです。 

入力:```
n = 2
a = [1, 100]
```2 番目の山は大きいですが、ゲームは依然として正確に 2 つの動きで構成されます (各山に 1 つずつ)。 

## アプローチ

 ブルートフォース シミュレーションでは、それぞれの動きを明示的にモデル化します。 現在の山へのポインタを維持し、そこから正の数を繰り返し減算し、各石の除去をシミュレートする可能性があります。 ただし、各パイルには最大で$10^9$石の場合、この解釈は次のことを示唆します。$10^9$最悪の場合の山ごとのアクションですが、これは明らかに実行不可能です。 

重要な観察は、最適なプレイは常に現在のパイルを即座に空にするということです。 除去を複数のターンに分割する方法に関係なく、対戦相手は常に同じ状況に直面することになるため、石を残すことに戦略的な利点はありません。 すべての山は、ゲームの長さに正確に 1 つの動きを効果的に貢献します。 

これにより、ゲーム全体が固定されたシーケンスに短縮されます。各パイルは 1 つの強制的な動きに対応し、プレイヤーは単に一連の長さにわたって交互に動きます。$n$。 残る唯一の問題は、誰が最後の動きをするかということだ。 

したがって、このゲームは山の数に関する単純なパリティ チェックと同等です。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$T$。 各テスト ケース間で状態が伝達されないため、各テスト ケースは独立しています。 
2. 各テスト ケースについて、次の内容を読んでください。$n$、杭の数。 山の実際の値は最終結果とは無関係であるため、読み取っても無視しても問題ありません。 
3. かどうかのみに基づいて勝者を決定します。$n$奇数か偶数です。 もし$n$それは奇妙で、アリスは最後の行動をとります。 もし$n$が互角の場合、ボブは最後の動きをします。 
4. 次の場合は「アリス」を出力します。$n$奇数である場合、「Bob」を出力します。 

### なぜ効果があるのか

 一番左の山をコントロールしているプレイヤーはいつでも 1 回のアクションですべての石を取り除くことができるため、各山はゲームに 1 つの手だけを貢献します。 パイルが空になると、そのパイルは再び場に現れることはなく、次のターンに次のパイルがアクティブになります。 したがって、ゲームは常に正確に続きます$n$パイルのサイズや分布とは無関係に移動します。 プレイヤーはアリスから順番に手を交互に動かしていくため、勝者は以下のパリティによってのみ決定されます。$n$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        arr = list(map(int, input().split()))
        
        if n % 2 == 1:
            print("Alice")
        else:
            print("Bob")

if __name__ == "__main__":
    solve()
```このソリューションは各テスト ケースを読み取り、すぐにパリティ チェックを実行します。 配列は、入力形式の制約を満たすためにのみ使用されます。 その値は計算には影響しません。 唯一の重要な決定は以下に基づいています$n$したがって、アルゴリズムは入力サイズに対して線形時間で実行されますが、読み取りを超えると要素ごとに一定の作業が行われます。 

ここでよくある実装上の間違いは、除去をシミュレートしたり、個々の石の数について推論しようとしたりすることです。 これにより、結果は変わりませんが、不必要な複雑さが生じます。
