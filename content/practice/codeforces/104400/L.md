 ## 解決策
 ## 問題の理解

 1日の長さのタイムスケジュールが与えられています`n`、毎分 1 台のバスが到着し、各到着にはバス番号がラベル付けされています。 したがって、入力配列は識別子のシーケンスであり、i 番目の値はどのバスが i 分に到着するかを示します。 

その後、受け取ります`q`クエリ。 各クエリは特定のバス番号を要求します`x`そしてポジション`y`、y 番目にバスが発生した瞬間を報告する必要があります。`x`happens in the timetable. そのバスが次の数より少ない場合は、`y`何度も戻ります`-1`。 

中心的な操作は時間そのものではなく、フィルターされたサブシーケンス内の出現のインデックス付けに関するものです。 概念的には、バス番号ごとに、それが表示されるすべての位置のリストを考慮します。 

制約は次のとおりです。`n, q ≤ 100000`。 クエリごとに直接スキャンすると遅すぎます。 各クエリが配列全体をスキャンすると、次の結果が得られます。`O(nq)`これは最悪の場合でも 10¹⁰ 回の操作に相当し、Python で許容される 2 秒をはるかに超えています。 

より微妙な制約は、バス番号が 10⁹ まで大きくなるため、バス番号を直接の配列インデックスとして使用できないことです。 どのソリューションもハッシュ化または座標圧縮に依存する必要があります。 

ここではいくつかの特殊なケースが重要です。 バスが 1 回だけ出現する場合、2 回目の出現を求めるクエリは返されるはずです。`-1`。 すべての値が同一の場合、大きい値をクエリします。`y`値は頻繁に失敗します。 バスがまったく表示されない場合、バスに対するすべてのクエリはすぐに実行されます。`-1`。 これらのケースでは、リストの長さをチェックせずに存在を前提としたソリューションが壊れます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに`(x, y)`、タイムテーブル全体をスキャンし、次の発生をカウントします。`x`y番目の試合に到達するまで。 ヒットしたらインデックスを返します。 最初に配列を終了した場合は、戻り値が返されます。`-1`。 

これは問題の定義を直接シミュレートするため、これは正しいです。 問題はコストです。 各クエリのコスト`O(n)`時間を越えて`q`まで実行するクエリ`n × q`比較。 どちらも最大 100,000 になると、これは大きすぎます。 

重要な点は、時刻表が変更されていないことです。 すべてのクエリは同じ固定シーケンスについて質問します。 つまり、すべての出現を一度に前処理して、バス番号ごとにそれが出現する位置のリストを保存できるということです。 その後、各クエリは単純な配列検索 (リストの y 番目の要素 (存在する場合)) になります。 

これにより、問題はスキャンの繰り返しからインデックス付きアクセスに変わります。 重い作業はアレイ上の 1 回のパスに移ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | 位置を事前計算する | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各バス番号をそのバス番号が表示される位置のリストにマッピングする辞書を作成します。 この構造が必要なのは、バス番号が大きくてまばらなため、配列のインデックス付けが不可能であるためです。 
2. 時刻表を左から右に見てください。 分 i ごとに、その位置のバス番号に対応するリストに i を追加します。 これにより、正確な出現順序が構築されます。クエリは時系列順に依存するため、これが必要です。 
3. 前処理の後、各バス番号には発生インデックスのソートされたリストが含まれます。左から右に挿入したため、自然に昇順になります。 
4. 各クエリについて`(x, y)`、どうかを確認してください`x`辞書に存在します。 そうでない場合は、すぐに出力します`-1`バスが一向に現れな​​いからです。 
5. 存在する場合は、リストに少なくとも`y`要素。 そうでない場合は出力`-1`要求されたオカレンスが存在しないためです。 
6. それ以外の場合はインデックスの要素を出力します`y-1`リストにあります。 これは、時間順で y 番目の出現に直接対応します。 

このインデックス付けが機能する理由は、前処理中に正確な時系列順序が保存されているためで、リストの順序は時間の順序と同等です。 

### なぜ効果があるのか

 このアルゴリズムは、各バス番号に対する不変条件に依存します。`x`、その保存されたリストにはすべてのインデックスが含まれます。`x`厳密に昇順で表示されます。 すべてのクエリは時間内で y 番目の出現を要求するため、これは順序付きリストの y 番目の要素に相当します。 並べ替えや再計算はまったく必要ないため、各クエリは、事前に計算された正しい構造に対する定数時間の検索に減ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    pos = {}

    for i, v in enumerate(a, start=1):
        if v not in pos:
            pos[v] = []
        pos[v].append(i)

    out = []

    for _ in range(q):
        x, y = map(int, input().split())
        if x not in pos:
            out.append("-1")
        else:
            lst = pos[x]
            if y <= 0 or y > len(lst):
                out.append("-1")
            else:
                out.append(str(lst[y - 1]))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```前処理ループは、バス番号をキーとしたハッシュ マップを構築し、すべての出現インデックスを保存します。 の使用`enumerate(..., start=1)`問題の分のインデックス付けと一致するように、1 から始まる位置を確実に保存します。 

各クエリは、辞書のメンバーシップとリストの境界をチェックすることによって一定時間で処理されます。 境界条件`y > len(lst)`これを怠ると、範囲外のアクセスや周波数に関する誤った仮定につながるため、これは不可欠です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q) | 位置リストを構築するための 1 回のパス、その後クエリごとの定数時間 |
 | スペース | O(n) | 各インデックスはリストに 1 回だけ保存されます。 

前処理とクエリ処理の両方が入力サイズに比例して拡張されるため、このソリューションは制限内に問題なく収まります。 と`n, q ≤ 100000`、これは一般的な時間制約内で十分に維持されます。

 ## 特殊なケース

 決して表示されないバスは、辞書のメンバーシップによって完全に処理されます。 いつ`x`が存在しない場合、検索はすぐに失敗し、返されます。`-1`リストには触れずに。 これにより、偶発的な KeyError や誤ったデフォルトの仮定が回避されます。 

バスの出現回数が要求よりも少ない場合は、保存されたリストの長さのチェックに依存します。 たとえば、次の場合`pos[x] = [2, 5]`そしてクエリは次のように要求します`y = 3`、条件`y > len(pos[x])`トリガー、返す`-1`。 このチェックを入れずにアクセスすると、`pos[x][2]`クラッシュするだろう。 

大きい`y`値は反復を必要としないため安全です。 このアルゴリズムでは、クエリ中に出現回数がカウントされることはありません。`y`値は、1 回の比較を超えてパフォーマンスや正確性に影響を与えることはありません。
