 ## 問題の理解

 次の整数の順列を構築するように求められます。$1$に$n$各要素の値とその位置の間の絶対差の合計が指定された数値と等しくなるようにする$k$。 正式に言うと、$p$我々が望む順列です$\sum_{i=1}^{n} |p_i - i| = k$。 入力は複数のテスト ケースを提供し、それぞれに$n$そして$k$, そして、正確な合計を達成する順列を生成するか、そのような順列が存在しないことを報告する必要があります。 

最初の洞察は制約から得られます。 と$n$と同じくらい大きい$2 \cdot 10^5$そして最大まで$10^4$テスト ケースでは、二次複雑度を持つアルゴリズムは直ちに実行不可能になります。 テストケースごとに線形または線形算術的なアプローチが必要です。 可能な最大のマンハッタン値は、順列を逆にすると発生します。$n = 5$、$[5,4,3,2,1]$与える$|5-1| + |4-2| + |3-3| + |2-4| + |1-5| = 4+2+0+2+4 = 12$。 これは、達成可能なマンハッタン値の範囲が$[0, n(n-1)/2]$、これにより、不可能なケースを迅速に検出できます。 

エッジケースが現れるのは、$k$非常に小さい (0) か、非常に大きい (最初の合計を超える)$n-1$整数)。 たとえば、次の場合$n=1$、 のみ$k=0$可能です。 のために$n=3$、リクエストされた$k=4$で実現可能です$[3,1,2]$、 しかし$k=5$ということは不可能です。なぜなら、その合計が得られる順列がないからです。 すべての順列を試す単純なアプローチは、大規模な場合には何も言わずに失敗します。$n$時間の制約があるため、建設的で直接的な方法を見つける必要があります。 

## アプローチ

 ブルートフォースの解決策は簡単です。すべてを列挙します。$n!$の順列$1$に$n$、それぞれのマンハッタン値を計算し、一致するかどうかを確認します。$k$。 小さいのは正しいですが、$n$、これは指数関数的に遅くなります。 のために$n = 10$、 がある$3.6 \cdot 10^6$順列; のために$n = 20$、カウントが超えています$2 \cdot 10^{18}$。 明らかに、これは不可能です。 

重要な洞察は、より大きな数値を自然な位置から遠くに配置すると、絶対的な差が局所的に最大化されるという観察から得られます。 たとえば、最初と最後の要素を交換すると、それらの位置のマンハッタン値の可能な限り最大の増分が生成されます。 この観察は、貪欲な戦略を示唆しています。つまり、左から右へ順列を構築し、各位置で残りの最小数 (寄与度が最小) を配置するか、残りの最大数 (寄与度が最大) を配置するかを決定できます。 各ステップで、残りのマンハッタン値が許容する場合は利用可能な最大の数値を選択し、そうでない場合は最小の数値を選択します。 これにより、あらゆる実現可能性を達成できることが保証されます$k$線形時間で。 

つまり、総当たり攻撃は徹底的なチェックによって正確性を保証するため機能しますが、階乗増加により失敗します。 利用可能な数値の範囲が判明すると、各数値の寄与が他の数値から独立していることを認識すると、貪欲な構築が可能になります。 私たちは、困難な探索を、残りの情報に基づいた一連のローカルな決定に削減します。$k$、これは線形です$n$。

 ## アルゴリズムのチュートリアル

 1. 長さとして可能なマンハッタンの最大値を計算します。$n$、つまり$n(n-1)/2$。 もし$k$これを超える場合は、どの並べ替えも達成できないため、すぐに「いいえ」を返します。 
2. 2 つのポインターを初期化します。`low = 1`そして`high = n`、未使用の最小値と最大値、および空の配列を表します。`perm`。 
3. 位置を反復処理する$i = 1$に$n$。 各位置での残りのマンハッタン値への最大寄与は次のとおりです。`high - i`私たちが置くなら`high`この位置で。 
4. もし`k >= high - i`、追加`high`に`perm`、デクリメント`k`による`high - i`、およびデクリメント`high`。 これは、マンハッタンの値をできるだけ多く吸収するために最大の数値を使用します。 
5. それ以外の場合は追加します`low`に`perm`、増分`low`最小の数字を配置すると、マンハッタンの値への寄与が最小限に抑えられ、残りの位置を調整する余地が残ります。 
6. すべてのポジションが埋まるまで続けます。 最後に、もし`k`はゼロではありません。何か問題が発生しました。 それ以外の場合は、「Yes」を返し、構築された`perm`。 

なぜ機能するのか: 各ステップで、残りのターゲットをオーバーシュートすることなくマンハッタンの寄与を最大化または最小化します。`k`。 不変条件は、残りの`k`残りの数値を使用すれば常に達成可能であり、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        max_k = n * (n - 1) // 2
        if k > max_k:
            print("No")
            continue
        
        perm = []
        low, high = 1, n
        for i in range(1, n + 1):
            if k >= high - i:
                perm.append(high)
                k -= high - i
                high -= 1
            else:
                perm.append(low)
                low += 1
        print("Yes")
        print(" ".join(map(str, perm)))

if __name__ == "__main__":
    solve()
```コードは貪欲アルゴリズムを直接実装します。`max_k`実現可能性をチェックします。`low`そして`high`利用可能な番号を管理します。 各反復では、利用可能な最大の数値を使用して残りのマンハッタンの価値を「費やす」ことができるかどうかに基づいて、どの数値を配置するかを決定します。 の選択`high`または`low`残りを確保します`k`まだ到達可能です。 オフバイワンエラーは慎重に計算することで回避されます`high - i`配置後にポインターを更新します。
