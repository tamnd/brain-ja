 ## 解決策
 ## 問題の理解

 この問題は、メイン配列と、時間の経過とともに保存される追加配列のストリームで機能します。 その後、メイン配列のサブ配列を保存されているすべての配列と比較するように求めるクエリを受け取りますが、比較は位置的なものではありません。 

2 つの配列にまったく同じ値の複数セットが含まれている場合、それらの配列は同等であるとみなされます。 順序は重要ではなく、各値が何回出現するかだけが重要です。 クエリでは、メイン配列のセグメントが与えられたときに、そのセグメントとまったく同じ値の頻度分布を持つ、以前に格納された配列がいくつあるかを尋ねます。 

微妙な点は、セグメント内の値だけでなく、_どこにでも現れるすべての個別の値_に対して等価性が定義されていることです。 つまり、すべての配列は、固定されているが未知の値の世界にわたる周波数ベクトルとして考えることができます。 この問題では、すべての配列にわたる個別の値の数が少ない (100 で制限されている) ため、値をインデックスに安全に圧縮し、周波数ベクトルの観点から推論することができます。 

入力サイズは大きく、最大 200,000 クエリ、挿入される配列の合計長は最大 1,000,000 です。 これにより、クエリごとに周波数を最初から再計算したり、保存された各配列を各クエリに対して直接比較したりすることが直ちに排除されます。 単純な解決策では、頻度マップを作成することによって、保存されたすべての配列と各クエリを比較することになり、コストはおよそ O(Q × 保存された合計サイズ) であり、これでは非常に遅すぎます。 

いくつかの特殊なケースが重要です。 

格納された配列は、別の格納された配列と同じマルチセットを持つ可能性があるため、重複をカウントする必要があります。 クエリ部分配列は、値の構成が同一であっても、順序が異なる場合があります。 たとえば、A = [1,2,1] で、格納された配列が [2,1,1] の場合、位置は異なっていても一致します。 

もう 1 つの微妙なケースは、クエリされた部分配列には決して現れない値が配列に含まれる可能性があることです。 たとえば、格納された配列に部分配列内で 0 回出現する余分な値が含まれている場合でも、等価性に影響を与えるため、同じグローバル周波数空間で一貫して追跡する必要があります。 

## アプローチ

 ブルート フォースのアイデアは簡単です。保存されている配列ごとに周波数マップを計算し、クエリごとに A[l..r] の周波数マップを計算し、2 つのマップを比較します。 それらが正確に一致する場合、カウントされます。 

等価性は純粋に複数集合の等価性であるため、これは正しく機能します。 ただし、格納されている各配列の周波数マップの構築には O(k) のコストがかかり、2 つのマップの比較には O(σ) のコストがかかります。ここで、σ は個別の値の数です。 合計 10^6 個までの要素が挿入され、最大 2×10^5 個のクエリが実行されると、最悪の場合、実行不可能な約 10^11 回の操作が発生します。 

重要な観察は、各配列を順序に依存しない正規表現に変換できることです。 σ ≤ 100 であるため、各配列をサイズ σ のベクトルとして表すことができます。ここで、各座標は特定の値の頻度です。 このベクトルをハッシュ可能なオブジェクトにマッピングする高速な方法があれば、同一のベクトルの出現をカウントできるでしょう。 

残りの課題は、保存された配列に周波数ベクトルを挿入し、A の任意の部分配列に対して高速に計算できるように、周波数ベクトルを効率的に表現する方法です。メイン配列の場合、プレフィックス周波数配列がこれを解決します。値 ID ごとにプレフィックス カウントを維持するため、A[l..r] の周波数は O(σ) 時間で計算されます。 

格納されたすべての配列も σ 次元ベクトルを生成するようになりました。 このベクトルを単一のハッシュにエンコードすると (たとえば、次元にわたるランダム化ハッシュまたは多項式ローリング手法を使用)、同一ベクトルの数をハッシュ マップに保存できます。 次に、各クエリは A[l..r] のベクトルを計算し、それをハッシュし、それに一致する格納された配列の数を取得します。 

これにより、周波数ベクトル署名の維持と同一の署名のカウントの問題が軽減されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(Q × 合計サイズ × σ) | O(合計サイズ) | 遅すぎる |
 | 周波数ベクトル + ハッシュ | O(全体のサイズ × σ + Q × σ) | O(合計サイズ) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. A 全体のすべての個別の値と、挿入されたすべての配列を 0 から σ−1 までのインデックスに圧縮します。 これが必要なのは、周波数ベクトル内の固定位置が必要なためです。 
2. メイン配列 A のプレフィックス頻度配列を構築します。ここで、pref[i][c] には、圧縮値 c が A[1..i] に出現する回数が格納されます。 これにより、値ごとの定数時間の頻度クエリが可能になります。 
3. 挿入された配列の各周波数ベクトルが何回出現するかを格納するハッシュ マップを維持します。 挿入された各配列は σ 長の周波数ベクトルに変換され、単一のハッシュ値にエンコードされます。 
4. セグメント [l, r] に対するタイプ 2 クエリの場合、プレフィックスの差を使用して周波数ベクトルを構築します。値 c ごとに、pref[r][c] − pref[l−1][c] を計算します。 
5. 保存された配列と同じ方法を使用してこの周波数ベクトルをハッシュし、マップからそのカウントを返します。 

重要な設計上の選択は、完全な周波数ベクトルの安定したエンコードを使用することです。 直接タプルは強力なハッシュ サポートを持つ言語で機能しますが、競技プログラミングでは、制約の下では次元ごとにランダム化されたハッシュの方がより堅牢です。 

これが機能する理由: すべての配列は、すべての値の頻度が一致する場合に限り、まったく同じ正規オブジェクトによって表されます。 プレフィックスの減算により、セグメント周波数の正しい再構成が保証されます。 ハッシュは挿入とクエリの間で一貫しているため、マルチセットの等価性はハッシュの等価性となり、カウントは辞書内の頻度カウントに減少します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict

MOD = (1 << 64) - 1

def solve():
    n, q = map(int, input().split())
    A = list(map(int, input().split()))

    values = set(A)
    queries = []
    stored = []

    # read queries first to collect all values
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            k = int(tmp[1])
            arr = list(map(int, input().split()))
            stored.append(arr)
            values.update(arr)
            queries.append((1, arr))
        else:
            l, r = map(int, tmp[1:])
            queries.append((2, l, r))

    # compress values
    comp = {v: i for i, v in enumerate(values)}
    sigma = len(comp)

    # prefix frequency for A
    pref = [[0] * sigma for _ in range(n + 1)]
    for i in range(1, n + 1):
        pref[i] = pref[i - 1].copy()
        pref[i][comp[A[i - 1]]] += 1

    # random-ish hashing base
    base = [91138233 + i * 972663749 for i in range(sigma)]

    def hash_vec(vec):
        h = 0
        for i, v in enumerate(vec):
            if v:
                h = (h + v * base[i]) & MOD
        return h

    freq_map = defaultdict(int)

    ptr = 0
    stored_hashes = []

    # process stored arrays in order
    for t in queries:
        if t[0] == 1:
            arr = t[1]
            vec = [0] * sigma
            for x in arr:
                vec[comp[x]] += 1
            h = hash_vec(vec)
            freq_map[h] += 1
        else:
            l, r = t[1], t[2]
            vec = [0] * sigma
            for i in range(sigma):
                vec[i] = pref[r][i] - pref[l - 1][i]
            h = hash_vec(vec)
            print(freq_map[h])

if __name__ == "__main__":
    solve()
```コードは、周波数ベクトルがコンパクトでインデックス付け可能になるように、値を圧縮することから始まります。 これにより、大きな整数キーを直接処理することが回避されます。 

プレフィックス配列は、各クエリが σ (最大 100) にわたる線形時間で周波数ベクトルを再構築できるように、メイン配列に対して構築されます。 

格納された各配列は周波数ベクトルに変換され、単一の整数にハッシュされます。 そのハッシュは、同一のベクトルがいくつ出現したかを数える辞書のキーになります。 

各クエリはプレフィックスの違いから同じ種類のベクトルを再構築し、同じハッシュを適用することで、辞書内の定数検索を可能にします。 

最もデリケートな部分は、ハッシュの一貫性です。格納された配列とクエリのサブ配列の両方が同一のエンコードを通過する必要があり、そうでない場合、衝突により正確さが失われます。 次元ごとの固定重みを使用することで、決定論的なマッピングが保証されます。 

## 実用的な例

 ### 例 1

 A = [1, 2, 3, 3] について考えてみましょう。 M1 = [2, 3, 1, 3] を挿入し、[1, 4] をクエリするとします。 

| ステップ | ベクトル (1,2,3) | ハッシュアクション | 保存されたカウント |
 | --- | --- | --- | --- |
 | M1 を挿入 | (1,1,2) | 保存されたハッシュ | {h:1} |
 | クエリ [1,4] | (1,1,2) | ハッシュ検索 | 1 |

 クエリは M1 と同じ周波数ベクトルを再構築するため、答えは 1 になります。 

これにより、順列の違いがマッチングに影響を与えないことが確認されます。 

### 例 2

 A = [5, 1, 2, 5, 1] とします。 

M1 = [1,1,5,5,2] を挿入し、M2 = [1,2,5] を挿入します。 

| ステップ | ベクトル | ハッシュアクション | 保存されたカウント |
 | --- | --- | --- | --- |
 | M1 を挿入 | (2,1,2) | ストア | {h1:1} |
 | M2 を挿入 | (1,1,1) | ストア | {h2:1} |
 | クエリ [1,5] | (2,1,2) | 検索 | 1 |

 M1 のみがフルセグメント周波数と一致します。 

これは、余分な多重度または欠落した多重度が直ちにハッシュを分離することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + Q) × σ) | 各プレフィックス クエリまたはベクター ビルドは、最大 100 個の値を反復処理します。 
| スペース | O(n × σ + 保存されたベクトルの合計) | 保存された周波数ベクトルのプレフィックス テーブルとハッシュ マップ |

 σ ≤ 100 および総要素数 ≤ 10^6 の場合、これは制限内に問題なく収まります。 この解決策は、個別の値の数が少ないという制約に依存しており、これにより周波数ベクトル表現のコストが高くなりすぎることが防止されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、メイン配列内のすべての要素が同一である場合です。 たとえば、A = [7,7,7,7]。 サブ配列の周波数ベクトルは単一の次元数に折りたたまれ、格納されている多くの配列が一致する可能性があります。 プレフィックスの減算によって正しいカウントが生成され、ハッシュ化はその単一の座標にのみ依存するため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、格納された配列に A に決して現れない値が含まれている場合です。たとえば、A = [1,2,3] で、格納された配列に 999 が含まれる場合、その周波数ベクトルの次元には非ゼロの座標があり、すべてのクエリで常に 0 のままになります。 これにより、そのハッシュがどのクエリ ベクトルとも一致しないことが保証されます。 

最後の微妙なケースは、同じ格納配列が繰り返される場合です。 ハッシュ マップにカウントを保存するため、同じ周波数ベクトルを複数回挿入するとその周波数が増加するため、クエリではすべての重複が正しくカウントされます。
