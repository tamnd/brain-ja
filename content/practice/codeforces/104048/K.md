 ## 解決策
 ## 問題の理解

 それぞれが小文字の文字列である、最大 10 個の短いフレーズが与えられます。 タスクは、指定されたすべてのフレーズを部分文字列として含む単一の結合フレーズを構築することです。 「部分文字列として含まれる」とは、元の各文字列が最終文字列のどこかに出現し、他の文字列と重複する可能性があり、必ずしも分離されている必要はないことを意味します。 

このように結合されたすべての文字列の中で、可能な限り最小限の長さが必要です。 

入力の構造は文字列の数という点では少ないですが、各文字列は非常に長くなる可能性があるため、重要な困難はすべての文字をスキャンすることではなく、重複を利用して文字列を効率的にマージする方法を決定することです。 

N ≤ 10 という制約は、サブセットにわたる指数関数的な動作が許容されることを直ちに示唆しています。 N の階乗解はすでに境界線に達していますが、まだ推論するには十分小さいです。 ただし、文字列の長さが 10^4 に達するため、文字のすべてのインターリーブを繰り返し試行することは不可能です。 

多くの場合、最初に現れる素朴なアイデアは、すべての文字列を並べ替えて、順序ごとに次の文字列を現在の結果と貪欲にオーバーラップするというものです。 これは、オーバーラップの決定が独立していないため失敗します。局所的に最大のオーバーラップを早期に選択すると、後でより適切な全体的な配置が妨げられる可能性があります。 

2 番目の単純なアプローチは、考えられるすべての方法で文字列をペアごとに繰り返しマージしようとすることです。 これは、マージの数と文字列の長さの両方ですぐに指数関数的になり、同じグローバルな相互作用の問題にも悩まされます。 

素朴な貪欲戦略を破るエッジケースとは、文字列が別の文字列の中に完全に含まれている状況、または間接的なオーバーラップが直接的な最大のオーバーラップよりも優れている状況です。 たとえば、1 つの文字列が「abcde」、もう 1 つが「cdeab」、3 つ目の文字列が「eabx」の場合、貪欲なマージによって大きな重複が早期に優先され、3 つすべてをより短いチェーンに圧縮できる最適な位置合わせが失われる可能性があります。 

もう 1 つの微妙なケースは、文字列が他の 2 つの文字列の連結に完全に埋め込まれている場合です。 ローカル オーバーラップ ヒューリスティックはこれを無視して個別にカウントし、最終的な長さが不正確になる可能性があります。 

## アプローチ

 この問題についての正しい考え方は、最終的な文字列を直接構築することから、文字列の順序と、連続する各ペアがどの程度重複するかを決定することに焦点を移すことです。 

ブルート フォース ビューでは、文字列のすべての順列を試します。 順列ごとに、最初の文字列を完全に取得し、次の文字列ごとに重複しないサフィックスのみを追加して、マージされた文字列を構築します。 2 つの文字列間の重複を計算するには、2 番目の文字列の接頭辞と一致する最初の文字列の最大の接尾辞をチェックします。 これは正しいですが、N もあります。 順列があり、各マージのコストは最大 O(L) になるため、合計の複雑さはおよそ O(N! · N · L) となり、N = 10 の場合でも実現可能をはるかに超えています。 

重要な観察は、ペアごとの重複と文字列の配置順序のみを考慮しているということです。 すべての順序ペア間のオーバーラップが判明すると、問題は文字列のサブセットを通る最短パスになります。オーバーラップを最大化すると最終的な長さが最小化されるため、オーバーラップの合計が最大になる順序が必要になります。 

これにより、問題はビットマスク動的プログラミング問題に変換されます。 各文字列をノードとして扱い、i から j に移動する際のゲインは、i のサフィックスと j のプレフィックスの間のオーバーラップになります。 次に、すべてのノードを 1 回だけ訪問する最適なパスを計算します。 

オーバーラップの計算自体は、KMP や Z 関数などの文字列マッチング手法を使用して効率的に実行できますが、N は最大でも 10 であるため、ペアごとの単純な 2 ポインター チェックでも十分です。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 貪欲なマージを使用してすべての順列を試してみる | O(N!・N・L) | O(L) | 遅すぎる |
 | 事前計算されたオーバーラップを備えたビットマスク DP | O(N^2・L + N^2・2^N) | O(N · 2^N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 冗長な文字列を削除します。 

文字列がすでに別の文字列内に完全に出現している場合、その文字列を DP に含める必要はまったくありません。 保持しても正しさは変わりませんが、削除すると不要な状態が減ります。 

### 2. ペアごとのオーバーラップを計算する

 文字列の順序付きペア (i, j) ごとに、長さ k の文字列 i の接尾辞が長さ k の文字列 j の接頭辞と等しくなるように、最大長 k を計算します。 

この値は、j​​ を i の直後に配置した場合に節約される文字数を表します。 

### 3. DP 状態を定義する

 dp[mask][i] が、マスク内の文字列のセットを正確に使用して文字列 i で連結を終了することによって達成される最大合計オーバーラップを表すものとします。 

この状態は、使用されたサブセットと最後に選択された文字列の両方をキャプチャします。オーバーラップは隣接関係に依存するため、これが必要です。 

### 4. 基本ケースを初期化する

 単一の文字列は重複に寄与しないため、各文字列 i について、dp[1 << i][i] は 0 になります。 

### 5. 移行

 各状態 (マスク、i) について、マスクにないすべての文字列 j に拡張してみます。 dp[mask | を更新します。 (1 << j)][j] i から j にオーバーラップ ゲインを加算します。 

このステップは、有効な順序を明示的に並べ替えることなく暗黙的にすべて列挙するため、ソリューションの中核となります。 

### 6. 答えを抽出する

 完全なマスクの各終了文字列 i について、最終的な長さは、すべての文字列の合計長から dp[full_mask][i] の累積オーバーラップを引いたものと等しくなります。 可能なすべての終点の最小値を取得します。 

### なぜ効果があるのか

 DP は、文字列のすべての有効な順序が状態を通過する 1 つのパスに正確に対応することを強制し、各遷移では文字列を追加するときに必要な追加文字を正確に考慮します。 オーバーラップはすべてのペアに対して正確に計算されるため、順序付けのコストは近似せずに表されます。 したがって、最適な順序付けは、重複の合計を最大化するものであり、DP はすべてのサブセットとエンドポイントにわたって徹底的に探索します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def overlap(a, b):
    # maximum suffix of a matching prefix of b
    max_k = min(len(a), len(b))
    for k in range(max_k, 0, -1):
        if a[-k:] == b[:k]:
            return k
    return 0

def solve():
    n = int(input().strip())
    s = [input().strip() for _ in range(n)]

    # remove strings contained in others
    used = [True] * n
    for i in range(n):
        for j in range(n):
            if i != j and s[i] in s[j]:
                used[i] = False

    strings = [s[i] for i in range(n) if used[i]]
    n = len(strings)

    if n == 0:
        print(0)
        return

    # recompute total length
    total_len = sum(len(x) for x in strings)

    # overlaps
    ov = [[0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            if i != j:
                ov[i][j] = overlap(strings[i], strings[j])

    INF = -10**18
    dp = [[INF] * n for _ in range(1 << n)]

    for i in range(n):
        dp[1 << i][i] = 0

    for mask in range(1 << n):
        for i in range(n):
            if dp[mask][i] == INF:
                continue
            for j in range(n):
                if mask & (1 << j):
                    continue
                nmask = mask | (1 << j)
                dp[nmask][j] = max(dp[nmask][j], dp[mask][i] + ov[i][j])

    full = (1 << n) - 1
    best_overlap = max(dp[full])

    print(total_len - best_overlap)

if __name__ == "__main__":
    solve()
```この実装では、完全に含まれるフレーズが DP を汚染しないように、最初に冗長な文字列をフィルタリングします。 オーバーラップ関数は単純な方法で記述されており、文字列の数が少ない場合にはこれで十分です。 より厳密な設定では、線形時間プレフィックス関数アプローチに置き換えられます。 

DP テーブルはサブセットとエンドポイントを反復します。 重要な点は、overlap は保存された文字を表すため、トランジションによって生の文字列の長さではなく、overlap[i][j] が追加されることです。 合計の長さから最終的に減算すると、「最大保存文字数」が「最終的な文字列の最小長」に変換されます。 

## 実用的な例

 ### 例 1

 入力:```
3
abcd
defg
fghi
```重複を計算しますが、一方の接尾辞が他方の接頭辞と一致しないため、重複はすべてゼロになります。 DP は任意の順序で連結のように動作します。 

| ステップ | マスク | 終わり | ベストオーバーラップ |
 | --- | --- | --- | --- |
 | 初期化 | 001 | 0 | 0 |
 | 拡張する | 011 | 1 | 0 |
 | 拡張する | 111 | 2 | 0 |

 全長は 4 + 4 + 4 = 12 です。重なりがないので、答えは 12 になります。 

これは、構造が存在しない場合に DP が単純な連結に正しく縮退することを示しています。 

### 例 2

 入力:```
2
lovely
lycoris
```ここでは「lovely」と「lycoris」が「ly」で重なっています。 

| ステップ | マスク | 終わり | ベストオーバーラップ |
 | --- | --- | --- | --- |
 | 初期化 | 01 | 素敵 | 0 |
 | 拡張する | 11 | リコリス 2 |
 | 初期化 | 10 | リコリス 0 |
 | 拡張する | 11 | 素敵 | 0 |

 最良の重なりは 2、全長は 6 + 7 = 13、したがって答えは 11 です。 

これは、lovely → lycoris のみが保存に寄与するため、DP がどのように方向性の重複を正しくキャプチャするかを示しています。

 ## 特殊なケース

 重要なエッジケースは、ある文字列が別の文字列に完全に含まれている場合です。 例えば：```
2
abc
zabcq
```「abc」はすでに「zabcq」に含まれているため、アルゴリズムの前処理によって削除されます。 その後、DP は残りの文字列に対してのみ実行され、正しい長さ 5 が生成されます。 

もう 1 つのエッジ ケースは非対称オーバーラップです。i は j とオーバーラップしますが、その逆はありません。```
2
abca
caab
```ここでの重なりは方向によって異なります。 DP は両方の遷移を正しく評価し、より適切な順序を選択します。 

最後のケースは、複数の文字列が長いオーバーラップ チェーンを形成する場合です。 DP は、貪欲なマージによって間違った順序で重複が早期に消費されてしまう場合でも、最適なチェーンが確実に発見されるようにします。
