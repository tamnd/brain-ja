 ## 解決策
 ## 問題の理解

 いくつかのテスト ケースが与えられ、それぞれのテスト ケースには 0 から n − 1 までの数値の順列が含まれています。この順列の連続するセグメントについて、そのセグメント内に現れない最小の非負の整数、つまりセグメントの mex を調べます。 0 から n までのすべての考えられる値 k について、k と正確に等しい mex を持つ部分配列がいくつあるかを数えなければなりません。 

テスト ケースの出力は n + 1 の数値のシーケンスであり、k 番目の数値は k に等しい mex を生成する間隔の数を示します。 

この制約は、すべてのテスト ケースの合計の長さが最大 ​​10^6 であることを意味します。 テスト ケースごとに 2 次の解法では、最悪の場合でも約 10^12 の演算が必要になりますが、これは 2 秒で実行できる演算をはるかに超えています。 テスト ケースあたり O(n log n) のアプローチであっても、よほど厳密でない限り危険です。 これにより、全体として O(n) または償却された O(n) のソリューションが実現されます。 

置換のグローバル構造を考慮せずに mex についてローカルに推論する場合、微妙な失敗例が発生します。 

各部分配列の mex を個別に計算しようとすると、たとえスライディング ウィンドウを使用したとしても、更新にコストがかかりすぎます。 

もう 1 つのよくある間違いは、mex k に寄与する間隔は k より大きい値とは独立して動作するが、値 k 自体が唯一の障害となるのに、mex では k より大きい値は無視しても安全であると想定することです。 この非対称性が重要な構造特性です。 

## アプローチ

 直接的なアプローチでは、すべての間隔 [i, j] を考慮し、周波数構造をスキャンまたは維持することによってその mex を計算し、その mex 値の答えを増分します。 これは定義に明示的に従っているため正しいですが、mex を維持するには間隔ごとに O(n) の作業が必要となり、最適化を使用すると O(n^3) またはせいぜい O(n^2) になり、全体で 10^6 までの n には遅すぎます。 

重要な観察は、セグメントの mex が k に等しいという意味を言い換えることから得られます。 このようなセグメントには 0 から k − 1 までのすべての数値を含める必要があり、k を含めることはできません。 順列を扱っているため、各値は 1 回だけ出現するため、各数値の位置は固定されています。 

固定 k の場合、0 ～ k − 1 の位置が必須のカバー セグメントを定義します。 有効な間隔にはこれらの位置がすべて含まれている必要があるため、その左端点はそれらの最小位置またはその前、右端点はそれらの最大位置またはその後にある必要があります。 同時に、その間隔は k の位置を避けなければなりません。 

これにより、各 k の問題は、単一の禁止点を回避しながら、固定セグメントをカバーする間隔がいくつあるかを数えるという問題に縮小されます。 最小位置と最大位置に関するプレフィックス情報を増分的に維持する場合、その構造は k ごとに一定時間で評価できます。 

ブルート フォースはすべての間隔を明示的にチェックするため機能しますが、mex の再計算にコストがかかるため失敗します。 mex 制約が小さな値の位置にのみ依存するという観察により、問題はライン上の幾何学的カウント タスクに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) から O(n^3) | O(1) から O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、pos[x] が値 x のインデックスを与えるように、順列内のすべての値の位置を保存します。 

k = 0 の場合、mex が 0 である部分配列をカウントします。これは、部分配列に 0 が含まれてはいけないことを意味します。0 の位置を除くすべての部分配列が有効です。 部分配列の総数は n(n + 1)/2 で、無効なものは pos[0] を含むもので、その位置の左側の左端点と右側の右端点を選択することで数えられます。

k ≥ 1 の場合、k を増加しながら 2 つの実行値を維持します。つまり、値 0 ～ k − 1 の間の最小位置と最大位置です。これらは、有効な間隔に完全に含まれなければならないセグメントを定義します。 

各 k について、次のように処理します。 

1. pos[k − 1] を使用して現在の最小位置と最大位置を更新します。 これにより、k 未満のすべての値を含む最小のセグメントが追跡されます。 
2. 0 ～ k − 1 の最小位置を L、0 ～ k − 1 の最大位置を R とします。 
3. x を pos[k] とします。 x が [L, R] の内側にある場合、L と R の両方を含むすべての区間には自動的に k が含まれるため、区間が正確に mex を k とすることはできず、答えは 0 になります。 
4. それ以外の場合、mex k に寄与する間隔は [L, R] をカバーし、x を回避する必要があります。 制限なしで [L, R] をカバーする区間の数は、左端点では L 個の選択肢、右端点では (n − R + 1) 個の選択肢です。 
5. これらから、x も含まれる間隔を引きます。 x は [L, R] の外側にあるため、有効な交差領域は min(L, x) 以降に開始し、max(R, x) 以降に終了する区間となり、左端点には min(L, x) の選択肢が与えられ、右端点には (n − max(R, x) + 1) 個の選択肢が与えられます。 
6. 最終的な答えは、これら 2 つのカウントの差です。 

k = n の場合、間隔に 0 から n − 1 までのすべての数値が含まれる場合にのみ mex が n と等しくなります。これは配列全体のみであるため、答えは 1 になります。 

### なぜ効果があるのか

 k ごとに、有効な間隔内に出現する必要がある値のセットは、まさにセット {0, 1, ..., k − 1} です。 順列では、これらの値のそれぞれが一意の位置に対応するため、間隔の実現可能性は、間隔がこれらの必要な要素の極端な位置をカバーするかどうかによってのみ決まります。 これらの極端な値をカバーする間隔には、必要な値がすべて自動的に含まれます。 mex が k であることに対する唯一の障害は k 自体の存在であり、k も一意に位置するため、単一の禁制点として機能します。 これにより、条件が単純な間隔包含制約に減らされるため、有効な間隔はすべて 1 回だけカウントされ、無効な間隔は含まれません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        pos = [0] * n
        for i, v in enumerate(p):
            pos[v] = i

        total = n * (n + 1) // 2

        ans = [0] * (n + 1)

        x0 = pos[0]
        left = x0
        right = x0

        ans[0] = total - (x0 + 1) * (n - x0)

        for k in range(1, n):
            pk = pos[k - 1]
            if pk < left:
                left = pk
            if pk > right:
                right = pk

            x = pos[k]

            if left <= x <= right:
                ans[k] = 0
                continue

            base = left * (n - right)

            lo = min(left, x)
            hi = max(right, x)
            bad = lo * (n - hi)

            ans[k] = base - bad

        ans[n] = 1

        out.append(" ".join(map(str, ans)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は、O(1) で各値にアクセスできるように、順列を位置配列に変換することから始まります。 アルゴリズムは k を増加させながら値の位置を繰り返しクエリするため、これは不可欠です。 

k = 0 の場合、すべての部分配列を計算し、左右の選択肢の直接の組み合わせカウントを使用して 0 の位置を含む部分配列を減算します。 

k ≥ 1 の場合、常に 0 から k − 1 までの値の極端な位置を表す動的間隔 [左、右] を維持します。 k まで拡張する場合、この範囲を更新し、pos[k] がその範囲内にあるかどうかを評価します。 含まれている場合は、必要な要素をカバーするすべての間隔に k が含まれている必要があるため、すぐにゼロを割り当てます。 

それ以外の場合は、同じエンドポイント カウント ロジックを使用して、[left, right] をカバーする間隔の数を計算し、pos[k] も含まれる間隔の数を減算します。 

最後のケース k = n は、常に完全な配列に対応するため、個別に処理されます。 

## 実用的な例

 順列 [0, 1, 2, 3] を考えてみましょう。 

k = 0 の場合、すべての部分配列をカウントし、0 を含む部分配列を減算します。 

| k | 左 | 右 | pos[k] | 有効な間隔 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | 0 | 0 を含む合計マイナス間隔 |

 k = 1 の場合、必要なセットは {0} です。 これで、左と右は両方とも 0 になります。1 がどこに現れるかを確認し、それが位置 0 の左にあるか右にあるかに基づいて計算します。 

k = 2 および k = 3 の場合、同じロジックが拡張され、そのたびに必要なセグメントが拡張されます。 

ここで、より興味深い順列 [2, 0, 1, 3] を考えてみましょう。 

k = 1 の場合、値 0 のみが必要なので、left = right = pos[0] = 1 となります。pos[1] = 2 は右にあるため、有効な間隔は位置 1 をカバーする必要がありますが、2 は避けなければなりません。 

| k | 左 | 右 | pos[k] | ベース | 悪い | 答え |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 2 | 計算された | 計算された | ベース - 悪い |

 このトレースは、禁止されたポジションが、それ以外の場合は有効なカバー間隔のサブセットをどのように切り分けるかを示しています。 

2 番目の例は、構造が位置制約のみに依存し、順序を超えた実際の数値には依存しないことを強調しています。

 ## 特殊なケース

 最小の要素 0 が配列の一端にある場合、ほとんどすべての区間がそれを回避するか、予測可能な方法でそれを含めるため、k = 0 の寄与は最大になります。 計算はインデックスのみに依存するため、0 や n − 1 のような境界位置も、特別な分岐を行わずに同じ組み合わせ式によって正しく処理されます。 

pos[k] が現在の [L, R] の内側に正確に存在する場合、すべての必要な要素をカバーする区間には必然的に k が含まれるため、アルゴリズムは正しくゼロを返します。 これにより、カバレッジは満たしているが mex 条件に違反する間隔を過剰にカウントすることが回避されます。 

順列がすでに順序付けされている場合、新しい k ごとに間隔が徐々に拡張され、k = 0 と k = 1 のみが非自明なカウントを生成する、高度に構造化された一連の応答が生成されます。 [L, R] の増分メンテナンスにより、この縮退ケースが再計算なしで線形時間で処理されることが保証されます。
