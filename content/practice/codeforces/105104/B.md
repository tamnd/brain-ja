 ## 解決策
 ## 問題の理解

 2 つの数値 x と y から始めます。 各演算により、それらの 1 つを「ポンプ」することができます。最初の演算を選択すると、x は係数 k で乗算的に増加し、y は固定の加算ブースト d を取得します。 2 番目の操作を選択すると、役割が逆転します。 各ステップの後、1 つの変数が乗算され、もう 1 つの変数が線形に増加します。 目標は、どちらかの値を個別に最大化することではなく、できるだけ少ない操作で積 x · y が少なくとも z に達するようにすることです。 

主な問題は、両方の操作で両方の変数が同時に変更されることです。 1 つの変数が現時点で小さい場合でも、もう 1 つの変数を繰り返し乗算すると、加法結合により、後のステップでの成長が間接的に加速される可能性があります。 

制約は非常に大きく、値は最大 10¹² まで可能であり、k も 10¹² まで大きくすることができます。 これにより、すべての中間ペア (x, y) を明示的に追跡することに依存する状態空間の探索が即座に除外されます。 両方の変数が際限なく増加し、分岐係数が各ステップで 2 倍になるため、状態を超える BFS または DP は爆発します。 

微妙なエッジケースは、乗算と加算の間の相互作用から生じます。 k が大きく、1 つの変数がすでに大きい場合、それを乗算すると積がすぐにしきい値を超える可能性があります。 しかし、他の場合には、最適な戦略は、反対側の変数に加算ゲインを蓄積することを優先して乗算を遅らせます。 

「常に小さい変数を乗算する」といった単純な欲張りな考えは失敗します。 たとえば、x = 1、y = 10⁶、k = 2、d = 10⁶、z が中程度の場合、小さい方をやみくもに乗算するとターンが無駄になる可能性がありますが、大きい方に加算するとすぐに目的の積が得られます。 

k = 1 の場合、別の失敗ケースが発生します。その場合、乗算は何も行われず、問題は積の純粋な加法的増加となり、一般的なケースとは大きく異なる動作をします。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるすべての操作シーケンスが試行されます。 各ステップで、2 つの可能性に分岐し、更新されたペア (x, y) をシミュレートします。 これにより、状態の二分木が形成されます。 k が小さいか d が小さい場合、値の増加が遅くなる可能性があるため、必要な深さは厳密に制限されません。 最悪の場合、状態の数は 2^t と指数関数的に増加するため、最大 10⁵ 以上のステップを探索することはすでに不可能になります。 

中心的な観察は、プロセスが制御された方法で単調であるということです。 すべての演算で x と y の両方が増加し、値が大きくなると k による乗算が加算よりも優先されます。 これは、少数のステップの後、変数の 1 つが製品に大きく寄与することを意味します。 

両方の変数を対称的に追跡する代わりに、プロセスを 2 つの成長パターンのいずれかを繰り返し適用するものとして解釈できます。 各ステップは、x を乗算して y を線形に増加させるか、またはその逆のいずれかを行います。 重要な考え方は、決定は乗算によって「加速」するためにどの変数を選択するかによってのみ決まり、他の変数は予測どおりに進化するということです。 

O(log Answer) ステップの時間内でプロセスを貪欲にシミュレートできます。 各ステップで、演算 1 と演算 2 を適用した場合の利点を比較します。乗算は加算よりも大幅に速く選択した変数をスケーリングするため、最適な選択は、相加効果を考慮した後、積に対する現在より小さい寄与を常に乗算することです。 

これにより、問題は分岐ツリーの探索から決定論的な一連の決定へと軽減されます。

 ## アルゴリズムのチュートリアル

1. 現在の積 p = x · y を計算します。 p がすでに z 以上である場合は、すぐに 0 を返します。 これは、拡張が必要な​​い些細なケースを処理します。 
2. p ≥ z になるまで繰り返します。 

1. 演算 A を考えます。x は x · k になり、y は y + d になります。 結果の積は (xk)(y + d) になります。 
2. 演算 B を考えます。y は y · k になり、x は x + d になります。 結果の積は (yk)(x + d) になります。 
3. これら 2 つの結果の積を比較し、より大きな積を生成する演算を選択します。 

目標は純粋に製品をできるだけ早く最大化することであるため、この比較は有効です。 将来のステップは更新された状態にのみ依存するため、局所的な最大化は単調増加による全体的な進行と一致します。 

1. 選択した操作を適用し、それに応じて x と y を更新します。 
3. 実行された操作の数を数えます。 

どちらの操作も少なくとも 1 つの変数を厳密に乗算的に増加させ、k ≥ 2 により時間の経過とともに少なくとも 1 つの方向に指数関数的に増加するため、ループは終了する必要があります。 

### なぜ効果があるのか

 すべてのステップで、正確に t 回の操作で到達できるペア (x, y) を維持します。 どちらの操作でも積は単調増加します。 将来の成長は現在の大きさのみに依存し、たどったパスには依存しないため、より大きな即時積を生成する操作を選択しても、より良い最終状態へのアクセスが妨げられることはありません。 どちらの操作も単調な増加を維持し、以前の利益を逆転させるトレードオフを導入しないため、より悪い製品で始まる代替シーケンスは、最終的な到達可能性を低下させることなく段階的に交換できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, y, z, k, d = map(int, input().split())

    if x * y >= z:
        print(0)
        return

    steps = 0

    while x * y < z:
        # option A: x *= k, y += d
        ax = x * k
        ay = y + d
        prodA = ax * ay

        # option B: y *= k, x += d
        bx = x + d
        by = y * k
        prodB = bx * by

        if prodA >= prodB:
            x, y = ax, ay
        else:
            x, y = bx, by

        steps += 1

    print(steps)

if __name__ == "__main__":
    solve()
```このコードは、前述した段階的な比較を直接実装します。 各反復では、考えられる 2 つの次の状態を計算し、より大きな即値を生成する状態を選択します。 早期の終了により、すでに十分なインプットがカバーされます。 常により大きな製品に向かって進むため、ループ条件によって正確さが保証されます。 

実装の微妙な点は、Python の任意精度の整数を使用することです。これにより、固定幅言語に存在するオーバーフローの問題が回避されます。 もう 1 つは、反復ごとに両方の候補状態を完全に再計算することです。これは、乗算的な増大によりループの深さが小さいままであるため、許容されます。

 ## 特殊なケース

 初期積がすでに z を超えている場合、ループ条件に入らないため、アルゴリズムは直ちに終了し、ゼロ ステップが正しく生成されます。 

k = 1 の場合、乗算は効果がないため、増加は完全に反復的な加算更新によって行われます。 両方の候補演算の乗算べき乗が対称になり、比較は d を受信することでどちらの側がより多くの利益を得るかを評価することになるため、アルゴリズムは引き続き機能します。 

d が x および y に対して非常に大きい場合、加法項が初期の決定を支配する可能性があります。 積の比較には +d シフトの完全な効果が含まれており、乗算が支配的になる前に初期のステップで加算的加速を優先するため、アルゴリズムはこれを自然に捉えます。 

x と y の不均衡が非常に大きい場合、選択を繰り返すと、小さい寄与を最初に押し上げる傾向があります。これは、次の反復での限界積の増加が最大化され、それが比較式に直接反映されるためです。
