 ## 問題の理解

 ブロックを繰り返すことで形成される固定パターン文字列が与えられます。`"xtu"`その通り`n`回。 したがって、完全な文字列`p`長さがある`3n`非常に厳密な周期構造で構成されています。3 文字ごとに常に`x`、 それから`t`、 それから`u`。 

これに加えて、各テスト ケースではクエリ文字列が提供されます。`q`。 タスクは、インデックスを選択できる明確な方法が何通りあるかを数えることです。`p`選択した文字が順番に読み取られて正確に形成されるようにする`q`。 2 つの方法は、どの位置が異なるかによって異なるとみなされます。`p`使用されていました。 

したがって、中心となるオブジェクトは部分文字列のマッチングではなく、部分列のカウントであり、異なる位置にある同じ文字が個別の組み合わせの選択に寄与します。 

制約は非常に特殊な点で非常に厳しいものです。 繰り返し回数`n`最大 10、つまりメイン文字列`p`クエリの長​​さは最大 30 です。クエリの長​​さも次の制限を受けます。`3n`, したがって、多くても30です。 ただし、テスト ケースの数は次のように大きくなる可能性があります。`10^5`したがって、解は各テスト ケースのサイズが線形に近く、定数が非常に小さい必要があります。 

テスト ケースごとの単純なサブシーケンス DP は、状態サイズの点ではすでに許容可能ですが、指数関数的なものはすべて許容されます。`|p|`または`|q|`テスト ケースごとに実行すると、すべてのテストにわたって遅すぎる可能性があります。 

微妙な点が 1 つありますが、`p`は高度に構造化されており、サブシーケンスは文字タイプではなく位置によってカウントされます。 これは、同じ文字が異なる位置に出現することを意味します。`p`互換性はなく、異なるカウントが生成されます。 

エッジケースは次の場合に発生します。`q`外側に文字が入っている`{x, t, u}`。 その場合、答えはすぐにゼロになります。`p`それらは決して含まれません。 

もう 1 つの重要なエッジケースは次のような場合です。`q`は空です。 何も選択しないため、空のサブシーケンスを形成する方法の数は常に 1 です。 

最後に、いつ`q`より長いです`p`の場合、存在する以上のポジションを選択できないため、答えはゼロです。 

## アプローチ

 この強引なアイデアは、問題を文字どおり、最大 30 までの長さの文字列をカウントする部分列として扱うことです。`p`採用するかスキップするか、一致する方法が何通りあるかを追跡する`q`。 これはインデックスのすべてのサブセットを調査します。`2^(3n)`可能性。 と`n ≤ 10`、せいぜいこれくらいです`2^30`、テスト ケースごとに約 10 億の操作があり、これはあまりにも大きすぎます。`10^5`テスト。 

サブセットの列挙を避ける必要があります。 重要な観察は次のとおりです`p`は任意ではなく、3 文字のサイクルの繰り返しです。 これは、位置は異なっていても、その文字タイプが予測可能なパターンで繰り返されることを意味します。 したがって、構造を、何文字かを追跡する小さな状態空間にわたる動的プログラミングに圧縮できます。`q`スキャン中に一致しました`p`。 

サブセットの観点から考える代わりに、`p`左から右へ、DP を維持します。`dp[i]`最初のものと一致する方法の数です`i`の登場人物`q`の接頭辞を使用して`p`ここまで処理しました。 の各キャラクター`p`標準的なサブシーケンス方法で DP を更新します。 なぜなら`|p| ≤ 30`、これはテスト ケースごとに最大 900 の遷移であり、これは、`10^5`テストケース。 

単純サブシーケンス DP が十分であることは制約によりすでに保証されているため、周期構造はこれ以上の特別な最適化を必要としません。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1.読む`n`そして文字列を構築します`p`として`"xtu"`繰り返された`n`回。 これにより、構造をさらに分析する必要のない固定ソース シーケンスが得られます。 
2. 文字列を読み取ります`q`。 もし`|q| > |p|`、次のシーケンスがないため、すぐに 0 を返します。`p`より長くてもよい`p`自体。 
3. DP 配列を初期化する`dp`サイズの`|q| + 1`。 値`dp[i]`プレフィックスを形成する方法の数を表します`q[0:i]`の接頭辞の部分列として`p`ここまで処理しました。 セット`dp[0] = 1`空のプレフィックスは常に 1 つの方法で形成できるためです。 
4. 各文字を反復処理します。`c`で`p`。 このような文字ごとに、DP 配列を右から左に更新します。`q`。 ポジションごとに`j`から`|q| - 1`まで`0`、 もし`q[j] == c`そうすると、あらゆる形成方法を拡張できます。`q[0:j]`形成方法に`q[0:j+1]`。 そこで追加します`dp[j]`の中へ`dp[j+1]`。 

右から左の順序は、1 回の反復で同じ文字位置を複数回再利用することを防ぐため、必須です。これにより、文字列内で単一の位置が誤って許可されてしまいます。`p`複数回貢献すること。 
5. すべての文字を処理した後、`p`、答えは`dp[|q|]`、剰余を取得`998244353`。 

### なぜ効果があるのか

 DP は、最初の処理後、正確な組み合わせ不変式を維持します。`k`の登場人物`p`、`dp[i]`それらからサブシーケンスを選択する方法の数を正確に数えます。`k`最初の文字と等しい文字`i`の登場人物`q`。 各更新ステップでは、現在の文字が`p`で次に一致する文字として使用されます。`q`、逆の反復により、 の各位置が保証されます。`p`サブシーケンス構築ごとに最大 1 回使用されます。 これにより、DP 累積と有効なサブシーケンス間の 1 対 1 の対応が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        parts = input().split()
        n = int(parts[0])
        q = parts[1] if len(parts) > 1 else ""

        p = "xtu" * n
        m = len(p)
        k = len(q)

        if k > m:
            print(0)
            continue

        dp = [0] * (k + 1)
        dp[0] = 1

        for c in p:
            for j in range(k - 1, -1, -1):
                if q[j] == c:
                    dp[j + 1] = (dp[j + 1] + dp[j]) % MOD

        print(dp[k] % MOD)

if __name__ == "__main__":
    solve()
```コードは、標準のサブシーケンス DP テンプレートに従います。 の建設`p`は明示的ですが、最大長が 30 であれば許容されます。DP 配列には、次の部分一致の数が格納されます。`q`。 

逆方向ループオーバー`q`は重要な実装の詳細です。 前方の場合は、同じ文字が`p`単一の反復内で複数回再利用することができ、事実上、サブシーケンスのカウントがマルチセットの組み合わせのカウントに変わり、過剰カウントになる可能性があります。 

モジュロ`998244353`オーバーフローを防止し、値の境界を維持するために、加算のたびに適用されます。

 ## 特殊なケース

 のために`q = ""`、DP は影響を与えるいかなる遷移も実行しません。`dp[0]`、それで残ります`1`。 アルゴリズムの出力`dp[0]`、正しくは 1 を与えます。 

のために`q`にない文字が含まれている`{x, t, u}`、より高い DP 状態への更新は行われません。 たとえば、`p = "xtu"`そして`q = "a"`、`dp[1]`ずっと 0 のままなので、答えは 0 です。 

のために`q`に等しい`p`、すべての位置を順番に選択する方法は 1 つだけであるため、各文字の一致は DP を介して 1 つの有効なパスを正確に拡張し、最終的なカウントは 1 になります。
