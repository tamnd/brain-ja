 ## 解決策
 ## 問題の理解

 まずは豚足ご飯の既存の「おいしさの価値」を集めることから始めます。 これらの値は配列を形成し、並べ替えると、その並べ替え順序での連続する値間の最大ギャップとしてメニューの不安定性を定義します。 並べ替えられた順序で隣接するペアが離れすぎていない場合、メニューは安定していると見なされます。 

追加料理を作成してメニューを充実させることができます。 新しい料理はそれぞれ、豚足の種類のセットから 1 つの値を選択し、米の種類のセットから 1 つの値を選択し、それらを乗算することによって形成されます。 このようなすべての積は、配列に挿入できる潜在的な新しい要素です。 

目標は、これらの積のどのサブセットを追加するかを決定して、結合されたセットを並べ替えた後、隣接する最大の差ができるだけ小さくなるようにすることです。 

重要な点は、追加する項目の数を最大にしたり、すべての組み合わせを含めたりする必要はないということです。 私たちは、最終的にソートされたシーケンスの「最悪のギャップ」を改善しようとしているだけです。 

制約は集合サイズが小さく、初期値と使用可能な乗数の合計数が 1000 程度に制限されています。これは、次のことをすぐに示唆しています。$O(n^2 \log n)$あるいは$O(n^3)$このアプローチは本質的に不可能ではありませんが、答えを推測するたびにすべての候補製品に対して完全な再計算を繰り返す必要があるものは、おそらく遅すぎるでしょう。 

微妙な問題は、新しい値が独立した挿入ではないという事実から生じます。 各候補製品はギャップの構造を大幅に変更することができ、1 つの値を挿入することで複数の大きなギャップを同時に削減できます。 最大ギャップに貪欲にプロダクトを挿入する単純な試みは、1 つのギャップを修正するプロダクトが別の場所にさらに悪い最大ギャップを作成する可能性があるため、失敗することがよくあります。 

貪欲な直感による失敗の小さな例:

 入力:```
a = [1, 10, 20]
products = [6]
```挿入しない場合、ギャップは 9 と 10 であるため、不一致度は 10 になります。6 を挿入すると、ソートされた配列が生成されます。`[1, 6, 10, 20]`ギャップは 5、4、10、まだ 10 です。最大のギャップだけをターゲットにする貪欲な戦略は、改善は可能であると誤って想定する可能性がありますが、単一の挿入では役に立ちません。 

これは、問題が局所的な改善に関するものではなく、利用可能な「橋渡し」ポイントで大きなギャップを埋めるという全体的な実現可能性に関するものであることを示しています。 

## アプローチ

 ブルート フォースの見方は簡単です。考えられるすべての製品を生成します。$x_i \cdot y_j$、それらを元の配列にマージし、これらの製品のすべてのサブセットを試してください。 サブセットごとに、結果の配列をソートし、最大隣接差分を計算します。 

これは正しいですが、すぐには実行できません。 考えられる製品が最大 1000 個ある場合、サブセットの数は次のようになります。$2^{1000}$、これは計算の限界をはるかに超えています。 「すべての製品を使用する」ように制限したとしても、ソートされたマージと再計算には依然として多額のコストがかかります。 

別の視点が必要です。 重要な観察は、最終的な答えは、元の配列と選択された積の値の和集合のソートされた構造のみに依存するということです。 組み合わせ的な意味で任意のサブセットを選択しているわけではありません。 代わりに、潜在的に「ブリッジ」値を挿入した後、ソートされた元の配列内のすべてのギャップが大きすぎないことを確認しようとしています。 

これは問題を再構成することを示唆しています。目標値を推測するとします。$D$そして、最終セットで、連続する 2 つの要素の差異が 2 つ以上ないことを保証できるかどうかを尋ねます。$D$。 この実現可能性を効率的に確認できれば、答えを二分探索することができます。 

これで構造がより明確になりました。 固定の場合$D$、元の配列には制約が課されます: より大きいギャップ$D$少なくとも 1 つの積値を内部に挿入して「埋める」必要があります。そうしないと、構成が無効になります。 

したがって、問題は次のようになります。 間隔ごとに$[a_i, a_{i+1}]$と$a_{i+1} - a_i > D$、その間隔内に少なくとも 1 つの製品値を配置できますか? 積の値は乗法集合を形成します$x_i y_j$したがって、基本的には、このセットが特定の間隔と交差するかどうかを確認していることになります。 

これにより、問題はサブセットの選択から、構造化された候補セットによる区間の範囲に変換されます。 

実現可能性を確認するために、すべての製品を事前に計算して並べ替えます。 次に、大きなギャップ間隔ごとに、製品が存在するかどうかを確認します。$(a_i, a_{i+1})$。 大きなギャップがすべてカバーされれば、候補者は$D$動作します。 

これにより、二分探索が行われます$D$、ソートされた製品に対する二分探索を使用して、各チェックがギャップに対して線形時間で実行されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (サブセット) |$O(2^{XY} \cdot n \log n)$|$O(XY)$| 遅すぎる |
 | 二分探索 + 区間チェック |$O((n + XY)\log XY \log V)$|$O(XY)$| 承認済み |

 ## アルゴリズムのチュートリアル

 次に、ソリューションを段階的に構築していきます。 

1. 可能なすべての製品を生成する$x_i \cdot y_j$それらをリストに保存し、並べ替えます。 これにより、二分探索を使用して積が任意の区間にあるかどうかを効率的にクエリできる構造が得られます。 
2. 元の配列をソートします。 不安定性はソートされた順序での隣接する差異によって純粋に定義されるため、制御する必要があるギャップを明らかにするにはソートが必要です。 
3. 関数を定義する`check(D)`これは、製品のサブセットを挿入した後に最大ギャップ ≤ D を確保できるかどうかを決定します。 
4. 内部`check(D)`、隣接するすべてのペアを反復処理します。$a_i, a_{i+1}$。 もし$a_{i+1} - a_i \le D$、このセグメントはすでに有効であり、介入の必要はありません。 
5. もし$a_{i+1} - a_i > D$、少なくとも 1 つの製品値が 2 つの間に厳密に存在することを確認する必要があります。$a_i$そして$a_{i+1}$。 ソートされた製品リストに対して二分検索を使用して、その区間に要素が存在するかどうかを確認します。 存在しない場合、この設定は$D$不可能です。 
6. すべてのギャップが実現可能性テストに合格した場合、これに対して true を返します。$D$。 
7. 二分探索オーバー$D$0 から配列内の最大可能差まで、常に答えを更新します`check(mid)`成功する。 

### なぜ効果があるのか

 重要な不変条件は、最大ギャップ ≤ D の有効な最終構成では、D を超えるすべての元のギャップ内に少なくとも 1 つの要素を配置する必要があるということです。そのようなギャップが少なくとも 1 つの挿入された値によって分割されると、問題は結果のセグメント上の小さな独立した部分問題に分解されます。 最大ギャップのみを考慮するため、各セグメント内の内部構造は、挿入後にセグメント間で相互作用しません。 したがって、実現可能性は、元の大きなギャップを少なくとも 1 つの利用可能な製品値で交差できるかどうかのみに依存し、製品が何個選択されるか、または製品がどのように世界中に分散されるかには依存しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, X, Y = map(int, input().split())
    a = list(map(int, input().split()))
    x = list(map(int, input().split()))
    y = list(map(int, input().split()))

    a.sort()

    prod = []
    for i in range(X):
        for j in range(Y):
            prod.append(x[i] * y[j])
    prod.sort()

    from bisect import bisect_left, bisect_right

    def exists(l, r):
        # check if any product in (l, r)
        L = bisect_right(prod, l)
        if L < len(prod) and prod[L] < r:
            return True
        return False

    def check(D):
        for i in range(n - 1):
            if a[i + 1] - a[i] > D:
                if not exists(a[i], a[i + 1]):
                    return False
        return True

    lo, hi = 0, max(a) - min(a)
    ans = hi

    while lo <= hi:
        mid = (lo + hi) // 2
        if check(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```解決策は、元の値と派生積セットの両方を並べ替えることから始まります。 すべての実現可能性クエリは、値が特定の数値範囲内にあるかどうかを尋ねることになり、これが二分探索操作になるため、積の並べ替えは非常に重要です。 

ヘルパー関数`exists(l, r)`を使用してこの間隔クエリを実行します`bisect_right`より厳密に大きい最初の積を見つけるには`l`、そしてその候補がまだ下にあるかどうかを確認します`r`。 これにより、ギャップごとに製品リスト全体をスキャンする必要がなくなります。 

の`check(D)`関数は、中核となる実現可能性条件をエンコードします。D よりも大きいすべてのギャップには、少なくとも 1 つの積が含まれている必要があります。 このようなギャップに積が欠けている場合、その候補 D は達成できません。 

最後に、D に対して二分探索が適用されます。最大許容ギャップを緩和するだけで条件が満たされやすくなるため、特定の D が実現可能であれば、より大きな D も実現可能であるため、探索空間は単調です。 

よくある落とし穴は、閉じた間隔で製品の存在を誤ってチェックすることです。 この問題では、a[i] と a[i+1] の間に厳密に挿入する必要があるため、境界処理では、エンドポイントに等しい積が有効なフィラーとして扱われないようにする必要があります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての製品が大きなギャップの外側にある場合に発生します。 次のものがあるとします。```
a = [1, 100]
products = [50]
```D < 99 の場合、(1, 100) に値を挿入する必要があり、50 が存在するため、D = 50 が可能です。 ただし、代わりに製品があった場合、`[1, 100]`、厳密には内部値は存在せず、改善は不可能です。 アルゴリズムはこれを正しく処理します。`exists(l, r)`厳格な不平等を強制します。 

もう 1 つのケースは、複数のギャップが存在し、すべてのギャップ内で 1 つの製品しか利用できない場合です。 このアルゴリズムは、ギャップごとに積を割り当てようとしません。 ギャップごとに独立して存在をチェックするだけです。 これが機能するのは、使用回数に制約されないため、同じ製品が実現可能性チェックの複数のギャップを概念的に「提供」できるからです。 

最後のエッジ ケースは、元の配列に候補 D より大きいギャップがすでに存在しない場合です。この状況では、次のようになります。`check(D)`製品を参照せずにすぐに true を返し、挿入が必要ないことを正しく反映します。
