 ## 解決策
 ## 問題の理解

 各テスト ケースには、軸が揃った 4 つの長方形が与えられます。 各長方形は回転できるので、その辺を自由に交換できます。 課題は、これら 4 つのピースを重なり合わずに配置して、隙間を残さず、境界の外側にはみ出さずに完全な正方形を正確に埋めることができるかどうかを判断することです。 

重要な制約は、長方形の切断や変形は許可されておらず、移動と回転のみが許可されていることです。 したがって、最終的な形状は、正確に 4 つの長方形ブロックを使用して正方形を完全にタイリングする必要があります。 

入力サイズは、テストごとの作業という点では控えめですが、テスト ケースの数が多くなる可能性があります。 最大 1000 のテスト ケースとケースごとに 4 つの長方形のみを使用する場合でも、$O(4!)$または、ケースごとの小さな定因数指数検索も許容されます。 テスト ケースごとに数千の構成より悪いものはすでに不要ですが、構造が 4 つの部分に固定されているため、大きなパラメーターの多項式はここでは表示されません。 

素朴な推論における微妙な失敗モードは、「合計面積が一致する」だけで十分であると仮定することです。 そうではない。 たとえば、長方形 (1, 1)、(1, 1)、(1, 1)、(1, 3) の合計面積は 6 ですが、いずれにしても正方形の面積ではありませんが、たとえ合計が正方形に一致したとしても、ジオメトリは失敗する可能性があります。 

もう 1 つのよくある間違いは、「すべての四角形が 1 行または 1 列にある」などの 1 つのレイアウトのみをチェックすることです。 これでは、正方形を 2 つの水平ストリップに分割し、各ストリップを 2 つの長方形で並べて埋めるなどの有効な構成が失われます。 

最大の問題は、長方形が共有エッジに沿って完全に整列する必要があることであり、そのため、グループ間で辺の長さをどのように一致させるかについて強い構造的制約が課せられます。 

## アプローチ

 ブルートフォース手法では、仮想の正方形内に 4 つの長方形を配置できるすべての配置が試行されます。 そのためには、正方形の辺の長さを選択してから、連続ジオメトリまたはバックトラッキング配置を使用して長方形をパックすることを試みる必要があります。 長方形が 4 つだけの場合でも、連続配置により多くの自由度が導入されます。各長方形は多くの座標に配置でき、重なりのチェックは簡単ではなくなります。 最悪の場合、配置の探索は、必要なものをはるかに超えた大規模な連続検索スペースを伴う幾何学的バックトラッキング問題にまで悪化します。 

重要な観察は、4 つの長方形を使用して正方形を有効にタイリングする場合は、非常に厳密な構造に従わなければならないということです。 すべてのカットは軸に沿って配置されており、長方形は重なり合うことができないため、正方形は少数の組み合わせパターンでのみ分解できます。 4 つの長方形を使用すると、すべての有効な構成が 3 つの構造形式のいずれかに折りたたまれます。 

最初の形式は、単一の水平ストリップまたは垂直ストリップの分解であり、すべての長方形が一方向に整列します。 この場合、すべての長方形は正方形の辺に等しい 1 つの寸法を共有し、他の寸法の合計は辺の長さとなります。 

2 番目の形式は、正方形を 2 つの水平 (または垂直) 行に分割します。各行には、並べて配置された 2 つの長方形が含まれます。 この構成では、各行の高さが均一である必要があり、各行内の幅の合計が正方形の辺に一致する必要があります。 さらに、2 つの行の高さの合計が正方形の辺になる必要があります。 

3 番目の形式は、回転対称である 2 番目の形式と基本的に区別されないため、追加のケースは導入しません。 

幾何学的な配置から構造化されたパーティショニングへのこの削減により、問題は、方向の選択を伴う、グループへの長方形の組み合わせ割り当ての一定数をチェックすることに削減されます。

 ## アルゴリズムのチュートリアル

 問題を、4 つの長方形の向きを変えて有効な正方形のタイルに分割するための一貫した方法をすべて試みることに集約します。 

1. 各長方形のすべての回転を列挙します。 各長方形には 2 つの可能な状態があるため、次のようになります。$2^4 = 16$向きの設定。 これは、1 つの向きに収まらない長方形でも、辺を入れ替えると収まる可能性があるため必要です。 
2. 各方向の構成について、4 つの長方形のすべての順列を考慮します。 これにより 24 の並べ替えが行われ、グループ化の決定が入力順序によって偏らないことが保証されます。 
3. 配置ごとに、構造パターンに基づいて候補タイリングを計算します。 
4. まず、単一行構成を確認します。 4 つの長方形すべてを 1 つの水平ストリップ内に並べて配置したものとして扱います。 これは、すべての長方形が同じ高さを共有し、その幅の合計が正方形の辺の長さと等しい場合にのみ有効です。辺の長さは共通の高さです。 
5. 次に、単一列構成を対称的に確認します。 すべての長方形は同じ幅を共有する必要があり、その高さの合計もその幅に一致する必要があります。 
6. 次に 2 列構成を確認します。 4 つの長方形を 2 つずつ 2 つのグループに分割します。 考えられる分割ごとに、各グループが行を形成できるかどうかを確認します。グループ内では、すべての長方形が水平方向に揃うように同じ高さでなければなりません。 各グループの幅の合計が同じ値になる必要があり、これが正方形の辺の長さになります。 最後に、正方形の高さは 2 つの行の高さの合計となり、前に決定した幅と一致する必要があります。 
7. いずれかの構成がこれらの制約を満たす場合、答えは「はい」です。 存在しない場合は、「いいえ」を出力します。 

### なぜ効果があるのか

 軸が整列した 4 つの長方形で正方形を有効にタイリングすると、その正方形は、長方形の境界によって定義される水平または垂直のストリップに分割されます。 部分が 4 つしかないため、パーティション グラフにはどちらの方向にも最大 2 レベルの細分があります。 これにより、すべての有効なレイアウトが 4 つの長方形からなる 1 つのストリップ、または 2 つの長方形からなる 2 つのストリップのいずれかに強制的に配置されます。 回転が明示的に列挙されるため、方向の不一致が排除され、すべてのパーティションが試行されるため、構造的な配置が失われることはありません。 一定サイズの構成空間にわたるこの網羅性により、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from itertools import permutations, product

def can(rects):
    for perm in permutations(rects):
        a, b, c, d = perm

        # single row
        h = a[1]
        if b[1] == h and c[1] == h and d[1] == h:
            if a[0] + b[0] + c[0] + d[0] == h:
                return True

        # single column
        w = a[0]
        if b[0] == w and c[0] == w and d[0] == w:
            if a[1] + b[1] + c[1] + d[1] == w:
                return True

        # two rows: (a,b) and (c,d)
        # check pairing (0,1)|(2,3)
        pairs = [((a, b), (c, d)), ((a, c), (b, d)), ((a, d), (b, c))]

        for (r1, r2) in pairs:
            (x1, y1), (x2, y2) = r1
            (x3, y3), (x4, y4) = r2

            if y1 == y2 and y3 == y4:
                h1 = y1
                h2 = y3
                if x1 + x2 == x3 + x4 and x1 + x2 > 0:
                    s = x1 + x2
                    if h1 + h2 == s:
                        return True

    return False

def solve_case(rects):
    for mask in range(16):
        oriented = []
        for i in range(4):
            w, h = rects[i]
            if mask & (1 << i):
                oriented.append((h, w))
            else:
                oriented.append((w, h))
        if can(oriented):
            return True
    return False

def main():
    t = int(input())
    for _ in range(t):
        rects = [tuple(map(int, input().split())) for _ in range(4)]
        print("Yes" if solve_case(rects) else "No")

if __name__ == "__main__":
    main()
```このソリューションでは、まず方向の処理を構造の検証から分離します。 の`solve_case`この関数はビットマスクを使用してすべての回転状態を反復し、すべての四角形が可能な両方の方向で考慮されるようにします。 

の`can`次に、関数は入力順序への依存を避けるために、四角形のすべての置換を試みます。 その中で、コードは 3 つの構造の可能性をチェックします。つまり、すべての四角形が 1 行にあること、すべてが 1 列にあること、および 2 行に分割されていることです。 

2 行の場合は、可能な 3 つの組み合わせすべてで四角形を明示的にペアにすることで処理されます。 各ペアは、ペア内で同じ高さを強制し、両方の行の幅の合計が一貫していることを確認することによって、潜在的な行としてテストされます。 最終的な正方形の辺は行の幅から導出され、全体の高さに対して検証されます。 

正確かどうかは、方向が固定されたら、有効なタイリングがこれらの個別のパーティション パターンのいずれかに整列する必要があるという事実にかかっています。

 ## 特殊なケース

 例外的なケースの 1 つは、すべての長方形が同一の正方形である場合です。 その状況では、すべての方向が有効なタイリングにつながりますが、アルゴリズムは単一の構成に依存してはなりません。 回転ループにより、入力順序が不利な場合でも、有効な順列が確実に検出されます。 

もう 1 つのケースは、(1, 6)、(2, 3)、(3, 2)、(6, 1) など、長方形の面積は一致しているが辺の長さが一致していない場合です。 総面積は一貫していますが、行または列の位置合わせを行ってもグループ全体の寸法を均等にすることはできません。 実行中、すべての置換は行の等高さ制約または列の等幅制約のいずれかに失敗するため、関数はそのケースを正しく拒否します。 

3 番目のケースは、非対称だが有効なタイリングです。この場合、正方形が高さの異なる 2 つの行に分割され、各行には幅が異なるが高さが等しい 2 つの長方形が含まれます。 2 行チェックでは、各ペア内で同じ高さを明示的に適用するため、グループ化が正しく揃っている限り、そのような構成も検出されます。
