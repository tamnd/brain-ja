 ## 解決策
 ## 問題の理解

 選挙区のリストが与えられますが、それぞれの選挙区は投票数を表す単一の整数によってのみ記述されます。 各選挙区では、2 人の候補者のうちの 1 人がその選挙区からのすべての票を獲得するため、各選挙区はその全値を一方の陣営またはもう一方の陣営のいずれかに貢献する単一の「ブロック」のように動作します。 

隠された質問は選挙のシミュレーションに関するものではありません。 代わりに、これらの投票ブロックの構造が十分に厳格であり、合法的な方法で投票ブロックを 2 つのグループに分割すると、全体的に固有の結果パターンが得られるかどうかが問われます。 同様に、我々は 2 つの異なる符号の割り当てが存在するかどうかを知りたいのです。1 つは「候補者 A がこの選挙区で勝利する」に対応し、もう 1 つは「候補者 B が勝利する」に対応し、結果として得られる加重和がすべての法的変換の下で区別できないように動作するかどうかです。 声明内の例は、これを示唆しています。異なる記号の割り当てが全体としては同じ効果を生み出す可能性があり、これは選挙結果の決定が曖昧になることを意味します。 

入力サイズは最大 100,000 個の値で、それぞれの大きさは 2^31 − 1 です。これにより、サブセットを列挙したり、考えられるすべてのパーティションを比較しようとするアプローチは即座に除外されます。 選挙区のペアに対する二次アプローチでさえ遅すぎます。 解決策は本質的に線形または線形でなければなりません。 

多くの値が等しい場合、または小さな値が大きな値から構成される場合、微妙な問題が発生します。 このような場合、異なる符号の割り当てが予期しない形で互いに打ち消し合う可能性があります。 たとえば、配列に 1、2、3、4 のような値が含まれている場合、符号を組み合わせて複数の方法で等しい合計を作成できます。これはあいまいさに相当します。 「異なる数値が一意性を保証する」という素朴な直観は、符号上の線形結合でも衝突する可能性があるため、当てはまりません。 

もう 1 つのエッジ ケースは、すべての値が 2 の累乗であるか、厳密に増加する構造に従う場合です。 このような場合、一意性は多くの場合維持されますが、それは各値が以前のすべての値の合計と比較して十分に大きい場合に限られます。 そうしないと、キャンセルによって以前の値が後の値をシミュレートする可能性があります。 

## アプローチ

 強引な解釈では、同じ選挙結果をもたらす 2 つの異なる符号割り当てが存在するかどうかを確認しようとします。 これを考える 1 つの方法は、選挙区のすべてのサブセットを考慮し、考えられるすべての符号付き合計を計算することです。 すべてのサブセットが個別の値を生成する場合、システムは明確になります。 ただし、これはすぐに 2^n 通りの可能性をもたらし、n = 40 の場合でも、これはすでに実行不可能です。 

別の試みは、値をソートし、動的プログラミングを使用してサブセット合計間の衝突を検出しようとすることです。 合計の範囲が最大 n * 2^31 と膨大であり、合計を超える DP は時間的にもメモリ的にも実現不可能であるため、これは依然として爆発的です。 

重要な洞察は、各要素がプラスまたはマイナス記号で取得できるマルチセットのサブセット和の一意性条件として問題を再解釈することです。 これは、非常に限定された意味で、セットが「{−1, 0, 1} の係数に対して線形独立」であるかどうかを尋ねることと同じです。 重要な観察は、より小さな要素のサブセットが結合してより大きな要素と一致する場合に、まさにあいまいさが現れるということです。 

配列をソートすると、条件は大幅に単純化されます。 いずれかの時点で、残っている最大の要素が、これまでに考慮されたすべての小さな要素の合計よりも厳密に大きくない場合、衝突する 2 つの異なる符号の割り当てを構築できます。 逆に、すべての要素が以前のすべての要素の合計よりも厳密に大きい場合、各要素には以前の要素の組み合わせでは複製できない新しいスケールが導入され、一意性が保証されます。 

これにより、ソート後の問題は貪欲な線形スキャンに変換されます。

 ## アルゴリズムのチュートリアル

 ### アルゴリズムのチュートリアル

 1. 小さい値が大きい値を構築できるかどうかを常に考慮できるように、配列を非降順でソートします。 キー プロパティは小さな要素からの累積到達可能性に依存するため、並べ替えが必要です。 
2. 実行合計変数を 0 として初期化します。この合計は、すでに処理された要素の組み合わせを使用して構築できる最大値を表します。 
3. 並べ替えられた配列を最小要素から最大要素まで繰り返します。 
4. 各要素 ai について、ai が現在の累計合計以下であるかどうかを確認します。 この条件が当てはまる場合は、あいまいさが存在すると即座に結論付けて停止します。 
5. ai が現在の合計よりも厳密に大きい場合、この要素は構築可能な値の範囲を拡張するため、ai を追加することで現在の合計を更新します。 
6. ループが失敗条件をトリガーせずに終了した場合、符号割り当て間の衝突の可能性はないと結論付けられます。 

### なぜ効果があるのか

 すべてのステップで、累計は、前に処理された要素の符号付きの組み合わせを使用して生成できる値の全範囲を表します。 新しい要素がこの合計以下である場合、それは適切な符号を持つ以前の要素の組み合わせとして表現できることを意味するため、新しい独立した方向が導入されるわけではありません。 これは、2 つの異なる符号の割り当てが全体として同じ効果を生み出し、一意性が損なわれる可能性があることを意味します。 すべての新しい要素が現在の到達可能な範囲を超える場合、以前の要素で複製することはできないため、各要素は新しい独立したスケールに寄与し、セット全体にわたるキャンセルベースの衝突を防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    s = 0
    for x in a:
        if x <= s:
            print("NO")
            return
        s += x

    print("YES")

if __name__ == "__main__":
    solve()
```実装は貪欲な構造に正確に従います。 ソートにより、実現可能性を常に段階的にテストできるようになります。 累計`s`前の要素によってすでに形成されているものを追跡します。 この境界を超えない要素に遭遇した瞬間に、表現可能性における潜在的な衝突を検出し、早期に終了します。 

よくある実装上の間違いは、`<`の代わりに`<=`。 現在の合計に等しい要素は、以前の要素の符号付きの組み合わせによって正確に複製され、曖昧さが生じるため、等価性は失敗するはずです。 もう 1 つの微妙な点は、単一の合計のみを維持することです。 構築には対称性が暗黙的に含まれているため、正の範囲と負の範囲を個別に追跡する必要はありません。

 ## 特殊なケース

 最小のエッジケースは単一選挙区です。 入力あり`1`、比較ができないため、どの値も自明のことながら一意のシステムを形成します。 このアルゴリズムは合計をゼロに初期化し、最初の値が正の場合はすぐにそれを受け入れます。 

入力用`2\n1 1`、収量の選別`[1, 1]`。 最初の要素は合計を 1 に設定します。2 番目の要素は現在の合計と等しく、失敗条件がトリガーされます。 これは、2 つの同一のブロックが全体の結果を変えることなくサイド間で交換され、曖昧さが生じるという事実を反映しています。 

入力用`3\n1 2 4`、実行中の合計は 1、3、7 と変化します。各要素は厳密にその前の合計よりも大きいため、以前の要素で表現できる要素はありません。 アルゴリズムにより一意性が正しく確認されます。 

入力用`5\n1 2 3 8 16`、1、2、3 を処理した後、プレフィックスの合計は 6 に達します。次の要素 8 はまだ安全ですが、16 は厳密な増加を維持したまま最終的に全体の構造を超えます。 ただし、8 の代わりに 6 を含めるように少し変更すると、6 は 1+2+3 に等しいため、すぐに失敗が発生します。これは、値が等しくない場合でも、サブセットの構成可能性が一意性をどのように損なうかを示しています。
