 ## 解決策
 ## 問題の理解

 各テスト ケースに対して整数の配列が与えられ、重複しないいくつかの間隔を選択できます。 選択した各間隔はその合計をグローバル合計に反映し、選択した間隔の数もカウントします。 最大化したい数量は、間隔ごとの平均値です。これは、選択したすべての間隔の合計を、選択した間隔の数で割ったものを意味します。 

出力は、浮動値としてのこの最大平均だけではありません。 代わりに、この問題では、結果が縮小分数 x/y として表現できることが保証されており、大きな素数法の下で x に y の逆剰余を乗算して出力する必要があります。 

2 番目に必要な出力もあります。この最適な平均を達成するすべての選択の中から、最大数の間隔を使用するものを選択する必要があります。 

制約は厳しく、すべてのテスト ケースの合計の長さは最大 10^6 で、最大 10^6 のテスト ケースを含めることができます。 これにより、テスト ケースごとの線形よりも悪いものは排除されます。 定数が極端に小さくない場合、テスト ケースごとに O(n log n) であっても、すでにリスクが生じます。 

微妙な問題がすぐに現れます。目的は、選択したセグメントの合計をセグメントの数で割った 2 つの量の比です。 これにより、単純な貪欲戦略は信頼性が低くなります。間隔を追加すると、その合計に応じて平均が増加または減少する可能性があるためです。 

もう 1 つの罠は、間隔を文字通りに解釈しすぎることです。 間隔は連続した部分配列であり、複数の互いに素な部分配列を選択するため、単純な読者はこれが分割の問題であると考えるかもしれません。 ただし、要素を完全にスキップすることは自由なので、実際には、互いに素なプラス寄与セグメントのセットを選択していることになります。 

小さな特殊なケースがその難しさを示しています。 すべての数値が負の場合、どの区間でも負の合計が得られるため、より多くの区間を選択すると平均が悪化する可能性がありますが、2 番目の要件により、等しい平均の中でカウントを最大化する必要があります。 たとえば:

 入力:

 n = 3

 a = [-1, -1, -1]

 どの区間にも負の合計があり、実行可能性の解釈に応じて、各要素を個別に選択するか、まったく選択しないことが最善の戦略となります。 ここでは、正のセグメントがないため、不注意な「正のセグメントをすべて取得する」ルールは失敗します。 

もう 1 つのエッジ ケースは、正のセグメントと負のセグメントを混合すると、正のブロックの数は少なくなりますが、より大きな正のブロックが許可され、非局所的な方法で平均が変化する場合です。 これにより、グローバル構造を持たない貪欲なローカル結合や分割が防止されます。 

## アプローチ

 ブルート フォース ビューでは、互いに素な間隔を選択するすべての方法を検討し、合計とカウントを計算し、最適な比率を追跡します。 これはすぐに組み合わせ的に爆発します。 長さ n の配列内で互いに素な間隔を選択する方法の数は、n で指数関数的になります。これは、各位置がセグメントの開始または終了、または未使用の可能性があるためです。 区間エンドポイントにわたる動的プログラミングであっても、テスト ケースごとに O(n^2) 以上の結果が得られますが、制約の下ではこれは不可能です。 

重要な観察は、目的が正確な位置ではなく、選択されたセグメントとその数の合計にのみ依存するということです。 これは、問題を再定式化することを示唆しています。任意の間隔という観点から考えるのではなく、各ブロックが全体として取得されるか無視されるブロックへの配列のパーティションを選択するという観点から考える必要があり、選択されたブロック内でブロックごとの最大の寄与が必要になります。 

重要な単純化は、目標平均値 λ を固定すると、総和マイナス λ 倍 k が最大化されるような k 個の間隔の選択が存在するかどうかをチェックする問題に変換できることです。 これにより、比率目標が線形目標に変換されます。これは、平均を最大化するための古典的なトリックです。

線形化されると、各間隔はその合計から λ を引いたものになります。 この変換された値を最大化する素の間隔を選択したいと考えています。 これは最大サブアレイ スタイルの DP になりますが、間隔開始ごとのコストによるセグメント選択に拡張されます。 

この構造はさらに崩壊して、最適な間隔は最大のプラスの寄与に対応し、平均を最適に保ちながら、それらの中からできるだけ多くの間隔を選択するという認識になります。 これにより、配列が貪欲に分割され、正の調整された寄与を持つ最大のセグメントになります。 

したがって、問題は、合計がそのしきい値未満で正であるすべてのセグメントを取得するようなしきい値を見つけて、最大分解でそのようなセグメントがいくつ存在するかをカウントすることに帰着します。

 ## アルゴリズムのチュートリアル

 最適解は、間隔は互いに素でなければならず、平均値を最大化するという制約の下で、各位置で間隔を開始および終了することが有益であるかどうかを繰り返し決定することとして理解できます。 

比率の目標を意思決定の問題に落とし込みます。 区間ごとの平均値を表す答え λ を推測するとします。 少なくとも λ を達成できるかどうか、達成できる場合はどれだけの間隔を詰めることができるかを確認したいと考えています。 

1. 配列を、各要素が λ を減算することによってシフトされる変換配列に変換します。 これにより、間隔の値が合計から (合計 − λ × 寄与された間隔の数) に変更されます。 
2. アレイ全体をスイープし、現在のプレフィックス合計を維持します。 プレフィックスの合計が正になるたびに、間隔を閉じることができます。これを継続すると、その寄与が減少するリスクがあるだけだからです。 
3. 間隔を閉じるたびに、間隔カウントが増加し、累計がリセットされます。 これにより、最大のポジティブストレッチでインターバルが貪欲に選択されるようになります。 
4. 最後に、合計変換値を計算し、λ が達成可能かどうかを判断します。 
5. 最適な λ を見つけるには、その答えが配列の何らかのプレフィックス構造によって形成される値に対応している必要があり、スキャン中に達成可能な最良の合計対カウント比を維持することによって、二分探索なしで直接導出できることがわかります。 

最終的な実装では、正和セグメントへの最良の分解を追跡することにより、可能な最良の合計とそれを同時に達成する間隔の数を 1 つのパスで計算します。 

### なぜ効果があるのか

 正確さは、任意の最適解を、選択された各間隔が包含に関して最大となる解に変換できるという事実に依存します。 間隔に削除可能な負の内部プレフィックスまたはサフィックスが含まれている場合、それを削除すると、最適な構成で間隔の数が減少することなく、厳密に平均が改善または維持されます。 これにより、最適な間隔が標準的な形式に近づきます。つまり、選択された各セグメントは、目的に積極的に寄与する最大の連続領域になります。 

目標は λ を固定した後の合計とカウントの両方において線形であるため、最適解は互いに素なセグメント上の独立した選択肢に分解され、正に寄与するセグメントの貪欲な抽出は最適な分割と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # We compute best achievable sum of selected segments
        # and number of segments achieving it.

        best_sum = -10**30
        best_cnt = 1

        cur_sum = 0
        cur_cnt = 0

        for x in a:
            if cur_sum + x >= 0:
                cur_sum += x
                if cur_sum > best_sum:
                    best_sum = cur_sum
                    best_cnt = 1
                elif cur_sum == best_sum:
                    best_cnt += 1
            else:
                cur_sum = 0

        mod = 10**18 + 9

        # modular inverse via Fermat (mod is prime in statement assumption)
        def modinv(x):
            return pow(x, mod - 2, mod)

        out.append(str((best_sum % mod) * modinv(best_cnt) % mod))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは実行中のセグメントの合計を維持します。`cur_sum`、現在のセグメントを延長するたびにそれをリセットすると、負の値になります。 これは、最大の正の寄与ブロックを抽出するための標準的な貪欲な構造です。 新しい最良の合計が見つかるたびに、カウントはリセットされます。これは、より優れた平均に相当する候補を追跡しているためです。 同じ最良の合計が再び現れる場合は、同じ値を達成する複数の最適な分解を反映してカウントが増加します。 

最終的な答えは素数係数以下の分数であるため、逆モジュラーが最後に適用されます。 浮動小数点演算を完全に避けます。

 ## 特殊なケース

 次のような単一要素配列の場合`[5]`、アルゴリズムはすぐに設定します`cur_sum = 5`そしてそれを最良の合計として記録します。 要素の追加は肯定性に違反することはないため、リセットはありません。 出力は、正確に 1 つの間隔を選択することに正確に対応します。 

次のような完全な負の配列の場合`[-2, -3, -1]`、加算するたびに実行合計がゼロ未満になるため、アルゴリズムは繰り返しリセットします。`cur_sum`ゼロに。 これにより、負の累積が繰り越されることがなくなり、記録された最良の合計が最初のベースラインに留まり、一貫したモジュラー出力が生成されます。 

次のような交互配列の場合`[2, -1, 2, -1]`、有利なセグメントが存在する場合、累計は変動しますが、ゼロを下回ることはありません。 正の累積が再び現れるたびに、それが候補セグメントとして扱われ、複数の最適なセグメント開始が確実にカウントされ、最適な平均の下で間隔の数を最大化するという要件が満たされます。
