 ## 解決策
 ## 問題の理解

 各通話は連続した時間間隔を占めます。 通話は 2 つのエンドポイントと開始時間によって記述されます。`S`そしてその終了時間`S + D`、 どこ`D`その期間です。 電話番号自体は回答に影響しません。 誰が話しているのかを識別するだけなので、通話を読んだ後はその時間間隔だけが必要です。 

警察の問い合わせごとに、別の時間間隔が与えられます。 正の時間にわたってそのクエリと重複する呼び出しの数をカウントする必要があります。 クエリの開始と同時に終了する呼び出しはカウントされません。また、クエリの終了と同時に開始される呼び出しもカウントされません。 つまり、通話が占有されている場合、`[a, b]`そしてクエリが占有します`[c, d]`、正確に言うと、それらは少なくとも 1 秒間交差します。`a < d`そして`b > c`。 

1 つのテスト ケースの呼び出し数は 10,000 未満、クエリは 100 未満である可能性があります。 したがって、すべての呼び出しとすべてのクエリの直接比較は、最大でも実行されます。`9999 * 99 = 989901`1 つのテスト ケースでの重複チェック。 これは天文学的に大きな数ではないため、これらの規定の範囲内では強引な攻撃が可能です。 それでも、クエリの構造により、大幅に改善された結果が得られます。 通話の開始時間と終了時間を並べ替えると、バイナリ検索を使用して各クエリに回答できるようになり、クエリごとの作業が通話数の線形から対数に減少します。 

時間の値は大きくなる可能性がありますが、`Start + Duration`符号付き 32 ビット整数に収まります。 とにかく、ここでは Python の整数にはオーバーフローの問題はなく、個々の秒をシミュレートする必要はありません。 

よくある境界ミスの 1 つは、接触するだけの間隔を数えることです。 考慮する：```
1 1
10 20 0 10
10 1
0 0
```通話が占有されています`[0, 10]`、クエリが占有している間、`[10, 11]`。 それらの交差部分の継続時間はゼロであるため、答えは次のようになります。`0`。 を使用した不注意な実装`call_start <= query_end`そして`call_end >= query_start`間違って数えてしまうでしょう。 

別の境界ケースは、クエリが完全に呼び出し内にある場合に発生します。```
1 1
1 2 0 10
3 2
0 0
```通話は次からアクティブです`0`に`10`、クエリはカバーします`3`に`5`、したがって、答えは次のとおりです`1`。 クエリ内で通話が開始または終了するかどうかのみをチェックするメソッドは、通話のどちらのエンドポイントもクエリ内にないため、このケースを見逃す可能性があります。`[3, 5]`。 

3 番目のケースは、完全にクエリ内での呼び出しです。```
1 1
1 2 4 2
0 10
0 0
```通話が占有されています`[4, 6]`そしてクエリが占有します`[0, 10]`、ということで、答えはまたこうなります。`1`。 これは、包含の一方向のみをチェックするのではなく、間隔のエンドポイントを通じてオーバーラップを表現する必要がある理由を示しています。 

## アプローチ

 簡単な解決策は、すべての呼び出しを間隔として保存します。 警察の問い合わせごとに`[L, R]`、すべての通話をスキャンし、各通話が`[S, E]`満足する`S < R`そして`E > L`。 これら 2 つの不等式は、正の長さの交差を正確に特徴付けます。 最大で 9,999 件の呼び出しと 99 件のクエリがあるため、最悪のケースでは、テスト ケースごとに 989,901 回の間隔チェックが行われます。 これは、指定された制約に対してすでに十分小さいものであり、単純さのみを重視する場合には、完全に合理的な実装です。 

より高速なアプローチは、オーバーラップ条件を書き直すことによって実現されます。 通話は重複しません`[L, R]`正確に、それがクエリの完全に左または完全に右にあるとき。 通話は終了時間が最大でも完全に左側にあります。`L`。 コールの開始時刻が少なくとも次の場合、コールは完全に右に移動します。`R`。 

したがって、必要な数値は次のように書くことができます`N - (# calls with end <= L) - (# calls with start >= R)`。 

これら 2 つの量は独立しています。 すべての通話終了時刻がソートされている場合、二分探索により次の数以下の終了数が得られます。`L`。 すべての通話開始時間がソートされている場合、別の二分検索により開始回数以上が得られます。`R`。 

パイソンの`bisect_right`値の数を正確に返します`<= L`、 その間`bisect_left`値の数を与える`>= R`その結果をから引くことによって`N`。 厳密な不等式により、エンドポイントに触れる呼び出しが答えから消えてしまいます。 

前処理コスト`O(N log N)`、すべてのクエリにコストがかかります`O(log N)`。 クエリが 100 未満であれば、これは快適に高速であり、クエリの数が増加した場合の拡張性も大幅に向上します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(NM)`|`O(N)`| 規定の範囲内で受け入れられます |
 | 最適 |`O(N log N + M log N)`|`O(N)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての通話を読み取り、それぞれを開始時刻と終了時刻に変換します。 スタート付き通話の場合`S`と期間`D`、終了時間は`S + D`。 クエリでは時間的な重複のみが尋ねられるため、送信元と宛先の番号は必要ありません。 
2. すべての呼び出し開始を 1 つの配列に保存し、すべての呼び出し終了を別の配列に保存します。 これらの配列を並べ替えると、クエリの前後に何回の呼び出しがあるかという疑問が二分探索問題に変わります。 
3. 両方の配列をソートします。 並べ替え後、特定の値以下のすべての終了時刻が 1 つのプレフィックスを形成し、特定の値以上のすべての開始時刻が 1 つのサフィックスを形成します。 
4. で始まるクエリの場合`L`期間付き`D`、終了時間を計算します`R = L + D`。 
5. 使用する`bisect_right(ends, L)`終了時刻が最長の通話をカウントする`L`。 このような呼び出しはクエリが開始される前に完全に終了するため、クエリとの共通期間はゼロです。 
6. 使用する`bisect_left(starts, R)`開始時刻が少なくとも次の最初の呼び出しを検索します。`R`。 がある`N - bisect_left(starts, R)`そのような電話。 これらの呼び出しはクエリがすでに終了したときに開始されるため、共通期間もゼロになります。 
7. 重複しない両方のグループを`N`。 残りの呼び出しは満たします`start < R`そして`end > L`これは、正の時間だけクエリをオーバーラップしていることを意味します。 このカウントを出力します。 

### なぜ効果があるのか

 あらゆる通話に対して`[S, E]`そしてクエリ`[L, R]`、3 つの状況のうち 1 つが正確​​に当てはまります。 次の場合、呼び出しはクエリよりも完全に前になります。`E <= L`、クエリの完全に後で、`S >= R`、またはどちらの条件も当てはまらない場合はクエリが重複します。 最初の 2 つのグループは、クエリに次のものがあるため、互いに重複することはできません。`L < R`。 したがって、すべてのグループから両方のグループを削除します。`N`通話はまさに満足のいく通話を残します`S < R`そして`E > L`これは、正確には、クエリ間隔の少なくとも 1 秒間でアクティブなコールです。 

## Python ソリューション```python
import sys
from bisect import bisect_left, bisect_right

input = sys.stdin.readline

def solve():
    out = []

    while True:
        n, m = map(int, input().split())

        if n == 0 and m == 0:
            break

        starts = []
        ends = []

        for _ in range(n):
            source, destination, start, duration = map(int, input().split())
            starts.append(start)
            ends.append(start + duration)

        starts.sort()
        ends.sort()

        for _ in range(m):
            start, duration = map(int, input().split())
            end = start + duration

            finished_before = bisect_right(ends, start)
            started_after = n - bisect_left(starts, end)

            answer = n - finished_before - started_after
            out.append(str(answer))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```入力ループは、次の時点までテスト ケースを処理します。`0 0`。 すべての通話に対して、`start`そして`start + duration`電話番号は重複クエリに参加しないため、保持されます。 

2 つのソートされた配列は、呼び出しがクエリと重複しない 2 つの方法を表します。`bisect_right(ends, start)`クエリの開始部分と正確に一致する終了部分が含まれます。 クエリの開始と同時に終了する呼び出しには交差がゼロであるため、これは意図的なものです。 同様に、`bisect_left(starts, end)`クエリの終了と正確に等しい開始が含まれますが、これも回答から除外する必要があります。 

減算は、重複しないグループが両方ともカウントされた後にのみ実行されます。 クエリごとに個々の呼び出しを検査する必要はありません。 

Python では整数オーバーフローの問題もありません。 元の境界ではエンドポイントが 32 ビット符号付き整数に収まることが保証されていますが、Python の整数型はエンドポイントを直接表すことができます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(N log N + M log N)`| 2 つのエンドポイント アレイの並べ替えにかかるコスト`O(N log N)`、それぞれの`M`クエリは 2 つのバイナリ検索を使用します。 
| スペース |`O(N)`| 開始配列と終了配列には、それぞれ呼び出しごとに 1 つの値が含まれます。 

最大のテスト ケースに含まれる呼び出しは 10,000 件未満であるため、並べ替えのコストは低くなります。 各クエリでは、すべての呼び出しをスキャンするのではなく、バイナリ検索が 2 回だけ必要になります。 この方法では、タイムスタンプの実際の大きさに依存することも回避されるため、数千秒続く呼び出しでは、その秒間を繰り返す必要がありません。

 ## 特殊なケース

 最初の境界ケースは、クエリの開始と同時に呼び出しが終了することです。 例えば：```
1 1
10 20 0 10
10 1
0 0
```通話は次で終了します`10`、クエリは次から始まります`10`。`bisect_right(ends, 10)`返品`1`、そのため、呼び出しはクエリ境界よりも前、またはまさにクエリ境界で終了したものとして分類されます。 答えは、`1 - 1 - 0 = 0`。 

対称のケースは、クエリが終了したときにちょうど呼び出しが開始されることです。```
1 1
10 20 10 5
0 15
0 0
```電話は`[10, 15]`、クエリは`[0, 15]`したがって、これらの間隔は実際には時間の前に重なっています。`15`そして答えは`1`。 関連する二分探索は次のとおりです。`bisect_left(starts, 15)`を返します。`1`ただし、通話は に開始されるため、通話は削除されません。`10`、これは厳密には以前です`15`。 

代わりにクエリが`[0, 10]`:```
1 1
10 20 10 5
0 10
0 0
```それから`bisect_left(starts, 10)`返品`0`、与える`started_after = 1`。 呼び出しはクエリの終了境界で正確に開始されるため、答えは次のようになります。`0`。 

クエリは完全に呼び出し内に含めることができます。```
1 1
1 2 0 10
3 2
0 0
```ここでの電話は`[0, 10]`そしてクエリは`[3, 5]`。 までに通話が終了することはありません`3`、以降は通話が開始されません`5`、したがって、式は次のようになります`1 - 0 - 0 = 1`。 このメソッドでは、呼び出しのどちらのエンドポイントもクエリ内に存在する必要はありません。 

逆の封じ込めも同様に処理されます。```
1 1
1 2 3 2
0 10
0 0
```電話`[3, 5]`完全に内側にある`[0, 10]`。 繰り返しますが、重複しないグループのいずれにもコールは属さないため、答えは次のようになります。`1`。 

最後に、クエリはすべての呼び出しの外側に完全に存在する可能性があります。```
2 1
1 2 0 2
3 4 5 2
2 1
0 0
```電話は次のとおりです。`[0, 2]`そして`[5, 7]`、クエリは`[2, 3]`。 最初の通話は正確に終了します`2`、 それで`bisect_right`それを削除します。 2 回目の通話はその後に開始されます`3`、 それで`bisect_left`それを削除します。 どちらの呼び出しも除外されます。その答えは次のとおりです。`0`。 これはまさに、端点接触を重複として扱うと誤った結果が生じる状況です。
