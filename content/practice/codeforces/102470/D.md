 ## 解決策
 ## アプローチ

 簡単なアプローチは、ゲーム ツリー全体を保持することです。 両方のスコアを含む状態から、考えられるすべてのダーツ結果を試し、次の状態に移動し、再帰的に続行します。 これは正しいです。なぜなら、起こり得るそれぞれの未来がその確率で探求されるからです。 ただし、考えられる履歴の数は指数関数的に増加します。 スローごとに 20 の結果だけを考慮したとしても、数十ターンでプログラムが処理できるよりも多くの分岐がすでに作成されています。 

有益な観察は、将来は残り 2 つのスコアと誰の順番にのみ依存するということです。 どのようにしてそのスコアに到達したかを思い出す必要はありません。 ゲームは有限状態の動的プログラムです`(score of A, score of B, turn)`。 

させて`winA[a][b]`は、A の番になり、残り 2 つのスコアが次のとおりになったときに、最終的に A が勝つ確率です。`a`そして`b`。 させて`winB[a][b]`B の番のときも同じ確率になります。 

A の移行は直接的です。すべての可能なセクター ヒットに対して、A が直ちに終了するか、ゲームは A スコアの小さい B のターンに移行します。 B の移行も同様ですが、B が勝とうとしているため、B のスローが成功した場合、A の勝率に寄与する確率はゼロになります。 

非終端遷移ごとに 1 人のプレイヤーのスコアが減少するため、状態は 2 つのスコアの昇順に満たされます。 計算するとき`(a, b)`、必要な状態はすべてすでに計算されています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 投球数の指数関数 | 指数再帰ツリー | 遅すぎる |
 | 最適 | O(N² · 20) | O(N²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. A の確率分布を事前計算します。20 セクターのすべてに確率があります。`1/20`, したがって、A の分布はどの州でも同じです。 
2. 考えられる各ターゲット セクターを選択した後に B が取得する確率分布を事前計算します。 すべてのターゲットについて、ターゲット セクターとその 2 つの隣接セクターは確率を受け取ります。`1/3`。 与えられた残りのスコアについて、B はゲームを終了する可能性を最大化するターゲットを選択します。 
3. 2 つの動的プログラミング テーブルを構築します。`winA[a][b]`A がスコアを付けて投げた場合の A の勝率を格納します`a`そして`b`。`winB[a][b]`B がスローしたときに同じ値を格納します。 
4. 小さいスコアから大きいスコアまでテーブルを埋めます。 計算するとき`winA[a][b]`、考えられるすべての A ダーツの結果を調べます。 正確に削除した結果`a`ポイントを獲得すればすぐに勝利が得られます。 他の有効な結果は次の場所に移動します。`winB[a - value][b]`。 
5. 計算する場合`winB[a][b]`まず、B に最適なターゲット セクターを決定します。そのターゲットから考えられるすべての結果が考慮されます。 正確に打つ`b`は A が負けることを意味しますが、他のすべての結果は A のターンで継続されます。 
6. 入力について`N`、最初に要求された回答は`winA[N][N]`。 2つ目は`1 - winB[N][N]`、 なぜなら`winB`B が開始したときに A が勝つ確率を格納します。 

なぜ効果があるのか:

 不変条件は、各動的プログラミング エントリがそのゲーム状態からの正確な勝利確率を表すということです。 トランジションは、すべての可能なダーツの結果を、確率の合計が 1 になる相互排他的なケースに分割します。 勝てない結果はすべて 1 人のプレイヤーのスコアを減らすため、依存関係は常に計算済みの状態を指します。 考えられるすべての最初のスローとその後のすべての状態が含まれるため、計算された確率は実際のゲームの確率と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

ORDER = [20, 1, 18, 4, 13, 6, 10, 15, 2, 17,
         3, 19, 7, 16, 8, 11, 14, 9, 12, 5]

MAXN = 501

def solve():
    # A's distribution
    a_prob = [0.0] * 21
    for x in ORDER:
        a_prob[x] += 1.0 / 20.0

    # For every score, compute B's best distribution.
    # b_probs[score] is a list of (value, probability) pairs.
    b_probs = [[] for _ in range(MAXN + 1)]
    for score in range(1, MAXN + 1):
        best = None
        best_finish = -1.0
        for i in range(20):
            dist = {}
            for j in ((i - 1) % 20, i, (i + 1) % 20):
                dist[ORDER[j]] = dist.get(ORDER[j], 0.0) + 1.0 / 3.0
            finish = dist.get(score, 0.0)
            if finish > best_finish:
                best_finish = finish
                best = list(dist.items())
        b_probs[score] = best

    win_a = [[0.0] * (MAXN + 1) for _ in range(MAXN + 1)]
    win_b = [[0.0] * (MAXN + 1) for _ in range(MAXN + 1)]

    for a in range(1, MAXN + 1):
        for b in range(1, MAXN + 1):
            wa = 0.0
            for value, p in enumerate(a_prob):
                if value == 0:
                    continue
                if a - value <= 0:
                    wa += p
                else:
                    wa += p * win_b[a - value][b]
            win_a[a][b] = wa

            wb = 0.0
            for value, p in b_probs[b]:
                if b - value <= 0:
                    pass
                else:
                    wb += p * win_a[a][b - value]
            win_b[a][b] = wb

    out = []
    for line in sys.stdin:
        n = int(line)
        if n == 0:
            break
        out.append(f"{win_a[n][n]:.12f} {1.0 - win_b[n][n]:.12f}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初の部分では、A の固定投球確率を構築します。 後の遷移では削除される点の数のみが考慮されるため、配列には考えられるセクター値ごとに 1 つのエントリがあります。 

2 番目の部分では、B の決定を構築します。 考えられるすべての現在のスコアについて、コードはすべてのターゲット セクターを試し、すぐに終了する可能性が最も高いセクターを保持します。 動的プログラミングの状態は非終了スロー後の未来をすでに表しているため、これで十分です。 

2 つのネストされたループがゲームの状態を埋めます。 ループの順序が機能するのは、すべての遷移が A のスコアまたは B のスコアのいずれかを減少させるためです。そのため、状態自体や将来の状態に依存する状態は存在しません。 

最終的な出力では、`1.0 - win_b[n][n]`なぜなら、B ターン テーブルは A が勝つ確率として定義されているからです。 要求された値は反対のイベントです。 

## 実用的な例

 のために`N = 5`、初期状態は`(5,5)`。 

| 状態 | ターン | 検討中のアクション | 結果 |
 | --- | --- | --- | --- |
 | (5,5) | あ | A は 5 | を押すことによってのみ終了できます。 A は確率 0.05 ですぐに勝ちます。そうでない場合は状態が変わります。 
| (残りAスコア、5) | B | B はフィニッシュの可能性を最大化するセクターを選択します。 B ターン値が使用されます |
 | (5,5) | 最初の | 動的プログラミング値 | 0.136363636364 |

 このトレースは、オーバーシュートを削減として扱うことができない理由を示しています。 ほとんどのスローではスコアは変わりません。再帰は相手のターンに戻らなければなりません。 

のために`N = 100`、同じ繰り返しがはるかに大きな状態空間に適用されます。 

| 状態 | ターン | メイントランジション | 保存された値 |
 | --- | --- | --- | --- |
 | (100,100) | あ | 同様に可能性の高い 20 セクターの平均 |`win_a[100][100]`|
 | (a,100) | B | B の最良のターゲットを使用してスコア 100 を達成する |`win_b[a][100]`|
 | (100,100) | Bファースト | A 勝利確率を B 勝利確率に変換する | 0.950215081962 |

 2 番目のトレースは、同じ事前計算テーブルが、ゲームを再計算せずにすべての入力サイズに応答することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(501² · 20) | すべてのスコア ペアは 1 回処理され、各トランジションは最大 20 のダーツ セクターをチェックします。 
| スペース | O(501㎡) | 2 つの確率テーブルにはすべてのゲーム状態が保存されます。 

最大のテーブルには、それぞれ約 252,000 のエントリが含まれます。 操作数はわずか数百万回であり、制限内に十分収まります。

 ## 特殊なケース

 入力用`1`、動的プログラムはすべての dart 値を考慮します。 値 1 を持つセクターのみがゼロになります。 他のすべてのセクターではスコアが変わらないか高すぎるため、これらの確率は他のプレイヤーのターンまで続きます。 これにより、残りのスコア以上の値を勝利としてカウントするというよくある間違いを回避できます。 

入力用`5`、20 や 18 などのセクターはフィニッシュスローとしては役に立ちません。 トランジションにより、これらの結果のスコアは変更されません。 スコアが変化しなくてもターンは変化するため、テーブルは引き続き状態を処理します。 

入力用`501`、可能な最大の状態はまだ事前計算されたテーブル内にあります。 可能なゲーム履歴の数ではなく、可能なスコアの数が実行時間を制御するため、同じ繰り返しが機能します。
