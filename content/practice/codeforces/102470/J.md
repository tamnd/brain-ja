 ## 解決策
 ## 問題の理解

 各テストケースには小文字の文字列があります。`s`そして整数`m`。 少なくとも出現する最長の連続部分文字列を見つける必要があります。`m`回`s`。 オカレンスは重複することができます。 複数の部分文字列の最大長が同じである場合、部分文字列自体を識別する必要はありません。 最適な部分文字列のすべての出現の中で最大の開始位置を出力します。 

入力には、いくつかの独立したテスト ケースが含まれています。 テストケースの最初の行は次のようになります`m`、その後にメッセージ文字列が続きます。 を含む行`m = 0`入力を終了します。 文字列の長さは次のとおりです`m`そして`40000`したがって、単一のテスト ケースでも、すべての部分文字列を列挙して直接比較することが不可能なほど大きくなる可能性があります。 元の問題には 1 秒の時間制限と 256 MB のメモリ制限があります。 

重複条件は、出現を素として扱うアプローチを除外します。 たとえば、`s = "ababa"`そして`m = 2`、部分文字列`aba`位置で発生します`0`そして`2`。 2 つの出現は中央を共有します`a`、しかし両方ともカウントされます。 正しい出力は次のとおりです`3 2`。 出現箇所を見つけた後にその末尾を越えてジャンプする実装では、誤って 2 番目の出現箇所を見逃してしまいます。 

ケース`m = 1`も別の境界条件です。 すべての部分文字列が少なくとも 1 回出現するため、文字列全体が自動的に最適化されます。 のために`m = 1`そして`s = "abc"`、答えは`3 0`。 繰り返される部分文字列のみを中心に設計されたソリューションでは、誤って出力される可能性があります。`none`2 つ以上の出現が予想されるためです。 

空ではない有効な部分文字列が存在しないこともあります。 たとえば、`m = 3`そして`s = "abc"`、すべての 1 文字の部分文字列は 1 回だけ出現するため、3 回出現することはできません。 正しい出力は次のとおりです`none`。 不用意に実装すると、次のような事実が扱われる可能性があります。`n >= m`として十分ですが、長さ 1 の部分文字列が誤って出力されます。 

最後に、右端の出現ルールは最大長とは無関係です。 と`m = 2`そして`s = "ababa"`、 両方`aba`その出現箇所は最適な長さ 3 を持ち、右端の出現箇所は次の位置から始まります。`2`。 最初の最適な出現位置を返す`0`、間違った答えが返されます。 

## アプローチ

 直接的な解決策は、考えられるすべての部分文字列を考慮することから始まります。 がある`n(n+1)/2`位置と長さが異なるため、Θ(`n²`）の候補者。 各候補について、文字列内のすべての可能な開始位置と比較することができ、比較により Θ(`n`) 最悪の場合。 等価文字が長く続くような文字列では、ほとんどすべての比較が不一致を発見する前に最後に達します。 したがって、総作業量は Θ(`n⁴`)、先頭比較の回避策を使用`n⁴ / 12`。 で`n = 40000`、これは制限時間の許容範囲をはるかに超えています。 ハッシュを使用して部分文字列の比較を改善したとしても、単純な候補の列挙は二次形式のままです。 

問題の構造は、より強力な表現を示唆しています。 私たちは部分文字列間の任意の関係には興味がありません。 私たちは、すべての部分文字列の 2 つのプロパティ、つまりその長さと部分文字列が終了するすべての位置に注目します。 接尾辞オートマトンは、部分文字列を終了位置のセットによって正確にグループ化します。`endpos`セット。 1 つの状態で表されるすべての部分文字列はまったく同じ出現位置を持ち、その長さは 1 つの連続した間隔を形成します。`len(link[v]) + 1`を通して`len[v]`。 これはまさにここで必要な情報です。 

ある状態を仮定します`v`もっている`len[v] = 10`そしてその出現数は少なくとも`m`。 この場合、その状態によって表される最長の部分文字列の長さは 10 であり、すでに繰り返し要件を満たしています。 答えを改善できないため、同じ状態で表されるすべての短い文字列を検査する必要はありません。 複数の状態の最大値が同じ場合`len`、 彼らの`endpos`セットは、最長の代表がどこに発生するかを教えてくれるので、右端の開始位置を選択することもできます。 

すべての状態の出現数は、最初に新しく作成されたすべての非クローン状態に 1 つの出現を割り当て、クローンには 0 を割り当て、次にサフィックス リンクに沿ってカウントを減少させることによって計算できます。`len`注文。 同じ伝播で最大の終了位置を運ぶことができます。 これは、標準的なサフィックス オートマトンの出現カウント手法です。 

結果として得られるアルゴリズムは文字列長において線形です。 オートマトンのサフィックスは最大でも`2n - 1`固定小文字アルファベットの場合、その構造は線形です。

 ## アルゴリズムのチュートリアル

 1. 文字列を左から右に読みながら接尾辞オートマトンを構築します。 各州が保管する`len`、そのサフィックス リンク、その出力遷移、発生カウンタ、およびその状態について現在知られている最大の終了位置。 新しく追加された文字に対して作成された状態は、出現カウント 1 から始まり、終了位置は現在のインデックスと同じになります。 

オートマトンは、既存の遷移が表現された長さが長すぎる状態を指している場合、クローンを作成することがあります。 クローンは古い状態の遷移とサフィックス リンクをコピーしますが、クローンの作成では新しいオカレンスが導入されないため、オカレンス カウント 0 から始まります。 
2. 構築後、考えられるすべての長さを持つステートの数を数えます。 カウンティングソートを使用して増加中のすべての状態を取得します`len`注文。 どの州にもあるので、`0 <= len <= n`、この並べ替えは比較ベースではなく線形です。 

状態のサフィックスリンクの親の値は常に小さいため、後で長さを減らす必要があります。`len`。 親の前に子を処理すると、すべての状態の蓄積された情報がその親に 1 回だけ到達するようになります。 
3. 減少しながら州を横断する`len`。 ルート以外の各状態について`v`、最初にその累積された出現数を調べます。 もし`occ[v] >= m`、によって表される最長の部分文字列`v`は有効な候補であり、長さがあります`len[v]`。 
4. 適格な状態については、その最大の終了位置から右端の出現を計算します。 もし`max_end[v]`は最大の終了インデックスです。対応する最も長く表現された部分文字列は次の位置から始まります。`max_end[v] - len[v] + 1`。 

この長さが現在の回答より大きい場合は、両方の回答の値を置き換えます。 長さが等しい場合は、大きい方の開始位置を維持します。 
5. 状態を評価した後、その出現回数と最大終了位置をそのサフィックスリンクの親に伝播します。 によって表される部分文字列`v`その出現箇所はすべて、次の接尾辞の出現箇所として扱われます。`link[v]`したがって、両方の情報を転送する必要があります。 
6. 正の長さの状態が到達しない場合`m`オカレンス、印刷`none`。 それ以外の場合は、最大修飾長とその右端の開始位置を出力します。 

### なぜ効果があるのか

 重要な不変条件は、すべての接尾辞オートマトンの状態が 1 つだけを表すということです。`endpos`同等クラス。 同じ状態で表されるすべての部分文字列は、まったく同じ終了位置に出現し、そのような最長の部分文字列は長さを持ちます。`len[v]`。 発生伝播後、`occ[v]`は、によって表されるすべての部分文字列の正確な出現数です。`v`。 最大位置の伝播後、`max_end[v]`は、それらの出現の右端の終了位置です。 

したがって、すべての州は、`occ[v] >= m`長さの有効な部分文字列を 1 つ与える`len[v]`、その状態によって表される部分文字列はそれより長くすることはできません。 すべての部分文字列は何らかの状態に属しているため、最大のものを取得します`len[v]`条件を満たすすべての州を対象として、グローバルに最も長い有効な部分文字列を見つけます。 同じ長さの州の間では、`max_end[v] - len[v] + 1`は正確に右端の開始位置であるため、タイブレーク ルールも正確に処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(m, s):
    n = len(s)

    # A suffix automaton has at most 2*n states.
    max_states = 2 * n

    transitions = [{} for _ in range(max_states)]
    length = [0] * max_states
    link = [-1] * max_states

    # occ[v] is initially 1 only for newly created states.
    # Clones keep occ = 0.
    occ = [0] * max_states

    # Largest ending position belonging to the state's endpos set.
    max_end = [-1] * max_states

    size = 1
    last = 0

    for i, ch in enumerate(s):
        c = ord(ch) - 97

        cur = size
        size += 1

        length[cur] = length[last] + 1
        occ[cur] = 1
        max_end[cur] = i

        p = last

        while p != -1 and c not in transitions[p]:
            transitions[p][c] = cur
            p = link[p]

        if p == -1:
            link[cur] = 0
        else:
            q = transitions[p][c]

            if length[p] + 1 == length[q]:
                link[cur] = q
            else:
                clone = size
                size += 1

                length[clone] = length[p] + 1
                link[clone] = link[q]
                transitions[clone] = transitions[q].copy()

                # The clone represents the same end positions as q
                # before later occurrence propagation.
                max_end[clone] = max_end[q]

                # A clone is not a newly observed occurrence.
                occ[clone] = 0

                while p != -1 and transitions[p].get(c) == q:
                    transitions[p][c] = clone
                    p = link[p]

                link[q] = clone
                link[cur] = clone

        last = cur

    # Counting sort states by len.
    count = [0] * (n + 1)
    for v in range(size):
        count[length[v]] += 1

    for i in range(1, n + 1):
        count[i] += count[i - 1]

    order = [0] * size
    for v in range(size - 1, -1, -1):
        lv = length[v]
        count[lv] -= 1
        order[count[lv]] = v

    best_len = 0
    best_pos = -1

    # Reverse order gives decreasing length.
    for idx in range(size - 1, 0, -1):
        v = order[idx]

        if occ[v] >= m:
            cur_len = length[v]
            cur_pos = max_end[v] - cur_len + 1

            if cur_len > best_len:
                best_len = cur_len
                best_pos = cur_pos
            elif cur_len == best_len and cur_pos > best_pos:
                best_pos = cur_pos

        parent = link[v]

        if parent >= 0:
            occ[parent] += occ[v]
            if max_end[v] > max_end[parent]:
                max_end[parent] = max_end[v]

    if best_len == 0:
        return "none"

    return f"{best_len} {best_pos}"

def solve():
    out = []

    while True:
        line = input()
        if not line:
            break

        m = int(line)
        if m == 0:
            break

        s = input().strip()
        out.append(solve_case(m, s))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```建設は維持します`last`、これまでに処理されたプレフィックス全体に対応する状態。 新しい文字が追加されると、`cur`新しい最長のプレフィックスを表します。 最初のサフィックスリンク ループは、以前は存在しなかったすべてのサフィックス状態に新しい遷移を追加します。 

移行の競合には 2 つの可能性があります。 もし`len[p] + 1 == len[q]`、既存の状態`q`すでに正確に必要な長さを持っているので、`cur`直接リンクできます。 さもないと、`q`部分文字列の長さの範囲が広すぎます。 クローンはその範囲を分割します`len[p] + 1`、その後両方とも`cur`そして`q`クローンをサフィックスリンクターゲットとして使用できます。 

クローンは次のコピーを受け取ります`q`の変遷。 クローン作成では元の文字列に新しい位置を追加せずにオートマトンの構造が変更されるため、その出現カウンタは 0 のままです。 オカレンスは、サフィックス リンクの伝播を通じて後で回復されます。 この違いは、誤ったサフィックス オートマトンの実装の一般的な原因です。 

の`max_end`配列は次と同じ伝播ルールに従います。`occ`。 状態に位置で終わるオカレンスが含まれている場合`i`、サフィックス リンクの祖先によって表されるすべてのサフィックスも出現し、末尾は次のようになります。`i`。 より大きな状態からの処理状態`len`小さくする`len`単一の順伝播で十分になります。 

表現`max_end[v] - length[v] + 1`で表される最長の部分文字列の開始位置です。`v`右端の終了位置にあります。 インデックス付けはゼロベースで、必要な出力と一致します。 

状態の長さは 0 から 0 までの整数であるため、Python の比較ソートの代わりにカウント ソートが使用されます。`n`。 これにより、アルゴリズム全体が線形に保たれます。 Python では整数オーバーフローは発生せず、状態の最大数は以下になります。`80000`のために`n <= 40000`。

    try:

    finally:

 ## 特殊なケース

 のために`m = 1`の場合、ルート自体は空の文字列を表すため、候補とみなされません。 ルート以外のすべての状態には少なくとも 1 つの出現があり、完全な文字列に対応する状態には`len = n`。 その右端の終了位置は、`n - 1`, したがって、その開始位置はゼロです。 のために`1`そして`abc`、アルゴリズムは到達します`best_len = 3`そして`best_pos = 0`、生産`3 0`。 

不可能な繰り返しのしきい値については、次のことを考慮してください。`3`そして`abc`。 各文字の出現回数は 1 であり、長い部分文字列も 1 回だけ出現します。 伝播後、ルート以外のすべての状態は次のようになります。`occ < 3`、したがって、答えの変数は残ります`best_len = 0`そして`best_pos = -1`。 プログラムは印刷します`none`。 

重複するオカレンスについては、次の点を考慮してください。`2`そして`ababa`。 部分文字列`aba`位置で終了`2`そして`4`なので、出現回数は 2 回です。 その終了位置クラスを表す状態には、`len = 3`そして`max_end = 4`。 開始位置は、`4 - 3 + 1 = 2`、与える`3 2`。 アルゴリズムのどこにも素の仮定は現れないため、重複は自然に処理されます。 

すべて等しい文字列の場合、次の 6 つのコピーを考慮します。`c`と`m = 3`。 長さ 4 の部分文字列が開始位置に発生します`0`、`1`、 そして`2`、一方、長さ 5 は 2 回だけ発生します。 の状態`cccc`長さは 4、出現回数は 3、右端の終了位置は 5 であるため、右端の開始位置は次のようになります。`5 - 4 + 1 = 2`。 結果は`4 2`、サンプルと一致します。 

最大サイズの場合は、`40000`のコピー`a`そして要求する`20000`出来事。 長さの部分文字列`L`すべて等しい文字列が発生する`40000 - L + 1`回。 少なくとも必要なもの`20000`出来事が与える`L <= 20001`。 したがって、有効な最長の長さは次のようになります。`20001`、その右端の出現は から始まります。`40000 - 20001 = 19999`。 接尾辞オートマトンは正確に生成します`20001 19999`、許可される最大の入力と右端の位置の計算の両方を実行します。
