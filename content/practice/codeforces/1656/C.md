 ## 解決策
 ## 問題の理解

 負ではない整数の配列が与えられます。 1 回の操作で整数を選択します$x \ge 2$すべての要素を同時に置き換えます$a_i$と$a_i \bmod x$。 

この操作は、ゼロを含む任意の回数適用できます。 目的は、配列のすべての要素が同じ値を持つ状態に到達できるかどうかを判断することです。 

配列の長さは次のように大きくできます。$10^5$単一のテスト ケース内で、すべてのテスト ケースの合計の長さは最大で$2 \cdot 10^5$。 多くの可能な mod 操作をシミュレートしたり、配列の状態を調査しようとするソリューションは、直ちに除外されます。 線形に近いものが必要です。$O(n \log n)$テストケースごとに。 

この問題の興味深い部分は、モジュロ演算によって数値間の関係がどのように変化するかを理解することです。 この操作はすべての要素に一度に適用されるため、個々の値を個別に操作することはできません。 

いくつかの特殊なケースは見落とされがちです。 

考慮する：```
3
1 1 1
```答えは`YES`すべての要素がすでに等しく、ゼロ操作を実行できるためです。 

次に、次のことを考えてみましょう。```
3
0 2 5
```答えは`YES`。 選択する$x=2$与える:```
0 0 1
```そして選択する$x=2$もう一度与えます:```
0 0 1
```それで仕事は終わりではありませんが、$x=5$最初に生成されるもの:```
0 2 0
```その後$x=2$与える:```
0 0 0
```「ゼロがある場合、答えは常に NO」のような単純なルールは失敗します。 

重要な反例は次のとおりです。```
3
0 1 5
```答えは`NO`。 

ゼロは決して変わることがないので、$0 \bmod x = 0$。 値$1$また、常に変化することはありません。$x \ge 2$、```
1 mod x = 1
```したがって、ゼロと 1 は決して等しくなりません。 ゼロが存在するかどうかだけをチェックするアプローチでは、これを見逃してしまいます。 

もう 1 つの重要なケースは次のとおりです。```
4
5 9 17 5
```答えは`YES`。 

選択する$x=4$与える:```
1 1 1 1
```元の値がかなり異なっていても、係数を慎重に選択すると、それらをすぐに等しくすることができます。 

## アプローチ

 ブルートフォースの考え方では、可能な値を検索しようとします。$x$、演算を適用し、配列が最終的に単一の値に折りたたまれるかどうかを確認します。 

これは現実的ではありません。 数字は次のように大きいです$10^9$、したがって、可能なモジュライは数十億通りあります。 状態空間のほんの一部を探索することさえ不可能です。 さらに悪いことに、操作のシーケンスが異なると異なる配列が生成され、巨大な検索ツリーが作成される可能性があります。 

進歩するには、どのプロパティが決して変化しないのかを理解する必要があります。 

重要な観察は、数字の 0 と 1 が特別であるということです。 

ゼロは永続的です。 どのような係数を選択しても、$$0 \bmod x = 0.$$許容されるすべての係数が満たされるため、1 は永続的でもあります。$x \ge 2$、 それで$$1 \bmod x = 1.$$配列内に 0 と 1 の両方が存在する場合、それらは永久に異なるままになります。 すべての要素が等しい配列に到達することは不可能になります。 

ここで、配列に 0 は含まれているが 1 は含まれていないとします。 

させて$m$配列内の最小の正の値になります。 以来$m \ge 2$、選択する$x=m$のあらゆる発生を変える$m$ゼロに変換され、より大きな値は範囲内の数値になります。$[0,m-1]$。 この考えを繰り返すと、最終的にはすべての正の値がゼロになります。 ゼロの存在自体は問題ではありません。 唯一の問題は、0 と 1 の両方を同時に持つことです。 

ゼロがまったくない場合はどうなるでしょうか?

 させて$m$最低限の要素となります。 選択する$x=m$あらゆる出来事が起こります$m$ゼロになる。 以前にゼロがなかったので、新しい配列にはゼロが含まれますが、元の配列に連続する値のペアがない場合は 1 を含むことはできません。 リダクションプロセスを繰り返すと、最終的にはすべてが等しくなります。 

残りの障害は、2 つの連続する値の存在です。 配列に値が含まれている場合$k$そして$k+1$十分なリダクションの後、それらは 0 と 1 とまったく同じように動作します。これが重要な唯一のことであることがわかります。 

受け入れられた解決策は非常にシンプルです。 

配列に 0 が含まれる場合、1 を含めることはできません。 

より一般的には、並べ替え後、隣接する 2 つの値が 1 つだけ異なる場合、答えは次のようになります。`NO`。 

それ以外の場合の答えは、`YES`。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取ります。 
2. 配列をソートします。 

並べ替えると、すべての値が昇順に配置されるため、2 つの値が 1 つだけ異なるかどうかを簡単に検出できます。 
3. 配列にゼロが含まれているかどうかを確認します。 
4. 0 が存在する場合は、ソートされた配列をスキャンして 1 を探します。 

0 と 1 の両方が存在する場合、出力`NO`。 

ゼロは決して変わらないし、１も変わらないので、決して平等になることはありません。 
5. ゼロが存在しない場合は、ソートされた順序で隣接する要素をスキャンします。 

いずれかのペアが 1 つだけ異なる場合、出力`NO`。 

連続した値は、最終的には 0 と 1 の場合と同じ障害を作成します。 
6. 前の条件がどちらもトリガーされなかった場合、出力`YES`。 

### なぜ効果があるのか

 重要な不変条件は、値 0 と 1 が一度一緒に出現すると、決してマージできないということです。 ゼロは常にゼロのままであり、1 は常に 1 のままです。 

配列にすでにゼロが含まれている場合、今後のすべての配列にもゼロが含まれます。 したがって、1 が存在すると、ゴールは直ちに不可能になります。 

ゼロがない場合、最小値を係数として選択することにより、常に最小値をゼロに減らすことができます。 2 つの数値が 1 だけ異なる場合、この縮小によって最終的に 0 と 1 の両方が作成され、不可能な構成が生成されます。 逆に、連続するペアが存在しない場合は、削減を繰り返すことで、禁止された状況を引き起こすことなく、すべての値を同じ数値にすることができます。 

したがって、問題は、配列に禁止された連続ペアが含まれているかどうかを検出することになり、ゼロが存在する場合にのみ問題となる特別な処理が行われます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        a.sort()
        
        if a[0] == 0:
            if 1 in a:
                print("NO")
            else:
                print("YES")
        else:
            ok = True
            for i in range(1, n):
                if a[i] - a[i - 1] == 1:
                    ok = False
                    break
            
            print("YES" if ok else "NO")

solve()
```最初のステップは配列をソートすることです。 並べ替え後は、連続する値が隣り合って表示されるため、正確に 1 つの違いをチェックするのは単純な線形スキャンになります。 

並べ替え後、最小値を簡単に識別できます。 それが 0 の場合、配列内のどこかに 1 が存在するかどうかだけを知る必要があります。 使用する`1 in a`合計入力サイズは次のように制限されるため、十分に効率的です。$2 \cdot 10^5$。 

ゼロがない場合、アルゴリズムはすべての隣接するペアをチェックします。 1 の差が見つかった瞬間、答えはわかります。`NO`。 

Python の整数は問題の制限をはるかに超える値を処理するため、オーバーフローの懸念はありません。 唯一微妙な点は、重複は無害であることを覚えておくことです。 ゼロの差は何の障害も生じないため、正確に 1 の差だけが問題になります。

 ## 特殊なケース

 次のことを考慮してください。```
1
3
0 1 5
```並べ替えると、次のようになります。```
0 1 5
```アルゴリズムは 0 と 1 の両方を認識し、すぐに出力します。`NO`。 

ゼロは常にゼロのままであり、1 は常に 1 のままであるため、これは正しいです。 どのような mod 操作の順序でもそれらを等しくすることはできません。 

次に、次のことを考えてみましょう。```
1
4
2 4 8 16
```ソートされた配列は変更されません。 隣接する違いは次のとおりです。```
2, 4 -> 2
4, 8 -> 4
8, 16 -> 8
```なしは 1 に等しいため、アルゴリズムは次のように出力します。`YES`。 

連続した値がないということは、数値を減らしながら、禁止された 0 と 1 の構成を回避できることを意味します。 

最後に次のことを考慮してください。```
1
5
0 2 2 10 20
```配列には 0 が含まれていますが、1 は含まれていません。 アルゴリズムの出力`YES`。 

重複は関係ありません。 ゼロの次に危険な値は 1 だけです。 これが存在しないため、すべての正の値は最終的にゼロに減らされ、配列全体が等しくなる可能性があります。
