 ## 解決策
 ## 問題の理解

 長さの隠しバイナリ配列が与えられます。$n$。 配列を直接見ることはできません。 代わりに、任意の間隔でクエリを実行できます。$[l, r]$、システムはそのセグメント内の 1 の数を返します。 この情報から、$k$左から - 番目のゼロ。 

配列には 0 と 1 のみが含まれるため、範囲合計クエリは、そのセグメント内に 1 がいくつあるかを効果的に示します。 セグメントの長さとその合計がわかっていれば、ゼロは単なる欠落しているものであるため、セグメント内にゼロがいくつあるかを推定することもできます。 

インタラクション制限は厳しく、最大 20 クエリのみです。 配列サイズは最大です$2 \cdot 10^5$, したがって、直線的にスキャンすることは不可能です。 有効なソリューションでは、対数のクエリを使用して答えを見つける必要があり、位置に対する二分探索が即座に提案されます。 

主な難しさは、固定値を検索しているのではなく、ゼロの累積数が到達する位置を検索していることです。$k$。 これは、範囲合計クエリの背後に隠されたプレフィックスベースの条件です。 

単純な間違いは、特定の位置が見つかるまで個々の位置をテストできると考えることです。$k$-番目のゼロ。 それには最大で$O(n)$最悪の場合、制限をはるかに超えるクエリが実行されます。 もう 1 つの微妙な間違いは、クエリ結果をゼロへの直接アクセスとして誤解することです。 1 のみを与えるため、セグメント長による変換を忘れると、誤ったプレフィックス ロジックが発生します。 

たとえば、配列が次の場合、$[1, 0, 1, 1, 0, 1]$そして$k=2$、答えは位置 5 です。単純なスキャンでは位置 2 と 5 でゼロが検出されますが、範囲推論がなければ、多くのソリューションはこれを効率的に構築できません。 

## アプローチ

 ブルート フォースのアイデアは単純です。各位置またはプレフィックスをクエリしてゼロを数えながら、左から右に歩きます。 位置がゼロかどうかを知る必要があるたびに、個別にクエリを実行します。 すべてのクエリが単一の要素を分離するため、これは論理的に機能しますが、最大で$n$テストケースごとのクエリ。 と$n$まで$2 \cdot 10^5$、これは遅すぎます。 

重要な観察は、プレフィックス内のゼロの数が単調であるということです。 関数を定義すると$Z(x)$ゼロの数として$[1, x]$、 それから$Z(x)$として増加するだけです$x$が増加します。 最小の位置を探しています。$Z(x) \ge k$。 これはまさに二分探索条件です。 

ゼロを直接クエリすることはできませんが、1 から計算することはできます。 プレフィックスの場合$[1, x]$1 の合計をクエリすると、0 は次のようになります。$x - \text{ones}(1, x)$。 これにより、二分探索が可能な単調関数が得られます。 

したがって、問題は、範囲合計クエリを使用して位置に対して二分検索を実行し、$k$-番目のゼロは中点の左側または右側にあります。

 ## アルゴリズムのチュートリアル

 最小のインデックスを見つけたい$x$少なくとも存在するように$k$接頭辞のゼロ$[1, x]$。 

1. 検索境界を初期化する$l = 1$、$r = n$。 これらは、答えが存在するはずの範囲を表します。 
2. その間$l < r$、中点を計算します$m = (l + r) // 2$。 答えが左半分にあるのか右半分にあるのかをテストしています。 
3. セグメントの合計を問い合わせる$[1, m]$。 これをそのままにしておきます$S$。 このプレフィックスのゼロの数は、$m - S$。 これにより、問題は「1 ベースのフィードバック」から直接のゼロカウントに変換されます。 
4. もし$m - S \ge k$、その後、$k$-番目のゼロはそれ以前です$m$したがって、右の境界を移動します。$r = m$。 それ以外の場合は、厳密に右側にあるため、次のように設定します。$l = m + 1$。 
5. ループが終了すると、$l = r$プレフィックスに少なくとも次の内容が含まれる最小の位置です。$k$ゼロ。 その立場が答えです。 

重要な不変条件は、すべてのステップで真の答えが内部に残っているということです$[l, r]$、および述語「プレフィックスには少なくとも次のものが含まれます」$k$ゼロ」は単調です。プレフィックスが条件を満たすと、それより大きなプレフィックスもすべて条件を満たすため、二分探索は有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(l, r):
    print("?", l, r)
    sys.stdout.flush()
    s = int(input().strip())
    if s == -1:
        sys.exit(0)
    return s

n, t = map(int, input().split())

for _ in range(t):
    k = int(input().strip())

    l, r = 1, n
    while l < r:
        m = (l + r) // 2
        ones = ask(l, m)
        zeros = (m - l + 1) - ones

        if zeros >= k:
            r = m
        else:
            k -= zeros
            l = m + 1

    print("!", l)
    sys.stdout.flush()
```この実装は二分探索を実行しますが、右に移動するときに「消費」されるゼロの数を追跡することでわずかに最適化されています。 完全なプレフィックス条件を再計算する代わりに、次のように調整します。$k$左側のセグメントを削除して、縮小した検索ウィンドウとロジックの一貫性を持たせます。 

対話型の処理は重要です。すべてのクエリは即座にフラッシュされ、-1 を受け取ると終了します。

 ## 特殊なケース

 重要なエッジケースは、配列が多数の 1 で始まる場合です。 例えば、$[1, 1, 1, 0]$と$k=1$。 二分検索では、初期のプレフィックスに有効なゼロが含まれていないことを認識して、先頭のすべてを正しくスキップする必要があります。 述語`zeros >= k`最後のセグメントまで false のままとなり、検索が最終インデックスまで正しく折りたたまれます。 

もう 1 つのエッジ ケースは、次のように先頭にゼロが密に詰め込まれている場合です。$[0, 0, 0, 1, 1]$と$k=2$。 ここでは、正解は前半の内側にあり、アルゴリズムは一貫して右半分を早い段階で破棄する必要があります。 プレフィックス ゼロ カウントの単調性により、中間点プレフィックスに少なくとも次の値が含まれることが保証されます。$k$ゼロの場合、より大きなインデックスはすべて有効な候補のままであるため、有効な答えが誤って除外されることはありません。
