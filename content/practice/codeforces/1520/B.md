 ## 問題の理解

 複数のクエリが与えられ、各クエリは 1 つの正の整数で構成されます。$n$。 それぞれについて$n$1 から 1 までの範囲にある数字がいくつあるかを数える必要があります。$n$10 進表現ではすべての桁が同一になります。 

これらの「普通の」数値は非常に厳格な構造を持っています。 有効な数字はすべて、1 から 9 までの数字を選択し、それを 1 回以上繰り返すことによって形成されます。 したがって、有効な例には 7、88、444、999999999 が含まれますが、10、101、123 などの数値は少なくとも 2 桁が異なるため除外されます。 

制約$n \le 10^9$は、各数値が最大 10 桁であることを意味します。 これが重要な構造上の制限です。全体的に考えられる通常の数は少数しかなく、すべての整数の範囲内でそれらは非常にまばらです。 

素朴なアプローチは、1 から 2 までのすべての数値をチェックすることです。$n$、すべての桁が等しいかどうかを確認します。 これには以下の検査が必要になります。$10^9$最悪の場合のクエリあたりの数。これは、与えられた許容範囲をはるかに超えています。$t \le 10^4$。 テストケースごとにリニアスキャンさえ不可能です。 

エッジケースが発生するのは次の場合です$n$小さいか、通常の数値と完全に一致します。 たとえば、次の場合$n = 5$、一桁の数字はどれも普通なので、答えは 5 です。 もし$n = 10$、10 は普通ではないので、答えは 9 のままです。 桁の長さにのみ基づいてカウントする不注意なアプローチでは、10 またはその他の混合桁の数字が誤って含まれる可能性があります。 

主な微妙な点は、答えが分布や算術特性に依存しないことを認識していることです。$n$ただし、純粋に、非常に小規模な構造化された候補者のセットを数えているだけです。 

## アプローチ

 ブルートフォースソリューションでは、1 から 2 までを繰り返します。$n$、各数値を文字列に変換し、すべての文字が同一かどうかを確認します。 これは定義に直接従うため、単純かつ正しいです。 ただし、そのコストは次のとおりです。$n \log n$数字チェックのため、テスト ケースごとにテストが実行されなくなります。$n$到達する$10^9$そして$t$大きいです。 

重要な観察は、通常の数値が固定された組み合わせ構造を持っているということです。 1 から 9 までの各桁について、1、11、111、1111 などの数字を構成できます。 固定長の場合$k$、通常の数字はちょうど 9 つあります。1 から 9 までの各桁に 1 つずつあります。問題は、以下の数字がいくつあるかを数えるということになります。$n$。 

すべての整数を反復処理する代わりに、これらの構造化された候補のみを生成します。 最大 9 桁、最大 10 の長さがあるため、候補の総数は 90 に制限されます。これにより、各クエリが小さな固定セットに対する定数時間のスキャンに変わります。 

ブルート フォースはすべての数値を明示的にチェックするため機能しますが、宇宙が巨大であるため失敗します。 通常の数値は桁の選択と長さによって完全に決定されるという観察により、検索空間が線形から崩壊します。$n$一定のサイズに。

 ## アルゴリズムのチュートリアル

 私たちは、数字を選択してそれを繰り返すことで、あらゆる普通の数値を生成できるという事実を利用します。 

1. 以下のすべての通常の数値を事前計算します。$10^9$1 から 9 までの数字の選択を繰り返し、長さが増加する繰り返し数字を構築します。 

各構築は 0 から開始して同じ数字を繰り返し追加することによって行われ、値が幾何学的に増加します。 
2. 生成されたすべての値をリストに保存します。 
3. 二分検索または単純なカウントを使用してクエリに答えられるように、リストを並べ替えます。 
4. 各クエリについて$n$、以下の事前計算値がいくつあるかを数えます。$n$。 

カウントのステップは事実上、ソートされた静的配列に対するプレフィックス クエリであり、対数時間での二分探索で実行できますが、90 要素にわたる線形スキャンでも十分です。 

### なぜ効果があるのか

 すべての通常の数値は、ペア (桁、長さ) に一意に対応します。 異なる桁長の構成では常に異なる整数が生成されるため、重複はありません。 このようなペアはすべて、次のような桁制限内で徹底的に生成されるため、$10^9$、事前に計算されたセットは、有効な回答の世界と正確に一致します。 最終的なカウント$n$したがって、これはこの完全なセット内の要素の数を超えないものにすぎません。$n$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Precompute all ordinary numbers up to 1e9
ordinaries = []

for digit in range(1, 10):
    val = 0
    for _ in range(10):  # max 10 digits because n <= 1e9
        val = val * 10 + digit
        ordinaries.append(val)

ordinaries.sort()

t = int(input())
for _ in range(t):
    n = int(input())
    
    # count how many are <= n
    cnt = 0
    for x in ordinaries:
        if x <= n:
            cnt += 1
    print(cnt)
```コードは、数字を固定し、それを繰り返し追加することによって、すべての候補の普通数を構築します。 生成された各値はグローバル リストに保存され、単調なクエリのために並べ替えられます。 

テスト ケースごとに、事前に計算されたリストを繰り返し処理し、以下の値の数を数えます。$n$。 リストのサイズはわずか 90 であるため、これは実質的にクエリごとに一定の時間になります。 

よくある実装上の間違いは、次の桁の長さまでの数値のみを生成しようとすることです。$n$クエリごとに動的に。 これにより、ロジックが不必要に複雑になり、10 のべき乗などの境界値を処理するときに 1 ずつずれたエラーが発生する危険があります。 事前計算により、そのような問題がすべて回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(t)$| 各テスト ケースは最大 90 個の事前計算値をチェックします。 
| スペース |$O(1)$| 通常の数値の固定リストのみが保存されます。 

制約により、最大で$10^4$各クエリは一定の作業を実行します。 このソリューションは、時間とメモリの制限内に無理なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    ordinaries = []
    for digit in range(1, 10):
        val = 0
        for _ in range(10):
            val = val * 10 + digit
            ordinaries.append(val)
    ordinaries.sort()

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        cnt = 0
        for x in ordinaries:
            if x <= n:
                cnt += 1
        out.append(str(cnt))
    return "\n".join(out)

# provided samples
assert run("6\n1\n2\n3\n4\n5\n100\n") == "1\n2\n3\n4\n5\n18"

# minimum size
assert run("1\n1\n") == "1"

# boundary around 10
assert run("2\n9\n10\n") == "9\n9"

# exact ordinary number
assert run("1\n111\n") == "3"

# large value
assert run("1\n1000000000\n") == "90"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 1 | 可能な最小の入力 |
 | 9 / 10 | 9 / 9 | 非通常数を超える境界 |
 | 111 | 3 | 複数桁の繰り返しカウント |
 | 1e9 | 90 | 上限を完全にカバー |

 ## 特殊なケース

 のために$n = 10$の場合、10 は繰り返される数字ではないため、アルゴリズムは 1 ～ 9 のみをカウントします。 事前に計算されたリストには 11 が含まれているため、カウント中に 11 は正しく除外されます。$n$。 

のために$n = 999999999$、1 桁から 9 桁までのすべての繰り返し番号が含まれます。 アルゴリズムは、事前に計算された 90 個の値すべてを反復処理し、すべてをカウントして 90 を生成します。 

のために$n = 1$、リストの最初の要素のみが寄与します。 生成されるその他の値はすべて 1 より大きいため、結果は正確に 1 のままになります。
