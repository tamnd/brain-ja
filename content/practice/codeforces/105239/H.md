 ## 解決策
 ## 問題の理解

 3 つの独立した石の山でプレイされる小さな組み合わせゲームが与えられます。 各移動は、正確に 1 つの山を選択し、そこからいくつかの石を取り除くことで構成されます。 除去される石の数は、入力で指定された固定の許容セットに属している必要があります。 プレーヤーは交互に手を動かし、正当な手を打てなかったプレーヤーが負けます。 

タスクは、3 つのパイル サイズによって定義される開始位置が、最適なプレイの下で最初のプレーヤーにとって勝っているか負けているかを判断することです。 

杭は 3 つありますが、重要な構造特性は、動きが杭間で相互作用しないことです。 各パイルは独立して進化し、移動は状態の 1 つの座標にのみ影響します。 これは、公平なゲームの選言的合計の典型的な特徴です。 

制約は非常に小さく、各パイル サイズは最大 100 であり、移動セットのサイズもその最大値によって制限されます。 これにより、完全な状態にわたる指数関数的なゲーム ツリーの探索が即座に除外されます。これは、単純な再帰はメモ化せずに状態を繰り返し再訪し、境界が小さいため原理的には引き続き実行可能ですが、構造を考慮すると不要であるためです。 

パイルが小さすぎて許可された移動を実行できない場合、微妙なエッジケースが発生します。 たとえば、許可された移動が {3, 5} で、パイルのサイズが 2 の場合、そのパイルは正当な移動には寄与しません。 すべての山がこの状況にある場合、現在のプレイヤーは即座に負けます。 少なくとも 1 つのパイルが常にプレイ可能であると仮定する単純なシミュレーションでは誤って再帰が継続される可能性があるため、これは重要です。 

もう 1 つの重要な状況は、移動セットに 1 が含まれている場合です。この場合、すべての正の山は常に段階的に削減可能であり、通常、グランディ値の周期的または単調な動作につながります。 スパースな遷移を想定した誤った DP は機能する可能性がありますが、完全な遷移構造を見落とす危険があります。 

## アプローチ

 ブルートフォース手法では、各状態をトリプル (n1、n2、n3) で定義されるゲーム グラフ内のノードとして扱います。 あらゆる状態から、すべての正当な手を列挙します。各パイルについて、パイル サイズを超えない許容される各 AI を減算し、結果の位置を再帰的に評価します。 少なくとも 1 つの手が負け状態につながる場合、その状態は勝利しています。 

これにより、状態空間のサイズは最大 1013、つまり約 100 万の状態になります。 各状態には最大 3,000 個の遷移があり、k は最大 100 なので、状態ごとにおよそ 300 個の遷移があります。 これにより、最悪の場合、約 3 億のエッジが生成され、単純な再帰ではメモ化せずに状態を繰り返し再計算することになり、非常に遅くなります。 メモ化を行ったとしても、その構造は、標準的な公平なゲーム DP を再計算していることを示唆しており、体系的に処理する方が適切です。 

重要な洞察は、これが同一のサブゲーム (山ごとに 1 つ) の素の合計であるということです。 各山は独立した減算ゲームです。サイズ x の山から、許容される ai ≤ x については x - ai に移動できます。 このようなゲームは、最大までのすべてのヒープ サイズのグランディ数を計算することで解決されます。 

単一の山の Grundy(x) を計算すると、完全なゲーム状態 (n1、n2、n3) は 3 つの山の Grundy 値の XOR に等しい Grundy 値を持ちます。 これは、公平なゲームに関する Sprague-Grundy の定理に従います。 この XOR が 0 の場合、開始位置は最初のプレーヤーの負けとなります。 

したがって、問題は、単一次元にわたる標準 DP を計算し、次に 3 つの値を組み合わせることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースゲーム検索 | O(状態 × 遷移) ≈ O(10^6 × 300) | O(10^6) | 遅すぎる |
 | グランディ DP + XOR | O(n · k + n1 + n2 + n3) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、0 から n1、n2、および n3 の最大値までのすべての杭サイズのグランディ数を計算します。

各値 x について、適用できるすべての動き ai を調べます。 各移動は到達可能な位置 x - ai につながり、したがって到達可能な状態のグランディ値のセットが得られます。 

x のグランディ値は、到達可能な値の中に存在しない最小の非負の整数として定義されます。 

この配列を計算した後、Grundy(n1)、Grundy(n2)、および Grundy(n3) の XOR を取ることによって最終状態を評価します。 結果がゼロの場合、そのポジションは最初のプレーヤーの負けです。 それ以外の場合は勝ちです。 

### なぜ効果があるのか

 各パイルは独立した公平なゲームであるため、ゲーム全体はそれらの論理和になります。 Sprague-Grundy 定理は、そのようなすべてのゲームに Grundy 値を割り当てることができること、およびコンポーネント Grundy 値の XOR が勝敗状態を完全に特徴付けることを保証します。 DP 構造により、各 Grundy(x) がそのパイル サイズからの可能なすべての手を正しくエンコードすることが保証されるため、到達可能なオプションが省略されたり、到達不可能な値が mex 計算に含まれたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n1, n2, n3 = map(int, input().split())
    k = int(input())
    moves = list(map(int, input().split()))

    max_n = max(n1, n2, n3)

    grundy = [0] * (max_n + 1)

    for x in range(1, max_n + 1):
        reachable = set()
        for a in moves:
            if a <= x:
                reachable.add(grundy[x - a])
        g = 0
        while g in reachable:
            g += 1
        grundy[x] = g

    result = grundy[n1] ^ grundy[n2] ^ grundy[n3]

    if result == 0:
        print("Vasya")
    else:
        print("Peter")

if __name__ == "__main__":
    main()
```DP アレイ`grundy`単一の山サイズのグランディ値を保存します。 サイズごとに、許可された各移動を減算することによって生成される、到達可能なすべての状態を収集します。 mex の計算はインクリメントによって行われます。`g`到達可能なセット内で見つからなくなるまで。 値は最大 100 で制限されるため、これは小規模です。 

最後の XOR は、3 つの独立したパイルを結合します。 出力は、XOR がゼロかどうかに直接応じて決まります。 

## 実用的な例

 ### 例 1

 入力:```
1 1 1
1
1
```グランディ値を 1 まで計算します。 

| × | 到達可能 | グランディ(x) |
 | --- | --- | --- |
 | 0 | {} | 0 |
 | 1 | {0} | 1 |

 次に、以下を評価します。 

グランディ(1) XOR グランディ(1) XOR グランディ(1) = 1 XOR 1 XOR 1 = 1。 

したがって、結果は最初のプレーヤーである出力ピーターの勝ちです。 

これは、石を 1 つ削除するだけで、ゲームがサイズ 1 の標準 Nim ヒープと同様に動作し、3 つの同一のヒープがゼロ以外の XOR を生成することを確認します。 

### 例 2

 入力:```
10 10 10
2
3 4
```グランディは 10 までしか考慮しません。DP は 3 または 4 を引くことに基づいて値を構築します。 

| × | x から到達可能 | グランディ(x) |
 | --- | --- | --- |
 | 0 | {} | 0 |
 | 1 | {} | 0 |
 | 2 | {} | 0 |
 | 3 | {0} | 1 |
 | 4 | {0} | 1 |
 | 5 | {1} | 0 |
 | ... | ... | ... |

 このテーブルから Grundy(10) を計算し、3 つの同一の値の XOR を計算します。 すべての山は同一であるため、XOR は相殺され、ゼロになります。 

したがって、出力はVasyaです。 

これは対称性を示しています。同一のヒープは、Grundy 値が一致すると XOR でキャンセルされます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n・k) | max(n1, n2, n3) までのパイル サイズごとに、許可されるすべての動きを反復し、小さなセットで mex を計算します。 
| スペース | O(n) | すべてのヒープ サイズの Grundy 値を最大パイル サイズまで保存します。 

最大パイルサイズは 100 であるため、DP は非常に小さいです。 k が 100 までの場合でも、合計の操作は 1 秒の制限内で無視できます。

 ## 特殊なケース

 重要なエッジケースは、すべての山がゼロの場合です。 入力は次のとおりです。```
0 0 0
...
```移動は不可能なので、現在のプレイヤーは即座に負けます。 DP はすべての山に Grundy(0) = 0 を割り当てるため、XOR は 0 となり、出力は Vasya となり、負け条件と一致します。 

もう 1 つのケースは、ムーブ セットに大きな値のみが含まれている場合です。次に例を示します。```
3 3 3
1
5
```どのパイルも移動できないため、x < 5 の場合、ゼロを超えるすべてのグランディ値はゼロのままです。計算により、各パイルのグランディ(3) = 0 が得られ、XOR はゼロになります。 アルゴリズムは Vasya を正しく出力します。 

最後の微妙なケースは、k = 1 および a1 = 1 の場合です。この場合、すべての正のヒープには、ゼロまで強制的に移動するチェーンが含まれます。 DP は交互の Grundy 値を生成し、XOR ルールは Grundy シーケンスでエンコードされたパリティに基づいて勝利状態を正確に識別します。
