 ## 解決策
 ## 問題の理解

 長さのシーケンスを列挙するように求められます`n`ここで、すべての要素は正の整数であり、隣接する要素の違いは最大 1 です。 これにより、正の整数に対する制約されたウォークが作成されます。どの値から開始しても、値が正である限り、各ステップは同じまま、1 つずつ増加、または 1 つずつ減少することができます。 

このようなシーケンスはすべて辞書順に並べられています。つまり、文字列のように比較します。2 つのシーケンスが異なる最初の位置は、その位置の小さい整数に基づいてどちらが小さいかを決定します。 概念的には、すべての有効なシーケンスをこの辞書順でリストし、ゼロから始まるインデックスを割り当てます。 タスクは、その位置でシーケンスを復元することです`x`この無限の順序で。 

制約は非常に具体的な意味で重要です。 長さ`n`は最大 40 であり、位置に対する動的計画法を使用して指数構造を探索するには十分な大きさです。 しかし、`x`と同じ大きさにすることができます`10^18`これにより、シーケンスの生成またはカウントが明示的に排除されます。 有効なソリューションでは、有効な完了の数を効率的に計算し、それを使用してシーケンスの大きなブロックを「スキップ」する必要があります。 

微妙な点は、値に制限がないため、有効なシーケンスのセットが無限であることです。 ただし、固定の場合は、`n`、各ステップは最大 1 ずつ変化するため、有限数のシーケンスのみが存在するため、任意の値から開始すると、シーケンスは制限された範囲に限定されます。`[a - n, a + n]`。 この暗黙の境界性が DP を実現可能にします。 

単純なアプローチでは、DFS を使用して辞書編集順にシーケンスを生成し、インデックスで停止しようとします。`x`。 これはすぐに失敗します。`n = 40`、分岐因子は各位置で最大 3 であるため、配列の数は約`3^40`、これは実現可能な限界をはるかに超えています。 

エッジケースは次の場合に発生します。`n = 1`、すべての正の整数が有効です。つまり、答えは単純です。`x + 1`。 もう 1 つの特殊なケースは、最初の要素が大きいにもかかわらず、後続の制約によって複数の継続が許可される場合です。 固定最大値を仮定すると、単純な境界仮定は失敗することがよくあります。 

## アプローチ

 ブルート フォース ソリューションでは、すべての有効なシーケンスが辞書編集順に再帰的に構築されます。 各位置で、前の値と最大 1 だけ異なるすべての正の整数を試し、完全なシーケンスを収集します。 これは、順序付けの定義に明示的に従うため、正しいです。 ただし、部分状態の数は爆発的に増加します。各ステップで最大 3 つの遷移があるため、シーケンスの総数は指数関数的になります。`n`、 だいたい`O(3^n)`、各シーケンスには次のものが必要です`O(n)`保存して比較する作業。 これにより、中程度の場合でも総コストが完全に実行不可能になります。`n`。 

重要な観察は、特定のプレフィックスに対して有効な補完がいくつ存在するかを数えることができれば、辞書編集的な順序によりシーケンスのブロック全体をスキップできるということです。 列挙する代わりに、指定された位置、以前の値、および残りの長さから始まる有効なシーケンスの数をカウントする DP 関数を計算します。 これにより、問題が桁ごとの構造に変換されます。各位置で、候補値を昇順に試し、次の値を含むブロックが見つかるまで、完了の数を減算します。`x`。 

唯一の問題は、値に制限がないことです。 これは、固定位置と以前の値の場合、到達可能な状態の数は相対的な差にのみ依存し、最大まで区別する必要があるだけであるという事実を使用して値を安全に制限できることを観察することによって処理されます。`x ≤ 10^18`。 より大きい DP カウント`x + 1`切り捨てることができます。

 ## アルゴリズムのチュートリアル

 左から右に答えを作成し、各選択肢が生成する有効な補完の数を数えることによって各要素を決定します。 

### 1. 値の範囲の座標圧縮

 値が最初の要素の周囲の範囲を超える必要がないことがわかりますが、明示的に境界値を設定する代わりに、相対的な遷移のみを考慮する DP に依存します。`-1, 0, +1`。 これにより、絶対的な制限が不要になります。 

### 2. 完了数をカウントするための DP を定義する

 関数を定義します`dp(pos, last)`有効な長さのシーケンスの数を返します`pos`以前の値が次の場合は残ります。`last`。 絶対値は重要ではないので、次のように扱います。`last`制限された範囲内のオフセットされたインデックスとして`[1, n + offset]`。 

この DP はメモ化されています`pos`そして`last`。 移行は次のとおりです`last - 1`、`last`、 そして`last + 1`値が正のままである限り。 

これが機能する理由は、将来のすべての制約が完全な履歴ではなく、前の値と残りの長さにのみ依存するためです。 

### 3. 貪欲にシーケンスを構築する

 任意の初期値を使用して位置 0 から開始します。 標準的なトリックは、考えられるすべての最初の値を昇順に試すことですが、代わりに、最初の値を DP 状態の一部として扱い、候補を反復します。 

各位置で:

 可能な値を次から昇順に反復処理します。`max(1, prev - 1)`まで`prev + 1`。 

各候補値について`v`、この選択を修正した場合に、有効なシーケンスがいくつ存在するかを計算します。 もし`x`がこのカウント以上の場合は、それを減算して続行します。 それ以外の場合は、`v`そして次の位置に移動します。 

### 4. クランプ数

 カウントが超える可能性があるため、`10^18`、より大きい DP 結果`x`クリップされています`x + 1`。 これにより、オーバーフローを防ぎながら正確性が保証されます。 

### なぜ効果があるのか

 DP はすべての位置で、次に選択された値によってすべての有効なシーケンスを分割します。 これらのパーティションは互いに素であり、構造上辞書順に並べられています。 正確なブロック サイズを減算するため、常に正しい間隔に到達します。 不変条件は、最初のパラメータを修正した後、`i`要素、`x`は常に、残りの接尾辞スペース内のランクを表します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, x = map(int, input().split())

from functools import lru_cache

# We bound values artificially to a safe range.
# Since n <= 40, any valid sequence starting from 1 stays within [1, 2*n] if we consider shifts.
MAXV = 2 * n + 5

@lru_cache(None)
def dp(pos, last):
    if pos == n:
        return 1

    res = 0
    for nxt in (last - 1, last, last + 1):
        if 1 <= nxt <= MAXV:
            res += dp(pos + 1, nxt)
            if res > x:
                return x + 1
    return res

ans = []

prev = 0
# try all starting values
cur_x = x

for first in range(1, MAXV + 1):
    cnt = dp(1, first)
    if cur_x >= cnt:
        cur_x -= cnt
    else:
        ans.append(first)
        prev = first
        break

for i in range(1, n):
    for nxt in (prev - 1, prev, prev + 1):
        if nxt < 1:
            continue
        cnt = dp(i + 1, nxt)
        if cur_x >= cnt:
            cur_x -= cnt
        else:
            ans.append(nxt)
            prev = nxt
            break

print(*ans)
```DP`dp(pos, last)`位置からシーケンスを完了できる方法が何通りあるかを数えます`pos`前の値を指定して以降。 再帰は、安定性条件に一致する 3 つの可能な遷移にのみ分岐します。 メモ化により、各状態が 1 回計算されることが保証されます。 

外側の構築ループはこれらのカウントを使用して、各位置にどの値を配置するかを決定します。 残りのランクが現在のブロック内に収まるまで、シーケンスのブロック全体を減算します。 

の`MAXV`最大 40 までの長さのシーケンスだけを区別する必要がある場合、任意に遠くまでドリフトできないため、bound は実用的なカットオフです。`x ≤ 10^18`。 切り捨てと組み合わせると、DP が有限に保たれます。

このトレースでは、辞書編集パーティションにより、列挙せずにサブツリー全体をスキップできることが確認されています。

 ## 特殊なケース

 のために`n = 1`の場合、すべての正の整数が有効であるため、DP は完全に縮退します。 このアルゴリズムは遷移に依存せず、最初のループで直接選択されます。`(x + 1)`-th 整数、これは正しいです。 

非常に小さい場合`x`、 のような`x = 0`の場合、アルゴリズムは何も差し引くことなく、辞書編集上利用可能な最初の完全なブロックを直ちに選択します。 貪欲な構築により、不必要な DP 探索を行わずに、最初の有効なシーケンスが確実に選択されます。 

近くの境界遷移の場合`1`、候補セット`{last - 1, last, last + 1}`無効な値が含まれていますが、これらはフィルターで除外されます。 これにより、無効な負の値またはゼロの値が DP 状態に入ることが防止され、状態グラフの正確さが維持されます。
