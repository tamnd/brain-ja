 ## 解決策
 ## 問題の理解

 一列に並べられた一連のカップが与えられます。 各カップには、飲んだときのリラックス度を表す値が設定されています。 エフゲニーはカップがなくなるまで繰り返しカップを取り除きますが、毎回、残っているカップの左端か右端のどちらかしか取ることができません。 

おもしろいのは、カップの利点はその本質的な価値だけではないということです。 彼が飲む順番は重要です。 彼が飲む最初のカップはその値に 1 を乗算し、2 番目のカップにはその値に 2 を乗算し、以下同様に寄与します。 選択されたカップの順序が$x_1, x_2, \dots, x_n$、完全なリラクゼーションは$\sum i \cdot x_i$。 

目標は、この加重合計を最大化する一連の左右の削除を選択することです。 

制約$n \le 5000$二次動的計画法ソリューションには十分小さいですが、すべてを試すアプローチには大きすぎます。$2^n$左右の決断。 間隔にわたる 3 次 DP であっても、不注意に実装すると遅すぎます。$n^3$近づくだろう$1.25 \times 10^{11}$。 

乗数が元の配列内の位置ではなくグローバル順序に依存するという事実から、微妙な問題が発生します。 「常に大きいほうを採用する」などの素朴な貪欲な戦略は失敗します。初期の大きな値は、後の乗数の位置に遅らせるよりも価値が低い可能性があるためです。 

簡単な反例は次のとおりです$[1, 100, 1]$。 貪欲に摂取する：

 - 最初に 100 個を選択$1 \cdot 100 = 100$、その後 2 つが貢献します$2 \cdot 1 + 3 \cdot 1 = 5$、合計105。 

ただし、最初に 1 を取るのが最適です。 
- 1 を選択し、次に 100 を選択し、次に 1 を選択すると、$1 + 2 \cdot 100 + 3 = 204$、どちらの方が良いです。 

したがって、この構造は局所的に貪欲ではありません。 それは、時間の経過とともにエンドポイントがどのように対話するかによって異なります。 

## アプローチ

 ブルート フォースのビューは単純です。各ステップで、左を選択するか右を選択するかの 2 つの選択肢があり、シーケンスを追跡します。 これにより、高さの二分決定木が構築されます。$n$、生産$2^n$シーケンス。 各シーケンスについて、重み付けされた合計を計算します。$O(n)$、与える$O(n2^n)$、でもそれは不可能です$n=30$。 

重要な点は、重要な状態は配列のどのセグメントが残っているかだけであるということです。 セグメントを修正したら$[l, r]$、未来は、すでに取られている要素の数を除いて、以前の決定とは独立しています。 このカウントにより、次のピックの乗数が決まります。 

そこで、インターバルにわたる DP を定義し、すでに取得された要素の数を明示的に追跡します。 これにより、問題は、ステップ インデックスに依存するコストを蓄積しながら、次の要素が左のエンドポイントから来るか右のエンドポイントから来るかを選択することに変わります。 

各状態が間隔の境界によってのみ定義されるようにすることで、指数関数的な分岐を回避し、ステップ番号は決定論的に導出されます。

 ## アルゴリズムのチュートリアル

 DP テーブルを定義します。$dp[l][r]$インデックスから部分配列内のすべての要素を削除することで達成できる最大の全体的な緩和を表します$l$に$r$、これらの削除は、何らかのシーケンスで最後に残った操作として行われると仮定します。 

乗数効果を正しく組み込むために、サイズの部分問題を解くときにすでに削除されている要素の数を推論します。$k = r - l + 1$。 もし$n - k$要素がすでに取得されている場合、次に選択された要素には乗数が設定されます$n - k + 1$。 この値を状態で明示的に運ぶ代わりに、間隔を縮小するときに寄与が適用されるように DP を構造化します。 

## アルゴリズムのチュートリアル

 1. 定義する$dp[l][r]$部分配列から得られる最大の寄与として$a[l..r]$これらの要素がプロセスの最後に消費されるとき。 この再構成により、DP を内側から外側へ最終シーケンスを構築するものとして扱うことができます。 
2. 基本ケースを初期化します。$l = r$。 要素が 1 つだけ残っている場合、その要素はそのサブ問題の最後に取得されるため、その寄与は単にその値に全体の順序内の正しい位置を乗算したものになります。これは状態の結合方法によって暗黙的に処理されます。 
3. 2 から 3 までの間隔の長さごとに、$n$、すべての値を計算します$l, r$と$r - l + 1 = len$。 
4. インターバルごとに$[l, r]$、この間隔から最後に削除された要素が$a[l]$または$a[r]$。 私たちが選ぶなら$a[l]$、前の状態は次のようになります。$dp[l+1][r]$; 同様に選択する$a[r]$につながる$dp[l][r-1]$。 
5. キー トランジションは、選択したエンドポイントに、グローバル順序でその前にすでに配置されている要素の数を乗算します。これは次の値となります。$n - (r - l)$。 この係数は、最終シーケンスの再構築がどの程度深く行われているかを反映します。 
6.アップデート$dp[l][r]$2 つの選択肢の最大値を取得し、それぞれが部分問題の解決策と、選択したエンドポイントの適切な重み付けされた寄与を組み合わせます。 

### なぜ効果があるのか

 どの時点でも、残りのセグメントは内部順序がまだ固定されていない要素のセットを表します。 すべての DP 遷移は、最終シーケンスの次の要素として 1 つの要素を割り当て、その乗数を一意に決定します。 左右の削除のすべての有効なシーケンスは、これらの間隔短縮による 1 つのパスに正確に対応し、そのようなパスはすべて 1 回評価されるため、DP は重複することなくすべての有効なシーケンスを探索します。 端点が次の要素として選択されると、残りの問題は独立しており、短縮された間隔にのみ依存するため、最適な部分構造が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 1:
        print(a[0])
        return

    dp = [[0] * n for _ in range(n)]

    for i in range(n):
        dp[i][i] = a[i] * n

    for length in range(2, n + 1):
        mult = n - length + 1
        for l in range(0, n - length + 1):
            r = l + length - 1

            dp[l][r] = max(
                dp[l + 1][r] + a[l] * mult,
                dp[l][r - 1] + a[r] * mult
            )

    print(dp[0][n - 1])

if __name__ == "__main__":
    solve()
```DP は間隔の長さによってボトムアップで構築されます。 乗算係数`mult`最終的な飲酒順序の位置に対応します: サイズの間隔が開いたとき`length`そのまま、正確に`n - length + 1`カップはすでに選択されているため、次に選択されたカップがその乗数を受け取ります。 

基本ケースでは、各単一要素に最終的な乗数を割り当てます。$n$、それはその部分問題で最後に残っている選択であるためです。 

トランジションは対称的です。つまり、左または右のいずれかを削除し、現在のグローバル ステップに基づいてその寄与を追加してから、より小さい間隔で続行します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    if n == 1:
        return str(a[0])

    dp = [[0] * n for _ in range(n)]
    for i in range(n):
        dp[i][i] = a[i] * n

    for length in range(2, n + 1):
        mult = n - length + 1
        for l in range(n - length + 1):
            r = l + length - 1
            dp[l][r] = max(
                dp[l + 1][r] + a[l] * mult,
                dp[l][r - 1] + a[r] * mult
            )

    return str(dp[0][n - 1])

assert run("1\n5") == "5"
assert run("2\n1 2") == "4"
assert run("3\n1 100 1") == "303"
assert run("4\n1 2 3 4") == str(run("4\n1 2 3 4"))
assert run("5\n5 5 5 5 5") == str(5 * (1+2+3+4+5))

 ## 特殊なケース

 次のような単一要素入力`1\n7`基本ケースによって直接処理されます。 DP は呼び出されず、出力は単純に要素に 1 を乗算したものになります。$n$その些細なケースでは。 

次のような厳密に増加する配列`1 2 3 4 5`アルゴリズムが正しい端を一貫して選択するのではなく、バランスの取れた端点の削除を優先するかどうかを強調します。 DP は各間隔で両方の可能性を評価するため、将来のゲインに対して初期の乗数のバランスが正しくとられます。 

次のような均一な配列`5 5 5 5 5`解が正しい算術構造に縮退するかどうかをテストします。 すべての構成は、同じ値に適用される同じ乗算器のマルチセットを生成するため、有効な DP パスは同じ結果を生成し、遷移ロジックの一貫性が確認されます。
