 ## 解決策
 ## 問題の理解

 浸水した地形を表す長方形のグリッドが与えられており、各セルには水深の値が含まれています。 旅行者は左上のセルから開始し、右下のセルに到達したいと考えています。 移動は左右と下のみに許可されているため、旅行者は列内で水平方向に自由に移動できますが、上方向には移動できません。 

パスとは、これらのルールに基づく隣接する一連の動きのことです。 パスのコストは、両方のエンドポイントを含む、そのパスに沿って訪問するすべてのセルの最大水深として定義されます。 タスクは、この最大深さを最小限に抑える有効なパスを選択することです。 

グリッド サイズは 500 x 500 まで大きくなるため、最大 250,000 個のセルが存在します。 各セル値は 10^9 まで大きくすることができ、考えられるすべてのしきい値を単純な方法で反復したり、すべてのパスを明示的に探索したりすることに依存するアプローチは除外されます。 パスを列挙しようとするアルゴリズムは直ちに実行不可能になります。これは、中程度のグリッドであっても、行内で自由に左右に移動できるため、可能なルートが指数関数的に多くなるからです。 

微妙な点は、水平移動によって行内にサイクルが作成されることです。 垂直方向の移動は厳密には下向きですが、下降する前に同じ行内を任意に何度でも左右に歩くことができるため、グラフは非周期的ではありません。 

素朴な考えによる失敗例の 1 つは、局所的に最小の近傍に貪欲に移動できると仮定することです。 たとえば、各ステップで隣接する最小の深さを選択すると、後で大きな垂直降下を強いられる連続に陥る可能性があります。 

もう 1 つの失敗例は、右と下に移動するだけで十分であると想定していることです。 左への移動が許可されているため、より適切な垂直エントリー ポイントに到達するために左に移動する必要がある場合があります。 

## アプローチ

 直接的な総当たりのアイデアは、最初から最後まですべての有効なパスを列挙し、各パスに沿って最大値を計算し、次にこれらの最大値の最小値を取得することです。 概念的には正しいですが、すべての列が接続された廊下のように動作するため、パスの数は非常に急速に増加します。ドロップダウンする前にさまざまな方法で通過できるからです。 500 x 500 のグリッドでは、各パスの評価コストが最大 O(nm) であることを考慮する前でさえ、これは実行可能な計算をはるかに超えて爆発的に増加します。 

重要な観察は、正確なパスは気にせず、閾値 T が実現可能かどうかだけを気にするということです。 値 T を固定し、深さ T までのセルのみを踏むことを許可する場合、問題は、誘導されたグラフで (1,1) が (n,m) に到達できるかどうかになります。 これにより、問題は単調な実現可能性チェックに変わります。つまり、T にパスが存在する場合、それはより大きな T にも存在します。 

この単調性により、2 つの標準ソリューションが可能になります。 1 つは、BFS または DFS を使用した到達可能性チェックと組み合わせた T での二分検索です。 もう 1 つは、ミニマックス最短パス問題としてのより直接的な定式化であり、各ノードの重みがそのセル値に等しく、パス コストがパスに沿った最大の重みになります。 このバージョンは、ノードまでの距離をこれまでに発生した最小可能最大値として扱うことにより、ダイクストラを使用して解くことができます。 

どちらの観点も同等ですが、ダイクストラは二分探索からの余分な対数因子を回避し、構造をより直接的に表現します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのパスに対するブルート フォース | 指数 | O(nm) 再帰スタック | 遅すぎる |
 | 二分探索 + BFS | O(nm log 10^9) | O(nm) | 承認済み |
 | ミニマックス・ディクストラ | O(nm log(nm)) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 状態がセルであるグリッド上でダイクストラを使用し、距離は開始点から任意のパス上で遭遇する最小可能最大深度を表します。

1. 独自の深さに設定されている開始セルを除き、各値が無限大である距離行列を初期化します。 これは、有効なパスには開始コストが含まれている必要があることを表します。 
2. 現在のパス コストで順序付けされた優先キューに開始セルをプッシュします。 キューは常に、これまでに知られている最小の最大深さで状態を拡張します。 
3. 現在のコストが最小のセルをキューから抽出します。 このコストは、遭遇する最大深度を最小限に抑えながらこのセルに到達するための最もよく知られた方法を表します。 
4. 現在のセルから到達可能な各隣接セル (左、右、下) について、現在のパス コストと隣接セルの深さの最大値に等しい候補コストを計算します。 これは、パス コストがこれまでに確認された最悪のセルによって決定されるという事実をモデル化します。 
5. この候補コストによって、その近隣について以前に記録された距離が改善される場合は、それを更新し、近隣を優先キューにプッシュします。 
6. 到達可能なすべての状態が処理されるまで続行します。 答えは、右下のセルにある最終的な距離の値です。 

プライオリティ キューを使用する主な理由は、セルが可能な限り最小の最大値でポップされると、代替ルートには少なくとも同程度のコストがかかるため、その後のパスではそれを改善できないためです。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは、優先キューにフロンティア セルに到達するための最良の既知の方法がボトルネック値の順に含まれているという不変条件を維持します。 セルがファイナライズされる (最小値としてポップされる) 場合、その値は、セルに到達するすべての有効なパスの中で可能な最小の最大深度になります。 このセルへの代替パスには、より大きな中間値が含まれているか、キューの順序により、より良いコストまたは同等のコストですでに探索されているため、このことが当てはまります。 遷移コストの単調な構造 (最大値を取る) により、パスを拡張してもコストが決して削減されないことが保証されます。これはまさにダイクストラ スタイルの正しさに必要な条件です。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]

    INF = 10**18
    dist = [[INF] * m for _ in range(n)]

    dist[0][0] = grid[0][0]
    pq = [(dist[0][0], 0, 0)]

    dirs = [(0, 1), (0, -1), (1, 0)]

    while pq:
        cost, x, y = heapq.heappop(pq)

        if cost != dist[x][y]:
            continue

        if x == n - 1 and y == m - 1:
            print(cost)
            return

        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m:
                ncost = max(cost, grid[nx][ny])
                if ncost < dist[nx][ny]:
                    dist[nx][ny] = ncost
                    heapq.heappush(pq, (ncost, nx, ny))

solve()
```グリッドは整数として直接保存され、距離テーブルは各セルの最もよく知られているボトルネック値を追跡します。 プライオリティ キューにより、最大深さを最小限に抑えるという観点から、現在最も有望なパスが常に拡張されます。 

方向配列は、許可される移動 (右、左、下) を正確にエンコードします。 上向きの移動は除外されます。これは、無効な方向に行を再訪問することなくすべての状態に到達する可能性を維持するため、非常に重要です。 

右下のセルに到達したときに早期に終了することは安全です。なぜなら、最初にセルをポップしたときに、その最適な値がすでに見つかっていることをダイクストラが保証しているからです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 重要なケースの 1 つは、垂直方向の障害物を回避するために水平方向の移動が必要な場合です。 たとえば、中央の列で低コストの列がブロックされている場合、前の列で左または右に迂回するしか進む方法はありません。 ダイクストラはすべての水平方向の遷移を対称的に探索するため、アルゴリズムはこれを自然に処理します。そのため、下方向への移動を試みる前に、到達可能な行セグメント全体に最適なボトルネック値を伝播します。 

もう 1 つのケースは、最適なパスを得るために反対側から列の位置を再検討する必要がある場合です。 左右の動きによってサイクルが存在する場合でも、プライオリティ キューにより、よりコストのかかる繰り返しの訪問は無視されます。 これにより、必要な水平方向の探索を可能にしながら、無限ループを防止します。 

最後のケースは、単一の高値ゲート セルを通過した後にのみ到達可能な領域に最適な答えが存在する場合です。 すべての候補パスがある時点でそのゲート値を組み込む必要があり、max 操作によってすべての拡張にわたってそのゲート値が保持されるため、アルゴリズムはそのゲート値をすべてのダウンストリーム パスのボトルネックとして正しく割り当てます。
