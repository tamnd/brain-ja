 ## 解決策
 ## 問題の理解

 各ノードが重みと色という 2 つの属性を持つツリーが与えられます。 このツリーから、2 つの同時制限を持つ頂点のサブセットを選択します。 まず、選択された 2 つの頂点がツリー内で隣接してはいけないため、選択されたセットは独立したセットでなければなりません。 次に、たとえツリー内で遠く離れていても、同じ色を共有する 2 つの頂点を選択することはできません。 

両方の制約を満たすすべてのサブセットの中で、最大の合計重みを持つサブセットが必要です。 

入力サイズから、ツリーには最大 1000 個の頂点と最大 10 個の個別の色があることが分かります。 この組み合わせは、色のサブセットまたは頂点のサブセットに対して動的計画法を実行できるほど十分に小さいですが、サブセットの数が n で指数関数的であるため、有効な頂点サブセットをすべて列挙するのが不可能になるほど十分に大きいです。 

頂点のすべてのサブセットを試す単純なアプローチでは、最大 2^1000 の可能性が考慮されますが、これはまったく実行不可能です。 妥当性のチェック自体がサブセットごとに線形であるため、独立性や色の制約による枝刈りでも十分な効果は得られず、天文学的に大きな複雑性が生じます。 

さらに微妙な問題は、制約間の相互作用から発生します。 よくある間違いは、色を独立して扱い、色ごとに独立した集合問題を解決したり、色ごとに最も重い頂点を貪欲に選択したりすることです。 これは、隣接によって異なる色が結合されるため失敗します。1 つの色の重い頂点を選択すると、その近傍にある他の色の複数の候補がブロックされる可能性があります。 

もう 1 つの間違った方向は、ツリー上の独立したセットの最大重みを計算し、その後単純に個別の色を適用することです。 最適な独立セットには同じ色の複数の頂点が含まれている可能性があり、後で重複を削除するのは局所的に最適ではないため、これも失敗します。 

## アプローチ

 主な問題点は、独立性制約がツリー上で構造的であるのに対し、色の制約は選択したノード全体でグローバルであることです。 色の数が少ないということは、頂点ではなく色が状態空間を制御する必要があることを示唆しています。 

ブルート フォースの観点では、隣接する 2 つのノードが選択されず、色の繰り返しがないことを確認しながら頂点の選択を検討します。 これは当然、頂点のサブセットを探索して検証することになります。 n 個のノードを持つツリーでは、独立したセットの数だけでもすでに指数関数的になっており、色の一意性を追加しても、制御された方法で組み合わせの爆発が減少するわけではありません。 このアプローチは、n が約 30 または 40 を超えると失敗します。 

主な観察点は、隣接を超える唯一のグローバル制限は「各色につき最大 1 つの頂点」であるということです。 C ≤ 10 なので、各色を選択次元として扱うことができます。 各色について、その色の頂点を最大 1 つ選択することも、まったく選択しないこともできます。 したがって、頂点の観点から考えるのではなく、選択した色ごとに代表的な頂点を割り当てる観点から考えます。 

ただし、隣接性は依然として重要です。 たとえば赤と青の 2 つの色を選択し、各色の頂点を 1 つ選択する場合、それらの 2 つの頂点がツリー内で隣接していないことを確認する必要があります。 これは、色のサブセットに対する DP を示唆しており、遷移によって選択された代表間の互換性が保証されます。 

任意のノードでツリーをルート化します。 各ノードについて、どの色がすでに「現在のサブツリー選択で使用されている」かをエンコードする DP 状態を考慮します。しかし、より明確な定式化は、ノードを選択するかどうかに関係なく、各ノードについてサブツリー内で可能な最良の選択を追跡する DP を使用してツリーを処理することです。 色はグローバルであるため、代わりに色ごとに候補を集約し、色のビットマスクと組み合わせたツリー DP によって非隣接性を強制します。

両方の制約を解決するきれいな方法は、問題を色ごとに最大 1 つのノードを選択し、選択したノードが独立したセットを形成するようにすることです。 色が少ないため、まずノードを色ごとにグループ化します。 各色について、最終的には最大 1 つのノードを選択することになるため、異なる色の 2 つの候補ノード間の互換性を事前に計算します。これらのノードはツリー内で隣接することはできませんが、より重要なのは、サブツリー構造に関係なく、隣接しないままでなければならないということです。 

次に、構造がツリーであり、n が小さいため、ノードと色のサブセットに対して DP を実行でき、選択内で選択したノードがペアごとに隣接していないことを確認できることがわかります。 これは、各カラー クラスから最大 1 つのノードが選択されるという追加の制約を付けて最大重み独立集合を解くことと同じです。 これは、状態が現在の部分独立セットで既に使用されている色のビットマスクであるツリー上の DP によって処理できます。 

ツリーをルート化するとき、独立したセットに対して標準ツリー DP を実行しますが、サイズ C のカラー ビットマスクで状態を拡張します。ノードごとに、それを取得するかどうかを決定し、取得する場合はマスクにその色を設定します。 遷移は、親と子の間の独立性制約を確保しながら、子 DP テーブルを結合します。 

これが機能するのは、ツリー DP が隣接性制約を自然に処理し、ビットマスクがグローバルな色の一意性を追跡するためです。

 ## アルゴリズムのチュートリアル

 ノード 1 でツリーをルート化し、DFS ベースの動的プログラミングを実行します。 

1. 各ノードの DP テーブルを定義します。ここで、dp[u][mask] には、このサブツリーで選択された色のセットがマスクに正確に対応する場合に、u のサブツリーで達成可能な最大重みが格納されます。 マスクには C ビットがあるため、どの色がすでに使用されているかを表します。 
2. 各ノード u について、最初に u が選択されていないものとして DP を初期化します。 この場合、dp[u] は dp[u][0] = 0 で始まります。これは、このノードではまだ色が使用されていないことを意味します。 
3. u の各子 v を処理し、その DP テーブルを u の DP にマージします。 このマージは、dp[u] と dp[v] の間で互換性のあるマスクをすべて結合することによって行われます。 ここでの互換性とは、カラー セットが互いに素なままでなければならないことを意味します。 結合するときは、マスクのすべてのペアを試し、それらの重みを追加します。 
4. u を取得せずにすべての子をマージした後、u が選択された場合を考えます。 u を選択する場合、その色はどの子選択にもすでに表示されていてはいけないため、色 c[u] を含まないマスクのみを許可します。 w[u] の寄与候補を設定し、どの子も u の色を使用できないという制約の下で子をマージします。 
5. 各子について、u が選択されるとき、子のサブツリーが独立性を侵害する u に隣接するノードを選択しないようにする必要があります。 隣接関係は親と子の間にのみ存在するため、u を選択するとすべての子は競合するノードの選択を回避しますが、ツリー DP ではこれは、子が u の位置も選択する構成を除外することで処理されます。 
6. 最後に、ノード u については、すべての dp[u][mask] 値の最大値を取得します。これは、サブツリーの有効なサブセットでは一部の色が未使用のまま残される可能性があるためです。 

### なぜ効果があるのか

正確さは 2 つの結合された不変条件に依存します。 まず、ツリー DP 不変式により、子からの状態の任意の組み合わせが、隣接する選択ノードのない頂点のセットに対応することが保証されます。これは、隣接関係が親エッジと子のエッジの間にのみ存在し、マージ中に競合する選択が明示的に回避されるためです。 第 2 に、ビットマスク不変条件により、選択された 2 つの頂点が同じ色を共有しないことが保証されます。これは、すべての遷移では素のカラー マスクのマージのみが可能であり、ノードを選択するとそのカラーがマスク内に永続的に設定されるためです。 すべてのノードは再帰で 1 回だけ処理され、すべてのマージでは両方の不変条件が保持されるため、dp で表されるすべての状態は有効なサブセットに対応し、すべての有効なサブセットはツリーに沿った同じ分解に従うことで構築できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, C = map(int, input().split())
    w = list(map(int, input().split()))
    c = list(map(int, input().split()))
    c = [x - 1 for x in c]

    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    FULL = 1 << C

    dp = [None] * n

    def dfs(u, p):
        # dp[u]: dict mask -> best value
        cur = {0: 0}

        for v in g[u]:
            if v == p:
                continue
            dfs(v, u)

            nxt = {}
            dv = dp[v]

            for m1, val1 in cur.items():
                for m2, val2 in dv.items():
                    if m1 & m2:
                        continue
                    nm = m1 | m2
                    if nm not in nxt or nxt[nm] < val1 + val2:
                        nxt[nm] = val1 + val2

            cur = nxt

        # option: take u
        take = {}
        cmask = 1 << c[u]

        for m, val in cur.items():
            if m & cmask:
                continue
            nm = m | cmask
            take[nm] = max(take.get(nm, 0), val + w[u])

        # merge: not take u OR take u
        res = cur
        for m, val in take.items():
            if m not in res or res[m] < val:
                res[m] = val

        dp[u] = res

    dfs(0, -1)
    print(max(dp[0].values()))

if __name__ == "__main__":
    solve()
```このソリューションは事後走査を実行します。 各ノードは、カラー マスクをそのサブツリー内で最も達成可能な合計にマッピングする辞書を維持します。 マージ ステップは、子全体にわたるナップザック スタイルの畳み込みであり、互換性のないカラー マスクは破棄されます。 

「ノード u を取得」ステップは、その色が蓄積されたマスクにすでに存在するかどうかをチェックすることによって色の制限を強制します。 そうでない場合は、ノードの重みを追加し、そのカラー ビットを設定します。 

すべての色を使用する必要はないため、最終的な答えは、ルートのすべてのマスクの中で最良の値になります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのノードが同じ色を共有する場合です。 この場合、色の制約だけで選択できるノードは 1 つまでに制限されるため、答えは単純に最大重みノードになります。 すべてのマージが同じ単一ビット マスクを保持し、複数の選択を防ぐため、DP はこれを正しく適用します。 

もう 1 つのケースは、1 つの中心ノードが異なる色の多数の葉に接続する星形のツリーです。 最適解は、重みが小さい場合は中心を避け、代わりに複数の葉を選択します。 DP はこれを処理します。これは、リーフ サブツリーがきれいにマージされる一方で、センターはそれ自体と隣接するものの同時選択をブロックする隣接制約を導入するためです。 

最後の微妙なケースは、重みの高いノードが色を共有しているものの、ツリー内で遠く離れている場合です。 ビットマスク制約が上向きに伝播し、距離に関係なくグローバルに色ごとに 1 つだけが保証されるため、アルゴリズムは依然としてそれらの結合を除外します。
