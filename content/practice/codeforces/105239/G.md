 ## 解決策
 ## 問題の理解

 店舗に行くたびにバターボールには 2 つの独立した物資が与えられます。それは米と鶏の胸肉です。 彼は旅行中ずっと、決まった量の食事を組み立てたいと考えています。$k$しかし、ルールにより、材料の組み合わせ方が制限されています。 

1回の食事で正確に摂取する必要があります$k$グラム単位で使用され、使用される各グラムは購入した株の 1 つからのものでなければなりません。 重要な制約は、混合が「部分的にグローバル」でしかないことです。旅行内では、米と鶏肉はパッケージとしてまとめられていますが、旅行全体では同じ種類の材料を分離できます。 

正式には、旅行ごとに$i$、ペアがあります$(a_i, b_i)$。 それぞれの旅行で、同じ旅行から米を鶏肉とは独立して使用できますが、食事は 3 つの方法のいずれかで形成されます。 同じ旅行から米と鶏肉の両方を摂取し、その旅行の貢献を次のように分割します。$x + y = k$。 あるいは、さまざまな旅行で米の部分を組み合わせて、完全に米だけで食事を構成することもあります。 または、さまざまな旅行で鶏肉を組み合わせて、鶏肉のみから食事を構成します。 

制限は、一度ご飯と鶏肉の両方を「混ぜて」食べると、それは 1 回の旅行で得られたものでなければならないということです。 旅行全体でソースを混合することを決定した瞬間、単一の材料タイプに制限されます。 

ですので、各食事は「一回使いの混合食」か「純米食」か「純鶏食」のいずれかになります。 

出力では、グラムを再利用せずにリソースを消費して、形成できるばらばらの食事の最大数が求められます。 

境界$n \le 500$そして$k \le 500$総使用重量またはトリップごとの寄与に対する擬似多項式動的プログラミングを含むソリューションが実現可能であることを示しています。 大きな値は、$a_i, b_i \le 10^9$グラムを明示的に反復できないことをすぐに暗示します。 すべてのものは、残差または最大容量によってインデックス付けされた状態に圧縮する必要があります。$k$、実際の数量ではありません。 

微妙なエッジケースは、旅行ごとに常に「最高の」完全な食事を摂ろうとする貪欲な戦略である場合です。 たとえば、ある旅行で$(k, 0)$そしてもう一人は$(0, k)$, 欲張りに考えると、すぐに2食を提案するかもしれません。 ここでは機能しますが、旅行全体で部分的な再利用が必要になると失敗します。 別の失敗例は、旅行の総重量が十分である場合に発生します。$a_i + b_i \ge k$しかし、それを最適に分割するには、地域の決定ではなく、世界的な米や鶏肉の割り当てとの調整が必要です。 

本当の難しさは、各トリップが 2 つのリソースを含む境界付きのナップザックのような構造に寄与することですが、それらを一緒にバインドする (1 つのトリップ内で混合する) ことも、完全に 2 つの独立したナップザックに分離することもできることです。 

## アプローチ

 強引なアプローチでは、すべての旅行を通じて米と鶏肉のグラムごとに、それを食事にどのように割り当てるかを決定しようとします。 これにより、問題は効果的に最大で多次元の分割問題として扱われることになります。$10^9$-スケール容量。 たとえ旅行ごとに離散化したとしても、旅行ごとに、考えられるすべての分割方法を考慮する必要があります。$(a_i, b_i)$混合食事や残りの米と鶏肉の割り当てに。 各旅行はさまざまな組み合わせで多くの食事に部分的に寄与する可能性があるため、旅行ごとの州の数が指数関数的に増加します。 

重要な簡素化は、食事の構造を分離することです。すべての食事は、完全に 1 回の旅行内で行われるか (混合の場合)、複数の旅行にわたって完全に単一の食材タイプ内で行われます。 これは、旅行全体にわたって正確なグラムレベルの割り当てを追跡する必要がないことを意味します。 各旅行でどれだけの混合食を取るかを決めた後、どれくらいの量の米と鶏肉を「残しておける」かを知る必要があるだけです。 

その解釈を修正すると、各旅行は制限された数の「混合食事」を提供すると見なすことができ、残りの米と鶏肉は独立した資源となり、2つの別々のナップザックのようなサイズの蓄積に貢献します$k$。 

重要な観察は、各食事が正確に消費するため、$k$、各リソースの状態はモジュロのみが重要です$k$。 これにより、各次元が最大で次のように縮小されます。$k$意味のある状態。 

次に、旅行中に動的プログラミングを実行し、米と鶏肉から何回の完全な食事を形成できるか、および旅行中にすでに約束した混合食事の数を追跡します。

 ## アルゴリズムのチュートリアル

 私たちはDPテーブルを管理しており、州が未使用の米と鶏肉をどれだけ繰り越すかを剰余のモジュロで表します。$k$。 それぞれの移行は 1 回の旅行を処理し、そこから摂取する混合食の数を決定し、残り物を世界の米と鶏肉のプールに分配します。 

1. DP 配列を初期化します。$dp[r][c]$これまでに得られた満腹食事の最大数を表します。$r$米かすのグラムと$c$将来の食事を作るためにまだ利用できる鶏肉残渣のグラム数。 初期状態は$dp[0][0] = 0$。 
2. 各旅行を処理する$(a_i, b_i)$順次。 既存の州ごとに、この旅行から混合食事を抽出するための実行可能なすべての方法を検討します。 混合食の消費量は$x$お米と$y = k - x$同じ旅行からのチキン。 両方なので$x$そして$y$整数であり、利用可能なリソースによって制限される必要があります。$x$からの範囲$0$に$k$ただし、有効な分割のみです。$x \le a_i$そして$y \le b_i$が考慮されます。 
3. ミックスミールの選択ごとに$t$、それに応じて旅行で利用可能なリソースを減らし、残りは$a_i - x \cdot t$お米と$b_i - y \cdot t$チキン。 これらの残り物は失われることはありません。 代わりに、それらはグローバルプールに追加され、後で純米または純チキンミールの形成に貢献します。 
4. 混合配分を処理した後、残った米と鶏肉を満腹形成への寄付に変換します。$k$シングルタイプのお食事サイズです。 これらの貢献をモジュロで追跡します$k$、将来の完成には残りだけが重要なので。 
5. 以前の残留状態と旅行からの新しい残留を組み合わせて DP 遷移を更新し、残留合計が$k$。 
6. すべてのトリップが処理された後、答えはすべての DP 状態にわたる最大値になります。 

### なぜ効果があるのか

 このアルゴリズムは、すでに形成されたすべての食事が完了してシステムから削除されるという不変条件を維持しますが、残りのリソースはすべて、最大の残差によってのみ表現されます。$k-1$ご飯と鶏肉に。 新しい食事には正確な量が必要なので、$k$単一タイプのユニットまたはシングルトリップ混合物の場合、同一の残基を含むあらゆる構成は、同一の将来の可能性をもたらします。 これにより、将来の最適な決定に関連する情報が失われることがなくなり、リソースのすべての有効な分解が、有界状態空間上の DP 遷移を通じて探索されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    trips = [tuple(map(int, input().split())) for _ in range(n)]

    dp = [[-10**18] * k for _ in range(k)]
    dp[0][0] = 0

    for a, b in trips:
        ndp = [[-10**18] * k for _ in range(k)]

        for r in range(k):
            for c in range(k):
                if dp[r][c] < 0:
                    continue

                base = dp[r][c]

                # try number of mixed meals from this trip
                for x in range(k + 1):
                    y = k - x
                    if x > a or y > b:
                        continue

                    rem_a = a - x
                    rem_b = b - y

                    nr = (r + rem_a) % k
                    nc = (c + rem_b) % k

                    add_full = (r + rem_a) // k + (c + rem_b) // k

                    ndp[nr][nc] = max(ndp[nr][nc], base + add_full)

        dp = ndp

    ans = 0
    for r in range(k):
        for c in range(k):
            ans = max(ans, dp[r][c])

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、残りの米と鶏肉のモジュロに対して 2 次元の DP が維持されます。$k$。 ネストされた遷移は、混合食事への旅行の可能なすべての分割を反復します。各混合食事は一意の整数パーティションに対応するため、これは有効です。$x + y = k$。 構成ごとに、残りのリソースは残余更新とサイズの完全なグループに折りたたまれます。$k$すぐに完成した食事に変換されます。 

実装によくある落とし穴は、満腹の食事を数える前に、残り物を以前の残り物と組み合わせる必要があることを忘れていることです。 変換を個別に実行すると、状態間のキャリーが失われるため、正確さが失われます。

 ## 特殊なケース

 エッジ ケースの 1 つは、個別の旅行に十分な総重量があるにもかかわらず、有効な分割ができない場合に発生します。 のような入力の場合$k=5$、$(3,1)$、整数がないため、アルゴリズムは混合食事の形成を正しく回避します。$x$両方を満たす$x + y = 5$そしてリソースの境界。 DP 遷移では、無効な分割がすべてスキップされ、残基は変更されません。 

もう 1 つのケースは、最適なソリューションが将来の完成を可能にするために 1 つのタイプに残留物を残す必要がある場合です。 たとえば、初期の消費で米 2 個の残りが生じ、その後の旅行で米 3 個が提供された場合、DP はその残りを繰り越し、合計が 5 に達した場合にのみ完全な食事に変換されます。モジュロ追跡により、将来の組み合わせ可能性を失うことなく、この蓄積が確実に保存されます。 

最後のエッジケースは、すべての旅行が同一で、比較的小さい場合です。$k$。 DP は食事を形成するのに十分な残留物を蓄積することはなく、すべての状態はゼロのままであり、有効な値がないため、正しい出力と一致します。$k$-パーティションは任意の組み合わせで存在します。
