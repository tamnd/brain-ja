 ## 解決策
 ## 問題の理解

 英語の小文字で構成されるいくつかの短い文字列が与えられます。 各文字列について、母音と子音という 2 つのクラス間で文字がどのように交互するかに応じたルールに基づいて、それが「有効」であるかどうかを判断する必要があります。 

ルールは前処理ステップの後に適用されます。 Wordland では、同じ文字が複数回連続して出現する場合、それが 1 回出現したものとして発音されます。 したがって、文字列は最初に、同一の文字の最大ブロックをすべて 1 つの文字に折りたたむことによって圧縮されます。 この圧縮の後、結果のシーケンスが母音と子音の間で厳密に交互になっているかどうかを確認します。 圧縮文字列内のすべての隣接するペアが 1 つの母音と 1 つの子音で構成されている場合、単語は有効です。 

母音セットは a、e、i、o、u、y に固定されており、他の文字はすべて子音です。 

入力サイズは非常に小さく、最大でも 100 ワード、各長さは最大 100 です。これは、二次または三次の解でも快適に通過することをすぐに示唆しますが、タスクの構造は、ワードごとの線形スキャンが自然に適合することを示唆しています。 

主な微妙な点は圧縮ルールです。 単純なアプローチでは、交互をチェックする前に連続する重複をマージすることを忘れる可能性があります。 それは誤った拒否または受け入れにつながります。 

たとえば、「ととろおお」という単語を考えてみましょう。 交替を直接チェックすると、末尾の「oooo」は複数の母音が連続しているように見え、交替に違反します。 しかし、圧縮後は、「oooo」は単一の「o」になり、構造は「to o t o r o」となり、正しく交互になります。 

2 番目のエッジ ケースは、「rr」のような単語です。 圧縮後は「r」となり、ルールに違反する隣接ペアがないため、有効となるはずです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各単語について、最初に連続する同一の文字を結合して新しい文字列を明示的に構築します。 これは、文字列をスキャンし、前の文字と異なる場合にのみ文字を追加することで実行できます。 この圧縮の後、縮小された文字列を反復処理し、すべての隣接するペアをチェックして、一方が母音で、もう一方が子音であることを確認します。 

このアプローチでは、各単語のサイズがすでに線形になっています。 最悪の場合、長さ 100 の 100 単語を考慮したとしても、約 10,000 文字の操作を実行することになりますが、これは些細なことです。 より高度な最適化は必要ありません。 

重要な観察は、問題は本質的に、単語ごとに 2 つの独立した線形パス (ランレングス圧縮用のパスと検証用の 1 つのパス) であるということです。 どちらも O(L) であるため、概念的にはそれらを 1 つのスキャンにマージできます。 スキャン中、最後に保持された文字 (圧縮後) を追跡し、新しい文字ブロックが開始されたときにのみそれと比較します。 

ブルート フォース バージョンは、圧縮表現を明示的に構築するため機能します。 最適化されたバージョンでは、文字の保存が回避され、代わりに最後の関連文字とその母音ステータスのみが維持されます。

 ## アルゴリズムのチュートリアル

1. 単語ごとに、文字が母音であるかどうかを判断するヘルパー関数を定義します。 これは、セット {a, e, i, o, u, y} に対する定数時間のルックアップです。 
2. 受け入れた最後の「圧縮された」文字を維持しながら、単語の文字を左から右に繰り返します。 最初は前のキャラクターは存在しません。 
3. 文字を見つけたら、生の文字列内の前の文字と比較します。 同じ場合は、同じ実行に属し、圧縮構造が変更されないため、スキップします。 
4. 前の生の文字と異なる場合、それを圧縮シーケンスの次の文字として扱います。 この時点で、その母音/子音のタイプを最後に保持された圧縮文字と比較します。 両方が同じクラスに属している場合、その単語は無効であることがすぐにわかります。 
5. 最後の圧縮文字を更新し、スキャンを続行します。 
6. 違反が見つからずに単語の最後まで到達した場合、その単語は有効です。 

設計上の重要な点は、圧縮境界を生き延びた文字のみを比較するということです。 これらの重複は明示的に無視されるため、実行内で比較することはありません。 

### なぜ効果があるのか

 ランレングス圧縮では、重要なシーケンス、つまり個別の文字間の遷移が正確に保存されます。 代替ルールの違反は、これらの遷移のいずれかで発生する必要があります。 一連の同一の文字内では、すべての文字が同一の母音ステータスを持つため、文字を折りたたんでも、交互に関連する情報が失われることはありません。 したがって、圧縮された境界シーケンスのみをチェックするだけで十分であり、完全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

VOWELS = set("aeiouy")

def is_vowel(c: str) -> bool:
    return c in VOWELS

n = int(input())
for _ in range(n):
    s = input().strip()
    
    prev_raw = None
    prev_kept = None
    
    ok = True
    
    for c in s:
        if c == prev_raw:
            continue
        
        if prev_kept is not None:
            if is_vowel(c) == is_vowel(prev_kept):
                ok = False
                break
        
        prev_kept = c
        prev_raw = c
    
    print("YES" if ok else "NO")
```ソリューションは 2 つの状態を維持します。 最初、`prev_raw`、純粋に圧縮のために使用されます。現在の文字が繰り返し実行の一部であるかどうかを追跡します。 2番目、`prev_kept`, は、圧縮シーケンスの最後の文字を表します。 

重要な点は、新しい圧縮文字が出現した場合にのみ母音クラスを比較するということです。 これにより、正確性を維持しながら、明示的な文字列の構築を回避できます。 

よくある間違いは、元の文字列内の隣接するすべてのペアを比較することです。これにより、繰り返される母音または子音が誤ってペナルティを受けます。 もう 1 つの間違いは、圧縮するが、圧縮境界の後でのみ比較することを忘れることです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    VOWELS = set("aeiouy")
    
    def is_vowel(c):
        return c in VOWELS
    
    n = int(sys.stdin.readline())
    out = []
    for _ in range(n):
        s = sys.stdin.readline().strip()
        
        prev_raw = None
        prev_kept = None
        ok = True
        
        for c in s:
            if c == prev_raw:
                continue
            if prev_kept is not None and is_vowel(c) == is_vowel(prev_kept):
                ok = False
                break
            prev_kept = c
            prev_raw = c
        
        out.append("YES" if ok else "NO")
    
    return "\n".join(out)

# provided samples
assert run("5\nkukaracha\nramen\nfoot\nemployees\ntotoroooo\n") == "NO\nYES\nYES\nNO\nYES"
assert run("2\nrr\nttttt\n") == "YES\nYES"

# custom cases
assert run("1\na") == "YES"
assert run("1\naa") == "YES"
assert run("1\nab") == "YES"
assert run("1\naba") == "YES"
assert run("1\nabbaa") == "NO"

 ## 特殊なケース

 エッジ ケースの 1 つは、同じ文字が繰り返されて完全に構成される単語です。 たとえば、入力「ttttt」は「t」に圧縮されますが、これには交互に違反する遷移がないため、有効です。 アルゴリズムはこれを処理します。`prev_kept`2 番目の個別の圧縮文字が現れるまでは決して比較されません。 

もう 1 つのエッジ ケースは、「lesssoon」など、複数の場所で重複する単語です。 繰り返される「sss」は単一の「s」に折りたたむ必要があります。そうしないと、単純な隣接チェックでラン内の母音子音違反が誤って検出されてしまいます。 このアルゴリズムでは、繰り返される文字はすべて次のようにスキップされます。`prev_raw`、実行境界のみがチェックに寄与するようにします。 

3 番目の特殊なケースは、「totoroooo」など、文字とブロックが繰り返される場合です。 後続の母音を複数の交互として解釈してはなりません。 スキップ ロジックでは、実行からの移行のみが考慮されるため、正確性は生の繰り返しではなく、圧縮された構造のみに依存します。
