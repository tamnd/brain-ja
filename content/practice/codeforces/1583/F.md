 ## 解決策
 ## 問題の理解

 頂点 1 から n までの完全な有向非巡回グラフが与えられます。ここで、i < j のすべてのペア (i, j) は、i から j までの有向エッジを持ちます。 すべてのパスは単に厳密に増加する頂点のシーケンスであり、その長さはエッジの数であり、シーケンス内の頂点の数から 1 を引いたものになります。 

すべてのエッジに色を割り当てる必要があります。 この制約はパス全体にわたってグローバルです。パスに少なくとも k 個のエッジが含まれる場合は常に、それらのエッジに沿った色をすべて同じにすることはできません。 言い換えれば、長さが少なくとも k であるすべてのパスに少なくとも 2 つの異なる色が表示される必要があります。 

使用する色の数を最小限に抑え、この最小限を達成する 1 つの有効な色を構築することが求められます。 

グラフのサイズは最大でも n = 1000 なので、エッジは約 500k になります。 カラーリングを構築するための O(n^2) の解は許容されますが、パスの数が指数関数的であるため、パスを列挙したり、すべてのサブシーケンスについて明示的に推論したりすることは不可能です。 

k = 1 の場合、微妙なエッジ ケースが現れます。この場合、すべての単一エッジがすでに長さ 1 のパスを形成しているため、少なくとも長さ 1 のパスは単色にはなりません。 これにより、単一のエッジが単色になると要件に違反するため、すべてのエッジに個別の色が強制されます。 逆に、k が n に近い場合、パスは長くなりますがまばらになり、制約が弱くなり、構造化された色の再利用が可能になります。 困難は、必然的に禁止されたパスが含まれる前に、単色のチェーンがどのくらいの長さを安全に保つことができるかを特徴付けることにあります。 

## アプローチ

 素朴な解釈は、パス チェックの観点から考えることです。色を任意に割り当てて、少なくとも k 以上の長さのすべてのパスに少なくとも 2 つの色が含まれているかどうかを検証できます。 パスを数えることさえ指数関数的であるため、これはすぐに計算上失敗します。 

2 番目の単純な方向は、ローカルに考えることです。どのパスに沿った k 個の連続エッジのシーケンスも単色ではないことを確認します。 しかし、パスは任意の増加するサブシーケンスに対応するため、「パス内の連続するエッジ」は隣接構造内の連続するエッジに対応しないため、これでもすべての増加するシーケンスに対する推論に帰着しますが、これもまた実行不可能です。 

重要な観察は、条件を逆転させることです。 単色の長いパスを禁止する代わりに、長さ k 以上の単色パスを許可する構造は何かを尋ねます。 このようなパスは、一連の頂点 v1 < v2 < ... < v(k+1) に対応し、すべてのエッジ (vi, vi+1) が同じ色を共有します。 そのため、カラー クラスは推移的なトーナメントのような構造を誘発し、カラー クラスに長さ k+1 のチェーンが含まれていないことを確認する必要があります。 

これはまさにポーズセット内の最長連鎖問題であり、1 つの色のエッジがサブグラフを定義し、その最長パスの長さは最大でも k-1 でなければなりません。 基礎となるグラフは完全な DAG であるため、任意のカラー クラスは、長さ k+1 の完全に増加するチェーンの形成を回避する必要があるエッジのセットに対応します。 

最適な構築は、端点間の距離のみに依存することがわかります。 正しい構造は、(j - i) の関数によってエッジを分割することですが、線形ではありません。 その代わりに、極度の構造は、単色パスがインデックスを増加させながら繰り返し前進することに対応し、そのようなパスが選択されたエッジ全体の合計「距離」を蓄積するという事実から来ています。 長い単色チェーンを防ぐには、単一の色内で、強制的に色を変更せずに k 個の連続した前進ステップを蓄積することが不可能であることを確認する必要があります。

これにより、各エッジ (i, j) を (j - i) を除算する 2 の最大累乗でエンコードするか、(j - i) の最下位ビットの位置でエンコードするという最適なアイデアが得られます。 これにより、k エッジの増加シーケンスに沿って、長さ k に達する前に LSB 構造が少なくとも 1 回変更される必要があります。 n までのすべての差にわたるこの関数の個別の値の数は正確に ⌊log2(n)⌋ + 1 であり、これが最適です。 

建設的な証明は、2 つのエッジが同じ最低セット ビット位置を共有する場合、それらを k 回連鎖させると、頂点インデックスのバイナリ キャリー伝播との矛盾が強制されることを示しています。 逆に、このカラーリングでは、長いチェーンでは最終的に LSB レベルが増加し、少なくとも 2 つのカラーが生成されることが保証されます。 

したがって、問題はビット構造に基づいて各エッジに色を割り当てることに帰着し、n を表すのに必要なビット レベルの数に等しい色の最小数が得られます。

 ## アルゴリズムのチュートリアル

 (j - i) の最下位ビットに基づいてエッジ (i, j) に色を割り当てます。 

1. 各エッジの値 d = j - i を計算します。 この差は、パスの 1 歩でどれだけ前にジャンプするかを表します。 すべてのパスの構造は、このような違いの順序によって完全に決定されます。 
2. c = n を表すのに必要なビット数、つまり、floor(log2(n)) + 1 を計算します。これは、n までの差の中で異なる LSB 位置の可能な最大数です。 
3. 各エッジ (i, j) について、t = (j - i) & (-(j - i)) を計算します。これにより、差の最小設定ビットが分離されます。 
4. t の 2 進対数を取得して、t をカラー インデックスに変換します。 これにより、すべてのエッジが 0 から c-1 までの小さな整数にマップされます。 
5. 問題ステートメントの要求に従って、すべての色をエッジの辞書編集順に出力します。 

このマッピングが意味のある理由は、エッジを 2 の累乗の最小ステップ サイズでグループ化し、インデックスのバイナリ表現でジャンプがどのように「整列」するかを制御するためです。 同じ配置のエッジは、繰り返し適用するとより高いビット レベルへのキャリーが強制されるため、長く均一なチェーンを維持できません。 

### なぜ効果があるのか

 各カラー クラスは、ステップ サイズが同じ最低設定ビットを持つエッジに対応します。 どのパスに沿っても、1 つの色に留まろうとすると、バイナリ構造により最大 k ステップ後に上位ビットへのキャリーが強制される数値を繰り返し加算することになります。 これは、長さ k の単色パスにより最下位セット ビットの安定性に矛盾が生じるため、色間の遷移が少なくとも 1 回発生する必要があることを意味します。 これにより、すべての長いパスが虹になることが保証されます。 

各ビット レベルは、ステップ サイズがバイナリでどのように整列するかだけが異なるチェーンを分離するために必要であるため、構築も最小限です。 色を削除すると 2 つのレベルがマージされ、k エッジにわたる色の変化を回避するチェーンを構築できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    
    # number of colors needed: number of bits up to n
    c = (n - 1).bit_length()
    
    res = []
    
    # precompute log2 for lowest set bit
    # we can use a simple lookup for powers of two
    bit_index = {}
    for i in range(c + 1):
        bit_index[1 << i] = i
    
    for i in range(1, n + 1):
        for j in range(i + 1, n + 1):
            d = j - i
            lowbit = d & -d
            color = bit_index[lowbit]
            res.append(str(color + 1))
    
    print(c)
    print(" ".join(res))

if __name__ == "__main__":
    solve()
```実装は、ステートメントで要求される直接エッジ列挙順序に従い、頂点 i から開始して終点 j まで辞書順に反復します。 重要な計算は、j - i の最小設定ビットを抽出することであり、これは次のように行われます。`d & -d`。 小さなルックアップ テーブルは、その 2 のべき乗値をコンパクトなカラー インデックスに変換します。 

内部マッピングでは自然に 0 から始まるインデックスが生成されるため、1 から始まる色を出力する場合には注意が必要です。 ビット長の計算により、n までの考えられるすべての違いをカバーするのに十分な色が存在することが保証されます。

 差と最小設定ビットを計算します。 

| エッジ | d = j - i | ロービット | 色 |

 | (1,2) | 1 | 1 | 0 |
 | (1,3) | 2 | 2 | 1 |
 | (1,4) | 3 | 1 | 0 |
 | (1,5) | 4 | 4 | 2 |
 | (2,3) | 1 | 1 | 0 |
 | (2,4) | 2 | 2 | 1 |

これは、単一のカラー クラス内で長く均一なパスを維持できないことを示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | すべてのエッジが 1 回処理されます。 
| スペース | O(1) 追加 (出力を除く) | ビットインデックス用の小さなルックアップテーブルのみ |

 出力自体のサイズは Θ(n²) であるため、正しい解は結果を出力するだけで少なくとも 2 次の時間を費やす必要があります。 エッジごとのすべての計算は定数時間のビット演算であるため、この構築は制限内に留まります。

## 特殊なケース

 n = 2 など、n が非常に小さい場合、グラフにはエッジが 1 つだけあるため、k ≥ 1 の場合、そのエッジはカラー クラス内でただちに強制的に単独になります。 (j - i) が常に 1 であり、その最小設定ビットが固定されているため、アルゴリズムは単一の色を割り当て、有効な自明な色を生成します。 

k が n に近い大きい場合、長いパスはまれですが、構築は k にまったく依存しません。 k に依存する適応カラーリングは中間のパス長では失敗する危険性があるため、この独立性は重要です。 ビットベースのパーティションは、すべての k に対して均一に正確さを保証します。 

差が 2 の累乗である場合、下位ビットは差そのものに等しいため、これらのエッジは独自の強力な位置合わせクラスを形成します。 アルゴリズムはこれらを一貫して別々の色として扱い、構造的に重要なエッジが誤って結合することを防ぎます。
