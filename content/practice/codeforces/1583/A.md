 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには個別の正の整数の配列があり、タスクは、選択された要素の合計が素数にならないように、できるだけ多くの要素を選択することです。 すべての有効な選択肢の中で、可能な最大サイズのサブセットを出力する必要があります。 

出力は合計そのものではなく、選択した要素のインデックスです。 したがって、本当の目標は、すべての要素を含めることができるかどうか、含めることができない場合は、どの最小の削除が総和の素数を修正するかを決定することです。 

重要な制約は、各配列の要素が最大 100 個、各値が最大 200 個であることです。これにより、サブセットの数が 2ⁿ と指数関数的に増加するため、すべてのサブセットをブルート フォースすることが不可能になります。 完全な列挙には、テスト ケースごとに最大約 2¹⁰⁰ のサブセットが必要になりますが、これは最適化された Python であっても実現可能な制限をはるかに超えています。 

重要な構造上の観察は、サブセットに対して任意の関数を最適化しているわけではないということです。 重要なのは、選択した要素の合計と、その合計が素数であるか合成であるかだけです。 

要素を貪欲に削除したり、サブセットを任意の順序でテストしようとする単純なアプローチは、微妙な場合に失敗する可能性があります。 たとえば、最小の要素を最初に削除しても必ずしも素数和が修正されるわけではなく、最大の要素を削除すると、別の削除でサイズが維持される場合でもサブセットが不必要に縮小される可能性があります。 

もう 1 つの失敗例は、完全な配列が常に有効であると仮定した場合に発生します。 合計が素数の場合、慎重に選択した要素を 1 つだけ削除すると修正される可能性があっても、完全なセットは無効になります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのサブセットを生成し、その合計を計算し、それが複合であるかどうかを確認し、条件を満たす最大のサブセット サイズを追跡します。 これは、すべての可能性を直接評価するため、正しいです。 ただし、2ⁿ のサブセットを評価する必要があり、各サブセットの合計を計算すると別の係数が追加され、実質的に O(n・2ⁿ) になります。 n = 100 の場合、これは不可能です。 

重要な観察は、サブセット空間を検索する必要がまったくないということです。 選択した要素の合計のみを考慮します。 すべての数値は正であるため、要素を追加すると常に合計が増加し、合計が素数でない限り、最大のサブセットは単純に完全な配列になります。 

合計がすでに合成されている場合、答えは自明ながらすべての要素になります。 唯一問題となるのは、合計が素数の場合です。 この場合、単一の要素を削除すると合計が変更され、1 つの要素を削除すると合計が合成されるかどうかを確認するだけで済みます。 すべての数値は正であるため、複数の要素を削除してもサブセット サイズがさらに小さくなるだけなので、最適な解決策は配列全体、または配列から 1 つの要素を引いたものでなければなりません。 

したがって、問題は、全和の素数をチェックし、それが素数である場合、その除去によって残りの和が合成される単一の要素を見つけることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・2ⁿ) | O(n) | 遅すぎる |
 | 最適 | O(n・√S) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 S をすべての要素の合計とします。 

1. すべての配列要素を合計して S を計算します。 これにより、配列全体の選択に対応する合計が得られます。 
2. √S までの約数を試して、S が素数であるかどうかを確認します。 S が複合の場合、作業は完了し、すべてのインデックスを選択できます。 
3. S が素数の場合、要素を 1 つだけ削除する必要があります。 各インデックス i を試し、S - a[i] を計算します。 この値が複合値の場合、i と stop を除くすべての要素を選択できます。 
4. 結果のサブセットを出力します。 

1 つの要素の削除のみを考慮する理由は、複数の要素を削除するとサブセット サイズが厳密に減少し、カーディナリティが最大化されるためです。 

### なぜ効果があるのか

正しさは単純な極論に依存します。 有効な答えはすべて、完全な配列のサブセットです。 合計が複合である場合、その合計はサイズにおいてすべての小さなサブセットよりも優れているため、最適である必要があります。 合計が素数の場合、有効な解はその正確な合計を回避する必要があります。 最大サイズを維持する最も近い方法は、可能な限り最小の数の要素を削除することです。合計を正の量だけ変更すると、正確な素数が壊れてしまうため、1 つの要素を削除するだけで十分です。 すべての単一の削除をテストするため、有効な最大サブセットが存在する場合は必ずそれを見つけることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_prime(x):
    if x < 2:
        return False
    if x % 2 == 0:
        return x == 2
    i = 3
    while i * i <= x:
        if x % i == 0:
            return False
        i += 2
    return True

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    total = sum(a)

    if not is_prime(total):
        print(n)
        print(*[i + 1 for i in range(n)])
        continue

    # try removing one element
    found = False
    for i in range(n):
        if not is_prime(total - a[i]):
            print(n - 1)
            print(*[j + 1 for j in range(n) if j != i])
            found = True
            break

    # guaranteed to exist per problem statement
    if not found:
        # fallback (should never happen)
        print(1)
        print(1)
```この実装では、最初に合計を計算し、標準の √n 試行除算法を使用して素数性をチェックします。 合計が素数でない場合は、すべてのインデックスを直接出力します。 それ以外の場合は、各要素を反復処理し、要素を削除すると合成合計が生成されるかどうかを確認します。 最初に成功した候補が使用されます。 

フォールバック ブランチは安全のためのみに含まれていますが、問題はすべての場合において有効なサブセットの存在を保証します。

 ## 特殊なケース

 重要なエッジケースは、合計がちょうど素数になる場合です。 このような状況では、単一の要素を削除すると問題が解決しても、すべての要素を取得すると失敗します。 たとえば、次のような配列`[8, 1, 2]`合計は 11 になり、これは素数です。 アルゴリズムはこれを正しく検出し、合計が合成されるまで要素を 1 つずつ削除しようとします。 

もう 1 つのエッジ ケースは、単一の要素を削除しても素数の和が残る場合です。 この問題により、この状況が有効な入力では発生しないことが保証されるため、単一の削除に対する検索で十分であり、常に成功します。 

最後のエッジ ケースは、サイズ 3 の小さな配列です。ここでも、全合計が合成されるか、少なくとも 1 つの除去によって合成合計が生成されるため、ロジックが成り立ち、空のサブセットや複数の除去のサブセットを考慮する必要がなく、有効な答えが存在することが保証されます。
