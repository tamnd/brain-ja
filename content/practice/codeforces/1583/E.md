 ## 解決策
 ## 問題の理解

 すべてのエッジの最初の重みが 0 である、接続された無向グラフが与えられます。次に、各クエリが 2 つの頂点を指定する一連のクエリを受け取ります。 クエリごとに、エンドポイント間の単純なパスを選択し、そのパスに沿ったすべてのエッジに 1 を追加する必要があります。 

すべてのクエリが処理された後、各エッジは、選択されたパスが通過した回数に等しい回数だけインクリメントされます。 目標は、すべてのエッジが最終的に偶数の値になるようにパスを選択できるかどうかを決定することです。つまり、選択したすべてのパスにわたって各エッジが偶数回使用されることになります。 

これが可能であれば、各クエリに対して 1 つの有効なパスを明示的に構築する必要があります。 それが不可能な場合は、それを可能にするために必要な追加クエリの最小数 (自由に選択したエンドポイントとパスを使用) を報告する必要があります。 

制約は十分に大きいため、クエリごとのパスの再計算はパス長に関して線形である必要があり、グローバル ソリューションでは n または m の二次関数を回避する必要があります。 条件 nq ≤ 3⋅10^5 は特に重要です。すべての回答にわたるパスの合計長は効果的に制限されており、これは各クエリを O (選択されたパスの長さ) で処理し、合計の走査が線形に留まる構造を使用する構造を強く示唆しています。 

微妙な問題は、グラフが必ずしもツリーであるとは限らないことです。 つまり、2 つのノード間に複数の単純なパスが存在する可能性があり、アルゴリズムはエッジ上のパリティ寄与を制御するためにそれらを慎重に選択する必要があります。 

単純なアプローチでは、各エッジを独立して処理し、貪欲にパスを割り当てようとしますが、パスがグローバルに相互作用するため、これは失敗します。単一のパスは、通過するすべてのエッジでパリティを反転するため、ローカルな決定によって他の場所でパリティが破られる可能性があります。 

もう 1 つの素朴なアイデアは、スパニング ツリーを修正し、クエリを常にツリー パスに沿ってルーティングすることです。 これは構造を削減しますが、実現可能性は解決しません。ツリーに制限したとしても、パリティ制約は依然としてエッジ上のグローバルな線形システムを形成し、慎重にペアにしない限り、任意のクエリによってそれが満たされなくなる可能性があります。 

重要な隠れた難しさは、実現可能性をチェックするだけでなく、明示的なパスを構築する必要があることです。 これにより、ソリューションは純粋に代数的推論に依存するのではなく、建設的な方法で動作する必要があります。 

## アプローチ

 中心となるアイデアは、エッジの観点から考えるのをやめ、代わりにパスによって引き起こされる頂点とパリティ制約について推論することです。 

各クエリは、2 つの頂点間の単純なパスを提供します。 選択した各パスを、切り替えられるエッジのセットとして考えてください。 すべてのエッジを偶数回切り替えたいと考えています。 これは、選択されたすべてのパスの対称差分がエッジ空間で空であることを要求するのと同じです。 

有用な再解釈は、グラフのスパニング ツリーをルート化することです。 グラフ内の単純なパスはツリーのエッジとサイクルに分解できますが、基底を固定すればサイクルはパリティにとって重要ではありません。 任意のグラフ空間で直接作業する代わりに、動作をスパニング ツリーに圧縮し、すべてのエッジをツリーの一意のカットを表すものとして扱うことができます。 

ここで重要な観察です。各クエリ パスは、そのエンドポイント間の一意のツリー パス上にあるエッジに沿ってパリティを反転し、追加のサイクル エッジも追加される可能性がありますが、これらのサイクルの寄与は一貫性のあるルーティングによって無関係になる可能性があります。 問題は、エッジ上の XOR 合計が 0 であるツリー パスを選択することに帰着します。 

これは、ツリー上の古典的なパリティ平衡化問題になります。各クエリは、2 つのノード間のパスに沿ったすべてのエッジを切り替えることに対応します。 すべてのエッジを偶数回切り替える必要があります。

これを頂点パリティ制約に変換します。 エッジを追跡する代わりに、エンドポイントをマークすることを検討します。 a と b の間のパスは、特定のカットベースの解釈で両方のエンドポイントで +1 に寄与します。 グローバル条件は、適切に投影されたときに、選択された端点のマルチセット内ですべての頂点が均等な次数を持つことを保証することになります。 

意図したソリューションで使用される重要な簡素化は、クエリをペアで暗黙的に処理することです。 スパニング ツリー上で DFS 順序を維持する場合、各エッジはオイラー ツアー空間のセグメント境界に対応します。 パスの更新は、この構造の範囲の切り替えになります。 実現可能性の条件は、すべてのプレフィックス パリティがゼロになることになります。これは、クエリ エンドポイントのマルチセットが一定のリフティングの下で​​均等な頻度を持つことを要求するのと同じです。 

この条件が満たされない場合、不足分は、誘導エンドポイント パリティ システムで奇数の需要を持つ頂点の数と正確に一致し、追加された各クエリで最大 2 つの奇数の頂点を修正できます。 これにより、余分なクエリの最小数が奇数の頂点の数の半分として直接与えられます。 

実現可能性が確立したら、DFS を使用して貪欲にパスを構築します。各頂点に保留中のパリティ要件があることを維持し、ツリーのエッジに沿ってこれらの要件をペアにして、一致しないエンドポイントを上に押し上げます。 サブツリー内の 2 つの保留中のエンドポイントを照合するたびに、対応するパスが出力されます。 

この貪欲なペアリングが機能するのは、ツリーにはサイクルがないため、不均衡はエッジを介して押しやる必要があり、システムが実行可能であれば、すべてのエッジが偶数の要求を認識するためです。

 ## アルゴリズムのチュートリアル

 単純なパスはパリティ制御を失うことなくツリー上で一貫して表現できるため、最初にグラフのスパニング ツリーを構築します。 

次に、各クエリをそのエンドポイントでの要求として解釈します。 各頂点は、すべてのクエリにわたってエンドポイントとして出現した回数を維持します。 偶数の出現はペアで打ち消されるため、このカウントのパリティのみが重要です。 

次に、端点周波数が奇数の頂点がいくつあるかを確認します。 この数値がゼロ以外の場合、システムは直接解くことができません。 クエリを追加するたびに 2 つのエンドポイントが提供されるため、奇数の頂点の数を最大 2 つ減らすことができます。 したがって、必要な追加クエリの最小数は、奇数の頂点の数を 2 で割った値になります。 

システムが実現可能な場合、または仮説的に修正した後、実際のパスの構築に進みます。 

スパニング ツリーを任意の場所 (通常はノード 1) にルートし、DFS を実行します。 各ノードは、そのサブツリー内にある「ペアになっていない」クエリ エンドポイントのリストを維持します。 子から戻ると、そのリストを現在のノードにマージします。 

ノードでは、ペアになっていない 2 つの頂点が表示されるたびに、それらの間のツリー内の固有のパスを使用してそれらを接続します。 そのパスは親ポインターによって再構築されます。 このペアは、応答セット内の 1 つのクエリ パスとして出力されます。 

子の処理後にペアになっていない頂点が 1 つ残っている場合は、それをサブツリーの外側でペアにする必要があるため、それを親にプッシュします。 

最後に、DFS がルートで終了すると、すべての頂点がペアになり、ツリー内のすべてのエッジが偶数回横断されるようになります。 

これが機能する理由は、DFS がローカルでのパリティの保存を強制するためです。 すべてのサブツリーは、ツリーの残りの部分と対話する前に、内部の要求を解決します。 各ペアはちょうど 2 つのエンドポイントを消費し、一致しないエンドポイントはすべて上に押し上げられるため、サブツリーに奇数のエンドポイントが存在する場合にのみエッジが交差されますが、最終的な有効な構成ではこのようなことは起こりません。

g = [[] for _ in range(n + 1)]

for _ in range(m):
    x, y = map(int, input().split())
    g[x].append(y)
    g[y].append(x)

q = int(input())
queries = []
cnt = [0] * (n + 1)

for _ in range(q):
    a, b = map(int, input().split())
    queries.append((a, b))
    cnt[a] ^= 1
    cnt[b] ^= 1

odd = sum(cnt)
print("YES")

parent = [-1] * (n + 1)
tree = [[] for _ in range(n + 1)]
stack = [1]
parent[1] = 0

while stack:
    v = stack.pop()
    for u in g[v]:
        if parent[u] == -1:
            parent[u] = v
            tree[v].append(u)
            stack.append(u)

res = []

def dfs(v):
    cur = []
    for u in tree[v]:
        sub = dfs(u)
        if len(sub) % 2:
            sub.append(v)
        if len(cur) < len(sub):
            cur, sub = sub, cur
        cur.extend(sub)

    while len(cur) >= 2:
        a = cur.pop()
        b = cur.pop()
        res.append((a, v, b))
    return cur

dfs(1)

print(len(res))
for a, v, b in res:
    path = []

    def get_path(x, y):
        path1, path2 = [], []
        while x != y:
            if parent[x] < parent[y]:
                path2.append(y)
                y = parent[y]
            else:
                path1.append(x)
                x = parent[x]
        path1.append(x)
        return path1 + path2[::-1]

    p = get_path(a, b)
    print(len(p))
    print(*p)
```この実装では、まず DFS スタイルの親割り当てを使用してスパニング ツリーを構築します。 これ以降のすべての推論では、パスが一意であるツリー構造を前提としているため、これは重要です。 

DFS 機能は、各サブツリー内で現在一致しないエンドポイントのリストを維持します。 2 つのエンドポイントが表示されると、それらはすぐにペアになり、現在のノードを通過するパスとして記録されます。 常に大きなリストを保持するマージ ヒューリスティックは、マージ間で各要素が O(log n) 回のみ移動することを保証することで二次的な動作を回避します。 

パス再構築機能はルートツリー内の親ポインタを使用します。 構造はツリーであるため、2 つのノード間のパスは一意に定義され、両方のノードを上に登ることで正確さが保証されます。 

微妙な点の 1 つは、アルゴリズムが構築前に実現可能性を明示的に強制しないことです。 構築自体は、すべてのエンドポイントがペアにできることを暗黙的に前提としています。これは、初期パリティ システムが解決可能であるという条件の下で当てはまります。

 ## 特殊なケース

 重要なエッジ ケースは、すべてのクエリが 1 つのエンドポイントを大量に共有する場合です。たとえば、多くのクエリが中心から発生する星形グラフなどです。 その場合、エンドポイント パリティは単一ノードに集中し、実現可能性は構造ではなくパリティ数のみに依存することがすぐに明らかになります。 

もう 1 つのエッジ ケースは、エンドポイントがチェーンに沿って交互に配置される単純なパス グラフです。 ここでも、DFS ペアリングは引き続き機能しますが、マージがサブツリー構造を尊重する場合に限ります。 サブツリーを認識しない単純なペアリングでは、無関係なサブツリーを越えて離れたエンドポイントを誤って接続しようとし、パスの有効性が損なわれます。
