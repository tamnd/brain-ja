 ## 解決策
 ## 問題の理解

 長方形のボードが与えられ、各セルはブロックによってブロックされています。`X`または空です。 空のセルからは上または左にのみ移動できます。 このような動きのシーケンスによってグリッドから離れることができる場合、そのセルは終了可能と呼ばれます。 問題は、それらの動きをシミュレートすることではありません。 代わりに、列の多くの間隔について、終了可能なセルのパターンがその列範囲内のブロックされたセルの元の配置を一意に決定するかどうかを判断する必要があります。 

各クエリは連続した列のセットを取得し、2 つの異なる障害物構成がまったく同じ脱出パターンを生成できるかどうかを尋ねます。 曖昧さがなければ答えます`YES`。 それ以外の場合はお答えします`NO`。 

製品`n × m`せいぜい`10^6`, so processing the whole grid once is affordable. クエリ数が到達しました`2·10^5`これにより、クエリごとにサブグリッド全体をスキャンするソリューションは除外されます。 間隔の幅にわたる線形スキャンでも、おおよその結果が得られます。`2·10^11`最悪の場合の運用。 クエリ処理は定数時間または対数時間である必要があります。 

難しいのは、どのような局所的なパターンがあいまいさを生み出すのかを理解することです。 

考慮する```
.X
X.
```左下のセルと右上のセルは両方ともブロックされています。 これら 2 つの障害が、情報の伝達を妨げるコーナーを形成します。 右下のセルもブロックされた場合、同じ終了パターンが表示されます。 ブロックされたセルをカウントするだけの不注意なソリューションでは、これを見逃してしまいます。 

もう 1 つの微妙なケースは、単一列です。```
X
.
X
```左右のエンドポイントが同じであるすべてのクエリは、次の値を返す必要があります。`YES`曖昧さを生み出す可能性のある隣接する列のペアがないためです。 

3 番目のエッジ ケースは、いくつかの不良位置が存在するが、そのすべてがクエリ間隔の外側にある場合に発生します。```
..X.
.X..
....
```唯一問題のある境界が列 2 と列 3 の間にあると仮定します。`[1,2]`まだ戻るべきです`YES`。 列範囲が異なれば動作も異なるため、グリッド全体に対するグローバルな答えだけでは十分ではありません。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのクエリを個別に検査します。 列間隔の場合`[l,r]`、対応するサブグリッドを検査し、その中にあいまいな構造が存在するかどうかを判断できます。 このアプローチは、クエリされた領域を直接チェックするので正しいですが、最悪の場合、各クエリはほとんどの領域に影響を及ぼします。`10^6`細胞。 と`2·10^5`クエリの合計作業量は約`2·10^11`限界をはるかに超えた操作。 

重要な観察は、曖昧さは 1 種類のローカル構成のみから生じるということです。 セルを仮定します`(i,j)`そして細胞`(i-1,j+1)`どちらもブロックされています。 次に、これら 2 つの障害物が対角のコーナーを形成します。```
. X
X .
```このようなパターンが 2 つの隣接する列にわたって存在すると、一部のセルの正確な配置を出口可能性情報だけから再構築することは不可能になります。 

これは、問題のあるすべての構造が 2 つの隣接する列間の境界によって表現できることを意味します。 各列ごとに`j`、ある行に両方が含まれているかどうかだけを知る必要があります。`(i,j)`そして`(i-1,j+1)`ブロックされました。 その場合、列間の境界`j`そして`j+1`悪いです。 

クエリ`[l,r]`これらの列の間に少なくとも 1 つの不正な境界がある場合、は無効になります。 これにより、問題は 1 次元配列に対する範囲存在クエリに変換され、プレフィックス maxima を使用して簡単に処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(qnm) | お(1) | 遅すぎる |
 | 最適 | O(nm + q) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取り、配列を作成します`bad`長さの`m+1`、最初はゼロで埋められます。 
2. すべてのセルについて`(i,j)`と`i ≥ 1`そして`j ≥ 1`、両方かどうかを確認してください`(i,j-1)`そして`(i-1,j)`含む`X`。 

これら 2 つのセルは対角線パターンを形成します```
. X
X .
```その存在が曖昧さを生み出します。 
3. そのようなペアが存在する場合は、列の境界をマークします。`j`設定によって悪い`bad[j]=1`。 

値`j`列間の境界を表します`j`そして`j+1`1 ベースのインデックス付け。 
4. プレフィックス合計配列を構築する`pref`。`pref[j]`位置間の不正な境界の数を保存します`1…j`。 
5. 各クエリについて`[l,r]`、計算する```
pref[r-1] - pref[l-1]
```この量は、厳密に間隔内にある不良境界をカウントします。 
6. カウントがゼロの場合、出力`YES`。 それ以外の場合は出力`NO`。 

### なぜ効果があるのか

 情報の損失はすべて、オブジェクトの対角を占めるブロックされたセルの対角線ペアから発生します。`2×2`四角。 このようなペアがあると、同じ脱出パターンを生み出すいくつかの障害物構成を区別できなくなります。 

クエリ間隔は、隣接する列のペアのいずれにもそのような対角線の競合が含まれていない場合に正確に決定できます。 すべての不正な構成は隣接する列間の単一の境界に局在化されているため、すべての不正な境界を保存し、それらの境界に対する範囲クエリに応答することで、必要な条件を正確に取得できます。 区間内に不正な境界がないということは、あいまいさが存在しないことを意味しますが、不正な境界が 1 つでも存在すると、すでに複数の有効なグリッドが作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
grid = [input().strip() for _ in range(n)]

bad = [0] * (m + 1)

for i in range(1, n):
    for j in range(1, m):
        if grid[i][j - 1] == 'X' and grid[i - 1][j] == 'X':
            bad[j] = 1

pref = [0] * (m + 1)
for j in range(1, m + 1):
    pref[j] = pref[j - 1] + bad[j]

q = int(input())
ans = []

for _ in range(q):
    l, r = map(int, input().split())
    if pref[r - 1] - pref[l - 1] == 0:
        ans.append("YES")
    else:
        ans.append("NO")

sys.stdout.write("\n".join(ans))
```ネストされたループは次の間隔でスキャンします。`2×2`間接的に正方形になります。 右上と左下のセルが両方ともブロックされている場合、それらの列間の境界が問題になります。 

配列`bad`1 から始まる境界番号付けを使用します。 位置`j`列間の境界に対応します`j`そして`j+1`。 このインデックス付けは間違いやすいです。 クエリ`[l,r]`境界が含まれています`l,l+1,…,r-1`、式を説明します。`pref[r-1]-pref[l-1]`。 

すべてのカウントが最大値であるため、整数オーバーフローは問題になりません。`m≤10^6`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nm + q) | グリッドを 1 回通過し、クエリごとに一定の作業が行われます。 
| スペース | O(m) | 配列`bad`そして`pref`|

 以来`nm≤10^6`、前処理フェーズでは約 100 万回の操作が実行されます。 応答する`2·10^5`一定時間内のクエリは制限内に簡単に収まります。 

## テストケース```python

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    bad = [0] * (m + 1)

    for i in range(1, n):
        for j in range(1, m):
            if grid[i][j - 1] == 'X' and grid[i - 1][j] == 'X':
                bad[j] = 1

    pref = [0] * (m + 1)
    for j in range(1, m + 1):
        pref[j] = pref[j - 1] + bad[j]

    q = int(input())
    ans = []

    for _ in range(q):
        l, r = map(int, input().split())
        ans.append("YES" if pref[r - 1] - pref[l - 1] == 0 else "NO")

    return "\n".join(ans)

 ## 特殊なケース

 単一列クエリには、隣接する列のペアが含まれません。```
3 1
X
.
X
1
1 1
```の`bad`境界がまったくないため、配列はゼロのままになります。 クエリは計算します`pref[0]-pref[0]=0`、したがって、答えは次のとおりです`YES`。 

対角線の衝突を考える```
2 2
.X
X.
1
1 2
```前処理中、`(1,1)`左下と右上のセルは両方とも`X`、 それで`bad[1]=1`。 クエリが評価するのは、`pref[1]-pref[0]=1`、生産`NO`。 

最後に、競合がクエリされた間隔の外側にあると仮定します。```
3 4
..X.
.X..
....
2
1 2
2 4
```境界 2 のみが不良とマークされます。 のために`[1,2]`、違いは`pref[1]-pref[0]=0`、したがって、答えは次のとおりです`YES`。 のために`[2,4]`、違いは`pref[3]-pref[1]=1`、生産`NO`。 このアルゴリズムは、単一のグローバルな決定を使用するのではなく、各間隔を正しく分離します。
