 ## 解決策
 ## 問題の理解

 このゲームは、掃除機、ケトル、スピーカーの 3 台のロボットが決まった順序でプレイします。 彼らは 4 桁の番号を次々に呼び出しますが、プレイヤーは有効な動きをする前にいくつかの番号を試す必要がある場合があります。 プロトコルには、失敗した試行を含む、話されたすべての数字が含まれており、次で終わります。`0`。 

数値が有効であるのは、その数値に 4 つのゼロ以外の異なる桁があり、これまでに成功した数値として表示されておらず、最初の成功した手を除いて、その最初の桁が以前に成功した数値の最後の桁と一致する場合です。 試行が失敗すると、現在のロボットにペナルティ ポイントが与えられ、同じロボットが有効な数字を言うまで試行を続けます。 有効な数字を出した後、次のロボットに順番が移ります。 

このタスクは、ロボットごとに、試行した回数とペナルティの数を数えるというものです。 すべての音声数字は移動の試行であるため、最初の値には成功した試行と失敗した試行の両方が含まれます。 

入力サイズはステートメント内で明示的に制限されていませんが、プロトコルには多くの行を含めることができます。 すべての行を検査する必要があるため、自然なターゲットは入力の単一パスです。 すべての数値の履歴全体を繰り返しスキャンするソリューションは二次関数になる可能性があるため、不要です。 ルールは以前の成功した数値と、すでに使用された成功した数値のセットにのみ依存するため、線形シミュレーションで十分です。 

いくつかの詳細が不注意な実装を壊す可能性があります。 最初に話される番号には、以前の番号制限はありません。 例えば：```
1234
2345
0
```最初の数値は受け入れられ、2 番目の数値も受け入れられます。`2`の末尾の数字の後に続きます`1234`。 最初の手を受け入れる前に前の番号を必要とするソリューションは、誤って拒否されてしまいます。`1234`。 

数字の繰り返しは、成功した移動の場合にのみ禁止されます。 例えば：```
1234
4567
4567
0
```最初の 2 つの数値は有効です。 3 回目の試行は無効です。`4567`はすでに正常に使用されているため、出力は次のようになります。```
2 0
1 1
0 0
```話されたすべての番号を使用済みとしてマークするソリューションでは、以前の試行が失敗した場合、後の有効な番号も誤って拒否されます。 

すべての行の後に順番が変わるとは限りません。 例えば：```
1234
5678
6789
0
```後`1234`そして`5678`、スピーカーの試み`6789`前回の成功した番号が次で終わっているため、これは無効です`8`, そのため、スピーカーはペナルティを受け、有効な数字が表示されるまでターンを続けます。 

## アプローチ

 簡単なアプローチは、ゲームをシミュレートすることです。 話されたすべての数字について、すべてのルールを満たしているかどうかを確認します。 それが無効な場合、現在のプレーヤーのペナルティを増分し、プレーヤーを変更しないままにします。 有効な場合は、プレーヤーの成功した移動回数を増やし、その数値を使用済みセットに追加し、最後の桁を更新して、次のプレーヤーに切り替えます。 

この直接シミュレーションはすでに最適なアプローチです。 重要な観察は、ゲームの状態が非常に小さいということです。 次の数字が有効かどうかを判断するには、最後に成功した数字の終了桁、以前に成功した数字のセット、および現在のプレーヤーのインデックスのみが必要です。 ゲーム履歴を再構築したり、先を見据えたりする必要はありません。 

総作業量はプロトコルの行数に比例します。 ハッシュ セットを使用すると、数値が使用されたかどうかのチェックに平均一定の時間がかかるため、ソリューション全体は線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k²) | O(k) | 大規模なプロトコルには遅すぎる |
 | セットを使ったシミュレーション | O(k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 終端のゼロまでのすべての数値を読み取り、順番に処理します。 現在のプレーヤーは掃除機として開始され、インデックスで表されます。`0`。 
2. 話された番号ごとに、まずその番号が無効であると想定し、すべてのルールを確認します。 番号は 4 桁である必要があり、ゼロを含まず、繰り返しの数字がなく、既に受け入れられている一連の番号に含まれておらず、前の有効な番号が存在する場合は前の終了桁と一致する必要があります。 
3. 番号が無効な場合は、現在のプレーヤーに 1 つのペナルティを追加します。 同じロボットが挑戦し続ける必要があるため、プレイヤー インデックスは変わりません。 
4. 数値が有効な場合、現在のプレーヤーの移動カウントを増やし、その数値を使用済みセットに追加します。 最後に成功した数字の最後の桁を更新し、循環順序を使用してプレーヤーを切り替えます。 
5. プロトコルが終了したら、掃除機、ケトル、スピーカーの保存された統計を印刷します。 

シミュレーション中の不変条件は、保存された状態が実際のゲームの位置を正確に表すということです。つまり、現在のプレイヤーがそのターンのプレイヤーであり、使用されるセットには成功した数字のみが含まれ、保存された最後の桁は最後に成功した手のものです。 すべての新しい行はこの状態から判断されるため、すべての決定は元のルールと一致します。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    stats = [[0, 0] for _ in range(3)]
    used = set()

    player = 0
    last_digit = -1
    has_previous = False

    for line in sys.stdin:
        s = line.strip()
        if s == "0":
            break

        stats[player][0] += 1

        ok = True

        if len(s) != 4:
            ok = False
        else:
            if '0' in s:
                ok = False
            elif len(set(s)) != 4:
                ok = False

        if ok and s in used:
            ok = False

        if ok and has_previous and int(s[0]) != last_digit:
            ok = False

        if ok:
            used.add(s)
            last_digit = int(s[-1])
            has_previous = True
            player = (player + 1) % 3
        else:
            stats[player][1] += 1

    print(*stats[0])
    print(*stats[1])
    print(*stats[2])

if __name__ == "__main__":
    solve()
```配列`stats`ロボットごとに 2 つの値を保存します。 最初の値はロボットが話したすべての数値をカウントしますが、2 番目の値は失敗した試行のみをカウントします。 現在のプレーヤーはインデックスとして保存されます。`0`に`2`これにより、ターンの変更が簡単なモジュロ演算になります。 

セット`used`成功した数字のみが含まれます。 失敗しても数値は消費されないため、これは重要です。 変数`has_previous`最初の有効な手とそれ以降のすべての手を分離し、存在しない以前の数値との誤った比較を回避します。 

検証チェックは、状態を変更する前に実行されます。 有効な数値は使用されたセットと前の終了桁を更新しますが、無効な数値はペナルティ カウンタのみを変更します。 この順序により、失敗した試行が将来の移動に影響を与えるのを防ぎます。

import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        data = sys.stdin.read().splitlines()

        stats = [[0, 0] for _ in range(3)]
        used = set()
        player = 0
        last_digit = -1
        has_previous = False

        for s in data:
            if s == "0":
                break

            stats[player][0] += 1
            ok = True

            if len(s) != 4 or '0' in s or len(set(s)) != 4:
                ok = False
            if ok and s in used:
                ok = False
            if ok and has_previous and int(s[0]) != last_digit:

                used.add(s)
                last_digit = int(s[-1])
                has_previous = True
                player = (player + 1) % 3
            else:
                stats[player][1] += 1

        return "\n".join(f"{a} {b}" for a, b in stats) + "\n"
    finally:
        sys.stdin = old_stdin

 ## 特殊なケース

 最初の動きは特別です。なぜなら、前に成功した数字がないからです。 入力時:```
1234
2345
0
```アルゴリズムは次から始まります`has_previous = False`, したがって、最初の桁の比較はスキップされます。`1234`が受け入れられると、前の数字が`4`、 そして`2345`で始まるので受け入れられます`2`。 

繰り返し成功した数値の場合:```
1234
4567
4567
0
```最初の 2 行は`used`セット。 スピーカーが言うと`4567`の場合、その番号はセット内にあるため、スピーカーはペナルティを受けてターンを維持します。 スピーカーからの将来の番号は引き続き通常どおりチェックされます。 

ゲームの状態を変更しない無効な試行の場合:```
1234
5670
6789
0
```掃除機は正常に再生されました`1234`。 やかんを試す`5670`、これはゼロが含まれているため無効であるため、ケトルはペナルティを受けます。 次の番号`6789`は依然としてやかんの動きとして判断され、で始まるため、`6`、それは受け入れられます。 失敗した試行は、前の桁や使用されたセットには影響しませんでした。
