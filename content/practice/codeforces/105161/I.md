 ## 解決策
 ## 問題の理解

 それぞれ 2 色のいずれかでタグ付けされた一連の整数が与えられます。 数字は左から右に到着します。 各番号が表示されるたびに、現在「ペアになっていない」番号のマルチセットが維持されます。 以前に保存された反対色の数字が少なくとも 1 つ存在する場合、そのような数字を 1 つ選択して反応を行うことができます。選択された 2 つの数字は削除され、その合計に等しい単一の数字に置き換えられ、2 番目のマルチセットに記録されます。 その時点で反対色のパートナーが存在しない場合、新しい番号は待機プールに追加されるだけです。 

このプロセスは、すべての要素が処理され、考えられるすべての反応 (選択された組み合わせに従って) が実行されるまで続きます。 目標は、このプロセスをシミュレートすることだけではなく、生成されるすべての合計の最小値ができるだけ大きくなるように、戦略的に組み合わせを選択することです。 

主な問題は、組み合わせの決定がグローバルであることです。 初期のペアリングが小さいと、後の要素の一致が悪化する可能性があり、生成される最小合計が減少する可能性があります。 

制約はここでは明示的に述べられていませんが、並べ替えと二分探索を必要とする解決策の存在は、最大約 2×10^5 要素であることを強く示唆しています。 これにより、二次ペアリングのシミュレーションが即座に除外されます。 すべての選択肢を試す素朴な貪欲なシミュレーションでさえ、各要素が他の多くの要素とペアになる可能性があり、指数関数的な分岐につながる可能性があるため、実行不可能です。 

ある色のすべての要素が他の色よりもはるかに小さい場合、微妙なエッジ ケースが表示されます。 たとえば、すべての赤が 1 で、すべての青が大きい場合、どの組み合わせでも青を繰り返し使用する必要があります。 貪欲に即座にペアにする単純な戦略では、たとえ有効なグローバルな取り決めが存在していたとしても、誤って小さな青を早期に消費し、後で大きな赤の制約を満たせなくなる可能性があります。 

## アプローチ

 直接的なアプローチは、反対色の要素が現れるたびにすべての可能な組み合わせを試しながらプロセスをシミュレートすることです。 それぞれの新しい要素には複数の有効なパートナーが存在する可能性があり、将来の実現可能性は以前の選択に依存するため、これはすぐに指数関数的になります。 ローカル ヒューリスティックによる枝刈りでも、グローバルな依存関係は修正されません。ペアにする要素を選択すると、将来のペアリングに使用できるプールが変更されます。 

中心的な観察は、ペアリングを出力することは求められておらず、生成されたすべての合計が少なくともあるしきい値 x であることを保証できるかどうかを判断することだけを求められているということです。 これにより、問題は実現可能性のチェックに変換されます。 候補 x をテストできれば、可能な最大の答えを二分探索できます。 

固定 x の場合、すべての反応は少なくとも x の合計を生成する必要があります。 要素 y を別の要素 z と組み合わせる場合は、z ≥ x − y でなければなりません。 これにより、どのパートナーが受け入れられるかについて厳しい制約が課されます。 

今度は構造が貪欲になります。 要素を処理するとき、マルチセット S1 には常に単一色の要素が含まれます。これは、反応が発生するたびに、その時点で各色の 1 つの要素が削除されるためです。 したがって、いつでも、制御された方法で色の遷移によってプールが効果的に分離され、ペアリングの順序を推論できるようになります。 

現在のプールから異なる色の要素 y を見つけた場合、それを z ≥ x − y を満たす S1 の要素と一致させる必要があります。 すべての有効な選択肢の中で、そのような最小の z を選択することが最適です。 直観的には、大きな要素は将来のより厳しい制約を満たすことができるため、より「柔軟性」があると考えられます。 小さい有効な要素が存在するときに大きな要素を早い段階で無駄にすると、将来の要素が大きなパートナーを必要とするが、誰も残っていないときに、後で失敗を余儀なくされる可能性があります。 

これは、貪欲な実現可能性チェックにつながります。S1 をソートされた構造に維持し、常に最小の有効なパートナーを選択します。 いずれかの時点で有効なパートナーが存在しない場合、しきい値 x は不可能です。

 ## アルゴリズムのチュートリアル

 答えを値 x として扱い、生成されたすべての合計が少なくとも x であることを確認できるかどうかをテストします。 

1. 候補値 x を決定します。 すべての合計が少なくとも x になるようにすべての反応を配置できるかどうかを確認します。 これにより、最適化が意思決定問題に変換されます。 
2. 現在一致していない要素のマルチセット S1 を値順に維持し、現在の処理フェーズによって暗黙的にそれらの色の状態を追跡します。 
3. 要素を左から右にスキャンします。 新しい要素 y を挿入すると、可能であれば、現在 S1 にある反対色の要素と即座に反応しようとします。 
4. S1 に反対色の要素がない場合は、単に y を S1 に挿入して続行します。 これにより、将来の試合に対する柔軟性が保たれます。 
5. 適格な反対色の要素がある場合は、z + y ≥ x となるように S1 から 1 つの z を選択する必要があります。 S1 でそのような最小の z を検索します。 そのような z が存在しない場合は、y を安全にペアにすることができないため、この x を直ちに拒否します。 
6. そのような z が存在する場合、それを S1 から削除し、ペアリングを暗黙的に記録します。 新しい値 z + y は概念的には S2 に配置されますが、S2 は実現可能性によってのみ重要になります。 
7. すべての要素が正常に処理された後、x を実行可能として受け入れます。 
8. 0 から max(ai) + max(ai) までの範囲で x を二分探索し、上記の貪欲な手順を使用して毎回実現可能性をチェックします。 

正確さは、単調な実現可能性特性から得られます。つまり、値 x が実現可能であれば、それより小さな値も実現可能です。 これにより二分探索が可能になります。 

貪欲チェック中の重要な構造的不変条件は、ペアリングを実行するときは常に、最小の有効なパートナーを維持することで将来の柔軟性を最大限に維持できるということです。 すべての有効な選択肢はすでに制約 z ≥ x − y を満たしているため、より大きな選択肢を選択しても、現在の実現可能性は向上せずに将来の要素の選択肢が減るだけになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(x, vals, col):
    # S1 as sorted list
    import bisect
    s1 = []

    for y, c in zip(vals, col):
        if not s1:
            s1.append((y, c))
            continue

        # try to match if opposite color exists
        # check if any opposite color exists
        has_opposite = any(cc != c for _, cc in s1)

        if not has_opposite:
            s1.append((y, c))
            s1.sort()
            continue

        # try greedy match
        need = x - y

        # find smallest valid opposite-color element >= need
        best_idx = -1
        best_val = None

        for i, (v, cc) in enumerate(s1):
            if cc != c and v >= need:
                best_idx = i
                best_val = v
                break

        if best_idx == -1:
            return False

        # remove chosen element
        s1.pop(best_idx)

    return True

def solve():
    n = int(input())
    vals = list(map(int, input().split()))
    col = list(map(int, input().split()))

    lo, hi = 0, max(vals) * 2

    def ok(x):
        return check(x, vals, col)

    ans = 0
    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、説明どおりに実行可能性チェックに従います。 二分探索は単調述語をラップします。 

最もデリケートな部分は、パートナー要素の選択です。 しきい値条件を満たす最小の有効な反対色の要素を明示的にスキャンします。 これは Python では漸近的に最適ではありませんが、概念的な貪欲ルールを直接反映しています。 完全に最適化された実装では、これは色ごとに分割された 2 つのバランスの取れた構造に置き換えられます。 

意味のある最適なペアリング構造では有効な合計がその範囲を超えることができないため、二分探索の上限は最大要素値の 2 倍として選択されます。

 ## 特殊なケース

 重要なエッジケースは、初期の大きな要素を後で照合するために保存する必要がある場合です。 たとえば、小さな y が初期に出現し、技術的には大きな z とペアになることができますが、それをペアリングすると、後の大きな y が有効なパートナーを見つけることができなくなる場合、最小の有効な z を選択する貪欲なルールによってこれが防止されます。 このアルゴリズムにより、可能な限り大きな値が保存され、将来の実現可能性が維持されます。 

もう 1 つのエッジ ケースは、S1 に残っているすべての候補が入力要素と同じ色である場合です。 その場合、値に関係なく反応は許可されず、アルゴリズムは無効な一致を強制することなく挿入を正しく延期します。 

最後のエッジケースは、x の設定が高すぎる場合に発生します。 最初に失敗したペアリングは実行不可能であることがすぐに明らかになり、バイナリ検索の効率に不可欠な不必要なスキャンの継続が妨げられます。
