 ## 解決策
 ## 問題の理解

 整数のマルチセットまたは配列が与えられます。 ゲームでは 2 人のプレーヤーが交互にターンします。 各ターンで、プレイヤーは構造内に存在する現在の最大値を 1 つ削除することができます。 それを削除した後、プレイヤーは、何も追加しない可能性も含め、ステートメントで説明されている利用可能な「プレフィックスのような」プールから選択された、その最大値よりも厳密に小さい要素のサブセットを追加することもできます。 

ゲームは有効な手がなくなるまで続き、動けなかったプレイヤーが負けとなります。 タスクは、初期設定から、最初のプレーヤーが強制的に勝利するかどうか、または 2 番目のプレーヤーが勝つために常に最適な対応ができるかどうかを判断することです。 

この操作はリッチに聞こえますが、重要な隠された構造は、グローバルに関連する唯一の数量は、最初に表示される最大値の回数であるということです。 

複雑さの観点から見ると、入力サイズは要素数に比例します。 これにより、ゲーム ツリーのシミュレーションが即座に除外されます。 各削除後の状態をモデル化しようとしたり、追加されたすべての可能な構成を追跡しようとするアプローチは、それぞれの移動が多くの可能なサブセットに分岐するため、組み合わせ的に爆発的に増加します。 

唯一の実行可能な解決策は、ゲームを線形時間で計算される単一の集計統計に縮小する必要があります。 

微妙なエッジケースは、すべての要素が等しい場合です。 その状況では、すべての動きは単に最大値を削除するだけであり、意味のある「より小さいプレフィックス」は存在しません。 素朴な読者は、オプションの追加操作が結果に影響を与える可能性があると考えるかもしれませんが、最大の要素を繰り返し削除することによってプレイが完全に決定されるという事実は決して変わりません。 

たとえば、配列が次の場合、`[5, 5, 5]`、各移動は`5`。 ゲームは3手で終了し、最初のプレイヤーが勝ちます。 そうであれば`[5, 5]`、2番目のプレイヤーが勝ちます。 これはすでにパリティ現象を示唆しています。 

## アプローチ

 ブルートフォース手法では、ゲームを明示的にシミュレートします。 各状態は現在のマルチセットを保存し、各遷移は 1 つの最大値を削除し、追加する小さな要素の可能なすべてのサブセットに分岐します。 小さな要素のサブセットの数が指数関数的に増加する可能性があり、ゲーム状態の数が爆発的に増加するため、これはすぐに実行不可能になります。 中程度の場合でも`n`、このアプローチは非常に小さなインスタンスを超えて進むことはできません。 

重要な観察は、追加された要素が現在の最大値と一致しない限り、最大値のアイデンティティに影響を与えないということです。追加できるのはより小さい要素のみであるため、これは禁止されています。 したがって、マルチセット内の最大値は、現在の最大値がすべて削除された場合にのみ厳密に減少します。 最大値を下回る内部構造は、最大削除数に影響を与えません。 

これにより、ゲームは純粋なカウント プロセスに縮小されます。最大値が出現するたびに、制御が切り替わる 1 つの重要な動きに対応します。 オプションの操作は、最大値が削除される回数の同等性に影響を与えず、最適なプレイで勝者を完全に決定します。 

したがって、問題は、グローバル最大値に等しい要素の数を数え、この数が奇数か偶数かをチェックすることに集約されます。

 ## アルゴリズムのチュートリアル

 ここで、最適推論プロセスを直接のシーケンスで説明します。 

1. 入力配列を読み取り、存在する最大値を特定します。 すべての操作は最大値の削除を中心に展開されるため、これはゲーム内の強制構造を決定する唯一の値です。 
2. この最大値が配列内に何回出現するかを数えます。 各手によって最大値が 1 つだけ削除されるため、このカウントはゲーム内の重要な手の合計数を表します。 
3. このカウントの同等性に基づいて勝者を決定します。 最大要素の数が奇数の場合、最初のプレイヤーが最後の手を打って勝ちます。 互角の場合は、2 番目のプレーヤーが最後の動きをして勝ちます。 

重要な考え方は、プレイヤーが小さな要素のオプションの挿入をどのように使用しても、残りの最大要素の数を増やすことはできず、最終的に各最大要素を 1 つずつ削除する必要があるという事実を変えることはできないということです。 

### なぜ効果があるのか

 不変条件は、二次操作とは関係なく、最大要素のマルチセットが移動ごとに正確に 1 つずつ減少することです。 すべての追加挿入には厳密に小さい値が含まれるため、現在の最大層に影響を与えることはできません。 

この分離により、ゲームは固定長のシーケンスに分解されます。`k`強制的な移動、どこで`k`最大要素数です。 プレイヤーはこれらの強制的な動きを交互に行いますが、スキップしたりマージしたりすることはできません。 したがって、勝者は完全に次のいずれかによって決まります。`k`奇数か偶数です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, input().split()))
    if not data:
        return
    n = data[0]
    arr = data[1:1+n]

    mx = max(arr)
    cnt = 0
    for x in arr:
        if x == mx:
            cnt += 1

    print("First" if cnt % 2 == 1 else "Second")

if __name__ == "__main__":
    solve()
```このソリューションでは、まず入力を単一パスで解析します。 Python の組み込み関数を使用して最大値を計算し、単純なループでその出現回数をカウントします。 これにより、不必要なデータ構造が回避されます。 

よくある実装の落とし穴は、入力形式が`n`配列値と同じ行にあるため、直接分割は慎重に処理する必要があります。 もう 1 つの微妙な点は、変換されたデータに誤って重複が含まれる要素以上の比較ではなく、最大値に等しい要素のみがカウントされるようにすることです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 1 回のパスで最大出現回数と発生回数を検出します。 
| スペース | お(1) | 少数の整変数のみが使用されます。 

このアルゴリズムは、Codeforces に典型的な制約内に簡単に適合します。`n`まで`2 × 10^5`またはそれ以上。 これにより、シミュレーションが回避され、ゲーム全体が配列の 1 回のスキャンに短縮されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    data = list(map(int, inp.split()))
    n = data[0]
    arr = data[1:1+n]
    mx = max(arr)
    cnt = sum(x == mx for x in arr)
    return "First" if cnt % 2 == 1 else "Second"

# minimum case
assert run("1\n5") == "First"

# simple even case
assert run("2\n1 1") == "Second"

# mixed values
assert run("5\n1 3 3 2 3") == "First"

# all distinct
assert run("4\n1 2 3 4") == "First"

# large parity check
assert run("6\n9 1 9 2 9 2") == "Second"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 5`| 最初 | 単一要素の基本ケース |
 |`2 1 1`| 2番目 | 偶数の最大数 |
 |`5 1 3 3 2 3`| 最初 | 典型的な混合分布 |
 |`4 1 2 3 4`| 最初 | すべての要素は最大 1 回またはタイの処理です。 
|`6 9 1 9 2 9 2`| 2番目 | より大きな偶数パリティの場合 |

 ## 特殊なケース

 次のような単一要素配列の場合`[x]`、最大値が 1 回表示され、それを削除すると最初のプレイヤーがすぐに勝ちます。 アルゴリズムはカウントを正確に識別します`1`そして先手プレイヤーの勝利を返します。 

すべての要素が同一である配列の場合、次のようにします。`[7, 7, 7, 7]`、すべての要素は最大値です。 カウントは 4 なので、2 番目のプレイヤーの勝ちです。 各移動が枯渇するまで 1 つの要素を削除するため、シミュレーション ビューはこれに正確に一致します。 

一意の最大値と多数の小さな要素を持つ配列の場合、`[10, 1, 1, 1]`、最大カウントは 1 で、最初のプレイヤーの勝利が保証されます。 「より小さいプレフィックスを追加する」操作を使用しようとしても、決定的な動きが 1 つだけ存在するという事実は変わりません。
