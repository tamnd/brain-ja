 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times m$各セルに重みがあるグリッド。 タスクは、このグリッド上に重なり合わない長方形タイルを配置して、カバーされるセルの重みの合計を最大化することです。 各タイルは、辺の長さの 1 つが 1 に固定され、もう一方の辺は任意の正の整数にできるという意味でドミノのようなオブジェクトです。そのため、すべてのタイルは、単一行の任意の長さの水平セグメントか、単一列の任意の長さの垂直セグメントのいずれかになります。 

これらのタイルが「L 字型に 4 つ接続されていない」という制約は、2 つの垂直方向の隣接と 1 つの水平方向の隣接が 1 つのコーナーに組み合わされ、カバレッジ相互作用の 2×2 コーナー パターンを形成する重なり合う直交セグメントに対応する構成の作成が禁止されることを意味します。 簡単に言うと、行ごとにカバレッジを決める際に、上に続く縦のセグメントと、同じ列の前の行から始まる横のセグメントが競合しないように一貫性を確保する必要があります。 これはまさに、従来のプロファイルまたはプラグ動的プログラミングに見られる種類の依存関係です。 

入力はグリッドの次元と重み行列です。 出力は単一の整数、つまり有効なタイリングの下で​​カバーされるセルの達成可能な最大合計です。 

主な問題は、タイルの配置の決定がローカルではないことです。 タイルを水平方向または垂直方向に拡張することを選択すると、将来の行と列に影響を与えるため、貪欲な行処理や独立した行処理が妨げられます。 

素朴な解釈では、すべてのタイリング、さらには長方形のすべてのサブセットを列挙しようとします。 各行を個別に制限するだけでも、すでに指数関数的に複雑になります。$m$、各行を任意のセグメントに分割できるためです。 行全体にわたる互換性の制約により、これがさらに悪化します。 

エッジケースは次の場合に発生します。$n = 1$または$m = 1$、グリッドは単一の線に縮退します。 その場合、最適な解決策は単に行全体または列全体を 1 つのタイルとして取得することですが、両方の次元が重要であると想定する単純な DP は依然として無効な状態遷移を伝播しようとする可能性があります。 もう 1 つのエッジ ケースは、すべての重みが負の場合です。 空のカバレッジが許可される場合、最適な答えはゼロであり、それ以外の場合は解釈に応じて最適な単一セグメントになります。 正しい DP では、有効な状態として「何も配置しない」ことが許可される必要があります。 

## アプローチ

 強引なアプローチでは、制約を満たす水平セグメントと垂直セグメントにグリッドを分割する可能なすべての方法を列挙しようとします。 構成ごとに、カバーされるすべてのセルの合計を計算し、最大値を保持します。 

各セルについて、水平セグメントまたは垂直セグメントのどちらを開始するかを決定することに注意を限定したとしても、可能性の数は指数関数的に増加します。$nm$。 各セルは二者決定に参加し、妥当性制約により隣接するセルが両方向に結合され、大まかに次の結果が得られます。$O(2^{nm})$州。 これは、非常に小さなグリッドを超えると完全に実行不可能です。 

重要な構造上の観察は、グリッドがスキャン順序で処理できること、および有効性を保証するために必要な唯一の情報は、各列が現在の行と前の行の間でどのように相互作用するかであるということです。 行内を左から右にスイープするときは、各列の前の行から垂直セグメントがすでに「アクティブ」であるかどうかも知る必要があります。 これにより、当然のことながら、あるサイズのビットマスクを超えるプロファイル DP 状態が発生します。$m$、不正な L 字型のオーバーラップを防ぐために、列ごとに垂直継続情報の 1 ビットの追加ビットが追加されます。 

これはまさにプラグ DP です。タイル形状の完全な履歴を保存する代わりに、境界の相互作用のみを保存します。

 ## アルゴリズムのチュートリアル

 現在の行境界における各列の状態を記述するビットマスクを維持しながら、行優先の順序でグリッドをセルごとに処理します。 

1. DP 状態を定義します$dp[i][j][S]$、 どこ$(i, j)$行優先トラバーサルの現在位置です。$S$各列が行間の境界で現在「占有」されているか「開いている」かをエンコードします。 実際には、これをマスク上でのみローリング DP に圧縮します。 
2. 各セルで$(i, j)$、未使用のままにするか、タイルに含めるかを決定します。 未使用のままにしておくと、状態が変更されずに前方に伝播されるだけで、将来の配置の互換性が維持されます。 
3. 含めることを選択した場合$(i, j)$、右に伸びる水平セグメントに属するか、下に伸びる垂直セグメントに属するかを決定する必要があります。 水平方向の拡張は現在の行マスクにのみ影響しますが、垂直方向の拡張は列内の次の行の状態に影響します。$j$。 
4. 微妙な制約により、無効なコーナー インタラクションが防止されます。 垂直セグメントが前の行から列に続いている場合$j$、また水平セグメントを次の位置で開始します。$(i, j)$の場合、条件に違反する L 字型の交互作用が形成されます。 これを防ぐには、列がアクティブであるかどうかだけでなく、それが上から来たのか、新しく開始されたのかも状態でエンコードする必要があります。 
5. これを強制するために、マスクを拡張して列ごとに 2 層の情報を保存します。つまり、セルがすでに上から覆われているかどうか、および現在同じ行で水平に拡張されているかどうかです。 これにより、遷移によって競合する重複が発生することがなくなります。 
6. すべてのマスクとトランジションを反復処理し、選択したセルが覆われているときにそのセルの重みを追加することで DP 値を更新します。 
7. ローリング配列を使用します$(i, j)$、前のステップのみが必要なため、メモリが削減されます。$O(nm2^m)$に$O(m2^m)$。 

### なぜ効果があるのか

 どのステップでも、DP 状態はグリッドの処理済み部分と未処理部分の間の相互作用フロンティアを完全に記述します。 このフロンティアを横切るタイルはすべてその状態で表現する必要があり、無効な L 字型構成では、列が同時に垂直方向に継続しているかどうか、および水平セグメントを開始しているかどうかについて矛盾した情報が必要になります。 状態によってこれらの役割が明示的に分離されるため、すべての遷移で一貫性が維持されます。 すべての有効なタイリングは一貫した状態遷移の 1 つのシーケンスに正確に対応し、すべての遷移はタイル制約を尊重するため、DP はすべての有効な構成を重複または省略することなく列挙します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    # DP over profile masks
    # state: mask of columns currently "open from previous row"
    # interpretation: 1 means column has a vertical continuation constraint active

    INF = -10**18
    dp = [INF] * (1 << m)
    dp[0] = 0

    for i in range(n):
        for j in range(m):
            ndp = [INF] * (1 << m)
            w = a[i][j]

            for mask in range(1 << m):
                if dp[mask] == INF:
                    continue

                cur = dp[mask]

                # 1. skip cell
                if cur > ndp[mask]:
                    ndp[mask] = cur

                # 2. take cell as horizontal start/extension
                # only allowed if no vertical conflict in this column
                if not (mask & (1 << j)):
                    new_mask = mask
                    if cur + w > ndp[new_mask]:
                        ndp[new_mask] = cur + w

                # 3. take cell as vertical continuation into next row
                # mark column j as active downward
                new_mask = mask | (1 << j)
                if cur + w > ndp[new_mask]:
                    ndp[new_mask] = cur + w

            dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```この実装では、DP を状態ごとに 1 つのマスクに圧縮します。各ビットは、垂直セグメントがその列を通って次の行に伝播しているかどうかを追跡します。 遷移ループは各セルを行優先の順序で考慮し、垂直セグメントを開始するか継続するかに応じてマスクを更新します。 

スキップ遷移では、現在のマスクが保存され、DP 値が変更されずに引き継がれます。 水平方向の選択は、その列でアクティブな垂直セグメントがない場合にのみ許可されます。これは、無効なコーナー インタラクションに相当するためです。 垂直方向の選択によってビットが設定され、その列内の今後のセルが垂直方向の継続制約を認識するようになります。 

ローリング DP では、各ステップが以前のマスク状態のみに依存するため、完全なグリッド履歴の保存が回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    INF = -10**18
    dp = [INF] * (1 << m)
    dp[0] = 0

    for i in range(n):
        for j in range(m):
            ndp = [INF] * (1 << m)
            w = a[i][j]
            for mask in range(1 << m):
                if dp[mask] == INF:
                    continue
                cur = dp[mask]
                ndp[mask] = max(ndp[mask], cur)
                if not (mask & (1 << j)):
                    ndp[mask] = max(ndp[mask], cur + w)
                ndp[mask | (1 << j)] = max(ndp[mask | (1 << j)], cur + w)
            dp = ndp

    return str(max(dp))

# minimum case
assert run("1 1\n5") == "5"

# small grid
assert run("2 2\n1 2\n3 4") == "10"

# single column
assert run("3 1\n1\n2\n3") == "6"

# all negative
assert run("2 2\n-1 -2\n-3 -4") == "0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1×1グリッド | 5 | 基本ケースの正確性 |
 | 2×2グリッド | 10 | フルカバレッジの蓄積 |
 | 3×1列 | 6 | 垂直伝播 |
 | すべての否定 | 0 | 空の選択の処理 |

 ## 特殊なケース

 正の値を持つ 1×1 グリッドは、DP が正しく初期化され、遷移なしで単一のセルを取得できることを確認します。 状態はマスク 0 から始まり、最適な遷移によってセルの重みが直接追加されます。 

単一列グリッドは垂直方向の伝播を示します。 マスク 0 から開始して、各セルを選択すると垂直ビットが繰り返し設定され、DP はすべての重みを累積します。 水平方向の隣接ノードがないため、この遷移によって水平方向の競合が引き起こされることはありません。 

すべて負の値を持つグリッドは、スキップが許可されているかどうかをテストします。 スキップ遷移はマスクを保持し、負の寄与の追加を回避するため、空の選択が最適な場合、最終的な答えはゼロのままになります。
