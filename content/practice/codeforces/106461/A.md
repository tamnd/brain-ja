 ## 問題の理解

 私たちは、各試行が既知の確率で成功または失敗する一連の独立した試行をモデル化しています。 タスクはプロセスをシミュレートすることではなく、時間の経過に伴う確率を計算することです。具体的には、非常に特定のパターンがその位置で初めて現れる確率です。$X$。 

パターンは位置の周りに固定された剛構造を持っています$X$。 から後ろを振り返ると$X$、正確に のブロックが必要です$K$で終わる連続成功$X$、その直前に位置で障害が発生しました$X-K$、その時点より前に、パターンがシーケンスの前半ですでに発生していてはなりません。 

したがって、入力は、パターンの長さを記述するパラメーターとともに、各試行の成功確率のリストを表します。$K$そして目標位置$X$。 出力は単一の確率値です。つまり、この「失敗して K 回成功」パターンの最初の有効な発生が正確にその位置で終了する確率です。$X$。 

制約は明示的には示されていませんが、累積積を使用する際のヒントは次のとおりです。$O(1)$クエリごとの試行数は、通常は最大$10^5$またはそれ以上。 これにより、すべての部分配列に対する二次推論や、すべての部分配列に対する繰り返しスキャンが即座に排除されます。$X$。 有効なソリューションでは、セグメント確率を一定時間でクエリできるように情報を前処理する必要があります。 

素朴なアプローチが「初めて」という条件を無視した場合、微妙な失敗例が発生します。 たとえば、次のように仮定します。$K = 2$そして、次のような一連の成功が得られます。

 ## アプローチ

 ブルート フォース アプローチでは、シーケンス全体で成功と失敗の考えられるすべての構成を明示的に列挙し、最初の有効な発生が次の時点で終了するかどうかを確認します。$X$。 これは急速に指数関数的に増加します$N$, 各トライアルは 2 つの結果に分岐するためです。 で終わるウィンドウのみをチェックするように制限しようとしても、$X$、同じ構造を満たす以前のウィンドウがないことを確認する必要があり、最悪の場合、各候補エンドポイントの以前の位置をすべてスキャンする必要があります。 それは次のことにつながります$O(N^2)$行動。 

重要な観察は、この条件が 3 つの独立したセグメントのみに依存していることです。$X-K-1$、での単一の失敗$X-K$、およびブロック$K$～からの連続成功$X-K+1$に$X$。 これらはモデルの下では独立しているため、確率は倍増します。 唯一の複雑な点は、パターンが以前に出現しないように強制することですが、この条件は「i までは出現しない」という実行確率を維持することで処理できます。 

この構造がプレフィックス確率と固定長ウィンドウ確率に帰着することを認識すると、成功確率と失敗確率のプレフィックス積を事前計算できます。 その後、各候補エンドポイントを一定時間で評価することができ、特定のインデックスの前にパターンが発生したかどうかを追跡する DP スタイルのプレフィックス配列を構築できます。

 ## アルゴリズムのチュートリアル

 一連の成功確率を仮定します$p[i]$、失敗確率あり$q[i] = 1 - p[i]$。 また、連続するセグメントの確率が必要であると想定しているため、プレフィックス積に依存します。 

1. 高速な範囲乗算を可能にする方法で、成功確率と結合セグメント確率のプレフィックス積を事前計算します。 これにより、どのセグメントでも許可されます$[l, r]$プレフィックス値の比率の積として一定時間で計算される独立した試行の数。 
2. 配列を維持する`pref_ok[i]`で終わる接頭辞のどこにもパターンが発生していない確率を表します。$i$。 イベントが「初めて発生」するため、これが必要になります。 
3. ポジションごとに$i$、それを潜在的なエンドポイントとして扱います$X$。 位置が決まる確率を計算する$i-K+1$に$i$プレフィックス製品構造を使用すると、すべて成功します。 
4. その位置の確率を掛けます。$i-K$失敗です。 
5. 乗算`pref_ok[i-K-1]`これにより、以前の有効なオカレンスが存在しないことが強制されます。 
6. この投稿を回答に追加して更新します`pref_ok[i]`新しい出来事が次の時点で終了する確率を引くことによって$i$、「これまでのところ発生しない」確率が維持されることを保証します。 
7. このプロセスを次の段階まで続けます。$N$、有効なエンドポイントでのみ貢献を蓄積します$i \ge K+1$。 

重要な設計上の選択は、以前の出現を明示的に検索しないことです。 代わりに、その制約をプレフィックス DP 状態に折りたたむため、「最初の出現」条件が段階的に維持されます。 

### なぜ効果があるのか

 各インデックスで$i$、有効な最初の出現を定義するすべてのイベントは、互いに素なセグメント、つまり前の接頭辞のみに依存します。$i-K-1$、での単一の失敗$i-K$、および長さのサフィックスウィンドウ$K$。 これらのセグメントには独立した試験が含まれるため、確率は倍増します。 DP 状態`pref_ok[i]`有効なパターンがその時点またはそれ以前に終了していない確率に等しいという不変式を維持します。$i$。 新しい出現はすべてそのエンドポイントでのみ導入され、将来のプレフィックスから直ちに除外されるため、構成が二重にカウントされることはなく、有効な最初の出現はすべて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, x = map(int, input().split())
    p = list(map(float, input().split()))

    # prefix product of success probabilities
    pref = [1.0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] * p[i - 1]

    def range_prod(l, r):
        if l > r:
            return 1.0
        return pref[r] / pref[l - 1]

    # dp[i]: probability no pattern ends at or before i
    dp = [1.0] * (n + 1)
    ans = 0.0

    for i in range(1, n + 1):
        dp[i] = dp[i - 1]

        if i >= k + 1:
            l = i - k + 1
            r = i

            success_block = range_prod(l, r)
            failure = 1.0 - p[i - k - 1]

            contrib = dp[i - k - 1] * failure * success_block
            ans += contrib

            dp[i] -= contrib

    print(ans)

if __name__ == "__main__":
    solve()
```プレフィックス積配列`pref`連続した成功ブロックを一定時間で計算できます。 ヘルパーさん`range_prod`空または無効な範囲をきれいに処理します。これは次の場合に不可欠です。$k = 0$または、インデックスが配列の先頭近くで整列している場合。 

配列`dp`これは、状態を越える古典的な DP 遷移ではなく、以前のパターン完了によってどれだけの確率質量が既に「消費」されたかを追跡する実行確率質量です。 引き算`contrib`設定がその位置で終了するとカウントされることを保証します`i`、「最初の出現」制約を維持し、後の位置に寄与することはできません。 

インデックス作成には細心の注意が必要です。失敗の位置は次のとおりです。`i - k - 1`の場合にのみ有効になります。`i >= k + 1`。 この境界は、オフバイワンの間違いの最も一般的な原因です。 

## 実用的な例

 次の小さなケースを考えてみましょう$n = 4$、$k = 1$、および確率:```
p = [0.5, 0.5, 0.5, 0.5]
```各エンドポイントの寄与度を計算します。 

| 私 | 障害インデックス (i-k) | 成功ブロック | dp[i-k-1] | 貢献 |
 | --- | --- | --- | --- | --- |
 | 2 | 1 | p[2] | dp[0]=1 | 0.5 * 0.5 * 1 = 0.25 |
 | 3 | 2 | p[3] | dp[1] | 0.5 * 0.5 * dp[1] |

 この表は、各エンドポイントが以前のプレフィックス状態にどのように依存するかを示しています。 の`dp`期間は、以前の発生が蓄積するにつれて寄与を減らし、「初回」制約を強制します。 

このトレースは、アルゴリズムが過去のセグメントを決して再計算せず、蓄積されたプレフィックス確率のみを使用することを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、故障位置インデックスがゼロまたは負になる場合です。 仮定する$k = 2$そして$i = 2$。 それから$i-k-1 = -1$、これは無効です。 アルゴリズムは、次の場合にのみコントリビューションを開始することで、これを明示的に回避します。$i \ge k+1$、参照されるすべてのプレフィックス状態が存在することを確認します。 このような入力では、計算は実行されず、答えは 0 のままになります。これは正しいことです。先行する障害がなければ有効なパターンは存在できないからです。 

すべての確率が 1 の場合、別のエッジ ケースが発生します。そのシナリオでは、障害状態の確率はどこでもゼロになるため、有効なパターンは形成できません。 アルゴリズムは正しく乗算します。`(1 - p[i-k-1])`、ゼロになり、すべての寄与が排除されます。 

3 番目のケースは次の場合です。$k = 0$、「成功ブロック」は空です。 範囲積関数は空の間隔に対して 1 を返すため、イベントは「以前に発生したことのない位置 i-1 での失敗」に帰着しますが、これは変更せずにプレフィックス DP 構造によって正しく処理されます。
