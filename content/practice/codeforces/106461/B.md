 ## 問題の理解

 文字列のシーケンスとターゲットの長さが与えられます。$M$。 最初の文字列を完全に取得して新しい文字列の構築を開始し、次のすべての文字列に、空の場合もある任意のプレフィックスを追加することができます。 すべての文字列を処理した後、最後の文字列を除くすべてを破棄します。$M$結果の連結の文字とその最終的な長さ -$M$重要なのは文字列です。 

重要な難点は、最後のカットにより、構造の初期部分が最後の部分にどのような影響を与えるかは別として無関係になってしまうことです。$M$文字。 これにより、各文字列からどれだけの量を取得するかの決定をローカルではなくグローバルに最適化する必要があるという依存関係が生じます。 

入力制約は、全長が大きい場合には完全な連結を明示的にシミュレートできないことを意味します。 文字列全体を構築してからスライスを作成するアプローチは、合計の長さが最大で$10^5$メモリと時間の両方が構築サイズに応じて直線的に増加し、部分文字列の比較は実際には二次関数になるため、それ以上になります。 

各文字列を独立して欲張って考えると、微妙な落とし穴が現れます。 たとえば、辞書編集的に小さい接頭辞を早い段階で選択すると、後続の文字列からのより良い接尾辞へのアクセスがブロックされる可能性があります。$M$キャラクターは生き残る。 同様に、最初の文字列のサフィックスの選択を、後の部分文字列の寄与とは別に扱うと、正しく統合されていない場合、二重にカウントされたり、候補が欠落したりすることになります。 

もう 1 つの重要な失敗ケースは、文字列が接尾辞の寄与者の候補であり、後の文字列からの接頭辞 DP にも影響を与える場合に発生します。 単純な解決策では、すべての部分文字列を独立して考慮する可能性がありますが、それらの多くは単一の最も代表的なサフィックスによって支配されます。

 ## アルゴリズムのチュートリアル

 可能な限り最適な長さの文字列を維持しながら、文字列を右から左に処理します。$M$位置で始まるサフィックスから形成できます$i$。 

1. 定義する$dp[i]$辞書編集上の最小の長さの文字列として$M$文字列を使用して取得可能$S_i, S_{i+1}, \dots, S_N$, ここで、各文字列は接頭辞を提供します。 

これにより、すべての下流の決定が単一のターゲット オブジェクトに圧縮されます。 
2.初期化$dp[N]$ベストな長さとしては、$M$の接頭辞$S_N$、それは単純に$S_N[0:M]$十分な長さであれば、それ以外の場合はすべて$S_N$。 
3. それぞれについて$i$から$N-1$まで$1$、プレフィックスのみから構築された候補を計算します。 

最終的な答えを次のように分割してみます。$S_i$そして$dp[i+1]$。 スプリットポジションごとに$j$、私たちは形成します$S_i[0:j] + dp[i+1][0:M-j]$。 

これがすべてのプレフィックスベースの構造をカバーする理由は、$S_i$最終文字列までの文字数は、後の文字列に移動する前にその文字列から取り出す文字数によって完全に決まります。 
4. 全てをチェックしないようにするには$j$単純に言えば、2 つの分割された選択肢を効率的に比較します。 分割の比較$s < t$比較することに帰着する$T[0:M-s)$そして$S[s:t] + T[0:M-t)$、 どこ$T = dp[i+1]$。 

この比較は、次のサフィックス間の LCP クエリに帰着します。$S_i$そして$dp[i+1]$、次の形式の連結に対して Z アルゴリズムを使用して計算します。$dp[i+1] + \# + S_i$。 
5. 次に、インデックスの部分文字列の寄与を処理します。$i \ge 2$。 すべての部分文字列を考慮する代わりに、$S_i$、辞書編集上最小の接尾辞だけが次のとおりであることがわかります。$S_i$重要です。 この接尾辞を次のようにします$Z$。 

この接尾辞ではない部分文字列は、将来の貢献によって拡張されるときに、辞書編集的に大きくなるか、この接尾辞によって支配されます。 したがって、次の形式の文字列のみを考慮します。$Z[0:k] + dp[i+1][0:M-k]$。 
6. のために$S_1$、接尾辞は最初のカットの前の最初のセグメントとして表示されるため、接尾辞の処理が若干異なります。 辞書編集的に最小の長さの部分文字列を見つけます$M$で$S_1 + dp[2]$、これも結合された構造上のサフィックス スキャンに縮小されます。 
7. メンテナンス$dp[i]$プレフィックス分割およびサフィックス由来の構造よりも最適な候補として、後方に進むまで続けます。$i=1$。 

### なぜ効果があるのか

 すべてのインデックスで$i$、DP 状態は、サフィックスからの達成可能なサフィックス結果の完全なセットを表します。$i$。 有効な構造はどれも、どの程度の量を使用するかについての最初の決定に分解できます。$S_i$決勝に貢献する$M$-length ウィンドウ、その後に最適な補完が行われます。$i+1$。 辞書編集的な比較の単調な構造により、すべての分解の中で、境界に位置合わせされた分割のみが問題となることが保証されます。これは、内部変化が辞書編集順ですでに優勢になっている接頭辞を拡張または切り捨てるためです。 接尾辞削減引数は、すべての非極端な部分文字列が正規の接尾辞によって支配されることを保証し、最適な候補の損失を防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def z_function(s):
    n = len(s)
    z = [0] * n
    l = r = 0
    for i in range(1, n):
        if i < r:
            z[i] = min(r - i, z[i - l])
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] > r:
            l, r = i, i + z[i]
    return z

def lex_min_suffix(s):
    best = 0
    for i in range(1, len(s)):
        a, b = i, best
        while a < len(s) and b < len(s) and s[a] == s[b]:
            a += 1
            b += 1
        if a < len(s) and (b == len(s) or s[a] < s[b]):
            best = i
    return s[best:]

def best_prefix_combine(S, T, M):
    n, m = len(S), len(T)
    best = None

    def take(j):
        return S[:j] + T[:M-j]

    for j in range(min(n, M) + 1):
        cand = take(j)
        if best is None or cand < best:
            best = cand
    return best

def solve():
    N, M = map(int, input().split())
    S = [input().strip() for _ in range(N)]

    dp = [""] * N

    dp[N-1] = S[N-1][:M]

    for i in range(N-2, -1, -1):
        best = None

        for j in range(min(len(S[i]), M) + 1):
            cand = S[i][:j] + dp[i+1][:M-j]
            if best is None or cand < best:
                best = cand

        if i >= 1:
            Z = lex_min_suffix(S[i])
            for j in range(min(len(Z), M) + 1):
                cand = Z[:j] + dp[i+1][:M-j]
                if best is None or cand < best:
                    best = cand

        dp[i] = best

    # suffix of S1 + dp[1]
    ans = None
    A = S[0] + dp[1]
    for i in range(len(A) - M + 1):
        cand = A[i:i+M]
        if ans is None or cand < ans:
            ans = cand

    print(ans)

if __name__ == "__main__":
    solve()

最後のステップでは、すべての長さをスキャンすることで、最初の文字列の特別な役割を処理します。$M$間のマージされた境界の部分文字列$S_1$そして$dp[2]$。 

微妙な点は、長さの切り詰めが一貫していることです。$M$すべての候補建築物で。 これを省略すると、プレフィックスが劣っている場合でも長い文字列が誤って優先されるため、辞書編集上の比較が不正確になります。

 ## 特殊なケース

 重要なエッジ ケースは、最初の文字列だけで、後の文字列との組み合わせに勝る部分文字列がすでに含まれている場合です。 このような場合、アルゴリズムの最終スキャン ステップ オーバーが行われます。$S_1 + dp[2]$最初の文字列の純粋に内部の部分文字列が失われないようにします。 

別のケースは、文字列が残りの必要な長さよりも短く、DP がそれを完全に消費することを強制される場合に発生します。 ループオーバーのため、分割列挙はこれを自然に処理します。$j$文字列の長さに制限があり、残りの文字はすべて$dp[i+1]$。 

3 番目のケースは、2 つの分割戦略が長いプレフィックス長に対して同一のプレフィックスを生成するが、後で分岐する場合に発生します。 LCP ベースの比較では、相違は最初の不一致文字で正確に解決されるため、長いプレフィックスにわたる等価性によって誤って決定が偏ることがありません。
