 ## 問題の理解

 大文字で構成される文字列が与えられており、「U の後に P が続き、その後に C が続く」という形式の重み付けされた構造を抽出することに興味があり、追加の C がさらに後に現れます。 4 つのインデックスを選択するたびに、$i < j < k < l$有効な構成を形成すると、それらの位置の積に等しい値が得られます。$i \cdot j \cdot k \cdot l$。 各インデックスは、選択したすべてのクアドルプルにわたって最大 1 回使用できます。 

タスクは、順序付け制約を尊重するすべての可能な素の 4 倍数にわたってこれらの積の合計を最大化することです。 

制約が十分に大きいため、すべてのクアドルプルのチェックやすべてのサブシーケンスに対する動的計画法を含むアプローチは直ちに実行不可能になります。 A naive enumeration of all$O(n^4)$枝刈りを行ったとしても、4 倍は可能性をはるかに超えています。$n$次のような典型的な Codeforce 制限に達する$10^5$。 平$O(n^2)$各要素は複数の潜在的なペアに関与しているため、注意深く構造化せずに実装すると相互作用が遅くなりすぎます。 

欲張りな推論による微妙な失敗例は、文字を左から右の順序で一致させようとしたときに発生します。 たとえば、可能な限り早い U と可能な限り早い P を貪欲にペアリングすると、インデックスが大きくなり、より大きな積が生成される後の構成がブロックされる可能性があります。 次のような文字列を考えてみましょう

 アップカップピーシーシー

 単純な前方マッチングでは、小さなインデックスが早期にペアになり、大きなインデックスが次善の方法で未使用のままになる可能性があります。 主な問題点は、値がポジションに乗算的に依存するため、後のインデックスの価値が不釣り合いに高くなるということです。 

## アプローチ

 ブルート フォース ビューでは、互いに素な 4 倍体を選択するすべての方法を考慮します。$(i, j, k, l)$そのような$S_i = U$、$S_j = P$、$S_k = C$、$S_l = C$インデックスが増加します。 有効な選択ごとに積を計算し、合計します。 複数の素な増加チェーンを選択しているため、これはすぐに指数関数的、または少なくとも組み合わせ爆発につながります。 

ブルート フォースの失敗点は、選択肢の数だけではなく、選択肢間の依存関係にもあります。 1 つのクアドルプルを選択すると、後でより適切なクアドルプルの一部となっていた可能性のあるインデックスが削除されるため、グローバルな順序付けの原則が必要になります。 

重要な洞察は、値関数が各インデックスで単調で乗算的であるため、再配置引数が可能であるということです。 任意の 2 つの操作を実行し、選択したインデックスを座標順に並べ替えた場合、合計値は減少しません。 これは、最適解には構造があると仮定できることを示す古典的な交換議論です。つまり、選択されたインデックスは単調に配置されており、利用可能な最大の有効なインデックスを最初に取得することを安全に選択できることを意味します。 

これにより、問題はグローバルな組み合わせ論から貪欲な構造に変換されます。 すべての有効な 4 つ組を検索する代わりに、右から左に処理し、常に右端の可能なチェーンを完了しようとします。 文字を見るたびに、部分的に形成されたチェーンを可能な限り拡張しようとし、常に利用可能な最大のインデックスを消費します。

 ## アルゴリズムのチュートリアル

 これまでに「C ← P ← U ← C」の構築が何段階完了したかを表す部分チェーンを維持しながら、文字列を右から左に処理します。 

1. 以下からインデックスをスキャンします。$n$まで$1$、後のポジションはより大きな乗算係数に寄与するため、より価値のあるものとして扱います。 この順序付けは、インデックス内で最適な構造を単調にできるという交換の議論と一致しています。 
2. 部分工事に対応した3つのキューを確保しております。 1 つは利用可能な C ポジションを保存し、もう 1 つは完了した「PC」値を保存し、もう 1 つは完了した「UPC」値を保存します。 各キュー要素は、まだ拡張できる最適な部分チェーンを表します。 
3. C に遭遇した場合、可能であればすぐにフルチェーンを完了しようとします。 完成した UPC チェーンが存在する場合は、最良のものを選択し、現在のインデックスを乗算して、それを答えに追加します。 そうでない場合は、この C を将来の P 一致の潜在的な開始点として保存します。 
4. P に遭遇すると、既存の C を PC チェーンに拡張しようとします。 利用可能な C がある場合は、それを現在のインデックスと組み合わせ、乗算して PC 値を形成し、後の拡張のために保存します。 
5. U に遭遇すると、既存の PC チェーンを UPC チェーンに拡張しようとします。 利用可能な PC がある場合は、それを乗算して UPC として保存します。 

各ステップでは、右から左への処理により最大のインデックスに対応する、最近利用可能なコンポーネントが貪欲に使用されます。 

各操作が局所的に最適である理由は、以前に選択した場合、将来の拡張の乗数効果が減少するだけであるためです。 利用可能な最適な部分チェーンを常に使用することで、より大きな継続が存在する場合に、より小さな継続で大きなインデックスが無駄にならないようにします。 

### なぜ効果があるのか

 交換引数は、すべての最適解の中に、前のステップで使用されるインデックスが同じロールで後のステップで使用されるインデックスより決して小さくならないものが存在することを保証します。 これにより、単調な構造を強制することができます。最適性を失うことなく、すべての部分チェーンが右から左に構築されます。 キューは、現在のインデックスと利用可能な最良の継続を常に組み合わせることにより、この構造をシミュレートし、各段階で可能な最大の寄与を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    c = []
    pc = []
    upc = []

    ans = 0

    for i in range(n, 0, -1):
        ch = s[i - 1]

        if ch == 'C':
            if upc:
                val = upc.pop()
                ans += val * i
            else:
                c.append(i)

        elif ch == 'P':
            if c:
                j = c.pop()
                pc.append(j * i)

        elif ch == 'U':
            if pc:
                val = pc.pop()
                upc.append(val * i)

    print(ans)

if __name__ == "__main__":
    solve()
```実装は右から左へのスイープの直後に続きます。 各リストは厳密なキューではなくスタックとして機能します。処理順序が逆転するため、最後に追加された (最大のインデックス) 要素を常に最初に使用する必要があるため、これで十分です。 重要な点は、部分構造を拡張するときに乗算が即座に行われ、完全なタプルを保存する必要がなく、累積された積が保存されることです。 

よくある間違いは、特定のキャラクターについて考えられるすべての以前の状態を一致させようとすることです。 これは、交換議論によって保証されている単調な構造を壊すため、不必要かつ有害です。 貪欲なスタック動作により、各インデックスが利用可能な最も価値のある拡張機能で常に 1 回だけ使用されることが保証されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての有用な文字が文字列の末尾に集まっている場合です。 たとえば、「UUUPPPCCC」では、アルゴリズムは右から左に処理し、最大のインデックスが常に最初に使用されるようにします。 単純な左から右への貪欲な場合、誤って小さなインデックスを早期に消費して、より高い価値のチェーンの形成を妨げる可能性があります。 

もう 1 つのエッジ ケースは、複数の部分チェーンが同じステージで利用できる場合です。 スタックベースのアプローチでは、最後に形成された部分チェーンを常に拡張することでこの問題を自然に解決します。これは、逆スキャンによる利用可能な最大の寄与に対応します。
