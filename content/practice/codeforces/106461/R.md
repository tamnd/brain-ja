 ## 問題の理解

 簡略化されたじゃんけん設定でプレイする人々のグループに関する集計情報を表す 2 つの整数が与えられます。 個々のやり取りを追跡する代わりに、じゃんけん、紙のそれぞれの手を選択した人の数だけを考慮します。 それらのカウントを次のようにします$R$、$S$、 そして$P$。 プレイヤーの総数を合計する必要があります$N$また、ハサミと紙に関する 2 番目の線形制約も満たさなければなりません。ハサミの数の 2 倍と紙プレーヤーの数の 5 倍が指定された値に等しいということです。$M$。 

タスクは、実際の構成を構築することではなく、非負の整数のトリプルが存在するかどうかを判断することだけです。$(R, S, P)$両方の方程式を満たすものが存在します。 さらに、ゲームに勝者がいる有効な構成が存在するかどうかも判断する必要があります。 このステートメントは、この条件を構造的特性としてエンコードしています。勝者は、3 つのハンド タイプすべてが同時に存在しない場合、つまり、次の 2 つのタイプが同時に存在しない場合に正確に存在します。$R, S, P$ポジティブです。 

問題はゲームの観点から表現されていますが、中心となる構造は、非負の整数変数を使用した線形制約の小さなシステムに対する純粋な算術実行可能性です。 

この制約は、自由度の点で非常に小さな探索空間を意味します。 一度$S$そして$P$選ばれ、$R$が強制されるため、システムは事実上、変数の除去方法に応じて 1 次元または 2 次元の格子上の整数解をチェックすることになります。 これは、両方の変数をブルート フォースで攻撃する可能性があることを強く示唆しています。$N$大規模なものではすでに遅すぎるでしょう$N$、最悪の場合、それは二次関数になるためです。 

主な微妙な点は、実現可能性が実数値の解だけではなく、整数の一貫性に依存することです。 よくある間違いは、線形システムを実数で解き、実現可能性が引き継がれると仮定することですが、割り算の制約によりほとんどの候補が除外される可能性があります。 

エッジ ケースは、ソリューションが 1 つ以上の境界上にある場合に発生します。$R, S, P$ゼロになる。 たとえば、次の場合$P = 0$、方程式は次のようになります。$2S = M$、均等である場合もそうでない場合もあります。 同様に、$S = 0$、私たちは得ます$5P = M$これらの境界ケースは、実現可能性と「勝者が存在する」条件の両方にとって重要です。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアが列挙されます。$(S, P)$そのような$2S + 5P = M$、計算する$R = N - S - P$、すべての変数が非負であるかどうかを確認します。 方程式自体がすでに検索スペースを大幅に制限しています。$P$までの範囲$M/5$、そしてそれぞれの選択肢について計算します$S = (M - 5P)/2$整数の場合。 これはすでに線形です$M$、小さな制約であれば許容できますが、制約が大きい場合には非効率になります。$M$特に複数のテスト ケースが存在する場合は大きくなります。 

重要な観察は、システムが実際には 2 次元ではないということです。 2 番目の方程式は、次の関係を特定します。$S$そして$P$、それで一度$P$選ばれて、$S$有効かどうかは一意に決まります。 それから$R$強制されます。 したがって、問題は非負の整数が存在するかどうかを確認することになります。$P$可分性と範囲制約の両方が満たされるようにします。 

勝者が存在するかどうかに関する 2 番目の部分は、構造的にはより単純です。 勝者は、次の 3 つがすべて揃っていない場合に存在します。$R, S, P$ポジティブです。 したがって、有効な解が見つかったら、変数の少なくとも 1 つがゼロであるかどうかをさらにチェックします。 すべてが正である解が存在する場合、それは完全に混合された状態に相当するため、特定の条件下では勝者は存在しません。 すべての有効な解決策が必然的にゼロ成分を強制する場合、勝者となる可能性があります。 

これにより、問題は狭い範囲のスキャンに軽減されます。$P$、コンピューティング対応$S$、導出$R$、制約を確認します。

 ## アルゴリズムのチュートリアル

 1. 可能なすべての値を反復処理します。$P$0から$\lfloor M/5 \rfloor$。 各論文は 2 番目の方程式に 5 単位を寄与し、これより大きな値はすぐに超過するため、これで十分です。$M$。 
2. それぞれについて$P$、ハサミの残りの寄与を次のように計算します。$M - 5P$。 この量は偶数である必要があります。それ以外の場合は整数ではありません$S$存在します。 
3. 偶数の場合は計算します$S = (M - 5P)/2$。 このステップでは、浮動小数点演算を行わずに 2 番目の方程式が正確に満たされるようにするため、精度の問題が回避されます。 
4. コンピューティング$R = N - S - P$。 これは総人口の制約から直接得られます。 
5. かどうかを確認します。$R, S, P$はすべて非負です。 いずれかが負の場合、カウントの解釈の実現可能性に違反するため、この候補を破棄します。 
6. 有効なトリプルが見つかった場合は、実現可能性を記録します。 さらに、少なくとも 1 つの変数がゼロに等しい有効なトリプルが少なくとも 1 つ存在するかどうかを追跡します。これにより、勝者構成が存在するかどうかが決まります。 

これが機能する理由は、2 番目の方程式が整数点の 1 次元格子を定義しているという事実に基づいています。$(S, P)$飛行機。 すべての有効な解決策はこの格子上に存在する必要があり、すべての候補は選択することによって完全に決定されます。$P$。 最初の方程式は、正しく投影される格子点のみを選択するフィルターとして機能します。$N$。 どちらの制約も線形であり、各ステップで整合性を強制するため、有効な解がスキップされたり、無効な解が受け入れられたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())

    possible = False
    has_winner = False

    for P in range(M // 5 + 1):
        rem = M - 5 * P
        if rem < 0:
            break
        if rem % 2 != 0:
            continue

        S = rem // 2
        R = N - S - P

        if R < 0:
            continue

        possible = True
        if R == 0 or S == 0 or P == 0:
            has_winner = True

    if not possible:
        print("NO")
    else:
        print("YES" if has_winner else "NO")

if __name__ == "__main__":
    solve()
```コードは列挙の直後に続きます。$P$。 パリティ チェックにより、次のことが保証されます。$S$は整数のままであり、無効な半値を回避します。 一度$S$導出され、$R$は最初の方程式によって強制されます。 

微妙な実装の詳細は、次の場合に早期に中断されることです。$M - 5P < 0$これは技術的には不要ですが、病理学的入力での余分な反復を防ぎます。 もう 1 つの重要な詳細は、計算後の非負性のチェックです。$R$なぜなら、たとえ 2 番目の式が満たされたとしても、最初の制約によって候補が無効になる可能性があるからです。 

勝者の条件は列挙中に追跡されます。これは、有効な解が少なくとも 1 つの変数をゼロに置くかどうかのみに依存するためです。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$M$奇数です。 この場合、どの候補者も$P$奇数の剰余を生成します$M - 5P$いつでも$5P$偶数か奇数かは一貫性がありませんが、実際にはパリティは次の場合にすべての候補を即座に除外します。$S$整数にはなりません。 例えば、$N = 10, M = 3$有効な解決策は得られません。$2S = 3 - 5P$整数であっても指定できません$P$。 

もう 1 つのエッジケースは次のような場合です$P = 0$、これによりシステムは次のように縮小されます。$2S = M$そして$R = N - S$。 例えば、$N = 7, M = 4$与える$S = 2, R = 5$、1 つの変数がゼロである有効なソリューションであり、勝者の構成が保証されます。 

3 番目のエッジ ケースは、すべての変数が厳密に正になるが、依然として両方の方程式を満たす場合です。 例えば、$N = 8, M = 13$生成する$(R, S, P) = (3, 4, 1)$。 このアルゴリズムは実現可能性を正確にマークしますが、唯一の有効な解空間ではゼロになる変数がないため、勝者をマークしません。
