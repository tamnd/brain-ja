 ## 解決策
 ## 問題の理解

 私たちは、各オブジェクトが同時に有向接続のソースとターゲットのように機能するシステムに注目しています。 具体的には、すべてのボールは、現在位置しているボックスからボール自身のインデックスまでの有向エッジを誘発します。 複数のボールで平行なエッジを作成でき、ボールが同じインデックスのボックス内にすでに存在する場合、自己ループが許可されます。 

操作は、指示されたトレイルを横断し、途中でエッジを消費することに対応します。 私たちが求めるコストは、すべてのエッジを 1 回正確にカバーするために必要なそのようなトレイルの最小数です。 グラフの用語では、これは古典的な分解の問題になります。有向マルチグラフのすべてのエッジをカバーするには、いくつの有向トレイルが必要かということです。 

重要な構造上の観察は、すべての頂点の入次数と出次数が等しく、どちらも固定パラメータ M に等しいということです。これにより、各連結成分が (無向の意味で) オイラー型になることが即座に強制されます。 単一の接続コンポーネント内では、すべてのエッジを 1 つのオイラー ツアーでカバーできます。 ただし、接続されたさまざまなコンポーネント間にパスがないため、これらのコンポーネントを 1 つのトレイルに結合することはできません。 これにより、答えは純粋な組み合わせ量、つまり基礎となる無向グラフの連結成分の数に変わります。 

したがって、タスクは、非常に特定の次数制約の下でランダムな有向マルチグラフを生成し、予想される接続成分の数を計算することに帰着します。 

制約は組み合わせ定式化の中に隠されています。 頂点の数 N と次数 M は、グラフの列挙やエッジの反復さえも不可能になるほど大きくなる可能性があります。 すべてのグラフを明示的に構築または走査しようとしたり、構成ごとに O(N^2) 接続推論を使用したりするソリューションは、直ちに実行不可能になります。 唯一の実行可能な方法は、指数母関数または同等の組み合わせ分解を使用して構造をカウントすることです。 

M が小さいが N が大きい場合、微妙なエッジ ケースが発生します。 各頂点には入射エッジがほとんどありませんが、ラベル付き構成の数は階乗的に増加します。 たとえば、N = 2 および M = 1 の場合、考えられる有向エッジは合計で 2 つだけですが、ボールのラベル付けにより複数の構成が依然として存在します。 ラベル付けを考慮せずに接続性が程度のみに依存するという単純な仮定は、不正確なカウントにつながります。 

別の失敗例は、基礎となる無向構造ではなく有向レベルで接続を解釈するときに発生します。 たとえば、エッジが 1→2 および 2→1 であるグラフは接続されていますが、単純な有向のみのビューではグラフが誤って分割される可能性があります。 

## アプローチ

 直接的なアプローチでは、頂点ごとに M 個の外向きエッジの割り当てをすべて列挙します。 各構成は有向マルチグラフを定義し、基礎となる無向グラフ上で DFS または DSU を使用して連結成分を計算できます。 これは概念的には簡単ですが、完全に実行不可能です。 グラフの数は、各頂点からの M 個のラベル付きボールを N 個のターゲットに分配することによって与えられます。これは、次のとおりです。$(N^2)^{NM}$規模的には。 たとえ小さなパラメータであっても、これはすぐに爆発します。 

重要な洞察は、構造をラベル付きの組み合わせクラスとして再解釈することです。 各頂点は M 個の区別できない発信スタブを提供し、各スタブはターゲット頂点と照合されます。 これは配布に相当します$iM$ラベル付きオブジェクトを、等しい多重度制約を持つ i 個のラベル付きビンに配置します。 i 頂点上のこのような有向マルチグラフの総数は次のようになります。$$a_i = \frac{(iM)!}{(M!)^i}.$$ここで、接続によってこのカウントを調整したいと思います。 させて$b_i$サイズ i の接続された構造の数になります。 そうすれば、どんなグラフも一連の連結成分として見ることができ、標準的な指数公式の関係がすぐに得られます。$$A(x) = \exp(B(x)).$$これは、指数母関数における古典的な集合の構築です。一般的な構造は連結成分の集合であり、指数母関数は集合を指数関数に変換します。 

接続がエンコードされると、$B(x)$、接続コンポーネントの予想数は、各構造をコンポーネントの数で重み付けすることによって取得されます。 シンボリック組み合わせ論では、これは 1 つのコンポーネントをあらゆる方法でマークすることに相当し、次の結果が得られます。$$C(x) = B(x) \cdot \exp(B(x)).$$以来$\exp(B(x)) = A(x)$、これを直接単純化して次のようにすることができます。$$C(x) = A(x)\log A(x).$$したがって、問題全体は、既知の EGF とその対数の積の係数を計算することに帰着します。 

残りのタスクは純粋に代数的なものです: 計算$A(x)$、形式的なべき級数を介して対数を取得し、逆乗し、畳み込みを使用して係数を効率的に抽出します。$O(N \log N)$。

 ## アルゴリズムのチュートリアル

 1. 塩基配列を計算する$a_i = \frac{(iM)!}{(M!)^i}$私はNまでです。 

これは、必要な次数制約を持つすべての可能な有向マルチグラフをカウントします。 階乗構造は、出力エッジのエンドポイントを並べ替えることから直接得られます。 
2. 指数母関数を構築する$A(x)$係数を使用する$a_i / i!$。 

組み合わせセットの構築は EGF で自然に表現されるため、この正規化が必要です。 
3. 形式対数を計算する$B(x) = \log A(x)$べき級数演算を使用します。 

このステップでは、接続されたコンポーネントが基本的な組み合わせの構成要素に対応するため、接続された構造を分離します。 
4. コンピューティング$C(x) = A(x)\log A(x)$。 

これは、コンポーネントのセット内のコンポーネントをマークすることで発生し、コンポーネントの数によって各構造に重みを付けます。 
5. 係数を抽出する$[x^N] C(x) / [x^N] A(x)$。 

この比率は、総コンポーネント数をすべての構造の期待値に変換します。 

機能する理由: すべての有効なグラフは、接続されたコンポーネントのセットに一意に分解できます。 セットの指数母関数は、コンポーネント クラスの指数です。 対数を取るとこの分解が逆になり、接続された構成要素が回復されます。 生成されるマーキング引数$C(x)$各連結成分が出現ごとに正確に 1 単位に寄与することを保証するため、係数抽出はすべてのグラフの成分数の合計に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def ntt(a, invert=False):
    n = len(a)
    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            a[i], a[j] = a[j], a[i]

    length = 2
    while length <= n:
        wlen = pow(3, (MOD - 1) // length, MOD)
        if invert:
            wlen = modinv(wlen)
        for i in range(0, n, length):
            w = 1
            half = length >> 1
            for j in range(i, i + half):
                u = a[j]
                v = a[j + half] * w % MOD
                a[j] = (u + v) % MOD
                a[j + half] = (u - v + MOD) % MOD
                w = w * wlen % MOD
        length <<= 1

    if invert:
        inv_n = modinv(n)
        for i in range(n):
            a[i] = a[i] * inv_n % MOD

def convolution(a, b):
    n = 1
    while n < len(a) + len(b):
        n <<= 1
    fa = a[:] + [0] * (n - len(a))
    fb = b[:] + [0] * (n - len(b))
    ntt(fa)
    ntt(fb)
    for i in range(n):
        fa[i] = fa[i] * fb[i] % MOD
    ntt(fa, True)
    return fa

def poly_inv(f, n):
    g = [modinv(f[0])]
    while len(g) < n:
        m = len(g) * 2
        f_cut = f[:m]
        while len(f_cut) < m:
            f_cut.append(0)
        g_pad = g + [0] * (m - len(g))
        fg = convolution(f_cut, g_pad)
        for i in range(m):
            fg[i] = (2 * g_pad[i] - fg[i]) % MOD
        g = fg[:m]
    return g[:n]

def poly_log(f, n):
    df = [(i * f[i]) % MOD for i in range(1, len(f))] + [0]
    inv_f = poly_inv(f, n)
    prod = convolution(df, inv_f)
    res = [0] * n
    for i in range(1, n):
        res[i] = prod[i - 1] * modinv(i) % MOD
    return res

def solve():
    M = int(input())
    N = int(input())

    fact = [1] * (N * M + 1)
    for i in range(1, N * M + 1):
        fact[i] = fact[i - 1] * i % MOD

    inv_fact_m = modinv(fact[M])
    a = [1] * (N + 1)

    for i in range(1, N + 1):
        a[i] = fact[i * M]
        for j in range(i):
            a[i] = a[i] * inv_fact_m % MOD

    inv = [1] * (N + 1)
    for i in range(2, N + 1):
        inv[i] = MOD - MOD // i * inv[MOD % i] % MOD

    A = [0] * (N + 1)
    for i in range(N + 1):
        A[i] = a[i] * inv[i] % MOD

    B = poly_log(A, N + 1)

    C = convolution(A, B)[:N + 1]

    ans = C[N] * modinv(A[N]) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```コードは最初に階乗値を構築して閉じた形式を計算します。$a_i = (iM)! / (M!)^i$。 次に、これらを i 階乗で除算して指数母関数係数に変換します。 

対数は、標準のニュートンベースの級数反転および畳み込みパイプラインを使用して計算されます。直接級数展開は係数ごとに 2 次となるため、これが必要になります。 

最後に、次の間の畳み込み$A$そして$\log A$重み付き構造カウント関数を生成し、次で割ります。$A[N]$期待に正規化されます。 

よくある落とし穴は、対数と指数が通常の母関数ではなく指数母関数で定義されていることを忘れていることです。 もう 1 つは、階乗正規化の誤った処理です。これは、たとえ中間値が妥当であるように見えても、正確性を静かに破ってしまいます。 

## 実用的な例

 最小限のケースを考えてみましょう。$N = 2$、$M = 1$。 頂点が 2 つあり、それぞれに 1 つの外向きエッジがあります。 考えられるすべてのグラフは、2 つの有向エッジの順列です。 

| ステップ | A[i] (EGF 係数) | B[i] = ログ A | C[i] = A・B |
 | --- | --- | --- | --- |
 | 0 | 1 | 0 | 0 |
 | 1 | 1 | 0 | 0 |
 | 2 | 2 | 1 | 2 |

 これは、サイズ 2 での接続コンポーネントの合計の寄与が 2 であるのに対し、合計の構造は 2 であり、期待値は 1 であることを示しています。 

ここで考えてみましょう$N = 3$、$M = 1$。 各頂点には出力エッジが 1 つだけあるため、構造は関数グラフになります。 

| ステップ | A[i] | B[i] | C[i] |
 | --- | --- | --- | --- |
 | 0 | 1 | 0 | 0 |
 | 1 | 1 | 0 | 0 |
 | 2 | 2 | 1 | 2 |
 | 3 | 6 | 2 | 12 |

 比率$C[3]/A[3] = 12/6 = 2$、この構造の下でサイズ 3 のランダム関数グラフ内のコンポーネントの予想数と一致します。 

これらのトレースは、対数分解によって接続された構造が正しく分離され、最終的な正規化によって意味のある期待値が得られることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(NM + N \log N)$| 階乗前処理が支配的$NM$、畳み込み、級数演算が寄与します$N \log N$|
 | スペース |$O(N)$| 多項式係数と階乗テーブルを保存する |

 この複雑さは、畳み込みが対数的にのみ支配的であり、すべての重い組み合わせが線形前処理に削減されるため、N が約 2e5 までの一般的な制約に快適に適合します。

 ## 特殊なケース

 いつ$N = 1$、グラフには頂点が 1 つだけあり、M 個のエッジはすべて自己ループです。 構造は常に接続されているため、コンポーネントの予想数は 1 です。アルゴリズム セット$A(1)$そして$B(1)$一貫して、畳み込みは高次構造の寄与をゼロにし、比率は 1 のままになります。 

いつ$M = 1$、各頂点には出力エッジが 1 つだけあるため、システムは関数グラフに縮小されます。 対数ステップでは、サイクルが連結成分として正しく識別され、最終的な正規化では、予想されるサイクル数とそれに接続されたツリーが生成され、既知の組み合わせ構造と一致します。 

いつ$N$が大きく、M が小さい場合、階乗比が支配的になります。 前処理によりモジュロ演算下での数値安定性が確保され、すべての増加はモジュラー逆関数を通じて処理され、オーバーフローや精度のドリフトを防ぎます。
