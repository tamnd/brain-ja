 ## 解決策
 ## 問題の理解

 このタスクは、階乗の 2 進表現の末尾にあるゼロ ビットの数を要求します。 入力は単一の整数です`n`、出力は のバイナリ値の何倍かになります。`n!`奇数になる前に 2 で割ることができます。 の値`n!`それ自体は、許容される最大入力に対してさえ、直接構築するには大きすぎます。 

重要な変化は、階乗の桁について考えるのをやめ、代わりに因数について考えることです。 2 進数の末尾のゼロは、その数値に次の因数があることを意味します。`2`。 数値が次の数で割り切れる場合`2^k`しかし、それによってではありません`2^(k+1)`、そのバイナリ表現は正確に終わります`k`ゼロ。 問題は次の指数を求めることです`2`内部`n!`。 

入力制限に達しました`10^6`。 までのすべての数値のループ`n`は完全に合理的ですが、階乗を構築することは不可能です。`n!`入力サイズよりもはるかに速く増加します。 階乗自体を保存したり繰り返し操作したりするアプローチでは、時間またはメモリが不足します。 

難しいケースのほとんどは、因数を正しく数えることに関するものです。 のために`n = 1`、階乗は`1`、そのバイナリ表現は次のとおりです。`1`, したがって、答えはゼロです。 間違った点からカウントを開始するソリューションでは、係数 2 が誤って追加される可能性があります。 

例えば：```
Input:
1

Output:
0
```偶数はありません`1!`, したがって、末尾のゼロビットはありません。 

もう 1 つのよくある間違いは、2 の倍数だけを数えて、より高い累乗を無視することです。 例えば：```
Input:
8

Output:
7
```偶数は次のように 2 の因数に寄与します。`2`1つを貢献し、`4`2つ貢献します、`6`1 つを貢献し、`8`3つ貢献します。 合計は`1 + 2 + 1 + 3 = 7`。 偶数のみをカウントする不注意な実装は、`4`その代わり。 

## アプローチ

 直接的なアプローチは、階乗を計算し、それが均等なままになるまで繰り返し 2 で割ることです。 除算ごとにバイナリ表現から末尾の 0 が 1 つ削除されるため、これは数学的に正しいです。 問題は階乗の大きさです。 のために`n = 10^6`、階乗には何百万もの桁があるため、階乗を構築して除算するには、膨大な整数を操作する必要があります。 

より良い方法は、乗算で 2 の因数が何個出現するかを数えることです。`1 * 2 * 3 * ... * n`。 すべての偶数は 2 の少なくとも 1 つの因数に寄与します。 4 で割り切れる数値は追加の係数に寄与し、8 で割り切れる数値は別の係数に寄与し、このパターンは続きます。 

の倍数`2`最初のうちに`n`整数は`floor(n / 2)`。 の倍数から得られる追加因子の数`4`は`floor(n / 4)`。 の倍数からの追加因子の数`8`は`floor(n / 8)`。 2 のべき乗が より大きくなるまでこれらの値を加算します。`n`末尾の 2 進ゼロの正確な数を示します。 

ブルートフォースのアイデアは、乗算の結果を表現しようとするため失敗します。 最適化されたアイデアでは、重要な素因数だけをカウントするため、膨大な数を操作することから、少数の対数除算を実行することに問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nのサイズ! × 分割数) | O(n のサイズ!) | 遅すぎる |
 | 最適 | O(log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして答えをゼロに初期化します。 答えには、次の式に含まれる 2 つの因数の合計数が格納されます。`n!`。 
2. 値から始めます`2`そしてそれを繰り返し乗算します`2`。 2 の累乗ごとに`p`、 追加`n // p`答えに。 
3. 現在の 2 の累乗が 2 より大きくなった時点で停止します。`n`。 からの番号はありません`1`に`n`2 の因数をそれだけ多く含むことができるため、より大きな累乗は何も寄与しません。 
4. 蓄積された回答を印刷します。 

これが機能する理由は、次の数値に 2 の因数が出現するたびに、`1`に`n`バイナリで末尾のゼロを 1 つ作成します。 ～の倍数を数える`2`の倍数を数えて最初の因数を見つけます。`4`それらの数値に含まれる追加の因子を見つけ、さらに高い累乗を続けると、考えられるすべての寄与が捕捉されます。 

なぜ効果があるのか:

 素数の指数`p`階乗の は、次の倍数を加算することによって与えられます。`p`、次に、の倍数`p²`、次に、の倍数`p³`、 等々。 ここでプライムは`2`したがって、合計は正確に次のようになります。`floor(n/2) + floor(n/4) + floor(n/8) + ...`この値が最大です`k`そのような`2^k`分割する`n!`。 2 進数の末尾のゼロは 2 の 1 つの因数に正確に対応するため、この値が必須の答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    ans = 0
    power = 2

    while power <= n:
        ans += n // power
        power *= 2

    print(ans)

if __name__ == "__main__":
    solve()
```変数`ans`これまでに見つかった 2 の因数の合計数を格納します。 ループは次から始まります`2`なぜなら、カウントされるすべての要素は 2 の倍数でなければならないからです。 

掛け算`power *= 2`シーケンスを移動します`2, 4, 8, 16, ...`。 各反復では、この 2 の累乗を約数として含む数値がいくつあるかを数えます。 整数の除算では、正確な倍数が得られます。 

Python の整数はオーバーフローしないため、答えを得るために特別な処理は必要ありません。 可能な最大の答えは階乗自体よりもはるかに小さく、ループは約 20 回しか実行されません。`n = 10^6`。

## テストケース```python
import sys
import io

def solve_data(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n = int(sys.stdin.readline())
    ans = 0
    power = 2
    while power <= n:
        ans += n // power
        power *= 2

    sys.stdin = old_stdin
    return str(ans) + "\n"

# provided samples

assert solve_data("8\n") == "7\n", "sample 2"
assert solve_data("1000000\n") == "999993\n", "sample 3"

# custom cases
assert solve_data("2\n") == "1\n", "smallest even factorial"
assert solve_data("3\n") == "1\n", "boundary before power of two"
assert solve_data("16\n") == "15\n", "power of two boundary"
assert solve_data("32\n") == "31\n", "larger power of two boundary"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 入力の場合:```
1
```ループは決して実行されないため、`2 > 1`。 答えはゼロのままで、これは次の事実と一致します。`1! = 1`末尾のゼロビットはありません。 

入力の場合:```
8
```アルゴリズムは権力を訪問します`2`、`4`、 そして`8`。 追加します`8 // 2 = 4`、`8 // 4 = 2`、 そして`8 // 8 = 1`、生産`7`。 これは、次のような数値の場合を処理します。`8`2 の複数の因数に寄与し、偶数だけを数えるというよくある間違いを防ぎます。 

入力の場合:```
1000000
```アルゴリズムは決して構築しようとしません`1000000!`。 までの 2 のべき乗のみをチェックします`524288`、各貢献を追加します。 最終的な答えは、`999993`、これは完全に階乗構築ではなく因数カウントから来ています。
