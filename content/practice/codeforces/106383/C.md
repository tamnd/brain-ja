 ## 解決策
 ## 問題の理解

 私たちには一連の映画と人々のグループが与えられ、各人が映画について 2 つの発言をします。 各ステートメントは、特定の映画を視聴リストに含めるべきであるか、特定の映画を除外すべきであるかのどちらかです。 

課題は、すべての映画について、その映画を観るかどうかを決定し、すべての人にとって 2 つの発言のうち少なくとも 1 つが真実になるようにすることです。 必須の映画が含まれているか、禁止されている映画が除外されている場合、ステートメントは true になります。 

出力について考えるのに役立つ方法は、映画ごとに、映画を含めるかどうかの二者決定を構築しているということです。 各人は、これらの決定に対して 2 つの単純な条件の論理和である制約を課します。 

入力サイズは最大 100,000 人の人物と 100,000 本の映画に達します。これにより、映画の選択のすべての組み合わせを試行するアプローチは除外されます。 サブセットを完全に列挙すると映画の数は指数関数的に増加し、サブセットごとに推論するだけでも実現可能な限界をはるかに超えます。 映画や人物についての二次推論ですら遅すぎます。 

これは、構造が 2 つの条件にそれぞれ依存する句を持つブール変数に対する制約を満たすことを直ちに示唆しています。 この構造は 2-SAT の古典的な信号です。 

エッジ ケースは、制約がサイクル内で互いに矛盾する場合に発生します。 たとえば、ある人が映画 2 を除外しない限り映画 1 を含めるよう強制し、別の人がその逆の関係を強制した場合、両方を満たす割り当てが存在しない可能性があります。 もう 1 つの微妙なケースは、ある人の発言の両方が同じ映画について言及している場合です。 たとえば、「ムービー 1 を含めるか、ムービー 1 を含める」は無害ですが、「ムービー 1 を除外する、またはムービー 1 を除外する」と指定すると、他のすべてに関係なく、そのムービーが強制的に除外されます。 制約が複数の人々にまたがって相互作用するため、映画ごとに単純に貪欲に選択すると、このような世界的な矛盾を見逃してしまいます。 

## アプローチ

 強引なアイデアは、各ムービーをバイナリ変数として扱い、考えられるすべての包含パターンを試すことです。 M 映画の場合、これは意味します$2^M$非常に小さな M であっても直ちに実行不可能な構成です。 

もう少し構造化されたブルートフォースは、これまでの制約が満たされているかどうかを維持しながら、映画ごとに決定を試みます。 ただし、問題は、それぞれの決定が以前の満足感を遡って壊す可能性があり、それを修復するには多くの選択を遡る必要があることです。 最悪の場合、各割り当ては 2 つの可能性に分岐し、各分岐は多くの制約に影響を及ぼし、再び指数関数的な動作につながります。 

重要な観察は、各人が「A または B」という形式の制約を課していることです。ここで、A と B はそれぞれ 1 つの映画に対して単純な条件です。 これはまさに 2 変数論理節です。 全体的な問題は、すべての句を満たす変数へのブール値の割り当てが存在するかどうかを判断することになります。 

これは、含意を使用してグラフ問題としてモデル化できます。 各条件はブール値リテラルとして書き換えることができます。 句 (A または B) は 2 つの含意に相当します。A が false の場合、B は true でなければならず、B が false の場合、A は true でなければなりません。 これにより、問題は有向グラフ上の到達可能性の制約に変換されます。 

この含意グラフを構築すると、矛盾の構造がグラフの接続性になります。変数とその否定が同じ強く接続されたコンポーネントに属している場合、変数はそれ自体を真と偽の両方に強制することができ、システムが不可能になります。 それ以外の場合は、コンポーネントの順序付けから有効な割り当てを抽出できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 割り当てに対するブルートフォース | O(2^M・N) | お(1) | 遅すぎる |
 | バックトラッキング検索 | O(2^M) 最悪の場合 | O(M + N) | 遅すぎる |
 | SCC 経由の 2-SAT | O(N + M) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ムービーをブール変数としてエンコードします。 「true」は映画が最終選択に含まれることを意味し、「false」は含まれないことを意味します。 

各人は 2 つのリテラルを提供し、それぞれが極性 (含めるか除外する) で映画を参照します。 これらをブール変数に変換し、意味を構築します。 

1. グラフ内の 2 つのノードを使用して各映画 i を表します。1 つは「i が含まれる」ノード、もう 1 つは「i が含まれない」ノードです。 これにより、変数とその否定の両方を明示的に表すことができます。 
2. 各人について、2 つの条件を読み上げます。 各条件は、映画の肯定的な形式または否定的な形式のいずれかの文字通りのノードになります。 
3. リテラルの各ペア (A、B) に対して、2 つの有向含意を追加します。 A が満たされない場合は、B も満たさなければなりません。 対称的に、B が満たされない場合は、A も満たされる必要があります。 唯一の禁止された状況は A と B の両方が false であるため、これにより OR 制約が正しくエンコードされます。 
4. すべての含意を構築した後、Tarjan の方法などの標準アルゴリズムを使用して、有向グラフの強結合成分を計算します。 SCC 構造は、相互の到達可能性を暗黙的に捉えます。 
5. 各ムービーの一貫性を確認します。 「含まれる」を表すノードと「含まれない」を表すノードが同じ SCC に属している場合、制約により矛盾が生じ、解決策は存在しません。 
6. 矛盾が存在しない場合は、SCC の逆のトポロジー順序で値を割り当てます。 トポロジー順序で後から現れるコンポーネントが最初に割り当てられます。 各ムービーについて、「含まれる」ノードのコンポーネントが「含まれない」ノードよりも上位にランク付けされている場合は、そのコンポーネントを含まれるものとして割り当て、そうでない場合は除外します。 

この順序付けが機能する理由は、SCC 凝縮が有向非巡回グラフを形成し、コンポーネントを逆順で処理すると含意の方向が尊重されるためです。 

### なぜ効果があるのか

各句は、禁止された構成を 1 つだけ削除します。つまり、両方のリテラルが false になります。 含意グラフは、強制的な決定を伝播する方法でこの制限をエンコードします。 強く接続されたコンポーネントは、強制的な等価性のサイクルを捕捉します。 変数とその否定が同じサイクル内にある場合、そのサイクルは両方の真理値を同時に強制しますが、これは不可能です。 それ以外の場合、凝縮グラフは強制的な含意の部分的な順序を提供し、逆トポロジー順序で値を割り当てることにより、変数が設定されるたびに、それを必要とするすべての含意がすでに尊重されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    
    # 2 nodes per movie: i -> 2*i (true), 2*i+1 (false)
    # We will map:
    # include i = 2*i
    # exclude i = 2*i+1
    
    def neg(x):
        return x ^ 1

    g = [[] for _ in range(2 * m)]

    def add_imp(u, v):
        g[u].append(v)

    def add_or(a, b):
        # a or b  =>  (not a -> b) and (not b -> a)
        add_imp(neg(a), b)
        add_imp(neg(b), a)

    for _ in range(n):
        t1, i1, t2, i2 = input().split()
        i1 = int(i1) - 1
        i2 = int(i2) - 1

        a = 2 * i1 + (0 if t1 == "S" else 1)
        b = 2 * i2 + (0 if t2 == "S" else 1)
        add_or(a, b)

    # Tarjan SCC
    index = 0
    stack = []
    onstack = [False] * (2 * m)
    ids = [-1] * (2 * m)
    low = [0] * (2 * m)
    comp = [-1] * (2 * m)
    cid = 0

    def dfs(u):
        nonlocal index, cid
        ids[u] = low[u] = index
        index += 1
        stack.append(u)
        onstack[u] = True

        for v in g[u]:
            if ids[v] == -1:
                dfs(v)
                low[u] = min(low[u], low[v])
            elif onstack[v]:
                low[u] = min(low[u], ids[v])

        if low[u] == ids[u]:
            while True:
                x = stack.pop()
                onstack[x] = False
                comp[x] = cid
                if x == u:
                    break
            cid += 1

    for i in range(2 * m):
        if ids[i] == -1:
            dfs(i)

    ans = [0] * m

    for i in range(m):
        if comp[2*i] == comp[2*i + 1]:
            print("IMPOSSIVEL")
            return
        ans[i] = 'S' if comp[2*i] > comp[2*i + 1] else 'N'

    print(" ".join(ans))

if __name__ == "__main__":
    solve()
```この実装では、各リテラルがノードに対応する有向含意グラフが構築されます。 ヘルパー関数`add_or`各人の制約を 2 つの意味にエンコードします。 Tarjan のアルゴリズムは、線形時間で強結合成分を計算するために使用されます。 最後の決定ステップでは、SCC インデックスを比較します。コンポーネント ID が高いほど、圧縮順序の後半で処理されることを意味し、論理的により「強制」されることに対応します。 

よくある実装上の落とし穴は、「S/N」とブール極性の間のマッピングを混同することです。 もう 1 つは、SCC ID が Tarjan の順序に対してのみ有効であることを忘れていることです。 コンポーネント間の比較を逆にすると、SCC の計算が正しい場合でも、すべての出力が誤って反転されます。

 ## 特殊なケース

 微妙な特殊なケースは、句内の両方のステートメントが同じ映画を参照している場合です。 たとえば、「S 1 S 1」は含意グラフ内で自己ループを生成しますが、矛盾は生じません。 SCC 計算では、それ自体に到達するコンポーネントにリテラルが配置されますが、その否定は分離されたままであるため、代入は引き続き機能します。 

もう 1 つのケースは、映画がいかなる条項にも制約されない場合です。 その状況では、両方のノードがグラフ内で分離されます。 SCC はそれらをシングルトン コンポーネントに割り当て、比較ルールは一貫して一方を選択します。通常、順序付けにより優先順位が下になる場合は、デフォルトで除外されます。 

完全に矛盾したインスタンスは、句によって変数とその否定が同じ強く接続されたコンポーネントに強制される場合に発生します。 このような場合、Tarjan のアルゴリズムは、含意による相互到達可能性によりそれらをマージし、チェックによって即座に不可能性の出力がトリガーされます。
