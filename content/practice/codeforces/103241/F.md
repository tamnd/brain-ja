 ## 解決策
 ## 問題の理解

 私たちは本棚に置かれた本のリストを渡されました。 各書籍には、小文字の 1 語のタイトルと発行年が記載されています。 このタスクは、本が主にタイトルの最初の文字によってアルファベット順にグループ化されるように、棚の順序を変更することです。 このような各グループ内では、出版年が古いものから新しいものへと書籍を並べる必要があります。 

出力は、インデックスやペアとしての順序付け自体ではなく、単に最終的にソートされた順序で 1 行に 1 つずつ書籍タイトルのシーケンスが表示されます。 

入力サイズは最大約1万冊になります。 これはすぐに次のことを示します。$O(n^2)$スキャンやリストへの挿入を繰り返し行うソリューションは、最悪の場合、速度が非常に遅くなります。 アン$O(n \log n)$並べ替えが優先され、正しい順序付けキーを定義するだけで済むため、このアプローチは十分であり、期待されています。 

主な微妙な点は、順序付けがカスタムの意味で辞書編集的であることです。つまり、完全な文字列の並べ替えではなく、グループ化に重要なのは最初の文字のみであり、そのグループ化内では年が重要です。 

年だけ、または名前だけで並べ替えると、単純な間違いが発生します。 

たとえば、次のことを考えてみましょう。 

入力:```
3
banana 2000
apple 1990
apricot 1980
```正しい出力:```
apricot
apple
banana
```年だけを基準に並べ替える単純なアプローチでは、次の結果が得られます。```
apricot
apple
banana
```ここでは偶然に機能しますが、文字が異なる場合は失敗します。 

次に、次のことを考えてみましょう。```
3
banana 1980
apple 2000
apricot 1990
```正しい出力:```
apple
apricot
banana
```最初の文字を無視すると、年でソートすると次のようになります。```
banana
apricot
apple
```最初の文字によるグループ化が必須であるため、これは不正確です。 

もう 1 つの微妙な問題は、年が等しい場合の安定性です。 2 つの本が同じ最初の文字と同じ年を共有する場合、それらの相対的な順序はステートメントによって明示的に定義されないため、一貫したタイブレーク (名前による辞書編集など) は許容されますが、決定論を保証する必要があります。 

## アプローチ

 この強引なアイデアは、リストを繰り返しスキャンし、ルール (最初の文字優先、次に年) に従って次に小さい有効な書籍を選択することで、手動で並べ替えをシミュレートすることです。 これは、カスタム コンパレーターでの選択ソートに似ています。 これは正しいです。各ステップで次の有効な要素を順番に明示的に選択しますが、各選択にはコストがかかります。$O(n)$、そしてこれを全員のために行う$n$ポジションは～につながります$O(n^2)$操作。 と$n = 10^4$、これくらいになります$10^8$これは、一般的な制約の下では Python では境界線に達するか、遅すぎます。 

重要な観察は、順序関係が、文字列の最初の文字、次に年、最後にオプションでタイブレーク用の完全なタイトルという小さなタプルによって定義される厳密な合計順序であるということです。 これを認識すると、問題は標準的な並べ替えタスクに集約されます。 並べ替えアルゴリズムは内部で順序付けを効率的に処理します。$O(n \log n)$Python の Timsort は、そのような構造化キー用に最適化されています。 

したがって、決定をシミュレートする代わりに、ルールをソートキーとしてエンコードし、順序付けを標準ライブラリに委任します。

 | --- | --- | --- | --- |
 | ブルートフォースセレクション |$O(n^2)$|$O(1)$番外編 | 遅すぎる |
 | キーによるソート |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. すべての本を読んで記憶に残す

 各エントリは、タイトルと発行年のペアとして保存されます。 これにより、入力アクセスを繰り返すことなくソートキーを計算できるようになります。 

### 2. 順序付けルールを取得する並べ替えキーを定義します。 

本ごとにタプルを構築します`(first_letter, year, title)`。 最初の文字はグループ化を強制し、年は各グループ内での時系列順を強制し、タイトルは決定的なタイブレーカーとして機能します。 

### 3. キーを使用してリストを並べ替えます。 

定義されたタプルを使用して、すべての書籍に標準の並べ替えを適用します。 ソート アルゴリズムはタプルを辞書順に比較し、必要な順序と正確に一致します。 

### 4. タイトルのみをソート順に出力します

 ソート後、順序付けにのみ使用されるため、年は無視して、各タイトルを順番に印刷します。 

### なぜ効果があるのか

 正確さは、目的の順序が辞書編集上の比較によって完全に記述されているという事実から得られます。`(first_letter, year, title)`。 これは全体の順序を定義します。つまり、書籍のすべてのペアが比較可能であり、推移的な一貫性が保たれます。 ソートアルゴリズムは、このコンパレータと一致するシーケンスを生成することが保証されているため、結果として得られるリストは、必要な棚の配置と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    books = []
    
    for _ in range(n):
        name, year = input().split()
        year = int(year)
        books.append((name, year))
    
    books.sort(key=lambda x: (x[0][0], x[1], x[0]))
    
    for name, _ in books:
        print(name)

if __name__ == "__main__":
    main()
```実装の重要な詳細はソートキーです。 明示的に使用します`x[0][0]`タイトルの最初の文字を抽出し、最初の文字で確実にグループ化します。 2 番目のコンポーネントは年であり、時系列の昇順が強制されます。 最後のコンポーネント`x[0]`前のフィールドが両方とも等しい場合、関係が安定します。 

よくある間違いは、最初の文字のグループ化を完全に忘れたり、最初に完全な文字列でソートしたりすることです。これにより、意図した順序付けの構造が変わってしまいます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \log n)$| 仕分け$n$辞書編集キーを使用した書籍 |
 | スペース |$O(n)$| 書籍リストの保存とソートのオーバーヘッド |

 この制約により、最大 10,000 冊の書籍が許可されます。$n \log n$操作は Python の制限内で問題なく行われるため、このソリューションは問題に対して十分に効率的です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    books = []
    for _ in range(n):
        name, year = input().split()
        books.append((name, int(year)))

    books.sort(key=lambda x: (x[0][0], x[1], x[0]))

    return "\n".join(name for name, _ in books)

# sample
assert run("""4
harry 1987
orange 1776
hotels 1973
moon 2018
""") == "hotels\nharry\nmoon\norange"

# minimum size
assert run("""1
alone 2020
""") == "alone"

# same first letter different years
assert run("""3
apple 2000
apex 1990
aardvark 2010
""") == "apex\napple\naardvark"

# same first letter and year
assert run("""3
bbb 2000
bba 2000
bbc 2000
""") == "bba\nbbb\nbbc"

# reverse order input
assert run("""3
c 3
b 2
a 1
""") == "a\nb\nc"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単行本 | それ自体 | 最小限のエッジケース |
 | 同じプレフィックスでも年が変わる | 年順に並べ替え | コアルール |
 | 同じプレフィックスと年 | 決定的なタイブレーク | 安定性 |
 | 逆順 | 完全な並べ替えの正確さ | 一般的なケース |

 ## 特殊なケース

 複数の本が同じ開始文字と同じ出版年を共有する場合、微妙な特殊なケースが発生します。 3 番目のタイ ブレーカーがないと、異なるソート実行により異なる有効な順列が生成される可能性があり、これは決定論的な出力問題では望ましくありません。 

例えば：```
3
booka 1999
bookb 1999
bookc 1999
```このアルゴリズムは完全なタイトルを最終キーとして使用するため、実行は辞書編集順に進行し、一貫した出力が保証されます。```
booka
bookb
bookc
```もう 1 つの特殊なケースは、すべての本が異なる文字で始まる場合です。 最初の文字のルールによって順序が完全に決まり、年は影響しません。 タプルの比較では自然に最初の文字が優先されるため、アルゴリズムは引き続き機能します。 

最後に、すべてのブックが同じ最初の文字を共有する場合、問題は年によるソートに帰着し、実装は特別なケースを使用せずに自動的にその動作に折りたたまれます。
