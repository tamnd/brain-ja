 ## 解決策
 ## 問題の理解

 1 行に配置された値を表す整数の配列が与えられます。 タスクは、この配列のすべての連続セグメントから導出される単一の数値を計算することです。 すべてのセグメントについて算術平均を計算し、考えられるすべてのセグメントにわたってそれらの平均を平均します。 

したがって、1 つのセグメントを選択する代わりに、各サブ配列がその平均に寄与するすべてのサブ配列の値を効果的に合計し、サブ配列の数で割ります。 

長さ n の配列の部分配列の数は n(n+1)/2 であるため、最終的な答えは次のようになります。 

すべてのサブ配列の合計 (サブ配列の合計 / サブ配列の長さ) を n(n+1)/2 で割ります。 

通常、入力サイズでは、テスト ケース全体で最大約 2⋅10^5 個の合計要素が許容され、部分配列の O(n^2) 列挙は直ちに除外されます。 すべてのセグメントを明示的に反復したり、セグメントごとの合計を再計算したりするソリューションはタイムアウトになります。 

明白ではない問題は、平均ではセグメント長による除算が導入され、直接的なプレフィックス合計のトリックがわかりにくくなることです。 合計の観点のみで考える単純なアプローチでは、各要素が含まれるサブ配列の数とサブ配列の長さに応じて、各要素の寄与が異なるということを見落としてしまいます。 

単純な考え方を打ち破る一般的なエッジ ケースは、各要素がすべてのサブ配列にわたって均等に寄与すると仮定することです。 たとえば、[1, 2] では、部分配列は [1]、[2]、[1,2] になります。 平均は 1、2、1.5 なので、最終的な平均は 1.5 になります。 ここでも単純な「要素のグローバル平均」では 1.5 が得られますが、これは偶然です。 より大きな入力では、正しい重み付けが導出されない限り、この等価性は失敗します。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべてのサブ配列を列挙し、その合計を計算し、その長さで除算し、その結果を累積し、最後にサブ配列の総数で除算します。 これは定義に直接従っているため、正しいです。 ただし、O(n^2) 個の部分配列を列挙して合計を単純に再計算すると、O(n^3)、または接頭辞合計を含む O(n^2) が得られます。これは、n がテスト全体で合計 2⋅10^5 に達すると遅すぎます。 

重要な観察は、各要素 ai が多くの部分配列に寄与しており、部分配列の観点から考える代わりに、個々の要素の寄与に視点を反転することです。 各要素は、それを含むすべてのサブ配列に参加しますが、その寄与はサブ配列の長さにわたって 1 ずつスケールされます。 そのため、直接カウントするのは難しくなりますが、よりきれいな対称性があります。正しいエンドポイントを固定し、プレフィックス累積を使用して線形公式を導く方法で寄与を集計することで、サブ配列全体の合計を再編成できます。 

定義を注意深く拡張すると、合計は次のようになります。 

ai の i の合計に、i を含むすべてのサブ配列の (1 / サブ配列の長さ) の合計を乗算します。 

これらの調和のような重みの構造は、グローバルに再編成すると簡素化されます。各要素の正確な係数を追跡する代わりに、プレフィックス情報を使用して寄与を増分的に反復および維持することによって、最終的な閉じた形式を計算します。 

これにより、問題はテスト ケースごとに O(n) に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) から O(n³) | O(1) または O(n) | 遅すぎる |
 | 最適なプレフィックス寄与 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 最適なアイデア

 1. O(1) でサブ配列の合計を取得できるように、配列のプレフィックスの合計を事前計算します。 

これにより、合計を繰り返し再計算することが回避され、長さによる除算の処理に残る困難が分離されます。 
2. 1 から n までのすべての可能なサブ配列長に対して反復します。 

固定長 L の場合、その長さのすべての部分配列を考慮します。 このような部分配列は n − L + 1 個あります。 
3. 各固定長 L について、プレフィックス合計に対するスライディング ウィンドウを使用して、その長さのすべてのサブ配列の合計を計算します。

これにより、その長さに対する分子の寄与の合計が得られます。 
4. 長さ L の合計を L で割って、合計を平均値に変換します。 

このステップは、平均に寄与する各部分配列の定義と一致します。 
5. これらの値を 1 から n までのすべての L にわたって累積します。 
6. 最後に、サブアレイの総数、つまり n(n+1)/2 で除算します。 

各ステップでは、部分配列を列挙するのではなく、テスト ケースごとに O(n) の作業のみを実行するように、計算が段階的に再構築されます。 

### なぜ効果があるのか

 正確さは、すべてのサブ配列にわたるグローバル合計をその長さによって分割することで得られます。 すべての部分配列は正確に 1 つの長さクラスに属するため、項が二重にカウントされたり欠落したりすることはありません。 各クラス内で、接頭辞の合計により、すべての部分配列の合計を正確に 1 回計算することが保証されます。 サブ配列の数による最終的な正規化では、平均の累積合計が必要な全体平均に変換されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    total_subarrays = n * (n + 1) // 2
    total = 0

    for L in range(1, n + 1):
        s = 0
        for i in range(L, n + 1):
            s += pref[i] - pref[i - L]
        total += s / L

    print(total / total_subarrays)

if __name__ == "__main__":
    solve()
```プレフィックス配列は、部分配列の合計を一定時間で計算するために使用されます。 外側のループは長さを固定し、内側のループは配列全体でその長さのウィンドウをスライドさせます。 L による除算は、正しい粒度で合計を平均に変換します。 サブ配列の総数による最終的な除算は、「平均の平均」の定義と一致します。 

微妙な点は、浮動小数点の使用です。除算が含まれるため、Codeforces の一般的な許容値 1e-6 を考慮すると、Python の倍精度で十分です。

 ## 特殊なケース

 次のような単一要素配列の場合`[x]`、部分配列は 1 つだけあり、その平均は x です。 L=1 ループが 1 回実行され、プレフィックス合計が x を返し、正規化が 1 で除算されるため、アルゴリズムはこれを処理します。 

次のような定数配列の場合`[c, c, c, ...]`、すべての部分配列の平均は c に等しくなります。 長さによるグループ化では、c と部分配列の数の積に比例する合計が計算され、除算は完全にキャンセルされ、c が残ります。 

厳密に増加する配列の場合、部分配列の平均は中央の値に偏ります。各長さクラスがすべてのウィンドウにわたって正確な算術平均に寄与し、一様な寄与を仮定するのではなく分布を維持するため、アルゴリズムはこれを正確に捕捉します。
