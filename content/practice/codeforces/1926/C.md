 ## 解決策
 ## 問題の理解

 すべてのテストケースには番号が与えられます`n`。 Vlad は次のすべての整数を書き込みます`1`を通して`n`ボード上で。 次に、各整数がその 10 進数の合計に置き換えられます。 

タスクは計算することです$$\sum_{i=1}^{n} \text{digitSum}(i)$$どこ`digitSum(i)`の桁の合計です`i`。 

たとえば、次のようなとき`n = 12`、桁の合計は次のとおりです。$$1,2,3,4,5,6,7,8,9,1,2,3$$そしてそれらの合計は`51`。 

制約は重要な観察事項です。 まであります`10^4`テストケースとそれぞれの`n`と同じ大きさにすることができます`200000`。 以下を反復することにより、テスト ケースごとに独立して答えを計算します。`1`に`n`同じ作業を何度も繰り返すことになります。 それでも`200000`それ自体は大きくありませんが、それを行うのは`10000`テスト ケースには約 20 億の操作が必要ですが、これは、`0.5`2回目の制限時間。 

の最大値`n`だけです`200000`、これは別の戦略を示唆しています。 すべてのクエリは同じ範囲の数値にわたるプレフィックスの合計を要求するため、次のすべての値に対する回答を前処理できます。`1`に`200000`1 回だけ、一定時間内に各テスト ケースに答えます。 

いくつかの特殊なケースは注目に値します。 

考慮する`n = 1`。 

入力：```
1
1
```答えは次のとおりです。```
1
```最初の値がスキップされないように、プレフィックス配列は正しく初期化する必要があります。 

考慮する`n = 10`。 

桁の合計は次のとおりです。$$1+2+3+4+5+6+7+8+9+1 = 46$$よくある間違いはそれを忘れることです`digitSum(10) = 1`、 ない`10`。 

考慮する`n = 99999`そして`n = 100000`。 

桁の合計は、10 の累乗を超えると急激に減少します。$$digitSum(99999)=45,\qquad digitSum(100000)=1$$キャリーを適切に処理せずに単純な算術パターンを使用して値を導出しようとすると、そのような境界付近で失敗します。 

## アプローチ

 最も直接的な解決策は、各テスト ケースを個別に処理することです。 与えられた`n`からのすべての数値を反復処理します。`1`に`n`、各桁の合計を計算し、結果を累積します。 

これは、答えがその範囲内のすべての桁の合計の正確な合計であるため、機能します。 問題はコストです。 桁の合計の計算には約`O(log n)`演算を行い、次の値までのすべての数値に対してそれを実行する必要があります。`n`。 1 つのテスト ケースの複雑さはおおよそ次のとおりです。`O(n log n)`。 と`n = 200000`そして`10000`テストケースの作業量は膨大になります。 

重要な観察は、すべてのテスト ケースが同じ種類のプレフィックス クエリを要求していることです。$$\text{answer}(n)=\sum_{i=1}^{n}\text{digitSum}(i)$$これらの合計を繰り返し再計算する代わりに、一度に計算することができます。 

させて$$dp[i] = \text{digitSum}(i)$$そして$$pref[i] = \sum_{j=1}^{i} dp[j]$$したがって、あらゆるテストケースの答えは単純に次のようになります。`pref[n]`。 

可能な限り大きいので、`n`だけです`200000`、クエリを読み取る前に、その制限までのすべての桁の合計とすべてのプレフィックスの合計を事前計算できます。 

もう一つ有益な観察があります。 数値の桁の合計は再帰的に計算できます。$$digitSum(i)=digitSum(i//10)+(i\bmod 10)$$これにより、以下のすべての桁の合計が可能になります。`1`に`200000`線形時間で効率的に計算されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースごとに O(n log n) | お(1) | 遅すぎる |
 | 最適 | O(MAXN) 前処理 + クエリあたり O(1) | O(MAXN) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのテスト ケースを読み取り、その値を保存します。 
2. 前処理に必要な最大値を見つけます。 この問題ではいつもそうです`200000`ですが、クエリされた最大の値を使用することもできます。 
3. 配列を作成する`digit`どこ`digit[i]`の桁の合計を格納します`i`。 
4. 漸化式を使用して桁の合計を計算します。$$digit[i] = digit[i // 10] + (i \% 10)$$最後の数字が寄与します`i % 10`、残りの数字は正確に`i // 10`。 
5. プレフィックス合計配列を作成する`pref`。 
6. それぞれについて`i`、計算する$$pref[i] = pref[i-1] + digit[i]$$このステップの後、`pref[i]`に必要な答えと等しい`i`。 
7. すべてのテスト ケースについて、出力`pref[n]`。 

### なぜ効果があるのか

 の再発`digit[i]`すべての 10 進数は最後の桁とその前のすべての桁で構成されるため、これは正解です。 数値を分割する`i // 10`そして`i % 10`これら 2 つの部分を正確に分離します。 

プレフィックス配列は、インデックスの処理後も不変条件を維持します。`i`、$$pref[i]=\sum_{k=1}^{i} digit[k]$$これは最初は当てはまりますが、`i=0`、各ステップで正確に 1 つの新しい桁の合計が加算されます。 その結果`pref[n]`からの桁の合計の合計に等しい`1`を通して`n`、これはまさに問題で必要な量です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    queries = [int(input()) for _ in range(t)]

    mx = max(queries)

    digit = [0] * (mx + 1)
    pref = [0] * (mx + 1)

    for i in range(1, mx + 1):
        digit[i] = digit[i // 10] + (i % 10)
        pref[i] = pref[i - 1] + digit[i]

    out = [str(pref[n]) for n in queries]
    sys.stdout.write("\n".join(out))

solve()
```最初のステップではすべてのクエリを読み取るため、前処理がどこまで行われなければならないかがわかります。 以下まで配列を構築する理由はありません`200000`すべてのクエリが小さい場合。 

の`digit`配列は反復を使用します```
digit[i] = digit[i // 10] + (i % 10)
```なぜなら`i // 10`は常により小さいです`i`、必要な値はすでに計算されています。 

プレフィックス配列も同時に構築されます。 の桁の合計を計算した後、`i`、すぐに累計を延長します。 

最大の答えは数百万にすぎないため、Python の整数で十分です。 オーバーフローに対する特別な処理は必要ありません。 

よくある実装上の間違いは、次の場所でループを開始することです。`0`。 ここでも繰り返しは有効ですが、プレフィックス定義はよりクリーンです。`pref[0] = 0`そして処理はから始まります`1`。

 ## 特殊なケース

 可能な最小の入力を考えてみましょう。```
1
1
```前処理ループは以下を計算します。```
digit[1] = digit[0] + 1 = 1
pref[1] = pref[0] + 1 = 1
```アルゴリズムの出力`pref[1] = 1`、それは正しいです。 

最初のキャリー境界を考えてみましょう。```
1
10
```計算された値は次のとおりです。```
digit[9] = 9
digit[10] = digit[1] + 0 = 1
```プレフィックスの合計は次のようになります。```
45 + 1 = 46
```の桁の合計なので、答えは正しいです。`10`は`1`、 ない`10`。 

長いキャリー チェーンを考えてみましょう。```
1
100000
```反復により次のことが得られます。```
digit[100000]
= digit[10000] + 0
= digit[1000] + 0
= digit[100] + 0
= digit[10] + 0
= digit[1] + 0
= 1
```アルゴリズムは、特別な場合を必要とせずにこれを自然に処理します。 プレフィックスの合計には、以前のすべての数値の寄与がすでに含まれているため、この最終値を加算すると正しい結果が得られます。
