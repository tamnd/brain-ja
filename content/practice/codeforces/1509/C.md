 ## 解決策
 ## 問題の理解

 市議会議員全員の走行速度が与えられています。 実行する順序は任意に選択できます。 

選択した順序のすべてのプレフィックスについて、すでに参加しているすべてのランナーを調べます。 そのプレフィックスの不一致は、これまでに確認された最大速度と最小速度の差です。 最大値と最小値が同じであるため、最初のランナーは常にゼロを貢献します。 

私たちの目標は、すべてのプレフィックスの不一致の合計ができるだけ小さくなるようにランナーを配置することです。 

入力は単なる速度の配列です。 出力は、最適な順序を選択した後に達成可能な最小の不一致合計です。 

最も重要な観察は、不一致がすでに選択されているランナーの現在の最小値と最大値にのみ依存するという事実から得られます。 両極端が現れた後は、その範囲内の出走馬の正確な内着順は問題になりません。 

制約は$n \le 2000$。 すべての順列を総当りで検索することは完全に不可能です。$n!$可能な注文。 サブセットに対する動的プログラミングでも、$2^n$これもまた手の届かないところにあります。 と$n=2000$、周りの解決策$O(n^2)$現実的ですが、$O(n^3)$はすでに遅すぎるでしょう。 

見落としやすいエッジケースがいくつかあります。 

考慮する：```
1
7
```答えは次のとおりです。```
0
```ランナーは 1 人だけなので、矛盾はゼロです。 

考慮する：```
3
5 5 5
```答えは次のとおりです。```
0
```すべての速度は同じです。 すべてのプレフィックスには最大値と最小値が等しい。 

考慮する：```
3
1 2 100
```単純な戦略では、走者をソート順に配置する可能性があります。 不一致は次のようになります。```
0 + 1 + 99 = 100
```ただし、最適な順序は次のとおりです。```
2, 1, 100
```与える：```
0 + 1 + 99 = 100
```この例では両方が偶然一致しますが、より大きな場合には、通常、最良の順序付けは単に並べ替えられた順序ではありません。 累積コストを全体的に最小化する方法が必要です。 

## アプローチ

 ブルートフォースソリューションでは、ランナーの可能な順序をすべて試します。 各順列について、左から右にスキャンし、現在の最小速度と最大速度を維持し、すべての不一致を計算し、最小の合計を維持できます。 

これが機能するのは、実行可能なすべての配置を直接チェックするためです。 

問題は順列の数です。 と$n=2000$、 がある$2000!$可能な注文数は天文学的な数です。 たとえ$n=15$、網羅的な検索はすでに不可能です。 

より良いアプローチを見つけるために、速度を並べ替えてみましょう。 

ソートされた速度が次のようになると仮定します。$$a_0 < a_1 < \cdots < a_{n-1}$$選択したランナーのセットを徐々に構築することを考えてください。 並べ替え後、すでに選択されているランナーのコレクションは、並べ替えられた配列内で一定の間隔を占める必要があります。 選択されたランナーが正確にポジション間のランナーであることがわかっている場合$l$そして$r$の場合、現在の不一致は単純に次のようになります。$$a_r - a_l$$ここで、最終的な順序を逆に構築することを想像してください。 

ある段階で、すべてのランナーをインターバルから配置する必要があります。$[l,r]$。 この間隔内で最終的に現れる最大の不一致は正確に次のとおりです。$$a_r - a_l$$どのエンドポイントを最後に追加するかを決定すると、残りの問題はより短い間隔の 1 つになります。$[l+1,r]$または$[l,r-1]$。 

この間隔構造は、範囲に関する動的プログラミングを示唆しています。 

させて$$dp[l][r]$$ソートされた位置が$[l,r]$。 

インターバル時$[l,r]$複数のランナーが含まれており、現在の範囲幅$$a_r-a_l$$支払いは 1 回だけ行う必要があり、その後はいずれかの短い間隔で続行されます。 

これにより、次の繰り返しが得られます。$$dp[l][r] = (a_r-a_l) + \min(dp[l+1][r], dp[l][r-1])$$基本的なケースは次のとおりです。$$dp[i][i]=0$$単一のランナーが矛盾に貢献しないためです。 

答えは$dp[0][n-1]$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n! \cdot n)$|$O(n)$| 遅すぎる |
 | インターバルでの最適な DP |$O(n^2)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 速度を読み取り、並べ替えます。 
2. 次のような 2 次元 DP テーブルを作成します。`dp[l][r]`は、ソートされた間隔に必要な最小合計不一致寄与を表します。`l`に`r`。 
3. 単一ランナーの不一致がゼロであるため、すべての単一要素間隔をゼロで初期化します。 
4. 間隔を長さの昇順に処理します。 
5. しばらくの間`[l, r]`、その幅を計算します。$$a_r-a_l$$この幅は、間隔が完全に表現されるときに 1 回出現する必要があります。 
6. この幅を支払った後、左のエンドポイントまたは右のエンドポイントが最後に追加されました。 

左のエンドポイントが最後に追加された場合、以前の状態は`[l+1,r]`。 

正しいエンドポイントが最後に追加された場合、以前の状態は`[l,r-1]`。 
7. 次の 2 つの可能性のうち、より良い方を選択します。$$dp[l][r] = (a_r-a_l) + \min(dp[l+1][r],dp[l][r-1])$$8. 間隔が終わるまで続けます`[0,n-1]`計算されています。 
9. 出力`dp[0][n-1]`。 

### なぜ効果があるのか

 ソート後、既に組み込まれているランナーの各セットは、ソートされた配列の連続した間隔に対応します。 

インターバル用$[l,r]$、この間隔全体がアクティブになるときに寄与する不一致は正確に$a_r-a_l$。 この時点では、2 つのエンドポイントのうち 1 つが最後に追加されている必要があります。 最後に追加したエンドポイントを削除すると、どちらかの間隔が残ります$[l+1,r]$または間隔$[l,r-1]$。 

繰り返しでは両方の可能性を検討し、より安価な方を維持します。 すべての有効な構築シーケンスは最終的に単一の要素間隔に減少し、すべての遷移はその段階で導入された正確な不一致を説明するため、DP は可能な最小の合計不一致を計算します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = sorted(map(int, input().split()))

    dp = [[0] * n for _ in range(n)]

    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1
            dp[l][r] = (a[r] - a[l]) + min(
                dp[l + 1][r],
                dp[l][r - 1]
            )

    print(dp[0][n - 1])

solve()
```最初のステップでは速度を並べ替えます。 並べ替え後は、関連するすべての状態が連続した間隔になります。これが、ソリューションの重要な構造特性です。 

DP テーブルには、すべての間隔の回答が保存されます。 速度が 1 つだけ存在する場合は矛盾が存在しないため、単一要素の間隔はゼロのままです。 

外側のループは長さを増やすことによって間隔を処理します。 これにより、計算時に次のことが保証されます。`dp[l][r]`、 両方`dp[l+1][r]`そして`dp[l][r-1]`すでに計算されています。 

再発は証明と直接一致します。 間隔幅`a[r] - a[l]`は 1 回支払われ、その後、以前の 2 つの可能な間隔のうち、より良い方が選択されます。 

すべての値は Python 整数に快適に収まります。 考えられる最大の答えは次のとおりです。$n \cdot 10^9$, これは Python の制限を大幅に下回っています。

 | 測定 | 複雑さ | 説明 |

 | 時間 |$O(n^2)$| がある$O(n^2)$間隔、それぞれが処理される$O(1)$時間 |

と$n \le 2000$、DPには約400万の州が含まれています。 各状態は一定量の作業のみを必要とするため、解は指定された制限に対して十分高速になります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())
    a = sorted(map(int, input().split()))

    dp = [[0] * n for _ in range(n)]

    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1
            dp[l][r] = (a[r] - a[l]) + min(
                dp[l + 1][r],
                dp[l][r - 1]
            )

    return str(dp[0][n - 1]) + "\n"

# provided sample
assert run("3\n3 1 2\n") == "3\n", "sample 1"

# minimum size
assert run("1\n7\n") == "0\n", "single element"

# all equal
assert run("4\n5 5 5 5\n") == "0\n", "all equal"

# simple increasing
assert run("2\n1 10\n") == "9\n", "two elements"

# off-by-one interval handling
assert run("3\n1 2 10\n") == "10\n", "small interval DP"

```考慮する：```

```最終的な答えはゼロのままで、すべてのプレフィックスの最大速度と最小速度が同じであることを正しく反映しています。

2

```唯一重要な間隔は次のとおりです。`[0,1]`。

```どちらの小さい間隔もコストがゼロの単一要素であるため、次のようになります。```
