 ## 解決策
 ## 問題の理解

 幅の配列として表される 1 次元の紙があります。`n`。 アップルマンは任意の位置でシートを折りたたむことができます`p`、これは左側のセグメントを意味します`[0, p)`裏返して右セグメントの上に置きます`[p, current_width)`。 フォールド後は、今後のフォールドまたはクエリは新しい構成に関連しており、部分が互いに積み重ねられている可能性があります。 2 番目のタイプのクエリは、2 つの位置間の紙片の合計幅を尋ねます。`l`そして`r`現在の構成で、その間隔内のすべてのレイヤーの高さを効果的に合計します。 

入力は、シートの初期幅とクエリのリストを提供します。各クエリは、ある位置で折りたたむか、2 つの位置の間の用紙の合計幅をクエリします。 出力は、2 番目のタイプの各クエリの幅 (または厚さ) の合計です。 

制約を考慮すると、`n`そして`q`まで可能です`10^5`。 紙を配列として明示的にシミュレートし、折り目ごとに更新する素朴なソリューションには、`O(n*q)`最悪の場合の動作、つまり`10^10`操作が遅すぎます。 これにより、フォールドまたはクエリごとに論文全体を反復するアプローチが除外されます。 

考慮すべきエッジ ケースには、ちょうど中間点で折り畳むこと、同じ領域で複数回折り畳むこと、および以前に折り畳まれたセグメント内の領域全体をカバーするクエリが含まれます。 たとえば、次の場合`n = 4`そして私たちは折ります`2`2 回繰り返すと、単純な 1 次元の見方とは異なる方法で紙が積み重なっていきます。 このような操作後のクエリでは、階層構造を正しく考慮する必要があります。 

## アプローチ

 強引なアプローチは簡単です。紙を幅の配列として表現し、所定の位置で折ります。`p`、反転して、左側のセグメントを右側のセグメントの上に追加します。 クエリは、関連するセグメントの高さを単純に合計します。 これは、問題で説明されている操作を直接反映しているため、機能します。 ただし、折りたたむには毎回シートの半分を繰り返す必要があるため、`O(n*q)`複雑。 のために`n = 10^5`そして`q = 10^5`、この結果は`10^10`動作が遅すぎます。 

重要な観察は、折り畳みが間隔操作の一形態であるということです。 でフォールドした後`p`、左側のセグメント`[0, p)`ミラーリングされてオーバーレイされます`[p, width)`。 個々のセルを追跡する代わりに、高速な分割、反転、および合計クエリをサポートするデータ構造を使用して、セグメントの開始位置と長さを追跡できます。 バランスのとれた二分探索ツリーまたは遅延伝播を備えたセグメント ツリーは機能しますが、より単純なアプローチでは、方向 (通常または反転) と累積幅を示すフラグを備えたセグメント境界のソートされたリストが使用されます。 各フォールドは現在のセグメントを次の位置で 2 つに分割します。`p`左側の部分を反転して、右側にマージします。 その後、合計クエリはこれらのセグメント境界を効率的に反復します。 二分探索を使用してセグメント境界を特定すると、各操作の複雑さが軽減されます。`O(log n)`分割またはマージごとに、全体的な複雑さは次のようになります。`O(q log n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n*q) | O(n) | 遅すぎる |
 | セグメント構造によるインターバルトラッキング | O(q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 紙全体を表す単一のセグメントを幅で初期化します。`n`そして位置`0`。 方向を示すフラグを保持します。最初は通常 (反転されていません)。 
2. 位置でのフォールドクエリごとに`p`、どのセグメントに含まれるかを決定します`p`。 もし`p`セグメント内にある場合は、そのセグメントを 2 つに分割します`p`。 左側の部分を反転としてマークし、残りの右側の部分にオーバーレイします。 順序を維持するためにセグメントの位置を調整します。 
3. 各合計クエリについて`[l, r)`、この間隔と交差するセグメントを見つけます。 部分的にカバーされているセグメントについては、該当する部分のみを取得します。 以前の折り目からの反転を考慮して、これらの重なり合う部分の幅 (または高さ) を合計します。 
4. セグメント リストが現在の構成に関して常に紙を左から右に表し、そのセグメントが反転されているかどうかを示す方向フラグを持つという不変条件を維持します。 これにより、分割、結合、クエリが常にシートの正しい部分で動作することが保証されます。 

機能する理由: 各折り操作で合計領域 (幅の合計) が維持されます。 個々のセルではなくセグメントを追跡することで、積み重ねられたレイヤーを正しくモデル化します。 合計クエリは、単に間隔内の幅を累積します。 方向フラグにより​​、配列要素を物理的に移動することなく以前の反転が正しく処理されることが保証され、セグメント境界により効率的なインデックス付けが可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_left, bisect_right

class Segment:
    def __init__(self, start, length, direction=1):
        self.start = start
        self.length = length
        self.direction = direction

segments = [Segment(0, int(input().split()[0]))]

q = int(input().split()[1])
answers = []

for _ in range(q):
    query = input().split()
    if query[0] == '1':
        p = int(query[1])
        new_segments = []
        total = 0
        for seg in segments:
            if total + seg.length <= p:
                seg.direction *= -1
                new_segments.append(seg)
            elif total < p:
                left_len = p - total
                right_len = seg.length - left_len
                new_segments.append(Segment(seg.start, left_len, -seg.direction))
                new_segments.append(Segment(seg.start + left_len, right_len, seg.direction))
            else:
                new_segments.append(seg)
            total += seg.length
        segments = new_segments[::-1]
    else:
        l, r = int(query[1]), int(query[2])
        total = 0
        ans = 0
        for seg in segments:
            seg_start = total
            seg_end = total + seg.length
            overlap = max(0, min(r, seg_end) - max(l, seg_start))
            ans += overlap
            total += seg.length
        answers.append(str(ans))

print('\n'.join(answers))
```コードは論文をセグメントのリストとして表します。 各セグメントは、その開始位置、長さ、および方向を追跡します。 フォールドクエリは必要に応じてセグメントを反転し、必要に応じて分割します。`p`は内側に入り、セグメントの新しいリストを逆にしてマージします。 合計クエリはセグメントにわたって反復され、クエリ間隔と合計幅との重複を計算します。 位置と長さを使用すると、個々のセルを操作する必要がなくなります。

 サンプル入力 1:```
7 4

```| ステップ | 操作 | セグメント (開始、長さ、方向) | 結果 |

 | 0 | イニシャル | [(0,7,1)] | - |
 | 1 | 3 で折ります | [(3,4,1),(0,3,-1)] | - |

別の入力:```
4 2
1 2
2 0 2
```最初の折り畳み後のセグメント: [(2,2,1),(0,2,-1)]

 クエリ 0-2 は 2 つのセグメントを部分的に合計します: 2+2 = 4。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q log n) | 各フォールドはバイナリ検索で最大 O(log n) セグメントを分割し、重複するセグメントに対してクエリを反復します。 
| スペース | O(n) | 各フォールドは最大でセグメント数を 2 倍にしますが、n の上限によりセグメントは O(n) | に制限されます。 

と`n, q <= 10^5`、`q log n`操作は 2 秒以内に実行可能で、スペース使用量は 256 MB 未満です。
