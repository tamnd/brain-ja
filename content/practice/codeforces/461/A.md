 ## 解決策
 ## 問題の理解

 与えられたすべての数値を含む 1 つのグループから始めます。 

トーストマンがグループを受け取るたびに、そのグループ内のすべての数値の合計をスコアに追加します。 グループに複数の数値が含まれている場合、Appleman はそれを 2 つの空でないグループに分割し、両方を Toastman に送り返すことがあります。 単一要素グループは破棄されます。 

このプロセスは、すべての番号が独自のシングルトン グループに入るまで続きます。 分割の順序と構造は完全に制御できます。 私たちのタスクは、プロセス全体で蓄積された合計スコアを最大化することです。 

入力は単純な正の整数の配列です。 出力は、分割戦略を最適に選択することで達成可能な最大スコアです。 

制約$n \le 3 \cdot 10^5$ツリーの分割を明示的に検討するアプローチは直ちに除外されます。 可能なバイナリ パーティション構造の数は指数関数的に増加するため、ブルート フォースは不可能です。 と$3 \cdot 10^5$要素と 2 秒の制限、$O(n \log n)$解決策が自然な目標である一方、$O(n^2)$遅すぎます。 

微妙な点は、すべての数字が複数回スコアに貢献することです。 不注意なアプローチでは、初期合計とシングルトン合計のみがカウントされる可能性があります。 

たとえば:

 入力```
2
1 10
```最適なスコアは次のとおりです。```
22
```グループ$[1,10]$貢献する$11$、その後、シングルトン グループが貢献します$1$そして$10$、合計で$22$。 

もう 1 つの簡単な間違いは、すべての数値が平等に扱われるべきであると仮定することです。 

入力```
3
1 2 100
```最適なスコアは次のとおりです。```
306
```大きな値は、その値を含むグループが合計されるたびに再び寄与するため、大きなグループ内にできるだけ長く留まる必要があります。 100 を分離するのが早すぎる戦略はスコアを失います。 

最後のエッジケースは、$n=1$。 

入力```
1
7
```出力```
7
```分割は不可能であるため、唯一の貢献は最初のグループ自体です。 

## アプローチ

 ブルート フォース ビューでは、考えられるすべての分割シーケンスをシミュレートします。 すべての非シングルトン グループはさまざまな方法で分割でき、巨大な検索ツリーが生成されます。 このアプローチはあらゆる法的戦略を検討するので正しいですが、絶望的に費用がかかります。 数十の要素であっても、可能なバイナリ パーティション構造の数は膨大であり、調査できる範囲をはるかに超えています。 

より良い解決策を見つけるには、単一の数値がスコアにどのように寄与するかを理解する必要があります。 

いくつかの値が、数ラウンドの分割中にグループ内に留まると仮定します。 Toastman がその値を含むグループを受け取るたびに、その値がスコアにもう一度追加されます。 大きな数値は、合計されたグループにできるだけ多く出現する必要があります。 

最後の分割シーケンスを別の観点から考えてみましょう。 少数のグループを早期に分離すると、より大きなグループは一緒に残り、将来のグループの合計に貢献し続けます。 まさにそれが私たちが望んでいることです。 最善の戦略は、より大きな要素をすべて 1 つのグループに保持しながら、残っている最小の要素を繰り返し分離することです。 

配列をソートした後:$$a_1 \le a_2 \le \cdots \le a_n$$最適なプロセスが維持される$a_n$最後まで生き続ける、生き続ける$a_{n-1}$ほぼ同じくらい生きている、など。 

させて$$S = a_1+a_2+\cdots+a_n$$の合計となります。 

初期グループが貢献$S$一度。 

ソート後、最適な分割シーケンスにより、完全な配列を除くすべてのサフィックスの合計に等しい追加の寄与が生成されます。$$(a_2+\cdots+a_n),$$

$$(a_3+\cdots+a_n),$$等々。 

同等のより単純な式は次のとおりです。 

すべての要素は、最初の合計の一部として 1 回だけ寄与します。 最小の要素を除くすべての要素は、その前の小さな要素ごとに 1 回余分に寄与します。 

並べ替えると、答えは次のようになります。$$S + \sum_{i=2}^{n} a_i \cdot (i-1)$$1 から始まるインデックスを使用します。 

これは、ソート後に直接計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n log n) | O(1) 追加 (ソートを除く) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取ります。 
2. 数値を降順でない順に並べ替えます。 

最も小さい値が最初に削除され、より大きな値がグループ内に残り、繰り返しカウントされるようにする必要があります。 
3. すべての要素の合計を計算します。 

これは初期グループの寄与であり、分割戦略に関係なく常に表示されます。 
4. この合計で答えを初期化します。 
5. ソートされた配列を 2 番目の要素から順に走査します。 
6. 各ポジションについて$i$(0 ベース)、追加$a_i \times i$答えに。 

値$a_i$正確に存在し続ける$i$追加のグループ合計があるため、$i$孤立する前に分割できる小さな要素。 
7. 最終的な答えを出力します。 

### なぜ効果があるのか

 並べ替え後、最適な分割が行われるたびに、残っている最小の要素が削除され、より大きな要素はすべて一緒に保持されます。 これにより、大きな値を含む将来のグループ合計の数が最大化されます。 

ソートされた位置の値$i$初回合計金額に1回参加します。 そして、孤立する前に、それぞれの$i$この値が大きなグループに残っている間、小さな要素は一度に 1 つずつ削除できます。 それはまさに$i$追加出演。 

さまざまな要素からの貢献が独立して加算されるため、合計スコアは各要素の合計にその要素が出現する回数を乗じたものと等しくなります。 アルゴリズムはこの量を正確に計算するため、可能な限り最大のスコアが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    ans = sum(a)

    for i in range(1, n):
        ans += a[i] * i

    print(ans)

if __name__ == "__main__":
    solve()
```最初のステップは並べ替えです。 数値を並べ替えると、将来のグループの合計に各値が何回追加で現れるかを推論できます。 

変数`ans`元のグループは常に 1 回カウントされるため、配列全体の合計から始まります。 

最小の要素の前にはそれより小さい値がないため、ループはインデックス 1 から始まります。 初期合計額によってのみ貢献します。 他のすべての要素は、ソートされた順序でのインデックスに等しい追加の外観を取得します。 

答えは非常に大きくなる可能性があります。 と$3 \cdot 10^5$最大サイズの要素$10^6$、結果は 32 ビット整数の範囲をはるかに超えています。 Python の整数はこれを自動的に処理します。 

この実装では、接尾辞の合計の構築や分割のシミュレーションが回避されます。 ソリューション全体は、並べ替えと 1 つの直線パスだけです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

| スペース | O(1) 追加 (並べ替えを除く) | 少数の変数のみが使用されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    def input():
        return sys.stdin.readline()

    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    total = sum(a)
    ans = total

    suffix = total
    for i in range(n - 1):
        suffix -= a[i]
        ans += suffix

    return str(ans) + "\n"

# provided sample
assert run("3\n3 1 5\n") == "26\n", "sample 1"

# minimum size
assert run("1\n7\n") == "7\n", "single element"

# two elements
assert run("2\n1 10\n") == "22\n", "basic split"

# all equal
assert run("4\n5 5 5 5\n") == "50\n", "all equal values"

# increasing sequence
assert run("3\n1 2 100\n") == "306\n", "large value should stay longest"

# off-by-one check
assert run("3\n1 1 1\n") == "8\n", "small uniform case"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 単一要素の場合を考えてみましょう。 

入力```
1
7
```ソートされた配列はまだ残っています`[7]`。 合計は 7 です。分割するものがないため、サフィックス処理は行われません。 アルゴリズムは 7 を出力します。これは、可能な唯一のスコアと一致します。 

次の 2 つの要素を考えてみましょう。 

入力```
2
1 10
```ソートされた配列:`[1, 10]`。 

最初のグループは 11 を寄与します。最小の要素を削除した後、接尾辞の合計 10 が再び寄与します。 最後に、シングルトン グループは 1 と 10 を提供します。アルゴリズムのサフィックス合計の定式化により、正確に 22 が生成されます。 

繰り返される値を考慮してください。 

入力```
4
5 5 5 5
```ソート順は変更されません。 すべての値が同一であるため、すべての分割は事実上同等です。 アルゴリズムは、値の複数セットとそれらの並べ替えられた位置のみに依存するため、依然として正しい答えを計算します。 

非常に不均衡な配列を考えてみましょう。 

入力```
3
1 2 100
```最適な戦略は、最後まで残り最大のグループ内に 100 人を維持します。 サフィックスの合計は 103、102、および 100 です。シングルトンの寄与を加算すると 306 になります。アルゴリズムは、最大の係数を最大の値に割り当てることで、この動作を正確に再現します。
