 ## 解決策
 ## 問題の理解

 私たちには、周期的に配置された部屋のシステムが与えられています。`0`に`n-1`。 各部屋には 1 つの整数があります`a[i]`円形の文字盤に表示されます。 部屋から`i`, ボボには 2 つのアクションがあり、それぞれに正確に 1 単位の時間がかかります。 

彼は部屋でダイヤルを回すことができます`i`時計回りに増加します`a[i]`または、すぐに部屋にテレポートできます`(i + a[i]) mod n`、ダイヤルの現在の値をジャンプ長として使用します。 

ボボは部屋からスタート`0`そして部屋に着きたい`x`最小の合計時間で。 

重要な点は、配列が`a[i]`は固定されていません。 部屋のテレポートを使用することを決定するたびに、事前にその値を増やすのに時間を費やした可能性があり、その変更された値はその部屋を将来使用するために保持されます。 

したがって、問題は固定エッジ上の最短パスだけではありません。 これは、ノードからのエッジの重みが、ノードを使用する前にそのノードをインクリメントした回数に依存する最短パスです。 

制約により、最大で次のことが許可されます。`n = 100000`これにより、すべての状態をシミュレートしようとするソリューションは即座に除外されます。`(room, value of all a[i])`。 完全なグローバル状態を保存することすら不可能です。 ソリューションでは、インクリメントをグローバル状態空間の一部として扱うことを避ける必要があります。 

いくつかの特殊なケースでは、単純な推論の失敗が明らかになります。 もし`a[i] = 0`みんなのために`i`, テレポートは最初にインクリメントしない限り何も行わないため、有用な移動にはステップごとに少なくとも 1 つのインクリメントを支払う必要があります。 もしすべてなら`a[i]`すでに大きくなり、`x`、最適な答えは、増分をまったく行わずにほんの数回のテレポートである可能性があります。 もう 1 つの厄介な状況は、1 つの部屋を複数回使用する前に繰り返し増加させることで、増加分が永続的で再利用可能であるため、長期的なルーティングが向上する場合に発生します。 

## アプローチ

 直接のブルート フォース ビューでは、アレイの各構成を状態として扱います。 状態から、任意のインデックスをインクリメントするか、現在の部屋からテレポートすることができます。 これは爆発につながります。増分ごとにグローバル状態が変化し、それぞれの`a[i]`任意に大きくなる可能性があります。 偶数制限値のモジュロ`n`まだ残っています`n^n`可能な状態ですが、まったく実行不可能です。 

より構造化されたブルート フォース アプローチは、各ノードが存在する展開されたグラフ上で最短パスをシミュレートすることです。`(current room, full array state)`。 それはまだ指数関数的であり、使用できません。 

重要な点は、増分の履歴を完全に追跡する必要がないということです。 重要なのは、次のテレポート使用前に各部屋が何回インクリメントされるかだけです。 各増分はローカルで部屋全体で独立しており、ある値で部屋を使用することに決めたら、特定の実効オフセットを達成できる最適な時間だけを気にするようになります。 

固定部屋の場合`i`、その後に使用することにした場合`k`増加すると、その部屋で支払われる費用は正確に`k + 1`(k の増分と 1 つのテレポート)、遷移は次のようになります。`(i + a[i] + k) mod n`。 これは、各部屋が、増加するコストを伴う無限の連続した出力エッジを生成し、単調な構造を形成することを意味します。 

この構造により、各ノードが増加するコスト増分を持つ一連の出ていくエッジを持つグラフ上の最短パスとして問題を扱うことができます。 各部屋を遅延処理することができ、必要に応じて次の未使用の増分レベルを常に考慮します。 これは、状態に対するダイクストラのような処理で自然に処理されます。`(room, how many times we have used this room as a source)`完全な配列状態を明示的に保存せずに。 

私たちは常に、利用可能な最も安価な「次のテレポートの使用」をすべての部屋にわたって拡張します。これにより、部屋ごとのコスト増加が単調であるため、最適性が保証されます。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各部屋をモデル化します`i`使用前にそれを増やした回数によってインデックス付けされた、可能なテレポートアクションのシーケンスを持つものとして。 それを使うと、`k`- 回目の費用`k + 1`その部屋の使用に対するアクションの合計、そして私たちを次の場所に移動させます`(i + a[i] + k) mod n`。 

次に、部屋全体で最短パス プロセスを実行しますが、部屋ごとに 1 つのエッジを持つのではなく、各部屋からより優れたエッジを遅延生成します。 

1. 距離配列を初期化する`dist`サイズの`n`無限大と設定`dist[0] = 0`部屋から始めるから`0`。 
2.各部屋ごとに`i`、ポインタを維持します`used[i] = 0`以前の拡張でその部屋に対してすでに「消費」した増分数を表します。 これにより、同じ増分レベルを 2 回再検討することがなくなります。 
3.プッシュ`(0, 0)`優先キューに入れられ、部屋にいることを表します`0`コストゼロで。 
4.状態を繰り返し抽出する`(d, i)`キューからの距離が最小です。 もし`d`に等しくありません`dist[i]`、古いので飛ばしてください。 
5. 部屋から`i`、現在の増分レベルで次に利用可能なテレポートの使用法を検討します。`used[i]`。 使用にかかる費用は、`d + used[i] + 1`、そして目的地は`(i + a[i] + used[i]) mod n`。 
6. この新たなコストが改善されれば`dist[j]`、 どこ`j`目的の部屋です、更新します`dist[j]`そしてそれを優先キューにプッシュします。 
7. インクリメント`used[i]`次回部屋を拡張するときから 1 つずつ`i`、テレポートの次の増分バージョンを検討します。 
8. 優先キューが空になるまで続行します。 

このアルゴリズムは常に、可能な限り安価な次のテレポートの使用をすべての部屋に拡大し、各部屋を再度使用するコストを段階的に増加させます。 

### なぜ効果があるのか

 各部屋は、可能なテレポート アクションの厳密に増加するシーケンスを生成します。その部屋からの k 番目のアクションのコストは、常に前のアクションよりも正確に 1 増加します。 この単調性により、部屋の k 番目の使用を検討した後は、同じレベルの将来の使用が後で安くなることはないことが保証されます。 

優先キューにより、世界で最も安価な利用可能なアクションが常に次に処理されるようになります。 これは、各部屋にコストでソートされた出力エッジの無限チェーンがある暗黙的に展開されたグラフでダイクストラを実行することと同等です。 部屋ごとのエッジ コストは単調であり、各レベルは 1 回だけ処理されるため、最適なパスがスキップされたり、誤って遅延されたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    INF = 10**18
    dist = [INF] * n
    dist[0] = 0

    used = [0] * n
    pq = [(0, 0)]

    while pq:
        d, i = heapq.heappop(pq)
        if d != dist[i]:
            continue
        if i == x:
            print(d)
            return

        k = used[i]
        used[i] += 1

        j = (i + a[i] + k) % n
        nd = d + k + 1

        if nd < dist[j]:
            dist[j] = nd
            heapq.heappush(pq, (nd, j))

solve()
```この実装では標準のダイクストラ フレームワークが使用されますが、各ノードはすべての出力エッジを一度に公開するわけではありません。 代わりに、各ルームは、優先キューからポップされるたびに、1 つの新しい発信遷移を明らかにします。 

の`used[i]`配列は必須です。 これがないと、同一の遷移が繰り返し再生成され、処理が無限または重複することになります。 ルームの各増分レベルが 1 回だけ消費されることが強制されます。 

終了チェック`if i == x`ダイクストラは、最初に目的地をポップするときに最小限のコストで目的地に到達することを保証しているため、安全です。

 ## 特殊なケース

 重要なエッジケースは、次のような場合です。`a[i]`はゼロです。 この状況では、すべてのテレポートは最初に同じ部屋にループバックするため、進行状況は移動前の増分の蓄積に完全に依存します。 アルゴリズムは、同じ部屋を繰り返し拡張し、増加させることでこれを処理します。`used[i]`そのたびに、有効な目的地は徐々に変化し、最終的には新しい部屋に到達します。 

もう 1 つのケースは、単一の増分によって無駄なトランジションが直接のショートカットに変換される場合です。`x`。 各部屋は小さい順に拡張されているため、`k`、有益な増分レベルに初めて到達すると、そのレベルが検出され、正しいコストでキューにプッシュされ、後でより高価なバージョンで上書きされることがなくなります。 

最後の微妙なケースは、複数の部屋が異なる増分コストで同じ目的地に到達できる場合に発生します。 プライオリティ キューは、最小のコストのみが生き残ることを保証します。`dist`一方、冗長でより大きなコストの到着はポップ時に無視され、状態が大量に重複している場合でも正確性が維持されます。
