 ## 解決策
 ## 問題の理解

 一列に配置された位置に対するパリティ制約のシステムが与えられています。 各制約は 2 つのプレフィックス位置間のパリティ関係を記述し、通常は 2 つのインデックス間の「アクティブな」要素の数が偶数か奇数かを表します。 タスクは、これらの制約を順番に処理し、以前の制約と論理的に矛盾する最初の点を検出することです。 

問題を再構成する有効な方法は、プレフィックス パリティの観点から考えることです。 各位置が 0 または 1 のいずれかに寄与するが、その値がわからない配列を想像してください。 代わりに、セグメントの合計が偶数であるか奇数であるかに関するステートメントのみを受け取ります。 各ステートメントは、2 を法とする 2 つのプレフィックス合計の差を制限します。 

出力は配列の最終構成ではなく、入力シーケンス内で矛盾が現れた最初のインデックスです。 すべての制約を同時に満たすことができた場合、成功と報告されます。 

制約サイズでは、最大 10^5 ステートメントが推奨されます。 割り当てを明示的に再構築したり、以前のすべての制約にわたる一貫性を繰り返し再計算しようとしたソリューションは、二次関数の動作に低下して失敗します。 これにより、パス圧縮を伴う素集合共用体構造など、ほぼ一定時間の制約マージを伴う線形に近い構造がすぐに得られます。 

制約がサイクルを形成する場合、微妙なエッジケースが発生します。 たとえば、A から B までが偶数であり、B から C までが偶数であることがすでにわかっているが、新しい制約によって A から C が奇数であると主張されるとします。 ローカルでは各ステートメントは有効ですが、グローバルでは矛盾します。 推移的パリティを追跡せずにペアごとの関係のみをチェックする単純な実装では、この矛盾を見落としてしまいます。 インデックスが累積されたパリティ オフセットを持つ連結コンポーネントとしてではなく独立して扱われる場合、別の障害モードが発生します。 

## アプローチ

 ブルート フォース アプローチでは、各ノードがプレフィックス インデックスを表し、各制約がパリティ 0 または 1 のラベルが付いたエッジを追加するグラフを維持します。一貫性を保つために、新しいエッジが追加されるたびに、構造全体に対して BFS または DFS を使用してパリティ関係を再計算しようとします。 各チェックは、最悪の場合、以前に追加されたすべての制約に触れる可能性があり、制約が密な場合は 2 次またはそれ以上の複雑さになります。 

すべての制約は単にグラフ内の関係を強制するだけであり、一貫性はサイクル内の矛盾の検出に帰着するため、これは概念的に機能します。 ただし、挿入のたびに到達可能性とパリティを最初から再計算するのはコストがかかりすぎます。 

重要な観察は、完全な再計算は決して必要ないということです。 必要なのは、接続された各コンポーネント内の接続性と相対的なパリティを維持することだけです。 これはまさに、ノードから親へのパリティ オフセットを追加した場合に、素セット共用体構造が格納できるものです。 2 つのノードが統合されると、新しい制約が適用されるようにそれらのパリティ関係を調整できます。 それらがすでに接続されている場合は、暗黙のパリティが既存のパリティと一致するかどうかのみがチェックされます。 

これにより、各結合または検索操作が逆アッカーマンであるため、各制約がほぼ一定の時間で償却されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースグラフ再計算 | O(q・(n+q)) | O(n+q) | 遅すぎる |
 | パリティ付き DSU | O(q α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各プレフィックスの位置を、素のセット共用体構造内のノードとしてモデル化します。 さらに、パリティ値を保存します`dist[x]`ノード間のパリティを表す`x`とその親。 

制約を 1 つずつ処理し、制約ごとに次の手順を実行します。 

1. 制約を 2 つのノード間の関係に変換します。`u`そして`v`、必要なパリティ付き`w`。 これは、ステートメントをプレフィックス パリティ間の差異として解釈することに由来します。 
2. のルートを見つけます。`u`同時にパリティを計算します`u`その根元まで。 私たちも同じことをします`v`。 このステップによりパスが圧縮され、今後のクエリが確実に高速化されます。 
3. のルーツがある場合`u`そして`v`異なる場合は、2 つのコンポーネントをマージします。 1 つのルートをもう 1 つのルートの下に接続し、制約を維持するためにパリティ値を割り当てます。`dist[u] XOR dist[v] = w`。 これにより、新しいエッジが両方のコンポーネント内の以前に知られていたすべての関係と確実に一致します。 
4. ルートがすでに同じである場合、それらの間の既存のパリティ関係が確認されます。`u`そして`v`マッチ`w`。 一致しない場合は、矛盾が検出されたことになり、現在のインデックスが返されます。 
5. すべての制約が処理されるか、矛盾が見つかるまで処理を続けます。 

この構造が機能する理由は、各接続コンポーネントが任意のグローバル フリップまでパリティ値の一貫した割り当てを維持するためです。 の`dist`配列は相対パリティをエンコードするため、すべてのノードはコンポーネントのルートを基準とした相対的な値を認識します。 When merging two components, we only need to ensure that the new constraint is satisfied at the point of union, after which all transitive constraints remain consistent automatically.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n
        self.parity = [0] * n  # parity to parent

    def find(self, x):
        if self.parent[x] != x:
            p = self.parent[x]
            self.parent[x] = self.find(p)
            self.parity[x] ^= self.parity[p]
        return self.parent[x]

    def get_parity(self, x):
        self.find(x)
        return self.parity[x]

    def union(self, x, y, w):
        rx = self.find(x)
        ry = self.find(y)
        px = self.get_parity(x)
        py = self.get_parity(y)

        if rx == ry:
            return (px ^ py) == w

        if self.rank[rx] < self.rank[ry]:
            rx, ry = ry, rx
            px, py = py, px

        self.parent[ry] = rx
        self.parity[ry] = px ^ py ^ w

        if self.rank[rx] == self.rank[ry]:
            self.rank[rx] += 1

        return True

def solve():
    q = int(input().strip())
    dsu = DSU(2 * q + 5)

    # map original positions to prefix nodes if needed
    # (classic formulation uses prefix indices directly)
    offset = q + 2

    for i in range(q):
        l, r, w = input().split()
        l = int(l)
        r = int(r)

        # parity of segment [l, r] becomes prefix relation
        u = l - 1
        v = r
        w = 0 if w == "even" else 1

        if not dsu.union(u, v, w):
            print(i)
            return

    print(q)

if __name__ == "__main__":
    solve()
```DSU は、構造とパリティの両方の一貫性を維持します。 の`find`この関数はパス圧縮を実行すると同時にパリティを更新し、各ノードがルートを基準にしてパリティを直接保存するようにします。 の`union`この関数はまず現在のパリティ関係を抽出し、次に両方のノードがすでに接続されているかどうか整合性を検証するか、接続されたルートのパリティを修正してコンポーネントをマージします。 

実装の微妙な詳細は、パス圧縮中のパリティの処理です。 後続のクエリの一貫性を保つために、ルートを返す前に XOR の蓄積を行う必要があります。 もう 1 つの重要な点は、ランクごとにコンポーネントを交換することです。 これがないと、敵対的な場合に再帰の深さとパフォーマンスが低下する可能性があります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、制約が同じ位置を 2 回参照し、実質的に長さ 0 のセグメントに条件を課す場合です。 プレフィックス形式では、これはそれ自体に接続されたノードになります。 両方のエンドポイントが同じルートを共有しているため、DSU はこれをすぐに検出します。 パリティ チェックでは、必要なパリティがゼロであることを検証する必要があります。そうでない場合は、直ちに矛盾が発生します。 

もう 1 つのケースは、ルート間に直接制約が追加される前に、複数の制約が中間ノードを介して 2 つのコンポーネントを徐々に接続する場合です。 このアルゴリズムはパスを明示的に再計算しません。 代わりに、パス圧縮により、最終制約がチェックされるときに、両方のノードがルートに対する累積パリティを反映することが保証されます。 矛盾は、矛盾した XOR 条件が評価された瞬間に正確に捕捉されます。 

最後の微妙なケースには、パス圧縮とランクによる結合がないと再帰の深さが大きくなる可能性がある結合の長いチェーンが含まれます。 実装では、常に小さいランク ツリーを大きいランク ツリーの下に接続し、検索操作中にパスを平坦化することでこれを回避し、敵対的なシーケンスであっても効率的かつ安定した状態を維持できるようにします。
