 ## 解決策
 ## 問題の理解

 有向非巡回グラフの同じ頂点セットの 2 つの順列が与えられます。 それらの 1 つは、未知の DAG の辞書編集上最小のトポロジー的順序付けであり、もう 1 つは、同じ DAG の辞書編集上最大のトポロジー的順序付けです。 タスクは、そのような DAG が存在できるかどうかを判断し、存在する場合は両方の順序に一致する DAG を構築することです。 

トポロジカルな順序付けではエッジの方向が考慮されます。つまり、すべての有向エッジは順序付けにおいて前の頂点から後の頂点に進む必要があります。 辞書編集上の最小のトポロジー順序は、貪欲な構築の各ステップで、利用可能な最小の頂点を優先する順序です。 辞書編集的に最大のものは、代わりに利用可能な最大の頂点を優先します。 

重要な問題は、グラフ構造が与えられておらず、その 2 つの極端なトポロジカル ソートだけが与えられているということです。 これら 2 つの貪欲な動作を正確に強制する一連の制約 (エッジ) をリバース エンジニアリングする必要があります。 

この制約では、最大 100,000 個の頂点と最大 1,000,000 個のエッジが許可されます。 したがって、どのソリューションも基本的に線形時間または線形に近い時間で実行する必要があります。 n の 2 次関数や、隣接行列上の重い定数を伴う n log n でさえも実行不可能です。 完全な DAG には制限をはるかに超える O(n²) 個のエッジが含まれるため、構築も疎である必要があります。 

素朴な誤解は、任意の順序付け A と B は、前の A から後の A にエッジを追加することによって接続できると考えることですが、これはトポロジカル ソートの辞書編集上の最小性と最大性というグローバルな制約を無視しています。 たとえば、A と B が大きく一致しない場合、両方を極トポロジー次数として認める DAG は存在しない可能性があります。 もう 1 つの微妙な障害モードは、一貫性を保証せずにエッジが A または B から独立して導出される可能性があると仮定することです。 

具体的なエッジ ケースは、A が B に等しい場合です。その場合、グラフはトポロジー順序が 1 つだけ存在するようなものでなければなりません。 これには完全な順序制約構造が必要ですが、それでもエッジ制限に違反してはなりません。 もう 1 つのケースは、A が B の逆である場合です。これは実現可能です。空の DAG の辞書編集上の最小および最大のトポロジカル ソートはいずれも任意の置換になる可能性があるため、これは空のグラフに対応しますが、タイ ブレークによって一貫して許可される場合に限ります。 ただし、A と B が異なるため、矛盾する優先順位制約が強制される場合、DAG は存在しません。 

## アプローチ

 ブルートフォースの観点は、考えられるすべての DAG を再構築し、A が辞書編集的に最小の位相ソートであり、B が最大であるかどうかをチェックすることを想像することです。 これには、n 個の頂点間のエッジ サブセットを列挙する必要がありますが、これは n(n−1)/2 の可能性で指数関数的になります。 単一のグラフを検証する場合でも、辞書編集的に極端なトポロジカル ソート (O(n + m)) を両方計算する必要がありますが、候補グラフの数によりこれは不可能になります。 

重要な洞察は、任意の DAG の観点から考えるのをやめ、代わりに頂点のペア間にどのような制約を適用する必要があるかに焦点を当てることです。 どの DAG においても、辞書編集上最小のトポロジカル順序 A では頂点 u が v より前に出現するが、B では v が u より前に出現する場合、両極端を調和させる唯一の方法は、すべての有効なトポロジカル ソートでどちらか一方を回避できないようにする有向依存関係を強制することです。 これは、エッジが A と B の相対的な順序から導出される必要があることを示唆しています。 

より正確には、A と B を 2 つの優先システムを定義するものとして扱います。 A は小さい優先の実現可能性を望み、B は大きい優先の実現可能性を望んでいます。 両極端を強制できる唯一の構造は、A と B の間で順序が一致しない頂点のすべてのペアを拘束する必要がある一貫した部分順序です。

これは中心的な構築につながります。u が A では v の前で、B では v の後に現れる場合に、エッジ u → v が追加されるグラフを構築します。これらはまさに、2 つの極端な貪欲動作間で相対順序が一致しないペアであるため、グラフによって修正する必要があります。 これらのエッジが追加されたら、結果の制約によってサイクルが生成されるかどうかを確認します。 循環とはAとBの間の矛盾を意味します。 

この構築が機能するのは、辞書編集的に最小の位相ソートが、先行要素がすでに削除されている最小の頂点を繰り返し選択することと同等であり、最大の頂点についても同様であるためです。 両方のプロセスが正確に A と B を生成できる唯一の方法は、すべての強制反転がエッジとしてエンコードされる場合です。

 ## アルゴリズムのチュートリアル

 1. 位置配列 posA と posB を構築して、任意の 2 つの頂点の相対順序を一定時間で比較できるようにします。 これにより、順序の競合を効率的に検出できるようになります。 
2. すべての頂点のペア (u, v) について、A では u が v より前に来ているか、B では v が u より前にあるかどうかを概念的にチェックします。そうであれば、有向エッジ u → v を追加します。これにより、2 つの極端な順序間の一貫性が強制されます。 
3. すべてのペアを明示的に反復することはありません。それは O(n²) になるためです。 代わりに、2 つの順序をマージすることによって引き起こされる隣接する制約のみを考慮する必要があることがわかります。これは、一方の順序で頂点をソートし、もう一方の順序で相対位置を処理することで実装できます。 
4. エッジ セットを構築した後、結果のグラフが非巡回であることを確認します。 これは、標準のトポロジー ソートまたは次数 BFS を使用して行われます。 サイクルが存在する場合、有効な DAG は A と B の両方を生成できません。 
5. グラフが非循環の場合は、それを出力します。 各頂点ペアが最大 1 つの有向制約に寄与し、必要なエッジのみが含まれるため、エッジの数は自動的に制限されます。 

機能する理由: 有効な DAG は両方の極端な貪欲プロセスを尊重する必要があります。 A と B がペア (u、v) に関して一致しない場合は常に、両方の極値特性を保持するすべての位相ソートで少なくとも 1 つの方向を禁止する必要があります。 構築されたエッジは、強制された決定を正確にエンコードします。 サイクルが表示されない場合、部分順序は一貫しており、極限トポロジー ソートが A と B に一致する DAG を少なくとも 1 つ許可します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))
    
    posA = [0] * (n + 1)
    posB = [0] * (n + 1)
    
    for i, x in enumerate(A):
        posA[x] = i
    for i, x in enumerate(B):
        posB[x] = i

    # collect vertices sorted by A
    vertices = list(range(1, n + 1))
    vertices.sort(key=lambda x: posA[x])

    adj = [[] for _ in range(n + 1)]
    indeg = [0] * (n + 1)
    edges = []

    # we use sweep idea: maintain structure by comparing order in B
    # add edge when relative order is reversed between A and B
    import bisect
    order = []

    for u in vertices:
        # maintain increasing order by B position
        # find all elements that should point to u
        i = bisect.bisect_left(order, (posB[u], u))
        # all elements after i must come after u in B but before in A => no edge needed
        # elements before i are consistent; we only connect necessary constraints
        for j in range(i):
            v = order[j][1]
            adj[v].append(u)
            indeg[u] += 1
        order.insert(i, (posB[u], u))

    # check DAG
    from collections import deque
    dq = deque([i for i in range(1, n + 1) if indeg[i] == 0])
    topo = []

    while dq:
        u = dq.popleft()
        topo.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                dq.append(v)

    if len(topo) != n:
        print("No")
        return

    print("Yes")
    print(len(edges))
    for u in range(1, n + 1):
        for v in adj[u]:
            print(u, v)

if __name__ == "__main__":
    solve()
```この構築では、B で順序付けされたバランスの取れた構造を維持しながら、A でソートされた頂点のスイープを使用します。各挿入では、B の以前の要素が A で後から現れるときに現在の頂点を指す必要があり、これにより反転制約が正確に捕捉されます。 

サイクル検出ステップにより、矛盾する順序付け制約が導入されていないことが保証されます。 矛盾が存在する場合、BFS はすべてのノードを訪問しません。 

微妙な実装の詳細は、エッジが別のリストに保存されないことです。 代わりに、隣接リストから直接出力されます。 これにより、構築と出力の間の同期エラーが回避されます。

 ## 特殊なケース

 重要なエッジケースは、A と B の両方が同一である場合です。 その状況では、反転が存在しないため、アルゴリズムはエッジを作成しません。 結果のグラフは空で、辞書編集上の最小および最大のトポロジカル ソートはいずれも自明のことですが A です。構築は有効なままです。 

もう 1 つのケースは、A と B が 1 回のスワップだけ異なる場合です。 このアルゴリズムは、交換された要素間に制約エッジを 1 つだけ導入し、有向依存関係を強制します。 これにより、両方の貪欲なプロセスが、反対ではあるが一貫した方法で曖昧さを解決することが保証されます。 

最後のケースは、A と B が完全に逆転した場合です。 構築に使用される特定のタイプの反転は発生しないため、エッジは作成されません。 これは、すべての順列が有効なトポロジカル ソートであり、両方の極限要件に一致する空のグラフに対応します。
