 ## 解決策
 ## 問題の理解

 1 から n のラベルが付いた頂点にルート付きツリーが与えられます。ここで、ルートを除くすべてのノードには、より小さいインデックスの親を指す出力エッジが 1 つだけあります。 この方向により、すべての頂点にルートへの一意のパスが設定されます。 

n 人のドライバーが次々と到着します。 各ドライバーは優先頂点 si から開始します。 その頂点が空いている場合、それらはそれを占有します。 それ以外の場合は、最初の空いている頂点を見つけてそこに駐車するまで、親ポインターに沿って上に移動します。 ルートへのパス全体がすでに占有されている場合、ドライバーは失敗します。 

すべてのドライバーがこのルールに従って自由な頂点を見つけることに成功した場合、シーケンスは有効であると呼ばれます。 このタスクは、長さ n の有効なシーケンスがいくつあるか (998244353 を法として) カウントすることです。 

入力ツリーは任意ではありません。 これは、各 i が前の頂点に均一に付加される、非常に特殊な増加ラベル形式で生成されます。 これにより、構造はランダムな再帰ツリーになりますが、この問題では 1 つの固定された実現が与えられ、それに対する答えを計算する必要があります。 

n が 100000 までの制約により、シーケンスを明示的にシミュレートしようとするアプローチから遠ざけられます。 単一シーケンスの単純なシミュレーションには O(n) のコストがかかり、n^n 個のシーケンスが存在しますが、これは完全に実行不可能です。 頂点のサブセットに対する動的プログラミングでも 2^n 状態が含まれることになりますが、これも不可能です。 

さらに微妙な問題は、駐車が順序に左右されることです。 小さなツリーの場合でも、初期ドライバーを交換すると、可用性パターンが大幅に変わる可能性があります。 たとえば、ツリーが 1 ← 2 ← 3 のチェーンである場合、(3,3,3) と (1,2,3) のようなシーケンスはまったく異なる動作をし、単純な対称性の仮定はすぐに崩れます。 

隠れた重要な問題は、各ドライバーの最終位置が開始ノードの最初の空の祖先にのみ依存することです。そのため、このプロセスは、ばらばらのパスで利用可能な最も高い祖先を繰り返し要求するのと同じであり、シミュレーションではなく構造的なカウント アプローチを示唆しています。 

## アプローチ

 直接的な総当たりアプローチでは、優先頂点の n 長シーケンスをすべて列挙します。 各シーケンスについて、O(n) で駐車プロセスをシミュレートし、占有されている頂点をマークし、空いている頂点が見つかるまで上方に歩きます。 これにはすでにシーケンスごとに O(n) のコストがかかり、n^n 個のシーケンスがあるため、総作業量は天文学的に大きくなります。 

順列に注意を限定したり、対称性を利用しようとしても、それぞれの職業がルート パス全体に沿って可用性を変えるため、選択肢間の依存関係はグローバルなままです。 ボトルネックは、各シミュレーションが親ポインターを介して上向きに繰り返し歩き、同じ構造が何度も再訪されることです。 

重要な観察は、視点を逆転させることです。 ドライバーを優先頂点に割り当てる代わりに、シーケンスが特定の最終占有パターンを実現できる方法が何通りあるかを考えることができます。 パーキング プロセスは常に、すべての頂点が 1 回だけ占有された状態で終了し、最終状態は常に、祖先制約と一致する方法で満たされた頂点の順列になります。 

これは、各頂点が可能な開始位置のセグメントに対する責任を「主張」する、増加するフォレスト構造を構築するプロセスとして見ることを示唆しています。 ツリーの向きにより、各頂点が最初に利用可能なストップであることをめぐってその祖先とのみ競合することが保証され、サブツリーのサイズを条件付けすると、これらの競合はサブツリー間で独立します。 

重要な単純化は、この特定のランダム再帰ツリーでは、サブツリーのサイズが乗法的に相互作用することです。つまり、すべてのノードがそのサブツリーのサイズにのみ依存する係数に寄与します。 最終的な答えは、サブツリー境界内で最終的に解決されるドライバーの選択肢がいくつ存在するかによって導出される、組み合わせ項の頂点の積になります。

これにより、問題は指数関数的な列挙からサブツリー DP が蓄積する寄与を伴う単一の走査に軽減されます。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n · n^n) | O(n) | 遅すぎる |
 | ツリーDP製品フォーム | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを 1 にルートし、サブツリーのサイズを計算します。 

1. DFS を使用して、すべてのノードのサブツリー サイズを計算します。 ノードのサブツリー サイズは、ノードが祖先として依存する頂点の数を表します。 パスに沿った駐車の決定はすべて、祖先の 1 つのチェーンにのみ影響し、サブツリーのサイズはノードを通過するそのようなチェーンの数を測定するため、これは非常に重要です。 
2. 応答変数を 1 として初期化します。各ノードからの寄与を個別に蓄積します。 
3. ツリーと一致する任意の順序でノードをトラバースします (ポストオーダーが便利です)。 各ノード u について、su をそのサブツリー サイズとします。 答えにsuを掛けます。 この要素が現れるのは、サブツリーを分離して考える場合、そのサブツリーの構造内で「最後に埋められていない選択境界」を割り当てる方法がいくつかあるためです。 
4. 最終積のモジュロ 998244353 を出力します。 

アルゴリズムは一見単純です。各ノードは、そのサブツリーが競合せずに入力される優先チェーンを吸収できる方法の数に等しい乗法自由度を効果的に寄与するため、すべてがサブツリー サイズの積に折りたたまれます。 

### なぜ効果があるのか

 駐車プロセスでは、解決頂点が特定の祖先パス上にあるグループへのドライバーの分割が行われます。 上位の祖先が修正されると、各サブツリーは独立したシステムのように動作します。これは、サブツリーの外で開始されるドライバーは、そのサブツリーのルートを経由せずにそのサブツリーにスキップすることができず、そのルートが占有されるかどうかに関係なく、サブツリーの内部構造が独立して進化するためです。 

この独立性は、有効なシーケンスの総数がノードにわたって因数分解されることを意味します。 各ノードは、サブツリー内に到着を「固定」する方法の数に正確に等しい多重度を提供します。これは、まさにそのサブツリーのサイズです。 すべての割り当ての選択はサブツリー境界に対してローカルであり、互いに素な領域に干渉しないため、ノード間の乗算により正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(200000)

def solve():
    n = int(input())
    p = [0] * (n + 1)
    for i in range(2, n + 1):
        p[i] = int(input().split()[0])

    g = [[] for _ in range(n + 1)]
    for i in range(2, n + 1):
        g[p[i]].append(i)

    mod = 998244353

    sz = [0] * (n + 1)

    def dfs(u):
        sz[u] = 1
        for v in g[u]:
            dfs(v)
            sz[u] += sz[v]

    dfs(1)

    ans = 1
    for i in range(1, n + 1):
        ans = (ans * sz[i]) % mod

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、まず親ポインターからルート付きツリーを再構築します。 DFS はサブツリーのサイズを線形時間で計算します。 最後のループは、指定された素数を法とするすべてのサブツリー サイズを乗算します。 

n は 100000 に達する可能性があるため、実装の重要な詳細は再帰の深さです。再帰の制限を増やすと、スタックのオーバーフローが回避されます。 オーバーフローを防ぐために、乗算ステップは反復ごとに 998244353 を法として実行する必要があります。 

## 実用的な例

 ### 例 1

 入力:```
3
1 1
```ツリー構造は、1 をルートとして子 2 と 3 を持つスターです。 

| ノード | サブツリーのサイズ | 回答への貢献 |
 | --- | --- | --- |
 | 1 | 3 | 3 |
 | 2 | 1 | 1 |
 | 3 | 1 | 1 |

 答え = 3 × 1 × 1 = 3

 これは、各葉が分岐の選択肢に寄与しない一方で、根がすべての構造的柔軟性を獲得していることを示しています。 

### 例 2

 入力:```
3
1 2
```これは 1 ← 2 ← 3 のチェーンです。 

| ノード | サブツリーのサイズ | 貢献 |
 | --- | --- | --- |
 | 1 | 3 | 3 |
 | 2 | 2 | 2 |
 | 3 | 1 | 1 |

 答え = 3 × 2 × 1 = 6

 これは、サブツリーのサイズが各祖先レベルを介して「バブルアップ」できるドライバーの数をエンコードするため、チェーンが深くなると中間ノードでの組み合わせの自由度がいかに高まるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ノードは DFS で 1 回、最終集約で 1 回アクセスされます。 
| スペース | O(n) | 隣接リストと再帰スタックはツリーを格納します。 

線形複雑度は制約 n ≤ 100000 に快適に一致し、最悪の場合のチェーン形状ツリーでも時間とメモリの両方が十分に制限内に収まります。

 ## 特殊なケース

 単一のチェーンは、サブツリー乗算が深度効果を正しく蓄積するかどうかを明らかにします。 1 <- 2 <- 3 <- 4 のようなチェーンの場合、サブツリーのサイズは 4、3、2、1 で、積は 24 になります。DFS はこれらのサイズを正しく計算します。これは、すべてのノードが上向きのパスを 1 つだけ提供し、再帰によって二重にカウントすることなく自然に累積されるためです。 

星型のツリーは、兄弟の独立性が保たれているかどうかを強調します。 ルート 1 とその他すべてを子として、サブツリーのサイズはルートが n、すべてのリーフが 1 となり、答え n が生成されます。 DFS は、再帰によって子のサイズがノードごとに 1 回だけ親に集約されるため、各リーフが独自のサブツリー内で分離され、兄弟からの寄与が誤って蓄積されないようにします。
