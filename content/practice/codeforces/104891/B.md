 ## 解決策
 ## 問題の理解

 制約の小さなコレクションが与えられ、それぞれが等価または厳密な不等号を使用して 2 つの文字列を比較します。 各文字列は通常の意味での数値ではなく、各文字が数字または大文字の英字である 10 進数の数値です。 すべての文字は 0 から 9 までの数字を表し、同じ文字が出現する場所では常に同じ数字にマッピングされる必要があります。 

すべての文字に数字が割り当てられると、すべての文字列は 10 進数の具体的な整数になり、各制約は標準の数値比較になります。 このタスクは、26 文字に数字を何回割り当てるとすべての制約が同時に真になるかを数えることで、答えは 998244353 を法として得られます。 

重要な構造は、制約の数と合計入力サイズが非常に小さいことです。 制約は最大 10 個、全体で最大 50 文字あります。 これにより、制約ごとに割り当てを個別に列挙しようとしたり、文字列に対して大規模な DP 状態を構築しようとしたりするアプローチが即座に排除されます。 本当の困難は制約の数ではなく、比較間での共有文字によって引き起こされるグローバルな結合です。 

単純な試みでは、数字を文字に直接割り当て、すべての制約を評価します。 それは原理的に 10^26 通りの可能性があるため、不可能です。 制約は共有変数を通じてグローバルに相互作用するため、制約ごとに個別に枝刈りを行っても失敗します。 

微妙なエッジケースは、先行ゼロが許可されていることから生じます。 これにより、数値の最初の文字をゼロにすることはできないという通常の制限がなくなり、位置に基づいて代入をプルーニングすることができなくなります。 もう 1 つの問題は、文字列が異なれば長さが異なる可能性があるため、正規化を行わないと辞書編集的な直感が直接適用できないことです。 

たとえば、次のような制約`A > 99B`B に一貫した割り当てがない限り、長さを比較してローカルに決定することはできません。同様に、`AB = BA`A と B を強制的に同じ数字にするわけではありません。 重み付けされた数値を制限するだけです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。各文字に 0 から 9 までの数字を割り当て、すべての制約を評価します。 これには 10^26 の割り当てをチェックする必要があり、各チェックのコストは O (制約の合計の長さ) であり、無視できる程度です。 問題は純粋に組み合わせ爆発です。 

重要な観察は、実際に表示される文字のみが重要であるということです。 全長が最大 50 であるため、個別の文字の数も最大 50 ですが、より重要なのは、各制約が数値の比較であり、位置の重みを構築することで段階的に評価できることです。 完全な割り当ての観点から考える代わりに、部分的な割り当ての観点から考え、十分な構造がわかったらすぐに制約を評価できます。 

このような問題を圧縮する標準的な方法は、各文字を変数として扱い、各文字列を基数 10 の線形形式として解釈することです。文字列 S の場合、その値は digit × 10^k の位置の合計です。 これにより、すべての制約が 10 を底とする変数に対する多項式の不等式に変換されます。 

次に、文字に対してバックトラッキングを実行し、数字を 1 つずつ割り当てます。 重要な最適化は、文字列値を毎回最初から再計算しないことです。 代わりに、各文字列値に対する割り当てられた各文字の増分寄与を維持し、影響を受ける位置のみを更新します。 

制約は最大で 10 個、全長は 50 であるため、各制約に含まれる項はわずか数個だけです。 これにより、DFS 中に制約満足度を迅速に再計算できるようになります。 

ブルートフォースに対する改善点は枝刈りです。残りの変数に関係なく、部分的な代入によって制約を満たすことが不可能になるとすぐに、早期にバックトラックします。 最も大きな異なる桁が割り当てられると、不等式が固定されることが多いため、これは特に強力です。

 | --- | --- | --- | --- |
 | ブルートフォース | O(10^26・50) | お(1) | 遅すぎる |
 | プルーニングを使用した最適な DFS | O(10^k · 枝刈り) ここで、k ≤ 50 | お(50) | 承認済み |

 ## アルゴリズムのチュートリアル

 それぞれの異なる文字を変数として扱います。 k を個別の文字の数とします。 

### 1. 制約を構造化形式に解析する

 各制約をスキャンし、両側を項のリストに変換します。各項はペア (文字または数字、位置の重み) です。 数字は固定値に寄与します。 文字は、その位置に応じて 10 のべき乗を乗じた変数に寄与します。 

この表現により、最初から再計算することなく、部分的に割り当てられた文字列を評価できます。 

### 2. 各側の係数マップを構築する

 制約ごとに、文字からその文字列内の合計係数寄与へのマッピングと、数字からの定数オフセットを維持します。 

これにより、すべての制約が次のようになります。 

値(X) = 合計(a_i * 数字(文字i)) + 定数_X

 値(Y) = 合計(b_i * 数字(文字i)) + 定数_Y

 ### 3. 変数を特定する

 すべての個別の文字を収集し、0 から k−1 までのインデックスを付けます。 これらは DFS 割り当ての変数です。 

### 4. 深さ優先の数字の割り当て

 数字を文字に再帰的に割り当てます。 各ステップで 1 つの文字を選択し、0 から 9 までの値を試します。 

部分的な代入では、各制約の部分的な評価を維持します。 

既知の文字を置き換え、未知の文字の代わりに象徴的な貢献を保持します。 

### 5. 初期の制約評価

 各制約について、割り当てられていない変数を考慮して、考えられる値の差の下限と上限を計算します。 どの完了でも制約を満たすことができない場合は、プルーニングが行われます。 

これが機能するのは、割り当てられていない残りの文字は、その係数に応じて最大でも制限された範囲に寄与する可能性があるためです。 

### 6. 有効な完了を数える

 すべての文字が割り当てられると、すべての制約が正確に評価されます。 すべて当てはまれば、答えに 1 を加えます。 

### なぜ効果があるのか

どの DFS ノードでも、アルゴリズムは部分マッピングと一致するすべての完全な割り当てのセットを正確に表します。 残りの寄与の境界が正確であるため、枝刈りステップでは有効な補完が削除されることはありません。未割り当てのすべての文字は 0 から 9 まで独立して変化する可能性があるため、計算された間隔にはすべての可能な補完が完全に含まれます。 したがって、不可能な分岐のみがカットされ、有効な割り当てはすべて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input().strip())
    if n == 0:
        print(pow(10, 26, MOD))
        return

    constraints = []
    letters = set()

    def parse_side(s):
        # returns (coeff dict, constant)
        coeff = {}
        const = 0
        n = len(s)
        for i, ch in enumerate(s):
            power = n - i - 1
            if '0' <= ch <= '9':
                const += int(ch) * (10 ** power)
            else:
                letters.add(ch)
                coeff[ch] = coeff.get(ch, 0) + (10 ** power)
        return coeff, const

    for _ in range(n):
        line = input().strip()
        # find operator
        if '=' in line:
            op = '='
        elif '>' in line:
            op = '>'
        else:
            op = '<'

        parts = line.split(op)
        left, right = parts[0], parts[1]

        cl, vl = parse_side(left)
        cr, vr = parse_side(right)

        constraints.append((op, cl, vl, cr, vr))

    letters = list(letters)
    idx = {c: i for i, c in enumerate(letters)}
    k = len(letters)

    def dfs(i, assign):
        if i == k:
            for op, cl, vl, cr, vr in constraints:
                lv = vl
                rv = vr
                for ch, c in cl.items():
                    lv += c * assign[idx[ch]]
                for ch, c in cr.items():
                    rv += c * assign[idx[ch]]
                if op == '=' and lv != rv:
                    return 0
                if op == '>' and not (lv > rv):
                    return 0
                if op == '<' and not (lv < rv):
                    return 0
            return 1

        ans = 0
        for d in range(10):
            assign[i] = d
            ans += dfs(i + 1, assign)
        return ans % MOD

    print(dfs(0, [0] * k) % MOD)

if __name__ == "__main__":
    solve()
```解析ステップでは、各文字列を文字と定数の線形式に変換します。 DFS は、数字を文字に 1 つずつ割り当てます。 すべての文字が割り当てられると、制約が直接チェックされます。 

微妙な点は、数字が 10 のべき乗でスケールされた定数として扱われるため、各辺がすでに数値に正規化されていることです。 再帰では文字列を再度解釈する必要はなく、線形式を評価するだけです。 

このソリューションは意図的にシンプルになっており、高度な枝刈りではなく、少数の制約と文字に依存しています。 

## 実用的な例

 ### サンプル 1

 入力:```
1
P=NP
```ここには P と N という 2 つの文字があります。 

| ステップ | 割り当て済み | P | N | 値(P) | 値(NP) | 制約 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | なし | - | - | - | - | 保留中 |
 | 1 | P=0 | 0 | - | 0 | - | 保留中 |
 | 2 | P=0、N=0..9 | 0 | 0-9 | 0 | 10・0+P | N=0 のみが有効 |

 N=0 の代入のみが等価性を満たしますが、P は自由です。 

有効な割り当ての数は 10^25 mod 998244353 = 766136394 です。 

### サンプル 2

 入力:```
1
2000CNY>3000USD
```| ステップ | 解釈 |
 | --- | --- |
 | 左 | 2000 から始まり、2000·10^3 + CNY 期間 |
 | 右 | 3000 で始まり、3000·10^3 + USD の期間になります。 

すべての文字が 0 に設定されている場合でも、左の最大プレフィックスは右の最小プレフィックスよりも厳密に小さいため、不等式を満たす代入はできません。 

DFS は最終的にすべてのブランチをプルーニングするか、リーフ評価時に拒否して 0 を返します。

 ## 特殊なケース

 重要なエッジケースは、制約がない場合です。 この場合、26 文字のすべての割り当ては有効であるため、答えは 10^26 mod 998244353 です。少なくとも 1 つの制約が存在すると仮定すると、単純な DFS は失敗します。 

もう 1 つの特殊なケースは、次のような矛盾した制約です。`A > A`これにより、すべての割り当てが即座に削除されます。 DFS では、これはリーフ評価時にのみ表示されますが、制約の自己一貫性がチェックされている場合は早期に削除できます。 

3 番目のエッジ ケースは、制約の両側で文字が繰り返される場合です。 例えば`AB = BA`A と B を強制的に同じ数字にするわけではありません。 数値関係を強制します。 両方の出現が同じ割り当て配列から一貫して置換され、構造的な結合が確実に保持されるため、アルゴリズムはこれを正しく処理します。
