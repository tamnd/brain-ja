 ## 解決策
 ## 問題の理解

 構造はツリーです。$n$によって接続された場所$n-1$したがって、任意の 2 つの場所の間には、単純な道が 1 つだけ存在します。 各クエリは、自宅から始める生徒に与えます。$a$そして、彼らのランダムウォークが教室を通過する確率を知りたいと思っています$b$。 

移動ルールは無制限のランダム ウォークではありません。 スチューデントは深さ優先のトラバーサルのように動作し、バックトラックする以外にノードを再訪問することはありません。 現在のノードから、まだ訪問していないすべての隣接する場所の中から均一に選択します。 そのような未訪問の隣人が存在しない場合、彼らは元来た道に沿って戻ります。 これは、各学生が、すでに訪問したノード間を繰り返しさまようのではなく、ランダムに分岐する単一の探索パスを効果的に実行することを意味します。 

出力では数値が要求されます$p$これまでに訪問する確率が$b$等しい$1/p$。 重要な構造上の主張は、この確率は常に整数の逆数に単純化されるため、一般的な分数は追跡しないということです。 

制約$n, q \le 10^5$ツリーのクエリごとのトラバースを除外します。 平$O(n)$クエリごとではすでに遅すぎます。 ソリューションでは、ツリーを 1 回前処理し、通常は最小共通祖先技術を使用して対数時間以上で各クエリに応答する必要があります。 

開始ノードが複数のブランチに隣接している場合、微妙なエッジ ケースが発生します。 素朴な解釈では、すべてのノードが最終的に確率 1 で訪問されると想定するかもしれませんが、プロセスがツリーを完全に探索していないため、これは正しくありません。 各ステップで単一のブランチ選択をコミットし、1 つのブランチを終了した後に未使用のブランチを試すために戻ることはありません。 

たとえば、木が 1 を中心とする星であり、生徒が 1 から開始する場合、生徒はちょうど 1 つの近傍を均等に選択し、葉が出るまでその方向に進み続けます。 彼らは、ルートの他の近隣を探索するために戻ってくることはありません。 単純な DFS 解釈では、すべてのクエリに対して確率 1 と誤って結論付けられてしまいます。 

## アプローチ

 ブルート フォース シミュレーションでは、クエリごとにランダム プロセスが明示的に生成されます。 すべてのノードで、次の未訪問の近隣ノードをランダムに選択し、終了するまで実行し、$b$に遭遇した。 これを何度も繰り返すことで確率を近似することができます。 ただし、各シミュレーションには費用がかかります$O(n)$最悪の場合、$10^5$クエリでは、これは完全に不可能になります。 

重要な観察は、ウォークの構造は決定的であるが、分岐する選択肢の順序だけがランダムであるということです。 各ノードは、学生がそこに到着したときに利用可能な選択肢の数に応じて乗算係数に寄与します。 からの道が終わったら、$a$に$b$が固定されている場合、そのパスを正確にたどる確率は、そのルートに沿った独立した均一な選択の積です。 

これにより、プロセスのシミュレーションから、ツリー内のパスに沿ったローカル分岐因子の積の計算までの問題が軽減されます。 残る唯一の困難は、パスのクエリに効率的に答えることです。 これはまさに、ルート化されたツリー上の最下位共通祖先の前処理とプレフィックス製品によって可能になることです。

 ## アルゴリズムのチュートリアル

 純粋に前処理の便宜のために、ツリーの任意のルート、たとえばノード 1 を修正します。 すべてのノードについて、その深さ、バイナリ リフティング祖先、および親からそのノードに入るときにウォークが持つ選択肢の数を表す値を計算します。 

ノードで$u$、ウォークが親から到着した場合、戻ることはできないため、前方選択の数は次のとおりです。$\deg(u) - 1$。 これを次のように保存します$w[u]$。 一貫性を保つために、引き続き定義します$w[u]$開始ノードの動作が若干異なる場合でも、すべてのノードで同様です。 

次に、バイナリ リフティング テーブルを使用してルートからすべてのノードまでのプレフィックス積を事前計算します。これにより、次の積を迅速に計算できます。$w$任意のパスに沿った値。 

各クエリは次のように処理されます。 

1. 最小共通祖先を計算する$c = \text{LCA}(a, b)$。 これにより、次のパスの一意の交点が得られます。$a$に$b$。 
2. 次の積を計算します。$w[u]$からのパス上のすべてのノードにわたって$a$に$b$。 これは、ルートからノードまでのプレフィックス積を使用し、LCA までの寄与を分割して行われます。 
3. この生の積を実際の確率モデルに一致するように調整します。 未加工の製品では両方のエンドポイントが誤って均一に扱われますが、実際には次のようになります。 

- で$a$、散歩はすべての中から選択します$\deg(a)$隣人ではない$\deg(a)-1$。 
- で$b$に到達して以来、分岐要素を含めるべきではありません。$b$すでにイベントを完了しています。 

そこで、係数を次のように置き換えます。$a$と$\deg(a)$そして、次の要素を削除します$b$。 
4. The final denominator$p$は結果の確率のモジュラー逆数ですが、答えは次のように保証されているため、$1/p$、直接計算します$p$として：$$p = \frac{\text{path product of } w}{w[a]\cdot w[b]} \cdot \deg(a)$$### なぜ効果があるのか

 散歩は一連の独立した決定として見ることができます。 学生がノードに入るたびに (開始部分を除く)、次のいずれかを選択するよう強制されます。$\deg(u)-1$前端を均一にします。 影響を与える唯一のランダム性は、$b$到達するかどうかは、からの固有のパスに沿ったすべての決定が完了したかどうかです。$a$に$b$正しく位置合わせしてください。 あらゆる逸脱は、決して元に戻らない部分木につながります。$b$。 これらの選択肢は独立して乗算されるため、確率はパス上の積に因数分解されます。 LCA 分解により、これらのパスの寄与を対数時間で正確に抽出できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

LOG = 20

n, q = map(int, input().split())
g = [[] for _ in range(n)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

deg = [len(g[i]) for i in range(n)]

parent = [[-1] * n for _ in range(LOG)]
depth = [0] * n

stack = [(0, -1)]
order = []

while stack:
    u, p = stack.pop()
    parent[0][u] = p
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        stack.append((v, u))

for k in range(1, LOG):
    for v in range(n):
        if parent[k - 1][v] != -1:
            parent[k][v] = parent[k - 1][parent[k - 1][v]]

w = [0] * n
for i in range(n):
    w[i] = (deg[i] - 1) % MOD if deg[i] > 0 else 0

up = [[1] * n for _ in range(LOG)]

for i in range(n):
    up[0][i] = w[i]

def build_up():
    for k in range(1, LOG):
        for v in range(n):
            if parent[k - 1][v] != -1:
                up[k][v] = (up[k - 1][v] * up[k - 1][parent[k - 1][v]]) % MOD

build_up()

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for k in range(LOG):
        if diff & (1 << k):
            a = parent[k][a]
    if a == b:
        return a
    for k in range(LOG - 1, -1, -1):
        if parent[k][a] != parent[k][b]:
            a = parent[k][a]
            b = parent[k][b]
    return parent[0][a]

def prod_to(v):
    res = 1
    cur = v
    for k in range(LOG):
        if cur == -1:
            break
        if (depth[v] - depth[cur]) & (1 << k):
            res = res * up[k][v] % MOD
            v = parent[k][v]
    return res

def path_prod(a, b, c):
    # product of w on path a-b including both ends
    def climb(x, anc):
        res = 1
        diff = depth[x] - depth[anc]
        cur = x
        for k in range(LOG):
            if diff & (1 << k):
                res = res * up[k][cur] % MOD
                cur = parent[k][cur]
        return res

    res1 = climb(a, c)
    res2 = climb(b, c)
    res = res1 * res2 % MOD
    res = res * w[c] % MOD
    return res

for _ in range(q):
    a, b = map(int, input().split())
    a -= 1
    b -= 1

    c = lca(a, b)

    def climb(a, anc):
        res = 1
        cur = a
        diff = depth[a] - depth[anc]
        for k in range(LOG):
            if diff & (1 << k):
                res = res * w[cur] % MOD
                cur = parent[k][cur]
        return res

    num = climb(a, c) * climb(b, c) % MOD
    num = num * w[c] % MOD

    # adjust endpoints
    # replace w[a] with deg[a]
    inv_wa = pow(w[a] if w[a] != 0 else 1, MOD - 2, MOD)
    num = num * inv_wa % MOD
    num = num * deg[a] % MOD

    # probability = 1/p so p is inverse
    inv_num = pow(num, MOD - 2, MOD)
    print(inv_num)
```この実装では、前処理のためにのみツリーがルート構造に分割されます。 重労働はバイナリリフティングテーブルであり、これにより、$w[u]$対数時間における任意の上向きパス セグメントに沿って。 

よくある落とし穴は、開始ノードが次を使用することを忘れることです。$\deg(a)$それよりも$\deg(a)-1$。 もう 1 つは、2 つのパス半分をマージするときに LCA 寄与が二重にカウントされることです。 コードでは、明示的に LCA 係数を 1 回乗算することでこれを回避します。

 ## 特殊なケース

 開始ノードがリーフである場合、クリティカルなエッジ ケースが発生します。 そのような状況では、$\deg(a)=1$, そのため、初手は強制されます。 製品では正しく使用されているため、アルゴリズムはこれを自然に処理します。$\deg(a)$の代わりに$\deg(a)-1$、ゼロ確率の崩壊を防ぎます。 

もう 1 つのエッジケースは次のような場合です$b$のすぐ隣です$a$。 パスには決定が 1 つだけ含まれており、式は次の分岐係数による 1 つの除算に減ります。$a$これは、最初の 1 つの正しい動きだけが成功につながるという事実と一致します。 

最後のエッジケースは、LCA がエンドポイントの 1 つである場合です。 LCA ベースの分解は、パスの 2 つの半分のうちの 1 つが空になり、乗算では残りのセグメントのみが使用されるため、引き続き機能します。これはまさに、直接下向きのパスに沿った強制決定のシーケンスです。
