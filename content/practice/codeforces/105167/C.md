 ## 解決策
 ## 問題の理解

 水平線と垂直線を使用して描画されたグリッドが与えられます。 グリッドは次のように完全に定義されます。$n$水平線と$m$平面内に等間隔に配置された垂直線。 形成する長方形はすべて、これらの線を境界として使用する必要があります。これは、長方形の各辺がグリッド線の 1 つに正確に位置することを意味します。 

有効な長方形は、上下の境界として 2 本の異なる水平線を選択し、左右の境界として 2 本の異なる垂直線を選択することによって決定されます。 このような選択はすべて、1 つの長方形を一意に定義します。 2 つの長方形は、その 4 つの隅の点が一致する場合にのみ同じとみなされます。これは、同じ水平線のペアと同じ垂直線のペアを選択することに正確に対応します。 

タスクは、そのような非縮退長方形がいくつ存在するかを数えることです。 

制約は小さく、$n, m \le 100$したがって、3 次または 2 次のアプローチも実現可能です。 ただし、問題の構造は、シミュレーションではなく、組み合わせの計数の同一性を期待する必要があることを示唆しています。 ジオメトリをチェックしてすべての四角形を明示的に反復するアプローチは、すでに効果的です。$O(n^2 m^2)$ここではまだ問題ありませんが、不要です。 

よくある間違いは、「グリッド線」ではなく「グリッド セル」の観点から考えることです。 誰かが解釈したら$n$そして$m$線ではなくセルとして使用すると、誤って使用される可能性があります。$n \cdot m$または類似の表現。 もう 1 つの微妙な間違いは、長方形には 2 本の異なる水平線と 2 本の異なる垂直線が必要であることを忘れていることです。$n < 2$または$m < 2$ゼロを生成する必要があります。 

たとえば、次の場合$n = 1, m = 4$、横線は1本しかないので、長方形はまったく形成できません。 正解は 0 です。実現可能性を確認せずに「任意のペアを選択する」ことを前提としたアプローチでは、暗黙的に無効な組み合わせが生成されます。 

## アプローチ

 ブルートフォース解釈では、まず上下の水平線を明示的に選択し、次に左右の垂直線を選択し、有効な組み合わせをすべて数えます。 これはすでに問題の直接的なモデルです。すべての四角形は、明確な境界線の 4 つの 1 つに正確に対応します。 

ブルートフォース手法は、水平線のすべてのペアと垂直線のすべてのペアを反復処理することによって機能します。 水平ペアの数は$\binom{n}{2}$、垂直ペアの数は$\binom{m}{2}$。 組み合わせごとに、長方形を 1 つと数えます。 長方形はその境界線によって一意に決まるため、これは正しいです。 

この非効率性は、すべての四角形をセルごとにスキャンしたり、ジオメトリを明示的に検証したりするなど、幾何学的列挙の用語で考えた場合にのみ現れます。 それでも、問題のサイズは十分に小さいため、$O(n^2 m^2)$合格するでしょう、なぜなら$n, m \le 100$、せいぜい与えます$10^8$操作は限界に達していますが、最適化された Python ではまだ許容可能です。 

重要な観察は、水平方向と垂直方向の選択が独立しているということです。 2 本の水平線を選択すると、有効な垂直線のペアと組み合わせることができます。 これにより、問題が 2 つの組み合わせカウントに分離されます。 

したがって、長方形の総数は次のようになります。$$\binom{n}{2} \cdot \binom{m}{2}$$これにより、反復の必要性がすべてなくなり、ソリューションが定数時間の演算に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2 m^2)$|$O(1)$| 受け入れられるが不要 |
 | 最適 |$O(1)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$n$そして$m$。 これらは、利用可能な水平および垂直グリッド線の数を表します。 
2. 2 本の異なる水平線を選択できる方法が何通りあるかを計算します。 これは$\frac{n(n-1)}{2}$。 その理由は、長方形には上下の境界が必要であり、順序は重要ではないということです。 
3. 2 本の異なる垂直線を選択できる方法が何通りあるかを計算します。 これは$\frac{m(m-1)}{2}$、同じ理由です。 
4. これら 2 つの値を乗算します。 各水平ペアは任意の垂直ペアと組み合わせることができ、それぞれの組み合わせで 1 つの長方形が形成されます。 
5. 積を出力します。 

### なぜ効果があるのか

 すべての長方形は、2 本の水平線と 2 本の垂直線の選択によって一意に識別されます。 異なる選択間に重なりはなく、選択によって複数の四角形が生成されることはありません。 これにより、有効な長方形のセットと 2 つの組み合わせセットのデカルト積との間に全単射が作成されます。 この 1 対 1 のマッピングにより、四角形を数えることは、独立した組み合わせの選択肢を乗算することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

# choose any 2 horizontal lines
h = n * (n - 1) // 2

# choose any 2 vertical lines
v = m * (m - 1) // 2

print(h * v)
```この解決策は、反復ではなく、組み合わせの恒等性に完全に依存しています。 最も一般的な実装上の間違いは、行数を操作する代わりにグリッド セルをシミュレートしようとした場合のインデックス作成が 1 つずつずれてしまうことです。 もう1つの問題は整数の除算を忘れることですが、ここでは明示的に使用します。`//`整数の結果を保証するため。 

Python では任意精度の整数を使用できるため、乗算ステップは安全であるため、オーバーフローの懸念は存在しません。 

## 実用的な例

 ### 例 1

 入力:```
3 4
```組み合わせを段階的に計算します。 

| ステップ | 水平線 | 縦線 | 水平ペア | 垂直ペア | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | 3 | 4 | - | - | - |
 | ペアを計算する | 3 | 4 | 3 | 6 | - |
 | 最終回 | 3 | 4 | 3 | 6 | 18 |

 ここ、$\binom{3}{2} = 3$そして$\binom{4}{2} = 6$、18個の長方形が得られます。 

これにより、小さなグリッドでも境界の組み合わせにより複数の長方形が生成されることが確認されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline
    n, m = map(int, input().split())
    h = n * (n - 1) // 2
    v = m * (m - 1) // 2
    return str(h * v)

# provided sample
assert run("3 4") == "18"

# minimum case: no rectangle possible
assert run("1 1") == "0"

# only vertical flexibility
assert run("2 5") == "10"

# only horizontal flexibility
assert run("5 2") == "10"

# larger balanced case
assert run("10 10") == str((10*9//2)**2)
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 いつ$n = 1$または$m = 1$の場合、二項項の 1 つがゼロになるため、式は正しくゼロを返します。 入力用`1 4`、計算は次のようになります$\binom{1}{2} = 0$、結果は 0 になります。アルゴリズムはこれを分岐せずに自然に処理します。 

のために`2 2`、両方の次元には、可能な線のペアが 1 つだけあります。 計算の結果は、$1 \cdot 1 = 1$、これは外側の境界によって形成される単一の長方形に対応します。 

次のような、より大きくてもまだ小さい入力の場合、`3 3`、アルゴリズムが生成する$3 \cdot 3 = 9$、交差の 2D グリッド内のすべての可能な長方形の完全な列挙と一致します。
