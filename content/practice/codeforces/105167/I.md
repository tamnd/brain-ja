 ## 解決策
 ## 問題の理解

 私たちは、次の長さの DNA 文字列を与えられています。$n$アルファベットの上に$\{A, C, G, T\}$。 この文字列内には「編集可能」な位置の固定セットがあり、これらの位置のそれぞれを独立して 4 つの文字のいずれかに変更できます。 

このDNAとともに私たちに与えられたのは、$k$パターン文字列。 各パターンには重みがあります。 編集後に取得した最終的な DNA 文字列については、パターンごとに、それが部分文字列として出現する回数 (重複する出現は許可されます) を数え、その回数にパターンの重みを掛けて、すべてのパターンを合計することによってスコアを計算します。 

タスクは、この合計加重パターン出現スコアを最大化するために、すべての編集可能な位置の文字を選択することです。 

重要な問題は、単一の文字を変更すると多くの重複する部分文字列に影響があり、パターンが互いに重複する可能性があるため、ある位置の影響が他の位置と高度に結合することです。 

制約は、テスト ケースごとではなく、合計サイズにおいて非常に厳しいです。$n \le 1000$テストごとと合計$n$テスト全体の値も小さいです。 パターンの合計長も全体で 1000 に制限されます。 これは、テストごとに 2 次または小さな 3 次のアプローチは許容されるが、編集可能な位置の数を超える指数関数的なアプローチは許容できないことを強く示唆しています。 

単純なアプローチでは、編集可能な位置への文字の割り当てをすべて試してみます。 あれば$m$そのような立場は、$4^m$構成は、中程度の構成でもすでに不可能です$m$。 

もう 1 つの素朴なアイデアは、文字列一致アルゴリズムを使用して、割り当てごとにすべてのパターン一致を再計算することです。 それぞれの評価があったとしても$O(nk)$、依然として指数関数的な数の割り当てが支配的です。 

さらに微妙な落とし穴は、パターンが独立していると仮定することです。 たとえば、「AA」と「AAA」のような 2 つのパターンは重なり合っています。 一方の出現を最大化すると、非局所的な方法で他方に影響を及ぼす選択を強いられる可能性があります。 このような対話では、貪欲なポジションごとの割り当ては直ちに失敗します。 

## アプローチ

 中心的な観察は、文字を選択しているにもかかわらず、スコアはパターンの小さなセットの部分文字列の出現のみに依存するということです。 これは、部分文字列を直接考慮するのをやめ、代わりにすべてのパターン一致を同時にエンコードするオートマトンを構築する古典的な設定です。 

まずすべてのパターンのトライを構築し、それを Aho-Corasick オートマトンに拡張します。 各状態は、あるパターンのプレフィックスを表し、各状態は、その状態で終了するすべてのパターンの重みの合計に等しい値を保持します (障害リンクで伝播された出力を含む)。 文字列を 1 文字ずつトラバースするときは、このオートマトンを通過し、出力がゼロ以外の状態に到達するたびにスコアを蓄積します。 

ここで、DNA 構築問題は、選択された文字に応じて各位置がオートマトン状態間で遷移するシーケンス構築問題になります。 位置が固定されている場合、その位置には出力遷移が 1 つだけあります。 編集可能な場合は、最大 4 つのトランジションが可能です。 

これは当然、位置とオートマトンの状態に関する動的計画法の問題になります。 位置で$i$では、DNA のプレフィックスを処理し、特定のオートマトン状態で終了した後に達成可能な最高のスコアを追跡します。 固定ポジションの場合、遷移は決定的です。 編集可能な位置については、4 文字すべてを試して、結果として最良のトランジションを取得します。 

ポジションとオートマトンの状態に対するブルートフォース DP は次のようになります。$O(n \cdot S \cdot 4)$、 どこ$S$はオートマトンの状態の数であり、パターンの合計長によって制限されます。 制約を考慮すると、これは十分小さいです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース割り当て |$O(4^m \cdot n k)$|$O(n)$| 遅すぎる |
 | アホコラシック + DP |$O(n \cdot S \cdot 4)$|$O(S)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、すべてのパターン文字列から Aho-Corasick オートマトンを構築します。 各ノードには、4 つの DNA 文字の遷移、失敗リンク、およびそのノードで終了するすべてのパターンの合計重みを表す累積出力値が格納されます。 

次に、DNA 位置に対して DP を実行します。 

1. すべてのパターンからオートマトンを構築し、障害リンクを計算します。 各状態は、それ自体とその障害チェーンからの出力重みを蓄積します。 これにより、ある状態に到達したときに、そこで終了するパターン マッチの数がすぐにわかるようになります。 
2. DP テーブルを初期化します。$dp[i][v]$最初の処理後の最大スコアを表します$i$オートマトン状態の文字と結末$v$。 すべての値は負の無限大から始まります。$dp[0][root] = 0$。 
3. 各位置を反復処理します。$i$0から$n-1$。 州ごとに$v$、ポジションに応じてトランジションを考慮します。$i$編集可能です。 
4. 位置の場合$i$キャラクターに固定されている$c$からのオートマトンの遷移をたどります。$v$を使用して$c$を計算し、結果の状態の出力値を加算します。 
5. 位置の場合$i$は編集可能であるため、4 つの文字すべてを試し、結果の状態を計算し、それらの中で最大のスコアを取得します。 
6. すべての位置を処理した後、答えはその位置におけるすべてのオートマトン状態の最大値になります。$n$。 

これが機能する理由は、すべてのパターン一致をローカルでエンコードするオートマトンに関係しています。 すべての部分文字列の出現は、何らかのパターンが終了する状態に入ることに対応し、失敗リンクは重複が正しくカウントされることを保証します。 DP は、オートマトン内で部分文字列がどのように変化するかを追跡しながら、編集可能な位置での文字の一貫した割り当てをすべて調査することを保証します。 考えられるすべての DNA 構造がこの DP を通る 1 つのパスに正確に対応し、すべてのパス スコアが定義どおりに正確に計算されるため、最大 DP 値は最適な IQ スコアと一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("next", "link", "out")
    def __init__(self):
        self.next = [-1] * 4
        self.link = 0
        self.out = 0

def char_id(c):
    if c == 'A':
        return 0
    if c == 'C':
        return 1
    if c == 'G':
        return 2
    return 3

def build_aho(patterns):
    nodes = [Node()]
    
    for s, w in patterns:
        v = 0
        for ch in s:
            c = char_id(ch)
            if nodes[v].next[c] == -1:
                nodes[v].next[c] = len(nodes)
                nodes.append(Node())
            v = nodes[v].next[c]
        nodes[v].out += w

    from collections import deque
    q = deque()

    for c in range(4):
        u = nodes[0].next[c]
        if u != -1:
            nodes[u].link = 0
            q.append(u)
        else:
            nodes[0].next[c] = 0

    while q:
        v = q.popleft()
        nodes[v].out += nodes[nodes[v].link].out

        for c in range(4):
            u = nodes[v].next[c]
            if u != -1:
                nodes[u].link = nodes[nodes[v].link].next[c]
                q.append(u)
            else:
                nodes[v].next[c] = nodes[nodes[v].link].next[c]

    return nodes

def solve():
    n, m, k = map(int, input().split())
    s = input().strip()
    editable = [False] * n
    if m:
        for x in map(int, input().split()):
            editable[x - 1] = True

    patterns = []
    for _ in range(k):
        parts = input().split()
        patterns.append((parts[0], int(parts[1])))

    nodes = build_aho(patterns)
    S = len(nodes)

    dp = [-10**18] * S
    dp[0] = 0

    for i in range(n):
        ndp = [-10**18] * S
        if editable[i]:
            for v in range(S):
                if dp[v] < 0:
                    continue
                for c in range(4):
                    u = nodes[v].next[c]
                    ndp[u] = max(ndp[u], dp[v] + nodes[u].out)
        else:
            c = char_id(s[i])
            for v in range(S):
                if dp[v] < 0:
                    continue
                u = nodes[v].next[c]
                ndp[u] = max(ndp[u], dp[v] + nodes[u].out)
        dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```実装は、遷移を固定配列に格納できるように、DNA 文字を整数にエンコードすることから始まります。 オートマトン構築ステップでは、失敗リンクを介して出力値も伝播するため、各状態は、サフィックス リンクを介して一致するものを含む、そこで終了するすべてのパターン補完を即座に反映します。 

各層は前の層にのみ依存するため、DP 配列はメモリ効率を高めるためにオートマトン状態全体にわたって 1 次元です。 各ポジションで、4 つの選択肢に分岐するか、単一の強制遷移に従います。 トランジションでは事前に計算されたオートマトンのエッジが使用され、各ステップが確実に$O(1)$。 

微妙な点は、オートマトンのルートで欠落している遷移を初期化して、すべての文字が常に有効な遷移を持つようにすることです。これにより、DP 中の特殊なケースが回避されます。 もう 1 つの重要な点は、最大の計算に到達不可能な状態が混入することを避けるために、大きな負のセンチネルを使用することです。

 ### 例 1

 1 つの編集可能な位置と 1 つのパターンを持つ短い DNA を考えてみましょう。 

入力：```
n = 3, m = 1, k = 1
s = "AAA"
editable = [2]
pattern = ("AA", 1)
```オートマトンの状態全体にわたって DP を追跡します。 

| 私 | 編集可能 | dp 状態の概要 (概念的には状態ごとに最適) |
 | --- | --- | --- |
 | 0 | いいえ | ルート = 0 のみ |
 | 1 | いいえ | 「A」の遷移後 |
 | 2 | はい | エアコン/G/Tを試してください |

 位置 2 で「A」を選択すると、「AA」が 2 回出現する「AAA」が作成され、スコア 2 が与えられます。その他の文字は出現を中断します。 

最終的な答えは 2 です。 

これは、オートマトンの出力集計によって重複する一致がどのように自然に処理されるかを示しています。 

### 例 2

 入力:```
n = 2, m = 2, k = 2
s = "AC"

patterns: ("A",1), ("C",2)
```DP を通じてすべての組み合わせを評価します。 

| 私 | 選択 | DP への貢献 |
 | --- | --- | --- |

これは、立場の独立性が想定されていないことを裏付けています。 DP はすべての組み合わせを効率的に探索します。

 ## 特殊なケース

 キー エッジ ケースは、パターン「A」、「AA」、「AAA」がすべて同時に存在するなど、重なり合います。 直接の一致のみをカウントする単純なアプローチでは、カスケード寄与が見逃されます。 各状態が障害リンクに沿って出力を集約するため、オートマトンはこれを解決します。 

もう 1 つのケースは、すべての位置が編集可能な場合です。 位置ごとの貪欲な戦略は、局所的に最適な文字がグローバルな重複構造を減らすことができるため、失敗しますが、DP はオートマトンの状態を介した将来の遷移を正しく考慮します。 

3 番目のケースは、パターンが長いがまばらな場合です。 オートマトン圧縮がなければ、部分文字列スキャンの繰り返しは状態遷移ごとに二次関数的なものになり、遅すぎます。 オートマトンは、パターン数に関係なく、各遷移が一定時間であることを保証します。
