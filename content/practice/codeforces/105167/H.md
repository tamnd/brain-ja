 ## 解決策
 ## 問題の理解

 私たちには飲み物のコレクションが与えられ、それぞれの飲み物には種類と時間単位で測定される有効期限が設定されています。 時間は離散的に進みます。サシャは 1 時間にちょうど 1 杯の飲み物を消費し、機械は 1 時間ごとにどの飲み物を分配するかを選択する必要があります。 ドリンクは一定の時間が経過すると使用できなくなります。つまり、シーケンスの最初の位置の 1 つでのみ使用できます。 

重要な問題は、消費量をシミュレーションすることではなく、すべての種類の飲み物で何回完全な「ラウンド」を達成できるかを判断することです。 ラウンドとは、マシン内に存在するすべてのタイプについて、サシャがそのタイプの少なくとも 1 つのアイテムをなんとか飲むことを意味します。 何らかの型が存在しない場合、その型はすぐに答えを 0 にします。 

各ドリンクには最終注文の締め切り位置があります: ドリンクに価値があるかどうか`b`、最大でも所定の位置に配置できます。`b + 1`消費シーケンスの。 同様に、消費を 1 からインデックス付けすると、各項目には許可された最新の位置が存在します。 

機械は最適に制御されていると想定されます。 これは、有効期限の制約を尊重する限り、完全なタイプ カバレッジ ラウンドの数を最大化するために、ドリンクの注文を自由に選択できることを意味します。 

目標は、最大の整数を計算することです`k`少なくともスケジュールを立てることができるように`k`あらゆる種類のドリンクをそれぞれの期限までに受け取ります。 

制約は大きく、テストあたり最大 3·10^5 ドリンク、合計 5·10^5 までです。 これにより、2 次または 3 次の動作を使用した素朴な方法で候補ステップごとに明示的な順列を構築することによって、スケジュールをシミュレートしたり、実現可能性をチェックしようとするソリューションは即座に除外されます。 どのアプローチも、テストごとに線形に近い、または n log n でなければなりません。 

一部の型が完全に欠落している場合、微妙なエッジケースが発生します。 そうなると1周すら不可能です。 もう 1 つの重要な例外ケースは、同じタイプのアイテムが多数存在するものの、有効期限が厳しいため、それらのアイテムが非常に早いスロットを占有することを余儀なくされ、実行可能な完全なラウンドの数が制限される場合です。 

## アプローチ

 直接的に解釈すると、消費秩序を段階的に構築していくと考えることができます。 時間ごとに、まだ有効な飲み物を選択し、時間をかけてすべての種類のバランスの取れた数を収集できるように努めます。 考えられるすべての有効なスケジュールをシミュレートし、表示される完全なタイプセットの数をチェックすることを想像することもできます。 ただし、順列の数は n の階乗であり、バックトラッキングを使用した貪欲なシミュレーションですら非常に遅すぎます。 

より構造化された総当たり攻撃のアイデアは、二分探索です。`k`、フルラウンドの数。 固定の場合`k`、少なくとも選択できるかどうかを確認する必要があります。`k`選択したすべての飲み物を期限を考慮して有効な順序に配置できるように、各タイプの飲み物を選択します。 これは、制約付きスケジューリングの実現可能性の問題になります。 単純な実現可能性チェックでは、すべてのアイテムを期限で並べ替え、位置を貪欲に割り当てる可能性がありますが、タイプごとに個別に実行したり、スキャンを繰り返したりすると、簡単に O(n^2 log n) になってしまいます。 

重要な洞察は、視点を反転することです。グローバルなシーケンスを構築するという観点から考えるのではなく、各ドリンクを初期のポジションに貢献する能力として扱い、すべてのタイプが少なくとも貢献していることを確認しながら、全体でいくつのアイテムを「維持」できるかを尋ねます。`k`アイテム。 各タイプは目的において対称であるため、問題は選択できるかどうかを検証することに帰着します。`k`タイプごとの項目と期限があり、最初の項目を占有することができます。`k · m`ポジション。 

これにより、問題はタイプごとのグループ化と組み合わせた、期限付きのスケジュール設定の実現可能性チェックに古典的に変換されます。 それぞれのタイプについて、次の点のみを考慮します。`k`実行可能な選択では、常に遅い締め切りが優先されるため、最良 (最長の締め切り) の項目を選択します。 すべてのタイプにわたってこれらの候補を収集した後、期限の昇順に配置できるかどうかをテストします。貪欲なスキャンで十分です。 

これにより、クリーンな二分探索が行われます。`k`、ソート後の各チェックは線形です。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. すべての飲み物を種類ごとにグループ化し、有効期限を別のリストに保存します。 これが必要なのは、要件がタイプごとに対称的であるため、決定はグローバルではなくグループごとに行われるためです。 
2. タイプごとに、有効期限値を降順に並べ替えます。 これにより、どれがどれであるかをすぐに特定できるようになります。`k`を目指す場合、項目は含めるのに最適です。`k`ラウンドします。 その理由は、最適な選択では、同じタイプ内で長い期限よりも短い期限が優先されることは決してないということです。 
3. 答えを二分探索します`k`0 から可能な最大値まで。これは、任意のタイプの項目の最大数と、`n // m`。 
4. 候補者が確定した場合`k`、上部を取得して、選択した項目のマルチセットを構築しようとします。`k`各タイプの締め切り。 タイプの値が以下の場合`k`項目がある場合、この候補者はすぐに不合格になります。 
5. 選択したすべてのアイテムをタイプごとに収集し、サイズのリストを作成します`k · m`。 
6. このリストを期限順に並べ替えます。 
7. タイムスロット 1 から 1 までの割り当てをシミュレートします。`k · m`。 位置で`i`、アイテムの期限が少なくともあるかどうかを確認します`i`。 いずれかの項目がこの条件を満たさない場合、そのスケジュールは実行できません。`k`。 
8. すべての項目が合格すれば達成できます`k`, そこで、二分探索を上に移動します。 それ以外の場合は下向き。 

重要な考え方は、締め切り順に並べ替えることで最適な貪欲なスケジューリングが強制されるということです。つまり、常に最も制限された項目を最初に使用します。 

### なぜ効果があるのか

 このアルゴリズムは、単調な実現可能性プロパティに依存しています。 日程調整が可能であれば`k`フルラウンド、その後任意`k' < k`必須項目を削除しても制約が緩和されるだけなので、これも実現可能です。 固定の場合`k`を選択して、`k`選択したアイテムをより期限の短いものに置き換えると、実現可能性が低下するだけであるため、タイプごとに最も遅い期限のアイテムが最適です。 最後に、時間の増加による貪欲な割り当てにより、割り当てが存在する場合、この並べ替えられた割り当ては必ず成功します。これは、常に最も制約の厳しい要素用に初期スロットを最初に予約するためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(k, groups):
    items = []
    for g in groups:
        if len(g) < k:
            return False
        # take k largest deadlines
        for x in g[:k]:
            items.append(x)
    items.sort()
    for i, d in enumerate(items, start=1):
        if d < i:
            return False
    return True

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        groups = [[] for _ in range(m + 1)]
        for i in range(n):
            groups[a[i]].append(b[i])

        for i in range(1, m + 1):
            groups[i].sort(reverse=True)

        if any(len(groups[i]) == 0 for i in range(1, m + 1)):
            print(0)
            continue

        lo, hi = 0, n // m
        ans = 0

        while lo <= hi:
            mid = (lo + hi) // 2
            if check(mid, groups):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()
```実装では、まず有効期限をタイプごとにグループ化し、次に各グループを降順で並べ替えて、最初のものが選択されるようにします。`k`要素は、最も柔軟な項目を選択することに対応します。 

の`check`候補の実現可能性を強制する機能`k`。 次のようにして候補者プールを構築します。`k`項目をタイプごとに分類し、期限ごとにグローバルに並べ替えます。 貪欲な検証ステップでは、i 番目にスケジュールされた項目が時間まで存続できるかどうかをチェックします。`i`。 

二分探索はこの実現可能性テストをラップして、有効な最大値を見つけます。`k`。 

よくある実装の落とし穴は、デッドライン条件ではインデックスが 1 から始まることを忘れることです。 もう 1 つの微妙な問題は、タイプごとの選択で常に最大の期限が使用されるようにすることです。 そうしないと、実現可能性が誤って拒否される可能性があります。

 | ステップ | アクション | アイテム |

 ## 特殊なケース

 主なエッジ ケースは、少なくとも 1 つのタイプに項目がゼロの場合です。 その状況では、グループ化すると空のリストがすぐに明らかになり、肯定的なものはすべて表示されます。`k`失敗します。 アルゴリズムは、バイナリ検索の前の早期チェックによってこれを処理し、ゼロを返します。 

もう 1 つのケースは、締め切りが非常に厳しい場合です。`b_i = 0`。 どのタイプもアイテムが足りていても最初の位置しか使えないので、`k`1 を超えることはできませんが、グループ化によって競合が発生する場合は、多くの場合 0 になります。 ソートされた期限は早期ポジション制約に直ちに違反するため、貪欲な実行可能性チェックはこれを検出します。 

最後の微妙なケースは、あるタイプには大きな期限の項目が多く含まれ、別のタイプにはほとんどが小さな期限の項目がある場合に発生します。 二分探索では、大規模な結果が得られる可能性があります。`k`、ただし、実現可能性の構築中に、選択された項目が満たされない早期配置を強制するため、期限が短いタイプはグローバル順序付けステップに失敗します。
