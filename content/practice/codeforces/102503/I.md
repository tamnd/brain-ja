 ## 解決策
 ## 問題の理解

 私たちは持っています`n`それぞれ一定のサービス時間を必要とする人々`a_i`。 がある`k`独立したレジ係。 列は、1 人のレジ担当者に割り当てられた人の順序付きリストであり、人の待ち時間は、同じ列でその前に配置されていた全員のサービス時間の合計です。 

目標は、全員が終了するまでの時間を最小限に抑えることではありません。 すべての始動遅延の合計を最小限に抑えるためです。 可能な最小合計待ち時間を見つけた後、それを達成できるさまざまな回線配置の数を数えなければなりません。 

サービス時間のある人々を含む 1 つの固定回線の場合`x1, x2, ..., xm`、最適な順序は常に最小値から最大値の順です。 貢献度は次のようになります。`(m-1)x1 + (m-2)x2 + ... + 1*x(m-1) + 0*xm`制約により許可されるのは、`n`到達する`100000`、合計で`n`すべてのテストにわたって、次の制限も受けられます`100000`。 これにより、ラインやすべてのパーティションへの人の割り当てをすべて試行するものは除外されます。 解は線形に近いか、`O(n log n)`。 並べ替えは許容されますが、指数関数または二次関数は許容されません。 

難しいケースは、レジ係の数とサービス時間が等しいことから生じます。 

全員に十分なレジ係があれば、誰も待つ必要はありません。 例えば：```
1
3 5
4 4 4
```答えは次のとおりです。```
0 60
```がある`5 * 4 * 3`3 人に異なるレジ係を選択する方法。 人の順列のみをカウントするソリューションでは、レジ係の選択を見逃してしまいます。 

もう 1 つの微妙なケースは、値が等しい場合です。 のために：```
1
3 2
5 5 5
```最小待ち時間は、`5`、ただし、3 人の最適な配置はすべてカウントする必要があります。 組み合わせカウントを行わずに、等しい値を区別可能な並べ替え位置として扱うと、間違った答えが得られます。 

## アプローチ

 ブルートフォースソリューションでは、人々の可能な限りの分布を試みることになります。`k`行と各行内のすべての順序。 それぞれの手配について、合計待ち時間を計算し、最適な待ち時間を維持できます。 これはあらゆる可能性を直接チェックするので正しいですが、アレンジメントの数は指数関数的よりも速く増加します。 と`n = 100000`、それらのごく一部を生成することさえ不可能です。 

係数を調べると、有益な観察が得られます。 行内で最後の人が係数を貢献します`0`、前の人が係数を貢献します`1`、次の寄与係数`2`、 等々。 合計待ち時間は次の合計です。`a_i`これらの係数を乗算します。 

結果を最小限にするには、最大のサービス時間が最小の係数を受け取る必要があります。 これは並べ替えの背後にある交換引数と同じです。大きい値の係数が小さい値よりも大きい場合、それらを交換すると合計が減少します。 

残る唯一の問題は、どの係数が利用できるかということです。 空でないすべてのレジ担当者は、係数を持つ 1 つのスロットを提供します`0`。 その後、レジ担当者が増えるたびに係数が作成されます`1, 2, 3, ...`。 大きな係数の作成を避けるために、追加の人員をレジ担当者にできるだけ均等に配分する必要があります。 

させて：`extra = n - k`列の最後尾以外の人の数になります。 もし`n >= k`、すべてのレジ担当者に最後の担当者を付けることができます。 配布します`extra`間の係数スロット`k`線。 もし：`extra = q * k + r`次に、からのすべての係数`1`に`q`表示されます`k`倍と係数`q+1`表示されます`r`回。 

カウント部分も同じ順序に従います。 係数スロットが固定されると、より大きな値を持つ人はより小さな係数を埋める必要があります。 等しい値は交換できるため、等しい値のグループを処理し、それらが使用可能なラベル付きスロットを占有する方法が何通りあるかを数えます。

 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. サービス時間を並べ替えます。 並べ替えにより、交換引数を適用できます。つまり、より大きな値は、より小さな待機係数に配置する必要があります。 
2. もし`k >= n`、各人が自分のレジを受け取ることができるため、最小待ち時間はゼロです。 手配の数は、レジ担当者への人の注入割り当ての数です。`k * (k-1) * ... * (k-n+1)`。 

1. それ以外の場合は、係数バケットを作成します。 がある`k`係数付きスロット`0`。 させて`extra = n-k`、`q = extra // k`、 そして`r = extra % k`。 追加`k`各係数のスロット`1`を通して`q`を追加します。`r`係数付きスロット`q+1`。 
2. ソートされた人々を最大値から最小値の順に係数スロットに最小値から最大値まで割り当てて、最小値を計算します。 係数リストの最初の部分は、最終的な待機合計を示します。 
3. 同じ価値観を持つ人々をまとめて処理することで、最適な割り当てをカウントします。 すべての値グループについて、最小の係数を持つ現在使用可能なスロットの数を取得します。 グループが係数バケットの一部のみを使用する場合は、どのラベル付きスロットを組み合わせて使用​​するかを選択します。 スロットを選択した後、同じ値のグループ内の人々を自由に並べ替えることができます。 

なぜ効果があるのか:

 係数表現は、スケジューリングの問題を固定コストへの値の割り当てに変換します。 余分な 1 人を長いラインから短いラインに移動すると、存在する最大係数が減少するため、余分な人数を均等に分散することで係数マルチセットが最小化されます。 係数が固定されると、並べ替え不等式により、値を係数の逆の順序で並べ替えると最小の合計が得られることが証明されます。 カウント プロセスでは、等しい値によって複数の最適な割り当てが作成される場合に、可能なままの選択肢が正確に列挙されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

MAXN = 100000
fact = [1] * (MAXN + 1)
invfact = [1] * (MAXN + 1)

for i in range(1, MAXN + 1):
    fact[i] = fact[i-1] * i % MOD

invfact[MAXN] = pow(fact[MAXN], MOD - 2, MOD)
for i in range(MAXN, 0, -1):
    invfact[i-1] = invfact[i] * i % MOD

def comb(n, r):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n-r] % MOD

def solve_case(n, k, a):
    if k >= n:
        ways = 1
        for i in range(n):
            ways = ways * (k - i) % MOD
        return 0, ways

    a.sort()

    coeff = []
    extra = n - k
    q, r = divmod(extra, k)

    coeff.extend([0] * k)
    for c in range(1, q + 1):
        coeff.extend([c] * k)
    coeff.extend([q + 1] * r)

    ans = 0
    for x, c in zip(a, sorted(coeff, reverse=True)):
        ans += x * c

    buckets = []
    i = 0
    while i < n:
        j = i
        while j < n and a[j] == a[i]:
            j += 1
        buckets.append((a[i], j - i))
        i = j

    cnt = {}
    for c in coeff:
        cnt[c] = cnt.get(c, 0) + 1

    levels = sorted(cnt)
    ptr = 0
    rem = [cnt[x] for x in levels]

    ways = 1

    for _, size in reversed(buckets):
        need = size
        used_slots = 0
        while need:
            take = min(need, rem[ptr])
            ways = ways * comb(rem[ptr], take) % MOD
            rem[ptr] -= take
            need -= take
            used_slots += take
            if rem[ptr] == 0:
                ptr += 1
        ways = ways * fact[size] % MOD

    return ans % MOD, ways

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        x, y = solve_case(n, k, a)
        out.append(f"{x} {y}")
    print("\n".join(out))

if __name__ == "__main__":
    main()
```前処理では階乗と逆階乗が計算されるため、すべての組み合わせクエリは定数時間になります。 これが必要なのは、等しい値のグループが係数バケット間で分割される可能性があるためです。 

の建設`coeff`ウォークスルーのバランスの取れた分布の議論に従います。 リストには、最適な配置で使用可能な待機係数が正確に含まれています。 

最小の答えを得るには、並べ替えた値を逆の係数と組み合わせることにより、最大の値が最小の係数に配置されます。 

カウントするために、コードは各係数レベルにどれだけのスロットが残っているかを保存します。 等しい値のグループを処理する場合、どのラベル付きスロットがその値を受け取るかを選択し、そのグループ内の人々の内部順列の数を乗算します。 

答えに関係するすべての算術はモジュロで実行されます`10^9+7`。 最小待機時間自体は 32 ビット整数を超える可能性があるため、Python 整数が直接使用されます。

 ## 特殊なケース

 レジ係の数が人よりも多い場合、アルゴリズムは係数バケットの作成を回避し、単射代入を直接カウントします。 これは、誰でもすぐに始められるケースに対応します。 

すべてのサービス時間が等しい場合、並べ替えだけでは一意の配置を決定できません。 グループベースのカウント手順は、同一人物間の有効な交換をすべて保存するものです。 

いつ`n`よりわずかに大きいだけです`k`、正の係数はほとんどありません。 たとえば、`n=5`そして`k=4`、待つ必要があるのは 1 人だけなので、係数リストは次のようになります。`[0,0,0,0,1]`。 この構築では、特別なケースを使用せずにこれを処理します。 

いつ`k=1`、からのすべての係数`0`に`n-1`は 1 回だけ表示されます。 この方法は、サービス時間を増やすことでソートするという古典的な単一行スケジュール ルールになります。
