 ## 解決策
 ## 問題の理解

 惑星は有向非巡回グラフを形成します。 各惑星には科学値があり、惑星間の片道ルートごとにある程度の燃料が消費されます。 船は惑星 0 から出発し、消費される燃料の合計がタンク容量を超えない限り、ルートをたどることができます。`V`。 惑星を訪問すると、その科学的価値がミッションの合計に追加されます。 課題は、科学の合計が可能な限り最大となる惑星 0 から始まるパスを選択することです。 

入力には、いくつかのテスト ケースが記述されています。 それぞれについて、惑星の数、指示されたルートの数、および利用可能な最大燃料を受け取ります。 また、すべての惑星の科学的価値とその燃料費を含むルートも受け取ります。 出力は、有効なパスで収集できる最大の科学です。 

有用な制約は、グラフが DAG であるということです。 サイクルを含む一般的なグラフでは、繰り返される状態と潜在的に無限の探索を処理する必要がありますが、ここではすべてのパスの長さは最大でも`n`。 燃料制限も小さく、最大 6000 です。これは、残りの燃料または使用済みの燃料を含む動的プログラミング状態を強く示唆しています。 DAG には依然として膨大な数の異なるパスが含まれる可能性があるため、考えられるすべてのパスに依存するソリューションは指数関数的になります。 と`n`6000までは、それに近い値が必要です`O(nV + mV)`惑星のサブセットやパスの列挙に関係するものではなく。 

いくつかの特殊なケースでは、不注意な実装が失敗する可能性があります。 たとえ船がどこにも移動できなかったとしても、出発惑星は科学に貢献します。 例えば：```
1
1 0 0
50
```正しい答えは次のとおりです。```
50
```優位に立った後にのみ回答を更新する実装では、誤ってゼロが返されます。 

もう 1 つのよくある間違いは、残りの燃料よりもコストがかかるルートを無視することです。 考慮する：```
1
2 1 5
10 100
0 1 6
```正しい答えは次のとおりです。```
10
```唯一のルートが燃料制限を超えているため、2 番目の惑星には到達できません。 燃料なしで到達可能性のみを追跡する最短経路スタイルの実装では、誤って 2 番目の惑星が含まれてしまいます。 

3 番目の問題は、惑星ごとに最適な値を 1 つだけ保存することです。 考慮する：```
1
4 4 10
0 100 200 1000
0 1 5
0 2 6
1 3 5
2 3 4
```正しい答えは次のとおりです。```
210
```惑星 1 に到達すると科学力 100 が得られますが、惑星 3 に到達するのにちょうど十分な燃料が残されており、合計は 110 になります。惑星 2 に到達すると科学力は 200 になり、その後惑星 3 に到達可能になり、210 になります。最も安価なルートだけを維持するか、惑星への最初の到着のみを維持する貪欲なアプローチでは、有用な状態が破棄される可能性があります。 

## アプローチ

 直接的な総当りのソリューションでは、惑星 0 からの考えられるすべてのルート選択を再帰的に試行します。惑星に到達するたびに、現在消費された燃料と収集された科学情報が記録され、出発ルートの探索が継続されます。 すべての有効なパスが考慮されるため、これは正しいです。 

問題はパスの数です。 DAG には、指数関数的に多くのパスを含めることができます。 すべての層が多くの選択肢に分岐するグラフを作成できます。`2^n`考えられるルート。 のために`n = 6000`、それらのパスのごく一部を生成することさえ不可能です。 

重要な観察は、将来の決定に影響を与える唯一の情報は、現在の地球と、すでに使用された燃料の量であるということです。 私たちがそこに到着した正確な歴史は重要ではありません。 これにより、問題は動的プログラミングに変わります。 

州`dp[u][f]`惑星に到達した後に得られる最大の科学を表します`u`正確に過ごしながら`f`燃料。 グラフは非巡回であるため、惑星を位相順序に従って処理できます。 状態がわかっている場合、すべての出力エッジはその状態を新しい状態に拡張できます。 燃料寸法はあくまで`V + 1`、全体の作業を管理しやすくします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数的、最大 O(2^n) パス | O(n) 再帰の深さ | 遅すぎる |
 | 最適 | O((n + m)V) | O(nV) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 有向グラフを構築し、惑星のトポロジカルな順序を計算します。 グラフにはサイクルがないため、すべてのルートがこの順序で進みます。 
2. 動的プログラミング テーブルを作成します。`dp[u][f]`船が惑星に到着したときに収集された最高の科学を保管します`u`正確に費やした後`f`燃料。 最初はすべての値が不可能です。`dp[0][0] = s[0]`。 
3. 位相順序に従って惑星を処理します。 現在の惑星で到達可能な燃料量ごとに、すべての往路を試してください。 ルートが次へ進む場合`v`とコスト`c`、次の場合に移行が可能です。`f + c <= V`。 
4. 新しいサイエンス値で宛先の状態を更新します。 新しい価値は古い科学にプラス`s[v]`を訪問しているので、`v`その科学を収集します。 
5. すべての遷移が処理された後、答えは DP テーブル全体の最大値になります。 ミッションはどこででも停止できるため、最後の惑星は関係ありません。 

これが機能する理由は、すべての有効なパスがトポロジカルな順序で惑星の固有のシーケンスを持っているためです。 アルゴリズムが惑星に到達するとき、あらゆる燃料量でそこに到達するためのあらゆる方法がすでに検討されています。 保存された値はこれらの方法の中で最も優れた科学であるため、それを拡張しても将来のより良い道が失われることはありません。 考えられるすべてのパスは一連の DP 遷移に対応し、すべての DP 遷移は有効なパス拡張に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, m, V = map(int, input().split())
        s = list(map(int, input().split()))

        graph = [[] for _ in range(n)]
        indeg = [0] * n

        for _ in range(m):
            a, b, c = map(int, input().split())
            graph[a].append((b, c))
            indeg[b] += 1

        order = []
        stack = [i for i in range(n) if indeg[i] == 0]

        while stack:
            u = stack.pop()
            order.append(u)
            for v, _ in graph[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    stack.append(v)

        neg = -1
        dp = [[neg] * (V + 1) for _ in range(n)]
        dp[0][0] = s[0]

        for u in order:
            current = dp[u]
            for fuel in range(V + 1):
                if current[fuel] == neg:
                    continue
                value = current[fuel]
                for v, cost in graph[u]:
                    nf = fuel + cost
                    if nf <= V:
                        nv = value + s[v]
                        if nv > dp[v][nf]:
                            dp[v][nf] = nv

        answer = 0
        for row in dp:
            answer = max(answer, max(row))
        ans.append(str(answer))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```遷移中に必要なのは発信ルートのみであるため、グラフは隣接リストとして保存されます。 トポロジカルな順序付けは、カーンのアルゴリズムを使用して生成されます。 初期状態には、燃料消費ゼロの惑星 0 とその科学がすでに収集されているのみが含まれています。 

値`-1`すべての科学値は負ではないため、到達不可能な状態を表します。 移行は、新しい燃料の量が最大以下の場合にのみ発生します。`V`したがって、サイズが大きすぎるルートを特別に処理する必要はありません。 

Python の整数は、科学の大きな合計を自動的に処理します。 考えられる最大の答えは 32 ビット整数の制限を超える可能性があるため、固定サイズの整数を使用する言語には 64 ビット型が必要になります。 

最適な停止点はどの惑星でも可能であり、残りの燃料は余分な価値を提供しないため、最終スキャンではすべての惑星とすべての燃料量がチェックされます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m)V) | 各惑星がスキャンする`V`燃料値と到達可能な各状態は出力エッジをチェックします。 |
 | スペース | O(nV + m) | DP テーブルはメモリ使用量の大半を占めます。 |

 最大の入力には、合計 6000 個の惑星と 12000 個のルートがあります。 と`V`また、最大 6000 であれば、動的プログラミングの作業は意図した制限内にあり、メモリ要件は 800 MB の制限内に問題なく収まります。 

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    out = []
    t = int(sys.stdin.readline())

    for _ in range(t):
        n, m, V = map(int, sys.stdin.readline().split())
        s = list(map(int, sys.stdin.readline().split()))
        g = [[] for _ in range(n)]
        indeg = [0] * n
        for _ in range(m):
            a, b, c = map(int, sys.stdin.readline().split())
            g[a].append((b, c))
            indeg[b] += 1

        order = []
        stack = [i for i in range(n) if indeg[i] == 0]
        while stack:
            u = stack.pop()
            order.append(u)
            for v, c in g[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    stack.append(v)

        dp = [[-1] * (V + 1) for _ in range(n)]
        dp[0][0] = s[0]

        for u in order:
            for f in range(V + 1):
                if dp[u][f] >= 0:
                    for v, c in g[u]:
                        if f + c <= V:
                            dp[v][f + c] = max(dp[v][f + c], dp[u][f] + s[v])

        out.append(str(max(max(row) for row in dp)))

    sys.stdin = old
    return "\n".join(out)

 ## 特殊なケース

 ゼロルートの場合は、初期状態が次のように処理されるため、処理されます。`dp[0][0]`すでに始まりの惑星の科学が含まれています。 このアルゴリズムでは、答えを検討する前に遷移を必要とすることはありません。 

燃料制限が利用可能なすべてのルートよりも小さい場合、すべての移行が拒否されます。 2 つの惑星とコスト 6 のルートの例では、`V = 5`、到達可能な唯一の状態は科学 10 の惑星 0 のままであるため、結果は正しいです。 

同じ惑星に到達するための複数の方法に対して、アルゴリズムは各燃料量を個別に保持します。 4 つの惑星の例では、6 つの燃料と高い科学力を持って惑星 2 に到達することと、5 つの燃料と低い科学力を持って惑星 1 に到達することは異なります。 どちらの状態も後の遷移に使用できるため、最適な継続を見つけることができます。
