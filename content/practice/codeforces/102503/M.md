 ## 解決策
 ## 問題の理解

 入力では、シャツに着用日のラベルが付けられた 2 つのスタックが記述されています。 最初のスタックは下から上にリストされ、2 番目のスタックも同様にリストされます。 目標はシャツを順番に脱ぐことです`1, 2, ..., m+n`。 シャツをあるスタックから別のスタックに移動するには 1 単位のエネルギーがかかりますが、既に露出しているときに正しいシャツを取り出すには何のコストもかかりません。 

可能なすべての動きを直接シミュレーションすることは不可能です。`400000`シャツ。 多くの可能な再配置を試みるソリューションは、非常に遅くなります。 唯一の意味のある決定が 2 つのスタック トップの避けられない動きであるような表現を見つける必要があります。 

便利なエッジケースは、1 つのスタックが空の場合です。 例えば：```
0
1 2 3
```答えは`0`なぜなら、すべてのシャツはすでに唯一のスタックからアクセスできるからです。 両方のスタックに常に最上位のシャツがあると想定する実装は、ここで失敗する可能性があります。 

もう 1 つのエッジ ケースは、必要なシャツが 2 番目のスタックからすぐにアクセスできる場合です。```
1 2
3
```答えは`0`シャツだから`1`最初のスタックとシャツの上にあります`2`必要になった後は 2 番目のスタックの一番上にあります。 1 つのスタック方向のみをチェックするソリューションでは、オーバーカウントが発生します。 

## アプローチ

 この強引なアイデアは、実際にスタックをシミュレートすることです。 次のシャツを取得するには、ターゲットが表示されるまでスタック間でシャツを 1 枚ずつ移動してみてください。 すべての合法的な操作が明示的にシミュレートされているため、これは正しいです。 ただし、最悪の場合、リクエストされたシャツごとに残りのシャツをほぼすべて移動する可能性があります。`O(N^2)`操作。 と`N = 400000`、これは不可能です。 

重要な観察は、シャツの相対的な循環順序が決して変わらないということです。 円の周りに最初のスタックを下から上に配置し、次に 2 番目のスタックを上から下に配置することを想像してください。 スタック間でシャツを移動すると、この円上の 2 つのスタック間の分割位置が変わるだけです。 露出した 2 枚のシャツは、この分割の隣にある 2 枚のシャツです。 

これにより、問題は円形配列での移動カットの維持に変わります。 現在のカットから要求されたシャツまでの距離を知る必要があるだけです。 シャツを脱いだ後、新しいカットは常に、残りの円の脱いだシャツの直前で終了します。 

削除後に距離を維持するために、フェンウィック ツリー内でどの元の位置がまだ生きているかを保存します。 範囲内で生きているシャツを数え、k 番目の生きている位置を見つけることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) | O(N) | 遅すぎる |
 | 循環秩序 + フェンウィック ツリー | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 循環的な順序を構築します。 最初のスタックを指定された順序で配置し、2 番目のスタックを逆の順序で追加します。 このサークル内のすべてのシャツの位置を保存します。 

現在のカットは 2 つの元のスタックの間にあります。 保管しております`cur`最初のスタックの一番上のシャツの位置として。 もう一方の露出したシャツは、次の生きた位置です。`cur`。 

1. シャツの位置ごとに 1 つを含むフェンウィック ツリーを初期化します。 

フェンウィック ツリーは、シャツをいくつか脱いだ後の現在のサークルを表します。 

1. からの背番号ごとに`1`に`N`から現在の円周距離を求めます。`cur`。 

シャツがあれば、`d`生存位置から時計回りに`cur`、その後、それを取得するには次のコストがかかります。```
min(d - 1, remaining - d)
```最初の項は、シャツが 2 番目のスタックトップになるまでカットを前方に移動することを意味します。 2 番目の項は、最初のスタック トップになるまで後退することを意味します。 

1. この最小コストを答えに追加します。 
2. フェンウィックの木からシャツを外します。 

取り外し後、設定してください`cur`シャツを脱ぐ直前のイキ位置へ。 

なぜ効果があるのか:

 循環順序不変とは、考えられるすべての動きのシーケンスがカット位置のみを変更することを意味します。 距離の式では、カットを移動するために考えられる両方の方向が考慮されます。移動するたびにカットが 1 つの位置だけ変更されるため、いずれか 1 つが常に最適になります。 シャツを削除した後は、どの方向が使用されたかに関係なく、前の位置が新しい最初のスタックのトップになるため、維持された状態は常に有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        res = 0
        while i:
            res += self.bit[i]
            i -= i & -i
        return res

    def range_sum(self, l, r):
        if l > r:
            return 0
        return self.sum(r) - self.sum(l - 1)

    def kth(self, k):
        idx = 0
        step = 1 << (self.n.bit_length() - 1)
        while step:
            nxt = idx + step
            if nxt <= self.n and self.bit[nxt] < k:
                idx = nxt
                k -= self.bit[nxt]
            step >>= 1
        return idx + 1

def solve():
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    m = a[0]
    first = a[1:]
    n = b[0]
    second = b[1:]

    circle = first + second[::-1]
    total = m + n

    pos = [0] * (total + 1)
    for i, x in enumerate(circle, 1):
        pos[x] = i

    bit = Fenwick(total)
    for i in range(1, total + 1):
        bit.add(i, 1)

    if m:
        cur = m
    else:
        cur = total

    ans = 0
    alive = total

    for x in range(1, total + 1):
        p = pos[x]

        if p == cur:
            cost = 0
        else:
            before = bit.sum(cur)
            if p > cur:
                dist = bit.range_sum(cur, p - 1)
            else:
                dist = bit.range_sum(cur, total) + bit.range_sum(1, p - 1)

            cost = min(dist - 1, alive - dist)

        ans += cost

        bit.add(p, -1)
        alive -= 1

        if alive:
            before = bit.sum(p - 1)
            if before:
                cur = bit.kth(before)
            else:
                cur = bit.kth(alive)

    print(ans)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは生きている位置を保存するため、削除と円の距離は円を再構築せずに処理されます。 の`kth`残りのシャツのうち、削除された位置の前の部分が必要であるため、シャツを削除した後にこの操作が使用されます。 

コストの表現が微妙な部分です。`dist`現在のトップからターゲットまでに生存しているポジションがいくつあるかをカウントします。 最初に露出したシャツがターゲットの場合、`dist`ゼロは別個に処理されます。 それ以外の場合は前進します`dist - 1`回は、後方に移動しながら、2 番目のスタックからそれを公開します。`alive - dist`回は最初のスタックから公開します。 

Python の整数は任意の精度であるため、累積された答えには特別な処理は必要ありません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N log N) | 各シャツは Fenwick のクエリと更新を実行します。 
| スペース | O(N) | ポジションとフェンウィックツリーを保存 |
