 ## 解決策
 ## 問題の理解

 アイランドとブリッジは、接続された無向マルチグラフを形成します。 ガンジーは、グラフの接続を維持しながら、できるだけ多くの橋を削除したいと考えています。 ブリッジの最大数を削除すると、残りのグラフには接続に必要な最小数のエッジが正確に含まれる必要があるため、残りのブリッジでスパニング ツリーが形成されます。 

考えられるすべてのスパニング ツリーの中で、カルチャ値の合計が最大値を持つスパニング ツリーのみが有効です。 クエリごとにブリッジ インデックスのセットが与えられ、少なくとも 1 つの最適なスパニング ツリーにそれらのブリッジがいくつ出現するかをカウントする必要があります。 

入力サイズにより、スパニング ツリーを明示的に構築する試みが除外されます。 グラフには約 133000 個のブリッジが含まれる可能性があるため、二次関数に近いアルゴリズムであっても不可能です。 ソートと線形に近いグラフ処理に基づいたソリューションが必要です。 

難しいケースは、文化的価値観が等しいことから生じます。 すべての値が異なる場合、最大スパニング ツリーは一意になりますが、値が等しい場合は多数の有効なツリーが作成される可能性があります。 もう 1 つのよくある間違いは、Kruskal の 1 回の実行で選択されたすべてのエッジを唯一の可能な答えとして扱うことです。 このクエリは、エッジが任意の最大スパニング ツリーに出現できるかどうかを尋ねます。 

例えば：```
1
3 3
1 2 5
2 3 5
1 3 5
1
3 1 2 3
```答えは次のとおりです。```
3
```1 つのクラスカル実行を使用する不用意な実装では、エッジが 2 つだけ保持され、誤って 2 と答えてしまいます。すべてのエッジは等しい値を持つため、任意の 2 つが最大スパニング ツリーを形成し、すべてのエッジが可能になります。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのスパニング ツリーを列挙し、そのカルチャ値を計算し、最大値を保持してから、すべての最適なツリーに対してすべてのクエリ エッジをテストできます。 これは定義を直接チェックするので正しいですが、スパニング ツリーの数は指数関数的に増加する可能性があります。 エッジのサブセットのみを生成する場合でも、約 (2^b) 個の可能性が得られますが、これは最大のグラフではすでに不可能です。 

有益な観察は、最大スパニング ツリーには貪欲な構造があるということです。 Kruskal のアルゴリズムは、より大きなカルチャ値からより小さなカルチャ値までエッジを処理します。 1 つのカルチャ値について、より大きな値を持つエッジはすでに固定されています。 より大きなエッジによって形成されたコンポーネントを縮小した後、2 つの異なるコンポーネントを接続する現在の値のすべてのエッジを最適なスパニング ツリーに含めることができます。 エンドポイントがすでに接続されているエッジは、より適切なサイクル接続がすでに存在するため、決して表示されません。 

したがって、問題は、クラスカルのアルゴリズムによって許可されるすべてのエッジを見つけて、許可されたインデックスを数えることによってクエリに答えることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(b log b) | O(n + b) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての橋を文化価値の降順に並べ替えます。 最大スパニング ツリーでは、Kruskal と同じ貪欲な順序付けが使用されますが、最大の重みが最初に付けられます。 
2. 以前に処理されたすべての大きなカルチャ値によって作成された接続コンポーネントを含む、素の集合結合構造を維持します。 
3. 同じカルチャ値を持つグループで橋を処理します。 グループ内の各ブリッジについて、その 2 つのエンドポイントが現在異なる DSU コンポーネントに属しているかどうかを確認します。 そうなった場合は、可能な限り橋にマークを付けてください。 その理由は、この等値レイヤー内では、ループ以外のエッジをスパニング フォレストの一部として選択できるためです。 
4. グループ全体を確認した後、そのグループ内の、異なる現在のコンポーネントを接続するブリッジのすべてのエンドポイントをマージします。 これらのマージは、より小さい値に移動する前に、このカルチャ値を構造に追加することを表します。 
5. すべてのクエリについて、リストされたブリッジ インデックスの中で可能なものとしてマークされたものがいくつあるかを数えます。 

機能する理由: DSU は常に、厳密に大きなカルチャ値によってすでに接続されているコンポーネントを表します。 2 つの異なるコンポーネントを独自の重みで結合するエッジは、最大スパニング ツリー内の同じ重みを持つ別のエッジを置き換えることができるため、少なくとも 1 つの最適なソリューションに属します。 1 つの DSU コンポーネント内のエッジは、それより劣らないエッジを使用してサイクルを作成するため、これを含めてもスパニング ツリーを改善することはできず、最適化で必要とすることもできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n + 1))

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a != b:
            self.p[b] = a

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, b = map(int, input().split())
        edges = []

        for i in range(1, b + 1):
            x, y, c = map(int, input().split())
            edges.append((c, x, y, i))

        edges.sort(reverse=True)

        possible = [False] * (b + 1)
        dsu = DSU(n)

        i = 0
        while i < b:
            j = i
            while j < b and edges[j][0] == edges[i][0]:
                j += 1

            for k in range(i, j):
                _, x, y, idx = edges[k]
                if dsu.find(x) != dsu.find(y):
                    possible[idx] = True

            for k in range(i, j):
                _, x, y, _ = edges[k]
                dsu.union(x, y)

            i = j

        q = int(input())
        for _ in range(q):
            data = list(map(int, input().split()))
            cnt = 0
            for idx in data[1:]:
                if possible[idx]:
                    cnt += 1
            ans.append(str(cnt))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```並べ替えステップでは、同じカルチャ値をグループ化します。これは、一度に 1 つのエッジを処理すると、同じグループ内の別のエッジに誤って同じ重みのエッジが影響を与える可能性があるためです。 

DSU のマージは、グループ全体をマークした後に行われます。 この順序付けが主な実装の詳細です。 マージがすぐに行われた場合、同じカルチャ値を持つ後続のエッジが誤ってブロックされているように見える可能性があります。 

配列`possible`問題のグラフ部分の答えを保存します。 すべてのクエリの合計サイズはブリッジの数によって制限されるため、すべてのクエリはリストされたエッジを単純にスキャンできます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(b log b) | ソートが大部分を占めますが、DSU 操作はほぼ一定の償却時間になります。 
| スペース | O(n + b) | エッジ、DSU の親、および可能なフラグを格納します。 

この制約では約 133,000 のブリッジが許可されているため、ソートと DSU 処理で制限時間内に簡単に収まります。 

## 実際に動作した例

 サンプルの場合:```
4 4
1 3 40
3 4 20
1 2 30
2 4 10
```橋はすでに文化によって順序付けられています。 

| ステップ | 現在のエッジ | DSU の状態 | 可能 |
 | --- | --- | --- | --- |
 | 40 | 1-3 | {1,3} が結合されました | エッジ1 |
 | 30 | 1-2 | {1,2,3} が結合されました | エッジ3 |
 | 20 | 3-4 | {1,2,3,4} が結合されました | エッジ2 |
 | 10 | 2-4 | 同じコンポーネント | いいえ |

 有効なブリッジは 1、2、および 3 です。最初のクエリにはエッジ 2 と 4 が含まれているため、エッジ 2 のみが可能であり、答えは 1 です。2 番目のクエリにはエッジ 2 と 3 が含まれており、どちらも可能であるため、答えは 2 です。 

## 特殊なケース

 両方のエンドポイントが常に同じ DSU 代表を持つため、自己ループは自動的に拒否されます。 

ブリッジはエンドポイントではなくインデックスによって識別されるため、並列ブリッジは正しく処理されます。 同じ島を繋ぐ 2 つの橋は、文化的価値観が異なれば、異なる答えが得られる可能性があります。 

すべての橋が同じカルチャ値を持つグラフも正しく処理されます。 最初の DSU パスでは、異なるコンポーネント間のすべてのエッジが可能な限り確認されます。これは、すべてのエッジが何らかのスパニング ツリーに属することができるという事実と一致します。
