 ## 解決策
 ## 問題の理解

 料理名は、次の 3 つの要素を連結して作成されます。`TJ`、`si`、 そして`log`。 1 つの部分が出現するたびに、対応する材料の 1 回分を表します。 ピースはセパレーターなしで混ぜ合わせられており、3 つのピースがそれぞれ何回出現するかを回収することが課題となります。 

入力すると、いくつかの料理名が得られます。 各名前には長さが伴いますが、文字列自体に必要な情報がすべて含まれているため、長さは入力メタデータとしてのみ存在します。 すべての名前について、出力には次の順序で 3 つのカウントが含まれている必要があります。`TJ`、`si`、 そして`log`。 

すべての料理名の合計の長さは最大 100,000 です。つまり、アルゴリズムは各文字を一定の回数だけ処理する必要があります。 二次アプローチでは、最悪の場合、約 100000 平方の演算が実行されますが、これは必要な量をはるかに超えており、制限時間内に収まりません。 すべての文字は 3 つの有効な部分の 1 つに正確に属するため、リニア スキャンで十分です。 

主なエッジケースは、ピースの長さが異なるという事実から生じます。 不注意な解決策では、トークンではなく文字をカウントしたり、すべての小文字セグメントが同じサイズであると仮定したりする可能性があります。 

例えば：```
1
TJTJ
```正しい出力は次のとおりです。```
2 0 0
```の数を数える`T`文字を追加するか、2 文字ごとをトークンとして扱うと、ここでは偶然に機能しますが、次の点に達するとすぐに失敗します。`si`そして`log`現れる。 

別のケースは次のとおりです。```
1
silog
```正しい出力は次のとおりです。```
0 1 1
```を検索するソリューション`log`最初に 3 文字をスキップすると、誤って`si`正しいスキャン位置が維持されない場合は、その部分を取り外してください。 

最後の境界ケースは、トークンが 1 つだけ含まれる名前です。```
1
log
```正しい出力は次のとおりです。```
0 0 1
```実装では、末尾を超えて文字を読み取ろうとせずに、短い文字列を処理する必要があります。 

## アプローチ

 簡単なアプローチは、文字列内の既知の部分を繰り返し検索して削除することです。 文字列は有効であることが保証されているため、いつでも次のような分解を見つけることができます。`TJ`、`si`、 そして`log`。 取り除いたすべての部分が 1 回分に相当するため、この方法は正しいです。 

このアプローチの問題は、残りの文字列の検索と再構築が繰り返されることです。 文字列の長さが 100000 の場合、その大部分を繰り返しスキャンすると、最悪の場合、約 100000 × 100000 回の操作、つまり約 100 億文字のチェックが行われる可能性があります。 それは不必要です。 

重要な観察点は、文字列がすでに有効な部分のシーケンスとして配置されていることです。 ピースがグローバルにどこにあるかを見つける必要はありません。 左から右に移動しながら現在の駒を決めるだけです。 最初の文字によってトークンのタイプが完全に決まります。 あ`T`を始めなければなりません`TJ`、小文字が始まるのはどちらかです`si`または`log`。 小文字のトークンは 2 番目の文字で区別されます。`si`から始まる`s`そして`log`から始まる`l`。 

すべての有効な分解で同じカウントが得られるため、ブルート フォースは機能しますが、1 回のスキャンですぐに特定できる位置を再検出し続けるため、失敗します。 すべてのトークンに固有の開始パターンがあるという観察により、タスク全体を線形パーサーに減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 料理名の最初の文字から始めて、左から右に移動します。 カウンターを 3 つ維持する`TJ`、`si`、 そして`log`。 
2. 現在のキャラクターが`T`、1つ数えてください`TJ`インデックスを 2 位置前に移動します。 有効性が保証されるということは、次の文字が次の文字でなければならないことを意味します。`J`。 
3. 現在のキャラクターが`s`、1つ数えてください`si`インデックスを 2 位置前に移動します。 次の文字は次でなければなりません`i`, したがって、トークンは完全に消費されます。 
4. 現在のキャラクターが`l`、1つ数えてください`log`インデックスを 3 位置前に移動します。 次の 2 文字でトークンが完成することが保証されています。 
5. スキャンが文字列の終わりに達したら、3 つのカウンターを出力します。 

この解析が機能する理由は、2 つの有効なトークンが同じ開始文字を共有しないためです。 残りのトークンの先頭でスキャンが行われる場合、考えられる解釈は 1 つだけであるため、バックトラッキングや動的プログラミングは必要ありません。 

なぜ効果があるのか:

 スキャン中の不変条件は、現在のインデックスの前のすべての文字がすでに完全なトークンに分割されており、正しくカウントされていることです。 各ステップで、次のトークンは最初の文字によって一意に識別されるため、アルゴリズムは有効なトークンを 1 つだけ消費し、対応するカウンターを正確に増加させます。 入力は有効な料理名であることが保証されているため、スキャンでは文字列全体が消費され、各食材トークンの出現数に等しいカウンターが残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, s = input().split()

        tj = 0
        si = 0
        log = 0

        i = 0
        while i < len(s):
            if s[i] == 'T':
                tj += 1
                i += 2
            elif s[i] == 's':
                si += 1
                i += 2
            else:
                log += 1
                i += 3

        ans.append(f"{tj} {si} {log}")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```入力は次を使用して読み取られます`sys.stdin.readline`テストケースがたくさんある可能性があるからです。 この関数は各文字列を個別に処理し、答えをまとめて出力する前に保存します。 

3 つのカウンターは、必要な出力値を直接表します。 インデックス変数は、認識されたトークンの長さだけ進みます。 これを 1 つ増やすと、すでにカウントされたトークンの一部である文字を繰り返し検査することになるため、これは重要な実装の詳細です。 

入力によってすべての料理名が有効であることが保証されるため、トークンの次の文字を読み取る前に境界チェックを行う必要はありません。 整数オーバーフローは Python では問題になりません。可能な最大カウンター値は文字列の長さだけです。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []

    for _ in range(t):
        n, s = input().split()
        tj = si = log = 0
        i = 0

        while i < len(s):
            if s[i] == 'T':
                tj += 1
                i += 2
            elif s[i] == 's':
                si += 1
                i += 2
            else:
                log += 1
                i += 3

        out.append(f"{tj} {si} {log}")

    return "\n".join(out)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    result = solve()
    sys.stdin = old_stdin
    return result

""") == "5 0 0", "sample 1"

assert run("""2

assert run("""1
2 TJ
""") == "1 0 0", "single TJ token"

assert run("""1
3 log
""") == "0 0 1", "single log token"

assert run("""1
14 silogloglog
""") == "0 1 3", "multiple adjacent log tokens"
