 ## 解決策
 ## 問題の理解

 天使たちは、すべてのタバコに対して一定の神聖さの値を定義します。 このプロセスを観察するのに役立つ方法は、天使そのもののことを忘れて、タバコのインデックスのバイナリ表現を調べることです。 

タバコ(x)を考えて、(y=x-1)と書きます。 エンジェル (i) は、(y) の ((i-1)) 番目のビットが設定されたときに正確に (x) に触れます。 したがって、(x) がタッチされた回数は、(x-1) に設定されているビットの数と正確に一致します。または、

 [
 \オペレーター名{ポップカウント}(x-1)。 
】

 タバコに触れたタイミングは、まさにセットされたビットの位置です。 2 つのタバコのタッチ回数が同じ場合、それらのタッチ履歴は最新のタッチから逆方向に比較されます。 最初の異なるタッチは、対応するビットがより重要なタバコの後にあります。 したがって、ポップカウントが等しい紙巻きタバコの中で、(x-1) の値が大きいほど、つまり紙巻きタバコ指数 (x) が大きいほど、より神聖なものになります。 

したがって、ランキングのルール全体は非常に単純になります。 

[
 x_1 \text{ は } x_2 より神聖です
 】

 まさにいつ

 [
 \bigl(\オペレーター名{ポップカウント}(x_1-1),x_1\bigr)

 >

 \bigl(\オペレータ名{ポップカウント}(x_2-1),x_2\bigr)
 】

 辞書順に。 

各テスト ケースについて、この順序を間隔 (L,\ldots,R) に制限します。 値 (a) と (b) は、ランク (a) から (b) までを占める要素の合計を求めます。 

間隔には最大 (10^9) 個のタバコを含めることができ、(5\cdot10^4) 個のテスト ケースが存在する可能性があります。 1 つの間隔にわたる線形作業ですらすでに多すぎるのに、(O((R-L+1)\log(R-L+1))) ソートは完全に不可能です。 数値 (10^9) もバイナリでは十分小さいため、関連するすべてのインデックスは 30 ビットのみを使用します。これは、私たちが利用する構造的特性です。 

実装を静かに破壊する可能性のある境界ケースがいくつかあります。 

可能な限り最小の入力の場合、```
1
1 1 1 1
```タバコは(1)だけなので、答えは(1)です。 ここでは (x-1=0)、ビットがゼロに設定されています。 誤って使用してしまう実装`popcount(x)`の代わりに`popcount(x-1)`より長い間隔で間違った順序が与えられる可能性があります。 

のために```
1
1 2 1 1
```答えは(2)です。 タバコ (2) には (x-1=1) があるため、一度触れられますが、タバコ (1) には決して触れられません。 したがって、最初のランクは (2) になります。 

ポップカウントが等しい場合にも注意が必要です。 考慮する```
1
10 11 1 1
```(x-1) の対応する値は (9=1001_2) と (10=1010_2) です。 どちらにも 2 つのセット ビットがありますが、(10) の 2 回目のタッチはエンジェル (2) で発生し、(9) の 2 回目のタッチはエンジェル (1) で発生します。 したがって、タバコ (11) はより神聖であり、答えは (11) です。 タッチ数だけで並べ替えると、この比較は未解決のままになります。 

2 のべき乗の境界もよくある間違いの原因です。 のために```
1
8 9 1 2
```(x-1=7) と (8) があります。 最初のものには 3 つの設定ビットがあり、2 つ目には 1 つの設定ビットがあるため、順序は (8,9) となり、答えは (17) になります。 タバコのインデックス自体をバイナリ値として扱うと、タッチ数が変化し、誤った結果が生成されます。 

## アプローチ

 直接的な解決策は、間隔内のすべてのタバコを検査し、その神聖性キーを計算し、すべてのキーをソートし、要求されたランクを合計することです。 実際に天使をシミュレートしてキーを計算するには、(10^9<2^{30}) であるため、タバコごとに約 30 ビットのチェックが必要になります。 長さ (10^9) の間隔の場合、ソート前の基本チェックは約 (3\cdot10^{10}) 回になります。 結果として得られる 10 億個の値を並べ替えるには、さらに大まかに (10^9\log_2(10^9))、または約 (3\cdot10^{10}) 回の比較が必要になります。 このアプローチは時間制限とリモートで互換性がなく、(5\cdot10^4) 個のテスト ケースの線形スキャンを繰り返すことさえ不可能です。 

二項観測により問題は完全に変わります。 タバコを列挙する必要は決してありません。 区間内で設定されたビット数が指定された数を数えて合計するだけで済みます。

残りのタスクは、1 つのグループの一部のみを選択することです。 グループは (y) の降順で順序付けされているため、二分探索で境界値を見つけることができます。 それぞれのカウントまたは合計クエリは、30 ビットの数値を 2 つの 15 ビットの半分に分割することに基づく小規模な前処理スキームの後に、一定時間にすることができます。

[
 y=h\cdot2^{15}+l。 
】

 [

 ## アルゴリズムのチュートリアル

 1. すべてのタバコのインデックス (x) を (y=x-1) に変換します。 エンジェル (i) は、(y) のビット (i-1) が 1 のときに正確に (x) にタッチするため、タッチ数は次のようになります。`popcount(y)`。 タッチ数が等しい場合、最新のイベントからのタッチ履歴を逆方向に比較することは、(y) を数値的に比較することと同等です。 したがって、順序はポップカウントが減少し、次に減少 (y) します。 
2. クエリ間隔を (A=L-1) ～ (B=R-1) として表します。 これらの (y) 値を完全に処理し、その合計をタバコのインデックスに変換する場合にのみ 1 を追加します。 
3. (15) ビットを使用して、すべての (y) を上位半分と下位半分に分割します。 
[
 y=(h\ll15)+l。 
】
 考えられるすべての下位エンドポイントについて、すべてのポップカウントの 15 ビット数値がいくつ出現するか、およびそれらの合計はいくらになるかを事前計算します。 
4. 完全な上位ブロックについて同じ情報を事前計算します。 高位部分 (h) を含む完全なブロックには、(0) から (2^{15}-1) までのすべての低位値が含まれます。 下位部分に (j) ビットが設定されている場合、完全なブロックが寄与します。 
[
 \binom{15}{j}
 】
 事前計算により下位部分の合計が判明している数値。 
5. これらの表を使用して、一定時間内の固定ポップカウント (c) を持つ数値 (y\le X) のカウントと合計を答えます。 (h) より前の完全なブロックは上位テーブルから直接取得されます。 最後の部分ブロックは、下位プレフィックス テーブルから取得され、次のようにシフトされます。`popcount(h)`。 
6. クエリ間隔については、(B) のプレフィックス情報から (A-1) のプレフィックス情報を減算します。 これにより、`cnt[c]`、popcount (c) による間隔値の数、および`sm[c]`、それらの合計 (y) 合計。 
7. 最初 (k) 個の最も神聖なタバコの合計を計算するには、ポップカウントを (30) から (0) までスキャンします。 グループ全体が最初 (k) 位に収まる場合は、その完全な合計を加算します。 それ以外の場合は、このグループの一部のみが必要であり、グループは降順 (y) で順序付けされているため、残りの最大値が必要になります。 
8. グループに (n) 個の値が含まれており、その最大の (t<n) 値が必要だとします。 同様に、最小 (n-t) 値を削除できます。 区間内で ((n-t)) 番目に小さい (y) を二分探索します。 fix-popcount プレフィックス カウント クエリは、候補に十分な値が含まれているかどうかを示すため、各二分探索ステップは定数時間になります。 
9. ランク (b) のプレフィックス合計を計算し、ランク (a-1) のプレフィックス合計を減算します。 この差は、要求されたランク (a) から (b) の合計と正確に一致します。 

なぜそれが機能するのか。 重要な不変条件は、すべてのタバコが正確に 1 つのポップカウント グループに属し、すべてのグループが厳密にポップカウントの降順で発生することです。 1 つのグループ内で、タッチ履歴が最新のエンジェルから後方に比較されます。これはまさに、バイナリ表現を最上位ビットから下に向かって辞書順に比較することになります。 ポップカウントは固定であるため、この比較は数値の降順と同等です。 したがって、前処理により、最終的なランキングにおけるすべての連続ブロックの正確なサイズと合計が得られます。 要求されたプレフィックスが 1 つのブロック内で終了する場合、二分探索により、必要な数値サフィックスの境界が正確に特定されます。 したがって、プレフィックスの合計に含まれるすべての要素は正確に正しいランクを持ち、そのプレフィックス以外の要素は含まれません。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

BITS = 15
BLOCK = 1 << BITS
MAX_Y = 10**9 - 1
MAX_HIGH = MAX_Y >> BITS
MAX_POP = 30

# Binomial coefficients C(15, k).
comb = [1] * (BITS + 1)
for i in range(1, BITS + 1):
    comb[i] = comb[i - 1] * (BITS - i + 1) // i

# For all 15-bit values, grouped by popcount:
# full_cnt[k] = number of values in [0, BLOCK-1] with popcount k
# full_sum[k] = their sum
full_cnt = comb[:]
full_sum = [0] * (BITS + 1)
for k in range(1, BITS + 1):
    full_sum[k] = ((BLOCK - 1) * comb[k - 1] * k) // BITS

# Low-half prefix tables.
# low_cnt[k][x] = count of v <= x with popcount(v) = k
# low_sum[k][x] = sum of those v
low_cnt = [array('I', [0]) * BLOCK for _ in range(BITS + 1)]
low_sum = [array('Q', [0]) * BLOCK for _ in range(BITS + 1)]

low_pop = [0] * BLOCK
for x in range(BLOCK):
    low_pop[x] = x.bit_count()

for k in range(BITS + 1):
    cnt = 0
    sm = 0
    ac = low_cnt[k]
    ass = low_sum[k]

    for x in range(BLOCK):
        if low_pop[x] == k:
            cnt += 1
            sm += x
        ac[x] = cnt
        ass[x] = sm

# High-block prefix tables.
#
# high_cnt[k][h] = number of y in complete blocks with high part < h
#                  having popcount k.
# high_sum[k][h] = corresponding sum of y.
#
# h itself is an exclusive endpoint.
HIGH_SIZE = MAX_HIGH + 1

high_cnt = [array('I', [0]) * HIGH_SIZE for _ in range(MAX_POP + 1)]
high_sum = [array('Q', [0]) * HIGH_SIZE for _ in range(MAX_POP + 1)]

high_pop = [h.bit_count() for h in range(MAX_HIGH)]

for k in range(MAX_POP + 1):
    cnt = 0
    sm = 0
    ac = high_cnt[k]
    ass = high_sum[k]

    for h in range(MAX_HIGH):
        j = k - high_pop[h]

        if 0 <= j <= BITS:
            c = full_cnt[j]
            cnt += c
            sm += h * BLOCK * c + full_sum[j]

        ac[h + 1] = cnt
        ass[h + 1] = sm

def prefix_distribution(x):
    """Return counts and sums by popcount for all y in [0, x]."""
    if x < 0:
        return [0] * (MAX_POP + 1), [0] * (MAX_POP + 1)

    h = x >> BITS
    l = x & (BLOCK - 1)
    hp = h.bit_count()

    cnt = [0] * (MAX_POP + 1)
    sm = [0] * (MAX_POP + 1]

    for k in range(MAX_POP + 1):
        c = high_cnt[k][h]
        s = high_sum[k][h]

        j = k - hp
        if 0 <= j <= BITS:
            lc = low_cnt[j][l]
            ls = low_sum[j][l]
            c += lc
            s += ls + h * BLOCK * lc

        cnt[k] = c
        sm[k] = s

    return cnt, sm

def count_sum_upto(x, k):
    """Count and sum y <= x with popcount(y) = k."""
    if x < 0:
        return 0, 0

    h = x >> BITS
    l = x & (BLOCK - 1)
    hp = h.bit_count()

    cnt = high_cnt[k][h]
    sm = high_sum[k][h]

    j = k - hp
    if 0 <= j <= BITS:
        lc = low_cnt[j][l]
        ls = low_sum[j][l]
        cnt += lc
        sm += ls + h * BLOCK * lc

    return cnt, sm

def sum_largest_in_group(A, B, k, total_count, total_sum, take):
    """
    Sum the 'take' largest y in [A, B] having popcount k.
    The group is ordered increasingly by y here, so we remove
    the smallest total_count - take values.
    """
    if take == 0:
        return 0
    if take == total_count:
        return total_sum

    remove = total_count - take

    base_count, base_sum = count_sum_upto(A - 1, k)

    lo = A
    hi = B

    # Find the remove-th smallest value.
    while lo < hi:
        mid = (lo + hi) // 2
        c, _ = count_sum_upto(mid, k)
        c -= base_count

        if c >= remove:
            hi = mid
        else:
            lo = mid + 1

    _, boundary_sum = count_sum_upto(lo, k)
    smallest_sum = boundary_sum - base_sum

    return total_sum - smallest_sum

def prefix_holiest(A, B, need, cnt, sm):
    """
    Sum the first 'need' holiest cigarettes in [A+1, B+1],
    where A and B are y=x-1 endpoints.
    """
    if need <= 0:
        return 0

    answer = 0
    remaining = need

    for k in range(MAX_POP, -1, -1):
        group_count = cnt[k]
        if group_count == 0:
            continue

        if remaining >= group_count:
            answer += sm[k]
            remaining -= group_count

            if remaining == 0:
                break
        else:
            answer += sum_largest_in_group(
                A, B, k, group_count, sm[k], remaining
            )
            break

    # Convert the selected y values into cigarette indices x=y+1.
    return answer + need

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        L, R, a, b = map(int, input().split())

        A = L - 1
        B = R - 1

        right_cnt, right_sum = prefix_distribution(B)
        left_cnt, left_sum = prefix_distribution(A - 1)

        cnt = [0] * (MAX_POP + 1)
        sm = [0] * (MAX_POP + 1)

        for k in range(MAX_POP + 1):
            cnt[k] = right_cnt[k] - left_cnt[k]
            sm[k] = right_sum[k] - left_sum[k]

        result_b = prefix_holiest(A, B, b, cnt, sm)
        result_a = prefix_holiest(A, B, a - 1, cnt, sm)

        out.append(str(result_b - result_a))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初の前処理ブロックは、15 ビットの二項係数を構築します。 正確に (k) 個のビットが設定された 15 ビット値のグループには、(\binom{15}{k}) 個の要素が含まれます。 対応する合計は、15 ビット位置のすべてが正確に (\binom{14}{k-1}) 個の値で発生することを観察することによって取得されます。 

下位半分のテーブルには、(0) から (32767) までのすべてのエンドポイントの正確なプレフィックス情報が保存されます。 15 ビット値に対して可能なポップカウントは 16 個しかないため、これらのテーブルは小さいです。 

上位半分のテーブルは完全なブロックを表します。`high_cnt[k][h]`高位部分が以下の完全なブロックをすべて含みます。`h`。 この排他的な規則により、プレフィックス クエリがクリーンになります: 要求された値に上位部分が含まれる場合`h`、前のブロック`h`完成していて、ブロックの下の部分だけです`h`特別な処理が必要です。 

機能`prefix_distribution`これら 2 つの部分を組み合わせます。 高い部分が寄与する場合`hp`ビットを設定してから、下位部分を`j`ビットを設定すると、合計ポップカウントが得られます`hp + j`。 その数値は`h * BLOCK + low`、追加事項を説明します`h * BLOCK * count`合計の項。 

間隔分布は、2 つのプレフィックスを減算することによって取得されます。 (A=L-1) が最初の (y) であり、厳密に (A) より前の値が必要なため、この減算では元のタバコ座標の (L-2) を使用する必要があります。`prefix_holiest`タッチカウントが主な神聖さの基準であるため、ポップカウントを最大から最小の順に処理します。 1 つのポップカウント グループ内では、最大の数値が最初に来るため、`sum_largest_in_group`数値的に昇順のグループの必要なサフィックスを選択します。 

二分探索では、実際の値を構築するのではなく、fixed-popcount count 関数を使用します。 検索間隔は両側を含み、条件は`c >= remove`少なくとも必要な数の小さい要素を含む最初の値を検索します。 したがって、その境界における合計には、正確に最小値が含まれます。`remove`(A) の前のプレフィックスを減算した後の要素。 

Python の整数には任意の精度があるため、合計がオーバーフローする危険はありません。 前処理に使用される配列では、カウントには符号なし 32 ビット整数が、合計には符号なし 64 ビット整数が使用されるため、数値範囲全体をカバーしながらメモリ使用量が少なく抑えられます。

 | プロセスグループ | 0 | 0 | 0 | 1 | 1 | 0 |
 | タバコインデックスに変換 | 0 | 0 | 0 | 1 | 0 | 1 |

 選択された (y) 合計はゼロですが、選択されたすべての (y) はタバコ (y+1) に対応します。 したがって、答えは (0+1=1) となります。 

サンプル 2 の最初のクエリの場合、間隔は (2) ～ (11) であるため、(y) の範囲は (1) ～ (10) になります。 グループは

サンプル 2 の 3 番目のクエリの場合、間隔は (2) ～ (17) で、(y=1) ～ (16) に対応します。 注文の始まりは、

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 前処理時間 | (O(30\cdot2^{15})) | ポップカウントの低いプレフィックス テーブルと高いポップカウント プレフィックス テーブルを構築します。 
| テストケースごと | (O(30+\log 10^9)) | 2 つのディストリビューション、2 つのプレフィックス スキャン、および最大 2 つの 30 ステップのバイナリ検索 |
 | 合計時間 | (O(30\cdot2^{15}+T\log 10^9)) | 共有前処理とすべてのテスト ケース |
 | スペース | (O(30\cdot2^{15})) | Popcount カウントと合計テーブル |

 前処理は 1 回だけ実行されます。 (5\cdot10^4) のテスト ケースの場合、クエリ作業は数百万回の小さなテーブル操作と、要求されたプレフィックスごとに約 30 回のバイナリ検索反復だけです。 これにより、10 億本近くの紙巻きタバコを含む間隔の重要な要件である (R-L+1) への依存が回避されます。 

## テストケース

 次のテスト ハーネスは、直接のブルート フォース オラクルを使用します。 これは送信ではなく検証を目的としているため、意図的に単純になっています。```python
import io
import sys

def run(inp: str) -> str:
    data = io.StringIO(inp)
    t = int(data.readline())
    answers = []

    for _ in range(t):
        L, R, a, b = map(int, data.readline().split())

        values = list(range(L, R + 1))
        values.sort(
            key=lambda x: ((x - 1).bit_count(), x),
            reverse=True
        )

        answers.append(str(sum(values[a - 1:b])))

    return "\n".join(answers)

# Provided samples
assert run(
    """1
1 1 1 1
"""
) == "1", "sample 1"

assert run(
    """3
2 11 6 8
2 11 1 1
2 17 12 14
"""
) == "18\n8\n31", "sample 2"

# Minimum interval
assert run(
    """1
1 1 1 1
"""
) == "1", "minimum-size input"

# Using x-1 instead of x must be handled correctly.
assert run(
    """1
1 2 1 1
"""
) == "2", "x-1 popcount boundary"

# Equal popcount, where numerical order breaks the tie.
assert run(
    """1

"""
) == "11", "equal-popcount ordering"

# Crossing a power of two changes the touch count sharply.
assert run(

# Large index, testing the upper numeric boundary.

 ## 特殊なケース

 最低限の入力に関しては```
1
1 1 1 1
```(A=B=0) があります。 メンバーを持つ唯一のグループは、popcount 0 で、count 1 と sum 0 です。 最初の最も神聖な接頭辞によってその 1 つの値が選択され、最後の変換によって 1 が追加されて (1) が生成されます。 

のために```
1
1 2 1 1
```変換された区間は (y=0,1) です。 Popcount-one グループには (y=1) が含まれるため、(y=0) を含む Popcount-zero グループより前に処理されます。 したがって、最初のランクはタバコです (1+1=2)。 これにより、コンピューティングでよくある間違いがわかります`popcount(x)`の代わりに`popcount(x-1)`。 

のために```
1
10 11 1 1
```変換された値は (9=1001_2) と (10=1010_2) です。 どちらも2タッチです。 両者の最新のタッチは angel (4) であるため、比較は前のタッチに移ります。 天使 (2) が (10) に触れ、天使 (1) が (9) に触れました。 したがって、(10) は (9) よりも神聖であり、タバコ (11) がランク 1 であることに対応します。 

のために```
1
8 9 1 2
```変換された値は (7=111_2) と (8=1000_2) です。 タッチ数はそれぞれ 3 回と 1 回です。 ポップカウント 3 のタバコは、その数値が小さいかどうかに関係なく最初に来なければならず、順序 (8,9) と答え (17) が与えられます。 

最大インデックスについては、```
1
1000000000 1000000000 1 1
```変換された値は (999999999) ですが、それでも 30 ビットに収まります。 前処理テーブルとルックアップ テーブルは、(10^9-1) までのすべての可能な変換値をカバーするため、シングルトン間隔は特別なケースなしで処理され、答えは正確に (1000000000) になります。 

次のような部分的なグループの場合、```
1
1 4 2 3
```変換された値は (0,1,2,3) です。 彼らのポップカウントは (0,1,1,2) であるため、タバコの順序は (4,3,2,1) になります。 ランク(2)と(3)は(3)と(2)で(5)となります。 このアルゴリズムは、popcount-2 グループ全体を消費した後、popcount-1 グループに到達し、部分グループ選択ルーチンを使用して必要な最大値を正確に取得します。
