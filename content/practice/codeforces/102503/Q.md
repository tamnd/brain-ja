 ## 解決策
 # 問題の理解

 うちには根が生えた木があります。 各ノードには子の順序付きリストがあります。 ステートメント内のプログラムは、通常の深さ優先トラバーサルをもう実行しません。ノードがそのすべての子を終了した後、そのノードをもう一方の端からリストに戻します。 タスクは、結果として得られる無限シーケンス内のいくつかの非常に大きな位置に出力される値を決定することです。 

入力は、ノード 1 をルートとするツリーを記述します。 すべてのノードについて、順番にアクセスされる子がわかっています。 ツリーの説明の後に、各クエリは無限の出力シーケンス内の位置を示します。 クエリの答えは、その位置に出力されるノード番号です。 

難しいのは木のサイズではありません。 ツリーにはノードが 50 個しかないため、二次前処理であっても問題はありません。 ただし、位置には最大 100 桁を含めることができるため、クエリ位置に到達するまでシーケンスを生成できなくなります。 プロセス自体の中に繰り返し構造を見つける必要があります。 

不注意に実装すると、いくつかの細かい点で失敗する可能性があります。 単一ノードのツリーが良い例です。```
Input
1 3
0
1
2
100000000000000000000
```出力は次のとおりです。```
1
1
1
```すべてのノードが最終的に別のノードに移動することを想定したソリューションは、リーフが繰り返しスケジュールを実行するため失敗します。 

もう 1 つのよくある間違いは、完全な両端キューではなく、出力されたノードのみをシミュレートすることです。 例えば：```
Input
2 5
1 2
0
1
2
3
4
5
```出力は次のとおりです。```
1
2
1
2
1
```次に出力されるノードは、以前に出力された値だけでなく、両端キューに格納されている保留状態にも依存します。 内部状態を忘れると、間違ったサイクルが発生します。 

# アプローチ

 簡単なアプローチは、プログラムを直接シミュレートすることです。 ペアの両端子を保持します`(node, child_index)`、正確な操作を実行し、印刷されたすべてのノードを記録します。 これは文字通りオリジナルのプログラムであるため、これは正しいです。 この問題は、クエリが位置などを要求するときに発生します。`10^100`; シミュレーションには不可能な数の操作が必要になります。 

有益な観察は、プログラムには無限のメモリがないということです。 将来に影響を与える唯一の情報は、現在の両端キューの内容です。 デキューの状態は、ノードと子の位置を記述するペアのみで構成されます。 ツリーには最大でも 50 個のノードがあるため、可能なペアのタイプは少数しかありません。 このプロセスは決定的です。同じデック状態は常に同じ次の状態と同じ将来の出力を生成します。 

すべての遷移を簡単にシミュレートできるため、ブルート フォースは機能しますが、シーケンスの長さが膨大であるため失敗します。 最終的にデキュー状態が繰り返されるという観察により、問題を決定論的状態マシン内のサイクルを見つけることに帰着させることができます。 サイクルがわかれば、すべての巨大なクエリをそのサイクル内の対応する位置にマッピングできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(位置) | O(n) | 遅すぎる |
 | 最適 | O(C + k) | O(C) | 承認済み |

 ここ`C`反復前に到達した個別の両端キュー構成の数です。 与えられた制限を考慮すると、これは小さいです。 

# アルゴリズムのチュートリアル

 1. 現在のプログラム状態をペアのデキューとして保存します`(node, next_child_index)`。 まずはシングルペアから`(1, 0)`。 2 つの等しいデキューは同一の先物を生成するため、すべてのシミュレーション ステップの前に、デク全体をサイクル検出のキーとして使用します。 
2. 現在の両端キュー状態はこれまでに出現したことがありませんが、生成されたシーケンス内のその位置を覚えておいてください。 右側から要素を削除し、そのノード番号を応答シーケンスに追加し、元のプログラムとまったく同じ両端キュー更新を実行します。 
3. 以前に確認されたデキュー状態が現れたら、生成されたシーケンスをプレフィックスと繰り返しサイクルに分割します。 このデキュー状態が最初に発生すると、サイクルの開始がマークされます。 
4. すべてのクエリ位置について、位置がその内側にある場合はプレフィックスを直接使用します。 それ以外の場合は、サイクル開始を減算し、サイクル長によるモジュロを使用してサイクル内の同等の位置を見つけます。 

これが機能する理由は、deque 遷移の決定論的な性質です。 deque 構成には、今後のすべての操作を決定するために必要なすべての情報が含まれています。 同じ構成が 2 回出現すると、その後の一連の構成と出力されたノードを永久に繰り返す必要があります。 

# Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    children = [[] for _ in range(n + 1)]
    for i in range(1, n + 1):
        data = list(map(int, input().split()))
        children[i] = data[1:]

    queries = [input().strip() for _ in range(k)]

    q = deque()
    q.append((1, 0))

    seen = {}
    order = []

    while True:
        state = tuple(q)
        if state in seen:
            cycle_start = seen[state]
            break

        seen[state] = len(order)

        node, idx = q.pop()
        order.append(node)

        if idx != len(children[node]):
            q.append((node, idx + 1))
            q.append((children[node][idx], 0))
        else:
            q.appendleft((node, 0))

    cycle_len = len(order) - cycle_start

    ans = []
    for s in queries:
        pos = int(s) - 1
        if pos < len(order):
            ans.append(str(order[pos]))
        else:
            pos = cycle_start + (pos - cycle_start) % cycle_len
            ans.append(str(order[pos]))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```コード内の両端キューは、元のプログラムと同じ構造です。 ペアは次のように削除されます`pop()`元のプログラムが使用しているため、`pop_right`。 2 つの可能な更新は直接コピーされます。未完了のノードは継続をプッシュし、次に次の子をプッシュしますが、完了したノードは左側に挿入されます。 

タプル変換は実装の重要な詳細です。 可変の両端キューは辞書キーとして使用できないため、現在の内容は不変のタプルに変換されます。 Python 整数は 100 桁のクエリ値を自動的に処理するため、特別な大きな整数の処理は必要ありません。 

サイクル マッピングは内部でゼロベースのインデックスを使用します。 クエリは最初に 1 減らされ、次にプレフィックスの外側の位置がサイクル内でラップされます。 これにより、サイクルの正確な最初の要素に関する 1 つずつ異なる間違いが回避されます。

# 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(C + k) | それぞれの一意の deque 状態を 1 回シミュレートし、各クエリに 1 回応答します。 |
 | スペース | O(C) | 保存された状態と生成されたシーケンスは、サイクル検出プロセスに比例します。 |

 # エッジケース

 単一ノード ツリーの場合、唯一のデキュー状態は次のとおりです。`(1,0)`。 すべてのステップでノード 1 が出力され、同じ状態が両端キューに戻されます。 サイクルの長さは 1 であるため、すべてのクエリは同じ値にマップされます。 

ノードに複数の子があるツリーの場合、アルゴリズムは、アクセス後に子が消えるとは想定しません。 各継続ペアは、処理されるまで両端キュー内に残ります。 これが、現在のノードだけではなく完全なデック状態が保存される理由です。 

クエリ値が非常に大きい場合、アルゴリズムは要求された位置までカウントアップしようとしません。 サイクルの開始と長さがわかったら、次のような値が得られます。`10^100`サイクル長に対する除算とモジュロを使用して削減され、シーケンスの繰り返し部分に同じ位置が生成されます。
