 ## 解決策
 ## 問題の理解

 日誌には工場の状態が時系列で記載されています。 ログが開始される前に、すべての従業員を識別するための 2 つの方法 (役職と名前からなる完全な ID とニックネーム) が与えられます。 ログには、従業員の入場、従業員の退出、デモの発生、および特定の従業員が現在屋内にいるかどうかを尋ねるクエリが含まれます。 

タスクはログを順番に処理することです。 デモが発生した場合、工場内の現在の従業員数が必要になります。 クエリが表示されたら、参照されている従業員が現在存在するかどうかを判断し、出力する必要があります。`FOUND`または`404`。 

最初の課題は、同じ人物が 2 つの異なる形式で現れる可能性があることです。 たとえば、従業員は次のように入力できます。`Sir Richard`その後、次を使用して検索されます`the Knight`。 これら 2 つの文字列は、同じ内部状態を参照する必要があります。 

最大の入力には、最大 100,000 人の従業員と 100,000 のログ エントリが含まれます。 2 秒の制限時間では、全従業員または現在活動しているすべての人々を繰り返しスキャンするアルゴリズムは遅すぎます。 クエリごとに 100,000 のオペレーションを実行するソリューションでは、約 10^10 のオペレーションに達する可能性があり、これは Python が処理できる範囲をはるかに超えています。 意図したアプローチでは、各ログ行をほぼ一定の時間で処理する必要があります。 

いくつかの詳細により、単純な実装では誤った答えが生じる可能性があります。 間違いの 1 つは、ログに表示された正確なテキストのみを保存することです。 例えば：```
Sir Richard the Knight
----------
+ Sir Richard
FIND the Knight
END
```正しい出力は次のとおりです。```
FOUND
```治療するプログラム`Sir Richard`そして`the Knight`無関係な文字列は誤って出力されるため`404`。 

もう 1 つの問題は、従業員数が正しく更新されないことです。 考慮する：```
Sir Alice the Cat
----------
+ Sir Alice
UNION
- the Cat
UNION
END
```正しい出力は次のとおりです。```
1
0
```最初のデモはアリスが中にいるときに起こります。 2 つ目は、同じ従業員が退職した後に発生します。 ニックネームを名前とは別にカウントすると、同じ人物が 2 回カウントされてしまいます。 

最後のエッジケースは、何も動かさずにデモンストレーションを繰り返すことです。```
Sir Bob the Dog
----------
UNION
UNION
END
```出力は次のとおりです。```
0
0
```ソリューションは、現在の状態からのすべてのクエリに答える必要があります。 以前のデモンストレーションは状態を消費したり変更したりしません。 

## アプローチ

 簡単な解決策は、現在一部の従業員を屋内に留めておくことです。 毎回、`+`イベントが表示されると、その従業員を追加します。`-`イベントが発生した場合、その従業員を削除します。 クエリの場合、セットを検索して従業員が存在するかどうかを確認します。 これは正しいです。ログの一貫性が保証されているため、セットは内部の人々を正確に表しています。 

問題は、従業員を適切に配置しない場合の検索コストです。 アクティブな従業員のリストを使用すると、すべてのクエリですべての従業員を検査できます。 最悪の場合、従業員が 100,000 行、ログ行が 100,000 行あるため、約 10^10 の比較が行われます。 

重要な観察点は、ログを処理する前に従業員リストが固定されていることです。 すべての従業員に内部識別子を一度割り当てることができます。 フルネーム形式とニックネーム形式の両方を同じ識別子にマッピングできます。 その後、問題の動的部分は、各識別子がアクティブであるかどうかの問題のみになります。 

ハッシュ マップは、ログ内のテキストから識別子への一定時間の変換を行います。 ブール配列またはセットには、現在どの識別子が入っているかが格納されます。 また、当社では現役従業員のカウンターも維持しています。`UNION`イベントは現在のグループのサイズのみを要求します。 

この強引なアプローチは工場を直接シミュレートするため機能しますが、従業員の身元を再発見したり、無関係な多くの人々を検索したりするのに時間がかかります。 ID を整数 ID に圧縮できるという観察により、すべてのイベントが一定時間更新されるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(e * n) | O(e) | 遅すぎる |
 | 最適 | O(e + n) | O(e) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 従業員リストを読み取り、すべての従業員に一意の整数 ID を割り当てます。 可能な参照、完全なタイトル名形式とニックネーム形式の両方を、その ID を指す辞書に保存します。 

アルゴリズムの残りの部分では、従業員文字列を再度比較する必要はありません。 ログ内のすべての参照は、すぐに整数ルックアップになるはずです。 

1. 各従業員 ID が現在内部にあるかどうかを記録するデータ構造を作成します。 最初は従業員全員が外に出ています。 

ログは時系列であるため、現在の状態はすでに処理されたイベントにのみ依存します。 

1. までログの各行を読み取ります。`END`。 

エントリ イベントの場合は、従業員 ID を見つけてアクティブとしてマークします。 現在のカウントを増やします。 

終了イベントの場合は、従業員 ID を見つけて非アクティブとしてマークします。 現在のカウントを減らします。 

のために`UNION`イベントの場合、現在のカウントを出力します。 

のために`FIND`イベントを実行するには、参照を ID に変換し、その ID のアクティブ状態を確認します。 

1. 出力が必要なイベントが出現するのと同じ順序で回答を出力します。 

不変条件は、ログのプレフィックスを処理した後、アクティブな配列がその時点で工場内に物理的にいる従業員を正確に表すということです。 入退出イベントはログに従って 1 人の従業員を更新しますが、クエリ イベントは状態を読み取るだけです。 名前とニックネームの両方が同じ ID にマップされるため、すべてのクエリで正しい従業員が観察されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    ref = {}
    active = []
    emp_count = 0

    while True:
        line = input().rstrip("\n")
        if line == "----------":
            break
        parts = line.split()
        title = parts[0]
        name = parts[1]
        nick = parts[2]
        ref[title + " " + name] = emp_count
        ref["the " + nick] = emp_count
        emp_count += 1

    active = [False] * emp_count
    inside = 0
    ans = []

    while True:
        line = input().rstrip("\n")
        if line == "END":
            break

        if line == "UNION":
            ans.append(str(inside))
        elif line[0] == '+':
            key = line[2:]
            idx = ref[key]
            if not active[idx]:
                active[idx] = True
                inside += 1
        elif line[0] == '-':
            key = line[2:]
            idx = ref[key]
            if active[idx]:
                active[idx] = False
                inside -= 1
        else:
            key = line[5:]
            idx = ref[key]
            if active[idx]:
                ans.append("FOUND")
            else:
                ans.append("404")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```辞書構築フェーズでは、アイデンティティの問題を処理します。 各従業員は 1 つの ID を受け取り、両方の表現がその ID を指します。 辞書キーとして使用される文字列は、ログに表示される形式とまったく同じです。 

の`active`配列には現在の工場出荷時の状態が保存されます。 すべての従業員はすでにコンパクトな数値インデックスを持っているため、ブール配列で十分です。 の`inside`変数は、実行中の配列のスキャンを回避します。`UNION`。 

更新の順序は重要です。 エントリでは従業員をアクティブ化した後にカウントが増加し、終了では従業員を削除した後にカウントが減少します。 この問題により、無効な削除が発生しないことが保証されるため、チェックは防御的なものにすぎません。 

Python の整数はオーバーフローせず、可能な最大数は 100000 のみです。すべての操作で辞書検索または配列アクセスが使用されるため、解は必要な制限内に保たれます。

UNION
