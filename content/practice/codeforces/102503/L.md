 ## 解決策
 ## 問題の理解

 ボックスをラインナップしております。 各ボックスには多数のボールが格納されており、開いているか閉じているかの状態もあります。 この操作により、これら 2 つの情報が一緒に変更されます。 反転操作は、範囲内のすべてのボックスを開いた状態から閉じた状態、または閉じた状態から開いた状態に変更します。 追加操作は、範囲内で現在開いているボックスにのみ影響します。 クエリ操作では、ボックスが開いているか閉じているかに関係なく、範囲内のすべてのボックス内のボールの合計数が求められます。 

入力により、初期のボール数、初期の開閉状態、そして一連の操作が与えられます。 すべてのクエリ操作について、選択した間隔の現在の合計を出力する必要があります。 

制限は十分に大きいため、影響を受けるすべてのボックスをシミュレートすることは不可能です。 最大 320,000 のボックスと 320,000 のオペレーションを使用すると、すべてのオペレーションに対して線形作業を実行するソリューションでは、最悪の場合、約 10^11 の更新が実行される可能性があります。 2 秒の時間制限では、各操作を対数時間に近づける必要があるため、配列の直接更新や間隔スキャンの繰り返しは除外されます。 

難しいのは、操作が 2 つの関連するプロパティに影響を与えることです。 ボールの数は開いたボックスでのみ変化しますが、ボックスの状態は後で反転することで変化します。 合計を保存するだけのソリューションでは、どのボックスが今後追加されるべきかを知るために必要な情報が失われます。 

不注意な実装を壊す小さなケースとしては、フリップとそれに続く追加が挙げられます。```
Input
2 3
5 7
1 0
1 1 2
2 1 2 3
3 1 2
```最初の操作では、状態が閉じた状態、開いた状態に変わります。 この追加は 2 番目のボックスにのみ影響し、値は 5 と 10 になります。答えは次のとおりです。```
15
```合計のみを保存し、すべての加算を範囲加算として扱う実装では、18 が出力されます。 

もう 1 つのエッジ ケースは、同じ間隔に複数回適用される反転です。```
Input
1 4
10
1
1 1 1
1 1 1
2 1 1 5
3 1 1
```2 回のフリップはキャンセルされるため、加算が行われるとボックスは開いた状態になります。 最終的な答えは次のとおりです。```
15
```フリップ フラグを正しく組み合わせるのを忘れた遅延伝播の実装では、ボックスが誤って閉じられたままになる可能性があります。 

最後によくある間違いは、クエリされた合計を、開いているボックスのみの合計と混同することです。```
Input
2 1
4 9
1 0
3 1 2
```答えは次のとおりです。```
13
```閉じられたボックスは依然としてクエリに寄与します。 追加のみが閉じたボックスを無視します。 

## アプローチ

 簡単な解決策は、2 つの配列を保持することです。1 つはボール数用、もう 1 つは状態用です。 反転の場合、間隔を横断してすべての状態を切り替えます。 追加として、間隔を横断し、開いているボックスのみを追加します。 クエリの場合、間隔内のすべての値を合計します。 すべての操作が問題のルールに直接従うため、これは正しいです。 

問題は、1 回の操作で 320,000 個のボックスすべてにアクセスできることです。 すべての操作が完全な間隔を使用する場合、プリミティブ アクションの数は約 320,000 × 320,000 に達する可能性があり、これはおよそ 1,020 億の更新またはクエリに相当します。 このアプローチは正しいですが、遅すぎます。 

重要な点は、操作には個別のボックスが必要ないということです。 セグメントは、開いたボックスの値の合計と閉じたボックスの値の合計という 2 つの合計を知る必要があるだけです。 加算によりオープンサムのみが変化します。 フリップは単に 2 つの和を交換するだけです。 範囲クエリには、それらを組み合わせた値が必要です。 

この構造は遅延セグメント ツリーと一致します。 各ノードは間隔を表し、子に降りることなくクエリに答えたり、更新を適用したりするのに十分な情報を格納します。 遅延反転フラグは、セグメント全体が反転されたが、その子がまだ更新されていないことを記録します。 

ブルートフォース手法は、各ボックスの正確な情報を保持するため機能しますが、あまりにも多くのボックスが繰り返しタッチされると失敗します。 反転は 2 つのグループの単なる交換であるという観察により、必要な情報を圧縮し、各操作を対数時間で処理できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n) | 遅すぎる |
 | 最適 | O((n + m) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのノードが開いたボックス内のボールの合計、閉じたボックス内のボールの合計、および間隔内の開いたボックスの数を格納するセグメント ツリーを構築します。 

開いているボックスの数が必要になるのは、`v`オープンサムを増やす必要があります`v`セグメント内の開いているボックスの数を乗算します。 
2. 範囲を追加するには、セグメント ツリーに再帰的にアクセスします。 ノードが完全に更新間隔内にある場合は、そのオープン合計を次のように直接増加させます。`v * open_count`。 

この操作は現在開いているボックスのみに影響するため、閉じたボックスは無視されます。 
3. 反転操作の場合は、セグメント ツリーに再帰的にアクセスします。 ノードが完全に間隔内に入ったら、そのオープン合計とクローズド合計を交換し、オープン数を以前に閉じたボックスの数に置き換えて、遅延反転フラグを切り替えます。 

フリップしてもボール数は変わりません。 各ボックスがどのグループに属するかを変更するだけなので、保存されている 2 つのグループを交換するだけで十分です。 
4. クエリ操作の場合、カバーされたセグメントから開始値と終了値の合計を再帰的に収集します。 

クエリでは状態に関係なくすべてのボックスがカウントされるため、答えは両方のグループの合計になります。 
5. セグメント全体が反転されるときは常に遅延伝播を使用します。 保留中のフリップは、後の操作でそれらの子を検査する必要がある場合にのみ、子にプッシュされます。 

これにより、大きな反転間隔のすべての要素にアクセスすることがなくなります。 

これが機能する理由: すべてのセグメント ツリー ノードの不変条件は、保存されている 2 つの合計が、その間隔内のボックスの現在の実際の値を常に表し、現在の状態で区切られていることです。 開いたグループのみが変更されるため、追加ではこの不変条件が維持されます。 2 つの状態グループが役割を交換する間、ボックスはその値を保持するため、反転によってそれが保持されます。 遅延伝播はこれらの有効な変換を遅らせるだけであるため、すべてのクエリでは、すべての操作が個別に適用されたかのように同じ結果が表示されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegmentTree:
    def __init__(self, values, states):
        self.n = len(values)
        size = 4 * self.n
        self.open_sum = [0] * size
        self.closed_sum = [0] * size
        self.open_cnt = [0] * size
        self.flip = [False] * size
        self.values = values
        self.states = states
        self.build(1, 0, self.n - 1)

    def build(self, node, left, right):
        if left == right:
            if self.states[left]:
                self.open_sum[node] = self.values[left]
                self.open_cnt[node] = 1
            else:
                self.closed_sum[node] = self.values[left]
            return
        mid = (left + right) // 2
        self.build(node * 2, left, mid)
        self.build(node * 2 + 1, mid + 1, right)
        self.pull(node)

    def pull(self, node):
        self.open_sum[node] = self.open_sum[node * 2] + self.open_sum[node * 2 + 1]
        self.closed_sum[node] = self.closed_sum[node * 2] + self.closed_sum[node * 2 + 1]
        self.open_cnt[node] = self.open_cnt[node * 2] + self.open_cnt[node * 2 + 1]

    def apply_flip(self, node, length):
        self.open_sum[node], self.closed_sum[node] = self.closed_sum[node], self.open_sum[node]
        self.open_cnt[node] = length - self.open_cnt[node]
        self.flip[node] = not self.flip[node]

    def push(self, node, left, right):
        if not self.flip[node] or left == right:
            return
        mid = (left + right) // 2
        self.apply_flip(node * 2, mid - left + 1)
        self.apply_flip(node * 2 + 1, right - mid)
        self.flip[node] = False

    def update_add(self, node, left, right, ql, qr, value):
        if qr < left or right < ql:
            return
        if ql <= left and right <= qr:
            self.open_sum[node] += self.open_cnt[node] * value
            return
        self.push(node, left, right)
        mid = (left + right) // 2
        self.update_add(node * 2, left, mid, ql, qr, value)
        self.update_add(node * 2 + 1, mid + 1, right, ql, qr, value)
        self.pull(node)

    def update_flip(self, node, left, right, ql, qr):
        if qr < left or right < ql:
            return
        if ql <= left and right <= qr:
            self.apply_flip(node, right - left + 1)
            return
        self.push(node, left, right)
        mid = (left + right) // 2
        self.update_flip(node * 2, left, mid, ql, qr)
        self.update_flip(node * 2 + 1, mid + 1, right, ql, qr)
        self.pull(node)

    def query(self, node, left, right, ql, qr):
        if qr < left or right < ql:
            return 0
        if ql <= left and right <= qr:
            return self.open_sum[node] + self.closed_sum[node]
        self.push(node, left, right)
        mid = (left + right) // 2
        return self.query(node * 2, left, mid, ql, qr) + self.query(node * 2 + 1, mid + 1, right, ql, qr)

def solve():
    n, m = map(int, input().split())
    values = list(map(int, input().split()))
    states = list(map(int, input().split()))

    seg = SegmentTree(values, states)
    ans = []

    for _ in range(m):
        query = list(map(int, input().split()))
        typ = query[0]
        l = query[1] - 1
        r = query[2] - 1

        if typ == 1:
            seg.update_flip(1, 0, n - 1, l, r)
        elif typ == 2:
            seg.update_add(1, 0, n - 1, l, r, query[3])
        else:
            ans.append(str(seg.query(1, 0, n - 1, l, r)))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```セグメント ツリーは、ボックスの 2 つのカテゴリを分離します。 の`open_sum`そして`closed_sum`配列は、それらのカテゴリの現在の合計値を表します。 の`open_cnt`配列を使用すると、個々のボックスを知らなくても範囲の加算を適用できます。 

フリップ操作は、リーフにアクセスせずに処理されます。 すべてのボックスが 2 つのカテゴリ間のメンバーシップを変更するため、2 つの合計が交換されます。 開いたボックスの数も、セグメントの長さから古い開いた数を引いた閉じたボックスの数と交換されます。 

2 回のフリップはフリップなしと同等であるため、遅延フリップ フラグはブール値です。 保留中のフリップを持つノードがプッシュされると、親が部分的な操作を続行する前に、両方の子が同じ変換を受け取ります。 

すべてのインデックスは、問題の 1 から始まるインデックスから Python の 0 から始まるインデックスに変換されます。 Python の整数は、最大の答えが 32 ビットの範囲を超える可能性がある場合でも、オーバーフローを回避します。

 ## 特殊なケース

 議論の最初の特殊なケースは、フリップ後の追加です。 加算が適用される前に、フリップ操作により、保存されている開いたグループと閉じたグループが交換されるため、セグメント ツリーがこれを処理します。 入力の場合:```
2 3
5 7
1 0
1 1 2
2 1 2 3
3 1 2
```ツリーはオープン数を 1 ボックスから 1 ボックスに変更しますが、オープン合計は古いクローズ合計になります。 追加は 2 番目のボックスにのみ影響し、最終結果が生成されます。`15`。 

2 番目のエッジ ケースは、同じ間隔での複数のフリップです。 遅延フラグは、奇数のフリップが保留されているかどうかを格納します。 で：```
1 4
10
1
1 1 1
1 1 1
2 1 1 5
3 1 1
```最初の反転によりノードが反転済みとしてマークされ、2 番目の反転により保留状態が削除され、ボックスは開いたままになります。 足し算を適用すると答えは次のようになります`15`。 

最後のエッジケースは、閉じたボックスをクエリすることです。 クエリ関数は常に次の値を返します。`open_sum + closed_sum`, したがって、現在の状態に依存することはありません。 のために：```
