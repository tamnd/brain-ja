 ## 解決策
 ## 問題の理解

 うちには背の高い人が4人います`v`、`a`、`r`、 そして`p`。 その中から正確に 3 人を選択し、その 3 人を組み合わせなければなりません。 結果として得られる高さは、3 つの個別の高さの合計です。 ジェットコースターは、その合計が少なくとも`h`。 

タスクは、3 人からなる 4 つのグループのうち少なくとも 1 つが必要な高さに達するかどうかを判断することです。 そのようなグループが存在する場合は、`WAW`; それ以外の場合は印刷します`AWW`。 

入力には最初の 4 行に 4 つの高さが含まれており、その後に必要な最小の高さが続きます。`h`。 すべての値は 12 ～ 150 の間であるため、値は小さく、整数演算で十分です。 さらに重要なのは、ちょうど 4 人いるということです。つまり、`C(4,3) = 4`チェックできるグループ。 直接の全数検索でも一定数の加算と比較が実行されるため、1 秒の時間制限は決して制限的なものではありません。 

条件が不注意に記述されると、誤った実装が発生する可能性のある境界ケースがいくつかあります。 まず、必要な高さに正確に到達するだけで十分です。 たとえば、高さの場合`12, 12, 12, 20`そして`h = 36`、高身長の3人を選ぶ`12, 12, 12`正確に与える`36`したがって、正しい出力は次のようになります。`WAW`。 使用する`>`の代わりに`>=`間違って印刷されてしまう`AWW`。 

2 番目のケースは、唯一の成功したグループに最も背の高い人が含まれている場合に発生します。 たとえば、高さの場合`12, 12, 12, 20`そして`h = 44`、3 つの最大の高さの合計は次のようになります。`44`、したがって、答えは次のとおりです`WAW`。 最初の 3 つの入力値のみをチェックする実装では、有効なグループが見つからなくなります。 

3 番目のケースは、最も背の高い 3 人でも身長が低すぎる場合です。 高さがある`20, 20, 20, 20`そして`h = 61`、考えられるすべてのグループには高さがあります。`60`、したがって、答えは次のとおりです`AWW`。 4人が集まれば届くという事実`80`形成された人物には正確に 3 人が含まれている必要があるため、役に立ちません。 

## アプローチ

 ブルートフォース ソリューションでは、3 人のグループごとに単純に列挙し、身長を加算し、その合計が少なくとも以下であるかどうかを確認できます。`h`。 すべての法的選択が検討されるため、これは完全に正しいです。 4人いると、まさに`C(4,3) = 4`したがって、最悪のケースでは、列挙に一定のオーバーヘッドがかかるまで、4 回の加算と 4 回の比較が必要になります。 

実際には、この強引な方法が特定の問題に対して遅すぎるということはありません。 入力人数は 4 人に固定されているため、実行時間は`O(1)`。 一般化されたバージョンでは、`n`すべてのトリプルをチェックするには時間がかかります`O(n^3)`、高価になる可能性があります。 ただし、この Codeforces の問題に関しては、`n = 4`、網羅的な方法がシンプルかつ完全に受け入れられるようになりました。 

同じ観察をさらにコンパクトに行うことができます。 3 人からなるすべてのグループの中で、可能な限り最大の合計が得られるグループは、最も背の高い 3 人で構成されます。 あの三人が届かないなら`h`、他のグループではできません。 それができるのであれば、そのグループ自体が有効な選択です。 したがって、ソートは不要ですが、4 つの高さをソートして 3 つの最大値をチェックすると、一定時間で問題が解決されます。 

直接列挙はタスクの定義を正確に反映し、問題に不要な操作の導入を避けるため、推奨されます。 重要な洞察は、検索スペースには 4 つの選択肢しか含まれていないということです。

 | --- | --- | --- | --- |
 | ブルートフォース |`O(1)`4人用 |`O(1)`| 承認済み |
 | 最も高い 3 つをチェックしてください |`O(1)`4人用 |`O(1)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 4 つの高さを配列に読み取り、必要な高さを読み取ります。`h`。 高さを揃えておくと、考えられるすべての 3 つのグループについて推論するのが簡単になります。 
2. 4 つの高さのうちの 3 つの異なる位置のすべての組み合わせを列挙します。 組み合わせは 4 つだけなので、すべての法的グループを直接チェックできます。 
3. 各組み合わせについて、3 つの高さの合計を計算し、それを次と比較します。`h`。 使用`>=`身長がちょうど許容される最低身長の人が乗ることができるためです。 
4. いずれかの合計が少なくとも`h`、すぐに印刷`WAW`。 質問では有効なグループが少なくとも 1 つ存在するかどうかが尋ねられるため、成功したグループを 1 つ見つけるだけで十分です。 
5. 4 つの組み合わせがすべて比較に失敗した場合は、次のように出力します。`AWW`。 この時点で、考えられる 3 つのグループがすべてチェックされているため、有効な取り決めは存在しません。 

### なぜ効果があるのか

 不変条件は、任意の数の組み合わせをチェックした後、チェックされたすべての組み合わせが十分に高いか低すぎるかのいずれかに正しく分類されるということです。 このアルゴリズムは、考えられる 3 つのグループすべてを 4 つ調べます。 印刷される場合`WAW`、合計が少なくとも以下であるグループが見つかりました。`h`、したがって、答えは有効です。 印刷される場合`AWW`、考えられるすべてのグループの合計は以下になります。`h`したがって、有効なグループが存在しません。 アルゴリズムはあらゆる法的な選択肢を考慮するため、解決策を見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

v = int(input())
a = int(input())
r = int(input())
p = int(input())
h = int(input())

heights = [v, a, r, p]

for i in range(4):
    for j in range(i + 1, 4):
        for k in range(j + 1, 4):
            if heights[i] + heights[j] + heights[k] >= h:
                print("WAW")
                sys.exit()

print("AWW")
```4 つの高さはリストに保存されるため、組み合わせループは均一に機能します。 3 つのネストされたループでは、`i < j < k`これにより、3 人からなる各セットが 1 回だけ考慮され、2 回選択される人が存在しないことが保証されます。 

比較には、`>= h`、形成された人の身長が正確にしきい値である可能性があるという要件に一致します。 有効なトリプルが見つかるとすぐに、`sys.exit()`残りのトリプルを調べても答えを変えることはできないため、プログラムを終了します。 

Python では整数オーバーフローの懸念はありません。固定幅の整数型を使用する言語でも、ここで考えられる最大の合計は次のとおりです。`150 + 150 + 150 = 450`。 

入力にはテスト ケースが 1 つだけ含まれているため、外部のテスト ケース ループはありません。 要求された`input = sys.stdin.readline`フォームは、効率的で標準的な競技プログラミングの入力処理に今でも使用されています。 

## 実用的な例

 ### サンプル 1

 4つの高さはすべて`20`、必要な高さは`61`。 3 つのグループはすべて同じ合計になります。 

|`i`|`j`|`k`| 選択された高さ | 合計 |`sum >= h`|
 | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 2 | 20、20、20 | 60 | いいえ |
 | 0 | 1 | 3 | 20、20、20 | 60 | いいえ |
 | 0 | 2 | 3 | 20、20、20 | 60 | いいえ |
 | 1 | 2 | 3 | 20、20、20 | 60 | いいえ |

 4 つの法的グループすべてが失敗する理由`60 < 61`。 アルゴリズムは最終段階に到達`print("AWW")`、正しい出力が生成されます。 

### サンプル 2

 高さは`24, 55, 42, 69`、 と`h = 143`。 

|`i`|`j`|`k`| 選択された高さ | 合計 |`sum >= h`|
 | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 2 | 24、55、42 | 121 | いいえ |
 | 0 | 1 | 3 | 24、55、69 | 148 | はい |

 2番目のグループはすでに到達しています`143`、アルゴリズムは次のように出力します`WAW`残りの 2 つの組み合わせを調べる必要なく終了します。 これは、有効なグループが 1 つ見つかるとすぐにアルゴリズムが停止する理由を示しています。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    heights = [int(input()), int(input()), int(input()), int(input())]
    h = int(input())

    for i in range(4):
        for j in range(i + 1, 4):
            for k in range(j + 1, 4):
                if heights[i] + heights[j] + heights[k] >= h:
                    return "WAW"

    return "AWW"

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        return solve()
    finally:
        sys.stdin = old_stdin

# Provided samples
assert run("20\n20\n20\n20\n61\n") == "AWW", "sample 1"
assert run("24\n55\n42\n69\n143\n") == "WAW", "sample 2"

# Minimum-size values, and exactly reaching the threshold.
assert run("12\n12\n12\n12\n36\n") == "WAW", "minimum values at boundary"

# Maximum-size values, with a threshold that is exactly reachable.
assert run("150\n150\n150\n12\n450\n") == "WAW", "maximum values at boundary"

# All groups are one unit short of the threshold.
assert run("20\n20\n20\n20\n61\n") == "AWW", "just below threshold"

# The only successful group contains the fourth input value.
assert run("12\n12\n12\n20\n44\n") == "WAW", "valid group uses fourth person"

print("All tests passed.")

 |`150 150 150 12, h = 450`|`WAW`| 最大値と正確なしきい値 |
