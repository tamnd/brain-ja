 ## 解決策
 ## 問題の理解

 私たちには、通常の文の中にいくつかの「動物の名前」が埋め込まれたテキストメッセージが与えられます。 各動物の名前は単語の連結として書かれ、各単語は大文字で始まり小文字が続きます。 文中には、通常の小文字の単語と並んで、スペースで区切られた複数のそのような名前が表示されます。 

文全体の長さを減らすために、一部の動物の名前を短縮することが許可されています。 短縮操作は各動物の名前に対して独立して機能します。最後の大文字のセグメントのいくつかを切り取ることができますが、名前内の単語間の境界に沿ってのみです。 名前を短縮する場合は、3 文字のマーカー「...」を追加する必要があります。 重要なのは、すべての名前を同じセグメント数だけ短縮する必要があることです。つまり、グローバル整数 k を選択し、すべての名前から末尾の大文字で始まる単語 k 個を削除します。 

目標は、最終的に再構築された文が指定された最大長 L を超えないようにしながら、できるだけ小さい k を選択することです。k を選択しても文が適合しない場合、答えは不可能です。 

それぞれの名前の構造は重要です。 名前は大文字で始まる一連の単語を貼り合わせたものであるため、その自然な分割点はまさに最初の文字の後の大文字になります。 これは、各名前には固定数のセグメントがあり、切り捨てによって常に境界から始まる接尾辞セグメントが削除されることを意味します。 

この制約は、文字列が最大 200,000 文字であることを示唆しており、k の多くの値に対して完全な候補文字列を繰り返し再構築するアプローチは除外されます。 考えられるすべての k とすべての名前に対する単純なシミュレーションでは、大きな文字列が繰り返し構築され、最悪の場合は 2 次の動作が発生します。 

微妙な特殊ケースは、異なる長さの名前から生じます。 グローバルに多くのセグメントを切り取りすぎると、一部の名前が完全に消えたり、「...」を追加する前に空になったりする可能性がありますが、それでも一貫して処理する必要があります。 もう 1 つのエッジ ケースは、k が 0 の場合に発生します。これは切り捨てがないことを意味します。その場合でも、元の文がすでに L 内に収まるかどうかを検証する必要があります。 

もう 1 つの重要な例外ケースは、長さの制約を満たす複数の最適な k 値が存在する場合です。 この問題では、有効な k だけでなく最小の k が必要であるため、検索は k において単調である必要があります。 

## アプローチ

 ブルートフォースのアイデアは、可能な限りの数の削除されたセグメント k を試してみることです。 各 k について、すべての名前のすべての単語をスキャンし、結果の短縮形を計算し、完全な文を構築し、その長さを測定します。 それが L 内に収まる場合、k を回答候補として追跡します。 

これが機能するのは、任意の固定 k に対して、結果の文字列を決定論的に計算できるためです。 ただし、コストが高い。 合計 N 文字がある場合、k ごとに出力全体を再構築すると、O(N) のコストがかかります。 k は任意の名前のセグメントの最大数と同じくらい大きくなり、場合によっては O(N) になるため、合計の複雑さは O(N^2) になり、200,000 文字には遅すぎます。 

重要な観察は、k を増加してもそれぞれの名前が短縮されるだけであるということです。 全長に対する各名前の寄与は、k の単調非増加関数です。 この単調性により、すべての値を試す代わりに、答え k を二分探索することができます。 

固定 k の場合、実際に文字列を構築する必要はありません。 長さを計算するだけで済みます。 各名前は、そのサイズを超えて切り詰められない場合はその完全長、または保持されたセグメントまでの接頭辞に「...」の 3 文字を加えたものになります。 これは、各名前内のセグメントのプレフィックス長を事前計算することで計算できます。 

次に、計算された合計の長さが ≤ L になるように最小の k を二分探索します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) | O(N) | 遅すぎる |
 | 二分探索 + 接頭辞の合計 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列をスペースで区切られたトークンに解析し、各トークンが大文字の名前であるか通常の単語であるかを保持します。 大文字の名前ごとに、大文字の部分にさらに分割します。 このステップにより、すべての名前がセグメント長の配列として得られます。 

この構造が必要なのは、切り捨てが文字境界ではなくセグメント境界で定義されるためです。 
2. 名前ごとに配列を計算します。`pref`、 どこ`pref[i]`最初の i セグメントの全長です。 これにより、名前の任意のプレフィックスを定数時間で計算できるようになります。 
3. k の上限を、すべての名前にわたるセグメントの最大数として決定します。 k を大きくすると、少なくとも 1 つの名前からすべてのセグメントが削除され、スペースが無駄になるだけです。 
4. 関数を定義する`can(k)`すべての名前から k 個のセグメントを削除した後の文の全長を計算します。 

m 個のセグメントを持つ名前ごとに次のようになります。 

- k ≥ m の場合、名前は 3 文字の「...」のみになります。 
- それ以外の場合は、最初の m − k セグメントを保持し、貢献します`pref[m − k] + 3`。 
- 名前以外の単語は、最後のトークンを除き、元の長さにスペース 1 つを加えたものになります。 
5. k を 0 から max_k まで二分探索します。 述語`can(k)`は単調です: k を増加しても全長は増加しません。 
6. 最小の k を見つけた後、同じ切り捨て規則を各名前に適用し、「...」を追加することによって最終文を再構築します。 すべてを単一のスペースで結合します。 
7. k = max_k でも length ≤ L を満たさない場合は、-1 を出力します。 

### なぜ効果があるのか

 重要な不変条件は、k ごとに計算された全長が、すべての名前を k 個のセグメントで均一に切り捨てることによって生成される有効な文字列に正確に対応することです。 切り捨てによって名前の長さが増加することはないため、全長関数は k で単調減少します。 これによりバイナリ検索の正確さが保証されます。k の値が十分であれば、それより大きな値はすべて十分なままであるため、検索空間を安全に分割できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def split_name(name):
    segs = []
    start = 0
    for i in range(1, len(name)):
        if name[i].isupper():
            segs.append(name[start:i])
            start = i
    segs.append(name[start:])
    return segs

def solve():
    S = input().rstrip('\n')
    L = int(input())

    tokens = S.split(' ')
    names = []
    words = []

    max_k = 0

    for t in tokens:
        if t and t[0].isupper():
            segs = split_name(t)
            pref = [0]
            for s in segs:
                pref.append(pref[-1] + len(s))
            names.append((segs, pref))
            max_k = max(max_k, len(segs))
            words.append(None)
        else:
            words.append(t)

    def can(k):
        total = 0
        ni = 0
        for t in tokens:
            if t and t[0].isupper():
                segs, pref = names[ni]
                ni += 1
                m = len(segs)
                if k >= m:
                    total += 3
                else:
                    total += pref[m - k] + 3
            else:
                total += len(t)
            if total > L:
                return False
        return total <= L

    if not can(max_k):
        print(-1)
        return

    lo, hi = 0, max_k
    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid):
            hi = mid
        else:
            lo = mid + 1

    k = lo

    res = []
    ni = 0
    for t in tokens:
        if t and t[0].isupper():
            segs, pref = names[ni]
            ni += 1
            m = len(segs)
            if k >= m:
                res.append("...")
            else:
                cut = pref[m - k] + 3
                # rebuild prefix up to cut segments
                cur = ""
                cnt = 0
                for s in segs:
                    if cnt == m - k:
                        break
                    cur += s
                    cnt += 1
                res.append(cur + "...")
        else:
            res.append(t)

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```名前のみが切り捨てロジックに関与するため、実装では解析中に名前を通常の単語から分離します。 の`can(k)`関数は文字列の構築を回避し、制限内に収めるために重要である長さのみを追跡します。 

実現可能条件の単調性を使用して、二分探索が k に対して適用されます。 k を見つけた後、切り捨てが名前ごとに、ただしすべての名前に均一に適用されることを注意深く考慮して、再構成が 1 回実行されます。 

微妙な点は、k がセグメント数を超える名前を処理することです。 これらは単なる「...」に折りたたまれますが、元のサイズに関係なく、正確に 3 文字が含まれます。

 ## 特殊なケース

 特殊なケースとしては、名前にセグメントが 1 つしかない場合があります。 のような入力の場合`Apple`、k = 1 の場合、名前全体が「...」に折りたたまれます。 k ≥ m は特殊なケースをトリガーし、負のプレフィックスインデックス付けを回避するため、アルゴリズムはこれを正しく処理します。 

もう一つのケースは、L が非常に小さい場合です。 例えば：```
A B
3
```最大の切り捨てを行った場合でも、各名前は「...」となり、スペースを含む合計の長さは 7 となり、L を超えます。k = max_k の実現可能性チェックではこれが検出され、正しく -1 が返されます。 

3 番目のケースは、元の文字列が切り捨てられずにすでに適合している場合です。 その状況では、単調チェックによって k = 0 がすぐに受け入れられ、二分探索では k が増加することはなく、最小性が維持されます。
