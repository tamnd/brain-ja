 ## 解決策
 ## 問題の理解

 カエルは列の最初の石からスタートします。`n`石があり、最後の石に到達したいと考えています。 通常は 1 歩前に進み、すべての石を順番に訪問します。 旅の途中で一度だけ、前方に特別なジャンプをすることができます。`k`中間の石を完全にスキップして位置を決めます。 

各石は、カエルが訪れたときのスコアに値を与えます。 カエルは常に最初と最後の石を訪問し、訪問した石の値を合計スコアに追加します。 スキップされた石は決して訪問されないため、何も貢献しません。 

タスクは、訪問された値の合計ができるだけ大きくなるように、単一のロング ジャンプを使用する場所を選択することです。 

制約は次のとおりです`n = 3 · 10^5`これは、二次時間ですべての可能なジャンプ位置を単純に試行する解決策を即座に除外します。 すべての候補位置のセグメントにわたる合計を再計算するアプローチは、最大で`O(n)`選択肢とそれぞれの費用がかかる`O(n)`仕事。 

いくつかの特殊なケースは見落とされがちです。 

もし`k = 1`、「幅跳び」は通常の動きと同じであるため、何も変化せず、答えは単にすべての値の合計になります。 

もし`k = n`、カエルは最初の石から最後の石まで、その間のすべてをスキップして直接ジャンプできます。 その場合、最適な戦略は中間値が全体的に負であるかどうかに応じてジャンプを使用する場合と使用しない場合がありますが、構造的には依然として同じモデルと一致します。 

もう 1 つの微妙なケースは、すべての値が正の場合です。 したがって、何かをスキップすることは有害であるため、最良の答えはやはり全額です。 

最後のケースは、大きな負のブロックが正の配列内に存在する場合です。 これらはまさにジャンプが避けようとしているものです。 

## アプローチ

 計算時間の制限を無視すれば、カエルが走り幅跳びをするあらゆる可能な位置を試すことができます。 ある位置からジャンプしたとします`i`に`i + k`。 次に、カエルはこれらのインデックス間のすべての値をスキップします。これは、そのセグメントを除いた完全なパスの合計を再計算する必要があることを意味します。 これを直接行うには、それぞれの範囲を合計する必要があります。`i`、そして、あります`O(n)`そのような位置なので、全体の複雑さは次のようになります。`O(n^2)`。 

これは、すべての有効な決定を明示的に評価するため論理的に機能しますが、次の場合には非常に遅すぎます。`n`数十万に達します。 

重要な観察は、ジャンプを使用しないカエルの経路は固定されており、すべての要素の合計に等しいということです。 ジャンプを使用すると、正確に連続したブロックのみが削除されます。`k - 1`その合計からの要素。 カエルは依然としてジャンプの開始点と終了点を訪問するため、そのブロックのエンドポイントは含まれたままになります。 

したがって、この問題は、次の長さのセグメントを見つけることと同じになります。`k - 1`最低額で。 最小合計セグメントを削除すると、可能な最大の残りの合計が得られます。 

これが分かると、解決策は固定長ウィンドウに対する古典的なスライディング ウィンドウの最小値に縮小されます。

 ## アルゴリズムのチュートリアル

 この問題を、スキップされたセグメントのコストを最小化することに変換します。 

1. すべての値の合計を計算します。 これは、ジャンプ効果が考慮されなかった場合のスコアを表します。 
2. もし`k = 1`、意味のある方法で要素がスキップされないため、すぐに合計を返します。 
3. スキップされるセグメントの長さを次のように定義します。`L = k - 1`。 可能なすべてのジャンプは、同じ長さの 1 つの連続したサブ配列を削除することに対応します。`L`。 
4. 長さの最初のウィンドウの合計を計算します。`L`。 これにより、最小スキップ合計のベースライン候補が得られます。 
5. アレイ上でウィンドウを左から右にスライドさせます。 各ステップで、前のウィンドウの左端の要素を削除し、新しい右端の要素を追加します。 これにより、シフトごとに O(1) 時間でウィンドウ合計が更新されます。 
6. このプロセス中に発生した最小ウィンドウ合計を追跡します。 
7. この最小スキップ合計を合計合計から減算し、結果を返します。 

### なぜ効果があるのか

 有効な戦略は、単一のジャンプの位置によって完全に決定されます。 この選択は、次の 1 つの連続したブロックを選択することに正確に対応します。`k - 1`訪問されない要素。 他のすべての要素は常に含まれます。 したがって、すべての有効な回答は「合計から固定長の 1 つのウィンドウの合計を引いたもの」に相当し、そのウィンドウの合計を最小限に抑えることで、可能な限り最高の最終スコアが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    total = sum(a)

    if k == 1:
        print(total)
        return

    L = k - 1

    window = sum(a[1:1+L])
    min_window = window

    for i in range(2, n - L + 1):
        window += a[i + L - 1] - a[i - 1]
        if window < min_window:
            min_window = window

    print(total - min_window)

if __name__ == "__main__":
    solve()
```コードは最初にすべての石の合計を計算します。 その後、特殊なケースを処理します`k = 1`意味のあるスキップは発生しません。 

変数`window`現在スキップされているセグメントの合計を追跡します。 インデックスで始まる最初の有効なセグメントに初期化されます。`1`(ジャンプはエンドポイント間の内部ノードをスキップするため、0 ベースのインデックス付けの 2 番目の要素)。 このループは、ウィンドウから出る要素を削除し、新しい開始要素を追加することによって、このウィンドウを一定時間で更新します。 

最終結果は、そのような最小のウィンドウを合計から減算します。 

よくある実装上の間違いは、スキップされたセグメントでのインデックス付けが 1 つずれていることです。 セグメントは次で開始する必要があります`i + 1`そしてで終わります`i + k - 1`、ジャンプのエンドポイントは含まれません。 

## 実用的な例

 ### 例 1

 入力:```
5 3
1 2 -3 4 5
```ここ`k = 3`、したがって、スキップされたセグメントの長さは次のようになります。`2`。 

合計を計算します。`1 + 2 - 3 + 4 + 5 = 9`次に、長さ 2 のすべてのセグメントを評価します。 

| ウィンドウの開始 | セグメント | 合計 |
 | --- | --- | --- |
 | 2 | [2、-3] | -1 |
 | 3 | [-3、4] | 1 |
 | 4 | [4、5] | 9 |

 最小スキップ合計は次のとおりです`-1`。 

最終的な答えは、`9 - (-1) = 10`。 

これは、最善の戦略は有害なセグメントをスキップし、完全なパスと比較して効果的に価値を獲得することであることを示しています。 

### 例 2

 入力:```
5 2
1 2 3 4 5
```ここ`k - 1 = 1`, したがって、単一の要素を削除します。 

合計額は`15`。 

すべての単一要素ウィンドウは次のとおりです。 

| ウィンドウの開始 | 値 |
 | --- | --- |
 | 2 | 2 |
 | 3 | 3 |
 | 4 | 4 |
 | 5 | 5 |

 最小値は`2`。 

最終的な答えは、`15 - 2 = 13`。 

これは、スキップが許可されている場合、アルゴリズムが最小の寄与を自然に回避することを確認します。

 ## 特殊なケース

 いつ`k = 1`の場合、アルゴリズムはすぐに全額を返します。 スキップされるセグメント長がないため、スライディング ウィンドウ ロジックは完全にバイパスされます。 入力用`1 1`価値のあるもの`7`、出力は`7`これは、実際のジャンプは発生しないという定義と一致します。 

いつ`k = n`、ウィンドウの長さは次のようになります。`n - 1`これは、スキップされる可能性のあるセグメントが 1 つだけであることを意味します。 アルゴリズムは引き続き、単一ウィンドウの合計として正しく計算します。 たとえば、`5 5`価値観を持って`1 2 3 4 5`、スキップされたセグメントは`[2, 3, 4, 5]`、結果を与える`15 - 14 = 1`。 カエルはフルパスかダイレクトジャンプのどちらかを効果的に選択し、式はそれを正確に捉えます。
