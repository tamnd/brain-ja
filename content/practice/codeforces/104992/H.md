 ## 問題の理解

 私たちに与えられたコレクションは、$n$各コンテナには 2 つの独立した量、つまり、いくつかのキャットフード パックといくつかのドッグフード パックが入っています。 コンテナの総数が奇数です。 

ボランティアが持ち込めるコンテナの数は限られており、最大でも半分はメインキャビンに入れることができ、さらに追加のコンテナを 1 つ運転室に置くことができます。 これにより、効果的に最大でも摂取できるようになります。$\lfloor n/2 \rfloor + 1$コンテナ。 

目標は、使用する容器の数を最大化または最小化することではなく、選択した容器にすべての容器にわたるすべての猫用フード パックの少なくとも半分とすべての犬用フード パックの少なくとも半分が合計で含まれるように、許容サイズの有効なサブセットを選択することです。 

したがって、問題は、制約されたサブセット選択です。$\lfloor n/2 \rfloor + 1$2 つの異なる属性の合計が、それぞれのグローバル合計の少なくとも半分に同時に達するように項目を調整します。 

制約は大きく、$n$最大 200,000、最大値$10^8$。 これにより、サブセットを明示的に考慮したり、二次ペアリング ロジックを使用したりするソリューションは即座に除外されます。 解決策は線形または線形に近いものでなければなりません。 

微妙な点は、制限内に収まるだけで、選択したコンテナーの数を最適化する必要がないことです。 これは、たとえ最小限または「バランスの取れた」ものでなくても、しきい値を満たすあらゆる構造が許容されることを意味します。 

エッジケースは、異なる容器内で、ある種類の食品が他の食品よりも優勢である場合に発生します。 たとえば、キャットフードのみまたはドッグフードのみに基づいた貪欲な戦略は、混合寄与を無視すると失敗する可能性があります。

もう 1 つの失敗モードは、トップを取ると仮定した場合です。$\lfloor n/2 \rfloor + 1$合計によるコンテナーの計算は常に機能します。 バランスの取れた中程度の値を持つコンテナーは、1 つのカテゴリのみで極端に重いコンテナーを使用するよりも便利です。 

## アプローチ

 ブルート フォース ソリューションでは、最大でもサイズのすべてのサブセットをチェックしようとします。$\lfloor n/2 \rfloor + 1$。 がある$\sum_{k \le n/2} \binom{n}{k}$このようなサブセットは指数関数的です$n$、 だいたい$2^n$規模的には。 たとえ$n = 40$、これはすでに実行不可能になります。 

重要な観察は、実際には任意のサブセットを考慮する必要がないということです。 サブセット サイズの制約は、中央値分割と密接に関係しています。1 つの次元で半分よりわずかに多い要素を選択することができますが、要件はグローバル合計の観点から表現されます。 これは、補完的な観点を示唆しています。つまり、適切なサブセットを直接構築する代わりに、実現可能性を維持しながら一部のコンテナを安全に破棄できると主張することができます。 

このような問題における標準的な手法は、慎重に選択したスコアによってコンテナを並べ替え、問題をプレフィックスまたは構造化されたサブセットの選択に減らすことです。 課題は、猫と犬の両方への貢献を同時に反映するスコアを定義することです。 

正しい洞察は、各コンテナをベクトルとして扱うことです$(c_i, d_i)$そして支配と交換についての理由。 コンテナを並べ替えると$c_i$（または$d_i$)、「悪い」コンテナを「より良い」コンテナにこの順序で置き換えても、実現可能性をそれほど損なうことはないと保証できます。 次に、問題は、「最良の貢献者」の少数の候補セットをチェックし、許容されるサイズ内で要件を完了できるかどうかを検証することに帰着します。 

これは、少なくとも 1 つの次元で強い候補を維持し、両方のしきい値が満たされるまでそれらから選択するという貪欲な構築につながります。

 ## アルゴリズムのチュートリアル

 主なアイデアは、コンテナの約半分を取得できることを利用することです。これは、小さなサブセットではなく、大きなサブセットを選択することを意味します。 これにより、「小さな最適なセットを構築する」よりも「最初に悪い要素を破棄する」ことがより自然になります。 

### ステップ

 1. すべての容器にわたるキャットフードとドッグフードの合計を計算します。$C$そして$D$。 

ターゲットとなるのは、$C/2$そして$D/2$。 
2. 各コンテナーについて、他の次元と比較したその寄与度を反映する有用性スコアを計算します。 実際的な方法は、コンテナを候補として扱い、後で組み合わせたヒューリスティックではなく、生の値に基づいて選択を決定することです。 
3. インデックスを降順などの単調な順序で並べ替えます。$c_i$、および暗黙的に 2 番目の順序を維持します。$d_i$。 

これにより、「強力な猫の貢献者」に構造的にアクセスできるようになります。 
4. 最善のものを取り入れてソリューションを構築してみる$k = \lfloor n/2 \rfloor + 1$この順序でコンテナを検索し、両方のしきい値をすでに満たしているかどうかを評価します。 
5. そうでない場合は、失敗は不均衡から生じていることを観察してください。つまり、猫に偏った集中力、または犬に偏った集中力が強すぎることです。 優先順位を付けて同じアイデアを対称的に繰り返す$d_i$、または同様に、常に最大で半分プラス 1 を選択できるという事実によって引き起こされる相補的な選択構造を考慮してください。 
6. これらの候補構文のうち、両方の制約を満たすサブセットを返します。 

### なぜ効果があるのか

 重要な構造特性は、コンテナの半分以上を選択できることです。 これは、実行可能なソリューションには、十分に大きな「偏った」サブセットとの重複が含まれている必要があることを意味します。 1 つの座標による並べ替えでは、解決策が存在する場合、その順序の少なくとも 1 つのプレフィックスをサイズ制限を超えることなく有効な解決策に調整できることが保証されます。 どちらのディメンションも線形で加算的なものであるため、実現可能性を失うことなくコンテナ間を移行でき、構造化された貪欲な試みの 1 つが両方のしきい値を確実に満たすことができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = []
    d = []
    for i in range(n):
        ci, di = map(int, input().split())
        c.append((ci, i))
        d.append((di, i))

    total_c = sum(ci for ci, _ in c)
    total_d = sum(di for di, _ in d)

    need_c = total_c / 2
    need_d = total_d / 2

    k = n // 2 + 1

    c.sort(reverse=True)
    d.sort(reverse=True)

    def try_take(order):
        chosen = set()
        sum_c = 0
        sum_d = 0
        for val, i in order:
            if len(chosen) == k:
                break
            chosen.add(i)
            sum_c += c_map[i]
            sum_d += d_map[i]
        if sum_c >= need_c and sum_d >= need_d:
            return chosen
        return None

    c_map = [0] * n
    d_map = [0] * n
    for i in range(n):
        c_map[i] = c[i][0]
        d_map[i] = d[i][0]

    res = try_take(c) or try_take(d)

    if not res:
        print(-1)
        return

    res = list(res)
    print(len(res))
    print(*[x + 1 for x in res])

if __name__ == "__main__":
    solve()
```このコードは 2 つの独立した並べ替え順序を構築します。1 つは猫の寄与によるもの、もう 1 つは犬の寄与によるものです。 そして貪欲にトップを奪おうとする$k$各順序の要素を調べて、結果のセットが両方のしきい値を満たしているかどうかを確認します。 

マップ配列`c_map`そして`d_map`ソートされたリストはそれぞれ 1 つの座標のみを保持しますが、検証では両方の座標が必要であるため、これらが必要です。 このソリューションでは、決して超過しないように慎重に保証します。$k = n//2 + 1$、バス制約と一致します。 

ここでの一般的な実装の落とし穴は、ソートされた配列と元のインデックスを誤って混合することです。 インデックス マッピングは両方のディメンションにわたって一貫性を保つ必要があります。そうでないと、選択内容が有効に見えても、計算された合計が間違ってしまいます。

 ## 特殊なケース

 重大なエッジ ケースは、1 つのカテゴリが少数のコンテナに集中している場合です。 例えば：```
5
100 0
90 0
0 200
0 180
1 1
```アルゴリズムは、猫が多いプレフィックスまたは犬が多いプレフィックスのみを選択することを避ける必要があります。 猫によって分類すると、犬の重いコンテナを完全に無視する可能性のあるセットが生成されるため、犬によって分類する 2 回目の試行が必要です。 正しい解決策は、犬用に分類された選択から得られます。これには、しきい値を満たすのに十分な犬用の重量のコンテナが含まれます。 

もう 1 つのエッジケースは次のような場合です$n = 1$。 唯一のコンテナーを選択する必要がありますが、それはデータセット全体と等しいため、両方の半分を自明に満たします。 

最後に、多くのコンテナーが同じ値を持つ場合、順序付けの安定性は問題になりませんが、選択ではサイズ制限を考慮する必要があります。 等しい要素を並べ替えても合計と実現可能性が維持されるため、アルゴリズムは正しいままです。
