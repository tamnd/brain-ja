 ## 解決策
 ## 問題の理解

 トレーニング プロセスでは、一連の演習が作成されます。 各演習には、フクロウが提供する「正解」と、グリシャが書いた回答があります。 グリシャの答えが受け入れられない場合、フクロウは後でその演習を繰り返すため、同じ演習が複数回表示される場合があります。 

登場するたびに、最初にグリシャの答え、次に正解という 2 つの文字列が与えられます。 文字列の書式設定がわずかに異なる場合でも、受け入れ規則は寛大です。大文字小文字、句読点、語順の違いは無視され、同じ正規化の考え方に従って、小さなスペルの違いは無関係なものとして扱われます。 実際には、これは、句読点と大文字小文字の違いを取り除いた後、同じ単語のセットで構成されている 2 つの回答が同等であるとみなされ、語順は重要ではなくなることを意味します。 

タスクは、試行ごとに不一致をカウントすることではありません。 代わりに、グリシャが最初に登場したときに失敗した別の演習の数を数えなければなりません。 演習に初めて正解すると、その後同じ演習を繰り返すことは解答とは無関係になります。 

重要な観察は、同じタスクには常に同じ正解文字列が含まれるため、演習の同一性は正規化後の正解によって決定されるということです。 したがって、正規化された各正解が最初に表示される時間と、グリシャの正規化された応答がそれと一致するかどうかのみを考慮します。 

この制約により、最大 40,000 回の試行と最大 200,000 文字の合計入力サイズが許可されます。 これにより、二次形式で文字列を繰り返し比較するソリューションは除外されます。 文字列ごとに線形または線形に近い前処理を行うだけで十分ですが、正しく集計している限り、大きな構造を不注意に繰り返しソートしても、全長が短いため合格します。 

同じ演習が複数回表示され、最初は不正解で、その後は正解する場合、微妙なエッジ ケースが発生します。 たとえば、演習「A」が最初は不正解として表示され、その後再び表示された場合でも、それを 1 回だけカウントする必要があります。 もう 1 つのエッジ ケースは、表面的には異なって見える 2 つの文字列が、正規化の下では実際には同じ答えを表す可能性があるため、文字列を直接比較するとエラーが誤ってカウントされる可能性があることです。 

## アプローチ

 ブルート フォース解釈では、すべてのペアを独立して扱い、カスタムの等価性ルールに基づいて 2 つの文字列を直接比較します。 n 個のペアのそれぞれについて、小文字化、句読点の除去、単語への分割、並べ替え、比較によって両方の文字列を正規化します。 合計の入力サイズが小さいため、これは複雑さの点ではすでに許容可能ですが、単純な実装では誤って同じ正解を複数回再処理したり、ネストされた方法で正規化を繰り返し試行したりして、不要なオーバーヘッドが発生する可能性があります。 

重要な構造的洞察は、各演習が正規化後の正解によって一意に識別されるということです。 同じタスクが繰り返し発生すると、常に同じ正しい文字列が再利用されるため、その識別子によって試行をグループ化できます。 各識別子の最初の出現が正しいかどうかだけを知る必要があります。 

これにより、正規化された正解をキーとする辞書を維持するという問題が軽減されます。 新しいペアごとに、両方の文字列の正規表現を計算し、比較します。 タスクがこれまでに表示されていない場合は、正しさに基づいて回答を増やすかどうかを決定し、表示済みとしてマークします。 それ以降の出現は無視されます。

 ## アルゴリズムのチュートリアル

 1. 試行回数 n を読み取り、2n 行を (グリシャの答え、正解) の n 組として処理します。 各ペアは 1 回の送信試行に対応します。 
2. 各文字列について、単語を抽出し、小文字に変換し、結果として得られる単語のリストを並べ替えることによって、文字列を正規形式に変換します。 この変換により、句読点、大文字の使用、語順に対する影響が排除されます。 
3. この正規形式を使用して、正解のキーを作成します。 このキーは演習の ID を表します。 
4. この演習をすでに処理したかどうか、およびその最初の出現が正しかったかどうかを格納する辞書を維持します。 
5. 新しい演習キーに初めて遭遇したときは、グリシャの答えの標準形式と正しい答えを比較してください。 それらが異なる場合は、エラー カウンタをインクリメントします。 
6. 今後の繰り返しが無視されるように、演習を「実行済み」としてマークします。 

中心的な考え方は、最初に出現したものだけが答えに寄与できるということです。 演習はすでに解決されているため、後で繰り返してもカウントに影響を与えることはできません。 

### なぜ効果があるのか

 正規表現では、すべての同等の回答が同一の文字列に折りたたまれます。 同じ演習のすべての繰り返しは同じ正解を共有するため、同じ正規キーを共有します。 ディクショナリでは、各キーの最初の出現のみが評価されることが保証されるため、各演習は最終的なカウントに最大 1 つの決定に寄与します。 この問題では、外観ではなく、個別の演習ごとに最初の試行の正しさが問われるため、これにより正しさが保証されます。 

## Python ソリューション```python
import sys
import re
input = sys.stdin.readline

def normalize(s: str):
    words = re.findall(r"[a-zA-Z]+", s.lower())
    words.sort()
    return " ".join(words)

n = int(input())
seen = {}
errors = 0

for _ in range(n):
    grisha = input().rstrip("\n")
    correct = input().rstrip("\n")

    key = normalize(correct)
    if key not in seen:
        if normalize(grisha) != key:
            errors += 1
        seen[key] = True

print(errors)
```このソリューションは、同じ正規化ルーチンを使用して、生徒の解答と正解の両方の正規表現を構築します。 正規表現は、句読点やスペースのアーティファクトを無視して単語を抽出します。 ソートにより、語順の違いが等価性に影響を与えないことが保証されます。 辞書は、特定の演習をすでに処理したかどうかを追跡し、最初に出現したもののみが解答に寄与することを保証します。 

よくある間違いは、生の文字列または小文字バージョンのみを比較することです。これは、語順が変更されたり、句読点が挿入されたりすると失敗します。 もう 1 つは、繰り返されるタスクの重複排除を忘れることで、エラーが過大にカウントされてしまいます。
