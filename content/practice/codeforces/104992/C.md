 ## 解決策
 ## 問題の理解

 私たちは鳥に割り当てられた一連の個別の評価を与えられており、各位置は順番に遭遇した新しい鳥に対応しています。 オレグは、最初に鳥に出会ったとき、それぞれの鳥の鳴き声を一度だけ聞きますが、彼の行動により、余分に聞き直すことになります。以前に見た評価よりも評価が低い鳥に出会うたびに、これまで見た最高の評価の鳥に「ジャンプして戻り」、続行する前にその最高の鳥の鳴き声をもう一度聞きます。 

したがって、このプロセスは配列をウォークスルーすることになりますが、これまでに確認された現在の最大要素に時折リセットされます。 新しい値が現れるたびに、その新しい値を聞くために常に 1 分を支払います。 さらに、新しい値が現在の最大プレフィックス値より小さい場合は、その最大要素を再度リッスンするために 1 分の追加料金も支払います。 

出力では、リッスン イベントの総数 (最初のリッスンとすべての繰り返し) と、このプロセス中に単一の鳥がリッスンされる最大回数の 2 つのことが求められます。 

n が 200,000 までという制約は、O(n) または O(n log n) の解が必要であることを意味します。 動作はプレフィックス最大値と比較のみに依存するため、シミュレーションでは最大値を繰り返しスキャンすることを避ける必要があり、最悪の場合 O(n^2) にまで低下します。 

最大値を増加した後に多数の「ドロップ」が発生すると、単純なアプローチは失敗します。 たとえば、シーケンスが高い値と低い値を交互に繰り返す場合、最大値を繰り返し再計算したり、非効率的に訪問を追跡したりすると、フル スキャンが繰り返されることになります。 

微妙なエッジ ケースは、厳密に増加するシーケンスのように、最大​​値が頻繁に変化し続ける場合です。 その場合、繰り返しは発生しません。 逆に、次のようなシーケンス`100, 1, 99, 2, 98, 3, ...`多くのジャンプを同じ最大値に繰り返し強制的に戻します。 

## アプローチ

 直接シミュレーションでは、すでに訪問した鳥のリストが維持され、現在の評価が最大値よりも低い場合は常に、各ステップでその中から最大評価の鳥が検索されます。 これには、ステップごとの線形スキャンまたは更新を伴う優先順位構造のいずれかが必要ですが、実際の困難は、動的に削除または挿入を行っておらず、現在のプレフィックスの最大値のみが必要であることです。 

ブルート フォース解釈では、各ステップ i で、必要に応じて、以前のすべての要素の最大値を計算します。 最悪の場合、各ステップで O(n) のスキャンがトリガーされ、O(n^2) が得られます。 n が最大 200,000 であるため、これは遅すぎます。 

重要な観察は、「これまでで最高の鳥」は単に接頭辞の最大値であるということです。 この値を段階的に維持すると、再計算する必要はなくなります。 プロセスは決定論的になります。a_i を確認すると、それを現在の最大値 M と比較します。a_i > M の場合、M を更新します。そうでない場合は、M への追加の訪問を追加します。 

これにより、プロセス全体が単一の線形パスに削減され、すべての鳥は位置によって一意に識別されるため、位置によってインデックス付けされた辞書または配列を使用して鳥ごとの訪問数を追跡することもできます。 

合計分数は、シミュレーションする合計訪問数にすぎません。 1 羽の鳥が訪問する最大回数は、鳥のカウンターをインクリメントするたびに更新されます。

 ## アルゴリズムのチュートリアル

 バードを左から右に処理し、2 つの状態を維持します。つまり、これまでに確認された現在の最大評価と、バード インデックスから聴取回数までのマップです。 

1. 現在の最大値を最初の鳥の評価として初期化し、その訪問カウントを 1 に設定します。これは、オレグが最初に遭遇したときに一度聞くためです。 これにより、少なくとも 1 羽の鳥の声が聞こえた基本状態が確立されます。 
2. 最初のリスニング イベントに合わせて、合計時間を 1 として初期化します。 
3. 2 から n までの次の鳥 i ごとに、最初に独自のカウンターをインクリメントします。これは、Oleg が到着時に常に新しい鳥を 1 回聞くためです。 これは必須の観察ステップを反映しています。 
4. この最初のリスニングの合計時間に 1 を加えます。 
5. a_i を現在の最大値と比較します。 a_i が最大値より大きい場合は、最大値を a_i に更新し、他には何も行いません。 その理由は、以前に見た鳥の中でこの鳥より優れた鳥はいないため、後戻りは起こらないということです。 
6. a_i が最大値より小さい場合、どの鳥が現在最大値を保持しているかを調べ (そのインデックスを追跡します)、その訪問カウンタをインクリメントし、合計時間に 1 を加えます。 これは、オレグがこれまでで最高の鳥をもう一度聞くために戻ってくることをモデル化しています。 
7. すべての鳥を処理した後、すべての訪問カウンタの最大値を計算します。 

正確さは、再検討の唯一の候補が常にプレフィックスのグローバル最大値であること、およびこの最大値が厳密に大きな評価が表示された場合にのみ変更されるという事実にかかっています。 

### なぜ効果があるのか

 すべてのステップで、履歴に依存する唯一の決定は「バック ジャンプ」が発生するかどうかであり、その決定は現在の値が以前のすべての値の最大値よりも小さいかどうかのみに依存します。 プレフィックスの最大値は一意に定義され、単調に更新されるため、アルゴリズムは必要な再訪問を見逃すことはなく、不必要な再訪問を実行することもありません。 すべての再訪問は、接頭辞の最大値が現在の要素を支配する 1 つのインスタンスに正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # track current maximum value and its index
    max_val = a[0]
    max_idx = 0
    
    # visit counts per bird
    cnt = [0] * n
    
    cnt[0] = 1
    total = 1
    
    for i in range(1, n):
        cnt[i] += 1
        total += 1
        
        if a[i] > max_val:
            max_val = a[i]
            max_idx = i
        else:
            cnt[max_idx] += 1
            total += 1
    
    print(total, max(cnt))

if __name__ == "__main__":
    solve()
```実装では、アルゴリズムで記述されたプロセスを直接エンコードします。 配列`cnt`各鳥が何回鳴き声を聞いたかを保存します。`max_val`そして`max_idx`プレフィックスで現在の最高の鳥を維持します。 各反復は、厳密に 1 つの必須リッスンに寄与し、現在の要素が新しい最大値ではない場合には、追加のリッスンが追加されることもあります。 

微妙な点は、最大値を最初から再計算することは決してないということです。 変数`max_idx`プレフィックスの最大値は、厳密に大きい値が表示された場合にのみ変更されるため、常に再訪問の正しい候補を指します。

 ## 特殊なケース

 1 羽の鳥の場合、プロセスには分岐がありません。 アルゴリズムが初期化されます`cnt[0]=1`合計はすぐに 1 になり、反復が発生しないため、最大訪問数は 1 となり、予想される出力と一致します。 

次のような厳密に増加するシーケンスでは、`1 2 3 4`、すべての要素が新しい最大値になるため、`max_idx`各ステップで更新され、再訪問は発生しません。 この実装では「new max」分岐のみが実行され、合計が n に等しく、すべてのカウントが 1 に等しくなります。 

次のような厳密に減少するシーケンスでは、`5 4 3 2 1`、最初の要素がグローバル最大値になり、そのまま残ります。 後続の各ステップにより、インデックス 0 への再アクセスがトリガーされます。コードは繰り返しインクリメントされます。`cnt[max_idx]`、最初の要素に対する n 回の訪問を累積し、合計を算出します。`2n-1`、最初の後のステップごとに 1 回の追加の再訪問と一致します。
