 ## 解決策
 ## 問題の理解

 ビデオのコレクションが与えられています。各ビデオは大文字で構成される文字列です。 各文字は、特定の種類の動物の 10 秒のセグメントを表します。 ビデオを見るということは文字列全体を消費することを意味するため、ビデオのコストはその長さに比例します。 

合計視聴時間がちょうど M 分になるように、繰り返しのないいくつかのビデオを選択する必要があります。 各キャラクターの貢献時間は 10 秒、1 分は 60 秒であるため、各キャラクターは 1/6 分を貢献します。 これは、選択したビデオの文字数の合計が正確に 600 万に達する必要があることを意味します。 

追加の順序制約があります。選択したビデオのうち、視聴順序の最後のビデオは文字 C で終わる必要があります。他のビデオの順序は重要ではないため、これは、全長が 6M のサブセットを選択し、選択したビデオを最後に配置できるため、少なくとも 1 つの選択したビデオが C で終わることを保証することと同じです。 

制約は十分に小さいため、全長 6000 までの 2 次または擬似 2 次動的計画法ソリューションが実現可能です。 N が 2000 まで、目標合計が 6000 までの場合、O(N・sum) アプローチが許容されます。 

素朴なアプローチではビデオのすべてのサブセットを試しますが、それは 2^2000 の可能性をもたらし、これは完全に実行不可能です。 

合計が 6M になる有効なサブセットが存在するが、そのビデオのどれも C で終わらない場合、微妙なエッジ ケースが発生します。そのようなサブセットは、たとえ時間制約を満たしていても無効です。 たとえば、選択したすべてのビデオが D または P で終わる場合、順序に関係なく最終制約を満たすことができません。 

別のエッジ ケースは、複数の有効なサブセットが存在するが、その一部にしか C エンディング ビデオが含まれていない場合に発生します。 正しいアルゴリズムでは、制約が後付けではなくグローバルに適用されるようにする必要があります。 

## アプローチ

 ブルートフォース戦略では、ビデオのすべてのサブセットを列挙し、その合計の長さを計算します。 サブセットごとに、選択したビデオの少なくとも 1 つが C で終わるかどうかもチェックします。これは問題の定義に直接一致するため論理的に機能しますが、2^N 個のサブセットを検査し、単一のサブセットを評価する場合でも長さを合計する必要があるため、N = 2000 では終了できない指数関数的な爆発につながります。 

問題の構造は、選択した長さの合計と、選択したセットに C で終わるビデオが含まれるかどうかを記述する 1 つの追加のブール条件のみを考慮することです。これは、状態が達成可能な全長と C 条件が満たされているかどうかの両方を追跡する、ナップザック スタイルの動的プログラミング ソリューションをすぐに示唆します。 

C エンディングの要件を順序付けの制約として扱うのではなく、サブセットのプロパティとして再解釈します。最後のビデオは選択されたビデオの中から常に選択できるため、適格な候補は少なくとも 1 つだけ必要です。 

これにより、バイナリ フラグを使用して最大 6000 の合計に対する到達可能性を計算するという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^N・N) | O(N) | 遅すぎる |
 | 動的計画法 (合計 + フラグ) | O(N・6000) | O(N・6000) | 承認済み |

 ## アルゴリズムのチュートリアル

 各項目の重みが文字列の長さに等しいナップザックとして問題をモデル化します。 少なくとも 1 つの C エンディング ビデオをすでに選択したかどうかを維持します。

1. 所要時間 M を目標文字数 T = 6M に換算します。 これにより、時間制約が純粋な整数部分集合和の問題に変わります。 
2. ダイナミック プログラミング テーブル dp[s][b] を定義します。s はこれまでに達成された全長、b は C で終わるビデオを少なくとも 1 つ選択したかどうかを示すバイナリ値です。 
3. 何かを選択する前に、dp[0][0] を到達可能として初期化します。 
4. ビデオを 1 つずつ処理します。 長さ L とフラグ c (C で終わる場合は 1、そうでない場合は 0) を持つ各ビデオ i について、s + L ≤ T である限り、到達可能なすべての状態 (s, b) から (s + L, b OR c) への遷移を試みます。同じビデオを複数回再利用することを避けるために、合計を降順で処理します。 
5. 遷移の実行中、後で選択したサブセットを再構築できるように、新しく到達した各状態の親ポインターを保存します。 各状態は、その状態がどの前の状態から来たのか、どのビデオがその状態を作成したかを記憶しています。 
6. すべてのビデオを処理した後、dp[T][1] が到達可能かどうかを確認します。 そうでない場合は、有効なサブセットがありません。 
7. 到達可能な場合は、親ポインタを使用して状態 (T, 1) から (0, 0) に到達するまで逆方向に歩いてサブセットを再構築します。 
8. 再構成されたサブセットから、C で終わるビデオを選択し、それを最後のビデオとして指定します。 残りのビデオを任意の順序で出力し、その後にこの選択した最後のビデオを出力します。 

### なぜ効果があるのか

 すべての dp 状態は、特定の全長を達成する処理済みビデオのサブセットと、C エンディング ビデオが含まれているかどうかの記録を表します。 トランジションでは一度に 1 つの未使用ビデオのみが追加されるため、到達可能な各状態は有効なサブセットに対応します。 親ポインターにより、そのサブセットの実際の構成が失われないことが保証されます。 

ビデオの順序は最後の要素を除いて無関係であり、最後の要素はサブセット内の C エンディング ビデオから自由に選択できるため、dp[T][1] を保証することは、有効な最終配置が存在することを保証することと同等です。 再構築により、その状態を達成する明示的なサブセットが復元されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    videos = []
    for i in range(n):
        s = input().strip()
        videos.append((len(s), s[-1] == 'C', i + 1))

    T = 6 * m

    dp = [[False] * 2 for _ in range(T + 1)]
    parent = [[None] * 2 for _ in range(T + 1)]

    dp[0][0] = True

    for idx, (length, ends_c, vid) in enumerate(videos):
        for s in range(T - length, -1, -1):
            for b in range(2):
                if not dp[s][b]:
                    continue
                nb = b | ends_c
                ns = s + length
                if not dp[ns][nb]:
                    dp[ns][nb] = True
                    parent[ns][nb] = (s, b, vid)

    if not dp[T][1]:
        print("NO")
        return

    # reconstruct subset
    res = []
    s, b = T, 1
    used = set()

    while s != 0 or b != 0:
        ps, pb, vid = parent[s][b]
        res.append(vid)
        used.add(vid)
        length = None
        for L, c, v in videos:
            if v == vid:
                length = L
                break
        s, b = ps, pb

    # choose last C-ending video
    last = None
    for v in res:
        for L, c, vid in videos:
            if vid == v and c:
                last = v
                break
        if last is not None:
            break

    res.remove(last)
    print("YES")
    print(len(res) + 1)
    print(*res, last)

if __name__ == "__main__":
    solve()
```DP テーブルは、T までのすべての可能な合計継続時間の到達可能性を追跡しますが、2 番目の次元では、選択したサブセット内に有効な終了候補が存在するかどうかを確実に記憶します。 親配列は遷移を記録するため、実現可能性を判断するだけでなく、明示的な解決策を再構築できます。 

再構成ステップでは、ターゲット状態から逆方向に進み、選択されたビデオを収集します。 その後、C で終わる 1 つのビデオを分離し、順序制約を満たす最後に配置します。 

微妙な点の 1 つは、遷移中に合計を降順で処理することです。 これにより、同じ繰り返しで同じビデオを複数回再利用することがなくなり、選択の 0/1 の性質が維持されます。 

## 実用的な例

 ### サンプル 1

 DP が全長 T = 6M の有効な状態に達すると仮定します。 

| ステップ | アクション | dp 状態の概要 |
 | --- | --- | --- |
 | 0 | 開始 | dp[0][0] = true のみ |
 | 1 | プロセスビデオ 1 | 到達可能な合計を展開します |
 | 2 | プロセスビデオ 2 | さらに合計が追加されました |
 | 3 | プロセスビデオ 4 | dp[T][1] が true になります。 

DP の後、再構成により {1, 2, 4} などのサブセットが得られます。 このうちビデオ 4 は C で終わり、最後に配置できます。 

これは、アルゴリズムが実現可能性 (サブセットの合計) を順序付け (最終的な選択) から分離していることを確認します。 

### サンプル 2

 | ステップ | アクション | dp 状態の概要 |
 | --- | --- | --- |
 | 0 | 開始 | dp[0][0] のみ |
 | 1-3 | ビデオを処理する | 合計は形成されますが、C フラグを使用して T に到達する有効な組み合わせはありません。 
| 最終 | チェック | dp[T][1] = false |

 必要な継続時間に同時に一致し、C エンディング ビデオを含むサブセットはないため、アルゴリズムは正しく NO を出力します。 

これは、時間制約を単独で満たすことができる場合でも、追加の制約によってすべての解決策が無効になる可能性があることを示しています。

 ## 特殊なケース

 すべてのビデオを合わせると必要な全長に達するが、C で終わるビデオがない場合、dp テーブルは dp[T][0] を到達可能として正しくマークしますが、dp[T][1] は false のままです。 有効な最終ビデオが存在しないため、アルゴリズムはこのケースを直ちに拒否します。 

C で終わる有効なビデオが 1 つだけ存在するが、長すぎて他のビデオと組み合わせることができない場合、そのビデオを含めた状態では DP は T に到達せず、再構築は失敗します。 逆方向の親追跡により、不可能であることが確認されました。 

再構築されたサブセットに複数の C エンディング ビデオが存在する場合、それらのいずれかを最後として選択できます。 残りの中での順序は無関係であるため、アルゴリズムは最初に見つかったものを安全に選択します。
