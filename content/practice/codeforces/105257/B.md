 ## 問題の理解

 を構築するように求められています。$n \times m$3 つのシンボルだけで埋められたグリッド:`1`、`+`、 そして`*`。 グリッドは単なる静的なオブジェクトではなく、2 方向の式を定義します。 

すべての行を左から右に読むと、有効な算術式になります。 すべての列は、上から下に読んでも有効な算術式になります。 有効な式の定義は再帰的です。つまり、1 つ以上の連続する単一ブロックです。`1`s は有効であり、2 つの有効な式が`+`または`*`、結果も有効です。 

したがって、概念的には、各式は、以下の実行を連結して構築されたバイナリ ツリー式です。`1`、 どこ`+`そして`*`部分式間の演算子として機能します。 

グリッド全体の値は、すべてを評価することによって定義されます。$n$行式と$m$列式とその数値結果の合計。 この合計値を最小化するグリッドを構築する必要があります。 

主な問題は、行と列が独立していないことです。 各セルは 1 つの行式と 1 つの列式に正確に関与するため、シンボルを配置すると 2 つの評価が同時に影響を受けます。 

制約$3 \le n, m \le 9$非常に小さいです。 これは、特にローカルで選択肢を枝刈りしたり構造化できる場合には、グリッド パターンに対する指数関数的または組み合わせ的な構築が受け入れられることを直ちに示唆しています。 パターンや貪欲なローカル構築に対する総当たり推論に近い解決策が考えられます。 

微妙なエッジ ケースは再帰文法に由来します。つまり、式は標準の演算子の優先順位規則では評価されず、文法によって完全に括弧で囲まれた構造として評価されます。 これを標準の算術として誤解すると、完全に間違った値が得られます。 例えば、`1+1*1`必ずしも乗算の優先順位で解釈されるわけではありません。 これは、構築ルールによって定義された構造化された式ツリーです。 

## アプローチ

 素朴な考えは、各セルを個別に扱い、すべてを試してみることです。$3^{nm}$グリッド、それぞれを検証します。 グリッドごとに、すべての行文字列と列文字列を抽出し、それらを式に解析して、その値を計算する必要があります。 たとえ$n,m \le 9$、これは$3^{81}$あまりにも大きすぎて概念的に列挙することさえできません。 

行ごとの推論に限定したとしても、依然として行と列にわたる依存性に直面します。 中心的な問題は、セルが 2 つの式に同時に影響を与えるため、ローカルな決定が両方向に結合されることです。 

重要な観察点は、有効な式の構造により、どこに使用するかが大幅に制限されるということです。`+`そして`*`現れることがあります。 有効な式は、純粋な式の連結から構築されます。`1`つまり、演算子は 1 の連続するセグメント間の区切りとしてのみ重要です。 これは、式の数値は、セグメントの境界を越えた演算子の任意の配置ではなく、式がどのようにセグメントに分割されるかによってのみ依存することを意味します。 

これにより、問題は任意の式の解析から各行と列のセグメント構造の制御に移ります。 各行と列は、連続したグループのシーケンスとして見ることができます。`1`s は演算子で区切られ、値はそれらのグループのサイズによって決まります。 

グリッドが小さいため、対称性を利用できます。各セルの選択は、1 つの行セグメント構造と 1 つの列セグメント構造にのみ影響します。 最適なソリューションでは、多くの小さな分割に最大限に分割する構成が優先されます。`1`これは、小さな乗法コンポーネントが、加算マージによって全体の値が増加するよりも積極的に全体の値が減少するためです。 

これは、建設的な貪欲パターンにつながります。つまり、長時間連続して実行されることを避けたいのです。`1`両方の方向で、代わりに構造化されたチェッカーボードのような方法で演算子を導入します。 最適な構造は、行方向と列方向のセグメントの最小化のバランスをとることで導き出すことができ、次のようなパターンが得られます。`1`は疎な構造に配置され、演算子が残りを埋めて大規模な乗法連鎖を防ぎます。 

以来$n,m \le 9$、標準的なパターンを修正できます。`1`そして`*`すべての行と列が有効な式のままであることを保証しながら、制御されたグリッド内で実行できます。 すべての有効な構成の中で、最小限の構成は、断片化を最大化することによって実現されます。`1`セグメント。

 ## アルゴリズムのチュートリアル

 1. 各行と列を、連続して実行されるシーケンスとして解釈することから始めます。`1`価値貢献の問題。 これは、`1`すぐに値を増やします。 
2. 長く途切れることのない一連の作業を避けることを決定します。`1`両方向に同時に。 あまりにも多く置きすぎると`1`■ 直線の場合、その行または列はセグメント サイズが大きいため、大きな値が生成されます。 
3. グリッドを構築します。`1`は、行方向と列方向の両方に一度に大きな連続ブロックが形成されるのを防ぐ位置に配置されます。 最も単純で安定した構造は、長く連続する行や列が含まれないようにパターンを交互に配置することです。`1`s.
 4. 残りの位置を次のように埋めます。`*`構造化評価では、乗算は式のコンポーネントを加算するよりも積極的に分割するため、セパレータとして使用します。 
5. すべての行と列に少なくとも 1 つの行と列が含まれるため、構築によってすべての行と列が有効な式を形成していることを確認します。`1`、区切り文字は有効な部分式のみを分割するため、文法は常に満たされます。 
6. 結果のグリッドを出力します。 

### なぜ効果があるのか

 重要な不変条件は、行や列が長く連続したセグメントを形成しないことです。`1`s は式の値を支配します。 再帰的な乗算構造により、式の値はセグメントの長さに応じて超線形に増加するため、演算子を再配置することによる利点はセグメント サイズを最小限に抑えることによって決まります。 この構造により、あらゆる最大限の走行が保証されます。`1`s には制限されたサイズがあり、セグメントをマージする代替構成では、少なくとも 1 つの行または列の寄与が、他の行または列の寄与を減らすよりも必然的に増加します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    # We construct a checkerboard-like pattern:
    # put '1' on cells where (i + j) % 2 == 0, otherwise '*'
    # This guarantees no long consecutive runs of '1' in any row or column.

    grid = []
    for i in range(n):
        row = []
        for j in range(m):
            if (i + j) % 2 == 0:
                row.append('1')
            else:
                row.append('*')
        grid.append(''.join(row))

    print("\n".join(grid))

if __name__ == "__main__":
    solve()
```この実装は、連続的な接続を防ぐというアイデアを直接エンコードしています。`1`セグメント。 市松模様の条件により、水平方向および垂直方向に隣接する 2 つのセルが両方とも存在しないことが保証されます。`1`これは、すべてのランレングスを 1 に制限します。これは、グリッド内で最も強力な断片化であるため、再帰的な乗算と加算の構造による式の爆発を最小限に抑えます。 

微妙な点は、式を明示的に構築したり評価したりすることは決してないということです。 記号配置の構造制御に完全に依存していますが、表現文法はセグメンテーションを考慮すると決定的であるため、これで十分です。`1`s.

 ## 特殊なケース

 潜在的なエッジケースは、次のように両方の次元が奇数である場合です。$3 \times 3$または$5 \times 5$。 このような場合、単純な交互パターンが行と列の寄与の不均衡を引き起こしていると疑われる可能性があります。 ただし、グローバル パリティではなく隣接性の制約によって有効性が決定されるため、チェッカーボードの構造は一貫性を保ちます。 

たとえば、$3 \times 3$:```
1*1
*1*
1*1
```すべての行が分離されています`1`s、およびすべての列にも分離された`1`s. たとえその数であっても、`1`s は行と列の間でわずかに異なり、長さ 1 を超えるランは存在しないため、乗算構造による式のインフレは発生しません。 

もう 1 つのエッジ ケースは、列を考慮せずに貪欲な行単位の構築を試みた場合に、単一の長い行または列セグメントが誤って形成されることです。 例えば：```
111
1*1
111
```これにより、大きな連続セグメントを含む行が作成され、値が大幅に増加します。 チェッカーボード パターンは、列制約を同時に適用することでこれを完全に回避し、そのような隠れた爆発を防ぎます。
