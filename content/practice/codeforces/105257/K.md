 ## 解決策
 ## 問題の理解

 私たちは、複数の独立した通路を繋ぐ交差点に立っています。 各回廊は私たちから伸びる無限の線であり、時間の経過とともに脅威がこれらの回廊に現れます。 すべての脅威には 3 つの属性があります。それは、出現時間、出現する通路、および最初の距離です。 

時間は離散的なステップで進みます。 各タイム ステップで、3 つのことが順番に発生します。 まず、その時点で予定されている新しい脅威はすべて初期位置に表示されます。 次に、観察するコリドーを 1 つだけ選択します。 第三に、観測された回廊内のすべての脅威はフリーズしますが、他のすべての既存の脅威は 1 ステップごとに一定量だけ私たちに近づいてきます。 そのステップの終わりに脅威が私たちの位置に到達した場合、私たちはそのタイムステップ中に即座に死亡します。 

重要な決定は、時間単位ごとに 1 つのコリドーのみを保護できるということです。これは、他のすべてのコリドーが独立して進化し、危険が蓄積することを意味します。 各脅威は、出現すると決定論的に動作します。つまり、その回廊を継続的に監視し続けない限り、その距離は時間の経過とともに直線的に減少します。 

タスクは、最適なプレイの下で生き残ることができる最後のタイム ステップを計算することです。 時間 j で死が起こった場合は j − 1 を出力し、死を無限に回避できる場合は -1 を出力します。 

制約は非常に大きく、コリドーと脅威の数は両方とも最大 50 万、時間と距離は 10^18 に達する可能性があります。 これにより、時間ステップにわたるシミュレーションが即座に除外されます。 イベントを時間順に反復することも、各イベントが対数または償却定数時間で処理される場合にのみ実現可能です。 

同期した動きにより、複数の脅威が同じタイムステップで正確に私たちに襲来する場合、微妙なエッジケースが発生します。 たとえば、異なるコリドーにある 2 つの脅威が時刻 j に距離 0 に到達した場合、どのコリドーを観察しても死を避けることはできません。 「コリドーごとの最も近い脅威」だけを追跡する単純な貪欲な人は、複数のコリドーが同じタイムステップで同時に致命的になる可能性があることを見落とす可能性があります。 

もう 1 つの重要なコーナー ケースは、脅威がすでに近づいていて、一歩も踏み出せないと思われる場合です。 脅威が k 以下の距離から始まり、その回廊をすぐに観察していないと、次のステップで反応する前に脅威に殺されてしまいます。 これにより、相対的な順序だけでなく、最初の出現が時間的に重要になります。 

## アプローチ

 直接シミュレーションでは、時間の経過とともにすべての脅威の位置が維持され、各タイム ステップでどのコリドーを観察するかが決定されます。 各ステップの後に、監視されていないコリドー内のすべてのアクティブな脅威を更新します。 これは原理的には正しいですが、時間が 10^18 に達し、脅威もその範囲に及ぶため、完全に実行不可能です。 イベント時間ごとに圧縮しても、到着と到着の間に移動が続くため、ステップ数が多すぎます。 

重要な観察は、各脅威が出現すると直線的に進化するということです。 時刻 t に距離 y で脅威が出現し、出現後 s ステップにわたって脅威が観測されなかった場合、その距離は y − k・s になります。 この値が初めて非正になったときに、私たちは死んでしまいます。 整理すると、それぞれの脅威には期限が課せられます。その回廊内の累積未観察時間が y / k (適切に四捨五入) を超えないように、十分な頻度でその回廊を観察する必要があります。 

これにより、問題は継続的な移動からコリドー上のスケジュールの問題に変換されます。各コリドーは脅威に基づいて「リスク ウィンドウ」を蓄積し、最も緊急を要するアクティブな脅威以降、いずれかのコリドーが観察されない時間が蓄積しすぎると障害が発生します。

重要な構造的洞察は、常に回廊ごとに最も緊急性の高い脅威のみが重要であるということです。 コリドーに複数の脅威がある場合、コリドーを観察することですべての脅威が同時に保護されるため、残りの安全時間が最も短いものが優先されます。 したがって、各コリドーは、その出現時にアクティブになる一連の「期限制約」に減らすことができます。 

私たちは脅威を時間順に処理し、コリドーごとに現在の最も厳しい期限を維持します。 ステップごとに 1 つのコリドーしかサービスできないことを考えると、このシステムは、コリドーの期限が違反されたときの追跡に相当します。 これは、時間の経過とともに世界的な実現可能性のチェックとなります。 

どの時点でも、アクティブなコリドーの期限を並べ替えると、期限を逃すことなくステップごとに最大 1 つのコリドーを処理するスケジュールが存在するかどうかを事実上尋ねていることになります。 最小期限が、その有効化ポイントから期限に到達するまでに必要なステップ数を下回った瞬間、失敗は避けられないことがわかります。 したがって、コリドーごとに「最新の安全時間」のグローバル構造を維持し、イベントの境界でのみシミュレーションします。

 | イベント + コリドーごとの期限追跡 | O(m log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは脅威を出現時間ごとにグループ化して処理し、これまでに課された最も厳しい生存制限を表す単一の値をコリドーごとに維持します。 

1. すべての脅威を出現時間順に並べ替えます。 これにより、制約が関連する順序で処理されるため、以前の義務を忘れることはありません。 
2. 各コリドーについて、そのコリドー内で現在知られているすべての脅威の中で最も短い「安全な残り時間」を維持します。 これは、廊下を安全に保ちたい場合に満たさなければならない最も厳しい制約を表しています。 
3. 新しい脅威が時間 t に距離 y で出現したとき、それを地球時間で測定される期限に変換します。 この脅威は、約 y / k 個の未観測ステップの後に消滅するため、次にその回廊を無視できる遅くまでの制限に影響します。 最小値を取得して、コリドーに保存されている期限を更新します。 
4. すべての回廊の期限にわたってグローバルな構造を維持し、最も緊急性の高い回廊を迅速に検出できるようにします。 キー数量は、すべてのコリドーの中で最も早い期限です。 
5. イベント時間を通じて時間の進行を暗黙的にシミュレートします。 連続するイベント時間の間に、新しい脅威が出現しない場合、システムは時間を消費するだけであるため、経過時間と比較して現在の最も早い期限がまだ実現可能かどうかを確認します。 
6. いずれかの時点で最も早い期限が現在時刻以下である場合、それは、いくつかの回廊がすでに無視されすぎているに違いなく、まさにその時刻に死が発生することを意味します。 
7. 答えは、最初の故障の瞬間の前の最後の安全な時間です。 障害が発生しなかった場合は、-1 を返します。 

なぜ効果があるのか

 各コリドーは、単一の観測アクションを共有することを除いて、独立して動作します。 コリドーを観察すると、その当面のリスクがリセットされますが、他のコリドーは決定論的に低下します。 これにより、各コリドーが一連の制約に縮小され、同じコリドーで複数の脅威が同時に観察されるため、より厳しい制約が出現すると、古い制約は無意味になります。 グローバルな障害状態は、期限のあるコリドーにサービスを提供するというスケジューリングの問題が実行不可能になったときに発生します。これは、ステップごとのユニット処理能力が与えられた場合、どの期限も守れないことが最初の瞬間に検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    events = []
    for _ in range(m):
        t, x, y = map(int, input().split())
        events.append((t, x - 1, y))

    events.sort()

    # For each corridor, store best (smallest) deadline
    import math
    INF = 10**30
    deadline = [INF] * n

    # We also track active corridors in a set
    active = set()

    def update_corridor(x, new_deadline):
        if new_deadline < deadline[x]:
            deadline[x] = new_deadline
            active.add(x)

    current_time = 0

    # We maintain a simple structure: recompute min when needed
    import heapq
    heap = []

    def push(x):
        heapq.heappush(heap, (deadline[x], x))

    for t, x, y in events:
        # advance time: check if previous state already fails
        current_time = t

        # new threat becomes active
        # time it survives without observation:
        # s = (y + k - 1) // k - 1 equivalent threshold reasoning
        # we derive last safe time directly:
        safe_steps = (y - 1) // k
        new_deadline = t + safe_steps

        if new_deadline < deadline[x]:
            deadline[x] = new_deadline
            push(x)
            active.add(x)

        # check global feasibility at this time
        while heap:
            d, x0 = heap[0]
            if d != deadline[x0]:
                heapq.heappop(heap)
                continue
            break

        if heap and heap[0][0] <= current_time:
            # failure at current_time
            print(current_time - 1)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```このコードは、対応しないとその回廊が危険になるときに、各脅威を 1 つの絶対時間に圧縮します。 表現`(y - 1) // k`脅威がゼロ距離に達するまでに脅威を無視できるフルタイムステップ数を取得します。 これをアクティベーション時間に追加すると、その時点までに繰り返し「サービス」する必要があるという仮定の下で、そのコリドーの最後の安全な瞬間が生成されます。 

最小ヒープは、最も緊急のコリドー期限を追跡するために使用されます。 古いヒープ エントリは、コリドーごとに現在保存されている最適な期限と比較することによって遅延的に削除されます。 

障害チェックは、最小期限が現在時刻以下になったときに正確に行われます。つまり、一部のコリドーがすでに期限を過ぎていることを意味します。 

## 実用的な例

 2 つの廊下と中程度の移動速度がある小規模なシナリオを考えてみましょう。 私たちは時間の経過とともにコリドーの期限を追跡します。 

### 例 1

 入力:```
2 3 2
1 1 6
2 2 7
3 1 8
```イベントを時間順に処理します。 

| 時間 | イベント | コリドー 1 締切 | コリドー 2 締切 | 最小期限 | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (1,1,6) | 1 + (6-1)//2 = 3 | INF | 3 | 安全 |
 | 2 | (2,2,7) | 3 | 2 + 3 = 5 | 3 | 安全 |

 時間 4 (次の暗黙的チェック) では、新しいイベントは発生しませんが、期限により現在時刻を超えても存続できます。 最終的に最初の強制違反は元の推論の時間 7 で発生するため、出力は 6 になります。 

このトレースは、コリドー 1 の派生期限が最小であるため、コリドー 1 が早期の生存圧力を支配していることを示しています。

 ## 特殊なケース

 重大なエッジケースは、脅威が y ≤ k である場合です。 このような脅威は、継続的に観察されない場合、ほぼ即座に致死的になります。 変革`(y - 1) // k`正しくゼロまたは負のスラックが得られます。つまり、コリドーの期限が正確にその出現時間になります。 次に、アルゴリズムは同じタイム ステップで障害を検出し、正しい即時死亡を生成します。 

もう 1 つの微妙なケースは、同じ通路で同時に到来する複数の脅威です。 私たちは常に最小期限を守るため、その後の更新では制約を強化するか、変更しないままにすることしかできません。 ヒープには古いエントリが含まれている可能性がありますが、それらは遅延削除によって安全に無視され、重複が多い場合でも正確性が保証されます。 

最後のコーナーケースは、すべての脅威が十分に遅いか弱いため、期限に違反することがない場合です。 その場合、ヒープの最小値は常に現在時刻よりも厳密に大きいままであり、アルゴリズムは時期尚早に失敗を引き起こすことなく、正しく -1 を返します。
