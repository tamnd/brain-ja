 ## 問題の理解

 ## アルゴリズムのチュートリアル

 文字列を左から右に処理し、各位置をそこで終わるすべての部分文字列の右境界として扱います。 

ポジションごとに`i`、DP テーブルを維持します`dp[a][b]`。 このテーブルの意味は、インデックスで終わるすべての部分文字列に対する合計寄与度です。`i`、 どこ`a`何文字かを表します`s1`部分文字列内の部分シーケンスとして一致しました。`b`は同じことを表します`s2`。 言い換えると、次で終わるすべての部分文字列は、`i`現在のサブシーケンス状態のカウントをこのテーブルの 1 つのセルに入力し、テーブルはすべての開始位置を集計します。 

1.初期化`dp`ポジションのために`0`部分文字列がまだ存在しないため、空の構造体を除いてすべてゼロとして扱われます。 
2. 各文字を反復処理します。`S[i]`左から右へ。 
3. 新しい DP テーブルを開始します`ndp`から初期化されました`dp`で終わる既存のすべての部分文字列があるため、`i-1`で終わる部分文字列は残ります`i`拡張機能が適用される前。 
4. すべての州について`(a, b)`、で終わるすべての部分文字列の拡張をシミュレートします。`i-1`追加することで`S[i]`。 これは、両方のパターンのサブシーケンスの進行状況を更新することを意味します。 もし`S[i]`の次に必要な文字と一致します`s1`、その後、その前進する部分シーケンスが一致します`a`形成することもできます。 同様に`s2`。 
5. トランジションを処理した後、すべてのポジションが`i`以下のみからなる新しい部分文字列を開始できます`S[i]`。 これは基本状態に寄与します`(0, 0)`その単一文字の部分文字列内の部分シーケンスの形成用。 
6. 1回`ndp`で終わるすべての部分文字列の寄与が構築されます。`i`すべての状態を合計し、完了した一致の数を乗算して得られます。`s1`そして`s2`遷移を通じて暗黙的にエンコードされます。 これを最終的な答えに積み上げます。 
7. 交換`dp`と`ndp`そして続けます。 

重要な不変条件は、処理後の位置です。`i`、DP テーブルは、正確に終了するすべての部分文字列にわたる集計された部分列状態分布を正確に表します。`i`。 次で終わるすべての部分文字列`i`で終わる部分文字列の拡張子のいずれかです`i-1`、または新しく開始された部分文字列`i`、両方のケースが 1 回だけ説明されます。 サブシーケンスの遷移は現在の状態と次の文字のみに依存するため、それ以降の履歴情報はありません。`(a, b)`が必要です。 

これにより、すべての部分文字列がエンドポイントごとに 1 回正確にカウントされ、各部分文字列内で、`s1`そして`s2`状態の進化に正しく貢献します。 同じ状態空間で両方のパターンを同時に追跡するため、積の構造は保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

S = input().strip()
s1 = input().strip()
s2 = input().strip()

n = len(S)
m1 = len(s1)
m2 = len(s2)

# dp[a][b] = number of ways (over all substrings ending at current i)
# where a chars of s1 and b chars of s2 have been matched as subsequences
dp = [[0] * (m2 + 1) for _ in range(m1 + 1)]

ans = 0

for ch in S:
    ndp = [[0] * (m2 + 1) for _ in range(m1 + 1)]

    for a in range(m1 + 1):
        for b in range(m2 + 1):
            val = dp[a][b]
            if not val:
                continue

            # extend without using ch
            ndp[a][b] = (ndp[a][b] + val) % MOD

            # try to match s1
            if a < m1 and ch == s1[a]:
                ndp[a + 1][b] = (ndp[a + 1][b] + val) % MOD

            # try to match s2
            if b < m2 and ch == s2[b]:
                ndp[a][b + 1] = (ndp[a][b + 1] + val) % MOD

    # start new substring at current position
    ndp[0][0] = (ndp[0][0] + 1) % MOD

    dp = ndp

    # count fully matched states
    ans = (ans + dp[m1][m2]) % MOD

print(ans % MOD)
```このコードは、すべての部分文字列が前の部分文字列を拡張するか、新しく開始することによって構築されるという考えに従っています。 DP 状態は、両方のサブシーケンス オートマトンの同時進行を追跡します。 各ステップでの答えに寄与する唯一の状態は、両方のパターンが完全に一致した状態です。これは、各部分文字列内の 1 つの有効な部分列埋め込みペアに対応するためです。 

微妙な実装ポイントは、「新しい部分文字列の開始」遷移です。 明示的に注入せずに`(0,0)`位置ごとに 1 回、以下で始まる部分文字列`i`決してカウントされないでしょう。 もう 1 つの微妙な点は、インプレース更新では単一のキャラクターが同じレイヤー内で複数のサブシーケンス ステップを進めることを誤って許可してしまうため、前の DP から新しい配列にトランジションを適用する必要があることです。 

## 実用的な例

 重複するサブシーケンスが存在する小さな例を考えてみましょう。 させて`S = ababa`、`s1 = aba`、`s2 = ba`。 

集約された意味のみに焦点を当てて、各位置の DP レイヤーを追跡します。 

で`i = 0`、部分文字列のみ`"a"`存在します。 どちらのパターンも完了できないため、貢献度はゼロです。 

で`i = 1`、部分文字列`"ab"`そして`"b"`終了位置が考慮されます。`"ab"`両方のパターンに部分的に一致しますが、まだ完全には一致していないため、寄与はゼロのままです。 

で`i = 2`、部分文字列`"aba"`が表示されます。 これは最初の位置です。`s1`サブシーケンスとして照合できます。`s2`複数の方法で一致させることもできます。 DP は、両方のオートマトンが最終位置に到達した状態に対するゼロ以外の寄与を蓄積するようになり、これらは次で終わるすべての部分文字列の答えに寄与します。`2`。

 ## 特殊なケース

 重要なエッジケースは、両方のパターンが同一である場合です。 この状況では、すべての部分文字列の寄与は部分シーケンス数の 2 乗となり、繰り返される文字が大幅に増幅されます。 両方のオートマトンが同一の遷移をたどるため、DP はこれを自然に処理します。そのため、特別なケーシングを必要とせずに、それらの状態が同期して進化します。 

もう 1 つのケースは、長さが 1 の非常に短い部分文字列です。 これらは常に DP を基本状態にリセットし、両方のパターンの長さが 1 で同じ文字に一致する場合にのみ影響します。 明示的な「新しい部分文字列の開始」遷移により、これらが正確に 1 回カウントされることが保証されます。 

最後のエッジケースには、次のような繰り返しの多い文字列が含まれます。`"aaaaa..."`、サブシーケンスの数は組み合わせ的に増加します。 DP は組み合わせを明示的に列挙しません。 代わりに、状態遷移を通じてそれらを集約するため、指数関数的な増加は位置ごとの多項式状態更新に圧縮されます。
