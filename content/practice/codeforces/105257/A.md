 ## 解決策
 ## 問題の理解

 各入力行は、コンパクトな数値形式でエンコードされた Unix のような権限設定を記述します。 ファイルに対するアクセス許可を直接与える代わりに、システムは 3 桁の数字を使用します。各桁は、所有者、グループ、その他の 3 つのユーザー クラスのいずれかのアクセス権を個別に表します。 

各桁は 0 ～ 7 であり、3 ビットのマスクとして解釈される必要があります。 3 ビットは、固定の順序で読み取り、書き込み、および実行のアクセス許可に対応します。 ビットが設定されている場合、対応する文字が最終的な許可文字列に表示されます。それ以外の場合は、ダッシュが使用されます。 

各テスト ケースの出力は 9 文字の文字列です。 これは、3 桁のそれぞれを 3 文字のブロックに拡張し、そのブロックを所有者、グループ、その他の順序で連結することによって形成されます。 

制約は小さく、テスト ケースは最大 100 個で、ケースごとの作業は一定です。 これにより、入力ラインごとの線形処理を超えるものは即座に除外されますが、二次関数の動作も依然として通過します。 問題の構造は固定幅デコードであるため、パフォーマンスは主な問題ではありません。 

よくある間違いは、ビット順序の誤解から生じます。 最上位ビットは読み取りに、中間ビットは書き込みに、最下位ビットは実行に対応します。 たとえば、数字 6 はバイナリ 110 に対応します。これは、読み取りと書き込みは有効ですが、実行は無効であることを意味し、文字列「rw-」が生成されます。 もう 1 つのよくあるエラーは、各トリプレット内の文字の順序が逆になることで、「wr-」や「-rw」などの誤った順列が発生します。 

## アプローチ

 ブルートフォースのアイデアは、各桁を 0 から 7 までの数値として扱い、モジュロまたはバイナリ変換ロジックを繰り返し使用して各アクセス許可を明示的にテストすることです。 すべての桁について、2 で割ることを繰り返すか、ビットを 1 つずつ抽出して、一時配列に文字列を構築することができます。 これは正しいです。各桁が 3 つの独立したブール フラグを正確にエンコードしているからです。 

このアプローチは、ビットが 3 つしかないため、桁ごとにすでに一定時間で実行されますが、より冗長でエラーが発生しやすい方法で記述される傾向があります。 文字列操作やループ内での連結の繰り返しを使用して不注意に実装すると、理論上の複雑さはわずかであっても、不必要に遅くなったり、煩雑になったりする可能性があります。 

重要な観察は、各桁が 3 つの固定ビット位置に直接マッピングされていることです。 バイナリ抽出をシミュレートする代わりに、ビット単位の演算を使用できます。 これにより、解決策は 3 つのビットのそれぞれが設定されているかどうかを直接検索することになります。 1 桁あたりの可能な値は 8 つだけであるため、マッピングは完全に決定的で一定時間になります。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取り、各入力文字列を繰り返し処理します。 
2. 文字列内の各文字を整数に変換します。 
3. 各桁について、読み取り、書き込み、実行という固定の順序で許可文字を決定します。 
4. 各権限について、ビットごとの AND を使用して、数字の対応するビットを確認します。 
5. ビットが設定されている場合は、対応する文字を追加し、設定されていない場合はダッシュを追加します。 
6. すべての桁の 3 文字のブロックを連結し、結果の 9 文字の文字列を出力します。 

この順序付けが機能する理由は、問題がビットと許可タイプの間の厳密な位置マッピングを定義しているためです。 各桁は独立しているため、所有者、グループ、その他の間で相互依存関係なくデコードをローカルで実行できます。 

### なぜ効果があるのか

各桁は 3 要素セットのサブセットをエンコードし、各要素はアクセス許可のタイプに対応します。 数字のバイナリ表現は、まさにそのサブセットの特性ベクトルです。 ビットから文字へのマッピングは固定的かつ単射的であるため、各ビットを個別にチェックして文字列を再構築すると、曖昧さのないすべての情報が保存されます。 デコードされたブロックを連結すると、完全な許可文字列が一意に再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def decode_digit(d):
    r = 'r' if d & 4 else '-'
    w = 'w' if d & 2 else '-'
    x = 'x' if d & 1 else '-'
    return r + w + x

t = int(input())
out = []

for _ in range(t):
    s = input().strip()
    res = []
    for ch in s:
        d = ord(ch) - ord('0')
        res.append(decode_digit(d))
    out.append(''.join(res))

print('\n'.join(out))
```実装の中核となるのは、`decode_digit`関数。ビットごとの AND を使用して 3 つの許可ビットを分離します。 定数 4、2、および 1 は、それぞれ読み取り、書き込み、および実行位置のバイナリ重みに対応します。 

メイン ループは、この変換を各文字に個別に適用し、結果を連結するだけです。 蓄積にリストを使用すると、文字列連結のオーバーヘッドの繰り返しが回避されます。これは不要ですが、それでも Python 競技プログラミングでは良い習慣です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def decode_digit(d):
        r = 'r' if d & 4 else '-'
        w = 'w' if d & 2 else '-'
        x = 'x' if d & 1 else '-'
        return r + w + x

    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        res = []
        for ch in s:
            d = ord(ch) - ord('0')
            res.append(decode_digit(d))
        out.append(''.join(res))

    return '\n'.join(out)

# provided sample (interpreted)
assert run("2\n760\n123\n") == "rwxrw----\n--x-w--wx"

# minimal case
assert run("1\n0\n") == "---------"

# all ones
assert run("1\n111\n") == "--x--x--x"

# full permissions
assert run("1\n777\n") == "rwxrwxrwx"

# mixed case
assert run("1\n504\n") == "r-x---r--"

 ## 特殊なケース

 のような入力の場合`0`、数字にはビットが設定されていないため、3 つの権限はすべてダッシュにマップされます。 アルゴリズムが評価するのは、`0 & 4`、`0 & 2`、 そして`0 & 1`、これらはすべて false であり、各グループに「---」が生成されます。 これを 3 回繰り返すと、9 つのダッシュからなる完全な文字列が得られ、これは意図した空の権限状態と一致します。 

のような入力の場合`7`、すべてのビットが設定されます。 小切手`7 & 4`、`7 & 2`、 そして`7 & 1`すべて true として評価され、「rwx」が生成されます。 この動作はすべての桁で一貫しており、各桁が独立して処理されるため、グループ間の干渉がなく、均一な場合や極端な場合でも正確性が保証されます。
