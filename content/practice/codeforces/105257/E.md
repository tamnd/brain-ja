 ## 解決策
 ## 問題の理解

 私たちに与えられた円は次のように分割されます。$K$等間隔の位置とそのサブセット$n$これらのポジションには市場が含まれています。 各市場は円上の固定点に位置するため、入力は円形配列上のインデックスの増加シーケンスと考えることができます。 

あらゆる市場向け$i$、そこから別の市場への有向接続を引き出すことが許可されています$j$ただし、次の場合に限ります。$j$～から最も遠い市場の一つです$i$円に沿って。 距離は、円上の 2 点間の短い円弧に沿って測定されるため、「最も遠い」とは、その円形の距離が最大になることを意味します。 複数の市場が同じ最大距離を達成する場合は、そのうちのいずれかを選択できます。 

選択された各接続は、円の内側に描かれたコードになります。 可能な限り多くの有効な有向接続を選択したいと考えていますが、2 つのコードが端点以外の場所で交差したり重なったりすることは許可されないという制限があります。 

出力は、構築できるこのような交差しない有向接続の最大数です。 

制約$n \le 10^5$に近いものが必要であることを意味します$O(n \log n)$または$O(n)$。 市場のすべてのペアを試したり、交差をペアごとにチェックしたりするものは、二次関数の動作によりすぐに失敗します。 

微妙な問題は、円形のジオメトリに起因します。 市場の最も遠い有効なターゲットは、単一の点ではなく、円の反対側にある連続した領域です。 これは、各送信元ノードが 1 つの固定された宛先を指すのではなく、候補の間隔全体を指すことを意味します。 ノードごとに最も遠い候補を恣意的に選択する単純なアプローチでは、大域的な最適性が簡単に崩れる可能性があります。これは、「不適切な」最も遠いエンドポイントを先に選択すると、その後の多くの非交差エッジがブロックされる可能性があるためです。 

別の失敗例は、複数の市場がまさに最も遠い境界線上にある場合に発生します。 たとえば、点が対称である場合、複数の目的地が結びつき、異なる選択により異なる交差構造が生成されます。 将来の実現可能性を考慮せずに欲張った選択をすると、答えが減ってしまう可能性があります。 

## アプローチ

 ジオメトリを少し無視すると、強引なアイデアは簡単です。つまり、あらゆる市場に対応するということです。$i$、有効な最も遠い目的地をすべて試してください$j$、次に、どの弦も交差しないようにエッジのサブセットを選択してみます。 これは、円上の幾何学的間隔選択問題になります。 候補エッジのすべてのペアの交差をシミュレートし、すべてのサブセットを試すことができます。 これはすぐに指数関数的な検索に陥り、単一のサブセットの有効性をチェックするだけでも時間がかかります。$O(n^2)$交差点テスト。 

重要な単純化は、「円の最遠」が実際に何を意味するかを理解することから生まれます。 マーケットをポジションで固定すると$x$、その最も遠い市場はまさに、$x$。 ソートされた位置の観点からは、これはインデックスの連続した間隔になります。 したがって、各ノードが単一の宛先を持つのではなく、各ノードには可能な宛先の間隔があります。 

さて、問題は次のとおりです。$n$それぞれのソースには許可されたターゲットの間隔があり、できるだけ多くのペアを選択したいと考えています$(i, j)$できる限りそれぞれが$i$ソースとして使用されるのは最大 1 回だけです。$j$は宛先として最大 1 回使用され、結果として得られるコードは交差しません。 直線上では (円を適切に分割した後)、非交差構造は単調な順序付け制約に対応します。$i_1 < i_2$、その場合は、次のことを避けなければなりません。$j_1 > j_2$。 

これにより、問題は互換性のある間隔割り当ての最大数を選択することに変わります。 各ソース$i$パートナーが欲しい$j$内部$[L_i, R_i]$そして、順序を維持する方法で、ソースを個別のターゲットに貪欲に一致させたいと考えています。 このような割り当てを最大化する古典的な方法は、正しいエンドポイントの昇順にソースを処理し、常に最も早い利用可能な有効なターゲットを割り当てることです。 これにより、初期のノードで大きな選択肢を無駄にせず、後のノードでの柔軟性を確保できます。 

未使用の候補を追跡するデータ構造をソートして使用することで、これを効率的に実装できます。

 ## アルゴリズムのチュートリアル

 1. まず、市場ポジションを昇順に並べ替え、それらを円ではなく線上の点として扱います。 これは、最も遠い構造の候補を壊すことを避ける開始カットを選択できるため安全です。 概念的には、円をセグメントに「展開」します。 
2. 市場ごとに$i$、その最遠距離を計算します。 円上で最も遠い領域は、まさにその点からの円周距離が同じである点です。$i$最大化され、円の反対側の半分に相当します。 ソートされた座標では、これは連続したインデックス間隔になります。$[L_i, R_i]$。 
3. 各市場を解釈する$i$リクエストとして: 正確に 1 つのターゲットに一致する必要があります$j$その間隔から選ばれる$[L_i, R_i]$。 有効な解決策はすべて、そのような一致を選択することに対応します。 
4. すべてのソースを並べ替える$i$増やすことで$R_i$。 この順序により、右のエンドポイントが小さいほど、可能なターゲットが少なくなることを意味するため、常に最も制限された選択肢が最初に処理されることが保証されます。 
5. 目的地として機能する、現在使用されていない市場指数の構造を維持します。 ソートされた順序でソースを処理する際、許可された間隔内で利用可能な最小のインデックスを各ソースに割り当てます。$[L_i, R_i]$。 ターゲットが使用されると、そのターゲットは利用可能から削除されます。 
6. 割り当てが成功するたびに答えが 1 つずつ増え、すべてのソースが処理されるまで続行されます。 

### なぜ効果があるのか

 各ソース間隔は、最大距離を維持する可能性のあるすべての最も遠いエンドポイントを表します。 重要な特性は、任意の有効なソリューションを、エッジの数を減らすことなく、目的地が位置の昇順で割り当てられるソリューションに変換できることです。 この単調な構造を強制すると、問題は標準的な貪欲な間隔マッチングになります。つまり、実行可能な最も早い宛先を取得しても、より良いグローバル ソリューションがブロックされることはありません。これは、後のソースでは、以前のソースが取得できた可能性のある以前の未使用の宛先を使用するメリットが得られないためです。 

これにより、貪欲な割り当てが間隔制約の下で最大サイズの非交差マッチングを生成することが確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    K, n = map(int, input().split())
    a = list(map(int, input().split()))

    a.sort()

    # Compute intervals [L, R] of farthest candidates
    # Distance on circle -> opposite semicircle
    L = [0] * n
    R = [0] * n

    # We will treat circle linearly; farthest region is half-circle away.
    # Convert K to "half range"
    half = K / 2

    # For each i, we find points within distance ~half in circular sense.
    # Using two pointers over sorted array.
    j1 = 0
    j2 = 0

    for i in range(n):
        # move j1 to maintain left boundary (too close clockwise)
        while j1 < n and (a[i] - a[j1]) % K < half:
            j1 += 1
        # move j2 to maintain right boundary (within half in opposite direction)
        while j2 < n and (a[j2] - a[i]) % K <= half:
            j2 += 1

        L[i] = j1
        R[i] = j2 - 1

    # Greedy matching on intervals
    used = [False] * n
    ans = 0

    # sort indices by R
    order = sorted(range(n), key=lambda i: R[i])

    ptr = 0
    for i in order:
        # find smallest available j in [L[i], R[i]]
        j = L[i]
        while j <= R[i] and used[j]:
            j += 1
        if j <= R[i]:
            used[j] = True
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装の中心となるアイデアは、循環「最も遠い」制約をインデックス間隔に変換することです。 2 ポインター スイープは、並べ替えられた配列に対して線形時間でこれらの間隔を構築します。 その後の問題は純粋にインターバル割り当てタスクになります。 

微妙な点は、エッジを幾何学的に明示的に構築することは決してないということです。 インデックス空間でのみ推論します。 これにより、右エンドポイントによる貪欲な順序付けにより非交差が暗黙的に強制されるため、コード交差テストを直接処理することが回避されます。

 ## 特殊なケース

 重要なエッジケースの 1 つは、すべての市場が単一の半円内にある場合です。 この状況では、すべてのポイントの最も遠い領域が同様の反対の間隔に崩壊し、すべてのポイント間で重度の重複が生じます。$[L_i, R_i]$。 適切なエンドポイントによる貪欲な順序付けにより、最も狭い間隔を最初に消費することで、引き続き最大数の素な割り当てを抽出できます。 

もう 1 つのケースは、市場が円の周りに等間隔に配置されている場合です。 ここでは、各区間がほぼ単一の候補となります。 このアルゴリズムは直接マッチングのように動作し、最大数に達するまで、すべてのソースを個別にペアにすることができます。 

3 番目のケースは、複数の候補者が最も離れて並んでおり、間隔が広くなっている場合に発生します。 各ソースには柔軟性がありますが、貪欲な構造により、将来のより厳しい制約を妨げない場合にのみ柔軟性が使用され、最適性が維持されます。
