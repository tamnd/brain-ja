 ## 解決策
 ## 問題の理解

 ジムで 2 人のアスリートが交互に固定サイズの反復ブロックを行います。 マルセルは常に最初のブロックを実行し、次にジョアンサン、次に再びマルセルというように実行します。 各ブロックには正確に次の内容が含まれます`M`繰り返し。 彼らは個人ごとの個別の貢献を追跡しません。 代わりにカウンターが 1 つあります`N`合計で何回繰り返しが完了したかを記録します。 

タスクは、誰の順番が次に来るかを正確に決定することです`N`ターンが厳密にサイズのブロックで交互に行われることを考えると、繰り返しはすでに実行されています`M`。 

この状況を言い換える便利な方法は、一連の繰り返しがサイズの塊に分割されていると想像することです。`M`。 チャンク 0 はマルセルのもの、チャンク 1 はジョアンサンのもの、チャンク 2 は再びマルセルのもの、というようになります。 合計`N`これは、このチャンク化されたシーケンス内でどのくらいの距離にいるのかを示し、現在どのチャンクにいるのか、そしてそれがすでに終了しているかどうかを識別する必要があります。 

制約により許可されるのは、`N`そして`M`まで`10^9`。 これにより、最悪の場合、最大 10 億ステップが必要になるため、繰り返しを繰り返すシミュレーションは即座に除外されます。 代わりに、ソリューションでは算術演算を使用して一定時間内に答えを計算する必要があります。 

微妙なエッジケースが現れるのは、`N`はまさに次の倍数です`M`。 たとえば、次の場合`M = 3`そして`N = 6`、ちょうど 2 つの完全なブロックが完了しました。 この状況では、新しいブロックの開始点にいるため、ジョアンオザンがフルブロックを完了した後は常にマルセルからターンが再開されるため、次はマルセルになるはずです。 チェックだけを行う単純な実装`(N // M) % 2`ブロックの内側にいるのか、ブロックの境界にいるのかを考慮せずに、完了と部分的な進行を同じように扱うと、答えが間違って移動しやすくなります。 

もう 1 つの重要なエッジケースは次のような場合です。`N < M`。 たとえば、次の場合`M = 8`そして`N = 6`、私たちはまだマルセルの最初のブロック内にいます。 次の完全なブロック境界に到達していませんが、正解は依然として Marcel です。 

## アプローチ

 ブルートフォース シミュレーションでは、繰り返しを 1 つずつ追跡し、ブロックごとにアクティブな人を切り替えます。`M`繰り返しが完了しました。 現在のブロックの進行状況のカウンターと、誰のターンであるかの切り替えを維持します。 繰り返すたびにカウンタが増加し、カウンタがその値に達すると、`M`、リセットしてプレイヤーを切り替えます。 

このアプローチは、問題で説明されているプロセスを直接反映しているため、正しいです。 ただし、実行します`N`繰り返し、そしてそれ以降`N`と同じ大きさにすることができます`10^9`、制限時間内に走るには遅すぎます。 

重要な観察は、次のターンを決定するのに重要なのは完全なブロックのみであるということです。 毎`M`繰り返すと、アクティブなプレーヤーが反転します。 したがって、個々の繰り返しをシミュレートする代わりに、完了した完全なブロックの数を数えるだけで済みます。`N // M`そして、部分的に完成したブロックの内側にいるのか、それとも正確に境界にいるのかを判断します。 

「ブロックの内部」と「正確な境界」の区別により、現在のブロックと次のブロックのどちらを見るべきかが決まります。 もし`N % M == 0`、新しいブロックの開始点にいるため、次のプレイヤーは完了したブロックのパリティによって直接決定されます。 もし`N % M != 0`、まだ現在のブロック内にいるので、次のプレイヤーが現在アクティブなプレイヤーになります。

 ## アルゴリズムのチュートリアル

 1. サイズの完全なブロックの数を計算します。`M`整数除算を使用して完全に終了します`q = N // M`。 ターンが完全に切り替わった回数をカウントします。 ブロックが完成するたびにアクティブなプレイヤーが反転するため、これは重要です。 
2. 現在のブロック内でどのくらいの距離にいるかを計算します。`r = N % M`。 これにより、正確に境界にいるのか、それともまだブロックの途中にいるのかがわかります。 
3. もし`r == 0`の場合、部分的に塗りつぶされたブロックでは現在、繰り返しは実行されていません。 次に開始するブロックはブロックです`q`したがって、次のプレイヤーの身元は、次のプレイヤーかどうかによってのみ決まります。`q`偶数または奇数です。 Marcel はブロック 0 から始まるため、偶数のインデックスは Marcel に対応し、奇数のインデックスは Joãozão に対応します。 
4. もし`r != 0`、私たちはブロック内にいます`q`。 つまり、現在アクティブなプレーヤーがまだこのブロックで作業しているため、次の繰り返しはブロックに割り当てられた同じプレーヤーに属します。`q`。 同じパリティ ルールが適用されます。 
5. 次の場合は「MARCEL」を出力します。`q`偶数である場合、「JOAOZAO」を出力します。 

中心となる決定により、プロセス全体が、どのブロックにいるのかを追跡し、パリティを使用してブロックをプレーヤーにマッピングするまでに短縮されます。 

### なぜ効果があるのか

 サイズの各完全なブロック`M`1 人のプレイヤーによる中断のないターンに正確に対応し、マルセルから開始して決定的に交互にターンします。 したがって、ブロックインデックスだけでプレイヤーを一意に決定します。 残り`r`どのブロックにいるのかは変わりません。ただ、そのブロックの端にいるのか、その中にいるのかだけです。 次のアクションは常に現在のブロック割り当てによって決定されるため、次のアクションのパリティは`q`すべての場合において正しいプレーヤーを決定するにはこれで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

N = int(input())
M = int(input())

q = N // M
r = N % M

if q % 2 == 0:
    print("MARCEL")
else:
    print("JOAOZAO")
```コードは最初に 2 つの整数を読み取り、完了した完全なブロックの数を計算します。 剰余は計算されますが、ブロックの内側にいるのか境界にいるのかを確認する以外の最終的な決定には影響しません。どちらの場合も同じパリティ ベースのルールに解決されます。 

重要な実装上の選択は、シミュレーションを完全に無視することです。 除算の動作を確認する以外に、ブロック内の進行状況を追跡する必要はありません。 整数の除算とモジュロはシステムの状態を完全にエンコードします。

 ## 特殊なケース

 いつ`N = 0`、繰り返しは実行されていません。 アルゴリズムは計算します`q = 0`これは偶数であるため、Marcel が出力されます。 これは、マルセルが常に最初にスタートするという事実と一致します。 

いつ`N`は正確に割り切れます`M`、 のような`N = 20, M = 5`、 我々は持っています`q = 4`。 アルゴリズムはこれを新しいブロックの開始として扱い、ブロック 4 が再び Marcel (偶数インデックス) に対応するため、出力は正確になります。 

いつ`M = 1`、すべての繰り返しは独自のブロックです。 このアルゴリズムは、問題を各ステップの交互実行とパリティに縮小します。`N`予想される交互シーケンスと一致する結果を直接決定します。
