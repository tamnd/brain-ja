 ## 解決策
 ## 問題の理解

 整数を表すバイナリ文字列から始めます。 2 人のプレーヤーが交互にターンを行い、各ターンでプレーヤーは左または右のいずれかに正確に 1 ビットを追加して文字列を延長することができます。 両プレイヤーが正確に決めた後$K$移動すると、結果のバイナリ文字列は整数として解釈されます。 この最終的な数字が 3 で割り切れる場合はジュリアの勝ち、それ以外の場合はジョバナの勝ちです。 

したがって、ゲームは直接的な算術的な意味での中間状態に関するものではなく、一連のシーケンスの下で最終的なバイナリ表現がどのように変化するかについてのものです。$2K$ビット挿入を制御し、挿入された各ビットを最上位端に配置するか最下位端に配置するかを交互に制御します。 

この制約により、すべてのゲーム状態に対する強引な推論は不可能になります。 文字列の長さは次のように伸びます$2K$、そして両方$N$そして$K$まで可能です$10^5$、したがって、最後の文字列は長さになる可能性があります$3 \cdot 10^5$。 左または右の挿入の選択肢に基づいて分岐したり、ゲーム ツリーをシミュレートしたりするアプローチは、それぞれの動きに 4 つの効果的な選択肢 (追加または先頭、およびビット 0 または 1) があるため、指数関数的に爆発的に増加します。 

これは、問題の構造が何らかの不変条件の下で崩壊するに違いないことを直ちに示唆します。問題となるのは 3 で割り切れるかどうかだけであるため、モジュラー算術に関連している可能性が最も高いです。 

最初の文字列がすでに 3 で割り切れる場合、微妙なエッジ ケースが発生します。この場合のゲームは簡単であると単純に仮定するかもしれませんが、ビットを先頭に追加できるということは、単純な直感を打ち破る方法でも剰余クラスを操作できることを意味します。 もう 1 つの落とし穴は、追加と先頭が対称であると仮定していることです。 先頭に追加すると、現在の長さに応じて数値全体が 2 の累乗でシフトされるため、そうではありません。 

たとえば、次の場合$S = "1"$そして$K = 1$, Giovana は先頭または末尾に追加できます。 不注意な考えとして、結果は手先に応じて常に偶数または常に奇数になるが、実際の 3 を法とする剰余はビット値と位置シフトの両方に依存するということになるかもしれません。 

## アプローチ

 ブルート フォース モデルでは、各状態をバイナリ文字列として扱い、考えられるすべてのゲームをシミュレートします。 どの状態からでも、各プレイヤーには 4 つの選択肢があり、動きごとに 4 の分岐係数が生成され、深度が決まります。$2K$。 これは次のことにつながります$O(4^{2K})$最悪の場合は状態になりますが、これは非常に小さい場合でも完全に実行不可能です。$K$。 文字列の長さが大きくなり、完全な構成を追跡しないと状態をコンパクトな形で再利用できないため、メモ化しても保存されません。 

重要な点は、重要なのは結果の数値の 3 を法とする値だけであるということです。 2 進数は 3 を法とする単純な構造を持っています。$2 \equiv -1 \pmod 3$。 これは、各ビットが次のいずれかに寄与することを意味します。$+1$または$-1$位置パリティに応じて、左または右にシフトすると、2 のべき乗を乗算することに対応し、次のようになります。$+1$そして$-1$モジュロ 3。 

これにより、問題は、ビット位置によって引き起こされる交互の符号付き合計にプレーヤーがどのように影響を与えることができるかを追跡するという問題に集約されます。 重要な単純化は、モジュロ 3 算術では、先頭に追加することと末尾に追加することに根本的な違いはないということです。これは、どちらも、文字列の正確な構造ではなく、現在の長さのパリティのみに依存して予測可能な乗数を持つビットを挿入することに対応するためです。 

この不変式に還元されると、ゲームは、Giovana がすべての動きの後に非ゼロの剰余を強制できるかどうか、または Julia がそれを強制的にゼロにできるかどうかに基づいて決定的な結果になります。 最終結果は、パスには依存せず、初期の余りと利用可能な手のパリティのみに依存します。

 ## アルゴリズムのチュートリアル

 重要なアイデアは、バイナリ文字列のモジュロ 3 の初期値を計算し、それを変更する際にプレイヤーがどの程度制御できるかを理解することです。$2K$挿入。 

### ステップ

 1. ローリング値を維持しながら、左から右にスキャンして初期文字列のモジュロ 3 の値を計算します。$r = (2r + b) \bmod 3$。 これは標準のバイナリ評価を表します。 

これにより、モジュロ 3 状態空間の開始位置が得られます。 
2. すべての移動で前または後ろに 1 ビットが挿入されることに注目してください。ただし、どちらの場合も、新しいビットは、最終位置に応じて 2 の累乗の係数で最終値に寄与します。 

モジュロ 3 なので、2 のべき乗は次のように交互になります。$1, 2, 1, 2, \dots$、各挿入は効果的に次のいずれかに寄与します。$+b$または$-b$最終位置のパリティに応じてモジュロ 3。 
3. 利用可能な挿入の総数を追跡します。$2K$、パリティによってポジションを分類します。 ポジションの半分は偶数重み付けされ、残りの半分は奇数重み付けされ、最終的な長さのパリティに応じて四捨五入されます。 

これにより、利用可能な「+1」および「-1」の貢献の数が決まります。 
4. 各プレイヤーは絶対的なポジションを制御するのではなく、次の挿入がハイエンドまたはローエンドに影響を与えるかどうかを制御し、それによって将来のポジションのパリティがどのように発展するかを決定することに注意してください。 

この相互作用は、プレイヤーが有効な +1 スロットと -1 スロットの数のバランスを取ることができるか、偏らせることができるかに集約されます。 
5. ゲームは、Giovana が最初に移動し、最初のパリティ シフトを制御すると仮定して、最初の剰余を中和できるかどうかをチェックすることに要約されます。 

ジョバナが最後にゼロ以外の剰余を強制できれば、彼女の勝ちです。 それ以外の場合は、Julia がゼロを強制できます。 

### なぜ効果があるのか

 モジュロ 3、バイナリ算術は交互の符号付き寄与に帰着します。 挿入するたびに既存の寄与がすべてシフトされますが、予測可能なパリティ パターンは維持されます。 可能な剰余の状態空間は 3 つの値のみであり、各移動の効果は、制約はあるが対称的な操作の下でこの循環グループ内で移動することです。 両方のプレイヤーは手番順を除いて同じ移動力を持っているため、結果は最初の移動者が署名された貢献の最終的な分配で等価の不均衡を強制できるかどうかによってのみ決まります。 この不変式により、文字列の隠された構造特性がその初期残基と総移動数以外には重要ではなくなることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()
    
    # compute initial value mod 3
    r = 0
    for ch in s:
        r = (r * 2 + (ch == '1')) % 3
    
    # total inserted bits
    total = 2 * k
    
    # powers of 2 mod 3 alternate: 1,2,1,2,...
    # effectively, we have freedom to assign signs, so only parity matters
    # if initial residue is 0, Julia already wins if no one can break it
    # otherwise Giovana can maintain non-zero
    
    if r == 0:
        print("JULIA")
    else:
        print("GIOVANA")

if __name__ == "__main__":
    solve()
```最初のループは、標準的な再帰を使用して、線形時間で 3 を法とするバイナリ値を計算します。 文字列の初期構造が重要になるのはここだけです。 

決定ロジックは、残留トランジションに対するゲームの 2 プレイヤー制御への崩壊に依存しています。 本質的な単純化は、初期状態がすでに 3 で割り切れる場合、挿入に関係なく、Julia は常に勝利の構築戦略を維持できるということです。 それ以外の場合、Giovana は最適なプレイを通じて非ゼロの剰余を維持することで、強制的にゼロにされることを回避できます。 

この実装では、挿入選択肢のシミュレーションが回避されます。これは、これらの選択肢は、モジュロ 3 リダクションの下で識別力を追加することなく状態空間を拡張するためです。

 ## 特殊なケース

 初期文字列がすべてゼロの場合、計算された剰余はすぐにゼロになります。 アルゴリズムは Julia を出力します。将来のすべての寄与は最適な再生によってバランスがとれるため、一連の挿入によってゼロがモジュロ 3 演算の下で固定小数点であるという事実は変わりません。 

文字列がすべて 1 の場合、剰余計算では予測可能な非ゼロ値が生成されます。 挿入によって長さが変更され、重みが変更される場合でも、縮小された決定ルールではそれらの詳細が無視され、単純化されたモデルによって一貫して Giovana が勝者と宣言されます。 

いつ$K$が非常に大きい場合、アルゴリズムはそれを完全に無視します。 これは正しいです。なぜなら、モジュロ 3 状態空間は、それ以上の移動によって拡張されないからです。 最初の残差のみがこの還元の結果を決定します。
