 ## 解決策
 ## 問題の理解

 この問題では、道路で接続された都市の無方向、無重みのグラフが得られます。 Lex は都市 1 から開始し、都市 N に到達する必要があります。一部の都市は「債務都市」としてマークされており、これらの都市を通過することは望ましくないことを意味します。 

パスは 2 段階で評価されます。 まず、パス上に出現する債務都市の数を数えます。 次に、負債都市の数を可能な限り少なくするすべてのパスの中で、道路ステップ数が最も少ないパスを選択します。 

したがって、目標は通常の意味での最短距離だけではありません。 代わりに、すべての都市には、債務セットに属している場合は 1 のペナルティが課され、そうでない場合は 0 のペナルティが課されます。 パスに沿ったこれらのペナルティの合計を最小化する 1 から N までのパスが必要であり、そのようなすべてのパスの中で使用されるエッジの数を最小限に抑えます。 

この制約により、エッジごとに線形または対数に近いグラフの走査が行われます。 最大 100,000 の都市と 100,000 の道路があるため、パスを列挙したり、ルートに対して指数関数的な検索を実行しようとしたソリューションは、すぐに失敗します。 1 秒の制限の下では 10^10 の演算は不可能であるため、ノードに対する二次アプローチでもすでに大きすぎます。 

重要な点は、最適化が辞書編集的であることです。 距離を最小限に抑えるだけであれば、BFS を使用できます。 負債の数を最小限に抑えるだけであれば、ノードの重みを指定した最短パスを使用することもできます。 難しいのは、両方を順番に最適化する必要があり、どちらも無視できないことです。 

いくつかのエッジな状況は、誤って対処しやすいものです。 

都市 1 または都市 N が債務都市である場合、コストにはそれらを含める必要があります。 たとえば、1 が債務都市であり、N が債務都市ではなく、N に直接エッジ 1 がある場合、正解は 0 と 1 ではなく、債務数 1 と距離 1 になります。 

もう 1 つの問題は、階段の多いパスが債務都市を回避し、短いパスが債務都市を通過する場合です。 たとえば、負債として 2 を含む三角形 1-2-N と、負債のない都市を含む代替のより長いルート 1-3-4-N では、負債の最小化が優先されるため、より長いルートを優先する必要があります。 

最後に、同じ負債数に対して複数の最適なルートが存在する可能性があります。 その場合でも、恣意的なタイブレークではなく、エッジ数が最小のものを選択する必要があります。 

## アプローチ

 強引なアイデアは、1 から N までのすべての単純なパスを列挙し、各パスに含まれる債務都市の数とその長さを計算し、最適なものを選択することです。 これは目的を正確に評価するため正しいですが、グラフ内の単純なパスの数は指数関数的に増加する可能性があります。 密なグラフ、または中程度に接続されたグラフでは、パスの数は実行可能な制限をはるかに超え、最悪の場合は 2^N を軽く超えます。 これにより、小さなグラフであってもブルート フォースを使用できなくなります。 

重要な観察は、これが各ノードがコストに寄与する最短経路問題であるということです。 エッジに沿ったすべての遷移は同じ構造を持っています。隣接する遷移に移動するとパスの長さが 1 増加し、ノードに入ると負債カウンタが 1 増加する可能性があります。これは、すべての状態を値のペアで表すことができ、辞書編集的にパスを比較できることを意味します。 

この構造は、距離をタプルとして扱うときにダイクストラのアルゴリズムがサポートするものとまったく同じです。 各ノードには、最もよく知られたペア (debt_count、steps) が割り当てられます。 近傍を探索するときは、これらのペアを更新し、常に辞書順に最小のものを保持します。 これが機能するのは、両方のコンポーネントが負ではなく、パス拡張がコンポーネントに追加されるだけであり、最適な部分構造が維持されるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのパス) | 指数 | O(N) 再帰スタック | 遅すぎる |
 | ディクストラと (借金、距離) | O(M log N) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 各都市を、負債都市の場合はコストが 1、そうでない場合はコストが 0 のノードとしてモデル化します。辞書編集的緩和を使用して、都市 1 から他のすべての都市に最良のコストを伝播したいと考えています。

1. 各エントリがペア (debt_count, distance) を格納する距離配列を初期化します。 すべての値を辞書編集的な意味で無限大に設定します。これは、非常に大きなペアを意味します。 開始ノード 1 のコストを (isDebt[1], 0) に設定します。 これは、道路を進む前にすでに都市 1 に立っていることを反映しています。 
2. (debt_count, distance) で順序付けされた優先キューを使用します。 開始状態 (isDebt[1], 0, 1) をプッシュします。 これにより、常に現在最もよく知られている状態を最初に展開することができます。 
3. キューが空でない間に、最小の辞書編集ペアを持つノードを抽出します。 この状態がこのノードに保存されている最良の値よりもすでに悪い場合は、より良いルートがすでに見つかっているため、スキップします。 
4. 現在のノードの近隣ノードごとに、候補状態を計算します。 新しい借金数は現在の借金に isDebt[neighbor] を加えたもので、新しい距離は現在の距離に 1 を加えたものです。これは、もう 1 本の道路を横断し、借金都市に入る可能性があることを反映しています。 
5. この候補ペアが辞書編集的に近隣ペアの格納値よりも小さい場合は、それを更新してキューにプッシュします。 
6. 到達可能なすべての州を処理した後、都市 N の答えは、保存されているペア (debt_count, distance) になります。 

これが機能する理由は、優先キューからノードを完成させるたびに、そのノードに対して可能な限り最適な辞書編集ペアが見つかっているという不変条件に基づいています。 代替パスはすでに処理されているか、以前のステップでより悪いプレフィックスが付けられている可能性があり、すべての拡張機能は非負の値を追加するだけであるため、後で改善されることはありません。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m, d = map(int, input().split())
    debt_set = set(map(int, input().split()))

    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    INF = (10**18, 10**18)
    dist = [INF] * (n + 1)

    start_cost = (1 if 1 in debt_set else 0, 0)
    dist[1] = start_cost

    pq = [(start_cost[0], start_cost[1], 1)]

    while pq:
        dcnt, dlen, u = heapq.heappop(pq)

        if (dcnt, dlen) != dist[u]:
            continue

        for v in g[u]:
            ndcnt = dcnt + (1 if v in debt_set else 0)
            ndlen = dlen + 1
            nd = (ndcnt, ndlen)

            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (ndcnt, ndlen, v))

    print(dist[n][0], dist[n][1])

if __name__ == "__main__":
    solve()
```グラフは隣接リストとして保存され、高速な近隣反復をサポートします。 優先キューには、最初に負債数、次にパス長によって順序付けされた状態が格納され、辞書編集上の正確性が保証されます。 

よくある落とし穴は、負債コストがエッジではなくノードに関連付けられているということを忘れていることです。 そのため、アップデートで追加されるのは、`v in debt_set`現在のノードを離れるときではなく、近隣ノードに入るときです。 

もう 1 つの微妙な点は初期化です。 開始ノードは、パスにすでに負債コストが含まれているため、負債コストを直ちに寄与します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、開始都市自体が債務都市である場合です。 アルゴリズムは、その都市を即座に含むものとして開始コストを正しく初期化します。 のような入力の場合`1 -> 2`都市 1 が債務リストにある場合、初期状態はすでに`(1, 0)`そして最終的な答えは、その避けられないコストを反映しています。 

もう 1 つのケースは、目的地が借金のある都市であるが、借金のない道を通ってのみ到達できる場合です。 コストはパスの完了時ではなく、ノード N への入口時に追加されるため、アルゴリズムは依然として宛先を正確にカウントします。 

3 番目のケースは、複数のパスの負債コストは同じだが長さが異なる場合です。 優先キューにより、等しい負債値の中で短いパスが最初に展開され、辞書編集的な比較によって正しい順序が維持されることが保証されます。
