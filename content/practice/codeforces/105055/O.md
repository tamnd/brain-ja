 ## 解決策
 ## 問題の理解

 状況は方向を間違えた単純なロードトリップです。 関連する距離は 2 つあります。1 つ目は、旅行者が間違った方向に進んだ後に移動した距離であり、2 つ目は、出発地から正しいルートに沿った目的地までの残りの距離です。 

間違いに気づいた後、彼らは向きを変えて旅の一部を事実上元に戻し、正しい道に沿って進みます。 実際に移動する合計距離は、間違った方向のセグメントと目的地までの修正されたルートの合計です。 

したがって、タスクは、迂回路と最終的な正しい移動を組み合わせたときに、合計で何キロ移動するかを計算することになります。 

入力には、A と B という 2 つの整数が与えられます。A は、方向転換するまでに間違った方向に移動した距離です。 B は出発地から目的地までの正しい距離です。 出力は、間違ったパスと正しいルートの両方を含む合計移動距離です。 

制約は小さく、各値は最大 10^6 です。 これにより、高度なデータ構造や最適化の必要性が即座に排除されます。 定数時間の算術式で十分です。 

順序、パリティ、または構造に関する微妙な特殊なケースはありません。 唯一意味のあるエッジ ケースは、A または B が 1 に等しい場合ですが、その場合でも計算は直接の算術合計のままです。 重要なのは、間違った方向のセグメントが打ち消されるのではなく、物理的に 2 回移動することを理解することです。1 回目は間違って進み、もう 1 回目は正しい経路に戻ります。 

## アプローチ

 強引な解釈では、旅を段階的にシミュレートすることになります。 間違った方向に A キロメートル前進し、次に出発点に A キロメートル戻り、最後に目的地に向かって B キロメートル移動することを想像することもできます。 これにより、合計移動距離は A + A + B になります。これは概念的には有効ですが、不必要なシミュレーションが発生します。 

問題の構造により、シミュレーションが冗長になります。 間違った方向への移動は、方向転換するときに正確に反映されます。つまり、迂回路の長さが最終的な距離の 2 倍に寄与することになります。 その後、正しいパスが一度追加されます。 これにより、反復を行わずにプロセスが直接的な式にまとめられます。 

重要な観察は、行程が 3 つの直線セグメントで構成されており、その長さは入力値によって完全に決定されるということです。 シミュレーションや状態追跡を必要とするステップ間に依存関係はありません。

 ## アルゴリズムのチュートリアル

 1. 間違った方向に移動した距離を表す整数 A を読み取ります。 この区間は往路と復路の計2回通過します。 
2. 出発地から目的地までの正しい距離を表す整数 B を読み取ります。 この区間は旅行の最後に 1 回だけ通過します。 
3. 合計距離を 2 × A + B として計算します。係数 2 は、方向の間違いによる往復を考慮します。 
4. 計算値を直接出力します。 

### なぜ効果があるのか

 移動経路は、長さ A の最初の前方への誤り、長さ A の戻り、そして長さ B の最終的な正しい横断という 3 つの互いに素なセグメントに分解されます。これらのセグメントは独立しており連続しているため、合計距離は加算されます。 距離は正味の変位ではなく物理的な移動を測定するため、重複やキャンセルはありません。 これにより、セグメントの長さを合計すると正確な合計距離が得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a = int(input().strip())
b = int(input().strip())

print(2 * a + b)
```このソリューションは 2 つの整数を読み取り、派生した式を直接適用します。 の使用`strip()`末尾に改行が存在する場合でも安全な解析が保証されます。 乗算は単一の式で加算の前に実行され、中間変数を回避しながらロジックを明示的に保ちます。 

唯一の微妙な点は、間違った方向への移動は破棄されず 2 回カウントされることを認識していることです。 これは直接エンコードされます`2 * a`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    a = int(input().strip())
    b = int(input().strip())
    return str(2 * a + b)

# provided samples
assert run("4\n2\n") == "10", "sample 1"
assert run("5\n7\n") == "17", "sample 2"
assert run("2\n4\n") == "8", "sample 3"

# minimum values
assert run("1\n1\n") == "3", "min case"

# asymmetric small values
assert run("1\n10\n") == "12", "small A, large B"

# large values
assert run("1000000\n1000000\n") == "3000000", "max case"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1、1 | 3 | 最小境界の正確性 |
 | 1、10 | 12 | セグメント間の不均衡 |
 | 10^6、10^6 | 3×10^6 | オーバーフローセーフな算術 |

 ## 特殊なケース

 可能な最小の入力は、両方の距離が 1 の場合に発生します。この場合、旅行者は 1 km 間違って 1 km 戻り、その後 1 km 正しく進み、合計 3 になります。式 2A + B は正しく 3 を生成し、最小限のパスでも構造が維持されることが確認されます。 

A = 10^6 および B = 1 など、A が大きく B が小さい場合、迂回が結果を支配します。 計算は依然として 1 つの式に減り、Python では任意精度の整数によるオーバーフローの問題は発生しません。 

B が大きく、A が最小の場合、迂回は最終セグメントに比べて無視できますが、それでもその値のちょうど 2 倍に寄与します。 これは、迂回が最終的なルートの長さとは無関係であり、加法分解がすべてのレジームで有効なままであることを確認します。
