 ## 解決策
 ## 問題の理解

 文字だけからなる文字列が与えられます`a`そして`b`。 この文字列は任意ではありません。バイナリ パスワードのエンコードであると想定されています。`0`ブロックに置き換えられました`ab`そしてそれぞれ`1`ブロックに置き換えられました`aba`。 元のパスワードはビットのシーケンスであり、エンコードではこれらの固定ブロックが順番に連結されます。 

私たちの仕事は、指定された文字列を生成した可能性のある有効な元のビット列を復元することです。 文字列を一連の有効なブロックに分割できない場合`ab`そして`aba`、失敗を報告する必要があります。 

したがって、本当の問題は、2 つの終端規則を伴う文字列文法に関する解析の問題です。 入力文字列が、連結によって生成された言語に属するかどうかを判断する必要があります。`ab`そして`aba`はいの場合は、有効な選択肢のシーケンスを 1 つ再構築します。 

長さの制限は最大 100,000 文字です。 これにより、考えられるすべてのセグメンテーションに対する指数関数的な検索が即座に除外されます。 間のすべての分割を試みる単純なバックトラッキング アプローチ`ab`そして`aba`複数の位置に分岐する可能性があり、最悪の場合、分解の数が指数関数的に増加します。`aba`2 つまたは 3 つのキャラクターを消費するかの選択が導入されます。 

したがって、線形または線形に近い解析戦略が必要です。 

プレフィックスが`aba`が発生します。 その位置では、両方の解釈が可能です。`aba`として`1`、または取る`ab`として`0`次に解析する文字を残します。 次のような入力でより長い一致が中断されることを常に優先する貪欲な戦略。`ababa`、どこに行くか`aba`有効な分解が存在する場合でも、最初は無効なサフィックスを残します。 

## アプローチ

 ブルート フォース ソリューションでは、文字列を位置 0 から分割しようとし、有効なトークンが見つかるたびに分岐します。 どの位置からでも`i`、 もし`s[i:i+2] = ab`、次のように解釈してみます。`0`、そしてもし`s[i:i+3] = aba`、次のように解釈してみます。`1`。 これにより、再帰ツリーが形成されます。`aba`2 つの継続に分岐できます。 

このアプローチの正しさは、考えられるすべてのセグメンテーションを調査するため、簡単です。 ただし、最悪の場合、次のような文字列が発生する場合があります。`ababababa...`、ほぼすべての位置で両方の選択が可能であり、再帰状態の数は長さに応じて指数関数的に増加します。 これは実現可能な範囲をはるかに超えています`n = 10^5`。 

重要な観察は、これが回線上の古典的な到達可能性の問題であるということです。各インデックスで`i`、接尾辞かどうかのみを気にします。`i..n`解析できる。 各ポジションは最大でも 2 つのフォワード ポジションにのみ依存します。`i+2`そして`i+3`。 この構造により、線形時間で右から左への動的プログラミングが可能になります。 

パスを探索する代わりに、ブール値の実現可能性配列を計算します。`dp[i]`で始まるサフィックスかどうかを示します。`i`完全に解析できます。 これがわかったら、DP テーブルを使用して有効な解を左から右に貪欲に再構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースバックトラッキング | O(2^n) | O(n) | 遅すぎる |
 | 動的プログラミング + 再構築 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 問題の状態を定義する

 私たちは定義します`dp[i]`位置から始まる部分文字列かどうかとして`i`有効なブロックに完全に分割できます。 位置`n`(文字列の終わり) は、空のサフィックスにはトークンが必要ないため、常に有効です。 

### 2. 右から左への遷移を計算する

 からのインデックスを処理します`n-1`まで`0`。 それぞれのポジションで`i`、有効なトークンを取得できるかどうかを確認します。 

部分文字列の場合`s[i:i+2]`等しい`ab`、次に移動できます`i+2`もし`dp[i+2]`それは本当です。 

部分文字列の場合`s[i:i+3]`等しい`aba`、次に移動できます`i+3`もし`dp[i+3]`それは本当です。 

保管します`dp[i] = true`いずれかのオプションが成功した場合。 

### 3. 有効な回答を再構築する

 もし`dp[0]`が false の場合、有効な解析が存在しないため、失敗が出力されます。 それ以外の場合はインデックスから開始します`0`有効なトランジションを繰り返し選択します。 私たちは取ることを好みます`ab`最初に（代表して）`0`) ただし、それが有効な接尾辞につながる場合に限ります。`dp`。 そうでない場合は、`aba`(代表して`1`）。 

この再構築により、一貫したビット シーケンスが確実に構築されます。 

### なぜ効果があるのか

 DP は次のことを保証します。`dp[i]`で始まるサフィックスの有効なセグメンテーションが少なくとも 1 つ存在する場合に、正確に true になります。`i`。 遷移ごとに問題が厳密に小さなサフィックスに縮小されるため、サイクルは存在しません。 再構築中は常に解決可能であることがわかっている状態に移行するため、途中で行き詰ることはありません。 これにより、出力が文字列の完全に有効な分解に対応することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

dp = [False] * (n + 1)
dp[n] = True

for i in range(n - 1, -1, -1):
    if i + 2 <= n and s[i:i+2] == "ab" and dp[i+2]:
        dp[i] = True
    if i + 3 <= n and s[i:i+3] == "aba" and dp[i+3]:
        dp[i] = True

if not dp[0]:
    print(":(")
    sys.exit()

i = 0
ans = []

while i < n:
    if i + 2 <= n and s[i:i+2] == "ab" and dp[i+2]:
        ans.append('0')
        i += 2
    else:
        ans.append('1')
        i += 3

print("".join(ans))
```DP 配列は逆方向に埋められるため、評価するときに`dp[i]`、 両方`dp[i+2]`そして`dp[i+3]`はすでに知られています。 再構築フェーズは、すべてのステップで少なくとも 1 つの有効な遷移が存在するという不変条件に依存します。`dp[0]`真実であることが確認されました。 

優先するという選択`ab`最初は任意です。 DP は少なくとも 1 つの有効なパスが残ることを保証するため、一貫したタイブレークは機能します。
