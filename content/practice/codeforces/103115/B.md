 ## 解決策
 ## 問題の理解

 私たちには、次のように書かれた仮想状態にある膨大な数の同一のプレーヤーから始まるプロセスが与えられています。$(0,0)$。 州$(a,b)$勝ったプレイヤーを表します$a$試合と負け$b$ゲーム。 ゲームは、プレーヤーが常にまったく同じ状態の他のプレーヤーとのみペアになるラウンドで展開します。 試合ごとに勝者の勝利数と敗者の損失数が増加するため、状態は$(a,b)$次の 2 つの可能な状態に分割されます。$(a+1,b)$そして$(a,b+1)$。 

プレイヤーは境界条件に達するとすぐに削除されます。$n$勝つか彼らが苦しむか$m$損失。 彼らがそのような境界に達すると、すぐにシステムから抜け出します。 

最初に、次のものがあります。$2^{n+m}$の選手$(0,0)$、すべてのプレイヤーが終了するまでプロセスが続きます。 複数のクエリの場合は、特定の境界状態で正確に終了するプレイヤーが何人いるかが尋ねられます。$(a,b)$、どちらか$a=n$または$b=m$。 

制約に関する重要な洞察は次のとおりです。$n$そして$m$と同じ大きさにすることができます$2 \cdot 10^5$、まであります$2 \cdot 10^5$クエリ。 これにより、プロセスのシミュレーションやプレイヤーごとの追跡が即座に除外されます。 暗黙的な状態空間は$O(nm)$、これは実現不可能です。 

正しいアプローチでは、プロセス全体を閉じた形式の組み合わせ式に圧縮する必要があります。 

早期撤退を考えると、微妙なエッジケースが現れます。 たとえば、プレーヤーが到達する$(n,b)$または$(a,m)$すぐに停止するため、より深い状態への流れが影響を受けているのではないかと疑われるかもしれません。 ただし、このプロセスは完全に対称的で質量が保存されています。すべての内部状態はその母集団を次の層に完全に分割し、終了では境界にあるノードのみが削除され、ノードに到達する数には影響しません。 

たとえば、小さなケースを考えてみましょう$n=2, m=1$。 シミュレートしてみると、数式を使用せずにパスをカウントすると面倒になり、状態に対する単純な DP がスケーリングすると依然として爆発することがすぐにわかります。 

## アプローチ

 強引な解釈では、状態全体の拡張をシミュレートすることになります。 各州$(a,b)$各試合で人口を半分に分割します。 状態の数はグリッドとして増加するため、$(0,0)$外側では、遷移の総数は深さが指数関数的になります。$n+m$、それは完全に不可能です。 

重要な洞察は、個人という観点から考えるのをやめ、代わりにプレイヤーがどのようにしてその状態に到達できるかという観点から考えることです。$(a,b)$。 すべてのプレイヤーは一連の勝ちと負けに対応し、勝ちが増えるたびに増加します。$a$そしてそれぞれの損失が増加します$b$。 到達$(a,b)$合計で正確に必要です$a+b$これらのステップの順序は自由に選択できます。 

したがって、への個別のパスの数は、$(a,b)$は単なる二項係数です$\binom{a+b}{a}$。 Each step in the process also halves the population because each group splits evenly into winners and losers. これにより、次の要因が導入されます。$2$各深さレベルでのスケーリング。 

注意深く追跡すると、各ステップでパスの重みが 1 分の 1 ずつ減少します。$1/2$、そしてへのパス以来$(a,b)$長さがある$a+b$、合計スケーリングは次のようになります。$2^{-(a+b)}$。 から始まる$2^{n+m}$、きれいな閉じたフォームが得られます。 

したがって、答えはシミュレーションではなく直接の組み合わせ式になります。

 ## アルゴリズムのチュートリアル

 1. 階乗および逆階乗を最大で事前計算します。$n+m$、二項係数を計算する必要があるため$\binom{a+b}{a}$モジュロ演算を効率的に実行します。 これにより、クエリごとの組み合わせの再計算が回避されます。 
2. クエリごとに$(a,b)$、プロセスが停止する境界状態として解釈します。 遷移をシミュレートしません。 代わりに、この正確な状態に到達する個別の進化パスがいくつあるかを計算します。 
3. 二項係数を計算する$\binom{a+b}{a}$、勝ちと負けのシーケンスが何回続くかを数えます。$(a,b)$。 
4. これにスケーリング係数を掛けます。$2^{n+m-a-b}$、これは初期母集団が$2^{n+m}$各ステップで 2 つのブランチ間で質量が効果的に均等に分配されます。 
5. 結果のモジュロを出力します。$10^9+7$。 

### なぜ効果があるのか

 重要な不変条件は、すべての内部状態がその人口全体を 2 つの子状態に均等に分配し、境界の終点を除いて質量が失われないことです。 これは、システムが、長さ以下のすべてのシーケンスを完全にバイナリ展開したように動作することを意味します。$n+m$ここで、各パスは均等かつ独立して、正確に 1 つの終端境界状態に寄与します。 各パスは勝ち負けの順序によって一意に決定されるため、パスをカウントするだけで十分であり、分割対称性により 2 の累乗による均一な重み付けが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modexp(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def solve():
    n, m, q = map(int, input().split())
    N = n + m

    fact = [1] * (N + 1)
    invfact = [1] * (N + 1)

    for i in range(1, N + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[N] = modexp(fact[N], MOD - 2)
    for i in range(N, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(x, y):
        if y < 0 or y > x:
            return 0
        return fact[x] * invfact[y] % MOD * invfact[x - y] % MOD

    pow2 = [1] * (N + 1)
    for i in range(1, N + 1):
        pow2[i] = pow2[i - 1] * 2 % MOD

    for _ in range(q):
        a, b = map(int, input().split())
        steps = a + b
        ways = C(steps, a)
        ans = ways * pow2[n + m - steps] % MOD
        print(ans)

if __name__ == "__main__":
    solve()
```階乗事前計算は高速な二項係数クエリをサポートし、2 のべき乗テーブルは繰り返しのべき乗を効率的に処理します。 重要な詳細は使用しています$a+b$組み合わせパスの深さとして調整し、$n+m-(a+b)$システムの初期スケーリングに合わせて調整します。 

よくある間違いは、次から次へと移行をモデル化しようとすることです。$(0,0)$プロセスが対称的であり、パスカウントがすでにすべての有効な進化を捕捉していることを認識していません。

 ## 特殊なケース

 主なエッジケースは次のような場合です$a=0$または$b=0$、つまり、純粋に 1 種類の結果を通じてその状態に到達することを意味します。 そのような場合には、$\binom{a+b}{a}=1$となり、答えは完全に 2 のべき乗のスケーリング係数になります。 階乗ベースの二項計算はこれらの極値に対して 1 を返すため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジケースは次のような場合です$a+b = n+m$、つまり、状態が最大の深さに到達したことを意味します。 ここで指数はゼロになるので、答えは正確に$\binom{n+m}{a}$、これ以上の分割が残っていないことを反映しています。 

最後に、境界状態は次のとおりです。$a=n$または$b=m$数式は座標を超えて勝ち境界状態と負け境界状態を区別しないため、特別な分岐を行わずに一律に処理されます。
