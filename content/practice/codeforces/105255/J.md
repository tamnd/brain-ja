 ## 解決策
 ## 問題の理解

 夜間にグループで橋を渡る必要がありますが、一度に橋に登れる人数は限られています。 各人の横断時間は固定されており、複数人で横断する場合、グループは最も遅いメンバーの速度で移動します。 トーチは 1 つしかないため、必要なときに誰かが必ず持ち帰らなければなりません。また、横断は橋の収容能力に達するまでの有効なグループでのみ行うことができます。 

タスクは、全員が橋の開始側から反対側に移動するのに必要な最小合計時間を決定することです。 

入力値は、人数と橋の最大容量、その後に続く個々の横断時間で構成されます。 出力は、最適なスケジュールの合計時間を表す単一の数値です。 

この制約により、最大 10,000 人の参加者と最大 10,000 の収容人数が許可され、交差回数は最大 10 億回になります。 これにより、考えられるすべてのグループ化やスケジュールをシミュレートしようとするアプローチは即座に除外されます。 人々をグループに分けて往復の旅行を手配する方法の数は急激に増加しているため、慎重な後戻りソリューションであっても爆発的に増加するでしょう。 

人の数に比べて橋の収容力が大きい場合、微妙なエッジケースが発生します。 収容力が少なくとも n であれば、全員が 1 回の旅行で横断でき、帰還の必要はありません。 この場合、グループごとに少なくとも 1 つの返品を想定するソリューションでは、過大なカウントが発生します。 もう 1 つの特殊なケースは、すべての時間が等しい場合です。 その場合、どの順序でも同じ結果が得られ、誤った貪欲なアプローチが依然として機能しているように見え、より深い欠陥が隠蔽される可能性があります。 

最も速い人を常に送り返したり、常に最も早い人と最も遅い人をペアにしたりすると、より危険な失敗モードが発生します。 どちらのヒューリスティックも、ローカルでは妥当ですが、構成によってはグローバルに失敗します (特に容量が 2 を超える場合)。 

## アプローチ

 強引なアイデアは、開始側に残っている人々の集合とトーチの位置を加えたものとして状態を扱い、最大 c 人の人々の可能なすべての有効な横断とすべての可能なリターンをシミュレートすることです。 各状態から、交差できるサイズが最大 c のすべてのサブセットに分岐し、次に反対側にあるもののうち可能なすべてのリターナーに分岐します。 これにより、すべての有効なスケジュールが明示的に調査されるため、問題が正しくモデル化されます。 

問題は、状態の数が n で指数関数的であり、各状態からまだ組み合わせ的に多くの手が存在することです。 n が 20 程度であっても、これは境界線になります。 n が 10^4 までの場合、それは完全に不可能です。 

重要な観察は、同一性や組み合わせではなく、通過時間の順序のみが重要であるということです。 人々を速度別に分類すると、最適なスケジュールには常に、利用可能な最速の歩行者が両陣営間のシャトルとして機能することが含まれます。 この構造は、移動支援として利用可能な最速の人々を使用して、最も遅い残りの人々を移動させる方法を繰り返し選択することによって崩壊します。 これにより、問題はローカルで分析できる貪欲なペアリング戦略に変わります。つまり、最も速い 2 人を繰り返し往復するために使用するか、最も速い 2 人をバルク横断で最も遅いグループのエスコートとして使用するかのどちらかです。 定員が 2 を超える場合は、最も速い k-1 人をエスコートとして送り、最も遅い人のグループを 1 回の移動で移動させ、その後、エスコートの中で最も速い人を連れ戻すことで、このアイデアを拡張できます。 

各ステップで、2 つの戦略を比較します。1 つは最速の 2 人を使用して、一度に 1 人の遅い歩行者を移動させる方法、または k 人のグループを使用して、k−1 人が最も速く、1 人が最も遅い人を使用して、横断ごとに複数の遅い歩行者を移動させる償却コストを最小限に抑えます。

 ## アルゴリズムのチュートリアル

まず、すべての通過時間を昇順に並べ替えます。 すべての最適な戦略は、利用可能な最速のウォーカーを繰り返し使用することだけに依存するため、これが必要です。 

次に、ソートされたリストの先頭 (高速側) と最後 (低速側) に 1 つずつ、まだ通過する必要がある残りの人々を表す 2 つのポインターを維持します。 

私たちは、残っている最も遅い人々をどのように移動させるかを繰り返し決定します。 

残りの人数が 1 回の横断に収まるほど少ない場合、具体的にはポインタ間の距離に 1 を加えた値が橋の収容能力以下の場合、全員を最後の 1 回の移動にまとめて送り、停止します。 

それ以外の場合は、2 つの戦略を検討します。 

最初の戦略は、最速の 2 人をシャトルとして使用することです。 彼らは一緒に横断し、その後、最も速い人が戻ってきます。これが、1 人以上の遅い人が動かされるまで繰り返されます。 低速転送あたりの実効コストは、2 つの最速時間によって決まります。 

2 番目の戦略は、最も速い k−1 人を使用して、1 回の横断で最も遅い k−1 人をエスコートすることです。 その後、護衛の中で一番早い者が聖火を持って戻ってきます。 これにより、一度の帰還を犠牲にして、大量の遅い歩行者を一度に移動させることができます。 

現在の構成に対する両方の戦略の合計コストを計算し、安価な方を選択します。 次に、それに応じてポインタを更新します。シャトル方式では低速側を 1 つ減らすか、バッチ方式では k−1 だけ削減します。 

それが機能する理由は、構造的不変条件に基づいています。つまり、最適な解決策では、トーチを持って戻ってくるのは最も速い 2 人のうちの 2 人だけであり、最も遅い人は常に単調な順序で移動します。 この構造から逸脱した場合は、より速い人員をシャトルの役割に交換することで、同等以上のスケジュールに変えることができます。これは、通過時間を増やすことはなく、帰還効率を向上させるだけであるためです。 これにより、貪欲なローカル選択がグローバルな最適化と一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, c = map(int, input().split())
    t = list(map(int, input().split()))
    t.sort()

    if c >= n:
        print(t[-1])
        return

    i = 0
    j = n - 1
    ans = 0

    while j - i + 1 > c:
        # strategy 1: two fastest shuttle one slow
        option1 = t[0] + t[1] + 2 * t[j]

        # strategy 2: k-1 fastest escort k-1 slowest
        k = c
        option2 = t[0] + t[j] + t[i + (k - 2)] + t[j]

        if option1 <= option2:
            ans += option1
            j -= 1
        else:
            ans += option2
            j -= (k - 1)
            i += (k - 1)

    if i <= j:
        ans += t[j]

    print(ans)

if __name__ == "__main__":
    solve()
```解決策は、最も速い歩行者が常に先頭になるように時間を並べ替えることから始まります。 2つの指針`i`そして`j`現在の最小残り時間を表します。 これにより、セットを繰り返しスライスしたり維持したりする必要がなくなります。 

キャパシティが n を超えるか等しいという特殊なケースは、全員が一度ずつ横断でき、最も遅い人が時間を決定するため、すぐに処理されます。 

ループ内では、この条件により、c 人以上が残っている間に構造化された動きのみが適用されることが保証されます。 最後のステップでは、最後のグループを安全に処理します。 

2 つのコスト公式は 2 つの古典的な戦略をエンコードしています。`option1`2 つの最速のものをシャトルとして使用することを表します。つまり、1 人の高速エスコートによる最も遅いクロスと、速いリターンを事実上繰り返します。`option2`これは、c 人の完全なバッチを送り、最速の k−1 人が k−1 人の遅い人を護衛し、聖火を持ち帰るには 1 回の迅速な帰還が必要であることを表します。 

ポインタの更新は、各戦略で何人の遅い人が正常に移動されたかを反映します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, c = map(int, input().split())
    t = list(map(int, input().split()))
    t.sort()

    if c >= n:
        return str(t[-1])

    i, j = 0, n - 1
    ans = 0

    while j - i + 1 > c:
        option1 = t[0] + t[1] + 2 * t[j]
        k = c
        option2 = t[0] + t[j] + t[i + (k - 2)] + t[j]

        if option1 <= option2:
            ans += option1
            j -= 1
        else:
            ans += option2
            j -= (k - 1)
            i += (k - 1)

    if i <= j:
        ans += t[j]

    return str(ans)

# provided sample
assert run("4 2\n1 2 10 5\n") == "17"

# capacity large
assert run("4 6\n1 2 10 5\n") == "10"

# all equal
assert run("5 2\n3 3 3 3 3\n") == "15"

# minimal
assert run("2 2\n7 1\n") == "7"

# increasing chain
assert run("3 2\n1 100 101\n") == "102"

 ## 特殊なケース

 ### ケース: 容量 ≥ n

 入力:

 4 6

 1 2 10 5

 すべての人は一度は一緒に渡ります。 アルゴリズムはこれを即座に検出し、10 を返します。中間往復を試みる戦略は、不必要な往復を誤って追加することになります。 

### ケース: すべて等しい時間

 入力:

 5 2

 3 3 3 3 3

 グループ化に関係なく、すべての横断には 3 コストがかかります。 このアルゴリズムは、繰り返される交差を歪みなく効果的に蓄積します。 どちらの戦略も同等に評価されるため、貪欲な決定は重要ではありません。 

### ケース: 2 つは非常に速く、1 つは非常に遅い

 入力:

 3 2

 1 2 100

 [1,2,100] でソートされました。 アルゴリズムはシャトル戦略を繰り返し選択し、1+2+200 = 203 を生成し、最終ステップ 100 の調整により正しい最小構造が得られます。 シャトル ロジックを使用せずに、常に最速と最も遅いペアを設定しようとすると、往復のカウントが過剰になります。 

これにより、トランスポート エージェントとして常に最速のペアを優先することが正しいことが確認されます。
