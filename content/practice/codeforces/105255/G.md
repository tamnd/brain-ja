 ## 解決策
 ## 問題の理解

 それぞれ最初に赤、緑、または青に色付けされた一連のライトと、一連のボタンが与えられます。 各ボタンはライトのサブセットに接続されています。 ボタンを押すと、接続されているすべてのライトに色の周期的な並べ替えが適用されます。つまり、赤が緑に、緑が青に、青が赤になります。 各ライトは最大 2 つのボタンの影響を受けます。 

目標は、すべての信号を赤にする、またはそれが不可能であると判断するためのボタンを押す最小回数を見つけることです。 

重要な問題は、プレスがライトごとに独立していないことです。 1 つのライトの最終的な色は、最大 2 つの入射ボタンがそれぞれ押された回数によって決まり、それらの選択は共有構造全体で相互作用します。 

制約は大きく、ライトの数は最大 2 · 10^5、総発生数は最大 4 · 10^5 です (各ライトは最大 2 つのボタンに表示されるため)。 すべてのプレスの組み合わせを試したり、ライトごとの状態を明示的に追跡したりするソリューションは失敗します。 唯一の実行可能なアプローチは、問題を制約の数において本質的に線形または線形に近いものに減らす必要があります。 

複数のライトを間接的に共有する 2 つのボタン間の一貫性を解決する方法がない場合、微妙なエッジ ケースが発生します。 たとえば、依存関係の小さなサイクルにより、3 を法とする矛盾した要件が強制され、局所的には各制約が実現可能に見えても、答えが不可能になる可能性があります。 

もう 1 つの失敗モードは、ライトごとの貪欲な固定です。 各ライトを修正するボタンの押し方を貪欲に個別に選択しようとすると、すぐに競合が発生します。これは、1 つのボタンが複数のライトに影響を与え、その効果が単純な 2 値の加算ではなく循環モジュロ 3 であるためです。 

## アプローチ

 重要な観察は、ボタンを押すたびに、変数 (ライト) のサブセットに適用される +1 モジュロ 3 の演算であるということです。 各ライトにはターゲット状態があります。最終値は 0 (赤) である必要があります。 各ライトは、R、G、B に対応する {0,1,2} の値で始まります。 

ライトが 1 つのボタンのみに接続されている場合、ライトの状態はそのボタンが押された回数によって完全に決まります。 2 つのボタンに接続されている場合、その最終値は、対応する 2 つの変数の合計によって決まります。 これは、3 を法とする線形方程式系を直ちに示唆します。 

ボタンごとに 1 つの変数を定義し、ボタンが押された回数を法 3 で表します。ボタンを 3 回押すことは何もしないことと同じであるため、Z3 ではすべての解決策を検討できます。 

各ライトについて、1 つのボタン a に接続されている場合、方程式 xa ≡ -c (mod 3) が得られます。ここで、c は初期カラー オフセットです。 2 つのボタン a と b に接続されている場合、xa + xb ≡ -c (mod 3) が得られます。 これにより、問題全体がモジュロ 3 変数にわたる制約のグラフに変換され、各ライトは単項制約または二項制約のいずれかに寄与します。 

各ライトは最大 2 つのボタンに関与するため、各制約には最大 2 つの変数が含まれます。 結果として得られる構造は、ノードがボタン、エッジがライト、そしてエッジがモジュロ 3 制約を持つグラフになります。 

ここで、割り当てられた値の合計を最小限に抑えながら、すべてのエッジ制約が満たされるように、{0,1,2} の値を各ノードに割り当てる必要があります (各プレスがコスト 1 に寄与し、0..2 で代表を選択できるため)。 

これは、連結成分に関するグラフ制約問題になります。 各コンポーネントは独立して解決できます。 各コンポーネントについて、任意のルート変数を選択し、それを基準にして他のすべての変数を表現します。 これにより、一貫性チェックが行われます。DFS または BFS 中に制約が伝播されます。 矛盾に遭遇すると、そのインスタンスは不可能になります。 

すべての変数をルート値 x で表現すると、すべてのノードは xi = x + di (mod 3) になります。 総コストは x の関数となり、コストを最小化するために x = 0、1、2 を試行します。

ブルートフォースの代替案では、ボタン押下に対するすべての割り当てが一定の限界まで試行されるため、ボタンやライトの数が指数関数的に複雑になります。 状態を総当たり的に列挙して各コンポーネントを解決しようとしても、最悪の場合 3^b になり、これは不可能です。 線形方程式への還元とコンポーネントごとの伝播により、状態空間が崩壊します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^b) | O(b + l) | 遅すぎる |
 | 最適 | O(l + b) | O(l + b) | 承認済み |

 ## アルゴリズムのチュートリアル

 ライトをボタン間の制約に変換します。 

まず、色を 3 を法とする剰余にマッピングします。ここで、赤は 0、緑は 1、青は 2 です。各ボタン変数は、押された回数を法 3 で表します。 

次に、ライトごとに制約を構築します。 ライトが 1 つのボタン a に接続されている場合、すぐに xa を必要な値に修正します。 2 つのボタン a と b に接続されている場合、エッジ制約 xa + xb ≡ target を保存します。 

3 番目に、ノードがボタン、エッジが 2 つのボタンを接続するライトからの制約であるグラフを構築します。 

4 番目に、DFS を使用して、このグラフの各接続コンポーネントを個別に処理します。 任意のノードを選択し、それに値 0 を割り当てます。エッジを通して伝播します。xa がわかっている場合、エッジ制約 xa + xb ≡ c に対して、xb ≡ c - xa (mod 3) を設定します。 xb がすでに割り当てられている場合は、整合性がチェックされます。 不一致がある場合は、システムに解決策がないことを意味します。 

第 5 に、伝播後、コンポーネント内の各ノードは、固定相対値 di と未知のグローバル シフト x を持ちます。 このシフトは、制約を破ることなくコンポーネント内のすべてのノードに同じ値を追加できる自由を表します。 

6 番目に、{0,1,2} 内の考えられる各シフト x のコストを計算します。 各ノードの最終値は (di + x) mod 3 で、コンポーネント内のすべてのノードを合計します。 私たちは最小限のものを選択します。 

これが機能する理由は、Z3 ではすべての制約が線形方程式に帰着するためです。 DFS は、すべての制約がローカルで満たされることを保証し、コンポーネントごとに残る唯一の自由度は 1 つの加法定数です。 Z3はサイズ3なのでシフトの徹底的なチェックが完了し、コストの最小化に最適です。

    data = list(map(int, input().split()))
    k = data[0]
    arr = [x - 1 for x in data[1:]]

        need = (-color[init[a]] ) % 3
        if fixed[a] != -1 and fixed[a] != need:
            print("impossible")
            sys.exit(0)
        fixed[a] = need
    else:
        a, b2 = arr
        c = (-color[init[a]]) % 3
        d = (-color[init[b2]]) % 3

        # constraint: xa + xb = something derived from both endpoints
        # we store as xa + xb = w
        w = (c + d) % 3

        adj[a].append((b2, w))
        adj[b2].append((a, w))

visited = [False] * b
val = [-1] * b

def dfs(u):
    visited[u] = True
    for v, w in adj[u]:
        if val[v] == -1:
            val[v] = (w - val[u]) % 3
            dfs(v)
        else:
            if (val[u] + val[v]) % 3 != w:
                print("impossible")
                sys.exit(0)

res = 0

for i in range(b):
    if val[i] == -1:
        val[i] = 0
        dfs(i)

        nodes = []
        stack = [i]
        while stack:
            x = stack.pop()
            nodes.append(x)
            for y, _ in adj[x]:
                if y not in nodes:
                    stack.append(y)

        best = 10**18
        for shift in range(3):
            cost = 0
            for x in nodes:
                cost += (val[x] + shift) % 3
            best = min(best, cost)
        res += best

微妙な点の 1 つは、各ボタンの値は 3 を法としてのみ意味があるということです。これより多くのボタンを押す回数を減らしても結果は変わりませんが、コストは増加するため、0..2 に制限するのが最適です。 

もう 1 つの重要な実装の詳細は、DFS 内の整合性チェックです。 Z3 を超える線形システムに矛盾が現れると、部分的な修復は存在しないため、モジュラー制約の違反は直ちに終了する必要があります。

 ## 特殊なケース

 エッジ ケースの 1 つは、ライトに接続されているボタンが 1 つだけある場合です。 その場合、ボタンの値は完全に固定されます。 たとえば、ライトが緑色でボタン 1 にのみ接続されている場合、ボタン 1 はモジュロ 3 で 1 回押す必要があります。アルゴリズムはこれを即座に設定することで処理します。`fixed[a]`、その後の矛盾は不可能を引き起こします。 DFS は固定制約を変更しないため、一貫性が維持されます。 

もう 1 つのエッジ ケースは、各コンポーネントに単項代入以外の制約がない、切断されたグラフです。 このような場合、各コンポーネントは事実上、固定値または自由値を持つ単一の変数になります。 DFS は基本値 0 を割り当て、シフト列挙により、コンポーネントごとの独立した最適化と一致する最小コストが {0,1,2} から正しく選択されます。 

最後のエッジケースは、コンポーネントに制約がまったくない場合です。 これは、そのコンポーネント内のどのボタンにもライトが接続されていない場合に発生します。 アルゴリズムは引き続きそれを値 0 の単一ノードとして扱い、シフトを評価しますが、ノードが存在しないか、孤立したノードのみであるため、寄与はゼロであり、プレスが必要ない、またはプレスが不必要にコストを増加させるだけであるという事実と一致します。
