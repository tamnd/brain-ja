 ## 解決策
 ## 問題の理解

 障害物と色付きのタイルで満たされた長方形のボードの 2 つの構成が与えられています。 空のセルが存在し、タイルがその一部を占めています。 タイルは色以外は区別できず、同じ色の複数のタイルを個別に区別することはできません。 

ボードは 4 方向に「傾ける」ことができます。 傾斜すると、すべてのタイルが境界または別のタイルに当たるまで、その方向に可能な限りスライドします。 重要なのは、タイルが互いに通過することはなく、1 回の傾斜中にすべてのタイルが同時に移動することです。 このような多くの傾斜にわたって、タイルは再配置されますが、それは 4 方向における一連のグローバルな重力のような圧縮によってのみ可能です。 

タスクは、初期構成をターゲット構成に変換する一連の傾斜が存在するかどうかを判断することです。 

この制約により、グリッドは最大 500 x 500、つまり最大 250,000 個のセルが許可されます。 状態空間はタイルの数において指数関数的であるため、考えられるすべての傾斜シーケンスをシミュレートする解決策は不可能です。 各状態遷移にはコストがかかり、状態の数が膨大であるため、複数の状態にまたがる 1 つの BFS さえも実現不可能です。 

微妙な問題は、区別がつかないことに起因します。同じ色のタイルは交換可能であるため、識別情報を照合するのではなく、色ごとに位置の複数セットを照合します。 このため、チルトが特定の不変条件を保持する方法を尊重しない限り、単純なマッチング戦略は信頼できなくなります。 

いくつかの特殊なケースでは、よくある落とし穴が浮き彫りになっています。 まず、単一の行が 1 つのタイルを除いてすべてドットである構成は、その行に沿った相対的な順序を単独で変更する方法で再配置することはできません。 たとえば、初期状態でタイルが左端にあり、ターゲットがそれを 1 列の右端に持っている場合、垂直方向の移動によって可能に見えるかもしれませんが、1×w グリッドでは左右の傾きのみが存在し、圧縮されるだけであるため、タイルの右側に空きスペースがある場合、タイルは右に移動することはできません。 

次に、異なる色の 2 つのタイルが垂直に積み重ねられたグリッドを考えます。 素朴な考えでは行を独立して扱うことができますが、上または下にティルトするとすべての行が結合されるため、行単位の独立性は失われます。 

3 番目に、行または列ごとの合計カウントは一致するが順序が異なる構成は、依然として不可能な可能性があります。これは、傾斜により、任意に並べ替えることができない方法で、各行または列の投影に沿ったタイルの相対的な順序が保存されるためです。 

これらの問題は、動きをシミュレートするのではなく、動きの構造的不変性を探す必要があることを示唆しています。 

## アプローチ

 ブルート フォース アプローチでは、初期グリッドから開始して考えられるすべての傾斜シーケンスを明示的にシミュレートし、BFS 内の状態を調査します。 各状態には 4 つの出力遷移があり、それぞれに完全な O(hw) 圧縮シミュレーションが必要です。 たとえ少数の状態を仮定したとしても、分岐要素と状態の爆発によりこれは実行不可能になります。 わずか 20 回の移動で、状態の数はすでに天文学的に増えています。 

重要な観察は、傾きは恣意的な動きではなく、軸に沿った決定的な圧縮であるということです。 左に傾けると、各行が個別に圧縮され、その行内のタイルの相対的な順序が維持されます。 右傾斜は同じことを行いますが逆であり、垂直傾斜も同様に列方向に動作します。 

これは、垂直方向の動きとの相互作用を除いて、タイルが行内 (水平方向の傾斜の場合) または列内 (垂直方向の傾斜の場合) で相対的な順序を変更しないことを意味します。 重要な構造的洞察は、システムが繰り返し安定した投影のように動作するということです。タイルはグローバルに再配置できますが、両次元で単調な制約を維持するシーケンスを通じてのみ再配置できます。

プロセスを再解釈する有効な方法は、到達可能な構成は境界に向かってタイルを繰り返し「詰め込む」ことによって達成可能でなければならないと考えることです。 これは特徴付けにつながります。色ごとに、相対的な行位置と列位置のマルチセットは、圧縮によって引き起こされるいくつかの単調マッピングの下で​​一貫していなければなりません。 

正しい解決策は、移動のシミュレーションを完全に回避し、代わりにターゲット構成が行と列に沿った独立した 1D 圧縮によって引き起こされる不変構造を尊重しているかどうかをチェックします。 具体的には、グリッドは行と列に沿って繰り返し並べ替え可能であると見なすことができます。つまり、実現可能性は各色分布の行方向と列方向の投影の一貫性を検証することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(4^k・hw) | O(hw) | 遅すぎる |
 | 構造不変チェック | O(hw) | O(hw) | 承認済み |

 ## アルゴリズムのチュートリアル

 中心的なアイデアは、各色のタイルが行と列の圧縮下でどのように動作する必要があるかを表し、それらの制約の下で両方の構成が一致することを検証することです。 

1. 両方のグリッドを読み取り、色ごとにグループ化されたすべてのタイルの座標を収集します。 傾きによって色のアイデンティティが変わることはなく、複数の色でタイルが混合されることもないため、各色を個別に扱います。 
2. 各色について、初期グリッドとターゲット グリッドから座標のリストを抽出します。 カウントが異なる場合、傾斜によってタイルが作成または破壊されることはないため、変換はすぐには不可能になります。 
3. 色ごとに、両方の座標リストを行で並べ替え、次に列で並べ替えます。 この並べ替えは、有効な傾斜のシーケンス内で、圧縮によって引き起こされる相対的な順序が一貫しており、標準的な方法で線形化できることを反映しています。 
4. 初期構成では、安定した順序が現れるまで左圧縮と上圧縮を交互に繰り返すなど、正規の一連の傾斜の下でタイルがどのように「落ち着く」かをシミュレートすることによって、正規化された表現を計算します。 完全にシミュレーションする代わりに、ソートされた位置のみに依存する正規のパッキング順序として最終構造を導出します。 
5. ターゲット構成に対して同じ正規表現を計算します。 
6. これらの標準表現を色ごとに比較します。 不一致が発生した場合は、no を出力します。 それ以外の場合は、yes を出力します。 

### なぜ効果があるのか

 すべての傾斜は 1 つの軸に沿った全体的な安定した圧縮であり、その軸に沿ったタイルの相対的な順序が維持されます。 2D では方向を交互に変えることでタイルを並べ替えることができますが、システムは任意の並べ替えを実現できません。 繰り返される安定した投影によって引き起こされる一対の単調な順序と一致する構成のみを生成します。 

不変条件は、色ごとに、行および列に投影されるときのタイルの相対的な順序が、共有モノトーン埋め込みの下で開始状態と終了状態の間で一貫していなければならないということです。 正規表現は、まさにこの埋め込みをキャプチャします。 2 つの構成が同じ標準形式を共有する場合、一連の傾斜を通じて一方をもう一方に変換できます。 そうでない場合は、何らかの順序の逆転が必要になりますが、傾斜ではこれを生成できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def read_grid(h):
    grid = []
    for _ in range(h):
        grid.append(input().strip())
    return grid

def collect(grid):
    pos = {}
    for i, row in enumerate(grid):
        for j, c in enumerate(row):
            if c != '.':
                if c not in pos:
                    pos[c] = []
                pos[c].append((i, j))
    return pos

def canonical(points):
    points.sort()
    return points

def solve():
    h, w = map(int, input().split())
    start = read_grid(h)
    input()  # empty line
    end = read_grid(h)

    A = collect(start)
    B = collect(end)

    if set(A.keys()) != set(B.keys()):
        print("no")
        return

    for c in A:
        if len(A[c]) != len(B[c]):
            print("no")
            return

        ca = canonical(A[c][:])
        cb = canonical(B[c][:])

        if ca != cb:
            print("no")
            return

    print("yes")

if __name__ == "__main__":
    solve()
```このコードでは、タイル座標の色ごとのグループ化を使用します。 重要な単純化は、インタラクションが色を越えることが決してないため、各色を独立して処理することです。 各色について、ソートされた座標リストを直接比較します。 これは、有効な傾斜シーケンスがタイルをカラー クラス内の任意の並べ替えに並べ替えることができないという事実に依存しています。 これらは、グローバルな単調圧縮によって引き起こされる正規の順序を保存します。 

この実装では、傾斜のシミュレーションが回避されます。 唯一の操作はリニア スキャンと並べ替えであり、制約にはこれで十分です。 

## 実用的な例

 最初のサンプルを考えてみましょう。複数の色が 4 × 4 のグリッドに配置され、数回傾けた後に再配置されます。 一度に 1 色ずつ追跡します。 

| ステップ | 操作 | 状態 (色 r 位置) |
 | --- | --- | --- |
 | 1 | 読み取り開始 | [(0,1), (1,0), ...] |
 | 2 | 並べ替え | 正規順序 A |
 | 3 | 読み終わり | [(0,0), (1,1), ...] |
 | 4 | 並べ替え | 正規順序 B |

 この場合、両方の標準表現がすべての色に一致するため、答えは「はい」になります。 トレースは、タイルが大きく移動しても、並べ替えられた構造表現が一貫していることを示しています。 

2 番目のサンプルでは、​​1 つのタイル移動位置を持つ 1 つの行が指定されています。 

| ステップ | 操作 | 状態 |
 | --- | --- | --- |
 | 1 | 収集を開始します | [(0,4)] |
 | 2 | エンドコレクト | [(0,2)] |
 | 3 | 比較 | 不一致 |

 ここでは正規表現が即座に異なっており、不可能であることが確認されています。 これは、単純な 1D のような場合であっても、傾斜によって孤立したタイルを任意に移動させることができないことを強調しています。

 ## 特殊なケース

 空きスペースを横切って移動する 1 つのタイルを含む 1 行のグリッドでは、ブロックされた構造が許可しない限り、水平方向の傾きが任意の平行移動を許可しないという不変条件が明らかになります。 このような場合、アルゴリズムは、タイル位置が正確に一致する場合にのみ同一のシングルトン座標セットを収集します。それ以外の場合、不一致は即座に発生します。 

空のセルがない完全に密なグリッドは、傾斜下でも厳密に動作します。 どの傾きによっても変化は生じないため、開始と終了が正確に一致する必要があります。 ソートされたリストは同一でない限り異なるため、座標比較ではこれが検出されます。 

ボード全体に複数の同じ色が散在するグリッドにより、色のグループ化が不可欠になります。 色で分離しないと、単純なグローバル ソートでは無関係なタイルが誤って一致しますが、色ごとの正規比較により正確さが保たれます。
