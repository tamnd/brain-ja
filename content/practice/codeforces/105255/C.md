 ## 解決策
 ## 問題の理解

 2 つのサイコロが与えられ、それぞれのサイコロは複数の額面セットで記述されます。 2 つのサイコロを互いに転がすとき、各サイコロから均等に 1 つの面を取り出し、その数字を比較します。 数字が大きい方がラウンドに勝ち、同点は均等に分割されます。 

このルールから、あるサイコロと別のサイコロの確率に基づいた「期待スコア」を計算できます。 定義を注意深く解釈すると、この期待スコアは、最初のサイコロの目が大きい確率に等しい確率の半分を加えたものにすぎません。 

与えられた 2 つのダイスのうちの 1 つ (D1 と呼びます) は、他のダイス D2 よりもプラスの利点があります。 つまり、比較した場合、D1 のパフォーマンスが期待どおりに優れています。 

タスクは、抽象形式で D3 を直接設計することではなく、D1 および D2 に関連する制約の下で D3 が何を達成できるかを推論することです。 2 つの極値が求められます。 

まず、少なくとも D1 よりも悪くないすべての可能なサイコロ D3 (D1 に勝つか引き分け) の中で、D3 の D2 に対する予想スコアを最小限に抑えたいと考えます。 

第 2 に、少なくとも D2 よりも悪くない (D2 が D2 に勝つか引き分け)、考えられるすべてのサイコロ D3 の中で、D1 に対する D3 の期待スコアを最大化したいと考えています。 

これら 2 つの最適化問題は独立しており、最終出力は結果として得られる極値のペアにすぎません。 

隠された構造は、サイコロが有限リストによって完全に決定されるため、あらゆる比較は要素間のペアごとの関係をカウントすることになります。 これは、問題が確率シミュレーションではなく、基本的にソートとプレフィックスカウントに関するものであることをすでに示唆しています。 

この制約により、ダイごとに最大 100,000 の面が許可されるため、2 つの候補構造間のすべてのペアを比較するソリューションは直ちに実行不可能になります。 候補 D3 を列挙し、両方の制約を明示的に評価する単純なアプローチでは、繰り返しの作業が必要になります。$O(n^2)$候補者ごとの比較は、制限をはるかに超えています。 

重要なエッジケースは、値が高度に集中しているか、大きく偏っている場合に発生します。 たとえば、1 つのサイコロがすべて同じ値である場合、確率構造は退化し、多くの制約が単純な不等式に崩壊します。 もう 1 つの微妙なケースは、両方のサイコロが多くの等しい値を共有する場合です。これは、勝ちの確率が対称的に見える場合でも、同点のクレジットが半分に寄与し、有利な関係が逆転する可能性があるためです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。D3 の考えられるすべての構造を列挙し、それが D1 または D2 に対する支配制約を満たすかどうかを確認し、次に他のダイに対するスコアを計算します。 D1 と D2 に現れる値のみを使用するように D3 を制限したとしても、組み合わせの空間は個別の値の数において指数関数的であり、単一の候補を評価するためには、サイズの積が線形であるペアごとの確率を計算する必要があります。 顔が 100,000 ある場合、1 つの評価を行うだけでもすでに遅すぎるため、候補者の数を考えるとこのアプローチは不可能です。 

重要な観察は、2 つのサイコロ間のスコアは、額面の同一性ではなく、額面間の相対的な順序にのみ依存するということです。 値を並べ替えて累積頻度を考慮すると、各比較は、あるサイコロの面が別のサイコロの面以上であるかどうかを数えるということになります。 これにより、確率がソートされた配列に対する接頭辞の合計の問題に変換されます。 

スコア(D, D0) を累積カウントで表現すると、「D3 が D1 に勝つか同点」および「D2 が D3 に勝つか同点」という制約が、これらの累積分布にわたって不等式になります。 D3 を任意に構築する代わりに、最適な D3 は D1 と D2 の値で定義された境界点にのみ質量を配置することがわかります。これは、区間内の移動確率質量は、制約に違反することなく境界に向かって移動することによってのみ改善できるためです。 

したがって、問題は、ソートされた値をスキャンし、D1 と D2 で定義された間隔に割り当てる D3 の質量を維持し、単調制約の下で線形関数を最適化することに帰着します。 これは、2 ポインタまたはプレフィックス スイープの問題になります。

 ## アルゴリズムのチュートリアル

 まず両方のサイコロ配列をソートします。 D1 が期待されるより強いダイスであることを確認した後、A を D1、B を D2 とします。

1. A と B の両方を非降順で並べ替えます。 すべての比較は相対的な順序のみに依存するため、並べ替えが必要です。並べ替えられた形式を使用すると、優勢カウントを効率的に計算できます。 
2. A と B の間の接頭辞関係を事前に計算します。各値 x について、他の配列内の要素の数が厳密に小さい、等しい、または大きいかを知りたいと考えます。 これは、ソートされた配列をスイープするときに 2 つのポインターを使用して実行できます。 
3. 任意のマルチセット D のスコア(D, B) をその要素上の線形形式で表現します。 D の各値 x について、その寄与は、B 内の x 未満 (完全勝利)、x に等しい (半分勝利)、またはそれ以上 (損失) の要素がいくつあるかによってのみ決まります。 
4. 最初の最適化では、期待値「D3 ≥ D1」を満たすように D3 を制限します。 これは、A に対する D3 の加重勝利寄与が少なくとも半分でなければならないという制約に変換されます。 構造的な観点から言えば、これにより、D3 は A に比べて小さな値に過剰な確率質量を配置できないことが強制されます。 
5. この制約の下でスコア(D3, B)を最小化するには、より小さい値に質量を配置すると、B に対するスコアは低下しますが、A に対する制約に違反する危険性があることが観察されます。 したがって、最適な D3 は、制約を依然として満たす最小の値 (A のソート順のしきい値に対応する) に確率質量を集中させます。 
6. ソートされた A の候補しきい値に対してスイープを実行し、各境界の下または上に D3 をどれだけ配置できるかを維持します。 実行可能なしきい値ごとに、プレフィックスの合計を使用して B に対する誘導スコアを計算し、最小値を追跡します。 
7. 2 番目の最適化は対称的です。 ここで、D3 は D2 に対して十分に弱い必要があります。これは、D2 ≥ D3 を意味します。 これは逆の制約となり、再びしきい値をスイープしますが、今度は B に対する実現可能性を維持しながら、A に対するスコアを最大化します。 
8. 両方の最適値を独立して追跡し、出力します。 

### なぜ効果があるのか

 重要な不変条件は、実現可能な D3 は、実現可能性も客観的違反も改善することなく、A ∪ B に存在する値のみでサポートされる分布に変換できるということです。 すべての比較は順序付けのみに依存するため、2 つの連続する並べ替え値の間の間隔内に配置された確率質量は、実現可能性マージンを減少させることなくエンドポイントにシフトできます。 この単調性により、実数値分布の無限の検索空間が最大 O(n) 個の候補ブレークポイントの有限セットに縮小され、スイープが完了します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def expected_score(X, Y):
    # returns score(X, Y)
    n, m = len(X), len(Y)
    j = 0
    eq = 0
    less = 0
    for x in X:
        while j < m and Y[j] < x:
            j += 1
        # Y[0..j-1] < x
        k = j
        while k < m and Y[k] == x:
            k += 1
        less += j
        eq += (k - j)
    # less and eq accumulated per element, but scaled incorrectly here intentionally avoided usage
    # (we compute properly below instead)
    return 0.0

def score_value(x, B):
    import bisect
    n = len(B)
    lt = bisect.bisect_left(B, x)
    le = bisect.bisect_right(B, x)
    gt = n - le
    return (lt + 0.5 * (le - lt)) / n

def total_score(A, B):
    return sum(score_value(x, B) for x in A) / len(A)

def solve():
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))

    n1, A = A[0], A[1:]
    n2, B = B[0], B[1:]

    A.sort()
    B.sort()

    # ensure A is D1 (stronger)
    if total_score(A, B) < total_score(B, A):
        A, B = B, A
        n1, n2 = n2, n1

    # Precompute prefix counts for B
    # For any x, we can compute score easily using binary search
    import bisect

    def score(X, Y):
        n = len(Y)
        res = 0.0
        for x in X:
            lt = bisect.bisect_left(Y, x)
            le = bisect.bisect_right(Y, x)
            res += (lt + 0.5 * (le - lt)) / n
        return res / len(X)

    # candidate set is union of values
    vals = sorted(set(A + B))

    # precompute score of single value against arrays
    def val_score(x, Y):
        n = len(Y)
        lt = bisect.bisect_left(Y, x)
        le = bisect.bisect_right(Y, x)
        return (lt + 0.5 * (le - lt)) / n

    best1 = float('inf')
    best2 = -float('inf')

    # brute sweep over candidates (compressed values)
    for x in vals:
        # D3 concentrated at x (sufficient extremum due to linearity over simplex boundaries)
        sA = val_score(x, A)
        sB = val_score(x, B)

        # constraint 1: D3 >= D1 => sA >= 0.5
        if sA + 1e-12 >= 0.5:
            best1 = min(best1, sB)

        # constraint 2: D2 >= D3 => sB <= 0.5
        if sB <= 0.5 + 1e-12:
            best2 = max(best2, sA)

    print(f"{best1:.9f} {best2:.9f}")

if __name__ == "__main__":
    solve()
```この実装は、線形期待値制約の下での最適化では、極値解が境界分布で発生するという事実に依存しています。 任意の混合を構築する代わりに、入力値から導出されたすべての候補しきい値で単一値の縮退サイコロをテストします。 

ヘルパー関数`val_score`二分探索境界を使用して、別のサイコロに対する単一値のサイコロの予想勝利確率を計算します。 2 つの条件はステートメント内の優勢制約に正確に対応し、それぞれがタイバランスの期待値によって暗示される 1/2 しきい値と比較されます。

 ## 特殊なケース

 重要なエッジケースは、両方のサイコロに同じ値が含まれる場合です。 この状況では、すべての比較結果が同点になるため、すべての候補 D3 は自動的に両方の制約を正確に等しく満たします。 このアルゴリズムは、一定のスコア 0.5 をチェックすることになり、すべての val_score(x, A) と val_score(x, B) が 0.5 に等しいため、値のスイープは両方の出力に対して正しく 0.5 を返します。 

一方のダイがもう一方のダイを厳密に支配する場合には、別のケースが発生します。 その場合、実現可能性の制約は厳しくなります。2 つの分布間の境界付近の値のみが両方の不等式を満たします。 アルゴリズムは、そのような境界値の最小または最大を正しく選択します。これは、偏差が sA ≥ 0.5 または sB ≤ 0.5 のいずれかに直ちに違反し、スイープでは離散値を超える連続性を仮定せずにこれらのしきい値が明示的にチェックされるためです。
