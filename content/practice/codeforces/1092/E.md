 ## 解決策
 ## 問題の理解

 すでにフォレストになっているグラフが与えられています。これは、複数の切り離されたツリーで構成されていることを意味します。 タスクは、これらすべてのツリーを 1 つのツリーに接続するのに十分なエッジを正確に追加することです。 木の上にあるので`n`頂点は正確に持っています`n - 1`エッジ、および入力にはすでに含まれています`m`エッジを追加する必要があります`n - 1 - m`エッジ。これは接続されたコンポーネントの数より正確に 1 つ減ります。 

これらのエッジを追加した後、コンポーネントを接続する方法を自由に選択できますが、結果として得られる構造はツリーのままでなければなりません。 コンポーネントを接続するすべての可能な方法の中で、最終的なツリーの直径を最小化する方法が必要です。直径とは、頂点のペア間の最大最短パス距離です。 

コンポーネントは任意に接続できるため、入力グラフの構造は、接続されたコンポーネントと各コンポーネントの内部構造を通じてのみ重要になります。 

制約`n ≤ 1000`これは、コンポーネントごとに 2 次または 2 次に近い前処理であっても受け入れられることを意味します。 すべてのコンポーネントにわたる合計作業量は約`O(n^2)`最悪の場合。 

素朴だが間違った直感は、コンポーネントを任意に接続したり、チェーンで接続したりすることです。 直径が順序の影響を受けやすいため、これは失敗します。 

たとえば、次の 3 つのコンポーネントがあるとします。 

コンポーネント A は長さ 10 の長いパス、コンポーネント B は単一エッジ、コンポーネント C は別の単一エッジです。 A-B-C のチェーンで接続すると、両方のアタッチメントを通る直径が必要以上に大きくなります。 より良い戦略は、コンポーネント間の距離を制限する方法で最大の「中心」を配置することです。 

もう 1 つの微妙な失敗例は、ツリーの中心ではなく端点を選択することです。 中心ノードの代わりにリーフを接続すると、たとえ全体的な構造が最適であっても、コンポーネント内の距離によって最終的な直径が膨張します。 

中心的な問題は、各コンポーネントが半径のある「ボール」のように動作することであり、これらのボールをどのように接着するかを決定しているところです。 

## アプローチ

 ブルートフォース ソリューションでは、コンポーネントをツリーに接続するあらゆる方法が試行され、そのたびに結果の直径が計算されます。 あれば`k`コンポーネント、あります`k^(k-2)`Cayley の公式によるラベル付きツリーの可能性があり、コンポーネント間のエッジの選択に制限しても依然として指数関数的な構成が残ります。 構成ごとに直径コストを計算`O(n)`または`O(n^2)`方法によっては、小規模であってもこれは完全に不可能になります`n`。 

重要な観察は、各コンポーネントが 2 つの値 (直径と中心) によって要約できることです。 直径は最悪の内部距離を示し、中心はコンポーネント内のすべてのノードまでの最大距離を最小化します。 コンポーネントを接続する場合、コンポーネントを横切るパスは選択した接続ポイントを通過する必要があるため、コンポーネントを表す唯一の有用な表現は、選択した接続ポイントから最も遠いノードがどのくらい離れているかということです。 

各コンポーネントの中心を選択し、すべての中心をスター型で接続すると、すべてのコンポーネント間のパスが単一のハブを通過します。 次に、2 つのコンポーネント間のパスは、それらの半径とそれらの間の 1 つのエッジの合計によって制御されます。 これにより、問題全体が最適なハブ コンポーネントの選択に集約されます。 

最適なハブは、半径が最大のコンポーネントです。 これにより、他のすべてのコンポーネントが最大のコンポーネントに接続されるため、最悪のコンポーネント間パスが最小限に抑えられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 最適 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DFS または BFS を使用して、グラフを連結コンポーネントに分割します。 最初はコンポーネント間にエッジが存在しないため、各コンポーネントは独立して処理されます。 
2. コンポーネントごとに、任意のノードを選択し、BFS を実行して最も遠いノードを見つけます。`a`。 このノードは直径候補の 1 つの端点です。 
3. から BFS を再度実行します。`a`最も遠いノードを見つけるには`b`。 間の距離`a`そして`b`はこのコンポーネントの直径です。 これが機能するのは、任意の開始点から最も遠いノードが常にツリー内のある直径の終点であるためです。 
4.BFS を実行します。`a`もう一度、そしてから`b`もう一度すべてのノードまでの距離を計算します。 ノードごとに計算します`max(dist_a[x], dist_b[x])`。 この値を最小にするノードがコンポーネントの中心になります。 このノードは、他のすべてのノードとの最大距離を最小限に抑えます。 
5. 各コンポーネントの直径と中心を保存します。 
6. 最大半径を持つコンポーネントを特定します (実際には直径の半分が切り上げられますが、計算された最大距離を直接使用します)。 このコンポーネントがハブになります。 
7. 他のすべてのコンポーネントについては、追加したエッジを使用してその中心をハブの中心に接続します。 これらのエッジは、すべてのコンポーネントを単一のツリーに接続するのに十分です。 
8. 最終的な直径を 2 つの値の最大値として計算します。元のコンポーネントの最大直径と、コンポーネントのすべてのペアの最大値です。`radius[i] + 1 + radius[j]`、最大の半径と 2 番目に大きい半径をペアにすることで最大化されます。 

### なぜ効果があるのか

 各コンポーネントはその中心に根を張る木のように動作し、コンポーネントに出入りするパスは構造内でその中心を通過する必要があります。 これにより、各コンポーネントが、その半径に等しい重みを持つ重み付けされたノードに縮小されます。 したがって、コンポーネントを横切るパスの直径は、2 つの半径と 1 つの接続エッジによって決まります。 ハブとして最大の半径を選択すると、他のすべてのコンポーネントが複数の半径を連鎖して蓄積するのではなく単一の点を介して接続されるため、異なるコンポーネントにわたる 2 つの半径の最悪の合計が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

n, m = map(int, input().split())
g = [[] for _ in range(n)]

for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

vis = [False] * n
comp = []

def bfs(start):
    dist = [-1] * n
    q = deque([start])
    dist[start] = 0
    order = []
    while q:
        x = q.popleft()
        order.append(x)
        for y in g[x]:
            if dist[y] == -1:
                dist[y] = dist[x] + 1
                q.append(y)
    return dist, order

def find_center(nodes):
    start = nodes[0]
    dist1, _ = bfs(start)
    a = max(nodes, key=lambda x: dist1[x])

    dista, _ = bfs(a)
    b = max(nodes, key=lambda x: dista[x])

    distb, _ = bfs(b)

    best = None
    best_val = 10**9
    for x in nodes:
        val = max(dista[x], distb[x])
        if val < best_val:
            best_val = val
            best = x

    diameter = dista[b]
    radius = best_val
    return a, b, best, diameter, radius

components = []

for i in range(n):
    if not vis[i]:
        stack = [i]
        vis[i] = True
        nodes = []
        while stack:
            x = stack.pop()
            nodes.append(x)
            for y in g[x]:
                if not vis[y]:
                    vis[y] = True
                    stack.append(y)

        a, b, c, diam, rad = find_center(nodes)
        components.append((rad, c, diam))

if len(components) == 1:
    rad, c, diam = components[0]
    print(diam)
    sys.exit()

components.sort(reverse=True)
hub_rad, hub_center, hub_diam = components[0]

edges = []

for i in range(1, len(components)):
    edges.append((hub_center, components[i][1]))

ans = hub_diam
if len(components) > 1:
    ans = max(ans, components[0][0] + components[1][0] + 1)

print(ans)
for u, v in edges:
    print(u + 1, v + 1)
```コードはまず、DFS を使用してフォレストをコンポーネントに分解します。 各コンポーネントに対して、BFS ベースの直径抽出を実行し、2 つの直径の端点までの最大距離を最小化することで中心を計算します。 各コンポーネントが中心、半径、直径に要約されると、アルゴリズムは最大半径を持つコンポーネントをハブとして選択します。 

他のすべてのコンポーネントはこのハブ中心に直接接続され、星型構造を形成します。 最終的な直径の計算は、コンポーネント間パス解析から導出された理論上の限界と一致します。 

微妙な実装の詳細は、直径エンドポイントからの BFS 結果を再利用して中心候補を計算することです。 これにより、不必要な再計算が回避され、解が範囲内に保たれます。`O(n^2)`。

| コンポーネント | 直径 | センター | 半径 |

 どちらかを選択します`{1,2}`または`{3,4}`ハブとして。 仮定する`{1,2}`ハブです、私たちは接続します`1-3`そして`1-5`。 

最終的な直径は`max(1, 1 + 1 + 1) = 3`。 

これらの例は、複数のコンポーネントの半径がゼロ以外になった場合に、コンポーネント間のパスがどのように支配的になるかを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from collections import deque

    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    vis = [False] * n

    def bfs(start):
        dist = [-1] * n
        q = deque([start])
        dist[start] = 0
        while q:
            x = q.popleft()
            for y in g[x]:
                if dist[y] == -1:
                    dist[y] = dist[x] + 1
                    q.append(y)
        return dist

    def comp_nodes(i):
        stack = [i]
        vis[i] = True
        nodes = []
        while stack:
            x = stack.pop()
            nodes.append(x)
            for y in g[x]:
                if not vis[y]:
                    vis[y] = True
                    stack.append(y)
        return nodes

    def center(nodes):
        dist1 = bfs(nodes[0])
        a = max(nodes, key=lambda x: dist1[x])
        dista = bfs(a)
        b = max(nodes, key=lambda x: dista[x])
        distb = bfs(b)
        best = min(nodes, key=lambda x: max(dista[x], distb[x]))
        return best

    comps = []
    for i in range(n):
        if not vis[i]:
            nodes = comp_nodes(i)
            comps.append(nodes)

    return str(len(comps))

 ## 特殊なケース

 単一コンポーネントの入力はすでにツリーを形成しているため、エッジは追加されず、答えはその直径だけです。 コンポーネントが 1 つしか存在しない場合、アルゴリズムはコンポーネント接続段階に入らないため、このアルゴリズムは自然にこれを処理します。 

完全に切断されたノードは、それぞれ半径 0 のサイズ 1 のコンポーネントを形成します。 アルゴリズムはそれらすべてを選択したハブ ノードに接続し、スターを生成します。 直径は最大 2 になります。これは、孤立したノード上のツリーは少なくとも 2 の直径を持つ必要があるため、最適です。`n ≤ 2`。 

多くの小さなコンポーネントと組み合わされた長いパスにより、ハブの選択が正しいかどうかがテストされます。 このアルゴリズムにより、半径が最も長いコンポーネントの中心が確実にハブになり、小さなコンポーネントが接続ポイントとして使用されて直径が大きくなるのを防ぎます。
