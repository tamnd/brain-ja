 ## 解決策
 ## 問題の理解

 文字列が固定長になるように、クエリごとに文字列を構築するように求められます。`n`最初のものだけを使用します`k`小文字のラテン文字、から`'a'`まで`k`- 番目の手紙。 これらのどれも`k`文字は最終文字列に少なくとも 1 回出現する必要があります。 すべての有効な構造の中で、文字列内で使用される文字の最小頻度を最大化したいと考えています。 

つまり、配布しているのは、`n`間の位置`k`明確なシンボル。 各シンボルは少なくとも 1 回は出現する必要があり、最小のバケットができるだけ大きくなるように、可能な限り最もバランスのとれた分散が必要です。 

制約は小さいです。`n ≤ 100`、`k ≤ 26`、そして最大`t ≤ 100`クエリ。 これにより、高度なデータ構造や最適化技術の必要性が即座に排除されます。 クエリごとに線形時間または二次時間で実行されるソリューションであれば、十分に十分です。 この構造は、検索や動的プログラミングではなく、建設的な解決策を提案します。 

重要な微妙な点は、「最小周波数の最大化」が何を意味するのかを理解することです。 カウントを割り当てると`c1, c2, ..., ck`を最大化しています。`min(ci)`すべての制約の下で`ci ≥ 1`そして合計すると`n`。 これは純粋なバランスの問題です。 

エッジケースは次の場合に発生します。`n`よりわずかに大きいだけです`k`。 たとえば、次の場合`n = k`の場合、すでにすべての文字が必要であり、余分なスペースがないため、すべての文字が 1 回だけ出現する必要があります。 「さらにバランスをとろう」という試みは不可能です。 

もう 1 つのエッジケースは次のような場合です`n`よりもはるかに大きいです`k`。 常に次の文字を周期的に追加する素朴な貪欲なアプローチは機能しますが、周波数バランスについての推論がなければ、より複雑な再配置が必要であると誤って仮定する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、`n`間の位置`k`各文字が少なくとも 1 回出現するように、あらゆる方法で文字を表示します。 分布ごとに最小頻度を計算し、最適な頻度を追跡します。 このようなディストリビューションの数は、次のパーティションに相当します。`n`の中へ`k`正の整数。次のように指数関数的に増加します。`n`。 たとえ`n = 100`、これは完全に不可能になります。 

目的関数の構造により、問題ははるかに単純になります。 最小カウントを最大化することのみを考慮するため、可能な限り最善の解決策は、すべての周波数を可能な限り均等化しようとします。 すべての文字が正確に一致していれば`n / k`それが理想的ですが、整数の除算では完全な等価性は得られません。 したがって、最適な最小周波数は、サイズの完全なブロックがいくつあるかによって決まります。`k`に適合する`n`。 

目標を均等な配分として解釈すると、構築は簡単になります。 最初の文字列全体にわたってラウンドロビン方式で繰り返し文字を割り当てます。`k`文字。 これにより、すべてのプレフィックスが保証されます。`k`文字は完全にバランスが取れており、残りは最初から再分配され、可能な限り最良の最小頻度が維持されます。

 ## アルゴリズムのチュートリアル

 クエリごとに個別に文字列を構築します。 

1. 空の結果文字列を初期化します。 
2. から反復処理`0`に`n - 1`。 
3. ポジションごとに`i`に対応する文字を追加します。`(i mod k)`。 

これにより、最初の項目を循環的に実行できるようになります。`k`何度も手紙。 
4. ループが終了したら、構築された文字列を出力します。 

ステップ 3 の背後にある理由は、サイクリングによって均一な使用が保証されるということです。 すべてのブロック`k`連続した位置には、許可された各文字が 1 つだけ含まれます。 これにより、どのキャラクターも他のキャラクターと比べて頻度が遅れることがなくなります。 

### なぜ効果があるのか

 長さの各完全なサイクル`k`すべての文字が 1 回出現するだけです`'a'`に`'a' + k - 1`。 後`⌊n / k⌋`全サイクルでは、すべての文字が同じ基本周波数を持ちます。 残っているもの`n mod k`位置は最初の数文字に割り当てられ、頻度が最大で 1 ずつ増加します。 これにより、任意の 2 つの文字頻度の差が最大でも 1 であることが保証され、これが可能な限り最良のバランスとなります。 したがって、最小周波数は最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    
    res = []
    for i in range(n):
        res.append(chr(ord('a') + (i % k)))
    
    print("".join(res))
```実装は循環構築の直後に行われます。 リスト`res`効率性を高めるために文字列連結の代わりに使用されますが、制約が与えられているため、どちらでも合格します。 

重要な詳細はモジュロ演算です`(i % k)`これにより、常に許可されたアルファベットの範囲内に収まることが保証されます。 マッピング`chr(ord('a') + x)`整数のオフセットを小文字に変換します。 

次のようなエッジケースには特別な処理は必要ありません。`n = k`または`k = 1`これは、同じループが両方のシナリオで有効な出力を自然に生成するためです。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        res = []
        for i in range(n):
            res.append(chr(ord('a') + (i % k)))
        out.append("".join(res))
    return "\n".join(out)

def run(inp: str) -> str:
    return solve(inp)

# provided samples
assert run("3\n7 3\n4 4\n6 2\n") == "abcabca\nabcd\nababab"

# custom cases
assert run("1\n1 1\n") == "a", "single character"
assert run("1\n5 1\n") == "aaaaa", "single letter repeated"
assert run("1\n5 5\n") == "abcde", "each letter once"
assert run("1\n10 3\n") == "abcabcabca", "repeating cycle"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1 | | 最小のケース |
 | 5 1 | ああああ | 単一文字の繰り返し |
 | 5 5 | ABCDE | 正確な分布境界 |
 | 10 3 | アブカブカ | 複数のブロックにわたる循環バランシング |

 ## 特殊なケース

 いつ`n = k`の場合、ループは各文字を 1 回だけ生成します。`(i % k)`からのすべての値をカバーします`0`に`k - 1`ちょうど1回。 例えば、`n = 4, k = 4`生成する`abcd`, which already satisfies the requirement that each letter appears at least once and no balancing is possible beyond that.

 いつ`k = 1`、すべての位置は次のようにマッピングされます。`'a'`。 モジュロ演算は常にゼロであるため、出力は次の文字列になります。`n` `'a'`文字。 許可される文字は 1 つだけなので、これが最適です。 

いつ`n`で割り切れない`k`、残りの文字は、最初の数文字の頻度を単純に増加させます。 例えば、`n = 7, k = 3`生成する`a, b, c, a, b, c, a`、最大 1 だけ異なるカウントが得られます。 これにより、再配分によって少なくとも 1 人のキャラクターがこの下限を下回ることが強制されるため、これ以上の最小頻度は達成できないことが確認されています。
