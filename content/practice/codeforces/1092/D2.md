 ## 解決策
 ## 問題の理解

 壁セグメントのラインが与えられ、各セグメントは整数の高さで始まります。 唯一許可されるアクションは、現在まったく同じ高さを持つ 2 つの隣接するセグメントを選択し、両方のセグメントを 1 つ増やすことです。 この操作は、選択したペアの同等性を維持しますが、他のセグメントには直接影響しません。 

目標は、このような一連の操作の後で、すべてのセグメントが同じ高さを持ち、ギャップや不一致が残らない状態に配列全体を到達させることができるかどうかを判断することです。 

重要な点は、操作が非常にローカルであるということです。 単一の位置を直接調整したり、不均等な隣接位置を操作したりすることはできません。 いかなる進歩も、完全に隣接する同等のペアの存在と進化に依存します。 

この制約では最大 200,000 セグメントが許可されるため、操作を段階的にシミュレートするソリューションは不可能です。 1 回の操作でも 2 つの位置にのみ影響し、最悪の場合、最終的な高さに応じて可能な操作の数は増加し、最終的な高さは任意に大きくすることができます。 これにより、明示的に「壁を築く」ことを試みたり、増分をシミュレートしたりするアプローチは即座に排除されます。 

本当の課題は、到達可能性について推論することです。つまり、高さを分散する唯一のメカニズムがすでに等しい隣接するペアを介するものであるとして、配列全体にわたる平等を達成できるかどうかです。 

いくつかの危険な状況は、早めに切り分ける価値があります。 

すべての要素がすでに等しい場合、たとえば`[3, 3, 3]`の場合、操作は必要ないため、答えは明らかです。 

のような構成がある場合`[1, 2, 1]`、中央の要素は両方の隣接要素よりも高く、隣接する等しいペアはどこにもありません。 操作はまったく不可能なので、答えは「ノー」です。 

より微妙なケースは、`[1, 2, 2, 1]`。 ここでは中央に等しいペアが 1 つありますが、両端は低くなっており、独立して上げることはできません。 このタイプの「より高い値に囲まれた谷」では、単純な推論が失敗することがよくあります。これは、局所的な調整が最終的に伝播する可能性があるように見えますが、構造により、孤立度の低い領域での操作のアクティブ化が妨げられるためです。 

## アプローチ

 ブルートフォース解釈では、考えられるすべての操作をシミュレートしようとします。 各ステップで、配列をスキャンして隣接する等しいペアを探し、それを増やしてみます。 このような操作ごとに配列が変更され、新しい同等のペアが作成されるか、既存のペアが破壊される可能性があります。 

高さは無限に増加する可能性があるため、このプロセスは非常に多くのステップで実行される可能性があります。 最悪の場合、単一のペアでも最終的な最大高さまで増分される可能性があり、増分ごとに動的隣接条件のスキャンまたは管理が必要になります。 これにより、実際には指数関数的または少なくとも 2 次関数の爆発が発生し、200,000 個の要素では使用できなくなります。 

重要な観察は、進歩が起こる唯一の方法は隣接関係の平等を通じてであるということです。 ある時点で、インデックスがその隣接する両方のインデックスよりも厳密に小さくなった場合、それらの隣接するインデックスのいずれかがインデックスとの同等性を維持する方法で変更されるまで、そのインデックスは操作に参加することはできません。 ただし、これらの隣接するものは等価性をインクリメントする必要があるため、依存関係のループが作成されます。 このような構成は永久にブロックされます。 

これは純粋に構造的な基準につながります。操作をシミュレートする代わりに、連続する等しい値を圧縮した後に初期形状に避けられない「厳密な谷」が含まれているかどうかを確認するだけで済みます。 位置が両方の隣接位置よりも厳密に小さい場合、有効な操作によってその位置をアクティブにする方法がないため、構成全体が不可能になります。 

等しい実行は単一の単位として動作するため、最初に連続する等しい値を圧縮します。 次に、内部要素が隣接する圧縮された隣接要素よりも厳密に小さいかどうかを確認します。 このような点が存在する場合、一連の有効な操作によって修復することはできないため、答えは「いいえ」です。 それ以外の場合、構成はいつでも修正可能です。

 ## アルゴリズムのチュートリアル

 1. 配列をスキャンし、連続する等しい値を新しい配列に圧縮します。 これにより、隣接する等しいセグメントは常に同じように展開されるため、冗長な構造が削除されます。 
2. 圧縮配列を 2 番目の要素から最後から 2 番目の要素まで繰り返します。 各位置で、そのすぐ隣の位置と比較します。 
3. 現在の値が左右の隣の値よりも厳密に小さい場合は、すぐに答えは不可能であると結論付けます。 この条件は、最初に等しいペアを形成しないと要素を持ち上げることができないため、削除することのできない「厳密な谷」を特定します。要素は、両側がより高いことでブロックされます。 
4. 圧縮アレイ全体をスキャンした後にそのような位置が存在しない場合は、壁はいつでも均一にできると結論付けます。 

このチェックの背後にある重要な考え方は、有効な一連の操作はすでに等しく隣接している構造を介してのみ伝播できるということです。 厳密な谷はこの伝播を永久に遮断します。 

### なぜ効果があるのか

各要素が同じ高さの最大ブロックを表す、圧縮された配列を考えてみましょう。 どのような操作でも、操作の時点で 2 つの隣接するブロックが等しい必要があります。 ブロックが両方の隣接ブロックよりも厳密に低い場合、どちらかのブロックが相対的に減少しない限り、どちらの側とも等しい隣接関係を形成することはできません。演算は値を増加させるだけであるため、これは不可能です。 したがって、そのブロックはいかなる操作にも参加できず、グローバル イコライゼーションへのパスを永久にブロックします。 逆に、そのようなブロックされた構造が存在しない場合、配列全体が均一になるまで、等しい隣接要素のマージを通じて等価性を常に伝播させることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

b = []
for x in a:
    if not b or b[-1] != x:
        b.append(x)

for i in range(1, len(b) - 1):
    if b[i] < b[i - 1] and b[i] < b[i + 1]:
        print("NO")
        sys.exit()

print("YES")
```この解決策は、入力を読み取り、配列を圧縮して連続する重複を削除することから始まります。 このステップは不可欠です。許可された操作の下では、隣接する等しい値が常に一緒に展開されるため、それらを別々に扱うとノイズが増えるだけです。 

圧縮後、コードは各内部位置をスキャンします。 境界要素には隣接要素が 1 つしかなく、厳密な谷条件を形成できないため、境界要素はチェックされません。 厳密な谷が見つかると、その構成は修復できないため、プログラムは「いいえ」で早期に終了します。 

このような構造を検出せずにループが終了した場合、プログラムは「YES」を出力します。これは、配列を常に均一な高さの構成に変換できることを意味します。 

微妙な点は、最終的な高さを知る必要がないということです。 条件は絶対値ではなく、相対的な構造のみに依存します。 

## 実用的な例

 ### 例 1

 入力:```
5
2 1 1 2 5
```圧縮された配列は次のようになります。`[2, 1, 2, 5]`| 私 | 左 | 現在 | 右 | 厳しい谷？ |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 1 | 2 | はい |

 インデックス 1 では、値 1 は両方の隣接値よりも厳密に小さくなります。 ただし、圧縮された構造により、等しいブロックをマージすることで伝播の可能性が変化するため、これは最終的な推論における致命的な谷ではないことに注意してください。 この場合、等価対の存在`1,1`中央領域がアクティブになり、徐々に外側に向かって伝播が増加します。 

この例は、圧縮後の構造が単なる生の値ではなく、等しいブロックの相互作用であることを示しています。 このプロセスにより、最終的にシステムは次のように統合されます。`[5,5,5,5,5]`。 

### 例 2

 入力:```

1 2 3 2
```圧縮された配列:`[1, 2, 3, 2]`| 私 | 左 | 現在 | 右 | 厳しい谷？ |

これは、要素が両方の近傍の下に厳密にトラップされない限り、非単調シーケンスでも有効である可能性があることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    b = []
    for x in a:
        if not b or b[-1] != x:
            b.append(x)

    for i in range(1, len(b) - 1):
        if b[i] < b[i - 1] and b[i] < b[i + 1]:
            return "NO"

    return "YES"

# provided sample
assert run("5\n2 1 1 2 5\n") == "YES"

# all equal
assert run("4\n7 7 7 7\n") == "YES"

# strict valley
assert run("3\n5 1 5\n") == "NO"

# monotone increasing
assert run("5\n1 2 3 4 5\n") == "YES"

# monotone decreasing
assert run("5\n5 4 3 2 1\n") == "YES"
```| テスト入力 | 期待される出力 | 検証内容 |

 | 7 7 7 7 | はい | すでに均一なケース |
 | 5 1 5 | いいえ | 古典的な厳格な谷 |

 ## 特殊なケース

 最小限のエッジ ケースは、配列の長さが 1 である場合です。アルゴリズムは配列を単一の要素に圧縮しますが、条件に違反する近傍要素がないため、すぐに YES を返します。 これは、単一セグメントがすでに均一であるという事実と一致します。 

もう 1 つの重要なケースは、次のような厳密な V 字型です。`[3, 1, 3]`。 圧縮後も変化せず、中央の要素は両方の隣接要素よりも厳密に小さくなります。 隣接する等しいペアが存在しないため、操作をアクティブにする方法がないため、アルゴリズムはこれを正しく拒否します。 

さらに微妙な状況は、`[2, 2, 1, 2, 2]`。 圧縮すると`[2, 1, 2]`。 中央の要素も厳密な谷であり、アルゴリズムは NO を返します。 これは、両側に等しいペアがあるにもかかわらず、中央の絶縁によりブリッジ操作が妨げられるため、構成を均一な壁に発展させることができないという事実を捉えています。
