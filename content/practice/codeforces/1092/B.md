 ## 解決策
 ## 問題の理解

 学生のスキル レベルを表す整数の配列が与えられます。 生徒は正確にペアリングされなければなりません$\frac{n}{2}$素のペアなので、すべての生徒が 1 回だけ使用されます。 ペアは、その中の両方の生徒がまったく同じスキルレベルになる場合にのみ「有効」になります。 スキルは増加することのみが可能であるため (減少することはありません)、増加ごとに 1 単位コストを支払い、個々の生徒を何度でも増加させることができます。 

課題は、すべてのペアが等しい値で構成されるようにペアリングの構造と増分を選択すると同時に、すべての生徒で実行される増分の合計数を最小限に抑えることです。 

制約から得られる重要な観察点は次のとおりです。$n \le 100$したがって、ペアやソートに関する二次または三次推論も完全に安全です。 以上の漸近最適化については心配しません。$O(n^2)$これは、複雑なデータ構造や大規模な状態に対する DP ではなく、貪欲な戦略またはペアリング戦略に焦点を当てる必要があることを示唆しています。 

素朴な考え方による微妙な失敗例は、最初に等しい値を一致させてから、残りを貪欲に修正しようとすることです。 たとえば、値の不均衡が著しく大きい場合、ローカル一致を早期に修正すると、将来の調整にコストがかかる可能性があります。 もう 1 つの落とし穴は、並べ替えや構造化を行わないペアリングであり、全体的に最適なペアリングを簡単に見逃してしまう可能性があります。 

たとえば、`1 100 2 3`、のような素朴な組み合わせ`(1,100)`そして`(2,3)`構造的には合理的に見えますが、コストが膨大です。 より優れたグローバル ペアリングは、`(1,2)`そして`(3,100)`これにより、大きな値の調整がより効率的に分散されます。 

これは、順序が根本的に重要であることを示唆しています。 

## アプローチ

 ブルートフォースアプローチでは、生徒をペアにするあらゆる方法を試し、各ペアを等しくするためのコストをペアごとに計算します。 あるので$(n-1)!!$ペアリングする方法$n$アイテム、これは非常に急速に成長します。 たとえ$n = 20$、これは不可能になります。 各ペアリングでは、ペアを等化するコストを計算する必要があるため、コスト計算が高速であっても、列挙が優先されます。 

重要な洞察は、配列をソートすることです。 並べ替えると、最適なペアリングが構造化されます。隣接する要素をペアにします。 これが機能するのは、2 つの近い値をペアにすることで、小さい値を大きい値と一致させるコストが最小限に抑えられ、より適切なローカルの代替値が存在する場合に、並べ替えによって小さい値と非常に大きい値のペアを回避できるためです。 

ソート後はペアのみを考慮する必要があります$(a_0, a_1), (a_2, a_3), \dots$。 各ペアのコストは単純に次のようになります。$a_{i+1} - a_i$小さい要素のみを増加させるためです。 

これにより、問題は、組み合わせペアリングの問題から、ソートされた配列に対する線形スキャンに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース ペアリングの列挙 |$O(n!)$|$O(n)$| 遅すぎる |
 | ソート + 貪欲な隣接ペアリング |$O(n \log n)$|$O(1)$または$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての生徒のスキル値を配列に読み取ります。 目標は、等しいペアを形成するために必要な合計増分を最小限に抑えることです。 
2. 配列を降順でない順に並べ替えます。 このステップにより、数値的に近い値が確実に隣接するようになります。これは、調整コストを最小限に抑えるために不可欠です。 
3. 変数を初期化する`answer = 0`必要な増分の合計数を累積します。 
4. 連続するペアを考慮して、ソートされた配列を 2 ステップで繰り返します。 
5. ペアごとに`(a[i], a[i+1])`、コストを次のように計算します。`a[i+1] - a[i]`。 これは、小さい値を大きい値に合わせて増加させることを表します。 
6. このコストを累計に加算します。 
7. 最終的な累積コストを出力します。 

### なぜ効果があるのか

 ソート後、コストを増加させることなく、隣接する要素間でペアリングが行われる最適なソリューションに変換できます。 ペアリングなど、2つのペアが交差している場合`(a_i, a_k)`そして`(a_j, a_l)`と$i < j < k < l$、それらを交換します`(a_i, a_j)`そして`(a_k, a_l)`ペア内の大きなギャップが減少するため、総コストが増加することはありません。 この引数を繰り返し適用すると、すべての交差が排除され、隣接するペアが最適になります。 

これは、貪欲な隣接ペアリングが便利なだけでなく、構造的に最適であることを証明します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

a.sort()

ans = 0
for i in range(0, n, 2):
    ans += a[i+1] - a[i]

print(ans)
```この解決策は、入力を読み取り、スキル配列を並べ替えることから始まります。 ソートは、最適な組み合わせが局所的になる構造を作成するため、不可欠です。 

ループは配列を 2 つのチャンクに分けて処理します。 各反復では 2 つの隣接する並べ替え値をペアにし、グローバル最適構造の下でそのペアの最小コストを保証します。 増分のみが許可されるため、差は直接加算されます。したがって、常に小さい値を上げて大きい値と一致させます。 

境界の問題がないので、$n$さえ保証されているので、`a[i+1]`は常に有効です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \log n)$| 並べ替えが優先され、その後は単一の直線パス |
 | スペース |$O(1)$または$O(n)$| インプレースソートの実装に依存します |

 制約$n \le 100$これで十分以上になります。 単純な並べ替えや繰り返しのスキャンでも、制限内で問題なく通過できます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    ans = 0
    for i in range(0, n, 2):
        ans += a[i+1] - a[i]
    return str(ans)

# provided sample
assert run("6\n5 10 2 3 14 5\n") == "5"

# all equal
assert run("4\n7 7 7 7\n") == "0"

# increasing sequence
assert run("4\n1 2 3 4\n") == "2"

# large gap case
assert run("4\n1 100 2 3\n") == "98"

# minimum case
assert run("2\n1 10\n") == "9"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべて等しい値 | 0 | ゼロコストのペアリングの正確性 |
 | 1 2 3 4 | 2 | 隣接ペアリングの最適性 |
 | 1 100 2 3 | 98 | 大きな不均衡に対処する |
 | 1 10 | 9 | 最小境界の場合 |

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての値がすでに等しい場合です。 アルゴリズムはそれらを並べ替えますが、隣接する差分はすべてゼロであるため、結果はゼロのままです。 入力用`4 / 5 5 5 5`、ソートされた配列は変更されず、計算された差分はすべて消えます。 

もう 1 つのエッジ ケースは、値が大きく偏っている場合です。`1 1 1 100`。 ソート後のペアは次のようになります。`(1,1)`そして`(1,100)`。 1 つ目はコスト 0 を寄与し、2 つ目はコスト 99 を寄与しますが、大きな値が 1 つしか存在しないため、これは避けられません。 

最後のエッジケースは可能な限り最小の入力です`n = 2`。 このアルゴリズムは、並べ替え後の 2 つの値の差を単純に返します。これは、唯一の有効なペアに直接一致します。
