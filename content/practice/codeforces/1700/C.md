 ## 解決策
 ## 問題の理解

 木々の小道に沿った土壌水分レベルを表す整数の配列があります。 それぞれの値は正、負、ゼロのいずれかになります。目標は、プレフィックスを 1 減らす、サフィックスを 1 減らす、配列全体を 1 増やすという 3 つの操作を使用して、すべての値をゼロに減らすことです。 タスクは、ゼロ配列を達成するためのそのような操作の最小数を決定することです。 

配列のサイズ`n`すべての合計は 200,000 に達する可能性があります`n`すべてのテスト ケースの数も 200,000 に制限されます。 これは、テスト ケースごとにおよそ O(n) を超える作業を実行するアルゴリズムを導入する余裕がないことを意味します。 二次関数以上のものは遅すぎます。 水分値はどちらの方向でも最大 10^9 と非常に大きくなる可能性があるため、各増加または減少を個別にシミュレートしようとするアプローチは除外されます。 

明らかでないエッジ ケースには、すべての値が負である配列、正の値と負の値が交互に現れる配列、または境界で極値が発生する配列が含まれます。 たとえば、配列`[-3, -2, -5]`ゼロに達するには配列全体の増加のみが必要ですが、次のような混合配列は`[5, -5, 5, -5]`プレフィックスとサフィックスの操作を慎重に分割する必要があります。 左から右に 1 回だけスキャンする単純なアプローチでは、グローバル増加操作で負の値を「プッシュ」する必要性を考慮できないため、これらのアプローチでは失敗します。 

## アプローチ

 ブルートフォース手法は概念的には単純です。 操作ごとに、配列をスキャンし、ゼロ以外の値を持つプレフィックスまたはサフィックスを見つけて、デクリメント (またはグローバル操作の場合はインクリメント) を適用します。 各操作では一部の値が 1 ずつ減り、すべての値が 0 になるまで繰り返します。 これが機能するのは、許可された操作が整数の任意のパターンをゼロに操作するのに十分であるためです。 しかし、このアプローチは遅すぎます。`n = 2 * 10^5`そして最大値`10^9`の場合、シミュレートされた操作の数は数十億に達しますが、これは 2 秒では不可能です。 

最適なソリューションのための重要な洞察は、連続する要素間の違いの観点から操作を扱うことから得られます。 あるポジションから次のポジションに必要な変化を見ると、各ステップに必要な正の増加と正の減少の合計として合計移動を表すことができます。 具体的には、最小移動数は、最初の要素の絶対値の合計に、左から右に移動する場合のすべての正の差の合計と、右から左に移動する場合のすべての負の差の合計を加えたものになります。 これが機能するのは、それぞれのプレフィックス/サフィックス操作が違いを効率的に「吸収」するものとして解釈できるためです。 

基本的に、隣接する要素間の各ローカルな増加または減少は、単一の接頭辞または接尾辞の操作によって満たされ、グローバルな増加操作は負の開始値を処理します。 これらの差を 1 回のパスで蓄積することで、シミュレーションを回避し、問題を O(n) 時間に短縮します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * max( | a_i | )) |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして配列`a`。 
3. カウンタの初期化`actions`ゼロに。 これにより、必要な操作全体が追跡されます。 
4. 最初のステップは、最初の要素を処理することです。 もし`a[0]`はマイナスです、必要です`-a[0]`アレイ全体で増加します。 陽性の場合、必要です`a[0]`プレフィックス操作によって減少します。 これを追加`actions`。 
5. 配列をインデックス 1 から n-1 までループします。 要素ごとに`a[i]`、差を計算します`diff = a[i] - a[i-1]`。 もし`diff > 0`、これは、前の要素と比較して必要な追加の増加を表し、接頭辞操作によって達成できます。 もし`diff < 0`、これは、サフィックス操作によって達成可能な追加の減少を表します。 の絶対値を加算します。`diff`に`actions`。 
6. ループが完了したら、`actions`配列をゼロにするために必要な最小限の操作が含まれています。 
7. 印刷`actions`テストケースごとに。 

機能する理由: カウントする各操作は、連続する要素間の傾きを修正するために必要な最小作業単位に対応します。 プレフィックスとサフィックスの操作は正と負の差に自然に対応し、グローバル増加は最初の負の開始点を処理します。 この不変条件により、冗長な手がカウントされないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        actions = abs(a[0])  # handle the first element
        for i in range(1, n):
            diff = a[i] - a[i-1]
            actions += abs(diff)
        print(actions)

if __name__ == "__main__":
    solve()
```コードが初期化されます`actions`最初の要素の絶対値を使用し、最小操作カウントを反映して開始をゼロにします。 次に、ループは連続する要素間のすべての勾配のコストを累積します。 使用する`abs`正の調整と負の調​​整の両方を確実にカウントし、単一のループでテスト ケースごとにこの O(n) が行われます。 境界エラーは、インデックス 1 から開始することで回避されます。

 ## 特殊なケース

 次のような厳密に負の配列の場合`[-3, -2, -5]`、`actions`最初の要素は 3 から始まります。 すると違いは`(-2)-(-3)=1`そして`(-5)-(-2)=-3`, そこで追加します`1 + 3 = 4`これは、3 つのグローバルな増加とスロープ間の調整を反映し、配列を正しくゼロにします。 

交互配列の場合`[1, -2, 3, -4]`、計算します`abs(1)=1`、次に違い`-3, 5, -7`、追加`3+5+7=15`各ステップは、シミュレーションなしでプレフィックスおよびサフィックスの操作に必要な正確な動きをキャプチャします。 

これにより、アルゴリズムが境界差、混合符号、および極値を一貫して処理していることが確認されます。
