 ## 解決策
 ## 問題の理解

 2 つのバイナリ グリッドが与えられ、それぞれにちょうど 2 つの行があり、$n$列。 すべてのセルには 0 または 1 が含まれます。 グリッドは初期構成で開始され、ターゲット構成に変換する必要があります。 

許可される唯一の操作は、エッジを共有する 2 つのセル間で値を交換することです。つまり、それらのセルは列内で垂直方向に、または行内で水平方向に隣接しています。 各スワップには 1 回の移動が必要です。初期グリッドをターゲット グリッドに変換するために必要な移動の総数を最小限に抑えるか、それが不可能であると判断する必要があります。 

構造は重要です。グリッドは垂直方向には非常に薄い (2 行のみ) ですが、水平方向には非常に長くなる可能性があります (最大 200,000 列)。 そのため、これを一般的なグラフのように扱ったり、スワップを直接シミュレートしようとしたりするアプローチは実行不可能になります。 

最初の制約の意味はサイズに由来します。 と$n \le 200000$、二次関数で動作する任意のアルゴリズム$n$すぐに失敗します。 平$O(n \log n)$解決策はギリギリ許容可能ですが、問題の構造が線形または線形に近い動作を示唆しているため、おそらく不要です。 

重要な隠された構造は、1 の合計数がスワップで保存されることです。 これにより、両方のグリッドに同じ数の 1 が含まれていなければならないという必要な条件がすぐに得られます。 そうでなければ、答えは直ちに不可能になります。 

2 番目の明白ではないエッジ ケースは、接続の制約から生じます。 スワップは隣接するセル間でのみ許可されるため、再配置によっては、独立した行について誤った推論を行うと、最適に横断できない「ブロック構造を介して」セルを移動する必要がある場合があります。 

たとえば、最初のグリッドのすべての 1 が一番上の行にあるが、ターゲット グリッドでは垂直エッジと交差する必要がある位置でいくつかの 1 が一番下の行になければならない状況を考えてみましょう。 移動制約のパリティが一致しない場合は、1 の合計数が一致しても変換は不可能です。 

単純な間違いは、各行を並べ替えの問題として独立して扱うことです。 これは、垂直方向のスワップによって行が結合されるため、失敗します。つまり、トークンが行間を移動してから水平方向に継続する可能性があります。 

もう 1 つの微妙な失敗例は、貪欲な左から右への一致が常に機能すると仮定することです。 スワップはローカルであるため、トークンを右端に移動すると、他のトークンがブロックされたり、コストが増加したりする可能性があるため、グローバル構造が重要です。 

## アプローチ

 ブルートフォース解釈では、それぞれを個別のトークンとして扱い、ターゲット構成に到達するまでグリッド上でスワップをシミュレートします。 グリッドの完全な状態空間で BFS またはダイクストラを実行することを想像できます。各状態はバイナリ行列であり、エッジは隣接するスワップに対応します。 これは原理的には正しいです。すべてのスワップは可逆的であり、すべての移動のコストは 1 であるため、最短パスの検索により最小の操作数が得られます。 

問題は、状態空間が巨大であることです。 だけでも$2n$セルの数が増えると、構成の数は指数関数的に増加します。$n$、このアプローチは小さなものを超えると完全に実行不可能になります$n$。 

重要な洞察は、構成の観点から考えるのをやめ、代わりにそれぞれを固定グラフに沿った移動可能なトークンとして扱うことです。 グリッドは 2 by$n$ラダー グラフは 2 部構成で高度に構造化されています。 すべての交換は 2 つの隣接する位置を交換するだけなので、事実上、グラフに沿って同一の項目を並べ替えることになります。 

位置の順序を修正すると、最初のグリッド内の位置とターゲット グリッド内の位置を一致させることが問題になります。 すべてのものは区別できないため、最適な戦略は、合計距離を最小化する方法で、グラフに沿って走査する順序でそれらをペアにすることになります。 

重要な削減点は、最短の変換コストが、ラダー グラフの正規の走査順序に沿ってソートされた位置を一致させる最小コストに等しいことです。 残る唯一の問題は実現可能性です。行間の移動制約により、パリティ制限が課され、これを遵守する必要があります。 

これを処理する標準的な方法は、2 を次のように変換することです。$n$グリッドを長さの線形シーケンスに変換する$2n$ジグザグ マッピングを使用します。 両方のグリッドが一貫して平坦化されたら、1 の位置を比較し、一致するインデックス間の絶対差の合計を計算します。 カウントが異なる場合、または構造上の制約によりペアリングの一貫性が損なわれる場合、答えは不可能です。

 ## アルゴリズムのチュートリアル

 グリッドを直線構造に縮小し、隣接性と移動コストを維持します。 

1. すべての線形順序付けを構築します。$2n$グリッド内の隣接するスワップがこの順序で隣接するインデックスに対応するようにセルを配置します。 自然な順序付けは列単位です: インデックス$(0, i)$まず、それから$(1, i)$、またはその逆も一貫して行われます。 これにより、許可されたすべてのスワップが 1D 配列内の隣接するインデックスのスワップになることが保証されます。 
2. 初期グリッドとターゲット グリッドの両方を 2 つの長さの配列に平坦化します。$2n$同じ順序を使用します。 解が存在する場合、各配列にはまったく同じ数の 1 が含まれます。 
3. 初期配列内のすべての 1 のインデックスをリストに抽出します。$A$、同様にターゲット配列からインデックスを抽出します。$B$。 
4. もし$|A| \neq |B|$、すぐに -1 を返します。 これは、スワップ中のものの保存を反映しています。 
5. k番目のものをペアリングします$A$k番目のもので$B$。 ソートされた順序で同一のアイテムを交換すると、線形構造内の絶対変位の合計が最小限に抑えられるため、このペアリングは最適です。 
6. 総コストを次のように計算します。$\sum |A_k - B_k|$。 距離の各単位は、平坦化された表現における 1 つの隣接するスワップに対応します。 
7. この合計を答えとして返します。 

順序どおりのペアリングが有効である主な理由は、ペア間の交差代入により不必要な反転が発生し、総コストが増加するためです。 単調マッチングは、線上の L1 距離を最小化するための独自の最適解です。 

### なぜ効果があるのか

 この変換により、グリッドは、各セルがノードであり、スワップがエッジに対応するパス グラフに縮小されます。 このような構造では、トークンは区別できず、移動はエッジに沿った単位コストの交換になります。 ライン上の最適な搬送問題は、位置をソートし、順番にマッチングすることで解決されます。 ラダー グラフは隣接距離を変更せずにラインに埋め込むことができるため、コストはその埋め込みにおける差の絶対値の合計になります。 モノトーンマッチングから逸脱すると、交差フローが発生し、合計距離が厳密に増加します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    a = []
    b = []
    
    # flatten 2 x n grid into 1D of size 2n
    for r in range(2):
        row = list(map(int, input().split()))
        for c, v in enumerate(row):
            if v:
                a.append(r * n + c)
    
    for r in range(2):
        row = list(map(int, input().split()))
        for c, v in enumerate(row):
            if v:
                b.append(r * n + c)
    
    if len(a) != len(b):
        print(-1)
        return
    
    ans = 0
    for i in range(len(a)):
        ans += abs(a[i] - b[i])
    
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、グリッドの一貫した線形インデックスを構築し、問題を一致する位置に変換します。 実装上の重要な選択は、両方のグリッドに同じ平坦化順序を使用して、平坦化された配列内の距離がグリッド内の実際の移動コストに対応するようにすることです。 

微妙な点は、貪欲なスワッピング シミュレーションを試みていないことです。 代わりに、位置を計算するだけなので、中間状態をシミュレートする必要がなくなります。 もう 1 つの微妙な点は、距離の解釈が無効になるため、グリッド間で行優先と列優先の順序を誤って混合しないようにすることです。

 ## 特殊なケース

 重要なエッジ ケースは、初期グリッドとターゲット グリッドの間で 1 の数が異なる場合です。 この状況では、スワップはマルチセットのコンテンツを保持するため、一連のスワップによって不一致を修正することはできません。 アルゴリズムは、抽出された位置リストを比較することでこれを即座に検出します。 

もう 1 つのエッジ ケースは、最初のグリッドではすべての 1 が 1 つの行に集中しているが、ターゲットでは両方の行に分散している場合です。 垂直方向の動きが線形表現の隣接する位置にエンコードされるため、平坦化アプローチでもこれを正しく処理できます。そのため、実現可能性は一致するカウントと順序にのみ依存します。 

最後の微妙なケースは、密集している場合です。 単純な貪欲なシミュレーションでは、トークンを 1 つずつ移動し、不必要なクロスを導入して誤って過剰支払いを行う可能性があります。 モノトーンペアリングは、一致するペア間で反転がないことを保証し、はしご構造に沿った輸送コストを最小限に抑えるため、これを回避します。
