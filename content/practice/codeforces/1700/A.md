 ## 解決策
 ## 問題の理解

 カメがテーブルの左上隅から右下隅まで移動するための最小コストを見つけるように求められます。 テーブルには、\(n\)行と\(m\)各セルには数値 \((i-1) \cdot m + j\) が含まれます。ここで、\(i\)そして\(j\)は行と列のインデックスです。 カメは各ステップで下または右にのみ移動できます。 パスのコストは、開始セルと終了セルを含む、そのパスに沿って訪問したすべてのセルの数値の合計です。 

制約を考慮すると\(1 \le n, m \le 10^4\)最大 1000 のテスト ケースでは、パターンを分析した後、テスト ケースごとに \(O(1)\) のアルゴリズムが必要です。これは、グリッドを構築するか、すべてのパスを列挙すると \(O(n \cdot m)\) になり、これは到達する可能性があるためです。\(10^8\)テスト ケースごとの操作が制限時間に対して明らかに遅すぎます。 

明らかではないエッジ ケースには、単一行または単一列のテーブルが含まれます。 たとえば、次の場合\(n = 1, m = 10\)、カメには行に沿って 1 つのパスしかありません。 正しい出力は、連続する整数の合計です。\(1 + 2 + ... + 10 = 55\)。 近隣を検査することで「最小限の」ステップを選択しようとする不用意なアプローチは、方向に選択肢がないため失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、完全なグリッドを構築し、動的プログラミングソリューションを試みます。 させて\(dp[i][j]\)セル \((i,j)\) に到達するための最小コストになります。 次のように定義できます。$$
dp[i][j] = a_{ij} + \min(dp[i-1][j], dp[i][j-1])
$$ベースケース付き\(dp[1][1] = 1\)。 これは正しく動作しますが、テスト ケースごとに \(O(n \cdot m)\) の時間を要します。 最大の入力の場合、これは次の値に達します。\(10^8\)動作が遅すぎます。 

重要な観察は、カメは右か下にしか移動できないということです。 したがって、すべての最小限のパスはエッジに沿って移動することから開始する必要があります。最初にすべて下に移動してからすべて右に移動するか、すべて右に移動してからすべて下に移動するかのいずれかです。 他のすべてのパスはこれらの動きの順列であり、パスに沿って同じ一連の数値が生成されますが、順序は異なります。 たとえば、3x2 テーブルでは次のようになります。$$
\begin{matrix}
1 & 2 \\
3 & 4 \\
5 & 6
\end{matrix}
$$\((1,1)\) から \((3,2)\) までのすべてのパスには、数値 1、2、4、5、6 が順序どおりに含まれている必要があります。 これらの数値の合計は、グリッド上で反復することなく、等差級数の公式を使用して実行できます。 

パスを「垂直、水平」または「水平、垂直」に分割すると、合計を直接計算できます。 させて\(n\)行数になり、\(m\)列の数。 最小のコストは、外側の境界線に沿って、最初の列に沿って最後の行まで下に進み、最後に最後の行に沿って右に進むことで達成されます。 最初の列の合計は次のとおりです。$$
\text{sum of first column} = 1 + (1+m) + (1+2m) + ... + (1 + (n-1)m) = n + m \cdot \frac{n(n-1)}{2}
$$すでにカウントされている角を除いた最後の行に沿った合計は次のようになります。$$
\text{sum of last row excluding first column} = (n-1)m + 1 + 2 + ... + (m-1)
$$両方を組み合わせた簡略化された式は次のようになります。$$
\text{cost} = n + m \cdot \frac{n(n-1)}{2} + \frac{(m-1)m}{2} + (n-1)m
$$単純化すると、次のようになります。$$
\text{cost} = n \cdot m \cdot (n-1)/2 + m \cdot (m-1)/2 + n
$$または、列に沿って合計を計算し、次に残りの行に沿って合計を計算することで、より明確になります。 この式では、テスト ケースごとに \(O(1)\) の計算が行われます。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る\(t\)。 テスト ケースごとに、次の内容を読んでください。\(n\)そして\(m\)。 

2. 最初の列に沿って \((1,1)\) から \((n,1)\) までの合計を計算します。 これは初項1と公差のある等差数列です\(m\)。 合計の式は次のとおりです。$$
\text{first column sum} = n + m \cdot \frac{n(n-1)}{2}
$$3. \((n,2)\) から \((n,m)\) までの最後の行に沿って合計を計算します。 この行の最初の要素は \(a_{n,1} = 1 + (n-1)m\) で、残りは 1 ずつ増加します。最初の列を除いたこの行の合計は次のようになります。$$
\text{last row sum excluding first column} = \frac{(2 + ... + m)}{} + a_{n,1} \cdot 0?
$$より単純なアプローチ: 最初の列の合計には次のものが含まれます。\(a_{n,1}\)なので、行の残りの部分を追加します\(a_{n,2} + ... + a_{n,m}\)。 これらのそれぞれは \(a_{n,j} = (n-1)m + j\) で、j=2..m で合計されます。$$
\sum_{j=2}^{m} ((n-1)m + j) = (m-1)(n-1)m + \frac{m(m+1)}{2} - 1
$$4. 2 つの部分を合計して、最小パス コストの合計を取得します。 

5. 各テストケースの結果を出力します。 

機能する理由: タートルは左にも上にも移動できないため、最小パスは最後の行に到達するまで上端と左端を抱き、その後最後の行に沿って進む必要があります。 他のパスには以前より大きな数値が含まれており、合計が増加します。 これは、行と列に沿って厳密に増加する番号付けパターンによって保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    if n > m:
        n, m = m, n  # swap to simplify formula, assume n <= m

    # sum along first column: 1, 1+m, 1+2m, ..., 1+(n-1)m
    first_col = n + m * n * (n-1) // 2
    # sum along last row excluding first column: (n-1)m + 2 to (n-1)m + m
    last_row = (m*(m+1)//2) - 1 + (n-1)*m
    total = first_col + last_row
    print(total)
```コードはまず n と m を交換して n <= m にし、計算を簡素化します。 最初の列の合計を等差級数として計算し、最後の行の残りを加算します。 最後の行の最初のセルが二重にカウントされるのを避けるために、1 を減算します。
