 ## 解決策
 ## 問題の理解

 各クロスワードに次のいずれかの時間がかかることを前提として、Adilbek が一定の時間内に完全に解決できるクロスワードの予想数を計算するように求められます。`t_i`または`t_i + 1`等しい確率で独立して秒数が発生します。 彼はクロスワードを厳密に順番に解き、合計時間が達するかそれを超えるとすぐに停止します。`T`。 計算する期待値は、完成したクロスワードの可能なすべての数の確率で重み付けされた合計です。 

入力により得られるのは、`n`、クロスワードの数、`T`、合計利用可能時間、およびリスト`t`個々のクロスワードの時間。 出力は次のように表される期待値です。`P * Q^{-1} mod 10^9+7`どこ`P/Q`は合理的な期待値です。 

制約が厳しい:`n`最大 2·10^5 にすることができ、`T`2・10^14まで。 これにより、すべてを考慮した強引なアプローチは除外されます。`2^n`完了時間のシーケンス。 単純な再帰または明示的な確率テーブルでは、遅すぎる可能性があります。 それぞれ`t_i`は最大 10^9 であるため、整数のオーバーフローを避けるために累積和を慎重に処理する必要があります。 

エッジケースには、次のような状況が含まれます。`T`最初のクロスワード時間より小さいか (期待値は 0 である必要があります)、またはちょうど 1 つのクロスワードに十分な値です (期待値は小数になる可能性があります)。 もう 1 つの微妙なケースは、複数のクロスワードが同じ時間を持っている場合に発生します。完了の確率分布には 1/2 の累乗が含まれ、正確なモジュラー演算が必要です。 

## アプローチ

 単純なアプローチでは、成功と 1 秒以上の遅延の考えられるすべてのシーケンスを考慮し、0、1、…、が終了する正確な確率を計算します。`n`クロスワード。 各クロスワードには 2 つの選択肢があります。`2^n`合計シーケンス。 のために`n=2*10^5`、これは不可能です。 

重要な洞察は、期待の直線性です。 遅延のすべての組み合わせを考慮する必要はありません。 アディルベックが完了すると予想されるクロスワードの数は、時間内に完了する確率の各クロスワードの合計です。 もし`dp[i]`後の合計時間にわたる確率分布を表します。`i`クロスワード、期待される貢献`(i+1)`- 番目のクロスワードは、それまでのすべてのクロスワードを完了し、十分な時間が残っている確率の合計にすぎません。 

累積確率のスライディング ウィンドウを使用して、これを効率的に実装できます。 させて`prefix[i]`回数の合計になる`t[0..i-1]`。 その後に時間が空いた場合は、`i`クロスワードは超える`T - t[i]`、クロスワードは確実に完成します。 それを超えた場合`T - t[i] - 1`、確率1/2で完成します。 これにより、問題はシーケンス全体の累積和を計算し、1/2 の累乗を適用することに減ります。 モジュラ逆算は、モジュロ演算で 1/2 因数を処理します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 線形期待値 + プレフィックスの合計 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. クロスワード時間のプレフィックスの合計を事前計算します。 これにより、`S[i] = t_0 + t_1 + … + t_{i-1}`。 これらは最初の作業を完了するまでの最小時間を表します。`i`クロスワード。 
2. 余分な 1 秒ごとに 1/2 の確率で発生するため、2 の逆剰余を計算します。 モジュール逆関数により、以下の確率計算が可能になります。`10^9+7`。 
3. 変数を初期化する`prob`前のすべてのクロスワードが最小限の時間内に完了する確率を表す 1 として。 
4. 各クロスワードを繰り返す`i`。 累積和の場合`S[i] + t[i]`以下である`T`, クロスワードは確実に完成します。 追加`prob`期待値に。 もし`S[i] + t[i] + 1`以下である`T`、クロスワードは 1/2 の確率で完成します。 追加`prob * 1/2`。 乗算する`prob`追加秒シナリオを考慮すると、その後のクロスワードを完了する確率が半分になるため、1/2 になります。 
5. すべてのクロスワードを反復した後、有理分数として期待値が得られます。`P/Q`。 乗算する`Q^-1 mod 10^9+7`最終的な答えを得るために。 

機能する理由: 期待値の線形性により、各クロスワードの期待される寄与を個別に合計することができます。 プレフィックスの合計により、実行可能な完了のみを考慮することが保証されます。 1/2 のべき乗は、シーケンスの指数関数的な列挙を回避しながら、余分な 1 秒の遅延を正確に考慮します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def main():
    n, T = map(int, input().split())
    t = list(map(int, input().split()))
    
    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + t[i]
    
    inv2 = modinv(2)
    expected = 0
    prob = 1
    
    for i in range(n):
        if prefix[i + 1] <= T:
            expected = (expected + prob) % MOD
        elif prefix[i] + t[i] <= T:
            expected = (expected + prob * inv2) % MOD
            prob = (prob * inv2) % MOD
            break
        else:
            break
        prob = (prob * inv2) % MOD

    print(expected)

if __name__ == "__main__":
    main()
```この解決策は、完了時間を最小限に抑えるためのプレフィックスの合計から始まります。 浮動小数点演算を避けるために、逆モジュラーを明示的に処理します。 の`prob`変数は、以前のすべてのクロスワードが最小限の時間内に完了する確率を維持します。 乗算`inv2`次のクロスワードにさらに 1 秒かかる可能性をシミュレートします。 エッジケースはプレフィックスの合計比較によって自然に処理されます。
