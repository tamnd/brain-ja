 ## 解決策
 ## 問題の理解

 いくつかの独立したグリッドが与えられます。 各グリッドは文字のマトリックスであり、各セルはすでに黒であるか、まだ白です。 白マスを一度に 1 つずつ黒に変えることができます。 目標は、グリッドに少なくとも 1 つの「十字」を含めることです。 

十字は行を選択することで定義されます`x`そしてコラム`y`行内のすべてのセルが`x`列内のすべてのセルが黒です`y`黒です。 言い換えれば、完全に黒の行が 1 つと完全に黒の列が 1 つ必要で、それらは 1 つのセルで交差します。 

クエリごとに、再描画する必要がある白いセルの最小数を計算して、そのようなペアが少なくとも 1 つ存在するようにする必要があります。`(row, column)`存在します。 

制約があるため、私たちは効率について慎重に考える必要があります。 すべてのクエリのセルの合計数は最大 4 × 10^5 であるため、各セルを一定の回数だけ処理するソリューションであればどれでも受け入れられます。 ただし、すべての行と列のペアを明示的にテストしようとすると、最悪の場合 O(nm(n+m)) になるため、遅すぎます。 

単純な間違いは、実際のコストを評価せずに、候補となる行と列を貪欲に選択できると考えることです。 これは、複数の行と列がほぼ完成しているものの、いくつかの点在する位置で異なるグリッドでは失敗します。 たとえば、行で欠落しているセルが 1 つだけで、列で多くのセルが欠落している場合、列の相互作用を考慮せずに貪欲に行を選択すると、必要な再描画コストが過小評価または過大評価される可能性があります。 

複数のペアが同じ欠落セルを共有する場合、別の微妙な失敗ケースが発生します。 単一のセルを再描画すると、行と列の両方が同時に修正される可能性があるため、行の補完と列の補完を個別に扱うと、不正確な答えが得られます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 考えられるすべてのペアについて`(x, y)`、行内に何個の白セルが存在するかを計算します。`x`加えて列にいくつ存在するか`y`, ただし、交差セルを二重にカウントすることは避けなければなりません。 その交差が白の場合、単純合計で 2 回カウントされるため、1 回減算します。 

これは、行が必要な場合に機能するため、`x`完全に黒の場合は、その中のすべての白いセルを再ペイントする必要があります。 列についても同様に`y`。 これらの再描画操作を結合すると、候補コストが得られます。 すべてのペアを試すと正確さが保証されますが、コストが法外に高くなります。 行数と列数の計算には O(nm) がかかり、すべてのペアのチェックには O(nm) がかかり、すでに境界線に達しているグリッドごとに O(nm) となり、クエリが多くなるとこれ以上詳細な再計算が遅くなりすぎます。 

重要な観察点は、ペアのコストが`(x, y)`事前に計算された 3 つの量のみに依存します: 行内の白セルの数`x`、列内の白セルの数`y`、そして`(x, y)`すでに黒か白になっています。 これらが判明すると、各候補ペアは O(1) で評価されます。 これにより、行と列の統計を 1 回計算し、その後すべてのセルをもう一度スキャンして最適なペアを見つけるという問題が軽減されます。 

交差点の修正により、問題が自明ではなくなります。`(x, y)`が白の場合、行と列の両方の白数に含まれるため、1 を減算します。 

すべてのセルを反復処理し、各セルを潜在的な交差中心として扱うことで、すべてのペアを暗黙的に試行します。 すべての有効な十字が何らかのセルの中心になければならず、すべての中心候補が行と列の一意のペアに対応するため、これで十分です。

 ## アルゴリズムのチュートリアル

 ### 1. 行および列ごとに黒と白のセルを数える

 グリッド全体を 1 回スキャンします。 各行について、そこに含まれる白セルの数を計算し、各列についても同じことを行います。 これにより、行または列を完全に黒くするには何回の再描画操作が必要かをすぐに知ることができます。 

### 2. 交差チェックのためにグリッドの状態を保存する

 各セルのブール値または文字表現を保持しているので、特定の交差セルがすでに黒であるか、またはペイントする必要があるかを確認できます。 交差セルは行と列の合計で 2 回カウントされるため、これは重要です。 

### 3. すべてのセルを潜在的な交差中心として試してください。 

細胞ごとに`(i, j)`、行を作成するコストを計算します`i`完全に黒で柱状`j`完全に黒。 費用は次のとおりです。 

列にある白マスの数`i`列内の白セルの数を加えたもの`j`、セルの場合はマイナス 1`(i, j)`白いです。 

減算により、同じ再描画操作の二重カウントが回避されます。 

### 4. すべての候補の最小コストを追跡する

 答えを大きな値として初期化し、セルごとに更新します。 計算された最小値がそのクエリの答えになります。 

### なぜ効果があるのか

 すべての有効なクロスは、行と列のペアに対応する必要があります。`(x, y)`。 その十字を作成するコストは、これら 2 つの行の欠落しているセルを埋めることだけに依存します。 行外の再描画操作`x`または列`y`は不要であり、そのペアを改善することはできません。 考えられるすべてのセンターを評価するため、`(x, y)`、必ず最適なクロス構成を評価し、最小値が見つかることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n, m = map(int, input().split())
        grid = [input().strip() for _ in range(n)]

        row_white = [0] * n
        col_white = [0] * m

        for i in range(n):
            for j in range(m):
                if grid[i][j] == '.':
                    row_white[i] += 1
                    col_white[j] += 1

        ans = float('inf')

        for i in range(n):
            for j in range(m):
                cost = row_white[i] + col_white[j]
                if grid[i][j] == '.':
                    cost -= 1
                if cost < ans:
                    ans = cost

        print(ans)

if __name__ == "__main__":
    solve()
```実装では、前処理と評価が分離されます。 まず、行と列のホワイト カウントが 1 回のパスで計算されます。 次に、各セルが潜在的な交点として扱われ、一定時間で評価されます。 重要な点は、交差セルがすでに白の場合は 1 を減算することです。そうでない場合は 2 回カウントされるためです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        q = int(input())
        for _ in range(q):
            n, m = map(int, input().split())
            grid = [input().strip() for _ in range(n)]

            row_white = [0] * n
            col_white = [0] * m

            for i in range(n):
                for j in range(m):
                    if grid[i][j] == '.':
                        row_white[i] += 1
                        col_white[j] += 1

            ans = float('inf')

            for i in range(n):
                for j in range(m):
                    cost = row_white[i] + col_white[j]
                    if grid[i][j] == '.':
                        cost -= 1
                    ans = min(ans, cost)

            print(ans)

    solve()
    return sys.stdout.getvalue().strip()

 ## 特殊なケース

 主なエッジ ケースは、交差セルが白であり、行と列の両方の再描画カウントに影響を与える場合です。 たとえば:

 入力:```
1
2 2
..
..
```ロウホワイトは`[2,2]`そして列の白は`[2,2]`。 セル用`(1,1)`、ナイーブコストは`2 + 2 = 4`、しかしこれは二重にカウントされます`(1,1)`。 正しいコストは`3`。 アルゴリズムは正しく 1 を減算し、`3`、すべてのセルの最小値は次のとおりです。`3`これは、中央を共有する 1 行全体と 1 列全体をペイントすることに相当します。 

もう 1 つのエッジ ケースは、行または列がすでに完全に黒になっている場合です。 この場合、最適な解決策は単に他の次元を完成させることであり、カウントの 1 つがゼロであるため、アルゴリズムは自然に最小値を返します。 

最後のケースは、最適な中心が複数存在する場合です。 このアルゴリズムはすべてのセルを均一にスキャンし、最小値のみを追跡するため、特別なロジックを必要とせずに自然に同点を処理します。
