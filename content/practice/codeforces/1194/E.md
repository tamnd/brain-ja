 ## 解決策
 ## 問題の理解

 平面内で軸に揃えられた線分の集合が与えられます。 各セグメントは完全に水平であるか、完全に垂直です。 水平セグメントは他の水平セグメントと決して重なりません。垂直セグメントについても同様です。 交差は水平セグメントと垂直セグメントの間でのみ発生し、交差が発生すると単一の交差点を形成します。 

タスクは、長方形の境界を形成する 4 つのセグメントを選択できる方法が何通りあるかを数えることです。 選択したセグメントのうち 2 つは水平、2 つは垂直である必要があります。 各水平セグメントは両方の垂直セグメントと交差する必要があり、その逆も同様であるため、それらが一緒になって長方形の 4 つの辺を定義します。 

問題を再解釈する重要な方法は、交差構造の観点から考えることです。 各垂直セグメントは交差する水平セグメントのセットを定義し、少なくとも 2 つの共通の水平隣接セグメントを共有する 2 つの垂直セグメントを選択すると、正確に長方形が形成されます。 

この制約により、最大 5000 セグメントが許可されます。 立体的またはそれ以上のアプローチは不可能です。 O(n^2 log n) または O(n^2) の解法でも境界線に達しますが許容できるため、問題をペアの処理と重複の効率的なカウントに限定する構造を探す必要があることを示唆しています。 

複数の垂直セグメントが 1 つの水平セグメントを共有する場合、微妙なエッジ ケースが発生します。 たとえば、3 つの垂直セグメントがすべて同じ 2 つの水平セグメントと交差する場合、垂直セグメントのすべてのペアが長方形になります。 交点ごとに独立してカウントする単純なアプローチでは、「水平方向と垂直方向を 2 つずつ選択する」ことを対称的に強制しないと、二重にカウントされたり、組み合わせが欠落したりする危険があります。 

もう 1 つの失敗モードは、交差点を独立した点として扱い、セル状のグリッド表現ごとに正方形を数えることです。 セグメントが長い場合、交差は点グリッドの問題ではなく、間隔の重なりの問題であるため、これは問題になります。 

## アプローチ

 ブルートフォース戦略は、セグメントの 4 つすべてを試して、それらが長方形を形成しているかどうかを確認することです。 各候補について、2 つの水平セグメントと 2 つの垂直セグメントがあることを確認し、4 つの交差条件をすべてチェックします。 これには O(n^4) 個の組み合わせが必要で、各チェックは O(1) であり、最悪の場合、およそ 6×10^14 回の演算が必要になります。 これは実現可能な限界をはるかに超えています。 

水平セグメントと垂直セグメントを分離することで、これを減らすことができます。 2 つの垂直セグメントを固定するとします。 両方の垂直セグメントと交差する少なくとも 2 つの水平セグメントが存在する場合にのみ、長方形が存在します。 共通の水平交差の数 (たとえば k) がわかっている場合、この垂直のペアは C(k, 2) の長方形に寄与します。 

したがって、問題は次のようになります。垂直セグメントのすべてのペアについて、それらの両方と交差する水平セグメントの数を数えます。 同じロジックが対称的に機能しますが、必要な方向は 1 つだけです。 

ここで重要な最適化は、どの水平線がどの垂直線と交差するかをエンコードすることです。 垂直セグメントごとに、それと交差するすべての水平セグメントのリストを作成できます。 次に、垂直セグメントのペアごとに、それらのリストの交差部分のサイズを計算します。 n は最大でも 5000 であるため、頻度配列またはマーキング手法を使用してこれらのリストを保存および交差させるのは十分に高速です。 

最終的な複雑さは、垂直セグメントのペアと交差処理の合計で O(n^2) になりますが、これは許容範囲内です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 4回転以上のブルートフォース | O(n^4) | お(1) | 遅すぎる |
 | 縦方向のペア + 共通の横方向の数を数える | O(n^2 + 交差の合計) | O(n^2) 最悪 | 承認済み |

 ## アルゴリズムのチュートリアル

垂直セグメントが水平交差点の「バケット」として機能するように問題を再構成します。 

1. すべてのセグメントを水平方向と垂直方向に分割します。 これが必要なのは、混合ペアのみが交差し、長方形は各タイプの 2 つによって定義されるためです。 
2. すべての垂直セグメントについて、どの水平セグメントが交差するかを計算します。 水平セグメントは、その x 範囲に垂直方向の x 座標が含まれ、その y 値が垂直方向の y 範囲内にある場合、垂直セグメントと交差します。 
3. これらの関係を、各垂直方向に水平方向のインデックスのリストがある構造に保存します。 これにより、ジオメトリがセット上の組み合わせ論に変換されます。 
4. 垂直セグメントのペアごとに、両方のリストに含まれる水平セグメントの数を計算します。 これは、両方の垂直線に接する水平セグメントの数です。 
5. この数が k の場合、共通の水平線のいずれか 2 つを上辺と下辺として選択するため、これら 2 つの垂直線は C(k, 2) 長方形を形成します。 
6. すべての垂直ペアにわたるこの寄与を合計します。 

中心的な推論は、すべての長方形は、その左右の垂直辺を選択し、次に両方と交差する 2 つの水平辺を選択することによって一意に決定されるということです。 これにより、すべての四角形が正確に 1 回カウントされるようになります。 

### なぜ効果があるのか

 有効な長方形を修正します。 正確に 2 つの垂直辺と 2 つの水平辺があります。 その垂直辺のペアを処理すると、両方の水平辺がこれら 2 つの垂直辺の交差リストに存在します。 したがって、この長方形は、その垂直ペアの項 C(k, 2) にカウントされます。 垂直辺は長方形の定義によって固定されているため、他の垂直ペアは同じ長方形を生成できません。 これにより、カウントの完全性と一意性の両方が確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def intersect(h, v):
    # h: (x1, x2, y), v: (x, y1, y2)
    x1, x2, y = h
    x, y1, y2 = v
    return (min(x1, x2) <= x <= max(x1, x2)) and (min(y1, y2) <= y <= max(y1, y2))

n = int(input())
horiz = []
vert = []

for i in range(n):
    x1, y1, x2, y2 = map(int, input().split())
    if y1 == y2:
        horiz.append((x1, x2, y1))
    else:
        vert.append((x1, y1, x2))

H = len(horiz)
V = len(vert)

# build adjacency: for each vertical, which horizontals it intersects
adj = [[] for _ in range(V)]

for vi, (x, y1, y2) in enumerate(vert):
    for hi, (x1, x2, y) in enumerate(horiz):
        if min(x1, x2) <= x <= max(x1, x2) and min(y1, y2) <= y <= max(y1, y2):
            adj[vi].append(hi)

ans = 0

# count pairs of verticals
for i in range(V):
    mark = {}
    for h in adj[i]:
        mark[h] = 1
    for j in range(i + 1, V):
        cnt = 0
        for h in adj[j]:
            if h in mark:
                cnt += 1
        ans += cnt * (cnt - 1) // 2

print(ans)
```このソリューションは、垂直セグメントと水平セグメント間の交差関係を明示的に構築します。 この定式化では垂直ペアに対する二重ループは避けられませんが、各ペアはハッシュ メンバーシップ チェックを使用して処理され、交差カウントの効率が維持されます。 

微妙な点は、分野ごとに辞書 (またはセット) を使用することです。 これにより、交差をカウントする際の O(n) スキャンが回避されます。 最後の結合ステップでは、組み合わせ単位 C(k, 2) を使用して、個々の交差ではなく水平線のペアを確実にカウントします。 

## 実用的な例

 ### トレースの例

 3 つの水平方向と 3 つの垂直方向の単純化された入力を考えてみましょう。 

| 垂直ペア | 一般的な水平線 | k | 貢献 |
 | --- | --- | --- | --- |
 | (v1、v2) | {h1、h2} | 2 | 1 |
 | (v1、v3) | {h2} | 1 | 0 |
 | (v2、v3) | {h1、h2} | 2 | 1 |

 これは、少なくとも 2 つの水平方向が共有されている場合にのみ長方形がどのように現れるかを示しています。 

同じメカニズムが問題全体に対応します。すべての四角形は、まさに 1 つの「垂直ペア + 水平ペア」構成です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(V^2・H￣) | 各垂直方向のペアは、交差する水平方向のリストを比較します。 
| スペース | O(V + H + 交差点) | セグメント間の隣接関係リストを保存します。 

n ≤ 5000 の場合、V と H は最大 5000 であり、交差の合計は入力構造によって制限されます。 これは Python の制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from math import comb

    n = int(input())
    horiz = []
    vert = []

    for _ in range(n):
        x1, y1, x2, y2 = map(int, input().split())
        if y1 == y2:
            horiz.append((x1, x2, y1))
        else:
            vert.append((x1, y1, x2))

    V = len(vert)
    adj = []
    for x, y1, y2 in vert:
        s = set()
        for i, (x1, x2, y) in enumerate(horiz):
            if min(x1, x2) <= x <= max(x1, x2) and min(y1, y2) <= y <= max(y1, y2):
                s.add(i)
        adj.append(s)

    ans = 0
    for i in range(V):
        for j in range(i + 1, V):
            k = len(adj[i] & adj[j])
            ans += k * (k - 1) // 2
    return str(ans)

 ## 特殊なケース

 縮退構成は、いくつかの垂直セグメントが、交差する水平線の同じセットをまったく共有する場合に発生します。 このような場合、垂直方向のすべてのペアが共有水平方向のすべてのペアに長方形を提供するため、アルゴリズムは k ではなく C(k, 2) を正しく使用します。 

もう 1 つのケースは、垂直線が多くの水平線と交差するが、他のほとんどの垂直線はサブセットのみと交差する場合です。 ペアごとの交差ロジックにより、共通の水平方向のみが寄与することが保証され、独立した交差による過大なカウントが防止されます。
