 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$最初はすべてのエッジの値が 0 であるノード。任意の 2 つの異なるリーフ ノードを選択し、実数を加算する操作を実行できます。$x$これら 2 枚の葉を結ぶユニークなパスに沿ってすべての端まで。 この問題は、エッジへの実数の任意の割り当てについて、これらの演算の有限シーケンスを使用してその構成を実現できるかどうかを問うものです。 

ツリー入力は次のように指定されます。$n-1$接続するエッジ$n$ノード。 出力は、いずれかの構成が達成可能であれば単に「YES」となり、一部の構成に到達できない場合には「NO」となります。 

制約$2 \le n \le 10^5$あらゆる解は最大でも線形でなければならないことを意味します。$n$、$O(n)$または$O(n \log n)$、二次方程式のアプローチは大まかに実行されるため、$10^{10}$操作を続け、制限時間を超えます。 この問題では任意の実数が許可されるため、整数のオーバーフローは問題になりませんが、操作はリーフ間のパスにのみ影響するため、ツリー構造には微妙な制限が導入されます。 考えられるすべての葉のペアをシミュレートしようとする単純なアプローチでは、時間がかかりすぎて不必要になります。 

ノードの次数が 2 の場合、明白ではないエッジ ケースが発生します。3 つのノードのチェーンを考えてみましょう。$1-2-3$。 ノード 2 はリーフではなく、次数 2 を持ちます。リーフはノード 1 と 3 だけです。どの操作も、エッジを含む 1 から 3 までのパスに影響します。$1-2$そして$2-3$一緒に。 エッジを立てようとしたら$1-2$1とエッジへ$2-3$to 2, a single operation cannot achieve this because both edges change by the same amount. Therefore, the tree must not contain degree-2 internal nodes if arbitrary configurations are to be possible.

 ## アプローチ

 The brute-force approach would consider each pair of leaves, choose some value$x$、パス上のすべてのエッジを更新します。 適切なリーフ ペアを選択することで、各エッジを体系的に解決しようとすることもできますが、リーフ ペアの数は最大で$\binom{n}{2}$、 だいたい$5 \cdot 10^9$のために$n=10^5$。 これでは遅すぎて現実的ではありません。 

重要な観察は、すべての操作が 2 つのリーフを接続するパスに沿ったエッジを変更するということです。 ノードの次数がちょうど 2 の場合、ノードは 2 つのリーフを接続する 1 つのパス上に存在します。 このノードは独立して制御できないため、それに隣接するエッジに任意の独立した値を割り当てることはできません。 逆に、すべての内部ノードの次数が少なくとも 3 であるか、リーフである場合は、任意のエッジをリーフ間のパスの組み合わせとして表現できます。 これにより、必要なエッジ割り当てをリーフからリーフへのパスからの寄与に分解することで、すべてのエッジの値を「解決」することができます。 

言い換えれば、次数 2 の内部ノードが存在すると、隣接するエッジ間に線形依存関係が導入され、任意の割り当てが防止されます。 次数 2 の内部ノードがない場合、リーフ操作はすべてのエッジ割り当ての空間に広がり、あらゆる構成が実現可能です。 この洞察により、問題はノード次数の単純なチェックに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(L^2 * n) ここで、L = #leaves | O(n) | 遅すぎる |
 | 学位ベースのチェック | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノード数を読み取る$n$そしてのリスト$n-1$エッジ。 ツリーの隣接リスト表現を構築します。 これにより、効率的なトラバースと次数の計算が可能になります。 
2. サイズの配列を初期化します$n$各ノードの次数をカウントします。 すべてのエッジをトラバースし、両方のエンドポイントの次数カウントを増加します。 
3. 各ノードについて、それが内部ノード (次数 > 1) であり、次数が 2 であるかどうかを確認します。そのようなノードが存在する場合は、「NO」を出力して終了します。 これは、そのようなノードが独立して任意のエッジ値を持つことができないためです。 
4. 次数 2 内部ノードが存在しない場合は、「YES」を出力します。 その理由は、各内部ノードの次数が少なくとも 3 (独立した分解が可能) であるか、またはリーフであるため、すべてのエッジ値はリーフからリーフへのパスの加算の合計として表現できるということです。 

これが機能する理由: 不変条件は、ツリー内のすべてのエッジが葉から葉へのパスの一部として表現できるということです。 次数 2 の内部ノードは、どのような操作においても 2 つのエッジが常に同時に変化するように制約します。 次数 2 の内部ノードが存在しないことを保証することで、操作の組み合わせを通じてすべてのエッジが独立して制御可能であることが保証されます。 正確さは、実際の数値ではなく、純粋にツリーの組み合わせ構造に依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
degree = [0] * (n + 1)

for _ in range(n - 1):
    u, v = map(int, input().split())
    degree[u] += 1
    degree[v] += 1

for i in range(1, n + 1):
    if degree[i] == 2:
        print("NO")
        sys.exit(0)

print("YES")
```コードは、次を使用してノードとエッジの数を効率的に読み取ります。`sys.stdin.readline`。 各ノードの次数をカウントし、次数がちょうど 2 のノードは「NO」出力をトリガーします。 これにより、次数 2 の内部ノードが任意の構成を防止するという洞察が正しく実装されます。 次数 1 (葉) または次数 ≥ 3 のノードが受け入れられます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    degree = [0] * (n + 1)
    for _ in range(n - 1):
        u, v = map(int, input().split())
        degree[u] += 1
        degree[v] += 1
    for i in range(1, n + 1):
        if degree[i] == 2:
            return "NO"
    return "YES"

# Provided samples
assert run("2\n1 2\n") == "YES", "sample 1"
assert run("3\n1 2\n2 3\n") == "NO", "sample 2"

# Custom cases
assert run("4\n1 2\n1 3\n1 4\n") == "YES", "star tree"
assert run("5\n1 2\n2 3\n3 4\n4 5\n") == "NO", "chain of 5 nodes"
assert run("6\n1 2\n1 3\n2 4\n2 5\n3 6\n") == "YES", "binary tree"
assert run("3\n1 3\n2 3\n") == "YES", "triangle shaped with 1 degree-2 node as leaf"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 4ノードスター | はい | 中央ノードに接続された複数のリーフ |
 | 5 ノード チェーン | いいえ | 内部次数 2 ノードを持つチェーン |
 | 6 ノードのバイナリ ツリー | はい | バランスの取れた二分木、次数 2 の内部ノードなし |
 | 3 ノード「トライアングル」 | はい | 次数 2 のノードはリーフに隣接しており、有効です |

 ## 特殊なケース

 最小入力の場合$n=2$は両方のノードがリーフであるため、自然に処理されます。 長さ 3 以上のチェーンは失敗します。これは、次数 2 の内部ノードが独立したエッジの割り当てをブロックするためです。 1 つの中心ノードと複数の葉を持つ星型ツリーは、中心ノードの次数が 3 以上であるため、常に「YES」を出力します。 アルゴリズムは次数チェックを使用してこれらのケースを正しく区別します。
