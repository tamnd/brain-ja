 ## 解決策
 ## 問題の理解

 配列が与えられ、固定長のすべてのサブシーケンスを調べるように求められます。$k$。 選択した各サブシーケンスについて、その要素を精神的に並べ替え、すべてのペアごとの違いを調べます。 そのサブシーケンスの「美しさ」は、選択された 2 つの要素間の絶対差の最小値として定義されます。 

タスクは、サイズのすべての部分列にわたってこの美しさを合計することです$k$。 サブシーケンスの数が多いため、出力は剰余として取得されます。$998244353$。 

この問題を言い換えると、値のマルチセットを超えたサブシーケンスの構造には関心がないという便利な方法が得られます。 各サブシーケンスは、並べ替え後の最も近いペアによってのみ決定される値に寄与します。 

制約$n \le 1000$そして$a_i \le 10^5$3 次以上の複雑さの解決策をすぐに提案してください。$n$安全ではありません。 平$O(n^2 k)$は限界に近いため慎重な取り扱いが必要です。そのため、ソリューションでは、組み合わせカウントを繰り返し再計算するのではなく、事前計算と中間結果の再利用に依存する必要があります。 

すべてを列挙する素朴なアプローチ$\binom{n}{k}$サブシーケンスはすでに不可能です$n=1000, k=500$、これは指数関数的に増加するためです。 たとえサブシーケンスを修正してその美しさを計算したとしても$O(k \log k)$、列挙型が完全に優勢です。 

より微妙な障害モードは、答えが配列全体の最小値や最大値などのグローバル統計にのみ依存すると考えることから生まれます。 たとえば、入力では$[1, 100, 101, 102]$と$k=3$、異なるトリプルには含まれる要素に応じて異なる最小ギャップがあるため、寄与は大域的な極値だけによって決定されるわけではありません。 

主な問題は、最小差が完全な配列のプロパティではなく、選択された各サブセット内の最も近いペアのプロパティであることです。 

## アプローチ

 ブルートフォース手法では、サイズのすべてのサブセットが生成されます。$k$、それを並べ替え、隣接する差分を計算し、最小値を取得します。 これは正しいですが、根本的に実行不可能です。 がある$\binom{n}{k}$サブセット、さらには$n=30, k=15$これはすでに数百万に達しています。 と$n=1000$、それはまったく不可能です。 

構造上のブレークスルーは、最初に配列全体をソートすることで実現します。 一度並べ替えると、サブセットはその順序を継承します。 選択したサブセットの最小ペアごとの差は、サブセットのソート順にある 2 つの連続する要素間で発生する必要があります。 これは、答えがペアの合計として表現できることを意味します$(i, j)$、 どこ$i < j$、というイベントに対応します。$a_j - a_i$は、選択したサブセット内の最小ギャップになります。 

固定ペアの場合$(i, j)$、両方の要素が選択され、並べ替えられた順序でそれらの間から要素が選択されない場合、このペアはサブセットに寄与します。 要素があったとしたら$x$それらの間で、次にどちらか$a_j - a_x$または$a_x - a_i$よりも小さいでしょう$a_j - a_i$という仮定に違反します。$(i, j)$最小ギャップを定義します。 

したがって、問題を有効な数を数えるということに縮小します。$k$- サブセットには最も近いギャップとして特定のペアがあり、その差によって重み付けされます。$a_j - a_i$。 

残りのタスクは純粋に組み合わせです。要素を左側に分割します。$i$そしてその右側$j$、残りを分配します$k-2$それらの間で選択します。 

問題は、すべてのペアの合計には依然として内部関数が含まれることです。$O(k)$直接実行される場合は畳み込み。 最適化では、プレフィックスとサフィックスの選択用の組み合わせテーブルを事前計算し、集計されたサフィックスの合計を再利用して、各ペアが次の手順で処理されるようにします。$O(k)$ただし、内部寄与を繰り返し再計算する必要はありません。

 ## アルゴリズムのチュートリアル

 インデックスの順序が値の順序と一致するように配列を並べ替えます。 これにより、任意のサブセットではなく間隔についての推論が可能になります。 

二項係数を最大で事前計算します。$n$というのは、左右のセグメントから要素を選択する方法を繰り返し数えているからです。 

次に、2 つの DP テーブルを構築します。 最初のテーブル$L[i][t]$選択する方法の数を保存します$t$最初からの要素$i$要素。 2番目のテーブル$R[i][t]$選択する方法の数を保存します$t$で始まるサフィックスの要素$i$。 

これらのテーブルでは、固定ペアの両側の要素を選択できる方法が何通りあるかを数えることができます。 

ただし、各ペアは次の値に比例するため、右側から重みを組み込む必要もあります。$a_j$。 そのために、2 つのサフィックス集計テーブルを構築します。 

私たちは定義します$Q[i][t]$選択方法の数として$t$で始まるサフィックスの要素$i$、 そして$P[i][t]$選択数によって重み付けされた、その接尾辞内の最も左にある選択された要素の値の合計として。 具体的にはポジションごとに$p$、その値に、サフィックスから残りの要素を選択する方法の数を乗じた値を追加します。$p$。 

この変換により、正しいエンドポイントのすべての寄与を状態ごとに一定時間で表現できるようになります。 

ここで、考えられるすべての左側のエンドポイントを反復処理します。$i$。 それぞれについて$i$、要素の数を繰り返します。$l$左側から選ばれます。 残り$r = k-2-l$右側から来なければなりません。 

各構成について、貢献度は 2 つの部分に分割されます。$a_j$有効な右端点よりマイナス$a_i$有効な右エンドポイントの数を掛けます。 これらはまさにそれです$P[i+1][r]$そして$Q[i+1][r]$代表する。 

最後に、次を掛けます。$L[i-1][l]$、左側を選択し、累積する方法の数。 

### なぜ効果があるのか

 すべての有効なサブセットには、最小ギャップを達成する並べ替えられた順序で隣接する要素の一意のペアがあります。 アルゴリズムは、そのような各ペアを 1 回だけカウントします。 組み合わせ分解により、固定の最小ギャップ ペアと一致するすべてのサブセットがカウントされ、中間要素が厳密にギャップを削減するため、真の最小ギャップではないペアのサブセットはカウントされません。 これにより、サブセットとその美しさの原因となる寄与ペアとの間に全単射が生じます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    # binomial coefficients
    C = [[0] * (n + 1) for _ in range(n + 1)]
    for i in range(n + 1):
        C[i][0] = 1
        for j in range(1, i + 1):
            C[i][j] = (C[i - 1][j] + C[i - 1][j - 1]) % MOD

    # L[i][t] = ways to pick t from first i elements
    L = [[0] * (k + 1) for _ in range(n + 1)]
    L[0][0] = 1
    for i in range(1, n + 1):
        for t in range(k + 1):
            L[i][t] = L[i - 1][t]
            if t > 0:
                L[i][t] = (L[i][t] + L[i - 1][t - 1]) % MOD

    # Q[i][t] = ways to choose t from suffix i
    Q = [[0] * (k + 1) for _ in range(n + 2)]
    # P[i][t] = weighted sum of contributions from suffix i
    P = [[0] * (k + 1) for _ in range(n + 2)]

    for i in range(n, 0, -1):
        for t in range(k + 1):
            Q[i][t] = Q[i + 1][t]
            P[i][t] = P[i + 1][t]

        for t in range(k + 1):
            if t == 0:
                Q[i][t] = (Q[i][t] + 1) % MOD
            else:
                Q[i][t] = (Q[i][t] + Q[i + 1][t - 1]) % MOD
                P[i][t] = (P[i][t] + P[i + 1][t - 1] + a[i - 1] * Q[i + 1][t - 1]) % MOD

    ans = 0

    for i in range(1, n + 1):
        for l in range(k - 1):
            r = k - 2 - l
            if r < 0:
                continue

            left = L[i - 1][l]
            right_sum = P[i + 1][r]
            right_cnt = Q[i + 1][r]

            ans += left * (right_sum - a[i - 1] * right_cnt) * (n >= 0)
            ans %= MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```解決策は並べ替えから始まります。最小ギャップに関するすべての推論は順序付けに依存しているため、並べ替えは不可欠です。 DP テーブル$L$選択したインデックスの前に要素を選択できる方法が何通りあるかをキャプチャします。$Q$そして$P$すべての有効な選択を、重み付けされた寄与とともに右側に要約します。 

最もデリケートな部分はメンテナンスです$P$そして$Q$同時に。$Q$組み合わせを数えますが、$P$値の寄与を有効なペアの潜在的な正しいエンドポイントとして蓄積します。 繰り返しにより、すべてのサフィックス構成が正確に 1 回カウントされるようになります。

 ## 特殊なケース

 重要なエッジケースは、すべての値が同一である場合です。 その状況では、すべてのペアの差がゼロであるため、すべてのサブセットの美しさはゼロになります。 アルゴリズムは、各項以降、ゼロを正しく累積します。$a_j - a_i$組み合わせに関係なくゼロにキャンセルされます。 

もう 1 つのエッジケースは次のような場合です$k=2$。 すべてのサブセットは単なるペアであるため、答えはすべてのペアごとの差の合計になります。 内部要素がなく、すべてのペアが同じ式を通じて 1 回だけ寄与し、予想される単純化と一致するため、DP は正しく折りたたまれます。
