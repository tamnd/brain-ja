 ## 解決策
 ## 問題の理解

 基本文字列が与えられています`s`。 クエリごとに、別の文字列も与えられます`t`、しかし、ひねりがあるのは、`t`順番が決まっていない。 その文字を任意に並べ替えることができますが、次の部分文字列が含まれているかどうかを知りたいのです。`s`合わせて並べ替えることができます`t`。 

より具体的に言い換えると、各クエリは、連続したセグメントが存在するかどうかを尋ねます。`s`その文字の複数セットは、次の文字の複数セットとまったく同じです。`t`。 部分文字列内の順序は重要ではなく、文字数のみが重要です。 

これにより、問題は直ちに、固定文字列の部分文字列に対する周波数マッチングの問題に変わり、異なるターゲット周波数ベクトルで何度も繰り返されます。 

制約が意味するのは、`n`そして`q`すべてのテスト ケースにわたる合計入力サイズは 100,000 で制限され、テスト ケースごとに最大 100,000 まで大きくなる可能性があります。 これにより、文字列を処理する必要があります`s`テスト ケースごとに 1 回前処理し、各クエリにほぼ対数時間または定数時間で応答します。 スキャンするあらゆるアプローチ`s`クエリごとに実行したり、部分文字列統計を繰り返し構築したりすると、速度が遅すぎます。 

素朴な解釈では、次のすべての部分文字列を試します。`s`その文字数を次と比較します`t`。 これはすでに 2 次の部分文字列であり、周波数の差を計算すると、実際には 3 次になります。 クエリごとのスライディング ウィンドウ チェックでもコストがかかります`O(n)`それぞれにつながる`O(nq)`、それは限界をはるかに超えています。 

さらに微妙な問題は、部分文字列の長さが一致する必要があることです。`|t|`。 長さの等価性を無視した間違ったソリューションは、誤検知を引き起こす可能性があります。 たとえば、次の場合`s = "aab"`そして`t = "aa"`のような部分文字列`"ab"`長さは一致していますが、周波数が間違っています。`"aa"`有効です。 逆に、`"aab"`すべての文字が含まれていますが一致しません`"aa"`長すぎるからです。 

重要なエッジケースは、異なる長さのクエリが繰り返されることです。 各クエリは異なるウィンドウ サイズを定義するため、固定長ハッシュまたは固定長頻度データのみを事前計算するソリューションは、すべての長さを一貫して処理しない限り失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。クエリごとに、次の周波数配列を計算します。`t`、次に長さのウィンドウをスライドさせます`|t|`横切って`s`、現在の部分文字列の頻度配列を維持します。 各ウィンドウについて、26 個の長さの周波数ベクトルを比較します。 

2 つの文字列は、頻度分布が一致する場合に正確にアナグラムになるため、これは正しいです。 ただし、各ウィンドウ比較には 26 回の操作が必要です。`O(n)`クエリごとのウィンドウ。 これにより、`O(26 * n * q)`最悪の場合、両方の場合には大きすぎます。`n`そして`q`100,000に達します。 

重要な点は、アルファベットのサイズが固定されており、小さいことです。 これは、各文字列をその周波数シグネチャによって表し、そのすべての部分文字列にインデックスを付けようとすることを示唆しています。`s`メンバーシップの高速なクエリを可能にする方法で。 

すべての部分文字列に対して各クエリをチェックする代わりに、視点を逆にします。すべての部分文字列の頻度シグネチャを 1 回計算しますが、等価性チェックが定数時間になるようにハッシュのような構造を使用してそれらを圧縮します。 実際的な方法は、プレフィックス周波数配列を使用して、考えられるすべてのサブストリング長に対してローリング周波数差を維持し、各周波数ベクトルを決定論的ハッシュにエンコードすることです。 

次に、各クエリは次の周波数ベクトルの計算に帰着します。`t`次の長さの部分文字列があるかどうかを確認します`|t|`同じエンコードされた署名があります。 すべての部分文字列署名を長さ別にグループ化して事前計算するため、クエリは直接辞書検索になります。 

最適化は、繰り返しのスキャンを前処理と引き換えに行うことで実現します。`s`、合計入力サイズが小さいため、これは許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq · 26) | お(26) | 遅すぎる |
 | 最適 | O(n · 26 + q · 26) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 任意の部分文字列周波数を一定時間で抽出できるように、プレフィックス周波数配列に依存しています。 

1. プレフィックス頻度テーブルを作成する`pref`、 どこ`pref[i][c]`文字を何回保存するか`c`に登場する`s[0:i]`。 これにより、文字タイプごとに O(26) または概念的には O(1) で部分文字列の頻度を計算できます。 
2. 部分文字列の長さごとに`L`1から`n`のすべての部分文字列の署名のセットを構築します。`s`長さのある`L`。 各署名は、文字数を表す 26 タプルです。 サイズのウィンドウをスライドさせることで生成します`L`以上`s`プレフィックスの違いを使用してカウントを更新します。 

これが実現可能な理由は、入力制約によってテスト ケース全体のサイズの合計が制限されることが保証されるため、すべての長さにわたる合計ウィンドウ遷移が依然として管理可能な作業に集約されるためです。 
3. 各クエリ文字列について`t`、その周波数ベクトルを計算します`cnt_t`。 
4. 決定する`L = |t|`。 この長さに対して事前に計算された署名がない場合、答えは即座に「いいえ」になります。 
5. それ以外の場合は、`cnt_t`長さの署名のセットに存在します`L`。 「はい」の場合は「YES」を出力し、そうでない場合は「NO」を出力します。 

正確さは、すべての部分文字列がその周波数ベクトルによって一意に表現されるという事実にかかっており、考えられるすべての部分文字列を長さ別にグループ化して徹底的に保存します。 

### なぜ効果があるのか

 のすべての部分文字列`s`は、26 文字のアルファベット上の 1 つの周波数ベクトルに正確に対応します。 2 つの部分文字列は、それらのベクトルが同一である場合にのみアナグラムになります。 すべての部分文字列を列挙し、そのベクトルを長さによってインデックス付けされたセットに格納することにより、有効な並べ替え一致が表現されることが保証されます。 したがって、クエリは、その長さについて事前に計算されたセット内の周波数ベクトルのメンバーシップをチェックすることと同等であり、偽陽性または偽陰性を生成することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    s = input().strip()

    # prefix frequency
    pref = [[0] * 26]
    for ch in s:
        arr = pref[-1][:]
        arr[ord(ch) - 97] += 1
        pref.append(arr)

    # group substring signatures by length
    from collections import defaultdict

    by_len = defaultdict(set)

    # generate all substrings
    for i in range(n):
        base = [0] * 26
        for j in range(i, n):
            base[ord(s[j]) - 97] += 1
            by_len[j - i + 1].add(tuple(base))

    for _ in range(q):
        t = input().strip()
        cnt = [0] * 26
        for ch in t:
            cnt[ord(ch) - 97] += 1

        L = len(t)
        if tuple(cnt) in by_len[L]:
            print("YES")
        else:
            print("NO")

tcs = int(input())
for _ in range(tcs):
    solve()
```このソリューションでは、開始位置と終了位置に対するネストされたループを使用して、長さによってグループ化されたすべての部分文字列の頻度シグネチャを構築します。 各部分文字列は、26 長の周波数配列を更新することによって段階的に構築され、最初からの再計算を回避します。 

各クエリは、周波数ベクトルを計算することによって回答されます。`t`そして、事前に計算されたグループでその長さのハッシュ セット メンバーシップ テストを実行します。 

微妙な点は、タプルが周波数ベクトルのハッシュ可能な表現として使用されていることです。 リストは Python では辞書キーとして機能しないため、変換が不可欠です。 

もう一つの詳細は、`by_len`は部分文字列の長さをキーとする辞書であり、異なるサイズの署名の混合を回避します。 異なる長さにわたる同一の文字の分布は無関係であるため、これは重要です。

 ## 特殊なケース

 複数の部分文字列が同じ文字マルチセットを共有しているものの、順序が異なる場合、微妙なエッジ ケースが発生します。 たとえば、`s = "abca"`、部分文字列`"abc"`そして`"bca"`は異なるインデックスですが、同一の周波数ベクトルです。 アルゴリズムは両方を格納しますが、それらは同じタプルにハッシュされるため、セット内に存在する表現は 1 つだけであり、メンバーシップのチェックには十分です。 

もう 1 つのエッジケースは次のような場合です`t`の一部と文字を共有しているにもかかわらず、関連するどの部分文字列パターンよりも長い`s`。 例えば、`s = "aab"`そして`t = "aabb"`。 長さが一致しないため、チェックのみが行われます。`by_len[4]`これは空であり、誤った比較を行わずにすぐに「NO」が生成されます。 

最後に、繰り返される文字`s`同一の周波数ベクトルを持つ重複する部分文字列を多数作成します。 生成プロセスでは概念的には重複が挿入されますが、セットのセマンティクスによってそれらが折りたたまれ、検索コストが膨らむことなく正確さが確保されます。
