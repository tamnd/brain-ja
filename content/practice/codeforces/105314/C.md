 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースは、固定された順序で配置された一連の項目を記述します。 すべてのアイテムには ID と色があります。 

このシーケンスから、元の順序を維持しながら項目のサブシーケンスを選択したいと考えています。 選択されたサブシーケンスは 2 つの条件を満たさなければなりません。 まず、選択した項目の ID は、サブシーケンスに沿って進むにつれて厳密に増加する必要があります。 第 2 に、選択された 2 つの連続した項目がサブシーケンス内で隣り合っている場合は常に、それらの色は異なっていなければなりません。 

各テスト ケースのタスクは、そのような有効なサブシーケンスの可能な最大長を決定することです。 

サブシーケンスは元の順序に従わなければならないという制約により、項目を並べ替えたり並べ替えたりするという考えは即座に排除されます。 どのような選択でも位置を尊重する必要があるため、インデックスよりも動的プログラミングを推進することになります。 

すべてのテスト ケースで合計最大 10^5 個の項目がある場合、すべての要素の前の位置をすべてチェックする O(n^2) アプローチは存続できません。 この種のソリューションでは、最悪の場合でも約 10^10 の遷移が実行されますが、これは許容される 2 秒の制限をはるかに超えています。 したがって、各項目を対数またはほぼ一定の償却時間で処理する方法が必要です。 

複数のアイテムが同じ ID または色を共有する場合、微妙なエッジケースが発生します。 

たとえば、ID は厳密に増加しますが、色は交互になると考えてください。 

入力:```
1
5
1 2 3 4 5
1 1 1 1 1
```IDが増えても同じ色で2つ連続で配置できないので正解は1です。 

別の失敗例は、色が完全に交互になっているにもかかわらず、ID によって連鎖が妨げられている場合です。 

入力:```
1
4
1 3 2 4
1 2 3 4
```色を変更することはできますが、ID 順序の制約により、すべての項目を有効な ID の増加サブシーケンスに含めることができません。 

これらの例は、どちらの制約も独立して最適化できないことを示しています。 両方を同時に施行する必要があります。 

## アプローチ

 直接的なアプローチは、考えられるすべてのサブシーケンスを試すことです。 各ポジションについて、以前のすべてのポジションを確認した後、それを含めるかどうかを決定します。 これは、各インデックスで終了する最適な有効なサブシーケンスを計算する古典的な動的プログラミングの定式化につながります。 トランジションでは、より小さい ID と異なる色の以前のすべてのインデックスが試行されます。 これは正しいですが、すべての位置について以前のすべての要素をスキャンする必要があるため、二次的な複雑さが生じます。 

ボトルネックは、最適な互換性のある前任者を繰り返し検索することです。 問題の構造は、2 つの独立した制約を示唆しています。1 つは ID の順序に関するもので、もう 1 つは色の隣接に関するものです。 ID 制約は標準の「値によるプレフィックス最大値」タイプの条件であり、通常は圧縮 ID に対するフェンウィック ツリーまたはセグメント ツリーで処理されます。 同じ色からの遷移を除外する必要があるため、色の制約により問題が複雑になります。 

重要な考え方は、位置順に処理されるアイテムのプレフィックスごとに 2 つの情報を維持することです。 しきい値を下回る ID を持つすべての有効な候補について最適なサブシーケンス長を維持し、同じ ID 範囲内の色ごとの最適な値も追跡します。 新しいアイテムの遷移を計算するとき、全体的に最良のものを採用し、そのアイテム自体の色からの無効な寄与を差し引きます。 

ID によるプレフィックス クエリと更新の両方を効率的にサポートするために、圧縮 ID 上でセグメント ツリー (またはフェンウィック ツリー) を使用します。 各ノードは、その ID 範囲の最適な DP 値を保存します。 これに加えて、同じ ID 制限の下でその色についてこれまでに確認された最良の DP 値を追跡する色ごとの構造も維持します。 これら 2 つの構造を組み合わせることで、要素ごとに有効な遷移を対数時間で計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DP | O(n^2) | O(n) | 遅すぎる |
 | セグメント ツリー + カラー トラッキング | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 アイテムを指定された順序で処理し、そのアイテムで終了する最も有効なサブシーケンスを表す各アイテムの DP 値を維持します。 

1. すべての ID を圧縮して、連続した範囲に収まるようにします。 これにより、それらをセグメント ツリーのインデックスとして使用できるようになります。 
2. ID 値を使用してセグメント ツリーを初期化します。 ツリー内の各位置には、その位置に対応する ID を持つ項目で終わるサブシーケンスの最大 DP 値が格納されます。 
3. 処理されたすべてのアイテムの中でこれまでに確認された最良の DP 値を色ごとに保存するハッシュ マップまたは辞書を維持します。 この値は、ID 制約に関係なく、その色で終わる最適なサブシーケンスを表します。 
4. 順番に項目ごとに、その項目で終わる最適なサブシーケンスを次のように計算します。 まず、現在のアイテムの ID より厳密に小さいすべての ID にわたる最大 DP 値をセグメント ツリーにクエリします。 これにより、ID 制約のみに基づいて拡張できる最良のサブシーケンスが得られます。 
5. 前のステップで取得した最良のサブシーケンスが現在のアイテムと同じ色で終了する場合、それを直接拡張することはできません。 その場合は、その使用を避け、代わりに次に最適な有効なオプションに依存する必要があります。 これは、カラー マップをチェックし、同じ色の寄与を再利用しないようにすることで処理されます。 
6. DP[i] を 1 に取得した最良の有効な値を加えた値に設定します。 これは、現在の項目をサブシーケンスの最後の要素として選択することを意味します。 
7. 現在の ID の位置にあるセグメント ツリーを DP[i] で更新し、格納されている値が改善される場合は、現在の色のカラー マップを DP[i] で更新します。 

### なぜ効果があるのか

すべてのステップで、セグメント ツリーには、現在の ID よりも小さい有効な ID で終わる、達成可能な最良のサブシーケンスが保存されます。 これにより、すべての拡張機能が厳密に増加する ID 制約を遵守することが保証されます。 カラー マップにより、サブシーケンスの拡張を検討するときに、隣接するカラー条件に違反する遷移を特定して除外できるようになります。 すべての DP 状態は以前に有効な状態からのみ構築され、両方の制約の下ですべての有効な先行状態を常に考慮するため、最適なサブシーケンスが失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        vals = sorted(set(a))
        comp = {v: i+1 for i, v in enumerate(vals)}
        m = len(vals)

        seg = [0] * (4 * m)
        dp = [0] * n
        best_color = {}

        def update(node, l, r, idx, val):
            if l == r:
                seg[node] = max(seg[node], val)
                return
            mid = (l + r) // 2
            if idx <= mid:
                update(node * 2, l, mid, idx, val)
            else:
                update(node * 2 + 1, mid + 1, r, idx, val)
            seg[node] = max(seg[node * 2], seg[node * 2 + 1])

        def query(node, l, r, ql, qr):
            if ql > r or qr < l:
                return 0
            if ql <= l and r <= qr:
                return seg[node]
            mid = (l + r) // 2
            return max(
                query(node * 2, l, mid, ql, qr),
                query(node * 2 + 1, mid + 1, r, ql, qr)
            )

        for i in range(n):
            ci = comp[a[i]]

            best = 0
            if ci > 1:
                best = query(1, 1, m, 1, ci - 1)

            cand = best

            if b[i] in best_color:
                cand = max(cand, best_color[b[i]])

            dp[i] = cand + 1

            update(1, 1, m, ci, dp[i])

            if b[i] not in best_color or best_color[b[i]] < dp[i]:
                best_color[b[i]] = dp[i]

        print(max(dp))

if __name__ == "__main__":
    solve()
```このソリューションは ID を圧縮して、セグメント ツリー操作の効率を維持します。 セグメント ツリーは、すべての小さい ID の中で達成可能な最良の DP 値を取得するために使用されます。 辞書は色ごとに最適なサブシーケンスを追跡するため、2 つの同じ色が連続して配置される無効な遷移を回避できます。 

DP の計算は左から右に行われ、各項目の処理時に必要なすべての状態がすでに利用可能であることが保証されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各項目はセグメント ツリー クエリを実行し、圧縮 ID を更新します。 
| スペース | O(n) | セグメント ツリー、DP 配列、およびカラー マップのストレージ |

 すべてのテスト ケースにわたる操作の合計数は項目数において線形であり、セグメント ツリーにより各操作は対数になります。 n が最大 10^5 であれば、これは制限内に問題なく収まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        vals = sorted(set(a))
        comp = {v: i+1 for i, v in enumerate(vals)}
        m = len(vals)

        seg = [0] * (4 * m)
        dp = [0] * n
        best_color = {}

        def update(node, l, r, idx, val):
            if l == r:
                seg[node] = max(seg[node], val)
                return
            mid = (l + r) // 2
            if idx <= mid:
                update(node * 2, l, mid, idx, val)
            else:
                update(node * 2 + 1, mid + 1, r, idx, val)
            seg[node] = max(seg[node * 2], seg[node * 2 + 1])

        def query(node, l, r, ql, qr):
            if ql > r or qr < l:
                return 0
            if ql <= l and r <= qr:
                return seg[node]
            mid = (l + r) // 2
            return max(
                query(node * 2, l, mid, ql, qr),
                query(node * 2 + 1, mid + 1, r, ql, qr)
            )

        for i in range(n):
            ci = comp[a[i]]
            best = 0
            if ci > 1:
                best = query(1, 1, m, 1, ci - 1)

            cand = best
            if b[i] in best_color:
                cand = max(cand, best_color[b[i]])

            dp[i] = cand + 1
            update(1, 1, m, ci, dp[i])

            best_color[b[i]] = max(best_color.get(b[i], 0), dp[i])

        out.append(str(max(dp)))

    return "\n".join(out)

 ## 特殊なケース

 すべてのアイテムが同じ色を共有するケースは、カラー マップにより、その色を使用する拡張が単一の要素チェーンを超えることができないことが保証されるため、アルゴリズムが 2 つの同じ色をチェーンすることがないことを示しています。 

入力：```
1
4
1 2 3 4
7 7 7 7
```セグメント ツリーは常に ID ごとに増加する DP 値を返しますが、カラー マップはすべての遷移で単一要素のサブシーケンスのみを考慮するように強制します。 結果は 1 のままです。 

ID が減少するケースでは、座標圧縮だけで順序付けを処理できるかどうかをテストします。 

入力:```
1
5
5 4 3 2 1
1 2 3 4 5
```ID の昇順を満たすペアはないため、すべての DP は 1 のままです。セグメント ツリーは意味のあるプレフィックスを返すことはなく、逆入力での正しさを確認します。
