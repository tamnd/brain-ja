 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースには項目の配列があります。 各項目には 2 つの属性があります: 値`a[i]`そして重みのようなパラメータ`b[i]`。 注文した商品のペアごとに`(i, j)`、それらのビット単位の OR に依存する寄与を定義します。`a`値を乗算する`b[j]`。 タスクは、すべての固定値を計算することです。`i`、全体に対する合計貢献度`j`。 

したがって、各インデックスについて`i`、式を評価する必要があります$$\sum_{j=1}^{n} (a_i \,|\, a_j)\cdot b_j$$そしてそれを出力します。 

重要な問題は、式が非対称であることです。`i`そして`j`なぜなら乗数は`b[j]`、 ない`b[i]`。 これは、計算を慎重に再構成しない限り、対称行列を事前計算したり、ペアの寄与を直接再利用したりすることができないことを意味します。 

この制約により、私たちは二次推論から遠ざけられます。 合計`n`すべてのテスト ケースにわたって 1e6 に達する可能性があるため、すべてのペアを明示的に検査しようとするアプローチであっても失敗します。 単純な二重ループでできることは、$10^{12}$最悪の場合、1 秒の制限をはるかに超える操作が行われなくなります。 

微妙なエッジケースは、ビットごとの OR 構造から生じます。 価値観は自分次第だから$2^{15}$、すべての動作は 15 ビットに制限されます。 これは、解が数値を不透明な整数として扱うのではなく、ビットごとの分解を利用する必要があるというヒントです。 

よくある間違いは、次のプレフィックスの合計のようなものを事前計算しようとすることです。`a`または`b`独立して。 OR は加算的ではなく、線形構造を維持する方法で合計を分配しないため、これは失敗します。 

## アプローチ

 ブルート フォース ソリューションでは、定義が直接評価されます。 あらゆる人にとって`i`、すべてループします`j`、計算します`(a[i] | a[j]) * b[j]`、それを蓄積していきます。 これは定義に文字通り従っているため、正しいです。 問題はパフォーマンスです。 と`n`まで$2 \cdot 10^5$、各テスト ケースにはすでに必要があります$4 \cdot 10^{10}$最悪の場合は操作が可能になり、テストケース全体でこれは実行不可能になります。 

重要な構造観察は、ビット レベルでの OR の拡張から得られます。 各ビット位置について、`(a[i] | a[j])`いずれかに設定されている場合、そのビットに寄与します。`a[i]`または`a[j]`。 これは、合計をビットごとの寄与に分割することを示唆しています。 すべてのペアの OR を再計算する代わりに、各ビットが何回出現するかを数えることができます。`a[j]`で重み付けされる`b[j]`、ビットが既に存在するかどうかを個別に処理します。`a[i]`。 

固定ビットの場合`k`、このビットの貢献`(a[i] | a[j])`は:

 - いつも`2^k`噛まれたら`k`に設定されています`a[i]`- さもないと`2^k`噛まれたら`k`に設定されています`a[j]`これにより、問題が事前計算可能なグローバル統計に分割されます。`j`。 

ビットごとに事前計算します`k`、すべての合計`b[j]`どこ`a[j]`そのビットが設定されています。 これにより、2 番目のケースの寄与を迅速に評価できるようになります。 最初のケースは以下にのみ依存します。`i`そしてすべての合計`b[j]`。 

したがって、それぞれについて`i`、以下を組み合わせます。 

- すでに存在するビット`a[i]`の全額を寄付します`b[j]`そのようなビットごとに
 - ビットが欠落しています`a[i]`のサブセットのみに貢献します`b[j]`そのビットが存在する場所`a[j]`これにより、各テスト ケースが O(n * B) に縮小されます (B は 15)。

 ## アルゴリズムのチュートリアル

 1. すべての合計を事前計算します。`b[j]`。 すべてのペアがあるため、これはすべてのインデックスで再利用されます。`(i, j)`含まれています`b[j]`全く同じ方法で。 
2. 各ビット位置について`k`0から14まで、計算します`sum_bit[k]`、すべての合計`b[j]`k番目のビットが`a[j]`が設定されています。 これにより、各ビットがすべてのアイテムにどれだけの重みを与えているかが分離されます。 
3. インデックスごとに`i`、答えをゼロとして初期化します。 
4. 各ビットについて`k`、ビットかどうかを確認します`k`に設定されています`a[i]`。 設定されている場合は、`(a[i] | a[j])`に関係なく、常にこのビットが存在します`a[j]`、だからすべての`b[j]`貢献します。 したがって、追加します`2^k * total_b`。 
5.ビットの場合`k`に設定されていません`a[i]`の場合、OR はそれらからこのビットのみを取得します。`j`どこ`a[j]`すでに持っています。 この場合、追加します`2^k * sum_bit[k]`。 
6. それぞれの計算値を出力します。`i`。 

正確さは、各ビットを独立して処理し、次の値で重み付けされた独立したバイナリ寄与の合計として OR を再構築するかどうかにかかっています。`b[j]`。 

### なぜ効果があるのか

 OR 演算は、位置ごとのビット単位の最大値を取ることと同じです。 各ビットは最終値に独立して寄与し、その寄与はそれがいずれかのオペランドに現れるかどうかによってのみ決まります。 を乗算するので、`b[j]`ビットの独立性を妨げないため、合計をビット全体に再分配できます。 各ビット、すべてのペアについて`(i, j)`常にそのビットを提供するか、またはのみに基づいて条件付きでそのビットを提供します。`a[j]`。 これにより、異なる間の依存関係が削除されます。`j`値を確認し、線形集計が有効であることを確認します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        total_b = sum(b)
        
        sum_bit = [0] * 15
        
        for i in range(n):
            x = a[i]
            bi = b[i]
            bit = 0
            while x:
                if x & 1:
                    sum_bit[bit] += bi
                x >>= 1
                bit += 1
        
        res = [0] * n
        
        for i in range(n):
            ai = a[i]
            ans = 0
            for k in range(15):
                if ai & (1 << k):
                    ans += (1 << k) * total_b
                else:
                    ans += (1 << k) * sum_bit[k]
            res[i] = ans
        
        print(*res)

if __name__ == "__main__":
    solve()
```この実装では、前処理がクエリの構築から分離されます。 の`sum_bit`配列は、すべてのビットの重み付けされた寄与を累積します。`j`。 2 番目のループでは、ビットの存在をチェックして各応答を構築します。`a[i]`。 

微妙な点は、OR を直接再計算することは決してないということです。 あらゆる出来事が起こる`(a[i] | a[j])`は独立したビット寄与の合計に置き換えられ、二次の複雑さが完全に回避されます。

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        total_b = sum(b)
        sum_bit = [0] * 15
        
        for i in range(n):
            x = a[i]
            bi = b[i]
            bit = 0
            while x:
                if x & 1:
                    sum_bit[bit] += bi
                x >>= 1
                bit += 1
        
        res = []
        for i in range(n):
            ans = 0
            for k in range(15):
                if a[i] & (1 << k):
                    ans += (1 << k) * total_b
                else:
                    ans += (1 << k) * sum_bit[k]
            res.append(ans)
        print(*res)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as sio
    out = sio.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

 ## 特殊なケース

 単一要素の配列の場合、式は次のようになります。`(a[i] | a[i]) * b[i]`、つまり`a[i] * b[i]`。 アルゴリズムはこれを処理します。`total_b = b[i]`そして`sum_bit`その要素のビットのみをカウントするため、設定されたすべてのビットが正確に寄与します`bit * b[i]`。 

入力の場合、すべて`a[i]`同じ価値観を共有する`sum_bit[k]`どちらかが等しい`total_b`そのビットが設定されているかどうかに応じて、またはゼロになります。 その後、各インデックスは同一の寄与を受け取り、アルゴリズムは定数配列を正しく生成します。 

値に互いに素なビットがある場合、それぞれの値は`sum_bit[k]`インデックスの互いに素なサブセットを集計します。 各ビットが独立して処理されるため、アルゴリズムはこれらの寄与を明確に分離し、無関係なビット間の干渉が発生しないようにします。
