 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、$n$間隔。 それぞれのインターバルから$[l_i, r_i]$、整数を 1 つだけ選択する必要があります$x_i$。 すべての選択を行った後、選択したすべての値の合計を計算します。 目標は、異なる選択の数が次の値で割り切れる合計額を生成するかどうかを数えることです。$k$。 答えはモジュロで計算する必要があります$10^9 + 7$。 

選択は間隔ごとに 1 つの値を選択することによって完全に決定されるため、問題は合計に対するモジュラー制約の下で有効な組み合わせをカウントすることです。 重要な問題は、各間隔が複数の可能な値に寄与することであり、これらの選択が合計モジュロにどのような影響を与えるかを考慮する必要があることです。$k$、正確な合計ではありません。 

制約は非常に特殊な点で厳しいです。 すべてのテスト ケースにわたる間隔の数は最大で$2 \cdot 10^5$したがって、テスト ケースごとに一定時間または対数時間を超えて各間隔を処理するメソッドは失敗する可能性があります。 の値$k$は非常に小さく、最大でも 10 です。これは、問題の状態が剰余モジュロに圧縮できることを強く示唆しています。$k$。 これにより、正確な合計を追跡したり、すべての組み合わせを列挙したりするアプローチは即座に排除されます。 

素朴なアプローチは、各間隔ですべての選択肢を試して合計を計算することです。 間隔サイズを事前に計算したとしても、各間隔には最大で$10^9$値なので列挙することは不可能です。 もう 1 つの素朴なアイデアは、すべての合計に対して DP を維持することですが、合計は最大で$2 \cdot 10^{14}$、これも実行不可能です。 

間隔が大きいにもかかわらずモジュロで均一に動作する場合、より微妙なエッジ ケースが表示されます。$k$。 たとえば、次の場合$k = 2$、次のような間隔$[1, 10^9]$剰余頻度を注意深く数えない限り、自明な方法で均等に分布することはできません。 境界で部分的なサイクルを処理せずに一様な分布を仮定するソリューションでは、不正確なカウントが生成されます。 

## アプローチ

 ブルートフォースの観点は、間隔を 1 つずつ処理することによって答えを構築し、各間隔について考えられるすべての値を試し、累計を更新し、最終的に次の値で割り切れるかどうかを確認することです。$k$。 これは問題の定義を直接モデル化しているため、概念的には正しいですが、天文学的に大きな間隔サイズの積に拡張されます。 

最初の単純化は、モジュロのみを評価するという観察から生じます。$k$最終条件が重要です。 実際の整数を気にする代わりに、区間が各剰余クラスにどのように寄与するかを知ることだけが必要です。$0$を通して$k-1$。 それが分かると、各区間は剰余全体にわたる小さな分布になります。 

これにより、問題はモジュロ クラスに対する古典的な畳み込みに変換されます。 DP 配列を維持します。$dp[r]$剰余を含む和を求める方法の数です$r$間隔のいくつかのプレフィックスを処理した後。 各間隔は遷移に寄与します。現在の DP をその間隔の可能な残差寄与分すべてシフトし、累積します。 

主な技術的課題は、間隔ごとに、整数の個数を効率的に計算することです。$[l_i, r_i]$各剰余モジュロに該当します$k$。 以来$k \le 10$、これは次のように計算できます。$O(k)$完全なサイクルと残りのセグメントに分割することにより、間隔ごとに実行されます。

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、すべての間隔を剰余剰余の度数テーブルに圧縮します。$k$。 

1. インターバルごと$[l, r]$、配列を計算します`cnt`サイズの$k$、 どこ`cnt[x]`値が一致する区間内の整数の数です。$x \bmod k$。 これは、最初に長さの完全なブロックをカウントすることによって行われます。$k$、次に残ったプレフィックスを処理します。 このステップは、大きな数値範囲を小さな離散分布に変換するため、不可欠です。 
2. DP 配列を初期化する`dp`サイズの$k$、 どこ`dp[0] = 1`他のすべてのエントリはゼロです。 これは、数値を選択する前に、達成可能な合計はゼロのみであることを表します。 
3. 間隔ごとに、新しい DP 配列を構築します。`ndp`ゼロに初期化されます。 
4. 前回の残りごとに`r`から$0$に$k-1$、そしてすべての残差に対して`x`から$0$に$k-1$、 アップデート：$$ndp[(r + x) \bmod k] += dp[r] \cdot cnt[x]$$このステップでは、現在の間隔から 1 つの値を使用して部分選択を拡張するすべての方法を集約します。 
5. 交換する`dp`と`ndp`各間隔の処理後。 
6. すべての間隔が処理されると、答えは次のようになります。`dp[0]`。 

この遷移が正しい理由は、各区間が独立しており、各剰余を生成する選択肢の数がわかれば、純粋に寄与のモジュラー加算によってそれらを結合できるためです。 

### なぜ効果があるのか

 処理後のDPの状態$i$間隔は、可能な各和モジュロを達成する方法の数を正確にエンコードします。$k$処理間隔ごとに 1 つの選択肢を使用します。 次の区間からのすべての選択がその剰余寄与分布によって完全に捕捉され、モジュラー加算が最終的な割り算条件に影響を与える唯一の演算であるため、遷移は正確さを維持します。 独立した選択肢を乗算することで、考えられるすべての組み合わせが 1 回だけ計算されるため、最終的なカウントは正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def build_counts(l, r, k):
    cnt = [0] * k
    total = r - l + 1

    full = total // k
    rem = total % k

    start = l % k
    for i in range(k):
        cnt[i] = full

    for i in range(rem):
        cnt[(start + i) % k] += 1

    return cnt

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        dp = [0] * k
        dp[0] = 1

        for _ in range(n):
            l, r = map(int, input().split())
            cnt = build_counts(l, r, k)

            ndp = [0] * k
            for i in range(k):
                if dp[i] == 0:
                    continue
                for j in range(k):
                    if cnt[j] == 0:
                        continue
                    ndp[(i + j) % k] = (ndp[(i + j) % k] + dp[i] * cnt[j]) % MOD

            dp = ndp

        print(dp[0])

if __name__ == "__main__":
    solve()
```実装の中核は、間隔範囲から剰余カウントへの変換です。 機能`build_counts`サイズの全サイクルを使用することで、すべての整数の反復処理を回避します$k$これにより、間隔が非常に大きい場合でも正確さが保証されます。 

DP ループは、モジュロ クラスに対する単純な畳み込みです。 ダブルループオーバー$k$安全なので$k \le 10$したがって、間隔ごとのコストは一定のままです。 

残りのセグメントの処理には注意が必要です。残りのセグメントは次から始まります。$l \bmod k$モジュロをラップアラウンドします$k$、残基の正しい位置合わせを保証します。 

## 実用的な例

 次のような小さなテストケースを考えてみましょう。$n = 2$、$k = 3$、間隔$[1, 3]$そして$[1, 3]$。 

のために$[1, 3]$、残基は$1, 2, 0$、 それで`cnt = [1, 1, 1]`。

 | dp[0] | dp[1] | dp[2] | アクション |
 | --- | --- | --- | --- |
 | 1 | 0 | 0 | 初期化 |

 最初の間隔を処理した後:

 | 新しい dp[0] | 新しい dp[1] | 新しい dp[2] |
 | --- | --- | --- |
 | 1 | 1 | 1 |

 これは、考えられる単一の選択肢すべてに一致します。 

### 秒間隔

 以前のディストリビューションと別のディストリビューションを結合します`[1,1,1]`。 

| 古いr | 古いDP | 貢献 | 更新された状態 |
 | --- | --- | --- | --- |
 | 0 | 1 | [1,1,1] を追加します | すべて +1 |
 | 1 | 1 | シフトされた | 周期的 |
 | 2 | 1 | シフトされた | 周期的 |

 最終結果は再び均一になります。 

| dp[0] | dp[1] | dp[2] |
 | --- | --- | --- |
 | 3 | 3 | 3 |

 したがって、答えは`dp[0] = 3`。 

これは、DP が残基構造を維持しながら区間全体でどのように組み合わせを蓄積するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · k²) | 各間隔は k 個の剰余を計算し、k × k 個の DP 遷移を実行します。

 ## 特殊なケース

 重大なエッジケースは、間隔が極端に大きい場合です。$[1, 10^9]$。 単純な試みでは、残りのセグメントを適切に処理せずに列挙したり均一性を仮定したりしようとする可能性があり、これにより残基のアライメントが崩れます。 実装されたアプローチでは、これは完全なサイクルと、から始まるプレフィックスに分割することによって処理されます。$l \bmod k$、正確な残留カウントを保証します。 

もう 1 つのエッジケースは次のような場合です$k = 1$。 すべての数値は自動的に 0 に一致するため、間隔に関係なくすべての選択が有効になります。 DP は自然に単一の状態に崩壊し、処理全体を通じて 1 のままになります。 

最後の微妙なケースは、間隔が以下の短い長さである場合です。$k$、 例えば$[5, 7]$と$k = 10$。 ここでは、完全なサイクルは存在せず、残りのループのみが寄与します。 残差カウント ロジックは、少なくとも 1 つの完全なブロックを想定せず、カウントを実際に使用可能な値に直接分配するため、引き続き機能します。
