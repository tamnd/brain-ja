 ## 解決策
 ## 問題の理解

 各ノードが整数値を保持するツリーが与えられます。 順序のないノードのペアごとに$u, v$、それらの間のユニークな単純なパスを見ていきます。 そのパス上で、パス上のノードの数と、パスに沿ったすべてのノード値の gcd という 2 つの量を定義します。 彼らの製品は二人の貢献によるものです。 タスクは、個別のノードのすべてのペアにわたるこの寄与を合計することです。 

したがって、ノードの各ペアは、ツリーの構造と、接続パスに沿った値の算術相互作用の両方に依存する何かを提供します。 構造部分はパス長が線形ですが、値部分はパス全体を 1 つの gcd に圧縮します。 

制約により、ほぼ線形またはわずかに超線形の解決策が求められます。 と$n \le 10^5$、すべてのペア、さらにはすべてのパスを明示的に検査するソリューションは不可能です。 単純なすべてのペアの最短パス スタイルの列挙では、すでに次のことが得られます。$O(n^2)$ペア、およびパス処理が行われていたとしても$O(1)$、これは大きすぎます。 どのソリューションでも、明示的にペアを列挙したり、ペアごとに gcd を最初から再計算したりすることは避けなければなりません。 

微妙な問題は、コントリビューションの両方のコンポーネントが互換性のない方法でパスに依存していることです。 長さはパス内のノードにわたって加算的に分解されますが、gcd はサブパスにわたってきれいに分解されないグローバル集約です。 この不一致により、部分パスをマージする方法を慎重に構造化しない限り、パス上での単純な動的プログラミングが不可能になります。 

エッジケースは、ツリーが非常に歪んでいたり、非常に星状である場合に発生します。 1 を中心とする星では、すべての葉のペアが中心を通って接続されます。 単純なアプローチでは、個々のパスが単純であっても、すべてのリーフの寄与をペアごとに結合して、すぐに 2 次の動作に到達しようとする可能性があります。 もう 1 つの失敗ケースは、すべての値が等しい場合です。この場合、gcd の動作は些細なものになり、実装の非効率性が隠れて、誤ってペアごとの再計算に低下する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 ノードのペアごとに、それらの間のパスを計算し、そのパス上のすべての値を収集し、gcd を計算し、ノードの数を数え、乗算して答えに加算します。 LCA の前処理を行ったとしても、各クエリでは依然としてパスに沿って情報を移動または結合する必要があるため、$O(n)$最悪の場合はペアごとに。 と$O(n^2)$ペアの場合、これは次のようになります$O(n^3)$、限界をはるかに超えています。 

LCA とバイナリ リフティングを使用してパス抽出を最適化したとしても、パスに沿った複数の値セットに対して gcd を計算する必要があります。 これを動的に維持することは、再計算するか、大量の状態を保存することなしには実現できません。 

重要な観察は、エンドポイントのペアという観点から考えるのをやめ、代わりに中心構造を介して「接着」されているパスという観点から考えることです。 ノードを分解中心として固定すると、すべてのパスは 1 つのサブツリー内に完全に収まるか、中心を通過します。 これにより、グローバル合計が管理可能な独立した部分に分割されます。 固定中心を通過するパスの場合、その子をルートとするさまざまなサブツリーからの寄与を組み合わせるだけで済みます。 

その時点で、各サブツリーは部分的なパス状態のコレクションに寄与します。サブツリー内のノードについては、パスに沿った考えられる gcd 値ごとに、それを生成するノードの数と中心からの距離の合計を格納することで、中心からそのサブツリーへのすべてのパスを記述することができます。 gcd 値はパスを延長するときにのみ減少し、多様性が制限されるため、これらの集約された状態は小さくなります。 

次に、サブツリーを段階的にマージします。 新しいサブツリーを追加するとき、新しいサブツリーで始まり、中心を経由してすでに処理されたサブツリーで終わるパスの寄与を計算します。 2 つのパスの gcd は、保存された状態の gcd と中心値を取得することによって計算されます。 長さの寄与は、深さの合計に中心の 1 を加えたものにきれいに分割されます。 

このセントロイドまたは分解ベースのマージでは、明示的にペアを列挙することが回避され、各ノードが対数的な数のマージ操作に参加することが保証されます。

 | --- | --- | --- | --- |

 | gcd 状態マージによる重心分解 |$O(n \log n \log A)$|$O(n \log A)$| 承認済み |

 ## アルゴリズムのチュートリアル

 重心分解を使用してツリーをレベルに分割します。 各重心で、分解パス上の最高の重心が現在のパスであるすべてのパスを処理します。 

1.重心を選択します$c$現在のツリーコンポーネントの。 これを削除すると、コンポーネントが独立したサブツリーに分割されます。 
2. 各サブツリーについて$c$、から始まる DFS を実行します。$c$そのサブツリーに。 すべてのノードについて$x$からのパスに沿った値の gcd を計算します。$c$に$x$、そしてからの距離も$c$に$x$。 この情報を各 gcd 値をマッピングする構造に集約します。$g$ペアに$(\text{count}, \text{sum\_dist})$。 
3. まず、1 つのエンドポイントが存在するパスを考慮します。$c$。 州ごとに$(g, cnt, sumdist)$、すべてのノードは、長さが次のパスに寄与します。$sumdist + cnt$、各パスには重心自体が含まれるためです。 追加された貢献度は、$g \cdot (sumdist + cnt)$。 
4. 次に、エンドポイントが次の異なるサブツリーにあるパスを処理します。$c$。 以前に処理されたサブツリーの集約マップを維持します。 新しいサブツリーごとに、そのマップ内のすべての状態とグローバル マップ内のすべての状態を結合します。 2 つの州の場合$(g_1, c_1, s_1)$そして$(g_2, c_2, s_2)$、フルパスに沿った gcd は次のとおりです。$\gcd(g_1, g_2, c[c])$。 このようなすべてのペアの合計寄与度は次のとおりです。$$\gcd(g_1, g_2, c[c]) \cdot (c_2 s_1 + c_1 s_2 + c_1 c_2)$$ここで、3 つの項は各辺からの距離の合計に重心の寄与を加えたものに対応します。 
5. クロスサブツリー寄与を処理した後、現在のサブツリー マップをグローバル マップにマージして続行します。 
6. 重心を削除した後、各サブツリーを再帰的に実行し、同じ手順を繰り返します。 

重要な考え方は、各パスがその分解パスの最も高い重心で 1 回だけカウントされるということです。 

### なぜ効果があるのか

 ツリー内のすべての単純なパスには、分解階層内で固有の最高位の重心があります。 その重心は、パスの終点がさまざまな分解されたコンポーネント内に存在する最初の点です。 この時点で、アルゴリズムは、集約されたサブツリー情報を使用して、パスを 1 回だけカウントします。 gcd と長さは両方とも完全に再構築されたパス情報 (中心から端点と結合) から計算されるため、近似は導入されません。 分解により、再帰レベル全体で責任が切り離され、二重カウントが防止されます。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

MOD = 10**9 + 7

from collections import defaultdict
import math

n = int(input())
c = list(map(int, input().split()))
g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

sub = [0] * n
blocked = [False] * n

def dfs_size(u, p):
    sub[u] = 1
    for v in g[u]:
        if v != p and not blocked[v]:
            dfs_size(v, u)
            sub[u] += sub[v]

def dfs_centroid(u, p, total):
    for v in g[u]:
        if v != p and not blocked[v]:
            if sub[v] * 2 > total:
                return dfs_centroid(v, u, total)
    return u

def collect(u, p, cur_g, dist, mp):
    ng = math.gcd(cur_g, c[u])
    mp[ng][0] += 1
    mp[ng][1] += dist
    for v in g[u]:
        if v != p and not blocked[v]:
            collect(v, u, ng, dist + 1, mp)

def decompose(root):
    dfs_size(root, -1)
    ctd = dfs_centroid(root, -1, sub[root])

    centroid_value = c[ctd]

    global_answer = 0

    full = defaultdict(lambda: [0, 0])

    for v in g[ctd]:
        if blocked[v]:
            continue
        mp = defaultdict(lambda: [0, 0])
        collect(v, ctd, ctd, 1, mp)

        for g1, (cnt1, sum1) in mp.items():
            g1 = math.gcd(g1, centroid_value)
            global_answer += g1 * (sum1 + cnt1)

        for g1, (cnt1, sum1) in mp.items():
            for g2, (cnt2, sum2) in full.items():
                gg = math.gcd(math.gcd(g1, g2), centroid_value)
                global_answer += gg * (cnt1 * sum2 + cnt2 * sum1 + cnt1 * cnt2)

        for k, v in mp.items():
            full[k][0] += v[0]
            full[k][1] += v[1]

    for v in g[ctd]:
        if not blocked[v]:
            decompose(v)

    blocked[ctd] = True

    return global_answer

```実装は重心分解に従います。 の`collect`この関数は、重心のサブツリーごとに、重心からそのサブツリーまでのすべてのパスの圧縮表現を構築します。 各エントリには、特定の gcd に寄与するノードの数と合計距離が格納されます。 

次に、重心からサブツリー ノードへのパスと、異なるサブツリー間を横切るパスという 2 種類の寄与を処理します。 1 つ目は、カウントと距離の合計を組み合わせた直接式を使用します。 2 番目の方法では、サブツリー集合体のペアごとのマージを使用し、結合された gcd と拡張された長さの式を適用します。 

gcd の伝播には注意が必要です。すべての状態の gcd には、セントロイド値とパス上のすべての値の両方が含まれている必要があります。 距離は常に重心から測定されるため、長さは距離と該当する場合は 1 つの中心ノードの合計としてきれいに再構築されます。 

## 実用的な例

 3 つのノードからなる小さなチェーンを考えてみましょう。$1 - 2 - 3$価値観を持って$[2, 3, 6]$。 

重心用$2$2 つのサブツリーがあります: ノード$1$とノード$3$。 

| ステップ | サブツリー | 状態 (g、cnt、sumdist) | アクション |
 | --- | --- | --- | --- |
 | 1 | 左 | (gcd(2,3)=1, 1, 1) | 集める |
 | 2 | 右 | (gcd(3,6)=3, 1, 1) | 集める |
 | 3 | 重心パス | (1,1,1) と (3,1,1) | セントロイドの貢献 |
 | 4 | クロスマージ | (1) × (3) | パス 1-3 |

 これにより、リーフ間のパスが中心で正確に 1 回カウントされ、両側を通る正しい gcd 伝播が確認されます。 

ここで中心のある星を考えてみましょう$1$そして葉を残します$2,3,4$、すべての値は 1 に等しくなります。 

| ステップ | サブツリー | 州 | 貢献 |
 | --- | --- | --- | --- |
 | 1 | 葉2 | (1,1,1) | セントロイドリーフ |
 | 2 | 葉3 | (1,1,1) | 葉と十字架 2 |
 | 3 | 葉4 | (1,1,1) | 前の | と交差します。 

各リーフ ペアは中心で 1 回だけ寄与し、すべての gcd 値は 1 のままであり、高度に分岐している場合でも正確であることがわかります。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \log n \log A)$| 各ノードは重心レベルに参加し、各マージは gcd 状態にわたって動作します。 
| スペース |$O(n \log A)$| 重心レベルごとの圧縮された gcd 分布のストレージ |

 分解により、幾何学的に縮小するコンポーネント内でのみ各ノードが処理されるようになり、再帰レベル全体にわたる総作業量が制限されます。 gcd 値はノード値の約数によって境界付けられる減少チェーンを形成するため、gcd 圧縮により状態の爆発が防止されます。 

これは、次の制限内に快適に適合します$n = 10^5$Python 実装の最適化を行った場合でも。

 ## 特殊なケース

 ペアが存在しないため、単一ノード ツリーは直ちにゼロを生成し、アルゴリズムはペアの寄与を生成するセントロイド処理の開始を正しく回避します。 

星型ツリーでは、すべてのペアの相互作用は中心の重心で発生します。 分解により、各リーフ サブツリーがグローバル マージ構造に 1 回だけ寄与することが保証されるため、すべてのリーフ ペアが重複することなくクロスサブツリー式でカウントされます。 各リーフの距離の合計は 1 のままであるため、長さの再構成は一貫しています。 

チェーンでは、重心分解によって中間ノードが選択され、パスがバランスの取れたサブ問題に確実に分割されます。 gcd 値は重心から各方向に沿って再計算され、両方の半分が完全な gcd 履歴を結合ステップに戻すため、マージ ステップは完全なパス gcd を正しく再構築します。
