 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。 この配列から、概念的には、個別のインデックスの順序付けされたすべてのペア間のすべてのペアごとの差を形成します。 ポジションの各ペアについて$i \neq j$、計算します$|a_i - a_j|$。 これにより、サイズのマルチセットが生成されます$n(n-1)$、両方向がカウントされるためです。 

タスクは、このマルチセットを明示的に構築することではなく、その最大の合計を見つけることです。$m$価値観。 

困難は次のような事実から生じます。$n$すべてのペアを列挙することが不可能なほど大きい場合があります。 たとえ$n = 2 \cdot 10^5$、ペアの数は約$4 \cdot 10^{10}$、これは実行可能な計算をはるかに超えています。 解決策は、これらの違いがどのように分散されるかという構造に依存する必要があります。 

単純な実装では、すべてのペアごとの差を明示的に計算し、並べ替えて、上位を合計します。$m$。 これでは時間的にもメモリ的にもすぐに失敗します。 

対称性について推論する場合、さらに微妙な問題が発生します。 各ペアは、マルチセット内の 2 つの値に寄与します。$|a_i - a_j|$そして$|a_j - a_i|$、これらは等しい。 したがって、すべての個別の順序なしペアは、同じ値をちょうど 2 倍提供します。 この重複を忘れると、カウントと合計で 2 の因数から外れるエラーが発生します。 

すべての値が等しい場合、エッジケースが発生します。 この場合、すべての差はゼロになるため、答えは次のいずれかに関係なくゼロになる必要があります。$m$。 順序付けまたは分割に依存するソリューションでは、すべての寄与が単一の値に集約される退化ケースを処理する必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 インデックスのペアごとに$i$そして$j$、計算する$|a_i - a_j|$、それをリストに保存し、リストを降順に並べ替えて、最初のものを取得します。$m$要素。 これは、問題で説明されているマルチセットを明示的に構築するため、正解です。 ただし、生成する必要があります$n(n-1)$値はサイズが 2 次です。 のために$n = 2 \cdot 10^5$、これは時間的にもメモリ的にも不可能になります。 

重要な観察は、絶対的な違いは位置ではなく順序のみに依存するということです。 配列をソートすると、より大きな差は、ソート順でより離れたペアに対応します。 具体的には、2つの要素について$a_i \le a_j$、違いは$a_j - a_i$。 この値を最大化することは、小さな要素と大きな要素をペアにすることを意味します。 

すべてのペアを生成する代わりに、並べ替えられた配列の観点から、すべての差異を降順でランク付けするときに各ペアごとの距離を何回「選択」できるかを考えることができます。 この構造は、インデックス空間の固定距離によって引き起こされる差異が、値空間の単調セグメントに対応するというものです。 これにより、個々のペアではなく距離レイヤーごとに寄与を集計することができます。 

標準的な変換では、配列をソートし、対称パーティション間の差異を考慮します。 最大の違いは極端な場合に生じます。$a_1$と$a_n$、 それから$a_1$と$a_{n-1}$そして$a_2$と$a_n$、 等々。 これは、残りの最大ギャップを繰り返し取得する 2 ポインタ構造を示唆していますが、これを貪欲に行うには、各ペアが 2 回貢献するため、依然として慎重にカウントする必要があります。 

これをより確実に考える方法は、組み合わせランキングです。 ソートされた配列内の固定差分位置ごとに、少なくとも指定されたしきい値以上の差分を生成するペアの数を数え、これを使用して上位を累積します。$m$貢献。 これにより、問題は明示的な列挙ではなく、ソートされた差分のカウント + プレフィックスの合計に変わります。

 | 最適 (ペアをカウントしてソート) |$O(n \log n)$テストごと |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 すべての違いを次のように表現できるように配列を並べ替えます。$a[j] - a[i]$と$j > i$。 次に、各ペアが 2 回貢献するという考えに基づいて作業します。 

1. 配列を降順でない順に並べ替えます。 これにより、すべての差が非負の前方差として扱われることが保証され、絶対値の複雑さが排除されます。 
2. 順序のないペアが合計で何個存在するかを計算します。$n(n-1)/2$そして、それぞれがマルチセット内で 2 回寄与することを覚えておいてください。 これにより、順序付きペアまたは順序なしペアの観点から一貫して推論することができます。 
3. 私たちは最大のものを望んでいます$m$すべての順序付けされた差分の値。 差異を生成するのではなく、値の大きい順に差異を選択することを考えます。 
4. 固定インデックスの場合$i$、すべてのペア$(i, j)$と$j > i$価値を生み出す$a[j] - a[i]$、次のように減少するシーケンスを形成します。$i$増加し、$j$減少します。 この構造は、エンドポイントを固定し、エンドポイントが生成するペアの数をカウントすることで寄与を列挙できることを意味します。 
5. 貪欲な 2 ポインター累積を使用して、最大の差の選択をシミュレートします。 極端なペアがすべての内部ペアを支配するため、ソートされた配列の左端と右端から次善の候補ギャップを常に比較します。 
6. ペアを選ぶたびに$(i, j)$、その寄与を答えに 2 回追加し、減分します。$m$それに応じて。 次に大きな未使用の差分を生成できるようにポインタを移動します。 
7. まで続けます$m$順序の違いは考慮されています。 

### なぜ効果があるのか

 ソート後、すべての差異はインデックスの一意のペアに対応します。$(i, j)$。 ペアの値は両方向で単調です: 増加$j$差が大きくなり、小さくなります$i$それを増やします。 したがって、ペアごとの差の全体的な順序付けは、配列の両端に近いペアと一致します。 非極端なペアは、まだ使用されていない極端なペアによって制限されているため、貪欲な選択では常に、残っている利用可能な差の最大値が選択されます。 これにより、すべてのステップで、すべての候補を明示的に維持する必要がなく、マルチセットの次に大きい要素が選択されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        i, j = 0, n - 1
        ans = 0

        # We process pairs in a greedy manner from the ends.
        # Each pair contributes twice to the multiset.
        while i < j and m > 0:
            left_gain = a[j] - a[i]
            
            # number of pairs available using this boundary
            cnt = (j - i) * 2

            take = min(m, cnt)

            ans += take * left_gain

            m -= take

            # move the pointer that reduces future maximum span
            # shrinking from the side with fewer remaining contributions
            if (j - i) <= (n - 1 - j + i):
                j -= 1
            else:
                i += 1

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは、違いが方向性を持つように各テスト ケース配列を並べ替えることから始まります。 2つの指針`i`そして`j`圧縮している現在の極端な間隔を表します。 表現`a[j] - a[i]`現在のセグメントにまたがるすべてのペアの間で考えられる最大の差です。 

変数`cnt`これは、順序付けされていない各ペアがマルチセット内に 2 回出現するという事実を説明しているため、最大で`2 * (j - i)`この値の順序付けされた差。 から引きます`m`それに応じて。 

ポインタ移動ヒューリスティックは、残りのペアが少ない側からセグメントを縮小するように設計されており、大きな差レベルを使い果たした後に、より小さな差レベルを体系的に明らかにします。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n, m = map(int, input().split())
            a = list(map(int, input().split()))
            a.sort()

                diff = a[j] - a[i]

                        j -= 1
                    else:
                        i += 1

    return solve()

 ## 特殊なケース

 すべての要素が等しい場合、すべてのペアの差はゼロになります。 アルゴリズムは即座に生成します`diff = 0`あらゆる段階で、たとえ`m`が大きい場合、累積された答えはゼロのままです。 間隔を縮小してもペアの値は決して変更されないため、ポインターの移動は問題になりません。 

いつ`n = 2`、マルチセット内で 2 回繰り返される固有の違いが 1 つだけあります。 アルゴリズムセット`i = 0`、`j = 1`、差分を 1 回計算し、最大 2 つの順序付けられた寄与を消費します。 これは、両方の要件に一致します。$(1,2)$そして$(2,1)$存在する。 

いつ`m`非常に大きい、近い$n(n-1)$、アルゴリズムは最終的に間隔を完全に縮小し、考えられるすべての寄与をすでに考慮しています。 残っているもの`m`は合計に影響を与えないゼロ値の寄与に対応し、次のような場合でも安定性を確保します。`m`マルチセット全体のサイズに等しい。
