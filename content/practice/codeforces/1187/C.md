 ## 解決策
 ## 問題の理解

 任意の長さの整数配列を構築するように求められます。$n$これは、部分配列に関する一連の制約と一致します。 各制約は、セグメントが非減少でなければならないか、非減少でなければならないかのいずれかを記述します。 

「ソート済み」としてマークされたセグメントは、その中のすべての隣接するペアを強制的に満たします。$a_i \le a_{i+1}$。 「未ソート」としてマークされたセグメントは、その中に少なくとも 1 つの隣接する反転が存在することのみを必要とします。$a_j > a_{j+1}$その間隔内で。 課題は、配列自体が与えられるのではなく、重複する間隔に対する関係制約のみが与えられることです。 

主な問題点は、「ソートされた」制約はグローバルで厳格であるのに対し、「ソートされていない」制約は実存的でローカルであることです。 有効な構造は、すべての単調要件を満たしながら、各禁止区間内に少なくとも 1 つの下りを配置する必要があります。 

制約$n, m \le 1000$許可する$O(n^2)$または$O(nm)$前処理や伝播による構築は可能ですが、すべての配列を列挙したり、すべての割り当てをチェックしたりする必要があるものは実行できません。 私たちは明らかに、建設的または貪欲な体制にあり、徐々に構造を強化しています。 

「ソートされていない」セグメントが、「ソートされた」制約によって強制的に非減少となる領域内に完全に含まれる場合、微妙なエッジ ケースが発生します。 その場合、単調性によりその領域のどこでも下降が禁止されるため、答えは直ちに不可能になります。 たとえば、こう言われたら$(1, 1, 5)$そしてまた$(0, 2, 3)$の場合、最初の制約はすべての隣接関係を強制するため、2 番目の制約は不可能です。$[1,5]$減らないこと。 

もう 1 つの微妙なケースは、ソートされたセグメントが重なっていることで、大規模な結合に対して全体としてグローバルな単調性を強制するため、すべての強制領域の外側にない限り、必要な降下を配置することが不可能になります。 

## アプローチ

 素朴な考えは、配列を未知のものとして扱い、隣接する要素間の不等式の可能な代入をすべて試し、各ペアについて次のことを決定することです。$a_i \le a_{i+1}$または$a_i > a_{i+1}$。 これらの決定が修正されると、それらと一致する実際の数値を割り当てることができます。 

ただし、これは指数関数的です$n$、それぞれの$n-1$隣接関係は増加または減少する可能性があります。 整合性チェックのみを考慮した場合でも、各割り当てではすべての内容を検証する必要があります。$m$制約、与える$O(2^n \cdot nm)$、それは限界をはるかに超えています。 

重要な観察は、重要な唯一の実際の構造は、減少を配置できる場所であるということです。 タイプ 1 制約により特定の隣接関係が非減少である必要があると判断した場合、タイプ 0 制約には、この強制セットの外に少なくとも 1 つの隣接関係が含まれている必要があります。 これにより、問題は「禁止された等価エッジ」のセットを構築し、各「ソートされていない」間隔に厳密なドロップが許可されるエッジが少なくとも 1 つ含まれるようにするというように再構成されます。 

これは貪欲な構築を示唆しています。最初にすべての隣接関係が非減少であると仮定し、次にすべてのタイプ 0 制約を満たすために厳密な減少を選択的に導入します。 タイプ 1 制約では特定の範囲での減少が禁止されているため、選択した減少位置がすべての禁止された間隔の外側にあることを確認する必要があります。 

最後のステップは、実際の値を割り当てることです。単純に大きな値から開始し、ブレークを配置するかセグメントのラベルを使用するかに応じて、値を減らすか維持することができます。

 ## アルゴリズムのチュートリアル

 この問題を、どの隣接する位置を決定するかに変換します。$i \to i+1$厳しいドロップになります。 これらを「ブレークポイント」と呼ぶことにします。 

1. すべての隣接するペアが非減少であると仮定することから始めます。これは、最初に強制ブレークを設定しないことを意味します。 
2. すべてのタイプ 1 制約を処理します。 各セグメントごとに$[l, r]$、すべての隣接をマークします。$l \le i < r$減少していない必要があります。 実際には、これは、これらのセグメント内にブレークポイントを配置することができないことを意味します。 
3. タイプ 1 制約から、ブレークが許可されない禁止されたエッジのセットを構築します。 有効なブレークポイントは、これらすべての強制モノトーン領域の外側に存在する必要があります。 
4. 次に、タイプ 0 制約を処理します。 インターバルごとに$[l, r]$少なくとも 1 つのブレークポイントが必要です$i$と$l \le i < r$それは禁止されていません。 そのような立場が存在しない場合、即座に答えることは不可能です。 
5. これを効率的に保証するために、ブレークポイントの位置を貪欲に選択します。 すべての位置を反復処理し、まだ満たされていないタイプ 0 の間隔に遭遇するたびに、禁止されていない限り、その間隔内の最も右側の有効な位置にブレークポイントを配置します。 これにより、将来の制約が必要以上に損なわれることがなくなります。 
6. すべてのブレークポイントを決定したら、配列を構築します。 値を左から右に割り当てます。 大きな数値から始めて設定する$a_1 = 10^9$。 それぞれについて$i$、位置の場合$i$ブレークポイントです、設定されています$a_{i+1} = a_i - 1$。 それ以外の場合は設定$a_{i+1} = a_i$。 

これが機能する理由は、等しい隣接値は非減少セグメントをエンコードし、厳密な減少は保証された違反をエンコードするためです。 すべてのタイプ 0 間隔には少なくとも 1 つの強制減少が含まれるため、ソートされないことが保証され、禁止領域内にブレークが配置されないため、すべてのタイプ 1 制約は有効なままになります。 

維持される不変条件は、各制約を処理した後、これまでに確認されたすべてのタイプ 0 間隔に少なくとも 1 つの選択されたブレークポイントが含まれており、タイプ 1 で強制されたモノトーン セグメント内にブレークポイントが存在しないことです。 これにより、競合が誤って蓄積されるのを防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    # forbidden[i] means we cannot place a "decrease" between i and i+1
    forbidden = [False] * (n + 1)

    type0 = []
    
    # First process type 1 constraints: forbid decreases inside them
    for _ in range(m):
        t, l, r = map(int, input().split())
        if t == 1:
            for i in range(l, r):
                forbidden[i] = True
        else:
            type0.append((l, r))

    # Try to place breaks greedily for type 0 constraints
    break_at = [False] * (n + 1)

    for l, r in type0:
        found = False
        # try to place a break as right as possible
        for i in range(r - 1, l - 1, -1):
            if not forbidden[i]:
                break_at[i] = True
                found = True
                break
        if not found:
            print("NO")
            return

    # construct array
    a = [0] * (n + 1)
    a[1] = 10**9

    for i in range(1, n):
        if break_at[i]:
            a[i + 1] = a[i] - 1
        else:
            a[i + 1] = a[i]

    print("YES")
    print(*a[1:])

if __name__ == "__main__":
    solve()
```コードはまず、すべてのタイプ 1 制約を禁止された隣接位置に変換します。これは、これらのエッジが非減少のままでなければならないことを意味します。 次に、各タイプ 0 間隔内で右から左にスキャンし、可能な限り最新の有効な位置にブレークを配置することで、すべてのタイプ 0 間隔に少なくとも 1 つの選択されたブレークポイントがあることを確認します。 最後に、値を左から右に伝播し、選択したブレークポイントでのみ減少することによって具体的な配列を構築します。 

実装の微妙な詳細は、制約処理中に値を直接変更するのではなく、隣接ごとにブレークポイントを保存することです。 この分離により、重複する制約間の偶発的な相互作用が回避され、実現可能性チェックが数値割り当てから独立したままになることが保証されます。

 スタート$a_1 = 10^9$。 インデックス 5 までは均等を維持し、その後 5 で減少し、その後再び均等を維持します。 これにより、すべての制約に一致する有効な配列が得られます。

 ## 特殊なケース

 タイプ 1 制約が配列全体をカバーする場合、1 つのエッジ ケースが発生します。 その状況では、すべての隣接する位置でのブレークが禁止されるため、タイプ 0 の制約は直ちに不可能になります。 内部スキャンで有効なブレークポイントが見つからず、NO が返されるため、アルゴリズムがこれを処理します。 

もう 1 つのエッジ ケースは、複数のタイプ 0 間隔が重なり合っているものの、単一のブレークポイントによってすべてが満たされる場合に発生します。 ブレークポイントが設定されると、そのインデックスをカバーするすべての間隔が暗黙的に満たされ、追加の作業が必要ないため、貪欲な戦略はこれを自然に処理します。 

最後の微妙なケースは、制約により、許容されるブレークポイントの「狭いコリドー」が強制される場合です。たとえば、1 つの隣接のみが空きのままになる場合です。 このアルゴリズムは常に右端の有効な位置を試行し、将来の制約を最大限にカバーする方法で限られた柔軟性が確実に使用されるため、引き続き成功します。
