 ## 解決策
 ## 問題の理解

 私たちはスタックのグリッドを維持しています。 の各セル$N \times N$ボードには文字が縦に並んでいます。 このシステムは、時間の経過とともに適用される 3 種類の操作をサポートします。つまり、文字をスタックにプッシュする、スタックから最上位の文字をポップする、特定の文字が特定のスタック内の「多数派」であるかどうかをクエリするです。 

手紙は積み重ねが美しいと考えられています$c$現在そのセルのスタックにあるすべての文字の中で、$c$スタックの高さの半分よりも厳密に大きくなります。 各クエリは、特定の文字がその時点でスタック内の過半数になるかどうかを尋ねます。 

重要な課題は、操作が完全に動的であることです。 プッシュとポップはクエリとインターリーブし、各セルは独立して動作します。 以来$Q$まで可能です$2 \cdot 10^5$に近い操作ごとの効率が必要です。$O(1)$または$O(\log N)$スタックの更新ごとに。 

単純な解釈では、各スタックを明示的に維持し、クエリごとにスタック全体をスキャンして、特定の文字の出現をカウントすることになります。 これはすぐに次のことにつながります$O(Q^2)$単一スタックが大きくなった場合の最悪の場合の動作。 

空のスタックに対してポップ操作が発行されると、微妙なエッジ ケースが発生します。 これらは黙って無視する必要があります。つまり、スタックが常に存在する、または空ではないと仮定することはできません。 

もう 1 つのエッジ ケースは、同じセル上でクエリと更新を交互に行うことです。 単純なキャッシュ戦略は、ポップ後もスタック サマリーが有効であると仮定すると失敗する可能性があります。 

失敗シナリオの例: カウントは維持しているが、ポップ時に適切にデクリメントするのを忘れた場合、削除後にクエリで過半数が誤って報告される可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。各スタックを文字のリストとして保存します。 プッシュは追加し、ポップは可能であれば末尾から削除し、クエリはスタックを反復して要求された文字の出現をカウントします。 これは正しいですが、クエリごとにコストがかかります$O(h)$、 どこ$h$スタックの高さです。 すべての操作が同じセルを対象とする場合、総コストは次のようになります。$O(Q^2)$が遅すぎます。 

改善するために、各スタックが独立して進化し、それを変更するのは 2 つの操作 (上からのプッシュとポップ) だけであることを観察します。 これはまさに、元に戻す機能を備えたシーケンス上の動的なマルチセットです。 各文字について、現在の操作のプレフィックスにおけるその頻度を知る必要があるだけです。 

すべてのクエリでカウントを再計算する代わりに、セルごとに 26 文字にわたる頻度テーブルと現在のスタック サイズを維持します。 プッシュでは文字数とサイズが 1 つ増加し、ポップではスタックが空でない場合は減少します。 クエリは定数時間チェックになります。クエリされた文字の頻度とスタック サイズの半分を比較します。 

これにより、あらゆる操作が次のように削減されます。$O(1)$、アルファベットのサイズは一定であるため。

 | 最適 (スタックあたりの周波数) |$O(Q)$|$O(N^2 \cdot 26)$| 承認済み |

 ## アルゴリズムのチュートリアル

 セルごとに 2 つの構造を維持します。文字のスタックと、現在スタック内にある各文字のカウントを追跡するサイズ 26 の頻度配列です。 

1. を初期化します。$N \times N$各セルには空のリストとゼロに初期化された周波数配列が含まれるグリッドです。 これにより、すべての操作に定義された開始状態が保証されます。 
2. セルでのプッシュ操作の場合$(x, y)$、文字をスタックに追加し、その頻度を増やします。 これにより、頻度テーブルと実際のスタックの内容の同期が維持されます。 
3. でのポップ操作の場合$(x, y)$、まずスタックが空でないかどうかを確認します。 存在する場合は、最上位の要素を削除し、その頻度を減らします。 空の場合は、削除する要素がないため、何も行いません。 
4. お問い合わせについては、$(x, y)$手紙付き$c$、スタック サイズを計算して比較します。$2 \cdot \text{freq}[c]$スタックサイズ付き。 厳密に大きい場合は「yes」を出力し、そうでない場合は「no」を出力します。 

乗算により浮動小数点除算が回避され、整数安全な比較が保証されます。 

### なぜ効果があるのか

 すべてのプッシュで正確に 1 カウントが増加し、すべての有効なポップで正確に 1 カウントが減少するため、各ステップで周波数配列は現在スタック内にある要素のマルチセットと正確に一致します。 対応するスタック変更がなければ操作はカウントを変更しないため、一連の操作にわたって帰納的に一貫性が保たれます。 多数決条件はカウントと合計サイズのみに依存するため、クエリ チェックは常に定義と同等になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def idx(c):
    return ord(c) - 97

def solve():
    N, Q = map(int, input().split())
    
    grid_stack = [[[] for _ in range(N)] for _ in range(N)]
    grid_cnt = [[[0]*26 for _ in range(N)] for _ in range(N)]
    
    out = []
    
    for _ in range(Q):
        tmp = input().split()
        if not tmp:
            continue
        
        t = int(tmp[0])
        
        if t == 0:
            c = tmp[1]
            x = int(tmp[2])
            y = int(tmp[3])
            
            grid_stack[x][y].append(c)
            grid_cnt[x][y][idx(c)] += 1
        
        elif t == 1:
            x = int(tmp[1])
            y = int(tmp[2])
            
            if grid_stack[x][y]:
                c = grid_stack[x][y].pop()
                grid_cnt[x][y][idx(c)] -= 1
        
        else:
            c = tmp[1]
            x = int(tmp[2])
            y = int(tmp[3])
            
            size = len(grid_stack[x][y])
            cnt = grid_cnt[x][y][idx(c)]
            
            if cnt * 2 > size:
                out.append("yes")
            else:
                out.append("no")
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションではセルごとに明示的なスタックを保持するため、ポップ操作が有効になり、常に正しい文字が削除されます。 頻度配列はスタックの変更とロックステップで更新されます。クエリは順序ではなく集計カウントのみに依存するため、これは不可欠です。 

過半数チェックでは次のように使用されます。`cnt * 2 > size`分割の問題を避けるため。 サイズが奇数の場合、整数除算の精度が失われるため、これは重要です。 

空のポップの場合は、ポップする前にスタックが存在するかどうかをチェックすることで明示的に保護され、インデックス エラーが発生しないことが保証されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、空のスタックから繰り返しポップされることです。 演算は無視する必要があるため、周波数配列は変更されない必要があります。 たとえば、空のセルから開始して複数のポップを発行する場合は、状態を変更しないで、後のクエリの正確性を維持する必要があります。 

もう1つのケースはサイズ1のスタックです。 単一の文字が存在する場合、それは常に厳密な多数決です。 アルゴリズムはこれを自然に処理します。`cnt * 2 > size`になる`2 > 1`。 

最後の微妙なケースは、異なる文字が急速に切り替わることです。 各更新は 1 つの周波数スロットとスタックのみに影響を与えるため、周波数がスタックの内容と一致するという不変条件により、たとえ敵対的なシーケンスであっても状態が非同期にならないことが保証されます。
