 ## 解決策
 ## 問題の理解

 長さの文字列が与えられます$n$。 許可される唯一の操作はインデックスを選択することです$i$文字の位置を入れ替えます$i$そして$i+k$。 この操作は任意に何度でも繰り返すことができます。 

したがって、文字列は位置を接続するエッジに沿った交換を通じて進化します。$i$ポジション付き$i+k$。 問題は、最終的な構成を 1 つ見つけることではなく、そのようなスワップを何度でも行った後に元の構成から到達できる別の文字列の数を数えることです。 

重要な視点は、「操作」について考えるのをやめ、代わりにインデックス間の接続性について考えることです。 各スワップは、インデックス上のグラフの接続されたコンポーネント内の文字のみを並べ替えます。$1 \dots n$、エッジが接続される場所$i$そして$i+k$。 隣接するスワップによってそのコンポーネント上に完全な対称グループが生成されるため、各接続コンポーネント内で文字を任意に再配置できます。 

制約により許可されるのは、$n$まで$10^6$したがって、明示的に順列を構築したり、到達可能な文字列を列挙したりするアプローチは不可能です。 指数グラフの線形または線形に近い分解が必要です。 

素朴なアイデアは、スワップをシミュレートし、BFS を使用して到達可能なすべての文字列を探索しようとすることです。 サイズが 1 つのコンポーネントであっても、これはすぐに失敗します。$m$生成できる$m!$順列があり、それらを保存したり走査したりすることは、たとえ$m = 10$。 

2 番目の単純なアイデアは、各連結成分を独立して扱い、成分サイズの階乗を乗算することです。 これは正確に近いですが、重要な詳細が欠けています。文字は区別されないため、同一の文字を並べ替えるだけのコンポーネント内の並べ替えでは、新しい文字列は作成されません。 

不注意なアプローチを打ち破るエッジケースには、次のようなものがあります。 

もし$n = 4, k = 2, s = "aabb"$、インデックスはコンポーネントに分割されます$\{1,3\}$そして$\{2,4\}$。 各コンポーネントには 2 つの文字があるため、それぞれが次の係数に寄与します。$2$、与える$4$。 成分ごとの単純な階乗アプローチでは、次のようになります。$2! \cdot 2! = 4$、ここでは一致しますが、重複は単純であるため、これは偶然です。 

もし$n = 4, k = 1, s = "abca"$、文字列全体が 1 つのコンポーネントであるため、到達可能な文字列はすべてマルチセットの順列になります。 答えは$4! / (2!)$。 繰り返される文字を無視するアプローチでは、次のように出力されます。$24$、それは間違いです。 

本当の難しさは、グラフ構造 (ステップによって誘導されるコンポーネント) を結合することです。$k$) 各コンポーネント内のマルチセット順列を使用します。 

## アプローチ

 スワップは、各ポジションが次のようなグラフを定義します。$i$に接続されています$i+k$有効な場合。 このグラフは、に依存するチェーンのコレクションです。$k$。 操作を繰り返し適用すると、これらのエッジに沿って移動できるため、各連結成分はすべてのインデックスが一致するモジュロになります。$k$ただし、ステップがどのように相互作用するかを慎重に検査した後でのみです。 

ブルートフォースアプローチでは、スワップをシミュレートし、到達可能なすべての順列を列挙しようとします。 各スワップはローカルな順序を変更するだけですが、繰り返し適用するとコンポーネント内のすべての順列が調査されます。 最悪の場合、コンポーネントには次のものが含まれる可能性があります。$\Theta(n)$インデックスのため、列挙は次のように増加します$O((n!) )$、それは不可能です。 

重要な洞察は、グラフがエッジによって引き起こされるということです。$i \leftrightarrow i+k$インデックスを正確に分割します$g = \gcd(n, k)$独立したコンポーネント。 各コンポーネント内で、位置は次のステップで循環的に接続されます。$k$、等しい構造の素のサイクルを形成します。 各コンポーネントは独立しているため、最終的な答えは、そのコンポーネント内の文字の個別の順列の数のコンポーネントの積になります。 

文字数のあるコンポーネントの場合$c_1, c_2, \dots$、個別の再配置の数は次のとおりです。$$\frac{m!}{\prod c_i!}$$どこ$m$コンポーネントのサイズです。 完全な答えは、すべてのコンポーネントに対する製品です。 

階乗と逆階乗モジュロを事前計算します$10^9+7$剰余クラスモジュロによるグループインデックス$g$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 |$O(n!)$|$O(n!)$| 遅すぎる |
 | コンポーネント + マルチセットのカウント |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. コンピューティング$g = \gcd(n, k)$。 これは、スワップが繰り返されたときにインデックスがどのように独立したサイクルに分割されるかを決定します。 理由は、足したり引いたりを繰り返すと、$k$剰余モジュロを保存します$g$したがって、これらの境界を越える操作はありません。 
2. 階乗配列と逆階乗配列を最大で初期化します。$n$。 各コンポーネントは繰り返される文字の階乗で除算する必要があるため、これらは多項係数を効率的に計算するために必要です。 
3. パーティションインデックス$g$グループ、ここでグループ$r$インデックスが含まれています$r, r+g, r+2g, \dots$。 これが機能するのは、これらがまさにサイズの繰り返しジャンプによって引き起こされる連結コンポーネントであるためです。$k$。 
4. グループごとに、その位置に登場するキャラクターを集めます。 グループ内で完全に置換可能なマルチセットを効果的に抽出しています。 
5. グループ内の各文字の頻度を数え、個別の順列の数を次のように計算します。$m! / \prod c_i!$。 これは、交換操作によりコンポーネント内で任意の順列を実現できるが、同一の文字によって新しい文字列が作成されないことを反映しています。 
6. すべてのグループの結果を剰余で乗算します。$10^9+7$。 

### なぜ効果があるのか

 スワップ グラフは、次の繰り返し加算によって定義される連結成分に分解されます。$k$、各コンポーネントは他のコンポーネントから独立しています。 コンポーネント内では、隣接するスワップによってすべての順列が生成されるため、到達可能なセットは文字のマルチセットのすべての順列になります。 コンポーネントは相互作用しないため、合計カウントは独立した多項カウントの積になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def build_fact(n):
    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)

    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    return fact, invfact

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    g = 0
    import math
    g = math.gcd(n, k)

    fact, invfact = build_fact(n)

    visited = [False] * n
    ans = 1

    for start in range(g):
        if visited[start]:
            continue

        freq = {}
        idxs = []
        i = start

        while not visited[i]:
            visited[i] = True
            idxs.append(i)
            i = (i + k) % n

        for i in idxs:
            freq[s[i]] = freq.get(s[i], 0) + 1

        m = len(idxs)
        ways = fact[m]
        for c in freq.values():
            ways = ways * invfact[c] % MOD

        ans = ans * ways % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```階乗前処理は、すべてのコンポーネントに使用される組み合わせエンジンを構築します。 gcd は、独立したサイクルがいくつ存在するかを決定します。 各サイクルは、次の追加を繰り返して実行されます。$k$モジュロ$n$、スワップ接続を正しく追跡します。 

訪問された配列により、各インデックスが 1 回だけ処理されることが保証されます。 各コンポーネント内で、文字の多重度をカウントし、多項式を適用します。 最後の乗算では、独立したコンポーネントが結合されます。 

微妙な点は、ウォーキング時にモジュロ演算を使用することです。$i = (i + k) \% n$。 これにより、サイクル構造が正しくモデル化されます。 の各開始インデックス$0 \dots g-1$オーバーラップのない完全な軌道を生成します。

 ## 特殊なケース

 エッジケースの 1 つは次の場合に発生します。$k = n$。 この場合、有効なスワップは存在しません。$i+k$すべての人にとって限界外です$i$, したがって、文字列は固定されます。 アルゴリズムはこれを処理します。$g = \gcd(n,n) = n$, しかし、各コンポーネントのサイズは 1 なので、答え 1 が得られます。 

もう 1 つのケースは、すべての文字が同一である場合です。 各コンポーネントは構造的に多くの順列を許可しますが、多項係数はコンポーネントごとに 1 に崩壊します。 すべての階乗除算がキャンセルされるため、アルゴリズムは正しく 1 を返します。 

最後の微妙なケースは次のような場合です。$k$と互いに素である$n$。 それから$g=1$そして文字列全体が 1 つのコンポーネントです。 このアルゴリズムは、スワップがすべてを 1 つの完全に置換可能なシステムに接続するという事実と一致して、文字列全体にわたって単一の多項係数に削減されます。
