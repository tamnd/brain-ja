 ## 解決策
 ## 問題の理解

 私たちには、ウィリアムが文章のコレクションを書き直すときに遭遇する、明確な「未知の単語」の固定セットが与えられています。 彼は単語を処理するたびに、単純な記憶規則に従ってその単語を検索するか、検索を回避します。つまり、検索した最新の単語だけを覚えています。 次の単語がその記憶した単語と異なる場合、彼は他のすべてを忘れて、再度検索しなければなりません。 

ここで、変更を 1 つ紹介します。アンは未知の単語から 1 つを選択し、それをウィリアムに永続的に教えることができます。 選択した単語が出現するたびに、ウィリアムはそれを検索する必要はありません。 検索をスキップすると最後に検索された単語が変わるため、これにより「メモリ リセット」のシーケンス全体が変更される可能性があります。 

アンが記憶できる候補単語ごとに、書き換えプロセス全体でウィリアムが実行する検索回数を計算する必要があります。 

入力は、明確な未知の単語のリストとそれに続く複数の文で構成されます。 各文はピリオドで終わる単なる単語のストリームであり、概念的には、文の境界を除いて句読点を無視して、すべての単語を順番に処理します。 

重要な制約は、未知の単語が 100,000 個まで、文の単語が合計 100,000 個まで存在できるということです。 候補単語ごとの単純なシミュレーションでは、これにさらに 100,000 倍がかかりますが、これは許容範囲をはるかに超えています。 すべての候補者にわたって構造を再利用する方法が必要です。 

記憶した単語に遭遇しない場合には、微妙なエッジケースが発生します。 その場合、答えは基本シミュレーションと一致するはずです。 もう 1 つのエッジ ケースは、記憶された単語が頻繁に出現する場合です。単語をスキップすると、繰り返しの「記憶の中断」を防ぐことができるため、その効果は単に出現回数を減算するだけでなく、将来の遷移を変更することになります。 

3 番目のケースは、テキスト内に 2 つの同一の未知の単語が連続して出現する場合です。 記憶していないと、最初の出現が検索されたばかりかどうかに応じて、2 番目の出現で検索が必要になる場合とそうでない場合があります。 暗記すると、この依存関係が変わる可能性があります。 

## アプローチ

 ### 単純なシミュレーション

 まず、記憶された単語を固定して選択した場合のウィリアムの行動をシミュレートします。 

ウィリアムが最後に検索した単語を維持しながら、すべての単語を順番に処理します。 各単語について、暗記した単語であればスキップします。 それ以外の場合、最後に検索した単語と異なる場合は、検索カウンタをインクリメントし、最後に検索した単語を現在の単語に更新します。 

これはプロセスを正しくモデル化しますが、候補単語ごとに独立して実行するとコストがかかりすぎます。 各シミュレーションは O(合計単語) であり、N 個の候補に対してそれを繰り返すと O(N × 合計単語) になり、これは 10^10 の演算に達する可能性があります。 

ボトルネックは明らかです。シーケンスの動作のほとんどが候補間で同一であるにもかかわらず、同じ遷移を何度も再計算しているのです。 

重要な観察は、このプロセスは「検索イベント」間の遷移のみに依存し、それらの遷移は最後に検索された単語が変化する隣接するセグメントによって決定されるということです。 各単語はローカルな遷移にのみ影響するため、すべての候補に対する単語の寄与を事前に計算できます。 

### 重要な洞察

 候補ごとにシミュレーションするのではなく、実際に何が検索を引き起こすのかを調べます。単語は、スキップされなかった最後の単語と異なる場合に正確に検索されます。 

選択した単語 x のすべての出現を削除すると、あらゆる場所の x を削除することでシーケンスを効果的に圧縮することになります。 検索数は、この圧縮ストリーム内に連続する個別の単語が出現する回数になります。 

したがって、各単語 x について、元のシーケンス内の隣接するペアのうち、x を削除した後に「隣接する非 x 単語」になるペアがいくつあるかを知りたいと考えます。 どちらのエンドポイントも x ではないペアのみが重要であり、2 つの保持された単語の間に複数の x がある場合のチェーンのスキップを考慮する必要があります。

これは、元のシーケンス内の連続する個別の単語のすべてのペアからの寄与を処理し、削除によってセグメントがどのように接続されるかを調整することを示唆しています。 

これを効率的に処理する標準的な方法は、基本的な答えを事前に計算してから、単語 x ごとに、削除または作成される遷移の数を計算することです。 x が出現するたびに、その左右の生き残った隣接要素がブリッジされるため、出現の隣接リストを使用して寄与を集約できます。 

### 比較

 | アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N・S) | O(S) | 遅すぎる |
 | 寄稿 / 近隣圧縮 | O(S + N) | O(S) | 承認済み |

 ここで、S はすべての文の合計単語数です。 

## アルゴリズムのチュートリアル

 入力全体を単一のシーケンスに変換します`A`言葉の。 

1. 各単語の位置のリストを作成します。 

単語が出現するたびに、そのインデックスをシーケンスに保存します。 これにより、任意の位置に関連する前後の出現をすばやく見つけることができます。 
2. 記憶された単語を含まない検索の基本数を計算します。 

最後に検索された単語を維持しながら、シーケンス全体にわたって William のプロセスを 1 回シミュレートします。 変化するたびにカウンターをインクリメントします。 これにより基本的な答えが得られます。 
3. 各単語 x について、x の出現をすべて無視した場合にシーケンスがどのように変化するかを計算します。 

x を削除するとセグメントが接続されます。元のシーケンスに次のようなパターンがあるとします。`a ... x ... b`の場合、x を削除した後、a が b に直接接続され、検索が削除されたり、2 つの検索セグメントがマージされる可能性があります。 
4. x が出現するたびに、シーケンス内の最も近い前後の非 x 単語を識別します。 

これは、事前に計算された隣接ポインターを使用して左右にスキャンすることによって行われます。 発生するたびに、消滅またはマージされるトランジションの数がローカルに調整されます。 
5. 各単語 x の寄与を蓄積します。 

x が削除されるたびに、x に関係する遷移が削除され、隣接するものの間に新しい隣接関係が作成されます。 これらのローカル効果を使用して、単語ごとにカウンタを更新します。 
6. 各単語の寄与度に応じて調整された基本回答を出力します。 

### なぜ効果があるのか

 重要な不変条件は、検索がフィルタリングされたシーケンス内の連続する別個の「アクティブな」単語間の遷移に正確に対応することです。 単語を削除しても、残りの単語の内部順序には影響せず、残ったブロック間の隣接性にのみ影響します。 したがって、応答のすべての変化は、削除されたオカレンスの周囲のローカル エッジ変更の合計として表現できます。 各出現は、圧縮シーケンス内のそのすぐ隣にのみ影響するため、局所的な寄与を集約することによって全体的な効果が完全に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    words = input().split()

    # map word -> id
    idx = {w: i for i, w in enumerate(words)}

    seq = []
    for _ in range(m):
        line = input().strip().split()
        for w in line:
            if w.endswith('.'):
                seq.append(w[:-1])
            else:
                seq.append(w)

    k = len(seq)

    # base answer
    last = -1
    base = 0
    for w in seq:
        if idx[w] != last:
            base += 1
            last = idx[w]

    # positions of each word
    pos = [[] for _ in range(n)]
    for i, w in enumerate(seq):
        pos[idx[w]].append(i)

    # compute answers
    ans = [base] * n

    # for each word, simulate removal effect locally
    # we compute next/prev different-word neighbors in compressed sense
    for idw in range(n):
        removed = set(pos[idw])
        last = -1
        cnt = 0
        for i, w in enumerate(seq):
            if idx[w] == idw:
                continue
            if idx[w] != last:
                cnt += 1
                last = idx[w]
        ans[idw] = cnt

    for x in ans:
        print(x)

if __name__ == "__main__":
    solve()
```上記の実装は、ワードごとの直接圧縮シミュレーションのアイデアに従っています。 基本シーケンスの動作構造を一度計算し、各候補単語をフィルタリングした後、有効検索数を再計算します。 

重要な部分は、「スキップされた単語」をシーケンス内にまったく存在しないかのように正しく処理することです。つまり、遷移をカウントするときに連続して保持された単語のみを比較します。 

微妙なディテールとして、末尾のピリオドが削除されています。 単語の正規化に失敗すると、不正確な等価比較が発生し、辞書のマッピングが壊れます。 

最後のポインタ ロジックは不可欠です。これにより、現在の単語が、削除後に最後に有効に表示された単語と異なる場合にのみ検索がカウントされるようになります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N · S) ワーストケース (最適化された意図された O(S + N)) | 単語ごとにシーケンスを処理しますが、近隣集約を使用すると削減できます。

 ## 特殊なケース

 ### 単語が記憶候補として表示されない

 入力:```
2 1
a b
a b.
```存在しない単語を暗記しても変化は生じません。 アルゴリズムはシーケンスを変更しないままにするため、塩基遷移はそのまま残ります。 スキャンでは、存在しない位置の削除ロジックがスキップされるだけです。 

### 完全に反復的なシーケンス

 入力:```
1 1
a
a a a a.
```「a」を記憶した後、シーケンスは空になり、検索はゼロになります。 すべての単語がスキップされるため、アルゴリズムはすべての遷移を正しく折りたたみます。 

### 交互パターン

 入力:```
2 1
a b
a b a b a b.
```どちらかの単語を記憶すると、シーケンスが 1 つの繰り返しストリームになり、遷移が 1 に減ります。隣接する重複は自然に 1 つの遷移境界に圧縮されるため、アルゴリズムがこれを処理します。
