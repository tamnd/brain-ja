 ## 解決策
 ## 問題の理解

 一連の大文字で書かれたテキストを表す長い文字列が与えられます。 このテキストに加えて、辞書の単語のコレクションが提供されます。 各クエリはテキストのセグメントを指定し、そのセグメント内の部分文字列が辞書内の単語と一致する数を数えなければなりません。 

重要な点は、すべての出来事が重要であるということです。 クエリ間隔内で単語が重複またはバラバラの位置で複数回出現する場合、それぞれの出現が個別に回答に寄与します。 これは「個別の部分文字列」に関する質問ではなく、位置に固定された一致の純粋なカウントです。 

制約が非常に厳しいため、各クエリ間隔を個別にスキャンしようとするソリューションは失敗します。 まで$5 \cdot 10^4$キャラクターと$10^5$クエリ、クエリごとのリニア スキャンでも、すでに$5 \cdot 10^9$限界をはるかに超えた最悪の場合の操作。 辞書の合計サイズは、単語の一致を繰り返しの文字列検索ではなく事前計算の問題として扱う必要があることも示唆しています。 

ここでよく見られる単純な間違いは、各クエリをすべての辞書単語に対する部分文字列検索の問題として扱っていることです。 たとえば、テキストが「ABCDABCD」で、クエリが全範囲である場合、各単語を個別に繰り返しスキャンすると、同じ文字の冗長な再スキャンが発生します。 もう 1 つの微妙な問題は、慎重に集計せずにクエリごとにローリング ハッシュを使用して最適化しようとすると、重複が正しくカウントされないことです。 

単純なクエリごとのマッチングの小さな失敗例を次に示します。 

テキスト: 「ああああ」

 単語：「A」、「AA」、「AAA」

 クエリ:$[1, 5]$正解は次のとおりです。 

5 (「A」の場合) + 4 (「AA」の場合) + 3 (「AAA」の場合) = 12

 クエリごとの単語ごとの単純なスキャンでもこれは正しく計算されますが、$10^5$クエリが実行できなくなります。 

本当の課題は、「テキスト内の一致が存在する場所」と「どのクエリがそれらをカバーするか」を切り離すことです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのクエリについて、すべての辞書単語を調べ、クエリ間隔内で出現するすべての単語を検索しようとします。 テキスト内の各単語の出現をすべて事前計算したとしても、クエリに答えるには、間隔の境界によってそれらの出現をフィルター処理する必要があります。 単語が出てきたら$k$回もあるし、$Q$ご質問があれば、最終的に確認する場合があります$O(kQ)$全体的な相互作用。 最悪の場合、単一文字のような短い単語が多数ある場合、これは基本的にすべてのクエリのすべての位置をスキャンすることになります。 

重要な構造上の観察は、有効な一致はすべてテキスト上の区間であるということです。単語の出現はセグメントに対応します。$[l, r]$。 クエリでは、以下に完全に含まれるすべてのセグメントの合計を求めます。$[L, R]$。 これにより、問題は、間隔にわたる古典的なオフライン範囲カウントの問題に変換されます。 

問題を「次のことをする必要がある」とみなしたら、$10^5$間隔と$10^5$「クエリ、各クエリ範囲内にある間隔の数を数えます。」の場合、ソリューションはエンドポイント上のスイープラインまたはフェンウィック ツリーになります。右側のエンドポイントで並べ替え、左側のエンドポイントに対して BIT を使用して昇順にクエリを処理します。 

テキスト内のすべての単語の出現を効率的に生成する必要があります。 これは、辞書単語のトライを構築し、トライを走査しながらテキストをスキャンすることによって処理されます。 合計の単語の長さは次のように制限されているため、$10^5$、実際には、組み合わせたマッチングコストは線形のままです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(Q \cdot N \cdot M)$最悪の場合 |$O(1)$番外編 | 遅すぎる |
 | 最適 |$O((N + total\_matches)\log N + Q\log N)$|$O(N + M)$| 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を間隔カウントに変換します。 

1. すべての辞書の単語からトライを作成します。 各終端ノードは、それが表す単語の長さを格納します。 これにより、テキストをスキャンするときに有効な語尾を認識できるようになります。 
2. テキストを左から右に移動します。 各ポジションで、そのキャラクターから始まるトライをたどってみてください。 終端ノードに到達するたびに、発生間隔を記録します。$[i, j]$、 どこ$i$は開始位置であり、$j$一致した単語の終了位置です。 このステップでは、テキスト内のすべての辞書一致を列挙します。 
3. 見つかったすべての間隔を右のエンドポイントで並べ替えます。 この順序により、テキスト上にポインターを移動するときに間隔を段階的にアクティブにすることができます。 
4. 各クエリを変換する$[L, R]$リクエストに含める: 満たされる間隔の数を数えます$L \le l$そして$r \le R$。 
5. クエリを適切なエンドポイントで並べ替える$R$。 間隔とクエリの両方を昇順で処理します。$R$、開始位置の上にフェンウィックツリーを維持します。 
6. 掃除中$R$左から右に、右端が$\le R$フェンウィックツリーの位置に$l$。 この構造により、位置で開始されるアクティブな間隔の数を問い合わせることができます。$\ge L$または、選択した規則に応じて接頭辞内に含めます。 
7. 各クエリについて、少なくとも開始位置を持つ挿入された間隔の数を計算します。$L$、これはクエリ範囲に完全に含まれる間隔に正確に対応します。 

フェンウィック ツリーは、幾何学的包含条件を開始のプレフィックス合計に変換します。 

### なぜ効果があるのか

 任意のスイープ位置で$R$、データ構造には、終了が現在のプレフィックス内にあるすべての間隔が正確に含まれます。 で終わるクエリの場合$R$、すべての有効な一致がすでに挿入されている必要があり、正確性は、間隔の開始が次より前かどうかをチェックすることに帰着します。$L$。 この不変条件により、各間隔がその右のエンドポイントに 1 回だけ挿入されるため、一致が見逃されず、一致が 2 回カウントされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def build_trie(words):
    nxt = [dict()]
    out = [[]]

    for w in words:
        v = 0
        for c in w:
            if c not in nxt[v]:
                nxt[v][c] = len(nxt)
                nxt.append({})
                out.append([])
            v = nxt[v][c]
        out[v].append(len(w))

    return nxt, out

def solve():
    n, m, q = map(int, input().split())
    s = input().strip()

    words = [input().strip() for _ in range(m)]

    nxt, out = build_trie(words)

    intervals = []

    for i in range(n):
        v = 0
        for j in range(i, n):
            c = s[j]
            if c not in nxt[v]:
                break
            v = nxt[v][c]
            if out[v]:
                for length in out[v]:
                    intervals.append((i + 1, j + 1))

    queries = []
    for idx in range(q):
        l, r = map(int, input().split())
        queries.append((r, l, idx))

    intervals.sort(key=lambda x: x[1])
    queries.sort()

    bit = BIT(n)
    ans = [0] * q

    ptr = 0
    for r, l, idx in queries:
        while ptr < len(intervals) and intervals[ptr][1] <= r:
            start, end = intervals[ptr]
            bit.add(start, 1)
            ptr += 1

        ans[idx] = bit.range_sum(l, n)

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```トライ構造は、すべての辞書単語をコンパクトな接頭辞構造に収集します。 テキスト スキャン フェーズでは、すべての開始位置を明示的に拡張し、不一致になるまでトライ エッジをたどり、すべての有効なエンドポイントを記録します。 辞書全体の長さは制限されているため、これでも十分効率的です。 

フェンウィック ツリーは、クエリ ウィンドウ内で開始されるアクティブな間隔の数をカウントするために使用されます。 開始位置を保存し、終了位置を増やすことで間隔をアクティブ化し、クエリが処理されるときに、関連するすべての間隔がすでに存在していることを確認します。 

微妙な点はインデックス付けです。フェンウィック ツリーは正のインデックス付けに依存しているため、BIT に挿入する前にすべてが 1 から始まるインデックスに変換されます。 

## 実用的な例

 ### サンプル 1

 テキスト:`ABCDABCDABCDABCDBCA`(概念的に)

 説明のために、一致のサブセットのみを追跡します。 

| ステップ | 間隔 | アクティブな間隔 | クエリが処理されました | ビット状態 |
 | --- | --- | --- | --- | --- |
 | 挿入 | (1,2)「AB」 | {(1,2)} | - | 開始=1 |
 | 挿入 | (2,3) 「BC」 | {(1,2),(2,3)} | - | 開始=1,2 |
 | クエリ [4,7] | R=7 を使用 | 間隔 ≤ 7 アクティブ | 計算する | カウント開始 ≥4 |

 問い合わせ用$[4,7]$、ウィンドウ内に完全に一致するもののみがカウントされ、サンプルでは 3 が生成されます。 

このトレースは、BIT が無関係な間隔を決して保存せず、現在の正しい境界の下で有効な間隔のみを集計することを示しています。 

### サンプル 2

 テキスト: すべて`A`キャラクター

 単語: 複数の重複する「A」、「AA」、「AAA」

 クエリ: 全範囲

 | ステップ | 間隔の長さ | カウントが追加されました | ビット |
 | --- | --- | --- | --- |
 | 挿入 | (1,1) | 1 | 開始=1 |
 | 挿入 | (1,2) | 1 | 開始=1 |
 | 挿入 | (1,3) | 1 | 開始=1 |

 すべての間隔は同じ開始点を共有するため、BIT はすべての寄与を位置 1 に累積します。最後のクエリでは、予想される 15 と一致する合計を取得します。 

これにより、それぞれの出現が独立した間隔の挿入であるため、重複する一致が自然に処理されることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O((N + K)\cdot L + (K + Q)\log N)$| テキストのトラバーサルと間隔とクエリのフェンウィック操作を試してみます。 
| スペース |$O(N + K)$| トライとインターバルストレージとBIT |

 境界$N, Q, M \le 10^5$スキャンとフェンウィックの操作は両方ともほぼ線形であり、対数的なオーバーヘッドが小さいため、このアプローチと互換性があります。
