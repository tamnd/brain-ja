 ## 解決策
 ## 問題の理解

 私たちは、ノードがテーマを表し、エッジがテーマ間の一方向の関係を表す有向グラフを扱っています。 グラフは、有向非循環構造を形成する既存のエッジの大規模なセットから始まり、その後、1 つずつ挿入される追加のエッジのシーケンスが与えられます。 

ノードからの新しい有向エッジごとに$u$ノードへ$v$、このエッジを追加すると、両方を含む有向サイクルが作成されるかどうかを判断する必要があります。$u$そして$v$。 このようなサイクルが現れた場合は「YES」を出力し、そうでない場合は「NO」を出力します。 回答後、エッジはグラフに永続的に追加され、今後のすべてのクエリに影響します。 

という制約が$N \le 1000$中心的な構造上の手がかりです。 まであり得るとしても$5 \cdot 10^5$初期エッジでは、ノード数が少ないため、高密度の到達可能性情報を維持することが可能であることがわかります。 クエリ数$Q \le 1000$も小さく、これは、エッジで対数または線形よりもコストがかかるクエリごとのグラフ更新を許容できることを強く示しています。 

重要な観察は、新しいエッジによってサイクルが導入されるということです。$u \to v$からのパスがすでに存在するかどうかのみに依存します。$v$に戻る$u$現在のグラフでは。 そのようなパスが存在する場合は、$u \to v$有向サイクルを閉じます。 そうでない場合は、そうではありません。 

素朴だが重要なエッジケースは、ノード間に複数の間接パスが存在する場合に発生します。 たとえば、次の場合$v \to a \to b \to u$存在する場合は追加します$u \to v$直接エッジがない場合でもサイクルを作成します$v \to u$。 ここでは、完全な到達可能性が考慮されていない限り、純粋な隣接関係ベースまたはローカルのチェックは失敗します。 

もう 1 つの微妙なケースは、更新によって将来のクエリの到達可能性が変更される場合です。 たとえば、現在のクエリがサイクルを作成しない場合でも、後のクエリに影響を与える新しい到達可能性が導入される可能性があるため、挿入のたびに推移的な構造を更新する必要があります。 

## アプローチ

 ブルート フォースのアイデアは単純です。各クエリ エッジに対して$u \to v$からグラフ検索 (DFS または BFS) を実行します。$v$到達できるかどうかを確認するために$u$。 可能であれば、エッジを追加するとサイクルが作成されます。 それ以外の場合はそうではありません。 その後、エッジを隣接リストに挿入します。 

これは正しいです。なぜなら、有向サイクルには両方が含まれるからです。$u$そして$v$まさにそのときに存在します$v$すでに到達できる$u$。 ただし、各到達可能性チェックには時間がかかるため、このアプローチはコストが高くなります。$O(N + M)$、そしてそれ以来$M$おおよそまで成長します$5 \cdot 10^5 + 1000$、全体のコストの合計$Q = 1000$Python では、特に大規模な隣接リストの走査が繰り返されるため、クエリが境界線に達するか、さらに悪化します。 

重要な洞察は次のとおりです$N$とても小さいです。 到達可能性を毎回最初から再計算する代わりに、動的推移閉包行列を維持できます。 具体的には、ブール行列を維持します。`reach[i][j]`からのパスがあるかどうかを示す$i$に$j$。 

新しいエッジのとき$u \to v$が追加されると、フォームの新しいパスを作成できます$x \to u \to v \to y$。 これは推移的な更新を示唆しています。$x$到達できる$u$、 それから$x$から到達可能なすべてのノードに到達できるようになりました$v$、同様に到達できるすべてのノード$u$にアクセスできるようになりました$v$の発信到達可能性。 これは本質的にはローカライズされた推移的閉包の更新であり、$N \le 1000$、Floyd のような増分更新はクエリごとに実現可能です。 

私たちは以下を維持します:

 -`reach[i][j] = True`もし$i$到達できる$j$- オプションで、更新の転置構造を介して逆到達可能性が暗黙的に指定されます

 エッジ挿入ごとに、接続できるようになったノードを通じて改善を伝播するだけで済みます。$u \to v$。 これは以下で行われます$O(N^2)$クエリごとに。 

以来$Q \le 1000$そして$N \le 1000$、最悪の場合の複雑さが近づいています$10^9$ブール演算。ローカル参照を使用して慎重に実装し、Python の大きなオーバーヘッドを回避すれば、最適化された Python で許容されます。

 ## アルゴリズムのチュートリアル

 私たちはすべてのノードにわたる到達可能性マトリックスを維持します。 

### ステップ

 1. 2D ブール行列を初期化する`reach`サイズの$N \times N$、必要に応じて自己到達可能性を除くすべてのエントリを false に設定します。 

次に、最初のエッジをすべて読み取り、マークを付けます。`reach[u][v] = True`。 これらのエッジは DAG を形成するため、最初はサイクルが存在しませんが、複数のエッジにより到達可能性はすでに自明ではありません。 
2. Floyd-Warshall スタイルの緩和を使用して初期推移閉包を計算します。 

すべての中間ノードに対して$k$、 もし$i \to k$そして$k \to j$、次に設定します$i \to j$。 

これにより、クエリを処理する前に、正しいベースラインの到達可能性構造が得られます。 
3. 各クエリエッジについて$u \to v$、まず次のことを確認してください。`reach[v][u]`それは本当です。 

そうであれば、からのパスがすでに存在します。$v$に戻る$u$、追加します$u \to v$両方のノードを含む有向サイクルを閉じます。 「YES」を出力します。 
4. もし`reach[v][u]`が false の場合、現時点では両方のエンドポイントを含むサイクルを形成できないため、「NO」が出力されます。 
5. 答えに関係なく、新しいエッジを挿入し、到達可能性を更新します。 

到達可能なすべてのノードが$u$～から到達可能なものすべてに到達できるようになりました$v$、同様に$v$到達可能なすべてのノードから到達可能性を継承します。$u$。 

これは、すべてのペアを反復処理することによって行われます。$(i, j)$新しく有効になった接続を介して更新します。 

### なぜ効果があるのか

 いつでも、`reach[i][j]`現在のグラフに有向パスが存在するかどうかを正確に表します。 新しいエッジを生み出す唯一の方法$u \to v$からのパスがすでに存在する場合、両方のエンドポイントを含むサイクルを作成できます。$v$に$u$。 その状態はまさに私たちがテストするものです。 

新しく導入されたすべてのパスが少なくとも 1 回は新しいエッジを通過する必要があるため、更新ステップでは正確さが維持されます。 このようなパスは、次で終わるプレフィックスに分解されます。$u$、エッジ$u \to v$、およびで始まるサフィックス$v$。 両側からの到達可能性の伝播により、そのようなすべての構成が確実に捕捉され、各挿入後に完全な推移的閉包が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    n0 = n

    reach = [[False] * n for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        reach[u-1][v-1] = True

    # Floyd-Warshall transitive closure
    for k in range(n):
        rk = reach[k]
        for i in range(n):
            if reach[i][k]:
                ri = reach[i]
                for j in range(n):
                    if rk[j]:
                        ri[j] = True

    for _ in range(q):
        u, v = map(int, input().split())
        u -= 1
        v -= 1

        if reach[v][u]:
            print("YES")
        else:
            print("NO")

        if not reach[u][v]:
            # add edge and update closure
            # copy lists for speed
            ru = reach[u]
            rv = reach[v]

            # nodes that can reach u
            for i in range(n):
                if reach[i][u]:
                    ri = reach[i]
                    # everything reachable from v becomes reachable from i
                    for j in range(n):
                        if rv[j]:
                            ri[j] = True

            # nodes reachable from v now inherit from u
            for j in range(n):
                if rv[j]:
                    ru[j] = True
```このソリューションは、コンパクトなブール隣接行列を中心に構築されています。 最初の Floyd-Warshall パスでは、クエリが開始される前にすべての間接的な到達可能性が確立されるため、各クエリは一貫したグローバル ビューに依存できます。 

更新中、最初の伝播ループは、すべての先行バージョンからの到達可能性を拡張します。$u$を通して$v$の発信構造。 2 番目のループは、到達可能性を拡張します。$u$直接。 これら 2 つの方向を合わせて、挿入されたエッジを通過する必要があるすべての新しいパスをシミュレートします。 

微妙な実装の詳細は、不必要な書き込みを回避することです。伝達するのは次の場合のみです。`reach[i][u]`または`rv[j]`は true であり、定数係数が大幅に減少します。 また、ループ内で変換が繰り返されることを避けるために、インデックス付けは全体を通して 0 ベースに保たれます。

### サンプル 1 (部分的な解釈)

 最初のいくつかのクエリは、クエリされたペア間に後方到達可能性がまだ存在しないため、非循環的です。 十分なエッジが蓄積されると、後のクエリは最終的にノードを到達可能性 DAG 内の祖先に接続し直し、「YES」を生成します。

 ## 特殊なケース

 重要なエッジ ケースは、グラフにすでに長い間接パスが含まれているものの、クエリ エンドポイント間に直接接続がない場合です。 たとえば、チェーン$1 \to 2 \to 3 \to 4$。 クエリ$4 \to 1$「YES」を返す必要があります。$1$到達する$4$間接的にですので、$4$戻って連絡できる$1$挿入後。 アルゴリズムはこれを処理します。`reach[1][4]`はクロージャ後にすでに true であるため、リバース チェックによってサイクルの形成が正しく検出されます。 

もう 1 つのケースは、到達可能性の繰り返しの強化です。 エッジの場合$u \to v$のときに追加されます$u$すでに到達しています$v$、アップデートは適用されません。 条件`if not reach[u][v]`冗長な伝播を回避し、正確性を維持しながら更新を最小限に抑えます。 

最後の微妙なケースは、複数ステップの更新による自己完結型サイクルの作成です。 どちらのエンドポイントも最初はもう一方のエンドポイントに到達しなかったとしても、中間の更新によりパスが導入される可能性があります。$v \to u$クエリの前に挿入し、後の挿入をすぐに循環させます。 常にチェックしているので`reach[v][u]`クエリ時に完全に更新されたクロージャを使用すると、この依存関係は自然に処理されます。
