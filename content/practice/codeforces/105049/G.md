 ## 解決策
 ## 問題の理解

 数直線上の 2 つの点の集合が与えられます。 最初のコレクションは、ポジションを持つパン屋で構成されます$x_1, x_2, \dots, x_N$。 2 番目は、ポジションを含むメールボックスで構成されます。$y_j$、それぞれにも重みがあります$k_j$シラノがそのメールボックスを訪問した場合に遭遇する追加の敵を表します。 

シラノは各パン屋から出発して正確に 1 回の移動を実行する必要があります。 立地のパン屋さんに$x_i$、彼は任意のメールボックスを選択します$y_j$訪問すること。 メールボックスの選択にかかる費用$j$パン屋さんから$i$旅費には次の 2 つの要素があります。$x_i \cdot y_j$、追加の固定費$k_j$あの郵便ポストで求婚者たちと戦うことから。 目標は、すべての選択肢の合計コストを最小限に抑えるために、各ベーカリーに 1 つのメールボックスを正確に割り当てることです。 

したがって、タスクはそれぞれ独立して選択することになります。$x_i$、メールボックスインデックス$j$最小化する$x_i y_j + k_j$、すべてのパン屋を合計します。 

制約$N, M \le 10^5$すべてのペアのチェックを直ちに除外します$(i, j)$、それは$10^{10}$操作。 どのソリューションも一次式の構造を利用する必要があります$x_i y_j + k_j$ペアごとの評価を避けるため。 

微妙なエッジケースはゼロ値から発生します。 もし$x_i = 0$、コストは次のように減少します。$k_j$つまり、メールボックスの重量のみが重要になります。 もしすべてなら$y_j = 0$、その後、すべてのベーカリーは最小限のメールボックスを選択します$k_j$。 ゼロ処理を無視したり、傾きが厳密に正であると仮定した単純な実装でも数学的には機能しますが、候補を誤って枝刈りすると失敗することがよくあります。 

もう 1 つの落とし穴は、すべてのパン屋にとって同じメールボックスが最適であると想定していることです。 最適な$j$に依存します$x_i$したがって、グローバル最小値$k_j$または$y_j$だけでは不十分です。 

## アプローチ

 ブルートフォースソリューションはすべてのペアを評価します$(i, j)$、コンピューティング$x_i y_j + k_j$そしてそれぞれの最小値を取る$i$。 これは問題の定義に直接従うため、正しいです。 ただし、必要なのは$O(NM)$に達する評価$10^{10}$最悪の場合、操作が不可能になり実行不可能になります。 

重要な点は、固定メールボックスの場合です。$j$、次の観点からのコスト関数$x$線形です:$$f_j(x) = x \cdot y_j + k_j$$各メールボックスは回線を定義します。 各ベーカリーの値について$x_i$、その時点のすべての行にわたる最小値が必要です$x_i$。 これはまさに動的な凸包トリック クエリ問題です。静的に追加された行があり、多くのクエリをクエリします。$x$-コーディネート。 

ただし、さらに簡略化されています。 動的に行を維持する必要はありません。 傾きによって並べ替えることができます$y_j$そして線の凸包を構築します。 傾きは静的であるため、すべての行を一度に前処理して、すべてのクエリに効率的に答えることができます。 

クエリはソートされていないため、ベーカリーを次の基準でソートできます。$x_i$、それらを昇順に処理し、償却定数時間で各クエリに答えるために凸包上のポインタを維持します。 

全体的な構造は次のようになります。傾きによってソートされた線の下側の凸包を構築し、クエリを昇順でスイープします。$x_i$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース |$O(NM)$|$O(1)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 各メールボックスを解釈します$j$傾きのある線として$y_j$そしてインターセプト$k_j$、各パン屋さん$i$質問点として$x_i$。 

### 1. メールボックスの行を傾きで並べ替えます

 メールボックスを増加順に並べ替えます$y_j$。 これにより、凸包を構築するときに、凸性を効率的に維持するために必要な、勾配が単調な順序で処理されることが保証されます。 

### 2. 線の下側の凸包を構築する

 ソートされたメールボックスを反復処理し、候補行のスタックを維持します。 新しい行ごとに、最後の行が今後のすべてのクエリに無関係になった場合、スタックから削除します。 これは、船体の最後の 2 つのラインと新しいラインの間の交差比較を使用してチェックされます。 

これが機能する理由は、どの行でも最小にならないためです。$x$安全に廃棄できます。 

### 3. ベーカリーをクエリとして処理する

 ベーカリーを次の基準で分類します$x_i$。 それぞれについて$x_i$、凸包へのポインターを維持します。 として$x_i$増加すると、最適なライン インデックスは船体に沿って単調に移動します。 

コストを評価します$x_i y_j + k_j$現在の最良の行のみを対象とし、次の行の値が小さい場合はポインタを進める可能性があります。 

### 4. 答えを蓄積する

 各ベーカリーについて、モジュロを使用して、見つかった最良のコストを合計に加算します。$10^9+7$。 

### なぜ効果があるのか

 各メールボックスは線形関数を定義しており、問題は一連の線にわたって点ごとの最小値を取ることに帰着します。 これらの線の下側の包絡線は、すべての最適な選択を完全に特徴づけています。 傾きとクエリの両方をソートすると、単調性を利用できます。つまり、ラインが最適でなくなると、より大きなラインでは再び最適になることはありません。$x$。 これにより、各行の追加と削除が最大 1 回行われること、および各クエリでポインタが最大 1 回進むことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def bad(l1, l2, l3):
    # check if l2 is unnecessary between l1 and l3
    # (k2 - k1)/(y1 - y2) >= (k3 - k2)/(y2 - y3)
    y1, k1 = l1
    y2, k2 = l2
    y3, k3 = l3
    return (k2 - k1) * (y2 - y3) >= (k3 - k2) * (y1 - y2)

def eval_line(line, x):
    y, k = line
    return y * x + k

def solve():
    N, M = map(int, input().split())
    x = [int(input()) for _ in range(N)]
    mail = [tuple(map(int, input().split())) for _ in range(M)]

    mail.sort()  # sort by slope y

    # build convex hull
    hull = []
    for line in mail:
        while len(hull) >= 2 and bad(hull[-2], hull[-1], line):
            hull.pop()
        hull.append(line)

    # queries sorted
    queries = sorted(x)

    ans = 0
    j = 0

    for xi in queries:
        while j + 1 < len(hull) and eval_line(hull[j + 1], xi) <= eval_line(hull[j], xi):
            j += 1
        ans = (ans + eval_line(hull[j], xi)) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、メールボックスの前処理がベーカリー クエリから分離されます。 の`bad`関数は、浮動小数点除算を避けるためにクロス乗算を使用してハルを構築するときに冗長な線を削除します。 

ポインタ`j`ソートされたクエリは最適な行インデックスの単調性を保証するため、前方にのみ進みます。 これが線形クエリ処理の鍵です。 

微妙な点の 1 つは、乗算は 32 ビットの範囲を超える可能性があるため、Python の任意精度で安全に処理されますが、より厳密な言語では 128 ビットの整数が必要になることです。

 ## 特殊なケース

 いつすべて$x_i = 0$、コストは勾配に依存せず、最小の値を選択することになります。$k_j$あらゆるパン屋さんに。 すべてのラインがその切片を評価し、船体が最小切片ラインを維持するため、アルゴリズムは引き続きこれを処理します。$x = 0$。 

いつすべて$y_j = 0$、どの行も一定です。 船体は最小限のラインまで縮小します$k_j$、すべてのクエリは同じ値を返します。 すべての評価が一貫して一致するため、ポインター ロジックが壊れることはありません。 

同じ傾きの郵便受けが複数ある場合$y_j$、最小のもののみ$k_j$船体の建造は生き残る。 の`bad`チェックにより、冗長な行が確実に削除され、誤った優位性が防止されます。 

いつ$x_i$値はソートされていませんが、ソートによりハルの単調な走査が保証されます。 ソートを行わないと、ポインタの動きが単調でなくなり、償却保証を破り、スキャンが繰り返される可能性があります。
