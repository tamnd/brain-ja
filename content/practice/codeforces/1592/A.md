 ## 解決策
 ## 問題の理解

 ゲーム内のエージェントが、それぞれ固定ダメージを持つ一連の武器を使用して、特定の体力を持つ敵をどれだけ早く倒すことができるかを判断することが求められます。 エージェントは複数回攻撃できますが、同じ武器を連続して 2 回使用することはできません。 入力は、いくつかの独立したテスト ケースを提供します。 各テスト ケースでは、武器の数、敵の初期体力、各武器のダメージ値を指定します。 各テスト ケースの出力は、敵の体力をゼロ以下にするために必要な攻撃の最小数です。 

制約により、テスト ケースは最大 100,000 個あることがわかりますが、各テスト ケースに含まれる武器は最大 1,000 個で、すべてのテスト ケースにわたるすべての武器の合計は最大 200,000 個になります。 体力とダメージの値は非常に大きくなり、最大 10 億にも達します。 これにより、大きなヘルス値に対して各攻撃を 1 つずつシミュレートするソリューションは除外されます。これには数十億の操作が必要になるためです。 代わりに、武器のダメージの特性を使用して数学的に答えを計算する戦略が必要です。 

単一の武器のダメージが敵の体力以上である場合、明らかではないエッジケースが発生します。 この場合、より高いダメージを与える別の武器があったとしても、必要な攻撃は 1 つだけです。 武器を交互に使用することを常に前提とする不用意な実装は、移動数を過剰にカウントします。 2 つの最強の武器を組み合わせても敵の体力を正確に分割できない場合、別の特殊なケースが発生します。 ここで、最も強いペアを繰り返した後の残りの体力には、最も強い武器による追加の攻撃が 1 回必要になる場合があります。 

## アプローチ

 素朴なアプローチは、攻撃プロセスをシミュレートすることです。 以前の武器とは異なる最も強力な武器を繰り返し選択し、敵の体力からそのダメージを差し引くことができます。 これは正しいですが、ヘルス値が大きい場合 (最大 10^9)、ループが何十億回も繰り返される可能性があるため、非常に遅くなり、実行不可能になります。 

重要な洞察は、ダメージ値が最も高い 2 つの武器のみが重要であるという認識から得られます。 最強の武器にダメージを与えよう`max1`そして二番目に強いのは`max2`。 エージェントが最適に攻撃すると、これら 2 つの武器を交互に使用してダメージを最大化します。 2 回の移動での合計ダメージは、`max1 + max2`。 ヘルス値が大きい場合は、整数除算を使用して完全な 2 つの移動サイクルが何回必要かを計算し、残りのヘルスを 1 つまたは 2 つの追加の移動で処理できます。 これにより、各攻撃をシミュレートするのではなく、問題を 2 つの最大値を使用した単純な計算に削減します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(H / 最小ダメージ) | お(1) | 遅すぎる |
 | 最適 | テスト ケースごとの並べ替えの場合は O(n log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テストケースについて、武器の数を読み取ります。`n`そして敵の健康状態`H`。 武器のダメージ値を配列に読み取ります。 
2. 配列から最大の 2 つのダメージ値を見つけます。 並べ替えは便利で簡単です。降順で並べ替え、最初の 2 つの値を取得します。 させて`max1`最大であり、`max2`2番目に大きいものになります。 
3. 最強の武器だけで敵を倒すのに十分かどうかを確認します。 もし`max1 >= H`の場合、攻撃は1回で十分なので答えは1です。 
4. それ以外の場合は、必要な完全な 2 移動サイクルの数を計算します。 各サイクルは次のことを行います`max1 + max2`ダメージ。 整数除算を使用します。`full_cycles = H // (max1 + max2)`。 
5. これらの全サイクル後の残りのヘルスを計算します。`remaining = H - full_cycles * (max1 + max2)`。 
6. 敵を倒すために必要な追加の手を決定します。 もし`remaining`が 0 の場合、追加の移動は必要ありません。 もし`remaining <= max1`、最強の武器でもう一回攻撃すれば十分です。 それ以外の場合は、さらに 2 つの攻撃 (最も強い、次に 2 番目に強い) が必要です。 
7. 全サイクルの移動 (各サイクルは 2 移動) と追加の移動を合計して、テスト ケースの最小移動数を取得します。 

機能する理由: 2 つの最強の武器を交互に使用すると、1 組の動きごとに最大のダメージが保証され、これは常に他の武器シーケンスの選択と少なくとも同じくらい高くなります。 残りを個別に処理することで、完全なサイクルではカバーできない残りのヘルスを考慮します。 このアプローチにより、手を過剰にカウントしたり過小カウントしたりすることがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, H = map(int, input().split())
    weapons = list(map(int, input().split()))
    weapons.sort(reverse=True)
    max1, max2 = weapons[0], weapons[1]

    if max1 >= H:
        print(1)
        continue

    full_cycles = H // (max1 + max2)
    remaining = H - full_cycles * (max1 + max2)

    moves = full_cycles * 2
    if remaining == 0:
        print(moves)
    elif remaining <= max1:
        print(moves + 1)
    else:
        print(moves + 2)
```このソリューションは、次を使用して入力をすばやく読み取ります。`sys.stdin.readline`。 武器のダメージを並べ替えると、最も強い 2 つの値が得られます。 早期終了が一般的であるため、最初に単一攻撃のケースを処理します。 全サイクルと残りの計算により、ヘルス値が大きい場合に法外に遅くなる各動きを個別にシミュレートすることを回避できます。 残りをチェックすることで、全サイクル後に追加の攻撃が 1 つだけ必要になるというエッジ ケースを正しく処理できるようになります。
