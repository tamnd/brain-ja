 ## 解決策
 ## 問題の理解

 整数の配列と要素の交換に関する制限が与えられます。2 つの要素の位置が少なくとも異なる場合にのみ、2 つの要素を交換できます。`x`。 ここでのタスクは、この制約の下で配列を非降順でソートできるかどうかを判断することです。 各テスト ケースでは配列と値を指定します。`x`。 

最初の観察は、次のような場合です。`x`配列の長さに比べて大きい場合、一部の位置は事実上「ロック」されます。 たとえば、次の場合`x = n`、スワップはまったく不可能であるため、配列はすでにソートされている必要があります。 逆に、もし`x = 1`、制限はなく、任意のスワップを実行できます。つまり、いつでも配列をソートできます。 厄介なケースが起こるのは、`1 < x < n`、特定のポジションのみが対話できるためです。 

制約は次のことを教えてくれます`n`まで可能です`10^5`テストケースごと、およびすべての合計`n`すべてのテスト ケースで最大でも`2 * 10^5`。 これは、より複雑なソリューションを意味します。`O(n log n)`テストケースごとの処理は遅すぎる可能性があります。 スワップのすべてのシーケンスを試す単純なアプローチでは、指数関数的になるため、まったく実行不可能です。 

明らかではないエッジ ケースは、配列がほぼソートされているにもかかわらず、最小または最大の要素が中央にトラップされ、次の理由により十分に移動できない場合に発生します。`x`制限。 たとえば、次のように考えてみましょう`[3, 2, 1]`と`x = 3`。 配列は十分に小さいため、スワップは許可されないため、ほとんどソートされていますが、答えは「いいえ」です。 もう 1 つの注意が必要なシナリオは配列です。`x`よりもわずかに小さいです`n/2`、端と相互作用できない中間セグメントが残ります。 

## アプローチ

 ブルートフォースアプローチは簡単です。配列がソートされるか、すべての可能性がなくなるまで、すべての構成で許可されているすべてのスワップを試します。 最終的には到達可能なすべての順列を探索するため、これにより正確さが保証されます。 ただし、スワップの数は指数関数的に増加します。`n`、したがって、`n = 20`実用的ではなくなります。 

重要な観察は、少なくとも次の位置にある要素のみが`x`離れて交換できます。 もし`x <= n/2`の場合、開始付近のすべての要素は、場合によっては一連のスワップを通じて、最終的には終了近くのすべての要素に到達する可能性があります。 ただし、長さの中間領域の要素`n - 2*x`拘束されている: 次の場合、端に到達するまで十分に移動することができません。`x > n/2`。 したがって、配列がこれらの中間位置でまだソートされていない場合、ソートは不可能です。 

最適なソリューションは、配列を完全にソートされたバージョンと比較することでこれを利用します。 端に到達できない各要素 (「固定」中間セグメント) がすでに正しい位置にあるかどうかを確認するだけで済みます。 このような要素がすべてソートされた配列と一致する場合、ソートは可能です。 それ以外の場合はそうではありません。 これにより、スワップをシミュレートする必要がなく、ソート後の単純な比較に問題が軽減されます。

 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。`n`、`x`、および配列`a`。 
2. Create a sorted version of the array,`sorted_a`。 This represents the target arrangement.
 3. もし`x <= n/2`、すべての要素は最終的に任意の位置に交換できます。 この場合は直ちに「YES」を返してください。 
4. それ以外の場合、ポジションについて`i`から`n - x`に`x - 1`(端に到達できない「中間」セグメント)、次のことを確認します。`a[i] == sorted_a[i]`。 異なる要素がある場合は「NO」を返します。 
5. 中間セグメントのすべての位置がソートされた配列と一致する場合は、「YES」を返します。 

機能する理由: 中間セグメントの外側の要素は、許可されたスワップを介して端に到達するまで自由に移動できます。 中央のセグメントは事実上、相対的な順序で固定されます。 これらの固定位置をソートされた配列と照合することで、実現可能性を判断します。 この不変条件により、スワップをシミュレートせずに正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_sort(n, x, a):
    sorted_a = sorted(a)
    if x <= n // 2:
        return "YES"
    for i in range(n - x, x):
        if a[i] != sorted_a[i]:
            return "NO"
    return "YES"

t = int(input())
for _ in range(t):
    n, x = map(int, input().split())
    a = list(map(int, input().split()))
    print(can_sort(n, x, a))
```機能`can_sort`コアロジックを捉えています。 まず配列をソートしてターゲットの位置を確認します。 のために`x <= n//2`、任意の配列をソートできるため、すぐに「YES」を返します。 大型の場合`x`では、拘束された中間セグメントのみをチェックします。 使用する`range(n - x, x)`十分に移動できないインデックスを正確に選択します。 ここでの off-by-one エラーは、エッジ ケースでは黙って失敗するため、包含境界と排他境界に注意することが重要です。 

## 実用的な例

 **例 1**

 入力:`n = 3, x = 3, a = [3, 2, 1]`| 私 | a[i] | ソート済み_a[i] | 比較 |
 | --- | --- | --- | --- |
 | 0 | 3 | 1 | 不一致 |
 | 1 | 2 | 2 | 一致 |
 | 2 | 1 | 3 | 不一致 |

 以来`x = n`、中央のセグメントは配列全体です。 不一致が存在します。出力は「NO」です。 

**例 2**

 入力:`n = 5, x = 2, a = [5, 1, 2, 3, 4]`ここ、`x <= n//2`は false なので、中間インデックスを確認してください`n-x`に`x-1`→`i = 3 to 1`→ 空の範囲、チェックする位置がありません。 「YES」を出力します。 

このトレースは、中間セグメントのチェックが実行不可能な構成を直接特定し、可動位置を無視する方法を示しています。

 ## 特殊なケース

 配列の長さが等しい場合`x`、交換はできません。 のために`[3, 2, 1]`と`x = 3`、中央のセグメントは完全な配列であり、ソートされていません。 アルゴリズムはすべての位置をチェックし、「NO」を出力します。 

のために`x <= n//2`、 のような`[5, 1, 2, 3, 4]`と`x = 2`、中央のセグメントは事実上空です。 すべての要素は自由にシャッフルできるため、関数は「YES」を出力します。 

要素が繰り返される配列の場合、例:`[1, 2, 2, 1]`と`x = 3`を使用すると、アルゴリズムは中間セグメントの位置を調整する必要があるかどうかを正確に識別し、誤検知を回避します。
