 ## 問題の理解

 円形の火星のコロニー上の都市の位置のリストが与えられます。都市には法で番号が付けられています。$10^9+7$。 各クエリは、固定長の道路を使用して特定の部分配列内のすべての都市を接続できるかどうかを尋ねます。$D$。 長い道路と接続する$D$つまり、接続されている 2 つの都市を選択すると、$x$そして$y$、 違い$|x-y|$モジュロ$10^9+7$で割り切れる必要があります$D$。 目標は、連続する各ペアが正確に異なるような都市の順序が存在する場合に「はい」と答えることです。$D$モジュロ$10^9+7$、それ以外の場合は「いいえ」。 

制約は大きく、最大で$2 \cdot 10^5$都市とクエリ。これにより、都市の配置のブルートフォース順列チェックが排除されます。 単純な方法でサブ配列を反復処理するソリューションは、次のような結果になります。$O(N \cdot Q)$操作、潜在的に$4 \cdot 10^{10}$、実現可能性をはるかに超えています。 

この問題の明らかではない側面は、都市が繰り返される可能性があり、配列がソートされていないことです。 不用意なアプローチでは、たとえば、最初と最後の都市が次の倍数異なるかどうかを確認するだけになる可能性があります。$D$, しかし、都市間の内部差異が距離要件に違反する場合、これは失敗します。 たとえば、都市について考えてみましょう`[0, 3, 6]`そして$D=3$。 どのサブ配列も機能しますが、サブ配列が`[0, 6]`エンドポイントのみを使用した単純なチェックでは、誤って「いいえ」と答えてしまう可能性があります。$6-0$は 3 で割り切れますが、配列が`[0, 4, 8]`そして$D=2$、エンドポイントのみを見ると、誤って「はい」と表示されますが、$4-0=4$そして$8-4=4$はどちらも 2 で割り切れるので、この場合は実際に機能します。 エッジ ケースには、単一の都市を含むサブ配列、またはすべての都市が同一である場合が含まれます。$D$動作します。 

## アプローチ

 ブルート フォース アプローチは簡単です。クエリごとに、部分配列を反復処理し、連続する都市間のすべての差異をチェックし、それぞれの差異がモジュロであることを確認します。$10^9+7$で割り切れます$D$。 This is correct because the problem directly asks for divisibility of distances, but it is too slow. 各部分配列が長さの場合$N$最悪の場合、$Q$クエリの結果、$O(N \cdot Q) \sim 4 \cdot 10^{10}$操作。 

重要な点は、すべてのペアを考慮する必要はないということです。 必要なのは、サブ配列内のすべてのペアごとの差の最大公約数 (GCD) だけです。 これらの差の GCD が次で割り切れる場合、$D$そうすると、道路の長さに合わせて都市を順番に配置することが可能になります。$D$。 これが機能するのは、シーケンスを任意に並べ替えることができるためです。 GCD は、すべての都市間に存在する最も細かい共通間隔をキャプチャします。 配列内の差異のプレフィックス GCD を事前計算することで、次の各クエリに答えることができます。$O(\log N)$セグメントツリーまたはスパーステーブルを使用します。 これにより、全体的な複雑さが実現不可能なものから軽減されます。$O(NQ)$実現可能に$O(N \log N + Q \log N)$。

 ## アルゴリズムのチュートリアル

 1. 連続する都市間のすべての差を法で計算します。$10^9+7$。 アレイの場合`a`、 作成する`diff[i] = (a[i+1] - a[i]) % MOD`。 これにより、道路建設のために位置合わせする必要がある有効距離が把握されます。 
2. スパーステーブルを構築する`diff`GCD クエリの場合。 これにより、差の部分配列の GCD を計算できます。$O(1)$クエリごとに。 
3. クエリごとに`(L, R, D)`、インデックスから部分配列を検討します`L-1`に`R-1`。 差の GCD を計算する`diff[L-1:R-1]`。 
4. この GCD が次で割り切れる場合`D`、「はい」を出力します。 それ以外の場合は「いいえ」を出力します。 
5. 単一要素のサブアレイは、接続するギャップがないため、自明に「はい」になります。 

機能する理由: 部分配列内のすべての連続する差分の GCD を取得することで、都市間の最小間隔を取得します。 この間隔が次の数で割り切れる場合は、`D`そうすると、各接続が正確に一致するように都市をレイアウトすることが可能になります。`D`。 モジュロにより、オーバーフローすることなく円形構造が正しく処理されることが保証されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

MOD = 10**9 + 7

def build_sparse_table(arr):
    n = len(arr)
    K = n.bit_length()
    st = [[0]*n for _ in range(K)]
    st[0] = arr[:]
    for k in range(1, K):
        for i in range(n - (1 << k) + 1):
            st[k][i] = math.gcd(st[k-1][i], st[k-1][i + (1 << (k-1))])
    return st

def query(st, l, r):
    k = (r - l + 1).bit_length() - 1
    return math.gcd(st[k][l], st[k][r - (1 << k) + 1])

def main():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    if n > 1:
        diff = [(a[i+1] - a[i]) % MOD for i in range(n-1)]
        st = build_sparse_table(diff)
    else:
        diff = []
        st = []

    for _ in range(q):
        L, R, D = map(int, input().split())
        L -= 1
        R -= 1
        if L == R:
            print("Yes")
            continue
        g = query(st, L, R-1)
        print("Yes" if g % D == 0 else "No")

if __name__ == "__main__":
    main()
```このソリューションでは、まず連続的な差分を事前計算して、潜在的な距離を取得します。 スパース テーブルでは、クエリごとに O(1) で GCD クエリを実行できます。 単一要素のサブ配列は、空の範囲を避けるために個別に処理されます。 インデックスから 1 を減算すると、インデックスが 0 から始まる Python リストに揃えられます。 モジュロ演算により、円形の都市位置を適切に処理できるようになります。
