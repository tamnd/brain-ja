 ## 解決策
 ## 問題の理解

 配列が与えられています$B$これは、未知の元の配列に奇妙なプロセスが適用された結果であると主張されています$A$。 このプロセスは、次の 2 つの位置を繰り返し選択することで機能します。$A$(ステップ間で繰り返すことができ、同じインデックスを何度も再利用できます)、選択した値を合計し、その合計を新しい配列に追加します。 これを正確に実行した後、$N$回、出力配列を取得します$B$長さの$N$。 

タスクは、整数配列が存在するかどうかを判断することです。$A$それは与えられたものを生み出すことができたでしょう$B$、そうであれば、有効な候補を 1 つ構築します。 

重要な構造上の制約は、すべての要素が$B$同じ未知のマルチセットからの 2 つの要素の合計です$A$、同じペアリングは操作全体で固定されません。 これは、1 回限りの変換を再構築するのではなく、次のことを確認していることを意味します。$B$固定の基礎となる配列から抽出されたペアごとの合計のマルチセットとして解釈できます。 

制約$N \le 1000$そして$B_i \le 10^6$と提案する$O(N^2)$または$O(N^2 \log N)$方法はもっともらしいですが、より高い累乗やすべてのペアの完全な組み合わせ再構築を伴うものは遅すぎます。 ペアへの合計の代入に対する三次探索はすでに次の値を超えます。$10^9$操作。 

重要な点は、このプロセスによりインデックスの再利用が可能になり、素のペアが一致するという概念がなくなることです。 素朴な解釈は、それぞれのことを誤って仮定することがよくあります。$B_i$の一意のペアに対応します$A$、これにより問題は完全に一致する再構成に変わります。 その解釈は間違っており、不必要な複雑さをもたらします。 

2 番目のエッジ ケースは、次のすべての値が存在する場合に発生します。$B$等しいです。 多くの解が存在するように見えるかもしれませんが、実際には、すべてのペアごとの合計が何らかの構造化された方法で一致する必要があるため、システムは高度に制約されます。 たとえば、次の場合$B = [5,5]$、 それから$A$満たさなければなりません$a_i + a_j = 5$選択したペアに対して一貫して。 

## アプローチ

 直接的な総当たりのアイデアは、元の配列を推測しようとすると仮定することです$A$ですべての値を生成できるかどうかを確認します。$B$からペアを選択して$A$。 これは、候補者が固定された場合でもすぐに手に負えなくなります。$A$の有効な割り当てが存在するかどうかを確認します。$N$間のペア$N$繰り返しが許可された要素は、$O(N^2)^N$最悪の場合の可能性も。 

単純化の鍵となるのは、視点を逆転させることです。 構築することを考えるのではなく、$B$から$A$、それぞれを解釈します$B_i$次の形式の線形制約を強制します。$$a_{x_i} + a_{y_i} = B_i$$未知のインデックスの選択について$x_i, y_i$。 目標は、これらすべての方程式を同時に満たすインデックスと値の割り当てを見つけることです。 

重要な点は、インデックスは自由に再利用できるため、一致する構造を強制されないということです。 これにより、システムをグラフのラベル付け問題のように動作するものに折りたたむことができます。つまり、変数の小さなセットに値を割り当て、すべての方程式にわたる一貫性を確保します。 

1 つの要素を任意に固定し、他のすべての要素をその要素に対して相対的に表現できます。 各方程式は制約伝播ルールになります。 1 つの変数に値を割り当てると、合計内でその変数が出現するたびに、その相手の値が決まります。 これにより、問題は、ペア和方程式系に一貫したラベル付けが存在するかどうかをチェックすることに帰着します。 

最適な戦略は、未知のノード値とエッジ制約を持つグラフを定義するものとして方程式を解釈しようとする構造を仮定することです。 次に、値を貪欲に割り当て、伝播する際に一貫性を検証します。

 ## アルゴリズムのチュートリアル

 1. それぞれの値を解釈します$B_i$方程式として$a_u + a_v = B_i$、 どこ$u$そして$v$元の配列内の未知のインデックスです。 目標は、インデックスと値の両方を一貫して割り当てることです。 
2. まず、1 つの方程式を選択し、その方程式に対して 2 つの指数を任意に選択します。 自然な出発点は、最初の方程式を 2 つの変数を定義するものとして扱うことです。$a_0$そして$a_1$、次のような値を割り当てます。$a_0 = 0$、$a_1 = B_0$。 この選択は特別なものではありません。 それは単にシステムを固定するだけです。 
3. 残りのすべての方程式について、すでに発見されている変数の中のインデックスのペアにそれを割り当てようとします。 両方のインデックスが既知の場合は、それらの合計の一貫性を検証します。 正確に 1 つがわかっていれば、もう 1 つを推定します。 何も不明な場合は、新しい変数ペアを作成し、次と一致する値を割り当てます。$B_i$。 
4. 方程式を処理する際、インデックスから値へのマッピングを維持します。 新しい値を導出するたびに、それが以前に割り当てられた値と競合するかどうかを確認します。 矛盾が出た場合は無理として終了させて​​いただきます。 
5. すべての方程式を矛盾なく処理できれば、構築された値は有効な元の配列を形成します。$A$。 

重要な点は、エッジが対応するグラフ上に線形制約のシステムを効果的に構築していることです。$B_i$価値観。 各接続コンポーネントは任意に固定でき、他のすべての値は強制されます。 

### なぜ効果があるのか

 各方程式は 2 つの変数の合計を制限します。 連結成分内の 1 つの変数が固定されると、他のすべての変数は置換を繰り返すことで決定されます。 インデックスの再利用が許可されているため、方程式が一致する構造や非循環構造を形成する必要はありません。 すべての有効な解決策は、この制約グラフ内の一貫した割り当てに対応します。 矛盾が生じた場合、それは方程式系が同じ変数に対して 2 つの異なる値を暗示していることを意味し、再構成が不可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    b = list(map(int, input().split()))

    # We will build a constructive assignment.
    # Use two base variables repeatedly.
    # A simple consistent model is to assign pairs sequentially.

    a = [0] * n

    # Anchor first two values
    a[0] = 0
    a[1] = b[0]

    # Now we interpret each b[i] as a sum of some pair.
    # We alternate using indices 0 and 1 to generate valid structure.

    for i in range(1, n):
        if i % 2 == 1:
            # use (0, i) pairing logic
            a[i] = b[i] - a[0]
        else:
            # use (1, i) pairing logic
            a[i] = b[i] - a[1]

    # Verify consistency
    vals = []
    for i in range(n):
        for j in range(i + 1, n):
            vals.append(a[i] + a[j])

    vals.sort()
    b_sorted = sorted(b)

    if vals[:n] == b_sorted:
        print("YES")
        print(*a)
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```この実装では、2 つの初期値を固定し、指定された合計制約の 1 つを満たすように 1 つおきの要素を割り当てることで候補配列を構築します。 これは、生成されたペアの合計をマルチセットと一致させようとするヒューリスティックな再構成です。$B$。 

検証ステップでは、構築された値からすべてのペアごとの合計を計算します。$A$そしてそれらを比較します$B$。 複数の割り当てはローカルの制約は満たしても、グローバルでは失敗する可能性があるため、これは不可欠です。 

微妙な点は、最初から正確なインデックスのペアを割り当てようとしていないことです。 代わりに、任意のペアを複数回使用できる柔軟性を利用し、構築された配列を事後的に検証できるようにします。

 ## 特殊なケース

 重要なエッジケースは、すべての要素が$B$は同一です。 その状況では、すべての方程式で同じ合計制約が適用されます。 このアルゴリズムは事実上、その合計を一貫して再現する値のペアを見つけることに集約されます。 通常、構築は対称性によって成功しますが、検証によって正確さが保証されます。 

もう 1 つのエッジケースは次のような場合です$B$次のような、矛盾した割り当てを強制する値が含まれています。$B = [1, 2, 100]$。 一貫したペアの合計を割り当てようとすると、検証中にすぐに不一致が発生します。これは、固定されたペア構造ではそのような広範囲にわたる合計を生成できないためです。 

3 番目のケースは最小の入力です$N = 2$。 ここで問題は、合計が次の両方のエントリに等しい 2 つの数値が存在するかどうかをチェックすることに帰着します。$B$。 これは、両方のエントリが等しく、有効なエントリが存在する場合にのみ可能です。$A$は単純にその値を合計した単一のペアです。
