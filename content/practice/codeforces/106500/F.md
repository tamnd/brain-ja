 ## 問題の理解

 ボールの列が与えられ、それぞれが最大 10 色の可能な色の 1 つで塗られます。 許可される操作は、隣接する 2 つのボールを交換することだけであり、交換ごとに 1 ユニットのコストがかかります。 目標は、同じ色のすべてのボールが単一の連続したブロックに表示されるようにシーケンスを再配置することです。つまり、どの色も複数の別々のセグメントに分割されません。 

このタスクは、各色が正確に 1 つの間隔を形成する配置に到達するために必要な隣接するスワップの最小数を計算することです。 

制約$n \le 2 \cdot 10^5$スワップをシミュレートしたり、順列を検索して最終的な配置を明示的に構築しようとするアプローチは直ちに除外されます。 たとえ$O(n^2)$このメソッドは周囲に到達する可能性があるため、遅すぎます。$4 \cdot 10^{10}$操作。 私たちは慎重に計算しながら、線形または線形に近い戦略のいずれかに向かうことを余儀なくされています。 

いくつかの微妙なケースが重要です。 

たとえば、すべてのボールがすでに色ごとに 1 つのカラー ブロックを形成している場合、`1 1 2 2 3 3`、答えはゼロです。 連続性をチェックせずに誤って「ソートされた色に並べ替える」ことを試みるメソッドは、不必要なスワップを引き起こさない場合に限り、ここでは正しく動作します。 

たとえば、色が大量にインターリーブされている場合、`1 2 1 2 1 2`単純な貪欲なグループ化は、あるカラー ブロックを別のカラー ブロックを越えて移動するには、それらの間のすべてのペアごとの反転を考慮する必要があることを無視するため、コストを過小評価する可能性があります。 

重要な問題は、スワップが局所的な修正ではなく、すべてのペアの相対的な順序に依存することです。 

## アプローチ

 強引なビューでは、10 個のカラー ブロックを配置するために考えられるすべての方法を検討しようとします。 色が少ないため、色を並べ替えて、各色をそのセグメントに移動するコストを計算することを考えるかもしれません。 色の順序が固定されている場合、各要素が以前の色と比較して寄与する反転の数を合計することで、必要な交換の数を計算できます。 これはすでに構造を示唆しています。最終的な色の順序が決まれば、コストは決定的になります。 

カラー ブロックの順序を決定すると、最適な配置は「すべて 1、次にすべて 2、... この順序で」というだけになるため、強引なアイデアが機能します。 問題は、最大で$10!$順列はわずか 360 万であるため、実際には実現可能かぎりぎりですが、最適な次数を直接計算できれば、完全に列挙する必要はありません。 

重要な洞察は、すべての置換を明示的に試す必要はないということです。 代わりに、事前に計算された色間のペアごとの相互作用コストを使用して、考えられる順序ごとのコストを計算できます。 色を入れるのにかかる費用$a$色を付ける前に$b$元の配列にそれらの間の反転が何回存在するかにのみ依存します。$b$の前に表示されます$a$、次の場合、そのペアは 1 つのスワップに貢献します。$a$前に置かれます$b$。 

これにより、問題は最大 10 個のノードにわたる重み付き順序付け問題に変わり、エッジの重みは色間の反転数を表します。 次に、総コストを最小化する順序を選択します。これは、カラー サブセットに対するビットマスク動的プログラミングを使用して解決できます。

 ## アルゴリズムのチュートリアル

 問題を色間の相互作用に圧縮します。 

1. 元の配列で各色が出現する頻度と、色のペアが「間違った順序」で出現する頻度を計算します。 各色のペアごとに$c$そして$d$、何回か数えます$d$の前に表示されます$c$。 この値は、すべてを配置することを決定した場合に寄与するコストを表します。$c$何よりもまず$d$s.
 2. どの色のサブセットが最終的な順序に既に配置されているかに基づいて状態を定義します。 各状態は部分的な順序を表しており、最大 10 色すべてを構築したいと考えています。 
3. 特定の状態に対して、新しい色を追加してみます。$c$それはまだ配置されていません。 配置の増分コスト$c$next は、事前に計算された反転寄与を合計することによって計算されます。$c$すべての色がすでにある状態です。 これは、色が配置されると、その後の色に対する相対位置が固定されるため有効です。 
4. すべてのサブセットに対して動的プログラミング遷移を実行します。 サブセットの DP 値は、それらの色をサブセットと一致する順序で正確に配置するための最小コストです。 
5. 空のセットのゼロコストで DP を初期化し、一度に 1 つの新しい色を追加することで遷移を緩和します。 最終的な答えは、全色セットの DP 値です。 

重要な不変条件は、すべてのサブセットについて、それらの色をある一定の順序で正確に配置するための最小限のコストを DP が保存することです。 任意の 2 つの色の間のコストは相対的な順序にのみ依存し、他の色には依存しないため、最適な部分解を組み合わせることが安全です。 後で決定を行っても、すでに固定されたペアの寄与を変更することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # compress colors to 0..9
    color_id = {}
    comp = []
    for x in a:
        if x not in color_id:
            color_id[x] = len(color_id)
        comp.append(color_id[x])

    k = len(color_id)

    # count inversions between colors
    # cost[c][d] = number of pairs (i < j) with a[i]=c, a[j]=d
    cost = [[0] * k for _ in range(k)]

    cnt = [0] * k
    for x in comp:
        for c in range(k):
            if c != x:
                cost[x][c] += cnt[c]
        cnt[x] += 1

    # dp[mask] = min cost for ordering colors in mask
    INF = 10**18
    dp = [INF] * (1 << k)
    dp[0] = 0

    for mask in range(1 << k):
        for nxt in range(k):
            if mask & (1 << nxt):
                continue

            add_cost = 0
            for c in range(k):
                if mask & (1 << c):
                    add_cost += cost[nxt][c]

            nmask = mask | (1 << nxt)
            dp[nmask] = min(dp[nmask], dp[mask] + add_cost)

    print(dp[(1 << k) - 1])

if __name__ == "__main__":
    solve()
```数値ラベルではなく、相対的な同一性のみが重要であるため、ソリューションでは最初に色を圧縮します。 反転カウントのステップでは、順序付けられた色のペアの間で強制的に交換が行われる回数のマトリックスを構築します。 

次に、DP は色のすべてのサブセットを調査します。 トランジションは、現在の順序に色を追加するための増分コストを計算します。これは、すでに配置されている色との競合の正確な合計です。 ここで、実装において多くの間違いが発生します。スワップはコストに方向性がある必要があります。$c$前に$d$は対称ではありません$d$前に$c$。 

最終的な答えは完全なビットマスクから得られ、すべての色が配置されたことを表します。 

## 実用的な例

 インプットを考慮する`4 / 2 1 2 1`。 

まず色を圧縮します。`2 -> A`、`1 -> B`。 配列は次のようになります`A B A B`。 

反転コストを計算します。 

| ステップ | マスク | アクション | コストを追加 | DP値 |
 | --- | --- | --- | --- | --- |
 | 0 | 000 | 開始 | 0 | 0 |
 | 1 | 001 | 場所A | 0 | 0 |
 | 2 | 011 | 場所B | 1 | 1 |
 | 3 | 010 | 場所B | 0 | 0 |
 | 4 | 110 | 場所A | 1 | 1 |

 最終結果は 1 になり、カラーをグループ化するには隣接する 1 つの交換で十分であるという事実と一致します。 

このトレースは、DP が最終文字列を直接構築しているのではなく、ペアごとの順序付けコストを一貫して蓄積していることを示しています。

 ## 特殊なケース

 単一色の場合、DP には空を超える状態が 1 つだけあり、コスト マトリックスは空であるため、すべての遷移でゼロが追加されます。 アルゴリズムは正しくゼロ スワップを返します。 

次のような完全に色でソートされた配列の場合`1 1 1 2 2 2`、すべての反転カウントは「正しい方向」でゼロになるため、自然なグループ化を尊重するすべての順序付けではコストがゼロになり、偶発的なペナルティなしに DP がゼロに収束します。 

次のような交互パターンの場合`1 2 1 2 1 2`、反転行列は対称になりますが、非ゼロになります。 DP は、相互反転を最小限に抑える順序を正しく選択し、ローカル スワップを修正しようとするのではなく、すべてのステップですべてのペアごとの競合を一貫してカウントするため、過少カウントが防止されます。
