 ## 解決策
 ## 問題の理解

 3 次元の属性ベクトルのコレクションがあります。 1 回の移動で、単一のベクトルを選択し、その 3 つの座標のサブセットを選択し、選択したすべての座標に同時に 1 を追加または 1 を減算します。 目標は、総移動数を最小限に抑えながら、すべてのベクトルを同一にすることです。 

選択した最終ベクトルについて`(x, y, z)`、1 つの元のベクトルを考えます。`(a, b, c)`。 座標を増加する必要がある場合、他の増加する座標と移動を共有できます。 座標を減少させる必要がある場合、他の減少する座標とのみ移動を共有できます。 これは、このベクトルの移動数が、絶対値での最大の正の差と最大の負の差を加算したものであることを意味します。```
max(x-a, y-b, z-c, 0) + max(a-x, b-y, c-z, 0)
```入力サイズは以下に達します`100000`したがって、考えられるすべての最終座標をチェックすることは不可能です。 可能な座標の検索空間が大きすぎるため、各次元の広い範囲にわたる線形スキャンでも使用可能な時間を超えてしまいます。 考えられるすべての答えを試すのではなく、コスト関数の構造を活用する必要があります。 

よくある間違いは、答えが単にすべての点をカバーする最小の立方体であると考えることです。 1 つの移動ですべての座標を独立して変更できるのであれば、これは正しいことですが、ここでは、正の変更と負の変更を 1 つの移動で組み合わせることができません。 例えばポイントの場合`(0,0,0)`そして`(10,10,0)`、座標範囲は答えを示唆するのに十分小さい`5`ただし、ある点を別の点に移動するには、2 つの座標を一緒に増やす必要があり、コストがかかります`10`正しい方向に。 

もう 1 つの特殊なケースは、すべてのベクトルが同一である場合です。 入力の場合:```
3
5 7 9
5 7 9
5 7 9
```答えは`0`。 常に中間値に向かって移動しようとするソリューションでは、現在の値がすでに最適であることを無視すると、操作が無駄になる可能性があります。 

2 番目のエッジ ケースは、1 つの座標のみが異なる場合です。 入力の場合:```
2
1 4 8
6 4 8
```答えは`5`。 最初の座標のみが変更されますが、最終的な座標は引き続き選択する必要があります。 操作数は 2 つの値の間の距離であり、その半分ではありません。 

## アプローチ

 ブルートフォースアプローチでは、可能な最後のトリプルをすべて試します。`(x, y, z)`座標範囲内です。 すべての候補者について、すべてをチェックして総コストを計算します。`n`ベクトル。 候補者の数はおよそである可能性があります`100000^3`、それぞれに費用がかかります`O(n)`、あり得ない最悪のケースを示します。 

重要な観察は、コスト関数が凸であるということです。 各ベクトルは一次式の最大値から作られた関数に寄与し、凸関数の和は凸のままです。 凸関数にはグローバル ミニマムから離れたローカル ミニマムがないため、良い位置から開始して、より良い近傍に向かって繰り返し移動できます。 

絶対値ベースの凸関数は中央値付近で最小化されるため、各次元については中央値が良い開始点となります。 3 つの座標中央値を選択した後、離散勾配検索を実行します。 現在の点を 3 次元の 27 方向すべてに移動してみます。 変更によって答えが改善された場合は、それを受け入れて続行します。 それ以外の場合は、ジャンプ サイズを半分に減らします。 この関数は凸型であるため、大きなジャンプでは正しい領域が検出され、小さなジャンプでは正確な整数の最小値が調整されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(範囲3 * n) | お(1) | 遅すぎる |
 | 凸検索 | O(n log C) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのベクトルを読み取り、3 つの座標配列を個別に保存します。 これらの配列は、開始点の検索とコスト関数の評価の両方に必要です。 
2. 各座標の中央値を最初の候補として選択します`(x, y, z)`。 距離に基づく凸関数は中央値付近で最小値に達する傾向があり、強力な開始位置が得られます。 
3. 候補点のコストを定義します。 すべてのベクトルについて、増加する必要がある最大量と減少させる必要がある最大量を計算します。 それらの合計は、そのベクトルに必要な演算の数になります。 
4. 初期ジャンプ サイズを 3 つの座標すべての間の最大の広がりに設定します。 これは、可能な検索領域全体を横断するのに十分な大きさです。 
5. 各座標が変化するすべての方向を試します。`-jump`、`0`、 または`jump`。 新しいポジションのコストが低い場合は、すぐにそこに移動してください。 
6. 27 個の隣接する位置のいずれも結果を改善しない場合は、ジャンプ サイズを半分にします。 ジャンプを小さくすると、検索が正確な整数の最適値に近づくことができます。 
7. ジャンプサイズがゼロになったとき、現在位置が最適であり、そのコストが答えになります。 

それが機能する理由は凸性に基づいています。 1 つのベクトルのコストは、凸状の一次関数の 2 つの最大値の合計です。 すべてのベクトルを加算すると、関数は凸型のままになります。 凸関数では、より悪い点の背後により良い点が隠れることはできないため、近傍をチェックすることによる局所的な改善がグローバル ミニマムにつながります。 ジャンプ サイズを小さくすると、検索では最終的に、必要な近くの整数位置をすべてテストできるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)

    a = []
    b = []
    c = []

    for _ in range(n):
        x, y, z = map(int, input().split())
        a.append(x)
        b.append(y)
        c.append(z)

    def value(x, y, z):
        ans = 0
        for i in range(n):
            d1 = x - a[i]
            d2 = y - b[i]
            d3 = z - c[i]
            ans += max(d1, d2, d3, 0)
            ans += max(-d1, -d2, -d3, 0)
        return ans

    sa = sorted(a)
    sb = sorted(b)
    sc = sorted(c)

    x = sa[n // 2]
    y = sb[n // 2]
    z = sc[n // 2]

    best = value(x, y, z)

    step = max(
        max(a) - min(a),
        max(b) - min(b),
        max(c) - min(c)
    )

    while step:
        moved = False
        current = best

        for dx in (-1, 0, 1):
            for dy in (-1, 0, 1):
                for dz in (-1, 0, 1):
                    nx = x + dx * step
                    ny = y + dy * step
                    nz = z + dz * step
                    cur = value(nx, ny, nz)
                    if cur < current:
                        current = cur
                        x, y, z = nx, ny, nz
                        moved = True

        best = current
        if not moved:
            step //= 2

    print(best)

solve()
```の`value`関数は、固定の最終ベクトルの演算カウントを直接実装します。 2 つの最大値の式は、増加と減少の 2 つのグループの操作を表します。 

中央値の初期化により、検索空間の任意の隅から開始することが回避されます。 仕分け費用`O(n log n)`、これは許容されます`100000`要素。 

検索ループは整数ジャンプを使用します。 重要な境界条件は、最適値が厳密な傾斜ではなく平坦な領域に存在する可能性があるため、各次元でゼロ移動を許可することです。 半減を繰り返すことで、`step`最終チェックが最適値に十分近い状態で行われることを保証します。 

## 実用的な例

 入力の場合:```
3

```中央点は`(2,2,2)`。

 3 番目のベクトルでは、最初の座標で 1 回減少し、3 番目の座標で 1 回減少する必要があります。 これらはターゲットに対して逆方向であるため結合できず、2 つの操作が必要です。 

入力の場合:```
3
2 3 1
3 5 3
3 2 1
```中央点は`(3,3,1)`。 

| ステップ | ポジション | コスト | アクション |
 | --- | --- | --- | --- |
 | 開始 | (3,3,1) | 4 | 初期中央値 |

 | 最終回 | (3,3,1) | 4 | 答え |

 この例は、座標の中央値が必ずしもすべての座標がすでに位置合わせされていることを意味するわけではないことを示しています。 これらは、凸型探索の適切な開始点を提供するだけです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().split()
    sys.stdin = old

    if not data:
        return ""

    it = iter(data)
    n = int(next(it))
    pts = []
    for _ in range(n):
        pts.append((int(next(it)), int(next(it)), int(next(it))))

    a = [p[0] for p in pts]
    b = [p[1] for p in pts]
    c = [p[2] for p in pts]

    def value(x, y, z):
        res = 0
        for i in range(n):
            d1 = x - a[i]
            d2 = y - b[i]
            d3 = z - c[i]
            res += max(d1, d2, d3, 0)
            res += max(-d1, -d2, -d3, 0)
        return res

    x = sorted(a)[n // 2]
    y = sorted(b)[n // 2]
    z = sorted(c)[n // 2]

    ans = value(x, y, z)
    step = max(max(a)-min(a), max(b)-min(b), max(c)-min(c))

    while step:
        moved = False
        for dx in (-1, 0, 1):
            for dy in (-1, 0, 1):
                for dz in (-1, 0, 1):
                    nx, ny, nz = x + dx * step, y + dy * step, z + dz * step
                    cur = value(nx, ny, nz)
                    if cur < ans:
                        ans = cur
                        x, y, z = nx, ny, nz
                        moved = True
        if not moved:
            step //= 2

    return str(ans)

 ## 特殊なケース

 次のような同一のベクトルの場合:```
3
5 7 9
5 7 9
5 7 9
```中央値は正確に現在の値です。 コスト関数はゼロを返し、検索では改善する動きが見つかりません。 

単一の座標の違いの場合:```
2
1 4 8
6 4 8
```検索は中央値付近から始まります`(6,4,8)`。 最初のベクトルは、最初の座標を 5 増やす必要があります。 1 方向のみが関与するため、式は次のようになります。`5`、実際の移動数と一致します。 

次のような、複数の座標が同じ方向に移動する必要がある場合:```
2
0 0 0
5 5 5
```中間の値を選択すると、コストは次のようになります。`5`3 つの座標すべてをすべての操作で一緒に調整できるためです。 このアルゴリズムは、座標を独立して処理するのではなく、最大項を通じてこれを捕捉します。
