 ## 解決策
 ## 問題の理解

 コンテストの主催者はギフト カードを持っており、上位 7 人の出場者にちょうど 7 枚を贈りたいと考えています。 選択したカードを 1 位の賞品から 7 位の賞品まで並べ替えた後、値は 2 つの公平性ルールを満たさなければなりません。 1 位の賞品が、2 位と 3 位の賞品を合わせた場合と比べて高額すぎることはありません。 また、最初の 3 つの賞品の合計は、最後の 4 つの賞品の合計よりも小さくなければなりません。 可能なすべての公平な選択の中で、選択された 7 枚のカードの最大合計値が必要です。 

入力により、利用可能なカードの数とその値が得られます。 出力は、有効な 7 枚のカードのグループの最大の合計、または`-1`そのようなグループが存在しない場合。 

カードの数は 500,000 に達する可能性があります。これにより、7 つのグループすべてをチェックすることはすぐに除外されます。これには、約$N^7$これは通常の制限時間をはるかに超えています。 平$O(N^2)$最大入力サイズに対して大きすぎます。 ソートの複雑さに近いソリューションが必要です。$O(N \log N)$または$O(N)$並べ替え後。 

難しいのは、最大の 7 つの値が必ずしも答えになるとは限らないということです。 非常に高額な 1 等賞品は最初の不等式を破る可能性があり、7 つの値の分布が重要です。 たとえば、次のようになります。```
7
1 2 3 4 5 6 7
```可能なグループはすべてのカードだけです。 出力は次のとおりです。```
-1
```最大 7 枚のカードの合計をチェックするだけの不注意な解決策では 28 が返されますが、最大の賞品 7 は 6 プラス 5 より小さくないため、配分は無効になります。 

無視すべき特大カードがある場合には、別の特殊なケースが発生します。 のために：```
10
5 5 5 5 5 5 10 5 5 5
```答えは次のとおりです。```
35
```素朴な貪欲なアプローチでは、合計が増加するため、10 を含める可能性があります。 ただし、選択した値を次のように並べ替えた後、`5 5 5 5 5 5 10`、最初の不等式は次のようになります。`10 < 5 + 5`、これは誤りです。 正しい解決策では、10 は未使用のままになります。 

## アプローチ

 直接的なアプローチは、7 枚のカードのすべてのセットを試し、それらの 7 つの値を並べ替えて、2 つの条件を確認することです。 考えられるすべての答えが考慮されているため、これは正しいです。 問題は可能性の数です。 50万枚の中から7枚選ぶと膨大な組み合わせになるため、この方法では終わりません。 

重要な観察は、有効な 7 つのグループが非常に特殊な構造を持っているということです。 すべてのカードの値を徐々に並べ替えます。 有効な選択を検討してください。```
a0 <= a1 <= a2 <= a3 <= a4 <= a5 <= a6
```中間の 2 つの値`a4`そして`a5`条件を分けます。 最大値は以下の値であれば十分です`a4 + a5`ただし、最初の 4 つの値の合計が より大きい場合のみ必要です。`a4 + a5`。 

有効なグループがソートされた配列内でまだ 7 つの連続した要素になっていない場合は、選択した要素を、同じ最大の選択した要素で終わるより適切な連続したウィンドウに置き換えることができます。 置き換えられたすべての値は少なくとも古い値と同じ大きさであり、中央と下位の部分が増加するだけであるため、2 つの不等式を満たすことが難しくなることはありません。 この変換を繰り返すと、ソート後の連続する 7 つのブロックである最適な答えが得られます。 

ここで問題は、サイズ 7 のすべてのウィンドウをチェックすることになります。 ウィンドウ サイズが固定されているため、すべてのチェックはプレフィックス合計を使用して定数時間で行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^7) | お(7) | 遅すぎる |
 | 最適 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのカードの値を昇順に並べ替えます。 最適な答えは、並べ替えると 7 つの連続する値として表現できるため、並べ替えを行うことで、それらの候補だけを調べることができます。 
2. ソートされた配列のプレフィックスの合計を作成します。 スキャン中に 4 つまたは 7 つの値のグループの合計を高速に計算する必要があります。 
3. 開始インデックスごとに`i`サイズ 7 のウィンドウの場合、値は次のようになります。`a[i], a[i+1], ..., a[i+6]`。 

最初の条件は次のようになります。`a[i+6] < a[i+4] + a[i+5]`。 

最大の賞はその下の 2 つの賞と比較されるため、これら 3 つの位置はウィンドウ内で固定されます。 
4. 2 番目の条件を確認します。`a[i+4] + a[i+5] < a[i] + a[i+1] + a[i+2] + a[i+3]`。 

最後の 4 つの賞は最初の 3 つの賞を上回る必要があります。 接頭辞の合計を使用すると、4 つの要素の合計をすぐに計算できます。 
5. 両方の条件が当てはまる場合は、このウィンドウ内の 7 つの値の合計で答えを更新します。 
6. ウィンドウが動作しない場合は、出力します。`-1`。 

これが機能する理由: 変換引数は、最適で有効な選択を、合計値を減らしたり不等式を壊したりすることなく、常に連続したソート ウィンドウにシフトできることを示しています。 スキャンでは考えられるすべての最適な形式がチェックされるため、見つかった最大有効ウィンドウが全体的な最適値となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    pref = [0] * (n + 1)
    for i, x in enumerate(a):
        pref[i + 1] = pref[i] + x

    ans = -1

    for i in range(n - 6):
        middle = a[i + 4] + a[i + 5]

        if a[i + 6] < middle:
            first_four = pref[i + 4] - pref[i]
            if middle < first_four:
                total = pref[i + 7] - pref[i]
                if total > ans:
                    ans = total

    print(ans)

if __name__ == "__main__":
    solve()
```並べ替えステップでは、ウィンドウ引数に必要な順序でカードを配置します。 ソート後は、ソートされた順序によって出場者のランキングが一意に決定されるため、順列を試行することなく有効な分布をチェックできます。 

プレフィックス合計配列には、ソートされたカードのすべてのプレフィックスの合計が格納されます。 表現`pref[i + 7] - pref[i]`完全な 7 枚のカード ウィンドウの合計が得られますが、`pref[i + 4] - pref[i]`ウィンドウの中に最小のカードを 4 枚出します。 

ループは次で停止します`n - 7`なぜなら、チェックされたすべてのセグメントには正確に 7 つの要素が含まれている必要があるからです。 不等式ではウィンドウを基準としたインデックスが使用されるため、中間のペアは常に位置になります。`i + 4`そして`i + 5`。 Python では整数の精度が任意であるため、オーバーフローの問題は発生しません。

 8 は 13 より小さく、13 は 14 より小さいため、2 番目のウィンドウは機能します。答えは 35 になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N log N) | 単一のリニア スキャンではソートが優先されます。 
| スペース | O(N) | プレフィックス合計配列には N + 1 の値が格納されます。 

この制約により、500,000 個の値を快適に並べ替えることができます。 並べ替え後、すべてのウィンドウが 1 回チェックされるため、残りの作業は直線的に行われます。 

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    pref = [0] * (n + 1)
    for i, x in enumerate(a):
        pref[i + 1] = pref[i] + x

    ans = -1
    for i in range(n - 6):
        mid = a[i + 4] + a[i + 5]
        if a[i + 6] < mid and mid < pref[i + 4] - pref[i]:
            ans = max(ans, pref[i + 7] - pref[i])

    return str(ans)

assert solution("7\n1 2 3 4 5 6 7\n") == "-1"
assert solution("8\n1 2 3 4 5 6 7 8\n") == "35"
assert solution("10\n5 5 5 5 5 5 10 5 5 5\n") == "35"

assert solution("7\n10 1 1 1 1 1 1\n") == "-1"
assert solution("7\n1 1 1 1 1 1 1\n") == "7"
assert solution("9\n1 2 3 4 5 6 7 8 100\n") == "35"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 7 つの増加する値 | -1 | 最大の 7 枚のカードは公平性ルールに違反する可能性があります。 
| 1 から 8 までの連続した値 | 35 | 基本的な有効なウィンドウの選択 |
 | 1 つの大きな値を持つ多数の等しい値 | 35 | 魅力的だが無効な高額賞金の拒否 |
 | 有力なカード 1 枚 | -1 | 最初の不等式の処理 |
 | すべて等しい値 | 7 | 等しい値境界の場合 |
 | 有効な値の後の大きな外れ値 | 35 | 使用できない高い値を正しく無視する |

 ## 特殊なケース

 この場合の場合:```
7
1 2 3 4 5 6 7
```アルゴリズムにはウィンドウが 1 つだけあります。 中央のペアは 6 と 5 で、11 になります。最大値 7 は最初の不等式を満たしますが、最初の 4 つの値の合計は 10 になり、これは 11 を超えません。アルゴリズムはウィンドウを拒否して出力します。`-1`。 

この場合の場合:```
10
5 5 5 5 5 5 10 5 5 5
```ソートされた配列では、10 が最後に配置されます。 これを含むウィンドウの最大値は 10、中間ペアの合計は 10 であるため、厳密な不等式は成立しません。`10 < 10`失敗します。 残りのウィンドウには 5 つだけが含まれており、有効な合計は 35 になります。 

この場合の場合:```
7
1 1 1 1 1 1 1
```すべての値は等しい。 最大値は 1 で、中央のペアの合計は 2 です。最初の 4 つの値の合計は 4 になるため、両方の不等式が成り立ちます。 アルゴリズムは合計 7 を返します。
