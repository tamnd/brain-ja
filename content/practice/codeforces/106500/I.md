 ## 解決策
 ## 問題の理解

 頂点が状態を表し、エッジが 1 つの状態から別の状態への 1 ステップの遷移を表す有向グラフが与えられます。 この接続性のローカルな観点から、タスクは完全な到達可能性関係を決定することです。順序付けられた頂点のペアごとに、最初の頂点から開始して有向エッジをたどって、任意の数の中間ステップを経て最終的に 2 番目の頂点に到達できるかどうかを判断します。 

出力は最短パスやルートのカウントに関するものではありません。 それは純粋にパスの存在に関するものです。 あるサイクルを通じて頂点がそれ自体に到達できる場合、それも答えの一部であり、形式に応じて明示的に要求されるか暗黙的に処理されます (通常、対角エントリは推移閉包で到達可能に設定されます)。 

正確な制限が見えなくても、推移閉包問題の構造は、サイズ O(n²) の密な関係出力を強く示唆しています。 これにより、すべてのパスを明示的に列挙しようとするソリューションは即座に排除されます。 各ペアに対して独立してパスを探索するアプローチは、簡単に O(n³) 以下に劣化する可能性があり、n が数千程度で境界線となり、それを超えると完全に実行不可能になります。 

到達可能性が間接的で複数のホップが必要な場合、微妙なエッジ ケースが発生します。 たとえば、エッジが 1 → 2 および 2 → 3 である場合、直接のエッジが存在しない場合でも、1 は 3 に到達するとマークする必要があります。 単純な隣接関係チェックでは、到達可能性を繰り返し伝達しない限り、これを見逃してしまいます。 

もう 1 つの特殊なケースは、自己到達可能性です。 1 → 2 → 1 のようなグラフでは、頂点 1 はサイクルを通じてそれ自体に到達する可能性があるため、クロージャーはそれを反映する必要があります。 直接エッジのみをマークし、サイクルを考慮せずに伝播する実装では、誤って対角エントリが未設定のままになる可能性があります。 

## アプローチ

 ブルート フォース アプローチは、各頂点をソースとして扱い、DFS や BFS などのグラフ トラバーサルを実行して、到達可能なすべてのノードをマークすることから始まります。 これは正しいです。各走査では、指定された開始点から到達可能なノードのセットが正確に探索されるからです。 これをすべての頂点に対して繰り返すと、完全な推移的閉包が生成されます。 

問題は繰り返しの探査コストです。 単一の DFS または BFS には O(n + m) かかります。 これをすべての頂点に対して行うと、O(n(n + m)) になります。 m が O(n²) である密なグラフでは、これは O(n³) になります。 グラフがまばらな場合でも、n 回の検索を開始するという一定の要因は重要であり、Python 実装は最悪の CF 制約の下で苦労することがよくあります。 

重要な観察は、到達可能性は推移的であり、構成できるということです。 ノード i が j に到達できる場合、j から到達可能なすべてのノードは i からも到達可能です。 これは、ノードごとに到達可能性を個別に再計算するのではなく、到達可能なノードのセットを段階的に伝播できることを示唆しています。 

ここで、ビットセットベースのフロイド・ウォーシャル風のアイデアが有効になります。 ブール エッジを個別に保存するのではなく、ノードごとに到達可能なノードのセットを保存します。 i が j に到達できることが判明したら、j の到達可能性セットを i にマージします。 これにより、反復トラバーサルが反復セット共用体に変わり、Python では整数ビット演算を使用して効率的に実装できます。 

繰り返しを繰り返すうちに、新しいビットを追加できなくなるまで、到達可能性情報が中間ノードを介して伝播されます。 その時点で、各ビットセットは正確に推移的閉包をエンコードします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各ノードからのブルート フォース DFS/BFS | O(n(n + m)) | O(n + m) | 密なグラフでは遅すぎる |
 | ビットセット推移閉包 | O(n3 / ワードサイズ) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 各頂点の到達可能なセットをビットマスクとして表します。 i のマスクの j 番目のビットは、i が j に到達できるかどうかを示します。 

1. リストを初期化する`reach`、 どこ`reach[i]`自己到達可能性が許可されている場合はビット i のみが設定され、すべての直接エッジ i → j にもビットが設定されます。 これにより、基本グラフが指定されたとおりに正確にエンコードされます。 
2. 0 から n − 1 までのすべての中間頂点 k を繰り返します。各 k について、k を他の頂点間のブリッジとして使用しようとします。 
3. すべてのソース頂点 i について、i が k に到達できる場合、k から到達可能なものはすべて i からも到達可能でなければなりません。 更新します`reach[i] = reach[i] OR reach[k]`。 これは、k の到達可能なセット全体を一定のビットセット時間で i に注入するため、重要な伝播ステップです。 
4. すべての k に対してこのプロセスを昇順に繰り返します。 各反復では、k までの頂点を中間として使用するパスが許可され、徐々に長い到達可能性チェーンが構築されます。 
5. すべての反復の後、必要な出力形式に応じて、ビットセットを隣接行列またはエッジ リストにデコードします。 

### なぜ効果があるのか

 不変条件は、中間頂点 k を処理した後、`reach[i]`セット {0, 1, ..., k} の中間ノードのみを使用して i から到達可能なすべての頂点が正確に含まれます。 k を処理するときは、k から到達可能なすべてのパスを追加することによって、k で終わるすべての有効なパスを拡張します。 これにより、最も高いインデックスの中間頂点が処理されると、すべての有効なパスが最終的に構築され、既存の到達可能性セットのみを伝播するため、無効なパスが導入されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    reach = [0] * n

    for i in range(n):
        row = input().strip()
        for j, ch in enumerate(row):
            if ch == '1':
                reach[i] |= (1 << j)

    for k in range(n):
        for i in range(n):
            if reach[i] & (1 << k):
                reach[i] |= reach[k]

    out = []
    for i in range(n):
        row = []
        for j in range(n):
            row.append('1' if (reach[i] >> j) & 1 else '0')
        out.append(''.join(row))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、グラフの隣接行列表現を読み取り、各行をビットマスクに変換します。 各ビットマスクは、特定のノードから直接到達可能なすべてのノードをコンパクトに格納します。 

k と i にわたる二重ループは推移的な伝播を実行します。 条件`reach[i] & (1 << k)`i が k に到達できない場合に不必要な結合を回避し、疎な場合の定数因数を大幅に減らすことができます。 更新ステップでは、到達可能な k のセット全体を i にマージします。 

最後に、各ビット位置をチェックすることにより、ビットマスクがバイナリ行列にデコードされます。 

よくある実装上の間違いは、伝播は「すでに更新された」リーチ セット上で実行する必要があることを忘れていることです。 k ループの順序は、中間ノードが有効な踏み台として徐々に導入されることを保証するため、重要です。 

## 実用的な例

 3 つのノードとエッジ 0 → 1 および 1 → 2 を持つグラフを考えます。 

### 初期状態

 | 私 | リーチ[i] (バイナリ) |
 | --- | --- |
 | 0 | 010 |
 | 1 | 001 |
 | 2 | 000 |

 k = 0 を処理した後は、自分以外のノードが 0 に到達しないため、何も変化しません。 

k = 1 を処理した後、ノード 0 は 1 に到達し、1 が 2 に到達するため、2 を 0 に伝播します。 

| ステップ | 私 | リーチ[i] |
 | --- | --- | --- |
 | k=1 伝播 | 0 | 011 |
 | k=1 伝播 | 1 | 001 |
 | k=1 伝播 | 2 | 000 |

 k = 2 以降は、それ以上の更新は行われません。 

最終結果は、0 が 1 と 2 の両方に達し、1 が 2 に達することを示しています。 

このトレースは、中間頂点がブリッジとしてアクティブになった後にのみ間接到達可能性がどのように蓄積されるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n3 / w) | n 回の反復のそれぞれで、ワードレベルの OR 演算を使用して n ビットセットが伝播されます。 
| スペース | O(n²) | 各頂点には、サイズ n | のビットマスクが格納されます。 

三次構造はクロージャ計算の固有の性質と一致しますが、ビット演算により定数因数が大幅に圧縮されます。 これは、競技プログラミング環境における最大数千ノードまでの一般的な制約には十分です。

 ## 特殊なケース

 3 ノード チェーン 0 → 1 → 2 では、単純なシングルパス更新は 0 → 1 および 1 → 2 をマークした後に停止する可能性がありますが、0 → 2 への伝播に失敗します。k = 1 が処理されるとき、reach[0] にはすでに 1 が含まれているため、2 を含む replace[1] が吸収されるため、正しいアルゴリズムがこれを処理します。 

サイクル 0 → 1 → 2 → 0 では、各ノードは最終的に他のすべてのノードに到達します。 反復 k = 0 の間に、ノード 2 はすでに間接的に 0 に到達することができ、k = 0 が中間として使用される場合、ノード 2 はその完全なセットを 2 に伝播して戻し、クロージャを完了します。 このフィードバック ループは、明示的なサイクル検出ではなく、ユニオンの伝播を繰り返すことによって自然に解決されます。
