 ## 解決策
 ## 問題の理解

 実際、ゲームは 2 つの錠前に書かれた正確な数字には依存しません。 チャーリーは、対応するホイールの各ペアが等しいか異なるかを記録するだけです。 位置を長さの文字列で表すことができます`N`各ホイールについて 2 つの可能な状態 (等しいか等しくない) が含まれます。 

いずれかのロックの 1 桁を変更すると、このパターン内の 1 つの位置にのみ影響します。 2 つの数字が等しい場合、そのうちの 1 つを変更すると、それらは異なります。 それらが異なる場合は、新しい桁を選択してそれらを等しくすることができます。 可能な桁は 10 個あるため、どちらの遷移もパターン レベルで常に可能です。 移動とは、パターンの 1 ビットを反転するだけです。 

一部のパターンは二度と出現することが禁止されており、すでに出現したパターンには再度アクセスすることはできません。 アリスは最初の差分パターンからスタートします。 動けなくなったプレイヤーが負けとなります。 

制約は、可能なロック構成の数ではなく、パターンの数を中心に設計されています。`N`は最大 10 なので、最大でも`2^10 = 1024`違いのパターン。 これにより、訪問可能なセットの数が頂点の数よりも天文学的に大きいため、ゲーム履歴に対する指数関数的な検索が除外されます。 ただし、状態グラフ自体に対してグラフ アルゴリズムを使用できます。 禁止リストには最大 1000 個のパターンを含めることができ、これはグラフ全体のサイズに近いため、ソリューションでは任意の削除された頂点を処理する必要があります。 

陥りやすい間違いは、ゲームを単純な最短経路または到達可能性の問題として扱うことです。 パターンにアクセスするとそのパターンが永久に削除されるため、動きの順序が重要になります。 たとえば、ホイールが 1 つで禁止状態がない場合、パターンは 2 つの頂点のサイクルを形成します。```
N = 1
Alice: 0
Bob:   0
```正しい結果は`Bob`なぜなら、アリスは他の唯一の州に移動し、ボブは許可された場合にのみ最初に戻りますが、すでに訪問されているからです。 ボブはアリスのターンの後は何も動けません。 素朴な到達可能性アプローチでは、訪問されたルールを捕捉できません。 

もう 1 つの微妙なケースは、すべての隣接パターンが禁止されているため、開始パターンに利用可能な手が存在しない場合です。```
N = 1
start = =
forbidden:
.
```正しい出力は次のとおりです`Bob`。 アリスはすぐに負けます。 最初のプレイヤーが常に合法的なフリップを持っていると仮定する解決策は失敗します。 

最後のエッジ ケースは、開始頂点が状態グラフの最大一致において唯一一致しない頂点である場合に発生します。 これはアリスが勝つ状況であるため、接続成分だけを数えたり、残りの状態の数を確認したりするだけでは十分ではありません。 

## アプローチ

 この強引なアイデアは、ゲームを再帰的にシミュレートすることです。 状態には、現在のパターンと、すでに訪問したパターンのセットが含まれます。 考えられるすべての動きに対して、次の状態を試し、少なくとも 1 つの動きが相手を負けさせた場合、現在のプレイヤーが勝利したとマークします。 

ゲームは有限であり、あらゆる継続が検討されるため、これは正しいことです。 問題は州の数です。 パターンは 1024 個しかありませんが、訪問セットにはパターンの任意のサブセットが含まれる可能性があり、最大で`1024 * 2^1024`理論的な状態。 これは保存したり探索したりできる範囲をはるかに超えています。 

重要な観察は、ゲーム グラフには方向性がないということです。 元の頂点に再度アクセスすることはできないことを除き、有効な動きはすべて反対側のプレイヤーによって元に戻すことができます。 これは古典的な無向頂点地理ゲームです。 このようなゲームでは、最大のマッチングによって結果が決まります。 

残りのグラフの最大一致を考慮します。 開始頂点が何らかの最大マッチングによってカバーされていない場合、2 番目のプレーヤーは常に、一致したエッジを取り戻すことで最初のプレーヤーの動きに答えることができます。 一致したペアは一緒に消費されるため、2 番目のプレーヤーが最初にスタックすることはありません。 

すべての最大一致が開始頂点をカバーする場合、最初のプレイヤーが強制的に勝利を収めることができます。 どのケースが当てはまるかを確認する標準的な方法は、グラフの最大一致サイズと開始頂点を削除した後の最大一致サイズを比較することです。 開始点を削除すると最大マッチング サイズが減少する場合、すべての最大マッチングにはその頂点が必要となるため、アリスが勝ちます。 そうでなければボブが勝ちます。 

状態グラフは、いくつかの頂点が削除された超立方体です。 これを明示的に構築し、パリティによって頂点を分割し、Hopcroft Karp を 2 回実行します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合の O(2^2^N) 状態 | 状態ごとに O(2^N) | 遅すぎる |
 | 最大一致 | O(V^2 * E^0.5) ホップクロフト カープ | O(V + E) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのパターンをビットマスクに変換します。 少し設定されています`1`は、対応する数字が異なることを意味します。 開始パターンも同様に変換され、禁止パターンは使用不可としてマークされます。 
2. 許可されたすべてのパターンのグラフを作成します。 2 つの頂点のマスクがちょうど 1 ビット異なる場合、それは 1 つのホイールの等価ステータスの変更を表すため、それらの頂点は接続されます。 
3. 設定されたビット数のパリティを使用して、グラフを 2 つの部分に分割します。 1 ビットを反転すると常にパリティが変更されるため、すべてのエッジが 2 つの部分の間に入ります。 
4. 完全に許可されたグラフ内で一致する最大のサイズを見つけます。 これにより、形成できる素のペアの最大数がわかります。 
5. 開始頂点を一時的に削除し、一致する最大サイズを再度見つけます。 サイズが小さくなると最大マッチングごとに開始頂点が必要でした。 
6. 印刷`Alice`開始点を削除すると、一致するサイズが減少します。 それ以外の場合は印刷します`Bob`。 

なぜ効果があるのか:

 このゲームは、パターン グラフ上の無向頂点地理ゲームです。 開始部分をカバーしない最大のマッチングにより、ボブにペアリング戦略が与えられます。アリスが一致した頂点に入ると、ボブはすぐにそのパートナーに移動します。 これらのパートナー頂点は、ペアが一緒に消費されるため、常に使用されません。 そのようなマッチングが存在しない場合、すべての最大マッチングにはスタートが含まれている必要があり、スタート プレーヤーは無向頂点地理の定理による勝利戦略を持っています。 

一致比較により、まさにこの情報が得られます。 スタートなしの最良のマッチングが小さい場合、スタートは必須であり、アリスが勝ちます。 変更されていない場合、開始を回避する最大の一致が存在し、ボブはペアリング戦略を使用できます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def hopcroft_karp(adj, left_nodes, right_nodes):
    pair_left = {x: -1 for x in left_nodes}
    pair_right = {x: -1 for x in right_nodes}
    dist = {}

    def bfs():
        q = deque()
        found = False
        for u in left_nodes:
            if pair_left[u] == -1:
                dist[u] = 0
                q.append(u)
            else:
                dist[u] = -1
        while q:
            u = q.popleft()
            for v in adj[u]:
                pu = pair_right[v]
                if pu == -1:
                    found = True
                elif dist[pu] == -1:
                    dist[pu] = dist[u] + 1
                    q.append(pu)
        return found

    def dfs(u):
        for v in adj[u]:
            pu = pair_right[v]
            if pu == -1 or (dist[pu] == dist[u] + 1 and dfs(pu)):
                pair_left[u] = v
                pair_right[v] = u
                return True
        dist[u] = -1
        return False

    result = 0
    while bfs():
        for u in left_nodes:
            if pair_left[u] == -1 and dfs(u):
                result += 1
    return result

def solve_case(n, c, a, b, forbidden):
    bad = [False] * (1 << n)

    start = 0
    for i in range(n):
        if a[i] != b[i]:
            start |= 1 << i

    for s in forbidden:
        mask = 0
        for i, ch in enumerate(s):
            if ch == '.':
                mask |= 1 << i
        bad[mask] = True

    vertices = [i for i in range(1 << n) if not bad[i]]

    color = {}
    for v in vertices:
        color[v] = v.bit_count() & 1

    def build(skip):
        left = []
        right = []
        alive = set(vertices)
        if skip in alive:
            alive.remove(skip)

        for v in alive:
            if color[v] == 0:
                left.append(v)
            else:
                right.append(v)

        adj = {v: [] for v in left}
        for v in left:
            for i in range(n):
                u = v ^ (1 << i)
                if u in alive:
                    adj[v].append(u)
        return hopcroft_karp(adj, left, right)

    full = build(-1)
    without_start = build(start)

    return "Alice" if without_start < full else "Bob"

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        n, c = map(int, input().split())
        a = input().strip()
        b = input().strip()
        forbidden = [input().strip() for _ in range(c)]
        ans.append(solve_case(n, c, a, b, forbidden))
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```入力パーサーはまず 2 つのロック構成を読み取り、それらの間の初期関係をビットマスクに変換します。 等しい情報のみが重要となるため、このステップの後に実際の数字は消えます。 

グラフの構築は内部で行われます`build`。 この関数はオプションで、2 番目のマッチング計算に必要な 1 つの頂点を削除します。 すべてのハイパーキューブ エッジは正確に 1 ビット変更されるため、頂点はパリティによって分割されます。 隣接リストには左側からのエッジのみが格納されます。これは Hopcroft Karp で必要な形式です。 

2 つの一致する呼び出しがソリューションの中心です。 1 つ目は、元のグラフで可能な限り最適な一致サイズを示します。 2 つ目は、開始頂点がなくても同じサイズの一致が可能かどうかを尋ねます。 それが不可能な場合は、すべての最大一致に開始を含める必要があります。 

グラフが疎で頂点数が少ないため、実装ではペアのマッチングに辞書を使用します。 Hopcroft Karp は最大 1024 頂点を通るパスのみをたどるため、再帰の深さの問題はありません。

 ## 特殊なケース

 開始パターンに正当な動きがない場合、グラフには開始頂点は含まれますが、その隣接頂点は含まれません。 開始なしのマッチングはグラフ全体と同じサイズであるため、アルゴリズムはすぐに Bob を返します。 

のために：```
1
0
0
.
```スタートマスクは`0`、そして唯一の隣人は禁止されています。 アリスは動けないので、ボブが勝ちます。 

多くのパターンが禁止されている場合、アルゴリズムはハイパーキューブが完全であると想定しません。 エッジを構築する前にそれらの頂点を削除します。 例えば：```

=.
.=

開始パターン自体がマッチングにおいて特別な役割を持つ場合、2 番目のマッチング計算でそれが捕捉されます。 よくある間違ったアプローチは、残りの状態の数だけを比較することです。 勝者は、パターンの総数ではなく、最大のマッチングに開始頂点が必要かどうかによって決まります。
