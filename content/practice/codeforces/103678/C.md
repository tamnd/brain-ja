 ## 解決策
 ## 問題の理解

 私たちは、最初は空であるかゼロで埋められている 1 次元配列を操作しており、2 種類の演算を処理するように求められます。 1 つの操作では、位置全体に等差数列を追加することで、連続したセグメントを更新します。 もう 1 つの操作では、以前のすべての更新が適用された後に、配列から導出された値または集計情報を要求します。 

等差数列の更新とは、位置からセグメントを選択するとき、`l`に`r`、定数値を追加するのではなく、ある値から始まるシーケンスを追加します。`l`右に移動すると一定の差分だけ増加します。 だから位置`l`最初の項を取得し、`l+1`最初の項に共通の差分を加えたものを取得するなど、`r`。 

課題は、インデックスの範囲と演算数の両方が大きくなる可能性があり、更新のたびに配列を明示的に再計算することができないことです。 単純なシミュレーションでは、更新ごとに潜在的に大きなセグメントに値を書き込む必要があるため、多くの更新が長い範囲に重なる場合、最悪の場合、二次的な動作が発生します。 

この制約は、各操作をほぼ対数時間以上で処理する必要があることを意味します。 更新ごとに各要素に触れるソリューションは、操作数が約 100,000 以上に達すると失敗します。 

いくつかの特殊なケースがあると、素朴な推論が脆弱になります。 等差数列に負の公差がある場合、セグメント全体で値が減少し、単調性を前提とした実装が壊れる可能性があります。 もし`l == r`の場合、更新は単一点の加算に変質し、数列内の少なくとも 2 つの要素を前提とするソリューションでは式が誤って適用される可能性があります。 もう 1 つの微妙なケースは更新の重複です。重複するセグメントに適用された 2 つの等差数列は別の単純な数列にマージされないため、セグメントごとに 1 つの「現在の数列」を保存しようとしても失敗します。 

## アプローチ

 ブルート フォース ソリューションは、次から反復して各更新を直接適用します。`l`に`r`そして対応する等差数列項を各位置に追加します。 各アップデートには費用がかかります`O(r - l + 1)`したがって、更新が配列全体に及ぶ最悪の場合、単一の操作は次のようになります。`O(n)`。 まで`m`操作すると、これは次のようになります`O(nm)`、両方が大きい場合、これは遅すぎます。 

重要な観察は、等差数列がインデックスの一次関数であるということです。 位置で`i`、付加価値は次の形式になります。`a + (i - l) * d`、次のように書き換えることができます`(a - l*d) + i*d`。 これにより、更新が 2 つの独立したコンポーネントに分離されます。1 つは範囲全体にわたる一定の寄与、もう 1 つはインデックスに比例した寄与です。 

この分解により、問題を 2 つの別々の範囲加算構造 (定数用と係数用) の維持に変換することができます。`i`。 定数の範囲加算を効率的にサポートし、線形係数の範囲加算を効率的にサポートできるようになると、すべての更新は 2 つの標準範囲更新の組み合わせになります。 次に、クエリは両方の構造からの寄与を結合します。 

これを効率的にサポートするために、差分配列スタイルのバイナリ インデックス ツリー (フェンウィック ツリー) を使用し、範囲更新後にプレフィックスの合計を再構築できるように 2 つの BIT を維持します。

 ## アルゴリズムのチュートリアル

 ### 1. 等差数列を書き直す

 それぞれのアップデートで`[l, r]`開始値あり`a`と違い`d`インデックスの関数として書き換えられる`i`:`a + (i - l) * d = (a - l*d) + i*d`。 

これにより、更新が定数部分と係数に分離されます。`i`、これが重要な構造の簡素化です。 

### 2. 2 つの独立した範囲加算構造を維持する

 私たちは 2 本のフェンウィック ツリーを維持しています。 1 つは定数の範囲加算を追跡し、もう 1 つはインデックスに適用される係数の範囲加算を追跡します。 この分離により、両方の効果を組み合わせて任意の位置で最終値を再構築できるようになります。 

### 3. 各更新を 2 つの範囲操作として適用します

 アップデートごとに`[l, r]`、私たちは以下を実行します:

 1 つの範囲の追加`(a - l*d)`定数 BIT に、次の範囲を 1 つ加算します。`d`係数BITまで同じ間隔で変化します。 

これが機能する理由は、両方の寄与が結合されると、範囲内のすべての位置が正確に正しい線形変換を受けるためです。 

### 4. 値を再構築してクエリに応答する

 位置の値を取得するには`i`、次のように計算します。`constant_sum(i) + i * coefficient_sum(i)`。 

どちらのコンポーネントも、それぞれの BIT に対するプレフィックス クエリを使用して取得されます。 

### 5. 複数の操作をオンラインで処理する

 すべての更新とクエリは順番に処理され、各クエリで以前のすべての更新の完全な効果が確実に表示されます。 

### なぜ効果があるのか

 核となる不変条件は、どの時点においても、適用されるすべての算術数列の正しい分解が 2 つの加算フィールド (定数フィールドと線形インデックス フィールド) に構造体が格納されることです。 各等差数列は定数項とインデックスに比例する項の合計として一意に表現できるため、更新ごとにこの分解が正確に保持されます。 フェンウィック ツリーは範囲更新とポイント クエリの下でプレフィックス集計を正しく維持するため、各インデックスでの再構築は常にすべての更新の累積寄与と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 2)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_add(self, l, r, v):
        self.add(l, v)
        self.add(r + 1, -v)

n, q = map(int, input().split())

bit_const = Fenwick(n)
bit_coef = Fenwick(n)

for _ in range(q):
    tmp = input().split()
    if not tmp:
        continue
    t = int(tmp[0])

    if t == 1:
        l, r, a, d = map(int, tmp[1:])
        bit_const.range_add(l, r, a - l * d)
        bit_coef.range_add(l, r, d)

    else:
        i = int(tmp[1])
        res = bit_const.sum(i) + i * bit_coef.sum(i)
        print(res)
```Fenwick 構造は、差分配列を介した範囲加算、ポイントクエリ モードで使用されます。 各等差数列の更新は、定数寄与と線形係数寄与に分割されます。 一定のBITが蓄積されます`(a - l*d)`係数 BIT が累積される間、範囲にわたって`d`。 

インデックスでのクエリの場合`i`、両方の BIT がプレフィックスでクエリされます`i`。 定数寄与は直接加算され、係数寄与は次のように乗算されます。`i`、元の線形式を再構築します。 

式は位置インデックスに直接依存するため、1 インデックス付けには注意が必要です。 調整せずに 0 インデックスを使用すると、すべての等差数列の値が誤ってシフトされます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    class Fenwick:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 2)

        def add(self, i, v):
            while i <= self.n:
                self.bit[i] += v
                i += i & -i

        def sum(self, i):
            s = 0
            while i > 0:
                s += self.bit[i]
                i -= i & -i
            return s

        def range_add(self, l, r, v):
            self.add(l, v)
            self.add(r + 1, -v)

    n, q = map(int, input().split())
    bit1 = Fenwick(n)
    bit2 = Fenwick(n)

    out = []

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == "1":
            _, l, r, a, d = map(int, tmp)
            bit1.range_add(l, r, a - l * d)
            bit2.range_add(l, r, d)
        else:
            _, i = tmp
            i = int(i)
            out.append(str(bit1.sum(i) + i * bit2.sum(i)))

    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは、単一要素の更新です。`l == r`。 その状況では、等差数列は単一の値に崩壊します。`a`。 変換はまだ機能します。`(a - l*d)`まさになる`a`以来`d`第 2 項が存在しない場合は無関係です。 係数の更新は、その 1 点以上には何も寄与しません。 

もう 1 つのケースは、ゼロ差分進行です。 ここでは、すべての要素が同じ値を受け取ります。 分解では、すべての寄与が定数 BIT に割り当てられ、係数 BIT には割り当てられません。これにより、均一な範囲の加算が正しくモデル化されます。 

最後のケースは、複数の重複する更新です。 各更新は独立して線形コンポーネントに分解され、両方のフェンウィック ツリーが加算累積をサポートしているため、重複するセグメントは干渉することなく自然に効果を合計します。
