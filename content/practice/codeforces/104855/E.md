 ## 解決策
 ## 問題の理解

 同じ長さの 3 つの配列が与えられ、私たちのタスクは 1 から n までのインデックスの順列を構築することです。 各位置 i について、順列内のその位置に割り当てられた値によって、i で収集する 3 つの報酬のどれが決まります。 選択した数値 p[i] が i より小さい場合、a[i] を取得します。 それが i に等しい場合、b[i] が得られます。 i より大きい場合は、c[i] を取得します。 目標は、すべてのポジションで収集される報酬の合計が最大化されるように、各番号を 1 回だけ割り当てることです。 

主な問題点は、すべてのインデックスがその使用方法に応じて報酬を与えると同時に、順列で一意の値を消費することです。 これにより、グローバルな結合が形成されます。つまり、早期に大きな値を設定することを選択すると、あるポジションでは役立つかもしれませんが、他の場所では将来の選択が制限される可能性があります。 

制約は大きく、n はテスト ケースごとに最大 200,000 にすることができ、すべてのテスト ケースの合計も 200,000 になります。これにより、すべての順列を試行するソリューションや、すべてのスワップを試行したり、テスト ケースごとにフローを実行したりするなどの 2 次関数さえも直ちに除外されます。 テスト ケースごとに O(n log n) または O(n) のアプローチを強いられます。 

3 つの報酬タイプ間の対称性から、微妙なエッジケースが発生します。 i をそれ自体に割り当てるか、より小さなものに割り当てるか、より大きなものに割り当てるかをローカルで決定する単純な貪欲型は、すべての代入に対応するものがあることを無視するため、失敗する可能性があります。 たとえば、あるポジションが「より大きい」割り当てを使用する場合、他のポジションはその大きな値を「より小さい」割り当てとして使用する必要があります。 この組み合わせを無視すると、局所的には最適に見えても全体的には実行不可能な、一貫性のない構築が生じます。 

## アプローチ

 ブルートフォースアプローチでは、1 から n までのすべての順列を試し、それぞれのスコアを計算します。 これは定義を直接評価するため正しいですが、n! 個あるため実行不可能です。 順列は、n が 20 程度の場合でも不可能になります。 

もう少し賢い大胆なアイデアは、ローカル ゲインに基づいて貪欲に値を割り当ててみることです。各位置 i について、利用可能な未使用の最適な数値を選択して、p[i] < i、p[i] = i、または p[i] > i のいずれにするかを選択します。 1 つのインデックスを選択すると、残りのすべてのインデックスの可用性構造が変更されるため、これは失敗します。 たとえば、「p[i] > i」の優先を満たすために早い段階で大きな数値を選択すると、別のインデックスがそれ自体の割り当てからさらに高いゲインを実現できなくなる可能性があります。 

重要な観察は、各インデックス i には 3 つのオプションがあると考えることができますが、実現可能性の制約は完全に順列構造に由来するということです。 どのインデックスに固定点が割り当てられるかを固定することを想像すると、残りの要素は「小さい側」の位置と「大きい側」の位置の間で全単射を形成する必要があります。 これは、独立した貪欲な選択ではなく、決定を構造化されたマッチングプロセスに分割する必要があることを示唆しています。 

このような問題を解決する標準的な方法は、インデックスを何らかの優先順位で並べ替え、最も「高価な」機会を最初に貪欲に照合して、価値の高いインタラクションが確実に保持されるようにすることです。 ここで、構造はさらに単純化されます。相対的な方向を決定し、並べ替えられた順序で要素をペアにすることによって問題を順列を構築するものとして扱うことができ、これにより制御された割り当て問題に帰着します。

 ## アルゴリズムのチュートリアル

 中心となるアイデアは、「小さい値を優先」、「固定小数点を優先」、または「大きな値を優先」のいずれとして扱うのが最適であるかに基づいてインデックスを 3 つのグループに分類することですが、厳密な分類の代わりに、選択肢間の潜在的なゲイン差に応じてインデックスを並べ替えることで順列を構築します。

1. 各インデックス i について、優先 a[i] と c[i] の間のゲイン差を計算します。 具体的には、i が順列の「左側」または「右側」にあることでより多くの利益が得られるかを把握する優先度の値を定義します。 
2. すべてのインデックスをこの優先順位に従って並べ替えます。 ソート順序によって、どのポジションを先に「小規模消費」として扱い、どのポジションを後で「大量生産」として扱うべきかが決まります。 この順序付けにより、一方の側に強い優先順位を持つインデックスが最初に処理され、後の競合が回避されます。 
3. 2 つのポインタを維持します。1 つは順列範囲内の使用可能な最小値から開始し、もう 1 つは使用可能な最大値から開始します。 
4. ソートされた順序でインデックスを走査します。 各インデックス i に対して、左ポインタから値を割り当てるか、右ポインタから値を割り当てるか、または i 自体を割り当てるかを決定します。 
5. i を割り当てること自体が、それをどちらかの側に強制する場合と比較して最も高い即時寄与 b[i] を生み出す場合、および i がまだ利用可能な場合は、p[i] = i を割り当て、利用可能なプールから i を削除します。 
6. それ以外の場合は、より小さい値 (左ポインタ) を配置するか、より大きな値 (右ポインタ) を配置すると、このインデックスのゲインが向上するかを比較します。 a[i] が c[i] よりも優れている場合は、使用可能な最小値を割り当てます。 それ以外の場合は、使用可能な最大値を割り当てます。 
7. 割り当て後に対応するポインタを移動し、すべてのインデックスが処理されるまで続行します。 

重要な考え方は、固定点は明らかに有益である場合は常に貪欲に処理され、残りのインデックスは値の範囲の両端から埋められる 2 つの単調グループに分割されるということです。 

### なぜ効果があるのか

 順列制約により、すべての値が 1 回だけ使用されることが強制されるため、どの戦略でも「小さな割り当て」と「大きな割り当て」をグローバルに組み合わせる必要があります。 優先順位に従ってインデックスを並べ替えることにより、柔軟性が最も高いときに、各側の最も強い要求が早期に満たされることが保証されます。 インデックスが左側または右側に配置されると、境界値のみが消費され、単調な構造が維持されます。 これにより、すべての決定がグローバルに一貫した優先度の強さの順序で行われるため、後の割り当てによって以前のより良い選択が妨げられることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        c = list(map(int, input().split()))

        idx = list(range(n))

        # priority: how much we prefer left (a) vs right (c)
        idx.sort(key=lambda i: a[i] - c[i])

        p = [0] * n
        used = [False] * (n + 1)

        l, r = 1, n

        for i in idx:
            # try fixed point if possible
            if not used[i + 1] and b[i] >= max(a[i], c[i]):
                p[i] = i + 1
                used[i + 1] = True
                continue

            # otherwise assign to better side
            if a[i] >= c[i]:
                while used[l]:
                    l += 1
                p[i] = l
                used[l] = True
                l += 1
            else:
                while used[r]:
                    r -= 1
                p[i] = r
                used[r] = True
                r -= 1

        print(*p)

if __name__ == "__main__":
    solve()
```実装は、差分 a[i] - c[i] に従ってインデックスを並べ替えることから始まります。これにより、より小さい割り当てを優先するインデックスに向けて初期の処理が偏ります。 これにより、後で競合することなく、左から右への入力が一貫して機能するようになります。 

使用される配列は、固定点を含め、どの順列値がすでに割り当てられているかを追跡します。 ポインタ l と r は、使用可能な最小値と最大値を維持し、すでに使用されている値をスキップします。 

固定小数点条件は、b[i] が i をそれ自体に割り当てることを正当化するのに十分強いかどうかをチェックします。 その場合は直ちにロックさせていただきます。 これにより、固定した方が厳密に優れている位置で極端な値を無駄にすることがなくなります。 

その後、a[i]とc[i]のどちらが大きいかに応じて、残りのインデックスを左端または右端に貪欲に割り当てます。 ソートされた順序により、この貪欲な決定が以前の割り当てと矛盾しないことが保証されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての値が固定小数点を強く優先する場合です。これは、すべての i について b[i] が a[i] および c[i] の両方よりも大きいことを意味します。 この状況では、アルゴリズムはソートされたパス内のすべての位置を固定点として割り当て、すべてのインデックスを即座に消費します。 ポインタ ロジックは決してトリガーされません。これは正しいことです。固定点からの逸脱は厳密に合計スコアを減らすことになるからです。 

別のエッジ ケースは、すべての a[i] が c[i] よりもはるかに大きい場合に発生し、すべてのインデックスが左側を優先するようになります。 ソートされた順序により、インデックスは左への割り当てを優先して処理され、l ポインタは衝突することなく 1 から n にきれいに進みます。 使用済みの追跡によって一貫性が保証されるため、インデックスはすでに使用されている値を取得しようとすることはありません。 

3 番目のエッジ ケースはまったく逆で、すべての c[i] が a[i] を支配します。 次に、r ポインタは n から 1 まで下方向に移動し、再び重複のない有効な順列が生成されます。 両側の対称性により、極度のスキューの下でもアルゴリズムが一貫して動作することが保証されます。
