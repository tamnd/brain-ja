 ## 解決策
 ## 問題の理解

 各エッジに色と呼ばれるラベルが付けられた有向グラフが与えられます。 ノード 1 から始めて、有向エッジに沿って何度でも歩くことができ、ノードを再訪問してエッジを再利用することができます。 唯一の制限は、パスを横断するときに、同じ色の 2 つの連続するエッジを取ることができないことです。 私たちのタスクは、この制約の下でノード 1 からどのノードに到達できるかを判断することです。 

したがって、グラフ自体は静的ですが、ウォークの有効性は最後に使用されたエッジの履歴に依存します。 これは、到達可能性がノードの単なるプロパティではなく、ノードとそこに到達するために使用された最後のエッジの色で構成されるペアのプロパティであることを意味します。 

制約は大きく、すべてのテスト ケースにわたるノードとエッジの合計数は 100 万に達する可能性があります。 これにより、パスを明示的にシミュレートしようとしたり、メモ化せずにエッジのシーケンスを探索しようとしたりするソリューションは即座に除外されます。 パスがサイクルによって任意に長くなる可能性があり、同じノードが異なる最終色のコンテキストで再訪問される可能性があるため、パス上のナイーブ DFS または BFS は爆発します。 

同じ色の複数のエッジがサイクルを形成する場合、微妙なエッジ ケースが発生します。 たとえば、ノード 1 に 1 -> 2 (赤)、2 -> 3 (赤)、3 -> 1 (赤) のような自己ループ構造がある場合、通常のグラフの意味では構造的にすべてのノードに到達可能ですが、1 つの赤いエッジを取得した後は 2 番目の赤いエッジをすぐに使用できないため、カラフルな制約の下ではノード 2 のみに到達できます。 

もう 1 つの特殊なケースは、2 つの異なる色を介してノードに到達できるが、そのうちの 1 つだけがさらに進むことができる場合に発生します。 たとえば、赤色のエッジを介してノードに到達すると、発信エッジも赤色であるためすべての発信エッジがブロックされ、青色のエッジを介してノードに到達すると継続が許可される場合、単純な Visited[node] アプローチではこれらの状態が誤ってマージされ、到達可能性を過大評価または過小評価することになります。 

## アプローチ

 ブルートフォースアプローチでは、最後に使用されたエッジカラーを追跡しながら、ノード 1 から始まるすべての可能なウォークを探索しようとします。 これを状態 (ノード、last_color) にわたる DFS または BFS としてモデル化できます。 各状態から、色が last_color と異なるすべての出力エッジを試します。 

このアプローチは、制約を直接強制するため正しいですが、状態空間の根本的な爆発に悩まされます。 最悪の場合、各ノードに多数の異なる最終色が到達し、エッジ遷移ごとに別の状態が生成される可能性があります。 エッジの数として m を表す場合、可能な色の数も最大 m になる可能性があるため、状態グラフは病的な場合には O(nm) に近づく可能性があります。 これは、合計入力サイズ 10^6 には大きすぎます。 

重要な点は、最後の色は正確性にとって重要ですが、必要なのは、考えられるすべての最後の色ではなく、任意の有効な最後の色でノードに到達できるかどうかだけを知る必要があるということです。 これは、遷移を効率的に表現し、同等の状況の再訪を避けることができれば、状態を超えた BFS が依然として実行可能であることを示唆しています。 

したがって、各状態が (node, last_color) である層状状態グラフにグラフを拡張しますが、訪問した遷移を暗黙的に保存することで、ノードごとのすべての色の明示的な保存を回避します。 各有向エッジは、c_prev != c_i の場合は必ず (u, c_prev) から (v, c_i) への遷移になります。 秘訣は、(1, 0) から始まる BFS を実行することです。0 は「前の色がない」ことを表し、繰り返しを防ぐために状態を訪問済みとしてマークします。 

各状態は最大 1 回処理され、各エッジは状態間で最大一定数の遷移を誘発するため、合計の複雑さは、実際に発見される有効な状態遷移の数に比例し、O(n + m) によって制限されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (カラー上のパス DFS) | 最悪の場合は指数関数的 | O(nm) | 遅すぎる |
 | 状態 BFS (ノード、最後の色) | O(n + m) 償却 | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、各状態が最後に使用されたエッジの色を記憶している拡張状態空間での検索として再定式化します。 

1. 状態 (1, 0) から開始します。0 はエッジがまだ取得されていないことを表します。 これにより、ノード 1 からの発信エッジを使用できるようになります。 最初のステップには色の制限がないため、この初期化が必要です。 
2. 各エントリがペア (隣接、色) を格納する隣接リストを作成します。 これにより、ノードから発信されるすべての遷移を効率的に列挙できるようになります。 
3. 状態のキュー (node、last_color) を使用して BFS を実行します。 状態 (u, c_prev) をデキューするたびに、すべての出力エッジ (u -> v, c_i) を探索します。 c_i が c_prev と異なる場合、遷移は有効です。 
4. 有効な遷移ごとに、状態 (v, c_i) に移動します。 この状態が以前に訪問されたことがない場合は、訪問済みとしてマークし、キューにプッシュします。 これにより、同一の状況を再処理することがなくなり、指数関数的な爆発が防止されます。 
5. ノードが何らかの状態で訪問されたことがあるかどうかを記録する別の配列到達可能[ノード]を維持します。 新しい状態 (v, c_i) に到達するたびに、reachable[v] を true としてマークします。 
6. BFS が完了すると、reachable[node] が true であるすべてのノードが出力されます。 

正確性は、考えられるすべての有効な最後のカラー コンテキストを 1 回だけ探索することにかかっており、有効なウォークが見逃されないようにしながら、サイクルによって引き起こされる無限の再訪問を防ぎます。 

### なぜ効果があるのか

 重要な不変条件は、状態 (u, c_prev) が処理されるたびに、BFS が u で終わり、最後のエッジの色 c_prev を持つ有効なカラフルなパスをすべてすでに検出していることです。 有効なパスの拡張はすべてそのような状態からのものでなければならず、すべての有効な拡張は異なる色の出力エッジに正確に対応します。 各状態は最大 1 回訪問され、すべての有効な拡張が探索されるため、到達可能なノードが見逃されることはありません。 逆に、訪問されたすべての状態は構造上、有効なカラフルなパスに対応するため、間違ったノードが到達可能とマークされることはありません。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())

        g = [[] for _ in range(n + 1)]
        for _ in range(m):
            u, v, c = map(int, input().split())
            g[u].append((v, c))

        # visited states: (node, last_color)
        # since colors are up to m, we store dict per node
        visited = [set() for _ in range(n + 1)]

        q = deque()
        q.append((1, 0))
        visited[1].add(0)

        reachable = [False] * (n + 1)
        reachable[1] = True

        while q:
            u, last_c = q.popleft()

            for v, c in g[u]:
                if c == last_c:
                    continue
                if c in visited[v]:
                    continue
                visited[v].add(c)
                reachable[v] = True
                q.append((v, c))

        res = [str(i) for i in range(1, n + 1) if reachable[i]]
        print(" ".join(res))

if __name__ == "__main__":
    solve()
```実装は BFS 状態を正確にミラーリングします。 隣接リストにはエンドポイントとエッジの色の両方が保存されるため、エッジごとに一定時間で遷移をチェックできます。 訪問された構造はノードごとに維持され、最後に使用された色によってキー付けされるため、同じ状態のペアを再訪問することがなくなります。 

重要な詳細は、BFS をカラー 0 で初期化することです。このセンチネルにより、色に関係なく常に最初のエッジを取得できることが保証されます。 もう 1 つの微妙な点は、新しい状態をデキューするときではなく、新しい状態を発見した瞬間に到達可能[v]をマークすることです。これにより、新しく発見された状態で最初に到達するノードの欠落を回避できます。 

## 実用的な例

 ### 例 1

 入力グラフ: 1 -> 2 (赤)、2 -> 3 (青)、1 -> 3 (赤)

 状態全体にわたる BFS をシミュレートします。 

| ステップ | 状態 (ノード、色) | 移行 | 新しい州 |
 | --- | --- | --- | --- |
 | 1 | (1, 0) | 1 から赤を 2 に、赤を 3 に変換します。 (2、赤)、(3、赤) |
 | 2 | (2、赤) | 赤 -> 青のエッジを 3 まで許可 | (3、青) |
 | 3 | (3、赤) | 有効な発信内線番号がありません | なし |
 | 4 | (3、青) | 出力エッジがありません | なし |

 すべてのノード 1、2、3 が到達可能になります。 

これは、同じノード (3) が複数のカラー コンテキストで到達でき、両方を追跡する必要があることを示しています。 

### 例 2

 入力グラフ: 1 -> 2 (赤)、2 -> 3 (赤)、3 -> 4 (赤)、2 -> 4 (青)

 | ステップ | 状態 | 移行 | 新しい州 |
 | --- | --- | --- | --- |
 | 1 | (1, 0) | 1 -> 2 (赤) | (2、赤) |
 | 2 | (2、赤) | 3 には赤エッジを使用できませんが、4 には青を使用できます | (4、青) |
 | 3 | (4、青) | ターミナル | なし |

 ノード 3 へのすべてのパスが連続した赤いエッジを強制するため、ノード 3 には到達しません。 色の変更によりノード 4 に到達できます。 

これは、到達可能性がグラフの接続性だけでなく色の遷移にも依存することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) 償却 | 各状態 (ノード、last_color) は 1 回訪問され、各エッジは有効な色の遷移ごとに最大 1 回処理されます。 
| スペース | O(n + m) | 隣接リストとノードごとの訪問状態追跡 |

 テスト ケース全体の合計入力サイズは 100 万のノードとエッジによって制限され、各状態遷移は定数時間です。 これにより、ソリューションが制限内で快適に実行されることが保証されます。

 ## 特殊なケース

 微妙なケースとして、複数の入力カラーを介してノードに到達可能であるにもかかわらず、さらに走査できるのは 1 色だけである場合が発生します。 ノード 1 から赤を経由し、ノード 1 から青を経由してノード 2 に到達するとします。 2 からの発信エッジがすべて赤の場合、状態 (2、青) のみが続行でき、(2、赤) は行き止まりになります。 訪問先がノードおよび色ごとに追跡されるため、アルゴリズムはこれらの状態を正しく分離し、両方の状態が独立して調査されます。 

もう 1 つのケースは、ノードが最初に「デッド」カラー状態で発見された場合です。 最初の発見はどこにもつながりませんが、reachable[node] は依然として true に設定されており、後で生産的な色の状態もそれに到達する可能性があります。 ノードレベルの到達可能性は特定の状態が継続できるかどうかに依存しないため、これにより正確さが保証されます。
