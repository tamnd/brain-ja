 ## 解決策
 ## 問題の理解

 円形に配置された箱が与えられ、それぞれの箱にはいくつかの同じアイテムが入っています。 人は最初のボックスから開始し、一定のルーチンを繰り返し実行します。つまり、現在のボックスにアイテムがまだある場合は、アイテムを 1 つだけ削除し、実行中のカウンターを増やしてから、次のボックスに移動します。 現在のボックスがすでに空の場合は、削除ステップをスキップして先に進みます。 これは、すべてのボックスが空になるまで無期限に続きます。 

私たちが計算しなければならない重要な数量は、すべての値の合計である最終的な食べたアイテムの総数ではなく、より動的なものです。各ボックス インデックスについて、特定のボックスが初めて空になったまさにその瞬間に食べられたアイテムの総数を知りたいのです。 

この制約は、すべてのテスト ケースにわたるボックスの合計数が最大 200,000 である一方、個々の値は 10^9 まで大きくなる可能性があることを意味します。 これにより、ステップごとに 1 つの項目を減らすシミュレーションは直ちに除外されます。 単純なプロセスでは、全サイクルごとに最大ですべての a_i 操作の合計が必要になる可能性があります。また、ウォークは周期的であるため、訪問数は簡単に O(n * max(a_i)) に達する可能性がありますが、これは完全に実行不可能です。 

単純なアプローチを破る微妙な問題は、空の時間が独立していないことです。 たとえば、1 つのボックスの値が非常に大きい場合、小さなボックスが終了した後も長い間そのボックスがサイクルに寄与し続けるため、それらの小さなボックスが空になるタイミングが変化します。 ボックスを個別に処理しようとしたり、単一のパスを想定したりするソリューションはすべて正しくありません。 

具体的な失敗例として、n = 3、a = [100, 1, 1] を考えます。 ボックス 2 と 3 はすぐに空になりますが、ボックス 1 がプロセスを長時間支配します。 単純な「各ボックスを個別に処理する」アプローチでは、ボックス 1 がサイクルを維持し、システムが安定する前に発生する完全な回転数を増大させるという事実を見逃して、各ボックスがそれ自体の値に比例して終了すると仮定する可能性があります。 

## アプローチ

 直接シミュレーションは文字通りルールに従います。 ポインタをインデックス内で循環させ、可能な限りデクリメントし、各ボックスがゼロに達した瞬間を記録します。 これは正しいですが、コストがかかります。各ステップでボックスからちょうど 1 ユニットが削減されるため、合計で sum(a_i) 演算が実行されます。 最大 10^9 の値では、これは制限をはるかに超えています。 

プロセスの構造は、時間をボックスごとのアクションではなく、個別のグローバルなステップとして見ると理解しやすくなります。 各ステップは、循環的な順序でのボックスへの 1 回の訪問に対応します。 長さ n の 1 つの完全なサイクルにわたって、空でないすべてのボックスはちょうど 1 つの減少に寄与します。 これは、完全なサイクル中に、すべてのボックスが 0 になるまで 1 ずつ減り、少なくとも 1 つのボックスが 0 以外である間、プロセスが継続することを意味します。 

重要な観察は、視点を逆転させることです。時間の進みをシミュレートする代わりに、各ボックスが生き残る全サイクルと部分サイクルの数に基づいて、各ボックスが終了するグローバル時刻を決定します。 ボックスの値が a_i の場合、そのボックスはそれ自体への a_i の完全な「訪問」の間アクティブのままですが、それらの訪問は全サイクルにわたって分散されます。 完全なサイクルごとにすべてのアクティブなボックスが 1 つずつ減少するため、k 個の完全なサイクルの後、すべてのボックスは k 個のユニットを失います。 したがって、ボックスは a_i サイクル後に空になりますが、正確な瞬間は、他のボックスがどのように早く終了してプロセスを短縮するかによって異なります。 

この問題は、各ボックスが消えるまでに実質的に何回の完全なサイクルが必要かを追跡しながら、ボックスを a_i の降順に処理することと同等になります。 ボックスが考慮されると、以前のボックスの一部がすでに削除されており、将来のサイクルに参加していない可能性があることを考慮して、ボックスがゼロに達するまでにまだ完全に何回回転する必要があるかを計算できます。

これは、古典的なオフライン順序付け戦略につながります。つまり、サイクル内でまだ「生きている」要素の数を維持しながら、最も高い a_i から下に向かってボックスを処理します。 新しい値を処理するたびに、以前の完全なサイクルによって寄与されたステップの合計数と、このボックスが終了するまでの残りの部分サイクルを計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(合計 a_i) | O(n) | 遅すぎる |
 | 仕分け + 循環会計 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 このプロセスを、現在のアクティブ ボックスのセットに対して完全なサイクルが繰り返されるものとして再解釈します。 

1. 各ボックスをインデックスと初期値に関連付け、a_i の降順にボックスを並べ替えます。 この順序により、いつボックスがプロセスから「ドロップアウト」するかを推論することができます。 
2. サイクル内でまだアクティブなボックスの数を表す変数 cnt を維持します。 すべてのボックスが参加しているため、最初は cnt = n になります。 
3. すべてのボックスを組み合わせてこれまでに実行されたアイテム削除の合計数を表す実行ポインタ時間を維持します。 これは実質的に世界的なタイムラインです。 
4. a_i の降順にボックスを処理します。 値 x を持つボックスに到達すると、そのボックスが空になる前に現在のアクティブ セットのちょうど x サイクルだけ生き残ったものと解釈します。 各完全なサイクルは、サイクルごとに 1 回、このボックスに影響を与える cnt 操作に寄与します。 
5. したがって、このボックスが終了する瞬間は、時間 + x * cnt です。 これを回答として記録します。 
6. このボックスは今後のサイクルに参加しないため、このボックスを処理した後、cnt を 1 つデクリメントします。 サイクルが短縮されたため、残りのボックスはより速く完了します。 
7. すべてのボックスが処理されるまで続行し、結果を元のインデックスにマッピングします。 

重要な点は、ソートによってボックスが常にシステムから消える順序で処理されることです。 より大きなボックスが考慮されると、残りすべてのボックスのサイクル長が効果的に短縮されます。これはまさに実際のプロセスで起こっていることです。 

### なぜ効果があるのか

 常に、すべてのアクティブ ボックスが固定された循環順序でアクセスされ、各フル サイクルですべてのアクティブ ボックスがちょうど 1 単位ずつ減ります。 これは、システムが段階的に進化し、各段階が現在のアクティブ セットの 1 回の完全な走査に対応することを意味します。 値による並べ替えにより、これらのフェーズの終了を正しい順序でシミュレートすることが保証されます。つまり、最大の値がほとんどのフェーズで生き残るため、サイクル サイズの最も初期の構造変化が定義されます。 各ボックスは消滅するまでサイクルごとに 1 ユニットだけ寄与するため、その値に現在のサイクル サイズを乗算すると、グローバル時間での合計寄与が取得され、それを削除すると、実際のダイナミクスと一致して将来のサイクル長が短縮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        arr = [(a[i], i) for i in range(n)]
        arr.sort(reverse=True)
        
        ans = [0] * n
        cnt = n
        cur_time = 0
        
        for val, idx in arr:
            ans[idx] = cur_time + val * cnt
            cur_time += val
            cnt -= 1
        
        print(*ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず各値を元のインデックスと組み合わせて、並べ替え後に結果を復元できるようにします。 降順で並べ替えることにより、ボックスがサイクルへの寄与を効果的に停止する順序でボックスが処理されるようになります。 

変数 cnt は、まだアクティブなボックスの数を追跡します。これは、1 つの完全なサイクルで訪問される位置の数に直接対応します。 変数 cur_time は、完了したフェーズの寄与を累積します。 ans[idx] を割り当てるとき、完了したサイクルと、現在のサイクル長でスケールされた独自の残りの寄与を組み合わせることによって、このボックスが終了するときの正確なグローバル ステップを計算します。 

よくある間違いは、各ボックスの処理後に cnt が変化することを忘れることで、静的なサイクル長を誤って仮定することになる。 cntの削減が不可欠なのは、一旦ボックスが空になると、今後のサイクルにはcntが含まれなくなり、残っているすべてのボックスに必要な時間が短縮されるためである。

すべてのテスト ケースの合計 n は最大 200,000 であるため、O(n log n) ソリューションは制限内に問題なく収まります。 このアルゴリズムは、テスト ケースごとに並べ替えと単一の線形スイープのみを実行します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    import math

    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))
            arr = sorted([(a[i], i) for i in range(n)], reverse=True)
            ans = [0]*n
            cnt = n
            cur_time = 0
            for val, idx in arr:
                ans[idx] = cur_time + val * cnt
                cur_time += val
                cnt -= 1
            out.append(" ".join(map(str, ans)))
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 n = 1 の場合、システムにはサイクリング効果はありません。 単一のボックスは繰り返し訪問されますが、他に位置がないため、各ユニットが順番に消費され、終了時間はちょうど a_1 になります。 cnt は 1 から始まり、代入前に変更されないため、アルゴリズムはこれを処理します。そのため、ans[0] は 0 + a_1 * 1 になります。 

同じ値、たとえば [k, k, k] の場合、すべてのボックスは何らかの順序で処理されますが、それぞれのボックスでサイクル長が 3、2、1 ずつ減少します。出力は、インデックスに応じて何らかの順序で k・3、k・2、k・1 になります。 各除去によりcntが均一に減少し、同じ式構造が各要素に適用されるため、アルゴリズムはこれを正しく反映している。
