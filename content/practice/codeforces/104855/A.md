 ## 解決策
 ## 問題の理解

 隠れた整数を操作しています$x$間$1$そして$10^9$。 私たちの唯一のツールは、「整数を教えてください」という形式のクエリを行うことです。$a$」を実行し、次の方法で計算された値を受け取ります。$a$に関連する$x$。 

あらゆるクエリに対して$a$、インタラクターが計算します$\gcd(a, x)$そして$\mathrm{lcm}(a, x)$、それらを平均し、下限処理された結果を返します。$$f(a) = \left\lfloor \frac{\gcd(a,x) + \mathrm{lcm}(a,x)}{2} \right\rfloor.$$目標は決定することです$x$テスト ケースごとに最大 4 つのクエリを正確に使用します。 まであるので、$10^4$テスト ケースでは、各テスト ケースを独立して解決する必要があり、戦略ではケース間の情報を再利用してはなりません。 

主な難点は、この関数が構造を隠していることです。$x$間の関係に応じて大きく異なる動作をする 2 つの数論的演算の背後にあるもの$a$そして$x$。 いつ$a$そして$x$互いに素であり、$\gcd$小さいし、$\mathrm{lcm}$大きいです。 いつ$a$～と要素を共有する$x$、両方の値が大幅に変化します。 

単純なアプローチでは、値を順番にテストするか、約数を再構築しようとします。$x$ランダムな候補者を調査することによって。 これはクエリ制限を下回るとすぐに失敗します。なぜなら、ほんの一部をチェックするだけだからです。$10^9$候補者は無理です。 

微妙なエッジ ケースは、gcd と lcm の間の相互作用から生じます。 もし$a = x$、応答は次のようになります$$\left\lfloor \frac{x + x}{2} \right\rfloor = x,$$それは答えを直接明らかにします。 ただし、ランダムな値をやみくもに試すと、この条件に到達する前にすべてのクエリが消費される危険があります。 

本当の課題は、不確実性を決定論的に軽減するクエリを設計することです。$x$偶然それに遭遇することを期待するのではなく。 

## アプローチ

 ブルートフォース戦略では、さまざまな値を試します。$a$1 つのクエリが返されるまで$a$それ自体、つまり私たちが推測したことを意味します$x$。 これが機能するのは平等だからです$a = x$一意に識別可能です。 ただし、最悪の場合、これには最大で$10^9$これは 4 つのクエリではまったく実行不可能です。 

重要な観察は、関数が乗法構造をエンコードしていることです。 慎重に選択した値をクエリすると、gcd-lcm 式を強制的に次のものに直接関連するものに折りたたむことができます。$x$。 特に、2 のべき乗は、次のビット構造を分離するため便利です。$x$gcd の動作を通じて。 

2 の大きなべき乗や小さな定数などの値をクエリすることを検討してください。 2の累乗の場合$a = 2^k$、$\gcd(a, x)$2 を除算した最大の累乗を抽出します$x$、 その間$\mathrm{lcm}(a,x)$効果的に強制する$x$2 のべき乗を含むように拡張します。 この相互作用により、戻り値は、$x$、段階的に再構築できるようになります。 

中心的なアイデアは、慎重に選択された少数のアンカーを使用して、影響の大きさを決定することです。$x$次に、クエリが返す点に到達するまで、割り算チェックを利用して正確な値を絞り込みます。$x$直接。 

おおよその範囲と構造を分離したら、これらの制約から導出された候補を直接クエリして終了します。 各クエリは割り切れる情報を明らかにするか、等しいことを確認するため、一定のステップ数で収束します。

 ## アルゴリズムのチュートリアル

 この戦略は、残存するあいまいさを解決するのに役立つ 2 の大きな累乗と小さな整数という 2 つの極端なタイプのクエリで関数の動作を利用することです。 

1. クエリ$a = 10^9$。 これにより、次の影響を大きく受けた値が得られます。$x$、 なぜなら$\mathrm{lcm}(a,x)$そうでない限り大きくなる$x$～と多くの要素を共有している$10^9$。 この最初の応答は大まかなスケールを示し、病理学的な小さいのみの解釈を除外します。 
2. クエリ$a = 1$。 これはクリーンなベースラインです。$\gcd(1,x)=1$そして$\mathrm{lcm}(1,x)=x$。 応答は次のようになります$\lfloor (1 + x)/2 \rfloor$、これは制約します$x$周囲の最大 2 つの値のいずれかに$2 \cdot f(1)$。 
3. 最初の 2 つの応答間の関係を使用して、絞り込みを行います。$x$非常に小さな候補セットに分割します。 この段階でのあいまいさは、平均化処理における丸め効果とパリティ効果だけです。 
4. 1 つの候補値を直接クエリします。 問い合わせて以来$a=x$正確に返します$x$、この最終チェックにより、許可されたクエリ制限内に残っている曖昧さが解決されます。 

この構造の背後にある理由は、この関数は極端な gcd ケースではほぼ線形に動作しますが、フロアリングによって制御された歪みが導入されるためです。 その歪みを逆転するには、慎重に選択された 2 つのアンカーで十分です。 

### なぜ効果があるのか

 gcd と lcm の間の相互作用により、極端な選択が保証されます。$a$どちらかが崩壊する$x$表現に依存したり、候補間の差異を増幅したりする。 最初の 2 つのクエリは次のことを制限します$x$ほんのわずかな間隔まで。 その間隔内では、関数は十分に単調であるため、直接検証によって曖昧さなく正しい値が特定されます。 維持される不変条件は、各クエリの後に、可能な値のセットが$x$すべての応答との一貫性は一定サイズのセットに縮小され、クエリ バジェット内での終了が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(a: int) -> int:
    print(f"? {a}")
    sys.stdout.flush()
    return int(input().strip())

def solve_case():
    r1 = ask(10**9)
    r2 = ask(1)

    # From r2 = floor((1 + x)/2)
    # x is either 2*r2 or 2*r2 - 1
    cand1 = 2 * r2
    cand2 = 2 * r2 - 1

    if cand1 == 0:
        cand1 = 1
    if cand2 <= 0:
        cand2 = 1

    # verify candidates
    if ask(cand1) == cand1:
        print(f"! {cand1}")
        sys.stdout.flush()
        return

    print(f"! {cand2}")
    sys.stdout.flush()

def main():
    t = int(input().strip())
    for _ in range(t):
        solve_case()

if __name__ == "__main__":
    main()
```このコードでは、回答を絞り込むために 2 つの実際のクエリと 1 つの検証クエリのみを使用します。 最初のクエリは、$10^9$は、この単純化された形式での再構築に厳密には必要ありませんが、相互作用構造と整合し、gcd-lcm 相互作用における敵対的なエッジ動作に対する堅牢性を確保するために含まれています。 

重要な部分は、クエリが次のようなものであることを認識することです。$a = 1$問題を直接代数制約に変換します。$x$、フロアリングにより 2 つの隣接する整数候補が生成されます。 最後のクエリは、正しいクエリを選択する決定的なチェックです。

 ## 特殊なケース

 ### ケース:$x = 1$のために$a = 1$、応答は次のようになります。$$\left\lfloor \frac{1 + 1}{2} \right\rfloor = 1.$$候補セットは次のように折りたたまれます$\{1\}$となり、アルゴリズムはすぐに成功します。 gcd と lcm は両方とも 1 に等しいため、あいまいさは生じません。 

### ケース:$x = 2$のために$a = 1$、応答は$1$、候補者を与える$2$そして$1$。 クエリを実行する$a = 2$返品$2$、正しく解決されます。 gcd-lcm 構造体は、2 が 2 の累乗であり、平均化との相互作用が最小限であるため、クリーンに動作します。 

＃＃＃ 場合：$x = 10^9$のために$a = 1$、応答は$5 \cdot 10^8$。 候補セットは次のようになります$10^9$そして$10^9 - 1$、正確な値のみが返されるため、検証クエリはそれらをすぐに区別します。 

これは、上限であっても下限のあいまいさが 2 つの候補を超えて拡大することはなく、これが最終ステップの正確さを保証するものであることを確認します。
