 ## 解決策
 ## 問題の理解

 タスクは、アリ識別プログラムが割り当てる次の識別子を回復することです。 入力は、認識システムが現在認識している識別子を記述します。 一部の値は有効な識別子ですが、負の数値や有効範囲をはるかに外れた数値などの不正な値は無視する必要があります。 残りの非負の識別子の中で、出現しないゼロから始まる最小の整数を見つける必要があります。 

入力には最大 100 万個の値を含めることができ、各値にはほぼ 100 桁が含まれる場合があります。 桁の長さが大きいため、固定サイズの整数型を使用する言語では、すべての値に対して通常の整数解析に依存することができなくなります。 さらに重要なのは、エントリが 100 万件ある場合、コレクション全体を繰り返しスキャンしたり、多数の回答候補をテストしたりするソリューションでは、多大な作業が必要になります。 入力値の数に関して線形に近いアプローチが必要です。 

回答範囲に関する重要な観察は、識別子の数から得られます。 N 個の入力値がある場合、欠落している最小の非負整数が N より大きくなることはありません。0 から N-1 までのすべての数値が出現したとしても、それらは N 個しか存在しないため、最初に考えられる欠損値は N になります。 これは、N より大きい値は答えに影響を与えず、すぐに破棄できることを意味します。 

いくつかの特殊なケースは、誤って処理されやすいものです。 値がない場合、セットは空であり、答えはゼロになります。```
Input:
0
```正しい出力は次のとおりです`0`。 0 ではなく 1 から検索を開始するソリューションはここで失敗します。 

2 番目のケースには、数値のように見えても有効な識別子ではない無視される値が含まれます。```
Input:
5
-3
999999999999999999999999
abc
0
1
```正しい出力は次のとおりです`2`。 関係があるのは 0 と 1 だけです。 解析されたすべての値を保存したり、すべての入力が通常の整数に適合すると仮定したりする不用意なソリューションは、メモリを浪費するか、解析中に失敗する可能性があります。 

先頭のゼロもバグの原因となる可能性があります。```
Input:
3
000
001
3
```正しい出力は次のとおりです`2`。 価値観`000`そして`001`0と1を表します。 これらを異なる文字列として扱うと、0 と 1 が存在しないと誤って認識されてしまいます。 

## アプローチ

 直接的な解決策では、候補者の番号を繰り返し確認することになります。 ゼロから開始して、それが入力セットに現れるかどうかをテストし、欠損値が見つかるまで 1、2 などと続けます。 存在しない最初の候補がまさに必要な識別子であるため、これは正しいです。 ハッシュ セットの場合、各検索は O(1) であることが期待されますが、このアプローチでは、すべての有効な値を保存し、候補を繰り返し検査する方法が必要です。 最悪の場合、入力には 0 から N-1 までのすべての数値が含まれるため、N 個の値を読み取った後、約 N 回の検索を実行します。 これはハッシュでは許容されますが、各候補の入力配列をスキャンする単純な実装では、約 N² の操作が必要になります。これは、100 万のエントリに対して約 10¹² のチェックに相当します。 

より良いアプローチは、重要な値のみを制限することから生まれます。 答えは最大でも N であるため、0 から N までの範囲内のどの数値が存在するかを知る必要があるだけです。 サイズ N+1 のブール配列を作成できます。 各入力値を読み取る際、負の値と N より大きい値は無視されます。有用な範囲内の値については、対応する位置にマークが付けられます。 すべての入力を処理した後、マークされていない最初の位置が欠落している識別子になります。 

難点は、入力数値が最大 100 桁であるため、すべてを整数に変換するのは不必要であり、安全でない可能性があることです。 代わりに、テキスト表現を N と比較します。符号と先頭のゼロを削除した後、値は、その長さが最大でも N の長さであるか、同じ長さで辞書編集的に N より大きくない場合にのみ使用できます。 

ブルート フォースは欠損値の定義を直接チェックするため機能しますが、回答範囲を超えた値や繰り返しの検索に労力が無駄になります。 答えが N によって制限されるという観察により、問題を考えられる識別子の小さな接頭辞をマークすることに縮小できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) | O(N) | 遅すぎる |
 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 識別子の数を読み取り、配列を作成します`present`N+1 ポジション。 位置`i`識別子かどうかを表します`i`が表示されます。 答えが N に等しくなる可能性があるため、N の追加の位置が必要です。 
2. 各識別子をすぐに整数に変換するのではなく、文字列として読み取ります。 同じ数値の異なるテキスト形式が同一になるように、非負の値から先頭のゼロを削除します。 
3. 負の値、または正規化された値が N より大きい値は無視します。答えは最大でも N であることが保証されているため、そのような値は欠落している最小の識別子を変更できません。 
4. 残りの値をすべてマークします。`present`配列。 これには、最終的な検索に必要な情報が正確に記録されます。 
5.スキャン`present`インデックス 0 から上に向かって、値が false である最初のインデックスを出力します。 このインデックスは、現在割り当てられていない最小の識別子です。 

これが機能する理由は、答えとなる可能性のあるすべての識別子が配列で表現されているためです。 この範囲外の値は答えになり得ないため、値を無視しても情報は失われません。 

なぜ効果があるのか:

 すべての入力を処理した後、`present[x]`識別子の場合にまさに true です`x`すべての関連入力値の中に表示されます。`x`0 と N の間。最初のインデックスを考慮します。`k`それは偽りのままです。 小さい識別子ごとにマークが付けられるため、0 から 5 までのすべての値がマークされます。`k-1`存在します。 識別子`k`は存在しないため、欠落している識別子の中で最も小さいものになります。 より小さい値が欠落していない場合、スキャンを早期に停止することはできないため、生成される答えは常に正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def normalize_number(s):
    if s[0] == '-':
        rest = s[1:].lstrip('0')
        if rest == '':
            return "0"
        return None
    s = s.lstrip('0')
    return s if s else "0"

def solve():
    line = input().strip()
    if not line:
        return
    n = int(line)

    present = [False] * (n + 1)
    limit = str(n)

    for _ in range(n):
        s = input().strip()
        value = normalize_number(s)
        if value is None:
            continue

        if len(value) < len(limit) or (len(value) == len(limit) and value <= limit):
            x = int(value)
            present[x] = True

    for i, exists in enumerate(present):
        if not exists:
            print(i)
            return

if __name__ == "__main__":
    solve()
```の`normalize_number`この関数は、任意精度の演算を必要とせずに、大きな入力フォーマットを処理します。 先頭のゼロを削除し、ゼロを正しく処理し、真の負の値を拒否します。 

との比較`n`電話をかける前に起こる`int`。 100 桁の値は、問題になるほど小さいことがすでに証明されていない限り変換すべきではないため、これは重要な最適化です。 文字列の長さと辞書編集上の比較により、値が最大 N であることが示されると、値はブール配列の範囲内に収まるため、変換は安全になります。 

の`present`配列には、正確に N+1 個の可能な答えが格納されます。 最後のループはゼロから始まります。これにより、ゼロが有効な識別子であることを忘れるというよくある 1 つ違いの間違いを回避できます。

 ## 特殊なケース

非常に大きな数の場合は、次のことを考慮してください。```

0
1
999999999999999999999999999999
-2
3
```正規化された大きな値には N より多くの桁があるため、変換前に破棄されます。 負の値も破棄されます。 マークされた識別子は 0、1、および 3 であるため、スキャンでは 2 が返されます。
