 ## 解決策
 ## 問題の理解

 ダグラスは、ラットの個体数を推定するために古典的な捕獲と再捕獲の実験を実行します。 

初日に彼は捕まえます`n1`ネズミを捕まえ、すべてにマークを付けて放します。 2日目に彼は捕まえます`n2`ネズミ、その中には`n12`はすでにマークされています。 推定を手動で計算する代わりに、私たちのタスクは単純にチャップマン推定量を評価することです。$$\left\lfloor \frac{(n_1+1)(n_2+1)}{n_{12}+1}\right\rfloor-1$$そして結果の整数を出力します。 

入力は正確に 3 つの整数で構成されているため、検索、シミュレーション、または最適化は必要ありません。 すべての値は最大 10000 で、最大の製品になります$$(10000+1)^2 = 100020001,$$これは 32 ビットの符号付き整数内に簡単に収まります。 いずれにせよ、Python の整数には任意の精度があるため、オーバーフローが心配されることはありません。 

必要な作業は、1 つの乗算、1 つの整数除算、および 1 つの減算を評価することだけです。 一定時間を超えるアルゴリズムは不要になります。 

実装上の微妙な間違いは、整数演算ではなく浮動小数点演算を使用していることです。 たとえば、入力の場合```
10000 10000 3
```正しい結果は```
25004999
```浮動小数点除算を使用してから整数に変換することは、これらの制限でも機能する可能性がありますが、浮動小数点に依存する必要はなく、同様の問題で丸め誤差が発生する可能性があります。 整数フロア除算は数学的定義と直接一致します。 

もう 1 つの簡単な間違いは、最後の 1 の減算を忘れることです。 入力用```
1 1 1
```式は次のようになります$$\left\lfloor\frac{2\cdot2}{2}\right\rfloor-1
=2-1
=1,$$したがって、正しい出力は次のとおりです```
1
```商のみを出力すると、誤って生成されます。`2`。 

3 番目のよくある間違いは、数式内で追加されたものを省略していることです。 入力用```
0 0 0
```正しい計算は$$\left\lfloor\frac{1\cdot1}{1}\right\rfloor-1=0,$$だから答えは```
0
```使用する`n1 * n2 / n12`ゼロで割ることもできます。 

## アプローチ

 強引な解釈では、考えられるすべての集団サイズを考慮したり、どの値が観察された捕獲と互換性があるかを確認したり、繰り返しの実験をシミュレートしたりすることによって、集団を推定しようとします。 このようなアプローチは数学的には不必要であり、検索範囲が十分に選択されている場合は、数百万の候補値を調べる必要がある可能性があります。 

問題ステートメントでは、希望する推定値としてチャップマン推定量がすでに提供されています。 人口規模はアルゴリズム的に推測する必要があるものではありません。 3 つの入力値を指定された式に代入し、結果を計算するだけです。 

重要な観察は、推定器に必要なフロア演算がすでに含まれていることです。 整数フロア除算は、浮動小数点演算を使用せずにまったく同じ値を計算します。 その後、1 を引いて結果を出力します。

 ## アルゴリズムのチュートリアル

 1. 3 つの整数を読み取ります`n1`、`n2`、 そして`n12`。 
2. 分子を計算する`(n1 + 1) * (n2 + 1)`。 この式では、乗算する前に両方のキャプチャ カウントに 1 を明示的に加算します。 
3. 分子を次の値で割ります。`n12 + 1`整数フロア除算を使用します。 これは、推定器のフロア演算と正確に一致します。 
4. 商から 1 を引いて、チャップマン推定値を取得します。 
5. 結果の整数を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、問題で与えられた数学的定義を直接実装したものです。 整数のフロア除算を計算します$$\left\lfloor\frac{(n_1+1)(n_2+1)}{n_{12}+1}\right\rfloor,$$これは正確に推定の最初の部分です。 その後 1 を減算すると式が正確に完成するため、計算された値は必要な推定値と同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n1, n2, n12 = map(int, input().split())

answer = ((n1 + 1) * (n2 + 1)) // (n12 + 1) - 1
print(answer)
```プログラムは、標準入力から 3 つの整数を読み取ることから始まります。 

次の行では、式を直接評価します。 乗算は除算の前に実行され、正確な整数演算が維持されます。 使用する`//`数式には商の下限が必要なため、これは必須です。 

最後に、プログラムは 1 を減算し、結果を出力します。 特別なケースは必要ありません。`n12 + 1`は常に少なくとも 1 であるため、ゼロによる除算は発生しません。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n1, n2, n12 = map(int, input().split())
    print(((n1 + 1) * (n2 + 1)) // (n12 + 1) - 1)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    solve()
    sys.stdin = backup_stdin
    sys.stdout = backup_stdout
    return out.getvalue()

# provided sample
assert run("15 18 11\n") == "24\n", "sample 1"

# minimum values
assert run("0 0 0\n") == "0\n", "minimum input"

# all values equal
assert run("5 5 5\n") == "5\n", "all equal"

# no recaptured rats
assert run("10 20 0\n") == "230\n", "zero recaptures"

# maximum values
assert run("10000 10000 10000\n") == "10000\n", "maximum values"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`0 0 0`|`0`| 最小限の正当な入力と追加された入力の正しい処理 |
 |`5 5 5`|`5`| 除算後の正しい引き算 |
 |`10 20 0`|`230`| マークされたラットが再捕獲されなかった場合、分母は 1 になります。 
|`10000 10000 10000`|`10000`| 最大入力値と上限付近の演算 |

 ## 特殊なケース

 インプットを考慮する```
0 0 0
```アルゴリズムは計算します`(0 + 1) * (0 + 1) = 1`、で割る`0 + 1 = 1`、取得`1`、そして 1 を引いて生成します`0`。 分母がゼロになることはないため、すべての操作は明確に定義されています。 

インプットを考慮する```
1 1 1
```分子は`(1 + 1) * (1 + 1) = 4`。 で割る`1 + 1 = 2`与える`2`1 を引くと、`1`。 これにより、最終的な減算が推定量の一部であり、省略できないことが確認されます。 

インプットを考慮する```
10000 10000 3
```分子は`10001 × 10001 = 100020001`。 整数の床除算`4`収量`25005000`、そして 1 を引くと、`25004999`。 計算は完全に整数演算の範囲内に留まり、許可される最大の乗算を処理しながら丸めの問題を回避します。
