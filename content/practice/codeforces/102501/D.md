 ## 解決策
 ## 問題の理解

 遺伝子は、非常に長いアミノ酸鎖の始まりを変更する短いプログラムです。 入力にはそのようなプログラムが 2 つ含まれており、そのタスクは、単純なアミノ酸の十分に長い鎖ごとにそれらが常に同じように動作するかどうかを判断することです。 

チェーンが巨大なため、実際の入力を構築できません。 遺伝子が接触できる唯一の部分は、鎖の有限の接頭辞です。 各操作では、最初の 1 つまたは 2 つのアミノ酸を削除、複製、交換、結合、または分割することによって操作します。 複合アミノ酸は、子が他のアミノ酸である二分木です。 

両方の遺伝子の全長は最大でも 10000 です。これにより、多くの可能な入力タンパク質を試したり、完全なツリーを繰り返し拡張したりすることができなくなります。 ソリューションは、各操作をほぼ一定の時間で処理する必要があります。 複製を繰り返すと表現されるオブジェクトが指数関数的に大きくなる可能性があるため、操作のたびにアミノ酸構造全体をコピーするシミュレーションは遅くなりすぎます。 

主なエッジケースは、アミノ酸をアイデンティティではなく値として扱うことと、失敗を無視することから生じます。 例えば：```
L
R
```答えがあります`True`。 最初のアミノ酸は常に単純であるため、両方の操作は考えられるすべての入力に対して失敗します。 成功した変換のみを比較する不注意な実装では、それらが異なるものとして誤って報告される可能性があります。 

もう 1 つの重要なケースは、複雑なアミノ酸の構造的同等性です。```
PU
SS
```答えがあります`True`。 2 つの遺伝子は元の鎖を変更せずに残します。 中間構造は異なっていてもかまいませんが、最終的なバイナリ ツリーは構造ごとに比較する必要があります。 

最後の罠は、参照の重複です。```
C
P
```答えがあります`False`。 最初の遺伝子変換`a-b-c-...`の中へ`a-a-b-c-...`、2番目は複雑なアミノ酸を作成します`<a,b>`。 葉のセットのみを比較すると、それらが誤って等しいものとして扱われてしまいます。 

## アプローチ

 直接的なアプローチは、シンボリック入力チェーンを生成し、両方の遺伝子を実行して、結果のチェーンを比較することです。 これは正しいです。入力は常に単純なアミノ酸から作成され、有限の記号接頭辞であらゆる可能なケースを表すことができるからです。 問題は、プレフィックスのサイズを選択し、構造を効率的に保存することです。 操作によって新しい複雑なアミノ酸が作成されるたびにツリーをコピーすると、多くのアミノ酸のシーケンスが作成されます。`C`そして`P`操作により、大きな式が繰り返し複製される可能性があります。 

有益な観察は、すべての操作でアミノ酸への参照のみが変更されるということです。 複雑なアミノ酸は、2 つの子参照を含むノードとして保存できます。 作成`<a,b>`新しいノードを 1 つだけ作成し、等しいペアはインターンを通じて同じノードを共有できます。 タンパク質全体がノード識別子のスタックになります。 

遺伝子の長さは、必要な初期プレフィックスの制限も与えます。 10000 回の操作で、プログラムは最大 10000 個のトップレベルのアミノ酸を削除できます。 それより少し多い値から開始すると、チェーンの長さを 3 以下に減らすことによって引き起こされる特別な失敗ルールがシミュレーション中に表示されないことを意味します。 残りの唯一の失敗は、適用によって引き起こされます。`L`、`R`、 または`U`スタック表現によって検出される単純なアミノ酸に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(L * 展開されたツリーのサイズ) | O(展開されたツリーのサイズ) | 遅すぎる |
 | 最適 | O(L) | O(L) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 十分に長い記号チェーン内の最初の単純なアミノ酸ごとに一意のノードを作成します。 すべての未処理の接尾辞要素は同一のままであるため、チェーンは遺伝子が実行できる削除の最大数よりも長くする必要があるだけです。 
2. 現在のタンパク質をノード識別子のスタックとして保存しながら、遺伝子を左から右に処理します。 スタックの一番上は、鎖の最初のアミノ酸を表します。 
3. のために`C`、最上位のスタック要素を複製します。 のために`D`、削除します。 のために`S`、上の 2 つの要素を交換します。 これらの操作は参照を再配置するだけなので、一定の時間がかかります。 
4. のために`P`、最初の 2 つのスタック要素を複雑な組み合わせで置き換えます。 子識別子のペアはテーブル内で検索されるため、同じ複合アミノ酸は常に同じ識別子を受け取ります。 
5. のために`L`、`R`、 そして`U`、最上位ノードが複雑かどうかを検査します。 それが単純であれば、遺伝子は失敗します。 それ以外の場合は、最上位要素を必要な子に置き換えます。 
6. 同じ初期記号チェーンを使用して、両方の遺伝子に対して同じシミュレーションを実行します。 一方のシミュレーションが失敗し、もう一方のシミュレーションが成功した場合、遺伝子は異なります。 両方が失敗した場合、それらは同等になります。 
7. 両方が成功した場合は、最終的なスタックを要素ごとに比較します。 すべての複雑なノードがインターンされるため、等しい識別子は等しいアミノ酸構造を意味します。 

機能する理由: 遺伝子内のすべての操作は、実際のタンパク質鎖に与える影響とまったく同じ影響をスタック表現に及ぼします。 唯一の違いは、変更されていない無限の接尾辞が、記号的な単純なアミノ酸の有限のコレクションによって表されることです。 遺伝子は境界のあるプレフィックスにのみアクセスできるため、この有限表現には遺伝子が観察できるすべてが含まれます。 インターンでは構造的同等性が維持されるため、最終的な比較は遺伝子同等性の定義と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

pairs = {}
left = []
right = []
simple_count = 25050

nodes = [None]

for i in range(simple_count):
    nodes.append((0, i))

def get_complex(a, b):
    key = (a, b)
    if key not in pairs:
        pairs[key] = len(nodes)
        nodes.append((1, a, b))
    return pairs[key]

def run_gene(gene):
    stack = list(range(simple_count, 0, -1))

    for ch in gene:
        if ch == 'C':
            stack.append(stack[-1])
        elif ch == 'D':
            stack.pop()
        elif ch == 'S':
            stack[-1], stack[-2] = stack[-2], stack[-1]
        elif ch == 'P':
            a = stack.pop()
            b = stack.pop()
            stack.append(get_complex(a, b))
        elif ch == 'L':
            a = stack[-1]
            if nodes[a][0] == 0:
                return None
            stack[-1] = nodes[a][1]
        elif ch == 'R':
            a = stack[-1]
            if nodes[a][0] == 0:
                return None
            stack[-1] = nodes[a][2]
        elif ch == 'U':
            a = stack.pop()
            if nodes[a][0] == 0:
                return None
            stack.append(nodes[a][2])
            stack.append(nodes[a][1])

    return stack

def solve():
    a = input().strip()
    b = input().strip()

    x = run_gene(a)
    y = run_gene(b)

    if x is None or y is None:
        print("True" if x is None and y is None else "False")
    else:
        print("True" if x == y else "False")

solve()
```ノード配列には、アミノ酸の完全な記号表現が格納されます。 単純なアミノ酸は、ノード タイプと一意のインデックスによって表されます。 複雑なアミノ酸は、その 2 つの子への参照を保存します。 

の`get_complex`関数は重要な実装の詳細です。 インターンなしでは、異なる操作シーケンスを通じて作成された 2 つの同一の複雑なツリーは再帰的比較が必要になります。 インターンは、構造的等価性を整数的等価性に変換します。 

リストの最後が現在の最初のアミノ酸であるため、スタックは逆の順序で初期化されます。 これにより、タンパク質の前面でのすべての操作が、タンパク質の前面での操作になります。`stack[-1]`。 

障害処理は以下に限定されます`L`、`R`、 そして`U`。 シミュレートされた鎖は、どの遺伝子も消費できるよりも長く開始されるため、鎖長の障害状態は発生しません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ベースは 1 回処理され、すべてのスタック操作は定数時間で行われます。 |
 | スペース | O(n) | 最大でも直線的な数のスタック エントリと複雑なノードが作成されます。 |

 ## 特殊なケース

 両方の遺伝子が常に失敗する場合は、最終スタックを比較する前に処理されます。 のために`L`そして`R`、チェーンの最初のシンボルは常に単純なアミノ酸であるため、シミュレーターはすぐに失敗を返します。 比較では、2 つの障害が同等のものとして正しく扱われます。 

等しい構造が異なるパスを通じて作成される場合は、インターニング マップによって処理されます。 複雑なアミノ酸は、それを生み出した歴史によって比較されるものではありません。 これは 2 つの子識別子によってのみ表されるため、2 つの同一の構造は常に同じ識別子を共有します。 

重複によりスタック サイズが増加する場合は、コピーの代わりに参照を使用することで処理されます。 長い一連の`C`操作では同じノードへの参照がさらに作成されるだけなので、メモリ使用量は線形のままです。
