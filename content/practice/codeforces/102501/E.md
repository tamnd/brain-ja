 ## 解決策
 ## 問題の理解

 長方形のバイナリグリッドがあります。 セルは黒または白のいずれかであり、スイッチが押されているセルのセットを選択する必要があります。 1 つのスイッチを押すと、そのセルとその 4 つの直交する隣接セルが切り替わります。 タスクは、押されたスイッチの有効なセットを 1 つ出力するか、そのようなセットが存在しないことを証明することです。 

入力により、各セルの望ましい最終状態が得られます。 出力は同じサイズの別のグリッドです。`P`対応するスイッチが押されていることを意味し、`A`押されていないことを意味します。 

セルの総数は最大でも 100000 です。すべてのセルに対する一般的なガウス消去法には、100000 個の変数を含む行列が必要ですが、これは処理できる量をはるかに超えています。 このソリューションでは、すべてのセルを無関係な変数として扱うのではなく、長方形の構造を利用する必要があります。 重要な観察は、領域が 100000 で区切られた場合、長方形の小さい方の辺が最大約 316 であるため、より小さい寸法の線形システムが実現可能であるということです。 

不注意な解決策が失敗する小さなケースがいくつかあります。 単一行の場合、セルを押すとその行内の隣接するセルにのみ影響するため、より大きなグリッドに使用される垂直方向の推論が引き続き機能する必要があります。 例えば：```
1 2
B W
```どちらかのスイッチが押されると、2 つのセルは常に同時に変化するため、答えは次のようになります。`IMPOSSIBLE`。 

2 番目の罠は、最初または最後の行に隣接する行が少ないことを忘れることです。 例えば：```
2 1
B
B
```上部のスイッチを押すと両方のセルが切り替わるので、上部のセルを押すと必要な結果が得られます。 すべてのセルに 4 つの隣接セルがあると仮定したソリューションでは、間違った方程式が構築されてしまいます。 

## アプローチ

 直接的なアプローチは、すべてのセルを変数として見て、GF(2) 上に線形システムを構築することです。 各変数は、スイッチが押されたかどうかを示します。 各方程式は、最終的なセルを黒にするか白にするかを記述します。 トグルは 2 を法とした加算と同等であるため、これは正しいです。 ただし、行列には​​最大 100,000 個の変数が含まれるため、通常の消去では時間がかかりすぎます。 最悪の場合、15 ビット操作が約 10 回必要になります。 

グリッド構造により、より良いルートが得られます。 1 つの行でどのスイッチが押されるかを決定すると、後続のすべての行を強制的に実行できます。 これは、Lights Out 問題で使用される古典的な追跡テクニックです。 唯一不明な部分が最初の行になります。 グリッドを転置できるため、列の数を常に小さい次元にすることができます。 最初の行には最大 316 個の変数が含まれます。 

残りの問題は、小規模な線形システムです。 最初の行の考えられる各基底ベクトルを使用して追跡を 1 回シミュレートし、最初の行のすべての変数が最後の行にどのように影響するかを学習します。 次に、ガウス消去法により、必要な最初の行のプレスが見つかります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2分(K,L) ) | O(KL) | 遅すぎる |
 | 最適 | O(KL⋅min(K,L)) | O(KL) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 行数が列数より大きい場合、グリッドを転置します。 これにより、最初の行が小さく保たれます。これは、ガウス消去法によって解決される唯一の部分です。 
2. すべての行をビットマスクとして表します。 ターゲット グリッドはバイナリ行列に変換されます。`1`黒という意味です。 
3. 追跡関数を定義します。 プレスの最初の行が与えられると、次のすべての行が決定されます。`i`行を選択して修正する必要があります`i + 1`。 式は次のとおりです。 

x i+1 ＝d i ⊕T(x i )⊕x i−1

 ここで、 T は、左右に隣接する行と一緒に行を切り替えます。 

1. 最初の行を空にしてチェイスを実行します。 最後の行の残りの差は、最終方程式の定数部分になります。 
2. 最初の行の単一ビットごとにチェイスを 1 回実行します。 結果として生じる最終行の差分は、線形システムの列を形成します。 
3. GF(2) に対するガウス消去法を使用して線形システムを解きます。 矛盾が出ると絵は出来ません。 
4. 解決された最初の行を使用して、最後にもう一度チェイスを実行し、プレスを出力します。 グリッドが転置されている場合は、回答を転置して戻します。 

チェイスの背後にある不変条件は、行の処理後のものです。`i`、それより上のすべての行はすでに正しいので、今後変更されることはありません。 考えられるすべてのソリューションには最初の行のプレスが必要であり、チェイスはその最初の行によって決定されたソリューションを正確に生成します。 最終的な線形システムは、どの最初の行が最後の行を正しくするかをチェックするため、見つかった解は常に有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def toggle_row(x, m):
    return x ^ ((x << 1) & ((1 << m) - 1)) ^ (x >> 1)

def chase(first, target, n, m):
    press = [0] * n
    press[0] = first
    for i in range(n - 1):
        cur = target[i] ^ press[i - 1] if i else target[i]
        press[i + 1] = cur ^ toggle_row(press[i], m)
    return press

def solve_system(cols, rhs, n):
    rows = []
    for i in range(n):
        mask = 0
        for j in range(n):
            if (cols[j] >> i) & 1:
                mask |= 1 << j
        if (rhs >> i) & 1:
            mask |= 1 << n
        rows.append(mask)

    pivot = 0
    where = [-1] * n
    for col in range(n):
        found = -1
        for r in range(pivot, n):
            if (rows[r] >> col) & 1:
                found = r
                break
        if found == -1:
            continue
        rows[pivot], rows[found] = rows[found], rows[pivot]
        where[col] = pivot
        for r in range(n):
            if r != pivot and ((rows[r] >> col) & 1):
                rows[r] ^= rows[pivot]
        pivot += 1

    for r in range(n):
        if rows[r] == (1 << n):
            return None

    ans = 0
    for i in range(n):
        if where[i] != -1 and ((rows[where[i]] >> n) & 1):
            ans |= 1 << i
    return ans

def main():
    k, l = map(int, input().split())
    a = [[1 if x == 'B' else 0 for x in input().split()] for _ in range(k)]

    transposed = False
    if k < l:
        a = [list(x) for x in zip(*a)]
        k, l = l, k
        transposed = True

    target = []
    for row in a:
        mask = 0
        for j, x in enumerate(row):
            if x:
                mask |= 1 << j
        target.append(mask)

    base = chase(0, target, k, l)
    rhs = target[-1] ^ (base[-2] if k > 1 else 0) ^ toggle_row(base[-1], l)

    cols = []
    for i in range(l):
        cur = chase(1 << i, target, k, l)
        cols.append(toggle_row(cur[-1], l) ^ (cur[-2] if k > 1 else 0) ^ rhs)

    first = solve_system(cols, rhs, l)
    if first is None:
        print("IMPOSSIBLE")
        return

    ans = chase(first, target, k, l)
    out = [['P' if (ans[i] >> j) & 1 else 'A' for j in range(l)] for i in range(k)]

    if transposed:
        out = [list(x) for x in zip(*out)]

    print('\n'.join(' '.join(row) for row in out))

if __name__ == "__main__":
    main()
```この実装では、すべての行を整数ビット マスクとして保存します。 これにより、水平方向の近傍演算が、セル間で反復されるのではなく、数ビットの演算になります。 チェイス関数は、上で説明したのと同じ不変条件に従います。つまり、行が渡されると、その行は永続的に固定されます。 

ガウス消去法では、整数をビットセットとして使用します。 各行の余分な最上位ビットには右側が格納されるため、行の XOR 演算により GF(2) に対して消去が実行されます。 転置ステップは、最終的なシステムの変数の数を少なく保つため、不可欠です。 

## 実用的な例

 最初のサンプルの場合:

 | ステップ | 最初の行の選択 | 最後の行の要件 | 結果 |
 | --- | --- | --- | --- |
 | イニシャル | 印刷機が選択されていません | 2 つのセルは異なるものでなければなりません | 不可能 |
 | 消去 | 一貫した割り当てが存在しません | 矛盾が見つかりました |`IMPOSSIBLE`|

 この矛盾は、両方のセルが常に一緒に切り替わり、ターゲット状態を分離できないために発生します。 

小さな有効な例としては、次のとおりです。```
2 1
B
B
```| ステップ | 現在の行で | を押します。 次の行は | を押します。 状態 |
 | --- | --- | --- | --- |
 | 開始 |`0`|`1`| 上の行は固定です |
 | 仕上げ |`1`| なし | 両方のセルが黒くなります。 

チェイスは、必要なペアを作成できる唯一のスイッチを正しく選択します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(KL⋅min(K,L)) | 考えられる最初の行ビットごとに 1 つのチェイスが必要であり、チェイスはすべてのセルにタッチします。 
| スペース | O(KL) | グリッドと答えが保存されます |

 グリッドの小さい方の辺は最大 316 であるため、セルの数が 100000 に達しても、乗算係数は小さいままです。

 ## 特殊なケース

 生成された線形システムには有効な最初の行の割り当てがないため、解決できない 2 セルの行が処理されます。 排除フェーズでは、無効なプレス パターンを生成するのではなく、矛盾を検出します。 

同じ繰り返しが引き続き適用されるため、単一行および単一列のグリッドが処理されます。 欠落している近傍は、ビット演算で単にゼロに寄与します。 

移調により、隠れたパフォーマンスの問題が回避されます。 寸法のあるグリッド`1 x 100000`そうしないと、100,000 個の変数を持つ線形システムが作成されてしまいます。 転置後はこうなります`100000 x 1`、システムには変数が 1 つだけあります。
