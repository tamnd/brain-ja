 # 問題の理解

 観察された鳥の動きの有向グラフが与えられます。 実際のフライトの元のグラフは不明ですが、すべての実際のエッジは観測されたグラフに表示される必要がありますが、観測された一部のエッジはより長い実際の経路を表すショートカットである可能性があります。 

固定ツリー T の場合、エッジ a → T が実際のエッジであることが保証されるようなすべてのツリー a を見つける必要があります。 観測されたエッジ a → T は、観測されたグラフ内の a から T までのすべての可能なパスがその正確なエッジを使用する場合にのみ保証されます。 

この制約では、最大 100,000 個のノードと 100,000 個のエッジが許可されます。 入力エッジごとにパスを個別にチェックするソリューションは、簡単に二次関数になり、遅すぎます。 線形または線形に近いトラバーサルでグラフを処理する必要があります。 

主なエッジケースは、代替ルートによって引き起こされます。 T への直接エッジだけでは十分ではありません。 例えば：```
3 3 2
0 1
0 2
1 2
```答えは次のとおりです。```
1
1
```ノード 0 には 2 へのエッジがありますが、パス 0 → 1 → 2 はそのエッジを回避するため、0 は無効です。 

もう 1 つのケースはサイクルです。```
3 3 2
0 2
0 1
1 2
```答えはまだノード 1 だけです。別の発信エッジが最終的に T に到達できるかどうかは、直接エッジでも問題ありません。 

# アプローチ

 直接的なアプローチは、T のすべての先行者 a を調べて、エッジ a → T を削除することです。T が a からまだ到達可能な場合、エッジは保証されません。 定義では代替パスが存在するかどうかを尋ねているため、これは正しいです。 ただし、すべての入力エッジに対してグラフの走査を行うと、最悪の場合でも O(M(N + M)) のコストがかかります。これは 100,000 個の頂点では不可能です。 

重要な観察は、a から T へのすべての代替パスは、a → T とは異なる a を残すエッジで始まる必要があるということです。各エッジを個別にテストする必要はありません。 どの頂点が T に到達できるかを知る必要があるだけです。 

T から開始して 1 つの逆グラフ走査を実行します。元のグラフで T に到達できる頂点はマークされます。 入力エッジ a → T の場合、a に別の出力エッジ a → x (x がマークされ、x が T ではない) がある場合、a から T への別のパスが存在するため、エッジは保証されません。 それ以外の場合、a から T に到達する唯一の方法は、a → T を経由することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(M(N+M)) | O(N+M) | 遅すぎる |
 | 最適 | O(N+M) | O(N+M) | 承認済み |

 # アルゴリズムのチュートリアル

 1. 逆グラフを作成します。 元のエッジ a → b ごとに反転エッジ b → a が追加されます。 このグラフの T からトラバースすると、元のグラフで T に到達できるノードが正確に訪問されます。 
2. 逆グラフで T から DFS または BFS を実行し、到達可能なすべてのノードをマークします。 これらは、T で終わるパスに出現できる唯一のノードです。 
3. 入力の読み取り中にすべてのノードのすべての出力エッジを保存します。これは、後で、候補となる先行ノードに T への別のルートがあるかどうかを検査する必要があるためです。 
4. すべてのエッジ a → T について、a のすべての出力エッジをチェックします。 x が T と異なり、x が T に到達可能とマークされているエッジ a → x が存在する場合、a は a → T を使用せずに T に到達できるため、それを破棄します。 
5. 残りのすべての先行ファイルを並べ替えて印刷します。 

これが機能する理由: エッジ a → T を回避する a から T へのパスは、他の出力エッジ a → x から開始する必要があります。 最初の移動後のパスの残りの部分は、まさに x から T へのパスになります。逆走査では、そのようなサフィックス パスが存在する x 値を正確にマークします。 したがって、アルゴリズムは代替パスを持つエッジを正確に拒否し、保証された実際のエッジを正確に受け入れます。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, t = map(int, input().split())

    graph = [[] for _ in range(n)]
    rev = [[] for _ in range(n)]
    incoming = []

    for _ in range(m):
        a, b = map(int, input().split())
        graph[a].append(b)
        rev[b].append(a)
        if b == t:
            incoming.append(a)

    reachable = [False] * n
    stack = [t]
    reachable[t] = True

    while stack:
        v = stack.pop()
        for u in rev[v]:
            if not reachable[u]:
                reachable[u] = True
                stack.append(u)

    ans = []
    for a in incoming:
        ok = True
        for x in graph[a]:
            if x != t and reachable[x]:
                ok = False
                break
        if ok:
            ans.append(a)

    ans.sort()
    print(len(ans))
    for x in ans:
        print(x)

if __name__ == "__main__":
    solve()
```到達可能性の方向が反転しているため、最初の走査は反転したグラフで機能します。 反転したグラフで T からノード x に到達するということは、もともと x から T へのパスがあったことを意味します。 

最後のループは、T への直接エッジを既に持っている頂点のみをチェックします。すべての答えは T の先行するものである必要があるため、これで十分です。そのような各頂点について、別の出力エッジは、最終的に T に戻る可能性のある頂点につながる場合にのみ危険です。 

Python の再帰の深さは頂点が 100,000 個のグラフには小さすぎるため、再帰は使用されません。 反復スタックはその問題を回避します。

 # エッジケース

 直接入ってくるエッジは依然として無効になる可能性があります。 で：```
3 3 2
0 2
0 1
1 2
```逆走査は、すべてのノードを 2 に到達できるものとしてマークします。ノード 0 をチェックすると、エッジ 0 → 1 が見つかり、ノード 1 がマークされるため、アルゴリズムは 0 を拒否します。 

サイクル内のノードはまだ有効である可能性があります。 2 番目のサンプルでは、​​ノード 4 には 2 へのエッジがありますが、他の出力エッジは存在しないため、4 から 2 へのすべてのパスは 4 → 2 を使用する必要があります。グラフの他の場所にサイクルが含まれている場合でも、アルゴリズムはそれを受け入れます。
