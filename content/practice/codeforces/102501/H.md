 ## 解決策
 ## 問題の理解

 ジェネレーターは固定の 40 ビット値から開始し、それを次の値に繰り返し変換します。 変換では、現在の値、下位 20 ビットを削除した値、および定数を加算し、下位 40 ビットのみを保持します。 タスクは最初に見ることです`N`生成された値を調べて、それらのうち偶数のものの数を数えます。 

入力値`N`ほぼ同じ大きさにすることができます`2^63`したがって、シーケンスを一度に 1 要素ずつシミュレートすることは不可能です。 非常に高速なループであっても、最大の入力には数十億年を必要とします。 要求された要素をすべて生成するのではなく、繰り返し構造を見つけて完全な繰り返しをカウントする必要があります。 

有益な観察は、40 ビット状態全体が必要ないということです。 この質問は、数値が偶数かどうかを決定するビットであるため、最下位ビットについてのみ尋ねます。 次に下位のビットを計算するには、現在の数値の下位 21 ビットのみが必要です。 ビットがシフトアウトしたのは、`>> 20`は正確にビット 20 であり、そのビットはこれらの 21 ビットの中に含まれています。 

不注意な解決策はいくつかの境界で失敗する可能性があります。 たとえば、入力の場合`0`、シーケンスには値が含まれていないため、答えは次のようになります。`0`。 常に初期状態を処理するソリューションでは、誤った出力が発生します。`1`。 

入力用`1`、 のみ`S(0)`カウントされます。 以来`0x600DCAFE`偶数の 16 進数で終わる場合、正解は次のとおりです。`1`。 カウントする前にトランジションを適用するソリューションでは、誤ってカウントしてしまう可能性があります。`S(1)`その代わり。 

非常に大きな入力の場合、次のようになります。`500000000`、生成されたすべての値を直接シミュレートすることは現実的ではありません。 正しい出力は次のとおりです`250065867`これには、生成されたすべての数値を反復するのではなく、縮小された状態のサイクルを使用する必要があります。 

## アプローチ

 ブルートフォースアプローチは定義に直接従います。 現在の 40 ビット値を保存し、そのパリティをチェックし、繰り返しを適用して繰り返します。 これは、問題で要求された値を正確に参照するため、正しいです。 ただし、`N = 2^63 - 1`、約`9.22 * 10^18`限界をはるかに超えたトランジション。 

漸化式の構造により、より小さな状態空間が得られます。 現在の値のパリティはビット 0 に依存します。 シフトされた項は上位部分からのみ寄与するため、次の値のビット 0 は現在の値のビット 0 とビット 20 に依存します。 したがって、下位 21 ビットは自己完結型のシステムを形成します。 

要求されたシーケンスの長さが膨大であるため、総当たり法は失敗します。 下位 21 ビットが独立して進化するという観察により、考えられる状態の数が減少します。`2^40`だけに`2^21`。 この小さなシーケンスを繰り返すまで生成し、1 サイクル内の偶数状態の数を数え、算術演算を使用して完全なサイクルをスキップすることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N) | お(1) | 遅すぎる |
 | 21 ビット状態のサイクル検出 | O(2^21) | O(2^21) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元の 40 ビット状態を下位 21 ビットのみに置き換えます。 現在の縮小状態が`x`、次の縮小された状態は次のように計算されます。`(x + (x >> 20) + 12345) mod 2^21`。 これが機能するのは、次の下位 21 ビットに影響を与える上位 19 ビットの情報はビット 20 だけであるためです。 
2. 以下から始まる縮小状態を生成します。`0x600DCAFE & ((1 << 21) - 1)`。 各状態が現れる最初の位置を保存します。 その時点からシーケンスは周期的になるため、状態が繰り返されるまで続行します。 
3. 生成されたシーケンスを非反復プレフィックスと反復サイクルに分割します。 両方の部分内の偶数の状態を数えます。 
4. もし`N`プレフィックス長より小さい場合は、プレフィックスから直接応答します。 それ以外の場合は、プレフィックスの寄与を追加し、整数除算を使用してできるだけ多くの完全なサイクルをスキップし、残りのサイクル要素を処理します。 

これが機能する理由: 縮小状態には、将来の縮小状態と生成されたすべての数値のパリティを決定するために必要な情報が正確に含まれています。 縮小状態が 2 回目に出現すると、後続のすべての縮小状態が同じ順序で繰り返されます。 アルゴリズムはプレフィックスを 1 回カウントし、すべての完全な繰り返しを数学的に考慮します。`N`値は 1 回だけ貢献します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MASK = (1 << 21) - 1
START = 0x600DCAFE & MASK
C = 12345

def build_cycle():
    seen = {}
    order = []
    x = START

    while x not in seen:
        seen[x] = len(order)
        order.append(x)
        x = (x + (x >> 20) + C) & MASK

    cycle_start = seen[x]
    return order, cycle_start

order, cycle_start = build_cycle()

prefix_even = [0] * (len(order) + 1)
for i, x in enumerate(order):
    prefix_even[i + 1] = prefix_even[i] + (1 if (x & 1) == 0 else 0)

cycle = order[cycle_start:]
cycle_even = sum(1 for x in cycle if (x & 1) == 0)

def solve(n):
    if n <= cycle_start:
        return prefix_even[n]

    ans = prefix_even[cycle_start]
    n -= cycle_start

    ans += (n // len(cycle)) * cycle_even
    n %= len(cycle)

    for i in range(n):
        if (cycle[i] & 1) == 0:
            ans += 1

    return ans

n = int(input())
print(solve(n))
```定数は縮小ジェネレーターを定義します。`MASK`最下位 21 ビットを正確に保持し、`START`初期 40 ビット値の無関係な上位ビットを破棄します。`build_cycle`唯一の大規模なシミュレーションを実行します。 せいぜい`2^21`さまざまな状態が現れる可能性があるため、ループは制限されています。 辞書には各状態の最初の出現が記録されるため、繰り返されるセグメントをすぐに識別できます。 

プレフィックス配列には偶数状態の累積数が格納されます。 これにより、クエリごとに非循環部分を再スキャンする必要がなくなります。 除算では完全な繰り返しをスキップできるため、サイクル数は個別に保存されます。 

移行では、`& MASK`モジュロ演算の代わりに。 法は 2 の累乗であるため、下位 21 ビットを保持することは正確に等価であり、不必要な作業を回避できます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def brute(n):
    s = 0x600DCAFE
    ans = 0
    for _ in range(n):
        if s % 2 == 0:
            ans += 1
        s = (s + (s >> 20) + 12345) & ((1 << 40) - 1)
    return str(ans)

def run(inp: str) -> str:
    return str(solve(int(inp.strip())))

assert run("0\n") == "0", "minimum size"
assert run("1\n") == brute(1), "single value boundary"
assert run("3\n") == "2", "sample 1"
assert run("10\n") == brute(10), "small manual range"
assert run("100\n") == brute(100), "larger prefix"

 ## 特殊なケース

 入力用`0`、アルゴリズムは最初の分岐に入ります。`N`サイクルプレフィックス長よりも小さいです。 インデックス 0 のプレフィックス配列値が返されます。これは、`0`。 生成された状態はカウントされません。 

入力用`1`、アルゴリズムは戻ります`prefix_even[1]`。 開始時の還元状態は偶数であるため、答えは次のようになります。`1`。 カウントする前に遷移は実行されないため、off-by-one エラーが回避されます。 

非常に大きな入力の場合、アルゴリズムは要求されたすべての値を生成しようとはしません。 サイクルを検出した後、非反復プレフィックスを削除し、残りの長さをサイクル長で割って、1 サイクル内の偶数状態の数を乗算します。 残りのいくつかの状態は個別にチェックされるため、最終的なカウントは最初の状態と正確に一致します。`N`生成された値。
