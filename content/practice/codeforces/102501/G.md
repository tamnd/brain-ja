 ## 解決策
 ## 問題の理解

 動物が待機列に入る順序を表す動物種のシーケンスが与えられます。 種のペアが互換性があるとリストされている場合、隣接する動物は場所を交換することができるため、最終的な出発順序は固定されていません。 課題は、すべての動物が最終的に去ったときに出現する可能性のある辞書編集上の最小の種の順序を見つけることです。 

入力は、種のセット、互いに交差する可能性のある種のペア、および元のシーケンスを記述します。 出力は、同じ動物を含む別のシーケンスですが、辞書の順序に従って可能な限り最も早い出発順序として配置されます。 

重要な問題は、スワップがローカルであることです。 動物は勝手に前に進むことはできません。 別の動物を横切って左に移動するには、その動物の種との交換を許可する必要があります。 この制約により、動物の数は最大でも 200 種しか存在しないことが分かります。 到達可能な注文の数は指数関数的に増加する可能性があるため、これにより、スワップのシミュレーションや可能な順列の探索が除外されます。 アルゴリズムは、種ごとにわずかな追加作業のみを使用して、シーケンスをほぼ線形に処理する必要があります。 

見落としやすいケースがいくつかあります。 ある種に友達がまったくいない場合、その動物は別の種を通過することができません。 例えば：```
2 0 3
A
B
A B A
```答えは次のとおりです。```
A B A
```どこにでも出現する最小の種を常に選択する不注意で貪欲なアプローチでは、次のような結果が得られます。`A A B`、これは不可能です。`A`渡れない`B`。 

もう 1 つの注意が必要なケースは、同じ種が繰り返し発生する場合です。 出力では個々の動物ではなく種名のみが考慮されるため、同種の種を交配する許可は必要ありません。 例えば：```
2 0 3
A
B
A A B
```答えは次のとおりです。```
A A B
```同じ種をブロッキングペアとして扱う解決策は、2 つの種を誤って防止することになります。`A`動物を一緒に考えないでください。 

3 番目のケースは、ある種の後の出現が、同じ種の以前の出現によってブロックされる場合です。 例えば：```
3 1 4
A
B
C
A B C B
A B
```答えは次のとおりです。```
A B C B
```最後`B`前に動けない`C`それでも`B`よりも小さいです`C`、 なぜなら`B`渡らなければなりません`C`、その交換は許可されていません。 

## アプローチ

 直接的なアプローチでは、到達可能なすべてのシーケンスを生成しようとします。 許可された隣接スワップごとに別の可能な状態が作成されるため、状態に対して幅優先検索を実行し、見つかった最小シーケンスを維持できます。 すべての法的スワップが調査されるため、これは正しいです。 ただし、動物の数が少ない場合でも、考えられる状態の数はほぼ同じになる可能性があります。`N!`、完全に不可能になります`N = 100000`。 

有益な観察は、実際にはスワップをシミュレートする必要がないということです。 代わりに、どの動物が他の動物よりも先に留まることを余儀なくされるかを説明することができます。 

所定の位置に 1 匹の動物を考える`i`。 以前の種の動物がいる場合`X`それはその種の友達ではありません`i`、次に動物`i`前の動物の前には決して動けない。 これにより、優先順位の制約が作成されます。つまり、前の動物は現在の動物より前に出発しなければなりません。 

重要な詳細は、各ブロック種の最新の発生のみが必要であるということです。 同じ種の以前の出現が存在する場合、最新のものは、通過する必要がある最も近い障害物になります。 その最新の出現種を交配することができれば、同じ種の以前のすべての出現種も交配することができます。 

これらの優先順位制約により、有向非巡回グラフが形成されます。 それぞれの動物はノードであり、エッジです。`a`に`b`動物を意味します`a`動物より先に出発しなければならない`b`。 有効な離脱順序はすべて、このグラフのトポロジカル順序付けです。 

すべてのトポロジー的順序付けの中で、辞書編集的に最小のものは、利用可能な最小のノードを繰り返し選択することによって見つけることができます。 これは、トポロジカル ソートの標準プライオリティ キュー バージョンです。 

ブルート フォースはすべての法的命令を調査するため機能しますが、命令が多すぎるため失敗します。 交換不可能な以前の種のみが制限を作成するという観察により、問題を DAG に圧縮して貪欲に解決できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(N * S + N log N) | O(N + S²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 種を読み取り、すべての種に整数 ID を割り当てます。 どの種のペアが交換できるかを保存します。 
2. 入力シーケンスを左から右にスキャンし、動物間の依存関係グラフを作成します。 現在の種の動物の場合`x`、すべての種を検査します`y`以前にも登場したもの。 もし`y`と交換することはできません`x`、最新のエッジを追加します。`y`現在の動物に起こったこと。 

エッジは、現在の動物がそこを通過できないため、前の動物が最初に出発しなければならないことを意味します。 
3. スキャン中にすべての種の最新の位置を維持します。 発生を処理した後、その種の最新の位置を更新します。 
4. 依存関係グラフ内のすべてのノードの次数を計算します。 次数 0 を持つすべてのノードは、合法的に次に離れる動物になることができます。 
5. 現在利用可能なすべての動物を種名順の最小ヒープに置きます。 最小の種を繰り返し削除し、それを答えに追加し、その出力近傍の次数を減らします。 
6. すべての動物が除去されるまで続けます。 生成された順序は必須の出発シーケンスです。 

なぜ効果があるのか:

 このグラフには、動物が互いにすれ違うことのできない制限がまさに含まれています。 ある動物から別の動物へのエッジがある場合、すべての有効なシーケンスはその順序を維持する必要があります。 依存関係のエッジがない場合、前の動物は後の動物が先頭に到達するのを妨げません。 したがって、すべての有効な離脱順序は、このグラフの位相順序に対応します。 

カーンのアルゴリズムの各ステップで、利用可能なノードはまさに、制限に違反することなく最前面に移動できる動物です。 有効な順序では、利用できない動物がその動物の前に現れることはないため、利用可能な最小の種を選択するのが常に安全です。 この選択を繰り返すと、すべての位置で可能な限り最小のプレフィックスが得られるため、シーケンス全体が辞書編集的に最小限になります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    S, L, N = map(int, input().split())

    names = [input().strip() for _ in range(S)]
    ids = {name: i for i, name in enumerate(names)}

    friend = [[False] * S for _ in range(S)]
    for _ in range(L):
        a, b = input().split()
        x, y = ids[a], ids[b]
        friend[x][y] = True
        friend[y][x] = True

    seq = [ids[x] for x in input().split()]

    graph = [[] for _ in range(N)]
    indeg = [0] * N

    last = [-1] * S

    for i, x in enumerate(seq):
        for y in range(S):
            if last[y] != -1 and y != x and not friend[x][y]:
                graph[last[y]].append(i)
                indeg[i] += 1
        last[x] = i

    heap = []
    for i in range(N):
        if indeg[i] == 0:
            heapq.heappush(heap, (names[seq[i]], i))

    ans = []

    while heap:
        _, u = heapq.heappop(heap)
        ans.append(names[seq[u]])

        for v in graph[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                heapq.heappush(heap, (names[seq[v]], v))

    print(" ".join(ans))

if __name__ == "__main__":
    solve()
```最初の部分では、種名を整数の識別子にマップします。 整数 ID を使用すると、フレンド行列とその後の比較が定数時間になります。 

グラフの構築がソリューションの中核です。 シーケンスをスキャンしながら、`last[y]`種の最新の発生を保存します`y`。 現在の動物が交換できない前の種を見た場合、その最新の出現が最も近い避けられないブロッカーとなるため、その出現から現在の動物にエッジが追加されます。 

トポロジカルソートフェーズでは、通常のキューの代わりにヒープを使用します。 通常のトポロジカルな並べ替えでは有効な順序が生成されますが、この問題では最小のアルファベット順が求められます。 ヒープは常に、利用可能な最小の種を削除します。 

ノードは動物を元のゼロベースの位置で表すため、1 によるずれの問題はありません。 Indegrees は依存関係が削除された場合にのみ更新され、ノードはその前にある動物がすべて出力された時点でヒープに入ります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

| スペース | O(N + S²) | グラフは最悪の場合、最大 O(N*S) 個の依存関係を保存し、種グラフは O(S²) 個のメモリを使用します。

 ## 特殊なケース

 友人関係がない場合:```
2 0 3
A
B
A B A
```アルゴリズムは最初からエッジを作成します`A`に`B`、 なぜなら`B`渡れない`A`。 2番目`A`にも依存します`B`もし`B`その前に現れます。 ヒープが 2 番目のデータを誤って公開することはありません`A`ブロックする前に`B`、唯一の有効な答えが得られます。 

同一種が繰り返される場合:```
2 0 3
A
B
A A B
```二人`A`動物は互いに依存関係を作りません。 スワップをチェックする場合、異なる種のみが問題になります。 グラフには最初からエッジがありません`A`2番目に`A`、したがって、両方とも以前に利用可能です`B`、正しい結果が得られます`A A B`。 

以前のオカレンスによってブロックされた後のオカレンスの場合:```
3 1 4
A
B
C
A B
A B C B
```最終処理時`B`、最新の`C`発生が阻害要因となるのは、`B`そして`C`友達ではありません。 グラフは追加します`C -> B`で、最終回`B`先にジャンプできない`C`。 トポロジカルな順序付けではこの制限が尊重され、到達可能な最小のシーケンスが返されます。
