 ## 解決策
 ## 問題の理解

 グリッドは湿地を表します。`*`細胞は川を形成します。 つながったグループ`*`セルは 1 つの河川エリアです。 カメラは次の場所にのみ設置できます`.`これらの河川エリアのいずれかに接するセル、および同じ河川エリアに接する 2 台のカメラを隣接させることはできません。 

ゲームはグリッド全体が一度に行われるわけではありません。 異なる河川エリア間の分離条件は、ある河川エリアの近くでの移動が別の河川エリアの近くでの移動に影響を与えることは決してないことを意味します。 これにより、ボードがいくつかの独立したゲームに変わり、その結果を組み合わせることができます。 

の値`N`は最大 10 なので、ボード全体のセルは 100 個のみです。 セルのサブセットの数が膨大であるため、ボード全体のあらゆる可能なゲーム状態をシミュレートするアプローチは除外されます。 グリッド サイズが小さいため、単一の河川エリアで指数関数的なアルゴリズムを使用できます。`2N`、または20個の湿ったセル。 重要なのは、ボード全体で指数関数的な作業を避けることです。 

よくある間違いは、可能なカメラ位置の数を数えて、それが奇数か偶数かだけを確認することです。 動きの順序が重要であるため、これは失敗します。 例えば：```
...
...
***
```川に接している可能性のあるカメラ セルは 3 つあります。 答えは`First player will win`中央のセルを選択すると、残りの両方のセルが使用されなくなるためです。 手数をカウントすると、常に 3 つの手が利用可能であると誤って予測されてしまいます。 

もう 1 つの間違いは、異なる河川エリアを 1 つのゲームに統合することです。 例えば：```
*...*
.....
*...*
```2 つの川は分離されており、カメラの選択は相互作用しません。 それらを 1 つのグラフとして扱うと、無関係なカメラ間に不正な制限が生じます。 

## アプローチ

 直接的なアプローチでは、河川エリアごとに可能なカメラ位置のグラフを作成し、可能なすべての動きを再帰的に試行します。 移動すると、選択したカメラ セルと隣接するすべてのカメラ セルが削除されます。これらのセルは使用できなくなるためです。 これはまさにグラフ上のノード・ケイルズ・ゲームです。 

将来のあらゆる可能なプレイが検討されるため、強引な攻撃は正しいです。 ただし、次のグラフ`k`候補となるカメラ セルには最大で次のものを含めることができます。`2^k`州。 これをグリッド全体に適用することは不可能です。 

有益な観察は、すべての河川エリアが独立しているということです。 Sprague-Grundy 理論では、それぞれの独立したゲームに番号を割り当てることができます。 すべての河川面積値の xor によって勝者が決まります。 残りの問題は、1 つの小さなグラフのグランディ値を計算することです。 

再帰中に、グラフの切断された部分を個別に解決できます。 1 つの接続されたコンポーネントの移動が別のコンポーネントに影響を与えない場合、Grundy 値は XOR 演算されます。 これにより、調査する必要がある状態の数が大幅に減少します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ボード全体のブルートフォース | O(2^(N²)) | O(2^(N²)) | 遅すぎる |
 | 河川面積ごとのグランディ再帰 | 1 つの領域のカメラ セルの数は指数関数的に変化します。 O(状態の数) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. フラッドフィルを使用して、接続されているすべての河川エリアを検索します。 入力により、異なる領域が相互に影響を与えないことが保証されるため、各領域は独立して処理されます。 
2. 河川エリアごとに、`.`少なくとも 1 つのウェットセルに隣接するセル。 これらのセルはゲーム グラフの頂点です。 対応するセルがグリッド内で隣接している場合、2 つの頂点にはエッジがあります。 
3. このグラフのグランディ数を再帰的に計算します。 状態は、残りのカメラ位置のセットによって表されます。 
4. ある状態で移動を試みる前に、残りのグラフを連結コンポーネントに分割します。 状態全体のグランディ値は、それらのコンポーネントの値の xor です。 
5. 接続状態については、残りのすべてのカメラ位置を試します。 カメラを配置すると、その位置とその近隣すべてが削除されます。 すべての移動後に到達可能なグランディ値を収集し、メックスを取得します。 
6. すべての河川エリアのグランディ値の XOR。 XOR がゼロの場合は 2 番目のプレーヤーが勝つことを意味し、それ以外の場合は最初のプレーヤーが勝ちます。 

機能する理由: すべての河川エリアは公平なゲームであり、どの移動も他のエリアに影響を与えることができないため、異なるエリアではばらばらの合計が形成されます。 Sprague-Grundy 理論では、互いに素な合計の値はコンポーネント値の xor であると述べています。 グランディ値の再帰的定義ではあらゆる正当な手が考慮されるため、mex の計算は将来起こり得るすべてのプレイを正確に表します。 

## Python ソリューション```python
import sys
from functools import lru_cache

input = sys.stdin.readline

def solve():
    n = int(input())
    grid = [input().strip() for _ in range(n)]

    wet_seen = [[False] * n for _ in range(n)]
    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    def inside(r, c):
        return 0 <= r < n and 0 <= c < n

    def get_grundy(adj):
        m = len(adj)
        full = (1 << m) - 1

        @lru_cache(None)
        def grundy(mask):
            if mask == 0:
                return 0

            parts = []
            seen = 0
            for i in range(m):
                if (mask >> i) & 1 and not ((seen >> i) & 1):
                    stack = [i]
                    seen |= 1 << i
                    comp = 0
                    while stack:
                        v = stack.pop()
                        comp |= 1 << v
                        nxt = adj[v] & mask & ~seen
                        while nxt:
                            b = nxt & -nxt
                            u = b.bit_length() - 1
                            seen |= b
                            stack.append(u)
                            nxt -= b
                    parts.append(comp)

            if len(parts) > 1:
                ans = 0
                for p in parts:
                    ans ^= grundy(p)
                return ans

            values = set()
            x = mask
            while x:
                b = x & -x
                v = b.bit_length() - 1
                values.add(grundy(mask & ~adj[v] & ~b))
                x -= b

            g = 0
            while g in values:
                g += 1
            return g

        return grundy(full)

    answer = 0

    for r in range(n):
        for c in range(n):
            if grid[r][c] == '*' and not wet_seen[r][c]:
                area = []
                stack = [(r, c)]
                wet_seen[r][c] = True

                while stack:
                    x, y = stack.pop()
                    area.append((x, y))
                    for dx, dy in dirs:
                        nx, ny = x + dx, y + dy
                        if inside(nx, ny) and not wet_seen[nx][ny] and grid[nx][ny] == '*':
                            wet_seen[nx][ny] = True
                            stack.append((nx, ny))

                candidates = set()
                for x, y in area:
                    for dx, dy in dirs:
                        nx, ny = x + dx, y + dy
                        if inside(nx, ny) and grid[nx][ny] == '.':
                            candidates.add((nx, ny))

                nodes = list(candidates)
                index = {p: i for i, p in enumerate(nodes)}
                adj = [0] * len(nodes)

                for x, y in nodes:
                    i = index[(x, y)]
                    for dx, dy in dirs:
                        nx, ny = x + dx, y + dy
                        if (nx, ny) in index:
                            adj[i] |= 1 << index[(nx, ny)]

                answer ^= get_grundy(adj)

    if answer:
        print("First player will win")
    else:
        print("Second player will win")

if __name__ == "__main__":
    solve()
```フラッド フィル フェーズは、独立したサブゲームを正確に識別します。 候補セットには、現在の川に接する強固な地面のセルのみが含まれるため、保護されたセルや無関係な地面がグラフに入力されることはありません。 

再帰関数は状態をビットマスクとして保存します。 ビットがセットされているということは、カメラ位置がまだ利用可能であることを意味します。 カメラが配置されると、選択したビットと隣接するすべてのビットが削除されます。 

連結コンポーネントの分割が主な最適化です。 これがなければ、多くの状態が 1 つの大きなグラフとして再計算されます。 これにより、独立した部分が、値の XOR が可能な小さなゲームに縮小されます。 

Python の整数は任意の長さのビットマスクを保持できるため、実装では頂点の数に対する特別な処理は必要ありません。 カメラ候補はボードの内側からのみ来ることができるため、グリッド境界チェックも重要です。

 ## 特殊なケース

 隣接する強固な地盤のない川では、空のグラフが作成されます。 最初のプレイヤーには移動がないため、グランディ値はゼロです。 再帰はすぐに空のマスクに到達し、ゼロを返します。 

境界付近の単一の行または列は、グリッドの外側のセルにアクセスしてはなりません。 の`inside`チェックにより、無効な近傍がカメラ位置になるのを防ぎます。 

複数の河川区域は分離しておかなければなりません。 このアルゴリズムは、洪水で満たされた同じ川の周りのカメラ位置間にエッジを構築するだけで、結果として得られる Grundy 値を xor と組み合わせます。 ある河川エリアから別の河川エリアに移動できないため、これは実際のゲームと一致します。
