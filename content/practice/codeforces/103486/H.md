 ## 解決策
 ## 問題の理解

 各エッジに 1 から 9 までの数字が含まれる無向グラフが与えられます。このグラフとともに、一連の頂点によって記述される固定ウォークが与えられます。$A_1, A_2, \dots, A_K$。 旅行者の出発点は、$A_1$そしてそこから一歩ずつ進もうとする$A_i$に$A_{i+1}$。 

この計画されたルートの 2 つの連続する頂点の間には、複数の平行なエッジが存在する可能性があります。 あれば$d$間のエッジ$A_i$そして$A_{i+1}$、旅行者は一様にランダムに 1 つを選択します。 選択された各エッジは、左から右に書かれる増加する数字にその桁を与えます。 全て完了したら$K-1$動く、$K-1$桁数が形成されます。 

タスクは、この結果の数値の期待値を計算することです。 各ステップは右側に追加される数字に寄与するため、その数字を基数 10 の数値を形成すると解釈すると、最終値はエッジの選択に応じたランダム変数になります。 

いずれかのステップで間にエッジがない場合は、$A_i$そして$A_{i+1}$、パスが無効であるため、失敗メッセージを出力する必要があります。 

答えは有理数であることが保証されています。 次のように出力する必要があります$A \cdot B^{-1} \bmod 998244853$、 どこ$A/B$期待値の縮小された部分です。 

制約は以下に達します$3 \cdot 10^5$頂点、エッジ、パスの長さ。 これにより、パスを列挙したり、ランダム性を明示的にシミュレートしたりするアプローチは即座に除外されます。 平$O(K \cdot M)$スタイルスキャンは不可能です。 各ステップを定数時間または対数時間に近い値に減らす必要があり、完全なソリューションは入力のサイズが線形である必要があります。 

複数のエッジが存在するにもかかわらず、単純なソリューションが一意性を前提としている場合、微妙な失敗のケースが発生します。 

たとえば、1 と 2 の間に 1 と 9 の数字を持つ 2 つのエッジがある場合、多重度を無視する不注意な実装では、その数字が固定されたものとして扱われ、分布ではなく決定的な答えが生成されます。 もう 1 つの失敗は、平行エッジの数で除算するときに逆剰余を忘れてしまい、不正確な有理演算につながることです。 

## アプローチ

 重要な観察は、最終的な数値が桁ごとに構築され、期待値が線形結合に分布することです。 最終的な数値を次のように表します。$$X = d_1 \cdot 10^{K-2} + d_2 \cdot 10^{K-3} + \dots + d_{K-1}$$それぞれ$d_i$間のエッジのセットとは独立して選択されます。$A_i$そして$A_{i+1}$、一様にランダム。 

したがって、期待値は次のようになります。$$E[X] = \sum_{i=1}^{K-1} E[d_i] \cdot 10^{K-1-i}$$これにより、連続する各ペアの計算の問題が軽減されます。$(A_i, A_{i+1})$、それらを接続するすべてのエッジの平均桁。 

ブルートフォース手法では、ステップごとにすべてのデータがスキャンされます。$M$エッジを使用して現在のペアを接続するエッジを見つけ、その平均を計算します。 それは与える$O(KM)$、これは大きすぎます$3 \cdot 10^5$。 

重要な洞察は、接続された頂点の順序のないペアごとに情報を事前に集約することです。 パスからペアのみをクエリするため、キーをキーとしたハッシュ マップを前処理できます。$(u,v)$エッジの数と桁の合計を保存します。 その後、各ステップで期待される桁を計算できます。$O(1)$ペアが存在することを確認するだけで済みます。 

また、位置の重み付けには 10 の累乗が必要で、エッジ数で除算するには逆モジュラーも必要です。 

これにより、問題はパス上の単純な線形スキャンに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(KM)$|$O(1)$| 遅すぎる |
 | 最適 |$O(M + K)$|$O(M)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのエッジを読み取り、順序のない頂点ペアごとにグループ化します。$(u, v)$、桁の合計とエッジの数の両方を保存します。 これにより、パス内の任意のステップの分布を一定時間で取得できるようになります。 
2. 10 モジュロの累乗を事前計算する$998244853$長さまで$K-1$。 これが必要なのは、各桁が最終的な数値内の位置に基づいて寄与するためです。 
3. 最大の整数のモジュラー逆元を事前計算します。$M$または、高速累乗を使用してオンデマンドで逆数を計算します。 これは、予想される桁値を計算するときに、平行エッジの数で除算するために必要です。 
4. パスのペアを反復処理します。$(A_i, A_{i+1})$。 マップ内にペアが存在しない場合は、パスをたどることができないため、ただちに失敗を出力します。 
5. 有効なペアごとに、期待される数字を次のように計算します。$\text{sumDigits} \cdot (\text{count}^{-1}) \bmod MOD$。 これにより、そのステップで期待される寄与が得られます。 
6. この予想される数字に適切な 10 の累乗を乗算し、最終的な答えのモジュロに累積します。$MOD$。 

### なぜ効果があるのか

 At each step, the digit is an independent random variable determined only by the chosen edge between the fixed pair of vertices. Independence is not needed across different steps for linearity of expectation; we only require that the contribution of each step is a fixed random variable whose expectation is well-defined. Since the final number is a linear combination of these digits with deterministic weights, expectation distributes cleanly across positions. Precomputing pair statistics ensures we exactly capture the uniform distribution over parallel edges.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244853

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, m, k = map(int, input().split())

    edges = {}

    for _ in range(m):
        u, v, w = map(int, input().split())
        if u > v:
            u, v = v, u
        if (u, v) not in edges:
            edges[(u, v)] = [0, 0]
        edges[(u, v)][0] += w
        edges[(u, v)][1] += 1

    path = list(map(int, input().split()))
    if len(path) != k:
        print("Stupid Msacywy!")
        return

    pow10 = [1] * k
    for i in range(1, k):
        pow10[i] = pow10[i - 1] * 10 % MOD

    ans = 0

    for i in range(k - 1):
        u, v = path[i], path[i + 1]
        if u > v:
            u, v = v, u
        if (u, v) not in edges:
            print("Stupid Msacywy!")
            return

        s, c = edges[(u, v)]
        val = s * modinv(c) % MOD
        ans = (ans + val * pow10[k - 2 - i]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、すべての平行エッジが、ソートされたエンドポイントをキーとする単一の辞書エントリに圧縮されます。 各エントリには桁の合計とエッジの数の両方が保存され、予期される桁値を直接計算できます。 

各ステップの桁が固定の位置の重みに寄与するため、10 のべき乗を事前に計算します。 インデックスマッピング`k - 2 - i`最初の遷移で最上位の桁が生成されることを反映しています。 

モジュラ反転は、モジュロ演算の下で合計をエッジの数で除算するために使用されます。 

必要なエッジ ペアが欠落している場合、障害状態は直ちに処理され、問題の要件に一致して計算が中止されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 |$O(M + K)$| 各エッジは 1 回処理され、各パス ステップも 1 回処理されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、2 つのノード間に複数の平行エッジが存在する場合です。 アルゴリズムは、合計とカウントの両方を集計することによってこれを処理します。 エッジ 1、2、9 を持つ 1-2 のような入力の場合、予期される桁は 12/3 になります。 コードは 3 の逆モジュラーを使用してこれを正しく削減します。 

もう 1 つのケースは、同じペアを異なる方向に繰り返したどることです。 エッジは無向であり、ソートされたエンドポイントとともに保存されるため、(u,v) と (v,u) は同じバケットにマップされ、方向に関係なく一貫した確率が保証されます。 

最後のエッジケースは即時失敗です。 パス内のペアがグラフに欠落している場合、アルゴリズムは部分的な計算を試行せずに停止します。 これにより、未定義の逆モジュラーや不正な累積が防止されます。
