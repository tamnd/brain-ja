 ## 問題の理解

 整数のコレクションから始まるターンベースのゲームが与えられます。最初は 2 から 2 までの数字です。$N+1$。 2 人のプレイヤーが交互にターンします。 ターンでは、プレイヤーは現在の数字の空でないサブセットを削除しますが、これは選択したサブセット内のすべての数字が 1 より大きい公約数を共有する場合に限られます。選択したサブセットを削除した後、残りの数字は破棄され、再び 2 から始まる新しい連続シーケンスとして再作成されます。新しい長さは、古い長さから削除された数字を引いたものと等しくなります。 

重要な結果は、移動するたびに、数字の実際の正体がリセットされるということです。 ゲーム全体で維持される唯一のことは、元の数字ではなく、残っている数字の数です。 ただし、移動の正当性はラベルを変更する前の現在の値に依存するため、連続した範囲からどのようなサブセットが可能であるかを理解する必要があります。 

タスクは、それぞれの初期値について、$N$、最初のプレイヤーが最適なプレイの下で強制的に勝利するかどうか。 

制約により許可されるのは、$N$まで$5 \cdot 10^5$最大 100 のテスト ケース。 これにより、サブセットをシミュレートしたり、動きを明示的に列挙したりするソリューションは即座に除外されます。 単一の状態にはすでに指数関数的な分岐があるため、状態のすべてのサブセットを反復処理することさえ不可能です。 テスト ケースごとの 2 次 DP も遅すぎます。 ソリューションは、テスト ケースごとに線形に近いか、より適切に償却される必要があります。 

微妙なエッジケースは、ゲームがすぐに終了する小さな値から発生します。 たとえば、次の場合$N=1$、数字は 2 のみで、最初のプレイヤーがそれを削除でき、即座に勝ちます。 これらの縮退状態を処理せずに大きな構造を仮定する推論は、ここでは失敗します。 

もう 1 つの重要な微妙な点は、各移動の後に数字のラベルが付け直されるにもかかわらず、合法性の条件が依然として連続した区間内の割り算構造に依存することです。 単純なアプローチでは、移動構造が保持される理由を正当化せずに、サイズのみが重要であると誤って仮定する可能性があります。 

## アプローチ

 直接的なブルート フォース解釈では、各状態を現在の数値のマルチセットとして扱い、すべての有効なサブセットを試行します。 サブセットは、その gcd が 1 より大きい場合に有効です。これは、選択されたすべての数値が何らかの素数を共有することを意味します。 セットサイズから$m$、これは、すべての整数のすべての倍数のすべてのサブセットを列挙することを意味します。$d \ge 2$。 gcd のチェックが効率的であっても、サブセットの数は指数関数的に増加します。$m$、このアプローチは非常に小さいものを超えると直ちに実行不可能になります$N$。 

重要な単純化は、すべての移動の後、残りの数値が常に 2 から始まる連続した間隔にリセットされることを観察することによって得られます。これにより、残りの要素の数を除くすべての構造履歴が破壊されます。 したがって、ゲームの状態は単一の整数で完全に記述されます。$m$、現在の要素数。 

ある状態から$m$要素では、現在の連続した範囲のサブセットを選択しています。 有効な手を実行するには、選択されたすべての数字が公約数を共有する必要があります。 約数を固定すると$d$、安全に選択できる唯一の数値は次の倍数です。$d$、そのような数値はすべて、少なくとも gcd を自動的に持ちます。$d$。 したがって、同じで割り切れる数値のサブセットは、$d$有効です。 

このような数値の最大のプールは、$d=2$、範囲内のすべての偶数が得られます。 がある$\lfloor (m+1)/2 \rfloor$偶数で$\{2, 3, \dots, m+1\}$、そしてそれらから空ではないサブセットを選択できます。 これは、任意の数の要素を削除できることを意味します$k$どこ$1 \le k \le \lfloor (m+1)/2 \rfloor$。 

したがって、ゲームは減算ゲームになります。$m$、プレイヤーは任意の場所に移動できます。$m-k$どこ$k$1との間です$\lfloor (m+1)/2 \rfloor$。 問題は、最大ステップ サイズが次のものに依存することです。$m$, したがって、固定の周期パターンをすぐに使用することはできません。 代わりに、勝利状態を動的に計算します。

 ## アルゴリズムのチュートリアル

 私たちは定義します$dp[m]$がある場合に現在のプレイヤーが勝つかどうか$m$残りの数。 

1.初期化する$dp[0] = \text{false}$数字が残っていない場合、現在のプレイヤーは移動できず、すぐに負けます。 これは、勝ち位置を上方に伝播する基本状態として機能します。 
2. それぞれについて$m \ge 1$、1 回の移動で削除できる要素の最大数を計算します。$k_{\max} = \lfloor (m+1)/2 \rfloor$。 これは、現在の範囲内の 2 の倍数をすべて選択することによって得られます。 
3.州から$m$、プレイヤーは任意の状態に移動できます$m-k$どこ$1 \le k \le k_{\max}$。 これにより、到達可能な状態の連続した間隔が形成されます。$L = m - k_{\max}$まで$R = m - 1$。 
4. 私たちが決める$dp[m]$間隔内に少なくとも 1 つの状態があるかどうかを確認することによって$[L, R]$次のプレイヤーが負けている、つまり$dp[x] = 0$一部の人にとっては$x$その範囲内で。 そのような状態が存在する場合、そこに移動することで強制的に勝利を得ることができます。 
5.これを効率的に維持するために、すべての指数を追跡します$x$そのような$dp[x] = 0$構造の中で。 加工前$m$、保存された損失ポジションが以下の場合は破棄されます。$L$、到達できなくなったため。 
6. 剪定後、構造内に損失箇所が残っている場合は、$dp[m] = 1$。 さもないと、$dp[m] = 0$。 
7. 追記します$m$次の場合にのみ構造に$dp[m] = 0$、そのため、将来の州の損失目標として機能する可能性があります。 

### なぜ効果があるのか

 正しさは、からのすべての動きに依存します。$m$前の状態のスライディング間隔内に正確に着地し、その間隔内に少なくとも 1 つの負けている状態が存在することが、勝利の動きにとって必要かつ十分であると考えられます。 すべての負けている状態は追跡され、到達できなくなると継続的に削除されるため、構造は常に現在関連する反例を正確に表します。 これにより、すべてのことが保証されます$dp[m]$は、到達可能な結果の完全かつ正しいセットから計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    max_n = 0
    ns = []
    for _ in range(T):
        n = int(input())
        ns.append(n)
        max_n = max(max_n, n)

    dp = [0] * (max_n + 1)
    dp[0] = 0

    # store indices i where dp[i] == 0
    zeros = [0]
    head = 0  # pointer into zeros list

    # we maintain zeros as a simple queue, but we also need to discard out of range
    for m in range(1, max_n + 1):
        kmax = (m + 1) // 2
        L = m - kmax
        R = m - 1

        # remove outdated zeros (< L)
        while head < len(zeros) and zeros[head] < L:
            head += 1

        if head < len(zeros):
            dp[m] = 1
        else:
            dp[m] = 0
            zeros.append(m)

    out = []
    for n in ns:
        out.append("mastermei" if dp[n] else "the greatest")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では、最大値までのすべての dp 値が計算されます。$N$テストケース全体で。 重要な考え方は、ゲームの唯一の構造効果が導出された区間遷移で捕捉されるため、リダクション ステップの後に gcd 条件を再度明示的に計算することは決してないということです。 

ゼロ状態のキューは移動ウィンドウとして維持され、ヘッド ポインターにより各インデックスが最大 1 回削除されることが保証されます。 これにより、スキャンの繰り返しが回避され、複雑さが線形に保たれます。 

よくある実装上の間違いは、次のことを忘れることです。$dp[m]$以前の状態だけでなく、間隔にも依存します$m-1$。 窓$[L, R]$すべての正当な移動サイズをキャプチャし、下限を欠いているものです$L$正しさをすぐに破ってしまいます。
