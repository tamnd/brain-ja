 ## 解決策
 ## 問題の理解

 重み付けされたエッジを持つ有向グラフが与えられます。各ノードはボード上の位置を表し、各エッジはランニング スコアを増減する動きを表します。 ノード 1 から開始して、発信エッジを繰り返し選択するか、ゼロ ゲインでその場に留まります。 膨大な数の移動の後、正確に T ステップのすべてのシーケンスにわたる移動あたりの最大可能平均ゲインに興味があります。ここで、T は非常に大きいです。 

重要な解釈は、戦略がノード 1 から始まる無限のウォークに対応し、ステップあたりのスコアが合計の重みをステップ数で割ったものであるということです。 T が非常に大きいため、このグラフのノード 1 から達成可能な 1 移動あたりの長期平均報酬の最適値を効果的に探します。 

制約では N と M が最大 2000 に設定されるため、O(NM) または O(N^3) スタイルの解決策は妥当ですが、すべてのパスを列挙したり、長い歩行をシミュレートしたりすることは不可能です。 値 T は巨大であるため、直接のシミュレーションは無関係です。 サイクルの漸近的な挙動のみが重要です。 

微妙な問題は、その場に留まることが許可されているものの、報酬がゼロであることです。 これは、ステップの実行可能性の観点から、すべてのノードが重み 0 の自己ループを持つシンクとして動作できることを意味しますが、最適なゲインを得るためにサイクル構造は変更されません。 

よくある失敗例は、サイクルの混合を考慮せずに、答えが到達可能な正のサイクルのみに依存すると仮定することです。 たとえば、あるサイクルの平均が 5 で、別のサイクルの平均が 1 である場合、それらを交互に行うことは、最良のサイクルに固執するよりも悪いですが、移行により、良好なサイクルに到達する前に一時的な損失が発生する可能性があります。 

もう 1 つの落とし穴は、到達可能性を無視することです。ノード 1 から到達できない場合、平均サイクルが高くても役に立ちません。 

## アプローチ

 単純な考えは、長い歩行をシミュレートし、重みの合計を経験的に最大化しようとすることです。 しかし、貪欲にシミュレーションしたとしても、得られる軌道は 1 つだけであり、可能な軌道の数は T とともに指数関数的に増加します。T は 10^10 のオーダーであるため、これは完全に不可能です。 

問題の実際の構造は、十分なステップを経た後、最適な戦略はほぼすべての時間を、強く接続された領域内で循環する必要があるという事実から来ています。 その領域への初期パスの寄与は、平均すると無視できるほどになります。 

これにより、問題は、ノード 1 から到達可能な、エッジごとの平均重みを最大化するサイクル (または強く接続されたコンポーネント内のサイクルの組み合わせ) を見つけることになります。これは、有向グラフにおける古典的な最大平均サイクル問題です。 

重要な変換は、「ステップごとの平均重みを最大化する」という質問を実現可能性の質問に変換することです。つまり、候補値 x について、平均が少なくとも x である歩行が存在するかどうかを検討します。 すべてのエッジの重みから x を減算すると、合計重みが負ではないサイクルが存在するかどうかを確認することになります。 このようなサイクルが存在する場合、少なくとも平均 x を達成できることを意味します。 そうでない場合、x は大きすぎます。 

この単調な特性により、x に対する二分探索が可能になります。 各チェックは、修正された重みを使用してグラフ内に正のサイクルが存在するかどうかを検出することになります。これは、O(NM) のベルマン フォード スタイルの緩和を使用して実行できます。 

N と M は両方とも 2000 までなので、O(NM 対数精度) が許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(T・M) | O(N) | 遅すぎる |
 | 二分探索 + ベルマンフォード | O(NM ログ(1e9)) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 ノード 1 からのステップごとに達成可能な最大の平均重みが必要です。これを決定問題に変換します。候補値 x について、平均重みが少なくとも x である到達可能なサイクルが存在するかどうかを尋ねます。

1. x の二分探索範囲から開始します。通常は、可能な最小のエッジの重みから可能な最大のエッジの重みまでです。 平均はエッジの極値内になければならないため、これが答えの限界となります。 
2. 固定 x の場合、すべてのエッジの重み w を w − x に変換します。 この変換されたグラフに総和 ≥ 0 のサイクルが存在する場合、元のグラフには平均重みが少なくとも x のサイクルが含まれます。 
3. ノード 1 から到達可能なこのようなサイクルを検出するには、すべてのエッジに対してベルマン・フォード緩和を N 回実行します。 dist[v] が v で達成可能な最大調整合計を表す距離配列を維持します。 
4. dist[1] = 0 と他のすべてのノードを非常に負の数に初期化します。 これにより、ノード 1 からの到達可能性が強制されます。 
5. すべてのエッジを繰り返し緩めます。 N 回の反復後に距離が改善した場合、それは変換されたグラフに正のサイクルがあることを意味し、x が実現可能であることを意味します。 
6. 実行可能なサイクルが存在する場合、二分探索の下限を上に移動します。 それ以外の場合は、上限を減らします。 
7. 十分な精度の反復 (または double の場合は 60 回などの固定反復) の後、見つかった最良の値を出力します。 

なぜ効果があるのか

 長い歩行は、あるサイクルへの単純なパスと、そのサイクルの繰り返しの横断に分解されます。 T が大きくなるにつれて、パスの寄与は無視できます。 したがって、限界平均はサイクル構造によって完全に決定されます。 変換 w − x は、問題を、いずれかのサイクルが非負のドリフトを維持できるかどうかを検出することに変換します。これは、平均が少なくとも x であることとまったく同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def has_positive_cycle(n, edges, x):
    INF = -10**30
    dist = [INF] * (n + 1)
    dist[1] = 0

    for _ in range(n):
        updated = False
        for u, v, w in edges:
            val = dist[u] + (w - x)
            if val > dist[v]:
                dist[v] = val
                updated = True

    for u, v, w in edges:
        if dist[u] + (w - x) > dist[v]:
            return True

    return False

def main():
    n, m = map(int, input().split())
    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((u, v, w))

    lo, hi = -1e9, 1e9

    for _ in range(60):
        mid = (lo + hi) / 2
        if has_positive_cycle(n, edges, mid):
            lo = mid
        else:
            hi = mid

    print(f"{lo:.10f}")

if __name__ == "__main__":
    main()
```この実装では、単一の距離配列を保持し、N ラウンドにわたってベルマン・フォード緩和を実行します。 最後のパスでは、改善の可能性がまだあるかどうかを検出し、変換されたグラフに正のサイクルが示されることを示します。 

二分探索では浮動小数点の中点が使用されます。 必要な 1e-6 精度には、60 回の反復で十分です。 

よくある実装上の間違いは、到達不可能なノードを非常に負の値として初期化するのを忘れることです。これにより、ノード 1 から到達できないサイクルが誤って答えに影響を与えることになります。 

## 実用的な例

 ### サンプル 1

 グラフ:

 1→2(2)

 2→1(-1)

 値 x を二分探索します。 x を減算して重みを変換した後の状態を考えます。 

| 反復 | 距離[1] | 距離[2] | 主な所見 |
 | --- | --- | --- | --- |
 | 初期化 | 0 | -inf | ノード 1 から開始 |
 | リラックス | 0 | 2-x | エッジ 1→2 |
 | リラックス | ×? | 更新情報 | サイクルが貢献を開始します |

 x = 0.5 の場合、サイクル 1→2→1 の重みは (2 + (-1)) = 1、平均 0.5 であるため、変換されたサイクルの合計重みはゼロとなり、実行可能になります。 

これにより、意味のあるサイクルのみが長さ 2 に対して合計重み 1 を持つため、答えが 0.5 であることが確認されます。 

### サンプル 2

 サイクル:

 1→2(-5)

 2→3(5)

 3→1(-5)

 合計のサイクルの重みは -5 であるため、すべての走査で平均が減少します。 最善の戦略は、ゼロ移動を使用してノード 1 にとどまることです。 

| ステップ | 距離[1] | 距離[2] | 距離[3] | コメント |
 | --- | --- | --- | --- | --- |
 | 初期化 | 0 | -inf | -inf | 開始 |
 | リラックス | 0 | -5-x | -inf | 最初のエッジ |
 | リラックス | -5-x | ... | -10-x | サイクルが悪くなる |

 x > 0 には正の循環は存在しないため、答えは 0 になります。 

これは、アルゴリズムが負のサイクルに強制されるよりも何もしないことを正しく選択していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N M log C) | チェックごとの Bellman-Ford O(NM)、精度よりも二分探索 |
 | スペース | O(N + M) | 隣接ストレージと距離配列 |

 N、M が 2000 までの場合、緩和ステップは最大 400 万回の操作であり、最大 60 回の反復で乗算しても制限内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    n, m = map(int, sys.stdin.readline().split())
    edges = []
    for _ in range(m):
        u, v, w = map(int, sys.stdin.readline().split())
        edges.append((u, v, w))

    def has_cycle(x):
        INF = -10**30
        dist = [INF] * (n + 1)
        dist[1] = 0

        for _ in range(n):
            for u, v, w in edges:
                if dist[u] > -10**20:
                    dist[v] = max(dist[v], dist[u] + (w - x))

        for u, v, w in edges:
            if dist[u] > -10**20 and dist[u] + (w - x) > dist[v]:
                return True
        return False

    lo, hi = -1e9, 1e9
    for _ in range(60):
        mid = (lo + hi) / 2
        if has_cycle(mid):
            lo = mid
        else:
            hi = mid

    return f"{lo:.6f}"

 ## 特殊なケース

 重要なエッジ ケースは、高値のサイクルが存在するがノード 1 から到達できない場合です。ノード 1 のみが有限値で開始されるため、距離の初期化により、そのようなサイクルがアクティブ化されないことが保証されます。 

もう 1 つのケースは、セルフステイのみが有効なグラフです。 滞在はゼロに寄与するため、正のサイクルが存在しない場合、アルゴリズムは正しくゼロを返します。 

最後に、負のサイクルによってアルゴリズムが誤って答えを減少させることはありません。これは、平均を超えて最大化しているため、負のサイクルはゼロに留まる場合と比べて魅力的ではなくなるからです。
