 ## 解決策
 ## 問題の理解

 0 から N − 1 までラベル付けされた N 個の頂点の円形配置と、固定ジャンプ サイズ S が与えられます。頂点 0 から開始して、N を法として正確に S 位置だけ繰り返し前進し、このサイクルで無限の決定論的歩行を形成します。 

タスクは、ウォークの繰り返しが開始される前に、いくつの個別の頂点が表示されるかを判断することです。 言い換えれば、このモジュラー等差数列で到達可能な状態セットのサイズが必要になります。 

この制約により、N と S は 10^9 まで許容されるため、プロセスをステップごとにシミュレートするソリューションは直ちに実行不可能になります。 単純なシミュレーションでは、繰り返しの前に最大 N ステップかかる可能性がありますが、これは 1 秒の制限には大きすぎます。 これにより、グラフの探索ではなく、数理論的な解釈が求められます。 

S が大きいか N に等しい場合、微妙なエッジ ケースが発生します。たとえば、N = 10 および S = 10 の場合、次の頂点は常に (x + 10) mod 10 = x であるため、頂点 0 から離れることはありません。正解は 1 です。少なくとも 1 つの移動位置の変更を想定する単純な実装では、モジュロの動作に注意しないと、ここで誤って過大カウントされてしまいます。 

もう 1 つのエッジ ケースは、制約によって S = 0 が許可されていないが、S = 1 では、繰り返す前にすべての頂点の完全な走査が生成される場合です。 これは、極端な直感を定着させるのに役立ちます。 

## アプローチ

 移動ルールは、剰余 N の決定論的関数を定義します: x → x + S mod N。0 から開始して、すべて N を法として取得されるシーケンス 0、S、2S、3S などを生成します。 

ブルート フォース アプローチでは、このプロセスを繰り返しシミュレートし、以前に確認した頂点に戻るまで、訪問した頂点をハッシュ セットに保存します。 各ステップには O(1) かかりますが、S と N が互いに素である最悪のケースでは、繰り返す前に N 個の頂点すべてを訪問します。 これにより O(N) 時間が得られますが、N が 10^9 に達するとこれは不可能になります。 

重要な観察は、これが古典的なモジュラー算術軌道問題であるということです。 シーケンス kS mod N は、kS ≡ 0 (mod N) となる最小の正の k に等しい周期で循環します。 この条件は、kS を N で割ったものと等価です。 そのような最小の k は N / gcd(N, S) です。 これは、S が N を法とする加法群のサブグループを生成し、軌道サイズがそのサブグループのインデックスに等しいという事実から導き出されます。 

そこで、動きをシミュレートする代わりに、問題を最大公約数の計算に落とし込みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N) | O(N) | 遅すぎる |
 | GCD ベースの式 | O(log N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 t = 0 から始まるシーケンス x_t = (t · S) mod N に現れる個別の頂点の数を計算します。 

1. 整数 N と S を読み取ります。これらはモジュール空間とステップ サイズを定義します。 
2. g = gcd(N, S) を計算します。 これにより、モジュロ システムのサイクル長と均等に一致する最大ステップ サイズが取得されます。 直感的には、N と S は両方とも、到達可能な状態の構造を変更せずに、公約数によってスケールダウンできます。 
3. 答えを N // g として計算します。 これは、S によるステップによって N 頂点が gcd によって決定される等しい長さのサイクルに分割されるという事実から来ています。 
4. N // g を、反復前に訪問した個別の頂点の数として出力します。 

gcd が表示される理由は、S の繰り返し加算が最終的に N の倍数に達したときにちょうどラップするためです。kS を N で割り切れるようにする最小のステップ数は N / gcd(N, S) であり、これがまさに軌道サイズです。 

### なぜ効果があるのか

 ウォークは、S によって生成された加法群モジュロ N のサブグループを形成します。到達可能なすべての頂点は、kS mod N の形式になります。2 つの値 kS と k'S は、(k − k')S が N で割り切れるとき、つまり N / gcd(N, S) がゼロに戻る最小の正のステップであることを意味します。 これはシーケンスの周期であり、したがって個別の訪問頂点の数になります。

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def solve():
    n, s = map(int, input().split())
    g = math.gcd(n, s)
    print(n // g)

if __name__ == "__main__":
    solve()
```この解決策は、gcd を効率的に計算することに完全に依存しています。 Python 数学ライブラリは、対数時間で実行される Euclid のアルゴリズムを実装しています。 残りの計算は 1 つの除算です。 

よくある間違いは、動きを明示的にシミュレートしようとしたり、サイクルが 0 から始まることを忘れたりすることです。つまり、最初に繰り返される頂点条件は、再び 0 に戻るときです。 

## 実用的な例

 ### 例 1: N = 14、S = 8

 g = gcd(14, 8) = 2 を計算するため、答えは 14 / 2 = 7 となります。 

| ステップ | 頂点 |
 | --- | --- |
 | 0 | 0 |
 | 1 | 8 モジュラ 14 = 8 |
 | 2 | 16 モジュラ 14 = 2 |
 | 3 | 10 |
 | 4 | 4 |
 | 5 | 12 |
 | 6 | 6 |
 | 7 | 0 |

 表は、7 ステップ後に 0 に戻り、繰り返しが始まる前に正確に 7 つの異なる頂点を訪問したことを示しています。 これにより、式がサイクル長と一致することが確認されます。 

### 例 2: N = 2、S = 1

 g = gcd(2, 1) = 1 を計算するので、答えは 2 になります。 

| ステップ | 頂点 |
 | --- | --- |
 | 0 | 0 |
 | 1 | 1 |
 | 2 | 0 |

 サイクルの完全なカバレッジと一致するように、最初に戻る前に両方の頂点を訪問します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(log N) | Euclid の gcd 計算が支配的 |
 | スペース | お(1) | 少数の整数のみが保存されます。 

この制約では最大 10^9 の値が許可されるため、対数 gcd ベースのソリューションは快適に高速であり、大きなサイクルにわたるシミュレーションを回避します。 

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    n, s = map(int, input().split())
    g = math.gcd(n, s)
    return str(n // g)

assert run("2 1\n") == "2"

assert run("10 10\n") == "1"
assert run("1 1\n") == "1"
assert run("12 3\n") == "4"
assert run("1000000000 1\n") == "1000000000"

 ## 特殊なケース

 ### ケース N = S

 入力 N = 10、S = 10 の場合、すべての移動が 10 を法として 0 を加算するため、ウォークは永久に 0 のままになります。gcd は 10 であるため、式は 10 / 10 = 1 を与え、これは開始頂点のみが訪問されるという事実と一致します。 

### 場合 N と S が互いに素

 入力 N = 12、S = 5 の場合、gcd は 1 であるため、答えは 12 です。これより小さなステップでは S 倍数を N の倍数に揃えることができないため、ウォークは 0 に戻る前にすべての剰余を循環します。アルゴリズムはシミュレーションなしで完全なカバレッジを正確に識別します。
