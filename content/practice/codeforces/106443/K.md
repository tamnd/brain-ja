 ## 解決策
 ## 問題の理解

 N 人の参加者のグループが、1 から K までの番号が付けられた観光スポットを訪問したいと考えています。各参加者は、訪問を拒否する場所のリストを持っています。 l から r までの連続する参加者のセグメントを選択すると、そのセグメントの誰も拒否しない場合にのみ、そのグループはその場所に行こうとします。 

したがって、各クエリ [l, r] について、その間隔内のすべての参加者を効率的に取得し、参加者のいずれかが嫌いなすべての場所を収集し、それらの場所を考慮から除外します。 答えは、区間内で誰にも禁止されていない 1 から K までの場所のセットです。 

言い換えれば、各人は禁止された場所のサブセットを定義し、クエリは、連続した範囲の人々にわたるこれらの禁止されたサブセットの結合の補数を要求します。 

制約はソリューションを強力に形作ります。 N は最大 100000、Q は最大 200000 であるため、クエリごとに間隔をスキャンするソリューションは遅すぎます。 K は最大でも 60 であり、すべての参加者にわたって場所ごとの統計を維持できるほど十分に小さいです。 この非対称性、N と Q は大きいが K は小さいことが、重要な構造上のヒントです。 

素朴なアイデアは、クエリごとに、[l, r] 内のすべての参加者を反復処理し、サイズ K のブール配列内の禁止された場所をマークし、残りの場所を出力することです。 これにはクエリごとに O((r-l+1)·K) がかかり、最悪の場合は O(NKQ) にまで縮退し、制限をはるかに超えます。 

多くのクエリが長い間隔をカバーする場合、より微妙な失敗のケースが発生します。 K が小さい場合でも、長距離を繰り返しスキャンするとタイムアウトになります。 

## アプローチ

 ブルート フォース アプローチでは、各クエリが個別に処理されます。 クエリ [l, r] の場合、すべての場所が許可されると仮定してサイズ K の配列を初期化し、範囲内のすべての参加者をスキャンして禁止された場所をマークします。 最後に、マークされていないすべての場所を出力します。 これは問題の定義を直接シミュレートするので正しいですが、各クエリでは最大 N 人の参加者をスキャンし、参加者ごとに最大 K 個のフラグを更新する必要がある場合があります。 Q が 200000 までになると、これは非常に遅くなります。 

重要な点は、クエリごとに情報を最初から再計算する必要がないということです。 それぞれの場所で重要なのは、[l, r] の少なくとも 1 人の参加者がそれを禁止しているかどうかだけです。 これにより、問題は、参加者によってインデックス付けされたバイナリ配列に対する場所ごとの範囲存在クエリに変換されます。 

場所 k ごとに、インデックス i までの何人が k を禁止するかを示す参加者のプレフィックス合計を事前計算できます。 次に、クエリ [l, r] の場合、プレフィックスの合計の差がゼロかどうかをチェックすることで、k が区間内の禁止リストに含まれるかどうかを場所ごとに一定時間で判断できます。 これにより、各クエリが O(K) に減りますが、K は最大 60 であるため、これは許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(Q・N・K) | O(K) | 遅すぎる |
 | 場所ごとのプレフィックス合計 | O(N・K + Q・K) | O(N・K) | 承認済み |

 ## アルゴリズムのチュートリアル

 入力をバイナリ行列として再解釈します。行は参加者に対応し、列は場所に対応します。 エントリ (i, k) は、参加者 i が k の場所を拒否した場合は 1、それ以外の場合は 0 になります。 

次に、列方向の接頭辞の合計を前処理して、範囲内に 1 が存在するかどうかをすぐに回答できるようにします。

1. 1 から i までの何人の参加者が場所 k を禁止するかを意味するテーブル pref[k][i] を作成します。 入力を読み取りながら段階的に埋めていきます。 これにより、分散リストが高速範囲クエリをサポートする構造に変換されます。 
2. 各参加者 i について、禁止リストを反復処理し、それらの k に対して pref[k][i] = pref[k][i-1] + 1 をマークしますが、他のすべての k は単純に pref[k][i-1] を継承します。 これにより、各列が累積的な発生を個別に追跡するため、正確さが保証されます。 
3. 前処理の後、各クエリ [l, r] は 1 から K までのすべての k をチェックすることによって応答されます。pref[k][r] - pref[k][l-1] を計算します。 この値がゼロの場合、区間内で k の位置を禁止する人はいないため、有効です。 
4. すべての有効な k を昇順に収集します。 存在しない場合は、-1 を出力します。 

クエリごとにすべての k を明示的に反復する理由は、K が小さく固定されているため、クエリごとに 60 回のチェックがあっても、N や Q に比べて無視できるからです。 

### なぜ効果があるのか

 各場所 k について、プレフィックス合計配列は、各位置までの禁止リストに k が現れる回数を正確にエンコードします。 範囲 [l, r] には、そのセグメント内で累積カウントが増加しない場合に限り、k の禁止された出現が含まれません。これは pref[k][r] = pref[k][l-1] と同等です。 各場所は独立しているため、すべての k をチェックすると、参加者間の対話を見逃すことなく、許可された場所の完全なセットが再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    N, K = map(int, input().split())
    
    # pref[k][i]: number of times place k is forbidden in [1..i]
    # using 1-based indexing for convenience
    pref = [[0] * (N + 1) for _ in range(K + 1)]

    for i in range(1, N + 1):
        data = list(map(int, input().split()))
        m = data[0]
        forbidden = data[1:]
        
        # carry previous prefix values
        for k in range(1, K + 1):
            pref[k][i] = pref[k][i - 1]
        
        for k in forbidden:
            pref[k][i] += 1

    Q = int(input())
    out = []

    for _ in range(Q):
        l, r = map(int, input().split())
        ans = []
        
        for k in range(1, K + 1):
            if pref[k][r] - pref[k][l - 1] == 0:
                ans.append(str(k))
        
        if not ans:
            out.append("-1")
        else:
            out.append(" ".join(ans))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```前処理ステップでは、K 個のプレフィックス配列を同時に構築します。 重要な実装の詳細は、現在の参加者に更新を適用する前に、pref[k][i-1] を pref[k][i] にコピーすることです。 これにより、各参加者は明示的に禁止した場所のカウントのみが増加し、他のすべての場所は変更されないことが保証されます。 

クエリ ステップはプレフィックスの違いに完全に依存しているため、参加者のクエリごとのスキャンは必要ありません。 

## 実用的な例

 3 人の参加者と 5 つの場所からなる小規模なシナリオを考えてみましょう。 

参加者 1 は 2 を禁止します。 

参加者 2 は 2 と 5 を禁止します。 

参加者 3 は何も禁止しません。 

クエリ [1, 2] は、参加者 1 と 2 の両方が許可する場所を尋ねます。 

プレフィックス数を構築します。 

| 私 | フォーブ(2) | フォーブ(5) |
 | --- | --- | --- |
 | 1 | 1 | 0 |
 | 2 | 2 | 1 |
 | 3 | 2 | 1 |

 クエリ [1,2] の場合、場所 2 のカウントは 2 - 0 = 2 であるため、除外されます。 5 位には 1 - 0 = 1 があり、これも除外されます。 1、3、4 の位置は有効なままであるため、出力は 1 3 4 となります。 

ここでクエリ [2,3] を考えてみましょう。 ここで、参加者 3 は制限を追加しません。 

| k | 設定[k][3] - 設定[k][1] |
 | --- | --- |
 | 2 | 2 - 1 = 1 |
 | 5 | 1 - 0 = 1 |

 したがって、再び 2 と 5 が除外され、同じ結果構造となり、プレフィックスの違いがどのように間隔を正しく分離するかを示しています。 

これは、アルゴリズムが区間外の絶対位置ではなく、区間内のカウントのみに依存していることを示しています。

| スペース | O(N・K) | すべての参加者にわたる各場所のプレフィックス合計を保存する |

 ## 特殊なケース

 微妙なケースは、参加者が場所を一切禁止しない場合です。 その場合、それらの行はプレフィックス数を変更すべきではなく、そのような参加者のみを含むクエリはすべての場所を返す必要があります。 インクリメントが適用されないため、プレフィックス構築により自然にこれが処理されます。 

もう 1 つのケースは、クエリが単一の参加者を対象とする場合です。 答えは単にその参加者の禁止されたセットを補うものでなければなりません。 pref[k][r] - pref[k][l-1] は単一のインデックスを分離するため、プレフィックスの違いは正確にその 1 行のチェックに帰着します。 

最後に、K=1 の場合、出力は「1」または「-1」のいずれかになります。 k にわたるループはクエリごとに 1 つのチェックに縮退し、プレフィックスの合計はその範囲内でその唯一の場所が禁止されているかどうかを正確に反映するため、このアルゴリズムは引き続き機能します。
