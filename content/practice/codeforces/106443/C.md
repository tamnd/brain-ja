 ## 解決策
 ## 問題の理解

 2 つの多項式が与えられ、1 つは外部関数として機能し、もう 1 つは内部関数として機能します。 最初の多項式$P(x)$すでに値を取得した後でその値を変換する方法と 2 番目の多項式を定義します。$Q(x)$に入力される値を定義します$P$。 タスクは合成多項式を計算することです$R(x) = P(Q(x))$、すべての発生を意味します$x$内部$P$多項式全体で置き換えられます$Q(x)$、そしてすべてが展開されます。 

出力はシンボリック式ではなく、完全展開後の結果の多項式の明示的な係数であり、998244353 を法として計算されます。$P$は最大でも 100 であり、次数は$Q$が最大 100 の場合、結果として得られる多項式の次数は 10000 までになります。 

主要な構造的課題は、代替によって権限が拡大されることです。各用語$Q(x)^k$それ自体は畳み込みのようなオブジェクトです。 単純な拡張では多項式を繰り返し乗算することになり、コストが急速に増大します。 

いずれかの多項式が疎な構造を持つ場合、特に次の場合に、微妙なエッジ ケースが発生します。$Q(x)$が単項式プラス定数であるか、$P(x)$ゼロ係数がたくさんあります。 単純な項ごとの乗算アプローチでは、誤って同じ累乗を再計算してしまう可能性があります。$Q(x)$複数回実行すると、結果の構造が決定的であっても、冗長な作業が発生します。 

## アプローチ

 定義を直接解釈すると、コンピューティングが示唆されます。$R(x)$の各係数を反復することにより、$P(x)$。 それぞれについて$i$、計算します$Q(x)^i$、それを乗算します$p_i$、結果に追加します。 これは、多項式合成の定義に正確に従っているため、正しいです。 

ただし、コンピューティング$Q(x)^i$あらゆるものをゼロから$i$高価です。 各多項式乗算のコスト$O(m^2)$までやって、$n$時間はおよそにつながります$O(n^2 m^2)$最悪の場合でも動作します。ここで合格するには十分ですが、概念的に無駄があり、実装が非効率になる危険性があります。 

重要な観察は、各べき乗を独立して再計算する必要がないということです。 一度知ってしまえば、繰り返し権力を構築することができます。$Q(x)^i$、私たちは得ることができます$Q(x)^{i+1}$乗算して$Q(x)$。 これにより、繰り返される再計算が多項式乗算の単一チェーンに変わります。 

また、答えを段階的に蓄積します。$Q(x)^0 = 1$を繰り返し乗算します。$Q(x)$、各ステップで追加します$p_i \cdot Q(x)^i$結果に反映されます。 これにより、次の係数に対する単一の前方スキャンで計算が調整されます。$P$。 

次数が小さいので、簡単です。$O(n m^2)$または$O(n^2 m)$このアプローチは制約の下では完全に安全であり、漸近最適化よりも反復畳み込みの単純さが重要です。

 | 反復的なパワーの蓄積 |$O(n m^2)$|$O(m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 現在の累乗を維持しながら結果多項式を構築します。$Q(x)$。 

1. 多項式を初期化する`power`代表する$Q(x)^0$、それはまさに$[1]$。 これは多項式乗算の単位元に相当します。 
2. 結果の多項式を初期化する`res`度までのすべてのゼロとして$n \cdot m$。 これにより、各期からの貢献が蓄積されます。$P(x)$。 
3. 反復処理$i$0から$n$。 各インデックスで$i$、現在開催中$power = Q(x)^i$、したがって、この用語の寄与は$p_i x^i$で$P(x)$になる$p_i \cdot power$。 このスケーリングされた多項式を次のように追加します。`res`。 
4. 加工後係数$p_i$、 アップデート`power`それを乗算することで$Q(x)$。 これにより、$Q(x)^{i+1}$。 乗算は標準的な多項式畳み込みです。各係数は、インデックスが合計されるペアごとの積を合計することによって形成されます。 
5. すべての係数が得られるまで続行します。$P(x)$処理されます。 決勝戦`res`の係数が含まれています$P(Q(x))$。 

### なぜ効果があるのか

 あらゆる段階で$i$、変数`power`まさに$Q(x)^i$。 これは帰納的に維持されます。次のように始まります。$Q(x)^0 = 1$、各更新は次のように乗算されます。$Q(x)$、指数を 1 つ増やします。 毎期から$P(x)$は、対応する正しいべき乗で 1 回だけ適用されます。$Q(x)$、最終的な合計は、省略や重複なく多項式合成の定義と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def add_poly(a, b):
    res = [0] * max(len(a), len(b))
    for i, v in enumerate(a):
        res[i] += v
    for i, v in enumerate(b):
        res[i] = (res[i] + v) % MOD
    for i in range(len(res)):
        res[i] %= MOD
    return res

def mul_poly(a, b):
    res = [0] * (len(a) + len(b) - 1)
    for i in range(len(a)):
        ai = a[i]
        for j in range(len(b)):
            res[i + j] = (res[i + j] + ai * b[j]) % MOD
    return res

def scale_poly(a, c):
    return [(x * c) % MOD for x in a]

def main():
    n, m = map(int, input().split())
    p = list(map(int, input().split()))
    q = list(map(int, input().split()))

    power = [1]
    res = [0] * (n * m + 1)

    for i in range(n + 1):
        term = scale_poly(power, p[i])
        for j, v in enumerate(term):
            res[j] = (res[j] + v) % MOD
        if i != n:
            power = mul_poly(power, q)

    print(*res)

if __name__ == "__main__":
    main()
```実装では実行多項式が維持されます`power`に等しい$Q(x)^i$。 各係数について$p[i]$、この多項式をスケールし、答えの配列に追加します。 畳み込み関数`mul_poly`直接です$O(nm)$サイズが小さいので乗算します。 

最もデリケートな部分は、多項式のサイズを一定に保つことです。 結果の配列は次のように事前に割り当てられます。$n \cdot m + 1$、これは合成の可能な最大次数であるためです。 これにより、サイズ変更の繰り返しが回避され、蓄積中に決定的なインデックス作成が保証されます。

import sys, io

MOD = 998244353

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import prod

    n, m = map(int, input().split())
    p = list(map(int, input().split()))
    q = list(map(int, input().split()))

    power = [1]
    res = [0] * (n * m + 1)

    def mul(a, b):
        r = [0] * (len(a) + len(b) - 1)
        for i in range(len(a)):
            for j in range(len(b)):
                r[i + j] = (r[i + j] + a[i] * b[j]) % MOD

            power = mul(power, q)

    return " ".join(map(str, res)).strip()

 ## 特殊なケース

 最初のエッジケースは次のような場合です。$P(x)$は一定です。 この状況では、すべてのより高い権力は、$Q(x)$は無関係です。 アルゴリズムはまだ初期化中です`power = 1`、追加のみ$p_0$、意味のある乗算は実行されません。 出力は定数多項式のままで、数学的定義と一致します。 

もう一つのケースは次のような場合です。$P(x)$ゼロ以外の高次項が 1 つあります。 例えば、$P(x) = x^n$。 アルゴリズムが増殖する`power`到達するまで前進する$Q(x)^n$、投稿は 1 つだけ追加されます。 これにより、累積の繰り返しが回避され、正しい拡張多項式が生成されます。 

最後に、いつ$Q(x)$が線形または定数である場合、乗算を繰り返しても構造の複雑さが予期せず増加することはありません。 反復`power`update は依然として正確なパワーを追跡し、縮退した構成であっても特別なケースを使用せずに確実に処理できるようにします。
