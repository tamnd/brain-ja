 ## 解決策
 ## 問題の理解

 最初は垂直面上の整数座標にいくつかの食品が配置されており、それらはすべて地面に向かってまっすぐに落ちています。$y = 0$。 毎秒、すべての食品は水平位置を変えずに、正確に 1 単位だけ下に移動します。 1 人のキャラクターは地面の原点から開始し、1 秒あたり 1 単位の速度で左、右に移動したり、その場に留まったりすることができます。 

食べ物は、地面に着いた瞬間にのみ食べられるようになります。 キャラクターは、同時に同じ水平座標に立っている場合にのみそれを食べることができます。 到着が早くても遅くても、食べ物は失われてしまいます。 

課題は、最適な移動スケジュールと対象となる食品の選択を選択することにより、食べられる食品の最大数を決定することです。 

入力では最大 2000 個の食品項目が得られ、それぞれが位置によって説明されます。$(x_i, y_i)$。 食物が地面に到達する時間は固定されており、$y_i$、1秒あたり1つずつ減少するため。 したがって、それぞれの食べ物は、その位置にあることへの要求として再解釈できます。$x_i$時に$y_i$。 

これにより、問題はできるだけ多くのリクエストを選択することになります。各リクエストには時間と位置があり、リクエスト間の移動は回線上の単位速度によって制限されます。 

主な問題は、すべての食品の組み合わせが順番に適合するとは限らないことです。 たとえ 1 つの食品が時間的に早く現れたとしても、残りの時間内にその位置から別の食品の位置に移動することは物理的に不可能な場合があります。 

単純な間違いは、時間順に分類するだけで十分で、常に手の届く食べ物を貪欲に摂取することがうまくいくと考えることです。 たとえば、次のことを考えてみましょう。 

入力:

 3

 0 1

 100 2

 1 2

 最初の食べ物は、$(0,1)$、2番目に$(100,2)$、3番目に$(1,2)$。 最も早く到達できることを優先する貪欲な選択は、誤った選択をする可能性があります。$(0,1)$それから試してください$(100,2)$、距離の関係で不可能です。有効なチェーンがありません$(0,1) \rightarrow (1,2)$。 

もう 1 つの失敗例は、待機の柔軟性を無視したことに起因します。 食品が起点から到達可能な場合でも、後の食品に到達するには、それをスキップした方が良い場合があります。 

これらの依存関係により、この構造は本質的に、計量制約の下で実行可能な最長の連鎖問題になります。 

## アプローチ

 Each food item can be viewed as a point$(t_i, x_i)$、 どこ$t_i = y_i$。 これらのポイントを時間の増加順にたどることができるように、これらのポイントの最大のサブセットを選択する必要があります。$(0, 0)$、連続した選択されたポイント間の移動は単位速度を尊重するという制約付き。 

選択した 2 つの食品間の移動制限$i$そして$j$、 と$t_i < t_j$、 は：$$|x_i - x_j| \le t_j - t_i$$これにより、Pou は時間内に 2 つの位置の間を物理的に移動できるようになります。 

ブルート フォース ソリューションでは、すべてのサブセットまたはすべてのパスが試行されます。 各食品について、以前の互換性のある食品の後にそれを含めるかどうかを決定しようとします。 これにより、ポイントのすべてのペア間の遷移をチェックし、すべてのチェーンを効果的に探索することができます。 正確さは簡単ですが、サブセットの数は指数関数的であり、ペアごとの探索さえも困難です。$O(n^2)$しかし、メモ化を行わないと、すぐに再帰的定式化で繰り返し再計算が行われるようになります。 

重要な観察は、食品が時間でソートされると、問題は有向非巡回グラフの最長経路になり、各ノードが食品を表し、エッジがそれらの間の移動の実現可能性を表すことです。 時間は厳密に増加するため、サイクルは存在せず、動的計画法がきれいに適用されます。 

各食品の DP 状態、つまりその食品で終わるまでに食べられる最適なアイテム数を定義します。 各状態は以前の時間のみに依存するため、昇順に計算できます。 

これにより、問題は指数関数的なサブセットの探索から、すべてのペアごとの遷移を一度に評価することに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットまたはパスに対するブルート フォース検索 | 指数 | O(n) から O(n^2) | 遅すぎる |
 | ソートされたイベントに対する DP | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. それぞれの食品をイベントに変換する$(t_i, x_i)$、 どこ$t_i = y_i$。 これにより、落下動作を明示的に追跡するのではなく、特定の時点をスケジュールするという問題が再構成されます。 
2. すべてのイベントを時間の増加順に並べ替えます。 これにより、有効な遷移は常に前のインデックスから後のインデックスに移行するため、状態を再訪する必要はありません。 
3. DP 配列を初期化します。$dp[i]$イベント終了時に食べられる食品の最大数を表します$i$。 
4. イベントごとに$i$, まず、オリジンから直接到達可能かどうかを確認します。 これは次の場合に有効です$|x_i| \le t_i$。 その場合は設定してください$dp[i] = 1$、それ以外の場合はゼロとして初期化します。 これは、その食品でチェーンが開始される可能性を捉えます。 
5. イベントの各ペアについて$j < i$、イベントかどうかを確認します$i$イベントをフォローできる$j$。 The transition is valid if:$$|x_i - x_j| \le t_i - t_j$$有効な場合は、次を更新します。$$dp[i] = \max(dp[i], dp[j] + 1)$$このステップでは、以前に最適だったチェーンを拡張することで、より長い実行可能なシーケンスを構築します。 

1. 答えはすべての中の最大値です$dp[i]$。 

これが機能する理由は、実行可能な食品のシーケンスが、連続する各ペアが移動制約を満たす点のシーケンスに正確に対応するためです。 時間による並べ替えにより、すべての有効なシーケンスがこの DP グラフ内のパスとして表示されることが保証され、DP 再帰ではそのようなすべてのパスが反復なしで探索されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    foods = []
    for _ in range(n):
        x, y = map(int, input().split())
        foods.append((y, x))
    
    foods.sort()
    
    dp = [0] * n
    ans = 0
    
    for i in range(n):
        t_i, x_i = foods[i]
        
        if abs(x_i) <= t_i:
            dp[i] = 1
        
        for j in range(i):
            t_j, x_j = foods[j]
            
            if dp[j] > 0 and abs(x_i - x_j) <= t_i - t_j:
                dp[i] = max(dp[i], dp[j] + 1)
        
        ans = max(ans, dp[i])
    
    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、各アイテムを時間位置イベントとして再解釈し、時間で並べ替えることから始まります。 DP 配列は増分的に構築され、各状態は原点から到達可能な場合は新しいチェーンを開始し、移動制約が許可する場合は前のチェーンを延長します。 

細かい点は、食べ物から開始するための初期化条件です。 確認せずに$|x_i| \le t_i$、DPは、プーが初期の食べ物に「テレポート」できると誤って想定しているでしょう。 この条件は、開始点から実現可能性を強制します。 

入れ子になったループは安全です。$n \le 2000$、作る$n^2$制限時間内で移行は可能です。 

## 実用的な例

 小さな例を考えてみましょう。 

入力:

 3

 0 1

 1 2

 2 4

 変換および並べ替え後:

 | 私 | 時間$t$| 位置$x$| dp初期化 | トランジション |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 0 | 1 | 有効な開始 |
 | 1 | 2 | 1 | 1 | 0から有効 |
 | 2 | 4 | 2 | 1 | 1 から有効 |

 のために$i=1$からの移行$i=0$成立するので$|1-0| \le 1$。 のために$i=2$、以前の両方の状態はシーケンス上で互換性がありますが、最適なチェーンは次のとおりです。$0 \rightarrow 1 \rightarrow 2$、 dp = 3 となります。 

これは、DP が物理的に実現可能な最長の動作チェーンを蓄積していることを示しています。 

別の例:

 入力:

 3

 0 1

 100 2

 1 2

 並べ替え後:$(1,0), (2,1), (2,100)$| 私 | dp値 | 最高の前任者 |
 | --- | --- | --- |
 | 0 | 1 | 開始 |
 | 1 | 2 | 0 |
 | 2 | 2 | 0 |

 ここで大きくジャンプします$x=100$距離の制約により以前の状態を追跡できないため、チェーン全体で改善されることはありません$0 \rightarrow 1$。 これは、DP が物理的に不可能な遷移を正しく拒否することを確認します。

 | 測定 | 複雑さ | 説明 |

 | 時間 |$O(n^2)$| 各イベントを以前のすべてのイベントと比較して、実現可能性の移行をテストします。 
| スペース |$O(n)$| DP 配列とイベント ストレージのみが必要です。 

と$n \le 2000$、最悪のケースには約 400 万回の遷移チェックが含まれますが、これは C++ の一般的な制限内に問題なく収まり、最適化された Python でも許容されます。

 ## 特殊なケース

 エッジケースの 1 つは、原点から食べ物に到達できない場合です。 たとえば:

 入力:

 2

 100 1

 200 2

 どの項目も違反している$|x| \le t$, したがって、DP 値は全体を通してゼロのままです。 有効な開始状態が作成されないため、アルゴリズムは正しくゼロを出力します。 

もう 1 つのエッジ ケースは、食品が起点から個別に到達可能であるものの、順番に相互に互換性がない場合です。 DP は、ペアごとの時間と距離の制約が成立する場合にのみチェーンを拡張するため、正確性が保証されます。 無効な遷移は当然無視され、過剰なカウントが防止されます。 

最後のエッジケースには、複数の食品が同時に含まれます。 グループを同じ時間でソートするため、同じ時間内の遷移は考慮されません。$t_j < t_i$が必要です。 これにより、同一のタイムスタンプでの不正な「インスタント ジャンプ」が防止されます。
