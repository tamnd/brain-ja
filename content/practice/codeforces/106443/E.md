 ## 解決策
 ## 問題の理解

 このタスクは、チェス盤を表す固定サイズのグリッド上での直接形式変換の問題です。 入力は 8 × 8 文字行列で、各セルはチェスの駒または空の正方形のいずれかです。 駒は標準的なチェスの記号を使用してエンコードされ、白の駒は大文字、黒の駒は小文字になります。一方、空の四角形はドットで表されます。 

必要な出力は、Forsyth-Edwards Notation (FEN) の単一の文字列です。 FEN は、ボードの各行を上から下に圧縮し、連続する空のマスをそのカウントに置き換え、駒の文字を変更しないようにします。 行はスラッシュで区切られます。 

入力の構造はすでに FEN ボードの空間レイアウトと一致しているため、問題はドットのみに適用される単純なランレングス エンコーディング ルールによる行単位の圧縮に帰着します。 

ボード サイズが 8 x 8 に固定されているため、制約は最小限です。これは、グリッド全体にネストされたループがあるソリューションであっても、あらゆるソリューションが一定時間で実行されることを意味します。 漸近的な最適化を行う必要はありません。 唯一の実際の要件は、連続する空の四角形と行区切り文字を正確に処理することです。 

最も一般的な間違いは、微妙な書式設定の問題に起因します。 よくあるバグは、行の終わりにある保留中のドットのカウントをフラッシュするのを忘れることです。 たとえば、次の行を考えてみましょう。```
........
```正しい出力は次のとおりです`8`ただし、ドット以外の文字に遭遇したときにのみカウントを発行する単純な実装では、行末フラッシュを明示的に処理しない限り、誤って空の文字列が生成されます。 

もう 1 つの特殊なケースは、数字と文字が混在していることです。 例えば、```
r.bk...r
```にならなければなりません`r1bk3r`。 バグのあるアプローチでは、複数のドット セグメントを個別に集計する必要があることを考慮せずに、数字を直接追加する可能性があります。 

Finally, row separation must be exact. 行間にスラッシュがないか、末尾にスラッシュを追加すると、無効な FEN が生成されます。 

## アプローチ

 ブルートフォース解釈では、各セルを処理し、すべての文字に対して即座に出力を出力しようとします。 ドットをそのまま追加し、後で文字列を後処理してドットの連なりを圧縮することもできます。 これには、ランレングスを計算するために中間文字列全体を再度スキャンする必要がありますが、これは不必要であり、エラーが発生しやすくなります。 

このアプローチの非効率性は、ボードのサイズが一定であるため、漸近的な意味での時間の複雑さではなく、構造の複雑さです。つまり、複数のパスと余分なストレージにより、行の境界を越えて誤ったグループ化が発生する可能性が高くなります。 

重要な点は、各行が独立しており、ドット圧縮は行内で純粋にローカルであるということです。 これは、連続したドットのカウンターを維持しながら、単一のリニア スキャンで各行を処理できることを意味します。 ドット以外の文字が見つかった場合、カウンタがゼロでない場合はカウンタをフラッシュし、文字を出力します。 行の最後で、残りのカウンタをフラッシュし、行の結果を追加します。 

これにより、問題は、一定の追加状態による行ごとの 1 つのパスに軽減されます。

 ## アルゴリズムのチュートリアル

 1. ボードの 8 行すべてを長さ 8 の文字列として正確に読み取ります。各行は FEN 出力順序の 1 つのランクに対応するため、反転する必要はありません。 これにより、表記法で必要とされる上から下の順序が維持されます。 
2. エンコードされた行を蓄積するために空のリストを初期化します。 リストを使用すると、入力サイズが小さい場合でも、文字列連結の繰り返しコストが回避されます。 
3. 行ごとに、連続するドットのカウンターと、その行のエンコードされたバージョンの空の文字列ビルダーを初期化します。 
4. Scan characters from left to right. 現在の文字がドットの場合、ドット カウンタをインクリメントします。 これにより、空のセグメントの全長がわかるまで出力が延期されます。 
5. 現在の文字がドットでない場合は、まずドット カウンタが 0 以外であるかどうかを確認します。 存在する場合は、その数値を行文字列に追加し、カウンターをリセットします。 Then append the piece character itself.
 6. 行のスキャンが終了した後、ドット カウンタがゼロでない場合は、ドット カウンタの最終フラッシュを実行します。 これにより、後続の空のセグメントが失われることがなくなります。 
7. Append the encoded row to the list of rows.
 8. すべてのエンコードされた行をスラッシュを使用して結合し、最終的な FEN 文字列を形成します。 

### なぜ効果があるのか

 各行は、ドットまたはピースの最大の連続セグメントに分解されます。 このアルゴリズムは、各最大ドット セグメントをその長さに置き換え、他のすべての文字は変更しないままにします。 セグメンテーションは重複することなく厳密に左から右に行われるため、すべての正方形が 1 つのセグメントに 1 回だけ寄与します。 行の独立性により、行境界を越えたセグメント間の相互作用がないことが保証されるため、行ごとのローカルな正確性は、完全な FEN 文字列のグローバルな正確性を意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def encode_row(row: str) -> str:
    res = []
    cnt = 0

    for ch in row:
        if ch == '.':
            cnt += 1
        else:
            if cnt:
                res.append(str(cnt))
                cnt = 0
            res.append(ch)

    if cnt:
        res.append(str(cnt))

    return ''.join(res)

def main():
    rows = [input().strip() for _ in range(8)]
    encoded = [encode_row(r) for r in rows]
    print('/'.join(encoded))

if __name__ == "__main__":
    main()
```このソリューションでは、行エンコードをヘルパー関数に分離することで、ドット圧縮ロジックが再利用可能になり、推論が容易になります。 実装の重要な詳細は、各行スキャン後のドット カウンタの最終フラッシュです。 これがなければ、後続の空の四角形は決して出力されません。 

リストの使用`res`ここでスケールが固定されている場合でも、文字列の連結が繰り返されることによる二次的な動作を回避します。 最後に結合すると、最終的なコンパクトな表現が生成されます。

import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    def encode_row(row: str) -> str:
        res = []
        cnt = 0
        for ch in row:
            if ch == '.':
                cnt += 1
            else:
                if cnt:
                    res.append(str(cnt))
                    cnt = 0
                res.append(ch)
        if cnt:
            res.append(str(cnt))
        return ''.join(res)

    rows = [input().strip() for _ in range(8)]
    print('/'.join(encode_row(r) for r in rows))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    solve()
    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

 ## 特殊なケース

 次のような完全に空の行`........`実装が行の終わりでドット カウンタを正しくフラッシュするかどうかをテストします。 アルゴリズムは 8 つのドットを蓄積してから追加します。`8`行が終了すると、状態が失われることはありません。 

次のような複数の分離された空の領域を含む行`r.bk...r`カウンタがセグメント間で正しくリセットされることを確認します。 スキャンによって生成されるのは、`r`、その後フラッシュします`1`、 それから`bk`、その後フラッシュします`3`、そして最後に`r`、生産`r1bk3r`。 

行全体がピースで構成されている場合、ドット カウンタは常にゼロのままであるため、偶発的な数字が挿入されることはありません。
