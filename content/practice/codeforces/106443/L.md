 ## 解決策
 ## 問題の理解

 私たちには、個別の単語からなる固定された辞書が与えられています。 任意の 2 つの単語の間に、その文字のみに依存する接続ルールを定義します。つまり、2 つの単語が少なくとも 1 つの共通の文字を共有する場合、2 つの単語は直接互換性があるとみなされます。 このルールを使用すると、直接互換性がある限り、辞書内の単語を別の単語に「変換」することができます。 突然変異チェーンは、隣接する各ペアが少なくとも 1 つの文字を共有する辞書の単語のシーケンスです。 タスクは、そのようなチェーンを使用して、ある辞書の単語から別の単語に移動できるかどうかを尋ねる多くの質問に答えることです。 

グラフの観点から見ると、各単語はノードであり、対応する文字列が少なくとも 1 つの文字を共有する場合、2 つのノード間に無向エッジが存在します。 各クエリは、2 つのノードがこのグラフの同じ接続コンポーネント内にあるかどうかを尋ねます。 

制約は大きく、最大 200,000 ワードと 200,000 クエリ、合計文字列長は最大約 1,000 万文字です。 これにより、単語のペアに対する二次構造が即座に除外されます。 共有文字のすべてのペアをチェックするだけでも、約$N^2$実行可能な限界をはるかに超えた最悪の場合の操作。 許容できる唯一の解決策は、合計入力サイズが線形に近いものです。 

接続性が直接のオーバーラップだけでは推移的ではなく、オーバーラップの連鎖によって推移する場合、微妙なエッジ ケースが発生します。 たとえば、「ab」が「bc」に接続され、「bc」が「cd」に接続される場合、直接文字を共有していなくても、「ab」は「cd」に接続されます。 クエリごとに直接の重複のみをチェックする単純なソリューションでは、次のような入力では失敗します。```
ab bc cd
ab cd
```正しい出力は YES (LUA) ですが、直接チェックすると誤って「いいえ」となります。 

もう 1 つの重要なエッジ ケースは、文字によるマージです。 構造的に無関係に見える単語であっても、中間単語を介して何らかの文字を共有している場合は同じコンポーネントに属する可能性があるため、グループ化はクエリローカルではなく辞書全体にわたってグローバルである必要があります。 

## アプローチ

 ブルート フォースの解釈は簡単です。単語の各ペアが少なくとも 1 つの文字を共有する場合に接続されるグラフを作成し、このグラフに対してグラフ トラバーサルまたはユニオン検索を実行します。 突然変異ルールを直接エンコードしているため、その正しさは明らかです。 問題は、すべてのエッジを構築するには単語のすべてのペアを比較する必要があり、各比較自体で最大 50 文字のスキャンが必要になる場合があることです。 それはおおよそ次のことにつながります$O(N^2 \cdot 50)$、200,000単語ではまったく不可能です。 

重要な観察は、エッジは実際には任意のペア間で定義されるのではなく、文字によって媒介されるということです。 単語は、接続性を確保するための完全な文字列としてではなく、一連の文字として重要です。 2 つの単語が同じ文字を共有する場合、それらは同じ連結要素内にある必要があります。 これは中間層、つまり文字そのものを導入することを示唆しています。 各文字は、それを含むすべての単語を接続するハブのような役割を果たします。 単語と単語を直接接続するのではなく、単語と文字、文字と単語を接続します。 これにより、グラフが密なワード グラフから 26 個の補助ノードのみを含む 2 部構造に縮小されます。 

次に、素の集合結合構造を使用して単語と文字を結合します。 それぞれの単語は、そこに含まれるすべての文字と結びついています。 この前処理の後、2 つの単語はその文字ノードを介して同じ DSU コンポーネントに属するため、文字を共有する場合にのみ接続されます。

 ## アルゴリズムのチュートリアル

 単語と文字の両方を、単一の素集合結合構造内でモデル化します。 単語には 0 から N-1 までのインデックスが付けられ、文字には追加のノードとしてインデックスが付けられます。 

1. N + 26 ノードで DSU を初期化します。最初の N は単語を表し、最後の 26 は文字を表します。 
2. 各単語について、その文字をスキャンし、その単語のノードと、その単語に含まれる各文字に対応するノードを結合します。 これにより、少なくとも 1 つの文字を共有するすべての単語の間にブリッジが作成されます。これらの単語はすべて同じ文字ノードに関連付けられるためです。 
3. 前処理の後、各クエリは 2 つの単語インデックスが同じ DSU コンポーネントに属しているかどうかを尋ねます。 
4. 各クエリについて、2 つの単語が同じ DSU ルートを持つ場合は「LUA」を出力し、そうでない場合は「RYEI」を出力します。 

重要な設計上の選択は、文字を共有コネクタとして扱うことです。 これにより、単語間のエッジを明示的に構築することがなくなります。 

### なぜ効果があるのか

 各文字は、それを含むすべての単語の代表ハブとして機能します。 単語が文字と結合すると、その文字の構成要素の一部になります。 2 つの単語が 1 つの文字を共有する場合、それらは両方とも同じ文字ノードに結合され、したがって同じ接続コンポーネントになります。 DSU は推移的であるため、共有文字のチェーンは自動的に単一のコンポーネントにマージされます。 これは、ミューテーション グラフの到達可能性の定義と正確に一致するため、接続クエリは DSU メンバーシップ チェックに減ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra = self.find(a)
        rb = self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

n, q = map(int, input().split())
words = [input().strip() for _ in range(n)]

dsu = DSU(n + 26)

def letter_id(c):
    return n + (ord(c) - ord('a'))

for i, w in enumerate(words):
    for c in set(w):
        dsu.union(i, letter_id(c))

for _ in range(q):
    a, b = input().split()
    ia = words.index(a)
    ib = words.index(b)
    if dsu.find(ia) == dsu.find(ib):
        print("LUA")
    else:
        print("RYEI")
```DSU 構造には、サイズによるパス圧縮と結合が標準装備されており、ほぼ一定の償却操作が保証されます。 文字マッピングは文字をインデックス範囲 [N, N+25] にシフトし、文字が単語と同じ結合検索構造内に共存できるようにします。 

この単純なバージョンの微妙な問題の 1 つは、`words.index(a)`クエリ内では、クエリごとに線形であり、最大の制約で TLE になります。 運用ソリューションでは、O(1) ルックアップを保証するために、単語文字列をインデックスにマッピングする辞書を 1 回構築する必要があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    class DSU:
        def __init__(self, n):
            self.p = list(range(n))
            self.sz = [1]*n
        def f(self,x):
            while self.p[x]!=x:
                self.p[x]=self.p[self.p[x]]
                x=self.p[x]
            return x
        def u(self,a,b):
            a,b=self.f(a),self.f(b)
            if a==b:return
            if self.sz[a]<self.sz[b]:
                a,b=b,a
            self.p[b]=a
            self.sz[a]+=self.sz[b]

    n,q=map(int,input().split())
    w=[input().strip() for _ in range(n)]
    mp={s:i for i,s in enumerate(w)}
    dsu=DSU(n+26)

    def lid(c): return n+ord(c)-97

    for i,s in enumerate(w):
        for c in set(s):
            dsu.u(i,lid(c))

    out=[]
    for _ in range(q):
        a,b=input().split()
        out.append("LUA" if dsu.f(mp[a])==dsu.f(mp[b]) else "RYEI")
    return "\n".join(out)

 ## 特殊なケース

 素朴な考えを打ち破るケースの 1 つは、接続が複数の中間語を介して間接的に行われる場合です。 考慮する`ab -> bc -> cd`。 DSU 構造は、共有レター ノード b および c を介して 3 つすべてを接続します。 加工時`ab cd`の場合、両方が同じ共用体コンポーネントに吸収されているため、検索操作は同じ代表を返します。 これは、マルチホップ接続が明示的なグラフ走査なしで自然に処理されることを確認します。 

もう 1 つのケースは、複数の文字を共有する単語です。 「abc」のような単語は 3 文字すべてと結合されている必要がありますが、別の単語がそれらの 1 つだけを共有している場合でも、接続性は正しく伝播されます。 DSU は、どの文字が最初に使用されるかには依存しません。 すべての文字が重複する単語に属している場合は同じコンポーネントに収束するため、結合の順序は正確さに影響しません。
