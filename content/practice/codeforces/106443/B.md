 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの整数シーケンスが与えられます。 1 つのシーケンスはドレックスに属し、もう 1 つはボスに属します。 インタラクションが発生する前に、ドレックスは自分のシーケンスを自由に並べ替えることができます。 After that arrangement is fixed, the two sequences are aligned index by index, and the total damage is computed as the sum of absolute differences between paired elements.

 課題は、この合計ができるだけ小さくなるように Drex のシーケンスの順序を選択することです。 

重要な構造上の詳細は、Drex の配列のみが並べ替え可能であるということです。 ボスの配列は固定されているため、問題は基本的に 2 つのマルチセットの要素を最適な方法で組み合わせることにあります。 

n が 2 × 10^5 までの制約により、二次ペアリング戦略は即座に除外されます。 Any solution that tries all matchings or even greedily tries local swaps without structure will fail in worst cases because the number of possible permutations grows factorially.

 一般的な障害モードは、等しいインデックスをペアにするか、単純な貪欲スキャンを実行するだけで十分であると想定した場合に発生します。 たとえば、ドレックスが`[10, 1, 100]`そして上司は`[2, 50, 60]`、元の順序でペアリングすると大きなコストがかかり、洞察をソートせずにローカルでスワップすると、依然としてグローバルに最適なペアリングを見逃す可能性があります。 

もう 1 つの微妙なエッジ ケースは、値が大きく偏っている場合です。グローバルな順序付けを行わずに、常に最も近い残りの値と一致する素朴な貪欲性は、最適ではない初期の選択に陥る可能性があります。 たとえば、ドレックス`[1, 100, 101]`そして上司`[2, 3, 200]`ローカルで最適なペアリングの決定ではなく、グローバルに一貫した順序付けが必要です。 

これらの問題は、問題がローカルな一致に関するものではなく、ソートされた構造のグローバルな位置合わせに関するものであることを示唆しています。 

## アプローチ

 ブルートフォースのアイデアは簡単です。Drex の配列のすべての順列を試し、結果として得られるボス配列との絶対差の合計を計算し、最小値を取得します。 これは、順列によって引き起こされるすべての可能なペアリングを明示的に評価するため、正しいです。 ただし、順列の数は n! であり、各評価のコストは O(n) であるため、O(n · n!) 回の演算が行われ、n が 10 程度の場合でも実行不可能になります。 

これを改善するために、ボスの配列が固定されていることを確認し、Drex の値が位置に割り当てられる方法のみを制御します。 絶対値コストは幾何学的解釈を示唆しています。つまり、1 次元で最小 L1 マッチング コストを使用して、数直線上の 2 つの点セットをマッチングしようとしています。 

1 つの次元では、絶対差の合計を最小化するための最適な戦略は、並べ替えられた要素と並べ替えられた要素をペアにすることです。 これが機能するのは、ペアリングの反転が改善可能であることが示されているためです。ソートされた順序で 2 つのペアが交差している場合、それらを交換してもコストが増加することはなく、多くの場合コストが減少します。 これは、回線上で最適なマッチングを行うための古典的な交換引数です。 

したがって、置換を試みる代わりに、両方の配列をソートし、要素 i を要素 i と照合します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n・n!) | O(n) | 遅すぎる |
 | 最適 (並べ替え + ペアリング) | O(n log n) | O(1) または O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、両方のシーケンスが一貫して順序付けされている場合にペアリングが最適になるという事実に依存しています。 

### ステップ

 1. 両方の配列のサイズである n を読み取ります。 
2. ドレックスの配列とボスの配列を読み取ります。 
3. 両方の配列を非降順で並べ替えます。 

並べ替えでは、小さい値が小さい値と整列し、大きい値が大きい値と整列するようにグローバル構造が適用されます。 
4. 合計ダメージのアキュムレータをゼロとして初期化します。 
5. i を 0 から n − 1 まで繰り返します。 
6. 各インデックス i について、i 番目に小さい Drex 値と i 番目に小さい Boss 値の間の絶対差を加算します。 
7. 累計を出力します。 

重要な決定はステップ 3 です。両方の配列をソートしないと、貪欲なペアリングはローカルな決定がグローバルな最適性を反映しない空間で動作します。 並べ替えると、問題は単調なマッチング問題に変わります。 

### なぜ効果があるのか

 ソート後、両方のシーケンスが同じ軸上に並べられます。 Drex[i] が Boss[j] とペアになっており、Drex[j] が Boss[i] とペアになっているようなインデックス i < j のペアが存在する場合、これらのペアを交換しても総コストを増やすことはできません。 これは、直線上の絶対値距離が、マッチングで交差するエッジを全長を悪化させることなく常に交差解除できるという性質を満たすためです。 この引数を繰り返し適用すると、ペア間のすべての反転が削除され、最適な解決策としてソートされた配列に同一ペアリングが強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    d = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    d.sort()
    b.sort()
    
    ans = 0
    for i in range(n):
        ans += abs(d[i] - b[i])
    
    print(ans)

if __name__ == "__main__":
    solve()
```ソートの原則を理解すれば、実装は直接的になります。 主な微妙な点は、ペアにする前に両方の配列が独立してソートされていることを確認することです。 よくある間違いは、Drex の配列のみをソートしたり、完全なソートを行わずに部分的な位置合わせを試行したりすることです。これにより、正確さに必要な単調な構造が壊れます。 

n が大きくなる可能性があるため、累算には標準ループが使用されますが、値の大きさが最大 ​​2 × 10^14 に達する可能性があるため、Python の整数演算は潜在的な合計サイズを快適に処理します。 

## 実用的な例

 ### 例 1

 入力:```
n = 3
d = [3, 1, 2]
b = [3, 1, 2]
```ソートされた配列:

 | 私 | d[i] | b[i] | |d[i] - b[i]| |

 |---|------|------|--------------|

 | 0 | 1 | 1 | 0 |

 | 1 | 2 | 2 | 0 |

 | 2 | 3 | 3 | 0 |

 合計 = 0

 これは、両方のマルチセットが同一である理想的なケースを示しています。 並べ替えにより同一の値が完全に整列されるため、コストはゼロになります。 

### 例 2

 入力:```
n = 4
d = [10, 1, 100, 50]
b = [2, 3, 60, 80]
```ソートされた配列:

 d = [1、10、50、100]

 b = [2、3、60、80]

 | 私 | d[i] | b[i] | 差分 |
 | --- | --- | --- | --- |
 | 0 | 1 | 2 | 1 |
 | 1 | 10 | 3 | 7 |
 | 2 | 50 | 60 | 10 |
 | 3 | 100 | 80 | 20 |

 合計 = 38

 これは、グローバル ソートによって同様にスケーリングされた値間の安定したペアリングがどのように強制され、100 と 2 または 1 と 80 のペアなどの不一致を回避するかを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、両方の配列に同一のマルチセットが含まれているものの、順序が異なる場合です。 例えば：```
n = 5
d = [4, 1, 3, 2, 5]
b = [1, 2, 3, 4, 5]
```両方をソートすると同一の配列が得られ、アルゴリズムのコストはゼロになります。 ソートを行わずに単純に貪欲にすると、早い段階で 4 と 1 を組み合わせてしまい、最適な配置が回復されず、不必要なコストの蓄積につながる可能性があります。 

もう 1 つのケースは極端な拡散です。```
n = 3
d = [-100, 0, 100]
b = [-50, -49, 200]
```並べ替え後:

 d = [-100, 0, 100]

 b = [-50、-49、200]

 インデックス順にペアリングすると、次の結果が得られます。 

50 + 49 + 100 = 199

 代わりに、グローバルな順序付けを行わずに最も近い値をローカルで一致させようとすると、早い段階で 100 と -50 が誤ってペアになり、-100 が 200 とペアになったままになり、合計がはるかに大きくなる可能性があります。 ソートされたペアリングは、グローバルな単調整列を強制することでこれを回避し、最終的なマッチングで交差ペアリングが存在しないようにします。
