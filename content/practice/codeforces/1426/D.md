 ## 解決策
 ## 問題の理解

 ゼロ以外の整数のシーケンスが与えられ、隣接する要素間のどこにでも任意の整数を挿入できます。 目標は、挿入される要素をできる限り少なくしながら、最終的な配列の連続セグメントの合計が正確にゼロにならないようにシーケンスを変更することです。 

部分配列の合計が 0 であることは、接頭辞の合計を使用することで最も簡単に理解できます。 配列内の 2 つの位置のプレフィックスの合計が同じである場合、それらの間の要素の合計は 0 になります。 したがって、この問題は、新しい要素を挿入して配列を「壊す」ことが許可された後、左から右にスキャンするときにプレフィックスの合計値が繰り返されるのを防ぐことと同じです。 

制約$n \le 2 \cdot 10^5$線形または線形に近い解決策が必要であることを意味します。 すべてのサブ配列を明示的にチェックしたり、変更された配列に対してプレフィックスの合計を繰り返し再計算したりするアプローチでは、要素の挿入によって構造が動的に変更され、二次伝播が発生する可能性があるため、時間がかかりすぎます。 

複数の互いに素なセグメントが個別にゼロサム区間を作成する場合、微妙なエッジ ケースが発生します。 たとえば、次のような配列では、$[1, -1, 2, -2]$、 両方$[1, -1]$そして$[2, -2]$ゼロサムセグメントを形成します。 最初に発生したものだけを修正する単純な貪欲型では、グローバル プレフィックスの動作を正しく追跡しない限り、その後の競合を見逃す可能性があります。 

## アプローチ

 ブルートフォースのアイデアは、要素を挿入する可能なすべての方法をシミュレートし、結果の配列にゼロサムのサブセグメントがあるかどうかを確認することです。 「各ペア間に挿入するか挿入しない」に制限したとしても、依然として指数関数的な可能性が生じます。 候補配列を修正したとしても、それを検証するにはプレフィックス合計と線形のハッシュ セットが必要です。 ただし、構成の数は時間とともに指数関数的に増加するため、すべての挿入構成を調査することは不可能です。$n$。 

重要な観察は、ゼロサム部分配列が完全にプレフィックスサムの繰り返しによって決定されるということです。 配列をスキャンしている間、現在のプレフィックスの合計を維持します。 すでに見たプレフィックスの合計に達した場合、それは合計が 0 になる部分配列が存在することを意味します。 これを防ぐには、繰り返し後にプレフィックスの合計が「再び一意になる」ようにする必要があります。 

要素を挿入すると、プレフィックスの合計の連続性が効果的にリセットされます。 概念的には、各挿入により、プレフィックス合計履歴が独立した新しい「セグメント」が開始されます。 ある時点で分割すると、前後のプレフィックスの合計は比較されなくなります。 

したがって、問題は現在のセグメントのプレフィックス合計のセットを維持することに帰着します。 配列をトラバースするとき、現在のセグメント内でプレフィックスの合計が繰り返されるたびに、続行する前にセグメントを切り取る必要があります。これは 1 つの要素を挿入することに相当します。 カット後、プレフィックス合計の追跡をゼロから再開します。 

この貪欲なセグメンテーションが機能するのは、カットを遅らせると、将来の衝突が減少することなく、さらなる衝突の可能性が増加するだけであるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての挿入を試行) | 指数 | O(n) | 遅すぎる |
 | 最適 (貪欲なプレフィックス セットのリセット) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在のセグメントに見られる現在のプレフィックス合計と一連のプレフィックス合計を維持しながら、配列を左から右に処理します。 

1. プレフィックスの合計が 0 で、0 のみを含む空のセットから開始します。これは、要素が処理される前の空のプレフィックスを表します。 
2. 配列の各要素を反復処理し、それを現在のプレフィックス合計に追加します。 
3. 更新されたプレフィックス合計が現在のセグメントに存在しない場合は、それをセットに挿入して続行します。 
4. プレフィックスの合計がすでに確認されている場合は、現在のセグメント内に合計が 0 であるサブ配列が存在することを意味します。 これを解消するために、概念的には、現在の位置の前に数値を 1 つ挿入し、セグメントをリセットします。 
5. 答えを 1 つ増やし、セットをクリアし、プレフィックス合計を現在の値のみにリセットしてセグメントを再開し、それを新しいセットに挿入します。 
6. 配列の最後まで続けます。 

### なぜ効果があるのか

 不変条件は、各アクティブ セグメント内では、すべてのプレフィックスの合計が異なるということです。 セグメント内の繰り返しは、そのセグメントに完全に含まれるゼロ和部分配列に正確に対応します。 過去の値を修正することはできないため、このような競合を除去する唯一の方法はセグメントを切断することです。 カットごとに以前のすべてのプレフィックス履歴が削除されるため、競合するプレフィックス セットが今後も引き継がれることはありません。 最初の繰り返しで貪欲にカットすることで、必要以上のセグメントが作成されることがなくなります。これは、その後のカットでも同じ競合するプレフィックス ペアを分離する必要があるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    seen = set([0])
    prefix = 0
    cuts = 0

    for x in a:
        prefix += x
        if prefix in seen:
            cuts += 1
            seen = set([0])
            prefix = x
            seen.add(prefix)
        else:
            seen.add(prefix)

    print(cuts)

if __name__ == "__main__":
    solve()
```このソリューションは、現在のセグメントで見られる実行中のプレフィックス合計とプレフィックス合計のハッシュ セットを維持します。 リセット ステップが重要な操作です。繰り返しが発生すると、応答をインクリメントし、新しいセグメントの最初の要素として現在の要素から追跡を再開します。 これは、数字を挿入するとプレフィックスの連続性が事実上破壊されるという考えを反映しています。 

微妙な点は、リセット後、現在の要素を新しいセグメントの最初のプレフィックスとして扱うため、プレフィックスはゼロにリセットされず、正しく再初期化されることです。

 ## 特殊なケース

 重要なエッジ ケースは、ゼロサム セグメントが前のセグメントの境界で正確に終了する場合です。 たとえば、`[1, -1, 1, -1]`、プレフィックス合計は複数回繰り返され、繰り返されるたびに強制的にリセットされます。 

処理後のステップバイステップ`[1, -1]`、プレフィックスは 0 に戻り、カットがトリガーされます。 正しくリセットしないと、単純な実装ではセグメント間のプレフィックス履歴が誤ってマージされ、必要な挿入が過小評価されてしまいます。 

もう 1 つのエッジ ケースは、リセット直後の繰り返しです。`[1, -1, 1]`。 加工後`[1, -1]`、リセットしました。 最終処理時`1`、プレフィックスは 1 になり、これは新しいセグメントですでに有効であるため、追加のカットは必要ありません。 これにより、リセットによりプレフィックス履歴が完全に分離され、セグメント間の干渉が防止されることが確認されます。
