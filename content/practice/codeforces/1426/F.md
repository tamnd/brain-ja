 ## 解決策
 ## 問題の理解

 文字「a」、「b」、「c」、および特殊文字「?」で構成される文字列が与えられます。 それぞれ "？" は、「a」、「b」、または「c」のいずれかの文字に独立して置き換えることができます。 考えられるすべての置換を実行した後、結果として得られるすべての文字列にわたる部分シーケンス「abc」の合計数をカウントする必要があります。 部分シーケンスには連続した文字は必要ありませんが、相対的な順序を維持する必要があります。 

入力サイズでは、最大 200,000 文字の文字列を使用できます。これは、すべての文字列を明示的に生成するアルゴリズムを意味します。$3^k$「？」の組み合わせ 実行不可能になります。 「？」の一つでも 文字列の数が 3 倍になる可能性があるため、総当たりの列挙は完全に問題外です。 重要な課題は、考えられるすべての置換を個別に反復処理せずに考慮することですが、これには慎重な組み合わせ推論や動的プログラミングが必要です。 

明らかでないエッジ ケースには、疑問符のみを含む文字列、「a」、「b」、または「c」を含まない文字列、および「abc」の形成を妨げる位置に文字が出現する文字列が含まれます。 たとえば、文字列「???」 は 27 個の文字列を生成でき、正しい出力は分布に応じて 1×3 + 3×1 + … になります。これは、単純なカウントでは疑問符からの乗算の寄与を簡単に見逃す可能性があることを示しています。 

## アプローチ

 素朴なアプローチは、「?」を置き換えることによって得られるすべての文字列を生成することです。 "a"、"b"、または "c" を使用して、各文字列内の "abc" のサブシーケンスを数えます。 これは正しいですが、k 個の疑問符が存在するため、非現実的です。$3^k$文字列。 のために$k = 20$、これは超えます$3^{20} \approx 3.5 \times 10^9$、1秒プログラムの実現可能な限界をはるかに超えています。 

効率的な解決策につながる洞察は、文字列を左から右に処理する際に、「a」、「ab」、および「abc」で終わる部分シーケンスが形成される方法の数を実行カウントを維持することです。 「？」を扱います。 ワイルドカードとして 3 文字のいずれかを使用できます。 それぞれ "？" それぞれが 3 つのオプションを生成できるため、既存のサブシーケンスを 3 で乗算しますが、新しいサブシーケンスにも寄与します。 部分サブシーケンスの数を追跡し、以前のワイルドカードを考慮して 3 のべき乗でスケーリングすることにより、線形時間で答えを計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(3^k \cdot n)$|$O(n)$| 遅すぎる |
 | 動的プログラミング (部分列のカウント) |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 3 つのカウンターを初期化します。`a_count`、`ab_count`、`abc_count`これらは、これまでに形成されたタイプ「a」、「ab」、および「abc」のサブシーケンスの数を表します。 初期化する`power_of_three`から 1 まで。これは、前の疑問符を置き換える方法の数を表します。 
2. 各文字を反復処理します。`ch`文字列の中で。 
3. もし`ch`は「a」、増分します`a_count`による`power_of_three`。 これは、以前のワイルドカードの既存の組み合わせがこの「a」によって拡張できることを反映しています。 
4. もし`ch`は "b"、増分`ab_count`による`a_count`。 以前の各「a」はこの「b」とペアになって、部分的な「ab」サブシーケンスを形成できます。 
5. もし`ch`は「c」、増分します`abc_count`による`ab_count`。 前の各「ab」はこの「c」とペアになり、「abc」サブシーケンスを完成させることができます。 
6. もし`ch`「?」の場合は「a」「b」「c」のいずれかとして扱うことができます。 カウントを更新する前に、現在の値を保存します。`a_count`、`ab_count`、 そして`abc_count`一時変数に。 「a」、「b」、または「c」の選択による寄与に応じて各カウントを更新します。 

- 新しい`abc_count`= 3 × 古い`abc_count`+古い`ab_count`(「?」が「c」の場合の寄与)
 - 新しい`ab_count`= 3 × 古い`ab_count`+古い`a_count`(「?」が「b」の場合の寄与)
 - 新しい`a_count`= 3 × 古い`a_count`+ 3 乗 (「?」が「a」の場合の貢献度)
 - 現在の「?」の 3 つのオプションを考慮して、古いカウントに 3 を掛けます。 新しいサブシーケンスの寄与を追加します。 
7.「?」を処理した後、乗算します。`power_of_three`追加のワイルドカードを反映するために 3 ずつ増加します。 
8. 戻る`abc_count`モジュロ$10^9 + 7$文字列全体を処理した後。 

**機能する理由**: すべてのステップで、カウントには、以前のすべての文字とワイルドカード拡張で形成できるすべてのサブシーケンスが反映されます。 「?」ごとにカウントを乗算的に更新することにより、 さらに、新しいサブシーケンスへの寄与については、組み合わせの欠落や二重カウントがないことを保証します。 アルゴリズムは不変条件を維持します。`a_count`= これまでに「a」を選択する方法の数、`ab_count`= 「ab」を選択する方法の数、および`abc_count`= 「?」のすべての置換を考慮した、「abc」を選択する方法の数。 そこまで見られました。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n = int(input())
s = input().strip()

a_count = 0
ab_count = 0
abc_count = 0
power_of_three = 1  # 3^number_of_question_marks_so_far

for ch in s:
    if ch == 'a':
        a_count = (a_count + power_of_three) % MOD
    elif ch == 'b':
        ab_count = (ab_count + a_count) % MOD
    elif ch == 'c':
        abc_count = (abc_count + ab_count) % MOD
    elif ch == '?':
        new_abc = (3 * abc_count + ab_count) % MOD
        new_ab = (3 * ab_count + a_count) % MOD
        new_a = (3 * a_count + power_of_three) % MOD
        a_count, ab_count, abc_count = new_a, new_ab, new_abc
        power_of_three = (power_of_three * 3) % MOD

print(abc_count)
```このソリューションはカウンターを初期化し、文字列を 1 回反復処理して、文字とワイルドカードの規則に従ってカウントを更新します。 微妙な点は、「?」が発生した場合に、前のシーケンスに対して正しく 3 を乗算することにあります。 「?」が発生した場合、形成された新しいサブシーケンスの寄与を追加します。 「a」「b」「c」になります。
