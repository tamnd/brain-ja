 ## 解決策
 ## 問題の理解

 数値 1 を含む単一要素の配列から始めます。 2 つの操作が可能です。任意の要素を 1 ずつインクリメントするか、任意の要素を配列の末尾にコピーします。 目標金額が与えられると$n$、配列の合計を少なくとも求めるために必要な演算の最小数を決定する必要があります。$n$。 

入力は複数の独立したテスト ケースを与え、それぞれが独自のテスト ケースを指定します。$n$。 出力は、各テスト ケースの最小操作数です。 以来$n$と同じ大きさにすることができます$10^9$配列上ですべての操作を直接シミュレートすると、移動ごとに配列サイズが 2 倍になったり、数値が増加したりする可能性があり、何十億ものステップが必要となるため、非常に遅すぎます。 したがって、各配列要素を追跡する単純なアプローチは実行不可能です。 

注意すべきエッジケースには、非常に小さな値が含まれます。$n$、 のように$n = 1$。 この場合、初期配列の合計はすでに十分であるため、答えは 0 手になります。 別の微妙なシナリオが発生するのは、$n$コピーを繰り返すことで達成できる 2 のべき乗の合計をわずかに上回る値です。 2 倍にするだけの不用意な貪欲な戦略はオーバーシュートする可能性があるため、いつコピーから増分に切り替えるかを慎重に検討する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、配列を明示的にシミュレートし、各ステップで合計が最も速く増加すると思われる操作を選択します。 最初、配列には 1 つの要素があります。 移動するたびに要素が増加するか、要素が複製される可能性があります。 操作ごとに配列の合計を更新し、次の値に達するまで繰り返します。$n$。 これは原理的には正しいですが、大規模な場合には遅すぎます。$n$操作の数は最大で数千万回以上になる可能性があり、コピーにより配列の管理が飛躍的に増大するためです。 

重要な洞察は、最適な戦略は、最大の要素がターゲットに近づくまでは常にコピーを使用し、その後、目標に到達するまで増分を使用することであるということです。$n$その通り。 より正式には、最大の要素を次のように表すと、$x$配列の長さは次のようになります$k$、各コピー操作で追加される$x$合計すると、大きな要素の効果が効率的に倍増します。 2 倍化が効率的でなくなると (つまり、合計が近づきます)$n$)、最大の要素の増分に切り替えます。 これにより、問題は単純な計算に帰着します。つまり、コピー数はおよそ次のようになります。$\lceil \log_2(n) \rceil$、残りの差は増分でカバーできます。 

配列全体が必要ではなく、合計と最大の要素だけが必要であることを認識することで、戦略をさらに最適化できます。 これにより、問題は純粋な数値シミュレーションに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | O(n) | n が大きいと遅すぎます |
 | 最適 | O(log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列の合計を 1、演算数を 0、最大要素を 1 に初期化します。 
2. 合計が以下の場合$n$、コピーによって最大の要素を 2 倍にすることが有益かどうかを判断します。 具体的には、合計に最大の要素を加えた値が依然として以下の場合、$n$、コピーを実行します。最大の要素によって合計を増分し、操作カウンターを増分します。 
3. 最大の要素を追加するとオーバーシュートが発生する場合$n$、増分に切り替えます: 間の差を計算します。$n$そして現在の合計額。 増分ごとに合計に 1 が加算されるため、この差を操作カウンターに直接加算して終了します。 
4. 総操作数を出力します。 

機能する理由: このアルゴリズムは 2 つの不変条件を維持します。 まず、合計は常に、一連の最適な移動後の実際の配列の合計を表します。 第 2 に、潜在的な 2 倍化のために最大の要素が常に最大化され、すべてのコピー操作が合計の可能な限り最大の増加に寄与することが保証されます。 増分への切り替えは、さらに 2 倍にすることでオーバーシュートが発生するときに正確に行われます。$n$、合計が少なくとも以下に達することを保証します$n$最小限の移動回数で。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_moves(n):
    if n == 1:
        return 0
    sum_arr = 1
    largest = 1
    moves = 0
    while sum_arr < n:
        if sum_arr + largest <= n:
            sum_arr += largest
            moves += 1
            largest = max(largest, sum_arr - (sum_arr - largest))
        else:
            moves += n - sum_arr
            sum_arr = n
    return moves

t = int(input())
for _ in range(t):
    n = int(input())
    print(min_moves(n))
```コードはすべての入力を読み取り、各テスト ケースの最小手を計算します。 変数`sum_arr`現在の合計を追跡し、`largest`最大の要素を追跡してコピー ゲインを最大化します。`moves`操作をカウントします。 ループは、オーバーシュートしない場合はコピーを実行し、オーバーシュートしない場合は増分に切り替えます。 

微妙な実装メモ: チェック`sum_arr + largest <= n`オーバーシュートを防ぎます。 エッジケースのような`n = 1`不要なループを避けるために個別に処理されます。 Python は大きな整数をネイティブに処理するため、オーバーフローの心配はありません。

 ## 特殊なケース

 のために$n = 1$、合計はすでに十分です。 アルゴリズムはすぐに 0 手を返します。 のために$n = 2$、最初のコピーまたは増分は合計 2 を生成し、アルゴリズムが最小限のアクションを正しく選択していることを示しています。 いつ$n$が 5 や 9 などの 2 のべき乗の合計をわずかに上回る場合、アルゴリズムはオーバーシュートが差し迫っているまでコピーを使用し、その後増分に切り替えて最小限の移動数を確保します。 これらのケースは、コピーによる 2 倍化と最後に正確なインクリメントを組み合わせるロジックが適切であることを裏付けています。
