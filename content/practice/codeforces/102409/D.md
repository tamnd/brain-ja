 ## 解決策
 ## 問題の理解

 1 から (N) までの番号が付けられたチケットが、円上に昇順に配置されています。 ディエゴはチケット(S)からスタート。 現在のチケットから、プロセスは、残っているチケットを正確に (K) 個右に移動し、チケットが到達した場所から削除します。 削除すると、現在のチケットはそのすぐ左側にある残りのチケットになります。 円は一周するため、チケット (N) を超えて移動すると、チケット 1 に進みます。 

タスクは、最後に残った唯一のチケットの ID を特定することです。 問題は、現在位置と目的地の間のチケットがすでに削除されている可能性があるため、移動は元の ID ではなく、現在残っているシーケンス上で行われることです。 

(N) の値は (10^{18}) まで大きくなる可能性がありますが、テスト ケースは (10^5) 個存在する可能性があります。 その規模では、チケットを単一の直線で通過することさえ不可能であり、ましてやサークルを明示的に維持することは不可能です。 (K\le 10) が重要な構造上の制限であるという事実。 コストが (K) に依存し、対数的に (N) にのみ依存するアルゴリズムを使用することはできますが、(O(N))、(O(NK))、または (O(N^2)) メソッドは直ちに除外されます。 

よくあるモデリングの間違いを明らかにするいくつかの特殊なケースがあります。 たとえば、(N=1) の場合、削除するものがないため、入力 (1\ 1\ 1) は 1 を生成する必要があります。 サイズをチェックする前に 1 回の消去を実行するシミュレーションでは、空の円にアクセスできます。 

(K=1) の場合も特殊です。 入力 (5\ 3\ 1) の場合、プロセスは 4、次に 5、次に 1、次に 2 を削除するため、チケット 3 が残ります。 したがって、(K=1) の場合、答えは常に最初のチケット (S) になります。 先行チケット自体がすでに削除されているため、削除されたチケットの直前のチケットがまだ生きているという仮定の下で導出された式はここで破綻します。 

ラップアラウンドは、off-by-one エラーのもう 1 つの原因です。 入力 (2\ 1\ 2) の場合、チケット 1 から 2 つのチケットを移動すると、チケット 1 に戻ります。そのため、チケット 1 が削除され、チケット 2 が勝ちます。 正しい出力は 2 です。(K) を通常の ID の違いとして扱うと、これを完全に見逃してしまいます。 

最後に、削除されたチケットは移動時にカウントされません。 入力 (4\ 1\ 2) の場合、チケット 3 が最初に削除されます。 次の移動はチケット 2 から始まり、チケット 4 と 1 を経て移動するため、次にチケット 1 が削除されます。 残りのチケットは 2 と 4 で、次にチケット 4 が削除され、チケット 2 が残ります。答えは 2 です。以前の ID に (K) を追加するだけの不注意な実装では、もう存在しないチケットに関する情報が使用されてしまいます。 

## アプローチ

 直接的なアプローチは、残っているチケット ID を循環リストに保持することです。 各ラウンドで、右側のチケット (K) 位置を見つけて削除し、現在のポインターを前のポインターに移動します。 これはプロセスに正確に従っているため、その正しさは簡単です。 

残念ながら、リストのサイズは初期状態では (N) です。 (N-1) 個の削除があり、宛先を見つけるのにかかるコストは (O(K)) のみですが、通常の配列からの削除には要素をシフトする必要があるため (O(N)) のコストがかかる可能性があります。 これにより、最悪の場合は (O(N^2)) 個の作業が行われ、(N=10^{18}) の場合は約 (10^{36}) 個の基本演算が行われます。 リンクされたリストはシフトを回避しますが、次のチケットを見つけるには、除去ごとに最大 (K) 個の生き残ったノードを追跡する必要があり、(O(NK)) が与えられ、それでも約 (10^{19}) 個の操作に達する可能性があります。 

有益な観察は、(K) が小さいということです。 すべての消去を実行する代わりに、多くの消去を同時に実行し、残りの円をまったく同じ問題のより小さなインスタンスに変えることができます。 

0 と (K\ge2) の相対的な開始位置については、(N>K) 個のチケットの円を考慮します。 最初に除外されたチケットは位置 (K) です。 削除後の新しい現在位置は (K-1) ですが、(K\ge2) であるためまだ生きています。 別の (K) の生き残ったチケットを移動すると (2K) に着地します。 同じ議論が続くので、最初の

[
 m=\left\lfloor\frac{N-1}{K}\right\rloor
 ]

 エリミネーションはまさにポジションです

 [
 K、2K、3K、\ldots、mK。 
]

 したがって、(m) 枚のチケットを一度に削除し、(N-m) 枚のチケットを残しました。 新しい現在のチケットは (mK-1) です。 その時点から、残りのプロセスは再び元の問題になります。小さな円上で、その位置の物理的なラベルが異なります。 

これは、ジョセフス問題の標準 (O(K\log N)) 最適化の背後にある同じバッチ削除原理ですが、この問題の先行ルールにより、マッピングが元の円に戻ります。 

ゼロベースの位置を使用し、最初の現在のチケットが位置 0 であると仮定して、(F(N,K)) を勝ち位置とします。バッチ削除後、次のように定義します。 

[
 m=\left\lfloor\frac{N-1}{K}\right\rfloor,\qquad
 Q=N-m。 
]

 (r=F(Q,K)) を再帰的に計算します。 元のサークルの新しい現在のチケットは次のとおりです。 

[
 P=mK-1。 
]

 (P) の後、残っているチケットはまず (mK+1,mK+2,\ldots,N) と続きます。 しましょう

 [
 R=N-mK
 ]

 この最後の部分ブロックの長さになります。 ラップアラウンドすると、残ったチケットは (K-1) のブロックで発生します。 

[
 1、\ldots、K-1、\quad K+1、\ldots、2K-1、\quad\ldots
 ]

 (K) の倍数がすべて削除されたためです。 

再帰的な答えが (r=0) の場合、それは (P) 自体を指します。 それ以外の場合は、(u=r-1) を設定します。 (u<R) の場合、答えは (P) の後の部分ブロックにあります。 

[
 mK+1+u。 
]

 それ以外の場合は、その部分ブロックをスキップした後、(v=u-R) とします。 対応する元の位置は

 [
 \左\lf階\frac{v}{K-1}\右\r階K
 +
 (v\bmod(K-1))+1。 
]

 再帰呼び出しごとに、(N) が約 (N(1-1/K)) に減ります。 したがって、再帰の深さは (O(K\log N)) になります。 (K\le10) なので、これは (N=10^{18}) の場合でも小さいです。

 ## アルゴリズムのチュートリアル

 1. ゼロベースの位置を操作し、最初の現在のチケットが位置 0 であるときの勝ち位置として (F(N,K)) を定義します。実際の開始チケット (S) は最終循環シフトとして適用されます。 
2. (K=1) の場合、0 を返します。1 つのチケットを移動すると、常に後続のチケットが削除され、新しい現在のチケットが開始時のチケットとなるため、最初のチケットは残ります。 
3. (N\le K) の場合、プロセスを直接シミュレートします。 この場合、チケットは最大 10 枚なので、一定の作業量だけがかかります。 
4. (N>K) および (K\ge2) について、計算します。 

[
 m=\left\lfloor\frac{N-1}{K}\right\r フロア。 
]

 最初 (m) 個の除外されたチケットは (K,2K,\ldots,mK) です。 最後のチケットの後の現在のチケットは (mK-1) です。 
5. それらの (m 個の) チケットを概念的に削除し、定義します

 [
 Q=N-m。 
]

 新しい現在のチケットから見た残りのプロセスは、(Q) チケットの場合と同じ問題です。 (r=F(Q,K)) を再帰的に計算します。 
6. 円が折り返される前に残っている部分ブロックの長さを計算します。 

[
 R=N-mK。 
]

 (r=0) の場合、再帰的な勝者は新しい現在のチケット (mK-1) です。 
7. (r>0) の場合、(u=r-1) を設定します。 (u<R) の場合、勝者はまだ (mK-1) 後の部分ブロック内にあるため、元の位置は (mK+1+u) の縮小法 (N) になります。 
8. (u\ge R) の場合、部分ブロックを減算し、(v=u-R) を設定します。 残りのチケットは、(K) の 1 つの削除された倍数で区切られた (K-1) のグループとして表示されます。 したがって、本来の位置は、

 [
 \左\lf階\frac{v}{K-1}\右\r階K
 +(v\bmod(K-1))+1。 
]
 9. 再帰的に計算された基本ケースから開始して、元の (N) が復元されるまでこれらのマッピングを逆の順序で適用します。 結果の値は (F(N,K)) です。 
10. 最後に、実際の開始チケットによって相対的な勝者を移動します。 (F) がゼロベースの場合、答えは次のようになります。 

[
 ((S-1+F)\bmod N)+1。 
]

 ### なぜ効果があるのか

不変条件は、(F(N,K)) がチケット 1 を基準とするのではなく、常に現在のチケットを基準にして勝者を表すことです。 (N>K) および (K\ge2) の場合、最初の (m) 個の除外は正確に (K) の倍数であり、それらの除外後の現在のチケットは (mK-1) です。 残りのチケットは循環順序を保持するため、ゲームの残りの部分は、その新しい現在のチケットから見た場合、正確に (F(N-m,K)) インスタンスになります。 マッピング式は残りのチケットを正確な循環順序で列挙するため、勝者を変更せずに再帰的な相対位置を元の位置に変換します。 基本シミュレーションは正確で、大きなインスタンスはすべて 1 つの小さな有効なインスタンスに縮小され、最終的な位置が真の生存者であることが証明されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def relative_winner(n, k):
    if k == 1:
        return 0

    frames = []

    while n > k:
        m = (n - 1) // k
        tail = n - m * k
        frames.append((n, m, tail))
        n -= m

    # n <= k, so direct simulation is tiny.
    circle = list(range(n))
    cur = 0

    while len(circle) > 1:
        size = len(circle)
        target = (cur + k) % size
        circle.pop(target)

        size -= 1
        cur = (target - 1) % size

    winner = circle[0]

    # Restore the positions removed by the batch steps.
    for n, m, tail in reversed(frames):
        if winner == 0:
            winner = m * k - 1
            continue

        u = winner - 1

        if u < tail:
            winner = (m * k + 1 + u) % n
        else:
            v = u - tail
            winner = (v // (k - 1)) * k + (v % (k - 1)) + 1

    return winner

def solve(reader=input):
    t = int(reader())
    out = []

    for _ in range(t):
        n, s, k = map(int, reader().split())
        f = relative_winner(n, k)
        answer = (s - 1 + f) % n + 1
        out.append(str(answer))

    return "\n".join(out)

if __name__ == "__main__":
    sys.stdout.write(solve())
```の`relative_winner`この関数は、実際の開始チケットを再帰計算から意図的に分離します。 関数内では、位置 0 は常に現在のチケットを意味し、すべての削減が (S) の元の値から独立したものになります。 

(K=1) の場合、開始チケットに関する答えはすぐにゼロになります。 この特別なケースが必要なのは、削除されたチケットの先行チケットがすでに消失している可能性があるため、(K\ge2) のバッチ引数は適用されないためです。 

より大きい (N) 場合、各フレームには 1 つの縮小を再構築するために必要な情報が格納されます。 数量`m`はバッチ内で除去される (K) の倍数です。`tail`からの残っているチケットの数です。`m * k + 1`(N)を通して。 

残りの小さなインスタンスは、Python リストを使用してシミュレートされます。 シミュレーションで使用するのは、`target = (cur + k) % size`ルールでは、現在のチケットを最初の動きとしてカウントするのではなく、残っているチケットを移動 (K) するように定められているためです。 取り外し後、`(target - 1) % size`生き残った前任者を選択します。 Python のモジュロ動作はここで役立ちます。`-1 % size`最後のインデックスを正しく提供します。 

復興の中で、`winner == 0`再帰的な勝者がまさに新しい現在のチケットであることを意味します。`m * k - 1`。 さもないと、`winner - 1`現在のチケットの後のシーケンスのどこまで再帰的勝者が存在するかをカウントします。 最初`tail`位置は部分ブロックを形成し、それ以降のすべては (K) の倍数ではない (K-1) 個のブロックに分割されます。 

Python の整数には任意の精度があるため、(10^{18}) までの値には特別なオーバーフロー処理は必要ありません。 この実装では再帰も回避され、呼び出しスタックが一定に保たれ、(O(K\log N)) の削減が明示的に行われます。

## テストケース```python
import sys
import io

def relative_winner(n, k):
    if k == 1:
        return 0

    frames = []

    while n > k:
        m = (n - 1) // k
        tail = n - m * k
        frames.append((n, m, tail))
        n -= m

    circle = list(range(n))
    cur = 0

    while len(circle) > 1:
        size = len(circle)
        target = (cur + k) % size
        circle.pop(target)

        size -= 1
        cur = (target - 1) % size

    winner = circle[0]

    for n, m, tail in reversed(frames):
        if winner == 0:
            winner = m * k - 1
        else:
            u = winner - 1

            if u < tail:
                winner = (m * k + 1 + u) % n
            else:
                v = u - tail
                winner = (v // (k - 1)) * k + (v % (k - 1)) + 1

    return winner

def solve(reader):
    t = int(reader())
    out = []

    for _ in range(t):
        n, s, k = map(int, reader().split())
        f = relative_winner(n, k)
        out.append(str((s - 1 + f) % n + 1))

    return "\n".join(out)

def run(inp: str) -> str:
    return solve(io.StringIO(inp).readline) + "\n"

# Minimum-size input

# Off-by-one case involving deleted tickets

 ## 特殊なケース

 (N=1) の場合、入力`1 1 10`すぐに 1 つの要素による小円シミュレーションに入ります。 削除は実行されないため、位置 0 が返され、チケット 1 に変換されます。アルゴリズムは、空のリスト内の先行要素を計算しようとすることはありません。 

(K=1) の場合、次のように考えます。`5 3 1`。 チケット 3 から、チケット 4 が削除され、次にチケット 5、次にチケット 1、次にチケット 2 が削除されます。チケット 3 は残ります。 アルゴリズムは (N) ごとに相対位置 0 を返し、最後のシフトによりそれが (S=3) に直接変換されます。 これにより、先行する仮定が偽である場合に (K\ge2) バッチ式を適用することが回避されます。 

現在のチケットに正確に戻る移動については、次のことを考慮してください。`2 1 2`。 チケット 1 に対して、残っている 2 つのチケットを移動すると、再びチケット 1 に到達するため、チケット 1 は削除されます。 チケット 2 が唯一残っているチケットであり、勝ちです。 基本シミュレーションはターゲットインデックスを計算します`(0+2)%2=0`、それを削除し、相対的な勝者 1 を残します。最終的な答えは 2 です。 

削除されたチケットによって距離の意味が変わる場合は、次のことを考慮してください。`4 1 2`。 チケット 3 が最初に削除されます。 次に現在のチケットは 2 で、2 つの生き残ったチケットを移動すると、生き残ったシーケンスは 2、4、1 であるため、チケット 4 ではなくチケット 1 に到達します。このアルゴリズムは、元の ID の違いを使用して移動を表すことはありません。 そのバッチ削減では、最初に (K) の倍数を明示的に削除し、次に圧縮された生き残ったシーケンスを通じて位置をマップします。 

(N=S=K=5) の場合、入力`5 5 5`チケット 5 から始まります。残っている 5 枚のチケットの最初の手がチケット 5 に戻るため、削除されます。 次に、残りの 4 つのチケットについてプロセスが続行され、最終的にチケット 1 が残ります。小さな円のシミュレーションでは、(N\le K) であるため、これを直接処理し、最初のバッチに (K) の完全な倍数が少なくとも 1 つ含まれているという仮定を回避します。 

最大値 (N=10^{18}) の場合、入力`1000000000000000000 1000000000000000000 1`これは (K=1) ショートカットによって処理され、開始チケットをすぐに返します。 より一般的には、リダクションでは、(10^{18}) の小さい倍数で囲まれた値に対する整数の除算、乗算、加算、および剰余のみが使用され、Python はこれらすべてをオーバーフローすることなく正確に処理します。
