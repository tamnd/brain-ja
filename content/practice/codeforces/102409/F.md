 ## 解決策
 ## 問題の理解

 文字がすでに ASCII 値によってソートされている単語が与えられています。 すべての文字を ASCII コードで置き換え、(N) 個の正の整数の配列を取得します。 

暗号化は、この配列のすべての可能なサブセットを取得し、選択された要素の合計を記録することで構成されます。 空のサブセットは (0) に寄与します。 正確に (2^N) 個のサブセットがあるため、出力には正確に (2^N) 個の整数が含まれ、非降順でソートされます。 

たとえば、この単語については、`ab`、ASCII 値は (97,98) です。 そのサブセットは、空のサブセット、各単一文字、および両方の文字の集合です。 それらの合計は (0,97,98,195) であるため、暗号化された出力は次のようになります。`0 97 98 195`。 

制約 (N \le 20) は十分に小さいため、(2^N) は管理可能です。 最大では (2^{20}=1,048,576) となるため、出力自体にはすでに 100 万を超える数値が含まれています。 これにより、有用な下限が得られます。受け入れられたアルゴリズムは、答えを生成するためだけに少なくとも (O(2^N)) 時間を費やす必要があります。 (O(N2^N)) アルゴリズムは、上限で出力サイズの約 20 倍の作業を実行しますが、(O(2^N \log 2^N)) の並べ替えアプローチは、大幅に多くの作業を実行します。 したがって、目標は、すべてのサブセットの合計を (O(2^N)) 時間で構築することです。 

直接的な実装では間違いが明らかになる可能性のあるエッジケースがいくつかあります。 1 つの文字で、たとえば```
1
a
```サブセットの合計は (0) と (97) だけであるため、出力は次のようになります。```
0 97
```よくある間違いは、空ではないサブセットのみを生成することです。これにより、最初のゼロが誤って省略されてしまいます。 

重複する文字値も重要です。 のために```
2
aa
```どちらの文字も値 (97) を持ちます。 4 つのサブセットは (0,97,97,194) を生成するため、正しい出力は次のようになります。```
0 97 97 194
```2 つの等しい (97) 値は、異なるサブセットに対応するため、両方とも出力に残る必要があります。 合計を重複排除すると、間違った結果が生成されます。 

すでにソートされた入力は、すべてのサブセットの合計が異なることを意味するわけではありません。 たとえば、この言葉は、`ab`は異なる値を持ちますが、より大きな配列では、異なる組み合わせでも同じ合計を生成できます。 アルゴリズムは、サブセットの合計をセットとして扱うのではなく、多重性を保持する必要があります。 

## アプローチ

 直接的なアプローチは、ビットマスクを使用してすべてのサブセットを列挙することです。 (0) から (2^N-1) までの各マスクについて、その (N) ビットを検査し、対応する配列値を追加します。 これにより、すべてのサブセットが 1 回だけ正しく生成されます。 次に、結果の (2^N) 合計を並べ替えることができます。 

問題は、サブセット生成における (N) 要素です。 最悪の場合、(2^{20}=1,048,576) 個のマスクがあり、各マスクではすべて (20) 個の位置を調べる必要がある場合があります。 これは、最終的な並べ替えの前に約 (20,971,520) 個の要素がチェックされることになります。 さらに 100 万個の整数をソートすると、おおよそ (2^{20}\log_2(2^{20}))、つまり約 2,000 万個の比較レベルが追加されます。 出力自体の要素が 100 万程度しかない場合、これは不要な作業です。 

便利な構造は、入力値がすでにソートされていることです。 より一般的には、最初の (k) 値を処理し、それらのすべてのサブセットの合計がソートされた順序ですでに得られていると仮定します。 新しい値 (x) を追加すると、古いサブセットはすべて 2 つの可能性を生成します。サブセットを変更せずに保持して (s) を与えるか、(x) を含めて (s+x) を与えるかです。 

古い合計が

 [
 s_1 \le s_2 \le \dots \le s_m、
 】

 (x) を加算して得られる新しい合計は次のようになります。 

[
 s_1+x \le s_2+x \le \dots \le s_m+x。 
】

 したがって、古い合計とシフトされた合計という 2 つの並べ替えられた配列ができます。 すべてを生成して後でソートするのではなく、線形時間内にそれらをマージできます。 

重要な観察は、単に最終的な分類を避けることよりもさらに強力です。 挿入するたびに、サブセット合計配列全体がソートされたままになります。 から始まる`[0]`、各新しい文字は既存のリストの 1 つのシフトされたコピーに寄与し、2 つのリストをマージできます。 リストのサイズはステップごとに 2 倍になるため、合計作業量は次のようになります。 

[

 】

 これは、出力の書き込みコストまでは最適です。

 ## アルゴリズムのチュートリアル

 1. (N) を読み取り、単語のすべての文字を ASCII 値に変換します。 単語は ASCII 値でソートされることが保証されているため、値はすでに減少していません。 
2. ソートされたリストから開始します`sums = [0]`。 これは、ゼロ要素を使用してすべてのサブセットの合計を表します。 この時点では空のサブセットが唯一のサブセットであるため、ゼロが完全で正しい初期状態です。 
3. 文字値を一度に 1 つずつ処理します。 現在ソートされたサブセットの合計が次のようになっていると仮定します。`sums`そして次の値は`x`。 
4. 以下を追加して、2 番目のソートされたシーケンスを構築します。`x`のあらゆる要素に`sums`。 もし`sums`がソートされると、すべての要素に同じ番号を追加すると順序が維持されるため、このシフトされたシーケンスもソートされます。 
5. オリジナルを結合する`sums`そしてシフトされたシーケンスは新しいソートされたリストに入れられます。 元のリストの各要素は、`x`、一方、シフトされた各要素は、使用する対応するサブセットを表します。`x`。 したがって、マージには、処理されたプレフィックスのすべてのサブセットが 1 回だけ含まれます。 
6. 交換する`sums`マージされたリストを使用して次の値に進みます。 (k) 文字を処理した後、`sums`正確に (2^k) 個の値が含まれています。 
7. すべての (N) 文字が処理された後、印刷します。`sums`。 その長さは (2^N) で、すべてのマージでソート順が保持されるため、出力はすでにソートされており、最終的なソート パスは必要ありません。 

### なぜ効果があるのか

 不変条件は、最初の (k) 文字を処理した後、`sums`これらの (k) 文字のすべてのサブセット合計が 1 回だけ含まれ、ソートされます。 

空のプレフィックスには、合計が 0 である空のサブセットというサブセットが 1 つだけあるため、最初は不変式が true になります。 新しい値 (x) が追加されると、すべての古いサブセットには 2 つの拡張子が含まれます。1 つは (x) を除外し、合計が同じで、もう 1 つは (x) を含み、合計が (x) だけ増加します。 元のリストにはすべての除外ケースが含まれ、シフトされたリストにはすべての包含ケースが含まれます。 これらのケースは互いに素であり、拡大されたプレフィックスのすべてのサブセットを一緒にカバーします。 

両方のリストはソートされているため、それらをマージすると、ソートされた順序で完全なコレクションが生成されます。 これは、不変式がすべての文字の後でも true のままであることを証明し、その結果、最終的なリストがまさに必要な暗号化メッセージであることがわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    word = input().strip()

    values = [ord(c) for c in word]

    sums = [0]

    for x in values:
        m = len(sums)
        shifted = [sums[i] + x for i in range(m)]

        merged = []
        i = 0
        j = 0

        while i < m and j < m:
            if sums[i] <= shifted[j]:
                merged.append(sums[i])
                i += 1
            else:
                merged.append(shifted[j])
                j += 1

        while i < m:
            merged.append(sums[i])
            i += 1

        while j < m:
            merged.append(shifted[j])
            j += 1

        sums = merged

    print(*sums)

if __name__ == "__main__":
    solve()
```の`ord(c)`呼び出しは、各文字をその ASCII 値に直接変換します。 Python には必要な数値コードがすでに用意されているため、大文字、小文字、または数字を手動で区別する必要はありません。 

リストには最初にのみ含まれています`0`、空のサブセットに対応します。 価値のために`x`、`shifted`以下を含むサブセットの合計が正確に含まれます。`x`。 オリジナル`sums`それを除外したサブセットの合計が含まれます。 

マージでは、`<=`それよりも`<`。 この選択は意図的なものです。 等しい合計は、それを生成するサブセットごとに 1 回発行する必要があります。 値が等しい場合にどちらかの側を選択しても、一度に 1 つのポインタだけが進むため、両方のコピーが保持されます。 

残った二人`while`ループはマージのまだ半分を追加します。 どちらかのループを省略すると、古典的なマージ実装エラーとなり、有効なサブセットの合計が失われます。 

Python の整数は、ここに関係する値ではオーバーフローしません。 許容される最大の文字は小文字であるため、可能な最大の合計でも最大 (20 \times 122) です。そのため、通常の整数演算で十分です。 

入力には 1 つの単語だけが含まれるため、テストケースのループはありません。 出力は次のように生成されます。`print(*sums)`、すべての (2^N) 整数をスペースで区切って書き込みます。

def brute_force(word: str) -> str:
    values = [ord(c) for c in word]
    n = len(values)

    result = []

    for mask in range(1 << n):
        total = 0
        for i in range(n):
            if mask & (1 << i):
                total += values[i]
        result.append(total)
