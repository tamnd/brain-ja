 ## 問題の理解

 各人のネットポジションがわかれば、元のローンは個別には問題になりません。 あらゆるローンについて`a b c`、 人`a`譲った`c`、一方、人`b`受け取りました`c`。 すべてのローンを合計したとき、個人の残高を、受け取るべきお金から支払うべきお金を差し引いたものと定義します。 プラスの残高はその金額を受け取らなければならないことを意味し、マイナスの残高はその絶対額を支払わなければならないことを意味し、ゼロの残高はその人がすでに決済されていることを意味します。 

たとえば、次の場合`0`貸した`1`5つのユニットと`1`後で貸しました`2`5 単位の場合、残高は次のとおりです。`0 = +5`、`1 = 0`、 そして`2 = -5`。 元の中間トランザクションは問題から消えます。`0`人から直接 5 単位を受け取るだけです`2`。 

出力は、すべての残高をゼロにする支払いの集合です。 最初の目的は、送金総額を最小限に抑えることです。 それが最適化されたら、2 番目の目標は支払い回数を最小限に抑えることです。 必要な出力形式は、支払回数の後に支払者、受取人、および金額が続くものです。 問題ステートメントは、元のローン グラフを結果の純残高に置き換えることができることを確認しています。 

最初の目的には簡単な特徴があります。 プラスの残高を合計すると、`P`。 残高がプラスのすべての人は、残高を正確に受け取る必要があるため、有効な決済は少なくとも送金されます。`P`単位。 正確に達成できます`P`マイナス残高の人のみがプラス残高の人に支払うことを許可することによって。 したがって、支払い回数の最適化を開始する前に、最低合計金額が固定されます。 

難しいのは2番目の目標です。 最大でも 18 名であり、これが重要な制約です。 多項式アルゴリズムは快適ですが、この問題には部分集合和のような選択肢が含まれています。つまり、人々のグループは、残高の合計がゼロになったときに正確に独立して決済できるということです。 このようなグループの最適なコレクションを見つけるのは一般に指数関数的であるため、`N <= 18`これにより、ビットマスク動的プログラムが実用的になります。 ローンの数は次のとおりです。`100000`、しかし、それらのローンは次のように積み立てられるだけです。`N`バランスが取れているため、その寄与は直線的になります。`K`。 

直接実装では誤って処理される可能性のあるエッジケースがいくつかあります。 

正反対のバランスを持つ 2 人の人物を考えてみましょう。```
2 1
1 0 1
```人`0`バランスがある`-1`そして人`1`バランスがある`+1`, したがって、支払いは次のとおりです。`0 1 1`。 元のローンの方向を維持する不用意な実装は、反対の方向を出力し、残高の決済に失敗します。 

ここで、多くのローンを利用したにもかかわらず、最終的に残高がゼロになった人のことを考えてみましょう。```
3 2
0 1 5
1 0 5
```すべての残高はゼロであるため、正しい出力は次のようになります。```
0
```ゼロバランスの人々を指数関数的 DP に維持しても正確さは変わりませんが、余分な人々ごとに状態空間が不必要に 2 倍になります。 多くのローンがキャンセルされる場合、DP の前にそれらを削除することは重要な最適化になります。 

より微妙なケースは、複数の独立したゼロサム グループが存在する場合です。 例えば、```
4 2
0 2 2
1 3 2
```バランスを与える`+2, +2, -2, -2`。 各ペア内で 1 回ずつ、2 回の支払いで十分です。 恣意的な債務者と債権者を繰り返し選択する貪欲な手順でも金銭を解決することはできますが、参加者が独立した構成要素に分割されるという事実を見落とす可能性があります。 2 番目の目的は、まさにそのような独立したコンポーネントをできるだけ多く見つけることです。 

最後に、同じペアが何度も発生する可能性があります。 入力```
2 100000
0 1 1
0 1 1
...
0 1 1
```繰り返しの行で`100000`時間はバランスを生み出す`-100000`そして`+100000`。 オリジナル`100000`ローンは集計後は無関係となり、決済の支払いは 1 回だけ必要になります。 正味残高の代わりにローンごとの状態を使用すると、問題を小さくする構造を完全に見逃してしまいます。 

## アプローチ

 ブルートフォース ソリューションでは、ゼロ以外の人々をグループに分割する可能性があるすべてを列挙できます。 各パーティションについて、すべてのグループの残高合計がゼロかどうかを確認します。 存在する場合、以下を含むグループ`s`人々はそれを使って定住することができます`s-1`したがって、支払いの合計数は、グループ数が最も多いパーティションによって最小化されます。 これは正しいです。なぜなら、決済のすべての連結要素は合計残高がゼロであり、ゼロサム グループが存在する必要があるからです。`s`人々はいつでも解決できる`s-1`支払い。 

問題はパーティションの数です。 18個のラベル付き要素の集合分割数は18番目のベル数となり、`682076806159`、 だいたい`6.82 * 10^11`。 すべてのパーティションについて一定量の情報をチェックするだけでも、1 秒の制限時間をはるかに超えています。 

ブルート フォースが機能するのは、独立したゼロサム グループを明示的に検索するためです。 情報の大部分が冗長である場合に完全なパーティションを検索するため、失敗します。 有益な観察は、グループの重要なプロパティはその残高合計がゼロかどうかだけであるということです。 これにより、人々のすべてのコレクションをビットマスクで表現し、すべての小さなマスクの結果を再利用できるようになります。 

マスク用`S`、 させて`sum[S]`その残高の合計になります。 定義する`dp[S]`内部で見つけることができるペアごとに互いに素なゼロ和サブセットの最大数として`S`。 これは最大のゼロサム サブパーティションであり、必ずしもすべてのパーティションである必要はありません。`S`。 

誰でも選んでください`x`で`S`。 もし`S`の合計はゼロにならないため、ゼロ和グループの最適な集合にすべての人を含めることはできません。`S`なぜなら、これらのグループを合わせると合計もゼロになるからです。 最適値を下げることなく、少なくとも 1 人を削除できます。 したがって、私たちは最善のものを得ることができます`dp[S without x]`あらゆる選択肢の上で`x`。 

もし`S`それ自体の合計はゼロになります。これは、最適なゼロサム分割です。`S`を含むいくつかのグループが含まれています`x`。 削除中`x`はそのグループを正確に破壊しますが、残りのグループはゼロサムのサブパーティションを形成します。`S without x`。 したがって、最適値は、1 つの要素を除去することによって得られるマスクの最良の結果よりも 1 つ大きくなります。 

これにより再発が得られます```
dp[S] = max dp[S without x]                         if sum[S] != 0
dp[S] = 1 + max dp[S without x]                    if sum[S] == 0
```全体`x`で`S`。 この再発は標準です`O(n 2^n)`最大ゼロサム分割の動的計画法定式化。 

ゼロ以外の残高の完全なセットは合計がゼロになるため、`dp[full]`は、まさに独立したゼロ和グループの最大数です。 あれば`m`ゼロではない人々と`g`グループ、各グループのサイズ`s`ニーズ`s-1`支払い。 グループを合計すると、```
(s1 - 1) + (s2 - 1) + ... + (sg - 1)
= m - g
```とても最大化しています`g`支払い回数を最小限に抑えることとまったく同じです。 

DP は最適なグループ数のみを提供します。 実際のグループを回復するには、バックトラックします。 残り1人を選ぶ`x`を含むサブマスクを列挙します`x`ゼロ和サブセットが見つかるまで`G`満足のいく```
dp[remaining without G] + 1 = dp[remaining]
```このようなサブセットは、DP の定義によって存在する必要があります。 一度`G`が見つかった場合は、削除して繰り返します。 

グループがわかったら、各グループを独立して解決できます。 1 つのグループ内で、債務者と債権者を 1 名ずつ選択し、残りの少ない方を繰り返し転送します。 支払いのたびに少なくとも 1 つはゼロになります。 グループが始まるので、`s`ゼロ以外の残高とすべての残高がゼロで終了します。正確に`s-1`支払いが発生します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(B_n * n)`|`O(n)`| 遅すぎる |
 | 最適 |`O(K + n 2^n)`|`O(2^n)`| 承認済み |

 ここ`B_n`は n 番目のベル番号ですが、最適な方法では`2^n`せいぜいマスクと検査だけ`n`マスクごとのトランジション。 

## アルゴリズムのチュートリアル

 1. すべてのローンを読み、純残高を蓄積します。 ローンの場合`a b c`、 追加`c`に`balance[a]`そして引きます`c`から`balance[b]`、 なぜなら`a`の間、返金を受け取る権利があります`b`借りがあります。 
2. 最終残高がゼロになった人をすべて削除します。 そのような人は必須の決済に参加せず、彼らを除外すると、答えを変えることなくビットマスクの次元が減少します。 
3. 残りの残高を長さの配列に格納します`m`。 元のローンはすべて、ある人から別の人にお金を移動させるため、すべての残高の合計はゼロになります。 
4. コンピューティング`sum[mask]`すべてのサブセットに対して。 最下位の設定ビットをから削除します`mask`、すでに計算された小さいマスクの合計を再利用し、対応するバランスを追加します。 これにより、すべてのサブセットの合計が計算されます。`O(2^m)`時間。 
5.初期化`dp[0] = 0`。 空ではないすべてのマスクについて、設定可能なビットをそれぞれ削除し、より小さいマスクから最良の結果を継承します。 現在のマスクの和がゼロの場合、現在のマスク自体が 1 つのゼロ和グループを形成できるため、候補に 1 を追加します。 
6.読む`dp[full]`独立したゼロ和グループの最大可能数として。 とのグループ以来、`s`人々はまさに必要としている`s-1`支払いの場合、最低支払い回数は`m - dp[full]`。 
7. グループを再構築します。 最も低い設定ビットを取得します`x`現在のマスクのサブマスクを列挙します。 サブマスクを見つける`G`含む`x`誰の合計がゼロになるのか、そして誰のために`dp[current without G] + 1`等しい`dp[current]`。 これにより、最適なパーティションで使用される 1 つのグループが識別されます。 
8. 削除する`G`現在のマスクを外し、人がいなくなるまで続けます。 再構築では、最大でも次のことを考慮します。`m`グループに分けられ、各再構築フェーズでは最大でも`2^m`サブマスクはまだ小さい`m <= 18`。 
9. 回収されたグループごとに、そのメンバーを、残高がマイナスの債務者と残高がプラスの債権者に分割します。 1 人の債務者と 1 人の債権者を照合し、絶対残高の小さい方を送金します。 
10. 支払いのたびに両方の残高を更新します。 債務者がゼロになった場合は、次の債務者に進みます。 債権者がゼロになった場合は、次の債権者に進みます。 反復ごとに少なくとも 1 つのポインターが進むため、サイズのグループが`s`正確に生成します`s-1`支払い。 

### なぜ効果があるのか

 重要な不変条件は次のとおりです`dp[mask]`から選択できる素のゼロ和グループの最大数に等しい`mask`。 もし`mask`はゼロサムではなく、すべてのゼロサム サブパーティションでは少なくとも 1 人が未使用のままになるため、適切な人物を削除すると最適な状態が維持されます。 もし`mask`はゼロ和であるため、選択した任意の人物を含むグループを取得します。 その人を削除すると、他のすべてのグループはそのまま残るため、`mask`は、対応する小さいマスクの最適値より正確に 1 つ大きい値です。 これは、マスクサイズの帰納法による再発を証明します。 

フルセットの場合、ゼロ以外のすべての人々自体の合計はゼロになるため、最適なサブパーティションは実際には全員のパーティションになります。 含まれている場合`g`グループと`m`人々、それらのグループが必要とするのは`m-g`支払い。 最大化`g`結果的に支払い回数が最小限に抑えられます。 

すべての支払いでは債務者から債権者にのみ送金されるため、最終的な貪欲決済は、選択した各グループ内で正しいものになります。そのため、送金総額は正の残高の合計とまったく同じになります。 これは可能な最小総転送量です。 各支払いで少なくとも 1 つの残高がゼロになり、最後の支払いで最後の 2 つの残高がゼロになり、正確に`s-1`グループへの支払い`s`人々。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(data: str) -> str:
    it = iter(map(int, data.split()))
    try:
        n = next(it)
        k = next(it)
    except StopIteration:
        return ""

    balance = [0] * n

    for _ in range(k):
        a = next(it)
        b = next(it)
        c = next(it)

        balance[a] += c
        balance[b] -= c

    people = []
    vals = []

    for person, value in enumerate(balance):
        if value != 0:
            people.append(person)
            vals.append(value)

    m = len(vals)

    if m == 0:
        return "0\n"

    size = 1 << m

    subset_sum = [0] * size

    for mask in range(1, size):
        bit = mask & -mask
        idx = bit.bit_length() - 1
        subset_sum[mask] = subset_sum[mask ^ bit] + vals[idx]

    dp = [0] * size

    for mask in range(1, size):
        best = 0
        bits = mask

        if subset_sum[mask] == 0:
            while bits:
                bit = bits & -bits
                candidate = dp[mask ^ bit] + 1
                if candidate > best:
                    best = candidate
                bits ^= bit
        else:
            while bits:
                bit = bits & -bits
                candidate = dp[mask ^ bit]
                if candidate > best:
                    best = candidate
                bits ^= bit

        dp[mask] = best

    groups = []
    mask = size - 1

    while mask:
        first = mask & -mask
        sub = mask

        while sub:
            if (sub & first) and subset_sum[sub] == 0:
                rest = mask ^ sub
                if dp[rest] + 1 == dp[mask]:
                    groups.append(sub)
                    mask = rest
                    break
            sub = (sub - 1) & mask

    answer = []

    for group in groups:
        debtors = []
        creditors = []

        bits = group
        while bits:
            bit = bits & -bits
            idx = bit.bit_length() - 1

            if vals[idx] < 0:
                debtors.append([idx, -vals[idx]])
            else:
                creditors.append([idx, vals[idx]])

            bits ^= bit

        i = 0
        j = 0

        while i < len(debtors) and j < len(creditors):
            debtor, owe = debtors[i]
            creditor, receive = creditors[j]

            amount = min(owe, receive)

            answer.append((people[debtor], people[creditor], amount))

            owe -= amount
            receive -= amount

            debtors[i][1] = owe
            creditors[j][1] = receive

            if owe == 0:
                i += 1
            if receive == 0:
                j += 1

    out = [str(len(answer))]
    out.extend(f"{a} {b} {c}" for a, b, c in answer)
    return "\n".join(out) + "\n"

def main():
    data = sys.stdin.buffer.read().decode()
    sys.stdout.write(solve(data))

if __name__ == "__main__":
    main()
```入力セクションでは、`sys.stdin.buffer.read()`繰り返し電話する代わりに`input()`。 まで`100000`ローンの場合、入力全体を一度に読み取るのはシンプルで高速ですが、実際のアルゴリズムはまだ`O(N)`財務状況。 

残高更新には次のものを使用します`balance[a] += c`そして`balance[b] -= c`。 入力は過去のローンの方向を表すのに対し、出力は最終的な返済の方向を表すため、これらの符号を逆にすることは誤った答えの一般的な原因となります。 

ゼロバランスの人々は、マスクを作成する前にフィルタリングされます。 その結果、`m`より小さくてもよい`N`、すべてのマスク ビットは実際の非ゼロ バランスに対応します。 すべての残高がゼロの場合、関数はすぐに戻り、特別な再構築ロジックを使用してサイズがゼロの DP 配列を作成することはありません。 

サブセット合計配列は、最も低い設定ビットを使用します。 もし`bit`それはちょっとです、それでは`mask ^ bit`他のすべての人が含まれているため、`subset_sum[mask]`は、以前に計算された 1 つのエントリから計算できます。 値は約に達する可能性があります`10^8`, so Python integers comfortably handle them without overflow.

 The DP transition deliberately considers every set bit instead of choosing only one fixed bit. この証明により、少なくとも 1 つの選択肢が最適なサブパーティションを保持することが保証され、すべての選択肢を考慮することで、再帰的にその選択肢を発見できるようになります。 

The reconstruction is separate from the DP because the recurrence stores only the optimal count, not the identity of every zero-sum group. Enumerating submasks during reconstruction is affordable because there are at most 18 non-zero people. また、ビット自体は対応するゼロサム コンポーネントを識別しないため、DP 遷移によって削除されたビットからグループを推測しようとするよりも安全です。 

The final settlement does not alter the original`vals`配列。 小さなミュータブルで動作します`[person, amount]`各グループ内のペア。 これは、DP が最適な分割を記述するのに対し、決済フェーズではその分割に対して 1 つの有効な支払いシーケンスを構築するだけで済むため、便利です。

 |`001`|`0`|`-5`|`0`|
 |`010`|`1`|`+2`|`0`|
 |`100`|`2`|`+3`|`0`|
 |`011`|`0,1`|`-3`|`0`|
 |`101`|`0,2`|`-2`|`0`|
 |`110`|`1,2`|`+5`|`0`|
 |`111`|`0,1,2`|`0`|`1`|

 適切なゼロサムのサブセットは存在しないため、3 人全員が 1 つのグループを形成します。 和解段階では債務者とのマッチングが行われる`0`債権者と`1`2単位の場合、その後債権者と`2`3台分。```
2
0 1 2
0 2 3
```このサンプルでは、​​反対側の債権者注文で同じ 2 つの支払いを使用していますが、これも同様に最適です。 

このトレースは、DP がゼロサム グループと任意の人々の集合を区別しなければならない理由を示しています。 フルセットはゼロサムであるため、1 つの独立したコンポーネントに寄与しますが、適切なサブセットを独立して解決することはできません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(K + m 2^m)`|`O(K)`残高を計算するには、`O(2^m)`部分集合の和については、`O(m 2^m)`DPの場合、および`O(m 2^m)`再建のための最悪の場合 |
 | スペース |`O(2^m + N)`| サブセットの合計と DP にはそれぞれ次のものが含まれます`2^m`エントリ、バランス配列には次のものが含まれます。`O(N)`エントリー |

 以来`m <= N <= 18`、せいぜいあります`262144`マスク。 メイン DP のパフォーマンスはおよそ以下です`18 * 262144`、 または`4.7 million`、ビット遷移。 再構成は同じ指数関数的なスケールを持ち、この限界でも実用的です。 の`100000`入力ローンは線形前処理パスのみを追加するため、ソリューションは意図した小規模な範囲内に問題なく適合します。`N`、 大きい-`K`問題の構造。 

## テストケース

 以下のテストでは同じものを使用します`solve`提出されたソリューションとして機能します。 この問題ではあらゆる最適な支払いシーケンスが受け入れられるため、この実装の決定論的な出力を比較するだけで、これらの固定テストには十分です。```python
import io
import sys

def solve(data: str) -> str:
    it = iter(map(int, data.split()))

    n = next(it)
    k = next(it)

    balance = [0] * n

    for _ in range(k):
        a = next(it)
        b = next(it)
        c = next(it)
        balance[a] += c
        balance[b] -= c

    people = []
    vals = []

    for person, value in enumerate(balance):
        if value:
            people.append(person)
            vals.append(value)

    m = len(vals)

    if m == 0:
        return "0\n"

    size = 1 << m
    subset_sum = [0] * size

    for mask in range(1, size):
        bit = mask & -mask
        idx = bit.bit_length() - 1
        subset_sum[mask] = subset_sum[mask ^ bit] + vals[idx]

    dp = [0] * size

    for mask in range(1, size):
        best = 0
        bits = mask

        while bits:
            bit = bits & -bits
            candidate = dp[mask ^ bit]

            if subset_sum[mask] == 0:
                candidate += 1

            if candidate > best:
                best = candidate

            bits ^= bit

        dp[mask] = best

    groups = []
    mask = size - 1

    while mask:
        first = mask & -mask
        sub = mask

        while sub:
            if (sub & first) and subset_sum[sub] == 0:
                rest = mask ^ sub
                if dp[rest] + 1 == dp[mask]:
                    groups.append(sub)
                    mask = rest
                    break
            sub = (sub - 1) & mask

    answer = []

    for group in groups:
        debtors = []
        creditors = []

        bits = group
        while bits:
            bit = bits & -bits
            idx = bit.bit_length() - 1

            if vals[idx] < 0:
                debtors.append([idx, -vals[idx]])
            else:
                creditors.append([idx, vals[idx]])

            bits ^= bit

        i = 0
        j = 0

        while i < len(debtors) and j < len(creditors):
            debtor, owe = debtors[i]
            creditor, receive = creditors[j]

            amount = min(owe, receive)

            answer.append(
                (people[debtor], people[creditor], amount)
            )

            debtors[i][1] -= amount
            creditors[j][1] -= amount

            if debtors[i][1] == 0:
                i += 1
            if creditors[j][1] == 0:
                j += 1

    out = [str(len(answer))]
    out.extend(f"{a} {b} {c}" for a, b, c in answer)
    return "\n".join(out) + "\n"

def run(inp: str) -> str:
    return solve(inp)

assert run(
    """2 1
1 0 1
"""
) == """1
0 1 1
""", "sample 1"

assert run(
    """3 4
2 0 2
1 0 1
1 0 1
2 0 1
"""
) == """2
0 1 2
0 2 3
""", "sample 2"

assert run(
    """1 0
"""
) == """0
""", "minimum size with no loans"

assert run(
    """4 2
0 2 2
1 3 2
"""
) == """2
3 0 2
2 1 2
""", "two independent equal groups"

assert run(
    """3 1
0 1 1
"""
) == """1
1 0 1
""", "zero-balance participant"

large_input = "2 100000\n" + ("0 1 1\n" * 100000)

assert run(large_input) == """1
0 1 100000
""", "maximum K and large aggregated balance"

 | --- | --- | --- |

 |`3 4 / sample 2`|`2 / 0 1 2 / 0 2 3`| 単一の 3 人のゼロサム コンポーネント |

 ## 特殊なケース

 正反対のペアは最も単純なゼロ和グループです。 のために```
2 1
1 0 1
```集計後の残高は、`[-1, +1]`。 完全なマスクは合計がゼロなので、`dp[full] = 1`。 Reconstruction では、両方の人々を 1 つのグループとして選択します。 和解段階で債務者を見つける`0`そして債権者`1`、1単位を譲渡し、両方の残高がゼロになります。 出力は```
1
0 1 1
```残高がゼロの人は、偽の取引を作成してはなりません。 のために```
3 2
0 1 5
1 0 5
```2つのローンは正確にキャンセルされ、残高が残ります`[0, 0, 0]`。 フィルタリングのステップではすべての人物が削除されるため、`m = 0`そしてアルゴリズムはすぐに出力します```
0
```これが、DP がすべての残高からではなく、ゼロ以外の残高から構築されるべき理由でもあります。`N`人々。 

独立したゼロサム コンポーネントは、任意の貪欲なマッチングを無効にする中心的なケースです。 のために```
4 2
0 2 2
1 3 2
```残高は`[+2, +2, -2, -2]`。 最適なパーティションには 2 つのグループがあります。`{0,3}`そして`{1,2}`。 各グループには 1 回の支払いが必要なので、最終的な回答には 2 つのトランザクションが含まれます。```
2
3 0 2
2 1 2
```合計転送額は 4 で、プラスの残高の合計に等しく、各独立ペアにはすでに 1 つ必要であるため、2 回の支払いが最適です。 

融資を繰り返すと、投入量と州の規模が区別されます。 と`100000`のコピー`0 1 1`、残高は次のようになります`[-100000, +100000]`。 ゼロでない人は2人しかいないため、DPにはまだマスクが4つしか含まれていません。 再構築では 1 つのグループが生成され、決済フェーズでは 1 回の支払いが行われます。`100000`:```
1
0 1 100000
```オリジナル`100000`ローンはそれぞれ 1 回処理されますが、個別の DP 状態は作成されません。 

最後の境界ケースは、ゼロバランスの人々の間に隠された単一の非ゼロペアです。 のために```
3 1
0 1 1
```残高は`[+1, -1, 0]`。 人`2`は破棄され、2 要素の DP 状態が残ります。`[+1, -1]`。 結果として生じる支払いは、```
1
1 0 1
```残高ゼロの参加者は決済に何の役割も持たず、ビットマスク インデックスは残りの 2 人のみを参照するため、元の個人 ID は再構築中に個別に保存する必要があります。
