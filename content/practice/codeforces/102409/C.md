 ## 問題の理解

 (N) 個の頂点を持つ重み付きツリーがあります。 各エッジは整数を格納し、任意の 2 つの頂点について、それらの頂点を接続する一意のパス上のすべてのエッジの重みの XOR としてパス値を定義します。 タスクは、これらのパス値を、順序付けされていない個別の頂点のすべてのペアに追加することです。 

ツリー構造は重要な特性を与えてくれます。それは、任意の 2 つの頂点間にはパスが 1 つだけ存在するということです。 課題は、個々のパスを見つけることではなく、(N) が (10^5) に達したときに膨大な数のパスを回避することです。 

(10^5) 個の頂点がある場合、ほぼ (5\times10^9) 個の順序のないペアが存在します。 各パスの処理に必要な作業を考慮する前に、(O(N^2)) アルゴリズムでさえ、すでに遅すぎます。 線形時間に近い解決策が必要です。 エッジの重みは最大 (10^9) であるため、(10^9 < 2^{30}) であるため、関連するすべての XOR は 30 ビット以内に収まります。 これにより、ビットごとのカウント戦略が実用的になります。 

実装が静かに失敗する可能性がある小さなケースがいくつかあります。 1 つ目は、単一の頂点を含むツリーです。```
1
```異なる頂点のペアは存在しないため、答えは (0) です。 この場合、少なくとも 1 つのエッジが失敗する可能性があると想定しているコードです。 

もう 1 つの便利なケースは、2 つの頂点を持つツリーです。```
2
1 2 1000000000
```唯一のペアはパス XOR (1000000000) を持つため、答えは (1000000000) になります。 これにより、ペアのカウントとエッジの重みの上限の両方がチェックされます。 

3 番目のケースは次のとおりです。```
3
1 2 1
2 3 2
```3 つのペアの値は (1)、(2)、(1\oplus2=3) であり、答えは (6) になります。 パス XOR を通常の合計のように扱う不用意な実装では、ここで偶然 (1+2+(1+2)=6) が生成されるため、対称性の低い例は実際の XOR 演算をテストするのに役立ちます。 

最後に、等しいエッジの重みを考慮します。```
4
1 2 7
1 3 7
1 4 7
```各リーフはルート XOR 値 (7) を持ち、ルートは値 (0) を持ちます。 3 つのルートからリーフのペアはそれぞれ (7) に寄与しますが、すべてのリーフからリーフのパスには XOR (7\oplus7=0) があります。 正解は(21)です。 XOR 値の代わりにエッジをカウントすると、リーフ間のパスに (14) が誤って割り当てられます。 

## アプローチ

 直接的な解法では、頂点のすべてのペアから開始して、その一意のパスを見つけ、そのパスに沿ったエッジの重みの XOR を計算し、その結果を答えに追加します。 これは、すべてのペアに要求された数量を正確に評価するため、正しいです。 

問題は繰り返し作業の量です。 パス形状のツリーでは、両端付近の 2 つの頂点に、ほぼ (N) 個のエッジを含むパスを含めることができます。 (N(N-1)/2) 個のペアがあるため、各パスを個別に処理するには、次のオーダーの処理が必要になります。 

[
 \frac{N(N-1)}{2}(N-1)=O(N^3)
 】

 エッジ訪問。 (N=10^5) の場合、これは最悪の場合、およそ (5\times10^{14}) 回のエッジ操作となり、制限時間の許容範囲をはるかに超えます。 事前に計算されたツリー情報を使用してすべてのペアを見つける、より効率的な実装でも、依然として (O(N^2)) 個のペアが存在することになりますが、これは多すぎます。 

重要な点は、各頂点に付加された値を使用して XOR パスを表現できることです。 頂点 (1) を任意のルートとして選択し、定義します

 [
 A[v]=\text{}1\text{ から }v までのパス上のすべてのエッジの重みの XOR。 
】

 ルートから (u) および (v) へのパスが最下位の共通祖先で出会うと仮定します。 共通のプレフィックスが両方のルート パスに存在するため、その XOR が 2 回表示され、キャンセルされます。 

[
 x\oplus x=0。 
】

 残るのは、(u) から (v) へのパスの XOR です。 その結果、

 [
 P(u,v)=A[u]\oplus A[v]。 
】

 これにより、ペア間のパスを見つける必要が完全になくなります。 

ここで問題は次のようになります。与えられた (N) 個の数値 (A[1],A[2],\ldots,A[N]) から、順序のないすべてのペアについて (A[u]\oplus A[v]) の合計を求めます。 

XOR は一度に 1 ビットずつ独立して処理できます。 特定のビットについて、一方のエンドポイントのそのビットが (0) に等しく、もう一方のエンドポイントのそのビットが (1) に等しい場合、ペアはそのビットに (1) を与えます。 (c_1) 値にビットが含まれ、(c_0=N-c_1) 値にビットが含まれていない場合、正確には

 [
 c_0c_1
 】

 ペアはその部分に貢献します。 したがって、最終的な答えへの貢献は次のとおりです。 

[
 c_0c_1\cdot 2^b。 
】

 1 回のツリー トラバーサルですべての root-XOR 値を計算し、それらの値にわたるセット ビットをカウントし、カウントを結合できます。 すべてのペアを独立して評価できるため、ブルート フォースは機能しますが、ペアが多すぎるため失敗します。 すべてのパス XOR が単に 2 つのルート プレフィックス XOR の XOR であるという観察により、グラフの問題は、30 ビット カウントが続く頂点値の線形数に縮小されます。

 ## アルゴリズムのチュートリアル

 1. ツリーの隣接リストを作成します。 各隣接エントリには、隣接する頂点と接続エッジの重みが格納されます。 
2. ツリーを頂点 (1) でルートし、スタックを使用して反復的にトラバースします。 店`xor_value[v]`、頂点 (1) から (v) までのすべてのエッジの重みの XOR。 当初は、`xor_value[1] = 0`。 
3. 重み (w) を使用して、すでに訪問した頂点 (u) から未訪問の頂点 (v) までエッジをトラバースする場合、次の値を割り当てます。 

[
 xor_value[v]=xor_value[u]\oplus w。 
】

 グラフはツリーであるため、ルートからすべての頂点までのパスが 1 つだけ存在するため、初めて (v) に到達したとき、この値は正しいルートパス XOR になります。 
4. 走査後、(0) から (29) までのすべてのビットを検討します。 そのビットが設定されている root-XOR 値の数を数えます。 このカウントを (c_1) と呼び、(c_0=N-c_1) とします。 
5. このビットについては、そのビットを含む 1 つの値とそのビットを含まない 1 つの値を持つすべてのペアが XOR に寄与します (1)。 このような順序のないペアは正確に (c_1c_0) 存在します。 追加

 [
 c_1c_0(1\ll b)
 】

 答えに。 
6. 30 ビットすべてを処理した後、累積された応答を出力します。 各ビットは独立してカウントされるため、重み付けされた寄与によってすべてのペアごとの XOR の合計が正確に再構築されます。 

### なぜ効果があるのか

 中心の不変条件は、すべての頂点 (v) について次のとおりです。`xor_value[v]`ルートから (v) までの一意のパス上のエッジの XOR に等しい。 任意の 2 つの頂点 (u) と (v) について、計算時にルート パスの共通部分が 2 回トラバースされます。`xor_value[u] XOR xor_value[v]`, キャンセルされます。 残りのエッジは、(u) と (v) の間の一意のパス上のエッジとまったく同じです。 

[
 P(u,v)=xor_value[u]\oplus xor_value[v]。 
】

 XOR では、ビットごとに、2 つのオペランドがその位置で異なる場合にそのビットが正確に設定されます。 (c_1) の頂点にビットがあり、(c_0) にはビットがない場合、そのビットに異なる値を持つペアが正確に (c_1c_0) 存在します。 したがって、アルゴリズムは、すべての順序なしペアのすべてのビットの寄与を 1 回だけカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    graph = [[] for _ in range(n)]

    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append((v, w))
        graph[v].append((u, w))

    xor_value = [0] * n
    parent = [-1] * n
    parent[0] = 0

    stack = [0]

    while stack:
        u = stack.pop()

        for v, w in graph[u]:
            if v == parent[u]:
                continue

            parent[v] = u
            xor_value[v] = xor_value[u] ^ w
            stack.append(v)

    answer = 0

    for bit in range(30):
        mask = 1 << bit
        ones = 0

        for value in xor_value:
            if value & mask:
                ones += 1

        zeros = n - ones
        answer += ones * zeros * mask

    print(answer)

if __name__ == "__main__":
    solve()
```元のツリーは無向であるため、隣接リストはツリーを表し、両方向の各エッジを格納します。 (2(N-1)) 個の隣接エントリがあるため、表現のサイズは線形のままです。 

反復トラバーサルは再帰的 DFS を置き換えます。 (10^5) 個の頂点を持つチェーンは再帰の深さ (10^5) を持つことができますが、これは通常の Python 再帰では安全ではありません。 明示的なスタックにより、この問題が回避されます。`xor_value[0]`ルートからそれ自体へのパスにはエッジが含まれないため、 はゼロに初期化されます。 未訪問の子に到達すると、その値は親の値と接続エッジの重みを XOR したものになります。 

の`parent`配列は、使用したばかりのエッジをすぐに横切って戻ってしまうのを防ぐのに十分です。 入力はツリーであることが保証されているため、サイクルを引き起こす可能性のある以前に訪問した他の頂点はありません。 ルートの親はそれ自体に設定されるため、トラバーサルは最初から定義された親の値を持ちます。 

最後のループでは、正確に 30 ビットをチェックします。 すべてのエッジの重みは最大 (10^9) であるため、エッジの重みのすべての XOR は (2^{30}) 未満になります。 Python の整数はオーバーフローしませんが、ループをこれらの関連する 30 ビットに制限することで、アルゴリズムの正確さと効率が維持されます。 

掛け算`ones * zeros * mask`32 ビット整数よりも大きくすることもできます。 Python の整数は必要に応じて自動的に増加するため、明示的なオーバーフロー処理は必要ありません。

 [
 50000\cdot50000=2500000000。 
】

 実装では、およそ (5\times10^9) 個の頂点ペアを列挙することなく、その結果が得られます。
