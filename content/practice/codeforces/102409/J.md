 ## 解決策
 ## 問題の理解

 長さ (L) のチョコレート バーの内側には (N-1) 個の正当な切断位置があります。 2 つの端点 (0) と (L) を追加すると、(N) 個の基本部分を記述する (N+1) 個の位置が得られます。 内部の位置を正確に 3 つ選択し、4 つの連続する部分を作成する必要があります。 

選択したカットが位置 (a<b<c) にある場合、4 つのピースの長さは次のようになります。 

[
 a、\qquad b-a、\qquad c-b、\qquad L-c。 
】

 この部門の品質は、最大の部分と最小の部分の違いです。 3 つのカットのすべての法的選択について、その差の可能な最小限の値が必要です。 

入力サイズは最初の警告サインです。 (N) が (10^5) と同じ大きさである場合、カットを 3 つずつ試すには次のことが必要になります。 

\frac{(N-1)(N-2)(N-3)}{6}
 】

 (N=10^5) の場合、約 (1.67\times10^{14}) の可能性があります。 1 秒の制限により、それは完全に排除されます。 座標は (10^{15}) に達する可能性があるため、実装では 64 ビット整数演算も使用する必要があります。 Python の整数はすでにこの範囲を安全に処理しています。 

もっともらしい実装が間違っている可能性がある境界例がいくつかあります。 まず、(N=4) の場合、合法的なカットがちょうど 3 つあるため、可能な分割は 1 つだけです。 例えば、```
4 10
2 5 7
```はピース (2,3,2,3) を生成するため、答えは (1) になります。 いくつかの中間的な選択肢があることを前提とした実装では、誤ってこのケースをスキップする可能性があります。 

エンドポイント (0) と (L) は切断スポットではありません。 のために```
4 10
1 5 9
```有効な部分は (1,4,4,1) だけで、答えは (3) になります。 エンドポイントを利用可能なカットであるかのように扱うと問題が変わり、無効な分割が発生する可能性があります。 

理想的な中間点が 2 つの利用可能なカットの間に正確に位置する場合、別の微妙なケースが発生します。 考慮する```
5 10
2 4 6 8
```適切なミドル カットの場合、左半分にはターゲット座標 (3) があり、(2) と (4) は両方とも同等に近いです。 どちらを選択しても、同じ 2 つの左側のピースの長さが逆の順序で生成されるため、答えは (2) になります。 挿入ポイントの片側だけをチェックする検索では、最適なものを見逃す可能性があります。 

最後に、座標は通常のマシン整数の範囲よりもはるかに大きくなる可能性があります。 のために```
4 1000000000000000
1 2 3
```唯一の除算の長さは (1,1,1,999999999999997) なので、答えは次のようになります。```
999999999999996
```浮動小数点を使用して中間点を見つけるのは不要であり、この規模では潜在的に安全ではありません。 以下の解決策は、すべての中点計算を整数演算で実行します。 

## アプローチ

 直接的な解決策は、最初、2 番目、および 3 番目のカットを選択することです。 それらの位置が (a<b<c) の場合、4 つの長さを計算し、次のように答えを更新します。 

[
 \max(a,b-a,c-b,L-c)-\min(a,b-a,c-b,L-c)。 
】

 これは正しいです。すべての法的分割は、内部カットの 1 つの増加トリプルに正確に対応するため、すべてのトリプルをチェックすると、すべての可能な分割がチェックされるからです。 問題はトリプルの数です。 (N=10^5) の場合、それらは約 (1.67\times10^{14}) 個あり、制限時間の許容範囲をはるかに超えています。 

2 番目の、つまり中央のカットを (b) の位置で一時的に固定すると、有用な構造が現れます。 (b) が修正されると、問題は 2 つの独立したペアに分離されます。 

左側の２枚は、

 [
 a、\qquad b-a、
 】

 それらの合計は (b) で固定されます。 右側の2枚は、

 [
 c-b、\qquad L-c、
 】

 それらの合計は (L-b) に固定されます。 

合計が固定された 2 つの数値の場合、それらを互いに近づけても、全体的な最大値、マイナス値、最小値が悪化することはありません。 現在のペアが (x,S-x) であると仮定します。 (x) を (S/2) に向かって移動すると、同時に大きい方の部材が下に移動し、小さい方の部材が上に移動します。 このペアの外側にある他の部分は影響を受けないため、グローバル範囲を増やすことはできません。 

これにより、中心的な観察結果が得られます。固定された中間カット (b) の場合、最良の最初のカットは、(b/2) に最も近い利用可能なカット位置です。 最適な 3 番目のカットは、次の位置に最も近い利用可能なカット位置です。 

[
 \frac{b+L}{2}。 
】

 1 番目のターゲットは (a=b-a) となる点であり、2 番目のターゲットは (c-b=L-c) となる点です。 カット位置はソートされているので、二分探索でそれぞれの最も近い位置を見つけることができます。 

ブルート フォースはすべてのトリプルを明示的に検査するため機能しますが、トリプルが多すぎるため失敗します。 固定ミドルカットにより各サイドが独立して最適化されるという観察により、問題は (O(N)) 個のミドルカットに削減され、それぞれに 2 つの (O(\log N)) 個の二分探索が行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^3)) | (O(N)) | 遅すぎる |
 | 最適 | (O(N\log N)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カット位置を 2 つのエンドポイントとともに保存します。 定義する

 [
 p_0=0、\quad p_1=x_1、\ldots、p_{N-1}=x_{N-1}、\quad p_N=L。 
】

 配列には (N+1) 個の位置がありますが、インデックス (1) から (N-1) のみが正当なカットです。 
2. 考えられるすべての中間カット (j) を反復します。つまり (2\le j\le N-2)。 ミドル カットには、その前に少なくとも 1 回のリーガル カットが必要で、その後に 1 回のリーガル カットが必要です。 

その座標を(p_j)とする。 左側の 2 つの部分は全長 (p_j) があるため、理想的な分割は次の位置で発生します。 

[
 \frac{p_j}{2}。 
】
 3. 座標が (p_j/2) に最も近い正当なカット (i<j) を見つけます。 位置がソートされているため、二分探索ではこのターゲットのすぐ周囲に挿入ポイントが表示されます。 挿入ポイントとその前の位置の位置を検査するだけで済みます。 

結果として得られる左側の部分は (p_i) と (p_j-p_i) です。 中間点に最も近い位置を選択すると、利用可能なカットが許す限りこれら 2 つの部分のバランスが取れます。 
4. 右側の場合、2 つの部分の合計の長さは (L-p_j) になります。 3 番目のカットが (p_k) の場合、それらは

 [
 p_k-p_j、\qquad L-p_k。 
】

 それらは等しいとき

 [
 p_k=\frac{p_j+L}{2}。 
】

 この座標に最も近い正当な位置 (k>j) を二分探索し、挿入点とその先行点を再度確認します。 
5. これら 2 つのローカルでバランスのとれた選択によって生成される 4 つの長さを計算し、グローバルな最小範囲を更新します。 
6. 考えられるすべての中間カットが処理された後、見つかった最小範囲を出力します。 

中間点検索では、浮動小数点ではなく整数ターゲットが使用されます。 中点 (S/2) の場合、((S+1)//2) を使用すると、上位の整数の中点が得られます。 (S) が奇数の場合、その位置とその前の位置をチェックすると両側がカバーされますが、偶数 (S) の場合は正確な中点が直接見つかります。 

### なぜ効果があるのか

中央のカットを修正します (b)。 有効な最初のカット (a) を考えてみましょう。 左側のペアは固定和 (b) を持っているため、(a) を (b/2) に近い利用可能な位置に置き換えると、左側の 2 つの長さの広がりが少なくなります。 その小さいメンバーは増加のみ可能であり、その大きいメンバーは減少のみ可能です。 同じ議論が右のペアに独立して適用され、その合計は (L-b) になります。 したがって、この固定ミドルカットの場合、中点に最も近いカットのペアは、そのグローバル範囲が同じミドルカットを使用する他のどの部門よりも大きくない部門を生成します。 このアルゴリズムは考えられるすべての中間カットを検査するため、少なくとも 1 回の反復で最適な除算の中間カットが考慮され、その反復によって最適な除算よりも悪くない除算が再構築されます。 したがって、全体的な最適値を生成する必要があります。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def solve():
    n, L = map(int, input().split())
    cuts = list(map(int, input().split()))

    # p[0] = 0, p[1..n-1] are legal cuts, p[n] = L.
    p = [0] + cuts + [L]

    ans = L

    # j is the middle cut. There must be one legal cut
    # on each side of it.
    for j in range(2, n - 1):
        pj = p[j]

        # Left pair: p[i], pj - p[i].
        # Its balance is best when p[i] is closest to pj / 2.
        left_target = (pj + 1) // 2
        i = bisect_left(p, left_target, 1, j)

        left_candidates = []
        if i < j:
            left_candidates.append(i)
        if i - 1 >= 1:
            left_candidates.append(i - 1)

        best_i = min(
            left_candidates,
            key=lambda idx: abs(2 * p[idx] - pj)
        )

        # Right pair: p[k] - pj, L - p[k].
        # Balance is best when p[k] is closest to (pj + L) / 2.
        right_target = (pj + L + 1) // 2
        k = bisect_left(p, right_target, j + 1, n)

        right_candidates = []
        if k < n:
            right_candidates.append(k)
        if k - 1 > j:
            right_candidates.append(k - 1)

        best_k = min(
            right_candidates,
            key=lambda idx: abs(2 * p[idx] - (pj + L))
        )

        a = p[best_i]
        b = pj
        c = p[best_k]

        pieces = (
            a,
            b - a,
            c - b,
            L - c
        )

        current = max(pieces) - min(pieces)
        ans = min(ans, current)

    print(ans)

if __name__ == "__main__":
    solve()
```位置配列は (0) で始まり (L) で終わります。 これは、すべてのピースの長さを 2 つのエントリの差として書き込むことができるため便利です。 選択された 3 つのカットは、依然としてインデックス (1) ～ (N-1) からのみ取得されます。 

ループは使用します`range(2, n - 1)`これは、両側に少なくとも 1 つの合法的なカットがあるミドル カットに正確に対応します。 (N=4) の場合、このループにはインデックス (j=2) が 1 つだけ含まれており、これが唯一の可能な中間カットです。 

左側の検索の場合、`bisect_left`インデックスに限定されます`[1, j)`。 これにより、二分探索で中央のカット自体または左側のエンドポイントが選択されなくなります。 適切な検索も同様に次のように制限されます。`[j+1, n)`、中間カットとエンドポイント (L) が選択されなくなります。 

表現`abs(2 * p[idx] - pj)`浮動小数点を使用せずに (p_j/2) からの候補の距離を比較します。 右側が使用しているのは、`abs(2 * p[idx] - (pj + L))`同じ理由で。 座標が (10^{15}) 付近であっても、すべての計算は正確なままです。 

各二分探索挿入点の周囲の 2 つの候補インデックスのみが最適となります。 位置が並べ替えられているため、前の位置は前の位置よりもターゲットから遠くなり、後の位置は挿入ポイントよりも遠くなります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(N\log N)) | (O(N)) 個の中間カットがあり、それぞれが 2 つの二分探索を使用します。 |

import io
from bisect import bisect_left

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        n, L = map(int, sys.stdin.readline().split())
        cuts = list(map(int, sys.stdin.readline().split()))

        p = [0] + cuts + [L]
        ans = L

        for j in range(2, n - 1):
            pj = p[j]

            left_target = (pj + 1) // 2
            i = bisect_left(p, left_target, 1, j)

            left_candidates = []
            if i < j:
                left_candidates.append(i)
            if i - 1 >= 1:
                left_candidates.append(i - 1)

            best_i = min(
                left_candidates,
                key=lambda idx: abs(2 * p[idx] - pj)
            )

            right_target = (pj + L + 1) // 2
            k = bisect_left(p, right_target, j + 1, n)

            right_candidates = []
            if k < n:
                right_candidates.append(k)
            if k - 1 > j:
                right_candidates.append(k - 1)

            best_k = min(
                right_candidates,
                key=lambda idx: abs(2 * p[idx] - (pj + L))
            )

            pieces = (
                p[best_i],
                p[j] - p[best_i],
                p[best_k] - p[j],
                L - p[best_k],
            )

            ans = min(ans, max(pieces) - min(pieces))

        print(ans)
        return sys.stdout.getvalue()

    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 特殊なケース

 (N=4) の場合、指定された 3 つの切断スポットが唯一の可能な切断です。 のために```
4 10
2 5 7
```位置配列は (0,2,5,7,10) です。 可能な 4 つのピースは (2,3,2,3) のみで、範囲 (3-2=1) が得られます。 ループは (j=2) を処理し、(i=1) と (k=3) を見つけて、(1) を返します。 

理想的な中間点が 2 つの法的立場の間にある場合、隣接する両方の候補者を考慮する必要があります。 で```
5 10
2 4 6 8
```(6) の真ん中のカットを考えてみましょう。 左のターゲットは(3)であり、法定位置(2)と(4)は等距離にあります。 どちらかを選択すると、同じペア (2,4) が逆の順序でのみ生成されます。 右側のターゲットは (8) で、これは利用可能なカットであり、駒 (2,4,2,2) と範囲 (2) を与えます。 アルゴリズムの挿入ポイントと先行チェックでは、タイが正しくカバーされます。 

エンドポイントは決して選択されたカットになってはいけません。 で```
4 10
1 5 9
```位置配列は (0,1,5,9,10) です。 有効な割り算は (1,4,4,1) のみで、答えは (3) です。 左側のバイナリ検索は中央のカットより前の正当なカット インデックスに制限され、右側のバイナリ検索はその後の正当なカット インデックスに制限されるため、(0) も (L) も選択されたトリプルに入ることができません。 

大きな座標には正確な中間点の処理が必要です。 のために```
4 1000000000000000
1 2 3
```4 つの長さは (1,1,1,999999999999997) であるため、答えは (999999999999996) となります。 実装では、これらの値が浮動小数点に変換されることはありません。 中間点の比較は、(2p_i-p_j) などの式を通じて実行され、許可されるすべての入力値の正確性が維持されます。 

最大サイズの等しいピースの場合でも、インデックス作成の境界が適用されます。 (N=100000)、(L=100000)、(1)から(99999)までの整数ごとにカットすると、(25000,50000,75000)でバーを分割できます。 結果として得られるすべての部分の長さは (25000) なので、答えは (0) になります。 このアルゴリズムは、トリプルを列挙することなく、考えられるすべて (99998) のミドルカット位置を処理します。これは、最大の入力に (O(N\log N)) 構造が必要な理由を示しています。
