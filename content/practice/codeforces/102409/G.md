 ## 解決策
 ## 問題の理解

 暗号化されたメッセージは、任意の数値の集合ではありません。 正確に (2^N) 個の値があり、元の (N) 文字コードのサブセットごとに 1 つずつ存在します。 元の文字コードが (x_1,x_2,\ldots,x_N) の場合、送信された配列には考えられるすべての合計が含まれます。 

[
 \sum_{i\in S}x_i
 】

 すべてのサブセット (S) に対して。 配列はソートされるため、その最初の値は常に (0) となり、空のサブセットに対応します。 

タスクは、これらのサブセットの合計から元の (N) 文字コードを復元することです。 回復されたコードは、ASCII の減少しない順序で文字として出力される必要があります。 元の文字は英数字であるため、復元された各値は有効な数字または文字に対応します。 

境界 (N\leq20) が中心の制約です。 最大の入力には (2^{20}=1,048,576) 個のサブセット合計があるため、送信される数値ごとにおよそ 1 回の演算を行うアルゴリズムが現実的です。 考えられるすべての元の単語を試すアルゴリズムは完全に不可能であり、(2^N) 要素の配列全体で線形検索を繰り返し実行するアプローチでも、おおよそ (2^{2N}) 個の作業に到達できます。 最大の英数字 ASCII 値は 122 であるため、サブセット合計の最大値は (20\cdot122=2440) のみです。この小さな値範囲により、特に有用な周波数配列表現が得られます。 

不注意な実装が失敗するエッジケースがいくつかあります。 一番小さいケースは、```
1
65
```サブセットの合計は (0) と (65) のみであるため、正しい出力は次のようになります。`A`。 空ではないサブセット合計のペアが常に存在すると想定しているデコーダーは、データの終わりを超えてしまう可能性があります。 

文字コードの繰り返しも可能です。 例えば、```
3
0 65 65 65 130 130 130 195
```から来ています`AAA`したがって、正しい出力は次のようになります。```
AAA
```多重度を保存する代わりにサブセットの合計をセットに格納するデコーダーは、(65) が 3 回発生するという事実を失い、単語を正しく再構成できません。 

文字コードが異なる場合でも、異なるサブセットは同じ合計を生成する可能性があります。 考慮する```
3
0 48 49 97 97 145 146 194
```元のコードは (48,49,97) で、以下に対応します。`01a`。 (97) の 2 つの出現は、異なるサブセット、つまり ({97}) と ({48,49}) です。 暗号化された値をマルチセットではなく個別の数値として扱うと、この情報は暗黙のうちに破棄されます。 

文字範囲には数字も含まれます。 例えば、```
3
0 48 122 122 170 170 244 292
```から来ています`0zz`。 復元されたすべての値が大文字または小文字であると想定するデコーダーは、有効な応答を拒否します。 

## アプローチ

 直接的な総当たりアプローチでは、考えられるすべての元の単語を試し、そのサブセットの合計を生成し、それらを並べ替えて、結果を入力と比較することができます。 使用可能な英数字は 62 文字あるため、必要な並べ替え順序を利用する前でも、(N=20) で (62^{20})、約 (7.0\cdot10^{35}) 個の候補単語が存在します。 すべての候補に対して (2^{20}) 個のサブセット合計を生成すると、このアプローチは制限時間を何桁も超えてしまいます。 

暗号化を逆にする、より構造化された方法があります。 いくつかの文字コードがすでに復元されていると仮定します。`subsets`それらの回復されたコードによって形成されるすべてのサブセット合計が含まれます。 当初はコードが復元されていないため、`subsets`(0) のみが含まれます。 

まだ消費されていない最小のサブセット合計を確認します。 すべての文字コードは正であるため、そのような最小値が次の未回復の文字コードである必要があります。 そのコードが (x) になると、回復されたコードから形成されたすべてのサブセットは (x) を追加することで拡張できます。 以前のサブセットの合計が (s) であった場合、対応する新しいサブセットの合計は (s+x) になります。 その結果、残りの暗号化されたマルチセットからどの値を削除する必要があるかが正確にわかります: (s) の (s) のすべての (s+x)`subsets`。 

これらの値を削除した後、各 (s+x) を`subsets`。 このプロセスは、(N) 個の文字コードが回復されるまで繰り返されます。 

残りの問題は、値を効率的に見つけて削除する方法です。 ハッシュ マップなどの汎用マルチセットは機能しますが、この問題により、すべてのサブセットの合計が (0) と (2440) の間にあるというさらに強力な特性が得られます。 あらゆる可能な合計の多重度を周波数配列に保存できます。 残りの最小値を見つけるには、最大 2440 個の位置を左から右に移動するポインターのみが必要で、値の削除は定数時間の配列のデクリメントです。 

必要な削除ごとに膨大なリストを検索する必要がある可能性があるため、総当たりの再構築は失敗します。 合計範囲が小さいことが観察されたため、これらの検索を直接インデックス付けに置き換え、再構成全体を (O(2^N)) 操作に減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 単語候補に対するブルートフォース | (O(62^N 2^N)) | (O(2^N)) | 遅すぎる |
 | すべての削除に対する線形検索 | (O(4^N)) | (O(2^N)) | 遅すぎる |
 | 周波数配列の再構成 | (O(2^N + 2440)) | (O(2^N + 2440)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (N) と (2^N) の暗号化されたサブセットの合計を読み取ります。 並べ替えられた順序に依存する代わりに、頻度配列内で各合計が何回発生するかを数えます。`freq`。 すべての合計は最大 2440 であるため、配列に必要なエントリは 2441 だけです。 
2.初期化`subsets = [0]`。 これは、これまでに復元された文字コードから形成できるすべてのサブセットの合計を表します。 何かを回復する前は、サブセットは空のサブセットのみです。 
3. ポインタを保持する`ptr`最初はゼロです。 しながら進めます`freq[ptr]`はゼロです。 正の頻度を持つ最初の位置は、すでに復元された文字によってまだ説明されていない最小のサブセット合計です。 
4.テイク`x = ptr`次の文字コードとして。 これがうまくいく理由はポジティブさです。 すべての未回復文字は正であるため、最小の未説明サブセット合計は、新しい文字を 1 つだけ取得し、以前に回復された文字を取得しないことによって取得する必要があります。 
5. しましょう`old_len = len(subsets)`。 それぞれについて、`old_len`既存のサブセットの合計`s`、デクリメント`freq[s + x]`。 これらは正確に、新しく回復された文字を含むサブセットの合計です。`x`それ以外の場合は、すでに回復された文字のサブセットを使用します。 
6. 毎に追加`s + x`に`subsets`。 この操作の後、`subsets`には、復元されたすべての文字コードから取得できるすべてのサブセット合計が含まれているため、次の反復で必要な新しい状態を表します。 
7. 前の手順を正確に (N) 回繰り返します。 復元されたすべての整数を次の文字に変換します。`chr`そしてそれらを連結します。 再構成では自然にコードが非降順で生成されるため、追加の並べ替えは必要ありません。 

### なぜ効果があるのか

 不変条件は、(k) 個の文字コードを回復した後、`subsets`これらのコードから形成された (2^k) 個のサブセットの合計が正確に含まれていますが、`freq[v]`元の暗号化されたマルチセット内で、復元されたコードによってまだ説明されていない (v) の出現回数を記録します。 

最初は、コードが回復されておらず、唯一のサブセット合計がゼロであるため、不変式が成り立ちます。 次のコードを回復する前にそれが成立すると仮定します。 説明されていない合計の最小値は、残っている元の文字コードの最小値でなければなりません。その文字を含む他のすべての説明されていないサブセットは少なくとも文字自体と同じくらい大きく、2 つ以上の正の未回復値を使用するすべてのサブセットはさらに大きいためです。 この値を (x) とすると、(x) を含むサブセットは正確に (s+x) になります。ここで (s) は、すでに復元されたコードのサブセットの合計です。 それらの出現を正確に削除すると、(x) を含まないサブセット合計が正確に残ります。 同じ (s+x) 値を追加する`subsets`(x) を追加した後にすべてのサブセットの合計を作成します。 したがって、不変式は反復ごとに保存され、(N) 回の反復後にはすべての元の文字コードが復元されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    m = 1 << n

    sums = list(map(int, input().split()))

    # Every original character is alphanumeric, so its ASCII value is
    # at most 122. With at most 20 characters, every subset sum is <= 2440.
    freq = [0] * 2441
    for x in sums:
        freq[x] += 1

    # The input array is no longer needed.
    del sums

    # All subset sums generated by the characters recovered so far.
    subsets = [0]

    answer = []
    ptr = 0

    for _ in range(n):
        while ptr <= 2440 and freq[ptr] == 0:
            ptr += 1

        x = ptr
        answer.append(chr(x))

        old_len = len(subsets)

        # Remove all subset sums that contain the newly recovered value x.
        for i in range(old_len):
            s = subsets[i]
            freq[s + x] -= 1

        # Add those sums to the set of subset sums of recovered values.
        for i in range(old_len):
            subsets.append(subsets[i] + x)

    print("".join(answer))

if __name__ == "__main__":
    solve()
```入力は最初に次のように変換されます。`freq`、メンバーシップだけではなく多重性を維持します。 暗号化された配列はマルチセットであり、多くの異なるサブセットに対して同じ合計が発生する可能性があるため、これは不可欠です。 

の`subsets`空のサブセットは常に使用できるため、配列はゼロから始まります。 現在 (k) 個の回復された値がある場合、そのサイズは正確に (2^k) です。 新しい価値観が生まれるとき`x`が見つかると、コードは最初に古いサイズを記憶します。 この境界は、古いサブセットの合計のみを使用して生成する必要があるため必要です。`s + x`。 リストを反復処理しながら同時に修正せずにリストに追加する`old_len`新しく作成された合計を同じ反復で処理し、誤った追加値が生成される可能性があります。 

周波数の減少は、新しい合計が追加される前に発生します。 これは不変条件から直接得られるものです。つまり、新たに生成された合計は、まさに新たに回復された文字によって説明される出現です。 

ポインタは前方にのみ移動します。 一度`freq[v]`がゼロに達すると、すべての操作は暗号化されたサブセットの合計のみを消費するため、その後の操作でその特定の値が再び説明不能になることはありません。 可能な最大合計は 2440 であるため、ポインターは合計で最大 2441 回の反復を実行します。 

Python の整数には、固定幅の整数の実装で発生する可能性があるオーバーフローの問題はありませんが、実際のサブセットの合計はすべて 2440 で制限されています。最大の構造は次のとおりです。`subsets`、最大 (2^{20}=1,048,576) 個の整数が含まれます。
