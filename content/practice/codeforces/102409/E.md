 ## 解決策
 ## 問題の理解

 円上に配置される (2N) 個の数字があります。 Diego はちょうど (N) 個の位置の連続するブロックを 1 つ選択し、Google は残り (N) 個の位置を受け取ります。 2 つのブロックは円全体をカバーするため、ディエゴが (X) の合計を取得すると、Google は合計から (X) を引いた値を取得します。 

ディエゴは最適にプレーするため、Google の観点からは、関連する量は (N) 連続するポジションの可能な最大合計となります。 ゲーム開始前に数字を完全に自由に入れ替えることができます。 課題は、この最悪のディエゴ スコアを最小化する循環順列を構築することです。 

入力には 1 つ (N) の後に正確に (2N) 個の正の整数が続きます。 値 (N) は最大 (6) であるため、円には最大 (12) の位置が含まれます。 すべての数値は最大でも (10^6) であるため、すべての合計は 64 ビット整数および Python の任意精度の整数に快適に収まります。 

(N) の小さな値が問題の主な信号です。 すべて (12!) 個の順列を試行すると、すでに (4.79\times10^8) 個の候補があり、各候補を評価する前でさえ多すぎます。 したがって、(O((2N)!)) アプローチは実現できません。 一方、(N!\cdot2^N) は (720\cdot64=46{,}080) のみで、小さいです。 

実装を簡単に壊す可能性のある境界ケースがいくつかあります。 (N=1) の場合、ディエゴは単純に 1 つの数字を取るため、考えられるすべての円形配置は同じ結果になります。 たとえば、入力の場合`1`そして`7 11`、出力が`7 11`または`11 7`。 選択されたすべてのブロックに少なくとも 2 つの数値があることを前提としたソリューションでは、誤って無効な位置にアクセスする可能性があります。 

値が等しいことも便利なテストです。 (N=2) と入力あり`5 5 5 5`、すべてのブロックの合計は (10) になります。 等しい値を個別のオブジェクトとして扱う解決策は依然として正しいですが、順列の重複を排除しようとする実装では、構造上の可能性を取り除きすぎないように注意する必要があります。 

円形の境界も重要です。 (N=2) と値を使用`1 2 3 100`の場合、位置 (3,0) を含むブロックは、出力された配列の末尾を横切らないブロックと同様に有効です。 アレンジメントについては`100 1 3 2`、4 つの巡回ブロックの合計は (101,4,5,102) であるため、Diego は (102) を取得できます。 通常の配列スライスのみをチェックすると、誤って (101) が報告されます。 

最後に、出力は順列ですが、必ずしもサンプルと同じ順列である必要はありません。 最適な最悪の場合のスコアを備えた任意の配置が受け入れられます。 したがって、テスト コードは、特定の最適な順序付けを必要とするのではなく、順列とそのスコアを検証する必要があります。 

## アプローチ

 直接的なアプローチは、(2N) 個の数値のすべての順列を生成することです。 各順列について、長さ (N) のすべて (2N) 個の巡回ウィンドウの合計を計算し、それらの最大値を取得し、最小の最大値を持つ順列を保持します。 これは、あらゆる可能な配置を明示的に考慮しているため、正しいです。 ただし、(N=6) の場合、(12!=479{,}001{,}600) 個の順列があります。 スライディング ウィンドウを使用して各候補がわずか (O(12)) 時間で評価されたとしても、これは約 (57) 億ウィンドウの更新に相当します。 単純な (O(12^2)) 評価はさらに悪くなります。 

互いに反対側の位置を見ると、有用な構造が現れます。 位置に番号を付けます (0、\ldots、2N-1)。 位置 (i) と (i+N) は反対であり、(N) 個の連続する位置のブロックには、反対側のペアごとに 1 つの要素が含まれます。 

数字を並べ替えます:

 [
 a_0\le a_1\le\cdots\le a_{2N-1}。 
】

 反対のペアが次のような最適な配置になります。 

[
 (a_0,a_1),(a_2,a_3),\ldots,(a_{2N-2},a_{2N-1})。 
】

 その理由は、反対のペアは、ウィンドウを 1 位置移動したときに交換される値のペアとまったく同じであるためです。 対向する位置の値を (x) と (y) とすると、ウィンドウの合計は (y-x) だけ変化します。 反対の値の間に大きなギャップがあると、連続するウィンドウの合計間に大きなジャンプが生じます。 連続する並べ替え値をペアにすることで、これらのギャップが最小限に抑えられます。 標準の非交差引数でも同じ結果が得られます。2 つのペアに不必要に分離された並べ替えられた値が含まれている場合は常に、それらの端点を相互に再接続しても、反対側のペアの最大絶対差を増やすことはできません。 この操作を繰り返すと、ソートされた連続したペアが残ります。 

この削減の後、残る決定は 2 つだけです。 

すべてのペアについて、どの端点が円の前半に属し、どの端点が反対側の半分に属するかを決定する必要があります。 そのような選択肢は (2^N) 通りあります。 

また、円周上の (N) 個のペアの順序も決定する必要があります。 (N!) 可能性があります。 

したがって、関連する検索空間全体は、

 [
 2^N N!\le 2^6\cdot6!=46{,}080.
 】

 すべての候補について、(2N) 要素の円を構築し、その最大巡回ウィンドウ合計を計算します。 これは簡単に十分に高速です。 

ブルートフォースアプローチと縮小アプローチを直接比較できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O((2N)!\cdot N)) | (O(N)) | 遅すぎる |
 | ペアリング + 列挙 | (O(2^N N!\cdot N)) | (O(N)) | 承認済み |

 2 番目のアプローチは単なるヒューリスティックではありません。 ソートされた隣接ペアリング補題は、すべての最適解をそれら (N) 個のペアの順序と方向によって表される解に還元し、そのような可能性をすべて列挙します。 

## アルゴリズムのチュートリアル

1. すべて (2N) の値を並べ替えます。 連続する値を (N) 個のペアにグループ化するため、ペア (i) は ((a_{2i},a_{2i+1})) になります。 これらのペアは、考慮する必要がある反対の位置です。 
2. (N) 個のペアインデックスのすべての順列を生成します。 これにより、反対側のペアが円の周りに表示される順序が選択されます。 ペアは常に 2 つの反対の位置に寄与するため、ペアの順序を選択するだけで相対的な位置を決定できます。 
3. ペアの順列ごとに、長さ (N) のすべてのビットマスクを生成します。 ビット (i) は、ペア (i) のどのメンバーを円の前半に配置するかを決定します。 もう一方のメンバーは自動的に対応する反対の位置に移動します。 
4. 円を作成します。 選択したペアの順序が (p_0,p_1,\ldots,p_{N-1}) の場合、ペア (p_i) の選択した端点を位置 (i) に配置し、もう一方の端点を位置 (i+N) に配置します。 すべてのペアがそれぞれの半分に 1 つの値を与えるため、すべての数値は 1 回だけ使用されます。 
5. 最初 (N) 個の位置の合計を計算します。 次に、ウィンドウを円の周りにスライドさせます。 ウィンドウが 1 ステップ移動すると、その出力値が減算され、入力値が加算されます。 これにより、ディエゴのブロックのすべて (2N) 個の可能な選択肢が (O(N)) 時間で評価されます。 
6. 最大の巡回ウィンドウ合計が最小となる候補を保持します。 これはまさに Google の保証スコアを最大化する取り決めです。Google は総額から Diego の最大スコアを差し引いたものを受け取るからです。 

### なぜ効果があるのか

 任意の固定円形配置の場合、Diego は (N) 個の連続する位置の任意の巡回ウィンドウを選択できるため、関連するスコアは正確にそのようなウィンドウの合計の最大値になります。 反対の位置により円が (N) 個のペアに分割され、ウィンドウを 1 位置ずつ移動すると、そのようなペアの 2 つのメンバーが交換されます。 連続するソート値をペアにすると、最大の交換量が最小化され、非交差引数は、これらのペアが互いに反対側にある最適な配置が存在することを示します。 

これらのペアが固定されると、この構造によって表されるすべての可能な配置は、ペアの順序と各ペアの方向という 2 つの選択肢によって完全に決定されます。 このアルゴリズムはすべての (N!2^N) 個の組み合わせを列挙するため、最適な配置を見逃すことはありません。 すべての候補はすべての巡回ブロックをチェックすることによって評価されるため、最小の最大ディエゴ スコアを持つ候補がまさに必要な出力となります。 

## Python ソリューション```python
import sys
import itertools

input = sys.stdin.readline

def solve_case(n, values):
    values = sorted(values)

    # Pair consecutive values in sorted order.
    pairs = [(values[2 * i], values[2 * i + 1]) for i in range(n)]

    best_score = None
    best_circle = None

    # Every permutation chooses the order of opposite pairs.
    for order in itertools.permutations(range(n)):
        # Every mask chooses the orientation of every pair.
        for mask in range(1 << n):
            circle = [0] * (2 * n)

            for pos, pair_id in enumerate(order):
                low, high = pairs[pair_id]

                if mask & (1 << pair_id):
                    circle[pos] = high
                    circle[pos + n] = low
                else:
                    circle[pos] = low
                    circle[pos + n] = high

            # Sum of the first N positions.
            window = sum(circle[:n])
            worst = window

            # Slide through all remaining cyclic windows.
            for start in range(1, 2 * n):
                window += circle[(start + n - 1) % (2 * n)]
                window -= circle[start - 1]
                if window > worst:
                    worst = window

            if best_score is None or worst < best_score:
                best_score = worst
                best_circle = circle[:]

    return " ".join(map(str, best_circle))

def main():
    n = int(input())
    values = list(map(int, input().split()))
    print(solve_case(n, values))

if __name__ == "__main__":
    main()
```最初の部分では値を並べ替え、反対のペアを作成します。 たとえば、サンプル値は次のようになります。 

[
 (100,100)、(101,102)、(115,117)、(145,147)、(982,992)。 
】

 ソートされた値をペアにするすべての可能な方法の中で、各ペア内の差異が可能な限り小さくなります。 

外側`itertools.permutations`ループは、ステップ 2 のペア順序の列挙を実装します。(N=6) の場合、(720) 個の順序のみが生成されます。 

マスク ループは方向の決定を実装します。 ビットが設定されている場合は、そのペアの大きい方のエンドポイントが前半に配置され、ビットが設定されていない場合は、小さい方のエンドポイントがそこに配置されます。 反対側のエンドポイントは、ちょうど (N) 位置離れて配置されます。 

円が回り込むため、ウィンドウの計算には注意が必要です。 最初のウィンドウは`circle[:n]`。 開始位置が から変更されるとき`start - 1`に`start`、出力値は`circle[start - 1]`、一方、受信値は`(start + n - 1) % (2 * n)`。 モジュロ演算は、最終ウィンドウが印刷された配列の末尾を正しく通過するようにするものです。 

Python の整数はオーバーフローしないため、可能な最大合計 (6\cdot10^6) には特別な処理は必要ありません。 元の値は決して変更されず、すべての候補は新しい順列として構築されます。これにより、後の候補が保存された回答を破損することも防止されます。 

入力にはテスト ケースが 1 つだけ含まれているため、テスト ケースのループはありません。`solve_case`。

## テストケース

 出力には任意の最適な順列を使用できるため、以下のテストでは返された順列を検証し、そのスコアを小規模な場合に個別に計算された最適値と比較します。 最大サイズの場合は、すべて等しい値を使用し、最適値がすぐにわかります。```python
import io
import itertools
import sys

def solve_case(n, values):
    values = sorted(values)
    pairs = [(values[2 * i], values[2 * i + 1]) for i in range(n)]

    best_score = None
    best_circle = None

    for order in itertools.permutations(range(n)):
        for mask in range(1 << n):
            circle = [0] * (2 * n)

            for pos, pair_id in enumerate(order):
                low, high = pairs[pair_id]
                if mask & (1 << pair_id):
                    circle[pos] = high
                    circle[pos + n] = low
                else:
                    circle[pos] = low
                    circle[pos + n] = high

            window = sum(circle[:n])
            worst = window

            for start in range(1, 2 * n):
                window += circle[(start + n - 1) % (2 * n)]
                window -= circle[start - 1]
                worst = max(worst, window)

            if best_score is None or worst < best_score:
                best_score = worst
                best_circle = circle[:]

    return best_circle

def solve(inp):
    data = list(map(int, inp.split()))
    n = data[0]
    values = data[1:1 + 2 * n]
    return " ".join(map(str, solve_case(n, values)))

def score(circle):
    m = len(circle)
    n = m // 2

    window = sum(circle[:n])
    best = window

    for start in range(1, m):
        window += circle[(start + n - 1) % m]
        window -= circle[start - 1]
        best = max(best, window)

    return best

def validate(inp, output):
    data = list(map(int, inp.split()))
    n = data[0]
    original = data[1:1 + 2 * n]

    result = list(map(int, output.split()))

    assert len(result) == 2 * n
    assert sorted(result) == sorted(original)
    assert score(result) >= 0

def brute_force_optimum(n, values):
    best = None

    for perm in itertools.permutations(values):
        cur = score(perm)
        if best is None or cur < best:
            best = cur

    return best

def run(inp: str) -> str:
    return solve(inp)

# Sample 1.
sample1 = """5
992 100 115 102 101 117 100 145 147 982
"""
out = run(sample1)
validate(sample1, out)

# Minimum size, N = 1.
case1 = """1
7 11
"""
out = run(case1)
validate(case1, out)
assert score(list(map(int, out.split()))) == 11

# All equal values.
case2 = """2
5 5 5 5
"""
out = run(case2)
validate(case2, out)
assert score(list(map(int, out.split()))) == 10

# Boundary-crossing case.
case3 = """2
1 2 3 100
"""
out = run(case3)
validate(case3, out)
assert score(list(map(int, out.split()))) == brute_force_optimum(
    2, [1, 2, 3, 100]
)
assert score(list(map(int, out.split()))) == 102

# Maximum-size input with extreme values.
case4 = """6
1 1 1 1 1 1 1000000 1000000 1000000 1000000 1000000 1000000
"""
out = run(case4)
validate(case4, out)
assert score(list(map(int, out.split()))) == 3000003

 ## 特殊なケース

 (N=1) の場合、入力には正確に 2 つの値が含まれます。 ディエゴは 1 つのポジションを選択するため、彼の最適スコアは単純に大きい値になります。 アルゴリズムは 1 つのペアを作成し、両方の方向を考慮して、どちらの方法でも同じ最悪のスコアを取得します。 のために`1 / 7 11`、 両方`7 11`そして`11 7`が最適です。 

重複する値の場合、連続してソートされたペアリングにより、差がゼロのペアが自然に生成されます。 と`2 / 5 5 5 5`、唯一のペアの差はゼロであり、可能なすべてのウィンドウの合計は (10) になります。 位置の値が等しい場合でも、位置は構造的に異なるままであるため、順列列挙は引き続き機能します。 

For a large gap, consider`2 / 1 2 3 100`。 ペア構造は`(1,2)`そして`(3,100)`。 候補者`100 1 3 2`ラップされたウィンドウ (2+100) を含むウィンドウ合計 (101,4,5,102) があります。 アルゴリズムはその最終ウィンドウを明示的に評価するため、不正確な非循環回答 (101) ではなく、正しいスコア (102) が得られます。 

6 個の最大 (N=6) の場合`1`sと6`1000000`s、可能な限り最良の配置では 2 つの値が交互になります。 各 6 要素ブロックには 3 つの大きな値と 3 つの小さな値が含まれており、次のようになります。 

[
 3\cdot1{,}000{,}000+3=3{,}000{,}003。 
】

 ソートされたリストは 3 つを形成するため、ペアの差はすべてゼロになります。`(1,1)`ペアと3つ`(1000000,1000000)`ペア。 残りの検索は完全に、これらの等しい値のペアの順序付けに関するものであり、すべて (6!) のペアの順序を列挙すると、バランスの取れた循環配置が見つかります。 

重要な実装のエッジ ケースは、周期的なウィンドウ更新です。 受信インデックスは次のとおりである必要があります`(start + n - 1) % (2 * n)`。 モジュロ演算を省略すると、出力された配列内に含まれるウィンドウのみが評価され、最後の位置から最初の位置に折り返されるウィンドウは無視されます。 この問題に関しては、これらのラップされたウィンドウは、ディエゴが行う他のすべての選択と同じくらい重要です。
