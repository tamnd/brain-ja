 ## 解決策
 ## 問題の理解

 1 から (N) までの番号が付けられた一連の部屋があります。 部屋 (N) が目的地ですが、コインはありません。 ディエゴは、部屋 (i) から、インデックスが最大 (i+k_i) である後続の部屋にジャンプできます。 彼が部屋 (i<N) を訪問すると、その (c_i) コインを収集します。 目標は、可能な限り多くのコインを持ってルーム (N) に到達する有効なジャンプ シーケンスを選択することです。 その最大値に達するすべてのパスのうち、(10^9+7) を法として、その数をカウントする必要もあります。 

部屋を表示する便利な方法は、有向非巡回グラフとして表示することです。 すべての部屋 (i) には、(i+1) から (i+k_i) までの頂点の間隔に対するエッジがあります。 すべてのエッジがより大きなインデックスに向かうため、部屋を右から左に処理すると、自然な動的プログラミング順序が得られます。 

値 (N) は (10^5) まで大きくすることができます。 二次アルゴリズムは、(N^2/2) 回程度、つまり最悪の場合でも (5\times10^9) 回程度の演算を実行します。 これは 1 秒の制限時間では処理できる範囲をはるかに超えています。 すべての部屋について、考えられるすべての目的地をスキャンすることを避ける必要があります。 コインの値は (10^9) に達する可能性があり、パスは (O(N)) 個の部屋を訪問する可能性があるため、コインの最大合計はおよそ (10^{14}) に達する可能性があります。 Python の整数はこれを安全に処理しますが、最適なパスの数は明示的に剰余 (10^9+7) で減らす必要があります。 

単純な実装が正しくない可能性があるいくつかの特殊なケースがあります。 

まず、最適なパスは多数存在する可能性があります。 考慮する：```
3
0 0
2 1
```ディエゴは部屋 1 から直接部屋 3 に行くことも、最初に部屋 2 を訪れることもできます。 どちらのパスでもコインがゼロなので、答えは次のようになります。`0 2`。 ウェイの数を蓄積せずに最良のコイン価値のみを保持する実装では、1 つのパスが誤って報告されます。 

第 2 に、ルームには最後のルーム以外に後継者を置くことはできません。 例えば：```
2
7
1
```可能なパスは (1\rightarrow2) のみであるため、答えは次のようになります。`7 1`。 動的プログラミングの状態を正しく初期化せずに部屋 (N) を通常の部屋のように扱うと、ゼロウェイが生成される可能性があります。 

第三に、最大間隔には右側のほぼすべての部屋を含めることができます。 例えば：```
5
0 0 0 0
4 3 2 1
```部屋 1 からジャンプするたびに、後の部屋に到達できます。 部屋 1 から部屋 5 までは 8 つの異なるパスがあるため、答えは次のようになります。`0 8`。 二次遷移スキャンでは正しい答えが得られますが、最大 (N) になると実行不可能になります。 

最後に、間隔の境界は包括的です。 (k_i=2) の場合、部屋 (i) は (i+1) または (i+2) にジャンプできますが、(i+3) にはジャンプできません。 右側のエンドポイントと排他的境界を混同すると、特に間隔が正確にルーム (N) で終了する場合に、微妙なオフバイ 1 エラーが発生します。 

## アプローチ

 直接動的計画法による定式化は簡単です。 (dp[i]) をルーム (i) からルーム (N) までに取得できるコインの最大数とします。 (ways[i]) を (dp[i]) を達成するパスの数とする。 最後の部屋については、(dp[N]=0) と (ways[N]=1) を定義します。これは、それ自体から目的地に到達しても追加のコインは提供されず、空の継続が 1 つだけ存在するためです。 

以前のすべての部屋 (i) について、有効な最初のジャンプはすべて、区間 ([i+1,i+k_i]) 内のいずれかのルーム (j) に移動します。 したがって、

 [
 dp[i] = c_i + \max_{j\in[i+1,i+k_i]} dp[j]。 
]

 最大値 (best) が判明すると、最適なパスの数は、(dp[j]=best) を満たす後続パスの (ways[j]) の合計になります。 

(i) からのすべてのパスには最初の宛先 (j) が 1 つだけあり、(j) に到達した後は、可能な限り最善の継続がまさに (dp[j]) で記述されるため、この総当り DP は正しいです。 問題は、最大値を見つけるコストとそれに関連する方法の数です。 すべての部屋の後続間隔全体をスキャンすると、最悪のケースでは約

 [
 \sum_{i=1}^{N-1}(N-i)=\frac{N(N-1)}2
 ]

 後継者試験。 (N=10^5) の場合、これは (4,999,950,000) 回の演算になります。 

重要な観察は、すべての遷移が同じ種類の質問をするということです。つまり、すでに計算された部屋の連続した区間の中で、最大 (dp) 値と、その最大値に属するウェイの総数を見つけます。 部屋は右から左に処理されるため、部屋 (i) の答えが必要なときは、後続区間のすべての値がすでに利用可能です。 

これはまさにポイント更新を伴う範囲クエリです。 セグメント ツリーには、セグメントごとに、最良 (dp) 値とその値を達成する方法の数を保存できます。 2 つの子セグメントを結合するのは簡単です。 1 人の子がより大きい (dp) を持っている場合、そのペアが答えになります。 両方が同じ (dp) を持つ場合、ウェイ数は (10^9+7) を法として加算されます。 

(dp[i]) と (ways[i]) を計算した後、そのペアを位置 (i) に挿入します。 各ルームは 1 回挿入され、1 回クエリされるため、(O(N\log N)) 時間がかかります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^2)) | (O(N)) | 遅すぎる |
 | 最適 | (O(N\log N)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最終的な部屋の状態を初期化します。 (dp[N]=0) および (ways[N]=1) を設定します。 最後の部屋はコインを提供しません。到達したら終了する方法は 1 つだけです。 
2. 位置 (i) のリーフにペア ((dp[i],ways[i])) が格納されるセグメント ツリーを構築します。 最初は、(N) を除くすべての位置は空です。 (N) のリーフには ((0,1)) が格納されます。 
3. 処理室 (i=N-1,N-2,\ldots,1)。 すべてのジャンプは右に移動するため、部屋 (i) の考えられるすべての目的地はすでに処理されています。 
4. 包含区間にわたるセグメント ツリーをクエリします。 

[
 [i+1,i+k_i]。 
]

 クエリは 2 つの情報を返します。 1 つ目は、到達可能なすべての目的地の最大値 (dp) です。 2 番目は、その最大値 (dp) を持つすべての目的地にわたる (ウェイ) の合計です。 

1. 現在のルームのコインをクエリされた最大値に追加します。 

[
 dp[i]=c_i+best。 
]

 部屋 (i) からの可能なすべての継続に同じコインの価値が追加されるため、(c_i) が追加されても最適なパスの数は変わりません。 したがって、

 [
 方法[i]=ベストウェイ。 
]

 1. ((dp[i],ways[i])) を使用して、位置 (i) のセグメント ツリーを更新します。 左側の将来の部屋は部屋 (i) を宛先として使用する可能性があるため、その状態は範囲クエリで利用できるようになっている必要があります。 
2. 部屋 1 を処理した後、(dp[1]) と (ways[1]) を出力します。 すべての有効な旅は部屋 1 から始まるため、これらはまさに必要な最大コイン合計と最適な旅の数です。

### なぜ効果があるのか

 不変条件は、部屋 (i) が処理されるたびに、(i) から到達可能なすべての部屋には、セグメント ツリーに正しい (dp) および (ways) の値が格納されていることです。 したがって、範囲クエリは、(i) のすべての可能な最初の宛先を考慮し、最大の継続値を選択し、その値を達成する宛先の間でのみパス数を合計します。 (c_i) を追加すると、(i) から始まる最良の合計が得られますが、対応するカウントは変更されません。 更新により、左隣の部屋の不変式が保持されます。 部屋 1 は最後に処理されるため、その保存されたペアは問題全体に対して正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
NEG = -10**30

class SegmentTree:
    def __init__(self, n):
        size = 1
        while size < n:
            size <<= 1

        self.size = size
        self.best = [NEG] * (2 * size)
        self.ways = [0] * (2 * size)

    def merge(self, left_best, left_ways, right_best, right_ways):
        if left_best > right_best:
            return left_best, left_ways
        if right_best > left_best:
            return right_best, right_ways
        if left_best == NEG:
            return NEG, 0
        return left_best, (left_ways + right_ways) % MOD

    def update(self, pos, value, ways):
        pos += self.size
        self.best[pos] = value
        self.ways[pos] = ways

        pos >>= 1
        while pos:
            lb = self.best[pos << 1]
            lw = self.ways[pos << 1]
            rb = self.best[pos << 1 | 1]
            rw = self.ways[pos << 1 | 1]

            b, w = self.merge(lb, lw, rb, rw)
            self.best[pos] = b
            self.ways[pos] = w

            pos >>= 1

    def query(self, left, right):
        if left > right:
            return NEG, 0

        left += self.size
        right += self.size

        left_best = NEG
        left_ways = 0
        right_best = NEG
        right_ways = 0

        while left <= right:
            if left & 1:
                lb = self.best[left]
                lw = self.ways[left]
                left_best, left_ways = self.merge(
                    left_best, left_ways, lb, lw
                )
                left += 1

            if not (right & 1):
                rb = self.best[right]
                rw = self.ways[right]
                right_best, right_ways = self.merge(
                    rb, rw, right_best, right_ways
                )
                right -= 1

            left >>= 1
            right >>= 1

        return self.merge(
            left_best, left_ways,
            right_best, right_ways
        )

def solve():
    n = int(input())
    c = [0] + list(map(int, input().split()))
    k = [0] + list(map(int, input().split()))

    seg = SegmentTree(n)

    # Room n is the destination.
    seg.update(n - 1, 0, 1)

    for i in range(n - 1, 0, -1):
        # Convert 1-based room indices to 0-based segment-tree indices.
        left = i
        right = i + k[i] - 1

        best, ways = seg.query(left, right)

        dp_i = c[i] + best
        seg.update(i - 1, dp_i, ways)

    answer, ways = seg.query(0, 0)
    print(answer, ways % MOD)

if __name__ == "__main__":
    solve()
```セグメント ツリーには、単一の最大値ではなく、すべてのノードでペアが保存されます。 最初のコンポーネントはそのセグメント内の最高のコイン合計であり、2 番目のコンポーネントはその最高の値に達するパスの数をカウントします。 

の`merge`操作は実装の中心部分です。 一方の値が大きい場合は、そのパス数のみが問題になります。 両側の値が同じ場合、最適パスの両方のグループが有効となり、それらのカウントはモジュロ (10^9+7) で加算されます。 の`NEG`value は、有効なルーム状態をまだ受け取っていない空のセグメントを表します。 

インデックス作成には特に注意が必要です。 動的計画法の方程式では 1 から始まる部屋のインデックスが使用されますが、セグメント ツリーでは 0 から始まる位置が使用されます。 部屋 (i) の場合、有効な宛先は 1 から始まる間隔 ([i+1,i+k_i]) です。 これらはゼロベースの位置 ([i,i+k_i-1]) となり、コード内でクエリされる範囲とまったく同じになります。 

最後の部屋はゼロベースの位置に挿入されます`n - 1`状態付き`(0, 1)`。 次に、1 つおきの部屋が右から左に処理されます。 (i+k_i\leq N) であるため、クエリ間隔は常にセグメント ツリー内に残ります。 

Python には整数オーバーフローの問題はありません。 最大パスは (10^5\cdot10^9=10^{14}) コインのオーダーで収集でき、Python はこれを直接表します。 ウェイの数のみモジュラー削減が必要であり、マージ操作では、等しい最適値が結合されるたびにその削減が実行されます。 

## 実用的な例

 ### サンプル 1

 入力は次のとおりです。```
5
0 0 0 0
4 3 2 1
```どの部屋にもコインはゼロなので、有効なパスはすべて最適です。 部屋を右から左に処理します。 

| 部屋(i) | クエリ間隔 | 最高の継続 | 方法 | (dp[i]) | (方法[i]) |
 | --- | --- | --- | --- | --- | --- |
 | 4 | [5、5] | 0 | 1 | 0 | 1 |
 | 3 | [4、5] | 0 | 2 | 0 | 2 |
 | 2 | [3、5] | 0 | 4 | 0 | 4 |
 | 1 | [2、5] | 0 | 8 | 0 | 8 |

 部屋 4 では、部屋 5 への直接ジャンプのみがあります。部屋 3 では、部屋 4 を経由するか、部屋 5 に直接ジャンプする 2 つの最適な継続があります。この数は、部屋 2 で再び 2 倍になり、最終的に部屋 1 で 8 になります。したがって、出力は次のようになります。`0 8`。 

### サンプル 2

 入力は次のとおりです。```
5
0 0 0 0
2 2 2 1
```到達可能な間隔が狭くなるため、存在するパスが少なくなります。 

| 部屋(i) | クエリ間隔 | 最高の継続 | 方法 | (dp[i]) | (方法[i]) |
 | --- | --- | --- | --- | --- | --- |
 | 4 | [5、5] | 0 | 1 | 0 | 1 |
 | 3 | [4、5] | 0 | 2 | 0 | 2 |
 | 2 | [3、4] | 0 | 3 | 0 | 3 |
 | 1 | [2、3] | 0 | 5 | 0 | 5 |

 部屋 2 では、部屋 3 と 4 を通るパスがそれぞれ 2 方向と 1 方向に寄与し、3 つの方向になります。 次に、部屋 1 は部屋 2 または部屋 3 のいずれかから開始することができ、(3+2=5) の最適なパスが得られます。 結果は`0 5`。 

これらのトレースは、キーの不変条件も示しています。セグメント ツリーには、現在の部屋の右側にあるすべての部屋の正しいペアが常に含まれているため、各範囲クエリには現在の遷移に必要な情報が正確に含まれています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(N\log N)) | (N-1) 個の部屋のそれぞれは、1 つの範囲クエリと 1 つのポイント更新を実行し、それぞれ (O(\log N)) かかります。 |
 | スペース | (O(N)) | セグメント ツリーには (O(N)) 個のノードが含まれており、入力配列も (O(N)) 個のメモリを使用します。 |

 (N=10^5) の場合、アルゴリズムは数十億回の後続スキャンではなく、およそ (N) 回のセグメント ツリー操作を実行します。 (O(N\log N)) の複雑さは意図した制約内に収まっており、メモリ使用量は 256 MB をはるかに下回っています。

import sys
import io

MOD = 10**9 + 7
NEG = -10**30

class SegmentTree:
    def __init__(self, n):
        size = 1
        while size < n:
            size <<= 1
        self.size = size
        self.best = [NEG] * (2 * size)
        self.ways = [0] * (2 * size)

    def merge(self, a, aw, b, bw):
        if a > b:
            return a, aw
        if b > a:
            return b, bw
        if a == NEG:
            return NEG, 0
        return a, (aw + bw) % MOD

    def update(self, pos, value, ways):
        pos += self.size
        self.best[pos] = value
        self.ways[pos] = ways

        pos >>= 1
        while pos:
            self.best[pos], self.ways[pos] = self.merge(
                self.best[pos << 1],
                self.ways[pos << 1],
                self.best[pos << 1 | 1],
                self.ways[pos << 1 | 1],
            )
            pos >>= 1

    def query(self, left, right):
        left += self.size
        right += self.size

        lb, lw = NEG, 0
        rb, rw = NEG, 0

        while left <= right:
            if left & 1:
                lb, lw = self.merge(
                    lb, lw, self.best[left], self.ways[left]
                )
                left += 1

            if not (right & 1):
                rb, rw = self.merge(
                    self.best[right], self.ways[right], rb, rw
                )
                right -= 1

            left >>= 1
            right >>= 1

        return self.merge(lb, lw, rb, rw)

def solve():
    n = int(input())
    c = [0] + list(map(int, input().split()))
    k = [0] + list(map(int, input().split()))

    seg = SegmentTree(n)
    seg.update(n - 1, 0, 1)

    for i in range(n - 1, 0, -1):
        best, ways = seg.query(i, i + k[i] - 1)
        seg.update(i - 1, c[i] + best, ways)

    ans, ways = seg.query(0, 0)
    print(ans, ways)

    old_stdin = sys.stdin
    old_input = input

    try:
        sys.stdin = io.StringIO(inp)
        input = sys.stdin.readline

        old_stdout = sys.stdout
        sys.stdout = io.StringIO()

        solve()
        result = sys.stdout.getvalue().strip()

        sys.stdout = old_stdout
        return result
    finally:
        sys.stdin = old_stdin
        input = old_input
