 ## 解決策
 ## 問題の理解

 次のサイズの正方形グリッドが与えられます。$N \times N$。 別の誰か、リディアは、左上隅から右下隅までの有効なパスをすでに選択しており、各ステップで右または下にのみ移動します。 彼女のパスは 2 文字で構成される文字列として提供され、各文字はグリッド内の 1 つの動きを表します。 

私たちのタスクは、同じ開始点から同じ目的地までの別の有効なパスを構築することです。これも右と下の移動のみを使用しますが、私たちのパスはリディアのパスと同一であってはいけないという制約があります。 言い換えれば、私たちのルートの少なくとも 1 つのステップは、彼女のステップとは位置が異なっている必要があるため、全体的な動きのシーケンスはまったく同じではありません。 

入力は単一のテスト ケース、つまりグリッドのサイズとリディアのパス文字列をエンコードします。 出力は、宛先に到達する同じ長さの有効な代替パスです。 

制約は十分小さいため、文字列の線形処理のみが必要です。 パスの長さは$2N - 2$、 どれでも$O(N)$施工は十分です。 バックトラッキングやパスの列挙を伴うものはすべて不必要であり、回避可能な複雑さが導入されます。 

このタイプの問題における単純な間違いは、右下隅で終了することを保証せずに、早い段階で逸脱するパスを構築しようとすることです。 たとえば、右ステップと下のステップの残りのバランスを追跡せずに手を「交換」しようとすると、無効なプレフィックスが生成される可能性があります。 

単一の文字だけを任意に変更しようとすると、別の微妙な問題が発生します。 リディアのパスが初期段階でほぼ一方向に単調である場合、コンテキスト内で慎重に処理しないと、単純な反転によって同じ完全なシーケンスが誤って再現される可能性があります。 

## アプローチ

 強引なアイデアは、右と下の動きのみを使用して左上から右下までのすべての有効なパスを試し、それぞれをリディアのパスと比較することです。 がある$\binom{2N-2}{N-1}$このようなパスは、次のように指数関数的に増加します。$N$。 中程度の場合でも$N$、パスの数がすでに天文学的な数に達しているため、これは完全に実行不可能になります。 

重要な点は、「特別な」異なるパスは必要なく、同一ではないパスだけが必要であるということです。 これにより、問題からほとんどすべての複雑さが解消されます。 有効なパスは複数の動きのセットによって完全に決定されるため、右と下の動きのカウントを保持する再配置は依然として有効な解決策につながります。 

リディアの道はまさに$N-1$右に移動し、$N-1$下に移動します。 すべての移動タイプを交換し、すべての右を下に、すべてのダウンを右に変えるパスを構築すると、有効性が自動的に保持されます。カウントは同一のままであるため、エンドポイントは依然として正確であり、各プレフィックスでグリッドの境界を超えることはありません。これは、単に反対方向のパターンで対称パスを横断しているだけだからです。 

重要な構造的洞察は、プレフィックスの実現可能性の範囲内に留まる限り、妥当性は各移動の順序ではなく、各移動の合計カウントにのみ依存し、この完全な反転の下で維持されるということです。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$N$そして文字列$S$リディアの軌跡を説明します。 文字列の長さは$2N - 2$、したがって、動きの順序を完全に決定します。 
2. 代替パスを 1 文字ずつ保存する空の結果リストを初期化します。 
3. の各文字をトラバースします。$S$左から右へ。 
4. 文字ごとに、直接変換を適用します。文字が「E」の場合は、結果に「S」を追加します。 「S」の場合は「E」を付加します。 これにより、各移動タイプの合計数を維持しながら、すべてのステップがリディアの対応するステップと異なることが保証されます。 
5. 完全な文字列を処理した後、結果リストを単一の文字列に結合して出力します。 

### なぜ効果があるのか

 構築されたパスには、リディアのパスとまったく同じ数の「E」と「S」の動きが含まれます。これは、すべての出現が 1 対 1 で交換されるためです。 これにより、右下隅に到達できるかどうかは水平方向と垂直方向の移動回数が正しいかどうかのみに依存するため、エンドポイントは同じままになります。 同時に、シーケンス内のすべての位置がリディアの対応する位置とは異なるため、パスが同一であることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    
    res = []
    for c in s:
        if c == 'E':
            res.append('S')
        else:
            res.append('E')
    
    print("".join(res))

if __name__ == "__main__":
    solve()
```実装はその構造を直接反映しています。 ループは入力文字列に対して 1 回のパスを実行し、線形な時間動作を保証します。 出力の構築にリストを使用するという決定により、Python で二次オーバーヘッドが発生することになる文字列連結の繰り返しが回避されます。 

微妙な点は、グリッド境界に対して追加の検証が必要ないことです。 変換では各移動の正確な数が保存されるため、最初から最後まで有効なラティス パスが暗黙的に維持されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n = int(sys.stdin.readline().strip())
    s = sys.stdin.readline().strip()
    
    res = []
    for c in s:
        res.append('S' if c == 'E' else 'E')
    
    return "".join(res)

# custom cases

 ## 特殊なケース

 例外的なケースは、すべての「E」が最初に移動するなど、リディアのパスが初期段階で完全に 1 方向で構成されている場合に発生します。 単一の位置のみを変更しようとする単純なアプローチでは、長いプレフィックスの構造が一致するパスが生成される可能性がありますが、完全な反転により、すべての位置が即座に異なることが保証されます。 

別のケースは最小のグリッドです。$N = 2$。 各タイプの動きは 1 つだけであるため、正しい解決策はその 1 つのペアを交換する必要があります。 アルゴリズムは各文字を個別に処理するため、これを自然に処理します。 

高度に交互するパスの場合、変換はパターンや構造に依存せず、文字ごとの反転のみに依存するため、有効性が維持されます。
