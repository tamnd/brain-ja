 ## 解決策
 ## 問題の理解

 サイズ n × n の正方形グリッドが与えられます。 リディアという名前の人は、左上隅から右下隅までのパスをすでに選択しており、右または下にのみ移動します。 このパスは長さ 2n − 2 の文字列としてエンコードされ、各文字は 1 つの移動 (右へのステップまたは下へのステップのいずれか) を表します。 

私たちのタスクは、私たちのパスがリディアのパスと同一にならないように、同じ移動制約を使用して、同じ開始点から同じ目的地までの他の有効なパスを構築することです。 

出力も同じ移動シンボルで構成される長さ 2n − 2 の文字列ですが、少なくとも 1 つの位置が指定された文字列と異なっていなければなりません。 

重要な制約は、両方のパスが有効なグリッド パスでなければならないということです。これは、各方向に正確に n − 1 回の移動が含まれていることを意味します。 これにより、常にグリッド内に留まり、右下隅に到達することが保証されます。 

入力サイズが十分小さいため線形スキャンは簡単ではありませんが、パスの有効性に対する制約により、カウントを保存しない限り、動きを任意に並べ替えることはできません。 

単純なアプローチでは、すべての有効なパスを生成し、それらをリディアのパスと比較しようとします。 有効なパスの数は組み合わせによるものであるため、これはすぐに失敗します。$\binom{2n-2}{n-1}$、n とともに指数関数的に増加します。 

実現可能性を維持しながら、リディアのパスを貪欲に「わずかに変更」しようとすると、より微妙な失敗例が現れます。 たとえば、実現可能性を確認せずに早期に手を変更すると、不可能な接尾辞を強制される可能性があります。 

障害シナリオの例:

 入力:```
3
E S E S
```カウントを考慮せずに最初の文字を反転して反対方向に一致させようとすると、後で 1 つの動きが多すぎて有効性が損なわれ、目的地に到達できなくなる可能性があります。 

実際の要件はもっと単純です。辞書編集的に制約されたパスや局所的に最適なパスではなく、どこかが異なる有効なパスのみが必要です。 

## アプローチ

 ブルートフォース手法では、(0, 0) から (n − 1, n − 1) までのすべてのパスを列挙し、それぞれをリディアのパスと照合して最初の不一致で停止します。 すべての有効なパスが考慮されるため、これは正しいですが、そのようなパスの数は n とともに指数関数的に増加するため、中程度の値であってもこれは実行不可能になります。 最悪の場合、おおよそ次のようなことが考えられます。$O(2^{2n})$候補配列。 

重要な観察は、妥当性と差異を超える構造は必要ないということです。 同一でない有効なパスはどれでも受け入れられます。 これにより、E および S 移動の正しい数を維持することを除いて、すべての順序制約が削除されます。 

リディアのパスには正確に n − 1 個の E の動きと n − 1 個の S の動きが含まれているため、カウントをグローバルに維持しながら各動きを独立して変換することで、別の有効なパスを構築できます。 最も単純な一貫した変換は、すべての手を交換することです。つまり、各 E を S に置き換え、各 S を E に置き換えます。これにより、複数の手のセットが交換下で保存されるため、各手の正確に n − 1 が生成されることが保証されます。 

この構造では、リディアのパスとの違いも保証されます。すべての位置が反転されるため、文字列が E と S の交換で対称でない限り、等価性は不可能です。これは、空ではない有効なパスでは起こり得ません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | O(2^(2n)) | O(2n) | 遅すぎる |
 | それぞれの動きを入れ替える | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数 n と長さ 2n − 2 のパス文字列 s を読み取ります。この文字列はグリッド上のリディアの動きをエンコードします。 
2. 空の結果文字列 r を作成します。 代替パスを文字ごとに構築していきます。 
3. s の各文字を繰り返し処理します。 位置ごとに決定論的変換を適用します。文字が「E」の場合は r に「S」を追加し、「S」の場合は r に「E」を追加します。 これにより、すべての動きが独立して反転されることが保証されます。 
4. すべての文字を処理した後、最終パスとして r を出力します。 

### なぜ効果があるのか

 この構築では、すべての E が S に変換され、すべての S が E に変換されるため、各移動の合計数が保存されます。リディアのパスにはすでに各方向の正確に n − 1 が含まれているため、変換されたパスにも各方向の正確に n − 1 が含まれており、最初から最後まで有効なグリッド パスのままであることが保証されます。 2 つのパスは文字ごとの全単射反転によりすべての位置で異なるため、元のパスと同等にすることは不可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    
    res = []
    for c in s:
        if c == 'E':
            res.append('S')
        else:
            res.append('E')
    
    print("".join(res))

if __name__ == "__main__":
    solve()
```実装は入力パスを読み取り、単一パスで出力を構築します。 変換ロジックは文字ごとにローカルであるため、プレフィックス制約やグリッド座標を追跡する必要がありません。 唯一の微妙な点は、入力文字列が完全に消費され、n とパスの読み取り以外に追加の解析が必要ないことを保証することです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n = int(input().strip())
    s = input().strip()
    
    res = []
    for c in s:
        res.append('S' if c == 'E' else 'E')
    return "".join(res)

# basic sample
assert run("3\nEESSSS\n") == "SSEEEE"

# minimal case
assert run("2\nES\n") == "SE"

# all same direction alternating edge
assert run("3\nESES\n") == "SESE"

# larger balanced case
assert run("4\nEESSEESS\n") == "SSEESSEE"

# symmetric pattern check
assert run("3\nEEE SSS".replace(" ","")) == "SSS EEE".replace(" ","")
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | n=2、ES | SE | 最小限のグリッドの正確さ |
 | n=3、EESSSS | そうだね | 完全な反転の正しさ |
 | n=4 交互 | 逆パターン | 交互構造の安定性 |
 | n=3 すべて E、その後 S | すべて S、次に E | 境界グループ化の正確性 |

 ## 特殊なケース

 1 つのエッジ ケースは最小のグリッドで、n = 2、パス長は 2 です。入力は ES のようなものである可能性があります。 アルゴリズムは各文字を反転して SE を生成しますが、このパスには 1 つの E と 1 つの S が含まれているため、有効なパスのままになります。 

もう 1 つのケースは、ESESESE のように、リディアのパスが厳密に交互になる場合です。 各文字が隣接する文字から独立しているため、変換は引き続き機能します。そのため、交互パターンは構造的には保持されますが、反転され、SESESES が生成され、これは依然として有効です。 

3 番目のケースは、すべての E 移動の後にすべての S 移動が続くなど、パスがグループ化されている場合です。 ここでも、反転するとすべての S に続いてすべての E が生成され、完全に異なるルートを保証しながら正確なカウントと有効性が維持されます。
