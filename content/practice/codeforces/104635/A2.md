 ## 解決策
 ## 問題の理解

 10 進数の文字列として書かれた数値が与えられます。 タスクは、この数値を他の 2 つの数値に分割し、それらを加算すると、通常の 10 進数の加算で桁ごとに元の数値が正確に再構成され、結果として得られる 2 つの数値のどちらにも数字 4 が含まれないようにすることです。 

これは、元の数値の各桁を取得し、その値を 2 つの新しい数値 A と B に分配する方法を決定して、A + B が元の数値と等しくなるようにする方法を決定するものと考えてください。どちらの構築された数値にも 4 を入れることはありません。 

入力は、文字列として書き込まれた単一の整数です。 出力は、A と B を表す同じ長さの 2 つの整数です。 

これは Codeforces の文字列操作の問題であるため、制約は暗黙的に大きくなります。 桁数は最大 10^5 以上になる可能性があり、整数全体にわたるキャリーを複数回使用して算術演算をシミュレートしたり、組み合わせを検索しようとしたりするアプローチは除外されます。 桁数の二次関数はすべてすぐに失敗します。 このソリューションは、各桁を個別に処理することで線形時間で機能する必要があります。 

数字に 0 または 4 が含まれる場合、微妙なエッジ ケースが発生します。単純な考えでは、すべてを 1 つの数字に代入し、もう 1 つの数字をゼロのままにすることも考えられますが、数字が 4 の場合、4 は禁止されているため、これは失敗します。 もう 1 つの潜在的な間違いは、グローバル キャリー構造を維持しながら桁を貪欲に調整しようとすることですが、これは不必要でエラーが発生しやすくなります。 重要な特性は、干渉を引き起こすことなく各桁を独立して処理できることです。 

たとえば、入力が 940 の場合、単純な分割では A = 940 および B = 0 が試行される可能性がありますが、A には 4 が含まれるため、これは無効です。正解は A = 930 および B = 010 となり、正しく合計され、両方の数値の桁 4 が回避されます。 

## アプローチ

 強引なアイデアは、これを数字分解問題として扱い、入力の各数字をその合計が 2 つの数字に分割し、結果として得られる数字が数字 4 を含まないという制約を満たすかどうかを検証することです。単純な実装では、各数字について考えられるすべての分割を試し、桁上げを伝播し、妥当性をグローバルにチェックする可能性があります。 各桁のオプションがわずかしかなかったとしても、すべてのポジションにわたるキャリーを管理する必要があるため、組み合わせ状態空間が作成されます。 最悪の場合、各位置は以前のキャリー状態と以前のすべての決定に依存するため、桁数が増えるにつれて指数関数的に増加します。 

重要な観察は、実際には何かを最適化したり、桁ごとに複数の分解を考慮したりする必要がないということです。 必要なのは有効な構造を 1 つだけです。 キャリーが必要ないことを確認すれば、各桁を独立して処理できます。 これは、キャリーを生成せずに元の数字と正確に合計される数字ごとの分割を選択することを示唆しています。 これを保証する最も簡単な方法は、各位置が独立して寄与することを保証することです。つまり、キャリー伝播を行わずに A[i] + B[i] = N[i] になります。 

その考えを修正すると、構築は決定論的になります。 4 を除くすべての数字について、それを 1 つの数字に完全に割り当て、もう 1 つの数字には 0 を与えることができます。 数字 4 については、2 と 2 に分割します。これにより、数字 4 が出現しないことが保証され、数字ごとの正確性が維持されます。

 ## アルゴリズムのチュートリアル

1. 入力数値を文字列として読み取り、整数に変換せずに 1 桁ずつ処理できるようにします。 これによりオーバーフローが回避され、ロジックが純粋に位置に保たれます。 
2. 構築された数字を格納する 2 つの空のリストまたは文字列 A と B を初期化します。 
3. 入力文字列内の各文字の数字 d を反復処理します。 各ステップの目標は、a + b = d となり、a も b も 4 に等しくなるような 2 つの数字 a と b を選択することです。 
4. 現在の桁が '4' の場合、a = 2 および b = 2 を割り当てます。これは、桁上げを防止しながら、禁止された桁の導入を回避する唯一の安全な分割です。 
5. それ以外の場合は、a = int(d) および b = 0 を割り当てます。これにより、B をクリーンかつシンプルに保ちながら、A の値は変更されません。 
6. 選択した数字をそれぞれ A と B に追加し、文字列として構築します。 
7. すべての桁を処理した後、A と B を出力します。 

### なぜ効果があるのか

 この構造により、すべての位置で、A と B の数字の合計が元の数字に等しいことが保証されます。また、合計が 9 を超えるペアは決して生成されないため、位置間のキャリーは発生しません。 この桁間の独立性により、ローカルな正確性がグローバルな正確性を意味します。 唯一の特殊なケースは数字 4 で、これは均等に分割することで解決され、数字の合計を維持しながら禁止された数字を完全に回避します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    a = []
    b = []
    
    for ch in s:
        if ch == '4':
            a.append('2')
            b.append('2')
        else:
            a.append(ch)
            b.append('0')
    
    print("".join(a), "".join(b))

if __name__ == "__main__":
    solve()
```このソリューションは数値を文字列として読み取り、1 回のパスで 2 つの出力を構築します。 重要な実装の詳細は、整数と文字列の間で整数と文字列の間で相互変換を決して行わないことです。これにより、パフォーマンスの問題と偶発的なキャリー ロジックの両方が回避されます。 

唯一重要な決定は、数字 4 の処理です。(2, 2) を割り当てることで、有効性と正確性の両方が保証されます。 他のすべての数字は制約に違反しないため、片側に完全に割り当てても安全です。

 ## 特殊なケース

 重要なエッジ ケースは、入力にゼロのみが含まれる場合です。 入力用`0`、アルゴリズムは生成します`0`そして`0`、禁止された数字が表示されず、合計が正しいままであるため、これは有効です。 

もう 1 つのエッジ ケースは 1 桁の 4 です。アルゴリズムはそれを次のように直接マッピングします。`2`そして`2`、周囲のコンテキストやキャリー処理を必要とせずに有効な分解を生成します。 

より微妙なケースは、次のように数字が 4 で終わる場合です。`1234`。 最後の桁は次のようになります`2`そして`2`、以前の桁は変更されないため、キャリーが前後に伝播することはなく、正確性が維持されます。
