 ## 解決策
 ## 問題の理解

 文字列として書かれた非常に大きな非負の整数が与えられます。 タスクは、この数値を 2 つの非負の整数に分割し、それらを A と B と呼びます。これにより、これらを桁ごとに加算すると元の数値が復元され、A も B も 10 進表現に数字 4 が含まれません。 

重要な制約は、算術の難しさに関するものではなく、表現に関するものです。 A と B の合計が元の数値と一致し、両方の作成された数値が 4 という数字を完全に避けている限り、A と B を桁ごとに自由に選択できます。 入力は非常に大きくなり、標準の整数制限をはるかに超える可能性があるため、すべての操作は文字列表現に対して実行する必要があります。 

複雑さの観点から見ると、入力の長さが重要な要素となります。 数値が最大 10^5 桁の場合、2 次的な解法や、ループ内で文字列の再構築を繰り返すことを伴う解法は失敗します。 唯一の実行可能なアプローチは、桁数が線形であることです。 

入力に慎重な分割を強いられる数字が含まれている場合、微妙なエッジケースが発生します。 たとえば、数字が 4 の場合、それを A または B に直接割り当てることはできません。これは、直ちに制約に違反するためです。 単純なアプローチで後処理や調整を行うことによってこれを「修正」しようとすると、合計の不変条件が崩れる危険があります。 

たとえば、次の入力を考えてみましょう。```
44
```不注意に試行すると、両方の数字を直接割り当てて、A = 44 および B = 0 が生成される可能性がありますが、A には 4 が含まれるため無効です。「構築後に 4 を別のものに置き換える」試みでも、合計の関係が壊れる可能性があります。 

最も難しいのは、桁ごとの合計制約と禁止桁制約を同時に満たさなければならないことです。 

## アプローチ

 この強引なアイデアは、a + b が元の数字と等しく、a も b も 4 にならないように、元の数値の各桁を 2 つの数字 (a、b) に分割するあらゆる方法を試すことです。各桁について、すべての有効なペアを列挙し、それらを文字列全体で結合することができます。 

これは、キャリー伝播を強制しない場合、キャリーなしの加算に関して各桁が独立しているため機能します。 ただし、一般的な桁の分割を処理しようとすると、組み合わせの数は数値の長さが指数関数的に増加します。 30 桁の場合でも、各位置に複数の有効な分割が存在する可能性があり、2^n またはそれより悪い可能性が生じるため、これは実行不可能になります。 

重要な観察は、いかなる方法でも A または B を最適化するように求められていないということです。 私たちに必要なのは存在だけです。 これにより、貪欲な桁ごとの構築が可能になります。 入力内のすべての数字 d に対して、a + b = d となるようにペア (a, b) を直接割り当て、両方の数字が 4 を回避します。最も単純で安定した構造は次のとおりです。 

d が 4 でない場合は、a = d および b = 0 を割り当てます。 

d が 4 の場合、a = 1 および b = 3 を割り当てます。 

これが機能するのは、1 + 3 = 4 であり、1 にも 3 にも禁止された数字が含まれていないためです。 他のすべての数字は、A に配置され、0 が B に配置された時点ですでに制約を満たしています。 

数字の独立性は重要な構造特性です。 単一の位置内で複数桁の分解を決して許可しないため、桁上げの相互作用はありません。

 ## アルゴリズムのチュートリアル

 1. オーバーフローすることなく任意の大きな値を安全に処理できるように、入力数値を文字列として読み取ります。 
2. 結果として得られる 2 つの数値の桁を格納する 2 つの空のリスト A と B を初期化します。 
3. 入力文字列の各文字の数字 d を反復処理します。 
4. d が「4」でない場合は、A に d を追加し、B に「0」を追加します。 
5. d が「4」の場合、A に「1」を、B に「3」を追加します。 
6. すべての数字を処理した後、A と B を文字列に結合します。 
7. A と B をスペースで区切って出力します。 

ステップ 5 の選択は、唯一重要な部分です。 特に 4 を 1 と 3 に分割しました。これは、どちらも有効な数字であり、その合計が正確に 4 になるためであり、各位置で局所的に正確性が保証されます。 

### なぜ効果があるのか

 このアルゴリズムは桁ごとの不変式に依存しています。つまり、すべての位置 i で、桁上げが導入または要求されることなく、A[i] + B[i] が位置 i の元の桁と等しいことを保証します。 各桁は独立して処理され、9 を超える桁が生成されるステップはないため、位置をまたぐ相互作用は発生しません。 これにより、桁ごとの合計が元の数値に正確に連結されることが保証され、また、構築された数値に数字 4 が含まれないことも保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    a = []
    b = []

    for ch in s:
        if ch == '4':
            a.append('1')
            b.append('3')
        else:
            a.append(ch)
            b.append('0')

    print("".join(a), "".join(b))

if __name__ == "__main__":
    solve()
```このソリューションでは、両方の数値を並行して構築します。 Python では文字列は不変であり、連結を繰り返すとパフォーマンスが二次時間まで低下するため、文字列の連結を繰り返す代わりにリストを使用することが不可欠です。 

ループ内のロジックは、桁分割ルールを直接エンコードします。 各桁は独立しているため、追加の状態は必要ありません。

 ## 特殊なケース

 最も重要なエッジ ケースは、入力が数字 4 だけで構成される場合です。その場合、すべての位置が強制的に分割 (1、3) に入れられ、アルゴリズムはすべて 1 とすべて 3 の 2 つの文字列を生成します。 入力の場合:```
444
```このプロセスでは、A = 111 および B = 333 が得られます。各位置は独立して合計制約を満たしているため、グローバルな結果は有効なままです。 

もう 1 つのケースは、4 がまったくない場合です。 アルゴリズムは特別な分割をトリガーしないため、A は元の数値になり、B はすべて 0 になります。 入力の場合:```
709
```A = 709 および B = 000 が得られますが、どちらの数値にも 4 が含まれていないため、制約は自明に満たされます。 

境界ケースは 1 桁の入力です。 アルゴリズムは位置コンテキストやキャリーに依存しないため、同じロジックが変更なしで適用されます。
