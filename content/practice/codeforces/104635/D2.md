 ## 解決策
 ## 問題の理解

 1 から N までのラベルが付いた隠れたポジションのセットが与えられています。これらのポジションの一部は「壊れている」もので、残りは「機能中」です。 壊れた位置の数は直接与えられませんが、システムに対話的に問い合わせることができます。 

各クエリは、長さ N のバイナリ文字列の送信で構成されます。ジャッジは、作業位置に対応するビットのみを取得し、相対的な順序を維持して、それらをより短い文字列に連結することによって応答します。 言い換えれば、クエリ文字列から壊れた位置をすべて削除した場合に得られる応答が返されます。 

タスクは、できるだけ少ないクエリを使用して、どの位置が壊れているかを正確に特定することです。 

N が大きくなる可能性がある (この問題ファミリーの完全版では最大約 10^5) という制約は、各位置を個別にテストしようとするアプローチが遅すぎることを意味します。 N 個のクエリによる線形スキャンは、各クエリが非常に安価な場合にのみ許容されますが、通常は相互作用ルールによって不要になります。 代わりに、応答の構造は、すべてのインデックスにわたって情報を並行してエンコードすることを強く示唆しています。 

ブレークポジションがない場合、または 1 つのポジションを除くすべてのポジションがブレークしている場合、微妙なエッジケースが発生します。 すべてが機能する場合、すべてのクエリは元の文字列を変更せずに返すため、「短縮形の欠落」信号を想定するロジックは失敗します。 単一動作の場合、すべての応答はクエリごとに 1 文字だけであるため、列が 1 つだけ残っている場合でも再構築の一貫性が保たれている必要があります。 

## アプローチ

 強引なアイデアは、クエリ内で各位置を反転することで各位置を個別にテストし、他の位置は固定したままにして、そのステータスが明らかになるように出力が変化するかどうかを観察することです。 ただし、応答が壊れた位置を圧縮してしまうため、これはすぐにあいまいさに陥ります。これは、直接的な位置の対応が失われることを意味します。 各インデックスを分離しようとすると O(N) クエリが必要になり、各クエリは部分的な情報しか提供しないため、このアプローチは時間がかかり、概念的にも信頼性が低くなります。 

重要な洞察は、クエリを「インデックスごとのテスト」として考えるのをやめ、代わりにクエリをすべてのインデックスを一度に並列ビット エンコーディングとして扱うことです。 各インデックス i にバイナリ表現を割り当てると、すべてのインデックスの 1 つのビット位置を同時に要求するクエリを構築できます。 ジャッジの応答は、作業インデックス間の順序を維持するため、すべての応答列は、すべてのクエリにわたって同じ存続インデックスに一貫して対応します。 

約 log N 個のクエリを発行し、各クエリがインデックスの 1 ビットをエンコードすることで、すべての作業位置の完全な ID を再構築できます。 作業セットがわかったら、壊れた位置は単なる補完になります。 

重要な構造特性は、作業インデックスの順序がすべての応答にわたって維持されることです。 この位置合わせにより、応答文字列内の各位置を、異なるクエリ間で同じ元のインデックスに属しているものとして扱うことが可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | インデックスごとのブルート フォース | O(N^2) の相互作用 | O(N) | 遅すぎる/信頼性が低い |
 | ビットごとのエンコーディングの再構築 | O(N log N) 前処理 / O(log N) クエリ | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1 から N までラベル付けされた N 個の位置を仮定し、B = ⌈log2 N⌉ とします。

1. 0 から B-1 までの各ビット k について、位置 i に i の k 番目のビットが含まれるクエリ文字列を構築します。 これにより、すべてのインデックスがそのビット位置で同時にエンコードされます。 
2. このクエリを送信し、応答文字列 r_k を受け取ります。 この文字列には、ビット位置 k にあるすべての作業インデックスのビットが、すべてのクエリにわたって同じ相対順序で正確に含まれています。 
3. すべての応答文字列 r_k を保存します。 各 r_k は、作業インデックスの数に等しい長さを持ちます。 
4. 応答文字列内の位置 j ごとに、すべての r_k から j 番目の文字を取得して 2 進数を再構成します。 この 2 進数は、j 番目の作業位置の元のインデックスに対応します。 
5. 再構築されたすべてのインデックスを動作中としてマークします。 
6. 再構築されたワーキングセットにない 1 ～ N のインデックスは壊れているので出力します。 

これが機能する理由は、ジャッジがすべてのクエリにわたって生き残った要素の相対的な順序を保持するため、すべての応答 r_k の j 番目の文字が常に同じ基礎となる作業インデックスに対応するためです。 

### なぜ効果があるのか

 各クエリは、すべてのインデックスを 1 つのビット次元に投影し、残りの要素を並べ替えることなく、壊れたインデックスを除外します。 これは、すべてのクエリの i 番目に残っている要素が、すべてのビット クエリにわたって同じ元のインデックスに対応することを意味します。 その結果、収集された応答の各列は 1 つの作業インデックスの一貫したバイナリ エンコーディングを形成し、インデックス間の混合は不可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    
    # number of bits needed
    b = n.bit_length()
    
    res = []
    
    # build bitwise queries
    for k in range(b):
        query = []
        for i in range(1, n + 1):
            if (i >> k) & 1:
                query.append('1')
            else:
                query.append('0')
        print("".join(query))
        sys.stdout.flush()
        
        r = input().strip()
        res.append(r)
    
    w = len(res[0])
    working = set()
    
    for j in range(w):
        idx = 0
        for k in range(b):
            if res[k][j] == '1':
                idx |= (1 << k)
        working.add(idx)
    
    broken = []
    for i in range(1, n + 1):
        if i not in working:
            broken.append(i)
    
    print("!".join(map(str, broken)) if broken else "!")

if __name__ == "__main__":
    solve()
```実装の中核はビットクエリの構築です。 各クエリは決定的であり、ビット位置のみに依存するため、以前の応答に基づいて適応する必要はありません。 

再構成ステップは、各列インデックス j をすべての応答にわたる固定された生存者 ID として扱うことに依存します。 k に対するビット単位の OR により、その生存者の元のインデックスが再構築されます。 唯一の微妙な点は、インデックス付けの一貫性を確保することですが、これは問題の順序が維持されることで保証されます。 

最後に、補集合を計算します。 これにより、壊れたインデックスに関する曖昧さが回避され、壊れた要素がないなどの極端な場合でも正確さが保証されます。 

## 実用的な例

 N = 5 で作業インデックスが {1, 3, 5} である小さなケースを考えてみましょう。 この場合、応答にはクエリごとに常に 3 文字が含まれます。 

k = 0 (最下位ビット) の場合、クエリは [1,0,1,0,1]、応答は [1,1,1] です。 

k = 1 の場合、クエリは [0,1,1,0,0]、応答は [0,1,0] です。 

k = 2 の場合、クエリは [0,0,0,1,1]、応答は [0,0,1] です。 

次に、列ごとに再構成します。 

| j | r0[j] | r1[j] | r2[j] | 再構築されたインデックス |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 0 | 1 |
 | 2 | 1 | 1 | 0 | 3 |
 | 3 | 1 | 0 | 1 | 5 |

 これにより、各列が単一の作業インデックスに対応していることが確認されます。 

ここで、インデックス 2 のみが機能する N = 4 を考えてみましょう。 

すべてのクエリは単一文字の文字列を返し、常にインデックス 2 の値を返します。再構築ではインデックス 2 のみが生成され、その他はすべて壊れているとして正しく分類されます。 

これらの例は、ワーキング セットが最小または最大の場合でも、列の一貫性が維持されることを確認しています。

 ## 特殊なケース

 すべての位置が機能している場合、すべてのクエリは構築された文字列を正確に返します。 再構築ステップでは 1 から N までのすべてのインデックスが生成され、最後の補数は空であるため、出力は壊れた位置を正確に報告しません。 

1 つの位置のみが機能する場合、すべてのクエリは 1 つの文字を返します。 再構築ループは 1 つの列を処理し、バイナリ表現からそのインデックスを正しく再構築します。これは、アルゴリズムが複数の生存者に依存していないことを示しています。 

1 つを除くすべての位置が壊れている場合、応答の長さは 1 になり、すべての列が単一の一貫したインデックスに折りたたまれます。 各ビット クエリはすべての応答にわたって整列されたままであるため、ビットごとの再構築は引き続き機能します。
