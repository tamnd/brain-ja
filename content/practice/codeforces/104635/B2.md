 ## 解決策
 ## 問題の理解

 正方形グリッドの左上隅から始まり右下隅に到達する単一のグリッド パスが与えられます。 パスは一連のユニットの移動として記述され、各移動は右または下に進みます。 このシーケンスは、グリッドを通る 1 つの有効なルートを表します。 

私たちのタスクは、新しいルートが指定されたルートと同一にならないように、同じ開始点から同じ終了点まで別の有効なルートを構築することです。 指定されたパスで使用されるセルやエッジを回避する必要はなく、最終的な移動シーケンスが少なくとも 1 つの位置でそれと異なるだけで済みます。 

したがって、入力はグリッド上の制約されたウォークをエンコードし、出力は開始と終了の制約が同一であるがステップ シーケンスが異なる別のウォークをエンコードする必要があります。 

この問題の典型的な B2 バージョンに含まれる制約は十分に大きいため、パスの長さは最大約 20 万手になる可能性があります。 これにより、複数の候補パスを明示的に列挙または比較しようとする戦略は即座に除外されます。 どのソリューションも、指定された文字列を線形時間で処理し、単一パスで回答を構築する必要があります。 

グリッドが最小の場合、微妙なエッジケースが発生します。 グリッドのサイズが 2 x 2 の場合、パスの長さはちょうど 2 移動分になります。 たとえば、入力が次の場合`RD`有効性を維持せずにパスを「シフト」または「回転」しようとすると、誤って無効なシーケンスが生成されたり、同じパスが再現されたりする可能性があります。 もう 1 つのエッジ ケースは、すべての権利の後にすべてのダウンが続くなど、入力パスが均一である場合です。 この構造化されたケースでも、不注意な変換により偶然一致しただけではなく、出力はどこかで異なっているはずです。 

## アプローチ

 ブルートフォース手法では、左上から右下まですべての有効なパスを生成し、指定されたパスと等しくないパスを選択しようとします。 長さが約 2n の有効なグリッド パスには、二項係数のオーダーで指数関数的に多くの可能性があります。 適度な n の場合でも、パスの数は 2^(2n) / sqrt(n) のように増加し、列挙できなくなります。 ボトルネックは、有効な四球の組み合わせが爆発的に増加することです。 

重要な観察は、すべてのパスについて推論する必要はまったくないということです。 出力が 1 つの固定シーケンスと異なることを確認するだけで済みます。 これは、少なくとも 1 つの位置が異なることを保証しながら、有効なパスを決定論的に構築できることを意味します。 

有効なパスは元のパスとまったく同じ数の右への移動と下への移動で構成されているため、カウントを維持しながら各ステップを独立して安全に変換できます。 すべての右の動きを下の動き、すべての下の動きを右の動きと交換した場合、結果のシーケンスには依然として同じ複数の動きセットが含まれているため、開始から終了まで有効なパスが形成されます。 同時に、パスが空でない限り (空ではありませんが)、すべての位置で移動が反転されるため、新しいパスは元のパスとは異なることが保証されます。 

これにより、問題は文字ごとに定数時間変換を行う単一のリニア スキャンに軽減されます。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元のパスを表す整数 n と文字列 s を読み取ります。 文字列の長さは 2n - 2 で、各文字は次のいずれかです。`R`または`D`。 
2. 空のリストまたは配列を初期化して、回答を作成します。 これにより、文字列の連結が繰り返されることが回避され、二次的な動作が発生する可能性があります。 
3. 入力文字列内の各文字を繰り返し処理します。 文字ごとに、反対方向を構築します。文字が`R`、追加`D`出力へ。 もしそうなら`D`、追加`R`。 
4. すべての文字を処理した後、蓄積されたリストを 1 つの文字列に結合して出力します。 

変換は各ステップに独立して適用されるため、パスの形状に関する全体的な推論は必要ありません。 水平方向と垂直方向の移動回数は変更されないため、パスの有効性は自動的に保持されます。 

### なぜ効果があるのか

 左上から右下までのグリッド パスは、複数の移動セット、特に移動のカウントによって完全に決定されます。`R`そして`D`。 各移動を交換すると、これらのカウントが正確に保存されます。 到達可能性は各方向の番号が正しいかどうかのみに依存するため、結果として得られるシーケンスは常に有効なパスを形成します。 出力はインデックスごとに入力と異なるため、元のパスと同一ではないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    
    res = []
    for c in s:
        if c == 'R':
            res.append('D')
        else:
            res.append('R')
    
    print(''.join(res))

if __name__ == "__main__":
    solve()
```このソリューションは線形時間で入力を読み取り、リスト アキュムレーターを使用して答えを構築します。 中心となる変換は文字の直接交換であり、無効な中間状態のリスクを回避します。 

唯一の微妙な実装の詳細は、ループ内での文字列の連結を避けることです。 Python 文字列は不変であるため、連結を繰り返すと、最大入力サイズで二次時間までパフォーマンスが低下します。

 ## 特殊なケース

 n = 2 など、パスの長さが最小になる最小のグリッド サイズの場合、入力には正確に 2 つの動きが含まれます。 アルゴリズムはそれぞれの動きを独立して反転するため、この縮退したケースでも出力は有効かつ明確なままになります。 例えば、`RD`になる`DR`、移動回数が保持されるため、開始制約と終了制約は依然として満たされます。 

同じ動きが長く続くなど、高度に構造化された入力の場合、アルゴリズムは均一に動作します。 入力が`RRRRDDDD`、各文字は独立して反転されて生成されます。`DDDDRRRR`。 変換は位置に依存しないため、入力の対称性が強い場合でもパスの有効性が崩れるリスクはありません。
