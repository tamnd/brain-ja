 ## 解決策
 ## 問題の理解

 10 進数で書かれた 1 つの大きな整数が与えられ、それを合計が元の数値に等しい 2 つの非負の整数に分割する必要があります。 追加の制約は、結果として得られる 2 つの数値のいずれも、10 進表現に数字 4 を含めることができないことです。 

入力について考えると便利な方法は、入力は算術的に扱うべき数値ではなく、桁ごとに分解できる桁の文字列であるということです。 出力は数値を表す 2 つの文字列であり、それらの桁ごとの合計は元の入力を正確に再構築する必要があります。 

通常、制約は十分に大きく、数値は最大で数万桁になることがあります。 これにより、整数演算や減算の繰り返しを伴うアプローチは即座に排除されます。 桁ごとに定数を処理するソリューションであればどれでも受け入れられますが、桁数が 2 次のものであれば問題ありません。 私たちが避けなければならないのは、プリフィックスの再計算や単純な方法での桁上げによる加算のシミュレーションを伴うものです。 

数字が 4 に等しい場合、微妙なエッジ ケースが発生します。制約を考慮せずに単純に数字を任意に分割しようとすると、出力の 1 つに誤って 4 が残ってしまう可能性があります。 たとえば、入力桁が 4 で、それを 1 つの数字にすべて割り当てると、その数字は無効になります。 もう 1 つのエッジ ケースは先行ゼロです。出力の 1 つに当然先行ゼロが含まれる可能性がありますが、正規の整数書式設定ではなく数字列を扱っているため、これは許容されます。 

## アプローチ

 強引なアイデアは、A + B が N に等しく、どちらにも数字 4 が含まれない 2 つの数字 A と B を見つけるとして問題を扱うことです。キャリーと数字の分割を分散するためのすべての可能な方法を反復したり、候補ペアを生成して妥当性をチェックしたりすることさえ想像できます。 たとえ中程度のサイズの入力であっても、可能な分解の数は桁数に応じて指数関数的に増加するため、これはすぐに実行不可能になります。 任意の分割を試みると、各桁は事実上決定空間を 2 倍にし、d 桁について 2^d 通りの可能性が生じます。 

重要な点は、何かを最適化したり、独自の分解を見つけたりする必要がないということです。 有効な分解のみが必要です。 これにより、数字間の結合がすべて除去されます。 どちらの出力数値も最小化または最大化する必要はなく、合計を保持して出力の桁 4 を避けるだけでよいため、入力の各桁は独立して処理できます。 

これにより、直接構築戦略が可能になります。つまり、各桁を独立して処理し、どの桁も 4 にならないように、それを 2 つの出力数値に割り当てます。最も単純で安全な分割は、一方の数値に元の数値から選択した部分を除いたすべての数値を与え、もう一方の数値に残りを与えることです。 特に、4 が表示されると、それを 3 と 1 に分割します。他のすべての数字については、最初の数字に数字全体を割り当て、2 番目の数字に 0 を割り当てることができます。 

これが機能するのは、ここでは桁上げのない桁ごとの加算で十分であるためです。すべての位置で、構築された桁の合計が元の桁と正確に等しいことを保証することで、桁上げの相互作用を意図的に回避しています。

 ## アルゴリズムのチュートリアル

 入力数値と同じ長さの 2 つの文字列 A と B を作成します。

1. 各桁を個別に処理できるように、入力数値を文字列として読み取ります。 これにより、整数のオーバーフローや不必要な演算が回避されます。 
2. 2 つの空の文字列 A と B を初期化します。これらには、結果として得られる 2 つの数値の桁が格納されます。 
3. 入力文字列内の各文字 d を反復処理します。 各位置で、この数字を A と B に分割する方法を決定します。 
4. 現在の数字が「4」の場合、A に「3」を追加し、B に「1」を追加します。これにより、この位置の合計を保持しながら、A にも B にも禁止された数字が含まれないことが保証されます。 
5. 数字が '4' 以外の場合、その数字自体を A に追加し、'0' を B に追加します。これにより、B がクリーンでシンプルなままであると同時に、寄与が完全に 1 つの数字に保たれます。 
6. すべての桁を処理した後、A と B を 2 つの別々の整数として出力します。 

なぜそれが機能するのかは、桁ごとの不変条件に帰着します。 すべてのインデックスで、A に配置された数字と B に配置された数字は元の数字に等しく、構築された数字が 4 になることはありません。桁上げを導入しないため、各位置は独立しており、桁ごとの等しいことは、結果の合計が完全に数値的に等しいことを直接意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    a = []
    b = []

    for ch in s:
        if ch == '4':
            a.append('3')
            b.append('1')
        else:
            a.append(ch)
            b.append('0')

    print("".join(a), "".join(b))

if __name__ == "__main__":
    solve()
```この実装は、桁ごとの構造を正確に反映しています。 文字列を繰り返し連結する代わりに、効率性を高めるために 2 つの文字配列を構築します。Python では不変性のため 2 次になります。 必要な分岐ロジックは数字 4 の特別な処理だけです。 それ以外はすべて直接渡されます。 

微妙な点は、2 番目の数値から先行ゼロを削除する必要がないことです。 B がゼロで始まっている場合でも、このコンテキストでは依然として負でない整数の有効な表現です。 

## 実用的な例

 インプットを考慮する`940`。 

| 数字 | これまでのところ | これまでのB | コメント |
 | --- | --- | --- | --- |
 | 9 | 9 | 0 | 4 桁以外のコピー |
 | 4 | 93 | 01 | 4 を 3 と 1 に分割する |
 | 0 | 930 | 010 | ゼロは A | になります。 

出力は A = 930、B = 010 です。それらの合計は 940 で、どちらにも数字 4 は含まれません。 

ここで考えてみましょう`444`。 

| 数字 | これまでのところ | これまでのB | コメント |
 | --- | --- | --- | --- |
 | 4 | 3 | 1 | 分割 |
 | 4 | 33 | 11 | 分割 |
 | 4 | 333 | 111 | 分割 |

 出力は A = 333、B = 111 で、合計はちょうど 444 です。このケースでは、制約された数字の繰り返しの出現が強調され、位置間の独立性が十分であることが示されています。 

## 複雑さの分析

import sys, io

def run(inp: str) -> str:

        solve()
    return out.getvalue().strip()

 ## 特殊なケース

 次のような最小限の入力`4`最も直接的なストレステストです。 アルゴリズムは 1 つの数字を読み取り、それを特殊なケースとして検出し、A = 3 および B = 1 を生成します。合計は正しく、両方の出力で数字 4 が回避されます。 

次のような入力の場合`4000`、アルゴリズムは各位置を独立して処理します。 最初の桁は 3 と 1 になり、残りのゼロは 0 と 0 になります。これにより、A = 3000 と B = 1000 が生成され、それらの合計は位置間の相互作用なしに元の数値を正確に再構成します。 

のような数値の場合`9994`の場合、最後の桁のみが分割をトリガーします。 最初の 3 桁は A に直接コピーされ、B はそこで 0 を取得します。 最後の桁では、分割によって局所的に正確さが保証され、キャリーがないため、前の桁は影響を受けません。
