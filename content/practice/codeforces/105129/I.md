 ## 解決策
 ## 問題の理解

 各テスト ケースではジュース ボトルのコレクションが提供されます。ここで、i 番目のボトルには特定のリットル数が含まれます。 アブデラリームは正確に m 人の友人にサービスを提供し、選択したボトルごとに、すべての友人のカップに同じ整数リットルを注ぐことが許可されます。 彼がボトルを使用しない場合、それは完全に無視されます。 

選択したボトルには厳しい制約があります。 数人の友達に平等に分けた後、ボトルに残った液体がわずかに残ってはいけません。 ボトルは何も残らないように使用されるか、少なくとも k リットルが残るように使用されます。 選択した分割方法でどちらの条件も満たさない場合、そのボトルはその構成では使用できません。 

このタスクは、使用されるすべての選択されたボトルに対して友人ごとに単一の均一な量を選択すると仮定して、友人ごとのジュースの量を最大化することです。 

重要な解釈は、各友人がすべての使用済みボトルから何リットルを受け取るかを表す単一の整数 x を選択しているということです。 体積 a の各ボトルについて、それを使用しないか、m・x リットルが分配されるように分割し、残りは a − m・x になります。 この剰余は、a − m・x = 0 または a − m・x ≥ k のいずれかを満たさなければなりません。 

入力サイズは大きく、テスト ケースごとに最大 5 × 10^5 のボトルがあり、値は最大 10^9 です。 これにより、各ボトルの x に対する値ごとの検索が除外されます。 各候補 x の実現可能性をテスト ケースごとに個別にチェックしようとするソリューションは、遅すぎます。 この構造は、各ボトルが x の制約区間に寄与しており、最終的な答えはすべての制約を同時に満たす最大の整数 x であることを強く示唆しています。 

すべてのボトルを使用する必要があると仮定した単純なアプローチでは、微妙な失敗例が発生します。 たとえば、ボトルをきれいに割ることができない場合や、十分な残りが残らない場合は、単純にスキップする必要があります。 もう 1 つの失敗例は、両方のオプションが許可されることを考慮せずに、剰余条件を常に割り算を必要とするもの、または常に剰余 ≥ k を必要とするものとして扱うことです。 

## アプローチ

 直接的な試みは、1 から最大 ai までの x のすべての可能な値を試し、各 x についてすべてのボトルをチェックすることです。 固定 x の場合、各ボトルは m・x を計算し、それが正確な除算に適合するか、少なくとも k 個の残りが残るかどうかをチェックすることによってテストされます。 これは正しいですが、遅すぎます。 最悪のケースでは、5 × 10^5 のボトルと最大 10^9 の候補値が含まれ、10^14 スケールの計算が不可能になります。 

重要な観察は、各ボトルが許可される x の値を個別に定義していることです。 固定 a の場合、条件は 2 つのケースに分かれます。 

ボトルが完全に使用されている場合、a = m・x となり、割り切れる場合は単一の候補 x = a / m になります。 

部分的に使用する場合は、a − m・x ≥ k が必要になります。これは、x ≤ (a − k) / m に再配置されます。 

したがって、各ボトルでは、特定のしきい値までのすべての x に加えて、おそらく 1 つの追加の正確な値が許容​​されます。 厳密値オプションは、x の最大化には無関係です。単一の正確な点は、すべての制約の最大しきい値と一致しない限り、それを超えることができないからです。 実際の制限は、すべてのボトルについて、それを無視するか、x が x ≤ (a − k) / m を満たすことを確認する必要があるということです。 これは、各ボトルが x に上限制約を課すことを意味します。

ただし、ボトルの無視は、ルール違反を強制しない場合にのみ有効です。 ボトルを安全に無視できるのは、ボトルを使用しないことを選択した場合にのみ許可されます。声明では飲み物を完全に飲まないことが許可されているため、これは常に当てはまります。 したがって、全体的な実現可能性は、x がアクティブなボトルのしきい値を超えないようにすることになります。 したがって、最適な x は、すべての有効な寄与の最大値であり、ボトル全体で少なくとも 1 つの有効な構成が存在するように最適な x として計算されます。これは、単にボトルごとの制約をすべて満たす実現可能な最大の x です。 

各ボトルについて、a ≥ k の場合、最も強い制約は x ≤ (a − k) / m であり、それ以外の場合は何も寄与しません。 答えは、少なくとも 1 つのボトルがそれをサポートできる最大の x になります。x を最大化しているので、有効なボトルごとの境界全体の最大値を取得します。 

これにより、すべてのボトルをスキャンし、それぞれのボトルから導き出される最良の候補値を計算するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 私たちは、各ボトルを個別に処理する少なくとも 1 つの有効な方法と互換性のある、友人ごとの可能な限り最良の量 x を選択するという問題を再解釈します。 

1. 値 a を持つ各ボトルについて、0 個または少なくとも k 個の残りを残したままサポートできる完全な m サイズのサービングの最大数を計算します。 実行可能な最大の x 範囲が生成されるため、「少なくとも k を残す」条件に焦点を当てます。 これにより、a ≥ k の場合は常に候補境界 x ≤ (a − k) // m が得られます。 
2. a < k の場合、ボトルは有効な残りの構成に寄与できません。 唯一可能な使用法は正確な除算です。これは a が m で割り切れる場合にのみ機能し、x = a // m が得られます。 これは範囲ではなく単一の固定値です。 
3. 各ボトルについて、それがサポートできる可能な限り最高の値を抽出します。 a ≥ k の場合、これは (a − k) // m です。 a < k の場合、 // m で割り切れる場合は m ですが、そうでない場合は何も寄与しません。 
4. すべての有効なボトルごとの候補の最大値を追跡します。 直感的には、達成可能な x は少なくとも 1 つのボトル構成でサポートされている必要があり、最適な戦略は、最大の x を許容するボトルネックのないボトルを選択することです。 
5. 見つかった最大値を返すか、有効なサービングをサポートするボトルがない場合は 0 を返します。 

これが機能する理由は、x を共有して選択すること以外、各ボトルが他のボトルと相互作用しない構造に基づいています。 x が固定されると、ボトルごとの実現可能性は独立します。 この独立性により、グローバル最適化は、ボトルごとの実行可能なセットの和集合から最良の許容可能な x を選択するように折りたたまれます。また、x を最大化するため、解はすべての有効なセットにわたる最大の上限によって決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        ans = 0
        
        for x in a:
            if x >= k:
                ans = max(ans, (x - k) // m)
            else:
                if x % m == 0:
                    ans = max(ans, x // m)
        
        print(ans)

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを個別に処理し、実行中の最大の答えを維持します。 主なロジックはボトルのループ内にあり、各ボトルが 1 つの候補値に減らされます。 k による減算は残りの制約を処理し、m による整数除算は残りの使用可能なボリュームをフレンドごとの割り当てに変換します。 

よくある落とし穴は、k < k のボトルでも正確な割り算によって寄与できることを忘れていることです。 もう 1 つは (a - k) // m の演算順序を混合することであり、負の寄与を避けるために a ≥ k を検証した後に計算する必要があります。 

## 実用的な例

 n = 3、m = 3、k = 2、ボトル [10、7、4] の小さな例を考えてみましょう。 

| ボトル | | 状態 | 候補者 x |
 | --- | --- | --- | --- |
 | 1 | 10 | (10 − 2) // 3 = 2 | 2 |
 | 2 | 7 | (7 − 2) // 3 = 1 | 1 |
 | 3 | 4 | (4 − 2) // 3 = 0 | 0 |

 最大値は 2 です。これは、1 つのボトルでより高い値が許容される場合でも、ボトルがよりきつくなると答えがどのように制限されるかを示しています。 

ここで、n = 2、m = 4、k = 5、およびボトル [16、9] を考えてみましょう。 

| ボトル | | 状態 | 候補者 x |
 | --- | --- | --- | --- |
 | 1 | 16 | (16 − 5) // 4 = 2 | 2 |
 | 2 | 9 | (9 − 5) // 4 = 1 | 1 |

 答えは 2 で、最初のボトルによって決まります。 2本目のボトルは弱くなっていますが、最大値には影響しません。 

これらの例は、各ボトルが独立して x の天井を生成し、答えは最も強い天井によって決定されることを確認します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    output = []
    
    input = sys.stdin.readline
    T = int(input())

        n, m, k = map(int, input().split())

        output.append(str(ans))
    return "\n".join(output)

 ## 特殊なケース

 厄介なケースは、k が十分に大きく、ほとんどのボトルが a < k のカテゴリに分類される場合です。 ボトル [48, 51] の入力 n = 2、m = 3、k = 50 の場合、アルゴリズムは 48 が m で割り切れる場合にのみ候補として扱い、それ以外の場合は何も寄与しません。 48 は 3 で割り切れないので無視されます。 51 の場合、候補は (51 − 50) // 3 = 0 となるため、答えは 0 になります。 

段階的に実行すると、中間状態が必要ないことがわかります。 各ボトルは独立して評価され、有効な算術パスのみが最大値に寄与します。
