 ## 解決策
 ## 問題の理解

 私たちが検証しているシステムは非常に単純です。テスト ケースごとに、プログラムが実行するはずのテストの数と、実際に合格したテストの数が示されます。 これから、プログラムが完全に成功したかどうかを判断します。 

各入力テスト ケースは 1 つの送信を記述します。 最初の数字は、その提出に対して存在するテスト ケースの総数です。 2 番目の数字は、送信が成功したテスト ケースの数です。 必要な決定は二者択一です。 すべてのテスト ケースが合格した場合、提出物は完全に正しいと宣言され、AC が出力されます。 テスト ケースが 1 つでも合格しなかった場合は、WA を出力します。 

制約は小さく、クエリあたりのテスト ケースの数は最大 100 に制限されています。これは、最も単純なテスト ケースごとの処理であっても、計算コストの観点からはわずかであることを意味します。 チェックごとの入力サイズは定数制限されており、チェックごとの操作は定数時間の比較であるため、事前計算、データ構造、または最適化のトリックは必要ありません。 

エッジケースは主に境界の等価性に関するものです。 最も重要な状況は、合格したテストの数がテストの総数と等しいときです。これには、両方が 1 である最小のケースも含まれます。たとえば、次のような入力です。`1 1`ACを出力する必要があります。 次のような少し異なる入力`1 0`少なくとも 1 つのテストが失敗したため、WA を出力する必要があります。 単純な実装でよくある間違いは、誤って次のことをチェックしてしまうことです。`m > 0`の代わりに`m == n`、次のようなケースを誤って受け入れます。`3 2`。 

もう 1 つの微妙な問題は、すべてのテストに合格することは、「完全に近い」ことを意味するのではなく、完全に同等であることを意味することを忘れていることです。 のような入力`100 99`成功率が高くても WA が生成されるはずです。 

## アプローチ

 問題を強引に解釈すると、各テスト ケースを個別にチェックすることをシミュレートできます。 n 個のテストすべてを繰り返して、それぞれが合格としてマークされているかどうかを確認することを想像できます。 ただし、入力によってすでに集計された情報 (成功したテストの数 m) が提供されているため、これは不要です。 

直接シミュレーションでは、概念的にサイズ n の配列を再構築し、そのうちの m を合格としてマークし、障害が存在するかどうかを検証します。 その場合、テスト ケースごとに O(n) のコストがかかります。 n は最大 100 ですが、個々のテスト結果を検査する必要がないため、このアプローチは論理的に冗長です。 

重要な観察は、問題全体が 1 つの等価性チェックに帰着するということです。 成功したテストの数がテストの総数と等しい場合、失敗はありません。 それ以外の場合は、少なくとも 1 つの障害が存在します。 これにより、問題は構造の反復から単一の比較に分解されます。

 ## アルゴリズムのチュートリアル

 私たちは各提出物を独立して処理し、直接比較してその評決を決定します。 

1. テスト ケース T の数を読み取ります。これにより、評価する提出物の数が決まります。 
2. 送信ごとに、2 つの整数 n と m を読み取ります。 1 つ目はテストの合計数、2 つ目は合格したテストの数です。 これら 2 つの値によって正確さが完全に決定されるため、追加のデータは必要ありません。 
3. m と n を比較します。 それらが等しい場合は、すべてのテストが成功したことを意味します。 それ以外の場合、少なくとも 1 つのテストが失敗しました。 
4. m が n に等しい場合は「AC」を出力し、そうでない場合は「WA」を出力します。 

入力はすでに完全な評価結果をエンコードしているため、ロジックは意図的に最小限になっています。 

### なぜ効果があるのか

 送信ごとに、失敗したテストのセットのサイズは n − m になります。 この数量がゼロの場合にのみ、提出が受け付けられます。 n − m = 0 は m = n と同等であるため、等価性は正しさを完全に特徴づけます。 テスト ケース間には隠れた構造や依存関係がないため、この条件は必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        if n == m:
            out.append("AC")
        else:
            out.append("WA")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、すべてのテスト ケースを 1 回読み取り、結果をリストに保存して、繰り返しの I/O オーバーヘッドを回避します。 決定の中心となるのは平等性チェックです`n == m`、テスト ケースが失敗したかどうかを直接エンコードします。 入力行を正しく解析すること以外にエッジ条件はありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(T) | 各テスト ケースは、単一の整数比較で処理されます。

 ## 特殊なケース

 意味のある最小のケースは、`n = 1`。 入力用`1 1`の場合、m が n に等しいため、アルゴリズムは等価性を比較し、AC をすぐに出力します。 のために`1 0`、条件は失敗し、WA が生成されます。 これにより、特別なケースを使用せずに境界値が正しく処理されることが確認されます。 

境界に近い場合、次のような場合`100 99`場合でも、比較では少なくとも 1 つのテストが失敗したことが正しく識別されます。 計算は大きさには依存せず、等しいことだけに依存するため、大きな値は小さな値と同じように動作します。
