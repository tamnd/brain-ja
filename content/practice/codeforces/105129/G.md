 ## 解決策
 ## 問題の理解

 私たちは、学生とその蓄積されたボーナス ポイントを追跡する小規模なトレーニング管理システムをシミュレートしています。 各生徒は、1 から n までのインデックスとそれに関連付けられた名前によって与えられる固定のアイデンティティを持っています。 最初は生徒全員がゼロ点からスタートします。 

初期化後、一連のコマンドを処理します。 コマンドには2種類あります。 1 つのコマンドにより、特定の生徒にボーナス ポイントが追加されますが、これは指定されたパスワードがシステム パスワードと正確に一致する場合に限られます。 もう 1 つのコマンドは、蓄積されたポイントに基づいて生徒の現在のランキングを出力します。 

ランキングのルールは簡単です。学生は合計ポイントによって降順に並べ替えられ、2 人の学生が同じポイント数を持っている場合は、ID が小さい学生が最初に表示されます。 スコアボードを印刷するときは、現在ゼロ以外のポイントを持っている生徒のみが表示され、この並べ替え順序に従ってランクが割り当てられます。 等しいスコアは同じランクを共有します。 

制約は小さく、生徒数は最大 100 人、操作数は 100 回です。 これは、クエリごとに O(n log n) または O(n²) のアプローチで完全に十分であることをすぐに示唆しています。 ボトルネックはアルゴリズムの複雑さではなく、順序付け、結合、フィルタリングの正しい処理にあります。 

主な微妙な点は、ランキングが増分的に維持されるのではなく、現在の状態からの要求に応じて再計算されることです。 もう 1 つの微妙な問題は、パスワード チェックが正確かつ大文字と小文字を区別する必要があることです。 たとえ小さな不一致でも更新は拒否されるはずです。 

ランクの計算方法にはエッジケースが現れます。 単純にソート順にランクを 1、2、3 として割り当てると、スコアが等しい場合に誤った結果が生成されます。 たとえば、2 人の生徒が両方とも 10 ポイントを持っている場合、彼らは同じランクを共有する必要があります。 

もう 1 つの特殊なケースは、0 点の生徒を扱うことです。 これらがシステム内に存在する場合でも、スコアボード出力には決して表示してはなりません。 

最後に、ID による順序付けのタイブレーカーが重要です。 これがないとソートが不安定になり、実装ごとに結果が異なる可能性があります。 

## アプローチ

 直接的なアプローチは、各生徒の現在のスコアを格納するサイズ n の配列を維持することです。 ボーナス コマンドの場合は、パスワードをチェックします。 一致する場合は、一定時間でスコアを更新します。 複雑さのボトルネックは、スコアボード コマンドを実行するときに現れます。すべての生徒をスコアと ID で並べ替えてから、ランクを計算し、ゼロ以外のランクを出力する必要があります。 

この強引な戦略はすでに快適に適合しています。 n ≤ 100 要素のソートには O(n log n) のコストがかかり、q ≤ 100 のすべてのクエリに対してソートを行ったとしても、合計の作業量は無視できます。 

重要な点は、バランスの取れたツリーやヒープのような複雑なデータ構造が必要ないということです。 データセットは十分に小さいため、順序を最初から再計算する方が、段階的に維持するよりも簡単でエラーが発生しにくくなります。 各スコアボード クエリは独立しているため、必要に応じて並べ替えられたビューを再構築できます。 

唯一の実際の設計上の決定は、ランクを正しく割り当てる方法です。 並べ替えが完了したら、リストをスキャンして同じランクを等しいスコアに割り当てます。そうでない場合は、ランク カウンターを適切にインクリメントします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (各クエリの並べ替えを再計算) | O(q · n log n) | O(n) | 承認済み |
 | 最適 (制約による総当たりと同じ) | O(q · n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 2 つの配列を維持します。1 つは生徒名用、もう 1 つは現在のスコア用で、どちらも生徒 ID によってインデックス付けされます。

1. n とシステムパスワードを読み取り、すべての生徒の名前を読み取ります。 名前を配列に保存することで、ID によって生徒の名前に直接アクセスできるようになります。 
2. ボーナスはまだ付与されていないため、サイズ n のスコア配列をゼロで初期化します。 
3. 各コマンドについて、そのタイプを解析します。 ボーナス コマンドの場合は、ターゲット ID、ボーナス値、パスワード文字列を抽出します。 
4. 提供されたパスワードと保存されているパスワードを比較します。 正確に一致しない場合は、拒否メッセージを出力し、更新をスキップします。 
5. パスワードが一致した場合、生徒のスコアにボーナスが追加され、成功メッセージが出力されます。 
6. コマンドがスコアボードの場合、ID、名前、スコアを含むすべての生徒のリストを作成します。 
7. このリストをスコアの減少、次に ID の増加によってソートします。 この順序により、スコアが等しい場合でも、決定的なランキングが保証されます。 
8. スコアボードに表示されるべきではないため、スコアがゼロの生徒をすべて除外します。 
9. ソートされたリストをスキャンしながらランクを割り当てます。 最初の生徒にはランク 1 が与えられます。次の生徒のスコアが前の生徒のスコアと等しい場合、同じランクが与えられます。 それ以外の場合、そのランクは、表示されているエントリ内の現在のインデックス位置になります。 
10. 各エントリを「ランク ID 名スコア」として出力します。 

これらの手順を完了すると、システム状態は一貫しており、次のコマンドを実行できる状態になります。 

### なぜ効果があるのか

 いつでも、スコア配列は、受け入れられたすべてのボーナス操作の合計を正確に表します。 スコアボードは常にこの配列から直接派生されるため、並べ替えによって正しいグローバル順序が生成されます。 ランキングは隣接するソートされたスコアの同等性にのみ依存するため、等しい値のランクを共有することで、必要な定義の下で正確さが維持されます。 除外されたすべての要素は肯定的なスコア間のランクに影響を及ぼさないため、ゼロのフィルター処理は順序付けには影響しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, password = input().split()
    n = int(n)

    names = [""] * (n + 1)
    for i in range(1, n + 1):
        names[i] = input().strip()

    score = [0] * (n + 1)

    q = int(input())
    out = []

    for _ in range(q):
        parts = input().split()

        if parts[0] == "bonus":
            idx = int(parts[1])
            val = int(parts[2])
            pw = parts[3]

            if pw == password:
                score[idx] += val
                out.append("Updated successfully")
            else:
                out.append("Wrong password please try again")

        else:
            arr = []
            for i in range(1, n + 1):
                if score[i] > 0:
                    arr.append((score[i], i, names[i]))

            arr.sort(key=lambda x: (-x[0], x[1]))

            rank_out = []
            current_rank = 0
            prev_score = None
            seen = 0

            for s, idx, name in arr:
                seen += 1
                if prev_score is None or s != prev_score:
                    current_rank = seen
                prev_score = s
                rank_out.append(f"{current_rank} {idx} {name} {s}")

            if rank_out:
                out.extend(rank_out)

        out.append("---")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、O(1) アクセスのために名前とスコアを直接インデックスベースの配列に保存します。 ボーナス コマンドごとに、一定時間のパスワード チェックが実行され、有効な場合はスコアが更新されます。 スコアボード コマンドの場合、アクティブな生徒のリストを再構築し、スコアの優先順位と ID のタイブレークの両方を強制するタプル キーを使用して生徒を並べ替え、スコアの変化を追跡してランクを割り当てます。 

微妙な点はランクの割り当てです。実行中のカウンターを使用します。`seen`ソートされたフィルタリングされたリスト内の位置を表します。 スコアが変化するたびに、ランクはこの位置に設定されます。 それ以外の場合は再利用されます。 これにより、同じスコアが同じランク値を共有することが保証されます。 

区切り線は、スコアボード出力の後を含め、必要に応じてすべてのコマンドの後に追加されます。 

## 実用的な例

 スコアの変化とスコアボードの出力に焦点を当てて、最初のサンプルをコンパクトな形でトレースします。 

初期状態ではすべてのスコアがゼロになります。 

| ステップ | コマンド | スコア（部分図） | アクション |
 | --- | --- | --- | --- |
 | 1 | ボーナス 3 12 ShAC | 3:12 | 更新成功 |
 | 2 | ボーナス 1 8 ShAC | 1:8、3:12 | 更新成功 |
 | 3 | ボーナス 3 80 ShaC | 変更なし | 間違ったパスワード |
 | 4 | ボーナス 6 12 ShAC | 1:8、3:12、6:12 | 更新成功 |

 スコアボードが並べ替えられるようになりました (3:12、6:12、1:8)。 3 と 6 は同点なので、ランク 1 を共有します。 

| ランク | ID | スコア |
 | --- | --- | --- |
 | 1 | 3 | 12 |
 | 1 | 6 | 12 |
 | 3 | 1 | 8 |

 これは、同点処理と、等しいスコア間の ID ベースの順序付けの両方を示しています (ID 3 < 6 は保持されます)。 

2 番目のサンプルでは、​​繰り返し更新と複数のスコアボード クエリを実行します。 スコア配列以外の状態は必要ないため、毎回の再計算の一貫性が保たれていることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q · n log n) | 各スコアボードの再構築は最大 n 人の生徒を並べ替え、q 回繰り返されます。 
| スペース | O(n) | 名前とスコアのストレージ |

 n、q ≤ 100 の場合、最大操作は最大 100 要素にわたる 10⁴ ソート操作程度であり、これは容易に制限内に収まります。

 ## 特殊なケース

 重要なエッジケースは、生徒全員が 0 点を持っている場合です。 この場合、スコアボード コマンドはランキング行をまったく生成せず、区切り文字のみを生成する必要があります。 明示的にフィルタリングするため、アルゴリズムがこれを処理します。`score[i] > 0`並べ替える前に。 

もう 1 つの特殊なケースは、多くの生徒で同じ得点が繰り返されることです。 たとえば、すべての生徒が 10 ポイントに到達した場合、全員がランク 1 を共有する必要があります。ランク割り当てロジックは、新しいスコアの最初の出現に基づいてランクを設定するため、より低いスコアが表示されるまで増分は発生しません。 

連続したボーナスコマンドでのパスワードの不一致も重要です。 パスワードが一致しない限り状態は変更されないため、間違った試行が繰り返されるとスコア配列は変更されず、その後のスコアボード出力には有効な更新のみが反映されます。
