 ## 解決策
 ## 問題の理解

 2 つのシーケンスが与えられ、それぞれが 1 から n までの整数の同じセットの順列です。 タスクは、両方の順列に出現し、厳密に増加している最も長い部分列の長さを見つけることです。 

サブシーケンスとは、各配列内の相対的な順序を変更せずに要素を選択することを意味します。 増加するということは、値自体が厳密に増加する必要があることを意味します。 したがって、2 つの制約を同時に尊重する値のシーケンスを探します。それは、両方の順列内で順番に出現する必要があり、選択された値が増加していなければなりません。 

問題を再解釈する便利な方法は、1 つの順列を順序を定義するものとして考え、2 番目の順列を最初の順序に投影したときに最長の増加パターンを抽出するシーケンスとして考えることです。 

この制約により、複数のテスト ケースを含むテスト ケースごとに n が最大 100000 まで許可されます。 これにより、ポジションのすべてのペアに対する二次アプローチが即座に除外されます。 解は、テスト ケースごとに線形または n log n に近い必要があります。 インデックスのペアに対する動的プログラミングやすべてのサブシーケンスのチェックなどは遅すぎます。 

単純な間違いは、これを最初に最長共通部分列として扱い、その後で昇順を適用することです。 これでは、両方の配列が順列であるという構造が無視されます。 もう 1 つのよくある間違ったアプローチは、位置を正しくマッピングせずに、一方の順列の値を使用して他方の順列で LIS を直接計算することであり、これは位置合わせ条件を破ります。 

## アプローチ

 ブルートフォースの観点は、古典的な最長共通部分列から始まります。 dp[i][j] がプレフィックス a[1..i] および b[1..j] の答えである DP を定義できます。 これは一般的なシーケンスでは機能しますが、テスト ケースごとに O(n^2) のコストがかかります。これは、n が 100000 の場合、制限をはるかに超えています。 

重要な単純化は、両方の配列が順列であるという事実から来ています。 これは、すべての値が各配列に 1 回だけ出現することを意味します。 位置の一致について考える代わりに、問題を単一のシーケンスの問題に変換できます。 

配列 b を参照順序として固定します。 a の各値を b の位置にマッピングします。 次に a を配列 p に変換します。ここで、p[i] は b 内の a[i] のインデックスです。 ここで、 a の部分列は p の部分列に対応し、両方の置換に共通であるという要件は、b 内の位置が増加する値を選択することを意味します。 選択された値の値が増加するという条件は、b 順序を尊重するサブシーケンスから順番に選択すれば、すでに自動的に満たされます。 これにより、問題は、マップされた配列 p の最長の増加サブシーケンスを見つけることになります。 

問題全体は、長さ n の配列に関する標準的な LIS 問題となり、二分探索による貪欲尾配列を使用して O(n log n) で解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース LCS DP | O(n^2) | O(n^2) | 遅すぎる |
 | ポジションマッピング + LIS | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。

1. pos[x] が順列 b の値 x のインデックスである配列 pos を構築します。 これにより、b の順序を比較する迅速な方法が得られます。 
2. 各要素 a[i] を pos[a[i]] に置き換えます。 この変換の後、a の各要素が b のどこに現れるかを表す数値シーケンス p が得られます。 ここで問題は、p 内の最長の増加部分列を見つけることに縮小されます。 
3. 配列 tails を維持します。tails[len] には、これまでに見つかった長さ len の増加するサブシーケンスの最小可能最後の値が格納されます。 この構造により、拡張が最も簡単なサブシーケンスが確実に保持されます。 
4. p の各値 x について、二分探索を使用して、x が既存の末尾を拡張または置換できる尾部の最初の位置を見つけます。 x が現在のすべての尾部よりも大きい場合、シーケンスを拡張します。 それ以外の場合は、適切な位置を更新します。 
5. 尾部の最終的なサイズは、最も長く増加する部分列の長さであり、これが答えです。 

二分探索が有効である理由は、末尾が常にソートされたままであるためです。 各位置は、その長さのサブシーケンスの可能な最良の終了値を表すため、潜在的な最適な拡張が失われることはありません。 

### なぜ効果があるのか

 共通の増加サブシーケンスは、b 内の位置が厳密に増加している値のシーケンスに対応します。 各値を b 内の位置によってエンコードするため、p 内の増加するサブシーケンスを正確に選択することになります。 逆に、p の増加する部分列は、両方の順列で増加順に現れる値に対応します。 したがって、p 上の LIS は LCIS 長を正確に捕捉します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, x in enumerate(b):
            pos[x] = i

        p = [pos[x] for x in a]

        tails = []

        for x in p:
            lo, hi = 0, len(tails)
            while lo < hi:
                mid = (lo + hi) // 2
                if tails[mid] < x:
                    lo = mid + 1
                else:
                    hi = mid
            if lo == len(tails):
                tails.append(x)
            else:
                tails[lo] = x

        print(len(tails))

if __name__ == "__main__":
    solve()
```最初の部分では、b の逆位置マッピングを構築します。これは、値の比較をインデックスの比較に変換するため不可欠です。 このステップがなければ、2 つの順列を 1 つの数列問題に統合することはできません。 

2 番目の部分は、b の座標系における a の変換表現である p を構築します。 後のすべてのステップはこの削減に依存します。 

LIS の実装では、標準的な忍耐力の並べ替えのアイデアが使用されます。 二分探索により最適な末尾を効率的に維持できるようになり、完全なシーケンスを保存する代わりに末尾を更新することでメモリの線形性が維持されます。 

## 実用的な例

 a = [1, 3, 2, 4] および b = [1, 2, 3, 4] の単純なケースを考えてみましょう。 次に、pos は {1:0, 2:1, 3:2, 4:3} になり、p は [0, 2, 1, 3] になります。 

| ステップ | × | 前の尾 | アクション | 後の尾 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | [] | 追加 | [0] |
 | 2 | 2 | [0] | 追加 | [0, 2] |
 | 3 | 1 | [0, 2] | インデックス 1 を置き換える | [0, 1] |
 | 4 | 3 | [0, 1] | 追加 | [0、1、3] |

 最終的な答えは 3 です。これは部分列 [1, 2, 4] に対応します。 

次に、a = [4, 3, 2, 1]、b = [1, 2, 3, 4] の逆の場合を考えてみましょう。 この場合、p = [3, 2, 1, 0] となります。 

| ステップ | × | 前の尾 | アクション | 後の尾 |
 | --- | --- | --- | --- | --- |
 | 1 | 3 | [] | 追加 | [3] |
 | 2 | 2 | [3] | 置き換える | [2] |
 | 3 | 1 | [2] | 置き換える | [1] |
 | 4 | 0 | [1] | 置き換える | [0] |

 増加する構造が存在しないため、最終的な答えは 1 です。 

最初のトレースは、ローカル置換によって将来の拡張性がどのように向上するかを示しています。これは、LIS の背後にある中心的なメカニズムです。 2 つ目は、厳密に減少する変換されたシーケンスが長さ 1 に折りたたまれることを示しています。

 ## 特殊なケース

 重大なエッジ ケースは、1 つの順列がまったく逆になっている場合です。 その場合、マッピングは厳密に減少するシーケンスを生成し、LIS アルゴリズムは、誤って拡張することなく、それを長さ 1 に正しく縮小する必要があります。 尾部の配列は拡張されるのではなく継続的に置き換えられ、正確性が維持されます。 

もう 1 つのケースは、両方の順列が同一である場合です。 次に、pos は各要素を独自のインデックスにマップし、すでに増加するシーケンスを生成するため、すべての要素が末尾を拡張します。 この場合、アルゴリズムは置換をトリガーしてはなりません。 

3 番目の微妙なケースは、最良のサブシーケンスがどちらの配列でも連続していない場合です。 LIS 変換は、隣接関係ではなく b の相対的な順序付けのみに基づいて動作するため、これを自然に処理し、そのようなパターンが引き続き正しく検出されるようにします。
