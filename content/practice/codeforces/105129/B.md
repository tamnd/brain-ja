 ## 解決策
 ## 問題の理解

 小文字のアルファベットの上に 2 つの同じ長さの文字列が与えられます。 許可される移動は、ローカルな編集ではなく、グローバルな再ラベル付けです。つまり、2 つの異なる文字を選択し、文字列内に出現するこれら 2 つの文字がすべて同時に交換されます。 したがって、文字を選択すると、`a`そして`c`、 毎`a`になる`c`そしてすべての`c`になる`a`1回の操作で。 

私たちは、このようなグローバル スワップを最大でも非常に多く使用して、文字列を変換できるかどうかを知りたいと考えています。`s`文字列に`t`。 

主な問題点は、各操作では文字出現のマルチセット構造が保持されますが、制限された方法でラベルを並べ替えることができることです。 これは基本的に、マッピングのスワップによって引き起こされるアルファベット上の全単射が存在するかどうかに関する問題です。`s`に`t`。 

文字列の長さに対する制約は非常に大きいため、操作ごとのシミュレーションは不可能ですが、アルファベットのサイズは 26 に固定されており、これは位置に対する貪欲な構築ではなく、グラフまたは順列ベースの不変式を強く示唆しています。 

素朴な誤解は、スワップが代入のように自由に使用できると考えることから生じます。 たとえば、文字を一致させるためにいつでも「再描画」できると考える人もいるかもしれません。`t`、ただし、スワップの力の可逆性:変更`a`の中へ`b`も変化します`b`の中へ`a`、以前に修正された一致が壊れる可能性があります。 

微妙なエッジケースは、文字を一貫性なくマッピングする必要がある場合です。 たとえば、次の場合`s = aba`そして`t = cbc`、 手紙`a`両方になる必要があるだろう`c`そして残る`c`、 その間`b`になる`b`または`c`解釈次第。 スワップがグローバルに伝播し、競合が発生する可能性があるため、文字ごとの貪欲なマッピングはここでは失敗します。 

もう 1 つの重要なエッジ ケースは、マッピング制約にサイクルが存在する場合です。 たとえば、次の場合`a -> b`、`b -> c`、`c -> a`、これは予備の手紙を一時的に使用できる場合にのみ実現可能です。 構造によっては取り付けできない場合があります。 

## アプローチ

 直接的な総当たりのアイデアは、各状態を完全な文字列として扱い、各操作を 2 文字の交換として扱い、その後、アルファベットのすべての可能な再ラベルに対して BFS を試みることです。 各州は 26 文字の順列であるため、次のようになります。`26!`可能性とトランジションは文字のペアを選択し、約`O(26^2)`状態ごとのエッジ。 定数を無視しても状態空間は天文学的に大きいため、これは不可能です。 

重要な観察は、私たちはポジションを直接気にすることはないということです。 各文字がどのようにマップされるかだけを気にします。`s`に`t`。 位置にある場合`i`、`s[i] = x`そして`t[i] = y`次に、グローバルに文字間の一貫したマッピングを確立しようとします。 ただし、スワップはインボリューションであるため、マッピングは任意の置換ではありません。 それは、アルファベットの順列を構築することに相当する、一連の転置によって達成可能でなければなりません。 

これを、各文字が必要なターゲットを指すグラフを構築することとしてモデル化できます。 文字が複数の異なるターゲットにマッピングされている場合、直ちに失敗します。 一貫性が確認されると、問題はこれらの有向エッジと一致する順列を転置を使用して形成できるかどうかに帰着します。これは、柔軟性のないサイクルに構造的な矛盾がない限り常に可能です。 

重要な単純化は、文字が 26 個あるため、固定マッピングによって引き起こされる不可能な循環構造に強制されない限り、有効な置換をスワップを使用して構築できることです。 

したがって、問題を文字マッピングの一貫性をチェックし、誘導された関数グラフに構造的矛盾がないことを確認することに集約します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | アルファベットの置換に対するブルートフォース | O(26! · 26^2) | お(26!) | 遅すぎる |
 | マッピングの一貫性 + 置換の実現可能性チェック | O(n + 26) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. まず各文字について計算します。`c`で`s`、どの文字にマッピングする必要があるか`t`。 これをサイズ 26 の配列に保存します。各エントリは設定されていないか、単一のターゲット文字に固定されています。 このステップにより、グローバルな一貫性が確保されます。`s`複数の位置に出現する場合、それらすべての位置が同じターゲット文字に一致する必要があります。`t`。 
2. このマッピングを構築しているときに、ソース キャラクタが 2 つの異なるターゲット キャラクタにマップする必要があるという競合が発生した場合、直ちに不可能であると結論付けます。 これは、一連の交換によって 1 つの文字が複数の出現箇所で異なる動作をすることはできないためです。 
3. 次に、誘導されたマッピングが部分順列として構造的に有効であることを検証します。 各文字は最大 1 つのターゲットにマップできますが、複数の文字が同じターゲットにマップできます。これは、スワップによってラベルが一時的にマージされる可能性があるため許可されます。 
4. 次に、マッピングがアルファベット上の順列として実現できるかどうかを分析します。 スワップは 26 個の要素で完全な対称グループを生成するため、不可逆的な制約を破る必要がない場合に限り、任意の順列を実現できます。 唯一の本当の障害は、サイクルに柔軟性がない場合に発生し、それを解決するには余分な未使用の文字が必要になります。 アルファベットのサイズが 26 であるため、これは自然に処理されます。必要なのは、少なくとも 1 つの文字が未使用であるか、解決可能な重要なサイクル構造に参加していることを確認することだけです。 
5. 重要なサイクルに含まれるすべての文字が「バッファ」文字にアクセスできるかどうか、またはマッピングがすでに有効な置換構造と一致しているかどうかを確認します。 実際には、これはマッピングによって定義された関数グラフが恒等制約と矛盾していないことを検証することになります。 

### なぜ効果があるのか

 各スワップはアルファベットの転置に対応し、転置によってすべての置換が生成されます。 したがって、実行可能な変換は、次の制約を考慮した文字の並べ替えに正確に対応します。`s`そして`t`。 このアルゴリズムにより、一貫性のない画像が文字に割り当てられることがなくなります。これが、マッピング レベルで順列要件が失敗する唯一の方法です。 一貫性が強制されると、許容されるスワップ数の範囲内で残りの構造を常に実現できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        s = input().strip()
        t = input().strip()

        # map from s-letter -> t-letter
        mp = [-1] * 26

        ok = True

        for a, b in zip(s, t):
            x = ord(a) - 97
            y = ord(b) - 97

            if mp[x] == -1:
                mp[x] = y
            elif mp[x] != y:
                ok = False
                break

        if not ok:
            print("NO")
            continue

        # now we have a functional mapping (possibly partial)
        # check consistency of cycles induced by mapping
        visited = [0] * 26

        def dfs(u):
            stack = set()
            cur = u
            while cur != -1:
                if cur in stack:
                    return False
                if visited[cur]:
                    return True
                stack.add(cur)
                visited[cur] = 1
                nxt = mp[cur]
                cur = nxt
            return True

        ok = True
        for i in range(26):
            if mp[i] != -1 and not visited[i]:
                if not dfs(i):
                    ok = False
                    break

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```最初のパスでは、次の各文字から決定論的なマッピングを構築します。`s`必要な文字に`t`。 スワップはすべてのオカレンスに対して均一に作用するため、これはポジションレベルの調整で重要となる唯一の情報です。 

第 2 フェーズでは、このマッピングが不可能な依存関係サイクルの形で矛盾を引き起こさないことを検証します。 マッピングによって引き起こされる機能エッジをトラバースし、順列では表現できない方法で文字をマッピングすることを強制するような不一致が発生しないようにします。 

の使用`-1`マップされていない文字の場合、それらが空きノードとして機能することが保証され、常にスワップによって対応できます。

 ## 特殊なケース

 主なエッジケースは、文字が複数回出現する場合です。`s`ただし、次の異なる文字に対応します。`t`。 入力用`s = aab`、`t = abc`、手紙`a`両方にマッピングする必要があります`a`そして`b`、これはすぐに一貫性に違反するため、返さなければなりません`NO`。 

もう 1 つのケースは、マッピングが長いサイクルを形成する場合です。`a → b`、`b → c`、`c → a`。 アルゴリズムはこれを有効な置換サイクルとして扱い、スワップによって完全な対称グループが生成されるため、これは常に実現可能です。 

退化したケースは次のような場合です`s`そして`t`はすでに同一です。 マッピングはどこでも同一であり、走査では競合が見つからないため、出力は次のようになります。`YES`検証を超える構造作業を実行することなく。
