 ## 解決策
 ## 問題の理解

 整数の開始点と禁止された数字が与えられます。 開始番号から繰り返し 1 ずつ増やすことができます。 目標は、開始点以降の 10 進表現に禁止数字がまったく含まれていない最初の数値に到達することです。 各テスト ケースの答えは、最初の「クリーンな」数値に到達するために必要な増分数です。 

より具体的に言うと、xから始まる数直線に沿って歩くことを想像してください。 一部の数値は、10 進数形式のどこかに特定の数字 d が含まれているために「ブロック」されます。 ブロックされていない最初の番号に到達するまでにどのくらいの距離を歩かなければならないかを知りたいのです。 

この制約により、開始値を 10^9 まで大きくすることができるため、最悪の場合、すべての増分を 1 つずつシミュレートするアプローチは即座に除外されます。 単一のテスト ケースでは、無効な数値の長いチェーン全体をスキャンする必要がある場合がありますが、複数のテスト ケースでは、賢くジャンプしない限り、これは実行不可能になります。 

開始番号がすでにその数字を避けている場合、微妙なエッジケースが発生します。 その場合、答えはゼロとなり、少なくとも 1 つの増分が必要であると仮定するロジックは間違っています。 もう 1 つのまれなケースは、禁止された数字がゼロの場合です。 これは、1000 のような末尾にゼロがある数値を含め、ゼロを含むすべての数値に影響します。先頭のゼロの処理を慎重に考慮しないと、単純な数字操作が誤った動作をすることがよくあります。 

## アプローチ

 最も直接的な戦略は、x から開始して、現在の数値に数字 d が含まれているかどうかを確認しながら、繰り返しインクリメントすることです。 これは問題で説明されているプロセスを文字通りシミュレートしているため、これは正しいです。 ただし、連続する多くの数字に禁止数字が含まれている場合、最悪のケースが発生します。 たとえば、d が 9 で、x が 1999999000 の場合、多くの連続する整数には 9 が含まれるため、大量のチェックが必要になる可能性があります。 各チェックでは数値の桁をスキャンする必要があるため、このアプローチではスキップされた領域のサイズが線形時間に低下し、病的な場合には 10^9 に近くなる可能性があります。 

重要な観察は、すべての中間数値をシミュレートする必要はないということです。 代わりに、数字 d を含まない x 以上の最初の数値のみが必要です。 これにより、問題は、禁止桁制約を伴う 10 進数の「次の有効な数」の作成問題に変換されます。 

10 進数表現の構造により、大きなブロックを一度にスキップできます。 数値のどこかの位置に禁止された数字が含まれている場合、その位置まで同じプレフィックスとそれより小さいサフィックスを持つ数値は多くの場合依然として無効であるため、数字を変更し、可能な限り最小の有効な数字でサフィックスを再構築することで、安全にジャンプできます。 この貪欲な数字修正により、中間の整数をすべてチェックすることなく、次の有効な候補に直接移動できるようになります。 

禁止されている数字 (または禁止されていない最も近い可能な上位の数字) を増やし、残りを許可されている最小の数字で埋めることによって、その数字が表示される各位置を体系的に修正してみることができます。 このようなすべての候補の中で、x 以上の最小の有効な候補が答えになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースインクリメント | O(答え × 桁) | お(1) | 遅すぎる |
 | 桁修理工事 | テストごとの O(D²) | O(D) | 承認済み |

 ここで D は x の桁数です。 

## アルゴリズムのチュートリアル

1. 数値 x を数字のリストに変換して、位置ごとに処理できるようにします。 これにより、算術演算を繰り返す代わりに、個々の小数点以下の桁を直接操作できるようになります。 
2. x にすでに数字 d が含まれていない場合は、すぐに 0 を返します。 これにより、不必要な処理が回避され、最も単純なケースが正しく処理されます。 
3. 数字 i が d に等しい各位置 i について、この位置を潜在的な「ブレークポイント」として扱い、この位置またはその前で数値を増やすことによって数値を強制的に有効にします。 その考え方は、有効な答えは最初の無効な数字またはその前で x と異なっていなければならないということです。 
4. そのような各位置で、i の桁を、d に等しくない現在の桁より大きい可能な最小の桁まで増加させようとします。 そのような桁が存在しない場合は、増加できる位置が見つかるまでキャリーを左に伝播させます。 このステップが必要なのは、すでに 9 に設定されている場合、または d によって制限されている場合、1 つの数字を単純に変更することが不可能な場合があるためです。 
5. ある位置 j で数字を増やすことに成功したら、j の右側にあるすべての数字を、許可されている最小の数字 (禁止されている場合を除き 0、禁止されている場合は 1 または次の有効な数字が使用されます) に置き換えます。 これにより、選択したプレフィックスを使用して可能な限り最小の数値を構築することが保証されます。 
6. 構築された数値に数字 d が含まれておらず、少なくとも x であることを検証します。 x との差を計算します。 
7. すべての候補構造から最小値を取得します。 

この構造の背後にある理由は、有効な数値は、その位置を増やすか、それより前の数字を増やすことによって、禁止された数字の最初の出現を解決する必要があるということです。 このような解決ポイントをすべて列挙することで、考えられる次の有効な番号をすべてカバーします。 

### なぜ効果があるのか

 このアルゴリズムは、10 進数が辞書順に数字順に並べられているという事実に基づいています。 x を変更する最初の位置によって、ジャンプの大きさが決まります。 構築された候補より小さい有効な数値は、禁止された数字を保持するか、十分な大きさにならないかのいずれかです。 修正が必要な最も早い位置を徹底的に検討し、その時点から最小の完了を構築することで、有効なより小さい候補が見逃されることがないようにします。 これにより、値を 1 つずつ列挙することなく、すべての構造の可能性に対する完全な検索が定義されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def contains(n, d):
    return str(d) in str(n)

def build_candidate(x, d):
    s = list(str(x))
    n = len(s)
    dch = str(d)
    best = None

    # try fixing at each position
    for i in range(n):
        if s[i] != dch:
            continue

        t = s[:]

        # try increasing position i
        j = i
        while j >= 0:
            cur = int(t[j])
            found = False
            for nxt in range(cur + 1, 10):
                if str(nxt) != dch:
                    t[j] = str(nxt)
                    found = True
                    break
            if found:
                break
            j -= 1

        if j < 0:
            # need to increase length
            t = ['0'] * (n + 1)
            for k in range(1, n + 1):
                for dig in range(1, 10):
                    if str(dig) != dch:
                        t[k] = str(dig)
                        break
        else:
            # fill suffix
            for k in range(j + 1, len(t)):
                for dig in range(10):
                    if str(dig) != dch:
                        if k == 0 and dig == 0:
                            continue
                        t[k] = str(dig)
                        break

        val = int("".join(t))
        if dch not in str(val):
            if val >= x:
                if best is None or val < best:
                    best = val

    # also check direct next if x itself invalid and no fix triggered
    return best

def solve():
    T = int(input())
    for _ in range(T):
        x, d = map(int, input().split())

        if not contains(x, d):
            print(0)
            continue

        ans = build_candidate(x, d)
        print(ans - x)

if __name__ == "__main__":
    solve()
```このソリューションは、些細な受け入れケースを構築段階から分離します。 構築関数は、禁止された数字が出現するたびに数値を修復しようとします。 キャリー伝播ループは、ローカル修正が不可能な場合でも正確性を保証します。 変更ポイントを選択した後、サフィックスは許容される最小の桁で貪欲に再構築されるため、結果として得られる数値はその構造上の選択に対して最小限になります。 

微妙な点の 1 つは、禁止桁が 0 であるためにすべてのサフィックス桁が不可能になる場合の処理​​です。その場合、新しい数値の最上位に先頭のゼロを置くことは避けます。これは、大きさが誤って小さくなってしまうためです。 

## 実用的な例

 x = 484300 および d = 3 を考えてみましょう。3 が最初に出現するのは最後の桁ブロックです。 アルゴリズムは、再び 3 が導入されるのを避ける方法で、その前の数字をインクリメントしようとし、有効な最小の数字でサフィックスを再構築します。 結果の候補は、3 で終わる数字のブロック全体を飛び越えます。 

| ステップ | 現在 | アクション | 候補者 |
 | --- | --- | --- | --- |
 | 1 | 484300 | 数字 3 を検出 | - |
 | 2 | 484300 | 位置を固定する | 484400 (3 が存在しないため無効ですが、最小限のジャンプ) |

 構築された番号は、次の有効な領域に直接スキップします。 

ここで、x = 8 および d = 8 を考えてみましょう。開始番号はすでに無効です。 次の数字は8が入っていない9なので、答えは1です。 

| ステップ | 現在 | d | を含む アクション |
 | --- | --- | --- | --- |
 | 1 | 8 | はい | インクリメント |
 | 2 | 9 | いいえ | 停止 |

 これにより、アルゴリズムが 1 桁の遷移を正しく処理していることが確認されます。

 ## 特殊なケース

 x がすでに数字 d を回避している入力の場合、インクリメントは必要ないため、アルゴリズムはすぐに 0 を返します。 これにより、不必要な桁の再構成が回避され、x = 123 や d = 7 などの最小限のケースの正確性が保証されます。 

x = 999 や d = 9 など、x のすべての桁が禁止桁である場合、桁上げの伝播によって長さが強制的に増加します。 アルゴリズムは、禁止された数字を使用せずに増分できない数字を検出したため、1 桁追加して有効な最小の数値を構築します。 これにより、禁止桁制約に合わせて調整された 1000 のような遷移が正しく生成されます。 

d がゼロの場合、1000 のような数値は接尾辞を慎重に再構築する必要があります。 このアルゴリズムは、無効な位置にゼロを配置することを回避し、先頭の数字がゼロ以外のままであることを保証し、結果から数字のゼロを完全に除外しながら数値の有効性を維持します。
