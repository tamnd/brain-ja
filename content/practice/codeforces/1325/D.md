 ## 問題の理解

 ## アルゴリズムのチュートリアル

 回答の長さを増やす際の実現可能性を確認していきます。 

1. もし`u == v`、単一要素の配列をすぐに出力できます。`[u]`。 これが機能するのは、XOR と sum が両方とも同じ 1 つの値に等しく、入力が負ではないため正の値が満たされるためです。 
2. サイズ 2 の答えを構築しようとすると、システムを解きます。$a \oplus b = u$、$a + b = v$以下を導き出します。$a = (v - u) / 2$、$b = (v + u) / 2$以下の場合のみ受け付けます。`v >= u`、`(v - u)`は偶数であり、両方とも`a`そして`b`は負ではない整数です。 これにより、追加の要素を導入することなく、ビット単位の制約と算術制約の両方が同時に満たされることが保証されます。 
3. サイズ 2 が有効な場合、出力します。`[a, b]`。 有効なサイズ 1 のケースはすでに処理されているため、これは最適です。 
4. それ以外の場合は、サイズ 3 を構築します。まず、実現可能性を確認します。`v < u`、XOR はどのような構成でも正の整数の合計を超えることができないため、解決策は存在しません。 
5. サイズ 3 の場合、標準的なビット分割トリックを使用します。 私たちが選ぶのは:$a = u$

$b = (v - u) // 2$

$c = (v - u) // 2$これにより、XOR が作成されます。$a \oplus b \oplus c = u \oplus x \oplus x = u$以来$b = c$、同じ数値の XOR がキャンセルされます。 

合計は次のようになります。$u + 2x = v$、 それで$x = (v - u)/2$これは次の場合にのみ機能します`(v - u)`は偶数で負ではありません。 そうでない場合は、ビットを分散する少し異なる構造に移行します。`u`2 つの数値に分割し、3 番目の数値を使用してキャリーを調整します。 このような構築はいつでも可能です`v >= u`。 

### なぜ効果があるのか

 不変条件は、XOR が GF(2) に対して線形に動作するため、重複する値はきれいにキャンセルされますが、sum は整数に対して線形に動作するということです。 この構造では、XOR の責任を小さな固定構造 (単一の数値または重複のペア) に分離し、3 番目の数値の残りの自由度を使用して算術和制約を満たします。 XOR パリティに誤って影響を与えることなく、常に整数をビット単位の素のコンポーネントに分割し、それらを再結合できるため、パリティや負性によって除外されない場合、システムには常に解決策があります。

import sys, io

def run(inp: str) -> str:

 ## 特殊なケース

 重大なエッジケースは次のような場合です。`u > v`。 例えば、`u = 5, v = 2`。 正の配列は、少なくとも個々の要素に等しい合計を持ちますが、この領域では XOR が合計を超えることはできません。 アルゴリズムはこれを早期に正しく拒否し、戻り値を返します。`-1`。
