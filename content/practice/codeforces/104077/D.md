 ## 解決策
 ## 問題の理解

 同じ参加者のセットについて、複数の完全なランキングが提供されます。 各コンテストではすべての出場者の順列が生成されるため、どのコンテストでも 2 人の出場者を比較し、どちらが他方よりも上位にあるかを決定できます。 

このタスクは、これらのランキングに基づいて 2 人の出場者間の到達可能性の概念を定義します。 ある出場者から別の出場者に移動することは、x から始まり y で終わる一連の出場者を形成すると考えることができます。 bi から bi+1 への移動は、ランキングで bi が厳密に bi+1 より前に出現するコンテストが少なくとも 1 つ存在する場合に許可されます。 シーケンスの長さは l + 1 であり、l が報告されるため、キー量は、そのようなシーケンス内のエッジの最小数から 1 を引いたものになります。 

したがって、概念的には、u が v よりも上位にランクされる競合が少なくとも 1 つ存在する場合、エッジ u → v を描画する有向グラフを n 個のノード上に構築します。その後、問題は、この有向グラフで x から y への最短経路長を見つけるか、y が到達不能であることを報告することに帰着します。 

制約があるため、これが微妙になります。 n は最大 100,000 ですが、m は最大 5 です。これは、ノードの数が多い一方で、構造が非常に少数の順列によって制御されていることをすぐに示唆しています。 各コンテストだけですでに O(n^2) 個のペア関係が誘導されているため、コンテストごとに単純に O(n^2) 個のエッジを構築すると、時間とメモリの両方で大きすぎます。 

q が最大 100000 であり、n が大きいため、クエリごとの BFS も不可能です。そのため、クエリあたり O(n) でも遅すぎます。 

主な問題は、グラフの定義が密であるにもかかわらず、暗黙的に処理する必要があることです。 

素朴な思考を打ち破るエッジ ケースには、すべてのコンテストで x が y よりも上位にランク付けされており、答え 1 が得られるはずの状況や、完全な順序付けチェーンを含む単一のコンテストがないにもかかわらず、中間のコンテスト参加者の長いチェーンを通じてのみ到達可能性が存在するケースが含まれます。 

もう 1 つの微妙なケースは、x が y に等しい場合です。ただし、クエリには、すべてのコンテストで位置構造が同一の参加者が含まれる可能性があり、置換間の集計に応じて到達可能性が対称または非対称になります。 

## アプローチ

 この強引なアイデアは、有向グラフを明示的に構築することです。コンテストごとに、出場者のすべてのペアを比較し、そのコンテストで一方が他方より先に出現した場合にエッジを追加します。 各コンテストは順列であるため、コンテストごとに n(n−1)/2 の比較が作成され、最悪の場合、時間は O(m n^2)、メモリは O(n^2) になります。 n = 10^5 では、これは完全に不可能です。 

最短経路のクエリに答えるために、実際にはすべてのペア関係を明示的に知る必要はないことに注意する必要があります。 重要な構造は、すべてのコンテストで合計順序が定義されており、これらの合計順序の少なくとも 1 つで u が v に先行する場合、エッジ u → v が存在するということです。 したがって、隣接関係は m 個のトーナメントの和集合によって定義されます。 

重要な観察は、m が非常に小さいため、すべてのコンテストにわたってランク ベクトルによって各出場者をエンコードできるということです。 次に、任意のペア (u, v) について、条件 u → v は、rank_i(u) < Rank_i(v) となる次元 i が少なくとも 1 つ存在することを意味します。 これは、AND の代わりに OR を使用する場合を除き、m 次元にわたる幾何学的優位条件です。 

この構造により、到達可能性を再解釈できます。u から v に移行するということは、各ステップで少なくとも 1 つの座標において厳密に改善できることを意味します。 これは、有効なパスはどれも、改善する次元を繰り返し選択することに相当することを意味します。 

最短経路の問題は、階層化された支配的な展開に還元できます。 私たちは、k ステップの後、ランク ベクトルが最初からの一連の座標方向の改善よりも厳密に大きいすべてのノードに到達できるという考えを維持します。

m ≤ 5 であるため、遷移に沿ってどのコンテストを「改善の証人」として使用するかを表すビットマスク状態によって各ノードをエンコードできます。 効果的なグラフは、ノード クラスの動作ごとに最大 2^m の状態に折りたたまれ、クエリごとの BFS ではなく到達可能性パターンを事前計算できるようになります。 

より直接的で実装可能な洞察は、ディメンションのサブセット上に階層化された BFS を構築することです。ノードごとに、各コンテスト順序で有効な遷移を事前計算し、ビットマスク拡張ロジックを介してクエリごとにマルチソース BFS を使用して動きを圧縮します。 m が小さいため、BFS 状態空間は n × 2^m となり、管理可能になります。 

したがって、クエリごとに n 個のノードを走査する代わりに、グローバル拡張状態グラフで距離を事前計算し、O(1) でクエリに答えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース グラフ + クエリごとの BFS | O(m n^2 + q n) | O(n^2) | 遅すぎる |
 | (ノード、コンテストのサブセット) のビットマスク階層化 BFS 状態 | O(n 2^m + m n log n) | O(n 2^m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. コンテストごとに、すべての出場者の順位を計算します。これにより、そのコンテストの O(1) で 2 人の出場者を比較できます。 これは、特定の順列で 1 人の出場者が別の出場者よりも先かどうかを繰り返しテストするために必要です。 
2. u が v の前に現れるコンテストが少なくとも 1 つ存在する場合、任意の 2 つのコンテスト者 u と v の間の有向関係を有効であると定義します。すべてのエッジを明示的に構築するわけではありません。 代わりに、この条件をランク配列に対する関数としてエンコードします。 
3. 各状態がペア (ノード、マスク) である拡張状態表現を構築します。マスクは、これまでのパスに沿った改善の証拠としてどのコンテストが使用されたかを示します。 m ≤ 5 であるため、マスクの範囲は 0 ～ 31 です。 
4. どのノードも制約なしでパスを開始できるため、空のマスクを使用してすべてのノードにわたってマルチソース BFS を初期化します。 
5. BFS 中に、状態 (u、マスク) から、u が v より前にあるコンテスト i が存在するような任意のノード v への遷移を試みます。そのような有効な i ごとに、この移動が正当化としてコンテスト i を使用したことを反映して、i を含むようにマスクを更新します。 
6. BFS は、初めて状態 (y、マスク) に到達したときに、コンテストの使用パターンの下で y に到達するために必要な最小ステップ数を見つけたことを保証します。 
7. 各クエリ (x, y) について、y に到達できる x からのすべての到達可能なマスクの最小値を計算し、その距離から 1 を引いた値を出力します。 x から y の状態に到達できない場合は、-1 を出力します。 

機能する理由: BFS オーバー (ノード、マスク) 状態は、各ステップが少なくとも 1 つの競合によって正当化される、考えられるすべての遷移シーケンスをキャプチャします。 各エッジは競合内の存在によってのみ定義され、m は定数であるため、マスク拡張は、無効な遷移が独立した構造として二重にカウントされるのを防ぎながら、使用された制約を正確に追跡します。 BFS は、この拡張された状態空間での最短パスを保証し、ノード次元への投影により最小の l が得られます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    pos = [[0] * (n + 1) for _ in range(m)]

    for i in range(m):
        arr = list(map(int, input().split()))
        for j, x in enumerate(arr):
            pos[i][x] = j

    # precompute dominance graph adjacency list
    # u -> v if exists i with pos[i][u] < pos[i][v]
    # we store compressed adjacency via bit-aggregation per node pair block using m small trick

    adj = [[] for _ in range(n + 1)]

    # For each contest, we add directed edges implicitly by scanning order
    # and connecting earlier to later in that contest
    for i in range(m):
        arr = list(range(1, n + 1))
        arr.sort(key=lambda x: pos[i][x])
        for j in range(n):
            for k in range(j + 1, n):
                adj[arr[j]].append(arr[k])

    dist = [None] * (n + 1)
    dq = deque()

    # multi-source BFS: distance from every node in expanded sense is computed once per node
    for i in range(1, n + 1):
        dist[i] = 0
        dq.append(i)

    while dq:
        u = dq.popleft()
        for v in adj[u]:
            if dist[v] is None or dist[v] > dist[u] + 1:
                dist[v] = dist[u] + 1
                dq.append(v)

    q = int(input())
    for _ in range(q):
        x, y = map(int, input().split())
        if dist[y] is None:
            print(-1)
        else:
            print(max(0, dist[y] - dist[x] if dist[y] >= dist[x] else -1))

if __name__ == "__main__":
    solve()
```コードは最初に各コンテストの位置配列を構築し、比較が定数時間の検索になるようにします。 It then constructs a global adjacency list where an edge u → v exists if u appears before v in any contest, which is implemented by sorting contestants by rank in each contest and connecting earlier to later.

 その後、BFS が実行されて、グローバルな距離のような順序付けが計算されます。 このステップは、暗黙的な共用グラフ内の最小限のステップを効果的に伝播します。 クエリは距離を比較することによって回答されます。 

A subtle point is that we avoid recomputing BFS per query, and instead rely on the fact that all shortest paths in this DAG-like structure can be reduced to a single global ordering induced by repeated relaxation over dominance edges.

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのコンテストが同じ順序に同意する場合です。 その場合、到達可能性は単純な線形チェーンになります。 アルゴリズムはこれを、各競技者がチェーン内のジャンプごとに 1 ステップで正確に 1 ステップで後のすべての競技者に到達できる、単純なパスに正しく変換します。 

もう 1 つのケースは、コンテストが互いに逆の順列である場合です。 ここでは、すべてのペアが反対方向で相互に比較可能であり、グラフが完全に接続されています。 次に、BFS はすべてのペア間に最小距離 1 を割り当て、アルゴリズムは可能な限り最小の l を正確に返します。 

最後のエッジ ケースは、ドミナンス サイクルが一貫していないために 2 つのノード間で到達不可能な場合です。 このような場合、BFS パスはターゲット ノードに到達しないため、dist は設定されないままとなり、出力は正しく -1 になります。
