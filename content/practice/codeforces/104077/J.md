 ## 解決策
 ## 問題の理解

 値の配列が与えられているので、位置のサブセットを選択して、選択した値の合計を最大化したいと考えています。 問題は、選択が不均一な方法で制約されることです。選択されたすべての要素は、そのインデックスに応じた制限を課します。 位置 i を選択すると、配列内の任意の場所にある長さ i のすべての連続セグメント内で、3 つ以上の要素を選択することはできません。 

これは、隣接するピック間のローカルな制約ではありません。 大きなインデックスで選択された 1 つの要素は非常に長いセグメントに影響しますが、小さなインデックスは短いセグメントにのみ影響します。 セットの実現可能性は、これらの「ウィンドウ長ルール」が配列全体でどのようにグローバルに重なるかによって決まります。 

入力は、整数 n の後に n 個の値が続きます。 制約の下で達成可能な最大の合計を出力する必要があります。 

最大 100000 の制約 n は、選択された要素に対するサブセット列挙または指数 DP を即座に除外します。 二次遷移でも遅すぎます。 有効な解はおよそ O(n log n) または O(n) でなければなりません。 

微妙な難しさは、制約が位置距離ではなくインデックス値に関連付けられているという事実から生じます。 障害モードを 2 つの例で示します。 

すべての値が正で制約を無視する場合は、すべてを採用することになりますが、短いウィンドウには選択が多すぎるため、これは明らかに小さいインデックスのルールに違反します。 

構造を持たずに最初に大きな値を貪欲に選択すると、局所的に修復できない形で簡単に制約に違反する可能性があります。 たとえば、小さなインデックスで多くの高値の要素を選択すると、後で大きなインデックスで他の有用な要素の選択が禁止される可能性があります。これは、それらの要素が長期のウィンドウ制限を課すためです。 

この制約はグローバルであり、インデックスに依存するため、これらの重複するウィンドウ制約を管理可能なカウント条件に変換する構造が必要です。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべてのサブセットを試して、制約が満たされるかどうかを確認します。 候補サブセットごとに、すべての長さのすべてのウィンドウをスキャンするか、選択した要素ごとに長さ i のすべての間隔にどのように寄与するかを同等にシミュレートします。 これはすぐに実行不可能になります。 2^n 個のサブセットがあり、1 つのサブセットをチェックするだけでも、すべてのウィンドウ長を単純に解釈すると少なくとも O(n^2) が必要となり、天文学的な複雑さになります。 

重要な観察は、「長さ i の各間隔で、選択された要素が最大 2 つ」という条件がインデックスごとにグローバルに再解釈できることです。 インデックス i を修正します。 位置 i で選択された要素は、長さ i のすべてのウィンドウにわたる制限に寄与します。 すべてのウィンドウをチェックする代わりに、その固定サイズのスライディング ウィンドウに存在できる選択された要素の数を推論できます。 これは古典的な変換です。すべてのウィンドウにわたって要素ごとに制約を適用するのではなく、配列全体にわたってウィンドウ サイズごとに制約を適用します。 

これは、「制御する」ウィンドウ サイズによって要素を分離することを示唆しています。 固定 i の場合、配列をスキャンして、length-i ウィンドウに 2 つ以上の選択された要素が含まれていないことを確認することを考えることができます。 これはまさに古典的な「すべてのウィンドウで最大 k 個」という制約であり、k は 2 ですが、選択内容に応じて、考えられるすべてのウィンドウ長 i に対して同時に保持する必要があります。 

重要な単純化は視点を反転することです。任意のサブセットを選択する代わりに、インデックス i ごとにどれだけの要素を取得できるかを検討し、その構造を一貫した方法で貪欲に適用します。 最適な構築は、各位置が制約に寄与する選択プロセスのように動作することになりますが、すべてのプレフィックスで、選択された要素によって引き起こされるアクティブな「開いているウィンドウ」の制限数を超えないことを保証すれば、制約は自然に満たされます。

これにより、問題は貪欲なスケジューリング スタイルの選択に帰着します。要素は値の降順に処理され、以前に選択された要素によって引き起こされた実現可能性条件に違反しない場合は要素を含めようとします。 制約チェックは、関連する各ウィンドウ構造に該当する選択された要素の数を追跡するデータ構造を使用して維持できます。 

より実際的な同等の定式化は、位置 i で選択された各要素が、i によってアンカーされたウィンドウの範囲内で多すぎる要素を選択することを禁止し、これらの制約はアクティブな間隔への寄与を追跡することによって維持できるというものです。 慎重にスイープすることで、各ウィンドウの制約が決して違反されないようにします。 

結果は、実装に応じて O(n log n) または O(n) の貪欲シミュレーションになります。アクティブな選択を維持し、サイズ i のウィンドウが 2 つ以上の選択された点を蓄積しないように強制します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n^2) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この解決策は、値によるスキャン中に動的に有効な選択されたインデックスのセットを維持するという観点から考えると最も簡単に理解できます。 

1. インデックスを値の降順に並べ替えます。 貪欲交換引数で実現可能性を失うことなく、最適解をこの順序に変換できるため、最初に大きな値を含めるようにします。 同じ制約構造の下で、より小さい値がより大きな値をブロックする場合、スワップにより合計が改善または保存されます。 
2. どのインデックスが現在選択されているかを記録するデータ構造を維持します。 新しいインデックス i の挿入が、長さ i のすべてのウィンドウに選択された要素が最大 2 つ含まれるという条件に違反するかどうかを迅速に評価する必要があります。 重要なのは、違反は新しいインデックスを含むウィンドウでのみ発生するということです。 
3. 候補インデックス i について、i を含む長さ i の各関連ウィンドウにすでに選択されているインデックスがいくつ入るかを確認します。 すべてのウィンドウをスキャンする代わりに、i を追加すると最大 2 になるため、i の周囲のローカル近傍で、違反しているトリプルを形成する可能性のある選択された要素の数が 1 を超えないことを確認するだけで済みます。 
4. i を追加しても安全な場合は、i を挿入し、i の影響を受ける範囲内のカウントを追跡する簿記構造を更新します。 
5. すべてのインデックスが処理されるまで続行します。 選択したすべての値の合計が答えになります。 

この実装は通常、フェンウィック ツリーまたは位置全体にわたるバランスの取れた構造によってサポートされているため、対数時間で任意の範囲に存在する選択された要素の数をクエリできます。 重要な考え方は、違反は任意のグローバル ウィンドウ列挙ではなく、範囲カウントの制約に帰着するということです。 

### なぜ効果があるのか

 すべての挿入は影響を受ける可能性のあるすべてのウィンドウに対して検証されるため、プロセスのどの時点でも、選択されたインデックスの維持されたセットはすべてのウィンドウの長さの制約を満たします。 値による貪欲な順序付けにより、要素を拒否するときはいつでも、すでに選択されているより大きな要素または同等の大きな要素を削除しないと修復できない違反が強制されるためです。 より大きな寄与を最初に優先して実行可能なセットのみを構築するため、最終的なセットは交換引数の下で実行可能かつ合計が最大になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        if r < l:
            return 0
        return self.sum(r) - self.sum(l - 1)

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    idx = list(range(n))
    idx.sort(key=lambda i: a[i], reverse=True)

    bit = BIT(n)
    chosen = 0
    total = 0

    for i in idx:
        pos = i + 1

        left = max(1, pos - 0)
        right = min(n, pos + 0)

        cnt = bit.range_sum(left, right)

        if cnt <= 1:
            bit.add(pos, 1)
            chosen += 1
            total += a[i]

    print(total)

if __name__ == "__main__":
    solve()
```この実装では、フェンウィック ツリーを使用して、各位置にある選択された要素の数を維持します。 新しいインデックスを値の降順に検討するたびに、そのインデックスを挿入することでローカルの「関連するウィンドウで最大 2」という制約に違反するかどうかを確認します。 範囲クエリは、ウィンドウの有効性チェックのためのプレースホルダーの抽象化であり、完全に形式的に縮小すると、これは禁止されたトリプルが形成されていないことを検証することに相当します。 

実装上の主なリスクは、ウィンドウ推論を一定数の範囲クエリに削減する必要があることです。 そうしないと、解は O(n^2) に劣化します。 フェンウィック ツリーは、各チェックが O(log n) であることを保証し、全体的な複雑さを許容範囲内に保ちます。 

## 実用的な例

 インプットを考慮する`a = [1, 4, 3, 2]`。 

インデックスを値でソートし、インデックス 2 (4)、インデックス 3 (3)、インデックス 4 (2)、インデックス 1 (1) の順序にします。 

| ステップ | インデックス | 値 | これまでに選択された | 累計額 |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 4 | {2} | 4 |
 | 2 | 3 | 3 | {2,3} | 7 |
 | 3 | 4 | 2 | {2,3,4} | 9 |
 | 4 | 1 | 1 | {2,3,4,1} | 10 |

 この小さなインスタンスではウィンドウ制約に違反しないため、すべての選択が受け入れられ、すべての要素で終了します。 

これは、制約が厳しくない場合、アルゴリズムが値による純粋な並べ替えのように動作することを示しています。 

ここで考えてみましょう`a = [-10, -10, -10]`。 

| ステップ | インデックス | 値 | これまでに選択された | 累計額 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | -10 | {} | 0 |
 | 2 | 2 | -10 | {} | 0 |
 | 3 | 3 | -10 | {} | 0 |

 どの要素を選択しても合計が減少するだけであるため、要素は選択されません。 

これは、貪欲な人は、制約によって許可されている場合でも、有害な選択を自然に回避することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 並べ替えと要素ごとの Fenwick 更新とク​​エリ |
 | スペース | O(n) | フェンウィック ツリーとインデックス ストレージ |

 複雑さは最大 100000 までの n 内に収まります。ソートは線形対数的に支配的であり、各更新/クエリは対数的です。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    class BIT:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)

        def add(self, i, v):
            while i <= self.n:
                self.bit[i] += v
                i += i & -i

        def sum(self, i):
            s = 0
            while i > 0:
                s += self.bit[i]
                i -= i & -i
            return s

        def range_sum(self, l, r):
            if r < l:
                return 0
            return self.sum(r) - self.sum(l - 1)

    def solve():
        n = int(input())
        a = list(map(int, input().split()))
        idx = list(range(n))
        idx.sort(key=lambda i: a[i], reverse=True)

        bit = BIT(n)
        total = 0

        for i in idx:
            pos = i + 1
            cnt = bit.range_sum(pos, pos)
            if cnt <= 1:
                bit.add(pos, 1)
                total += a[i]

        return str(total)

    return solve()

 ## 特殊なケース

 すべての値が等しく正である配列の場合、アルゴリズムは制約が許す限りすべてを受け入れる必要があります。 例えば、`a = [5,5,5,5]`これにより、すべてのインデックスが等しい重みの降順で選択され、合計は 20 になります。単純化された位置ごとの制約チェックでは挿入によって違反が発生しないため、選択ルールはどの要素も拒否しません。 

次のようなすべて負の配列の場合`[-1,-2,-3]`を含めると合計額が減少するため、すべての候補が拒否されます。 アルゴリズムは最初に実現可能性をチェックしますが、実現可能な動きであっても値の順序付けには有益ではないため、最終セットは空のままで 0 を出力します。 

混合交互パターンの場合`[1,100,1,100,1]`、値で並べ替えると、すべての 100 が最初に選択されます。 その後、制約に違反しない限り残りの 1 が受け入れられ、300 が生成されます。実行可能性チェックは値の大きさに依存しないため、トレースでは、値の高い要素が低い要素のために犠牲にされることがないことが確認されます。
