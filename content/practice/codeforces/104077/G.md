 ## 解決策
 ## 問題の理解

 文字列のコレクションが与えられます。 このコレクションから新しい文字列を構築したいと思います。その文字列のすべての連続部分が入力文字列の 1 つとして指定されたコレクション内のどこかに出現する場合、その文字列を有効と呼びます。 

言い換えれば、候補文字列の任意の部分文字列を取得する場合、たとえ長さが 1 または 2 以上の非常に短いものであっても、その部分文字列は提供された文字列の少なくとも 1 つと正確に一致する必要があります。 このような有効な文字列の可能な最大長を見つけるように求められます。 

入力サイズでは、すべての文字列の合計で最大 100,000 文字が許可されます。 長さ n の単一の文字列にはすでに約 n 個の二乗部分文字列が含まれているため、単純な方法ですべての文字列のすべての部分文字列をグローバルに列挙しようとするアプローチは直ちに除外されます。 単一の長い文字列に対する二次スキャンはすでに遅すぎます。 

微妙な点は、有効性が非常に制限されていることです。 文字列が有効な場合、その文字列のすべての部分文字列自体が完全な文字列として入力リストに表示される必要があります。 これには、文字列自体、そのすべてのプレフィックス、すべてのサフィックス、およびその間のすべてが含まれます。 これは、多くの候補文字列、特に「欠落している」短いパターンを含む候補文字列が早期に削除されることを意味します。 

単純な推論でよくある失敗例は、短い部分文字列のみをチェックすれば十分であると想定することです。 

たとえば、入力に次のものが含まれているとします。`"a"`、`"b"`、`"ab"`、`"bc"`しかしそうではありません`"abc"`。 文字列`"abc"`すでに失敗しているので、`"abc"`たとえその長さすべての 2 つの部分文字列が入力全体に何らかの形で存在する可能性があるにもかかわらず、それ自体が欠落しています。 これは、ローカルな隣接関係だけでなく、完全な部分文字列のクロージャーを検証する必要があることを示しています。 

## アプローチ

 ブルートフォースのアイデアは単純です。 入力文字列ごとに、それが有効かどうかを確認します。 これを行うには、すべての部分文字列を列挙し、それぞれが入力セットに存在することを確認します。 O(1) メンバーシップ チェックのために、すべての入力文字列をハッシュ セットに保存します。 

文字列の長さが L の場合、約 L(L+1)/2 個の部分文字列があります。 すべての文字列を合計すると、最悪の場合、これは 2 次になります。 長さ 100,000 の単一の文字列がある場合、すでに約 50 億の部分文字列チェックが行われることになり、これは時間制限をはるかに超えています。 

重要な点は、すべての文字列を同等に考慮する必要はないということです。 私たちは強い構造的制約を乗り越えた文字列のみを考慮します。すべての部分文字列も辞書に存在する必要があります。 つまり、欠落している部分文字列が 1 つ見つかると、無効な文字列はすぐに破棄され、短い欠落パターンがすべてを壊してしまうため、ほとんどの文字列は非常に早い段階で失敗します。 

すべての入力文字列をハッシュ セットに保存し、各文字列を段階的に検証し、部分文字列を生成し、欠落している文字列が見つかったらすぐに停止することで、これを利用します。 ローリング ハッシュまたはダイレクト スライスとハッシュを使用すると、部分文字列チェックごとのオーバーヘッドが削減され、実際には早期終了によりほとんどの作業が回避されます。 

問題は基本的に、入力文字列を「substring-closed」プロパティでフィルタリングし、生き残った文字列の最大長を返すことです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (枝刈りせずに文字列ごとにすべての部分文字列をチェック) | O(∑L²) | O(∑L) | 遅すぎる |
 | ハッシュ セット + 早期終了部分文字列の検証 | O(∑L²) 最悪だが、枝刈りのため実際には速い | O(∑L) | 承認済み |

 ## アルゴリズムのチュートリアル

 入力文字列を辞書として扱い、それぞれを潜在的な答えとしてテストすることで進めます。 

### ステップ

 1. すべての文字列を読み取り、ハッシュ セットに挿入します。 

これにより、文字列が入力コレクションに存在するかどうかを定期的にチェックできるようになります。 
2. 変数を初期化する`best`ゼロに設定すると、これまでに見つかった最大有効長が保存されます。 
3. 文字列ごとに`s`入力では、それを回答候補として扱います。 
4. 次のすべての部分文字列を生成します。`s`開始インデックスを固定し、終了インデックスを拡張することによって。 

各部分文字列について、それがハッシュ セットに存在するかどうかを確認します。 
5. セット内に部分文字列が見つからない場合は、直ちに破棄します。`s`そして次の文字列に移動します。 

単一の部分文字列が欠落していると文字列全体が無効になるため、この早期の終了は重要です。 
6. 次のすべての部分文字列が`s`セット内で見つかった場合は更新します`best`現在の値の最大値と`len(s)`。 
7. すべての文字列を処理した後、出力します`best`。 

### なぜ効果があるのか

 重要な不変条件は、文字列のすべての部分文字列が指定された辞書に出現する場合にのみ文字列を受け入れるということです。 すべての有効な候補は定義上この特性を満たさなければならないため、無効な文字列を誤って受け入れることはありません。 逆に、文字列がこの特性を満たす場合、それを考慮して答えを更新することが保証されます。 したがって、アルゴリズムは正確です。有効性の定義条件を使用して入力セットをフィルタリングし、最も長く生き残ったものを選択します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def all_substrings_valid(s, word_set):
    n = len(s)
    for i in range(n):
        cur = []
        for j in range(i, n):
            cur.append(s[j])
            if "".join(cur) not in word_set:
                return False
    return True

def solve():
    n = int(input().strip())
    words = [input().strip() for _ in range(n)]
    
    word_set = set(words)
    
    best = 0
    for w in words:
        if all_substrings_valid(w, word_set):
            best = max(best, len(w))
    
    print(best)

if __name__ == "__main__":
    solve()
```実装は検証プロセスを直接エンコードします。 セット`word_set`定数時間検索用にすべての入力文字列を保存します。 各候補文字列について、各開始位置から展開して部分文字列を列挙します。 内側のループは、スライスのオーバーヘッドの繰り返しを避けるために部分文字列を段階的に構築しますが、主なコストは依然として検査される部分文字列の数です。 

これを実際に実行可能にするのは、重要な早期終了です。欠落している部分文字列が検出されると、ほとんどの文字列はすぐに失敗します。

## 特殊なケース

 特殊なケースの 1 つは、すべての文字列の長さが 1 である場合です。 この状況では、すべての候補のすべての部分文字列が自明に存在するため、答えは単に同一の単一文字列間の最大長になります。 文字列ごとにチェックする部分文字列のタイプが 1 つだけであるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、入力に長い文字列が出現するが、その内部の部分文字列の 1 つが出現しない場合に発生します。 たとえば、次の場合`"abcd"`存在しますが、`"bc"`が欠けている場合、`"abcd"`部分文字列が存在する場合、ただちに拒否されます。`"bc"`検証中に発生しました。 このアルゴリズムは、残りのすべての部分文字列を検査する必要がなく、文字列を正しく失敗させます。 

最後のエッジケースは、入力に重複した文字列が含まれている場合です。 ハッシュ セットは多重度を無視し、有効性は頻度ではなく存在のみに依存するため、これは正確さに影響しません。
