 ## 解決策
 ## 問題の理解

 私たちは、明示的に構築されるのではなく、垂直線と水平線によって暗黙的に形成されるグリッド上で定義される幾何学的選択問題に取り組んでいます。 

X 軸には次の値が与えられます。$n$位置にある縦線$x_1 < x_2 < \dots < x_n$、それぞれの垂直線には重みがあります。$a_i$。 y 軸には次のように与えられます。$m$位置にある水平線$y_1 < y_2 < \dots < y_m$、それぞれに重みがあります$b_j$。 

垂直線の任意のペアは垂直セグメントを定義し、水平線の任意のペアは水平セグメントを定義します。 2 本の垂直線と 2 本の水平線を選択すると、辺がこれらの指定された線上に正確に位置する長方形が形成されます。 このような長方形の面積は純粋に座標の差によって決まりますが、コストもかかります。 コストは、その 4 つの辺のコストの合計であり、各辺は、その幾何学的な長さに、それが置かれているラインの重みを乗じたものになります。 

したがって、垂直インデックスによって形成される長方形の場合$i < j$と水平インデックス$p < q$、費用は次のとおりです。$$(x_j - x_i)\cdot a_i + (x_j - x_i)\cdot a_j + (y_q - y_p)\cdot b_p + (y_q - y_p)\cdot b_q.$$これは次のように再グループ化できます。$$(x_j - x_i)(a_i + a_j) + (y_q - y_p)(b_p + b_q).$$複数の質問に答えなければなりません。 各クエリには予算が与えられます$c$、そしてそのコストが超えないように、可能な最大の長方形の面積を計算する必要があります。$c$。 幅または高さがゼロの縮退長方形は許可されるため、実現可能性が問題になることはありません。 

制約$n, m \le 5000$すぐに除外します$O(n^2 m^2)$列挙。 平$O(n^2 m)$大きすぎます。 ソリューションでは、各クエリが次元ごとに二次またはほぼ線形の時間で応答されるように、検索スペースまたは事前計算構造を慎重に縮小する必要があります。 

微妙な問題は、両方の次元が領域内での乗算によってのみ相互作用するのに対し、コストは次元間で加算されることです。 この分離が主な構造上の手がかりとなります。 

すべての重みが大きい場合に 1 つのエッジ ケースが発生し、最適な長方形が縮退することになります。 たとえば、すべてが$a_i$そして$b_j$非常に大きく、$c$が小さい場合、最良の長方形は実質的に面積ゼロであり、これは 1 つの次元で同一の線を選択するか、両方の次元を折りたたむことによって実現されます。 正の幅と高さを仮定する単純な解決策では、これが見逃されます。 

もう 1 つの特殊なケースは、座標ギャップがゼロの場合ですが、座標の順序が厳密であるため、これは起こり得ません。 ただし、重みは大きく異なる可能性があるため、最適なソリューションは、低重みのエンドポイントと組み合わせた非常に小さな幾何学的スパンから得られる可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 垂直線のすべてのペアと水平線のすべてのペアを試し、それらが形成する長方形のコストを計算し、その面積を確認します。 各クエリについて、制約の下で最大面積を取得します。 

がある$O(n^2)$垂直ペアの選択肢と$O(m^2)$水平ペアの選択肢を与える$O(n^2 m^2)$長方形。 と$n = m = 5000$、これは次の順序です。$6.25 \times 10^{14}$これは、複数のクエリを検討する前でさえ、まったく実行不可能です。 長方形ごとに 1 回の計算コストでさえ、すでに計算予算をはるかに超えています。 

重要な観察は、コスト関数が垂直成分と水平成分にきれいに分離していることです。 次のように定義すると、$$C_x(i, j) = (x_j - x_i)(a_i + a_j), \quad C_y(p, q) = (y_q - y_p)(b_p + b_q),$$総コストは$C_x + C_y$、一方、面積は$(x_j - x_i)(y_q - y_p)$。 

この構造は、問題を 2 つの独立した 2D 選択空間の畳み込みとして扱うことを示唆しています。 4 つのインデックスすべてを一度に選択する代わりに、考えられるすべての垂直「プロファイル」と水平「プロファイル」を事前計算できます。各プロファイルはペアです。$$(\text{length}, \text{cost}, \text{weight-sum})$$しかし、実際に必要なのは、長さ、コスト、および誘発面積の寄与の間の関係だけです。 

より有用な再定式化は、垂直ペアを修正することです。$(i, j)$。 それによって幅が生まれます$w = x_j - x_i$およびコスト係数$a_i + a_j$、したがって垂直コストは$w \cdot A$。 同様に、各水平ペアは高さを与えます$h$と係数$B$なので、水平コストは$h \cdot B$。 長方形の場合、次のようになります。$$wA + hB \le c, \quad \text{maximize } w \cdot h.$$これで構造が明確になりました。各軸は、2D ナップザックのような積の最大化における一連の線形制約に寄与します。 重要なのは、固定の場合です。$w, A$、最良の計算ができます$h, B$、その逆も同様ですが、すべてのペアにわたる単純なペアリングでは依然として次のことが起こります。$O(n^2 m^2)$。 

画期的な点は、各軸について、(コスト係数、長さ) の平面内で達成可能なペアの凸包のみが必要であることを観察したことです。 各軸は候補線のセットに縮小され、最適な組み合わせはこれらの縮小されたセットに対する 2D 畳み込みに縮小され、ソートと単調最適化によって解決できます。 

すべての垂直ペアを単位面積当たりのコストの寄与によってソートされた配列に前処理し、水平ペアに対しても同じことを行った後、クエリ バジェットから導出されたしきい値をスイープできます。 可能な予算の分割ごとに$c = c_x + c_y$、以下で達成可能な最適な垂直幅を計算します。$c_x$および以下の最適な水平高さ$c_y$、そして製品を最大化します。 どちらの関数もバジェットが単調であるため、プレフィックス最大値を事前計算し、最適な垂直方向または水平方向の選択が変化する削減されたブレークポイントのセットをスキャンすることで各クエリに答えることができます。 

これにより、問題が二次ペアから管理可能な問題に軽減されます。$O(n^2 + m^2)$による前処理$O(1)$または$O(\log n)$クエリの処理は実装に応じて異なります。

 ## アルゴリズムのチュートリアル

 このソリューションは、垂直方向と水平方向の貢献を分離し、予算分割を通じてそれらを組み合わせることで構築されます。 

1. 考えられるすべての垂直セグメントを計算します。 すべてのペアについて$i < j$、幅を計算します$w = x_j - x_i$およびコスト係数$A = a_i + a_j$、そのペアを垂直状態の候補として保存します。 私たちは「与えられたコスト予算、達成可能な最大の幅寄与は何か」という関数に関心があるため、支配的なフィルタリングを可能にする方法で状態を保存します。 
2. 垂直状態をコスト別に並べ替える$w \cdot A$。 ソート後、コスト増加を考慮して達成可能な最大幅を維持するプレフィックス エンベロープを構築します。 これにより、コストを上げても幅が改善されない支配的な状態が削除されます。 
3. 水平ペアに対して同じプロセスを繰り返し、予算を達成可能な最大の高さにマッピングするエンベロープ関数を生成します。 
4. 各クエリの予算について$c$、に分割します$c_x$そして$c_y$。 両方の次元は独立しているため、垂直エンベロープのブレークポイントによって引き起こされるすべての意味のある分割点を試します。 候補者ごとに$c_x$、計算します$c_y = c - c_x$そして評価します:$$\text{area} = \text{bestWidth}(c_x) \cdot \text{bestHeight}(c_y).$$5. すべての分割の最大値を取得します。 エンベロープは次の時点でのみ変化するため、$O(n^2)$ブレークポイントの場合、すべての値をスキャンしなくても、ブレークポイントを反復処理するだけで十分です。$c$。 

重要な実装の詳細は、すべての予算を明示的に反復することは決してないということです。 垂直方向または水平方向の最適な選択が変化する予算のみを考慮します。 

### なぜ効果があるのか

 どの長方形でも、コストは独立した垂直部分と水平部分にきれいに分割されます。 垂直方向にどれだけの予算が費やされるかを決定すると、最適な水平方向の選択は垂直方向の選択とは無関係になります。 これにより、問題は、スカラー バジェットの 2 つの単調関数への分割に対する最適化に縮小されます。 最適解は常に、少なくとも 1 つの次元が最適な状態を変更する点にあり、これはエンベロープ ブレークポイントに正確に対応します。 これにより、予算の徹底的な分割を回避しながら、最適な長方形の候補を見逃すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_envelope(coords, w):
    n = len(coords)
    pairs = []
    for i in range(n):
        for j in range(i + 1, n):
            length = coords[j] - coords[i]
            cost = length * (w[i] + w[j])
            pairs.append((cost, length))
    pairs.sort()

    env = []
    best = 0
    for c, l in pairs:
        if l > best:
            best = l
            env.append((c, best))
    return env

def query(env, budget):
    # max length with cost <= budget
    l = 0
    for c, v in env:
        if c <= budget:
            l = v
        else:
            break
    return l

def solve():
    n, m, T = map(int, input().split())
    x = list(map(int, input().split()))
    a = list(map(int, input().split()))
    y = list(map(int, input().split()))
    b = list(map(int, input().split()))

    vert = build_envelope(x, a)
    hori = build_envelope(y, b)

    for _ in range(T):
        c = int(input())
        ans = 0

        # try splitting budget across envelopes
        for i in range(len(vert)):
            cv, w = vert[i]
            if cv > c:
                break
            remaining = c - cv
            h = query(hori, remaining)
            ans = max(ans, w * h)

        print(ans)

if __name__ == "__main__":
    solve()
```実装は、すべての垂直セグメントと水平セグメントのペアを構築することから始まります。 各ペアは、その幅または高さを実現するために必要なコストと、それが与える幾何学的寄与をエンコードします。 ソートのステップは、支配的な状態を圧縮できるため、不可欠です。 

エンベロープ構造では、コストを増加させるために達成可能な最大長を改善しないペアはすべて削除されます。 これは、後のクエリを効率化するための重要な最適化です。 

クエリごとに、垂直エンベロープ ブレークポイントを反復処理し、水平エンベロープで線形スキャンを使用します。 エンベロープ サイズが完全な 2 次セットよりも大幅に小さく、各エントリが達成可能なジオメトリの大幅な改善に対応するため、これは許容できます。 

微妙な点は、恣意的な予算を決して考慮していないことです。 実際に最適な構造を変更する垂直コストに等しい予算のみを考慮します。 これにより、実行時間を管理しやすくしながら、最適な分割の欠落を回避します。

 ## 特殊なケース

 重要なエッジケースは、すべてのコストがクエリ予算を超える場合です。 その状況では、すべてのエンベロープ クエリは長さ 0 を返すため、最終的な答えは 0 になります。 どちらのエンベロープも最適な値をゼロに初期化し、ゼロ以外の選択を強制しないため、アルゴリズムはこれを自然に処理します。 

別のケースは、すべての重みが等しい場合です。 この場合、コストは純粋にセグメントの長さに比例し、最適な長方形は単純にグリッド内の最大面積の長方形になります。 長いセグメントがコストと価値の両方で同時に短いセグメントを圧倒し、きれいなモノトーン構造を生成するため、エンベロープ構造は依然として機能します。 

最後のエッジ ケースは、非常に偏った重みであり、一方の軸は非常に短いが安価なセグメントを優先し、もう一方の軸は長くて高価なセグメントを優先します。 バジェット分割ループはすべての垂直ブレークポイントを明示的にテストするため、特別な処理を必要とせずに正しい非対称性を自然に検出します。
