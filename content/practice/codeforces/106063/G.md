 # 問題の理解

 この問題は、演算のたびに同じ乗算係数によって減少する値をモデル化します。 Gatunoはハートサイズから始まります`H1`。 一口食べるたびに、現在の心臓のサイズが で乗算されます。`(B - 1) / B`, そのため、操作を行うたびに値が小さくなります。 心臓のサイズが最大になるまでに必要な最小の咬傷数を見つける必要があります。`H2`。 

入力には多くの独立したケースが含まれています。 各ケースには、開始値、目標値、および値が毎回どれだけ縮小するかを制御する残忍性係数が示されます。 出力は、次の乗算の最小数です。`(B - 1) / B`目標を達成するために必要です。 

テスト ケースの数は次のように大きくなります。`100000`したがって、すべての咬み傷をシミュレートするソリューションは不可能です。 最悪の場合、その答えは数百万回の操作に及ぶ可能性があります。 1 つのケースでは数百万回の反復が処理可能に聞こえますが、それに乗算すると、`100000`あまりにも多くの操作を実行します。 テスト ケースごとに少量の一定量の作業のみを実行するソリューションが必要です。 

の値`H1`と同じ大きさにすることができます`10^12`これにより、浮動小数点演算を使用してハートの値を繰り返し保存および更新するアプローチが除外されます。 多くの演算を行うと値が非常に小さくなり、乗算を繰り返すと精度誤差が蓄積される可能性があります。 数学的な関係を直接扱う必要があります。 

よくある間違いは、値が最初に ** 以下** になったときが答えであることを忘れることです。`H2`、厳密にはそれ以下ではありません。 例えば：```
1
100 50 2
```一口食べた後の値は正確です`50`、したがって、答えは次のとおりです`1`。 以下の値のみをチェックする実装`H2`間違って戻ってきます`2`。 

減少が非常に遅い場合には、別の特殊なケースが発生します。 例えば：```
1
1000 1 10
```その要因は`0.9`, そのため、値は徐々に減少します。 答えは`66`。 答えが小さいと仮定したり、固定回数の反復を試行したりする解決策は、ここで失敗します。 

最終的な精度のエッジ ケースは、数学的答えが整数に非常に近い場合です。 例えば：```
1
100 99 100
```レシオが小さいのでバイト数は多めです。 対数を使用して答えを計算すると、次のような値が得られます。`100.00000000001`正確にはではなく`100`。 やみくもに応募すると`ceil`、数えすぎてしまう可能性があります。 

# アプローチ

 直接的なアプローチは、プロセスをシミュレートすることです。 から始める`H1`を繰り返し乗算します。`(B - 1) / B`、値が以下になるまで何回行うかを数えます。`H2`。 これはプロセスに正確に従っているため、明らかに正しいです。 

問題は操作回数です。 単一のテスト ケースに対する最大の答えは約数百万であり、`100000`テストケース。 シミュレーションを実行すると、全体的に非常に多くの乗算が必要になります。 

重要な観察は、乗算を繰り返すと等比数列が形成されるということです。 後`n`バイトの値は次のとおりです。`H1 * ((B - 1) / B)^n`最小のものが必要です`n`次のような:`H1 * ((B - 1) / B)^n <= H2`すべての中間値を生成する代わりに、対数を使用してこの不等式を解くことができます。 対数を取ると、指数が乗算に変換されます。`n * log((B - 1) / B) <= log(H2 / H1)`ベースが間にあるので、`0`そして`1`、対数が負なので、割るときに不等号の方向が変わります。 並べ替えると次のようになります。`n >= log(H2 / H1) / log((B - 1) / B)`条件を満たす最小の整数がこの値の上限となります。 

浮動小数点精度には若干の補正が必要です。 答えの候補を計算した後、対数を使用して近くの整数をチェックすることで、ローカルで答えを検証します。 これにより、整数の境界に非常に近い値によって引き起こされるエラーが回避されます。

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、等比数列の公式を使用して、答えの対数推定値を計算します。 

この式は、ターゲットが交差する正確な点を表す実数を与えます。 整数のバイト数が必要なので、答えはこの値を下回らない最小の整数でなければなりません。 
2. 推定値を四捨五入して、回答の候補を取得します。 

これは、浮動小数点の丸めによって真の境界よりわずかに下の値が得られる通常のケースを処理します。 
3. 対数式を再度比較して、候補の周囲のいくつかの値を確認します。 

浮動小数点精度で考えられる唯一の間違いは、1 つずれることです。 近くの値をテストすると、遅いシミュレーションを必要とせずに問題が修正されます。 
4. 不等式を満たす最初にチェックされた値を返します。 

これにより、有効な最小数のバイトが返されることが保証されます。 

それが機能する理由: 心臓のサイズの順序はまさに等比数列です。 対数変換により、有効なバイト数と無効なバイト数の間の正確な数学的境界が得られます。 修正ステップでは数値表現の問題のみが解決されますが、基礎となる比較は依然として元の不等式に従います。 

# Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve_case(h1, h2, b):
    # Need the smallest n where:
    # h1 * ((b - 1) / b)^n <= h2

    ratio_log = math.log((b - 1) / b)
    need_log = math.log(h2 / h1)

    ans = math.ceil(need_log / ratio_log)

    def ok(x):
        return math.log(h1) + x * ratio_log <= math.log(h2) + 1e-15

    while ans > 0 and ok(ans - 1):
        ans -= 1

    while not ok(ans):
        ans += 1

    return ans

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        h1, h2, b = map(int, input().split())
        out.append(str(solve_case(h1, h2, b)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、まず等比数列条件を対数不等式に変換します。`ratio_log`収縮率の対数を格納し、`need_log`ターゲット比率の対数を格納します。 

初期の`ceil`すぐに近い答えを返します。 2 つの while ループは単なる小さな修正です。 これらは、浮動小数点演算により計算値が整数境界の間違った側に配置される場合を処理します。 

比較では、実際の心拍数を計算する代わりに対数を使用します。 直接乗算を行うと、多くのバイトの後で非常に小さな浮動小数点数を処理する必要があり、精度が失われる可能性があります。 

の`1e-15`マージンは、小さな浮動小数点ノイズが原因で数学的に等しいはずの値が拒否されるのを防ぎます。

# テストケース```python
import sys
import io
import math

def solve_case(h1, h2, b):
    ratio_log = math.log((b - 1) / b)
    need_log = math.log(h2 / h1)
    ans = math.ceil(need_log / ratio_log)

    def ok(x):
        return math.log(h1) + x * ratio_log <= math.log(h2) + 1e-15

    while ans > 0 and ok(ans - 1):
        ans -= 1
    while not ok(ans):
        ans += 1
    return ans

def run(inp: str) -> str:
    data = inp.strip().split()
    t = int(data[0])
    idx = 1
    res = []
    for _ in range(t):
        h1 = int(data[idx])
        h2 = int(data[idx + 1])
        b = int(data[idx + 2])
        idx += 3
        res.append(str(solve_case(h1, h2, b)))
    return "\n".join(res)

 # エッジケース

 正確な対象ケースの場合:```
1
500 500 2
```縮小する必要がないため、対数式ではゼロが生成されます。 アルゴリズムは戻ります`0`数学的条件を即座に通過します。 不必要な噛みつきは決して行いません。 

等価境界の場合:```
1
100 50 2
```一口食べた後の表情はまさに`50`。 検証ステップのチェック内容`<=`ということで候補は`1`有効のままです。 厳密に比較すると、誤って答えが増えてしまいます。 

非常にゆっくりと縮小する場合:```

```比率は`0.9`つまり、各操作では現在の値の 10 パーセントのみが削除されます。 このアルゴリズムは、何百万回も繰り返される乗算を回避し、交差点を直接計算します。 

精度が重要な値の場合:```
1
100 99 100
```数学的な答えは整数に近くなります。 最初の対数推定値はわずかに不正確である可能性がありますが、最終的な修正では隣接する値をチェックし、真の最小値の有効な答えに移動します。
