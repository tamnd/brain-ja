 ## 問題の理解

 一連の床の形をした塔が与えられます。 各フロアには少数の部屋が含まれており、連続するフロアの間には、フロア上のいくつかの部屋を接続する方向のある階段があります。`t`上の階の部屋へ`t+1`。 

膨大な数のプレイヤーが 1 階からスタートし、最初はそこにある部屋を選択します。 その後、プロセスはフロアごとに進化します。 各フロアでは、すべての部屋に厳しい制限が課せられます。収容人数を超えるプレイヤーが到着した場合、その部屋にはその人数だけが生き残り、残りは排除されます。 このフィルタリングステップの後、生き残ったプレイヤーは階段を通って次のフロアに移動し、そこで再び定員に直面します。 

重要な点は、問題がゲームの 1 回の実行について問うものではないことです。 代わりに、フロアのすべてのプレフィックスに対して`1..t`、私たちは独自に尋ねます：ゲームがフロアで停止したかどうか`t`、初期分布とすべての動きを最適に選択すると仮定して、終了できる生存者の最大数は何人ですか。 

したがって、概念的には、各クエリは`t`質問: フロア 1 の無制限の供給から始めて、この層状グラフをフロアまで押し進めることができるプレイヤーの最大フローはいくらですか`t`、各部屋は容量制限のある頂点のように機能し、エッジは隣接するフロア間のみを通過します。 

制約は非常に特殊な点で厳しいです。 フロア数は最大 1000 で、各フロアには最大 15 の部屋があります。 これは、各フロアを多項式で独立して処理するソリューションはすべて、`k`このアプローチは実行可能ですが、プレイヤーの数は事実上無限であるため、個々のプレイヤーをシミュレートしようとすることは不可能です。 本当の制限は数値的なものではなく、構造的なものです。 

それぞれの流れを明示的にシミュレートしようとする単純なアプローチ`t`別々に同じプレフィックス間で作業を繰り返します。 この繰り返しが、ほとんどの不正確または遅い解決策が失敗する場所です。すべてのプレフィックスに対して完全な動的プロセスを最初から再計算すると、余分な要素が発生します。`n`、これは不要です。 

微妙なエッジケースは、収容人数がゼロの部屋のフロアから発生します。 部屋の容量がゼロの場合、多くの入力エッジが存在する場合でも、部屋は完全なブロックのように動作します。 たとえば、フロアに収容人数 0 の 1 つの部屋があり、すべてのパスがそこを通過する必要がある場合、プレイヤーはそのフロアを超えて進むことはできません。 伝播前に容量を適用することを忘れたソリューションでは、そのようなノードを介したフローが誤って許可されてしまいます。 

もう 1 つの落とし穴は、移動が厳密に連続するフロア間で行われるという誤解です。 スキップ フロアがないため、階層化を無視した最短パスまたはグローバル グラフ フローの解釈は、到達可能性を過大評価します。

 ## アルゴリズムのチュートリアル

 1. フロア 1 の場合、実質的に無限の数のプレイヤーが参加できるように各部屋を初期化します。 すぐに定員が適用されるため、各部屋`j`フロア 1 では、最終的には正確に保持されます`C[1][j]`選手たち。 これが初期状態となります。 
2. フロアを昇順に処理します。 処理フロア開始時`t`、そのフロアの各部屋に到達できるプレイヤーの数はすでにわかっています。 
3. フロアの容量制約を適用する`t`各部屋を確保することで`j`多くても`C[t][j]`選手たち。 これは移動前の排除をモデル化します。 
4. 部屋からの各階段ごと`u`床の上で`t`部屋へ`v`床の上で`t+1`、生き残ったプレイヤー全員をから押し出します`u`の中へ`v`。 複数の階段が同じ部屋につながっている場合、その貢献度は合計されます。 
5. 床に流入する流れをすべて集めた後`t+1`、各部屋を最大で 2 までに固定するために容量制約を再度適用します。`C[t+1][j]`。 
6. フロアで生き残っているプレイヤーの総数を保存します`t`そのプレフィックスの答えとして上に移動する前に。 
7. 最後のフロアまで続けます。 

重要なアイデアは、各フロアがボトルネック変換として機能するということです。つまり、入力分布を受け取り、それをキャップして、次の層に再配布します。 

### なぜ効果があるのか

 各フロアで`t`、各ルームに何人のプレイヤーがいるかを表す状態ベクトルは、プレフィックスのすべての有効な戦略の下で達成可能な最大値です。`t`。 より効果的であると主張する代替戦略では、ある部屋のキャパシティを超えるか、存在しない階段を通じてより多くの流れを送る必要があります。 両方の制約がすべての遷移で正確に適用されるため、不正な累積がカウントされることはありません。 したがって、このプロセスでは、到達可能な最適なフローが層ごとに維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, m = map(int, input().split())
    C = [list(map(int, input().split())) for _ in range(n)]

    adj = [[] for _ in range(n)]
    for _ in range(m):
        f, u, v = map(int, input().split())
        f -= 1
        u -= 1
        v -= 1
        adj[f].append((u, v))

    dp = [0] * k
    ans = []

    # floor 1 initialization
    for j in range(k):
        dp[j] = C[0][j]
    ans.append(sum(dp))

    # process floors
    for t in range(1, n):
        nxt = [0] * k

        # move flow through stairs from floor t-1 to t
        for u, v in adj[t - 1]:
            nxt[v] += dp[u]

        # apply capacities of floor t
        for j in range(k):
            if nxt[j] > C[t][j]:
                nxt[j] = C[t][j]

        dp = nxt
        ans.append(sum(dp))

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```実装では単一のベクトルが保持されます`dp`現在のフロアの各部屋に何人のプレイヤーが参加できるかを表します。 移行ステップでは、現在のレイヤーから始まる階段のみを使用して、次のフロアの分布を構築します。 流入フローを蓄積した後、容量アレイがハード キャップとして適用されます。 

微妙な点は、フロア間の現在の遷移に属するエッジのみを処理することです。 エッジは入力のフロアによってインデックス付けされるため、すべてのエッジをスキャンすることは避けられます。`m`エッジを繰り返します。 

もう一つの詳細は、合計です`dp`各フロアが安全になった後は、生存者の総数がそのレベルの部屋全体の有効なフローの合計に正確に一致するためです。 それ以降は、隠れた再配布は行われません。

1階以降の状態は`[3, 1]`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf

    n, k, m = map(int, input().split())
    C = [list(map(int, input().split())) for _ in range(n)]
    adj = [[] for _ in range(n)]
    for _ in range(m):
        f, u, v = map(int, input().split())
        adj[f - 1].append((u - 1, v - 1))

    dp = [0] * k
    out = []

    for j in range(k):
        dp[j] = C[0][j]
    out.append(sum(dp))

    for t in range(1, n):
        nxt = [0] * k
        for u, v in adj[t - 1]:
            nxt[v] += dp[u]
        for j in range(k):
            if nxt[j] > C[t][j]:
                nxt[j] = C[t][j]
        dp = nxt
        out.append(sum(dp))

    return "\n".join(map(str, out))

 ## 特殊なケース

 単一フロアのインスタンスは、アルゴリズムが伝播ステップを試行せず、容量を直接適用することをテストします。 で入力する場合`n = 1`、dp ベクトルは次から初期化されます。`C[1]`、合計はすぐに返され、1 階で停止の定義と一致します。 

完全に切り離されたグラフでは、`m = 0`フローがフロア間を移動できないようにします。 このアルゴリズムは、ゼロ遷移ベクトルを生成することによってこれを処理するため、最初のフロア以降の各フロアはそれぞれの容量に従って崩壊し、分離を正しくモデル化します。 

キャパシティーがすべてゼロのフロアは、ハードエリミネーションを示します。 その層では DP ベクトルが 0 にクランプされているため、利用可能な階段に関係なく、後続のすべての階は 0 のままであり、ボトルネックを超えて生き残るプレイヤーがいないことを反映しています。
