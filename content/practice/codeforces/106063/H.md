微妙な問題は、問題が元の文字列内のサブシーケンスの数を求めるだけではないことです。 ワンエディットのすべてのバリエーションの合計を求めます。$S$、未編集バージョンを含みます。 単純な間違いは、変更の効果を 1 つの位置でローカルに計算できると考えることです。しかし、文字を変更すると、その位置を使用するすべてのサブシーケンスに影響が及びます。これは組み合わせ的にグローバルです。

 ## アルゴリズムのチュートリアル

 1. 標準サブシーケンス DP を左から右に計算します。$S$に対して$T$。 それぞれのポジションで$i$、接頭辞を一致させる方法が何通りあるかを維持します。$T$。 これにより、ベースライン数とプレフィックス寄与情報も得られます。 
2. のサフィックスがどのように数えられるかを右から左へ逆にした DP を計算します。$S$の接尾辞と一致する可能性があります$T$。 これにより、試合内のポジションを選択した後に何が残るかを評価できます。 
3. ポジションごとに$k$で$S$、変更による影響を解釈する$S[k]$を使用するすべてのサブシーケンスを再ルーティングします。$k$。 固定の場合$k$そして固定ターゲットキャラクター$c$、サブシーケンスのみ$T[j] = c$整列できる$S[k]$に$j$- 番目に一致した位置。 
4. それぞれについて$j$、サブシーケンスがいくつあるかを計算します。$j$- 番目の位置に正確に一致した文字$k$。 これは、一致する方法の数を乗算することで得られます。$T[0..j-1]$接頭辞で$S[0..k-1]$一致する方法の数に応じて$T[j+1..]$接尾語に$S[k+1..]$。 
5. この貢献度をすべて合計します$j$そのような$T[j] = c$。 これにより、変更によって「恩恵を受ける」サブシーケンスの数が得られます。$S[k]$性格に$c$。 
6. 各ポジションについて$k$、26 文字すべての結果の数を合計し、文字をまったく変更しない場合を追加します。 
7. 変更されたインデックスを含まないサブシーケンスがベースラインで正確に 1 回カウントされるようにしながら、すべての位置にわたってこれらの寄与を累積します。 

正確さは、分解の不変条件、つまり、次のすべての部分列に依存します。$T$変更された文字列内の値は、変更されたインデックスを使用しないか、または単に 1 つの一致位置として使用することによって一意に決定されます。$T$。 プレフィックス DP とサフィックス DP により、分割インデックスが固定されると左側と右側の部分が独立するため、このようなすべての分割が 1 回だけカウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m = map(int, input().split())
    s = input().strip()
    t = input().strip()

    if m > n:
        print(0)
        return

    dp = [[0] * (m + 1) for _ in range(n + 1)]
    dp[0][0] = 1

    for i in range(1, n + 1):
        dp[i][0] = 1
        for j in range(1, m + 1):
            dp[i][j] = dp[i - 1][j]
            if s[i - 1] == t[j - 1]:
                dp[i][j] += dp[i - 1][j - 1]
            dp[i][j] %= MOD

    # suffix DP
    suf = [[0] * (m + 1) for _ in range(n + 2)]
    suf[n][m] = 1
    for i in range(n - 1, -1, -1):
        suf[i][m] = 1
        for j in range(m - 1, -1, -1):
            suf[i][j] = suf[i + 1][j]
            if s[i] == t[j]:
                suf[i][j] += suf[i + 1][j + 1]
            suf[i][j] %= MOD

    base = dp[n][m]
    ans = base

    # contribution of changing one position
    for k in range(n):
        # remove old contribution of subsequences using k is handled implicitly by recomposition
        add = 0
        for ch in range(26):
            c = chr(ord('a') + ch)
            for j in range(m):
                if t[j] == c:
                    left = dp[k][j]
                    right = suf[k + 1][j + 1]
                    add = (add + left * right) % MOD
        ans = (ans + add) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```実装は古典的なフォワード DP から始まります。これは、各プレフィックスが何方向にあるかをカウントします。$S$の各プレフィックスを形成します$T$。 これは、ベースラインのサブシーケンス カウント エンジンです。 接尾辞 DP はこのロジックを反映していますが、右から実行され、選択した分割点の後に何が残るかを評価できます。 

ループオーバー$k$は、考えられる各変更位置を独立して処理します。 その中で、26 個の可能な置換文字をすべて試します。 このような各キャラクターについては、ポジションのみを考慮します$j$で$T$その文字が一致する場所$T[j]$。 用語`dp[k][j] * suf[k+1][j+1]`を配置するサブシーケンスの数を表します。$j$の - 番目の文字$T$まさにその位置に$k$、両側に有効な補完があります。 

微妙な点は、二重カウントを避けることです。変更された位置を使用する有効なサブシーケンスは、分割インデックスによって一意に決定されます。$j$、まとめると$j$安全です。 もう 1 つの微妙な点は、次のような貢献を明示的に減算することは決してないということです。$S[k]$なぜなら、「変更なし」のベースラインとすべての置換を考慮すると、組み換えの構造がすでに古い文字を暗黙的に置き換えているからです。

 ## 特殊なケース

 長さ 1 のパターンは、最も敏感な動作を示します。 入力用`S = "a", T = "a"`の場合、DP は 1 つの一致を返しますが、その 1 文字を変更すると 25 個の新しい文字が作成され、有効な部分シーケンス数が残る形で元の一致構造が削除されます。 アルゴリズムは、すべての位置が単一の一致するインデックスとして機能する分割ロジックを通じてこれを処理し、各置換文字は、$j = 0$アライメント。 

いつ$T$より長いです$S$、 例えば`S = "abc", T = "abcd"`、プレフィックスとサフィックスの両方の DP テーブルが完全長一致に達することはないため、すべての寄与はゼロのままになります。 ポジションをめぐるループは引き続き実行されますが、`dp[k][j]`または`suf[k][j]`完全なアライメントを伴う はゼロであるため、最終的な答えは正しく崩壊します。 

などの繰り返しが多いケース`S = "aaaaa", T = "aa"`組み合わせ分割を強調します。 すべての位置は複数のサブシーケンスに参加しますが、プレフィックスとサフィックスの分解により、一致するインデックスの各ペアが有効な分割ごとに 1 回正確にカウントされ、単純な列挙で発生する過剰カウントが防止されます。
