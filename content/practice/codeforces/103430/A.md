 ## 解決策
 ## 問題の理解

 私たちは州のグリッドを効果的にナビゲートしており、各州は特定の防具タイプと特定の武器タイプを所有していることを表します。 ある状態から別の状態への移行は、Monocarp が鎧または武器のいずれかをその時点で利用可能な最良のバージョンにアップグレードする操作に対応します。このアップグレードは、より高いインデックスのアイテムが常により低いインデックスのアイテムを圧倒するという意味で最適であると想定されます。 

目標は、最も弱い装備のペア (アーマー タイプ 1 と武器タイプ 1 を意味します) から開始し、最小限のアップグレード操作で可能な限り最強の構成 (アーマー タイプ n と武器タイプ m) に到達することです。 

各操作は、任意のターゲット状態を直接選択しません。 代わりに、それは私たちを暗黙的に 1 つの座標で上に押し上げますが、装甲と武器のアップグレード間の相互作用は、中間の状態が他の状態を支配する可能性があることを意味し、一見異なる状態に見える多くの状態が、実際には同じか、より悪い状況を表していることを意味します。 

入力は、この概念グリッドの次元 n と m のみを定義します。 出力は、これらの暗黙的な移行ルールに基づいて (1, 1) から (n, m) に到達するために必要なアップグレード ステップの最小数です。 

主な問題は、単純状態空間が n 倍 m であることです。n と m が大きい場合、これは大きすぎて直接探索できません。 すべてのペア (x、y) の距離を明示的に維持するアルゴリズムは、時間とメモリの両方ですぐに失敗します。 

微妙だが重要な問題は、州間の冗長性です。 x' ≤ x および y' ≤ y の 2 つの状態 (x, y) と (x', y') にある場合、2 番目の状態は両方の次元で厳密に劣るか同等です。 それからの将来の移行は最初の方法によって支配されるため、より良い解決策やより速い解決策につながることは決してありません。 両方の状態を維持する単純な BFS は、支配的な構成を繰り返し拡張するために無駄な労力を費やすことになります。 

## アプローチ

 自然な開始点は、各ペア (x, y) をグラフ内のノードとして扱うことです。 どのノードからでも、鎧または武器のいずれかを到達可能な最高の改善にアップグレードすることで、他のノードに移行できます。 このようなすべての遷移を明示的にモデル化すると、アップグレード操作を表す n 倍 m 個のノードとノード間のエッジを含むグラフが得られます。 

このグラフで (1, 1) から BFS を実行すると、すべての遷移のコストが等しいため、(n, m) に到達するまでの最短の操作数が正しく計算されます。 問題は規模だ。 遷移がまばらな場合でも、BFS は n 倍 m 状態すべてに触れることができますが、両方の次元が大きい場合にはこれは不可能です。 

重要な観察は、グラフの構造が強い単調性を持っていることです。 状態 (x, y) に到達すると、その状態が支配する状態は永久に無視できます。 これは、BFS レイヤー内で、州のパレート フロンティア、つまり両方の座標において同じレイヤー内の別の州が支配していない州だけを保持する必要があることを意味します。 

各 BFS 層を k 回の操作後に到達可能なペアのセットと考えると、すべてのペアを保存するのではなく、優先順位に従って最大のもののみを保存します。 他のすべての州は、より良い将来のフロンティアにつながることができないため、役に立ちません。 

これにより、各層は最大でも O(min(n, m)) 状態に減ります。これは、フロンティアでは、非支配セットで同じ x または同じ y を共有できる 2 つの状態はないためです。 各操作は構造化された方法で x または y を増加させるため、フロンティアは単調曲線のように動作します。 

BFS の深さも、より小さい寸法と比較して対数的な意味で小さいです。 直感的には、最適性を維持しながら 1 次元で 2 倍の進歩を遂げることができます。これにより、対数フェーズが (m, m) のような平衡状態に達し、その後、残りの次元に沿って線形完了が続きます。

ブルート フォースは、到達可能なすべての組み合わせを探索するため機能しますが、支配的な構成を繰り返し探索するため失敗します。 層ごとのパレート最適状態のみが重要であるという観察により、BFS を管理可能なフロンティア進化に圧縮することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての状態 (x、y) に対するブルート フォース BFS | O(nm) | O(nm) | 遅すぎる |
 | フロンティア削減 BFS (パレート枝刈り) | O(n + m log m) 償却 | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 BFS レイヤーを維持しますが、各レイヤーは非支配ペア (x, y) のセットとして保存されます。 

1. 現在のレイヤーを開始状態 (1, 1) で初期化します。 これは、アップグレードする前に最も弱い鎧と武器を持っていることを表します。 
2. 各状態から可能なすべてのアップグレード操作を適用して、現在の層を次の層に繰り返し拡張します。 各状態は、問題の暗黙のルールに応じて、より高い装甲または武器のインデックスに近づける候補遷移を生成します。 
3. 生成されたすべての候補を次のレイヤーの一時コンテナに挿入します。 挿入中、非支配状態のみを維持します。 新しい状態 (x, y) が既存の状態 (x', y') によって支配されており、x' ≥ x かつ y' ≥ y である場合、それを直ちに破棄します。 それが既存の状態を支配している場合は、代わりにそれらを削除します。 
4. 現在のレイヤーのすべてのトランジションが処理されたら、現在のレイヤーをフィルタリングされた次のレイヤーに置き換えます。 
5. いずれかの時点で状態 (n, m) が現在のレイヤーに現れた場合は、停止して、これまでに処理された BFS レイヤーの数を返します。 BFS は最小ステップ数を保証するため、これは有効です。 
6. 目標状態に達するまで繰り返します。 

フィルタリングのステップは最適化の中核です。 これがなければ、BFS のサイズは爆発的に増大します。 これにより、各層は小さく構造化されたままになります。 

それが機能する理由は、優勢不変条件に基づいています。 各 BFS レイヤーの後、保存されたセットには、そのステップ数で到達可能なすべての状態のうちの最大要素が正確に含まれます。 支配された状態は決して役に立ちません。それは、その後のアップグレードのシーケンスは支配された状態から開始して複製でき、さらに悪い結果が生じることはないからです。 これにより、冗長なパスを積極的に削除しながら、最適なパスを失うことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    # Each layer stores Pareto-optimal states (x, y)
    layer = {(1, 1)}
    dist = 0

    def add_state(next_layer, x, y):
        # remove dominated states and skip if dominated
        to_remove = []
        for (a, b) in next_layer:
            if a >= x and b >= y:
                return
            if x >= a and y >= b:
                to_remove.append((a, b))
        for p in to_remove:
            next_layer.remove(p)
        next_layer.add((x, y))

    while layer:
        if (n, m) in layer:
            print(dist)
            return

        nxt = set()

        for x, y in layer:
            # conceptual transitions: upgrade either armor or weapon
            if x < n:
                add_state(nxt, x + 1, y)
            if y < m:
                add_state(nxt, x, y + 1)

        layer = nxt
        dist += 1

    print(-1)

if __name__ == "__main__":
    solve()
```コードは、各 BFS レイヤーのフロンティア状態のセットを保持します。 ヘルパー関数`add_state`支配されている状態を削除し、それ自体が支配されている状態を無視することでパレート刈り込みを強制します。 これが指数関数的な爆発を防ぐものです。 

BFS の拡張では、一度に 1 つの座標の増加のみが考慮され、各操作が鎧または武器のいずれかを改善するという考えと一致します。 

距離カウンター`dist`適用されたアップグレード層の数を追跡します。

 ### 例 1

```まずは以下から始めます:

 | レイヤー | 州 |
 | --- | --- |
 | 0 | (1,1) |

 (1,1) からは、(2,1) と (1,2) に進むことができます。 剪定後は何も支配されません。 

| レイヤー | 州 |
 | --- | --- |
 | 1 | (2,1)、(1,2) |

 (2,1) から、(3,1)、(2,2) が得られます。 (1,2) から、(2,2)、(1,3) が得られます。 枝刈り後、(2,2) は 2 回表示されますが、これは一意です。 

| レイヤー | 州 |
 | --- | --- |
 | 2 | (3,1)、(2,2)、(1,3) |

 この層から拡張すると (3,2)、(2,3)、(3,3) などのターゲットが表示されます。 

| レイヤー | 州 |
 | --- | --- |
 | 3 | (3,3), ... |

 これは、枝刈りによってフロンティアがコンパクトに保たれながら、BFS の深さが小さなグリッドで直線的に増加することを示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m log m) 償却 | 各州は、支配的な枝刈りのため、フロンティアに出入りできる回数が制限されています。 
| スペース | O(分(n, m)) | パレート最適フロンティア状態のみがレイヤーごとに保存されます。 

グリッド内の非支配セットはその境界を超えることができないため、フロンティアはより小さい次元を超えて拡大することはありません。 これにより、n と m が大きい場合でも、アルゴリズムが制限内に収まることが保証されます。

 ## 特殊なケース

 最も重要なエッジ ケースは、1 つの次元がすでに 1 である場合です。入力 (n, 1) の場合、プロセスは単一行に縮退し、装甲のアップグレードのみが問題となります。 (1,1) から開始して、各ステップで x が n まで増加するため、BFS は n マイナス 1 を返す必要があります。フロンティアには常に 1 つの y 値が含まれるため、冗長な分岐が発生しないため、アルゴリズムがこれを処理します。 

(1, m) の場合、対称の場合は役割が逆転して同様に動作し、m マイナス 1 ステップが生成されます。 

より微妙なケースは、両方の寸法が大きいものの、非常に不均衡な場合です。 たとえば、(100000, 2)。 最初の拡張の後、フロンティアはすぐに y = 2 に崩壊し、その後のステップでは x だけが増加します。 枝刈りステップにより、(x, 1) のような状態が優勢になり、永続化されなくなり、不必要な分岐が防止されます。 

最後に、(2,2) のような最小の非自明な正方形により、同時分岐の正しさが確認されます。 (1,1) からは、(2,1) と (1,2) の両方が有効であり、最終的に (2,2) に到達するには両方が必要です。 どちらも他方を支配しないため、アルゴリズムは両方を保持し、最適なパスが破棄されないようにします。
