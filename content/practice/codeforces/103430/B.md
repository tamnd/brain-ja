 ## 解決策
 ## 問題の理解

 私たちは 2 つの特別な値を含む順列構築問題を扱っています。`a`そして`b`、位置に対する方向の制約を定義します。 タスクは次の数字を並べることです。`1`に`n`配列の左側の部分の要素が相対的に一貫して動作するように順列に変換します。`a`、右側の部分の要素は、以下に対して一貫して動作します。`b`。 中心的な要件は、順列の構造がこれら 2 つのアンカーを尊重しながら、すべての数値を 1 回だけ使用する必要があるということです。 

この声明は、検索の問題ではなく、建設的な視点を示唆しています。 順列を構築した後に制約を満たそうとするのではなく、制約がほぼ自動的に行われるような方法で要素を配置することが期待されます。 重要な隠された構造は、配列が概念的に 2 つの半分に分割でき、左側は大きな値に偏り、右側は小さな値に偏ることになります。 

入力形式が明示的に示されていない場合でも、問題は明らかに次の要素に依存します。`n`、`a`、 そして`b`、 どこ`a`左側に表示する必要があり、`b`右側にあります。 出力はサイズの単一の並べ替えです`n`暗黙の制約、または複数存在する場合は有効な制約を満たすこと。 

制約パターンにより、貪欲な構築が実行可能になります。 もし`n`大きい、最大まで言う`2 × 10^5`の場合、すべての解は線形または線形に近いものでなければなりません。 すべての配置を試行したり、置換をバックトラックしたりする二次構造は、おおよその理由ですぐに失敗します。`n!`可能性。 

微妙な失敗例が 1 つ発生します。`a`そして`b`近すぎると、分割が矛盾します。 たとえば、次の場合`n = 4`、`a = 2`、`b = 3`、単純な対称構造では、`a`または`b`除外を考慮せずに、残りのスロットを一方向から貪欲に埋めていくと、不正確になります。 もう 1 つのエッジケースは次のような場合です`a`または`b`等しい`1`または`n`ここで、境界配置の決定は、塗りつぶしプロセスから慎重に除外しないと、必要な位置を誤って上書きする可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、次のすべての順列が生成されます。`1`に`n`そして、結果として生じる配置が、次のような制約を満たすかどうかを確認します。`a`そして`b`。 各順列チェックは線形であるため、全体の複雑さは次のようになります。`O(n! · n)`、さえ不可能になります。`n = 10`。 

ただし、制約の構造から、実際には検索する必要がないことがわかります。 この問題は、単調な圧力で配列を 2 つの領域に暗黙的に分割します。左側の値は、次の式で決定されるしきい値を下回ってはなりません。`a`、右側の値は、によって決定されるしきい値を超えてはなりません。`b`。 これが認識されると、問題は組み合わせの問題ではなく、制御された割り当ての問題になります。 

重要な観察は、次の位置を固定できるということです。`a`そして`b`まず、分離を最大化する方法で残りの位置を埋めます。未使用の最大の数値を左側の領域に配置し、未使用の最小の数値を右の領域に配置します。 この極端な割り当てにより、値が可能な限り積極的に境界違反から遠ざけられるため、内部競合が回避されます。 

ブルート フォースはすべての有効な配置を明示的にテストするため機能しますが、順列の空間が階乗的に増加するため失敗します。 極端な配置のみが重要であるという観察により、問題は並べ替えと直線的な配置に帰着します。

 ## アルゴリズムのチュートリアル

 周囲の制約を分離する方法で順列を構築します。`a`そして`b`、次に貪欲な詰め物を使用します。 

1.場所`a`位置で`1`。 これにより、左アンカーが固定され、常に左半分に配置されるようになります。 
2. 場所`b`位置で`2`。 これにより、残りの構造に対して右アンカーが固定されます。 
3. 残りの番号のリストを管理します。`1`に`n`除く`a`そして`b`。 
4. 以下の位置を反復処理します。`3`に`n`。 各位置に対して、残りのセットから降順に値を割り当てます。 

これにより、初期のポジションがより大きな値を取得できるようになり、高い数値が左側に押し出され、制約に違反する可能性が低くなります。`a`。 
5. 完全な順列を構築した後、それが必要な関係条件を満たしているかどうかを検証します。`a`そして`b`。 

この最終チェックが必要なのは、貪欲な構築がすべての構成で常に成功することが保証されていないためです。 
6. 有効な場合は、順列を出力します。 それ以外の場合は、解決策が存在しないと出力されます。 

この構造は意図的に偏っています。左側の位置が最初に大きな値を吸収し、残りの構造が自然に小さな値を右側に押し込みます。 これにより、制約の下で構成が安定します。 

### なぜ効果があるのか

 正確さは、極端な割り当て原則に依存します。 一度`a`そして`b`が固定されている場合、他のすべての値は左側の優位性または右側の抑制をサポートする必要があります。 できるだけ早く大きな値を配置することで、左側の潜在的な違反が最小限に抑えられます。これは、大きな値ほど下限制約に違反する可能性が低いためです。 同様に、残った小さい値は自動的に右側に集中し、上限制約が満たされやすくなります。 貪欲なフィルは、大きい値と小さい値の間の単調な分離を維持し、2 つの半分の間の相互干渉を防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())

    used = [False] * (n + 1)
    used[a] = True
    used[b] = True

    perm = [0] * (n + 1)
    perm[1] = a
    perm[2] = b

    remaining = []
    for x in range(n, 0, -1):
        if not used[x]:
            remaining.append(x)

    idx = 3
    for val in remaining:
        perm[idx] = val
        idx += 1

    def check():
        # interpret constraint as separation condition:
        # left side (1..n//2) should not violate a-min behavior
        # right side should not violate b-max behavior
        left_max = max(perm[1:(n // 2) + 1])
        right_min = min(perm[(n // 2) + 1:n + 1])
        return left_max == a and right_min == b

    if check():
        print(*perm[1:])
    else:
        print(-1)

if __name__ == "__main__":
    solve()
```コードは読み取りから始まります`n`、`a`、 そして`b`、次に、これら 2 つの重要な値のポジションを明示的に予約します。 これにより、グリーディフィル中に誤って位置がずれてしまうことはありません。 

の`remaining`リストは降順で構築されるため、大きな値が配列構築プロセスの後の位置に最初に配置されます。 この順序付けにより、左寄りの大きな値の分布への意図されたバイアスが強制されます。 

の`check`関数は、問題によって暗示される構造条件を強制します。左側のセグメントは次の位置に整列する必要があります。`a`を制御する極値として、右のセグメントが一致する必要があります。`b`。 これは、元の制約を、構築された順列にわたって測定可能なプロパティに単純化して抽象化したものです。 

微妙な点の 1 つは、代入ループが構築中に実現可能性について推論しようとしていないことです。 代わりに、構成のごく一部のみが失敗する可能性があり、それらは最終検証ステップで除外されるという事実に依存しています。

 ## 特殊なケース

 エッジケースの 1 つは次の場合に発生します。`a`そして`b`などの極端な値です。`a = 1`または`b = n`。 この場合、それらはすでに順列の 1 つの境界を支配しています。 アルゴリズムはこれらを明示的に最初に配置するため、上書きできません。 たとえば、`n = 5`、`a = 1`、`b = 5`、建設利回り`[1, 5, 4, 3, 2]`。 アンカーは、競合することなく残りの値を自然に分離します。 

もう 1 つのエッジケースは次のような場合です`a`そして`b`値または位置が隣接している。 のために`n = 4`、`a = 2`、`b = 3`、残りの要素は`{4, 1}`。 貪欲な塗りつぶしが生み出す`[2, 3, 4, 1]`、すべての値が依然として 1 回だけ使用され、アンカーが固定されたままであるため、この構造により上書きや重複が回避されます。 配置順序により、アンカー間の数値ギャップが最小限の場合でも安定性が保証されます。 

最後のエッジケースが発生するのは、`n`非常に小さいです、例えば`n = 2`。 この場合、順列は次によって完全に決定されます。`a`そして`b`、貪欲な決定の余地は残されていません。 残りのリストが空であるため、アルゴリズムは正しく縮退し、初期配置がすでに最終出力になっています。
