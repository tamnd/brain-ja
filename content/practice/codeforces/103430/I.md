 ## 解決策
 ## 問題の理解

 セグメントのコレクションが与えられ、各セグメントは行に配置されたテトリスのピースを表します。 各ピースは、左の端点から数直線上の連続した間隔を占めます。$L_i$正しいエンドポイントへ$R_i$、値を運びます$c_i$。 タスクは、これらの断片を最大でも次の数に整理することです。$k$行。 単一の行内では、ピースは厳密に重なり合わない左から右の順序で表示される必要があります。つまり、2 つのピースが同じ行に配置されている場合、2 番目のピースは最初のピースが終了した後に厳密に開始する必要があります。 

したがって、各行は互換性のあるセグメントのチェーンを形成します。 すべての行にわたって、各ピースは最大 1 回使用でき、選択したピースの値の合計を最大化したいと考えています。 

主な困難は、重複しない間隔のサブセットをグローバルに選択するだけではないことです。 複数の独立したチェーンが許可されます。$k$、各チェーンは、互換性のある間隔のソートされたシーケンスのように動作します。 

制約の観点から見ると、セグメントの数が十分に大きいため、すべての区間ペアにわたる二次構築が遅くなりすぎます。 すべての間隔のペア間の互換性をチェックする単純なアプローチでは、次のような結果が得られます。$O(n^2)$遷移が発生し、その密なグラフ上で一般的な最小コスト最大フローを実行する試みは実行不可能になります。 これにより、遷移が明示的に列挙されるのではなく暗黙的に表現される定式化が強制されます。 

複数の間隔がエンドポイントを共有する場合、微妙なエッジケースが発生します。 2つの区間を満たす場合$R_i = L_j$、条件では厳密な分離が必要であるため、同じ行に属することはできません。$R_i < L_j$。 非厳密な不等式を使用する不注意な実装では、無効な連鎖が誤って許可されてしまいます。 たとえば、間隔$[1,2]$そして$[2,3]$誤って一緒に配置された可能性がありますが、実際には境界で重なり、厳密な順序に違反します。 

もう 1 つのエッジ ケースは、すべての間隔が重なり合う場合です。$[1,10]$何度も繰り返しました。 この場合、最適解は最大でも次の値を選択する必要があります。$k$そのうち 1 行に 1 つずつあり、チェーンすることはできません。 長いチェーンが存在することを前提としたアプローチは、過大評価になります。 

## アプローチ

 ブルートフォースの観点は、各区間がノードであり、接続される有向グラフを明示的に構築することです。$i \to j$間隔の場合$j$間隔をたどることができる$i$、 意味$R_i < L_j$。 各ノードには重みがあります$c_i$までを選択したいと思います。$k$合計の重みを最大化する別々のパス。 これは古典的な最小コスト フローの定式化です。選択された各パスは行に対応し、フローは互いに素なチェーンを選択します。 

このモデルの正しさは簡単です。なぜなら、行への間隔の有効な割り当ては、頂点が分離されたパスのセットに正確に対応し、またその逆も同様であるからです。 目的は、パスの重みを最大化すること、または同様にマイナスのコストを最小限に抑えることになります。 

問題はグラフ自体です。 すべてのエッジを構築するには、間隔のすべてのペアをチェックする必要があります。$O(n^2)$。 さらに悪いことに、このグラフで標準の最小コスト フローを実行すると、次のような複雑さが生じます。$O(n^3 k)$実際には、密な状態空間上で最短経路の計算が繰り返されるためです。 これは、入力が大きいとすぐに中断します。 

重要な観察点は、互換性関係はエンドポイントのみに依存するということです。$R_i < L_j$。 これは、密なグラフ内で間隔を相互に直接接続する必要がないことを意味します。 代わりに、数直線自体を構造として表現し、コストを収集する際に線のセグメントをスキップするショートカットとして機能する間隔を使用して、フローを座標内で移動させることができます。 

圧縮された座標軸上にフロー ネットワークを構築します。 流れは数直線に沿って左から右に移動します。$k$行数を表します。 各インターバルは特別なエッジとなり、そこからジャンプできるようになります。$L_i$に$R_i + 1$費用がかかる$-c_i$。 このエッジを取ることは、行の 1 つでその区間を選択することに対応します。 

これにより、問題は送信に変わります。$k$最小の座標から最大の座標までの流れの単位を調整し、コストを最小限に抑えます。 基本グラフは単純なチェーンであるため、重要な頂点のみを保持する必要があります。$L_i$そして$R_i + 1$。 中間点は単一の入力エッジと出力エッジのみを持ち、短縮できるため冗長です。 

この削減により、グラフが折りたたまれます。$O(n)$頂点と$O(n)$エッジにより、標準的な連続最短パスの最小コスト フローが可能になります。

 ## アルゴリズムのチュートリアル

 まず、関連するすべての座標を圧縮します。 すべての間隔は、次の 2 つの重要な位置に影響します。$L_i$そして$R_i + 1$。 これらのポイント間の遷移のみが重要であるため、これらの値を並べ替えて重複を排除します。 

次に、これらの圧縮された位置に対してチェーン グラフを構築します。 隣接する各ペアは、区間を選択せず​​に数直線に沿って前進することを表します。 各位置インデックスを接続します$i$に$i+1$容量あり$k$そしてコスト$0$。 容量$k$せいぜいそれを反映しています$k$行は同時に構造を横断できます。 

各インターバル$[L_i, R_i]$の圧縮インデックスから有向エッジとして追加されます。$L_i$の圧縮インデックスに$R_i + 1$、容量あり$1$そしてコスト$-c_i$。 容量$1$各間隔を最大 1 回使用できるように強制します。 

次に、連続した最短経路アルゴリズムを実行します。$k$流量の単位。 各反復では、Bellman-Ford または SPFA を使用して開始座標から終了座標までの最も安価なパスを見つけ、流量の 1 単位を増加し、残存容量を更新します。 

最後に、総コストのマイナスを出力します。これは、選択した間隔の達成可能な最大合計に対応します。 

### なぜ効果があるのか

 フローの各単位は 1 つの行を表します。 フローは左から右にのみ移動し、各間隔エッジは最大 1 回しか使用できないため、間隔は複数行または複数回出現することはできません。 チェーン構造により、単一の流路内で間隔が座標によって自動的に順序付けされることが保証されるため、互換性が確保されます。$R_i < L_j$明示的なチェックではなく構築によって強制されます。 容量$k$最大でも作成することを保証します$k$互いに素なパスであり、問​​題の要件に正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

class Edge:
    def __init__(self, to, cap, cost, rev):
        self.to = to
        self.cap = cap
        self.cost = cost
        self.rev = rev

class MinCostFlow:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, fr, to, cap, cost):
        fwd = Edge(to, cap, cost, None)
        bwd = Edge(fr, 0, -cost, fwd)
        fwd.rev = bwd
        self.g[fr].append(fwd)
        self.g[to].append(bwd)

    def min_cost_flow(self, s, t, f):
        n = self.n
        res = 0
        INF = 10**18

        while f > 0:
            dist = [INF] * n
            inq = [False] * n
            prevv = [-1] * n
            preve = [None] * n

            dist[s] = 0
            dq = deque([s])
            inq[s] = True

            while dq:
                v = dq.popleft()
                inq[v] = False
                for e in self.g[v]:
                    if e.cap > 0 and dist[e.to] > dist[v] + e.cost:
                        dist[e.to] = dist[v] + e.cost
                        prevv[e.to] = v
                        preve[e.to] = e
                        if not inq[e.to]:
                            inq[e.to] = True
                            dq.append(e.to)

            if dist[t] == INF:
                break

            addf = f
            v = t
            while v != s:
                e = preve[v]
                addf = min(addf, e.cap)
                v = prevv[v]

            f -= addf
            res += addf * dist[t]

            v = t
            while v != s:
                e = preve[v]
                e.cap -= addf
                e.rev.cap += addf
                v = prevv[v]

        return res

def solve():
    n, k = map(int, input().split())
    seg = []
    coords = set()

    for _ in range(n):
        l, r, c = map(int, input().split())
        seg.append((l, r, c))
        coords.add(l)
        coords.add(r + 1)

    coords = sorted(coords)
    idx = {x: i for i, x in enumerate(coords)}

    m = len(coords)
    mcf = MinCostFlow(m)

    for i in range(m - 1):
        mcf.add_edge(i, i + 1, k, 0)

    for l, r, c in seg:
        mcf.add_edge(idx[l], idx[r + 1], 1, -c)

    ans = -mcf.min_cost_flow(0, m - 1, k)
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まずフロー グラフが小さくなるように座標を圧縮します。 連続する座標間のチェーン エッジにより、最大で$k$独立した走査、に対応$k$行。 

各間隔は、前方にスキップして負のコストを収集するショートカット エッジになります。 最小コスト フロー ルーチンは、キュー ベースのベルマン フォード バリアントを使用して最短の拡張パスを繰り返し見つけます。これは、すべてのエッジ コストが小さな整数であり、圧縮後のグラフが疎であるため、これで十分です。 

よくある間違いは、使用することを忘れることです$R + 1$の代わりに$R$。 このシフトがないと、端点で接する間隔が誤って重複してしまいます。 

## 実用的な例

 ### 例 1

 セグメントを考慮する$[1,2,5]$、$[3,4,6]$、 そして$[2,5,4]$と$k = 2$。 座標は次のようになります。$1,2,3,4,5,6$。 

| ステップ | 流路 | 取得間隔 | コスト |
 | --- | --- | --- | --- |
 | 1 | 1 → 2 → 3 → 4 → 5 → 6 | [1,2] および [3,4] | 11 |
 | 2 | 残りの容量は未使用 | なし | 0 |

 最適なソリューションでは、1 つの行で 2 つの互換性のある間隔が選択され、2 番目の行には未使用の容量が残ります。 

これは、総コストが削減されるため、フローでは可能な限りチェーン化が自然に優先されることを示しています。 

### 例 2

 セグメント$[1,5,10]$、$[1,5,7]$、$[1,5,3]$、 と$k = 2$。 

| ステップ | 行 | 選択された間隔 | 残容量 |
 | --- | --- | --- | --- |
 | 1 | 行 1 | 最良の間隔 | 1 |
 | 2 | 行 2 | 2番目に良い | 0 |

 すべての間隔が重複するため、連鎖することはできません。 フローは複数の行に分割され、それぞれが単一の間隔を選択します。 

これにより、モデルが不可能な場合に誤ってチェーンを強制しないことが確認されます。

 ## 特殊なケース

 重要なエッジケースは、間隔が境界で正確に一致する場合です。 入力用$[1,2]$、$[2,3]$、単純な実装では連鎖が許可される可能性がありますが、正しいモデルではそれが禁止されています。 の使用$R+1$座標圧縮では、これらが互いに切り離された位置になるため、流路が両方の間隔を連続して通過することはできません。 

もう 1 つのエッジケースは次のような場合です$k$は、使用可能な分離パスの数よりも大きいです。 フロー ネットワークでは、引き続き次のことが可能です。$k$ただし、収益性の高いパスのみがフローを運びます。 余分な容量は未使用のまま残され、最大でも選択した要件に一致します。$k$行。 

最後のエッジケースは、間隔が重複していることです。 各間隔エッジの容量は 1 であるため、重複は独立して処理され、フローは各出現を最大 1 回選択できます。これは、独立した部分の意図された解釈と一致します。
