 ## 解決策
 ## 問題の理解

 この問題のプロセスは、段階的に成長するシーケンスとして考えるのが最も簡単です。各ステップはチャットでもう 1 つのメッセージを送信することに対応し、各メッセージはシーケンス内の位置に応じて特定の数の「エモート」を提供します。 

しきい値パラメータがあります。それを呼び出します$k$、貢献パターンが変化します。 到達する前に$k$メッセージの場合、貢献度は単純です。最初のメッセージは 1 を貢献し、2 番目のメッセージは 2 を貢献します。 到達後$k$、パターンは成長し続けるのではなく、対称的に減少し始めます。 

指定された数のメッセージに対して$y$、生成されるエモートの合計数を計算し、この値を目標と比較する必要があります。$x$。 重要なタスクは、特定の$y$少なくとも到達するのに十分です$x$エモートを作成し、この単調な動作を使用して、そのような最小限のものを見つけます。$y$。 

重要な構造特性は単調性です。 送信する場合$y$ターゲットに到達するのに十分なメッセージがあれば、さらに多くのメッセージを送信しても十分です。 これは、二分探索を使用して答えを見つけることができることをすぐに示唆しています。$y$。 

ソリューション要件によって暗示される制約から、各メッセージの寄与を 1 つずつ構築する単純なシミュレーションは、次の場合に遅すぎます。$y$各評価には線形時間がかかり、二分探索ではそのコストに対数係数が乗算されるため、この値は大きくなります。 の範囲であれば、それでも大きすぎます。$y$あたりまでです$10^9$。 

境界ではさらに微妙な問題が発生します$y = k$。 この時点で動作が変わり、特に等差数列の式を増加部分を超えて拡張しようとする場合、単純な実装では遷移を誤って処理することがよくあります。 減少部分は対称ですが、接頭辞の合計を使用して慎重に表現する必要があります。 

エッジケースは次の場合に発生します。$y < k$、 いつ$y = k$、そしていつ$y$可能な最大値に近い$2k - 1$。 特に、$y$近いです$2k - 1$、減少するセグメントは非常に小さくなり、ミラー化された数式でのインデックス付けが正しくないと、負のエラーまたは 1 ずつずれたエラーが発生する可能性があります。 

失敗例の具体例としては、$k = 4$。 のために$y = 5$、正しい計算には、4 までの完全な増加接頭辞が含まれ、その後 3 から始まる減少継続が含まれている必要があります。ピークでの重複を調整せずに等差数列を単純に拡張すると、二重カウントされるか、ピーク寄与を見逃します。 

## アプローチ

 ブルート フォース アプローチでは、各メッセージを直接シミュレートし、その影響を蓄積します。 与えられた$y$1 から 1 までを繰り返します。$y$、前か後かに応じて寄与度を計算します。$k$、すべてを合計します。 これはプロセスを正しくモデル化しますが、コストがかかります$O(y)$小切手ごとに。 広範囲にわたる二分探索と組み合わせると、$y$、これは次のようになります$O(y \log y)$最悪の場合、それは不可能です$y$大きくなる可能性があります。 

重要な観察は、シーケンスが区分的に算術的で対称であるということです。 増加する接頭辞は標準の等差数列であり、減少する接尾辞は 2 つの算術和の差として書き換えることができます。 両方の部分がプレフィックス式を使用して定数時間で計算できることが認識されると、それぞれの実現可能性チェックは次のようになります。$O(1)$、二分探索を有効にします$y$対数時間で。 

2 番目の重要なアイデアは、減少するセグメントを直接構築しないようにすることです。 代わりに、以下の完全な接頭辞として表現します。$k-1$、到達しない部分を表す切り捨てられた接頭辞を差し引いたもの$y$減少領域では十分小さい。 これにより、インデックスの間違いが回避され、すべてが単一のヘルパー関数として維持されます。$cnt(\cdot)$、三角数を表します。

 | ブルートフォース |$O(y)$小切手ごとに、$O(y \log y)$全体 |$O(1)$| 遅すぎる |
 | 最適 |$O(\log k)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. ヘルパー関数を定義する$cnt(n) = \frac{n(n+1)}{2}$、最初の合計を表します。$n$正の整数。 これは、すべてのプレフィックス計算の構成要素です。 
2. 関数を定義する$f(y)$後に生成されるエモートの総数を計算します。$y$メッセージ。 
3. もし$y < k$、 戻る$cnt(y)$私たちはまだ増加段階にあり、対称性が始まっていないため、直接的に。 
4. もし$y \ge k$、ピークまでの完全な増加寄与から開始します。$cnt(k)$。 
5. 減少部分を追加します。 下方向に反復する代わりに、算術合計の差として計算します。 

1 から 1 までの値の合計から始まります$k-1$、つまり$cnt(k-1)$、ミラー降下で早期に停止したために含まれない部分を差し引きます。これは、に相当します。$cnt(2k-1-y)$。 
6. 両方の部分を組み合わせて、$f(y) = cnt(k) + cnt(k-1) - cnt(2k-1-y)$。 
7. 二分探索を使用します。$y$、答えを安全に含めるのに十分な大きさの検索範囲を維持します。通常は最大$2k-1$。 
8. 二分探索の各ステップで、次を計算します。$f(mid)$を満たすか超えるかに応じて範囲を縮小します$x$。 
9. 最小値を返す$y$そのような$f(y) \ge x$。 

正しさは次の事実に依存します$f(y)$は減少していない$y$。 シーケンスがピークに達し、ステップごとの寄与が減少し始めると、完全な対称構造が使い果たされるまで常に正の寄与を追加するため、累積和は依然として単調増加します。 これにより、二分探索で遷移を見逃したり振動したりしないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cnt(n):
    return n * (n + 1) // 2

def f(y, k):
    if y < k:
        return cnt(y)
    return cnt(k) + cnt(k - 1) - cnt(2 * k - 1 - y)

def solve():
    x, k = map(int, input().split())
    
    lo, hi = 1, 2 * k - 1
    ans = hi
    
    while lo <= hi:
        mid = (lo + hi) // 2
        if f(mid, k) >= x:
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、算術ロジックが小さなヘルパー関数に分離されるため、二分探索は読み取り可能なままになります。 主な微妙な点はミラーリングされた用語です$cnt(2k-1-y)$これにより、下降三角形構造のうち、到達しない部分を正しく差し引くことが保証されます。$y$より小さいです。 

よくある実装ミスは、$cnt(y-k)$減少部分に直接。 これは、減少するセグメントが独立していないため、破綻します。 これはピークと重なっており、ゼロから始まる新たな進行ではなく、完全に鏡像化された三角形を基準にして表現する必要があります。 

## 実用的な例

 検討してください$k = 4$、$x = 10$。 この関数はメッセージが増加するにつれて成長し、ピークに達し、その後ミラーリングされます。 

二分探索の評価を追跡します。 

| ミッド | y < k | f(y) の計算 | f(y) |
 | --- | --- | --- | --- |
 | 3 | はい | cnt(3)=6 | 6 |
 | 5 | いいえ | cnt(4)+cnt(3)-cnt(2)=10+6-3 | 13 |
 | 4 | いいえ | cnt(4)=10 | 10 |

 このトレースは、以前の値がどのように変化したかを示しています。$k$単純な三角形に従い、その後の値は$k$ミラー減算項を組み込みます。 

次に、より大きな例を考えてみましょう$k = 5$、$x = 16$。 

| ミッド | 地域 | 計算 | 値 |
 | --- | --- | --- | --- |
 | 6 | y ≧ k | 15 + 10 - cnt(3)=25 - 6 | 19 |
 | 4 | y < k | cnt(4) | 10 |
 | 5 | ピーク | cnt(5) | 15 |

 これは、ピークが$y = k$はきれいに処理され、関数のターニングポイントとして機能します。

 ## 特殊なケース

 いつ$y < k$、関数は純粋な三角数になります。 たとえば、$k = 6$そして$y = 3$、計算は$cnt(3) = 6$。 アルゴリズムは、ミラー化されたロジックを呼び出すことなく、この分岐を直接返します。これにより、不必要な演算が回避され、初期化されていない減少セグメントからの誤った減算が防止されます。 

いつ$y = k$、関数はちょうどピークで遷移します。 のために$k = 4$、$f(4) = cnt(4) = 10$。 2 番目のブランチは目的にのみ使用されるため、実装ではこれをクリーンに処理します。$y \ge k$ただし、正確な境界では減算は行われません。 

いつ$y$に近いです$2k - 1$、ミラー用語$cnt(2k - 1 - y)$小さくなる。 たとえば、$k = 5$そして$y = 8$、用語は次のようになります$cnt(1)$。 これにより、負のインデックスや無効な等差数列範囲を生成することなく、減少する尾部が正しく短縮されることが保証されます。
