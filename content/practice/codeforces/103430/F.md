 ## 解決策
 ## 問題の理解

 正の整数のペアが与えられ、常に大きい方の値に作用する演算を繰り返し適用します。 許可される唯一の方法は、大きい数値を小さい数値との差で置き換えることです。 このプロセスは、いずれかの数値がゼロになるまで続きます。 

タスクは、終了時だけでなく中間状態も含め、このプロセス中の任意の時点でターゲット値がペアのいずれかのコンポーネントとして現れるかどうかを判断することです。 

重要な解釈は、プロセスがランダムに分岐しないということです。 ペアが固定されると、すべての状態は、大きい値から小さい値を繰り返し減算することによって決定され、順序が反転した場合には時々入れ替えられます。 

この制約は、値が十分に大きくなり、すべての減算をシミュレートするのが時間内に不可能になる可能性があることを意味します。 単純な実装では、ある数値から別の数値を繰り返し減算し、初期値に比例する線形数の演算を実行する可能性があります。 数値が連続した大きな整数である場合など、最悪の場合、減算チェーンは非常に長いシーケンスに縮退し、直接シミュレーションが不可能になります。 

ターゲット値が元の数値のいずれかに等しい場合、微妙なエッジ ケースが発生します。 たとえば、ペアが (10, 6) でターゲットが 10 の場合、アルゴリズムが後で状態を (10, 6) から変換するとしても、答えはすぐに YES になります。 終了時にのみチェックする単純な実装では、誤ってこれを見逃してしまいます。 

もう 1 つのエッジ ケースは、ターゲットが 2 つの数値の間にあるにもかかわらず、中間の到達可能な剰余を追跡せずに誤って最適化を試みた場合に、大きな減算ステップによってスキップされる場合に発生します。 

## アプローチ

 強引なアイデアは文字通りルールに従います。 各ステップで、順序が入れ替わるまで、大きい数値から小さい数値を減算し、その後、再度続行します。 これはユークリッド アルゴリズムをシミュレートしますが、すべての中間状態を暗黙的に列挙します。 すべての減算は O(1) であるため、ステップ数は依然として膨大になる可能性があります。 最悪の場合、数値が近い場合、減算が 1 つずつ発生し、O(max(a, b)) の演算が行われることになります。 

到達可能なすべての状態はこの決定論的な削減プロセスによって生成されるため、これは概念的に機能します。 ただし、ボトルネックは、これらの減算のほとんどは状態の構造を有意に変更するものではなく、一方の座標をもう一方のコピーを繰り返すことによって減らすだけであることです。 

重要な観察は、a から b を繰り返し減算するフェーズ中に、a の値が a、a - b、a - 2b のように変化するということです。 これらを 1 つずつ実行する代わりに、不等式条件が変化する前に最後の有効な値に直接ジャンプできます。 これは、繰り返し減算を除算に置き換えるときにユークリッド アルゴリズムで使用されるのとまったく同じ最適化です。 

各段階で、プロセスを有効に保ちながら、大きい数値から小さい数値を何回減算できるかを計算します。 これにより、チェーン全体を対数時間でシミュレートできるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(max(a, b)) | お(1) | 遅すぎる |
 | 最適 | O(log max(a, b)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在のペアは、a が少なくとも b になるように順序付けされていると仮定します。 このアルゴリズムは、長い減算実行を繰り返し圧縮します。

1. a が大きい値であることを確認し、必要に応じて入れ替えます。 これにより、現在のフェーズではすべての操作で a から b が減算されるという不変条件が維持されます。 
2. 目標値 x がすでに a または b のいずれかに一致しているかどうかを確認します。 そうなった場合、プロセスはすでに有効な状態に達しているため、すぐに停止できます。 
3. b が a マイナス b より大きい場合、減算が直ちに順序付け条件に違反する状況になります。 この場合、構造を有効に保つために、限られた数の安全な減算のみを実行します。 
4. しきい値を下回るか、ターゲット領域に向かってオーバーシュートする前に、a から b を何回減算できるかを計算します。 これは、繰り返し減算を置き換える圧縮ステップです。 
5. a を a マイナス cnt 倍 b に更新します。ここで、cnt は計算された安全な減算の数です。 
6. a または b のいずれかがゼロになるか、目標値に達するまで、このプロセスを繰り返します。 

重要な考え方は、アルゴリズムの各フェーズがユークリッド アルゴリズムのセグメントに正確に対応し、一方の座標がもう一方の座標を法として一括して縮小されるということです。 

### なぜ効果があるのか

 このプロセスでは、到達可能なすべての状態は、大きい値から小さい値を何らかの順序で繰り返し減算することに等しいという不変条件が保存されます。 ブルートフォース減算中に現れる状態は、現在のペアによって定義された一連の等差数列に基づいている必要があります。 各数列の境界に直接ジャンプすることで、ターゲットに等しい可能性のある値をスキップしません。これは、すべての中間値が小さい数を法として合同であり、減算範囲によって明示的に説明されるためです。 したがって、圧縮により、冗長なステップが削除されながら、到達可能性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b, x = map(int, input().split())
    
    while a and b:
        if a < b:
            a, b = b, a
        
        if a == x or b == x:
            print("YES")
            return
        
        if b == 0:
            break
        
        if a - b >= b:
            cnt = (a - b) // b
        else:
            cnt = 1
        
        cnt = max(1, cnt)
        
        if a - cnt * b <= 0:
            cnt = a // b
        
        a -= cnt * b
    
    if a == x or b == x:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```コードは、減算の方向が固定されるように、ソートされたペアに対して常に演算を行うという不変式を維持します。 最終状態だけでなく中間状態も重要であるため、x のチェックは各反復の早い段階で行われます。 

cntの計算が最適化の鍵となる。 a から b を一度に 1 つずつ減算する代わりに、構造が変更される前に有効な完全な減算を何回実行できるかを推定します。 この調整により、ゼロを超えてオーバーシュートしたり、相対的な順序が変化する領域をスキップしたりすることがなくなります。 

最後に、1 つの値がゼロになることでループが終了する場合は、最終状態も到達可能なシーケンスの一部であるため、最後のチェックを実行します。 

## 実用的な例

 入力 (a, b, x) = (10, 6, 4) を考えてみましょう。 

| ステップ | | b | CNT | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 10 | 6 | 1 | a = 10 - 6 = 4 |
 | 2 | 4 | 6 | スワップ | (6, 4) |
 | 3 | 6 | 4 | 1 | a = 6 - 4 = 2 |
 | 4 | 2 | 4 | スワップ | (4,2) |
 | 5 | 4 | 2 | 2 | a = 4 - 4 = 0 |

 ステップ 1 では、値 4 が直接表示されるため、答えは YES です。 トレースは、ターゲットが最終状態に必ずしも存在するわけではないため、中間値が重要であることを示しています。 

ここで、(a, b, x) = (15, 7, 1) について考えてみましょう。 

| ステップ | | b | CNT | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 15 | 7 | 1 | a = 8 |
 | 2 | 8 | 7 | 1 | a = 1 |
 | 3 | 1 | 7 | スワップ | (7, 1) |
 | 4 | 7 | 1 | 7 | a = 0 |

 ここでは、2 回の圧縮後にターゲット値 1 が表示されます。 このプロセスは、減算を繰り返すことで剰余の完全な等差数列がどのように自然に生成されるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(log max(a, b)) | 各ステップでは、ユークリッド形式の圧縮によって 1 つの値が減ります。 
| スペース | お(1) | 一定数の変数のみが維持されます。 

対数的な動作は、各圧縮ステップがユークリッド アルゴリズムを反映し、少なくとも 1 つの数値の大きさを厳密に小さくするという事実から来ています。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    def solve():
        a, b, x = map(int, input().split())
        while a and b:
            if a < b:
                a, b = b, a
            if a == x or b == x:
                return "YES"
            cnt = (a - b) // b if b else 0
            cnt = max(1, cnt)
            if a - cnt * b <= 0:
                cnt = a // b
            a -= cnt * b
        return "YES" if a == x or b == x else "NO"
    
    return solve()

assert run("10 6 4\n") == "YES"
assert run("15 7 1\n") == "YES"
assert run("10 6 5\n") == "NO"
assert run("8 3 2\n") == "YES"
assert run("7 7 7\n") == "YES"

 ## 特殊なケース

 最初に両方の数値が等しい場合、アルゴリズムは、すべての減算ステップが 1 がゼロになるまで等しいことをすぐに認識するため、初期値に等しい目標には簡単に到達できます。 

ターゲットが小さい方の数値と等しい場合、直接減算中ではなくスワップ後に表示される場合があります。 交換手順により、この構成を見逃すことがなくなります。 

一方の数値が他方の数値を割ると、プロセスは正確な減算の単一の連鎖に崩壊します。 このアルゴリズムは、cnt が商に直接ジャンプできるようにすることでこれを処理し、中間の倍数がスキップされないようにし、したがって x の潜在的な一致が失われないようにします。
