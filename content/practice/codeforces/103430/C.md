 ## 解決策
 ## 問題の理解

 スポーツ A に 1 つのグループ、スポーツ B に 1 つのグループという 2 つの独立したアスリートのグループが与えられています。各アスリートには数値的なスキル値があり、明示的に選手を「交換」することを決定しない限り、すべてのアスリートは自分のスポーツに留まらなければなりません。つまり、代わりに他のスポーツで競争することを意味します。 

目標は、スポーツ A に割り当てられるちょうど k 人のアスリートとスポーツ B に割り当てられるちょうど k 人のアスリートの最終選択を形成し、入れ替え後のスキルの合計を最大化することです。 スワップは非常に特殊な方法でコストがかかります。アスリートがもともとスポーツ A に所属していたが、スポーツ B で使用された場合、その貢献はペナルティ x だけ減らされます。同様に、B のアスリートが A で使用された場合、ペナルティは y です。 

したがって、この構造は、各リストから最適な k を個別に選択するだけではありません。 スポーツ間でアスリートを混合することは許可されていますが、すべてのクロスアサインには方向性に応じて一定の損失が伴います。 

制約 (ICPC スタイルの設定から暗黙的に) は、両方のリストにわたって n が最大約 2×10^5 または同様の大きな値になる可能性があることを示唆しています。 これにより、アスリートのあらゆる可能な再配分について個別に部分和を再計算することが直ちに除外されます。 ソートを繰り返したり、プレフィックスを再計算したり、構成ごとに選択肢をシミュレートしたりするソリューションは遅すぎます。 単一の並べ替えパスと O(n) 回の遷移が必要です。 

貪欲な選択がスポーツごとに個別に適用される場合、微妙なエッジケースが発生します。 たとえば、1 人の非常に強いアスリートを B から A に交換すると、より弱い A アスリートが B に強制的に置き換えられ、そのカスケードでも x と y の差により合計スコアが向上する可能性があるとします。 素朴な「両側から上位 k を取る」は、2 つのプール間の相互作用を無視するため、ここでは失敗します。 

もう 1 つの失敗モードは、対称性を仮定することです。つまり、A→B と B→A の交換を同等のものとして扱います。 ペナルティ x と y は異なり、最適な分割はその非対称性に依存するため、そうではありません。 

## アプローチ

 この強引なアイデアは、最後に選択された 2,000 人の役割のうち、スポーツ A から合計何人のアスリートを採用するかを決定することです。 z が固定されると、残りの 2k − z はスポーツ B から取得されます。z ごとに、ソートされた各リストから利用可能な最良の選手を選択し、スポーツごとの k の最終要件を満たすためにスワップを適用します。 

z を固定すると、自然な貪欲な構造は明らかです。A から上位 z 人のアスリートを取得し、B から上位 2k − z を取得します。ここで、スポーツごとに必要な k と比較して「間違った側」にいるアスリートの数を比較します。 z < k の場合、割り当て A が不足するため、スワップごとにペナルティ y を支払って、k − z 人のアスリートを B から A に変換する必要があります。 z > k の場合、z − k 人の選手を A から B に変換し、交換ごとにペナルティ x を支払わなければなりません。 したがって、合計スコアは、プレフィックスの合計の組み合わせから線形ペナルティ項を差し引いたものになります。 

すべての z を最初から独立して試行すると、プレフィックスの合計が繰り返し再計算されるため、z ごとの作業量が O(k)、つまり O(k^2) になります。 ソートを追加すると、これは O(n log n + k^2) になり、k が大きい場合は遅すぎます。 

重要な観察は、z が 1 ずつ増加すると、1 人のアスリートだけが暫定選択で B から A に移動するということです。 これにより、ペナルティ構造とプレフィックス合計が段階的に変更されます。 両方のソートされたリストのプレフィックス合計を維持し、現在の部分合計を追跡すると、ステップごとに合計スコアを O(1) で更新できます。 これにより、0 から 2k までの z にわたる完全な掃引が線形スキャンに変わります。 

プレフィックスの合計が常に最良の選択を表すように、両方の配列を降順で並べ替えます。 次に、上位から t までの合計を即座にクエリできるように、プレフィックスの合計を事前計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k^2 + n log n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ソートされた配列 A と B を降順で維持し、それらのプレフィックスの合計 SA と SB を維持します。

1. 両方の配列を降順に並べ替えます。 これにより、どの接頭辞も各スポーツからのそのサイズの最良の選択を表すことが保証されます。 
2. A の最初の i 選手の合計としてプレフィックス合計 SA[i] を事前計算し、B についても同様に SB[i] を事前計算します。これにより、任意の上位セグメント合計の定数時間計算が可能になります。 
3. z を 0 から 2k まで繰り返し、z を合計 2k の選択されたアスリートのうち A から選択されたアスリートの数として解釈します。 各 z について、B からの数は 2k − z です。 
4. この構成の基本合計を SA[z] + SB[2k − z] として計算します。 これは、交換前の可能な限り最高の生のスキル合計を表します。 
5. 最終的な課題の実現可能性を調整します。 z < k の場合、A ラベルの付いたアスリートが十分にいないため、k − z 人のアスリートを B から A に変換する必要があります。このような変換ごとに合計が y 減るため、y · (k − z) を引きます。 z > k の場合、z − k 人のアスリートを A から B に変換する必要があるため、x · (z − k) を減算します。 
6. すべての z にわたる最大値を追跡します。 
7. 最良の結果を出力します。 

重要な点は、すべての構成が前処理後に一定時間で評価されるため、再計算が完全に回避されることです。 

### なぜ効果があるのか

 任意の固定 z については、カーディナリティ制約を超える選択間に相互作用がないため、上位 z および上位 2k − z アスリートを選択することが最適です。 選ばれた選手をより弱い選手に置き換えるような逸脱は、プレフィックスの合計を減らすだけです。 2 つのグループ間に残っている唯一の結合は、スポーツごとにカウントを正確に k にバランスさせることであり、その結合は、どの特定のアスリートが選択されたかに関係なく、不均衡において線形です。 「最適なプレフィックス選択」と「線形補正」の間のこの分離により、z 上のスイープで構造的に異なるすべての最適な状態が確実に探索されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k, x, y = map(int, input().split())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))

    A.sort(reverse=True)
    B.sort(reverse=True)

    # prefix sums
    SA = [0]
    for v in A:
        SA.append(SA[-1] + v)

    SB = [0]
    for v in B:
        SB.append(SB[-1] + v)

    ans = 0

    # z = number taken from A among 2k total
    for z in range(0, 2 * k + 1):
        if z > len(A) or (2 * k - z) > len(B):
            continue

        base = SA[z] + SB[2 * k - z]

        if z < k:
            base -= y * (k - z)
        elif z > k:
            base -= x * (z - k)

        if base > ans:
            ans = base

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、両方のリストをソートして、任意のプレフィックスがそのサイズの最適な選択に対応するようにすることから始まります。 プレフィックスの合計により、任意の z の定数時間評価が可能になります。 

z 上のループは、2 つのスポーツの間で考えられるすべての分割をチェックします。 実現可能性チェックにより、無効なプレフィックス インデックスにアクセスしないことが保証されます。 調整ステップでは、スポーツ A の割り当てが不足しているか過剰に割り当てられているかに応じて、正しいペナルティが適用されます。 

最大値はグローバルに追跡され、最後に出力されます。 この実装は、正しいプレフィックス インデックス付けに大きく依存しています。 SB[2k − z] が常に範囲内になければならないことを忘れることは、実行時エラーの一般的な原因です。 

## 実用的な例

 k = 2 という小さなケースを考えてみましょう。 

A = [10、4、3]、B = [9、8、1]、x = 2、y = 3。 

すでに降順に並べ替えています。 

プレフィックスの合計を計算します。 

A: SA = [0、10、14、17]

 B: SB = [0、9、17、18]

 z を評価します。 

| z | SA[z] | SB[4−z] | 基礎額 | 調整 | 合計 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 18 | 18 | − y・2 = −6 | 12 |
 | 1 | 10 | 17 | 27 | − y・1 = −3 | 24 |
 | 2 | 14 | 9 | 23 | 0 | 23 |
 | 3 | 17 | 0 | 17 | − x・1 = −2 | 15 |
 | 4 | 無効 | 0 | スキップ | スキップ | スキップ |

 最良の結果は z = 1 で 24 です。これは、B の高い値がペナルティを上回るため、k のバランスが取れているにもかかわらず、A よりも B から意図的に多くを取り出すことを意味します。 

このトレースは重要な動作を示しています。最適な分割は必ずしも k を中心とするわけではなく、すべての z をスキャンするとそのシフトが捕捉されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + k) | ソートが優先され、z 上のスイープは線形です。 
| スペース | O(n) | プレフィックス配列は累積合計を格納します。 

この制約により、大きな入力サイズまで許容されますが、ソートが主なコストであり、その他はすべて線形であるため、この複雑さは一般的な制限内に問題なく収まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m, k, x, y = map(int, input().split())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))

    A.sort(reverse=True)
    B.sort(reverse=True)

    SA = [0]
    for v in A:
        SA.append(SA[-1] + v)

    SB = [0]
    for v in B:
        SB.append(SB[-1] + v)

    ans = 0
    for z in range(0, 2 * k + 1):
        if z > len(A) or 2 * k - z > len(B):

        if z < k:
            base -= y * (k - z)
        elif z > k:
            base -= x * (z - k)
        ans = max(ans, base)

    return str(ans)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、配列の 1 つが小さすぎて z の極値を満たすことができない場合です。 たとえば、k = 3 の場合、A には要素が 2 つだけあり、B には多くの要素があります。 z = 5 の場合、SA[z] は無効なのでスキップする必要があります。 このアルゴリズムは、プレフィックス合計にアクセスする前に境界を明示的にチェックし、不可能な構成を非候補として扱うことで正確性を保証します。 

ペナルティがゼロの場合、別のエッジケースが発生します。 この状況では、スワップにはコストがかからないため、最適な解決策は単に結合から上位 2,000 個の要素を取得することです。 z に対するスイープは引き続き機能しますが、z が両方の配列にわたる大きな値の分布と自然に一致する場所で最良の値が表示されます。 

最後のエッジケースは、一方のリストが他方のリストを大きく支配し、すべての最適な構成が一方に偏ってしまう場合です。 たとえば、すべての B 値が A よりもはるかに大きい場合、最適な z は 0 に近い可能性があります。すべての z を列挙することで、k でのバランスを仮定するのではなく、この極値が引き続き評価されることが保証されます。
