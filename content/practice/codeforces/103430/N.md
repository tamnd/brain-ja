 ## 解決策
 ## 問題の理解

 3 つの別々のテキスト行が与えられ、各行をターゲットの母音数パターンと照合してチェックする必要があります。 パターンは、1 行目の母音 5 個、2 行目の母音 7 個、3 行目の母音 5 個に固定されています。 

ただし、ねじれは、その文字です。`y`（大文字でも小文字でも）曖昧です。 最初は母音としてカウントされませんが、必要に応じてオプションで母音として扱うことができます。 1 つおきの文字は固定されており、母音または子音のいずれかであり、その役割を変更することはできません。 

各行について、2 つの値を計算します。 1つ目は`v`、行内の限定母音の数（除く）`y`そして`Y`。 2つ目は`y`、の出現数`y`または`Y`。 それぞれなので`y`母音または子音のいずれかとして独立して機能することができ、その行内で達成可能な母音の数によって次の間隔が形成されます。`v`に`v + y`。 

行は必要なターゲットに対して有効です`V`そのターゲットがこの間隔内にある場合に限ります。 入力全体が受け入れられるためには、3 行すべてがそれぞれのターゲットを同時に満たさなければなりません。 

入力は 3 つの短い文字列のみで構成されているため、制約は最小限です。 文字の単純なスキャンでも十分に高速であるため、合計入力サイズが線形であれば、どのようなソリューションでも十分です。 高度なデータ構造や各行の 1 回のパスを超える最適化は必要ありません。 

よくある間違いは治療中に起こります`y`いつものように母音か、いつものように子音。 たとえば、次の行を考えてみましょう`"bYb"`。 ここ`v = 0`そして`y = 1`、したがって、考えられる母音数は次のいずれかです。`0`または`1`。 数え間違えたら`Y`いつものように母音を使用すると、それを強制的に寄与させてしまい、より厳密な目標が必要な場合に実現可能性を誤って結論付ける可能性があります。 同様に、常に子音として扱うと、ターゲットに到達する必要があるケースを誤って拒否する可能性があります。 

## アプローチ

 ブルートフォース解釈では、それぞれのすべての割り当てが明示的に試行されます。`y`母音または子音のいずれかの文字。 を含む行の場合`k`の発生`y`、これは次のことにつながります`2^k`構成ごとに母音をカウントし、結果の値がターゲットと一致するかどうかを確認します。 3 行にわたって、これは最悪の場合指数関数的になりますが、問題の構造を考えると不要です。 

重要な点は、実際には割り当てを列挙する必要がないということです。 それぞれ`y`最大母音数を独立して 1 つだけ増やしますが、最小数には影響しません。 これは、すべての行が単純な間隔に圧縮されることを意味します。`[v, v + y]`。 次に問題は、固定整数が間隔 (1 行あたりの一定時間) 内にあるかどうかをチェックすることに帰着します。 

この変換は有効です。`y`独立して貢献し、他のキャラクターと対話しません。 この独立性を認識すると、指数関数的な選択空間は単純な範囲チェックに崩壊します。

 ## アルゴリズムのチュートリアル

 3 つの行をそれぞれ独立して処理し、行ごとに必要な母音数を満たせるかどうかを計算します。 

1. 行を読み取り、2 つのカウンタを初期化します。`v = 0`定母音の場合と`y = 0`曖昧なため`y`文字。 この分離は非常に重要です。`y`柔軟性に貢献します。 
2. 行内のすべての文字を繰り返します。 キャラクターが次のいずれかの場合`a, e, i, o, u`いずれの場合も増分します`v`。 キャラクターが`y`または`Y`、増分`y`。 他の文字はすべて、カウントの目的では無視されます。 分類は回線全体の状態です。 
3. この行の位置に基づいて、この行に必要な母音の数を決定します。最初の母音は 5、2 番目の母音は 7、3 番目の母音は 5 です。 
4. 間隔条件を使用して実現可能性を確認する`v ≤ V ≤ v + y`。 これがいずれかの行で失敗した場合、テスト ケース全体が無効になるため、早期に停止できます。 
5. 3 行すべてを処理した後、すべての条件が満たされていれば "YES" を出力し、そうでない場合は "NO" を出力します。 

### なぜ効果があるのか

 それぞれ`y`文字は、まさに 1 単位の柔軟性に寄与します。つまり、子音のままになることも、母音になることもできます。 他のキャラクターはこの特性を持っていません。 したがって、最小母音数は次のように固定されます。`v`、最大値はすべての変換によって達成されます。`y`母音に変える`v + y`。 すべての選択肢は独立しているため、この範囲内のすべての整数値が達成可能ですが、この範囲外の値は不可能です。 したがって、実現可能性のチェックは、ターゲットが各ラインのこの間隔内にあるかどうかをチェックすることとまったく同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

VOWELS = set("aeiouAEIOU")

def check_line(s, target):
    v = 0
    y = 0
    for c in s:
        if c == 'y' or c == 'Y':
            y += 1
        elif c in VOWELS:
            v += 1
    return v <= target <= v + y

def solve():
    lines = [input().rstrip('\n') for _ in range(3)]
    targets = [5, 7, 5]
    
    for s, t in zip(lines, targets):
        if not check_line(s, t):
            return "NO"
    return "YES"

if __name__ == "__main__":
    print(solve())
```この実装は、間隔推論を直接反映しています。 ヘルパー関数`check_line`カウントロジックを分離し、明確な母音と柔軟な母音を分離します。`y`文字。 これにより、オフバイワンの間違いにつながりやすいロジックの混合が回避されます。 

パターン 5-7-5 が固定されているため、ターゲットは順番にハードコーディングされます。 失敗時の早期復帰により、不必要なチェックが実行されなくなりますが、実際には入力サイズが非常に小さいため、これは純粋にスタイル上の理由です。 

細かい点はケースの処理です。 大文字と小文字の両方のバリアントを明示的にチェックするため、文字列全体を変換する必要はありません。これにより、余分なオーバーヘッドが回避され、ロジックが透過的に保たれます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、行にのみが含まれる場合です。`y`文字。 例えば：```
y
```ここ`v = 0`そして`y = 1`、したがって、考えられる母音の数は次のようになります。`[0,1]`。 ターゲットが 5 または 7 の場合、条件は`v ≤ V ≤ v + y`5 は達成可能な範囲外であるため、正しく拒否されます。 間隔チェックは特別なケースなしで失敗するため、アルゴリズムはこれを自然に処理します。 

もう一つのケースは、`y`全然キャラクター。 例えば：```
aeiou
```これにより、`v = 5`そして`y = 0`したがって、唯一の達成可能な値はちょうど 5 です。必要な値が 7 の場合、次の理由により条件は失敗します。`7 ≤ 5 + 0`は誤りです。 このシナリオでは、アルゴリズムに分岐は必要ありません。 同じ間隔のチェックですでにエンコードされています。 

最後の微妙なケースは、次のような大文字と小文字の混合です。```
AeIyOu
```ここでは、大文字と小文字の両方が明示的なチェックによって均一に処理されるため、`v`大文字と小文字に関係なく、すべての標準母音を正しく数えます。`y`正確さに影響を与えることなく柔軟性に貢献します。
