 ## 解決策

 ## 問題の理解

 個別の整数のコレクションが与えられ、それぞれを n ビットのマスクとして見ることができます。 これらの数値を頂点とするグラフを構築し、ビットごとの AND が 0 になるたびに 2 つの頂点を接続します。 言い換えれば、2 つの数値が両方とも 1 を持つビット位置を共有しない場合、2 つの数値は隣接しています。 

タスクは、このグラフに含まれる連結成分の数を判断することです。 

重要な構造上の制約は、n が最大 22 であることです。これは、すべての数値が最大 2²² のサイズの宇宙に存在することを意味します。 これは、ビットのサブセットを状態として扱い、全累乗セットを推論できるほど十分小さいですが、最大 2²² までの m にわたる単純なペアごとのグラフ構築が不可能であるほど十分に大きいです。 

素朴な解釈では、グラフを明示的に構築し、すべてのペアに対して DFS または DSU を実行することを提案します。 ペアの数は m² であるため、これはすぐに問題に直面します。これは、最悪の場合、約 2⁴⁴ の操作となり、実行可能な制限をはるかに超えます。 

各ノードをいくつかの任意の補体に接続しようとしただけの場合、より微妙な障害モードが表示されます。 たとえば、単一の素のパートナーに番号を貪欲に接続すると、中間ノードを介した推移的な接続を簡単に見逃す可能性があります。 小さな例でこれを説明します。 

入力:```
n = 3
a = [1, 2, 4]
```ここでは、すべてのペアに AND ゼロがあるため、グラフは完全に接続されており、答えは 1 です。各ノードを単一の補数に接続するだけのアプローチや、不完全な近傍生成を使用するアプローチでは、完全なクリーク構造を捕捉できない可能性があります。 

主な問題は、隣接関係が指定されたリスト内のローカル構造ではなく、グローバル ビット制約によって定義されることです。 

## アプローチ

 直接グラフを構築すると、すべてのペアがチェックされ、それらのペアが互いに素なビットマスクにリンクされます。 これは正しいですが、m が大きい場合には実行できません。 各エッジ テストは O(1) ですが、ペアが O(m²) あるため、合計作業量は急速に減少します。 

重要な観察点は、グラフが恣意的ではないということです。 すべてのノードは、ビットマスクが完全に補数マスクの内側にあるすべてのノードに接続されます。 これは、ペアごとの比較ではなく、ビットのサブセットの観点から考えることを示唆しています。 

各ノードからエッジを探索する代わりに、視点を反転することができます。つまり、完全な 2ⁿ ユニバースを状態空間として扱い、サブセットにわたるふるいのような伝播を使用します。 中心となるアイデアは、互いに素なマスクを介して接続できる場合は常に、到達可能なすべてのノードを同じコンポーネントの下に統合することです。これは、ビットマスク空間内の補数を横断することに対応します。 

どのマスクが存在するかを前処理し、ビットマスク補数空間上の DFS を使用して接続を伝播します。 マスクにアクセスするたびに、入力セット内に存在するその補数のすべてのサブマスクに移動しようとします。 これにより、任意のペア間に明示的にエッジを構築することが回避されます。 

ペアワイズ チェックを構造化されたサブセット トラバーサルに置き換えることで効率が向上します。 各マスクはその補数のサブマスクを通じて遷移を生成し、慎重に償却すれば 22 ビット空間にわたるサブセットの列挙が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースグラフ | O(m²・n) | O(m) | 遅すぎる |
 | 補数空間上のサブマスク DFS | O(m · 2^(n/2)) 償却 | O(2^n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 指定されたすべての数値を、サイズ 2ⁿ の全ビット空間にわたるブール配列またはハッシュ セットに格納します。 これにより、O(1) メンバーシップ チェックが可能になります。 このステップが必要なのは、後の遷移が候補マスクが存在するかどうかのクエリに依存するためです。 
2. 各番号が正確に 1 つの連結成分に割り当てられるように、同じ空間上で訪問済みの配列を維持します。 これにより、状態の再訪が防止され、到達可能な状態にわたる線形償却が保証されます。 
3. すべての入力数値を反復処理します。 まだアクセスされていない番号ごとに、その番号から DFS を開始し、コンポーネント カウンタをインクリメントします。 
4. ノード x の DFS 内で、すべてのビットが 1 XOR x に設定されると定義される n ビット内でその補数マスクを計算します。 この補数は、x の近傍に出現できるすべてのビットを表します。 
5. この補数のすべてのサブマスクを列挙します。 各サブマスク y は、x から独立した候補ノードを表します。 y が入力セットに存在し、まだ訪問されていない場合は、訪問済みとしてマークし、y から DFS を続行します。 サブマスクの列挙は、補数から開始し、(サブマスク - 1) に移動して補数を繰り返すという標準的な手法を使用して行われます。 
6. したがって、DFS は、素の遷移を繰り返すことで到達可能なすべてのノードを介して拡張され、完全な接続コンポーネントを効果的に検出します。 

### なぜ効果があるのか

 核となる不変条件は、DFS が「ペアごとに素のビットマスクのチェーンを通じて接続できる」関係の終結を正確に探索するということです。 隣接性は素であることによって定義されるため、グラフ内のエッジは有効な遷移に対応します。 逆に、補数のすべてのサブマスクが現在のノードから素であるため、トラバーサル ステップは有効なエッジのみをたどります。 到達可能なすべてのノードは、一連の素な中間マスクを介して接続されている必要があり、DFS はそのような有効な遷移をすべて漏れなく探索するため、各コンポーネントは 1 回だけ検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
arr = list(map(int, input().split()))

N = 1 << n
present = [False] * N
vis = [False] * N

for x in arr:
    present[x] = True

sys.setrecursionlimit(10**7)

def dfs(x):
    vis[x] = True
    comp = (~x) & (N - 1)

    sub = comp
    while True:
        if present[sub] and not vis[sub]:
            dfs(sub)
        if sub == 0:
            break
        sub = (sub - 1) & comp

ans = 0

for x in arr:
    if not vis[x]:
        ans += 1
        dfs(x)

print(ans)
```この解決策は、サイズ 2ⁿ の完全なビットマスク ユニバースに依存します。これは、n ≤ 22 であるため実現可能です。DFS は再帰を使用しますが、再帰の深さが懸念される場合は、明示的なスタックに変換できます。 実装の重要な詳細は、サブマスクの正しい列挙です。完全補数から開始して繰り返し適用します。`(sub - 1) & comp`、すべてのサブセットが正確に 1 回アクセスされるようにします。 

微妙なポイントはマスキング`(~x) & (N - 1)`、補数を n ビットに制限します。 これがないと、Python の無限ビット整数は有効な領域の外側で誤った遷移を引き起こすことになります。

トレースは、完全なサブマスク列挙がすべての互いに素な隣接要素を正しくキャプチャし、完全な接続コンポーネントを生成していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m · 2ⁿ⁻ᵃᵐᵒᵘⁿᵗ) 償却 | 各状態は 1 回訪問され、各 DFS はサブマスクを効率的に列挙します。 
| スペース | O(2ⁿ) | 配列はビットマスク領域全体にプレゼンスと訪問を格納します。 

制限 n ≤ 22 により、2ⁿ サイズの配列がメモリ内で実行可能になり、サブマスクの列挙は、訪問された状態間での償却により時間制限内に留まることが保証されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    arr = list(map(int, input().split()))

    N = 1 << n
    present = [False] * N
    vis = [False] * N

    for x in arr:
        present[x] = True

    sys.setrecursionlimit(10**7)

    def dfs(x):
        vis[x] = True
        comp = (~x) & (N - 1)
        sub = comp
        while True:
            if present[sub] and not vis[sub]:
                dfs(sub)
            if sub == 0:
                break
            sub = (sub - 1) & comp

    ans = 0
    for x in arr:
        if not vis[x]:
            ans += 1
            dfs(x)

    return str(ans)

 ## 特殊なケース

 エッジ ケースの 1 つは、数値のセット内に有効な近傍がない場合に発生します。 たとえば、n = 3 で入力が [7] の場合、補数は 000 となり、DFS はそれ自体にのみアクセスします。 入力に補数のサブマスクが存在しないため、アルゴリズムは 1 つの孤立したコンポーネントを正確にカウントします。 

もう 1 つのケースは、多くの数値がまばらなビット パターンを共有する場合です。 たとえば、n = 4 で 1、2、4、8 のような数値の場合、それぞれの補数には多くのサブマスクが含まれますが、入力には一部のみが存在します。 DFS は引き続き、`present`配列を使用して、存在しないマスクがコンポーネントを展開しないようにします。 

最後の微妙なケースは、ゼロが含まれる場合です。 ゼロはすべての数値と素であるため、ハブになります。 この場合、すべてのマスクはその補数のサブマスク (すべてのビットが設定されている) であるため、0 からの DFS は存在するすべてのノードを探索します。 このアルゴリズムは、グラフ構造に合わせて、セット全体を 1 つのコンポーネントに自然にまとめます。
