 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$n$、そしてそれは2つのランダムな手順のうちの1つによって生成されたと言われています。 どちらの手順も恒等順列から始まります$[1, 2, 3, \dots, n]$、次に、2 つの異なる位置を均等にランダムに選択して交換することを繰り返します。 唯一の違いはスワップの数です。1 つのメソッドが実行します。$3n$もう一方が実行している間にスワップします$7n + 1$交換します。 

タスクは、2 つの生成プロセスのどちらが、指定された最終的な順列を生成する可能性がより高いかを判断することです。 

重要な制約は、$n$と同じ大きさにすることができます$10^6$したがって、どのような解も時間的に線形またはほぼ線形である必要があります。 スワップや確率的サンプリングの繰り返しシミュレーションを伴うものは、制限内では不可能です。 

微妙な点は、両方のプロセスが「ランダムに見える」に非常に近い順列を生成するため、反転を数えたり、並べ替えをチェックするなどの単純な考えでは直接それらを分離できないことです。 違いは単一の順列の構造ではなく、ランダム スワップの数の違いによってもたらされる統計的な偏りにあります。 

よくある間違ったアプローチは、シャッフルをシミュレートしたり、正確な分布について推論しようとしたりすることです。 たとえば、各順列が一様にどの程度近いかをモデル化しようとすると失敗します。$3n$そして$7n+1$スワップはすでに、大規模な場合には均一に極めて近い分布を生成しています。$n$、そして正確な確率計算は実行不可能です。 

別の失敗例は、スワップのパリティベースの不変条件が重要であると仮定することです。 各スワップによって順列反転のパリティが変更されますが、スワップの数が多いため、両方のケースでパリティが基本的に均一に混合されるため、2 つの分布を確実に分離することはできません。 

実際の分離は、ランダム転置に関する既知の事実に依存します。つまり、一様性への収束はスワップの数に依存し、特定の統計は異なる速度で収束します。 このような統計の 1 つは、固定点の数、つまり元の位置に残っている要素の数です。 比較的少数の交換の後、より完全に混合された順列と比較して、より多くの要素が同一性に「近い」ままになります。 

## アプローチ

 直接的な総当たり解釈では、シャッフル プロセスを何度もシミュレートし、どのプロセスが特定の順列を生成する可能性がより高いかを推定します。 これには、スワップのランダムなシーケンスを繰り返し生成し、確率を近似する必要があります。 各シミュレーションの費用$O(n)$、そして意味のある確率分離を得るには非常に多くの試行が必要となり、このアプローチは完全に実行不可能になります。 

もう 1 つの強引なアイデアは、各プロセスで順列を取得する正確な確率を計算することです。 それにはマルコフ連鎖を全体的に追跡する必要がある$n!$順列、それは不可能です。 

重要な観察は、完全な分布情報は必要ないということです。 2 つのプロセス間の唯一の意味のある違いは、置換が同一性に対してどの程度「混合」されているかということです。 スワップが少ないほど、開始時の構成からより多くの構造が保持されます。 スワップが増えると、構造がより徹底的に破壊されます。 

有用な測定可能な指標は、次の位置の数です。$p[i] = i$、つまり固定点です。 少数のランダムな交換の後でも、一部の要素が移動されないままになるか、元の位置構造に戻るという顕著な偏りが依然として存在します。 大幅に多くのスワップを行った後、順列は均一に近づき、予想される固定点の数は 1 付近で安定します。 

したがって、問題は、与えられた順列内の固定点の数を、「混合が少ない」(Petr) と「混合が多い」(Um_nik) を区別するしきい値と比較することに帰着します。 

インデックスの数を計算します$i$そのような$p[i] = i$。 この値が、十分に混合された順列で予想される値と比較して比較的大きい場合、それを Petr として分類します。 それ以外の場合は、Um_nik として分類されます。 この問題では、意図したカットオフ動作は直接比較に単純化されます。つまり、より多くの構造 (より多くの固定点) を持つ順列は、より短いシャッフルから得られる可能性が高くなります。

 ## アルゴリズムのチュートリアル

 この解決策は、順列を 1 回スキャンして、元の位置に留まった要素の数という単一の統計を抽出することに基づいています。 

1. サイズの順列を読み取る$n$。 
2. カウンタの初期化$f = 0$固定点を追跡します。 
3. すべてのインデックスを反復処理します。$i$1から$n$。 位置の値が$i$等しい$i$、増分$f$。 
4. 比較する$f$混合時間によって暗示されるしきい値動作に対する: より高い$f$より少ないスワップが実行されたことを示唆していますが、$f$さらに混合することを提案します。 
5. 順列が同一に近い場合は「Petr」を出力し、そうでない場合は「Um_nik」を出力します。 

重要な推論ステップは、なぜ固定点が有益なのかということです。 各スワップには固定点を破壊または作成する機会がありますが、より長いランダム プロセスは、ランダムな順列の定常分布に向かってより強く収束します。固定点は、依存関係に依存しない一定の期待値の周りに集中します。$n$。 より短いプロセスでは、恒等順列との残留相関が保持されます。 

### なぜ効果があるのか

 ランダムなスワップを繰り返すプロセスは、順列グループのランダム ウォークです。 後$3n$スワップの場合、ウォークは完全に混合されていないため、順列には、より多くの予想される固定点の数を含む、開始時のアイデンティティ構成の測定可能なメモリがまだ保持されています。 後$7n+1$スワップすると、ウォークは平衡に大幅に近づき、固定点の数は平均 1 のポアソン確率変数のように動作します。この収束速度の違いにより、単純な統計で 2 つのケースを確実に区別できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    
    fixed = 0
    for i, x in enumerate(p, start=1):
        if i == x:
            fixed += 1

    # decision rule based on mixing heuristic
    # fewer fixed points -> more swaps (Um_nik)
    # more fixed points -> fewer swaps (Petr)
    if fixed * 2 >= n:
        print("Petr")
    else:
        print("Um_nik")

if __name__ == "__main__":
    solve()
```実装は順列を読み取り、単一パスで固定小数点を計算します。 決定ルールは単純な線形しきい値を使用し、混合の少ない順列と混合の多い順列間の分離を反映します。 

最もデリケートな部分は、しきい値の選択です。 定数因子の比較が機能するのは、2 つのレジームがたとえ大規模な場合であっても、固定点の著しく異なる分布を生成するためです。$n$、そしてこの問題は生成のランダム性を保証し、堅牢なヒューリスティック分離を可能にします。

 ## 特殊なケース

 特殊なケースは恒等置換です。 その状況では、すべての位置が固定されるため、アルゴリズムはすぐに「Petr」を出力します。 これは、短いプロセスではスワップが発生する可能性は低いが、長いプロセスではほぼ確実に ID 構造が破壊されるという考えと一致しています。 

もう 1 つの特殊なケースは、その位置に一致する要素がないという完全な混乱です。 この場合、fixed はゼロに等しく、アルゴリズムは「Um_nik」を出力します。 これは激しい混合を反映しており、より長いスワップシーケンスと一致しています。 

3 番目のエッジ ケースは、複数の短いサイクルを持つ順列など、固定点が配列の約半分にある場合に発生します。 このような中間構造は、完全にランダム化された置換ではなく、不完全な混合の特徴であるため、アルゴリズムは引き続き一貫して動作し、そのため、しきい値ルールの下では Petr に傾きます。
