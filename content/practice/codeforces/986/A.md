 ## 問題の理解

 都市の接続された無向グラフが与えられます。 各町はちょうど 1 種類の商品を生産しており、全体で最大 100 種類の商品が存在します。 町のペアの場合、それらの間で商品を移動する場合、グラフ内の最短経路距離がコストとなります。ここで、各道路は単位長さを持ちます。 

あらゆる街に$v$にあるフェアを開催したいと考えています。$v$。 フェアを運営するには、少なくとも次の商品を集めなければなりません$s$異なるタイプ。 選択したタイプごとに、そのタイプを生産する最も安価な町を選択できます。$v$、そしてその町からへの最短距離を支払います。$v$。 目標は、少なくとも持ち込みにかかる総コストを最小限に抑えることです。$s$さまざまなタイプに$v$。 

出力は長さの配列です$n$ここで、各エントリは、その特定の町で見本市を開催するための最小コストに対応します。 

主な困難は 2 つのスケールの組み合わせにあります。グラフには次のようなものがあります。$10^5$ノードごとに最短パス アルゴリズムを実行することは不可能ですが、タイプの数は$k$は小さい (最大 100) ため、ノードごとではなくタイプごとに距離を前処理することを示唆しています。 

世界中のタイプごとに代表的な町を 1 つだけ選択しなければならないと仮定すると、素朴な誤解が生じます。 タイプに最適な送信元の町は送信先の町によって異なるため、これは不正確です。 たとえば、町 1 に近いタイプは町 2 から遠く離れている可能性があるため、各目的地ではタイプごとに最も近い生産者を独自に選択する必要があります。 

2 番目の微妙な特殊ケースは、同じタイプの町が複数存在する場合です。 タイプごとに世界的に最も優れた生産者だけを選択すると、別の目的地に近い生産者を見逃してしまう可能性があります。 たとえば、タイプ 1 が遠くのクラスターと近くのクラスターの両方で生成された場合、正解はどちらのクラスターが現在のフェア位置に近いかによって異なります。 

この制約は、どのソリューションもクエリごとの最短パスを回避する必要があることを意味します。 と$n = 10^5$、 平$O(n \log n)$ノードごとに実行することは不可能です。 ただし、以来、$k \le 100$、あるタイプのすべてのソースからの距離を同時に計算するソリューションが実行可能になります。 

## アプローチ

 ブルートフォース戦略では、町ごとに計算が行われます。$v$、BFS を使用して他のすべての町への最短距離を選択し、タイプごとに$s$異なるタイプのノード間の最小距離。 これには必要になります$n$BFS の実行、それぞれのコスト$O(n + m)$、につながる$O(n(n+m))$、それは限界をはるかに超えています。 

重要な構造的観察は、距離がタイプに依存しないということです。最短パスは純粋にグラフベースであり、タイプへの唯一の依存はその後のフィルタリング ステップです。 これは視点を逆転させることを示唆しています。 各宛先について、各タイプの最も近いソースは何かを尋ねる代わりに、特定のタイプのすべてのプロデューサーを同時ソースとして扱い、外側への距離を計算します。 

これにより、タイプごとにマルチソース BFS が実現されます。 種類ごとに$t$を生産するすべての町からBFSを開始します$t$、コンピューティング$dist[t][v]$、あらゆる種類の町からの最小距離$t$に$v$。 最大 100 種類のタイプがあるため、最大 100 回の BFS トラバーサルを実行します。$O(n+m)$、それは実現可能です。 

これらの距離を計算した後、各町について$v$、私たちはを収集します$k$価値観$dist[t][v]$、それらを並べ替えて、最小のものを合計します$s$。 以来$k \le 100$、この仕分けは安いです。 

ブルート フォースから最適への移行は、「宛先優先」の計算順序と「タイプ優先」の計算順序を入れ替えることにかかっています。

 ## アルゴリズムのチュートリアル

 1. すべての町を生産タイプごとにグループ化します。 種類ごとに$t$、ソースノードのリストを保存します。 これは、各 BFS が同じタイプのすべてのソースから同時に開始されるため必要です。 
2. 種類ごとに$t$、すべての町が生産するBFSを運営します。$t$距離 0 で初期化されます。エッジ トラバースごとに距離が 1 ずつ増加します。これにより、任意のタイプの町からの最短距離が計算されます。$t$他のすべての町へ。 
3. 結果を行列に保存する$dist[t][v]$、活字を導入するのにどれだけコストがかかるかを表します$t$街へ$v$。 
4. 街ごとに$v$、すべての値を収集します$dist[t][v]$すべてのタイプにわたって$t$。 
5. これらの値を並べ替えて最小値を取得します$s$。 それらを合計して町の答えを導き出します$v$。 
6. すべての回答を出力します。 

BFS ステップの正確さは、BFS が増加する距離レイヤーで探索するため、あるタイプのすべてのソースから同時に開始することが、そのようなソースからの最小距離を計算することと同等であるという事実に依存します。 

## なぜ機能するのか

 固定タイプごとに$t$、BFS は関数を計算します$dist[t][v]$それは等しい$\min_{u: a_u=t} d(u,v)$。 これはまさにタイプをインポートするコストです$t$町へ$v$。 有効なフェア$v$選択する必要があります$s$個別のタイプであり、選択されたタイプごとに、コストは他の選択されたタイプから独立しています。 したがって、総コストを最小限に抑えるには、$s$の中で最も小さい値$k$独立したタイプとコスト。 この選択ステップを超えるとタイプ間に結合は存在しないため、タイプごとの局所的な最適性が全体的な最適性につながります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, k, s = map(int, input().split())
    a = list(map(int, input().split()))
    a = [x - 1 for x in a]

    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    INF = 10**18
    dist = [[INF] * n for _ in range(k)]

    for t in range(k):
        q = deque()
        for i in range(n):
            if a[i] == t:
                dist[t][i] = 0
                q.append(i)

        while q:
            v = q.popleft()
            for to in g[v]:
                if dist[t][to] > dist[t][v] + 1:
                    dist[t][to] = dist[t][v] + 1
                    q.append(to)

    res = []
    for v in range(n):
        vals = [dist[t][v] for t in range(k)]
        vals.sort()
        res.append(str(sum(vals[:s])))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```BFS の走査を繰り返す必要があるため、グラフは隣接リストとして保存されます。 距離テーブルは、$k \times n$これにより、各 BFS は干渉することなく独自のレイヤーに直接書き込むことができます。 

各 BFS は両端キューを使用して線形時間トラバーサルを保証します。 ある型のすべてのプロデューサーは距離 0 に挿入されます。これは重要です。すべてのソースを同時に初期化できないと、BFS が単一ソースとして誤って扱われてしまいます。 

最後のループでは、町ごとのコスト ベクトルを抽出し、最小のものを選択します。$s$。 並べ替えは許容されます。$k$最大でも 100 です。

 ## 特殊なケース

 1 つのタイプの単一ノード グラフの場合、$s=1$, BFS は距離 0 にある唯一のノードを初期化し、移動が必要ないため、答えは正しく 0 になります。 

同じタイプが両端に表示される折れ線グラフでは、マルチソース BFS が両端から正しく広がり、中間ノードが固定エンドポイントではなく最も近いソースを確実に選択します。 たとえば、ノード 1 と 4 のタイプ 1 は対称の距離フィールドを生成し、アルゴリズムは各目的地に対してより近いエンドポイントを自然に選択します。 

密集したスター グラフでは、すべての BFS 層が中心から 1 ステップで伝播し、すべてのリーフが中心を、保持するタイプに最も近いプロデューサーとして正しく認識するようになり、他のリーフを通る長いパスを過剰にカウントするのを防ぎます。
