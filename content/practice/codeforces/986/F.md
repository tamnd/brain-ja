 ## 問題の理解

 非常に大規模な位置のセットで関数を設計できるかどうかを尋ねられます。$10^{18}$、毎秒適用される決定論的なジャンプ ルールのように動作します。 各位置は次の 1 つの位置を正確に指しており、すべての要素はこの固定ルールに従って移動します。 まさにその後$k$このルールを適用すると、すべての要素は元の位置に戻らなければならないため、それ自体で構成される関数は$k$時間はセット全体でアイデンティティのように機能する必要があります。 

これは、次の順列を構築するのと同じです。$\{1, \dots, n\}$すべてのサイクル長が分割されるように$k$順列を繰り返し適用すると、サイクル長の直後に各要素がそれ自体に戻されるため、グローバルに$k$すべてを同期して戻す必要があります。 追加の制限が 1 つあります。1 つのステップで要素を固定したままにすることはできません。つまり、長さ 1 のサイクルは存在しません。 

したがって、問題は分割できるかどうかを決定することになります。$n$要素をサイクルに分割し、その長さが少なくとも 2 で、すべてが分割される$k$。 

この制約により、数論的な視点が強制されます。 の値$n$巨大です、最大で$10^{18}$, したがって、何も列挙したりシミュレーションしたりすることはできません。 クエリの数が多く、最大$10^4$、ただし、個別の数$k$値は小さく、最大 50 です。これは、個別ごとに前処理することを示唆しています。$k$許容されます。 

素朴な解釈ではサイクルを明示的に構築しようとしますが、存在のみが重要であるため、それは無関係です。 

微妙な失敗例は、$k$いつでも自由に使用して合計することができます$n$。 たとえば、次の場合$k = 3$、長さ 3 のサイクルのみが許可されます。 それから$n = 4$3分割でも無理$k$, 残りの要素は少なくとも 2 の長さのサイクルを形成できないためです。 

もう一つの微妙なケースは、$k = 1$ここでは、すべてのサイクルの長さが 1 になるため、有効なサイクルはまったく存在しませんが、これは禁止されています。

### なぜ効果があるのか

 有効な関数はすべて、サイクルに分解された順列です。 その後の状態は$k$ステップごとにすべてが元に戻り、すべてのサイクル長が強制的に分割されます$k$。 もし$k \ge 2$、少なくとも 1 つの有効なサイクル長が存在します (要素をペアにすることができるため、構築の意味では 2 が常に機能します)。 許可された長さのサイクルでセットを並べて並べることができたら、順列を構成します。$k$各サイクルの長さが分割されるため、times は各サイクルを恒等に戻します。$k$。 唯一不可能な状況は、要素が 2 つ未満である場合、または自明でないサイクル長が存在しない場合であり、これは次の場合にのみ発生します。$k = 1$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        if k == 1 or n == 1:
            out.append("NO")
        else:
            out.append("YES")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは、上記で導出された分類を直接実装します。 各テスト ケースは 2 つの境界チェックに減らされます。$k$自明でないサイクル構造を許可します。$n$強制的な固定点を避けるのに十分な大きさです。 比較以外の算術は必要ありません。 

重要な点は、順列を構築しようとしていないことです。 存在引数は、明示的に構築しなくても構築可能性を保証します。
