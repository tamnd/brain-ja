 ## 解決策
 ## 問題の理解

 システム内の各ユーザーは、数直線上の閉区間で記述されます。 トラック ID を 1 から 10^9 までの巨大な軸上の位置と考えると、ユーザー i はセグメント内の整数点を正確に好みます。$[l_i, r_i]$。 

j のセグメントが i のセグメントを完全にカバーする場合、ユーザー j はユーザー i の予測子と呼ばれます。 言い換えれば、i が気に入ったトラックはすべて j も気に入っているということです。$l_j \le l_i$そして$r_j \ge r_i$、j は i に等しくありません。 

固定ユーザー i については、そのすべての予測子を調べます。 2 つの条件が当てはまる場合、i にはトラック x を強く推奨します。 まず、私は x が好きではないので、x は外側にあります$[l_i, r_i]$。 第 2 に、i のすべての予測子は x と同様です。つまり、x はすべての予測子セグメントの交差部分にあります。 

したがって、各 i について、以下を含むすべてのセグメントの交差部分に事実上興味を持ちます。$[l_i, r_i]$。 そのようなセグメントがない場合、答えは 0 です。 

主な問題点は、予測変数がセグメントの両方向の包含に依存しているため、すべてのペア間の単純な比較ですでに次のことが示唆されることです。$O(n^2)$テストケースごとの構造。 テスト全体で合計 n が最大 2×10^5 の場合、ペア間の二次相互作用は遅すぎます。 

複数の同一セグメントが存在する場合、微妙なエッジケースが発生します。 封じ込めには双方向性があるため、各セグメントは他のセグメントの予測子となります。 「self」を誤って削除したり、厳密な封じ込めのみを考慮した単純なソリューションでは、予測変数のカウントを誤る可能性があります。 

もう 1 つの厄介な状況は、最小の包含セグメントが一意でない場合に発生します。 2 人の異なるユーザーが同じ最小の囲み間隔を定義した場合、交差はその間隔そのものとなり、重複を忘れると不正確な空の交差が発生します。 

最後に、予測子を持たないユーザーは、たとえ「空集合上の交差」が数学的には行全体であっても、0 を出力しなければなりません。 この規則は明示的に処理する必要があります。 

## アプローチ

 直接的なアプローチでは、すべてのユーザー i について、他のすべてのユーザー j をチェックして、j に i が含まれているかどうかを判断します。 これにより、予測子の完全なセットが得られます。 このセットを取得したら、すべての左端点の最大値とすべての右端点の最小値を取得して交差を計算し、ユーザー自身のセグメントを減算します。 これは正しいですが、コストがかかります$O(n^2)$最悪の場合、テスト ケースごとに封じ込めチェックが行われますが、これは実行不可能です。 

重要な観察は、封じ込めはエンドポイントによる順序付けのみに依存するということです。 左端点を増加させることによって区間を並べ替える場合、指定された区間 i を含むすべての区間のうち、有効な候補の中で左端点が最小のものだけが、左側の交差を絞り込むために問題になります。 対称的に、i を含むもののうち、最大の右側のエンドポイントを持つもののみが右側の締め付けに影響します。 

これにより、問題は、区間が i を完全にカバーしなければならないという制約の下で、区間ごとに、左側の境界で最適な囲み区間と、右側の境界で最適に囲む区間を計算するようになります。 この制約は、次の間隔に注意を制限することと同じです。$l_j \le l_i$そして$r_j \ge r_i$。 

ソートされた順序で間隔を処理し、適切なエンドポイントをキーとするデータ構造を維持することで、すべての間隔の間で効率的に追跡できるようになります。$l_j \le l_i$、最大右端点、およびそれに関連するクエリ制約$r_i$。 左側のエンドポイントに対するスイープと、圧縮された右側のエンドポイントに対するフェンウィック ツリーまたはセグメント ツリーを使用して、プレフィックス最大クエリをサポートできます。 

秘訣は、包含を 2 つの単調な条件に分割し、固定 i をクエリするときに、両方の制約を満たす有効な j のみを考慮するようにすることです。 

各 i について、そのすべての予測子の交差を決定できれば、答えは単にその交差の長さから次の長さを引いたものになります。$[l_i, r_i]$、ゼロでクリップされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(n)$| 遅すぎる |
 | スイープ + フェンウィック/セグメント ツリー |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 左の端点を増加させてすべての間隔を並べ替えます。 これにより、区間 i を処理するときに、すべての潜在的な予測子 j が次のようになります。$l_j \le l_i$すでに見られているか、プレフィックス構造で効率的に説明できます。 
2. すべての右エンドポイントを座標圧縮して、フェンウィック ツリーまたはセグメント ツリーに保存できるようにします。 右エンドポイントは最大 10^9 になる可能性があるため、これが必要です。 
3. 間隔の右エンドポイントの挿入と、挿入されたすべての間隔の中で最大の右エンドポイントのクエリをサポートするデータ構造を構築します。 この構造は、左端点 ≤ 現在のすべての間隔を表します。 
4. 左端点でソートされた順序で間隔をスイープし、各間隔を構造に挿入します。 
5. 各区間 i について、j に i が含まれるすべての j を見つける必要があります。 条件は$l_j \le l_i$(スイープによって処理されます) および$r_j \ge r_i$。 2 番目の条件を強制するために、挿入されたすべての間隔の構造をクエリし、右端が少なくとも次の値を持つ間隔のみを考慮します。$r_i$。 これらの有効な j の中で最大の右端点を計算し、これにより交差点の右境界が得られます。 
6. 交差点の左境界を正しく計算するために、右から左への対称スイープを繰り返し、次の間隔で左端の最小値を維持します。$r_j \ge r_i$。 これにより、すべての予測子の中で最も狭い左限界が得られます。 
7. i の予測子として適格な区間がない場合は、0 を出力します。そうでない場合は、交差を計算します。$[L_i, R_i]$2 つのスイープから、強く推奨されるカウントは次のとおりです。$(R_i - L_i + 1) - (r_i - l_i + 1)$、ゼロでクリップされます。 

### なぜ効果があるのか

 このアルゴリズムは、封じ込めを 2 つの独立した単調な制約に分解します。 スイープにより、一方の制約が構築によって強制され、フェンウィックまたはセグメント ツリーによってもう一方の制約が強制されます。 不変条件は、各ステップで、データ構造が、左端が封じ込めに有効な区間のセットを正確に表し、そのセット内ですべての予測子の交差を定義する極右端点を抽出できることです。 間隔の交差は極値エンドポイントによってのみ決定されるため、これらの極値を維持するだけで、厳密に推奨されるセットを再構築できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        seg = []
        for i in range(n):
            l, r = map(int, input().split())
            seg.append((l, r, i))

        # compress right endpoints
        rs = sorted({r for _, r, _ in seg})
        comp = {v: i for i, v in enumerate(rs)}

        seg_sorted_l = sorted(seg, key=lambda x: x[0])
        seg_sorted_r = sorted(seg, key=lambda x: x[1])

        # Fenwick for prefix max
        class BIT:
            def __init__(self, n):
                self.n = n
                self.bit = [-1] * (n + 1)

            def update(self, i, v):
                i += 1
                while i <= self.n:
                    self.bit[i] = max(self.bit[i], v)
                    i += i & -i

            def query(self, i):
                i += 1
                res = -1
                while i > 0:
                    res = max(res, self.bit[i])
                    i -= i & -i
                return res

        bit = BIT(len(rs))

        max_r_pred = [0] * n

        j = 0
        for l, r, idx in seg_sorted_l:
            while j < n and seg_sorted_l[j][0] <= l:
                _, rr, id2 = seg_sorted_l[j]
                bit.update(comp[rr], rr)
                j += 1
            # all inserted intervals have l_j <= l_i
            best = bit.query(len(rs) - 1)
            max_r_pred[idx] = best

        # symmetric for left boundary
        seg_sorted_l_rev = sorted(seg, key=lambda x: -x[0])
        seg_sorted_r_rev = sorted(seg, key=lambda x: -x[1])

        bit2 = BIT(len(rs))
        min_l_pred = [10**18] * n

        j = 0
        for l, r, idx in seg_sorted_l_rev:
            while j < n and seg_sorted_l_rev[j][0] >= l:
                ll, _, id2 = seg_sorted_l_rev[j]
                bit2.update(comp[seg_sorted_l_rev[j][1]], ll)
                j += 1
            best = bit2.query(len(rs) - 1)
            if best != -1:
                min_l_pred[idx] = best

        ans = []
        for i in range(n):
            l, r, _ = seg[i]
            L = min_l_pred[i]
            R = max_r_pred[i]

            if L == 10**18 or R == -1 or L > R:
                ans.append("0")
            else:
                total = R - L + 1
                own = r - l + 1
                ans.append(str(max(0, total - own)))

        print("\n".join(ans))

if __name__ == "__main__":
    solve()
```最初のスイープでは、区間ごとに、すべての候補予測子の間の最大右境界が構築されます。 これは、共通の交差点が右にどこまで伸びることができるかを捕捉します。 

2 番目のスイープは、予測変数間の最小左境界をキャプチャするロジックを反映しています。 これら 2 つの値を合わせて、すべての予測子セグメントの交差部分を定義します。 

強く推奨されるトラックはその外側にある必要があるため、最後の減算ではユーザー自身のセグメントが削除されます。 

## 実用的な例

 ### 例 1

 入力:```
3
3 8
2 5
4 5
```左のエンドポイントでソート:

 (2,5)、(3,8)、(4,5)

 | ステップ | アクティブな間隔 | 最大 R | 最小L |
 | --- | --- | --- | --- |
 | (2,5) | (2,5) | 5 | 2 |
 | (3,8) | (2,5),(3,8) | 8 | 2 |
 | (4,5) | すべて | 8 | 2 |

 ユーザー (4,5) の場合、予測子は (2,5) と (3,8) です。 交差点は [3,5] なので、外側 (4,5) は空いていることを強くお勧めしますが、内側の交差点では 1 つのトラックが与えられます: 3。 

これにより、アルゴリズムが極値境界を正しく維持していることが確認されます。 

### 例 2

 入力:```
2
42 42
1 1000000000
```2 番目の区間には最初の区間が含まれるため、(42,42) の予測子は (1,10^9) のみになります。 交差は完全 [1,10^9] で、42 を削除すると 999999999 になります。 

スイープにより、含まれる区間が唯一のアクティブな寄与者であり、境界が正確であることが保証されます。

 ## 特殊なケース

 主なエッジケースは、複数のユーザーが同じ間隔を共有する場合です。 次のような入力の場合:```
3
5 7
5 7
5 7
```すべてのユーザーは他のすべてのユーザーの予測子です。 交差は [5,7] ですが、各ユーザーがその中のすべてのトラックをすでに所有しているため、強く推奨されるカウントは 0 です。両方のスイープで同一の極値が確認され、減算によって完全な間隔が削除されるため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、他のすべてを含む単一の大きな間隔です。```
1 100
2 3
4 5
```小さな間隔の場合、唯一の予測子は大きな予測子であるため、交差は [1,100] になります。 独自のセグメントを減算すると、正しい正の値が得られます。
