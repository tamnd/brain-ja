 ## 解決策
 ## 問題の理解

 連続したビー玉取りゲームでアリスの最終スコアを計算するように求められます。 のコレクションがあります`n`それぞれ特定の色のビー玉。 アリスとボブは、アリスから順番に交互にターンします。 各ターンは、ビー玉を 1 つ取り除くことで構成されます。 アリスのスコアは、彼女が所有する色に基づいて計算されます。アリスは、少なくとも 1 回取得した色ごとにポイントを獲得し、その色のビー玉をすべて集めた色ごとに追加ポイントを獲得します。 

入力は複数のテスト ケースを提供します。 各テスト ケースでは、ビー玉の数とその色を指定します。 出力は、両方のプレーヤーが最適にプレイすると仮定した場合、各ゲームのアリスのスコアです。アリスはポイントを最大化し、ボブはポイントを最小化します。 

制約を考慮すると (`n ≤ 1000`そしてすべての合計`n`テスト ケース ≤ 1000) の場合、時間計算量が最大 O(n²) のアルゴリズムは 2 秒の制限内で快適に実行されます。 これは、実行時間を超過することなく、色ごとの操作を考慮し、すべての色に対する単純な貪欲な戦略をシミュレートすることさえできることを意味します。 

明らかではないエッジ ケースは、単一の色が優勢である場合、またはすべての色が固有である場合に発生します。 たとえば、すべてのビー玉が同じ色の場合、ボブが最適に介入する前にアリスはすべてのビー玉を取得できないため、順番に関係なく 1 つのポイントしか獲得できません。 ビー玉がすべて異なる色である場合、別のトリッキーなシナリオが発生します。 たとえ最適なプレイをしても、「この色のすべてのビー玉」という追加のポイントは達成できない可能性があるため、単純なカウントの合計ではアリスのスコアが過大評価されてしまいます。 

## アプローチ

 ブルートフォースソリューションでは、アリスとボブの間でビー玉を選択する可能性のあるすべてのシーケンスをシミュレートしようとします。 これには、ビー玉のすべての順列を探索し、それぞれのアリスのスコアを評価し、すべてのシーケンスの最大値を取得することが含まれます。 これは正しいですが、法外に遅いです。 のために`n = 1000`、シーケンスの数は`1000!`、それは天文学的な大きさです。 

重要な洞察は、アリスとボブが個々のビー玉ではなく、色の制御のみを考慮していることを認識することです。 特定の色について`x`それが現れる`k`場合によっては、アリスがそれらのビー玉の半分以上を確保できれば、すべてを獲得して追加のポイントを獲得できます。 そうでなければ、彼女は少しでも摂取することを望むことしかできません。 ボブの最適な戦略は、アリスが完成に近づいている色からビー玉を取り除くことです。 これにより、問題は色ごとにビー玉を数えることと、アリスが少なくとも 1 つを使用できる色と、すべてを使用できる色の数を計算することになります。 

貪欲なアプローチは次のようになります。各色に存在するビー玉の数を数え、交互の順番を考慮して、アリスが完全に要求できる色の最大数を決定します。 アリスの先手有利により、ボブがビー玉を割る前に先に行動できれば、色を確保できる可能性があります。

 ## アルゴリズムのチュートリアル

 1. 指定されたビー玉のリスト内の各色の出現数を数えます。 これにより周波数マップが得られます`freq[color]`。 
2. 異なる色の総数を計算します。`distinct_colors`。 アリスには、収集した色ごとに少なくとも 1 ポイントが保証されますが、これは個別の色の数によって制限されます。 
3. アリスが合計で取れるビー玉の数を決定します。 彼女が先に行くので、彼女は取るでしょう`(n + 1) // 2`ビー玉。 
4. 色を周波数の降順に並べ替えます。 これにより、アリスはより多くのビー玉を含む色を優先することができ、色を完成させる可能性を最大限に高めることができます。 
5. 並べ替えた色を繰り返し処理します。 各色ごとに`c`と`k`ビー玉、アリスがこの色から取れるビー玉の数を計算します。 

- アリスが取れるビー玉の残りが≧の場合`k`、彼女はすべてを取る`k`ビー玉を獲得し、「少なくとも 1 つ」ポイントと「すべてのビー玉」ポイントの両方を獲得します。 
- アリスが取れるビー玉の残りが <`k`、すべてを取得することはできませんが、一部を取得することはできます。少なくとも 1 つ取得した場合、「少なくとも 1 つ」ポイントのみを獲得します。 
6. すべてのターンが使用されるか、すべての色が処理されるまで、各色のアリスのスコアを蓄積します。 
7. 累計スコアを返します。 

重要な不変条件は、アリスが最初に触れる個別の色の数を最大化し、できるだけ多くのフルカラーを完成させようとするのに対し、ボブの干渉により色を完成させる能力が低下するということです。 ビー玉の数とハーフターンの割り当てを考慮することで、ボブの動きを明示的にモデル化することなく、最適なプレイを自動的にシミュレートします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import Counter

def alice_score(n, marbles):
    freq = Counter(marbles)
    total_colors = len(freq)
    alice_turns = (n + 1) // 2
    # Sort frequencies descending
    counts = sorted(freq.values(), reverse=True)
    score = 0
    for k in counts:
        if alice_turns == 0:
            break
        take = min(k, alice_turns)
        # At least one marble of this color
        if take > 0:
            score += 1
        # If she takes all marbles of this color, add extra point
        if take == k:
            score += 1
        alice_turns -= take
    return score

t = int(input())
for _ in range(t):
    n = int(input())
    marbles = list(map(int, input().split()))
    print(alice_score(n, marbles))
```コードは各色の頻度をカウントし、降順に並べ替えます。 アリスは、高周波色からできるだけ多くのビー玉を取得し、完了を優先して追加のポイントを獲得しようとします。 私たちは彼女の残りのターンを追跡して、彼女が獲得できるビー玉の総数を超えないようにします。 このロジックにより、「少なくとも 1 つの」ポイントと「すべてのビー玉」のポイントの両方が正しく計算されることが保証されます。

## テストケース```python
import sys, io
from collections import Counter

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    def alice_score(n, marbles):
        freq = Counter(marbles)
        alice_turns = (n + 1) // 2
        counts = sorted(freq.values(), reverse=True)
        score = 0
        for k in counts:
            if alice_turns == 0:
                break
            take = min(k, alice_turns)
            if take > 0:
                score += 1
            if take == k:
                score += 1
            alice_turns -= take
        return score
    t = int(input())
    for _ in range(t):
        n = int(input())
        marbles = list(map(int, input().split()))
        output.write(str(alice_score(n, marbles)) + '\n')
    return output.getvalue().strip()

# Provided samples
