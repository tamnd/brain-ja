 ## 解決策
 ## 問題の理解

 を構築するよう求められています。$k$-番目の数値の順列$1$を通して$n$特定の隣接プロパティを満たすもの。各数値は、その前の数値と比較して最大 1 だけ減少します。 正式には、順列の場合$a_1, a_2, \dots, a_n$、私たちは持っている必要があります$a_{i+1} \ge a_i - 1$あらゆる人にとって$i$。 入力は複数のテスト ケースで構成され、それぞれが順列の長さを示します。$n$そしてインデックス$k$辞書順に。 出力は順列そのもの、または`-1`もし$k$-番目の順列は存在しません。 

制約が示すのは、$n$まで可能です$10^5$、の合計$n$すべてのテストケースにわたって、$10^5$、 そして$k$非常に大きくなる可能性があり、最大で$10^{18}$。 これにより、ほぼソートされた順列の数が階乗的に増加するため、すべての順列を生成したり、メモリに保存したりすることができなくなります。 すべての順列を列挙し、条件をチェックする素朴なアプローチは、次のようなパフォーマンスを発揮します。$n!$したがって、実行不可能です。 

エッジケースが発生するのは次の場合です$n$非常に小さい、または$k$は、ほぼソートされた順列の合計数よりも大きくなります。 たとえば、次のようなとき$n = 1$そして$k = 2$、有効な順列がないため、正しい出力は次のようになります。`-1`。 同様に、$n$より大きいですが、$k$ほぼソートされた制約によって生成される有効なシーケンスの数を超えると、単純なソリューションでは存在しないシーケンスにインデックスを付けようとしてクラッシュする可能性があります。 

## アプローチ

 ブルートフォース手法では、長さのすべての順列が生成されます。$n$、ほぼソートされた条件でフィルターし、辞書順にソートしてから、$k$- 番目。 これは原理的には正しいですが、$n!$たとえ$n = 10$すでに何百万ものシーケンスが含まれており、大規模なものではすぐに扱いにくくなります。$n$。 このアプローチの操作数は次のとおりです。$O(n! \cdot n)$、各順列が必要とするように$O(n)$状態を確認する時間と、$O(n! \log n!)$並べ替えを考慮すると。 これは合理的な時間制限を超えています。 

重要な観察は、ほぼソートされた状態が構築的な構造を暗示していることです。つまり、増加する数値の連続ブロックを先頭で反転して、辞書編集的により大きな次の順列を生成することができます。 より正確には、ブロック内の最大の数値を段階的に前方に移動して、次の条件を満たすことができます。`a_{i+1} \ge a_i - 1`以前に固定された位置を壊さずにプロパティを変更できます。 反転できる次のブロックのサイズを繰り返し決定することで、$k$-th の順列を直接入力$O(n)$すべての順列を列挙することなく、時間を計算します。 これは、プレフィックスの長さが減少するシーケンスの数が減少するという組み合わせの事実を使用します。$m$は$2^{n-m-1}$これにより、二分探索で各ブロックのサイズを効率的に決定できます。

 | ブルートフォース | O(n! \* n) | お(ん!) | 遅すぎる |
 | 建設的なブロックの反転 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 結果の順列とカウンターを保持する空のリストを初期化します。`current`から始まる`1`次の未使用の番号を表します。 

2. その間`current`を超えない`n`、反転する次のブロックのサイズを決定します。 ブロック サイズは最大の整数です`block_size`残りの数値の順列数が少なくとも`k`。 これは、各位置について、$2^{remaining-1}$プレフィックスの長さが最大で減少する、ほぼソートされたシーケンスを形成する方法`remaining`。 

3. より小さいブロックを選択して、スキップされたシーケンスの数を減算します。`k`残りの位置のインデックスを調整します。 

4. 以下の数字のブロックを追加します。`current`に`current + block_size - 1`結果とは逆の順序になります。 インクリメント`current`による`block_size`。 

5. すべての数字が配置されるまで繰り返します。 いつでも`k`形成できるシーケンスの数を超えた場合、出力`-1`。 

機能する理由: このアルゴリズムは、これまでに構築された部分順列が残りの部分順列に対して辞書編集的に最小であるという不変条件を維持します。`k`。 各決定ステップでは、ほぼソートされた条件を満たしながら順列を最小限に抑える、実行可能な最大のブロックが選択されます。 ブロックを反転すると、すべての数値が前の数値よりも 1 少ない範囲内に収まり、からの減算が保証されます。`k`残りの順列に正しくインデックスを付けます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        res = []
        current = 1
        remaining = n
        while current <= n:
            block_size = 1
            count = 1
            while block_size < remaining and count * 2 <= k:
                count *= 2
                block_size += 1
            if count < k:
                k -= count
            else:
                res += list(range(current + block_size - 1, current - 1, -1))
                current += block_size
                remaining -= block_size
        print(" ".join(map(str, res)))

solve()
```コードは最初にテスト ケースの数を読み取ります。 それぞれの場合について、次のようになります。`n`そして`k`。 の`while`ループはブロックごとに置換を構築します。 内側のループが二重になります`count`シーケンスが超えない最大ブロック サイズを見つけるには`k`。 現在のブロックのシーケンス数が以下の場合`k`、デクリメントします`k`そして続けます。 それ以外の場合は、反転した数値ブロックを結果に追加し、カウンターを調整します。 印刷は、順列が完全に構築された後に行われます。 

確実に行われるよう注意が払われています`current`は正しく増分され、残りの位置数はオーバーシュートを防ぐために追跡されます。 の使用`range(current + block_size - 1, current - 1, -1)`逆ブロックを効率的に生成します。
