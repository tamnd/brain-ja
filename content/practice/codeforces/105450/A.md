 ## 解決策
 ## 問題の理解

 キャンディーを表す整数の酸味値のリストが与えられます。 アリスは正確に削除することができます$k$このリストのキャンディー、出発します$n-k$後ろにはキャンディー。 削除後、残りのセットを確認し、残っている最大値と最小値の差を取ることで、それがどの程度「広がっているか」を測定します。 目標は、最終的なスプレッドができるだけ小さくなるように、どのキャンディーを削除するかを選択することです。 

言い換えれば、選択したサブセット内のペアごとの差異を直接制御しようとしているのではなく、削除後に残るものの範囲を制御しているのです。 目的は、残りの値を数直線上でできるだけ緊密にクラスター化することです。 

制約$n \le 1000$大まかに次のような解決策を許可します$O(n^2)$だけでなく、パフォーマンスを気にせずに並べ替えやスライディング ウィンドウを使用できるようになります。 何でも$O(n^3)$それ以上の場合は大規模なリスクが伴いますが、それでも$O(n^2)$快適に過ごせるでしょう。 

すべての数値が同一である場合、微妙だが重要な特殊なケースが発生します。 その場合、すべてのサブセットの範囲はゼロであり、除去に関係なく答えはゼロでなければなりません。 もう 1 つのエッジ ケースは、削除後にキャンディーが 1 つだけ残る場合です。$n-k=1$。 単一要素の範囲は常にゼロであり、正しいアプローチではこれを明示的または暗黙的に処理する必要があります。 

よくある間違ったアプローチは、最適な連続ブロックを考慮せずに、両端から極端な値を貪欲に削除することです。 最適なソリューションが中心にない場合、または複数の密集したクラスターが存在する場合、これは失敗する可能性があります。 たとえば、次のような値を使用すると、$[1, 2, 3, 100, 101]$、間違った極端な値を削除すると、たとえタイトなブロックが存在していても、大きなギャップが残る可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。サイズの可能なすべてのサブセットを試してください。$n-k$、その最小値と最大値を計算し、可能な最小範囲を追跡します。 これはすべての構成をチェックするため正しいですが、計算上実行不可能です。 サブセットの数は$\binom{n}{n-k}$、指数関数的に成長し、$n=30$。 

重要な観察は、値の相対的な順序のみが重要であり、値の元の位置ではないということです。 配列がソートされると、残りの最適なサイズのセットが$n-k$は、この並べ替え順序で連続した要素で構成されている必要があります。 連続していない場合は、選択範囲内にギャップが生じ、極端な要素をより近い欠落要素に置き換えると、常に範囲が縮小または維持されます。 

これにより、ウィンドウのサイズを選択するという問題が軽減されます。$n-k$ソートされた配列内でそのエンドポイント間の差異を最小限に抑えます。 各ウィンドウは、キャンディーをしっかりと詰めたグループを保持し、その外側にあるすべてのものを破棄することを表します。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(\binom{n}{k} \cdot n)$|$O(n)$| 遅すぎる |
 | 並べ替え + スライド ウィンドウ |$O(n \log n)$|$O(1)$番外編 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を降順でない順に並べ替えます。 並べ替えでは、最適なサブセットがこの順序付けで連続したセグメントになるように、すべての候補が整理されます。 
2. 残るキャンディーの数を計算します。$m = n - k$。 これは、評価する必要があるウィンドウの固定サイズです。 
3. 適切なサイズのウィンドウをスライドさせます$m$ソートされた配列全体にわたって。 インデックスで始まる各ウィンドウについて$i$、ウィンドウは次の要素をカバーします。$i$に$i+m-1$。 
4. 各ウィンドウについて、最後の要素と最初の要素の差を計算します。 この値は、それらのキャンディーを正確に保持する場合の範囲を表します。 
5. すべてのウィンドウにわたってそのような最小の差を追跡し、それを出力します。 

並べ替えによって構造が作成され、ウィンドウによってサブセット サイズの制約が強制され、エンドポイントの評価によってウィンドウ内をスキャンせずに範囲が直接キャプチャされるため、各ステップが必要です。 

### なぜ効果があるのか

 並べ替え後のサイズのサブセット$m$連続していない場合は、大きな内部ギャップをサブセットの外側のより近い要素に置き換えることで改善できます。 この交換によって範囲が増加することはなく、多くの場合減少します。 この引数を繰り返すと、最適解が強制的に連続ブロックになります。 したがって、すべての最適解は、長さの 1 つのスライディング ウィンドウに正確に対応します。$m$そして、そのようなウィンドウをすべてチェックすることで、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort()
    
    m = n - k
    if m <= 1:
        print(0)
        return
    
    ans = float('inf')
    
    for i in range(n - m + 1):
        ans = min(ans, a[i + m - 1] - a[i])
    
    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、最適な選択が連続したブロックとして表示されるように配列をソートすることから始まります。 変数`m`削除後に残っているキャンディーの数を表します。 キャンディーが 1 つだけ残っている場合、スプレッドは存在しないため、答えはすぐにゼロになります。 

ループは、可能なすべてのサイズのウィンドウをチェックします。`m`。 開始インデックスごとに`i`、 違い`a[i + m - 1] - a[i]`そのセグメントの範囲を計算します。 すべてのウィンドウの最小値が、達成可能な最良の構成です。 

よくある実装上の間違いは、`n-k`残りの要素ではなく、削除された要素の数として誤って表示されます。 もう 1 つの微妙な問題は、最後の有効なウィンドウが で始まることを忘れていることです。`n-m`、 ない`n-m+1`。

 ## 特殊なケース

 入力などの単一要素の残りの場合:```
3 2
10 1 7
```ソートすると、[1, 7, 10] が得られます。$m = 1$。 単一要素ウィンドウの範囲はゼロであるため、アルゴリズムはすぐに 0 を返します。 これにより、無効なウィンドウ エンドポイントへのアクセスが回避され、範囲の定義が正しく反映されます。 

すべて等しい値の場合:```
5 2
7 7 7 7 7
```どのサイズのウィンドウも同じエンドポイントを持つため、計算されるすべての範囲は 0 になります。最小値は 0 のままで、アルゴリズムは特別なケースを使用せずにこれを自然に処理します。 

広く分離されたクラスターの場合:```
6 2
1 2 3 100 101 102
```ソートされた配列には、すでに 2 つの緊密なグループが表示されています。 サイズ 4 の Windows には、両方のクラスターが含まれるか、1 つのクラスターのみが含まれます。 最適なウィンドウは、範囲 99 を与える [1, 2, 3, 100] か、同様に 99 を与える [2, 3, 100, 101] です。 これは、アルゴリズムがすべての連続する選択候補を体系的に評価し、分割クラスター構成を見逃さないことを確認します。
