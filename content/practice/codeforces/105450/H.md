 ## 解決策
 ## 問題の理解

 各セルが使用可能またはブロックされている長方形のグリッドが与えられます。 トークンは左上のセルから始まり、2 人のプレイヤーが交互に動きます。 ターンでは、プレイヤーはトークンを下、右、または右斜め下に 1 歩移動します。ただし、これは移動先のセルがグリッド内にあり、ブロックされていない場合に限られます。 プレイヤーが正当な手を持っていない場合、そのプレイヤーは直ちに負けます。 

課題は、最初のプレイヤーであるアリスが勝利する戦略を持っているかどうかを判断することです。 

グリッド サイズは 1000 x 1000 まで大きくなる可能性があるため、すべての移動シーケンスを探索しようとするソリューションは明示的に実行不可能になります。 各セルからの完全なゲーム ツリーは最大 3 方向に分岐し、r + c に比例して指数関数的に深さが増大する可能性があるため、単純な再帰探索では時間制限を何桁も超えてしまいます。 

微妙な問題の 1 つは、ブロックされたセルによって孤立した領域が作成され、境界近くにない場合でも一部の位置が行き止まりになる可能性があることです。 たとえば、後方方向以外の黒い四角で囲まれたセルは、後方への移動が許可されていないため無関係であり、実質的に端末負け状態になります。 

もう 1 つのエッジ ケースは、開始セルに有効な動きがまったくない場合です。 白であることが保証されている場合でも、完全に黒または境界に囲まれている可能性があり、アリスは即時に損失につながります。 

## アプローチ

 ゲームの直接シミュレーションでは、すべての白いセルがゲームの状態として扱われ、到達可能なすべての手を再帰的に探索します。 各状態から、相手が負ける局面への手が存在するかどうかを確認します。 これは、有向グラフ上の公平なゲームの標準的なミニマックス定義です。 

ただし、この再帰では同じ部分問題が何度も繰り返されます。 最悪の場合、各 r × c セルが 3 つの遷移に分岐し、指数関数的な動作が発生する可能性があります。 メモ化を行っても、すべての移動が行または列のいずれかを増加させるため、構造は非循環的になります。そのため、各状態はグリッド内の「後の」セルにのみ依存します。 

この単調な構造が重要な観察です。 すべての移動はどちらかの座標を厳密に増加させるため、サイクルはありません。 つまり、ボトムアップで結果を計算できます。どのセルも、その右、下、または右斜め下のセルにのみ依存します。 グリッドを逆の順序で、右下から左上に処理すると、すべての遷移はすでに計算された状態につながります。 

各白いセルについて、少なくとも 1 つの負けのセルに移動できる場合、そのセルを勝ちとしてマークします。 すべての可能な動きが勝利の位置につながる場合、現在のセルは負けています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DFS | O(3^(r+c)) | O(r・c) 再帰 | 遅すぎる |
 | ボトムアップDP | O(r・c) | O(r・c) | 承認済み |

 ## アルゴリズムのチュートリアル

 各セルを勝ちまたは負けのゲーム状態としてモデル化します。 

1. 各セルに、そこからスタートする現在のプレーヤーが勝利を強制できるかどうかを格納する DP テーブルを作成します。 黒マスはその上に立つと無効なので常に負けです。 
2. 右下隅から開始して左上隅に向かって、逆の順序でグリッドを反復処理します。 この順序により、セルを評価するたびに、セルの移動先となるすべてのセルがすでに処理されていることが保証されます。 
3. 各白いセルについて、すべての有効な移動（下、右、斜め右下）を試します。 これらの動きのいずれかが負けるセルにつながる場合、現在のセルを勝ちとしてマークします。 その理由は、相手を不利な立場に追い込むことができるということです。 
4. どの手が負け状態にならない場合、すべての手が相手に勝ちの位置を与えるため、現在のセルを負けとしてマークします。 
5. DP テーブルに記入した後、答えは開始セルの値 (0,0) によって決まります。 勝っている場合は、アリスが勝利を強制できますが、そうでない場合はボブが勝ちます。 

### なぜ効果があるのか

DP テーブルは、DAG 上の公平なゲームの基本的な特性をエンコードします。つまり、ポジションが負けているポジションに対して少なくとも 1 つの出エッジを持っている場合、そのポジションは正確に勝っていることになります。 移動グラフは非巡回であるため、すべての状態は処理順序で厳密に後の状態にのみ依存するため、各値は 1 回だけ計算され、無効になることはありません。 これにより、ローカルな決定とグローバルなゲーム結果との間の一貫性が確保されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    r, c = map(int, input().split())
    grid = [input().strip() for _ in range(r)]
    
    dp = [[False] * c for _ in range(r)]
    
    for i in range(r - 1, -1, -1):
        for j in range(c - 1, -1, -1):
            if grid[i][j] == 'B':
                dp[i][j] = False
                continue
            
            win = False
            
            if i + 1 < r and grid[i + 1][j] == 'B':
                win = win or not dp[i + 1][j]
            elif i + 1 < r:
                win = win or (not dp[i + 1][j])
            
            if j + 1 < c:
                win = win or (not dp[i][j + 1])
            
            if i + 1 < r and j + 1 < c:
                win = win or (not dp[i + 1][j + 1])
            
            dp[i][j] = win
    
    print("Alice" if dp[0][0] else "Bob")

if __name__ == "__main__":
    solve()
```実装の中核は、グリッドの逆走査です。 各 dp セルは 1 回だけ計算され、遷移はグリッド内でのみ前方を参照します。 ブール ロジックはミニマックス ルールを直接捉えています。つまり、何らかの動きが負け状態につながる場合、ポジションは勝ちになります。 

唯一の微妙な点は、黒セルの処理です。 これらは強制的に負ける状態であり、決して有効な移動ターゲットとして扱ってはなりません。 これは、即座に False を割り当て、遷移をスキップすることで強制されます。

 ## 特殊なケース

 単一の白いセルで構成される最小限のグリッドでは、ゲームは直ちに終了します。 DP は、送信する手がないため負けとしてマークし、ボブが勝者と宣言されます。 

開始セルのすべての隣接セルがブロックされているグリッドも、アリスにとって即座に損失をもたらします。 DP は (0,0) からの遷移を検出しないため、False のままとなり、最終状態を正しくモデル化します。 

完全に開いたグリッドは異なる動作をします。各セルは最終的に右下の境界近くの負け位置に少なくとも 1 回移動し、スタートが勝ちになるまで勝ち状態を逆方向に伝播します。
