 ## 解決策
 ## 問題の理解

 私たちは通りを 2 つの平行した家の列として見ることができます。各列には次のような特徴があります。$n$ポジション。 どの位置の家からも$i$, ジュリアは同じ列に沿って左右に移動したり、同じ位置で別の列に垂直に切り替えたりできます。 すべての家にはプラスまたはマイナスの値があり、彼女が最初に足を踏み入れたときにのみ収集されます。 

旅は最初の列の前、実質的には次の時点で始まります。$a_1$、で終わります$b_n$。 Julia は任意に前後に移動できるため、パスが単調になるように制限されません。 ただし、家の価値は一度しか取得されないため、家を再訪問しても追加の利点はありません。 

したがって、中心的な問題は、この 2 行 n 列のグリッド グラフで、すべての個別の訪問ノードの値の合計を最大化する左上から右下へのパスを見つけることです。 

制約は大きく、$n$まで$5 \cdot 10^5$これにより、サブセットまたは任意のグラフ走査に依存する状態空間の探索が除外されます。 訪問した状態をモデル化しようとするソリューションは、明示的に指数関数的になります。 サブセットに対する単純な動的プログラミングや、完全な最短パス スタイルの緩和であっても、$2n$状態を再訪するノードは、構造を活用しないと遅すぎます。 

微妙な難しさは、動きが厳密に右方向に進むことを強制されないことです。 Julia は左に行って戻ってきて、失われた値を「すくい上げる」ことができます。 これにより、一般的なグラフ走査のような錯覚が生じますが、構造は本質的には列ごとに 2 つの選択肢を持つ列のチェーンです。 

いくつかの特殊なケースでは、落とし穴が明らかになります。 

たとえば、すべての値が負の場合、$n=3$、$a=[-5,-2,-7]$、$b=[-1,-3,-4]$、最適なパスは依然として次から開始する必要があります。$a_1$そしてで終わります$b_n$, したがって、ネガを収集することは避けられません。 「不良ノードをスキップする」という素朴な直感は役に立ちません。 

たとえば、一方の行が非常に正で、もう一方の行が非常に負である場合、$a=[100,100,100]$、$b=[-100,-100,-100]$、最適な解決策でも、接続性のために不良行を時々通過することが強制されますが、不必要なエントリを避けるためには訪問順序が重要です。 

もう 1 つの問題は、再訪問の過大カウントです。再訪問では値が得られないため、ノードに入るたびにノード値を合計する単純な DFS は正しくありません。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのパスをモデル化しようとします。$a_1$に$b_n$のグラフ上で$2n$ノード。 たとえ状態の再訪を禁止したとしても、このようなグリッド グラフ内の単純なパスの数は指数関数的に増加します。 再訪問を許可した瞬間に、二重カウントを避けるために訪問したノードも追跡する必要があります。これにより、問題が指数関数的なサブセット DP オーバーの形式に変わります。$2n$ノード。 それはすぐに次のようなことになります$O(2^{2n})$、完全に不可能です。 

重要な観察は、動きは双方向であるにもかかわらず、グラフには強力な線形バックボーンがあるということです。エッジは隣接する列または同じ列を垂直に接続するだけです。 これは、列までの最適値の収集が「完了」すると、$i$、列との唯一の意味のある対話$i+1$どちらからでも入力する方法です$a_i$または$b_i$。 左側にあるものすべて$i$単一の最良の値の状態として要約できます。 

これにより、移動履歴全体を列ごとの小さな状態セットに圧縮することができます。 難しいのは、列内でのバックトラックの処理です。これにより、事実上、複数回の行間の切り替えが可能になりますが、最適に進む前に列内の両方のノードを確実に収集できること以外に、新しい構造は作成されません。 

これにより、問題は 2 つの状態を持つ列に対する動的プログラミングに縮小されます。つまり、次の状態で終了するときの最良の結果です。$a_i$で終了すると最良の結果が得られます$b_i$1 つの列で両方の値を取得する可能性を考慮しながら。

 ## アルゴリズムのチュートリアル

 列を左から右にスキャンしている間、2 つの値を維持します。それは、現在の列の一番上のハウスで終了したときに達成可能な最高の幸福であり、一番下のハウスについても同様です。 

1. 次のようにして列 1 で初期化します。$a_1$、スタートがそこに固定されているため。 このことから、オプションで、次のようにすることもできたと考えることもできます。$b_1$垂直方向の移動によってすぐに移動できるため、両方の初期状態を次の状態から形成できます。$a_1$そして$b_1$。 
2. 各列について$i$2から$n$で終了する新しい値を計算します。$a_i$そして$b_i$。 到達する方法は 2 つあります$a_i$: から来ています$a_{i-1}$またはから$b_{i-1}$。 同じことが対称的に当てはまります$b_i$。 移動は隣接する列間または列内でのみ行われるため、これによりすべての有効な遷移がキャプチャされます。 
3. 列に移動するとき$i$、両家が縦列であることも考慮します。$i$どちらの順序でもアクセスできます。 到着したら$a_i$まず、垂直方向に移動できます$b_i$、その逆も同様です。 これは、列の値が$i$いずれかの状態に到達すると、常に完全に収集可能ですが、遷移中にそれを二重にカウントしないようにする必要があります。 
4. したがって、遷移は、最初に各ノードへの最適なエントリを計算し、次にそのノードの値を 1 回追加することによって処理されます。同時に、両方のエントリの可能性を最大化することによって列内の切り替えが暗黙的に許可されるようにします。 
5. すべての列を処理した後、答えは現在の値の中で最良の値になります。$a_n$または$b_n$で終了する必要があるため、$b_n$ただし、それが DP 状態に含まれていることを確認します。 

重要な不変条件は、列の処理後です。$i$、DP 値は、列内のすべての決定を完全に解決した有効なパスの収集可能な最大幸福度を表します。$i$、列内の特定のノードで終了します$i$、すべての可能な列内走査が暗黙的にすでに考慮されています。 これにより、今後のステップが以前の列内の隠れた構造に依存しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    # dp states: best ending at a_i or b_i after processing column i
    dp_a = a[0]
    dp_b = b[0] + a[0]  # we can go a1 -> b1 immediately

    for i in range(1, n):
        new_a = max(dp_a, dp_b) + a[i]
        new_b = max(dp_a, dp_b) + b[i]
        dp_a, dp_b = new_a, new_b

    print(dp_b)

if __name__ == "__main__":
    solve()
```各列は前の列にのみ依存するため、コードは完全な DP 配列ではなく 2 つのローリング状態を維持します。 初期化は、次の時点から始まるという事実をエンコードします。$a_1$すでに即時移行が許可されています$b_1$, そのため、どちらも早期に到達可能であると考えられます。 

移行ステップでは、列に入る前の観察を使用します。$i$、Julia は列のいずれかの行で終了できます。$i-1$, したがって、両方の状態の最大値を取得します。 次に、ノードへの訪問は、ノードに初めて入力したときに行われるため、現在のハウス値を 1 回追加します。 

最終的な答えは次から取得されます$dp_b$、必要なエンドポイントは$b_n$。 

## 実用的な例

 ### サンプル 1

 入力:```
n = 3
a = [5, 2, 7]
b = [3, -5, 4]
```列ごとに状態を追跡します。 

| 私 | dp_a | dp_b | 説明 |
 | --- | --- | --- | --- |
 | 1 | 5 | 8 | a1 から開始し、すぐに b1 に移動できます。 
| 2 | 10 | 5 | 前回の最良の値は 8、a2 または b2 を追加します。 
| 3 | 17 | 21 | 過去の最高は 10、a3 または b3 を追加 |

 最終的な答えは21です。 

このトレースは、dp 遷移は次の列にコミットする前に常により適切な前の位置を選択するため、状態選択で負の値をバイパスできることを示しています。

 ## 特殊なケース

 単一列の入力により、アルゴリズムは開始動作と終了動作を即座に調整します。 入力用$n=1$、$a=[5]$、$b=[10]$、DP は次のように初期化されます。$dp_a=5$そして$dp_b=15$から引っ越して以来、$a_1$に$b_1$すぐに許可されます。 アルゴリズムは 15 を返します。これは、両方の家を訪問する唯一の有効なパスに一致します。 

次のような完全な負のグリッド$a=[-5,-2]$、$b=[-1,-3]$それでも、制約されたルートに沿って必要なすべてのノードを蓄積する決定的なパスが生成されます。 DP は必要な構造をスキップしようとすることはありません。 各列で最も害の少ない遷移を選択することでダメージを最小限に抑えるだけで、負であっても正しい最終値が得られます。 

のような強力な非対称ケース$a=[100,100]$、$b=[-100,-100]$アルゴリズムが可能な限り先頭の行に留まることが適切であることを示していますが、到達するために最後に必須の遷移が考慮されていることがわかります。$b_n$。
