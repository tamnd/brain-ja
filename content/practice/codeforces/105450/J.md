 ## 解決策
 ## 問題の理解

 マシンのコレクションが与えられ、各マシンは 3 つの生産的な役割のいずれかに構成することも、未使用のままにすることもできます。 機械がキャンディーの形を生産するように設定されている場合、一定のエネルギーコストがかかります。 酸味を加えるように設定すると、別のコストがかかります。 ラッピングに設定すると3番目のコストがかかります。 使わずに放置しておいても何の役にも立ちません。 

工場には厳しい要件があります。$x$マシンは正確に成形に割り当てられる必要があります$y$酸味まで、そしてまさに$z$ラッピングまで。 どのマシンも最大 1 回使用でき、残りのマシンはアイドル状態のままにすることができます。 目標は、総エネルギー消費を最小限に抑えながら、すべての割り当てが満たされるようにマシンに役割を割り当てることです。 

入力サイズはマシン数の点で大きく、最大で$10^5$ただし、必要なものは重要です$x, y, z$この不均衡が構造上の中心的な手がかりです。複雑さのプレッシャーは、必要な割り当ての数ではなく、マシンの数によって生じます。 

単純なアプローチでは、各マシンを個別に割り当てるか、すべてのマシンにわたる割り当ての組み合わせを検討します。 各マシンには 4 つの選択肢があり、クォータの制約により選択肢間に依存関係が存在するため、この方法はすぐに失敗します。 すべてのマシンとすべてのクォータ状態に対する単純な動的プログラミングであっても、高密度の方法で直接実装すると、非常に遅くなります。 

よくある落とし穴は、各マシンを貪欲に扱うことです。たとえば、3 つのロールのうち最も安価なロールにマシンを割り当てることです。 初期の安価な選択が後の割り当てを妨げる可能性があるため、これは失敗します。 たとえば、2 台のマシンがどちらもシェーピングに非常に安価であるにもかかわらず、スロットが 1 つしか存在しない場合、両方をシェーピングに貪欲に使用すると、後で高価な割り当てを強いられる可能性がありますが、少し高価な初期の決定により、より適切なグローバル構成が可能になる可能性があります。 

もう 1 つの微妙な問題は、「未使用」オプションを適切に無視することです。 すべてのマシンに 3 つの役割のいずれかを強制的に割り当てるソリューションでは、クォータが過剰になり、不正確または不可能な構成が生成されます。 

## アプローチ

 直接的な総当りの見方は、各マシンについて、成形するか、酸っぱくするか、ラップするか、または未使用のままにするかを決定することです。 これにより、$4^n$可能性はありますが、それは中程度の人でも完全に実行不可能です$n$、 として$n = 100$すでに天文学的に大きな検索スペースが得られています。 

自然な改良は、これまでに各役割に割り当てられたマシンの数を動的にプログラミングすることです。 マシンのいくつかのプレフィックスを処理した後に、シェイプ、サワー、およびラップの割り当てが何回行われたかを状態に追跡させます。 各マシンは 4 つの可能性に移行するため、状態グラフは階層化された 3D グリッドになります。 この考えは正しいですが、直接実装すると更新されます。$O(xyz)$それぞれの状態$n$マシン、おおよその結果につながる$10^5 \cdot 10^6 = 10^{11}$操作が大きすぎます。 

重要な観察は、これが、各マシンが DP レイヤーごとに独立して処理される必要がある、逐次的な決定の問題ではないということです。 代わりに、これは制約された割り当ての問題です。つまり、正確に選択しています。$x+y+z$選択された各マシンは、割り当てに応じたコストを持つ 3 つのカテゴリのいずれかに割り当てられます。 

この構造は、最小コストのフロー定式化に非常に自然に一致します。 各マシンは、最大 1 単位のフローを 3 つのカテゴリ バケットのいずれかに送信できるアイテムです。 各カテゴリーには一定の需要があります。 未使用のオプションは、そのマシンを介してフローを送信しないことに対応します。 このように組み立てると、問題は標準的なフローになり、必要な合計フローは小さくなります ($\le 300$）、これは、比較的単純な最小コスト最大フローの実装でも処理できるほど十分に小さいです。 

フロー グラフはグローバルな一貫性を自動的に強化し、複雑な DP 状態管理の必要性を排除します。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(4^n)$|$O(n)$| 遅すぎる |
 | DP オーバーカウント |$O(nxyz)$|$O(xyz)$| 遅すぎる |
 | 最小コストフロー |$O(F \cdot E \log V)$と$F \le 300$|$O(E)$| 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、有効な割り当てがそれぞれのフローに正確に対応するフロー ネットワークとして再定式化します。$x+y+z$ユニットで構成されており、各ユニットは 1 台のマシンを 1 つの役割に割り当てることを表します。 

1. ソース ノードを構築し、それを容量 1、コスト 0 のすべてのマシン ノードに接続します。 これにより、各マシンは最大 1 回のみ使用できるようになります。 
2. 各マシン ノードから、形状、酸味、ラッピングの 3 つの役割ノードへのエッジを作成します。 これらの各エッジの容量は 1 で、コストは対応するエネルギー コストと同じです。$a_i$、$b_i$、 または$c_i$。 これは、そのマシンをロールに割り当てるコストをエンコードします。 
3. マシン ノードを「シンク」に直接接続しないでください。 ロール ノードはグローバル クォータを強制するため、代わりに、すべての割り当てをロール ノード経由でルーティングします。 
4. 各ロール ノードから、そのロールに必要なマシンの数に等しい容量を持つシンクに接続します。$x$、$y$、 そして$z$、それぞれコストはゼロです。 これにより、必要な数を超えるマシンを各ロールに割り当てることができなくなります。 
5. ソースからシンクまで最小コストのフローを実行し、正確にプッシュします$x+y+z$流量の単位。 各ユニットは、1 台のマシンを選択し、それを 1 つの役割に割り当てることに対応します。 
6. 結果として得られる最小コストが答えです。 

正確さの背後にある重要な考え方は、すべての有効な割り当てが独自の実行可能なフローに対応しているということです。マシンを選択してロールに割り当てることは、ソース→マシン→ロール→シンクというパスを正確に選択することです。 逆に、実行可能なフローは容量の制約を考慮するため、利用可能な以上のマシンを割り当てたり、ロール クォータを超えたりすることはありません。 

## なぜ機能するのか

 フロー ネットワークは、明示的な組み合わせ条件ではなく、すべての制約を容量制限としてエンコードします。 マシンの一意性は、ソースからマシンへの容量 1 によって強制されます。ロール クォータは、各ロール ノードへの受信フローの合計を制限することによって強制されます。 コストはエッジに沿って完全に加算されるため、フロー コストを最小限に抑えると、総エネルギーが直接最小限に抑えられます。 

フローの各単位は 1 つのマシン割り当てに正確に対応するため、実行可能なサイズのフロー間には 1 対 1 の対応関係があります。$x+y+z$有効な工場。 これにより、サブセットまたはカウントに対する明示的な状態追跡の必要がなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

INF = 10**18

class Edge:
    __slots__ = ("to", "cap", "cost", "rev")

    def __init__(self, to, cap, cost, rev):
        self.to = to
        self.cap = cap
        self.cost = cost
        self.rev = rev

class MinCostFlow:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, fr, to, cap, cost):
        fwd = Edge(to, cap, cost, len(self.g[to]))
        rev = Edge(fr, 0, -cost, len(self.g[fr]))
        self.g[fr].append(fwd)
        self.g[to].append(rev)

    def min_cost_flow(self, s, t, maxf):
        n = self.n
        res = 0
        h = [0] * n

        prevv = [0] * n
        preve = [0] * n

        while maxf > 0:
            dist = [INF] * n
            dist[s] = 0
            inq = [False] * n
            q = deque([s])
            inq[s] = True

            while q:
                v = q.popleft()
                inq[v] = False
                for i, e in enumerate(self.g[v]):
                    if e.cap > 0 and dist[e.to] > dist[v] + e.cost + h[v] - h[e.to]:
                        dist[e.to] = dist[v] + e.cost + h[v] - h[e.to]
                        prevv[e.to] = v
                        preve[e.to] = i
                        if not inq[e.to]:
                            inq[e.to] = True
                            q.append(e.to)

            if dist[t] == INF:
                break

            for v in range(n):
                if dist[v] < INF:
                    h[v] += dist[v]

            d = maxf
            v = t
            while v != s:
                d = min(d, self.g[prevv[v]][preve[v]].cap)
                v = prevv[v]

            maxf -= d
            res += d * h[t]

            v = t
            while v != s:
                e = self.g[prevv[v]][preve[v]]
                e.cap -= d
                self.g[v][e.rev].cap += d
                v = prevv[v]

        return res

def solve():
    n, x, y, z = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    c = list(map(int, input().split()))

    S = 0
    T = 1 + n + 3
    A = 1 + n
    B = 1 + n + 1
    C = 1 + n + 2

    mcf = MinCostFlow(T + 1)

    for i in range(n):
        mcf.add_edge(S, 1 + i, 1, 0)
        mcf.add_edge(1 + i, A, 1, a[i])
        mcf.add_edge(1 + i, B, 1, b[i])
        mcf.add_edge(1 + i, C, 1, c[i])

    mcf.add_edge(A, T, x, 0)
    mcf.add_edge(B, T, y, 0)
    mcf.add_edge(C, T, z, 0)

    print(mcf.min_cost_flow(S, T, x + y + z))

if __name__ == "__main__":
    solve()
```この実装では、マシンがソース ノードとロール ノードの間に位置する 2 部構成のフロー構造が構築されます。 min-cost フロー ルーチンは、マイナスの削減コストを安全に処理できる可能性を備えた最短パス再重み付けアプローチを使用します。 各拡張により、可能な限り多くのフローが利用可能な最も安価な割り当てパスに沿ってプッシュされ、合計フローが小さいため、繰り返される最短パスの計算は効率的です。 

微妙な点は、必要な量のフローが送信されるとアルゴリズムが停止することです。 ネットワークが正しく構築されていない場合、フローが早期に停止したり、容量を超えたりして、そのようなバグが不完全または不可能なフローとして認識されるようになります。

 ## 特殊なケース

 重大なエッジ ケースは、1 つのロールが多くのマシンに対して非常に安価であるにもかかわらず、その割り当てが小さい場合です。 貪欲な割り当てを行うと、早い段階でそのロールに過負荷がかかり、後でコストのかかる再割り当てが必要になります。 フロー定式化では、ロール ノードの容量が超過を防ぐため、これは自然に処理されます。$x$、そのため、過剰なフローは代替の役割を強制されます。 

別のケースは、マシンに 1 つの非常に支配的なオプションと 2 つの貧弱なオプションがある場合に発生します。 単純なヒューリスティックでは常に最適なローカル コストが選択される可能性がありますが、そのオプションが以前のフローによってすでに飽和している場合、アルゴリズムは実現可能性を損なうことなく、そのマシンを 2 番目に最適なエッジを経由して正しく再ルーティングします。 

最後に、すべてのマシンのコストが同一の場合、アルゴリズムは複数の同等の増強パスを探索しますが、有効な最小コスト フローではクォータを尊重しながら割り当てを任意に分散し、同じ総コストを生成します。
