 ## 解決策
 ## 問題の理解

 私たちには一連のキャンディーが与えられ、それぞれのキャンディーを食べることがどれだけ楽しいかを表す数値が示されています。 これらの値はプラスにもマイナスにもなり得るため、キャンディーを摂取することは全体的な楽しみを助けることもあれば、損なうこともあります。 

これらのキャンディーの中には、Mizyu のお気に入りのタイプとしてマークされているものもあります。 鈴鹿は配列の任意の連続セグメントを選択できますが、1 つの制限があります。選択したセグメントには少なくとも 1 つのお気に入りのキャンディーが含まれていなければなりません。 このようなすべての有効なセグメントの中で、可能な最大の値の合計が必要です。 

したがって、このタスクは制約付き最大部分配列問題です。任意の部分配列を許可する代わりに、マーカー配列が 1 に等しいインデックスを少なくとも 1 つ含むもののみを考慮し、それらの最大合計を求めます。 

この制約により、キャンディーは最大 200,000 個まで許可されるため、すべての部分配列を直接試行するソリューションは遅すぎます。 合計を繰り返し再計算する 2 次または 3 次のアプローチには、およそ次のような処理が必要になります。$O(n^2)$または、1 秒の制限をはるかに超えるさらに悪い操作。 線形または線形に近いものが必要です。 

素朴な推論を打ち破ることが多い、微妙な失敗例が 2 つあります。 

1 つのお気に入りのキャンディーを除いて、すべてのキャンディーがマイナスの場合、問題が 1 つ発生します。 単純な Kadane のアルゴリズムは全体として最適なサブ配列を正しく選択しますが、注意深い境界処理を行わずに単に「お気に入りを含む最適なサブ配列を追跡する」という変更を行うと、誤ってさらに悪い負の領域に拡張されたり、最適な単一のお気に入りサブ配列が除外されたりする可能性があります。 

別の問題は、最適なサブ配列に複数のお気に入りのキャンディーが含まれており、最適な選択がお気に入りの中心ではなく、その全体にわたる場合に発生します。 適切に貢献を分割せずに、お気に入りのポジションを 1 つ固定し、独立してカダネを左右に実行する単純な試みは、最適なクロスを見逃す可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。考えられるすべての部分配列を列挙し、お気に入りのキャンディーが少なくとも 1 つ含まれているかどうかを確認し、その合計を計算し、最大値を追跡します。 これは問題の定義を直接評価するため、正しいです。 

ただし、約$n(n+1)/2$サブアレイ。 のために$n = 200000$、これについてです$2 \times 10^{10}$たとえ一定時間で各サブ配列をチェックすることが可能だったとしても、それでも限界を桁違いに超えることになります。 素朴に合計を計算すると事態はさらに悪化するでしょう。 

重要な洞察は、制約を再構成することです。 「少なくとも 1 つのお気に入りを含める必要がある」をサブ配列に対するグローバルな制限として扱う代わりに、各お気に入りの位置を中心にソリューションを固定することができます。 有効なサブ配列にはお気に入りのインデックスが含まれている必要があるため、最適な答えはサブ配列内のお気に入りの位置のすべての選択肢の最大値になります。 

お気に入りのインデックスを修正する$i$。 以下を含む最良の部分配列が必要です。$i$。 この部分配列は 3 つの部分に分割できます: で終わる左の拡張子。$i$、の値$i$、およびで始まる右拡張子$i$。 最適な選択は、次で終わる最適なサフィックスを個別に最大化することです。$i$で始まる最適なプレフィックス$i$ただし、継続すると合計が減少する場合は、早期に停止できるという意味で、両方とも空ではない必要があります。 

これにより、問題は、インデックスごとに、そのインデックスで終了する最適なサブ配列 (古典的なカダン順方向パス) と、そのインデックスで始まる最適なサブ配列 (逆方向カダン パス) を計算することになります。 次に、お気に入りのインデックスごとに$i$、左右の貢献を組み合わせます。 

これが機能するのは、最適な部分構造が保持されるためです。$i$で終わる最適なセグメントに分解されます。$i$左から、最適なセグメントは次のとおりです。$i$両側間の干渉なしに右から。

 ## アルゴリズムのチュートリアル

 2 つの配列を構築します。 1 つは各位置で終わる最大サブ配列合計を保存し、もう 1 つは各位置で始まる最大サブ配列合計を保存します。 

1. 各インデックスに対して順方向動的計画法配列を計算します。$i$、前の部分配列を拡張するか、新しく開始するかを決定します。$i$。 これにより、次で終わる最適な合計が得られます。$i$。 この決定は、以前の累積合計が有益であるか有害であるかを反映します。 
2. 同じロジックを逆の順序で使用して、各インデックスから始まるサブ配列の後方バージョンを計算します。 これにより、最適な右拡張子が得られます。 
3. ポジションごとに$i$お気に入りとしてマークされている場合は、次を使用する最適な有効な部分配列を計算します。$i$「ブリッジポイント」として。 これは、次で終わる最良の貢献を組み合わせることによって行われます。$i$左から、から始まる$i$右から引くと$a[i]$二重カウントを避けるために 1 回です。 
4. すべてのお気に入りの位置にわたる最大値を追跡します。 

減算が必要な理由は、左右の DP の両方にインデックスの値が含まれるためです。$i$。 この重複を修正しないと、要素は 2 回カウントされます。 

### なぜ効果があるのか

 有効なサブ配列には、少なくとも 1 つのお気に入りインデックスが含まれている必要があります。 お気に入りのインデックスを 1 つ修正する$i$。 以下を含む任意のサブ配列$i$で終わる左側の部分に一意に分割できます。$i$そして右側の部分は次から始まります$i$。 このような最良の分解は、一方の側での制限が他方の有効な選択肢に影響を与えないため、両側で独立しています。 DP 配列は、各辺について、境界に対する最適な選択がすでに保存されていることを保証します。 したがって、お気に入りのインデックスごとにそれらを組み合わせることで、すべての有効な部分配列を漏れなく探索し、最大値を取得することで最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    left = [0] * n
    right = [0] * n

    left[0] = a[0]
    for i in range(1, n):
        left[i] = max(a[i], left[i - 1] + a[i])

    right[n - 1] = a[n - 1]
    for i in range(n - 2, -1, -1):
        right[i] = max(a[i], right[i + 1] + a[i])

    ans = -10**18

    for i in range(n):
        if b[i] == 1:
            val = left[i] + right[i] - a[i]
            ans = max(ans, val)

    print(ans)

if __name__ == "__main__":
    solve()
```フォワードパスが構築される`left[i]`インデックスで正確に終了する必要がある最適なサブ配列として`i`。 これは標準的な Kadane の繰り返しで、前のセグメントを延長するか再開します。 

逆方向パスは、各インデックスから始まるサフィックスについてのこの考え方を反映しています。 

お気に入りのインデックスを評価するときは、両方の DP 値を組み合わせて減算します。`a[i]`両面に含まれているからです。 これにより、サブ配列が正確に 1 回カウントされることが保証されます。 

最終的な答えは、すべてのお気に入りのポジションの最大値です。

 ## 特殊なケース

 大きな負の値で囲まれた単一のお気に入り要素が配列に含まれている場合でも、前方および後方 DP 配列は、要素自体としてそのインデックスで終了および開始する最良のセグメントを正しく計算します。 両方の側が長さ 1 の最適な部分配列のみを提供するため、組み合わせの式はちょうどその値に減ります。 

すべての要素がお気に入りの場合、すべてのインデックスは有効なアンカーとなり、アルゴリズムは、お気に入りを中心とした考えられるすべての組み合わせをチェックすることになります。 すべてのサブ配列には定義により少なくとも 1 つのお気に入りが含まれるため、すべてのアンカーの最大値はグローバル最大サブ配列と一致します。
