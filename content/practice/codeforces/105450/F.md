 ## 解決策
 ## 問題の理解

 各ノードに 1 つの値を持つツリーが与えられ、そのコンテナー内にあるキャンディーの数を表します。 マジシャンはエッジを削除することができます。これにより、ツリーが接続されたコンポーネントに分割されます。 結果として得られる各コンポーネントはファンに与えられ、すべてのファンはノード値の合計が偶数であるコンポーネントを受け取る必要があります。 何も破棄できないため、削除後はすべてのノードが 1 つのコンポーネントになる必要があります。 

課題は、すべてのコンポーネントの合計に対するパリティ制約を尊重しながら、最終的に得られるコンポーネントの数を最大化することです。 そのような方法でツリーを分割することが不可能な場合、答えは -1 です。 

最大 200,000 ノードという制約は、どのソリューションも線形に近い必要があることを直ちに示唆しています。 ノードまたはエッジのペアに対する 2 次アプローチは非常に遅すぎます。$O(n \log n)$または$O(n)$複数の DFS パスを使用するものは許容されますが、カットごとの再計算やエッジ除去ごとのグローバルな再計算を伴うものは許容されません。 

微妙な点は、ノードの任意のパーティションを選択しているわけではないということです。 ツリーのエッジに沿ってのみ分割できるため、すべてのコンポーネントは暗黙的にルート化された意味でサブツリーになります。 この構造により、問題は 1 回の DFS 計算に還元されます。 

グローバルな同等性を考慮せずに貪欲に考えると、いくつかの特殊なケースが間違いやすくなります。 

すべてのノード値の合計が奇数になる場合 (たとえば、値を持つ 3 つのノードの行)$1, 1, 1$、エッジがどのように削除されたとしても、すべてのコンポーネントの合計は依然としてすべてのコンポーネントの合計合計となり、奇数になるため、少なくとも 1 つのコンポーネントが奇数である必要があります。 これにより、答えは -1 になります。 

もう 1 つの失敗例は、ルートの観点からの一貫性を確保せずに、貪欲な戦略がローカル サブツリーを参照するたびに切断しようとする場合に発生します。 鎖のような木の中で$1 - 2 - 3$価値観を持って$1, 2, 1$の場合、合計は 4 で偶数ですが、サブツリー全体の合計を計算する前にノード 2 で不注意に切断すると、間違った順序で計算された場合に無効なコンポーネントが誤って分離される可能性があります。 

主な問題は、エッジをカットできるかどうかが、ローカル ノード値だけでなく、その下のサブツリー全体のパリティに依存することです。 

## アプローチ

 ブルートフォースアプローチでは、エッジのすべてのサブセットを削除することが検討されます。 各サブセットはフォレストを定義し、各コンポーネントの合計を計算して、すべてが均等であるかどうかを検証できます。 と$n-1$エッジ、これにより得られます$2^{n-1}$可能性があり、各パーティションをチェックするだけでも直線的に時間がかかるため、$O(n 2^n)$、それは完全に不可能です。 

コンポーネントを段階的に構築しようとする少し洗練された総当たり攻撃でも、エッジを切断する決定はグローバル接続に影響を及ぼし、サブツリーの合計を繰り返し再計算しない限り独立して評価できないため、失敗します。 

重要な洞察は、任意のカットの観点から考えるのをやめ、代わりにツリーをルート化し、サブツリーの合計を分析することです。 ルートを修正すると、すべてのエッジの削除はサブツリーをその親から分離することに相当します。 唯一の疑問は、サブツリーはいつデタッチできるのかということです。 

サブツリーの総和が偶数であれば、それ自体で有効なコンポーネントを形成できます。 つまり、親に接続しているエッジを切断できるということです。 その合計が奇数の場合、そのコンポーネントはパリティ制約に違反するため、上向きに接続されたままにしておく必要があります。 

これにより、問題が単一の DFS に変換され、サブツリーの和を法 2 で計算し、切り離せるサブツリーの数がカウントされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | エッジサブセットに対するブルートフォース |$O(n 2^n)$|$O(n)$| 遅すぎる |
 | DFS サブツリー パリティ分析 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 たとえばノード 1 でツリーを任意にルートし、DFS を使用してサブツリーの合計を計算します。 

1. ルートから DFS を実行し、ノードごとにサブツリー内の値の合計を計算します。 計算は事後処理されるため、子は親より前に処理されます。 
2. DFS 中に、各ノードのサブツリーの合計が維持されます。 すべての子を処理した後、ノード独自の値を追加します。 
3. ノードのサブツリーの合計が偶数の場合、そのノードを「コンポーネントの切断可能なルート」としてマークします。これは、そのサブツリー全体を親エッジから切り離すことができることを意味します。 
4. サブツリーの合計が偶数であるノードの数を数えます。 これらのノードは、親からきれいに分離できるサブツリーに正確に対応します。 
5. ルートを個別に確認します。 すべてのノードの合計 (ルートのサブツリーの合計) が奇数の場合、有効なパーティションは存在しないため、-1 を返します。 
6. それ以外の場合、答えはサブツリーの合計が偶数であるノードの数になります。 

微妙な点は、偶数のサブツリー合計を持つノードの上のエッジをカットするたびに新しいコンポーネントが作成され、これらのカットは互いに素なサブツリーに対応するため独立しているということです。 

### なぜ効果があるのか

 DFS は、すべてのサブツリーの合計が一貫した階層で計算されることを強制します。 有効な最終コンポーネントは、境界がカット エッジであるサブツリーに対応する必要があります。 このようなカットは、サブツリーの合計が偶数の場合にのみ有効です。これにより、ツリーの残りの部分もグローバル パリティの一貫性が維持されることが保証されます。 カットはサブツリーの境界でのみ行われるため、選択された 2 つのカットが干渉することはなく、偶数のサブツリーごとに 1 つの追加コンポーネントが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n = int(input())
a = list(map(int, input().split()))

g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

even_subtree = 0
total = 0

def dfs(v, p):
    global even_subtree
    s = a[v]
    for to in g[v]:
        if to == p:
            continue
        s += dfs(to, v)
    if s % 2 == 0:
        even_subtree += 1
    return s

total = dfs(0, -1)

if total % 2 == 1:
    print(-1)
else:
    print(even_subtree)
```DFS はサブツリーの合計をポストオーダー方式で計算し、各ノードがパリティの決定を行う前にすべての子孫からの値を確実に集計します。 グローバルカウンター`even_subtree`取り外し可能なコンポーネントのルートとして機能できるノードの数を追跡します。 

サブツリーの合計が偶数であればルートも当然このカウントに含まれますが、カット エッジには対応しません。 これは、最終的なカウントではカットではなく 1 つのコンポーネントにのみ寄与するため、一貫性があります。 

チェーン形状のツリーのスタック オーバーフローを回避するために、再帰制限が増加しました。 

## 実用的な例

 ### サンプル 1

 入力ツリーには、複数のサブツリーの合計が偶数になるような値と構造を持つ 4 つのノードがあります。 

| ノード | サブツリーの合計 | 平？ |
 | --- | --- | --- |
 | 1 | 10 | はい |
 | 2 | 6 | はい |
 | 3 | 2 | はい |
 | 4 | 4 | はい |

 DFS は、分離可能なコンポーネントに寄与する 3 つの偶数サブツリー ノードをカウントし、合計 3 つのコンポーネントを生成します。 

このトレースは、すべての有効なカットがサブツリーの合計が偶数であるノードに正確に対応し、追加のブックキーピングが必要ないことを示しています。 

### サンプル 2

 ここでは、DFS 伝播後に偶数の合計になるサブツリーは 2 つだけです。 

| ノード | サブツリーの合計 | 平？ |
 | --- | --- | --- |
 | 1 | 10 | はい |
 | 2 | 6 | はい |
 | 3 | 1 | いいえ |
 | 4 | 3 | いいえ |

 アルゴリズムは、有効な取り外し可能なサブツリーの数に一致する 2 を返します。 

これにより、奇数のサブツリー合計を持つノードは、パリティ制約に違反せずに分離できないことが確認されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    sys.setrecursionlimit(10**7)

    n = int(input())
    a = list(map(int, input().split()))
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    even_subtree = 0

    def dfs(v, p):
        nonlocal even_subtree
        s = a[v]
        for to in g[v]:
            if to == p:
                continue
            s += dfs(to, v)
        if s % 2 == 0:
            even_subtree += 1
        return s

    total = dfs(0, -1)
    if total % 2 == 1:
        return "-1\n"
    return str(even_subtree) + "\n"

 ## 特殊なケース

 それぞれの値が 1 である 3 つのノードなど、完全に奇数の構成は、合計が偶数でなければならないというグローバル制約を示しています。 DFS は引き続きサブツリーの合計を正しく計算しますが、ルートでの最終パリティ チェックにより -1 出力がトリガーされます。 

単一ノード ツリーは、実装がエッジを必要とせずにルートを有効なコンポーネントとして正しく扱うかどうかをテストします。 値が偶数の場合、サブツリーの合計は偶数であり、答えは 1 になります。これは、ツリー全体が 1 つの有効なコンポーネントであるという事実と一致します。 

深いチェーンは再帰の安定性をテストし、サブツリーの蓄積がツリーの分岐構造から独立していることを確認します。 すべてのノードのサブツリーの合計は、リーフから上への線形伝播で計算され、中間カットの決定が正確さを妨げないようにします。
