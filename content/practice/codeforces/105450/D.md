 ## 解決策
 ## 問題の理解

 2D グリッド上の一連の点が与えられ、座標 (0, 0) の原点から開始します。 方向を選択して、原点を通る直線を歩きたいと考えています。 その線に沿って移動しながら、その線上にあるすべてのキャンディーを集めます。 目標は、原点を通過し、指定された点を最大数含む線を選択することです。 

それぞれのキャンディーは平面内の単なる固定点です。 有効な直線は原点を通過する直線のみであるため、すべての候補解は (0, 0) からキャンディ ポイント (x, y) への方向ベクトルによって完全に決定されます。 このような同じ線上にあるすべての点は、同じ傾き、より正確には、同じ縮小方向比を共有します。 

入力サイズは最大 100,000 ポイントに達するため、ポイントのすべてのペアを比較したり、勾配のすべてのペアをチェックしたりすることが直ちに除外されます。 O(n²) の動作を試みるソリューションでは、最悪の場合、最大 10¹⁰ の比較が実行されますが、これは 1 秒間に実行可能な限界をはるかに超えています。 これにより、O(n log n) または O(n) アプローチが推進されます。 

ここではいくつかの微妙なケースが重要です。 まず、(2, 3) と (-4, -6) のように、反対側の象限にある点は原点を通る同一線上に位置する可能性があります。 単純な傾き計算 y/x は、慎重に正規化しない限り、それらを異なる符号として扱います。 

次に、縦線を処理する必要があります。 (0, 5) のような点は有効な直線を定義しますが、個別に処理しない場合、傾きの表現にはゼロによる除算が含まれます。 

第三に、正規化が重要です。 方向ベクトルを正準形式に削減しないと、同じ行が (2, 4) や (1, 2) などの異なる整数表現で複数回カウントされる可能性があり、これらは同一であると見なされなければなりません。 

## アプローチ

 強引なアイデアは、すべての点のペアを考慮し、原点とそのペアの方向を通過する線を計算することです。 このような各ラインについて、外積を介して共線性をチェックすることで、そのライン上にある点の数を数えることができます。 これが機能するのは、2 つの点が方向を定義し、他のすべての点をその方向に対してテストできるためです。 

ただし、これにより O(n²) 個の候補方向が生成され、各方向についてすべての n 点をスキャンして、最悪の形式で O(n³) が得られるか、カウントを最適化した場合は最高でも O(n²) が得られる可能性があります。 n = 10⁵ では、O(n²) ですら不可能です。 

重要な観察は、原点を通るすべての有効な線は、原点からその線上の任意の点までの方向ベクトルによって一意に表現できるということです。 点のペアを列挙する代わりに、正規化された方向によって各点を分類するだけで済みます。 同じ縮小方向を共有する点は同じ線上にあるため、タスクは正規化された方向ベクトルの頻度をカウントすることに縮小されます。 

これにより、この問題は、縮小された整数のペアに関するハッシュ問題に変換されます。 各ポイントは正確に 1 つの方向に寄与し、最大カウントを見つけるために周波数マップを維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) から O(n³) | お(1) | 遅すぎる |
 | 方向ハッシュ | O(n log n) または O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各点 (x, y) について、原点からの方向の正規化された表現を計算します。 これにより、同じ線上のすべてのポイントが同じキーにマッピングされることが保証されます。 y/x などの生の比率は、整数のスケーリングや符号の変更では安定しないため、正規化が必要です。 
2. x が 0 の場合、その方向を特別な垂直クラスとして扱います。 x = 0 のすべての点は、y が正か負かに関係なく、原点を通る同じ直線に属します。 
3. x がゼロ以外の場合、x と y の最大公約数を計算し、両方をその値で割ります。 これにより、ペアが最小の整数表現に縮小されます。 このステップでは、(2, 4) や (1, 2) などの重複を削除します。 
4. 同等の方向が同一にマッピングされるように符号を正規化します。 標準ルールでは、x が正であるか、x がゼロの場合は y が正であることを確認します。 x が負の場合、両方の成分に -1 を掛けます。 
5. 正規化された各方向をハッシュ マップに保存し、その頻度を増加させます。 
6. すべてのポイントを処理した後、すべての方向クラス間で見られる最大周波数を返します。 

これが機能する理由: すべての点は原点を通る 1 本の直線に属し、そのようなすべての直線は 1 つの縮小方向ベクトルに正確に対応します。 正規化により、幾何学的ラインとハッシュ キー間の 1 対 1 マッピングが保証されるため、頻度をカウントすることは、各有効なライン上にある点の数をカウントすることと同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd
from collections import defaultdict

def solve():
    n = int(input())
    freq = defaultdict(int)

    for _ in range(n):
        x, y = map(int, input().split())

        if x == 0:
            # vertical line through origin
            key = (0, 1)
        else:
            g = gcd(x, y)
            x //= g
            y //= g

            if x < 0:
                x = -x
                y = -y

            key = (x, y)

        freq[key] += 1

    print(max(freq.values()))

if __name__ == "__main__":
    solve()
```このソリューションは、各点を個別に処理し、それを標準方向ベクトルに変換します。 gcd ステップにより、すべての比例ベクトルが同じ表現に折りたたまれます。 符号の正規化により、同じ線上の反対方向が別々のグループに分割されないことが保証されます。 

実装の微妙な詳細は、gcd 正規化を試行する前に x = 0 を処理することです。 このガードがないと、除算ロジックは有効なままですが、特に (0, y) と (0, -y) に関して、符号規則が矛盾します。 垂直線を明示的に修正すると、曖昧さが回避され、マッピングが簡素化されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各点には、座標サイズが対数である gcd 計算が必要です。

## テストケース```python
import sys, io
from collections import defaultdict
from math import gcd

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    def solve():
        n = int(input())
        freq = defaultdict(int)

        for _ in range(n):
            x, y = map(int, input().split())

            if x == 0:
                key = (0, 1)
            else:
                g = gcd(x, y)
                x //= g
                y //= g
                if x < 0:
                    x = -x
                    y = -y
                key = (x, y)

            freq[key] += 1

        return str(max(freq.values()))

    return solve()

""") == "3"

 ## 特殊なケース

 重要なエッジ ケースは、すべての点が同じ幾何学的線上にあるにもかかわらず、異なる整数スケールと符号で表示される場合です。 たとえば、(1, 2)、(2, 4)、(-3, -6) などです。 アルゴリズムでは、gcd で割って符号を固定することにより、すべて (1, 2) に変換されるため、まとめてカウントされます。 この正規化がなければ、これらは誤って異なる方向として扱われてしまいます。 

もう 1 つの特殊なケースは、垂直方向の配置です。 (0, 1)、(0, -1)、(0, 5) のような入力の場合、ゼロによる除算または一貫性のない表現により、傾きに基づくグループ化は失敗します。 単一の正規キー (0, 1) への明示的なマッピングにより、そのようなすべての点が確実にマージされ、頻度カウントはそれらが原点を通る同一線上にあることを正確に反映します。
