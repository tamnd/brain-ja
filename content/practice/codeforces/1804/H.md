 ## 解決策
 ## 問題の理解

 私たちに与えられた円形のダイヤルは、$k$ポジション。 各位置には最初から異なる文字でラベルが付けられます。$k$アルファベットの文字。 開始する前に、どの文字をどの位置に配置するかを変更することができます。 この順列を修正した後、位置 1 から開始して、指定された長さのパスワード文字列を入力します。$n$。 

タイピングは非常に機械的な方法で行われます。 1 秒ごとに、ダイヤルを時計回りに 1 ステップ、反時計回りに 1 ステップ回転するか、ボタンを押して現在の文字を追加します。 戦略のコストは、パスワードが完全に入力されるまでの合計秒数です。 

重要な自由は、文字と位置の間で全単射を選択できることです。 このマッピングを修正した後、連続する必須文字間の最適な移動を仮定すると、入力コストが決定的になります。 

文字列全体を入力するのに必要な最小時間と、その最小値に達する文字の順列の数の 2 つを見つけるように求められます。 

制約は決定的です。 アルファベットのサイズは最大 16 なので、順列は最大 16 個の要素にわたって存在します。 これは、サブセット上の階乗状態 DP またはビットマスク DP を直ちに示唆します。 パスワードの長さは次のとおりです$10^5$したがって、どのようなソリューションでも、への依存を回避する必要があります。$n$指数部分で代わりに繰り返し構造を圧縮します。 

微妙な点は、コストは文字列内の位置ではなく、パスワード内の連続する文字間の遷移のみに依存することです。 順列を修正すると、移動コストは隣接するペア間で加算され、位置 1 からの最初の移動が加算されます。 

単純な間違いは、すべての順列にわたる動きを直接シミュレートしようとすることです。 たとえ 1 つの順列の計算コストが$O(n)$、乗算$16!$不可能です。 もう 1 つの間違いは、出現の絶対位置を考慮する必要があると想定することです。 実際には、遷移周波数のみが問題となります。 

2 番目の微妙なエッジケースは開始位置です。 多くの誤った定式化では、初期位置 1 から最初に押された文字までのコストが忘れられ、特別な「開始文字」遷移のように動作します。 

## アプローチ

 文字の順列をサイクルに固定すると、文字列を入力することは固定サイクル グラフ上を歩くことになります。$k$ノード。 2 つの文字間のコストは、割り当てられた位置間の最短円周距離になります。 

したがって、順列の場合、$p$、総費用は次のとおりです。 

- 開始位置 1 から最初の文字までのコスト
 - 位置間の最短距離の文字列内のすべての隣接するペアの合計を加算します。 

これは、順序付けされた文字の各ペアがパスワード内で連続して出現する頻度を事前計算することを直ちに示唆します。 させて$cnt[a][b]$文字の回数になります$a$手紙が続きます$b$、同様に最初の文字を仮想開始からの遷移として処理します。 

これで、構造は次のようになります。各文字をサイクル上の位置に割り当て、各ペアは重みと位置間の距離の積に寄与します。 

これはサイクル メトリックに関する 2 次代入スタイルの問題であり、一般に NP 困難ですが、ここでは$k \le 16$、割り当てられた位置のサブセットに対してビットマスク DP を有効にします。 

ダイヤルの始点として位置 0 を固定して、円を圧縮します。 対称性を破ると残りの位置は線を形成しますが、円周距離を考慮する必要があります。 標準的なトリックは、サイクル上で事前に計算された距離を使用して、1 つの文字を位置 0 に固定し、残りの配置を線形順序で処理することです。 

位置間の距離を事前計算します$dist[i][j]$。 次に、DP は文字を 1 つずつポジションに割り当て、すでに配置されている文字に基づいて貢献度を蓄積します。 新しい文字を配置すると、以前に配置されたすべての文字に対するその文字の寄与がわかります。 

これにより、ペアごとの頻度から計算された遷移コストを使用して、文字のサブセットおよび位置のサブセットにわたる DP が得られます。 

重要な洞察は、順列を直接最適化するのではなく、順列を段階的に構築し、すでに割り当てられている文字を使用して増分コストを維持するということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 |$O(k! \cdot n)$|$O(1)$| 遅すぎる |
 | 割り当てに対するビットマスク DP |$O(k^2 \cdot 2^k)$|$O(2^k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、入力文字列を文字間の遷移カウントに圧縮します。 これにより、次への依存が軽減されます。$n$固定に$k^2$構造。 

開始位置も追加のソースとして扱います。 配列を定義します$start[a]$パスワードの最初の文字が次の場合は 1 です。$a$、それ以外の場合は 0。 

次に距離行列を計算します$dist[i][j]$、位置がサイズの円上に配置されます。$k$、距離は$\min(|i-j|, k-|i-j|)$。 

次に、文字と位置のサブセットに対して DP を実行します。 

1. DP 状態を定義します$dp[mask][last]$文字を割り当てた後の最小コストとして`mask`いくつかの選択された位置に移動します。`last`固定順序で最後に選択された位置です。 This ordering is used to break rotational symmetry by fixing position 0 as always used first.
 2. We initialize by trying every letter placed at position 0. For each letter$c$、設定しました$dp[1<<c][0]$スタートレターから$c$。 
3. 文字のマスクを反復処理します。 州ごとに新しい文字を配置してみます$c$新しい立場に$p$。 増分コストは、次の間の寄与を加算することによって計算されます。$c$および、事前に計算された周波数行列と距離行列を使用して、すでに配置されているすべての文字。 
4. また、各 DP 状態を達成する方法の数も追跡し、コストが等しい場合にカウントを合計します。 
5. 答えは、1 つの文字を位置 0 に固定することによってすべての回転が暗黙的に固定されることを考慮して、すべての文字が配置される完全なマスクの中で最良の値です。 

主な困難は、増分コストの計算です。 文字を入れる場合$c$、全額のコストは再計算されません。 代わりに以下を追加します。$$\sum_{a \in mask} cnt[a][c] \cdot dist[pos[a]][pos[c]]$$そして同様に$c \to a$方向転換が重要な場合。 

### なぜ効果があるのか

 どの DP 状態でも、割り当てられた文字のセットはサイクルの位置への部分的な埋め込みを定義します。 コスト関数は、文字間のペアごとの寄与と独立した開始寄与に完全に分解できます。 すべての遷移コストはその端点の位置のみに依存するため、新しい文字を追加すると、すでに配置されている文字との新しいペアごとの相互作用が導入されるだけで、以前に計算されたペアごとの距離は変更されません。 これにより、DP 遷移では再計算を行わずに正確な総コストが維持されます。 

1 つの文字を位置 0 に固定すると回転対称性がなくなり、有効な円形配置はすべて正確に表現されます。$k$しかし、一貫してアンカーしているため、コストの最小化と対称性の破れによるカウントの両方で過剰カウントを回避します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k, n = map(int, input().split())
    s = input().strip()

    # count transitions
    cnt = [[0] * k for _ in range(k)]
    start = [0] * k

    start[ord(s[0]) - 97] = 1
    for i in range(n - 1):
        a = ord(s[i]) - 97
        b = ord(s[i + 1]) - 97
        cnt[a][b] += 1

    # circular distance on k positions
    dist = [[0] * k for _ in range(k)]
    for i in range(k):
        for j in range(k):
            d = abs(i - j)
            dist[i][j] = min(d, k - d)

    INF = 10**18
    size = 1 << k

    # dp[mask][last_pos] but we compress last into position only
    dp = [[INF] * k for _ in range(size)]
    ways = [[0] * k for _ in range(size)]

    # choose first letter at position 0
    for c in range(k):
        mask = 1 << c
        cost = 0
        cost += start[c] * 0
        dp[mask][0] = min(dp[mask][0], cost)
        ways[mask][0] += 1

    for mask in range(size):
        for last_pos in range(k):
            if dp[mask][last_pos] == INF:
                continue

            used_letters = []
            for i in range(k):
                if mask >> i & 1:
                    used_letters.append(i)

            for c in range(k):
                if mask >> c & 1:
                    continue

                nmask = mask | (1 << c)

                # assign next position
                for np in range(k):
                    if np == last_pos:
                        continue

                    add = dp[mask][last_pos]

                    # cost from start transitions
                    if start[c]:
                        add += dist[0][np]

                    # transitions with previous letters
                    for a in used_letters:
                        add += cnt[a][c] * dist[0][np]

                    if add < dp[nmask][np]:
                        dp[nmask][np] = add
                        ways[nmask][np] = ways[mask][last_pos]
                    elif add == dp[nmask][np]:
                        ways[nmask][np] += ways[mask][last_pos]

    full = (1 << k) - 1
    best = INF
    ans = 0
    for p in range(k):
        if dp[full][p] < best:
            best = dp[full][p]
            ans = ways[full][p]
        elif dp[full][p] == best:
            ans += ways[full][p]

    print(best, ans)

if __name__ == "__main__":
    solve()
```実装は、パスワードを移行カウントに圧縮することから始まります。移行カウントは、コスト計算に関連する唯一の情報です。 距離行列は円形ジオメトリをエンコードするため、すべての移動コストが直接ルックアップになります。 

DP 構造は意図的に過完全になっています。回転の曖昧さを避けるために、文字のサブセットと位置アンカーの両方を追跡します。 遷移ループは、一度に 1 文字ずつ追加し、すでに選択されている文字との増分相互作用のみを再計算することによって状態を構築します。 ネストされたループオーバー`used_letters`許容できる理由は$k \le 16$、作る$2^k \cdot k^2$管理可能。 

初期化には注意が必要です。最初のプレスは固定された仮想原点からの遷移のように動作するため、開始位置の寄与は個別に処理する必要があります。 カウンティングは、リセットせずに等コスト遷移全体で累積する必要があります。

 ## 特殊なケース

 エッジ ケースの 1 つは、パスワードが同じ支配的な遷移パターンで始まり、終わり、複数の順列が同様に最適になる場合です。 DP は等コスト状態全体でカウントを蓄積する必要があります。 そうしないと過小評価されてしまいます。 

もう一つのケースは次のような場合です。$k = 2$。 循環距離は単純な 2 ノードのグラフに分解され、線形隣接のみを仮定した場合、円周距離の処理を誤ると誤ったコストが生成される可能性があります。 

最後の微妙なケースは、開始位置を忘れることです。 最初の文字が位置 1 から遠く離れているにもかかわらず、モデルがそのコストを省略している場合、DP は体系的にすべての解を過小評価し、誤った順列を選択する可能性があります。
