 ## 解決策
 ## 問題の理解

 文字列として表される多肢選択式の試験解答用紙が与えられます。 各位置は質問に対応し、各文字は A、B、C からの固定の選択肢、または疑問符が付いている不明のいずれかです。 すべての疑問符を 3 つのオプションのいずれかに置き換える必要があります。 

実際の正解キーには制約があります。連続する 2 つの質問が同じ正解を共有することはできません。 正しいキーはわかりませんが、この規則に従わなければならないことはわかっています。 記入された答えが未知の正しいキーと一致する位置ごとに 1 ポイントを獲得します。 

ねじれは、制約と一致する、考えられる最悪の有効な正解キーで保証される正解数を最大化する充填戦略が必要であるということです。 言い換えれば、私たちがすべての「?」を埋めることを約束した後、攻撃者はスコアを最小化するために「隣接する同等の文字がない」という条件を満たす有効な回答キーを選択します。 この最低達成可能なスコアを最大化する詰め物を選択したいと考えています。 

入力は複数のテスト ケースで構成され、それぞれは最大 100,000 の長さの文字列です。 テスト全体の合計サイズが十分に大きいため、部分文字列に対する 2 次または 3 次の推論は失敗します。 

素朴な間違いは、局所的に貪欲に「?」を埋めようと考えることです。 独立して十分です。 たとえば、「A???A」のようなパターンでは、グローバル制約を考慮せずにローカルで一貫性のある補完を選択すると、攻撃者がすべての推測構造を回避する有効な代替キーを配置する状況が発生する可能性があります。 

もう 1 つの微妙な失敗は、固定文字間の各セグメントが境界パリティ制約を考慮せずに個別に最適化できると想定していることから発生します。 たとえば、「A????B」では、エンドポイント間の強制的な交互パターンにより、どの位置を強制的に正しくできるかが制限されます。 

## アプローチ

 強引なアイデアは、各「?」を埋めるすべての方法を列挙することです。 A、B、または C を使用して、入力完了ごとに、すべての有効な代替応答キーに対する一致の最小数を計算します。 塗りつぶしの数だけでも「?」の数は指数関数的であり、塗りつぶしごとに有効なキーのセットも指数関数的になります。 3^N はすでに実現可能な限界を超えているため、N が 30 程度の場合でも、これはすぐに手に負えなくなります。 

重要な観察は、実際には立場ごとに独立して回答を選択しているわけではないということです。 「隣接する 2 つの正解が等しくない」という制約は、正解キーが自己ループのない 3 つのノードの完全なグラフ上を歩くように動作することを意味します。 敵対者の目標は常に、私たちの固定された選択肢との一致を可能な限り避ける有効な交互シーケンスを選択することです。 

これにより、問題は隣接する位置間の局所的な一貫性ゲームに変わります。 重要な構造の単純化は、連続する位置間の遷移のみが重要であり、グローバルに有効なキーはその最初の文字によって完全に決定されることです。 その後、残りの 2 つの文字の間で各位置が交互に配置されますが、正確な交代は前の文字の選択によって異なります。 

したがって、任意のキーについて考える代わりに、考えられる 3 つの開始文字と、各開始文字の選択が埋められた文字列とどの程度一致するかという観点から考えることができます。 開始文字ごとに、敵対者の最良の応答は固定されており、結果として生じる一致の数は簡単に計算できます。 

「？」の具材を選びます。 そのため、最悪の場合でも、最良の開始文字によって可能な限り多くの一致が得られます。

 ## アルゴリズムのチュートリアル

1. 各テスト ケースについて、有効な回答キーは最初の文字を選択し、ステップごとに他の 2 つの選択肢を交互に選択することによって決定されるという事実を考慮してください。 これにより、有効なキーのスペースが、テスト ケースごとにちょうど 3 つの可能性まで減ります。 
2. 考えられる 3 つの開始文字 A、B、および C のそれぞれについて、その後に続く強制的な交互シーケンスをシミュレートします。 位置 i で期待される文字は、i の開始文字とパリティによって完全に決定されます。 
3. 固定開始文字をシミュレートしながら、入力文字列内の既知の固定文字と一致する位置の数を数えます。 入力に「?」がある場合、攻撃者がキーを選択する前に入力を制御するため、入力を柔軟なものとして扱い、この位置合わせを維持するために最適に入力できると想定します。 
4. 各位置 i について、s[i] が固定文字の場合は変更しません。 「?」の場合、概念的には、その開始文字の保証された一致が最大化されるため、最適な開始文字の現在のシミュレートされたキーに一致する文字に設定します。 
5. 各開始文字の達成可能な最高のスコアを計算した後、3 つの値の最大値を取得します。 これは、最悪の場合のキー選択における最適な充填戦略を表しています。 

微妙な部分は、フィリングと敵対者の選択の間の相互作用です。 敵対者のキーは制約されていますが、隣接関係の有効性を超えて入力された選択肢とは独立しているため、各開始シナリオを個別に最適化するだけで十分です。 

### なぜ効果があるのか

 有効な応答キーは最初の文字によって一意に決定され、その後は隣接制約によって決定的な変更が強制されます。 したがって、敵の戦略空間は 3 つの構造化されたシーケンスに崩壊します。 私たちの充填は、これらのシーケンスの最良のものとの一致を最大化する文字列を選択することとして解釈できます。 配列が固定されると各位置が独立して寄与するため、問題は 3 つの決定論的なアラインメントを評価し、最良の結果を取得することに分解されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def next_char(c):
    if c == 'A': return 'B', 'C'
    if c == 'B': return 'A', 'C'
    return 'A', 'B'

def simulate(start, s):
    n = len(s)
    cur = start
    best = 0

    for i in range(n):
        if s[i] == '?':
            best += 1
        else:
            if s[i] == cur:
                best += 1
        # move to next char in a valid alternating way
        if i + 1 < n:
            a, b = next_char(cur)
            cur = a
    return best

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    ans = 0
    for start in "ABC":
        ans = max(ans, simulate(start, s))

    print(ans)
```このコードは、考えられる 3 つの開始文字をそれぞれ評価し、その選択によって引き起こされる固有の交互シーケンスをシミュレートします。 機能`next_char`任意の文字から次の有効な文字が 2 つだけ存在するというルールをエンコードします。 シミュレーション中、固定キャラクターは強制シーケンスと一致する場合にのみ寄与しますが、未知の位置は選択したシナリオに一致するように常に割り当てることができるため、自由に寄与します。 

よくある実装の落とし穴は、任意のシーケンスを検証しているのではなく、固定開始によって引き起こされたシーケンスのみを検証していることを忘れていることです。 そのため、最初の文字以降の遷移は決定的になります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        def nxt(c):
            if c == 'A': return 'B', 'C'
            if c == 'B': return 'A', 'C'
            return 'A', 'B'

        def sim(start):
            cur = start
            res = 0
            for i in range(len(s)):
                if s[i] == '?' or s[i] == cur:
                    res += 1
                if i + 1 < len(s):
                    a, b = nxt(cur)
                    cur = a
            return res

        ans = 0
        for st in "ABC":
            ans = max(ans, sim(st))
        output.append(str(ans))

    return "\n".join(output)

""") == "3"

 ## 特殊なケース

 重要なエッジケースは、文字列全体が「?」で構成されている場合です。 In this situation, any alternating pattern is achievable, and the optimal strategy is to align completely with one of the three deterministic sequences. すべての位置が一致可能として扱われるため、アルゴリズムは、選択された開始のすべての位置に完全なクレジットを与えることでこれを処理します。 

もう 1 つの微妙なケースは、固定文字がまばらに表示されるものの、最適な開始が大きく制限される場合です。 たとえば、「A????C」では、両方のエンドポイントと一致する開始のみが高スコアを達成できます。 The simulation correctly evaluates all three starts, and only the compatible one yields maximal alignment, avoiding incorrect greedy local fills.

 最後のエッジ ケースは、長さが 1 または 2 の短い文字列であり、代替制約は自明です。 アルゴリズムは引き続きそれらを均一に扱い、遷移のあいまいさが存在しないため、各開始で正しい評価が生成されます。
