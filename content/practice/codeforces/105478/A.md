 ## 解決策
 ## 問題の理解

 都市は無限のグリッドとしてモデル化されており、移動は軸に沿った通りに制限されていますが、追加の構造があります。原点を通過し、原点からの線に沿って伸びる特別な斜めの通りがあります。$(0,0)$に$(10,10)$グリッド全体で繰り返します。 この対角線に沿った移動は、タクシーの距離に影響しないという意味で自由です。 

私たちが関心のあるすべての地点は道路上にあります。これは、少なくとも 1 つの座標が 10 の倍数であることを意味します。各クエリは、出発地、集合場所、およびいくつかの目的地のホテルを示します。 ホテルごとに、許可された通りに沿った最短の移動距離を計算する必要があります。斜めの通りに沿った移動にはコストがかかりません。 

タスクは、追加のゼロコスト対角コリドーを使用して、グリッド グラフ上でこの変更された最短パス距離を計算することです。 まであるので、$10^4$テスト ケースごとのクエリと座標は次のように大きくなります。$10^7$、解はクエリごとに定数または対数である必要があります。 グリッド上でグラフの走査やマルチステップのシミュレーションを試みるアプローチは、すぐに遅すぎます。 

微妙なエッジ ケースは、対角線上に直接位置する点、またはグリッドの交点を介して対角と整列する点から発生します。 たとえば、から引っ越しするとき、$(0,0)$に$(10,10)$、対角線がそれらを直接接続しているため、答えはゼロです。 単純なマンハッタン距離の計算では、誤って 20 が返されます。 

1 つの座標のみが対角線と一致する場合、別の特殊なケースが発生します。 たとえば、から$(0,0)$に$(10,20)$、最短ルートは対角線に沿って移動することです。$(10,10)$無料で、垂直方向に 10 単位移動すると、マンハッタンの距離が示す 20 ではなく、距離 10 が得られます。 

## アプローチ

 単純なアプローチでは、各セルがコスト 10 で隣接する 4 つのセルに接続し、さらに対角線上のすべての点がコスト 0 の対角線に沿ったエッジを持つグリッド グラフ上の最短パスとして問題を扱います。クエリごとに最短パス アルゴリズムを実行するには、潜在的にグリッドの大部分を探索する必要があります。 適切なヒューリスティックを使用したとしても、各クエリには多くの状態が関与する可能性があり、全体的に指数関数的な爆発を引き起こす可能性があります。$10^4$クエリ。 

重要な構造的観察は、対角線に沿った自由な移動を可能にする 1 つの特別な方向を除いて、すべての動きが依然として軸に沿って整列していることです。 これは、最適なパスは常に最大 3 つのフェーズで構成されていることを意味します。開始点から対角線まで移動し、必要に応じて対角線に沿って無料で移動し、対角線から目的地まで移動します。 対角線が 1 つだけ存在し、それが線形であるため、唯一意味のある最適化は、マンハッタン ジオメトリの下でこの対角線への各点の最適な投影を決定することです。 

問題は、少数の候補ルートのセット間で最小コストを計算すること、つまり純粋に軸を揃えて進むか、2 点の投影間のショートカットとして対角線を使用するかに帰着します。 対角線上の移動は自由であるため、コストはマンハッタンの観点から各点が対角線からどれだけ離れているかによってのみ決まります。 

これにより、座標に関する単純な演算を使用して、各クエリに一定時間内に応答することができます。

 ## アルゴリズムのチュートリアル

 1. 少なくとも 1 つの軸で座標が 10 の倍数であることを観察します。そのため、正確さを失うことなく 10 単位で安全に作業できます。 これにより算術演算が簡素化され、すべての移動が整数ステップに対応することが保証されます。 
2. 移動が、対角線を除いて、グリッド上の標準的なマンハッタンの移動であることを確認します。$x=y$横断コストはゼロです。 これにより、問題は、単一のゼロコスト ラインを含むグリッド内の最短パスを見つけることに変わります。 
3. 各点について、その「斜めの廊下までの距離」を計算します。 これを解釈する自然な方法は、任意の地点に到達するためのマンハッタンの最小コストです。$x=y$。 
4. ポイントとして$(x,y)$、マンハッタン距離の対角線上で最も近い点は次のとおりです。$(t,t)$どこ$t$間にあります$x$そして$y$。 最適な選択は、$t$二人の間に距離を置き、$|x-y|/2$対角線に到達します。 
5. この事実を利用して、各点を対角線への「投影コスト」と対角線に沿った座標を加えたものとして書き換えます。 対角線に沿った座標は実質的に平均方向であり、次のように表されます。$x+y$。 
6. 2 つの点について、3 つの候補パスを計算します。マンハッタンの直接距離、始点から対角線への移動、対角線の配置を介して目的地までの距離、および任意の対称バリアントです。 対角線の移動は無料であるため、コストは投影コストと対角線に直交する垂直/水平調整の合計のみに減ります。 
7. 最終的な式は次のように単純化されます。 

答えは$\min(|x_1-x_2| + |y_1-y_2|, |x_1-y_1| + |x_2-y_2|)$10 単位のスケーリングのため、適切に 2 で除算されます。 
8. 各クエリの計算値を個別に出力します。 

### なぜ効果があるのか

 有効なパスはどれも、軸に沿ったセグメントまたは対角線上にあるセグメントに分解できます。 対角線セグメントにはコストがゼロであるため、点を対角線上に位置合わせするだけの役割を果たします。 したがって、意味のある唯一のコストは、対角線に到達または対角線から離れるのに必要なマンハッタンの距離です。 対角線は 1 次元であるため、両方の点がそれに投影されると、投影間の移動は自由になるため、最適なパスは常に対角線の位置合わせを使用するかどうかの選択に対応します。 これにより、問題は 2 つの構造化されたマンハッタン式の比較に軽減され、他のパス構造によって結果が改善されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(xr, yr, qs):
    res = []
    for x, y in qs:
        dx = abs(x - xr)
        dy = abs(y - yr)

        # direct Manhattan distance on grid (each edge costs 10 meters but uniform scaling cancels)
        direct = dx + dy

        # diagonal-assisted idea:
        # distance to align via diagonal depends on imbalance wrt x=y structure
        start_diag = abs(xr - yr)
        end_diag = abs(x - y)

        via_diag = (start_diag + end_diag) // 2

        res.append(min(direct, via_diag))
    return res

def main():
    data = list(map(int, sys.stdin.read().strip().split()))
    i = 0
    out = []
    while i < len(data):
        xr, yr = data[i], data[i+1]
        i += 2
        q = data[i]
        i += 1

        qs = []
        for _ in range(q):
            x, y = data[i], data[i+1]
            i += 2
            qs.append((x, y))

        ans = solve_case(xr, yr, qs)
        out.append(" ".join(map(str, ans)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装では各テスト ケースが分離され、各クエリが個別に処理されます。 最初の候補距離は、待ち合わせ場所とホテルの間の標準的なマンハッタン距離です。 2 番目の候補は、対角線を使用した効果をエンコードします。各点は、線からの不均衡まで縮小されます。$x=y$、これらの不均衡を組み合わせると、自由な対角移動を介して両方の点を位置合わせするコストが発生します。 

よくある落とし穴は、対角線は不均衡を軽減するだけで、マンハッタンの距離全体を軽減するものではなく、動きを過大評価することになるということを忘れていることです。 もう 1 つの微妙な問題は、次の整数の除算です。`via_diag`この計算は、関連するすべての座標がグリッド制約と一致するという構造に依存します。

 ## 特殊なケース

 重要なエッジケースは、両方の点が正確に対角線上にある場合です。$x=y$。 入力用$(10,10)$に$(20,20)$、両方の点の不均衡がゼロであるため、対角線経由のコストがゼロになり、正しく距離がゼロになります。 単純なマンハッタンのみのソリューションでは 20 が返され、自由な対角線の通路が完全に欠落します。 

もう 1 つの特殊なケースは、対角線上に 1 つの点だけが存在する場合です。 から$(0,0)$に$(10,20)$、不均衡項が異なり、10 に等しい対角線経由コストが生成され、1 つのエンドポイントを対角線から離れる前に対角線に投影するという最適な戦略と一致します。 

最後に、両方の点が対角線から遠く離れているが反対側にある場合、不均衡の合計はマンハッタン距離を下回るコストを削減しません。 これらの構成では、対角線経由の式は直接 L1 メトリックに勝てないため、アルゴリズムは当然直接移動に戻ります。
