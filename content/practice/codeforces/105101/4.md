 ## 解決策
 ## 問題の理解

 いくつかの独立したグリッドが与えられます。 各グリッドは長方形のケーキを表しており、各セルには味の寄与を表す整数値が含まれています。 各グリッドから、その正方形内のすべての値の合計ができるだけ大きくなるように、単一の正方形部分行列 (同じ数の行と列、グリッド内の任意の位置) を選択する必要があります。 

各グリッドの出力は、まさにこの達成可能な最大平方和です。 

重要な問題は、正方形のサイズとその位置の両方が不明であることです。 正方形の範囲は 1 × 1 から min(N, M) × min(N, M) まであり、すべての配置を考慮する必要があります。 

制約は非常に具体的な意味で重要です。 各グリッドは最大 500 x 500 にできますが、すべてのグリッドの合計の高さも 500 によって制限されます。これは、定数に注意している場合に限り、最悪の場合でもテストあたりおよそ O(N³) のアルゴリズムを許容できますが、O(N³M) のようなものや、前処理なしで単純にすべての正方形を列挙するようなものは許容できません。 

素朴なアプローチでは、すべての正方形のサイズ、すべての左上の位置を試し、その合計を最初から計算します。 500 x 500 になるとすぐに遅くなりすぎます。これは、正方形の数だけでも O(N²M²) であり、これは実現可能性をはるかに超えているためです。 

いくつかの特殊なケースは概念的に重要です。 

グリッドは、1 つの正のセルを除いてほとんどが負である場合があります。 例えば：```
1 1
-5 -5
-5 10
```最適な正方形は 1 x 1 であるため、答えは 10 です。大きな正方形のみを考慮する方法では、これを見逃してしまう可能性があります。 

もう 1 つのケースは、完全なグリッドに多くの正の値が含まれているにもかかわらず、最適な正方形が完全なグリッドではない場合です。```
2 2
1 -100
1 -100
```最適な正方形は、やはり 1 x 1、または長方形が許可されている場合は垂直のストリップですが、許可されるのは正方形のみであるため、すべてのサイズを正しく比較する必要があります。 

最後に、混合符号グリッドでは、ロジックが正しい場合でも合計を繰り返し再計算すると時間制限をオーバーフローする可能性があるため、プレフィックス合計を慎重に処理する必要があります。 

## アプローチ

 ブルートフォース手法は簡単です。 正方形のサイズ k を 1 から min(N, M) まで選択します。 各 k について、グリッド上で k × k ウィンドウをスライドさせ、そのセルの合計を計算し、最大値を追跡します。 

各平方和を単純に計算するには、k² セルを合計することになるため、各配置のコストは O(k²) になります。 O(NM) 個の配置と O(min(N, M)) のサイズがあるため、直接実行すると、最悪の場合、合計の複雑さはおよそ O(NM·min(N, M)³) になります。これは、500 x 500 のグリッドではまったく実行不可能です。 

重要な点は、必要なのは高速な部分行列合計クエリだけであるということです。 O(1) で任意の長方形の合計を計算できるようになると、すべての正方形の列挙が管理可能になります。 これはまさに 2D プレフィックス合計が提供するものです。つまり、各グリッドを、軸に揃えられた四角形の合計が一定時間で計算される構造に変換する前処理ステップです。 

プレフィックス合計の場合、各二乗和は O(1) となるため、作業量の合計は O(NM・min(N, M)) になります。これは境界線ですが、すべてのテスト ケースの合計 N が 500 に制限されることを考えると、許容範囲内です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | サイズあたり O(NM·k²)、最大 O(NM·min(N,M)³) | お(1) | 遅すぎる |
 | プレフィックスの合計 + 列挙 | O(NM・分(N,M)) | O(NM) | 承認済み |

 ## アルゴリズムのチュートリアル

 各グリッドを個別に処理します。 

1. グリッド上に 2D プレフィックス合計配列を構築します。 各エントリには、(1,1) から (i,j) までの部分行列の合計が格納されます。 これにより、O(1) 内の任意の四角形の合計をクエリできるようになります。 これが役立つ理由は、すべての候補正方形を長方形クエリに縮小できるためです。 
2. 1 から min(N, M) までのすべての可能な正方形サイズ k について、k × k の正方形が収まるすべての左上隅 (i, j) を考慮します。 目標は、その二乗の合計を迅速に評価することです。 
3. このような位置ごとに、プレフィックス合計の式を使用して合計を計算します。 これにより、すべての k² 要素の反復処理が回避され、コストが一定時間に削減されます。 
4. すべての正方形の最大値を追跡します。 単一のセルであっても有効な正方形であるため、初期化では、非常に小さな数値または最初に計算された正方形から開始して、負の値を安全に許可する必要があります。 
5. すべてのサイズと位置を確認した後、最大値を出力します。 

重要な効率の向上は、繰り返しの合計を定数時間のクエリに置き換えることによってもたらされ、コンテンツを再計算することなくジオメトリを完全に列挙できるようになります。 

### なぜ効果があるのか

 すべての正方部分行列は、パラメータのペア (左上隅と辺の長さ) に一意に対応します。 プレフィックス合計構造により、そのような平方和が近似や省略なしに正確に計算されることが保証されます。 考えられるすべての正方形が 1 回だけ列挙されるため、アルゴリズムは実行可能なすべての候補を評価し、最適な候補を見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, m, grid):
    ps = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(n):
        row_sum = 0
        for j in range(m):
            row_sum += grid[i][j]
            ps[i + 1][j + 1] = ps[i][j + 1] + row_sum

    def get(x1, y1, x2, y2):
        return (ps[x2][y2]
                - ps[x1 - 1][y2]
                - ps[x2][y1 - 1]
                + ps[x1 - 1][y1 - 1])

    best = -10**18

    limit = min(n, m)
    for k in range(1, limit + 1):
        for i in range(1, n - k + 2):
            i2 = i + k - 1
            for j in range(1, m - k + 2):
                j2 = j + k - 1
                best = max(best, get(i, j, i2, j2))

    return best

def main():
    T = int(input())
    out = []
    for _ in range(T):
        n, m = map(int, input().split())
        grid = [list(map(int, input().split())) for _ in range(n)]
        out.append(str(solve_case(n, m, grid)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```このソリューションは、標準の 2D プレフィックス合計テーブルを構築することから始まります。 各エントリ ps[i][j] は、左上隅から (i, j) までの長方形の合計を表します。 この構築では、水平合計を繰り返し再計算することを避けるために行累積を使用します。 

get 関数は、部分行列の合計に包含/除外式を適用します。 境界処理が重要になるのはここだけです。 1 から始まるインデックス付けにより、負のインデックスの繰り返しチェックが回避されます。 

列挙は、すべての正方形サイズとすべての有効な位置をループします。 ネストされたループは、テスト全体のグリッド サイズの合計が制限されているため、累積反復回数が制限内に留まるため安全です。 

よくある間違いは、行の合計を間違って再計算したり、正方形の境界が包括的であることを忘れたりすることです。これにより、すべての計算領域が 1 セルずつシフトされてしまいます。

 ## 特殊なケース

 アルゴリズムは引き続き 1 x 1 の正方形ごとに評価するため、完全に負のグリッドは正しく処理されます。 例えば：```
2 2
-1 -2
-3 -4
```プレフィックスの合計は引き続き正しい値を計算し、最大値は個々のセルから更新され、-1 が生成されます。 

すべてのサイズが独立して反復されるため、最適な正方形が最大ではないグリッドが処理されます。 例えば：```
3 3
10 -100 10
-100 -100 -100
10 -100 10
```このアルゴリズムは、1 x 1 の角 (値 10) と大きな正方形 (強い負) の両方を評価し、10 を正しく選択します。 

1 から始まるプレフィックス合計により、境界処理は安全です。 上端または左端の正方形をクエリすると、明示的に 0 に初期化されるプレフィックス配列のインデックスが 0 になるため、減算項は自動的に消えます。
