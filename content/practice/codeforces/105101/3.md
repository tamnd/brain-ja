 ## 問題の理解

 このマジシャンのトリックは、1 から 100 までの隠された数字を特定する作業を、固定された 7 つの「はい」または「いいえ」の質問に答える作業に軽減します。 7 枚のカードのそれぞれには、その範囲の数字のサブセットが含まれており、観客はカードごとに、選択した数字がそのカードに表示されているかどうかを示します。 

ソルバーの観点から見ると、入力は単に 7 つのバイナリ応答を順番に並べたものであり、それぞれが 1 枚の事前定義されたカードに対応します。 隠された数字は、それが含まれるカードの組み合わせによって一意に決定されるため、出力は 7 つの答えすべてと一致する 1 つの数字になります。 

重要な構造上の制約は、考えられる結果は 100 個しかないということですが、各結果はカード全体のメンバーシップの個別の 7 ビット パターンに対応します。 これは、カードが数値をバイナリ表現またはそれに近い変形としてエンコードする必要があることを直ちに意味します。 「はい」または「いいえ」の回答が 7 つしかない場合、パターンのスペースは最大でも 2^7 = 128 で、これは 1 から 100 までの範囲を快適にカバーします。これは、各数字がカードの一意のサブセットにマッピングされていることをすでに示唆しており、再構築は直接のデコード問題です。 

素朴な解釈では、1 から 100 までの各数値をテストし、指定された答えと一致するかどうかをシミュレートしようとする可能性があります。 これは 100 回のチェックだけなので制約内で安全に機能しますが、その必要はありません。 意図された構造は直接デコードです。各「はい」は、最終的な回答に固定の重みを与えます。 

カードの内容を任意に仮定すると、微妙なエッジケースが発生します。 セットがランダムであると誤って仮定すると、再構成があいまいになります。 たとえば、2 つの数値が同じメンバーシップ パターンを共有する場合、出力は未定義になります。 この問題により、適切なエンコードが保証されるため、各パターンは正確に 1 つの数値にマップされ、この曖昧さが回避されます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 1 から 100 までのすべての数字について、7 枚のカードにわたるその存在パターンが入力応答と一致するかどうかを確認します。 具体的には、候補番号ごとに 7 枚のカードをシミュレートし、指定された「はい」または「いいえ」のシーケンスと比較します。 これには、最大 100 個の数値をスキャンし、各数値に対して最大 7 つの条件をチェックする必要があり、テストごとに最大 700 回の操作が行われます。 拡張しても、これは些細なままですが、トリックの構造が隠蔽されます。 

重要な洞察は、7 枚のカードが数値をバイナリ形式でエンコードしているということです。 各カードは固定ビット位置に対応しており、「はい」はそのビットが隠し番号に設定されていることを意味します。 すべての候補をチェックする代わりに、「はい」の回答に関連付けられた 2 の累乗を合計することによって数値を直接再構築します。 

これにより、問題は検索から解読へと変わります。 入力の構造はすでに答えのバイナリ表現を表しているため、再構築は 7 つの値に対する 1 回のパスで行われます。

 ## アルゴリズムのチュートリアル

 1. 2 進数に対応する 7 つの位置のそれぞれに重みを割り当てます。 最初のカードは 2^0、2 番目のカードは 2^1 などを表します。 これは、各カードが隠された数字のバイナリ表現でビットをエンコードしているという事実を反映しています。 
2. アキュムレータ変数をゼロに初期化します。 これにより、ビットが解釈されるときに再構築された数値が保存されます。 
3. 7 つの応答を順番に繰り返します。 
4. 各応答について、それが「はい」の場合、対応する 2 のべき乗をアキュムレータに加算します。 「いいえ」の場合は、そのビットが数値に存在しないため、何も行いません。 
5. 7 つの応答すべてを処理した後、アキュムレータを再構成された数値として出力します。 

### なぜ効果があるのか

1 から 100 までの各数値は、最大 7 ビットを使用した一意の 2 進数表現を持ちます。 各カードは、その表現内の 1 つのビット位置に正確に対応します。 「はい」はビットが 1 であることを示し、「いいえ」はビットが 0 であることを示します。バイナリ表現は一意であるため、アクティブなビットを合計すると、曖昧さのない元の数値が再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    responses = input().split()
    
    ans = 0
    for i, r in enumerate(responses):
        if r == "Yes":
            ans += (1 << i)
    
    print(ans)

if __name__ == "__main__":
    solve()
```ソリューションは 7 つの応答を読み取り、それらを順番に処理します。 各応答のインデックスによってビット位置が決まります。 応答が「はい」の場合、対応する 2 のべき乗がビット シフトを使用して加算されます。 最終的な合計が答えとして出力されます。 唯一の微妙な点は、一貫したインデックス付けを保証することです。最初の応答は最下位ビットに対応する必要があります。そうでないと、再構築された数値が不正確になります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての応答が「いいえ」である場合です。 このアルゴリズムはアキュムレータをゼロに初期化し、2 のべき乗を加算して 0 を生成することはありません。有効範囲は 1 から始まるため、このケースは通常、無効な入力または特殊なエンコードのケースを表しますが、計算の一貫性は保たれます。 

もう 1 つのケースは、すべての応答が「はい」の場合です。 アキュムレータは 1 + 2 + 4 + 8 + 16 + 32 + 64 となり、127 になります。これにより、7 ビット エンコーディングの上限が正しく処理されることが検証されます。 

3 番目のケースでは、「Yes No Yes No Yes No Yes」を交互に繰り返すなど、散在するビットが含まれます。 このアルゴリズムは、選択された 2 の累乗のみを正確に累積し、結果は位置間の干渉なしに正確なバイナリ構成を反映します。
