 ## 解決策
 ## 問題の理解

 私たちは、E2 から始まり、一定数の白い動きにわたって進化する白いポーンの垂直方向の動きの履歴を追跡しています。 ランクのみが重要であるため、ポーンの状態は 2 から 8 までの整数の位置で表すことができます。ポーンは 2 から始まり、移動するたびに同じランクに留まるか、1 ランクずつ上がるか、2 ランクずつ上がることができますが、2 段階の移動が許可されるのは、それが最初の移動である場合のみです。 ポーンがランク 8 に到達すると、それ以上移動することはできませんが、ゲームの残りの間はそこに留まる可能性があります。 

白が動くたびに、記録システムがポーンの現在のランクを記録します。 ポーンがいずれかの時点でキャプチャされると、記録は直ちに停止するため、有効な履歴は常にキャプチャ時または最後の移動境界で終了します。 タスクは、これらのルールの下で、長さ N の記録されたランクの個別のシーケンスがいくつ発生できるかをカウントすることです。 

重要な解釈は、小さな線形状態空間上の制約されたパスを数えているということです。ここでの遷移は、最初のステップにいるか、すでに吸収境界 8 にいるかどうかによってわずかに異なります。 

N が 10^6 までという制約は、すべてのシーケンスを明示的にシミュレートするアプローチを即座に除外します。 動的計画法の解であっても O(N) または O(N log N) である必要があり、各状態遷移は一定であるため、O(N) の解がターゲットとなります。 

最初の動きには微妙な例外ケースが発生します。+2 移動する能力は 1 回だけ存在するため、最初の遷移は他の遷移とは異なります。 もう 1 つのエッジ ケースは、早期にランク 8 に到達し、その後「失速」することです。これにより、依然として異なる履歴に寄与する一定の状態の長いサフィックスが作成されます。 

単純な間違いは、すべての動きをステップごとに同一のトランジション +0、+1、+2 として扱うことです。 たとえば、N=2 の場合、2 番目のステップで +2 の移動を含むシーケンスが誤って許可され、カウントが正しい 10 を超えて膨張します。 

## アプローチ

 ブルートフォース解釈により、ポーン位置の可能なすべてのシーケンスが段階的に生成されます。 現在のランクとステップのインデックスから、留まるか、1 つずつ移動し、最初のステップの場合は 2 つ移動するかに分岐します。 また、概念的に任意のステップでキャプチャを許可する場合はパスを終了しますが、キャプチャは「最初の移動の直後に発生する可能性がある」以上に明示的に制約されていないため、事実上、早期に終了するシーケンスに対応します。 

このアプローチは、ルールによって記述された状態空間を正確に探索するため、正しいです。 ただし、各ステップで最大 3 つの選択肢があるため、シーケンスの数は N に応じて指数関数的に増加します。 +2の手を1ステップに限定したとしても、残りの分岐因子は少なくとも2なので、およそO(2^N)の成長となり、40前後のNでも不可能になります。 

重要な観察は、プロセスを続行するために必要な唯一のメモリは、現在のランクと最初の動きにいるかどうかだけであるということです。 最初の動きが完了すると、システムはランク 2 から 8 までの標準的な有界歩行となり、トランジション +0 および +1 が付きますが、8 が吸収になる点が異なります。 これは、問題全体を、特別な初期遷移層を備えた小さな有限オートマトン内で歩行をカウントすることとして再定式化できることを意味します。 

パスを列挙する代わりに、動的プログラミングを使用して、各ステップの後に各ランクに到達する方法の数を計算します。 唯一の複雑な点は、追加の +2 遷移を考慮して最初のステップを個別に処理することです。

 ## アルゴリズムのチュートリアル

 私たちは、ランク 8 が吸収であることを尊重しながら、各移動後にポーンが各ランクで何通りになれるかを数えるという問題として扱います。

1. 状態配列 dp を初期化します。ここで、dp[i] は、動きのプレフィックスを処理した後にポーンがランク i になれる方法の数を表します。 ポーンは E2 から始まるため、最初は dp[2] = 1 です。 
2. 最初の動きを個別に処理します。 ポーンはランク 2 から 2、3、または 4 に進むことができます。これらは、滞在、移動 +1、または移動 +2 に対応します。 最初の移動後の状態を反映した新しい分布 dp1 を蓄積します。 
3. 2 手目以降、トランジションは均一になります。 r < 8 の任意のランクから、r (留まる) または r+1 (前進) に進むことができます。 ランク8は吸収なので自身のみに移行します。 
4. 後続の各ステップで、カウントを分散することによって前のステップから新しい dp 配列を計算します。r < 8 の場合、各 dp[r] は dp_next[r] および dp_next[r+1] に寄与し、dp[8] は dp_next[8] にのみ寄与します。 
5. N 個の手をすべて処理した後、ランク 2 から 8 までのすべての dp[r] を合計して、有効な記録された履歴の総数を取得します。 

すべての最終ランクを合計する理由は、記録が特定のランクで終了する必要がないためです。 N ステップ後の最終位置は有効なシーケンスを表します。 

### なぜ効果があるのか

 このアルゴリズムは、k ステップ後の dp が k 移動後の各ランクで終了する有効な履歴の正確な数を格納するという不変条件を維持します。 各遷移ステップは、状態を導入したり省略したりすることなく、ルールで許可されている動きを正確に適用するため、正確性が維持されます。 最初の動きは +2 トランジションが存在する唯一のポイントであるため、特別な処理が必要です。 その時点を過ぎると、システムは時間的に均一になります。 ランク 8 は、そこから離れるトランジションがないため、吸収として正しく処理され、ポーンが E8 から前に進むことができないというルールと一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input().strip())
    
    # dp[r] for ranks 2..8 (we shift index by -2)
    dp = [0] * 7
    dp[0] = 1  # rank 2

    if n == 1:
        print(3)
        return

    # first move: 2 -> 2,3,4
    ndp = [0] * 7
    ndp[0] = 1  # 2 -> 2
    ndp[1] = 1  # 2 -> 3
    ndp[2] = 1  # 2 -> 4
    dp = ndp

    for _ in range(n - 1):
        ndp = [0] * 7
        for i in range(7):
            if dp[i] == 0:
                continue
            ndp[i] = (ndp[i] + dp[i]) % MOD
            if i < 6:
                ndp[i + 1] = (ndp[i + 1] + dp[i]) % MOD
        dp = ndp

    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```+2 移動が存在する唯一のポイントであるため、コードは最初の遷移を明示的に分離します。 最初のステップで dp を初期化した後、ループは均一な遷移を処理します。 配列サイズ 7 は、ランク 2 から 8 までに対応します。 

遷移ステップは、ランク 8 に対応するインデックス 6 を除き、dp[i] をそれ自体 (滞在) と i+1 (前進) に追加します。この場合、滞在のみが可能です。 最終的な合計は、考えられるすべての終了ランクを集計します。 

よくある落とし穴は、ランク 8 が依然として前方滞在トランジションに貢献していることを忘れていることです。 この定式化では、i+1 更新をスキップすることで自然に処理されます。

これにより、最初の動きからの分岐が正しく統合され、均一な遷移によって展開されることが確認されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、N = 1 の場合です。この場合、先手ルールのみが適用され、均一な遷移は存在しません。 アルゴリズムは、3 つの可能な最初の手を直接返すことによってこれを処理し、無効な遷移ロジックが実行されないようにします。 

もう 1 つのエッジケースは、ポーンが非常に早い段階でランク 8 に到達する場合です。 たとえば、最初の移動後の dp からの開始にはすでにランク 4 が含まれており、トランジションを繰り返すと質量がすぐに 8 に到達する可能性があります。 8 になると、DP は自己遷移のみを許可し、正確性を維持してそこに留まることを保証します。 

最後のエッジ ケースは N が大きく、ほぼすべての寄与がランク 8 に集中します。アルゴリズムは依然として各ステップを一定時間で処理し、出力遷移が存在しないため、吸収状態での累積は有効なままであり、カウントの漏洩を防ぎます。
