 ## 解決策
 ## 問題の理解

 この状況を次のように再解釈できます。 

開始時の整数強度があります`s`そして敵のリスト。 各敵は、戦いを生き残るために必要な閾値の強さと、勝利後に得られるボーナスの 2 つの値で表されます。 いずれかの時点で、しきい値が厳密に現在の強さ以上である敵を選択した場合、すぐに失敗します。 それ以外の場合は、それを倒し、ボーナスによって強さを増加させます。 

目標は、固定シーケンスをシミュレートすることではなく、すべての敵を倒すことを可能にする敵の順序が存在するかどうかを判断することです。 

入力サイズは小さく、ドラゴンの数は最大でも約 1000 です。これは、O(n^2) の貪欲な戦略が受け入れられることをすぐに示唆していますが、n! であるため、順列を超える指数関数的なものは不可能です。 注文数は中程度の n であっても爆発的に増加します。 

素朴な間違いは、任意の順序が機能する、または強さによる並べ替えだけで十分であると仮定することです。 弱いドラゴンが後でより強いドラゴンのロックを解除する大きなボーナスを与える場合、これは失敗します。 

たとえば、次のことを考えてみましょう。 

入力:```
s = 2
(1, 99), (100, 0)
```強いドラゴンと先に戦ってしまうとすぐに死んでしまいます。 最初に弱いドラゴンと戦えば、2番目のドラゴンを倒すのに十分な強さになります。 したがって、順序は非常に重要です。 

もう 1 つの微妙なエッジ ケースは、最初はすべてのドラゴンが強すぎるが、そのうちの 1 匹がかろうじて到達でき、残りのドラゴンのロックを解除するのに十分なボーナスを与える場合です。 貪欲な選択では、この段階的なロック解除プロセスを検出する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、ドラゴンのすべての組み合わせを試し、戦闘をシミュレートします。 これは正しいですが、実行不可能です。n 個あります。 順列があり、n = 15 でさえすでに大きすぎます。 

重要な観察は、私たちがドラゴンを倒すのに十分な強さになったら、より早く強くなるのに役立つのであれば、ドラゴンとの戦いを遅らせる理由はないということです。 遅れれば、より強力なドラゴンをより早くアンロックする機会を逃すリスクが生じるだけです。 これは貪欲な戦略につながります。各ステップで、現在倒せるすべてのドラゴンの中から 1 つを選択するというものです。 

残る問題は、どの「倒せる」ドラゴンを最初に選ぶかです。 正しい選択は、最初に強度要件の小さいドラゴンを優先することです。 必要な強さによってドラゴンを分類することで、前方にスキャンするたびに、現在到達可能なすべてのオプションが常に構造化された方法で表示され、継続的に範囲を拡大しながら、難易度が上がる順にそれらを貪欲に消費することができます。 

アルゴリズムは次のようになります。しきい値によってソートし、到達可能なすべてのドラゴンを繰り返し取得し、通常はリニア スキャンを使用して任意の順序で消費します。

 ## アルゴリズムのチュートリアル

 1. 各ドラゴンの必要な強さとボーナスをタプルのリストに組み合わせ、このリストを必要な強さの昇順に並べ替えます。 ソートにより、より難しいドラゴンよりも簡単なドラゴンを常に考慮するようになります。これは、強さのロックを解除するのは段階的であるべきであるという考えと一致します。 
2. 変数を維持する`cur`初期強度に初期化されます。 これは、プロセスのあらゆる瞬間における現在の能力を表します。 
3. ソートされたリストを繰り返し、次のドラゴンの必要な強さが厳密に以下になるたびに、`cur`、敗北可能としてマークします。 これが機能するのは、ソートにより、以前に考慮されたすべてのドラゴンも要件において弱いか同等であることが保証されるためです。 
4. 現在利用可能なすべてのドラゴンの中から、まだ訪れていないドラゴンを繰り返し選んで倒し、ボーナスを追加します。`cur`。 敗北するたびに新しいドラゴンのロックが解除される可能性があるため、可用性セットは動的に更新する必要があります。 
5. 現在のパスでこれ以上ドラゴンを倒すことができなくなるまで、このプロセスを続けます。 次に、ソートされたリストの前方へのスキャンを再開して、新しくロック解除されたドラゴンを見つけます。 
6. 考えられるすべての拡張が処理された後、すべてのドラゴンが倒されたかどうかを確認します。 ある場合は「YES」を出力し、そうでない場合は「NO」を出力します。 

### なぜ効果があるのか

 正確さは、単調な到達可能性の不変条件から得られます。どの時点でも、必要な強さが現在の強さよりも小さいドラゴンのセットを維持し、そのようなドラゴンが存在する場合は最終的にそれを処理することを保証します。 ドラゴンを倒すと強さが増すだけなので、到達可能なセットは時間の経過とともに増加するだけであり、縮小することはありません。 これにより、完全な順序付けが存在する場合、貪欲なプロセスは必要な中間ロック解除をスキップすることなく有効なシーケンスを発見することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, s = map(int, input().split())
dragons = [tuple(map(int, input().split())) for _ in range(n)]

dragons.sort()  # sort by required strength

cur = s
i = 0
used = 0

visited = [False] * n

while True:
    progress = False

    while i < n and dragons[i][0] < cur:
        if not visited[i]:
            visited[i] = True
            cur += dragons[i][1]
            used += 1
            progress = True
        i += 1

    if not progress:
        break

print("YES" if used == n else "NO")
```このコードでは、まずドラゴンを強さの要件に基づいて並べ替えるため、実行可能性が常に昇順にチェックされます。 ポインタ`i`順方向スキャンが 1 回だけ行われるようにすることで、作業の繰り返しを防ぎます。 内側のループは現在倒せるすべてのドラゴンを収集し、それらのボーナスをすぐに適用し、より強力なドラゴンのロックを解除できる可能性があります。 

微妙な詳細は、`< cur`それよりも`<= cur`。 これは、生き残るためには同じ強さだけでは不十分であるというルールと一致します。 

このアルゴリズムは、各ドラゴンが最大 1 回処理されるという事実に依存しており、ソート後の全体的な複雑さが線形になります。

 ## 特殊なケース

 特殊なケースの 1 つは、複数のドラゴンが同じ必要な強さを持っている場合に発生します。 アルゴリズムはこれを正しく処理します。`cur`そのしきい値を超えると、それぞれが独立して強度を高めるため、すべてが同時に利用可能になり、任意の順序で消費できます。 

もう 1 つのケースは、最適な戦略が、より高いボーナスを持つ弱いドラゴンを優先して、強力だが到達可能なドラゴンを遅らせる必要がある場合です。 現在到達可能なすべてのドラゴンが処理されるため、貪欲スキャンはこれを自然に処理します。ボーナスは将来の到達可能性を高めるだけであるため、いずれかを人為的に遅らせるメリットはありません。 

最後のエッジケースは、初期強度がすでにすべてのしきい値を超えている場合です。 その場合、アルゴリズムは単純に 1 回のスイープですべてを消費し、すべてが到達可能になった後は順序付けの制約が無関係であることが確認されます。
