 ## 解決策
 ## 問題の理解

 私たちには、それぞれに価値のある本の列と、時間をかけて端から本を取り除くプロセスが与えられます。 毎秒、2 つのことが順番に起こります。まず、キーが現在のセグメントのどこからでも残りの本を 1 冊だけ取り出す可能性があり、次に火が現在の左端と右端の本を焼きます。 その後、残ったセグメントが両側で 1 位置ずつ内側に縮小し、何も残らなくなるまでこのプロセスが繰り返されます。 

重要な制約は、Keys がすでにそれらの本を以前に取得したかどうかに関係なく、書き込みによって常に現在の端が削除されることです。 キーズさんは、本が壊れたり、縮小してアクセスできなくなったりする前に、なんとか選んだ本の価値の合計を最大化しようとしています。 

したがって、問題は縮小間隔にわたるスケジューリングの問題です。時刻 t では中央の部分配列のみが残り、各タイム ステップでキーは端が削除される前にその部分配列から 1 つの要素を選択できます。 

入力サイズ N は最大 100000 まで可能で、選択された位置のすべての選択肢をシミュレートしたり、サブセットに対して指数関数的な DP を使用したりするソリューションは即座に除外されます。 正しいアプローチは、最大でも O(N log N) または O(N) でなければなりません。 

微妙な点は、削除のタイミングが重要であるということです。 位置 i にある本は、縮小プロセスがどちらかの側から到達するまでのみ利用可能です。 つまり、各位置には、純粋に近い端までの距離によって決定される、選択可能な最後の時間が存在します。 これにより、隠れた構造が作成されます。すべてのアイテムには期限があり、1 秒あたり最大 1 つのアイテムを選択できます。 

よくある間違いは、各ステップで現在の間隔から残りの最大値を貪欲に選択する必要があると想定することです。 これは失敗します。より余裕のある別の大きな値を優先して選択を遅らせると、書き込まれようとしている大きな値が見逃される可能性があるためです。 

たとえば、[100, 1, 1, 100] のような配列では、両方の 100 が終わり近くにあります。 それぞれの縮小後に残るグローバル最大値を常に選択すると、正しくスケジュールされていれば両方とも個別に安全であっても、間違った側で 1 ステップを無駄にし、100 のうちの 1 つを完全に失う可能性があります。 

別の障害モードは、すべてのサブアレイにわたる間隔 DP のように処理します。 それには O(N^2) 状態が必要ですが、これは大きすぎます。 

最も難しいのは、プロセスがインデックスごとに時間ウィンドウを定義しており、決定は単にどの要素をどのタイムスロットにスケジュールするかだけであることを認識することです。 

## アプローチ

 強引な解釈では、縮小する境界を追跡しながら、各秒でどの本を手に取るかについて考えられるすべての選択肢をシミュレートしようとします。 時間 t では、残りの間隔は固定されており、その中の 1 つの要素を選択します。 選択肢の数は現在の間隔サイズに比例するため、分岐係数は N から始まり直線的に減少します。 枝刈りを行ったとしても、各ステップで選択肢間の明確な優劣関係なしに縮小集合から 1 つの要素を選択するため、可能なシーケンスの数は N で指数関数的になります。 

これは、初期段階での決定が、後で選択されるまで高価値の要素が生き残るかどうかに影響を及ぼし、値だけに対する単純な貪欲な順序付けが存在しないため、失敗します。 

重要な観察は、視点を反転することです。 時間の経過とともに短縮される間隔について考える代わりに、各位置に「生存時間」、つまり、燃焼されるまでのステップ数を割り当てます。 両端が対称的に削除されるため、位置 i は、min(i, N - i + 1) 層の燃焼が到達するまで正確に残ります。 つまり、各書籍にはその値に等しい期限があるということです。 毎秒、最大でも 1 冊の本を受け取ることができるため、期限と利益を設定した単位時間の仕事を効果的にスケジュールすることができます。

これにより、問題は古典的な貪欲なスケジューリング問題に帰着します。つまり、各ジョブに期限がある場合、タイムスロットごとに最大 1 つのジョブを選択することで総利益を最大化するというものです。 最適な戦略は、書籍を値の降順に並べ替え、期限を超えない範囲で最新の利用可能なスロットに各書籍を割り当てることです。 

私たちはどのタイムスロットが空いているかを追跡する構造を維持しており、各書籍を値の降順で、まだ占有できる最新の利用可能なスロットに貪欲に配置します。 これにより、価値の高い書籍は、以前の書籍がすでに使用されている場合にのみ、遅いスロットを消費することが保証されます。

 ## アルゴリズムのチュートリアル

 ### 重要なアイデア

 私たちは縮小プロセスを、各ポジションに焼かれる前に生き残るラウンド数に等しい期限を与えるものとして再解釈します。 

### ステップ

 1. 各インデックス i について、火災が到達するまでの層の数として生存限界を計算します。 これは min(i, N - i + 1) です。 

これは、本をまだ手に入れることができる最後の秒を表します。 
2. 各書籍を利益 a[i] と期限 d[i] を持つ仕事として扱います。 

1 秒ごとに 1 つの利用可能なスロットが対応します。 
3. すべての書籍を価値の高い順に並べ替えます。 

一度スロットを取得すると再利用できないため、価値の高い書籍を優先します。 
4. 1 から N までの空きタイム スロットを表す構造、通常は DSU または「次に利用可能なスロット」ジャンプを備えたブール配列を維持します。 
5. ソートされた順序で書籍を繰り返し処理します。 各書籍について、期限以内の最新の利用可能なスロットに配置するようにしてください。 
6. そのようなスロットが存在する場合は、そこに本を割り当て、その値を答えに追加します。 それ以外の場合はスキップしてください。 

### なぜ効果があるのか

 どのような場合でも、両方が可能であれば、書籍を後のスロットに割り当てることは、前のスロットに割り当てるよりも常に優れています。これは、締め切りが厳しい書籍のために前のスロットを保持するためです。 常に高い値を最初に処理することで、書籍をスケジュールできる場合でも、制約が最小限の方法でスケジュールされることが保証されます。 貪欲な交換の議論は、実行可能なスロット内でより低い値の割り当てをより高い値の割り当てと交換しても結果が減少することはないため、合計値を減らすことなく、最適なスケジュールをこの貪欲なスケジュールに変換できることを示しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def find(parent, x):
    if parent[x] != x:
        parent[x] = find(parent, parent[x])
    return parent[x]

def union(parent, x, y):
    parent[x] = y

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    jobs = []
    for i, v in enumerate(a):
        d = min(i + 1, n - i)
        jobs.append((v, d))

    jobs.sort(reverse=True)

    parent = list(range(n + 1))

    def get_slot(x):
        x = find(parent, x)
        return x

    ans = 0

    for v, d in jobs:
        if d <= 0:
            continue
        slot = get_slot(d)
        if slot == 0:
            continue
        ans += v
        parent[slot] = slot - 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、近い方の端までの距離を使用して、各インデックスを期限に変換することから始まります。 これにより、火がその位置に達したときを正確に捉えることができます。 

並べ替えのステップでは、常に価値の高い書籍を最初に配置するように努めます。 それが最も貪欲な優先事項です。 

Union-find 構造は、「次に利用可能なスロット」トラッカーとして使用されます。 スロットを占有するたびに、それを逆方向にマージして、将来のクエリが次の空き位置に効率的にジャンプできるようにします。 これにより、配置ごとに線形にスキャンすることが回避され、ソリューションが O(N) 付近に保たれます。 

微妙な点は、min(i, n - i + 1) の代わりに min(i + 1, n - i) を使用していることです。これは、0 ベースのインデックス付けと 1 ベースのインデックス付けを切り替えることに起因しています。 ロジックは同じであり、最も近い境界までの距離です。

 ## 特殊なケース

 単一要素の配列の場合、期限は 1 で、要素を選択すると常にその要素が取得されます。 アルゴリズムはそれをスロット 1 に直接割り当てるため、答えはまさにその値になります。 

[100, 1, 100, 1, 100, 1] などの高い値と低い値を交互に指定する場合、アルゴリズムにより、低い値がスペースを消費する前に、すべての高い値が最初に使用可能なスロットに配置されます。 各高価値要素には個別のスロットに割り当てるのに十分な期限があるため、最終的な合計にはすべての大きな要素が正しく含まれます。 

すべての値が等しい配列の場合、アルゴリズムは、すべての選択肢が等しいため、最適な動作と一致する、使用可能なタイム スロットの合計に等しいサイズの有効なサブセットを効果的に選択します。
