 ## 解決策
 ## 問題の理解

 1 から N までの数字を一列に並べた順列が与えられます。 目標は、スワップを使用してこの順列を 1 から N のソート順に変換することですが、許可されるスワップには厳密な制限があります。 

交換は、間に 1 人がいる 2 つのポジション間でのみ許可されます。 つまり、位置 i と i+2 を交換することはできますが、隣接する位置や離れた位置を交換することはできません。 各移動では配列の残りの部分が保持され、これら 2 つの要素のみが交換されます。 

タスクは、この制約の下でソートされた順列に到達することが可能かどうかを判断し、到達できる場合は、必要なそのようなスワップの最小数を計算することです。 

N が最大でも 1000 であり、O(N^2) または O(N^3) の解が許容される可能性があることを示唆していますが、制約が十分に厳しいため、任意のシーケンスのスワップや順列にわたる BFS を試行するシミュレーションは実行不可能です。 順列の状態空間は階乗であるため、枝刈りを行っても構成を探索することは不可能です。 

この問題の微妙な点は、スワップ操作がシフトされた方法でインデックス パリティを保持することです。i と i+2 をスワップすると、要素は常に同じパリティ クラスの位置内で移動することになります。 これにより、即時の実現可能性の制約が生じます。 

いくつかの特殊なケースを強調する価値があります。 N = 1 の場合、配列はすでにソートされており、答えは 0 です。 偶数のインデックスにあるはずの要素が奇数のインデックスで始まる場合、すべてのスワップでインデックスのパリティが保持されるため、正しい位置に到達することはできません。 たとえば、N = 3 で配列が [3, 1, 2] の場合、要素 1 はインデックス 2 (偶数) にありますが、並べ替えられた配列では要素 1 はインデックス 1 (奇数) になければなりません。 この不一致により並べ替えが不可能になり、単純なグリーディ スワップ シミュレーションでは、この不変条件違反が認識されずに誤ってスワップが継続される可能性があります。 

## アプローチ

 ブルートフォースの試みでは、並べ替えプロセスを直接シミュレートしようとします。 場違いな要素を繰り返し見つけて、有効なスワップを使用して、場合によっては BFS オーバーミューテーションまたは貪欲なローカル修正を使用して、その要素をターゲット位置に移動しようとすることができます。 これは原理的には正しいです。各スワップは状態空間内の正当な遷移を保持し、最終的には到達可能な構成が見つかる可能性があるからです。 

問題は、順列にわたる単純な BFS でもすぐに爆発してしまうことです。 Nもいるよ！ 各状態の可能なスワップは最大で O(N) 個であるため、検索空間は N = 10^3 であっても実現可能な制限をはるかに超えています。 ポジションを繰り返し修正する貪欲なシミュレーションでも、局所的な改善は独立していないため、循環したり、最適なスワップ数を見つけられなかったりする可能性があります。 

重要な観察は、スワップは 2 異なるインデックスのみを接続するため、配列が 2 つの独立したサブシーケンスに分割されることです。奇数位置の要素と偶数位置の要素は決して相互作用しません。 元の配列の位置 i と i+2 は圧縮パリティ シーケンスの連続する位置に対応するため、各サブシーケンス内で隣接する要素を事実上交換できます。 

これにより、問題は、それぞれ隣接するスワップを使用する、サブシーケンスに関する 2 つの独立した並べ替え問題に縮小されます。 シーケンスをソートするために必要な隣接スワップの最小数は、まさにその反転カウントです。 したがって、両方のサブシーケンスにパリティ クラスに必要な値の正しいマルチセットが正確に含まれている場合、答えは奇数インデックスのサブシーケンスと偶数インデックスのサブシーケンスの反転カウントの合計になります。 

パリティ制約に違反すると、ソートができなくなります。

 ## アルゴリズムのチュートリアル

1. 位置パリティに基づいて配列を 2 つのシーケンスに分割します。1 つはインデックス 1、3、5 の要素を含み、もう 1 つはインデックス 2、4、6 の要素を含みます。これは、スワップによってこれらのグループ間で要素が移動されることがないという事実を反映しています。 
2. 両方のグループに、ソートされた配列内のパリティ位置に正確に正しい要素が含まれていることを確認して、実現可能性を確認します。 奇数インデックス グループには、ソート順で奇数の位置に表示される数値が正確に含まれている必要があり、偶数の位置でも同様です。 この条件が失敗した場合は、-1 を返します。 
3. 各パリティ グループ内で必要なスワップの最小数を個別に計算します。 グループ内で許可される操作は、事実上、その圧縮シーケンス内の隣接する要素を交換することになります。 
4. 各グループについて、反転数を計算します。 各要素について、以前に見た要素がその要素よりも大きいものがいくつあるかを数えます。 このカウントは、バブル ソートの意味でその要素を正しい位置に移動するために必要なスワップの数を表します。 
5. 両方のグループの反転数を合計し、結果を出力します。 

反転カウントが適用される主な理由は、元の配列内の各有効なスワップが、パリティ圧縮された配列の 1 つの隣接する要素のスワップに対応し、隣接するスワップはシーケンスをその反転番号で正確にソートすることが知られているためです。 

### なぜ効果があるのか

 重要な不変条件は、要素がインデックスのパリティを決して変更しないことです。 これにより、順列が相互作用せずに進化する 2 つの独立したシーケンスに分割されます。 各シーケンス内で、許可されたスワップは完全な隣接グラフを形成します。これは、隣接スワップを使用してそのサブシーケンスの任意の順列に到達できることを意味します。 隣接するスワップはすべての順列を生成し、各スワップはちょうど 1 つの反転を修正するため、スワップの最小数はまさに反転カウントになります。 2 つのパリティ シーケンスは独立して進化するため、それらのコストは干渉することなく追加されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def inversion_count(arr):
    n = len(arr)
    inv = 0
    for i in range(n):
        for j in range(i):
            if arr[j] > arr[i]:
                inv += 1
    return inv

n = int(input())
a = list(map(int, input().split()))

odd_pos = []
even_pos = []

for i in range(n):
    if i % 2 == 0:
        odd_pos.append(a[i])
    else:
        even_pos.append(a[i])

target_odd = sorted(range(1, n + 1))[::2]
target_even = sorted(range(1, n + 1))[1::2]

if sorted(odd_pos) != target_odd or sorted(even_pos) != target_even:
    print(-1)
else:
    print(inversion_count(odd_pos) + inversion_count(even_pos))
```コードはまず、インデックスのパリティに基づいて配列を 2 つのシーケンスに分割します。 これは、スワップがこれら 2 つのグループを決して混合しないという構造上の制約と一致します。 次に、ソートされた配列から各パリティ クラスの値の予想されるマルチセットを構築し、それらを実際の内容と比較します。 それらが異なる場合、有効なスワップのシーケンスによって並べ替えを修正することはできません。 

inversion_count 関数は、単純なネストされたループを使用して、各サブシーケンス内の反転の数を計算します。 O(N^2) ですが、N ≤ 1000 であれば十分です。 

最後に、反転カウントの合計がスワップの合計最小数として出力されます。

 ## 特殊なケース

 N = 1 の場合、アルゴリズムは単一要素の奇数サブシーケンスと空の偶数サブシーケンスに分割されます。 どちらの反転カウントもゼロであり、単一の値がすでに存在しているため、実現可能性は自明です。 

入力 [1, 3, 2] などのパリティ不一致の場合、奇数の位置には [1, 2] が含まれますが、N = 3 の予想される奇数セットは [1, 3] です。 不一致があると、反転カウントの前に即座に拒否が引き起こされます。 これにより、到達不可能な構成での計算の無駄が防止されます。 

完全に反転された配列の場合、各パリティ サブシーケンスは減少シーケンスになり、反転カウントは各独立したチェーン内で必要なスワップの最大数を正確に捕捉します。
