 ## 解決策
 ## 問題の理解

 配列が与えられ、隣接するスワップを使用してソートされた配列に変換できるかどうかを尋ねられますが、プロセスが進むにつれてスワップが徐々に難しくなる制約があります。 

この操作は標準のスワップではありません。 プロセス全体の j 番目の交換では、2 つの値のうち小さい方が少なくとも j である場合にのみ、位置 i と i+1 の要素を交換できます。 これは、初期のスワップは許容的ですが、後のスワップでは両方の参加値がますます大きくなる必要があることを意味します。 スワップ数はポジションごとではなくシーケンス全体でグローバルであるため、スワップごとに 1 単位の「許可レベル」が消費されます。 

タスクは、配列を降順でない順序でソートするような一連のスワップが存在するかどうかを判断することです。 

n を 100000 までに制限すると、スワッピング シーケンスのシミュレーションが即座に除外されます。 最適なバブルソートのようなプロセスでさえ、O(n^2) 個のスワップが必要になる可能性があり、各スワップの有効性は、操作のグローバルな順序における位置に依存します。これにより、時間と状態が結合され、直接シミュレーションが不可能になります。 

グローバル・スワップ指数からは微妙な問題が生じます。 単純な解釈では、各位置に独自のしきい値があると誤って仮定する可能性がありますが、j 番目のスワップはプロセス履歴全体に適用されます。 これは局所性を壊し、標準的な貪欲バブル推論を無効にします。 

危険性を明らかにする小さな例は、小さな要素が多数の大きな要素と交差する必要がある配列です。 局所的には各スワップが有効に見えても、蓄積されたスワップ インデックスが最終的に大きくなりすぎて、将来必要なスワップが不可能になります。 

## アプローチ

 この強引なアイデアは、スワップの有効性をチェックしながらバブル ソートをシミュレートすることです。 配列を繰り返しスキャンし、許可されている場合は隣接する反転を交換します。 スワップごとにグローバル カウンタ j がインクリメントされ、min(a[i], a[i+1]) ≥ j であることが検証されます。 

これは原理的には正しいです。スワップの有効なシーケンスは、解決される隣接する反転のシーケンスに対応するからです。 ただし、最悪の場合、ソートには O(n^2) 個のスワップがかかり、各ステップにはスキャンまたは構造の維持が含まれるため、総コストは O(n^2) になります。 n が最大 100000 であるため、これは実現可能な限界をはるかに超えています。 

重要な観察は、視点を逆転させることです。 スワップについて考える代わりに、スワップ インデックスに対するグローバルに増加する制約の下で要素がどのように移動しなければならないかを考えます。 重要な制限は、スワップを実行するたびに、2 つのスワップ値のうち小さい方が少なくともスワップ番号 j でなければならないということです。 これは、スワップのシーケンスの早い段階で小さな値が出現する必要があることを意味します。 そうしないと、j が大きくなるにつれて使用できなくなります。 

次に、並べ替えの観点からプロセスを考えてみましょう。 小さい要素は多くのスワップに関与できません。これは、それらに関与するすべてのスワップがグローバル バジェットの 1 単位を消費するためです。 したがって、各要素には、その値に関連付けられた自然な「移動の予算」があります。要素の値が x の場合、時間 x を超えてスワップに参加することはできません。 これにより、問題は、各要素があまりにも多くのスワップを強制されることなくソートされた位置に到達できるかどうかをチェックすることに変わります。 

最終的な並べ替え順序をシミュレートし、各要素がどこまで移動する必要があるかを追跡することで、これをモデル化できます。 重要な変換は、値がスワップ深さ制約以上である要素のみが必要な反転に参加できることに注意することです。 これにより、フェンウィック ツリーまたは反転スタイルのカウントを使用した貪欲な実現可能性チェックが行われますが、各値が「許容」できる有効なスワップの数についての制約が追加されます。 

これを確認するより簡単な方法は、各要素を正しい位置に移動するために必要なスワップ数を維持しながら、配列を左から右に処理し、この必要なスワップ数が要素の値を超えないようにすることです。 

これにより、問題は制約付き反転距離の実行可能性チェックに変換されます。

 ## アルゴリズムのチュートリアル

 この問題は、ソートされた位置に到達するために参加しなければならないスワップの回数を各要素が「余裕」できるかどうかをチェックするものであると解釈します。 

1. 配列のソートされたバージョンを構築し、ソートされた順序で各値を最終位置にマップします。 これにより、あらゆる出来事が最終的にどこに到達するのかがわかります。 
2. 最終的な配置に関して、現在配置されている要素の数が大きくなるか小さくなるかを計算できる構造を維持しながら、配列を走査します。 
3. 要素ごとに、ソートされた順序に対してその要素が寄与する反転の数を計算します。 これは、実際に参加する必要があるスワップの数を表します。 
4. 各要素の反転要件がその値を超えているかどうかを確認します。 そうなった場合、要素はその値より大きい時間 j で強制的にスワップされ、最小制約に違反します。 
5. すべての要素がこの実現可能性条件を満たしている場合は YES を出力し、そうでない場合は NO を出力します。 

重要な考え方は、各反転が最終的に発生する 1 つのスワップに対応し、グローバル スワップ インデックスが単調増加するということです。 値 x を持つ要素は x を超えるスワップに耐えられないため、x を超える反転負荷は不可能であることを意味します。 

### なぜ効果があるのか

 隣接スワップのプロセスでは、反転を一度に 1 つずつ解決することで配列を変換します。 各反転解像度は、その反転内の小さい要素が関与する少なくとも 1 つのスワップに対応します。 スワップ番号 j は j ≤ min(a[i], a[i+1]) を満たす必要があるため、反転の最小要素は、その反転が解決されるまでの時間を制限します。 

したがって、すべての要素は、スワップの小さい側として参加できる反転の回数に厳しい制限を課します。 必要な数がその値を超える場合、スワップの順序付けによってグローバル制約への違反を回避することはできません。 したがって、インバージョン会計では、プロセスをシミュレートすることなく、必要なスワップ債務をすべて取得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        vals = sorted(set(a))
        comp = {v: i + 1 for i, v in enumerate(vals)}

        bit = BIT(len(vals))
        inv = [0] * n

        # count how many greater elements appear before each position
        for i in range(n):
            x = comp[a[i]]
            inv[i] = i - bit.sum(x)
            bit.add(x, 1)

        # now check feasibility via reverse pass
        bit = BIT(len(vals))
        for i in range(n - 1, -1, -1):
            x = comp[a[i]]
            greater_on_right = bit.sum(len(vals)) - bit.sum(x)
            if greater_on_right > a[i]:
                print("NO")
                break
            bit.add(x, 1)
        else:
            print("YES")

if __name__ == "__main__":
    solve()
```反転をカウントする際には相対的な順序のみが重要となるため、このソリューションでは値が圧縮されます。 フェンウィック ツリーは、反転関連のカウントを効率的に計算するために使用されます。 

順方向パスでは周波数情報が構築されますが、重要なチェックは逆方向パスで行われます。要素ごとに、その右側に大きい要素がいくつあるかを数えます。 この数は、左方向に何回スワップする必要があるかに対応します。 これが要素の値を超えると、スワップ シーケンスで十分長く存続できなくなります。 

状態はトラバース中に厳密にチェックされます。 違反した場合は直ちに拒否します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict
    import sys
    input = sys.stdin.readline

    class BIT:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)

        def add(self, i, v):
            while i <= self.n:
                self.bit[i] += v
                i += i & -i

        def sum(self, i):
            s = 0
            while i > 0:
                s += self.bit[i]
                i -= i & -i
            return s

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))
            vals = sorted(set(a))
            comp = {v: i + 1 for i, v in enumerate(vals)}
            bit = BIT(len(vals))

            ok = True
            for i in range(n):
                x = comp[a[i]]
                bit.add(x, 1)

            bit = BIT(len(vals))
            for i in range(n - 1, -1, -1):
                x = comp[a[i]]
                greater = bit.sum(len(vals)) - bit.sum(x)
                if greater > a[i]:
                    ok = False
                    break
                bit.add(x, 1)

            out.append("YES" if ok else "NO")
        return "\n".join(out)

    return solve()

## 特殊なケース

 重要なエッジケースは、すべての値が等しい場合です。 この状況では、min(a[i], a[i+1]) は常に n までのスワップ インデックスにのみ等しく、順序付けの制約が存在しないため、すべてのスワップは常に有効です。 どの要素も厳密にそれより大きい要素と交差する必要がないため、アルゴリズムは正しく YES を返します。 

最小の要素が配列の終わりに近い場合、別のエッジ ケースが発生します。 この要素は必要なスワップを多数蓄積しますが、その値が小さいため、すぐに制約に違反します。 逆パス チェックは、その右側にある大きな要素の数を数えることによって、これを即座に捕捉します。 

3 番目のエッジ ケースは、厳密に減少する配列です。 すべての要素は、それ自体よりも小さいすべての要素と交差する必要があり、最小の要素が最大の負担を蓄積します。 アルゴリズムは、その負担が要素の値を超えるとすぐに拒否され、必要なスワップ シーケンスを維持することが不可能になります。
