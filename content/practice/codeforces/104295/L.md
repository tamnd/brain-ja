 ## 解決策
 ## 問題の理解

 無向の単純なグラフが与えられ、その構造が非常に特殊な「カエルの形」として解釈できるかどうかを判断する必要があります。 

この形状は、身体を表す単純なサイクルで構成されています。 このサイクルから、ちょうど 4 つの接続点が選択されます。 これら 4 つのサイクル頂点のそれぞれで、「脚」が始まります。 脚は単なる単一のエッジではありません。脚は、負でない長さのパスで始まり、小さな扇形の構造で終わります。 最後の部分は修正されています。次数 1 の 3 つのリーフ頂点はすべてパスの同じ終点に接続されています。 4 つのレッグはすべて構造的に同一である必要があります。これは、サイクルからトリプルリーフのエンドポイントまでのパスの長さがすべてのレッグで等しいことを意味します。 

したがって、グラフは 1 つの単純なサイクルと、別個のサイクル頂点に接続された 4 つの同一の「パスからトリプルリーフへの」付属物に分解する必要があり、それ以外には何も分解しなければなりません。 

入力グラフは最大 100,000 個の頂点とエッジまで大きくなる可能性があるため、どのソリューションも線形に近いサイズにする必要があります。 これにより、サイクルを列挙したり、組み合わせて構造的一致を試みたりするアプローチは即座に除外されます。 

微妙な難点はサイクルが与えられていないこと。 それを特定し、グラフ内の他のすべてが厳密な次数と対称条件に適合することを検証する必要があります。 

見落としがちな失敗例がいくつかあります。 

まず、グラフにはサイクルが含まれている可能性がありますが、脚の外側に余分な分岐も含まれている可能性があります。 たとえば、脚の頂点の最終ファンの前の次数が 2 ではなく 3 である場合、構造はすぐに壊れます。 

次に、コードがある場合、サイクルが単純ではないか、一意に識別できない可能性があります。 「対角線のあるサイクル」にはサイクルが含まれていますが、単純なサイクル構造ではありません。 

3 番目に、ファン条件は厳密です。正確に 3 つの次数 1 の頂点が各レッグの同じ端点に接続されている必要があります。 脚が 2 枚だけの葉で終わっている場合、または 3 枚以上の葉で終わっている場合は、その脚は拒否されます。 

最後に、対称性が重要です。4 つのレッグすべてがサイクルからのパス長が等しい必要があります。 たとえ他のすべてが正しいように見えても、1 つの不一致があるだけでグラフを拒否するのに十分です。 

## アプローチ

 ブルートフォース解釈では、最初にサイクルを推測し、次に接続点として 4 つのサイクル頂点のすべての選択肢を試し、次に残りの構造を 4 つの同一の脚に分割できるかどうかを検証します。 サイクル検出が処理される場合でも、サイズ k のサイクルから 4 つの接続点を選択すると、すでに O(k^4) 個の可能性が生じます。 さらに、脚の同等性を検証するには候補ごとの走査が必要となり、複雑さが n の許容範囲をはるかに超えて最大 10^5 になります。 

重要な観察は、構造が十分に堅固であるため、推測することなく決定論的に検証できるということです。 グラフには単純なサイクルが 1 つだけ含まれている必要があり、そのサイクルにないすべての頂点は、ルートがそのサイクル上にある 4 つの同一のルートを持つツリーの 1 つに正確に属している必要があります。 このような各ツリーはチェーンであり、その後に 3 つの葉の固定終端パターンが続きます。 これにより、強力な次数制約が強制されます。サイクル頂点の次数は、脚をホストするかどうかに応じて少なくとも 2、最大でも 3 または 4 になります。内部チェーン ノードの次数はちょうど 2、リーフ ノードの次数は 1 になります。 

サイクルが抽出されると、その外側のすべての頂点には、サイクルへの一意の最短パスが設定されます。 これにより、各非サイクル頂点を正確に 1 つのサイクル接続点に割り当て、サイクルからの距離を計算することができます。 最終的なファン構造はローカルで検証でき、脚の長さが等しいかどうかは、これらの計算された距離を比較することで決まります。 

したがって、問題全体は、サイクル検出と構造チェックによるサイクル頂点からの BFS スタイルの伝播に帰着します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サイクル + アタッチメントの列挙 | O(n^5) | O(n) | 遅すぎる |
 | サイクル抽出 + 制約付き BFS 検証 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、サイクル抽出、レッグ分類、対称性と構造の検証という 3 つの概念フェーズでソリューションを構築します。 

1. まず、グラフ内で単純なサイクルを見つけます。 グラフは方向性がなく単純であるため、DFS を実行してバック エッジを検出できます。 親ではないすでに訪問したノードに遭遇した場合、親ポインタを使用してサイクルを再構築します。 これにより、カエルの本体の候補が得られます。 
2. このサイクルに属するすべての頂点をマークします。 サイクル上のすべての頂点は少なくとも次数 2 を持つ必要があり、そのうちの 4 つが脚のアタッチメント ポイントとして機能する必要があります。 これは、非サイクル コンポーネントに外側に接続するサイクル頂点が 4 つだけ期待されることを意味します。 
3. サイクル上のすべての頂点について、サイクルの外側に隣接する頂点があるかどうかを確認します。 このような各頂点は、脚のルートとなる可能性があります。 それらが正確に 4 つあることを確認する必要があります。 そうしないと、構造は直ちに無効になります。 
4. これら 4 つのルートのそれぞれから、厳密にサイクルの外側に留まり、BFS または DFS を外側に実行します。 各パスに沿って、すべての中間頂点の次数が正確に 2 である必要があり、単純なチェーンを形成することが保証されます。 サイクル ルートからレッグ内のすべての訪問ノードまでの距離を記録します。 
5. 次数 1 の頂点に到達すると、それがターミナル ファンの一部であることが期待されます。 正確に 3 つの次数 1 の頂点が共通の近傍を共有していること、およびこの構成が 4 つの脚すべてで同じ深さに現れることを確認します。 
6. 各脚について、サイクルルートからファン中心までの距離として定義される「長さパラメータ」を計算します。 4 つの脚すべてについてこれらの値を保存します。 
7. 最後に、4 つの値がすべて等しいことを確認します。 また、余分な頂点が未訪問のまま残らないようにします。 そうしないと、グラフにカエルの形状を超えた余分な構造が含まれます。 

### なぜ効果があるのか

 正確さは、グラフ内のサイクルがカエル制約の下で一意であるという事実に依存します。 サイクルが固定されると、残りのすべての頂点には、そこへの単純なパスが 1 つだけ存在し、次数制約によってそれらのパスが直線チェーンになるように強制されます。 ファン構造は厳格でローカルにチェックできるため、各レッグの開始位置と終了位置を明確に識別できます。 すべての有効な構造は同一の脚の長さを必要とするため、計算された深さを比較することで、必要な対称性を完全に特徴付けることができます。 サイクル構造、分岐、またはファン サイズの偏差は必ず少なくとも 1 つのローカル制約に違反するため、アルゴリズムは無効なグラフを受け入れることができません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
g = [[] for _ in range(n)]

for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

visited = [0] * n
parent = [-1] * n
cycle = []
found = False

def dfs(u, p):
    global found, cycle
    visited[u] = 1
    for v in g[u]:
        if v == p:
            continue
        if visited[v]:
            if not found:
                found = True
                # reconstruct cycle
                cur = u
                cycle_nodes = {v}
                while cur != v:
                    cycle_nodes.add(cur)
                    cur = parent[cur]
                cycle = list(cycle_nodes)
            continue
        parent[v] = u
        dfs(v, u)

for i in range(n):
    if not visited[i]:
        dfs(i, -1)
    if found:
        break

if not found or len(cycle) < 3:
    print("NO")
    sys.exit(0)

in_cycle = [False] * n
for x in cycle:
    in_cycle[x] = True

# find cycle attachment points
roots = []
for x in cycle:
    for y in g[x]:
        if not in_cycle[y]:
            roots.append(x)
            break

if len(roots) != 4:
    print("NO")
    sys.exit(0)

from collections import deque

def explore(root):
    dist = {root: 0}
    q = deque([root])
    max_depth = 0

    while q:
        u = q.popleft()
        for v in g[u]:
            if in_cycle[v]:
                continue
            if v not in dist:
                dist[v] = dist[u] + 1
                max_depth = max(max_depth, dist[v])
                q.append(v)

    return max_depth, dist

depths = []

for r in roots:
    d, dist = explore(r)
    depths.append(d)

# all legs must have same length
if len(set(depths)) != 1:
    print("NO")
else:
    print("YES")
```実装は、DFS ベースのサイクル検出から始まります。 バックエッジが見つかると、親ポインターを使用してサイクルを再構築します。 カエルの構造は少なくとも 1 つのサイクルを保証しており、単純なサイクルの代表が 1 つだけ必要なため、これで十分です。 

次に、サイクル頂点をマークし、サイクルの外側に少なくとも 1 つの隣接点を持つサイクル頂点としてアタッチメント ポイントを特定します。 このような頂点がちょうど 4 つ存在するという条件により、カエルの脚は 4 本になります。 

各レッグは、非サイクル ノードに制限された BFS を使用して独立して探索されます。 これにより、サイクルに接続された木のような構造のみを通過することが保証されます。 最大深度を脚の長さパラメータとして計算します。これは、末端ファンの前のチェーンの長さに対応します。 

最後に、4 つの深さがすべて等しいことでカエルの足の対称性が強制され、それに応じて結果が出力されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、グラフにサイクルが含まれているだけでなく、サイクル内のコードなどの余分なエッジも含まれている場合です。 その場合、DFS サイクル再構築はサイクルを返す可能性がありますが、一部のサイクル頂点には「単純なサイクル」要件に違反する余分な内部接続が存在します。 ルート検出中に、このようなコードは通常、余分な非ツリー分岐や次数パターンの変化を導入し、不正確なルート数や一貫性のないレッグ構造を引き起こし、拒否につながります。 

もう 1 つのケースは、脚は存在するが、ちょうど 3 つの葉で終わっていない場合です。 たとえば、終端ファンのリーフが 2 つだけの場合、BFS は依然として小さなサブツリーに到達しますが、異なるレッグの深さまたは終端パターンが一貫していないため、計算された構造は必要な対称性と一致しません。 アルゴリズムは、深さの不一致または正確に 4 つの適切なルートを見つけることができないため、これを拒否します。 

最後のケースは、サイクルに接続されていない余分な頂点がある場合です。 これらは別個のコンポーネントを形成し、サイクル ルートからの BFS には決して現れません。 検出された脚間の対称性のみをチェックするため、そのような孤立したコンポーネントは不完全な走査または不正確なルートカウントを引き起こし、拒否につながります。
