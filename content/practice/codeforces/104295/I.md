 ## 解決策
 ## 問題の理解

 長い 3 レーンのトラックを移動するランナーが与えられます。各行は時間のステップであり、3 つの列はそれぞれ 1 つのレーンを表します。 各セルは空、コイン、障害物、またはトランポリンのいずれかです。 ランナーは中央レーンの1列目からスタートします。 目標は、できるだけ多くのコインを集めながら、最後の行の任意のセルに到達することです。 

動きはトラックの構造によって制限されます。 通常のセルから、ランナーは次の行に移動します。 各ステップで、ランナーは同じレーンに留まるか、隣のレーンに移動し、中央のレーンでは両側への移行が可能になります。 次の行の移動先のセルが障害物である場合、その移動は禁止されます。 現在のセルがトランポリンの場合、ランナーは有効なレーン調整を選択したまま 1 列ではなく 2 列前進し、障害物ではないセルに着地する必要があります。 コインは、ランナーがコインを含むセルに着地した場合にのみ収集されます。 トランポリンを介してコインを通過しても、コインは収集されません。 

入力サイズでは最大 100,000 行が許可されるため、パスを明示的に列挙しようとするソリューションは直ちに除外されます。 レーンが 3 つしかない場合でも、分岐パスを使用して各行を個別に扱う単純なグラフ トラバーサルは、慎重に構造化されていない限り、深さが指数関数的に爆発的に増加します。 行に対する線形または線形に近い動的プログラミングが必要です。 

微妙なエッジケースは、トランポリンが列をスキップすることから発生します。 スキップされた行にコインが配置されている場合、コインは収集されません。そのため、スキップされた中間セルを考慮せずに移動を単純に「同じ遷移を持つ +2 行」として扱うと、誤った過大カウントにつながります。 もう 1 つの失敗ケースは、行内のすべてのセルが障害物である場合です。 たとえば、「###」のような行では、前の状態に関係なく続行できなくなります。 このような場合、前の行が到達可能であっても、正解は -1 になります。 

## アプローチ

 ブルートフォース解釈では、ゲームを状態空間グラフとして扱い、各状態は (行、レーン) によって定義されます。 各状態から次の行に移行したり、トランポリンの上に立っている場合は 1 行スキップしたりすることができます。 各トランジションは最大 3 つのレーン選択肢に分岐します。 これにより、行ごとに最大 3 の分岐係数と最大 100,000 の深さが作成されます。 障害物による枝刈りを無視しても、指数関数的な数のパスが生成され、実行不可能になります。 

重要な観察点は、グラフの行順序が非循環であり、遷移は前方にのみ進むということです。 これは、行を昇順に処理し、各レーンでその状態に到達したときに達成可能な最高のスコアを維持できることを意味します。 レーンが 3 つしかないため、各行は状態ごとに一定量の計算のみを必要とします。 トランポリンは 2 段階の依存関係を導入しますが、DP 更新で慎重に処理された場合には、既に順番に計算されている将来の状態にのみ依存します。 

各セルをノードとして扱い、そのセルに到達したときに収集された最大コインを表す DP 値を計算できます。 トランポリンの場合、遷移は前の行またはその前の行にのみ依存します。 これにより、指数関数的な分岐が行ごとに一定サイズの遷移システムに折りたたまれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^n) | O(n) | 遅すぎる |
 | 最適なDP | O(n) | O(1) または O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 dp[r][c] を行 r と列 c に到着したときに収集されるコインの最大数として定義します。 到達不可能な状態は負の無限大です。 

また、トランポリンも考慮する必要があるため、前のセルがトランポリンかどうかに応じて、r-1 または r-2 から遷移する可能性があります。

1. すべての dp 値を負の無限大に初期化します。 最初の行の中央から開始するため、dp[1][1] を 0 に設定します。 そのセルにコインが含まれている場合は、すぐにコインを追加します。 
2. 1 から n までの行を昇順に処理します。 各行は、将来の行への遷移のソースとして使用されます。 
3. 各セル (r、c) について、dp[r][c] に到達できない場合は、有効なパスがこの状態に到達しないため、スキップします。 
4. 通常のセル (「.」または「o」) から、行 r+1 への遷移を試みます。 範囲内に留まり、ターゲット セルが障害物にならない限り、すべての有効なレーン c-1、c、c+1 への移動を試みます。 各トランジションは、dp[r+1][nc] を dp[r][c] に加えてコイン (存在する場合) で更新します。 
5. トランポリン セル ('^') から、r+1 ではなく r+2 行への遷移を試みます。これにより、境界や障害物の影響を受けながら、-1、0、+1 のレーン シフトが可能になります。 dp[r+2][nc]も同様に更新します。 
6. すべての状態を処理した後、答えはすべての dp[n][c] の最大値になります。 すべてに到達できない場合は、-1 を返します。 

重要な考え方は、各状態は時間的に前方にのみ伝播し、レーンが 3 つしかないため、各状態の拡張は継続的な作業であるということです。 

### なぜ効果があるのか

 任意の行 r で、dp[r][c] には、その状態に到達するすべての有効なパスの中で可能な最良のコイン カウントがすでに格納されています。 すべての遷移は行インデックス内で厳密に前方に移動するため、後の更新で以前の状態を遡って改善することはできません。 すべての有効なパスは、dp 遷移の 1 つのシーケンスに正確に対応し、アルゴリズムは重複することなくそのようなすべての遷移を探索します。 トランポリン ルールは 2 ステップ先の状態を転送することによって処理されます。これにより、中間のスキップされたセルが着地のスコアや有効性に影響を与えることができないため、正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

NEG = -10**18

n = int(input())
grid = [None] * (n + 3)

for i in range(1, n + 1):
    grid[i] = list(input().strip())

dp = [[NEG] * 3 for _ in range(n + 3)]

# start at (1, 1) which is middle lane (index 1)
start = 1
if grid[1][start] == '#':
    print(-1)
    sys.exit()

dp[1][start] = 1 if grid[1][start] == 'o' else 0

for r in range(1, n + 1):
    for c in range(3):
        if dp[r][c] == NEG:
            continue

        cell = grid[r][c]

        if cell == '.':
            step = 1
        elif cell == 'o':
            step = 1
        elif cell == '^':
            step = 2
        else:
            continue

        nr = r + step
        if nr > n:
            continue

        for dc in (-1, 0, 1):
            nc = c + dc
            if nc < 0 or nc >= 3:
                continue
            if grid[nr][nc] == '#':
                continue

            val = dp[r][c]
            if grid[nr][nc] == 'o':
                val += 1

            if val > dp[nr][nc]:
                dp[nr][nc] = val

ans = max(dp[n])
print(ans if ans > NEG else -1)
```この実装では完全な DP テーブルが保持されますが、前方遷移のみが使用されるため、各状態は 1 回処理されます。 ステップ サイズは現在のセルに依存し、別のロジック層を必要とせずにトランポリンを明確にモデル化します。 

唯一の微妙な点は、コインの収集が目的のセルでのみ行われ、中間のスキップされたセルでは決して行われないことです。 トランジションはランディング行に直接ジャンプするため、これは当然尊重されます。 

## 実用的な例

 ### 例 1

 入力:```
#.#
##o
#o#
o##
#o#
```1列目中央レーンからスタートします。 空なので dp[1][1] = 0 となります。 

| 行 | 状態の更新 |
 | --- | --- |
 | 1 | (1,1)=0 |
 | 2 | 障害物のため、ほとんどの車線からは到達できません。 
| 3 | 有効な遷移のみが形成を開始します。 
| 4 | 最適なパスが伝播する |
 | 5 | 計算された最終的な到達可能な状態 |

 有効なパスは障害物を避けるためにレーンを縫う必要があり、DP はコインが存在する列 3 と 5 に着地した場合にのみコインを蓄積します。 最終的な答えは、行 5 の到達可能な最大 dp 値に対応します。 

これにより、すべての無効な遷移が自然にブロックされるため、車線切り替えと障害物フィルタリングが正しく適用されていることを確認できます。 

### 例 2

 入力:```
#.#
ooo
ooo
ooo
ooo
#^#
###
o..
...
```(1,1) から始めます。 列 2 と列 3 では、中央のレーンでコインを集める簡単な移動が可能です。 行 5 のトランポリンに到達すると、状態は行 7 にジャンプします。 

| ステップ | ポジション | コイン |
 | --- | --- | --- |
 | 1 | (1,1) | 0 |
 | 2 | (2,1) | 1 |
 | 3 | (3,1) | 2 |
 | 4 | (4,1) | 3 |
 | 5 | (5,1 '^') | 3 |
 | 6 | (7,0) | 4 |

 このトレースは、重要なトランポリンの動作を示しています。行 6 は完全にスキップされるため、そこにあるコインはカウントされず、ジャンプが収集をバイパスするルールと一致します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | n 行のそれぞれは最大 3 つの状態を処理し、それぞれ最大 9 つの遷移に拡張されます。 
| スペース | O(n) | DP テーブルは行ごとに 3 つの値を格納します。 

定数係数が小さく、セルごとの演算が最小限であるため、線形の複雑さは 100,000 行の制約内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    NEG = -10**18
    n = int(input())
    grid = [None] * (n + 3)
    for i in range(1, n + 1):
        grid[i] = list(input().strip())

    dp = [[NEG] * 3 for _ in range(n + 3)]

    start = 1
    if grid[1][start] == '#':
        return "-1\n"

    dp[1][start] = 1 if grid[1][start] == 'o' else 0

    for r in range(1, n + 1):
        for c in range(3):
            if dp[r][c] == NEG:
                continue
            cell = grid[r][c]
            step = 2 if cell == '^' else 1
            nr = r + step
            if nr > n:
                continue
            for dc in (-1, 0, 1):
                nc = c + dc
                if 0 <= nc < 3 and grid[nr][nc] != '#':
                    val = dp[r][c] + (1 if grid[nr][nc] == 'o' else 0)
                    dp[nr][nc] = max(dp[nr][nc], val)

    ans = max(dp[n])
    return str(ans if ans > NEG else -1) + "\n"

## 特殊なケース

 重要なエッジ ケースは完全なブロッキング行です。 入力の場合:```
#.#
###
#.#
```DP は行 1 から行 2 に到達しますが、行 2 のすべてのセルが無効であるため、遷移は伝播しません。 行 1 を超えるすべての dp 状態は到達不可能なままであり、最終的な最大値は負の無限大となり、-1 が生成されます。 すべての遷移では dp を更新する前に障害物がないかチェックするため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、トランポリンが境界車線に着地する場合です。 例えば：```
#.#
.o.
#^#
.o.
```トランポリンが行 3 にある場合、有効な遷移は行 5 のみです。到達可能な唯一の着陸レーンがブロックされている場合、その状態からのすべての遷移は破棄されます。 DP は無効なものをフィルタリングすることでこれを保証します。`nc`更新前にセルを妨害し、不法な「強制」着陸を防ぎます。 

最後の微妙なケースは、トランポリンがコインの上を飛び越える場合です。 DP は目的のセルにコインを追加するだけなので、行 r から r+2 にジャンプするときに行 r+1 のコインはカウントされません。 これはルールに正確に一致し、スキップされた行のコインを合計するというよくある間違いを回避します。
