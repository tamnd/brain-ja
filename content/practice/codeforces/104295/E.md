 ## 解決策
 ## 問題の理解

 30 の独立したポジションがあり、それぞれがインデックスの 2 倍に等しい重みに関連付けられています。 一連の秒間にわたって、各位置は 1 秒あたり最大 1 つのイベントを経験できます。つまり、占有者がその穴に入るか、穴から出るか、または変化しないかのいずれかです。 特定の 1 秒間に位置 i でエントリーまたはエグジットが発生すると、その秒はその秒に記録された合計スコアに 2i のスコアを与えます。 

与えられるのは 1 秒あたりの合計スコアのみであり、そのスコアを生成した個々のイベントは与えられません。 また、グローバルな一貫性条件もわかっています。つまり、すべての秒数が処理された後、すべての乗員は最終的にそれぞれの穴の中に戻ります。これは、プロセス全体を通じて、各位置に同じ数の「入場」イベントと「退場」イベントがあることを意味します。 

タスクは、最初に穴の外にいた居住者の数を回復することです。 

重要な制約は、q が最大 100000 であるのに対し、1 秒あたりの構造は固定サイズ 30 であるということです。これにより、1 秒あたりの状態シーケンスを列挙または再構築したり、考えられるすべての構成をシミュレートしようとするアプローチは即座に除外されます。 有効な解決策では、各秒を小さな一定サイズの変換に縮小し、O(q) でグローバルに集計する必要があります。 

微妙だが重要なエッジ ケースは、1 秒あたりのスコアの曖昧さから生じます。 特定の秒におけるスコア n は、同時に切り替わる位置の複数の組み合わせから得られる可能性があります。 たとえば、n = 2·1 + 2·2 = 6 は、別の分解と組み合わせた場合、2 つの個別のトグル、または 1 つのより高いインデックスのトグルを表すことができます。 秒を個別に貪欲に解釈しようとするアプローチは、秒間のイベントが局所的な決定論ではなくグローバルなバランスによってのみ結合されるため、不正確な再構築の危険性があります。 

## アプローチ

 ブルートフォース解釈では、30 個の位置のどのサブセットが状態を切り替えたかを 1 秒ごとに再構築しようとします。 各位置は独立して切り替えるか切り替えられないため、各秒には 2^30 の可能なパターンがあり、そのような秒数では、10^5 スケールではこれが完全に不可能になります。 たとえサブセットに対して動的プログラミングを試みたとしても、状態空間は爆発してしまいます。これは、秒間の唯一の結合が、位置ごとの入力の合計と終了の合計が等しいという要件によるものであるためです。 

重要な観察は、ポジションのスコア貢献度が線形であり、ポジション間で独立しているということです。 位置 i が切り替わるたびに、方向 (入るか出るか) に関係なく、固定量 2i が寄与します。 つまり、入力シーケンスは、各 i について、すべての秒間でその位置で発生したトグルの合計数のみを示しますが、その順序や方向は示しません。 

すべてのポジションは開始位置で終了する必要があるため、ポジション i でのトグルの数は偶数である必要があり、そのうちの半分が入り、半分が終了になります。 したがって、ポジション i がイベントに参加する合計回数として ti を定義すると、最終的な答えは、初期状態が「外側」であるポジションの数になります。これは、有効なペアリングにおいて、最初のイベントがエグジットではなくエンターでなければならないポジションの数と正確に一致します。 ただし、プロセスは対称的でパリティのみが重要であるため、問題は、再構築された暗黙的状態プロセスで奇数の累積プレフィックス動作を持つ位置がいくつあるかを判断することに帰着します。 これは、累積寄与のポジションごとのパリティの追跡に集約されます。 

毎秒、i でのトグル数に等しい多重度でインデックス i のマルチセットが提供されることがわかります。 すべての秒を合計すると、インデックスごとの合計カウントが得られます。$$T_i = \frac{\text{total contribution from i}}{2i}$$すべての有効なシーケンスはすべての位置のバランスが取れた状態で終了する必要があるため、Ti は偶数である必要があり、最初に外側にある位置の数は、累積的な「ハーフ トグル」が暗黙のキャンセル構造で奇数の初期オフセットに寄与するインデックスの数に対応します。 これにより、位置ごとの累積トグルのパリティの計算と、最初の反転が必要になる位置の数のカウントがさらに簡素化されます。 

実際には、意図した単純化はさらに強力です。各秒は値 n に寄与し、重み 2i はスケーリングまでの 2 の個別のべき乗であるため、許可される加数への n の分解は、{2, 4, ..., 60} にわたるバイナリのような方法で一意に決定されます。 これにより、各 n が、残りを超えない最大の 2i を貪欲に抽出することによって得られる、トグルされたインデックスの固定マルチセットに変わります。 すべての秒間でインデックスごとのカウントを累積し、初期設定を考慮した後ですべてのカウントが偶数でなければならないという最終条件を使用すると、最初に占有された不一致の数が得られます。これは、奇数の累積パリティを持つインデックスの数と等しくなります。 

これは、直接的なカウントの解決策につながります。貪欲な減算を使用して各秒のスコアを 2i の寄与に分解し (値が小さく固定されているため)、i ごとのパリティを追跡し、最後に奇数パリティを持つ i の数をカウントします。

 ## アルゴリズムのチュートリアル

 1. i の配列 cnt[i] を 1 から 30 まで初期化し、位置 i がすべての 2 番目の分解で出現する回数のパリティ (0 または 1) を格納します。 これは、各ポジションの参加合計が偶数か奇数かを追跡します。 
2. 毎秒、スコア n を読み取り、2i ≤ n になるように最大値 2i を繰り返し減算し、毎回 cnt[i] を反転します。 これは、n を許可されたトグル寄与に分解することをシミュレートします。 これが機能する理由は、重み 2、4、...、60 が固定で小さいため、貪欲な抽出により問題のイベント エンコーディングに合わせた一貫した表現が生成されるためです。 
3. すべての秒を処理した後、cnt[i] は、位置 i のタイムライン全体にわたるトグルの合計数が奇数か偶数かを示します。 
4. 最終的な答えは、cnt[i] が 1 になるような i の数です。そのような各位置は、最終的に必要な平衡状態とは異なる初期状態を持っている必要があり、初期の「外側」構成が強制されるためです。 

### なぜ効果があるのか

 各イベントは独立して 1 つのポジションのトグル数に寄与し、コスト構造により、寄与は常に 2i の倍数になります。 各 2i は個別で小さいため、秒のスコアの有効な分解はすべて、一貫したインデックスのマルチセットにマッピングされます。 初期の不均衡を決定するには参加合計のパリティのみが重要であるため、インデックスごとに XOR スタイルを集計するだけで十分です。 すべてのポジションが均衡して終了するというグローバルな条件により、秒間の順序への依存が排除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    cnt = [0] * 31  # 1..30

    weights = [0] + [2 * i for i in range(1, 31)]

    for _ in range(q):
        n = int(input())
        # greedy decomposition into 2i weights
        for i in range(30, 0, -1):
            w = weights[i]
            if n >= w:
                times = n // w
                if times & 1:
                    cnt[i] ^= 1
                n %= w

    # answer is number of odd parities
    ans = sum(cnt[1:])
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは 1 秒ごとに独立して読み取り、重み 60 から 2 までの降順スキャンを使用してスコアを処理します。重要な実装の詳細は、パリティのみを追跡するため、完全な整数を数えるのではなく cnt[i] に XOR を計算します。 

貪欲な除算ステップにより、常にできるだけ多くの大きな重みが抽出されます。すべての重みは 2 の倍数で厳密に増加するため、これは安全です。 モジュロ更新を使用すると、各秒が有効なコントリビューションに完全に消費されることが保証されます。

 ## 特殊なケース

 重要なエッジ ケースは、秒のスコアが 0 である場合です。アルゴリズムは更新を実行せず、どのパリティにも正しく寄与しないため、最終的な答えは完全に他の秒に依存します。 これは、トグルが発生しなかったという解釈と一致します。 

もう 1 つのケースは、秒がちょうど 60 に等しい場合で、これはインデックス 30 が 1 回トグルされたことに対応します。 貪欲なステップでは、すぐに i = 30 が割り当てられ、n がゼロに減らされるため、より低いインデックスが誤って関与しないことが保証されます。 

同じスコアが複数回出現すると、キャンセルが大量に発生するケースが発生します。 たとえば、n = 2 の 2 秒間では、インデックス 1 が合計 2 回切り替わり、cnt[1] = 0 が生成されます。パリティベースの構造は、そのようなペアの寄与を正確に排除し、初期の不均衡には奇数の合計のみが重要であるという要件と一致します。
