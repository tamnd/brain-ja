 ## 解決策
 ## 問題の理解

 塔の高さのコレクションが与えられています。 がある$n$塔、どこ$n$は奇数であることが保証されており、各タワーはある程度の初期高さを持っています。 私たちにも与えられています$k$追加のユニットキューブ。 各キューブを正確に 1 つのタワーに追加して、高さを 1 つ増やすことができます。 

全部配布したら$k$任意の方法でキューブを作成すると、最終的な構成は非降順でソートされます。 ソート後の完全な配列には興味がなく、中央値の要素のみに興味があります。$\frac{n+1}{2}$- 番目に小さい高さ。 私たちの目標は、$k$この中央値ができるだけ大きくなるように立方体化します。 

重要な問題は、1 つのタワーにキューブを追加すると、ソート後にそのタワーが中央値の位置よりも下になるか上になるかによって、中央値に影響を与える場合と与えない場合があるということです。 ソートは最後に適用されるため、タワーの ID は重要ではなく、最終的な値のマルチセットのみが重要になります。 

制約は大きいです:$n$最大300,000まで可能です$k$まで$10^9$したがって、キューブの配置を段階的にシミュレートしたり、並べ替えを繰り返したりするソリューションは、直ちに不可能になります。 一度の並べ替えは問題ありませんが、中央値を動的に繰り返し調整および再評価しようとすると失敗します。 

微妙なエッジケースが現れるのは、$k = 0$。 次に、単純に元の配列の中央値を返すだけですが、このような些細なケースでも、推論は一般的な方法と一致する必要があります。 

もう 1 つの重要なエッジ ケースは、中央境界付近で多くの値が等しい場合です。 素朴な直感は「中央値のタワーを直接上げる」ことを試みるかもしれませんが、並べ替えはすべての操作の後に行われるため、十分な要素が持ち上げられない限り、1 つの要素を増やしても実際に中央値の位置が改善されることはなく、その要素を他の要素の上に押し出すだけになる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、$k$あらゆる方法で立方体を作成し、並べ替えた後に結果の中央値を計算します。 それぞれの増分で考えて離散化しても、$n$タワー、これは配布に相当します$k$同一のアイテムを$n$バケットには、$\binom{k+n-1}{n-1}$可能性。 これは小さな値であっても天文学的に増加し、完全に実行不可能です。 

もう少し構造化された強引なアイデアは、貪欲な割り当てを試すことです。つまり、中央値を増やすのに現在最も有益と思われる立方体をタワーに繰り返し追加します。 問題は、中央値がグローバルな順序に依存するため、ローカルでの貪欲な選択では、将来の変更後にどの要素が中央値の位置になるかを確実に追跡できないことです。 

重要な観察は、個々のタワーの追跡をやめ、代わりにしきい値に焦点を当てることです。 目標の高さを推測するとします$x$中央値の場合。 問題は、塔の少なくとも半分が最終的に少なくとも高さになるようにできるかどうかです。$x$? できれば、$x$並べ替え後の中央値として取得できます。 

このチェックを効率的に行うために、初期の高さが以下のすべてのタワーが存在することに注意してください。$x$少なくとも次の水準まで引き上げる必要がある$x$、そのような各タワーにはキューブ単位で明確に定義されたコストがあります。 すでにタワー以上の高さ$x$キューブを消費せずに中央値条件を満たすことに自然に貢献します。 

これにより問題は、しきい値の大きさを決定することになります。$x$限られた予算でサポートできます$k$増加します。 実現可能性は単調なので、$x$、答えを二分探索できます。

 ## アルゴリズムのチュートリアル

 ランクに関する推論が安定するように配列をソートします。 目標の中央位置を次のようにします$mid = \frac{n}{2}$0 から始まる用語で。 

次に、答えを二分探索します$x$少なくとも中央値を達成できるかどうかを確認します$x$。 

1. 高さの配列を並べ替えます。 ID を追跡せずに、しきい値の下または上に要素がいくつあるかを推論できるようにするために、並べ替えが必要です。 
2. 関数を定義する`can(x)`中央値が少なくとも次の値になることが可能かどうかを決定します。$x$。 
3. 内部`can(x)`、すべてのタワーを反復処理し、以下の高さのすべてのタワーを持ち上げるのに必要な立方体の数を計算します。$x$まで$x$。 このような高さのある塔ごとに$a[i] < x$、私たちは蓄積します$x - a[i]$。 
4. 合計金額を超える場合$k$、すぐに false を返します。 これは、最適な分布を考慮する前でさえ、中央値のしきい値を確保するのに十分な質量を持ち上げることができないためです。 
5. 合計金額が以内の場合$k$、 true を返します。これは、塔の少なくとも半分を強制的に高さに到達させることができることを意味します。$x$以上で、中央値の状態が保証されます。 
6.二分探索をします$x$可能な最小の高さから可能な最大の高さまでの範囲にプラス$k$, すべてのキューブが関連するタワーに配置されている場合、中央値は超えることができないためです。 
7. 最終的な答えが最大です$x$誰のために`can(x)`それは本当です。 

### なぜ効果があるのか

 正しさは、中央値の条件が、要素の同一性ではなく、特定の値以上である要素の数のみに依存するという事実に基づいています。 候補が決まったら$x$、以下の塔のいずれか$x$上半分に寄与させたい場合は、それに到達するまで増加する必要があります。 すでに上にあるタワーでキューブを消費する$x$～の実現可能性のためには決して必要ではない$x$、それらはすでに制約を満たしているためです。 

これにより、少なくとも中央値を達成できれば、単調な実現可能性構造が作成されます。$x$なら、どんなことも達成できます$y < x$必要なコストは、しきい値が減少するにつれて減少するだけであるためです。 この単調性こそが、二分探索を有効なものにしているのです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))
a.sort()

mid = n // 2

def can(x):
    need = 0
    for i in range(n):
        if a[i] < x:
            need += x - a[i]
            if need > k:
                return False
    return True

lo, hi = min(a), max(a) + k

while lo < hi:
    mid_val = (lo + hi + 1) // 2
    if can(mid_val):
        lo = mid_val
    else:
        hi = mid_val - 1

print(lo)
```実装は、高さを順番に処理できるように配列をソートすることから始まりますが、実現可能性チェック自体はソート後の位置の更新に依存しません。 

の`can(x)`関数は、以下のすべての要素を引き上げるのに必要なキューブの合計数を計算します。$x$まで$x$。 早期退場時`need > k`特に次のような場合には、効率化に不可欠です。$k$大きいです。 

二分探索ではアッパーミッドバイアスを使用します`(lo + hi + 1) // 2`上向きに収束するときに無限ループを避けるため。 検索スペースは安全に境界が定められています。`max(a) + k`すべてのキューブを 1 つのタワーに配置すると、どの要素も最大で 1 つ増加する可能性があるためです。$k$。 

## 実用的な例

 ### 例 1

 入力:```

```ソートされた配列:`[1, 2, 2, 3, 5]`、中央値のインデックスは 2 (0 からインデックス化) です。 

実現可能性をテストします。 

| × | x に到達するまでのコスト | 缶(x) |
 | --- | --- | --- |
 | 2 | (1→2)=1 | はい |
 | 3 | (1→3)=2 + (2→3)=1 + (2→3)=1 = 4 | いいえ |

 実現可能な最大値は 2 です。 

これは、追加の立方体がなければ、中央値を初期値を超えて上昇させるのに十分な質量を押し込むことができないことを示しています。

 入力:```

| × | 費用 | 実現可能 |

これは、中央値を改善するには、1 つだけではなく複数の要素を同時に引き上げるのに十分な予算が必要であることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    def can(x):
        need = 0
        for v in a:
            if v < x:
                need += x - v
                if need > k:
                    return False
        return True

    lo, hi = min(a), max(a) + k
    while lo < hi:
        mid = (lo + hi + 1) // 2
        if can(mid):
            lo = mid
        else:
            hi = mid - 1
    return str(lo)

# provided samples
assert run("5 0\n1 3 2 5 2\n") == "2"
assert run("5 3\n1 5 2 2 3\n") == "2"

# minimum case
assert run("1 10\n5\n") == "15"

# all equal
assert run("5 4\n2 2 2 2 2\n") == "3"

# large k on skewed array
assert run("3 100\n1 1 1\n") == "34"

# no improvement possible
assert run("3 0\n10 1 2\n") == "1"

 ## 特殊なケース

 のために$n = 1$、中央値が唯一の要素であるため、すべての立方体が答えを直接増加させます。 実現可能性チェックは単純に蓄積されるため、アルゴリズムがこれを処理します。$k$単一の値に変換すると、二分探索は次の値に達します。$a[0] + k$。 

すべての要素が同一の場合、中央値は、少なくとも半分のキューブがしきい値を超えるのに十分なキューブが存在する場合にのみ増加します。 以下のすべての要素のコストが請求されるため、実現可能性関数はこれを正確に反映します。$x$1 つの要素だけを持ち上げるだけでは決して十分ではありません。 

いつ$k = 0$、二分探索は元の中央値に崩壊します。 の値がないので、$x$中央値を超える場合は、検索により、特別なケースを使用せずに、ソートされた中央の要素が自然に返されます。
