 ## 解決策
 ## 問題の理解

 ラテン語の小文字のグリッドとして表される長方形の壁が与えられています。$n$行と$m$列。 このグリッド内に固定サイズの正方形のフレームを配置します。$k \times k$。 フレームを配置するたびにサブグリッドが選択され、選択した正方形内に「花」という単語が完全に出現する回数を数えることに興味があります。 通常、出現箇所は 4 つの主な方向 (水平方向の左から右、垂直方向の上から下、またはコンテストの規約に応じて他の標準的な直線の解釈。ここで意図されている読み方は、グリッド内の通常の連続する直線の一致です) のいずれかで単語を形成する一連の文字として解釈されます。 

すべての有効なポジションの中で、$k \times k$正方形の場合、そのような出現が最大数含まれる正方形を選択する必要があります。 複数の位置が同じ最大値に達する場合は、列インデックスが最も小さいものが優先され、まだ同点である場合は行インデックスが最も小さいものが優先されます。 

グリッド サイズは大きく、両方の次元で最大 35,000 ですが、追加の制約があります$n \cdot m \le 10^7$。 これは、どの解もグリッド サイズが線形または線形に近いものでなければならず、正方形ごとの再計算は不可能であることを強く示唆しています。$O(nm)$可能な正方形の配置。 

素朴なアプローチでは、それぞれの場合、$k \times k$ウィンドウですべてのセルをスキャンし、単語の出現数を数えてみます。 水平一致だけを効率的にチェックしたとしても、コストはかかります$O(nmk^2)$最悪の場合、限界をはるかに超えます。 

より微妙な故障モードは、重複カウントや重複の欠落によって発生します。 たとえば、次のような行です。```
flowersflowers
```2 つの出現は重なり合い、各ウィンドウ内で単純に文字列をスキャンすると、重なり合う四角形全体で同じ一致が繰り返し再計算され、境界条件が誤って処理された場合、非効率性と間違いの両方が発生します。 

もう 1 つの微妙なエッジケースはタイブレークです。 複数の最適な正方形が存在する場合、問題は最初に列、次に行ごとに辞書編集上の最小位置を強制します。 更新を慎重に順序付けせずに最大数のみを追跡するソリューションでは、有効ではあるが最適ではない結合の選択が簡単に出力される可能性があります。 

## アプローチ

 強引なアイデアは簡単です。すべてのスライドをスライドさせます。$k \times k$グリッド上の四角形を配置し、各四角形内で「花」の出現をすべて数えます。 出現箇所を長さ 7 の水平部分文字列として解釈すると、単一の正方形内ですべての行をスキャンし、すべての開始位置をチェックできます。 つまり$O(k^2)$1平方あたりに約$O(nm)$正方形、与える$O(nmk^2)$。 と$k$35,000 までは、縮小した形であってもこれは不可能です。 

重要な観察は、実際には正方形ごとのパターン マッチを再計算する必要がないということです。 「花」の出現はそれぞれ、その開始セルによって決まります。 すべての出現がグリッド内のどこから始まるのかがわかれば、各正方形はその中にそれらの開始点がいくつあるかを知るだけで済みます。 これにより、問題は 2D 範囲カウント問題に変換されます。 

バイナリ グリッドを前処理します。各セルは、「花」の発生がそこから始まる場合は 1、それ以外の場合は 0 になります。すると、タスクは次のようになります。$k \times k$サブグリッド内の値の合計を計算し、最適なものを選択します。 これは古典的な 2D プレフィックス合計アプリケーションであり、各クエリは次のように応答されます。$O(1)$前処理後。 

境界の調整には引き続き注意する必要があります。$(i, j)$完全に内側にあります$k \times k$正方形の左上隅がグリッド内に完全な単語を保持できる範囲内にある場合にのみ、正方形になります。 ただし、開始位置のみをカウントしているため、オカレンスは既にグリッドに完全に含まれていると暗黙的に想定されます。これは、有効な開始位置のみをマークするため安全です。 

したがって、解決策は、出現グリッド上でプレフィックスの合計を構築し、考えられるすべての左上の位置をスキャンすることになります。

 ## アルゴリズムのチュートリアル

 ### 1. 出現する単語をすべて検出する

 すべての行をスキャンし、考えられるすべての開始列をチェックします$j$部分文字列「flowers」の場合。 一致するたびに、別のグリッドに 1 をマークします。$(i, j)$。 

このステップにより、パターン検索がウィンドウ集約から分離され、これにより、さまざまな四角形にわたる情報の再利用が可能になります。 

### 2. マークされたグリッド上で 2D プレフィックス合計を構築します。 

任意の四角形の合計を定数時間で計算できるように、プレフィックス合計配列を構築します。 これにより、繰り返されるカウント クエリが O(1) オペレーションに変換されます。 

### 3. をスライドさせます。$k \times k$すべての有効な位置を正方形にします

 左上のすべての位置について$(i, j)$、接頭辞の合計の式を使用して、正方形内のマークされた出現の数を計算します。 

### 4. タイブレークで最良の回答を追跡する

 これまでに確認された最高のカウントと座標を維持しています。 更新するときは、まずカウントを比較し、次に列、次に行を比較します。 これにより、辞書編集上の正確さが保証されます。 

### なぜ効果があるのか

 単語の有効な出現はすべて、マークされたグリッド内で 1 回だけ表されます。 すべての正方形は、開始点がその中にある出現を正確にカウントします。 接頭辞の合計は正確な四角形の合計を計算するため、各四角形のスコアは正確です。 すべての正方形が評価されるため、最大値が見つかり、決定的なタイブレークによって一意の正解が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m, k = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    word = "flowers"
    L = len(word)

    occ = [[0] * m for _ in range(n)]

    for i in range(n):
        row = grid[i]
        for j in range(m - L + 1):
            if row[j:j+L] == word:
                occ[i][j] = 1

    pref = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(n):
        for j in range(m):
            pref[i+1][j+1] = (
                occ[i][j]
                + pref[i][j+1]
                + pref[i+1][j]
                - pref[i][j]
            )

    def get_sum(x1, y1, x2, y2):
        return (
            pref[x2][y2]
            - pref[x1][y2]
            - pref[x2][y1]
            + pref[x1][y1]
        )

    best = -1
    best_i = 0
    best_j = 0

    for i in range(n - k + 1):
        for j in range(m - k + 1):
            val = get_sum(i, j, i + k, j + k)
            if val > best or (val == best and (j < best_j or (j == best_j and i < best_i))):
                best = val
                best_i = i
                best_j = j

    print(best_i + 1, best_j + 1)

if __name__ == "__main__":
    main()
```最初のループでは、パターン「flowers」の有効な開始位置をすべて抽出します。 これにより、ウィンドウ評価中に同じ部分文字列を繰り返しスキャンすることが回避されます。 プレフィックス合計の構造は、標準の 2D 累積合計の考え方を拡張して、サブスクエアを定数時間で評価できるようにします。 

機能`get_sum`プレフィックス グリッド上の包含/除外をエンコードします。 負のインデックスを付けずに境界がきれいに機能するように、インデックスを 1 つシフトすることが重要です。 

最後のネストされたループは、可能なすべての配置を列挙します。$k \times k$四角。 比較ロジックは、タイブレーク ルールを直接エンコードします。最初にカウントを最大化し、次に列インデックスを最小化し、次に行インデックスを最小化します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m, k = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    word = "flowers"
    L = len(word)

    occ = [[0] * m for _ in range(n)]
    for i in range(n):
        for j in range(m - L + 1):
            if grid[i][j:j+L] == word:
                occ[i][j] = 1

    pref = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(n):
        for j in range(m):
            pref[i+1][j+1] = occ[i][j] + pref[i][j+1] + pref[i+1][j] - pref[i][j]

    def get(i1, j1, i2, j2):
        return pref[i2][j2] - pref[i1][j2] - pref[i2][j1] + pref[i1][j1]

    best = -1
    bi = bj = 0
    for i in range(n - k + 1):
        for j in range(m - k + 1):
            v = get(i, j, i + k, j + k)
            if v > best or (v == best and (j < bj or (j == bj and i < bi))):
                best = v
                bi, bj = i, j

    return f"{bi+1} {bj+1}"

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、グリッド内のどこにも「花」が存在しない場合です。 その状況では、どのマス目もスコアが 0 になります。 アルゴリズムは最良のスコアを -1 として初期化するため、処理された最初の正方形が答えになります。 列、行の順にスキャンするため、選択された位置は (1, 1) となり、必要なタイブレーク ルールと一致します。 

もう 1 つの特殊なケースは、単一の行内でオカレンスが重なり合う場合です。 たとえば、「flowersflowers」のような行は、2 つの隣接する有効な開始位置を生成します。 プレフィックス合計グリッドにより、両方が独立してカウントされることが保証され、$k \times k$それらをカバーするウィンドウは、重複することなく正しく集約されます。 

3 番目のエッジケースは次のような場合です。$k = 1$。 この場合、すべての正方形が 1 つのセルとなり、アルゴリズムは最も多くの出現を開始するセルを選択することになります。 オカレンスは有効なインデックスでのみ開始されるため、プレフィックスの合計は引き続き正しく動作し、タイブレーク ルールによりすべての等しいセルが決定的に解決されます。
