 ## 解決策
 ## 問題の理解

 従業員の予定されている出張のリストが渡されました。 各旅行は連続した日数の間隔を占め、都市を指定します。 重要な問題は、これらの間隔が異なる都市で重複する可能性があり、重複が発生するたびに、従業員は同じ日に複数の都市にいることが暗黙的に要求されることですが、これは不可能です。 このタスクは、異なる都市に属する少なくとも 2 つの重複する間隔によって影響を受ける暦日を数えることです。 

入力は、各間隔の開始日によってすでにソートされています。これは強力な構造上のヒントです。重複は、順番に前方にスキャンし、進行中の旅行のアクティブなセットを維持することによってのみ発見できます。 

制約は最大 100,000 間隔、日の値は最大 10 億です。 これにより、毎日をシミュレートしたり、明示的なタイムライン配列を構築したりするアプローチは除外されます。 単純な 1 日あたりのシミュレーションでは、最大 10^9 の操作が必要になりますが、これは実行可能な制限をはるかに超えています。 間隔ごとのペアごとの比較でも、最悪の場合は 10^10 の演算が行われる可能性があります。 

複数の間隔が長い期間にわたって重なっているが、日を部分的にしか共有していない場合、微妙なエッジ ケースが発生します。 たとえば、次のことを考えてみましょう。```
1 10 1
2 3 2
4 5 3
```正解は 0 です。2 日は、重複構造を超えて異なる都市間で同時に共有されません。 任意の間隔のペア間のすべての重複を単にカウントする単純なアプローチでは、競合日の結合を正確に追跡せずに、誤って過大にカウントされる可能性があります。 

複数の区間が同じ範囲を共有しているが都市が異なる場合、別のエッジ ケースが発生します。```
1 5 1
1 5 2
1 5 3
```1 から 5 までの毎日は無効ですが、個別の日を数えるのではなく、誤ってペアごとの重複を複数回数えてしまう可能性があります。 

## アプローチ

 ブルートフォース手法では、間隔のすべてのペアを比較し、それらの交差を計算します。 各ペアについて、都市が異なるかどうか、およびそれらの間隔が重複しているかどうかを確認し、重複するセグメントを不良日のグローバル セットに追加します。 概念的には単純ですが、このアプローチは O(N^2) ペアのチェックを必要とし、それぞれが長い間隔のマージを生成する可能性があるため、機能しません。 N が 10^5 までになると、これは不可能になります。 

重要な観察は、問題は基本的に、各時点でアクティブな都市がいくつ存在するかを追跡することにあるということです。 間隔をペアごとに比較する代わりに、すべての間隔境界をタイムライン上のイベントとして処理できます。 各間隔は、開始日に +1 イベント、終了日に -1 イベントに 1 を加えたものになります。 ただし、都市を区別する必要があるため、アクティブな間隔を単にカウントするだけではなく、常にアクティブな個別の都市の数を追跡する必要があります。 

これにより、問題は、アクティブな都市の頻度マップを維持する圧縮されたイベント上のスイープ ラインに変換されます。 連続するイベント ポイント間の任意のセグメントで、個別にアクティブな都市の数が少なくとも 2 つある場合、そのセグメント内のすべての日は無効となり、カウントする必要があります。 

これにより、日ごとのシミュレーションが回避され、問題がイベント ポイントの並べ替えとリニア スキャンに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースペアワイズ | O(N^2) | O(N) | 遅すぎる |
 | イベントのあるスイープライン | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各間隔を 2 つのイベントに変換します。都市がアクティブになる d1 の開始イベントと、都市が非アクティブになる d2 + 1 の終了イベントです。 これにより、毎日が一貫してハーフオープン形式で表現されるようになり、セグメントを結合する際の 1 つずつのあいまいさが回避されます。 
2. すべてのイベントを収集し、日ごとに並べ替えます。 変更を時系列で処理することによってのみ重複を検出できるため、並べ替えが必要になります。 
3. アクティブな都市の頻度カウンターと、現在アクティブな個別の都市の数を追跡する変数を初期化します。 
4. 並べ替えられたイベントを順番に確認します。 連続する 2 つのイベント日の間で、アクティブ セットが一定である日のセグメントを考慮します。 
5. セグメントの開始時にアクティブな都市の数が少なくとも 2 である場合、そのセグメント内の毎日が答えに寄与するため、セグメントの長さを結果に追加します。 
6. 頻度マップを更新して、当日のすべてのイベントを処理します。開始イベントの場合は増分、終了イベントの場合は減分します。 都市のカウントがゼロに低下すると、その都市はアクティブ セットから削除され、それに応じて個別のカウントが更新されます。 
7. すべてのイベントが処理されるまで続行し、最終的に累積された回答が重複するすべての期間を反映していることを確認します。 

### なぜ効果があるのか

 アルゴリズムは、どの時点でも、その日の間隔をカバーする都市の正確なセットを維持します。 このセットはイベントの境界でのみ変更されるため、連続する 2 つのイベント日の間ではセットは一定です。 したがって、このアルゴリズムは問題を、状態が変化しない独立した時間セグメントに分割します。 毎日はそのセグメントの状態を継承し、すべてのセグメントが 1 回だけカウントされるため、正しく分類されます。 これにより、二重カウントやオーバーラップの見逃しがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    events = []
    
    for _ in range(n):
        l, r, c = map(int, input().split())
        events.append((l, c, 1))
        events.append((r + 1, c, -1))
    
    events.sort()

    from collections import defaultdict
    freq = defaultdict(int)
    active = 0

    ans = 0
    i = 0
    m = len(events)

    while i < m:
        day = events[i][0]

        if i > 0:
            prev_day = events[i - 1][0]
            if active >= 2:
                ans += day - prev_day

        while i < m and events[i][0] == day:
            _, city, typ = events[i]
            if typ == 1:
                if freq[city] == 0:
                    active += 1
                freq[city] += 1
            else:
                freq[city] -= 1
                if freq[city] == 0:
                    active -= 1
            i += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、並べ替えられたイベントに対して標準のスイープ ライン パターンを使用します。 各間隔は 2 つの境界更新に寄与し、これによりイベント ポイント間のアクティブ状態が明確に定義されます。 の`freq`ディクショナリは都市ごとの多重度を追跡します。これは、同じ都市からの重複する複数の間隔が 1 つのアクティブな都市としてカウントされるためです。 

の`active`counter は、現在活動している個別の都市の数を追跡します。 これは重要です。都市の代わりに間隔をカウントすると、同じ都市への複数の旅行が競合として誤って扱われてしまいます。 

セグメント貢献度`day - prev_day`が有効なのは、2 つのイベント日の間でアクティブ状態が変化しないため、その間隔内の毎日は重複ステータスの点で同一であるためです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    def solve():
        n = int(input())
        events = []
        for _ in range(n):
            l, r, c = map(int, input().split())
            events.append((l, c, 1))
            events.append((r + 1, c, -1))

        events.sort()
        freq = defaultdict(int)
        active = 0
        ans = 0
        i = 0
        m = len(events)

        while i < m:
            day = events[i][0]
            if i > 0:
                prev_day = events[i - 1][0]
                if active >= 2:
                    ans += day - prev_day

            while i < m and events[i][0] == day:
                _, city, typ = events[i]
                if typ == 1:
                    if freq[city] == 0:
                        active += 1
                    freq[city] += 1
                else:
                    freq[city] -= 1
                    if freq[city] == 0:
                        active -= 1
                i += 1

        return str(ans)

    return solve()

 ## 特殊なケース

 微妙なケースの 1 つは、同じ都市からの複数の区間が互いに重なる場合です。 周波数マップは、都市が 0 から 1 つのアクティブな間隔に移行するときにのみアクティブな都市の数を増加させるため、アルゴリズムはこれを正しく処理します。 例えば：```
1 5 1
2 4 1
1 5 2
```都市1は2回出現しても1回としてカウントされます。`active`。 都市 2 が都市 1 と全体的に重なっているため、スイープ ラインは 1 日目から 5 日目までを競合していると正確に識別しますが、単一の都市内での重複によって競合数が増加することはありません。 

もう 1 つの特殊なケースは、間隔が連続した日に終了および開始される場合です。 使用する`r + 1`終了イベントにより、日の境界が一貫して処理されることが保証されるためです。 このシフトがなければ、間隔は次のようになります`[1,2]`そして`[2,3]`イベントベースの表現では、2 日目に重複して表示される問題がありました。
