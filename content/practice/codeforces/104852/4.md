 ## 解決策
 ## 問題の理解

 単一の非負の整数が与えられます$n$、そして、非負の整数の順序のないペアがいくつあるかを数えるように求められます。$(a, b)$満足する$a + b = n$、特別な制限の下で: 両方$a$そして$b$きっと「楽しい」はずです。 

数値を 10 進数形式で記述したときに、最大 2 桁の異なる数字が使用される場合、その数値は fun と呼ばれます。 たとえば、555 は 1 桁のみを使用するため有効であり、272772 は桁 {2, 7} を使用するため有効であり、100 は桁 {1, 0} を使用するため有効です。 123 のような数字は、3 つの異なる数字を使用するため面白くありません。 

出力は、次の表現をカウントするものではありません。$n$位置的な意味ではありますが、10 進構造がこの桁制限を満たす実際の整数のペアを数えることについてです。 2 つのペアは、順序が異なるだけであれば同じとみなされます。$(a, b)$そして$(b, a)$は一つとして扱われます。 

制約$n \le 10^9$これは、最大 10 桁の長さの値を処理していることを意味します。 これにより、すべてのペアを試行するアプローチは直ちに除外されます。$n$、次のオーダーが必要になるため、$10^{18}$操作。 すべての分解を反復しても、$n$不可能です。 代わりに、このような整数の数は列挙するには十分小さいため、楽しい数値のセット自体の構造を活用する必要があります。 

微妙なエッジケースは、ゼロの処理です。 数字の 0 は楽しいですが、次のようなペアを数えるときは慎重に扱う必要があります。$(0, n)$、特に次のような場合に$n = 0$、 どこ$(0,0)$正確に 1 回カウントする必要があります。 もう 1 つの特殊なケースは、楽しい数値を作成する際の先行ゼロです。これは、数値のゼロ自体を除いて許可されません。 先行ゼロを自由に使用できる単純な数字構築アプローチでは、1 を表す 01 や 001 などの無効な重複が生成されます。 

## アプローチ

 問題を直接解釈すると、すべてのペアを反復処理することが示唆されます。$(a, b)$そのような$a + b = n$、両方楽しいかどうかを確認します。 これには反復処理が必要になります$a$0から$n$、すでに到達しています$10^9$、各値について、数字をスキャンして面白いかどうかを確認します。 たとえ高速な桁チェックを行ったとしても、これは実現不可能です。 

重要な観察は、次の値までのすべての整数は必要ないということです。$n$、楽しい数字のサブセットのみ。 最大 2 桁の異なる数字を持つ数値は高度に構造化されており、最大 2 桁を選択し、それらを最大 10 桁に配置することで決定されます。$n \le 10^9$）。 これにより、検索スペースが大幅に制限されます。 

合計する数値のペアを反復する代わりに、$n$、最初に楽しい数値の完全なセットを生成します。$n$。 数字のペアの選択ごとに、有効な文字列の数は最大でも次のとおりであるため、このセットは小さくなります。$2^{10}$、順序のない数字のペアは 55 個だけです。 このセットを構築した後、メンバーシップを高速にテストできるようにハッシュ セットに保存します。 次に、楽しい数字ごとに$a$かどうかを確認します。$n - a$も楽しいです。 二重カウントを避けるため、以下の場合のみカウントします。$a \le n - a$。 

これにより、問題は膨大な数値範囲の検索から大まかな反復処理に変わります。$O(10^4 \sim 10^5)$候補者たち。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 全てにおいてブルートフォース$a$|$O(n \log n)$|$O(1)$| 遅すぎる |

 ここ$S$は最大の楽しい数字の数です$10^9$、快適に扱えるほど小さいです。 

## アルゴリズムのチュートリアル

 ソリューションは 2 つのフェーズで構築されます。つまり、すべての楽しい数値の生成と、それに続く有効なペアのカウントです。 

1. 順序付けされていないすべての数字のペアを反復処理します。$(d_1, d_2)$、各桁の範囲は 0 ～ 9 です。これには大文字と小文字が含まれます。$d_1 = d_2$、1 桁のみを使用して数値を表します。 
2. 各桁のペアについて、これらの桁のみを使用して、1 から 10 までの長さのすべての可能な数値を生成します。 それぞれのポジションはどちらかです$d_1$または$d_2$。 これにより作成されるのは、最大でも$2^{10}$ペアごとの候補者。 数値自体が正確にゼロでない限り、先頭にゼロがある数値はスキップされます。 
3. 生成された各数値は、その数字形式から整数に変換され、セットに格納されます。 これにより、異なる構造が同じ整数を生成する場合の重複が排除されます。 
4. 生成後、必要に応じて、次の値を超える数値を除外します。$n$、有効な金額に参加できないためです。 
5. すべての楽しい数字を繰り返します$a$セットで。 それぞれについて$a$、計算します$b = n - a$。 
6. もし$b$セット内に存在しており、$a \le b$、これを 1 つの有効な順序なし表現としてカウントします。 
7. 最終的なカウントを出力します。 

### なぜ効果があるのか

 すべての有効なペア$(a, b)$は 2 つの楽しい数値で構成されている必要があるため、両方の要素が生成されたセット内に存在する必要があります。 すべての楽しい数値を 1 回だけ列挙し、ハッシュ セットを使用して補数をテストするため、すべての有効なペアがカウントされます。 条件$a \le b$順序のない各ペアが正確に 1 回カウントされるようにし、対称ペアからの重複を防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def generate_fun(limit):
    fun = set()

    digits = list(range(10))

    for d1 in digits:
        for d2 in digits:
            # generate all strings of length 1 to 10
            stack = [("", 0)]
            while stack:
                s, length = stack.pop()
                if 1 <= length <= 10:
                    # skip leading zeros unless single digit 0
                    if not (s[0] == '0' and len(s) > 1):
                        val = int(s)
                        if val <= limit:
                            fun.add(val)
                if length == 10:
                    continue
                for d in (d1, d2):
                    stack.append((s + str(d), length + 1))

    return fun

def solve():
    n = int(input().strip())

    fun = generate_fun(n)

    ans = 0
    for a in fun:
        b = n - a
        if b in fun and a <= b:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```生成フェーズでは、桁が選択したペアに制限されているすべての数値を構築し、長さ 10 まで拡張します。`limit`を超えて不必要な値を保存することを回避します。$n$、セットをコンパクトに保ちます。 

カウントフェーズは、直接的なハッシュベースの補数検索です。 順序付けの制約`a <= b`ソートや追加の簿記を必要とせずに、順序付けされていないペアの一意性を強制します。

 ## 特殊なケース

 重要なケースの 1 つは、$n = 0$。 唯一の有効な表現は、$(0,0)$。 0 は楽しいセットに含まれており、アルゴリズムはこれを自然に処理します。$0 - 0 = 0$で1回カウントされます$a \le b$ルール。 

もう 1 つの微妙なケースは、小さい値など、有効な補数が多数繰り返される数値です。$n$どちらも$a$そして$n-a$多くの人にとって楽しいです$a$。 順序付け条件により、反復中に両方の方向が出現しても、どちらか一方のみがカウントされることが保証されます。 

先頭のゼロの処理は生成中に解決されます。「01」のような文字列は整数に変換されないため、異なる数字パスから生成された 1 などの重複によってセットが不正に拡張されることはありません。
