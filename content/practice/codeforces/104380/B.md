 ## 解決策
 ## 問題の理解

 長方形のグリッドが与えられ、各セルには、そのセルの周囲の特定の近傍にどれだけの地雷が存在するかを示す数値が含まれています。 近傍とは、セル自体だけでなく、角や端でセルに接するすべてのセルも含み、そのセルを中心とする 3 × 3 のブロックを形成します。 したがって、各値は事実上、周囲の 8 セルにある地雷の数にそれ自体を加えたものになります。 

追加の構造上の制約があります。グリッドの外側の境界には地雷が存在しません。 これが重要なのは、すべての有効な鉱山が完全にグリッド内に完全に定義された 3 x 3 の近傍を持つことを保証するためです。そのため、すべての鉱山が一貫したパターンで正確に 9 個のセルのカウントに寄与します。 

タスクは、すべての鉱山の正確な座標を再構築し、行ごと、列ごとに並べ替えて出力することです。 

この制約では、最大 1,000 行と列、つまり最大 100 万個のセルが許可されます。 状態空間はセルの数において指数関数的であるため、考えられるすべての鉱山構成をテストしようとするソリューションは直ちに不可能です。 セルごとの 2 次アプローチでも遅すぎるリスクがあるため、線形または線形に近い再構成戦略を探しています。 

微妙な点は、鉱山のバイナリ グリッド上の 1 の固定 3 x 3 カーネルによるローカル畳み込みとして数値を解釈することから生じます。 これは、各地雷が正確に 9 つのセルに +1 を寄与し、重複する寄与が合計されることを意味します。 

セルの値が地雷かどうかに直接対応すると仮定すると、素朴な落とし穴が生じます。 たとえば、4 とラベル付けされたセルは、それが地雷であるかどうかを意味するものではなく、周囲の地雷を反映しているだけです。 もう 1 つの失敗モードは、重複する近傍間の一貫性を強制せずに貪欲な推論を試みることで、矛盾が生じます。 

小さな混乱の例としては、(2,2) にある単一の地雷があります。 3 x 3 の近傍にあるすべてのセルが 1 になります。代わりに、セルごとに個別に地雷を推測した場合、9 つのセルすべてが誤って地雷としてマークされ、ひどく過大カウントされてしまいます。 

## アプローチ

 強引なアイデアは、各セルを独立して扱い、それに関係するすべての制約をチェックすることによって、それが地雷であるかどうかを推定しようとすることです。 セルが地雷であると想定し、そのセルが接触する 3 × 3 の近傍すべてからその影響を差し引いて、すべての数値が満たされるまで再帰的に継続してみることもできます。 これはすぐに後戻りや制約を満たす問題に変わります。 最悪の場合、約 100 万個のセルのそれぞれが地雷であるかそうでないかの可能性があり、2^(mn) 個の状態が発生します。 枝刈りを行ったとしても、制約が重なり合っているため、これを実現できるほど分岐係数は減少しません。 

重要な観察は、問題の構造が線形であるということです。 各鉱山は正確に 9 つのセルに影響を与え、各セルの値は近くの鉱山からの貢献の合計です。 これはグリッド上の固定線形システムですが、さらに重要なのは、決定論的な左から右、上から下のスイープで局所的に解決できることです。 

重要なアイデアは、ある位置に地雷が存在するかどうかを判断するときに、すでに処理されたセルに対する将来の寄与がすべてすでに決定されている順序でグリッドを処理することです。 行ごとにトラバースする場合、(i, j) での現在残っている必要な寄与に基づいて (i, j) での決定を「修正」できます。これは、(i, j) に影響を与える可能性のある将来の地雷は 3 行 3 列の近傍内に存在する必要があり、境界地雷なし制約と処理順序により、それらの将来の位置が一貫した方法で制御されるためです。

私たちは、各セルで満たす必要のある貢献の数を表す作業グリッドを維持します。 (i, j) に地雷を配置すると決めた場合、その 3 × 3 の近傍にあるすべてのセルから 1 を減算します。 地雷を設置しなければ、私たちは何もしません。 この正しさは、(i, j) に到達した時点で、まだ影響を受ける可能性がある上または左のすべてのセルがすでに確定されているという事実から得られます。 

これにより、問題は局所修正を伴う貪欲な再構築に帰着します。

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取り、残りの必要な貢献を表す可変配列として保存します。 このグリッドは、将来の決定によって説明が必要な内容を常に反映するように、地雷を設置すると更新されます。 
2. 境界セルには地雷が含まれていないことが保証されているため、境界セルをスキップして、グリッドを上から下、左から右に移動します。 この順序により、セルを決定するときに、そのセルに影響を与えた以前のすべての相互作用がすでに解決されていることが保証されます。 
3. 各セル (i, j) で、そのセルの現在の残りの値が 0 より大きいかどうかを確認します。 ゼロの場合、残りの制約では地雷を必要としないため、ここに地雷を設置することは正当化できません。そのため、先に進みます。 
4. 値が正の場合、(i, j) に地雷を配置します。 これは、各機雷がこのセルに正確に 1 ユニットを提供することを尊重しながら、この位置での残りの要件を削減する、局所的に一貫した唯一の方法です。 
5. 地雷を配置した後、(i, j) を中心とする 3 × 3 の近傍内のすべてのセルから 1 を減算します。 これは、影響を受けるすべてのセルに対する地雷の影響をモデル化し、残りの必要な寄与を更新します。 
6. すべての有効な内部セルが処理されるまでスイープを続けます。 地雷が設置された位置が最終的な答えとなります。 

重要な不変条件は、セル (i, j) を処理する前に、以前に決定された地雷からのすべての修正がすでに適用されているため、(i, j) の値は、それをカバーする必要がある追加地雷の数を正確に表していることです。 (i, j) に影響を与える可能性のある将来の地雷は後で処理される領域に存在する必要があり、それらの貢献は独自の決定が行われるときに対称的に処理されるため、貪欲な決定は安全です。 これにより、オーバーコミットが防止されます。セルがゼロに削減されると、再び誤って増加することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    m, n = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(m)]
    mines = []

    for i in range(1, m - 1):
        for j in range(1, n - 1):
            if grid[i][j] > 0:
                mines.append((i, j))
                for di in (-1, 0, 1):
                    for dj in (-1, 0, 1):
                        grid[i + di][j + dj] -= 1

    if not mines:
        print(0)
    else:
        mines.sort()
        for i, j in mines:
            print(i, j)

if __name__ == "__main__":
    solve()
```このソリューションはグリッドの作業コピーを維持し、地雷の設置の効果を直接シミュレートします。 二重ループにより、行優先の昇順でセルにアクセスすることが保証されます。 条件`grid[i][j] > 0`地雷がそこに存在する必要があるかどうかを決定します。その時点での肯定的な要件は、現在のセルに配置された地雷によって直ちに満たされる必要があるためです。 

3 x 3 の更新ループは核となる変換であり、各鉱山が影響を受けるすべてのセルに適切に寄与するようにします。 最後にソートすると、必要な出力順序が保証されますが、トラバーサルによってすでに自然に出力順序が生成されています。 

実装の微妙な点は、貪欲な構造により順番に処理する際の一貫性が保証されるため、地雷を設置することが将来の制約に違反するかどうかを確認する必要がないことです。 

## 実用的な例

 提供されたサンプル入力は、重なり合う近傍がすでに明確に示されているため、メイン トレースとして使用します。 

100 万セルすべてを完全に拡張するのではなく、概念的にいくつかのキーの配置を追跡してみましょう。 

開始時には、すべてのセルが最初に必要な寄与を保持します。 

セル (1,1) に到達すると、その値は正なので、そこに地雷を配置し、周囲の 3 × 3 ブロックから 1 を減算します。 これにより、すぐに近くのセルの値が減少し、効果が伝播します。 

(1,3) に移動すると、以前の配置では説明できない正の値が再び見つかるため、別の地雷を配置し、同じローカル デクリメントを適用します。 

処理が続行されると、近傍が重なり合うため、必要なすべての地雷が考慮された場所で、値が自然にゼロに向かって落ち着きます。 

小さなフラグメントの簡略化されたトレース:

 | ステップ | ポジション | | 前 | グリッド[i][j] アクション | 効果 |
 | --- | --- | --- | --- | --- |
 | 1 | (1,1) | >0 | 私の場所を | 3x3 ブロックで 1 を引く |
 | 2 | (1,3) | >0 | 私の場所を | 3x3 ブロックで 1 を引く |
 | 3 | (2,3) | >0 | 私の場所を | 3x3 ブロックで 1 を引く |

 これは、重複する貢献がどのように徐々にキャンセルされるかを示しています。 

ここで確認された重要な動作は局所性です。各決定は単一セルの現在の残差のみに依存し、更新はバックトラッキングを必要とせずに一貫して伝播します。

 ## 特殊なケース

 重要なエッジ状態は、グリッドに地雷がまったく含まれていない場合です。 この状況では、すべてのセルは最初からゼロであるため、スイープによって配置がトリガーされることはありません。 出力は単一のゼロになり、アルゴリズムは走査後に明示的に処理します。 

もう 1 つのケースは、3 × 3 のグリッドの中心にある 1 つの孤立した鉱山です。 アルゴリズムは中央のセルを訪問し、正の値を確認し、地雷を配置し、すぐに 9 つのセルすべてから 1 を減算します。 その更新後、すべてのセルはゼロになり、それ以上地雷は配置されず、予想される再構成と一致します。 

より微妙なケースは、複数の重なり合う地雷であり、その影響は地域全体で不均一に相殺されます。 各配置はその効果を隣接するすべての配置に即座に伝播するため、オーバーラップは残留グリッド内で自然に解決されます。 貪欲なルールにより、影響を与える可能性のある位置に対応する地雷が配置されない限り、正の需要がセルに残らないことが保証されます。
