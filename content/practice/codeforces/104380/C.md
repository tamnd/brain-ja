 ## 解決策
 ## 問題の理解

 最初は 1 に等しい単一の整数を格納するマシンから始めます。2 つの操作が許可されます。 1 つの操作は現在の値を 3 で乗算してから 2 を加算し、もう 1 つの操作は単に値を 1 だけ増加させます。指定された目標数値に到達したいと考えています。`n`可能な限り最小限の操作を使用します。 

より具体的に言うと、1から`n`数直線上にありますが、動きは均一ではありません。 1 つの移動はサイズ 1 の小さなステップであり、もう 1 つは現在の値のスケールも変更する大きな非線形ジャンプです。 目標は、正確に着地するような変換の最短シーケンスを見つけることです。`n`。 

制約`n ≤ 10^18`値に対する前方検索や動的プログラミングは即座に除外されます。 数値をノードとして扱う BFS ですら不可能です。状態空間が膨大であり、遷移によって値が非常に急速に増大するためです。`3x + 2`手術。 フォワード シミュレーションは大規模に達するずっと前に爆発するでしょう。`n`。 

単純なアプローチでは、操作のすべてのシーケンスを調査しようとする可能性があります。 一定の長さのシーケンスにさえ制限する`k`、可能性の数は指数関数的に増加します`2^k`、そしてそれ以来`n`最適なパスは非常に大きくても、実行不可能なほど長い場合があります。 

微妙なエッジケースが現れるのは、`n`小さくて直接手が届きます。 たとえば、次の場合`n = 2`複数の手順が必要であると誤解するかもしれませんが、実際には繰り返し行われます。`+1`操作はすぐにそれに到達します。 もう 1 つのエッジケースは、申請時です。`3x+2`オーバーシュート`n`重みがあり、前方の貪欲な選択が誤解を招くことになります。 

主な難点は、`3x+2`操作は大きさを増大させ、シフトを導入するため、直接的な推論を困難にします。 

## アプローチ

 ブルートフォースのアイデアは、各整数をノードとして扱い、1 から開始して最短経路検索を実行することです。各値から`x`、私たちはに行くことができます`x + 1`または`3x + 2`。 ボタンを押すすべてのシーケンスがこのグラフのパスに対応するため、これは原理的には正しいです。 ただし、グラフの成長が速すぎます。 までの値だけを探索したとしても`n`、分岐係数と範囲により、これは完全に不可能になります。`n`まで`10^18`。 

重要な洞察は、将来の成長は考えるのに正しい方向ではないということです。`3x + 2`順方向については説明が難しいですが、逆方向にすると構造化されます。 数字がわかったら`y`、それがどこから来たのかを尋ねることができます。`y - 1`、またはそれがどこから来たのか`(y - 2) / 3`いつ`y - 2`は 3 で割り切れます。 

これにより、問題は逆に最短経路に変わります。`n`1 まで減少し、ステップごとに値が減少します。 逆グラフは単純です:`y`、私たちはいつでも行くことができます`y - 1`、時々行くこともあります。`(y - 2) / 3`。 どちらの操作も数値を厳密に減少させるため、貪欲な逆方向トラバーサルを安全に実行できます。除算が有効な場合は常に除算を優先します。これは、1 ずつ減分するよりもはるかに速く大きさが減少するためです。 

これにより、問題は 1 に達するまで最適なリダクションを繰り返し適用するように変換されます。

 ## アルゴリズムのチュートリアル

 からの番号を処理します`n`1 に達するまで下向きに進みます。 

1. 目標値からスタート`n`オペレーション用のカウンターを維持します。 
2. 現在の値が 1 より大きいときに、乗算の逆の演算が適用できるかどうかを確認します。 これは、次のことを確認することを意味します。`(current - 2)`は 3 で割り切れ、結果は少なくとも 1 になります。 
3. 除算条件が成立した場合、現在の値を次のように置き換えます。`(current - 2) / 3`。 これにより値が大幅に圧縮され、以降の手順が削減されるため、この方法が推奨されます。 
4. 除算条件が満たされない場合は、現在の値を 1 減算します。これは、除算条件を逆転することに相当します。`+1`手術。 
5. 各変換は 1 つの操作としてカウントされるため、ステップごとに操作カウンターをインクリメントします。 
6. 値が 1 に達するまで続けます。 

1 を引くか逆除算を適用するかの選択は、完全に実現可能性によって決まります。 除算は、次の順構造と正確に一致する場合にのみ有効です。`3x + 2`。 これが有効な場合、複数の順方向インクリメントと 1 つの乗算が 1 つの逆方向ステップに圧縮されて表され、常に効率的になります。 

### なぜ効果があるのか

 すべての有効な順方向操作には、固有の逆方向マッピングがあります。 操作`x -> x + 1`になる`y -> y - 1`、 そして`x -> 3x + 2`になる`y -> (y - 2) / 3`有効な場合。 どちらの逆演算も厳密に値を減らすため、以下のシーケンスは`n`to 1 は最終的に終了する必要があります。 

除算は減算よりもはるかに積極的に大きさを減らすため、可能な限り除算を適用するという貪欲な選択は正しいです。 あるステップで除算が可能な場合、除算を遅らせても総演算数を減らすことはできません。減算は、除算がまだ利用できる領域に状態を移動するだけであるか、またはさらに役に立たなくなるからです。 したがって、除算をすぐに適用しても、最適なパス長は決して増加しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    x = n
    ops = 0
    
    while x > 1:
        if x > 2 and (x - 2) % 3 == 0:
            x = (x - 2) // 3
        else:
            x -= 1
        ops += 1
    
    print(ops)

if __name__ == "__main__":
    solve()
```ソリューションは繰り返し減少します`x`2 つの操作から派生した逆のルールを使用します。 重要な実装の詳細を確認しています`(x - 2) % 3 == 0`これにより、逆乗算ステップが有効な順方向状態に対応することが保証されます。 減算の場合は、次の逆関数によって分解できないすべての数値を処理します。`3x + 2`。 

ループは 1 で終了し、各ステップはちょうど 1 回の進むボタンの押下に対応します。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。`n = 1`。 ループは決して実行されず、正しい出力はゼロです。 アルゴリズムはこれを自然に処理します。`while x > 1`すぐに失敗します。 

もう 1 つの特殊なケースは、除算が決して適用できない少数の場合です。 例えば、`n = 5`繰り返しは減算のみをトリガーし、繰り返しを正しくシミュレートします。`+1`逆の操作。 これは、アルゴリズムが利用可能な除算に依存していないことを確認します。 

3 番目のエッジケースは次のような場合です。`(x - 2)`は 3 で割り切れますが、結果は非常に小さな数になります。 例えば、`x = 8`与える`(8 - 2) / 3 = 2`これは有効であり、状態空間を大幅に削減します。 アルゴリズムはこのステップに正しく優先順位を付け、不必要な中間デクリメントを回避します。
