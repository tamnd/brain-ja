 ## 解決策
 ## 問題の理解

 池を表すバイナリ グリッドが与えられます。各セルは水または何もない地面です。 このグリッドの上に、固定サイズの可能なすべての正方形領域を考慮します。$k \times k$。 このような正方形ごとに、そこに含まれる水のセルの数を数えますが、この数が常に偶数である必要があるという要件があります。 1 つの正方形でもこの条件に違反すると、グリッド全体が拒否されます。 

したがって、このタスクは、個々のセルのローカルなプロパティだけではなく、グリッドの重複するすべてのサブスクエアにわたるグローバルな一貫性チェックです。 

制約は小さいです。$n, m \le 100$、 そして$k \le \min(n, m)$。 これはすぐに次のことを示します。$O(n^3)$または$O(n^2 k^2)$原理的にはすでに許容できる解ですが、各サブスクエア内で繰り返し合計を再計算するものはすべて脆弱になります。 せいぜい約$10^4$グリッド内の四角形。各四角形には最大で次のものが含まれます。$10^4$セルなので、単純な再計算では次の値に達します。$10^8$これは境界線にありますが、注意深く最適化された場合にのみ Python で合格する可能性があります。 意図したソリューションはよりクリーンで、繰り返しの作業を完全に回避します。 

微妙なエッジケースが現れるのは、$k = 1$。 各正方形は 1 つのセルであるため、各セルには偶数個の水のセルが含まれている必要があります。つまり、すべての水のセルは実際には 0 でなければなりません。したがって、グリッド全体はすべて 0 でなければなりません。 と仮定する素朴なソルバー$k \ge 2$誤ってこれをスキップしたり、単一セルのパリティの解釈を誤ったりする可能性があります。 

別の特殊なケースが発生するのは、$k = n = m$。 正方形は 1 つだけあり、その答えは、グリッド内の 1 の合計数が偶数かどうかを確認することになります。 スライディング ウィンドウ ロジックは、サブスクエアが 1 つだけ存在する場合も正しく処理する必要があります。 

## アプローチ

 直接的なアプローチは、可能性のあるすべての左上隅を反復処理することです。$k \times k$二乗してセルの合計を最初から再計算します。 そのような位置ごとに、スキャンします$k^2$セルを表示し、出現するセルの数を数えます。 あるので$(n-k+1)(m-k+1)$このような正方形の場合、これはおおよそ次のようになります。$O(nmk^2)$操作。 すべての次元が 100 である最悪のケースでは、これは約$10^8$携帯電話の訪問。 これは 1 秒の制限時間内での Python の上限にすでに近づいており、さらに重要なことに、重複する領域を繰り返し合計することで計算が無駄になります。 

重要な観察点は、隣接していることです。$k \times k$正方形はほぼ完全に重なっています。 ウィンドウを右または下に 1 ステップ移動すると、セルの細いストリップのみが変化します。 各合計を再計算する代わりに、プレフィックス合計を使用して各平方の現在の合計を効率的に維持できます。 2D プレフィックス合計を使用すると、線形前処理後に一定時間内に任意の四角形の合計を計算できます。 これにより、繰り返しの合計の問題が、正方形ごとの定数時間のクエリに軽減されます。 

この場合、問題は純粋に四角形の合計のパリティをチェックすることになり、プレフィックスの合計はまさにこのために設計されたツールです。

 ## アルゴリズムのチュートリアル

 グリッドを 2D プレフィックス合計配列に前処理して、任意の長方形合計を一定時間で取得できるようにします。 その後、可能な限りスキャンします$k \times k$サブスクエアを作成し、そのパリティを検証します。 

1. プレフィックス合計配列を構築する`ps`どこ`ps[i][j]`左上隅 (0,0) から (i-1,j-1) までの長方形に 1 の数を格納します。 このインデックス作成のシフトにより、境界の問題が回避されます。 プレフィックス合計を使用する理由は、2D 範囲合計を 4 つの配列ルックアップに変換するためです。 
2. すべてのセルについて、反復を使用して値を累積します。$$ps[i][j] = grid[i-1][j-1] + ps[i-1][j] + ps[i][j-1] - ps[i-1][j-1]$$この減算により、重複領域の二重カウントが補正される。 
3. 可能なすべての左上隅を反復処理します。$k \times k$正方形、意味$i \in [0, n-k]$、$j \in [0, m-k]$。 
4. 包含除外を使用してその二乗の合計を計算します。$$total = ps[i+k][j+k] - ps[i][j+k] - ps[i+k][j] + ps[i][j]$$これにより、正確に分離されます$k \times k$一定時間内の領域。 
5. ある場合`total % 2 == 1`、条件に違反しているため、すぐに false を返します。 
6. すべての正方形が通過した場合、true を返します。 

### なぜ効果があるのか

 プレフィックス合計配列は、すべてのエントリが原点からの長方形にわたる正確な累積カウントを表すという不変条件を維持します。 なぜなら、すべての$k \times k$sum は、個々のセルを再計算することなくこれらの累積カウントから再構築され、各クエリは正確であり、走査順序とは無関係です。 正確さは、サブスクエア内の各セルが正確に 1 回カウントされ、サブスクエアの外側にあるセルが結果に寄与しないことを保証する包含/除外によって決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]

    ps = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        row_sum = 0
        for j in range(1, m + 1):
            row_sum += grid[i - 1][j - 1]
            ps[i][j] = ps[i - 1][j] + row_sum

    for i in range(n - k + 1):
        for j in range(m - k + 1):
            total = (
                ps[i + k][j + k]
                - ps[i][j + k]
                - ps[i + k][j]
                + ps[i][j]
            )
            if total % 2 == 1:
                print("false")
                return

    print("true")

if __name__ == "__main__":
    solve()
```この実装では、実行中の行アキュムレータを使用して、繰り返しの追加を避けるために、行ごとにプレフィックスの合計を構築します。 これにより、再計算に比べて定数係数が削減されます。`ps[i][j-1] + grid[i][j]`繰り返し。 

サブスクエア チェックでは、直接包含-除外が使用されます。 インデックス付けは 1 だけシフトされ、プレフィックス合計境界ケースが条件付きチェックなしで自然に 0 に評価されるようになります。 無効な正方形が 1 つ見つかると、それ以上の計算は不要になるため、早期に終了することが重要です。

 ## 特殊なケース

 いつ$k = 1$、すべてのセルが独自の正方形を形成します。 このアルゴリズムは、各セルの値が偶数であるかどうかをチェックすることになります。 値は 0 または 1 のみであるため、単一の 1 は即座に失敗します。 各クエリは 1 つのセルだけを分離するため、プレフィックス合計方法は引き続き機能します。 

いつ$k = n = m$、正方形は 1 つだけ存在します。 プレフィックス合計クエリはグリッド全体を 1 回評価し、合計合計にパリティ チェックが適用されます。 これにより、単一の評価を超える反復ロジックが必要なくなります。 

グリッドがすべてゼロの場合、すべてのプレフィックスの合計はゼロのままになるため、$k \times k$クエリはゼロを返し、パリティ チェックに簡単に合格します。
