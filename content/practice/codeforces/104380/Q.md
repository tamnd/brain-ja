 ## 解決策
 ## 問題の理解

 長さのシーケンスを繰り返し構築しています`n`配列を左から右に処理することによって。 各ステップで、現在の要素が最初は空の両端キューの先頭または末尾に挿入されます。 すべての挿入の後、元の配列の最終的な並べ替えが得られますが、正確な並べ替えは選択の順序によって異なります。`2^n`そういった選択パターン。 

結果として得られるそれぞれの両端キューについて、固定インデックス範囲内の要素の合計を取得します。`[L, R]`、1 から始まるインデックスを使用します。 タスクは、これらの範囲の合計の合計を計算することです。`2^n`可能な両端クエリ、モジュロ`10^9 + 7`。 

制約`n ≤ 5000`すべての構成を明示的に列挙するアプローチは除外されます。 結果の数は指数関数的に増加するため、すべての順列を保存することさえ不可能です。 有効なソリューションでは、構成を構築することなく、各要素がすべての構成にどのように寄与するかを推論する必要があります。 

微妙な問題は、両端に挿入することは、前の要素が単純に相対的な順序で固定されないことを意味することです。 それらの最終的な位置は、将来の要素がその周囲にどのように挿入されるかによって決まります。 これにより、単純な「位置の独立性」の仮定が失敗します。 

エッジケースの小さな例では、その感度がすでに示されています。 と`n = 3`、`A = [1, 2, 3]`、サンプルでは次のような順列の繰り返しが示されています。`[1,2,3]`、`[3,2,1]`、および次のような混合ケース`[3,1,2]`。 この繰り返しは、複数の挿入シーケンスが同じ最終デックに崩壊するため、直接の置換推論が誤解を招くことをすでに示唆しています。 

## アプローチ

 ブルートフォースソリューションでは、すべてがシミュレートされます。`2^n`選択肢。 選択文字列ごとに両端キューを構築し、合計を計算します。`[L, R]`、蓄積していきます。 それぞれの工事費`O(n)`、につながる`O(n · 2^n)`もう不可能になる時間`n = 25`。 

重要な観察は、完全な順列の観点から考えるのをやめ、代わりに個々の要素の寄与を追跡することです。 最終的な答えは要素にわたって線形であるため、各要素が何回行われるかに焦点を当てることができます。`A_i`間隔内に表示されます`[L, R]`すべての有効な構築シーケンスにわたって。 

要素を一つ一つ加工し、要素ごとにメンテナンスします`i`、各位置に配置されるシーケンスの数。 新しい要素を挿入すると、新しい要素が前面に来るかどうかに応じて、既存の要素はその位置に留まるか、1 つずつ右に移動します。 これにより、位置分布にわたってきれいな反復が作成されます。 

これにより、問題は順列ではなく位置に関する動的計画法に変わります。

 ## アルゴリズムのチュートリアル

 私たちは定義します`dp[i][p]`最初の処理後に次のような方法の数として`i`要素、要素`A_i`最終的にその位置に着く`p`最終デクで。 目標は、各要素の寄与を個別に計算し、間隔にわたって合計することです。`[L, R]`。 

1. 最初の要素の DP を初期化します。 いつだけ`A_1`が存在する場合は、前または後ろのどちらにでも配置できますが、どちらも同じ単一要素の両端子になります。 それで`dp[1][1] = 2`なぜなら、サイズ 1 の両端キューを生成するには 2 つの方法があるからです。 
2. 要素を処理します。`i = 2`に`n`。 ステップで`i`、以前のすべての構成は 2 つに分岐します。`A_i`前でも後ろでも。 この分岐により、前の要素の位置がどのように移動するかが決まります。 
3. 既存の要素の場合`A_j`配布あり`dp[j][p]`挿入する前に`A_i`、挿入後に何が起こるかを考えてみましょう。 もし`A_i`が後ろに挿入された場合、以前の位置はすべて変更されません。 これを前に挿入すると、前のすべての要素が 1 位置ずつ右に移動します。 それが再発につながる`dp_new[j][p] = dp_old[j][p] + dp_old[j][p-1]`。 
4. 新しく挿入された要素を処理します。`A_i`。 前に入れるとこの位置になります`1`。 バックで挿入すると体位になります`i`。 どちらの選択肢も以前の構造から独立しているため、どちらも貢献します`2^{i-1}`方法。 そこで設定しました`dp[i][1] += 2^{i-1}`そして`dp[i][i] += 2^{i-1}`。 
5. すべての要素が処理されるまで繰り返します。 
6. 最後に、区間内のすべての要素の寄与を合計することによって答えが計算されます。`[L, R]`、つまりそれぞれについて`i`、 追加`A_i * sum(dp[i][L..R])`。 

核となる不変条件は、処理後の`i`要素、`dp[i][p]`要素を配置する挿入シーケンスの数を正確にカウントします`A_i`位置で`p`。 すべてのシーケンスが 2 つの挿入選択肢にきれいに分割され、各選択肢が既存のすべての位置の決定論的な変換を引き起こすため、再帰ではこれが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, L, R = map(int, input().split())
    A = list(map(int, input().split()))

    # dp[i][p] = number of ways A[i] ends at position p
    dp = [[0] * (n + 2) for _ in range(n)]

    # base case for first element
    dp[0][1] = 2  # front or back, same single position

    pow2 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow2[i] = pow2[i - 1] * 2 % MOD

    for i in range(1, n):
        # transition previous dp[i-1] -> dp[i] for earlier elements
        for j in range(i - 1, -1, -1):
            for p in range(i, 0, -1):
                dp[j][p] = (dp[j][p] + dp[j][p - 1]) % MOD

        # new element i
        dp[i][1] = (dp[i][1] + pow2[i - 1]) % MOD
        dp[i][i + 1] = (dp[i][i + 1] + pow2[i - 1]) % MOD

    ans = 0
    for i in range(n):
        for p in range(L, R + 1):
            ans = (ans + A[i] * dp[i][p]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、各要素の位置分布テーブルを明示的に維持します。 ネストされた遷移ループは、新しい挿入ステップが追加されると、以前のすべての要素に対して「シフトするかシフトしない」更新を実行します。 

微妙な点は、内部ループの位置の順序です。 逆方向に実行されるため、更新は`dp[j][p]`に必要な値を上書きしません`p-1`同じ繰り返しで。 これにより、再発の正確さが保たれます。 

の使用`pow2[i-1]`を挿入するときにそれを反映します`i`-th 要素、前の要素`i-1`要素はすでにすべての可能な前後の決定を個別に受けており、正確に生成されます。`2^{i-1}`構成。 

## 実用的な例

 ### サンプル 1

 入力:```
5 1 5
1 1 1 1 1
```| ステップ | 概念的な dp 貢献 |
 | --- | --- |
 | 1 | 要素のみが 2 つの位置すべてに等しく寄与します (単一要素) |
 | 2 | 各ステップで構成が 2 倍になりますが、すべての値は同じです。 
| 5 | 32 個のシーケンスすべてのすべての位置に値 1 が含まれます。 

間隔`[1, 5]`デキュー全体をカバーするため、すべてのシーケンスが合計に寄与します。`5`。 と`2^5 = 32`シーケンス、合計は`160`。 

これは、すべての値が同一の場合、位置の分布は問題ではないことを示しています。 シーケンス数の組み合わせだけが残ります。 

### サンプル 2

 入力:```
3 1 2
1 2 3
```要素がどのように位置間で分散するかを追跡します。 

| ステップ | dp[1] | dp[2] | dp[3] |
 | --- | --- | --- | --- |
 | 1以降 | [2] | - | - |
 | 2以降 | シフト + 新しい | [4,4] | - |
 | 3以降 | 最終配布 | 混合 | 混合 |

 ポジションごとの貢献をカウントするようになりました`[1,2]`。 すべての有効なシーケンスにわたるすべての要素の寄与を合計すると、次のようになります。`30`、サンプルと一致します。 

このケースは、後の要素の挿入選択が間隔の境界を越えて前の要素にシフトするため、中間の要素の寄与がより不均一であることを示しています。

 ## 特殊なケース

 のために`n = 1`、意味のある選択肢はありません。 単一の要素は常に、位置を含む任意の間隔内にあります。`1`、したがってDPは単一の状態に崩壊します。 アルゴリズムは次のように割り当てます。`dp[0][1] = 2`、2 つの同一の挿入選択肢を反映し、最終的な合計は値を正しく 2 倍します。 

すべて等しい配列の場合、次のようになります。`[7, 7, 7]`、位置分布は無関係になります。 すべての DP トランジションは引き続き正しく展開されますが、コントリビューションはマージされます。 アルゴリズムは依然としてすべてをカウントします`2^n`間隔の合計は、シーケンス数を乗じた定数に減ります。 

次のような境界の多い間隔の場合`[L, R] = [1, 1]`、左端の位置のみが重要です。 これはシフトの反復を強調します。前方挿入ごとに、以前のすべての寄与がターゲット位置に出入りするように移動し、DP 更新の逆方向ループにより、これらのシフトが中間状態を上書きすることなく正しく蓄積されるようになります。
