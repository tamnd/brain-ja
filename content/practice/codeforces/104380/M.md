 ## 解決策
 ## 問題の理解

 この問題の各塔は、数直線上に配置された光源のように機能します。 所定の位置にある塔$a_i$から始まる明るさを発します$p_i$独自の位置にあり、そこから遠ざかるにつれて直線的に減少します。 所定の位置に立つと$x$、その塔からの貢献は$p_i - |a_i - x|$, ただし、ゼロ以下にはなりません。 

その場に立っているあらゆる人にとって$b_j$、複数のタワーからの貢献を追加しません。 代わりに、単一の塔から発せられる最も強い光だけを受け取ります。 したがって、タスクは、クエリ ポイントごとに、すべての塔によって形成されるこれらの切り取られた「ピラミッド」の最大値を計算することです。 

入力サイズにより、すべてのタワーとすべての人物間のブルート フォース インタラクションが大きすぎます。 まで$2 \cdot 10^5$塔と$2 \cdot 10^5$素朴な疑問$O(nm)$評価は次のとおりです$4 \cdot 10^{10}$1 秒で実行できる操作をはるかに超えています。 

主要な構造上の制約は、各タワーが V 字を逆三角形にしたような形状の関数に寄与し、その傾きが正確であることです。$-1$右側と$+1$左に。 これにより、グローバルな答えが、そのような多くの区分的線形関数の上限エンベロープになります。 

いくつかの特殊なケースでは、典型的な間違いが明らかになります。 よくあるのは、近くのタワーのみが重要であると想定し、あるしきい値の後に遠くのタワーをスキップすることです。 これは、ハイの場合には失敗します。$p_i$塔は遠くから見えます。 

たとえば、次の 2 つの塔について考えてみましょう。```
n = 2, m = 1
towers: (1, 2), (100, 100)
query: 50
```最初のタワーの寄与は 0、2 番目のタワーの寄与は$100 - 50 = 50$したがって、答えは 50 です。近くのタワーのみをチェックするヒューリスティックでは、これを見逃してしまいます。 

もう 1 つの失敗モードは、ゼロの最大値を忘れることによって発生します。 遠くにあるタワーは何も寄与しないはずであり、バグのある実装で誤って最大値を減らす負の値であってはなりません。 

## アプローチ

 直接的なアプローチでは、すべてのクエリ、コンピューティングに対してすべてのタワーを評価します。$p_i - |a_i - b_j|$そして最大値を追跡します。 これは文字通り定義に従っているので正しいです。 費用は$O(nm)$、最悪の場合、数百億の算術演算に劣化し、使用できなくなります。 

各タワーの影響力の構造は、よりグローバルな視点を示唆しています。 各タワーは、左側に傾き +1 を持つ区分線形関数を定義します。$a_i$右に -1 の傾きがあり、境界のある間隔の外側ではゼロで上限が設定されます。 任意の位置における最終的な答えは、これらすべての関数の最大値になります。 

直線上の線形関数の最大値を処理する標準的な方法は、各関数を集計しやすい形式に変換することです。 式を展開すると、次のようになります。$$p_i - |x - a_i| =
\begin{cases}
(p_i + a_i) - x & x \ge a_i \\
(p_i - a_i) + x & x < a_i
\end{cases}$$したがって、各タワーは 2 つの線形式に寄与します。 

形の一つ$(-x + (p_i + a_i))$そして別の形式$(x + (p_i - a_i))$、それぞれの片側で有効です$a_i$。 

これにより、問題が 2 方向の一次関数の最大値の追跡に分割されます。 ソートされた順序でクエリを処理することにより、2 つのスイープ構造を維持できます。1 つは左側からの寄与を処理し、もう 1 つは右側からの寄与を処理します。 各辺は古典的な「時間の経過とともに傾きが ±1 の最大ライン」問題になり、アクティブな範囲をキーとした優先順位構造を使用して維持できます。 

重要な観察は、各タワーが内部でのみアクティブであるということです。$[a_i - p_i, a_i + p_i]$。 この間隔の外では、寄与はゼロになります。 内部では線形関数のように動作するため、スイープ ラインがこれらのエンドポイントを横切るときにタワーをアクティブ化および非アクティブ化するだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nm)$|$O(1)$| 遅すぎる |
 | アクティブな間隔 + ヒープを使用したスイープ |$O((n+m)\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 どのタワーが現在「アクティブ」であるかを維持しながら、数直線を左から右に処理します。これは、タワーの影響範囲が現在の領域をカバーすることを意味します。 

1. 各タワーについて、そのアクティブなセグメントを計算します。$[a_i - p_i, a_i + p_i]$。 これは、その寄与がゼロではない領域です。 このセグメントの外では、回答に影響を与えることはありません。 
2. 2 つのイベント リストを作成します。1 つは次の時点でアクティブ化するためのものです。$a_i - p_i$、もう 1 つは非アクティブ化用です$a_i + p_i + 1$。 スイープの進行に合わせてタワーを追加したり削除したりします。 +1 により、タワーが正しいエンドポイントで引き続きアクティブであることが保証されます。 
3. すべてのイベントとクエリを位置ごとに並べ替えます。 それらを昇順に処理することで、いつでもその座標でどのタワーがアクティブであるかを正確に知ることができます。 
4. の最大値を返せる構造を維持する$p_i - |a_i - x|$現在の位置にあるアクティブなタワーの間。 絶対値は動作を分割するため、左寄りの形式と右寄りの形式からの寄与を暗黙的に表す 2 つのヒープを維持します。 
5. 位置でクエリを処理する場合$x$、すべてのアクティブなタワーから可能な限り最良の寄与を計算し、それを出力します。 すべてのタワーが影響するため、これは機能します$x$以前のイベントによってすでにアクティブ化されており、まだ削除されていません。 

微妙な部分は、非アクティブなタワーが最大値を汚染しないようにすることです。 これは遅延処理されます。エントリは有効期間を過ぎると破棄されます。 

### なぜ効果があるのか

 任意のスイープ位置で$x$、アルゴリズムは、影響範囲に含まれるタワーのセットを正確に維持します。$x$。 このような各タワーの貢献度は、$x$は、相対位置に応じて線形形式の 1 つで正しく表現されます。 常にすべてのアクティブなタワーの最大値を取得し、アクティブなときにすべてのタワーの寄与が完全に表現されるため、アルゴリズムはその時点ですべての有効な関数の正確な上限エンベロープを計算します。 非アクティブなタワーは、間隔が除外されているため貢献できません。$x$アクティブ化イベントによってその位置でのクエリの前に確実に含められるため、アクティブなタワーは省略されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    towers = [tuple(map(int, input().split())) for _ in range(n)]
    queries = list(map(int, input().split()))

    events = []

    for a, p in towers:
        l = a - p
        r = a + p
        events.append((l, 1, a, p))      # add tower
        events.append((r + 1, -1, a, p)) # remove tower

    for i, x in enumerate(queries):
        events.append((x, 0, i, 0))

    events.sort()

    import heapq

    active = {}
    heap = []

    def add(a, p):
        heapq.heappush(heap, (a, p))

    def value(a, p, x):
        return p - abs(a - x)

    def get_best(x):
        while heap:
            a, p = heap[0]
            if active.get((a, p), 0) == 0:
                heapq.heappop(heap)
                continue
            return value(a, p, x)
        return 0

    ans = [0] * m

    for pos, typ, x, p in events:
        if typ == 1:
            a, p = x, p
            active[(a, p)] = active.get((a, p), 0) + 1
            add(a, p)
        elif typ == -1:
            a, p = x, p
            active[(a, p)] -= 1
        else:
            i = x
            ans[i] = get_best(pos)

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```この解決策は、数直線上のグローバル イベント スイープを構築します。 各タワーは、その影響力の境界を示す 2 つのイベントに貢献します。 クエリは同じタイムラインに挿入されるため、スイープはすべてを順番に処理します。 

ヒープには候補タワーが格納されますが、`active`ディクショナリは、タワーがまだ有効であるかどうかを追跡します。 クエリに最適な値を抽出する場合、無効なエントリは遅延して破棄されます。 評価式は必要な場合にのみ直接適用されるため、複雑な構造を事前に計算することなく正確性が保証されます。 

実装の微妙な点は、タワーが位置とパワーの両方によって識別されることです。 これにより、複数のタワーが座標を共有する場合に辞書内での衝突が回避されます。 もう 1 つの重要な詳細は、非アクティブ化が厳密に正しいエンドポイントの後に行われ、正確な境界位置での正確性が維持されることです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O((n+m)\log n)$| 各タワーは 2 つのイベントを提供し、各クエリは 1 回処理され、ヒープ操作が支配的になります。 
| スペース |$O(n)$| ヒープとアクティブ マップは最大でもすべてのタワーに格納されます。 

操作の総数は次の値に比例するため、複雑さは制限内に問題なく収まります。$2n + m$、それぞれ対数ヒープのメンテナンスが必要です。

 ## 特殊なケース

 まれなケースは、タワーの影響がその境界にあるクエリ ポイントにかろうじて到達する場合に発生します。 タワーを考えてみましょう$a = 10$と$p = 3$。 その影響力は 13 で終了し、7 から始まります。 

クエリ 13 での貢献度は次のとおりです。$3 - 3 = 0$。 スイープには、早期にタワーを削除するのではなく、この時点でタワーを含める必要があります。 での非アクティブ化$r + 1$正確に 13 のクエリでもタワーが表示されるようにします。 

別の特殊なケースには、同一の座標を持つ複数のタワーが含まれます。 アクティベーション追跡のキーとなるのは、$(a_i, p_i)$、重複は独立して処理されます。 各コピーは個別に提供され、アクティブな構造内の他のコピーを上書きしません。 

3 番目のケースは、すべてのタワーがクエリから遠く離れている場合に発生します。 ヒープには古いエントリのみが含まれる場合があります。 遅延削除により、構造が空になるまで無効なタワーがすべて破棄され、その時点で答えが正しくゼロになります。
