 ## 解決策
 ## 問題の理解

 単一の正の整数が与えられます`x`そして、特定の桁の制約を回避する最も近い小さい整数を見つけるには、厳密に下方向に移動する必要があります。その 10 進数の桁はどれも使用できません。`7`。 以下のすべての整数の中で`x`、この制限を満たす最大のものが必要です。 

このタスクは基本的に、指定された境界以下の整数を検索するものですが、その数字を含む数値を除外するフィルターが使用されます。`7`。 出力は単なる有効な数値ではなく、制約の下での最大の有効な数値であるため、これは「最も近い有効な先行」問題になります。 

制約`x ≤ 10^4`検索スペースが小さいことを意味します。 リニアスキャンでも`x - 1`まで`1`実行されるチェックは最大 1 万件で、各チェックでは数桁のみが検査されます。 これにより、高度なデジタル DP や貪欲な再構成の必要性が即座に排除されます。 単純な反復であっても、制限時間内に問題なく収まります。 

エッジケースは次の場合に発生します。`x`それ自体は禁止領域のすぐ上にあります。 たとえば、次の場合`x = 7000`、次に次のような数字`6999`、`6998`など、有効なものが見つかるまで注意深く調べる必要があります。 不注意な間違いは、一度デクリメントして結果が有効であると仮定することです。これは、次のような入力に対してすぐに失敗します。`x = 70`、 どこ`69`有効ですが、`69`1 つのステップだけを実行した場合、常に見つかるとは限りません。 もう 1 つの微妙なケースは、答えが複数の桁の境界をまたぐ場合です。`x = 100`、答えはどこにありますか`99`、 ない`99`または数字置換ロジックを含むもの。 

## アプローチ

 最も直接的な戦略は、以下から始めることです。`x - 1`そして、10 進表現にその数字が含まれない数値が見つかるまでデクリメントを繰り返します。`7`。 各候補は文字列に変換され、その文字がスキャンされることでチェックされます。 すべての整数を降順で探索し、最初に見つかった有効な数値が以下の有効な最大値であることを保証するため、これは正しいです。`x`。 

非効率性の懸念は、禁止された数字によって無効な数字が長く続く場合にのみ発生します。 最悪の場合、次のような数字をスキップする可能性があります。`70, 71, 72, ..., 79`、または次のような大きなパターン`7000`下向きですが、それでもチェックの総数は次の制限を受けます。`10^4`。 各チェックのコストは O(log x) であるため、合計の作業量は無視できます。 

重要な観察は、数字を結び付ける構造上の制約は、除外することを除いて存在しないことです。`7`。 これにより、数字に関する組み合わせ推論の必要がなくなります。 貪欲なデクリメントとテストのループにより、ソリューション空間が完全にキャプチャされます。

## アルゴリズムのチュートリアル

 1. 直下の整数から開始`x`。 これは可能な最大の候補であり、正しい順序で下方向に検索することが保証されます。 
2. 候補番号ごとに、その数字が含まれているかどうかを確認します。`7`それを文字列に変換し、すべての文字をスキャンします。 このステップでは、算術数字の抽出を必要とせずに制約を直接適用します。 
3. 番号に何も含まれていない場合`7`、すぐに返却してください。 下方向にスキャンしているため、最初の有効な数値が最大の有効な答えであることが保証されます。 
4. それ以外の場合は、候補を 1 つ減らしてチェックを繰り返します。 

有効な数値が見つかるまでループが続きます。 ドメインは次のように制限されているため、`x ≤ 10^4`、終了が保証されます。 

### なぜ効果があるのか

 このアルゴリズムは、すべての数値が現在の候補より大きく、以下であるという不変条件を維持します。`x`すでに検討され、却下されました。 下方向にのみ移動し、値をスキップすることはないため、数字フィルターを通過する最初の数値は、以下の有効な最大数値である必要があります。`x`。 より大きな候補はすべてシーケンスの早い段階でテストされるため、より良い答えを見逃す可能性はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def has_seven(n: int) -> bool:
    return '7' in str(n)

def solve():
    x = int(input().strip())
    cur = x - 1
    
    while cur > 0:
        if not has_seven(cur):
            print(cur)
            return
        cur -= 1
    
    print(0)

if __name__ == "__main__":
    solve()
```機能`has_seven`桁チェック ロジックを分離することで、メイン ループがより明確になり、エラーが発生しにくくなります。 ループは次から始まります`x - 1`なぜなら、問題では明らかにより小さい数が必要だからです。 

微妙な点は、ゼロより大きい有効な数値が存在しない場合の処理​​です。 以来`1 ≤ x ≤ 10^4`、 そして`0`は含まれていません`7`、ループは常に安全に終了しますが、ガードは退化推論であっても正確さを保証します。

 ## 特殊なケース

 入力用`x = 7`、アルゴリズムセット`cur = 6`。 小切手`'7' in str(6)`はすぐに false になるため、出力されます`6`。 これにより、禁止された数字が正確に境界にある場合に正しい処理が行われることが確認されます。
