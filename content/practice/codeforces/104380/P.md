 ## 解決策
 ## 問題の理解

 ダンジョンは直線であり、騎士は位置 0 から位置 D まで決して引き返さずに歩きます。 この道沿いにはモンスターとショップの 2 種類の遭遇があり、それぞれが固定位置に配置されています。 各モンスターには必要な強さと、到達時にナイトが弱すぎる場合のペナルティコストがあります。 各店には騎士の体力を一定値まで上昇させるポーションが用意されており、購入にもコインが必要となる。 

重要な行動は、騎士の強さはポーションを購入した場合にのみ増加するということです。 ポーションは加算的な意味で以前のポーションと積み重ねられるのではなく、そのレベルが現在のレベルよりも高い場合、単に彼の強さをそのポーションのレベルに設定するだけです。 モンスターの強さは変わりません。 現在の強度が不十分な場合にのみコストがかかります。 

目標は、コインの合計コストを最小限に抑えるために、どのポーションを購入するか (存在する場合)、およびバイパスするためにどのモンスターに支払うかを決定することです。 

制約は大きく、最大 100,000 のモンスターと 100,000 のショップがあり、位置は最大 10^9 になります。 これにより、パスに沿って段階的に移動をシミュレートしたり、イベントごとに個別にコストを再計算したりするアプローチは即座に除外されます。 イベントまたは候補状態に対する二次戦略も、2 秒の制限の下では失敗します。 解決策は、問題をソートと線形または対数処理に近いものに減らす必要があります。 

微妙な点は、モンスターと店の位置は、ラインでの注文以外には実際には相互作用しないことです。 「騎士がモンスターの前にすでに店を通過したか」以外はタイミングに依存するものはなく、強さは減少しないため、正確な空間順序は最適なコスト構造に影響を与えないことがわかります。 これは、多くの誤ったアプローチが見逃している重要な単純化です。 

よくある失敗例の 1 つは、ポーションの選択が初期のモンスターに動的に依存するという想定から生じます。 たとえば、騎士が早い段階で弱いモンスターに遭遇し、アップグレードせずにお金を払うことにした場合、単純な貪欲な人は、後で安価にアップグレードした方が世界的には優れていたことを見逃す可能性があります。 もう 1 つの失敗例は、複数の現在の強度を維持しながら移動をシミュレートしようとすることですが、強度は最大 10^9 までの多くの値を取る可能性があるため、すぐに爆発してしまいます。 

具体的なエッジケースは、すべてのモンスターが強力で、後期の強力なポーション 1 つを除いてすべてのポーションが高価である場合です。 貪欲に初期の小さなアップグレードを購入すると、最終アップグレードまでにすべてのペナルティを単に支払うよりも悪い結果になる可能性があります。 

## アプローチ

 ブルートフォース戦略では、ショップのすべてのサブセットを試し、購入したポーションの選択ごとに移動をシミュレーションします。 選択したサブセットごとに、すべてのモンスターをスキャンし、強さが不足するたびにペナルティを合計します。 これは、考えられるすべての戦略を直接評価するため、原理的には正しいですが、サブセットの数は 2^m であり、100000 どころか、m = 40 の場合でも完全に実行不可能です。単一の最適なポーションに制限しても、候補ごとに O(n) を必要とするモンスターとの相互作用が依然として残ります。 

重要な観察は、ポーションの行動は購入の順序ではなく、達成された最大レベルによってのみ支配されるということです。 ナイトの強さが L で終了する場合、レベルが最大でも L のポーションは無関係であり、L を超えるポーションは、決定的なアップグレードとして 1 回購入された場合にのみ考慮されます。 これにより、状態空間が指数関数的なサブセットから、可能な最終強度値に対する単純な選択へと崩壊します。

これを理解すると、問題は 2 つの独立したコンポーネントにきれいに分割されます。 1 つの要素は、与えられた最終的な強さ L を達成するための最適なコストを決定することであり、これはレベル L を提供するショップのみに依存します。もう 1 つの要素は、強さ L がある場合にモンスターに対していくら支払うかを計算することであり、これは各モンスターの必要な強さが L を超えるかどうかにのみ依存します。 

独立性が重要です。モンスターはどのポーションを購入するかに影響を与えず、ポーションはモンスターの順序に依存しません。 これにより、各候補 L を独立して評価し、2 つのコスト寄与を組み合わせることができます。 

これを効率化するために、必要な強さによってソートされたモンスターのコストを事前計算し、特定の L に適用されるペナルティの合計を高速にクエリできるようにします。

 | サブセットに対するブルート フォース | O(2^m・n) | お(1) | 遅すぎる |
 | 各強度レベルの評価 + 前処理 | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは問題を、すべての意味のある最終強度値を評価し、それぞれの最適なコストを計算することに変換します。 

1. ショップからすべての候補強度値を抽出し、ポーションが購入されないベースライン ケースとして強度 0 も含めます。 これらは、騎士が最終的に得られる可能性のあるすべての最終的な強さを表しています。 
2. 各強度値 L について、それを取得するための最適なコストを決定します。 同じLを提供するショップが複数ある場合は、その中で最小のコストを採用します。 L が 0 の場合、購入は行われないためコストは 0 です。 これが機能するのは、ポーションの購入は最終レベルによってのみ重要であり、中間のアップグレードは役に立たないためです。 
3. すべてのモンスターを必要な強さ順に並べ替えます。 これに加えて、モンスターの接尾辞に対する合計ペナルティを迅速に照会できるように、ペナルティコスト f の接頭辞の合計を計算します。 
4. 与えられた候補の強さ L に対して、必要な強さが L を超えるモンスターの総コストを計算したいとします。これは、h > L を持つモンスターの f をすべて合計することに相当します。ソートされた h 配列の二分探索を使用して、L に負けていない最初のモンスターを見つけ、対応するサフィックスの合計を取得します。 
5. 固定Lの総コストは、LのベストショップコストとLのモンスターペナルティコストの合計です。 
6. すべての候補 L についてこの値を計算し、すべての候補の最小値を返します。 

実装の重要な詳細は、パスに沿った動きを決してシミュレートしないことです。 位置 a_i と b_i は、順序付けにのみ影響し、実現可能性やコストの累積には影響しないため、無関係です。 

### なぜ効果があるのか

 このアルゴリズムは、騎士の強さは空間順序とは無関係に増加する単一のスカラー値によって完全に記述されるという不変式に依存しています。 最終的な強さ L を選択し、それに到達するための効果的なアップグレードを 1 つだけ支払うことで、あらゆる戦略を表現できます。 L が固定されると、すべてのモンスターは、h_i が L を超えるかどうかのみに基づいて、無料または有料の遭遇として独立して動作します。これにより、ダンジョン内のさまざまなポイントでの決定間の結合がすべて取り除かれ、逐次的な最適化が小さな離散セットに対する静的な最小化に変わります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    D, n, m = map(int, input().split())

    monsters = []
    for _ in range(n):
        a, h, f = map(int, input().split())
        monsters.append((h, f))

    shop_best = {}
    candidates = [0]

    for _ in range(m):
        b, l, w = map(int, input().split())
        if l not in shop_best:
            shop_best[l] = w
        else:
            shop_best[l] = min(shop_best[l], w)

    for l in shop_best:
        candidates.append(l)

    candidates = list(set(candidates))
    candidates.sort()

    monsters.sort()  # sort by h
    hs = [h for h, f in monsters]
    fs = [f for h, f in monsters]

    # suffix sum of f
    suf = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suf[i] = suf[i + 1] + fs[i]

    def monster_cost(L):
        # first index with h > L
        lo, hi = 0, n
        while lo < hi:
            mid = (lo + hi) // 2
            if hs[mid] <= L:
                lo = mid + 1
            else:
                hi = mid
        return suf[lo]

    ans = float('inf')

    for L in candidates:
        cost_shop = shop_best.get(L, 0)
        cost_mon = monster_cost(L)
        ans = min(ans, cost_shop + cost_mon)

    print(ans)

if __name__ == "__main__":
    main()
```コードは、モンスターを読み取り、各強さレベルに到達するための最も安価な方法のみを保持するマップに店舗情報を圧縮することから始まります。 達成される最大強度のみが重要であるため、これで十分です。 

モンスターは必要な強さによって並べ替えられるため、二分探索を使用して、倒されたモンスターと候補 L に当てはまらないモンスターに分割できます。その後、サフィックス合計配列により、分割ポイントを超えるすべてのモンスターに対する合計ペナルティを定数時間で計算できます。 

各候補の強さは独立して評価されます。 最終的な答えは、ショップでの購入とモンスターのペナルティを合計した最小コストです。 

よくある微妙な点は、強度 0 が候補として確実に含まれるようにすることです。 これがなければ、ポーションを購入しないことが最適なケースは完全に見逃されてしまいます。

 ### サンプル 1

 最適な選択は L = 30 で、モンスターのペナルティとアップグレードコストを最小限に抑える選択的な購入と組み合わせると、190 が生成されます。 

これは、より安価な中間アップグレードが存在する場合でも、ポーション レベルが高くなると、そのコストを正当化するのに十分なだけモンスターのペナルティを軽減できることを示しています。

これは、トレードオフが純粋にグローバルなものであり、順序に依存していないことを裏付けています。

import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    D, n, m = map(int, input().split())

    monsters = []
    for _ in range(n):
        a, h, f = map(int, input().split())
        monsters.append((h, f))

    shop_best = {0: 0}
    candidates = [0]

    for _ in range(m):
        b, l, w = map(int, input().split())
        shop_best[l] = min(shop_best.get(l, float('inf')), w)

    for l in shop_best:
        candidates.append(l)

    candidates = sorted(set(candidates))

    monsters.sort()
    hs = [h for h, f in monsters]
    fs = [f for h, f in monsters]

    suf = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suf[i] = suf[i + 1] + fs[i]

    def cost_mon(L):
        lo, hi = 0, n
        while lo < hi:
            mid = (lo + hi) // 2
            if hs[mid] <= L:
                lo = mid + 1
            else:
                hi = mid
        return suf[lo]

    ans = float('inf')
    for L in candidates:
        ans = min(ans, shop_best.get(L, 0) + cost_mon(L))

    return str(ans)

 ## 特殊なケース

 重要なエッジケースは、購入する価値のあるポーションがない場合です。 その状況では、唯一の候補の強さは 0 であり、すべてのモンスターの h_i > 0 があるため、アルゴリズムはすべてのモンスターのペナルティを正しく合計します。 

もう 1 つの微妙なケースは、複数のショップが同じ強度を提供していることです。 アルゴリズムはそれらを単一の強度あたりの最適コストに正しく圧縮し、数えすぎや誤った複数購入を防ぎます。 

さらに、非常に強力だが高価なポーションが存在する場合も考えられます。 それが候補セットに含まれているため、アルゴリズムは依然としてそれを考慮しており、十分なモンスターペナルティを軽減する場合はすべての中間選択肢を支配する可能性があります。
