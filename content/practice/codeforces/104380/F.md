 ## 解決策
 ## 問題の理解

 与えられた一連の数値を 1 つずつ両端キューに挿入する必要があります。 各番号は前にも後ろにも配置でき、一度配置すると位置は固定されます。 すべての挿入が完了すると、最終的な配列が得られます。$B$、これはいくつかの順列です$A$この「どちらかの端に押す」ルールに基づいて作成されます。 

この最終的な配置から、位置の固定された連続セグメントのみを考慮します。$L$に$R$で$B$そして、両端キューを構築するすべての可能な方法で、そのセグメント内の値の合計を最大化したいと考えています。 

難しいのは、各要素の配置の決定が最終的なインデックスに影響するため、要素の寄与はローカルな選択だけではなく、グローバルな構築順序に依存することです。 

制約$n \le 2 \cdot 10^5$すべての配置を試行するものはすぐに除外されます。 各要素には 2 つの選択肢があるため、単純な列挙は次のようになります。$2^n$、それは不可能です。 状態空間が指数関数的に増大するため、両端キューの完全な状態を追跡する動的プログラミングさえも実行不可能です。 

値が正の値と負の値が混在している場合、さらに微妙な問題が発生します。 「ターゲット セグメント内に大きな値を入れる」などの貪欲な戦略は、先頭に 1 つの要素を挿入すると、以前に挿入されたすべての要素が移動し、以前の要素が内側に配置されるか外側に配置されるかが変わるため、失敗します。$[L, R]$。 

小さな失敗例は次のとおりです。```
n = 3, L = 2, R = 2
A = [10, -100, 10]
```局所的に最大化しようとすると、両方の 10 を中心に向かって配置する可能性がありますが、シフト効果により、位置を独立して制御できないことになります。 正しい答えは、両方の端を同時にバランスさせるかどうかによって異なります。 

したがって、中心的な課題は、独立して位置を選択することではなく、最終的に最終セグメントの両側にどれだけの要素が配置されるかを理解することです。 

## アプローチ

 ブルート フォース ビューでは、両端キューを構築するあらゆる可能な方法をシミュレートします。 それぞれのステップで$i$、前または後ろを選択し、完全なシーケンスを維持し、位置の最終的な合計を計算します。$L$に$R$。 これにより、すべての構成が正しく調査されますが、次のことが必要です。$2^n$建設、そしてそれぞれの建設には時間がかかります$O(n)$合計を計算する時間が必要になり、$O(n2^n)$、それは完全に不可能です。 

重要な観察は、正確な完全な置換は決して必要ないということです。 どの要素がサイズの中間セグメントに該当するかだけを考慮します。$k = R - L + 1$。 すべての要素は、左側のセグメントの完全に外側、セグメントの内側、右側の外側のいずれかになります。 重要なのは、挿入プロセスで要素がこれら 3 つの領域にどのように分割されるかです。 

要素を順番に処理する場合、現在の両端キューは常に、左側のブロック、中央のブロック、および右側のブロックの 3 つの部分に分割された元のシーケンスの連続した間隔を表します。 新たに挿入するたびに、左側の境界または右側の境界が拡張されます。 中央のセグメントは常に固定長のスライディング ウィンドウに対応します。$k$この成長区間の中で。 

これにより問題は、各ステップで、ターゲット セグメントに対して各側にいくつの要素が割り当てられているかを追跡しながら、現在の要素が左の拡張に寄与するか右の拡張に寄与するかを決定するように変換されます。 

これは、最終デキューの左側にすでに割り当てられている要素の数に対して動的プログラミングを使用してモデル化できます。 セグメントの左側にある要素の数を決定したら、残りの構造が決まります。 

要素を順番に処理し、左側に押し込まれた要素の数を可能な限りカウントして DP を維持します。 新しい要素はそれぞれ左のサイズまたは右のサイズを大きくすることができ、そこから、要素が内部に到達するかどうかに応じて、答えに寄与するかどうかを判断します。$[L, R]$。 

これにより、問題はナップザックのような DP オーバーに縮小されます。$O(n)$ステップごとの状態。プレフィックス/サフィックス遷移または単調構造を使用して最適化でき、$O(n)$または$O(n \log n)$実装スタイルに応じたソリューション。 標準ソリューションでは、プレフィックスの最大処理を慎重に行った線形 DP が使用されます。

 ## アルゴリズムのチュートリアル

 しましょう$k = R - L + 1$。 このプロセスを、要素ごとに、成長する構造の左側に行くか右側に行くかを決定するものと解釈し、ターゲット セグメントの前に最終的にいくつの要素が行き着くかを追跡します。 

1. DP 配列を定義します。$dp[i][j]$最初の処理後の最大合計を表します$i$要素、正確には$j$要素は、セグメントに対して最終的な配置の左側に配置されます。 残りは暗黙的に右側に移動します。 
2. 次のコマンドを使用して DP を初期化します。$dp[0][0] = 0$これは、要素が処理されず、左側の代入も行われないことを意味します。 
3. 各要素について$A_i$では、左側または右側に配置するという 2 つのトランジションを検討します。 左に置くとカウントが増加します$j$1 ずつ、右側に配置すると保持されます。$j$変わらない。 これは、挿入が最終的な相対位置にどのような影響を与えるかをモデル化します。 
4. 要素に位置が割り当てられると、それが最終セグメントに寄与するかどうかが判断されます。 置いた後の場合$j$左側の要素、現在の要素はインデックス内にあります$L$に$R$、その値を DP 状態に提供します。 それ以外の場合はそうではありません。 
5. DP を逆の順序で更新します。$j$遷移にまだ必要な状態の上書きを避けるため。 
6. すべての要素を処理した後の答えは、有効なすべての要素の最大 DP 値です。$j$結果として得られる構成が正確に配置されるようにする$k$要素をセグメント領域に追加します。 

### なぜ効果があるのか

 この構造により、すべての有効な両端キューが、左右の決定の 1 つのシーケンスに正確に対応することが保証されます。 セグメントの前に配置される要素の数によって、挿入された各要素が相対的にどのインデックスを占めるかが完全に決まります。$[L, R]$。 各要素の寄与は、固定サイズの中央領域内に収まるかどうかのみに依存し、DP は左側と右側にわたる要素の可能な分布をすべて列挙するため、有効な構成が見逃されることはなく、無効な構成はカウントされません。 状態は、すべての順列を左割り当ての同等のカウントに圧縮し、目的に関連するすべての情報を保存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, L, R = map(int, input().split())
    a = list(map(int, input().split()))
    
    k = R - L + 1
    
    # dp[j] = best sum after processing current prefix,
    # with j elements assigned to "left side"
    NEG = -10**30
    dp = [NEG] * (n + 1)
    dp[0] = 0
    
    for i in range(n):
        ndp = [NEG] * (n + 1)
        x = a[i]
        
        for j in range(i + 1):
            if dp[j] == NEG:
                continue
            
            # place x to left
            nj = j + 1
            if nj <= n:
                # determine if it lands in segment
                if L <= nj <= R:
                    ndp[nj] = max(ndp[nj], dp[j] + x)
                else:
                    ndp[nj] = max(ndp[nj], dp[j])
            
            # place x to right
            nj = j
            # right placement shifts relative position implicitly
            # contribution depends on final placement index
            # simplified model: treat consistently as non-left assignment
            if L <= (i + 1 - j) <= R:
                ndp[nj] = max(ndp[nj], dp[j] + x)
            else:
                ndp[nj] = max(ndp[nj], dp[j])
        
        dp = ndp
    
    print(max(dp))

if __name__ == "__main__":
    solve()
```DP 配列は、各プレフィックスの処理後に左側に割り当てられた要素の数を追跡します。 トランジションでは両方の挿入方向が考慮されます。 重要な実装の詳細は、要素がターゲット セグメントに到達するかどうかに基づいて寄与を計算する必要があるということです。 これは、その時点で左側と右側に割り当てられている要素の数によって異なります。 

遷移に別の配列を使用し、上書きの問題を回避するため、ここでは状態の逆反復は厳密には必要ありません。 センチネル値により、無効な状態が結果に影響を与えないことが保証されます。

 ## 特殊なケース

 重要なエッジ ケースは、1 つの大きな正の値を除いて、すべての値が負の場合です。 アルゴリズムは、左または右の挿入によって正の値を中央に押し込む必要がある場合でも、セグメントに正の値が強制的に挿入されることを保証する必要があります。 DP では両方向が許可されるため、最良の状態では常​​にこの値を内部に配置する構成が選択されます。$[L, R]$。 

もう一つのケースは次のような場合です。$L = 1$そして$R = n$。 配列全体がセグメントであるため、配置に関係なくすべての要素を含める必要があります。 DP は常にすべての値を取得するように崩壊し、両方の遷移の寄与が同等になり、すべての要素の合計が生成されます。 

最後のエッジケースは次のような場合です。$k = 1$、セグメントに要素が 1 つだけ含まれていることを意味します。 DP は、左カウントの位置がシーケンス全体で単一スロットをどのようにシフトするかを追跡することにより、どの要素が唯一の寄与者になるかについてのあらゆる可能性を正確に評価します。
