 ## 解決策
 ## 問題の理解

 学生の試験成績のシーケンスが与えられ、各成績は 0 から 100 までの整数です。タスクは、残りの成績の相対的な順序を元のリストとまったく同じに保ちながら、60 未満のすべての成績を削除した、このシーケンスのクリーンなバージョンを作成することです。 

入力は本質的にリスト変換の問題です。リストを 1 回スキャンし、要素ごとに、それが出力に残るか破棄されるかを決定します。 しきい値に基づくフィルタリングを超える、並べ替え、集計、および要素間の相互作用はありません。 

グレード数の制限 (最大 100,000) により、リスト内の要素を繰り返しシフトしたり、ネストされたスキャンを実行したりするアプローチは即座に除外されます。 Python リストを反復処理しながら要素を削除する単純な実装では、削除するたびに要素がシフトされるため、二次的な動作に低下する可能性があります。 要素が 100,000 個ある場合、そのような動作は 1 秒の制限では遅すぎます。 唯一の安全な方向は、出力のシングルパス構造です。 

エッジケースは数値的なものではなく構造的なものがほとんどです。 すべての成績が 60 未満の場合、出力は空になり、何も印刷されません。 すべてのグレードが 60 以上の場合、出力は入力と完全に一致します。 空の結果を出力するときに、微妙な間違いがよく発生します。実装によっては、誤って余分な改行を出力したり、まったく出力を生成できなかったりすることがあります。 インデックスを削除してインプレース フィルタリングを試みると、インデックスのシフトにより要素がスキップされる可能性があるため、別の問題が発生します。 たとえば、`[59, 58, 61]`、59 を削除すると、その場所に 58 がシフトされ、インデックスベースのループは、反復の構造に応じてチェックをスキップする可能性があります。 

## アプローチ

 この問題を考える最も直接的な方法は、文字通りプロセスをシミュレートすることです。つまり、リストをスキャンして 60 未満の要素を削除します。抽象的な意味では、これは仕様と正確に一致するため、正しいです。 ただし、Python リスト内で削除を実装するとコストがかかります。 削除するたびに、後続のすべての要素が 1 つ左に移動し、最悪の場合、削除ごとに O(n) のコストがかかります。 ほとんどの要素が小さい場合、ほとんどすべてのエントリが削除され、O(n²) の動作が発生する可能性があります。 

構造的な洞察は、リストを適切に変更しない場合には削除は不要であるということです。 代わりに、新しいリストを作成し、有効な要素のみを追加できます。 リストへの追加は一定時間で償却されるため、これにより各要素の処理コストが O(1) に変換されます。 問題は、条件をテストして要素を前方にコピーするかどうかを決定する単一の線形スキャンに帰着します。 

これが効率的に機能する理由は、保持される要素の出力順序が入力順序と同じであるためです。 決定間に依存関係がないため、各グレードを独立して評価できます。 元のコンテナを保存しようとするのをやめ、代わりにフィルタリングされたコンテナを構築すると、複雑さは潜在的に 2 次から線形に崩壊します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 反復中のインプレース削除 | O(n²) | お(1) | 遅すぎる |
 | フィルタリングされたリストを作成する | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 等級数を読み取る`n`。 これは、一度に正確に検査する値の数を定義します。 
2. 空のリストを初期化する`result`これには、しきい値チェックに合格したすべてのグレードが保存されます。 
3. それぞれを反復処理します。`n`入力から読み取られた評価。 
4. 各等級について、60 と比較します。 
5. 成績が 60 以上の場合は、それを追加します。`result`。 それ以外の場合は完全に無視してください。 
6. すべての成績を処理した後、各値を次のように出力します。`result`追加されたのと同じ順序で独立した行に記述します。 

重要な設計上の選択は、入力シーケンスを決して変更しないことです。 各決定は単一要素に対してローカルであるため、将来の反復に影響を与える可能性のある副作用を回避します。 

### なぜ効果があるのか

 スキャンの各ステップで、`result`これまでに確認された少なくとも 60 個のすべてのグレードのシーケンスが、入力に出現したのと同じ順序で正確に含まれます。 新しいグレードを処理するとき、それが 60 未満の場合は破棄し、有効な場合は最後に追加します。 これにより、フィルタリングの正確さと順序付けの安定性の両方が維持されます。 すべての要素は 1 回だけ検査され、その要素が含まれるかどうかはその要素自体の値のみに依存するため、後の操作によって以前の決定が無効になることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    result = []

    for _ in range(n):
        x = int(input())
        if x >= 60:
            result.append(x)

    sys.stdout.write("\n".join(map(str, result)))

if __name__ == "__main__":
    main()
```このソリューションでは、高速入力を使用します。`sys.stdin.readline`標準では最大 100,000 行を読み取ることができるため、`input()`不要なオーバーヘッドが発生する可能性があります。 各成績は読み取り直後に処理され、有効な成績のみが保存されます。 

実装の微妙な詳細は、最終出力の構築です。 行ごとに出力する代わりに、すべての有効な整数を 1 つの文字列に結合します。 これにより、厳しい制限下では Python で遅くなる可能性がある I/O 呼び出しの繰り返しが回避されます。 

もう 1 つのポイントは、次のような場合の処理​​です。`result`は空です。 結合操作では、当然のことながら、余分な行のない、必要な出力形式と一致する空の文字列が生成されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各グレードは 1 回読み取られ、1 回チェックされます。 
| スペース | O(k) | グレード ≥ 60 (k ≤ n | ) のみを保存します。 

このアルゴリズムはグレードの数に比例してスケールします。これは、すべての入力要素を少なくとも 1 回検査する必要があるため、最適です。 n が最大 100,000 であるため、これは時間とメモリの両方の制約内に無理なく収まります。

 ## 特殊なケース

 全ての学年が60未満の場合など`10, 20, 30`、アルゴリズムは依然として各値を反復処理し、単純に何も追加しません。 結果は空のリストのままであり、結合操作により空の文字列が生成されます。この文字列は、余分な行がなく、必要な出力形式に正しく一致します。 

すべてのグレードが有効な場合、たとえば`60, 80, 100`、すべての要素が条件を満たし、順番に追加されます。 このアルゴリズムは事実上、入力の直接コピーとなり、意図しない変換が発生しないことを確認します。 

次のように、値がしきい値の周囲で交互に現れる場合`59, 60, 58, 61`、それぞれの決定は独立しています。 スキャンの結果、拒否された値がその後の承認に影響を与えず、順序が必要どおりに正確に保持されていることがわかります。
