 ## 解決策
 ## 問題の理解

 文字のみで構成されるバイナリ文字列が与えられます`0`そして`1`。 隣接するパターンを繰り返し見つけることができます`"01"`そしてそれを文字列から完全に削除し、削除によって生じたギャップを埋めます。 なくなるまでこれを続けます`"01"`部分文字列は文字列内の任意の場所に存在します。 タスクは、最終的な安定した文字列とその長さを出力することです。 

このプロセスに関する重要な観察は、削除は局所的であるが、その影響はグローバルであるということです。 1 つ削除する`"01"`新しいものを作成できる`"01"`したがって、削除の順序は実装では重要ですが、最終結果では重要ではありません。 

入力サイズは最大です`10^5`これにより、単純な方法で文字列を繰り返しスキャンし、途中の部分文字列を削除するアプローチが除外されます。 1 回の削除には O(n) のコストがかかる可能性があり、最悪の場合は O(n) 回の削除が実行され、制約の下では遅すぎる O(n^2) の動作が発生する可能性があります。 これは、線形または線形に近いシミュレーションが必要であることを直ちに示唆しています。 

カスケード削除が発生するように 0 と 1 がインターリーブされる場合、微妙なエッジ ケースが発生します。 たとえば、`"0101"`、最初の部分を削除します`"01"`葉`"01"`再度削除すると、別の削除が可能になります。 新しく形成された境界を再考しない単純な左から右への単一パスは、ここでは失敗します。 

もう 1 つの重要な観察は、この操作では削除されるだけであるということです。`"01"`、 一度もない`"10"`。 この非対称性が、最終的な文字列の構造を決定します。 

## アプローチ

 直接シミュレーションのアプローチでは、文字列を維持し、繰り返しスキャンして、`"01"`、何も残らなくなるまでオカレンスを削除します。 これは許可された操作を正確に反映しているため、これは正しいです。 ただし、各スキャンは O(n) であり、削除のたびに文字列がシフトされ、これも O(n) です。 交互パターンなど、削除が何度も発生する最悪の場合、合計実行時間は 2 次関数になります。 

重要な洞察は、明示的な削除を避け、代わりにスタックのようなプロセスを使用してキャンセルをシミュレートすることです。 左から右にスキャンすると、`1`、以前の不一致をキャンセルする可能性があります`0`それなら`0`スタックですぐに利用可能になります。 それぞれ`"01"`削除はペアリングに対応します`0`先に現れたものと後に現れたもの`1`。 これは、一致しないゼロがまだ利用可能であるかどうかを追跡するだけで十分であることを示唆しています。`1`どちらかをキャンセルするか、生き残る。 

これにより、単一のカウンターまたはゼロのスタックを維持するという問題が軽減されます。 それぞれ`0`今後の中止候補として推されており、それぞれ`1`そのような候補が 1 つ存在する場合は削除します。 残っているのは、一致しないゼロと、その左側にあるものをキャンセルできなかった一致しないゼロです。

 | --- | --- | --- | --- |
 | ブルートフォースによる繰り返し削除 | O(n²) | O(n) | 遅すぎる |
 | スタック / カウンタ シミュレーション | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まだ削除できなかった一致しない文字を格納するスタックを維持しながら、文字列を左から右にスキャンします。 

スタックは、処理されたプレフィックスの現在の縮小形式を表します。 
2. キャラクターごとに、取り外し可能なキャラクターを形成するかどうかを決定します。`"01"`スタックの一番上のパターン。 

取り除くだけです`"01"`、したがって、唯一有用なキャンセルは、次の場合です。`1`そしてスタックトップは`0`。 
3. 現在のキャラクターが`0`、後で将来によって削除される可能性があるため、スタックにプッシュします。`1`。 
4. 現在のキャラクターが`1`、スタックが空でなく、その最上位が空であるかどうかを確認します。`0`。 もしそうなら、それをポップしてください`0`の削除を表します。`"01"`ペア。 それ以外の場合はプッシュ`1`スタックに。 
5. 文字列全体を処理した後、スタックには最終的な還元不可能な文字列が含まれます。 その長さと内容を出力します。 

機能する理由: スキャンのどの時点でも、スタックは内部のプレフィックスを持たない縮小形式を維持します。`"01"`残りのペア。 どんな未来でも`1`以前とのみ対話できます`0`s とスタックにより、常にペアになることが保証されます。`1`利用可能な最新のものを使用して`0`、これがまさに唯一の状況です。`"01"`削除が発生する可能性があります。 有効な削除はすべて 1 回だけシミュレートされ、無効なペアリングは導入されないため、最終スタックは一意の固定点となり、`"01"`残っています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    stack = []

    for ch in s:
        if ch == '0':
            stack.append('0')
        else:
            if stack and stack[-1] == '0':
                stack.pop()
            else:
                stack.append('1')

    print(len(stack))
    print(''.join(stack))

if __name__ == "__main__":
    solve()
```ソリューションは文字列を 1 回読み取り、各文字を順番に処理します。 スタックは、純粋に、一致しないシンボルのシミュレーション ツールとして使用されます。 唯一重要な決定は、`1`: 前のをキャンセルできるかどうかを確認します`0`。 これが唯一の有効な削除パターンであるため、他のケースは必要ありません。 

最終出力は、後処理を行わずにスタックから直接構築されます。 

## 実用的な例

 ### 例 1:`00011`スタックを維持しながら各文字を処理します。 

| ステップ | シャア | 前にスタック | アクション | 後にスタック |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | [] | 0を押します | [0] |
 | 2 | 0 | [0] | 0を押します | [0,0] |
 | 3 | 0 | [0,0] | 0を押します | [0,0,0] |
 | 4 | 1 | [0,0,0] | ポップ0 (フォーム01) | [0,0] |
 | 5 | 1 | [0,0] | ポップ0 (フォーム01) | [0] |

 最終的なスタックは`[0]`、したがって出力は長さになります`1`と文字列`"0"`。 

これは、複数の`1`は、以前のゼロを繰り返しキャンセルすることができ、明示的に削除せずにプロセスがどのように自然に収束するかについて説明します。 

### 例 2:`11010101011011111110101`スタックの進化に焦点を当てた凝縮されたトレースを示します。 

| プレフィックス | シャア | スタックトップアクション | スタック |
 | --- | --- | --- | --- |
 | 1 | 1 | プッシュ | [1] |
 | 2 | 1 | プッシュ | [1,1] |
 | 3 | 0 | プッシュ | [1,1,0] |
 | 4 | 1 | ポップ0 | [1,1] |
 | 5 | 0 | プッシュ | [1,1,0] |
 | 6 | 1 | ポップ0 | [1,1] |
 | ... | ... | 度重なるキャンセル | ... |
 | 最終 | - | 安定した | [1,1,1,1,1,1,1,1,1] |

 このプロセスでは、あらゆる機会が繰り返し削除されます。`1`先行するものを消費する`0`。 そのようなペアがすべて使い果たされると、一致しないものだけが残ります`1`s が残り、期待される出力と一致します`"111111111"`。 

このトレースは、すべての 0 が最終的にその右側に一致する 1 を見つけるため、長い交互構造が 1 の単調なブロックに崩壊することを強調しています。

 ## 特殊なケース

 重大なエッジケースは、以前に分離された領域にわたって削除がカスケードする場合です。 考慮する`0101`。 最初`"01"`除去葉`"01"`、これもまた取り外し可能なペアを形成します。 スタックはこれを自動的に処理します: 処理後`0`、スタックは`[0]`、 それから`1`ポップして去ります`[]`、次へ`0`プッシュして最後に`1`再びポップすると、空のスタックが生成されます。 スキャンを繰り返す必要がなく、出力は正確です。 

もう 1 つのエッジ ケースは、多くの 1 で始まり、その後にゼロが続く文字列です。`111000`。 ないので`"01"`出現してもスタックは増大するだけで、アルゴリズムは文字列全体を保持します。 これは、この方法が過剰に除去しないことを確認します。`"10"`許可されていない操作であるパターン。 

最後のエッジケースは、文字列が空になる場合です。 次のようなシーケンス`000111`すべてのゼロが最終的にその右側に一致するものを見つけるため、完全に減少します。 スタックは自然に空になり、アルゴリズムは長さを正しく出力します。`0`そして空の文字列。
