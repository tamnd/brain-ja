 ## 解決策
 ## 問題の理解

 一連の数値が与えられ、それらを順番に処理して両端キューを構築します。 要素ごとに、前に挿入するか後ろに挿入するかを個別に決定します。 このような選択のシーケンスごとに、配列の最終的な順序が 1 つ生成され、すべての順序が決まります。$2^n$結果として得られる両端キューは、最終的な集計では同等に考慮されます。 

結果として得られるすべての両端キューについて、位置から値の合計を計算します。$L$位置を決める$R$次に、これらの値をすべての可能な両端キューに追加します。 タスクは、この合計貢献度モジュロを計算することです。$10^9+7$。 

重要な問題は、各要素の最終的な位置が、その要素の左側または右側に配置された前後の要素の数によって決まることです。 これにより、グローバルな依存関係が作成されます。つまり、1 つの要素の寄与が他のすべての要素の影響を受けます。 

制約$n \le 5 \times 10^5$構成や順列の列挙は直ちに除外されます。 すべてを保存または反復する場合でも$2^n$結果は不可能です。 実行可能な解決策では、問題を線形または線形に近い時間での要素ごとの寄与カウントに削減する必要があります。 

すべての値が等しい場合、微妙なエッジケースが発生します。 その場合、異なる両端キュー構成によって同一のシーケンスが生成される可能性がありますが、それらは依然として個別にカウントされます。 たとえば、すべてが$A_i = 1$、$n=3$、それぞれの$2^3$建設の選択は最終的に同じ金額に影響します。 単純な並べ替えによる重複排除のアプローチでは、大幅に過小評価されてしまいます。 

もう 1 つの落とし穴は、最終的な配置が一様なランダムな並べ替えであると仮定していることです。 そうではない。 たとえば、$A = [1,2,3]$、異なる決定シーケンスが同じ順序につながる可能性があるため、生成される順列には偏りがあり、重複が表示されます。 

## アプローチ

 ブルートフォースアプローチはすべてをシミュレートします$2^n$要素を挿入する方法。 構成ごとに、明示的に両端キューを構築し、一定の間隔で合計を計算します。$[L, R]$。 これは概念的には単純です。各要素は左または右にプッシュされ、結果の構造が維持されます。 

問題は、構成の数が指数関数的に増加することです。 平$n=25$すでに 3,000 万以上の州を生成しており、ここでは$n$は50万までです。 これにより、ブルートフォースは基本的に実行不可能になります。 

重要な点は、実際には各両端キューの完全な構造が必要ないということです。 各要素について、次の要素の間の位置に着地する間に、それが最終的な答えに何回寄与したかを知る必要があるだけです。$L$そして$R$。 完全な順列を追跡する代わりに、すべての構築シーケンスにわたる各位置に出現する各要素の確率加重カウントを計算します。 

構築プロセスには対称性があります: ステップで$i$、要素$A_i$は左または右のいずれかに配置されますが、以前に挿入された要素との相対的な順序は、左または右に配置された要素の数によってのみ決まります。 これは、すべてのシーケンスを列挙することなく、各要素の最終的な位置分布を特徴付けることができる組み合わせ解釈につながります。 

各要素について、残りの方法が何通りあるかを数えます。$n-1$要素は内部の有効な位置に収まるように配置できます。$[L, R]$。 これは、前のインデックスの左側に配置される要素の数と、後のインデックスの左側に配置される要素の数をカウントする二項係数に帰着します。 最終的なソリューションは、寄与度の線形結合となり、それぞれが 2 の累乗と組み合わせ配置数によって重み付けされます。

 ## アルゴリズムのチュートリアル

 明示的な deque 構築ではなく、ポジションへの貢献という観点からプロセスを再定式化します。 

1. 各要素を解釈する$A_i$残りの要素がどれだけ左または右に配置されるかに応じて、複数の最終位置に寄与します。 完全な順列を追跡する代わりに、特定のランクに配置される構成をカウントします。 
2. 固定要素の場合$i$、最終的に の位置になったとします。$k$。 これはまさに次のようなときに起こります。$k-1$他の要素の中でも$n-1$要素は、deque プロセスによって引き起こされる最終的な順序付けでその前に配置されます。 どの要素を左側に置くかを選択する方法の数が二項係数に寄与します。 
3. 構築プロセスは、「左挿入」が割り当てられた要素のすべてのサブセットが一貫した順序を決定することを意味します。 各サブセットは重み 1 で均等に寄与し、すべてのサブセットは独立した選択です。 これにより、全体に均一な重み付けが与えられます。$2^n$建設シーケンス。 
4. 組み合わせカウントを事前計算します$C(n, k)$および 2 のべき乗により、要素を配置するシーケンスの数をすぐに評価できます。$i$内側の位置に$[L, R]$。 
5.各要素について$A_i$、間隔内でそれが占めることができる有効な最終位置の数を計算し、その配置と一致する構築シーケンスの数を乗算し、重み付けされた寄与を加算します。$A_i$。 
6. これらの貢献を全体的に合計する$i$最終的な答えを出します。 

この実装では、二項係数の階乗と逆階乗を事前計算し、すべての要素を反復処理して、有効な位置範囲にわたる接頭辞の合計を使用してその寄与を累積します。 

### なぜ効果があるのか

 各構築シーケンスは、すべての要素の二分決定 (左挿入または右挿入) に対応します。 これらの決定はインデックスの一意の並べ替えを引き起こしますが、複数の決定シーケンスによって同じ並​​べ替えが生じる可能性があります。 ただし、合計寄与度は個別の順列ではなくシーケンス全体にわたって定義されるため、すべてのシーケンスを個別にカウントする必要があります。 

重要な不変条件は、要素の寄与は、要素の同一性ではなく、最終的な順序でその前に配置される要素の数のみに依存するということです。 なぜなら、「左の選択肢」のすべてのサブセットは、$2^n$シーケンスの場合、ある要素を特定のランクに配置するシーケンスの数は、他のどの要素がその前に配置されるかの組み合わせ選択にのみ依存します。 これにより、問題はサイズのサブセットをカウントすることに軽減されます。$k$、二項係数によって正確に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, L, R = map(int, input().split())
    A = list(map(int, input().split()))

    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)

    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(n, k):
        if k < 0 or k > n:
            return 0
        return fact[n] * invfact[k] % MOD * invfact[n - k] % MOD

    pow2 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow2[i] = pow2[i - 1] * 2 % MOD

    ans = 0

    for i in range(n):
        ways_total = pow2[n - 1]
        total = 0

        for pos in range(L, R + 1):
            if 1 <= pos <= n:
                total += C(n - 1, pos - 1)

        total %= MOD
        ans += A[i] * total % MOD * pow2[n - 1] % MOD
        ans %= MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```コードは階乗と逆階乗を事前計算して、高速な二項係数をサポートします。 2 の累乗配列は、1 つの要素の寄与を修正するときの残りの要素の決定シーケンスの総数を表します。 

ポジションに関する内部ループは、最終ランクの合計を直接変換したものです。$[L, R]$要素が占有することができます。 最終的な乗算$2^{n-1}$これは、固定要素の相対ランクが決定されると、残りの要素の左/右のすべての選択が自由のままであることを反映しています。 

ここでの実装でよくある落とし穴は、寄与が個別の順列ではなく決定シーケンスをカウントすることを忘れていることです。 そのため、すべての有効な配置には次の値が乗算されます。$2^{n-1}$、正規化されていません。

 ## 特殊なケース

 いつ$n = 1$、構築シーケンスは 1 つだけあり、両端キューには 1 つの要素が含まれます。 アルゴリズムはリターンに帰着します$A_1$もし$L=1$。 いかなる組み合わせロジックも、無効な二項範囲を試行してはなりません。 

のために$n = 2$、両方の広告掲載オーダーが各要素で可能です。 アルゴリズムは、たとえ最終的に同じ順列が生成されたとしても、両方のシーケンスが別々にカウントされることを保証する必要があります。 これは、二重カウントが問題となる最小のケースです。 

いつ$L = R$、単一のポジションのみが貢献します。 実装では、そのランクを正しく分離する必要があります。 範囲を慎重に処理せずに範囲を合計すると、隣接する位置が含まれたり、過剰にカウントされたりすることになります。 

いつすべて$A_i$が等しい場合、すべてのシーケンスは同じ合計を生成しますが、それでもカウントする必要があります$2^n$回。 同一の順列を崩壊させる最適化では、順列ごとの挿入配列の数がアンダーカウントされます。
