 ## 解決策
 ## 問題の理解

 グリッドの原点から開始して、ターゲット座標に到達したいと考えています$(x, y)$。 現在の位置から、ウサギには 3 つの可能な動きがあります。コストをかけて右に 1 歩移動できます。$A$、コスト的にはワンステップアップ$B$または、コストを考慮して両方の座標を 2 倍にスケールすることもできます。$C$。 目標は正確に達成することです$(x, y)$最小限の総コストで。 

主な難点は、倍増移動がグリッド ステップに関連付けられておらず、代わりに両方の座標のスケールを同時に変更することです。 これにより、ターゲット座標を単位ステップで段階的に構築するか、より小さいバージョンを構築して繰り返し 2 倍にするかの間でトレードオフが生じます。 

制約により、最大で次のことが許可されます。$10^4$最大の座標を持つテスト ケース$10^9$。 これにより、座標に対する状態空間検索や、次の値に依存する動的プログラミングが即座に排除されます。$x$そして$y$直接。 ソリューションでは、各テスト ケースを対数推論、または定数時間推論に削減する必要があります。 

問題を 2 つの独立した 1 次元の最適化として扱う場合、単純な落とし穴が発生します。 例えば、どうやって建てるかを個別に決めると、$x$そして$y$2 倍にすることは両方に同時に影響し、場合によってはオーバーシュートして結果を逆方向に「整形」する方が安くなるという事実を見逃してしまいますが、これはインクリメントとスケーリングのみが存在するため許可されていません。 

もう 1 つの微妙な問題は、次の場合に 2 倍演算が常に有益であると仮定していることです。$C < A + B$。 これでは十分ではありません。倍増の前後によって必要な単位の増分数が変化するからです。 たとえば、到達する$(4, 4)$から$(0,0)$構築するかどうかに応じて、異なるシーケンスが優先される場合があります。$(2,2)$最初か到達するか$(4,0)$そして$(4,4)$別に。 

3 番目のエッジケースは次の場合に発生します。$x = 0$または$y = 0$。 その場合、1 つの座標は無関係になり、問題は 2 倍演算を使用する 1 次元に縮小されます。この演算は、単位ステップを繰り返すよりも安いかどうかに応じて、役立つかどうかが決まります。 

## アプローチ

 ブルートフォースアプローチでは、各ポジションを状態として扱い、BFS またはダイクストラを使用して可能なすべての一連の動きを探索します。 各州$(x, y)$に移行できます$(x+1, y)$、$(x, y+1)$、 または$(2x, 2y)$。 原理的には正しいですが、グラフは膨大です。 までの値に制限しても、$10^9$の場合、エッジが 2 倍になると逆に指数関数的な分岐が発生し、最短経路の検索は直ちに実行できなくなります。 到達可能な状態の数は座標の大きさとともに増加するため、以下の条件下では直接の横断が不可能になります。$T = 10^4$。 

重要な構造的観察は、以下から逆算して考えると、このプロセスは有益な方法で可逆的であるということです。$(x, y)$。 前向きに構築する代わりに、ターゲットを減らすことを検討できます。$x$そして$y$が偶数であれば、からの 2 倍演算を介して到達した可能性があります。$(x/2, y/2)$。 それ以外の場合は、単位増分を使用して少なくとも 1 つの座標に到達している必要があります。 

これは、貪欲な後方削減戦略を示唆しています。つまり、2 倍化を「元に戻す」のが良いか、単位ステップを「元に戻す」のが良いかを繰り返し決定します。 コスト倍増を元に戻す$C$, ただし、これは両方の座標が偶数の場合にのみ可能です。 それ以外の場合は、どちらかから 1 を減らさなければなりません$x$または$y$、支払い$A$または$B$。 有効なシーケンスの最後の操作はパリティ制約によって決定されるため、各ステップでの決定は局所的かつ最適になります。 

に到達するまで問題を繰り返し縮小します。$(0,0)$。 これにより、テスト ケースごとに対数のステップ数が生成され、テスト ケースのビット数によって制限されます。$x$そして$y$。

 ## アルゴリズムのチュートリアル

 から逆算して作業します$(x, y)$に$(0, 0)$、常に現在の状態を生成した可能性のある最後の操作を選択します。 

1. 両方の場合$x = 0$そして$y = 0$、終わりました。 これまでに蓄積されたコストの合計が答えです。 
2. 両方の場合$x$そして$y$が偶数である場合、最後の動きが 2 倍演算であった可能性があることを考慮してください。 そのコストを比較してみます$C$その代わりに、以前のスケールで 2 つの独立した単位操作を使用して同じ状態に到達するというコストがかかります。 2 倍の方が安いか等しい場合は、両方の座標を 2 で割って加算します。$C$答えに。 このステップでは、2 倍演算の構造を尊重しながら状態を大幅に圧縮します。 
3. 少なくとも 1 つの座標が奇数である場合、最後のステップとして 2 倍にすることはできません。 ユニットの移動を元に戻さなければなりません。 減らすか比較する$x$または減らす$y$安いかどうか、つまり$A$または$B$より小さいです。 単価の小さい座標から減算します。 これにより、非対称性を生み出す最終ステップに必要以上の費用を支払うことがなくなります。 
4. 両方の座標がゼロになるまで繰り返します。 

重要な点は、パリティによって最後の動きの構造が強制されることです。 状態が偶数対偶の場合、それが倍増から来たのか、それとも長い一連のユニット移動から来たのかは曖昧ですが、最適解はそのスケールで 2 つの可能性のうち安価な方を選択します。 状態が偶数偶数でない場合、2 倍化は構造的に不可能であるため、最後の手は 1 つの座標の単位増分でなければなりません。 

### なぜ効果があるのか

 からのすべての有効なパス$(0,0)$に$(x,y)$最終的な動作を確認することで一意に分解できます。 もし$(x,y)$が偶数-偶数の場合、最終演算は次の 2 倍のいずれかです。$(x/2,y/2)$または、両方の座標を現在のパリティ状態に個別に構築する一連の単位ステップ。 ユニット ステップとダブリングがこのパリティ構成に到達する唯一の方法であるため、それらのコストをローカルで比較すると、最適な最後の遷移が得られます。 この推論を繰り返すと、各削減ステップが最適な下部構造を保持することが帰納的に保証されるため、累積コストはグローバル最小値に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(x, y, A, B, C):
    ans = 0
    while x > 0 or y > 0:
        if x % 2 == 0 and y % 2 == 0:
            if C < A + B:
                ans += C
                x //= 2
                y //= 2
            else:
                if x == 0:
                    ans += B
                    y -= 1
                elif y == 0:
                    ans += A
                    x -= 1
                else:
                    if A <= B:
                        ans += A
                        x -= 1
                    else:
                        ans += B
                        y -= 1
        else:
            if x % 2 == 1:
                ans += A
                x -= 1
            else:
                ans += B
                y -= 1
    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        x, y, A, B, C = map(int, input().split())
        out.append(str(solve_one(x, y, A, B, C)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```このソリューションは、後方リダクションを直接実装します。 ループは両方の座標がゼロに達するまで継続し、各ステップでどちらかが厳密に減少するため、確実に終了します。$x+y$または両方の値を半分にします。 

最もデリケートな部分は偶数の場合です。 両方の座標が 2 で割り切れる場合、コードは 2 倍化ステップを適用するコストと単位削減の支払いコストを比較します。 比較には、$C < A + B$2 倍化を元に戻すことは、以前に 2 つの半分を個別に構築したことに相当するため、しきい値として使用します。 2 倍にすることが有益でない場合、アルゴリズムは安価な座標から 1 単位を減算することに戻ります。 

奇数座標の場合は、以前の 2 倍化では奇数座標が生成されなかったため、単位のデクリメントが強制されます。

 ## 特殊なケース

 いつ$(x,y) = (0,0)$の場合、ループは決して実行されず、操作は必要ないため、答えは正確にゼロになります。 

たとえば、1 つの座標がゼロの場合、$(0, k)$の場合、偶数-偶数条件は部分的にしか役に立たないため、アルゴリズムは 2 倍化を考慮しません。 ゼロ以外の座標から繰り返し減算し、支払いを行います。$B$毎回、唯一の実現可能な構築パスと一致します。 

両方の座標が 2 のべき乗である場合、$C$は小さく、各ステップですぐに繰り返し半分化トリガーが実行され、対数時間で状態がゼロに減少し、繰り返し行われた 2 倍化演算のコストが正確に蓄積されます。 

コストのバランスが著しく崩れている場合$A \ll B$、アルゴリズムは一貫して、より安価な軸を介してより大きなコストの座標を排出し、パリティ制約の解決に必要以上のコストを支払うステップがないことを保証します。
