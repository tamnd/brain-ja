 ## 解決策
 ## 問題の理解

 0 から n までの整数の連続したリストが与えられます。 隣接する数値の各ペアの間にプラス記号またはマイナス記号を挿入することができ、各数値が累計にプラスに寄与するかマイナスに寄与するかを効果的に決定できます。 タスクは、結果の式が正確に x と評価されるような符号の選択肢があるかどうかを判断し、そうである場合は有効な式を構築することです。 

式の構造は固定されており、符号のみが異なります。 各数値 i は +i または -i に寄与するため、問題は、符号付き合計がターゲットと一致する数値のサブセットを選択することになります。 

制約は小さく、n は最大 100 です。これにより、高度な最適化手法やヒューリスティックを使用した枝刈りの多い検索の必要性が即座に排除されます。 多項式時間で実行されるソリューションは、たとえ O(n^2) または O(n^3) であっても、十分に高速です。 

重要な観察は、0 から n までのすべての数値の合計が n(n+1)/2 であるということです。 符号付き式は、この合計から始まり、特定の要素の符号を反転して、選択した要素の合計の 2 倍を効果的に減算すると見なされます。 この対称性は、-S から S までの到達可能な範囲を定義します。ここで、S は合計です。 

x がこの範囲外にある場合、エッジ ケースが発生します。 たとえば、n = 4 の場合、S = 10 となるため、x = 15 は不可能です。 実現可能性をチェックせずに貪欲に符号を割り当てようとする単純な実装でも式は生成できますが、ターゲットには一致しません。 

複数の構造が存在する場合、別の微妙なケースが発生します。 この問題では、辞書編集上の最小構造や最適な構造ではなく、有効な式のみが必要です。 これにより、より大きな数から下に向かって貪欲に構築することが可能になります。 

## アプローチ

 ブルートフォース手法では、すべての 2^n 符号の割り当てが試行されます。 各割り当ては、否定する数値のサブセットを選択することに対応します。 構成ごとに、結果の合計を計算します。 これは、考えられるすべての式を列挙しているため正しいですが、可能性の数は指数関数的に増加します。 n = 100 になると、これは天文学的に大きくなり、使用できなくなります。 

問題をより構造化した方法で再定式化できます。 総和 S = 0 + 1 + ... + n から開始します。 数値 i にマイナス記号を割り当てることにした場合、その寄与は +i から -i に変わり、合計が 2i 減ります。 したがって、否定する数値のセットを選択することは、合計が (S - x) / 2 に等しいサブセットを見つけることと同じです。 

これにより、問題は小さな n と小さな総和 S ≤ 5050 のサブセット和に変換されます。可能な和に対する動的計画法も機能しますが、カウントや最適化ではなく 1 つの構築のみが必要なため、完全な DP さえ必要ありません。 

数値が大きいほど調整力が大きくなるため、貪欲な構築が機能します。 n から 1 までの数値を処理し、各数値を反転することで残りの必要な調整に近づくかどうかを判断します。 これは、制限された範囲内での決定論的なサブセット合計の再構成のように動作します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | サブセット DP | O(n・S) | O(S) | 承認済み |
 | 貪欲な再構築 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 完全な正の合計からの偏差に関してターゲット方程式を書き直します。

1. S = n(n+1)/2 を計算します。 すべての符号がプラスの場合の値です。 
2. x が [-S, S] の外側にある場合は、符号反転の組み合わせがこれらの境界を超えることができないため、すぐに IMPOSSIBLE を返します。 
3. 必要な調整 D = S - x を定義します。 これは、符号を反転して減算する必要がある合計金額です。 
4. D が奇数の場合は、IMPOSSIBLE を返します。 反転するたびに合計が 2i ずつ変化するため、すべての調整は均等になります。 
5. 次に、合計が D/2 に等しい数値を選択する必要があります。 
6. 残り = D/2 を初期化します。 
7. i を n から 1 まで繰り返します。各 i について、i ≤ 残りの場合、i を否定し、残りから i を減算することを選択します。 それ以外の場合は、ポジティブなままにしてください。 
8. 合計には影響しないため、0 は常に +0 のままにしてください。 

符号の割り当てを構築した後、式を出力します。 

これが機能する理由は、すべてのステップで、残りが未処理の数値に対する有効なサブセット合計の剰余を表すという不変条件から来ています。 大きい値から小さい値へ処理するため、可能な場合に i を選択しても、将来の実現可能性が妨げられることはありません。これより大きい数値はすでに考慮されており、残りの数値の合計が表現可能な残りのギャップよりも常に優勢であるため、より小さい数値でも残りの剰余を完成させるのに十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    
    S = n * (n + 1) // 2
    
    if x < -S or x > S:
        print("IMPOSSIBLE")
        return
    
    D = S - x
    
    if D % 2 != 0:
        print("IMPOSSIBLE")
        return
    
    target = D // 2
    sign = ['+'] * (n + 1)
    
    for i in range(n, 0, -1):
        if i <= target:
            sign[i] = '-'
            target -= i
    
    expr = []
    for i in range(n + 1):
        expr.append(f"{sign[i]}{i}")
    
    print("".join(expr))

if __name__ == "__main__":
    solve()
```実装は、符号の割り当てからサブセット合計への削減の直接の後に行われます。 配列`sign`各数値がプラスに寄与するかマイナスに寄与するかを格納します。 すべてを正として初期化し、残りの必要な調整に適合するときに大きな数値を貪欲に反転します。 次に、式が 0 から n までの順序で出力されます。 

微妙な点は、すべての符号が「+」として初期化されていることです。 0 は常に含める必要があり、正確さに影響を与えてはならないため、これは重要です。 もう 1 つは、n から下方向に反復することで、より大きな寄与が最初に決定されることを保証し、これが貪欲な構築を有効にするものです。 

## 実用的な例

 ### 例 1: n = 3、x = 6

 S = 6、つまり D = 0、ターゲット = 0。 

| 私 | | までに残っています 決定 | | 以降の残り サイン |
 | --- | --- | --- | --- | --- |
 | 3 | 0 | スキップ | 0 | + |
 | 2 | 0 | スキップ | 0 | + |

 最終的な式は +0+1+2+3 で、6 と評価されます。 

このトレースは、ターゲットがすでに最大合計に等しいため、フリップが必要ない場合を示しています。 

### 例 2: n = 4、x = 9

 S = 10、つまり D = 1、target = 0.5 ですが、これは D が奇数であるため無効であるため、すぐに拒否します。 

構築は試みられていません。 

これはパリティ制約を示しています。反転するたびに合計が偶数だけ変化するため、奇数の調整に達することは不可能です。

 ## 特殊なケース

 n = 1 の場合、解は x = 1 と x = -1 の両方を正しく処理する必要があります。 アルゴリズムは S = 1 を計算します。x = 1 の場合、D = 0 であるため、反転は発生せず、出力は +0+1 になります。 x = -1、D = 2 の場合、target = 1 になります。1 ≤ target であるため、数値 1 を反転して、+0-1 を生成します。これは要件に一致します。 

x = S の場合、アルゴリズムは D = 0 とみなし、すべての符号を正のままにします。 これにより、不必要な操作を行わずに式が完全な合計に折りたたまれます。 

x = -S の場合、D は 2S になるため、ターゲットは S になります。貪欲ループは、n から 1 までのすべての数値を反転し、ターゲット全体を数値ごとに 1 回だけ消費します。 これにより、すべての負の符号が得られ、可能な最小の合計と一致します。
