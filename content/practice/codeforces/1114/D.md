 ## 解決策
 ## 問題の理解

 の行が与えられています`n`色付きの正方形。それぞれの色を表す整数がラベル付けされています。 目標は、一連の「塗りつぶし」操作を使用して、行全体を単一の色に再色付けすることです。 各操作では、選択した開始正方形を含む同じ色の連続したセグメントが選択され、そのすべての正方形が別の色に変更されます。 開始マス自体は 1 回選択され、移動としてカウントされません。 

入力により、正方形の数と色の順序が与えられます。 出力は、すべての正方形を同じ色にするために必要な最小ターン数です。 

と`n`5000 までは、考えられるすべての一連の動きを明示的に調べる単純なアルゴリズムでは遅すぎます。 たとえば、すべての可能な開始正方形とすべてのステップですべての色の選択を試みると、検索空間は指数関数的に増大し、簡単に超えてしまいます。`10^6`2秒の制限時間では実行不可能な操作です。 

微妙なエッジ ケースには、すでに均一な行 (この場合、答えは 0) や、各正方形が固有の色を持つ行 (これにより、必要な手数が最大化される) が含まれます。 もう 1 つの注意を要するシナリオは、最適な開始マスが終点ではなく中間のどこかにある場合であり、単純な貪欲なアプローチを超えて検討する必要があります。 

## アプローチ

 ブルートフォースアプローチは、開始正方形の可能なすべての選択と、可能な色の変化のそれぞれのシーケンスをシミュレートすることです。 移動ごとに、接続されたコンポーネントの色を変更し、結果の配列を確認します。 これは原理的には正しく動作しますが、`n = 5000`、シーケンスの数が指数関数的に増加するため、まったく実用的ではなくなります。 

最適化するための重要な洞察は、すべての正方形を個別に追跡する必要がないことを認識することから得られます。 代わりに、連続する同じ色を単一のセグメントに折りたたむことができます。 色の変更はセグメント境界でのみ重要です。 さらに、同じ色の 2 つのセグメントがその間に異なる色を持って表示される場合、最適な戦略により、最小限のステップで中間の色をターゲットの色に変えることでこれらのセグメントをマージできます。 

正式に、動的プログラミング状態を定義します。`dp[l][r]`セグメントを作成するために必要な最小回転数として`l`に`r`(包括的) 単色。 最初と最後のセグメントが同じ色である場合、それらを最適にマージできるため、最も外側の色付けを 1 回少ない操作で行うことができます。 この観察により、次のような再帰的な式が可能になります。```
dp[l][r] = 1 + min(dp[l+1][k] + dp[k+1][r])  for all k such that l <= k < r
```色が変化する位置のみを考慮すればよいことに気づき、さらに最適化します。これにより、効果的な効果が減少します。`n`正方形の総数からセグメントの数まで、多くの場合大幅に小さくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | セグメントの動的プログラミング | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力配列をセグメントに圧縮し、連続する同じ色が 1 つにまとめられます。 一意の色のシーケンスのみを保存します。 これにより、冗長な計算が削減されます。 
2. 2D DP 配列を初期化する`dp`サイズの`m x m`、 どこ`m`セグメントの数です。`dp[l][r]`セグメントの色を変更するための最小移動数を保存します`l`を通して`r`単色に。 
3. 基本ケースを設定します。`dp[i][i] = 1`必要に応じて、セグメントだけを 1 回の操作で単一の色に変えることができるため、すべての単一セグメントに適用されます。 
4. セグメント長を増やして DP テーブルを埋めます。 からのセグメントの場合`l`に`r`:

 - から始める`dp[l][r] = 1 + dp[l+1][r]`セグメントの色を変更すると仮定します`l`残りと一致するように。 
- その後、位置を反復処理します`k`から`l+1`に`r`。 もし`color[l] == color[k]`でセグメントを結合できます。`l`そして`k`そして結果を結合します:`dp[l][r] = min(dp[l][r], dp[l+1][k-1] + dp[k][r])`。 
5. 最終的な答えは次のとおりです。`dp[0][m-1]`、圧縮された行全体の色を変更するための最小移動数。 

**これが機能する理由:** DP の不変条件は次のとおりです。`dp[l][r]`セグメントの色を変更するための最小移動数を常に保存します`[l, r]`。 反復により、同じ色のセグメントがマージされ、中間色が効率的に考慮され、冗長な動きがカウントされなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
colors = list(map(int, input().split()))

# Step 1: Compress consecutive identical colors
comp = []
for c in colors:
    if not comp or comp[-1] != c:
        comp.append(c)

m = len(comp)
dp = [[0] * m for _ in range(m)]

# Step 2: DP base case
for i in range(m):
    dp[i][i] = 1

# Step 3: DP computation
for length in range(2, m+1):
    for l in range(m - length + 1):
        r = l + length - 1
        dp[l][r] = 1 + dp[l+1][r]
        for k in range(l+1, r+1):
            if comp[l] == comp[k]:
                dp[l][r] = min(dp[l][r], dp[l+1][k-1] + dp[k][r])

print(dp[0][m-1])
```コードは最初に色のシーケンスを圧縮します。これにより、意味のあるセグメント境界のみが考慮されるようになります。 長さ 1 のセグメントの基本ケースで DP テーブルを初期化します。 セグメントの長さを増やし、マージ ロジックを使用して DP を更新することを繰り返します。 の`dp`表は、より小さいサブ配列から計算された場合に、すべてのサブ配列の解が最適であることを保証します。 

## 実用的な例

 ### サンプル 1

 | 1 | 1 | 1 | [2] |
 | 2 | 2 | 1 | [2] |

 | 0 | 2 | 2 | 同じですが、合併を検討しています |

 このトレースは、遠い端で色が一致する場合に、セグメントを結合することで移動がどのように減少するかを示しています。 

### サンプル 2

 入力:`5 1 2 3 4 5`すべての色が異なります。 各セグメントは一意であるため、移動するたびに一度に 1 つのセグメントが変更されます。 DP は、隣接しない同じ色の結合は不可能であると計算します。 最小移動数 = 4。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | 圧縮後、各セグメントのペアを検討します。 内部ループは最大で繰り返します`m`回。 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    colors = list(map(int, input().split()))
    comp = []
    for c in colors:
        if not comp or comp[-1] != c:
            comp.append(c)
    m = len(comp)
    dp = [[0] * m for _ in range(m)]
    for i in range(m):
        dp[i][i] = 1
    for length in range(2, m+1):
        for l in range(m - length + 1):
            r = l + length - 1
            dp[l][r] = 1 + dp[l+1][r]
            for k in range(l+1, r+1):
                if comp[l] == comp[k]:
                    dp[l][r] = min(dp[l][r], dp[l+1][k-1] + dp[k][r])
    return str(dp[0][m-1])
