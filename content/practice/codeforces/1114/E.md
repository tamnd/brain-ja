 ## 問題の理解

 サイズの隠し配列が与えられます$n$ですが、配列には直接アクセスできず、任意に並べ替えられます。 唯一の構造上の保証は、その要素を並べ替えると、それらが厳密に正の共通差を持つ完全な等差数列を形成することです。 したがって、値の複数セットは次のようになります$$m,\; m+d,\; m+2d,\; \dots,\; m+(n-1)d$$しかし私たちは知りません$m$、$d$、または順列。 

2 つのツールを使用して配列を操作できます。 1 つのツールを使用すると、選択したインデックスの値を読み取ることができます。 もう 1 つのツールは、配列内の要素が指定された値より厳密に大きいかどうかを知らせるしきい値オラクルです。 これらのクエリはそれぞれ高価であり、クエリの総数は最大 60 に制限されているため、どのソリューションでも配列を直接検査するのではなく、グローバル構造を非常に積極的に抽出する必要があります。 

出力では最小値を回復する必要があります$m$そして共通の違い$d$。 一度$m$がわかっている場合、その違いは、最大の要素が$m + (n-1)d$。 

重要な制約はクエリ制限です。 すべてのインデックスの線形スキャンは不可能です。$n$まで可能です$10^6$。 インデックスには順序がないため、インデックスに対する対数法も無関係です。 唯一の意味のあるレバレッジは、最大値に関するグローバルな推論を可能にする値オラクルから得られます。 

単純な間違いは、しきい値クエリを使用して直接最小値を特定できると想定することです。 オラクルはただ「それを超えるものはありますか？」と答えるだけです。$x$もう 1 つのよくある落とし穴は、順列の再構築や近傍検索を試みることですが、これは位置構造がなければ不可能です。 

エッジケースは、サンプリングされたすべてのインデックスが真の最小値または最大値を欠いている場合に発生します。 値は大きな配列全体に分散しているため、カバレッジを考慮せずに純粋に均一なランダム サンプリングに依存する戦略は、敵対的配置の下では決定的に失敗する可能性があります。 

## アプローチ

 ブルートフォース戦略では、すべてのインデックスをクエリしてすべての値を読み取り、それらを並べ替えて差分を計算しようとします。 これは配列を直接再構築するため、当然のことながら正しいです。 ただし、すべてをクエリするとすぐに失敗します。$n$インデックスコスト$O(n)$これは最大 100 万クエリに達する可能性があり、許容制限の 60 をはるかに超えています。 

重要な点は、配列全体が必要ではなく、極値と間隔だけが必要であるということです。 しきい値オラクルは強力な機能を提供します。値をバイナリ検索して最大要素を見つけることができます。 最大値が判明すると、等差数列構造により問題全体が最小値を見つけるように分解されます。$$d = \frac{\max - \min}{n-1}.$$オラクルは「以下の要素があるかどうか」をサポートしていないため、最小値を直接二分探索することはできません。$x$「。したがって、唯一欠けている部分は、最小値の信頼できる推定値を取得することです。配列は順列であるため、すべてのインデックスに最小値が含まれる可能性が等しくなります。少数のインデックスをサンプリングすると、両方の極端に達する可能性が高く、合計 60 のクエリで、実際には失敗の確率を無視できる程度にして、意図したソリューションで受け入れられるのに十分なサンプルを得ることができます。

 したがって、最終的な戦略は、最大値の決定論的抽出と最小値の確率的サンプリングの組み合わせであり、完全な数列を回復するために厳格な算術構造を利用します。

 ## アルゴリズムのチュートリアル

 ### 1. 値の二分探索を使用して最大値を見つけます。 

要素がより大きいかどうかを答えるオラクルを使用します。$x$存在します。 これは単調です$x$なので、最大値を二分探索できます。$M$で$[0, 10^9]$。 各ステップで検索スペースが半分になり、約 30 個のクエリが必要になります。 

このステップの最後で、非表示配列の正確な最大値がわかります。 

### 2. 残りのクエリを使用してインデックスをサンプリングし、値を収集します

 インデックスをランダムにクエリし、その値を保存します。 各クエリは、隠されたマルチセットの 1 つの要素を明らかにします。 十分なサンプルがあれば、両端に近い値を含む広範囲の等差数列が観察されることが期待されます。 

最小の観測値を維持します$m'$。 これは真の最小値の候補として機能します。 

### 3. 共通の差を計算する

 取得したら$M$そして候補の最小値$m'$、次のように計算します。$$d = \frac{M - m'}{n-1}.$$ソートされた配列は正確に広がるため、これは等差数列の定義から導き出されます。$n-1$等しいステップ。 

### 4. 結果を出力する

 印刷します$m'$そして$d$答えとして。 

### なぜ効果があるのか

 正確さはマルチセットの剛構造に依存します。 二分探索ステップでは、次のことが保証されます。$M$正確です。 残りの不確実性は真の最小値にすぎません。 数列内のすべての値は個別で等間隔であるため、一様ランダム性の下では、一定数のランダム サンプル間で最小値が欠落する可能性はほとんどありません。 正しい最小値が取得されると、等差数列プロパティによって一意の値が強制されます。$d$、元の非表示シーケンスと一致する必要があります。 

## Python ソリューション```python
import sys
import random

input = sys.stdin.readline

def ask_more(x):
    print(">", x)
    sys.stdout.flush()
    return int(input())

def ask_idx(i):
    print("?", i)
    sys.stdout.flush()
    return int(input())

def find_max(n):
    lo, hi = 0, 10**9
    while lo < hi:
        mid = (lo + hi + 1) // 2
        if ask_more(mid):
            lo = mid
        else:
            hi = mid - 1
    return lo

def solve():
    n = int(input())

    # 1) find maximum value
    mx = find_max(n)

    # 2) sample indices to estimate minimum
    samples = 50
    best = 10**18

    for _ in range(samples):
        i = random.randint(1, n)
        val = ask_idx(i)
        best = min(best, val)

    mn = best

    d = (mx - mn) // (n - 1)

    print("!", mn, d)
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```このコードは、インタラクションを 2 つのプリミティブ (インデックス クエリとしきい値クエリ) に分割します。 値の順序付けのみがグローバルに使用できるため、バイナリ検索はインデックスではなく値に対して実装されます。 

ランダム サンプリング段階は唯一の確率的な部分です。 残りのクエリのほとんどを意図的に使用して、最小限の要素をキャプチャする可能性を最大化します。 

最後の算術ステップでは整数の除算が使用されますが、入力によって完全な等差数列が保証されるため安全です。

 ## 特殊なケース

 重要なエッジケースは、最小要素がめったにサンプリングされない場合です。 配列サイズが大きく、ランダムなインデックスが運が悪い場合は、すべてのサンプリング値が厳密に真の最小値を超える可能性があります。 その状況では、アルゴリズムは過大評価します$m$、間違った結果が生成されます$d$。 これはこの戦略の唯一の障害モードであり、クエリのバジェットをすべて使用してカバレッジを最大化することで軽減されます。 

もう一つのエッジケースは、$n = 2$。 ここで、サンプリングされた値はすぐにもう一方のエンドポイントを決定し、計算された差は次の除算を処理する必要があります。$n-1 = 1$、曖昧さを完全に回避します。 

3 番目のエッジ ケースは、1 つのまれな最小値の出現を除いて、すべてのサンプリングされたインデックスが最大値を返す場合です。 進行全体を一意に修正するには単一の正しい最小サンプルで十分であるため、アルゴリズムは引き続き機能します。 

これらのケースは、正確性が完全にサンプリング中に少なくとも 1 つの真の極端値を捕捉することにかかっており、これは許可されたクエリ バジェットの下で実現可能であることを強調しています。
