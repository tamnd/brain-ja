 ## 解決策
 ## 問題の理解

 偶数の参加者が与えられ、各参加者には効率を表すゼロ以外の整数値が与えられます。 すべての参加者が正確に 1 つのペアで使用されるように、それらをペアにする必要があります。 ペアのスコアは、そのペアの 2 つの値の積として定義され、目標は、すべてのペアの積の合計を最大化するペアリングを選択することです。 

主な問題は、ペアリングの決定がグローバルに相互作用することです。 単一の要素は他の要素と組み合わせることができ、初期の選択が適切でないと、より適切なグローバル構成が妨げられる可能性があります。 値は負または正の可能性があるため、符号間の相互作用は大きさと同じくらい重要です。 

入力サイズは最大 10^6 要素まで可能です。 O(n log n) より悪い解はタイムアウトする危険性があり、O(n^2) の構築でさえ完全に実行不可能です。 また、メモリの制約により、線形空間を超えて大きな補助構造を保存することを避ける必要があります。 

負の数が関係する場合、微妙な特殊なケースが発生します。 たとえば、2 つの負の数値を組み合わせるとプラスの寄与が生成されますが、負の数値とプラスの数値を組み合わせるとマイナスの寄与が生成され、合計が減少します。 隣接する要素またはペアを任意に組み合わせる単純な貪欲なアプローチは、ひどく失敗する可能性があります。 

次の入力を考えてみましょう。```
-5 -1 2 4
```(-5, 2) と (-1, 4) のような単純な組み合わせでは、-10 + -4 = -14 となります。 

ただし、(-5, -1) と (2, 4) を組み合わせると、5 + 8 = 13 となり、これが最適になります。 

これは、サインを意識したグループ化が不可欠であることを示しています。 

もう 1 つの特殊なケースは、すべての数値が正であるか、すべてが負である場合です。 どちらの場合も、最適なペアリングの構造は簡素化されますが、一般的なアルゴリズムは依然としてそれらを均一に処理する必要があります。 

## アプローチ

 ブルートフォース手法では、考えられるすべてのペアリング構成が試行されます。 これは、n 個の要素のすべての完全一致を生成し、それぞれの積の合計を計算するものとみなすことができます。 このような一致の数は (n - 1) × (n - 3) × ... × 1 となり、超指数関数的に増加します。 n = 20 の場合でも、これは実行不可能になります。 

ブルート フォースが正しい理由は、すべての有効なパーティションをペアに探索し、目的を直接評価するためです。 ただし、ペアリングの数が組み合わせ的に爆発的に増加し、同等の構造的選択の再検討を回避する枝刈りがないため、この方法は失敗します。 

重要な観察は、ペアの寄与は値自体にのみ依存し、その位置には依存しないということです。 これは、要素を自由に並べ替えるべきであることを示唆しています。 一度ソートされると、最適なペアリングの構造は決定論的になります。つまり、大きなポジティブなものは一緒にペアにする必要があり、大きなネガティブなものは一緒にペアにする必要があり、強制しない限り、符号の混合は一般に有害です。 

これを形式化すると、配列をソートすると、ソートされた順序で隣接する要素をペアにすることが最適な戦略であることがわかります。 これが機能するのは、標準の交換引数である、交差ペアを非交差ソートペアに再配置しても合計が減少しないためです。 直観的には、極端な値をペアにすることで寄与が安定します。負の値は互いにプラスに増幅し、正の値はグループ化したときに大きさを維持します。

 ## アルゴリズムのチュートリアル

 1. 配列を降順でない順に並べ替えます。 

これにより、類似した符号と大きさを持つ要素が隣接することが保証されます。これは、最適なペア構造が出現するために必要です。 
2. 現在の合計をゼロに初期化します。 
3. ソートされた配列を 2 ステップで繰り返し、連続するペアを取得します。 

各ペア (a[i]、a[i+1]) は、a[i] × a[i+1] として加算されます。 

このペアリング ルールは、隣接関係から逸脱すると、合計を減らさずに交換できる交差構造が導入されるため、安全です。 
4. すべてのペア積を最終的な答えに累積します。 
5. 累計を出力します。 

### なぜ効果があるのか

 正しさは、ペアリングに関する交換引数に依存します。 要素 a ≤ b ≤ c ≤ d を使用して交差する 2 つのペア (a, c) と (b, d) が形成されているとします。 代替のペア (a, b) と (c, d) は、次の理由から、合計がより小さくなることはありません。 

ソート順では (a・b + c・d) − (a・c + b・d) = (a − d)(b − c) ≥ 0。 

これは、合計を減少させることなく、交差するペアを局所的に隣接するペアに改善できることを示しています。 この変換を繰り返し適用すると、すべての交差が除去され、ソートされた順序で連続する要素のペアが作成されます。 したがって、貪欲な隣接ペアリングは全体的に最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort()
    
    ans = 0
    for i in range(0, n, 2):
        ans += a[i] * a[i + 1]
    
    print(ans)

if __name__ == "__main__":
    solve()
```実装はアルゴリズムに直接に従います。 並べ替えは、貪欲なペアリングを可能にする重要な前処理ステップです。 ループは 2 ずつ進み、各要素が 1 回だけ使用されるようにします。 Python では整数の乗算に制限がないため、オーバーフローの心配はありません。 

実装の微妙な詳細は、入力サイズが 100 万要素に達する可能性があるため、sys.stdin.readline の使用が必要であることです。 ソートは複雑さを支配するため、ループは線形オーバーヘッドのままになります。

 ## 特殊なケース

 次のような負の数値のみを含む入力の場合`-4 -3 -2 -1`、収量の選別`-4 -3 -2 -1`隣接する要素を組み合わせると、`( -4, -3 ) = 12`そして`( -2, -1 ) = 2`、合計 14。交差ペアなどの代替ペアリングは、積和を減少させます。これは、より近い大きさのペアリングにより常に負の相互作用が少なくなるためです。 

混合符号の場合は次のように入力します`-10 -1 2 3`、ソートされたペアリングにより生成される`(-10, -1) = 10`そして`(2, 3) = 6`、合計 16。`(-10, 2)`そして`(-1, 3)`収量`-20 + -3 = -23`、間違った混合が目的にどれほど悪影響を与えるかを示しています。 

次のような交互の符号を持つ入力の場合`-2 1 -1 2`、並べ替え`-2 -1 1 2`アルゴリズムが陰性値を最初にグループ化することを保証し、符号変更の不安定性を回避します。
