 ## 問題の理解

 各頂点が値を保持するツリーが与えられます。 閾値も与えられています`c`。 ツリー内のすべての単純なパスのうち、パス上の最小値が最大値であるという意味で、パス上の値が「極端すぎない」パスのみを考慮します。`c`パス上の最大値は少なくとも`c`。 言い換えれば、すべての有効なパスには、次の値以下の頂点が少なくとも 1 つ含まれている必要があります。`c`以上の値を持つ少なくとも 1 つの頂点`c`、つまりパスはレベルを「横切る」`c`価値空間で。 

このようなすべての有効なパスの中で、パスに沿ったすべての頂点値の XOR を最大化する必要があります。 

ツリーには最大 100,000 個の頂点があるため、すべてのパスを列挙しようとするソリューションは直ちに不可能になります。 ツリー内の単純なパスの数は 2 次であり、各パスの関数を計算するだけでもすでに遅すぎます。 このため、明示的にパスを考慮することを避け、代わりにツリー分解、重心、または動的集約を利用する構造的削減を探す必要があります。 

重要な点は、制約がエンドポイントに関するものではなく、パスに沿った複数の値セットに関するものであることです。 パスは、少なくとも 1 つの値 ≤ c と少なくとも 1 つの値 ≥ c を含む場合にのみ有効です。 これは、パス上のすべての値が厳密に < c であるか、厳密に > c である場合にのみ、パスが無効であることを意味します。 

エッジケースは、有効なパスがまったく存在しない場合に発生します。 たとえば、すべての値が厳密に次の値より小さい場合、`c`、またはすべてが厳密に次よりも大きい`c`の場合、条件を満たすパスはありません。 このような場合は、単一の頂点パスであっても、不等式の要件の両側を満たさないため無効になります。

## アプローチ

 直接的なアプローチでは、ノードのすべてのペアが考慮されます。`(u, v)`、パスに沿った値の XOR を計算し、パスが有効かどうかを確認します。 木の中には、`O(n^2)`ペアとパス XOR を単純に計算するとコストがかかります`O(n)`ルートからプレフィックス XOR を事前計算しない限り、ペアごとに。 プレフィックス XOR を使用する場合でも、有効性チェックにはパス上の最小値と最大値を知る必要があり、通常、最小値と最大値を格納するセグメント ツリーまたはバイナリ リフティングによる LCA 前処理が必要です。 これにより、`O(n^2)`列挙`O(1)`クエリはまだ大きすぎます`n = 10^5`。 

重要な観察は、制約がしきい値に基づいてツリーを 2 つの領域に分割していることです。`c`。 パスが完全に片側に留まっている場合、そのパスは無効です。`c`。 したがって、「ローサイド」と「ハイサイド」を接続するパスに本当に興味がありますが、ノードは以下に等しいため、`c`min ≤ c と max ≥ c の両方の条件を自動的に満たすため、コネクタとして機能します。 これは、重心の周りにツリーをルート化し、ツリー構造に対して分割統治を使用して、境界条件を越える最適な XOR パスを計算することを示唆しています。 

ツリー内の最大 XOR パスを処理する標準的な方法は、セントロイド分解または DFS ベースのトライ マージを使用することです。 各重心で、それを通過するすべてのパスを考慮し、重心から各サブツリー内のノードまでの XOR を計算し、バイナリ トライを使用して異なるサブツリー間の XOR を最大化します。 に関する制約`c`これは、ノードがしきい値の上か下かに応じてノードを有効なカテゴリに分割し、有効なパスを生成する寄与のみを結合することを保証することによって適用されます。 

これにより、グローバル パスの問題が各重心でのローカル マージ問題に縮小されます。

 ## アルゴリズムのチュートリアル

 パス セグメント全体で最大の XOR クエリを維持するために、バイナリ トライと組み合わせたセントロイド分解を使用して問題を解決します。 

1. ツリーの重心分解を構築します。 

各段階で、重心ノードを選択し、それを通過するすべてのパスを答えの候補として扱います。 これが機能するのは、ツリー内のすべてのパスが最初に完全に含まれる最も高い分解レベルの重心を持っているためです。 
2. 現在の重心について、DFS を使用して重心から残りのサブツリー内のすべてのノードまでの XOR 値を計算します。 

これらの XOR 値を、重心からそのノードへのパスに少なくとも 1 つの値 ≤ c と少なくとも 1 つの値 ≥ c が含まれるかどうかを示すフラグとともに保存します。 このフラグは、しきい値を下回るか上回る値が検出されたかどうかを追跡することで、DFS 中に段階的に維持できます。 
3. セントロイドを介して別のサブツリーと結合したときの有効なグローバル パスの形成に関する有効性ステータスによって、各サブツリー内のノードを分離します。 

異なるサブツリーからのノードのペアは、結合されたパスがしきい値条件を満たす場合、重心を通る有効なパスを形成します。しきい値条件は、少なくとも一方の側が ≤ c 値を提供し、もう一方が ≥ c 値を提供するか、重心自体が欠落している側を満たすかどうかによって決まります。 
4. 1 つのサブツリーの XOR 値をバイナリ トライに挿入します。 

別のサブツリー内の各ノードについて、トライをクエリして、XOR ペアの最大値を見つけます。 これにより、これら 2 つのサブツリー間の重心を通過する最適なパスが得られます。 
5. クエリの試行中にパスの有効性を強制します。 

パス全体に値 ≤ c と値 ≥ c の両方が含まれるという条件を満たす組み合わせのみが許可されます。 これは、保存されたフラグを使用して追跡され、しきい値の片側に完全にある無効な組み合わせが考慮されないことが保証されます。 
6. 重心のすべてのサブツリー ペアを処理した後、各サブツリーを再帰的に分解します。 

### なぜ効果があるのか

 ツリー内のすべての単純なパスには、最初に完全に含まれる分解における固有の最高重心があります。 その重心では、パスは 1 つのサブツリー内に完全に存在するか、複数のサブツリーを通過します。 重心ステップでは、すべてのクロスサブツリー パスが 1 回だけ考慮されることが保証されます。 バイナリ トライにより、すべての有効なクロスサブツリー XOR の組み合わせのうち、可能な最大値が効率的に計算されます。 有効性フラグは、両側に値を含むという要件に違反するパスが選択されないことを保証します。`c`。 分解ではツリーが対数的に分割され、各ノードが`O(log n)`レベルでは、すべての貢献が重複することなく考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class Trie:
    def __init__(self):
        self.nxt = [[-1, -1]]
        self.count = [0]

    def reset(self):
        self.nxt = [[-1, -1]]
        self.count = [0]

    def add(self, x):
        node = 0
        for i in reversed(range(31)):
            b = (x >> i) & 1
            if self.nxt[node][b] == -1:
                self.nxt[node][b] = len(self.nxt)
                self.nxt.append([-1, -1])
                self.count.append(0)
            node = self.nxt[node][b]
            self.count[node] += 1

    def query(self, x):
        node = 0
        res = 0
        for i in reversed(range(31)):
            b = (x >> i) & 1
            toggled = b ^ 1
            if self.nxt[node][toggled] != -1:
                node = self.nxt[node][toggled]
                res |= (1 << i)
            else:
                node = self.nxt[node][b]
        return res

def solve():
    n, c = map(int, input().split())
    a = list(map(int, input().split()))
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    sub_size = [0] * n
    removed = [False] * n

    def dfs_size(u, p):
        sub_size[u] = 1
        for v in g[u]:
            if v != p and not removed[v]:
                dfs_size(v, u)
                sub_size[u] += sub_size[v]

    def dfs_centroid(u, p, total):
        for v in g[u]:
            if v != p and not removed[v]:
                if sub_size[v] > total // 2:
                    return dfs_centroid(v, u, total)
        return u

    ans = -1

    def dfs_collect(u, p, xr, has_low, has_high, out):
        xr ^= a[u]
        has_low = has_low or (a[u] <= c)
        has_high = has_high or (a[u] >= c)
        out.append((xr, has_low, has_high))
        for v in g[u]:
            if v != p and not removed[v]:
                dfs_collect(v, u, xr, has_low, has_high, out)

    def add_trie(nodes):
        for xr, lo, hi in nodes:
            if lo and hi:
                trie.add(xr)

    def query_trie(nodes):
        nonlocal ans
        for xr, lo, hi in nodes:
            if lo and hi:
                ans = max(ans, trie.query(xr))

    def decompose(entry):
        dfs_size(entry, -1)
        ctd = dfs_centroid(entry, -1, sub_size[entry])

        removed[ctd] = True

        trie.reset()

        # centroid itself contributes
        has_low_ctd = a[ctd] <= c
        has_high_ctd = a[ctd] >= c

        if has_low_ctd and has_high_ctd:
            ans_holder = 0  # trivial path

        for v in g[ctd]:
            if removed[v]:
                continue
            nodes = []
            dfs_collect(v, ctd, 0, has_low_ctd, has_high_ctd, nodes)

            query_trie(nodes)
            add_trie(nodes)

        for v in g[ctd]:
            if not removed[v]:
                decompose(v)

    decompose(0)
    print(ans)

if __name__ == "__main__":
    solve()
```ソリューションは重心分解を中心に構成されています。 の`dfs_size`そして`dfs_centroid`関数は、現在のコンポーネント内のバランスの取れた分割ポイントを見つけます。 の`dfs_collect`関数は、しきい値のどちらかの側の値に遭遇したかどうかを追跡しながら、重心から各サブツリーへの XOR 値を計算します。 トライは、異なるサブツリーからの XOR 値を効率的に組み合わせるために使用されます。 

実装の微妙な詳細は、重心からのパスに沿って値 ≤ c と ≥ c の両方が確認されたという点で「完全に有効」なノードのみを挿入してクエリすることです。 これにより、無効な部分パスの結合が防止されます。 

もう 1 つの重要な詳細は、各重心でトライをリセットすることです。 これがないと、以前のコンポーネントの値が誤って混合され、現在の重心を通過しないパスが過大にカウントされてしまいます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、しきい値条件の片側を満たす値が存在しない場合です。 たとえば、すべての値が以下の場合、`c`、すべての DFS コレクションが生成します`has_high = False`したがって、トライにノードが挿入されることはありません。 その後、重心ステップでは有効な XOR ペアが生成されず、最終的な答えが残ります。`-1`。
