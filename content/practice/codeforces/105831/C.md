 ## 解決策
 ## 問題の理解

 家の高さの固定配列が与えられています。 各クエリは、連続した間隔の住宅を描画します。 塗装後、その間に燃えている家屋をすべて消火するには何回の「消防活動」が必要か尋ねられます。 

消防士の操作は任意ではありません。すべての値が 1 より大きい公約数を共有する、つまりそのセグメントの gcd が少なくとも 2 である住宅のセグメントにのみ適用できます。1 つの操作により、選択したセグメント内で現在燃えている家屋がすべて消火されますが、セグメント自体が完全にクエリ間隔内にある必要はありません。 ただし、燃えている家屋の消火のみを考慮しているため、有用なセグメントは現在の燃えている領域と交差する必要があります。 

各クエリは独立しているため、常に同じ固定配列に基づいて推論されます。 

中心となるタスクは次のとおりです。 間隔ごとに$[l, r]$、選択された各サブセグメントの gcd が厳密に 1 より大きくなるように、最小数のサブセグメントに分割します。 

制約により、線形または線形に近い前処理ソリューションが強制されます。 配列サイズは最大です$10^5$、クエリの数は次のとおりです。$10^6$。 これにより、クエリごとに gcd 情報を再計算したり、間隔を単純にスキャンしたりするソリューションは即座に除外されます。 平$O(n \log n)$クエリごとには不可能です。 意図した構造では、前処理後に一定時間またはほぼ一定時間で各クエリに応答できる必要があります。 

微妙な問題は、標準のインターバル カバー問題のように、有効なセグメントが事前に固定されていないことです。 セグメントは、そのセグメント内のすべての要素を分割する素数が少なくとも 1 つ存在する場合にのみ有効です。 これは、有効なセグメントが、事前に指定された間隔セットによってではなく、素数の可分性構造によって誘導されることを意味します。 

単純な間違いは、gcd が 1 より大きくなるクエリの最長のプレフィックスを貪欲に選択できると想定することです。 これは、異なる素数を持つ短い重複セグメントが存在する場合でも、gcd が 2 を下回る可能性があるため、失敗します。 別の失敗モードは、すべてのセグメントのすべての拡張に対して gcd を再計算しようとすることであり、これはすべてのクエリにわたって二次関数になります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各クエリ間隔について、左から右にカバーしようとします。 現在カバーされていない位置で、gcd を 1 より大きく維持しながらセグメントを可能な限り延長しようと試み、その後、切断して次の位置から続行します。 各拡張では、gcd を繰り返し再計算するか、多くの候補セグメントをチェックする必要があるため、$O(n^2)$最悪の場合のクエリごとの動作。 

gcd は、要素を追加しても減少するか安定を維持できるという意味で単調であるため、これは小規模な場合には機能します。 ただし、失敗点は、ある位置から始まる最適なセグメントがプレフィックスだけでは決定されないことです。 それは共有素因数がどこで存在しなくなるかによって決まります。 

重要な観察は、gcd が 1 より大きいということは、セグメント内のすべての要素を分割する少なくとも 1 つの素数が存在することと同等であるということです。 したがって、すべての有効なセグメントは、すべての要素を固定素数で分割するインデックスの連続ブロック内に完全に含まれます。 これにより、問題がインターバルの範囲に変換されます。つまり、カバーしたいのは、$[l, r]$可能な限り最大の「素数一貫性」間隔を使用します。 

インデックスごとに$i$でセグメントを開始した場合に、延長できる右への最も遠い位置を計算できます。$i$。 この範囲がわかると、貪欲スキャンは決定的になります。つまり、常に現在の位置から最も遠くまで延びるセグメントを取得します。 

残りの課題は、この貪欲なプロセスを最大で十分な速度にすることです。$10^6$クエリ。

 ## アルゴリズムのチュートリアル

 配列を素数分割構造に変換し、それを固定素数が有効な最大セグメントに圧縮します。 

### 1. 各数値を因数分解します

 あらゆるポジションについて$i$、 要素$a_i$異なる素約数に変換します。 各素数は、有効なセグメントをサポートする可能性のある候補です。 

### 2. 主要出現リストを作成する

 素数ごとに$p$、すべてのインデックスを保存します。$a_i$で割り切れます$p$。 このような各リストは、この素数が「アクティブ」である位置を表します。 

### 3. 素数ごとに連続した実行に圧縮する

 各素数リストについて、それを最大の連続ブロックに分割します。 1 つのブロック内では、すべての位置が同じ素数で割り切れるため、そのブロック内のサブセグメントは少なくとも gcd を持ちます。$p$したがって、有効です。 

インデックスごとに$i$、記録します`best[i]`、以下を含むすべてのプライム ブロックの中で最も右端のエンドポイント$i$。 

これが機能する理由は、次から始まる有効なセグメントが存在するためです。$i$少なくとも 1 つのそのような素数ブロックに完全に含まれている必要があるため、可能な限り最も遠い拡張が正確にすべての素数分割の中で最良のブロックになります。$a_i$。 

### 4. クエリの貪欲な範囲

 クエリを処理するには$[l, r]$、ポインタを維持します`cur`から始まる$l$。 から始まるセグメントを繰り返し選択します。`cur`それは～にまで及ぶ`best[cur]`、そして移動します`cur`に`best[cur] + 1`。 このようなセグメントが何個必要になるか数えます。`cur > r`。 

### なぜ効果があるのか

 どの位置でも、そこから始まるすべての有効なセグメントは完全に素一貫性ブロックに含まれます。 より短いセグメントを選択すると、後で必要な操作の数が増えるだけで、新たな到達可能性が得られないため、そのような最も遠いブロックが常に短い選択肢より優先されます。 これにより、あらゆるステップで貪欲な選択が最適になり、セグメンテーションが決定的になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

n = int(input())
a = list(map(int, input().split()))

# factorization helper (trial division up to sqrt)
def factor(x):
    res = set()
    d = 2
    while d * d <= x:
        if x % d == 0:
            res.add(d)
            while x % d == 0:
                x //= d
        d += 1
    if x > 1:
        res.add(x)
    return res

pos = defaultdict(list)

# store which indices each prime appears in
for i, x in enumerate(a):
    for p in factor(x):
        pos[p].append(i)

best = [0] * n

# build best reach per index
for p, idxs in pos.items():
    start = 0
    while start < len(idxs):
        end = start
        while end + 1 < len(idxs) and idxs[end + 1] == idxs[end] + 1:
            end += 1
        l = idxs[start]
        r = idxs[end]
        for k in range(start, end + 1):
            best[idxs[k]] = max(best[idxs[k]], r)
        start = end + 1

q = int(input())
for _ in range(q):
    l, r = map(int, input().split())
    l -= 1
    r -= 1

    cur = l
    ans = 0
    while cur <= r:
        ans += 1
        nxt = best[cur]
        cur = nxt + 1

    print(ans)
```因数分解ステップでは素構造を構築します。 の`best`配列には、インデックスごとに、そのインデックスを含む有効な素一致セグメントの最も右の境界が格納されます。 次に、クエリ ループは貪欲なセグメンテーションを実行し、常に現在の位置から可能な限り遠くにジャンプします。 

微妙な実装上のポイントは、`best[i]`はグローバルであるため、貪欲なプロセスはクエリの境界を越えて拡張される可能性があります。 一度停止して工程をクランプするので安全です`cur > r`、オーバーシュートは依然として、最後に必要な位置をカバーする有効なセグメントに対応します。

 ## 特殊なケース

 重要なエッジケースは、すべての数値がペアごとに互いに素である場合です。たとえば、`[2, 3, 5, 7, 11]`。 この状況では、1 要素より長いセグメントには 1 より大きい gcd がないため、すべてのクエリは単一要素の操作に縮退します。 アルゴリズムはこれを正しく処理します。`best[i]`等しい`i`、グリーディ ループをステップごとに 1 つのインデックスだけ進めることを強制します。 

もう 1 つのエッジ ケースは、単一の素数が大きな領域を支配しているものの、次のような互いに素なクラスターに出現する場合です。`[2, 4, 3, 9, 2, 8]`。 素数ごとの連続ランの構築により、真に連続した割り切れる位置のみがマージされることが保証され、ギャップ間の誤ったマージが防止されます。 

最後に、クエリが大きな有効なブロック内で開始され、途中で終了する場合、アルゴリズムは正しい境界をオーバーシュートする可能性があります。 ループ条件が発生するため、これは無害です。`cur <= r`完全に必要なセグメントのみがカウントされるようにし、オーバーシュートによって答えが増加したり、正確性に影響を与えたりすることはありません。
