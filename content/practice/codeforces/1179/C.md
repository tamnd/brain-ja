 ## 解決策
 ## 問題の理解

 私たちは、各料理に 1 つのコピーがあり、各生徒が買える範囲で最も高価な料理を購入する学校の食堂をシミュレートする任務を負っています。 私たちの主人公であるセルジュは、生徒全員が買い物を終えるまで待ったらどの料理が手に入るのか知りたいと考えています。 最初に、さまざまな料理の価格とさまざまな生徒の予算があります。 次に、一連のクエリによって料理の価格または生徒の予算が変更されます。 各質問の後、セルジュが生徒全員が買い終わるまで待った場合に購入する料理の価格を報告しなければなりません。 

主な課題は、最大 300,000 の料理、300,000 人の生徒、および 300,000 のクエリを効率的に処理することです。 クエリごとにキューをシミュレートする単純なアプローチでは、クエリごとに O(n m) の操作が必要となり、おおよその結果が得られます。$10^{11}$最悪の場合は操作が不可能になります。 したがって、すべての生徒を個別にシミュレートすることなく、どの料理が購入される可能性が高いかを追跡する方法が必要です。 

エッジケースには、すべての料理がすべての生徒にとって高すぎるため、セルジュが残りの最も高価な料理を自由に選択できる状況が含まれます。 すべての料理が生徒によって購入された場合、セルジュには何も得られません。 料理の価格や生徒の予算を変更すると、セルジュの結果が料理を手に入れるかどうかで変わる可能性があるため、ソリューションは動的更新を正しく処理する必要があります。 

## アプローチ

 この強引なアプローチでは、各生徒が買える範囲で最も高価な皿を購入することをシミュレートし、セルジュに残る最大の皿を見つけます。 これは正確性に関しては機能しますが、最悪の場合、クエリごとに O(n m) の操作を実行することになり、n、m、q では最大 300,000 個の操作が不可能になるため、時間制約が満たされません。 

重要な洞察は、どの生徒がどの料理を買うかを正確に知る必要はないということです。 それぞれの料理について、現在の予算を考慮して購入されるかどうかを知る必要があるだけです。 この観察により、問題をソートされた配列間のマッチングとして扱うことができます。つまり、料理と瞳孔を価格と予算でソートし、最も高価な料理から順に貪欲なマッチングをシミュレートします。 最も高価な料理が生徒全員の予算を超えた場合、それはセルジュに残ります。 そうでなければ、それを買う余裕のある最初の生徒がそれを買うでしょう。 

クエリによって料理の価格や生徒の予算が動的に変更されるため、最大値を効率的に維持し、特定のしきい値を超える料理の数を追跡できるデータ構造が必要です。 二分探索またはマルチセット構造を備えたソートされたリストが機能します。O(log n) 時間で料理の価格や生徒の予算を更新し、セルジュ氏が効率的に入手する料理を見つけることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n m) | O(n + m) | 遅すぎる |
 | ソートされたマルチセット/セグメント ツリーを使用した貪欲な | クエリごとに O(log n + log m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのソートされたマルチセットを維持します。1 つは料理の価格用、もう 1 つは生徒の予算用です。 並べ替えにより、常に最高の値を効率的にクエリできるようになります。 
2. クエリごとに、料理の価格または生徒の予算を更新します。 マルチセットから古い値を削除し、新しい値を挿入します。 これにより、O(log n) 操作でソートされた順序が維持されます。 
3. 各アップデートの後、セルジュの結果を決定します。 まず、予算が少なくとも最も高価な料理の価格である生徒の数を見つけます。 これは、ソートされた予算配列の二分検索を使用して実行できます。 
4. そのような生徒の数が、それぞれのしきい値を超える価格の料理の数よりも少ない場合、セルジュは残りの最も高い価格の料理を獲得します。 そうでない場合は、すべての料理が購入され、セルジュは -1 されます。 
5. 各クエリの後に結果を出力します。 

機能する理由: このアルゴリズムは、料理の価格と生徒の予算の並べ替えられたリストがすべての更新後の現在の状態を常に反映するという不変条件を維持します。 生徒は貪欲に買い物をし、食器は 1 部単位であるため、マッチングの問題は、何人の生徒がどの食器を買うことができるかを数えるということになります。 ソートされたマルチセットを使用すると、最も高価な料理がすべての購入に耐えられるかどうかを効率的に判断できます。 

## Python ソリューション```python
import sys
import bisect

input = sys.stdin.readline

n, m = map(int, input().split())
dishes = list(map(int, input().split()))
pupils = list(map(int, input().split()))
q = int(input())

from sortedcontainers import SortedList

dish_sl = SortedList(dishes)
pupil_sl = SortedList(pupils)

for _ in range(q):
    t, i, x = map(int, input().split())
    i -= 1  # convert to 0-based index
    if t == 1:
        # update dish price
        dish_sl.discard(dishes[i])
        dishes[i] = x
        dish_sl.add(x)
    else:
        # update pupil budget
        pupil_sl.discard(pupils[i])
        pupils[i] = x
        pupil_sl.add(x)
    
    # find Serge's dish
    if not dish_sl:
        print(-1)
        continue

    # binary search for the first pupil who can buy the most expensive dish
    max_dish = dish_sl[-1]
    idx = bisect.bisect_left(pupil_sl, max_dish)
    # number of pupils who can afford max_dish
    can_buy = len(pupil_sl) - idx
    if can_buy == 0:
        print(max_dish)
    else:
        if can_buy >= len(dish_sl):
            print(-1)
        else:
            print(dish_sl[-can_buy-1])
```ソリューションでは、`SortedList`動的にソートされた配列を維持します。 クエリごとに、ディッシュまたは瞳孔配列を更新し、生き残る最も高価なディッシュを効率的に決定します。 微妙なのは、数え方を正しく処理することです。セルジュが選択する前に、生徒が何枚の皿を取り除いたかを知る必要があります。 

## 実用的な例

 サンプル 1:

 この痕跡は、生徒がその皿を買う余裕がないとき、セルジュがそれを受け取ることを示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q log n + q log m) | 各クエリは O(log n または log m) で SortedList を更新し、Serge の皿を見つけるには二分探索が必要です。 
| スペース | O(n + m) | 料理の価格と生徒の予算を SortedLists | に保存します。 

n、m、q が最大 300,000 の場合、ソリューションは最悪の場合でもクエリごとに約 180 万の操作を実行し、4 秒と 256 MB のメモリ内に十分収まります。
