 ## 解決策
 ## 問題の理解

 私たちは、巨大な整数線上の単調ステップカウンターのように動作するいくつかの関数を扱っています。 各関数は、位置 0 の値 0 で開始し、位置 10^18 の固定値 L で終了します。また、非常に制限された方法でのみ変更できます。x−1 から x に移動するとき、値は同じままか、ちょうど 1 だけ増加します。 

これは、すべての関数が本質的に、整数線上のどこかに配置された L 個の「ジャンプ」の隠れたシーケンスであることを意味します。 ジャンプ間では関数はフラットです。 ジャンプすると1つ増えます。 各関数の全体的な構造は、それらの L 個のジャンプ ポイントがどこにあるかによって決まります。 

タスクは、各関数 i に数直線上の区間 [l_i, r_i] を割り当て、この区間内で関数が少なくとも L/n 増加するようにすることです。 同時に、これらの間隔は、エンドポイントで接触する可能性がある場合を除き、異なる機能間で重複してはなりません。 

相互作用モデルでは、任意の関数および位置について f_i(x) をクエリできますが、クエリの数は制限されているため、すべての L ジャンプ位置を再構成することは一般に不可能です。 

この制約により、クエリごとの対数戦略が強制されます。 n は最大 1000 まで可能であり、L は非常に大きくなる可能性があるため、完全な機能プロファイルをスキャンまたは再構築しようとするソリューションは直ちに除外されます。 関数ごとの二分探索アプローチであっても、2⋅10^5 クエリ バジェット内に収まるように慎重に制御する必要があります。 

X 軸上の配置を調整せずに関数ごとに独立して間隔を割り当てようとすると、微妙な失敗例が発生します。 各間隔が個別に十分な成長を捕らえたとしても、x 内で重複する可能性があり、これは禁止されています。 したがって、核となる困難は、十分な成長間隔を見つけるだけでなく、それを全体的に重複しない順序で配置することです。 

## アプローチ

 ブルートフォースのアイデアは概念的に単純です。関数ごとに、関数が増加する次の点を繰り返し見つけて、すべての L 増分を効果的に再構築することで、すべてのジャンプ位置を見つけます。 完全な構造がわかれば、x 軸に沿って連続したセグメントを貪欲に切り出すことができます。 これが機能するのは、各関数がそのジャンプ セットによって完全に決定されるため、明示的な再構築により問題が簡単になるためです。 

問題はコストです。 各ジャンプには最大 10^18 の範囲にわたるバイナリ検索が必要で、約 60 クエリのコストがかかります。 L が膨大になる可能性があるため、関数ごとにこれを L 回実行することは不可能であり、すべての関数にわたる合計 L 回のジャンプに対してのみ実行することさえ制限をはるかに超えています。 

重要な観察は、完全な再構築は必要ないということです。 関数ごとに、ある開始位置からの L/n 増加が蓄積される単一のしきい値ポイントを見つけるだけで済みます。 この関数は単位ステップの単調であるため、これは古典的な「k 番目 1 の位置」のクエリ問題に帰着します。つまり、f_i(x) ≥ target である最小の x を二分探索できます。 

これにより、各関数を単一の重要な座標に圧縮できます。 各関数がそのような座標を 1 つ提供すると、問題内の存在保証により、これらの座標を有効な重複しないセグメンテーションに順序付けできることが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのジャンプの完全な再構築 | O(n · L · log 10^18) | O(Ln) | 遅すぎる |
 | しきい値の関数ごとの二分探索 | O(n log 10^18) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各関数を 1 つのキー位置にまとめます。L/n が蓄積される最も早い点は 0 から増加します。

1. 各関数 i について、ターゲット値 T = L/n を計算します。 これは、その間隔内でキャプチャしたい増分数です。 
2. 各関数 i について、範囲 [0, 10^18] の x を二分探索して、f_i(r_i) ≥ T となる最小位置 r_i を見つけます。各チェックはインタラクターへのクエリを使用します。 
3. すべての r_i を計算した後、関数を r_i で昇順に並べ替えます。 これにより、各関数が必要な増分量に「到達」する順序が決まります。 
4. この並べ替えられた順序で間隔を構築します。 最初の間隔が 0 から始まるように設定します。次の各間隔は、前の間隔が終了した場所から始まります。 ソート順で i 番目の関数については、その間隔を [current_left, r_i] として割り当て、current_left = r_i を更新します。 
5. 構築されたすべての間隔を出力します。 

重要な非自明なステップは、r_i によるソートです。 順序を付けないと間隔が勝手に重なってしまいます。 ソートされた構造により、数直線の一貫した左から右への分解が強制されます。 

それが機能する理由は単調性に関係しています。 各関数は増加するだけなので、ある時点 r_i だけ T インクリメントを蓄積すると、進行状況が失われることはありません。 ソートされたエンドポイントにより、前の間隔が後の間隔より早く終了することが保証され、各セグメント内で必要な増分しきい値を維持しながら、互いに素なセグメントをその順序で割り当てることが可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(i, x):
    print("?", i, x)
    sys.stdout.flush()
    return int(input().strip())

def solve():
    n, L = map(int, input().split())
    need = L // n

    r = []

    for i in range(1, n + 1):
        lo, hi = 0, 10**18
        while lo < hi:
            mid = (lo + hi) // 2
            val = ask(i, mid)
            if val >= need:
                hi = mid
            else:
                lo = mid + 1
        r.append((lo, i))

    r.sort()

    ans = []
    cur = 0
    for pos, i in r:
        ans.append((i, cur, pos))
        cur = pos

    print("!")
    for i, l, rr in ans:
        print(l, rr)

if __name__ == "__main__":
    solve()
```このコードは、関数ごとの標準バイナリ検索に依存しています。 各クエリは中間点で関数値を要求し、関数が必要なしきい値に達する最初の位置を分離するまで検索間隔を縮小します。 次に、並べ替えステップで、独立したしきい値をグローバルに一貫したパーティションに変換します。 

微妙な点は、出力がソート後に構築されることですが、それでも元の関数インデックスごとに出力する必要があるということです。 決勝戦`ans`list は、構築されたセグメントの順序を維持しながら、マッピングを関数 ID に戻して保存します。 

## 実用的な例

 n = 3 および L = 3 の単純なケースを考えてみましょう。したがって、need = 1 となります。各関数は、異なる未知の点でちょうど 1 ずつ増加します。 

各関数をバイナリ検索して、最初のインクリメント位置を見つけます。 

| 機能 | 二分探索結果 r_i |
 | --- | --- |
 | 1 | 5 |
 | 2 | 2 |
 | 3 | 8 |

 並べ替えると、関数 2、関数 1、関数 3 の順序が得られます。 

間隔を割り当てます。 

| ステップ | 機能 | 間隔 | 現在の左 |
 | --- | --- | --- | --- |
 | 1 | 2 | [0, 2] | 2 |
 | 2 | 1 | [2、5] | 5 |
 | 3 | 3 | [5、8] | 8 |

 r_i は、関数が必要なしきい値に到達する最初のポイントとして定義されているため、各間隔は、r_i の構築によってその関数の少なくとも 1 つの増分をキャプチャします。 

ここで、関数が成長中にインターリーブされるケースを考えてみましょう。 1 つの関数の成長が早く、もう 1 つの関数の成長が遅い場合でも、並べ替えにより、成長の早い関数がより早いセグメントを取得し、重複違反を防ぎます。

 ## 特殊なケース

 n = 1 の場合、間隔全体を 1 つの関数に割り当てる必要があります。 アルゴリズムは引き続き L 番目の増分位置の二分探索を実行し、結果の区間は当然 [0, r_1] となり、有効です。 

関数が同一の場合、すべての r_i 値が一致します。 その後、並べ替えによって任意の順序が生成されますが、すべてのエンドポイントが等しいため、構築されたチェーンは重複せずに接触するセグメントに縮退しますが、これはエンドポイントの条件で許可されています。 

L/n = 1 の場合、各関数はそのセグメント内で 1 つの増分のみを必要とします。 次に、二分探索によって各関数の最初のジャンプ位置が見つかり、セグメント化はこれらの最初のジャンプを軸に沿って並べることになります。
