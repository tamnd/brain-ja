 ## 解決策
 ## 問題の理解

 次の完全な重み付き有向グラフが与えられます。`n`隣接行列として表される頂点。 各エントリー`a[i][j]`頂点からのエッジの重みです`i`頂点へ`j`。 グラフが完成したので、個別の頂点のすべてのペアが両方向にエッジを持ちます。 グレッグは、グラフから頂点を順番に削除するゲームをプレイします。各頂点を削除する前に、残っている頂点のすべてのペア間の最短経路距離の合計を知りたいと考えています。 

入力では、削除の順序を頂点インデックスのシーケンスとして指定します。 削除ごとに、単一の整数、つまりその時点でグラフ内に残っている頂点のすべてのペア間の最短パスの合計を出力する必要があります。 最短パスは、残りの頂点とそのエッジのみを考慮して計算されます。 自己距離はゼロであり、合計には寄与しません。 

グラフには最大 500 個の頂点を含めることができるため、すべての頂点のトリプルを複数回反復するアルゴリズムは、`O(n^3)`時間。 削除するたびに最短パスを最初から再計算する単純なアルゴリズムでは、時間計算量は次のようになります。`O(n^4)`が遅すぎます。 エッジケースには最小のグラフが含まれます`n=1`、出力が自明にゼロになる場合、および不注意な整数処理がオーバーフローする可能性がある大きなエッジの重みがある場合。 

逆の削除順序を賢明に考慮しない場合、単純なアプローチも失敗する可能性があります。 たとえば、パスを効率的に更新せずにシーケンス内の頂点を削除すると、以前に削除された頂点によって一部のパスが短縮されている可能性があるため、間違った合計が得られる可能性があります。 

## アプローチ

 ブルートフォース手法では、削除シーケンスが繰り返されます。 頂点を削除するたびに、残りの頂点のサブグラフを作成し、Floyd-Warshall を使用してすべてのペアの最短パスを再計算します。 費用は`O(n^4)`最悪の場合には`n`それぞれの削除が必要です`O(n^3)`仕事。 これは正しいですが、遅すぎます`n=500`。 

最適なアプローチは、問題を逆転できるという観察を利用します。 頂点を削除する代わりに、**逆の順序で頂点を追加し直す**ことを検討できます。 空のグラフから開始して逆の削除順序に従って頂点を追加して、削除を逆方向に処理すると、動的な全ペアの最短パス行列を効率的に維持できます。 頂点を追加するたびに`k`、頂点のフロイド・ウォーシャル更新ステップを使用して距離を更新します。`k`:```
d[i][j] = min(d[i][j], d[i][k] + d[k][j])
```追加するたびに、現在アクティブなすべての頂点間の距離の合計を計算します。 これにより、複雑さが軽減されます。`O(n^3)`全体として、各頂点の追加に必要なのは`n x n`距離行列を更新します。 重要な洞察は、削除順序を逆にすると「削除問題」が「増分追加問題」に変換され、フロイド・ウォーシャル更新で最短パスを段階的に蓄積できるようになるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (削除ごとにすべてのペアを再計算) | O(n^4) | O(n^2) | 遅すぎる |
 | Floyd-Warshall による逆加算 | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 隣接行列を読み取る`a`そして削除シーケンス`x`。 逆行する`x`頂点を削除するのではなく追加し直すことをシミュレートします。 
2. 距離行列を初期化する`d`のコピーとして`a`。 これにより、動的な最短パス距離が保持されます。 
3. ブール配列を維持する`active`どの頂点が「追加」されたかを追跡します。 
4. 空のリストを初期化する`answer`各頂点を追加した後の最短パスの合計を保存します。 
5. 逆の削除シーケンスを繰り返します。 

1. 現在の頂点をマークします`k`アクティブとして。 
2. 頂点のペアごとに`i`そして`j`、 アップデート`d[i][j] = min(d[i][j], d[i][k] + d[k][j], d[i][k] + d[k][j])`アクティブな頂点のみを考慮します。 
3. 次の合計を計算します。`d[i][j]`すべてのペアに`(i,j)`どちらも`i`そして`j`活動中です。 
4. この合計を次の値に追加します。`answer`。 
6. すべての頂点を処理した後、反転します`answer`元の削除順序と一致させて印刷します。 

**これが機能する理由:** 不変条件は、各頂点を追加した後、`d[i][j]`間の最短経路距離が含まれます。`i`そして`j`これまでのところアクティブな頂点のみを考慮します。 削除順序を逆にすると、すべてのパス更新で、新しく追加された頂点によって導入される潜在的なショートカットが正しく反映されるようになります。 アクティブな頂点のみの距離を合計することで、各削除の前に必要な合計を複製します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = [list(map(int, input().split())) for _ in range(n)]
x = list(map(int, input().split()))
x = [v-1 for v in x][::-1]  # zero-based and reversed

d = [row[:] for row in a]
active = [False] * n
answer = []

for k in x:
    active[k] = True
    for i in range(n):
        if not active[i]:
            continue
        for j in range(n):
            if not active[j]:
                continue
            d[i][j] = min(d[i][j], d[i][k] + d[k][j])
    total = 0
    for i in range(n):
        if not active[i]:
            continue
        for j in range(n):
            if not active[j]:
                continue
            total += d[i][j]
    answer.append(total)

print(' '.join(map(str, answer[::-1])))
```距離行列`d`現在アクティブな頂点に対してのみ更新されます。 グラフにまだ存在していない頂点の距離をカウントしないように、アクティブな頂点に対してのみ反復するように注意する必要があります。 削除シーケンスを反転すると、出力が各削除前の合計に対応することが保証されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^3) | 追加された n 個の頂点のそれぞれでは、距離行列の n x n エントリを更新する必要があります。 |
 | スペース | O(n^2) | 距離行列`d`および隣接行列`a`必要とする`n^2`空間。 |

 と`n ≤ 500`、`n^3 = 125,000,000`制限時間3秒以内であれば操作可能です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = [list(map(int, input().split())) for _ in range(n)]
    x = list(map(int, input().split()))
    x = [v-1 for v in x][::-1]
    d = [row[:] for row in a]
    active = [False]*n
    answer = []
    for k in x:
        active[k] = True
        for i in range(n):
            if not active[i]:
                continue
            for j in range(n):
                if not active[j]:
                    continue
                d[i][j] = min(d[i][j], d[i][k] + d[k][j])
        total = sum(d[i][j] for i in range(n) for j in range(n) if active[i] and active[j])
        answer.append(total)
    return ' '.join(map(str, answer[::-1]))
