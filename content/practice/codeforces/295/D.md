 ## 解決策
 ## 問題の理解

 サイズ _n_ × _m_ の長方形を黒と白のセルでペイントして「洞窟」を形成する方法の数を数えるように求められます。 実際には、各行をすべて白にするか、ちょうど 2 つの黒いセルを含めることができます。 さらに、各行にちょうど 2 つの黒セルが含まれる行の連続した垂直セグメントが存在する必要があり、これらの黒セルは「山」パターンを形成する必要があります。黒セルを含む列は、ピーク行 _t_ まで下降するときにのみ拡張でき、その後は縮小します。 このセグメントの外側の他の行はすべて完全に白のままにする必要があります。 

入力は、長方形の寸法を表す 2 つの整数 _n_ と _m_ で構成されます。 出力は、有効な洞窟パターンの数を法的に表したものです。$10^9 + 7$。 

_n_ と _m_ は最大 2000 に達する可能性があるため、すべてを総当たりでチェックする必要があります。$2^{n \cdot m}$構成は不可能です。 これは、理想的には、_n_ と _m_ を基準とした多項式時間で動作するアプローチが必要であることを意味します。$O(n m^2)$またはそれより速くなります。 

微妙なエッジ ケースは、_n_ または _m_ のいずれかが非常に小さい場合です。 たとえば、_n_ = 1 および _m_ = 1 の場合、2 つの黒セルを連続して配置する方法はないため、答えは 0 になります。同様に、_m_ = 2 の場合、2 つの黒セルがある各行には可能な構成が 1 つだけあり、組み合わせが単純化されますが、アルゴリズムは根本的に変更されません。 

## アプローチ

 素朴なアプローチは、行の可能なすべての連続セグメントを反復処理し、行ごとに 2 つの黒いセルを割り当て、その後、考えられるすべてのピーク行のサブセット プロパティをチェックすることです。 長さ _k_ のセグメントの場合、行あたりの列の選択肢の数は次のようになります。$\binom{m}{2}$。 山の特性を検証するためにすべてのサブセットを列挙しようとすると、複雑さが爆発的に増大します。$O(n^3 m^k)$最悪の場合、これは明らかに非現実的です。 

重要な観察は、「山」プロパティが各行の黒セルの位置を、その上下の行を基準にして制約していることです。 これにより、動的プログラミングを使用して有効な構成の数を効率的に計算できるようになります。 させて`dp[i][j]`_(a,b)_ の位置にある一対の黒セル列で終わる高さ _i_ の有効な山を形成する方法の数を表します。`j`。 新しい行の有効なセットは前の行に比べて拡大または縮小しているため、次のように遷移できます。$O(m^2)$行ごとに。 考えられるすべての開始位置と山の長さを合計することにより、すべての有効な洞窟の構成が取得されます。 

この観察により、複雑さは大まかに軽減されます。$O(n m^2)$、これは与えられた制約に対して実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3 m^4)$|$O(n m)$| 遅すぎる |
 | 動的プログラミング |$O(n m^2)$|$O(m^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 幅 _m_ の行にある 2 つの黒セルを選択する方法の数を事前に計算します。 これは$\binom{m}{2} = m \cdot (m-1) / 2$。 これらは各行の有効な列のペアです。 
2. 2 つの配列を初期化する`up`そして`down`。`up[i][j]`列ペアのインデックスが _j_ の行 _i_ で終わる有効な増加シーケンスの数を格納します。`down[i][j]`行 _i_ から始まり、列ペア インデックス _j_ を持つ有効な減少シーケンスの数が格納されます。 これらの配列は、山の 2 つのフェーズに対して動的プログラミングを実装します。 
3. 行を上から下まで繰り返して埋めます`up`。 各行、考えられる各列ペアについて、現在のペアのサブセットである前の行のすべての列ペアのカウントを合計します。 これは山の拡大段階を捉えています。 
4. 行を下から上に繰り返して埋めます`down`。 各行、考えられる各列ペアについて、現在のペアのサブセットである次の行のすべての列ペアのカウントを合計します。 これは収縮期を捉えています。 
5. 山の頂上とみなされる行 _t_ ごとに、_t_ で終わる増加シーケンスの数と _t_ で始まる減少シーケンスの数を掛けます。 これにより、行 _t_ にピークがある山の合計数が得られます。 すべての行 _t_ を合計して、最終的な数を取得します。 
6. 答えのモジュロを返します$10^9 + 7$。 

機能する理由: サブセット条件を満たす一連の黒セル位置はすべて、有効な山に対応します。 動的プログラミング配列は、明示的に列挙することなく、すべてのシーケンスを効率的にカウントします。 各トランジションはサブセット プロパティを尊重するため、無効なシーケンスは含まれません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def main():
    n, m = map(int, input().split())
    
    if m < 2:
        print(0)
        return

    # Generate all possible pairs of columns
    pairs = [(i, j) for i in range(m) for j in range(i+1, m)]
    p = len(pairs)

    # Initialize DP arrays
    up = [ [0]*p for _ in range(n) ]
    down = [ [0]*p for _ in range(n) ]

    # Base case: first row can start any pair
    for j in range(p):
        up[0][j] = 1
    for i in range(1, n):
        for j, (a,b) in enumerate(pairs):
            # sum all previous pairs that are subsets
            for k, (c,d) in enumerate(pairs):
                if a <= c and d <= b:
                    up[i][j] = (up[i][j] + up[i-1][k]) % MOD

    # Base case for down
    for j in range(p):
        down[n-1][j] = 1
    for i in range(n-2, -1, -1):
        for j, (a,b) in enumerate(pairs):
            for k, (c,d) in enumerate(pairs):
                if c <= a and b <= d:
                    down[i][j] = (down[i][j] + down[i+1][k]) % MOD

    ans = 0
    for i in range(n):
        for j in range(p):
            ans = (ans + up[i][j] * down[i][j]) % MOD
    print(ans)

if __name__ == "__main__":
    main()
```コードは、_m_ < 2 という自明なケースを処理することから始まります。次に、行内の黒セル位置の可能なすべてのペアを列挙します。 の`up`array は展開シーケンスの数をカウントしますが、`down`縮小シーケンスの数をカウントします。 乗算する`up[i][j]`そして`down[i][j]`各行とペアについて、その行にピークを持つ有効な洞窟の合計数が表示されます。
