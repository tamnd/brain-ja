 ## 解決策
 ## 問題の理解

 無限の整数直線に沿って降雨量の蓄積をモデル化するように求められます。 毎日、特定の位置に雨が集中し、その強さは距離に応じて直線的に減衰します。 正式には、その位置で雨が降った場合`x_i`激しさとともに`p_i`、その後の位置での降雨量`j`増加します`max(0, p_i - |x_i - j|)`。 いずれかのポジションがこれ以上蓄積するとフラッドが発生します。`m`雨の単位。 

おもしろいのは、ちょうど 1 日分の雨が降った場合はキャンセルできるということです。 毎日、その日の雨を中止すれば洪水が防げるかどうかを確認する必要があります。 出力はバイナリ文字列です。`1`その日の雨が止むと洪水が起こらないことを示します。`0`洪水の跡を示しています。 

制約が厳しい: 日数`n`最大 200,000、および合計`n`すべてのテスト ケースの数も 200,000 です。 位置と強度は最大 10^9 に達することがあります。 これにより、有効な位置が広範囲に広がる可能性があるため、位置を反復する単純なシミュレーションは即座に除外されます。 サイズ 10^9 の配列を割り当てることはできず、整数の位置ごとに降雨量を個別に計算するのは遅すぎます。 

素朴な解決策が失敗する可能性があるエッジケースには、交差点で最大の蓄積が達成される重複した雨、非常に強い強度の隣に非常に小さな強度の日、および降雨範囲の端で洪水が発生するケースが含まれます。 たとえば、位置 1 と 10 に強度 5 の 2 つの雨が降った場合、位置 5 に蓄積された雨は 1 + 1 = 2 となります。`m = 2`、雨の中心のみを考慮する不注意な解決策では、エッジの蓄積を見逃す可能性があります。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。毎日、その日をキャンセルした後のすべての降雨量の累積をシミュレートします。 これには、残りのすべての雨の影響を受ける各整数の位置を反復し、寄与を合計し、いずれかの位置が超過するかどうかを確認することが含まれます。`m`。 これは理論的には正しいですが、雨が当たる位置の数は強度の合計に比例するため、位置が 10^9 まで大きくなる場合は実行不可能になります。 雨の影響を受ける位置のみを反復しようとしても、激しい雨が重なるという最悪のシナリオでは、テスト ケースごとに数百万回の操作が必要になります。 のために`n = 2*10^5`複数のテスト ケースにわたる場合、これは制限時間を超えます。 

重要な洞察は、位置を明示的に反復することを避けることです。 雨が降るたびに、両側の傾きが 1 の「ピラミッド」が生成されます。 総降水量は区分的線形関数であり、勾配はこれらのピラミッドの境界でのみ変化します。`x_i - p_i`そして`x_i + p_i`。 これにより、傾きの変化に対するプレフィックスの合計を使用して累積をモデル化することができます。 境界点をソートし、勾配の変化を累積的に計算し、降雨の数に対して線形時間で最大累積降雨量を再構成することで、すべての位置をシミュレートすることなく最大降雨量を計算できます。 

最大累積雨量と洪水が発生する「危険区域」がわかれば、毎日の雨を個別に確認できるようになります。 雨の影響で順位が上回った場合`m`、削除候補です。 そうでなければ、洪水とは無関係です。 これにより、数十億のポジションのシミュレーションから管理までの問題が軽減されます。`O(n)`イベントとリニア スキャンの実行。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * sum(p_i)) | O(最大範囲) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、すべての雨を次のように保存します。`(x_i, p_i)`タプルを作成し、位置によって並べ替えます。 並べ替えはオプションですが、処理の境界が簡素化されます。 
2. 雨ごとに、影響を受ける左端と右端の位置を計算します。`l_i = x_i - p_i`そして`r_i = x_i + p_i`。 各境界は、降雨関数の傾きの変化を表します。 
3. ピラミッドの寄与を傾き変化イベントに変換します。 で`l_i`、傾きは 1 ずつ増加します。`x_i`、傾きは 2 減少します。`r_i + 1`、傾きは再び 1 増加します。 これにより、総降雨量の区分的線形関数が構築されます。 
4. 実行勾配と累積降雨量を維持しながら、位置別に分類されたイベントを処理します。 各境界で、傾きに前の境界からの移動距離を乗算して、現在の降雨量を更新します。 発生した最大降雨量を記録してください。 
5.「オーバーフロー」量の特定：累積降雨量が超過する任意の位置`m`。 毎日、そのピラミッドがオーバーフロー位置に寄与しているかどうかを確認します。 これは、その日の雨の影響間隔とオーバーフローが発生する範囲を比較することで実行できます。 日を削除すると、上記の降雨のあるすべての位置が削除されます`m`、その日を次のようにマークします`1`。 それ以外の場合は、次のようにマークします`0`。 
6. すべての日の結果を連結して出力​​文字列を構築します。 

機能する理由: 傾斜ベースのイベント処理は、ライン全体を反復することなく、すべての重要な位置での正確な累積降雨量を再構築します。 各イベントは、総降雨量が傾きを変化させる境界に対応します。 オーバーフローにとって重要な間隔のみを検査することで、問題を間隔とフラッド ゾーン間の重複のチェックに縮小し、フィールド全体をシミュレーションすることなく正確さを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        rains = []
        for _ in range(n):
            x, p = map(int, input().split())
            rains.append((x, p))
        
        events = []
        for x, p in rains:
            events.append((x - p, 1))
            events.append((x, -2))
            events.append((x + p + 1, 1))
        events.sort()
        
        max_rain = 0
        cur_rain = 0
        slope = 0
        prev_pos = events[0][0]
        overflow_left = float('inf')
        overflow_right = float('-inf')
        
        for pos, delta in events:
            cur_rain += slope * (pos - prev_pos)
            slope += delta
            if cur_rain > m:
                overflow_left = min(overflow_left, pos)
                overflow_right = max(overflow_right, pos)
            prev_pos = pos
        
        result = []
        for x, p in rains:
            if x + p < overflow_left or x - p > overflow_right:
                result.append('1')
            else:
                result.append('0')
        print(''.join(result))

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを個別に処理します。 まず、それぞれの雨を斜面変化イベントに変換し、位置別に分類します。 ランニングスロープ変数はイベント間の累積降雨量を再構築し、オーバーフローゾーンの特定を可能にします。 最後に、これらのゾーンへの毎日の影響を確認して、雨を取り除くことで洪水が防止されるかどうかを判断します。 傾斜イベントを使用すると、あらゆる位置のシミュレーションを回避できます。これは、可能な座標範囲が広いことを考えると重要です。
