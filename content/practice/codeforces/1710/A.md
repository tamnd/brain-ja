 ## 解決策
 ## 問題の理解

 色を塗るよう求められています$n \times m$グリッドを使用して$k$色素は、それぞれ限られた数の細胞を着色できます。 すべてのセルがその色を 4 つのトロイダル状の隣接セルのうち少なくとも 3 つと共有している場合、その画像は美しいとみなされます。 ドーナツ状の隣接要素はグリッドのエッジを囲むため、最初と最後の行または列は隣接しているとみなされます。 タスクは、この近傍条件を満たしながら、顔料の制限を考慮して色を割り当てることが可能かどうかを判断することです。 

入力は複数のテスト ケースで構成されます。 それぞれのケースごとに、$n, m, k$および顔料の容量のリスト$a_1, a_2, \dots, a_k$。 美しい発色がある場合は「はい」、そうでない場合は「いいえ」が出力されます。 

境界$3 \le n,m \le 10^9$グリッドをシミュレートしたり、隣接するものを直接チェックしたりすることが不可能になります。$k \le 10^5$そしてすべての合計$k$オーバーテストケースも次によって制限されます$10^5$、そのため、顔料を効率的に処理する必要があります。 それぞれ$a_i$最大で大きくすることができます$10^9$したがって、正確な数が重要です。 不用意な解決策は、グリッドが常に均一に色付けできると仮定したり、1 つの次元が奇数である場合を処理できなかったりする可能性があり、これがストライプやブロックの並べ方に影響を与えます。 

いずれかの次元が奇数の場合、微妙な特殊なケースが発生します。 このような場合、すべてのセルに同じ色の隣接する 3 つのセルが存在するようにパターンを配置すると、失敗する可能性があります。 たとえば、$3 \times 3$一致しないセルを残さずにグリッドを水平ストライプのペアで埋めることはできません。 もう 1 つの特殊なケースは、すべての顔料が個別に行または列の少なくとも半分をカバーするには不十分である場合です。 単純に貪欲な割り当てを行うと、誤ってカラーリングが可能であると宣言される可能性があります。 

## アプローチ

 強引なアプローチでは、グリッドを明示的に構築し、隣接するものをチェックし、色素数を考慮しながらあらゆる方法でセルを埋めようとします。 このアプローチは小規模な場合には正しいでしょう$n$そして$m$しかし、それは明らかに不可能です$n, m$まで$10^9$なぜなら、操作の数は次のようになります。$O(n \cdot m)$。 

重要な洞察は、美しい写真に必要な規則性を認識することです。 各セルには、同じ色の隣接セルが少なくとも 3 つ必要です。 これは、細胞が水平方向または垂直方向に均一なストライプを形成する必要があることを意味します。 水平ストライプの場合、各行は 2 つ以上のブロックの色で構成されている必要があり、行全体を一貫してカバーするには、各ブロックのセルの数が 2 で割り切れる必要があります。 同様に、垂直ストライプの場合、列に沿ったブロックは 2 で割り切れる必要があります。 

各行または列を同じ色のセルのペアでタイル化する必要があることがわかったら、問題は、パリティを考慮して、顔料のカウントを行 (または列) の半分の倍数に分割できるかどうかを確認することになります。 少なくとも 1 つの次元が偶数であれば、ストライプへの分割は簡単です。 両方の次元が奇数の場合は、奇数の長さの行または列をペアで並べることができないため、不可能です。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n*m) | O(n*m) | 遅すぎる |
 | 最適 | テスト ケースごとの O(k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n, m, k$および顔料の制限のリスト$a_1, \dots, a_k$。 
2. 両方の場合$n$そして$m$美しいパターンには少なくとも 1 つの次元に沿ったペアリングが必要であるため、奇数の場合はすぐに「No」が出力されます。 
3. それ以外の場合は、ストライプ化するより大きな寸法を選択します。 一般性を失うことなく、次の場合は行に沿って水平ストライプを想定します。$n$は均等です。 
4. 選択した次元で必要なセルのペアの数を計算します。 横縞の場合、ペアの数は$m // 2$行ごとの合計$(m // 2) * n$ペア。 
5. 奇数の残りを無視して、利用可能な色素細胞の総数を 2 の倍数で合計します。 顔料のペアの合計が必要なペア数以上の場合、「はい」を出力します。 それ以外の場合は「いいえ」を出力します。 
6. 列に沿った縦縞が発生する可能性があるかどうか、同じチェックを繰り返します ($m$は偶数です)、しかし、成功するために必要な方向は 1 つだけです。 
7. 整数の除算とパリティは慎重に処理してください。一貫したストライプを形成できるのはセルのペアだけです。 

機能する理由: このアルゴリズムが機能するのは、美しい状態を維持するには、各セルが 3 つの隣接セルとその色を共有する必要があるためです。 これは、セルが 1 つの次元に沿って少なくとも長さ 2 のストライプを形成する場合にのみ発生します。 各顔料が提供できるペアの数を数え、必要なペアの数と比較することで、グリッドをシミュレートすることなく実現可能性を判断できます。 不変条件は、選択された各ストライプ方向のすべてのセルがサイズ 2 のブロック内に存在し、すべてのセルが 3 隣接要件を満たすことを保証することです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))

        if n % 2 == 1 and m % 2 == 1:
            print("No")
            continue

        def check(dim1, dim2):
            total_pairs = 0
            for cells in a:
                total_pairs += cells // 2
            required_pairs = (dim1 * (dim2 // 2))
            if total_pairs >= required_pairs:
                return True
            return False

        if n % 2 == 0:
            if check(n, m):
                print("Yes")
            else:
                print("No")
        else:
            if check(m, n):
                print("Yes")
            else:
                print("No")

if __name__ == "__main__":
    solve()
```このソリューションは入力を効率的に読み取り、奇数×奇数のグリッドの即時不可能性をチェックし、顔料のカウントがストライプ タイリングに十分であるかどうかを計算します。 ペアに分割することで、セルに必要な隣接セルが確実に存在します。 関数の使用`check`水平および垂直ストライプの可能性を対称的に処理できるようになります。 

## 実用的な例

 トレースサンプル 1 入力`4 6 3\n12 9 8`:

 | ステップ | n | メートル | 顔料 | 合計ペア数 | 必須ペア | 結果 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 4 | 6 | [12,9,8] | (12//2 + 9//2 + 8//2) = 6+4+4=14 | 4*(6//2)=4*3=12 | 14 >= 12 → はい |

 ペアの合計が必要ペアを超えているため、美しい画像が得られます。 

トレースサンプル 2 入力`3 3 2\n8 8`:

 | ステップ | n | メートル | 顔料 | 合計ペア数 | 必須ペア | 結果 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 3 | 3 | [8,8] | 8//2 + 8//2 = 4+4=8 | 3x3 (両方とも奇数) をストライプ化することはできません。 いいえ |

 このアルゴリズムは、奇数×奇数のグリッドが不可能であることを正確に識別します。
