 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられた 1 列の座席を管理しており、座席は占有されているか空席のいずれかになります。 一連の k イベントがオンラインに到着します。 各イベントは、新しい乗客を挿入するか、既存の乗客を削除します。 挿入イベントごとに、その時点で最も近い占有座席までの距離が最大になる座席を選択する必要があり、最小のインデックスを選択することで同点を解消します。 

重要なアイデアは、乗客を配置するたびに、自由席のセグメントをより小さなセグメントに効果的に分割することになるということです。 座席の品質は、その座席が最も近い座席の位置からどれだけ離れているかによってのみ決まります。つまり、私たちは常に、個々の座席が孤立しているのではなく、座席間の隙間を考慮していることになります。 

n が 10^18 までの制約により、明示的な配列表現が即座に除外されます。 座席を直接シミュレートすることも、空いている座席の範囲を線形にスキャンすることもできません。 最大 10^5 の操作数 k は、O(k log k) 構造がターゲットであることを示唆しており、おそらく優先キューまたはセグメント上の順序付きセットを使用しています。 

単純な間違いは、これを静的配列の問題として扱い、クエリごとにすべての空き位置をスキャンすることによって最適な座席を再計算することです。 たとえば、n = 10 ですべての座席が空の場合、最初の挿入はタイブレークに応じて座席 1 または 10 になりますが、ブルート フォース スキャンは機能します。 ただし、何度も挿入すると、残りのすべての空きシートの距離を再計算すると O(nk) に低下します。n が 10^18 の場合、これは不可能です。 

もう 1 つの微妙な失敗モードは、セグメント構造を追跡せずに占有位置のみを追跡しようとすることです。 たとえば、占有座席が {2, 8} の場合、次に最適な座席は 5 ですが、これは、占有座席間の間隔を明示的に維持しない限り効率的に導き出すことができません。 

## アプローチ

 この強引なアイデアは簡単です。挿入するたびにすべての座席をスキャンし、最も近い占有座席までの距離を計算します。 定義が直接的であるため、これは機能します。 ただし、各スキャンのコストは O(n) であり、これを k 回実行すると O(nk) になり、n が大きい場合は制限をはるかに超えます。 

構造的な洞察は、答えは常に 2 つの占有座席 (端を含む) の間の最大の空席によって決まるということです。 現在の空のセグメントをすべて維持する場合、各挿入では最適なセグメントを選択して分割するだけで済みます。 セグメント内の最良の座席は常にその中間点であり、セグメントの品質はその中間点の距離によって決まります。 

これにより、問題は「達成可能な最良の距離」によって順序付けられたセグメントの動的なセットを維持することになります。 優先キューを使用すると、次の乗客が座るべきセグメントを常に抽出できます。 

セグメントが分割されると、最大 2 つの小さなセグメントが生成され、構造内に押し戻されます。 これは、インターバルを最適なポイントで繰り返し分割するインターバル スケジューリングに似ています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nk) | O(n) | 遅すぎる |
 | セグメントヒープ (プライオリティキュー) | O(k log k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 各空きセグメントを区間 [l, r] として表し、その区間内の最良の座席を候補位置として定義します。

1. 初期セグメント [1, n] で優先キューを初期化します。 このセグメントは、行全体が最初は空であることを表します。 
2. セグメントに優先順位を割り当てる関数を定義します。 セグメント [l, r] の場合、境界 (l = 1 または r = n) に接している場合、片側に占有されている隣接セグメントがないため、最良の座席は端の 1 つになります。 それ以外の場合、最良の座席は中間点であり、そのスコアはセグメントの最も近い境界までの距離となります。 
3. スコア順に並べられた最大ヒープにセグメントを格納し、より小さいシート インデックスで同点を解消します。 これにより、複数のセグメントが同等に優れている場合に、必ず左端の座席が選択されます。 
4. 「+」演算ごとに、ヒープから最適なセグメントを抽出します。 割り当てる座席を計算します。セグメントが内部の場合は、mid = (l + r) // 2 を選択します。 それ以外の場合は、どちらの側が空いているかに応じて l または r を選択します。 
5. この座席を占有済みとして記録し、出力します。 
6. セグメントを最大 2 つの新しいセグメント [l, Seat - 1] と [seat + 1, r] に分割しますが、空でない長さのものだけを保持します。 
7. 今後のクエリで更新された構造が考慮されるように、新しいセグメントをヒープにプッシュして戻します。 
8. 「-x」操作の場合、以前に割り当てられたシートを削除します。 実際には、セグメントを直接変更することはありません。 代わりに、シートを再び空きとしてマークし、遅延構造の処理に依存します。 バランスの取れた実装では、占有状態を保存し、影響を受けるセグメントを再構築できますが、k が小さいため、順序付きセットまたは遅延削除を通じてセグメントを管理できます。 

機能する理由: すべてのステップで、ヒープには、占有席によって引き起こされる現在の最大空席間隔が正確に含まれます。 各挿入では、隣接する座席との最大最小距離を提供できる間隔が選択され、分割では、すべての空きスペースが空席を正確にカバーする素の間隔に分割されるという不変条件が維持されます。 すべての最適な座席は最大間隔の中間点にあるため、より良い候補者が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, k = input().split()
    n = int(n)
    k = int(k)

    occupied = set()
    # heap stores: (-priority, seat, l, r)
    heap = []

    def add_segment(l, r):
        if l > r:
            return
        if l == 1:
            seat = 1
            dist = r - l + 1
        elif r == n:
            seat = n
            dist = r - l + 1
        else:
            seat = (l + r) // 2
            dist = min(seat - l, r - seat) + 1
        heapq.heappush(heap, (-dist, seat, l, r))

    add_segment(1, n)

```この実装では、候補セグメントのヒープが維持されます。 各セグメントは、ヒープが優先する、可能な限り最良のシートをエンコードします。 遅延削除は、セグメントがポップされたときにまだ有効であるかどうかをチェックすることによって処理されます。 

重要な点は、削除後にセグメンテーション全体を明示的に再計算しようとしていないことです。 代わりに、古いセグメントがヒープ内に残ることを許可し、それらが見つかった場合は無視します。 これにより、複雑さが対数的に維持されます。 

脆弱な点の 1 つは、境界を正しく処理することです。 セグメントが 1 または n に接触する場合、片側のみに隣接制約があるため、別の方法で処理します。 もう 1 つの微妙な点は、l > r の無効なセグメントを決してプッシュしないようにすることです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k log k) | 各挿入およびヒープ操作には、最大で k 個のセグメントにわたって対数的な時間がかかります。 
| スペース | O(k) | 各操作では、最大でも一定数のセグメントが導入されます。 

この制約では最大 10^5 の演算が許可されるため、対数係数も簡単に受け入れられます。 n の値が大きくても、直接反復処理を行うことはないため、複雑さには影響しません。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import heapq

    n, k = map(int, sys.stdin.readline().split())
    occupied = set()
    heap = []

    def add(l, r):
        if l > r:
            return
        if l == 1:
            seat = 1
            dist = r - l + 1
        elif r == n:
            seat = n
            dist = r - l + 1
        else:
            seat = (l + r) // 2
            dist = min(seat - l, r - seat) + 1
        heapq.heappush(heap, (-dist, seat, l, r))

    add(1, n)

    out = []
    for _ in range(k):
        op = sys.stdin.readline().strip()
        if op[0] == '+':
            while True:
                neg, seat, l, r = heapq.heappop(heap)
                if l <= r and seat not in occupied:
                    break
            occupied.add(seat)
            out.append(str(seat))
            add(l, seat - 1)
            add(seat + 1, r)
        else:
            _, x = op.split()
            x = int(x)
            occupied.discard(x)

    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは、行の長さが 1 である場合です。アルゴリズムは依然として単一のセグメント [1,1] をプッシュし、唯一の有効なシートは常に 1 です。ヒープは常に同じセグメントを返し、代替構造がないため、削除は問題になりません。 

もう 1 つの特殊なケースは、削除と挿入が繰り返され、同一のセグメントが再作成されることです。 遅延削除を使用しているため、古いセグメントがヒープ内に残る場合がありますが、それらのセグメントが見つかった場合はスキップされます。 たとえば、座席を削除した後、後で隣接するセグメントを概念的に再度結合することができます。 ヒープは、新たな挿入を通じてこの構造を自然に再構築します。 

最後の微妙なケースは、最良の席が境界にある場合です。 [1, r] のようなセグメントの場合、アルゴリズムは Seat = 1 を強制します。これは正しいです。左隣がないため、距離を最大化すると、唯一占有されている側から押し出すことになります。
