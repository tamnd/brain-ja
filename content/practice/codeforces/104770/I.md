 ## 解決策
 ## 問題の理解

 列の列が与えられ、それぞれの列には個別の高さと、その上部に屋根を取り付けるための関連コストが設定されています。 単一の屋根は、ある柱から別の柱にまたがる水平セグメントであり、その端点の 1 つに正確に固定される必要があります。 屋根が列 i の左端に固定されている場合、列 i は、屋根がカバーするセグメント内のすべての柱の中で最も高くなければなりません。 対称的に、列 j の右端に固定されている場合、列 j はそのセグメントの最上位にある必要があります。 

各柱の最上部に屋根を付けることができるのは 1 つまでで、そこに屋根を付ける場合は、どこまで伸びても費用を支払います。 目標は、総コストを最小限に抑えながら、いくつかの列をアンカーとして選択し、選択した各列に有効な方向セグメントを割り当て、すべての列が少なくとも 1 つのそのようなセグメントでカバーされるようにすることです。 

重要な問題は、選択したアンカーがそれ自体をカバーするだけではないことです。 選択した方向に高い柱にぶつかるまで延長できますが、この延長は「セグメント内の最大値」ルールによって制限されます。 高さはすべて異なるため、各セグメントには一意の最大値があり、これにより重複相互作用が簡素化されますが、排除されるわけではありません。 

n が 200000 までという制約は、セグメントの二次列挙が不可能であることを意味します。 O(n log n) または O(n) の解も必要です。 考えられるすべての (i, j) ペアを考慮するアプローチは、直ちに実行不可能になります。 

カバレッジ方向の制約を考慮せずに、素朴な貪欲な選択によりローカルで最も安価な列が選択される場合、微妙なエッジ ケースが発生します。 たとえば、非常に安価な列が中央にあるものの、両側の高い列によってブロックされているために両側をカバーできない場合、貪欲な選択では遠くの領域をカバーできません。 

別の故障モードは、列が大きな間隔で最大値である場合に発生しますが、それを選択するのはコストが高く、同時にその領域をカバーする 2 つのより安価な極大値が近くに存在する場合に発生します。 単純な「グローバル最大値拡張」アプローチは、セグメンテーションを正しく処理しない場合、大幅にコストがかかりすぎる可能性があります。 

## アプローチ

 ブルートフォース解釈では、考えられるすべての間隔 [i, j] を検討し、i を左アンカーとして選択するか、j を右アンカーとして選択することでカバーできるかどうかを判断し、最小のコストですべてのインデックスをカバーする有効なアンカー間隔のサブセットを選択しようとします。 これにより、当然のことながら、O(n^2) 間隔にわたるセット カバー スタイルの定式化が行われ、それぞれに O(1) または O(log n) のチェックが必要となり、最悪の場合、すでに 10^10 の演算を超えてしまいます。 

構造的なブレークスルーは視点を逆転させることで生まれます。 間隔という観点から考えるのではなく、何を強制的にカバーしなければならないのかという観点から考えます。 各列は、有効なセグメントが到達する何らかのアンカーで覆われている必要があります。 固定アンカー i の場合、左側に延長できるセグメントは、左側の最も近い上位の列によって決まり、右側へは右側の最も近い上位の列によって決まります。 これらの最も近い大きな境界は、配列を最大の可視性ゾーンに分割します。 

これにより、問題は、次に大きい要素によって決定される範囲にわたって「責任を主張する」アンカーの選択に変換されます。 列 i は、前の大きい要素 + 1 から i までのすべてをカバーする左アンカーとして機能し、同様に、i から次の大きい要素 - 1 までをカバーする右アンカーとして機能します。 コストはスパンではなくアンカーに付加されるため、各アンカーは片側の重み付けされた間隔に対応します。 

ここで、タスクは、すべての位置が少なくとも 1 回カバーされるように、一連の有向区間 (列ごとに左または右方向) を選択することになります。 各列は最大 2 つの候補区間に寄与し、区間は単調で次に大きい構造によって誘導されるため、並べ替えられた区間エンドポイントに対して貪欲なスイープまたは動的プログラミングを使用してそれらを処理できます。

最後の重要な洞察は、カバレッジは、すべての位置について、少なくとも 1 つの選択された間隔がその位置をカバーすることを保証することと同等であり、間隔の構造は、エンドポイントが単調スタックによって制約される間隔による 1 次元のカバーと同様に、フロンティア全体にカバレッジを拡張する最も安価な方法を常に維持することによって最適な選択を導き出せるようなものであるということです。

 | 間隔を超えた総当たり攻撃 | O(n^2) 以上 | O(n^2) | 遅すぎる |
 | モノトーン境界 + 貪欲な区間カバー | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 単調減少スタックを使用して、インデックスごとに、左側と右側で最も近い大きい要素を計算します。 このステップでは、列が最高のエンドポイントとして機能できる最大セグメントを特定します。 これがなければ、各アンカーの有効なカバレッジ範囲を知ることができません。 
2. 各列 i に対して、最大 2 つの候補区間を構築します。 i を左アンカーとみなすと、left_greater[i] + 1 から i までをカバーできます。 i が右アンカーの場合、i から right_greater[i] − 1 までをカバーできます。これらの間隔は、i にアンカーされているすべての有効なルーフを表します。 
3. 加重区間のセットを使用して範囲 [1, n] 全体をカバーするものとして問題を解釈します。ここで、各区間はそのスパンに関係なくコスト c_i を持ちます。 各インデックス i は、同じ重みを持つ最大 2 つの間隔に寄与します。 
4. 生成されたすべての間隔を開始点で並べ替えます。 左から右にスキャンしながら、到達可能な最も遠い範囲を貪欲に維持します。 
5. 現在のカバーされていない位置またはそれより前に始まる候補間隔に対する優先順位構造を維持します。 各ステップで、同じアンカーからのすべての間隔は同じコストを共有しますが、到達範囲が異なるため、カバレッジを最も右側に拡張する間隔を選択し、暗黙的に関係を解消します。 
6. 現在のカバレッジ境界を選択した間隔の終わりまで移動し、アレイ全体がカバーされるまで続けます。 

### なぜ効果があるのか

 単調スタックは、各間隔が「最高エンドポイント」制約に関して最大であることを保証するため、有効な解決策はこれらの境界を超えて間隔を拡張できません。 したがって、実行可能なカバーはこれらの最大間隔の中から選択する必要があります。 間隔が固定されると、残りの問題は、ラインをカバーする間隔の古典的な最小選択です。コストが長さごとではなく間隔ごとに付加されるため、より早く終了する代替選択は必要な間隔の数を増やすだけであり、コストを削減できないため、各ステップで最も遠くに到達する利用可能な間隔を貪欲に選択することが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    h = list(map(int, input().split()))
    c = list(map(int, input().split()))

    left = [-1] * n
    st = []
    for i in range(n):
        while st and h[st[-1]] < h[i]:
            st.pop()
        left[i] = st[-1] if st else -1
        st.append(i)

    right = [n] * n
    st = []
    for i in range(n - 1, -1, -1):
        while st and h[st[-1]] < h[i]:
            st.pop()
        right[i] = st[-1] if st else n
        st.append(i)

    intervals = []
    for i in range(n):
        intervals.append((left[i] + 1, i, c[i]))
        intervals.append((i, right[i] - 1, c[i]))

    intervals.sort()

    import heapq
    i = 0
    pos = 0
    ans = 0
    pq = []

    while pos < n:
        while i < len(intervals) and intervals[i][0] <= pos:
            l, r, cost = intervals[i]
            heapq.heappush(pq, (-r, cost))
            i += 1

        best_r = -1
        best_cost = None

        while pq:
            r_neg, cost = heapq.heappop(pq)
            r = -r_neg
            if r < pos:
                continue
            if best_r < r or (r == best_r and cost < best_cost):
                best_r = r
                best_cost = cost
                break

        ans += best_cost
        pos = best_r + 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、単調スタックを使用して両方向で最も近いより大きな境界を計算することから始まります。 これが必要なのは、セグメント内の最大値のままで各列がどこまで拡張できるかを正確にエンコードするためです。 

次に、列ごとに 2 つの間隔を構築します。 左側の間隔は、左側のエンドポイントの最大値である列に対応し、右側の間隔は、右側のエンドポイントの最大値である列に対応します。 どちらも有効な独立した選択であり、両方を考慮する必要があります。 

貪欲なループがフロンティアを維持する`pos`これは、最初にカバーされていない列を表します。 この位置またはそれより前で開始できるすべての間隔は、右のエンドポイントによってキー設定されたヒープにプッシュされます。 コストはスパンではなく選択したアンカーのみに依存するため、リーチを最大化すると有料アンカーの数が減ります。

 ## 特殊なケース

 単一列の最小限の配列により、左右の間隔構造が両方とも自己カバー セグメントに正しく縮退し、アルゴリズムが即座にそれを選択することが確認されます。 

厳密に減少または増加するシーケンスでは、単調なスタック境界が強調されます。 このような場合、各列の片側がエッジまで伸びており、アルゴリズムは少数の長い間隔を選択することになり、境界の計算が極端な場合に中断されないことが確認されます。 

高度に交互のコストは、貪欲な選択が誤って短くても安く見える間隔を好むかどうかをテストします。 間隔の定式化により、一度長い間隔が利用可能になると、追加の有料アンカーを必要とする短い間隔のシーケンスよりも優先されることが保証されるため、コストが不規則に変動する場合でも貪欲な選択が最適なままになります。
