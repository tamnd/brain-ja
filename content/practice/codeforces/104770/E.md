 ## 問題の理解

 ホテル日誌に記録された金銭請求のリストを渡されました。 各エントリは、部屋そのものを含め、セルゲイの滞在中に提供されるサービスに対応しています。 データが複雑になるのは、どのエントリがどのサービス タイプに対応するかが分からなくなり、実際のコストだけが残ることです。 

主要な構造ルールは、どのサービス タイプも滞在中は固定料金であるということです。 つまり、ジャーナルにサービスが複数回出現する場合、それらの出現はすべて同じ値を共有しますが、同じコストの他のサービスと区別することはできません。 特別なサービスの1つは部屋で、セルゲイが正確に滞在したことが知られています`n`日なので、ルームサービスの料金は正確に請求されているはずです`n`合計で回。 

タスクは、各レコードを何らかのサービス タイプに割り当てることができ、ルーム サービスは正確に説明する必要があるという考えと一致して、1 日あたりの客室料金を表す可能性のあるすべての値を決定することです。`n`の`m`記録。 

入力サイズは大きく、最大 300,000 レコードです。 これにより、ペアに対する二次推論や候補ごとの完全な配列の繰り返しの再スキャンが即座に排除されます。 値ごとに実現可能性をチェックするソリューションは、全体として線形または線形に近い時間で実行する必要があります。 

微妙な落とし穴は、宿泊料金が正確に表示されなければならないと想定していることです。`n`回。 それは必須ではありません。 少なくとも表示される必要があるだけです`n`マルチセット内の回数を選択できるようにする`n`それらの間の出来事は、日々にわたる部屋を表します。 追加の発生は、単に同じコストが発生する他のサービスとして解釈できます。 

サービスが 1 日ごとにグループ化されていると考えると、別の混乱が生じる可能性があります。 サービスが存在するという事実を除けば、1 日に発生するサービスの数に制限はありません。`n`合計日数がかかり、ルームは 1 日に 1 回表示されます。 

## アプローチ

 直接的なアプローチは、すべての個別のコスト値を宿泊料金の候補として試してみることです。 各候補値について`x`、リストに表示される回数を数え、少なくとも表示されるかどうかを確認します。`n`回。 もしそうなら、私たちは割り当てることができます`n`それらの発生をルーム サービスに送信し、残りの発生を同じタイプの他のサービスとして解釈します。 これは正しいです。サービス タイプを複数の個別のジャーナル エントリに使用することを妨げるものはないからです。 

この強引なアイデアは正しいですが、すべてのデータを新たにスキャンする必要があります。`m`それぞれの個別の値をエントリすると、最悪のケースが発生します。`O(m^2)`すべての値が異なる場合、これでは遅すぎます。`m = 3 × 10^5`。 

重要な点は、スキャンを繰り返す必要がないということです。 値の実現可能性は、その頻度のみに依存します。 1 回のパスですべての値の周波数を計算したら、少なくとも周波数を持つ値を直接フィルタリングできます。`n`。

 ## アルゴリズムのチュートリアル

 1.読む`n`、`m`、費用のリスト。 目標は、各コストがどのくらいの頻度で発生するかを理解することです。 
2. リスト内のすべての値の頻度マップを作成します。 これにより、考えられる各サービス価格が仕訳帳に表示される回数がキャプチャされます。 
3. 周波数マップ内のすべての個別の値を反復処理します。 
4. 各値について`x`、その頻度が少なくとも`n`。 「はい」の場合は含めてください`x`解答セットにあります。 その理由は、次のように割り当てることができるということです。`n`これらの出来事をルームサービスに伝えます`n`日々。 
5. 有効な候補の数とリスト自体を任意の順序で出力します。 

### なぜ効果があるのか

 同じ値の出現はすべて固定価格の 1 つのサービスとして扱うことができるため、それぞれの個別のコスト値は潜在的なサービス タイプに対応します。 部屋を表す値の唯一の制約は、部屋のエントリを 1 日に 1 つだけ割り当てられる必要があることです。`n`日数、これには少なくとも必要です`n`出来事。 未使用のオカレンスは常に同じタイプの追加のサービス レコードとして解釈できるため、これ以上の構造上の制約はありません。 これにより、周波数が唯一の決定要因となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    c = list(map(int, input().split()))
    
    freq = {}
    for x in c:
        freq[x] = freq.get(x, 0) + 1
    
    res = []
    for x, f in freq.items():
        if f >= n:
            res.append(x)
    
    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```この実装は、単一パスで構築された周波数辞書に完全に依存しています。 これにより、スキャンを繰り返す必要がなくなります。 最後のフィルタリング ステップは、個別の値の数が線形であり、最大でも`m`。 

よくある間違いは、1 日ごとの割り当てをシミュレートしようとしたり、明示的なグループを作成したりすることです。 唯一のグローバル制約は合計発生数であり、1 日あたりの構造ではないため、これは不要です。

 ## 特殊なケース

 いつ`n = 1`、単一の発生がその日の宿泊料金として機能するため、すべての値が有効です。 すべての周波数が少なくとも 1 つであるため、すべてのキーが含まれるため、アルゴリズムはこれを自然に処理します。 

すべての値が同一の場合、頻度は次のようになります。`m`、アルゴリズムは次の場合にその値を正しく返します。`m ≥ n`。 正確に割り当てることができるため、グループ化の解釈は依然として有効です。`n`部屋に起こる出来事。 

値がほとんど一意で、1 つだけが十分な回数繰り返される場合、その繰り返し値のみが頻度しきい値を超えます。 辞書ベースのカウントにより、単一の出現を誤って有効な候補として扱うことがなくなります。
