 ## 解決策
 ## 問題の理解

 エレベーターのディスプレイに階数が書かれています。 カティアはそれを直接読んでいません。 彼女はパネルの前に置かれた鏡でそれを見ます。 ミラーは一度に 2 つの変換を行います。 まず、左右が入れ替わるため、数字の順序が逆になります。 第 2 に、各数字自体が垂直方向の反射後にどのように見えるかに置き換えられます。 一部の数字は反射後も有効なままになり、別の数字になりますが、その他の数字は有効な数字の形状と一致せず、変化せずに認識されます。 

したがって、タスクは、7 セグメント スタイルのディスプレイに書き込まれ、ミラーで表示されたときに数字がどのように変換されるかをシミュレートすることです。数字の順序を逆にし、そのマッピングが存在する場合は各数字をミラーリングされた対応する数字に置き換え、そうでない場合はそのままにしておきます。 

入力は 10^18 までの単一の整数 k です。これは、数値が最大 18 桁であることを意味します。 これにより、桁数の線形処理を超える大きな整数演算や文字列処理の必要性が即座に排除されます。 O(d) (d は桁数) で実行されるソリューションは、簡単に十分に高速です。 

微妙な問題は、すべての桁が反射下で正しく動作するわけではないことです。 このタイプの問題では、通常、0、1、2、5、6、8、9 などの数字がミラー変換で考慮されますが、有効なミラーリングされた数字に対応するのはその一部だけであり、その他の数字は、有効な反映が存在するかどうかに応じて、別の数字にマップされるか、変更されないままになります。 数字がきれいにマッピングされていない場合、反射後にその数字がそれ自体として認識されるという問題が発生し、情報の損失は防止されますが、非対称性が生じます。 

エッジケースは、反転後のリフレクションが先行ゼロとどのように相互作用するかによって発生します。 たとえば、250 を反転すると 052 となり、出力では先頭の 0 を削除する必要があります。 逆文字列を構築して直接出力する単純なアプローチでは、誤って先頭のゼロが出力されたり、整数として一貫性なく扱われたりする可能性があります。 

もう 1 つの特殊なケースは、有効なミラーリングされた対応物を持たない数字です。 不注意な実装では、数字の固定全単射が想定される可能性がありますが、この問題では明示的にフォールバック動作が許可されており、リフレクション後も一部の数字が変更されないままになります。 これは、ミラー マッピングが完全に対称であるという一般的な前提を打ち破り、数字ごとのルールの適用を強制します。 

## アプローチ

 強引な解釈は簡単です。 整数を文字列に変換して逆変換し、各文字に数字変換ルールを適用します。 これは正しいです。ミラー効果は純粋に位置と桁ごとの変換であるため、シミュレーションはプロセスと正確に一致します。 

このアプローチのコストは、最大 18 桁の桁数に比例します。これを n 桁の一般的な問題として扱ったとしても、複雑さは O(n) となり、入力サイズの観点からはすでに最適化されています。 同様のタスクでブルートフォースのアイデアが時々失敗する唯一の理由は、変換にネストされた操作または桁ごとの繰り返しの再計算が含まれる場合ですが、ここでは当てはまりません。 

重要な観察は、反転を超えて桁間にグローバルな依存関係がないことです。 各桁は反転された後に独立して変換されます。 これにより、問題全体が単純なマッピングと文字列の反転に集約されます。 動的計画法、グラフ推論、算術分解は必要ありません。

 ## アルゴリズムのチュートリアル

 数字の操作が直接的かつ安全であるように、数字を文字列として扱います。

1. 整数 k を文字列表現に変換します。 これにより、数値の算術抽出が回避され、明示的な順序が維持されます。 
2. 文字列を逆にします。 これは、ディスプレイ全体を水平に反転するミラーをシミュレートします。 これが最初に行われる理由は、反射が数字の同一性の前に空間位置に作用するためです。 
3. リフレクション用の桁変換ルールを定義します。 数字ごとに、カティアが鏡の後に何を認識するかを決定します。 数字が有効なミラーリングされた数字にマップされている場合は、それに応じて置き換えます。 そうでない場合は、数字を変更しないままにします。 
4. 反転された文字列を反復処理し、変換ルールを各文字に個別に適用します。 これが機能するのは、反射によってクロスディジット効果が導入されないためです。 
5. 変換された数字を 1 つの文字列に結合します。 
6. 先頭のゼロを整数に変換するか手動でトリミングして削除します。 これにより、出力が通常の数値形式と一致することが保証されます。 

### なぜ効果があるのか

 正確さは、ミラー操作を 2 つの独立したアクション (位置の置換とローカル数字変換) に分解することで得られます。 反転ステップは、ミラーによって引き起こされる位置の並べ替えを完全に捕捉します。 数字マッピングのステップでは、各グリフが反射下でどのように変化するかをキャプチャします。 どちらのステップも隣接する数字に依存しないため、それらの構成は、反復や修正を行わずに視覚的変換全体を 1 回だけモデル化するのに十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k = input().strip()
    if not k:
        return

    # reverse digit order
    k = k[::-1]

    # mirror transformation for digits
    mp = {
        '0': '0',
        '1': '1',
        '2': '2',
        '5': '5',
        '6': '9',
        '8': '8',
        '9': '6'
    }

    res = []
    for ch in k:
        if ch in mp:
            res.append(mp[ch])
        else:
            res.append(ch)

    ans = ''.join(res)

    # remove leading zeros
    ans = ans.lstrip('0')
    if not ans:
        ans = '0'

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、制約により整数の格納が許可されている場合でも、数値のオーバーフローの問題を回避するために数値を文字列として読み取ります。 反転はすぐに実行され、ミラーの幾何学的効果がモデル化されます。 マッピング ディクショナリは、対称的な数字や 6 と 9 などの交換されたペアを含む、数字の反映動作をエンコードします。 

マッピングに存在しない数字は変更されずに残され、問題のフォールバック ルールと一致します。 最後に、先頭のゼロが削除されます。これは、250 のような逆数では、標準の数値出力では無効なゼロで始まる文字列が自然に生成されるためです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、反転後に先行ゼロが生成される入力です。 入力用`10`、逆転は与えます`01`。 正規化を行わないと、単純な実装では次の出力が出力されます。`01`、これは無効です。 アルゴリズムは、変換された文字列を構築した後に先頭のゼロを削除することでこれを処理し、次の結果を生成します。`1`。 

もう 1 つのケースは、反射下でも不変のままである数字です。`8`。 入力用`808`、逆転が生み出す`808`、マッピングではすべての数字が変更されません。 このアルゴリズムでは各桁が独立して処理されるため対称性が維持され、位置の破損は発生しません。 

3 番目のケースには、次のような別の数字にマッピングされる数字が含まれます。`6`そして`9`。 入力用`609`、反転利回り`906`、マッピングによりスワップが正しく保存されます。 各桁は反転後に変換されるため、スワップは位置の正確さを妨げず、最終出力はミラーリングされた読み取り値と一致したままになります。
