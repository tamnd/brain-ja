 ## 解決策
 ## 問題の理解

 寸法のある長方形の広場が与えられます$n \times m$。 各ランプは、軸に沿った小さなサイズの正方形領域を照らすのに十分強力です。$k \times k$。 ランプが広場のどこかに設置されると、広場全体が覆われます。$k \times k$ブロック。 

目標は全体をカバーすることです$n \times m$最小限の長方形を使用する$k \times k$できるだけランプ。 ランプは重なり合ったり、広場の境界を越えて拡張したりできますが、長方形の外側をカバーしても役に立ちません。 

タスクは、その数を決定することになります。$k \times k$タイルを完全に敷き詰める、または覆うには正方形が必要です。$n \times m$グリッド。 

制約により許可されるのは、$n, m, k$まで$10^9$。 これにより、一度に 1 単位ずつ行または列を反復するアプローチは直ちに排除されます。 有効な解はすべて定数時間演算でなければなりません。 

素朴な誤解は、境界線での部分的なカバレッジを考慮せずに正方形を「当てはめる」ことを考えることから生じます。 たとえば、次の場合$n = 4, k = 3$、左上に配置された 1 つのランプは、たとえ$4 < 2 \cdot 3$欲深い仮定を誘惑するかもしれません。 

もう 1 つの微妙なケースは、次元が次の倍数である場合です。$k$。 もし$n = 6, k = 2$、その後、カバレッジはきれいになります。 しかし、もし$n = 7, k = 2$、たとえ 1 列だけが覆われていないとしても、最後のストリップにはまだ完全な追加ランプが必要です。 

これらの境界効果はまさに天井動作を不可欠なものにします。 

## アプローチ

 ブルートフォース手法では、行ごと、列ごとにランプの配置をシミュレートします。 グリッドをスキャンし、セルが露出するたびにランプを配置し、そのセル全体にマークを付けることを想像することもできます。$k \times k$カバーされている地域。 

これは概念的には機能しますが、コストは膨大です。 最悪の場合、各ランプは約$k^2$セルなので、配置数はおよそ$(n \cdot m) / k^2$。 と$n, m \le 10^9$、グリッドのサイズは最大です$10^{18}$、シミュレーションが不可能になります。 

重要な観察は、カバレッジが両方の次元で完全に周期的であるということです。 各ランプは以下の部分をカバーします。$k$-による-$k$ブロックなので、1 つの軸に沿って、サイズの完全なブロックがいくつあるかだけを考慮します。$k$フィット、および剰余が存在するかどうか。 各軸は独立した切り上げ問題になります。 

長さに沿って$n$、必要です$\lceil n / k \rceil$セグメント。 幅に沿って$m$、必要です$\lceil m / k \rceil$セグメント。 このようなセグメントの各ペアは、ブロックのグリッド内の 1 つのランプ配置に対応するため、合計はそれらの積になります。 

これにより、2D 幾何学的被覆問題が 2 つの独立した 1D 天井分割に縮小されます。

2. どれだけ満たされているかを計算します$k$- カバーするには長さのセグメントが必要です$m$同じ天井ロジックを使用します。 これにより、右端に覆われていないストリップが残らないようになります。

### なぜ効果があるのか

 各ランプは正確にカバーします$k \times k$軸揃えブロック。 有効な配置戦略では、平面を複数の領域に分割します。各領域は、単一のランプ内にある場合にのみ 1 つのランプで完全にカバーできます。$k \times k$カバーグリッドのブロック。 

各軸に沿った天井分割により、その軸を完全にまたがるのに必要な最小限の数のブロックが生成されます。 カバレージは長方形であり、軸全体で独立しているため、これらのパーティションのデカルト積により最小数のランプが得られます。 いずれかの軸の数を減らすと、セグメントが$k$発見された。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    
    # ceiling division without floats
    need_n = (n + k - 1) // k
    need_m = (m + k - 1) // k
    
    print(need_n * need_m)

if __name__ == "__main__":
    solve()
```このソリューションは 3 つの整数を読み取り、標準の整数トリックを使用して上限除算を計算します。$(x + k - 1) // k$。 これにより浮動小数点エラーが回避され、次の時間まで安全に動作します。$10^9$。 

乗算ステップは Python の整数範囲内で安全であり、追加のオーバーフロー処理は必要ありません。

 ## 特殊なケース

 主なエッジケースは、1 つの次元が以下よりも小さい場合です。$k$。 例えば、$n = 2, m = 10, k = 3$。 

ここ、$need_n = \lceil 2/3 \rceil = 1$そして$need_m = \lceil 10/3 \rceil = 4$、合計 4 つのランプになります。 

高さがランプのサイズより小さい場合でも、カバレッジを分割して配置できないため、少なくとも 1 列のランプが必要です。 

もう 1 つのエッジ ケースは、次のように両方の次元が正確な倍数である場合です。$n = 6, m = 6, k = 3$。 それから$need_n = 2$、$need_m = 2$、答えは 4 です。各ランプが固定されているため、境界を越えてカバレッジを「マージ」しようとすると失敗します。$k \times k$四角; オーバーラップを最適化しないと、グリッド数を減らすことができます。 

最後に、いつ$k = 1$、各セルには独自のランプが必要です。 式によって生成されるのは、$n \cdot m$これは、各単位正方形が個別に照明される必要があるという直観と一致します。
