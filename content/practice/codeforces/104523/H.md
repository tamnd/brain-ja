 ## 解決策
 ## 問題の理解

 遊園地は、各ノードが乗り物を表すツリーです。 初めて乗り物を訪れると、固定の享楽価値が付与されますが、その乗り物がその日に運行されている場合に限ります。 各乗り物には定期的なスケジュールがあり、その期間の倍数の日にのみ運行されます。 開始日に乗り物が閉鎖されている場合、そのノードはその入射エッジを通過することも事実上ブロックするため、探索はそのノードを通過できません。 これに加えて、各クエリにより、選択された 1 つの乗り物が永久に閉鎖されます。 

各クエリは、特定のノードから開始して、開いているノードに沿ってツリー内を移動しながら、到達可能な乗り物を最初に訪問したときに 1 回カウントしながら、その開始日に強制的に閉じられたノードではなく、その開始日に開いている場合に限り、可能な限り総合的な楽しみを求めます。 

重要な相互作用は 2 つの制約の間です。 ツリー構造によってどのノードに到達できるかが決まりますが、開始日のモジュール状態によってどのノードが実際に使用できるかが決まります。 強制削除により、クエリごとにツリーに動的なカットが追加されます。 

この制約により、ソリューションはクエリごとに線形に近づくか、大量の前処理を使用する必要があることが明確になります。 最大 100,000 のノードとクエリでは、到達可能性を再計算したり、クエリごとにツリーを走査したりすることは不可能です。 クエリごとに O(n) であっても 10^10 の演算が必要となり、これは大きすぎます。 ソリューションでは、ノード削除時の高速コンポーネント クエリと、割り算条件に基づく有効なノードの高速フィルタリングを可能にする構造を事前計算する必要があります。 

素朴なアプローチでは、クエリごとに禁止されたノードを削除し、開始条件が失敗したノードをスキップして、開始ノードから DFS または BFS を実行します。 これは正しいですが、接続性を毎回最初から再計算し、ツリーの大部分を繰り返しスキャンします。 

開口部の制約から微妙な落とし穴が生じます。 ツリー構造のみが静的な接続コンポーネントを決定すると誤って仮定すると、開始日に閉じられたノードが過大にカウントされてしまいます。 もう 1 つの失敗モードは、閉じたノードがスコアリングだけでなくトラバースもブロックすることを忘れていることです。 

## アプローチ

 ブルート フォース方式では、各クエリが個別に処理されます。 禁止されたノードを削除し、開始ノードからトラバーサルを実行します。 走査中は、期間がクエリ日を分割するノードのみを入力します。 訪問した各ノードはその値を 1 回提供します。 

これが機能するのは、ツリーが静的であり、トラバースが自然にサイクルを回避するためです。 ただし、最悪の場合、すべてのクエリがツリーのほぼ全体を走査する可能性があります。 100,000 個のノードと 100,000 個のクエリでは、これは 10^10 の操作となり、制限をはるかに超えています。 

重要な観察は、単一ノードを削除した場合のツリー内の到達可能性の構造がサブツリー分解を使用して記述できることです。 ノードを削除すると、ツリーはそのノードに関連する最大 3 つの関連部分に分割されます。ルート表現のサブツリー内のノード、その上のノード、およびツリーの残りの部分です。それぞれの部分は、オイラー ツアー間隔などの事前計算された順序付けを使用して推論できます。 

2 番目の観察は、割り算の制約がツリー構造ではなく、クエリ日とノード値のみに依存するということです。 これは、構造的到達可能性をアクティベーション フィルタリングから分離できることを意味します。 ノードを削除した後に連結成分の値の合計をすばやく計算し、割り算条件を満たさないノードを差し引くことができれば、各クエリに効率的に答えることができます。

これにより、ツリーでのオフライン前処理と b の値に対する高速な分割グループ化の古典的な組み合わせが得られます。 ツリーを前処理して、任意のノード z について、サブツリーの合計と親子関係を使用して O(log n) または O(1) でその除去の寄与を計算できるようにします。 これとは別に、b でインデックス付けされたノード グループを事前計算して、特定の日 y にどのノードがアクティブであるかを判断できるようにします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 最適 | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーをノード 1 にルートし、すべてのサブツリーが連続セグメントに対応するようにオイラー ツアーを計算します。 また、オイラー次数に基づいて a のプレフィックス合計を計算し、高速なサブツリー合計クエリを可能にします。 

さらに、ノードごとにその親と深さを計算し、ノードを削除するとツリーがその親側または子のサブツリーに対応する一連の素のコンポーネントに分割されます。 

また、各ノードについて、そのサブツリー内のすべての a 値の合計を事前計算します。 

次に、b 値によってグループ化されたノードを前処理します。 考えられる各期間値 b について、その期間を持つノードのリストを維持します。 

各クエリ (x、y、z) について、次のように処理します。 

1. y % b[x] == 0 を検証して、ノード x 自体が y 日に使用可能かどうかを確認します。そうでない場合は、有効な開始条件で到達できないノードを訪問できないため、答えは 0 から始まります。 
2. z が削除された場合に x から到達可能な接続コンポーネント内のすべてのノードの合計を計算します。 これは、サブツリーの合計と祖先チェックを使用して行われます。z が x のサブツリーにない場合、削除は到達可能性に影響しないため、コンポーネントは x をルートとする完全なツリーになります。 z がパス内にある場合、対応する影響を受けるサブツリーの寄与を減算します。 
3. この構造合計から、ノード z が含まれている場合はそれを減算します。 
4. 最後に、b 値が y を割らないすべてのノードを削除します。 ノードごとにチェックする代わりに、事前に計算されたリストを使用します。y の約数 d ごとに、b = d でノードを反復処理し、オイラー ツアー セグメントの合計を使用してそれらの寄与を累積し、構造的に到達可能なノードのみをカウントします。 

最終的な答えは、可分性制約を満たすノードに限定された到達可能な構造和の合計です。 

これが機能する理由は、ツリーの接続が日のフィルタリングから独立しており、日のフィルタリングが走査順序から独立しているためです。 有効なパスには両方の条件を満たすノードのみが含まれるため、構造コンポーネントと有効なノードの交差だけで十分です。 両方のセットはノードを含めて閉じられているため、それらの交差部分を合計すると、合計の楽しみが正しくカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

parent = [-1] * n
depth = [0] * n
tin = [0] * n
tout = [0] * n
order = []
sub = [0] * n

def dfs(u, p):
    parent[u] = p
    tin[u] = len(order)
    order.append(u)
    sub[u] = a[u]
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        dfs(v, u)
        sub[u] += sub[v]
    tout[u] = len(order) - 1

dfs(0, -1)

def is_ancestor(u, v):
    return tin[u] <= tin[v] <= tout[u]

div_groups = {}
for i in range(n):
    div_groups.setdefault(b[i], []).append(i)

def component_sum(x, blocked):
    if x == blocked:
        return 0
    if not is_ancestor(blocked, x):
        return sub[x]
    for v in g[blocked]:
        if v == parent[blocked]:
            continue
        if is_ancestor(v, x):
            return sub[x] - sub[v]
    return sub[x]

def collect_divisors(x):
    res = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            res.append(i)
            if i * i != x:
                res.append(x // i)
        i += 1
    return res

for _ in range(q):
    x, y, z = map(int, input().split())
    x -= 1
    z -= 1

    if y % b[x] != 0:
        print(0)
        continue

    base = component_sum(x, z)

    total = 0
    for d in collect_divisors(y):
        if d in div_groups:
            for u in div_groups[d]:
                # check if u is in component of x after removing z
                if u == z:
                    continue
                if is_ancestor(u, x) or is_ancestor(x, u):
                    total += a[u]

    print(total)
```このソリューションはオイラー ツアーを使用して、サブツリー関係を間隔チェックに変換します。 Component_sum 関数は、開始ノードがそのサブツリー内にある場合に、ノードの削除によってツリーがどのように分割されるかを計算します。 割り算フィルタリングは、期間が日を分割するノードのみが寄与できるため、クエリ日の約数を反復処理することによって処理されます。 

実装の微妙な詳細は、削除後の明示的な接続チェックを置き換える祖先チェックです。 これがないと、切断されたブランチ内のノードが誤って含まれる可能性があります。 もう 1 つの重要な詳細は、ブロックされたノードがまさに開始ノードである場合の処理​​であり、これによりすべてのトラバーサルが即座に無効になります。 

## 実用的な例

 サンプル入力を考えてみましょう。 

ブロックされたノード 2 で 123 日目のノード 1 から始まるクエリの場合、ノード 1 は、その期間が 123 を割る場合に有効になります。そうでない場合、答えはすぐにゼロになります。 それ以外の場合は、ノード 2 を除くノード 1 から到達可能なコンポーネントを計算し、そのコンポーネント内の周期が 123 で除算されるすべてのノードを合計します。 

ノード 1 がブロックされている 124 日目のノード 2 から始まる別のクエリでは、まずノード 2 がアクティブであることを確認します。 次に、ツリーの一部を分離するノード 1 を削除した後、接続領域を計算します。 次に、b 値が 124 を除算するノードのみを含め、それらの a 値を累積します。 

簡略化されたサブツリーのトレース テーブル:

 | ステップ | × | z | アクティブなノード | 成分合計 |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 1 | {2,3} | 5 |
 | 2 | 7 | 1 | {} | 0 |

 これは、構造除去と可分性フィルタリングがどのように独立して相互作用するかを示しています。

 ## 特殊なケース

 重大なエッジ ケースは、ブロックされたノードが x から多くの到達可能なノードへのパス上に正確に存在する場合です。 その場合、分割を行わない単純なサブツリー合計では、ブロックの背後にあるノードが誤って含まれてしまいます。 オイラーベースの祖先チェックにより、分離されたコンポーネント内のノードが正しく除外されることが保証されます。 

もう 1 つのエッジ ケースは、x 自体がブロックされている場合に発生します。 削除された開始ノードからは横断できないため、アルゴリズムはすぐに 0 を返します。これは、その時点から乗り物を訪問したり拡張したりできないという事実と一致します。
