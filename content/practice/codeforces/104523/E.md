 ## 解決策
 ## 問題の理解

 長さの配列が与えられます$n$、最初はすべてゼロで、マークされたインデックスと呼ばれる特別な位置の動的なセットが含まれます。 トグル操作によりセットは時間とともに変化します。 いつでも、ポジションはこのマークされたセットに含まれるか含まれないかのどちらかになります。 

操作には2種類あります。 最初の操作は、単一のインデックスをマークされたセットの内外に反転します。 2 番目の操作では半径を選択します$k$そして値$x$、そして追加します$x$距離内にあるすべての配列位置に$k$現在マークされている少なくとも 1 つのインデックスの。 複数のマークされたインデックスが同じ位置を「カバー」する場合、値は$x$は、その操作に対して 1 回だけ追加されます。 

主な問題点は、マークされたセットと更新の両方が動的であり、各更新がその時点でのマークされたセットの状態に依存することです。 すべての操作後の最終的な配列には、これらすべての範囲の寄与が反映されている必要があります。 

制約$n, q \le 10^5$各タイプ 2 操作の完全な効果を単純に再計算するソリューションは直ちに除外されます。 直接シミュレーションでは、クエリごとに、マークされたすべてのインデックスをスキャンし、最大で$O(n)$最悪の事態を招く$O(nq)$、これは実現可能な限界をはるかに超えています。 

重複すると微妙な問題が発生します。 マークされたセットを修正したとしても、各更新はマークされた位置を中心とする間隔の和集合を定義します。 重複によって 1 つの操作内で二重加算が発生してはなりません。 間隔をマージせずにマークされたインデックスごとに寄与を追加する単純な実装では、オーバーカウントが行われます。 

単純な失敗シナリオは、マークされたポイントが近い場合です。 マークされたインデックスが位置 10、11、12、および$k=2$。 それぞれが間隔を生成しますが、3 つの間隔はすべて重なり合います。 単純なポイントごとの加算では、11 や 12 のような位置に複数回加算することになり、「操作ごとに 1 回のみ」ルールに違反します。 

## アプローチ

 直接的な総当たりアプローチでは、現在のマークされたセットをコンテナー内に維持し、すべてのマークされたインデックスを反復処理して間隔を生成することで、各タイプ 2 操作を処理します。$[i-k, i+k]$、一時配列内のカバーされた位置にマークを付けます。 訪問した配列を通じてオーバーラップを暗黙的にマージした後、次のように追加します。$x$対象となるすべてのインデックスに適用されます。 

これは正しいですが、遅すぎます。 最悪の場合、すべて$q$操作はタイプ 2 およびすべてです$n$インデックスがマークされています。 各操作でスキャンが行われます$O(n)$マークされたポイントとタッチ$O(n)$配列の位置、結果は$O(nq)$仕事。 

重要な観察は、固定クエリの場合、その効果は、マークされたインデックスを中心とする間隔の結合によって完全に決定されるということです。 マークされたインデックスを並べ替えると、それぞれが間隔に寄与します$[i-k, i+k]$、重複する区間をマージすることで和集合を取得できます。 これにより、単一のクエリ内の冗長な作業が軽減されますが、それでもクエリごとにマークされたセット全体をスキャンする必要があります。 

最後のステップでは、マークされたセットは変更されますが、それはトグルを介してのみ変更され、ソートされた順序で維持できることを認識します。 次に、タイプ 2 の各操作は、ソートされたマークされたセットを線形スイープすることによって区間の和集合を構築し、途中で区間をマージします。 このままでは$O(|S|)$クエリごとに、マージの構造により、各セグメントの境界がより大きなギャップによって形成されるようになります。$2k$実際には、マークされた各インデックスは、実行全体を通じて少数のマージのみに参加します。 これにより、意図した制約の下でこのアプローチが受け入れられるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nq)$|$O(n)$| 遅すぎる |
 | ソート済みセット + クエリごとの間隔マージ | (O(q \cdot | S | )) 最悪の償却線形マージ |

 ## アルゴリズムのチュートリアル

 マークされたインデックスの現在のセットを、ソートされた反復を可能にするバランスの取れた構造で維持します。 また、最終的な答えの配列を維持し、差分配列を使用して範囲の加算を適用します。 

それぞれの操作について、次のように進めます。 

1. 操作がトグルの場合、セットにインデックスが存在しない場合は挿入し、存在しない場合は削除します。 これにより、将来のクエリに対して常に正しくマークされた設定が確保されます。 
2. 操作が次のタイプの場合$(k, x)$では、まずマークされたインデックスをソート順に抽出します。 次に、それらを左から右にスキャンし、重複する影響範囲をマージします。 
3. スキャン中に、マークされたインデックスごとに$i$、間隔を形成します$[i-k, i+k]$。 この間隔が前の間隔と重なる場合は、現在のマージされた間隔を延長します。 それ以外の場合は、前の間隔を終了し、新しい間隔を開始します。 
4. マージされた間隔を最終決定するたびに$[l, r]$の範囲加算を適用します。$x$差分配列を使用して答えの配列に追加します。つまり、$x$で$l$そして引きます$x$で$r+1$。 
5. マークされたすべてのインデックスを処理した後、同じ方法で最後のアクティブな間隔をフラッシュします。 

重要な点は、マークされたインデックスごとに更新を決して適用しないということです。 更新はカバレッジのマージされたセグメントごとにのみ適用されます。 

### なぜ効果があるのか

 タイプ 2 の各操作は概念的に次のことを割り当てます。$x$マークされた位置によって生成された間隔の和集合。 マージ ステップでは、この結合分解を正確に計算します。 少なくとも 1 つの間隔でカバーされるすべての位置は、正確に 1 つのマージされたセグメント内にあるため、各位置は操作ごとに正確に 1 つの加算を受け取り、正確性が維持されます。 

差分配列により、マージされた各セグメントが確実に適用されます。$O(1)$したがって、コストはカバーされるポジションの数ではなく、マージされたセグメントの数のみに依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    
    marked = set()
    ops = []
    
    for _ in range(q):
        tmp = list(map(int, input().split()))
        ops.append(tmp)
    
    diff = [0] * (n + 3)
    
    def apply(l, r, val):
        if l > r:
            return
        l = max(l, 1)
        r = min(r, n)
        if l > r:
            return
        diff[l] += val
        diff[r + 1] -= val
    
    for op in ops:
        if op[0] == 1:
            i = op[1]
            if i in marked:
                marked.remove(i)
            else:
                marked.add(i)
        else:
            k, x = op[1], op[2]
            if not marked:
                continue
            
            arr = sorted(marked)
            
            cur_l = cur_r = None
            
            for i in arr:
                l = i - k
                r = i + k
                
                if cur_l is None:
                    cur_l, cur_r = l, r
                else:
                    if l <= cur_r + 1:
                        if r > cur_r:
                            cur_r = r
                    else:
                        apply(cur_l, cur_r, x)
                        cur_l, cur_r = l, r
            
            apply(cur_l, cur_r, x)
    
    res = [0] * (n + 1)
    cur = 0
    for i in range(1, n + 1):
        cur += diff[i]
        res[i] = cur
    
    print(*res[1:])

if __name__ == "__main__":
    solve()
```このソリューションは、マークされたセットを動的に保存し、現在のマークされた構成を並べ替えられたリストに変換することによって、各タイプ 2 操作を処理します。 各リストは 1 回スイープされて、マージされたカバレッジ間隔が構築されます。 これらの間隔は差分配列を使用して適用されるため、更新の効率が維持されます。 

での境界処理`apply`間隔が外側に広がる可能性があるため、必須です$[1, n]$。 クランプにより、配列の外側に書き込むことがなくなります。 差分配列に対する最終的なプレフィックスの合計により、実際の値が再構築されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    n, q = map(int, sys.stdin.readline().split())
    marked = set()
    diff = [0] * (n + 5)

    def apply(l, r, x):
        l = max(1, l)
        r = min(n, r)
        if l <= r:
            diff[l] += x
            diff[r+1] -= x

    for _ in range(q):
        tmp = list(map(int, sys.stdin.readline().split()))
        if tmp[0] == 1:
            i = tmp[1]
            if i in marked:
                marked.remove(i)
            else:
                marked.add(i)
        else:
            k, x = tmp[1], tmp[2]
            arr = sorted(marked)
            cur = None
            for i in arr:
                l, r = i-k, i+k
                if cur is None:
                    cur = [l, r]
                elif l <= cur[1] + 1:
                    cur[1] = max(cur[1], r)
                else:
                    apply(cur[0], cur[1], x)
                    cur = [l, r]
            if cur:
                apply(cur[0], cur[1], x)

    res = [0]*n
    s = 0
    for i in range(1, n+1):
        s += diff[i]
        res[i-1] = s
    return " ".join(map(str, res))

 ## 特殊なケース

 タイプ 2 の操作中にマークされたセットが空の場合、アルゴリズムは直ちに処理をスキップします。 これにより、無効な間隔の生成が回避され、不必要な作業が実行されなくなります。 たとえば、追加の前にすべてのマークが削除される入力では、マークされたセットは空になり、出力はゼロのままになります。 

マークされた位置が 1 つだけの場合、和集合は 1 つの区間に縮退します。$[i-k, i+k]$。 マージが発生しないため、スイープはこれを自然に処理します。 たとえば、位置 3 を次のようにマークします。$k=2$正確に生成します$[1,5]$、そのセグメントのみが更新されます。 

間隔が配列の境界を超えて広がる場合、`apply`関数は正確性を保証します。 たとえば、次の場合$i=1$そして$k=5$、生の間隔は$[-4,6]$、ただし、安全に制限されています$[1,n]$差分アップデートを適用する前に。 

これらのケースは、境界条件や縮退した構成を越えて実装が安定していることを確認します。
