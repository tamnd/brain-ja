 ## 解決策
 ## 問題の理解

 2 つの条件が満たされる限り、連続したセグメントを消去できる配列とルールが与えられています。 セグメントの長さは少なくとも 2 でなければならず、セグメント内の値は、最大値と最小値の差が最大以下であるという意味で「タイト」である必要があります。$k$。 このようなセグメントを消去するたびに、その長さの半分を切り捨てたコストを支払い、配列の残りの部分は互いに近づきます。 

このプロセスは何度でも繰り返すことができます。 目標は、最終的に残る要素の数を最小限に抑えることだけではなく、残りの最小サイズに到達するすべての方法の中で、総コストを可能な限り小さくすることも求めています。 

重要な点は、削除によって隣接関係が変化するということです。 セグメントが削除されると配列が圧縮されるため、後の操作は元のインデックスではなく新しい配列に作用します。 これは、元の配列の固定間隔を個別に選択しているのではなく、構造が変化し続ける圧縮のシーケンスを構築していることを意味します。 

制約は小さく、すべてのテスト ケースの要素の合計数は最大 500 です。これにより、おおよそより悪いものは即座に排除されます。$O(n^3)$テスト ケースごとに、区間動的計画法のソリューションが妥当であることさえ示唆しています。 また、貪欲なシミュレーションではなく、サブ配列と再結合の観点から考える必要があることを強く示唆しています。 

アレイを完全に消去できない場合、微妙なエッジケースが発生します。 たとえば、すべての要素が遠く離れている場合、$k = 0$、長さが 2 以上の有効なセグメントが存在しないため、最終的なサイズは次のように固定されます。$n$そしてコストはゼロです。 もう 1 つのエッジ ケースは、複数の重複する削除が考えられる場合です。最初の有効なセグメントを貪欲に削除すると、全体的に安価な今後の大規模な削除がブロックされる可能性があります。 

## アプローチ

 単純なアプローチでは、プロセスを直接シミュレートします。 各ステップで、すべてのサブ配列をスキャンし、どれが有効であるかを確認し、再帰的に各サブ配列を削除して、最良の結果を計算します。 これは正しいですが、組み合わせ的に爆発します。 現在の配列構成によって状態をメモ化したとしても、削除のたびにさまざまな方法で構造が変化するため、可能な配列の数は指数関数的になります。 

重要な観察は、操作は動的であるにもかかわらず、構造は依然として元の順序の間隔によって支配されるということです。 有効な操作はすべて現在の配列の連続セグメントに作用し、最終的な結果は、間隔をより小さな独立した間隔に繰り返し分割するか、間隔全体を一度に削除することになると考えられます。 これは、元の配列の静的部分配列を直接操作して、一定の間隔で動的プログラミング状態を定義できることを示唆しています。 

どのセグメントでも$a[l..r]$、意味のある可能性は 2 つだけです。 妥当性条件を満たしている場合はセグメント全体を 1 回の操作で削除するか、セグメント内の一部の要素を保持して、独立して解決される小さな間隔にセグメントを分割する必要があります。 削除により構造は圧縮されますが、要素の順序は変更されないため、間隔 DP は一貫したままになります。 

したがって、セグメントを完全に処理した後に残っている要素の最小数と、その中で必要な最小コストという 2 つの値を追跡する間隔にわたる DP を定義します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォースシミュレーション | 指数 | 指数 | 遅すぎる |
 | インターバルDP |$O(n^3)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 間隔があるかどうかをすばやく確認できるヘルパー構造を事前計算します。$[l, r]$最大値から最小値を引いた値が最大であるという条件を満たします。$k$。 これは、小規模な場合は簡単な事前計算で実行できます。$n$、またはその場で再計算されます。$n$小さいです。 

次に、各状態が間隔を表す DP テーブルを定義します。 

1. 定義する$dp[l][r]$ペアとして$(s, c)$、 どこ$s$部分配列を完全に処理した後に残る要素の最小数です。$a[l..r]$、 そして$c$そのサイズを達成するすべての方法の中での最小コストです。 
2. 設定により基本ケースを初期化します。$dp[i][i] = (1, 0)$、単一の要素は削除できず、コストゼロで 1 つの生き残った要素に寄与するためです。 
3. 2 から 3 までの間隔の長さごとに、$n$、すべてを計算します$dp[l][r]$有効な$l, r$。 
4. まず、間隔全体を削除するオプションを検討します。$[l, r]$1回の操作で。 間隔が有効で、長さが少なくとも 2 の場合は、完全に削除でき、次の状態が得られます。$(0, \lfloor (r-l+1)/2 \rfloor)$。 これはセグメント全体を 1 ステップで圧縮することを意味するため、重要です。 
5. 次に、可能なすべての位置で間隔を分割することを検討します。$m$間$l$そして$r$。 分割の結果、2 つの独立した部分問題が結合されます。$dp[l][m]$そして$dp[m+1][r]$。 結果のサイズはそれらのサイズの合計であり、コストはそれらのコストの合計です。 
6. これらすべてのオプションの中で、残りのサイズが最小のものを選択します。 複数のオプションで同じサイズが得られる場合は、コストが小さいものを選択してください。 
7. 各テストケースの答えは次のとおりです。$dp[1][n]$。 

正確さは、有効な削除のシーケンスが、ある段階で区間を完全に削除するか、区間内の少なくとも 1 つの要素を保持することによって表現できるという事実に基づいています。これにより、パーティションがより小さな独立したセグメントに強制されます。 これにより、間隔の分解が完了します。すべての有効な操作シーケンスは、時折完全な間隔の削除と組み合わせた間隔の再帰的分割に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def check_valid(a, l, r, k):
    mn = float('inf')
    mx = -float('inf')
    for i in range(l, r + 1):
        v = a[i]
        if v < mn:
            mn = v
        if v > mx:
            mx = v
    return mx - mn <= k

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    dp_size = [[INF] * n for _ in range(n)]
    dp_cost = [[INF] * n for _ in range(n)]

    for i in range(n):
        dp_size[i][i] = 1
        dp_cost[i][i] = 0

    valid = [[False] * n for _ in range(n)]
    for i in range(n):
        mn = mx = a[i]
        for j in range(i, n):
            mn = min(mn, a[j])
            mx = max(mx, a[j])
            valid[i][j] = (mx - mn <= k)

    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1

            best_size = INF
            best_cost = INF

            if valid[l][r]:
                best_size = 0
                best_cost = length // 2

            for m in range(l, r):
                s = dp_size[l][m] + dp_size[m + 1][r]
                c = dp_cost[l][m] + dp_cost[m + 1][r]

                if s < best_size or (s == best_size and c < best_cost):
                    best_size = s
                    best_cost = c

            dp_size[l][r] = best_size
            dp_cost[l][r] = best_cost

    return dp_size[0][n - 1], dp_cost[0][n - 1]

t = int(input())
for _ in range(t):
    ans = solve()
    print(ans[0], ans[1])
```比較を簡単にするために、DP は 2 つの配列に分割されます。1 つは残りのサイズのトラック、もう 1 つはコストです。 各間隔について、許可されている場合は最初に完全に削除してから、可能なすべての分割を試します。 辞書編集的な比較により、サイズの最小化がコストを優先し、問題の要件に正確に一致することが保証されます。 

よくある落とし穴は、完全に削除すると、以前の構造に関係なく残りのサイズがゼロに設定されることを忘れることです。そのため、次のように明示的に上書きします。$(0, cost)$候補として。 

## 実用的な例

 ### 例 1

 完全な削除が頻繁に発生する可能性があるアレイを考えてみましょう。 

| 間隔 | 決定 | サイズ | コスト |
 | --- | --- | --- | --- |
 | [1..2] | 有効な場合は削除 | 0 | 1 |
 | [1..3] | 分割または削除 | オプションの最小数 | 計算された |

 これは、DP がサイズを削減するときにどのように完全な間隔の削除を優先するかを示しています。 

### 例 2

 小さい場合、長さ 2 以上の間隔が有効でない配列を取得します。$k$。 すべての間隔は分割のみに戻ります。 

| 間隔 | 決定 | サイズ | コスト |
 | --- | --- | --- | --- |
 | [i..i] | ベース | 1 | 0 |
 | [l..r] | 分割のみ | 合計 | 0 |

 これは、削除が不可能な場合、アルゴリズムが縮退してすべての要素を保持することを示しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        INF = 10**18

        def valid(i, j):
            mn = min(a[i:j+1])
            mx = max(a[i:j+1])
            return mx - mn <= k

        dp_size = [[10**9] * n for _ in range(n)]
        dp_cost = [[10**9] * n for _ in range(n)]

        for i in range(n):
            dp_size[i][i] = 1
            dp_cost[i][i] = 0

        ok = [[False]*n for _ in range(n)]
        for i in range(n):
            mn = mx = a[i]
            for j in range(i, n):
                mn = min(mn, a[j])
                mx = max(mx, a[j])
                ok[i][j] = (mx - mn <= k)

        for length in range(2, n+1):
            for l in range(n-length+1):
                r = l + length - 1
                best_s, best_c = 10**9, 10**9

                if ok[l][r]:
                    best_s = 0
                    best_c = (r-l+1)//2

                for m in range(l, r):
                    s = dp_size[l][m] + dp_size[m+1][r]
                    c = dp_cost[l][m] + dp_cost[m+1][r]
                    if s < best_s or (s == best_s and c < best_c):
                        best_s, best_c = s, c

                dp_size[l][r] = best_s
                dp_cost[l][r] = best_c

        output.append(str(dp_size[0][n-1]) + " " + str(dp_cost[0][n-1]))

    return "\n".join(output)

 ## 特殊なケース

 単一要素の配列では削除が許可されないため、DP はサイズ 1 とコスト 0 を返さなければなりません。 初期化$dp[i][i] = (1, 0)$これは直接強制され、移行によって改善することはできません。 

いつ$k = 0$、同じ値のセグメントのみを削除できます。 妥当性テーブルは削除を正しく制限しており、DP は当然ながら、利益が得られる場合にのみ同一の実行をマージするようになります。 

配列全体が 1 つのセグメントとして有効な場合、DP はすぐに最上部の間隔で完全な削除を検討し、それを任意のパーティション化戦略と比較し、より小さいサイズが得られる場合にはグローバルな削除が正しく選択されることを確認します。
