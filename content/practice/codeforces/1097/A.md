 ## 解決策
 ## 問題の理解

 Gennady がプレイするゲームには、ランクまたはスートに基づいてカードをマッチングすることが含まれます。 実際には、テーブルに 1 枚のカードと 5 枚のカードが与えられます。 各カードは 2 つの文字で表されます。最初の文字はランクで、2 ～ 9 の数字または T、J、Q、K、A の文字です。2 番目の文字はスートで、D、C、S、または H のいずれかです。タスクは、手札のカードの少なくとも 1 枚がテーブル カードとランクまたはスートを共有するかどうかを判断することです。 そのようなカードが存在する場合は、それをプレイすることができ、出力は「YES」になるはずです。 それ以外の場合、出力は「NO」になります。 

制約は小さいです。 テーブル カードは 1 枚、手札は 5 枚しかありません。 これは、各カードを個別に検査するアルゴリズムは十分に高速であることを意味します。 高度なデータ構造、ハッシュ、並べ替えは必要ありません。 この問題は入力サイズが固定されているため本質的に定数時間であり、主な課題はアルゴリズムの効率性よりも慎重な実装です。 

明らかではないエッジケースには、スートまたはランクのみでテーブル カードと一致するカードがハンドに含まれている状況が含まれます。 たとえば、テーブル カードが 9H で、手札が 2H 3D 4S 5C 6D の場合、スートと一致するため 2H をプレイできます。 もう 1 つの微妙なケースは、プレイできる複数のカードを手札に持っていることです。 「YES」を 1 回出力するだけでよく、どのカードであるかは関係ありません。 不注意な実装では、ランクとスーツの両方の一致が誤って要求される可能性があり、これらの例では失敗します。 

## アプローチ

 最も簡単なアプローチは総当たり法です。手札の各カードを反復処理し、そのランクがテーブル カードのランクと一致するか、またはそのスートがテーブル カードのスートと一致するかどうかを確認します。 カードが 5 枚しかないため、これは実質的に一定の操作数になります。 ブルート フォース アプローチは、すべての可能性を徹底的にチェックし、指定された入力に対して実行時間は無視できるため、正しいことが保証されます。 

ブルートフォース手法ではすでにすべてのカードが 1 回検査されるため、漸近的な複雑さの点でこれより速いアプローチはありません。 即座の決定を可能にする観察は、一致するカードが見つかったらすぐに「YES」を返すことができるということです。 有効な手が見つかったら、残りのカードを確認する必要はありません。 この小さな早期終了は小規模な最適化ですが、ロジックが明確になります。つまり、一致が存在すると完了です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 効果的に O(5) → O(1) | お(1) | 承認済み |
 | 最適 | 効果的に O(5) → O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テーブルカードと 5 枚の手札を読みます。 各文字列の最初の文字はランク、2 番目の文字はスーツです。 
2. わかりやすくするために、テーブル カードからランクとスートを個別の変数に抽出します。 
3. 手札の各カードを繰り返します。 
4. 各ハンドカードについて、そのランクとスートを抽出します。 
5. ランクがテーブル カードのランクと一致するか、またはスートがテーブル カードのスートと一致するかどうかを確認します。 
6. 一致するものが見つかった場合は、すぐに「YES」を出力し、プログラムを停止します。 
7. 一致するものが見つからずにループが完了した場合は、「NO」を出力します。 

このアルゴリズムが機能するのは、不変条件が単純であるためです。テーブル カードのランクまたはスーツのいずれかに一致する場合にのみ、カードをプレイすることが許可されます。 各ハンドカードを個別にチェックし、一致が成功したらすぐに戻ることにより、有効なカードが見落とされたり、無効なカードが「YES」をトリガーしたりすることがないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

table_card = input().strip()
hand_cards = input().strip().split()

table_rank = table_card[0]
table_suit = table_card[1]

for card in hand_cards:
    if card[0] == table_rank or card[1] == table_suit:
        print("YES")
        break
else:
    print("NO")
```コードはまずテーブル カードを読み取り、手をリストに分割します。 テーブル カードのランクとスートを明示的に保存するため、インデックス作成の繰り返しが回避されます。 ループは各ハンド カードを順番にチェックします。 を使用して、`else`for ループの句により、一致するカードがない場合にのみ「NO」が出力されるようになります。これは、微妙ですが明確な Python 的なアプローチです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    table_card = input().strip()
    hand_cards = input().strip().split()
    table_rank = table_card[0]
    table_suit = table_card[1]
    for card in hand_cards:
        if card[0] == table_rank or card[1] == table_suit:
            return "YES"
    return "NO"

# Provided samples
assert run("AS\n2H 4C TH JH AD\n") == "YES", "sample 1"
assert run("4D\n5H 6S 7C 8H 9S\n") == "NO", "sample 2"

# Custom cases
assert run("9H\n9D 2C 3S 4D 5C\n") == "YES", "rank match only"
assert run("KH\n2H 3H 4H 5H 6H\n") == "YES", "suit match multiple"
assert run("TD\n2C 3S 4H 5C 6S\n") == "NO", "no match at all"
assert run("AS\nAD 2D 3D 4D 5D\n") == "YES", "rank match with first card"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 9H\n9D 2C 3S 4D 5C | はい | ランクマッチのみ |
 | KH\n2H 3H 4H 5H 6H | はい | 複数のカードがスーツに一致します |
 | TD\n2C 3S 4H 5C 6S | いいえ | ランクまたはスートに一致するカードはありません |
 | AS\nAD 2D 3D 4D 5D | はい | 最初のカードがランクに一致します |

 ## 特殊なケース

 スーツのみが一致する場合は、`table_card = 7C`そして`hand_cards = 2C 3H 4S 5D 6H`, 最初の手札にはスーツの一致があります。 ループはそれを即座に識別し、「YES」を出力して終了します。 ランクのみが一致する場合は、`table_card = 5D`そして`hand_cards = 5H 2S 3C 4H 6S`、最初のカードはランクによって一致し、これも「YES」をトリガーします。 一致するハンドがない場合、ループは一致を見つけることなく完了し、`else`句は「NO」を正しく出力します。 これにより、アルゴリズムがすべての非明白なエッジケースを正しく処理していることが確認されます。
