 ## 解決策
 ## 問題の理解

 置換が与えられているので、それを元の配列から順番に取得したいくつかのサブシーケンスに分割する必要があります。 各要素は、正確に 1 つのサブシーケンスに属している必要があります。 すべてのサブシーケンスは厳密に単調であり、厳密に増加または厳密に減少する必要があります。 

本当の困難は、単にパーティションを構築することではなく、サブシーケンスの数が、すべての順列に適用される最悪の場合の最適限界を超えないことを保証することです。 この境界は厳密であり、特定の入力から独立していることが知られているため、有効な分解を生成しながら、常にその境界内に留まることがタスクとなります。 

制約から、すべてのテスト ケースの合計の長さは最大 100000 であるため、どの解も線形または線形演算に近いものでなければなりません。 ネストされた検索を使用して単純な方法でスキャンを繰り返したり、サブシーケンスを最適にパックしようとしたりするアプローチは、敵対的置換における二次的な動作を引き起こす危険があります。 

一般的な失敗モードは、増加するシーケンスのみを貪欲に拡張しようとすると発生します。 たとえば、次のようなジグザグの順列では、`3 1 4 2 5 7 6`、常に最初の有効なサブシーケンスに接続する単純な戦略は、たとえより良いグローバル構造が存在したとしても、後で多数の短いフラグメントで行き詰まってしまう可能性があります。 

もう 1 つの微妙な問題は、規律あるルールなしに増加シーケンスと減少シーケンスを混合することです。 任意の切り替えを許可すると、他の場所でローカルに使用されていないため、より小さな要素を増加するサブシーケンスに追加するなど、単調性制約に静かに違反することが簡単になります。 

この問題の構造は、組み合わせパーティション検索ではなく、アクティブなモノトーン チェーンに関するスケジューリング問題として扱う必要があることを示唆しています。 

## アプローチ

 ブルートフォースアプローチでは、単調性を維持しながら、それを受け入れることができる既存のサブシーケンスに各要素を割り当てようとします。 要素ごとに、すべてのサブシーケンスをスキャンして、最後に追加できるかどうかを確認します。 最悪の場合、O(n) 個のサブシーケンスを維持し、要素ごとに O(n) 個の候補をチェックすると、これは O(n²) になり、100,000 個の要素では不可能です。 

重要な観察は、実際には恣意的に決定する必要はないということです。 代わりに、サブシーケンスごとに最大 2 つの「アクティブ フロント」を常に維持できます。1 つはチェーンの増加用、もう 1 つはチェーンの減少用です。 各要素は単調性を維持するチェーンに挿入する必要があり、有効な選択肢の中で、オプションを開いたままにする方向に最後の値が最も近いチェーンを延長することを常に優先する必要があります。 

これは当然、2 つの優先順位構造を使用する貪欲な構築につながります。1 つは最後の要素をキーとするサブシーケンスを増加させるもので、もう 1 つは最後の要素をキーとするサブシーケンスを減少させるものです。 可能であれば、各数値は既存のサブシーケンスに配置されます。それ以外の場合は、新しいサブシーケンスが開始されます。 

重要な構造的洞察は、順列において、増加する連鎖の延長に失​​敗するたびに、その失敗は減少する連鎖の自然な候補を暗示し、またその逆も同様であるということです。 この二重性により、一方向のすべての「不適切な配置」がもう一方の強制的な切り替えに対応するため、最適な数以上のチェーンが必要になることがなくなります。 

これを運用するためのクリーンな方法は、要素を順番に処理し、2 セットのアクティブなサブシーケンスを維持することです。 各サブシーケンスは増加または減少しており、作成よりも再利用を優先して、単調性を維持する有効なサブシーケンスに常に現在の要素をアタッチします。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 貪欲なアクティブチェーン | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの順序付けられた構造を維持します。1 つは最後の要素をキーとするアクティブな増加サブシーケンスを保存し、もう 1 つは最後の要素をキーとするアクティブな減少サブシーケンスを保存します。 各サブシーケンスには、最後の値と ID が格納されます。 
2. 左から右へ順列を処理します。 
3. 各要素 x について、まずそれを増加するサブシーケンスに配置しようとします。 最後の値が厳密に x より小さいサブシーケンスが必要です。 このようなすべてのサブシーケンスの中で、最後の値が最大のものを選択します。これは、将来の要素に対して最大限の柔軟性を残すためです。 
4. このような増加するサブシーケンスが存在する場合は、それに x を追加し、その最後の値を更新します。 
5. それ以外の場合は、x を減少するサブシーケンスに配置しようとします。 最後の値が厳密に x より大きいサブシーケンスが必要です。 これらの中で、最後の最小値を選択します。 
6. どちらの配置も不可能な場合は、x のみを含む新しいサブシーケンスを開始し、将来の拡張の実現可能性に基づいてその初期方向を決定します。これは、単一要素のサブシーケンスが増加および減少しているため安全です。 
7. 最後に完全なサブシーケンスを出力できるように、各要素の割り当てを記録します。 

### なぜ効果があるのか

どの時点でも、各サブシーケンスは明確に定義された最後の値を持つ単調チェーンを表します。 貪欲な選択により、将来の要素のために最も多くの「スペース」を残すサブシーケンスを常に拡張することが保証されます。つまり、チェーンが増加する場合は可能な限り最大の先行処理、チェーンが減少する場合は可能な限り最小の後続処理が行われます。 これは忍耐のソート原理を反映しており、アクティブなチェーンの数が常に最小限に抑えられます。 すべての新しいチェーンは、既存のチェーンがその要素を受け入れることができない場合にのみ作成されるため、チェーンの数は、すべての置換に必要な最小限の分解限界と一致するように強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_left, bisect_right

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    inc_vals = []  # (last_value, id)
    dec_vals = []  # (last_value, id)
    
    # we store subsequences
    seq = []
    
    # mapping id -> list of values
    subs = []
    
    for x in a:
        placed = False
        
        # try increasing: find rightmost last < x
        if inc_vals:
            # inc_vals sorted by last value
            i = bisect_left(inc_vals, (x, -1)) - 1
            if i >= 0:
                last, sid = inc_vals[i]
                inc_vals.pop(i)
                subs[sid].append(x)
                inc_vals.insert(bisect_left(inc_vals, (x, sid)), (x, sid))
                placed = True
        
        if placed:
            continue
        
        # try decreasing: last > x, choose smallest such last
        if dec_vals:
            i = bisect_right(dec_vals, (x, 10**18))
            if i < len(dec_vals):
                last, sid = dec_vals[i]
                dec_vals.pop(i)
                subs[sid].append(x)
                dec_vals.insert(bisect_left(dec_vals, (x, sid)), (x, sid))
                placed = True
        
        if not placed:
            sid = len(subs)
            subs.append([x])
            inc_vals.insert(bisect_left(inc_vals, (x, sid)), (x, sid))
            dec_vals.insert(bisect_left(dec_vals, (x, sid)), (x, sid))
    
    print(len(subs))
    for s in subs:
        print(len(s), *s)

if __name__ == "__main__":
    solve()
```このコードは、アクティブなサブシーケンスの 2 つの並べ替えられたリストを維持し、要素が割り当てられるとそれらを更新します。 各サブシーケンスは一度保存され、その互換性の増加と減少の両方が同じ最後の値を介して追跡されます。 重要な実装の詳細は、追加するたびにサブシーケンスを削除して再挿入し、最後の値による順序を維持することです。 

決定ロジックは厳密です。他の場所に収まらない要素のチェーンの減少が保持されるため、配置の増加が常に最初に試行されます。 この順序により、新しいサブシーケンスの不必要な作成が防止されます。 

## 実用的な例

 ### 例 1:`4 3 1 2`アクティブなサブシーケンスとその最後の値を追跡します。 

| ステップ | × | 選択されたサブシーケンス | ステップ | 後の状態
 | --- | --- | --- | --- |
 | 1 | 4 | 新しい | [4] |
 | 2 | 3 | 新しい (増加を拡張することはできません) | [4]、[3] |
 | 3 | 1 | 新しい | [4]、[3]、[1] |
 | 4 | 2 | 拡張 [1] | [4]、[3]、[1,2] |

 これは、構造が出現すると、小さな要素が最終的に結合して増加するチェーンになる様子を示しています。 

### 例 2:`4 5 6 1 3 2`| ステップ | × | アクション | 状態 |
 | --- | --- | --- | --- |
 | 1 | 4 | 新しい | [4] |
 | 2 | 5 | 拡張する | [4,5] |
 | 3 | 6 | 拡張する | [4,5,6] |
 | 4 | 1 | 新しい | [4,5,6]、[1] |
 | 5 | 3 | 拡張する | [4,5,6]、[1,3] |
 | 6 | 2 | 新規または再配置 | [4,5,6]、[1,3]、[2] |

 トレースは、大きな増加構造が保存されている一方で、より小さな要素が個別のチェーンを形成し、後に増加セグメントになることを示しています。

 ## 特殊なケース

 次のような厳密に減少する順列`5 4 3 2 1`すべての要素が減少チェーンを開始または拡張するように強制します。 このアルゴリズムは、増加配置に繰り返し失敗し、すべての新しい要素が常に同じ減少構造に適合するため、断片化することなく単一の減少サブシーケンスを正しく構築します。 

次のような厳密に増加する順列`1 2 3 4 5`減少するフォールバックをトリガーすることはありません。 各要素は同じ増加チェーンを拡張し、単一のチェーンで十分な場合、アルゴリズムが不必要なサブシーケンスを作成しないことを確認します。 

のようなジグザグパターン`3 1 4 2 5`新しいサブシーケンスの強制と既存のサブシーケンスの拡張を交互に行います。 貪欲なルールにより、新しく作成された各サブシーケンスが無駄にされるのではなく、後の要素ですぐに役立つことが保証され、サブシーケンス全体の最適な境界が維持されます。
