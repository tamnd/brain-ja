 ## 解決策
 ## 問題の理解

 それぞれが最初は空である一連のマルチセットに対する操作をシミュレートするように求められます。 操作は、単一の値をマルチセットに割り当てるか、ユニオンを介して 2 つのマルチセットを結合するか、最大公約数を使用してマルチセットの積を介して 2 つのマルチセットを結合するか、または値の出現数のパリティをクエリするかのいずれかです。 入力はマルチセットの数と一連の操作を指定し、出力は次の文字列になります。`0`そして`1`各クエリの結果のモジュロ 2 に対応します。 

制約は厳しいです。最大 100,000 個のマルチセットと 1,000,000 個の演算が可能で、その値は 7000 で制限されます。各マルチセットのすべての要素を直接保存し、単純に GCD 積を計算するのは、あまりにも遅すぎます。$O(|A||B|)$要素。 単純なアプローチでは、最悪の場合は 2 次または 3 次になり、許容される 3 秒以内に完了することができません。 

明らかではないエッジ ケースは、同じマルチセットに対する繰り返し操作や、まったく存在しない可能性のある数値に関するクエリから発生します。 たとえば、マルチセットが複数回上書きされる場合は、以前の状態の結果が混在しないようにする必要があります。 もう 1 つの微妙な点は、答えはモジュロ 2 のみが必要であることです。 正確なカウントを維持しようとする試みはメモリを浪費するだけでなく、不必要です。 

小さな例でリスクを明確にします。 考慮する：```
2 3
1 1 6
3 2 1 1
4 2 3
```2 番目の操作では、マルチセット 1 の GCD をそれ自体で計算し、次の結果を生成します。`{6}`。 単純なカウントでは、繰り返される数値を誤って処理したり、モジュロ 2 の約定を忘れたりして、間違ったクエリの答えが生成される可能性があります。 

## アプローチ

 ブルートフォースアプローチは、各マルチセットを数値のリストとして明示的に保存することです。 シングルトンの割り当ては簡単です。 ユニオンはリストを連結することで実行できます。 積演算は、すべてのペアを反復して計算されます。`(a, b)`そして追加`gcd(a, b)`ターゲットのマルチセットに。 次に、クエリは、要求された数のモジュロ 2 の出現をカウントします。このアプローチは正しいですが、遅すぎます。サイズ 1000 の 2 つの大きなマルチセットの単一の積には、100 万回の GCD 計算が必要です。 10^6 の演算を行うと、合計時間は天文学的なものになります。 

効率的な解決策を可能にする重要な観察は、必要なカウントはモジュロ 2 だけであるということです。これにより、各マルチセットを値 1 ～ 7000 のビットセットとして表すことができます。ユニオン演算はパリティ目的でビットごとの XOR になり、代入は単一ビットを設定するだけです。 積演算は、各数値について、約数に関するメビウス反転によって表現できます。`v`、製品内でのパリティの出現は、次の倍数にわたるパリティの XOR です。`v`各オペランドから。 除数の関係を事前に計算すると、演算ごとに O(|A||B|) ではなく O(7000) で積を計算できるようになります。 これにより、合計実行時間が大幅に短縮されます。

 ## アルゴリズムのチュートリアル

 1. 1 ～ 7000 の数値のすべての約数を事前計算します。これにより、後で GCD 積を効率的に計算できます。 
2. メビウス関数を 7000 まで事前計算します。これは、2 を法とする積を計算するときに除数の合計を反転するために使用されます。 
3. の配列を初期化します。`n`各ビットは、その数値のカウントが奇数 (1) か偶数 (0) かを表します。 
4. 各操作を次の順序で処理します。 

1. 操作がシングルトンへの代入の場合`{v}`、ビットセットをリセットし、対応するビットを設定します。`v`1に。 
2. 演算がマルチセットの和集合の場合`y`そして`z`、ビットセットのビットごとの XOR を計算し、それをマルチセットに割り当てます。`x`。 
3. 演算がマルチセットの積である場合`y`そして`z`、ゼロの一時ビットセットを初期化します。 それぞれの番号について`v`1 ～ 7000 のすべてのパリティの XOR を計算します。`y`そして`z`の倍数に対して`v`事前に計算された除数セットとメビウス関数を使用し、結果をビットに割り当てます。`v`マルチセットの`x`。 
4. 操作がクエリの場合、クエリされた数値に対応するビット値を出力します。 
5. すべてのクエリ結果を文字列に連結して出力​​します。 

これが機能する理由: マルチセットを法 2 でビットセットとして表現すると、パリティ不変式が保持されます。 XOR は当然、加算法 2 をモデル化します。除数を事前計算し、メビウス反転を使用すると、すべてのペアを列挙することなく、法外に遅くなるマルチセット積が法 2 で正しく計算されます。 各操作は、パリティ カウントの正確さを維持する方法でマルチセットを変換します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 7000

# Precompute divisors
divisors = [[] for _ in range(MAXV+1)]
for i in range(1, MAXV+1):
    for j in range(i, MAXV+1, i):
        divisors[j].append(i)

# Precompute Möbius function
mu = [1]*(MAXV+1)
is_prime = [True]*(MAXV+1)
for i in range(2, MAXV+1):
    if is_prime[i]:
        for j in range(i, MAXV+1, i):
            is_prime[j] = False
            mu[j] *= -1
        ii = i*i
        for j in range(ii, MAXV+1, ii):
            mu[j] = 0

n, q = map(int, input().split())
multisets = [0]*(n+1)  # each multiset represented as integer bitset

# We will use integers as bitsets for numbers 1..7000
from array import array
bitsets = [array('B', [0]*(MAXV+1)) for _ in range(n+1)]

output = []

for _ in range(q):
    parts = input().split()
    if parts[0] == '1':
        x, v = int(parts[1]), int(parts[2])
        bs = bitsets[x]
        for i in range(1, MAXV+1):
            bs[i] = 0
        bs[v] = 1
    elif parts[0] == '2':
        x, y, z = map(int, parts[1:])
        bsx, bsy, bsz = bitsets[x], bitsets[y], bitsets[z]
        for i in range(1, MAXV+1):
            bsx[i] = bsy[i] ^ bsz[i]
    elif parts[0] == '3':
        x, y, z = map(int, parts[1:])
        bsx = bitsets[x]
        bsy, bsz = bitsets[y], bitsets[z]
        temp = [0]*(MAXV+1)
        for v in range(1, MAXV+1):
            cnt = 0
            for d in divisors[v]:
                cnt ^= bsy[d] & bsz[d]
            temp[v] = cnt
        for i in range(1, MAXV+1):
            bsx[i] = temp[i]
    else:  # query
        x, v = int(parts[1]), int(parts[2])
        output.append(str(bitsets[x][v]))

print(''.join(output))
```このソリューションでは、XOR 演算を明確にし、容易にするために、整数配列をビットセットとして使用します。 各代入、共用体、または積は、要素数のパリティを維持しながら、関連するビットセットを変更します。 クエリは、要求された数値に対応するビット値を直接読み取ります。
