 **タグ:** ビットマスク、ブルート フォース、DP
 **解決時間:** 3 分 57 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 360 度のダイヤルのように動作する円形のロックが与えられています。 ゼロから開始して一連の回転を実行します。各回転の大きさは固定されていますが、その方向は自由に選択できます (時計回りまたは反時計回り)。 時計回りは角度を加算し、反時計回りは角度を減算すると考えることができます。 

すべての回転を順番に適用した後、ポインタは 360 を法とする最終角度で終了します。タスクは、最終位置が正確に 0 に戻るように、すべての回転の方向を選択できるかどうかを判断することです。 

入力サイズは非常に小さく、最大 15 回転であり、各回転は 180 度で区切られます。 これは、符号割り当ての総数が最大でも 2^15、つまり約 32,000 構成であるため、全方向の選択に対する指数関数的検索が実行可能であることを直ちに示唆しています。 構成ごとの単純な評価でも、これは十分に制限内です。 

微妙な点は、問題が純粋に純和モジュロ 360 に関するものであるということです。中間の制約がないため、順序は固定されており、符号のみが問題となります。 

エッジケースはほとんどが小さな n 程度です。 n = 1 の場合、回転は 1 つだけ存在し、ゼロで終了する唯一の方法は、その 1 つの回転が 0 または 360 のいずれかである場合ですが、値は少なくとも 1 であるため、答えは常に NO です。 単純な誤解により、ステップごとにすぐにモジュロ 360 を減らそうとする可能性がありますが、最終的な合計のみを考慮するため、それは正確さに影響しません。 

もう 1 つのエッジ状況は、合計が 360 を複数回超える場合です。 たとえば、方向が相殺されて 360 の倍数になる可能性があるため、180、180、180 のような回転は引き続き機能します。 

## アプローチ

 この問題を考える最も直接的な方法は、各回転に方向を割り当てるあらゆる可能な方法を試してみることです。 それぞれの角度について、加算または減算を行い、結果の合計が 360 で割り切れるかどうかを確認します。この総当たり的なアプローチでは、すべての 2^n 符号の割り当てが試行されます。 すべての有効な構成を明示的に列挙しているため、これは正しいです。 

このアプローチのコストは急激に増加します。 n = 15 の場合、最大 32768 の構成を評価し、各構成について O(n) で合計を計算し、約 5×10^5 の演算を行います。 これは Python ではすでに問題ありませんが、さらに単純化することができます。 

重要な観察は、制約が十分に小さいため、力任せ以上の最適化は必要ないということです。 この問題は本質的に、各要素が正または負になるサブセット合計のバリアントです。 これはビットマスク列挙に直接マッピングされます。 

したがって、最適な解決策は、単純に 0 から (1 << n) - 1 までのすべてのマスクを反復処理し、各ビットを符号の選択肢として解釈し、結果の合計を計算して、それが 360 の倍数に等しいかどうかを確認することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (ビットマスク) | O(n · 2^n) | お(1) | 承認済み |
 | 最適 (同じ) | O(n · 2^n) | お(1) | 承認済み |

 この問題では、制約によりブルート フォースがすでに最適化されています。 

## アルゴリズムのチュートリアル

1. 角度のリストを読みます。 各角度は方向が決まっていない固定寄与を表します。 
2. 0 から (2^n - 1) までのビットマスクを使用して、符号割り当ての可能なすべてのサブセットを反復します。 各ビットは、そのステップで時計回りに回転するか反時計回りに回転するかを示します。 これにより、考えられるすべての有効な決定パスがエンコードされます。 
3. 各ビットマスクについて、累計をゼロに初期化します。 この合計は、選択した方向を適用した後の正味の角変位を表します。 
4. 回転リストの各インデックス i について、マスクの i 番目のビットをチェックします。 設定されている場合は、a_i を合計に加算し、設定されていない場合は、a_i を減算します。 これは、各回転で考えられる 2 つの方向をモデル化します。 
5. 指定されたマスクのすべての回転を処理した後、360 を法とする合計を計算します。それがゼロに等しい場合は、有効な構成が存在し、すぐに停止できます。 
6. どのマスクもゼロモジュロ結果を生成しない場合は、開始位置にポインタを戻す一連の方向はないと結論付けます。 

### なぜ効果があるのか

 すべての有効な方向シーケンスは 1 つのビットマスクに一意に対応します。 方向の選択から +a_i または -a_i への変換では、正確な最終角度が保存されます。 すべての 2^n の可能性を列挙するため、考えられるすべての最終結果をカバーします。 モジュロ条件はロックの循環的な性質を捉えており、360 度の倍数がゼロと同等であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [int(input()) for _ in range(n)]
    
    for mask in range(1 << n):
        total = 0
        for i in range(n):
            if mask & (1 << i):
                total += a[i]
            else:
                total -= a[i]
        if total % 360 == 0:
            print("YES")
            return
    
    print("NO")

if __name__ == "__main__":
    solve()
```この実装は、前述のビットマスク列挙に直接続きます。 各マスクは、時計回りまたは反時計回りの方向の完全な割り当てを表します。 内側のループは、結果として生じる変位を計算します。 モジュロチェックは円形ダイヤル上のラップアラウンドを処理します。 

よくある間違いは、減算は加算と同様に有効であることを忘れることです。 両方を対称的に考慮する必要があります。 もう 1 つの潜在的な落とし穴は、360 を法とする中間値をあまりにも早く減らそうとすることです。これは数学的には安全ですが不必要であり、推論がわかりにくくなる可能性があります。

 ## 特殊なケース

 n = 1 の場合、アルゴリズムは +a と -a の両方をチェックします。 a は 1 ～ 180 であり、どちらも 360 の倍数に等しくないため、条件を満たすマスクはなく、正しく NO が生成されます。 

180 180 など、すべての角度が 180 の場合、列挙には (+180, -180) と (-180, +180) が含まれ、両方の合計が 0 になり、正しく YES が返されます。 

90、90、90、90 のような大きな混合入力の場合、合計が 360 または 0 になる複数のマスクが存在し、網羅的な検索により、有効であれば少なくとも 1 つが見つかることが保証されます。
