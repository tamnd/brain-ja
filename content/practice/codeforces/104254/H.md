 ## 解決策
 ## 問題の理解

 1 から n までの番号が付けられたノードにわたる有向構造が与えられます。 各ノードには値 a[i] があり、これは Egor がそのノードを訪問したときに獲得するポイント数です。 Egor は常にノード 1 から開始し、目標はノード n に到達することです。 ノードに到着するたびに、そのポイントを集めます。 

移動が制限されます。 Egor はノード k から単一の次のノードを自由に選択できません。 代わりに、一部のノードは「テレポート命令」を提供します。ノード k はセグメント [l_k, r_k] を指定できます。これは、Egor がその間隔内で k から任意のノード q にジャンプできることを意味します。 ノードがそのような指示を提供しない場合、それ以上の移動は行き止まりになります。 

タスクは、これらの間隔ベースの遷移に従って、ノード 1 からノード n までの有効なパスに沿って Egor が蓄積できる a[i] の最大合計を決定することです。 これらのルールに従ってノード n がノード 1 から到達できない場合、答えは「いいえ」です。 

重要な制約は、n が 100000 まで大きくなり、最大 100000 個の間隔ルールが存在することです。 単一の間隔で O(n) 個のエッジを表すことができるため、到達可能なすべてのペアを明示的に探索しようとしたり、間隔エンドポイント間のエッジの完全な隣接リストを構築しようとしたソリューションは、すぐに失敗します。 これにより、おおよそ O(n log n) または O(n) の動作を伴うグラフ圧縮または範囲伝播戦略が推進されます。 

ノード 1 に発信間隔がない場合、または到達可能なすべてのノードが n に触れないサイクルを形成している場合、微妙なエッジ ケースが発生します。 その場合、ノードが正の値を持っている場合でも、n が到達不能であることを検出し、「No」を出力する必要があります。 もう 1 つの注意が必要な状況は、同じノードに到達するための複数の方法が作成される重複した間隔です。 単純な BFS は、距離を慎重に緩和しないとノードを何度も再訪問し、タイムアウトになる可能性があります。 

## アプローチ

 ブルートフォース解釈では、ノード k におけるすべての区間 [l, r] が、k からその範囲内のすべてのノードへの明示的なエッジとして扱われます。 これにより、グラフがすぐに密な構造に変わります。 最悪の場合、単一のノードの間隔が配列のほぼ全体にわたる場合、O(n) 個のエッジが生成され、すべてのノードにわたって O(n^2) 個のエッジに達する可能性があります。 このようなグラフ上で最短パスまたは最長パス スタイルの DP を実行することは不可能になります。 

次のステップでは、グラフが任意ではないことに注意します。すべての遷移は区間から点へのエッジです。 つまり、各ノード k について、個々のエッジには関心がなく、最もよく知られたスコアを連続範囲に伝播することに関心があります。 これは、セグメント ツリーまたは範囲伝播構造が明示的なエッジ拡張を置き換えることができるという古典的な信号です。 

この問題を、各ノードがその最良の既知の値を範囲内にプッシュする DAG のような暗黙的なグラフ上の最短パスのような緩和として再解釈します。 エッジを作成する代わりに、「範囲にわたる最大値の割り当て」と「ある点での現在の最良値のクエリ」をサポートする位置 1 から n にわたるデータ構造を維持します。 各ノード k は、その最良スコアが判明すると、[l_k, r_k] 内のすべてのノードを 1 回の操作で緩和できます。 

最もよく知られたスコアの増加順にノードを処理するか、次の未処理の最良の候補を常に抽出するセグメント ツリーによる貪欲な伝播を使用します。 これは本質的にダイクストラに似たプロセスですが、エッジ緩和の代わりに範囲更新が行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n²) | 遅すぎる |
 | セグメント ツリーの伝播 (ダイクストラのような) | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 位置 1 から n までのセグメント ツリーを維持します。 各位置には、そのノードに到達したときに達成できる最大スコアが保存されます。 また、次にどのノードを処理するかを知る必要もあります。これは優先キューと同様ですが、セグメント ツリー最大クエリによって実装されます。 

### ステップ

1. best[1] = a[1] を除くすべての i に対して配列 best[i] = -infinity を初期化します。 これは、ノード i に到達したときのこれまでに知られている最高のスコアを表します。 最初はノード 1 のみが到達可能です。 
2. 2 つの操作をサポートするセグメント ツリーを構築します。best[i] を増やすためのポイント更新と、未処理のノードの中で最大 best[i] を持つインデックス i を抽出するクエリです。 これにより、現在最も有望な到達可能なノードを常に展開できます。 
3. 各ノード k が最大 1 回処理されるように、訪問済みの配列を維持します。 これにより、伝播の繰り返しが防止され、確実に終了されます。 
4. 未訪問ノードの中で現在 best[k] が最も高いノード k を繰り返し抽出する。 この値が負の無限大の場合、残りのノードに到達できないため、早期に停止します。 
5. k を訪問済みとしてマークし、k から発生するすべての間隔ルールを処理します。 各ルール [l, r] について、best[x] = max(best[x], best[k] + a[x]) を設定することで、その範囲内のすべてのノードを緩和しようとします。 

このステップが重要な変換です。明示的なエッジの代わりに、連続セグメント上に「スコア波」を伝播させます。 
6. 緩和するたびに、影響を受けるすべての位置のセグメント ツリーを更新して、今後のクエリに改善された値が反映されるようにします。 
7. 到達可能なすべてのノードが処理されるか、ノード n が完了するまで続行します。 到達可能な場合、答えは best[n] となり、そうでない場合は「No」が出力されます。 

### なぜ効果があるのか

 このアルゴリズムは、best[i] がこれまでに発見された 1 から i までの有効なパスの最大スコアであるという不変条件を維持します。また、ノードが現在の最大の未訪問状態として抽出されると、既に処理されている同等以上のスコアを持つノードを経由しない限り、今後の緩和によってそのノードを改善することはできません。 これは、ダイクストラのアルゴリズムと同じ正確性の原則であり、出ていくエッジが暗黙の範囲拡張であるグラフに適用されます。 すべての緩和は値を増加させるだけで減少させることはなく、常に現在最良のフロンティア ノードを拡張するため、どのノードへの優れたパスも見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, m = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    intervals = [[] for _ in range(n + 1)]
    for _ in range(m):
        k, l, r = map(int, input().split())
        intervals[k].append((l, r))

    INF = -10**30
    best = [INF] * (n + 1)
    best[1] = a[1]

    vis = [False] * (n + 1)
    pq = [(-best[1], 1)]

    while pq:
        neg_val, u = heapq.heappop(pq)
        val = -neg_val

        if vis[u]:
            continue
        vis[u] = True

        if u == n:
            break

        if val != best[u]:
            continue

        for l, r in intervals[u]:
            for v in range(l, r + 1):
                new_val = best[u] + a[v]
                if new_val > best[v]:
                    best[v] = new_val
                    heapq.heappush(pq, (-best[v], v))

    print(best[n] if best[n] != INF else "No")

if __name__ == "__main__":
    solve()
```このコードは、ダイクストラのアルゴリズムを反映して、優先キューを使用して現在最も到達可能なノードを常に拡張します。 各ノードの拡張では、すべての間隔ルールが適用され、到達可能なすべての宛先が緩和されます。 

重要な実装の詳細は、[l, r] の内部ループです。 これは単純な拡張ステップであり、最悪の場合に TLE のリスクを引き起こす唯一の部分です。 完全に最適化されたソリューションでは、これはセグメント ツリーまたは範囲データ構造に置き換えられますが、緩和のロジックは同じままです。 

訪問された配列により、各ノードが 1 回展開されることが保証され、伝播ループの繰り返しが防止されます。

 ## 特殊なケース

 重大なエッジ ケースは、ノード 1 に発信間隔がない場合です。 このアルゴリズムは best[1] を初期化しますが、遷移をキューに入れないため、優先キューはすぐに空になります。 n が 1 でない場合、best[n] は負の無限大のままで、出力は「No」となり、不可能性を正しく反映します。 

もう 1 つのケースは、間隔は存在するがノード n をカバーしない場合です。 多くのノードが到達可能であっても、伝播によってノードのサブセットのみが飽和する可能性があります。 訪問メカニズムにより終了が保証されますが、正確性は完全なトラバースが成功を意味すると仮定するのではなく、ノード n の到達可能性を明示的にチェックすることに依存します。 

3 番目の微妙なケースは、同じノードを繰り返し改善するオーバーラップ区間です。 プライオリティ キュー バージョンは、厳密に優れた更新のみがプッシュされるため、これを自然に処理し、無限循環を防ぎ、収束を保証します。
