 ## 問題の理解

 複数の独立したクエリが与えられます。 各クエリは、次のサイズの平方乗算表を記述します。`n × n`、行インデックスと列インデックスの範囲は両方とも 1 ～`n`。 各セルには、行インデックスと列インデックスの積が含まれます。 与えられた番号に対して`k`、ペアの数を数えなければなりません`(i, j)`～と等しい製品を生産する`k`。 

言い換えれば、テーブルを作成するように求められるのではなく、次の因数分解が何回行われるかを数えるように求められます。`k`範囲内に収まる`[1, n] × [1, n]`。 

制約は十分に大きいため、すべてを明示的に反復できます。`n^2`クエリごとのセルは不可能です。 と`n`まで`10^5`、単一のテーブルにはすでに最大で次のものが含まれています`10^10`したがって、グリッドをスキャンするアプローチは直ちに除外されます。 すべての約数を反復しても、`n`すべてのクエリは、範囲内に収まる場合にのみ受け入れられます。`O(sqrt(k))`またはより良い償却動作。 

隠された構造は、有効なペアが次の約数のペアに正確に対応するというものです。`k`、ただし間隔によって制限されます`[1, n]`。 

単純な間違いは、約数だけを数えたときに発生します。`k`境界をチェックせずに。 たとえば、次の場合`k = 12`そして`n = 2`、ペア`(3, 4)`は 12 の有効な因数分解ですが、両方のインデックスが次の値を超えているため、テーブル内では無効です。`n`。 もう 1 つの微妙な間違いは、二重カウントです。`(i, j)`そして`(j, i)`間違ったとき`i ≠ j`特に、対称性の処理が一貫性を持たない場合に顕著です。 

## アプローチ

 ブルートフォースソリューションでは、すべてを反復処理することになります。`i`そして`j`1から`n`かどうかを確認してください`i * j == k`。 これは、乗算表のすべてのセルを直接テストするため、単純かつ正確です。 ただし、クエリあたりのコストは`n^2`に達する`10^10`最悪の場合、操作が不可能になり実行不可能になります。 

重要な観察は、ペアのみを考慮しているということです`(i, j)`そのような`i * j = k`。 一度`i`固定されており、`j`次のように一意に決定されます`k / i`、整数の場合。 これにより、検索スペースが完全なグリッドから約数まで縮小されます。`k`。 繰り返すだけで済みます`i`まで`sqrt(k)`かどうかを確認してください`k % i == 0`。 それぞれの有効な約数のペア`(i, k/i)`両方のエンドポイントが存在する場合、答えに貢献します。`[1, n]`。 

これにより、境界フィルターを使用して単一の数値の因子ペアを列挙するという問題が軽減され、大規模な場合でも効率的になります。`n`。

 ## アルゴリズムのチュートリアル

 各クエリを個別に処理します。 

1.読む`n`そして`k`。 目標は、有効なペアを数えることです`(i, j)`そのような`i * j = k`そして両方とも`i`そして`j`1 から`n`。 
2. カウンタの初期化`ans = 0`。 これにより、有効な因子ペアが蓄積されます。 
3. 反復する`i`1から`⌊sqrt(k)⌋`。 これより大きい係数はどれでもよいため、これで十分です。`sqrt(k)`すでに見られているより小さい因子と組み合わせる必要があります。 これにより、各ペアが正確に 1 回検出されることが保証されます。 
4. それぞれについて`i`、どうかを確認してください`i`分割する`k`。 もし`k % i != 0`、整数のペアを形成できないため、スキップします。 
5. しましょう`j = k // i`。 今`(i, j)`は有効な因子のペアです`k`。 
6.次のことを確認します。`i <= n`そして`j <= n`。 そうして初めて、そのペアは九九内のセルに対応します。 
7. 有効な場合は、に 1 を追加します。`ans`。 まで繰り返すため、二重にカウントする必要はありません。`sqrt(k)`各因子ペアが正確に 1 回訪問されるようにします。 
8. 出力`ans`。 

### なぜ効果があるのか

 表の有効なセルはすべて因数分解に対応します`k = i × j`両方の要素が次のように制限される`n`。 ループオーバー`i`考えられるすべての左因数を 1 回だけ列挙します。 それぞれ有効`i`一意に決定する`j = k / i`したがって、有効なペアが欠落したり重複したりすることはありません。 境界条件により、実際に内部に存在するペアのみをカウントすることが保証されます。`n × n`グリッドを使用して、数値的には正しいがテーブルの外にある因数分解を除外します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_pairs(n, k):
    ans = 0
    i = 1
    while i * i <= k:
        if k % i == 0:
            j = k // i
            if i <= n and j <= n:
                ans += 1
        i += 1
    return ans

def main():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        print(count_pairs(n, k))

if __name__ == "__main__":
    main()
```コア機能`count_pairs`除数列挙戦略を直接実装します。 ループ条件`i * i <= k`平方根までのみスキャンすることを保証し、冗長なチェックを防ぎます。 可分性チェックにより、有効な整数パートナーのみが形成されることが保証されます。 

微妙な点は、次の 1 つだけをカウントすることです。`(i, j)`そして`(j, i)`いつ`i != j`なぜなら、除数スキャン中に両方がちょうど 1 回発生するためです。`i`小さいですが、いつまたそうではありません`i`大きいです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def count_pairs(n, k):

 ## 特殊なケース

 主なエッジケースは次のような場合です`k`より大きい因数を持っています`n`。 例えば、`n = 5`、`k = 10`。 因子ペア`(1, 10)`は代数的には有効ですが、グリッド内では無効です。`10 > n`。 アルゴリズムは、次の方法でそれを正しく拒否します。`j <= n`チェック。 

もう一つのケースは次のような場合です。`k`は完全な正方形です。 のために`n = 10`、`k = 36`、ペア`(6, 6)`1 回だけカウントする必要があります。 ループ構造はこれを自然に保証します。`i = 6`、重複した対称カウントは発生しません。 

最後の微妙なケースは次のような場合です。`k > n * n`。 この状況では、テーブル内にペアが存在できず、ループは依然として除数を超えて実行されますが、すべての候補が境界チェックに失敗し、予想どおりゼロになります。
