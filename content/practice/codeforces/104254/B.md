 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられ、2 番目の配列のみを自由に並べ替えることができます。 最初の配列の要素と並べ替えられた 2 番目の配列の要素間のペアリングを修正した後、すべてのペアの gcd 値の合計を計算します。 課題は、この合計を最大化する組み合わせを選択することです。 

ここでの構造は、シーケンスの順序やプレフィックスの動作に関するものではなく、純粋に選択肢の一致に関するものです。 最初の配列の各要素は 2 番目の配列の 1 つの要素とペアになる必要があり、その逆も同様で、ペアの寄与はその gcd にのみ依存します。 2 番目の配列を自由に並べ替えられるため、これは、gcd で定義された重み関数を最大化しようとする割り当て問題に変わります。 

n ≤ 700 という制約により、順列に対する 3 次またはそれより悪い組み合わせ検索が即座に除外されます。 b のすべての置換を完全に総当たりで実行すると、n が関与します。 これは、n = 12 の場合でも実現可能をはるかに超えています。すべての組み合わせを直接試しても、階乗になります。 これにより、構造化された最適化手法が必要になります。 

よくある落とし穴は、各 a[i] を利用可能な最適な b[j] と個別に照合するような貪欲なペアリングを想定することです。 初期の選択により、より適切なグローバルな組み合わせがブロックされる可能性があるため、これは失敗します。 たとえば、1 つの大きな a[i] が特定の b[j] から恩恵を受けるが、その b[j] が他の多くの a[j] にも適度に役立つ場合、貪欲なアプローチは間違った一致でそれを無駄にする可能性があります。 

もう 1 つの微妙な問題は、両方の配列を並べ替えることが役立つと想定していることです。 gcd は順序を保持しないため、ソートによって gcd 構造が単調に整列することはありません。 数値が大きいからといって、数値が大きいと必ずしも大きな gcd が生成されるわけではありません。 

## アプローチ

 この問題は、i と j の間の重みが gcd(a[i], b[j]) である古典的な割り当て最大化問題です。 ブルート フォースの見方は簡単です。b のすべての順列を試し、結果の合計を計算し、最大値を取得します。 これは、考えられるすべての一致を調査するため、正しいです。 ただし、その複雑さは n! ペアリング、さらには n = 15 ですらすでに実行不可能です。 

より良い視点は、2 つのセットをペアごとの重み関数と照合していることに注目することです。 これは、最大重みの完全なマッチングが必要な 2 部マッチング問題です。 n は最大 700 であるため、標準的なハンガリーのアルゴリズムは、比較的大きな定数と重い計算を伴う O(n^3) の複雑さにより遅すぎます。 

重要な観察は、gcd 値が約数と多重度のみに依存するということです。 すべてのペアワイズ エッジを同等に扱う代わりに、値を gcd レベルごとにグループ化し、大きな gcd 寄与がまれで構造化されているという事実を利用します。 この問題を、約数に関する値と周波数の最適化に変換できます。 

中心的なアイデアは、gcd 値を大きい値から小さい値まで処理し、b の倍数の頻度カウントを使用して、可能な限り一致を貪欲に割り当てることです。 各 a[i] に対して、gcd を最大化する利用可能な最良の b[j] を割り当てます。これは、値によってインデックス付けされた未使用の要素の数を維持し、除数を反復することによって効率的に行うことができます。 

視点を逆転させます。各 a[i] に対してすべての b[j] を試す代わりに、考えられる gcd 値を反復し、その gcd を達成する一致を形成しようとします。これにより、より高い寄与を最初に見逃さないようにします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | お(ん!) | O(n) | 遅すぎる |
 | 貪欲な除数ベースのマッチング | O(n √V log V) | O(V) | 承認済み |

 ここで、V は最大値の範囲です。 

## アルゴリズムのチュートリアル

 2 番目の配列の周波数構造を操作し、最初の配列の各要素を可能な限り最適なパートナーと照合することで、ソリューションを構築します。

1. 頻度マップを使用して、配列 b 内の各値の出現をカウントします。 これにより、候補値がまだ照合に使用できるかどうかをいつでも知ることができます。 
2. 配列 a を降順にソートします。 大きな値には高い gcd 寄与を達成するためのより厳しい制約があるため、大きな値を最初に処理します。 遅延すると、質の高い試合が失われる可能性があります。 
3. a の各値 x について、gcd(x, y) を最大化する b の最適な y にそれを割り当てようとします。 すべての y をスキャンする代わりに、x の約数を反復処理し、どの約数レベルに b の使用可能な候補があるかを確認します。 
4. 高速検索をサポートするために、b 内の未使用の要素が指定された数で割り切れる数を追跡する構造を維持します。 b の値を消費すると、それに応じてそのすべての約数のカウントがデクリメントされます。 
5. 各 x について、x のすべての約数 d を降順で繰り返します。 d で割り切れる利用可能な b 要素がまだある最初の約数 d は、gcd 寄与 d を与えます。 そのような要素を 1 つ選択し、構造から削除します。 
6. 選択した gcd 値を答えに累積します。 

重要な実装のアイデアは、除数の列挙により、すべてのペアをテストするのではなく、意味のある gcd 候補に直接ジャンプできるということです。 

### なぜ効果があるのか

 すべてのステップで、gcd の観点から現在の a[i] に利用可能な最適なパートナーを割り当てます。 a を降順で処理し、残りのリソースを使用して各要素の達成可能な最高の gcd を常に選択するため、より小さい a 値で高い gcd の機会を無駄にすることがなくなります。 不変条件は、k 要素を処理した後、残りの要素の実現可能性を低下させることなく、未割り当てのペアリングが処理されたプレフィックスに対してより高い合計寄与を生み出すことはできないということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get_divisors(x):
    small = []
    large = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            small.append(i)
            if i * i != x:
                large.append(x // i)
        i += 1
    return small + large[::-1]

def main():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    maxv = max(b)

    freq = [0] * (maxv + 1)
    for v in b:
        freq[v] += 1

    # div_count[d] = how many numbers in b currently divisible by d
    div_count = [0] * (maxv + 1)
    for v in range(1, maxv + 1):
        if freq[v]:
            for d in get_divisors(v):
                div_count[d] += freq[v]

    a.sort(reverse=True)

    used = [0] * (maxv + 1)

    def remove_value(v):
        freq[v] -= 1
        for d in get_divisors(v):
            div_count[d] -= 1

    ans = 0

    for x in a:
        best_d = 1

        for d in get_divisors(x):
            if d <= maxv and div_count[d] > 0:
                best_d = d
                break

        # find a concrete y divisible by best_d
        y = best_d
        # escalate to an actual available value
        for v in range(best_d, maxv + 1, best_d):
            if freq[v] > 0:
                y = v
                break

        ans += best_d
        remove_value(y)

    print(ans)

if __name__ == "__main__":
    main()
```コードは、残りの b 値の生の頻度と、各潜在的な gcd で割り切れる残りの値の数をカウントする派生構造という 2 つの主要な構造を維持します。 各 a 要素について、その約数を降順にスキャンして、達成可能な最適な gcd を見つけます。 選択したら、それを実現する具体的な b 値を特定し、両方の構造から一貫して削除します。 

正確性は、除数の数を削除と同期させて、将来の選択が常に現在利用可能なプールを反映するかどうかに依存します。

 ## 特殊なケース

 n = 1 の最小のケースは、可能な唯一のペアリングが強制されるため、自明に動作します。 入力 7 と 9 の場合、アルゴリズムは gcd(7, 9) = 1 を計算し、すぐに 1 を返します。 

a = [1, 1, 1, 1] や b = [7, 7, 7, 7] などの完全に一様な配列では、すべてのペアリングで gcd 1 が生成されます。アルゴリズムは任意に、しかし一貫して一致を割り当て、ステップごとに 1 つの b 値を消費し、合計 4 を累積します。 

a = [8, 8, 8] や b = [2, 4, 8] のような密な割り算の場合は、アルゴリズムがどのように最も高い gcd を最初に優先するかを示しています。 最初の 8 は、8 が 8 を与えると一致し、次に 8 と 4 が 4 を与えると一致し、最後に 8 と 2 が 2 を与えると一致し、最適な合計 14 と一致します。
