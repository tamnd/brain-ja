 ## 解決策
 ## 問題の理解

 ノードが惑星を表すツリーが与えられます。 各惑星は最初、銀河と呼ばれる K 個のラベル付きグループの 1 つに属します。 これらの銀河はデフォルトでは接続された構造ではなく、ノード上の単なるカラーラベルです。 

私たちは、ある銀河のすべての惑星を取り出し、それらを別の銀河に再着色する操作を繰り返し実行することができます。 このような各操作では、2 つのカラー クラスが完全にマージされます。 

最後に、主要な交通ハブとして機能する銀河を 1 つ選択したいと思います。 この選択された銀河の要件は構造的なものです。その銀河に属する惑星だけを見る場合、ツリー内のそれらの惑星によって引き起こされる部分グラフは接続されていなければなりません。 言い換えれば、選択した銀河のすべての惑星は、その銀河内にエンドポイントがあるエッジのみを使用して他のすべての惑星に到達できなければなりません。 

タスクは、この意味で少なくとも 1 つの銀河が接続されるように、必要なマージ操作の最小数を計算することです。 

この制約により、ツリー サイズは最大 200,000 ノードに設定され、N の二次関数や色ごとのグローバル スキャンの繰り返しが直ちに除外されます。 接続を再計算したり、銀河ごとに独立してツリー トラバーサルを繰り返し実行したりするソリューションは失敗します。 この構造により、各ノードがすべての色にわたる少数の集計計算のみに参加するソリューションが強制されます。 

銀河がすでに接続されたサブツリーを形成している場合、微妙なエッジケースが現れます。 その場合、マージは必要ありません。 もう 1 つの重要な状況は、銀河のノードがツリー全体に散在し、それらの接続パスがさまざまな色のノードを通過する場合です。 「各色の成分を数える」という素朴な考えでは不十分です。なぜなら、同じ色内で結合するだけではなく、中間色を吸収することによって接続性を固定できるからです。 

## アプローチ

 強引な解釈は、各銀河を最終ハブ候補とみなして、それを「修正」しようとすると何が起こるかをシミュレーションすることです。 固定色の場合は、そのすべてのノードを接続する必要があります。 ツリー上では、一連のノードを接続する最小限の構造は、ノード間のすべての単純なパスの結合であり、これらの端末のシュタイナー サブツリーと呼ばれることがよくあります。 

ある色に対してこのサブツリーを明示的に構築できれば、その中に現れる別の色の数を数えることができます。 そのサブツリーに t 個の異なる色が含まれている場合、それらを単一の銀河に折りたたむには、少なくとも t − 1 回のマージが必要になります。これは、各マージによって個別の色の数がちょうど 1 つ減るためです。 

ブルートフォース失敗の原因は建設コストにあります。 各色について、そのノード間のすべてのパスを再計算すると、ツリー全体が繰り返し影響を受ける可能性があり、最悪の場合は O(N²) 動作が発生します。 

重要な観察は、全ペアのパスが決して必要ないということです。 1 つの色のノードにまたがる最小限のサブツリーのみが必要です。 この構造は、マークされたノードと LCA から構築された仮想ツリーを使用して構築できます。 これにより、問題は色ごとの線形構造に縮小され、残りのタスクは、元のツリーのどのノードがそのサブツリーに属するかを計算することになります。 

色のシュタイナー サブツリー内のノードを特定できたら、その色の答えは、それらのノードに表示される個別の色の数から 1 を引いたものになります。 最終的な答えは、すべての色にわたる最小値です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パス列挙を使用した色ごとのブルート フォース | O(N²) | O(N) | 遅すぎる |
 | カラーごとの仮想ツリー + サブツリー マーキング | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを任意にルート化し、LCA クエリを前処理して、最小共通祖先を迅速に計算できるようにします。 

色ごとに以下のように進めていきます。

1. この色に属するすべてのノードを収集します。 これらは、接続性に注目する端末です。 
2. これらのノードをオイラー ツアー順序でソートし、連続するノード間に LCA を挿入して、仮想ツリー ノード セットを構築します。 これにより、端末間のすべてのパスがコンパクトなツリー構造を使用して表現可能になります。 
3. スタックを使用して仮想ツリーを構築します。 結果として得られる構造のサイズは、この色の端子の数に比例します。 
4. 仮想ツリーのすべてのエッジについて、そのエンドポイント間の元のツリー パス上のすべてのノードを「シュタイナー サブツリーの一部」としてマークする必要があります。 パスを直接たどる代わりに、差分マーキング手法を使用します。つまり、両方のエンドポイントで +1 を加算し、LCA で 2 を減算します。 すべての仮想エッジを処理した後、単一の DFS 累積によってすべてのノードのカバレッジ値が得られます。 
5. カバレッジがゼロより大きいノードはすべて、この色のシュタイナー サブツリーに属します。 
6. このサブツリーのすべてのノードをスキャンし、そこに表示される個別の色のセットを収集します。 この数を t とします。 
7. この色のコストは t − 1 です。 
8. すべての色に対して繰り返し、最小コストを出力します。 

正確かどうかは、仮想ツリーが端末間のすべてのペアごとのパスの和集合を正確に捕捉するかどうかにかかっています。 正のカバレッジを持つすべてのノードは、少なくとも 1 つのそのようなパスの一部であり、必要なすべてのパスは仮想ツリー エッジを通じて表されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

N, K = map(int, input().split())
adj = [[] for _ in range(N)]

for _ in range(N - 1):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    adj[a].append(b)
    adj[b].append(a)

color = []
for _ in range(N):
    color.append(int(input()) - 1)

# LCA preprocessing
LOG = 20
parent = [[-1] * N for _ in range(LOG)]
depth = [0] * N
tin = [0] * N
tout = [0] * N
timer = 0

def dfs(v, p):
    global timer
    tin[v] = timer
    timer += 1
    parent[0][v] = p
    for to in adj[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        dfs(to, v)
    tout[v] = timer

dfs(0, -1)

for i in range(1, LOG):
    for v in range(N):
        if parent[i - 1][v] != -1:
            parent[i][v] = parent[i - 1][parent[i - 1][v]]

def is_ancestor(a, b):
    return tin[a] <= tin[b] and tout[b] <= tout[a]

def lca(a, b):
    if is_ancestor(a, b):
        return a
    if is_ancestor(b, a):
        return b
    for i in range(LOG - 1, -1, -1):
        if parent[i][a] != -1 and not is_ancestor(parent[i][a], b):
            a = parent[i][a]
    return parent[0][a]

nodes_by_color = [[] for _ in range(K)]
for i, c in enumerate(color):
    nodes_by_color[c].append(i)

# helper arrays reused per color
mark = [0] * N
vis_color = [0] * K
used_nodes = []

def add_path(u, v, diff):
    w = lca(u, v)
    mark[u] += diff
    mark[v] += diff
    mark[w] -= 2 * diff

def dfs_acc(v, p):
    for to in adj[v]:
        if to == p:
            continue
        dfs_acc(to, v)
        mark[v] += mark[to]

answer = N

for c in range(K):
    terminals = nodes_by_color[c]
    if len(terminals) <= 1:
        answer = 0
        continue

    nodes = terminals[:]
    nodes.sort(key=lambda x: tin[x])

    m = len(nodes)
    stack = []

    def add_edge(u, v):
        add_path(u, v, 1)

    stack.append(nodes[0])

    for i in range(1, m):
        l = lca(nodes[i], nodes[i - 1])
        nodes.append(l)

    nodes = list(set(nodes))
    nodes.sort(key=lambda x: tin[x])

    stack = []
    for v in nodes:
        if not stack:
            stack.append(v)
            continue
        while stack and not is_ancestor(stack[-1], v):
            stack.pop()
        if stack:
            add_edge(stack[-1], v)
        stack.append(v)

    dfs_acc(0, -1)

    used_colors = set()
    def collect(v, p):
        if mark[v] > 0:
            used_colors.add(color[v])
            for to in adj[v]:
                if to != p:
                    collect(to, v)

    for t in terminals:
        collect(t, -1)

    cost = len(used_colors) - 1
    answer = min(answer, cost)

    for i in range(N):
        mark[i] = 0

print(answer)
```この実装では、固定色の仮想構造を構築することと、カバレッジ マークの伝播を使用して誘導されたシュタイナー サブツリー内にどのノードがあるかを識別することという 2 つのアイデアが分離されます。 の`mark`配列はツリー パス上の差分カウンターとして機能し、仮想エッジからの寄与がエンドポイントにプッシュされて LCA でキャンセルされ、DFS で蓄積されます。 

よくある落とし穴は、LCA も仮想ノード セットに含める必要があることを忘れることです。 これらがないと、再構築されたツリーは分岐点を見逃してしまい、接続性が過小評価されてしまいます。

 ## 特殊なケース

 重要なエッジケースは、すべてのノードがすでに 1 つの銀河に属している場合です。 その状況では、Sreiner サブツリーはカラー クラス全体であり、追加のカラーは表示されないため、計算されるコストはゼロになります。 使用色セットには要素が 1 つしか含まれていないため、アルゴリズムは当然 0 を返します。 

もう 1 つの重要なケースは、色が 1 回だけ出現する場合です。 その端子セットのサイズは 1 であるため、仮想エッジは作成されず、サブツリーにはそのノードのみが含まれます。 アルゴリズムは、すでに接続されているものとして正しく処理します。 

3 番目のケースは、端子が木の直径全体に広がっている場合です。 仮想ツリーは小さいですが、シュタイナー サブツリーは長いパスをカバーします。 マーキング メカニズムにより、すべての中間ノードが確実に含まれるようになり、色の集約により、そのパスに沿って検出されたすべての個別の色が正しくキャプチャされます。
