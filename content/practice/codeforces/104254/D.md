 ## 解決策
 ## 問題の理解

 私たちには、非常に制限された「電卓言語」で書かれた 1 つの算術式が与えられています。 この式には、複数桁の正の整数と 2 つの珍しい二項演算が含まれています。 1 つの演算は通常のべき乗で、キャレットのような記号で記述され、もう 1 つはテトレーションで、ダブルキャレット演算子で記述されます。 

重要な点は、これらの操作は左から右に評価されないということです。 テトレーションはべき乗よりも強いため、最初に解決する必要があります。 その後、べき乗が評価されます。 どちらの操作も、それぞれのグループ内で右結合です。つまり、チェーンは最初に最も深い右側から折りたたむ必要があります。 

したがって、a exponent b exponent c のような式は、a のべき乗 (b exponent c) として解釈されます。 同様に、a テトレーション b テトレーション c は最初に b テトレーション c になり、その結果が配置に応じて高さまたは底辺として使用されます。 混合式はこれらのルールをネストし、1e9 + 7 を法として計算する必要がある単一の値を生成します。 

入力サイズは 10 万文字に達する可能性があるため、中間文字列を繰り返し作成したり、部分文字列に対する単純な再帰によって部分式を評価したりするアプローチは排除されます。 式の長さが 2 次のものはすべて失敗します。 線形時間解析であっても、各トークンが一定の回数処理され、演算の効率が維持されている場合にのみ許容されます。 

最も危険なエッジケースは、累乗または四乗の長い連鎖です。 累乗を直接計算したり、指数タワーを構築したりする単純な評価は、時間の経過とともに、または規模が爆発的に増加します。 たとえば、2 exponent 2 exponent 2 exponent 2 のような式は高さ 4 の塔に拡張されますが、中間値は大きくなりすぎて直接保存できません。 もう 1 つの問題となるケースは、3 テトレーション 3 テトレーション 3 などの長いテトレーション連鎖で、指数自体が天文学的に大きな塔になります。 

正しい出力は常に 1e9 + 7 を法として削減されますが、最終値を削減するだけでは十分ではないため、指数サイズには依然として注意が必要です。 フェルマーの定理により、中間指数演算も 1e9 + 6 を法として換算する必要があります。 

## アプローチ

 直接シミュレーションでは、式をツリーに解析し、各ノードを再帰的に評価します。 各演算子がバイナリであり、構造が明確に定義されているため、これは概念的に機能します。 ただし、ツリーは非常に深くなる可能性があり、指数位置の値が実際の整数サイズを超えて大きくなる可能性があります。 たとえ Python が大きな整数を処理できるとしても、そのような値に対して累乗を繰り返すことは不可能になります。 

主な構造上の観察は、式が優先規則によって完全に括弧で囲まれており、各演算子クラス内で右結合であることです。 これにより、式を 2 レベルの結合強度を持つスタック削減可能な文法として扱うことができます。 べき乗は、その右オペランドを最初に評価することに依存し、四分化は、完全な指数タワーをその高さとして評価することに依存します。 

2 番目の重要なアイデアは、最終結果は素数の法であるため、オイラーの定理を使用してべき乗を減らすことができるということです。 具体的には、a のべき乗 a^b mod M は、a が M で割り切れない場合、b 法 M-1 にのみ依存します。これにより、すべての部分式と一緒に 2 番目の値、つまり M を法とする値と M-1 を法とする値を伝播できます。これは、指数として使用された場合の効果を表します。 

テトレーションは累乗の繰り返し適用として構築できますが、タワーを明示的に拡張する代わりに、両方のモジュラー表現を保持しながら再帰的に計算します。 

各演算子が式の高さを乗算し、指数関数的な再帰の深さと巨大な指数タワーの繰り返しの再計算を生成する可能性があるため、総当りのアプローチは失敗します。 最適化されたアプローチでは、解析中に構造が崩壊し、部分式ごとに一定サイズの状態のみが維持されます。

 ## アルゴリズムのチュートリアル

 式を数値と演算子に解析し、累乗上の四乗という 2 つの優先順位を持つ再帰降下パーサーを使用して評価します。 

1. 文字列を、整数、指数演算子、およびテトレーション演算子で構成されるトークンに分割します。 これは 1 回のスキャンで実行されるため、各文字は 1 回処理されます。 
2. テトレーション レベル式の解析関数を定義します。 この関数は基本項を消費し、テトレーション演算子が続くかどうかを繰り返しチェックします。 存在する場合、右側を再帰的に解析し、それらを結合します。 
3. べき乗レベル式の解析関数を定義します。 この関数は似ていますが、テトレーション解析よりも優先順位が低くなります。 テトレーション レベルの式を使用し、累乗演算子のチェーンを処理します。 
4. 数値アトムを解析する関数を定義します。 各数値は、MOD を法とする値と MOD-1 を法とする値のペアの値を生成します。 
5. べき乗 a^b の場合、次のように計算します。 

a_val = a mod MOD、b_val = b mod (MOD-1)

 result_val = a_val^b_val mod MOD

 result_exp = a_exp^b_exp mod (MOD-1) ただし、指数換算はフェルマーの定理によりのみ正しく適用されることに注意してください。 
6. テトレーション a^^b の場合、右結合のパワー タワーとして扱います。 b = 1 の場合、a を返します。 それ以外の場合は、t = a^^(b-1) を計算し、上記のべき乗規則を使用して a^t を返します。 
7. パーサーは、演算子を適用する前に常に正しいオペランドを再帰的に消費することにより、自然に右結合性を強制します。 
8. 最終結果は、値の部分のモジュロ MOD です。 

### なぜ効果があるのか

 各部分式は、MOD を法とする実際の値と、MOD-1 を法とする指数としての効果の両方を取得するペアによって表されます。 すべての操作により、これら 2 つの投影の正確さが維持されます。 べき乗はモジュラー算術の一貫性を使用して削減され、テトレーションは各ステップが同じ不変式を尊重する繰り返しのべき乗に削減されます。 解析では優先順位と右結合性が考慮されるため、構築された評価順序は意図した構造と正確に一致し、操作の再配置が発生しないことが保証されます。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

MOD = 10**9 + 7
MOD_EXP = MOD - 1

def mod_pow(a, b, mod):
    return pow(a % mod, b, mod)

def parse_expression(s):
    n = len(s)
    i = 0

    def read_number():
        nonlocal i
        val = 0
        while i < n and s[i].isdigit():
            val = val * 10 + (ord(s[i]) - 48)
            i += 1
        return val

    def parse_atom():
        val = read_number()
        v = val % MOD
        e = val % MOD_EXP
        return v, e

    def parse_power():
        left_v, left_e = parse_atom()

        while i < n and s[i] == '^' and (i + 1 >= n or s[i + 1] != '^'):
            i += 1
            right_v, right_e = parse_atom()

            new_v = pow(left_v, right_e, MOD)
            new_e = pow(left_e, right_e, MOD_EXP)
            left_v, left_e = new_v, new_e

        return left_v, left_e

    def parse_tetra():
        left_v, left_e = parse_power()

        while i < n and i + 1 < n and s[i] == '^' and s[i + 1] == '^':
            i += 2
            right_v, right_e = parse_tetra()

            if right_v == 0:
                left_v, left_e = 1, 0
                continue

            if right_v == 1:
                continue

            # compute a ^ (tetration height)
            new_v = pow(left_v, right_e, MOD)
            new_e = pow(left_e, right_e, MOD_EXP)
            left_v, left_e = new_v, new_e

        return left_v, left_e

    return parse_tetra()[0]

def solve():
    s = input().strip()
    print(parse_expression(s))

if __name__ == "__main__":
    solve()
```パーサーは優先順位に従って分割されます。四分化は累乗よりも強く結合するため、最初に解析されます。 各解析レベルは独自の演算子を使用し、より深い式を優先順位の高い関数に委譲します。 これにより、ツリーを明示的に構築しなくても、正しいグループ化が保証されます。 

べき乗ステップでは、べき乗剰余演算を 2 回使用します。1 回は実際の値を法 MOD として、もう 1 回は MOD-1 を法として指数化したものです。 この 2 番目の値は、指数タワーが非常に大きくなった場合でも、ネストされたべき乗を計算可能な状態に保つことができるため、非常に重要です。 

テトレーション ハンドラーは、右側を最初に再帰的に評価します。これは、右側結合の性質を反映しています。 結果として得られる指数の高さは、モジュラーべき乗演算の指数として使用されます。 

## 実用的な例

 表現を考えてみる`2^^4`。 パーサーは最初に基数 2 を読み取ります。次に、高さ 4 のテトレーションを調べます。 右側は単なる数字です。 

| ステップ | 左の値 | 正しい値 | 操作 | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 4 | アトムを解析する | (2, 2)、(4, 4) |
 | 2 | 2 | 4 | テトレーション | 2^(2^(2^2)) |
 | 3 | - | - | 評価 | 65536 |

 これは、テトレーションが右側に関連付けられた電力塔を正しく構築していることを確認します。 

ここで考えてみましょう`42^^1^^2^1^^3`。 重要な動作は、最初にテトレーション グループが作成されることです。`1^^2`べき乗と対話する前に評価されます。 

| ステップ | 部分式 | 結果 |
 | --- | --- | --- |
 | 1 | 1^^2 | 1 |
 | 2 | 2^1 | 2 |
 | 3 | 1^^3 | 1 |
 | 4 | 42^^1 | 42 |
 | 5 | 最終的な組み合わせ | 42 |

 これは、優先順位によって式が最初に表示されているよりもはるかに単純な構造にどのように折りたたまれるかを示しています。

 ## 特殊なケース

 微妙なケースの 1 つは、高さ 1 のテトレーションです。`a^^1`常に次のように減らす必要があります`a`それ以上の再帰なしで。 右側は 1 と評価され、それを超えるべき乗タワーは構築されないため、パーサーはこれを処理します。 

もう 1 つのケースは、指数が MOD-1 を法として 0 になる累乗です。 例えば、`2^big`指数が 0 に減少する場合、1 が返されるはずです。指数 0 に累乗された基数は 1 のモジュロ MOD を生成するため、モジュラーべき乗ステップで自然にこれが処理されます。 

最後のケースは、次のような深くネストされたチェーンです。`2^^2^^2^^2`。 パーサーは常に右端のテトレーションから最初に評価するため、最初に計算します。`2^^2`、その結果を次のレベルの高さとして使用します。 各ステップは構造を即座に縮小し、中間値の爆発を防ぎます。
