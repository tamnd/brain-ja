 ## 解決策
 ## 問題の理解

 下端が x 軸上に固定され、上端が厳密に増加する x 座標を持つポリラインで記述される壊れた板が与えられます。 これは、形状が x 単調であることを意味します。つまり、左から右に歩く場合、x 内で後方に移動することはなく、境界は指定された頂点によって完全に決定されます。 

厚板には最初、ある程度の領域があります。これは、ちょうどこの壊れた上部境界の下で X 軸より上の領域です。 商人は、その面積に比例した価格で、最終的に加工された板を購入します。 販売する前に、ヴァディムはエポキシを注ぐことができます。 エポキシには 2 つの効果があります。1 つは使用量に比例してコストがかかること、もう 1 つは隙間を埋めることで、厚板が直線の最終境界に沿って切断される前に、壊れた構造の一部が 1 つの最終形状に「滑らかに」されることです (声明の後処理ステップで暗示されているように)。 

重要な意味は、販売前に有効な上部境界を変更するためにエポキシが使用されており、形状を変更すると、最終的な販売面積と消費されるエポキシの量の両方が変化するということです。 目的は、最終領域からの収益からエポキシコストを引いたものとして定義される利益が最大化されるように、実行する平滑化の量を選択することです。 

入力サイズは最大 10^5 頂点であるため、ジオメトリの二次再構成やペアごとの構造チェックは不可能です。 構造は x 内で単調であるため、解決策は線形または線形に近い時間で機能する必要があり、おそらくスタックベースの幾何学的縮小または凸性プロパティを使用します。 

単純なアプローチでは、ポリラインの一部を「直線化」するすべての可能な方法をシミュレートしようとしたり、すべてのサブセグメントを直線に置き換えることを検討したりする場合があります。 セグメントの選択肢の数は 2 次であるため、これはすぐに失敗します。 

ローカルで考えると、より微妙な問題が現れます。 たとえば、3 つの連続する点が (1, 4)、(2, 1)、(3, 4) のような「バンプ」を形成する場合、単純なアルゴリズムではすべてのローカル スムージングが独立していると想定する可能性があります。 これは間違っています。1 つの凹面を除去すると、以前は無関係だった別の凹面が露出する可能性があるためです。つまり、構造がローカルではなくグローバルであることを意味します。 

もう 1 つの落とし穴は、元のポリラインが常に最適であるか、常に変更されていないと想定していることです。 エポキシが販売価格に比べて安い場合は、たとえ局所的な修正が高価に見えても、境界を全体的により「凸状」の形状に変換することが有益である可能性があります。 

## アプローチ

 強引な解釈では、壊れた上部境界の一部を直線セグメントに置き換えるあらゆる可能な方法を検討します。 それぞれの選択により、面積を計算できる異なる最終ポリゴンが定義され、エポキシのコストは元の形状と変更後の形状の差に対応します。 ただし、グローバル ジオメトリに応じてすべての頂点が削除または保持される可能性があるため、有効な上限を定義する頂点のサブセットを選択する方法の数は点の数で指数関数的に増加します。 たとえセグメントの選択に限定されていたとしても、有効な単純化をすべて列挙すると、すでに O(n²) かそれ以上に大きくなります。 

重要な観察は、最適な最終形状は、指定された点の上凸包絡線でなければならないということです。 ある点が他の 2 つの点の間の線分の下にある場合、その点を維持しても、直線化された境界の下で最終的に達成可能な面積が減少するだけであり、局所的な決定に依存する形で利益は向上しません。 これは古典的な幾何学的圧縮です。冗長な「凹型」頂点は最適な境界には決して現れません。 

これが認識されると、問題は、x 座標によってソートされた一連の点の上部凸包を構築することになります。これは、モノトーン スタックを使用して線形時間で実行できます。 元の面積と船体の面積の両方が得られると、エポキシのコストは変更される面積の量に比例するため、利益はこれら 2 つの値で単純な直線式になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての境界変更に対するブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 単調凸包 + 面積計算 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ポリゴンが x-monotone であり、最適なエポキシ使用下では上部境界のみが変化するという事実を利用します。 

1. 連続する頂点間の台形則を使用して、指定されたポリラインの下の元の面積を計算します。 各セグメントは、平均高さと幅に基づいた単純な領域に寄与します。 これにより、ベースライン形状領域が得られます。 
2. スタックを使用して、x 次の増加に従って指定された点の上部凸包を構築します。 私たちは候補の境界を維持し、上から見たときに境界が「凹状に曲がる」ことがないようにします。 最後の 3 つのポイントが凸性を侵害している場合、中央のポイントは削除されます。 
3. ハルを構築するとき、残っている頂点のみを保存します。 これらは、エポキシが凹面領域を満たした後の、最終的に直線化された境界を表します。 
4. ハルも x に関する区分線形関数であるため、同じ台形方法でハルの下の面積を計算します。 
5. 2 つの領域を組み合わせて利益を生み出します。 m が k より大きい場合、最終面積を増やすことが有益であるため、船体面積を最大化することを好みます。 m が k より小さい場合、エポキシによって作成される追加領域にはコストの価値がないため、事実上元の構成のままになります。 これにより、2 つの事前計算された領域間の単純な比較が行われます。 

### なぜ効果があるのか

 非凸頂点は、エポキシ対面積比を増加させることなく常に直線セグメントに置き換えることができる局所的なくぼみを作成するため、エポキシを収益性の高い領域に変換する効率を大幅に低下させます。 これにより、限界利益の点で凸包境界が他の境界よりも決して悪くならないという支配関係が生じます。 ハルは x でソートされた点に対して一意であるため、アルゴリズムは最適な構造を決定的に生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def area(poly):
    s = 0.0
    for i in range(len(poly) - 1):
        x1, y1 = poly[i]
        x2, y2 = poly[i + 1]
        s += (y1 + y2) * (x2 - x1) * 0.5
    return s

def cross(o, a, b):
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

n = int(input())
m, k = map(float, input().split())

pts = [tuple(map(int, input().split())) for _ in range(n)]

orig = area(pts)

hull = []
for p in pts:
    while len(hull) >= 2 and cross(hull[-2], hull[-1], p) >= 0:
        hull.pop()
    hull.append(p)

hull_area = area(hull)

if m >= k:
    ans = m * hull_area - k * (hull_area - orig)
else:
    ans = m * orig

print(f"{ans:.6f}")
```このソリューションでは、まず元の壊れた板の面積を計算し、次に単調スタックを使用して上部の凸状境界を構築します。 外積条件により、上部エンベロープを形成するときに非凸状のターンを作成する可能性のある点が削除されます。 その後、両方の面積が台形によって計算されます。 

微妙な点は、外積条件の向きです。 x は厳密に増加しているため、スタックは単一のチェーンを維持し、ターンが「上に凸」でないときにポイントを削除することで、常に可能な限り最高のエンベロープを維持することが保証されます。 

すべての計算は入力座標の線形結合であるため、浮動小数点精度で十分であり、この問題では倍精度で十分であることが保証されます。 

## 実用的な例

 船体の形成と面積の比較を説明するために、小さな建造例をトレースします。 

考慮すべきポイント:

 (1, 1)、(2, 3)、(3, 2)、(4, 4)

 元の面積と船体の面積を計算します。 

| ステップ | ハルスタック | アクション |
 | --- | --- | --- |
 | (1,1) | (1,1) | 追加 |
 | (2,3) | (1,1),(2,3) | 追加 |
 | (3,2) | (1,1)、(2,3)、(3,2) | まだ削除されていません |
 | (3,2) チェック | (1,1),(3,2) | 凹面のため (2,3) を削除 |
 | (4,4) | (1,1)、(3,2)、(4,4) | 追加 |

 中間点 (2,3) は、上部エンベロープに対して非凸状のターンを作成するため、削除されます。 

元の領域ではすべてのセグメントが使用されますが、船体領域では単純化された境界が使用され、最終的に達成可能な形状が増加します。 

これは、アルゴリズムがローカルで動作するのではなく、エンベロープの一貫性をグローバルに強制することを示しています。 

ポイントが削除されない 2 番目の例:

 (1,1)、(2,2)、(3,3)、(4,4)

 ポイントはすでに凸状であるため、スタックがポップすることはありません。 船体は元の形状と等しいため、両方の領域が一致し、エポキシによる変形が起こらないという利点があります。

 ## 特殊なケース

 すべての点が直線上にある場合、縮退のケースが発生します。 たとえば、(0,0)、(1,0)、(2,0)。 凸包アルゴリズムは、実装に応じてすべての中間点を保持するか折り畳みますが、計算された領域は全体を通してゼロのままです。 元の面積と船体の面積が同じであるため、利益の計算式は不安定になることなく正確に減少します。 

もう 1 つのケースは、(1,5)、(2,1)、(3,5) のような単一の「深い谷」です。 中間点は船体建造時に除去されます。 スタックは (1,5) と (3,5) に対して凹面のターンを作成するため、(2,1) をポップします。 最終的なハルは直線セグメントであり、面積の差がエポキシで調整された改善として正確にキャプチャされます。 

最後の微妙なケースは、複数の連続するポイントが凸状と凹状の動作を交互に繰り返す場合です。 凸性の不変条件が復元されるまでスタックは繰り返しポップし、ローカルな決定に依存するのではなく、長距離の依存関係が正しく解決されるようにします。
