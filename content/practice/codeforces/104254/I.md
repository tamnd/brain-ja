 ## 解決策
 ## 問題の理解

 最大 10 万の長さの配列が与えられ、すべての要素は非常に小さなドメインに制限されます。つまり、1 から 6 までの値のみが表示されます。 この配列に対して、サブセグメントに対する 2 種類の操作をサポートする必要があります。 

1 回の操作で、選択したセグメントがソート順に並べ替えられます。 これは何も尋ねず、配列を変更するだけです。 もう 1 つの演算では、その時点での指定されたセグメント内の最長の非減少サブシーケンスの長さを求めます。 

重要な観察はすでに制約から始まります。 値はサイズ 6 の定数セットによって制限されますが、配列のサイズと演算数は両方とも大きくなります。 クエリごとにセグメントを直接スキャンしてセグメント全体の応答を再計算するソリューションでは、最悪の場合、10^5 の演算には遅すぎる二次関数の動作が発生する危険があります。 

最も危険な単純な落とし穴は、各クエリを個別に処理することです。 たとえば、セグメントに対する単純な動的スキャンを使用してすべてのタイプ 2 クエリの LIS を再計算すると、クエリごとにすでに O(n) が得られ、O(nq) になります。 さらに悪いことに、サブ配列を毎回直接ソートすると更新ごとに O(n log n) が発生し、これも操作を繰り返すと崩壊します。 

微妙なエッジ ケースは、並べ替え操作によって将来のクエリの構造が変更されるという事実から生じます。 たとえば、次のことを考えてみましょう。 

入力:```
5 3
3 2 1 6 5
1 1 3
2 1 5
2 1 3
```最初の 3 つの要素を並べ替えると、配列は次のようになります。`1 2 3 6 5`。 並べ替え操作後に実際に配列を正しく更新しない単純なソリューションでは、古いデータに基づいて LIS 値が計算され、間違った答えが暗黙的に生成されます。 

もう 1 つの重要なケースは、ソートの重複です。 交差するセグメントに対する 2 つの並べ替え操作は、独立した変換ではなく、実際の上書きのように動作する必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 タイプ 1 クエリの場合、部分配列を物理的に並べ替えます。 タイプ 2 クエリの場合、セグメントをスキャンし、古典的な O(length log length) メソッドまたは O(length^2) DP を使用して LIS を計算します。 これは問題定義を直接シミュレートするため、これは正しいです。 

ただし、各クエリは最大 10^5 の要素を扱う可能性があります。 更新ごとにサイズ n のセグメントをソートすると、操作ごとに O(n log n) になります。 q の操作では、最悪のケースは O(nq log n) になり、これは実現可能な限界をはるかに超えています。 LIS クエリだけでも、すでにランタイムを支配します。 

重要な構造的洞察は値の制限から得られます。 すべての要素は 1 ～ 6 の間であるため、セグメントは任意のデータではなく、小さなアルファベットのマルチセットになります。 これにより、正確な順序を保存する代わりに、各値のカウントによって各セグメントを表すことができます。 

2 番目の洞察は、そのような制限された領域において LIS が何を意味するかについてです。 小さな順序付きアルファベットのシーケンスの場合、セグメント内の最長の非減少サブシーケンスは、各値の要素がいくつ存在するか、およびそれらをどのように配置できるかによって完全に決まります。 ソート操作の後、セグメントは完全にソートされます。つまり、すでに非降順になっているため、その LIS はその長さと同じになります。 ソートされていないセグメントの場合でも、構造化された方法でカウントの貪欲なマージを使用して LIS を計算できます。 

これを処理する標準的な方法は、各ノードがマージされたときにシーケンスがどのように動作するかを圧縮した表現を格納するセグメント ツリーです。 値は 1 ～ 6 のみであるため、値間の遷移を通じて LIS を再構築するのに十分な情報をセグメントごとに維持できます。 

各ノードは、セグメントに制限された場合に達成可能な最良の増加サブシーケンスを記述する小さな DP のような構造を保持します。また、アルファベットのサイズが一定であるため、マージは定数時間です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 値圧縮を使用したセグメント ツリー | O(q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードが値 1 ～ 6 に基づく固定サイズの構造を使用してセグメントを要約するセグメント ツリーを構築します。各ノードに対して、配列 dp を格納します。ここで、 dp[x] は、そのセグメント内の値 x で終わる最適な増加サブシーケンスの長さを表します。 

1. 各リーフ ノードについて、dp[a[i]] = 1 および他のすべてのエントリがゼロになるように dp を初期化します。 これは、単一の要素がそれ自体の値で終わる長さ 1 のサブシーケンスを形成することを反映しています。 
2. 2 つの子をマージする場合、左側のセグメントのサブシーケンスと右側のセグメントのサブシーケンスを結合する必要があります。 左側の dp は、ある値で終わるすべてのサブシーケンスを表し、右側の dp はその上に構築されます。 i ≤ j の値のすべてのペアについて、左側の子の i で終わるサブシーケンスを、j から始まる右側の子のシーケンスで拡張できます。 
3. 最初に左側の dp をコピーし、次に非減少条件を尊重しながら右側の dp を使用してそれを拡張することによって、マージされたノードの新しい dp を計算します。 値の範囲は 1 ～ 6 のみなので、すべての遷移を明示的にチェックできます。 
4. セグメントを並べ替えるタイプ 1 クエリの場合、要素を物理的に並べ替える必要はありません。 ソートとは、セグメントが完全に減少しなくなることを意味し、そのため、その dp が最大になります。つまり、すべての値が順番に寄与します。 セグメント ツリーの間隔を、事前に計算された「並べ替えられた状態」表現で上書きできます。 
5. タイプ 2 クエリの場合、セグメント ツリーをクエリし、範囲全体の dp 表現をマージします。 答えは、結果として得られる dp 配列の最大値です。これは、増加するサブシーケンスの最適な終了値を表すためです。

これが機能する理由は、各ノードが終了値でグループ化されたセグメント内のすべてのサブシーケンスを正しくエンコードするという不変条件に基づいています。 2 つのセグメントがマージされる場合、結合されたセグメント内のすべての有効なサブシーケンスは、完全に片側に収まるか、非減少順序を維持しながら左からの有効なサブシーケンスと右からの有効なサブシーケンスを連結することによって形成される必要があります。 値 1 から 6 までのすべての遷移を明示的に考慮するため、有効なサブシーケンスが失われることも、無効なサブシーケンスが導入されることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("dp",)
    def __init__(self):
        self.dp = [0] * 7

def merge(a, b):
    res = Node()
    for i in range(1, 7):
        res.dp[i] = max(a.dp[i], b.dp[i])
    for i in range(1, 7):
        for j in range(i, 7):
            res.dp[j] = max(res.dp[j], a.dp[i] + b.dp[j])
    return res

def make_leaf(v):
    node = Node()
    node.dp[v] = 1
    return node

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [Node() for _ in range(4 * self.n)]
        self.build(1, 0, self.n - 1, arr)

    def build(self, v, l, r, arr):
        if l == r:
            self.t[v] = make_leaf(arr[l])
            return
        m = (l + r) // 2
        self.build(v * 2, l, m, arr)
        self.build(v * 2 + 1, m + 1, r, arr)
        self.t[v] = merge(self.t[v * 2], self.t[v * 2 + 1])

    def query(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.t[v]
        m = (l + r) // 2
        if qr <= m:
            return self.query(v * 2, l, m, ql, qr)
        if ql > m:
            return self.query(v * 2 + 1, m + 1, r, ql, qr)
        left = self.query(v * 2, l, m, ql, qr)
        right = self.query(v * 2 + 1, m + 1, r, ql, qr)
        return merge(left, right)

n, q = map(int, input().split())
arr = list(map(int, input().split()))

st = SegTree(arr)

for _ in range(q):
    t, l, r = map(int, input().split())
    l -= 1
    r -= 1
    if t == 2:
        res = st.query(1, 0, n - 1, l, r)
        print(max(res.dp))
    else:
        seg = arr[l:r+1]
        seg.sort()
        arr[l:r+1] = seg
        st = SegTree(arr)
```セグメント ツリー ノードは、終了値によってグループ化されたサブシーケンスをコンパクトに動的プログラミングで表現したものです。 マージ関数は重要な部分であり、値の順序付けの制約を尊重しながら、増加するサブシーケンスを左から右に拡張するあらゆる方法を考慮して 2 つの半分を結合します。 

ここでの並べ替え操作は、わかりやすくするために簡単な方法で実装されており、後でセグメント ツリーを再構築します。 これは実際には最適ではありませんが、セグメントを並べ替えられた状態に変える概念モデルには一致します。 より最適化されたバージョンでは、再構築の代わりに周波数ベースのノードで遅延伝播を使用します。 

クエリ操作は、パスに沿ってノードをマージすることによって、達成可能な最良のサブシーケンスを返し、最大の dp エントリを取得することで、可能な限り最良の終了点を取得します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    class Node:
        def __init__(self):
            self.dp = [0]*7

    def merge(a,b):
        res = Node()
        for i in range(1,7):
            res.dp[i]=max(a.dp[i],b.dp[i])
        for i in range(1,7):
            for j in range(i,7):
                res.dp[j]=max(res.dp[j],a.dp[i]+b.dp[j])
        return res

    def make(v):
        n=Node()
        n.dp[v]=1
        return n

    class ST:
        def __init__(self,a):
            self.n=len(a)
            self.t=[Node() for _ in range(4*self.n)]
            self.a=a
            self.build(1,0,self.n-1)

        def build(self,v,l,r):
            if l==r:
                self.t[v]=make(self.a[l])
                return
            m=(l+r)//2
            self.build(v*2,l,m)
            self.build(v*2+1,m+1,r)
            self.t[v]=merge(self.t[v*2],self.t[v*2+1])

        def query(self,v,l,r,ql,qr):
            if ql<=l and r<=qr:
                return self.t[v]
            m=(l+r)//2
            if qr<=m:
                return self.query(v*2,l,m,ql,qr)
            if ql>m:
                return self.query(v*2+1,m+1,r,ql,qr)
            return merge(self.query(v*2,l,m,ql,qr),self.query(v*2+1,m+1,r,ql,qr))

    n,q=map(int,input().split())
    a=list(map(int,input().split()))
    st=ST(a)

    out=[]

    for _ in range(q):
        t,l,r=map(int,input().split())
        l-=1;r-=1
        if t==2:
            res=st.query(1,0,n-1,l,r)
            out.append(str(max(res.dp)))
        else:
            a[l:r+1]=sorted(a[l:r+1])
            st=ST(a)

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースは、重複するセグメント上で繰り返し並べ替えが行われることです。 端点は変更されないまま、中央領域のみが繰り返しソートされる配列を考えてみましょう。 このアルゴリズムは、ソートごとにそのセグメントの内部順序が完全にリセットされ、後続のクエリが常に再構築を通じて更新された構造に対して動作し、dp 状態の正確さを維持するため、これを処理します。 

もう 1 つのエッジ ケースは、部分的に複数回ソートされたセグメントに対するクエリです。 グローバル配列履歴は複雑ですが、セグメント ツリーは常に最新の配列状態を反映するため、次のようなクエリが実行されます。`2 l r`常に正しい現在の dp ノードをマージします。 

最後に、単一要素セグメントにより、基本初期化の正確さが保証されます。 dp 配列は要素値の 1 つの単位で初期化されるため、単一のインデックスに対するクエリは 1 を返します。これは、単一の要素に対する LIS の定義と一致します。
