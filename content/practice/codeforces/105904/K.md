 ## 解決策
 ## 問題の理解

 合計 N 回のキックを連続するトレーニング セットに分割する方法を数えるように求められます。 各トレーニング セットには正の数のキックがあり、これらのサイズは合計がちょうど N になるシーケンスを形成します。 

2 つのルールにより、この順序が制約されます。 まず、各セットは前のセットよりも長くすることはできないため、セグメントの長さのシーケンスは増加しません。 第 2 に、禁止されたサイズ K があり、正確に K 個のキックを持つセグメントは許可されないことを意味します。 セグメントは正であるため、有効なセグメント サイズはすべて少なくとも 1 です。 

したがって、タスクは、1 から K-1 までの範囲の値のみを許可しながら、合計が N になる非増加する正の整数のシーケンスをすべてカウントすることになります。 

これは、最大パーツ サイズが制限されている古典的な整数パーティション構造です。 

この制約により、N は最大 4000 まで許可されます。すべてのパーティションを列挙しようとするソリューションでは、パーティションの数がおおよそ exp(O(√N)) のように増加するため、指数関数的に爆発的に増加します。 パーティション上での軽度の組み合わせであっても、遅すぎる可能性があります。 Python では約 1,600 万回の遷移が許容されるため、O(N·K) 以上の動的プログラミング アプローチが唯一の現実的な方向です。 

K = 1 の場合、微妙なエッジ ケースが発生します。この場合、唯一の禁止サイズは 1 ですが、すべてのセグメントは少なくとも 1 でなければならないため、N が 0 でない限り有効なセグメンテーションは存在しませんが、これは許可されていません。 したがって、K = 1 の場合、正解はすべての N について 0 になります。 

素朴な考えを陥れる可能性のあるもう 1 つの点は、「増加しない」という制約です。 たとえば、1 + 2 + 1 のような分解は、たとえすべての部分が K を避けていたとしても、数列が増加するため無効です。 順序付けを強制せずにこれを単純な合成問題として扱う解決策では、過度にカウントされます。 

## アプローチ

 直接的な試みでは、N を正の整数に分割し、増加しないものをフィルタリングして K を回避するすべての方法が生成されます。この総当り的な方法は基本的に再帰ツリーを探索し、各ステップで次のセグメント サイズを選択します。 最悪の場合、各状態は最大 O(N) 個の選択肢に分岐し、深さも O(N) となり、実行可能な限界をはるかに超えた爆発につながります。 

重要な観察は、順序制約によって問題が順列問題ではなく分割問題に変わってしまうということです。 部分が非増加であることが要求されると、有効な各解は、順序付けされたシーケンスではなく整数のマルチセットに対応します。 これにより階乗の過剰カウントが排除され、構造化された DP が可能になります。 

このタスクは、最大でも K−1 のサイズの部分を使用して N の分割をカウントするものとして再解釈できます。 「非増加」を暗黙的に強制する標準的な方法は、現在の最大値までのパーツを使用したソリューションの構築のみを許可し、許容されるパーツ サイズの昇順に処理することです。 

これにより、許容される各パーツ サイズが使用される回数を決定し、非増加順序を自動的に保持する方法で合計を累積する、古典的なナップザック スタイルの DP が得られます。

 | --- | --- | --- | --- |
 | ブルートフォース列挙 | 指数 | O(N) 再帰 | 遅すぎる |
 | パーティション DP (境界部分) | O(N・K) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 dp[x] が許可されたセグメント サイズを使用して合計 x を形成する方法の数を表す DP 配列を構築し、構築によって非増加構造に決して違反しないようにします。

1. dp[0] = 1 を初期化します。これは、セグメントをまったく使用せずに合計ゼロを形成する方法が 1 つだけあるためです。 他のすべての dp 値は、まだ合計に到達できないため、0 から始まります。 
2. 許可されるセグメント サイズを 1 から K-1 まで反復します。 各サイズは、何度でも使用できる「積み木」として扱われます。 
3. セグメント サイズ s ごとに、dp 配列を s から N に更新します。合計 x ごとに、dp[x − s] を dp[x] に追加します。 このステップでは、サイズ s のセグメントを追加することによって、以前のすべての有効な構造を拡張します。 
4. 更新は の昇順で実行されるため、暗黙的な構造で大きなセグメント サイズが小さなセグメントの前に配置されることはありません。 これにより、より大きな部分が考慮される前に、以前の決定がより小さな部分または等しい部分が修正されることに対応するため、非増加構造が維持されます。 
5. 許可されたすべてのセグメント サイズを処理した後、dp[N] には有効なパーティションの総数が含まれます。 

微妙な点は、遷移は境界のないナップザックのように見えますが、セグメント サイズに対する反復の順序付けにより非増加制約が暗黙的にエンコードされ、同じマルチセットの無効な並べ替えが防止されることです。 

### なぜ効果があるのか

 すべての有効なトレーニング プランは、1 から K-1 までのセグメント サイズのマルチセットに正確に対応します。 各パーツ サイズが固定順序で導入されるため、DP は各マルチセットを 1 回だけカウントします。そのため、同じパーツの順列が複数の方法で形成されることはありません。 したがって、非増加要件は、明示的にチェックされるのではなく、構造的に強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    N, K = map(int, input().split())
    
    if K == 1:
        print(0)
        return

    max_part = K - 1
    dp = [0] * (N + 1)
    dp[0] = 1

    for s in range(1, max_part + 1):
        for x in range(s, N + 1):
            dp[x] = (dp[x] + dp[x - s]) % MOD

    print(dp[N])

if __name__ == "__main__":
    solve()
```この解決策は、最初に縮退ケース K = 1 を明示的に処理します。 次に、DP 配列がパーティションをカウントするために初期化されます。 セグメント サイズに対する外側のループは、各サイズが制御された方法で寄与することを保証し、一方、内側のループは、到達可能な合計ごとに寄与を蓄積します。 モジュロ演算は更新のたびに適用され、オーバーフローを防ぎ、必要な制約内に収まります。 

一般的な実装の落とし穴は、ループの順序を逆にすることです。 最初に合計を反復し、次にセグメントサイズを誤って繰り返すと、誤ってパーティションではなく順列をカウントしてしまう可能性があります。 選択された順序はそれを回避します。 

## 実用的な例

 N = 4、K = 3 という小規模なケースを考えてみましょう。したがって、許可されるセグメント サイズは 1 と 2 になります。 

dp = [1, 0, 0, 0, 0] から始めます。 

サイズ 1 を処理すると、dp は次のようになります。 

| × | dp[x] 更新 |
 | --- | --- |
 | 1 | 1 |
 | 2 | 1 |
 | 3 | 1 |
 | 4 | 1 |

 サイズ 2 を処理した後、dp[x−2] からの寄与を追加します。 

| × | dp[x] 前 | dp[x−2] | | 後の dp[x]
 | --- | --- | --- | --- |
 | 2 | 1 | 1 | 2 |
 | 3 | 1 | 1 | 2 |
 | 4 | 1 | 2 | 3 |

 最終的な dp[4] = 3、非増加構造の下でパート 1 と 2 を使用して 4 の有効なパーティションと一致します。 

これは、DP がシーケンスの並べ替えではなく部分の組み合わせを蓄積することを裏付けています。 

2 番目の例として、N = 5、K = 4 を例に挙げます。したがって、許可されるパーツは 1、2、3 になります。DP は、最大パーツ サイズ 3 で 5 のすべてのパーティションを徐々に構築し、各更新レイヤーは、順序付けの制約を破ることなく、許可されるセグメント サイズの新しい次元を追加します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N・K) | K-1 個のパーツ サイズのそれぞれは、N 状態にわたって完全な DP 更新を実行します。 
| スペース | O(N) | 合計に対する単一の DP 配列のみが維持されます。 

N と K が最大 4000 の場合、合計操作数は約 1600 万回で、これは単純なループで実装された場合の Python の一般的な制限内に十分収まります。

 ## 特殊なケース

 K = 1 の場合、すべてのセグメント サイズが禁止されます。 そうしないと、DP を実行すると、dp[0] が dp[1] に誤って伝播することが示唆され、無効な構造が誤ってカウントされます。 明示的なチェックにより状態遷移が防止され、答えはゼロのままになります。 

K > N の場合、1 から N までのすべてのセグメント サイズが許可され、問題は N の標準的な整数パーティションに限定されます。ループには N を超えずにすべての意味のある部分サイズが含まれているだけであるため、DP は依然として正しく動作します。 

N = 1 や N = 2 など、N が小さい場合、DP は単純な更新に縮退します。 dp[0] = 1 が唯一のシード状態であり、すべての有効なパーティションが中間の曖昧さなしにそこから直接構築されるため、この構造は依然として保持されます。
