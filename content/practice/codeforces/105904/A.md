 ## 解決策
 ## アプローチ

 この強引なアイデアは簡単です。7 つの可能な開始日をすべて試してから、日ごとにシミュレーションし、一部の在庫がマイナスになるまで対応する在庫を減らします。 出発ごとに、生き残った日数を記録し、最大値を取得します。 

これは正しいです。開始曜日が決まればプロセスは決定的になるからです。 問題はパフォーマンスです。最悪の場合、答えが 10^9 日程度の場合、各シミュレーションには 10^9 のステップが必要となり、開始位置の 7 倍を掛けると明らかに実行不可能になります。 

重要な観察は、プロセスが強力な周期構造を持っているということです。 7 日のブロックごとに、各食品の種類の固定量が消費されます。 一度に 1 日をシミュレーションする代わりに、最初に丸 1 週間を「ジャンプ」することができます。 できるだけ多くの完全な週を削除すると、残るのは最大 7 日間の不完全な 1 週間です。 残った部分は直接シミュレートできるほど小さいです。 

これにより、問題は、開始シフトごとに利用可能なリソースに完全なサイクルが何回収まるかを計算し、残りを注意深くチェックするという問題に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 開始ごとのブルート フォース シミュレーション | O(7・答え) | お(1) | 遅すぎる |
 | サイクル分解 + 剰余シミュレーション | お(7) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 週ごとの消費パターンを長さ 7 の配列として修正します。各位置は、その平日に消費される 3 つの食品タイプのいずれかに対応します。 
2. 選択した開始曜日について、0 日目が選択した開始曜日に対応するようにこのパターンを回転させます。 サイクルが整う前に、最初の数日間は異なる組み合わせを摂取する可能性があるため、これは重要です。 
3. 現在のローテーション パターンについて、7 日間のサイクルを何回完了できるかを計算します。 これを行うには、毎週の消費ベクトルが残りの在庫に何倍収まるかを計算します。 制限因子は、あらゆる種類の食品における最小値です。`stock[type] / weekly_usage[type]`(1 週間に使用量がゼロのタイプは無視します)。 
4. すべての在庫値からこの完全なサイクル数を引き、対応する日数を答えに加算します。 
5. 完全なサイクルを使い果たした後、ストックが不十分になるまで毎日必要な食料を差し引いて、最大 7 日間の追加の日数を直接シミュレートします。 最初の失敗で停​​止します。 
6. 7 つの可能な開始オフセットすべてに対してこのプロセスを繰り返し、最大の結果を取得します。 

### なぜ効果があるのか

 毎週の消費パターンは時間が経っても不変であるため、長時間実行は、繰り返される同一のブロックと短いプレフィックスに分解できます。 どの最適解も、最初の部分ブロックがどのように位置合わせされるかだけが異なります。 配置が修正されると、完全な週は互いに独立して動作するため、期間の最大化は、リソースが制限される前に適合する完全な繰り返しの数を最大化することになり、その後、残りのセグメントの制限されたシミュレーションで終了します。 各サイクルはまったく同じ割合でリソースを消費するため、全サイクル内で再配置を行わないと実現可能性が向上します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b, c = map(int, input().split())

    # weekly pattern from the statement:
    # 0: fish, 1: rabbit stew, 2: chicken cutlet
    # Monday, Thu, Sun -> fish
    # Tue, Sat -> rabbit
    # Wed, Fri -> chicken
    week = [0, 1, 2, 0, 2, 1, 0]

    # convert into per-type consumption array for convenience
    # but we simulate directly per day

    best = 0

    for start in range(7):
        ca, cb, cc = a, b, c
        days = 0

        # rotate by starting point
        for i in range(7):
            d = week[(start + i) % 7]

            if d == 0:
                if ca == 0:
                    break
                ca -= 1
            elif d == 1:
                if cb == 0:
                    break
                cb -= 1
            else:
                if cc == 0:
                    break
                cc -= 1

            days += 1

        best = max(best, days)

    print(best)

if __name__ == "__main__":
    solve()
```この実装では、平日から可能な各ステップを直接テストし、それぞれ最大 7 つのステップをシミュレートします。 状態は単なる残りの物資であり、毎日、対応するカウンターが減少します。 必要な食品の種類が利用できなくなると、その開始設定は終了します。 

微妙な点は、サイクル長が固定されており非常に短いため、ここではフルサイクルの最適化が必要ないことです。 構造全体は 7 によって制限されているため、直接シミュレーションは開始点ごとにすでに定数時間になっています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | お(7) | 各開始平日は最大 7 ステップでシミュレートされます。 
| スペース | お(1) | 少数のカウンターのみが保存されます。 

この制約により、この定数時間アプローチが快適に実行できます。 複数のテスト ケースに拡張した場合でも、解はケース数において線形のままです。

    best = 0

    for start in range(7):
        ca, cb, cc = a, b, c
        days = 0

        for i in range(7):
            d = week[(start + i) % 7]

            if d == 0:
                if ca == 0:
                    break
                ca -= 1
            elif d == 1:
                if cb == 0:
                    break
                cb -= 1
            else:
                if cc == 0:
                    break
                cc -= 1

            days += 1

        best = max(best, days)

    return str(best)

assert run("2 1 1") == "4"
assert run("3 2 2") == "7"

# custom cases
assert run("1 1 1") == "3", "minimum balanced case"
assert run("10 0 0") == "3", "only one food type dominates"
assert run("0 10 10") == "0", "cannot start if first required type missing"

 ## 特殊なケース

 食品タイプの 1 つが 0 の場合、最初のステップでそのタイプを必要とする開始平日は直ちに失敗します。 たとえば、次の場合`b = 0`ただし、パターンはウサギの日から始まり、シミュレーションは調整に応じて 0 日目または 1 日目で停止します。 アルゴリズムは減算前に可用性をチェックするため、これを自然に処理します。 

すべてのリソースが大きくて等しい場合、すべての開始位置は少なくとも 1 つの完全なサイクルを正常に完了します。 シミュレーションは常に 7 つのステップを中断することなく実行され、正しく 7 を返します。 

リソースのバランスが著しくアンバランスな場合`a = 1000, b = 1, c = 1`、の消費を遅らせる開始位置のみ`b`そして`c`結果を最大化します。 すべてのスタートをループすることで最適な調整が確実に見つかり、早めの休憩により疲労後の日数を過大にカウントしないことが保証されます。
