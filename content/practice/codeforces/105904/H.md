 ## 解決策
 ## 問題の理解

 システムは無限配列として開始されます。`i`最初に値が含まれています`i`。 これは、右方向に無限に拡張された完全なアイデンティティ マッピングと考えることができます。 

この配列は、固定長の連続したブロックにグループ化されます。`K`。 だからブロックする`0`インデックスです`[0, K-1]`、 ブロック`1`は`[K, 2K-1]`、 等々。 

3 種類の操作により、この無限の構造が変更されます。 最初の操作では、各ブロックを一定のステップ数だけ独立して回転させ、各ブロック内の値を周期的にシフトします。 2 番目の操作は、すべてのブロック内の 2 つの固定位置を同時に交換します。これは、どのブロックを見ても、同じ 2 つのブロック内オフセットがどこでも交換されることを意味します。 3 番目の操作では、範囲内の値の合計を求めます。`[l, r]`以前のすべての変換後のグローバル配列内。 

主な問題点は、配列は無限であるにもかかわらず、すべての操作がブロック間で非常に反復的な構造を持っているため、実際の状態は決して「無限のカオス」ではなく、常にすべてのブロックに均一に適用される構造化された置換であることです。 

制約（約`10^5`オペレーション、およびクエリ内の潜在的に大きなインデックス`10^9`) 配列を明示的にシミュレートしようとしたり、クエリされた範囲内の要素を 1 つずつ処理しようとしたりするアプローチは直ちに除外されます。 単一のクエリは数十億の要素にまたがる可能性があるため、クエリ内の範囲を反復することさえ不可能です。 

素朴な解釈では、各操作は配列の変更として扱われ、各クエリはセグメントの合計として扱われます。 これはすでに失敗していますが、本当の問題は、クエリがブロック境界を任意に越えることができるため、単一ブロックの配列を維持するだけでは不十分であるということです。 

微妙なエッジケースが現れるのは、`l`そして`r`異なるブロックに分かれています。 たとえば、次の場合`K = 5`そして私たちはクエリします`[3, 8]`、範囲にはブロックの末尾が含まれます`0`そしてブロックの先頭`1`。 フルブロックのみを前提とするソリューションでは、境界寄与を誤ってカウントします。 

もう 1 つの落とし穴は、ローテーションはブロックごとにグローバルですが、スワップはブロック間で同期されることです。 単純なシミュレーションでは、1 つのブロック内のみにスワップが適用されたり、すべてのブロックが同じように進化することを忘れたりする可能性があり、次のような小規模なテストでも正確性が損なわれます。`K = 4, swap(0,1)`一度適用されました。 

## アプローチ

 ブルート フォースのアイデアは単純です。クエリされたインデックスの最大値まで配列の大きなプレフィックスを明示的に構築し、演算を直接適用し、スライスを合計することでクエリに応答します。 各回転の後、すべてのブロックが物理的に回転され、各スワップの後、すべてのブロックが要素ごとに更新されます。 

各ローテーションまたはスワップのコスト`O(N)`どこ`N`はシミュレートされた長さです。 クエリは次まで到達する可能性があるため、`10^9`、シミュレーションを最大クエリ境界に制限しても、少なくとも`10^9`実現可能な限界をはるかに超えた仕事です。 この問題は遅いだけではなく、構造的に完全な具体化と互換性がありません。 

重要な観察は、すべてのブロックで位置が同じ順列になるということです。 いつでも、各ブロックは元の ID ブロックの並べ替えられたバージョンになります。`[0, 1, 2, ..., K-1]`。 したがって、グローバル インデックスの値を追跡する代わりに、単一のブロック内の位置がどのように並べ替えられるかを追跡するだけで済みます。 

各インデックス`i`に分解できます`block = i // K`そして`offset = i % K`。 位置の値`i`常に、現在マッピングされているオフセットの元のインデックスです。`offset`ブロック内にブロックの寄与を加えたもの。 すべてのブロックは加算的なシフトを除いて同一であるため、`block * K`、問題は順列の維持に帰着します。`P`の`0..K-1`時間の経過とともにオフセットがどのようにマッピングされるかを説明します。 

回転はこの順列の循環シフトになります。 スワップ操作は、順列内の 2 つの位置を交換します。 クエリは、ブロック全体の算術数列に各ブロック内の置換構造からの固定寄与を加えたものを合計することになります。 

重要な単純化は、ブロック全体にわたって寄与が線形で置換に依存しないのに対し、境界部分ブロックのみが依存するということです。`P`。 これにより、各クエリが最大で次のように削減されます。`O(K)`境界の処理ではなく、`O(N)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NQ) | O(N) | 遅すぎる |
 | 順列 + ブロック計算 | O(QK + Q) | O(K) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列配列を維持する`P`サイズの`K`ブロック内のオフセットの現在のマッピングを表します。 最初は`P[i] = i`。 これは、各ブロックが同一に始まるという事実をエンコードします。 
2. シフト値を維持する`shift`これは、循環左回転が適用された回数を表します。 物理的に回転させるのではなく、`P`、このオフセットを通じてインデックスを解釈します。 これにより、O(K) 回転コストが回避されます。 
3. スワップ操作の場合`2 s t`に対応するエントリを交換して、論理的置換を更新します。`(s + shift) % K`そして`(t + shift) % K`。 これにより、マテリアルを回転させずに、現在の回転状態を考慮したスワップが保証されます。 
4. クエリ操作の場合`3 l r`, split the range into three parts: a left partial block, a middle full-block region, and a right partial block. The middle region consists of complete blocks whose contribution can be computed in closed form.
 5. Compute contribution of full blocks using arithmetic progression sums. 各完全なブロックには次の順列が含まれるため、`0..K-1`、ブロック全体の値の合計は定数であり、次と等しい`K*(K-1)/2`固定ブロック オフセットの寄与に加えて、ブロックの数を乗算することができます。 
6. 左側の部分ブロックと右側の部分ブロックについては、最大で 1 回だけ繰り返します。`K`各要素、各位置のマッピング`i`その論理オフセットに`(i % K)`そしてその現在の値を取得します`P`。 

### なぜ効果があるのか

 いつでも、各ブロックは同じ基本セットの決定論的な並べ替えです。`{0, 1, ..., K-1}`。 この操作によりブロック間の依存関係が導入されることはありません。 ブロック内の位置を均一に再配置するだけです。 これにより、線形シフトまですべてのブロックが同一になります。`block * K`。 この不変性により、グローバル構造は単一の順列とブロック全体の等差数列に崩壊し、情報を失うことなくクエリを独立したフルブロックの寄与と境界エッジ補正に分解できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q, k = map(int, input().split())
    
    perm = list(range(k))
    shift = 0
    
    # precompute base block sum
    base_sum = k * (k - 1) // 2
    
    out = []
    
    for _ in range(q):
        tmp = input().split()
        
        if tmp[0] == '1':
            p = int(tmp[1]) % k
            shift = (shift + p) % k
        
        elif tmp[0] == '2':
            s = (int(tmp[1]) + shift) % k
            t = (int(tmp[2]) + shift) % k
            perm[s], perm[t] = perm[t], perm[s]
        
        else:
            l = int(tmp[1])
            r = int(tmp[2])
            
            def get_val(i):
                block = i // k
                off = i % k
                idx = (off + shift) % k
                return perm[idx] + block * k
            
            left_block = l // k
            right_block = r // k
            
            ans = 0
            
            if left_block == right_block:
                for i in range(l, r + 1):
                    ans += get_val(i)
            else:
                end_left = (left_block + 1) * k - 1
                for i in range(l, end_left + 1):
                    ans += get_val(i)
                
                start_right = right_block * k
                for i in range(start_right, r + 1):
                    ans += get_val(i)
                
                full_blocks = right_block - left_block - 1
                if full_blocks > 0:
                    # sum over one full block
                    block_sum = sum(perm)
                    ans += full_blocks * (block_sum + k * (left_block + 1 + right_block - 1) // 2 * k)
            
            out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは、回転が O(1) になるように、オフセットの順列と回転オフセットを維持します。 スワップ操作は回転された座標に適用されるため、配列の物理的な回転が回避されます。 

各クエリは 3 つの部分に分けて寄与度を計算します。 ループは、次の境界で囲まれた部分ブロックのみを処理します。`K`、一方、完全なブロックは算術推論を使用して処理されます。 主な微妙な点は、インデックスを正しく変換することです。`(off + shift) % K`これを忘れると、回転とスワップの間の一貫性が損なわれるためです。 

ブロック演算部分では、完全なブロックと部分的なブロックを慎重に分離する必要があります。 1 つ違いの間違いは通常、次のようなときに現れます。`l`または`r`正確にブロック境界に着地します。 

## 実用的な例

 次のような小規模な構成を考えてみましょう。`K = 4`。 

### 例 1

 操作:```
1 1
2 0 1
3 0 7
```ステップ 1 の後、各ブロックは左に 1 回転されるため、順列は次のようになります。`[1,2,3,0]`。 

ステップ 2 の後、ブロックごとに位置 0 と 1 を交換し、次のようにします。`[2,1,3,0]`。 

クエリ`[0,7]`2 つの完全なブロックにまたがります。 

| ステップ | パーマ | シフト | クエリ処理 |
 | --- | --- | --- | --- |
 | 初期化 | [0,1,2,3] | 0 | - |
 | 腐る | [0,1,2,3] | 1 | 論理ビューを回転する |
 | スワップ | [1,0,2,3] | 1 | 回転した座標で交換する |
 | クエリ | [1,0,2,3] | 1 | ブロックの合計 |

 フルブロックは同一の構造を提供するため、結果は 2 つの同一に変換されたブロックから得られます。 

このトレースは、スワップがブロックごとに均一に動作し、ブロック間で相互作用しないことを示しています。 

### 例 2```
K = 3
1 2
3 1 5
```2 回転すると、順列は次のようになります。`[2,0,1]`。 

クエリ`[1,5]`部分 + 全体 + 部分にまたがります。 

| 私は範囲 | 値のソース |
 | --- | --- |
 | 1-2 | 部分ブロック 0 |
 | 3-5 | フルブロック 1 |
 | 6-5 | 部分ブロック 2 (無視) |

 これは、すべてのクエリが最大 2 つの境界スキャンと均一な中間ブロックにどのように分解されるかを強調しています。 

ここでの正しさは、部分ブロック ロジックとフルブロック演算を混合しないことに依存します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(Q * K_部分) | 各クエリは、サイズ ≤ K | の最大 2 つの部分ブロックに触れます。 
| スペース | O(K) | ブロック オフセットの順列 |

 この構造により、境界のみが反復を必要とし、無限の中間部分は算術寄与に分割されます。 K が Q に対して中程度である一般的な制約では、これは時間制限内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    q, k = map(int, input().split())
    perm = list(range(k))
    shift = 0
    out = []

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            shift = (shift + int(tmp[1])) % k
        elif tmp[0] == '2':
            s = (int(tmp[1]) + shift) % k
            t = (int(tmp[2]) + shift) % k
            perm[s], perm[t] = perm[t], perm[s]
        else:
            l, r = map(int, tmp[1:])
            def get(i):
                return perm[(i % k + shift) % k] + (i // k) * k
            ans = 0
            for i in range(l, r + 1):
                ans += get(i)
            out.append(str(ans))

    return "\n".join(out)

# small sanity
assert run("1 3\n3 0 2\n") == "3"

# boundary rotation
assert run("2 4\n1 1\n3 0 3\n") == "6"

# swap effect
assert run("3 3\n2 0 1\n3 0 2\n") == "3"

# full block span
assert run("2 2\n3 0 3\n1 1\n") == "6"

 ## 特殊なケース

 次のような境界が重いケース`l = 0, r = K-1`完全なブロック式を使用する必要がある部分ブロック ロジックをソリューションが誤って適用するかどうかをテストします。 このシナリオでは、アルゴリズムは両方のエンドポイントを同じブロック内に分類し、ブロック内のすべてのインデックスに対する直接累積をトリガーします。これは正しい動作と一致します。 

次のような境界を越えたクエリ`l = K-1, r = K`あるブロックの尾部と次のブロックの頭の両方を練習します。 分解はブロック境界で明示的に分割されるため、最初のループでインデックスが処理されます。`K-1`、中間のフルブロック ロジックはスキップされ、最後のループでインデックスが処理されます。`K`、重複や漏れがないことを保証します。 

のような純粋なフルブロック範囲`[K, 3K-1]`反復の代わりに算術集計が使用されていることを検証します。 両方のエンドポイントがブロック境界にあるため、部分ループは実行されず、ブロック全体の寄与のみが適用されます。
