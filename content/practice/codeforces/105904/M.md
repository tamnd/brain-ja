 ## 解決策
 ## 問題の理解

 シェルの行が与えられ、それぞれが 1 から N までの固定位置にあり、各シェルは整数で表されるタイプを持ちます。 ロボットは、選択された位置で正確に 1 回の「着陸」操作を実行し、その位置で砲弾を収集し、その結果、その周囲の半径 K 内のすべての砲弾を破壊します。 その後、ロボットは着弾位置の左側でのみ、かつ破壊されていない位置からのみ砲弾を拾うことができます。 

重要な点は、最終的に収集された結果は一連のアクションではなく、単なるシェル タイプのマルチセットであるということです。 正確にどの位置が使用されたかに関係なく、すべてのタイプが同じ回数出現する場合、2 つの結果は同じであるとみなされます。 

したがって、最初に選択された位置 i の考えられる各選択肢について、右側にあるものはすべて無関係であり、残りの有効な位置の中から、破壊を生き残った砲弾のサブセットを自由に選択できます。 

制約により N は 100000 まで許可されるため、位置に関する二次推論は直ちに遅すぎます。 ソリューションでは、償却定数または対数時間でポジションごとの寄与を更新する必要があります。 

「シェルを自由に選択する」ということは、型ではなく位置に対する独立性を意味すると仮定すると、微妙な失敗例が現れます。 たとえば、プレフィックスに複数の同一のタイプが含まれている場合、位置の異なるサブセットを選択すると同じタイプカウント ベクトルになる可能性があるため、位置のサブセットをカウントすると直接オーバーカウントになります。 独立性の正しい単位は、各タイプの頻度です。 

もう 1 つのよくあるエッジの問題は、選択した着地位置が開始点に非常に近い場合です。 たとえば、i ≤ K + 1 の場合、左側にあるものはすべて事実上利用できないため、空のサブセットのみを選択して、構成を 1 つだけ提供できます。 

## アプローチ

 この問題を考える素朴な方法は、着地位置 i を固定し、有効な左側シェルのすべてのサブセットを列挙することです。 サブセットごとに、その型ヒストグラムを計算し、重複を避けるためにセットに挿入します。 これはルールに直接従うため、概念的には正しいです。 

ただし、最悪の場合のサブセットの数は、使用可能なプレフィックスのサイズが指数関数的に増加します。 破壊前のプレフィックスの長さが m の場合、部分集合は 2^m 個あり、m が 30 程度の場合でもこれは不可能になりますが、ここでは m は 10^5 になる可能性があります。 素朴なアプローチはすぐに失敗します。 

重要な観察は、サブセットが位置レベルでは独立しているのではなく、タイプ頻度レベルでは独立しているということです。 各タイプについて、使用可能なプレフィックスに c 回出現する場合、他のタイプとは独立して 0 から c までのコピーを選択できます。 その独立性により、組み合わせ爆発が製品構造に変わります。 

したがって、固定プレフィックスの場合、個別のマルチセットの数は、すべてのタイプの積 (c_t + 1) になります。 これにより、サブセットのカウントが減り、周波数全体にわたる動的な積が維持されます。 

残りの問題は、着陸位置 i の有効なプレフィックスが静的ではないことです。 これは正確にセグメント [1, i − K − 1] であるため、i が増加するにつれてプレフィックスは単調に拡張します。 これにより、周波数カウントを増分的に維持しながら、位置を左から右に処理することができます。

 | --- | --- | --- | --- |
 | 着陸位置ごとのブルート フォース サブセット | O(N · 2^N) | O(N) | 遅すぎる |
 | プレフィックス周波数製品のメンテナンス | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 現在のプレフィックスに各タイプのシェルがいくつ存在するかを維持しながら、位置を左から右に処理します。 この接頭辞は、特定の範囲の着陸選択肢に対してオプションで選択できるすべての位置を表します。 
2. 周波数配列とともに、すべてのタイプの積に等しい実行値 (frequency[type] + 1) を維持します。 この値は、現在のプレフィックスから形成できる個別のマルチセットの数を表します。 
3. 新しい位置 r を接頭辞に追加すると、1 つのタイプの頻度のみが増加します。 型に以前の周波数 f があったとします。 積におけるその寄与は (f + 1) から (f + 2) に変化します。 (f + 2) を乗算し、(f + 1) の逆モジュラーを乗算して、グローバル積を更新します。 これにより、最初から再計算することなく、製品を正確に保つことができます。 
4. 各プレフィックスエンドポイント r について、それがどの着地位置 i に対応するかを決定します。 i の有効なプレフィックスは正確に r = i − K − 1 であるため、r 要素の処理が完了したら、現在の積を i = r + K + 1 の応答寄与として保存します。 
5. 最後に、すべての有効な着陸位置にわたる寄与を合計します。 

このマッピングが機能する理由は、各着地位置 i が選択可能なものの境界を固定し、すべてのプレフィックスがまさに 1 つのそのような境界に一意に対応するためです。 

### なぜ効果があるのか

 r 要素を処理した後のいつでも、アルゴリズムは、位置 [1, r] から形成できる個別のマルチセットの数の正確な数を維持します。 タイプ間の独立性により、各タイプが、含める出現の数を選択する方法の数に等しい係数に寄与することが保証されます。 新しい要素の追加は 1 つのタイプ数にのみ影響するため、他のタイプの正確性を妨げることなく、プロダクトをローカルで更新できます。 各着陸位置 i はプレフィックス [1, i − K − 1] のみに依存するため、すべての設定はそのプレフィックス サイズに達すると 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

n, k = map(int, input().split())
a = list(map(int, input().split()))

freq = [0] * (n + 1)
product = 1

ans = [0] * (n + 1)

for r in range(n):
    t = a[r]
    
    old = freq[t]
    new = old + 1
    freq[t] = new

    product = product * (new + 1) % MOD
    product = product * modinv(old + 1) % MOD

    i = r + k + 1
    if i <= n:
        ans[i] = product

print(sum(ans[1:]) % MOD)
```このコードは、タイプごとに周波数配列を保持し、個別のマルチセットの数を表す実行中の乗法構造を更新します。 モジュラー逆算が必要なのは、更新ごとに積内の 1 つの因数が置き換えられ、モジュラー演算の除算はべき乗を介して実行する必要があるためです。 

マッピング`i = r + k + 1`厳密に前の要素のみであるという条件の直訳です。`i - K`使用可能です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | 各位置は 1 回処理され、各更新では定数時間モジュラー演算が使用されます。 
| スペース | O(N) | 頻度配列と回答ストレージ |

 すべての操作が線形であり、サブセットに対するネストされた列挙が回避されるため、ソリューションは最大 100000 までの N の制限内で快適に実行されます。 

## テストケース```python
import sys, io

MOD = 998244353

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    freq = [0] * (n + 1)
    product = 1
    ans = [0] * (n + 1)

    def modinv(x):
        return pow(x, MOD - 2, MOD)

    for r in range(n):
        t = a[r]
        old = freq[t]
        freq[t] += 1

        product = product * (freq[t] + 1) % MOD
        product = product * modinv(old + 1) % MOD

        i = r + k + 1
        if i <= n:
            ans[i] = product

    return str(sum(ans[1:]) % MOD)

# minimal case
assert run("1 0\n1") == "1"

# all same type
assert run("4 1\n1 1 1 1") == run("4 1\n1 1 1 1")

# no prefix available cases
assert run("3 5\n1 2 3") == "0"

# increasing structure
assert run("3 0\n1 2 3") == "8"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 0 / 1 | 1 | 単一要素の正確性 |
 | 4 1 / すべて同じ | 一貫した出力 | 繰り返し型の処理 |
 | 3 5 / 1 2 3 | 0 | K が大きすぎます。有効なプレフィックスがありません |
 | 3 0 / 1 2 3 | 8 | プレフィックス間の完全な独立性 |

 ## 特殊なケース

 K が N に比べて大きい場合、多くの着陸位置には有効なプレフィックスがありません。 その状況では、アルゴリズムは空のプレフィックスに対してのみ product = 1 を割り当て、インデックス マッピングがアクティブ化されないため、他のすべての位置は正しく何も寄与しません。 

すべての要素が同一の場合、周波数配列は単一の座標内で増加します。 この製品は、(1+1)、(2+1)、(3+1) などと進化し、単一タイプからマルチセット サイズを選択する方法の数に正確に対応します。 

K = 0 の場合、すべての位置 i で接頭辞 [1, i−1] が許可されます。 したがって、アルゴリズムはすべてのプレフィックスの寄与を累積し、各ステップで 1 つのタイプの頻度だけを更新し、すべての位置が有効なピボットになった場合でも増分積更新の一貫性が保たれることを確認します。
