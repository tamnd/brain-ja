 ## 解決策
 ## 問題の理解

 この問題により、廊下で接続された部屋のツリーが得られ、各廊下には通過コストがかかります。 一部の部屋には、時間ゼロからスペースを「占有」し始める人がいます。 占有されている各部屋は、人々が到着する時刻までに到着しない限り安全ではなくなります。「到達時間」は、最初に占有されていた部屋からの最短経路距離によって決まります。 

時間ごとに部屋 1 から始まる旅行者を制御します$t$、そして彼は同じエッジコストで廊下に沿って移動します。 重要な制限は、到着時間が人々が到着する時刻以下の場合にのみ部屋に入室できるということです。 彼が厳密に遅れて到着した場合、部屋は永久に封鎖されます。 平等が許可されるため、境界タイミングが重要になります。 

目標は、最小の開始遅延を選択することです$t$部屋 1 から部屋への有効なルートが少なくとも 1 つ存在するようにする$N$、すべての安全な制約内に留まります。 

この構造は、2 つの競合する最短パス プロセスを暗示しています。1 つは人のソースから伝播し、もう 1 つはノード 1 から開始して可変オフセットを持つ旅行者から伝播します。 

制約により、最大で次のことが許可されます。$10^5$ノードとエッジのため、実際にはどのようなソリューションも本質的に線形または線形に近いものでなければなりません。$O(N \log N)$。 この規模では、単一のダイクストラ実行でさえすでにコストがかかるため、すべての候補開始時間に対して個別に最短パスを再計算しようとするソリューションはすぐに失敗します。 

微妙なエッジケースは、等価性の処理から発生します。 人々が到着する時間に旅行者が正確に到着した場合、その部屋はまだ使用できます。 これは、比較は非厳密である必要があることを意味します。 たとえば、ノードの距離が等しい場合、そのノードは引き続き使用可能ですが、等しさを無視すると不必要なブロックが発生します。 

複数の初期ソースが存在する場合、別の問題が発生します。 「人々の到着時間」は複数ソースの最短経路の問題であるため、単一ソースからの単純な BFS は不正確です。 

最後に、旅行者にとって最適なパスが 1 から N への世界的に最短のパスではないという、明白ではないケースがあります。早期に汚染されたノードを回避する場合、より長いルートが有効になる可能性があります。 したがって、1 からの最短経路のみを考慮する解決策は不完全です。 

## アプローチ

 ブルート フォース ビューは、開始遅延を推測することから始まります。$t$。 候補者ごとに$t$、訪問したノードごとに、パスが 1 から N まで存在するかどうかをシミュレートします。$v$、条件$$dist_1(v) + t \le dist_{people}(v)$$が成立する。 有効なノードに限定された BFS またはダイクストラを使用して到達可能性を再計算できます。 

これは正しいですが、高価です。 一つ確認しても$t$費用$O(N \log N)$、最大距離範囲まですべての可能な値を試してみると、不可能になります。$O(N^2 \log N)$またはより悪い行動。 

重要な観察は、実現可能性が単調であるということです。$t$。 遅延の場合$t$動作する場合、さらに大きな遅延が発生する$t' > t$トラベラーを後から作成することしかできないため、制約を改善することはできません。 むしろ、条件が厳しくなります。 これは二分探索を示唆しています$t$。 

この問題を自明ではないものにしているのは、「固定の有効性」ということです。$t$” それ自体は、ノード制約の下での最短パスに依存します。これを、2 つの距離配列を事前計算することで解決します。

 1 つは、人が占有しているすべてのノードからのマルチソース最短パスです。$dist_P[v]$。 

もう 1 つはノード 1 からの最短パスであり、次のようになります。$dist_1[v]$。 

次に、特定の実現可能性$t$これは、次を満たすノードのみを使用して 1 から N へのパスが存在するかどうかをチェックすることに帰着します。$$dist_1[v] + t \le dist_P[v]$$これを「安全な時間」によって引き起こされる部分グラフとして解釈します。$t$各実現可能性チェックは標準のグラフ走査になります。 

したがって、問題は、複数ソースのダイクストラ、単一ソースのダイクストラ、およびしきい値制約上の二分探索の組み合わせになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 全てにおいてブルートフォース$t$毎回完全検索 |$O(N^2 \log N)$|$O(N)$| 遅すぎる |
 | 距離の事前計算 + 二分探索 + BFS チェック |$O(N \log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 人々がいるすべての部屋から開始してマルチソースのダイクストラを実行します。 これにより、$dist_P[v]$、人々が各部屋に到着する最も早い時間。 これが必要なのは、複数のソースが同時に拡大し、真に最も早い到着が必要であるためです。 
2. 部屋 1 から標準ダイクストラを実行して計算します。$dist_1[v]$、旅行者が制限なく各部屋に到着できる最も早い時間。 
3. 関数を定義する`can(t)`開始遅延に対して有効なルートが存在するかどうかを確認します$t$。 各ノードについて$v$、それが使用可能かどうかを計算します。$dist_1[v] + t \le dist_P[v]$。 使用できないノードはブロックされたものとして扱います。 
4. 内部`can(t)`、ノード 1 から BFS または DFS を実行しますが、使用可能なノードのみを走査します。 If ノード$N$到達可能な場合は true を返します。 
5.最小二分探索$t$そのような`can(t)`それは本当です。 検索範囲は、$dist_P$そして$dist_1$、または単にエッジの重みの合計や最大最短パスの差のような大きな安全境界。 
6. 有効な最小値を出力します$t$。 

### なぜ効果があるのか

 重要な不変条件は、固定された$t$、条件$dist_1[v] + t \le dist_P[v]$走査順序とは無関係に、許可される頂点の固定セットを定義します。 有効なパスはすべてこのセット内に完全に存在する必要があり、このセット内のパスは構造上のタイミング制約を尊重します。 増えてからは$t$許可されたセットを縮小するだけであり、実現可能性は単調であるため、二分探索が正当化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

INF = 10**18

def dijkstra(n, graph, sources):
    dist = [INF] * (n + 1)
    pq = []
    for s in sources:
        dist[s] = 0
        heapq.heappush(pq, (0, s))

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

def can(n, graph, dist1, distP, t):
    if dist1[1] + t > distP[1]:
        return False

    vis = [False] * (n + 1)
    stack = [1]
    vis[1] = True

    while stack:
        u = stack.pop()
        for v, _ in graph[u]:
            if not vis[v]:
                if dist1[v] + t <= distP[v]:
                    vis[v] = True
                    stack.append(v)

    return vis[n]

def solve():
    n, m, k = map(int, input().split())
    graph = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b, c = map(int, input().split())
        graph[a].append((b, c))
        graph[b].append((a, c))

    sources = list(map(int, input().split()))

    distP = dijkstra(n, graph, sources)
    dist1 = dijkstra(n, graph, [1])

    lo, hi = 0, max(distP[1], dist1[n]) + 1

    ans = -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if can(n, graph, dist1, distP, mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、問題を前処理と意思決定チェックに分割します。 2 つのダイクストラ実行により、パス構造からタイミング情報が完全に切り離されます。 

実現可能性チェックにより、最短パスの再計算が回避されます。 代わりに、時間制約を頂点フィルターとして扱い、各チェックを線形グラフの走査に減らします。 

二分探索はこれを効率的にラップするので、$O(\log V)$このような横断が必要です。 

微妙な点の 1 つは、条件に等価性を含める必要があるということです。`dist1[v] + t <= distP[v]`。 これを厳密な不等式に変更すると、特に最短パスで位置合わせされた例で、有効な境界ケースが誤って削除されます。

 ## 特殊なケース

 重要なエッジケースは、開始ノードが小規模なノードにとってすでに安全ではない場合です。$t$。 この状況では、ノード 1 が制約に違反するため、実行可能性チェックは直ちに失敗します。$dist_1[1] + t \le dist_P[1]$これにより、不等式が有効になるまで二分探索が強制的に上方に移動します。 

もう 1 つのケースは、唯一の有効なパスが長いルートを迂回する必要がある場合です。 到達可能性は最短パス構造に依存するのではなく、フィルター処理されたグラフで計算されるため、アルゴリズムはこれを正しく処理します。 

最後のケースには、波面が同じ時間に出会うように配置された複数の人物のソースが含まれます。 マルチソース ダイクストラがないと、計算された到着時間が不正確になり、ノードが誤って安全または安全でないとしてマークされ、実現可能性チェックが損なわれる可能性があります。
