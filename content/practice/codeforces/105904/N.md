 ## 解決策
 ## 問題の理解

 公園内の場所とそれらの間の経路を表す無向の重み付きグラフが与えられます。 各道には距離があり、その距離は 2 つの異なるグループ (自転車に乗るカルロスと徒歩の人々) の移動時間に換算されます。 カルロスは長さ C のエッジに沿って時間 C で移動しますが、人々は同じエッジに対して 2C かかります。 人々はちょうど時刻 0 に K 個のエントリ ポイントから拡散を開始し、そこから最短経路の移動時間を使用してグラフ内を同時に拡大します。 

カルロスはノード 1 から開始しますが、時間 0 より前に開始することが許可されています。 彼が開店の s 分前に出発した場合、ノードへの有効到着時間は、通常の最短移動時間から s を引いたものになります。 彼はノード N に到達したいと考えていますが、厳密な制約があります。つまり、人々がすでにノードに到達した後で厳密にノードに入ることができないということです。 同時到着も引き続き可能です。 

タスクは、カルロスが人々よりも遅れてノードに到達することがない 1 から N までのパスが存在するように、最小の非負の整数 を計算することです。 

制約は最大 100,000 のノードとエッジに及ぶため、すべてのパスを明示的に試行するアプローチは除外されます。 どのようなソリューションも最短パスに依存し、その後、およそ O((N + M) log N) 時間で二次グラフ推論ステップを実行する必要があります。 

1 から N までのすべてのパスを列挙し、両方の到着プロセスをシミュレートする単純なアプローチは、パスの数が指数関数的なため、すぐに失敗します。 固定された s の実現可能性をチェックする場合でも、試行のたびにマルチソースの最短経路推論が必要になりますが、これを繰り返すとやはり時間がかかりすぎます。 

カルロスと人々がまったく同時にノードに到着すると、微妙なエッジ ケースが発生します。 そのノードは引き続き使用できますが、人々がほんのわずかでも早く到着すると、そのノードはカルロスにとってパスの継続を禁止されます。 これにより、問題はローカル エッジの決定ではなく、2 つのグローバル距離フィールド間の厳密な比較に依存するようになります。 

## アプローチ

 主な問題は、2 つの独立した波面が同じグラフ上を異なる速度で伝播することです。 1 つはノード 1 から発信され、Carlos に依存し、もう 1 つは複数のソースから発信され、群衆を表します。 どちらも最短経路距離を使用してキャプチャできます。 

まず、エッジの重み 2C のマルチソース最短パスを使用して、人々がすべてのノードに到達する最も早い時間を計算します。 これにより、距離配列 distP が生成されます。 これとは別に、エッジの重み C を使用してノード 1 からのカルロスの最短移動時間を計算し、distC を生成します。 

両方がわかると、s を早めに開始したときにカルロスがノード v に安全に到達するための条件は、 distC[v] − s ≤ distP[v]、または同等の s ≤ distC[v] − distP[v] になります。 これにより、問題は動的時間シミュレーションから静的ノード制約に変換されます。すべてのノードは値 delta[v] = distC[v] − distP[v] を持ち、パス上のすべてのノードが delta[v] ≥ s を満たす場合、開始時刻 s はパスに対して有効になります。 

したがって、時間の発展の観点から考える代わりに、パスに沿った最小デルタを最大化する 1 から N までのパスを検索します。 これは、ノードの重みに関する古典的なボトルネック パスの問題です。 デルタが固定されると、グラフのエッジは接続性のみを定義しますが、実現可能性はパス上の最も弱いノードに依存します。 

ブルート フォース ソリューションでは、すべてのパスを試し、その最小デルタ (指数関数的) を計算します。 制約が 1 つのボトルネック値にまで減少するという観察により、貪欲な伝播が可能になります。つまり、ノードごとに、ノード 1 からの達成可能な最良のボトルネック値を維持します。 

これを最大ヒープまたは優先度ベースの緩和を使用して伝播します。u から v への遷移により候補値 min(best[u], delta[v]) が得られます。 これにより、すべてのノードが 1 からの任意のパスに沿って達成可能な最良の最小デルタを保存するようになります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのパスに対するブルート フォース | 指数 | O(N) | 遅すぎる |
 | 2 つのダイクストラ + ボトルネック DP | O((N + M) log N) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. エッジの重み 2C を使用して、K 個のすべての入口から開始するマルチソース最短パスを実行します。 これにより、群集が各ノードに到達する最も早い時間である distP[v] が計算されます。 このステップでは、人々の同時拡散を単一の最短経路の計算として捉えます。 
2. エッジの重み C を使用してノード 1 から標準ダイクストラを実行し、カルロスが制限なしで各ノードに到達する最も早い時刻である distC[v] を計算します。 これにより、カルロスさんの旅行は群衆から独立して孤立することになります。 
3. 各ノード v について、delta[v] = distC[v] − distP[v] を計算します。 この値は、カルロスがそのノードの群衆と比較してどれだけ早く到着できるかを測定します。 正の値は安全マージンを示し、負の値は群衆が最初に到着することを示します。 
4. best[v] が 1 から v までの任意のパスに沿った最小デルタの最大値を表す最良の配列を構築します。 
5. best[1] = delta[1] を初期化します。 ノード 1 を、最良の値をキーとする最大優先キューに挿入します。 
6. キューの処理中に、最高の best[u] を持つノード u を抽出します。 各近傍 v について、candidate = min(best[u], delta[v]) を計算します。 この候補が best[v] を改善した場合、それを更新し、v をキューにプッシュします。 このステップでは、パスのスコアがその最も弱いノードによって決定されるようにします。 
7. 答えは [N] が最適です。 best[N] が負の場合、負でない有効な開始時刻は存在しません。 それ以外の場合、その値は実現可能な最大開始時間になります。 

### なぜ効果があるのか

 重要な不変条件は、best[v] が 1 から v までのすべてのパスにわたって可能な最大の最小デルタを常に格納することです。パスを拡張するたびに、ボトルネックは減少するだけであり、すべての可能な先行パスにわたって最大値をとることで、より良いパスを決して見逃さないことが保証されます。 すべての緩和では正しいボトルネック構造が保存されるため、ノード N での最終値はすべての可能なパスの中で最適になります。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

INF = 10**30

def dijkstra_sources(n, adj, sources, weight_mul):
    dist = [INF] * (n + 1)
    pq = []
    for s in sources:
        dist[s] = 0
        heapq.heappush(pq, (0, s))
    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in adj[u]:
            nd = d + w * weight_mul
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

def solve():
    n, m, k = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        a, b, c = map(int, input().split())
        adj[a].append((b, c))
        adj[b].append((a, c))
    sources = list(map(int, input().split()))

    distP = dijkstra_sources(n, adj, sources, 2)
    distC = dijkstra_sources(n, adj, [1], 1)

    delta = [0] * (n + 1)
    for i in range(1, n + 1):
        delta[i] = distC[i] - distP[i]

    best = [-INF] * (n + 1)
    best[1] = delta[1]

    pq = [(-best[1], 1)]

    while pq:
        val, u = heapq.heappop(pq)
        val = -val
        if val != best[u]:
            continue
        for v, _ in adj[u]:
            cand = min(val, delta[v])
            if cand > best[v]:
                best[v] = cand
                heapq.heappush(pq, (-cand, v))

    ans = best[n]
    if ans < 0:
        ans = 0
    print(ans)

if __name__ == "__main__":
    solve()
```この解決策では、問題を 2 つの最短パスの計算に分割し、その後にボトルネック パス DP が続きます。 最初のダイクストラは、エッジの重みが 2 倍になったマルチソース波として群衆をモデル化します。 2 つ目はカルロスの旅をモデル化したものです。 減算ステップでは、時間的制約をノードごとの静的スコアに変換します。 最後の最大ヒープ伝播により、最も弱い安全マージンを最大化するパスが選択されます。 

微妙な実装の詳細は、両方のダイクストラ実行が独立しており、状態を共有しない必要があることです。これは、それらを混合するとデルタ計算の正確性が損なわれるためです。 もう 1 つの重要な点は、第 2 フェーズは古典的な意味での最短パスではなく、最小値の最大化であるということです。そのため、加算距離の代わりに最大ヒープと最小値の組み合わせが必要になります。 

## 実用的な例

 ユーザーが 1 つのエントリから開始し、カルロスがノード 1 から開始する小さなグラフを考えてみましょう。2 つのダイクストラ計算を実行した後、各ノードは安全マージンを表すデルタ値を受け取ります。 次に、2 番目のフェーズでは、これらの値がパスに沿って伝播されます。 

| ステップ | ノード | 最高[u] | デルタ[v] | 候補者 | 最高[v] |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | 1 | デルタ[1] | - | - | デルタ[1] |
 | リラックス | u → v | 現在のベスト | デルタ[v] | min(ベスト[u], デルタ[v]) | 大きい場合は更新 |

 このトレースは、各パスのスコアがその最も弱いノードによって制御されており、パスが低デルタ ノードを回避した場合にのみ改善が起こることを示しています。

 ## 特殊なケース

 カルロスと群衆がまったく同時にノードに到着すると、重大なエッジ ケースが発生します。 その状況では、デルタはゼロになり、ノードは引き続き使用可能になります。 伝播中、アルゴリズムはゼロを有効なボトルネック値として扱います。つまり、そのようなノードを通過するパスは引き続き実行可能ですが、最終開始時間をゼロより長くすることはできません。 

もう 1 つの重要なケースは、すべてのデルタ値が負の場合です。 その状況では、考えられるすべてのパスには、群衆が時刻 0 でカルロスよりも厳密に早く到着するノードが少なくとも 1 つ含まれます。 伝播フェーズは best[N] を正しく負に保ち、最終的なゼロへのクランプはプラスの利点が存在しないことを反映しているため、より早く開始すると有効なパスを作成できません。
