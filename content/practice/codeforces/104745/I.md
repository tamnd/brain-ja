 ## 解決策
 ## 問題の理解

 私たちは、強盗が左上のセルから右下のセルに移動しようとするグリッドで作業しています。 グリッドのサイズは静的ですが、一部のセルにカメラが配置されているため動的に危険です。 各カメラは、現在の向きに応じて行全体または列全体を観察し、この向きは毎秒反時計回りに 90 度回転します。 つまり、すべてのカメラの方向が 4 ステップのサイクルで変化するため、危険なセルのセットも時間の経過とともに変化します。 

強盗は時刻 0 にセル (1, 1) から開始し、(n, n) に到達したいと考えています。 毎秒、強盗はその場に留まるか、4 つの基本的な方向に 1 歩移動することができます。 移動はカメラの回転と同時に行われ、所定のタイム ステップで強盗がセルを占有した瞬間に安全性が判断されます。 そのステップでカメラが回転した後、移動先のセルがどのカメラにも覆われていない場合、移動は有効です。 

課題は、強盗がその時点でカメラが映っているセル内にいないでも目的地に到達できる一連の移動と待機アクションが存在するかどうかを判断することです。 

グリッドは 1000 x 1000 までの大きさにすることができ、テスト ケースごとに最大 100 台のカメラを使用でき、テスト全体で合計 n の合計は 1000 までになります。これは、時間次元は原則として制限がなく、時間の経過とともに切り詰められた BFS でさえすぐにコストが高くなるため、単純に実行すると (行、列、時間) にわたる全時間展開の最短パスが大きすぎることを強く示唆しています。 

重要なエッジケースは、動きと回転のタイミングの間の相互作用から生じます。 セルは時間 t では安全ではないが、時間 t+1 では安全である可能性があり、回転後に安全になった場合、強盗はそのセルに移動することが許可されます。 たとえば、最初は右を向いていたカメラは、時間 0 ではセルを脅かさない可能性がありますが、回転後の時間 1 ではセルを脅かす可能性があるため、セルの単純な静的ブロックは正しくありません。 

もう 1 つの微妙なケースは、強盗が待ち構えている場合です。 独房内にとどまることは、すべての出口を同時にブロックしてしまうカメラのビームの掃引を避けるために最適な場合があります。 これにより、貪欲な最短幾何学的パスが無効になります。 

最後に、カメラはグリッド内の光線全体をカバーするため、1 台のカメラで長く連続したセグメントを無効にすることができ、推論ではローカル セルの障害ではなく行方向および列方向のグローバルな効果を考慮する必要があります。 

## アプローチ

 直接的なアプローチは、状態 (r、c、t) にわたるグラフとして状況をモデル化することです。カメラの方向は 4 ステップごとに繰り返されるため、t は 4 を法とする時間です。 各状態は最大 5 つの次の状態 (4 つの移動と待機) に接続します。 状態は、時刻 t においてセル (r, c) がどのカメラにもカバーされていない場合にのみ有効です。 

このアプローチは、すべてのダイナミクスを明示的にエンコードするため正しいですが、サイズが大きくなる可能性があります。 グリッドには最大 10^6 のセルがあり、時間レイヤーが 4 つしかない場合でも、約 400 万の状態になります。 各遷移ではカバレッジをチェックします。これには、カメラをスキャンするか、時間層ごとの影響を事前計算する必要があります。 状態ごとの単純なチェックでは最大 4 * 10^6 * 100 の操作が必要になり、これでは遅すぎます。 

重要な観察は、カメラが恣意的なブロッキング パターンを作成しないということです。 各カメラは、ブロックされた行と列の決定的な周期的なセットを定義します。 どのセルでも、その時間の経過に伴う安全性は、その時点でその行または列にあるカメラがそのセルに向いているかどうかによってのみ決まります。 方向サイクルは固定されており短いため、カメラごとに、4 つの各時相でどのライン (行セグメントまたは列セグメント) がブロックされているかを事前計算できます。 

これにより、問題は 4 層のグラフ上の最短経路に変換されますが、事前に計算された動的障害物が含まれます。 すべての動きのコストが等しいため、モデリングに応じて BFS または 0-1 BFS を実行します。 状態空間は最大 4n^2 ですが、n は全体的に十分小さいため、制約の下では許容されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | オンデマンド チェックを備えた時間拡張 BFS | O(4 n^2 m) | O(n^2) | 遅すぎる |
 | ブロックされたセル ルックアップを備えた事前計算された 4 層 BFS | O(4 n^2 + m) | O(n^2 + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 カメラの方向が 4 秒ごとに繰り返されるという事実を利用するため、すべてのセルを 4 つの時間状態で分析するだけで済みます。 

### 1. 時相ごとのカメラの影響を事前計算する

 各カメラは 4 つの方向を循環します。 各初期方向を時間 t モジュロ 4 での方向にマッピングします。カメラごとに、その行または列のどのセルが各フェーズでブロックされているかをマークします。 レイ全体を繰り返しマークするのではなく、各行と列に対して、時相ごとの各方向の最も近いブロックの影響を保存します。 

このステップでは、動的視線を一定時間内に「時刻 t にこのセルが見えるかどうか」を答えることができる構造に変換します。 

### 2. 状態空間を (行、列、時間 mod 4) として定義します。 

グリッド内の各セルは、時相に応じて 4 つのバージョンがあるものとして扱います。 セルがそのフェーズでカバーされていない場合、状態は有効です。 

この削減が有効なのは、カメラの動作が期間 4 で周期的であるため、将来の時間はこれら 4 つの構成のいずれかにマッピングされるためです。 

### 3. (1, 1, 0) から BFS を実行します。 

時間 0 から開始します。開始セルが時間 0 の時点ですでに安全でない場合、答えは即座に不可能になります。 

次に、有効な状態に対して BFS を実行します。 各状態から、上、下、左、右に移動、または滞在という 5 つの遷移を試みます。 各遷移では時間を 4 を法として 1 つ進めます。 

移動は、次のタイムフェーズで宛先セルが安全な場合にのみ許可されます。 

### 4. 訪問した州を追跡する

 サイズ n × n × 4 の訪問済み配列を維持します。これにより、等価な構成を再訪することがなくなり、状態空間の線形探索が保証されます。 

### 5. (n、n、いつでも) に達したら停止します

 安全な時間相で目的のセルに到達した場合は、YES を返します。 

### なぜ効果があるのか

 不変条件は、BFS が各タイムフェーズでの正確な安全制約を尊重しながら、ステップ数を増やしながら到達可能なすべての構成を探索するということです。 このシステムは周期 4 で周期的であるため、グリッドの考えられる将来の状態はすべてこれらの 4 つのレイヤーで表されます。 BFS は、無限の時間拡張グラフに有効なパスが存在する場合、この有限層グラフへのその投影にも到達可能であることを保証します。 すべての遷移では時間発展の正確性と安全性チェックが維持されるため、無効なパスが追加されることはなく、有効なパスがスキップされることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

DIRS = [(-1,0),(1,0),(0,-1),(0,1),(0,0)]

def solve():
    n, m = map(int, input().split())
    
    # blocked[t][r][c] would be too big explicitly,
    # so we store per row/col influence per phase
    
    row_block = [[[False]*n for _ in range(n)] for _ in range(4)]
    col_block = [[[False]*n for _ in range(n)] for _ in range(4)]
    
    cams = []
    for _ in range(m):
        r, c, d = input().split()
        r = int(r)-1
        c = int(c)-1
        cams.append((r,c,d))
    
    def dir_at(d, t):
        # anticlockwise rotation cycle: U->L->D->R->U
        order = ['U','L','D','R']
        i = order.index(d)
        return order[(i+t)%4]
    
    # mark influence naively (simplified representation)
    # for correctness explanation, assume O(n^2 m) marking
    for t in range(4):
        for r,c,d in cams:
            dt = dir_at(d, t)
            if dt == 'U':
                for i in range(r+1):
                    row_block[t][i][c] = True
            elif dt == 'D':
                for i in range(r,n):
                    row_block[t][i][c] = True
            elif dt == 'L':
                for j in range(c+1):
                    col_block[t][r][j] = True
            else:
                for j in range(c,n):
                    col_block[t][r][j] = True
    
    def bad(r,c,t):
        return row_block[t][r][c] or col_block[t][r][c]
    
    if bad(0,0,0):
        print("NO")
        return
    
    vis = [[[False]*4 for _ in range(n)] for _ in range(n)]
    dq = deque([(0,0,0)])
    vis[0][0][0] = True
    
    while dq:
        r,c,t = dq.popleft()
        nt = (t+1)%4
        
        for dr,dc in DIRS:
            nr,nc = r+dr,c+dc
            if 0 <= nr < n and 0 <= nc < n:
                if not vis[nr][nc][nt] and not bad(nr,nc,nt):
                    vis[nr][nc][nt] = True
                    if nr == n-1 and nc == n-1:
                        print("YES")
                        return
                    dq.append((nr,nc,nt))
    
    print("NO")

if __name__ == "__main__":
    solve()
```この実装では、グリッドを 4 つの時間レイヤーに明示的に拡張します。 機能`dir_at`回転サイクルをモデル化し、すべてのカメラの方向が各時相で正しく計算されるようにします。 可視性の単純なマーキングでは、各カメラからの直接的なライン伝播を使用します。これは概念的には正しいですが、単純なグリッド スキャンを前提としています。 より最適化されたバージョンでは、これは、事前に計算された最近接障害物構造またはプレフィックスベースのスイープに置き換えられます。 

BFS は、時刻 t から t+1 に常に移行し、移動と回転の同時ルールに一致することで正確さを維持します。 宛先チェックは、不要な作業を避けるためにエンキュー時に行われます。 

微妙な点は、安全性が出発時ではなく到着時にチェックされるという点であり、これは、ローテーション後に安全になった場合、現在安全ではない独房に強盗が侵入する可能性があるという記述と一致します。

 ### 例 1

 入力:```
3 1
2 2 U
```(1,1) から始めます。 時間 0 では、(2,2) のカメラは上を向いており、列 2 から行 1 までをカバーしています。これは (1,1) には影響しません。 BFSが始まります。 

| ステップ | 状態 (r,c,t) | アクション | 次の状態 | 安全？ |
 | --- | --- | --- | --- | --- |
 | 1 | (1,1,0) | 右 | (1,2,1) | はい |
 | 2 | (1,2,1) | ダウン | (2,2,2) | いいえ |
 | 3 | (1,1,0) | ダウン | (2,1,1) | はい |

 カメラ スイープを完全に回避する有効なパスが存在するため、出力は YES になります。 

このトレースは、時間内に待機または再配線することで、一時的な列のブロックを回避できることを示しています。 

### 例 2

 入力:```
3 2
2 2 U
3 2 R
```ここでは複数のカメラが列 2 で交差し、繰り返しスイープを作成しています。 

| ステップ | 状態 | アクション | 次へ | 安全 |
 | --- | --- | --- | --- | --- |
 | 1 | (1,1,0) | 右 | (1,2,1) | はい |

 | 3 | (1,2,1) | 待って | (1,2,2) | いいえ |

 列 2 を通過しようとすると、交互の段階でブロックされ、廊下が事実上通行できなくなります。 

これは、静的な到達可能性がパスの存在を誤って示唆するため、時間次元が不可欠であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(4 n^2 + m n) | 4 層にわたる BFS とカメラ伝播 |
 | スペース | O(n^2 × 4 + m) | 訪れた州とカメラの保管場所 |

 ## 特殊なケース

 重要なエッジ ケースは、開始セルが時間 0 ですぐにカバーされる場合です。アルゴリズムは BFS が開始する前にこれをチェックするため、探索せずに NO を返します。 

もう 1 つのケースは、目的地が特定の段階でのみ安全である場合です。 (n,n,t) を任意の t に対して有効なものとして扱うため、BFS は、初期のフェーズでは安全でなくても、後のフェーズでそれに到達し、時間依存の到着を正しくキャプチャすることができます。 

最後の微妙なケースは、カメラが一時的にちょうど 1 歩分の廊下を開くように振動する場合です。 BFS レイヤー構造では、時間の進行が明示的かつ周期的であるため、この一時的な開口部が確実に探索されるため、アルゴリズムは特別なケースを使用せずにこれらの 1 ステップ ウィンドウを自然にキャプチャします。
