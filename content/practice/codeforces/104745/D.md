 ## 解決策
 ## 問題の理解

 私たちは、ハビエルが保有するディスクの数を時間の経過とともに増加させる、非常に単純な製造プロセスをシミュレートしています。 彼は一枚のディスクから始めます。 彼は毎分何枚かのディスクを選択し、それらをマシンに入れます。1 分後にマシンはその 2 倍の数のディスクをプールに戻します。 彼が使用しないディスクは利用可能なままであるため、システムは在庫が増加しているかのように動作します。 

正式には、i 分前の彼の現在の在庫が c で、x 枚のディスクを選択した場合、x が利用可能でなければならず、その分後の彼の在庫は c - x + 2x になり、c + x と単純化されます。 選択した金額は事実上、現在の株式に追加される増分ですが、x ≤ c によって制約されます。 

m 分後、在庫はちょうど n になるはずです。 m を最小化し、m ステップで n に到達するすべての最適な方法の中で、辞書編集的に最小の選択された値 x₁、x₂、…、xₘ のシーケンスを出力するように求められます。 

n ≤ 10^9 という制約は十分に大きいため、O(n) シミュレーションは不可能です。 最適に使用するとプロセスが指数関数的に速く成長するため、どのようなソリューションでも問題を対数的または貪欲なものに減らす必要があります。 

いくつかのエッジの状況を切り分ける価値があります。 

n = 2 の場合、プロセスは 1 ステップで 1 から 2 に進む必要があるため、x₁ = 1 が強制されます。 

n が大きくても 2 の累乗に近い場合、正確な到達可能性を慎重に確保しない限り、常に 2 倍になる単純な貪欲ではオーバーシュートまたはアンダーシュートする可能性があります。 

重要な微妙な点は、m を最小化するために急速な成長を望む一方で、すべての x が相加的に寄与し、x ≤ 現在のストックという制約の下で実行可能でなければならないため、最終的な合計を正確に制御する必要があることです。 

## アプローチ

 ブルートフォース戦略では、x の考えられるすべての選択肢を毎分シミュレートします。 ステップ i では、現在のストック c を使用して、1 から c までのすべての x を試し、結果として得られるすべての状態を再帰的に探索できます。 これは大きく分岐します。状態の数は、m ステップにわたっておおよそ c × c × c のように増加し、n が小さい場合でも天文学的に大きくなります。 その理由は、状態空間が縮小しておらず、それぞれの選択が別の完全な選択肢を生み出すためです。 

プロセスの構造は、より強力なパターンを示唆しています。 各操作では現在のストックに x が追加されるため、ステップ数を減らす最善の方法は、各段階で x をできるだけ大きくすることです。 制約 x ≤ c は、考えられる最大の成長が x = c であり、在庫が 2 倍になることを意味します。 これは、ストックが毎分 2 倍以上の速度で成長することはできないことを直ちに意味します。そのため、1 から n に到達するには、少なくとも約 log₂ n ステップが必要です。 

これにより、m の下限が決まります。 より難しいのは、この限界を単に超えるだけでなく、n に到達しながらもこの限界が正確に達成可能であることを示すことです。 解決策は、プロセスを逆方向に構築することです。 x の将来を決定する代わりに、各ステップの後に株価がどのくらいになるべきかを決定し、株価が 2 倍を超える速度で増加しないようにし、差から x を回復します。 

この逆方向の構築により、一意の最小長の状態シーケンスが生成され、それらの状態から辞書編集上の最小の一連の移動が決定論的に続きます。

 ## アルゴリズムのチュートリアル

1. m 分後の最終必要在庫 n から開始します。 m はまだわかりませんが、プロセスが 2 倍より速く成長することはできないことがわかっているため、逆遷移を繰り返し適用します。つまり、前のストックは次のストックの少なくとも半分でなければなりません。 
2. cₘ = n を定義し、cᵢ₋₁ = ceil(cᵢ / 2) を計算します。 これにより、1 回の有効な移動で cᵢ に到達できる最小の以前の状態が得られます。 cᵢ は最大でも cᵢ₋₁ の 2 倍でなければならないため、天井が表示されます。 
3. c₀ = 1 に達するまでステップ 2 を繰り返します。実行される逆ステップの数は最小 m です。 
4. すべての状態 c₀、c₁、…、cₘ がわかったら、次の演算を計算します。 各 i について、xᵢ = cᵢ − cᵢ₋₁ を設定します。 これはまさにその分間に追加された量です。 
5. m とシーケンス x₁、…、xₘ を出力します。 

再構成が機能する理由は、前進する各ステップが自動的に制約を満たしているためです。構築により cᵢ ≤ 2cᵢ₋₁ であるため、常に xᵢ = cᵢ − cᵢ₋₁ ≤ cᵢ₋₁ となり、実現可能性が保証されます。 

辞書編集上の最小条件は、逆方向の構築によって強制されます。各ステップで可能な限り最小の前の状態を選択すると、最小限の時間で完了できると同時に、初期の増分が可能な限り小さくなります。 初期の xᵢ を減らそうとすると、後の状態が許容よりも速く成長し、m が増加することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

states = [n]

# build states backward until reaching 1
while states[-1] > 1:
    c = states[-1]
    prev = (c + 1) // 2
    states.append(prev)

states.reverse()

m = len(states) - 1
print(m)

res = []
for i in range(1, len(states)):
    res.append(states[i] - states[i - 1])

print(*res)
```このソリューションでは、まず、可能な限り厳密な先行ルールを使用して、到達可能な株価のシーケンスを逆方向に構築します。 式 (c + 1) // 2 は ceil(c / 2) の整数形式であり、前の値を 2 倍しても c を下回らないことが保証されます。 

反転後、リストは、各ステップが前のストックの最大 2 倍であるという制約の下で、1 から n までの一意の最小長の軌道を表します。 連続する状態間の差異により、実際の x 値が得られます。 

よくある落とし穴は、x を順方向で直接決定しようとすることです。 このアプローチは失敗します。ローカルでの貪欲な選択ではグローバルな実現可能性が維持されないためです。 逆方向の構築により、最初にグローバルに実現可能性が強制されます。 

## 実用的な例

 ### 例 1: n = 8

 後方構築:

 | ステップ | c (ターゲット) | 前 = ceil(c/2) |
 | --- | --- | --- |
 | 4 | 8 | 4 |
 | 3 | 4 | 2 |
 | 2 | 2 | 1 |

 したがって、状態は [1、2、4、8] になります。 

前方再構築:

 | 私 | ₋₁ | | xᵢ |
 | --- | --- | --- | --- |
 | 1 | 1 | 2 | 1 |
 | 2 | 2 | 4 | 2 |
 | 3 | 4 | 8 | 4 |

 出力は1・2・4の3段階です。 

これにより、各ステップでプロセスが 2 倍になり、可能な限り最小限の時間が達成されることが確認されます。 

### 例 2: n = 10

 後方構築:

 10→5→3→2→1

 状態: [1、2、3、5、10]

 x 値を転送します。 

| 私 | ₋₁ | | xᵢ |
 | --- | --- | --- | --- |
 | 1 | 1 | 2 | 1 |
 | 2 | 2 | 3 | 1 |
 | 3 | 3 | 5 | 2 |
 | 4 | 5 | 10 | 5 |

 これは、n が 2 のべき乗ではない場合、プロセスは自然に、実行可能性を維持するために早い段階で小さな増分を導入し、その後も可能な限り積極的な状態を維持することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(log n) | 各ステップでは、逆の構成で値が少なくとも半分減少します。 
| スペース | O(log n) | 1 から n までの状態のシーケンスを格納します。 

n ≤ 10^9 は最大約 30 個の状態を意味するため、このアルゴリズムは容易に制限内に収まります。

 ## 特殊なケース

 n = 2 の場合、逆方向プロセスは 2 → 1 を即座に生成し、m = 1 および x₁ = 1 を与えます。ceil(2/2) = 1 はすぐに終了するため、アルゴリズムがこれを処理します。 

2 のべき乗の場合、すべての逆半分は正確なままであり、きれいな double のチェーンが生成されます。 四捨五入がないため、シーケンスは厳密な等比数列になります。 

奇数の値の場合、上限演算により、現在の値に到達するには小さすぎる前の状態が選択されることがなくなります。 たとえば、2·2 = 4 では不十分ですが、2·3 = 6 は有効であるため、5 から 3 に進みます。 

これらの各ケースは、不変条件 cᵢ ≤ 2cᵢ₋₁ がすべてのステップで維持されることを示しており、これが構築の中心的な実現可能条件です。
