 ## 解決策
 ## 問題の理解

 私たちには一連の銀行小切手が与えられており、それぞれが固定の金銭的価値を持っています。 このシーケンスから、最大でも選択できるのは、`k`私たちの目標は、選択された小切手の合計価値を最大化することです。 受け取ることができる数の制限以外に、どの小切手を選択するかについて制限はありません。 

入力では次の 2 つのことが説明されます: 利用可能なチェックの数`n`、および最大数`k`それは償還できるのです。 次に、次の配列が続きます`n`各チェックの値を表す整数。 出力は単一の数値であり、以下を選択して取得できる最大の合計です。`k`配列からの要素。 

制約`n ≤ 10^4`つまり、すべてのサブセットのチェックや組み合わせのシミュレーションなどの 2 次解法でも時間がかかりすぎるということです。 アン`O(n^2)`このアプローチにはすでに約 10^8 の操作のリスクがあり、これは Python の厳密な 1 秒制限の境界線です。 指数関数的なものはすぐには不可能です。 

問題の構造には順序付けの要件が隠されていません。 連続する小切手を選択したり、スタックの順序を保持したりする必要はありません。 最大サイズのサブセット`k`は有効であり、問​​題を純粋な選択タスクに単純化します。 

主なエッジケースは、「最大 k 回のチェック」というフレーズを理解することで得られます。 たとえば、次の場合`k = n`、すべての要素を取得する必要があります。 もし`k = 1`、単一の最大値を選択するだけです。 

次のシナリオを考慮してください。 

入力:```
5 1
3 10 2 8 7
```出力：```
10
```素朴なアプローチでは組み合わせを試すかもしれませんが、正解は最大の要素にすぎません。 

入力：```
4 4
1 2 3 4
```出力：```
10
```ここでは、制限によりすべての要素が許可されるため、すべてを取得する必要があります。 

間違ったアプローチは通常、選択が位置または順序によって制約されているかどうかの誤解から生じます。 この問題では、純粋に組み合わせの問題です。 

## アプローチ

 ブルートフォース解釈では、最大でもすべてのサブセットが試行されます。`k`要素を抽出し、その合計を計算し、最良の結果を追跡します。 これはタスクの定義に直接一致するため正しいですが、サブセットの数は膨大です。 厳密に制限しても`k`要素が与える$\binom{n}{k}$、成長が早すぎて一度に列挙することはできません`n`数十にも達します。 

重要な点は、要素の順序は無関係であるということです。 選択されたサブセットの合計は、その位置ではなく、どの値が含まれるかによってのみ決まります。 これにより、最大のものを選択する作業が軽減されます。`k`配列からの値。 最適なソリューションには最大の要素が含まれている必要があります。選択した小さい要素を未使用の大きい要素に置き換えると、常に合計が改善または維持されるためです。 

これにより、問題は古典的な選択問題に変換されます。つまり、配列を並べ替えて先頭を取得します。`k`値を追跡する実行構造を維持するか、`k`最大の要素。 

並べ替えは最も単純かつ直接的なアプローチです。 降順に並べ替えると、答えは最初の値の合計になります。`k`要素。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 上位 k | 並べ替え O(n log n) | O(1) または O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題は、最大値のみが最適な選択に寄与するという事実に焦点を当てて解決します。 

1.読む`n`そして`k`、チェック値のリストを読みます。 これにより、選択できる候補者の完全なプールが決まります。 
2. 最大の値が最初に表示されるように、リストを降順に並べ替えます。 このステップにより、最良の候補者が最前面に配置されるため、選択が簡単になります。 
3. 最初のものを取る`k`ソートされたリストからの要素。 これらは、利用可能な最大値に対応します。 
4. これらの合計を計算します`k`要素を抽出して答えとして出力します。 

各ステップにより問題の複雑さが軽減されます。サブセットについて推論する代わりに、ソート後に決定的な順序付けとスライスに集約されます。 

### なぜ効果があるのか

 正しさは単純な交換議論から得られます。 最適な選択には何らかの要素が含まれているとします`a`より大きな要素を除外しながら`b`選択の中にありません。 交換中`a`と`b`最大でも選択するという制約に違反することなく合計を増加させます。`k`要素。 この置換プロセスを繰り返すことで、最適なソリューションを、正確に構成されたソリューションに確実に変換できます。`k`最大値。 したがって、上部を選択すると、`k`ソート後は常に最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))
    arr.sort(reverse=True)
    print(sum(arr[:k]))

if __name__ == "__main__":
    solve()
```Python のデフォルトの入力は大規模な配列に対して低速になる可能性があるため、ソリューションは高速 I/O を使用して入力を読み取ります。 並べ替えステップでは、大きい値が最初に配置されます。 スライス`arr[:k]`許可されたチェックの数を正確に抽出し、それらを合計すると最適な合計が得られます。 

微妙な詳細により、誤って以下のものを含めないようにすることができます。`k`要素。 スライスは境界を排し、次の場合でも安全です。`k = n`、これにより、エッジケースの処理が完全に回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    arr = list(map(int, input().split()))
    arr.sort(reverse=True)
    return str(sum(arr[:k]))

# provided sample
assert run("3 2\n11 5 10\n") == "21"

# minimum n
assert run("1 1\n7\n") == "7"

# k = n
assert run("4 4\n1 2 3 4\n") == "10"

# all equal
assert run("5 3\n5 5 5 5 5\n") == "15"

# mixed values
assert run("6 2\n-1 10 3 7 2 8\n") == "18"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1/7 | 7 | 最小サイズのケース |
 | 4 4 / 1 2 3 4 | 10 | すべての要素を選択する |
 | 5 3 / すべての 5 | 15 | 均一な値 |
 | 混合配列 | 18 | 正しい貪欲な選択 |
