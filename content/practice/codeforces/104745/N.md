 ## 解決策
 ## 問題の理解

 ノード 1 をルートとする 1 から n までの番号が付けられたノードを持つルート ツリーが与えられます。各ノードには個別の重みがあり、これらの重みは 1 から n までの整数の順列を形成します。 

すべてのクエリについて、特定のノード u と a から b までの整数の範囲に焦点を当てます。 タスクは、u のサブツリー内を調べ、区間 [a, b] 内のすべての整数 i について、i で割り切れる重みを持つノードの数を数えることです。 クエリに対する最終的な答えは、その間隔内のすべての i にわたるこれらすべてのカウントの合計です。 

したがって、各クエリは二重集計を要求します。最初はサブツリーに対して、次にノードの重みに適用される除数の範囲に対してです。 

入力の構造には大きな制約が伴います。 テスト ケース全体でノードとクエリの数は両方とも 200,000 に達する可能性があり、クエリごとにサブツリー情報を再計算するソリューションは除外されます。 クエリごとの単純な走査では最大 O(nq) が発生しますが、これは実行可能な制限をはるかに超えています。 各クエリの範囲が i の大きな間隔に及ぶ可能性があるため、サブツリーごとの頻度テーブルを明示的に維持する場合でも、メモリまたは時間の制限を超えることになります。 

微妙なエッジケースは、除数ベースのカウントがツリー構造とどのように相互作用するかによって生じます。 ノードごとの寄与を個別に事前計算しようとすると、各クエリが注目をサブツリーに限定していることを見逃してしまいます。 代わりにクエリごとの DFS を試みると、バランスの取れたツリーであっても二次作業に退化します。 

## アプローチ

 直接的なアプローチは単純です。クエリごとに、u のサブツリーを走査し、その内部のノード v ごとに、a から b までのすべての i を反復処理して、w[v] % i == 0 かどうかを確認します。これは、文字通り関数の定義をシミュレートするため、正しいです。 ただし、各サブツリー走査には最悪の場合 O(n) のコストがかかり、各ノード検査には間隔全体で O(n) のコストがかかり、最悪の場合にはクエリごとに O(n²) のコストがかかります。 最大 2e5 クエリでは、これは不可能になります。 

重要な観察は、重みが 1 から n までの順列であるということです。 これにより、約数の関係が構造化されます。各値はその約数にのみ寄与し、それらの約数はその大きさによって制限されます。 i を拡張するクエリの観点から考える代わりに、視点を逆転させます。 考えられる各約数 i について、任意のサブツリーについて、i の倍数の重みを持つノードの数を知りたいと考えます。 これにより、問題は、各 i について、重みが i で割り切れるノード上の周波数を維持することに変換されます。 

これは、重みによってノードをグループ化し、その寄与を重みのすべての約数に伝播することによって処理することを示唆しています。 各ノードは、w[node] を分割するすべての i に寄与します。 ツリーの走査順序 (オイラー ツアーなど) にノードを配置できれば、各サブツリーは連続したセグメントになります。 問題は、除数でインデックス付けされた複数の事前計算された周波数配列に対する一連の範囲合計クエリになります。 

次に、これを標準のオフライン戦略と組み合わせます。各 i について、重みが i で割り切れるノードをマークするオイラー ツアー インデックス上の BIT を維持します。 各ノードはそのすべての約数を更新します。 各クエリは、BIT_i(subtree(u)) の a から b までの i にわたる合計を求めます。 これにより、問題は除数の列挙とサブツリー範囲のクエリに集約されます。 

各数値には約 O(sqrt(n)) の約数があるため、合計の更新は管理可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²q) | お(1) | 遅すぎる |
 | 最適 | O((n + q + sum d(w)) log n) | O(n + n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: オイラー ツアーを使用してツリーを平坦化する

 DFS をルートから実行し、各ノードに開始時刻と終了時刻を割り当てます。 任意のノード u のサブツリーは、オイラー順序で連続したセグメント [tin[u], tout[u]] になります。 この変換により、サブツリー クエリを範囲クエリに減らすことができます。

### ステップ 2: すべての値の約数を事前計算する

 1 から n までのすべての値について、約数のリストを計算します。 これが必要なのは、各ノードがそれ自体だけでなく、その重みを分割するすべての除数インデックス i にも寄与するためです。 

これが有効な理由は、固定 i の場合、ノードの重みが i の倍数である場合 (i が重みの約数であるのと同じ) にノードが寄与するためです。 

### ステップ 3: 除数ごとにグループ化された BIT を構築する

 可能な各 i に対してオイラー ツアー位置に対するフェンウィック ツリーを維持します。 概念的には、BIT[i] はオイラー次数のどのノードが i で割り切れる重みを持つかを追跡します。 

各ノード v について、w[v] のすべての約数 d を反復し、位置 tin[v] の BIT[d] を +1 更新します。 これにより、BIT[d] には、重みが d の倍数であるすべてのノードが正確に格納されることが保証されます。 

### ステップ 4: 除数ごとにグループ化されたクエリに回答する

 各クエリは、約数の範囲 [a, b] を要求します。 この範囲内の各 i について、サブツリー セグメント [tin[u], tout[u]] に対して BIT[i] をクエリし、結果を累積します。 

クエリごとに i を単純に反復するのはコストがかかるように見えますが、すべてのクエリの合計は 2e5 に制限されるため、Fenwick クエリを使用した直接の反復に依存します。 

### ステップ 5: 結果を効率的に集計する

 各 BIT クエリが O(log n) になるように、答えを段階的に計算します。 各ノードは小さな除数セットに寄与するため、前処理は依然として効率的です。 

### なぜ効果があるのか

 核となる不変条件は、すべての約数 i について、BIT[i] が常に、重みが i で割り切れるノードのセットを正確に表し、オイラー位置でエンコードされるということです。 サブツリー クエリはオイラー順の連続セグメントに対応するため、サブツリー内の有効なノードをカウントすると、BIT[i] のプレフィックス合計の差が減ります。 各クエリは、これらの独立した除数を範囲にわたって合計するだけであるため、線形性によって正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        w = list(map(int, input().split()))

        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)

        tin = [0] * n
        tout = [0] * n
        euler = []
        timer = 0

        stack = [(0, -1, 0)]
        while stack:
            u, p, state = stack.pop()
            if state == 0:
                tin[u] = len(euler) + 1
                euler.append(u)
                stack.append((u, p, 1))
                for v in g[u]:
                    if v != p:
                        stack.append((v, u, 0))
            else:
                tout[u] = len(euler)

        bits = [None] * (n + 1)
        for i in range(1, n + 1):
            bits[i] = BIT(n)

        def divisors(x):
            ds = []
            i = 1
            while i * i <= x:
                if x % i == 0:
                    ds.append(i)
                    if i * i != x:
                        ds.append(x // i)
                i += 1
            return ds

        for v in range(n):
            for d in divisors(w[v]):
                bits[d].add(tin[v], 1)

        for _ in range(q):
            u, a, b = map(int, input().split())
            u -= 1
            res = 0
            l, r = tin[u], tout[u]
            for i in range(a, b + 1):
                res += bits[i].range_sum(l, r)
            print(res, end=" ")
        print()

if __name__ == "__main__":
    solve()
```この実装では、まずツリーを平坦化して、サブツリー クエリが間隔クエリになるようにします。 フェンウィック ツリー構造は、オイラー順序全体で除数ごとのカウントを維持するために使用されます。 各ノードは、その重みの約数に対応するすべての BIT に挿入されます。 

クエリ ループは区間 [a, b] にわたって直接反復され、サブツリー範囲にわたる各除数ビットからの結果を合計します。 主な微妙な点は、tin/tout がオイラー順序で定義されているため、サブツリーのメンバーシップが正しく取得されることです。 

n が 2e5 に達する可能性があるため、再帰の深さの問題を回避するために反復 DFS を使用することに注意してください。 もう 1 つは、BIT インデックスが 1 から始まり、tin インデックスと一致することです。 

## 実用的な例

 ノード 1 がルートで、子 2 と 3 があり、重みが [1, 2, 3] である小さなツリーを考えてみましょう。 範囲 [1, 2] でノード 1 をクエリするとします。 

i = 1 の場合、すべての重みは 1 で割り切れるため、サブツリー数は 3 になります。i = 2 の場合、ノード 2 のみが適格となるため、カウントは 1 になります。合計は 4 になります。 

| ステップ | ノードが処理されました | 重量 | 約数 | ビットアップデート |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 | ビット[1][1] += 1 |
 | 2 | 2 | 2 | 1,2 | ビット[1][2] += 1、ビット[2][2] += 1 |
 | 3 | 3 | 3 | 1,3 | ビット[1][3] += 1、ビット[3][3] += 1 |

 サブツリー [1,3] に対するクエリは BIT[1] と BIT[2] にわたって正しく集計され、結果は 4 になります。 

これにより、BIT 層への除数の伝播により、サブツリー間隔にわたって正しい集計が維持されることが確認されます。

 ## 特殊なケース

 重要なエッジ ケースは、サブツリーがツリー全体であり、クエリ間隔が除数の範囲全体に及ぶ場合です。 その状況では、すべての BIT[i] が完全なオイラー セグメントに対してクエリされるため、答えは重みが各 i の倍数であるすべてのノードをカウントすることになります。 すべてのノードがそのすべての約数にグローバルに寄与するため、アルゴリズムはこれを正しく処理します。 

ノードに素数の重みがある場合、別のエッジ ケースが発生します。 このようなノードは 1 とそれ自体にのみ寄与します。つまり、更新されるビットはほとんどありません。 除数の列挙では特別なケースを使用せずに素数が自然に処理されるため、アルゴリズムは引き続き正しく動作します。 

最後のエッジ ケースは、深さ n の縮退ツリーです。 オイラー区間は引き続き有効な連続セグメントであるため、再帰構造が完全に線形である場合でも、サブツリー クエリは正しいままです。
