 ## アルゴリズムのチュートリアル

 私たちはこのプロセスを、順序付けられた一連の生徒を選択するものとして扱います。 正確に選択すると決めたとします。$k$学生たち。 学生を使用する場合$j$- 番目のピック (0 からインデックス付き)、その後に終了します$k-1$数日後、その学生が貢献します$a_i + j$。 これは、それぞれの選択が 1 日に対応しており、まだ選択されていない生徒がすべて一律に増加しているためです。 

これにより、明示的な時間シミュレーションが削除され、順序構造に置き換えられます。

### なぜ効果があるのか

 重要な不変条件は、有効な戦略は選択された生徒の順序に一意に対応し、その順序によって各生徒が受け取る増分数と総使用日数の両方が決定されるということです。 問題を「選択」としてエンコードすることで、$k$「アイテムを順番に並べ、増加するオフセットを割り当てます」と明示的に時間をシミュレートすることなく、すべての有効なタイムラインを保存します。すべての実際のプロセスは、正確に 1 つの DP 構築にマップされ、すべての DP 構築は有効なピック スケジュールに対応するため、ソリューションが失われたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))

        INF = 10**9
        ans = INF

        for k in range(1, n + 1):
            # dp[j][s]: using j picks, sum s achievable
            dp = [[False] * (x + 1) for _ in range(k + 1)]
            dp[0][0] = True

            for ai in a:
                for j in range(k - 1, -1, -1):
                    for s in range(x + 1):
                        if not dp[j][s]:
                            continue
                        val = s + ai + j
                        if val <= x:
                            dp[j + 1][val] = True

            if dp[k][x]:
                ans = min(ans, k - 1)

        print(ans if ans != INF else -1)

if __name__ == "__main__":
    solve()
```DP テーブルは候補者のピック数ごとに構築されます$k$。 重要な実装の詳細は反復です$j$現在の構成で各生徒が最大 1 回使用されるように、逆方向に設定します。 移行により追加されるのは、$ai + j$、 どこ$j$は、すでに選択されている生徒の数であり、日のオフセット効果をエンコードします。 

全部試してみます$k$、変換が成功しました$k$時間の中に$k-1$。 これは安全です。$k$学生の皆さん、最後のピックは当日に行われます$k-1$、そして以前のピックは自然に以前の日と一致します。
