 ## 解決策
 ## 問題の理解

 この問題では、指定された数の同値クラスを作成できる異なる演算シーケンスの数を数えるよう求められます。 から始めます`n`すべて同一であるとみなされる要素。 各操作では、要素の一部のサブセットが選択され、選択された要素が選択されていない要素から分離されます。 すべての操作の後でも、2 つの要素がすべての操作で常に同じ方法で扱われる場合、それらの要素は依然として正確に等価です。 タスクは、可能な数の最終同値クラスを次から出力することです。`1`に`n`、操作シーケンスの数が正確にその数のクラスを生成するかどうか。 これは、Codeforces Gym 106195 の「等価クラス」というタイトルの問題です。 

操作を表示する重要な方法は、各要素にバイナリ署名を割り当てることです。 すべての操作に対して、要素は`0`それが選択されたサブセットの外にあった場合、および`1`中にあったら。 後`k`操作では、すべての要素に長さのバイナリ文字列が含まれます。`k`。 2 つの要素は、それらの署名が等しい場合に正確に同等であるため、等価クラスの数は、使用される個別の署名の数になります。 

がある`2^k`可能な署名。 制約により許可されるのは、`n`到達する`10000`、だから、`O(n^2)`解決策は現実的ですが、状況に応じて何でも`2^k`直接は無理なので`k`と同じ大きさにすることができます`10^18`。 のみを使用する数式が必要です`n`そしてモジュラー演算。 

微妙な点は、クラスの数が以下を超えることはできないということです。`n`たとえ署名の可能性が多数あったとしても。 よくある間違いは、要素にラベルが付いていることを考慮せずに、クラスを選択する方法を数えることです。 たとえば、次の場合`n = 2`そして`k = 1`、可能な署名は 2 つあります。`0`そして`1`。 

入力の場合:```
2 1
```考えられる操作シーケンスは 4 つあります。 空のセットを選択すると、両方の要素に署名が与えられます`0`、フルセットを選択すると両方の署名が与えられます`1`、いずれかの単一要素サブセットを選択すると、2 つの異なる署名が得られます。 答えは次のとおりです。```
2
2
```最初の行は、1 つのクラスを作成する方法が 2 つあることを意味し、2 行目は、2 つのクラスを作成する方法が 2 つあることを意味します。 署名の可能なセットのみをカウントする不注意なアプローチでは、要素は区別可能なため、最初の値が間違ってしまう可能性があります。 

次の場合には、別のエッジケースが発生します。`k`巨大ですが、`n`小さいです。 例えば：```
3 1000000000000000000
```考えられる署名は天文学的にたくさんありますが、必要なのは下降階乗の最初のいくつかの値だけです`(2^k)(2^k-1)...`なぜなら、実際に使用できるのは最大 3 つの異なる署名だからです。 シグネチャを列挙しようとするアプローチはすぐに失敗します。 

## アプローチ

 強引なアイデアは、考えられるすべての最終署名を検討することです。 それぞれの`n`要素はいずれかを受け取ることができます`2^k`バイナリ文字列なので、`(2^k)^n`可能な割り当て。 すべての割り当てを生成し、個別の署名の数を数え、クラスの数に応じて答えを増やすことができます。 

これは正しいです。一連の操作は、要素ごとに 1 つの署名を選択することとまったく同じであるためです。 ただし、課題の数が多すぎて処理できません。 次のような中程度の値であっても、`n = 100`そして`k = 100`、検索スペースは、プログラムがアクセスできる範囲をはるかに超えています。 

有益な観察は、どの特定のシグネチャが使用されているかは気にせず、異なるシグネチャがいくつ出現するかだけを気にするということです。 最終的なクラス数が`i`。 まず、どれを選択する必要がありますか`i`署名が使用されます。 がある`C(2^k, i)`選択肢。 次に、を割り当てる必要があります`n`これらのラベル付き要素`i`すべての署名が少なくとも 1 回表示されるように署名を選択します。 

2 番目の部分は、からの on 関数の数です。`n`要素を`i`クラス。 この値は`i! * S(n, i)`、 どこ`S(n, i)`は第 2 種スターリング数です。 2 つの部分を乗算すると、次のようになります。```
C(2^k, i) * i! * S(n, i)
```これは次のように書き換えることができます。```
(2^k)(2^k - 1)...(2^k - i + 1) * S(n, i)
```最初の因子は下降階乗です。 までの値のみが必要なので、`i = n`、以上のものは決して必要ありません`10000`項なので、モジュロを直接計算できます`998244353`。 

スターリング数は漸化式で計算されます。```
S(n, i) = S(n - 1, i - 1) + i * S(n - 1, i)
```再帰は最後の要素を考慮することから生まれます。 それ自体で新しいクラスを形成するか、既存のクラスの 1 つに結合します。`i`クラス。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((2^k)^n) | O(n) | 遅すぎる |
 | 最適 | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. の値を計算します。`2^k`モジュロ`998244353`。 数式内のすべての乗算と減算は係数に基づいて行われるため、実際の値は必要ありません。 
2. すべてのスターリング数を計算する`S(n, i)`のために`1 <= i <= n`動的プログラミングを使用します。 繰り返しでは、行ごとに回答が作成されます。各行は、要素の接頭辞を指定された数の空でないグループに分割する方法の数を表します。 
3. 下降階乗値を構築します。 から始める`1`を繰り返し乗算します。`(2^k - i)`可能なクラス数ごとに。 後の値`i`掛け算は、選択および順序付けする方法の数を表します`i`さまざまな署名。 
4. 可能なすべてのクラス数について`i`、下降階乗に次の値を掛けます。`S(n, i)`。 これにより、正確に生成される操作シーケンスの数が得られます。`i`等価クラス。 

これが機能する理由は、すべての最終状態が要素の署名によって一意に表現されるためです。 まさに`i`署名が表示されると、使用された署名を順序付けできます。`P(2^k, i)`要素は次のように分割する必要があります。`i`これらの署名に割り当てられた空ではないグループ。 スターリング数はそれらのパーティションを正確にカウントするため、有効なシーケンスはすべて 1 回カウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())

    sig = pow(2, k, MOD)

    dp = [0] * (n + 1)
    dp[0] = 1

    for elements in range(1, n + 1):
        nxt = [0] * (n + 1)
        for groups in range(1, elements + 1):
            nxt[groups] = (dp[groups - 1] + groups * dp[groups]) % MOD
        dp = nxt

    ans = [0] * (n + 1)
    fall = 1
    for i in range(1, n + 1):
        fall = fall * ((sig - i + 1) % MOD) % MOD
        ans[i] = fall * dp[i] % MOD

    print("\n".join(map(str, ans[1:])))

if __name__ == "__main__":
    solve()
```コードの最初の部分は計算します`2^k`べき乗剰余演算を使用します。 これは、非常に大きな値を処理します。`k`可能な署名の実際の数を構築することはありません。 

動的プログラミング配列には、スターリング数の現在の行が格納されます。 新しい要素を追加する場合、その要素は、1 つシフトされた前の行で表される新しいクラスを作成するか、既存のクラスに結合して、使用可能なグループの数を乗算します。 

下降階乗は段階的に構築されます。 表現では、`sig - i + 1`なぜなら選んだ後だから`i - 1`署名、つまり、残された選択肢は非常に少なくなります。 すべての値を制限するために、乗算の前にモジュロ演算が適用されます。 

最後の乗算では、実際の署名の選択とラベル付けされた要素のそれらへの分配という 2 つの独立した選択肢が結合されます。

```可能な署名は次のとおりです`0`そして`1`。

 2 つの 1 クラス シーケンスは両方の要素を一緒に選択し、2 つの 2 クラス シーケンスは要素を分離します。 これにより、数式がラベル付き要素を正しくカウントしていることが確認されます。

4
36
24
```最後の行は、3 つの異なるシグネチャを選択し、それぞれに 1 つの要素を割り当てることを表します。 中央の行では、3 つのラベル付き要素を 2 つの空ではないグループに分割する 3 つの可能な方法を使用しています。

 ## 特殊なケース

 いつ`n = 1`、要素は 1 つだけであるため、考えられるすべての操作シーケンスで 1 つの等価クラスが残ります。 必要なスターリング値は次のとおりであるため、アルゴリズムはこれを処理します。`S(1,1)=1`、下降階乗には 1 つの項があります。 

いつ`k`は非常に大きく、可能な署名の数は膨大ですが、アルゴリズムに必要なのは`2^k mod 998244353`。 たとえば、`n = 3`そして`k = 10^18`、コードは署名自体を保存することはなく、必要な 3 つの階乗項のみを計算します。 

必要なクラスの数が利用可能なシグネチャの数より大きい場合、下降階乗は自動的に 0 になります。 これは、最終的には存在するよりも多くの個別のシグネチャを選択しようとするため、これらのクラス数の答えは正しく 0 になるために発生します。
