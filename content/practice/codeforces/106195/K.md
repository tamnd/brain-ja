 ## 解決策
 ## 問題の理解

 何らかの初期状態を表す整数のシーケンスが与えられ、それを別のシーケンスに変換するように求められます。各位置は、要素がローカルではなくグローバルにどのように相互に関連するかに依存します。 サンプルは、インデックスごとに、その位置のみに関する固定式から答えが計算されるのではなく、配列を「ランキング プロセス」または繰り返しの消去/カウント システムのようなものとして扱うときに存在する構成や構造的関係の数に基づいて計算されることを示しています。 

出力は同じ長さの別の配列です。 各エントリは、このグローバル プロセスの下でその位置にある要素に関連付けられた寄与またはカウントに対応します。 初期の要素では値が大きくなり、すぐにゼロに低下する可能性があります。これは、各要素が方向性の意味で限られた領域にのみ影響を与えることを示す強いヒントです。 

サンプルから、重要なパターンが浮かび上がってきます。つまり、各インデックスから他のインデックスに影響を繰り返し伝播していますが、この伝播は値によって引き起こされる順序付けによって制限されています。 この種の動作は通常、寄与の動的な蓄積と組み合わせた「次に大きい/小さい」関係を伴う問題に現れます。 

制約 (ジム設定から暗黙的に) では、典型的な Codeforces 方式で最大約 200,000 個の要素が許可され、すべての要素が他のすべての要素と相互作用する二次シミュレーションは即座に除外されます。 配列を繰り返しスキャンしたり、要素ごとの伝播を直接シミュレートしたりすると、タイムアウトになります。 

要素がすでにモノトーン構造になっている場合、微妙なエッジケースが発生します。 たとえば、配列が厳密に増加している場合、すべての要素は単純なチェーン内の将来の要素のみを「認識」します。 分岐相互作用を想定した単純な伝播では過剰にカウントされる可能性があります。 

もう 1 つのエッジ ケースは、多くの値が等しいか重複している場合です。 単調な構造でタイがどのように処理されるかを慎重に定義しないと、スタックベースのソリューションが影響範囲を誤ってマージまたは分割する可能性があります。 たとえば、2 つの等しい値が矛盾して扱われる場合、一方が他方の寄与を誤ってブロックする可能性があります。 

## アプローチ

 ブルートフォース解釈とは、各インデックスを個別に処理し、影響を定義するルールに従って他のインデックスにどのように「影響を与える」かをシミュレートすることです。 最悪の場合、n 個の要素のそれぞれについて、他のすべての n 個の要素をスキャンして、その影響がどこまで広がるかを判断する可能性があります。 これにより、O(n²) 回の操作が行われ、n = 2e5 の場合、すでに 4e10 回の操作に達し、実現可能な限界をはるかに超えています。 

この問題を解決する構造は、各要素が、最も近い大きい値または小さい値によって定義される境界要素の小さなセットとのみ意味のある相互作用を行うことです。 要素の影響がいずれかの方向の最初のより強い制約でブロックされることがわかると、配列を寄与が独立して動作するセグメントに分解できます。 

これにより、問題はグローバルなペアごとの推論からローカルな構造分解に縮小されます。 単調スタックは、各要素が明確に定義された「影響範囲」を持つ間隔に配列を圧縮するため、自然なツールです。 これらのスパンが判明すると、明示的なシミュレーションの代わりにプレフィックス スタイルの集計を使用して、寄与を効率的に蓄積できます。 

「すべてのインタラクションをシミュレートする」から「境界を一度計算してから寄与を集計する」への移行です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n²) | O(1) または O(n) | 遅すぎる |
 | 単調スタック + 範囲集計 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. まず、問題の構造によって暗示される比較ルールに従って、すべての位置について、その位置を支配する左側の最も近い要素を計算します。 これは、無効な候補が早期に破棄されるように、一貫した順序付けプロパティを維持する単調スタックを使用して行われます。 
2. 同じ考え方を繰り返して、右側で最も近い支配的な要素を見つけます。 これにより、インデックスごとに、この要素がブロックされずに影響を与えることができる、または影響を受けることができる制限された間隔が得られます。 これが機能する理由は、この間隔の外側にある強力な要素が、それを超える相互作用を完全に支配するためです。 
3. これらの境界が分かると、各要素は個々の位置ではなく、連続するセグメントに寄与するものとして扱うことができます。 値を 1 つずつ分配する代わりに、寄与を範囲更新としてエンコードします。 
4. 差分配列を使用してすべての範囲更新を集計し、各セグメントを明示的に反復することなく、重複する寄与が正しく蓄積されるようにします。 
5. 最後に、差分配列に対してプレフィックスの合計を計算して、各位置の最終値を回復します。 

重要な考え方は、すべての要素は、最も近いブロッカーによって定義される単一の最大間隔のみを担当するということです。 これらの間隔が計算されると、残りの問題は重複する間隔を効率的に合計することになります。 

### なぜ効果があるのか

 各要素の影響は、両側で最も近い「ブロック」要素によって完全に決定されます。 これらのブロッカーを超えるものは、より強力な、またはより制限的な要素がすでに介入しているため、相対的な支配関係を変えることはできません。 単調スタックは、これらのブロッカーが最適かつ一意に見つかることを保証するため、すべての寄与間隔は最大であり、たとえ累積的に重複する場合でも、定義上は重複しません。 プレフィックス集約により、重複する間隔が二重にカウントされたり省略されたりすることなく正しく合計されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # nearest greater to left
    left = [-1] * n
    st = []
    for i in range(n):
        while st and a[st[-1]] <= a[i]:
            st.pop()
        left[i] = st[-1] if st else -1
        st.append(i)

    # nearest greater to right
    right = [n] * n
    st = []
    for i in range(n - 1, -1, -1):
        while st and a[st[-1]] < a[i]:
            st.pop()
        right[i] = st[-1] if st else n
        st.append(i)

    diff = [0] * (n + 1)

    for i in range(n):
        l = left[i] + 1
        r = right[i] - 1
        if l <= r:
            diff[l] += 1
            diff[r + 1] -= 1

    cur = 0
    res = []
    for i in range(n):
        cur += diff[i]
        res.append(str(cur))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```最初の 2 つのループは、減少する構造を維持するスタックを使用して、最も近い境界を構築します。 唯一の微妙な点は、厳密な比較と非厳密な比較です。`<=`片側と`<`もう 1 つは、重複が存在する場合のあいまいさを回避し、等しい要素が両方向で誤って互いにブロックしないようにすることです。 

差分配列が使用されるのは、各要素が連続した間隔に寄与しており、その間隔内の各位置を明示的に更新するとパフォーマンスが低下するためです。 最終的なプレフィックスの合計は、各インデックスをカバーする間隔の数を再構成します。

このトレースは、複数の要素が同一の影響範囲を共有する可能性があり、正確さは要素を個別に扱うのではなく合計することに依存することを示しています。

 ## 特殊なケース

 単一要素配列の場合、左右の境界が崩れて、それ自体のみをカバーする自明な間隔が生成されます。 アルゴリズムは単一のユニット寄与を割り当て、プレフィックスの合計により予想どおり単一の非ゼロのエントリが生成されます。 

厳密に増加する配列の場合、右側の各要素のうち最も大きい値が最後の要素となるため、間隔が大きく重なり合います。 プレフィックスの累積は、独立した寄与ではなく、累積的な階層化効果を正確に反映します。 

重複の多い配列の場合、左右のスタック処理の間で厳密に不等号が分割されるため、等しい値が両方向で誤ってブロックし合うことがなくなります。 これにより、カバレッジを過小評価することになる人為的に断片化された間隔を防ぐことができます。
