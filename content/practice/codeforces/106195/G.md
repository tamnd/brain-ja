 ## 解決策
 ## 問題の理解

 整数配列と順列が与えられます。 順列は、互いに素なサイクルの集合を表します。つまり、すべてのインデックスが別のインデックスを指し、インデックス自体が指すことはありません。 操作ではインデックスが選択されます`x`そして両方の兆候を変える`a[x]`そして`a[p[x]]`。 

目標は、すべての操作を実行した後、順列によって接続されたすべてのペアが非負の和になるように、選択したインデックスのシーケンスを出力することです。 演算数は配列サイズの半分を超えることはできません。 

制約により、最大で`2 * 10^5`したがって、さまざまな操作セットを繰り返し試行したり、多くの可能性をシミュレートしたりするソリューションは不可能です。 各インデックスを一定の回数処理する必要があります。 順列構造は、関係のグラフが単なるサイクルの集合であることを意味するため、特に役立ちます。 

よくある間違いは、合計が負であるすべてのペアに演算を適用して修正してしまうことです。 操作が重複しているため、これは機能しません。 2 つの隣接するエッジを反転すると、同じ頂点が 2 回反転し、予期しない場所で効果がキャンセルされる可能性があります。 

たとえば、次のことを考えてみましょう。```
n = 3
a = [-5, 4, 4]
p = [2, 3, 1]
```サイクルは`1 -> 2 -> 3 -> 1`。 合計は`-1`、`8`、 そして`-1`。 不注意な解決法を行うと、最初と 3 番目のエッジが負であるために反転する可能性があります。 頂点`1`2 回反転されて元の符号に戻りますが、頂点は`2`そして`3`一度ひっくり返されます。 最終状態は必ずしもすべてのエッジを満たしているわけではありません。 

もう 1 つの重要なケースは、サイクルに奇数の負の値が含まれる場合です。 すべての負の値を単純に反転すると、そのサイクルに奇数の操作が残りますが、すべての操作が 2 つの頂点を反転するため、エッジを選択することで直接表すことはできません。 

例えば：```
n = 3
a = [-1, 10, 10]
p = [2, 3, 1]
```正しい出力は次のようになります。```
1
1
```反転インデックス`1`配列を次のように変更します`[1, 10, 10]`、すべてのサイクルエッジを有効にします。 パリティを考慮せずにすべての値を非負にすることに固執するソリューションでは、演算を構築できない可能性があります。 

## アプローチ

 ブルートフォースアプローチは、可能な一連の操作を調べることです。 すべてのサイクルにはエッジの多くのサブセットが含まれる可能性があるため、これは指数関数的に増加します。 長さ 20 のサイクルでも、すでに 100 万を超えるエッジ選択が可能です。 この総当たりの考え方は、考えられるすべての最終構成をチェックするため正しいですが、大量の入力を処理することはできません。 

重要な点は、最初に演算について考えるのをやめて、配列値の最終的な符号について考えることです。 すべての値が負でなくなると、必要なすべての合計が自動的に有効になります。 唯一の制限は、操作では常に 2 つの頂点が反転されるため、符号が変更される頂点のセットは各サイクル内で均一なサイズでなければならないことです。 

各サイクルで、すべての負の値をマークすることから始めます。 マークされた頂点の数が偶数であれば、これはすでに反転する有効な頂点のセットです。 奇数の場合は、そのサイクルで最小の絶対値を持つ追加の頂点を 1 つ反転します。 この変更後、おそらく選択された 1 つの値を除いて、すべての値は非負になります。 絶対値が最小であるため、隣接する値も少なくとも同じ大きさになるため、2 つの隣接する合計は負でないままになります。 

残りのタスクは、反転する目的の頂点セットを実際のエッジ操作に変換することです。 サイクル上で、エッジを選択するか選択しない場合、2 つの入射エッジのうちの 1 つが正確​​に選択されると、各頂点が反転されます。 これにより、単純な XOR 関係が形成されます。 サイクルを歩き回ることで、有効なエッジ セットを 1 つ見つけることができます。 すべてのエッジを反転すると、すべての頂点の両方の入射エッジが変更され、相殺されるため、有効なエッジ セットの補数も有効です。 2 つのセットのうち小さい方を選択し、サイクル エッジの最大半分を保証します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列を独立したサイクルに分解します。 2 つの異なるサイクルを接続する操作はないため、各サイクルは個別に解決できます。 
2. サイクルごとに、現在の値が負である頂点を収集します。 これらは、値を正にするために反転する必要がある頂点です。 
3. サイクル内の負の頂点の数が奇数の場合、絶対値が最小の頂点を見つけて反転セットに追加します。 これにより、追加の値が 1 つだけ変更されます。 隣接する絶対値が小さくないため、この頂点に接する 2 つのエッジは有効なままになります。 
4. 選択した頂点反転セットをエッジ操作に変換します。 サイクルを順番に実行し、連続する頂点間の XOR 遷移を使用して各サイクル エッジを選択するかどうかを割り当てます。 
5. 選択したエッジをカウントします。 すべてのサイクル エッジの相補セットは同じ頂点反転を与えるため、現在のセットにサイクル エッジの半分以上が含まれている場合は、そのセットをその補セットに置き換えます。 
6. 選択したエッジの代表を回答に追加します。 サイクルからエッジを選択するということは、その置換エッジがそのサイクル エッジを表すインデックスを出力することを意味します。 

なぜ効果があるのか:

 このアルゴリズムは、選択された操作が構築された反転セット内の頂点を正確に反転するという不変条件を維持します。 すべてのサイクルは、すべての値が負でないか、または 1 つの最小絶対値が負で終了し、両方の隣接値が少なくとも同じ大きさになります。 したがって、順列によって接続されたすべてのペアの合計は負ではありません。 隣接する選択されたエッジが 1 つ存在する場合に頂点が正確に反転されるため、エッジ変換は正確です。これはまさに構築中に使用される xor 条件です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    p = [x - 1 for x in map(int, input().split())]

    visited = [False] * n
    answer = []

    for start in range(n):
        if visited[start]:
            continue

        cycle = []
        cur = start
        while not visited[cur]:
            visited[cur] = True
            cycle.append(cur)
            cur = p[cur]

        m = len(cycle)
        flip = [False] * m

        cnt = 0
        for i, v in enumerate(cycle):
            if a[v] < 0:
                flip[i] = True
                cnt += 1

        if cnt % 2 == 1:
            pos = 0
            for i in range(1, m):
                if abs(a[cycle[i]]) < abs(a[cycle[pos]]):
                    pos = i
            flip[pos] = not flip[pos]

        edges = []
        state = False
        edge = [False] * m

        for i in range(m):
            if flip[i]:
                state = not state
            edge[i] = state

        if sum(edge) > m - sum(edge):
            edge = [not x for x in edge]

        for i, take in enumerate(edge):
            if take:
                edges.append(cycle[i])

        answer.extend(edges)

    print(len(answer))
    if answer:
        print(*[x + 1 for x in answer])

if __name__ == "__main__":
    solve()
```最初の部分は配列を読み取り、順列をゼロベースのインデックスに変換します。 次に、順列を 1 回だけ走査してサイクルを抽出します。 

各サイクル内では、`flip`符号を変更する頂点を表します。 パリティ補正は、必要に応じて最小の絶対値の頂点を追加します。 これは、最終的な配列に負の値が含まれる唯一のケースであり、最小の大きさを選択することで隣接する合計が保持されます。 

の`edge`配列は演算表現です。 変数`state`サイクルを実行している間、xor プレフィックスを保存します。 現在の xor 値が次の遷移が必要であると示すたびに、エッジが選択されます。 補数が小さい場合にその補数を取得することにより、操作の制限が適用されます。 

出力にはサイクル エッジ インデックスが格納されます。 サイクルからエッジが選択された場合、その開始頂点を操作引数として使用すると、必要なペアが正確に反転されます。

| ステップ | 現在のサイクル状態 | アクション |

 ## 特殊なケース

 すべてのペアの合計がすでに非負である場合、アルゴリズムは演算を出力しない可能性があります。 例えば：```
2
5 5
2 1
```サイクルには負の値が含まれていないため、フリップ セットは空で、出力はゼロ演算になります。 

負の値が奇数個あるサイクルの場合:```
3
-1 10 10
2 3 1
```負のセットには最初の頂点のみが含まれます。 このアルゴリズムは、すでに最初の頂点である最小の絶対値の頂点を追加し、2 番目の負の値の必要性を取り除きます。 生成された操作はその頂点を反転し、値を生成します`[1,10,10]`。 

多くの頂点が負であるサイクルの場合、アルゴリズムは負の値ごとに 1 つの演算を直接出力しません。 まず、目的の頂点反転をエッジの選択肢に変換し、次に 2 つの同等のエッジ セットのうち小さい方を選択します。 これにより、操作の合計数が必要な制限内に保たれます。
