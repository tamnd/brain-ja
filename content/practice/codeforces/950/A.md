 ## 解決策
 ## 問題の理解

 トレーニングセッションでは、左手だけが使える人、右手だけが使える人、どちらかの手に割り当てられる両利きのプレーヤーの 3 つのグループに分けられます。 コーチは、チームのちょうど半分が左手でプレーし、残りの半分が右手でプレーするような、均等な規模のチームを構築したいと考えています。 

各左利きのプレーヤーは左側にのみ貢献でき、各右利きのプレーヤーは右側にのみ貢献でき、両利きの各プレーヤーはチームのバランスに応じてどちらかのサイドに割り当てることができます。 

課題は、そのようなバランスの取れたチームのプレーヤーの総数を最大化することです。 

すべてのカウントが最大 100 であるという制約は、ソリューションが高度なデータ構造や定数時間算術推論を超える最適化を必要としないことを意味します。 O(1) または O(n) までの任意の解で十分です。 

重要な微妙な点は、両利きのプレーヤーは単なる追加参加者ではなく、両側に分割できる柔軟なリソースであるということです。 単純な間違いは、バランスをとった後、残った両利きのプレーヤーがペアで貢献して両方のチームを均等に増やすことができるということを考慮せずに、それらを小さい側だけに追加された単一のプールとして扱うことです。 

よくある失敗例は、すべての不均衡が完全に解決されていないにもかかわらず、両手利きのプレーヤーがまだ利用できる場合に発生します。 

たとえば、次のことを考えてみましょう。 

入力:```
1 10 3
```貪欲に「不均衡を修正」するだけであれば、3 人の両手利きプレーヤーをすべて左側に割り当て、左 4 人、右 10 人になる可能性がありますが、それでも 8 人を超えるバランスの取れたチームを形成することはできません。正しい推論では、部分的なバランスを調整した後でも、残った両手利きのプレーヤーを引き続きペアにすることができると考慮する必要があります。 

もう 1 つのエッジ ケースは、左右のプレイヤーがまったくいない場合です。 

入力:```
0 0 5
```均等な半分を維持するには 1 人のプレイヤーを削除する必要があるため、正解は 5 ではなく 4 です。 

これらのケースは、構造が最初にバランスをとり、次にペアリングによって駆動されることを示しています。 

## アプローチ

 強引なアイデアとしては、0 から 2(l + r + a) までの可能なすべての均等なチーム サイズを試し、利用可能な選手を使用してちょうど左半分と右半分を割り当てることができるかどうかを確認することです。 候補サイズ 2k ごとに、k 個の左スロットと k 個の右スロットを分配して、両手利きのプレーヤーが不足をカバーできるかどうかを確認することで実現可能性を検証します。 これは、k ごとに割り当てをシミュレートし、n ≤ 100 の場合でも不要な、およそ O(n^2) の動作につながるため、すぐに非効率になります。 

重要な観察は、構造が貪欲であるが分解可能であるということです。 まず、必須の割り当てを使用します。左のみのプレーヤーと右のみのプレーヤーは、それぞれの側に自然に貢献します。 唯一の柔軟性は両利きのプレーヤーにあります。 彼らの役割は 2 つのフェーズに分かれています。まず、左右のカウントの不均衡を解決します。次に、ペアになっていない単一の両手利きの割り当てがバランスを崩すため、残りの両手利きのプレーヤーは対称ペアでのみ使用できます。 

これにより、問題は直接計算に集約されます。最初に辺を等しくしてから、両方の辺を均等に拡張することで、バランスのとれたペア数をできるだけ多く構築します。

 ## アルゴリズムのチュートリアル

 ペアの最大可能数 k を計算します。最終的なチーム サイズは 2k です。 

1. 左専用プレーヤーと右専用プレーヤーの最小値として初期保証ペアを計算します。 これにより、まだ両手利きのプレーヤーが必要とされない、ベースラインのバランスの取れた構造が得られます。 この時点では、片側にまだ未使用の容量がある可能性があります。 
2. このベースライン ペアリング後の 2 つの側の間の不均衡を計算します。 この不均衡は、さらなる対称的な拡張を可能にするために、両側を均等にするために何人の両手利きプレーヤーが必要であるかを表しています。 不均衡の方向は問題ではなく、その大きさだけが問題になります。 
3. この不均衡をできるだけ減らすために、両手利きのプレーヤーを使用します。 ここで使用される両利きの各プレーヤーは、大きい側に影響を与えることなく、小さい側を 1 つ増やします。 これは、ペアでの使用を必要とせずにバランスを変更する唯一の操作です。 
4. できるだけバランスをとった後、双方が平等になるか、両利きのプレイヤーがアウトになります。 残りの両手利きプレーヤーはペアで使用する必要があります。これは、各側に 1 人が割り当てられ、バランスが保たれるためです。 このようなペアごとにチーム サイズが 2 増加します。これは、k が 1 増加することを意味します。 
5. 最終的な答えは、結果の k の 2 倍になります。 

### なぜ効果があるのか

 どの段階でも、チームの両サイドのサイズが等しいという不変条件を維持します。 チームの有効な拡張は、この平等を維持する必要があります。 両利きのプレイヤーは、不均衡を修正したり、両方のチームを同時に拡大したりできる唯一のリソースです。 不均衡が最小限に抑えられると、非対称的な使用は再び不均衡をもたらし、潜在的なペアを無駄にするため、対称的な使用のみが最適なままになります。 

この構造により、両手利きの割り当てを再配置しても、計算された値よりも大きなバランスのとれたチームが生成されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    l, r, a = map(int, input().split())

    k = min(l, r)

    diff = abs(l - r)

    t = min(a, diff)
    k += t
    a -= t

    k += a // 2

    print(2 * k)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、厳密に制限されたプレーヤーからの保証された一致をロックインします。 次に、両利きの選手を起用して不均衡を軽減します。それが、さらなる対称的な成長を可能にする唯一の方法だからです。 最後に、残った両手利きプレーヤーはペアで消費され、各ペアは両側に均等に増加します。 

実装上の微妙な点は、整数の 2 による除算は不均衡の解決後にのみ適用する必要があることです。 これを早く行うと、システムのバランスが整う前に対称性があると誤って想定されてしまいます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    l, r, a = map(int, input().split())

    k = min(l, r)
    diff = abs(l - r)
    t = min(a, diff)
    k += t
    a -= t

 ## 特殊なケース

 プレイヤーがまったくいない場合、min(l, r) とその後のすべての寄与がゼロであるため、アルゴリズムは直ちに k = 0 を返します。 これにより、出力は 0 になり、これが唯一有効な偶数のチーム サイズになります。 

l が r に等しい状態でシステムのバランスがすでに取れている場合、不均衡はゼロになるため、両手利きのプレーヤーはすぐにペアで使用されます。 これにより、中間的な修正フェーズを必要とせずに、チームが直接拡大されます。 

両手利きのプレイヤーの数がアンバランスよりも少ない場合は、部分的なバランスのみが可能です。 アルゴリズムは a が枯渇した時点で正しく停止し、不等な構成が残るため、その時点を超えると対称ペアリングのみが許可されなくなり、無効な過大評価が防止されます。
