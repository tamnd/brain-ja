 ## 解決策
 ## 問題の理解

 正の整数のシーケンスが与えられ、要素を分割することでそれを変更できます。 1 回の操作で 1 つの数値を選択し、その合計が元の値に等しい隣接する 2 つの正の整数に置き換えます。 他のすべての要素の相対的な順序は保持されるため、この操作では合計の合計を変更せずに配列の長さのみが増加します。 

目標は、できるだけ少ない分割を実行してシーケンスを回文に変換することです。 要素を結合することは許可されていません。要素をより小さな部分に洗練することのみが許可されています。 最終的なシーケンスは、左から右と右から左に同​​じように読み取る必要があります。 

重要な制約は、すべてのテスト ケースの合計の長さが最大 ​​3×10^5 であることです。 これにより、回文が出現するまで任意の分割を明示的にシミュレートするソリューションは即座に除外されます。 各分割は潜在的にさらに多くの比較にカスケードされる可能性があり、各操作の後に回文性を繰り返しチェックする単純なシミュレーションでは、最悪の場合、遅すぎる二次関数の動作に劣化する可能性があります。 

明らかではない問題は、分割によって値ではなく配置が変更されることです。 10 のような値は、分割方法に応じて単一のブロックとして動作することも、多数の小さなブロックとして動作することもでき、最適な戦略は対称位置全体で一致する合計に依存します。 

いくつかの特殊なケースでその構造が強調されます。 

配列がすでに回文 ([1, 2, 3, 2, 1] など) である場合、答えは 0 です。要素を分割しようとしても、演算数が不必要に増加するだけです。 

[4, 4, 4, 4] のように、すべての要素が同一である場合、すでに対称であり、再び 0 が返されます。 

さらに興味深いケースは [3, 2, 1] です。 対称ではありませんが、3 を [1, 2] に分割すると両端を一致させ、[1, 2, 2, 1] を生成できます。 要素を 1 対 1 で比較するだけの素朴な貪欲なアプローチは、分割された配置のシフトを考慮していないため、ここでは失敗します。 

## アプローチ

 直接的な強引なアイデアは、プロセスをシミュレートすることです。 各ステップで、考えられるあらゆる方法で要素の分割を試み、新しいシーケンスを生成し、回文を形成できるかどうかを確認します。 これは巨大な状態空間を探索します。値 x の各要素は x−1 通りに分割でき、分割は繰り返し発生する可能性があるため、分岐係数は膨大になります。 たとえ貪欲な選択に限定したとしても、値の合計に応じて長さが直線的に増加する可能性のあるシーケンスに直面することになります。これは、処理できる量をはるかに超えています。 

重要な点は、分割はミラー化された構造全体で合計を一致させるためのツールにすぎないということです。 個々の要素で考えるのではなく、総重量が等しい連続したブロックを左端と右端から合わせて考える必要があります。 

部分的に消費された値を表す「現在のセグメント」を維持しながら、2 つのポインター (1 つは左から始まり、もう 1 つは右から始まります) を使用して配列を処理できます。 片側のセグメントが小さい場合、概念的には大きいセグメントをそれに合わせて分割します。 分割するたびに、実質的に演算数が 1 つ増加し、一方の残りの値が減ります。 

構造は貪欲ですが決定的になります。常に左右の合計を一致させ、暗黙的に分割することで残りの質量が大きい側から消費します。 

これにより、問題は 2 つの数値ストリームが一致するまでバランスをとるという問題に変換されます。各不一致は、正確に 1 つの分割操作に対応します。

 ## アルゴリズムのチュートリアル

 私たちは 2 つの指針を維持します。`l`初めにそして`r`最後と 2 つの実行値`x`そして`y`それぞれの側からの現在の比類のない「チャンク」を表します。 

また、両側を揃えるために値を分割する必要があった回数に対応する操作のカウンターも維持します。 

1.初期化`l = 0`、`r = n - 1`、`x = a[l]`、`y = a[r]`、 そして`ops = 0`。 これらは、一致する現在のアクティブなセグメントを表します。 
2. その間`l < r`、 比較する`x`そして`y`。 等しい合計のみが対称ペアを形成できるため、目標はそれらを等しくすることです。 
3. もし`x == y`、対称ペアのマッチングに成功しました。 両方のポインターを内側に移動します (`l += 1`、`r -= 1`）そしてリセット`x = a[l]`、`y = a[r]`。 この境界には分割が必要なかったため、ここでは操作は必要ありません。 
4. もし`x < y`、概念的に右側を分割する必要があります。 引き算します`x`から`y`必要に応じて、左ポインタを前方に移動して次の値をフェッチします。 大きいセグメントを小さいセグメントと一致させるために縮小するたびに、増加します。`ops`。 これは、一致する境界を作成するために必要な 1 つの分割操作を反映しています。 
5. もし`x > y`、左側を対称的に分割します。`y`から`x`、それに応じて左側の消費を進め、増分します`ops`。 
6. ポインタが出会うか交差するまで続けます。 この時点で、すべての質量が対称構造に一致します。 

減算で十分である理由は、分割部分を明示的に構築する必要がないためです。 各減算は、もう一方の側と一致させるために、より大きなセグメントから質量単位を消費することを表し、そのようなすべての消費は、正確に 1 つの分割操作に対応します。 

### なぜ効果があるのか

 すべてのステップで、左側のプレフィックスと右側のサフィックスがすでに等しい重みのミラーリングされたセグメントに変換されていることを維持します。 唯一の未解決部分は現在のペアです`(x, y)`。 それらが異なる場合、それらを一致させる唯一の方法は、不一致が発生する境界で大きい方を分割することです。 各分割により、小さい側の現在のセグメントの量だけ不均衡が軽減されるため、分割の代替シーケンスによって操作数をさらに削減することはできません。 この貪欲なマッチングにより、すべての操作で不均衡ができるだけ早く修正され、必要な分割が延期されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        l, r = 0, n - 1
        x, y = a[l], a[r]
        ops = 0
        
        while l < r:
            if x == y:
                l += 1
                r -= 1
                if l < r:
                    x = a[l]
                    y = a[r]
            elif x < y:
                y -= x
                ops += 1
                l += 1
                if l <= r:
                    x = a[l] if l < r else 0
            else:
                x -= y
                ops += 1
                r -= 1
                if l <= r:
                    y = a[r] if l < r else 0
        
        print(ops)

if __name__ == "__main__":
    solve()
```このコードは、両端からの値の部分的な消費を追跡しながら、配列に対する 2 ポインター スイープを実装します。 変数`x`そして`y`現在の要素の残りの不一致部分を次の場所に保存します。`l`そして`r`。 一致すると、対称的なペアが形成されたため、双方が前進します。 

一方の辺が小さい場合、残りの値を減らして 1 回の操作をカウントすることで、大きい方の辺の分割をシミュレートします。 ポインタの移動により、最終的にはどちらかの側から完全な要素が消費されることが保証されます。 更新には注意が必要です`x`そして`y`現在のセグメントが使い果たされた場合にのみ、部分値と完全値が誤って混在することを回避します。 

微妙な点は、分割配列を決して構築しないことです。 減算は値の一部を消費することを直接表しており、そのような各消費は 1 つの分割操作に正確に対応します。 

## 実用的な例

 単純なケースとより複雑なケースを追跡します。

 | 0 | 2 | 3 | 1 | 0 |
 | 0 | 2 | 2 | 0 (分割後) | 1 |

 最初の不均衡は 3 と 1 の間です。概念的に 3 を 1 と 2 に分割し、1 つの操作を支払います。 アラインメント後、シーケンスは事実上、回文である [1, 2, 2, 1] として動作します。 

これは、分割が配列全体ではなく、不一致境界でのみ重要であることを示しています。

 分割するたびに、完全な対称性が達成されるまで、ミラーリングされたセグメント間の不一致が減少します。

 ## 特殊なケース

 次のようなすでに対称的なシーケンスの場合`[1, 2, 1]`の場合、アルゴリズムは外側の値とすぐに一致します。`x == y`最初はそのため、操作はカウントされず、ポインターはきれいに内側に折りたたまれます。 

次のような非常にアンバランスなエンドポイントの場合`[10, 1]`、アルゴリズムは、大きい値から小さい値を繰り返し減算し、単一の分割をシミュレートします。 ポインタの移動により、不均衡を消費した後、残存価値が考慮されないまま残らないことが保証されます。 

次のような均一な配列の場合`[4, 4, 4, 4]`、すべての比較で等価性が得られるため、アルゴリズムは減算ステップを行わずにポインターの移動のみを実行し、結果として演算はゼロになります。 

それぞれのケースで、減算ベースのバランシングが、不一致境界で正確に適用される単位コスト操作として分割を正しくモデル化していることが確認されます。
