 ## 解決策
 ## 問題の理解

 各乗客には 2 つの属性があります。 バスが内側に留まっている場合、その質量はバスの重量に寄与しますが、バスが外に出て押す場合にのみ、押す力が寄与します。 

何人かの乗客を押し手として選んだとします。 押す力の合計は少なくともバスに残る重量以上でなければなりません。 残りの重量は、空のバスと下車しなかったすべての乗客の質量で構成されます。 

課題は、この条件を満たしながら、できるだけ少ないプッシャーを選択することです。 乗客の選択の余地がなくバスを移動できない場合、答えは次のとおりです。`-1`。 

すべてのテスト ケースの合計乗客数は最大で`2 × 10^5`。 これにより、すべてのサブセットを試すことが直ちに除外されます。`2^40`それはすでに不可能ですが、`2^200000`実際の計算をはるかに超えています。 アン`O(n^2)`アルゴリズムも高価すぎるため、最悪の場合は約`4 × 10^10`操作。 アン`O(n log n)`ソリューションはこれらの制限に対して十分に高速です。 

いくつかの特殊なケースは注目に値します。 

他の乗客よりもはるかに大きな力を持つ乗客について考えてみましょう。```
1
3 5
2 2 2
10 1 1
```正しい答えは、`1`。 単純に最も重い乗客を最初に排除する戦略では、たとえ最も強い乗客だけがすでに成功しているにもかかわらず、誤って 2 人を選択することになります。 

もう一つ重要なケースは、全員が降りてもバスの移動が不可能な場合です。```
1
2 100
1 1
30 40
```乗客全員が押しても、合計の力はわずかです。`70`、バスだけでも重量はありますが、`100`。 正しい答えは、`-1`。 

2 人の乗客が同じ力を持っているが質量が異なる場合、より微妙な状況が現れます。```
1
2 5
100 1
10 10
```重い乗客を選択することは、どちらも同じ力に寄与するため、軽い乗客を選択することと少なくとも同じくらい良いですが、重い乗客を取り除くと、バスからより多くの重量が軽減されます。 乗客数を無視して関係を断つソリューションは、最適な答えを逃す可能性があります。 

## アプローチ

 最も直接的な解決策は、乗客のすべてのサブセットを列挙することです。 サブセットごとに、合計の押す力と残りの重量を計算し、条件を満たす最小のサブセットを保持します。 考えられるすべての選択肢が検討されるため、これは正しいです。 残念ながら、それには、`O(2^n · n)`それは完全に不可能な時間です。 

有効な選択を表す不等式は次のとおりです。```
sum(force of chosen)
≥
w + sum(mass of unchosen)
```させて`M`すべての乗客の合計質量になります。 

以来```
sum(mass of unchosen)
=
M - sum(mass of chosen),
```条件はこうなる```
sum(force) + sum(mass) ≥ w + M.
```選択された乗客全員が、追加することで個別に貢献できるようになりました。```
force + mass
```決まった目標に向かって```
w + M.
```この変換により、選択された乗客と選択されなかった乗客の間の相互作用が削除されます。 各乗客には単純に価値がある```
value = force + mass.
```目標金額を達成しながら選択される乗客の数を最小限に抑えるという貪欲な戦略は明らかです。 常に、利用可能な最大値を最初に取得します。 を使用した解決策の場合`k`乗客が存在する場合、`k`最大の値は、他の値と少なくとも同程度の合計貢献度を達成します。`k`乗客。 

これらの値を降順に並べ替えた後、累積貢献度が目標に達するまで乗客を乗せ続けます。 乗客全員を合わせても足りない場合、答えは次のとおりです。`-1`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(2^n · n)`|`O(n)`| 遅すぎる |
 | 最適 |`O(n log n)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての乗客の質量と力を読み取ります。 
2. 総乗客質量を計算する`M`。 必要な貢献度は、`target = w + M`。 
3. すべての乗客について、計算します。`value = mass + force`。 これは、その乗客の選択がどの程度役立つかを測定します。 それらの力は不等式の左側を増加させますが、それらの質量を取り除くと必要な重量がまったく同じ量だけ減少します。 
4. すべての値を降順に並べ替えます。 乗客の数を最小限に抑えたいため、選ばれたすべての乗客が可能な限り多くの寄付を提供する必要があります。 
5. 蓄積された寄与を維持しながら、ソートされた値を最大値から最小値までたどります。 
6. 累積寄付金が最低額以上になった時点で、`target`、何人の乗客が乗車したかを出力します。 同じ乗客数を持つ他のセットの寄与は、すでに選択されている最大値以下であるため、これより小さい答えはあり得ません。 
7. ターゲットに到達せずにリスト全体が処理された場合、出力`-1`。 

### なぜ効果があるのか

 変換された不等式は、次の合計にのみ依存します。`mass + force`選ばれた乗客の上に。 正確に含むすべてのサブセットの中で`k`乗客にとって、可能な限り最大の貢献は、`k`最大値。 これらの最大値がターゲットに到達しない場合、他のサイズのサブセットは存在しません。`k`成功することができます。 逆に、ターゲットに到達すると、サイズの有効なサブセットが`k`存在します。 ソートされたリストの最初に成功したプレフィックスは、まさに必要なプッシャーの最小数です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, w = map(int, input().split())
        masses = list(map(int, input().split()))
        forces = list(map(int, input().split()))

        target = w + sum(masses)
        values = [m + f for m, f in zip(masses, forces)]
        values.sort(reverse=True)

        cur = 0
        ans = -1
        for i, v in enumerate(values, 1):
            cur += v
            if cur >= target:
                ans = i
                break

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初の部分では、空のバスの重量に乗客の総質量を加えたターゲット寄与度を計算します。 

各乗客は、その質量と力に等しい単一の値に変換されます。 これは、元の不等式の代数変換から直接得られます。 

これらの値を降順に並べ替えることで、アルゴリズムはあらゆるサイズの可能な限り最適なサブセットを検査できるようになります。 累計は、現在の乗客数を使用して達成可能な最大の寄与を表します。 

合計がターゲットに達する最初のプレフィックスがすぐに最適な答えを与えます。 完全なプレフィックスがまだ不足している場合は、全員を選択してもバスを移動できません。 

Python の整数は可能な最大の合計を自動的に処理するため、オーバーフローに対する予防策は必要ありません。

import sys, io

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, w = map(int, input().split())
        m = list(map(int, input().split()))
        f = list(map(int, input().split()))
        target = w + sum(m)
        vals = sorted((a + b for a, b in zip(m, f)), reverse=True)
        s = 0
        ans = -1
        for i, v in enumerate(vals, 1):
            s += v
            if s >= target:
                ans = i
                break
        out.append(str(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    solve()
    res = sys.stdout.getvalue().strip()
    sys.stdin = backup_stdin
    sys.stdout = backup_stdout
    return res

 ## 特殊なケース

 ある乗客が他の乗客よりも圧倒的に強い場合を考えてみましょう。```
1

2 2 2
10 1 1
```ターゲットは`11`。 変換された値は次のとおりです。`[12, 3, 3]`。 最初の値を選択した後、蓄積された貢献度はすでに`12`、したがってアルゴリズムはすぐに戻ります`1`。 乗客数だけを基準に乗客を選択すると、この解決策を逃すことになります。 

次に、不可能な例を考えてみましょう。```
1
2 100
1 1
30 40
```目標は等しい`102`、すべての乗客の貢献総額はわずか`72`。 累計が目標に達することはないため、アルゴリズムは正しく返します。`-1`。 

最後に、力は等しいが質量が異なる乗客を調べます。```
1
2 5
100 1
10 10
```変換された値は次のとおりです。`[110, 11]`、そしてターゲットは`106`。 最初の値だけですでに目標に達しているため、答えは次のようになります。`1`。 これは、力だけを考慮するのではなく、質量と力の両方を単一の寄与値に組み合わせる必要がある理由を示しています。
