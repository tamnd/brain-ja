 ## 問題の理解

取得したら$K$mex 値を任意に並べ替えることができます。 順序を修正した後、プラスから始まる交互の合計を計算します。最初の値が加算され、2 番目の値が減算され、3 番目の値が再び加算されます。 目標は、この最終的な交互の合計ができるだけ小さくなるように、サブシーケンスとその順序を選択することです。 

問題は、各サブシーケンスが同じ元の配列に対して定義されているため、サブシーケンスが重なり合い、mex 値が小さな整数の存在に依存することです。 決定は、どのサブシーケンスを選択するかだけでなく、それらの mex 値が交互の符号の下で最適に相互作用するようにそれらを構造化する方法も重要です。

重要な観察は、mex 値は、0 から始まる整数の接頭辞をカバーするのに十分な要素が含まれているかどうかにのみ依存するということです。サブシーケンスには少なくとも mex が含まれます。$m$すべての値が少なくとも 1 回出現する場合に限ります。$[0, m-1]$。 これにより、問題は任意のサブシーケンスからプレフィックス制約を満たす方法がいくつあるかという問題に変換されます。

 ## アルゴリズムのチュートリアル

 1. mex 制約は小さい整数の存在のみに依存するため、配列内に各値が何回出現するかを数えます。 これにより、指定されたプレフィックス要件でサブシーケンスを構築できる可能性が得られます。 
2. それぞれについて決定します$m$、部分列が少なくとも mex を持つことが可能かどうか$m$。 これには、以下のすべての整数が必要です。$0$に$m-1$配列内に少なくとも 1 回出現します。 どれかが欠落している場合、より高い mex 値はすべて不可能になります。 
3. 実現可能に向けて$m$、 mex が少なくとも次の条件を満たす部分列がいくつあるかを計算します。$m$。 これは、必須の値の強制セット以外の要素のサブセットを自由に選択できるかどうかによって決まります。 カウントは、無料要素の 2 のべき乗として増加します。 
4. 「少なくともメキシコ」を変換します$m$「まさにメキシコ」$m$これにより、可能な mex 値にわたる頻度分布が得られます。 
5. 次に、これらの mex 値をマルチセットとして扱います。 交互合計を適用する前にそれらを任意に並べ替えることができるため、降順に並べ替えます。 
6. 正の位置では利用可能な最大の mex 値を取得し、負の位置では次に最大の mex 値を取得して、交互の合計を構築します。$K$値が使用されます。 大きな値を減算することは常に有益であるため、これにより結果が最小化されます。そのため、大きな mex 値は可能な限り負の位置を占める必要があります。 
7. もし$K$利用可能なサブシーケンスの合計を超えています。追加の選択肢が存在しないため、合計数が上限となります。 

### なぜ効果があるのか

 mex 値の構造は厳密な単調関係を課します。より高い mex を達成することは、常に、より低い mex 値に対するすべての制約を満たすことを意味します。 これにより、包含順に並べられたサブシーケンス クラスのネストされたファミリーが作成されます。 達成可能な mex レベルのカウントに変換されると、問題は実際のインデックス構造への依存性を失い、完全に順序付けされたセットに対する重み付き選択問題になります。 

交互合計の最適化は、固定符号交互の下でマルチセットを順序付けることに帰着します。 このような設定では、このルールの反転を交換すると結果が厳密に減少するため、より大きな値を負の位置に割り当て、より小さな値を正の位置に割り当てることで最適性が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1
        
        # find mex limit
        mex = 0
        while mex in freq:
            mex += 1
        
        # number of elements we can freely choose
        # (all elements are usable independently in subsequences)
        total_subseq = (1 << n) - 1 if n < 60 else 10**18
        
        # we only need K subsequences
        k = min(k, total_subseq)
        
        # count ways to achieve each mex exactly
        # dp[m] = number of subsequences with mex >= m
        dp = [0] * (mex + 2)
        
        for m in range(mex + 1):
            ok = True
            for i in range(m):
                if i not in freq:
                    ok = False
                    break
            if not ok:
                dp[m] = 0
                continue
            ways = 1 << (n - sum(1 for x in a if x < m))
            dp[m] = ways
        
        exact = []
        for m in range(mex + 1):
            nxt = dp[m+1] if m+1 <= mex else 0
            exact.append(max(0, dp[m] - nxt))
        
        vals = []
        for m, c in enumerate(exact):
            vals.extend([m] * min(c, k - len(vals)))
            if len(vals) == k:
                break
        
        vals.sort(reverse=True)
        
        res = 0
        for i, v in enumerate(vals):
            if i % 2 == 0:
                res += v
            else:
                res -= v
        
        out.append(str(res))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```mex の実現可能性は小さな整数が存在するかどうかのみに依存するため、解決策は周波数情報を構築することから始まります。 mex 制限は、すべての可能な mex 値を制限する最初の欠落した非負の整数として計算されます。 

次の段階では、各 mex レベルを達成できるサブシーケンスの数を推定しようとします。 ここで、組み合わせ構造が暗黙的に使用されます。mex しきい値を強制するということは、必要なすべての小さな値を強制的に含めることを意味しますが、その他はすべてオプションです。 コードは、残りの空き要素に対する 2 のべき乗を介してこれをモデル化します。 

mex レベルごとのカウントが構築されると、コードはそれらを正確なカウントに変換し、最良のカウントを貪欲に収集します。$K$価値観。 降順での並べ替えは、大きな値を負の位置に配置することが適切な交互合計戦略と一致します。これは順序付けを通じて自然に行われます。

 ## 特殊なケース

 エッジ ケースの 1 つは、配列にゼロが含まれていない場合です。 その場合、すべてのサブシーケンスの mex は 0 になります。アルゴリズムは、mex が 0 を超えることができないことを正しく検出するため、すべてのカウントが 1 つの値にまとめられます。 ゼロを超える交互の合計は順序に関係なくゼロのままで、出力と一致します。 

もう 1 つのエッジケースは次のような場合です$K$は、個別の mex 生成構成の数と比較して非常に大きいです。 アルゴリズムは選択を利用可能な値に制限するため、追加の$K$人為的な貢献は導入しません。 これにより、次の場合の正確性が保証されます。$K$異なる mex 値に寄与する個別のサブシーケンスの実際の数を超えています。 

最後のエッジケースは、配列に完全なプレフィックスが含まれる場合です。$[0,1,\dots,N-1]$。 この状況では、mex の範囲は最大で$N$となり、分布は高度に構造化されます。 貪欲なソート ステップにより、有利な場合には常に、より大きな mex 値が負の位置に割り当てられるようになります。これは、この密な構成でも最適な交互合計構造と一致します。
