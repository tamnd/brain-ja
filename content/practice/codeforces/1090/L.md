 ## 問題の理解

 あります`t`学生と`n`講義。 学生は少なくとも出席すれば合格します`k`講義。 

講義は 2 つの講堂で交互に行われます。 奇数のインデックスを持つ講義は、最大でも収容可能な第 1 講堂で開催されます。`a`学生たち。 偶数のインデックスを持つ講義は、最大収容人数が 2 人の第 2 講堂で行われます。`b`学生たち。 

対応する講堂の定員を超えない限り、各講義にどの学生が参加するかは私たちが自由に決定できます。 学生は講義のどのサブセットにも参加できます。 

課題は、少なくとも最終的に出席できる生徒の最大数を決定することです。`k`講義。 

値は次のように大きくできます。$10^9$、これにより、学生や講義に対するあらゆるシミュレーションが即座に除外されます。 たとえ$O(n)$アルゴリズムは不可能なので、`n`それ自体はそうかもしれない$10^9$。 ソリューションでは、一定数の算術演算のみを使用する必要があります。 

問題の微妙な点は、講義への出席が事前に特定の学生に関連付けられていないことです。 講義ごとに出席を完全に再調整できます。 重要なのは、各講堂タイプのすべての講義で利用可能な座席の合計数です。 

### 明らかではないエッジケース

 次のことを考慮してください。```
10 3 4 4 5
```講義は 3 つしかありませんが、合格するには 5 つの講義を受講する必要があります。 合格できる生徒はいないでしょう。 

正しい答えは次のとおりです。```
0
```利用可能な座席の合計のみをカウントする不注意なソリューションでは、誤って肯定的な答えが生成される可能性があります。 

ここで次のことを考えてみましょう。```
5 4 5 3 3
```各講堂タイプで 2 つの講義が行われます。 

利用可能な座席の合計:```
2 * 5 + 2 * 3 = 16
```合格する生徒 1 人につき 3 回の出席が必要です。 

以来$16 / 3 = 5$、5 人の生徒全員が合格できます。 

正しい答えは次のとおりです。```
5
```この例は、答えが小さな講堂だけで決まるわけではないことを示しています。 

もう 1 つの重要なケースは次のとおりです。```
100000 100000 100000 100000 1
```合格には 1 回の講義のみが必要です。 

すべての学生は 1 回だけ講義に出席し、合格することができます。 

答えは次のとおりです。```
100000
```学生の数自体が制限要因になります。 

## アプローチ

 強引な考え方では、学生を講義に割り当て、各学生が何回講義に出席したかを追跡しようとします。 学生数も講義数も上限に達する可能性があるため、これはすぐに不可能になります。$10^9$。 

重要な観察は、学生のアイデンティティは重要ではないということです。 私たちが気にするのは、出席枠がいくつ存在するかだけです。 

正確に欲しいと仮定してください`x`合格する生徒たち。 

これらの学生はそれぞれ少なくとも出席する必要があります`k`講義。 合格するすべての生徒に少なくとも次のものが必要です。$$x \cdot k$$出席枠。 

参加枠はいくつありますか?

 させて$$o = \left\lceil \frac{n}{2} \right\rceil$$は奇数のインデックスが付いた講義の数であり、$$e = \left\lfloor \frac{n}{2} \right\rfloor$$偶数インデックスの講義の数になります。 

コース全体で利用可能な座席の総数は、$$S = o \cdot a + e \cdot b.$$もし望むなら`x`学生が合格するには、私たちが必要です$$xk \le S.$$一見すると、これは示唆しています$$x \le \left\lfloor \frac{S}{k} \right\rfloor.$$ただし、もう 1 つ制限があります。 1 人の学生が受講可能なすべての講義を超えて受講することはできません。 

学生は最大でも参加できます`n`講義。 もし`k > n`、合格は不可能です。 

もし`k ≤ n`, そうすれば、出席枠はいつでも選択した学生に分配できます。 残る唯一の制限は、次の値を超えて通過できないことです。`t`学生たち。 

したがって、答えは次のようになります。$$\min\left(t,\left\lfloor\frac{S}{k}\right\rfloor\right).$$唯一の例外は次の場合です。`k > n`、この場合、答えはゼロです。

 ## アルゴリズムのチュートリアル

 1. 第一講堂で開催される講義の数を計算します。$$o = \frac{n+1}{2}$$整数の除算を使用します。 
2. 第 2 講堂で開催される講義の数を計算します。$$e = \frac{n}{2}.$$3. もし`k > n`、出力`0`。 

学生はそれ以上出席することはできません`n`講義。 
4. 出席枠の合計数を計算します。$$S = o \cdot a + e \cdot b.$$5. 少なくとも受け入れることができる生徒の最大数を計算します。`k`出席者数:$$\left\lfloor \frac{S}{k} \right\rfloor.$$6. 最終的な答えは、この値と、`t`、しかないからです。`t`学生が利用可能です。 

### なぜ効果があるのか

 通過する生徒は全員、少なくとも`k`出席枠。 まさにあるので、`S`コース全体を通じて利用できる出席枠は次のとおりです$\lfloor S/k \rfloor$学生は合格できます。 

逆に言うと、`k ≤ n`、任意のコレクション`x`学生$$xk \le S$$十分な講義訪問を割り当てることができます。 消費される唯一のリソースは出席キャパシティであり、合計キャパシティは正確に`S`。 学生は全部に参加できるので、`n`講義の場合、追加のボトルネックはありません。 

したがって、合格可能な最大の生徒数は正確に次のようになります。$$\min\left(t,\left\lfloor\frac{S}{k}\right\rfloor\right).$$## Python ソリューション```python
import sys
input = sys.stdin.readline

t, n, a, b, k = map(int, input().split())

if k > n:
    print(0)
else:
    odd_lectures = (n + 1) // 2
    even_lectures = n // 2

    total_slots = odd_lectures * a + even_lectures * b

    print(min(t, total_slots // k))
```実装は数学的導出に直接従います。 

最初のチェックは、唯一不可能なシナリオ、つまり、コースに存在する数を超える講義への出席を必要とするシナリオを処理します。 

奇数および偶数のレクチャーの数は整数演算で計算されます。 奇数の場合`n`、講義番号は 1 から始まるため、最初の講堂では 1 つの追加講義が受けられます。 

すべての計算は 64 ビット整数内に快適に収まります。 可能な最大値はおおよそ次のとおりです$$10^9 \cdot 10^9 = 10^{18},$$これは Python ではまだ安全です。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    t, n, a, b, k = map(int, input().split())

    if k > n:
        return "0"

    odd = (n + 1) // 2
    even = n // 2
    total = odd * a + even * b

    return str(min(t, total // k))

# provided samples

# custom cases
