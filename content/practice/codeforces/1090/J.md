 ## 解決策
 ## 問題の理解

 2 つの文字列が与えられています。`s`そして`t`。 から`s`、空ではない任意のプレフィックスを取得できます。`t`、空ではない任意のプレフィックスを取得することもできます。 このような選択肢のすべてのペアに対して、選択されたプレフィックスを連結します。`s`選択したプレフィックスを使用して`t`。 タスクは、この方法で形成できる個別の文字列の数を決定することです。 

問題の構造は基本的にプレフィックス セットのデカルト積ですが、工夫が施されています。異なるペアが同じ結果の文字列を生成する可能性があり、それらの衝突は 1 回だけカウントする必要があります。 課題は完全に重複を効率的に処理することです。 

この制約により、各文字列の長さは最大 100,000 文字になります。 すべてのプレフィックス ペアを単純に列挙すると、最悪の場合、すでに最大 10^10 の連結が生成され、すべての候補を明示的に構築または比較するソリューションは即座に除外されます。 メモリの制約下では、すべての結果を保存することすら不可能です。 

両方の文字列が長く繰り返される構造を共有する場合、微妙なエッジ ケースが発生します。たとえば、`s = "aaaaa..."`そして`t = "aaaaa..."`。 この場合、多くの異なるプレフィックス ペアが同一の文字列にまとめられ、答えはペアの総数よりもはるかに小さくなります。 逆に、もし`s`そして`t`プレフィックス構造に重複がなく、ほとんどすべてのペアが異なる結果を生成します。 正しい解決策は、暗黙のうちに両極端を考慮する必要があります。 

もう 1 つの微妙な問題は、結果の文字列が等しいかどうかは、接尾辞間の重複パターンにのみ依存することです。`s`と接頭辞`t`。 これらの重複を慎重に調整しない単純なハッシュ手法では、ケースが誤ってマージまたは分離される可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。空でないすべてのプレフィックスを生成します。`s`、空でないすべてのプレフィックスを生成します。`t`、それらを連結し、結果をセットに挿入します。 もし`n = |s|`そして`m = |t|`、これにより生成される`n * m`文字列。 最悪の場合、各連結のコストは O(n + m) となり、O(nm(n+m)) の操作が必要になりますが、これは長さ 100,000 の文字列では実現不可能です。 

プレフィックスごとにローリング ハッシュを使用して最適化したとしても、依然として O(nm) 個の組み合わせに直面します。 本当のボトルネックは文字列を構築することではなく、重複を効率的に区別することです。 問題は、2 つのペアがいつになるかを理解することです。`(i, j)`そして`(i', j')`同じ文字列を生成します。`s[0..i] + t[0..j] = s[0..i'] + t[0..j']`。 

この等価性は、接頭辞の接尾辞がどのように配置されるかによって決まります。`s`の接頭辞と重複する`t`。 重要な洞察は視点を変えることです。連結を構築する代わりに、接頭辞の接尾辞の間で起こり得るすべての重複を分析します。`s`と接頭辞`t`。 

固定プレフィックス長の場合`s`、 言う`i`、唯一の違いは`j`値が重複する可能性があるのは、次の場合です。`s[0..i]`の冒頭と重なる`t`。 したがって、それぞれのプレフィックスに対して、`s`、すべての可能なオーバーラップ長について知る必要があるだけです。`k`、 かどうか`s[i-k+1..i] == t[0..k-1]`。 

これは当然、次の間で一致するすべての接頭辞関数スタイルを前処理することを示唆しています。`t`と部分文字列`s`。 Z アルゴリズムまたはローリング ハッシュを使用して、すべての位置を計算できます。`s`、最長のプレフィックス`t`そこから始まるマッチング。 次に、この情報を伝播して、プレフィックスごとに発生する個別の連結の数を数えます。`s`。 

最終的な構造は次のようになります。`s`、考えられるすべてのオーバーラップ長を次のように考慮します。`t`、それぞれの重複が結果として得られる一意の文字列を決定します。 重複しないケースも独立して寄与します。 

効率的なソリューションにより、問題は、`(prefix of s, overlap length with t prefix)`これは、ハッシュまたは Z 配列前処理を使用して線形時間で追跡できます。

 | 最適 (プレフィックス マッチング + ハッシュ/Z) | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字列に対して Z 配列スタイルのアプローチを使用します。`t + '#' + s`各ポジションがどれくらいかを計算するには`s`のプレフィックスと一致します`t`。 

1. 新しい文字列を構築します`u = t + '#' + s`、 どこ`#`どちらの文字列にも存在しない区切り文字です。 これにより、次のプレフィックスを比較できるようになります。`t`すべてのサフィックス位置で`s`ワンパスで。 
2. 次の Z 配列を計算します。`u`。 ポジションごとに`pos`に対応する`s`、Z 値は最長のプレフィックスを与えます。`t`の部分文字列と一致する`s`その位置から始めます。 
3. プレフィックス長ごとに`i`の`s`、考えられるすべての重複を決定します`t`。 の接頭辞`t`長さの`k`の接尾辞と一致する可能性があります`s[0..i]`位置で終わる`i`対応する部分文字列アライメントが Z 配列に存在する場合。 
4. 固定プレフィックスの場合`s[0..i]`、有効なオーバーラップ長をすべて列挙します`k`。 それぞれ`k`同じ結果をもたらす小さな重複がすでに考慮されていない限り、別個の連結文字列が生成されます。 
5. プレフィックスごとにどのオーバーラップ長が見られたかを追跡することにより、セットのような構造を暗黙的に維持します。`s`。 文字列を明示的に保存する代わりに、一意の文字列をカウントします。`(i, k)`州。 
6. すべてのプレフィックスにわたる寄与を合計します。`s`。 それぞれの有効な状態は、正確に 1 つの異なる連結に寄与します。 

### なぜ効果があるのか

 結果として得られるすべての文字列は、2 つのパラメータによって一意に決定されます。`s`そして重なり合う長さは`t`。 オーバーラップの長さは、接尾辞間の接頭辞の同一性によって完全に決定されます。`s[0..i]`と接頭辞`t`。 Z 配列を使用すると、このようなすべての等式がアライメントごとに 1 回正確に計算されます。 オーバーラップの長さが異なると、配置境界も異なるため、2 つの異なる境界は存在しません。`(i, k)`ペアは、同一のプレフィックス アラインメントを表さない限り、同じ文字列を生成します。プレフィックス アラインメントはすでに構築によって除外されています。 これにより、カウントされた状態と個別の文字列との間に 1 対 1 のマッピングが確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def z_function(s):
    n = len(s)
    z = [0] * n
    l = r = 0
    for i in range(1, n):
        if i < r:
            z[i] = min(r - i, z[i - l])
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] > r:
            l, r = i, i + z[i]
    return z

def solve():
    s = input().strip()
    t = input().strip()

    n, m = len(s), len(t)

    u = t + "#" + s
    z = z_function(u)

    ans = 0

    for i in range(n):
        pos = m + 1 + i
        max_match = min(z[pos], m)

        ans += max_match + 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装は結合された文字列を構築します`u`の各位置から始まる Z 値が`s`何文字かを直接エンコードします`t`そこから始まるサフィックスと一致します。 各プレフィックスエンドポイントに対して`i`で`s`、位置合わせされた位置で Z 値を読み取り、それをクランプします。`m`、それを有効なオーバーラップ長の数として解釈します。 の`+1`重複が発生しない場合を考慮します。これは、のプレフィックス全体を意味します。`t`一致せずに追加されます。 

重要な実装の詳細は、正しいインデックス付けです。つまり、`s`インデックスにマップします`m + 1 + i`区切り文字により結合された文字列に含まれます。 ここでオフバイワンエラーが発生すると、位置合わせが完全に崩れ、オーバーラップカウントが不正確になります。

 ## 特殊なケース

 重要なエッジケースは、両方の文字列が同一またはほぼ同一である場合です。 入力用`s = "aaaa"`そして`t = "aaa"`、すべての接尾辞の位置合わせにより、複数の等価な連結が生成されます。 Z 配列はすべてのアライメントで完全なプレフィックス一致を返し、クランプにより有効なオーバーラップ長のみをカウントするため、アルゴリズムはこれを正しく処理します。`|t|`。 

もう 1 つの特殊なケースは、共通の文字がまったく存在しない場合です。`s = "abc"`そして`t = "xyz"`。 この場合、すべての Z 値はゼロであるため、各プレフィックスは 1 つの一意の連結に寄与します。 アルゴリズムは自然にカウントに退化します`|s|`オーバーラップインフレのない状態。 

最後の微妙なケースは、オーバーラップが中央にのみ存在する場合に発生します。`s`ただし、プレフィックス境界と一致していません。 Z 位置合わせにより、すべての一致がプレフィックス エンドポイントに固定されているため、適切に配置された一致のみがカウントされるようになります。`s`、無効な境界を越えたマージを防ぎます。
