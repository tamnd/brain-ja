 ## 解決策
 ## 問題の理解

 いくつかの箱が与えられ、それぞれに一連の異なるアイテムが入っています。 各アイテムには種類があり、同じ種類の重複したボックスはありません。 アイテムの総数が多く、アイテムをボックス間で一度に 1 つずつ移動できます。 

目標は、すべてのボックスのサイズを可能な限りバランスよくすることです。つまり、すべての操作の後、すべてのボックスに ⌊S / n⌋ または ⌊S / n⌋ + 1 個の項目 (S は項目の総数) が含まれる必要があります。 このバランスのとれた構成を実現するあらゆる方法の中で、実行される個々のアイテムの移動の数を最小限に抑えたいと考えています。 各移動は、ボックスに重複したアイテム タイプを含めることはできないというルールを常に維持しながら、1 つのボックスから 1 つの特定のアイテムを取り出して別のボックスに配置することで構成されます。 

重要な問題は、単にカウントを再配布しているわけではないということです。 どの項目を正確に移動し、どこに移動するかを明示的に決定し、すべての中間構成と最終構成が有効なままであることを確認する必要があります。 

制約が十分に大きいため、ボックスまたはアイテムに対する二次的な動作を伴うソリューションは失敗します。 最大 100,000 個のボックスと合計アイテム数が 500,000 個のアイテムを扱う場合、オペレーションはアイテム数の合計において直線に近いものでなければなりません。 これにより、バランスのシミュレーションを繰り返したり、アイテムごとのグローバル割り当てを再計算したりするアプローチは除外されます。 

複数のボックスが同じサイズである場合、または追加の +1 容量を受け取るボックスについて有効な選択肢が多数ある場合、微妙な問題が発生します。 どのボックスを「より大きなターゲット ボックス」にするかを不用意に選択すると、移動回数が不必要に増加する可能性があります。すでに大きいボックスにより高いターゲットを割り当てると、余分な移動が減少するためです。 

もう 1 つの隠れたエッジ ケースは、すべてのボックスの差異がすでに最大で 1 つしかないにもかかわらず、アイテムが選択されたターゲット構成に対して「正しい」ボックス内にないため、初期分布が依然として最適ではない場合です。 この場合でも、移動が必要になる場合がありますが、それは容量の不一致を修正する移動のみです。 

## アプローチ

 直接的な強引なアイデアは、最小のボックスと最大のボックスを繰り返し選択し、サイズの差が最大 1 になるまで任意のアイテムを最大のボックスから最小のボックスに移動することです。 これは簡単にシミュレートできますが、各移動はアイテムのアイデンティティを尊重する必要があり、移動するアイテムの選択が将来の可能性に影響するため、失敗します。 最悪の場合、各移動では制約に違反しない有効なアイテムを見つけるためにボックスをスキャンする必要があり、アイテムの総数に対して 2 次またはさらに悪い動作が発生します。 

重要な観察点は、最終的なターゲット構成はアイテムの種類ではなく、ボックスのサイズのみに依存するということです。 各ボックスの最終的なサイズを決定したら、すべてのアイテムは元のボックスに保管されるか、移動されます。ボックスごとの容量制限を除いて、異なるアイテム間の結合はありません。 これにより、問題はフローのような割り当てになります。各ボックスは元のアイテムを正確に固定数保持する必要があり、余分なアイテムはすべて不足しているボックスに移動する候補になります。 

移動を最小限に抑えるために、元の箱に保管されるアイテムの数を最大化します。 これは、総余剰を最小限に抑える方法で目標容量を割り当て、余剰アイテムを不足ボックスと貪欲に組み合わせることで実現されます。 

すべてのボックスに ⌊S / n⌋ を割り当て、最大の初期サイズを持つ r ボックスに +1 の容量を与えます。ここで、r = S mod n です。 この選択により、初期サイズとターゲット サイズ間の正の合計の差が最小限に抑えられるため、移動する必要があるアイテムの数が最小限に抑えられます。 

目標が決まったら、目標を超えたボックスから余ったアイテムを回収し、目標を下回るボックスに再分配します。 すべてのアイテムはボックス内で個別に区別されるため、制約に違反することなく余剰アイテムを自由に移動できます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 貪欲なバランス調整を繰り返す | O(S・n) 最悪の場合 | O(S) | 遅すぎる |
 | 目標規模 + 余剰再分配 | O(S) | O(S) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. アイテムの総数 S を計算し、base = S // n と剰余 r = S % n を計算します。 最終的な構成は、サイズのベース + 1 の r 個のボックスとサイズのベースの n - r 個のボックスで構成される必要があります。 
2. ボックスを現在のサイズで降順に並べ替え、最初の r ボックスを容量ベース + 1 の「大きいターゲット ボックス」として割り当て、残りのボックスを容量ベースで割り当てます。 この割り当てにより、初期ボックスが大きいほど容量が吸収されるため、移動する必要がある余分なアイテムの総数が最小限に抑えられます。 
3. 各ボックスについて、その余剰を current_size - target_size として計算します。 この値が正の場合、ボックスはちょうどその数のアイテムを寄付する必要があります。 負の場合はアイテムを受け取る必要があります。 ゼロの場合、すでにバランスが取れており、間接的にソースまたはシンクとしてのみ参加します。 
4. 余ったボックスごとにアイテムを積み重ねて保管し、任意のアイテムを効率的に取り出して移動できるようにします。 ボックス内で独自性が保たれている限り、アイテムの特定のアイデンティティは重要ではありません。 
5. 不足ボックスのリストを維持します。各ボックスには、target_size - current_size に等しい数の受信アイテムが必要です。 
6. 不足ボックスを繰り返し、利用可能な余剰ボックスから繰り返しアイテムを取り出します。 転送ごとに、転送元ボックス、転送先ボックス、およびアイテム タイプを説明する移動を出力します。 ソースの余剰数と宛先の不足数を減らします。 
7. すべての不足が満たされるまで続けます。 実行される移動の総数はすべての余剰の合計に等しくなりますが、これは構造上最小限になります。 

正しさは、項目の同一性がボックス全体の実現可能性を決して制約しないという事実に依存します。 各アイテムは常に 1 つのボックス内に存在し、別の場所に挿入される前に元のボックスから削除されるため、アイテムを移動しても重複は作成されません。 

### なぜ効果があるのか

 このプロセスでは、初期ボックス サイズと最終ボックス サイズの間の L1 距離を最小化するターゲット サイズ分布が修正されます。 アイテムを移動するたびに、あるボックスでは 1 単位の黒字が減り、別のボックスでは 1 単位の赤字が減ります。 各手は厳密に合計の不均衡を 1 つ削減し、どの手も不均衡の単位を超えて削減することはできないため、手数は強制的に総余剰と等しくなります。 この合計余剰を最小限に抑えるターゲット サイズを選択するため、結果として得られる一連の移動は最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    boxes = []
    total = 0

    items = []
    for i in range(n):
        arr = list(map(int, input().split()))
        s = arr[0]
        total += s
        boxes.append([s, i])
        # store items separately
        items.append(arr[1:])

    base = total // n
    rem = total % n

    boxes_sorted = sorted(boxes, reverse=True)

    target = [base] * n
    for k in range(rem):
        target[boxes_sorted[k][1]] += 1

    surplus = [0] * n
    deficit = [0] * n

    give = [[] for _ in range(n)]
    need = []

    for i in range(n):
        s = boxes[i][0]
        t = target[i]
        if s > t:
            surplus[i] = s - t
            give[i] = items[i][:]
        elif s < t:
            deficit[i] = t - s
            need.append(i)

    ptr = 0
    surplus_stack = []

    for i in range(n):
        if surplus[i] > 0:
            # store (box, items list pointer index)
            surplus_stack.append(i)

    res = []

    # for each deficit box, fill it
    for i in need:
        while deficit[i] > 0:
            while surplus[ptr] == 0:
                ptr += 1
            j = ptr
            x = give[j].pop()
            surplus[j] -= 1
            deficit[i] -= 1
            res.append((j + 1, i + 1, x))

    print(len(res))
    for a, b, c in res:
        print(a, b, c)

if __name__ == "__main__":
    solve()
```この実装では、まずボックス サイズのグローバル ターゲット分布を計算します。 次に、総移動コストを最小限に抑えるために、どのボックスを少し大きくする必要があるかを割り当てます。 その後、余剰ボックスを特定し、そのアイテムをソースとして機能できるように保管します。 赤字ボックスは貪欲に満たされ、常に次に利用可能な余剰ボックスからアイテムを消費します。 

微妙な点は、一意性制約はボックスに対してローカルであるため、その値を超えてアイテムのアイデンティティを追跡する必要がないということです。 アイテムがボックスから取り出されると、再度重複を引き起こすことはできないため、すぐに別の場所に置くのが安全です。

 ## 特殊なケース

 重要なエッジケースは、すべてのボックスがすでに最終的なサイズ条件を満たしているが、項目が選択されたターゲット分布に対して「適切な位置」にない場合です。 このアルゴリズムは、ボックスが割り当てられた容量を超えた場合にのみアイテムを移動するため、引き続き機能します。 

+1 の容量スロットを割り当てているときに、複数のボックスが最大サイズを獲得する場合、別のエッジ ケースが発生します。 それらの間の一貫した選択は有効であり、正確にどのボックスが追加スロットを受け取るかではなく、総余剰のみが重要であるため、アルゴリズムは正しいままです。 

最後の微妙なケースは、ボックスにターゲットよりも 1 つだけ多くのアイテムが入っている場合です。 この最小限の余剰状況であっても、アルゴリズムはそれをドナーとして一律に扱い、その単一アイテムは中間の再シャッフルを必要とせずに赤字ボックスに直接移動されます。
