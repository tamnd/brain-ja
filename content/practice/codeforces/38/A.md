 ## 解決策
 ## 問題の理解

 Vasya は現在ランクを保持しています`a`軍隊に所属しており、最終的には階級に到達したいと考えています`b`。 ランクからの移動`i`ランク付けする`i + 1`配列に格納される固定年数が必要です`d`。 

配列には長さがあります`n - 1`まさにあるから`n - 1`連続するランク間の移行。 例えば、`d[0]`ランクから移動するのに必要な年数を表します`1`ランク付けする`2`、 そして`d[1]`ランクから移動するのに必要な年数を表します`2`ランク付けする`3`。 

ランクに到達するには`b`, Vasyaはすべての中間ランクを順番に通過する必要があります。 つまり、合計時間は、次の移行間のすべての移行コストの合計にすぎません。`a`そして`b`。 

制約は非常に小さいです。`n`せいぜい`100`したがって、配列に対する単純なループでも十分高速です。 二次解も快適に通過します。最悪の場合でも次のように実行されるからです。`10,000`操作。 この問題は、最適化ではなく、慎重なインデックス作成に焦点を当てています。 

ランクには次から始まる番号が付けられているため、間違いの主な原因はインデックス作成が 1 つずつずれていることです。`1`、一方、Python の配列はからインデックスが付けられます。`0`。 

次の例を考えてみましょう。```
4
1 2 3
2 4
```正しい答えは次のとおりです。```
5
```ランクから時間が必要です`2`に`3`、つまり`2`、そしてから`3`に`4`、つまり`3`。 それらの合計は`5`。 

不注意な実装により、インデックスからの合計が誤って計算される可能性があります`2`を通して`4`、または間違った境界が含まれています。 

もう 1 つの簡単な間違いは、余分なセグメントを 1 つ含めることです。 

例：```
5
10 20 30 40
1 3
```正しい出力:```
30
```必要なトランジションは次のとおりです。`1 -> 2`そして`2 -> 3`、したがって、答えは次のとおりです`10 + 20 = 30`。 

誰かが誤ってインデックスを合計した場合`3`、トランジションが誤って含まれてしまいます。`3 -> 4`そして手に入れる`60`。 

## アプローチ

 最も直接的なアプローチは、昇進パスをランクごとにシミュレートすることです。 ランクから始める`a`に達するまで、次のランクに移動するために必要な年数を繰り返し加算します。`b`。 

この総当り的な方法は、最大でも`99`合計で移行します。 最悪の場合、配列全体を 1 回合計します。`O(n)`操作。 

これが機能する理由は、プロモーション構造が完全に直線的であるためです。 ランクからの可能なパスは 1 つだけです`a`ランク付けする`b`。 分岐、最短パス ロジック、動的プログラミングは必要ありません。 すべての有効な移動は、同じ連続する遷移を通過する必要があります。 

より複雑なソリューションでは、不必要なオーバーヘッドが追加されます。 重要な観察は、答えがまさに次の連続する部分配列の合計であるということです。`d`。 

具体的には、ランクを移動するには`a`ランク付けする`b`、次のものが必要です。```
d[a-1] + d[a] + ... + d[b-2]
```各配列要素が連続するランク間の 1 つのエッジを表すことが認識されると、実装は単純な範囲合計になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 この問題では、制約が小さく、構造が線形であるため、総当たりアプローチと最適アプローチは事実上同じです。 

## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`、ランクの数。 
2. 配列を読み取る`d`長さの`n - 1`。 

各要素は、あるランクから連続する次のランクに移動するのに必要な年数を表します。 
3. 整数の読み取り`a`そして`b`。 

Vasya の現在のランクは`a`そしてランクに到達したい`b`。 
4.初期化`answer = 0`。 

この変数は、必要な合計年数を累積します。 
5. 以下のインデックスを反復処理します。`a - 1`まで`b - 2`。 

これらはまさにヴァシャが完了しなければならない移行です。 
6. 対応する各値を次から追加します。`d`の中へ`answer`。 
7. 印刷`answer`。 

### なぜ効果があるのか

 各要素`d[i]`ランクからの移行に対応`i + 1`ランク付けする`i + 2`。 ランクから移動するには`a`ランク付けする`b`, Vasya は、その間の連続するすべてのトランジションを完了する必要があります。 

このアルゴリズムは、必要なトランジションのみを正確に合計します。 ランク間の可能なパスは 1 つだけであるため、この合計は一意に決定され、常に正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
d = list(map(int, input().split()))
a, b = map(int, input().split())

answer = 0

for i in range(a - 1, b - 1):
    answer += d[i]

print(answer)
```最初の 2 行は、ランクの数と、連続するランク間の移行コストを読み取ります。 

重要な詳細はループ範囲です。```
range(a - 1, b - 1)
```仮定する`a = 2`そして`b = 4`。 トランジションが必要です:```
2 -> 3
3 -> 4
```これらは配列インデックスに対応します。```
1 and 2
```Pythonでは、`range(1, 3)`まさにそれらのインデックスを生成します。 

ループはその前で停止します`b - 1`ランクに到達した後に誤って次の遷移を含めることを防ぎます。`b`。 

このソリューションでは、入力配列と 1 つのアキュムレータ変数のみを保存するため、一定の追加メモリを使用します。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())
    d = list(map(int, input().split()))
    a, b = map(int, input().split())

    ans = 0

    for i in range(a - 1, b - 1):
        ans += d[i]

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("3\n5 6\n1 2\n") == "5\n", "sample 1"

# minimum size input
assert run("2\n7\n1 2\n") == "7\n", "minimum case"

# all equal values
assert run("5\n3 3 3 3\n1 5\n") == "12\n", "all equal"

# off-by-one check
assert run("5\n10 20 30 40\n1 3\n") == "30\n", "boundary correctness"

# larger path
assert run("6\n1 2 3 4 5\n2 6\n") == "14\n", "multiple transitions"

print("All tests passed!")
```| テスト入力 | 期待される出力 | 検証内容 |
