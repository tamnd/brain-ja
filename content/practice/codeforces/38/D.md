 ## 解決策
 ## 問題の理解

 立方体を一つ一つ積み上げていきます。 すべての立方体は軸が揃っており、地面への投影は正方形です。 立方体は実際の立方体であるため、辺の長さは正方形の底辺によって決まります。 

キューブ`i`キューブの上に直接置かれます`i-1`。 それらの投影は正の領域と重なるため、上の立方体は常に前の立方体と物理的に接触します。 問題は、新しい立方体が前の立方体に触れているかどうかではなく、タワー全体が重力の下でバランスを保っているかどうかです。 

すべての立方体がその上にあるすべての立方体の合計重心を支えていれば、タワーは安定しています。 キューブ用`i`からのすべての立方体を考慮します。`i`頂上へ。 それらを組み合わせた重心は、立方体間の重なり領域の内側に厳密に存在する必要があります。`i-1`そして立方体`i`。 もしそれがそのエリアを離れることがあれば、立方体`i`崩壊、建設中止、そしてすべてのより高いキューブは無関係です。 

入力により、すべての正方形の底面の反対側の角の座標が得られます。 これらの座標から次のことを導き出すことができます。 

- 辺の長さ、
 - 立方体の質量、次の値に等しい`side^3`、
 - 正方形の中心。 

安定したキューブの最大プレフィックスを出力する必要があります。 

制約は小さいですが、`n ≤ 100`。 それは問題を完全に変えます。 高度なジオメトリ構造や最適化のトリックは必要ありません。 アン`O(n^3)`ソリューションはすでに小さく、約 100 万操作です。 

危険な部分はパフォーマンスではなく、物理学を正しくモデル化することです。 

よくある間違いは、現在の立方体の中心が重なり部分の内側にあるかどうかだけをチェックすることです。 実際の状態は、接触面上のサブタワー全体の質量中心によって異なります。 

次の例を考えてみましょう。```
3
0 0 10 10
4 0 14 10
8 0 18 10
```2 番目と 3 番目の立方体はうまく重なり、個々の立方体の中心はすべて、前の立方体との重なり合いの内側にあります。 しかし、上部の立方体が一緒になって重心を右に大きく移動させると、下部の接触が不安定になります。 

もう 1 つの簡単なバグは、非厳密な不等式を使用することです。 重心はサポート領域内に厳密に存在する必要があります。 境界に触れるということは、許容範囲がゼロの完全なバランスを意味し、問題では落下として扱われます。 

例：```
2
0 0 2 2
1 0 3 2
```x 方向の重なりは次のとおりです。`[1, 2]`。 重心が正確になれば`1`または`2`、タワーが不安定です。 

3 番目の微妙な問題は、すべての中間タワーで安定性を維持する必要があることです。 キューブであっても`1..5`一緒に何とか再び安定しますが、答えはまだ最初の失敗によって決まります。 

例：```
4
0 0 10 10
7 0 17 10
8 0 18 10
0 0 10 10
```立方体 3 がすでに崩壊を引き起こしている場合、立方体 4 は現実に配置されることはありません。 

## アプローチ

 ブルートフォースのアイデアは物理学に直接準拠しています。 

すべてのプレフィックスに対して`1..k`、タワーが安定しているかどうかをテストします。 安定性をテストするために、サポートを上から下に加工します。 キューブ間のサポート用`i-1`そして`i`、立方体の質量中心を計算します。`i..k`。 その点が立方体の重なり合う長方形の内側に厳密に存在する場合`i-1`そして`i`、サポートは存続します。 そうしないと塔が崩壊します。 

重心の計算は簡単です。$$cx = \frac{\sum m_j x_j}{\sum m_j}$$そして同様に`cy`。 

これが機能するのは、各サポートがその上の総質量のみを考慮するためです。 

単純な実装では、毎回これらの合計を最初から再計算します。 あらゆる人にとって`k`、あらゆるサポートに対して`i`、すべての立方体をスキャンします`j ≥ i`。 それには費用がかかります`O(n^3)`。 

と`n = 100`、 平`100^3 = 10^6`動作は全く問題ありません。 公式の難しさは、実行時間ではなく、ジオメトリの推論に起因します。 

それでも、接尾辞の累積を使用して実装を簡素化できます。 下方向に反復している間、現在のサポートを超えるすべての立方体の総質量と重み付けされた座標の合計を維持します。 次に、各重心クエリは次のようになります。`O(1)`。 

重要な観察は、サポートの上にある合計の質量中心がわかれば、サポートは独立しているということです。 トルクや力を明示的にシミュレートする必要はありません。 均一な重力と軸が揃った立方体により、点が長方形の中にあるかどうかをチェックするだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | お(1) | 承認済み |
 | 最適 | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての立方体を読み取り、その座標を正規化します。`x1 < x2`そして`y1 < y2`。 
2. すべての立方体について、次を計算します。 

- 辺の長さ`a = x2 - x1`、
- 質量`m = a^3`、
 - 中心座標:$$cx = \frac{x1 + x2}{2}, \quad cy = \frac{y1 + y2}{2}$$1. タワーのサイズを反復処理します。`k`から`1`に`n`。 立方体かどうかをテストします`1..k`安定した塔を形成します。 
2. それぞれについて`k`、プロセスは上から下までサポートします。 

立方体間のサポート`i-1`そして`i`キューブを持ち歩かなければならない`i..k`。 
3. 以下を維持します。 

- 現在のサポートを超える総質量、
 - 重み付けされた x 和、
 - 重み付き y 和。 

最初は立方体のみが含まれています`k`。 下に移動するにつれて、さらに立方体を追加します。 
4. 立方体の質量中心を計算する`i..k`:$$com_x = \frac{sx}{sm}, \quad com_y = \frac{sy}{sm}$$1. 立方体間の重なり合う長方形を計算します。`i-1`そして立方体`i`:$$lx = \max(x1_{i-1}, x1_i)$$

$$rx = \min(x2_{i-1}, x2_i)$$y についても同様です。 

1. 重心が厳密にオーバーラップの内側にあるかどうかを確認します。$$lx < com_x < rx$$

$$ly < com_y < ry$$どちらかの条件が満たされない場合、立方体`i`バランスを失う、そして答えは`k-1`。 

1. すべてのサポートが生き残った場合は、次のステップに進みます。`k`。 
2. すべてのプレフィックスが安定している場合、出力`n`。 

### なぜ効果があるのか

 どのような支持面でも、静的平衡において重要なのは、その面の上にあるすべてのものの総質量中心の投影だけです。 その突起が支持領域の内側にある場合、重力によって転倒トルクは発生しません。 エリアから離れるとタワーが回転して落下します。 

アルゴリズムは、すべてのプレフィックス タワーのすべてのサポートについてこの条件を正確にチェックします。 考えられるすべての障害点がテストされ、各テストが物理的安定性基準に一致するため、アルゴリズムがタワーを誤って分類することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    cubes = []

    for _ in range(n):
        x1, y1, x2, y2 = map(int, input().split())

        if x1 > x2:
            x1, x2 = x2, x1
        if y1 > y2:
            y1, y2 = y2, y1

        side = x2 - x1
        mass = side ** 3

        cx = (x1 + x2) / 2.0
        cy = (y1 + y2) / 2.0

        cubes.append((x1, y1, x2, y2, mass, cx, cy))

    for k in range(n):
        sm = 0.0
        sx = 0.0
        sy = 0.0

        for i in range(k, -1, -1):
            x1, y1, x2, y2, mass, cx, cy = cubes[i]

            sm += mass
            sx += mass * cx
            sy += mass * cy

            if i == 0:
                continue

            px1, py1, px2, py2, _, _, _ = cubes[i - 1]

            lx = max(px1, x1)
            rx = min(px2, x2)

            ly = max(py1, y1)
            ry = min(py2, y2)

            com_x = sx / sm
            com_y = sy / sm

            eps = 1e-9

            if not (lx + eps < com_x < rx - eps and
                    ly + eps < com_y < ry - eps):
                print(k)
                return

    print(n)

solve()
```最初の部分では、座標を正規化し、すべての物理量を一度に計算します。 後で生のジオメトリの代わりに中心を使用すると、実装がコンパクトに保たれます。 

外側のループはプレフィックスを段階的にテストします。 いつ`k = 4`たとえば、立方体かどうかをチェックしています。`1..5`安定してください。 

そのループ内で、累積質量情報を維持しながらサポートを通って下に移動します。 これにより、重心を繰り返し再計算することがなくなります。 

重なり合う四角形は、間隔の交差を使用して計算されます。 この問題では、連続する立方体間の正の重複が保証されるため、`lx < rx`そして`ly < ry`常に幾何学的に成り立ちます。 

厳密な不平等は重要です。 ちょうど境界上にある重心は不安定です。 浮動小数点比較では、精度ノイズを避けるために小さなイプシロンが使用されます。 

もう 1 つの微妙な点は、更新の順序です。 まず立方体を追加します`i`累積合計に変換し、サポートをテストします`(i-1, i)`。 そのサポートはキューブを運びます`i..k`、上記の立方体だけではありません`i`。

 ## 特殊なケース

 厳密な境界の場合を考えてみましょう。```
2
0 0 4 4
2 0 6 4
```Cube 2 には中心があります`x = 4`。 立方体 1 との重なりは、`[2,4]`。 中心がちょうど境界線上にあるため、支持が不安定です。 

アルゴリズムは以下を計算します。 

| 数量 | 値 |
 | --- | --- |
 | オーバーラップ | (2,4) |
 | 重心 | 4 |
 | チェック | 2 < 4 < 4 |

 最後の不等式は成立しないので、答えは次のようになります。`1`。 

ここで累積不均衡を考えてみましょう。```
3
0 0 10 10
4 0 14 10
8 0 18 10
```キューブ 3 だけではキューブ 2 上で安定しています。危険な部分は下部サポートです。 

キューブ 1 と 2 の間のサポートの場合:

 | 数量 | 値 |
 | --- | --- |
 | 大衆 | 1000 と 1000 |
 | センター | 9と13 |
 | 結合COM | 11 |
 | オーバーラップ | (4,10) |

 以来`11`オーバーラップの外側にある場合、下部サポートは失敗します。 アルゴリズムは、下方累積合計の処理中にこれを検出します。 

最後に、座標の正規化について考えます。```
2
4 4 0 0
1 1 3 3
```最初の正方形は逆の順序で与えられます。 正規化を行わないと、辺の長さが負になり、ロジックが壊れてしまいます。 

アルゴリズムは座標を交換し、すべての正方形が次のようになります。```
(0,0)-(4,4)
(1,1)-(3,3)
```正規化後、すべての幾何学的計算が正しく機能し、出力は次のようになります。`2`。
