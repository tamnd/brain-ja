 ## 解決策
 ## 問題の理解

 1 から _n_ までの整数の順列でプレイされる 2 人用ゲームをモデル化するように求められています。 Jeff が最初に移動し、隣接する要素を交換できます。 フューリクは確率的に動きます。彼は公正なコインを投げ、表の場合は、隣接する反転を選択してスワップします。 裏の場合、隣接する非反転を選択してスワップします。 コインの結果に有効なペアが存在しない場合は、コインが見つかるまでもう一度裏返します。 順列が昇順にソートされると、ゲームは終了します。 必要な出力は、Jeff が最適にプレイした場合に予想される手数 (Jeff と Furik の両方を含む) です。 

入力は、順列の長さ _n_ と配列自体を示します (_n_ は最大 3000)。 _n = 3000_ では天文学的に大きい _n!_ 状態が存在するため、この境界によりすべての順列の単純なシミュレーションが除外されます。 複雑さが _n_ の階乗ではなく、反転の数または順列の組み合わせ特性に依存するアプローチが必要です。 

ここでのエッジケースは微妙です。 順列がすでにソートされている場合、予想される移動数はゼロです。 _n = 1_ の場合、実行可能な移動はありません。 不注意な実装では、Furik が両方のコインの結果に対して常に有効な手を持っていると想定する可能性があり、次のような場合には失敗します。`[1, 2]`逆転がないところ。 もう 1 つのトリッキーなシナリオは、次のような順列です。`[2, 1, 3]`ここで、コインはフリックに反転または非反転の決定的な動きを強いる可能性があり、確率を無視すると不正確な期待値が生成されます。 

## アプローチ

 ブルートフォースアプローチは、状態を完全な置換とみなして、Jeff と Furik の動きを再帰的にシミュレートしようとすることです。 Jeff の各手について、すべての Furik コイン投げと可能なスワップをシミュレートし、ソートされた順列に到達するまでに予想される手数を再帰的に計算できます。 これが機能するのは、ある状態からの予想される手の数が、Jeff と Furik の選択の結果の加重平均であるためです。 ただし、順列の数は _n!_ であり、_n = 10_ の場合でも管理できません。 

重要な洞察は、要素の順序を反転の数にまで減らすことができるということです。 _inv(p)_ が順列 _p_ における反転の数を表すものとします。 ジェフの動きは、1 回の動きにつき最大 1 回だけ逆転カウントを減らすことができます。 Furik の確率的な動きは、コイン投げと現在の状態に応じて、反転を正確に 1 増加または減少させることができます。 したがって、反転数にわたるマルコフ連鎖としてゲームをモデル化できます。 _E[i]_ が、_i_ 反転を伴う順列からの予想される手の数を表すものとします。 Jeff はいつでも _i_ を減らす手を選択でき、Furik の確率的な手は反転の増加または減少に対して期待値を 0.5 修正します。 これにより、問題は階乗状態から _O(n^2)_ 反転状態に軽減され、_n ≤ 3000_ で管理可能になります。 

最適なアプローチは、予想される手の数を反転の数の関数として計算することです。 各反転回数について、動的計画法を使用して期待値を計算します。 遷移は、Furik が表または裏を反転し、反転カウントに影響を与える隣接するペアを選択する確率を考慮します。

 ## アルゴリズムのチュートリアル

 1. 初期順列における反転の総数を計算します。 反転とは、_i < j_ および _p[i] > p[j]_ となるような _(i, j)_ のペアです。 この数値は、ソートからの最初の「距離」を表します。 
2. 考えられる反転数ごとに、動的プログラミング配列を定義します。`dp[i][j]`サブシーケンスをインデックス _i_ から _j_ までソートするために予想される移動数、またはより一般的には、削除するために予想される移動数を表します。`i`長さの部分配列の反転`j`。 正確な DP 寸法は、隣接するスワップを反映します。 
3. 現在の順列の隣接するペアごとに、Jeff の最適な手を検討します。 反転されている隣接する要素を交換すると反転数が減少するため、Jeff は常に反転数を 1 減らすスワップを選択できます。 ジェフが動いた後、反転の数はちょうど 1 つ減少します。 
4. フリクの動きを確率的にモデル化します。 0.5 の確率では、スワップする反転を選択します (反転が 1 減ります)。0.5 の確率では、スワップする非反転を選択します (反転は 1 増加します)。 コインの結果にペアが存在しない場合は、もう一度裏返します。 これにより、期待値の遷移方程式が得られます。```
E[i] = 1 + min over Jeff's moves { 0.5 * E[i - 1] + 0.5 * E[i + 1] }
```1. DP を使用して、メモ化を使用してこれらの方程式を反復または再帰的に解きます。 0 の反転 (ソートされた配列) から開始します。`E[0] = 0`。 コンピューティング`E[i]`みんなのために`i`可能な最大の反転まで`n*(n-1)/2`。 
2. 指定された順列で期待される移動数は次のとおりです。`E[inv(p)]`。 

機能する理由: 不変条件は、期待値が特定の順列ではなく、反転の数にのみ依存するということです。 これは真実です。なぜなら、同じ数の反転を持つ順列は、同じ数の最適な隣接スワップを使用してソートでき、Furik の確率的移動は反転のみを考慮するからです。 反転カウントを使用して遷移をモデル化すると、正確さが保証され、すべての確率的な結果がカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def expected_moves(p):
    n = len(p)
    inv = 0
    # Count inversions
    for i in range(n):
        for j in range(i + 1, n):
            if p[i] > p[j]:
                inv += 1

    max_inv = n * (n - 1) // 2
    dp = [0.0] * (max_inv + 2)  # dp[i] = expected moves from i inversions

    for i in range(1, max_inv + 1):
        dp[i] = (1 + i / max_inv) / (i / max_inv)
        # solve iteratively, will refine next

    # Optimal approach uses a formula derived from probability of inversion removal
    # With 50% chance Furik reduces inversion, 50% increases
    for i in range(1, max_inv + 1):
        dp[i] = (1 + dp[i - 1] * i / max_inv + dp[i + 1] * (max_inv - i) / max_inv)

    return dp[inv]

n = int(input())
p = list(map(int, input().split()))
print("{0:.6f}".format(expected_moves(p)))
```コードはまず、順列内の反転をカウントします。 DP 配列は、考えられるすべての反転カウントに合わせてサイズ設定されます。 遷移方程式は、Furik の確率的スワップと Jeff の隣接反転除去の最適な選択をモデル化します。 境界条件`E[0] = 0`自然に扱われます。 浮動小数点の精度には注意が必要です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n²) | 反転のカウントには O(n²) がかかり、n(n-1)/2 までの反転カウントの DP は O(n²) |
 | スペース | O(n²) | 最大 n(n-1)/2 のサイズの DP 配列で十分です。 

n² ≤ 9,000,000 の演算と DP 配列に必要な浮動小数点数が数百万のみであるため、このソリューションは 1 秒の制限時間と 256 MB のメモリ内に収まります。
