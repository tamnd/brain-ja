 ## 解決策
 ## 問題の理解

 いくつかのカフェの候補地と飛行機内のいくつかのランドマークポイントが与えられました。 固定カフェの場所ごとに$C_i$、異なるランドマークのすべてのペアを考慮します$L_j, L_k$。 それぞれのペアとカフェが三角形を形成します$C_iL_jL_k$。 

次に、任意の点を選択するところを想像してください$P$飛行機の中。 固定カフェの場合$C_i$のスコアを定義します。$P$三角形とのランドマークペアの数として$C_i$厳密に含まれています$P$。 カフェの場所とポイントの両方を選択できます$P$、可能な限り最大のスコアが必要です。 

キーの構造は、固定の$C_i$、単一の点を評価しようとしているわけではありません。$P$ですが、代わりに、多くの三角形の重なりが平面内のどこで最大になるかを尋ねます。 

各テスト ケースでは最大 400 のカフェと 400 のランドマークが与えられ、テスト ケースは多数ありますが、すべてのテストの合計ポイント数には制限があります。 これは、構成ごとに 2 次または 3 次に近い解決策は許容されるが、すべてのトリプルを処理したり、三角形ごとおよびクエリ ポイントごとにジオメトリを明示的に処理しようとした場合は失敗することを強く示唆しています。 

素朴な試みとしてはカフェを選ぶでしょう$C_i$、すべて列挙します$\binom{M}{2}$次に、平面上の深度マップを計算するか、三角形の境界の交差によって形成される候補点をテストします。 それはすぐに手に負えなくなる。$O(M^2)$三角形は生み出すことができます$O(M^4)$原則として交差点の複雑さ、さらに候補点の反復が大きすぎます。 

より微妙な故障モードは、ある点を修正しようとすることで発生します。$P$配向条件をチェックして、それを含む三角形を数えます。 それには必要になります$O(M^2)$あたり$P$、しかし、関連する明白な有限セットはありません。$P$これらの三角形がどのように重なるかの幾何学的形状を理解しない限り、候補の正確性は保証されません。 

小さな落とし穴の例としては、最適な$P$必ずしもランドマークやカフェの地点である必要はなく、ランドマークを通る 2 つの線の交点である必要もありません。 これは、組み合わせの重複を最大化することによって定義されるため、単純な候補の削減は信頼できません。 

## アプローチ

 カフェの場所を修正する$C_i$。 問題は次のようになります。$C_i$2 つのランドマークとポイントを見つけます$P$それはこれらの三角形の最大数にあります。 

有用な幾何学的な再定式化は、三角形に関する推論から光線に関する推論に切り替えることです。$C_i$。 ポイント$P$三角形の中にあります$C_iL_jL_k$光線が次から始まる場合に限り、$C_i$方向に$C_iP$セグメントと交差します$L_jL_k$。 これにより、問題は、光線が「当たった」ランドマーク セグメントの数を数えるという問題に変換されます。 

だから固定のために$C_i$そして方向$\theta$、からの光線を定義します$C_i$。 各ペア$(L_j, L_k)$セグメントが貢献する場合$L_jL_k$その光線と交差します。 の答えは、$C_i$すべての光線方向にわたる交差するセグメントの最大数です。 

次に、2 つのランドマークを見てください。 という観点からすると、$C_i$、各ランドマークには極角があります。 セグメント$L_jL_k$方向に光線が交差します$\theta$まさにいつ$\theta$～の角度の間にあります$L_j$そして$L_k$周囲の小さな円弧に沿って$C_i$。 言い換えれば、各ペアは、角円上の間隔を定義します。$C_i$、そして、単一の角度をカバーするこれらの間隔の最大数が必要です。 

したがって、それぞれについて$C_i$、問題は円区間の重複問題になります。$O(M^2)$間隔。 角度範囲を 2 倍にしてスイープすることで線に変換します。 

ブルートフォースアプローチでは、すべての方向を明示的にテストするか、角度を離散化しますが、任意の 2 つのランドマーク方向の間で最適値が発生する可能性があるため、これは失敗し、継続的な検索が必要になります。 間隔スイープは、すべての最適な方向の候補を捕捉します。

 ## アルゴリズムのチュートリアル

 各カフェごとに独自に処理します。 

1. カフェポイントを修正する$C_i$。 すべてのランドマークを相対的な極座標に変換します。$C_i$で角度を計算します。$[0, 2\pi)$。 

すべての三角形構造は絶対座標ではなく、カフェからの方向のみに依存するため、これが必要です。 
2. すべてのランドマークを極角ごとに並べ替えます$C_i$を追加してリストを複製します。$2\pi$円形のラップアラウンドを処理するために各角度に調整します。 

これにより、円形の間隔を線形の間隔として扱うことができます。 
3. ランドマークのペアごとに$L_j, L_k$、すべての方向を表す角度間隔を構築します。$\theta$どのセグメントから$L_jL_k$～からの光線を通して見える$C_i$。 

具体的には、この間隔は、それらの角度の間の円に沿った、短手方向に沿った開いた円弧です。$C_i$。 
4. このような間隔ごとに、スイープ構造の開始角度に +1 イベントを追加し、終了角度に -1 イベントを追加します。 

これは、考えられる光線方向ごとに交差するセグメントの数をエンコードします。 
5. すべてのイベントを角度ごとに並べ替え、それらをスイープして、累計を維持します。 

検出された最大値は、この固定カフェの三角形の最適な数です。 
6. すべてに対して繰り返します$C_i$すべてのカフェの最大値を取得します。 

### なぜ効果があるのか

 固定カフェの場合$C_i$、すべての三角形$C_iL_jL_k$得点に貢献する$P$まさに光線が当たったとき$C_iP$によって決定される角度間隔内にあります。$L_j$そして$L_k$。 これにより、各三角形が方向の円上の間隔に縮小されます。 任意の点$P$からの方向に一意に対応します$C_i$したがって、三角形の包含を最大化することは、最大の間隔の重なりを持つ方向を見つけることと同じです。 角度の端点をスイープすると、組み合わせ的に異なる方向領域がすべてチェックされ、最適な値が見逃されないことが保証されます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        N, M = map(int, input().split())

        cafes = [tuple(map(int, input().split())) for _ in range(N)]
        lands = [tuple(map(int, input().split())) for _ in range(M)]

        ans = 0

        for cx, cy in cafes:
            angles = []
            for x, y in lands:
                angles.append(math.atan2(y - cy, x - cx))

            angles.sort()

            a = angles
            n = len(a)

            events = []

            for i in range(n):
                for j in range(i + 1, n):
                    ai, aj = a[i], a[j]
                    # normalize difference to (0, 2pi)
                    d = aj - ai
                    # choose minor arc interval where ray lies between them
                    if d < 0:
                        d += 2 * math.pi

                    # interval is (ai, aj) on circle, but ensure it is minor arc
                    if d > math.pi:
                        # swap to take other arc
                        start = aj
                        end = ai + 2 * math.pi
                    else:
                        start = ai
                        end = aj

                    events.append((start, 1))
                    events.append((end, -1))

            events.sort()

            cur = 0
            best = 0
            for _, v in events:
                cur += v
                best = max(best, cur)

            ans = max(ans, best)

        print(ans)

if __name__ == "__main__":
    solve()
```この実装ではカフェを修正し、すべてのランドマークをその周囲の角度に変換します。 すべてのランドマークのペアは角円上の間隔になり、イベントのエンドポイントをスイープすることにより、そのような間隔が最適な方向で重なる数を数えます。 

微妙な点は、角度の円形の性質を処理することです。 このコードは、間隔を次の範囲を超えて延長できるようにすることで、この問題を解決します。$2\pi$、ラップアラウンド間隔が線形になるように円を効果的に展開します。 

もう 1 つの重要な詳細は、各ペアが小さい円弧に対応する 1 つの間隔に正確に寄与することです。 より大きな円弧を選択すると、有効な光線の交差に対応しない方向が誤って二重にカウントされます。 

## 実用的な例

 原点に 1 つのカフェがあり、斜めに配置された 4 つのランドマークを考慮します。$0^\circ, 90^\circ, 180^\circ, 270^\circ$。 各ペアはマイナー アーク間隔を定義します。 

| ペア | 角度間隔 (度) |
 | --- | --- |
 | (0, 90) | (0, 90) |
 | (0, 180) | (0, 180) |
 | (0, 270) | (270, 360) U (0) は unwrap | によって処理されます。 
| (90, 180) | (90, 180) |
 | (90, 270) | (90, 270) |
 | (180, 270) | (180, 270) |

 これらの間隔をスイープすると、最大のオーバーラップが付近で発生します。$90^\circ$に$180^\circ$、複数の円弧が交差する場所。 

これは、最適な方向が、多くのランドマーク ペアがカフェからの光線を同時に「見る」領域に対応することを示しています。 

ここで、ランドマークが 1 つの半円の中に集まっているという、歪んだ構成を考えてみましょう。 次に、ほとんどのペアがその密集領域をカバーする間隔を生成し、スイープではそのクラスターの中心近くに明確なピークの重複が示され、最良のビュー方向はランドマークの最も密集した角度集中方向であるという直観と一致します。

 ## 特殊なケース

 最初の微妙なケースは、すべてのランドマークがカフェの周囲の狭い角度のセクター内にある場合です。 この状況では、ほとんどのペアは、ほぼ同じ領域をカバーする重複する間隔を生成します。 すべての間隔が密集したスイープ領域に収まり、最大のオーバーラップがそのクラスター内のペアの組み合わせ爆発を反映するため、アルゴリズムはこれを正しく処理します。 

もう 1 つのケースは、ランドマークが円の周りに等間隔に配置されている場合です。 ここでは、強く有利な方向はなく、それぞれの間隔は短いです。 多くのペア間隔内に同時に角度方向が存在しないため、スイープは比較的均一な低い最大値を正確に示します。 

最後のケースは、ラップアラウンド ペアです。この場合、1 つのランドマークは小さな角度にあり、もう 1 つは近くにあります。$2\pi$。 間隔の構築はそれを超えて拡張する必要があります$2\pi$、角度の複製により、これらの間隔が展開されたライン上で連続したセグメントとして表示されることが保証されます。 拡張イベント リストのスイープでは、寄与を誤って分割することなく、これらを正しくカウントします。
