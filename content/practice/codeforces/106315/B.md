 ## 解決策
 ## 問題の理解

 私たちには、隠された単語が既知の語彙から来ており、固定されたアルファベットの文字が使用されている、制約付きバージョンのハングマンが与えられています。 ゲームは、推測者が単語内のすべての文字を発見するか、不正確な推測が多すぎるまで続きます。 

おもしろいのは、セッターが戦略的に行動することが許可されていることです。後から語彙内の少なくとも 1 つの単語との一貫性を正当化できる限り、ゲーム中に隠し単語を事実上自由に「シフト」できます。 シーザーは、最後にジョセフが 1 つの決まった語彙を指し、すべての応答がその単語と一致していることを証明できる必要があることを要求することで、これを阻止しようとします。 

したがって、質問はゲームのシミュレーションに関するものではありません。 それは、シーザーがどのように文字を推測しても、ジョセフが常に少なくとも 1 つの候補単語をすべての答えと一貫性を保つことができる一方で、シーザーが n 個の間違った推測を使い果たす前に単語を終えることができないようにするような語彙と戦略をジョセフが構築できるかどうかにかかっています。 

入力により、アルファベットのサイズ a、語彙のサイズ v、単語の長さ l、および許容される誤った推測の数 n が得られます。 アルファベットは抽象的なものであり、重要なのはそのサイズだけです。 語彙には v 個の単語が含まれており、それぞれの長さはアルファベットの l です。 私たちは、ジョセフが勝利戦略の存在を保証できるかどうかを判断する必要があります。 

テスト ケースごとの制約は小さく、すべての値は最大 26 ですが、テスト ケースの数は最大 2 × 10^5 と大きくなります。 これは、テスト ケースごとにソリューションが O(1) または O(log 26) でなければならないことを意味します。 言葉を超えた構築やシミュレーションは不可能です。 

単純に読むと、実際の単語を基に構築したり推論したりすることを示唆するかもしれませんが、重要なのはカウントのみであるため、問題は敵対的な文字クエリの下で単語を分離する組み合わせの実現可能性に帰着します。 

語彙サイズが 1 の場合、微妙な特殊なケースが発生します。その場合、Joseph には柔軟性がありません。 シーザーは、ジョセフに解釈を「切り替える」ことを決して許さずに、単語を推測し、正しい推測を強制することができます。 これにより、ほとんどの興味深い戦略が即座に失格になります。 

もう 1 つの重要なエッジ ケースは、許可される不正な試行 n が非常に小さい場合です。 n が 1 に等しい場合、手紙の不在を早期に暴露することを常に回避できない限り、ジョセフは 1 つの不一致ですでにゲームに負けます。 

最後に、語彙サイズ v とアルファベット サイズ a の間の相互作用が重要です。 v が文字全体の識別可能なパターンの数に比べて大きすぎる場合、Joseph は推測全体のあいまいさを維持できません。 

## アプローチ

 ブルートフォース解釈では、考えられるすべての語彙を列挙し、敵対的な推測をシミュレートしようとします。 語彙ごとに、シーザーが最適な順序で文字を選択し、ジョセフが一貫した単語を切り替えながら応答することをシミュレートします。 単一のテスト ケースであっても、可能な語彙の数は a^l 個の単語の組み合わせのオーダーであり、これは天文学的に膨大です。 与えられた v 語に限定しても、推測の相互作用ツリーは n で指数関数的に成長します。 これにより、直接シミュレーションが不可能になります。 

重要な観察は、ジョセフの力は、一連の文字のクエリの下で区別できない単語をどれだけ多く保持できるか、そして文字の推測を避ける「安全な」単語がどれだけ存在するかによってのみ決まるということです。 推測するたびに、語彙がその文字を含む単語と含まれない単語に分割されます。 ジョセフは、シーザーがすべての曖昧さをすぐに排除しないようにしながら、少なくとも 1 つの単語を残す側を常に選択できるかどうかの推測に耐えます。 

これは、問題を単純な極限条件に変換します。ジョセフは、n 回の強制的な削除に耐えられる十分な柔軟性が語彙に含まれており、アルファベットが一意に固定されるのが早すぎることを避けるのに十分な大きさの単語を構築できる場合にのみ成功します。

これを明確に理解する方法は、情報漏洩の観点から考えることです。 推測が間違っていると、単語の「安全なプール」が減ります。 ジョセフは、このように n 回削減した後でも、すべての応答に一致する有効な単語が少なくとも 1 つ残ることを確認できれば勝ちです。 各単語はアルファベットのサイズ a に対して長さ l であるため、識別可能なパターンの効果的な分岐は、単語に含まれていない文字の数と、回避パターンを共有する単語の数によって制御されます。 

これは単純な実現可能性チェックに集約されます。ジョセフは、最大 n 個の推測文字のシーケンスに対して、少なくとも 1 つの単語がすべての推測文字を回避できるように、語彙全体に異なる「回避署名」を割り当てるのに十分な個別の単語を必要とします。 これは、回避できる最大 n 個のサイズの文字のサブセットの数に比べて語彙サイズが十分に大きい場合にのみ可能です。 各単語は文字の一部を回避することができ、個別の回避プロファイルの数は、単語に存在しない文字を選択できる方法の数によって制限されます。 

制限要因は、単語が「生き残る」ことができる文字を選択する方法の数となり、アルファベットのサイズ a と推測の数 n によって決まります。 重要な単純化は、各単語はその文字に一致する推測でのみ失敗する可能性があり、長さ l の単語は l 個の文字を使用するため、その文字セット以外の推測の影響を受けないことです。 したがって、ジョセフの最善の戦略は、n 個までのすべての推測文字を避ける文字セットを持つ単語が常に存在するように単語を分散することです。 

これは古典的な鳩の穴スタイルの条件につながります。ジョセフは、語彙サイズ v が、少なくとも 1 つの素な単語を残しつつ、シーザーによって「ブロック」できる最大 n のサイズのアルファベットの個別のサブセットの数以上である場合にのみ生存を保証できます。 これにより、v が n 個の推測によって引き起こされるすべての危険な構成をカバーするのに十分な大きさであるかどうかのみに基づくしきい値条件にさらに単純化されます。 

この問題では、アルファベットのサイズは最大 26 文字であるため、重要な洞察は、唯一関連する数量は、最大 n 個の文字のセットを回避できる単語が存在するかどうか、およびそのような構造的に異なる単語が語彙に十分に含まれているかどうかであるということです。 これは、v が n によって決定されるしきい値を超えているかどうかをチェックすることに帰着します。n 回の誤った試行の後、Caesar がすべての候補を除外できないことを保証するには、ジョセフには少なくとも n + 1 個の個別のフォールバック オプションが必要です。 

したがって、最終条件は、v が n より大きいかどうかになります。

 ## アルゴリズムのチュートリアル

 この解決策は、テスト ケースごとに 1 つの不等式をチェックすることになります。 

1. a、v、l、n を読み取ります。 値 a と l は最終条件に影響を与えません。これは、Joseph が生き残れるかどうかは、許容される失敗に対して、明確なフォールバック ワードがどれだけ存在するかによってのみ決まるためです。 
2. v と n を比較します。 直感的には、間違った推測はそれぞれ単語を区別する際の自由度を最大 1 つ取り除き、n 回すべての間違った試行の後でも、ジョセフは常に少なくとも 1 つの一貫した単語を保持する必要があるということです。 
3. v が n より大きい場合は YES を出力し、それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 重要な不変条件は、ジョセフがすべての推測シーケンスと一致する語彙を少なくとも 1 つ維持しなければならないと同時に、シーザーが最大 n 個の間違った文字を使用してすべての候補を強制的に排除できないようにすることです。 それぞれの誤った推測は、語彙の構造内で最大でも 1 つの独立した「回避オプション」を削除していると解釈できます。 利用可能なエスケープオプションの数が n を超える場合、ジョセフは常に、すべての強制的な矛盾を回避する残りの単語に展開するゲーム状態をマッピングできます。 v が最大でも n の場合、シーザーは、ジョセフが単一の一貫した説明を安全に実行できる前に、各単語が候補として無効になるように推測をスケジュールできます。

これにより、単純なしきい値の比較が勝者の可能性を正確に特徴づけることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, v, l, n = map(int, input().split())
        if v > n:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```ゲームの構造上の複雑さはすべて 1 つの比較に集約されるため、実装は直接的です。 変数 a と l は、完全を期すために読み取り専用です。 臨界値は、ジョセフが保持できる別個の代替単語の数を表す v と、シーザーが誤った推測を強制的に除去できる数を表す n です。 

各テスト ケースは独立しているため、追加のデータ構造は必要なく、前処理も必要ありません。 

## 実用的な例

 v が 3、n が 2 である最初のサンプルケースを考えてみましょう。ジョセフには 3 つの単語があり、シーザーは最大 2 つの間違った推測をすることができます。 3 は 2 より大きいため、ジョセフは常に、進化するゲーム状態と一致する少なくとも 1 つの単語を保持します。 

| ステップ | v | n | 決定 |
 | --- | --- | --- | --- |
 | 開始 | 3 | 2 | 比較 |
 | チェック | 3 > 2 | 本当 | はい |

 これは、語彙がシーザーの最大強制力よりも高い柔軟性を提供していることを示しています。 

ここで、v が 1、n が 3 の場合を考えてみましょう。たった 1 つの単語では、ジョセフには解釈を変更する柔軟性がありません。 

| ステップ | v | n | 決定 |
 | --- | --- | --- | --- |
 | 開始 | 1 | 3 | 比較 |
 | チェック | 1 > 3 | 偽 | いいえ |

 これは、単一の固定単語では、間違った推測が繰り返された場合に敵対的な隠蔽をサポートできないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(t) | テスト ケースごとに 1 つの定数時間比較 |
 | スペース | お(1) | 入力変数以外に追加のストレージはありません |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        a, v, l, n = map(int, input().split())
        out.append("YES" if v > n else "NO")
    return "\n".join(out)

# provided samples
assert run("5\n9 3 3 2\n11 2 6 1\n10 5 4 3\n26 1 5 3\n26 26 26 26\n") == "YES\nYES\nYES\nNO\nNO"

# minimum-size case
assert run("1\n1 1 1 1\n") == "NO"

# boundary just above threshold
assert run("1\n1 2 1 1\n") == "YES"

# large vocabulary, small n
assert run("1\n26 26 26 1\n") == "YES"

# equal boundary case
assert run("1\n5 5 5 5\n") == "NO"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | v = n + 1 | はい | 最小限の勝利ケース |
 | v = n | いいえ | 境界の失敗 |
 | v = 1 | いいえ | 単一単語の制限 |
 | 大きい v、小さい n | はい | 語彙力が高いという利点 |

 ## 特殊なケース

 v が 1 に等しい場合、Joseph は候補単語を適応的に切り替えることができないため、アルゴリズムは直ちに NO を返します。 一連の推測は単一の固定単語に対して検証できます。つまり、Caesar は曖昧さなく体系的に文字を削除できます。 

たとえば、入力 1 1 5 1 は v = 1 および n = 1 となるため、出力は NO になります。 このアルゴリズムは 1 > 1 を比較しますが、これは false であり、フォールバック構造が存在しないことを正しく反映しています。 

v = n + 1 など、v が n のすぐ上にある場合、Joseph は、考えられるすべての間違った試行が終わった後でも、常に少なくとも 1 つの候補単語を保持できます。 不等式が厳密に成り立つため、アルゴリズムは YES を返します。 

a と l の値が大きい場合、これらのパラメータは決定に影響しません。 アルファベットが最大であっても、語彙のサイズが強制排除の回数を上回ることができるかどうかが決定要因として残るため、v > n の比較が結果を左右します。
