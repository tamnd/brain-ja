 ## 解決策
 ## 問題の理解

 まず、チャンバー内にすでに存在する一連の化学物質の種類から始めます。 既知の反応規則を持つ化学物質のペアは毎秒、新しい種類の化学物質を生成する可能性があります。 重要な詳細は、反応が消費しないということです。新しい化学物質を生成した後も両方の反応物質が利用可能なままであるため、システムは時間の経過とともに化学物質を蓄積するだけです。 複数の反応が並行して発生する可能性があり、このプロセスは、新しい化学物質がまったく出現しなくなるまで、事実上、非常に多くのステップにわたって継続します。 

入力により、化学物質 ID の初期セットと、「化学物質 x と化学物質 y が両方とも存在する場合、化学物質 z を生成できます」という形式の反応規則のリストが与えられます。 課題は、考えられるすべての反応を無期限に適用し続けた場合に、最終的にいくつの異なる化学タイプが出現するかを決定することです。 

時間は 10^100 秒と表現されますが、プロセスは単調です。化学物質が一度出現すると消えることはなく、到達可能な化学物質がすべて生成されるとシステムは安定します。 したがって、本当の問題は、これらの生産ルールに基づくクロージャについてです。 

この制約では、テスト ケースごとに最大 1000 の初期化学物質と 1000 のルール (最大 500 のテスト ケース) が提案されます。 時間軸が天文学的に長いため、長期にわたる単純なシミュレーションは不可能です。 時間ステップではなく状態空間が重要であるため、1 秒あたりのシミュレーションさえも意味がありません。 

反応が連鎖またはサイクルを形成する場合、微妙なエッジケースが発生します。 たとえば、A と B が C を生成し、A と C が D を生成する場合、D はさらなる反応のロックを解除する可能性があります。 もう 1 つの重要なケースは、複数のルールが反応物を共有しているが、異なる出力を生成する場合です。 それらはすべて独立して説明される必要があります。 

単純な間違いは、反応を 1 回限りのイベントとして扱ったり、位相的な順序付けを仮定したりすることです。 もう 1 つの間違いは、適用可能なすべての反応を同時に許可するのではなく、ステップごとに 1 つの新しい化学物質のみをシミュレートすることです。これは、到達可能なセットを大幅に過小評価することになります。 

## アプローチ

 強引なアイデアは、システムを離散時間ステップでシミュレートすることです。 各ステップで、すべての反応ルールをチェックし、両方の反応物が現在存在するかどうかを確認します。 「はい」の場合、その製品を利用可能な化学薬品のセットに追加します。 フルパスで新しい化学物質が追加されなくなるまで、これを繰り返します。 

これは、ルールに直接従うため、正しいです。つまり、前提条件が満たされるたびにすべての反応が適用されます。 ただし、問題は、各パスが m 個のルールすべてをスキャンするため、最悪の場合、各層が 1 つの新しい化学物質をロック解除する場合、最大 O(n) 層の伝播が必要になる可能性があることです。 これにより、O(nm) 以上の動作が発生し、テスト ケースごとに n と m が両方とも 1000 になる可能性があり、テスト ケースが多数あるため、速度が非常に遅くなります。 

重要な観察は、これは時間発展の問題ではなく、ハイパーグラフの到達可能性の問題であるということです。 各リアクションは 2 つのノードが存在する場合にアクティブになるルールであり、アクティブになると新しいノードが永続的に追加されます。 これは、プロセスをクロージャ計算として扱う必要があることを示唆しています。利用可能な化学物質の現在のセットを維持し、前提条件が満たされているルールを繰り返しアクティブ化しますが、不必要にすべてを再スキャンすることは避けます。 

「新たに発見された化学物質」のキューを維持し、各化学物質がどの反応ルールに参加しているかを追跡できます。各ルールは、両方のエンドポイントがわかった場合にのみトリガーされます。 まだ不足している反応物の数をルールごとにカウンターを維持することで、ルールが完全に満たされたときにルールを 1 回だけアクティブにすることができます。 これにより、プロセスは、2 部構成の依存関係構造を介した BFS と同様のマルチソース伝播に変わります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(k · m) 最悪の場合 | O(n + m) | 遅すぎる |
 | 依存関係 BFS / アクティベーションの伝播 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初の化学物質をすべて読み、存在するものとしてマークします。 また、これらの化学物質は将来のすべての反応の開始フロンティアであるため、これらの化学物質でキューを初期化します。 
2. すべての反応ルール (x、y → z) について、それを x と y の両方の隣接リストに保存し、まだ欠落している反応物の数のカウンターを維持します。 最初、このカウンタは 2 です。 
3. キューからの化学物質を処理する際、化学物質 v に遭遇すると、v を含むすべての反応ルールを繰り返します。そのようなルールごとに、必要な化学物質の 1 つが出現したため、その欠落反応物カウンターをデクリメントします。 
4. ルールのカウンターがゼロに達すると、両方の反応物が存在するため、結果として化学物質 z を生成できます。 z が以前に存在しなかった場合は、それを存在するとマークし、キューにプッシュします。 
5. キューが空になるまで続行します。つまり、どのルールによっても新しい化学物質が生成されなくなります。 
6. 最後に、存在するとマークされた化学物質の数を数えます。 

これが機能する理由は、すべての反応ルールが、必要な両方の反応物が利用可能になった瞬間に、「非アクティブ」から「アクティブ」に 1 回だけ移行するためです。 キューにより、新しく発見された化学物質が即座に伝達され、各ルールがそのエンドポイントに比例した制限された回数だけ処理されることが保証されます。 

### なぜ効果があるのか

 プロセスのどの時点でも、化学物質は既知 (すでにセットに含まれている) か未知のいずれかです。 リアクション ルールは、両方のエンドポイントがわかっている場合にのみ適格になります。 すべての化学物質の到着はすべてのインシデント ルールを通じて伝播されるため、アルゴリズムにより、この適格性が 2 番目のエンドポイントの到着直後に検出されることが保証されます。 ルールを見逃すことはできず、ルールが途中で起動することもできません。 これにより、アルゴリズムが指定されたバイナリ生成ルールに基づいて初期セットの閉包を正確に計算することが確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict, deque

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        init = list(map(int, input().split()))
        
        present = set(init)
        q = deque(init)
        
        # for each chemical, list of (rule_id)
        adj = defaultdict(list)
        
        # rules: (x, y, z)
        x = []
        y = []
        z = []
        remaining = []
        
        for i in range(m):
            a, b, c = map(int, input().split())
            x.append(a)
            y.append(b)
            z.append(c)
            remaining.append(2)
            adj[a].append(i)
            adj[b].append(i)
        
        while q:
            v = q.popleft()
            for i in adj[v]:
                remaining[i] -= 1
                if remaining[i] == 0:
                    nz = z[i]
                    if nz not in present:
                        present.add(nz)
                        q.append(nz)
        
        print(len(present))

if __name__ == "__main__":
    solve()
```コードはグローバル セットを維持します`present`発見されたすべての化学物質を表します。 キューは、最初の化学物質から外側への伝播を推進します。 それぞれの反応ルールには小さな状態があり、`remaining[i]`、必要な入力のうちまだ不足しているものがいくつあるかを追跡します。 すべてのルールには正確に 2 つの入力があるため、カウンタは 2 から始まり、両方の入力が検出されたときに正確に 0 に達します。 

微妙な実装の詳細は、ルールが起動された後にそのルールを再検討することは決してないということです。`remaining[i]`ゼロに達すると、再び変更することはできません。 これにより、スキャンを繰り返すのではなく、ルール化学的発生数の直線的な複雑さが保証されます。

def run(inp: str) -> str:

    import sys
    from collections import defaultdict, deque

    input = sys.stdin.readline

    def solve():
        t = int(input())
        for _ in range(t):
            n, m = map(int, input().split())
            init = list(map(int, input().split()))
            present = set(init)
            q = deque(init)

            adj = defaultdict(list)
            x = []
            y = []
            z = []
            remaining = []

            for i in range(m):
                a, b, c = map(int, input().split())
                x.append(a); y.append(b); z.append(c)
                remaining.append(2)

                            present.add(z[i])
                            q.append(z[i])

            print(len(present))

    solve()

## 特殊なケース

 重要なケースの 1 つは、反応連鎖が長く、いくつかの中間ステップを経て初めて新しい化学物質が解放される場合です。 たとえば、1、2 → 3、3、4 → 5、5、6 → 7 です。アルゴリズムはこれを自然に処理します。これは、新しく追加された各化学物質が、それに関係するすべてのルールの再評価を即座にトリガーするため、明示的な階層化を行わずにチェーンが進行するためです。 

もう 1 つのエッジ ケースは、複数のルールが反応物を共有しているが、異なる出力を生成する場合です。 化学物質 x が出現した場合、x に関係するすべてのルールを同時に考慮する必要があります。 隣接関係ベースの伝播により、x がそのようなすべてのルールに寄与し、スキップされるものがないことが保証されます。 

最後のケースは、既存の化学物質を生成する冗長なルールです。 チェックしてるので`present`キューに入れる前に生成を繰り返しても、無限ループやオーバーカウントは発生しません。
