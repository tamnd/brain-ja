 ## 解決策
 ## 問題の理解

 Codeforces 105993J では、キャンバスは無限グリッドです。 一部のピクセルはすでに色付けされており、できるだけ少ない新しい色付け操作を使用して、特定の四角形のすべてのセルを色付けしたいと考えています。 新しいピクセルは、地上行の任意のセルに色を付けることによって作成できます。`y = 1`、または、すでに色が付いているピクセルからその 4 つの隣接ピクセルの 1 つに広げることによって。 

ターゲット長方形は水平間隔によって定義されます`[X1, X2]`と垂直間隔`[Y2, Y1]`。 入力は最大になります`100000`すでに色が付いているピクセル。 座標は次のように大きくできます。`10^9`, そのため、グリッドを構築したり、スプレッドをシミュレートしたりすることは不可能です。 1 秒の時間では、意図したソリューションは、指定されたピクセル数において線形に近くなければなりません。 

重要な問題は、長方形が巨大になる可能性があるにもかかわらず、重要なのは既存のピクセルだけであることです。 長方形自体の面積は最大で`10^18`したがって、すでに空いているセルの数と、長方形に接続するために長方形の外側に追加のセルがいくつ必要かを推論する必要があります。 

いくつかの特殊なケースは見落とされがちです。 ピクセルが既に四角形の内側にある場合は、ピクセルを作成する必要がないため、操作が 1 つ節約されます。 

例えば：```
1
3 4 3 3
3 4
```四角形には 1 つのセルが含まれており、そのセルはすでに色付けされています。 答えは次のとおりです。```
0
```四角形に入る方法のみを検索するソリューションでは、誤って 1 つの操作が追加される可能性があります。 

もう 1 つのケースは、既存のピクセルが長方形の外側から接触している場合です。 

例：```
1
3 4 3 3
3 5
```既存のピクセルは長方形の真上にあります。 一度に広がることができます`(3,4)`。 答えは次のとおりです。```
1
```新しいピクセルは四角形の内側にあるため、すでに欠落している四角形セルの 1 つとしてカウントされています。 接続を追加の操作としてカウントすると、誤った結果が得られます。 

最後の厄介なケースは、既存のピクセルがない場合です。 

例：```
0
4 4 4 4
```必要なセルは次のとおりです。`(4,4)`。 色を付けなければなりません`(4,1)`、`(4,2)`、`(4,3)`、 そして`(4,4)`、したがって、答えは次のようになります。```
4
```グラウンド操作では最初のピクセルが作成され、その後のすべてのピクセルがスプレッドになります。 

## アプローチ

 簡単なアプローチは、成長をシミュレーションすることです。 考えられるすべての地面位置を試し、既存のすべてのピクセルから広げて、色がつくセルの数を数えることもできます。 これは、許可された操作を文字通りモデル化しているため、正しいです。 問題は、長方形には最大で次のものを含めることができることです。`10^18`細胞なので、すべての細胞に一度触れることさえ不可能です。 

有益な観察は、長方形内の欠落しているセルはすべて、最終的には何らかの操作によって色付けされる必要があるということです。 それを支払う以外に方法はありません。 可能な唯一の最適化は、スプレッドが四角形に到達する前に、四角形の外側にある色付きの余分なセルの数を減らすことです。 

長方形の内側にすでに色付きのピクセルがある場合は、外部の作業を行わずに長方形全体を塗りつぶすことができます。 外側に色付きのピクセルがある場合は、それを長方形に接続するだけで済みます。 最も安価な接続は、長方形への最短のマンハッタン パスです。 最初に色の付いたピクセルの場合、このパスの最終ステップは四角形に入ります。そのため、その最終ステップの前のセルのみが余分になります。 

地上行の動作は若干異なります。 グラウンド操作では新しい色付きピクセルが作成されるため、グラウンド位置から長方形までのすべてのセルが寄与します。 最適な地上位置は常に長方形と水平方向に整列するため、追加のコストがかかります。`Y2 - 1`。 

答えは、長方形内の欠落しているセルの数に最小追加接続コストを加えたものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(長方形の面積) | O(長方形の面積) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初に色付けされたすべてのピクセルをセットに保存します。 このセットにより、重複ピクセルを 2 回カウントすることが回避され、ターゲットの四角形内にすでに色付けされているセルの数をカウントできるようになります。 
2. 長方形の面積を次のように計算します。`(X2 - X1 + 1) * (Y1 - Y2 + 1)`。 長方形内の既存のピクセルの数を減算します。 これらはまだ色を付ける必要があるセルです。 
3. 地上動作で最適な追加接続コストを初期化します。 長方形の任意の列の直下にある地上セルを選択するには、その列内の長方形の下にあるすべてのセルに色を付ける必要があります。 
4. 長方形の外側の既存のピクセルごとに、長方形の最も近いセルまでのマンハッタン距離を計算します。 距離がゼロの場合、ピクセルはすでに内部にあります。 それ以外の場合、最後の移動は長方形の中に入るため、外側の余分なセルの数は次のようになります。`distance - 1`。 
5. 不足している四角形セルの数に、最小追加接続コストを加算します。 これは、新しいピクセルの最小合計数です。 

機能する理由: コストを支払わずにセルに色を付ける操作は存在しないため、すべてのソリューションでは欠落している四角形のセルに色を付ける必要があります。 残された唯一の選択肢は、最初の色のピクセルを四角形に入れる方法です。 アルゴリズムは、すべての初期ピクセルとグランド行を含む、そのような接続の考えられるすべてのソースをチェックします。 ソースからの最短の接続はマンハッタン パスであり、アルゴリズムはそのパス上の四角形の外側にあるセルを正確にカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    X1, Y1, X2, Y2 = map(int, input().split())

    inside = 0
    seen = set()
    points = []

    for _ in range(n):
        x, y = map(int, input().split())
        if (x, y) not in seen:
            seen.add((x, y))
            points.append((x, y))
            if X1 <= x <= X2 and Y2 <= y <= Y1:
                inside += 1

    area = (X2 - X1 + 1) * (Y1 - Y2 + 1)
    answer = area - inside

    extra = Y2 - 1

    for x, y in points:
        if X1 <= x <= X2 and Y2 <= y <= Y1:
            continue

        if x < X1:
            dx = X1 - x
        elif x > X2:
            dx = x - X2
        else:
            dx = 0

        if y < Y2:
            dy = Y2 - y
        elif y > Y1:
            dy = y - Y1
        else:
            dy = 0

        dist = dx + dy
        extra = min(extra, dist - 1)

    print(answer + extra)

if __name__ == "__main__":
    solve()
```ピクセルは 1 回しか色付けできないため、コードは最初に重複を削除します。 変数`answer`長方形自体を埋めるために避けられないコストを格納します。 

変数`extra`地面列の使用コストとして始まります。 コードは、既存のピクセルごとに、四角形までのマンハッタン距離を計算します。 ピクセルの列がすでに長方形の内側にある場合、水平距離はゼロであり、垂直方向にも同じことが当てはまります。 

1の減算は微妙な部分です。 パスの最後のステップは四角形の内側に到達し、そのセルはすでに欠落している四角形の数に含まれています。 前のセルのみが追加の操作です。 

すべての算術演算では Python 整数が使用されるため、大きな座標範囲や四角形領域がオーバーフローすることはありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 提供されたすべてのピクセルは 1 回処理されます。 
| スペース | O(n) | 色付きピクセルのセットが保存されます。 

解決策は、最初に色が付けられたピクセルの数にのみ依存します。 四角形のサイズに比例してメモリが割り当てられることはないため、最大座標を簡単に処理できます。

import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline

    n = int(data())
    X1, Y1, X2, Y2 = map(int, data().split())

    inside = 0
    seen = set()
    points = []

    for _ in range(n):
        x, y = map(int, data().split())
        if (x, y) not in seen:
            seen.add((x, y))
            points.append((x, y))
            if X1 <= x <= X2 and Y2 <= y <= Y1:
                inside += 1

    area = (X2 - X1 + 1) * (Y1 - Y2 + 1)
    ans = area - inside
    extra = Y2 - 1

    for x, y in points:
        if X1 <= x <= X2 and Y2 <= y <= Y1:
            continue
        dx = max(X1 - x, 0, x - X2)
        dy = max(Y2 - y, 0, y - Y1)
        extra = min(extra, dx + dy - 1)

    sys.stdin = old
    return str(ans + extra) + "\n"

 ## 特殊なケース

 ピクセルがすでに四角形の内側にある場合、アルゴリズムはそのピクセルを欠落セル数から除外します。 入力の場合:```
1
3 4 3 3
3 4
```エリアは 1、内側のカウントは 1 なので、基本コストは 0 になります。 目標はすでに満たされているため、接続コストは問題になりません。 

ピクセルが長方形のすぐ外側にある場合、マンハッタン距離は 1 です。 このアルゴリズムでは 1 が減算され、余分なセルはゼロになります。 欠落している長方形のセル自体はスプレッド操作によって色付けされており、すでに基本コストに含まれています。 

地面からはるか上の長方形の場合、次のようになります。```
0
4 4 4 4
```地上費は`Y2 - 1 = 3`。 長方形には欠落しているセルが 1 つあり、次のようになります。`1 + 3 = 4`。 これは、地面からターゲットまで垂直柱を着色する実際の順序と一致します。
