 ## 解決策
 ## 問題の理解

 任意に並べ替えることができる 10 進数の複数のセットが与えられます。 これらの数字から、9 で割り切れる最大の数を構築したいと考えています。 条件を満たす正の数を形成できない場合は、失敗値を出力する必要があります (通常は、ステートメントの規則に応じて単一のゼロまたは -1 ですが、ここでは標準の CF バリアントであるため、単一のゼロとして扱います)。 

最大の困難は、2 つの相反する目標を同時に最適化していることです。 辞書編集的な意味で、結果の数値をできるだけ大きくする必要があります。これは、数字を降順に並べ替えることと同じですが、桁の順序ではなく合計に依存する割り算条件にも制約されます。 

最大 2⋅10^5 桁がある場合、すべてのサブセットを試行したり、組み合わせで削除をシミュレートしようとしたりするアプローチは非常に遅くなります。 このスケールでは、桁を超える二次戦略でさえ境界線になるため、線形または線形に近い貪欲な解決策または計数ベースの解決策を余儀なくされます。 

いくつかの危険な状況は、早めに切り分ける価値があります。 

たとえば、入力がゼロのみで構成されている場合、`0000`、正解は`0`、先頭のゼロは単一の正規表現に折りたたまれるため、空の文字列や一連のゼロではありません。 

たとえば、桁の合計がすでに 9 で割り切れる場合、`981`の場合、桁の削除は必要なく、単純に降順にソートされた桁を出力します。これにより、次の結果が得られます。`981`。 

より微妙なケースは、剰余条件によって数字の削除が強制される場合に発生します。 たとえば、数字が`1 1 1 1`、合計は 4 ですが、すべてを削除せずに数字だけを削除しても 9 の倍数に達することはできません。 任意の数字を貪欲に削除する単純なアプローチでは、誤って分割できない構成が残ったり、大きな数字が多すぎて削除されたりして、最大ではない結果が生じる可能性があります。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 数字のすべてのサブセットを考慮し、その数字の合計が 9 で割り切れるかどうかを確認し、すべての有効なサブセットの中から、数字を降順に並べ替えて結果を比較することによって、可能な最大の数を構築します。 これは、すべての有効な構造を徹底的に調査しているため、正しいです。 

ただし、サブセットの数は n とともに指数関数的に増加します。 40 桁ではすでにサブセットの数が 1 兆を超えており、2⋅10^5 桁ではこれは完全に不可能になります。 分割性の制約はグローバルであり、早期終了の保証がないため、枝刈り戦略に制限しても役に立ちません。 

重要な観察は、9 で割り切れるかどうかは、9 を法とする数字の合計にのみ依存するということです。 これは、実現可能性を判断する際に順序は考慮せず、どの桁が含まれるかのみを考慮することを意味します。 実現可能性が決定されると、順序は再び独立し、降順でソートすることで簡単に処理されます。 

したがって、タスクは、「値に寄与する」桁をできるだけ少なく削除しながら、その合計が 9 で割り切れるように桁マルチセットを調整することに帰着します。 最終的な数値を最大化するには、最初に小さい桁を削除することを好みます。これは、小さい桁を削除すると、大きい桁を削除するよりも最終的に構築される数値が減少するためです。 

これは貪欲な修正戦略につながります。すなわち、9 を法とする合計を計算し、合計の mod 寄与が剰余を修正する可能な限り最小の桁のセットを削除します。 その後、残りの桁を降順に並べ替えて最大値を形成します。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. すべての桁を読み取り、その頻度を数えながら、桁の合計を計算します。 これにより、マルチセット構造を見失うことなく、削除について推論することができます。 
2. コンピューティング`remainder = sum % 9`。 これがゼロの場合、すでに割り算の制約を満たしているため、数字を降順に並べ替えることですぐに答えを構築できます。 
3. 剰余がゼロ以外の場合は、その剰余だけ正確に合計を法 9 で減らす値を持つ数字を削除する必要があります。 削除する桁ごとに最終的な数値が減少するため、目標は、削除する桁数をできるだけ少なくすることです。 
4. 9 を法とする値が剰余と等しい 1 つの数字を削除してみます。 このようなすべての候補の中から、最小の桁を選択します。 1 桁を削除すると、できるだけ多くの桁が保持されるため、最適です。 
5. ステップ 4 が不可能な場合は、mod 9 の値の合計が 9 を法とした剰余となる 2 桁の削除を試みます。再度、辞書編集上最も有害でないペアを選択します。これは、条件を満たす利用可能な最小の桁を削除することに対応します。 
6. 必要な削除が適用されたら、残りの桁を降順で再構築して、最終的な数値を最大化します。 

### なぜ効果があるのか

 正確さは 2 つの特性に依存します。 まず、9 で割り切れるかどうかは、9 を法とする桁の合計にのみ依存するため、有効な解はその剰余を正確に調整する必要があります。 第 2 に、同じ剰余修正を達成するすべてのサブセットの中で、できるだけ大きな桁を維持することによって、辞書編集上最大の数が取得されます。 数字を削除すると、合計と最終的な並べ替えられた出力の両方が厳密に削減されるため、小さい数字の削除を優先しても最適性が損なわれることはありません。 削除された大きな数字を小さな数字に置き換える交換は、実現可能性を維持しながら最終的な数字を増やすだけであるため、貪欲な選択は安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    if not s:
        return

    digits = [int(c) for c in s]
    total = sum(digits)

    rem = total % 9

    # frequency count
    cnt = [0] * 10
    for d in digits:
        cnt[d] += 1

    def build():
        res = []
        for d in range(9, -1, -1):
            res.append(str(d) * cnt[d])
        return "".join(res).lstrip('0')

    if rem == 0:
        ans = build()
        print(ans if ans else "0")
        return

    # try removing one digit
    removed = False
    for d in range(10):
        if cnt[d] > 0 and d % 9 == rem:
            cnt[d] -= 1
            removed = True
            break

    # fallback: try removing two digits
    if not removed:
        found = False
        for i in range(10):
            if cnt[i] == 0:
                continue
            cnt[i] -= 1
            for j in range(10):
                if cnt[j] == 0:
                    continue
                if (i + j) % 9 == rem:
                    cnt[j] -= 1
                    found = True
                    break
            if found:
                break
            cnt[i] += 1

    ans = build()
    print(ans if ans else "0")

if __name__ == "__main__":
    solve()
```この実装では、並べ替えが暗黙的に処理されるように、まず入力を桁数に圧縮します。 これにより、中間ステップでソート操作を繰り返す必要がなくなります。 

の`build`関数は、9 から 0 までの数字を出力することで可能な最大の数値を再構築し、最適な順序を直接エンコードします。 の`lstrip('0')`このステップでは、次のようなケースが確実に発生します。`0000`単一のゼロ出力に正しく折りたたまれます。 

削除ロジックは意図的に最小限に抑えられています。 最初に 1 桁の修正を試行します。これは、2 桁を削除するよりも 1 桁を削除する方が、より多くの合計値を保持できるため、常に好ましいからです。 それが失敗した場合にのみ、ペアの削除を試みます。 

微妙な点の 1 つは、削除後に、すべての数字の削除を表す空の文字列が誤って生成されないようにすることです。 その場合、明示的に出力します`0`。

 ## 特殊なケース

 特殊なケースの 1 つは、すべての桁が 0 である場合です。 この状況では、並べ替えると次のような文字列が生成されます。`0000`ですが、正しい正規の出力は単一です。`0`。 アルゴリズムはこれを次のように処理します。`lstrip('0')`check は、すべてゼロの文字列を空の文字列に変換し、それを次の文字列に置き換えます。`"0"`。 

もう 1 つのエッジ ケースは、モジュロを修正するために桁を削除するときに、桁が残らない場合に発生します。 たとえば、入力がすべてを削除しないと合計を修復できない最小セットである場合、アルゴリズムは count 配列をすべて 0 に減らす可能性があります。 最後のガードにより、出力が保証されます。`0`空の結果の代わりに。 

3 番目のケースは、有効な削除の選択肢が複数存在する場合に発生します。 たとえば、複数の桁が個別に剰余条件を満たす場合があります。 両方の選択が有効であるとしても、より大きな桁を削除すると、最終的な数値が不必要に減少するため、そのような最小の桁を選択することが重要です。
