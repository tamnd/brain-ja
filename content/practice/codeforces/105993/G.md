 ## 解決策
 ## 問題の理解

 同じ次元の 2 つのバイナリ グリッドを使用しています。 1 つのグリッドはターゲット構成として固定されていますが、もう 1 つは完全に空の状態から開始されます。 空のグリッドを変更する唯一の方法は、選択した 1 つのセルにアクセスし、同時にグリッドの残りの部分に構造変更を引き起こす 1 つの操作を行うことです。 

各操作では、選択したセルを 0 から 1 または 1 から 0 に反転し、その選択したセルを含む行を除くすべての行に循環右シフトを適用します。 この操作を何回か繰り返して、最初は空のグリッドを正確にターゲットのグリッドに変換する必要があります。 

課題は、これが可能かどうかを判断するだけでなく、最小限の手数で目標を達成する一連の操作を構築することです。 

重要な問題は、すべての操作にグローバルな副作用があることです。 明示的に変更するのは 1 つのセルだけですが、ほとんどの行は右にシフトします。これは、以前に設定されたパターンが後の操作後に水平に移動する可能性があることを意味します。 これにより、問題はグリッドの構築と行全体の置換制御が混在したもののように感じられます。 

この制約により、最大 1000 x 1000 のグリッドが許可され、テスト ケースの合計グリッド サイズも 1000 x 1000 で制限されます。これにより、完全なグリッド上ですべての操作を単純にシミュレートしようとするアプローチが除外されます。これは、単一の操作で行をシフトするのに O(M) のコストがかかり、最悪の場合、最大 10^6 の操作がすでに遅すぎるためです。 私たちは、各セルを最大 1 回、または厳密に制御されたパターンで処理する構造を目指しています。 

いくつかのエッジな状況では、対処を誤ってしまいがちです。 

単一セルを含むグリッドは簡単ですが、実装がゼロ操作を正しく処理するかどうかが明らかになります。 たとえば、「0」の 1×1 ターゲットには出力 0 が必要で、これを演算で「修正」しようとすると誤って反転してしまいます。 

単一行グリッドは、シフトする「他の行」がないため、動作が異なります。 その場合、各操作はセルを反転するだけなので、問題は独立したビット固定に帰着します。 シフトが常に発生すると仮定する単純な解決策では、誤って過大評価したり、存在しない動きをシミュレートしたりする可能性があります。 

多くの行があり、列が 1 つある場合も、シフトには目に見える効果がないため、動作が異なりますが、操作では選択したセルが反転されます。 この縮退を無視すると、国家がどのように進化するかについて誤った推論につながります。 

## アプローチ

 直接的な総当たり解釈では、プロセスを状態ごとにシミュレートします。 現在のグリッドからセルを選択して反転し、他のすべての行に循環シフトを適用し、グリッドがターゲットと一致するまで再帰的に繰り返します。 これは操作の定義を正確に反映しているため、原理的には正しいです。 ただし、行シフトにより各ステップで O(N・M) 個のセルが変更され、分岐係数は O(N・M) 個の可能な移動になります。 この空間のごく一部を探索するだけでも指数関数的になり、非常に小さなグリッドを超えると実行不可能になります。 

重要な観察は、行シフトが決定的かつ均一であるということです。 1 行を除くすべての行は、操作ごとに 1 位置ずつ右に移動します。 これは、k 回の操作の後、その行がピボットとして選択され、そのステップのシフトを一時的に「リセット」する瞬間を除いて、すべての行が実質的に右に k 回回転されたことを意味します。 完全なグリッド状態を追跡する代わりに、相対的な位置合わせの観点から考えることができます。セル (i, j) を固定することに決めたとき、行 i が位置合わせされた瞬間の操作を選択できるため、蓄積されたシフトの下で列 j が現在「アクティブ」になります。

これにより、問題はポジションをめぐるスケジュールの問題に変わります。 シフトは相対的な列位置にのみ影響し、制御されたスイープでパリティを修正する機能には影響しないため、順序を慎重に決定すれば、各行を独立して処理できます。 最適な構成は、各セルが正しい列位置にあるときに正確に固定されることを保証する一貫した回転状態を維持しながら、行を 1 つずつ処理することです。 

重要な簡素化は、任意のインターリーブをシミュレートする必要がないことです。 行ごとに左から右へ貪欲にスイープし、各行の有効な回転オフセットを維持することと組み合わせることで、セルがターゲット位置に揃った瞬間にセルを反転する必要があるかどうかを常に決定できるようになります。

 ## アルゴリズムのチュートリアル

 元の状態と比較してその行に適用された巡回シフトの数を表す概念的な回転オフセットを行ごとに維持します。 中心的な考え方は、常に行ごとに操作を決定し、各行内で固定論理順序で列を走査し、オフセットを使用して実際のセルが各ターゲット列と現在位置合わせされているかを解釈するということです。 

1. すべての行を空として初期化し、回転オフセットをゼロに設定します。 空のグリッドはすべて 0 に対応し、まだ回転された行はありません。 
2. 行を上から下に処理します。 行の順序を固定する理由は、行の操作を決定すると、後で他の行にシフトすることによって生じる不一致が再び持ち込まれるのを避けるためです。 
3. 現在の行について、列を左から右にスキャンします。 論理列 j で、その行の現在の回転オフセットを適用した後、実際の列位置を計算します。 これにより、進化するグリッド内のどのセルがターゲット位置に対応するかがわかります。 
4. ターゲット グリッドのこの位置に 1 が必要な場合は、この行と計算された列を選択する操作を実行します。 これにより、ターゲット構成と一致した瞬間にセルが正しい状態に反転されます。 
5. 各操作の後に、他のすべての行のオフセットを 1 ずつ増やして、その行の回転状態を暗黙的に更新します。 物理的にシフトする代わりに、これをグローバル シフト カウンターとして追跡し、それに応じて比較を調整します。 
6. 行内のすべてのセルが処理されるまで続行し、次の行に移動します。 以降の操作は常に、すでに一致した構造を保持する制御された方法で適用されるため、各行は完了すると事実上ロックされます。 

中心となる不変条件は、行 i を処理する前の任意の時点で、i より上のすべての行がそれぞれの回転オフセットの下でターゲット構成とすでに一致していることです。 行 i を処理するとき、現在のオフセットにより、行の一貫した循環ビューが表示され、ターゲット 1 がアクティブな列と一致するときに各決定が正確に行われます。 すべての操作は予測可能な方法で相対的な位置合わせを変更するだけであるため、以前に固定された行は、進化するオフセットの下でもターゲットとの一貫性が維持されます。 これにより、以前の作業が後の操作によって無効になるのを防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        grid = [input().strip() for _ in range(n)]

        ops = []
        # rotation offset for each row (logical right shifts applied)
        shift = 0

        # We process row by row
        for i in range(n):
            # current row's effective shift relative to target
            row_shift = 0

            for j in range(m):
                # actual column in original grid after shifts
                col = (j - row_shift) % m

                # We want to decide if we need a flip operation
                if grid[i][j] == '1':
                    # perform operation at (i, col)
                    ops.append((i + 1, col + 1))

                    # after operation, all other rows shift right by 1
                    shift = (shift + 1) % m

                    # this row effectively cancels shift because it is chosen
                    row_shift = shift

        print(len(ops))
        for r, c in ops:
            print(r, c)

if __name__ == "__main__":
    solve()
```この実装では、選択されていないすべての行に適用される累積的な右回転を表すグローバル シフト カウンターが保持されます。 行 i のセルを選択すると、その行はシフトから除外されるため、操作後にそのローカル ビューをグローバル状態に同期させます。 

最もデリケートな部分は、一貫したインデックス作成を確保することです。 操作で使用される列は、元の静的なグリッド位置ではなく、現在の配置を反映する必要があります。 これら 2 つのビューを混合すると、このタイプの構築問題におけるオフバイワン エラーの一般的な原因になります。

 ## 特殊なケース

 1×1 グリッドは、実装が操作を必要としないことを考慮しているかどうかを明らかにします。 シフトは何も影響しないため、正しい答えは単に操作がゼロであり、操作を適用しようとするとすぐにターゲットが破損します。 

単一行グリッドは、もう 1 つの退化ケースです。 シフトする「他の行」がないため、状態が回転することはありません。 シフトが無関係になるため、アルゴリズムは引き続き機能しますが、グローバル シフトを常にインクリメントする不注意な実装では、インデックスの位置が誤って調整され、誤った反転が生成されます。 

単一の孤立した値を除くすべての値がゼロであるグリッドは、アルゴリズムが不必要な操作のカスケードを回避するかどうかをテストします。 フリップするたびにシフトがトリガーされるため、過度に熱心な戦略は不要なシフトを蓄積し、将来の操作を誤ってしまう可能性があります。 行単位のスイープは、必要な遷移が発生した場合にのみ動作し、操作の数を最小限に抑えるため、これを回避します。
