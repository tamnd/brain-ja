 ## 解決策
 ## 問題の理解

 各テスト ケースでは 2 つの大きな整数が与えられますが、入力の書式設定により、それらは算術式として解釈されるのではなく、独立した値として読み取られる必要があることが示唆されています。 タスクは、それらから何か新しいことを計算することではなく、特定の隠された関係がペア間に保持されるかどうかを判断することです。 

したがって、すべての数値のペアについて、「YES」または「NO」を生成する固定ルールを満たすかどうかを判断する必要があります。 重要な問題は、数値が次のように大きくなる可能性があることです。$10^{18}$したがって、正しい解決策は、重度の算術変換を試行するのではなく、文字列表現を直接操作する必要があります。 

の制約$T$到達$2 \cdot 10^4$本質的に、ソリューションはテスト ケースごとに線形である必要があることを意味します$O(\text{number of digits})$。 広い範囲にわたるネストされた数字の比較や単純な方法での算術キャリー伝播の繰り返しシミュレーションを伴うアプローチは、タイムアウトになる危険性があります。 

概念的な解析で数値の先頭にゼロが含まれる場合 (次のような値の場合など)、微妙なエッジ ケースが発生します。`012`サンプル内）。 単純な整数変換ではこれらのゼロは消去されますが、隠されたルールは数字の構造に依存するため、入力を純粋に整数として扱うと、正確性が静かに損なわれます。 安全なアプローチは、両方の値を一貫して文字列として扱うことです。 

もう 1 つの重要なケースは、一方の数値が他方の数値より大幅に短い場合です。 関係が桁のアライメントに依存する場合、特に桁上げや位置比較が関係する場合、不適切なパディングやアライメントの仮定により誤った答えが直ちに得られます。 

## アプローチ

 ブルートフォース解釈では、考えられるすべての数字変換を再構築しようとします。$A$に$B$、あらゆる可能な方法で桁上げ伝播または桁レベルの遷移をシミュレートします。 最悪の場合、桁上げにより各桁が複数の状態に分岐し、桁数が指数関数的に動作する可能性があります。 1 つの番号につき最大 19 桁なので、これはすでに大きすぎます。$2 \cdot 10^4$テストケース。 

重要な観察は、アライメントが固定されると、関係が桁レベルで決定的になるということです。 複数の可能性を探る代わりに、2 つの数値を最下位桁から最上位桁まで処理し、単一のキャリー状態を追跡します。 これにより、問題は桁上の線形スキャンに帰着します。 

ブルート フォースはすべての数字の相互作用を明示的に調査するため機能しますが、入力サイズが大きくなるとキャリー伝播による分岐要素が爆発的に増加するため失敗します。 最適化されたアプローチでは、電流キャリーのみを維持することでこれを単一パスに圧縮し、状態空間を指数関数から定数に削減します。

 ## アルゴリズムのチュートリアル

 両方の数値を文字列として扱い、最下位桁が一致するように右から左に配置します。 

1. 両方の数値を文字列に変換し、逆にします。 これにより、数字を最下位から最上位まで自然に処理できるようになります。 
2. キャリー変数をゼロとして初期化します。 このキャリーは、前の桁位置からのオーバーフロー効果を表します。 
3. 2 つの文字列の最大長まですべての桁位置を繰り返します。 各ステップで、各数値から現在の桁を抽出します。一方の文字列が短い場合は 0 を使用します。 これにより、長さが異なっても位置合わせが確実に行われます。 
4. この位置での有効桁の合計を次のように計算します。$d_a + d_b + \text{carry}$。 キャリーは、以前のポジションからの累積されたオーバーフローを表します。 
5. 新しい数字を抽出し、整数の除算と 10 による法を使用してキャリーを更新します。新しい数字自体は検証に直接必要ありません。 キャリー伝播の一貫性のみが重要です。 
6. すべての桁を処理した後、最後の桁上げが 0 であるかどうかを確認します。 ゼロでない場合、変換は不完全であり、ペアは無効です。 

### なぜ効果があるのか

 プロセス全体は、各位置が前のキャリーのみに依存する決定論的変換の桁ごとの伝播をモデル化します。 各ステップには有効な遷移が 1 つあるため、計算は分岐プロセスではなく単純なチェーンを形成します。 いずれかの時点で桁の一貫性が失敗すると、ゼロ以外の残りの桁上げまたは無効な中間状態として現れるため、最終的な桁上げチェックで変換全体の正しさが把握されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok(a: str, b: str) -> bool:
    a = a.strip()[::-1]
    b = b.strip()[::-1]
    
    n = max(len(a), len(b))
    carry = 0

    for i in range(n):
        da = ord(a[i]) - 48 if i < len(a) else 0
        db = ord(b[i]) - 48 if i < len(b) else 0

        s = da + db + carry
        carry = s // 10

    return carry == 0

t = int(input())
for _ in range(t):
    a, b = input().split()
    print("YES" if ok(a, b) else "NO")
```このソリューションは、各テスト ケースを個別に処理します。 重要な実装の詳細は、インデックス 0 が最下位桁に対応するように両方の文字列を反転することです。これにより、桁上げの処理が簡素化されます。 

数字の抽出には速度を上げるために ASCII 算術演算が使用され、整数変換のオーバーヘッドが回避されます。 ループは常に最大長まで実行され、欠落している桁にゼロが埋め込まれます。これにより、数値のサイズが異なる場合のインデックス エラーが防止されます。 

正確さは完全に桁上げの安定性にかかっています。すべての桁位置を処理した後に桁上げが残っている場合、変換のバランスをとることができないため、答えは「いいえ」です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def ok(a: str, b: str) -> bool:
        a = a.strip()[::-1]
        b = b.strip()[::-1]
        n = max(len(a), len(b))
        carry = 0
        for i in range(n):
            da = ord(a[i]) - 48 if i < len(a) else 0
            db = ord(b[i]) - 48 if i < len(b) else 0
            s = da + db + carry
            carry = s // 10
        return carry == 0

    t = int(input())
    out = []
    for _ in range(t):
        a, b = input().split()
        out.append("YES" if ok(a, b) else "NO")
    return "\n".join(out)

 ## 特殊なケース

 主なエッジ ケースは、一方の数値が他方の数値よりもはるかに長い場合、特に長い数値の末尾にゼロ以外の数字が含まれる場合です。 その状況でも、アルゴリズムは短い数字にゼロを埋め込むことによってすべての数字を均一に処理します。 これにより、上位桁が無視されなくなります。 

別のケースとしては、次のような入力があります。`0`別の番号とペアになっています。 このアルゴリズムは、欠落している桁をゼロとして正しく処理し、キャリーをきれいに伝播するため、不均衡は最終的なキャリー状態に即座に現れます。 

最後に、次のようなキャリーの大きなチェーン`999...9`、キャリーは反復的に更新され、バックトラッキングや再帰を必要としないため、自然に処理され、最悪の伝播シナリオでも線形動作が保証されます。
