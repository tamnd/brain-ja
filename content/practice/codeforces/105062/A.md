 ## 解決策
 ## 問題の理解

 2 つの整数が与えられます。`m`そして`d`。 考えてみましょう`m`暦年の月番号として、および`d`月の一日として。 課題は、このペアが、問題によって暗示される単純化された世界で有効な暦日を表すことができるかどうかを判断することです。 

実際には、重要な唯一の制約は、その日が`d`特定の月にとっても意味がある`m`。 年や暦体系が明示的に定義されていないため、問題は暗黙的に、その月の許容範囲内にその日が存在するかどうかを確認することになります。 

重要な観察点は、月によって含まれる日数と有効性が異なるということです。`(m, d)`計算上のトリックではなく、その構造に依存します。 

入力サイズは非常に小さいため、`m ≤ 12`そして`d ≤ 31`これにより、最適化に関する懸念が即座に排除されます。 カレンダー ルールを直接エンコードするか、有効なペアをハードコードするソリューションであればどれでも十分です。 

微妙な特殊なケースは、日の制限が月によって異なるという事実から生じます。 たとえば、素朴なアプローチでは、毎月が 31 日であると仮定する可能性があり、現実的なカレンダーの解釈では、2 月 30 日や 4 月 31 日などの無効な日付が誤って受け入れられてしまいます。 もう 1 つの潜在的な落とし穴は、解釈によっては最小の月でも少なくとも 28 日または 30 日が許容されることを忘れ、有効なペアを誤って過剰に制限してしまうことです。 

たとえば、すべての月が 31 日であると誤って仮定している人がいたとしても、その人は受け入れるでしょう。`(2, 31)`これは明らかに間違っています。 一方で、すべての月に 30 日などの均一で小さい限界を仮定すると、誤って拒否することになります。`(1, 31)`。 

したがって、問題は、どの月にどの最大日が許可されるかを正確に区別することに帰着します。 

## アプローチ

 強引な考え方では、考えられるすべての暦日を有効なものとして扱い、その後、`(m, d)`すべての有効な日付の事前計算されたリストに表示されます。 これは、カレンダー ルールに従ってすべての月と月ごとの可能なすべての日を列挙し、それらをセットに保存し、メンバーシップを確認することを意味します。 これが機能するのは、ドメインが非常に小さく、最大でも数百エントリであるためです。 

問題はパフォーマンスではなく、不必要な複雑さです。 構造自体が固定されており自明である場合、構造を構築してクエリを実行するのは過剰です。 

より直接的なアプローチは、月と最大日の関係をエンコードすることです。 月は 31 日と 30 日の間で交互に表示されますが、2 月は特別なケースです。 制約が非常に小さいため、最もクリーンな解決策は、単純に月あたりの最大日数をハードコーディングして比較することです。`d`それに対して。 

重要な洞察は、これはまったく動的問題ではないということです。 テスト ケースや計算の間には依存関係はありません。 答えは完全に一定の検索によって決定されます。

 ## アルゴリズムのチュートリアル

 1. 各月からマッピングを作成する`m`有効な最大日数まで。 これは、各月に既知の上限がある固定カレンダー構造を反映しています。`d`。 
2. 入力ペアを読み取ります`(m, d)`。 
3. 比較する`d`月の最大許容値に対して`m`。 
4. もし`d`範囲内です、出力`"YES"`、それ以外の場合は出力`"NO"`。 

ステップ 1 の背後にある理由は、将来のすべてのチェックは一定のルールに依存するため、ルールを事前計算することでロジックや条件の繰り返しを避けることができるということです。 

### なぜ効果があるのか

 正確さは、各月の有効な最大日数が固定されており、有効な日付は次の条件を満たす必要があるという不変条件に基づいています。`1 ≤ d ≤ max_days[m]`。 マッピングはカレンダーの正確な制約をエンコードしているため、すべての有効な入力は不等号チェックに合格しますが、すべての無効な入力は不等号チェックに違反します。 この問題には他の構造や隠れた依存関係が存在しないため、この比較は必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    m, d = map(int, input().split())

    # days per month in a standard calendar abstraction
    max_days = {
        1: 31,
        2: 28,
        3: 31,
        4: 30,
        5: 31,
        6: 30,
        7: 31,
        8: 31,
        9: 30,
        10: 31,
        11: 30,
        12: 31
    }

    if 1 <= d <= max_days[m]:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```このコードは、カレンダー構造を辞書に直接エンコードします。 これにより、単一の検索と比較を超えた分岐ロジックが回避されます。 重要な詳細は、両方のエンドポイントが有効な日であるため、境界が包括的であることを確認することです。 

実装に関する微妙な詳細の 1 つは、辞書が 2 月を 28 日として正しく反映する必要があることです。これを忘れることは、同様の問題で誤答を引き起こす最も一般的な原因となるためです。 残りの月は固定パターンに従います。

 ## 特殊なケース

 エッジケースの 1 つは、31 日ある月の最大有効日です。 入力用`1 31`、アルゴリズムは取得します`max_days[1] = 31`そして小切手`31 ≤ 31`、通過し、生成します`"YES"`。 これにより、上限が包括的であることが確認されます。 

もう 1 つの特殊なケースは、2 月のオーバーフローです。 入力用`2 29`、ルックアップが返されます`28`、および条件`29 ≤ 28`失敗したため、出力は次のようになります`"NO"`。 これは、月固有の制約が正しく適用されていることを示しています。 

最後のエッジケースは、4 月のような一般的な 30 日の月です。 次のような入力の場合`4 30`、マッピングは次のようになります`30`、等価性が満たされ、31 日未満の月が検索を超えて特殊なケースを使用せずに正しく処理されることが保証されます。
