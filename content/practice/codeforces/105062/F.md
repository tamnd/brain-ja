 ## 問題の理解

 正の整数が与えられます$n$からの数値を扱います。$1$に$n$アイテムのラベルとして。 タスクは、できるだけ多くの素のペアを形成することです。$(a, b)$は次の場合にのみ有効です$a \neq b$そしてその最大公約数は$a$そして$b$各数値は最大 1 回使用でき、そのようなペアの最大数と、その最大値を達成する 1 つの有効な構造の両方を出力する必要があります。 

より具体的には、一致する各ペアが少なくとも 1 つの素因数を共有するように整数を一致させようとしています。 のような数字$1$は素因数がないため使用できませんが、合成数は共有約数に応じて複数の方法で組み合わせることができます。 

制約$n \le 10^5$ほぼ線形または線形に近い動作が必要であることを示唆しています。 すべてのペアを明示的にチェックするソリューションには、$O(n^2)$これは許容範囲をはるかに超えています。 すべてのペアの割り算をチェックするなどの作業でさえ遅すぎます。 これにより、ブルートフォースペアリングが即座に排除されます。 

微妙なエッジケースは次のような場合です$n$とても小さいです。 のために$n = 1$、ペアはありません。 のために$n = 2$、有効なペアも存在しません。 のために$n = 3$、やはりペアは存在しません。$1,2,3$1 より大きい公約数を共有するペアはありません。もう 1 つの重要なケースは、数値が素数または素数に近い場合です。これは、互換性が非常に限られているためです。 連続した番号をペアにしようとする貪欲な行為は失敗します。たとえば、$n = 5$有効なペアを 1 つだけ与える$(4,2)$単純な隣接ペアリングではその構造が欠落しています。 

## アプローチ

 ブルートフォース戦略では、すべての未使用の番号を試し、gcd が 1 より大きい別の未使用の番号との組み合わせを試行します。これは、条件を直接強制するため論理的に機能しますが、各選択には最大 300 秒までのスキャンが必要です。$O(n)$候補者、につながる$O(n^2)$最悪の場合の行動。 と$n = 10^5$、これは完全に不可能になります。 

重要な観察は、2 の因数をすべて削除した後、パリティによって数値をグループ化することです。すべての偶数には少なくとも 1 つの 2 の因数があり、それらの多くはこの共有約数を使用してペアにすることができます。 同様に、3 の倍数は因数 3 などを介してペアにすることができます。 ただし、すべての素数を明示的に追跡する必要はありません。 

より構造的なビューは、ブロック内の数値をペアにして、最大の数値から始めて共有約数を貪欲に利用することです。 下方向に反復すると、数値に遭遇するたびに$i$、その小さな素因数の 1 つのまだ対になっていない最大の倍数とそれを対にしようとします。 この問題の標準的な構造はさらに単純化されます。次の数値を処理します。$n$まで$2$、および未使用の各$i$、未使用の最大の倍数と組み合わせます。$i$それはまだ利用可能です。 これが機能するのは、有効なペアには除数構造が含まれている必要があり、より高い倍数を貪欲に消費することで将来の実現可能性が保たれるためです。 

それを理解するもう 1 つの方法は、すべての有効なペアを「基本因子」に関連付けることができるということです。$d > 1$、およびで割り切れる数$d$内部で照合できるプールを形成します。 大きい値から小さい値へ処理することで、常に大きい倍数が最初に使い果たされるようになり、小さい数値の断片化が防止されます。

 ## アルゴリズムのチュートリアル

 1. 配列またはブール値マーカーを作成します。`used[1..n]`false に初期化され、ペアの空のリストが返されます。 これは、番号がすでにペアに割り当てられているかどうかを追跡します。 
2. 反復する$i$から$n$まで$2$。 逆の順序では、柔軟なペアリング オプションが少ない大きな番号が最初に処理されます。 
3. もし$i$はすでに使用されています。すでに前のペアにコミットされているため、スキップします。 
4. それ以外の場合は、パートナーを見つけてください。$i$。 の倍数をスキャンします$i$から$2i, 3i, 4i, \dots$まで$n$、最大のものを選択します$j$そのような$j$未使用です。 
5. そのような場合は、$j$が見つかった場合は両方にマークを付けます$i$そして$j$使用済みとしてペアを記録する$(i, j)$。 正しさは次の事実から生まれます$j$約数を共有することが保証されています$i$、 それで$\gcd(i, j) \ge i > 1$。 
6. すべての値が得られるまで続行します。$i$処理されます。 

### なぜ効果があるのか

 重要な不変条件は、ペアを形成するときは常に、$(i, j)$、私たちは保証します$i$分割する$j$なので、gcd 条件は常に満たされます。 まず、より大きなインデックスをペアにするという貪欲な選択により、利用可能な倍数が少ないより小さな数のために潜在的なパートナーを無駄にしないことが保証されます。 除数クラス内での交換により有効性が保持されるため、ペアの数を減らすことなく、代替のペアをこのプロセスで生成されたペアに変換できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    used = [False] * (n + 1)
    res = []

    for i in range(n, 1, -1):
        if used[i]:
            continue

        partner = -1
        # find a multiple of i that is still free
        for j in range(2 * i, n + 1, i):
            if not used[j]:
                partner = j

        if partner != -1:
            used[i] = True
            used[partner] = True
            res.append((partner, i))

    print(len(res))
    for a, b in res:
        print(a, b)

if __name__ == "__main__":
    solve()
```実装は貪欲な構築に直接続きます。 重要な点は、倍数を昇順にスキャンしながら、最後に使用可能なものを保持することです。これにより、未使用の最大の倍数が効果的に選択されます。 これにより、構造の後半で必要になる可能性のある小さな倍数が時期尚早にロックされるのを防ぎます。 

からのループ$n$まで$2$各数値が潜在的なベースとして 1 回処理されるようにします。 の`used`配列はペアの素性を保証します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import gcd

    n = int(sys.stdin.readline())
    used = [False] * (n + 1)
    res = []

    for i in range(n, 1, -1):
        if used[i]:
            continue

    for a, b in res:
        out.append(f"{a} {b}")
    return "\n".join(out)

 ## 特殊なケース

 のために$n = 1$の場合、ループが 2 から始まるため、アルゴリズムはすぐに出力を生成しません。そのため、ペアリングの試行は行われません。 結果は正しく 0 ペアです。 

次のような小さな素数の場合$n = 5$、約数を共有する数値のみがペアにできます。 アルゴリズムのペア$4$と$2$、出発$1,3,5$未使用。これは、さらに有効なペアが存在できないことに一致します。 貪欲スキャンにより、シングルトン素数が将来のマッチングをブロックする前に、複合構造が確実に悪用されます。
