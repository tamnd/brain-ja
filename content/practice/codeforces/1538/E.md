 ## 問題の理解

 私たちには、変数に文字列を格納する非常に小さな「プログラミング言語」が与えられています。 各変数には、最大 5 つの長さのリテラル文字列が割り当てられるか、以前に定義された 2 つの変数の連結として定義されます。 プログラムはこのような代入のシーケンスであり、最後の変数の値のみが重要です。 

私たちの仕事は、最終的な文字列を明示的に再構築することではなく、部分文字列が何倍になるかを計算することです。`"haha"`重複するものも含めて、その中に表示されます。 

重要な制約は、文字列の長さが、連結の繰り返しにより指数関数的に増大する可能性があることです。 一つ一つの基本文字列は小さいのに、繰り返し`x = a + b`操作により、実体化するには大きすぎる文字列がすぐに作成される可能性があります。 したがって、直接シミュレーションすることは不可能です。 

微妙な難しさはオーバーラップ効果によるものです。 2つの文字列を連結する場合`A + B`、の発生`"haha"`完全に現れることができます`A`、完全に`B`、またはそれらの間の境界をまたぐ。 その境界動作は、接尾辞のみに依存します。`A`と接頭辞`B`、完全な内容ではありません。 

素朴なアプローチを打ち破るエッジケースはすべてこの境界に関するものです。 

1 つ目の障害モードは、連結境界間のオーバーラップを無視することです。 例えば、`"ha" + "ha"`含まれていない`"haha"`内部的にはどちらかの半分にありますが、連結によって 1 つのオカレンスが形成されます。 

2 番目の障害モードは、十分なプレフィックスおよびサフィックス情報を持たずにカウントのみを維持しようとすることです。 たとえば、その数だけを追跡すると、`"haha"`各変数内に出現すると、連結後に形成された新しい出現を検出できなくなります。 

3 番目の障害モードは、文字列が誤って切り捨てられることです。 完全な文字列は必要ありませんが、境界を越えた一致がすべて検出できるように十分なコンテキストが必要です。 パターンの長さは 4 であるため、小さな固定プレフィックスとサフィックスを維持するだけで十分です。 

## アプローチ

 ブルート フォース解釈では、すべての文字列を明示的に構築し、それをスキャンして次の文字列が出現するかどうかを確認します。`"haha"`。 各連結では文字列全体がコピーされ、カウントには線形スキャンが必要になります。 文字列のサイズは各ステップで 2 倍になる可能性があるため、`n`操作では文字列の長さが指数関数的なサイズに達する可能性があるため、このアプローチは最大値であっても実行不可能になります。`n = 50`。 

重要な観察は、長さ 4 の固定パターンの一致のみを考慮しているということです。 あらゆる発生`"haha"`4 文字のローカル ウィンドウ内に完全に収まります。 2 つの文字列を連結する場合、境界を越える新しい文字列は、左側の文字列の最後の 3 文字で始まり、右側の文字列の最初の 3 文字まで続く必要があります。 したがって、変数ごとに 3 つの情報を維持すれば十分です。`"haha"`内部の出現、最大 3 文字の接頭辞、および最大 3 文字の接尾辞。 

この表現では、連結は定数時間になります。内部カウントが追加され、サフィックスとプレフィックス間の最大 3 つの重複位置をチェックすることによって境界交差が計算されます。

 ## アルゴリズムのチュートリアル

 ステートメントを順番に処理し、変数ごとに 3 つのコンポーネントで構成されるコンパクトな状態を維持します。`"haha"`文字列の最初の最大 3 文字と最後の最大 3 文字。 

1. ステートメントが次の形式である場合`x := s`、変数を直接初期化します。 の発生を数えます`"haha"`で`s`それ以来ブルートフォースによって`|s| ≤ 5`、プレフィックスとサフィックスを格納します (長さ 3 に切り捨てられます)。 紐が細いので安心です。 
2. ステートメントが次の場合`x = a + b`、保存された状態を組み合わせます。`a`そして`b`。 内部カウントの合計は次のように始まります。`cnt[a] + cnt[b]`。 
3. 次に、境界を越えた発生を計算します。 以来`"haha"`長さは 4 なので、交差する箇所は接尾辞を取得して形成する必要があります。`a`と接頭辞`b`。 必要なすべてのスプリットを試します`k`終わりからのキャラクター`a`(1から3まで)と`4-k`冒頭からの登場人物`b`、連結が等しいかどうかを確認します`"haha"`。 一致するたびにカウントが増加します。 
4. 次のようにして新しいプレフィックスを構築します。`a.prefix + b.prefix`そして最大の長さにトリミングする 3.
 5. 同様に、次から新しいサフィックスを構築します。`a.suffix + b.suffix`、また最大3の長さにトリミングします。 
6. 最終的な答えは、最後のステートメントで使用された変数に格納されているカウントです。 

これが機能する理由は、`"haha"`いずれかのコンポーネント内に完全に含まれているか、連結境界を越えています。 パターンの長さが 4 であるため、スパニング オカレンスは両側から最大 3 文字で境界と交差する必要があります。プレフィックスとサフィックスのストレージにより、そのような重複を検出するために必要な情報が決して失われないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def calc_small(s):
    cnt = 0
    for i in range(len(s) - 3):
        if s[i:i+4] == "haha":
            cnt += 1
    return cnt

def merge(a, b):
    cnt = a[0] + b[0]

    A = a[1]
    B = b[2]

    # cross boundary check
    for k in range(1, 4):
        if k <= len(a[2]) and (4 - k) <= len(b[1]):
            if a[2][-k:] + b[1][:4 - k] == "haha":
                cnt += 1

    new_pref = (a[1] + b[1])[:3]
    new_suf = (a[2] + b[2])[-3:]

    return (cnt, new_pref, new_suf)

t = int(input())
for _ in range(t):
    n = int(input())
    mp = {}

    last_var = None

    for _ in range(n):
        parts = input().strip().split()

        if ":=" in parts:
            x = parts[0]
            s = parts[2]
            cnt = calc_small(s)
            mp[x] = (cnt, s[:3], s[-3:])
            last_var = x
        else:
            x = parts[0]
            a = parts[2]
            b = parts[4]
            mp[x] = merge(mp[a], mp[b])
            last_var = x

    print(mp[last_var][0])
```この実装は、すべての文字列を一定サイズの署名に圧縮することに依存しています。 の`calc_small`基本文字列の長さは最大でも 5 であるため、この関数は安全です。 の`merge`この関数は中核です。この関数は各側から最大 3 文字だけを検査します。これは、4 文字パターンのすべての境界出現を検出するには十分です。 

よくある落とし穴は、境界分割を誤って反復することです。 4 文字のパターンを 2 つの文字列に分割できるすべての方法を明示的にテストし、重複するケースが見逃されないようにします。 もう 1 つの微妙な点は、プレフィックスとサフィックスの長さを 3 に制限することです。 それ以上のストレージは不要であり、偶発的な O(n²) 動作の危険性があります。 

## 実用的な例

 変数が繰り返し展開して連結される最初のサンプルを考えてみましょう。 

簡単にするために、最後の意味のある変数のみを追跡します。`d`。 

| ステップ | 操作 | カウント | プレフィックス | サフィックス |
 | --- | --- | --- | --- | --- |
 | |`"h"`| 0 | h | h |
 | b |`"aha"`| 0 | ああ | ああ |
 | c | a + b | 1 | はぁ→`hah`| はぁ→`aha`|
 | c | c + c | 3 | ハッ + ハッ →`hah`| ああ + ああ →`aha`|

 このトレースは、境界近くを除いてほとんどの成長が無関係であることを示しています。 境界を越えた組み合わせが形成された場合にのみカウントが増加します`"haha"`。 

次に、指数関数的な成長のケースを考えてみましょう。`x := haha`倍増を繰り返します。 各倍加は構造を保持し、境界を越えた重複は多数の新しい出現に寄与し、表現サイズが一定のままカウントが指数関数的に増加します。

 ## 特殊なケース

 重要なエッジ ケースは、完全なオカレンスが連結境界を越えて正確に分割される場合です。 入力用`a := ha`そして`b := ha`、両側には個別に何も含まれていません`"haha"`ですが、それらを連結すると 1 つの有効なオカレンスが形成されます。 このアルゴリズムは、サフィックスとプレフィックスの組み合わせを使用してすべての境界分割を明示的にチェックすることでこれを処理します。 

もう 1 つのケースは、短い文字列の概念的なサイズが急速に増大する倍加の繰り返しです。 たとえば、から始めて、`x := haha`そして繰り返し適用する`x = x + x`、出現数は指数関数的に増加します。 このアルゴリズムは文字列を決して展開せず、プレフィックスとサフィックスのオーバーラップ ロジックを使用してすべての 2 倍化が一定時間で処理されるため、これを処理します。 

3 番目のケースは、パターンをまったく含まない文字列ですが、サフィックスとプレフィックスの構造を通じて今後の一致に影響を与えるものです。 内部カウントがゼロの場合でも、保存されたプレフィックスとサフィックスは必須のままであり、アルゴリズムはそれらを出現回数とは関係なく保存するため、将来の連結が正しく評価されることが保証されます。
