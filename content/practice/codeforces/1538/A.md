 ## 解決策
 ## 問題の理解

 私たちには一連の石が与えられており、それぞれの石には明確な強度値があります。 1 回の移動で、2 つの境界石のうち、残っている左端または右端の石のいずれか 1 つだけを削除することができます。 最終的には、配列内で最も弱い石と最も強い石の両方を削除したいと考えています。 

タスクは、両方の極値が削除されるまでに必要な境界削除の最小数を決定することです。 

制約からわかる重要な点は、各テスト ケースが小さく、石の数が最大 100 個であるということです。 これにより、高度なデータ構造や多くの状態にわたるシミュレーションの必要性が即座に排除されます。 テスト ケースごとに O(n) または O(n^2) のソリューションでも、十分に高速です。 

素朴な解釈では、両方のターゲット要素が削除されるまで、左右の欠失の考えられるすべてのシーケンスをシミュレートすることを提案するかもしれませんが、それは指数関数的な数の可能性をもたらします。 n = 100 の場合でも、それは完全に不可能です。 

不注意な推論を打ち破る微妙なケースがいくつかあります。 まず、両方のターゲットがなくなるまで片側から削除するのが常に最適であるとは限りません。これは、最小値と最大値の位置に応じて、最初に左側から削除するか、右側から削除するか、または両方を組み合わせて削除することが最善の戦略になる可能性があるためです。 

たとえば、最小値が左端近くにあり、最大値が右端近くにある場合、それぞれの近い側を削除するとよいでしょう。 ただし、両方が同じ側にある場合は、その側だけを削除するのが最適である可能性があります。 

2 番目のエッジ ケースは、一方の極値がすでに終端に近づいているが、もう一方の極値がアレイの奥深くにある場合です。 両方向を比較せずに一方の側から貪欲に除去すると、簡単に手数をオーバーカウントしてしまいます。 

## アプローチ

 ブルートフォースアプローチでは、最小要素と最大要素の両方が削除されるまで、左または右の削除のすべてのシーケンスが試行されます。 各状態は現在の部分配列によって定義され、各状態から 2 つの可能性に分岐します。 これにより、最大 n の深さのバイナリ ツリーが形成され、O(2^n) 状態になります。 枝刈りを行ったとしても、各決定が両方のターゲットの将来の可用性に影響を与えるため、構造は依然として指数関数的です。 

重要な洞察は、シーケンスについて考えるのをやめ、代わりに位置について考えることです。 重要なのは、最小要素と最大要素が元の配列のどこにあるかということだけです。 それらのインデックスがわかれば、問題は両方のインデックスが削除されるまで配列を両端から縮小することと同等になります。 

最小要素と最大要素の位置を i と j で表す場合、両方のインデックスを削除するために必要な削除の数だけを考慮します。 意味のある戦略は 3 つだけです。 左側から両方がなくなるまで削除することも、右側から両方がなくなるまで削除することも、両端から一部を左側から削除し、一部を右側から削除することもできます。 

これにより、問題は i と j に基づいて一定数のケースを評価することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | テストあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 配列をスキャンして、最小要素のインデックスと最大要素のインデックスを見つけます。 他のすべての値は削除プロセスとは無関係であるため、これらの位置によって残りの計算が完全に決まります。 
2. i を最小インデックス、j を最大インデックスとします。 一般性を失わずに、i <= j と仮定します。 そうでない場合は、交換してください。 この正規化により、後で大文字と小文字が分割されることが回避されます。 
3. 3 つの候補戦略を計算します。 まず、左からiとjの遠い方までをすべて削除します。 ゼロからインデックスを付けるため、これには max(i, j) + 1 の移動がかかります。 
4. 次に、右側から i と j に近いものまですべてを削除します。 両方の位置が消えるまで右から削除するため、これには n - min(i, j) の移動がかかります。 
5. 第三に、左側の i までの部分と右側の j までの部分を個別に削除します。 これには (i + 1) + (n - j) 回の移動が必要です。 これは、まず i より前のすべての要素を削除し、次に j より後のすべての要素を削除することに対応します。 
6. それぞれの値は、両方のターゲット要素が削除されることを保証する有効な削除戦略に対応するため、答えはこれら 3 つの値の最小値になります。 

### なぜ効果があるのか

 ゲームの状態は常に連続した部分配列であるため、一連の動きは境界を内側に縮小することに対応します。 最小要素と最大要素は両方とも、最後に残ったセグメントの外側になければなりません。 したがって、有効な戦略は、両方のインデックスを除外する最終セグメントを選択することと同じです。 そのセグメントに到達するコストは、左右からどれだけの要素が削除されるかによってのみ決まります。これにより、境界位置を超える問題が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    mn = min(range(n), key=lambda i: a[i])
    mx = max(range(n), key=lambda i: a[i])
    
    i, j = mn, mx
    if i > j:
        i, j = j, i
    
    # three strategies
    left_only = j + 1
    right_only = n - i
    both = (i + 1) + (n - j)
    
    print(min(left_only, right_only, both))
```このソリューションでは、まず線形スキャンを使用して最小値と最大値のインデックスを特定します。 次に、最小インデックスが最初に来るように順序を正規化します。 これにより、ケースを分割することなく 3 つの除去戦略を明確に定式化できます。 

最初の戦略は、2 つのターゲットの右端が消えるまで、左側から削除します。 2 番目は、一番左が消えるまで右から削除します。 3 番目は、除去を両端の間で分割します。これは、どちらの端も含まれていない中間セグメントを分離することに対応します。 

すべての演算は必要な削除の数を直接カウントするため、プロセスのシミュレーションは必要ありません。 

## 実用的な例

 ### 例 1

 入力:`[1, 5, 4, 3, 2]`最小値はインデックス 0、最大値はインデックス 1 です。 

| ステップ | i (分) | j (最大) | 左のみ | 右のみ | 両方 | 答え |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初期化 | 0 | 1 | 2 | 5 | 4 | 2 |

 最善の戦略は、左端を 2 回削除し、1 と 5 の両方をすぐに削除することです。 これは、片側のみに焦点を当てた方が混合除去よりも優れたパフォーマンスを発揮できることを示しています。 

### 例 2

 入力:`[2, 1, 3, 4, 5, 6, 8, 7]`最小値はインデックス 1、最大値はインデックス 6 です。 

| ステップ | 私 | j | 左のみ | 右のみ | 両方 | 答え |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初期化 | 1 | 6 | 7 | 7 | 3 + 2 = 5 | 5 |

 ここでの最適な解決策は、最小値までのプレフィックスと最大値以降のサフィックスを削除することです。 これにより、中央領域での無駄な動きを回避できます。 

これら 2 つの例は、極端なクラスタリングと分離された極端な値の間のコントラストを示しています。これは、まさに 3 つの場合の公式が捉えているものです。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        mn = min(range(n), key=lambda i: a[i])
        mx = max(range(n), key=lambda i: a[i])
        
        i, j = mn, mx
        if i > j:
            i, j = j, i
        
        left_only = j + 1
        right_only = n - i
        both = (i + 1) + (n - j)
        
        out.append(str(min(left_only, right_only, both)))
    
    return "\n".join(out)

 ## 特殊なケース

 最小値と最大値が隣接している場合、すでに端にある場合を除き、答えは常に 2 になります。 入力用`[2, 1, 3, 4]`、最小値と最大値はインデックス 1 と 0 にあるため、最良の動きは、一方の側を削除してからもう一方の側を削除し、2 つの動きを与えることです。 

両極端がすでに反対の端にある場合、次のようになります。`[1, 2, 3, 4, 5]`の場合、どちらかの側を 2 回削除すると両方のターゲットが即座に分離されるため、答えは 2 になります。 アルゴリズムはこれを次のように捕捉します。`both`または特別なケーシングを使用しない片面式。 

両極端が中間にある場合、たとえば、`[3, 1, 5, 2, 4]`、最適な戦略は両端からの除去を分割することです。 計算された`both`この値は、2 つの位置間の間隔の外側にある要素のみを削除する必要があることを正しく反映しています。
