 ## 解決策
 ## 問題の理解

 各人が最初に保持しているキャンディーの数を表す整数の配列が与えられます。 1 回の操作で、一部の人々を選択し、その人たちからすべてのキャンディーを取り出し、それらのキャンディーを全員に自由に再分配することができます。 

目標は、この 1 回の再配分ステップの後にすべての値を等しくすることです。 ただし、制約があります。全員を無料で選ぶことはできません。 私たちが気にするコストは選ばれた人の数であり、完全に等しい最終構成を達成するために組み合わせたキャンディーが十分になるように、選択しなければならない人の数を最小限に抑えたいと考えています。 

タスクを再構成する便利な方法は、目標値に対する不足と余剰の観点から考えることです。目標値は、解が存在する場合には配列の平均でなければなりません。 再分配ステップは、選択したインデックスからキャンディーのみを収集することを除いて完全に制限がないため、唯一の制限は、選択したサブセットに、平均からのすべての偏差を修正するのに十分な合計の「調整可能な質量」が含まれているかどうかです。 

入力サイズの制限は中程度で、テスト ケースは最大 10,000 個、配列の合計長は最大 20,000 個です。 これにより、テストごとの二次解は除外されますが、テストごとにソートまたは線形パスが可能になります。 値自体は直接処理できるほど小さいため、重要な問題は算術的な大きさではなく、サブセットの構造です。 

合計が n で割り切れない場合、微妙なエッジ ケースが発生します。 その場合、選択した要素の数に関係なく、再配布によって同じ値を生成することはできません。 すべての値がすでに等しい場合には、別の特殊なケースが発生します。この場合は、要素を 0 個選択するだけで十分です。 3 番目のケースは、1 つの要素だけが平均からの偏差がゼロでない場合です。 要素が大きい場合でも、要素を削除すると不均衡が正確に修正されるため、その要素だけを選択するだけで十分です。 

## アプローチ

 ブルート フォース解釈では、インデックスのすべてのサブセットが試行されます。 サブセットごとに、選択した値の合計を計算し、それらを削除しても均等に分散できる合計が残るかどうかを確認します。 これは、許可された操作の定義に直接一致するため、原理的には正しいですが、n ではすぐに指数関数的になります。 テスト全体で n が最大 200,000 になると、サブセットを保存することさえ不可能となり、候補の数は 2^n として増加します。 

重要な点は、最終的な構成が固定されているということです。すべての要素は平均値で終了する必要があるため、合計がすべてを決定します。 これにより、問題は、どの要素が「修正」する必要があるかを決定することに変換され、要素の合計寄与によって偏差のバランスがとれるようになります。 再分配シーケンスについて推論する代わりに、選択したサブセットが全体の過剰または不足を説明できるかどうかのみを考慮します。 

目標平均を固定すると、各要素は目標平均からの偏差に寄与します。 タスクは、合計偏差が合計不均衡と一致する最小数の要素を選択することになります。 正と負の偏差は全体的に相殺される必要があるため、最適な戦略は、絶対偏差が最大の要素を優先することです。これは、選択したインデックスごとに最大の「修正力」が得られるためです。 

したがって、偏差を絶対値で分類し、必要な修正に達するまで貪欲に蓄積します。 残差不均衡がゼロに達した瞬間、より小さい要素での置換には厳密により多くのピックが必要となるため、選択された要素の数は最適になります。

 ## アルゴリズムのチュートリアル

1. 配列の総和を計算し、n で割り切れるかどうかを確認します。 割り切れない場合は等化できないため、答えは -1 になります。 これは、再分配によって総和が保存されるためです。 
2. 合計を n で割った値として目標値を計算します。 すべての最終構成では、この値を各位置に正確に割り当てる必要があります。 
3. 各要素について、ターゲットからの偏差を計算します。 偏差がプラスの場合は黒字、マイナスの場合は赤字を意味します。 これらの偏差は、各指数が不均衡にどの程度寄与しているかを表します。 
4. すべての偏差の合計がゼロであることに注意してください。そのため、タスクは、偏差が「アクティブ化」されているインデックスのサブセットを使用して不均衡をキャンセルすることになります。 
5. 要素を絶対偏差で降順に並べ替えます。 選択された各インデックスが不均衡の修正により多く寄与するため、大きな偏差はより効率的です。 
6. ソートされたリストを調べて、実行中の修正された不均衡がゼロに達するまで偏差の寄与を蓄積します。 使用された要素の数を数えます。 
7. この数を選択した友達の最小数として返します。 

### なぜ効果があるのか

 選択された各インデックスはシステムからその偏差を除去します。目標は、そのような除去の最小数を使用して全体の不均衡を除去することです。 すべての除去は偏差値に線形的に寄与するため、最初に大きな値を選択すると、全体の不均衡を解消するのに必要なステップ数が最小限に抑えられます。 より大きな偏差をスキップしながらより小さな偏差を使用するソリューションは、それらを交換することで改善でき、修正力を高めながら選択した要素の数を減らすか保存することで、貪欲な最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        s = sum(a)
        if s % n != 0:
            out.append("-1")
            continue

        target = s // n

        dev = [x - target for x in a]

        dev.sort(key=lambda x: abs(x), reverse=True)

        need = 0
        cnt = 0

        for d in dev:
            if need == 0:
                break
            need += d
            cnt += 1

        out.append(str(cnt))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、再分配によって全体の合計を変更できないため、合計の割り算を通じて実現可能性を検証することから始まります。 次に、問題を目標値からの偏差に変換し、解決する必要がある正確な不均衡を分離します。 

絶対偏差による並べ替えにより、最も影響力のある修正が常に最初に考慮されるようになります。 ループは不均衡が解消されるまで要素の取得をシミュレートし、カウンターは必要な要素の数を追跡します。 

微妙な点は、停止条件はすべての要素が処理されたときではなく、累積偏差が全体の不均衡を解消したときであることです。 これは、全体的な不一致を解決するために必要なインデックスのすべてではなく、選択された十分なインデックスのみが必要であることを反映しています。 

## 実用的な例

 ### 例 1

 入力:```
n = 4
a = [4, 5, 2, 5]
```ターゲットは 4。Dev = [0, 1, -2, 1]

 絶対値でソート: [-2, 1, 1, 0]

 | ステップ | 選ばれた | 累計額 |
 | --- | --- | --- |
 | 1 | -2 | -2 |
 | 2 | +1 | -1 |
 | 3 | +1 | 0 |

 3 つ選択すると停止します。これは、システムのバランスをとるには 3 つの要素で十分であることを意味します。 これは、大きな負の偏差を最初に修正する必要があり、小さな正の修正でバランスが完了することを示しています。 

### 例 2

 入力:```
n = 2
a = [0, 4]
```目標は 2 です。Dev = [-2, 2]

 ソート済み: [2, -2]

 | ステップ | 選ばれた | 累計額 |
 | --- | --- | --- |
 | 1 | 2 | 2 |
 | 2 | -2 | 0 |

 両方の要素が必要なので、答えは 2 です。これは、偏差が対称で大きさが等しい場合、両方を選択する必要があることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 並べ替えの偏差がテストごとに支配的 |
 | スペース | O(n) | 偏差配列 | を格納します。 

この制約では合計要素数が 2×10^5 まで許容されるため、n log n アプローチは十分に高速であり、メモリ使用量は線形のままです。

            cnt += 1

 ## 特殊なケース

 すべての要素がすでに等しい場合、偏差配列はすべて 0 になるため、ループはすぐに終了し、何も選択せずに 0 を返します。 

合計が n で割り切れない場合、ターゲット平均が存在しないためアルゴリズムは早期に停止し、-1 を出力し、サブセットの選択に関係なく再分配が不可能になります。 

要素が 1 つだけの場合、要素は常にそれ自体と等しいため、修正の必要がないため、答えは 0 になります。
