 ## 解決策
 ## 問題の理解

 道路には (n+1) 個の停留所と (n) 個の連続したセグメントがあります。 ランプ (i) は、ストップ (i) と (i+1) の間のセグメントを制御します。 インデックス (a,a+1,\ldots,b-1) のすべてのランプが点灯しているときはいつでも、タクシーは停留所 (a) から停留所 (b) まで移動できます。 

ランプ構成は時間 (0) で与えられます。 毎時間の終わりに、ちょうど 1 つのイベントが発生します。 トグルで 1 つのランプが変更され、クエリでは、停止 (a) から停止 (b) までの全期間が継続的に使用できた時間が何時間経過したかが尋ねられます。 クエリには、現在のイベント時刻までの完了したすべての時間が含まれます。 

制約は (n,q\le 300000) です。 すべてのクエリですべてのランプを直接スキャンすると (O(nq)) かかり、これは (9\cdot10^{10}) 回のランプ チェックに相当します。 これは、5 秒の制限がサポートできる範囲をはるかに超えています。 イベントごとにおおよそ対数作業が必要になり、(O((n+q)\log n)) の解が得られます。 

最初の微妙な点は、イベントが時間の終わりに発生することです。 考慮する```
1 1
1
query 1 2
```答えは、`1`、 ない`0`。 ランプは 1 時間目まで点灯していたので、完了した時間がカウントされます。 

2 番目の微妙な点は、1 時間の終わりに切り替えると、それ以降の時間にのみ影響することです。 公式サンプルでは、​​5 時間目の終わりにランプ 3 が切り替わります。設定は次のとおりです。`11011`1時間目から5時間目まで、`11111`したがって、6 時間目のクエリでは、ストップ 3 と 4 で使用可能な 1 時間がわかります。 

3 番目の微妙な点は、複数のランプにまたがるクエリです。 例えば、```
3 1
101
query 1 4
```答えがあります`0`, 真ん中のランプが消えているので。 エンドポイントのみをチェックすると、ルート全体が使用可能であると誤って結論付けられてしまいます。 

最後に、1 つのセグメントを含むクエリは依然として範囲クエリです。 のために```
2 1
01
query 2 3
```答えは`1`、ランプ 2 のみが重要であるためです。 エンドポイント規則を処理せずにストップ インデックスを直接セグメント インデックスに変換することは、off-by-one エラーの一般的な原因です。 

## アプローチ

 簡単な解決策では、現在のランプの状態をシミュレートし、クエリごとにランプ (a) ～ (b-1) を検査できます。 これらがすべてオンになっている場合、クエリの応答は、この構成を変更しないままにした前回のイベントからの時間数だけ増加する可能性があります。 構成は連続するトグル イベント間で一定であるため、これは正しいです。 

問題は範囲検査です。 1 つのクエリで (n) 個のランプを検査でき、(q) 個のクエリが存在する可能性があります。 最悪の場合、これにより (O(nq)=9\cdot10^{10}) チェックが行われます。 現在の状態を維持すること自体はコストがかかりませんが、区間全体が 1 で構成されているかどうかを繰り返し判断するのはコストがかかりません。 

重要な点は、この質問は、範囲が現在すべてオンになっているかどうかだけを尋ねているわけではないということです。 その範囲がすべてオンになっていた合計時間を尋ねます。 これは、履歴情報をセグメント ツリーに直接保存することを示唆しています。 

すべてのセグメント ツリー ノードについて、そのノード内のすべてのランプが現在オンになっているかどうか、およびノー​​ド全体がオンになっていた最後にそのノードが処理されるまでの合計時間を記録します。 また、このノードの履歴値が最後に確定されたときのタイムスタンプも保存します。 

あるノードが、ある時点 (最後) から完全にオンになっていると仮定します。 時刻 (t) で最初にその情報が必要なとき、未記録期間に対するその情報の寄与は単純に (t-last) になります。 ノードが現在オフである場合、寄与はゼロです。 ポイントの切り替えは (O(\log n)) 個のセグメント ツリー ノードのみを変更するため、影響を受けるすべての履歴値は (O(\log n)) で確定できます。 範囲クエリは (O(\log n)) 個の正規ノードを訪問し、それらの各ノードはクエリ時に同様に終了できます。 

ブルートフォースアプローチは、重要なすべてのランプを明示的にチェックするため機能します。 同じ長い範囲が何度もチェックされるため、失敗します。 子孫の 1 つが切り替えられた場合にのみセグメント全体の状態が変化するという観察により、累積された使用可能時間を保存し、必要な場合にのみ更新することができます。

 | 最適 | (O((n+q)\log n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (n) 個のランプ上にセグメント ツリーを構築します。 ノードごとに、`on`これは、そのノードによって表されるすべてのランプが現在オンになっている場合に正確に当てはまります。 ストアも`total`、ノード全体がオンになっていたすでに確定された時間、および`last`、通過するタイムスタンプ`total`が確定しました。 
2. すべてのノードの初期化`last`値をゼロにします。 初期設定は時間ゼロ以降有効であるため、時間はまだ蓄積されていません。 の`on`値は最初のバイナリ文字列から計算されます。 
3. ノードが時刻 (t) にアクセスされると、欠落している時間間隔が確定されます。 もし`on`が true の場合、(t-last) を追加します`total`。 次に設定します`last=t`。 もし`on`偽です、ただ`last`その間隔中にノードが何も貢献しなかったため、変更されます。 
4. 時間の終わり (t) にランプ (i) を切り替えるには、そのリーフからルートに向かって歩き、時間 (t) でパス上のすべてのノードを終了します。 これは、トグル前の 1 時間 (t) の間に存在した状態を記録します。 その後、葉っぱを裏返します`on`価値。 
5. 切り替えたリーフの祖先を下から上に再計算します。 親は、その子の両方が現在オンになっているときと同じように、現在オンになっています。 親の設定`last`新しい状態がこのタイムスタンプで始まるため、値を (t) に設定します。 
6. 停止(a)から停止(b)までの問合せの場合、半開ランプ間隔([a-1,b-1)]に換算します。 これらは正確にはランプ (a,a+1,\ldots,b-1) です。 この間隔を通常の (O(\log n)) セグメント ツリー ノードに分解します。 
7. 現在の時間 (t) で選択したすべてのノードを確定し、そのノードを追加します。`total`答えに対する価値観。 選択されたノードは互いに素であり、要求されたランプを正確に含むため、それらの使用可能時間の寄与を直接合計できます。 
8. 結果の合計を出力します。 クエリによってランプの構成は変更されないため、クエリ後にツリー状態を再計算する必要はありません。 

不変条件は、すべてのセグメント ツリー ノードについて、`total`時刻 0 から時刻までの間隔でセグメント全体がオンになっていた時間を正確に含みます。`last`。 その`on`flag は直後の設定を記述します。`last`。 後でノードがタッチされるたびに、`last`新しい時間の状態は一定であるため、その長さを加算すると、新しく完了したすべての使用可能な時間が正確に計算されます。 ポイント切り替えは、ルートからリーフへのパスに沿ってこの不変条件を保持し、範囲クエリは、表現された間隔が要求されたルートを正確に形成する、互いに素なノードを合計します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    s = input().strip()

    size = 1
    while size < n:
        size <<= 1

    # on[v]   = whether the whole segment of v is currently on
    # total[v] = finalized amount of time for which the whole segment was on
    # last[v] = time through which total[v] has been finalized
    on = [False] * (2 * size)
    total = [0] * (2 * size)
    last = [0] * (2 * size)

    for i, ch in enumerate(s):
        on[size + i] = (ch == '1')

    for v in range(size - 1, 0, -1):
        on[v] = on[v << 1] and on[v << 1 | 1]

    def touch(v, t):
        if on[v]:
            total[v] += t - last[v]
        last[v] = t

    def toggle(pos, t):
        v = size + pos

        # Finalize every node whose old state is about to change.
        u = v
        while u:
            touch(u, t)
            u >>= 1

        # Change the lamp itself.
        on[v] = not on[v]

        # Recompute ancestors using the new child states.
        v >>= 1
        while v:
            on[v] = on[v << 1] and on[v << 1 | 1]
            last[v] = t
            v >>= 1

    def query(left, right, t):
        # Query [left, right) in zero-based lamp indices.
        left += size
        right += size

        answer = 0

        while left < right:
            if left & 1:
                touch(left, t)
                answer += total[left]
                left += 1

            if right & 1:
                right -= 1
                touch(right, t)
                answer += total[right]

            left >>= 1
            right >>= 1

        return answer

    out = []

    for t in range(1, q + 1):
        event = input().split()

        if event[0] == "toggle":
            pos = int(event[1]) - 1
            toggle(pos, t)
        else:
            a = int(event[1])
            b = int(event[2])

            # Stops [a, b] correspond to lamps [a-1, b-1).
            left = a - 1
            right = b - 1

            out.append(str(query(left, right, t)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```反復範囲分解が簡単になるため、ツリーでは 2 のべき乗の数のリーフが使用されます。 余分なリーフはオフに初期化されます。 すべてのクエリはランプ (n) で終了するため、これらは有効なクエリには決して現れず、選択された正規ノードに影響を与えることはできません。 

の`touch`機能は中心的な操作です。 ノードの状態はその後変更されていません。`last[v]`したがって、現在オンになっている場合は、正確に`t - last[v]`さらに時間が経過すると、セグメント全体が点灯します。 

トグル操作は、最初に古い状態を使用してすべての祖先に触れます。 この順序が重要です。 リーフが最初に反転された場合、トグル直前の時間間隔が失われる可能性があります。 古い貢献が完了すると、葉がめくられ、祖先が再構築されます。 

クエリは、ストップを慎重にランプに変換します。 停止点 (a) から停止点 (b) までの移動には、ランプ (a) から (b-1) が使用されるため、ゼロベースの半開表記では、間隔は次のようになります。`[a - 1, b - 1)`。 

Python の整数はオーバーフローせず、最大の答えは最大 (q) であり、(300000) にすぎません。 この実装は、セグメント ツリーを再帰的に走査するのではなく反復的であるため、最大 (300,000) 個のイベントにわたる Python 再帰オーバーヘッドが回避されます。

フルストリート クエリは、オフバイワン エラーのもう 1 つの頻繁な原因です。 と```
3 1
111
query 1 4
```ストップ 1 からストップ 4 までのルートは、ランプ 1、2、および 3 を使用します。実装では、これを次のように変換します。`[0,3)`, したがって、3 つの葉がすべて選択されています。 最初の 1 時間は完全なセグメントがオンになっていたため、答えは次のとおりです。`1`。

オフのランプが 1 つ含まれる範囲は、たとえ他のすべてのランプがオンであっても、ゼロを寄与する必要があります。 のために```
