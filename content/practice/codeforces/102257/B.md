 ## 解決策
 ## 問題の理解

 頂点が島でエッジが橋である無向グラフがあります。 どの橋にも重量制限があるので、重量のある車は`w`電流制限が少なくとも次の値であるブリッジを正確に使用できます。`w`。 更新では 1 つの既存の橋の制限が変更されますが、指定された車両を運ぶことができる橋のみが利用可能な場合、クエリでは指定されたアイランドを含む接続コンポーネント内のアイランドの数が尋ねられます。 グラフとクエリの制限は十分に大きいため、クエリ シーケンス全体が事前にわかっているという事実を利用する必要があります。 公式の制約は次のとおりです`n <= 50,000`、`m <= 100,000`、 そして`q <= 100,000`、2 秒の時間制限と 512 MB のメモリ制限があります。 

重要な問題は、2 つの次元が同時に変化することです。 ブリッジ制限が更新されると同時に、すべてのクエリで異なる重みしきい値が選択されるため、グラフは時間の経過とともに変化します。 すべてのクエリを直接走査すると、基本的にグラフ全体が毎回検査されます。 まで`100,000`クエリと`100,000`エッジ、さらには`O(n + m)`クエリごとの走査は約`1.5 * 10^10`最悪の場合、2 秒の制限をはるかに超えて頂点とエッジにアクセスすることになります。 

誤って処理されやすい小さなケースがいくつかあります。 まず、空のグラフでも開始島自体をカウントする必要があります。 例えば、```
1 0
1
2 1 1
```出力があります```
1
```なぜなら、島には橋を使わずに島自体から到達できるからです。 訪問した近傍の数から応答を初期化するトラバーサル実装は、誤ってゼロを返す可能性があります。 

ブリッジ制限との比較は包括的です。 例えば、```
2 1
1 2 5
1
2 1 5
```出力があります```
2
```ちょうど重量のある車なので`5`制限が次の橋に入ることが許可されています`5`。 使用する`>`の代わりに`>=`静かにこの接続を失います。 

アップデートにより、橋はより強くなるだけでなく弱くもなります。 例えば、```
2 1
1 2 5
3
2 1 5
1 1 1
2 1 2
```生成する```
2
1
```アップデート後、唯一のブリッジに制限があるため`1`、つまり重量のある車`2`それを越えることはできません。 初期の重みのみを格納する実装では、誤った値が返され続けます。`2`。 

平行なブリッジも分離したままにする必要があります。 例えば、```
2 2
1 2 3
1 2 5
3
2 1 4
1 2 2
2 1 4
```生成する```
2
1
```アップデート前は限界の橋だったから`5`島々を繋ぎ、その橋を`2`、残りの橋には制限のみがあります`3`。 ブリッジをエンドポイントのペアのみで扱うと、この区別が失われます。 

## アプローチ

 ブルートフォースアプローチは簡単です。 タイプ 2 のクエリごとに、すべてのブリッジをスキャンし、現在の制限がクエリされた重み以上であるブリッジのみを保持し、要求されたアイランドから BFS または DFS を実行します。 横断ではその車両が利用できる橋を正確に使用するため、結果として得られる訪問数が正確な答えとなります。 この方法は正しいですが、最悪の場合のコストは次のとおりです。`O(q(n + m))`。 と`n = 50,000`、`m = 100,000`、 そして`q = 100,000`、それはおおよそです`1.5 * 10^10`Python のオーバーヘッドを考慮する前に、基本的な頂点とエッジの操作を説明します。 

有益な観察は、クエリの短い連続ブロック内では更新がまばらであるということです。 クエリシーケンスを約のブロックに分割します。`B = sqrt(q)`操作。 1 つのブロック内では、少数の個別のブリッジのみを更新できます。 これらの橋を特別なものと呼びます。 1 つおきのブリッジは、ブロック全体でまったく同じ重みを維持します。 

1つのブロックについて、すべての特殊な橋を一時的に削除します。 残りのグラフは静的です。 エッジを重みでソートし、要求された重みの降順ですべてのタイプ 2 クエリを処理できます。 DSU は、現在のクエリに対して十分な重みを持つすべての固定ブリッジによって形成される接続コンポーネントを表します。 

特別な橋だけがまだありません。 多くてもあります`B`そのため、1 つのクエリでエンドポイントの DSU コンポーネントを取得し、小さな補助 DSU を構築できます。 各補助頂点は固定グラフのコンポーネント全体を表し、その初期サイズはメイン DSU によって格納されているサイズと同じです。 この小さなグラフに特別なブリッジを追加すると、クエリされたアイランドを含むコンポーネントが正確に得られます。 

ブルートフォース手法は、すべてのクエリに対して正確なしきい値グラフを構築するため機能しますが、ほぼ同じ情報が繰り返し再構築されます。 ブロック観察により、高価な静的部分をブロックごとに 1 回構築し、すべての変更を最大で 1 つに分離できます。`B`クエリごとのエッジ。 

以下の実装は、すべてのクエリの現在の特殊エッジ状態をビット マスクとして表します。 ブロックを時系列に通過する際に、すべての特殊ブリッジの現在の重みがわかるため、どの特殊ブリッジが各クエリのしきい値を満たすかを記録できます。 後でクエリが重みによって並べ替えられると、元の状態がすでに保存されています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(q(n + m))`|`O(n + m)`| 遅すぎる |
 | ブロック分解 |`O((q/B)m log m + qB)`|`O(n + m + qB)`単純な形で | 承認済み |

 と`B`その周り`sqrt(q)`、コストのかかる作業はブロック全体に分散されますが、個々のクエリは少数の特別なブリッジのセットを検査するだけで済みます。 

## アルゴリズムのチュートリアル

 1. 何かに答える前に、グラフ全体とクエリ シーケンス全体を読んでください。 これにより、各ブロック内でどのブリッジが更新されるかを事前に知ることができるため、ブロック分解が可能になります。 
2. クエリを約サイズの連続したブロックに分割します。`sqrt(q)`。 現在のブロックについて、少なくとも 1 回更新されたすべてのブリッジを収集します。 これらは特別な橋です。 最大でも存在する可能性があります`B`ブロックに含まれるのは`B`操作。 
3. ブロックを元の時系列順にシミュレートします。 すべてのブリッジの現在の重量を維持します。 タイプ 1 クエリが特別なブリッジを変更するたびに、その重みを更新します。 すべてのタイプ 2 クエリについて、特殊ブリッジをスキャンし、現在の重みがクエリ重み以上である特殊ブリッジを正確に含むビット マスクを作成します。 これにより、クエリの正確な瞬間にグラフの特別な部分が記録されます。 
4. すべての特殊なブリッジを除外し、残りの固定ブリッジを重量の降順に並べ替えます。 それらの重みはブロック中に変更されないため、この並べ替え順序はブロック内のすべてのクエリに対して有効です。 
5. 必要な車両重量を減らすことによってブロックのタイプ 2 クエリを並べ替えます。 空の DSU から始めます。 クエリしきい値が減少するにつれて、重みが十分に大きくなったすべての固定ブリッジを追加します。 したがって、DSU は、そのクエリで使用できるすべての固定ブリッジを表します。 
6. このソート順の各クエリについて、その開始アイランドを含む固定グラフ コンポーネントを見つけます。 次に、アクティブな特別なブリッジがアクセスする基本コンポーネントのみを含む一時的な DSU を作成します。 すべての一時ノードに、対応する基本コンポーネントのサイズを与えます。 
7. クエリのマスクにビットが存在するすべての特別なブリッジについて、そのエンドポイントを含む基本コンポーネントを見つけて、それらの一時ノードを結合します。 両方のエンドポイントがすでに同じ基本コンポーネント内にある場合、特別なブリッジは何も変更しません。 
8. 開始島を含む一時コンポーネントのサイズが答えです。 クエリは入力順ではなく重み順に処理されるため、クエリの元の位置に保存します。 
9. 次のブロックに移動します。 ブリッジの重みには、前のブロックのすべての更新後の状態が正確に含まれるようになったので、同じプロセスを繰り返すことができます。 

### なぜ効果があるのか

 固定ブロックの場合、特別ではないすべてのブリッジはブロック全体にわたって一定の重みを持ちます。 クエリがしきい値の降順で処理される場合、メイン DSU には、制限が現在のしきい値以上である固定ブリッジが正確に含まれます。 したがって、そのコンポーネントはまさに特別なブリッジなしで取得できる接続コンポーネントです。 

残っている使用可能な橋はすべて特別であり、`B`彼らのうち。 すべてのメイン DSU コンポーネントを 1 つの一時的な頂点に縮小すると、固定ブリッジを介したすべての接続が維持されます。 現在の制限がクエリを満たす特別なブリッジを正確に追加すると、そのクエリの時点での完全なしきい値グラフが再現されます。 したがって、開始アイランドを含む一時コンポーネントには、到達可能なすべてのアイランドが正確に含まれるため、その格納サイズが必要な答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    __slots__ = ("parent", "size")

    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        parent = self.parent
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(self, a, b):
        parent = self.parent
        size = self.size

        a = self.find(a)
        b = self.find(b)

        if a == b:
            return False

        if size[a] < size[b]:
            a, b = b, a

        parent[b] = a
        size[a] += size[b]
        return True

def solve():
    n, m = map(int, input().split())

    eu = [0] * m
    ev = [0] * m
    weight = [0] * m

    for i in range(m):
        u, v, w = map(int, input().split())
        eu[i] = u - 1
        ev[i] = v - 1
        weight[i] = w

    q = int(input())
    queries = [None] * q

    for i in range(q):
        t, a, b = map(int, input().split())
        queries[i] = (t, a - 1, b)

    answers = [None] * q
    mask_at = [0] * q

    block_size = max(1, int(q ** 0.5) + 1)

    for left in range(0, q, block_size):
        right = min(q, left + block_size)

        special_set = set()

        for i in range(left, right):
            t, a, b = queries[i]
            if t == 1:
                special_set.add(a)

        special = list(special_set)
        k = len(special)

        special_pos = {e: j for j, e in enumerate(special)}

        # Record the exact state of special edges for every query.
        for i in range(left, right):
            t, a, b = queries[i]

            if t == 1:
                weight[a] = b
            else:
                mask = 0
                for j, e in enumerate(special):
                    if weight[e] >= b:
                        mask |= 1 << j
                mask_at[i] = mask

        # The non-special edges are static throughout this block.
        fixed = [e for e in range(m) if e not in special_set]
        fixed.sort(key=weight.__getitem__, reverse=True)

        # Queries are processed by threshold, not by their original order.
        ordered_queries = [
            i for i in range(left, right)
            if queries[i][0] == 2
        ]
        ordered_queries.sort(key=lambda i: queries[i][2], reverse=True)

        base = DSU(n)
        edge_ptr = 0
        fixed_count = len(fixed)

        for qi in ordered_queries:
            _, s, required = queries[qi]

            while edge_ptr < fixed_count:
                e = fixed[edge_ptr]
                if weight[e] < required:
                    break

                base.union(eu[e], ev[e])
                edge_ptr += 1

            # Build the small DSU induced by the special edges.
            local_parent = []
            local_size = []
            local_index = {}

            def get_local_node(root):
                node = local_index.get(root)
                if node is None:
                    node = len(local_parent)
                    local_index[root] = node
                    local_parent.append(node)
                    local_size.append(base.size[root])
                return node

            def local_find(x):
                while local_parent[x] != x:
                    local_parent[x] = local_parent[local_parent[x]]
                    x = local_parent[x]
                return x

            root_s = base.find(s)
            local_s = get_local_node(root_s)

            mask = mask_at[qi]

            while mask:
                bit = mask & -mask
                j = bit.bit_length() - 1
                mask -= bit

                e = special[j]

                ru = base.find(eu[e])
                rv = base.find(ev[e])

                a = get_local_node(ru)
                b = get_local_node(rv)

                a = local_find(a)
                b = local_find(b)

                if a != b:
                    if local_size[a] < local_size[b]:
                        a, b = b, a

                    local_parent[b] = a
                    local_size[a] += local_size[b]

            local_root = local_find(local_s)
            answers[qi] = local_size[local_root]

    sys.stdout.write(
        "\n".join(str(answers[i]) for i in range(q) if answers[i] is not None)
    )

if __name__ == "__main__":
    solve()
```の`DSU`すべてのコンポーネントの親とそのサイズの両方を保存します。 これらの DSU は決してロールバックされないため、パス圧縮が使用されます。 の`union`この操作では、小さいコンポーネントを大きいコンポーネントに接続し、ツリーを浅く保ちます。 

ブロックごとに、`special_set`値が変更される可能性のあるブリッジを正確に識別します。 時系列パスは、しきい値でソートされたパスの前に発生する必要があります。 そうしないと、クエリが発行時に存在していた重みではなく、ブリッジの最終的な重みを誤って使用する可能性があります。 

固定エッジは降順にソートされます。 ポインタ`edge_ptr`クエリのしきい値も減少するため、先に進むだけです。 条件は`weight[e] < required`、 ない`<=`, 車の重量が限界の橋が使えるからです。 

一時的な DSU は、基本コンポーネントのルートを頂点として使用します。 そのコンポーネントのサイズはこれらの基本コンポーネントのサイズから始まるため、2 つの一時ノードが結合されるとき、それらのサイズを単純に追加できます。 これは、接続性の計算を、要求されたコンポーネント サイズの計算に変換する部分です。 

ビットマスクは内部のブリッジの位置によってインデックス付けされます。`special`。 使用する`mask & -mask`高価な一時 DSU フェーズ中に非アクティブな位置をスキャンすることなく、一度に 1 つのアクティブな特別なブリッジを抽出します。 

すべての重みは Python 整数内に快適に収まります。 C++ 実装では、答え自体は最大でも`n`ただし、ブリッジ制限には 32 ビット整数が必要です。

 ## 特殊なケース

 空のグラフの場合、```
1 0
1
2 1 1
```ブロックには特別なエッジや固定エッジはありません。 基本 DSU には、最初はサイズ 1 のコンポーネントが 1 つあります。 クエリされたアイランドはそのコンポーネントにマッピングされるため、一時 DSU にもサイズ 1 の頂点が 1 つ含まれます。 出力は`1`。 

等価境界については、```
2 1
1 2 5
1
2 1 5
```固定エッジの重みはクエリしきい値とまったく同じです。 固定エッジ ポインターは次の条件を使用します。`weight[e] >= required`、したがって、エッジはベース DSU に挿入されます。 したがって、両方のアイランドは同じコンポーネントに属し、出力は次のようになります。`2`。 

減少するアップデートの場合、```
2 1
1 2 5
3
2 1 5
1 1 1
2 1 2
```ブリッジはブロック内で更新されるため特別です。 更新の前に、最初のクエリは特殊エッジ マスクをアクティブとして記録します。 アップデートにより重みが次のように変更されます。`1`。 最終クエリにはしきい値があります`2`、そのため、そのマスクには特別なエッジは含まれません。 基本グラフは空で、一時的な DSU には開始アイランドのみが含まれます。 答えは次のとおりです。`2`そして`1`。 

平行エッジの場合、```
2 2
1 2 3
1 2 5
3
2 1 4
1 2 2
2 1 4
```両方のブリッジは別々のエッジ インデックスで保存されます。 最初は重りの橋だけ`5`閾値を満たしている`4`、したがって、答えは次のとおりです`2`。 そのブリッジが次のように変更された後、`2`、どちらの橋も重量を支えることができません`4`、スタート島を放置して生産`1`。 このため、実装ではエンドポイント ペアではなくブリッジ ID によって特別なブリッジのインデックスが作成されます。 

同じブリッジへの繰り返しの更新を含むブロックの場合、特別なセットにはそのブリッジが 1 回だけ含まれます。 時間の流れの中で、`weight`値は更新が表示されるたびに変更され、タイプ 2 の各クエリはその正確な位置に現在の値を記録します。 したがって、同じブリッジが 1 つのブロック内の異なるクエリに対して異なるアクティブ ビットを持つことができますが、補助 DSU には依然としてそのブリッジに対して最大 1 つのノードが含まれます。 

中央の不変式は、これらすべてのケースで存続します。処理されるクエリごとに、メイン DSU には、クエリされた自動車が使用できる固定ブリッジが正確に含まれ、一時 DSU には、その時点で使用可能な特別なブリッジが正確に追加されます。 結果として得られるコンポーネントのサイズは、その車が到達できる島の数になります。
