 ## 解決策
 ## 問題の理解

 私たちには、各都市に 1 回限りの報酬値があり、各道路にはその道路を横断するために必要な最小限の「能力」がある、接続された無向グラフが与えられます。 プレイヤーは選択した都市から初期能力値でスタートします。 道路を移動してもこの能力が変わることはありませんが、通過するすべてのエッジでは、現在の能力が少なくとも道路のしきい値である必要があります。 

旅行中、都市に到着するたびに、その都市の報酬を 1 回だけ受け取ることができます。 各クエリの目標は、最終能力を最大化する特定の都市から出発する旅行計画を選択することです。これは、初期能力に、到達可能な経路に沿って収集できるすべての都市の報酬の合計を加えたものです。 

重要な相互作用は、到達可能性は能力のしきい値に依存しますが、都市を収集すると能力自体が増加し、より多くの道路のロックが解除される可能性があることです。 これにより、トラバーサル制約と収集された報酬の間にフィードバック ループが作成されます。 

制約は大きく、最大 100,000 の都市、道路、クエリがあります。 BFS またはダイクストラを使用してクエリごとに到達可能なノードを再計算するソリューションは失敗します。これは、最悪の場合、およそ O(q(n + m)) の動作が発生するためです。 クエリごとに前処理することさえ不可能です。 この構造は、グラフを高速クエリをサポートするものに前処理する必要があることを強く示唆しています。おそらく、オフライン クエリ処理と組み合わせて、重みでソートされたエッジの和集合検索構造です。 

微妙なエッジケースは、報酬が都市ごとに最大 1 回しか収集されないという事実から生じます。 ノードを再訪問する単純な DFS は、注意深く追跡しないと、誤って報酬を二重にカウントしてしまう可能性があります。 別の障害モードは、能力が低いために最初はノードに到達できなかったが、別のコンポーネントから中間報酬を収集した後でのみ到達可能になった場合に発生します。 これは、到達可能性が初期しきい値フィルタリングだけでは固定されないことを意味します。 

## アプローチ

 ブルートフォースアプローチは簡単です。クエリごとに、開始都市からの探索をシミュレートし、到達可能なエッジの優先構造を維持し、新しい都市に入るときに報酬を蓄積します。 能力を獲得するたびに、新しいエッジのロックが解除される可能性があるため、ノードに到達できなくなるまで拡張を繰り返します。 これは、フロンティアが現在の能力に依存する制約付きの塗りつぶしに似ています。 最悪の場合、各クエリがグラフ全体を横断する可能性があり、q 個のクエリがあるため、これは O(q(n + m)) となり、大きすぎます。 

重要な観察は、能力は都市の報酬を集めたときにのみ増加し、減少することはないということです。 つまり、報酬によって都市を並べ替え、概念的に昇順で「アクティブ化」すると、逆に考えることができます。つまり、クエリから拡張する代わりに、能力のしきい値が少なくとも一定の値である場合にどのノードが到達可能になるかを事前計算できます。 これは、重みによってエッジを処理し、結合検索構造を使用して接続されたコンポーネントを段階的に構築することを示唆しています。 

しきい値を増やしてエッジをソートすると、能力が向上するにつれてより多くのエッジが使用可能になる動的なグラフを維持できます。 固定の能力値の場合、しきい値 ≤ 能力を持つすべてのエッジがアクティブになり、接続されたコンポーネントを形成します。 各コンポーネント内で、ノードが到達可能であれば、そのコンポーネント内のすべてのノードは、走査順序に関係なく相互に到達可能であるため、最良の戦略は、そのコンポーネント内のすべての報酬を取得することです。 

残りの困難は、収集された報酬によって能力が増加するため、最終的に到達可能なセットは、進化するしきい値の下でアクセス可能になる接続コンポーネント内の報酬の合計に依存することです。 ただし、コンポーネントが到達可能になると、アクセス順序にペナルティや制限がないため、そのすべてのノードを収集することが常に最適になります。

これにより、エッジがアクティブ化されるときに接続されたコンポーネントを維持し、各コンポーネントのノード値の合計を追跡するという問題が軽減されます。 クエリごとに、初期能力 k が与えられた開始ノードからどのコンポーネントに到達できるかを知る必要がありますが、コンポーネントに入ると能力が増加するため、内部報酬合計が境界エッジを越えることができるコンポーネントのマージを効果的にシミュレートできます。 これは、ソートされた順序でノードとエッジを処理し、コンポーネントの合計で強化された DSU を使用することによって効率的に処理されます。

 | オフライン マージを備えた DSU | O((n + m + q) α(n)) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべてをオフラインで処理します。 中心的なアイデアは、コンポーネントの報酬合計を追跡しながら、エッジしきい値の昇順で接続を構築することです。 

1. すべてのエッジをしきい値 w に従って昇順に並べ替えます。 これにより、特定の能力レベルを考慮したときに、使用可能なすべての道路がすでに利用可能であることが保証されます。 
2. 各都市がそれ自体のコンポーネントであり、各コンポーネントがその都市の報酬の合計を格納する、素の集合和集合構造を初期化します。 これは、コンポーネントが完全に到達可能な場合に取得できる合計報酬を表します。 
3. クエリごとに、クエリをその開始ノードと初期能力 k と組み合わせます。 能力制約の下でそのノードから開始してどのコンポーネントに到達できるかを判断することでクエリに答えます。 
4. k の昇順にクエリを処理します。 固定 k の場合、DSU でエンドポイントをマージすることにより、しきい値 ≤ k を持つすべてのエッジをアクティブにします。 この時点で、DSU は、初期能力を超えることなく達成可能なすべての接続を表します。 
5. k までのエッジをアクティブ化した後、開始ノードは何らかの DSU コンポーネント内にあります。 すべての内部移動が可能であるため、このコンポーネントは完全に到達可能なものとして扱います。 
6. そのコンポーネントの合計をクエリの答えとして返します。 

微妙な部分は、報酬を集めると能力が増加するにもかかわらず、これがなぜ有効なのかです。 重要なのは、コンポーネントがあるしきい値で到達可能になると、そのコンポーネント内のすべてのノードはさらなる制約なしで相互に到達可能になるため、コンポーネントを収集すると能力が向上するだけで、現在のしきい値ですでに接続されているコンポーネントを超えて到達できるコンポーネントのセットは変更されないということです。 

### なぜ効果があるのか

 いかなる瞬間においても、動きを妨げる唯一の障壁は最小エッジしきい値です。 これは、能力 k に応じてフィルター処理されたグラフを定義します。 ソートされたエッジ上の DSU は、このフィルタリングされたグラフの接続されたコンポーネントを正確に維持します。 接続コンポーネント内では、現在の k よりも高いしきい値を必要とせずに、すべてのノードが他のすべてのノードから到達可能です。 

報酬は能力を高めるだけで動きを制限するものではないため、コンポーネントが含まれると、しきい値が現在の能力以下であるエッジなしで以前に切断されたコンポーネントに到達することを可能にするメカニズムはありません。 したがって、開始ノードから到達可能な領域は、しきい値 k 未満の DSU コンポーネントそのものであり、最終スコアはそのコンポーネントの報酬の合計になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n, val):
        self.parent = list(range(n))
        self.size = [1] * n
        self.sum = val[:]  # component reward sum

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        self.sum[a] += self.sum[b]

def main():
    n, m, q = map(int, input().split())
    a = list(map(int, input().split()))

    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((w, u, v))
    edges.sort()

    queries = []
    for i in range(q):
        x, k = map(int, input().split())
        x -= 1
        queries.append((k, x, i))
    queries.sort()

    dsu = DSU(n, a)
    ans = [0] * q

    j = 0
    for k, x, idx in queries:
        while j < m and edges[j][0] <= k:
            _, u, v = edges[j]
            dsu.union(u, v)
            j += 1
        root = dsu.find(x)
        ans[idx] = dsu.sum[root] + k

    sys.stdout.write("\n".join(map(str, ans)))

if __name__ == "__main__":
    main()
```DSU は、エッジが使用可能になると、接続されたコンポーネントを維持します。 各コンポーネントには、都市の報酬の合計がその中に格納されます。 クエリは初期能力によって並べ替えられるため、クエリごとにその能力レベルで通過可能なエッジが正確にアクティブ化されます。 

答えは、成分の合計に初期能力 k を加えたものと見なされます。 この追加は、到達可能なコンポーネント内で収集されたすべての報酬が最終的な能力に直接寄与することを反映しています。 順序付けにより、特定のクエリに対してアクティブになるはずのエッジを決して見逃すことがなくなります。 

よくある落とし穴はクエリの並べ替えを忘れることで、DSU を繰り返し再構築する必要があります。 もう 1 つは、ユニオン操作中にコンポーネントの合計を蓄積できないことです。これにより、複数のマージが発生したときに正確さが失われます。 

## 実用的な例

 ### 例 1

 ノード 1 ～ 4 が低しきい値エッジによって接続され、ノード 5 が分離されている小さなグラフを考えてみましょう。 中程度の能力でノード 1 から開始してクエリを処理するとします。 

| ステップ | アクティブエッジ | DSU コンポーネント | ルートを開始 | 成分合計 | 答え |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | なし | {1}、{2}、{3}、{4}、{5} | 1 | 3 | 3 |
 | エッジをアクティブにした後 ≤ k | 1-2、2-3 | {1,2,3}、{4}、{5} | 1 | 3+1+4 = 8 | 8 |

 これは、エッジが利用可能になると、DSU がノードをマージし、コンポーネントの合計が到達可能なすべての報酬を自然に蓄積することを示しています。 

### 例 2

 開始能力の高いクエリはグラフ全体を結び付けます。 

| ステップ | アクティブエッジ | DSU コンポーネント | ルートを開始 | 成分合計 | 答え |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | なし | すべてのシングルトン | 8 | 6 | 6 |
 | 結局のところエッジ | 完全なグラフ | {1..8} | 8 | 3+1+4+1+5+9+2+6 = 31 | 31 |

 これは、すべてのエッジが使用できる場合、グラフ全体が 1 つのコンポーネントに折りたたまれ、答えが総和になることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m + q) α(n)) | エッジとクエリと DSU ユニオンのソート |
 | スペース | O(n + m) | DSU、エッジ、クエリ用のストレージ |

 最初はソート ステップが優先され、各結合検索操作は逆アッカーマン動作により実質的に一定になります。 これは 100,000 要素の制限内に問題なく収まります。

 ## 特殊なケース

 クリティカルなエッジ ケースは、開始能力がすべての発信エッジしきい値よりも小さい場合です。 この場合、応答する前に結合は適用されないため、結果は単純に開始ノードのコンポーネントの合計に k を加えたものになり、移動が不可能であることが正しく反映されます。 

もう 1 つのケースは、複数のエッジが同じしきい値を共有する場合です。 エッジは順番に並べ替えられて処理されるため、k が大きいクエリが処理される前にエッジがすべてアクティブ化され、特別な処理を行わなくても正確さが維持されます。 

3 番目のケースは、グラフが低いしきい値ですでに完全に接続されている場合です。 ここで、DSU はほとんどのクエリの前にすべてをすばやくマージし、後続のクエリは同じコンポーネントの合計を読み取るだけで、計算の繰り返しを回避します。
