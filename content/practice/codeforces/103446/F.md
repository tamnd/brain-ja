 ## 解決策
 ## 問題の理解

 反復によって生成された整数の大きなマルチセットが与えられます。 概念的には、それぞれに値のラベルが付けられた多数のボールが入った箱と考えてください。 値は任意の入力ではなく、決定論的ジェネレーターによって生成されるため、そのシーケンスはゲームが始まる前にカイジに完全に知られています。 

次に、敵対者は制限の下で 2 つのボールを選択します。選択されたペアには、値が厳密にそれらの間にある 3 つ目のボールを含めることはできません。 つまり、すべての値を並べ替えた場合、攻撃者は 2 つの等しい値、または個別の値の並べ替え順序で隣接する 2 つの値のみを選択できます。 この制限により、選択されたすべてのペアは同一の値か、値スペクトル内の「隣接する」ペアのいずれかになります。 

カイジには選ばれたペアが見えません。 代わりに、彼は最初に検査する 2 つのハンドのうちの 1 つを選択し、その選択したボールの価値を学習し、次にもう一方のハンドに隠された価値が小さいか、等しいか、または大きいかを述べなければなりません。 

目標は、双方による最適なプレイの下でカイジが正解する確率を最大化することです。カイジは最高の成功率を保証する戦略を選択しようとしますが、敵対者はそれを最小化するペアを選択します。 

ジェネレーターはテスト ケースごとに最大 1,000 万の値を生成し、全体で合計 1,000 万の値を持つテスト ケースを最大 1,000 個作成できます。 これにより、リニア スキャンを超える重いデータ構造やテストごとのオーバーヘッドを使用する場合、単純な方法ですべてのテストのすべての値を保存または並べ替えるソリューションは直ちに除外されます。 テストごとの O(n) アプローチは、各操作が定数時間である場合にのみ受け入れられます。 

生成された値がすべて同一である場合、微妙なエッジケースが発生します。 この状況では、すべての有効なペアは等しい値で構成されているため、カイジは常に確率 1 で「等しい」と正しく答えることができます。少なくとも 2 つの異なる値を仮定するアプローチは、このケースを誤って確率的な結果に劣化させてしまいます。 

## アプローチ

 ゲームを直接シミュレーションすることは不可能です。 ペアを修正したとしても、カイジの意思決定プロセスには、どの要素を検査するか、その値が他の要素とどのように関連するかについて不確実性が伴います。 O(n²) 個の可能性があるため、すべてのペアを列挙することは不可能です。 

代わりに、許可されるペアの構造が簡素化の鍵となります。 敵対者は、ソートされた個別の値のリスト内で同一の値または隣接する値のペアのみを選択できます。 これは、カイジの観点から見ると、敵によって導入された唯一の不確実性は、隣接する個別の値の間の移行によってもたらされることを意味します。 

配列全体に個別の値が 1 つしかない場合、ゲームは簡単になります。すべてのペアが等しいため、カイジは等しいと述べて常に正しく答えます。 

少なくとも 2 つの異なる値があれば、敵はカイジに決定論的な情報の優位性を与えることを常に回避できます。 カイジが値を観察するたびに、その隠された値は、ソートされた別個の順序で隣接する値に対応する可能性があります。 カイジの観点から見ると、敵対者が等しくないペアを選択するたびに、状況はローカルな価値観の連鎖における方向性の区別に帰着し、可能な限り最高の成功確率が崩壊して 2 つの一貫した可能性の間で推測することになります。 

重要な観察は、少なくとも 2 つの異なる値が存在すると、どの戦略も成功確率を 2 分の 1 以上に押し上げることができないということです。 敵対者は、常に隣接する個別の値のペアを選択することができ、どちらのハンドが公開されるかに応じて、「これが小さく、もう一方が大きい」とその逆の構造の間で曖昧さが強制されます。 カイジは、対称的な不確実性を持つ 2 要素構造の終点を 1 つだけ見た後にコミットを強いられるため、最適な戦略は 2 値の推測に帰着します。 

したがって、問題全体は、生成されたすべての値が等しいかどうかをチェックすることに帰着します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ペアに対するブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適な個別チェック | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての値が同一のままであるかどうかを追跡しながら、反復を使用してシーケンスを生成します。 最初の値を参照ベースラインとして初期化し、後続のすべての値をそれと比較します。 
2. 生成された値がベースラインと異なる場合、配列内に少なくとも 2 つの異なる値が存在することがすぐにわかります。 この時点からさらに世代を続けることができますが、最終的な決定はすでに決定されています。 
3. すべての値を処理した後、2 番目の個別の値が観察されたかどうかに基づいて答えを決定します。 
4. 差異が観察されなかった場合は、有効なペアはすべて等しく、カイジは常に正解するため、1 が出力されます。 
5. それ以外の場合、最適な保証成功確率はちょうど 2 分の 1 であるため、998244353 の下に 2 の逆剰余を出力します。 

スキャンで十分である理由は、攻撃者の制限は値間の順序のみに依存しており、異なる値が複数存在すると構造が完全に崩壊するためです。 

### なぜ効果があるのか

 敵対者の制約により、選択されたすべてのペアがソートされた値の順序で局所的に一貫していることが保証されますが、この局所性は等価性の検出を超えて Kaiji にとって悪用可能な構造を作成しません。 複数の個別値が存在する場合、個別値の有効な隣接ペアが少なくとも 1 つ存在します。 敵対者はいつでもそのようなペアを選択することができ、そのペアについてカイジの観察は対称的な 2 つの結果の推論問題に帰着します。 カイジは片側のみを観察した後にコミットしなければならないため、決定論的な戦略は最悪の場合の 2 分の 1 を超える確率で不平等の方向を区別することはできません。 唯一の例外は、そのような隣接関係が存在しない場合であり、これはまさにすべての値が同一の場合に発生します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
INV2 = 499122177

def solve():
    it = iter(sys.stdin.read().strip().split())
    t = int(next(it))
    out = []

    for _ in range(t):
        n = int(next(it))
        a0 = int(next(it))
        A = int(next(it))
        B = int(next(it))
        C = int(next(it))
        M = int(next(it))

        first = a0
        prev = a0
        all_same = True

        for i in range(2, n + 1):
            prev = (A * prev * prev + B * prev + C) % M + 1
            if prev != first:
                all_same = False

        if all_same:
            out.append("1")
        else:
            out.append(str(INV2))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、繰り返しの以前の値のみが保持され、配列ストレージが回避されます。 n は 1,000 万に達する可能性があるため、これは不可欠です。 私たちが維持する唯一の状態は、生成されたすべての値が最初の値と一致するかどうかです。 

モジュール式の答えは、998244353 の下で事前に計算された 2 の逆数を使用します。これは、複数の個別の値が存在する場合に必要な出力だからです。 

## 実用的な例

 すべての値が同一である場合を考えてみましょう。 ジェネレーターは 5、5、5、5 のようなシーケンスを生成します。スキャンでは不一致が検出されないため、最終状態は all_same = True のままです。 

| ステップ | 現在の値 | 最初の値 | すべて同じ |
 | --- | --- | --- | --- |
 | 1 | 5 | 5 | 本当 |
 | 2 | 5 | 5 | 本当 |
 | 3 | 5 | 5 | 本当 |
 | 4 | 5 | 5 | 本当 |

 出力は 1 で、正確さの確実性を反映します。 

ここで、3、3、7、3 など、少なくとも 2 つの異なる値がある場合を考えてみましょう。7 が現れた瞬間、不変条件は破られます。 

| ステップ | 現在の値 | 最初の値 | すべて同じ |
 | --- | --- | --- | --- |
 | 1 | 3 | 3 | 本当 |
 | 2 | 3 | 3 | 本当 |
 | 3 | 7 | 3 | 偽 |
 | 4 | 3 | 3 | 偽 |

 all_same が False になると、シーケンスの残りの部分は無関係になります。 答えは1/2になります。 

これは、2 番目の個別の値の存在のみが重要であり、その頻度や位置は重要ではないことを示しています。

 ## 特殊なケース

 唯一の構造的に特殊なケースは、生成される値がすべて同一である場合です。 その状況では、アルゴリズムは all_same フラグを反転しないため、1 を出力します。 

生成された値が少なくとも 1 つ異なる入力の場合、フラグは最初の分岐時に正確に False になり、False のままになります。 このアルゴリズムは、発散がどこで発生するかには依存せず、発散が存在することだけに依存します。 

代表的な実行は入力 2 1 0 1 0 2 で、1、2 が生成されます。スキャンでは直ちに不一致が検出され、敵対的保証分析と一致する確率的結果 1/2 に切り替わります。
