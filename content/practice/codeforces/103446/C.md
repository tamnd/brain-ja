 ## 解決策
 ## 問題の理解

 最大 8 × 8 の非常に小さなグリッドが与えられます。各セルは 0 に固定されるか、1 に固定されるか、または柔軟で 2 としてマークされます。すべての 2 は独立して 0 または 1 になる可能性があるため、最終的な行列は、これらすべての置換を決定することによって選択されます。 

行列を修正した後、最終的にゼロになるセルだけを調べます。 これらのゼロ セルからサブセット S を選択する必要があり、S は構造要件を満たさなければなりません。グリッド内のすべてのゼロ セルは、同じ行または同じ列にある S 内の選択された少なくとも 1 つのセルによって「サポート」されなければならず、それらの間の長方形の領域にはゼロのみが含まれていなければなりません。 

具体的には、セル (u, v) を S に選択した場合、行または列を共有していればゼロのセル (i, j) をカバーすることができ、これら 2 つの点によって形成される軸に沿った長方形内のすべてのセルにはゼロのみが含まれます。 このように、S 内のセル自体も含めて、すべてのゼロ セルが少なくとも 1 つの選択されたアンカーによってカバーされる場合、セット S は有効です (セル自体を自明にカバーできます)。 

完成した行列の値は、そのような有効な S の可能な最小サイズです。各 2 が 0 または 1 になる方法を選択できるため、この最小 S サイズを最小化する補完を選択する必要があります。 

制約は非常に厳しく、n と m は最大 8 であるため、グリッドには最大 64 個のセルが含まれます。 これは、解がグリッド全体のセルまたは状態のサブセットに対して指数関数的な推論を可能にすることを直ちに示唆しています。 より小さい次元に余分な指数因子を含む 64 の多項式はまだ許容されますが、構造のない 64 セルすべてに指数関数があるものは避けるか、大幅に枝刈りする必要があります。 

素朴な解釈では、k 2 の 2k 置換をすべて試して、毎回最適に行列を解くことを提案するかもしれません。 これにより、すでに 2 番目の指数関数層が導入されています。 k が適度に大きい場合でも、このアプローチはすぐに実行不可能になります。 

さらに微妙な落とし穴は、最終的な最適化で 0 と 1 が対称であると仮定することです。 そうではありません。 1 つはハード ブロッカーとして機能します。カバレッジに必要な長方形が 1 を通過すると、その候補のカバー関係は破壊されます。 これを無視し、すべての 2 をゼロに安全に設定できると想定する不注意な解決策は、接続性を過大評価し、不正確な応答を生成します。 

もう 1 つの一般的な失敗ケースは、各ゼロ セルが最適なカバー アンカーを独立して選択できると想定していることです。 これは、アンカーが相互作用するため失敗します。S で 1 つのセルを選択すると、同時に多くのセルをカバーできる可能性があり、最適な S はグローバルな選択問題であり、セルごとの貪欲な選択ではありません。 

## アプローチ

 ブルートフォース戦略は、2 つのセルを 0 または 1 に置き換えるすべての可能性を列挙することです。完成した各行列について、ゼロ セルのサブセットを検索し、それらがカバレッジ ルールを満たすかどうかを確認することによって、有効なセット S の最小サイズを計算します。 これは定義に直接従っているので正しいですが、遅すぎます。 k 個のフレキシブル セルがある場合、これにより 2k の行列が導入され、各行列に対して S の別の 2n·m サブセットが導入され、最悪の場合は 2^128 までの爆発につながります。 

重要な単純化は、2 を 1 にすることは、長方形ベースのカバレッジ条件には決して役に立たないという観察から来ています。 1 はゼロのペア間の可視性を壊すだけですが、ゼロは可視性を高めるか維持するだけです。 したがって、S を最小化するには、すべての 2 を 0 として扱うことが常に最適です。これにより、最初の指数層が完全に削除され、問題が固定バイナリ行列に縮小されます。 

この後、問題はゼロ セルの固定セットに関する純粋な組み合わせになります。すべてのゼロ セルが、すべてゼロの四角形の可視性ルールに基づいて、S 内の少なくとも 1 つの選択されたアンカーによって「認識」されるように、最小のサブセット S を選択する必要があります。

これをセットカバー問題として再定式化できます。 各アンカー セル候補は、ルールに基づいてカバーできるすべてのゼロ セルで構成されるカバーのセットを定義します。 すべてのゼロ セルを和集合がカバーするアンカーの最小数を選択したいと考えています。 グリッドには最大 64 個のセルがあるため、ビットマスクを使用してカバレッジを表し、候補に対してサブセット DP を実行できます。

 ## アルゴリズムのチュートリアル

 ### 1.行列を正規化する

 すべての 2 を 0 に変換します。フレキシブル セルをゼロに変換しても、有効なカバレッジ四角形の数が増えるだけであり、既存のゼロ要件を無効にすることはできないため、これは安全です。 S のサイズを最小限に抑えているため、ゼロ領域を拡大することは、答えを変えるか、変更しないで済むだけです。 

### 2. 宇宙を特定する

 正規化後にゼロになるすべてのセルを収集します。 これらはカバーする必要がある要素です。 この集合を U とします。 

### 3. セル間の可視性を事前計算する

 ゼロセルの順序付きペア (s, p) ごとに、s が p をカバーできるかどうかを確認します。 この条件では、それらが同じ行または列にあり、それらの間の軸に揃えられた四角形内のすべてのセルもゼロである必要があります。 

このステップでは、幾何学的ルールを単純なブール関係にエンコードします。 この後、問題のすべての構造は、グリッド自体ではなくグラフのような関係に含まれます。 

### 4. カバレッジマスクを構築する

 各ゼロ セル s に対して、ビットマスク Cover(s) を構築します。s が U の i 番目のゼロ セルをカバーできる場合、i 番目のビットは 1 になります。また、S で s を選択すると常にセル自体の要件を満たすことができるため、すべてのセルがそれ自体をカバーすることも保証します。 

### 5. これらのセットの最小カバーを解決します。 

ここで、S の s にわたる Cover の和集合が U のすべてと等しくなるように、セルのサブセット S を選択する必要があります。これは、最大 64 個の要素と最大 64 セットにわたる古典的な最小セット カバーです。 

対象となる要素のサブセットに対して動的プログラミングを使用します。 各状態はどのセルがすでにカバーされているかを表し、遷移ではアンカー セルを 1 つ追加しようとします。 

### なぜ効果があるのか

 正しさは 2 つの特性に基づいています。 まず、すべての 2 を 0 に置き換えても、潜在的に最適なソリューションは削除されません。2 を 1 として使用するソリューションは、カバレッジを制限するだけで、改善することはできないからです。 第 2 に、行列が固定されると、すべての有効な S は、事前に計算された Cover(s) 関係に基づく U のセット カバーに正確に対応します。 DP は、そのようなカバーを選択するあらゆる可能な方法を検討するため、最適な構成を見逃すことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]

    # treat all '2' as '0'
    for i in range(n):
        for j in range(m):
            if grid[i][j] == '2':
                grid[i][j] = '0'

    cells = []
    idx = [[-1] * m for _ in range(n)]

    for i in range(n):
        for j in range(m):
            if grid[i][j] == '0':
                idx[i][j] = len(cells)
                cells.append((i, j))

    k = len(cells)
    if k == 0:
        print(0)
        return

    # precompute rectangle validity
    def ok_rect(i1, j1, i2, j2):
        if i1 == i2:
            lo, hi = sorted([j1, j2])
            for y in range(lo, hi + 1):
                if grid[i1][y] != '0':
                    return False
            return True
        if j1 == j2:
            lo, hi = sorted([i1, i2])
            for x in range(lo, hi + 1):
                if grid[x][j1] != '0':
                    return False
            return True
        return False

    cover = [0] * k

    for s in range(k):
        x1, y1 = cells[s]
        for p in range(k):
            x2, y2 = cells[p]
            if ok_rect(x1, y1, x2, y2):
                cover[s] |= (1 << p)

    FULL = (1 << k) - 1
    INF = 10 ** 9

    dp = [INF] * (1 << k)
    dp[0] = 0

    for mask in range(1 << k):
        if dp[mask] == INF:
            continue
        for s in range(k):
            new_mask = mask | cover[s]
            if dp[new_mask] > dp[mask] + 1:
                dp[new_mask] = dp[mask] + 1

    print(dp[FULL])

if __name__ == "__main__":
    solve()
```このソリューションでは、最初にすべてのフレキシブル セルをゼロに折りたたんでから、すべてのゼロ位置のリストを作成します。 2 つのセルが同じ行または列上にあり、その間に完全にゼロのセグメントがあるかどうかに基づいて、ペアごとの到達可能性関係を計算します。 この関係はビットマスクにエンコードされるため、各セルはカバーできる他のセルを正確に認識できます。 

その後、動的プログラミングは各ビットマスクをカバレッジの状態として扱います。 どの状態からでも、新しいアンカーを追加すると、カバーできるすべてのセルがマージされます。 最終的な答えは、マスクを完全にカバーするために必要なアンカーの最小数です。 

微妙な点は、DP は、選択されたアンカーが構造的な意味でばらばらであるか最小限であることを強制しないことです。 S では重複が許可されており、最小化によって冗長性が自然に削除されるため、これは正しいことです。 

## 実用的な例

 ゼロがきれいな行を形成する小さなグリッドを考えてみましょう。 

### 例 1

 入力グリッド:```
0 0 0
1 0 1
0 0 0
```すべてのゼロが有効な候補です。 中央の行のセルは、他のいくつかのセルを水平方向にカバーできます。 

| ステップ | マスク | 選ばれたS | カバーされた |
 | --- | --- | --- | --- |
 | 開始 | 000000000 | {} | {} |
 | 中心を追加 | 000111000 | {(1,1)} | 中段 |
 | コーナーを追加 | 111111111 | {(1,1),(0,0)} | いっぱい |

 これは、切断されたすべての領域をカバーできないため、1 つのアンカーだけでは不十分であることを示しています。 

### 例 2

 入力グリッド:```
0 1 0
0 1 0
0 0 0
```ここでは垂直接続が 1 つによってブロックされているため、カバレッジが断片化されています。 

| ステップ | マスク | 選ばれたS | カバーされた |
 | --- | --- | --- | --- |
 | 開始 | 000000000 | {} | {} |
 | 一番下の行を選択 | 000000111 | {(2,1)} | 一番下の行 |
 | 左の列を選択 | 001001001 | {(2,1),(1,0)} | いっぱい |

 これは、長方形を壊し、複数のアンカーを強制することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(2^k · k^2) | k が最大 64 のビットマスク上の DP、各遷移がカバレッジをマージします。 
| スペース | O(2^k + k^2) | DP 配列とペアごとのカバレッジ事前計算 |

 グリッド サイズは最大 64 セルであるため、k は 64 によって制限されます。指数関数的ではありますが、これは、特に Python ビット演算により実際にはマスク遷移が高速になるため、小さなグリッド ICPC 問題に典型的な厳しい制約の下では許容されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、2 を変換した後にグリッドにゼロが含まれない場合です。 この状況ではカバーする要素がないため、最適な S は空になります。 アルゴリズムは、k が 0 に等しいことを確認し、すぐに 0 を返すことによってこれを直接処理します。 

別のエッジ ケースは、ゼロが存在するが完全に 1 で区切られているため、2 つの異なるゼロの間に四角形が有効ではない場合に発生します。 その場合、すべての 0 はそれ自体をカバーすることしかできないため、S にはすべての 0 セルが強制的に含まれます。 すべてのカバーにはそれ自体しか含まれていないため、DP は自然にこれに到達します。そのため、完全なマスクに到達する唯一の方法は、すべての要素を個別に選択することです。
