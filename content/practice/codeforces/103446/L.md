 ## 解決策
 ## 問題の理解

 すべての頂点の次数がちょうど 3 であるグラフが与えられています。 グラフには自己ループまたは複数のエッジが含まれる場合があるため、エッジが単純であるとは保証されませんが、各頂点には正確に 3 つのエッジが発生します。 

タスクは、すべてのエッジを取得し、それぞれ正確に 3 つのエッジのグループに分割することです。 各グループは 3 つのエッジの長さのウォークを形成する必要があります。これは 4 つの頂点のシーケンスを意味します。$a \to b \to c \to d$エッジが$ab$、$bc$、 そして$cd$元のマルチセットではすべて異なります。 すべてのエッジは、そのようなすべてのウォークにわたって正確に 1 回使用される必要があります。 

同様に、エッジの使用を、エッジ セット全体をカバーする長さ 3 の切り離されたトレイルに向けようとしています。 

制約から、$n \le 500$、$m = \frac{3n}{2}$、すべての頂点の次数は 3 であるため、グラフはマルチセットの意味で立方体になります。 これは直ちに意味します$m \le 750$、だからどれでも$O(n^2)$あるいは$O(nm)$このアプローチは実行可能ですが、エッジ パーティションに対する指数関数的な検索は実行できません。 

繊細さはループとマルチエッジから生まれます。 標準的なグラフ理論では、自己ループは頂点の次数に 2 を寄与するため、ここではループは次数 3 の制約で 2 回の出現としてカウントされます。 これは、単純なグラフが壊れることを前提とした単純な隣接推論を意味します。 

素朴な間違いは、貪欲に任意にパスを拡張できると想定することです。 たとえば、頂点から開始して出力エッジを繰り返し選択すると、たとえ有効なグローバル パーティションが存在していても、すべてのエッジを消費する前にスタックしてしまう可能性があります。 この構造はグローバルであり、ローカルに貪欲ではありません。 

## アプローチ

 強引なアイデアは、エッジを 3 つのグループに分割して、各グループが有効な長さ 3 のトレイルを形成しているかどうかを確認することです。 あるので$m/3$グループごとに、エッジを分割する方法の数は多項係数のように増加し、おおよそ階乗になります。$m$、これはたとえ$m = 750$。 

構造上の重要な洞察は、すべての頂点が次数 3 を持つということです。これは、各頂点が長さ 3 のトレイルの 1 つまたは 2 つ内で非常に制御された方法で「使用」されるべきであることを強く示唆しています。 実際、各チェーンは内部ノードで次数 2 を消費し、エンドポイントで次数 1 を消費するため、各頂点は 1 つのチェーン内の内部頂点として、または 1 つのチェーン内のエンドポイントとして機能します。 

この種の制約により、問題は発生率に関するローカルペアリングの問題に変わります。 各頂点には 3 つの入射エッジ端があり、それらを長さ 3 のパスにペアにする方法を決定する必要があります。重要な観察は、各頂点を 3 つの「ポート」を持つ小さなガジェットとして扱うことができ、ポートを一貫して長さ 3 のセグメントに接続しようとしているということです。 

このようなローカル ペアリング制約を強制する標準的な方法は、問題を補助構造でのマッチングに変換するか、未使用のエッジが常に制約された次数を持つ素なコンポーネントを形成するようにしながらチェーンを段階的に構築することです。 次数はどこでも正確に 3 であるため、頂点で 2 つの入射エッジをペアにすることにコミットすると、3 番目のエッジは強制的にパスを延長することになります。 

これにより、バックトラッキングのない建設的な貪欲な構造が得られます。つまり、未使用のエッジを繰り返し取得し、訪問した各頂点で未使用のインシデント エッジをローカルにペアにすることでパスを成長させ、頂点に到達するたびに、パスが長さ 3 のエッジに達するまで、一貫した方法で残りのエッジの 2 つを消費します。 

正確さは、どのステップでも、すべての頂点に 0、1、または 2 つの未使用の入射エッジがあり、将来のパスに完成できない未使用のエッジが 1 つだけある頂点を残すことは決してないという不変条件から得られます。 次数は 3 に固定されており、内部で頂点に入るときは常に 2 つのブロックで消費されるため、有効な分解が存在する場合、プロセスが行き詰ることはありません。

 ## アルゴリズムのチュートリアル

 エッジを処理し、正確に 3 つのエッジのトレイルへの分解を構築します。 

1. 近隣ノードだけでなく、エッジ ID を保存する隣接リストを作成します。 これは、各エッジが 1 回だけ使用されることを確認する必要があり、複数のエッジでは区別する必要があるため重要です。 
2. ブール配列を維持する`used_edge`エッジがすでにチェーンに割り当てられているかどうかを追跡します。 これにより、構築されたすべてのトレイルにわたってグローバルな一貫性が確保されます。 
3. すべてのエッジに対して繰り返します。 未使用のエッジを見つけるたびに、そこから新しいチェーンの構築を開始します。 これにより、すべてのエッジが正確に 1 つのチェーンの一部になることが保証されます。 
4. 任意の未使用エッジでパスを開始します。$u \to v$。 これを使用済みとしてマークし、現在のエンドポイントを次のように設定します。$v$。 この時点で、パスの長さは 1 のエッジになります。 
5. パスを 3 エッジの長さまで貪欲に拡張します。 各ステップで、現在の頂点に到達します。$x$、そして私たちはある縁を通って到着したところです。 ここで、未使用のインシデント エッジを 1 つ選択します。$x$それは私たちが来た端ではありません。 それを使用済みとしてマークし、次の頂点に移動します。 
6. チェーンにちょうど 3 つのエッジが含まれるまで、この延長を繰り返します。 すべての頂点の次数は 3 であるため、既に入力に使用されている 1 つのエッジを持つ頂点に入るときは常に、残りの入射エッジが 2 つだけ存在し、常に続行できることが保証されます。 
7. チェーンの 4 つの頂点を記録し、出力します。 
8. すべてのエッジが使い果たされるまで続けます。 

なぜ拡張機能が常に機能するのかが重要なポイントです。 各内部ステップで、入力によって消費されたインシデント エッジが 1 つだけ存在し、利用可能な 2 つが残る頂点に到達します。 私たちには常に有効な継続の選択肢があります。 エッジは常に即座に消費されるため、エッジを再訪することはありません。また、各頂点の次数が固定されているため、頂点が途中でスタックすることはありません。 

### なぜ効果があるのか

 不変条件は、パスの構築中に頂点に入ると、その入射エッジの 1 つだけが現在のチェーンですでに使用されており、その時点で残っている未使用の入射エッジは、長さ 3 に達するまでチェーンをさらに 1 ステップだけ拡張するのに十分であるということです。すべての頂点は次数 3 から始まり、チェーン構築全体で内部頂点のペアでエッジを常に消費するため、エッジの一意性を侵害せずに部分的に構築されたチェーンを完了できない状態に頂点が陥ることはありません。 これにより、行き止まりが防止され、貪欲な構築によって有効な長さ 3 のトレイルへのエッジの完全な分割が得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m = map(int, input().split())

adj = [[] for _ in range(n)]
edges = []

for i in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    edges.append((u, v))
    adj[u].append((v, i))
    adj[v].append((u, i))

used = [False] * m

def get_next(v, pe):
    for to, eid in adj[v]:
        if not used[eid] and eid != pe:
            return to, eid
    return None

ans = []

for i in range(m):
    if used[i]:
        continue

    u, v = edges[i]
    used[i] = True

    path = [u, v]

    prev_edge = i
    cur = v

    # we need 2 more edges
    for _ in range(2):
        nxt = None
        for to, eid in adj[cur]:
            if not used[eid]:
                nxt = (to, eid)
                break

        if nxt is None:
            break

        to, eid = nxt
        used[eid] = True
        path.append(to)
        cur = to

    if len(path) != 4:
        print("IMPOSSIBLE")
        sys.exit(0)

    ans.append(path)

if any(not x for x in used):
    print("IMPOSSIBLE")
else:
    for a, b, c, d in ans:
        print(a + 1, b + 1, c + 1, d + 1)
```この実装ではエッジが明示的に保存され、使用状況がグローバルに追跡されます。 未使用のエッジから開始するたびに、現在の頂点から未使用の入射エッジを繰り返し選択して、長さ 3 のパスを拡張しようとします。 ここでの単純さは重要な制約を隠しています。次数 3 では、エッジの一貫性を維持しながら継続するのに十分な入射エッジが常に存在することが保証されます。 

実装の微妙な詳細は、隣接リストの順序に決して依存しないことです。 有効な分解が存在することで、この構造を使用した 3 次マルチグラフでの任意の選択が完了をブロックしないことが保証されるため、未使用のエッジがあれば十分です。

 ## 特殊なケース

 1 つ目のエッジ ケースは、自己ループの多用です。 ループは 2 度に 2 回寄与するため、頂点には 1 つのループと 1 つの法線エッジが存在する可能性があり、ループを単一の隣接関係として扱う不注意なトラバーサルは、使用可能な出口を誤ってカウントします。 アルゴリズムは、各エッジを個別の ID として扱い、それを 1 回消費することでこれを回避します。 

もう 1 つのエッジ ケースは、貪欲なトラバーサルがチェーンの途中でスタックしているように見える場合です。 単純な実装では、入力エッジを除いてすでに使用されているエッジのみを持つ頂点に到達すると、失敗が発生します。 有効な入力では、この状況はグローバルに発生することはありません。次数 3 の制約により、チェーンが完了するまで各内部ステップで 2 つの残りのエッジが強制されるためです。そのため、そのような失敗は、真の不可能性ではなく、誤ったエッジ消費ポリシーを示します。 

3 番目のエッジ ケースは、ローカルな選択が干渉する複数の並列コンポーネントです。 エッジは常に長さ 3 のチェーン全体で消費されるため、コンポーネントのバランスが保たれ、解が存在する場合には部分的に残ったエッジは表示されません。
