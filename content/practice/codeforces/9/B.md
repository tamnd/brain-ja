 ## 解決策
 ## 問題の理解

 学生はすでに、X 軸に沿って左から右に移動するバスに乗っています。 バスは定位置に止まります`(xi, 0)`昇順で。 最初の停留所を除くどの停留所でも、学生は下車して、次の場所にある大学まで直接走ることができます。`(xu, yu)`。 

学生がバスの停留所まで乗車した場合`i`、合計移動時間は 2 つの部分に分かれています。 最初の部分は、からのバスに費やした時間です。`x = 0`に`x = xi`。 バスは一定の速度で移動しますので、`vb`、今回は`xi / vb`。 後半部分の走行時間は、`(xi, 0)`に`(xu, yu)`。 この距離はユークリッド距離であるため、実行時間は次のようになります。$$\frac{\sqrt{(xu - xi)^2 + yu^2}}{vs}$$タスクは、合計到着時間を最小化する停止インデックスを見つけることです。 複数の停留所でまったく同じ時間が発生する場合は、物理的に大学に近い停留所を選択する必要があります。 

制約はわずかです。 停留所は最大 100 か所あるため、すべての停留所を直接確認することも簡単です。 解決策としては`O(n)`または`O(n^2)`作業は 1 秒以内であれば完全に安全です。 この問題は最適化のトリックに関するものではなく、比較ロジックを正しく実装し、浮動小数点比較を慎重に処理するためのものです。 

最初の微妙な特殊ケースは、タイブレーク ルールです。 2 つの停留所では合計移動時間がまったく同じになる可能性がありますが、答えは必ずしも早い停留所であるとは限りません。 私たちは大学に近い停留所を選択しなければなりません。 

考慮する：```
3 1 1
0 2 4
3 4
```ストップ 2 の場合:```
bus time = 2
run distance = 5
total = 7
```ストップ 3 の場合:```
bus time = 4
run distance = 1
total = 5
```バスの乗車時間は長くなりますが、走行距離ははるかに短くなりますので、遅い停留所が有利になります。 

もう 1 つの簡単な間違いは、生徒を最初の停留所で下車させてしまうことです。 この声明はこれを明示的に禁止しています。 インデックスから始まる迂闊なループ`0`間違った答えが生まれてしまいます。 

例：```
2 10 1
0 100
0 1
```学生はすぐに降りて距離を走りたいと考えています`1`, しかしそれは違法です。 正解は「やめる」です`2`。 

浮動小数点の等価性も別の危険です。 理論的に等しい 2 つの時間は、精度誤差によりわずかに異なる場合があります。 正確な値を使用する`==`double の比較は予期せず失敗する可能性があります。 最も安全なアプローチは、小さなイプシロンと比較することです。 

## アプローチ

 最も直接的なアプローチは、考えられるすべての停止をシミュレートすることです。 各停留所ごとに`i`、次を計算します。$$\text{time} = \frac{xi}{vb} + \frac{\sqrt{(xu-xi)^2 + yu^2}}{vs}$$次に、所要時間の短い停留所を選択します。 時間が同じ場合は、大学までの距離を比較し、短い方を選択してください。 

この強引なアプローチはすでに完全に受け入れられています。`n ≤ 100`。 総作業量はわずかで、数百の算術演算と平方根のみです。 

ここには隠れた動的プログラミングやジオメトリの最適化はありません。 重要な観察は、生徒が意味のある決定をするのは 1 つだけ、つまり、降りる停留所だけであるということです。 停車地が決まれば、全体のルートと所要時間は一意に決定されます。 これにより、問題は単純な列挙問題に変わります。 

より複雑なアプローチでは、凸性について推論したり、距離を幾何学的に最適化しようとしますが、入力サイズがすでに非常に小さいため、どれも役に立ちません。 最もクリーンで信頼性の高いソリューションは、すべての候補地を直接評価することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 停車駅の数、バスの速度、生徒の走行速度を読み取ります。 
2. 停止座標の配列を読み取る`x`。 
3. 大学の座標を読み取る`(xu, yu)`。 
4. 最適なストップをストップとして初期化します。`2`、学生は最初の停留所で下車することができないためです。 
5. インデックスからの各ストップごと`2`に`n`:

 バスの移動時間を計算します。$$\frac{xi}{vb}$$次に、走行距離を計算します。$$\sqrt{(xu-xi)^2 + yu^2}$$その距離を次の値で割ります`vs`実行時間を取得します。 
6. 両方の時間を加算して、この停車地の合計到着時間を取得します。 
7. この合計時間を現在のベスト時間と比較します。 

新しい時間が厳密に小さい場合は、回答を更新します。 

時間が浮動小数点精度内で等しい場合は、大学までの距離を比較し、近い方の停留所を維持します。 
8. 選択した停止インデックスを出力します。 

### なぜ効果があるのか

 有効な戦略はどれも、生徒がバスを降りる停留所を 1 つだけ選択することに相当します。 停留所が固定されると、合計時間はバスの乗車時間と直線の走行距離によって一意に決まります。 アルゴリズムはすべての合法的な停止を評価し、合計時間が最小の停止を保持するため、最適な答えを見逃すことはありません。 タイブレーク ルールは比較中に明示的に処理されるため、同時刻の場合も正しく解決されます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

n, vb, vs = map(int, input().split())
x = list(map(int, input().split()))
xu, yu = map(int, input().split())

eps = 1e-9

best_idx = 1
best_time = float('inf')
best_dist = float('inf')

for i in range(1, n):
    bus_time = x[i] / vb

    dist = math.sqrt((xu - x[i]) ** 2 + yu ** 2)
    run_time = dist / vs

    total_time = bus_time + run_time

    if total_time < best_time - eps:
        best_time = total_time
        best_dist = dist
        best_idx = i + 1
    elif abs(total_time - best_time) <= eps:
        if dist < best_dist:
            best_dist = dist
            best_idx = i + 1

print(best_idx)
```ループはインデックスから始まります`1`の代わりに`0`最初の停車は禁止されているためです。 これは、この問題で最も一般的な実装ミスです。 

変数`dist`現在の停留所から大学までの幾何学的距離を保存します。 同じ値が実行時間とタイブレークの両方に再利用されるため、実装が単純になります。 

イプシロン比較により、精度の問題が回避されます。 2 つの浮動小数点値が正確に等しいかどうかをチェックするのではなく、その差が極めて小さい場合、コードはそれらが等しいとみなします。 

答えは使用します`i + 1`Codeforces のインデックスは 1 から始まるのに対し、Python リストは 0 から始まるためです。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n, vb, vs = map(int, input().split())
    x = list(map(int, input().split()))
    xu, yu = map(int, input().split())

    eps = 1e-9

    best_idx = 1
    best_time = float('inf')
    best_dist = float('inf')

    for i in range(1, n):
        bus_time = x[i] / vb

        dist = math.sqrt((xu - x[i]) ** 2 + yu ** 2)
        run_time = dist / vs

        total_time = bus_time + run_time

        if total_time < best_time - eps:
            best_time = total_time
            best_dist = dist
            best_idx = i + 1
        elif abs(total_time - best_time) <= eps:
            if dist < best_dist:
                best_dist = dist
                best_idx = i + 1

    return str(best_idx)

# provided sample

0 2 4 6
4 1
"""

## 特殊なケース

 最初の重要なエッジケースは、禁止されている最初の停止です。 

入力：```
2 10 1
0 100
0 1
```最初の停留所での出発が許可される場合、合計時間はわずか`1`。 ただし、学生は少なくとも停車するまではバスに乗らなければなりません`2`。 

アルゴリズムはインデックスからループを開始することでこれを処理します。`1`、停止に相当します`2`1 から始まるインデックス付け。 評価される唯一の候補は stop です`2`したがって、出力は次のようになります。```
2
```もう 1 つの注意が必要な状況は、合計時間が等しい場合です。 

入力：```
3 1 1
0 1 2
1 0
```停止用`2`:```
bus = 1
run = 0
total = 1
```停止用`3`:```
bus = 2
run = 1
total = 3
```停止`2`すぐに勝ちます。 

次に、次のことを考えてみましょう。```
3 1 1
0 1 2
1 1
```浮動小数点演算では、計算された合計が非常に近くなります。 平方根は無理数であるため、直接等価性チェックを使用すると、一貫性のない動作が発生する可能性があります。 代わりにアルゴリズムではイプシロンしきい値が使用されるため、小さな丸め誤差は決定に影響しません。 

最後のエッジケースは、最適な停留所が終点である場合に発生します。 

入力：```
5 100 1
0 10 20 30 40
39 0
```バスは非常に速いのに、学生はゆっくりと走ります。 アルゴリズムは依然としてすべての停留所を個別にチェックするため、最後までバスに留まることで、バスの余分な移動を相殺するのに十分な走行距離が最小限に抑えられることを正確に検出します。
