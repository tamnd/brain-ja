 ## 解決策
 ## 問題の理解

 私たちには固定のシングルエリミネーショントーナメントが与えられています。$2^K$選手たち。 ブラケット構造は完全に事前に決定されています。プレーヤーは順番に配置され、最初のラウンドでは隣接するインデックスのペアになり、次に隣接する試合の勝者が次のラウンドで対戦するというように、チャンピオンが 1 人残るまで続きます。 これは、トーナメントが最初の順序のプレーヤーを葉とする完全な二分木であることを意味します。 

すべての試合で 1 人の勝者が決まりますが、結果は知らされません。 代わりに、括弧の構造と一致するあらゆる可能な結果セットを想像することができます。 試合ごとに、どちらかの参加者を勝者として選択できます。 私たちが計算しなければならないのは、各プレーヤーについて、そのプレーヤーが最終チャンピオンになることを余儀なくされた場合、トーナメントのすべての試合における「番狂わせ」の最小合計数はいくらか、ということです。 

試合は、勝者のパワーが敗者のパワーよりも大幅に低い場合、特に次の場合に番狂わせと呼ばれます。$P_{\text{winner}} < P_{\text{loser}} - X$。 私たちが結果をコントロールするため、特定の勝者を選択することで番狂わせが生じるかどうかに応じて、すべての試合が合計に 0 または 1 を与えます。 

課題は、プレイヤーに勝利を強制すると、ルートに至るまでのすべての試合が制約されるだけでなく、すべての中間試合の結果によって誰が進むか、したがって将来の試合がどうなるかを決定するため、すべてのサブツリーの選択に間接的に影響を与えることです。 

制約$K \le 18$せいぜい意味する$2^K \le 262144$選手たち。 トーナメントには、$2^K - 1$したがって、プレーヤーごとに試合の結果を個別にシミュレートするソリューションは、すぐに遅すぎます。 すべてのプレーヤーと試合に対する二次アプローチでさえ、実行可能な限界を数桁超えてしまいます。 

素朴な解釈では、各プレーヤーに対して、そのプレーヤーを強制的に勝利させながら、トーナメント全体を最適に再計算しようとする可能性があります。 これには、サイズの構造を再解決する必要があります。$O(n)$プレイヤーごとに、$O(n^2)$、それは限界をはるかに超えています。 

貪欲な推論による微妙な失敗例は、弱いプレイヤーが、後の番狂わせのコストを減らす方法で、強い対戦相手が早い段階でお互いを排除できるようにすることでブラケットを「設計」できる場合に現れます。 たとえば、将来の組み合わせを考慮せずに各試合で局所的に最適な勝者を選択すると、後のラウンドの対戦相手のアイデンティティが以前の選択に依存するため、最適ではないグローバル構成につながる可能性があります。 

最大の難点は、各試合が独立していないことです。勝者を選択すると、将来の対戦相手の身元が変わり、将来のコストも変わります。 

## アプローチ

 ブルートフォースのアイデアは単純です。トーナメント ツリーをシミュレートし、各プレイヤーに対して、試合の勝者を再帰的に選択して勝つためのあらゆる方法を試します。 各試合で、私たちは 2 つの可能性に分岐します。 各内部ノードにより可能なトーナメント構成の数が 2 倍になるため、これはすぐに指数関数的になります。$2^{2^K}$全体的に考えられる結果。 どのサブツリーも依然として大きく分岐しているため、固定の勝者に制限しても十分な効果はありません。 

重要な観察は、トーナメントの構造が固定バイナリ ツリーであるため、問題は当然ツリー動的プログラミングの問題であるということです。 完全なトーナメント結果を列挙する代わりに、すべてのサブツリーとすべての可能な「そのサブツリーの勝者」について、その状態を達成するために必要な最小番狂わせコストを計算します。 

各ノード (サブツリー) で、そのサブツリー内のプレーヤーに関する DP テーブルを維持します。値は、そのプレーヤーをサブツリーの勝者にするための最小コストです。 遷移を計算するには、左と右の子を結合します。 プレイヤーの場合$i$左側のサブツリーから来て、次に作成します$i$現在のノードに勝ちます。勝者を選択する必要があります$j$右のサブツリーから。 コストは作るのに最適なコストです$i$勝ち残ったものに最適なコストを加えたもの$j$勝利の権利に加えて、間の最終試合の費用がかかります$i$そして$j$、番狂わせかどうかに応じて 0 または 1 のいずれかになります。 

残る唯一の困難は、最適なものを効率的に見つけることです$j$それぞれに$i$なぜなら、反対側のサブツリー内のすべての候補に対する単純なスキャンは遅すぎるからです。 

これは、各サブツリー内のプレーヤーをパワー別にソートし、プレフィックス範囲にわたる高速な最小クエリを可能にする構造を維持することによって処理されます。 動揺状態は​​次の条件にのみ依存します。$P_j \le P_i + X$、つまり固定の場合$i$、右側のサブツリー内のすべての候補者は、勢力によって 2 つの連続するグループ、つまり動揺を引き起こさないグループと動揺を引き起こすグループに分割されます。 各グループは、DP 値の最小範囲を指定してクエリできます。 

これにより、各マージ ステップが状態ごとの対数クエリに削減され、各レベルがすべてのプレーヤーを 1 回処理するため、全体の複雑さが管理可能になります。

 ## アルゴリズムのチュートリアル

 トーナメントをバイナリ ツリーとして扱い、各ノードがプレイヤーのセグメントに対応します。 

### ステップ

 1. 固定ペアリング構造を使用してトーナメント ツリーをボトムアップで構築します。 

各リーフには 1 人のプレイヤーが含まれます。 内部ノードは 2 つの子セグメント間の一致を表します。 
2. すべてのノードについて、そのサブツリーに属するプレーヤーのリストとその権限を維持します。 このリストは、そのサブツリーのすべての可能な勝者を表します。 
3. 定義する$dp[v][i]$選手に必要な最低限の番狂わせの数として$i$ノードをルートとするサブツリーを獲得するには$v$。 
4. リーフノードの場合、初期化します。$dp[v][i] = 0$単一プレーヤーのサブツリー内では一致が発生しないためです。 
5. 2つの子ノードを結合する場合$L$そして$R$、各側の DP を個別に計算してからマージします。 

プレイヤーにとって$i$左側のサブツリーでは、次のように計算します。$$dp[v][i] = dp[L][i] + \min_{j \in R} (dp[R][j] + cost(i, j))$$どこ$cost(i, j)$の場合は 1$P_i < P_j - X$、それ以外の場合は 0。 

同じ対称計算が次の場合にも適用されます。$i$は右側のサブツリーにあります。 
6. 全体の最小値を計算するには$j$効率的に、適切なサブツリー プレーヤーをパワー別に並べ替えます。 累乗次数による DP 値に対する最小限のクエリをサポートする構造を構築します。 
7. それぞれについて$i$、しきい値を計算します$T = P_i + X$。 候補者を分割する$j$右側のサブツリー内のサブツリーに$P_j \le T$(動揺コストなし)$P_j > T$(コストは 1 を追加します)。 両方の範囲をクエリし、最小値を取得します。 
8. 結果を保存します$dp[v]$サブツリー内のすべてのプレーヤーに対して、ルートが処理されるまで上に進みます。 
9. 各プレイヤーの答えは次のとおりです。$dp[\text{root}][i]$。 

### なぜ効果があるのか

 DP 状態は、最適な結果を決定するために必要な情報を正確に取得します。つまり、サブツリーの勝者の ID によって、将来のすべての対戦が完全に決まります。 有効なグローバル トーナメント構成は、サブツリー勝者の独立した選択肢と各内部ノードでの 1 つの最終試合に分解できます。 各サブツリー DP は最小限のコストですべての勝者を列挙するため、それらを組み合わせることで最適性が維持されます。 範囲をパワーによって分割することで、対戦相手の選択肢をすべて明示的に列挙する必要がなく、試合コストの唯一の依存関係がローカルで処理されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    K, X = map(int, input().split())
    P = list(map(int, input().split()))
    n = len(P)

    # Each node will store:
    # players, dp values aligned with players, and sorted indices by power

    class Node:
        __slots__ = ("ids", "dp", "order")
        def __init__(self, ids):
            self.ids = ids
            self.dp = {i: 0 for i in ids}
            self.order = sorted(ids, key=lambda i: P[i])

    def merge(L, R):
        res_ids = L.ids + R.ids
        res = Node(res_ids)

        # Build sorted lists for R by power for range queries on dp
        r_sorted = sorted(R.ids, key=lambda i: P[i])
        r_ps = [P[i] for i in r_sorted]
        r_dp = [R.dp[i] for i in r_sorted]

        # prefix/suffix minima over dp
        pref = [0] * len(r_sorted)
        suff = [0] * len(r_sorted)

        inf = 10**18
        for i in range(len(r_sorted)):
            pref[i] = r_dp[i] if i == 0 else min(pref[i-1], r_dp[i])
        for i in reversed(range(len(r_sorted))):
            suff[i] = r_dp[i] if i == len(r_sorted)-1 else min(suff[i+1], r_dp[i])

        def query(T):
            # min dp[j] where P[j] <= T
            lo, hi = 0, len(r_sorted)-1
            ans1 = inf
            while lo <= hi:
                mid = (lo + hi) // 2
                if r_ps[mid] <= T:
                    ans1 = pref[mid]
                    lo = mid + 1
                else:
                    hi = mid - 1

            # min dp[j] where P[j] > T
            ans2 = inf
            lo, hi = 0, len(r_sorted)-1
            while lo <= hi:
                mid = (lo + hi) // 2
                if r_ps[mid] > T:
                    ans2 = min(ans2, suff[mid])
                    hi = mid - 1
                else:
                    lo = mid + 1

            return ans1, ans2

        for i in res_ids:
            best = 10**18

            if i in L.ids:
                base = L.dp[i]
                T = P[i] + X
                a0, a1 = query(T)
                best = base + min(a0, a1 + 1)
            else:
                base = R.dp[i]
                T = P[i] + X
                a0, a1 = query(T)
                best = base + min(a0, a1 + 1)

            res.dp[i] = best

        return res

    nodes = [Node([i]) for i in range(n)]

    # build tree
    size = n
    while size > 1:
        nxt = []
        for i in range(0, size, 2):
            nxt.append(merge(nodes[i], nodes[i+1]))
        nodes = nxt
        size //= 2

    root = nodes[0]
    print(" ".join(str(root.dp[i]) for i in range(n)))

if __name__ == "__main__":
    solve()
```このソリューションは、トーナメント ツリー上にボトムアップの DP を構築します。 各マージ ステップでは、ブラケットの 2 つの半分を結合し、結合されたセグメント内のすべての勝者候補について、残りの半分から相手の勝者を選択するための最小コストを計算します。 内部のヘルパー構造`merge`パワー別にソートされた相手の DP 値に対するプレフィックスとサフィックスの最小値を事前計算します。これにより、アップセットしきい値分割の効率的な評価が可能になります。 

実装上の微妙な問題は、選択した対戦相手が相対的にハイパワー領域にある場合にのみ最終マッチのコストが追加されるようにすることです。$P_i + X$。 分割ロジックはこの分離を強制するため、各候補は$i$両方の可能性を正しく評価します。

 ## 特殊なケース

 主なエッジケースは次の場合に発生します。$X = 0$勝者のパワーが低い試合はすべて自動的に番狂わせとなるためです。 この状況では、わずかな力の差でも重要であり、分割条件は力の厳密な比較に崩壊するため、DP は単純化されません。 

すべてのプレイヤーが同じパワー値を持っている場合、別の特殊なケースが発生します。 その場合、満足できる一致はありません$P_{\text{winner}} < P_{\text{loser}} - X$したがって、すべての dp 遷移は、構造に関係なく、コストがゼロになるはずです。 すべての分割の両側で同一のゼロコスト遷移が生成され、最小伝播では全体を通してゼロが維持されるため、DP は依然として正しく動作します。 

構造的に異なるエッジケースは、あるプレイヤーが他のプレイヤーよりも著しく強い場合です。$X$。 その場合、そのプレイヤーをトーナメントで勝たせることで番狂わせはゼロになるはずで、DP はペナルティ条件をトリガーすることなく、すべてのサブツリーで常にそのプレイヤーを勝者として選択することで、それを保証します。
