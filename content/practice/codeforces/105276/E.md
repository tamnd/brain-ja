 ## 問題の理解

 アルゴリズムにはいくつかのカテゴリがあり、各カテゴリには一定数の個別のアルゴリズムが含まれています。 次へ$K$ボブは 1 日に 1 つのカテゴリーを正確に学習し、その日は正確に学習する必要があります。$M$選択したカテゴリからのアルゴリズム。 

1 つのカテゴリを複数の日に再利用できますが、毎日は独立しています: ボブは選択するだけです$M$その日のそのカテゴリからの異なるアルゴリズム。 一部のアルゴリズムを完全に無視することが許可されているため、カテゴリをすべて網羅する必要はありません。 

目標は、可能な限り最大の整数を選択することです$M$それぞれにカテゴリを割り当てることができるように、$K$日、選択した各カテゴリには少なくとも$M$その日に使用可能な未使用のアルゴリズム。

制約により、最大で$10^5$カテゴリとアルゴリズムの合計数は最大$10^5$。 これは、二次関数の動作を伴う解はすべて、$N$または$a_i$不可能です。 平$O(N \log N)$これは問題ありませんが、チェックごとに線形またはほぼ線形より悪いものは、何度も繰り返すと遅すぎます。

 ## アルゴリズムのチュートリアル

 の値が大きくなるという事実を利用します。$M$カテゴリごとの使用可能日数を減らします。 

1. 関数を定義する`can(M)`それぞれの日に次を使用した場合に何日形成できるかを計算します。$M$単一カテゴリのアルゴリズム。 カテゴリごとに$a_i$、追加します$a_i // M$現在の合計に。 これは、サイズの完全なグループの数を数えます。$M$存在する。 
2. すべてのカテゴリにわたるグループの合計数が少なくとも$K$、 それから$M$実現可能です。 そうでなければ、それは実現不可能です。 これは、それぞれの要件に直接一致します。$K$日に 1 つの有効なグループを割り当てる必要があります。 
3. 二分探索を実行します。$M$1 ～ の範囲で$\max(a_i)$。 1 日あたり少なくとも 1 つのアルゴリズムが常に最小限の意味のある選択肢であるため、下限は 1 です。 
4. 中間点の場合$mid$、計算する`can(mid)`。 可能であれば、下限を上に移動してより大きな値を試します。 それ以外の場合は、上限を減らします。 
5. 二分探索が終了すると、下限は実行可能な最大値を指します。$M$。 

### なぜ効果があるのか

 機能`can(M)`単調非増加$M$。 増加中$M$は、各カテゴリ内の完全なグループの数を減らすか維持することしかできず、増やすことはできません。 これにより、実現可能空間が整数上の連続した接頭辞であることが保証されます。$M$したがって、二分探索は実行可能な値と実行不可能な値の間の境界を正しく見つけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(M, arr, K):
    total = 0
    for a in arr:
        total += a // M
        if total >= K:
            return True
    return False

def solve():
    N, K = map(int, input().split())
    arr = list(map(int, input().split()))
    
    lo, hi = 1, max(arr)
    ans = 1
    
    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, arr, K):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```実装の中核となるのは、`can`関数。各カテゴリが特定の時点でサポートできる丸「日数」のカウントに変換されます。$M$。 早期退場時`total >= K`実現可能性が確認されれば、無駄な作業を防ぐことができます。 

二分探索では、以下のすべての値が一致するという不変条件が維持されます。`lo`は実行可能な候補ですが、上記のすべての値は`hi`実行不可能です。 変数`ans`これまでに確認された最良の有効な中間点を追跡します。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

        total = 0
        for a in arr:
            total += a // M
            if total >= K:
                return True
        return False

    def solve():
        N, K = map(int, input().split())
        arr = list(map(int, input().split()))

                lo = mid + 1
            else:

    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

 ## 特殊なケース

 次のような単一カテゴリのケース`N = 1`解が正しく単純な除算に帰着するかどうかをテストします。 入力用`1 3`と`a = [10]`、実現可能性は完全に次のとおりであるかどうかに依存します。`10 // M >= 3`したがって、二分探索は、この制約を満たす最大の約数に正確に収束する必要があります。`M = 3`。 

すべてのカテゴリが等しい場合、たとえば`N = 5`、`K = 5`、 そして`a_i = 2`の場合、アルゴリズムは、各カテゴリが最大 1 日で寄与することを正しく認識します。`M = 2`、ただし、次の場合は 2 日貢献します`M = 1`。 二分探索では、明示的なケース処理を必要とせずに、このステップ変化をキャプチャします。 

次のような大きく偏った入力では、`a = [100, 1, 1, 1]`、ほとんどの容量は単一のカテゴリから得られます。 大型用`M`、小さいカテゴリの寄与はゼロで、大きいカテゴリのみが重要になります。 このアルゴリズムは寄与分を正しく合計し、一様分布を誤って仮定することはありません。
