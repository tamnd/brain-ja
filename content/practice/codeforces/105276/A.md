 ## 解決策
 ## 問題の理解

 私たちは、各セルが壁または自由空間であり、正確に 1 つのセルが開始としてマークされ、もう 1 つが出口としてマークされている格子状迷路に取り組んでいます。 移動ルールは通常の4方向ステップではありません。 代わりに、プレーヤーの状態は、位置と現在向いている方向の両方に依存します。 

特定のセルから、(現在の向いている方向に従って) すぐ前のセルが壁でない場合、プレーヤーは 2 つのアクションのうち 1 つを実行できます。 それらは、そのセル内に前進して方向を変えないままにすることも、前進し、同時に移動後に右に 90 度回転することもできます。 このような各アクションは 1 つの移動としてカウントされます。 タスクは、特定の初期方向で開始セルから開始して出口セルに到達するために必要な最小移動数を計算するか、それが不可能であると判断することです。 

グリッド サイズは 800 x 800 までの大きさにすることができ、これは最大 640,000 個のセルを意味します。 各セルは複数の方向の状態で訪問できるため、有効な状態空間は 4 倍になります。 これは、不用意に状態を再検討したり、パスの指数関数的な探索を試みたりするソリューションは失敗することを直ちに示唆しています。 拡張された状態空間にわたって線形または線形に近い時間で実行されるグラフ走査が唯一の現実的なオプションです。 

微妙な難しさは、動きと方向性の関係から生じます。 異なる方向から同じセルに到達すると、将来の可能性が異なるため、セル上の素朴な最短経路だけでは不十分です。 もう 1 つの落とし穴は、実際には前進の結果としてのみ方向転換が起こるのに、方向転換が動きとは無関係であると仮定することです。 

素朴な考えを打ち破る単純なエッジ ケースは、唯一の有効なパスが繰り返し方向変更を必要とする直線の廊下です。 

入力：```
4 5
#####
#S..#
#..E#
#####
R
```セル上の単純な BFS では、最短パスは純粋に水平距離であると結論付ける可能性がありますが、方向の制約によっては、向きが追跡されていない場合、一部の遷移は不可能になる可能性があります。 

正しい答えは、位置と向きの両方を同時にモデル化できるかどうかによって決まります。 

## アプローチ

 ブルートフォースアプローチでは、初期状態から開始して可能なすべての一連の動きを探索し、段階的にパスを拡張し、出口に到達したかどうかを確認しようとします。 各状態には最大 2 つの選択肢があり、グリッド サイズが大きいため、可能なシーケンスの数はパスの長さに応じて指数関数的に増加します。 同じセルを異なる向きで再訪問すると、明示的に追跡しない限り区別できない冗長なサブツリーが生成されるため、中程度の迷路であっても組み合わせ的に爆発する可能性があります。 

重要な観察は、これが暗黙的な有向グラフ上の最短経路問題であるということです。 各状態は単なるセルではなく、位置と方向のペアで構成されます。 どの状態からでも、遷移の構造は決定的です。つまり、前のセルを見て前に進むか、前に進んで右に回転します。 これにより、問題は均一なエッジの重みを持つグラフ上の標準的な最短経路探索に変わります。 

すべての移動のコストは 1 であるため、状態空間を正しく拡張すれば、幅優先探索で十分になります。 唯一の課題は、壁や境界を尊重しながらトランジションを効率的に構築することです。 

グリッドを最大 4NM の状態に分割し、それぞれが 4 つの方向のいずれかを向いたセル (i, j) 内にあることを表します。 順方向セルが有効な場合、各状態には最大 2 つの発信遷移があります。 BFS は、どの方向でも出口セルに初めて到達したときに、最小移動数が見つかったことを保証します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^k) | O(k) | 遅すぎる |
 | (セル、方向) 状態における最適な BFS | O(NM) | O(NM) | 承認済み |

 ## アルゴリズムのチュートリアル

 各構成を行、列、向きから構成される状態として扱います。 

1. グリッドを解析し、開始セルと終了セルを見つけます。 また、初期方向を読み取り、それを数値形式にマッピングします。 これにより、すべての検索が開始される初期状態が確立されます。 
2. 固定の巡回順序で上、右、下、左の方向ベクトルを定義します。 これにより、前のセルを計算したり、方向インデックスをシフトすることで右折を計算したりすることができます。 
3. 各状態に到達するために必要な最小移動数を表す、大きな値に初期化されたサイズ N x M x 4 の距離配列を作成します。 これにより、不必要に状態を再確認することがなくなり、BFS の正確さが保証されます。 
4. キューを開始状態と距離 0 で初期化します。 BFS は、移動の昇順で状態を拡張し、最適性を保証します。 
5. キューが空でない間に、現在の状態をポップします。 現在の位置が出口セルの場合、BFS は最小性を保証するため、すぐにその距離を返します。 
6. 現在の状態の直前のセルを計算します。 それが壁である場合、この状態からの遷移は不可能であり、続行します。 
7. 前方への移動が有効な場合、次の 2 つの可能な状態を生成します。1 つは前方に移動して方向を変えずに維持する状態、もう 1 つは前方に移動してから右に回転する状態です。 距離を更新し、未確認の状態をキューにプッシュします。 
8. キューがなくなるまで続行します。 出口に到達しない場合は、-1 を返します。 

重要な考え方は、BFS が展開された状態グラフ上で動作し、各ノードが位置と方向の両方によって一意に識別されるということです。 これにより、将来の移行において曖昧さがなくなります。 

### なぜ効果があるのか

このアルゴリズムは、状態がデキューされるたびに、保存される距離がその正確な位置と方向に到達するために必要な最小移動回数であるという不変条件を維持します。 すべての遷移のコストは均一であるため、BFS は距離が小さくならない順に状態を処理します。 すべての有効な一連の動きはこの状態グラフのパスに対応しており、そのようなすべてのパスはコストの増加順に探索されるため、最初に出口セルに到達した時点で、考えられるすべての方向の中から最適な解決策がすでに見つかっています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]
    start_dir = input().strip()

    dirs = ['U', 'R', 'D', 'L']
    di = [-1, 0, 1, 0]
    dj = [0, 1, 0, -1]

    dir_map = {d:i for i, d in enumerate(dirs)}

    sr = sc = er = ec = -1

    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'S':
                sr, sc = i, j
            if grid[i][j] == 'E':
                er, ec = i, j

    start_d = dir_map[start_dir]

    INF = 10**18
    dist = [[[INF]*4 for _ in range(m)] for _ in range(n)]

    dq = deque()
    dist[sr][sc][start_d] = 0
    dq.append((sr, sc, start_d))

    while dq:
        r, c, d = dq.popleft()
        if r == er and c == ec:
            print(dist[r][c][d])
            return

        nr = r + di[d]
        nc = c + dj[d]

        if 0 <= nr < n and 0 <= nc < m and grid[nr][nc] != '#':
            # move forward, keep direction
            if dist[nr][nc][d] > dist[r][c][d] + 1:
                dist[nr][nc][d] = dist[r][c][d] + 1
                dq.append((nr, nc, d))

            # move forward and turn right
            nd = (d + 1) % 4
            if dist[nr][nc][nd] > dist[r][c][d] + 1:
                dist[nr][nc][nd] = dist[r][c][d] + 1
                dq.append((nr, nc, nd))

    print(-1)

if __name__ == "__main__":
    solve()
```この実装では、3D 距離配列を使用して状態空間を明示的にエンコードします。 各 BFS ステップでは、最大 2 つの遷移が展開され、両方とも前方セルから派生します。 右折の方向更新は、方向インデックスのモジュラー演算によって処理されます。 

よくある実装上の落とし穴は、同じセルを 4 つの方向すべてにわたって追跡する必要があることを忘れていることです。 3 番目の次元がないと、アルゴリズムは状態を誤ってマージし、有効なパスを見逃したり、コストを過小評価したりする可能性があります。

 ## 特殊なケース

 重要なケースの 1 つは、特定の方向からのみ出口に到達できる位置にある場合です。 アルゴリズムは、単なる座標ではなく完全な状態に達した場合にのみ終了するため、これを正しく処理します。 

例えば：```
4 5
#####
#S..#
#..E#
#####
R
```E に到達するために、すぐには直観できない方向に向かう必要がある場合でも、BFS はそのセルのすべての方向の状態を調査します。 (E, 方向) が最初にキューから取り出されるとき、その距離は最小であることが保証されるため、他の方向が存在する場合でも、より短いパスを生成することはできません。 

もう 1 つのケースは、前進はいつでも可能ですが、将来のステップの方向を合わせるために何度も方向転換する必要がある廊下です。 方向転換は前進後にのみ可能であるため、BFS は一連の動作を通じて強制的に方向を変更するコストを正確に考慮し、誤って近道が想定されないようにします。
