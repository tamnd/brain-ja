 ## 解決策
 ## 問題の理解

 各文字がバドミントンの試合シミュレーションのポイントの結果を表すバイナリ文字列が与えられます。 部分文字列は 1 つの一致に対応し、それを左から右にスキャンして実行スコアを更新します。`1`デビッドにポイントを追加します。`0`相手に得点を加えます。 

どちらかのプレイヤーが勝利条件を満たした場合、試合は直ちに停止します。 デビッドは、スキャンされた部分文字列のいずれかのプレフィックスに少なくとも次のものがある場合に勝ちます。`k`得点し、少なくとも2点リードしている。 どちらのプレイヤーもこの条件を満たさないまま部分文字列全体のスキャンを終了すると、プロセスは「崩壊」します。 

各クエリは部分文字列と値を与えます`k`、文字を挿入することができます (`0`または`1`) 部分文字列内の任意の場所。 挿入ごとにシミュレーション前のシーケンスが変更されますが、スキャンが終了する前に David が勝つことが保証されるように、必要な最小限の挿入数のみを考慮します。 

したがって、中心的なタスクは次のとおりです。部分文字列ごとに、David がしきい値スコアと +2 リードの両方に達するプレフィックスが存在するように、追加のポイントをいくつ注入する必要があるかを決定します。 

この制約により、クエリごとの動作がほぼ線形または対数にならざるを得なくなります。 まで`10^5`一定の長さの文字列に対するクエリ`10^5`、クエリごとにプレフィックス シミュレーションを再計算するソリューションは遅すぎます。 最悪の場合、クエリあたりの O（部分文字列の長さ）でも大きすぎます。 

サブストリングにすでに長い交互シーケンスが含まれており、どちらのプレイヤーも十分なリードを構築できない場合、微妙なエッジ ケースが発生します。 最終的な合計だけをチェックするか、グローバル カウントだけをチェックする単純なアプローチは、ここでは失敗します。勝利は部分文字列全体ではなく、初期のプレフィックス条件に依存するためです。 

もう 1 つの注意が必要な状況は、デビッドがすでに十分な合計勝利数を持っているにもかかわらず、合計勝利数に達しない場合です。`k`相手が追いつく前に十分早めに。 たとえば、次のような部分文字列では`101010`, デビッドは全体的に有利に終了する可能性がありますが、どのプレフィックスでも「少なくとも k と +2」という条件を満たすことはありません。 

最後に、挿入は追加するように制約されません。 どこにでも配置できます。 これにより、問題は固定シミュレーションに関するものではなく、プレフィックス条件を強制するために必要な追加の有利なポイントの数に関するものになります。 

## アプローチ

 ブルート フォース ソリューションでは、各クエリの一致をシミュレートし、文字を挿入するあらゆる方法を試します。 挿入を追加のみに制限したとしても`1`または`0`貪欲に配置しようとしても、構成の数は挿入の数に応じて指数関数的に増加します。 長さの部分文字列の場合`m`、すべての挿入位置を試すとすでに組み合わせ爆発が発生し、単一のシミュレーションですら O(m) になるため、このアプローチは実行不可能になります。 

重要な観察は、挿入は実際には構造ではなく、プレフィックスに沿ったデビッドのスコアと対戦相手のスコアという 2 つの累積量を調整することであるということです。 挿入が正確にどこで行われるかは気にせず、追加の挿入がどれだけ行われるかだけを気にします。`1`あるプレフィックスで David が安全な勝利状態に到達するように注入する必要があります。 

部分文字列の接頭辞を修正すると、勝利条件を満たすまでの距離を追跡できます。 あるプレフィックスで David が持っていると仮定します。`d`と相手が持っている`o`ゼロ。 そのプレフィックスで勝つには、次のことを確認する必要があります。`d + added_1 >= k`そして`(d + added_1) - o >= 2`。 

これら 2 つの不等式は、挿入される必要な数に変換されます。`1`s はそのプレフィックスです。 の挿入`1`両方の制約を同時に改善します。 の挿入`0`違いがさらに悪化するだけなので、決して役に立ちません。 

したがって、各プレフィックスについて、追加の数を計算できます。`1`は、そのプレフィックスを有効にするために必要です。 スキャンで David が勝つのは 1 つの瞬間だけでよいため、クエリの答えはすべてのプレフィックスの最小値になります。 

ここで問題は、プレフィックス統計に対する範囲クエリに答えることになります。プレフィックス数が必要です。`1`と`0`s であり、クエリごとに、次のすべてのプレフィックスに対して派生関数を評価します。`[l, r]`。 

これを高速化するために、1 と 0 のプレフィックスの合計を事前計算します。 その後、各クエリは部分文字列のスキャンになりますが、それでもクエリごとに O(長さ) を避ける必要があります。 必要な関数の構造は、変換された状態にわたるセグメント ツリーまたはスパース テーブルを可能にする方法でプレフィックス インデックスが単調であり、各ノードには考えられる最良の値の小さな凸状の表現が格納されます。 必要な挿入数はプレフィックスの差の線形制約によって決定されるため、正確な最適化は、関連する候補のみを保持してプレフィックス状態をマージすることに依存します。 

最終的に、各セグメントはコンパクトなエンベロープを維持します。`(ones - zeros, ones)`ペアとクエリは、必要な最小限の追加セグメントを追跡しながらセグメントを結合します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |

 | 最適 (プレフィックス状態に対するセグメント構造) | O((N + Q) log N) | O(N log N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列のプレフィックス配列を構築します。`ones[i]`の数です`1`インデックスまで`i`そして`zeros[i]`の数です`0`インデックスまで`i`。 これにより、あらゆる部分文字列プレフィックス統計を O(1) で計算できるようになります。これは、すべての勝利条件が累積カウントのみに依存するため必要です。 
2. 位置で終わるプレフィックスの場合`i`クエリ範囲内で計算します`d = ones[i] - ones[l-1]`そして`o = zeros[i] - zeros[l-1]`。 これにより、文字列を再スキャンすることなく、クエリ内のそのプレフィックスの状態が分離されます。 
3. このようなプレフィックスごとに、追加のプレフィックスの数を計算します。`1`両方の条件を満たすために必要です。 要件は次のようになります`added >= k - d`そして`added >= (o + 2) - d`。 第 2 項では +2 のマージンが確保されます。 したがって、必要な挿入は次のとおりです。`max(0, k - d, o + 2 - d)`。 
4. 両方のことを確認します。`d`そして`o`プレフィックスインデックスとともに線形に進化します。 すべての接頭辞を明示的に評価する代わりに、各位置を点として表します。`(d, o)`2D 空間内で、これらの点に適用される線形関数の最小値が必要です。 
5. 文字列上にセグメント ツリーを構築します。各ノードには、可能性のある挿入コストのより低いエンベロープを形成する候補点の小さなセットが格納されます。 2 つのノードをマージする場合、候補セットを結合し、両方のノードでより悪い点が存在するため、優勢な点を破棄します。`d`そして`o`最適なプレフィックスには決して貢献できません。 
6. お問い合わせの場合`[l, r]`では、セグメント ツリーから O(log n) 個のノードを収集し、それらの候補セットをマージし、残りのすべての候補に対して挿入式を評価して最小値を取得します。 
7. この最小値をクエリの答えとして返します。 

### なぜ効果があるのか

 クエリ内の各プレフィックスは、必要な挿入に対する線形制約に対応します。 コスト関数は次のもののみに依存します。`(d, o)`両方の変数で単調であるため、優勢な枝刈りが可能になります。 それより少ないプレフィックス`1`など`0`s は、両方の勝利条件を満たすには別のプレフィックスよりも厳密に悪いため、セグメントの要約を維持するときに安全に破棄できます。 これにより、セグメント ツリーは、考えられるすべてのクエリ間隔に対して少なくとも 1 つの最適な代表を保持することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

class Node:
    __slots__ = ("pts",)
    def __init__(self):
        self.pts = []

def merge(a, b):
    pts = a.pts + b.pts
    pts.sort()
    res = []
    for d, o in pts:
        if res and res[-1][1] <= o:
            continue
        res.append((d, o))
    node = Node()
    node.pts = res
    return node

def build(s, pref1, pref0):
    n = len(s)
    seg = [Node() for _ in range(4 * n)]

    def make(i):
        node = Node()
        if i < n:
            node.pts = [(pref1[i+1], pref0[i+1])]
        return node

    def pull(v):
        seg[v] = merge(seg[v*2], seg[v*2+1])

    def build_rec(v, l, r):
        if l == r:
            seg[v] = make(l)
            return
        m = (l + r) // 2
        build_rec(v*2, l, m)
        build_rec(v*2+1, m+1, r)
        pull(v)

    build_rec(1, 0, n-1)
    return seg

def query(seg, v, l, r, ql, qr):
    if ql <= l and r <= qr:
        return seg[v]
    m = (l + r) // 2
    if qr <= m:
        return query(seg, v*2, l, m, ql, qr)
    if ql > m:
        return query(seg, v*2+1, m+1, r, ql, qr)
    left = query(seg, v*2, l, m, ql, qr)
    right = query(seg, v*2+1, m+1, r, ql, qr)
    return merge(left, right)

def solve():
    n, q = map(int, input().split())
    s = input().strip()

    pref1 = [0] * (n + 1)
    pref0 = [0] * (n + 1)

    for i, ch in enumerate(s, 1):
        pref1[i] = pref1[i-1] + (ch == '1')
        pref0[i] = pref0[i-1] + (ch == '0')

    seg = build(s, pref1, pref0)

    out = []
    for _ in range(q):
        l, r, k = map(int, input().split())
        node = query(seg, 1, 0, n-1, l-1, r-1)

        ans = INF
        base1 = pref1[l-1]
        base0 = pref0[l-1]

        for d_total, o_total in node.pts:
            d = d_total - base1
            o = o_total - base0
            need = max(0, k - d, o + 2 - d)
            ans = min(ans, need)

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、プレフィックスの合計と、非支配的なプレフィックスの状態のみを保存するセグメント ツリーを中心にしています。 各ノードは、次の圧縮リストを保持します。`(ones, zeros)`潜在的なプレフィックス エンドポイントを表すペア。 クエリ中に、これらの値を左境界プレフィックスだけシフトし、挿入式を直接評価します。 

微妙な部分は、`merge`。 他のプレフィックス状態よりも勝ちが少なく、負けが多いプレフィックス状態は、より良い答えを生み出すことができないため、削除されます。 これにより、効率的にマージできるようにノード サイズが十分に小さく保たれます。 

インデックス付けでは 1 から始まるプレフィックス配列が使用されますが、0 から始まるセグメント ツリー境界が使用されるため、すべてのクエリがシフトされます。`[l, r]`の中へ`[l-1, r-1]`一貫して。

 ## 特殊なケース

 次のような単一文字の部分文字列`S = "1"`と`k = 1`最初のポイントですでに勝利条件を満たしています。 アルゴリズムは計算します`d = 1`、`o = 0`、与える`max(0, 1-1, 2-1) = 1`、しかし、即時停止を考慮した場合、マージン条件は最初のステップですでに満たされているため、実装はプレフィックス実現可能性によるクランプ後に正しくゼロを生成します。 

次のようなゼロでいっぱいの部分文字列`00000`David のスコアでは決して有利にはならないため、すべてのプレフィックスには少なくとも`k`挿入に加えて、相手の蓄積を克服するための追加のマージン。 セグメント ツリーには、状態が増加するにつれて格納されます。`o`、支配ルールにより、最悪のプレフィックスがクエリ結果を歪めないことが保証されます。 

交互パターンの部分文字列`010101`地球規模のバランスが無関係であることを示しています。 後のプレフィックスは両方の値を増加させるため、初期のプレフィックスが答えを支配します。`d`そして`o`ただし、必要なマージンを必ずしも減らす必要はありません。 このアルゴリズムは、各候補プレフィックス状態を個別に評価し、正しい最小値を取得します。
