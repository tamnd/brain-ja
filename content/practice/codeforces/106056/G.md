 ## 解決策
 ## 問題の理解

 頂点に左から右に番号が付けられた完全なグラフができました。 通常、2 つの頂点間のエッジには、この線上の距離に等しいコストがかかります。 ただし、少数のペアは特別です。これらのペアには、通常の距離ではなく、独自の指定されたエッジ コストがあります。 タスクは、最小スパニング ツリーの合計の重みを見つけることです。 

困難は制約から生じます。 頂点の数は次のように大きくできます。$10^9$したがって、頂点を反復したりグラフを構築したりする解決策は不可能です。 同時に、変更されるエッジの数はわずかです。$10^5$すべてのテストの合計で、解はグラフのサイズではなく特別なエッジに依存する必要があることがわかります。 どれでも$O(n)$、$O(n \log n)$、 または$O(n^2)$以下の場合にはこの方法は除外されます$n$大きいです。 

よくある間違いは、連続する頂点間の通常のパスが常に MST であると仮定することです。 一部の連続したエッジは高価な特殊なエッジに置き換えられる可能性があるため、これは失敗します。 たとえば、入力の場合```
5 4
1 2 1000000000
1 3 1000000000
1 4 1000000000
1 5 1000000000
```通常のパスコストは次のようになります。$4$、しかし、頂点 1 を離れるすべてのエッジは高価です。 最適な答えは`1000000003`なぜなら、ツリーは頂点 1 を接続するために 1 つの高価なエッジを支払う必要があり、残りの頂点は通常のエッジで接続できるからです。 

もう 1 つのエッジ ケースは、特別なエッジがない場合です。```
5 0
```答えは`4`、 ない`0`表示されている頂点のみを接続するコストはかかりません。 ソリューションでは、たとえ明示的に格納されなかったとしても、すべての隠れた通常の頂点を考慮する必要があります。 

3 番目のトリッキーなケースは、安価な特別なロングエッジです。```
5 1
1 5 0
```答えは`3`。 特別なエッジは 2 つの端を接続しますが、中央の 3 つの頂点を接続する必要があります。 セグメント全体をコストに置き換えるだけのソリューション`0`それは不正確でしょう。 

## アプローチ

 ブルートフォースアプローチは、グラフ全体に対してクラスカルのアルゴリズムを実行することです。 グラフには、$n(n-1)/2$エッジがあるため、エッジを保管することさえ不可能です。 いつ$n$アプローチ$10^9$、このアイデアはすぐに失敗します。 

重要な観察は、特別なエッジに表示される頂点のみが通常のラインとは異なる動作をする可能性があるということです。 これらの頂点を重要な頂点と呼びましょう。 多くてもあります$2m$それらのうち、$O(m)$関連するポジション。 

重要でない頂点をすべて削除することを想像してください。 それらは重要な頂点間の連続したセグメントにあります。 このようなセグメントはすべてプレーンなチェーンです。 セグメントの内部頂点の接続には常に同量のコストが必要であり、それらを保存せずに考慮することができます。 

2 つの連続する重要な頂点が$a$そして$b$。 もし$b-a>1$、それらの間には内部頂点があります。 それらの内部頂点が貢献します$b-a-1$避けられないユニットエッジ。 それを支払った後、頂点が実際に隣接していない限り、2 つの重要な頂点間の残りの接続は常に 1 つの単位エッジで作成できます。 もし$a$そして$b$が隣接している場合、役立つ隠れ頂点がないため、実際のエッジ コストを使用する必要があります。 

これにより、圧縮されたグラフを構築できるようになります。 その頂点は重要な頂点のみです。 答えは、削除された通常の頂点の数に、この圧縮されたグラフの MST コストを加えたものです。 すべての特別なエッジと、連続する重要な頂点の間に必要なチェーン エッジを追加します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n²) | 遅すぎる |
 | 圧縮されたクラスカル | O(m log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 特別なエッジに表示されるすべての頂点を収集します。 頂点も含める`1`そして`n`、それはラインの境界だからです。 これらの重要な頂点を並べ替えて、重複を削除します。 これらの頂点の数は、特別なエッジの数によって制限されているため、少なくなります。 
2. 重要ではない頂点の数を数えます。 それらは圧縮されたグラフに表示される必要はありませんが、それでも最終的なツリーにエッジを提供します。 彼らの貢献は、`n - important_count`。 
3. 圧縮グラフ内に特別なエッジごとにエッジを作成します。 これらのエッジは、まさに MST を改善または悪化させる可能性がある異常な選択であるため、元の重みを維持します。 
4. 連続する重要な頂点のすべてのペアをソートされた順序で接続します。 元のグラフでそれらが隣接している場合、そのようなエッジが存在する場合は特別な重みを使用し、そうでない場合は重みを使用します。`1`。 それらの間に少なくとも 1 つの法線頂点がある場合は、ウェイトを使用します`1`残りの接続はいつでもチェーンを通じて行うことができるためです。 
5. 圧縮されたグラフに対して Kruskal のアルゴリズムを実行します。 結果として得られる MST コストを重要でない頂点の寄与に加算します。 

これが機能する理由: 重要でない頂点はすべて、特別なエッジが接触していない単純な線分に属します。 このような頂点は、新しい便利なショートカットを作成できないため、その唯一の役割は、固定数の単位コスト接続を追加することです。 MST に影響を与える可能性のあるすべての選択は重要な頂点間で発生し、圧縮されたグラフではそのようなすべての選択が保存されます。 Kruskal は圧縮グラフの最小スパニング ツリーを見つけるため、固定セグメント コストを加算し直すと元の MST が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, m, data):
    specials = {}
    important = {1, n}

    for u, v, w in data:
        specials[(u, v)] = w
        important.add(u)
        important.add(v)

    pts = sorted(important)
    idx = {x: i for i, x in enumerate(pts)}
    k = len(pts)

    edges = []

    for (u, v), w in specials.items():
        edges.append((w, idx[u], idx[v]))

    for i in range(k - 1):
        a = pts[i]
        b = pts[i + 1]
        if b - a == 1:
            w = specials.get((a, b), 1)
        else:
            w = 1
        edges.append((w, i, i + 1))

    edges.sort()

    parent = list(range(k))
    size = [1] * k

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a = find(a)
        b = find(b)
        if a == b:
            return False
        if size[a] < size[b]:
            a, b = b, a
        parent[b] = a
        size[a] += size[b]
        return True

    ans = n - k
    used = 0

    for w, a, b in edges:
        if union(a, b):
            ans += w
            used += 1
            if used == k - 1:
                break

    return ans

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        data = []
        for _ in range(m):
            u, v, w = map(int, input().split())
            data.append((u, v, w))
        out.append(str(solve_case(n, m, data)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```辞書`specials`は、重要な頂点の連続するペアが変更されたエッジであるかどうかをすばやく確認するために使用されます。 これにより、圧縮グラフの構築中にすべての特別なエッジをスキャンすることが回避されます。 

配列`pts`圧縮された頂点のみが含まれます。 DSU は、元の頂点番号ではなく、これらのインデックスに基づいて動作します。これは、元のグラフには最大で頂点番号が含まれる可能性があるため、必要です。$10^9$頂点。 

値`ans = n - k`圧縮中に削除された通常の頂点を考慮します。 それぞれに 1 つの単位コスト接続が必要です。 残りのコストは、圧縮されたグラフの MST から得られます。 

微妙なディテールがコンディションです`b - a == 1`。 この場合のみ、元のグラフで 2 つの重要な頂点が実際に隣接しているため、特別なエッジが通常のユニット エッジをブロックできます。 それ以外の場合は、非表示の頂点によりユニット接続を維持できます。

# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().split()
    sys.stdin = old

    it = iter(data)
    t = int(next(it))
    ans = []

    for _ in range(t):
        n = int(next(it))
        m = int(next(it))
        edges = []
        for _ in range(m):
            edges.append((int(next(it)), int(next(it)), int(next(it))))
        ans.append(str(solve_case(n, m, edges)))

    return "\n".join(ans)

 ## 特殊なケース

 特殊なエッジがライン全体を覆う場合:```
5 1
1 5 0
```圧縮されたグラフには頂点のみが含まれます`1`そして`5`。 重要ではない 3 つの頂点が寄与する`3`。 圧縮されたエッジには重みがあります`0`したがって、最終的な答えは次のとおりです。`3`。 このアルゴリズムは、ショートカットを完全な解決策として誤って扱うのではなく、隠れたチェーンコストを保持します。 

高価な隣接する特殊エッジの場合:```
5 4
1 2 1000000000
1 3 1000000000
1 4 1000000000
1 5 1000000000
```隠れた頂点はないので、答えは完全に圧縮されたグラフから得られます。 Kruskal は、頂点 1 の接続に必要なエッジを除いて、高価なエッジをすべて回避します。 

空のケースの場合:```
5 0
```アルゴリズムはエンドポイントのみを作成します。 圧縮されたエッジのコスト`1`、削除された中間頂点が追加されます。`3`、正しい MST コストが得られます`4`。
