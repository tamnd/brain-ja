 ## 解決策
 ## 問題の理解

 グリッドは、R by C マップとしてレイアウトされた小さな近隣地域を表します。 各セルは封鎖されているか、自由に歩ける場所、住宅候補地、学校、公園のいずれかになっています。 移動は直交して隣接する歩行可能セル間でのみ許可され、移動にはちょうど 1 ステップかかります。 

同社は、制約の下でどの住宅が実際に販売できるかを知りたいと考えています。購入者は、その住宅から学校と公園の両方がグリッド ステップで測定された最大距離 D 以内に到達できる場合にのみ住宅を受け入れます。 住宅は、ブロックされたセルによって通路が制限されている、D ステップ内に少なくとも 1 つの学校と、D ステップ内に少なくとも 1 つの公園が存在する場合にのみ有効です。 

タスクは、これらの到達可能性条件の両方を満たすハウス セルの数を数えることです。 

グリッド サイズは最大 30 x 30 なので、セルの数は最大 900 個になります。 距離制限が 1000 までであっても、状態空間は小さいため、複数のソースからの最短パスの計算が実行可能であることが強く示唆されます。 

素朴な考えとしては、BFS を各家から独立して運営し、学校と公園を探すことです。 これは、900 セル グリッド上で最大 900 の BFS を実行することを意味し、それぞれのコストは O(RC) であり、すでに限界に達していますが、まだ妥当です。 ただし、各 BFS も 2 つのターゲットを個別に検索したり、高価な作業を繰り返し再開したりすると、不要な重複が発生します。 

素朴なローカル検索の微妙な失敗例は、学校や公園を見つけた後、早期に BFS を停止しようとしたときに発生します。 たとえば、家は近くの学校をすぐに見つけるかもしれませんが、最も近い公園は完全な探索を必要とするグリッドのまったく異なる領域にある可能性があります。 部分的な検出に基づいて早期に停止すると、両方のターゲット タイプについて個別に処理しないと、誤った枝刈りが行われる危険があります。 

メモ化せずに DFS を使用して各住宅の距離を個別に計算すると、別の間違いが発生します。 コリドーのあるグリッドでは、同じ最短パスが何度も再計算され、実際には冗長な指数関数的な探索パターンが発生します。 

## アプローチ

 ブルート フォースの方向では、各家がクエリ ポイントとして扱われます。 すべての家から、学校と公園に到達するか、到達可能なセルをすべて使い果たすまで、グリッド上で最短経路検索を実行します。 各 BFS は O(RC) であるため、合計の複雑さは O(HRC) になります。ここで、H はハウスの数です。 最悪の場合、H は RC に近く、おおよそ O((RC)^2) になります。 RC が最大 900 の場合、これは約 810,000 セル訪問に近づく可能性があります。これはまだ境界線ですが、繰り返しのスキャン オーバーヘッドと BFS ごとの 2 つの別々のターゲット検索が含まれます。 慎重に実装すれば合格する可能性がありますが、すべての BFS が最初から同じ探索を繰り返すため、概念的に無駄です。 

重要な観察は、すべての住宅が同じ環境を共有しており、コスト指標が均一であるということです。 これは、視点を逆転することを示唆しています。各家から学校や公園までの距離を計算する代わりに、すべての学校からすべてのセルまでの距離、およびすべての公園からすべてのセルまでの距離を個別に計算します。 これは古典的なマルチソース BFS のアイデアです。 これら 2 つの距離フィールドがわかったら、両方の距離が D 以内であるかどうかをチェックすることで、O(1) で各家を評価できます。 

この変換は、重み付けされていないグリッド内の最短パス距離が開始クエリ セットに依存しないため機能します。 すべてのソースからの BFS は、そのタイプの最も近いソースまでの正しい最小距離を同時に生成します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各家からのブルート フォース BFS | O((RC)^2) | O(RC) | 許容できるが不要 |
 | 学校や公園からのマルチソース BFS | O(RC) | O(RC) | 承認済み |

 ## アルゴリズムのチュートリアル

 2 つの独立した距離マップを計算します。1 つは学校用、もう 1 つは公園用です。

1. すべてのスクール セルを収集し、それらすべてから同時に BFS を実行します。 それらの距離をゼロとして初期化し、それらをキューにプッシュします。 セルを拡張するたびに、より短い距離が見つかった場合は、その 4 つの隣接セルを緩和します。 これにより、各セルから最も近い学校までの最小距離が求められます。 
2. 公園についても同じプロセスを繰り返し、各セルから最も近い公園までの最小距離を格納する 2 番目の距離グリッドを作成します。 
3. グリッド内のすべてのセルを繰り返します。 ハウスセルに遭遇するたびに、両方の距離グリッドでその値をチェックします。 両方の距離が D 以下の場合、この家は有効であるとみなします。 
4. 有効な住宅の総数を出力します。 

BFS 拡張は正しく機能します。これは、キューの各層がソース セットからの距離の増加に対応し、可能な限り最小の距離でセルにアクセスすると、その後のそのセルへのパスは均一なエッジの重みによって長くなるだけであるためです。 

### なぜ効果があるのか

 このアルゴリズムは、セルが BFS キューからポップされたとき、その記録された距離がそのタイプのソース (学校または公園) からの可能な最短距離に等しいという不変条件を維持します。 すべてのエッジのコストが等しいため、BFS は距離の増加順に探索します。また、すべてのソースが距離 0 から開始し、同時に外側に伝播するため、マルチソースの初期化によって正確さが変化することはありません。 その結果、計算された距離グリッドは、それぞれ最も近い学校と最も近い公園までの真の最短経路距離を正確に表します。 

住宅は両方の最短経路制約が満たされる場合にのみ有効であり、正しい距離関数を使用して両方の制約が独立してチェックされるため、相互作用の影響によって結果が無効になることはありません。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def bfs(starts, grid, R, C):
    INF = 10**9
    dist = [[INF] * C for _ in range(R)]
    q = deque()

    for r, c in starts:
        dist[r][c] = 0
        q.append((r, c))

    dr = [1, -1, 0, 0]
    dc = [0, 0, 1, -1]

    while q:
        r, c = q.popleft()
        for k in range(4):
            nr, nc = r + dr[k], c + dc[k]
            if 0 <= nr < R and 0 <= nc < C:
                if grid[nr][nc] != '#':
                    if dist[nr][nc] > dist[r][c] + 1:
                        dist[nr][nc] = dist[r][c] + 1
                        q.append((nr, nc))

    return dist

R, C, D = map(int, input().split())
grid = [list(input().strip()) for _ in range(R)]

schools = []
parks = []
houses = []

for i in range(R):
    for j in range(C):
        if grid[i][j] == 'S':
            schools.append((i, j))
        elif grid[i][j] == 'P':
            parks.append((i, j))
        elif grid[i][j] == 'H':
            houses.append((i, j))

distS = bfs(schools, grid, R, C)
distP = bfs(parks, grid, R, C)

ans = 0
for r, c in houses:
    if distS[r][c] <= D and distP[r][c] <= D:
        ans += 1

print(ans)
```BFS 関数は、学校と公園の両方を対象として汎用的に作成されています。 主要な実装の詳細は、キューを開始する前に距離ゼロですべてのソースを初期化することであり、これによりキューがマルチソース BFS に変わります。 グリッドチェック`grid[nr][nc] != '#'`ensures we never traverse blocked cells.

 よくある間違いは、BFS はすべてのソースを同時に開始するものとして扱う必要があることを忘れることです。 代わりに、ソースごとに個別に BFS を実行し、最小限を手動で実行すると、ソリューションは大幅に遅くなり、冗長になります。 

もう 1 つの微妙な点は、初期化に大きなセンチネル値を使用することです。 これにより、初期化されていないデータとの誤った比較が回避され、到達可能なセルが適切に緩和されることが保証されます。 

## 実用的な例

 住宅が制限内で両方の施設に到達できるかどうかを評価する小さなグリッドを考えてみましょう。 

### 例 1

 入力:```
3 5 3
S...P
.#.#.
H...H
```学校からの BFS 後:

 | セル | Sまでの距離 |
 | --- | --- |
 | H(2,0) | 2 |
 | H(2,4) | 6 |

 公園からの BFS 後:

 | セル | Pまでの距離 |
 | --- | --- |
 | H(2,0) | 6 |
 | H(2,4) | 2 |

 今の評価：

 | ハウス | 距離 | 距離P | 有効 |
 | --- | --- | --- | --- |
 | (2,0) | 2 | 6 | いいえ |
 | (2,4) | 6 | 2 | いいえ |

 どちらの家も D=3 以内では両方に到達できないため、出力は 0 です。 

これは、両方の条件を同時に要求することで、非対称のアクセシビリティがどのように除外されるかを示しています。 

### 例 2

 入力:```
3 5 4
S...P
.....
H...H
```After BFS:

 | ハウス | 距離 | 距離P | 有効 |
 | --- | --- | --- | --- |
 | (2,0) | 2 | 4 | Yes |
 | (2,4) | 4 | 2 | Yes |

 出力は2です。 

これは、オープン パスが存在すると、マルチソース BFS が再計算なしでグローバル最短距離を正しく取得することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(RC) | 各 BFS は各セルを最大 1 回訪問し、2 つの BFS パスを実行します。 
| スペース | O(RC) | 2 つの距離グリッドと最大 RC セルにわたるキュー |

 グリッドは最大 900 セルであるため、係数オーバーヘッドが一定であっても、ソリューションは容易に制限内で高速になります。 BFS の複雑さは D ではなく構造に依存するため、このアプローチは最大距離の制約があっても引き続き効率的です。 

## テストケース```python
import sys, io

def solve():
    from collections import deque
    input = sys.stdin.readline

    def bfs(starts, grid, R, C):
        INF = 10**9
        dist = [[INF]*C for _ in range(R)]
        q = deque()
        for r,c in starts:
            dist[r][c]=0
            q.append((r,c))
        dr=[1,-1,0,0]
        dc=[0,0,1,-1]
        while q:
            r,c=q.popleft()
            for k in range(4):
                nr,nc=r+dr[k],c+dc[k]
                if 0<=nr<R and 0<=nc<C and grid[nr][nc]!='#':
                    if dist[nr][nc]>dist[r][c]+1:
                        dist[nr][nc]=dist[r][c]+1
                        q.append((nr,nc))
        return dist

    R,C,D=map(int,input().split())
    grid=[list(input().strip()) for _ in range(R)]

    S=[];P=[];H=[]
    for i in range(R):
        for j in range(C):
            if grid[i][j]=='S': S.append((i,j))
            if grid[i][j]=='P': P.append((i,j))
            if grid[i][j]=='H': H.append((i,j))

    ds=bfs(S,grid,R,C)
    dp=bfs(P,grid,R,C)

    ans=0
    for r,c in H:
        if ds[r][c]<=D and dp[r][c]<=D:
            ans+=1
    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return sys.stdout.getvalue() if False else None

 ## 特殊なケース

 特殊なケースの 1 つは、家がオープンセルで囲まれているものの、すべての学校からは薄い壁で隔てられている場合に発生します。 その状況では、学校からのBFSは決してハウスセルに到達しないため、その距離は無限のままであり、最終チェックで正しく拒否されます。 

もう一つは、学校や公園が複数ある場合です。 マルチソース BFS は、すべてのソースを距離 0 で初期化することでこれを自然に処理します。 距離フィールドはすべての可能なソースにわたって最小になるため、存在する数に関係なく、最も近い施設が常に優先されます。 

最後のエッジケースは、D が非常に大きい場合です。 たとえ D がグリッドの直径を超えたとしても、答えは D 自体の値ではなく、到達可能性にのみ依存します。 距離が正確に計算され、しきい値の比較がスケールに関係なく有効なままであるため、アルゴリズムはこれを正しく処理します。
