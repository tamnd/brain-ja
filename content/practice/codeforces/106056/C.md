 ## 解決策
 ## 問題の理解

 問題は、利益を最大化するためにパンを焼く方法を選択することです。 パン屋には一定量の生地といくつかの可能な詰め物があります。 各フィリングの種類には利用可能な量が限られており、そのフィリングを使用する各パンはフィリングと生地を消費し、一定の金額を与えます。 パン屋は、生地を消費するだけで一定の利益が得られる、中身のないプレーンなパンを作ることもできます。 目標は、可能な限り最大の収益を見つけることです。 

入力には、利用可能な生地、フィリングの種類の数、およびプレーン バンズのレシピが記述されます。 各フィリングの種類には、そのフィリングの合計量、バンズごとに必要なフィリングの量、バンズごとに必要な生地、および販売価格の 4 つの値が与えられます。 生産高は、獲得できる最大の金額です。 

生地の制限は最大 1000 であり、これが重要な制約です。 充填の選択肢の数が指数関数的に増加するソリューションは不可能です。充填の種類が少数であっても、組み合わせが多すぎる可能性があるからです。 ただし、充填タイプの数が多くても 10 種類と少ないことから、生地の使用状況を追跡する動的プログラミング状態を許容できることがわかります。 

難しいのは、各詰め物は複数回使用できますが、使用できる量までしか使用できないことです。 不注意な解決策は、生地 1 グラムあたりの価格が最も高い詰め物を貪欲に選択する可能性があります。 たとえば、入力が次の場合:```
10 2 2 1
7 3 2 100
12 3 1 10
```正しい出力は次のとおりです。```
241
```欲張った戦略では、パン 1 つにつき 100 のお金が得られるため、最初の具材のみに焦点を当てる可能性があります。 ただし、2 番目のフィリングでは生地の使用量が減り、より多くのバンズを製造できます。 両方の具材を混ぜ合わせるのが最適です。 

もう 1 つの特殊なケースは、プレーンのバンズが最良の選択肢である場合です。 考慮する：```
100 1 25 50
15 5 20 10
```正しい出力は次のとおりです。```
200
```常に具材を最初に使用しようとする方法では、損失が発生します。プレーンなバンズ 4 個の方が、具材を含むあらゆる組み合わせよりも収益が高くなるからです。 

## アプローチ

 簡単なアプローチは、すべてのフィリングの種類に対して、可能な限りすべての数のバンズを試してみることです。 フィリングについては、0 個のバンズから利用可能なフィリングで許可される最大値まで選択できます。 複数の詰め物があるため、組み合わせの数はこれらすべての選択肢の積になります。 

最悪の場合、各充填量が十分に大きいため、多くの選択肢が可能になります。 具材が 10 個しかない場合でも、すべての組み合わせを試すと時間がかかりすぎる可能性があります。 この強引なアイデアは、考えられるすべてのベーキング プランをチェックするので正しいのですが、検索スペースが大きすぎます。 

重要な観察点は、生地が制限リソースであり、その最大値はわずか 1000 であるということです。使用される具材の正確な組み合わせを覚える必要はありません。 生地がどれだけ残っているかを知る必要があるだけです。将来の決定はそれだけに依存するからです。 これにより、問題は有界ナップザック問題に変換されます。 

フィリングの種類ごとに、そのフィリングの可能な量をすべて処理し、生地の可能な量ごとに達成可能な最高の利益を更新します。 すべての具材を処理した後、最も収益性の高い方法で残りの生地にプレーンなバンズを詰めることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 詰め物数の指数関数 | お(1) | 遅すぎる |
 | 動的プログラミング | O(m * n * 最大可能文数) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 生地の量、餡の数、プレーンバンのレシピを読んでください。 動的プログラミング配列を作成します。`dp[x]`正確に使用して獲得できる最大金額を表します`x`加工された詰め物からの生地のグラム数。 
2. フィリングの種類ごとに、そのフィリングを使用して可能なバンズの最大数を計算します。 利用可能なフィリングと、各バンズが生地を消費するという事実の両方によって制限されます。 
3. 現在のフィリングについては、ゼロから可能な最大数までのあらゆる可能な数のバンズを試してください。 カウントごとに、それらのバンズをサポートできる生地の量ごとに新しい利益を更新します。 
4. すべての具材を加工したら、プレーンのバンズを検討します。 すでに餡に費やした生地のあらゆる量について、残りの生地から何個のプレーンバンズを作ることができるかを計算し、その利益を加算します。 
5. すべての最終状態の最大値が答えです。 

これが機能する理由は、動的プログラミング状態が将来の選択に必要なすべての情報を保存しているためです。 これまでに使用した生地の量がわかれば、以前のフィリングの選択は重要ではなくなります。 すべての有効なベーキング プランは 1 つの遷移シーケンスに対応するため、生地の量ごとに保存される最適な値は常に達成可能で最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, c0, d0 = map(int, input().split())
    fillings = []

    for _ in range(m):
        a, b, c, d = map(int, input().split())
        fillings.append((a, b, c, d))

    dp = [0] * (n + 1)

    for a, b, c, d in fillings:
        ndp = dp[:]
        limit = min(a // b, n // c)

        for cnt in range(1, limit + 1):
            dough = cnt * c
            value = cnt * d
            for used in range(dough, n + 1):
                if dp[used - dough] + value > ndp[used]:
                    ndp[used] = dp[used - dough] + value

        dp = ndp

    ans = 0
    for used in range(n + 1):
        plain = (n - used) // c0
        cur = dp[used] + plain * d0
        if cur > ans:
            ans = cur

    print(ans)

if __name__ == "__main__":
    solve()
```唯一変更されるリソースは生地であるため、コードは 1 次元の DP 配列を保持します。 それぞれの詰め物について、`ndp`は前の状態のコピーであるため、現在の充填物が許容量を超えて誤って再利用されることはありません。 

ループオーバー`cnt`各塗りつぶしの境界のある性質を処理します。 バンズの最大数は、使用可能な充填制限と生地制限の最小値です。 移行では、`used - dough`なぜなら、現在のバンズのグループを追加する前にどれだけの利益が可能だったかを尋ねているからです。 

フィリングの処理後、最後のループでプレーンのバンズが個別に処理されます。 量に制限がないため、プレーンのバンズを DP に混ぜるよりも簡単です。

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(m * n * n) | すべてのフィリングとすべての可能なカウントについて、すべての生地の量を更新します。

 ## 特殊なケース

 詰め物が存在しても、その量が足りなかったり、生地が足りなかったりするため、使用できない場合があります。 その場合、最大カウントはゼロとなります。 例えば：```
10 1 2 3
1 5 1 100
```充填には 5 つのユニットが必要ですが、存在するのは 1 つだけであるため、アルゴリズムはそれをスキップします。 パン屋はプレーンなパンを 5 つ作りますが、答えは 15 です。 

たとえ価値があるように見えても、餡は普通のバンズより劣る場合があります。 のために：```
100 1 25 50
15 5 20 10
```DP はフィリングの使用によるわずかな利益のみを保存し、最終ステップでプレーン バンズの残りの生地を使用する場合と比較します。 これにより、最悪の貪欲な選択の代わりに 200 が生成されます。 

すべての詰め物のコストと価値が同じ場合、特別な処理は必要ありません。 各遷移は依然として可能なベーキング計画を表しており、最大の利益が維持されます。 例えば：```
20 2 4 5
100 1 4 5
100 1 4 5
```5 つのバンズを使用すると DP は 25 に達します。これは、繰り返される等しい選択肢が正しく処理されることを確認します。
