 ## 解決策
 ## 問題の理解

 我が家には子供達が並んでいます。 子供`i`欲しい`a[i]`合計でキャンディー。 子どもが列の先頭に着くたびに、正確に受け取ります。`m`キャンディー。 

配布後も十分な数のキャンディーを受け取っていない場合は、子供たちは列の最後尾に移動します。 そうでない場合、彼らは永久に去ります。 このプロセスは、子がなくなるまで続行されます。 

課題は、どの子が最後に辞めるかを判断することです。 

制約は非常に小さいです。 子供は最大 100 人で、各子供が欲しがるキャンディーは最大 100 個です。 お菓子の総配布数が少ないため、直接シミュレーションでも制限時間内に収まりやすいです。 それでも、キューのシミュレーションをまったく回避する、よりクリーンな観察結果があります。 

各子供にとって重要なのは、出発するまでに何ターン必要かです。 子供がキャンディーを7個欲しがるとすると、`m = 3`、受け取ったキャンディーの順序は 3、6、9 であるため、彼らは前線に 3 回訪問する必要があります。`i`ニーズ$$\left\lceil \frac{a_i}{m} \right\rceil$$曲がる。 

微妙なケースは、複数の子が同じターン数を必要とする場合に発生します。 例えば：```
3 2
4 4 4
```各子供には 2 ターンが必要です。 最終的な出発は元の順序で行われるため、子 3 が最後に出発します。 必要なターンの最大数のみを検索し、最初に出現したものを返すソリューションでは、誤って 1 が出力されます。 

もう 1 つの簡単な間違いは、次の正確な倍数を誤って処理することです。`m`。```
2 3
3 4
```子 1 には 2 ターンではなく 1 ターンだけが必要です。 正しいターン数は 1 と 2 なので、答えは 2 です。 通常の整数の除算を使用する`a[i] // m`誤った結果が生成されてしまいます。 

最後のコーナーケースは最小入力です。```
1 100
1
```子供は 1 人だけなので、キャンディーの数に関係なく、答えは 1 です。 

## アプローチ

 簡単な解決策は、説明どおりにキューをシミュレートすることです。 ストアペア`(child_index, remaining_candies)`。 前の子を削除、減算を繰り返します。`m`キャンディーを家に送るか、列の最後尾に置きます。 

このシミュレーションは文字通りプロセスに従っているため、正確です。 与えられた制約の下では、十分に高速です。 各子供が要求できるのは最大でも$$\left\lceil \frac{100}{1} \right\rceil = 100$$したがって、キュー操作の合計数は最大でも約 10,000 です。 

ただし、このプロセスについてもっと簡単に考える方法があります。 

十分なサイズのバッチを受け取った子供は去ります`m`。 重要なのは、必要な訪問回数だけです。$$t_i = \left\lceil \frac{a_i}{m} \right\rceil$$より多くの面会が必要な子供たちは、列に長く留まります。 最後に残す子は、最大の値を持つ子です。`t_i`。 

複数の子が同じ最大値を持つ場合、元の行の後の子が後に残ります。 彼らは、同じ要件を持つ以前のすべての子供たちの後に最後の訪問を完了します。 

これは、必要なターン数が最大である最後の位置を見つけるだけでよいことを意味します。

 ## アルゴリズムのチュートリアル

 1.読む`n`、`m`、そしてキャンディーの要件の配列。 
2. 子ごとに、必要なターン数を計算します。$$t_i = \left\lceil \frac{a_i}{m} \right\rceil$$整数算術では、これは次のように記述できます。$$t_i = \frac{a_i + m - 1}{m}$$フロア分割を使用します。 
3. これまでに確認された最大ターン数と、対応する子のインデックスを追跡します。 
4. 子のターン数が現在の最大数以上の場合、この子への回答を更新します。 

使用する`>=`は不可欠です。 2 人の子が同じターン数を必要とする場合、後の子が後で出発し、前の回答を上書きする必要があります。 
5. すべての子を処理した後、格納されたインデックスを出力します。 

### なぜ効果があるのか

 それぞれの子どもたちにとって、`t_i`これは、子供が出発するまでに何回前に到達する必要があるかを正確に表します。 

それより小さい子供なら誰でも`t_i`より大きな子供を持つ子供よりも厳密に早く出発します。`t_i`、より少ないラウンドのサービスで終了するためです。 

二人の子供が同じものを持っている場合`t_i`、それらの相対的な順序は決して変わりません。 最後の訪問では、最初の列で後から開始した子供も、その訪問に遅く到着します。 したがって、最大ターン数を持つすべての子供の中で、元の順序の最後の子供が家に帰る最後の子供になります。 

アルゴリズムは、最大ターン数の最後の出現、つまりまさに必要な子を明示的に見つけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    best_turns = -1
    answer = -1

    for i, candies in enumerate(a, start=1):
        turns = (candies + m - 1) // m

        if turns >= best_turns:
            best_turns = turns
            answer = i

    print(answer)

solve()
```このソリューションは、各子を 1 回だけ処理します。 

表現`(candies + m - 1) // m`の上限を計算します`candies / m`整数演算を使用します。 これにより、浮動小数点演算が回避され、正確な倍数ではない値が正しく処理されます。`m`。 

比較には、`>=`それよりも`>`。 これは最も重要な実装の詳細です。 2 人の子が同じターン数を必要とする場合、後の子が後で出発するため、後の子が現在の答えになる必要があります。 

インデックスは次のように生成されます。`enumerate(..., start=1)`なぜなら、この問題では子の番号が 0 ではなく 1 から始まるからです。

 ## 特殊なケース

 次のことを考慮してください。```
3 2
4 4 4
```それぞれの子どもに必要なもの$$\left\lceil \frac{4}{2} \right\rceil = 2$$曲がる。 アルゴリズムは子を左から右に処理します。 子 1 は最大値を 2 に設定します。子 2 は最大値と一致し、答えになります。 子 3 も最大値と一致し、最終的な答えになります。 出力は次のとおりです。```
3
```これは実際のキュープロセスと一致します。 

次に、次のことを考えてみましょう。```
2 3
3 4
```ターン数は次のとおりです。$$\left\lceil \frac{3}{3} \right\rceil = 1$$そして$$\left\lceil \frac{4}{3} \right\rceil = 2$$アルゴリズムは子 2 を出力します。このケースでは、次の正確な倍数であることが確認されます。`m`延長時間を切り上げてはなりません。 

最後に、次のことを考慮してください。```
1 100
1
```一人の子供には 1 ターンが必要です。 スキャンでは 1 つの要素のみが参照され、インデックス 1 が返されます。他に子が存在しないため、その子が必ず最後に残ります。
