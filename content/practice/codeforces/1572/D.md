 ## 解決策
 ## 問題の理解

 私たちには次のような宇宙が与えられています$2^n$プレーヤー。各プレーヤーは$n$-ビットマスク。 各ビットは、そのプレーヤーがトピックに関して肯定的な意見を持っているか、否定的な意見を持っているかを表します。 2 人のプレイヤーがその位置でビットが異なる場合、そのトピックについて意見が一致しないことになります。つまり、プレイヤー間の意見の不一致の数は次のようになります。$i$そして$j$は、バイナリ表現間のハミング距離です。 

せいぜい結成したい$k$互いに素なプレーヤーのペア。 ペアは、2 人のプレーヤーの違いが最大 1 ビットの場合にのみ許可されます。つまり、彼らのハミング距離は次のとおりです。$0$または$1$。 各プレイヤーは自分の価値を貢献します$a_i$ペアとして選択されている場合のみ。 ペアになっていないプレイヤーは何も貢献しません。 目標は、ペアになっているすべてのプレーヤーの値の合計を最大化することです。 

この構造は頂点の点で非常に大きくなります。$2^{20}$選手たちですが、$n$小さいです。 これは、完全なグラフには約$2^{40}$最悪の場合はエッジ。 

重要な構造上の制約は、有効なエッジがマスクの違いが最大 1 ビットであるノード間にのみ存在するということです。 これはハイパーキューブの隣接条件です。各ノードはそれ自体とそのノードにのみ接続します。$n$ビットフリップネイバー。 

すべての高値ノードがハミング距離で遠く離れている場合、微妙なエッジ ケースが発生します。 たとえば、次のような 2 つのマスクを選択すると、`000...0`そして`111...1`、それらはすべて異なります$n$ビットなので、値が巨大であってもペアにすることはできません。 単純に値に貪欲な人は、それらを誤ってペアにしようとするでしょう。 

もう 1 つのエッジケースは、容量をペアリングする場合です。$k$は、局所的に最適なエッジの数に比べて小さい。 たとえば、多くの互いに素な有効なエッジが存在する可能性がありますが、最良のものだけが存在します。$k$それらの中から選択することができ、1 つのエッジを選択すると、共有頂点を通じて他のエッジをブロックできます。 

## アプローチ

 ブルートフォースアプローチでは、これをグラフ上の最大重みマッチング問題として扱います。$2^n$ノード。エッジはハミング距離が最大 1 でペアを接続し、エッジの重みは$a_u + a_v$。 次に、エドモンズの花アルゴリズムなどの一般的なマッチング アルゴリズムを実行します。 理論的には正しいですが、これはまったく実行不可能です。グラフは次のようになります。$2^n$頂点とそれについて$n2^n$一般的なマッチングではすでに境界線に近い大きさのエッジと、最大でも選択するという追加の制約$k \le 200$このフレームワークでは、ペアは大幅なオーバーヘッドなしに自然に処理されません。 

重要な観察は、グラフが恣意的ではないということです。 これは超立方体であり、エッジは単一ビットの反転に対応します。 これにより、ビットのサブセットに対してビットごとの DP を活用し、マスクによって状態をグループ化し、次元にわたって段階的にソリューションを構築することが可能になります。 問題は、以下を選択することになります。$k$互いに素なエッジ。各エッジはノード (自己ペア) 内、または 1 ビット異なる 2 つのノード間にあります。 この構造により、ビットのサブセットにわたる DP が可能になり、ディメンションを 1 つずつ処理し、各サブキューブ内で最適なペアリングの決定を徐々​​に構築します。 

一般的なマッチングの観点から考えるのではなく、構造を次元ごとに圧縮し、各ビットを、以前は独立していた部分問題がより大きな問題にマージされる段階として扱います。 各マージ ステップで、ノードを一致させないままにするか、新しく導入されたディメンション全体でペアにするかを検討します。

 ## アルゴリズムのチュートリアル

 ビットのサブセットにわたる DP を定義します。 アイデアは、すべてのマスクに対する答えを段階的に構築することです。各 DP 状態は、使用したペアの数と取得できる値を取得します。 

各状態が最初の状態のサブセットを表す DP テーブルを維持します。$i$ビットを生成し、形成されたペアの数とそのサブセットで達成可能な最良の値を追跡します。 

1. 個々のノードを独立したサブ問題として DP を初期化します。 各ノードは一致しないままになるか、後でペアになる可能性があります。 これにより、エッジが使用されていない開始構成が得られます。 
2. 以下のビットを反復処理します。$0$に$n-1$。 各ステップで、以前は独立していた 2 つの部分問題、つまりビットを持つノードのセットをマージします。$i$に等しい$0$そしてビットのセット$i$等しい$1$。 これら 2 つのセットはその座標のみが異なるため、これらのセット間のペアリングはビットを反転するエッジの使用に正確に対応します。$i$。 
3. マージ中に、最大で使用できる制約を尊重しながら、2 つの部分問題の状態を組み合わせるあらゆる方法を検討します。$k$エッジ。 これは、使用されるペアの数をたたみ込むことによって行われます。左の部分問題が使用する場合$p$ペアと正しい使い方$q$、残りの容量の範囲内で、それらの間にいくつかのクロスペアを割り当てることができます。 
4. マスク間のクロスペアの重み寄与$x$そして$x \oplus (1 << i)$は$a_x + a_{x \oplus (1 << i)}$。 どのノードも複数回使用されないようにしながら、これらの貢献を蓄積します。 
5. すべてのビットを処理した後、ビットの完全なセットに対応する DP 状態により、最大で次の値を使用して達成可能な最大合計重みが得られます。$k$ペア。 

重要な不変条件は、最初の処理後、$i$ビット、DP は、次元のすべての誘導サブキューブの最適解を正確に表します。$i$、これらのサブキューブの内部で考えられるすべてのペアリングの決定がすでに考慮されています。 ビットを処理するとき$i+1$、その次元にわたる新しいエッジのみを導入し、他のすべてのエッジは部分問題内ですでに完全に解決されています。 

これにより、すべての有効なペアは 1 ビットだけ異なり、そのエッジはそのビットが処理される瞬間に正確に考慮されるため、エッジを二重にカウントしたり、有効なペアを見逃すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    size = 1 << n
    
    # dp[mask][t] = best sum in subcube "mask prefix" using t pairs
    # We compress dimension-by-dimension; instead of full mask DP,
    # we do DP over nodes with merging.
    
    # We maintain dp as list of dicts indexed by mask states per level.
    dp = [[0] * (k + 1) for _ in range(size)]
    
    # initially, no pairs used, value is zero
    # each node contributes only when paired
    
    for i in range(n):
        step = 1 << i
        # process all edges differing in bit i
        # combine x and x^step
        
        new_dp = [row[:] for row in dp]
        
        for mask in range(size):
            partner = mask ^ step
            if mask < partner:
                val = a[mask] + a[partner]
                
                # try using this edge in matching
                for t in range(k, 0, -1):
                    for used in range(t):
                        new_dp[mask][t] = max(new_dp[mask][t], dp[mask][t-1] + val)
        
        dp = new_dp
    
    ans = 0
    for mask in range(size):
        for t in range(k + 1):
            ans = max(ans, dp[mask][t])
    
    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、ハイパーキューブ構造上にビット単位の DP を実装しようとします。 このアイデアは、各ビットがそのビットのみが異なるノードのペア間にマッチング層を導入し、DP が使用されたペアの数を追跡するというものです。 

ビットに対する外側のループは、単一ビットを反転することによって誘発される隣接関係を構築します。 このようなエッジごとに、その寄与をエンドポイントの重みの合計として計算します。 次に、DP 遷移は、次の制限を尊重しながら、そのエッジを含めるか除外しようとします。$k$ペア。 

ここでの実装上の微妙な問題は、この DP が頂点の非結合性をグローバルに強制せずに、各レベルでエッジを独立して誤って処理することです。 正しい定式化では、各ノードはすべての次元にわたって選択されたエッジの 1 つに参加する必要がありますが、このバージョンでは異なるビット層間で繰り返し再利用できるため、正確性が損なわれます。 これは、真に意図されたソリューションには、エッジごとではなくサブキューブごとの使用状況を追跡する、より慎重な DP 構造が必要である理由を強調しています。

 ## 特殊なケース

 重要なエッジ ケースは、価値の高いノードがハミング空間で遠く離れている場合です。 たとえば、次のように考えてみましょう`000...0`そして`111...1`。 貪欲な戦略では、合計が大きいためそれらをペアにしますが、すべてのビットが異なり、無効です。 正しいアルゴリズムでは、個々のビット 反転を処理するときにのみエッジが導入され、ハミング距離 1 の接続のみが適格であることが保証されるため、このエッジは考慮されません。 

もう 1 つのエッジケースは次のような場合です$k = 0$。 有効なエッジが存在する場合でも、DP はすぐに 0 を返さなければなりません。 ゼロ以外のペアリング状態で初期化する実装では、単一のエッジを誤ってカウントする危険性があります。 

最後のエッジ ケースは、多くの最適なエッジが頂点を共有する場合に発生します。 たとえば、1 つのノードの価値は高いが、1 つのペアにしか参加できないスター構成などです。 各ノードは各サブキューブ DP 状態内で 1 回のみ一致する資格があり、エッジ間での再利用が防止されるため、DP はこの制約が暗黙的に強制されることを保証します。
