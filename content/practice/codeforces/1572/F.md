 ## 解決策
 ## 問題の理解

 一連の都市があり、それぞれに放送局を置くことができます。 各ステーションには高さと範囲があります。 ステーションはその範囲限界まで右側の都市に到達できますが、その間にあるより高いステーションによってブロックされます。 初期状態では、すべてのステーションの高さはゼロであり、ステーション自体にのみ到達できます。 その後、一連のイベントが発生します。 一部のイベントではステーションが新しい高さと範囲で再構築され、一時的にシステム内で最も高いステーションになります。 他のイベントでは、指定された間隔内に各都市に到達できる駅の数の合計を要求します。 私たちの仕事は、すべてのイベントを効率的に処理し、クエリに答えることです。 

最大 200,000 の都市と 200,000 のイベントがあるため、クエリまたは再構築ごとに都市のすべてのペアを考慮するアプローチは遅すぎます。 ブルート フォース ソリューションでは、各都市の左側にあるすべての駅を反復処理することで、各都市に到達する駅の数を計算しようとします。 最悪の場合、こうなります$O(nq)$、または最大$4 \cdot 10^{10}$2 秒では実行不可能な操作です。 

明らかではないエッジ ケースには、複数のステーションが同じ都市に影響を与える範囲の重複や、以前のステーションがすでに到達していた都市を超えてステーションの範囲を拡張する再構築などが含まれます。 たとえば、都市 1 のステーションが最初はそれ自体にのみ到達し、その後高さ 1、範囲 5 に再構築され、その後都市 3 のステーションがさらに高い高さ、範囲 4 で再構築される場合、ブロックされた都市を正しく考慮する必要があります。 単純なカウントでは、相対高さの制約が無視されると、ブロックされたステーションを二重にカウントしたり、見逃したりする可能性があります。 

## アプローチ

 ブルートフォースアプローチでは配列が維持されます`b`どこ`b[j]`都市に到達する駅の数です`j`。 再構築ごとに、再構築された都市からその範囲と増分までをスキャンします。`b[j]`高さの制約を満たす都市 j ごとに。 各クエリについて、合計します。`b[l..r]`。 これは原理的には機能しますが、コストがかかります$O(n)$最悪の場合は再構築ごとに、最大で$O(nq)$すべてのイベントにわたって、これでは遅すぎます。 

重要な観察は、再構築するたびに常にこれまでで最も高いステーションが作成されるということです。 これにより、前のステーションによってブロックされないことが保証され、その右側のステーションのみがブロックされる可能性があります。 この構造により、ステーションが範囲を拡張するが、左側にある以前のより高いステーションを考慮する必要がない、動的なインターバル カバレッジとして問題をモデル化できます。 

範囲の更新と範囲のクエリをサポートするセグメント ツリーまたはフェンウィック ツリーを使用して、ステーションの効果を効率的に維持できます。 具体的には、フェンウィック ツリーを使用して各都市に到達するステーションの数を追跡し、再構築された都市から到達可能な最も遠い都市までの範囲の増分として再構築を処理します。 クエリはツリー上の単純な範囲合計クエリになります。 複数の再構築が重複する場合、ステーションは再構築時に最も高くなることが保証されているため、各増分は既存のカウントに正しく追加されます。

 ## アルゴリズムのチュートリアル

 1. サイズ n のフェンウィック ツリーを初期化します。 各位置は都市を表し、そこに到達できる駅の数が格納されます。 
2. 現在の最大高さの変数を維持します。 再構築するたびに、この最大値が増加します。 
3. 各イベントについて、そのタイプを確認します。 再構築の場合:

 1. 間隔を計算する`[c, w]`新しい駅が到達できること。 当初は、`c`再建された都市であり、`w`新しい範囲です。 
2. フェンウィック ツリー範囲更新を使用して、すべての都市のカウントを増加します。`[c, w]`これは、新しい駅がこれらすべての都市に到達するという事実を反映しています。 
4. イベントがクエリの場合:

 1. フェンウィック ツリー範囲クエリを使用して、カウントの合計を計算します。`[l, r]`。 
2. 結果を印刷します。 
5. 次のイベントに進みます。 

機能する理由: 各ステーションはその時点で最も高いものとして再構築されるため、以前のステーションによってブロックされることはありません。 フェンウィック ツリーを使用すると、重複する範囲が正確かつ効率的にカウントされます。 範囲増分は新しいステーションの到達範囲をモデル化し、範囲合計クエリは任意の都市に到達するステーションの数を正確に計算します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.tree = [0]*(n+2)
        
    def update(self, idx, delta):
        while idx <= self.n:
            self.tree[idx] += delta
            idx += idx & -idx
            
    def query(self, idx):
        res = 0
        while idx > 0:
            res += self.tree[idx]
            idx -= idx & -idx
        return res
    
    def range_add(self, l, r, delta):
        self.update(l, delta)
        self.update(r+1, -delta)
        
    def prefix_query(self, idx):
        return self.query(idx)
    
    def range_query(self, l, r):
        return self.query(r) - self.query(l-1)

n, q = map(int, input().split())
fen = Fenwick(n)

for _ in range(q):
    parts = list(map(int, input().split()))
    if parts[0] == 1:
        _, c, w = parts
        fen.range_add(c, w, 1)
    else:
        _, l, r = parts
        print(fen.range_query(l, r))
```フェンウィック ツリーは、範囲の増分と範囲の合計に使用されます。 インクリメントします`[c, w]`再構築が行われると、再構築されたステーションはブロックされることなくその範囲内のすべての都市に到達できるためです。 その後、クエリは単純なプレフィックスの合計になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q log n) | フェンウィック ツリー内の各更新とクエリには O(log n) がかかり、q 個のイベントがあります。 |

 n とすると、q ≤ 2×10^5、O(q log n) ≈ 2×10^5 × 18 ≈ 3.6×10^6 の演算となり、これは 2 秒以内に収まります。
