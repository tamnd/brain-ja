 ## 解決策
 ## 問題の理解

 色の配列で表される 1 次元の画像があります。 1 回の操作で、接続された単色セグメントを選択し、セグメント全体を任意の色に再描画します。 

接続の定義は少し特殊です。 同じ色の 2 つの位置は、それらの間のすべての位置も同じ色を持つ場合に接続されます。 1 次元配列では、これは単に等しい値の最大の連続ブロックを意味します。 操作ではそのようなブロックを 1 つ選択し、ブロック全体の色を変更します。 

目標は、最小限の操作で配列全体を単一色にすることです。 

1 つのブロックを再ペイントすると、そのブロックがターゲット カラーの隣接するブロックとマージされ、後で一緒に再ペイントできる大きな連結コンポーネントが作成される可能性があるため、シミュレーションの直接的な視点は誤解を招きます。 

すべてのテスト ケースの合計の長さは最大 3000 です。これが重要な制約です。 区間にわたる三次動的計画法ソリューションは、次の理由により実現可能です。$3000^3$は全体的に大きすぎますが、すべての色が最大 20 回出現するという特別な制限により、意味のある遷移の数が大幅に減少します。 意図したソリューションでは、この制限を利用して、すべての間隔分割の考慮を回避します。 

最も一般的な間違いは、座標圧縮後の連続ブロックの観点から考えることです。 そうなると重要な情報が失われます。 

考慮する：```
1 2 1
```答えは 1 です。中央のブロックを 2 から 1 に再描画すると、配列全体が色 1 になります。 

圧縮ベースのアプローチでは 3 つのブロックが認識され、2 つのマージが必要であると誤って結論付けられる可能性があります。 

別の微妙なケースは次のとおりです。```
1 2 3 2 1
```答えは 2 です。 

まず 3 を 2 に再ペイントします。```
1 2 2 2 1
```次に、中央の 2 ブロックを 1 に再ペイントします。```
1 1 1 1 1
```最適なシーケンスは間隔の両端で一致する同じ色に依存するため、常に最大のカラー ブロックを拡張する貪欲な戦略は失敗します。 

3 番目のトラップは、最終的な色が区間内のどこにでもすでに存在している必要があると想定しています。 

のために：```
1 2 1 4 2
```答えは 3 です。最適化プロセスでは、最終的なマージの前に、より大きな領域が繰り返し作成されます。 局所的な決定は全体的な最適値を明らかにしません。 

## アプローチ

 ブルート フォース アプローチでは、すべてのイメージ構成を状態として扱い、到達可能なすべての再描画に対して BFS を実行します。 この操作は簡単にシミュレートできます。ブロックを選択して色を変更します。 すべての操作には単価があるため、この検索は正しいです。 

問題は状態空間です。 控えめな値であっても、$n$、可能な色の数は指数関数的に増加します。 到達可能なすべての構成を調査することは期待できません。 

重要な観察は、再描画が Strange Printer などの区間マージ問題と非常によく似た動作をすることです。 2 つの同じ色が位置に表示される場合$i$そして$j$、最終的には間隔全体を作るかもしれません$[i,j]$両方のエンドポイントに個別に料金を支払うことなく、単一のリージョンにまとめられます。 

これは間隔 DP を示唆しています。 

させて$dp[l][r]$部分配列を作成するために必要な最小限の操作を示します$a_l \dots a_r$単色になる。 

位置が欲しいと仮定します$l$最終的な統合カラーに参加します。 再塗装するのも選択肢の一つです$a_l$残りは独立して解決してください。 ポジションが存在するたびに別の可能性が現れる$k$と同じ色の区間内$a_l$。 次に、エンドポイント$l$そして$k$同じ最終コンポーネントにマージできるため、操作の数が減ります。 

各色が最大 20 回出現するという制限があるため、これが実用的になります。 左側の各エンドポイントには、$O(20)$考慮すべきポジションの一致。 すべての分割点を試す代わりに、同じ色の出現箇所のみを遷移します。 

これにより、間隔 DP が潜在的に立方晶遷移構造からおおよその値に減少します。$O(n^2 \cdot 20)$。

 ## アルゴリズムのチュートリアル

 配列には 0 からインデックスが付けられます。 

定義する$dp[l][r]$間隔を作るために必要な最小操作数として$[l,r]$単色。 

答えは次のようになります。$dp[0][n-1]$。 

### 再発

 もし$l=r$、間隔はすでに 1 つの色で構成されています。$$dp[l][l]=0$$間隔を長くする場合は、左端の要素を分離することから始めます。$$dp[l][r]=1+dp[l+1][r]$$これは、その位置の色を再描画することに相当します。$l$別々に実行し、残りの間隔を解決します。 

今度はあらゆるポジションを検討してください$k$と$$l<k\le r,\qquad a_k=a_l$$ポジションの場合$l$そして$k$同じ色を持っている場合、同じ最終結合領域に参加できます。 

間隔$(l+1,k-1)$最初にモノクロにする必要があります。$l$そして$k$結合プロセスで隣接するようになります。 その後、サフィックス$[k,r]$独立して解決されます。 

これにより、$$dp[l][r] = \min \left( dp[l][r], \, dp[l+1][k-1] + dp[k][r] \right)$$ここで、空の間隔は 0 になります。 

### 効率的な列挙

 色ごとに、その色が表示される位置のリストを保存します。 

状態を処理するとき$(l,r)$、色の出現のみを反復します。$a_l$。 各色は最大 20 回出現するため、各状態はそのような遷移を最大 20 回実行します。 

### 注文の実行

 長さを増やして間隔を処理します。 

計算するとき$dp[l][r]$、必要なサブ間隔はすべて厳密に短いため、その値はすでにわかっています。 

### アルゴリズムのチュートリアル

 1. 各色の位置のリストを作成します。 
2.初期化$dp[l][l]=0$すべてのインデックスに対して。 
3. 処理間隔の長さは 2 ～$n$。 
4. インターバルごとに$[l,r]$、トランジションから始めます$$dp[l][r]=1+dp[l+1][r]$$位置を扱うもの$l$独立して。 
5. すべての出現を反復処理します。$k$色の$a_l$満足のいく$l<k\le r$。 
6. コンピューティング$$cost = dp[l+1][k-1] + dp[k][r]$$ここで、最初の項が 0 になるのは、$k=l+1$。 
7.アップデート$$dp[l][r]=\min(dp[l][r],cost)$$8. すべての間隔が処理された後、出力します。$dp[0][n-1]$。 

### なぜ効果があるのか

 再帰により、左端の位置の最適な可能性がすべて網羅されます。 

間隔の最適解では$[l,r]$、どちらかの位置$l$以降のその色の出現とは別に処理され、遷移が与えられます。$1+dp[l+1][r]$、または最終的に最初に一致した位置とマージされます$k$それは最後の単色コンポーネントに属します。 

いつ$l$そのようなものと合併します$k$、それらの間にあるすべての要素は互換性のある領域にすでに吸収されている必要があります。 そうするためにかかるコストは正確には$dp[l+1][k-1]$。 後$l$そして$k$リンクされているので、残りの作業は内部で行われます$[k,r]$独立していてコストがかかる$dp[k][r]$。 

すべての最適解はこれらのケースのいずれかに当てはまり、すべての遷移は実現可能な一連の操作に対応します。 間隔の長さに関する帰納法により、再帰化によりすべての間隔の真の最適値が計算されます。 

## Python ソリューション```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pos = defaultdict(list)
        for i, x in enumerate(a):
            pos[x].append(i)

        dp = [[0] * n for _ in range(n)]

        for length in range(2, n + 1):
            for l in range(n - length + 1):
                r = l + length - 1

                dp[l][r] = 1 + dp[l + 1][r]

                for k in pos[a[l]]:
                    if k <= l:
                        continue
                    if k > r:
                        break

                    left_cost = 0
                    if l + 1 <= k - 1:
                        left_cost = dp[l + 1][k - 1]

                    dp[l][r] = min(
                        dp[l][r],
                        left_cost + dp[k][r]
                    )

        ans.append(str(dp[0][n - 1]))

    sys.stdout.write("\n".join(ans))

solve()
```DP テーブルには、間隔ごとの回答が保存されます。 長さを増やして間隔を処理すると、参照されるすべての部分問題がすでに計算されていることが保証されます。 

初期化$dp[l][l]=0$テーブルはゼロで始まるため、自動的に取得されます。 

移行`1 + dp[l + 1][r]`左端の要素を個別に処理することに対応します。 

出現リストは重要な最適化です。 単純な実装では、考えられるすべての分割点をテストすることになります。$k$、生産$O(n^3)$トランジション。 ここでは、左端点と同じ色の位置のみを参照します。 各色は最大 20 回出現するため、状態ごとの遷移の数は制限されたままになります。 

空区間の場合は注意が必要です。 いつ$k=l+1$、間隔$[l+1,k-1]$には要素が含まれていないため、その寄与はゼロでなければなりません。 

## 実用的な例

 ### 例 1

 入力:```
1 2 3 2 1
```DP の主要なステートメントは次のとおりです。 

| 間隔 | 値 |
 | --- | --- |
 | dp[2][2] | 0 |
 | dp[1][3] | 1 |
 | dp[0][4] | 2 |

 全間隔の場合:

 | ステップ | 移行 | コスト |
 | --- | --- | --- |
 | イニシャル | 1 + dp[1][4] | 3 |
 | k=4 で一致 | dp[1][3] + dp[4][4] | 1 + 0 = 1 |
 | 最終 dp[0][4] | 1 + 最高のトランジション効果 | 2 |

 両端の色が等しいため、各端点を個別に処理するよりも安価に間隔を崩壊させることができます。 

### 例 2

 入力:```
1 1 2 2
```関連する州:

 | 間隔 | 値 |
 | --- | --- |
 | dp[0][1] | 0 |
 | dp[2][3] | 0 |
 | dp[0][3] | 1 |

 間隔全体について:

 | ステップ | 移行 | コスト |
 | --- | --- | --- |
 | イニシャル | 1 + dp[1][3] | 2 |
 | k=1 で一致 | dp[1][0] + dp[1][3] | 1 |
 | 最終回 | 1 | |

 先頭の 2 つの 1 はすでにマージされたコンポーネントを形成しているため、イメージ全体に対して必要な再描画操作は 1 回だけです。

 ## 特殊なケース

 次のことを考慮してください。```
1
1
5
```間隔の長さは 1 です。 DP 基本ケースは次のようになります。`dp[0][0] = 0`。 画像にはすでに単色が含まれているため、再ペイントする必要はありません。 

考慮する：```
1
3
1 2 1
```インターバル用`[0,2]`、初期遷移は次のようになります。$$1 + dp[1][2] = 2.$$位置 2 での一致により、次の結果が生成されます。$$dp[1][1] + dp[2][2] = 0.$$これにより、状態値が 1 に減ります。アルゴリズムは、中央の要素を 1 回再描画すれば十分であることを正しく認識します。 

考慮する：```
1
5
1 2 3 2 1
```エンドポイントは同じ色を共有します。 繰り返しでは、最終位置を含む、その後に出現する色 1 がすべて明示的にチェックされます。 その一致するエンドポイントを通過する遷移により、マージの最適なシーケンスがキャプチャされ、答え 2 が得られます。 

次のことを考慮してください。```
1
5
1 1 1 1 1
```すべての間隔で、同じ色の一致する出現が繰り返し検出されます。 DP 値はずっとゼロのままです。 カラー ブロックをカウントするソリューションでは 1 つの操作が誤って報告されますが、再描画が必要ないため、間隔 DP は正しくゼロを返します。
