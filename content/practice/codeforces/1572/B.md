 ## 解決策
 ## 問題の理解

 0 と 1 のシーケンスと、連続する 3 つの要素をそれら 3 つの要素の XOR に変更できる操作が与えられます。 タスクは、最大 n 回の操作を使用してシーケンス全体をすべて 0 にできるかどうかを判断し、できる場合は、これを達成する一連の操作を提供することです。 各演算は正確に 3 つの連続する位置に影響を与え、XOR 演算により、それを適用した結果がトリプレット内の 1 の数のパリティのみに依存することが保証されます。 

入力は複数のテスト ケースを提供します。 各シーケンスは最大 200,000 要素にすることができ、すべてのテスト ケースにわたる要素の合計数が 200,000 を超えることはありません。 これは、n での二次関数の解は非常に遅すぎることを意味します。 シーケンスの長さに関して線形またはほぼ線形のアプローチが必要です。 また、シーケンスがすでにすべて 0 である場合、1 と 0 が交互に並ぶシーケンス、または 1 の数が奇数ですべてをクリアすることが不可能になるシーケンスなど、エッジ ケースも処理する必要があります。 

微妙な点の 1 つは、合計が奇数であるトリプレットに XOR 演算を適用すると、3 つすべてが 1 に反転しますが、2 または 0 の合計では 0 が生成されることです。パリティやパターン アライメントを考慮せずに左から貪欲に演算を適用する不注意なアプローチは、たとえば次のようなシーケンスで、いくつかの演算が到達不能なループに陥る可能性があります。`[1, 0, 0, 1]`、すべてゼロに減らすことはできません。 

## アプローチ

 最も簡単なアプローチはブルートフォースです。少なくとも 1 つの 1 を含む 3 つの配列を繰り返しスキャンし、演算を適用し、配列がすべて 0 になるか、それ以上進められなくなるまで続けます。 これは原理的には正しいです。どのような解も存在しますが、重複するトリプレットに繰り返し影響を与える場合、最悪の場合、O(n^2) 回の演算が必要になる可能性があります。 n が 2*10^5 であることを考えると、これでは遅すぎます。 

重要な洞察は、XOR 演算は可換性と結合性の両方があり、トリプレットの合計のパリティにのみ依存するということです。 これにより、最初の 1 をターゲットにし、左から右または右から左に貪欲な方法で一連の操作を伝播することで、ソリューションを構築することができます。 具体的には、1 の合計数が偶数の場合、それらをすべてクリアする一連の操作が常に存在します。 問題は、配列をスキャンして、有効な 3 つ組を許可する位置に 1 が出現するたびに演算を適用することによって、一連の演算を構築することに帰着します。 1の合計数が奇数でずれていると無理です。 

1 が散在している、または位置がずれているシーケンスを処理するには、2 つのパスを試行できます。1 つは左端の 1 から開始し、もう 1 つは右端の 1 から開始します。どちらかのパスですべて 0 が正常に生成された場合は、そのシーケンスを返すことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 貪欲な左右パス | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケース t の数を読み取ります。 各テスト ケースについて、n と長さ n の配列 a を読み取ります。 空のリストを初期化する`operations`適用された操作のインデックスを保存します。 
2. 配列内の 1 の合計パリティをチェックします。 2 を法とする要素の総和が奇数の場合、配列をすべて 0 にすることは不可能であるため、すぐに「NO」を出力します。 
3. それ以外の場合は、貪欲に左から右へのパスを試みます。 各インデックス i について、0 ～ n-3 の場合、`a[i]`が 1 の場合、インデックス i で XOR 演算を適用し、`a[i], a[i+1], a[i+2]`XORに。 i+1 を追加`operations`1 から始まるインデックスを記録します。 これにより、左側に新しい 1 が再導入されることなく、左端の 1 が確実に削除されます。 
4. 左から右へのパスの後、配列がすべて 0 であるかどうかを確認します。 そうであれば、「YES」と記録された操作を出力します。 
5. 左から右へのパスが失敗した場合は、貪欲に右から左へのパスを試みます。 インデックス n-3 から 0 まで開始し、いつでも操作を適用します`a[i+2]`これは、最初の 1 が右端近くにあり、左から右への移動を使用して前方に伝播できないケースをキャプチャします。 
6. 両方のパスが失敗した場合は、「NO」を出力します。 
7. 操作の数が n を超えないようにしてください。 貪欲な手順では、各操作が左側 (または右側) に新しい未処理の 1 を導入することなく、少なくとも 1 つの 1 を削除するため、これが保証されます。 

不変条件は、すべての操作が最終的にすべての位置をカバーする方法で連続する操作の数を減らすということです。 XOR 構造により、偶数パリティの構成が到達不可能になることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total = sum(a)
        if total % 2 != 0:
            print("NO")
            continue
        
        operations = []
        arr = a[:]
        # left-to-right greedy pass
        for i in range(n-2):
            if arr[i] == 1:
                xor_val = arr[i] ^ arr[i+1] ^ arr[i+2]
                arr[i] = arr[i+1] = arr[i+2] = xor_val
                operations.append(i+1)
        
        if all(x == 0 for x in arr):
            print("YES")
            print(len(operations))
            if operations:
                print(*operations)
            else:
                print()
            continue
        
        # right-to-left greedy pass
        operations = []
        arr = a[:]
        for i in range(n-3, -1, -1):
            if arr[i+2] == 1:
                xor_val = arr[i] ^ arr[i+1] ^ arr[i+2]
                arr[i] = arr[i+1] = arr[i+2] = xor_val
                operations.append(i+1)
        
        if all(x == 0 for x in arr):
            print("YES")
            print(len(operations))
            if operations:
                print(*operations)
            else:
                print()
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```コードはまずパリティをチェックして、不可能なケースをすぐに排除します。 次に、左から右と右から左の 2 つのパスを実行し、3 連符の開始位置で 1 が検出されるたびに演算を適用します。 副作用を避けるために、パスごとに配列のコピーを使用します。 各操作は 1 から始まるインデックスで保存されます。 すべてゼロのチェックにより、成功したシーケンスのみが出力されることが保証されます。
