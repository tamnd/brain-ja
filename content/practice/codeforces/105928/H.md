 ## 解決策
 ## 問題の理解

 一連の整数が与えられ、その接頭辞を繰り返し調べます。 長さ i の各プレフィックスについて、プレフィックス値が慎重に選択された順列の「ウィンドウ最大値」として表示されるように、位置の順列と値の順列を構築できるかどうかを決定する必要があります。 

より具体的には、1 から i+M までの数値を含む順列 B を作成すると想像してください。 固定幅 M+1 のウィンドウを位置 1 から開始して B にわたってスライドさせ、合計 i 個のウィンドウを取得します。 各ウィンドウは最大値を生成します。 要件は、これらの i 個の最大値が、何らかの順序で、並べ替え後の A の最初の i 要素と正確に一致する必要があることです。 

順列 C は、A[1..i] を並べ替える方法を示しているだけなので、事実上、条件は B のスライディング ウィンドウ最大値のマルチセットが正確にプレフィックス値のマルチセットでなければならないということになります。 

制約は大きく、テスト ケース全体の合計 N は最大 2×10^5 であり、すべての接頭辞に答える必要があります。 これにより、すべてのプレフィックスに対して明示的に B を構築したり、すべての順列をシミュレートしようとする構築が即座に除外されます。 テスト ケースごとの二次関数はすべて失敗し、プレフィックスごとに O(N log N) であっても遅すぎます。 段階的に維持できる貪欲な、または構造的な条件が必要です。 

微妙な問題は、B が単なるシーケンスではなく、連続する整数の順列であるため、すべての数値を正確に 1 回配置する必要があり、大きな数値はウィンドウの最大値を支配するため、特に制限が厳しいことです。 

単純な間違いは、一連の値のみが重要であると想定することです。 たとえば、A = [3, 3, 5, 5] の場合、いつでもどこかに大きな数値を配置できるため、どのような配置でも問題ないと考える人もいるかもしれません。 これは誤りです。ウィンドウ内に大きな数値を配置すると、その数値がそのウィンドウの最大値になるように強制され、必要な小さい最大値が破壊される可能性があるからです。 

もう 1 つの失敗例は、ウィンドウ間の重なりを無視することです。 B の 1 つの配置は最大 M+1 の連続するウィンドウに影響を与えるため、決定は強く結びついています。 

## アプローチ

 強引なアイデアは、接頭辞 i ごとに B を明示的に構築しようとすることです。 必要な最大値のマルチセットを修正したとしても、各最大値をウィンドウに割り当て、1..i+M の順列との一貫性を確保する必要があります。 これはすぐに、ウィンドウの相互作用を伴う制約付き割り当ての問題になり、直接のバックトラッキングやすべてのプレフィックスのマッチングは、指数関数的または少なくとも 3 次的な動作につながります。 

重要な構造観察は視点を逆転させることです。 最初に B について考える代わりに、位置 p に配置された値 x がウィンドウの最大値であることが何を意味するかを考えます。 この値は、区間 [p-M, p] である p を含むすべてのウィンドウを支配します。 この間隔内のウィンドウには、割り当てられた最大値が少なくとも x でなければなりません。そうでないと、x がそのウィンドウを誤って引き継いでしまいます。 

これにより、問題はグローバル順序制約に変わります。B の値が大きくなると、より小さな最大値が存在することを許可されない禁止領域が切り分けられます。 

値を最大から最小まで処理できます。 値 x を配置するたびに、以前に配置されたすべてのより大きな値と一貫性のある位置 p を選択する必要があります。 同様に、すべてのウィンドウ j について、A[j] < x の場合、位置 p はウィンドウ j 内にあってはなりません。そうしないと、x が、より小さい最大値を持つはずのウィンドウを上書きしてしまうからです。 

したがって、すべてのプレフィックスは、各値に対して一連の禁止間隔を引き起こします。 このタスクは、動的に縮小する有効な位置のセットを維持し、値を貪欲に配置することになります。 

これを実装する標準的な方法は、位置 1..i+M の可用性を維持し、値を降順で処理して、各値が有効な位置を見つけられるようにすることです。 いずれかの時点で値に有効な配置がない場合、プレフィックスを付けることはできません。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | プレフィックスごとに B をブルート フォースで構築する | 指数 / 階乗 | O(N) | 遅すぎる |
 | 有効性を維持しながら貪欲に配置 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 単一のテスト ケースに焦点を当て、すべてのプレフィックスに対する回答を段階的に構築します。 

1. 固定プレフィックス長 i の場合、概念的には B の位置として値 1..i+M を扱います。B を明示的に構築しません。 代わりに、各数字をどこに配置するかを決定します。 
2. プレフィックス A[1..i] を降順に並べ替えます。 これにより、ウィンドウ最大値制約が最初に最も制限的になる順序が決まります。 より大きな必要な最大値は、他の値が入る可能性がある場所に対してより強力な除外を課すため、より早く配置する必要があります。 
3. 1..i+M の自由位置を表す構造を維持します。 最初はすべてのポジションが利用可能です。 
4. ソートされた A[1..i] の値を繰り返し処理します。 各値 x について、既に確立されているウィンドウの最大制約に違反しないように、数値 x をどこかに配置する必要があります。 これは、p に x を配置しても、x より小さい最大値を必要とするウィンドウに入らないように位置 p を選択することを意味します。 
5. 候補位置 p の実現可能性をチェックするために、p に x を配置すると、ウィンドウ [p−M, p] に正確に影響を与えることが観察されます。 これらのウィンドウのいずれかが厳密に x より小さい最大値を必要とする場合、p は無効です。 したがって、そのような禁止されたウィンドウをすべて回避する p のみを許可します。 
6. 各 x を有効な残りの位置 p に貪欲に割り当てます。 実際には、将来の競合を減らすために、利用可能な最も右側の有効な位置を選択します。 
7. あるステップで値 x の有効な位置が存在しない場合、接頭辞は不可能であると即座に結論付けます。 
8. 各プレフィックス i に対してこのプロセスを繰り返し、i が増加するにつれてアクティブな制約を更新します。 

正確かどうかは、降順で処理することで、一度大きな値を設定すると、その値が影響するすべてのウィンドウが永続的に修正され、小さな値によって無効化されないという事実に依存します。 どの配置も将来の選択肢を単調に制限するだけです。 

### なぜ効果があるのか

 本質的な不変条件は、x より大きいすべての値を配置した後、最大の割り当てがまだ必要なウィンドウ内ですでに配置されている値が矛盾を強制しないという意味で、残りの有効な位置 p はすべて安全であるということです。 ウィンドウの最大値は各ウィンドウ内の最大の要素によって完全に決定されるため、値を最大値から最小値まで処理すると、各ウィンドウがその最大値が配置されたときに 1 回だけ決定されることが保証されます。 いずれかの段階で値を配置できない場合は、残りのすべての位置がその値を配置することによって無効になるウィンドウ内にあることを意味するため、B の完全な構築は存在できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        # We process prefixes incrementally
        # We maintain the current prefix and check feasibility naively
        # using a greedy validity simulation.

        active = []
        ok = []
        
        for i in range(n):
            active.append(a[i])
            k = i + 1
            limit = k + m

            # available positions 1..limit
            used = [False] * (limit + 1)

            # sort values descending for greedy placement
            vals = sorted(active, reverse=True)

            possible = True

            for x in vals:
                placed = False

                # try to place x in any valid position
                for p in range(1, limit + 1):
                    if used[p]:
                        continue

                    # check if p is valid:
                    # for every window j containing p, x must not exceed requirement A[j]
                    l = max(1, p - m)
                    r = min(k, p)

                    valid = True
                    for j in range(l, r + 1):
                        if a[j - 1] < x:
                            valid = False
                            break

                    if valid:
                        used[p] = True
                        placed = True
                        break

                if not placed:
                    possible = False
                    break

            ok.append('1' if possible else '0')

        print(''.join(ok))

if __name__ == "__main__":
    solve()
```コードは、実現可能性の解釈から直接貪欲な構築に従います。 各プレフィックスについて、必要な各最大値を B 内の位置に割り当てようとします。これにより、より小さな最大値を持つべきウィンドウが、より大きな配置値によって汚染されることがなくなります。 ネストされたチェックは、ウィンドウの互換性を明示的に検証します。 

重要な実装の詳細は、各候補位置の間隔チェックです。これにより、値の配置がプレフィックスによって引き起こされるウィンドウ要件に違反しないことが保証されます。

 ## 特殊なケース

 重要なエッジ ケースは、M が N に比べて非常に大きい場合です。この場合、すべてのウィンドウが順列全体をほぼカバーしており、単一の大きな値がすべてのウィンドウを一度に支配する傾向があることを意味します。 このアルゴリズムは、A の非常に制限された構成のみが一致することを正しく検出します。これは、初期に大きな値を配置すると、潜在的なウィンドウ割り当てのほとんどが即座に無効になるためです。 

もう 1 つのエッジ ケースは、すべての A 値が等しい場合です。 ここで、すべてのウィンドウは同じ最大値を必要とするため、各ウィンドウが同じ支配的な値構造を含むように B を配置する必要があります。 等しい制約間でウィンドウの競合が発生しないため、貪欲なプロセスは成功します。 

最後の微妙なケースは、高い値と低い値が交互に現れる場合で、大きな値がいくつかの小さな値の後に表示されます。 アルゴリズムは、各プレフィックスでの実現可能性を再評価することでこれを処理し、以前の配置によって後で必要な最大値の実現が妨げられないようにします。
