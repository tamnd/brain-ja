 ## 解決策
 ## 問題の理解

 小文字、大文字、数字、ワイルドカード文字を含む文字列が与えられます。 各ワイルドカードは、任意の小文字、大文字、または数字に個別に置き換えることができます。 すべてのワイルドカードを置き換えた後、結果の文字列は、隣り合って使用できる文字を制限する一連の隣接ルールと、文字列の末尾の特定の文字に対する境界制限を満たしている必要があります。 

制約はローカルです。 各文字タイプには、隣に座ることができるものについての固定ルールがあります。 数字は閉じたクラスのように動作します。つまり、数字は数字にしか接触できません。 小文字は別の閉じたクラスを形成します。 大文字は独自の閉じたクラスを形成します。 また、3 つの特定の記号 (数字の 1、小文字の l、および大文字の I) を文字列のどちらの端点にも使用することが禁止されるという特別な制限もあります。 

出力では、文字列全体がこれらの隣接関係および境界ルールの下で有効になるように、すべてのワイルドカード文字を置き換える方法の数 (モジュロ 998244353 で計算) が求められます。 

テスト ケースの長さの合計は最大 100 万に達し、すべての割り当てを明示的に考慮するソリューションは即座に除外されます。 ワイルドカードごとにバイナリを選択するだけでも指数関数的な増加につながるため、ソリューションでは各位置を定数時間または対数時間で処理する必要があります。 これは、状態空間が小さい位置に対して動的計画法を定式化することを強く示唆しています。 

制約が純粋にキャラクタごとではなく、隣接するキャラクタに依存するという事実から、微妙な問題が発生します。 各文字を個別に割り当ててカウントを乗算する単純なアプローチは、隣接するセグメント間の境界を越えた互換性を強制しないため、失敗します。 たとえば、「a?1A」のようなセグメントは、中央の選択肢によって左右の部分の接続が許可されるかどうかが決定されるため、各位置を独立して処理してカウントすることはできません。 

もう 1 つの特殊なケースはエンドポイントから発生します。 文字の割り当てが文字列内でローカルに有効な場合でも、1、l、I などの禁止文字を 0 または n-1 の位置に配置すると、文字列全体が無効になります。 境界フィルタリングを忘れたソリューションではオーバーカウントが発生します。 

最後に、ワイルドカードの処理は非対称です。1 つのワイルドカードで異なるクラスを表すことができ、クラスの選択によって近隣との相互作用の方法が変わります。 これが重要な構造上の困難です。 

## アプローチ

 強引な解釈は簡単です。 すべての疑問符について、62 文字 (小文字 26 文字、大文字 26 文字、数字 10 文字) の間で可能なすべての置換が試行されます。 文字列を入力した後、隣接制約と境界条件をスキャンすることで線形時間で検証します。 これにより、すべての可能性が明示的に列挙され、妥当性が直接チェックされるため、正確性が得られます。 ただし、ワイルドカードが k 個ある場合、このアプローチでは 62^k 回の割り当てが必要になり、k が 30 程度であっても完全に実行不可能になります。 

重要な観察は、ルールが各文字の「タイプ クラス」にのみ依存し、ほとんどの文字の正確な識別子には依存しないということです。 小文字、大文字、数字の 3 つの構造クラスを区別するだけで済みます。 各クラス内では、境界で禁止されている 3 つの特殊文字 1、l、および I を除き、ほとんどの文字が隣接関係に関して同じように動作します。 文字列内では、それらはクラスのように動作するため、構造の変更ではなく、重み付けされた選択肢として処理できます。 

これにより、ローカル互換性ルールを使用して 3 つの状態にわたるシーケンスをカウントするという問題が軽減されます。 各位置は、割り当てたクラスに応じて乗算係数に寄与し、位置間の遷移は、クラスが隣接ルールに一致する場合にのみ許可されます。

したがって、前の文字のクラスを表す小さな状態を持つ位置に対して動的プログラミングを使用できます。 位置ごとに、プレフィックスの処理後に各クラスに終了するための有効な方法がいくつあるかを計算します。 固定文字に遭遇すると、許可される状態が制限されます。 ワイルドカードに遭遇した場合、それが表すことができるすべての有効なクラスを考慮し、そのクラス内の具体的な文字の数を掛けます。 

遷移は単純です。位置 i のクラスを選択したら、位置 i+1 は互換性のあるクラスになければなりません。 クラスが混在しないため、隣接性制約はクラスの同等性のチェックに限定されます。 唯一の問題は、クラスを実際の文字に拡張するときに多重度を正確にカウントすることです。

 ## アルゴリズムのチュートリアル

 文字システムを小文字、大文字、数字の 3 つの構造状態に圧縮します。 また、多重度も維持します。小文字は 26 の可能性を持ち、大文字は 26 の可能性を持ち、数字は 10 の可能性を持ちます。 

さらに、特殊文字 1、l、および I は、エンドポイントに出現できないため、それらのクラスの制約された代表として扱います。 

### ステップ

 1. プレフィックスの処理後に、小文字、大文字、数字で終わる有効な文字列の数を表すサイズ 3 の DP 配列を初期化します。 すべての値は 0 から始まります。 
2. 文字列を左から右に処理します。 各位置で、どのクラスが許可されるかを決定します。 

- 文字が固定の文字または数字の場合は、そのクラスに制限します。 
- 「?」の場合は、3 つのクラスすべてを許可します。 

このステップが必要なのは、各ポジションが独立してそのクラスを選択するためですが、選択には固定の制約が尊重される必要があります。 
3. 位置 i で許可されるクラスごとに、それが寄与する具体的な文字の数を計算します。 小文字と大文字の場合、通常はそれぞれ 26 です。 数字の場合、それは 10 です。ただし、最初または最後の位置にいる場合は、無効な選択肢を減算します。数字の場合、数字「1」と等しい場合は 1 を削除します。 小文字の場合は「l」を削除します。 大文字の場合は「I」を削除します。 これにより、境界の有効性がローカルで強制されることが保証されます。 
4. 以前の状態から現在の状態への DP 遷移を実行します。 隣接には同一のクラスが必要であるため、同じクラス内でのみ遷移を実行します。 クラスの以前の dp 値に、そのクラスの位置 i にある有効な文字の数を掛けます。 
5. すべての位置を処理した後、3 つの DP 状態をすべて合計して、有効な文字列の合計数を取得します。 

### なぜ効果があるのか

 不変条件は、位置 i を処理した後、最後の文字がクラス c に属し、プレフィックス内のすべての制約が満たされるように、dp[c] がプレフィックスに文字を割り当てる方法の数を表すことです。 隣接関係により近隣間のクラスの平等が強制されるため、クラス間の遷移を考慮する必要はありません。 すべての有効な完全な文字列は、クラス選択の 1 つのシーケンスに正確に対応し、各クラス シーケンスは多重性を通じて個別に具体的な文字割り当てに拡張されます。 境界制限はエンドポイントで正確に適用されるため、無効な文字列は DP に残りません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    s = input().strip()
    n = len(s)
    
    # dp: [lowercase, uppercase, digit]
    dp_l = dp_u = dp_d = 0
    
    def mul(a, b):
        return (a * b) % MOD

    for i, ch in enumerate(s):
        ndp_l = ndp_u = ndp_d = 0
        
        def allowed_count(c):
            if c == 'l':
                return 25 if (i == 0 or i == n - 1) else 26
            if c == 'I':
                return 25 if (i == 0 or i == n - 1) else 26
            if c == '1':
                return 9 if (i == 0 or i == n - 1) else 10
            return 0
        
        # lowercase
        if ch in ('?',) or ('a' <= ch <= 'z'):
            cnt = 26
            if ch == 'l':
                cnt = 25
            if i == 0 or i == n - 1:
                if ch == 'l':
                    cnt = 25
            ndp_l = (dp_l * cnt) % MOD
        
        # uppercase
        if ch in ('?',) or ('A' <= ch <= 'Z'):
            cnt = 26
            if ch == 'I':
                cnt = 25
            if i == 0 or i == n - 1:
                if ch == 'I':
                    cnt = 25
            ndp_u = (dp_u * cnt) % MOD
        
        # digits
        if ch in ('?',) or ch.isdigit():
            cnt = 10
            if ch == '1':
                cnt = 9
            if i == 0 or i == n - 1:
                if ch == '1':
                    cnt = 9
            ndp_d = (dp_d * cnt) % MOD
        
        # first position: initialize dp
        if i == 0:
            dp_l, dp_u, dp_d = ndp_l, ndp_u, ndp_d
        else:
            dp_l, dp_u, dp_d = ndp_l, ndp_u, ndp_d
    
    print((dp_l + dp_u + dp_d) % MOD)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```この実装は各文字を 1 回処理し、3 つの構造クラスに対して 3 つの実行カウンターを維持します。 各位置は、前の寄与にそのクラスの有効な具体文字の数を乗算します。 境界制限は、禁止されたエンドポイント文字の利用可能な選択肢を減らすことによって処理されます。 

微妙な実装の詳細は、隣接制約によってクラスの切り替えが効果的に防止されるため、DP では異なるクラス間の明示的な遷移が必要ないことです。 これにより、通常は 3 x 3 の遷移が 3 つの独立したチェーンに崩壊します。

import sys, io

MOD = 998244353

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    def solve():
        s = input().strip()
        n = len(s)
        dp_l = dp_u = dp_d = 0
        
        for i, ch in enumerate(s):
            ndp_l = ndp_u = ndp_d = 0
            
            if ch in ('?',) or ('a' <= ch <= 'z'):
                cnt = 26 - (1 if ch == 'l' else 0)
                if i == 0 or i == n - 1:
                    if ch == 'l':

            if ch in ('?',) or ('A' <= ch <= 'Z'):
                cnt = 26 - (1 if ch == 'I' else 0)
                if i == 0 or i == n - 1:
                    if ch == 'I':
                        cnt = 25
                ndp_u = dp_u * cnt % MOD
            
            if ch in ('?',) or ch.isdigit():
                cnt = 10 - (1 if ch == '1' else 0)
                if i == 0 or i == n - 1:
                    if ch == '1':
                        cnt = 9
                ndp_d = dp_d * cnt % MOD

                dp_l, dp_u, dp_d = ndp_l, ndp_u, ndp_d
            else:
                dp_l, dp_u, dp_d = ndp_l, ndp_u, ndp_d
        
        return str((dp_l + dp_u + dp_d) % MOD)
    
    t = int(input())
    out = []
    for _ in range(t):
        out.append(solve())
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースは、文字列の長さが 1 の場合です。単一の文字は同時に開始でもあり終了でもあるため、3 つの禁止記号はすべて除外されます。 アルゴリズムは、常にエンドポイント制限を適用することでこれを処理します。`i == 0 or i == n - 1`、特別な分岐を行わずに、単一文字の場合を自動的にカバーします。 

もう 1 つのエッジ ケースは、完全にワイルドカードで構成された文字列です。 この状況では、DP は、すべてのポジションにわたって許可された選択肢を個別に単純に乗算します。 すべての位置はローカルに制約され、クラス分離の下では隣接する位置から独立しているため、計算は安定かつ線形のままです。 

最後のエッジ ケースは、次のような固定文字が境界で禁止されている場合に発生します。`"I..."`。 位置 0 では、DP はそのクラスにゼロのウェイを割り当て、これはすぐに合計の答えがゼロに伝播します。 これにより、明示的な拒否ロジックを必要とせずに、無効な文字列が正しく削除されます。
