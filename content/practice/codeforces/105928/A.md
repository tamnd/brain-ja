 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースには複数の串があり、各串には特定の数の肉片が含まれています。 ヴァレサは、最初に左右の 2 つの面のうち 1 つを均等にランダムに選択して各串を食べ、次にその串の連続する部分ごとに面を交互に食べます。 

この交互パターンは、開始側が固定されると、その串の左右の噛み具合の配分が完全に決定されることを意味します。 唯一のランダム性は、串ごとの最初の選択です。 

すべての串を食べた後、左の奥歯と右の奥歯で噛まれた合計数を調べます。 これらの合計間の絶対差が最大でも 1 である場合、食事はバランスが取れていると見なされます。 タスクは、このイベントの確率を計算し、それを法 998244353 で出力することです。 

すべてのテスト ケースにわたるスキューの合計数が最大 2 · 10^5 であるという制約は、合計入力サイズに関して線形または線形に近いソリューションが必要であることを意味します。 n または ai の合計で 2 次的なものは直ちに不可能です。ai は 10^9 にもなる可能性があるため、個数レベルで食べることをシミュレートすることはできません。 構造はパリティまたは同様の圧縮された統計にのみ依存する必要があります。 

素朴な解釈では、すべての串をシミュレートし、左右の不均衡を直接追跡しようとします。 AI は巨大になる可能性があり、串ごとのシミュレーションですら遅すぎるため、これはすでに失敗します。 

より微妙な失敗例は、パリティのみが重要であることに気づかずに、各串を独立して処理した場合に発生します。 たとえば、全長のみを追跡する場合、サイズ 2 と 3 の串が同様に動作すると誤って考えることになりますが、a = 3 のような単一の串では実際に不均衡の可能性が生じますが、a = 2 ではそうではありません。 

## アプローチ

 この強引なアイデアは、ランダム性を明示的にシミュレートすることです。 串ごとに開始側を選択し、各部分を交互に割り当て、結果として生じる左と右の差を追跡します。 n 個のスキューの場合、開始側の 2^n 通りの選択肢が得られ、構成ごとにすべてのスキューをシミュレートして、O(n · 2^n) が得られます。 これはnが30くらいでも爆発します。 

重要な観察は、各串が最終的な不均衡に独立して寄与しており、その寄与は長さが偶数であるか奇数であるかによってのみ依存するということです。 

串の長さが均等な場合、両側を交互に配置すると、開始側に関係なく、両側が正確に半分の部分を受け取ることができます。 したがって、不均衡への寄与はゼロです。 

串の長さが奇数の場合、片側に 1 本余分に追加されます。 左側から開始すると、左側の相対寄与度が +1 されます。 右側から開始すると、右側は +1 を取得します。これは、寄与が等しい確率で +1 または -1 になることを意味します。 

したがって、問題全体は、それぞれ 0 (偶数スキューの場合) または ±1 (奇数スキューの場合) の独立した確率変数の合計に帰着します。 k が奇数長のスキューワーの数である場合、k 個の独立した ±1 変数の合計が {−1, 0, 1} にある確率が必要になります。 

これは標準的な二項分布問題です。 +1 を成功に、-1 を失敗にマッピングすると、合計は S = k − 2X になります。ここで、X は -1 の選択肢の数です。 有効な S につながる X 値の数を数えるだけです。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n · 2^n) | O(n) | 遅すぎる |
 | パリティ削減に関する組み合わせ論 | テストあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、奇数長のスキュワーからの ±1 寄与の構成をカウントすることに帰着します。

1. 奇数の長さの串が何本あるか数えます。 この番号をkと呼びます。 開始側に関係なく偶数の寄与が常にゼロになるため、これらの串のみが不均衡に影響します。 
2. 各奇数スキュワーが独立して +1 または -1 のいずれかを確率 1/2 で寄与することを観察します。 したがって、k 個の独立した対称確率変数を効果的に合計することになります。 
3. X を -1 に寄与するスキュワーの数とします。 すると総和は S = k − 2X となります。 
4. S が {−1, 0, 1} にあるようにします。 このセット内の各ターゲット値 t について、k − 2X = t を解き、X = (k − t) / 2 を求めます。 
5. 範囲 [0, k] 内の有効な整数 X ごとに、二項係数 C(k, X) を加算します。 これは、その不均衡を生み出す有効な符号の割り当ての数をカウントします。 
6. 割り当ての総数は 2^k であるため、確率は (有効な二項式の合計) / 2^k の法 998244353 となります。 
7. 2 · 10^5 までの階乗と逆階乗を事前計算して O(1) の二項クエリに答え、高速累乗を使用して 2^k の逆剰余を計算します。 

### なぜ効果があるのか

 各スキュワーの寄与はパリティのみに依存し、これらの寄与は独立しています。 ±1 変数の合計への変換により、独立性が維持され、最終的な不均衡が完全に特徴付けられます。 最終的なバランスの条件は合計値のみに依存するため、二項係数を介して有効な符号の割り当てを数えることは、省略や二重数えることなく確率空間と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAXN = 200000 + 5

fact = [1] * MAXN
invfact = [1] * MAXN

def modpow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def ncr(n, r):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

def solve():
    t = int(input())
    arr_cases = []
    max_k = 0

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        k = sum(x & 1 for x in a)
        arr_cases.append(k)
        max_k = max(max_k, k)

    for i in range(1, max_k + 1):
        fact[i] = fact[i - 1] * i % MOD
    invfact[max_k] = modpow(fact[max_k], MOD - 2)
    for i in range(max_k, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    inv2 = (MOD + 1) // 2

    for k in arr_cases:
        total = modpow(2, k)
        ans = 0

        def add(x):
            return ncr(k, x)

        for tval in [-1, 0, 1]:
            x = k - tval
            if x % 2 == 0:
                x //= 2
                ans = (ans + ncr(k, x)) % MOD

        ans = ans * modpow(total, MOD - 2) % MOD
        print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、各テスト ケースを奇数長のスキューワーの数まで圧縮します。 階乗および逆階乗は、必要な最大 k まで一度構築されるため、定数時間の二項計算が可能になります。 各テスト ケースについて、考えられる 3 つのターゲットの不均衡値を列挙し、それらを有効な二項インデックスに変換します。 最終的な正規化では、逆モジュラーを使用して 2^k で除算します。 

微妙な点は、パリティ抽出を超えてスキュワーを個別にシミュレートすることは決してないということです。これにより、制約範囲全体に対してソリューションが十分に効率的になります。 

## 実用的な例

 串を使った単一のテストケースを考えてみましょう`[1, 2, 3]`。 奇数の串は 1 と 3 なので、k = 2 です。 

考えられるすべての結果を計算します。 

| 串1 | 串3 | S |
 | --- | --- | --- |
 | +1 | +1 | 2 |
 | +1 | −1 | 0 |
 | −1 | +1 | 0 |
 | −1 | −1 | −2 |

 有効な合計は {−1, 0, 1} であるため、ここでは S = 0 のみが寄与します。 それは 4 件中 2 件で起こり、確率は 1/2 になります。 

ここで考えてみましょう`[1, 1, 1]`したがって、k = 3です。 

すべての合計をリストします。 

| 構成 | S |
 | --- | --- |
 | + + + | 3 |
 | + + - | 1 |
 | + − + | 1 |
 | − + + | 1 |
 | ＋ − − | −1 |
 | − + − | −1 |
 | − − ＋ | −1 |
 | − − − | −3 |

 有効な合計は -1、0、1 であるため、8 つの有効な構成のうち 6 つを数え、3/4 となります。 

これらのトレースは、±1 個の選択肢にわたる二項分布のみを効果的に処理していることを示しています。

 ## 特殊なケース

 エッジケースの 1 つは、すべての串の長さが均一である場合です。 この状況では k = 0 なので、ランダムな選択はありません。 合計は常に 0 であり、すでに必要な範囲内にあります。 アルゴリズムは C(0,0) / 1 = 1 を生成し、正しい決定論的な結果と一致します。 

もう 1 つのエッジ ケースは k = 1 です。単一の奇数スキュワーは ±1 に寄与するため、最終的な合計は常に [-1, 1] の範囲内になります。 この式では両方の構成が正しくカウントされ、2 で除算され、確率 1 が得られます。 

最後の微妙なケースは、k が大きいが、ほとんどの ai が偶数である場合です。 このソリューションはすべての構造を k に圧縮するため、実行時間は生の入力サイズではなく奇数の値の数のみに依存し、大きな ai 値によるオーバーフローやパフォーマンスの問題を回避します。
