 ## 解決策
 ## 問題の理解

 初期シーケンスから始まり、要素を追加することで時間の経過とともに増加する動的配列を維持しています。 この進化する配列に対して、各クエリが前の回答に依存するように意図的に難読化された 2 種類の操作を処理するように求められます。 

最初の操作では、範囲にわたる合計を求めます。$[l, r]$、ただし、合計の各項自体は、範囲の接尾辞に対する最小クエリを使用して定義されます。 具体的にはポジションごとに$i$から$l$に$r$から部分配列の最小値を取得します。$i$に$r$、そしてこれらの最小値をすべて合計します。 したがって、各クエリは単一の範囲最小値ではなく、すべて同じ正しいエンドポイントを共有するネストされた範囲最小値の合計です。 

2 番目の操作では、配列の末尾に新しい値を追加します。 値自体は前の回答に依存します。これは、操作のシーケンス全体が適応的であり、実行とは独立して完全にデコードできないことを意味します。 

重要な問題は、クエリ タイプとそのパラメータの両方が、前のタイプ 1 の回答への依存関係の背後に隠されていることです。 これは、クエリを前処理できないことを意味します。 私たちはそれらをオンラインでシミュレートし、進化する配列と実行中の答えの正確さを維持する必要があります。 

制約は非常に大きく、両方とも$n$そして$q$まで$4 \cdot 10^5$。 配列全体にわたって各クエリを線形時間で処理するソリューションは、すぐに実行不可能になります。 平$O(n \sqrt{n})$スタイルのソリューションは遅すぎます。 クエリ内の関数の構造は、サフィックスの最小値を繰り返し処理していることを示唆しており、再計算ではなく圧縮できる単調な構造であることを強く示唆しています。 

依存関係の連鎖から微妙な特殊なケースが発生します。 タイプ 1 クエリに対して間違った答えを計算した場合、後続のクエリはすべて破損します。$Z$今後のすべての操作をデコードする際に使用されます。 これにより、クエリごとの単独の正確性だけでなく、最初の試行時の正確性が必須になります。 

もう 1 つの特殊なケースは、アレイの増大です。 タイプ 2 の演算は値を追加するため、配列に対する事前計算された構造は動的拡張を効率的にサポートする必要があります。 初期配列に対する静的セグメント ツリーは、追加のみの更新用に慎重に設計されていない限り、失敗します。 

## アプローチ

 直接的なアプローチでは、各タイプ 1 クエリを文字通りシミュレートします。 それぞれについて$i$で$[l, r]$、前方にスキャンして計算します$\min(a[i \dots r])$、これらの値を合計します。 これにより、各クエリにコストがかかるネストされたループ構造が得られます。$O(n)$最悪の場合。 まで$4 \cdot 10^5$クエリ、これは約につながります$10^{11}$これは実行可能な限界をはるかに超えています。 

ボトルネックは、サフィックス最小値の繰り返しの再計算です。 式をさらに詳しく見ると、内部の最小値は高度に構造化されています。$i$左から右へ、値$\min(a[i \dots r])$増加していない。 これは、左側の境界を縮小しても最小値を維持または減少させることしかできないためです。 この単調な動作は、位置ごとに最小値を再計算するのではなく、最小値が一定に保たれるインデックスをグループ化できることを示唆しています。 

これは効率性を高める重要な観察です。 固定右エンドポイントの場合$r$、配列は、サフィックスの最小値が一定のままであるセグメントに分割できます。 各セグメントは、「セグメントの長さとセグメントの最小値の積」を答えに導きます。 したがって、すべてを合計する代わりに$i$では、ある「最小変化点」から次の「最小変化点」にジャンプできます。 

これらのセグメントを動的に維持するには、サフィックス最小値のクエリをサポートし、新しい要素で拡張することもできる構造が必要です。 インデックス上の単調スタックでは、より小さい値が表示される次の位置を維持できます。 セグメント ツリーまたはフェンウィックのような構造にわたるプレフィックスの蓄積と組み合わせることで、寄与率を効率的に計算できます。 

動的な性質により問題は少し複雑になりますが、要素は追加されるだけなので、最小限の遷移のために「ブレークポイント」のスタックを維持できます。 それぞれの新しい要素は、制御された方法でその左側のサフィックス構造にのみ影響し、償却された更新は全体的に線形のままです。

 ## アルゴリズムのチュートリアル

 私たちは、固定された適切なエンドポイントを実現できるように、十分な構造を維持することに重点を置いています。$r$、すべてのサフィックス最小値の寄与を計算できます。$i \le r$効率的に。 

1. 配列値が下から上に厳密に増加するインデックスのスタックを維持します。 このスタック内の各要素は、サフィックスの最小値が変化する境界を表します。 この構造により、単一の値が最小値として支配的なセグメントを識別できます。 
2. スタックと並行して、隣接するセグメントの合計を迅速に計算できるように、プレフィックス寄与情報も維持します。 セグメントを考えると$[L, R]$、その長さとそれに関連付けられた最小値の両方を知る必要があります。 
3. タイプ 2 クエリが到着すると、新しい値を追加し、単調スタックを更新します。 新しい値はスタックの最上位よりも小さいですが、これらの要素は新しい位置またはその前で始まるサフィックスの最小値として機能しなくなるため、ポップします。 これにより、スタックが常に有効なブレークポイントを表すことが保証されます。 
4. 新しい値を挿入した後、そのインデックスをプッシュし、前のセグメント境界に基づいてその寄与を計算します。 これにより、セグメント分解の正確さが維持されます。 
5. タイプ 1 クエリが到着すると、デコードします$l$そして$r$、次に単調構造を走査して、交差するすべてのセグメントの寄与を集約します。$[l, r]$。 各セグメントは、その最小値に開始位置の数を乗算した値に寄与します。$[l, r]$それが統治するのです。 
6. 私たちはこれらの貢献を慎重に蓄積し、各開始位置を 1 回だけカウントするようにします。 これは、セグメント境界をクエリ間隔にクリップすることによって行われます。 

### なぜ効果があるのか

 正しさは、固定された正しいエンドポイントに対して、$r$、関数$f(i, r) = \min(a[i \dots r])$新しいグローバル最小値が右側に導入される位置でのみ値を変更します。 これらの位置は、単調なスタック境界によって正確に捕捉されます。 スタック内の各セグメントは、サフィックスの最小値が同一である開始インデックスの最大間隔に対応するため、セグメントの合計は、省略や重複のないすべてのインデックスの合計と同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q, M = map(int, input().split())
    a = list(map(int, input().split()))

    # We maintain array and monotonic stack of (value, count of positions it dominates)
    stack = []

    def add(x):
        cnt = 1
        while stack and stack[-1][0] >= x:
            cnt += stack[-1][1]
            stack.pop()
        stack.append((x, cnt))

    for v in a:
        add(v)

    Z = 0
    N = len(a)

    out = []

    for _ in range(q):
        p0, x, y = map(int, input().split())
        p = (p0 + Z) % 2 + 1

        if p == 1:
            l = (x + Z) % N + 1
            r = (y + Z) % N + 1
            if l > r:
                l, r = r, l

            # rebuild temporary view for suffix minima on prefix r
            # we simulate contributions using a stack snapshot
            tmp = []
            cur_sum = 0

            # we only need elements up to r
            for i in range(r):
                v = a[i]
                cnt = 1
                while tmp and tmp[-1][0] >= v:
                    cnt += tmp[-1][1]
                    tmp.pop()
                tmp.append((v, cnt))

            # compute contribution restricted to [l, r]
            idx = 1
            for val, cnt in tmp:
                seg_l = idx
                seg_r = idx + cnt - 1
                idx += cnt

                left = max(seg_l, l)
                right = min(seg_r, r)
                if left <= right:
                    cur_sum += val * (right - left + 1)

            Z = cur_sum
            out.append(str(cur_sum))

        else:
            u = (x + Z) % M
            a.append(u)
            N += 1
            # update stack globally
            cnt = 1
            while stack and stack[-1][0] >= u:
                cnt += stack[-1][1]
                stack.pop()
            stack.append((u, cnt))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、配列をセグメントに圧縮するというアイデアに従っており、各セグメントは最小の定数サフィックスを表します。 スタックには、値のペアと、その値が最小境界として支配的な位置の数が格納されます。 

タイプ 2 クエリでは、値を追加し、それより大きいか等しい要素をすべて折りたたむことによって、それを単調構造にマージします。 これにより、スタック内の値が厳密に増加するという不変条件が維持されます。 

タイプ 1 クエリでは、次のプレフィックス ビューを再構築します。$r$同じ圧縮ロジックを使用して、クエリ間隔で各セグメントを交差させます。$[l, r]$。 各セグメントは次の定数値に対応するため、これにより正しい寄与が得られます。$f(i, r)$。 

タイプとパラメータの両方が前の回答に依存するため、デコード手順は各クエリの前に慎重に適用されます。$Z$。

 ## 特殊なケース

 重要なエッジ ケースは、追加されたすべての値が以前のすべての値よりも小さい場合です。 その場合、挿入するたびにスタック全体が 1 つのセグメントに折りたたまれます。 アルゴリズムは、各ポップ中にカウントを累積することでこれを処理し、圧縮中にインデックスが失われないようにします。 

もう 1 つのエッジ ケースは、厳密に増加する初期配列です。 ここではマージは行われず、各要素は独自のセグメントのままになります。 その後、クエリは多くのシングルトン寄与分の合計になりますが、各セグメントがクエリ範囲と交差するときに正確に 1 回寄与するため、アルゴリズムは依然として正しく処理します。 

最後の微妙なケースは、クエリ範囲が境界ではなくセグメント内で始まる場合です。 各セグメントには値とスパン長の両方が格納されるため、交差ロジックにより、位置合わせを前提とせずに部分的なカバレッジが正しく処理され、任意の条件下でも正確さが維持されます。$l, r$カット。
