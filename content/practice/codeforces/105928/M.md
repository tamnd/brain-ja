 ## 解決策
 ## 問題の理解

 2 人のプレイヤーには、ブリッジのようなゲームに関する完全な情報が与えられます。 各スートについて、各プレーヤーは、自分が宣言者になってそのスートを選択した場合に獲得できるトリックの数をすでに正確に知っています。 唯一の不確実性は、誰が申告者となり、どの契約が履行されるかを決定する入札プロセスです。 

契約は 1 から 7 までのレベルと、クラブ、ダイヤモンド、ハート、スペード、およびトランプなしで注文されたスーツによって定義されます。 高いレベルは常に低いレベルに勝ち、同じレベル内ではスーツの順序が強さを決定します。 プレーヤーはディルクから開始して入札を交互に行います。 各入札は以前の入札より厳密に改善する必要があり、そうでない場合は違法です。 どちらのプレイヤーもパスすることができ、両方のプレイヤーが連続してパスするとオークションは終了し、最後の入札者が宣言者となります。 誰も入札しなかった場合、結果はゼロになります。 

契約が選択されたら、宣言者は少なくともレベルに 6 つのトリックを加えたものを取得する必要があります。 最終的なスコアは、成功か失敗か、脆弱性、契約、成功か失敗のマージンによって異なります。 成功すると、トリック ポイント、契約ボーナス、オーバートリック報酬、高レベルのスラム ボーナスの組み合わせが得られます。 失敗すると、アンダートリックに基づいてディフェンダーにペナルティが与えられます。そのペナルティは脆弱性に応じて異なります。 

タスクは、両方のプレイヤーが完全に合理的であり、すべてのトリックの結果を完全に認識していることを認識して、両方のプレイヤーが最適に入札した後、ディルクの最終スコアを計算することです。 

主な制約は、テスト ケースが最大 104 個あり、各テストには一定量のデータ (各プレイヤーのスーツごとに 5 つの整数) のみが含まれることです。 これは、O(t · 70) より悪いものは問題ないため、あらゆる解がテスト ケースごとに線形またはほぼ一定である必要があることを直ちに意味しますが、入札シーケンスのシミュレーションやオークション全体の状態検索を伴うものは不要であり、リスクが伴います。 

微妙なエッジケースは、両プレイヤーの可能な限り最善の結果がマイナスだった場合です。 このような状況では、両者ともオークションが契約なしで終了し、収益がゼロになることを好みます。 常にコントラクトを強制する単純なアプローチでは、0 ではなく負の値が誤って出力されます。 

もう 1 つのエッジケースは、ディルクの最高の契約がプラスであるのに、デクレアラーとしてプレイされたカエヤの最高の契約がディルクにさらに悪いマイナスのスコアを与える場合です。 その場合、たとえディルクにも良いオプションがあったとしても、カエヤは自分の契約にオークションを強制するだろう。なぜなら、超過入札はどの契約においても常に可能だからである。 

## アプローチ

 ルールを強引に解釈すると、入札プロセス全体がゲーム ツリーとしてシミュレートされます。 各州には、現在の最高入札額、誰のターンであるか、前のプレイヤーがパスしたかどうかが含まれます。 各州から、プレーヤーはパスするか、有効なより高い入札を行うことができます。 ツリーの深さはスーツ レイヤーごとに最大 35 の意味のあるレベルに達し、分岐には複数のスーツとレベルが含まれます。 状態空間は有限ではありますが、各プレーヤーの選択がその後のすべての入札シーケンスに影響を与えるため、状態空間の探索は指数関数的な爆発に直接つながります。 

重要な観察は、入札システムが最終契約の選択以外の隠れたインタラクションを導入しないことです。 契約が確定し、宣言者が割り当てられると、スコアは完全に決定されます。 両方のプレーヤーがすべての結果を完全に知っているため、入札は完全競争の下でどの端末契約がアクティブになるかを選択することと同じです。 

これにより、問題は考えられるすべての契約を 2 回評価することになります。1 回目は Diluc が宣言者であると仮定し、もう 1 回目は Kaeya が宣言者であると仮定します。 各評価は決定的なスコアを生成します。 その後、オークションは単に最終結果が選択されるかどうかを競うものであり、すべての結果が否定的な場合には、両方のプレーヤーがパスを選択する可能性が追加されます。

したがって、入札プロセスはターミナル電力会社に対する最大選択に崩壊し、ディルクは彼の最高のデクレアラースコア、またはカエヤの最高のデクレアラースコアのマイナス、またはどちらの側も契約を強行することで利益を得られない場合はゼロを受け取ります。

 ## アルゴリズムのチュートリアル

 ### ## アルゴリズムのチュートリアル

 1. 宣言者として機能する固定プレーヤーの場合、レベル 1 から 7 までで定義された 35 の可能な契約すべてを反復し、クラブから切り札がないように訴えます。 すべての可能なオークションはまさにこれらの契約の 1 つで終了するため、これで十分です。 
2. 各契約について、レベルに 6 を加えたものとして必要なトリック数を計算し、それをそのスートのプレーヤーの既知のトリック数と比較します。 これが成功か失敗かを決定します。 
3. デクレアラーが成功した場合、スート依存の計算式を使用してトリック ポイントを計算し、契約ボーナス、実際のトリックと要求されたトリックの差を使用したオーバートリック ボーナス、レベルが 6 または 7 の場合はスラム ボーナスを追加します。各コンポーネントは独立しているため、直接蓄積できます。 
4. 宣言者が失敗した場合、アンダートリックの数を計算し、脆弱性ルールに従って防御者のスコアに変換します。 問題はゼロサムであるため、このスコアは宣言者にとってマイナスとして扱われます。 
5. 宣言者としての Diluc のすべての契約の最大スコアを取得します。 これは、彼がオークションに勝った場合に達成可能な最高の結果を表します。 
6. Kaeya の最高の達成可能なスコアを取得するために、宣言者として Kaeya に対して同じ計算を繰り返します。 
7. ディルクの最終的な答えは、ディルクの最高スコア、カエヤの最高スコアの否定、およびゼロのうちの最大値です。なぜなら、両方のプレイヤーが合理的にパスして契約なしで入札を終了することを選択する可能性があるからです。 

重要な不変条件は、すべての法的入札シーケンスは 1 つの契約で終了する必要があり、両方のプレーヤーが、希望する結果を達成するか停止を選択するまで競い続けることで、どの最終契約に達するかを完全に制御できるということです。 公共事業は最終段階で完全に決定され、最終段階に到達するまでの経路とは無関係であるため、中間入札の決定によって最終契約の選択を超える追加の構造が作成されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def score_declarer(tricks, need, level, suit, vuln):
    # suit index: 0 C, 1 D, 2 H, 3 S, 4 N
    if tricks >= need:
        y = tricks - need

        if suit in (0, 1):
            trick_points = 20 * level
            over = 20 * y
        elif suit in (2, 3):
            trick_points = 30 * level
            over = 30 * y
        else:
            trick_points = 30 * level + 10
            over = 30 * y

        if trick_points >= 100:
            contract_bonus = 500 if vuln else 300
        else:
            contract_bonus = 50

        slam = 0
        if level == 7:
            slam = 1500 if vuln else 1000
        elif level == 6:
            slam = 750 if vuln else 500

        return trick_points + contract_bonus + over + slam

    z = need - tricks
    if vuln:
        if z == 1:
            return -200
        if z == 2:
            return -500
        if z == 3:
            return -800
        return -(300 * z - 100)
    else:
        if z == 1:
            return -100
        if z == 2:
            return -300
        if z == 3:
            return -500
        return -(300 * z - 400)

def best(tricks, vuln):
    best_val = -10**18
    for level in range(1, 8):
        need = level + 6
        for suit in range(5):
            best_val = max(best_val, score_declarer(tricks[suit], need, level, suit, vuln))
    return best_val

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        v1, v2 = map(int, input().split())
        diluc = list(map(int, input().split()))
        kaeya = list(map(int, input().split()))

        d_best = best(diluc, v1)
        k_best = best(kaeya, v2)

        ans = max(d_best, -k_best, 0)
        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、宣言子のスコアリングが 1 つの関数に分離されるため、成功ケースと失敗ケースが対称的に保たれ、検証が容易になります。 の`best`関数は、検索スペースが一定で小さいため、枝刈りを行わずにすべてのコントラクトを列挙します。 最後の組み合わせステップは、入札のゼロサム構造を直接エンコードします。ディルクは自分の最高の契約をプレイするか、カエヤの最高の契約に負けるか、あるいは両方ともパスします。 

実装でよくある落とし穴は、オーバートリックのスコアが契約レベルではなくスーツに依存することを忘れていることです。 もう 1 つは、契約ボーナスのしきい値を正確に 100 トリック ポイント (包括的) で誤って処理したことです。 スラムボーナスも独立しており、他のすべてのコンポーネントの後に追加する必要があります。 

## 実用的な例

 Diluc は脆弱ではなく、強力なスペード スーツを持っていますが、Kaeya は全体的に弱いという単純化されたトレースを考えてみましょう。 単一の契約の評価として、4S をテストするとします。 

| ステップ | レベル | スーツ | 必要 | トリック | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 評価 | 4 | S | 10 | 12 | 成功 |

 ここでディルクは2つのトリックで成功します。 トリックポイントは 30 × 4 = 120 で、高い契約ボーナス層がトリガーされます。 オーバートリックの貢献度は 30 × 2 で、スラムボーナスは適用されません。 これは、成功が決定された後、オーバートリックと契約ボーナスがどのように独立してスタックされるかを確認します。 

ここで、高額契約のデクレアラーとしてのカエヤの失敗例を考えてみましょう。 

| ステップ | レベル | スーツ | 必要 | トリック | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 評価 | 6 | N | 12 | 9 | 失敗 |

 カエヤは 3 トリック差でダウンしているため、アンダートリックのスコアリングが適用されます。 脆弱性によってペナルティ曲線が変化するため、同じ不足でも v2 に応じて異なる大きさが生じます。 これは、スコアを対称性から推測するのではなく、プレーヤーごとに個別に計算する必要がある理由を示しています。

 ## 特殊なケース

 重要なエッジケースは、すべての契約が両方のプレーヤーにマイナスのスコアをもたらす場合です。 その状況では、両方のプレイヤーが合理的に契約を強制しないことを選択し、正しい出力はゼロになります。 最終的な答えには最大値に明示的にゼロが含まれるため、アルゴリズムはこれを処理します。 

もう1つのエッジケースは、ディルクの最良の契約がプラスであるものの、ディルクの観点からはカエヤの最良の契約よりもまだ悪い場合です。 の計算`max(d_best, -k_best, 0)`は、誰がデクレアラーの権利を取得するかというこの競争を正確に捉えており、カエヤ自身の最適な契約がより強力な結果を生み出した場合、カエヤがディルクの計画を無効にできることを保証します。
