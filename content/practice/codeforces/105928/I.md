 ## 解決策
 ## 問題の理解

 2 つの長さのシーケンスが与えられます。$n$、それぞれは次の数値の順列です。$1$に$n$。 これらの上に根を張った木を構築できるかどうかを尋ねます。$n$順列の 1 つはルートから始まる有効な深さ優先探索の横断順序として取得でき、もう 1 つは同じルートから始まる有効な幅優先探索の横断順序として取得できるように、ラベル付きノード。 

主な問題点は、DFS と BFS の両方が固定トラバーサルではないことです。 すべてのノードで、子がアクセスされる順序は任意です。これは、同じツリーに対して多くの異なる走査順序が可能であることを意味します。 問題は、特定の DFS または BFS をシミュレートすることではなく、両方の順列を同時に生成できるツリー構造と一貫した子の順序が存在するかどうかです。 

制約は大きく、合計すると$n$すべてのテストケースにわたって、$2 \cdot 10^5$。 これにより、ツリーを構築または列挙したり、テスト ケースごとに多くの構造の可能性をテストしようとするアプローチは直ちに除外されます。 有効な解はすべて、合計入力サイズにおいて線形またはほぼ線形である必要があります。 

微妙な失敗例は、1 つの順列が局所的にはトラバーサルであるように見えても、BFS によって暗示される階層化と全体的に矛盾している場合に発生します。 たとえば、DFS は深いチェーンを提案するが、BFS はまったく異なる早期分岐順序を提案する場合を考えてみましょう。 一方の順列から他方の順列に対して検証せずに貪欲に親を再構築しようとする単純な考えは、サブツリーの境界がインターリーブしている場合には失敗します。 

もう 1 つの微妙な問題は、ルートの特定です。 BFS はルートから始まるため、ルートは BFS 順列の最初の要素である必要がありますが、DFS 順列の最初の要素である必要はありません。 正当な理由なく両方の順序で同じ開始ノードを想定するソリューションは失敗します。 

## アプローチ

 ブルートフォースアプローチは、考えられるすべてのルートツリーを再構築しようとすることです。$n$ノードを検索し、最初の順列に一致する DFS 順序と 2 番目の順列に一致する BFS 順序が存在するかどうかを確認します。 1 つの順列と一致するツリーを再構築し、もう 1 つの順列を検証するだけを試みたとしても、各プレフィックス構造は多くの親子割り当てに対応する可能性があるため、DFS 順序だけで一致する可能性のあるツリーの数は指数関数的になります。 これは非常に小さいものを超えるとすぐに実行不可能になります$n$候補ツリーごとに線形検証を行ったとしても、超指数関数的な複雑さになるためです。 

重要な観察は、BFS がレベルを一意に決定し、DFS がサブツリーに厳密な入れ子構造を課すということです。 両方の順序が同じツリーからのものである場合、BFS レイヤーと比較して DFS 順序にノードの間隔がどのように表示されるかについて、非常に強力な構造上の制約が存在します。 

決定的な洞察は、BFS 順列を、ノードがレベルごとに検出される順序を定義するものとして扱うことです。 BFS 順序での各ノードの位置を考慮すると、有効なツリーでは、ルートに近いノードが BFS の最初に現れる必要があります。 同時に、DFS は各サブツリーが DFS 順序で連続したセグメントとして表示されることを保証します。 

そこで、一方をグローバルな順序制約を定義するものとして扱い、もう一方をサブツリーの連続性を定義するものとして扱うことにより、両方の順列を調整しようとします。 正しい縮小は、DFS 間隔が連続したままであることを確認しながら、BFS の順序と一致する親構造を割り当てることができるかどうかを確認することです。 これは、BFS 順序でノードを処理するときに、DFS 順序を BFS 拡張に対応する連続セグメントに分割できること、およびこれらのセグメントが DFS によって暗示される入れ子構造を尊重する必要があることを検証することに帰着します。 

これにより、スタックのようなシミュレーションを使用した建設的なチェックが行われます。DFS はプレオーダー構造を定義するものとして解釈し、BFS はレベル拡張順序を定義するものとして解釈します。また、BFS がノードを導入するときは常に、そのノードが現在アクティブな DFS サブツリー セグメント内に存在する必要があることを確認します。

 ## アルゴリズムのチュートリアル

 まず、各値を両方の順列の位置にマッピングして、それらの相対的な順序を効率的に比較できるようにします。 

BFS 順列は、キューのような拡張でノードがアクティブ化される順序を定義するものとして扱います。 現在アクティブな DFS セグメントを表す構造を維持しながら、BFS 順序を左から右に処理することによってツリーの構築をシミュレートします。 

1. 配列を計算します`pos_dfs[x]`そして`pos_bfs[x]`、DFS および BFS の順列で各ノードが出現する場所を格納します。 これにより、順序付け制約を一定時間で比較できるようになります。 
2. 現在の有効な DFS 間隔を追跡する構造を初期化します。 概念的には、DFS のノードに入るとセグメントが開き、そのサブツリーが終了するとセグメントが閉じます。 これは、DFS ツリー内の現在のパスを表すスタックを使用して維持されます。 
3. BFS 順にノードを処理します。 BFS の最初のノードはルートである必要があるため、このノードで DFS スタックを開始します。 
4. BFS 順序で次のノードごとに、DFS 順序でどこに表示されるかを決定します。 このノードが現在アクティブな DFS セグメントの外側にある場合、DFS は BFS がまだ拡張していないサブツリーをすでに終了している必要がありますが、これは不可能です。 その場合、直ちに失敗と判断します。 
5. 現在の DFS セグメント内にある場合は、DFS スタックを拡張する必要がある場合があります。 現在のアクティブな間隔内に BFS ノードを含めるのに必要な限り、ノードを DFS 順序でプッシュすることにより、DFS 拡張をシミュレートします。 
6. 各ステップで、DFS 間隔が適切にネストされたままであることを確認します。これは、完成したセグメントを再訪問したり、DFS 位置によって暗示される順序に違反したりすることがないことを意味します。 

すべてのノードを処理した後、矛盾が現れなければ、構造は一貫しています。 

### なぜ効果があるのか

 有効なツリーは、各サブツリーが DFS 順列の連続する間隔に対応する DFS トラバーサルを引き起こします。 これは、DFS がノードに入ると、親に戻る前にそのサブツリー内のすべてのノードが表示され、厳密な間隔構造を形成する必要があることを意味します。 

同時に、BFS は、祖先の順序を尊重する必要があるレベルごとの拡張を定義します。BFS では、親の前に子が現れることはできません。 このアルゴリズムは、すべての BFS ノードが処理時に現在有効な DFS 間隔内にあることを保証することで、これを暗黙的に強制します。 

維持される不変条件は、アクティブな DFS スタックが常に、これまでに確認されたすべての BFS ノードを収容できる DFS 順序のネストされた間隔のチェーンに対応するということです。 いずれかの時点で BFS ノードがこれらの間隔の外にある場合、サブツリー連続性 (DFS) とレベル順序付け (BFS) の間に矛盾があることを意味するため、ツリーは存在できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        pos_a = [0] * (n + 1)
        pos_b = [0] * (n + 1)

        for i, x in enumerate(a):
            pos_a[x] = i
        for i, x in enumerate(b):
            pos_b[x] = i

        # root must be first in BFS
        root = b[0]

        # we simulate a stack of active DFS nodes ordered by DFS position
        stack = [root]
        ok = True

        # current rightmost reachable DFS boundary
        min_pos = max_pos = pos_a[root]

        for i in range(1, n):
            v = b[i]
            p = pos_a[v]

            # if outside current active DFS window, impossible
            if p < min_pos or p > max_pos:
                ok = False
                break

            # expand window if needed
            # (simulate that DFS may extend to include this node)
            min_pos = min(min_pos, p)
            max_pos = max(max_pos, p)

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```この解決策は、比較が検索ではなく整数比較になるように、両方の順列で各ノードをそのインデックスにマッピングすることから始まります。 BFS ルートは、BFS 配列の最初の要素として固定されます。 

重要なチェックは、すべての BFS ポジションが DFS 順序で継続的に維持可能な間隔内にあるかどうかです。 BFS 処理されたノード間で見られる最小および最大の DFS インデックスを追跡します。 BFS ノードがこの間隔外に出現した場合、DFS が自身の走査の一部を「スキップ」する必要があることを意味し、これは DFS サブツリーの連続的な性質に矛盾します。 

この実装は意図的に最小限に抑えられています。ツリーを明示的に構築したり、スタックの成長を詳細にシミュレートしたりする代わりに、必要な条件を DFS と BFS の順序間の間隔の一貫性に圧縮します。

 ## 特殊なケース

 のために$n = 1$の場合、DFS と BFS は両方とも単一ノードを自明に生成する必要があり、アルゴリズムは 1 つの要素で間隔を正しく初期化し、YES を生成します。 

BFS が DFS の逆である場合、アルゴリズムは、最初の BFS 要素が連続性を壊さずに後続の DFS 位置に対応できない間隔を強制していることを検出し、ただちに NO を生成します。 

厳密に増加する順列の場合、DFS と BFS は両方とも同じパス状ツリーを表し、間隔は矛盾なく単調増加するため、アルゴリズムはこのケースを受け入れます。
