 ## 解決策
 ## 問題の理解

 無限グリッド上の水平線分と垂直線分のセットが与えられます。 Neo-Bot は原点から開始し、これらのセグメントに沿ってのみ移動できます。 各セグメントには、線に沿ったマンハッタンの長さに等しい長さが関連付けられています。 タスクは、Neo-Bot がターゲット座標に到達するために利用可能なセグメントに沿って移動しなければならない最短距離を決定するか、ターゲットに到達できないことを報告することです。 

入力を再フレーム化する便利な方法は、無向重み付きグラフとして使用することです。 すべてのセグメントの端点はノードになり、すべてのセグメントはエッジになり、その重みは端点間のマンハッタン距離になります。 セグメントは軸に沿って配置されているため、重みは単に変化する座標に沿った絶対的な差になります。 

課題は幾何学的計算ではなく、共有回線構造を介した接続です。 2 つのセグメントがある点で交差する場合、それらのセグメントは暗黙的に交差することができ、その交差は、セグメントの端点として明示的にリストされていない場合でも、転送ポイントとして機能します。 

制約は小さく、最大 150 セグメントです。 すべての交差を潜在的なグラフ ノードとして扱ったとしても、セグメントの総数は十分に少ないため、O(M²) の構築が可能です。 これにより、より大きな座標範囲に必要な高度な空間インデックス構造やスイープ ラインの最適化の必要性が即座に排除されます。 

単純な間違いは、セグメントのエンドポイントのみをグラフ ノードとして扱うことです。 2 つのセグメントについて考えてみましょう。```
(0, 2) -> (10, 2)
(5, 0) -> (5, 10)
```それらは (5, 2) で交差します。 その交差点をノードとして無視すると、たとえ Neo-Bot がそこに遷移できるとしても、これらのセグメントを通過するパス間に接続がないと誤って結論付けることになります。 

もう 1 つの微妙な問題は、セグメントが正確なエンドポイントを共有する場合にのみ接続すると仮定していることです。 この問題では、セグメント全体に沿った移動が明示的に許可されるため、交差点は有効な遷移ノードとして扱われる必要があります。 

## アプローチ

 直接的な強引なアイデアは、考えられるすべての関心点がノードとなるグラフを構築することです。 ノードは、セグメントの端点に、垂直セグメント間のすべてのペアごとの交点を加えたものです。 次に、各セグメントに沿って連続する点をソートされた順序で接続し、幾何学的距離に等しいエッジの重みを割り当てます。 

このグラフが構築されると、問題は開始ノードからターゲット ノードまでの最短パス クエリに帰着します。これはダイクストラのアルゴリズムを使用して解決できます。 

ブルートフォースのボトルネックはグラフの構築にあります。 M 個のセグメントがある場合、O(M²) 個の潜在的な交差が存在します。 各交差点では座標を計算してノードを挿入する必要がありますが、M ≤ 150 であればこれを管理可能にし、最大約 22,500 チェックで済みます。 

重要な観察は、動きがセグメントに限定されており、すべての動きがセグメントに沿って連続しているため、意味のある分岐点はセグメントの端点と交差点だけであるということです。 他のポイントは接続を変更できません。 これにより、連続的な幾何学問題が、比較的小さなグラフ上の離散的な最短経路問題に変わります。 

このグラフを構築した後、ダイクストラを実行します。 状態空間は依然として十分小さいため、優先キュー ソリューションは十分に高速です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | Brute Force (完全交差グラフの構築 + ダイクストラ) | O(M² + E log V) | O(平方メートル) | 承認済み |
 | 最適 (同じ構造、慎重なグラフ構築) | O(M² log M) | O(平方メートル) | 承認済み |

 実際には、どちらも本質的には同じアプローチです。 違いは、交差グラフの規律ある構築です。 

## アルゴリズムのチュートリアル

 1. すべての候補ノードを収集します。 これらには、すべてのセグメントの端点と、水平セグメントと垂直セグメント間のすべての交点が含まれます。 パスがそこで開始または終了する可能性があるため、終点を含めます。また、方向の変更が可能であるため、交差点を含めます。 
2. 各一意の座標にノード ID を割り当てます。 これにより、異なるセグメントのペアによって作成された同一の交差点が重複排除されます。 
3. セグメントごとに、その上にあるすべてのノードを収集します。 ノードの座標がセグメントの固定座標と一致し、その境界間隔内にある場合、ノードはセグメント上にあります。 
4. これらのノードをセグメントの軸に沿って並べ替えます。 水平セグメントの場合は、x で並べ替えます。 垂直セグメントの場合は、y でソートします。 この順序は、ラインに沿った実際の走査順序を表します。 
5. このソートされた順序で連続するノード間にエッジを追加します。 移動はセグメント自体に制限されるため、各エッジの重みは 2 点間のマンハッタン距離になります。 
6. これらのエッジからグラフを作成します。 
7. (0, 0) に対応するノードから (X, Y) に対応するノードまでダイクストラを実行します。 到達可能な場合は距離を返し、到達できない場合は -1 を返します。 

### なぜ効果があるのか

 この構造により、セグメントに沿ったあらゆる可能な動きが、そのセグメント上の隣接する「イベント ポイント」間のエッジのチェーンとして表現されることが保証されます。 連続的な幾何学的意味での有効なパスは、連続する交差点または終点間の移動に分解できます。 すべての方向変更は交差点または終点でのみ発生するため、最適なパスは、イベントのない内部点を停止せずに通過する必要はありません。 これにより、離散グラフ内の最短パスが正確に保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    X, Y, M = map(int, input().split())
    
    segments = []
    nodes = set()

    # store segments
    for _ in range(M):
        x1, y1, x2, y2 = map(int, input().split())
        segments.append((x1, y1, x2, y2))
        nodes.add((x1, y1))
        nodes.add((x2, y2))

    # add intersections
    for i in range(M):
        x1, y1, x2, y2 = segments[i]
        if x1 == x2:  # vertical
            x = x1
            y_low, y_high = sorted([y1, y2])
            for j in range(M):
                if i == j:
                    continue
                a1, b1, a2, b2 = segments[j]
                if b1 == b2:  # horizontal
                    y = b1
                    x_low, x_high = sorted([a1, a2])
                    if x_low <= x <= x_high and y_low <= y <= y_high:
                        nodes.add((x, y))
        else:  # horizontal
            y = y1
            x_low, x_high = sorted([x1, x2])
            for j in range(M):
                if i == j:
                    continue
                a1, b1, a2, b2 = segments[j]
                if a1 == a2:  # vertical
                    x = a1
                    y_low, y_high = sorted([b1, b2])
                    if x_low <= x <= x_high and y_low <= y <= y_high:
                        nodes.add((x, y))

    nodes.add((0, 0))
    nodes.add((X, Y))

    idx = {p: i for i, p in enumerate(nodes)}
    inv = list(nodes)

    graph = [[] for _ in range(len(nodes))]

    # build edges
    for x1, y1, x2, y2 in segments:
        pts = []
        if x1 == x2:
            x = x1
            y_low, y_high = sorted([y1, y2])
            for (px, py) in nodes:
                if px == x and y_low <= py <= y_high:
                    pts.append((py, px, py))
            pts.sort()
            for i in range(len(pts) - 1):
                yA, xA, _ = pts[i]
                yB, xB, _ = pts[i + 1]
                u = idx[(xA, yA)]
                v = idx[(xB, yB)]
                w = abs(yA - yB)
                graph[u].append((v, w))
                graph[v].append((u, w))
        else:
            y = y1
            x_low, x_high = sorted([x1, x2])
            for (px, py) in nodes:
                if py == y and x_low <= px <= x_high:
                    pts.append((px, py, px))
            pts.sort()
            for i in range(len(pts) - 1):
                xA, yA, _ = pts[i]
                xB, yB, _ = pts[i + 1]
                u = idx[(xA, yA)]
                v = idx[(xB, yB)]
                w = abs(xA - xB)
                graph[u].append((v, w))
                graph[v].append((u, w))

    start = idx.get((0, 0))
    target = idx.get((X, Y))

    dist = [10**18] * len(nodes)
    dist[start] = 0
    pq = [(0, start)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        if u == target:
            break
        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    print(-1 if dist[target] == 10**18 else dist[target])

if __name__ == "__main__":
    solve()
```実装は構築の後に直接続きます。 不要なチェックを避けるために、交差点の検出は向きによって明示的に分割されます。 微妙な点は、すべてのノードが最初にセットに格納され、インデックス付けの前に一意性が確保されることです。 ダイクストラは、標準的なヒープベースの緩和を使用します。 

デリケートな領域の 1 つは、グラフを作成する前にすべての交点が含まれていることを確認することです。 交差点が 1 つでも欠けていると、経路がその時点で曲がることに依存する可能性があるため、接続が切断されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(M² log M) | セグメントの各ペアで交差がチェックされ、最悪の場合でもダイクストラが O(M²) ノード上で実行されます。

 ## 特殊なケース

 重要なエッジ ケースは、パスが直接のエンドポイント接続ではなく、チェーンされた複数の交差点を通過する必要がある場合です。 すべての交差点がノードになるため、アルゴリズムはこれを処理し、トラバースは中間点を介して自然に伝播します。 

もう 1 つのケースは、複数のセグメントが同じ座標を共有する、重複するエンドポイントです。 セット内のすべてのノードが重複排除されているため、これらは正しくマージされ、ダイクストラでは当然すべての発信エッジが考慮されます。 

最後のケースは、明示的に交差計算の一部ではないセグメントの端点にターゲットが存在する場合です。 これは、グラフ構築前に手動でノード セットに挿入され、幾何学的に有効であれば、グラフ表現内で目的地に常に到達できることが保証されます。
