 ## 解決策
 ## 問題の理解

 ゲームの各実行では一連のスプリット時間が記録され、各実行には同じ数のスプリットが含まれます。 入力は次の行列として考えることができます。$N$行と$K$列、行$i$実行中の各分割にかかる時間を保存します$i$、列は異なる実行にわたる同じゲーム内の目標に対応します。 

どのクエリに対しても、分割インデックスが与えられます。$s$。 タスクは列だけを見ることです$s$を抽出します。$N$その分割のすべての実行からの値を取得し、任意の 2 つの実行間の最大の改善を計算します。 改善とは、後の実行での差が速くなったり遅くなったりすることを意味しますが、各実行内で時間は厳密に増加しているため、意味のある解釈は単にその列内の 2 つの値の間の最大差、つまり、$\max(t_i[s]) - \min(t_i[s])$。 

したがって、各クエリのコア出力は実行間の順序とは独立しており、単一列の値の範囲のみに依存します。 

制約により、最大で$N, K \le 700$これにより、保存される値の合計数は最大 490,000 になります。 クエリ数$Q$と同じ大きさにすることができます$10^5$これは十分に大きいため、単純に実行するとクエリごとに列範囲を再計算するのが遅すぎます。 

すべてをスキャンする単純なソリューション$N$クエリごとに実行するとコストがかかります$O(NQ)$、これは約になります$7 \times 10^7$最悪の場合の運用。 これは境界線に当たりますが、前処理が可能なため不要です。 

重要なエッジケースは、クエリの繰り返しから発生します。 同じ分割インデックスが何度も出現する場合、その最小値と最大値を繰り返し再計算することは時間を無駄にします。 

もう 1 つの微妙な点は、各実行の値が分割全体で厳密に増加しているにもかかわらず、このプロパティは単一列内では役に立たないことです。 行内の構造のみが保証され、実行全体では保証されません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに、すべての実行を繰り返し、要求された分割の値を収集し、最小値と最大値を計算します。 答えはそれらの違いです。 これは正しいです。なぜなら、改善の定義はその列内の最大の広がりまで減少するからです。 

問題は効率です。 各クエリのコスト$O(N)$、 それで$Q$クエリコスト$O(NQ)$。 と$N = 700$そして$Q = 100000$、これは 7,000 万の操作に達します。Python では、特にスキャンとインデックス作成を繰り返す場合、これは不必要なオーバーヘッドです。 

重要な点は、各クエリが固定行列の 1 つの列にのみ依存していることです。 行列は決して変更されないため、すべての列の最小値と最大値を 1 回事前計算できます。 その後、事前に計算された値を減算することにより、各クエリは一定時間内に応答されます。 

繰り返しのスキャンを 1 回限りのスキャンに置き換えます$O(NK)$前処理ステップ。 操作数は最大 490,000 回であるため、これは制限内に簡単に収まります。

 ## アルゴリズムのチュートリアル

 サイズの 2 つの配列を構築します$K$: 1 つは分割ごとの最小値、もう 1 つは分割ごとの最大値です。 

1. 2 つの配列を初期化する`mn`そして`mx`サイズの$K$。 すべて設定`mn`非常に大きな数値とすべての値`mx`値を非常に小さな数に設定します。 これにより、各列の極値を安全に更新する準備が整います。 
2. 各実行を 1 つずつ読み取ります。 実行ごとに、それを反復します。$K$値を分割します。 ポジションについて$j$、 アップデート`mn[j] = min(mn[j], value)`そして`mx[j] = max(mx[j], value)`。 これにより、すべての実行を処理した後、各列にグローバル最小値と最大値が確実に格納されます。 
3. For each query, read the split index$s$、ゼロベースのインデックスに変換して出力します。`mx[s] - mn[s]`。 

正確性は、すべてのクエリが固定列内の任意の 2 つの要素間の最大差を求めるという事実から得られます。 他のペアでは差が小さくなるため、重要な候補はその列のグローバル最小値とグローバル最大値だけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, K, Q = map(int, input().split())

    INF = 10**18
    mn = [INF] * K
    mx = [-INF] * K

    for _ in range(N):
        row = list(map(int, input().split()))
        for j in range(K):
            v = row[j]
            if v < mn[j]:
                mn[j] = v
            if v > mx[j]:
                mx[j] = v

    for _ in range(Q):
        s = int(input()) - 1
        print(mx[s] - mn[s])

if __name__ == "__main__":
    solve()
```この実装では、分割位置によってインデックスが付けられた 2 つの配列が維持されます。 前処理ループにより、各列の極値が入力行列の 1 回のパスで計算されるようになります。 クエリ処理は、配列の直接検索と減算に削減されます。 

ここでよくある間違いは、クエリごとに最小値と最大値を再計算したり、行ごとに配列を誤ってリセットしたりすることです。 もう 1 つの微妙な問題は、クエリ インデックスを 1 ベースから 0 ベースに変換するのを忘れていることです。これにより、回答が間違った分割に暗黙的にシフトされてしまいます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    input = sys.stdin.readline

    N, K, Q = map(int, input().split())

    INF = 10**18
    mn = [INF] * K
    mx = [-INF] * K

    for _ in range(N):
        row = list(map(int, input().split()))
        for j in range(K):
            mn[j] = min(mn[j], row[j])
            mx[j] = max(mx[j], row[j])

    out = []
    for _ in range(Q):
        s = int(input()) - 1
        out.append(str(mx[s] - mn[s]))

    return "\n".join(out)

## 特殊なケース

 1 回の実行による最小限の入力では、最小値が最大値と等しいため、すべての列の改善がゼロであることがわかります。 すべての値が両方の境界を同じ数値に更新し、クエリが正しくゼロを返すため、前処理は正しく初期化されます。 

すべての実行が列ごとに同じ値を共有する場合は、アルゴリズムが誤って行全体で差異を蓄積するかどうかをテストします。 各列の最小値と最大値は等しいままであるため、減算の結果はゼロとなり、予想される動作と一致します。 

値が大きく異なるにもかかわらず、実行間で並べ替えられていない場合は、実行の順序が重要ではないことを確認します。 このアルゴリズムは極値のみに依存するため、行をどのように並べ替えても同じ結果が得られ、計算は安定したままになります。
