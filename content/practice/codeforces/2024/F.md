 ## 解決策
 ## 問題の理解

 各ゲームには成功確率があります$p_i/100$そしてご褒美$w_i$。 

ゲームのサブセットを選択する場合があります。 問題は、選択したすべてのゲームに勝利した場合にのみ報酬を受け取ることができるということです。 選択したゲームが 1 つでも負けると、最終的な報酬はゼロになります。 

選択したサブセットについて$S$、$$\text{expected value} = \left(\prod_{i\in S}\frac{p_i}{100}\right) \left(\sum_{i\in S}w_i\right).$$この量を最大化する必要があります。 

まず目立つのは、その巨大な価値です。$n$、 まで$2\cdot 10^5$。 サブセットを明示的に考慮するアルゴリズムは不可能です。 平$O(n^2)$は大きすぎます。 

2 番目の珍しい制約は、$$p_i \cdot w_i \le 2\cdot 10^5.$$一見、目的とは無関係に見えますが、実は問題を解決する鍵となります。 

可能な確率値は 100 個のみです。 これは、ゲームを確率によってグループ化することを強く示唆しています。 

微妙なエッジケースは、$p_i=100$。 このようなゲームでは、確率積が減少することはありません。$1$何も変わりません。 報酬はプラスなので、$100\%$ゲームは常に取られるべきです。 

例えば：```
2
100 5
100 7
```最適な答えは$12$。 確率を無視すると、100 ゲームするとすぐに正確さが失われます。 

もう 1 つの簡単な間違いは、2 つのゲームの確率が同じである場合、その中から任意のゲームを選択できると仮定することです。 

考慮する：```
3
90 100
90 50
90 1
```確率でちょうど 2 試合を取ると決めた場合$90\%$、報酬を受け取る$100$そして$50$常に少なくとも取るのと同じくらい良いです$100$そして$1$。 同じ確率の場合、より大きな報酬がより小さな報酬よりも優勢になります。 

3 番目の罠は、最適解の合計報酬が任意に大きくなる可能性があると信じていることです。$n$巨大です。 特別な制約がそれを防ぎます。 この限界を証明することが、ソリューションの中心的な観察です。 

## アプローチ

 強引な解決策は明らかです。 すべてのサブセットを列挙し、その報酬合計と確率積を計算して、最良の答えを保持します。 

あらゆる可能性をチェックするため、これは正しいです。 

残念ながら、それは必要です$2^n$サブセット。 たとえ$n=50$これは絶望的ですが、実際の限界は$2\cdot 10^5$。 

次の疑問は、最適なサブセットのどのような特性を利用できるかということです。 

最適なサブセットに合計報酬があると仮定します。$W$。 

選択したゲームを選択してください$i$。 それを削除しても答えは改善されません。 させて$$q_i=\frac{p_i}{100}.$$最適化により得られるもの$$q_i W \ge W-w_i.$$並べ替えると、$$w_i \ge (1-q_i)W.$$乗算$p_i$、$$p_iw_i \ge \frac{p_i(100-p_i)}{100}W.$$あらゆる人にとって$1\le p_i\le 99$、$$\frac{p_i(100-p_i)}{100}\ge 0.99.$$以来$p_iw_i\le 2\cdot10^5$、$$W \le \frac{2\cdot10^5}{0.99} < 202021.$$これが画期的な点です。 

最適解にはおおよそ以上の総報酬は必要ありません$2\cdot10^5$。 

ここで、報酬額をナップザックの次元として考えることができます。 

もう一つの観察があります。 

一定確率の場合$p$、選択されたすべてのゲームは同じ乗算係数に寄与します。$p/100$。 正確に取ることにした場合$k$その確率グループからのゲームの場合、最良の選択は単に$k$最大級の報酬。 

したがって、各確率グループは、報酬を降順に並べ替えた後のプレフィックス合計のシーケンスになります。 

2 番目の計数引数は、確率について次のことを示します。$p<100$、最適なソリューションには最大で$$\left\lceil \frac1{\ln(100/p)} \right\rceil$$そのグループのゲーム。 これらの制限をすべて合計すると、$p=1,\dots,99$候補となるゲームは約 500 しかありません。 オリジナル$2\cdot10^5$ゲームは数百の関連するゲームに分割されます。 

この削減後は、総報酬を超える標準的なナップザックが実現可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n)$|$O(1)$| 遅すぎる |
 | 最適 |$O(W \cdot K)$|$O(W)$| 承認済み |

 ここ$W\approx 3\cdot10^5$そして$K\approx 500$。 

## アルゴリズムのチュートリアル

 ### 1. すべてのゲームを確率 100 で分離します。 

そのようなゲームは常に選択する必要があります。 

させて$$\text{base}=\sum w_i \quad (p_i=100).$$これらのゲームは確率積には影響しません。 

### 2. 残りのゲームを確率でグループ化する

 あらゆる人にとって$p\in[1,99]$、その確率を持つすべての報酬を集めます。 

各グループを降順に並べ替えます。 

### 3. 関連する最大の報酬のみを保持する

 確率については$p$、計算する$$\text{limit} = \left\lceil \frac1{\ln(100/p)} \right\rceil.$$一番大きいものだけ`limit`そのグループからの報酬が重要になる可能性があります。 

最適なソリューションでは、追加のゲームは役に立たないことが証明されています。 

### 4. 報酬額を求めてナップザックを実行する

 しましょう$$dp[s]$$追加報酬の合計で達成可能な最大確率の製品であること$s$。 

初期化する$$dp[0]=1.$$保持されているゲームごとに$(p,w)$、$$dp[s] = \max(dp[s],\, dp[s-w]\cdot p/100).$$これは標準的な 0/1 ナップザックのアップデートです。 

### 5. 最終的な答えを計算する

 報酬額ごとに$s$、$$\text{candidate} = dp[s]\cdot (base+s).$$全体の最大値を取る$s$。 

### なぜ効果があるのか

 重要な不変条件は、保持されたゲームのいくつかのセットを処理した後、`dp[s]`合計報酬が正確に一致するすべてのサブセットの中で可能な最大の確率積を格納します。`s`。 

トランジションは標準の 0/1 ナップザック トランジションです。 現在のゲームが選択されないか、または選択されて確率積に次の値が乗算されます。$p/100$。 

固定確率グループの場合、最適解の一部となるのは最大の報酬だけであるため、枝刈りステップは安全です。 さらに、1 つの確率グループから選択されたゲームの数に関する分析限界により、すべての最適解が枝刈り後に生き残ることが保証されます。 

すべての最適なサブセットは、到達可能な報酬合計に対応するため、$s$、 そして`dp[s]`その合計に対する最良の確率積を保存し、最大化します$$dp[s](base+s)$$考えられるすべての報酬合計について、最適なサブセットの客観的値を正確に調べます。 それらの最大値が大域最適値です。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

n = int(input())

groups = [[] for _ in range(101)]
base = 0

for _ in range(n):
    p, w = map(int, input().split())
    if p == 100:
        base += w
    else:
        groups[p].append(w)

items = []

for p in range(1, 100):
    if not groups[p]:
        continue

    groups[p].sort(reverse=True)

    limit = math.ceil(1.0 / math.log(100.0 / p))
    if limit < len(groups[p]):
        groups[p] = groups[p][:limit]

    for w in groups[p]:
        items.append((w, p / 100.0))

MAXS = base
for w, _ in items:
    MAXS += w

dp = [0.0] * (MAXS + 1)
dp[0] = 1.0

for w, prob in items:
    for s in range(MAXS, w - 1, -1):
        cand = dp[s - w] * prob
        if cand > dp[s]:
            dp[s] = cand

ans = float(base)

for s in range(MAXS + 1):
    if dp[s] > 0:
        ans = max(ans, dp[s] * (base + s))

print(f"{ans:.10f}")
```最初のセクションでは、確率 100 のゲームが常に有利であるため、それらを分離します。 

グループ化フェーズでは、各確率バケット内の報酬を並べ替えます。 枝刈り限界は、最適なソリューションで同じ確率のゲームが何回出現できるかという分析限界から決まります。 

剪定後の残り試合数はわずか数百試合。 だからこそナップサックが実現可能となるのです。 

DP は、確率積を浮動小数点値として直接格納します。 積は非常に小さくなる可能性がありますが、枝刈り限界によって乗算係数の数が制限されるため、通常の倍精度で十分です。 

ナップザック ループでは逆の反復順序が重要です。 順方向反復を使用すると、誤って同じゲームが複数回選択される可能性があります。

 ## 特殊なケース

 次のことを考慮してください。```
2
100 5
100 7
```アルゴリズムは両方の報酬を次のように配置します。`base = 12`。 

DP アイテムは作成されません。 

最終的な答えはこうなります$$1\cdot12=12.$$これにより、確実性のあるゲームが正しく処理されます。 

次に、次のことを考えてみましょう。```
3
90 100
90 50
90 1
```確率 90 のグループを分類した後の報酬は次のようになります。```
100, 50, 1
```このグループの 2 つのゲームを使用するソリューションは、2 つの最大の報酬によって表されます。 枝刈り引数は、同じ確率クラス内でより小さな報酬がより大きな報酬に置き換わることがないことを保証します。 

最後に次のことを考慮してください。```
1
1 200000
```期待値は$$0.01 \cdot 200000 = 2000.$$アルゴリズムはゲームを維持し、更新します`dp[200000] = 0.01`、この値を正確に計算します。 境界線$p_iw_i=200000$特別な困難は生じません。
