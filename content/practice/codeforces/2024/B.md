 ## 解決策
 ## 問題の理解

 自動販売機を設置しております`n`隠しスロットには、既知の数のレモネード缶が入っています。 もあります`n`ボタンはそれぞれ 1 つのスロットに正確にマップされていますが、マッピングは失われます。 対応するスロットに空きがある場合は、ボタンを押すと缶が得られる場合があります。 そうしないと何も起こりません。 缶がどのスロットから出てくるのかはわかりませんし、現在の中身もわかりません。 

タスクは次のとおりです。スロットの初期カウントとターゲットが与えられると、`k`、少なくとも取得を保証するボタンを押す最小回数を決定します。`k`どのボタンがどのスロットに対応しているかに関係なく、缶を使用できます。 缶の総量は少なくとも`k`。 

制約は、最大で次のことを行う可能性があることを示しています。`2 * 10^5`すべてのテスト ケースにわたって合計されたスロット、および`k`と同じ大きさにすることができます`10^9`。 これにより、到達するまでボタンを個別に押す必要があるため、考えられるすべての押し順序を試す総当りシミュレーションが除外されます。`k`O(k) 回の操作が必要になる可能性がありますが、これは大きすぎます。 スケールするメソッドが必要です`n`それよりも`k`。 

一部のスロットのカウントが非常に大きく、他のスロットのカウントが非常に小さい場合、微妙なエッジ ケースが発生します。 たとえば、次の場合`a = [1, 1000000000]`そして`k = 2`、盲目的にボタンを押す単純なアプローチでは、最初のスロットを押しすぎて無駄に押す可能性がありますが、最適な戦略では、保証するために最悪の場合の分布を考慮する必要があります。`k`缶。 

## アプローチ

 単純な解決策は、すべての押下シーケンスをシミュレートすることです。 貪欲な方法を試みることもできます。失敗するまで任意のボタンを繰り返し選択し、その後別のボタンに移動します。 原理的には正しいですが、カウントが大きい場合、これをシミュレートするのは遅すぎます。最悪の場合、O(k) 回のプレスが必要となり、最大 10^9 になります。 

重要な点は、最小押下回数が降順にソートされたスロット数に依存するということです。 スロット数を次のように表すと、`a_1 ≥ a_2 ≥ ... ≥ a_n`、最悪のシナリオは、プレスが最初に最大のスロットにヒットしたが、最後まで小さなスロットにヒットしなかった場合に発生します。 成功または失敗に基づいて押すたびに適応できるため、**ボタンごとの押下回数の二分探索**を使用してこれをモデル化できます。 

最適な解決策は、どのボタンがどのスロットにマッピングされるかの不確実性を考慮した方法で、複数のボタンに押しボタンを分散することであると考えることができます。 割り当てれば`x`各ボタンを押すと、各スロットから確実に収集される缶が`min(a_i, x)`、スロットの缶数が少ないため`x`その内容以上のものを与えることはできません。 これをすべてのスロットで合計すると、保証される缶の合計が得られます。 したがって、最小合計プレス数は最小になります。`x`の合計が`min(a_i, x)`すべてのスロットで少なくとも`k`。 

スロット数を降順に並べ替えることで、これを効率的に計算できます。 ソートしたら、貪欲なアプローチを使用できます。「最初に最大のスロットからできるだけ多くを取得する」ことを試みます。これは、可能なプレス数の二分探索に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | テスト ケースごとの O(k) | O(n) | 遅すぎる |
 | 貪欲 / 二分探索 | テスト ケースあたり O(n log max(a_i)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`そして`k`そして配列`a`。 選別`a`降順で。 ソートにより、最大のスロットを最初に「カバー」しようとします。 
2. 二分探索用に 2 つのポインタを初期化します。`low = 1`(最低 1 回押す) と`high = k`(最悪の場合: 缶ごとに 1 回プレス)。 
3. その間`low < high`、計算する`mid = (low + high) // 2`。 この候補者にとって`mid`ボタンごとの押下数、計算`sum(min(a_i, mid))`すべてのスロットにわたって。 この合計が各ボタンを押した場合の確定缶数となります`mid`適応戦略では、
 4. 合計が少なくとも`k`、その後、潜在的に達成できる`k`ボタンごとに押す回数が少なくて済むので、`high = mid`。 それ以外の場合は、設定します`low = mid + 1`プレス回数を増やすためです。 
5. 二分探索が完了したら、`low`は、ボタンごとに必要な最小押下回数です。 
6. 合計の押下回数を確認するには、各ボタンを割り当てられた回数まで押すことに注意してください。`low`回。 しかし、なぜなら`k`の合計よりも少ない場合があります`min(a_i, low)`、正確に一致するように最後のプレス回数を調整します。`k`。 したがって、プレスの合計は次の合計として計算されます。`min(a_i, low)`合計額に達するまで`k`。 

**機能する理由:** 二分探索では、次の不変条件が維持されます。`low`常に実現可能か小さすぎる、そして`high`常に保証するのに十分です`k`缶。 以来`min(a_i, x)`は単調です`x`の場合、検索は最小値に収束します。 ソートにより、プレスの最悪の場合の分布が考慮され、ボタンとスロットのマッピングに関係なく、保証された缶数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_presses(n, k, a):
    a.sort(reverse=True)
    low, high = 1, k
    while low < high:
        mid = (low + high) // 2
        total = sum(min(ai, mid) for ai in a)
        if total >= k:
            high = mid
        else:
            low = mid + 1
    # low is the minimum presses per button in worst case
    total_presses = 0
    remaining = k
    for ai in a:
        take = min(ai, low, remaining)
        total_presses += take
        remaining -= take
        if remaining == 0:
            break
    return total_presses

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    print(min_presses(n, k, a))
```コードの各部分はアルゴリズムのステップに直接対応します。 保証缶数を貪欲に計算するには、ソートが不可欠です。 二分探索ループは、各ボタンの押下をシミュレートすることなく、ボタンごとの最小押下回数を効率的に見つけます。 合計する`min(a_i, mid)`スロット制限を遵守することを保証します。 最後のループでは、合計プレス数が正確に満たされることを確認します。`k`。 

## 実用的な例

 **例 1**:

 入力:`n=2, k=2, a=[1,2]`| ステップ | ソート済み`a`| ミッド | Sum(min(a_i,mid)) | 決定 |
 | --- | --- | --- | --- | --- |
 | 初期化 | [2,1] | - | - | 低=1、高=2 |
 | 1 | - | ミッド=1 | 最小(2,1)+最小(1,1)=2 | 合計>=k → 高=1 |
 | 完了 | - | 低い=1 | 合計プレス数 = 分(2,1)+分(1,1)=2 | 出力 2 |

 各ボタンを 1 回押します。 最悪の場合、缶が2缶になります。 

**例 2**:

 入力:`n=3, k=4, a=[2,1,3]`| ステップ | ソート済み`a`| ミッド | Sum(min(a_i,mid)) | 決定 |
 | --- | --- | --- | --- | --- |
 | 初期化 | [3,2,1] | - | - | 低=1、高=4 |
 | 1 | - | ミッド=2 | 最小(3,2)+最小(2,2)+最小(1,2)=2+2+1=5 | 合計>=k → 高=2 |
 | 2 | - | ミッド=1 | 1+1+1=3 | sum<k → low=2 |
 | 完了 | - | 低い=2 | 缶が 4 個になるまでの min(a_i,2) の合計 = 2+2=4 | 成果 4 |

 これにより、アルゴリズムがプレスをスロット間で正しく分配して、`k`。
