 ## 解決策
 ## 問題の理解

 それぞれ同じ数の頂点を持つ 2 つの有向グラフが与えられ、各出力頂点からもう一方のグラフの入力頂点に 1 つのエッジを正確に追加するように求められます。 元の各グラフは強く結びついており、グラフ内の各サイクルの長さは指定された数で割り切れます。$k$。 目標は、これらを追加した後、$n$エッジを使用すると、結果として得られる結合グラフは、すべてのサイクル長が次の値で割り切れるという特性を保持します。$k$。 

入力は、各頂点に対して、それが発信頂点であるか着信頂点であるか、および両方のグラフのエッジを指定します。 サイクルの可分性プロパティを維持しながら、2 つのグラフにわたるすべての出力頂点を入力頂点と 1 対 1 でペアにすることが可能かどうかを判断する必要があります。 

制約により許可されるのは、$n$まで$2 \cdot 10^5$すべてのテスト ケースの合計で、エッジ カウントは最大$5 \cdot 10^5$グラフごとに。 これは、アルゴリズムはテスト ケースごとにほぼ直線的な時間で実行する必要があることを意味します。$O(n + m)$, なぜなら二次関数は制限時間を超えてしまうからです。 また、元のグラフは強く結びついており、すべてのサイクルは次のように割り切れます。$k$、cycle プロパティは、エッジを追加する方法に微妙な制限を設けます。 サイクルの長さを無視すると、単純なアプローチでは頂点が誤ってペアになり、無効な長さのサイクルが作成される可能性があります。 2 つのグラフの出力頂点と入力頂点の数が一致しない場合、エッジ ケースが発生します。この状況では、完全な一致を形成することは不可能です。 

この微妙さを示す小さな例は、最初のグラフのすべての頂点が発信であり、2 番目のグラフのすべての頂点が着信であるが、カウントが等しくないグラフです。 頂点が欠落していると 1 対 1 マッピングの形成が妨げられるため、単純な貪欲ペアリングは失敗します。 

## アプローチ

 ブルートフォースアプローチは、あるグラフから出て行く頂点を他のグラフの入ってくる頂点に一致させるあらゆる可能な方法を試し、作成されたすべての新しいサイクルが可分性プロパティを維持しているかどうかを確認することです。 グラフのペアごとに、$n$頂点、これには列挙が含まれます$n!$最悪の場合マッチング。 各マッチングでは、サイクル長を検証するために結果のグラフをシミュレートする必要があります。これには、グラフを走査する必要があり、少なくとも$O(n+m)$チェックあたりの時間。 これは小規模であってもすぐに実行不可能になります$n$したがって、ブルートフォースは選択肢ではありません。 

解決策を明らかにする重要な観察は、元のグラフが次で割り切れるすべてのサイクル長と強く結びついているということです。$k$。 この構造は、各グラフの頂点に「剰余クラス モジュロ」を割り当てることができることを意味します。$k$" 基準サイクルに沿った距離に基づきます。グラフ間にエッジを追加するとき、剰余の差がモジュロで一貫しているように、出力頂点を入力頂点にマッピングできます。$k$。 具体的には、すべてのサイクルをシミュレーションする必要はありません。 代わりに、発信頂点と着信頂点の数がグラフ間で一致していること、および各剰余クラスの剰余クラスの頂点の合計数がモジュロであることを確認するだけで済みます。$k$グラフ間でペアにすることができます。 グラフは強く結びついており、すべてのサイクルは次のように割り切れるためです。$k$、モジュロ条件が成立する場合、グラフ間のエッジの線形シフトはサイクルの可分性プロパティを保持します。 

これにより、問題はタイプとモジュロごとに頂点を数えて一致させるという問題に軽減されます。$k$を与える$O(n)$テストケースごとのソリューション。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。$n$そして$k$、各グラフの頂点の種類、およびエッジ。 エッジ情報は、強力な接続を保証するためにのみ必要です。 マッチングの計算に直接使用することはありません。 
2. 各グラフの発信頂点と着信頂点の数を数えます。 させて$out_1$そして$in_1$最初のグラフのカウントであり、$out_2$そして$in_2$2番目のグラフについては。 
3. 両方のグラフにわたる出力頂点の合計数が、入力頂点の合計数と等しいことを確認します。 具体的には、$out_1 + out_2 = in_1 + in_2 = n$。 これが成立しない場合は、1 対 1 マッピングは不可能であるため、「NO」を出力します。 
4. サイクルの割り算については、元のグラフにすべてのサイクルが次の値で割り切れるかどうかに注目してください。$k$次に、出力頂点を他のグラフの入力頂点に接続するエッジを追加すると、自己ループまたは不一致のモジュロを作成しない限り、プロパティが保持されます。 グラフ全体にわたって発信頂点と着信頂点のみを接続するため、新しいエッジごとに各グラフでサイクルがちょうど 1 ずつ増加します。 強力な接続により、距離剰余モジュロが保証されます。$k$サイクルは一貫したままです。 したがって、あるグラフからの出力頂点を他のグラフの入力頂点に一致させることは安全な法です。$k$。 これ以上のチェックは必要ありません。 
5. ステップ 3 に合格した場合は、「YES」を出力します。 それ以外の場合は「NO」を出力します。 

重要な洞察は、サイクル特性が元のグラフの構造と型ベースのマッチングによって保証されていることです。 サイクルを列挙する必要はありません。 

### なぜ効果があるのか

 不変条件は、エッジを追加した後、すべての頂点が 1 つの新しいエッジに参加し、1 対 1 のペアを維持することです。 元のグラフの強力な接続性により、サイクルに沿った距離が明確に定義されたモジュロであることが保証されます。$k$、タイプベースのペアリングにより、無効な長さのサイクルが作成されないことが保証されます。 カウントを一致させることで実現可能性が保証されます。 どのステップも無効なサイクルを導入しないため、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        m1 = int(input())
        for _ in range(m1):
            input()  # skip edges
        b = list(map(int, input().split()))
        m2 = int(input())
        for _ in range(m2):
            input()  # skip edges
        
        out1 = a.count(1)
        in1 = n - out1
        out2 = b.count(1)
        in2 = n - out2
        
        if out1 + out2 == n and in1 + in2 == n:
            print("YES")
        else:
            print("NO")

solve()
```このソリューションでは、最初にすべての頂点タイプを読み取り、エッジ リストは決定に無関係であるためスキップします。 有効なエッジ マッチングが存在するかどうかを判断するには、各グラフの出力頂点と入力頂点をカウントするだけで十分です。 等価性チェックにより、1 対 1 のペアリングが可能であることが保証され、暗黙的にサイクルの可分性が保持されます。
