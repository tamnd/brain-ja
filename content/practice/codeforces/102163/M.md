 ## 解決策
 ## 問題の理解

 各テスト ケースでは、(B_1^{P_1}) と (B_2^{P_2}) の形式の 2 つの給与を比較しています。 最初のペアは元の給与を表し、2 番目のペアは新しい給与を表します。 印刷する必要があります`Congrats`新しい給料が高くなったら、`HaHa`それが小さくなったとき、そして`Lazy`両方の給与がまったく同じ場合。 

基数と指数の値は両方とも (10^6) に達することがあります。 (B^P) を直接構築するのは現実的ではありません。 (2^{10^6}) の 10 進数は約 300,000 桁なので、通常の大きな整数のべき乗では、1 回の比較で数十万桁を操作する必要があります。 複数のテスト ケースと 3 秒の制限があるため、そのアプローチは私たちが望むものをはるかに超えています。 

有用な変換は次のとおりです

 [
 B^P = e^{P\ln B}。 
】

 指数関数は厳密に増加しているため、2 つの正の累乗を比較することは、それらの対数を比較することと同じです。 

[
 B_1^{P_1} < B_2^{P_2}
 \iff
 P_1\ln B_1 < P_2\ln B_2。 
】

 これにより、膨大な整数比較がいくつかの浮動小数点演算に変わります。 

対数を計算する前に分離する必要があるいくつかのエッジケースがあります。 底がゼロでその指数が正の場合、値はゼロになります。 例えば、```
1
0 5 2 3
```には給与 (0^5=0) と (2^3=8) があるため、答えは次のようになります。`Congrats`。 電話をかける`log(0)`無効になります。 

指数が 0 の場合、基数が正の場合は常に 1 の値が生成されます。 例えば、```
1
7 0 1 5
```(7^0=1) と (1^5=1) を比較するので、答えは次のようになります。`Lazy`。 ゼロの指数を式全体をゼロにするものとして扱う不注意な実装は間違っています。 

入力保証では各給与式の (0^0) が除外されるため、特別な数学的意味を割り当てる必要はありません。 たとえば、次のペア`(0, 0)`どちらの給与についても完全に説明することはできません。 

最後に、等しいべき乗でも異なる基数と指数を持つことができます。 例えば、```
1
2 4 4 2
```(2^4) と (4^2) を比較します。どちらも 16 に等しいです。基数または指数を個別に比較すると失敗しますが、(P\ln B) を比較すると等しいことが正しく識別されます。 

## アプローチ

 直接的なアプローチは、両方の累乗を計算して比較することです。 計算する値は正確に 2 つの給与であるため、数学的には簡単です。 問題はそのサイズです。 (B=10^6) と (P=10^6) の場合、結果の数値には、最も極端な大まかなスケールで約 (6\cdot10^6\log_{10}10) 桁が含まれ、さらに小さい例 (2^{10^6}) でさえ、すでに 300,000 桁を超えています。 このような整数の計算と保存は、整数の順序付けだけが必要な場合には不要な作業です。 最悪のケースでは、一定量の算術演算ではなく、テスト ケースごとに数十万または数百万の桁演算が必要になる可能性があります。 

重要な観察は、対数が正の数の順序を維持するということです。 (B^P) を評価する代わりに、その自然対数を計算します。 

[
 \ln(B^P)=P\ln B.
 】

 これで、どちらの給与も通常の浮動小数点数で表すことができ、その大きさは最大でも (10^6\ln(10^6)) 程度、およそ (1.4\cdot10^7) 程度になります。 比較はテスト ケースごとに一定時間になります。 

このブルートフォース手法は、累乗によって正確な給与が得られるため機能しますが、給与には膨大な桁数が含まれる可能性があるため失敗します。 対数観測により、それらを構築する必要がまったくなくなります。 この変換を通過できない唯一の値はゼロであるため、ゼロの基数は対数比較の前に個別に処理されます。 

浮動小数点演算では、2 つの対数値が数学的に等しい場合にも微妙な問題が発生します。 たとえば、(2^4) と (4^2) は両方とも次のようになります。`Lazy`ただし、浮動小数点の対数表現は、わずかな丸め誤差によって異なる場合があります。 したがって、十分に小さい差を同等として扱います。 公式スタイルのソリューションでは、この比較に小さな許容値を使用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (B^P) の桁数に応じて、テスト ケースごとに数十万桁の演算が行われる可能性があります。 潜在的に数十万桁 | 遅すぎる/実用的ではない |
 | 最適 | テスト ケースごとの (O(1)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (B_1,P_1,B_2,P_2) を読み取ります。 各ペアは 1 つの給与を表すため、最初のペアは古い給与、2 番目のペアは新しい給与です。 
2. いずれかの基数がゼロかどうかを確認します。 (0^0) は入力保証によって除外されるため、有効なゼロベース式には正の指数が必要です。 そんな給料はまさにゼロだ。 

両方のベースがゼロの場合、両方の給与もゼロとなり、答えは次のようになります。`Lazy`。 最初のベースのみがゼロの場合、古い給与はゼロですが、新しい給与はプラスになるため、答えは次のようになります。`Congrats`。 2 番目の基準のみがゼロの場合、新しい給与はゼロですが、古い給与はプラスになるため、答えは次のようになります。`HaHa`。 
3. 両方の塩基が正の場合、次のように計算します。 

[
 x_1=P_1\ln B_1、\qquad x_2=P_2\ln B_2。 
】

 これらは 2 つの給与の対数です。 指数が 0 の場合は当然 (x=0) となり、給与 1 に対応します。 
4. (x_1) と (x_2) を比較します。 それらの差がわずかな許容範囲内にある場合は、印刷します。`Lazy`差は浮動小数点の丸めで説明できるほど小さいためです。 
5. それ以外の場合、(x_1<x_2) の場合、新しい給与の方が大きいため、次のように出力します。`Congrats`。 (x_1>x_2) の場合、新しい給与は小さくなるため、次のように出力します。`HaHa`。 

アルゴリズムの背後にある不変条件は、ゼロのケースが削除された後はすべての給与がプラスになり、対数が厳密に増加するということです。 したがって、

 [
 P_2\ln B_2-P_1\ln B_1
 】

 まさに、新旧の給与の差を表しています。 許容誤差は、対数を表すために使用される有限精度のみを考慮します。 実際の給与値を構築する必要はありません。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

EPS = 1e-10

def solve_case(b1, p1, b2, p2):
    # A valid zero-base expression must have a positive exponent,
    # because 0^0 is excluded by the input guarantee.
    if b1 == 0 or b2 == 0:
        if b1 == b2:
            return "Lazy"
        if b1 == 0:
            return "Congrats"
        return "HaHa"

    # For positive bases:
    # log(B^P) = P * log(B)
    x1 = p1 * math.log(b1)
    x2 = p2 * math.log(b2)

    if abs(x1 - x2) <= EPS:
        return "Lazy"
    if x1 < x2:
        return "Congrats"
    return "HaHa"

def main():
    t = int(input())
    ans = []

    for _ in range(t):
        b1, p1, b2, p2 = map(int, input().split())
        ans.append(solve_case(b1, p1, b2, p2))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    main()
```の`solve_case`関数は最初にゼロベースを処理します。`math.log(0)`は未定義です。 問題の保証とは、基数が 0 の場合、対応する指数は正であるため、式は確実に 0 であることを意味します。 

両方の塩基がプラスになると、`math.log(b)`と定義されています。 それに指数を掛けると、対応する給与の対数が得られます。 これは、特別な分岐を行わずに指数ゼロも処理します。`p * log(b)`はゼロになります。これは正確に (\log(1)) です。 

比較には、`EPS`テストではなく`x1 == x2`。 浮動小数点対数は近似であるため、(2^4) や (4^2) などの数学的に等しい式では、最後の数ビットが異なる値が生成される可能性があります。 直接の等価性テストでは誤って出力される可能性があります`Congrats`または`HaHa`。 

整数には任意の精度があるため、Python には整数オーバーフローの問題はありませんが、いずれにしても、この解決策では巨大なべき乗が構築されません。 最大の中間対数値は (10^7) 程度にすぎず、これは Python 浮動小数点数で簡単に表現できます。

 ## 特殊なケース

 ゼロの底が対数計算に達することはありません。 のために```
1
0 5 2 3
```アルゴリズムが見る`b1 == 0`すぐに。 以来`b2`はゼロ以外です。最初の給与はゼロで、2 番目の給与はプラスです。 戻ります`Congrats`どちらの対数も評価せずに。 拠点を逆転させて、```
1
2 3 0 5
```新しい給与がゼロになるため、同じブランチが戻ります`HaHa`。 

指数がゼロの場合も、単純な実装では問題が発生する可能性があります。 のために```
1
7 0 1 5
```両方の底が正であるため、対数パスが使用されます。 最初の対数給与は

 [
 0\cdot\ln7=0、
 】

 そして2つ目は

 [
 5\cdot\ln1=0。 
】

 それらの差はゼロであるため、出力は次のようになります。`Lazy`、一致します (7^0=1^5=1)。 

異なるベースでも同じ給与を表すことができます。 のために```
1
2 4 4 2
```アルゴリズムが計算します

 [
 x_1=4\ln2
 】

 そして

 [
 x_2=2\ln4=2(2\ln2)=4\ln2。 
】

 2 つの浮動小数点値は四捨五入まで等しいため、許容誤差に基づく比較では次の結果が得られます。`Lazy`。 このため、基数または指数が一致するかどうかだけをチェックするだけでは不十分です。 

上限は、対数を使用する主な理由にもなります。 のために```
1
1000000 1000000 999999 1000000
```実際の給与は直接構築するには大きすぎます。 アルゴリズムは計算のみを行います

 [
 10^6\ln(10^6)
 】

 そして

 [
 10^6\ln(999999)、
 】

 これらは通常の浮動小数点値です。 前者が大きいため、新しい給与は小さくなり、生産高は小さくなります。`HaHa`。 

入力保証により、曖昧な (0^0) ケースが排除されます。 次のようなテスト```
1
0 0 2 3
```はこの問題に対して有効な入力ではないため、実装ではそれに対する規則を考案する必要はありません。 したがって、ゼロ処理は、すべてのゼロ基本給が正確にゼロであることに依存する可能性があります。
