 ## 解決策
 ## 問題の理解

 周期的に配置された時間 (N) があるため、時間 (N) の後に時間 (1) が来て、時間 (1) の前に時間 (N) が来ます。 各 (M) 人の生徒は 1 時間 (A_i) に開始し、(X_i) 時間ずつ時計を進めます。 正の値 (X_i) は時計回りに移動することを意味し、負の値は反時計回りに移動することを意味します。 開始時間と最終時間を含む中間時間ごとにアクセスされます。 公式の例はこの解釈を裏付けています。(N=5) の場合、(5) から開始し (X=2) の生徒が (5,1,2) を訪問します。そのため、時間 (2) は合計 3 回訪問されます。 

時間ごとに、その時間に移動経路を訪れる生徒の数が必要です。 答えは最大カウントの時間であり、複数の時間の最大カウントが同じ場合は、最小の時間を選択します。 

境界 (N,M\le 10^5) は、すべての生徒の長さ (O(N)) のパスを明示的にシミュレートするものを除外します。 最悪の場合、(10^5) 人の学生がいて、各移動 (10^5) ステップで、およそ (10^{10}) 回の個別訪問が発生する可能性があります。 2 秒の制限により、ほぼ一定時間または対数時間で各生徒を処理し、(N) 時間を 1 回スキャンする必要があります。 

直接的な実装が間違っている可能性がある境界ケースがいくつかあります。 まず、ムーブメントが時計を周回します。 例えば、```
1
3 2
1 3
1 1
```最初の生徒は (1,2) を訪問し、2 番目の生徒は (3,1) を訪問するので、答えは次のようになります。`1 2`。 時間を通常の配列として扱う実装では、2 番目の学生が時間 (1) を訪問することを見逃してしまいます。 

負の動きは反対方向にラップします。 例えば、```
1
5 1
1
-2
```パスは (1,5,4) なので、答えは次のようになります。`1 1`なぜなら、訪問されたすべての時間は 1 と数えられ、時間 (1) が最も小さいからです。 負の値が正の値と同じ間隔方向を使用して処理される場合、結果の範囲は間違ったものになります。 

値 (|X_i|=N) は、別の微妙なケースです。 例えば、```
1
4 1
2
4
```学生は (2,3,4,1,2) を訪問するため、時間 (2) は 2 回、1 時間おきに 1 回訪問されます。 「移動 (N) 時間の訪問を 1 時間ごとに 1 回行う」という単純なソリューションでは、開始時間までの追加の訪問が失われます。 

最後に、(X_i=0) は、開始時間自体が 1 回訪れたことを意味します。 のために```
1
3 1
2
0
```答えは`2 1`。 ゼロの移動を空の間隔として扱うと、誤ってゼロの訪問が生成されます。 

## アプローチ

 最も直接的な解決策は、すべての生徒の動きをシミュレートすることです。 生徒の時間 (A_i) から始めてその時間を数え、次に必要な方向に 1 時間ずつ移動し、正確に (|X_i|) 移動するまで新しい時間ごとに数えます。 すべての生徒を処理した後、周波数配列をスキャンしてその最大値を見つけます。 これは、すべての学生が訪問する時間の順序に正確に従っているため、これは正しいです。 

問題はシミュレートされた手の数です。 1 人の生徒は (N) 回移動できるため、最悪の場合は (O(MN)) 回の操作が必要になります。 (M=N=10^5) の場合、約 (10^{10}) 回のシミュレーション訪問となり、制限時間を大幅に超えます。 

重要な観察は、1 人の生徒の進路が常に連続した周期的な時間間隔であるということです。 その間隔内の時間を列挙する必要はありません。 代わりに、差分配列を使用して間隔全体に (1) を加算できます。 通常の間隔 ([L,R]) は、2 つの差分配列の更新により定数時間で追加できます。 循環間隔は ([1,N]) 内に留まるか、サフィックスとプレフィックスに分割されます。どちらも定数の更新で表すこともできます。 

(|X_i|=N) の場合、複雑な問題が 1 つあります。 パスには (N+1) 個の位置が含まれるため、完全に 1 周し、開始時刻を 2 回訪れます。 移動距離を完全な回路と残りの部分間隔に分解することで、これを均一に処理します。 (|X_i|\le N) なので、完全な回路は最大 1 つしか存在できません。 

すべての間隔更新が記録された後、1 つのプレフィックス合計パスによって時間ごとの訪問数が再構築されます。 時間 (1) から順にスキャンして、最大値を持つ最小の時間を選択します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(MN)) | (O(N)) | 遅すぎる |
 | 差分配列 | (O(N+M)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 差分配列を作成する`diff`長さは (N+1) です。 実際の訪問数は、後でプレフィックスの合計を取得することで取得されます。 範囲の増分は、その 2 つの境界のみを変更することで表現できます。 
2. 各生徒について、`d = abs(X_i)`。 距離を分割する`full = d // N`完全な回路と`rem = d % N`残りのステップ。 追加`full`実行することで毎時まで`diff[0] += full`そして`diff[N] -= full`。 これにより、個々の時間に影響を与えることなく、完全なサーキットによって寄与された訪問が処理されます。 
3. もし`rem = 0`、部分的な動きは残っていないので、次の生徒に進みます。 これにより、(X_i=0) と (X_i=\pm N) も正しく処理されます。 (X_i=\pm N) の場合、完全なサーキットは 1 時間ごとに 1 回の訪問に寄与しますが、開始時間はサーキットの最初の位置によってすでに 1 回含まれています。 
4. 開始時間をゼロから始まるインデックスに変換します。`a = A_i - 1`。 もし`X_i`が正の場合、残りのパスは時計回りに進みます。`a`に`(a + rem) % N`したがって、訪問間隔は、これら 2 つのエンドポイントからの周期間隔になります。 
5. もし`X_i`が負の場合、残りのパスは反時計回りに進みます。 その間隔は次から始まります`(a - rem) % N`そしてで終わります`a`。 この反転が、ポジティブな動きとネガティブな動きの主な違いです。 
6. 対応する周期間隔に 1 を加算します。 左の端点が右の端点より大きくない場合、それは通常の間隔であり、2 回の差分配列の変更が必要です。 左の端点の方が大きい場合、間隔は時間 (N) と時間 (1) の間の境界をまたぐため、配列の両端に 1 つずつ、合計 2 つの通常の間隔になります。 
7. すべての生徒の処理が完了したら、次のプレフィックスの合計を計算します。`diff`。 ゼロベースの位置での累計`i`は正確に時間当たりの訪問数です`i + 1`。 
8. これらのプレフィックスの合計を計算する際、最適な時間とその訪問数を維持します。 現在のカウントが厳密に最良のカウントよりも大きい場合にのみ、答えを更新してください。 スキャンは時間 (1) から時間 (N) まで行われるため、等しいカウントを変更しないままにすると、自動的に最小の時間が選択されます。 

### なぜ効果があるのか

 不変条件は、生徒の接頭語を処理した後、差分配列がそれらの生徒の時間ごとの貢献度の合計を正確に表すということです。 完全な回路は毎時同じ量を寄与しますが、残りの動きは 1 つの連続する周期的な間隔を訪れます。間隔更新操作はそれを正確に表します。 プレフィックスの合計を取得すると、これらの境界の変化が実際の訪問数に変換されます。 したがって、すべての学生が処理された後、時間ごとに正確な合計訪問数が得られ、左から右へのスキャンによって最大数が選択され、同数の中で最小の時間が選択されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def add_interval(diff, n, left, right, value=1):
    if left <= right:
        diff[left] += value
        diff[right + 1] -= value
    else:
        diff[left] += value
        diff[n] -= value

        diff[0] += value
        diff[right + 1] -= value

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        x = list(map(int, input().split()))

        diff = [0] * (n + 1)

        for start, move in zip(a, x):
            pos = start - 1
            distance = abs(move)

            full = distance // n
            rem = distance % n

            if full:
                diff[0] += full
                diff[n] -= full

            if rem == 0:
                continue

            if move > 0:
                left = pos
                right = (pos + rem) % n
            else:
                left = (pos - rem) % n
                right = pos

            add_interval(diff, n, left, right)

        current = 0
        best_hour = 1
        best_count = -1

        for i in range(n):
            current += diff[i]

            if current > best_count:
                best_count = current
                best_hour = i + 1

        out.append(f"{best_hour} {best_count}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`diff`範囲はゼロから始まるインデックスで終わるため、配列には 1 つの余分な位置があります`r`を追加することで表されます`diff[r + 1]`。 この追加スロットは、間隔が時間 (N) に達した場合にも便利です。 

の`full`そして`rem`分解は、許可されたすべての移動距離を処理します。 たとえば、次のようなとき`move = N`、`full`は 1 つであり、`rem`はゼロなので、1 時間ごとに 1 回の訪問が発生します。 開始時間は、完全なムーブメントの最終位置としても再び訪れます。これは、開始位置が完全な回路自体に含まれることによって表されます。 より正確には、(N+1) 個の位置は開始位置と (N) 個の移動で構成されるため、開始は 2 回カウントされ、開始点からの完全な周期間隔への分解には、循環トラバーサルを通じて繰り返される開始が含まれます。 

のために`rem > 0`、`left`そして`right`両方のエンドポイントを含む、残りのポジションの完全なセットを記述します。 正の動きの場合、間隔は開始位置から時計回りに進みます。 負の動きの場合、間隔は最終位置から反時計回りに開始位置に戻ります。 

ヘルパーさん`add_interval`通常の間隔とラッピング間隔の両方を処理します。 いつ`left <= right`、間隔は標準の配列範囲です。 いつ`left > right`、周期間隔は次のように構成されます。`[left, N-1]`そして`[0, right]`, したがって、この関数はパーツごとに 1 つの差分更新を実行します。 

Python の整数はオーバーフローせず、最大訪問数は 1 つの完全な走査パターンで 1 時間あたり最大 (M+1) であるため、通常の整数演算で十分です。

 ## 特殊なケース

 最初のエッジ ケースは、正方向の循環ラッピングです。 考慮する：```
1
5 1
4
2
```学生は (4,5,1) を訪問します。 内部的には、ゼロベースの開始は次のとおりです。`3`、残りのエンドポイントは`(3 + 2) % 5 = 0`、したがって、間隔は`[3,0]`。 左端の方が大きいので、`add_interval`それを分割します`[3,4]`そして`[0,0]`。 カウントは (1,0,0,1,1) となり、最小の最大時間は (1) になります。`1 1`。 

2 番目のエッジ ケースは反時計回りにラッピングされます。```
1
5 1
1
-2
```パスは (1,5,4) です。 ゼロベーススタートは`0`、残りのエンドポイントは`(0 - 2) % 5 = 3`。 このアルゴリズムは、次の周期間隔を処理します。`3`に`0`として`[3,4]`プラス`[0,0]`。 ちょうど 4、5、1 時間で 1 回の訪問を受け、`1 1`。 

3 番目のエッジ ケースは完全な回路です。```
1
4 1
2
4
```ここ`distance = 4`、 それで`full = 1`そして`rem = 0`。 完全なサーキットでは 1 時間ごとに 1 回の訪問が行われ、4 回移動した後に再び開始位置に到達します。 結果のカウントは (1,2,1,1) となるため、答えは次のようになります。`2 2`。 このため、完全な回路を考慮せずに単に (X) を (X\bmod N) に置き換えることは正しくありません。 

4 番目のエッジ ケースは、動きがゼロです。```
1
3 1
2
0
```距離はゼロであるため、ループは範囲の更新を実行しません。 最初は、学生が何も貢献していないように見えるかもしれませんが、初期位置自体がカウントされる必要があります。 長さゼロの移動は概念的には開始時間を正確に含む間隔であるため、差分配列表現はこれを処理します。 上記の実装では、これは、パスの完全な訪問解釈によって処理されます。`rem = 0`; ゼロ動作には完全な回路がないため、開始時間を明示的に表す必要があります。 あいまいさを避けるために、実装では次のように処理する必要があります。`move == 0`1 時間間隔として。 

その特定のブランチの修正された実装は次のとおりです。```
if distance == 0:
    diff[pos] += 1
    diff[pos + 1] -= 1
    continue
```この補正により、動きゼロの場合は次のようになります。`2 1`まさに要求どおりに。 

5 番目のエッジケースはタイブレークです。 のために```
1
4 2
1 3
0 0
```時間 (1) と (3) には両方とも 1 回の訪問がありますが、時間 (2) と (4) には訪問がありません。 プレフィックスサム スキャン中に、時間 (1) が現在の最良値になります。 時間 (3) も 1 に達すると、厳密に比較されます。`>`、 ない`>=`、したがって、保存された回答は時間 (1) のままになります。 結果は`1 1`。 

ゼロ動き補正は、上記の完全なソリューションにも適用する必要があります。 したがって、最終的な実装は次のようになります。```python
import sys
input = sys.stdin.readline

def add_interval(diff, n, left, right, value=1):
    if left <= right:
        diff[left] += value
        diff[right + 1] -= value
    else:
        diff[left] += value
        diff[n] -= value
        diff[0] += value
        diff[right + 1] -= value

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        x = list(map(int, input().split()))

        diff = [0] * (n + 1)

        for start, move in zip(a, x):
            pos = start - 1
            distance = abs(move)

            if distance == 0:
                diff[pos] += 1
                diff[pos + 1] -= 1
                continue

            full = distance // n
            rem = distance % n

            if full:
                diff[0] += full
                diff[n] -= full

            if rem == 0:
                diff[pos] += 1
                diff[pos + 1] -= 1
                continue

            if move > 0:
                left = pos
                right = (pos + rem) % n
            else:
                left = (pos - rem) % n
                right = pos

            add_interval(diff, n, left, right)

        current = 0
        best_hour = 1
        best_count = -1

        for i in range(n):
            current += diff[i]
            if current > best_count:
                best_count = current
                best_hour = i + 1

        out.append(f"{best_hour} {best_count}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```パスには常に開始時間が含まれるため、明示的なゼロ移動分岐が必要です。 (N) に等しいゼロ以外の移動の場合、全回路更新により 1 時間ごとに 1 回の訪問がすでに与えられていますが、最終位置が初期位置と等しいため、開始時間にはさらに 1 回の訪問が必要です。 最もクリーンな実装は、次の場合に追加の開始時間の訪問を追加することです。`rem == 0`そして`distance > 0`、上に示したように。
