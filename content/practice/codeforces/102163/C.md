 ## 解決策
 ## 問題の理解

 各テスト ケースには、(N) 個の整数の配列があります。 サブシーケンスは元の左から右の順序を維持しますが、任意の数の要素をスキップできます。 選択されたすべての値が以前に選択された値よりも厳密に大きい場合にのみ増加します。 

このタスクには 2 つの部分があります。 増加するサブシーケンスの可能な最大長が必要であり、その最大長に達する異なるサブシーケンスの数もカウントする必要があります。 2 つのサブシーケンスは、選択した値がたまたま同じであっても、配列内の異なる位置を選択すると異なります。 カウントはモジュロ (10^9+7) で出力されます。 

たとえば、```
1 2 1 4 3
```最大長は (3) です。 位置 (1,2,4) と (1,2,5) を使用するサブシーケンスは (1,2,4) と (1,2,3) を与えるため、LIS は 2 つあります。 

配列の長さは最大 (1000) であるため、(O(N^2)) 動的プログラミング ソリューションが実用的になります。 (O(N^3)) ソリューションは、(N=1000) のときにすでに約 (10^9) 個の演算を実行しますが、これは 4 秒の制限には多すぎます。 長さ (N) の配列には (2^N) 個の可能な位置サブセットがあるため、サブシーケンスの列挙は指数関数的に悪化します。 

値 (A_i) は (10^6) まで大きくすることができますが、動的プログラミング遷移では 2 つの値を比較するだけであるため、座標圧縮や特別なデータ構造は必要ありません。 重要な違いは厳密な不等号であるため、等しい値が増加する部分列を拡張してはなりません。 

いくつかの小さなケースでは、よくある間違いが明らかになります。 と```
1
1
7
```答えは```
1 1
```単一の要素自体が唯一の LIS であるためです。 ウェイの数をゼロに初期化する実装では、この基本ケースが失われます。 

と```
1
3
5 5 5
```答えは```
1 3
```各位置が独立して長さ 1 の LIS を形成するためです。 比較を (A_j \le A_i) として扱うと、誤って長いサブシーケンスが生成されます。 

と```
1
3
1 2 3
```答えは```
3 1
```なぜなら、3 つの位置すべてを選択する方法が 1 つだけあるからです。 結果の長さが現在の位置にとって最適な長さであるかどうかを確認せずに、すべての先行者からのカウントを合計する不用意な実装は、カウントをオーバーする可能性があります。 

最後に、カウント自体が非常に大きくなる可能性があります。 たとえば、多くの繰り返し構造を含む配列には多数の LIS が含まれる可能性があるため、動的プログラミングの移行中にカウントをモジュロ (10^9+7) で減らす必要があります。 

## アプローチ

 最も直接的な解決策は、配列のすべてのサブシーケンスを列挙し、それが厳密に増加しているかどうかを確認し、最も長いものを保持することです。 正確に (2^N) 個の位置サブセットが存在します。 各サブセットについて最大 (N) 個の位置を検査すると、最悪の場合の作業は (O(N2^N)) になります。 (N=1000) の場合、これは完全に不可能です。 

よりローカルな質問をすることで、より良い結果を得ることができます。 考えられるすべてのサブシーケンスを構築する代わりに、最終的に選択された位置が (i) である LIS を考えてみましょう。 (i) より前のすべては、それ自体、ある位置 (j<i) で終了する (A_j<A_i) の増加するサブシーケンスでなければなりません。 これは、(i) で終了するすべての有効なサブシーケンスは、それより前の位置で終了する有効なサブシーケンスを拡張することによって構築できることを意味します。 

すべての位置 (i) について、2 つの値を維持します。 1 つ目は、正確に (i) で終わる最長の増加サブシーケンスの長さです。 2 番目は、そのような最長のサブシーケンスの数です。 

(j<i) かつ (A_j<A_i) であるとします。 (j) で終わる最適なサブシーケンスの長さが (L) である場合、(A_i) を追加すると長さ (L+1) のサブシーケンスが作成されます。 これが (i) で以前に見つかったものよりも優れている場合は、長さを置き換えて (j) からウェイの数をコピーします。 現在の最適な長さに同点の場合は、(j) からウェイの数を追加します。 

ブルートフォースソリューションは、すべてのサブシーケンスが明示的に考慮されるため機能しますが、その数が指数関数的に多いため失敗します。 (i) で終わるすべての LIS が以前に選択された一意の位置を持っているという観察により、位置ごとに 2 つの値を使用して以前のすべての可能性を要約できます。 (N) は (1000) のみであるため、すべてのペア (j<i) をチェックすると、(O(N^2)) 個の動的プログラムが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N2^N)) | (O(N)) | 遅すぎる |
 | 最適なDP | (O(N^2)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を左から右に処理します。 すべての位置 (i) について、初期化します。`length[i] = 1`そして`count[i] = 1`。 単一の要素は常に長さ 1 の増加するサブシーケンスを形成するため、これらは正しい基本値です。 
2. 各位置 (i) について、以前のすべての位置 (j<i) を検査します。 サブシーケンスは厳密に増加する必要があるため、(A_j<A_i) を満たす位置のみが (i) の前に置くことができます。 
3. すべての有効な先行処理 (j) について、その最良のサブシーケンスを拡張して得られる長さを計算します。 

[
 候補 = 長さ[j] + 1。 
】

 もし`candidate`より大きい`length[i]`、 交換する`length[i]`それとセット`count[i]`に`count[j]`。 (i) で終わる既知の短いサブシーケンスはすべて、この位置を通って全体的に最長になることはないため、破棄できます。 

1. もし`candidate`等しい`length[i]`、 追加`count[j]`に`count[i]`。 これらは、(i) で終わる同じ最適な長さを持つ異なるサブシーケンスの新しいグループを表します。 和の剰余 (10^9+7) を計算します。 
2. すべての位置を処理した後、次の値の最大値を見つけます。`length`。 これはグローバル LIS の長さです。 
3.合計`count[i]`あらゆるポジションにわたって、`length[i]`グローバル最大値に等しい。 すべての LIS には最終ポジションが 1 つだけあるため、これによりすべての LIS が 1 回だけ合計されます。 再度、結果のモジュロ (10^9+7) を取得します。 

### なぜ効果があるのか

 不変条件は、位置 (i) を処理した後、`length[i]`は、(i) で終わる増加するサブシーケンスの正確な最大長です。`count[i]`は、正確にその長さを達成するサブシーケンスの数です。 

(i) で終了する増加するサブシーケンスは、(A_i) のみで構成されるか、(A_j<A_i) を持つ最後の先行部分 (j<i) を持ちます。 2 番目の場合、そのプレフィックスは (j) で終わる増加するサブシーケンスでなければなりません。 遷移では、可能なすべての先行処理が考慮されるため、最適なサブシーケンスが (i) に到達できるあらゆる可能な方法が考慮されます。 より長い長さが見つかった場合、その長いファミリーのみが最適な状態を維持できます。 等しい長さが見つかった場合は、その異なるサブシーケンスをすべて追加する必要があります。 

最終的に、各 LIS の最終ポジションは 1 つだけです。 最大値を持つポジションのカウントを合計する`length`したがって、すべての LIS を 1 回だけカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def main():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        length = [1] * n
        count = [1] * n

        for i in range(n):
            for j in range(i):
                if a[j] >= a[i]:
                    continue

                candidate = length[j] + 1

                if candidate > length[i]:
                    length[i] = candidate
                    count[i] = count[j]
                elif candidate == length[i]:
                    count[i] += count[j]
                    count[i] %= MOD

        best_length = max(length)

        total_count = 0
        for i in range(n):
            if length[i] == best_length:
                total_count += count[i]
                total_count %= MOD

        print(best_length, total_count)

if __name__ == "__main__":
    main()
```2 つの配列は動的プログラミング状態の中核です。`length[i]`位置で終了する最適なサブシーケンスを記述します`i`、 そして`count[i]`正確な長さを実現する方法が何通りあるのかを説明します。 

内側のループは、以前のすべての位置を検査します。 条件`a[j] >= a[i]`等しい値と減少する遷移を拒否し、問題で必要とされる厳密な不等式を正確に残します。 

厳密に優れた前任者が見つかった場合、`count[i]`追加するのではなく、置き換える必要があります。 (i) で終わる短いサブシーケンスは、(i) で終わる LIS に寄与できません。 候補が現在の最適長と同点の場合、両方の先行選択によって異なる位置サブシーケンスが生成されるため、カウントが追加されます。 

すべてのカウントは剰余 (10^9+7) で減算されます。 Python の整数はオーバーフローしませんが、モジュラスを取得すると値が小さく保たれ、必要な出力規則が直接実装されます。 

LIS は任意の位置で終了できるため、最終ループが必要です。 摂取のみ`count[n - 1]`たとえば、最後の配列要素がすべての LIS に属している場合にのみ正しくなります。 

遷移内のインデックスは次の条件を満たします`j < i`, したがって、配列の元の順序は自動的に保存されます。 ソートするとサブシーケンスの順序付け制約が破壊されるため、ソートは実行されません。

位置 (5) の状態は、カウントの遷移を示しています。 両方`1, 5, 4`(5>4) であるため無効ですが、`1, 2, 4`および他の有効な先行構造は独立して考慮されます。 DP は、厳密な比較を満たす先行データのみを保持し、等しい最適な長さに集約します。
