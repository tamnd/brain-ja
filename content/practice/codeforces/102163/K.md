 ## 問題の理解

 配列があります`A`一定の列に並んでいる生徒たちの皿に置かれたピザのスライスを表しています。 マサウドはこの配列の連続するセグメントを 1 つ選択する必要があります。つまり、左側のエンドポイントを選択することになります。`l`そして右端点`r`、すべてのスライスを盗みます`A[l..r]`。 合計が厳密に次の値より小さい異なる連続セグメントがいくつあるかを数える必要があります。`X`。 

「厳密に」という言葉が重要です。 合計が正確に一致するセグメント`X`は無効です。 以来、`A[i]`が正の場合、セグメントを拡張してもその合計は増加するだけです。 この単調性は、線形時間解を可能にする特性です。 

と`N`と同じくらい大きい`10^5`、エンドポイントのすべてのペアをチェックすることはすでにコストがかかりすぎます。 がある`N(N+1)/2`連続したセグメント、つまり約`5 * 10^9`いつ`N = 10^5`。 すべてのセグメントを個別に検査するソリューションでは、1 秒の制限時間に収まりません。 に近いアルゴリズムが必要です`O(N)`テストケースごとに。 の値`A[i]`そして`X`到達できる`10^9`、その答えは周囲にある可能性があります`5 * 10^9`したがって、実装には 32 ビット整数より大きい値を格納できる整数型も必要です。 Python の整数はこれを自然に処理します。 

よくある境界の間違いは、合計を以下と等しいものとして扱うことです。`X`有効として。 たとえば、`N = 1`、`X = 4`、 そして`A = [4]`、唯一のセグメントに合計があります`4`、したがって、答えは次のとおりです`0`、 ない`1`。 条件は`sum < X`、 ない`sum <= X`。 

もう 1 つの間違いは、単一の要素によってすでにウィンドウが無効になる可能性があることを忘れていることです。 のために`N = 2`、`X = 3`、 そして`A = [5, 1]`、 どちらでもない`[5]`または`[5, 1]`は有効ですが、`[1]`は有効なので、答えは`1`。 スライディング ウィンドウの実装では、現在の合計が再び有効になるまで、左端点を繰り返し移動する必要があります。 

3 番目の問題は、答えが 32 ビット整数に収まると仮定することです。 と`N = 100000`、`X = 100001`、そしてすべての`A[i] = 1`、空ではないすべての連続セグメントが有効です。 答えは`100000 * 100001 / 2 = 5,000,050,000`よりも大きい`2^32`これよりわずかに下回っていますが、すでに符号付き 32 ビットの範囲をはるかに超えています。 

## アプローチ

 直接的な解決策は、考えられるエンドポイントのペアをすべて列挙することです。 スタートポジションごとに`l`、延長できます`r`から`l`を通して`N - 1`、現在の合計を維持し、その合計が以下になるたびに答えを増分します。`X`。 これは正しいです。空ではないすべての連続セグメントには 1 組のエンドポイントがあるため、すべての有効なセグメントは 1 回カウントされるからです。 

ゼロから再計算するのではなく、現在の合計を維持したとしても、`N(N+1)/2`エンドポイントのペア。 のために`N = 10^5`、つまり`5,000,050,000`最悪の場合はセグメントチェックを行います。 これは 1 秒の制限をはるかに超えています。 

ブルートフォース手法は、すべての候補セグメントを明示的に検査するため機能します。 候補者が多すぎるため失敗します。 重要な観察は、すべての配列値が正であるということです。 現在のウィンドウの合計が次の値より小さいと仮定します。`X`。 右の端点を拡張すると、合計は増加するだけです。 逆に、ウィンドウが大きくなりすぎる場合、ウィンドウの左端を右に移動しても合計は減少するだけです。 

つまり、適切なエンドポイントごとに 1 つの有効なスライディング ウィンドウを維持できるということです。 固定右エンドポイントの場合`r`、 させて`l`次のような最小の左端点になります。`A[l..r]`合計が以下です`X`。 すべての値が正であるため、すべてのセグメントは次で終わります。`r`そしてどこからでも始めてください`l`を通して`r`も有効です。 まさにあります`r - l + 1`そのようなセグメント。 

この最小の有効な値を見つけることができます`l`現在の合計が少なくとも`X`。 各要素はウィンドウに 1 回入り、ウィンドウから出るのは最大 1 回であるため、ポインターの移動の合計数は線形です。

 ## アルゴリズムのチュートリアル

 1. 両方のポインターを配列の先頭から開始します。`left = 0`、そして保管してください`current_sum = 0`そして`answer = 0`。 
2.移動`right`から`0`に`N - 1`。 追加`A[right]`に`current_sum`新しい右端点は、この要素が現在のウィンドウに属することを意味するためです。 
3. その間`current_sum >= X`、 動く`left`前進と減算`A[left]`から`current_sum`増加する前に`left`。 合計を厳密に より小さくするには 1 回の削除では十分ではない可能性があるため、ループが必要です。`X`。 
4. ループが終了すると、現在のウィンドウが`A[left..right]`合計が以下です`X`。 すべての要素が正であるため、すべてのセグメントは次で終わります。`right`左の端点が次の間にあるのは`left`そして`right`合計が以下の場合もあります`X`。 
5.追加`right - left + 1`に`answer`。 これにより、現在位置で終了する有効なセグメントが正確にカウントされます。 
6. 考えられるすべての正しいエンドポイントが処理されるまで繰り返し、出力します。`answer`。 

### なぜ効果があるのか

 反復するたびに、`left`現在のウィンドウの最小インデックスです。`A[left..right]`合計が厳密に小さい`X`。 で終わるセグメント`right`そしてその前から始める`left`現在の有効なウィンドウと少なくとも 1 つの追加の正の要素が含まれるため、その合計は少なくとも`X`そしてそれは有効ではありません。 から始まるすべてのセグメント`left`以降は有効なウィンドウのサブセグメントであるため、正の合計がさらに小さいか等しいため、有効です。 したがって、まさに`right - left + 1`有効なセグメントは次で終わります`right`。 

なぜなら`right`ただ前に進むだけで、`left`また、前方にのみ移動するため、スライディング ウィンドウに複数回追加または削除される要素はありません。 したがって、アルゴリズムは配列全体を線形時間で処理します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))

        left = 0
        current_sum = 0
        answer = 0

        for right in range(n):
            current_sum += a[right]

            while current_sum >= x:
                current_sum -= a[left]
                left += 1

            answer += right - left + 1

        print(answer)

if __name__ == "__main__":
    solve()
```入力はテスト ケースごとに 1 回読み取られ、ウィンドウが大きくなりすぎたときに左ポインターで要素を減算できるように配列が保存されます。 メイン ループは、アルゴリズムの右ポインター ステップに直接対応します。 

の`while current_sum >= x`状態の使用`>=`、 それよりも`>`、合計は次と正確に等しいため、`X`は無効です。 ループの後、不変式は次のようになります。`current_sum < x`。 

表現`right - left + 1`で終了する有効なセグメントの可能な開始位置をカウントします。`right`。 両方のエンドポイントが包括的であるため、`+1`必要です。 たとえば、次の場合`left == right`、セグメントは 1 つだけ、つまり 1 つの要素が存在します。`right`。 

Python の整数型は、答えが数十億に達した場合のオーバーフローを回避します。 固定幅の整数型を使用する言語では、答えは 64 ビット整数で格納される必要があります。

 ## 特殊なケース

 セグメント合計が正確に一致する場合`X`、それは除外する必要があります。 考慮する`N = 1`、`X = 4`、 そして`A = [4]`。 アルゴリズムは追加します`4`、それがわかります`current_sum >= X`、削除します`A[0]`、そして進みます`left`に`1`。 現在のウィンドウは空なので、`right - left + 1 = 0`。 出力は`0`、厳密な不等式を正しく処理します。 

1つの要素がそれよりも大きい場合`X`、アルゴリズムが移動する可能性があります`left`現在を超えて`right`。 のために`N = 3`、`X = 4`、 そして`A = [1, 5, 1]`、加工後`1`答えは`1`。 追加後`5`、合計は`6`, したがって、アルゴリズムは以下を削除します`1`、出発`5`、その後削除します`5`、空のウィンドウを残します`left = 2`。 インデックスで終わるセグメントがありません`1`有効です。 最後を追加した後、`1`の場合、ウィンドウにはその要素のみが含まれるため、さらに 1 つのセグメントがカウントされます。 最終的な答えは、`2`、に対応`[1]`それぞれの端に。 

大きな答えは、32 ビット整数を使用する実装を静かに破壊する可能性がある別のケースです。 と`100000`要素はすべて等しい`1`そして`X = 100001`、可能な最大セグメント合計は次のとおりです。`100000`したがって、空でないすべてのセグメントは有効です。 アルゴリズムは追加します`1 + 2 + ... + 100000`、取得`5,000,050,000`。 Python はこの値をオーバーフローせずに保存し、最大スケールでもカウント式が正しいことをテストで確認します。 

最後に、すべての要素が正の場合、スライディング ウィンドウの単調性が保証されます。 たとえば、`A = [2,2,2,2]`そして`X = 10`、各セグメントには以下の合計があります`10`、 それで`left`決して動かない。 右の各エンドポイントで、アルゴリズムは次の値を追加します。`1`、 それから`2`、 それから`3`、 それから`4`、与える`10`有効なセグメントの合計数。 これは、核となる不変条件を示しています。つまり、ウィンドウが有効になると、正の要素を削除しても合計を増やすことができないため、そのウィンドウのすべてのサフィックスも有効になります。
