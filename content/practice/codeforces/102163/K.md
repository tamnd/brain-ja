 ## 解決策
 ## 問題の理解

 ピザの数の配列があります。`A[i]`のスライスの数です。`i`- 番目の生徒のプレート。 マサウドは、この配列の空ではない連続セグメント、つまり連続する生徒のグループを選択する必要があり、選択した値の合計は厳密に次の値よりも小さくなければなりません。`X`。 

タスクは、合計が以下の連続する部分配列をすべてカウントすることです。`X`。 異なる位置では異なるグループが定義されるため、異なる位置で同じ値であっても異なる選択肢を表します。 

この制約は、すべてのサブ配列を直接チェックすることを除外するのに十分な大きさです。 と`N = 10^5`、 がある`N(N+1)/2`、または約`5 * 10^9`、最悪の場合、連続するグループが発生する可能性があります。 O(N²) アルゴリズムでさえ、1 秒の制限時間で処理できる範囲をはるかに超えています。 配列内の正の値は、問題を線形時間で解決できるようにする重要な構造特性です。 

不注意な実装が露呈する可能性のある境界ケースがいくつかあります。 まず、条件は厳密に言うと、`< X`、 ない`<= X`。 たとえば、`N = 1`、`X = 4`、 そして`A = [4]`、正しい出力は次のとおりです。`0`、唯一の部分配列が正確に合計を持っているため`4`。 を使用した実装`sum <= X`間違って数えてしまうでしょう。 

2 番目のケースは、すべての要素がすでに大きすぎる場合です。 のために`N = 3`、`X = 5`、 そして`A = [5, 6, 7]`、答えは`0`。 スライディング ウィンドウの実装では、現在の合計が以下になるまで要素を削除する必要があります。`X`何かを数える前に。 

3 番目のケースは、配列全体が有効な場合です。 のために`N = 3`、`X = 10`、 そして`A = [1, 2, 3]`、空ではないすべての部分配列には以下の合計があります`10`、したがって、答えは次のとおりです`6`。 カウントには、単一の要素だけでなく、あらゆる長さのサブ配列を含める必要があります。 

最後に、答え自体は、`N`。 と`N = 10^5`そして十分に大きい`X`、すべての部分配列が有効であるため、`10^5 * 100001 / 2 = 5,000,050,000`有効なグループ。 Python の整数はこれを自然に処理しますが、32 ビット整数を使用する言語ではオーバーフローが発生します。 

## アプローチ

 直接的なアプローチは、すべての可能な開始位置とすべての可能な終了位置を列挙し、その部分配列の合計を計算し、合計が以下になるたびに答えをインクリメントすることです。`X`。 がある`N(N+1)/2`サブアレイ。 それぞれの合計が右端点を拡張し 1 つの要素を追加することによって計算される場合、合計作業量は O(N²) になります。`5 * 10^9`反復のとき`N = 10^5`。 プレフィックスの合計により、個々の部分配列の合計は O(1) になりますが、エンドポイントのペアは依然として O(N²) 個あるため、全体の複雑さは 2 次のままです。 

すべての連続グループが 1 回だけ考慮されるため、総当り方式が機能します。 問題は、すでに調べられたグループから妥当性が推測できるグループを検討するのに時間がかかることです。 

重要な観察は、すべての`A[i]`はポジティブです。 正しいエンドポイントを修正するとします`r`で終わるサブ配列を検討します`r`。 左の端点をさらに左に移動すると、それらの合計は増加するだけです。 特定の左端点が少なくとも次の合計を生成すると、`X`、すべての以前の左側のエンドポイントも少なくとも合計を生成します`X`。 

この単調な動作により、2 ポインターのスライディング ウィンドウが可能になります。 窓を維持する`[left, right]`その合計が厳密に以下である`X`。 いつ`right`進むと、新しい要素によって合計が増加します。 合計額が以上の場合`X`、 動く`left`ウィンドウが再び有効になるまで、削除された値を転送および減算します。 

一度`[left, right]`は有効で、すべてのサブ配列は次で終わります。`right`そしてどこからでも始めてください`left`を通して`right`も有効です。 まさにあります`right - left + 1`このような部分配列。 この数値を追加すると、明示的に列挙することなく、現在の位置で終わるすべての有効なグループがカウントされます。 

アレイの積極性が動きを生み出す`left`安全。 要素を削除すると合計は減少するだけであり、右のエンドポイントを拡張すると合計は増加するだけです。 負の値が許可されると、この単調な関係がなくなり、同じスライディング ウィンドウ引数は無効になります。

 | 最適なスライディングウィンドウ | O(N) | O(1) 補助スペース | 承認済み |

 ## アルゴリズムのチュートリアル

 1.セット`left = 0`、`current_sum = 0`、 そして`answer = 0`。 ポインタ`left`は、現在の右端点で終わる有効な部分配列を生成できる最小の開始位置を表します。 
2.移動`right`から`0`を通して`N - 1`。 追加`A[right]`に`current_sum`、現在のウィンドウが新入生を含めるように拡張されたばかりであるためです。 
3. その間`current_sum >= X`、 取り除く`A[left]`から`current_sum`そして増加します`left`。 ウィンドウは厳密に以下よりも小さくなければなりません`X`なので、以下と等価です`X`も無効です。 すべての配列値が正であるため、移動します。`left`forward は合計を減らすことしかできないため、最終的には 1 つの要素さえも削除されない限り、ウィンドウは有効になります。`A[right]`少なくとも`X`。 
4. ループ後、`[left, right]`合計が厳密に小さい`X`。 すべての開始位置から`left`を通して`right`で終わる別の有効な部分配列を与える`right`。 したがって、追加します`right - left + 1`に`answer`。 
5. 可能なすべての正しいエンドポイントが処理されるまで繰り返します。 印刷する`answer`テストケース用。 

### なぜ効果があるのか

 不変条件は、縮小フェーズの後、`current_sum`の合計です`[left, right]`厳密に以下です`X`, 一方、すべてのサブ配列は で終わります。`right`開始位置が前である`left`少なくとも和がある`X`。 

いつ`right`が固定されている場合、左から要素を削除すると、すべての値が正になるため、合計が小さくなります。 したがって、最初の有効な`left`すべての可能な開始位置を 2 つのグループに分類します。`0`を通して`left - 1`は無効ですが、からの位置は`left`を通して`right`有効です。 まさにあります`right - left + 1`有効な選択肢なので、答えに加算される金額は正確です。 

各ポインターは前方にのみ移動します。 右ポインタが動きます`N`内側のループは多くの操作を実行しているように見えますが、`left`せいぜい動く`N`テストケース全体で 3 回。 これにより、線形の合計仕事量が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))

        left = 0
        current_sum = 0
        answer = 0

        for right in range(n):
            current_sum += a[right]

            while current_sum >= x and left <= right:
                current_sum -= a[left]
                left += 1

            answer += right - left + 1

        print(answer)

if __name__ == "__main__":
    solve()
```入力セクションはテスト ケースの数を読み取り、次に各ケースの配列を読み取ります。 左ポインタは以前に追加された値を減算する必要がある場合があるため、配列を保存すると便利です。 

メインループは以下を追加してウィンドウを拡張します。`a[right]`。 の`while`状態の用途`>= x`、 それよりも`> x`、必要な条件が厳密に以下であるため、`X`。 

新しく追加された要素自体が少なくとも`X`、縮小ループは最終的にその要素も削除します。 その後`left`になる`right + 1`、`current_sum`ゼロになり、`right - left + 1`はゼロです。 これにより、その位置で終わる有効なサブ配列が正しくカウントされなくなります。 

答えは、ウィンドウが有効になった後にのみ更新されます。 表現`right - left + 1`有効な範囲内のすべての可能な開始位置をカウントします`[left, right]`。 

Python の整数には任意の精度があるため、答えは 32 ビット整数の範囲を安全に超えることができます。 実際、`N = 10^5`、最大の答えは`5,000,050,000`。 

操作の順序も重要です。 まず新しい正しいエンドポイントを追加し、次に厳密な不等式が満たされるまで縮小し、その後でのみ有効な開始をカウントします。 縮小する前にカウントすると、無効な部分配列が含まれる可能性があります。

## 特殊なケース

 厳密な不等式の場合については、次のことを考慮してください。```
1
1 4
4
```アルゴリズムは追加します`4`、それがわかります`current_sum >= X`、唯一の要素を削除します。 結果のウィンドウは空なので、`right - left + 1 = 0`。 出力は`0`、必要に応じて正確に。 を使用した実装`while current_sum > X`この部分配列を誤ってカウントしてしまいます。 

すべての要素が無効な場合については、次のことを考慮してください。```
1
3 5
5 6 7
```で`right = 0`、合計は`5`, したがって、要素は削除され、寄与はゼロになります。 で`right = 1`、同じことが起こります`6`、そして`right = 2`それは起こる`7`。 最終的な答えは、`0`。 この問題では空ではないグループが求められており、寄与率 0 によって正しく除外されるため、空のウィンドウは有効な内部状態です。 

すべての部分配列が有効な場合については、次のことを考慮してください。```
1
3 10
1 2 3
```ウィンドウを縮小する必要はありません。 3 つの正しいエンドポイントで、アルゴリズムは貢献します。`1`、`2`、 そして`3`、生産`6`。 これらの寄与は、それぞれの位置で終わるすべてのサブ配列に対応します。 

大きな答えの場合、次の配列を考慮します。`100000`あるもの`X = 10^12`。 配列全体でも合計のみなので、`100000`、収縮は起こりません。 インデックス時`r`、 その通り`r + 1`そこで終わる部分配列は有効なので、合計は次のようになります。`1 + 2 + ... + 100000 = 5,000,050,000`。 

Python はこの値をオーバーフローせずに保存し、アルゴリズムは依然として O(N) 作業のみを実行します。
