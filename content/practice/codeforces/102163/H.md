 ## 解決策
 ## 問題の理解

 粒子を無向グラフの頂点と考えてください。 既知のもつれ関係はすべて、2 つの頂点間にエッジを与えます。 このステートメントの推移的な特性は、粒子 (x) から粒子 (y) へのパスがある場合、2 つの粒子間に直接の関係が与えられていなくても、それらの粒子は絡み合っているとみなされることを意味します。 

したがって、すべてのクエリ ((x,y)) について、(x) と (y) がグラフの同じ連結成分に属しているかどうかを判断する必要があります。 出力はクエリ順のバイナリ文字列です。 (i) 番目の文字は`1`クエリされた 2 つのパーティクルが指定された関係を通じて接続されている場合、および`0`さもないと。 

(N)、(M)、および (Q) の値はそれぞれ (10^5) に達する可能性があります。 この規模と 2 秒の制限では、クエリごとにグラフの走査を実行するアルゴリズムはコストが高すぎます。 1 回の走査で既に (O(N+M)) 個の頂点とエッジを検査できるため、(10^5) 回繰り返すと、およそ (10^{10}) 回のグラフ操作に到達できます。 粒子のすべてのペアをチェックするような二次作業はさらに実行可能性が低くなります。 グラフを 1 回処理し、各クエリを一定時間に近づける必要があります。 

不注意に実装すると、誤った結果が生じる可能性があるケースがいくつかあります。 重複したリレーションによって接続が変更されてはなりません。 例えば、```
1
3 2 3
1 2
1 2
1 2
2 3
3 1
```パーティクル 1 と 2 の間に実際の接続は 1 つだけありますが、パーティクル 3 は分離されています。 正しい出力は次のとおりです`110`1 と 2 は接続されているため、1 と 2 は再び接続されますが、1 と 3 は接続されていません。 すべてのエッジが新しいコンポーネントに接続されているかのように入力エッジの数を扱う実装では、グラフ構造について誤った仮定が行われる可能性があります。 

クエリには同じパーティクルを 2 回含めることもできます。 例えば、```
1
1 1 2
1 1
1 1
1 1
```出力があります`11`。 頂点はそれ自体と同じ接続コンポーネントに属するため、パーティクルは常にそれ自体に接続されます。 クエリされた 2 つの頂点間に明示的なエッジがあるかどうかだけをチェックする実装は、そのようなクエリでは失敗します。 

最後に、接続は直接ではなく間接的に行うことができます。 考慮する```
1
3 2 2
1 2
2 3
1 3
1 1
```出力は`11`。 1 と 3 の間に直接のエッジはありませんが、パス (1 \rightarrow 2 \rightarrow 3) により、それらは同じ連結コンポーネントの一部になります。 明示的にリストされたペアのみを検索すると、誤った答えが返されます`0`最初のクエリの場合。 

## アプローチ

 直接的なアプローチは、隣接リストを構築し、クエリごとに BFS または DFS を実行することです。 (x) から開始して、(x) から到達可能なすべての粒子を探索し、(y) に到達したかどうかを確認します。 グラフの到達可能性はまさに推移的なもつれ関係の定義であるため、これは正しいです。 

問題は繰り返し作業です。 最悪の場合、1 つの BFS がすべて (N) 個の頂点を訪問し、すべて (M) 個のエッジを検査できるため、1 つのクエリに (O(N+M)) の時間がかかります。 (Q) 個のクエリの場合、合計は (O(Q(N+M))) になります。 最大値では、これは約 (10^5(10^5+10^5)=2\cdot10^{10}) 回の操作となり、制限時間を大幅に超えます。 

有益な観察は、グラフ自体がクエリ間で変化しないことです。 すべてのクエリは、連結コンポーネントへの頂点の固定分割について同じ質問をします。 これらのコンポーネントをペアごとに個別に再検出する必要はありません。 

Disjoint Set Union 構造は Union-Find とも呼ばれ、まさにこのパーティションを表します。 すべてのエッジ ((u,v)) を読み取りながら、(u) と (v) を含むコンポーネントをマージします。 すべてのエッジが処理された後、DSU 代表が等しい場合、2 つのパーティクルは正確に接続されます。 各クエリには 2 つの答えが返されます。`find`操作。 

ブルート フォース ソリューションは、グラフ トラバーサルによって到達可能性が正しく検出されるため機能しますが、同じコンポーネントが繰り返し検出されるため失敗します。 すべてのクエリが 1 つの固定グラフを参照しているという観察により、その連結コンポーネントを 1 回計算し、各クエリをコンポーネントの比較に減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(Q(N+M))) | (O(N+M)) | 遅すぎる |
 | 最適 | (O((N+M+Q)\アルファ(N))) | (O(N)) | 承認済み |

 ここで (\alpha(N)) は逆アッカーマン関数であり、成長が非常に遅いため、実際のすべての入力サイズに対して事実上一定です。 

## アルゴリズムのチュートリアル

 1. パーティクルごとに 1 つのセットを含む DSU 構造を作成します。 リレーションがまだ処理されていないため、最初はすべてのパーティクルが独自のコンポーネントです。 
2. (M) 個の既知のもつれ関係 ((u,v)) ごとに、次を呼び出します。`union(u, v)`。 2 つのパーティクルがすでに同じコンポーネントに属している場合は、何も変更する必要はありません。 それ以外の場合、それらのコンポーネント間のエッジにより、一方の側から到達可能なすべてのパーティクルがもう一方の側からも到達可能になるため、それらのコンポーネントはマージされます。 
3. すべての関係が処理された後、各クエリ ((x,y)) を読み取り、計算します。`find(x)`そして`find(y)`。 代表者が等しい場合は追加します`1`答えに。 それ以外の場合は追加`0`。 
4. 収集した文字を 1 つの文字列として出力します。 リスト内に回答を作成すると、クエリの処理中に新しい長い文字列を繰り返し作成する必要がなくなります。 

### なぜ効果があるのか

 DSU の不変条件は、すべての処理されたエッジが 1 つの連結コンポーネントを介して 2 つのパーティクルを接続するときに、2 つのパーティクルが正確に同じ代表を持つということです。 すべての粒子は単独であるため、最初はこれが当てはまります。 エッジが 2 つの異なるコンポーネントを結合すると、`union`不変条件を維持しながら、これら 2 つのコンポーネントを正確にマージします。 2 つのエンドポイントがすでに同じコンポーネント内にある場合、エッジは新しい接続を追加せず、DSU を変更しないままにするのが正しいことになります。 

(M) 個のエッジがすべて処理されると、DSU コンポーネントはまさにグラフ全体の接続コンポーネントになります。 クエリは、(x) と (y) が接続されているかどうかを尋ねます。これは、それらの代表が同じかどうかを尋ねることと同じです。 したがって、出力される文字はすべて正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    output = []

    for _ in range(t):
        n, m, q = map(int, input().split())

        parent = list(range(n + 1))
        size = [1] * (n + 1)

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def union(a, b):
            ra = find(a)
            rb = find(b)

            if ra == rb:
                return

            if size[ra] < size[rb]:
                ra, rb = rb, ra

            parent[rb] = ra
            size[ra] += size[rb]

        for _ in range(m):
            u, v = map(int, input().split())
            union(u, v)

        ans = []

        for _ in range(q):
            x, y = map(int, input().split())
            ans.append('1' if find(x) == find(y) else '0')

        output.append(''.join(ans))

    sys.stdout.write('\n'.join(output))

if __name__ == "__main__":
    solve()
```の`parent`配列には、すべての DSU ノードの親が格納されます。 ルートは次のように識別されます。`parent[x] == x`ので、初期化中です`parent`と`range(n + 1)`(N) 個の個別のコンポーネントを作成します。 入力頂点には 1 から (N) までの番号が付けられているため、インデックス 0 の追加の位置によりパーティクル番号を直接使用できます。 

の`size`配列はサイズによる結合をサポートします。 2 つの異なるルートが結合されると、小さいツリーが大きいツリーの下に接続されます。 これにより、DSU ツリーが浅くなります。 の`find`この関数は、訪問した各ノードをルートに近いポイントに変更することによってパス圧縮も実行します。 これら 2 つの最適化を組み合わせると、(\alpha(N)) で表されるほぼ一定の償却複雑度が得られます。 

重複したエッジは自然に処理されます。`union`。 両方のエンドポイントがすでに同じ代表者を持っている場合、関数はすぐに戻ります。 セルフエッジも同様に動作するため、特別なケースは必要ありません。 

このコードは、クエリに答える前にすべてのエッジを処理します。これは、質問が行われる前にグラフ全体が固定されているという事実と一致します。 隣接リストは必要ないため、実装では (O(N)) 個の補助メモリのみが使用されます。 

Python では整数オーバーフローの懸念はありません。 実装では反復を使用します`find`これにより、Python での再帰的な実装から発生する可能性のある再帰の深さの問題も回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O((N+M+Q)\アルファ(N))) | 各エッジは最大 2 つのほぼ一定の償却 DSU 操作を実行し、各クエリは 2 つを実行します。`find`オペレーション |
 | スペース | (O(N)) | の`parent`そして`size`配列にはそれぞれ (N+1) 個のエントリが含まれます。 

(N,M,Q\le10^5) を使用すると、アルゴリズムはテスト ケースごとに線形数の DSU 操作のみを実行し、各操作の償却コストは実質的に一定になります。 メモリ使用量も (N) では線形であり、快適に 256 MB 以内です。 このアプローチではグラフ全体の保存が回避されるため、実装とメモリ使用量の両方が小さく抑えられます。
