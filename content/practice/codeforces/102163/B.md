 ## 解決策
 ## 問題の理解

 寮は無向グラフとしてモデル化できます。 各部屋は頂点であり、各ポータルはエッジです。 ポータルは、エッジを削除すると接続されているコンポーネントが切断される場合 (ブリッジの標準定義)、まさにスーパーバイザにとって役立ちます。 

ハサンは 2 つの部屋の間に新しいポータルを 1 つだけ追加できます。 エッジを追加すると、新しいエッジによって既存のブリッジを含むサイクルが作成される可能性があるため、一部の既存のブリッジが破壊される可能性があります。 目標は、できるだけ少ない橋が残るように新しいポータルを選択することです。 

入力には複数の独立したグラフが含まれています。 各グラフで必要な出力は、1 つのエッジを追加した後のブリッジの最小数です。 

境界では、1 つのテスト ケースで最大 (10^5) 個の頂点と (10^5) 個のエッジが許可されます。 公式問題ページでは、制限時間は 3 秒、メモリ制限は 256 MB と記載されています。 このサイズでは、アルゴリズムはほぼ線形またはほぼ線形の時間でグラフを処理する必要があります。 すべての頂点ペアを列挙するにはすでに (O(N^2)) のコストがかかり、これは最大サイズで約 (5\cdot10^9) ペアになるため、考えられるすべての新しいポータルを個別に調べるソリューションは遅すぎます。 

不注意な実装が失敗する可能性があるグラフの詳細がいくつかあります。 まず、グラフが切断されている可能性があります。 例えば、```
1
4 2
1 2
3 4
```には 2 つのブリッジがありますが、異なる接続コンポーネントの頂点間にエッジを追加してもサイクルは作成されないため、答えは次のようになります。`2`。 ブリッジ構造全体を 1 つのツリーとして扱うソリューションでは、2 つのコンポーネントが誤って接続され、両方のブリッジが消滅したと主張される可能性があります。 

次に、グラフにはサイクルが含まれる場合があります。 のために```
1
3 3
1 2
2 3
3 1
```すでに橋はないので、答えは次のとおりです。`0`。 単純にエッジをカウントしたり、接続されたグラフ内のすべてのエッジがブリッジであると想定したりするソリューションでは、この問題が発生します。 

第三に、繰り返しエッジが発生した場合は、それを正しく処理する必要があります。 のために```
1
2 2
1 2
1 2
```どちらかのエッジを削除してももう一方の接続は残るため、どちらのエッジもブリッジではありません。 答えは`0`。 Tarjan のアルゴリズムでは、2 番目に出現したエッジを同じエッジとして扱うのではなく、2 つの物理エッジを区別する必要があります。 

入力に自己ループが含まれている場合、自己ループも無害なケースです。 のために```
1
1 1
1 1
```エッジでは何も切断できないため、答えは次のようになります。`0`。 以下の実装は自然にそれを処理します。 

## アプローチ

 直接的な解決策では、考えられるすべての部屋のペアを新しいポータルのエンドポイントとして試します。 各ペアに対して、概念的にエッジを追加し、ブリッジ検出アルゴリズムを実行し、残りのブリッジをカウントし、最小値を維持します。 新しいポータルの法的な選択はすべて明示的に評価されるため、これは正しいです。 

問題は選択肢の多さです。 (O(N^2)) 個のペアがあり、すべてのブリッジを見つけるには (O(N+M)) のコストがかかるため、合計の複雑さは (O(N^2(N+M))) になります。 (N=M=10^5) の場合、これは (10^{15}) 回のグラフ演算に相当し、まったく実現不可能です。 

有益な観察は、エッジを 1 つ追加すると、特定の 1 つのパス上のエッジがブリッジでなくなるだけであるということです。 2 つの部屋がすでに接続されているとします。 既存のブリッジがすべて縮小された後、エッジ二重接続されたコンポーネント間には固有のパスが存在します。 新しいエッジを追加すると、新しいエッジとそのパスで構成されるサイクルが作成されます。 パス上のすべての橋はサイクルの一部となり、橋ではなくなります。 道の外側にある橋は橋のままです。 

これは、ブリッジを含まないすべての最大領域を 1 つのコンポーネントに圧縮することを示唆しています。 この圧縮後、残ったエッジはすべて橋になり、その結果として得られる構造は森林になります。 このフォレストの各ツリーでは、2 つのコンポーネント間にエッジを追加すると、その固有のパス上のブリッジ エッジが正確に削除されます。 

したがって、問題ははるかに単純になります。 橋の総数を(B)とする。 ブリッジ フォレスト内の最長のパスの長さが (D) の場合、そのパスの 2 つの終点に属する部屋の間にポータルを追加し、正確に (D) のブリッジを削除できます。 結果的に答えは

 [
 B〜D。 
】

 元のグラフが切断されている場合、圧縮された構造は 1 つのツリーではなくフォレストになります。 2 つの異なるツリー間のエッジでは古いブリッジを削除できないため、すべてのツリーの最大直径を取得します。

 ## アルゴリズムのチュートリアル

 1. すべてのポータルの明示的なエッジ ID を使用して無向グラフを保存します。 2 つの異なるポータルが同じ部屋のペアに接続する可能性があるため、エッジ ID の使用が必要です。 
2. Tarjan のブリッジ アルゴリズムを実行します。 すべての頂点について、その検出時間を維持する`tin`および到達可能な最短の検出時間`low`。 (u) から (v) までの DFS ツリー エッジの場合、そのエッジはまさに次の場合にブリッジになります。`low[v] > tin[u]`。 

この実装では、再帰的 DFS の代わりに明示的なスタックが使用されます。 (10^5) 個の頂点を使用すると、再帰的 Python DFS は再帰制限に達したり、不要なオーバーヘッドが発生したりする可能性がありますが、反復バージョンでは同じ Tarjan ロジックが維持されます。 
3. すべてのブリッジを無視し、残りのグラフの接続されたコンポーネントを見つけます。 このようなコンポーネントはすべてエッジ二重接続コンポーネントです。つまり、コンポーネント内の単一のエッジがコンポーネントを切断できないことを意味します。 
4. 各エッジ二重接続コンポーネントに圧縮された頂点 ID を与えます。 すべてのオリジナルのブリッジは、2 つの異なる圧縮コンポーネントを接続します。 
5. これらのブリッジのみを含む新しいグラフを構築します。 内部の非ブリッジ エッジはすべて縮小されているため、このグラフはフォレストになります。 その中の各エッジは、正確に 1 つの元の橋を表します。 
6. すべてのブリッジ エッジを数えます。 この値を (B) と呼びます。 
7. ブリッジ フォレスト内のすべての木について、その直径を計算します。 すべての圧縮エッジは単位長さを持っているため、直径は単にパス上のブリッジ エッジの最大数になります。 
8. 標準的な 2 トラバース法により、各ツリーの直径が求められます。 任意の頂点から開始して、最も遠い頂点を見つけます (a)。 (a) から始めて、最も遠い頂点 (b) を見つけます。 (a) から (b) までの距離が木の直径です。 
9. すべての木の中で最大の直径 (D) を維持します。 このパスの 2 つのエンドポイント コンポーネントから部屋を接続すると、まさにそれら (D) ブリッジを含むサイクルが作成されるため、これらのブリッジは消えます。 
10. 戻る`total_bridges - maximum_diameter`。 

**機能する理由** ブリッジ以外のエッジがすべて縮小された後、残りのエッジはすべてブリッジになり、圧縮されたグラフはフォレストになります。 接続コンポーネント内に 1 つのエッジを追加すると、新しいエッジと圧縮ツリー内のその端点間の一意のパスで構成される 1 つのサイクルが作成されます。 まさに、そのパス上の橋の端は橋ではなくなりますが、他のすべての橋は橋のままです。 したがって、削除されたブリッジの数は正確にパスの長さになります。 可能な限り最適なパスは直径であるため、元の橋の数からフォレストの最大直径を差し引くと、残りの橋の可能な最小数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    answers = []

    for _ in range(t):
        n, m = map(int, input().split())

        adj = [[] for _ in range(n)]
        edges = []

        for eid in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            edges.append((u, v))
            adj[u].append((v, eid))
            adj[v].append((u, eid))

        tin = [-1] * n
        low = [0] * n
        parent = [-1] * n
        parent_edge = [-1] * n
        it = [0] * n
        is_bridge = [False] * m

        timer = 0

        for root in range(n):
            if tin[root] != -1:
                continue

            tin[root] = low[root] = timer
            timer += 1

            stack = [root]

            while stack:
                v = stack[-1]

                if it[v] < len(adj[v]):
                    to, eid = adj[v][it[v]]
                    it[v] += 1

                    if eid == parent_edge[v]:
                        continue

                    if tin[to] == -1:
                        parent[to] = v
                        parent_edge[to] = eid
                        tin[to] = low[to] = timer
                        timer += 1
                        stack.append(to)
                    else:
                        if tin[to] < low[v]:
                            low[v] = tin[to]
                else:
                    stack.pop()
                    p = parent[v]

                    if p != -1:
                        pe = parent_edge[v]

                        if low[v] > tin[p]:
                            is_bridge[pe] = True

                        if low[v] < low[p]:
                            low[p] = low[v]

        comp = [-1] * n
        component_count = 0

        for start in range(n):
            if comp[start] != -1:
                continue

            comp[start] = component_count
            stack = [start]

            while stack:
                v = stack.pop()

                for to, eid in adj[v]:
                    if is_bridge[eid]:
                        continue
                    if comp[to] != -1:
                        continue

                    comp[to] = component_count
                    stack.append(to)

            component_count += 1

        forest = [[] for _ in range(component_count)]
        total_bridges = 0

        for eid, (u, v) in enumerate(edges):
            if not is_bridge[eid]:
                continue

            a = comp[u]
            b = comp[v]

            forest[a].append(b)
            forest[b].append(a)
            total_bridges += 1

        seen = [False] * component_count

        def farthest(start, mark):
            stack = [(start, -1, 0)]
            far_vertex = start
            far_distance = 0

            while stack:
                v, parent_vertex, distance = stack.pop()

                if mark:
                    seen[v] = True

                if distance > far_distance:
                    far_distance = distance
                    far_vertex = v

                for to in forest[v]:
                    if to == parent_vertex:
                        continue
                    stack.append((to, v, distance + 1))

            return far_vertex, far_distance

        maximum_diameter = 0

        for start in range(component_count):
            if seen[start]:
                continue

            endpoint, _ = farthest(start, True)
            _, diameter = farthest(endpoint, False)

            if diameter > maximum_diameter:
                maximum_diameter = diameter

        answers.append(str(total_bridges - maximum_diameter))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```グラフは最初に隣接リストとして保存されます。 すべての隣接エントリには隣接頂点と物理エッジ ID の両方が含まれており、これにより Tarjan は平行エッジを正しく区別できます。 

最初の走査の計算`tin`そして`low`。 DFS の子の場合`v`終了、状態`low[v] > tin[parent[v]]`親エッジをブリッジとして識別します。 親エッジ自体は、親頂点をスキップするのではなく、その ID を使用してスキップされます。これはマルチグラフに必要な微妙な詳細です。 

ブリッジがわかった後、2 回目のトラバーサルでコンポーネント ID が割り当てられますが、ブリッジを通過することは拒否されます。 これらのコンポーネントは、まさに圧縮されたフォレストの頂点です。 次に、すべての元のエッジを 1 回検査し、ブリッジ エッジのみを追加します。`forest`。 

直径の計算には、以下を含むスタックが使用されます。`(vertex, parent, distance)`。 なぜなら`forest`はフォレストなので、親を覚えていれば後戻りを防ぐのに十分なので、トラバースごとに追加の訪問先配列は必要ありません。 ツリーの最初の走査では、その頂点にマークが付けられます。`seen`これにより、同じツリーを再度処理することができなくなります。 

Python では整数オーバーフローの懸念はありません。 考えられる最大の答えは最大でも (10^5) ですが、Python の整数はとにかく任意のサイズを処理します。 距離はゼロから始まるため、ブリッジ エッジのない圧縮コンポーネントの直径はゼロとなり、削除されるブリッジの数にはまったく影響しません。

1 2
1 2
```2 つのポータルのエッジ ID は異なります。 DFS 中に 2 番目の物理エッジに遭遇すると、それは DFS の親エッジと混同されるのではなく、バック エッジとして扱われます。 その結果、ローリンク値が十分に低下し、どちらのポータルもブリッジ条件を満たさなくなります。 圧縮されたグラフには 1 つのコンポーネントが含まれており、ブリッジ数は 0 であり、答えは次のようになります。`0`。 

セルフループの場合、```
1
1 1
1 1
```エッジは同じ頂点で始まり、同じ頂点で終わります。 グラフを切断できないため、Tarjan はグラフをブリッジとしてマークしません。 唯一の部屋が 1 つの圧縮されたコンポーネントになり、橋の森の直径はゼロになります。答えは次のとおりです。`0`。 

最も明らかなケースは単純なパスです。```
1
4 3
1 2
2 3
3 4
```3 つのエッジはすべて橋なので、圧縮された森は長さ 3 のパスになります。 最初の直径横断は一方の終点に到達し、2 番目の横断は距離 3 でもう一方の終点に到達します。 アルゴリズムは計算します`total_bridges = 3`、`maximum_diameter = 3`、そして戻ります`0`。 部屋 1 と 4 の間にポータルを追加すると、元のすべてのエッジを含むサイクルが作成されます。これはまさに最適な操作です。
