 ## 問題の理解

 各生徒の試験用紙は 1 つの正の整数としてエンコードされます。 その整数のバイナリ表現は生徒の正答と誤答を表します。設定されたビットは正しい正答を表し、未設定のビットは誤答を表します。 試験の解答はすべて正しかったため、生徒の得点は、数値を 2 進数で表現したときの設定ビット数とまったく同じになります。 

たとえば、次のような数字です。`13`は`1101`バイナリで。 これには 3 つのセットビットが含まれているため、対応する生徒の得点が決まりました。`3`。 

すべてのテスト ケースについて、次の配列を受け取ります。`N`このようなエンコードされた試験問題は、すべての要素のポップカウント、または設定されたビット数を同じ順序で出力する必要があります。 

の値`N`到達できる`10^5`したがって、すべての生徒のペアを比較するか、またはそれに比例した作業を実行するアプローチです。`N^2`、すぐには不適切です。 値自体は最大でも`10^9`、これは、各数値の 2 進数が最大 30 桁であることを意味します。 この小さな固定ビット幅が、リニア スキャンで十分な主な理由です。 1 秒の制限があるため、おおよその目標を達成する必要があります。`O(N)`テスト ケースごとに作業が行われ、数値ごとに少量の一定量の処理のみが行われます。 

バイナリ表現が特定の形状を持つと想定している場合、実装が誤る可能性があるケースがいくつかあります。 可能な最小の入力を考えてみましょう。```
1
1
1
```正しい出力は次のとおりです。```
1
```番号`1`には、設定ビットが 1 つだけあります。 誤って位置 0 ではなく位置 1 からビットのチェックを開始する実装では、誤ってゼロが生成されます。 

別の境界ケースは 2 の累乗です。```
1
3
2 4 8
```正しい出力は次のとおりです。```
1 1 1
```2 の累乗ごとに 1 つのセット ビットが存在します。 設定されたビット数の代わりに 2 進数の桁数をカウントする不注意な実装では、次のエラーが返されます。`2 3 4`、これは間違った量です。 

値には、隣接する設定ビットとそれらの間にゼロを含めることもできます。```
1
3
3 5 10
```バイナリ形式は次のとおりです。`11`、`101`、 そして`1010`したがって、正しい出力は次のようになります。```
2 2 2
```設定された最高または最低のビットのみをチェックすると、一部の正解を見逃してしまいます。 ビットパターン全体をカウントする必要があります。 

## アプローチ

 直接的なアプローチは、すべての整数をバイナリに変換し、そのすべてのビットを検査し、ビットが変化するたびに答えをインクリメントすることです。`1`。 これは完全に正しいです。`1`バイナリ表現の は、1 つの正しい質問に対応します。 

以来、`A_i`せいぜい`10^9`、最大でも 30 ビットです。 したがって、このアプローチでは`O(30N)`、これを単純化すると、`O(N)`30は定数だからです。 Python で最もクリーンな実装は、組み込みの整数演算を使用することです。`bit_count()`、ビットを手動で操作する必要なく、まさにこのポップカウント操作を実行します。 

手動ビットカウントループも第一原理から導き出すことができます。 表現`x & 1`最下位ビットが設定されているかどうかを示します。`x >> 1`そのビットを削除します。 これを繰り返すと、`x`設定されたビットごとにカウントがゼロになります。 さらに優れたビット操作の観察もあります。`x & (x - 1)`設定された最小ビットをから削除します`x`。 したがって、その操作を繰り返し適用すると、2 進数ごとに 1 回の反復ではなく、設定ビットごとに 1 回の反復が実行されます。 

ブルートフォース解釈は、なぜ答えがポップカウントなのかを理解するのに役立ちますが、`O(N^2)`アルゴリズム全然。 各学生レコードの構造は、他のすべてのレコードから独立しています。 各整数を個別に処理でき、制限された 30 ビット表現により、手動スキャンでも十分な速度が得られます。 パイソンの`int.bit_count()`直接同じ結果が得られ、最も単純で最適な実装です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 手動ビットスキャン | O(30N) = O(N) | O(1) 補助 | 承認済み |
 | 内蔵ポップカウント | O(N) | O(1) 補助 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 各テスト ケースは独立しているため、同じ手順を個別に適用できます。 
2.読む`N`そして`N`暗号化された試験問題。 スコアは独自のバイナリ表現に完全に依存するため、必要なのは各整数値のみです。 
3. すべての整数について`x`、計算する`x.bit_count()`。 これは、バイナリ表現で設定されたビット数を返します。`x`、これはまさにその整数でエンコードされた正解の数です。 
4. 結果のカウントを入力と同じ順序で保存し、スペースで区切られた 1 行として出力します。 各出力スコアは入力配列内の同じ位置にある生徒に対応するため、順序を維持することが重要です。 

これが機能する理由: すべての生徒にとって、各バイナリ位置が 1 つの質問を表し、設定されたビットが正解を表します。 の`bit_count()`この操作では、設定されたビットが正確にカウントされるため、生成される値はその生徒のスコアとまったく同じになります。 学生は入力順に独立して処理されるため、すべての出力位置に正しいスコアが与えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ans = [x.bit_count() for x in a]
        print(*ans)

if __name__ == "__main__":
    solve()
```プログラムは最初に読み取ります`T`、その後、各テスト ケースを個別に処理します。 配列は整数として読み取られ、リスト内包表記が適用されます。`bit_count()`すべての生徒の記録に。 

の使用`bit_count()`意図的です。 問題は次の数を求めます。`1`バイナリの長さや設定された最上位ビットの位置ではなく、ビットです。 Python の整数には、C++ などの言語のような固定幅のオーバーフロー動作がないため、最大値は`10^9`特別な型を使用せずに直接処理されます。 

オフバイワンの問題もありません。`bit_count()`ビット位置ゼロを正しく扱います。 例えば、`1`は位置 0 にある単一のセットビットで表されるため、そのカウントは次のようになります。`1`。 

出力は次のように生成されます。`print(*ans)`、すべてのスコアの間にスペースを挿入し、書式設定された大きな文字列を手動で構築することを回避します。 入力は次を使用します`sys.stdin.readline`、必要な高速 I/O パターンを満たします。

import sys
import io

def solve():
    input = sys.stdin.readline
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        print(*(x.bit_count() for x in a))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
sample = """\

""") == "1\n", "minimum size"
