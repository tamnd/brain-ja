 ## 解決策
 ## 問題の理解

 2 種類の有限線分があります。 水平セグメントは、左右の x 座標と固定の y 座標によって記述されます。 垂直セグメントは、その下端と上端の y 座標と固定の x 座標によって記述されます。 

点 C で交差する水平セグメントと垂直セグメントを 1 つずつ選択します。結果として得られるプラス記号の 4 つのアームは、これら 2 つのセグメントの 4 つの端点で終わります。 交差点がある場合`(x, y)`、4つの腕の長さは次のとおりです。`x - x1`、`x2 - x`、`y - y1`、 そして`y2 - y`。 

このプラス記号の値は、これら 4 つの数値の最小値です。 すべての有効な水平および垂直ペアにわたって可能な最大値が必要です。 

まで`10^5`水平セグメントと`10^5`垂直セグメントの場合、すべてのペアを試すには最大で`10^10`1 つのテスト ケースでチェックします。 1 秒の制限により、それは完全に排除されます。 たとえ`O((N+M) log(N+M))`ここでは、解決策の方がはるかに適切ですが、座標範囲は 1 つのみであるため、対数係数を追加したアルゴリズムも実用的です。`10^5`。 

適切な実装では慎重に処理する必要がある境界ケースがいくつかあります。 まず、端点での接触は有効な交差ですが、その辺の長さはゼロになります。 例えば、```
1
1 1
1 1 1
1 1 1
```答えがあります`0`。 厳密に正のオーバーラップを必要とするソリューションでは、交差が存在しないと誤って報告されてしまいます。 

2 番目のケースは、水平セグメントは十分に長くても、垂直セグメントが短すぎる場合です。 例えば、```
1
1 1
1 10 5
1 5 5
```答えがあります`0`。 セグメントは交差しますが、垂直セグメントには可能な限り最適な交差点で短辺に 2 単位のスペースしかなく、実際にはその全長はわずか 4 単位であるため、必要な交差点では 0 を超える長さの正のプラスを形成することはできません。 より一般的には、長さの候補`d`両方のセグメントの合計の長さが少なくとも必要です`2d`。 

3 番目のケースは、縮小された境界での等価性です。 考慮する```
1
1 1
1 5 3
1 5 3
```答えは`2`の交差点なので、`(3,3)`各方向にちょうど 2 つのユニットが残ります。 長さのチェック`d`次のような包含条件を使用する必要があります`x1 + d <= x <= x2 - d`。 それらを厳密な不等式に置き換えると、この有効な答えが失われます。 

入力はエンドポイントが昇順で表示されることを保証するものではないため、堅牢な実装では最初にすべてのセグメントを正規化する必要があります。 この問題の参照ソリューションでは、ジオメトリを処理する前に同じことを行います。 

## アプローチ

 直接的なアプローチは、すべての水平セグメントをすべての垂直セグメントに対して検査することです。 ペアの場合、x 範囲と y 範囲が交差するかどうかを確認し、交差座標を計算して、その点からセグメントの端点までの 4 つの距離を評価します。 これは正しいです。考えられるすべてのプラス記号は、そのようなペアの 1 つによって決定されるからです。 問題はペアの数です。 と`N = M = 10^5`、あるかもしれません`10^10`制限時間をはるかに超えています。 

有益な観察は、答えを直接最大化しようとするのをやめるということです。 代わりに、「はい」か「いいえ」で答える質問をしてください。値が少なくとも次のプラス記号を作成できますか?`d`?

 水平セグメントの場合`[x1, x2]`高所で`y`、x での交差には少なくとも`d`水平両側の単位が正確に一致するとき`x1 + d <= x <= x2 - d`。 

したがって、この特定のチェックでは、水平セグメントを許容される x 間隔で置き換えることができます。`[x1+d, x2-d]`。 もし`x1+d > x2-d`、この水平セグメントはサイズのプラスに参加できません`d`。 

同様に、垂直セグメント`[y1, y2]`x ではプラスのサイズをサポートできます`d`ちょうど交差点の高さが満たされるとき`y1 + d <= y <= y2-d`。 

これで、ジオメトリはスイープラインの問題になりました。 垂直セグメントを x で並べ替えます。 固定の場合`d`、スイープが次の値に達すると、有用な水平セグメントがそれぞれアクティブになります。`x1+d`、その後アクティブではなくなります`x2-d`。 座標 x で垂直セグメントを処理している間、アクティブな水平セグメントは、許容される x 間隔に x が含まれるセグメントとなります。 

アクティブな水平線のうち、少なくとも 1 つの水平線の y 座標が垂直セグメントの有効な間隔内にあるかどうかを知る必要があるだけです。`[y1+d, y2-d]`。 y 座標上のフェンウィック ツリーが標準実装です。 オリジナルで受け入れられている C++ ソリューションは、まさにこのスイープを使用し、左側の境界で水平線をアクティブにし、右側の境界の後で水平線を削除し、フェンウィック ツリーで y 区間をクエリします。 

最後の観察は単調性です。 サイズがプラスの場合`d`存在する場合、さらに小さなサイズごとのプラスも存在します。 これにより、答えは二分探索に適したものになります。 候補者をテストします`d`、可能であれば、より大きな値を検索します。 それ以外の場合は、より小さい値を検索します。 

以下の Python 実装では、同じスイープが、y 座標世界全体にわたる小さなブロックベースのビットセットと結合されます。 座標は最大でも`10^5`, そのため、対数ツリー演算を行わずに、どの y 座標が現在アクティブであるかを維持できます。 各ブロックには 256 y 位置が含まれており、2 番目の小さなビットセットはどのブロックが空ではないかを記録します。 間隔クエリは、最大 2 つの境界ブロックとコンパクトなブロック レベルのビットセットに触れます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(NM)`|`O(N+M)`| 遅すぎる |
 | 二分探索 + スイープ + フェンウィック ツリー |`O((N+M) log C log C)`|`O(N+M+C)`| 承認済み |
 | 二分探索 + スイープ + 有界座標ビットセット |`O((N+M) log C)`固定座標境界の場合 |`O(N+M+C)`| 承認済み |

 ここ`C`最大でも最大の座標です`10^5`。 2 番目のアプローチは通常のデータ構造の定式化ですが、3 番目のアプローチは、座標世界が明示的に制限されているため、1 秒の制限の下で Python に特に適しています。 

## アルゴリズムのチュートリアル

 1. すべての水平セグメントを次のように正規化します。`x1 <= x2`、およびすべての垂直セグメントにより、`y1 <= y2`。 セグメントの長さの半分から可能な最大の答えを計算します。 
2. 水平セグメントを 2 回、1 回目は次の順に並べ替えます。`x1`そして一度は`x2`。 確定候補者の場合`d`、その使用可能な間隔は`[x1+d, x2-d]`。 同じものを追加してから`d`順序が保持されるため、バイナリ検索中にリストを再度並べ替える必要はありません。 
3. 垂直セグメントを x 座標で並べ替えます。 それらを左から右にスイープしていきます。 
4. 候補者にとって`d`、すべての水平セグメントを破棄します。`x2-x1 < 2d`2 本の長さの腕を入れるのに十分な水平スペースがないため`d`。 残りの水平セグメントごとに、次のように定義します。`left = x1+d`そして`right = x2-d`。 
5. x スイープ中に、水平セグメントを挿入します。`left <= x`現在の垂直セグメントの場合。 ときは取り外してください`right < x`。 削除のための厳密な比較は意図的なものです。 もし`right == x`、垂直線は縮小された水平間隔の終点を通過しますが、それでも正確に得られます。`d`対応する側のユニット。 
6. 現在アクティブなすべての水平セグメントの y 座標を維持します。 複数のアクティブな水平線が同じ y 座標を持つ場合は、単純なブール値ではなくカウントを維持します。これは、そのうちの 1 つを削除しても、別の水平線がアクティブなままである間に誤って座標を削除してはいけないためです。 
7. 各垂直セグメントについて、最初に次のことを要求します。`y2-y1 >= 2d`。 その場合、交差する可能性のある高さは正確に次のようになります。`[y1+d, y2-d]`。 アクティブな y セットにこの間隔内の座標が含まれている場合、少なくともサイズにプラス`d`存在します。 
8. 実現可能な最大の二分探索`d`。 下限はゼロです。 上限は、入力セグメントの最大の半分の長さにすることができます。 もし`check(mid)`成功、保存`mid`そして右に進みます。 それ以外の場合は左に進みます。 

### なぜ効果があるのか

 固定の場合`d`、アクティブな水平セグメントは、両方の水平アームが少なくとも長さになるように x 座標を選択できる水平セグメントです。`d`。 スイープが垂直座標 x にある場合、アクティブ セットには、許容される x 間隔にその x が含まれるすべての水平線が正確に含まれます。 

垂直セグメントは少なくともサイズの有効なプラスに貢献します`d`ちょうどその y 座標が内部で選択できるとき`[y1+d, y2-d]`。 したがって、アクティブな水平方向の y 座標に対する範囲クエリは、ある水平方向とこの垂直方向がそのようなプラスを形成できる場合に正確に真となります。 したがって、スイープは答えます`check(d)`正しく。 

最後に、実現可能性は単調です。 必要なアームの長さを増やすと、可能性のある交差が削除されるだけであり、新しい交差が作成されることはありません。 その結果、二分探索により実現可能な最大値が見つかります。

class ActiveY:
    def __init__(self, max_y):
        self.size = max_y + 1
        self.blocks = [0] * ((max_y >> 8) + 1)
        self.count = [0] * (max_y + 1)
        self.nonempty = 0

    def add(self, y):
        c = self.count[y]
        self.count[y] = c + 1
        if c == 0:
            b = y >> 8
            bit = 1 << (y & 255)
            old = self.blocks[b]
            self.blocks[b] = old | bit
            if old == 0:
                self.nonempty |= 1 << b

    def remove(self, y):
        c = self.count[y] - 1
        self.count[y] = c
        if c == 0:
            b = y >> 8
            bit = 1 << (y & 255)
            new = self.blocks[b] & ~bit
            self.blocks[b] = new
            if new == 0:
                self.nonempty &= ~(1 << b)

    def any_in_range(self, lo, hi):
        if lo > hi:
            return False

        b1 = lo >> 8
        b2 = hi >> 8

        if b1 == b2:
            left = lo & 255
            right = hi & 255
            mask = ((1 << (right - left + 1)) - 1) << left
            return (self.blocks[b1] & mask) != 0

        left = lo & 255
        if self.blocks[b1] & (~((1 << left) - 1) & ((1 << 256) - 1)):
            return True

        right = hi & 255
        if self.blocks[b2] & ((1 << (right + 1)) - 1):
            return True

        if b2 - b1 <= 1:
            return False

        width = b2 - b1 - 1
        middle_mask = ((1 << width) - 1) << (b1 + 1)
        return (self.nonempty & middle_mask) != 0

    n = len(horizontal)
    m = len(vertical)

    horizontal.sort(key=lambda p: p[0])

        left_list = []
        right_list = []

                left_list.append((x1 + d, y))

        ri = 0

            while li < ln and left_list[li][0] <= x:
                active.add(left_list[li][1])
                li += 1

                active.remove(right_list[ri][1])
                ri += 1

            if active.any_in_range(y1 + d, y2 - d):
                return True

        return False

    lo = 0
    hi = max_len
    ans = 0

    while lo <= hi:
        mid = (lo + hi) // 2
        if check(mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    return ans

ここ`C <= 10^5`。 重要な実際的な特性は、動的 y 構造が Python ツリーの代わりに有界座標ユニバースを使用することです。`O(log C)`イベントごとに作業します。 二分探索には最大で約 17 回の反復が必要です。`2^17 > 10^5`したがって、大規模なテスト ケースごとにおよそ数百万のセグメント処理操作が実行されます。 

元の C++ ソリューションはフェンウィック ツリーを使用するため、スイープに追加の対数係数がありますが、C++ で規定されている制限に適合します。 Python バージョンでは、その対数データ構造が座標ビットセット表現に置き換えられ、同じ厳しい制限に適した実装が維持されます。

 ## 特殊なケース

 終点でのみ発生する交差の場合、使用可能な水平間隔が閉じているため、アルゴリズムは候補を保持します。 のために```
1
1 1
1 5 3
3 3 3
```水平セグメントにより、次の地点で横断できます。`x=3`一方、垂直セグメントは次の点でのみ交差できます。`y=3`。 交差は有効ですが、垂直セグメントの長さがゼロであるため、答えは次のようになります。`0`。 ポジティブレングスチェックでは、`y1+d <= y2-d`すべての場合すぐに失敗します`d > 0`。 

全長が要求された応答のちょうど 2 倍であるセグメントの場合、縮小された間隔は 1 つの座標で構成されます。 のために```
1
1 1
1 5 3
3 3 3
```候補者`d=0`実現可能ですが、`d=1`垂直セグメントは両側に 1 つのユニットを提供できないため、これは不可能です。 より一般的には、```
1
1 1
1 5 3
1 5 3
```候補者`d=2`水平範囲を生成します`[3,3]`と垂直範囲`[3,3]`。 スイープは使用します`<=`アクティベーションと`<`削除するため、共通の境界座標はアクティブのままになり、答えは`2`が見つかりました。 

いくつかの水平セグメントが同じ y 座標を持つ場合、アクティブな構造は多重性を表す必要があります。 同じ y を持つ 2 つの水平線がアクティブになり、1 つが期限切れになるとします。 y 座標は依然としてもう一方の水平方向で表されます。 の`count[y]`配列はこれを直接処理します。カウントが 0 から 1 に変化するとビットがセットされ、カウントが 0 に戻った場合にのみクリアされます。 

反転されたエンドポイントは、ジオメトリが実行される前に処理されます。 例えば、```
1
1 1
9 1 5
9 1 5
```からの 2 つのセグメントに正規化されます。`1`に`9`。 それらの中心は一致します`5`、答えを与える`4`。 正規化を行わないと、次のような式になります。`x2-x1`が負になり、二分探索の上限が暗黙のうちに不正確になる可能性があります。 

全縮退の場合も安心です。 すべての水平および垂直セグメントが 1 つの点で構成されている場合、考えられるすべてのプラスの値は 0 になります。 初期の二分探索の下限はゼロであり、`check(0)`肯定的な候補はすべて拒否されますが、実際の交差はすべて正しく受け入れられます。 

最後に、同じ座標にある複数の線が関与する交差点には、特別な処理は必要ありません。 この問題では、水平セグメントと垂直セグメントを 1 つずつ選択するように求められているため、アクティブな水平セグメントと現在の垂直セグメントを組み合わせたものが 1 つの有効なペアを表します。 アルゴリズムは、現在の候補長に対してそのようなペアが少なくとも 1 つ存在するかどうかのみを知る必要があり、存在するペアの数ではありません。
