 ## 解決策
 ## 問題の理解

 試合結果は最終ゴール数のみに左右されます。 すべてのテストケースについて、`X`はバシャールのチームが獲得したゴール数であり、`Y`は浜田チームの得点数です。 これら 2 つの整数を比較して、勝ったチームの名前を出力する必要があります。`Iskandar`スコアが同点の場合。 

選手、怪我、交代、試合期間などの話は計算には影響しません。 最終スコアが判明すると、考えられるすべての結果は次の 3 つのケースのいずれかに正確に当てはまります。`X > Y`、`X < Y`、 または`X == Y`。 

の値`X`そして`Y`せいぜい`10^5`したがって、1 つのテスト ケースにわたる線形スキャンでも低コストになります。 ただし、答えは 1 回の比較によって決定されるため、何もスキャンする必要はありません。 と`T`テストケース、`O(T)`ソリューションは、ケースごとに一定量の作業のみを実行します。これは、簡単に 1 秒の制限内に収まります。 スコア自体に比例する作業を実行するアプローチは不要であり、両方のスコアにわたるネストされたプロセスはおおよその範囲に達する可能性があります。`10^10`単一のペアに対する操作ですが、これは明らかに不適切です。 

不注意な実装が露呈する可能性のある単純なケースがいくつかあります。 スコアが等しい場合、結果は次のようになります。`Iskandar`。 たとえば、入力`3 3`生成する`Iskandar`; 使用して`>=`バシャールの勝利は正しく印刷されないため`Bashar`。 バシャールの得点がゼロで浜田の得点が多ければ、次のようになります。`0 1`、結果は`Hamada`; ゼロを特別な勝利値として扱うコードは間違っています。 逆境界の場合、`1 0`、生成する必要があります`Bashar`。 ついに、`0 0`引き分けであり、生産する必要があります`Iskandar`したがって、等価性を明示的にチェックするか、比較構造によって正しく表現する必要があります。 

## アプローチ

 ブルートフォース手法では、一方のチームのカウントに 1 ゴールを繰り返し加算し、最終的に結果の値を比較することでスコア差をシミュレートできます。 たとえば、次のことを判断するには、`X`よりも大きいです`Y`、一方がゼロになるまで、両方のスコアから 1 つのゴールを繰り返し削除することができます。 これは正しいです。各ペアの除去では、元のスコアがどちらが大きかったかが保持されるからです。 ただし、最悪の場合、`X = 100000`そして`Y = 99999`、これはほぼパフォーマンスを発揮します`100000`1 つのテスト ケースの反復。 多数のテスト ケースでは、実際の答えに必要な比較が 1 つだけである場合でも、不必要な作業が重要になる可能性があります。 より極端なネストされたシミュレーションでは、最大で次のようなパフォーマンスが得られます。`10^10`制限時間をはるかに超えた作戦。 

重要な観察は、勝者を決定するために必要な正確な量が入力にすでに含まれていることです。 再構築する隠れた状態や、シミュレートする一連の目標はありません。 2 つの最終スコアを直接比較すると、結果が完全に特徴づけられます。 ブルート フォースが機能するのは、最終的に 2 つの数値間の順序を検出するためですが、順序は比較演算子を通じてすでにすぐに利用可能です。 

したがって、最適解は次のようになります。`X`そして`Y`、それらを一度比較し、対応する結果を出力します。 各テスト ケースには一定の時間がかかります。`O(T)`合計時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(T × max(X, Y)) | お(1) | 不必要に遅い |
 | 最適 | O(T) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`T`なぜなら、同じ比較をすべての一致に対して独立して実行する必要があるからです。 
2. 各テスト ケースについて、次の内容を読んでください。`X`そして`Y`、バシャールと浜田のチームの最終目標を表しています。 
3. もし`X > Y`、印刷`Bashar`。 厳密にはバシャールのチームの方がゴール数が多いので、バシャールのチームが勝者です。 
4. それ以外の場合、`X < Y`、印刷`Hamada`。 以前の条件によりバシャールの勝利はすでに除外されており、浜田には厳密にはさらに多くのゴールがある。 
5. それ以外の場合、2 つのスコアは等しいため、次のように出力します。`Iskandar`。 これは次のような描画をカバーします。`0 0`そして`3 3`。 

なぜ機能するのか: 各テスト ケース全体を通して、`X`そして`Y`最終スコアは残ります。 まさにそのうちの 1 つ`X > Y`、`X < Y`、 または`X == Y`2 つの整数については true です。 このアルゴリズムは、これら 3 つの相互に排他的なケースをそれぞれ必要な出力に割り当てるため、誤った結果が生成されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    x, y = map(int, input().split())

    if x > y:
        print("Bashar")
    elif x < y:
        print("Hamada")
    else:
        print("Iskandar")
```最初の行は次のようになります`T`、処理する必要があるスコア ペアの数を正確に制御します。 使用する`sys.stdin.readline`実装をシンプルに保ちながら、高速な入力を提供します。 

ループ内では、`x`そして`y`整数として解析されます。 Python の整数には、これらの制約に対するオーバーフローの問題はなく、その値は実際の整数の制限をはるかに下回っています。 

比較順序は、スコア間に考えられる 3 つの関係を処理します。 厳密な不等式がどちらも成り立たない場合、残る唯一の可能性は次のとおりであるため、等しい場合は最後に配置されます。`x == y`。 この問題では最終的な整数スコアの順序のみが問われているため、1 つずれの懸念はありません。 

各結果はすぐに出力されるため、すべてのテスト ケースやすべての回答をメモリに保存する必要はありません。 

## 実用的な例

 最初のサンプルとして、最初の 3 つのテスト ケースを考えてみましょう。 

| テストケース |`x`|`y`| 比較 | 出力 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 5 |`1 < 5`|`Hamada`|
 | 2 | 2 | 0 |`2 > 0`|`Bashar`|
 | 3 | 0 | 0 |`0 == 0`|`Iskandar`|

 最初のケースでは、スコアが小さい方が負けることが確認されます。 2 つ目は、一方のチームがゴールを持たない境界を行使します。 3 つ目は、平等の場合はどちらかの勝ち分岐ではなく引き分け分岐が選択されることを確認します。 

残りのサンプルケースの場合:

 | テストケース |`x`|`y`| 比較 | 出力 |
 | --- | --- | --- | --- | --- |
 | 4 | 3 | 3 |`3 == 3`|`Iskandar`|
 | 5 | 6 | 2 |`6 > 2`|`Bashar`|

 4 番目のケースは、引き分けが実際のスコア値とは独立して処理されることを示しています。 5つ目は、バシャールがより大きなスコアを持っている場合の通常の勝利ケースを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(T) | 各テスト ケースには 1 つの定数時間比較が必要です。 |
 | スペース | お(1) | 現在のスコアのペアとループ状態のみが保存されます。 |

 このソリューションは、テスト ケースごとに少量の一定量の作業を実行します。 可能な最大スコア値であっても、`10^5`、アルゴリズムが目標自体を反復することはないため、スコアの大きさは実行時間には影響しません。 メモリ使用量も一定で、256 MB の制限を快適に下回っています。 

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline

    t = int(input())

    for _ in range(t):
        x, y = map(int, input().split())

        if x > y:
            print("Bashar")
        elif x < y:
            print("Hamada")
        else:
            print("Iskandar")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

""") == """Hamada

Bashar
""", "sample 1"

""") == """Iskandar
""", "minimum scores and draw"

""", "small scores and equality boundary"

 ## 特殊なケース

 最初の明白ではないケースは引き分けです。 入力用`3 3`、アルゴリズムは最初にチェックします`3 > 3`これは false であり、チェックが行われます。`3 < 3`、これも誤りです。 決勝進出です`else`ブランチとプリント`Iskandar`。 同じ推論が機能します`0 0`したがって、ゼロには別の特殊なケースは必要ありません。 

2番目のケースは、バシャールがゴールがなく、浜田がゴールを持っている場合です。 入力用`0 1`、`x > y`は誤りであり、`x < y`true であるため、アルゴリズムは次のように出力します。`Hamada`。 これにより、ゼロが通常のスコアとして扱われることが確認されます。 

逆の場合、入力`1 0`、最初の分岐に到達します。`1 > 0`、生産`Bashar`。 下限に対する特別な処理は必要ありません。 

上限に次のように入力します。`100000 99999`生成する`Bashar`最初の比較が真であるためです。 入力`99999 100000`生成する`Hamada`、 そして`100000 100000`生成する`Iskandar`。 これらのケースは、アルゴリズムが最大許容値および等値境界付近で正しいままであることを示しています。
