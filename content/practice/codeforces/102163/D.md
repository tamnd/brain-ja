 ## 解決策
 ## 問題の理解

 試合結果は最終ゴール数のみに左右されます。 テストケースごとに、`X`はバシャールのチームが獲得したゴール数であり、`Y`は浜田チームの得点数です。 タスクは、これら 2 つの整数を比較して出力することです。`Bashar`いつ`X`より大きく、`Hamada`いつ`Y`より大きく、そして`Iskandar`それらが等しいとき。 

元のストーリーには、選手、怪我、交代、試合時間に関する多くの詳細が含まれていますが、それらの値はいずれも要求された結果には影響しません。 2 つの最終スコアが提供されると、問題全体は 1 つの比較に減ります。 

各スコアは次の範囲にあります`0`そして`100000`したがって、値は標準の整数型に快適に適合します。 さらに重要なのは、その範囲を探索する必要がまったくないことです。 テスト ケースが多数ある場合でも、ケースごとに一定量の作業を実行するソリューションは、1 秒の制限を十分に満たす速度になります。 費用をかけるアプローチ`O(100000)`すべてのテスト ケースでの演算は既に不必要に高価になる一方、スコア範囲内の二次関数は完全に不適切になります。 

実装が失敗する単純なケースがいくつかあります。 バシャールがもっと目標を持った時、例えば```
1
6 2
```正しい出力は`Bashar`。 スコアが等しいかどうかのみをチェックする不注意な実装では、引き分け以外のすべてを同じ結果として誤って扱う可能性があります。 

浜田がさらにゴールを決めたとき、```
1
1 5
```正しい出力は`Hamada`。 比較を逆にすると、間違った勝者が静かに生成されます。 

等しい場合も重要です。```
1
3 3
```正しい出力は次のとおりです`Iskandar`。 のみを使用した実装`if X > Y`そして`else`間違って印刷されてしまう`Hamada`等価性は個別に処理する必要があるためです。 

最後に、どちらのチームにとってもゼロは有効なスコアです。 のために```
1
0 0
```結果は`Iskandar`したがって、どちらかのチームが少なくとも 1 回は得点したと仮定せずに比較が機能する必要があります。 

## アプローチ

 意図的に総当たり的なアプローチを使用すると、スコア値を 1 つずつ調べ、指定された 2 つのスコアのどちらが大きいかを、可能な範囲をスキャンして決定しようとする可能性があります。`0`に`100000`。 すべての有効なスコアがその範囲内にあるため、最終的には正しい答えが得られますが、2 つの実際の値がすでに利用可能であるという事実は完全に無視されます。 最悪の場合、これは実行されます`100001`1 つのテスト ケースの反復。 あったら`100000`テストケース、それは約に達します`10^10`これは 1 秒の制限をはるかに超えています。 

ブルート フォースは、最終的に関連するスコア値に遭遇するため機能しますが、答えと関係のない値の探索に時間がかかるため失敗します。 重要な観察は、勝者を決定するためには検索がまったく必要ないということです。 与えられた 2 つのスコアの関係はすでに完全な答えです。大きい場合はチームが勝つことを意味し、小さい場合は他のチームが勝つことを意味し、等しい場合は引き分けを意味します。 

したがって、各テスト ケースには、正確に 1 つの比較と 1 つの出力決定が必要です。 これにより、作業がスコア範囲に依存するものからテスト ケースごとの一定量に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(T * 100000)`|`O(1)`| 遅すぎて不必要 |
 | 最適 |`O(T)`|`O(T)`収集された出力の場合 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`T`。 以下の各テスト ケースには、2 つのチームの最終スコアが含まれています。 
2. すべてのテスト ケースについて、次の内容を読んでください。`X`そして`Y`。 入力により得点プロセスの最終結果がすでに得られているため、サッカーの試合のシミュレーションは必要ありません。 
3. 比較する`X`そして`Y`。 もし`X > Y`, バシャールのチームにはより多くの目標があるため、答えは次のとおりです。`Bashar`。 
4. もし`X < Y`, 浜田のチームの方がゴール数が多いので、答えはこうなります。`Hamada`。 
5. どちらのスコアも大きい場合、それらは等しくなければなりません。 その場合は印刷してください`Iskandar`。 
6. 各回答を保存し、入力処理後にすべての回答を印刷します。 文字列を収集すると、繰り返し呼び出しを回避することもできます。`print`個々のテストケースごとに。 

### なぜ効果があるのか

 すべてのテスト ケースについて、相互に排他的な 3 つの関係のうち 1 つだけが、`X`そして`Y`:`X > Y`、`X < Y`、 または`X = Y`。 このアルゴリズムは、これら 3 つの可能性を 3 つの必要な結果に直接マッピングします。`Bashar`、`Hamada`、 そして`Iskandar`。 どちらの最終スコアが大きいかによってのみ勝者が決まるため、選択された結果は常に正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    answers = []

    for _ in range(t):
        x, y = map(int, input().split())

        if x > y:
            answers.append("Bashar")
        elif x < y:
            answers.append("Hamada")
        else:
            answers.append("Iskandar")

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```最初の行は次のようになります`T`これにより、後に続くスコア ペアの数がプログラムに正確に通知されます。 その後、ループは一度に 1 つの完全な一致結果を処理します。 

三方`if`構造体はアルゴリズムを直接実装します。 厳密な比較により、勝者となる可能性のある 2 人が処理されますが、最終的な比較は`else`平等を表します。 通常の整数比較で両方の境界がすでに正しく処理されているため、ゼロまたは最大スコアを特別に処理する必要はありません。 

スコアは最大でも`100000`したがって、整数オーバーフローは Python では問題になりません。 実際、プログラムはスコアの演算をまったく実行せず、比較のみを実行します。 

回答はリストに蓄積され、最後に改行文字で結合されます。 これにより、テスト ケースの数が多い場合でも、出力処理の効率が維持されます。 

## 実用的な例

 サンプル 1 の最初の 2 つのテスト ケースを考えてみましょう。 

| テストケース |`X`|`Y`| 比較 | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 5 |`1 < 5`|`Hamada`|
 | 2 | 2 | 0 |`2 > 0`|`Bashar`|

 最初の試合では、浜田はバシャールの 1 ゴールに対して 5 ゴールを持っているため、2 番目のブランチは`Hamada`。 2 番目の試合では、バシャールは 2 ゴールを持っていますが、浜田は 1 ゴールも持っていないため、最初のブランチは`Bashar`。 これらのケースは、両方向の比較を示しています。 

サンプル 1 の等価の場合は、別の有用なトレースを示します。 

| テストケース |`X`|`Y`| 比較 | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 |`0 == 0`|`Iskandar`|
 | 2 | 3 | 3 |`3 == 3`|`Iskandar`|

 どちらの行でも厳密な比較は成功しません。 アルゴリズムは等価の場合に達し、出力します。`Iskandar`。 これにより、必要に応じて、ゼロゼロ スコアとプラスの引き分けが同じように扱われることが確認されます。 

サンプル 1 の最後の 2 行は、より大きなスコアの境界方向と、別の通常の勝利の両方を実行します。 

| テストケース |`X`|`Y`| 比較 | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | 6 | 2 |`6 > 2`|`Bashar`|
 | 2 | 2 | 0 |`2 > 0`|`Bashar`|

 すべての行を通して不変なのは、答えが 2 つの現在のスコアの順序によってのみ決定されるということです。 別のテスト ケースからの情報が現在の決定に影響することはありません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(T)`| Each test case performs one comparison and constant additional work |
 | スペース |`O(T)`| 出力文字列は印刷される前に保存されます。 

スコア制限は、`100000`アルゴリズムは可能なスコアを反復することがないため、実行時間には影響しません。 多数のテスト ケースでも、ケースごとに 1 つの定数時間比較のみが必要であり、1 秒の制限に十分適合します。 各テスト ケースは 1 つの短い出力文字列のみを提供するため、メモリ使用量も少なくなります。 

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    t = int(input())
    answers = []

    for _ in range(t):
        x, y = map(int, input().split())

        if x > y:
            answers.append("Bashar")
        elif x < y:
            answers.append("Hamada")
        else:
            answers.append("Iskandar")

    sys.stdout.write("\n".join(answers))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 特殊なケース

 スコアが等しい場合は、入力を考慮してください。```
1
3 3
```アルゴリズムは最初にチェックします`3 > 3`これは false であり、チェックが行われます。`3 < 3`、これも誤りです。 残りの可能性は等しいので、出力します。`Iskandar`。 同じ推論が機能します`0 0`そして`100000 100000`。 

片側のスコアがゼロの場合、次のように考えます。```
1
0 7
```最初の比較では、`0 > 7`、は誤りです。 ２回目の比較ですが、`0 < 7`、 true なので、出力は次のようになります。`Hamada`。 整数比較ではゼロは通常どおりに動作するため、特別なゼロのケースはありません。 

逆の状況は、```
1
7 0
```ここ`7 > 0`true であるため、出力は次のようになります`Bashar`。 両方をテストする`0 7`そして`7 0`2 つの入力変数または勝者名を誤って交換する実装を捕捉します。 

上の境界では、```
1
100000 99999
```与える`Bashar`、 その間```
1
99999 100000
```与える`Hamada`。 このアルゴリズムは、より小さい値の場合と同じ 2 つの比較を実行するため、オフバイ 1 の問題は発生しません。`100000`。 

中心的なエッジ ケースは等価です。これは、次のような 2 つの分岐の実装があるためです。`if X > Y: Bashar else: Hamada`平等を浜田の勝利として扱う。 明示的な 3 番目の結果は、正しい解決策とよくある間違いを分けるものです。
