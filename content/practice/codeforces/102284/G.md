 ## 問題の理解

 スイッチを一つずつ受け取ります。 スイッチ`i`整数のラベルがあります`a[i]`、およびラベルが付いた 2 つのスイッチの場合`x`そして`y`接続されている場合、そのチャネルにはコストがかかります`x XOR y`。 入力シーケンスのすべてのプレフィックスについて、すでに到着しているスイッチを正確に含む接続されたネットワークの可能な最小総コストが必要です。 

接続されたネットワークはコストを増加させることなくスパニング ツリーに縮小できるため、各挿入後のタスクは、頂点が現在のスイッチであり、間のエッジの重みが含まれる完全なグラフの最小スパニング ツリーの重みとなります。`x`そして`y`は`x XOR y`。 

最終的なスイッチの数は次のとおりです。`100000`したがって、すべてのプレフィックスに対して MST を最初から再構築するのはコストがかかりすぎます。 サイズのプレフィックスに対する 2 次 Prim 実装でも`k`Θ(`k²`) エッジの比較。 すべての接頭辞を合計すると、これは Θ(`n³`）、 について`3.3 * 10^14`比較する場合`n = 100000`。 二次アルゴリズムや三次アルゴリズムは、通常の競技プログラミングの制限時間に収まりません。 

値が満たされている`0 <= a[i] <= 200000`。 以来`200000 < 2^18`、すべての値に必要なのは、ビット 17 からビット 0 までの 18 バイナリ ビットだけです。この小さなビット幅が、バイナリ トライを有用にする構造上の特性です。 可能なスイッチのペアの数ではなく、ビット数でのアルゴリズム多項式が実現可能です。 

誤って対処しやすい特殊なケースがいくつかあります。 まず、等しい値は別個のスイッチですが、接続コストはゼロです。 入力用`3`価値観を持って`5 5 5`、答えは次のとおりです。`0 0 0`。 等しい値を重複頂点として扱う実装でも、ここで MST 重みを取得できますが、すべての新しい値が新しいトライ リーフを作成すると想定するため、挿入ロジックが簡単に壊れる可能性があります。 

より微妙なケースは、スイッチを追加すると 2 つのバイナリ トライ サブツリー間の最良のエッジが変更され、同時にそれらのサブツリーの 1 つの内部の MST が変更される場合です。 たとえば、`0 7 3`、答えは次のとおりです。`0 7 7`。 挿入後`3`、間の最高のエッジ`{0,3}`そして`{7}`になる`3 XOR 7 = 4`、以前のコストのクロスエッジを置き換えます`7`、しかしサブツリー`{0,3}`それ自体が今、コストのエッジを必要としています`3`。 2 つの変更はキャンセルされます。 新しいスイッチの最近接距離を以前の MST に単純に加算する不用意な解決策では、次の結果が得られます。`7 + 3 = 10`、それは間違いです。 

許可される最上位ビットは、別の境界ケースです。 入力用`3`価値観を持って`0 131072 131073`、答えは次のとおりです。`0 131072 131073`。 以来`131072 = 2^17`、ビット 17 を含める必要があります。 ビット 16 ～ 0 のみを使用すると、最も重要な寄与が自動的に失われ、不正確な結果が生成されます。 

最後に、最初のスイッチにはエッジがまったくないため、その MST コストはゼロです。 のために`2`価値観を持って`0 1`、必要な出力は次のとおりです。`0 1`。 逆のトライ分岐を行う前に答えを更新するコードは、存在しないエッジを誤って導入する可能性があります。 

## アプローチ

 直接的なアプローチは、すべてのプレフィックスを個別に処理することです。 を含むプレフィックスの場合`k`スイッチを使用すると、完全なグラフを暗黙的に構築し、Prim のアルゴリズムを実行できます。 新しく選択した頂点ごとに、残りの頂点をすべてスキャンし、それらの XOR 距離を計算します。 これは正しいです。Prim は常に MST を生成し、完全なグラフには考えられるすべてのチャネルが含まれているからです。 問題は繰り返し作業です。 1 つのプレフィックスには Θ(`k²`)、すべてのプレフィックスにコストがかかります`1² + 2² + ... + n² = Θ(n³)`。 

のために`n = 100000`、それはおおよそです`3.33 * 10^14`ペアチェックですが、実用的とは言えません。 

重要な観察は、XOR をその最大の異なるビットで調べることから得られます。 すべての値が何らかの固定プレフィックスを共有していることを考慮し、それらの次の関連ビットが`b`。 それらを次のように分割します`L`、誰のビット`b`がゼロであり、`R`、誰のビット`b`は 1 つです。 内側のあらゆるエッジ`L`そして内側のあらゆるエッジ`R`ビットがある`b`ゼロに等しい。 間のすべてのエッジ`L`そして`R`ビットがある`b`1に等しい。 このトライ ノード内ではすべての上位ビットが等しいため、すべての内部エッジはすべてのクロス エッジよりも厳密に安価になります。 

つまり、クラスカルは完全に接続することになります`L`そして`R`それらの間のエッジを考慮する前に、内部的に。 両側が接続された後は、クロス エッジが 1 つだけ必要になります。 したがって、可能な限り安価なクロス エッジは、次の値の間の最小 XOR になります。`L`と値`R`。 

これにより基本的な回帰が得られます。`MST(node) = MST(left) + MST(right) + minimum_cross(node)`、

 ここで、2 つの子のいずれかが空の場合、最後の項はゼロになります。 

バイナリ トライは、これらの再帰的パーティションを正確に表します。 残りの問題は動的です。1 つの値を挿入した後、変更できるのはその値のルートからリーフへのパス上のトライ ノードだけです。 このような各ノードでは、選択された子の内部 MST がトライのより深いところで変更され、新たに考えられるクロス エッジは、新しく挿入された値から反対側の子へのエッジだけです。 

したがって、すべてのトライノードについて、その 2 つの子を接続する現在の最も安価なエッジを維持します。 新しい価値観が生まれるとき`x`が挿入されたら、私たちはその真実の道を歩きます。 ビットに対応するノードで`b`、反対側の子がすでに存在する場合は、そのサブツリーに対して値を最小化するクエリを実行します。`x XOR y`。 これにより、ノードのクロス エッジを改善できる唯一の新しい候補が得られます。 新しいクロスエッジ コストと古いクロスエッジ コストの差によってグローバル MST の答えを更新します。 

最小 XOR クエリ自体は、標準のバイナリ トライ グリーディ ウォークです。 すべての下位ビットで、同じビットを含むブランチを優先します。`x`なぜなら、それは XOR に寄与しないからです。 その分岐が存在しない場合は、他の分岐を選択し、対応する 2 のべき乗をクエリ結果に追加します。 

ブルート フォースは、すべてのペアの関係を明示的に再計算するため機能します。 その情報のほとんどすべてが連続するプレフィックス間で変更されていないため、この処理は失敗します。 MST がバイナリ プレフィックスに沿って分解するという観察により、ルートからリーフへのパスを 1 つだけ更新でき、各クロスエッジ クエリは別のトライ ウォークになります。

## アルゴリズムのチュートリアル

 1. これまでに挿入されたすべての値を含む、最初は空のバイナリ トライを構築します。 各トライ ノードは、その 2 つの子と、それらの子を接続する現在の最小 XOR エッジを格納します。 

ルートは、挿入されたすべてのスイッチを表します。 ビット 17 に続き、次にビット 16 というように、バイナリ プレフィックスに従ってスイッチが分割されます。 
2. 受信値ごとに`x`、ルートから開始して、次のビットに対応するパスをたどります。`x`ビット 17 からビット 0 まで。 

このパス上のノードのみが次の場合に変更できます。`x`が追加されます。 他のすべてのトライ ノードには、以前とまったく同じ古いスイッチのセットが含まれています。 
3. ビットに対応するノードで`b`、と同じビットを含む子を識別します。`x`そして向かいの子。 

反対側の子が存在しない場合は、挿入前にクロス エッジがなく、挿入後もクロス エッジが存在しません。 一致する子のみを続行します。 
4. 反対の子が存在する場合は、そのサブツリーに次の最小 XOR をクエリします。`x`、以下のビットのみを考慮します`b`。 

現在のビットが正確に寄与します`2^b`二人の子供は少し違うから`b`。 下位ビットのトライ クエリは、エッジの重みの残りの部分を決定します。 
5. この候補クロスエッジ重みをノードに保存されている値と比較します。 

この挿入によって導入される新しいエッジは、`x`古いスイッチに。 このノードの 2 つの子を横切るエッジの中には、すべての古いペアがすでに存在していました。 したがって、古い最小値は変更されないままであるか、またはからのエッジによって置き換えられることしかありません。`x`反対側の子の最も近い値にします。 
6. 候補が小さい場合は、保存されているクロスエッジ値を置き換えて、その差をグローバル MST 応答に追加します。 

ここでの減少は可能です。 たとえば、挿入するとき`3`の中へ`{0,7}`、ルートのクロスエッジは から改善されます。`7`に`4`。 同時に、より深いノードが内部エッジを獲得します。`0 XOR 3 = 3`。 グローバルアンサーには両方の変更が記録されており、`7 - 3 + 3 = 7`。 
7. 一致する子がまだ存在しない場合は作成し、次の下位ビットに進みます。 

トライ パスの作成は反対側のサブツリーをチェックした後に行われるため、すべてのクエリでは現在の挿入前に存在していたスイッチのみが考慮されます。 
8. 18 ビットすべてを処理した後、現在のグローバル応答を出力に追加します。 

1 つのスイッチにはエッジがないため、当然、答えは 0 のままになります。 

### なぜ効果があるのか

 すべてのトライ ノードについて、そのサブツリー内のすべての値は同じ上位バイナリ プレフィックスを持ちます。 その子が少しでも異なる場合`b`、2 つの子を横切るすべてのエッジは同じより高い寄与を持ち、ビットを持ちます。`b`セットされますが、1 つの子の内側にあるすべてのエッジはビットを持ちます`b`設定を解除します。 その結果、すべての内部エッジはすべての交差エッジよりも安価になります。 クラスカルはクロス エッジを使用する前に 2 つの子部分問題を完了する必要があり、それらを接続するには最小のクロス エッジが 1 つあれば十分です。 これは再帰的 MST 分解を証明します。 

挿入中、新しい値のトライ パスの外側にあるすべてのノードにはまったく同じ頂点が含まれるため、それらの MST コストとクロスエッジ最小値は変更できません。 パス ノードでは、新しく利用可能なクロス エッジは、新しい値に付随するものだけです。 try クエリは、そのような最も安価なエッジを見つけます。 したがって、保存されたクロスエッジ最小値の更新は正確であり、変更されたすべてのノード寄与の合計が正確に新しい MST 重みになります。 挿入ではなく帰納法により、報告されるすべての答えが最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAX_BIT = 17

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # Each node has two children.
    # -1 means that the child does not exist.
    left = [-1]
    right = [-1]

    # cross[v] is the minimum XOR edge between the two
    # children of v. Zero means that one child is absent.
    cross = [0]

    answer = 0
    out = []

    for x in a:
        node = 0

        for b in range(MAX_BIT, -1, -1):
            bit = (x >> b) & 1

            if bit == 0:
                opposite = right[node]
            else:
                opposite = left[node]

            if opposite != -1:
                # Find the minimum XOR between x and a value
                # in the opposite subtree, using lower bits.
                cur = opposite
                lower_xor = 0
                k = b - 1

                while k >= 0:
                    xb = (x >> k) & 1

                    if xb == 0:
                        nxt = left[cur]
                        if nxt == -1:
                            nxt = right[cur]
                            lower_xor |= 1 << k
                    else:
                        nxt = right[cur]
                        if nxt == -1:
                            nxt = left[cur]
                            lower_xor |= 1 << k

                    cur = nxt
                    k -= 1

                candidate = (1 << b) + lower_xor
                old = cross[node]

                if old == 0 or candidate < old:
                    cross[node] = candidate
                    if old == 0:
                        answer += candidate
                    else:
                        answer += candidate - old

            # Move down the trie, creating the new path if necessary.
            if bit == 0:
                nxt = left[node]
                if nxt == -1:
                    nxt = len(left)
                    left.append(-1)
                    right.append(-1)
                    cross.append(0)
                    left[node] = nxt
            else:
                nxt = right[node]
                if nxt == -1:
                    nxt = len(left)
                    left.append(-1)
                    right.append(-1)
                    cross.append(0)
                    right[node] = nxt

            node = nxt

        out.append(str(answer))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```3 つの配列はバイナリ トライを表します。`left[v]`そして`right[v]`子どもたちを特定しながら、`cross[v]`2 つの子サブツリーを結合する最も安価なエッジを格納します。 頂点自体をトライノード内に保存する必要はありません。 

ループオーバー`b`新しい値は、関連する最上位ビットから最下位ビットまで続きます。 関連する最上位ビットは 17 です。`200000 < 2^18`。 すべての正当な入力には 18 ビットを使用すれば十分ですが、ビット 18 から開始しても機能しますが、不必要な作業が追加されます。 

一致する子に到達する前に、コードは反対側の子を検査します。 この順序が重要です。 新しいスイッチはまだトライに接続されていないため、反対側のサブツリーには以前に挿入されたスイッチのみが含まれている必要があります。 そうしないと、クエリで誤って使用される可能性があります。`x`自分自身を自分のパートナーとして。 

クエリはルートからではなく、反対側の子から直接開始されます。 現在のビットで`b`、2 つの子のプレフィックスはすでに異なっているため、そのビットの寄与は次のようになります。`2^b`。 下位ビットのみを最適化する必要があります。 これが、クエリが次から始まる理由です。`b - 1`。 

優先トライブランチが見つからない場合、クエリは他のブランチを選択し、対応するビットを`lower_xor`。 これは正確に最小限の XOR 検索を実装します。一致するビットはゼロに寄与するため、常に優先されます。 

の`cross`value はセンチネルとして 0 を使用します。2 つの異なる子の間の実際のエッジには少なくとも 1 つの異なるビットがあるため、その XOR 値は正になります。 等しいスイッチ ラベルは同じトライ リーフ内に残り、正のクロス エッジを作成することはありません。 

Python の整数は、潜在的に大きくなる可能性のある MST 合計を自動的に処理するため、オーバーフローの問題はありません。 いずれの場合でも、考えられる最大の答えは Python の整数機能の範囲内に十分収まります。

 | --- | --- | --- |
 | 時間 |`O(n log^2 A)`| がある`O(log A)`トライレベル、および各レベルでの最小 XOR クエリは`O(log A)`|
 | スペース |`O(n log A)`| せいぜい`O(n log A)`トライノードが作成される |

 ここ`A <= 200000`したがって、関連するビットは 18 個だけです。 各挿入では最大 18 回の最小 XOR 検索が実行され、下位ビット ステップの合計数は最大で`17 + 16 + ... + 0`これは、挿入あたりわずか 153 トライ ステップです。 のために`100000`これは、約 1,530 万の内部クエリ ステップに、通常のトライ挿入作業を加えたものになります。 

メモリ使用量も管理可能です。 実際には、それしかないので、`2^18`可能な値を使用すると、完全なバイナリ トライには以下の値が含まれます。`2^19`ノード、一般的なものであっても、`O(n log A)`分析には境界があれば十分です。 

## テストケース```python
# Helper: run the solution logic on an input string and return its output.
import sys
import io

MAX_BIT = 17

def solve_data(data: str) -> str:
    inp = io.StringIO(data)
    n = int(inp.readline())
    a = list(map(int, inp.readline().split()))

    left = [-1]
    right = [-1]
    cross = [0]

    answer = 0
    out = []

    for x in a:
        node = 0

        for b in range(MAX_BIT, -1, -1):
            bit = (x >> b) & 1

            if bit == 0:
                opposite = right[node]
            else:
                opposite = left[node]

            if opposite != -1:
                cur = opposite
                lower_xor = 0
                k = b - 1

                while k >= 0:
                    xb = (x >> k) & 1

                    if xb == 0:
                        nxt = left[cur]
                        if nxt == -1:
                            nxt = right[cur]
                            lower_xor |= 1 << k
                    else:
                        nxt = right[cur]
                        if nxt == -1:
                            nxt = left[cur]
                            lower_xor |= 1 << k

                    cur = nxt
                    k -= 1

                candidate = (1 << b) + lower_xor
                old = cross[node]

                if old == 0 or candidate < old:
                    cross[node] = candidate
                    answer += candidate if old == 0 else candidate - old

            if bit == 0:
                nxt = left[node]
                if nxt == -1:
                    nxt = len(left)
                    left.append(-1)
                    right.append(-1)
                    cross.append(0)
                    left[node] = nxt
            else:
                nxt = right[node]
                if nxt == -1:
                    nxt = len(left)
                    left.append(-1)
                    right.append(-1)
                    cross.append(0)
                    right[node] = nxt

            node = nxt

        out.append(str(answer))

    return "\n".join(out)

def run(inp: str) -> str:
    return solve_data(inp)

# Provided sample
assert run("6\n4 0 2 2 9 4\n") == "0\n4\n6\n6\n15\n15", "sample 1"

# Minimum-size input
assert run("2\n0 1\n") == "0\n1", "minimum size"

# All values equal
assert run("4\n123 123 123 123\n") == "0\n0\n0\n0", "all equal"

# Highest allowed bit and a lower-bit refinement
assert run("3\n0 131072 131073\n") == "0\n131072\n131073", "bit 17 boundary"

# Cases where the new vertex changes different trie levels
assert run("4\n0 7 3 4\n") == "0\n7\n7\n10", "multiple levels"

# Maximum-size input, all equal, answer always zero
vals = " ".join(["0"] * 100000)
expected = "\n".join(["0"] * 100000)
assert run("100000\n" + vals + "\n") == expected, "maximum size"

 ## 特殊なケース

 値が重複する場合はトライによって自然に処理されます。 入力用`4`価値観を持って`123 123 123 123`、すべての新しい値は、最初の値とまったく同じパスに従います。 どのレベルでも反対の子は作成されないため、クロスエッジの寄与は変化しません。 出力は`0 0 0 0`。 スイッチは依然として個別の頂点ですが、等しいラベルを接続する場合のコストはゼロです。 

トライには以前の値が含まれていないため、最初の挿入では反対側のサブツリーがどこにもありません。 入力用`2`価値観を持って`0 1`、最初の答えは`0`。 いつ`1`が挿入され、2 つの値は最初にビット 0 で異なり、そのビットの下のクエリは空で、新しいクロス エッジにはコストがかかります。`1`。 出力は`0 1`。 

最大値境界はビット 17 を使用します。入力の場合`3`価値観を持って`0 131072 131073`、挿入`131072`ビット 17 で分割を作成し、追加します`2^17 = 131072`。 いつ`131073`が到着すると、それは同じビット 17 サブツリーに属します。`131072`ビット 0 のみが異なるため、MST の方がコスト面で有利になります。`1`。 出力は`0 131072 131073`。 

最も欺瞞的なケースは、`0 7 3`。 後`0`そして`7`、唯一のエッジにコストがかかります`7`。 いつ`3`が到着すると、根元の最高のクロスエッジが向上します。`7`に`3 XOR 7 = 4`、ルートの寄与を減らす`3`。 下位ビットでは、`0`そして`3`分割、コストの新たな内部エッジ`3`が表示されます。 2 つの変更はキャンセルされ、答えは次のとおりになります。`7`。 アルゴリズムが新しいスイッチを以前の MST に追加された単一のエッジとして扱うのではなく、挿入パス上のすべてのトライ ノードを更新するのはまさにこのためです。 

最後のサンプルでは、​​いくつかのトライ レベルがすでに構築された後、重複挿入も実行されます。 で`4 0 2 2 9 4`、2番目`2`そして二番目`4`保存されたクロスエッジは改善されないため、それぞれの挿入時に答えは変化しません。 トライ構造と最小 XOR クエリがすでにゼロコスト接続を考慮しているため、このアルゴリズムでは特別な重複処理は必要ありません。
