 ## 解決策
 ## 問題の理解

 (n \times m) 個の高さマップがあります。 ブラウザは、(a) 連続した行と (b) 連続した列を正確に含む任意の四角形を表示できます。 その長方形のすべての可能な位置について、その最小の高さが必要であり、最後にそれらの最小値すべての合計が必要です。 

高さは明示的には指定されていません。 代わりに、それらは再発によって生成されます。 

[
 g_i=(g_{i-1}x+y)\bmod z、
 ]

 そして、行列はこのシーケンスから行ごとに埋められます。 したがって、ゼロベースの座標を使用する場合、セル ((r,c)) にはインデックス (rm+c) を持つシーケンス要素が含まれます。 

この制約により、両方の次元が (3000) に達することが許可されるため、行列には​​ (9)00 万個のセルを含めることができます。 (a\times b) 個の四角形のすべてのセルを検査するアルゴリズムは、あまりにも高価すぎます。 (a=b=1500) の場合でも、考えられる四角形はおよそ (225) 万個あり、それぞれに (225) 万個のセルが含まれており、約 (5\times10^{12}) 回の比較が行われます。 このソリューションでは、各行列セルを一定の回数だけ処理する必要があります。 

また、数値的に考慮すべき点が 2 つあります。 生成される高さは (10^9) 未満ですが、答えにはそのような値がほぼ (9)00 万個含まれる可能性があるため、答えはおおよそ (9\times10^{15}) に達する可能性があります。 Python 整数はこれを自動的に処理しますが、すべての高さは (10^9) 未満であるため、保存される高さにはコンパクトな 32 ビット表現で十分です。 

小さなエッジケースは 1 セル画面です。 のために```
1 1 1 1
5 0 0 10
```表示されている唯一の長方形には高さ (5) が含まれているため、答えは (5) になります。 ウィンドウに少なくとも 2 つのセルがあることを前提としたソリューション、または 2 番目の位置が表示されるまで最小値の記録を遅らせるソリューションでは、誤ってゼロが生成される可能性があります。 

ウィンドウが全幅の場合、別の境界ケースが発生します。 のために```
2 3 1 3
1 1 0 100
```生成された行列は

 [
 \begin{p行列}
 1&1&1\
 1&1&1
 \end{p行列}、
 ]

 したがって、表示される長方形はちょうど 2 つあり、答えは (2) になります。 列 (b) で回答の生成を開始する水平スライディング ウィンドウの実装では、間違った出力インデックスが使用されると、最初のウィンドウが失われる可能性があります。 

(a=n) の場合、垂直方向にも同じ問題が発生します。 のために```
3 1 3 1
4 1 0 100
```すべてのセルは (4) であり、(3\times1) 個の四角形は 1 つだけあり、答えは (4) です。 垂直キューには、(a+1) 行ではなく、正確に現在の (a) 行が含まれている必要があります。 

## アプローチ

 直接的なアプローチは、考えられるすべての左上隅を列挙し、その四角形内のすべての (a b) セルをスキャンすることです。 ((n-a+1)(m-b+1)) 個の長方形があるため、実行時間は次のようになります。 

[
 O((n-a+1)(m-b+1)ab),
 ]

 これは最悪の場合 (O(n^2m^2)) です。 (n=m=3000) では、これは完全に不可能です。 

最初の有用な観察は、2 次元の最小値が 2 つの 1 次元の最小値演算に分離できることです。 1 つの固定行を考えてみましょう。 その行のすべての長さ (b) セグメントの最小値がわかっている場合、(a\times b) の長方形を、その​​行の最小値 (a) の垂直ウィンドウに縮小できます。 これらの (a) 値の最小値を取ると、長方形全体の正確な最小値が得られます。 

残りの問題は、すべての 1 次元スライディング ウィンドウ最小値を効率的に計算する方法です。 単調キューは、候補位置をその値の昇順に保持します。 新しい値が挿入されると、その後ろにある大きな値はすべて破棄される可能性があります。これは、新しい値の方が小さくて新しいためです。そのため、破棄された値が、新しい値が期限切れになるまでの将来のウィンドウの最小値になることはありません。 したがって、キューの先頭は現在のウィンドウの最小値になります。 

これを水平方向に 1 回、垂直方向に 1 回適用します。 水平パスは (n(m-b+1)) 個の中間最小値を生成します。 垂直パスはこれらの値を消費し、完成したすべての (a) 要素ウィンドウを答えに直接追加します。 

標準の C++ 実装では、中間行列を整数として保存できます。 Python では、何百万もの値を通常の整数として保存すると、より多くのメモリが使用されるため、以下の実装では`array('I')`、コンパクトな 32 ビット符号なし整数配列。 これにより、同じ (O(nm)) アルゴリズムを維持しながら、最悪の場合でも中間行列が約 36 MB に保たれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O((n-a+1)(m-b+1)ab)) | (O(1)) 入力生成以外にも | 遅すぎる |
 | 2 つの単調パス | (O(nm)) | (O(n(m-b+1))) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 繰り返しから行ごとに行列を生成します。 各行はすぐにその水平ウィンドウの最小値に縮小できるため、元の行列全体を一度に必要とすることはありません。 
2. すべての行に対して、列インデックスの単調増加キューを維持します。 列 (c) を挿入する前に、現在の長さ (b) ウィンドウの外側にあるインデックスを削除します。 次に、インデックスの高さが少なくとも新しい高さになる間に、インデックスを背面から削除します。 フロントは現在の水平ウィンドウの最小値を識別します。 
3. 水平方向の最小値をコンパクトな配列に格納します。 行 (r) の場合、水平位置 (c) の値は、列 (​​c) から (c+b-1) までの元のセルの最小値を表します。 このような値は行ごとに (m-b+1) 個あります。 
4. 中間配列のすべての列を別の単調キューで処理します。 キューには列インデックスではなく行インデックスが含まれるようになりました。 行 (r) が到着したら、(a) より古い行を削除し、後ろから大きい値を破棄し、最小の候補を前に保持します。 
5. (a) 行が処理されると、キュー先頭の値は、対応する (a\times b) 長方形の最小値になります。 すぐに回答に追加してください。 長方形の最小値の最終行列を保存する必要はありません。 
6. 蓄積された回答を印刷します。 合計が (2^{32}) よりもはるかに大きくなる可能性があるため、Python の整数型がこの変数に使用されます。 

### なぜ効果があるのか

 すべての行について、水平キューはその先頭で現在の (b) セル間隔の最小値を正確に維持します。 したがって、各中間値は、最終的な長方形の 1 つの完全な水平ストリップの最小値になります。 これらの中間値の固定列の場合、(a) 連続する水平ストリップ最小値の最小値は、対応する (a\times b) 長方形内のすべてのセルの最小値に等しくなります。 2 番目の単調キューは、その垂直方向の最小値を正確に維持するため、すべての長方形がその真の最小値を 1 回だけ答えに寄与します。 

キューの不変条件は、そのインデックスが現在のウィンドウ内にあり、対応する値が減少しないことです。 後方から大きな値を削除しても、新しく挿入された値は小さく、期限切れになることがないため、将来の最小値が失われることはありません。 期限切れのフロント要素は現在のウィンドウに所属できなくなるため、削除しても安全です。 したがって、前面は常に必要な最小値を表します。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    n, m, a, b = map(int, input().split())
    g, x, y, z = map(int, input().split())

    w = m - b + 1

    # Horizontal minima. Heights are < 1e9, so unsigned 32-bit
    # integers are sufficient. Preallocating avoids the memory
    # overhead of millions of Python int objects.
    horizontal = array('I', [0]) * (n * w)

    # Monotonic queue of column indices for one row.
    q = [0] * m

    for r in range(n):
        row = [0] * m
        for c in range(m):
            row[c] = g
            g = (g * x + y) % z

        head = 0
        tail = 0
        base = r * w

        for c in range(m):
            # Remove columns that are left of the current
            # length-b window.
            while head < tail and q[head] <= c - b:
                head += 1

            # Keep values in increasing order.
            value = row[c]
            while head < tail and row[q[tail - 1]] >= value:
                tail -= 1

            q[tail] = c
            tail += 1

            if c >= b - 1:
                horizontal[base + c - b + 1] = row[q[head]]

    # Vertical pass. The queue contains row indices.
    q = [0] * n
    answer = 0

    for c in range(w):
        head = 0
        tail = 0

        for r in range(n):
            pos = r * w + c
            value = horizontal[pos]

            # Remove rows outside the current length-a window.
            while head < tail and q[head] <= r - a:
                head += 1

            # Remove values that cannot become a future minimum.
            while head < tail:
                back_row = q[tail - 1]
                back_value = horizontal[back_row * w + c]
                if back_value < value:
                    break
                tail -= 1

            q[tail] = r
            tail += 1

            if r >= a - 1:
                answer += horizontal[q[head] * w + c]

    print(answer)

if __name__ == "__main__":
    solve()
```最初の部分はジェネレーターのパラメーターを読み取り、計算します。`w`、各行の水平ウィンドウの数。 以来`w = m-b+1`、中間配列には、2 番目のパスで必要な値が正確に含まれています。 

の`horizontal`配列は符号なし 32 ビット型コードを使用します`I`。 生成されるすべての高さは (0) から (z-1)、および (z\le10^9) の範囲内にあるため、保存された高さがこの表現をオーバーフローすることはできません。 最大 900 万個の Python 整数の通常のリストでは大幅に多くのメモリを消費するため、コンパクトな配列は Python で役立ちます。 

各行について、`q`手動で実装された両端キューとして使用される配列です。`head`最初のアクティブな要素を指し、`tail`最後のアクティブ要素の 1 つ後の位置を指します。 繰り返し呼び出すのではなくインデックスを使用する`popleft`多くの Python オブジェクトの作成を回避し、ホット ループをシンプルに保ちます。 

有効期限条件`q[head] <= c-b`これは、インデックスが少なくとも次の値でなければならないと言っているのと同じです`c-b+1`、これは現在のウィンドウの左端点です。 最初の横の答えが表示されるのは、`c == b-1`これは、完全な (b) 要素間隔が存在する最初の列であるためです。 

垂直パスは同じキューのアイデアを使用しますが、キューには行インデックスが格納されます。 条件`q[head] <= r-a`現在の行から (a-1) 位置以上後ろにある行を削除します。 完全な垂直ウィンドウが最初に存在するのは、`r == a-1`。 

ジェネレーターの更新は、現在のセルを割り当てた直後に行われます。 これはシーケンスの定義と一致します。最初のセルは (g_0) を受け取り、次のセルは 1 つの反復ステップによって生成された値を受け取ります。 

掛け算`g * x`ほぼ (10^{18}) に達する可能性があり、これは Python の任意精度の整数範囲内に十分収まります。 最終的な答えは約 (9\times10^{15}) に達することもあるため、明示的なオーバーフロー処理は必要ありません。

    n, m, a, b = map(int, input().split())
    g, x, y, z = map(int, input().split())

    w = m - b + 1
    horizontal = array('I', [0]) * (n * w)

    q = [0] * m

    for r in range(n):
        row = [0] * m

        for c in range(m):
            row[c] = g
            g = (g * x + y) % z

        head = 0
        tail = 0
        base = r * w

        for c in range(m):
            while head < tail and q[head] <= c - b:
                head += 1

            value = row[c]
            while head < tail and row[q[tail - 1]] >= value:
                tail -= 1

            q[tail] = c
            tail += 1

            if c >= b - 1:
                horizontal[base + c - b + 1] = row[q[head]]

    q = [0] * n
    answer = 0

    for c in range(w):
        head = 0
        tail = 0

        for r in range(n):
            value = horizontal[r * w + c]

            while head < tail and q[head] <= r - a:
                head += 1

            while head < tail:
                br = q[tail - 1]
                if horizontal[br * w + c] < value:
                    break
                tail -= 1

            q[tail] = r
            tail += 1

            if r >= a - 1:
                answer += horizontal[q[head] * w + c]

    print(answer)

        solve()
        return sys.stdout.getvalue().strip()
    finally:

 ## 特殊なケース

 ### 1 セル行列

 のために```
1 1 1 1
5 0 0 10
```水平パスは列 (0) を処理し、ただちに唯一の水平最小値 (5) を作成し、垂直パスは行 (0) を処理し、(r=a-1=0) であるためすぐに (5) を加算します。 最終的な答えは(5)です。 ウィンドウ サイズが 1 の場合でも同じウィンドウ完了条件が機能するため、実装には特別なケースは必要ありません。 

### 全幅に等しいウィンドウ

 のために```
2 3 1 3
1 1 0 100
```生成される値はすべて (1) です。 (b=3) なので、水平キューは列 (2) まで中間値を生成しません。 その時点で、唯一の水平ウィンドウが最小値 (1) を持ちます。 垂直パスには (a=1) があるため、2 つの行のそれぞれが 1 つの値に寄与します。 結果は (1+1=2) となります。 

表現`c >= b - 1`これにより、最初の完全な水平ウィンドウが正確に右側の境界に表示されます。 

### 窓全体の高さに等しい

 のために```
3 1 3 1
4 1 0 100
```生成される 3 つの値はすべて (4) です。 水平パスでは、行ごとに 1 つの値が生成されます。 垂直パス中、行 (0) と (1) はまだ完全な (a=3) ウィンドウを形成していません。 行 (2) では、キューに 3 行すべてが含まれるため、最小値 (4) が 1 回だけ追加されます。 答えは(4)です。 

表現`r >= a - 1`これにより、完全な垂直ウィンドウが存在する前にアルゴリズムが結果を生成することがなくなります。 

### キュー内の同じ高さ

 いくつかの連続するセルが同じ最小値を持つと仮定します。 実装では、次を使用して値を削除します。`>=`、だけではなく`>`。 最新の等しい値は古い等しい値よりも後に期限切れになるため、この値を保持しておけば十分です。 最小値自体は変わりませんが、キューは短くなります。 これが、個別の重複値ルールを必要とせずに、すべてが等しいテストが正しいままである理由です。 

### 大きな回答

 最大 ((n-a+1)(m-b+1)) 個の四角形が存在でき、これは最大 (9)00 万個です。 それぞれの最小値は (10^9) より小さいため、答えは (9\times10^{15}) に近づく可能性があります。 保存された行列値は 32 ビット整数を使用しますが、`answer`意図的に通常の Python 整数のままにしておきます。 整数幅が固定されている言語では、答えに 32 ビット アキュムレータを使用すると、静かにオーバーフローが発生します。 

### 最大寸法

 (n=m=3000) の場合、行列には (9)00 万個のセルが含まれます。 水平中間配列には、最大でも同じ数の値が含まれます。 Python リストには参照と個別の整数オブジェクトが格納され、生の値の数倍のメモリを消費する可能性があります。`array('I')`は各高さを 4 バイトで格納するため、最悪の場合の中間行列は約 (36) MB を占有します。 キューと現在の行は (O(n+m)) のみで、256 MB の制限を下回る十分な余地が残っています。
