 ## 問題の理解

 アーカイブされた Codeforces コンテストでは、問題 B が «Бользие часы и маленькая окружность» としてリストされており、制限時間は 2 秒、メモリは 512 MB です。 

幾何学的設定は、中心にある 1 つの小さな円と、その周りに対称的に配置された (n 個の) 同一の大きな円で構成されます。 小さな円には半径 (r) があります。 すべての大きな円は外側で小さな円と接触しており、隣接するすべての大きな円のペアも互いに接触しています。 タスクは、それぞれの大きな円の半径 (R) を決定することです。 

重要な点は、大きな円の中心が正(n)角形を形成していることです。 2 つの円は外接しているため、共通の中心からすべての大きな円の中心までの距離は (R+r) になります。 同時に、2 つの隣接する大きな円の中心は互いに接触しているため、正確に (2R) 離れています。 

制約は (3 \le n \le 100) と (1 \le r \le 100) と小さいです。 これは、複雑な定数時間の幾何学的計算であっても十分に高速であり、円を反復する必要がないことを意味します。 本当の問題は数値の精度であり、実行時間ではありません。 必要な答えは実数であるため、実装では浮動小数点演算を使用し、十分な桁数を出力する必要があります。 

一見合理的に見える実装が間違っている可能性があるエッジケースがいくつかあります。 (n=6) かつ (r=1) の場合、答えは正確に (1) になります。 6 つの大きな円は小さな円の周りに正六角形を形成し、その中心は中心から距離 (2) の位置にあります。 半角 (\pi/n) が必要な場合に中心角全体 (2\pi/n) を使用する式では、間違った半径が得られます。

 直接的な総当たりアプローチでは、(R) を数値的に検索できます。 (n\ge3) と (r\l​​e100) なので、実際の答えは (647) 以下になります。 すべての候補を (10^{-6}) のステップで試した場合、最悪の場合、およそ (6 億 4,700 万) 個の候補を検査することになります。 各候補は幾何学的な接線条件をチェックする必要があるため、このアプローチは 2 秒の制限の合理的な範囲をはるかに超えています。 要求される応答は連続的であり、チェッカーは小さな絶対誤差または相対誤差を予期するため、ステップが大きいほど安全ではありません。 

二分探索はすでにはるかに優れています。 選択した (R) について、隣接する大きな円の中心間の距離を計算し、それを (2R) と比較できます。 (R) ではこの条件が単調であるため、倍精度を得るには約 60 ～ 100 回の二分探索反復で十分です。 このような解決策は受け入れられますが、幾何学が直接方程式を与える場合、それは依然として数値方程式を反復的に解くことになります。 

有益な観察は、大きな円の中心が正(n)角形を形成しているということです。 小さな円の中心、隣接する 2 つの大きな円の中心、およびそれら 2 つの大きな円の中心を結ぶ線分の中点を考えてみましょう。 これにより直角三角形が作成されます。 共通の中心と大きな円の中心を結ぶ斜辺は (R+r) です。 反対側は (R) です。隣接する大円の中心間の距離全体が (2R) であるため、その半分が (R) になります。

 ## アルゴリズムのチュートリアル

 1. 大きな円の数 (n) と小さな円の半径 (r) を読み取ります。 テスト ケースは 1 つだけであるため、外部のテスト ケース ループは必要ありません。 
2. 半角を計算します。 

[
 \theta=\frac{\pi}{n}。 
】

 隣接する中心は角度 (2\pi/n) で分離されており、直角三角形の構築ではその角度の半分が使用されます。 
3. コンピューティング

 [
 s=\sin(\シータ)。 
】

 直角三角形では、(R) は (\theta) の反対側で、(R+r) は斜辺であり、(s=R/(R+r)) となります。 
4. 式を並べ替えて次の値を取得します。 

[
 R=\frac{rs}{1-s}。 
]

 (n\ge3)、つまり (0<\pi/n\le\pi/3)、したがって (0<s<1) であるため、分母は正です。 
5. (R) を小数点以下の桁数を十分に指定して出力します。 小数点以下 10 桁の場合、必要な許容誤差よりもかなり高い精度が得られます。 

これが機能する理由: すべての大きな円の中心は、小さな円の中心から同じ距離 (R+r) に位置し、隣接する中心は (2R) 離れていなければなりません。 これら 2 つの事実は、3 つの中心によって形成される二等辺三角形を一意に決定します。 この三角形を半分に分割すると、正弦関係が正確に (R/(R+r)=\sin(\pi/n)) となる直角三角形が得られます。 アルゴリズムはこの方程式を代数的に解くため、出力される値は両方の接線要件を満たす固有の半径になります。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n, r = map(float, input().split())

    s = math.sin(math.pi / n)
    R = r * s / (1.0 - s)

    print(f"{R:.10f}")

if __name__ == "__main__":
    solve()
```最初の行は 2 つの幾何学的パラメーターを読み取ります。 (n) は数学的には整数ですが、浮動小数点値として読み取っても問題はなく、次の式を使用できます。`math.pi / n`直接書かれること。 

変数`s`(\sin(\pi/n)) を格納します。これは、式で必要となる唯一の非自明な幾何量です。 半径は次から取得されます。`r * s / (1.0 - s)`。 

分母は次のようにする必要があります`1.0 - s`、 ない`s - 1.0`。 後者は負の半径を生成します。 半角は次のようにする必要があります。`math.pi / n`、 ない`2 * math.pi / n`直角三角形には、隣接する円の中心間の角度の半分が含まれるためです。 

Python の整数には任意の精度があり、実際の計算には浮動小数点値が使用されるため、整数のオーバーフローの問題はありません。 取り得る値も十分小さいため、通常の倍精度で十分な精度が得られます。 

出力では小数点以下 10 桁が使用されます。 通常は 7 桁または 8 桁を印刷すれば十分ですが、10 桁であれば、必要なエラー許容範囲に十分な余裕が得られます。
