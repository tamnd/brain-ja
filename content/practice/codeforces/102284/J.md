 ## 問題の理解

カードを表現する便利な方法は配列を使用することです`limit[26]`、 どこ`limit[c]`文字を含むカードの数です`c`。 部分文字列は、すべての文字の頻度が最大でも次の対応する値以下の場合に有効です。`limit`。

## アプローチ

 最も直接的な解決策は、エンドポイントのすべてのペアを考慮します。 左の端点ごとに、右の端点を拡張し、現在の部分文字列内の文字の頻度を維持します。 すべての周波数がカードの制限内にある場合は常に、答えに 1 を追加します。 この増分バージョンには次のものが必要です`O(n^2)`操作があるため、`n(n+1)/2`エンドポイントのペア。 で`n = 100000`、つまり`5000050000`候補部分文字列がすでに多すぎます。 

さらに文字通りの総当たりソリューションでは、すべての部分文字列を構築し、その文字を個別にカウントします。 それには時間がかかります`O(n^3)`時間。 すべての部分文字列が 1 文字ずつスキャンされる場合、最悪の場合の文字訪問数は次のようになります。`1 + 2 + ...`すべての部分文字列の長さにわたって、つまり`n(n+1)(n+2)/6`。 

のために`n = 100000`、これはおよそ`1.6667 * 10^14`そのため、このアプローチははるかに早い段階で失敗します。 

ブルートフォース手法が機能するのは、必要な条件を正確にチェックするためです。つまり、すべての文字の頻度が利用可能な制限内に収まる必要があります。 問題は、重複する部分文字列を繰り返しチェックすることです。 重要な観察は、部分文字列を右に拡張すると妥当性が単調になるということです。 文字を追加しても、無効な周波数を修復することはできません。 ウィンドウにすでにある文字のコピーが多すぎる場合、その文字を含む大きなウィンドウもすべて無効になります。 

この特性により、スライディング ウィンドウが可能になります。 現在の正しい位置で終わる最大の有効な部分文字列を保持します。 新しい文字を追加するとウィンドウが無効になる場合は、ウィンドウが再び有効になるまで左の端点を前方に移動します。 固定右エンドポイントの場合、現在の左エンドポイント以降で始まるすべてのサフィックスが有効です。 左側のエンドポイントが`l`、まさにあります`r - l + 1`そのような接尾辞。 

したがって、すべての部分文字列を個別にチェックするのではなく、各文字は 1 回ウィンドウに入り、最大 1 回ウィンドウから出ます。 文字列全体を次のように処理できます。`O(n)`時間。

 ## アルゴリズムのチュートリアル

 1. 26 個の小文字のそれぞれに利用できるカードの枚数を数えます。 これらの値を次の場所に保存します`limit`。 
2. 周波数配列を初期化する`cnt`現在のウィンドウの左端点を設定します`l`ゼロに。 右のエンドポイントは左から右に移動します。`s`。 
3. ポジションごとに`r`、 追加`s[r]`周波数を増分して現在のウィンドウに合わせます。 候補者ウィンドウができました`s[l:r+1]`。 
4. 新たに追加されたキャラクターの周波数がカード制限を超えた場合、移動`l`一度に 1 位置ずつ右に移動し、破棄された各文字を`cnt`。 現在のウィンドウがすべてのカード制限を満たすまで続行します。 

新しい右端の文字のみが、以前に有効だったウィンドウを無効にできます。 文字を削除すると周波数が減少するだけなので、左側から文字を削除するだけでウィンドウを修復できます。 
5. ウィンドウが有効になったら、`r - l + 1`答えに。 次で終わるすべての部分文字列`r`からの任意の位置から開始します`l`を通して`r`はこの有効なウィンドウのサフィックスであるため、すべて有効です。 まさにあります`r - l + 1`そのようなことが始まります。 
6. すべての文字が処理されるまで続行します。 累積された答えは、有効な部分文字列の出現数です。 

### なぜ効果があるのか

 反復するたびに、`[l, r]`は有効なウィンドウであり、`l`ウィンドウが次で終了する最小の左端点です。`r`有効です。 したがって、次で終わるすべての部分文字列は、`r`少なくともある位置から開始します`l`は有効ですが、その前に開始`l`左側の境界が移動されたときにすでに無効なウィンドウが生成されます。 したがって`r - l + 1`で終わる有効な部分文字列をすべて正確にカウントします。`r`、漏れも重複もありません。 すべての文字は 1 回挿入され、多くても 1 回削除されるため、合計の作業は直線的です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    s = input().strip()
    t = input().strip()

    limit = [0] * 26
    for ch in t:
        limit[ord(ch) - ord('a')] += 1

    cnt = [0] * 26
    left = 0
    ans = 0

    for right, ch in enumerate(s):
        x = ord(ch) - ord('a')
        cnt[x] += 1

        while cnt[x] > limit[x]:
            y = ord(s[left]) - ord('a')
            cnt[y] -= 1
            left += 1

        ans += right - left + 1

    print(ans)

if __name__ == "__main__":
    solve()
```最初のループはカード文字列を`limit`配列。 順序を守る理由はない`t`なぜなら、カードは交換可能であり、その多重度だけが重要だからです。 

メインループは、現在のウィンドウの右側に 1 文字を追加します。 カウントが大きくなりすぎると、`while`ループは左側から文字を削除します。 チェックのみ`cnt[x]`ウィンドウは追加前に有効であったため、これで十分です`s[right]`したがって、この反復中に他の文字が無効になることはあり得ません。 

条件は以下を使用します`>`それよりも`>=`。 ちょうど 2 つある場合`a`カードとウィンドウにはちょうど 2 枚のカードが入っています`a`文字の場合、ウィンドウは有効です。 カウントが3になった場合のみ無効となります。 

答えは窓が修理された後にのみ更新されます。 その時点で、`right - left + 1`で終わる有効な部分文字列の数です。`right`。 左側の境界は次の位置まで移動できます。`right + 1`現在のキャラクターに使用可能なカードがない状況。 たとえば、次の場合`s[right] = 'a'`そして`limit['a'] = 0`、ループは、新しい文字を含む、現在ウィンドウ内にあるすべての文字を削除します。`a`、そして葉`left = right + 1`。 その場合、貢献度はゼロになります。 

Python の整数は、考えられる最大の答えを得るためにオーバーフローを回避します。`5000050000`。
