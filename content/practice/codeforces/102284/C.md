 ## 問題の理解

 2 列に (n 人) 人の生徒がいます。 最初の行の生徒 (i) の身長は (a_i)、2 行目の生徒 (i) の身長は (b_i) です。 チームは左から右に生徒を集めて編成されるため、選ばれた生徒の指数は厳密に増加する必要があります。 同時に、連続して選ばれる 2 人の生徒は異なる列から来なければなりません。 最初に選択した生徒には制限がなく、目標は選択した身長の合計を最大化することです。 公式の制約は (1 \le n \le 10^5) と (1 \le h_{r,i} \le 10^9) で、現在の Codeforces バージョンでは時間制限が 2 秒、メモリ制限が 256 MB です。 

上限 (n=10^5) により、考えられるすべてのチームはもちろん、ポジションのペアを検査するアルゴリズムも即座に除外されます。 (O(n^2)) の解は、最悪の場合でもすでに約 (10^{10}) 回の反復を実行しますが、これは 2 秒のコンテスト制限が処理できる範囲をはるかに超えています。 各列を一定の回数処理して、(O(n)) 個の解を得る必要があります。 答えは (n\cdot10^9=10^{14}) まで大きくなる可能性があるため、実装では 32 ビット符号付き整数を超える値を格納できる整数演算を使用する必要があります。 Python の整数はこれを自動的に処理します。 

最初のエッジ ケースは単一列です。 例えば、```
1
7
4
```答えがあります`7`。 利用可能な 2 番目のインデックスがないため、両方の学生を選択することは不可能です。 すべての遷移に前の列があると想定する実装は、ここで失敗する可能性があります。 

2 番目の特殊なケースは、同じ列から両方の学生を選択できないことです。 例えば、```
2
100 100
1 1
```答えがあります`101`、 ない`200`。 背の高い二人の学生`100`同じインデックスを持ちますが、ルールでは、次に選択されるインデックスが前のインデックスよりも厳密に大きいことが要求されます。 すべての列から単純に大きい方の高さを取得する不注意な解決策では、両方の高さが誤って選択されてしまいます。`100`s.

 3 番目のエッジ ケースは、前に選択した生徒が直前の列にいる必要がないことです。 考慮する```
3
1 100 1
1 1 100
```最適なチームはインデックスの最前列の生徒です`2`続いてインデックスの2列目の生徒`3`、与える`200`。 直前の列のみを先行列として考慮する遷移では、この組み合わせは見逃されます。 

最後に、すべての高さが等しい場合、答えは完全に構造上の制約によって決まります。 のために```
3
5 5 5
5 5 5
```答えは`15`, なぜなら、3 つの列と交互の行のそれぞれからちょうど 1 人の生徒を選択できるからです。 1 つの列の両方の行を選択できる実装では、オーバーカウントが発生します。 

## アプローチ

 直接的な総当たりソリューションでは、(2n) 人の生徒のすべてのサブセットを列挙し、選択されたインデックスが厳密に増加しているかどうか、および連続して選択された生徒が行を交互に配置しているかどうかを確認して、最大の高さの合計を維持できます。 これは正しいです。考えられるすべてのチームは何らかのサブセットで表されるからです。 ただし、(2^{2n}) 個のサブセットがあり、1 つのサブセットをチェックするには (O(n)) 時間がかかる場合があります。 したがって、最悪の場合の作業は (O(n\cdot2^{2n})) になります。 実際の制約では (10^5) 列が許可されますが、数十列の場合でもこれは実行不可能になります。 

問題を簡単にする構造は、列を左から右にスキャンすると、次の選択に影響を与える処理済みの部分の情報は最後に選択した生徒の行だけになるということです。 選択したインデックスの完全なシーケンスを記憶する必要はありません。 

列の接頭辞を処理したとします。 させて`top`最後に選択された生徒が最初の列の生徒である場合に、その接頭語から取得できる最適な合計高になります。 同様に、`bottom`最後に選択した生徒が 2 列目である場合に、合計が最も高くなります。 これらの状態では、最後に選択された生徒が処理されたプレフィックス内のどこにでも存在することがすでに許可されています。 

身長 (a_i) の新しい 1 列目の生徒に到達すると、2 つの可能性があります。 この学生をスキップして、ここを離れても構いません`top`変わらない。 あるいはそれを選択することもできます。 連続して選択された学生は異なる行に存在する必要があるため、前に選択された学生は次のように表す必要があります。`bottom`、新しい値は次のようになります`bottom + a_i`。 したがって、新しい最初の行の状態は次のようになります。 

[
 \text{new_top}=\max(\text{top},\text{bottom}+a_i)。 
]

 同じ推論により、

 [
 \text{new_bottom}=\max(\text{bottom},\text{top}+b_i)。 
]

 微妙な点は、`top`そして`bottom`は、必ずしも前の列にあるとは限りませんが、処理されたプレフィックス内の任意の場所で最適な選択を表します。 これにより、スキップされた列が自動的に処理されます。 すべての遷移では前の 2 つの状態値のみが使用されるため、(O(n)) DP 全体を一定の追加メモリに減らすことができます。 

ブルート フォースは、考えられるすべてのチームを明示的に検査するため機能しますが、チームの数が指数関数的に多いため失敗します。 未来は最後に選択された生徒の行にのみ依存するという観察により、多くの部分的なチームを 2 つの最適な状態に指数関数的にマージすることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n\cdot2^{2n})) | (O(n)) | 遅すぎる |
 | 最適なDP | (O(n)) | (O(1)) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの高さ配列を読み取ります。 すべての有効なチームのインデックスが厳密に増加しているため、左から右に列ごとに処理します。 
2.初期化`top = a[0]`そして`bottom = b[0]`。 最初の列のみが使用可能な場合、最後に選択された生徒が 1 行目にいる最も優れたチームは、その 1 行目の生徒で構成され、2 行目も同様になります。 
3. 以降の列ごとに`i`の古い値を保存します。`top`そして`bottom`。 新しい最初の行の状態は次のとおりです。`max(old_top, old_bottom + a[i])`。 最初の項は、現在の 1 列目の生徒をスキップすることを意味し、2 番目の項は、他の列で終了する有効なチームの後にそれを取得することを意味します。 
4. 新しい 2 行目の状態を次のように計算します。`max(old_bottom, old_top + b[i])`。 推論は対称的ですが、両方の新しい状態で古い値を使用する必要があります。 一方の状態を計算する前に他方の状態を更新すると、誤って両方の遷移で現在の列が使用されることになり、インデックスの厳密な増加条件に違反する可能性があります。 
5. 最後の列の後に戻る`max(top, bottom)`。 空ではないすべての有効なチームは 2 つの行のうちの 1 つで終了するため、これらの状態のうちより優れた状態が全体最適となります。 

### なぜ効果があるのか

 列 (i) を処理した後、`top`最後に選択された生徒が最初の行にある (i) までの列のみを使用して、すべての有効なチームの最大合計を格納します。 同じ不変条件が次の場合にも当てはまります`bottom`そして2列目。 列 (i) の 1 行目の生徒の場合、それを選択する有効なチームは、事前に、より小さいインデックスの 2 行目で終了する必要があります。`old_bottom`そのような最高のチームを代表します。 スチューデントをスキップすると、以前の最適値が保存されます。 可能性はこれら 2 つだけであるため、再帰ではすべての有効な最適なチームが考慮され、無効なチームを導入することはできません。 不変式はすべての列に適用され、最終的な最大値が最適なチームの合計となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    top = a[0]
    bottom = b[0]

    for i in range(1, n):
        old_top = top
        old_bottom = bottom

        top = max(old_top, old_bottom + a[i])
        bottom = max(old_bottom, old_top + b[i])

    print(max(top, bottom))

if __name__ == "__main__":
    solve()
```最初の 2 つの割り当ては、列 0 の 2 つの DP 状態を初期化します。 すべての高さは正の値であるため、空のチームには個別の状態は必要ありません。そのため、誰も選択しないよりも少なくとも 1 人の生徒を選択する方が常に優れています。 

ループ内では、`old_top`そして`old_bottom`現在の列を処理する前に状態を保存します。 これは不可欠です。 もし`top`最初に更新され、その後コンピューティング中に使用されました`bottom`、2 番目の遷移では、同じ列から 2 人の生徒を事実上選択する可能性がありますが、インデックスが等しいため禁止されています。 

表現`old_bottom + a[i]`は 2 行目から 1 行目への切り替えを表します。 以来`old_bottom`前に処理された列の前または前の任意の場所に 2 行目で終わる最も有効なチームがすでに含まれている場合、必要な厳密なインデックス増加は満たされます。 同じ議論が当てはまります`old_top + b[i]`。 

Python の任意精度の整数もここで役立ちます。 (10^5) 列と最大 (10^9) の高さの場合、答えは (10^{14}) に達する可能性があるため、32 ビット整数がデフォルトの整数型である言語ではオーバーフローします。

    bottom = b[0]

        old_bottom = bottom

    old_stdout = sys.stdout

        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

1
7
4
```初期状態は`top = 7`そして`bottom = 4`。 後続の列がないため、ループには入りません。 最終的な最大値は、`7`、まさにその通りです。 これは、繰り返しが必要な境界を処理します。`i-1`そうしないと、存在しない列にアクセスすることになります。
