 ## 問題の理解

 (n) 個の凸多角形があります。 ポリゴン (i) は反時計回りの順序で頂点によって与えられ、すべてのポリゴンにわたる頂点の総数は最大 (300,000) です。 すべてのクエリ ([l,r]) に対して、ポリゴンのミンコフスキー和の頂点の数 (l,l+1,\ldots,r) が必要です。 

2 つのセット (A) と (B) のミンコフスキー和には、(a\in A) と (b\in B) を含むすべての点 (a+b) が含まれます。 凸多角形の場合、結果は再び凸多角形になります。 入力ポリゴンには合計で最大 (300,000) 個の頂点を含めることができ、(100,000) 個のクエリが存在する可能性があります。 この制約により、クエリごとに個別にミンコフスキー和を構築することが直ちに除外されます。 クエリのすべてのエッジを 1 回処理するだけでも、(100,000 回) 繰り返すとコストがかかりすぎます。 ポリゴンをグローバルに前処理し、各間隔クエリにほぼ対数時間で答える必要があります。 

重要な幾何学的単純化は、ミンコフスキー和の頂点の数がエッジの方向によって完全に決定されることです。 2 つのエッジの方向が同じ場合、ミンコフスキー和では 1 つのエッジに結合されます。 方向が異なるエッジは分離されたままになります。 凸多角形は同じ方向を持つ 2 つの異なるエッジを持つことができないため、ある範囲の多角形に対する答えは、それらの多角形に現れる別個の有向エッジ方向の数となります。 

たとえば、2 つの同一の三角形について考えてみましょう。```

0 0
1 0
0 1
3
5 5
6 5
5 6
1

```正しい出力は次のとおりです```
3
```不注意な解決法を行うと、各三角形の 3 つのエッジを追加して (6) を返す可能性があります。 対応するエッジは同じ方向を持ち、ミンコフスキー和では単一のエッジになるため、これは誤りです。 

2 番目の境界ケースは、クエリにポリゴンが 1 つだけ含まれている場合に発生します。```
1
3
0 0
1 0
0 1
1

```答えは```

```クエリ範囲には、最後の頂点から最初の頂点までの終了エッジを含む、多角形 (1) の 3 つのエッジすべてが含まれている必要があります。 周期的なエッジを忘れると、誤って (2) が生成されてしまいます。 

もう 1 つの微妙なケースは、エッジ ベクトルの方向は同じだが長さが異なる場合です。 たとえば、ベクトル ((1,1)) と ((7,7)) は同​​じ方向を表します。 これらは等しいものとして扱う必要があるため、正規化されたベクトルではなく生のベクトルを比較すると間違った答えが得られます。 

両方の座標を (\gcd(|x|,|y|)) で割ることによって、ゼロ以外のすべてのエッジ ベクトル ((x,y)) を正規化します。 符号は保持されるため、((1,0)) と ((-1,0)) は異なる方向のままになります。 

## アプローチ

 直接的な幾何学的なアプローチでは、実際にはすべてのクエリのミンコフスキー和が計算されます。 2 つの凸多角形のミンコフスキー和は、それらのエッジ ベクトルを角度順にマージすることで構築でき、そのサイズは含まれるエッジの数に比例します。 これは正しいです。なぜなら、合計の境界は、両方のポリゴンのエッジ ベクトルを角度の増加順に取得することによって取得されるからです。 

問題は繰り返しです。 1 つのクエリに (300,000) のエッジが含まれており、ポリゴンを 1 つずつ追加して合計を計算するとします。 最悪の場合、中間結果は (3,6,9,\ldots,300,000) エッジまで増加します。 エッジ処理の総量はおよそ次のようになります。 

45,000、150,000、
 ]

 1 つのクエリに対してすでに (4.5\times10^{10}) 回の演算が行われています。 最大 (100,000) のクエリでは、このアプローチは完全に実行不可能です。 

幾何学的な構造を取り除く観察は、凸多角形がその境界に沿って、その有向エッジ ベクトルによって表現されるということです。 2 つの凸多角形を追加すると、それらのエッジ ベクトルが角度によってマージされます。 2 つのベクトルが同じ方向を持っている場合、それらはその角度順序で隣接しており、それらの長さは単純に加算されます。 したがって、すべての異なる有向エッジ方向は、最終的なミンコフスキー和に 1 つのエッジだけを寄与します。 

この角度マージを明示的に実行するため、ブルート フォースが機能します。 元のポリゴンにすでに存在する情報を繰り返し再構築するため、失敗します。 明確に正規化された方向のみが重要であるという観察により、座標と長さを完全に捨てることができます。 すべてのポリゴン エッジを 1 つの配列に平坦化し、各ポリゴンが連続セグメントを占め、すべてのエッジ ベクトルをそのプリミティブ方向に縮小します。 

残りの問題は、標準のオフライン範囲別クエリです。 すべてのクエリ ([l,r]) について、平坦化されたエッジ方向配列の対応する区間内の個別の値の数が必要です。 このようなすべてのクエリには、フェンウィック ツリーと各方向の最後の出現を使用して答えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (m) 個のエッジを含むクエリの場合は (O(m^2)) | (O(m)) | 遅すぎる |
 | 最適 | (O(V\log V + q\log V)) | (O(V+q)) | 承認済み |

 ここで、(V\le300,000) はポリゴンの頂点の総数、(q\le100,000) です。 

## アルゴリズムのチュートリアル

1. すべてのポリゴンを読み取り、その (k) 境界エッジのそれぞれを有向ベクトルに変換します。 頂点 (j) の場合、エッジは頂点 (j) から頂点 ((j+1)\bmod k) までのベクトルです。 最後のエッジは最初の頂点に戻るため、モジュロが必要です。 
2. すべてのエッジ ベクトル ((x,y)) を (\gcd(|x|,|y|)) で割って正規化します。 結果のペア ((x',y')) をエッジ方向として保存します。 座標は大きくなる可能性がありますが、正規化後のペアは方向を一意に表します。 
3. すべてのポリゴンの方向を 1 つのグローバル配列に追加します。 また、すべてのポリゴンの開始位置と最後のエッジの直後の位置も保存します。 ポリゴン (l) ～ (r) を含むクエリは、ポリゴン (l) の先頭からポリゴン (r) の末尾までの通常の配列間隔になります。 
4. 方向ペアを座標圧縮します。 等価性が確立された後は実際の数値は無関係になるため、すべての個別の方向に整数の識別子を割り当てることができます。 
5. すべてのクエリを読み取り、フラット化された配列内の右のエンドポイントごとにグループ化します。 多角形 (l) が位置 (L) で始まり、多角形 (r) が位置 (R) の直前で終了する場合、クエリは半開区間 ([L,R)] 内の個別の方向識別子の数を求めます。 
6. 平坦化された配列を左から右に処理します。 各方向について、フェンウィック ツリー内で最新の発生のみをアクティブにしておきます。 方向が位置 (i) に表示されると、以前のアクティブな出現があればそれを削除し、(i) をアクティブにします。 
7. スイープがクエリ ([L,R)] の右エンドポイント (R) に到達すると、フェンウィック ツリーには、(R) で終わるプレフィックスに発生するすべての方向に対してアクティブな位置が 1 つだけ含まれます。 方向は、その最新の出現が少なくとも (L) である場合に、([L,R)) 内に寄与します。 したがって、([L,R)) 上のフェンウィック範囲の合計は、正確にそのクエリ内の個別の方向の数になります。 

スイープ中の不変条件は単純です。位置 (i) を処理した後、位置 (0) ～ (i) で発生する各方向には、アクティブなフェンウィック位置が 1 つだけ、つまり最新の位置が存在します。 したがって、(i+1) で終わるクエリは、最新の出現がクエリの左境界より前にない方向を正確にカウントします。 すべての個別の方向がミンコフスキー和の 1 つのエッジに正確に対応するため、返されるカウントは必要な頂点の数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, delta):
        i += 1
        while i <= self.n:
            self.bit[i] += delta
            i += i & -i

    def prefix_sum(self, i):
        res = 0
        while i > 0:
            res += self.bit[i]
            i -= i & -i
        return res

    def range_sum(self, l, r):
        return self.prefix_sum(r) - self.prefix_sum(l)

def solve():
    n = int(input())

    directions = []
    borders = [0]

    for _ in range(n):
        k = int(input())
        points = [tuple(map(int, input().split())) for _ in range(k)]

        for j in range(k):
            x1, y1 = points[j]
            x2, y2 = points[(j + 1) % k]

            dx = x2 - x1
            dy = y2 - y1

            g = __import__("math").gcd(abs(dx), abs(dy))
            dx //= g
            dy //= g

            directions.append((dx, dy))

        borders.append(len(directions))

    # Coordinate-compress direction pairs.
    ids = {}
    arr = []

    for direction in directions:
        if direction not in ids:
            ids[direction] = len(ids)
        arr.append(ids[direction])

    m = len(arr)

    # next_pos[i] is the next occurrence of arr[i], or m if none exists.
    next_pos = [m] * m
    last = [m] * len(ids)

    for i in range(m - 1, -1, -1):
        x = arr[i]
        next_pos[i] = last[x]
        last[x] = i

    q = int(input())

    queries = [[] for _ in range(m)]
    answers = [0] * q

    for query_id in range(q):
        l, r = map(int, input().split())
        left = borders[l - 1]
        right = borders[r]

        queries[right - 1].append((left, query_id))

    fenwick = Fenwick(m)

    # Initially activate the last occurrence of every direction.
    for pos in last:
        if pos != m:
            fenwick.add(pos, 1)

    for i in range(m):
        # Queries ending at i + 1 use the half-open interval [left, i + 1).
        for left, query_id in queries[i]:
            answers[query_id] = fenwick.range_sum(left, i + 1)

        # Move the active occurrence of arr[i] from i to its next occurrence.
        fenwick.add(i, -1)

        if next_pos[i] != m:
            fenwick.add(next_pos[i], 1)

    sys.stdout.write("\n".join(map(str, answers)))

if __name__ == "__main__":
    solve()
```の最初の部分`solve`各ポリゴンを読み取り、最後の頂点から最初の頂点までの循環エッジを明示的に処理します。 正規化されたペアはエッジの方向を識別するのに十分であるため、その点以降は元の座標を保持する必要はありません。`borders`ポリゴン範囲を平坦化方向配列内の位置に変換します。 もし`borders[i]`はポリゴン (i) の直後の位置であり、ポリゴン (l) から (r) までが正確に占めます。`[borders[l - 1], borders[r])`。 ハーフオープン間隔を使用すると、考えられるいくつかのオフバイワンエラーが除去されます。 

辞書`ids`任意の方向ペアを小さな整数の識別子に圧縮します。 フェンウィック ツリーは 0 と 1 のみを格納する必要があるため、この圧縮により実装がコンパクトに保たれ、`last`そして`next_pos`配列も可能。 

逆パスでは、すべての方向の次の出現が計算されます。 前方スイープでは、これらのリンクを使用して、アクティブなオカレンスをある位置から次の位置に移動します。 これは、左から右にスキャンしながら各方向の最新の発生を維持することに相当します。 

クエリは、アクティブなオカレンスを位置に移動する前に評価されます。`i`。 その時点で、アクティブな位置はプレフィックス内の最新の出現位置を表します。`i`で終わるクエリに正確に必要なもの`i + 1`。 の使用`range_sum(left, i + 1)`と同じ半開区間規則に従います。`borders`。 

Python の整数には任意の精度があるため、座標の差分や正規化によって整数のオーバーフローが発生する危険はありません。 最大の座標の差は (2\cdot10^9) のみですが、Python の整数演算を使用すると、実装がマシンの整数幅に依存しなくなります。

import math

def solve_data(data: str) -> str:

    out = []

    def read():
        return inp.readline

    input_local = read
    n = int(input_local())

    borders = [0]

    arr = []

        if d not in ids:

        right = borders[r]

        pos += 1
        while pos <= m:
            bit[pos] += delta
            pos += pos & -pos

        while pos > 0:
            res += bit[pos]
            pos -= pos & -pos

        add(i, -1)
        if next_pos[i] != m:

 ## 特殊なケース

 最初のエッジケースは、ポリゴンを 1 つだけ含むクエリです。 のために```
1
3
0 0
1 0
0 1
1
1 1
```平坦化された配列には 3 つの方向があります`(1,0)`、`(-1,1)`、 そして`(0,-1)`。 クエリ間隔は`[0,3)`したがって、3 つのアクティブなポジションすべてがカウントされ、答えは次のようになります。`3`。 終了エッジは次のように生成されます。`(j + 1) % k`, したがって、誤って省略することはできません。 

2 番目のエッジ ケースは、方向が繰り返される場合です。 のために```
2
3
0 0
1 0
0 1
3
10 10
11 10
10 11
1
1 2
```2 番目の三角形は最初の三角形の平行移動であるため、6 つのエッジは 3 つの異なる方向識別子に減ります。 スイープ中、新しいオカレンスはそれぞれ、同じ方向の前のアクティブなオカレンスを置き換えます。 クエリエンドポイントでは、ちょうど 3 つの位置がアクティブなままとなり、`3`。 

3 番目のエッジ ケースは、長さが異なるベクトルに関するものです。 で```
2
3
0 0
2 0
0 2
3
10 10
14 10
10 14
1
1 2
```対応する水平エッジは次のとおりです。`(2,0)`そして`(4,0)`、他の方向も同様にスケーリングされます。 gcd で除算すると、両方のポリゴンが同じ 3 つの基本方向を生成します。 アルゴリズムは戻ります`3`、ミンコフスキー和幾何学と一致します。 

最後に、範囲変換は、off-by-one エラーの一般的な原因です。 ポリゴン (1) には 3 つのエッジがあり、ポリゴン (2) には 4 つのエッジがあるとします。 次に、ポリゴン (1) が占めます`[0,3)`ポリゴン (2) が占める`[3,7)`。 クエリ`[2,2]`にならなければなりません`[3,7)`、 ない`[3,6)`または`[4,7)`。 保管する`borders[i]`ポリゴン (i) の直後の位置が正確な半開間隔を与えるため、Fenwick クエリは`prefix(right) - prefix(left)`要求されたポリゴンに属するアクティブな位置を正確にカウントします。
