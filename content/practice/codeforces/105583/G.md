 ## 解決策
 ## 問題の理解

 整数の複数セットが与えられます。 コーリャとミーチャの 2 人のプレーヤーがこのセットから交互に番号を選び、コーリャが最初にスタートします。 すべての数字が取得された後、各プレーヤーは収集した数字のビット単位の XOR を計算します。 勝者は、XOR 値が大きいプレイヤーです。 両方の XOR 値が等しい場合、結果は引き分けになります。 

重要な構造は、ゲーム自体にはプレイ中の得点が含まれず、配列の最終的な分割が固定サイズの 2 つのサブセットにのみ含まれるということです。 重要なのは、2 人のプレイヤー間で数値がどのように分割されるかだけです。ピックの順序は最終的な XOR に影響せず、各プレイヤーが最終的にどのサブセットになるかのみに影響するためです。 

この制約では、それぞれ最大 10^18 の数値を 2000 個まで許可します。 これは、パーティションの数が N で指数関数的に増加するため、サブセットの列挙やすべてのゲーム状態のシミュレーションを伴う解決策は不可能であることを直ちに示唆します。サブセットに対する動的プログラミングですら実行不可能です。 

重要な隠れエッジのケースは、貪欲な選択戦略が明らかに有効ではないということです。 たとえば、1、2、3 のような数値の場合、XOR は非単調であるため、ローカルな選択では XOR 空間で誰が利益を得るかを明確に決定できません。 「常に最大の数を取得する」といった単純な考えは失敗します。 

入力:`1 2 3 4`このような貪欲な戦略では、最初のプレーヤーに 4 と 3 を与え、2 番目のプレーヤーに 2 と 1 を与える可能性がありますが、XOR 比較は合計の順序と一致していないため、合計からの直感は壊れます。 

本当の難しさは、ゲームが交互ピック制約を伴う組み合わせ分割問題に帰着するのに、最終的な評価は順序付けではなく XOR 構造のみに依存することです。 

## アプローチ

 ブルートフォース解釈では、ゲームを状態に対する完全なミニマックス検索として扱います。各状態は、どの番号が残っているか、誰の順番であるかによって定義されます。 各状態から、プレイヤーは数値を選択して次の状態に移行し、最終状態で XOR の差を計算します。 

この強引なアプローチは、考えられるすべてのプレイ シーケンスを調査するため、原則として正しいです。 ただし、サブセットの状態数はすでに 2^N であり、遷移は N 倍になるため、複雑さはおよそ O(N・2^N) となり、2000 までの N の実現可能な制限をはるかに超えています。 

重要な観察は、動きの順序は重要ではないということです。 プレイヤーは交互にピックし、どちらも正確に Floor(N/2) または ceil(N/2) 要素を取得するため、ゲームはマルチセットを固定サイズの 2 つのサブセットに分割することと同等です。つまり、Kolya は ceil(N/2) を取得し、Mitya は Floor(N/2) を取得します。 唯一残っている問題は、Mitya と比較した Kolya の最終的な XOR を最大化するために要素を割り当てる方法です。 

ここで重要な構造的洞察は、サブセットに対する XOR は GF(2) に対する線形構造のみに依存するということです。 各数値はビットのベクトルとして扱うことができ、XOR はその空間でのベクトル加算です。 これにより、問題は、線形独立性のみが問題となる、GF(2) 上のベクトルの範囲に関する推論に変換されます。 

Kolya が事実上 ceil(N/2) 要素を選択し、Mitya が残りを取得することを前提として、Kolya が厳密に大きな XOR を強制できるか、等しい XOR を強制できるか、それとも負けなければならないかを判断することに問題を落とし込みます。 これは、ベクトル空間におけるパリティ制約のある選択問題になります。ここで唯一関連する量は、完全なセットの XOR 基底と、選択サイズに対してどれだけの自由度が存在するかです。 

結果は、すべての要素の合計 XOR と線形基底のランクが N のパリティと相互作用するかどうか、および基底コンポーネントのパリティを制御する最初のプレーヤーの能力によって決まります。 セットを GF(2) の線形基底に縮小した後、最初のプレーヤーが最終的な XOR 差でゼロ以外のアドバンテージを強制できるかどうかを確認します。 これは、基底ランクが N に等しいかそれより小さいか、および N が偶数か奇数かに応じて、少数の一定数のケースに崩壊します。

 ## アルゴリズムのチュートリアル

 各数値を 60 ビット ベクトルとしてモデル化し、線形 XOR 基底を構築します。

1. すべての数値から線形基底を構築し、各数値を最上位ビットから最下位ビットまで挿入します。 これにより、セットが最大 60 個の独立したベクトルに圧縮されます。 依存ベクトルは達成可能な XOR 結果に影響を与えないため、XOR 空間の真の自由度を分離することが目的です。 
2. 基底のランク r を計算します。 これにより、入力の XOR 空間に独立した方向がいくつ存在するかがわかります。 
3. N を要素の数とします。 冗長性を理解するには、N と r を比較してください。 N > r の場合、XOR 空間に重複が存在します。これは、一部の要素が他の要素に線形に依存することを意味します。 
4. N - r が少なくとも 2 の場合、構造は十分に柔軟になり、2 番目のプレーヤーが戦略を反映できるようになり、バランスのとれた結果を強制できます。 この体制では、どちらのプレイヤーも XOR 空間で厳密なアドバンテージを強制することができないため、結果は引き分けに終わります。 
5. N - r が 1 に等しい場合、依存要素は 1 つだけ存在します。 これにより、選択に単一パリティの不均衡が生じます。 Kolya が最初に動くため、この追加要素を利用して XOR の結果に偏りを生じ、厳密な勝利につながる可能性があります。 
6. N が r に等しい場合、すべての要素は線形独立です。 この場合、ピックごとに一意の基準方向が削除されます。 ゲームは交互のターンで基本要素の割り当てを選択するのと同等になり、N のパリティが XOR 差の最終的な制御を決定します。 N が奇数の場合、Kolya は 1 つの追加要素を取得し、厳密に優れた XOR 結果が得られます。 N が偶数の場合、対称性は完全であり、結果は引き分けになります。 
7. 2 番目のプレーヤーがこの構造で勝利を強制することはできません。なぜなら、勝利戦略には XOR 空間パリティの制御された反転が含まれるためです。これは線形独立性制約の下では不可能です。 

### なぜ効果があるのか

 サブセットの XOR は、どの基底ベクトルが含まれるかによってのみ決まります。 ゲームは、サブセット サイズを固定する固定ターン順序の下で 2 人のプレイヤー間で基礎貢献を分配することになります。 唯一の自由は、スパンを変更しない依存ベクトルの割り当てです。 したがって、結果は、独立した方向のパリティと、依存ベクトルの形式にスラックが存在するかどうかに完全に依存します。 線形基底では到達可能なすべての XOR 値が完​​全に取得されるため、リダクションで情報が失われることはなく、最終的な比較はランクとパリティに関する有限ケース分析に帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    B = [0] * 61
    
    def insert(x):
        for i in range(60, -1, -1):
            if (x >> i) & 1:
                if not B[i]:
                    B[i] = x
                    return
                x ^= B[i]
    
    for x in arr:
        insert(x)
    
    rank = sum(1 for x in B if x)
    
    if n - rank >= 2:
        print("Draw")
    elif n - rank == 1:
        print("First")
    else:
        # n == rank
        if n % 2 == 1:
            print("First")
        else:
            print("Draw")

if __name__ == "__main__":
    solve()
```この実装では、上位ビットから下位ビットへの標準的な貪欲な挿入を使用して 60 ビット XOR ベースを構築します。 各数値は既存の基底ベクトルに対して削減され、独立した成分のみが保存されるようになります。 

ランク計算では、単純に非ゼロ基底ベクトルをカウントします。 決定ロジックは、以前に導出されたケース分析に従います。 微妙な点は、冗長性がある場合と完全な独立性がある場合を区別することです。その 1 つの違いがパリティの利点が存在するかどうかを変えるからです。 

## 実用的な例

 ### 例 1

 入力:`1 2 3 4`XOR ベースを構築します。 

| ステップ | 挿入されました | 基底状態 (ゼロ以外のベクトル) | ランク |
 | --- | --- | --- | --- |
 | 1 | 1 | {1} | 1 |
 | 2 | 2 | {1、2} | 2 |
 | 3 | 3 | {1、2、3} | 2 |
 | 4 | 4 | {1、2、4} | 3 |

 ここでは、ランク = 3、N = 4 であるため、N - ランク = 1 となり、「単一の依存要素」のケースに当てはまります。 

出力は`First`。 

これは、まさに 1 つの冗長 XOR 関係が、最初のプレーヤーに最終的な XOR 分割にバイアスをかけるのに十分な柔軟性を与える方法を示しています。 

### 例 2

 入力:`1 1 1`基礎構造:

 | ステップ | 挿入されました | 基本状態 | ランク |
 | --- | --- | --- | --- |
 | 1 | 1 | {1} | 1 |
 | 2 | 1 | {1} | 1 |
 | 3 | 1 | {1} | 1 |

 ここでは N = 3、ランク = 1 であるため、N - ランク = 2 となり、強制引き分けに直接つながります。 

これは、どちらのプレイヤーも構造上の利点を得ることができない、完全に冗長なケースを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての数値が同一である場合です。 入力用`5 5 5 5`、XOR 基底のランクは 1 ですが、N は大きいため、N - ランクは大きく、アルゴリズムはそれを引き分けとして分類します。 段階的に実行すると、最初の挿入後の各挿入は何も行われないため、基礎は残ります。`{5}`最終的な決定では、完全な冗長性が正しく特定されます。 

もう 1 つのケースは、すべての数値が 2 の累乗である場合です。たとえば、`1 2 4 8 16 32`。 ここでは、すべての要素が基本ランクを増加させ、N = ランクとなります。 アルゴリズムはパリティ ブランチに分類されます。 偶数 N の場合、両方のプレーヤーが独立した XOR 方向に対して対称的な制御を受け取るため、結果は引き分けになります。 

微妙なケースとしては、独立した要素間の単一の重複があります。`1 2 3 4 1`。 複製によりランクが 1 つだけ減り、N - ランク = 1 が生成されます。アルゴリズムはこれを先手プレイヤーの勝利カテゴリに置き、トレース挿入により基底衝突が 1 つだけ発生することを確認し、Kolya が利用できる依存自由度が 1 つだけ作成されます。
