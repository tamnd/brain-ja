 ## 解決策
 ## 問題の理解

 私たちはモジュール化された部品を繰り返して構成された垂直構造を構築しています。 高さの各単位がレイヤーであり、各レイヤーは一定数の同一のレンガを消費します。 レイヤーはブロックにグループ化されており、各ブロックには色が付いています。 ブロックは周期的に色を繰り返すので、利用可能な色をすべて使用した後、再び 1 色から開始します。 

塔には全高があるはずです$H$層。 各層に必要なものは、$P$レンガなので、完全なタワーをゼロから構築すると、正確に次のものが含まれることになります。$H \cdot P$レンガ。 しかし、塔の一部はすでに建設されており、最初に建設されたと伝えられています。$N$レンガ (下から上に数えて) は、同じ色のパターンに従ってすでに正しく配置されています。 タスクは、タワーを完成させるために各色の追加のレンガが何個必要かを判断することです。 

重要な構造は、色がレイヤーごとではなくブロックごとに割り当てられることです。 各ブロックには正確に次の内容が含まれます$K$ただし、高さが不完全な可能性がある最上部のブロックは除きます。 各レイヤーには次の内容が含まれているため、$P$レンガ、ブロック全体に含まれるもの$K \cdot P$レンガ。 ブロックの色は、シーケンス内のその位置にのみ依存します。ブロック 1 はカラー 1、ブロック 2 はカラー 2、というようにモジュロを循環します。$C$。 

課題は、位置からセグメント内に各色のレンガが何個現れるかを計算することです。$N+1$に$H \cdot P$この周期的なブロック色の構造で。 

制約は十分に大きいため、レンガごとの建設をシミュレートするソリューションはすべて、$H \cdot P$不可能です。 以来$H$最大 100,000 個、各層に最大 10,000 個のレンガが含まれ、合計サイズは最大 10,000 個に達します。$10^9$、線形シミュレーションは除外されます。 許容可能な解決策は、色の数、または最大でも高さの対数係数に比例して時間内に機能する必要があります。 

両端の部分ブロックから微妙なエッジケースが発生します。 すでに構築されているプレフィックス$N$レンガは層の途中で終わったり、ブロックの内側で終わったりする場合もあります。 同様に、残りのサフィックスは部分的に完成したブロック内で終了する場合があります。 完全なブロックのみまたは完全なレイヤーのみをカウントする単純なアプローチでは、これらの境界領域で誤ったカウントが発生します。 

たとえば、次の場合$P = 4$、$K = 2$, この場合、各ブロックは 2 層、8 個のレンガになります。 もし$N = 7$、その後、構築されたプレフィックスは最初のブロックの 2 番目の層の途中で終了します。 次の完全なブロックから色のカウントを開始するソリューションでは、部分的に消費されたレイヤーが誤って無視され、すべての色の割り当てがシフトされます。 

## アプローチ

 ブルートフォース戦略では、タワー全体を層ごとに再構築し、ブロックごとに色を割り当て、各レンガのカウンターを増分します。 構造が決定論的であるため、これは概念的に機能します。レンガの位置がわかれば、そのブロック インデックスとその色を導き出すことができます。 ただし、これにはすべてを繰り返す必要があります$H \cdot P$レンガ、最悪の場合は周囲にあります$10^9$制限時間をはるかに超えた作戦。 

重要な点は、実際にタワーを明示的に構築する必要がないということです。 各レンガの位置はブロック インデックスに直接マッピングされ、ブロックは間隔ごとに繰り返されます。$C$。 したがって、レンガを反復処理する代わりに、ブロックの範囲を操作し、部分的な境界を処理することで、特定の間隔内に各色のレンガが何個あるかを計算できます。 

ブロックレベルで見ると、構造ははるかに単純になります。 各ブロックのサイズは固定です$S = K \cdot P$おそらく最後のブロックを除いて、レンガのすべての連続セグメントは、最大 2 つの部分ブロックとその間のいくつかの完全なブロックに分解できます。 完全なブロックはそれぞれ 1 つの色に完全に寄与しますが、部分ブロックはすべて同じ色の範囲のレンガに寄与します。 

したがって、問題は次のようになります。 

まず各ブロックがどの色に属するかを決定し、次に各色の完全なブロックと部分ブロックがサフィックス内にいくつあるかを計算します。$[N+1, H \cdot P]$。 

これにより、問題はブリック全体での線形の問題から、色ごとの一定の作業といくつかの算術演算に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(H・P) | お(1) | 遅すぎる |
 | 最適 | O(C) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. タワー全体のレンガの総数を次のように計算します。$T = H \cdot P$。 このタスクは、間隔内の色を数えることに帰着します。$[N+1, T]$。 
2. ヘルパー構造を定義します。各ブロックにはサイズがあります。$S = K \cdot P$。 レンガ位置のブロックインデックス$x$は$(x - 1) // S$、色を次のように決定します。$(block\_index \bmod C) + 1$。 
3. インターバルを分割する$[N+1, T]$次のブロック境界までのプレフィックス、中間の完全なブロック、および最後の完全なブロック境界の後のサフィックスの 3 つの部分に分割されます。 この分解により、均一なセグメントから不規則な部分ブロックが分離されます。 
4. 最初の位置を特定する$L = N+1$そしてブロックの先頭からどれだけ離れているかを計算します。 残りは、そのブロックのレンガがすでに消費されている個数と、部分的な開始ブロックに残っている個数を決定します。 
5. もし$L$がブロック境界に位置合わせされていない場合は、ブロックの終わりまでに残っているレンガの数を計算して部分的な開始ブロックを処理し、それらすべてを対応する色に割り当てます。 
6. 開始部分ブロックの後、次のブロック境界に移動します。 終了位置に到達する前に、間隔内に完全に収まる完全なブロックの数を計算します。$T$。 
7. ブロック全体の場合、ブロックごとに処理するのではなく、インデックスの算術演算を使用して、範囲内に各色のブロックが何個出現するかをカウントします。 毎回色が繰り返されるので、$C$ブロックでは、各完全なサイクルがすべての色に均等に影響します。 
8. 最後に、終了部分ブロックを処理します。$T$ブロックの中にあります。 最後のブロックからその間隔に入るレンガの数を計算し、それらを正しい色に割り当てます。 

### なぜ効果があるのか

 正確さは、すべてのレンガが正確に 1 つのブロックに一意に属し、各ブロックが単一の固定色を持っているという事実に依存します。 間隔が最大 2 つの部分ブロックとブロック全体のシーケンスに分解されると、すべての部分が独立して最終的なカウントに寄与します。 モジュロベースのカラーリングにより、ブロックのカラーが一定の周期で繰り返されることが保証されます。$C$したがって、完全なサイクルをカウントすると、個々のブロックを追跡せずに均一に分散されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    H, P, C, K, N = map(int, input().split())

    total = H * P
    block_size = K * P

    # result per color (1-indexed)
    ans = [0] * C

    def add_block(block_idx, cnt):
        color = block_idx % C
        ans[color] += cnt

    # process range [L, R]
    L, R = N + 1, total

    if L > R:
        print(*ans)
        return

    # starting partial block
    start_block = (L - 1) // block_size
    start_block_start = start_block * block_size
    start_block_end = start_block_start + block_size - 1

    if L <= start_block_end:
        take = min(R, start_block_end) - L + 1
        add_block(start_block, take)
        L += take

    # full blocks
    if L <= R:
        first_full_block = (L - 1) // block_size
        last_full_block = (R - 1) // block_size

        if first_full_block <= last_full_block:
            for b in range(first_full_block, last_full_block + 1):
                bs = b * block_size
                be = bs + block_size - 1

                if bs < L:
                    left = L - bs
                else:
                    left = 0

                if be > R:
                    right = R - bs + 1
                else:
                    right = block_size

                add_block(b, max(0, right - left))

    print(*ans)

if __name__ == "__main__":
    solve()
```実装は区間分解の直後に続きます。 重要な部分は、次の整数除算によってブロック インデックスを計算することです。`block_size`。 各ブロックは 1 つの色のみに寄与し、次のように決定されます。`block_idx % C`, したがって、カラー配列ごとにカウントを累積します。 

境界演算には注意が必要です。 開始部分ブロックが最初に処理されるため、後の計算はブロックに位置合わせされたインデックスに対して実行されます。 この調整を行わないと、剰余ロジックで二重にカウントされたり、範囲がずれたりします。 ブロック数が最大でも次のとおりであるため、ブロック上のループは制約の下では安全です。$H / K$、これは管理可能です$H \le 10^5$ただし、完全に最適化されたバージョンでは、サイクルカウントによってさらに削減できる可能性があります。

 ## 特殊なケース

 カット位置が正確にブロック境界にある場合、クリティカルなエッジケースが発生します。 たとえば、次の場合$K = 2$、$P = 3$の場合、ブロック サイズは 6 になります。$N = 6$、プレフィックスは最初のブロックの最後で正確に終了するため、部分的な処理は発生しません。 

入力：```
H = 3, P = 3, C = 2, K = 2, N = 6
```ここ$T = 9$7 から 9 まで数えます。7 はブロック 2 内にあるため、部分ブロックから直接開始しますが、ブロック 1 からの残りはありません。 

アルゴリズムは以下を計算します。 

- 開始ブロック = 1
 - start_block_start = 6
 - 開始ブロック終了 = 11

 したがって、部分的なプレフィックスが残っていないことを正しく認識し、ブロック 2 内のサフィックスのみを処理します。結果の分布は直接手動カウントと一致し、境界の等価性によってオフバイ 1 エラーが発生しないことが確認されます。 

もう 1 つのエッジケースは次のような場合です$N = T - 1$。 するとレンガが1つだけ残ります。 このアルゴリズムは間隔を 1 つの位置に縮小し、対応するブロックのみがその色に 1 単位だけ寄与します。
