 ## 解決策
 ## 問題の理解

 固定長の文字列を構築するように求められます$N$、英小文字を使用して、できるだけ多くの異なる所定のパターン単語を「含む」ようにします。 パターンは、構築された文字列内のどこかに連続した部分文字列として出現する場合、存在するとみなされます。 各パターンは、複数回出現する場合でも、最大 1 ポイントに寄与します。 

したがって、タスクは出現回数を数えることではなく、単一の長さを選択することです。$N$の数を最大化する文字列$K$短い単語がその中のどこかに現れるとします。 

制約の構造は非常に小さいです。$N \le 14$、$K \le 10$、各パターンの長さは最大 7 です。これは、応答空間が で指数関数的であることをすぐに示唆しています。$N$ですが、それでもビットマスク動的プログラミングには十分小さいです。 26 文字にわたる長さ 14 の文字列は天文学的に大きいため、完全な文字列を直接検索することは不可能です。 ただし、重要な観察は、長さが最大 ​​7 の部分文字列間の相互作用のみが重要であるため、最近の文字のスライディング ウィンドウを超えて何も考慮する必要がないということです。 

素朴なアプローチではすべてを試してしまうだろう$26^N$文字列を調べて、それぞれにどのパターンが現れるかを確認します。 これはすでに不可能です$N=14$、 以来$26^{14}$実行可能な計算をはるかに超えています。 

2 番目の単純なアイデアは、文字列を段階的に構築し、即時のパターン一致を最大化する文字を貪欲に選択することです。 これは失敗します。パターンは、将来のいくつかの文字が選択された後でのみ一致可能になる可能性があり、ローカルの決定によって永続的にブロックされる可能性があるためです。 

重複するパターンが競合する場合、さらに微妙な失敗ケースが発生します。 たとえば、1 つのパターンを早期に完了するキャラクターを選択すると、両方がスコアに貢献する場合でも、後で長く重複するパターンが形成されるのを防ぐ可能性があります。 

したがって、正しいソリューションでは、どのパターンが将来完全に一致する可能性があり、どのパターンがすでに一致しているかに関する部分的な情報を追跡する必要があります。 

## アプローチ

 ここでの中心的な構造は、短い文字列を構築し、その中に小さな禁止パターンが現れるかどうかを気にするということです。 すべてのパターンの長さは最大 7 であるため、文字を追加する場合、最後の最大 7 文字のみが新しい一致に寄与できます。 

これは、文字列全体ではなく、構築された文字列の短い接尾辞を記憶する動的プログラミング状態を示唆しています。 

ブルート フォース ビューでは、次の長さのすべての文字列が考慮されます。$N$。 各文字列について、すべてをスキャンします$K$パターンを調べて、それぞれが部分文字列として表示されるかどうかを確認し、おおよそのコストを計算します$O(N \cdot K \cdot 7)$。 これはすでに文字列ごとに管理できますが、文字列の数により実行不可能になります。 

主な改善点は、文字列を左から右に構築し、将来のパターン一致を評価するために必要なもののみを維持することです。 どの時点でも、プレフィックスに関して重要なのは次のことだけです。 

最後の最大 7 文字と、どのパターンがすでに表示されているか。 

これにより、問題は、サフィックス文字列と一致したパターンのビットマスクで構成される状態にわたるグラフの走査に帰着します。 

各ステップは、1 文字の追加、サフィックスの更新 (最後の 7 文字のみを保持)、新しいサフィックス ウィンドウに表示されるパターンの更新によって移行します。 

以来$N \le 14$、DP ステップの数が少なく、接尾辞の長さが最大 ​​7 であるため、状態空間は次のように制限されます。$26^7 \cdot 2^{10}$ただし、実際には、到達可能な状態のみが問題となります。 

ステップとサフィックスに対して動的プログラミングを使用し、各状態で達成可能な最適なマスクを保存します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 文字列に対するブルートフォース |$O(26^N \cdot N \cdot K)$|$O(1)$| 遅すぎる |
 | サフィックス + マスク上の DP |$O(N \cdot 26^7 \cdot K)$(到達可能な州ははるかに少ない) |$O(26^7 \cdot K)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各 DP 状態は、構築された文字列内の現在位置、文字列の最後の最大 7 文字、およびどのパターンがすでに出現しているかを示すビットマスクによって表されます。 

また、パターンの一致を繰り返しチェックするのはコストがかかるため、考えられる小さな文字列サフィックスごとに、どのパターンが含まれているかを事前計算します。 

### ステップ

 1. 初期状態が一致するパターンのない空の文字列である DP テーブルを初期化します。 サフィックスは空で、ビットマスクはゼロです。 これは、文字が選択される前の開始を表します。 
2. 0 から 0 までの各位置について$N-1$では、「a」から「z」までの 1 文字を追加することで、到達可能なすべての状態を拡張することを検討します。 これは、文字列を段階的に構築することに対応します。 
3. 文字が追加されると、それを連結し、最後の 7 文字をトリミングすることによってサフィックスを更新します。 7 より長いパターンはないため、これより前のパターンは新しい一致を形成できないため、これで十分です。 
4. 新しい接尾辞については、その中の部分文字列としてどのパターンが現れるかを決定します。 パターンがどこかに出現すると、永久にカウントされ続けるため、これらのパターンを現在のビットマスクに OR 演算します。 
5. (位置、サフィックス) のペアごとに、達成可能な最良のビットマスクを保存します。 2 つの方法が同じサフィックスに到達する場合、より適切なマスクを持つ方法のみが保持されます。 
6. すべての処理が完了したら$N$位置に応じて、すべての最終状態をスキャンし、最大ビットマスク値、つまり最も多くのパターンに一致した状態を選択します。 
7. 遷移中に親ポインタを格納することにより、その状態に至る有効な文字列を再構築します。 

### なぜ効果があるのか

 正しさは、パターンの出現が完了する位置で終わる最大 7 の長さのウィンドウによって完全に決定されるという事実に依存します。 したがって、最後の 7 文字を維持すると、今後の一致を検出するために必要な情報が失われることはありません。 DP は完全な履歴には依存せず、この境界付きサフィックスのみに依存します。 すべての遷移ではサフィックスと蓄積されたパターン セットの両方が保持されるため、将来の拡張によって過去の正確性が変更されることはなく、深さで最適なマスクが維持されます。$N$最適な構造に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, K = map(int, input().split())
    patterns = [input().strip() for _ in range(K)]
    
    # Precompute pattern matching in a string
    def calc_mask(s):
        mask = 0
        for i, p in enumerate(patterns):
            if p in s:
                mask |= (1 << i)
        return mask
    
    from collections import defaultdict
    
    dp = [defaultdict(lambda: -1) for _ in range(N + 1)]
    parent = [{} for _ in range(N + 1)]
    
    dp[0][""] = 0
    
    for i in range(N):
        for suf, mask in dp[i].items():
            for c in "abcdefghijklmnopqrstuvwxyz":
                ns = (suf + c)[-7:]
                nmask = mask | calc_mask(ns)
                
                if dp[i + 1][ns] < nmask:
                    dp[i + 1][ns] = nmask
                    parent[i + 1][ns] = (suf, c)
    
    best_mask = -1
    best_state = None
    
    for suf, mask in dp[N].items():
        if mask > best_mask:
            best_mask = mask
            best_state = suf
    
    # reconstruct
    res = []
    cur = best_state
    for i in range(N, 0, -1):
        prev, ch = parent[i][cur]
        res.append(ch)
        cur = prev
    
    print("".join(reversed(res)))

if __name__ == "__main__":
    solve()
```DP テーブル`dp[i]`可能な各接尾辞を長さごとにマップします`i`一致したパターンの最適なビットマスクに変換します。 移行ステップはすべての文字を反復し、1 文字を追加し、接尾辞の最後の 7 文字のみを保持します。 ヘルパーさん`calc_mask`新しいサフィックス内にどのパターンが現れるかをチェックし、マスクを更新します。 

の`parent`構造体には各状態にどのように到達したかが格納されるため、DP の終了後に実際の文字列を再構築できます。 この問題では最大値だけでなく文字列自体が要求されるため、これが必要になります。 

微妙な点は、同じ長さの同じサフィックスのマスクのみを比較することです。 これにより、異なるパターン セットを持つ同一のサフィックスに到達する最適なパスが失われることが防止されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、プレフィックスの繰り返しなど、すべてのパターンが重なり合う場合です。 最後の 7 文字内にパターンが出現すると、そのパターンはマスクに永続的に記録され、失われることはないため、DP は複数の一致を正しく蓄積します。 

もう 1 つの特殊なケースは、文字の長いチェーンの後にのみパターンが表示される場合です。 サフィックスは常に長さ 7 にトリミングされるため、それより長いパターンは不可能ですが、制約によりこれが明示的に阻止されます。 したがって、有効なパターンが誤って「切り取られる」ことはありません。 

最後のエッジ ケースは、複数の異なる構築パスが同じサフィックスにつながる場合です。 DP は最大マスクのみを保持することによってそれらをマージします。これは、将来の拡張はサフィックスに到達する方法ではなく、サフィックスとマスクのみに依存するため安全です。
