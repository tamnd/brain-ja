 ## 解決策
 ## 問題の理解

 シャフトの根が生えた木のような形をした鉱山が与えられます。シャフト 1 が最上部にあり、他のすべてのシャフトには、一意の親につながる上向きの接続が 1 つだけあります。 この構造により、任意の 2 つのシャフト間には 1 つの単純なパスが存在します。 

各シャフトには既知の量の石炭が含まれています。 採掘キャンプは、選択された立坑 V に配置されます。そのキャンプから、鉱山労働者は、キャンプ立坑そのものと、ツリー内でその下にある立坑から石炭を抽出することができますが、それは最大 H エッジの距離内にいる場合に限られます。 移動はツリーの下方向への移動に制限されているため、到達可能な領域はまさに V のサブツリーであり、深さ H で切り詰められています。 

各クエリに対して、開始シャフト V と必要な石炭量 S が与えられます。距離 H 内の V のサブツリー内のすべてのノードの石炭の合計が少なくとも S になるような最小の H を見つける必要があります。V の子孫をすべて取得しても S に達しない場合は、-1 を返します。 

制約は大きく、最大 80,000 ノードと 125,000 クエリです。 クエリごとに到達可能な合計を最初から再計算するソリューションは、クエリごとに線形走査であっても、最悪の場合、およそ 10^10 の操作が発生するため、遅すぎます。 

主要な構造特性は、ツリーが静的でルート化されており、すべてのクエリが下向きのメトリック ボールの合計のみを尋ねることです。 これは、サブツリー構造を前処理し、オイラーまたは DFS オーダーを介した高速範囲クエリを介してクエリに応答することと、増加する深さ制限を効率的に処理する方法を組み合わせることを強く示唆しています。 

単純な間違いは、サブツリーの合計だけで十分であると想定することです。 距離が重要であるため、これは失敗します。 もう 1 つのよくある間違いは、これを深さ順の単純なプレフィックスとして扱うことですが、ツリーを慎重に平坦化しない限り、深さ順は単一の配列内で連続していません。 

S が 0 の場合、または V がリーフの場合、微妙なエッジ ケースが発生します。 V が葉であり、S がその値より大きい場合、答えは -1 でなければなりません。 もう 1 つのエッジ ケースは、必要な S が完全なサブツリーの合計に正確に等しい場合です。この場合、H は部分的な合計のために早く停止するのではなく、そのサブツリーの最大の深さまで拡張する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各クエリについて、ノード V から開始して、H を 0 から上に向かって徐々に増加させます。 各 H について、V のサブツリー内のすべてのノードを走査し、V からの距離が最大でも H であるかどうかを確認し、それらの石炭値を合計します。 合計が S に達するとすぐに停止し、H を報告します。 

これは、定義を直接シミュレートするため、正しいです。 しかし、その代償は悲惨なものです。 最悪の場合、単一のクエリがツリーのほぼ全体を複数回スキャンする可能性があり、H は最大 N まで増加する可能性があるため、H あたりの作業量は O(N)、つまり最悪の場合はクエリあたり O(N^2) になります。 

重要な観察は、H が増加するにつれて、到達可能なノードのセットが増加するだけであるということです。 これにより、石炭の合計は、任意の固定 V に対する H の単調非減少関数になります。単調性を認識したら、クエリごとに H を二分探索できます。 

残りの課題は、固定の V と H に対して、V との深さの差が最大 H である V のサブツリー内のノードの合計を計算することです。これは、深さ制約のあるサブツリー ノードに対する範囲クエリになります。 DFS 順序でツリーを平坦化し、深さによってノードをグループ化することで、オイラー順序で各深さのノードを維持でき、深さレイヤーごとの高速範囲合計クエリが可能になります。 次に、バイナリ検索の各チェックは、前処理に応じて最大 O(log N) または償却セグメントの合計に減ります。 

したがって、構造は古典的なパターンになります。つまり、ツリーの平坦化と深さの分解、そして答えに対する二分探索です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²Q) | O(N) | 遅すぎる |
 | 二分検索 + 深さのクエリ | O(Q log N log N) | O(N log N) | 承認済み |

## アルゴリズムのチュートリアル

 ツリーのルートを 1 に設定し、DFS を実行して各ノードの 2 つのキー値 (オイラー ツアーでのエントリ時間とルートからの深さ) を計算します。 オイラー ツアーでは、各サブツリーが配列内の連続したセグメントに対応することが保証されます。 

次に、深さ d ごとに、その深さのすべてのノードを収集し、それらのオイラー エントリ時間をソートされた順序で保存します。 これに加えて、その並べ替え順序に合わせて石炭価値のプレフィックス合計を維持します。 これにより、任意のサブツリー範囲 [tin[V], tout[V]] 内の深さ d にあるノードの合計を迅速に計算できます。 

クエリ (V, S) の場合、subtree(V) の u と Depth[u] ≤ Depth[V] + H を満たすすべてのノード u の合計が少なくとも S になるような最小の H が必要です。 

以下のように進めていきます。 

1. 深さ制限 L = Depth[V] + H を計算します。これにより、問題は深さレイヤーからの寄与の蓄積に変換されます。 
2. 固定 H の場合、深さ [V] から L までのすべての深さ d を反復処理して石炭の合計を計算します。深さ d ごとに、オイラー インデックスの二分探索を使用して、その深さのノード間でサブツリー (V) にどれだけの石炭があるかをクエリします。 
3. Hを増加させるとLが増加するだけなので、総和はHでは単調になります。 
4. クエリごとに、[0, N] の範囲で H をバイナリ検索します。 各中間点チェックでは、深層構造を使用して合計が計算されます。 
5. H = N でも足りない場合は、-1 を出力します。 

重要な考え方は、サブツリー制約がオイラー順序で間隔制約になり、深さ制約がグループ化されたリストになるということです。 それらの交差は、深さごとの範囲カウントによって効率的に計算できます。 

### なぜ効果があるのか

 正確さは 2 つの不変式に依存します。 まず、オイラー ツアー順序付けでは、すべてのサブツリーが連続セグメントであることが保証されるため、サブツリー (V) のメンバーシップは範囲チェックになります。 2 番目に、深さのグループ化により、固定の深さのすべてのノードがオイラーの昇順で格納されるため、二分探索境界を使用してサブツリー内に含まれるノードの数をカウントできます。 

サブツリー メンバーシップと深さ制約は両方とも範囲として独立して表現できるため、それらの交差を効率的にカウントできます。 H の単調性により、二分探索で候補を見逃すことなく最小有効半径が見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

N = int(input())
M = list(map(int, input().split()))

parent_info = list(map(int, input().split()))
tree = [[] for _ in range(N)]

for i, p in enumerate(parent_info, start=1):
    tree[p - 1].append(i)

tin = [0] * N
tout = [0] * N
depth = [0] * N
timer = 0

def dfs(u, d):
    global timer
    depth[u] = d
    tin[u] = timer
    timer += 1
    for v in tree[u]:
        dfs(v, d + 1)
    tout[u] = timer - 1

dfs(0, 0)

max_depth = max(depth)
depth_nodes = [[] for _ in range(max_depth + 1)]
depth_vals = [[] for _ in range(max_depth + 1)]

for i in range(N):
    depth_nodes[depth[i]].append(tin[i])
    depth_vals[depth[i]].append(M[i])

for d in range(max_depth + 1):
    order = sorted(range(len(depth_nodes[d])), key=lambda i: depth_nodes[d][i])
    depth_nodes[d] = [depth_nodes[d][i] for i in order]
    depth_vals[d] = [depth_vals[d][i] for i in order]
    for i in range(1, len(depth_vals[d])):
        depth_vals[d][i] += depth_vals[d][i - 1]

def query_subtree_depth(u, d):
    l, r = tin[u], tout[u]
    if d > max_depth:
        return 0

    arr = depth_nodes[d]
    if not arr:
        return 0

    import bisect
    left = bisect.bisect_left(arr, l)
    right = bisect.bisect_right(arr, r)
    if left >= right:
        return 0
    return depth_vals[d][right - 1] - (depth_vals[d][left - 1] if left > 0 else 0)

def calc(u, limit_depth):
    res = 0
    base = depth[u]
    for d in range(base, limit_depth + 1):
        res += query_subtree_depth(u, d)
    return res

Q = int(input())

for _ in range(Q):
    V, S = map(int, input().split())
    V -= 1

    lo, hi = 0, N
    ans = -1

    if M[V] >= S:
        lo = 0
        hi = N
    else:
        lo = 1
        hi = N

    while lo <= hi:
        mid = (lo + hi) // 2
        total = calc(V, depth[V] + mid)
        if total >= S:
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)
```DFS は、すべてのサブツリーが連続セグメントになるようにオイラー区間を構築します。 深さごとの配列にはオイラー順序でノードが格納され、プレフィックス合計により固定深さ内で O(1) 範囲合計抽出が可能になります。 機能`calc`許可されたすべての深さから現在の半径までの寄与を累積します。 

各クエリの二分探索は、H の増加に伴う到達可能な石炭の単調増加に依存します。 

微妙な実装の詳細は、空の深さレベルと境界ケースを二等分で処理することです。 もう 1 つは、深さのインデックス作成が事前に計算された最大深さを超えないようにすることです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、必要な合計 S が V のサブツリー全体の石炭の合計よりも大きい場合です。この場合、二分探索では大きな H が返される可能性がありますが、実行不可能性を検出して -1 を出力するのが正しい動作です。 最大 H であっても累積合計が S に達することはないため、アルゴリズムはこれを自然に処理します。`ans`−１のままです。 

もう 1 つのエッジ ケースは、V がリーフ ノードである場合です。 DFS 構造により、次のことが保証されます。`calc(V, depth[V])`ノード自体のみをカウントします。 S が M[V] より大きい場合、すべての二分探索反復は失敗し、正しく -1 が返されます。 

最後の微妙なケースは、深さが非常に大きい、歪んだ木です。 深度インデックス付けは実際の木の高さによって制限され、深度レイヤーがまばらな場合でもオイラー セグメンテーションによって正確さが保証されるため、深度ごとの反復は正確なままです。
