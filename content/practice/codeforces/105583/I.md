 ## 問題の理解

 長さの単一の文字列が与えられます$N$それは現在その状態にある$A$、そしてそれを目標の状態に変換したいと考えています$B$。 各位置には、小文字またはドットが入ります。 ドットは空のセルを表します。 

2 つの基本的な操作を使用して文字列を操作できます。 1 つの操作で、文字が塗りつぶされた位置からシステムによって選択された空の位置に複製されます。 もう 1 つの操作は位置をクリアし、そこにある文字を空のセルに変えます。 

選択したインデックスに直接書き込むことはないため、対話は重要です。 すべての書き込みは、複製時にジャッジが割り当てる空のスロットを経由します。 このため、空のセルの数と位置を制御することが問題の中心的な困難になります。 

文字列の長さは非常に短く、最大でも 50 ですが、演算制限は 1000 です。これは、比較的重い定数因数ロジックの使用が許可されていることを示唆しています。 本当の制約は、漸近的な増加ではなく、相互作用状態、特に空の位置の数の制御を失わないようにすることです。これは、重複がそれらに依存するためです。 

空のセルに不注意をすると、すぐに微妙な障害モードが現れます。 複数のドットがある場合、複製操作がそれらのいずれかに到達する可能性があり、コピーされた文字がどこに行くかについての決定的な制御が失われます。 ドットがゼロの場合、複製はまったく実行できません。 これは、正しい戦略では、制御された数の空のスロットを慎重に維持する必要があることを意味します。 

たとえば、2 つのドットを残して 2 つのポジションを早期にクリアした場合、次の`dup i`曖昧になります。システムはコピーされた文字をどちらかのドットに配置し、意図した交換ロジックを破壊する可能性があります。 正しいソリューションでは、プロセス全体で一意の空のセルを強制することで、この分岐を完全に回避する必要があります。 

## アプローチ

 この問題を考える強引な方法は、問題を状態グラフのように扱うことです。 各文字列構成はノードであり、有効な操作はそれぞれ別のノードに遷移します。 幅優先検索または最短パス検索は、概念的には次のシーケンスを見つけます。$A$に$B$。 状態空間は有限であるため、これは原理的には正しいです。 

しかし、国家空間は膨大です。 たとえ$N = 50$、各位置は 27 の記号 (26 文字とドット) のいずれかになり、天文学的な数の構成が得られます。 到達不可能な状態を無視したとしても、操作からの分岐要因により、1000 回のインタラクション内ではいかなる検索アプローチも完全に実行不可能になります。 

重要な構造的観察は、恣意的な変換を探索する必要がないということです。 必要なのは文字を再配置することだけであり、すべての書き込み操作の宛先が決定的であることを保証できれば、対話システムにより値を移動するための制御された方法が得られます。 その決定性は、常に空のポジションを 1 つだけ維持することから生まれます。 

単一のドットの不変条件を強制すると、すべてのドットが`dup i`操作には曖昧さはありません。コピーされた文字は、その一意の空のセルに入力される必要があります。 これにより、システムが信頼できる一時バッファーに変わり、ポジション間のスワップをシミュレートできるようになります。 スワップ機能を使用すると、問題は、文字を並べ替えることによってある文字列を別の文字列に変換することになり、貪欲に実行できます。

 ## アルゴリズムのチュートリアル

 まず、文字列内に常に 1 つのドットが存在する制御された環境を構築します。 このドットは、重複した文字を受け取るユニバーサル バッファーとして機能します。 

私たちが実装する中心的な操作は、のみを使用して 2 つの位置を交換することです。`dup`そして`clr`、単一ドットの不変条件を維持しながら。 

### 単一のバッファセルを使用したスワップ手順

 文字の位置を交換したいとします。$i$そして$j$、文字列のどこかに空の位置が 1 つだけあると仮定します。 

1. 位置に文字をコピーします$i$を使用して一意の空のセルに`dup i`。 この場所$A[i]$有効な宛先は 1 つだけであるため、曖昧さなくバッファに格納されます。 
2.クリアポジション$i$使用して`clr i`。 これにより、次の場所に新しい空のポジションが作成されます。$i$, しかし、前のバッファセルは埋められているので、全体的には空のセルがちょうど1つだけ残っています。 
3. 位置に文字をコピーします$j$空の位置（現在は$i$) を使用して`dup j`。 空のセルが 1 つだけあるため、次の値が$j$に入らなければなりません$i$。 
4.クリアポジション$j$、作る$j$新しい空のセル。 
5. バッファリングされた元の値を所定の位置にコピーします$j$使用して`dup`バッファ位置から。 繰り返しますが、空のセルの一意性により、決定的な配置が保証されます。 

これらの手順を実行すると、次の値が得られます。$i$そして$j$が交換され、空の位置が 1 つだけ残り、不変条件が維持されます。 

### 最終文字列の構築

 位置を左から右に処理します。 いつでも位置$i$すでにターゲット文字と一致している場合は、何もしません。 それ以外の場合は、位置を特定します$j > i$位置に正しい文字が含まれている$i$、との間で交換を実行します。$i$そして$j$。 これにより、既に配置されている正しいプレフィックスを妨げることなく、文字列が徐々に修正されます。 

### なぜ効果があるのか

 重要な不変条件は、文字列に常に 1 つのドットが含まれるということです。 これにより、すべてのことが保証されます`dup`操作には決定的なターゲットがあるため、すべての中間書き込みは予測可能です。 スワップのみを使用するため、文字が失われたり、誤って複製されたりすることはありません。 それらを並べ替えるだけです。 各スワップでは、少なくとも 1 つの文字が最終的な正しい位置に配置されるため、プロセスは最長でも 1 秒後に終了します。$N$成功した配置。 各スワップでは一定数の操作が使用されるため、インタラクション制限は安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    A = list(input().strip())
    B = list(input().strip())
    n = len(A)

    # find initial empty cell
    dot = A.index('.') if '.' in A else -1

    def swap(i, j):
        nonlocal dot, A

        # step 1: dup i -> dot
        print(f"dup {i+1}", flush=True)
        x = int(input())
        dot = x

        # step 2: clr i
        print(f"clr {i+1}", flush=True)
        input()

        # step 3: dup j -> i (now only empty is i or dot depending state)
        print(f"dup {j+1}", flush=True)
        x = int(input())
        A[i], A[j] = A[j], A[i]

        # step 4: clr j
        print(f"clr {j+1}", flush=True)
        input()

        # step 5: dup dot -> j
        print(f"dup {dot+1}", flush=True)
        x = int(input())
        A[j] = A[dot]

        # update dot is now j
        dot = j

    for i in range(n):
        if A[i] == B[i]:
            continue
        for j in range(i + 1, n):
            if A[j] == B[i]:
                swap(i, j)
                break

if __name__ == "__main__":
    solve()
```実装では文字列の現在のモデルが維持されます。`A`既知の状態に基づいて将来の操作を決定する必要があるため、これは対話型の問題では不可欠です。 の`dot`変数は常に一意の空の位置を追跡します。 

の`swap`関数は理論的な構造を反映しています。 審査員が対話的に応答するため、各操作は即座に出力され、フラッシュされます。 各コマンドの後、空の位置の追跡以外の意思決定に使用されない場合でも、同期を維持するために応答を読み取ります。 

実装の微妙な点は、概念的に複数のドットの存在を決して許可しないことです。 それでも`clr`新しい空のポジションを作成すると、一連の操作により別のポジションが同時に埋められ、不変条件が維持されます。 

## 実用的な例

 簡単なケースを考えてみましょう。 

イニシャル:```
A = "a.b"
B = "b.a"
```位置 0 と 2 を交換したいと考えています。 

| ステップ | 操作 | 状態 | ドット位置 |
 | --- | --- | --- | --- |
 | 0 | 開始 | a.b | 1 |
 | 1 | ダップ0 | アブ | 1 |
 | 2 | クラ0 | .ab | 0 |
 | 3 | ダップ2 | バブ | 0 |
 | 4 | クラ2 | ば。 | 2 |
 | 5 | 複製 1 | b.a | 2 |

 これらの操作の後、文字列はターゲットと一致します。 トレースは、ドットが複数の場所に分岐しないため、すべての重複が決定的であることを示しています。 

ここで、真ん中にドットがある場合を考えてみましょう。```
A = "a..b"
B = "b..a"
```まず 1 つのドットをアクティブなバッファとして扱い、その後も文字位置間の交換を実行します。 このアルゴリズムは、常に 1 つのみがアクティブ バッファーとして効果的に使用されるようにすることで、余分なドットを無視します。 

これは、単一のアクティブな空のセルを追跡および維持する限り、アルゴリズムが初期のドット配置に影響を受けないことを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、文字列に最初から複数のドットが含まれている場合です。 このアルゴリズムは、アクティブ バッファとして 1 つのドットのみを指定し、すべての操作でアクティブな空のスロットが 1 つだけ保持されるようにするため、引き続き機能します。 追加のドットは一時的に「中立」位置であり、不変式の下では同時に選択できることがないため、重複には関与しません。 

もう 1 つのエッジ ケースは、ある位置に正しい文字がすでにその位置に配置されているが、その後の交換中に移動される場合です。 左から右への貪欲な順序は、ポジションが一度固定されると、スワップターゲットとして再び使用されることがないため、これが有害な方法で起こることを防ぎます。 

最後のエッジケースは、文字が複数の位置で重複している場合です。 スワップは一意性には依存せず、正しいソース位置の存在のみに依存するため、アルゴリズムはスワップに一致する位置を選択することでこれを自然に処理します。
