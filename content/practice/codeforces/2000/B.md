 ## 解決策
 ## 問題の理解

 私たちはバスを持っています`n`1 列の座席で、1 から 2 までの番号が付いています。`n`。 乗客は一人ずつ乗車し、簡単なルールに従って座席を選択します。最初の乗客はどこに座っても構いませんが、後続の乗客はすでに占有されている座席の隣に座らなければなりません。 によって選ばれた議席の時系列順が与えられます。`n`乗客は、各乗客がこの推奨事項に従ったかどうかを判断する必要があります。 

入力は複数のテスト ケースで構成されます。 各テスト ケースが提供するのは、`n`そして座席番号の配列。 テスト ケース内のすべての乗客が隣接ルールに従っていた場合、出力は「YES」、そうでない場合は「NO」になります。 

制約により許可されるのは、`n`テスト ケースごとに 2 · 10^5 に達するまで、最大 10^4 のテスト ケースを使用できますが、すべてのテスト ケースの合計は`n`すべてのテスト ケース全体で、最大 2·10^5 です。 これは、O(n^2) アプローチを使用する余裕がないことを意味します。これは、最悪の場合、約 4・10^10 の演算を実行することになるからです。 全体的に線形または線形に近い複雑さを持つソリューションが必要です。 

エッジケースは、最初の数人の乗客がバスの端を占有する場合に発生します。 たとえば、次の場合`n = 5`そしてそのシーケンスは`[5, 4, 2, 1, 3]`、3番目の乗客が座席を選択します`2`、どちらの近隣も占有されていないため無効です。 これまでのシーケンスに座席番号が存在するかどうかだけをチェックする単純なアプローチでは、その時点では占有されている座席が連続していないため、これを見逃してしまいます。 

もう 1 つの微妙なケースは、乗客が一方の端から厳密に昇順または降順で座席を占有する場合に発生します。これは、すべての新しい座席が現在占有されているセグメントに隣接しているため当てはまります。 占有座席の連続セグメントを検出することは非常に重要です。 

## アプローチ

 強引なアプローチは簡単です。最初の乗客以降の各乗客について、すぐに左右の座席をチェックし、どちらかが埋まっているかどうかを確認します。 これは論理的に機能しますが、各チェックでは占有座席のリストをスキャンする必要があるため、テスト ケースごとに O(n^2) になります。 これは大規模な場合には不可能になります`n`。 

重要な観察は、どの時点においても、有効な座席のセットが占有座席の連続したブロックを形成しているということです。 新しい乗客はそれぞれ、左端または右端の占有座席のすぐ隣に座って、このブロックを拡張する必要があります。 したがって、現在占有されている左端と右端の座席を追跡するだけで済みます。 最初の乗客の場合は、両端をその座席に設定します。 後続の各乗客は、現在の左端のすぐ左か、現在の右端のすぐ右に座らなければなりません。 乗客がこれら 2 つのオプション以外の座席を選択した場合、規則に違反します。 

この観察により、2 つの変数を維持しながらシーケンスの O(n) スキャンが可能になります。`left`そして`right`、現在占有されているセグメントを表します。 複雑なデータ構造は必要ありません。 このソリューションはシンプルかつ効率的であり、特定の制約に対して理想的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての占有席をスキャン) | O(n^2) | O(n) | 遅すぎる |
 | セグメント トラッキング (2 つのポインタ) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのポインターを初期化します。`left`そして`right`、 に`-1`。 これらは、現在占有されている座席の連続したブロックを追跡します。 
2. 乗客の一連の座席選択を繰り返します。 
3. 最初の乗客の場合は、両方を設定します`left`そして`right`自分の座席番号に。 これにより、最初のセグメントが確立されます。 
4. 後続の乗客ごとに、自分の座席がすぐ左側にあるかどうかを確認します (`seat == left - 1`) またはすぐ右 (`seat == right + 1`) 現在のセグメントの。 
5. シートが左端まで伸びている場合は、更新します`left`この新しい席へ。 右端を伸ばしたら更新`right`。 どちらの端にも伸びていない場合は、このテスト ケースでは「NO」を返します。 
6. すべての乗客が隣接条件を満たしている場合は、「YES」を返します。 

機能する理由: 左端と右端の占有座席を維持することで、占有座席が連続したセグメントを形成することが保証されます。 乗客はこの区間に隣接して座ることのみが許可されているため、違反があった場合は直ちに規則違反となります。 この不変条件は各ステップの後に維持され、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def seating_in_bus():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        left = right = -1
        valid = True
        
        for seat in a:
            if left == -1:
                left = right = seat
            elif seat == left - 1:
                left = seat
            elif seat == right + 1:
                right = seat
            else:
                valid = False
                break
        
        print("YES" if valid else "NO")

if __name__ == "__main__":
    seating_in_bus()
```コードが初期化されます`left`そして`right`に`-1`空のバスを示します。 各乗客について、現在占有されているセグメントの隣に座っているかどうかを確認します。 セグメント境界を更新すると、後続のチェックが有効なままになります。 小切手`seat == left - 1`そして`seat == right + 1`両端を効率的に処理します。 最初の違反を早期に中断すると、不必要な計算が回避されます。

## 特殊なケース

 最初の乗客が中央に座る場合、たとえば、`n = 5`、 順序`[3, 2, 4, 1, 5]`、アルゴリズムが初期化されます`left=right=3`。 乗客 2 は次の場所に座ります`2`(`left-1`)、更新中`left=2`。 乗客 3 は次の場所に座っています。`4`(`right+1`)、更新中`right=4`。 乗客 4 が座るのは`1`(`left-1`)、更新中`left=1`。 乗客 5 は次の場所に座っています。`5`(`right+1`)、更新中`right=5`。 各ステップでは、連続セグメントの不変式が維持されます。 アルゴリズムは正しく「YES」を出力します。 これにより、両方向における自明ではないセグメントの増加が適切に処理されることが確認されます。
