 ## 解決策
 ## 問題の理解

 ボードに書かれた整数のリストが与えられますが、そのうちの 1 つは、いくつかの形式の破損した表現である可能性があります。$10^x$どこ$x \ge 2$。 この破損は、べき乗記号「^」が失われているために発生します。 例えば、$10^5$と書かれていたかもしれない$105$そして$10^{19}$として$1019$。 私たちの仕事は、ボード上の各数字について、それがそのような 10 の累乗の破損したバージョンであるかどうかを判断することです。 可能であれば、「YES」と出力します。 それ以外の場合は、「NO」と出力されます。 

入力サイズでは、それぞれ 10,000 を超えない、最大 10,000 個の整数を使用できます。 この上限は小さいため、複雑な算術変換を行うのではなく、すべての潜在的な有効な数値を事前計算し、各整数の単純なメンバーシップ チェックを実行できることがすぐにわかります。 問題の微妙な点は、何が破損したものとしてカウントされるかを正しく解釈することにあります。$10^x$: 数値は 10 で始まり、任意の数字ではなく、指数の数字が直接連結されている必要があります。 たとえば、1010 は次のようになります。$10^{10}$, しかし、100 や 1023 はできません。 

単純なソリューションがつまずく可能性のあるエッジケースには、100 のような数字が含まれます (これは$10^2$） - 以来$x \ge 2$の場合、破損により 102 が生成される可能性がありますが、100 は生成されません。同様に、1002 のような数値は慎重に解釈する必要があります。$10^2$指数として '2' が追加されていますが、指数は 2 である必要がありますが、桁が一致しないため、1002 自体は有効な破損した形式に対応しません。 小さな数値、先頭に複数のゼロがある数値、および 10,000 の制限に近い数値は、潜在的な落とし穴となります。 

## アプローチ

 ブルートフォースアプローチでは、再構築が試みられます。$10^x$みんなのために$x \ge 2$、それらを文字列に変換し、「^」記号を削除して破損をシミュレートし、破損した各数値を入力リストと比較します。 これは単一の整数に対しては実行可能ですが、10,000 個の整数や潜在的に非常に大きな指数に対してこれを行うのは非効率的です。 具体的には全部チェックすると、$x$整数は 10,000 で制限されているため、たとえば 1,000,000 までは不要です。 

重要な点は、ボード上の最大整数が 10,000 であるということです。これは、最大の整数を意味します。$10^x$この範囲内で破損した数値が生成される可能性があるのは、$10^2 = 100$まで$10^4 = 10000$。 より一般的に列挙すると、$x$2 から始まり、「10」と次の数字を連結して破損した数字を形成します。$x$1 ～ 10,000 の範囲内に収まるすべての有効な数値を事前計算できます。 次に、各入力数値について、その数値がこの事前計算されたセットに存在するかどうかを確認するだけです。 これにより、問題は数値ごとの定数時間の検索に軽減され、非常に高速になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (各 a について各 x をチェックする) | O(t * max_x) | お(1) | max_x が大きい場合は遅すぎる |
 | 有効な破損した数値を事前計算する | O(max_x + t) | O(max_x) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のセットを初期化して、破損している可能性のあるすべての数値を格納します。$10^x$と$x \ge 2$結果の数値は 10,000 以下です。 O(1) メンバーシップ チェックにはセットを使用します。 
2. 反復する$x$2から始めて変換します$x$を文字列に変換し、それを「10」と連結して、破損した数値をシミュレートします。 この連結された文字列を整数に戻します。 
3. 結果の整数が 10,000 より大きい場合は、ループを中断します。$x$入力範囲の外側にある、より大きな数値のみを生成します。 
4. 有効な各整数をセットに追加します。 
5. 各入力整数について、それが事前計算されたセットに存在するかどうかを確認します。 存在する場合は、「YES」を出力します。 それ以外の場合は、「NO」を出力します。 

これが機能するのは、破損が確定的であるためです。有効な数値は常に「10」で始まり、その後に指数を表す数字が続く必要があります。 入力制約内のすべての可能性を事前計算することで、正確性が保証され、不必要な計算が回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
numbers = [int(input()) for _ in range(t)]

valid_set = set()
x = 2
while True:
    corrupted = int("10" + str(x))
    if corrupted > 10000:
        break
    valid_set.add(corrupted)
    x += 1

for a in numbers:
    if a in valid_set:
        print("YES")
    else:
        print("NO")
```まず、すべての入力をリストに読み取ります。 事前計算ループは、結果の数値が 10,000 を超えるまで、2 から始まる各指数と「10」を連結することによって、すべての有効な破損数値のセットを構築します。 最後のループでは、セットの O(1) ルックアップを活用してメンバーシップを効率的に決定します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t + max_x) | 事前計算は破損が 10000 を超えるまで x をループします。 t 数値のチェックはそれぞれ O(1) です |
 | スペース | O(max_x) | Set には、有効な破損した数値がすべて保存されます。 max_x ≈ 100 |

 t ≤ 10^4 および整数 ≤ 10^4 の場合、最大でも数十の数値の事前計算とメンバーシップのチェックは非常に高速です。 メモリ使用量は最小限です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    
    t = int(input())
    numbers = [int(input()) for _ in range(t)]
    
    valid_set = set()
    x = 2
    while True:
        corrupted = int("10" + str(x))
        if corrupted > 10000:
            break
        valid_set.add(corrupted)
        x += 1
    
    for a in numbers:
        if a in valid_set:
            print("YES")
        else:
            print("NO")
    
    sys.stdout = sys.__stdout__
    return output.getvalue().strip()

# Provided sample
assert run("7\n100\n1010\n101\n105\n2033\n1019\n1002\n") == "NO\nYES\nNO\nYES\nNO\nYES\nNO", "Sample 1"

 ## 特殊なケース

 可能な最小の指数 x = 2 の場合、破損した数値は 102 です。アルゴリズムにはセットに 102 が含まれており、入力 '102' が "YES" として正しく識別されることが保証されます。 10002 など、10,000 の制限をわずかに超える数値の場合、事前計算ループはそれらを含める前に停止するため、アルゴリズムは正しく「NO」を返します。 セットベースの検索では、繰り返しの数値や順序付けされていない入力が正確さに影響を与えないことが保証されます。 破損した数値が確定的に形成されるため、有効な数値が省略されることはありません。
