 ## 解決策
 ## 問題の理解

 私たちは、各エッジに 2 つの移動モードがある重み付き無向グラフに取り組んでいます。 徒歩はいつでも利用でき、時間がかかりますが、バスは早いですが、日中の一定時間以外にのみ利用できます。 不明な出発時刻にノード 1 から出発し、期限までにノード n に到着したいとします。 ただし、徒歩は許可されますが、バスには乗車できない強制的な間隔があります。 

目標は、バス制限間隔を遵守し、期限までに到着するノード n への有効なルートがまだ存在するように、ノード 1 から可能な最も遅い開始時刻を決定することです。 

この制約により、すべてのテスト ケースにわたって合計で最大 100,000 個のノードとエッジを処理する必要があるソリューションが必要になります。 これにより、クエリごとまたは開始時間ごとに繰り返される最短パスの計算が排除されます。 テスト ケースごとに 1 つの最短パスの計算は実行可能ですが、繰り返しの再計算や時間間隔を超えた状態の爆発を伴うものは実行できません。 

強制的な歩行のみの区間を考慮せずに、バスと徒歩を独立した最短経路として扱うと、微妙な失敗例が発生します。 たとえば、ブロックされた間隔中にパスがバスのエッジに大きく依存している場合、時間制約を無視して計算された単純な最短パスは、移動の実現可能性を誤って過小評価することになります。 

もう 1 つの微妙なケースは、待機が最適になる場合です。 バスの制限は時間に依存するため、バスが再び利用可能になるまで中間ノードでの移動を遅らせることが最適な場合があります。 時間を意識した遷移を行わずに貪欲な連続移動を想定したソリューションは失敗します。 

## アプローチ

 強引なアプローチでは、考えられるすべての出発時刻を試し、バスが無効になっている時間枠を考慮した最短経路のシミュレーションを実行します。 各最短経路の計算には実装に応じて対数または線形の時間がかかり、すべての候補出発時間に対してそれを実行することは制約の下では不可能です。 

重要な観察は、出発時間では実現可能性が単調であるということです。 時間 x に出発し、時間通りに到着することが可能であれば、それより早い時間でも可能です。 この単調性により、答えに対する二分探索が可能になります。 

固定の出発時刻の場合、時間依存のエッジ コストの下でノード n への最も早い到着時刻を計算する必要があります。 これは、各状態にノードだけでなく現在時刻も含まれる、修正されたダイクストラ アルゴリズムを使用して処理されます。 遷移ルール​​は、移動間隔がブロックされたバス ウィンドウと重なるかどうかによって異なります。 徒歩はいつでも許可されますが、バスの移動は区間全体が制限区間外にある場合にのみ許可されます。 バスのトラバースがブロックされた区間に入る場合は、t2 まで待つか、その時点でそのエッジを回避する必要があります。 

これにより、問題は時間依存グラフの最短パスに短縮され、チェックごとに O(m log n) で計算できます。 二分探索と時間をかけて組み合わせると、完全なソリューションが効率的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(T · (n + m)) | O(n + m) | 遅すぎる |
 | 二分探索 + 時間認識ダイクストラ | O((n + m) log n log t) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、時間制限の下での最も早い到着時間を計算することで、指定された出発時間が機能するかどうかをテストできることがわかります。 これが実現可能性チェックの中核となります。 

次に、ゼロから t0 までの出発時刻範囲に対して二分探索を使用します。 各中間点は実現可能性チェックを使用してテストされ、それに応じて検索範囲を調整します。

実現可能性チェックの内部では、修正されたダイクストラ プロセスを実行します。 各州は、ノードに到着できる最も早い時間を追跡します。 常に最小の現在時刻で状態を展開します。 

各エッジについて、2 つの可能な遷移を計算します。 歩くと常に l2 だけ時間が進みます。 バスの移動は l1 ずつ進みますが、間隔 [t1、t2] と交差しない場合にのみ許可されます。 現在時刻がブロックされた間隔内にある場合は、バスに乗る前に t2 まで待つ必要があります。 

t0以内に目的地に到着すれば、出発時間は実現可能です。 

正確さは、ダイクストラの任意の点で、各ノードに保存された時間が、開始条件からのすべての有効な戦略の下で可能な最小到着時間であるという不変式に依存します。 待機は時間の増加とともに常に同じノードに留まるものとしてモデル化でき、すべてのエッジが単調な時間発展を尊重するため、時間依存の遷移は最適な下部構造を維持します。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

INF = 10**30

def can(start_time, n, adj, t0, t1, t2):
    dist = [INF] * (n + 1)
    dist[1] = start_time
    pq = [(start_time, 1)]
    
    while pq:
        t, u = heapq.heappop(pq)
        if t != dist[u]:
            continue
        if u == n:
            return t <= t0
        
        for v, b, w in adj[u]:
            nt = t
            
            if nt >= t1 and nt < t2:
                nt = t2
            
            if nt < t1:
                if nt + b <= t1:
                    nt2 = nt + b
                    if nt2 < dist[v]:
                        dist[v] = nt2
                        heapq.heappush(pq, (nt2, v))
                else:
                    nt2 = nt + w
                    if nt2 < dist[v]:
                        dist[v] = nt2
                        heapq.heappush(pq, (nt2, v))
            else:
                nt2 = nt + w
                if nt2 < dist[v]:
                    dist[v] = nt2
                    heapq.heappush(pq, (nt2, v))
    
    return False

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, m = map(int, input().split())
        t0, t1, t2 = map(int, input().split())
        
        adj = [[] for _ in range(n + 1)]
        for _ in range(m):
            u, v, l1, l2 = map(int, input().split())
            adj[u].append((v, l1, l2))
            adj[v].append((u, l1, l2))
        
        def ok(x):
            return can(x, n, adj, t0, t1, t2)
        
        lo, hi = 0, t0
        ans = -1
        
        while lo <= hi:
            mid = (lo + hi) // 2
            if ok(mid):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1
        
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```二分探索により、有効な最大出発時刻が特定されます。 ダイクストラ ルーチンは、すべての状態がタイム ウィンドウ制限、特に t1 から t2 での強制待機を正しく遵守することを保証します。 重要な実装の詳細は、時間を状態展開の一部として扱い、制限された間隔の外側に完全に適合する場合にのみバス エッジが使用されるようにすることです。 

## 実用的な例

 t1 より前に終了する直接バス パスが 1 から n まで存在する単純なケースを考えてみましょう。 このアルゴリズムにより、バスの連続移動が可能になり、早めの出発時間の実現可能性が即座に確認されます。 制限された間隔と強制的にオーバーラップするしきい値を超えて逸脱が増加すると、実行可能性チェックは失敗し、バイナリ検索ウィンドウが縮小します。 

2 番目のシナリオでは、最短パスは、より高速なバス エッジを取得するために t2 まで中間ノードで待機することに依存しているとします。 [t1, t2) の到着時刻は出力バス エッジを考慮する前に t2 に進められるため、修正されたダイクストラはこれを正しく処理します。

 ## 特殊なケース

 最適なルートが t1 でバス制限間隔に正確に入る必要がある場合、アルゴリズムは続行する前に t2 まで強制的に待機し、不正なバス遷移が発生しないようにします。 唯一の速いルートが区間の中間端を横切る場合、アルゴリズムはそれを正しく拒否し、より遅い歩行パスに戻ります。
