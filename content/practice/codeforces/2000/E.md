 ## 解決策
 ## 問題の理解

 重み付けされたオブジェクトをグリッド上に配置していますが、スコアはグリッド上の値の単なる合計ではありません。 代わりに、すべての配置が複数回寄与します。各セルは、いくつかの重複する固定サイズに参加します。$k \times k$合計スコアは、そのようなサブスクエアすべてのサブスクエア内の値の合計の合計です。 

同様に、各セルはその値に何倍を掛けた値を提供します。$k \times k$サブ正方形がそのセルを覆います。 タスクは、この重み付けされた寄与が最大化されるように、指定されたすべての重みをグリッド セルに配置することです。 

制約の合計サイズは大きいですが、テスト ケースごとではありません。つまり、余裕があることを意味します。$O(nm \log nm)$あるいは$O(nm)$テストケースごとに実行されますが、配置を列挙したり順列を試行したりするようなものではありません。 重要な意味は、構造を並べ替えと決定論的な割り当てに縮小する必要があるということです。 

ここでの単純な間違いは、局所的に考えることです。「あまり役に立たない」と思われるため、大きなゴリラを隅や端に配置します。 カバレッジはジオメトリのみに依存し、セルがグリッド自体の境界上にあるかどうかには依存しないため、これは不正確です。 もう 1 つのよくある失敗は、均一な寄与を想定することです。これは次の場合に破綻します。$k < n,m$内部セルは境界セルよりも多くのサブ正方形に属しているためです。 

たとえば、$3 \times 3$グリッド付き$k=2$、中央のセルがさらに表示されます。$2 \times 2$コーナーよりサブスクエア。 これを無視すると、たとえグリッドが対称的に見えても、高い値が間違って配置され、スコアが失われます。 

## アプローチ

 ブルートフォース ソリューションでは、ゴリラのセルへのすべての配置を試し、寄与度を直接計算します。 まであるので、$nm \le 2 \cdot 10^5$セルでは、重みの順列を考慮する前でさえ、これは階乗的であり不可能です。 

重要な観察は線形性です。合計スコアはセルの合計であり、各セルには次の条件によってのみ決定される固定係数があります。$n, m, k$。 これらの係数を計算すると、問題は純粋に割り当て問題になります。つまり、最大の係数に最大の重みを割り当てるということになります。 

セルの係数を計算するには$(i,j)$、何個数えますか$k \times k$サブスクエアにはそれが含まれます。 これは、行と列の寄与に独立して分割されます。 1D 配列内の特定のインデックスをカバーするウィンドウの数を定義すると、2D の答えは行と列の寄与の積になります。 これにより、問題全体が係数の並べ替えと重みの並べ替えに集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 |$O((nm)!)$|$O(nm)$| 不可能 |
 | 係数ソート |$O(nm \log nm)$|$O(nm)$| 承認済み |

 ## アルゴリズムのチュートリアル

 グリッドをセルごとの重みのリストに縮小し、それを重要度の値のリストと照合します。 

ステップ 1: 各行インデックスについて$i$、垂直方向の配置の数を計算します。$k$-length セグメントがそれをカバーします。 行は、開始位置が交差する範囲内にあるすべてのセグメントでカバーされます。$i$、連続した間隔を形成します。 有効な開始の数が値を与えます$row[i]$。 

ステップ 2: 同様に計算します$col[j]$列用。 これらは同一の 1D スライディング ウィンドウ カバレッジ カウントです。 

ステップ 3: 各セルについて$(i,j)$、その貢献乗数は$row[i] \cdot col[j]$。 これは、$k \times k$正方形は、有効な行間隔と列間隔を選択することによって独立して決定されます。 

ステップ 4: すべてのセル乗算器を単一のサイズの配列にフラット化する$nm$。 

ステップ 5: この配列を降順でない順に並べ替えます。 

ステップ 6: ゴリラの身長を降順でない順に並べ替えます。 

ステップ 7: 最大の高さに最大の乗数を掛けて合計します。 

### なぜ効果があるのか

 スコアは各セル値で線形であり、カバレッジ多重度が固定されるとセル間で独立します。 2 頭のゴリラを交換しても、個々の貢献にのみ影響します。 したがって、より大きな値とより大きな係数を組み合わせると、常に合計が増加または維持されます。これは再配置不等式を直接適用したものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        w = int(input())
        a = list(map(int, input().split()))

        # compute 1D coverage counts
        def coverage(x):
            # number of segments [l, l+k-1] covering x
            # l must satisfy l <= x <= l+k-1
            # => x-k+1 <= l <= x
            # valid l in [1, n-k+1]
            L = max(1, x - k + 1)
            R = min(x, n - k + 1)
            return max(0, R - L + 1)

        row = [coverage(i) for i in range(1, n + 1)]
        col = [coverage(j) for j in range(1, m + 1)]

        vals = []
        for i in range(n):
            for j in range(m):
                vals.append(row[i] * col[j])

        vals.sort()
        a.sort()

        # take largest weights with largest coefficients
        ans = 0
        for i in range(w):
            ans += a[i] * vals[i + (n * m - w)]

        print(ans)

if __name__ == "__main__":
    solve()
```最初の部分では、各行または列のインデックスが有効なインデックスに参加する頻度を計算します。$k$-ウィンドウ。 2 番目の部分では、積構造を介して多重度の完全なグリッドを構築します。 最終的なペアリングでは、ソートを使用して合計を最大化します。 

微妙なポイントは、トップのみを使用していることです。$w$係数だけなので、$w$ゴリラが配置されています。 残りのセルは寄与がゼロになります。 並べ替えにより、最大の高さと利用可能な最大の係数が確実に一致します。 

## 実用的な例

 ### 例 1

 検討してください$n=2, m=2, k=1$、重み$[5,7]$。 

すべてのセルは係数 1 を持ちます。$1\times1$サブスクエアはちょうど 1 つのセルをカバーします。 

| ステップ | 値 |
 | --- | --- |
 | 行/列のカバレッジ | すべて 1 |
 | セル係数 | [1,1,1,1] |
 | ソートされた係数 | [1,1,1,1] |
 | ソートされた重み | [5,7] |

 最大の 2 つの係数を 7 と 5 と組み合わせて 12 とします。 

これにより、次のことが確認されます。$k=1$の場合、問題は任意の 2 つのセルを選択することに帰着します。 

### 例 2

 取ってください$3 \times 3$グリッド付き$k=2$。 行と列のカバレッジは次のとおりです。$[1,2,1]$。 したがって、係数は次のようになります。 

| セル | 値 |
 | --- | --- |
 | コーナー | 1 |
 | エッジ | 2 |
 | 中央 | 4 |

 フラット化されたリスト:$[1,2,1,2,4,2,1,2,1]$並べ替えると得られるもの$[1,1,1,1,2,2,2,2,4]$。 最大の重みは 2 の次の 4 にする必要があります。 

これは、中央配置が優勢である理由と、貪欲な割り当てが必要な理由を示しています。
