 ## 解決策
 ## 問題の理解

 各長方形は次のグリッドです。$a_i$コラムと$b_i$行。 個々のセルに 1 つずつ色を付けることができます。 行が完全に色になるたびに 1 ポイントを獲得します。 列が完全に色になるたびに、1 ポイントも獲得します。 

長方形は独立しています。 1 つの四角形内で色付けされたセルは、他の四角形には影響しません。 私たちの目標は少なくとも稼ぐことです$k$色付きセルの総数を最小限に抑えながら、すべての長方形にわたる合計ポイントを獲得します。 

重要な問題は、セルの色付けが行の補完と列の補完の両方に影響する可能性があることです。 たとえば、列全体に色を付けると、すぐに 1 ポイントを獲得します。 その後、十分な列が完全に色付けされると、一部の行が自動的に完成し、追加のポイントが得られる場合があります。 

制約により、意図された方向が明らかになります。 まであります$1000$すべてのテストケースに四角形が表示されますが、$k \le 100$。 の小さな値$k$は最も重要な事実です。 複雑さが多項式に依存する任意のソリューション$k$おそらく、長方形の面積に応じて何でも受け入れられますが、$a_i b_i$寸法は次のように大きくなる可能性があるため、不可能です$100$。 

よくある間違いは、長方形内のすべての点を同じコストを持つものとして扱うことです。 

を考えてみましょう$6 \times 3$矩形。```
1 4
6 3
```4 点を獲得する最適な方法は、4 つの完全な列に色を付けることです。 各列のコスト$3$細胞なので、答えは$12$。 「ポイントコスト min(a,b)」という単純な考えでは、誤った予測が行われてしまいます。$4 \cdot 3 = 12$他の長方形では 4 番目の点が異なる方法で取得された場合でも同様です。 

もう 1 つの微妙なケースは、行と列が相互作用するときに発生します。 

のために$2 \times 2$矩形：```
1 3
2 2
```3 点を取得するには、両方の列に色を付けます。 これには費用がかかります$4$細胞。 完了した 2 つの列には 2 ポイントが与えられ、両方の行が自動的に完了して、さらに 2 ポイントが与えられます。 コストで実現できる3つのポイント$4$、 ない$6$。 

最後のエッジケースは不可能です。```
2 100
1 2
5 6
```最初の長方形は最大でも貢献できます$1+2=3$ポイント、最大で 2 番目$5+6=11$、合計で$14$。 到達$100$ポイントは不可能なので、答えは$-1$。 

## アプローチ

 ブルートフォースの観点は、すべての四角形でどのセルに色を付けるかを正確に決定することです。 それはすぐに絶望的です。 シングル$100 \times 100$長方形にはすでに含まれています$10^4$したがって、可能なサブセットの数は天文学的な数になります。 

最初の観察は、完了した行と完了した列のみが重要であるということです。 行や列が決して終わらない部分的な進行は役に立ちません。 

あるサイズの 1 つの長方形に注目するとします。$a \times b$。 私たちがまさに望んでいることを想像してください$p$この長方形からの点。 必要な色付きセルの最小数はいくつですか?

 列を完全に色付けする場合のコストは次のとおりです。$b$セルを作成すると、列ポイントが 1 つ獲得されます。 行を完全に色付けすると、コストは次のようになります。$a$セルを作成し、1 行ポイントを獲得します。 

重要な洞察は、単一の長方形に対する最適な戦略は常に行全体または列全体を終了することで貪欲に進められるということです。 させて$$x = \text{number of completed columns}, \qquad y = \text{number of completed rows}.$$そうすれば、私たちは得をします$x+y$ポイント。 

費用はいくらですか?

 完成した列に属するすべてのセルは色付けする必要があります。$xb$細胞。 その後、完了した各行にはすでに次のものが含まれています$x$色付きのセルのみ$a-x$完成した行ごとに追加のセルが必要になります。 

したがって、$$\text{cost}(x,y) = xb + y(a-x).$$対称的に、最初に行から始めることもできます。 最適なシーケンスは、残りの 2 つの方向のうち安い方を繰り返し選択することによって取得されます。 以来$a,b \le 100$、達成可能なポイント数ごとに最小コストを明示的に計算できます。$p$。 

すべての長方形がテーブルを提供すると$$best_i[p] = \text{minimum cost to obtain } p \text{ points},$$世界的な問題はナップザックになります。 

各長方形について、そこから取得するポイントの数を選択します。 合計ポイントが少なくとも以下に達している必要があります$k$、コストの合計は最小限になるはずです。 

以来$k \le 100$、ポイントを超える標準の DP は簡単に十分に高速です。

 ## アルゴリズムのチュートリアル

 ### 1 つの長方形のコスト テーブルを計算する

 長方形の場合$a \times b$、 させて$m=a+b$、可能な最大のポイント。 

配列を構築します`cost[p]`どこ`cost[p]`正確に取得するために必要な色付きセルの最小数です。`p`ポイント。 

編集ソリューションでは、単純な貪欲シミュレーションを使用します。 

仮定する$a \le b$。 コラムの完成にはコストがかかります$b$セルと行の完了にかかるコスト$a$細胞。 最初は行の方が安いため、使い果たされるまで繰り返し行を完了します。 行が完了すると、各列の一部がすでに色付けされているため、その後の列の完了が安くなります。 

同じ推論が次の場合にも対称的に機能します。$b < a$。 

利用可能な最も安価な完了のシーケンスをシミュレートすることにより、すべてのポイント カウントの最小累積コストを次から取得します。$1$に$a+b$。 

### グローバルナップザック

 しましょう`dp[j]`正確に取得するために必要な最小限の合計操作であること`j`いくつかの長方形を処理した後の点。 

最初に:```
dp[0] = 0
dp[j] = INF for j > 0
```各長方形にはローカルテーブルがあります`cost`。 

新しい DP 配列を作成します。 現在のスコアごとに`j`そして達成可能なあらゆる貢献`p`この四角形から更新します$$ndp[\min(k, j+p)] = \min( ndp[\min(k,j+p)], dp[j] + cost[p] ).$$上記のスコア$k$上限がある$k$、「少なくとも」だけなので、$k$「重要です。

 すべての長方形が処理された後、`dp[k]`答えが含まれています。 

### なぜ効果があるのか

 固定長方形の場合、完成したすべての行または列が 1 つのポイントに寄与します。 貪欲な構築により、連続する各ポイントに必要な追加のセルの最小数が生成されます。 同じ数のポイントを取得する別の方法では、同じ数の行と列を完了する必要があり、使用する新しい色のセルの数を減らすことはできません。 

グローバル DP は最適な下部構造に依存します。 各四角形で達成可能なすべてのポイント数の最小コストがわかれば、四角形は独立した選択肢になります。 ナップザック DP は、四角形間のポイントの分布をすべて列挙し、すべての合計スコアの最低コストを維持します。 考えられるすべての割り当てが 1 回だけ考慮されるため、最終的な値が最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10 ** 18

def rectangle_costs(a, b):
    m = a + b
    res = [INF] * (m + 1)
    res[0] = 0

    for cols in range(a + 1):
        cost = cols * b
        points = cols

        res[points] = min(res[points], cost)

        cur_cost = cost
        for rows in range(1, b + 1):
            cur_cost += a - cols
            res[points + rows] = min(
                res[points + rows],
                cur_cost
            )

    return res

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        n, k = map(int, input().split())

        dp = [INF] * (k + 1)
        dp[0] = 0

        total_possible = 0

        rects = []
        for _ in range(n):
            a, b = map(int, input().split())
            rects.append((a, b))
            total_possible += a + b

        if total_possible < k:
            answers.append("-1")
            continue

        for a, b in rects:
            local = rectangle_costs(a, b)

            ndp = dp[:]

            for cur in range(k + 1):
                if dp[cur] == INF:
                    continue

                for gain in range(1, len(local)):
                    if local[gain] == INF:
                        continue

                    nxt = min(k, cur + gain)

                    ndp[nxt] = min(
                        ndp[nxt],
                        dp[cur] + local[gain]
                    )

            dp = ndp

        answers.append(str(dp[k]))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```ヘルパーさん`rectangle_costs`1 つの長方形内で達成可能なすべてのスコアの最小コストを計算します。 完了した列の数を列挙します。 これらの列が固定されると、完成したすべての行に必要なのは、`a - cols`交差セルはすでに色付けされているため、セルを追加します。 

この式が実装の重要な詳細です。 使用する`rows * a`完成した列内にあるセルを二重にカウントします。 

DP は、標準的な複数選択のナップザックです。 各長方形は、いくつかの可能なポイント ゲインのうちの 1 つのオプションに寄与します。 スコアの上限は`k`DP 配列がサイズを超えることはありません`101`。 

不可能チェック`total_possible < k`正確さを保つためには必要ありませんが、不必要な計算を避けることができます。

import sys, io

def run(inp: str) -> str:
    from math import inf

    data = io.StringIO(inp)
    input = data.readline

    INF = 10 ** 18

    def rectangle_costs(a, b):
        m = a + b
        res = [INF] * (m + 1)
        res[0] = 0

        for cols in range(a + 1):
            cost = cols * b
            res[cols] = min(res[cols], cost)

            cur = cost
            for rows in range(1, b + 1):
                cur += a - cols
                res[cols + rows] = min(
                    res[cols + rows],
                    cur
                )
        return res

    t = int(input())
    out = []

    for _ in range(t):
        n, k = map(int, input().split())

        rects = []
        total = 0

        for _ in range(n):
            a, b = map(int, input().split())
            rects.append((a, b))
            total += a + b

        if total < k:
            out.append("-1")
            continue

        dp = [INF] * (k + 1)
        dp[0] = 0

        for a, b in rects:
            local = rectangle_costs(a, b)
            ndp = dp[:]

            for i in range(k + 1):
                if dp[i] == INF:
                    continue

                for gain in range(1, len(local)):
                    j = min(k, i + gain)
                    ndp[j] = min(
                        ndp[j],
                        dp[i] + local[gain]
                    )

            dp = ndp

        out.append(str(dp[k]))

    return "\n".join(out)
