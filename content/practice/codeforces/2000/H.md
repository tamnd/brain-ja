 ## 解決策
 ## 問題の理解

 私たちは、最大約 200 万までの限定された宇宙から抽出された動的な整数のセットを維持しています。 要素は挿入および削除でき、変更のたびに、セット内の「穴」の構造について質問される場合があります。 

キークエリは最小の開始位置を要求します$d$区間全体が$[d, d + k - 1]$セットの要素が含まれていません。 言い換えれば、長さの左端のストレッチを探しています。$k$それは完全にセットの補完にあります。 

構造を再解釈する便利な方法は、各位置が埋められている (値がセット内にある) か空である (値がセットに入っていない) 1 から 2e6 までのインデックスが付けられた配列を想像することです。 挿入および削除操作では、個々の位置が反転します。 クエリでは最も早い長さが要求されます。$k$完全に空の位置で構成されるブロック。 

制約が非常に厳しいため、クエリごとに配列をスキャンするアプローチは不可能です。 クエリごとに 2e6 ポジションにわたる 1 回のスキャンで最大 2e5 のオペレーションを実行すると、最悪の場合約 4e11 のオペレーションが発生しますが、これは許容範囲をはるかに超えています。 テストケースごとのスキャンでも遅すぎます。 

もう 1 つの微妙な問題は、答えがセット内の値に直接依存するのではなく、存在しない値の連続実行に依存することです。 ナイーブ セットまたはバランス ツリーは、連続する空のセグメントではなくメンバーシップのみを追跡するため、構造を最初から再計算しないとクエリに効率的に答えることができません。 

セットが疎か密である場合、エッジ ケースが発生します。 セットが空の場合、すべてのクエリは 1 を返します。セットが時折のギャップを除いてほぼいっぱいである場合、答えは挿入と削除のマージによって異なります。 特に注意が必要なのは、長さのギャップがある場合です。$k$これは、削除後にのみ 2 つの小さなギャップが結合して有効な答えになることを意味します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 セットをハッシュ構造に維持し、クエリごとに次からスキャンします。$d = 1$上向き、すべての値が次の値であるかどうかを確認します。$[d, d+k-1]$は不在です。 これには以下の確認が必要です$k$スタートごとの順位、最悪の場合は最大 2e6 スタート、$O(n \cdot 2e6)$クエリごとの動作。 これは制約がかかるとすぐに崩壊します。 

より構造化されたビューは、視点を切り替えることで得られます。現在の要素を追跡する代わりに、空のセグメントを追跡します。 クエリは、少なくとも長さ 0 のセグメントが存在する最初の位置を求めています。$k$が始まります。 

これは、1 が存在することを意味し、0 が存在しないことを意味するバイナリ配列を維持し、ポイント フリップと長さのゼロランの左端の出現に対するクエリという 2 つの操作をサポートすることを示唆しています。$k$。 これは古典的なセグメント ツリー拡張問題です。 

各セグメント ツリー ノードには、間隔内の最長連続ゼロ セグメント、ゼロ プレフィックスの長さ、ゼロ サフィックスの長さの 3 つの値が格納されます。 これら 3 つは、間隔をマージし、境界を越える実行を検出するには十分です。 この情報を使用すると、単一ポイントを更新することと、ガイド付き降下を使用して最初の有効な開始位置を検索することができます。 

主な改善点は、間隔を明示的に列挙しないことです。 代わりに、セグメント ツリーはすべての連続した構造情報を圧縮するため、クエリは事前に計算された実行統計に対する対数時間検索になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 実行情報を含むセグメント ツリー |$O(\log 2e6)$更新/クエリごと |$O(2e6)$| 承認済み |

 ## アルゴリズムのチュートリアル

 範囲にわたってセグメント ツリーを構築します$[1, 2 \cdot 10^6 + 2]$、各ポジションは最初は空から始まります。 

各リーフは単一の整数の位置を表します。 値 1 は、その数値がセット内にあることを意味するため、空のセグメントにはゼロが寄与します。 値 0 は、それが存在せず、空のセグメントに 1 を与えることを意味します。 

### 1. 初期構造を構築する

 セットのすべての初期要素を存在するものとしてマークします (値 1)。 他のすべての位置は暗黙的にゼロになります。 これにより、空の間隔の正しい初期セグメンテーションが得られます。 

### 2. 各ノードに間隔統計を保存する

 すべてのセグメント ツリー ノードについて、セグメント内のゼロの最長連続ラン、ゼロの最長プレフィックス、および最長サフィックスの 3 つの量を維持します。 

長いゼロ セグメントは、左の子に完全に含まれるか、右の子に完全に含まれるか、左のサフィックスと右のプレフィックスを組み合わせて形成されるため、これらで十分です。 

### 3. 挿入および削除操作を処理する

 挿入の場合は、対応する位置を 1 に設定します。削除の場合は、0 に戻します。各更新は、のみ影響します。$O(\log n)$ツリー内のノードを削除し、ルートに戻るパス上に保存された値を再計算します。 

### 4. k-load クエリに答える

 有効な最小値を見つけるには$d$では、ルートからセグメント ツリーを下降します。 

ノードで、左側の子に少なくとも長さのゼロのセグメントが既に含まれているかどうかを確認します。$k$。 そうであれば、答えは完全に左側のサブツリーにあるため、左側に移動します。 

そうでない場合は、有効なセグメントが左右の子の境界を越えているかどうかを確認します。 これは、左の子のサフィックスと右の子のプレフィックスが少なくとも一致する場合に発生します。$k$。 その場合、答えは左の子の内部の境界位置から始まります。 

どちらの条件も当てはまらない場合、有効なセグメントは正しいサブツリーに存在する必要があるため、右に移動します。 

最小の開始位置となる葉に到達するまで続けます。 

### なぜ効果があるのか

 セグメント ツリーには、各間隔内のすべての可能な連続ゼロ セグメントに関する正確な情報が格納されます。 答えの候補は、完全に左半分に収まるか、完全に右半分に収まるか、中間点を横切るかのいずれかでなければなりません。 保存されたプレフィックス、サフィックス、およびベストランの値は 3 つのケースすべてを完全に特徴付けるため、降下中のすべての決定は正しい間隔構造によって強制されます。 可能なすべての長さがあるため、候補セグメントをスキップすることはできません。$k$ゼロブロックは、分割ごとにこれら 3 つの形式のいずれかで表されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 2_000_005

class SegTree:
    def __init__(self, n):
        self.n = n
        self.size = 4 * n
        self.pref = [0] * self.size
        self.suf = [0] * self.size
        self.best = [0] * self.size
        self.length = [0] * self.size
        self.val = [0] * n  # 0 = absent, 1 = present

        self._build(1, 1, n)

    def _build(self, v, l, r):
        self.length[v] = r - l + 1
        if l == r:
            self.pref[v] = self.suf[v] = self.best[v] = 1
            return
        m = (l + r) // 2
        self._build(v * 2, l, m)
        self._build(v * 2 + 1, m + 1, r)
        self._pull(v)

    def _pull(self, v):
        L, R = v * 2, v * 2 + 1
        self.pref[v] = self.pref[L]
        if self.pref[L] == self.length[L]:
            self.pref[v] += self.pref[R]

        self.suf[v] = self.suf[R]
        if self.suf[R] == self.length[R]:
            self.suf[v] += self.suf[L]

        self.best[v] = max(self.best[L], self.best[R], self.suf[L] + self.pref[R])

    def update(self, v, l, r, idx, val):
        if l == r:
            self.val[idx] = val
            self.pref[v] = self.suf[v] = self.best[v] = 1 - val
            return

        m = (l + r) // 2
        if idx <= m:
            self.update(v * 2, l, m, idx, val)
        else:
            self.update(v * 2 + 1, m + 1, r, idx, val)
        self._pull(v)

    def query(self, k):
        return self._query(1, 1, self.n, k)

    def _query(self, v, l, r, k):
        if l == r:
            return l

        m = (l + r) // 2
        L, R = v * 2, v * 2 + 1

        if self.best[L] >= k:
            return self._query(L, l, m, k)

        if self.suf[L] + self.pref[R] >= k:
            return m - self.suf[L] + 1

        return self._query(R, m + 1, r, k)

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    m = int(input())

    st = SegTree(MAXV)

    for x in arr:
        st.update(1, 1, MAXV, x, 1)

    out = []
    for _ in range(m):
        tmp = input().split()
        if tmp[0] == '+':
            st.update(1, 1, MAXV, int(tmp[1]), 1)
        elif tmp[0] == '-':
            st.update(1, 1, MAXV, int(tmp[1]), 0)
        else:
            k = int(tmp[1])
            out.append(str(st.query(k)))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```セグメント ツリーは座標範囲全体にわたって構築されるため、現在のセット外の空の位置は自然にゼロとして処理されます。 更新のたびに、単一の位置が存在するものと存在しないものとの間で反転され、マージ ロジックによってすべての実行統計の正確さが維持されます。 

クエリ プロシージャは決して線形にスキャンしません。 左側に有効な実行が既に含まれているかどうか、または実行が中間点を横切るかどうかに基づいてツリーを下降するだけで、対数時間を保証します。 

## 実用的な例

 単純な集合を考えてみましょう$[3, 4, 6]$小さな宇宙を越えて。 

お問い合わせの場合$k = 2$の場合、アルゴリズムは左端のセグメントを検査します。 間隔$[1,2]$は空であるため、すぐに修飾され、1 が返されます。これは、プレフィックス 0 のランがスキャンせずにセグメント ツリーにどのようにキャプチャされるかを示しています。 

ここで、最初の有効なセグメントが境界を越える場合を考えてみましょう。 

セットをこうしましょう$[2, 3, 7]$。 空の構造は次のようになります。$[1]$空の、$[2,3]$満たされた、$[4,5,6]$空の、$[7]$満たされた、$[8..]$空の。 

のために$k = 3$、最初の有効なブロックは$[4,5,6]$。 ルートのセグメント ツリーは、左側の子が完全に満足できないことを確認します。$k$ただし、left のサフィックスと right のプレフィックスを組み合わせると、正しい交差検出が行われ、クエリが直接 4 に誘導されます。 

これらのトレースは、純粋なサブツリーと境界を越えたケースの両方が列挙なしで処理されることを確認します。

 ## 特殊なケース

 すべてのノードがその全長に等しい最大ゼロセグメントを報告するため、完全に空の構造は正しく処理されます。 ルートはすでにすべてのクエリを満たしているため、クエリはすぐに 1 に解決されます。$k$。 

完全に充填された構造は逆の動作をします。 すべてのノードには長さゼロのゼロセグメントがあるため、プレフィックス、サフィックス、または中間セグメントが満たされることはありません。$k$となり、クエリは右端の境界まで正しく移動し、ドメインを越えた空の末尾が暗黙的に答えを提供します。 

削除によって 1 つの削除された要素によって分離された 2 つの隣接するギャップが作成される場合、交差ルールによってサフィックスとプレフィックスが正しくマージされ、配列を再スキャンすることなく、新しく形成されたセグメントが即座に検出されることが保証されます。
