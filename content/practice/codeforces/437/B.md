 ## 解決策
 ## 問題の理解

 各要素に適用される特別な関数の合計が目標値と等しくなるように、1 から指定された上限までの個別の整数のセットを再構築するように求められます。 特別な機能、`lowbit(x)`、設定された最小ビットを抽出します。`x`バイナリ表現で。 具体的には、これは任意の整数に対して`x`、`lowbit(x)`2 を割る最大の累乗です`x`。 たとえば、`x = 12`（バイナリ`1100`)、右から最初の 1 は 3 番目の位置にあるため、`lowbit(12) = 4`。 

入力により 2 つの数値が得られます。`sum`(セット内のすべての下位ビットの目標合計) および`limit`(要素が取り得る最大値)。 出力はセットである必要があります`S`1 から までの整数`limit`の合計が`lowbit`すべての要素が等しい`sum`。 そのようなセットが存在しない場合は、-1 を出力します。 

制約は次のことを意味します`limit`最大 100,000 まで可能です。 以来`n`(セット内の要素の数) は最大 100,000 にもなる可能性がありますが、サブセットの数は指数関数的に増加するため、すべてのサブセットを明示的にチェックするソリューションは実行不可能です。 せいぜい線形か、低い倍数で反復するアプローチが必要です。`limit`。 エッジケースには、次のような状況が含まれます。`sum`可能な最小値より小さい`lowbit`(1) の合計以上`lowbit(i)`みんなのために`i`1から`limit`、解決が不可能になります。 

単純な間違いは、要素を 1 から 1 までの順序で選択することです。`limit`という事実を考慮せずに合計に達するまで`lowbit(x)`複数回繰り返すことができます。 たとえば、次の場合`sum = 3`そして`limit = 2`、盲目的に 1 と 2 を取得すると、低ビットの合計が得られます。`1 + 2 = 3`これは機能しますが、要素は個別である必要があるため、1 を 2 回取ると無効になります。 

## アプローチ

 ブルートフォースアプローチは、1 から 2 までの数値のすべてのサブセットを生成することです。`limit`そして彼らの`lowbit`和。 これは原理的には正しいですが、`limit`10^5 までは O(2^limit) の操作が必要ですが、これは実行不可能です。 

重要な洞察は次のとおりです`lowbit(x)`は常に 2 のべき乗であり、各整数は合計の 2 のべき乗 1 に正確に寄与します。 これにより、より大きな数値を考慮するという貪欲な戦略を使用できるようになります。`lowbit`まず、1 回の選択でより多くのターゲット合計を消費し、必要な要素の数が減るためです。 数値を降順に並べ替える`lowbit`選択の数を最小限に抑え、目標合計に達したら早期に停止できるようにします。 

要素を選択したら、その要素を差し引きます。`lowbit`残りの金額から。 いずれかの時点で残りの合計がゼロに達すると、セットは完了します。 ゼロに到達することなくすべての数値の反復を終了した場合、有効なセットは存在しません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^限界) | O(限界) | 遅すぎる |
 | ロービットを減らして貪欲に | O(制限 * log(制限)) | O(限界) | 承認済み |

 O(limit log limit) では、ソートが時間の複雑さを支配します。 プライオリティ キューを使用する必要はありません。 簡単な並べ替えで十分です。 

## アルゴリズムのチュートリアル

 1. 1 から 1 までの整数のリストを作成します。`limit`。 各整数について`x`、それを計算します`lowbit(x)`を使用して`x & -x`。 
2. この整数のリストを、その整数の値に従って降順に並べ替えます。`lowbit(x)`。 これにより、各選択が目標合計の達成に可能な限り貢献することが保証されます。 
3. 空のリストを初期化する`S`選択した整数を保持します。 初期化もする`remaining_sum = sum`。 
4. ソートされたリストを繰り返し処理します。 各整数について`x`、どうかを確認してください`lowbit(x)`以下である`remaining_sum`。 

- 「はい」の場合は追加します`x`に`S`そして引きます`lowbit(x)`から`remaining_sum`。 
- もし`remaining_sum`ゼロになるとループが終了します。 
5. ループ後、次のことを確認します。`remaining_sum`まだポジティブです。 そうである場合は、有効なセットが存在しないため、-1 を出力します。 
6. それ以外の場合は、サイズを出力します。`S`要素は任意の順序で表示されます。 

なぜ機能するのか: 各整数は正確に寄与します`lowbit(x)`合計額に。 貪欲に大きいものを選ぶことで`lowbit`利用可能な場合は、できるだけ少ない要素を使用して目標合計に到達することを保証します。 だって全部`lowbit(x)`は 2 のべき乗であり、残りの合計からそれらを減算すると、二重にカウントされることがなく、選択された下位ビットの合計がターゲットと正確に等しいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def lowbit(x):
    return x & -x

def main():
    sum_target, limit = map(int, input().split())
    nums = [(i, lowbit(i)) for i in range(1, limit + 1)]
    nums.sort(key=lambda t: -t[1])  # sort descending by lowbit

    S = []
    remaining = sum_target

    for num, lb in nums:
        if lb <= remaining:
            S.append(num)
            remaining -= lb
        if remaining == 0:
            break

    if remaining != 0:
        print(-1)
    else:
        print(len(S))
        print(' '.join(map(str, S)))

if __name__ == "__main__":
    main()
```計算します`lowbit`と`x & -x`設定された最下位ビットを効率的に抽出します。 降順に並べ替えると、貢献度の大きいものが最初に優先されます。 ループは次のことを注意深くチェックします。`remaining`をゼロにして早期に停止し、不要な反復を防ぎます。 最終チェックでは、目標合計が正確に満たされた場合にのみソリューションを出力することが保証されます。

 ## 特殊なケース

 入力用`sum=1, limit=1`、アルゴリズムは次のように計算します。`lowbit(1)=1`、それを選択し、正確に合計に達します。 のために`sum=100001, limit=100000`、すべての合計`lowbit(i)`は 100001 未満であるため、アルゴリズムは次のように終了します。`remaining != 0`そして -1 を出力します。 すべての場合において、アルゴリズムは、要素が個別であり、それぞれがその要素に正確に寄与するという制約を正しく尊重します。`lowbit`。
