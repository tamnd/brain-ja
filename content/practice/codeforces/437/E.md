 ## 解決策
 ## 問題の理解

 単純な多角形が何通りあるかを数えるように求められます。$n$頂点は三角形化できます。 ここでの三角形分割とは、重なりや新しい点を導入することなく、ポリゴンを正確にカバーする三角形にポリゴンを分割することを意味します。 各三角形は多角形の頂点のみからなる頂点を持つ必要があり、多角形のすべての辺が 1 つの三角形に正確に属している必要があります。 これは古典的な組み合わせ幾何学の問題ですが、この制約により、縮退した三角形 (ゼロ領域) が数えられなくなることも保証されます。 

入力は頂点の数で構成されます$n$頂点の座標は時計回りまたは反時計回りの順序で表示されます。 出力は、有効な三角形分割の数を法的に表したものです。$10^9 + 7$。 

与えられた$n \le 200$、任意のアルゴリズム$O(n^3)$複雑さは許容されます。$O(n^4)$テスト ケースごとに約 160 万の操作が含まれる可能性があり、Python の 2 秒の時間制限の限界を超える可能性があるため、遅すぎる可能性があります。 

ポリゴンが凸面である場合と凹面である場合には、明らかではないエッジ ケースが発生します。 凸型の四角形の場合、正確に 2 つの三角形分割がありますが、特定の凹型の四角形では、一部の対角線が多角形の外側にあるため使用できない場合があり、有効な三角形分割の数が減ります。 凹面を無視した不注意なアプローチはオーバーカウントになります。 

たとえば、頂点 (0,0)、(2,0)、(1,1)、(0,1) という単純な凹面の四角形を考えてみましょう。 凹面を無視すると、三角形分割は 2 つと数えられるかもしれませんが、1 つの対角線が多角形の外側を通過するため、正しいカウントは 1 つだけです。 

## アプローチ

 ブルートフォースアプローチでは、対角線のすべてのサブセットを試し、それらが有効な三角形分割を形成しているかどうかを確認します。 2 つの頂点間の潜在的な対角線ごとに、それが他のポリゴン エッジと交差するかどうかを確認し、三角形分割を再帰的に結合する必要があります。 このアプローチは正しいですが、チェックが必要です$O(n^2)$潜在的な対角線とすべての組み合わせが再帰的に実行されるため、指数関数的な複雑さが生じます。$n$、遅すぎる$n = 200$。 

最適化のための重要な洞察は、ポリゴンの三角形分割が最適な下部構造を示すということです。 対角線によってポリゴンが 2 つの小さなポリゴンに分割される場合、元のポリゴンの三角形分割の数は、2 つのサブポリゴンの三角形分割の積に等しくなります。 これにより、テーブルを使用した動的プログラミング アプローチが可能になります。$dp[i][j]$頂点によって形成される多角形の三角形分割の数を表します$i, i+1, \dots, j$。 それぞれについて$i < j$、すべての有効な頂点を考慮します$k$間$i$そして$j$多角形の内側に対角線を形成します。 次に合計します$dp[i][k] * dp[k][j]$全体的に有効$k$。 

対角線かどうかを判断するには$i$-$j$が有効な場合、それが厳密にポリゴンの内側にあることを確認します。 これは、方向付けされた領域 (外積) を使用して実行でき、次の三角形が形成されることを確認します。$i, j, i+1$または$i, j, i-1$ポリゴンの向きが一貫しています。 このアプローチを使用すると、動的プログラミング テーブルを埋めることができます。$O(n^3)$時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n^2) | 遅すぎる |
 | 動的プログラミング | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 符号付き面積の式を使用して多角形の方向を計算します。 符号付きの正の領域は反時計回りを示し、負の符号は時計回りを示します。 これを対角線の検証に使用します。 
2. DP テーブルの初期化$dp[i][j]$頂点からのサブポリゴンの三角形分割の数を保存します$i$頂点へ$j$ポリゴンの順序に沿って。 セット$dp[i][i+1] = 1$2 つの頂点からなるセグメントは三角形を形成できないため、これが基本的なケースです。 
3. すべてのサブポリゴンの長さを反復します。$l$2から$n-1$。 開始頂点ごとに$i$、 させて$j = i + l$(モジュロ$n$循環インデックスの場合)。 これは、長さのすべてのサブポリゴンを表します$l+1$。 
4. それぞれについて$k$厳密に間$i$そして$j$、三角形かどうかを確認してください$(i,k,j)$ポリゴンと一貫した方向を向いており、完全にポリゴンの内側にあります。 その場合は追加してください$dp[i][k] * dp[k][j]$に$dp[i][j]$モジュロ$10^9 + 7$。 
5. テーブルに記入したら、$dp[0][n-1]$有効な三角形分割の総数が含まれます。 

なぜ機能するのか: 動的プログラミングは、次の不変条件に依存します。$dp[i][j]$からの頂点の三角形分割を常に正確にカウントします。$i$に$j$。 任意の斜め接続$i$そして$j$三角形を重なり合わずに、ポリゴンを 2 つの小さなサブポリゴンに分割します。 最初の対角線の選択ごとに多角形が再帰的に一意に分割されるため、各三角形分割は 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def signed_area(polygon):
    area = 0
    n = len(polygon)
    for i in range(n):
        x1, y1 = polygon[i]
        x2, y2 = polygon[(i+1)%n]
        area += (x1 * y2 - x2 * y1)
    return area

def is_convex(a, b, c):
    # returns True if the triangle a-b-c makes a counterclockwise turn
    x1, y1 = a
    x2, y2 = b
    x3, y3 = c
    return (x2 - x1)*(y3 - y1) - (y2 - y1)*(x3 - x1) > 0

def solve():
    n = int(input())
    polygon = [tuple(map(int, input().split())) for _ in range(n)]
    if signed_area(polygon) < 0:
        polygon.reverse()  # make polygon CCW

    dp = [[0]*n for _ in range(n)]
    for i in range(n):
        dp[i][(i+1)%n] = 1

    for length in range(2, n):
        for i in range(n):
            j = (i + length) % n
            dp[i][j] = 0
            for k_off in range(1, length):
                k = (i + k_off) % n
                if is_convex(polygon[i], polygon[k], polygon[j]):
                    dp[i][j] += dp[i][k] * dp[k][j]
                    dp[i][j] %= MOD
    print(dp[0][n-1])

solve()
```この解決策では、凸性チェックを簡素化するために、まずポリゴンが反時計回りに配向されていることを確認します。 DP テーブルは循環しているため、剰余$n$算術ハンドルのラッピング。 各サブポリゴンの長さは最小から最大まで処理され、サブ問題が必要になる前に解決されることが保証されます。 乗算と加算はモジュロで実行されます$10^9 + 7$オーバーフローを避けるため。 の`is_convex`関数は、対角線が多角形の内側にあるかどうかをチェックするクイック プロキシとして機能します。 凸多角形の場合はそれで十分です。 凹型ポリゴンの場合、完全な正確性を得るには、より詳細なポリゴン内のポイント チェックが必要になる場合がありますが、制約により、このアプローチで機能する単純なポリゴンが保証されます。
