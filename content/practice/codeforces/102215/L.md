 ## 解決策
 ## 問題の理解

 2 つの円盤があり、それぞれが中心と正の半径で表されます。 それらの円周は正確に 2 点で交差するため、どちらの円盤にももう一方の円盤は含まれず、それらの交差点は非縮退レンズ形領域になります。 

このレンズ内に完全に収まる可能な最大の円を見つける必要があります。 出力は、(10^{-9}) の絶対誤差または相対誤差を満たすのに十分な精度を持つ、その円の中心と半径です。 

座標と半径の大きさは最大 (1000) であるため、関連する距離はすべて通常の浮動小数点の範囲内に収まります。 また、入力サイズも大きくありません。問題には円が 2 つだけ含まれています。 したがって、(O(1)) 幾何学的解法では 2 秒の制限は問題になりません。 数百回の反復を伴う反復数値法でも十分高速ですが、ジオメトリにより反復を完全に回避できます。 

最初の微妙なケースは、円の半径が等しい場合です。 例えば、```
0 0 5
6 0 5
```答えは```
3 0 2
```不用意に実装すると、最適な中心が元の中心の 1 つであると想定される可能性がありますが、正しい中心はそれらの中間にあります。 より一般的には、対称性により、答えは 2 つの円の中心を結ぶ線上に配置されますが、必ずしもその中点に配置されるわけではありません。 

もう 1 つのケースは、半径が異なる場合です。```
0 0 5
7 0 3
```ここで、(2 < 7 < 8) により円は交差します。 最適な中心は遠くにあります

 [
 \frac{7+5-3}{2}=4.5
 】

 最初の中心からの半径は次のようになります。 

[
 \frac{5+3-7}{2}=0.5。 
】

 よくある間違いは、半径に関係なく中心の中点を使用することです。 これでは間違った答えが得られます。なぜなら、より大きな円はより小さな円に向かって最適な中心を収容できるからです。 

最後のエッジ ケースは、境界が接線に非常に近い位置で交差する円に関するものです。 例えば、```
0 0 1
1.999999 0 1
```答えの半径は非常に小さく、約 (5\times10^{-7}) です。 整数演算、不十分な精度、またはほぼ等しい量の減算を含む式を不用意に使用する実装では、精度が失われる可能性があります。 中心距離を使用する直接式は、Python の倍精度で必要な誤差を十分に安定させます。 

## アプローチ

 単純な幾何学的なアプローチでは、細かいグリッド上の可能な中心位置を検索できます。 すべての候補点について、そこに配置できる半径、つまり 2 つの円の境界までの距離の小さい方を計算します。 おおよそ (2000) の座標範囲で (10^{-9}) の位置精度に達するには、均一なグリッドには次のオーダーが必要です。 

[
 2000^2 / 10^{-18} = 4\cdot10^{24}
 】

 候補点。 1 点につき 1 回の定数時間計算さえ絶望的です。 

より合理的な数値的アプローチでは、検索を 1 次元に削減し、三項検索を使用します。 レンズの対称性は、最適な中心が 2 つの元の中心を結ぶ線上にあることを意味します。 その線をパラメータ化し、実現可能な半径を数値的に最大化することができます。 数百回の反復ですでに十分であるため、このアプローチは実際には十分高速ですが、不必要であり、正確なジオメトリが回避する収束と精度の詳細が導入されます。 

重要な観察は、中心を結ぶ線分上の点では、2 番目の中心までの距離が減少するのと同じように、最初の中心までの距離が増加するということです。 中心が (C_1,C_2)、それらの距離が (d)、候補中心 (P) が (C_1) からの距離 (t) にあるとします。 次に(C_2)から(d-t)です。 

(P) を中心とする円は、最初の円盤の内側に最大半径で収まります。 

[
 r_1-t、
 】

 そしてそれは最大半径の 2 番目のディスクの内側に収まります

 [
 r_2-(d-t)。 
】

 したがって、(P) での実現可能な最大半径は次のようになります。 

[
 f(t)=\min(r_1-t,\ r_2-d+t)。 
】

 最初の式は (t) とともに減少しますが、2 番目の式は (t) とともに増加します。 それらの最小値と最大値は、それらが等しい場合に正確に発生します。 解決中

 [
 r_1-t=r_2-d+t
 】

 与える

 [
 t=\frac{d+r_1-r_2}{2}。 
】

 この値を代入すると、

 [
 r=\frac{r_1+r_2-d}{2}。 
】

 この問題では、円周に正確に 2 つの共通点があることが保証されており、次のようになります。 

[
 |r_1-r_2|<d<r_1+r_2。 
】

 したがって、計算された (t) は厳密に (0) と (d) の間にあり、計算された半径は厳密に正になります。 次に、2 つの中心間の線上の対応する点に答えを配置できます。 

ブルートフォース検索は、候補中心の実現可能な半径を直接評価するため機能しますが、2 次元の連続領域を探索する作業のほとんどすべてが無駄になります。 最適な中心は中心間の軸上になければならないという観察により、問題は 1 次元に縮小され、2 つの制限半径が一次関数であるという事実により、その 1 次元の最適化が 1 つの方程式を解くことに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(1/\varepsilon^2)) グリッド サンプル | (O(1)) | 遅すぎる |
 | 数値三項検索 | (お(い)) | (O(1)) | 受け入れられるが不要 |
 | 幾何学式 | (O(1)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 中心 (C_1=(x_1,y_1))、(C_2=(x_2,y_2))、および半径 (r_1,r_2) を読み取ります。 最初に必要な幾何学的量は 2 つの中心間の距離だけです。 
2. コンピューティング

 [
 d=\sqrt{(x_2-x_1)^2+(y_2-y_1)^2}。 
】

 円は 2 点 (d>0) で交差するため、(C_1) から (C_2) への方向は明確に定義されます。 

1. 目的の中心が (C_1) からどのくらい離れているかを決定します。 

[
 t=\frac{d+r_1-r_2}{2}。 
】

 これは、利用可能な 2 つの境界距離のバランスを取ることで実現されます。 答えが (C_1) に近い場合、最初の円はより大きな半径を許可し、2 番目の円は限界円になります。 それが(C_2)にさらに近づくと、状況は逆転します。 最大値はまさにバランスポイントにあります。 

1. 距離 (t) を座標に変換します。 (C_1) から (C_2) までの単位ベクトルは次のようになります。

[
 \left(\frac{x_2-x_1}{d},\frac{y_2-y_1}{d}\right)。 
】

 したがって、アンサーセンターは

 [
 x=x_1+\frac{x_2-x_1}{d}t、
 \qquad
 y=y_1+\frac{y_2-y_1}{d}t.
 】

 1. 次のいずれかの限界円を使用して半径を計算します。 

[
 r=r_1-t。 
】

 (t) の値を代入すると、次のように書くこともできます。 

[
 r=\frac{r_1+r_2-d}{2}。 
】

 1. 中心と半径を小数点以下の桁数で出力します。 パイソンの`float`は 64 ビット IEEE-754 double であり、必要な (10^{-9}) 誤差よりも大幅に高い精度が得られます。 

### なぜ効果があるのか

 レンズ内の点 (P) を中心とする円の半径は、(P) から元の円周までの距離を超えることはできません。 最適な中心は、元の中心を結ぶ線上で選択できます。その線を横切る実行可能な円を反射すると、両方の元のディスクが保存され、レンズがその線に関して対称であるためです。 この軸では、(r_1-t) と (r_2-d+t) の 2 つの使用可能な半径があります。 中心が (C_2) に向かうにつれて一方は減少し、他方は増加します。 それらの最小値は、それらの交差点で正確に最大化されます。 アルゴリズムはその交点を計算し、そこに中心を配置するため、他の点はより大きな円を受け入れることができません。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    x1, y1, r1 = map(int, input().split())
    x2, y2, r2 = map(int, input().split())

    dx = x2 - x1
    dy = y2 - y1

    d = math.hypot(dx, dy)

    t = (d + r1 - r2) / 2.0

    x = x1 + dx * t / d
    y = y1 + dy * t / d

    r = (r1 + r2 - d) / 2.0

    print(f"{x:.15f} {y:.15f} {r:.15f}")

if __name__ == "__main__":
    solve()
```最初の部分は 2 つの円を読み取り、計算します。`dx`そして`dy`、最初の中心から 2 番目の中心までの変位。`math.hypot(dx, dy)`明示的に平方根を書く必要なく中心距離を計算します。 

変数`t`最初の中心から最適な中心までの距離です。 ２つの交点についての保証とは、`t`は厳密に正であり、厳密に以下より小さい`d`で割ります。`d`安全です。 

座標は、最初の中心から 2 番目の中心の方向に正確に移動することによって取得されます。`t`。 計算を次のように書くと、`dx * t / d`そして`dy * t / d`単位ベクトルタプルを個別に構築することを回避します。 

半径は対称式を使用します`(r1 + r2 - d) / 2`。 直接計算する方が計算より簡単です`r1 - t`、不必要な余分な減算を回避します。 

整数には任意の精度があるため、Python では整数オーバーフローの懸念はありません。 唯一の浮動小数点演算には、大きさが最大でも数千の値が含まれるため、倍精度はそれらを快適に処理します。 

小数点以下 15 桁を出力すると、必要以上の精度が得られます。 審査員はフォーマットではなく数値を比較します。 

## 実用的な例

 ### サンプル 1

 入力は```
0 0 5
6 0 5
```主な変数は次のように変化します。 

| 変数 | 値 |
 | --- | --- |
 | (dx) | (6) |
 | (ダイ) | (0) |

 2 つの元の円から得られる半径は中点で等しく、両方とも (5-3=2) です。 どちらかの方向に移動すると、どちらかが小さくなるため、中点が最適です。 

### サンプル 2

 入力は```
-12 34 56
78 -90 123
```変位と導出された値はおよそ次のとおりです。 

| 変数 | 値 |
 | --- | --- |
 | (dx) | (90) |

## テストケース

 浮動小数点出力の場合、多くの異なる 10 進表現で同じ答えが記述される可能性があるため、完全な出力文字列を比較することは不適切です。 以下のテスト ヘルパーは 3 つの数値を解析し、厳密な絶対許容誤差と相対許容誤差を使用してそれらをチェックします。```python
import sys
import io
import math

def solve():
    input = sys.stdin.readline

    x1, y1, r1 = map(int, input().split())
    x2, y2, r2 = map(int, input().split())

    dx = x2 - x1
    dy = y2 - y1

    d = math.hypot(dx, dy)

    t = (d + r1 - r2) / 2.0

    x = x1 + dx * t / d
    y = y1 + dy * t / d

    r = (r1 + r2 - d) / 2.0

    print(f"{x:.15f} {y:.15f} {r:.15f}")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def assert_answer(inp: str, expected, message: str):
    out = run(inp).split()
    got = list(map(float, out))

    assert len(got) == 3, message

    for a, b in zip(got, expected):
        assert math.isclose(a, b, rel_tol=1e-9, abs_tol=1e-9), (
            f"{message}: got {got}, expected {expected}"
        )

# Provided sample 1
assert_answer(
    "0 0 5\n6 0 5\n",
    (3.0, 0.0, 2.0),
    "sample 1"
)

# Provided sample 2
assert_answer(
    "-12 34 56\n78 -90 123\n",
    (13.322257821855908, -0.888444110112585, 12.890601098820779),
    "sample 2"
)

# Minimum radii, equal circles, center distance 1
assert_answer(
    "0 0 1\n1 0 1\n",
    (0.5, 0.0, 0.5),
    "minimum-size circles"
)

# Equal values and diagonal center displacement
# d = sqrt(2), so t = sqrt(2)/2 and the answer is (0.5, 0.5).
assert_answer(
    "0 0 1\n1 1 1\n",
    (0.5, 0.5, (2.0 - math.sqrt(2.0)) / 2.0),
    "equal circles on a diagonal"
)

# Very close to external tangency
assert_answer(
    "0 0 1\n1.999999 0 1\n",
    (0.9999995, 0.0, 0.0000005),
    "near-tangent circles"
)

# Unequal radii, catches midpoint assumptions
assert_answer(
    "0 0 5\n7 0 3\n",
    (4.5, 0.0, 0.5),
    "unequal radii"
)
```| テスト入力 | 期待される出力 | 検証内容 |

 |`0 0 1`そして`1 0 1`|`(0.5, 0, 0.5)`| 最小半径と対称の場合 |
 |`0 0 1`そして`1 1 1`|`(0.5, 0.5, (2-sqrt(2))/2)`| 対角方向と距離の正規化 |
 |`0 0 1`そして`1.999999 0 1`|`(0.9999995, 0, 0.0000005)`| 接線付近の精度 |
 |`0 0 5`そして`7 0 3`|`(4.5, 0, 0.5)`| 不等な半径と非中点最適 |

 ## 特殊なケース

 等半径の場合```
0 0 1
1 0 1
```(d=1) があるので、

 [
 t=\frac{1+1-1}{2}=0.5
 】

 そして

 [
 r=\frac{1+1-1}{2}=0.5。 
】

 中心は`(0.5, 0)`。 ここでは中点ベースの実装がたまたま機能しますが、式はなぜそれが機能するのかを説明しており、不等半径にも一般化します。 

斜めのケース```
0 0 1
1 1 1
```(d=\sqrt2) があります。 式は次のようになります

 [
 t=\frac{\sqrt2}{2}。 
】

 最初の中心から 2 番目の中心への単位方向は、

 [
 \left(\frac1{\sqrt2},\frac1{\sqrt2}\right),
 】

 したがって、(t) を掛けると、`(0.5, 0.5)`。 これにより、誤って使用する実装が捕捉されます。`dx`そして`dy`あたかも中心距離が常に水平であるかのように直接。 

ほぼ接線の場合```
0 0 1
1.999999 0 1
```持っています

 [
 d=1.999999
 】

 したがって

 [
 r=\frac{2-1.999999}{2}=0.0000005。 
】

 最適な中心は`(0.9999995, 0)`。 半径は正ですが非常に小さく、実装が十分な浮動小数点精度を保持しているかどうかをテストします。 

最後に、半径が等しくない場合```
0 0 5
7 0 3
```与える

 [
 t=\frac{7+5-3}{2}=4.5
 】

 そして

 [
 r=\frac{5+3-7}{2}=0.5。 
】

 中心は`(4.5, 0)`、 ない`(3.5, 0)`。 これは、対称性により常に答えが 2 つの元の中心の中点にあるという一般的だが誤った仮定に対する最も有用なテストです。
