 ## 解決策
 ## 問題の理解

 2 つの円があり、それぞれが中心と半径で表されます。 それらの円周は正確に 2 点で交差するため、どちらの円にももう一方の円は含まれず、2 つの円盤は適切なレンズ形状の領域で重なり合います。 重なり合う部分の内側に完全に収まる最大の円が必要で、その中心と半径を印刷する必要があります。 入力範囲と必要な精度は、元の問題ステートメントで指定されているものです。 

中心を (O_1=(x_1,y_1)) と (O_2=(x_2,y_2)) とし、半径を (r_1) と (r_2) とします。 しましょう

 [
 d=|O_1O_2|
 】

 中心間の距離になります。 ちょうど 2 つの交点があると、厳密な不等式が得られます。 

[
 |r_1-r_2|<d<r_1+r_2。 
】

 上限は正のオーバーラップを保証しますが、下限は一方のディスクがもう一方のディスクの中に完全に収まることを防ぎます。 これらの厳密な不等式は、最終半径が正であり、2 つの中心が区別されることを保証するため、特に役立ちます。 

座標境界は ([-1000,1000]) のみであるため、ここでは組み合わせ入力サイズはありません。 課題は実行時間ではなく、幾何学的精度です。 一定数の浮動​​小数点演算を実行するソリューションは、2 秒および 256 MB の制限内に容易に収まり、数値検索や高密度の列挙は不要です。 

円の半径が等しいが水平線の中心にない場合、不注意に実装すると失敗する可能性があります。 例えば、```
0 0 5
3 4 5
```は (d=5) なので、答えは ((1.5,2)) を中心とする半径 (2.5) の円になります。 (x) 座標のみを変更する解決策、または中心が常に (x) 軸上にあると想定する解決策では、間違った中心が生成されます。 

不等な半径も間違いのよくある原因です。 考慮する```
0 0 5
6 0 9
```ここでは (d=6)、答えの中心は ((1,0))、半径は (4) です。 この中心は、元の 2 つの中心の中点ではありません。 中点をやみくもに使用すると、小さな円の片側にまだ未使用のスペースがあるにもかかわらず、半径 (3) が得られます。 

ほぼ接線の場合は数値的にも重要です。 例えば、```
-1000 0 1000
999 0 1000
```は (d=1999) なので、答えは半径 (0.5) と中心 ((-0.5,0)) になります。 入力値が大きくても必要な半径は小さいため、計算は浮動小数点で実行し、十分な桁数で出力する必要があります。 

## アプローチ

 文字通りの総当り的な方法では、中心の可能な位置を試し、両方のディスクの内側に残る最大の円を維持します。 候補中心 (P) の場合、最初の円で許容される最大半径は (r_1-|PO_1|) であり、2 番目の円で許容される最大半径は (r_2-|PO_2|) です。 したがって、候補半径は最小値になります。 

問題は、中心が連続点であるため、ブルート フォースには離散化が必要であるということです。 可能な座標範囲 ([-2000,2000]) にわたって (10^{-9}) の間隔でグリッド上のすべての座標を検査しようとすると、各軸に沿って (4\cdot10^{12}) 個の位置が存在することになります。 

[
 (4\cdot10^{12})^2=1.6\cdot10^{25}
 】

 候補センター。 これは 2 秒としては遅すぎるだけでなく、要求された精度を保証するには扱いにくい方法でもあります。 

より洗練された数値検索を使用すると、作業を大幅に削減できる可能性がありますが、ジオメトリにより正確な定数時間の解が得られます。 ブルートフォース手法は、候補中心の妥当性を直接チェックできるため機能します。 重要な観察は、最適なセンターには 2 次元検索がまったく必要ないということです。 

レンズ内の任意の中心候補 (P) を取得します。 (P) を直線 (O_1O_2) に投影し、(Q) を取得します。 この投影では (O_1) または (O_2) までの距離を増やすことはできません。 その結果、

 [
 r_1-|QO_1|\ge r_1-|PO_1|
 】

 そして

 [
 r_2-|QO_2|\ge r_2-|PO_2|。 
】

 したがって、元の 2 つの中心を結ぶ線上に中心を移動しても、可能な内接半径は決して小さくなりません。 最適化全体を 1 つの次元に制限することができます。 

次に、候補中心 (P) を (O_1) と (O_2) の間に配置します。 (t=|O_1P|) の場合、(|PO_2|=d-t)。 2 つの円により半径が許容されます

 [
 r_1-t
 】

 そして

 [
 r_2-(d-t)。 
】

 最大値または最小値は、これら 2 つの量が等しいときに正確に発生します。 それ以外の場合、どちらかが小さい場合は、(P) を対応する円に向かってわずかに移動し、小さい方の量を増やすことができます。 

解決中

 [
 r_1-t=r_2-d+t
 】

 与える

 [
 t=\frac{d+r_1-r_2}{2}。 
】

 これをいずれかの半径式に代入すると、次のようになります。 

[
 R=\frac{r_1+r_2-d}{2}。 
】

 (t) がわかれば、中心は単に (O_1) から (O_2) の方向に距離 (t) の点になります。

| 最適 | (O(1)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの円の中心とその半径を読み取ります。 コンピューティング

 [
 dx=x_2-x_1,\qquad dy=y_2-y_1
 】

 そして

 [
 d=\sqrt{dx^2+dy^2}。 
】

 2 つの交点が保証されるということは (d>0) を意味するため、(d) による除算は安全です。 
2. 最大円の半径を次のように計算します。 

[
 R=\frac{r_1+r_2-d}{2}。 
】

 これは、新しい中心から 2 つの元の円周までの距離を同じ半径にすると得られます。 
3. (O_1) から新しい中心までの距離を計算します。 

[
 t=\frac{d+r_1-r_2}{2}。 
】

 これは、両方の元の円が正確に (R) 単位の半径方向クリアランスを残すセグメント (O_1O_2) 上の固有の点です。 
4. その距離を座標変位に変換します。 (O_1) から (O_2) に向かう単位ベクトルは次のようになります。 

[
 \left(\frac{dx}{d},\frac{dy}{d}\right)。 
】

 したがって、新しいセンターは、

 [
 x=x_1+\frac{dx}{d}t、
 \qquad
 y=y_1+\frac{dy}{d}t。 
】
 5. 桁数が多い (x)、(y)、および (R) を出力します。 小数点以下 15 桁では、必要な精度 (10^{-9}) よりも大幅に精度が高くなります。

重要な不変条件は、選択した中心が (O_1O_2) 上にあり、両方の円の境界からのクリアランスがまったく同じであることです。 他の場所を中心とする有効な円は、可能な半径を減らさずにこの線上に投影できます。 線に沿って、中心が (O_1) から遠ざかるにつれて、最初の円の利用可能な半径は減少しますが、2 番目の円の利用可能な半径は増加します。 それらの最小値は、それらの交差点で正確に最大化されます。 したがって、計算された円は実現可能かつ最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x1, y1, r1 = map(int, input().split())
    x2, y2, r2 = map(int, input().split())

    dx = x2 - x1
    dy = y2 - y1

    d = (dx * dx + dy * dy) ** 0.5

    radius = (r1 + r2 - d) / 2.0
    dist_from_first = (d + r1 - r2) / 2.0

    x = x1 + dx * dist_from_first / d
    y = y1 + dy * dist_from_first / d

    print(f"{x:.15f} {y:.15f} {radius:.15f}")

if __name__ == "__main__":
    solve()
```最初の 2 行は、`solve`2 つの円を指定どおりに正確に読んでください。 すべての入力値は整数なので、`dx * dx + dy * dy`平方根を求める前にも正確に計算されます。 

値`d`は元の中心間の距離です。 円周にはちょうど 2 つの共通点があるため、中心は一致できません。`d`厳密にポジティブです。 人為的なイプシロンチェックや一致中心の特別なケースは必要ありません。 

表現`(r1 + r2 - d) / 2`は最終的な半径です。 厳密な交差条件により、分子が正であることが保証されます。 

変数`dist_from_first`最初の中心から解答中心までの距離です。 正規化ベクトルの乗算`(dx / d, dy / d)`この距離だけ、元の中心間の線に沿った正しい位置に答えが配置されます。 

Python では整数オーバーフローは発生しません。また、固定幅言語であっても、2 乗座標の差は 64 ビット整数の制限と比較するとごくわずかです。 答えが非合理的になる可能性があるため、最終的な計算では浮動小数点が使用されます。

## テストケース

 以下のアサーションは、フォーマットされた文字列を比較するのではなく、浮動小数点値を許容値と比較します。 これは実際の判定条件を反映しており、多くの異なる 10 進表現が正しい可能性があります。```python
import sys
import io
import math

def solve():
    input = sys.stdin.readline

    x1, y1, r1 = map(int, input().split())
    x2, y2, r2 = map(int, input().split())

    dx = x2 - x1
    dy = y2 - y1
    d = (dx * dx + dy * dy) ** 0.5

    radius = (r1 + r2 - d) / 2.0
    t = (d + r1 - r2) / 2.0

    x = x1 + dx * t / d
    y = y1 + dy * t / d

    print(f"{x:.15f} {y:.15f} {radius:.15f}")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def check(inp: str, expected):
    out = run(inp).split()
    got = list(map(float, out))

    assert len(got) == 3
    for a, b in zip(got, expected):
        assert math.isclose(a, b, rel_tol=1e-12, abs_tol=1e-12), (
            f"got {got}, expected {expected}"
        )

# Provided samples
check(
    """0 0 5
6 0 5
""",
    (3.0, 0.0, 2.0),
)

check(
    """-12 34 56
78 -90 123
""",
    (13.322257821855908, -0.888444110112585, 12.890601098820779),
)

# Minimum radii, equal circles, simple horizontal placement
check(
    """0 0 1
1 0 1
""",
    (0.5, 0.0, 0.5),
)

# Equal circles with a non-horizontal center line
check(
    """0 0 5
3 4 5
""",
    (1.5, 2.0, 2.5),
)

# Unequal radii, catches the incorrect-midpoint solution
check(
    """0 0 5
6 0 9
""",
    (1.0, 0.0, 4.0),
)

# Maximum coordinate values while still having two intersections
check(
    """-1000 0 1000
999 0 1000
""",
    (-0.5, 0.0, 0.5),
)

 ## 特殊なケース

 最小サイズの場合```
0 0 1
1 0 1
```(d=1) が得られます。 半径は

 [
 R=\frac{1+1-1}{2}=0.5、
 】

 最初の中心からの距離も (0.5) です。 方向は ((1,0)) なので、答えは正確に ((0.5,0,0.5)) になります。 このアルゴリズムでは、半径 (1) に対する特別な分岐は必要ありません。 

水平以外の場合```
0 0 5
3 4 5
```中心距離は(5)です。 等しい半径を与える

 [
 R=\frac{5+5-5}{2}=2.5
 】

 そして

 [
 t=\frac{5+5-5}{2}=2.5。 
】

 最初の中心から 2 番目の中心への単位の方向は ((3/5,4/5)) であるため、解答の中心は次のようになります。 

[
 (0,0)+2.5\left(\frac35,\frac45\right)=(1.5,2)。 
】

 これにより、ジオメトリを (x) 軸に沿った 1 次元として誤って扱う実装が捕捉されます。 

半径が等しくない場合、```
0 0 5
6 0 9
```(d=6) があります。 半径は

 [
 R=\frac{5+9-6}{2}=4、
 】

 その間

 [
 t=\frac{6+5-9}{2}=1。 
】

 したがって、中心は ((1,0)) になります。 2 つのクリアランスは両方とも (4) です。 

[
 5-1=4
 】

 そして

 [
 9-(6-1)=4。 
】

 これら 2 つの量が等しいことは、まさに最適条件です。 

接線境界に近い場合、```
-1000 0 1000
999 0 1000
```中心は (1999) 単位離れています。 最終的な半径は

 [
 R=\frac{1000+1000-1999}{2}=0.5。 
】

[
 \frac{-1000+999}{2}=-0.5。 
】

-0.500000000000000 0.000000000000000 0.500000000000000
```許容誤差まで。 このケースは、実装が応答半径がゼロから十分に離れていると想定してはならない理由を示しています。 入力保証は正の半径を与えますが、座標と半径の大きさに比べて任意に小さくすることができます。
