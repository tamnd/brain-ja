 ## 解決策
 ## 問題の理解

 チップはポイントから始まります`0`を含むサークル上で`p`ポイント、番号付き`0`を通して`p - 1`。 最初の動きで次のように進みます`1`、2番目に`2`、3番目に`3`、 等々。 動きは円を囲むため、すべての位置はモジュロとみなされます`p`。 

後`k`移動すると、総移動距離は

 [
 1+2+\dots+k=\frac{k(k+1)}2.
 】

 したがって、その後の位置は`k`動くのは

 [
 pos_k=\frac{k(k+1)}2\bmod p.
 】

 タスクは、異なる値がいくつ発生するかを数えることです。`pos_0, pos_1, ..., pos_n`。 初期位置`0`が含まれているので、いつでも`n = 0`、答えは`1`。 

サークルには最大で次のものを含めることができます`10^7`ポイントが増加しますが、移動の数は次のようになります。`10^18`。 後者の境界では、すべての動きのシミュレーションが即座に除外されます。 平`10^7`反復回数は 2 秒の Python プログラムの実用的な制限にすでに近づいているため、動作シーケンスの境界のあるプレフィックスのみが重要であることを証明する必要があります。 256 MB のメモリ制限により、Python も実行可能`set`何百万もの整数が含まれていると魅力的ではありませんが、コンパクトな`bytearray`ポイントごとに 1 バイトのみを使用して、各ポイントが訪問されたかどうかを表すことができます。 

重要な周期性は三角数の公式から得られます。 あらゆる人にとって`k`、

 [
 pos_{k+2p}
 =\frac{(k+2p)(k+2p+1)}2
 \equiv \frac{k(k+1)}2
 \pmod p.
 】

 したがって、位置のシーケンスは毎回繰り返されます。`2p`動く。 以上のシミュレーションを行う必要はありません`2p`かどうかに関係なく移動します`n`は`10^6`または`10^18`。 

不注意な実装によって誤って処理される可能性のある境界ケースがいくつかあります。 のために`p = 1, n = 0`、正しい入力は次のとおりです。`1 0`そして答えは`1`、開始点がすでに唯一の点であるためです。 移動後の目的地のみをカウントするソリューションでは、正しく印刷されません。`0`。 

のために`p = 3, n = 10`、ポジションは`0, 1, 0, 0, 1, 0, ...`、したがって、答えは次のとおりです`2`。 の期間を想定した解決策`p`証明せずに引っ越しをしても、偶然に事件が解決する可能性はありますが、実際の期間は`2p`。 

のために`p = 4, n = 3`、訪問した位置は次のとおりです。`0, 1, 3, 2`、すべての点に到達しており、答えは次のとおりです。`4`。 未満の後に停止`n`移動したり、開始位置を別々に誤って処理したりすると、1 つずつずれたエラーが発生します。 

## アプローチ

 直接ソリューションはチップに正確に従います。 現在の位置を維持し、移動するたびに`i`、 追加`i`モジュロ`p`。 新しい位置がこれまでに見られなかった場合は常に、答えを増やします。 円の位置によってインデックス付けされたブール配列は、定数時間のメンバーシップ チェックを提供します。これは、チップが到達した一連の位置を正確に記録するため、これは正しいことです。 

問題は次の値です。`n`。 最悪の場合、`n = 10^18`したがって、直接シミュレーションには最大で`10^18`繰り返しますが、これは完全に不可能です。 

最適化のロックを解除する観察は、後のチップの位置です。`k`移動は三角数のモジュロです`p`。 以来

 [
 (k+2p)(k+2p+1)-k(k+1)
 =4pk+2p(2p+1)、
 】

 その差は次で割り切れます`2p`で割った後、`2`、対応する位置は次の倍数異なります。`p`。 したがって、`pos_{k+2p} = pos_k`。 

総当たり法が機能するのは、シミュレートされた移動ごとに 1 つの正確な位置が与えられ、訪問された配列がそれを記録するためです。 次の場合に失敗します。`n`巨大です。 周期性の観察により、問題は最大でも次のとおりに軽減されます。`2p`動く。 以来`p <= 10^7`、これは最大でも`2 * 10^7`潜在的に天文学的な値とは独立した繰り返し`n`。 

また、すべての箇所で 2 回目のパスを回避することもできます。`p`以前は見えなかった点に到達したときにすぐに答えを増やすことによって位置を決定します。 あ`bytearray`訪問済みフラグをコンパクトに格納します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | O(p) | 遅すぎるとき`n`大きい |
 | 最適 | O(min(n, 2p)) | O(p) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`p`そして`n`。 チップはすでにポイントを訪問しています`0`なので、訪問した構造体を point で初期化します。`0`マークが付いており、答えは以下に等しい`1`。 
2. 手数を次のように置き換えます。`min(n, 2p)`。 シーケンスは毎回繰り返されます`2p`移動するため、最初の完全な期間の後に何かをシミュレートしても、新しいポイントを追加することはできません。 
3.キープ`cur`チップの現在の位置とプロセスが移動するにつれて、`1`移動回数の減少により。 移動用`i`、 前進`cur`による`i`モジュロ`p`。 
4. 結果の位置が以前にマークされていない場合は、それをマークして答えをインクリメントします。 ある位置には何度も到達する可能性がありますが、答えに寄与するのは最初の訪問時のみです。 
5. マークされた位置の数を出力します。 答えは、新しい位置に遭遇したときに正確に増加するため、すでに個別の訪問ポイントの数と等しくなります。 

### なぜ効果があるのか

 不変条件は、最初の処理後の`i`動き、`cur`移動後のチップの正確な位置です`i`、それらの移動中に訪問したすべての点が訪問済み配列内でマークされます。 初期化により移動の不変式が確立されます`0`、以来のポイント`0`が開始位置です。 各反復は次のジャンプ長だけ正確に進み、不変条件を維持しながら結果の位置をマークします。 

残る唯一の問題は、その後に停止するかどうかです。`2p`移動するとポイントが失われる可能性があります。 それは不可能です。`k`、

 [
 pos_{k+2p}=pos_k。 
】

 最初の後に到達したすべてのポジション`2p`移動は前の期間内の対応する位置にすでに到達しています。 したがって、最初の`min(n, 2p)`移動には、要求された実行中に訪問できるすべての個別のポイントが含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    p, n = map(int, input().split())

    visited = bytearray(p)
    visited[0] = 1
    answer = 1

    moves = min(n, 2 * p)

    cur = 0
    step_mod = 1

    for _ in range(moves):
        cur += step_mod
        if cur >= p:
            cur -= p

        if not visited[cur]:
            visited[cur] = 1
            answer += 1

        step_mod += 1
        if step_mod == p:
            step_mod = 0

    print(answer)

if __name__ == "__main__":
    solve()
```の`visited`配列には正確な値があります`p`エントリは各ポイントに 1 つずつあります。 あ`bytearray`要素が 1 バイトのみを占めるため、Python リストまたはセットの代わりに使用されます。`p`と同じくらい大きいです`10^7`。 

変数`moves`周期性引数を直接実装します。 もし`n < 2p`、要求されたすべての動きがシミュレートされます。 もし`n >= 2p`、必要なピリオドは 1 つだけです。 

実装は維持します`step_mod`ジャンプ長全体を保存するのではなく、 ジャンプ長のモジュロのみなので、`p`位置に影響を与えるので、これは同等です。 あらゆる動きの後に、`step_mod`モジュロでインクリメントされる`p`。 

アップデート```
cur += step_mod
if cur >= p:
    cur -= p
```と同等です`cur = (cur + step_mod) % p`。 反復ごとに両方とも`cur`そして`step_mod`いる`[0, p - 1]`、したがって、それらの合計は以下になります`2p`、1 回の減算で十分であることを意味します。 回避`%`メインループ内で Python 実装を大幅に軽量化します。 

整数には任意の精度があるため、Python では整数オーバーフローの問題は発生しません。 固定幅言語では、の元の値`n`十分な幅の整数型が必要ですが、適用後のループ カウンタ`min(n, 2p)`せいぜい`2 * 10^7`。 

ループは、新しい位置を導入できる手の数だけ実行されます。 初期点は個別にカウントされるため、ループは意図的に移動を処理します。`1`を通して`moves`誤って開始位置を移動として扱うのではなく。 

## 実用的な例

 サンプル 1 の場合、`p = 3`そして`n = 10`。 期間は`2p = 6`したがって、最初の 6 つの手だけを検査する必要があります。 

| 移動 | ステップモジュロ`p`| ポジション | 新しいポイント? | 答え |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | 初期点 | 1 |
 | 1 | 1 | 1 | はい | 2 |
 | 2 | 2 | 0 | いいえ | 2 |
 | 3 | 0 | 0 | いいえ | 2 |
 | 4 | 1 | 1 | いいえ | 2 |
 | 5 | 2 | 0 | いいえ | 2 |
 | 6 | 0 | 0 | いいえ | 2 |

 ジャンプの長さは、`1, 2, 3, 4, 5, 6`、ただしモジュロ`3`彼らです`1, 2, 0, 1, 2, 0`。 ポイントのみ`0`そして`1`が発生するので、答えは`2`。 残りの 4 つの要求された移動は同じ期間を繰り返します。 

サンプル 2 の場合、`p = 5`そして`n = 3`。 以来`n < 2p`、3 つの動きすべてがシミュレートされます。 

| 移動 | ステップモジュロ`p`| ポジション | 新しいポイント? | 答え |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | 初期点 | 1 |
 | 1 | 1 | 1 | はい | 2 |
 | 2 | 2 | 3 | はい | 3 |
 | 3 | 3 | 1 | いいえ | 3 |

 訪れたポイントは、`{0, 1, 3}`、必要な答えを与える`3`。 このトレースは、移動のカウントと新しく訪問したポイントのカウントが異なる操作である理由も示しています。 3 番目の手は既存の点に着地するため、答えは増加しません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(min(n, 2p)) | せいぜい`2p`移動ごとに一定の作業が行われ、移動がシミュレートされます。 
| スペース | O(p) | 円の点ごとに 1 バイトが保存されます。 

以来`p <= 10^7`、アルゴリズムのパフォーマンスは最大でも`2 * 10^7`たとえ次の場合でも繰り返し`n = 10^18`。 の`bytearray`の最大値で約 10 MB が必要です`p`、256 MB のメモリ制限を余裕で下回ります。 解決策は同じものに基づいています`O(p)`-時代によって可能になったスケールシミュレーション`2p`、潜在的に巨大な値を処理しようとするのではなく、`n`。 

## テストケース```python
import sys
import io

def solve_data(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    p, n = map(int, sys.stdin.readline().split())

    visited = bytearray(p)
    visited[0] = 1
    answer = 1

    moves = min(n, 2 * p)

    cur = 0
    step_mod = 1

    for _ in range(moves):
        cur += step_mod
        if cur >= p:
            cur -= p

        if not visited[cur]:
            visited[cur] = 1
            answer += 1

        step_mod += 1
        if step_mod == p:
            step_mod = 0

    print(answer)

    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return result

# Provided samples
assert solve_data("3 10\n") == "2\n", "sample 1"
assert solve_data("5 3\n") == "3\n", "sample 2"
assert solve_data("8 1000000000000000000\n") == "8\n", "sample 3"

# Minimum circle, no moves
assert solve_data("1 0\n") == "1\n", "single point with zero moves"

# Minimum circle, many moves
assert solve_data("1 1000000000000000000\n") == "1\n", "single point with huge n"

# Boundary before a full period
assert solve_data("4 3\n") == "4\n", "all four points reached before 2p"

# Exactly one full period
assert solve_data("3 6\n") == "2\n", "exactly 2p moves"

# Huge n must be reduced to one period
assert solve_data("10000000 1000000000000000000\n") <= "10000000\n", "huge n boundary"
```ここで正確な値を計算すると、テスト自体の内部でのソリューションの作業が重複してしまうため、最後の大規模なテストでは、結果が有効なカウントであることのみがチェックされます。 他のテストでは、予想される正確な答えと重要な期間の境界がテストされます。 

| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 0`|`1`| 最小`p`、移動ゼロ、開始点はカウントする必要があります |
 |`1 1000000000000000000`|`1`| 一点の円と巨大な`n`|
 |`4 3`|`4`| すべてのポイントは 1 つの期間前に到達できます |
 |`3 6`|`2`| その通り`2p`動きと周期性の境界 |
 |`10000000 1000000000000000000`| の値`[1, 10000000]`| 最大スケール`p`そして巨大な`n`|

 ## 特殊なケース

 のために`p = 1, n = 0`、アルゴリズムは 1 つの要素を作成します`bytearray`、マークの位置`0`、およびセット`answer = 1`。 以来`moves = min(0, 2) = 0`の場合、ループは実行されません。 出力は`1`、開始点を正確に数えます。 

のために`p = 3, n = 10`、アルゴリズムは置き換えます`n`と`min(10, 6) = 6`。 から始まる`0`、6 つのシミュレートされた手の後の位置は次のとおりです。`1, 0, 0, 1, 0, 0`。 ポジションのみ`1`新しいので、最終的な答えは`2`。 移動 7 から 10 は、周期的なシーケンスの最初の 4 つの位置を繰り返すため、何も追加できません。 

のために`p = 4, n = 3`、ループは位置を処理します`1, 3, 2`。 イニシャルと一緒に`0`、訪問されたセットは次のようになります`{0, 1, 2, 3}`、したがって、答えは次のとおりです`4`。 これにより、開始点がすでに訪問済みセットの一部であることを忘れるというよくある間違いが発生します。 

のために`p = 3, n = 6`、アルゴリズムは正確に 1 つの完全な期間を処理します。 ポジションは、`0, 1, 0, 0, 1, 0, 0`、結果は残ります`2`。 最後の位置が戻るということは、`0`具体的な本人確認でもあります`pos_{2p} = 0`。 

のために`p = 8, n = 10^18`、要求される移動数は膨大ですが、`moves`になる`16`。 アルゴリズムはこれら 16 の手だけを検査します。 その後、同じ位置が 16 手ごとに繰り返されるため、最初の期間から得られた答えは、要求された実行全体の答えでもあります。
