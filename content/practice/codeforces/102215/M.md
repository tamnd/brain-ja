 ## 問題の理解

 (n) 個のゲームがあります。 私たちが投票する前に、ゲーム (i) にはすでに (v_i) の投票があり、そのゲームを観るのが楽しみです (p_i)。 各ゲームに追加できる投票は最大 1 つであるため、選択するのは単にゲーム インデックスのサブセットです。 

投票後、すべての投票の中から一様にランダムに 1 票が選ばれます。 ゲーム (i) が (v_i+1) 票で終了した場合、それに投票したとき、期待される喜びへの寄与は (p_i(v_i+1)) になります。 賛成票を投じなかった場合、その貢献度は (p_i v_i) です。 

しましょう

 [
 V=\sum_i v_i
 】

 は既存の投票数であり、

 [
 P=\sum_i p_i v_i
 】

 それらの投票によって重み付けされた合計の喜びになります。 (k) 個のゲームを含むサブセット (S) を選択した場合、最終的な投票数は (V+k) ですが、重み付けされた喜びの合計は次のようになります。 

[
 P+\sum_{i\in S}p_i。 
】

 したがって、期待される喜びは、

 [
 \frac{P+\sum_{i\in S}p_i}{V+|S|}。 
】

 タスクは、この分数を最大化する (S) を選択し、その分数を既約形式で出力し、選択したゲーム インデックスを出力することです。 

制約は (n\le 1000) であるため、(O(n^2)) の解は容易に合理的であり、(O(n\log n)) の解は問題なく 2 秒の制限内に収まります。 一方、すべてのサブセットを列挙すると、すでに (2^{1000}) 個の可能性が得られますが、これはまったく実行不可能です。 最大 500 のテスト ケースが存在する可能性があるという事実により、指数関数的なアプローチはさらに現実的ではなくなります。 

不用意に実装すると失敗するケースがいくつかあります。 まず、ゲームを選択しないことは許可されなければなりません。 例えば、```
1
1
0 5
```はすでに期待される喜び (0) を持っており、ゲームに投票しても改善されません。 最適な答えは、```
0/1
0
```常に少なくとも 1 つのゲームを選択する実装では、ここでも同じ数値が得られますが、選択されたセットに関する独自の仮定に違反したり、不必要な投票が生成されたりする可能性があります。 

より重要なエッジケースは、既存の投票がないゲームです。 考慮する```
1
2
100 0
0 1
```私たちの投票がなければ、期待される喜びは (0) です。 ゲーム 1 に投票すると、合計 2 つの投票と期待される喜び (100/2=50) が得られるため、ゲーム 1 を選択する必要があります。 ゲーム 1 の既存の値 (p_i v_i) はゼロですが、追加の投票が寄与します (p_i)。 余分な貢献を忘れることは、誤った公式の一般的な原因です。 

快楽における結びつきもまた、境界例の一つです。 のために```
1
3
5 10
5 20
5 30
```ゲームを選択しないことも含め、期待されるあらゆる楽しみは (5) です。 どのサブセットも有効であるため、アルゴリズムは固有の最適なサブセットに依存してはなりません。 決定的なタイブレーク ルールはテストには役立ちますが、問題では必要ありません。 

最後に、答えは分数であり、必ずしも整数である必要はありません。 2 番目のサンプルでは、​​最適値は (5110/1114) ですが、これは (2555/557) になります。 未約分数を出力すると、数値が正しい場合でも出力要件に違反します。 

## アプローチ

 直接的なアプローチは、(n) 個のゲームのすべてのサブセットを列挙することです。 各サブセットについて、そのサイズを計算し、選択したゲームの楽しみを (P) に加え、(V+|S|) で割って、最良の部分を保持することができます。 これは正しいです。すべての法定投票戦略は正確に 1 つのサブセットであるため、列挙ではすべての可能な戦略が考慮されます。 

ただし、(2^n) 個のサブセットが存在します。 すべてのサブセットについてすべて (n) のゲームをスキャンして分子を計算すると、最悪の場合の作業は (O(n2^n)) になります。 各サブセットを (O(1)) 回追加で評価する、より慎重なサブセット動的プログラムを使用した場合でも、依然として (2^n) 個の状態が存在します。 (n=1000) では、これは実装で処理できる範囲をはるかに超えています。 

有益な観察は、分母はどのゲームを選択するかではなく、選択するゲームの数にのみ依存するということです。 正確に (k) 個のゲームに投票することを事前に決定したとします。 すると、分母は (V+k) に固定され、(P) も固定されます。 最適化できる唯一の部分は、

 [
 \sum_{i\in S}p_i。 
】

 正確に (k) 個の選択されたゲームの場合、この合計は (p_i) の (k) 個の最大値を取ることによって最大化されます。 (k) が固定されると、既存の投票数 (v_i) はどのゲームを選択するかに影響を与えなくなります。 それらは固定ベースライン (P) と (V) に影響しますが、同じ (k) を持つすべての候補は同じ分母と同じベースラインを持ちます。 

これにより、問題全体が (p_i) でゲームをソートし、そのソート順のすべてのプレフィックスを考慮することになります。 プレフィックスの長さ (k) については、サイズ (k) のすべてのサブセットの中で可能な限り最良の分子がわかります。 正確な整数演算を使用して、これらの (n+1) 個の候補を単純に比較します。 

この総当たり法は、各サブセットが 1 つの可能な投票戦略を表すため機能しますが、サブセットが指数関数的に多いため失敗します。 同じ数の追加投票を持つすべての戦略が同じ分母を共有するという観察により、サイズ (k) のすべてのサブセットを単一の最良の代表、つまり (k) 個の最大の喜びに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n2^n)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n\log n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (V=\sum v_i) と (P=\sum p_i v_i) を計算します。 これらは、既存の投票の合計数と、それらの投票によってもたらされた喜びの合計です。 すべての戦略は同じ既存の世論調査から始まるため、これらの数値がすべての候補者に共通のベースラインを形成します。 
2. すべてのゲームを (p_i) の降順に並べ替えます。 元のインデックスと喜びの値を保持します。 この順序により、考えられるすべてのサイズの最適なサブセットを接頭辞で表すことができます。 
3. (k=0) から開始します。 投票を追加しないため、候補値は (P/V) です。 投票を追加すると期待される喜びが減少する可能性があるため、このケースを考慮する必要があります。 
4. 分類されたゲームを最大の楽しみから最小の楽しみまでたどります。 次のゲームが追加されると、その(p_i)分だけ追加の楽しみが増え、投票数が1つ増えます。 長さ (k) のプレフィックスの場合、候補部分は次のようになります。 

[
 \frac{P+\text{prefixPleasure}}{V+k}。 
】

 プレフィックスには (k) 個の最大の喜びの値が含まれるため、正確に (k) 個のゲームを含むすべてのサブセットの中で最適です。

1. 現在の候補を、交差乗算によってこれまでに見つかった最良の分数と比較します。 分数 (a/b) と (c/d) については、(ad) と (cb) を比較します。 これにより、浮動小数点精度のエラーが回避され、正確な順序が与えられます。 
2. 新しい候補の方が厳密に優れている場合は常に、プレフィックスの長さとインデックスを保存します。 問題では任意の最適サブセットが受け入れられるため、値が等しい場合に最初の最適値を維持することは有効です。 
3. 最適なプレフィックスを見つけたら、その分子と分母を最大公約数で減らします。 縮小された分数、選択されたゲームの数、およびそれらの元のインデックスを出力します。 

これが機能する理由: 追加できるすべての可能な投票数 (k) について、分母 (V+k) は固定されます。 既存の貢献度 (P) も固定されます。 したがって、サイズ (k) のすべてのサブセット間で、期待される喜びを最大化することは、それらの (p_i) 値の合計を最大化することとまったく同じです。 (k) 個の最大 (p_i) 値がその最大値に達するため、ソートされたプレフィックスにより、考えられるすべての (k) に対して最適な戦略が得られます。 このアルゴリズムは (0) から (n) までのすべての (k) をチェックするため、考えられるすべてのサイズ クラスで最適な戦略をチェックし、その結果全体的に最適な戦略を見つけます。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())

        games = []
        total_votes = 0
        base_pleasure = 0

        for i in range(n):
            p, v = map(int, input().split())
            games.append((p, i + 1))
            total_votes += v
            base_pleasure += p * v

        games.sort(key=lambda x: (-x[0], x[1]))

        best_num = base_pleasure
        best_den = total_votes
        best_k = 0
        best_indices = []

        prefix = 0

        for k, (p, idx) in enumerate(games, 1):
            prefix += p

            cur_num = base_pleasure + prefix
            cur_den = total_votes + k

            if cur_num * best_den > best_num * cur_den:
                best_num = cur_num
                best_den = cur_den
                best_k = k
                best_indices = [games[j][1] for j in range(k)]

        g = gcd(best_num, best_den)
        best_num //= g
        best_den //= g

        out.append(f"{best_num}/{best_den}")
        out.append(str(best_k))
        out.append(" ".join(map(str, best_indices)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()

ソートでは喜びの減少を使用します。 元のインデックスによる 2 番目のソートは数学的には必要ありませんが、複数のゲームが同じ楽しみを持っている場合、プログラムが決定的になります。 目的に対して等しい喜びは交換可能であるため、それらの間のどのような順序付けも有効です。 

最初の候補は空のプレフィックスです。 その分母は`total_votes`、入力条件によって正であることが保証されているため、ゼロ除算のケースはありません。 

スキャン中に、`prefix`最初の喜びの合計が含まれています`k`ゲーム。 現在の分子は`base_pleasure + prefix`、分母は`total_votes + k`。 比較では乗算ではなく乗算が使用されます。`/`、したがってすべての決定は正確です。 Python の整数も自動的に増加するため、外積がオーバーフローすることはありません。 

選択したインデックスのリストは最初のインデックスから再構築されます。`k`厳密に優れた候補が見つかるたびにゲームをソートします。 これは、リテラル実装の改善ごとに (O(n)) であり、最悪の場合、スキャンが (O(n^2)) になる可能性があります。 (n\le1000) にとっては、これでも問題なく受け入れられます。 必要に応じて、実装では、`best_k`スキャン中にプレフィックスを再構築し、最後に 1 回プレフィックスを再構築して、厳密な (O(n\log n)) 実装を実現します。

            if cur_num * best_den > best_num * cur_den:
                best_num = cur_num
                best_den = cur_den

        assert num * best_den == best_num * den

 ## 特殊なケース

 (n=1) の場合、考えられる戦略は 2 つだけです。 入力用```
1
1
0 1
```ベースラインは (0/1) です。 唯一のゲームを選択すると、喜びが 0 の票が追加されるため、値は 0 のままになります。 スキャンは (k=0) から始まり、(k=1) の候補の方が厳密には優れているわけではないことを確認し、空のセットを保持します。 出力は```
0/1
0
```既存の投票がゼロのゲームは、`base_pleasure`はゼロですが、それを選択すると分子に最大の喜びが加わります。 のために```
1
2
100 0
0 1
```ベースラインは (0/1) です。 並べ替えると、ゲーム 1 が最初になります。 これを選択すると (100/2=50) が生成され、両方を選択すると (100/3) が生成されます。 したがって、最適なプレフィックスは最初のプレフィックスです。```
50/1
1
1
```複数のゲームが同じ楽しみを持っている場合、その順序は目的に影響しません。 のために```
1
3
5 10
5 20
5 30
```基本的な期待値はすでに (5) であり、追加された投票には喜びも含まれます (5)。 すべてのプレフィックスには期待値 (5) があります。 実装は厳密な改善のみを更新するため、(k=0) が維持され、次のようになります。```
5/1
0
```これが、分数を厳密に比較する理由でもあります。`>`それよりも`>=`便利です。 ここではどちらを選択しても有効な答えが得られますが、厳密に比較すると、安定した最小プレフィックスの答えが得られます。 

最後の微妙なケースは、ゲームを追加すると最終的に有害になる場合です。 のために```
1
3
10 1
9 1
0 100
```ベースラインは (19/102) です。 ソート後の楽しみは (10,9,0) です。 1 つのゲームを選択すると与える (29/103)、2 つのゲームを選択すると (38/104=19/52)、3 つすべてを選択すると (38/105)。 3 番目の投票は分母を増やす一方で分子には何も寄与しないため、長さ 2 のプレフィックスが最適になります。```
19/52
2
1 2
```このアルゴリズムは、より多くの快感をもたらすゲームをプレイすることが常に効果があると仮定するのではなく、すべてのプレフィックスをチェックします。 唯一の関連パラメータである選択されたゲームの数を徹底的にスキャンすることで、指数関数的な任意のサブセットを回避しながら最適性を維持できます。
