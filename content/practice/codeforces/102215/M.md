 ## 解決策
 ## 問題の理解

 (n) 個のゲームがあります。 ゲーム (i) には現在 (v_i) 票があり、そのゲームを見るのは楽しいです (p_i)。 どのゲームにも最大 1 回投票できます。 投票後、すべての投票から 1 票が一律に選択されるため、最終投票数が (x) のゲームが、確率 (x) を総投票数で割った値で選択されます。 

ゲームのセット (S) を選択するとします。 しましょう

 [
 V=\sum_{i=1}^{n}v_i,\qquad
 A=\sum_{i=1}^{n}v_i p_i。 
]

 投票する前に期待される楽しみは (A/V) です。 (S) のすべてのゲームに投票すると、総投票数は (V+|S|) になり、楽しみを加重した総投票数は次のようになります。 

[
 A+\sum_{i\in S}p_i。 
]

 したがって、(S) に期待される喜びは次のようになります。 

[
 \frac{A+\sum_{i\in S}p_i}{V+|S|}。 
]

 出力には、この最大期待値が既約分数として含まれ、その後に選択したゲーム数とそのインデックスが含まれている必要があります。 

制約は並べ替えには十分小さいですが、サブセットを列挙するには大きすぎます。 (n\le 1000) の場合、(O(n^2)) の解は容易に実用的であり、(O(n\log n)) の解は 2 秒の制限内で十分な余裕があります。 (500) のテスト ケースではこの結論は変わりません。これは、合計入力サイズが実際のテスト データ内の対応する (n) の合計によって制限されており、アルゴリズムが各ゲームを少数回処理するだけで済むためです。 

不用意に実装すると失敗するケースがいくつかあります。 まず、ゲームを選択しないことを許可する必要があります。 のために```
1
1
5 10
```期待される喜びはすでに (5) であり、唯一のゲームに投票しても期待は変わりません。 最適な出力は次のとおりです。```
5/1
0
```少なくとも 1 つのゲームを選択する必要があると想定した実装では、答えが不必要に制約されてしまいます。 

2 番目の問題は、現在の投票がゼロのゲームでも、追加するのに最適なゲームである可能性があることです。 のために```
1
2
0 0
10 1
```最初の期待値は (10) です。 ゲーム(1)を選択すると期待値は(5)に変更され、ゲーム(2)を選択すると期待値は(10)に変更されます。 何も選択しない場合も含め、どちらの選択も最適です。 (v_i>0) のゲームのみを考慮するソリューションでは、投票ゼロのゲームが現在の期待と同じ楽しみを持っている場合、有効な最適な選択を逃す可能性があります。 

最も重要なエッジケースは分母に関係します。 のために```
1
2
10 1
0 1
```最初に期待される喜びは (5) です。 ゲーム (1) を追加すると (20/3) が得られ、ゲーム (2) を追加すると (10/3) が得られます。 正解は(20/3)です。 1 票を追加する実際の効果ではなく、(p_i/v_i) のみを比較する方法は、別の問題を解決します。 

最後に、答えを減らす必要があります。 のために```
1
2
6 1
2 1
```初期の期待値は (4) であり、どちらかのゲームを選択すると期待値は (4) に維持されます。 答えは次のように出力する必要があります。`4/1`、 ない`8/2`または別の同等の分数。 

## アプローチ

 直接的なアプローチは、ゲームのすべてのサブセットを試してみることです。 選択したサブセット (S) について、次を使用してその期待される喜びを計算できます。 

[
 \frac{A+\sum_{i\in S}p_i}{V+|S|}。 
]

 これは正しいです。考えられるすべての投票決定は、正確に 1 つのサブセットで表されるからです。 問題はサブセットの数です。 それらは (2^n) 個あり、適切な前処理を使用して各サブセットが (O(1)) 時間で評価されたとしても、(n=1000) の最悪のケースでは (2^{1000}) の演算が必要になりますが、これは完全に実行不可能です。 

有益な観察は、分母は選択されたゲームの数のみに依存し、ゲームのアイデンティティには依存しないということです。 選択ゲーム数を(k)に固定します。 この場合、すべての候補は同じ分母 (V+k) を持ち、元の値 (A) も固定されます。 私たちが改善できる唯一の部分は、

 [
 \sum_{i\in S}p_i。 
]

 正確に (k) 個の選択されたゲームの場合、この合計は、(k) 個の最大の喜びの値を取得することによって最大化されます。 両方の選択で正確に 1 票が追加され、分母に同じ影響を与えるため、大きい値を除外しながら小さい値を選択する理由はありません。 

これにより、問題は 1 次元の検索に変わります。 (p_i) を減少させてゲームを並べ替え、その楽しみのプレフィックスの合計を計算して評価します。 

[
 \frac{A+P_k}{V+k}
 ]

 (0) から (n) までの (k) ごとに、(P_k) は最初の (k) 個の喜びの合計です。 単に最良の部分を保持するだけです。 

ブルート フォースは、考えられるすべてのサブセットを検査するため機能しますが、サブセットが指数関数的に多いため失敗します。 選択されたゲームの数のみが分母にとって重要であるという観察により、同じサイズのすべてのサブセットを 1 つの代表、つまり (k) 個の最大の楽しみを含むセットに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^n n))、またはサブセット前処理を使用した (O(2^n)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n\log n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのゲームを読み取り、現在の総投票数 (V) と現在の重み付けされた喜び (A=\sum v_i p_i) を計算します。 これらの値は、投票を追加する前の期待値を表します。 
2. ゲームを降順 (p_i) で並べ替えます。 どのゲームを選ぶかを決定する際に重要なのは、楽しみの順序だけです。 既存の投票数 (v_i) は、(A) と (V) ですでに完全に考慮されています。 
3. (k=0) から開始します。 対応する候補は、価値 (A/V) を伴うノーゲーム投票の決定です。 投票を追加すると期待値が下がる可能性があるため、(k=0) を含める必要があります。 
4. ソートされたゲームを最大の喜びから最小の喜びまでスキャンし、プレフィックスの喜びの合計 (P_k) を維持します。 最初の (k) 個のゲームを処理した後、正確に (k) 個のゲームを含むすべての選択肢の中から最良の答えは次のようになります。 

[
 \frac{A+P_k}{V+k}。 
]

 1. 相互乗算を使用して、この候補をこれまでに見つかった最良の値と比較します。 2 つの分数 (a/b) と (c/d) について、(a d) と (c b) を比較します。 これにより、浮動小数点精度の問題が回避され、正確な比較が可能になります。 
2. 候補の方が優れている場合は、その (k) を保存します。 選択されたゲームは、ソート順で正確に最初 (k) のゲームであるため、個別のサブセットの再構築は必要ありません。 
3. 保存された (k) の分子と分母を再計算し、両方を最大公約数で割って、約分した分数を出力します。 次に、保存された (k) と対応する元のインデックスを出力します。 

機能する理由: 固定 (k) ごとに、分母 (V+k) が固定されるため、期待値を最大化することは、追加される喜びを最大化することと同じです。 (k) 個の最大 (p_i) 値は、すべての (k) 要素サブセットの中で可能な最大の追加の喜びを与えます。 したがって、スキャンでは、考えられるすべてのカーディナリティ (k) に対して可能な限り最良のサブセットが考慮されます。 すべての有効なサブセットには (0) と (n) の間のカーディナリティがあるため、これらの候補の 1 つがグローバルに最適になります。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())

        games = []
        total_votes = 0
        weighted_pleasure = 0

        for idx in range(1, n + 1):
            p, v = map(int, input().split())
            games.append((p, idx))
            total_votes += v
            weighted_pleasure += p * v

        # For a fixed number k of new votes, choose the k largest pleasures.
        games.sort(reverse=True)

        best_k = 0
        best_num = weighted_pleasure
        best_den = total_votes

        prefix = 0

        for k, (p, idx) in enumerate(games, 1):
            prefix += p

            num = weighted_pleasure + prefix
            den = total_votes + k

            # num / den > best_num / best_den
            if num * best_den > best_num * den:
                best_num = num
                best_den = den
                best_k = k

        selected = [games[i][1] for i in range(best_k)]

        g = math.gcd(best_num, best_den)
        best_num //= g
        best_den //= g

        out.append(f"{best_num}/{best_den}")
        out.append(str(best_k))
        out.append(" ".join(map(str, selected)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初のループは、各ゲームの楽しみとオリジナルのインデックスを保存しながら (V) と (A) を計算します。 ソートによって順序が変更されるため、元のインデックスは保持されますが、出力は入力位置を参照する必要があります。 

逆の順序で並べ替えると、最大の喜びが最初に配置されます。 Python はタプルを辞書順にソートするため、`(p, idx)`と`reverse=True`また、快楽が等しい場合には指数を逆転させます。 同等の喜びは交換可能であるため、これは正しさには影響しません。 

スキャンは (k=0) 候補から始まります。 新しく追加されたゲームごとに、`prefix`は (P_k) となるため、候補分子は`weighted_pleasure + prefix`そしてその分母は`total_votes + k`。 

比較では乗算ではなく乗算が使用されます。`/`。 Python の整数には任意の精度があるため、次のような積でも`num * best_den`正確に処理されます。 これにより、浮動小数点の丸めとオーバーフローの問題の両方が回避されます。 

選択されたインデックスは最初のものです`best_k`並べ替え後のゲーム。 ついに、`math.gcd`正確な分数を減らします。 いつ`best_k`がゼロの場合、選択されたリストは空であり、最終出力行は単に空です。これは、(k=0) であるため有効です。 

## 実用的な例

 最初のテスト ケースには 5 つのゲームがあります。 当初は、

 [
 V=5+7+3+2+4=21
 ]

 そして

 [
 A=10\cdot5+4\cdot7+6\cdot3+8\cdot2+2\cdot4=132。 
]

 楽しみ順に並べ替えると、ゲームは (10,8,6,4,2) のように表示されます。 

| (k) | ゲームの楽しみを追加 | プレフィックス (P_k) | 分子 | 分母 | 値 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | 132 | 21 | (132/21=44/7) |
 | 1 | 10 | 10 | 142 | 22 | (71/11) |
 | 2 | 8 | 18 | 150 | 23 | (150/23) |
 | 3 | 6 | 24 | 156 | 24 | (6) |
 | 4 | 4 | 28 | 160 | 25 | (5/32) |
 | 5 | 2 | 30 | 162 | 26 | (81/13) |

 最良の候補は (k=3)、値は (6) です。 ただし、サンプル出力ではゲーム (1) と (4) が選択されており、(150/25=6) も得られます。 これは、複数の最適なサブセットが存在する理由を示しています。 上記の実装では、最初の厳密に優れた候補が保持されるため、選択されたインデックスがサンプルと異なる場合でも、出力も有効になります。 

2 番目のテスト ケースでは、

 [
 V=1000+100+10+1=1111
 ]

 そして

 [
 A=1\cdot1000+10\cdot100+100\cdot10+1000\cdot1=4000。 
]

 喜びはすでに昇順になっているため、並べ替えると (1000,100,10,1) が生成されます。 

| (k) | ゲームの楽しみを追加 | プレフィックス (P_k) | 分子 | 分母 | 値 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | 4000 | 1111 | (4000/1111) |
 | 1 | 1000 | 1000 | 5000 | 1112 | (625/139) |
 | 2 | 100 | 1100 | 5100 | 1113 | (1700/371) |
 | 3 | 10 | 1110 | 5110 | 1114 | (2555/557) |
 | 4 | 1 | 1111 | 5111 | 1115 | (5111/1115) |

 最大値は (k=3) で発生します。これは、喜びのある元のゲーム (10、100、1000)、つまりゲーム (2、3、4) に対応します。 結果として得られる分数は、

 [
 \frac{5110}{1114}=\frac{2555}{557}。 
]

 このトレースは、すべてのゲームをプレイすることが自動的に最適化されない理由も示しています。 最終ゲームには喜び (1) がありますが、追加の分母を補うには低すぎます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n\log n)) | ソートはリニア スキャンよりも優先されます。 
| スペース | (O(n)) | ゲームと選択したインデックスが保存されます。 

(n\le1000) の場合、(O(n\log n)) での並べ替えは簡単に 2 秒の制限内に収まります。 このアルゴリズムは、ソート後にゲームごとに一定数の整数演算のみを実行します。また、Python の任意精度の整数により、これらの境界に対する実際的なメモリの問題を引き起こすことなく、分数の比較が正確になります。

def validate(inp: str):
    output = solve_data(inp).strip("\n")
    lines = output.splitlines()

    data = inp.split()
    pos = 0
    t = int(data[pos])
    pos += 1

    line_pos = 0

    for case in range(t):
        n = int(data[pos])
        pos += 1

        games = []
        total_votes = 0
        weighted = 0

        for idx in range(1, n + 1):
            p = int(data[pos])
            v = int(data[pos + 1])
            pos += 2
            games.append((p, v))
            total_votes += v
            weighted += p * v

        frac = lines[line_pos]
        line_pos += 1

        num_s, den_s = frac.split("/")
        num = int(num_s)
        den = int(den_s)

        assert den > 0
        assert math.gcd(num, den) == 1

        k = int(lines[line_pos])
        line_pos += 1

        indices = []
        if line_pos < len(lines):
            current = lines[line_pos].strip()
            if current:

        line_pos += 1

        assert len(indices) == k
        assert len(set(indices)) == k
        assert all(1 <= x <= n for x in indices)

                    cnt += 1
            best = max(best, Fraction(weighted + s, total_votes + cnt))

        if n <= 10:

```初期値は(10/1=10)です。 ソート後の快楽シーケンスは (10,0) になります。 最初の候補は (20/2=10) であるため、初期値を結び付け、置き換えません。 2 番目の候補は (20/3) ですが、これはさらに悪いです。 答えは残っている`10/1`選択されたゲームがありません。 当然のことながら、ゼロ投票ゲームがまだスキャンに含まれていますが、その楽しさは他のすべてのゲームとまったく同じように評価されます。 

選択は現在の投票数ではなく、喜びに基づいて行われなければなりません。 のために```
1
2
10 1
0 1
```(A=10) と (V=2) があり、最初の期待値は (5) になります。 喜んでゲームを選択する (10) と (20/3) が生成され、楽しみながらゲームを選択する (0) と (10/3) が生成されます。 楽しみによって並べ替えると、正しいゲームが最初に配置され、スキャンによってそれが選択されます。 

等しい値にも厳密な比較が必要です。 のために```
1
3
7 1000
7 0
7 1
```(A=7007) と (V=1001) があるため、最初の期待値は正確に (7) になります。 追加されたすべての投票にも喜び (7) があるため、すべての (k) について、

 [
 \frac{7007+7k}{1001+k}=7。 
]

 アルゴリズムは (k=0) を維持しますが、任意の数のゲームを選択することも最適です。 これが、使用する理由です`>`それよりも`>=`これは便利です。すべての候補が同点の場合、空の選択を決定的に優先します。 

最後に、最適な (k) が見つかった後、分数削減が実行されます。 最初のサンプルの最適値 (156/24) の最大公約数は (24) であるため、出力される結果は次のようになります。`6/1`。 この最終的な削減まですべての算術演算を整数として維持することで、精度エラーが回避され、すべての比較が正確になります。
