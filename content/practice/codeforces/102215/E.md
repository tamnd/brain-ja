 ## 解決策
 ## 問題の理解

 私たちは持っています`n`ライブラリのバージョン。 バージョン`i`数値が包含区間内にあるすべての関数を提供します`[a_i, b_i]`。 Pavel には次のすべての関数が必要です`1`を通して`m`したがって、購入した間隔は整数範囲全体を集合的にカバーする必要があります。`[1, m]`。 

このタスクには 2 つの部分があります。 まず、そのようなバージョンのコレクションがそもそも存在するかどうかを判断する必要があります。 存在する場合は、可能な限り最小のバージョン数を持つコレクションを見つけて、その元のインデックスを出力する必要があります。 

大きな値`m`、 まで`10^9`、すべての関数番号を反復するアルゴリズムを即座に除外します。 便利なサイズパラメータは次のとおりです。`n`、最大でも`200000`、だから、`O(n log n)`アルゴリズムは 2 秒の制限に適しています。 アン`O(n^2)`ペアまたはより大きな組み合わせを検索するには、最大で約`4 * 10^10`制限をはるかに超えた間隔の比較。 

不注意な実装を破ってしまう可能性のある境界例がいくつかあります。 最初の間隔が関数で開始しない場合`1`、取材は不可能です。 例えば、```
2 5
2 5
1 1
```2 番目のバージョンで機能がカバーされているため、実際には可能です。`1`そして最初のカバー`2`を通して`5`。 グローバルに最大の正しいエンドポイントを持つ間隔を単純に選択する貪欲なアルゴリズムでは、`[2,5]`最初にその関数を誤って結論付ける可能性があります`1`が欠けています。 アルゴリズムは、右のエンドポイントを最大化する前に、左の境界を尊重する必要があります。 

本物のギャップがある場合、より直接的な障害が発生します。```
2 5
1 2
4 5
```正しい答えは、`NO`、関数なので`3`は利用できません。 次の間隔が現在カバーされているプレフィックスの 1 つ後の位置で開始する必要がある場合を除き、正しいエンドポイントのみに従って間隔を選択すると、これが正しく検出されません。 

もう 1 つのエッジ ケースは、最初に明らかになった関数から正確に始まる間隔です。```
3 6
1 2
3 4
5 6
```答えは`YES`3つのバージョンがあります。 関数は整数なので、ここまでを説明した後、`2`、から始まる間隔`3`完全に有効です。 条件は`a_i <= covered + 1`、 ない`a_i <= covered`。 

最後に、間隔が重複しているため、局所的に短いように見える選択が最適ではなくなる可能性があります。```
3 8
1 3
2 7
6 8
```最適なソリューションは次のようになります。`[1,3]`そして`[2,7]`別の間隔に達した場合のみ`8`ですが、そうではありません。したがって、この特定の入力では、答えは次のようになります。`NO`。 最後の間隔を次のように変更すると、`[6,8]`と同様の理由で、選択されたすべての間隔が現在カバーされているプレフィックスを拡張する必要がある理由がわかります。 貪欲な選択では、現在のカバレッジを継続できるすべての間隔の中で新しい適切なエンドポイントを常に最大化する必要があります。 

## アプローチ

 ブルート フォース アプローチは、定義に直接従います。 ライブラリのバージョンのすべてのサブセットを試して、結合がカバーしているかどうかを確認できます。`[1,m]`、最小の有効なサブセットを保持します。 考えられるすべての購入決定が明示的に考慮されるため、これは正しいですが、`2^n`サブセット。 と`n = 200000`、それは絶望的に大きいです。 

ブルート フォースをペア、トリプル、またはその他の小さな組み合わせに制限しても、一般的な問題は解決されません。 たとえば、すべてのペアを調べるにはすでに時間がかかります`O(n^2)`、おおよそに達します`2 * 10^10`ペアのとき`n = 200000`。 この問題には、組み合わせを列挙するのではなく、貪欲に選択を行う方法が必要です。 

重要な点は、すでに説明した関数が常に接頭辞を形成していることです。`[1, x]`。 仮定する`x`は現在カバーされている最大の機能です。 このプレフィックスを拡張できる間隔は次の条件を満たす必要があります。`a_i <= x + 1`。 そのようなすべての間隔の中で、最も大きいものを選択します`b_i`正しいエンドポイントが小さいものを選択することよりも悪いことはありません。 どちらの選択をしても、カバレッジの次の部分を開始できますが、間隔が長くなると、少なくとも残りの問題のほとんどが解決されるだけになります。 

これにより、最小限の間隔をカバーするための標準的な貪欲な戦略が得られます。 間隔を左側のエンドポイントで並べ替えます。 から始まる`covered = 0`、左の端点が最大であるすべての間隔をスキャンします。`covered + 1`そして、最も大きな正しいエンドポイントを持つものを覚えておいてください。 スキャンが右端から始まる間隔に達すると、現在使用可能なすべての間隔がすでに考慮されているため、これまでに見つかった最適な間隔にコミットする必要があります。 その最良の間隔が延長しない場合`covered`、ギャップがあり、答えは不可能です。 

ブルート フォースは、カバーされる領域を拡張するすべての方法を明示的に検索するため機能しますが、選択肢が指数関数的に多いため失敗します。 最も遠くに到達する使用可能な間隔のみが重要であるという観察により、検索は 1 つのソートされたスキャンに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(2^n n)`|`O(n)`| 遅すぎる |
 | 最適な貪欲 |`O(n log n)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての間隔を元のバージョン番号とともに保存し、左側のエンドポイントで間隔を並べ替えます。 ソートにより、現在カバーされているプレフィックスを 1 回の前方スキャンで継続できるすべての間隔を処理できます。 
2.セット`covered = 0`。 これは、まだどの関数もカバーされていないことを意味するため、最初に必要な関数は次のとおりです。`1`。 
3. ソートされた間隔をスキャンします。 インターバルがある間、`a_i <= covered + 1`、すでにカバーされているプレフィックスに直接接続できます。 このようなすべての間隔の中で、最も大きい間隔を維持します。`b_i`。 
4. 次のインターバルが開始されるとき`covered + 1`、現在のグループの検討を中止し、記憶されている間隔を購入します。 これは、現在のプレフィックスを拡張できるすべての間隔の中で可能な限り最良の選択です。 
5.アップデート`covered`選択した間隔の右のエンドポイントに を追加し、その元のインデックスを回答に追加します。 その後、まだ考慮されていない最初の間隔からスキャンを続行します。 
6. 使用可能なインターバルが見つからなかった場合、次の機能はカバーできません。 の間にギャップがあります`covered`と残りの間隔なので、正解は`NO`。 
7. もし`covered >= m`、必要な範囲全体`[1,m]`カバーされています。 選択した間隔により有効な解が形成されます。 

貪欲な選択が最適である理由は、交換引数によって把握されます。 現在のプレフィックスが次で終わると仮定します。`covered`。 すべての有効なソリューションは、次の間隔を選択する必要があります。`a_i <= covered + 1`取材を続けるために。 貪欲なアルゴリズムに、次で終了する適格な間隔を選択させます。`G`、最適なソリューションでは、 で終わる適格な間隔が選択されます。`O`。 貪欲な選択により適切なエンドポイントが最大化されるため、`G >= O`。 最適解の最初に選択された間隔を貪欲な間隔に置き換えても、貪欲な間隔は少なくとも同じ範囲に達するため、その後のカバレッジを難しくすることはできません。 すべての拡張でこの引数を繰り返すと、貪欲アルゴリズムが可能な最小数の間隔を使用することがわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    intervals = []
    for idx in range(1, n + 1):
        a, b = map(int, input().split())
        intervals.append((a, b, idx))

    intervals.sort()

    ans = []
    covered = 0
    i = 0

    while covered < m:
        best_right = covered
        best_idx = -1

        while i < n and intervals[i][0] <= covered + 1:
            a, b, idx = intervals[i]

            if b > best_right:
                best_right = b
                best_idx = idx

            i += 1

        if best_idx == -1:
            print("NO")
            return

        ans.append(best_idx)
        covered = best_right

    print("YES")
    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```入力は最初に次のように変換されます。`(left, right, original_index)`トリプル。 ソートによって間隔が格納される順序が変更される一方で、出力では入力に表示されたバージョンを参照する必要があるため、元のインデックスを保持する必要があります。 

ソートされたスキャンでは、`covered + 1`それよりも`covered`。 関数には整数で番号が付けられているため、次の未検出の関数から始まる間隔は現在のプレフィックスに完全に接続されます。 たとえば、`5`によって延長できます`[6,8]`。 

内側のループ内では、`best_right`現在使用可能なすべての間隔の中で最も遠いエンドポイントを記録します。 私たちは前進します`i`間隔が検査されるとすぐに、各間隔は内側のループに 1 回だけ入ります。 次のインターバルが経過したとき`a_i > covered + 1`の場合、間隔は左端で並べ替えられるため、現在のステップで未検査の間隔を使用することはできません。 

の`best_idx == -1`check は、空の使用可能なセットと、すべての使用可能な間隔が次の値を超えずに終了する状況の両方を処理します。`covered`。 すべての間隔があるので、`b_i >= a_i`、満足のいく間隔`a_i <= covered + 1`プレフィックスが またはそれより前に終了する場合にのみ、プレフィックスの拡張に失敗する可能性があります。`covered`。 このような間隔は役に立たないため、延長しない選択肢として扱うのが正しいです。 

Python の整数には任意の精度があるため、上限は`m <= 10^9`オーバーフローの問題は発生しません。

## テストケース

 以下のテスト ヘルパーは、メモリ内入力に対して同じ貪欲なロジックを実行し、特定の有効なセットを必要とする代わりに、返されたバージョン セットを検証します。 この問題ではあらゆる最適な解決策が可能になるため、これは重要です。```python
import sys
import io

def solve_io():
    input = sys.stdin.readline

    n, m = map(int, input().split())
    intervals = []

    for idx in range(1, n + 1):
        a, b = map(int, input().split())
        intervals.append((a, b, idx))

    intervals.sort()

    ans = []
    covered = 0
    i = 0

    while covered < m:
        best_right = covered
        best_idx = -1

        while i < n and intervals[i][0] <= covered + 1:
            a, b, idx = intervals[i]
            if b > best_right:
                best_right = b
                best_idx = idx
            i += 1

        if best_idx == -1:
            print("NO")
            return

        ans.append(best_idx)
        covered = best_right

    print("YES")
    print(len(ans))
    print(*ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve_io()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def check(inp: str, out: str) -> bool:
    lines = out.strip().splitlines()
    first = lines[0]

    data = inp.strip().split()
    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    intervals = []
    for idx in range(1, n + 1):
        a = int(next(it))
        b = int(next(it))
        intervals.append((a, b))

    # A small independent greedy check tells us whether coverage is possible
    intervals_sorted = sorted(intervals)
    covered = 0
    i = 0
    possible = True

    while covered < m:
        best = covered

        while i < n and intervals_sorted[i][0] <= covered + 1:
            best = max(best, intervals_sorted[i][1])
            i += 1

        if best == covered:
            possible = False
            break

        covered = best

    if not possible:
        return first == "NO"

    if first != "YES":
        return False

    k = int(lines[1])
    chosen = list(map(int, lines[2].split()))

    if k != len(chosen) or k == 0:
        return False

    if len(set(chosen)) != k:
        return False

    if any(x < 1 or x > n for x in chosen):
        return False

    chosen_intervals = [intervals[x - 1] for x in chosen]
    chosen_intervals.sort()

    covered = 0
    for a, b in chosen_intervals:
        if a > covered + 1:
            return False
        covered = max(covered, b)

    return covered >= m

 ## 特殊なケース

 ### 最初の使用可能な間隔は関数 1 に到達する必要があります

 検討してください```

2 5
1 1
```最初は`covered = 0`、つまり、条件は次のとおりです。`a_i <= 1`。 バージョン`2`、`[1,1]`は唯一使用可能な間隔であり、適用範囲は次の範囲に拡張されます。`1`。 次に使用可能な間隔は次のとおりです。`[2,5]`で始まります`covered + 1 = 2`、したがって、カバレッジは到達します`5`。 アルゴリズムの出力`YES`2つのバージョンがあります。 最初に接続性を確認せずに、最も大きな正しいエンドポイントの間隔を選択する戦略は、この場合失敗します。 

### 本物のギャップは NO を生み出す必要があります

 のために```

3 5
```最初の間隔が生成します`covered = 2`。 2 番目の間隔は、`a = 3`、満足のいく`a <= covered + 1`。 選択され、適用範囲が拡大される`5`。 答えは`YES`2つのバージョンがあります。 使用する`a <= covered`代わりに、この有効なケースを誤って拒否してしまいます。 

### 適用範囲を拡張しない間隔は選択しないでください

 仮定してください```
3 6
1 3
2 3
4 6
```選択後`[1,3]`、次の間隔`[2,3]`技術的に適格であるため、`2 <= 4`, ただし、カバーされるプレフィックスは増加しません。 アルゴリズムはそれを記録しますが、そのままにしておきます`best_right = 3`エンドポイントが大きくないためです。 それから`[4,6]`も対象となり、最良の選択肢となり、対象範囲を以下に拡大します。`6`。 冗長な`[2,3]`決して購入されません。 

適格性と有用性は異なる概念であるため、この詳細は役に立ちます。 間隔は、延長せずに現在のプレフィックスと重なることがありますが、そのような間隔は進行状況としてカウントされてはなりません。 

### 重複する間隔には最も遠いエンドポイントが必要です

 のために```
4 8
1 3
2 5
4 7
6 8
```最初のステップではのみを考慮します`[1,3]`、 それで`covered`になる`3`。 次のステップで使用できるのは、`[2,5]`、到達`5`。 そこから`[4,7]`使えて届く`7`、 に続く`[6,8]`。 アルゴリズムは 4 つの間隔を選択します。 

代替入力に次のものが含まれている場合`[2,7]`の代わりに`[2,5]`、貪欲なアルゴリズムは、より遠くまで到達するため、その間隔をすぐに優先します。 そうすることで、後で購入する必要がなくなります。 Exchange 引数は、到達可能な最も遠いエンドポイントを選択しても、その後必要な間隔の最小数が増加しないことを保証します。
