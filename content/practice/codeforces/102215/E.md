 ## 解決策
 ## 問題の理解

 (n) 個のライブラリ バージョンがあります。 バージョン (i) は、その番号が包含区間 ([a_i,b_i]) 内にあるすべての関数を提供します。 Pavel には (1) から (m) までのすべての関数が必要なので、選択されたバージョンは集合的に区間全体 ([1,m]) をカバーする必要があります。 

このタスクには 2 つの部分があります。 まず、そのようなバージョンのコレクションが存在するかどうかを判断する必要があります。 存在する場合は、可能な限り最小のバージョンの数を見つけて、そのインデックスを出力する必要があります。 間隔は重複する場合があり、1 つのバージョンは 1 回だけ使用できます。 

(m) の値は (10^9) まで大きくなる可能性があるため、すべての関数番号を個別の配列位置として扱うことは現実的ではありません。 間隔の数は最大でも (2\cdot10^5) です。つまり、(O(n^2)) アルゴリズムでは、最悪の場合でもすでに約 (4\cdot10^{10}) 間隔の演算が必要になります。 2 秒の制限では、(O(n\log n)) または (O(n)) に近い値が必要です。 間隔を 1 回ソートすることは許容されますが、すべてのペアを繰り返し比較することは許容されません。 

妥当なソリューションが失敗する可能性がある境界ケースがいくつかあります。 最初の有用な間隔が関数 (1) で始まらない場合、答えは即座に不可能になります。 例えば、```
2 5
2 5
3 5
```には関数 (1) を含むバージョンがないため、答えは次のようになります。`NO`。 最大の右端点が (m) に達するかどうかを単にチェックするだけのソリューションでは、誤って受け入れられてしまいます。 

2 番目のケースは、中央にギャップがある場合です。```
3 8
1 3
4 5
7 8
```間隔は (1) から (5) までをカバーし、関数 (6) はカバーされないままになります。 正しい出力は次のとおりです`NO`。 切断された間隔ではギャップをカバーできないため、結合の最小エンドポイントと最大エンドポイントをチェックするだけでは不十分です。 

もう 1 つの微妙なケースは、重複する間隔で、最初に利用可能な間隔を取得することが最適ではありません。```
3 8
1 3
1 5
5 8
```最適な答えはバージョン (2) と (3) を使用し、([1,5])、次に ([5,8]) をカバーします。 最初にバージョン (1) を選択すると、プレフィックスが短くなり、追加のバージョンが必要になります。 貪欲なアルゴリズムでは、単に継続できる最初の間隔ではなく、カバーされるプレフィックスを最も遠くまで拡張する間隔を選択する必要があります。 

最後に、1 つの間隔ですでにすべてがカバーされている場合、答えには 1 つのバージョンが含まれている必要があります。```
1 10
1 10
```正しい結果は`YES`、 に続く`1`とバージョン`1`。 (m) に到達した後に 2 番目の間隔を見つけることを要求するアルゴリズムでは、不必要な選択が発生します。 

## アプローチ

 直接的な総当たりアプローチは、(n) バージョンのすべてのサブセットを考慮することです。 各サブセットについて、その区間を収集し、和集合を決定し、その和集合に (1) から (m) までのすべての関数が含まれているかどうかを確認できます。 成功したすべてのサブセットの中で、最小サイズのサブセットを保持します。 これは正しいです。なぜなら、考えられるすべての購入決定は、正確に 1 つのサブセットに対応するからです。 

問題はサブセットの数です。 それらは (2^n) 個あり、すべての (n) 間隔をスキャンしてサブセットをチェックする場合でも、(O(n2^n)) 時間がかかります。 (n=200000) では、これは実際の限界をはるかに超えています。 何らかの方法で各サブセットを一定時間でチェックするアルゴリズムであっても、依然として不可能な (2^{200000}) 状態が存在します。 

この便利な構造は、すべての関数が (1) から (m) までの 1 つの順序付けられた行を形成するという事実から来ています。 すでにいくつかのバージョンを購入しており、(x) までのすべての機能をカバーしているとします。 隙間なくカバレッジを継続するには、次の間隔が (x+1) 以降に開始する必要があります。 この条件を満たすすべての間隔の中で、最大の正しいエンドポイントを持つ間隔を選択することは、他の間隔を選択する場合と少なくとも同じくらい優れています。 1 つのバージョンを使用しているだけで、少なくとも同じレベルまで到達します。 

これにより、貪欲な戦略が得られます。 間隔を左側のエンドポイントで並べ替えます。 何もカバーされていない状態から開始し、左端が最大でも最初のカバーされていない関数であるすべての区間を繰り返し検討します。 これらの間隔のうち、最も右に伸びている間隔を選択します。 現在の適用範囲を拡張するような間隔がない場合、ギャップは避けられず、答えは次のようになります。`NO`。 

この貪欲な選択が最適である理由は、交換議論にあります。 現在カバーされているプレフィックスが (x) で終わると仮定し、貪欲アルゴリズムに (g) で終わる間隔を選択させます。 (x) から続く有効な解は、左端が最大でも (x+1) である区間を選択する必要があります。 その間隔が (r) で終了する場合は、(g\ge r) になります。 貪欲な選択は少なくとも同じ範囲に及ぶため、これを貪欲な間隔に置き換えても、残りのカバレッジを難しくすることはできません。 すべてのステップでこの議論を繰り返すと、可能な最小数の間隔で解決策が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n2^n)) | (O(n)) | 遅すぎる |
 | 仕分け後の欲張り | (O(n\log n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての間隔を元のバージョンのインデックスとともに読み取り、左側のエンドポイントで並べ替えます。 並べ替えにより、間隔を使用できる正確な順序で処理できるようになります。 
2.セット`covered = 0`。 これは、関数 (1) ～`covered`すでに利用可能であることが保証されています。 最初は機能がカバーされていません。 
3. ポインタを維持する`i`ソートされた間隔に。 各反復で、すべての間隔を検査します。`a[i] <= covered + 1`。 このような間隔は、ギャップを残さずに、現在カバーされているプレフィックスに付加できます。 
4. 現在使用可能なすべての間隔の中で、最も大きな正しいエンドポイントを持つ間隔を保持します。 このエンドポイントを呼び出します`best_end`そしてそのバージョンインデックスを覚えておいてください。 後の間隔ではカバレッジがさらに拡張される可能性があるため、最初の使用可能な間隔にはすぐにはコミットしません。 
5. 以降のすべてのインターバルの終了後`covered + 1`検査されているかどうかを確認してください`best_end`より大きいです`covered`。 そうでない場合は、次の関数をカバーできる間隔がないため、完全な範囲をカバーできないため、出力します。`NO`。 
6. それ以外の場合は、記憶されているバージョンを選択し、その元のインデックスを回答に追加して、`covered = best_end`。 次の反復では、このより大きなプレフィックスを拡張しようとします。 
7. すぐに停止してください`covered >= m`。 (1) から (m) までのすべての機能がカバーされ、選択されたバージョンが有効なソリューションを形成します。 
8. 各反復では現在のプレフィックスから最も遠くに到達する間隔が選択されるため、貪欲交換引数は、より少ないバージョンのソリューションが存在できないことを証明します。 選択した間隔は、残りの機能をカバーする能力を低下させることなく、最適な継続の最初の間隔を置き換えることができます。 

### なぜ効果があるのか

 不変条件は、すべての選択の前に、(1) から (1) までのすべての関数が実行されることです。`covered`選択された間隔は、貪欲な選択の下で少なくともそこまで到達するために可能な最小限のバージョンを使用します。 次の選択の前に、カバレッジを継続できるすべての間隔が考慮され、アルゴリズムによって最も適切なエンドポイントを持つものが選択されます。 代替の有効な次の選択肢はそれ以上先には到達しないため、その選択肢を貪欲な間隔で置き換えても、その後に必要な間隔の数を増やすことはできません。 使用可能期間が延長されない場合`covered`の場合、次の関数は残りの間隔ごとに検出されるため、有効な解決策は存在しません。 いつ`covered`(m) に達すると、選択した間隔は、最小限のバージョン数で必要な範囲全体をカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    intervals = []
    for idx in range(1, n + 1):
        a, b = map(int, input().split())
        intervals.append((a, b, idx))

    intervals.sort()

    covered = 0
    i = 0
    answer = []

    while covered < m:
        best_end = covered
        best_idx = -1

        # Every interval starting at or before the next uncovered
        # function can extend the current prefix.
        while i < n and intervals[i][0] <= covered + 1:
            a, b, idx = intervals[i]

            if b > best_end:
                best_end = b
                best_idx = idx

            i += 1

        # No usable interval can extend the covered prefix.
        if best_idx == -1:
            print("NO")
            return

        answer.append(best_idx)
        covered = best_end

    print("YES")
    print(len(answer))
    print(*answer)

if __name__ == "__main__":
    solve()
```タプル`(a, b, idx)`エンドポイントと元のバージョン番号の両方を保存します。 これらのタプルをソートすると、主に次の基準でソートされます。`a`これはまさに貪欲スキャンで必要な順序です。`covered + 1`は、まだ説明されていない最初の関数です。 間隔は、左端がこの値以下の場合に使用できます。 この条件では、重複する間隔も正しく処理されます。 たとえば、次の場合`covered == 5`、から始まる間隔`5`はすでにカバーされている領域と重なっているため使用可能ですが、`7`葉機能`6`発見された。 

内側のループが進みます`i`永久に。 間隔が現在のプレフィックスの候補として考慮されると、再度調べる必要はありません。 その正しいエンドポイントが現時点で最良の拡張ではなかった場合、そのエンドポイントは固定されており、アルゴリズムは現在のフロンティアを拡張する間隔のみに関心があるため、カバーされるプレフィックスが前進した後はより良い候補にはなりません。 

小切手`best_idx == -1`最初のギャップとその後に現れるギャップの両方を検出します。 たとえば、次の場合`covered == 3`残りのすべての間隔は次から始まります`5`以降、機能をカバーできるものはありません`4`, なので継続は不可能でしょう。 

アルゴリズムはすぐに停止します`covered >= m`したがって、(m) を超える間隔は完全に許容されます。 エンドポイントをクリップする必要はありません。 Python の整数にも任意の精度があるため、オーバーフローの心配はありません。

 ### サンプル 1

この例では、間隔が包括的に解釈される理由も示しています。 関数 (2) と関数 (3) は連続しているため、区間 ([1,2]) に続く ([3,4]) にはギャップがありません。 

### サンプル 2

 間隔は```
1: [1,5]
2: [2,7]

```ソート後はすでに表示順になっています。 スキャンは次のように動作します。 

| 反復 | 次の発見 | 使用可能な間隔を検討 | 選択したバージョン | 新しいカバー |

## テストケース

 出力にはバージョン インデックスの最適なセットを含めることができるため、堅牢なテスト ハーネスでは、インデックスの特定の順序を必要とするのではなく、返されたソリューションを検証する必要があります。 次のテストでは、選択されたバージョンの数が指定されたケースに対して最適であるかどうかもチェックしながら、これを実行します。```python
# This test harness reimplements the solution as a callable function.
import sys
import io

def solve_io(data: str) -> str:
    inp = io.StringIO(data)
    out = io.StringIO()

    n, m = map(int, inp.readline().split())
    intervals = []

    for idx in range(1, n + 1):
        a, b = map(int, inp.readline().split())
        intervals.append((a, b, idx))

    intervals.sort()

    covered = 0
    i = 0
    answer = []

    while covered < m:
        best_end = covered
        best_idx = -1

        while i < n and intervals[i][0] <= covered + 1:
            a, b, idx = intervals[i]
            if b > best_end:
                best_end = b
                best_idx = idx
            i += 1

        if best_idx == -1:
            out.write("NO\n")
            return out.getvalue()

        answer.append(best_idx)
        covered = best_end

    out.write("YES\n")
    out.write(str(len(answer)) + "\n")
    out.write(" ".join(map(str, answer)) + "\n")
    return out.getvalue()

def validate(data: str, output: str, expected_k=None):
    lines = output.strip().splitlines()
    assert lines, "empty output"

    if lines[0] == "NO":
        assert expected_k is None
        return

    assert lines[0] == "YES"
    assert len(lines) == 3

    n, m = map(int, data.splitlines()[0].split())
    intervals = [None]

    for line in data.splitlines()[1:]:
        a, b = map(int, line.split())
        intervals.append((a, b))

    k = int(lines[1])
    chosen = list(map(int, lines[2].split()))

    assert len(chosen) == k
    assert len(set(chosen)) == k
    assert all(1 <= x <= n for x in chosen)

    covered = [False] * (m + 1)
    for idx in chosen:
        a, b = intervals[idx]
        for x in range(a, b + 1):
            covered[x] = True

    assert all(covered[1:]), "selected intervals do not cover [1, m]"

    if expected_k is not None:
        assert k == expected_k

# Provided sample 1

5 6
7 8
"""

validate(sample1, out, expected_k=4)

# Provided sample 2

"""

"""

## 特殊なケース

 最初のエッジケースは、明らかにされていない始まりです。 考慮する```
2 5
2 5
3 5
```初期値は`covered = 0`したがって、次に必要な関数は次のとおりです。`1`。 両方の間隔の左端点が次の値を超えています`1`これは、内側のループで使用可能な間隔が検査されないことを意味します。`best_idx`残る`-1`、そしてアルゴリズムは出力します`NO`。 関数 (1) を取得することはすでに不可能であるため、ある区間が関数 (5) に達することは問題ではありません。 

ミドルギャップの場合は、```
3 8
1 3
4 5
7 8
```最初の選択が変更されます`covered`から`0`に`3`。 次に必要な関数は、`4`、 それで`[4,5]`使えるし変わる`covered`に`5`。 次に必要な関数は、`6`、 しかし`[7,8]`始まりが遅すぎる。 どの候補もプレフィックスを拡張できないため、アルゴリズムは次のように出力します。`NO`。 チェックはすべてのフロンティアで実行されるため、切断されたカバレッジが完全なカバレッジと誤認されるのを防ぎます。 

貪欲な選択の場合は、```
3 8
1 3
1 5
5 8
```最初は両方とも`[1,3]`そして`[1,5]`使用可能です。 スキャンでは大きい方のエンドポイントが維持され、バージョン (2) が選択されます。`covered = 5`。 次に必要な関数は、`6`、 それで`[5,8]`が使用可能であり、適用範囲が次のように拡張されます。`8`。 答えは 2 つのバージョンを使用します。 最初の使用可能な間隔を選択する不注意な実装では、`[1,3]`、その後`[5,8]`機能 (4) をカバーできず、間違った追加手順が強制されたり、失敗が誤って報告されたりします。 

1 つのバージョンの場合は、```
1 10
1 10
```最初の反復では、間隔とセットのみが考慮されます。`covered = 10`。 外側のループ条件`covered < m`は false になるため、アルゴリズムは直ちに停止し、選択された 1 つのバージョンを出力します。 これは、別の間隔を無条件に検索するのではなく、フロンティアを更新した後に終了条件をチェックする必要がある理由を示しています。 

最大サイズの境界の場合は、(200000) 個のシングルトン間隔を使用します。`[1,1], [2,2], ..., [200000,200000]`。 選択後`[i,i]`の場合、次に必要な関数は正確に (i+1) であるため、次のシングルトンが使用可能になります。 すべての間隔が 1 回処理され、アルゴリズムは (200,000) 回の選択後に終了します。 これにより、このソリューションは (m) が小さいことに依存せず、意図した (O(n\log n)) 範囲内の最大許容バージョン数を処理できることが確認されます。
