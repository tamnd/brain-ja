 ## 解決策
 ## 問題の理解

 都市のツリーがあります。 各予測について、一部の頂点は赤、一部は青、残りの頂点はすべてニュートラルです。 私たちは気に入った道路を削除することがあります。 それらを削除した後も、すべての赤い都市は 1 つの接続されたコンポーネントに属している必要があり、すべての青い都市は別の接続されたコンポーネントに属している必要があり、赤い都市は青い都市に接続することはできません。 

主な問題は、削除した道路が多くの可能なパスと共有されていることです。 2 つの赤い都市を接続すると、中立都市を通る道路を維持する必要が生じ、それらの中立都市が赤い地域の一部になる可能性があります。 青い都市でも同じことが起こります。 問題は、実際のところ、すべての赤い頂点を含む最小接続サブツリーを、すべての青い頂点を含む最小接続サブツリーから切り離すことができるかどうかです。 公式入力には最大 (200,000) の都市があり、すべての予測にわたる色付きの頂点の総数も最大 (200,000) です。 

(n=200000) の場合、(O(n^2)) アルゴリズムは 2 秒の制限をはるかに超えています。 すべての予測の合計 (r+b) は (200000) にすぎないため、有用な目標は、予測あたり (O((r+b)\log n)) 個の前処理とそれに続く (O((r+b)\log n)) 個の作業です。 色分けされた都市ごとに対数計算を行う余裕はありますが、すべての予測のためにすべて (n) の都市をスキャンする余裕はありません。 

問題の単純な解釈を無効にするいくつかの特殊なケースがあります。 まず、赤と青のシュタイナー サブツリーは、両方の色を持つ都市がない場合でも、中立都市で出会うことができます。 例えば：```

```ここで、赤い都市は (2,4)、青い都市は (5,3) です。 赤色の接続は (2-1) を使用し、青色の接続は (3-1) を使用するため、両方の接続されたリージョンに都市 (1) が含まれます。 正しい答えは、`NO`。 明示的に色付けされた頂点が重なっているかどうかだけをチェックする不用意な解決策では、誤った結果が返されてしまいます。`YES`。 

同じ現象が最初のサンプルでも発生します。 2 番目の予測では、赤い都市は (4,6)、青い都市は (5,7) になります。 色付きの頂点は完全に離れていますが、必要な接続は両方とも都市 (1) を通過するため、答えは次のようになります。`NO`。 

2 番目のエッジ ケースは、1 つの色の必要なサブツリーに他の色の LCA が含まれている場合に発生します。 チェーンを考慮してください```

## アプローチ

 概念的には、直接的な総当たりアプローチが可能です。 すべての道路について、その道路を削除し、結果として得られる 2 つのコンポーネントを検査します。 すべての赤い都市が一方の側にあり、すべての青い都市が反対側にあるかどうか、また、赤と青のグループがそれぞれ接続されているかどうかを確認できます。 (n-1) 個の候補道路があり、完全な検証では (O(n)) 個の都市を検査できるため、1 回の予測に (O(n^2)) 時間がかかる可能性があります。 すべての予測には少なくとも 1 つの赤と 1 つの青の都市が含まれており、色付きの都市の総数は (200000) 以内に制限されるため、予測の数は (100000) まで大きくなる可能性があります。 最悪の場合の構築では、結果的に (10^5\cdot 2\cdot 10^5=2\cdot10^{10}) 回の頂点チェックに達する可能性がありますが、これは決して実現可能とは言えません。 

ツリーの有効な分割は常に接続されたコンポーネント間の切断エッジによって表されるため、ブルート フォースが機能します。 問題は、すべてのエッジを明示的に考慮せずにこれらのコンポーネントを見つけることです。 

有益な観察は、ツリーの内部では 2 つの都市の間には 1 本の経路しかないということです。 その結果、いくつかの赤い都市が接続されたままでなければならない場合、それらの間のすべての経路が強制されます。 それらの結合は、固有の最小接続サブツリーです。 青い都市についても同様です。 これはまさにシュタイナー サブツリーのツリー バージョンであり、指定された端子のセットを含む最小の接続されたサブグラフです。 

必要な 2 つのサブツリーが頂点で結合していない場合、各サブツリー内のすべてのエッジを保持し、ツリーの残りの部分からそれらを分離するエッジをカットできます。 赤い都市は接続されたままで、青い都市は接続されたままで、2 つのグループは相互に到達できません。 2 つのサブツリーが交差する場合、道路を削除しても役に立ちません。すべての赤い都市を含むすべての接続コンポーネントには赤いサブツリーが含まれ、すべての青い都市を含むすべての接続コンポーネントには青いサブツリーが含まれる必要があるためです。 

次に、都市 (1) にツリーをルートします。 頂点の任意のセットについて、その LCA をそのセット内のすべての頂点の最も低い共通の祖先とします。 (A) がすべての赤い都市の LCA である場合、すべての赤い頂点は (A) のサブツリー内にあります。 同様に、(B) がすべての青い都市の LCA である場合、すべての青い頂点は (B) のサブツリー内にあります。 

したがって、構造上の可能性は 2 つだけです。 (A) も (B) も他方の祖先ではない場合、それらのルートサブツリーは互いに素であるため、必要な 2 つのサブツリーは素であり、答えは次のようになります。`YES`。 (A) が (B) の祖先である場合、青色の必須サブツリーは (B) のサブツリー内にあります。 赤の必須サブツリーがそれと交差できる唯一の方法は、何らかの赤い都市自体が (B) のサブツリーの内側に存在することです。 対称の議論は、(B) が (A) の祖先である場合に適用されます。 

これにより、この問題の既知の解決策で使用されているのと同じ LCA ベースの特性評価が得られます。 

バイナリ リフティングを使用して、(O(\log n)) の 2 つの頂点の LCA を求めることができます。 次に、色クラス全体の LCA が段階的に取得されます。最初の赤い都市から開始して、現在の LCA をその都市と次の赤い都市の LCA に繰り返し置き換えます。 同じプロセスで青色の LCA が得られます。 すべての予測にわたる色付きの都市の合計数は最大 (200,000) であるため、これは十分な速度です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(qn^2)) を直接形式で | (O(n)) | 遅すぎる |
 | 最適 | (O(n\log n + S\log n))、ここで (S\le 200000) は色付きの都市の総数です | (O(n\log n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 都市 (1) でツリーをルートし、すべての都市の深さと直接の親を計算します。 親関係により、LCA クエリに必要な構造が得られます。 
2. バイナリリフティングテーブルを構築します。`up[k][v]`(v) の (2^k) 個上のエッジにある祖先を格納します。 これにより、対数的に多くの操作で大きな距離を上に移動できます。 
3. 予測ごとに、すべての赤い都市を読み取り、それらの共通 LCA を増分的に計算します。 最初の赤い都市から始めます`red_lca`。 後続の赤い都市 (x) ごとに、次のように設定します。`red_lca = LCA(red_lca, x)`。 結果として得られる頂点は、すべての赤い都市の祖先となる最下位の頂点です。 
4. すべての青い都市に対して同じことを行い、次の情報を取得します。`blue_lca`。 
5. コンピューティング`common = LCA(red_lca, blue_lca)`。 もし`common`が両方の LCA と異なる場合、どちらのカラー LCA ももう一方の祖先ではありません。 2 つの必要な領域は、次の異なる子サブツリーにあります。`common`ので、出力します`YES`。 
6. もし`red_lca == common`の場合、赤色 LCA は青色 LCA の祖先になります。 青色の必須サブツリーは、ルートが次のサブツリーに含まれています。`blue_lca`。 赤い都市 (x) をす​​べてチェックします。 もし`LCA(x, blue_lca) == blue_lca`の場合、(x) は blue-LCA サブツリー内にあります。 赤いサブツリーは (x) を他の赤い都市に接続する必要があるため、到達します。`blue_lca`、青色の required サブツリーに属します。 領域が交差するため、出力`NO`。 そこに赤い都市がない場合は、出力`YES`。 
7. 残りのケースは、`blue_lca == common`したがって、青の LCA は赤の LCA の祖先です。 すべての青い都市に対して対称テストを実行し、次のことを確認します。`LCA(x, red_lca) == red_lca`。 交差点が与えます`NO`; それ以外の場合、必要な 2 つの領域は互いに素であり、答えは次のようになります。`YES`。 

アルゴリズムの背後にある不変条件は次のとおりです。`red_lca`そして`blue_lca`それぞれの必要な接続されたサブツリーの強制ルートを常に記述します。 2 つの LCA が別々のルートサブツリーにある場合、必要な領域が一致できません。 一方の LCA に他方の LCA が含まれている場合、交差は子孫 LCA のサブツリー内でのみ発生し、その交差は反対の色に終端があるときに正確に存在します。 これはあらゆる可能な配置を特徴付けるものであるため、`YES`実現可能な一連の道路カットとすべての道路カットに対応します。`NO`避けられない交差点に相当します。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve(reader=None):
    input = reader if reader is not None else sys.stdin.readline

    n = int(input())

    graph = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        graph[u].append(v)
        graph[v].append(u)

    # Root the tree at 1.
    parent = array('i', [0]) * (n + 1)
    depth = array('i', [0]) * (n + 1)

    parent[1] = 1
    stack = [1]

    while stack:
        u = stack.pop()
        pu = parent[u]
        du = depth[u] + 1

        for v in graph[u]:
            if v == pu:
                continue
            parent[v] = u
            depth[v] = du
            stack.append(v)

    # Binary lifting table.
    log = n.bit_length()
    up = [parent]

    for _ in range(1, log):
        prev = up[-1]
        cur = array('i', (prev[prev[v]] for v in range(n + 1)))
        up.append(cur)

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a

        diff = depth[a] - depth[b]
        bit = 0

        while diff:
            if diff & 1:
                a = up[bit][a]
            diff >>= 1
            bit += 1

        if a == b:
            return a

        for k in range(log - 1, -1, -1):
            ua = up[k][a]
            ub = up[k][b]
            if ua != ub:
                a = ua
                b = ub

        return up[0][a]

    q = int(input())
    answers = []

    for _ in range(q):
        parts = list(map(int, input().split()))
        r, b = parts[0], parts[1]

        red = parts[2:2 + r]
        blue = parts[2 + r:2 + r + b]

        red_lca = red[0]
        for x in red[1:]:
            red_lca = lca(red_lca, x)

        blue_lca = blue[0]
        for x in blue[1:]:
            blue_lca = lca(blue_lca, x)

        common = lca(red_lca, blue_lca)

        if red_lca != common and blue_lca != common:
            answers.append("YES")
            continue

        if red_lca == common:
            possible = True

            for x in red:
                if lca(x, blue_lca) == blue_lca:
                    possible = False
                    break

            answers.append("YES" if possible else "NO")
        else:
            possible = True

            for x in blue:
                if lca(x, red_lca) == red_lca:
                    possible = False
                    break

            answers.append("YES" if possible else "NO")

    return "\n".join(answers)

if __name__ == "__main__":
    sys.stdout.write(solve())
```隣接リストには元のツリーが保存されます。 ツリーは Python の通常の再帰の深さを超える長さ (200,000) のチェーンになる可能性があるため、DFS は再帰的ではなく反復的です。 

の`parent`array は、Python リストではなく、コンパクトな整数配列です。 すべてのバイナリ リフティング レベルに同じ表現が使用されます。 (256) MB のメモリ制限の下では、(200,000) 整数の Python リストはパックされた整数配列よりも大幅に多くのオーバーヘッドを伴うため、これは重要です。 パイソンの`array`type は、固定サイズの数値要素をコンパクトに格納します。 

ルートはそれ自体を親として持ちます。 したがって、ルートを超える繰り返しジャンプは頂点 (1) に残ります。これにより、LCA の実装が単純になり、ゼロ祖先に対する特別な処理が回避されます。 

LCA 関数は、最初に深さの差のバイナリ表現を使用して深さを均等化します。 その後、2 の最大累乗から下方向へのジャンプを考慮します。 対応する 2 つの祖先が異なる場合、LCA は厳密にそれらの祖先より上にあるため、両方の頂点は安全に上にジャンプできます。 より大きなジャンプが不可能な場合、その直接の親は LCA になります。 

クエリごとに、赤と青のリストが入力行から直接スライスされます。 この制約により、完全なクエリが 1 つの入力行に収まることが保証されます。 祖先の場合、反対色のすべての端子を検査する必要があるため、リストは保持されます。 

Python では整数オーバーフローの問題はありません。 頂点識別子、深さ、およびテーブル エントリとして使用される最大値は最大 (200000) です。 

の使用`array('i')`また、(O(n\log n)) バイナリ リフティング テーブルをコンパクトに保ちます。 テーブルにはおよそ (200000\cdot18) の整数エントリがあり、通常の実装ではパックされた各整数が 4 バイトを占めるため、テーブル自体は数百メガバイトの Python 整数オブジェクトではなく、わずか約 15 メガバイトです。

## 特殊なケース

 単一の赤い都市と単一の青い都市の場合、必要な各サブツリーはその色付きの頂点のみで構成されます。 2 つの都市識別子は別個であるため、2 つのサブツリーは交差できません。 アルゴリズムは次のようになります`red_lca = red`、`blue_lca = blue`、そして彼らのLCAはそのうちの1つであるため、祖先のケースに到達します。 反対色の都市はその独自の頂点のサブツリー内に存在できないため、包含チェックは失敗します。 答えは`YES`。 

中立頂点での交差点については、次のことを考慮します。```
5
1 2
1 3
2 4
3 5
1
2 2 4 5 3
```赤い都市は (2,4) であるため、赤い LCA は (2) です。 青い都市は (5,3) であるため、青い LCA は (3) です。 共通の LCA は (1) であり、両方とは異なります。 一見、これは分離されたケースのように見えますが、赤色の必須サブツリーは (2-4) であり、青色の必須サブツリーは (3-5) だけです。 実際には交わらないので、正解は`YES`この特定の入力に対して。 

本物の中立交差点を実行するには、次を使用します。```
5
1 2
1 3
2 4
3 5
1
2 2 5 4 3
```赤い都市は (5,4) であるため、LCA は (1) になります。 青い都市 (3,4) は個別の色に違反するため、代わりに、きれいな例として赤 (4,6) と青 (5,7) を使用したサンプル構造を示します。```
7
1 2
1 3
2 4
2 5
3 6
3 7
1
2 2 4 6 5 7
```赤の LCA は (1)、青の LCA は (1) で、アルゴリズムはすぐに祖先ケースに入ります。 赤の都市 (4) を青の LCA (1) と照合すると、次のようになります。`LCA(4,1)=1`したがって、交差点が検出され、出力は次のようになります。`NO`。 

まだ分​​離可能な祖先関係については、次のことを考慮してください。```
5
1 2
2 3
3 4
4 5
1

```赤の LCA は (1)、青の LCA は (5)、共通 LCA は (1) です。 アルゴリズムは、いずれかの赤い都市が (5) のサブツリーにあるかどうかをチェックします。 どちらでもないので返されます`YES`。 最先端 (4-5) は、赤い都市を接続したまま、青い都市を分離します。 

逆の場合は、```
5

```赤の LCA は (1)、青の LCA は (3)、共通 LCA は (1) です。 赤い都市 (5) は (3) をルートとするサブツリーにあり、これは次のように検出されます。`LCA(5,3) == 3`。 赤い接続は青い都市 (3) を通過する必要があるため、アルゴリズムは次の値を返します。`NO`。
