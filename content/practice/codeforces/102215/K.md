 ## 解決策
 ## 問題の理解

 長さ (n) の文字列があり、各文字は次のいずれかになります。`R`、`G`、 または`B`。 文字列はデッキを上から下まで説明します。 カードを 1 枚ずつ 2 つの山に分けてもよいでしょう。 新しいカードはすべて、選択した山の一番上に置かれるため、各山の内部の順序は、元のデッキにカードが出現した順序とは逆になります。 最後に、一方の山全体がもう一方の山の上に配置されるため、最終的なデッキは、元の文字列の 2 つの反転したサブシーケンスを連結したものになります。 

目標は、最終的なデッキに各色のすべてのカードを含めることができるかどうかを決定することです。 3 つのカラー ブロックは任意の順序で表示できます。 公式問題では (1 \le n \le 1000) が許可されています。 

わずか 1,000 文字という制限は、カードを配布するすべての方法を網羅的に列挙することを不可能にするのに十分な大きさです。 2 つの山には (2^n) 個のカードの割り当てがあるため、(O(n)) 時間で 1 つの割り当てをチェックするだけでも (O(n2^n)) 回の操作が行われます。 (n=1000) の場合、これは 2 秒の制限で処理できる範囲をはるかに超えています。 代わりに、解決策では、色が 3 つしかなく、最終的なカラー ブロックの可能な順序が 6 つしかないという事実を利用する必要があります。 

不注意な実装を騙す可能性のある境界ケースがいくつかあります。 のような 1 枚のカードのデッキ`R`戻らなければなりません`YES`すでにソートされており、意味のある分割は必要ないためです。 3 色すべてが発生することを前提とした実装は、ここで失敗する可能性があります。 のようなデッキ`RGB`も戻らなければなりません`YES`たとえすべての色が一度だけ出現したとしても。 すべての色の繰り返しの出現を必要とするソリューションは、その色を誤って拒否してしまいます。 

存在しない色にも特別な処理が必要です。 例えば、`RRR`すでにソートされているので、答えは`YES`。 順序付け候補の最初または最後の色として選択された色が出現しない場合、境界として使用する実際の最初または最後の出現はありません。 たとえば、存在しない最初の出現を位置 (n) として扱うと、そのサイドに属すべきではないカードが誤ってカウントされる可能性があります。 以下の実装では、存在しない色を明示的に処理します。 

## アプローチ

 直接総当たりソリューションでは、すべてのカードを 2 つの山のいずれかに個別に割り当てることができます。 (2^n) の割り当てごとに、2 つの山を構築し、その内部順序を逆にし、可能な両方の順序で連結し、結果のデッキが最大 3 つのカラー ブロックで構成されているかどうかを確認できます。 これは正しいです。すべての正当な操作シーケンスが、まさに 2 つの山への分割に対応しているからです。 ただし、(2^n) 個のパーティションがあり、各チェックには (O(n)) がかかり、(O(n2^n)) 個の作業が行われます。 (n=1000) では、割り当ての数だけでも約 (10^{301}) となるため、このアプローチはリモートでは実行できません。 

有益な観察は、最終的なデッキには 3 つのカラー ブロックしか含まれていないということです。 3 つの異なる色 (A、B、C) をある順序で選択するとします。 2 つの山を反転して連結した結果が (C^*B^_A^_) になるように構築します。これはすでに有効なソート済みデッキです。 (A、B、C) の選択肢は 6 つだけです。 

固定の選択肢 (A、B、C) の場合、すべての (A) カードを最初の山に置き、すべての (C) カードを 2 番目の山に置きます。 残りの (B) カードには有効な場所が 2 つだけあります。 最初のカード (C) より前に出現したカード (B) は、2 番目の山に入れることができます。 最後の (A) の後に出現する (B) カードは、最初の山に入れることができます。 

正確になぜこれらのポジションなのでしょうか？ 最初の山は、元のデッキ順序で読み取ると、次の形式になります。 

[
 A A \ldots A B B \ldots B.
 】

 反転後はこうなります

 [
 B B \ldots B A A \ldots A.
 】

 2 番目の山は元の順序です

 [
 B B \ldots B C C \ldots C、
 】

 したがって、反転後は次のようになります

 [
 C C \ldots C B B \ldots B.
 】

 2番目の山を最初の山の上に置くと、

 [
 C C \ldots C B B \ldots B A A \ldots A、
 】

 それは並べ替えられています。 

唯一の問題は、同じカードを 2 回割り当てることなく、すべての (B) カードをこれら 2 つの山のいずれかに割り当てることができるかどうかです。 最初 (C) の前の A (B) は 2 番目の山に属し、最後の (A) の後の (B) は最初の山に属します。 最初の (C) と最後の (A) の間に何らかの (B) が存在する場合、この構造では配置できません。 2 つの領域が重なっている場合、(B) も 2 回カウントされる場合があります。 したがって、2 つの山に割り当てられたカードの数が (n) のときに、構築は正確に成功します。 

この特徴付けは、考えられるすべての有効な並べ替えにも十分です。 最終的な色の順序が (X,Y,Z) の場合、(A=Z)、(B=Y)、(C=X) となります。 2 つの最後のパイルの間のカットは、中央のカラー ブロック内のどこにでも発生する可能性があります。 2 つのピースを反転すると、最初のピースに属する (Y) 枚のカードが元のデッキの (X) より前に配置され、残りの (Y) 枚のカードが (Z) の後に配置されます。これは、まさに上記の構築でテストされた構造です。 6 つの順列をすべて列挙すると、考えられるすべての最終的な色の順序がカバーされます。 この問題に対する公開されたソリューションでも、同じ構造的な考え方が使用されています。

 ## アルゴリズムのチュートリアル

 1. それぞれの回数を数えます。`R`、`G`、 そして`B`が発生します。 また、各色の最初と最後の出現も記録します。 これらの値を使用すると、文字列を繰り返し検索することなく、すべての候補の順序をテストできます。 
2. 3 色の 6 つの順列 ((A,B,C)) をすべて列挙します。 (A) を最終的に並べ替えたデッキの一番下に配置される色、(C) を一番上に配置される色、(B) を中央の色として解釈します。 
3. すべての (A) カードを山 1 に置き、すべての (C) カードを山 2 に置きます。 これにより、外側の 2 つのカラー ブロックが固定されます。 
4. 最初の (C) カードの前に (B) カードを数えます。 これらのカードは安全にパイル 2 に入れることができます。 その山を反転した後、すべての (C) カードの後に​​表示されます。 
5. 最後の (A) カードの後の (B) カードを数えます。 これらのカードは安全にパイル 1 に入れることができます。 その山を反転した後、それらはすべての (A) カードの前に表示されます。 
6. (A) カード、(C) カード、および使用可能な 2 つのグループのカード (B) の数を加算します。 この合計が正確に (n) である場合、すべてのカードが 1 回だけ割り当てられているため、選択した順序によって有効な並べ替えが行われます。 合計が (n) より小さい場合、一部 (B) のカードが禁止された中央領域にあります。 (n) より大きい場合、一部の (B) カードは両側でカウントされます。 どちらの場合も、この順列は機能しないことを意味します。 
7. 6 つの順列のいずれかが成功した場合、出力します。`YES`。 どれも成功しなかった場合は、印刷します`NO`。 

色が発生しない場合、境界は意図的に解釈する必要があります。 (C) が存在しない場合、最初の (C) は存在しないため、(B) のカードは最初の (C) より前にあるものとして分類できません。 (A) が存在しない場合、最後の (A) は存在しないため、すべての (B) カードは最後の (A) の後にあります。 コードはこれら 2 つのケースを直接次のように表します。`first_c = n`そして`last_a = -1`、その後、対応するカウントを明示的に処理します。 

### なぜ効果があるのか

 固定順列 (A、B、C) の場合、構築では、すべての (A) カードのシーケンスをパイル 1 に割り当て、最後 (A) の後に選択された (B) カードが続きます。 その反転は、結果的に (B) カードのブロックの後に (A) カードのブロックが続くことになります。 2 番目の山には、最初の (C) カードの前に選択された (B) カードが含まれ、その後にすべての (C) カードが続きます。 そのリバーサルは、(C) カードのブロックに続いて (B) カードのブロックです。 したがって、パイル 2 をパイル 1 と連結すると (C^*B^_A^_) が生成されます。 

すべての元のカードがこれら 2 つの山のいずれかに 1 回だけ属する場合、カウントされる合計は正確に (n) に等しくなります。 したがって、成功した順列はすべて有効な並べ替えを生成します。 逆に、有効な並べ替えには 3 つのカラー ブロックと、最終的な 2 つの山の間の境界があります。 これらのブロックの逆順で (A、B、C) を選択すると、2 つの山に割り当てられたカードが、アルゴリズムによってテストされた境界構造と正確に一致するようになります。 6 つの順列すべてがチェックされるため、すべての有効な並べ替えが表現されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from itertools import permutations

def solve(s: str) -> str:
    n = len(s)
    colors = "RGB"

    count = {c: 0 for c in colors}
    first = {c: n for c in colors}
    last = {c: -1 for c in colors}

    for i, ch in enumerate(s):
        count[ch] += 1
        first[ch] = min(first[ch], i)
        last[ch] = i

    # Prefix counts let us count how many B cards occur
    # before an arbitrary position in O(1).
    prefix = {c: [0] * (n + 1) for c in colors}

    for i, ch in enumerate(s):
        for c in colors:
            prefix[c][i + 1] = prefix[c][i]
        prefix[ch][i + 1] += 1

    for a, b, c in permutations(colors):
        taken = count[a] + count[c]

        # B cards before the first C.
        if first[c] != n:
            taken += prefix[b][first[c]]

        # B cards after the last A.
        if last[a] != -1:
            taken += count[b] - prefix[b][last[a] + 1]
        else:
            # No A exists, so every B is after the last A.
            taken += count[b]

        if taken == n:
            return "YES"

    return "NO"

def main():
    s = input().strip()
    print(solve(s))

if __name__ == "__main__":
    main()
```最初のループは、すべての色の頻度と境界を記録します。`first[c]`に初期化されます`n`、 その間`last[a]`に初期化されます`-1`、そのため、有効なインデックス範囲外の特別なセンチネル値がなくても、存在しない色を検出できます。 

プレフィックス カウントの配列により、2 つの (B) 領域の測定が容易になります。`prefix[b][first[c]]`位置を厳密にカウントします。`first[c]`、これはまさに最初の領域に必要なものです。 他の地域については、`count[b] - prefix[b][last[a] + 1]`厳密にその後のポジションをカウントします`last[a]`。 の`+1`プレフィックス配列はハーフオープン範囲を使用するため、これが必要です。 

Python では整数オーバーフローの懸念はなく、すべてのカウントは最大 1000 です。6 つの順列は次のように生成されます。`itertools.permutations`したがって、3 色のすべての可能な順序が 1 回だけ検査されます。 

この実装では、追加の (3(n+1)) プレフィックス カウント構造体が 1 つ使用されます。 これは (n \le 1000) の場合は小さく、各順列の実際のテストを定数時間に保ちます。

| 順列 | カウントA | カウントC | 最初の C の前に B | 最後の A の後の B | 撮影 | 結果 |

 ## 特殊なケース

 1枚カード入力の場合`R`、アルゴリズムはすぐに以下を含む順列を考慮します。`R`。 もし`R`は (A) として選択されます。`count[A] = 1`、他の色のカウントはゼロです。 追加のカードは必要ありませんので、`taken = 1 = n`そして答えは`YES`。 アルゴリズムは、3 色すべてが存在するとは決して想定しません。 

のために`GGGGGG`、(A=G)を選択します。 すべてのカードはすでに (A) で表される外側のブロックの一部になっているため、`count[A] = 6`合計は正確に (n) になります。 欠落している色 (C) は、存在しない最初の出現の前にカードを提供しないため、欠落している色によって偶発的なカウントが発生することはありません。 

のために`BGR`、(A=R、B=G、C=B) を考えます。 最初`B`インデックス 0 と最後にあります`R`はインデックス 2 にあります。`G`最初の前のカード`B`そしていいえ`G`最後以降のカード`R`したがって、この特定の置換は成功しません。 すでにソートされた順序に対応して、別の順列が行われます。`B-G-R`。 この例は、1 つの色の順序を固定するのではなく、6 つの順列すべてをチェックする必要がある理由を示しています。 

のために`RGBRGBRGB`、すべての候補の順序は、必要な構造の下でどちらの山にも属さない領域に中央の色のカードを少なくとも 1 枚残します。 (A=R,B=G,C=B) の場合、最初の`B`インデックス 2 と最後に発生します`R`インデックス 6 にあります。1 つだけ`G`最初の前に発生します`B`、最後の後には何も発生しません`R`、3つありますが、`G`カードの合計。 したがって、9 枚のカードのうち 7 枚だけが考慮されます。 他の 5 つの色の順序は対称的に失敗し、必要な結果が得られます。`NO`。
