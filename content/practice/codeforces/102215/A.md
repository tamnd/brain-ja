 ## 解決策
 ## 問題の理解

 ダンジョンは (n+1) 個の部屋が直線的につながっているため、通過するたびに 1 つ右に移動するだけです。 通路(i)は(a_i)で表される。 その絶対値は、使用するパスの色です。 正の値は通過チェックが通過することを意味し、負の値は常に通過できるが、その色が永久に無効になることを意味します。 

(0) から (n-1) までのすべての開始部屋に対する答えが必要です。 答えは、最初の通路を通過する前に、何回通過できるかです。 成功したすべての通路は 1 つの新しい部屋に入るので、これはまさに到達した新しい部屋の数でもあります。 公式問題ページに記載されているように、入力は (n) から (500000) までに制限されます。 

重要な相互作用は、同じ色のネガティブな出現と、その後のポジティブな出現との間です。 負のパス (-c) を通過すると、パス (c) は無効になります。 それ以降 (+c) は不可能になります。 否定的な経過自体が私たちを止めることはありません。 

例えば、```
3
1 -1 1
```答えがあります```
2 2 1
```部屋 (0) から始めて、(+1)、次に (-1) と交差し、最後の (+1) がブロックされているため、2 つの通路が交差します。 部屋 (1) から開始して、交差 (-1)、色 (1) を無効にし、すぐに最後の通路でブロックされるため、交差する通路は 1 つだけです。 開始位置を考慮せずに、同じ色が後のどこかに現れるかどうかだけをチェックする不注意な解決策では、最初の否定的なパッセージをその後に発生する開始に誤って適用する可能性があります。 

もう 1 つのエッジ ケースは、同じ色のその後のポジティブな出現がないネガティブな通過です。```
3
-1 -2 -3
```答えは```
3 2 1
```すべてのネガティブなパスはいつでも通過でき、無効化されたパスはその後チェックされることはありません。 すべての否定的な文章を停止点の可能性があるものとして扱うと、誤って小さな答えが生成されてしまいます。 

否定的な文章を繰り返すことも重要です。 考慮する```
3
1 -1 -1
```答えは```
3 2 1
```部屋 (0) から開始すると、最初のパッセージはプラスで成功し、後のパッセージは両方ともマイナスであるため、3 つのパッセージすべてが交差します。 すべての無効化が最終的に失敗を引き起こすと仮定するメソッドは、2 番目の部分で誤って停止してしまいます。 

ブルート フォース シミュレーションは実装が簡単ですが、(n=500000) の制限により除外されます。 (O(n^2)) アルゴリズムでは、最悪のケースではおよそ (n(n+1)/2) が必要となり、これは約 (1.25\times10^{11}) 回の通過チェックに相当します。 これは、コンテストの制限時間である 2 秒をはるかに超えています。 

## アプローチ

 直接的なアプローチは、すべての部屋から開始して、独立して歩行をシミュレートすることです。 現在有効な色を維持し、左から右に移動し、否定的なパッセージに遭遇するたびに色を無効にし、肯定的なパッセージで無効な色が要求されたときに停止します。 これはダンジョンのルールを正確に再現しているので正解です。 

問題は、連続する開始位置がほぼ同じサフィックスを繰り返し検査することです。 たとえば、すべてのパッセージが正の場合、部屋 (0) での開始ではすべて (n) のパッセージが検査され、部屋 (1) での開始では (n-1) が検査されます。 合計作業量は (n(n+1)/2) で、所要時間は (O(n^2)) です。 

有用な観察は、パッセージで私たちを止めることができる唯一の方法は、出発点から、否定的なパッセージ (-c) が先行している肯定的なパッセージ (+c) であるということです。 開始ごとに現在の有効なパスのセットをシミュレートする代わりに、配列を逆方向に処理できます。 

右から左にスキャンしながら、すべての色について、その色の右への最も近いポジティブなパスを思い出すことができます。 私たちが否定的なパッセージ (-c) に遭遇したとき、その記憶されたポジティブなパッセージはまさに、この否定的なパッセージのために不可能になる最初の将来のパッセージです。 したがって、この否定的な通過は、開始時または開始前に移動できる距離に上限を作成します。 

さまざまな色からそのような境界がいくつか存在する可能性があります。 最も早い停止点のみを考慮するため、それらはすべて、許容される最小の最終通過インデックスを含む 1 つの変数で表すことができます。 逆スキャンにより、その変数を 1 回更新し、それより前の開始位置ごとに再利用できます。 

これは、この問題の標準的な解決策の背後にあるのと同じ逆の繰り返しです。

 ## アルゴリズムのチュートリアル

 1. パッセージには 1 から始まるインデックスを使用します。 (dp[i]) を、通路 (i) の直前から開始した場合に横切ることができる通路の数として定義します。 部屋 (s) に必要な答えは (dp[s+1]) となります。 
2. (n) から (1) までのパッセージをスキャンします。 維持する`next_pos[c]`、逆スキャン中にすでに確認されている色の最も近いポジティブパス (c)。 そのような通路が存在しない場合、その値はゼロです。 
3. メンテナンスも行う`limit`、これまでに発見されたすべての制限の中でまだ通過できる最小の通過インデックス。 初期状態では制限がないので設定します。`limit = n + 1`。 
4. (a_i>0) の場合、通路 (i) に到着すると常に横断可能です。これは、その通路を無効にできるすべての制限が現在のスキャンに対して左側になければならないためです。 それを越えた後、残りの旅はまさに (dp[i+1]) で表される状況になります。 このように設定
 [
 dp[i]=dp[i+1]+1。 
】
 それから保管してください`next_pos[a_i] = i`なぜなら、これは、以前のすべての位置の右側にある、その色の最も近いポジティブな通過だからです。 
5. (a_i<0) の場合、通路 (i) 自体が私たちを妨げることはありません。 カラーを無効にします(-a_i)。 その色の右側に肯定的な通過がない場合、この無効化はまったく問題になりません。 
[
 dp[i]=dp[i+1]+1。 
】
 6. 肯定的なパッセージ (p=\text{next_pos}[-a_i]) が存在する場合、パッセージ (i) を横切るとパッセージ (p) が不可能になります。 したがって、通路 (i) 以降から通路 (p-1) を越えることはできません。 アップデート
 [
 \text{制限}=\min(\text{制限},p-1)。 
】
 現在の開始点は通路 (i,i+1,\ldots,\text{limit}) を横切る可能性があるため、
 [
 dp[i]=\text{制限}-i+1。 
】
 の`limit`以前の否定的なパッセージがすでにさらに小さな停止点を課している可能性があるため、変数が必要です。 
7. すべてのパッセージを処理した後、(dp[1],dp[2],\ldots,dp[n]) を出力します。 これらは開始値 (0,1,\ldots,n-1) に直接対応します。 

### なぜ効果があるのか

 不変条件は、サフィックス (i,\ldots,n) を処理した後、`next_pos[c]`は、その接尾辞内の色 (c) の最初の正の部分です。`limit`は、サフィックスですでに処理されている否定的なパッセージによって禁止されている最初のパッセージです。 正のパッセージは、それが現在の最初のパッセージである場合に通過できるため、その答えは 1 に残りの接尾辞の答えを加えたものになります。 ネガティブな通路はいつでも横切ることができますが、その色が将来ポジティブな出来事を起こす場合、そのポジティブな通路は禁止され、まさに新しい境界が与えられます。`p - 1`。 最小値を選択すると、すべての色からの最も古い制限が保存されます。 したがって、計算されるすべての (dp[i]) は、その位置から通過できる連続する通路の最大数となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [0] + list(map(int, input().split()))

    # next_pos[c] = nearest positive passage of color c
    # to the right of the current position.
    next_pos = [0] * (n + 1)

    # dp[i] = number of passages that can be crossed
    # starting immediately before passage i.
    dp = [0] * (n + 2)

    # No restriction exists initially.
    limit = n + 1

    for i in range(n, 0, -1):
        x = a[i]

        if x > 0:
            # A positive passage can always be crossed at this point.
            dp[i] = dp[i + 1] + 1

            # It becomes the closest positive occurrence of this color
            # for all positions to its left.
            next_pos[x] = i

        else:
            color = -x
            p = next_pos[color]

            if p == 0:
                # No future positive passage uses this color,
                # so invalidating it has no effect.
                dp[i] = dp[i + 1] + 1
            else:
                # Passage p will be blocked after crossing i.
                limit = min(limit, p - 1)

                # We can cross from i through limit.
                dp[i] = limit - i + 1

    print(*dp[1:n + 1])

if __name__ == "__main__":
    solve()
```入力配列はインデックス (0) にダミー 0 を付けて保存されます。これにより、パッセージ番号が 1 ベースの数学的インデックスと直接一致します。 これにより、考えられるいくつかの off-by-one 変換が削除されます。`next_pos`可能なパス カラーごとに 1 つのエントリがあります。 色は最大 (n) であることが保証されているため、単純なリストの方が辞書よりも高速で簡単です。 

逆ループは計算します`dp[i]`さらに左に移動する前に。 正の値の場合、への代入`next_pos`計算後に必ず発生する`dp[i]`なぜなら、現在のポジティブなパッセージはそれ自体の右側のパッセージではないからです。 負の値の場合、関連する正の値がすでに処理されている必要があるため、検索は更新の前に行われます。 

表現`limit - i + 1`パッセージも含めてカウントします。 もし`limit == i`、ちょうど 1 つの通路を横切ることができます。 もし`limit == n`、(i) から (n) までのすべての通路を横切ることができます。 初期化`limit = n + 1`は制限がないことを表します。 

Python の整数は、これらの値ではオーバーフローしません。 この実装はパッセージごとに一定量の作業のみを実行します。これが、実装が処理できる主な理由です (n=500000)。

 ## 特殊なケース

 即時無効の場合は、```
3
2 -2 2
```逆スキャンでは最初に最終 (+2) が参照されるため、`next_pos[2] = 3`。 通路 2 の値は (-2) なので、これを越えると通路 3 は不可能になります。 制限は(3-1=2)、(dp[2]=1)となります。 通路 1 が処理されると、それは正であり、通過できるため、(dp[1]=dp[2]+1=2) となります。 出力は`2 1 1`。 の`p - 1`計算により、遮断された通路自体がカウントされなくなります。 

今後ポジティブな現象が発生しないネガティブな色の場合、```
3
-1 -2 1
```逆スキャンでは継代 3 で (+1) が見られますが、陽性 (+2) は見られません。 したがって、パッセージ 2 には制限がなく、(dp[2]=dp[3]+1=2) となります。 パッセージ 1 には将来 (+1) があるため、制限を (2) に設定し、(dp[1]=2) となります。 結果は`2 2 1`。 これは、色が後でチェックされる否定的なパッセージのみに影響を与える必要がある理由を示しています。`limit`。 

無効化が繰り返される場合は、```
3
1 -1 -1
```逆スキャンでは、ポジティブなパッセージに到達する前に両方のネガティブなパッセージが処理されます。 パッセージ 2 では、未来 (+1) はその右側ではないパッセージ 1 にあるため、パッセージ 2 の観点からは実際には将来のポジティブ (+1) はありません。 同じことがパッセージ 3 にも当てはまります。したがって、制限は作成されず、逆の再帰により次のことが得られます。`3 2 1`。 これはまさに前方歩行の動作です。両方のネガティブな通路を横切ることができ、その後のポジティブなチェックはありません。
