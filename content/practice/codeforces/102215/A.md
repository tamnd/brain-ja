 ## 解決策
 ## 問題の理解

 (n+1) 個の部屋と (n) 個の通路が並んでいます。 通路 (i) は部屋 (i-1) と部屋 (i) を接続するため、目的地に向かって移動することは常に配列を左から右に処理することを意味します。 各パッセージは整数 (a_i) で記述されます。 その絶対値がパスカラーです。 正の値は、通路が通過する前にその色をチェックすることを意味します。 負の値は、通路はいつでも横断できることを意味しますが、通過後はその色の通行が無効になります。 入力形式とこれら 2 つのパッセージ タイプは、公式声明によって示されています。 

すべての開始部屋 (s) について、すべてのパスが有効な状態から開始し、チェック中の通路ですでに無効なパスが必要になるか、部屋 (n) に到達するまで、繰り返し通路 (s+1,s+2,\ldots) を横切ります。 (s) の答えは、通過に成功した通路の数であり、これは部屋 (n) に向かって移動する間に入った部屋の数でもあります。 

境界 (n\le 500000) は二次関数を除外します。 すべての開始部屋の簡単なシミュレーションで、次のことを調べることができます。 

[
 n+(n-1)+\cdots+1=\frac{n(n+1)}2
 ]

 最悪の場合のパッセージは、(n=500000) の場合、約 (1.25\cdot10^{11}) 回の演算になります。 2 秒の制限には、本質的に線形の解決策、またはせいぜいそれに非常に近い解決策が必要です。 すべてのパス カラーが (1) と (n) の間にあるという事実により、高価な汎用構造を使用するのではなく、カラーごとの情報を通常の配列に格納することができます。 

直接実装を騙す可能性のある境界ケースがいくつかあります。 (n=1) と入力あり`1`、答えは`1`、唯一の通路を渡れるからです。 すべての回答には後のパッセージが必要であると想定した実装では、off-by-one エラーが発生する可能性があります。 

考慮する```
2
-1 1
```答えは`1 1`。 部屋 (0) から始めて、通路 1 を通過し、色 1 を無効にします。次に、通路 2 が拒否するため、通過する通路は 1 つだけです。 部屋 (1) から始めて、通路 2 のみに遭遇し、それを横切ることができます。 ネガティブなパッセージは決して進入を拒否しないため、ネガティブなパッセージを即座にブロックするものとして扱う解決策は間違っています。 

逆の順序も重要です。```
2
1 -1
```答えは`2 1`。 部屋 (0) から開始して、パスがまだ有効なうちにポジティブな通路を通過し、その後のネガティブな通路も通過します。 配列内のどこかに同じ色の否定的な出現を探すソリューションでは、最初のパッセージが誤って拒否される可能性があります。 パスを無効にできるのは、すでに通過したネガティブな発生のみです。 

最後に、無効化は選択された開始部屋の後にのみ問題になります。 のために```
2
-1 1
```部屋(1)から始めて答えを出します`1`たとえ左側に負のカラー 1 通路が存在しても。 すべての開始位置はすべてのパスが有効な状態で始まるため、開始前のイベントはそのクエリに影響を及ぼしてはなりません。 

## アプローチ

 ブルートフォース ソリューションは文字通りプロセスに従います。 開始部屋ごとに、どの色がまだ有効であるかを記述する状態を作成し、右側の通路をスキャンし、ネガティブな通路を横切ってその色を無効にし、色がすでに無効になっている最初のポジティブな通路で停止します。 これは動作ルールを正確に再現しているため、これは正しいです。 

問題は繰り返しスキャンすることです。 すべてのクエリが最後まで到達できる場合、最初のクエリは (n) 個のパッセージを検査し、2 番目のクエリは (n-1) 個を検査します。 合計は (n(n+1)/2) で、(n=500000) の場合、およそ (1.25\cdot10^{11}) 回の通過訪問数に達します。 それは制限時間をはるかに超えています。 

有益な観察は、思考の方向を逆転させることによって得られます。 現在、右から左にスキャンしながら通路 (i) を検討しているとします。 負の色 (c) の通過は、その右側のどこかに正の色 (c) の通過がある場合にのみ、最終的に失敗を引き起こす可能性があります。 このようなすべての肯定的な通路の中で、その特定の否定的な通路については、最も近い通路だけが重要である。なぜなら、それは、通行証を無効にした後に旅行者が停止する最初の場所だからである。 

右から左にスキャンしながら、`next_pos[c]`、現在知られている色の最も近いポジティブな通過 (c) が右側にあります。 色の否定的な通過(c)に遭遇したとき、`next_pos[c]`この否定的なパッセージが停止を引き起こす可能性がある最も早いパッセージを示します。 そうすれば、1 つのグローバル境界を維持できます。`limit`、すでに処理された否定的なパッセージによって引き起こされる最も早い停止位置に等しい。 

これがキー圧縮です。 すべての開始位置を個別にシミュレートする代わりに、現在のパッセージの右側にあるサフィックスは、各色の最も近いポジティブ パッセージと、関連するネガティブ パッセージによって引き起こされた最も早い失敗位置の 2 種類の情報だけで要約されます。 ここで使用されている逆回帰は、この問題に対する既存のソリューションにも反映されています。 

パッセージ (i) が正の場合、その右側の負のパッセージがまだ交差していないため、(i) がクエリの最初のパッセージであるときに常に交差することができます。 その答えは、単にパッセージ (i+1) の答えより 1 つ多いだけです。 

通路 (i) が負で、その色に右側に正の通路がない場合、それを横切っても将来の失敗を引き起こすことはできないため、やはりその答えは (i+1) の答えより 1 つ多くなります。 同じ色のポジティブなパスが位置 (p) に存在する場合、(i) から開始すると、最終的には (p) またはその前で失敗します。 旅行者は (p-1) までしか通路を正常に横断できないため、グローバル境界を (p-1) で更新します。

 ## アルゴリズムのチュートリアル

 1. 1 から始まるインデックスを使用してパッセージを保存します。 パッセージ (i) は、開始部屋が (i-1) であるクエリに対応するため、すべてのパッセージの答えを計算すると、必要な出力順序が直接得られます。 
2.作成`next_pos[c]`、すべてのパス カラーに対して、最初はゼロです。 右から左へのスキャン中に、`next_pos[c]`現在の位置の右側に最も近い色の正のパス (c) が含まれます。 
3. 作成する`ans[i]`すべてのパッセージに対して初期化します`ans[n+1]`ゼロに。 架空の位置 (n+1) は通路が残っていないことを表すため、きれいな基本ケースが得られます。 
4. メンテナンス`limit = n`。 この変数は、すでに確認されている否定的な通路によって障害が発生する前に、まだ通過できる最後の通路を表します。 そのような障害が存在しない場合、値 (n) は旅行者が最後まで到達できることを意味します。 
5. スキャン (i=n,n-1,\ldots,1)。 (a_i>0) の場合、パッセージ (i) 自体はそこから開始しても安全なので、

 [
 ans[i]=ans[i+1]+1。 
]

 その後のセット`next_pos[a_i] = i`。 右から左にスキャンしているため、この割り当てでは、この色の最も近い正の出現が記録されます。 

1. (a_i<0) の場合、(c=-a_i) とします。 もし`next_pos[c]`がゼロの場合、この色の右側への正の通過はありません。 現在の負の通路を横切ることは将来の失敗を引き起こす可能性がないため、設定してください
 [
 ansi]=ansi+1]+1。 
]
もし`next_pos[c]=p`、次に、通路 (i) を横切ると色 (c) が無効になり、(p) の正の通路がその無効なパスが拒否される最初の可能な場所になります。 アップデート

 [
 制限=\min(制限,p-1)。 
]

 (i) から出発する旅行者は、(i) から (i) までの通路を正確に横断できます。`limit`、与える
 [
 [i]=限界-i+1。 
]
 シングルの理由`limit`旅行者は、接尾辞内のすべての否定的なパッセージの中で最も早い失敗で停止するだけで十分です。 停止位置の最小値を取ることで、最初の失敗を正確に捉えることができます。 

1.最後に印刷します`ans[1], ans[2], ..., ans[n]`。 答え`ans[i]`部屋 (i-1) で開始することに対応し、必要な開始部屋 (0) から (n-1) に正確に一致します。 

なぜ機能するのか: (i) の厳密に右側の位置を処理した後、`next_pos[c]`は、その接尾辞内の色 (c) の最も近い正の部分です。 すでに処理されたすべての否定的なパッセージには、後に一致する肯定的なパッセージがないか、可能な限り最も早いブロック パッセージが特定されています。 したがって`limit`は、処理されたサフィックス内の否定的なパッセージによって生成される最も古いブロック境界です。 パッセージ (i) を追加すると、肯定的なパッセージはクエリの開始時に常に交差可能になりますが、否定的なパッセージは新しい制限を作成しないか、一致する肯定的なパッセージを最初の制限の別の候補として導入します。 したがって、不変条件は、すべてのクエリを停止できる最初のパッセージを正確に示します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [0] + list(map(int, input().split()))

    next_pos = [0] * (n + 1)
    ans = [0] * (n + 2)

    limit = n

    for i in range(n, 0, -1):
        x = a[i]

        if x > 0:
            ans[i] = ans[i + 1] + 1
            next_pos[x] = i
        else:
            color = -x
            p = next_pos[color]

            if p == 0:
                ans[i] = ans[i + 1] + 1
            else:
                limit = min(limit, p - 1)
                ans[i] = limit - i + 1

    print(*ans[1:n + 1])

if __name__ == "__main__":
    solve()
```入力配列は、インデックス 0 にダミーの 0 を挿入することで 1 ベースになります。 これにより、通路番号 (i) が数学的反復に合わせて維持され、通路インデックスと部屋インデックスの間の繰り返しの変換が回避されます。`next_pos`色ごとにインデックスが付けられています。 すべての色は最大 (n) であるため、長さ (n+1) のリストで十分であり、この問題では辞書を使用するよりも高速でメモリ効率が高くなります。`ans[n+1]`ゼロのままで、最終パッセージの繰り返しが自然な基本ケースになります。 たとえば、最後のパッセージが肯定的な場合、`ans[n] = ans[n+1] + 1 = 1`。 

ポジティブパッセージの操作順序は重要です。 その位置を保存する前に、その答えを計算します。`next_pos`。 クエリがまさにこのパッセージから始まる場合、肯定的なパッセージはその右側の否定的なパッセージによってブロックされないため、誤ってそれ自体の答えを決定するために使用される情報の一部になってはなりません。 

否定的な通路の場合、`next_pos[color]`これらは逆スキャンですでに訪問されている位置であるため、厳密にその右側にポジティブなパッセージのみが含まれています。 それはまさに、この否定的な通路を越えた後に障害となる可能性のある一連の通路です。 

表現`limit - i + 1`パッセージも含めてカウントします。 最初にブロックされた通路が (p) の場合、`limit = p - 1`、成功したパッセージは (i,i+1,\ldots,p-1) です。 それらの数は (p-i) で、これは次と同じです。`limit-i+1`。 

Python の整数はオーバーフローしないため、実際的な問題は線形メモリ割り当てと入力速度だけです。 実装では使用します`sys.stdin.readline`および少数の配列、どちらも (n=500000) に適しています。

結果として得られる答えは、`3 2 1 2 1 1`。 たとえば、部屋 0 から開始すると、通路 1、2、および 3 を通過し、その後通路 4 で通路 2 によって無効化された色 1 がチェックされることを意味します。

    ans = [0] * (n + 2)

                ans[i] = ans[i + 1] + 1
            else:

                ans[i] = limit - i + 1

    return " ".join(map(str, ans[1:n + 1]))

1 -1 -1 1
```逆スキャンでは、位置 4 にポジのカラー 1 のパッセージが記録されます。位置 3 のネガのパッセージがセットされます。`limit=3`一方、位置 2 の否定的なパッセージは、対応する肯定的なパッセージが依然として位置 4 であるため、同じ境界を維持します。 したがって、答えは次のようになります。`3 2 1 1`。 部屋 0 から始めて、旅行者は通路 1、2、および 3 を通過しますが、通路 4 は現在無効になっているカラー 1 パスを拒否します。 Starting at room 1 or room 2 gives progressively shorter walks.

 完全にポジティブパッセージで構成される最大サイズの場合、```
500000
1 1 1 ... 1
```パスを無効にする否定的なパスは決してありません。 逆再帰は単純に次のようになります。`ans[i] = ans[i+1] + 1`、生産`500000,499999,\ldots,1`。 スキャンは正確に (500000) 回の反復を実行し、線形解が制約に適合するのに、二次シミュレーションが適合しない理由を示します。
