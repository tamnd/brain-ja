 ## 解決策
 ## 問題の理解

 長さ n の配列があります。 その要素は 0 から n までの個別の整数であるため、その範囲内の値が 1 つだけ存在することはありません。 配列自体は非表示になります。 その値を直接読み取ることはできません。 代わりに、任意の配列位置 i とビット位置 b について、インタラクターに a i の b 番目のビットを要求することができます。 

タスクは、最大 2n+19 ビットのクエリを使用して欠損値を特定することです。 公式声明では、対話は n で始まり、各クエリは 1 ビットを返し、最終的な答えは次のように出力される必要があることを確認しています。`! x`。 

境界 n≤1000 は十分小さいため、すべての値 0、…、n に対する通常の計算は安価です。 難しい制約はクエリ制限です。 すべての配列要素のすべてのビットを読み取るには、およそ nlog 2 n 個のクエリが使用されます。これは、n=1000 の場合、約 10000 個のクエリに相当し、2019 年の許容値をはるかに上回ります。アルゴリズムは、単にローカル計算を最適化するだけでなく、質問の数を減らす必要があります。 

一般的に間違いを引き起こす特殊なケースが 2 つあります。 まず、欠損値は 0 になる可能性があります。たとえば、n=1 の場合、可能な配列は次のとおりです。`[1]`、したがって、答えは次のとおりです`0`。 答えをゼロ以外の値に初期化するソリューションや、ゼロを特別な失敗ケースとして扱うソリューションでは、この問題が発生する可能性があります。 

第 2 に、n 自体が 2 の累乗である場合も含め、欠損値は n になる可能性があります。 たとえば、n=4 および配列の場合`[0,1,2,3]`、答えは`4`。 ビット位置 4 が存在するため、ビット位置 2 が必要です。`100`バイナリで。 だけを使った迂闊なループ`range(int(log2(n)))`はそのビットをクエリする前に停止し、4 とそれより小さい値を区別できなくなります。 

配列には個別の値が含まれることが保証されます。 したがって、次のような入力`n=3`と`[1,1,2]`は有効なテスト ケースではありません。 特に、「すべてが等しい」配列は問題の領域外にあるため、提出された対話型ソリューションの正当性テストとして有意義に使用することはできません。 

## アプローチ

 直接的な解決策では、すべての配列要素が完全に再構築されます。 すべての値は 0 と n の間であるため、各値には最大 ⌊log 2 n⌋+1 ビットが必要です。 n=1000 の場合、つまり 10 ビットであるため、1000 個の要素すべてを再構築するには、最悪の場合でも 10000 個のクエリが必要になります。 値がわかれば、欠落している数値を見つけるのは簡単ですが、クエリのバジェットはすでに超過しています。 

有益な観察は、完全な配列値を知る必要がないということです。 欠落している 1 つの値のビットのみを知る必要があります。 

不足している数値の下位ビットがいくつかわかっていると仮定します。 まさにそれらのビットを持つ 0 から n までのすべての値を考慮します。 それらを可能な値と呼びます。 実際の配列要素のうち、欠損値を含むグループにはちょうど 1 つ少ない要素があり、他のすべてのグループには予想される数の要素が正確に含まれています。 

次に、次のビットをクエリします。ただし、既知のビットが欠落しているプレフィックスと一致する配列位置のみを対象とします。 ビット 0 を持つグループとビット 1 を持つグループの 2 つのグループが得られます。また、各グループに 0 から n までの値がいくつ属すべきかもわかります。 観測されたサイズが予想されるサイズよりも小さいグループには、欠損値が含まれている必要があります。 

これによりクエリが節約される理由は、b 個の下位ビットを固定した後、取り得る数値のモジュロ 2 b が同じ剰余になるためです。 次のビットはそれらをほぼ均等に分割します。 したがって、候補配列の位置は、反復ごとにおよそ 2 分の 1 ずつ縮小します。 すでに除外されたポジションについては決して問い合わせません。 

ブルート フォースは、クエリされたすべてのビットが要素を再構築するのに十分な情報を提供するため機能しますが、必要のない情報の再構築に Θ(nlogn) クエリを費やすため失敗します。 欠損値を含むグループのみが重要であるという観察により、この暗黙的なバイナリ パーティションを通る 1 つのパスをたどることができ、クエリの総数が O(n) に減ります。

 | --- | --- | --- | --- |

 | 最適 | O(nlogn) ローカル計算、O(n) クエリ | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 0 から n までのすべての値を欠損値の可能性として、すべての配列インデックスを候補位置として開始します。 

この時点では、欠落している数値については何もわかっていないため、すべての値とすべての配列要素が関連しています。 
2. ビット位置を最下位ビットから上に向かって処理します。`n.bit_length() - 1`。 

これらは、まさに 0 から n までの数値に出現する可能性のあるビットです。 下位ビットを最初に処理すると、同じ処理ビットを持つ値がほぼ偶数の等差数列を形成し、必要な縮小特性が得られるため便利です。 
3. 現在可能な値を次のように分割します。`possible_zero`そして`possible_one`現在のビットに従って。 

これらのリストは、ビット 0 とビット 1 が欠落していない場合に、ビット 0 とビット 1 を持つ必要がある値の数を示します。 
4. 現在の候補配列インデックスごとに、インタラクターにこのビットを要求し、インデックスを次のように分割します。`candidate_zero`そして`candidate_one`。 

以前に発見されたビットが欠落している数値と一致する候補についてのみ質問します。 他のすべての配列要素は、欠損値の原因としてすでに除外されています。 
5. 観察されたグループのサイズと予想されるグループのサイズを比較します。 

もし`len(candidate_zero) < len(possible_zero)`、欠損値はビット 0 になります。それ以外の場合は、ビット (1` になります。これは、欠損値を含むグループに値が 1 つだけ存在しないためです。
 6. 対応する値グループと候補インデックス グループのみを保持します。 

不変式が保存されるようになりました。`possible_values`欠落している数値の検出されたすべてのビットと一致する値が正確に含まれていますが、`candidates`値が同じビットを持つ配列の位置が正確に含まれます。 
7. 選択したグループがビット 1 グループである場合は常に、応答の対応するビットを設定します。 

関連するすべてのビットを処理した後、取り得る値は 1 つだけ残ります。 対話形式の回答形式で印刷します。 

### なぜ効果があるのか

 すべての反復の開始時に、候補配列の位置は、欠損値と同じ処理済みビットを持つすべての現在の値を表します。 対応する`possible_values`同じビット パターンを持つ 0 から n までのすべての値が含まれます。 ちょうど 1 つの値が欠落しているため、実際の配列には、欠落している値を含むグループ内で予想される要素よりも 1 つ少ない要素が含まれます。 観察されたグループ サイズと予想されるグループ サイズを比較すると、欠落しているビットを一意に特定できます。 両方のグループをフィルタリングすると、次のビットに対して不変式が保存されます。 すべてのビットが処理された後、2 つの異なる値が関連するすべてのビットを共有することはできないため、残りの可能な値は正確に欠損数になります。 

## Python ソリューション

 実際の Codeforces の問題は対話型であるため、以下のプログラムを対話型の解決策として提出する必要があります。 ステートメントのサンプルに示されている空の行は単なるプレゼンテーションの書式設定であり、実際の対話では、各クエリの後と最終的な回答の後にフラッシュする必要があります。```python
Pythonimport sysinput = sys.stdin.readline

def main():    n = int(input())
    possible_values = list(range(n + 1))    candidates = list(range(n))
    answer = 0
    for bit in range(n.bit_length()):        possible_zero = []        possible_one = []
        for value in possible_values:            if (value >> bit) & 1:                possible_one.append(value)            else:                possible_zero.append(value)
        candidate_zero = []        candidate_one = []
        for idx in candidates:            print("?", idx + 1, bit, flush=True)            response = int(input())
            if response == -1:                sys.exit(0)
            if response == 0:                candidate_zero.append(idx)            else:                candidate_one.append(idx)
        if len(candidate_zero) < len(possible_zero):            possible_values = possible_zero            candidates = candidate_zero        else:            possible_values = possible_one            candidates = candidate_one            answer |= 1 << bit
    print("!", answer, flush=True)

if __name__ == "__main__":    main()
```プログラムは最初に初期化します`possible_values`すべての n+1 値を使用します。これは、それらのいずれかが最初に欠落している可能性があるためです。`candidates`まだ位置が除外されていないため、すべての配列インデックスが含まれています。 

ビットごとに、可能な値が質問される前に分割されます。 これにより、各ビット グループの正確な期待値が得られます。 次に、配列の位置が 1 つずつクエリされ、その応答によって対応する観察されたグループが形成されます。 

比較`len(candidate_zero) < len(possible_zero)`が中心的な決定です。 欠損値が 2 つ存在することはできないため、ゼロ グループが予想よりも小さい場合は、その欠損メンバーが答えになる必要があります。 それより小さくない場合、その 1 つのグループにはメンバーが欠けているはずです。 

アンサービットは、1 つのグループが選択された場合にのみセットされます。 から答えを明示的に構築する必要はありません`possible_values`ただし、最後の反復の後では、リストには数値が 1 つだけ含まれます。`idx + 1`Python は配列インデックスを 0 から格納するのに対し、インタラクターは位置に 1 から番号を付けるため、これが必要です。 ステートメントではビットに 0 から番号が付けられるため、ビット自体はシフトまたは調整されません。 

ループは使用します`n.bit_length()`それよりも`int(log2(n))`。 n=4の場合、`n.bit_length()`は 3 なので、ビット 0、1、2 が処理され、値 4=100 2 が正しく処理されます。 Python の整数はオーバーフローしないため、特別な整数型は必要ありません。 

の`flush=True`インタラクティブな問題では、すべてのクエリで必須です。 これがないと、プログラムがインタラクターの応答を待機している間、Python は出力バッファーにクエリを保持し、デッドロックが発生する可能性があります。 このステートメントでは、すべての対話メッセージをフラッシュすることが明示的に要求されます。
