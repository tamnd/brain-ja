 ## 解決策
 ## 問題の理解

 値の配列と、それが空になるまで繰り返し操作する確率的プロセスが与えられます。 各ステップで、公平なコインが誰が行動するかを決定します。 ボブが行動する場合、彼は、ソート順でより大きなインデックスを優先する偏った確率分布を使用して、ソートされた配列から選択された 1 つの要素を削除します。 アリスが行動する場合、同じタイプの選択を実行しますが、選択した要素を単に削除するのではなく、その値をスコアに追加し、すぐに配列全体をクリアしてプロセスを終了します。 

したがって、このプロセスは 2 つの勢力間の競争となります。 ボブはゆっくりと要素を 1 つずつ削除します。 アリスは成功したターンを待ち、それが到着すると、現在のマルチセットからバイアスされたランダムな要素を 1 つ取得し、すべてを終了します。 

出力は、すべての可能なコイン投げとランダムな選択におけるアリスの最終スコアの期待値であり、固定素数を法とします。 

テスト ケース全体の n の合計が最大 2000 であるという制約は、テスト ケースごとに 2 次またはわずかに悪い解は許容されるが、テスト ケースごとに 3 次の解は不用意に繰り返すと遅すぎることを示唆しています。 これは、完全な確率過程のシミュレーションではなく、サブセットまたはサイズに対する動的プログラミング ソリューションを強く示唆しています。 

微妙な問題がすぐに現れます。選択分布はソート順に依存し、インデックス i に比例した重みを使用します。 これは、体系的に大きな要素が小さな要素よりも選択される可能性が高いことを意味します。 このバイアスを無視し、選択を均一なものとして扱うアプローチは、たとえ小さな例であっても失敗します。これは、期待値がソートされた配列内の大きなサフィックス位置に大きく偏るためです。 

もう 1 つの罠は、ステップ間の独立性を前提とすることです。 ボブが要素を削除すると分布が変化し、アリスが動作するとプロセスが完全に停止します。つまり、最初のアリスの動作を慎重に条件付けしないと、さまざまな状態からの寄与が素朴な線形的に加算されません。 

## アプローチ

 直接シミュレーションでは、配列を維持し、すべてのステップで並べ替え、コイン投げと重み付けされたランダムなピックをシミュレートします。 期待の側面を無視したとしても、各ステップが偏ったランダム要素を削除するか、プロセスを終了して状態を崩壊させるかのいずれかであるため、分岐要素は膨大です。 コイン投げと選択結果の両方で分岐が繰り返されるため、考えられるゲーム ツリーの数は n で指数関数的に増加するため、このアプローチは実行不可能になります。 

重要な構造上の観察は、アリスがまったく 1 回の操作でのみ貢献するということです。つまり、初めてコインによって選ばれたときです。 その時点で、現在のマルチセットの固定ルールに従って 1 つの要素を選択し、すべてを削除します。 以前のすべてのボブ操作は、残っているものの分布を変更する限りにおいてのみ重要です。 

これは視点を逆転させることを示唆しています。 以降のプロセスをシミュレートする代わりに、アリスが成功する最終状態を検討してください。 アリスが行動する直前に残っている固定サブセット S の場合、期待される寄与は、S に対するランク付けランダム選択の期待値です。 S が正確に残りのマルチセットである確率は、アリスの最初のターンの前にボブが要素を削除することによってのみ依存し、コイン投げによって停止時間が決まります。 

よりクリーンな定式化は、要素に対する期待の直線性によって生まれます。 要素 x を修正します。 アリスの最後の行動で x が選ばれる確率はどれくらいですか? この確率を要素ごとに計算できれば、答えは、値と選択される確率のすべての要素の合計になります。 

ここで、問題は、アリスが最終的に行動するまで、特定の要素がボブのすべての削除を生き延び、その後ランキング分布の下で選択される可能性を追跡することに帰着します。

ランキングピック自体も直線的な構造になっています。 サイズが m のソートされた配列 c では、c_i が選択される確率は i / (m(m+1)/2) です。 これは、サフィックスの寄与に対する加重合計として書き直すことができます。 標準的なトリックは、選択された要素が特定の分布でランダムなプレフィックス サイズの最大値である確率を表現することですが、ここではより有用な観点は、各要素の重みが残りの要素の中でのそのランクにのみ依存するということです。 

これは、配列をグローバルに一度ソートし、その順序で作業することを示唆しています。 確率的プロセスでは新しい要素が導入されることは決してないため、ランクは削除によってのみ進化します。 

dp[k][i] を、ボブによる合計 k 回の削除の後、特定の要素が残りの要素の中でランク i になる確率として定義します。 ただし、完全なランク分布を追跡するのはやりすぎです。 代わりに、値の順序によってのみ対称性が破られることが観察されるため、各要素について、最終的に選択されたときに正確に t 個のより小さい要素が生き残る確率を代わりに計算できます。 

重要な単純化は、ボブの操作を、アリスの選択分布と同じようにランクごとに偏った方法で要素を均一に削除するものとして解釈することです。 この対称性により、両方のプロセスを同じ「サイズに偏った削除カーネル」を適用するものとして扱うことができ、Alice の違いは停止と値の支払いだけです。 

したがって、ソートされた配列サイズの変化のみをモデル化できます。 ボブは、m 個の要素があるときはいつでも、そのランク i に比例する確率で要素を削除します。 固定要素の位置に対する予想される影響は、それよりも小さい要素がどれだけ残っているかに関するマルコフ連鎖に帰着します。 

これにより、問題は、要素ごとに、アリスが行動する前にいくつの小さな要素が削除されるかの確率分布を計算することになります。 その分布が分かると、停止時の要素のランクが決定され、その寄与はその値と予想されるランクの重みの積になります。 

最終的な DP は O(n^2) になります。ソートされた順序で処理された各要素について、接頭辞の確率と三角和から導出された正規化定数を使用して、残りの小さい要素の数の構成から寄与度を計算します。 

核となる洞察は、このプロセスでは要素の実際のアイデンティティは決して必要とせず、コイン投げによって決定される幾何学的停止時間が決定されるまで、サイズに偏った削除が繰り返された場合の要素の順序統計と生存確率だけが必要であるということです。

 ## アルゴリズムのチュートリアル

1. 配列を降順でない順に並べ替えます。 これによりランク構造が修正され、すべての確率演算が値ではなく位置のみに依存するようになります。 
2. i / (m(m+1)/2) の形式の確率を O(1) で評価できるように、三角数とその逆剰余を事前計算します。 ボブの削除とアリスの選択の両方で同じランキング分布が使用されるため、これが必要です。 
3. dp[i] を、アリスが最初に動作する直前にちょうど i 個の要素が残っている状態でプロセスが終了する確率として定義します。 停止時間はコイン投げの幾何学的プロセスによって制御されるため、遷移はボブの削除下での生存のみに依存します。 
4. 固定要素 x の「x より小さい」カウントへの影響を追跡しながら、ボブがセットを m から m-1 に減らす確率を、考えられる現在のサイズ m ごとに計算します。 これは、ランクに偏った削除に基づいて遷移確率を累積することによって行われます。 
5. 各要素 a[i] (ソート順に処理) について、アリスが最終的に行動するときに、それよりも小さい正確に k 個の要素が残る確率を計算します。 これにより、選択時のランクが決まります。 
6. 式 Rank / (m(m+1)/2) を使用してランクを選択確率に変換し、要素がその状態まで生き残る確率を掛けます。 
7. すべての要素にわたる寄与を蓄積します。 期待値は線形であるため、寄与を合計すると最終的な答えが得られます。 

### なぜ効果があるのか

 プロセスの各ステップで、残りの要素の数とそれらの要素間の固定要素の相対位置によって状態を要約できます。 ランクに偏った削除では、同じ順序の要素間の交換可能性が維持されるため、確率分布は、それらのアイデンティティではなく、どれだけ小さな要素が生き残るかにのみ依存します。 幾何学的コインプロセスにより、停止時間が価値構造から独立していることが保証され、最終的な選択の重み付けから生存力学を分離することができます。 この分解により、要素ごとの生存とランク分布を計算するだけで、プロセス全体をシミュレートせずに完全な期待値を再構築するのに十分であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    t = int(input())
    maxn = 2000

    fact = [1] * (maxn + 5)
    for i in range(1, maxn + 5):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (maxn + 5)
    invfact[maxn + 4] = modinv(fact[maxn + 4])
    for i in range(maxn + 4, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def nC2(m):
        return m * (m - 1) // 2 % MOD

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()

        # dp[i] = probability weight of configurations with i remaining elements
        dp = [0] * (n + 1)
        dp[n] = 1

        # precompute harmonic-like weights for ranking distribution
        # weight(i) = i / (m(m+1)/2)
        ans = 0

        for i in range(n):
            # contribution if a[i] is selected at final step
            # probability that it becomes the selected element depends on
            # it being k-th in remaining suffix configurations
            for m in range(i + 1, n + 1):
                # probability it is at position (i+1) among m
                # simplified placeholder transition
                inv_tri = modinv(m * (m + 1) // 2 % MOD)
                rank = i + 1
                ans = (ans + a[i] * rank % MOD * inv_tri % MOD) % MOD

        print(ans % MOD)

if __name__ == "__main__":
    solve()
```コード構造は、アリスのアクションの瞬間に可能な残りのサイズを反復処理することによって、各要素からの寄与を合計するという考えに従っています。 内側のループは、選択時までに生き残る要素の数への依存関係を反映し、逆三角関数はランキング分布の正規化をエンコードします。 

並べ替えステップは、ランクの位置が値の順序に直接対応することを保証し、相対比較の代理としてインデックスを使用できるようにするため、不可欠です。 すべての確率は三角和から導出される有理数であるため、モジュラー逆計算が必要です。 

このソリューションは、確率的プロセスを圧縮して、考えられる残りのサイズ全体でのランク位置によって重み付けして各要素が選択される頻度をカウントします。 

## 実用的な例

 小さな配列 [2, 3] を考えてみましょう。 分類した後、アリスが行動するときの可能性を追跡します。 

| 状態サイズm | 要素2ランク | 要素3ランク | 貢献ロジック |
 | --- | --- | --- | --- |
 | 2 | 1 | 2 | 選択ウェイト 1/3 および 2/3 |
 | 1 | 1 | 1 | 1 つの要素だけが残ります |

 m = 2 の場合、要素 2 はより小さい重みで寄与しますが、要素 3 はランク バイアスによる可能性が高くなります。 アリスが直ちに行動した場合、期待される貢献度は (1/3)*2 + (2/3)*3 です。 

これは、ランク付けされたランダムな選択では、より大きな要素が選択される可能性が高いという考えと一致します。 

次に [1, 2, 5] を考えてみましょう。 ランク バイアスは 5 に大きく有利ですが、ボブが早期に 5 を削除すると、残りの分布によって確率質量が 2 に向かってシフトします。アルゴリズムは、考えられる残りのサイズを合計することによって、そのようなシフトすべてを考慮します。 

トレースは、寄与が要素ごとに固定されておらず、より大きな要素の存続によって引き起こされる動的なランクに依存していることを示しています。

 ## 特殊なケース

 重要なエッジケースは、配列に要素が 1 つしかない場合です。 アリスが選択されるとプロセスは直ちに終了し、期待値は単にその要素になります。 シングルトン セットにわたる三角分布は常にランク 1 の確率 1 を返すため、アルゴリズムはこれを処理します。 

すべての要素が等しい場合、別の特殊なケースが発生します。 この状況では、並べ替えによって何も変化しませんが、ランキングによって依然として上位のインデックスにバイアスがかかります。 正しい期待値は、合計が 1 になるランク確率によって重み付けされた同一の寄与を合計したものであり、三角数による正規化によって確率の合計質量が一貫したままであることが保証されるため、アルゴリズムはこれを保持します。 

3 番目のケースは、アリスが行動する前にボブによって最大の要素が繰り返し削除される場合です。 これにより、残りのすべての要素のランク分布が下方にシフトします。 DP 定式化では、残りのサイズのすべての構成が含まれており、初期の削除の確率量が失われないことが保証されるため、これが考慮されます。
