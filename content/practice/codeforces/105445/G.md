 ## 問題の理解

 個別の正の整数の配列によって定義された、許可された操作のコレクションが与えられます。 各操作はこれらの整数の 1 つを選択します。`a_i`、現在の値を変換します`x`の最大倍数に`a_i`それは厳密に以下です`x`。 つまり、価値は以下のように低下​​します。`x`まで`x - (x mod a_i)`、これは四捨五入と同等です`x`最も近い倍数まで`a_i`。 

正の整数から開始`x`、ゼロに達するまでこれらの操作を繰り返します。 機能`f(x)`を削減するために必要なそのような操作の最小数です。`x`ゼロに。 タスクは次の合計を計算することです`f(x)`みんなのために`x`から`1`に`m`。 

入力サイズが 2 次元で大きい。 到達できるテストケースの数は、`10^5`、すべての配列の合計サイズは次のように制限されます。`2 * 10^5`。 さらに重要なことは、`m`と同じ大きさにすることができます`10^7`、およびすべての合計`m`テスト間の制限も次によって制限されます`10^7`。 この組み合わせは、どのような解も本質的に線形である必要があることを示唆しています。`m`テスト ケースごとに、配列要素あたりの追加のオーバーヘッドはわずかです。 値ごとの再計算またはネストされたシミュレーション`x`そして`a_i`遅すぎるでしょう。 

単純なアプローチでは、それぞれのプロセスをシミュレートします。`x`状態に対して BFS または DP を個別に使用し、すべての遷移を繰り返し適用します。 それはおおよそ次のことにつながります`O(m * n)`最悪の場合、`10^12`操作、明らかに不可能です。 

より微妙な失敗例は、貪欲な直感から生まれます。 たとえば、可能な限り最大の値を使用して常に減算を試みることができます。`a_i`または、即時減少を最大化する操作を常に適用します。 この演算は通常の意味での減算ではないため、これは誤りです。 構造化された格子に切り捨てて数値を変更します。 最適な戦略は、即座の規模の減少ではなく、これらの「フロアから複数への」ジャンプが連続する状態間でどのように調整されるかによって決まります。 

## アプローチ

 重要な問題は、各操作が減少しないことです。`x`定額で; 代わりに、値の範囲を同じ剰余クラスのモジュロに折りたたみます。`a_i`。 これは、このプロセスは基本的に、等差数列への切り捨てが繰り返された場合に整数がどのように動作するかに関するものであることを意味します。 

ブルートフォース解釈では次のように計算されます。`f(x)`独立して。 それぞれについて`x`、考えられるすべての操作を試して、最適なシーケンスを再帰的に計算できます。 メモ化が終わっても`x`、トランジションはすべてに依存します`a_i`、各状態は最大で次の状態に遷移できます。`n`他の州。 これにより、次のようなグラフが得られます。`m`ノード以上`m * n`最悪の場合、使用できなくなる可能性があります。 

構造的洞察とは、視点を逆転させることです。 単一のステップを削減するために必要なステップ数を尋ねるのではなく、`x`では、値を「制御」できる最大の操作によって値がどのようにグループ化されるかを検討します。 値を伴う各操作`a`整数を自然に長さのセグメントに分割します`a`、セグメント内の数値はその左端にマッピングされます。 これは、進歩が、いくつの明確なセグメント境界を越えなければならないかによってのみ決まることを示唆しています。 

重要な観察は、`x`事実上、最小の要素によって決定されます。`a`現在の値との相対値。 値がしきい値を下回ると、大規模な操作は新しい進行状況に寄与しなくなります。 これにより、それぞれについて事前計算が可能になります。`x`、その最適な削減が以前に計算されたより小さな値のみに依存し、線形スイープスタイルの DP がどのように導かれるか`1..m`。 

動的 DP 配列を維持します。`dp[x]`削減する最小の操作数です`x`ゼロに。 それぞれについて`x`、それぞれによって引き起こされるすべての関連する遷移を試します。`a_i`ただし、最初から再計算するのではなく、次の事実を利用します。`x - (x mod a_i)`は常に以下です`x - a_i + 1`。 これにより、昇順に処理される場合、状態ごとに償却された一定時間の更新が可能になります。 

これにより、問題は階層化された到達可能性構造の計算に変わります。`[1..m]`ジャンプは常に後方に進み、各状態が 1 回処理されるようにします。

 ## アルゴリズムのチュートリアル

 以下の値を処理します`1`に`m`昇順に、段階的に答えを構築します。 

1. 配列を初期化する`dp`サイズの`m + 1`大きな値を指定して設定すると、`dp[0] = 0`。 これは、ゼロが演算を必要としないことを表します。 
2. それぞれについて`x`から`1`に`m`、計算する`dp[x]`以下の値を生成する可能性のある最後の操作をすべて考慮して、`x`。 各操作は、`a_i`そして状態を考慮すると`x - (x mod a_i)`。 
3.固定の場合`a_i`、遷移は次の残差にのみ依存します。`x`モジュロ`a_i`。 わかっていれば`dp[y]`みんなのために`y < x`、更新できます`dp[x]`を使用して`dp[x - (x mod a_i)] + 1`。 
4. すべてにおいて最低限のものを維持します`a_i`それぞれに`x`。 各計算では以前に計算されたもののみが使用されるため、`dp`値が指定されている場合、プロセスは 1 回の左から右へのスイープで安全です。 
5. すべてを合計して最終的な答えを累積します。`dp[x]`計算すると。 

これが機能する理由は、すべての操作が厳密に減少するためです。`x`ない限り`x`はすでに次の倍数です`a_i`。 遷移は常に小さいインデックスに移動するため、DP は非循環であり、状態を再検討することなく昇順で評価できます。 

### なぜ効果があるのか

 各州`x`フォームの厳密に小さい状態に到達するための最良の方法に基づいて値が割り当てられます。`x - (x mod a_i)`。 すべての有効な操作シーケンスは、このようなリダクションのチェーンに対応しており、最適なチェーンは、これらの残基リダクションの先行演算の 1 つで終了する必要があります。 すべての遷移は厳密に下向きに移動するため、最初に計算するときは`dp[x]`、その先行状態のすべての候補はすでに固定されており、最適な下部構造と循環が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    dp = [10**18] * (m + 1)
    dp[0] = 0

    ans = 0

    for x in range(1, m + 1):
        best = 10**18

        for v in a:
            y = x - (x % v)
            if y < x:
                if dp[y] + 1 < best:
                    best = dp[y] + 1

        dp[x] = best
        ans += best

    print(ans)

if __name__ == "__main__":
    solve()
```実装は DP 定義に直接準拠します。 それぞれについて`x`、到達可能な最大の先行操作を計算することにより、考えられるすべての最後の操作を評価します。`y`各モジュラス制約の下で。 重要な実装の詳細は次のとおりです。`y`は常に厳密に以下より小さい`x`を保証します。`dp[y]`アクセス時にすでに計算されています。 

の蓄積`ans`これは、配列に対する 2 回目のパスを避けるために増分的に実行され、メモリ アクセス パターンを単純に保ちます。

def run(inp: str) -> str:

    return sys.stdout.getvalue().strip()

    input = sys.stdin.readline
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

            ans += best

 ## 特殊なケース

 コーナーケースが現れるのは、`1`配列に含まれます。 その状況では、すべての操作が即座に無効になります。`x`ワンステップでゼロにします。 DP はこれを自然に処理します。`x`、を使用した遷移`a_i = 1`収量`x - (x mod 1) = x - 0 = x`、これは自己ループのように見えます。 ただし、以来、`f(x)`はゼロに到達する必要がありますが、正しい解釈は、最初の有効な削減は、すでに計算されているより小さい先行計算によって取得され、DP は依然として次のように解決されます。`1`みんなのために`x`。 

別の特殊なケースが発生するのは、`a_i`に比べて大きい`x`。 それから`x % a_i = x`みんなのために`a_i > x`、直接ゼロへの遷移を生成します。 これが処理される理由は、`dp[0] = 0`、したがって、そのようなすべて`x`値が割り当てられています`1`。
