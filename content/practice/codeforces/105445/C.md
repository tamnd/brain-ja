 ## 解決策
 ## 問題の理解

 単一の配列が与えられ、すべての連続する部分配列から構築される非常に大きなネストされた合計を計算するように求められます。 開始インデックスごとに`i`、すべてのエンディングインデックスを調べます`j ≥ i`、部分配列の積を計算します。`a[i] ... a[j]`、次に、これらの値を可能な限りすべて合計します。`(i, j)`ペア。 

したがって、量は本質的にすべてのサブ配列の寄与の合計であり、各サブ配列はその積を 1 回寄与します。 

この簡単なバージョンでも、入力にはテスト ケース全体で最大 100 万個の要素が含まれる可能性があるため、部分配列を明示的に列挙したり積を最初から再計算したりするソリューションはすぐに失敗します。 部分配列の二次数はすでに約を与えています`5e11`最大サイズでの演算や、慎重に再利用しないと、各積の計算で別の線形係数が追加されてしまいます。 

主な問題は、積が乗算的に増加することですが、必要な合計はすべてのサブ配列にわたって加算されるため、重複するサブ配列全体で部分構造を再利用する方法が必要であることです。 

すべての値が以下の場合、微妙なエッジケースが発生します。`1`。 その場合、すべてのサブアレイ積は次のようになります。`1`、そして答えは部分配列の総数になります。`n(n+1)/2`開始点をまたいで合計すると、素朴な推論で三次のような成長パターンが生成されます。 これはまさに、総当たりシミュレーションが崩壊する場所です。 

もう 1 つのエッジ ケースは、次の値に近い大きな値です。`1e9`。 モジュラーリダクションを行わない直接乗算は、注意しないと 64 ビット整数をオーバーフローさせてしまう可能性があり、モジュロ演算でも再計算のオーバーヘッドを避けるために慎重な順序付けが必要です。 

## アプローチ

 ブルートフォース手法は簡単です。 開始インデックスごとに`i`、延長します`j`から`i`に`n`、稼働中の製品を保守します。`a[i]...a[j]`を答えに積み上げていきます。 すべてのサブ配列が 1 回だけアクセスされるため、これは定義と正確に一致し、機能します。 

ただし、このアプローチでは、製品を再計算したり、繰り返し更新したりすることになります。`(i, j)`ペア、につながる`O(n^2)`テストケースごとの乗算。 合計あり`n`まで`10^6`、これでは非常に遅くなります。 

重要な観察は、すべてのサブ配列の寄与を合計しており、各要素が構造化された方法で多くのサブ配列に参加していることです。 サブ配列の観点から考える代わりに、視点を逆にして、各位置の寄与をプレフィックスにわたる動的な累積の一部として扱うことができます。 

エンドポイントを修正する場合`j`、で終わるすべてのサブ配列`j`で終わるサブ配列を拡張すると見ることができます。`j-1`乗算して`a[j]`、次に単一要素の部分配列を追加します`[j]`。 これは、2 つのローリング量、つまり次で終わるすべての部分配列積の合計を維持することを示唆しています。`j`、そしてグローバルな答え。 

これにより、問題は線形反復に変換され、各ステップで以前のすべての寄与が係数で更新されます。`a[j]`ただし、以前のすべての状態を明示的に更新する代わりに、すべての部分配列の合計が次で終わるという事実を再利用します。`j-1`すでに製品をエンコードしています。 その合計を乗算すると、`a[j]`で終わるすべての部分配列を自動的に変換します。`j-1`で終わる拡張バージョンに`j`。 

したがって、遷移は位置ごとにローカルかつ一定時間になります。

 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | サフィックス寄与に対する最適な DP | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在のインデックスで終わるすべての部分配列の積の合計を表すローリング値を維持しながら、配列を左から右に処理します。 

1. 変数を初期化する`end_sum`現在の位置で終わるすべての部分配列の積の合計を保存します。 初期化する`answer`最終結果を蓄積します。 
2. インデックスから配列を反復処理します。`0`に`n-1`。 
3. 位置で`j`、で終わるすべてのサブ配列`j`のみで構成される新しい部分配列です。`a[j]`、またはで終わるサブ配列の拡張子`j-1`乗算`a[j]`。 これにより再発が得られます`end_sum = a[j] + end_sum * a[j] (mod M)`。 

これが機能する理由は、以前のすべての終了部分配列に次の値を乗算するためです。`a[j]`構造を失わずに正しく拡張します。 
4.追加`end_sum`グローバルに`answer`。 これにより、次で終わるすべてのサブ配列がキャプチャされます。`j`。 
5. 配列の最後まで続けます。 決勝戦`answer`すべての部分配列の合計です。 

### なぜ効果があるのか

 すべてのインデックスで`j`、`end_sum`右端が次のとおりであるすべての部分配列の積の合計に正確に等しい`j`。 このようなすべてのサブ配列は次のいずれかで始まるため、これは帰納的に保存されます。`j`または、で終わるサブ配列を拡張することによって形成されます。`j-1`。 乗算は加算よりも分配されるため、以前のすべての部分配列を次のように拡張します。`a[j]`彼らの貢献度の合計に次の値を乗じることと同じです。`a[j]`、シングルトン部分配列を追加するとセットが完了します。 各サブ配列には正しい端点が 1 つだけあるため、すべてを合計すると、`end_sum`値はすべての部分配列を 1 回だけカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        
        end_sum = 0
        ans = 0
        
        for x in a:
            end_sum = (x + end_sum * x) % MOD
            ans = (ans + end_sum) % MOD
        
        # q = 1 and l=1, r=n always
        input()  # consume query line
        print(ans)

if __name__ == "__main__":
    solve()
```実装における主要な状態は次のとおりです。`end_sum`、現在のインデックスで終わるすべてのサブ配列を表します。 更新のたびに、以前の状態に現在の要素が乗算され、新しい単一要素の部分配列が追加されます。 2番目のアキュムレータ`ans`すべてのエンドポイントにわたる貢献を集約します。 

入力は常に配列全体をカバーする単一のクエリを提供するため、グローバル結果をテスト ケースごとに 1 回計算するだけで、クエリ境界を読み取った後は無視します。 

よくある落とし穴は、再帰が各ステップでモジュロを適用することを忘れていることです。 乗算後にモジュラー削減を行わないと、コンパイルされたコンテキストでの Python のパフォーマンスを考慮しても中間値が大きくなりすぎます。

import sys, io

MOD = 10**9 + 7

def solve_input(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = out

    MOD = 10**9 + 7

    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        end_sum = 0
        ans = 0
        for x in a:
            end_sum = (x + end_sum * x) % MOD
            ans = (ans + end_sum) % MOD

        input()
        print(ans)

    sys.stdout = old_stdout
    return out.getvalue().strip()

# provided sample

1 3
""") == "53"

1 5

 ## 特殊なケース

 すべて 1 の配列の場合、次のようにします。`a = [1, 1, 1]`、再発により与えられる`end_sum`価値観`1, 2, 3`、そして最終的な答えは`6`。 これは、正確に 6 つのサブ配列があり、それぞれが値に寄与するという事実と一致します。`1`。 すべての拡張機能が値を保持するため、アルゴリズムはそれらを正しく蓄積します。 

次のような単一の大きな要素の場合`a = [10^9]`、再発により生成される`end_sum = 10^9`そして答える`10^9`。 サブ配列が 1 つだけあるため、オーバーフローや隠れた相互作用は発生せず、モジュロ演算によって結果が直接取得されます。 

次のような厳密に増加する配列の場合`[1, 2, 3, 4]`、各ステップでは、以前のすべてのサブ配列寄与に新しい要素を乗算し、新しいシングルトンを追加します。 トレースすると、サブ配列が二重にカウントされていないことがわかります。これは、各サブ配列がその正しいエンドポイントに一意に固定されており、繰り返し全体で独立したアカウンティングが保証されているためです。
