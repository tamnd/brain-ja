 ## 解決策
 ## 問題の理解

 少人数の面接官体制が与えられ、グループで面接を繰り返します。 各インタビューは正確に構成されています`z`個別の面接官がおり、各面接官は最大でも次の面接にのみ参加できます。`y`毎日のインタビュー。 がある`x`面接官の合計数は 1 人であり、その課題は、面接官 1 人あたりの能力の制約を尊重しながら、できるだけ多くの面接をスケジュールすることです。 

有効な出力はグループのリストであり、各グループは次のセットです。`z`個別の面接官 ID。 各グループは 1 回のインタビューを表します。 制約は純粋に、各面接官 ID がすべてのグループにわたって何回出現できるかということです。 

構造的な観点から見ると、これは有界の組み合わせパッキング問題です。 できるだけ多くのサイズを梱包できるよう努めておりますが、`z`可能な限りサブセットをマルチセットに分割する`x`各要素に容量がある要素`y`。 

制約は非常に小さいです。`x, y, z ≤ 10`。 これにより、考えられる個別のインタビュー グループの数は最大でも次のとおりであることがすぐにわかります。`C(10, z)`すべての組み合わせを列挙し、使用回数をシミュレートしたとしても、状態空間は小さいままです。 これは、貪欲な構築または体系的な列挙でさえ十分であることを強く示唆しています。 

微妙なエッジケースが現れるのは、`x < z`。 その場合、一連のグループを形成できないため、有効なグループはまったく存在しません。`z`個性豊かな面接官。 もう 1 つのエッジケースは次のような場合です`y = 0`、これにより、面接の回答がゼロになることが強制されます。`x`そして`z`。 これらのケースを明示的に保護しない単純な実装では、グループを構築しようとして無効なインデックスが作成されたり、実行不可能なスケジュールが生成されたりする可能性があります。 

## アプローチ

 ブルートフォース解釈では、サイズの可能な各サブセットが処理されます。`z`候補者の面接として、面接官が使用量を超過しないようにしながら、そのようなサブセットの最大数を選択するようにしてください。`y`。 これは本質的にハイパーグラフ上の最大パッキング問題であり、直接検索ではサブセットの組み合わせが試行されます。 

正しさを推論するのは簡単ですが、各サブセットが選択できるかどうかを考慮すると、組み合わせ爆発が発生し、大まかに次のようになります。`2^(C(x, z))`可能性。 それでも`x ≤ 10`、これはまだ最大につながります`2^252`最悪の場合は状態になりますが、これは完全に不可能です。 

重要な観察は、全体的な意味で最適なサブセットを選択する必要がないということです。 必要なのは、グループの数を最大化する実現可能な構造を作成することだけです。 すべての面接官が対称的なため、参加者を均等に分散できます。 自然な構造では、面接官を循環させ、常に連続したサイズのグループを選択します。`z`、各面接官が使用された回数を追跡しながら、周期的にラップアラウンドします。 

なぜなら`x`小さいし、`y`小さいので、次に利用可能なグループを常に選択しながら、貪欲に 1 つずつグループを構築できます。`z`まだ余力のある面接官。 ポインタを維持し、面接官 ID をローテーションすると、公平性が確保され、単一の参加者を過度に使用することがなくなります。 この構築は、有効なグループが形成されなくなるまで続けられます。 

これが機能する理由は、有効なスケジュールは総容量によってのみ制限されるためです。`x * y`、各インタビューは正確に消費します`z`容量の単位。 したがって、上限は`floor(x * y / z)`、そして貪欲な循環構築は、小さな制約内で自然にこの限界に近づきます。

 ## アルゴリズムのチュートリアル

 各面接官の残りのキャパシティを追跡しながら、繰り返し面接を構築します。 

1. 配列を初期化する`used[i] = 0`すべての面接官にとって`i`、彼らが参加したインタビューの数を表します。これにより、制限を強制できることが保証されます`y`。 
2. 現在のポインタを維持する`p`～からの面接官を超えて`1`に`x`。 このポインターは、同じサブセットから繰り返し選択するのではなく、使用量を均等に分散するのに役立ちます。 
3. 可能であれば、面接グループを 1 つ形成するようにしてください。 

から前方にスキャンします`p`そして次を選ぶ`z`個性豊かな面接官`used[i] < y`。 

このスキャン手順では、疲れきった面接官を明示的にフィルタリングするため、制約に違反することなく有効なグループを常に構築できます。 
4. いつでも見つからない場合`z`面接官、やめてください。 これは、これ以上有効なインタビューを形成できないことを意味します。 
5. グループ形成後、インクリメント`used[i]`選択した面接官ごとに、そのグループを回答リストに追加し、ポインタを前に移動して公平な配分を継続します。 
6. 終了条件に達するまで続行します。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは残りのキャパシティを持つ面接官のみを選択するため、制約に違反することはありません。 循環スキャンにより、実行可能なグループが存在する場合、そのグループが最終的に発見されることが保証されます。これは、利用可能なインタビュアーのすべての組み合わせが、小さな固定ユニバース上のローテーションを通じて到達可能であるためです。 容量は単調に減少するため、プロセスは終了する必要があり、終了すると、制約の下では有効なグループを形成できなくなります。つまり、この制限された設定の貪欲なポリシーの下で構築が最大になることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x, y, z = map(int, input().split())
        
        if z > x or y == 0:
            print(0)
            continue
        
        used = [0] * (x + 1)
        ans = []
        p = 1
        
        while True:
            group = []
            start = p
            i = start
            scanned = 0
            
            while scanned < x and len(group) < z:
                if i > x:
                    i = 1
                if used[i] < y:
                    group.append(i)
                i += 1
                scanned += 1
            
            if len(group) < z:
                break
            
            for v in group:
                used[v] += 1
            
            ans.append(group)
            p += 1
            if p > x:
                p = 1
        
        print(len(ans))
        for g in ans:
            print(*g)

if __name__ == "__main__":
    solve()
```このソリューションは、面接官ごとに使用状況カウンターを維持し、面接官 ID を周期的にスキャンすることで各グループを構築します。 内側のループにより正確に収集されます`z`余力のある個別の面接官。 ポインタ`p`同じ初期のインデックスを繰り返し選択することを避けるために、グループごとにシフトします。 

実装の微妙な詳細は、インデックスの明示的なラップアラウンドです。`i`。 これがないと、面接官リストの最後に達したときにスキャンで有効な候補者が見逃されてしまいます。 もう 1 つの重要な詳細は、以下の場合にすぐに中断されることです。`z`これ以上の試行も容量の単調な枯渇により失敗するため、候補を見つけることができます。

 ### 例 1

 入力:```
3 2 2
```面接官は3名で、1名につき2回出演可能で、各面接は2名で行います。 

| ステップ | ポインタ p | 選択したグループ | 使用済みカウント |
 | --- | --- | --- | --- |
 | 1 | 1 | [1,2] | 1:1、2:1、3:0 |
 | 2 | 2 | [2,3] | 1:1、2:2、3:1 |
 | 3 | 3 | [3,1] | 1:2、2:2、3:2 |

 ステップ 4 では、すべての面接官が定員 2 に達しているため、サイズ 2 のグループを形成できません。構築は 3 回の面接で停止します。 

これは、周期的スキャンによって負荷が均等に分散され、全容量の使用が達成されることを示しています。 

### 例 2

 入力:```
4 1 3
```各面接官は 1 回のみ出席でき、各グループには 3 人の面接官が必要です。 

| ステップ | ポインタ p | 選択したグループ | 使用済みカウント |
 | --- | --- | --- | --- |
 | 1 | 1 | [1,2,3] | 1:1、2:1、3:1、4:0 |

 この時点で、インタビュアー 2 と 3 は再利用するとすでに容量を超えているため、2 番目の有効なグループは存在しません。 アルゴリズムは 1 回のインタビュー後に停止します。 

これは、多くの組み合わせが存在する場合でも、容量制約によってグループの数がどのように直接制限されるかを示しています。

 ## 特殊なケース

 いつ`z > x`の場合、アルゴリズムはすぐにゼロを返します。 たとえば、入力の場合`x=2, z=3`、どのスキャンでも十分な個別のインタビュアーを収集できないため、内部ループは常に失敗し、グループを生成せずに停止します。 

いつ`y = 0`, どの面接官も最初からキャパシティはゼロです。 スキャン ループでは候補が追加されることはありません。`group`決してサイズに達しない`z`、アルゴリズムは出力とともに直ちに終了します。`0`。 

いつ`x = z`、有効な面接ではすべての面接官が参加する必要があります。 アルゴリズムが生成するのは最大でも`y`各インタビュアーは反復全体で均一に消費されるため、同一の完全なグループになります。 これは、各ラウンドが利用可能なすべての容量を均等に使用する最適なパッキングと一致します。
