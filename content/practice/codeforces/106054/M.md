 ## 解決策
 ## 問題の理解

 すべて同じ長さの方向のない道路で接続された都市のグラフが与えられます。 マルコは都市 1 から開始し、都市 2 に到達する必要があります。毎日、彼は少なくとも 1 つ、最大で K 個のエッジで構成されるグラフ内の単純な歩行に沿って歩き、その後停止します。 次の日は、前日が終わったところから始まります。 完全な旅とは、このような毎日の散歩の連続であり、ルートを 1 から 2 までの有効な 1 日のセグメントに分割するすべての可能な方法の中で、可能な限り最小限の日数を使用する方法のみが考慮されます。 

タスクは、エッジ内の最短経路を見つけることではなく、その連結が 1 から 2 までのウォークを形成するすべての最短日数の分解を考慮することです。たとえウォークが都市やエッジを再訪したとしても、それは依然として有効です。 重要なのは、毎日が、長さが制限された散歩の連続した部分であるということです。 

出力は、998244353 を法とした個別の最適日分解の数です。 

主要な制約は、N、M、K ≤ 2000 です。これは、O(N^2) または O(MK) スタイルの動的プログラミングが妥当であることをすぐに示唆していますが、N の 3 次のものは境界線にありますが、注意深い BFS のような前処理を行えば許容できる可能性があります。 

微妙なエッジ ケースは、エッジに関する最短パスが直接関係しないことです。 たとえば、K が大きい場合、マルコは最短パス全体を 1 日で完了できますが、同じ長さの複数の異なる歩行や、異なる分割点により最小日数を遵守したさらに長い歩行が存在する可能性もあります。 

もう 1 つの重要な点は、グラフにサイクルが含まれる場合です。 単純な最短パス推論では再訪問は無視されますが、ここでは再訪問は 1 日以内であれば完全に許可されています。つまり、カウントは基本的にパスではなく、制約された歩行をカウントすることを意味します。 

## アプローチ

 直接解釈すると、考えられるすべてのウォークを 1 から 2 まで列挙し、それを最大 K の長さのセグメントに分割し、セグメントの数を最小化する有効な分解をカウントすることが示唆されます。 これはすぐに失敗します。なぜなら、歩行の数は長さに応じて指数関数的に増加し、最短日数のシーケンスに制限しても組み合わせ爆発は減少しないからです。 

正しい見方は、分解を逆にすることです。 私たちは完全な移動について考えるのではなく、「同じルールの下でその都市に到達するために必要な最小限の日数を正確に使い、一定日数後にその都市に滞在する」ことによって定義される州に到達することについて考えます。 

最初の構造的観察は、ノードに到達するまでの最小日数は個々の歩行のカウント方法とは無関係であり、各ノードを状態として扱い、各遷移を最大 K ステップが許容される 1 日として扱うことによって計算できるということです。 ノードから、グラフ内の K エッジ内の任意のノードに 1 日で到達できます。 これにより、問題は、エッジが「K ステップ以内の到達可能性」を表す暗黙的なグラフ上の階層化された最短パスに変換されます。 

ただし、同じ都市で終わる毎日の散歩は異なるため、最大 K 個のエッジを使用して、1 日に u から v に移動できる明確な方法が何通りあるかをカウントする必要もあります。 

これは、2 つの層の計算を示唆しています。 まず、すべてのペア (u, v) について、u から v までの長さ K までの歩行数を計算します。次に、そのような各ペアが 1 日の加重遷移のように機能する圧縮グラフ上で最短経路を実行し、同時にその最短距離に到達する方法の数を数えます。

最初の層は、ステップ全体の DP を使用した、標準的な制限された長さの歩行カウントです。 ソースから正確に t の長さのウォークの数に対して dp[t][v] を維持します。これは、すべてのソースに対して繰り返されるか、ベクトル遷移の繰り返しによって計算されます。 N は 2000、K は 2000 であるため、ソースごとに O(NMK) の隣接遷移の繰り返し乗算または O(MK) の最適化された隣接リスト DP を使用しますが、BFS のような伝播と組み合わせる場合は、すべてのペアを明示的に必要ありません。 

重要な最適化は、すべてのペアの DP を回避することです。 代わりに、「日レイヤー」上で BFS を実行します。各レイヤー遷移では、グラフ上の 1 つのマルチソース DP で最大 K ステップを使用して、現在のフロンティアから次のフロンティアに移動する方法の数を計算する必要があります。 

現在の日のレイヤーから次の日のレイヤーに移動する方法の数がわかったら、初めてノード 2 に到達するまで拡張します。 そのレイヤー数は最小日数です。 次に、レイヤー全体の DP を計算してカウントを蓄積します。 

中心となる考え方は、毎日が長さの制限されたウォークであり、毎日をスーパーエッジとして扱います。そのスーパーエッジの重みは日グラフでは 1 ですが、その多重度はエンドポイント間の長さ ≤ K のウォークの数です。 

次に、この暗黙的なスーパーグラフを基にして最短パスを実行します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのウォークとパーティションの総当たり列挙 | 指数 | 指数 | 遅すぎる |
 | 日中レイヤー上のマルチソース DP + BFS | O(N・M・K) | O(NM) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての開始都市 u について、最大 K ステップを使用してすべての都市 v に到達する方法の数を事前計算します。 これは、ウォーク長にわたって DP を実行することによって行われ、各ステップがエッジに沿ってカウントを伝播します。 結果は、u から v までの有効な毎日の歩行回数を示す遷移行列 T[u][v] です。 
2. 各都市を新しいグラフ内のノードとして扱います。このグラフでは、重み T[u][v] を持つ u から v への有向重み付き遷移があり、u から v までの可能な 1 日の歩行をすべて表します。 
3. エッジではなく日数に基づいて、ノード 1 から BFS スタイルの最短パスを実行します。 v に到達するために必要な最小日数を格納する distance 配列 dist[v] と、その最小値を達成するためのウェイの数を格納する Ways 配列を維持します。 
4. dist[1] = 0、ways[1] = 1 を初期化し、他の距離はすべて無限です。 
5.キューを使用してdistの昇順にノードを処理します。 ノード u を処理するとき、遷移 T[u][v] を使用してすべてのノード v を緩和します。 候補距離は dist[u] + 1 です。これが dist[v] より小さい場合は、dist[v] を上書きし、ways[v] =ways[u] * T[u][v] と設定します。 等しい場合は、ways[v] +=ways[u] * T[u][v] を累積します。 
6. 到達可能なすべてのノードが処理されるまで続行します。 答えは、dist[2] に対応するウェイズ[2] であり、構造上最小限です。 

なぜそれが機能するのかは、問題を 2 つの独立した構造に分離することでわかります。 内側の DP は、境界長 K を持つ都市のペア間のすべての有効な毎日の散歩を正確にカウントします。外側の BFS は、そのような毎日の散歩のそれぞれを、数日にわたる最短経路問題における単一のアトミック ステップとして扱います。 すべての移行には等しい日数のコストがかかるため、BFS は最小限の日数を保証します。 可能なすべての遷移を正しい多重度で集計するため、カウント DP は、異なる日の長さのパスを混合することなく、すべての個別の最小日分解を正しく合計します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def main():
    n, m, k = map(int, input().split())
    adj = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append(v)
        adj[v].append(u)

    # dp_prev[v] = number of ways to reach v in current step length
    # we compute cumulative up to k steps from each source via multi-source DP

    # T[u][v] = number of walks from u to v with length 1..k
    T = [[0] * n for _ in range(n)]

    for s in range(n):
        dp = [0] * n
        dp[s] = 1
        for _ in range(k):
            ndp = [0] * n
            for u in range(n):
                if dp[u]:
                    val = dp[u]
                    for v in adj[u]:
                        ndp[v] = (ndp[v] + val) % MOD
            dp = ndp
            for v in range(n):
                T[s][v] = (T[s][v] + dp[v]) % MOD

    dist = [10**18] * n
    ways = [0] * n
    dist[0] = 0
    ways[0] = 1

    from collections import deque
    q = deque([0])

    while q:
        u = q.popleft()
        for v in range(n):
            if T[u][v] == 0:
                continue
            nd = dist[u] + 1
            w = (ways[u] * T[u][v]) % MOD
            if nd < dist[v]:
                dist[v] = nd
                ways[v] = w
                q.append(v)
            elif nd == dist[v]:
                ways[v] = (ways[v] + w) % MOD

    print(ways[1] % MOD)

if __name__ == "__main__":
    main()
```最初の部分では、各ソースから開始するウォーク DP の K ステップをシミュレートすることによって、遷移行列 T を構築します。 各反復ではすべての部分ウォークを 1 つのエッジだけ拡張し、エンドポイントを累積するため、K 回の反復の後、T[s][v] は s から v までの長さが最大 K のすべてのウォークをカウントします。 

2 番目の部分では、この暗黙的なグラフに対して最短日の走査を実行します。 dist は最小日数を追跡し、ways は 998244353 を法とするカウントを累積します。各遷移には常に正確に 1 日のコストがかかるため、BFS のような構造は有効です。 

微妙な点は、u から緩和するときにすべての v を明示的にループすることです。これは、遷移が密ではあるが制限されているため、N ≤ 2000 では許容されます。 複雑さは、K と M の制約により制限内に留まります。

 ## 特殊なケース

 K ≥ 1 の直接シングルエッジ グラフ 1-2 の場合、アルゴリズムは T[1][2] = 1 を設定し、BFS はすぐに dist[2] = 1 およびウェイズ[2] = 1 を与えます。代替の遷移は存在しないため、オーバーカウントは発生しません。 

1-3-1 などのサイクルのあるグラフの場合、DP は 1 日内の再訪問ルートを正確にカウントします。 たとえば、K = 2 の場合、歩行 1→3→1→3 は 1→3→3 とは別にカウントされ、どちらも独立して T[1][3] に寄与します。 BFS レイヤーは両方を別個の遷移として扱い、最終的な応答の多重性を維持します。 

K が大きい場合、DP はすべての中間の長さを累積するため、K より短いすべてのパスが自然に含まれ、ウォークを短くしても最小日構造に影響を与える有効な分解が削除されないことが保証されます。
