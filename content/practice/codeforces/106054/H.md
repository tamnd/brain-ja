 ## 問題の理解

 未知の整数の約数の複数セットが与えられています$X$ですが、約数が 1 つありません。 合計すると、$X$まさに$N+1$正の約数が与えられます$N$彼らのうち。 提供されたすべての数値は必ず割り算されます$X$、完全な約数セットからちょうど 1 つの約数が存在しません。 タスクは、元の数値と数値を再構築することです。$X$または、有効な再構成が複数存在すると判断します。 

約数セットは厳格な構造を持っています。約数は常にペアで構成され、その積は次のようになります。$X$。 このペアリング プロパティは、指定されたすべての数値を接続する中心的な制約です。 欠落している約数は何らかの既知の約数とペアになる必要があり、そのペアリングによって候補値が決まります。$X$。 

制約により、最大で$2 \cdot 10^5$それぞれ最大の数値$10^{18}$。 これにより、候補値を試行するアプローチは即座に除外されます。$X$または大きな整数を繰り返し因数分解します。 操作は本質的に線形または線形に近いものでなければなりません。$N$、128 ビットの中間値の並べ替えと算術に依存するあらゆる解決策が受け入れられます。 

重複または一貫性のないペアリング候補が発生すると、微妙な問題が発生します。 複数の異なる値がある場合、$X$可能性があるか、異なる組み合わせが矛盾する結果を暗示している場合、答えは曖昧であり、出力する必要があります。`*`。 もう 1 つのエッジ ケースは、欠落している除数が次のいずれかの場合です。$1$または$X$、これらは常に互いにペアになっており、そのうちの 1 つが欠けると構造が非対称に変化するためです。 

最大の数が常に次の値であると仮定すると、単純な故障モードが発生します。$X$。 たとえば、欠落している除数が大きい場合、指定される最大値は次の値よりも小さくなる可能性があります。$X$、そのような貪欲な仮定は間違っています。 

## アプローチ

 ブルートフォースの観点は、約数のペアリングのプロパティから始まります。 なんとなく推測してみたら$X$、与えられたすべての数値がそれを割るかどうか、および欠落している約数も存在するかどうかをチェックすることで検証できます。 ただし、すべての候補を試してみると、$X$不可能だから$X$まで可能です$10^{18}$、候補の生成は入力値の組み合わせに依存します。 

より構造化されたアイデアは、次のことを知っていればという事実を利用することです。$X$、すべての約数$d$とペアリングする必要があります$X/d$。 ちょうど 1 つの約数が欠落しているため、指定されたリストを使用してこれらの組み合わせを「シミュレート」してみることができます。 約数を並べ替える場合、自然な試みは、最小値と最大値を組み合わせて、それらの積が一貫しているかどうかを確認することです。 これは、約数が欠落していない場合に機能しますが、ここでは要素が 1 つ欠落しているため、ペアリングがわずかに壊れています。つまり、1 つのペアが不完全になります。 

重要な洞察は、欠落している約数を直接推測することを避け、代わりにそれをペアリングの不一致の問題として扱うことです。 の候補値を仮定すると、$X$に等しい必要があります$a_i \cdot a_j$欠落している要素を含むいくつかのペアの場合。 つまり、有効なすべての$X$次の形式でなければなりません$a_i \cdot a_k$、 どこ$a_k$既知の約数か、欠落している約数のいずれかです。 

これは正しい構造観察につながります。与えられたすべての約数を並べ替えると、真の$X$どちらかに等しくなければなりません$a_0 \cdot a_{n-1}$(欠落要素によってペアリングが妨げられない場合)、または、除数の欠落によって引き起こされる 1 つの「ペアになっていない」要素を含む積からのものである必要があります。 エンドポイントのペアリングから派生した候補をテストし、線形時間で検証できます。 

中心的な方法は次のようになります。 もっともらしい候補の小さなセットを試してみる$X$、暗黙的に欠落している除数を導出し、すべての要素にわたる一貫性を検証します。

 ## アルゴリズムのチュートリアル

 まず、指定された約数を並べ替えて、ペア構造が見えるようにします。 有効な数の約数は対称であるため、並べ替えが必要です。$\sqrt{X}$。 

次に、次の候補値を構築しようとします。$X$。 当然の第一候補は、$a_0 \cdot a_{n-1}$、除数が欠けていても最も外側のペアが壊れないと仮定します。 また、除数が欠落しているため、エンドポイントの 1 つが誤ってペアリングされる可能性があることも考慮されているため、ペアリング構造を 1 回交換して 2 番目の候補をテストします。 

候補者ごとに$X$、2 ポインター手法を使用して除数のペアをシミュレートすることで検証します。 残りの最小値と最大値にポインターを維持します。 これら 2 つの値の積が等しい場合$X$、両方を内側に移動します。 それ以外の場合は、小さい値を欠落パートナーが必要な可能性があるものとして扱い、暗黙の欠落除数を次のように計算します。$X / a_i$。 この候補欠損値を記録し、検証を続行します。 複数の矛盾した欠損値、または除算が正確ではない不一致が発生した場合、この候補は$X$は無効です。 

すべての候補をチェックした後、有効な再構成が 0、1、または複数ある可能性があります。 有効なペアが 1 つだけの場合$(X, \text{missing})$存在する場合、それを出力します。 それ以外の場合は出力します`*`。 

重要な点は、各候補が 1 回のリニア スキャンで検証され、大規模な入力でも効率が確保されることです。 

### なぜ効果があるのか

 除数ペアリング プロパティは、すべての約数が 1 つの相補ペアに属することを強制します。その積は次のとおりです。$X$。 除数を 1 つ削除すると、そのようなペアが 1 つだけ切断されます。 他のすべてのペアはそのまま残り、完全に一致する必要があります。 したがって、有効な$X$1 つを除くすべてのペアの一貫性を維持する必要があり、アルゴリズムはこの条件を明示的にチェックします。 間違った候補があると、可分性に違反するか、複数の互換性のない欠損値が生成され、確実に拒否されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(arr, X):
    n = len(arr)
    i, j = 0, n - 1
    missing = None

    while i <= j:
        if i == j:
            # single leftover must be sqrt(X)
            if arr[i] * arr[i] == X:
                i += 1
                j -= 1
                continue
            if missing is None:
                missing = arr[i]
                i += 1
                j -= 1
                continue
            return None

        if arr[i] * arr[j] == X:
            i += 1
            j -= 1
        else:
            if missing is not None:
                return None
            if X % arr[i] != 0:
                return None
            missing = X // arr[i]
            i += 1

    if missing is None:
        return None
    return missing

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    candidates = set()

    candidates.add(a[0] * a[-1])
    candidates.add(a[0] * a[1])
    candidates.add(a[-1] * a[-2])

    best = None

    for X in candidates:
        if X <= 0:
            continue
        missing = check(a, X)
        if missing is None:
            continue

        # verify consistency
        full = a + [missing]
        if len(full) != len(set(full)):
            # duplicates are fine, but must still form valid divisor structure
            pass

        full.sort()
        ok = True
        for i in range(len(full)):
            if X % full[i] != 0:
                ok = False
                break
            if full[i] * full[-1 - i] != X:
                ok = False
                break

        if ok:
            if best is None:
                best = (X, missing)
            else:
                print("*")
                return

    if best is None:
        print("*")
    else:
        print(best[0], best[1])

if __name__ == "__main__":
    solve()
```この解決策は、候補の組み合わせが意味のあるものになるように除数リストをソートすることから始まります。 候補セットは意図的に小さくなっており、有効であるためエンドポイントから派生しています。$X$ほぼ正しいペアリング構造の極値に関連している必要があります。 

の`check`関数は、欠落している除数に対応する 1 つのブレークを許可しながら、除数のペアをシミュレートします。 これにより、すべての不一致が制御された方法で考慮され、欠損値が 1 つだけ導入されることがなくなります。 

欠落している約数の候補を生成した後、完全な約数リストを再構築し、厳密なペアリングの対称性を検証します。 この最終チェックにより、ローカルで一貫したペアリングが依然として有効な除数システムを形成しない場合の誤検知を防止します。 

よくある落とし穴は、除数が欠落していると、エンドポイントでローカルにだけでなく、ペアリング構造がグローバルに影響を受けることを忘れていることです。 再構築ステップにより、グローバルな一貫性が保証されます。

 ## 特殊なケース

 重大なエッジ ケースの 1 つは、欠落している除数が 1 または$X$。 その状況では、最小要素と最大要素は正しいペアを形成しなくなります。 ペアリング シミュレーションではエンドポイントで直ちに不一致が検出され、それに応じて欠損値が割り当てられるため、アルゴリズムはこれを処理します。 もし$1$が欠落している場合、再構築された約数は次のように表示されます。$X$、その逆も同様ですが、検証により一貫性が強制されます。 

別のエッジケースが発生するのは次の場合です。$X$は完全二乗であり、不足している約数はその平方根です。 この場合、2 ポインター スキャン中に、中央の要素が単独で表示されます。 アルゴリズムは条件を明示的にチェックします$a[i]^2 = X$、追加の欠落した割り当てを強制することなく、このシングルトンが確実に処理されるようにします。 

最後のエッジケースは、複数の候補値が存在する場合です。$X$ローカル検証には耐えられますが、グローバルな整合性は失われます。 最終的な再構成チェックでは、欠損値を挿入した後に完全な約数対称性を強制することでこれを検出し、誤ったあいまいな出力を防ぎます。
