 ## 解決策
 ## 問題の理解

 2D グリッド上の一連の点が与えられ、各点は保護する必要がある木の位置を表します。 政府は、軸に沿った単純な閉じた境界、つまり側面が座標軸に平行なフェンスを構築したいと考えています。 フェンスは、その内部のすべてのポイントを完全に囲む必要があります。 

追加の幾何学的制約があります。すべての木は厳密にフェンスから少なくとも 1 ユニット離れた位置になければなりません。 したがって、フェンスはポイントの厳しい境界ボックスを直接通過することはできません。 木とフェンスの間に全方向に 1 ユニットのバッファーが存在するように、外側に拡張する必要があります。 

目標は、この長方形のフェンスの全長を最小限に抑えることです。 

入力により、最大 100,000 点と最大 1 億の座標が得られます。 これにより、すべての点のペアを試したり、候補となる四角形を列挙したりするなどの 2 次または 3 次幾何学アプローチが即座に除外されます。 O(n log n) であっても許容されますが、点のペアごとの組み合わせを含むものは遅すぎます。 

微妙な失敗例は、ツリーが 1 つしかない場合に発生します。 その状況では、単純な境界ボックスの幅と高さがゼロになり、フェンスの長さがゼロであると誤って結論付ける可能性があります。 ただし、フェンスが少なくとも 1 ユニット離れているという要件により、フェンスは非縮退長方形に拡張されます。 

たとえば、入力が単一点 (2, 3) の場合、正しいフェンスは、その周囲を中心とする辺の長さ 2、周囲長 8 の 2 x 2 の正方形です。バッファ制約を忘れたソリューションでは、誤って 0 が出力されます。 

## アプローチ

 ブルートフォース手法では、考えられるすべての整数座標の中から左、右、下、上の境界を選択することによって、明示的に四角形を選択しようとします。 各候補長方形について、すべての点が少なくとも 1 単位のマージンを持って内側にあるかどうかを確認します。 境界候補を既存のポイントの近くの値に制限したとしても、最終的には O(n^4) 個、またはせいぜい O(n^2) 個の極値の組み合わせになり、これは 100,000 個のポイントで実現可能な値をはるかに超えています。 

重要な観察は、最適なフェンスの形状は点セットの極端な座標によって完全に決定されるということです。 フェンスは軸に沿って整列されており、均一なマージンを持つすべての点を含める必要があるため、左側の境界は最小の x 座標の 1 単位左に強制され、右側の境界は最大の x 座標の 1 単位右に強制されます。y についても同様です。 これらの極端な値が固定されると、自由はなくなります。いずれかの辺を縮小すると実現可能性に違反し、いずれかの辺を拡張すると周囲が増加するだけだからです。 

したがって、問題は、x 値と y 値の最小値と最大値を計算し、固定変換を適用することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^4) | お(1) | 遅すぎる |
 | 最適 (最小/最大スキャン) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 極端な座標を追跡しながらポイントを 1 回処理し、拡張された長方形とその周囲を計算します。

1. 極値を追跡するために 4 つの変数 (最小 x、最大 x、最小 y、最大 y) を初期化します。 これらは最初の点から始まるため、常に有効な境界が維持されます。 これにより、人為的なセンチネル値に依存することがなくなります。 
2. すべての点に対して繰り返します。 各点 (x、y) について、両方の座標の最小値と最大値を更新します。 このステップでは、すべてのポイントを含む可能な限り厳密な境界ボックスを効果的に構築します。 
3. すべてのポイントを処理した後、境界ボックスの幅を max_x から min_x を引いたものとして計算し、高さを max_y から min_y を引いたものとして計算します。 これらは、必要なバッファーを考慮せずに、すべてのツリーを含む軸に揃えられた最小の長方形を表します。 
4. 両方の寸法を 2 単位だけ拡張します。 これは、各辺を外側に 1 単位ずつシフトすることによって得られます。左は 1 減少し、右は 1 増加し、下は 1 減少し、上は 1 増加します。したがって、各次元は正確に 2 増加します。 
5. 幅と高さの合計の 2 倍を使用して、拡張された長方形の周囲を計算します。 これにより、フェンスの全長が決まります。 

最終的な式は 2 * ((max_x - min_x + 2) + (max_y - min_y + 2)) です。 

### なぜ効果があるのか

 実行可能なフェンスには、境界から少なくとも 1 の距離にあるすべてのポイントが含まれている必要があります。 これにより、最適な場合には、長方形の各辺が極値点のちょうど 1 単位外側に配置されます。 内向きの動きは、極端な点ですぐに実現可能性を壊します。 外側への移動は実現可能性を向上させることなく周囲を拡大します。 したがって、最適解は全方向に 1 単位ずつ均等に拡張されたバウンディング ボックスによって一意に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    min_x = min_y = 10**18
    max_x = max_y = -10**18

    for _ in range(n):
        x, y = map(int, input().split())
        if x < min_x:
            min_x = x
        if x > max_x:
            max_x = x
        if y < min_y:
            min_y = y
        if y > max_y:
            max_y = y

    width = max_x - min_x
    height = max_y - min_y

    width += 2
    height += 2

    print(2 * (width + height))

if __name__ == "__main__":
    solve()
```この実装は、バウンディング ボックス引数を直接変換したものです。 唯一の微妙な点は、有効な入力ポイントが正しく置き換えられるように、十分に大きなセンチネルを使用して極値を初期化することです。 もう 1 つの重要な詳細は、周囲を計算する前に 2 による拡張を適用する必要があることです。そうしないと、1 倍の間違いが発生しやすくなります。

| ステップ | ポイント | 最小_x | マックス_x | 分_y | 最大y |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (2,2) | 2 | 2 | 2 | 2 |
 | 2 | (4,3) | 2 | 4 | 2 | 3 |

 境界ボックスの幅は 5 - 2 = 3、高さは 3 - 2 = 1 です。拡張後、幅は 5、高さは 3 になります。周囲長は 2 * (5 + 3) = 16 です。 

これは、複数のポイントが内部構造ではなく、極値を通じてのみ結果に影響を与えることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    n = int(input())
    min_x = min_y = 10**18
    max_x = max_y = -10**18

    for _ in range(n):
        x, y = map(int, input().split())
        min_x = min(min_x, x)
        max_x = max(max_x, x)
        min_y = min(min_y, y)
        max_y = max(max_y, y)

    width = max_x - min_x + 2
    height = max_y - min_y + 2
    print(2 * (width + height))

# provided samples (reconstructed)
assert run("""3
2 2
4 3
5 3
""") == "16"

# minimum size
assert run("""1
1 1
""") == "8"

assert run("""3

2 1
3 1
""") == "12"

# vertical line
assert run("""3
5 1
5 2
5 3
""") == "12"

# all same x extreme spread
assert run("""2
1 10

""") == "204"

 ## 特殊なケース

 ワンポイントケースは最もデリケートです。 入力用`1 2 3`、アルゴリズムはすべての極値を等しく設定し、拡張前に幅と高さをゼロにします。 必要なバッファを追加すると、両方の次元が 2 になり、周囲長が 8 になります。拡張ステップを忘れたソリューションでは誤って 0 が出力され、距離要件に違反します。 

もう 1 つの特殊なケースは、すべての点が直線上にある場合です。 境界ボックスの幅または高さはゼロですが、拡張すると有効な四角形が生成されます。 アルゴリズムはバッファを適用する前に正の領域を想定していないため、これを自然に処理します。
