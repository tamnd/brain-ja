 ## 解決策
 ## 問題の理解

 私たちは非常に小規模な支払いシステムをモデル化しています。 顧客は次の価格の商品を購入したいと考えています$A$ペソ。 彼は 1 枚の請求書相当額で支払います$B$ペソなので、キオスクは正確に返さなければなりません$B - A$変化中のペソ。 面白いのは、キオスクではコインや紙幣は返されず、キャンディーだけが返され、各キャンディーには固定の価値があることです。$C$ペソ。 

問題は、価値のあるキャンディ全体だけを使用して正確な変化量を表現できるかどうかです。$C$。 言い換えれば、違いがあるかどうかを判断する必要があります。$B - A$次のように書くことができます$k \cdot C$ある整数に対して$k \ge 0$。 

制約は非常に小さく、すべての値は最大 1000 です。直接の算術チェックであっても定数時間であるため、これによりパフォーマンスやオーバーフローに関する懸念がすぐに解消されます。 

微妙な問題は、「正確な変更」という要件を理解することです。 キオスクが近づくだけでは十分ではありません。 残りや不足があると、解決策が無効になります。 たとえば、次の場合$A = 6$、$B = 10$、 そして$C = 3$、変化は 4 です。キャンディー 2 つで 6 は多すぎますが、キャンディー 1 つで 3 は少なすぎます。 これは、値が小さいにもかかわらず割り切れない直接的な例です。 

エッジケースは主に、計算ではなく、割り算ロジックに関するものです。 以来$A < B$、変化は常に正であるため、ゼロまたは負の変化を処理する必要はありません。 これにより、解釈における唯一の潜在的な曖昧さが解消されます。 

## アプローチ

 この問題を考える強引な方法は、可能な限りの数のキャンディーを試してみることです。 私たちが選ぶなら$k$キャンディー、お返しします$k \cdot C$ペソ。 反復できる$k$0から$\lfloor (B-A)/C \rfloor$そして、必要な変更と正確に一致する選択肢があるかどうかを確認します。 

これは正しいです。有効なトランザクションは次の整数倍だけです。$C$。 ただし、ここでは範囲が十分に小さいにもかかわらず、このアプローチは構造的に非効率であり、不必要です。 問題のより大きな変形では、すべてを反復します。$k$変化量の大きさは直線的になります。 

重要な観察は、可分性を超えた特別な構造を探しているわけではないということです。 違いがあるかどうかを確認しているだけです$B - A$で割り切れます$C$。 そうであれば、キャンディーを使用して正確な変化を形成できます。 そうでなければ不可能です。 

これにより、問題全体が 1 つのモジュロ演算に集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(B-A)$|$O(1)$| 受け入れられるが不要 |
 | 最適 |$O(1)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変化量を計算する$D = B - A$。 これは、キオスクが返さなければならない正確な値を表します。 
2. かどうかを確認します。$D$で割り切れます$C$、どうかを意味します$D \bmod C = 0$。 これが当てはまる場合、キャンディーを使用して正確に変化を形成することができます。 
3. 割り算条件を満たしている場合は「S」を出力し、そうでない場合は「N」を出力します。 

このチェックで十分な理由は、各キャンディーが正確に寄与しているためです。$C$ペソであり、非ネガティブ以外にキャンディーの数に制限はありません。 

### なぜ効果があるのか

 有効な解はすべて、変化を同じサイズ単位の合計として表す必要があります。$C$。 つまり、変更はセット内にある必要があります$\{0, C, 2C, 3C, \dots\}$。 この集合はまさに次の倍数の集合です。$C$。 このセットのメンバーシップは、次の値で割ったときの余りが 0 になることと同じです。$C$。 以来$D = B - A$は固定的かつ決定的であるため、割り算のチェックは実現可能性を完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

A, B, C = map(int, input().split())

change = B - A

if change % C == 0:
    print("S")
else:
    print("N")
```このソリューションは 3 つの整数を読み取り、必要な変更を計算し、モジュロ チェックを適用します。 重要な実装の詳細は、最初に差を計算し、その後でモジュロを適用することです。これにより、ロジックがクリーンに保たれ、複数の式についての推論が回避されます。 

有効な回答の構造は純粋に算術的なものであるため、ループやエッジケースの分岐は必要ありません。 

## 実用的な例

 入力:```

| ステップ | 変更 (B-A) | C | 変更%C | 決定 |

 | チェック | 10 | 5 | 0 | S |

 10 は 5 の 2 倍であるため、キオスクは 2 つのキャンディーを返すことができます。 

これは、可分性が成立する場合には必ず正確な表現が存在するという不変条件を裏付けます。 

### 例 2

```変化は4です。 

| ステップ | 変更 (B-A) | C | 変更%C | 決定 |

 ここで、キャンディーの合計が 4 になる整数はありません。キャンディー 1 個では少なすぎ、キャンディー 2 個では必要な量を超えます。 これは、なぜ割り算が必要なのかを端的に示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

 この制約により、定数時間の算術解を制限内で快適に実行できるようになります。 ブルートフォースループでも十分高速です。$A, B, C \le 1000$ただし、モジュロ チェックは条件を直接数学的に特徴付けたものです。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline
    A, B, C = map(int, input().split())
    change = B - A
    return "S" if change % C == 0 else "N"

# provided samples
assert run("10 20 5") == "S"
assert run("6 10 3") == "N"

# custom cases
assert run("1 2 1") == "S"   # exact 1 candy
assert run("1 3 2") == "S"   # 2 change with 1 candy
assert run("1 4 2") == "S"   # multiple candies exact fit
assert run("1 5 2") == "N"   # remainder case
assert run("999 1000 7") == "N"  # small edge non-divisible
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 2 1 | S | 最小の有効な可分性 |
 | 1 3 2 | S | 正確な単一のキャンディーケース |
 | 1 5 2 | N | 割り切れない余り |
 | 999 1000 7 | N | 最大値に近い境界 |

 ## 特殊なケース

 エッジ ケースの 1 つは、変更が 1 つのキャンディーの値と正確に等しい場合です。 入力用`A = 1, B = 4, C = 3`、変化は 3 です。アルゴリズムは次のように計算します。$3 \bmod 3 = 0$なので、正しく「S」が出力されます。 これは、キャンディーを 1 つだけ与えることに相当します。 

もう 1 つの特殊なケースは、小銭がキャンディーよりも小さい場合です。 入力用`A = 6, B = 10, C = 7`、変化は 4 です。4 は 7 で割り切れないため、モジュロ チェックは失敗し、出力は「N」になります。 これは、より大きな固定単位を使用してより小さな量を表すことが不可能であることを捉えています。 

最後のエッジケースは、変化がゼロの場合であり、制約の下では実際には起こりません。$A < B$。 許可されていても、ゼロは任意の正の値で割り切れるため、アルゴリズムは引き続き正しく動作します。$C$、「S」を生成し、キャンディーを与えないことが有効であるという事実と一致します。
