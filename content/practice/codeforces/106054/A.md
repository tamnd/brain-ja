 ## 解決策
 ## 問題の理解

 ラテン文字の大文字のみで構成された、固定長 10 の単一の文字列が与えられます。 この文字列から文字を削除することはできますが、残った文字を並べ替えることはできません。 問題は、いくつかの文字を削除した後、部分列「TAP」を取得できるかどうかです。 

したがって、このタスクは、「T」、「A」、「P」をどこからでも独立して見つけることではありません。 これらは元の文字列内でこの順序で出現する必要があり、場合によっては間に他の文字が含まれるため、それらの余分な文字は無視できます。 

文字列の長さは常にちょうど 10 であるため、制約は非常に小さくなります。 このことは、二次法や三次法ですら過剰であることがすぐにわかります。 線形スキャンで十分であり、サブシーケンスに対する強引な攻撃であっても、パフォーマンスの観点からは許容可能です。 

明示的に指摘する価値のあるエッジ状況がいくつかあります。 3 文字すべてを含むが順序が間違っている文字列は失敗します。 たとえば、「PATXXXTXXX」にはすべての文字が含まれていますが、正しい順序で含まれていないため、無効です。 もう 1 つのケースは、「CONTRACETO」など、必須の文字の 1 つが完全に欠落している場合です。これは、「P」がないためすぐに失敗します。 最後に、文字を繰り返すと誤解を招く可能性があります。 「TAAAPPPPPP」のような文字列は、最初の有効な「T」、次に任意の「A」、その後の「P」を順番を維持して選択できるため、有効です。 

## アプローチ

 この問題を考える強引な方法は、長さ 3 のすべてのサブシーケンスを検討し、それが「TAP」に等しいかどうかを確認することです。 文字列の長さは 10 であるため、そのようなサブシーケンスは最大で C(10, 3) = 120 個あり、それぞれのチェックは定数時間になります。 これはすでに制限内で快適に動作しており、推論も簡単です。 

ただし、このアプローチでは明示的に組み合わせを列挙しますが、これは不必要です。 問題の構造は、「T」、次の「A」、その次の「P」を順番に見つけることができるかどうかを問うだけです。 順序だけが制約であることがわかれば、問題をシングルパスの貪欲スキャンに減らすことができます。 

重要な点は、固定パターンに従って進行状況を追跡するだけでよいということです。 「T」を探し始めます。 それを見つけたら、前の文字を気にするのをやめて、「A」を探し始めます。 その後「A」が見つかったら「P」を探します。 なんとかパターンの最後まで到達できれば、答えは「はい」です。 

これが機能するのは、パターンの各文字が順番に一致する必要があり、先にスキップしても将来の有効な一致が妨げられることがないためです。

 ## アルゴリズムのチュートリアル

 1. ポインタを初期化する`i = 0`これは、現在、最初の不一致文字との一致を試みていることを意味します。 
2. 各文字を反復処理します。`c`入力文字列の左から右へ。 
3. もし`c`等しい`TAP[i]`、 前進`i`1つずつ。 これは、次に必要な文字を順番に照合できたことを意味します。 
4. いつでも`i`が 3 になると、すでに「TAP」の文字がすべて一致しているので、早めに終了できます。 
5. 文字列全体をスキャンした後 (または途中で停止した後)、`i == 3`。 ある場合は「S」を出力し、そうでない場合は「N」を出力します。 

試合だけを進める理由は、秩序を守る必要があるからです。 一致しない文字をスキップすると、部分文字列ではなく部分シーケンスを効果的に検索できます。 

### なぜ効果があるのか

 このアルゴリズムは、入力内の各文字を処理する前に、次の不変条件を維持します。`i`入力文字列の処理されたプレフィックスのサブシーケンスを使用して形成できる「TAP」の最長プレフィックスの長さを表します。 次に必要な文字と一致するたびに、このプレフィックスを 1 つだけ拡張します。 Because we only move forward in both the input and the pattern, we never invalidate earlier choices, and any valid subsequence must correspond to some sequence of successful advances of`i`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
target = "TAP"

i = 0
for c in s:
    if i < 3 and c == target[i]:
        i += 1
        if i == 3:
            break

print("S" if i == 3 else "N")
```コードは単一の入力文字列を読み取り、ポインターを維持します。`i`パターン「TAP」に合わせます。 各文字は、現在必要な文字と照合してチェックされます。 3 文字すべてが一致すると、それ以上スキャンしても結果が変わることはないため、早期に終了します。 最後の条件では、完全なパターンが一致したかどうかがチェックされます。 

微妙な点は早めの退場です。 正確性を保つためには不要ですが、長さが 10 の場合でも、これは主にスタイル上のものですが、成功するとすぐにスキャンが停止することが保証されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = sys.stdin.readline().strip()
    target = "TAP"
    i = 0
    for c in s:
        if i < 3 and c == target[i]:
            i += 1
    return "S" if i == 3 else "N"

# provided samples
assert run("CONTRAPELO\n") == "S"
assert run("XATPTKABPB\n") == "S"
assert run("XATPTPKABB\n") == "N"

# custom cases
assert run("TAPXXXXXXXX\n") == "S"
assert run("XXXXXXXXXX\n") == "N"
assert run("TTTAAAAPPPP\n") == "S"
assert run("PTAATPXABCD\n") == "N"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | タップXXXXXXXX | S | 開始時にすでに形成されています |
 | XXXXXXXXXX | N | 必要な文字がすべて不足しています |
 | てつやあっぷっぷ S | 複数のオカレンスは引き続き有効です。 
| PTAATPXABCD | N | 文字は正しいが順序が間違っている |

 ## 特殊なケース

 微妙なケースの 1 つは、必要な文字がすべて存在しているにもかかわらず、正しくインターリーブされていない場合です。 入力「PTAATPXABCD」の場合、スキャンでは最初に「T」が見つかりますが、その後に正しい進行の「P」につながる有効な「A」が見つかりません。 ポインタは第 2 段階でスタックし、アルゴリズムはそれを正しく拒否します。 

もう 1 つのケースは、繰り返しが多い場合です。 「TTTAAAAPPPP」の場合、アルゴリズムは最適な出現を選択しようとはせず、単に最初の有効な進行、つまり最初の T、その後の最初の A、その後の最初の P を取得します。 有効なサブシーケンスではパターン内で少なくとも 1 つの単調な進行が許可されるため、これにより正確さが保証されます。
