 ## 解決策
 ## 問題の理解

 柵で囲まれた庭園を表す凸多角形が与えられています。 1 つの頂点は特別です。ヤギはこの頂点に一定の長さのロープで結ばれています。$L$。 ヤギは多角形の外を自由に移動できますが、柵を通過することはできず、ロープ自体も柵を越えることはできません。 したがって、到達可能な領域は単なる半径円ではありません。$L$なぜなら、その円の一部が多角形のエッジによってブロックされる可能性があるためです。 代わりに、ヤギはポリゴンの境界の周りにロープを「巻き付ける」ことができ、開始頂点からスイープできる角度領域を効果的に増やすことができます。 

タスクは、複数のクエリに答えることです。ロープの長さごとに、ヤギが到達できる領域の正確な面積を計算します。 

入力制約は大きく、最大で$10^5$頂点と$10^5$クエリ。 これにより、クエリごとにジオメトリを最初から再計算したり、連続的な動きをシミュレートしたりするアプローチは即座に除外されます。 どのソリューションでも、ポリゴンを 1 回前処理し、各クエリに対数時間または定数時間で答える必要があります。 

微妙な問題は、到達可能な領域が単に「エッジで切り取られた円のセクター」ではないことです。 ロープが十分に長い場合、ヤギは境界に沿って歩いて、開始点から遠く離れた頂点に到達し、そのような各頂点から再び円弧を描くように拡張できます。 これにより、境界の接頭辞チェーンに沿って、複数のポリゴン頂点を中心とする円形セクターの結合が作成されます。 

単純な間違いは、ユークリッド距離のみで単調性を仮定することです。 たとえば、凸多角形では、開始点から最も遠くに見える点が必ずしも直線の半径方向に沿っているとは限りません。 最初に端に沿って歩く必要があるかもしれません。 もう 1 つの微妙な問題は精度です。角度を計算するには`acos`は不安定であり、問​​題は明らかにそれを示唆しています`atan2`。 

## アプローチ

 直接的な総当たり的なアイデアは、与えられたロープの長さでヤギがポリゴンの境界に沿ってどこまで到達できるかをシミュレートすることです。$L$。 頂点 0 から開始して、残りのロープの長さが不十分になるまで、周囲の距離を累積してエッジに沿って歩きます。 到達可能な各頂点で、隣接するエッジによってクリップされた残りのロープの長さに等しい半径の円のセクターを計算します。 

このアプローチはすぐに実行不可能になります。 クエリごとに、次のことを行う可能性があります。$O(N)$頂点を計算し、角度の寄与を計算して、$O(NQ)$時間。 と$10^5$頂点とクエリ、これは$10^{10}$限界をはるかに超えた操作。 

重要な構造上の観察は、多角形が凸状であり、頂点が接続点から反時計回りの順序で与えられていることです。 これにより、2 つの重要な特性が保持されます。 まず、開始点から境界に沿って歩くことは、開始頂点の周りの単調な角度スイープに対応します。 第 2 に、境界に沿ってより多くの頂点を順番に含めるにつれて、到達可能な領域が継続的に増加します。 

これにより、問題を再解釈することができます。ロープの連続的な動きについて推論する代わりに、最終領域に対する各境界頂点の寄与を考慮します。 各頂点は円形の扇形を構成し、その半径はその頂点に到達した後の残りのロープの長さであり、その角度は境界に沿って累積された外部回転角度です。 

プレフィックスのエッジの長さとプレフィックスの回転角度を事前に計算できます。 次に、各クエリは、ポリゴンの境界に沿ってどこまで移動できるかを見つけ、接頭辞上の平滑関数を合計することに帰着します。これは、接頭辞積分と二分探索を使用して高速化できます。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(NQ)$|$O(N)$| 遅すぎる |
 | プレフィックス + 二分探索 + 事前計算 |$O((N+Q)\log N)$または$O(N+Q)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 開始頂点をインデックス 0 として固定し、凸多角形に沿ったすべてのエッジ ベクトルとエッジ長を反時計回りの順序で計算します。 これにより、テザー ポイントから開始して境界に沿った自然な歩行が可能になります。 
2. エッジの長さのプレフィックスの合計を計算します。 これにより、任意の頂点について答えが得られます。$i$、最初から境界線に沿ってどのくらい離れているか。 歩行に費やされるロープの長さがまさに移動距離の境界となるため、これは非常に重要です。 
3. 以下を使用して各エッジ方向の角度を事前計算します。`atan2`。 連続するエッジから、各頂点での外部回転角を計算します。 多角形は凸面であるため、これらの角度はすべて正であり、合計すると次のようになります。$2\pi$。 
4. これらの回転角度のプレフィックスの合計を作成します。 これにより、ヤギが頂点に到達したときに累積される合計角度スパンを知ることができます。$i$。 この角度スパンは、ロープがその頂点に「巻き付く」ことができると、開始点の周囲の円のどれだけがアクセス可能になるかに対応します。 
5. ロープの長さの問い合わせについて$L$、まずヤギが境界に沿ってどこまで歩くことができるかを決定します。 プレフィックスのエッジ長に対する二分検索を使用して、最大のインデックスを見つけます$k$頂点 0 から頂点までの距離$k$せいぜい$L$。 
6. 頂点に達した後の残りのロープ$k$は$r = L - \text{dist}[k]$。 この残りの長さは、開始頂点を中心とし、頂点を越えてさらに外側に広がる円形のセクターを定義します。$k$。 
7. 合計エリアは 2 つの部分で構成されます。 最初の部分は、完全に到達した頂点からの寄与の合計です。$0$を通して$k$、それぞれが回転角度によって決定されるセクター領域に寄与します。 2 番目の部分は、頂点に残っているロープからの最後の部分的なセクターの寄与です。$k$、に比例$r^2$その頂点を超えて利用可能な角度スパンの倍。 
8. プレフィックス合計を使用して、完全な寄与を計算します。$O(1)$見つけた後$k$、最後の部分項を直接計算します。 

### なぜ効果があるのか

 ポリゴンの凸面により、境界ウォークが開始頂点の周囲の厳密に順序付けられた角度スイープに対応することが保証されます。 これにより、ヤギが新しい頂点に到達するたびに、新しく露出した領域が、重複したりくさびが欠けたりすることなく、以前に到達可能な領域に正確に追加された円形の扇形になることが保証されます。 頂点のプレフィックスは、到達可能な領域のジオメトリを完全に特徴付けるため、問題をプレフィックス距離とプレフィックス角度の合計に軽減することで、二重にカウントすることなく正確な面積が保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def atan2(y, x):
    return math.atan2(y, x)

N, Q = map(int, input().split())
pts = [tuple(map(int, input().split())) for _ in range(N)]
L = list(map(int, input().split()))

# edges
dx = []
dy = []
dist = [0] * N

for i in range(1, N):
    x1, y1 = pts[i-1]
    x2, y2 = pts[i]
    dx.append(x2 - x1)
    dy.append(y2 - y1)
    dist[i] = dist[i-1] + math.hypot(dx[-1], dy[-1])

# angle of edges
ang = [math.atan2(dy[i], dx[i]) for i in range(N-1)]

turn = [0.0] * N
for i in range(1, N-1):
    z1x, z1y = dx[i-1], dy[i-1]
    z2x, z2y = dx[i], dy[i]
    a1 = math.atan2(z1y, z1x)
    a2 = math.atan2(z2y, z2x)
    d = a2 - a1
    if d < 0:
        d += 2 * math.pi
    turn[i] = d

pref_turn = [0.0] * N
for i in range(1, N):
    pref_turn[i] = pref_turn[i-1] + turn[i]

def solve(Li):
    # binary search on farthest reachable vertex
    lo, hi = 0, N-1
    while lo < hi:
        mid = (lo + hi + 1) // 2
        if dist[mid] <= Li:
            lo = mid
        else:
            hi = mid - 1
    k = lo

    r = Li - dist[k]

    # sector-like accumulation
    area = 0.0
    area += 0.5 * pref_turn[k] * (Li ** 2)

    # remaining part
    if k < N - 1:
        area += 0.5 * (r ** 2) * (2 * math.pi - pref_turn[k])

    return area

out = []
for x in L:
    out.append(str(solve(x)))

print("\n".join(out))
```実装は、ポリゴンの境界に沿ってプレフィックス距離を構築することから始まります。 これにより、ロープがエッジに沿ってどこまで「歩く」ことができるかを高速にバイナリ検索できるようになります。 回転角度は次を使用して計算されます。`atan2`、不安定な逆コサイン計算を回避します。 

各クエリは二分検索を使用して、完全に到達可能な最後の頂点を見つけます。 残りのロープの長さは、その頂点を超えて利用できる追加の円形領域の量を定義します。 最終的なエリア式は、プレフィックス角度の寄与と残りのセクターの寄与に分割されます。 

デリケートな部分は角度の正規化です。すべてのエッジからエッジへの回転が強制的に行われます。$[0, 2\pi)$。 この補正がないと、負の角度の差によりプレフィックスの蓄積が中断されてしまいます。

 ## 特殊なケース

 重要なエッジケースは、ロープの長さがポリゴン境界全体を横断するのに十分な長さである場合に発生します。 この状況では、二分探索により最後の頂点が返され、残りのロープが完全な円セクターを構成します。 プレフィックス角度の合計は次のようになるため、アルゴリズムは引き続き機能します。$2\pi$となり、残りの期間はゼロになります。 

ロープが最初のエッジにかろうじて到達するときに、別のエッジケースが発生します。 それから$k = 0$、プレフィックスの合計はゼロで、部分セクター式のみが使用されます。 プレフィックス配列はインデックス 0 のゼロで初期化されるため、実装はこれを自然に処理します。 

3 番目のケースは、角度がラップアラウンドする場合の数値安定性です。$2\pi$。 正規化を行わないと、負の角度の差が誤って蓄積されてしまいます。 の`if d < 0: d += 2*pi`修正によりプレフィックスが単調に保たれるため、長いポリゴンでもドリフトや符号エラーが発生しません。
