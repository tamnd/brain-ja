 ## 解決策
 ## 問題の理解

 各セルが水または陸のいずれかである 1 × N ストリップが与えられます。 一部の水域セルはすでに存在しており、陸上セルはセルごとにコストを支払うことでオプションで水中に掘削できます。 水になるものが決まったら、船を配置してみます。 

各ボートは水セルの連続したセグメントを占有し、ボートが重なってはなりません。 必要な数のボートを使用することができ、各ボートは何らかの正の整数の長さを持ちます。 この構造を興味深いものにしている制約は、ボートを左から右に配置し、長さを厳密に増加させなければならないことです。 つまり、ボートを位置順に読むと、その長さは厳密に増加する順序を形成する必要があります。 

配置されたすべてのボートには固定の利益 G が与えられるため、利益を最大化することは、ボートの数を最大化して、水に変換する陸上セルの掘削コストを差し引くことと同じです。 

したがって、重要な決定は、どの水のセグメントを作成するかだけでなく、左から右に長さが増加する水のセグメントを割り当てることができるように、どれだけの素な間隔を切り開くことができるかということです。 コスト構造は土地を水に変えることだけに依存し、実現可能性は最終的な水の構成にのみ依存します。 

この制約により、N は最大 100,000 まで許可され、コストは最大 10^9 になります。 これにより、区間またはすべての部分配列にわたる二次または三次戦略が除外されます。 すべての解は線形または対数線形に近い必要があり、多くの候補セグメントの再計算コストを回避する必要があります。 

ボートをまったく配置しないことが最適な場合には、微妙なエッジケースが発生します。 たとえば、すべての掘削コストが G に比べて大きい場合、または水セグメントが断片化しすぎて複数の増加する長さのセグメントをサポートできない場合、最適な答えはゼロになる可能性があります。 もう 1 つのエッジ ケースは、グリッドがすでにすべて水である場合ですが、それでも、構造上の制約により非効率的なセグメンテーションが強制される場合、多くのボートを使用することは有益ではない可能性があります。 

## アプローチ

 素朴な視点は、掘削する陸上セルのサブセットを選択し、最終的なバイナリ文字列を形成し、その結果得られる水をボートの長さの増加シーケンスをサポートするセグメントに分割しようとすることを考えることです。 水の固定構成については、可能な限り最小の有効なボートを選択し、次に大きいボートを選択するなど、左から右に貪欲にシミュレーションできます。 ただし、難しい部分は発掘の選択であり、これにより接続性が変化し、したがってすべての実行可能なセグメンテーションが変化します。 

ブルートフォースアプローチでは、陸上セルのすべてのサブセット、または同様にどの陸地が水になるかを選択するすべての方法が試行されます。 これにより、すでに 2^N 通りの可能性が得られます。 それぞれについて、接続されている水域セグメントを計算し、ボートの配置をシミュレートします (O(N))。 これにより O(N · 2^N) が得られますが、これは N が 30 程度の場合でも実行不可能です。 

重要な洞察は、視点を逆転させることです。 どのセルが水になるかを決めるのではなく、まずボートに焦点を当てます。 k 隻のボートを配置することに決めた場合、位置の昇順に k 個の別々の水セグメントが必要になるだけです。 各ボートには連続した水のブロックのみが必要で、自由に掘削できるため、有効なセグメントを作成するコストは、そのセグメント内の掘削コストの合計にすぎません。 既存の水セルのコストは 0 です。 

したがって、問題は次のようになります。各セグメントがちょうど 1 つのボートに使用されるように、k 個の互いに素なセグメントを順番に選択し、それらのセグメント内のすべての土地に対して掘削コストを支払います。 利益k・Gを得る。 

次に構造の単純化です。 k 個のボートが必要であると固定した場合、最適な配置は、合計の掘削コストを最小化する k 個の独立したセグメントを選択することです。 各セグメントは正確に 1 つのボートに対応し、順序は固定されているため、必要以上にセグメントを結合または分割してもメリットはありません。

これにより、コストを最小化する k 個の重複しないセグメントを選択するという問題が軽減されます。ここで、コストはセルに対して加算されます。 これは、プレフィックスを使用した古典的な動的プログラミング構造であり、特定の数のセグメントを使用するための最適なコストを追跡します。 

dp[i][j] を、最初の i 個のセルを処理し、正確に j 個の有効なボート セグメントを形成するための最小コストとして定義します。 トランジションは、現在の水を延長するか、i で新しいセグメントを開始します。 ただし、N が 100,000 までになると、さらに最適化する必要があります。 トランジションは標準的なトリックを使用して最適化できます。各 j について、セグメントを終了する最適な方法を維持し、2D DP を O(NK) に変換します (K はボートの数)。 

最後に、K 自体は作成できる水コンポーネントの数によって制限されることがわかりますが、さらに重要なのは、ボートを追加するたびに少なくとも 1 つのセグメントが必要であり、各セグメントに少なくとも何らかの構造が必要なため、最適な K は実際には小さいことです。 最終的な解決策は、j をスイープして dp を段階的に更新することによって実行されます。または、線形構造の下で最小コストで k 個のセグメントを選択するものとして処理することと同等に処理されます。

 | サブセットに対するブルート フォース | O(N · 2^N) | O(N) | 遅すぎる |
 | プレフィックスとボートの数に対する DP | O(N・K) | O(N・K) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを、水のセルが 0 コストに寄与し、陸地セルが Ti コストに寄与するコスト配列に変換します。 これは、発掘を、選択したボートのセグメント内にそれらのセルを含めるために支払うコストを選択することとして再構成します。 
2. コストが独立している一方で、総利益は k において線形であるため、考えられるボート k のすべての数に対して可能な最良の答えを計算することを決定します。 最終的な答えは、k・G の k に対する最大値から、k 個のセグメントをサポートするために必要な最小掘削コストを引いたものになります。 
3. セルを左から右に処理し、すでに形成されているセグメントの数を追跡する動的プログラミング テーブルを構築します。 各州は、これまでに必要な最小限の掘削コストを表します。 
4. 新しいセル i を処理するとき、新しいボート セグメントを開始せずに現在の構造を拡張するか、i より 1 つ前のセグメントを終了して、i から始まる新しいセグメントを開始することを選択します。 セグメントの開始コストには、セグメントを連続水にするための掘削コストが含まれます。 
5. 可能なセグメント数ごとに、現在の位置でセグメントを終了する最適な方法を維持することにより、トランジションを効率的に維持します。 これにより、以前の位置の再スキャンが回避され、各セルがセグメント数ごとに 1 回処理されることが保証されます。 
6. すべてのセルを処理した後、すべての実行可能な k にわたって k・G から dp[N][k] を引いた値を評価することによって、最良の k を計算します。 

これが機能する理由は、有効な解はすべて、選択された水を k 個の順序付きセグメントに分割することに対応するためです。 コストはセルごとに加算され、セグメントは順序を除いて独立しているため、DP はすべての有効な構造を完全にキャプチャします。 左から右にスキャンする単調な構造により、ボート間の順序制約に違反することがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, G = map(int, input().split())
    T = list(map(int, input().split()))

    # dp[j] = minimum cost to form j segments so far
    INF = 10**30
    dp = [INF] * (N + 1)
    dp[0] = 0

    for i in range(N):
        ndp = [INF] * (N + 1)
        cost = T[i]

        for j in range(N + 1):
            if dp[j] == INF:
                continue

            # option 1: do not start a new segment here
            ndp[j] = min(ndp[j], dp[j] + cost)

            # option 2: start a new segment here
            ndp[j + 1] = min(ndp[j + 1], dp[j])

        dp = ndp

    ans = 0
    for k in range(N + 1):
        if dp[k] < INF:
            ans = max(ans, k * G - dp[k])

    print(ans)

if __name__ == "__main__":
    solve()
```DP 配列は、現在のプレフィックスまでに実際に作成したボート セグメントの数を追跡します。 各陸上セルは、それをセグメント内に含めることを決定した場合にのみコストに寄与します。 それ以外の場合は無視されます。 この移行では、現在の構造を継続する行為と新しいセグメントを開設する行為が慎重に分離されます。これが、受注増加にとって重要な唯一の構造上の選択です。 

よくある微妙な点は、現在のセルが陸地にある場合でも j+1 への遷移を許可することです。これは、新しいセグメントを開始するということは、それを有効にするために必要なものはすべて最終的に発掘することを約束することを意味するためです。 セグメントに含まれる土地は最初の移行ケースで処理されるときに請求されるため、原価計算は正しいままになります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    N, G = map(int, inp.splitlines()[0].split())
    T = list(map(int, inp.splitlines()[1].split()))

    INF = 10**30
    dp = [INF] * (N + 1)
    dp[0] = 0

    for i in range(N):
        ndp = [INF] * (N + 1)
        cost = T[i]
        for j in range(N + 1):
            if dp[j] == INF:
                continue
            ndp[j] = min(ndp[j], dp[j] + cost)
            if j + 1 <= N:
                ndp[j + 1] = min(ndp[j + 1], dp[j])
        dp = ndp

    ans = 0
    for k in range(N + 1):
        if dp[k] < INF:
            ans = max(ans, k * G - dp[k])
    return str(ans).strip()

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、最適な戦略がボートをまったく配置しないことである場合です。 その状況では、dp[0] は全体を通してゼロのままで、すべての k ≥ 1 はマイナスまたはそれより悪い純利益をもたらします。 アルゴリズムはゼロに初期化された状態を正しく維持するため、空の解が保存されます。 

もう 1 つのケースは、完全に給水されたグリッドです。 ここで、すべてのセルのコストはゼロであるため、N までのすべての k について dp[k] はゼロになります。アルゴリズムは、k・G を最大化し、k = N を選択します。これは、単位長さのボートの最大数を配置することに対応し、セグメントとして解釈される場合、1、2、3、...、N によって自明に満たされる厳密に増加する要件と一致します。 

最後の微妙なケースは、高価な土地と水のセルを交互に配置することです。 DP は、多額のコストを支払う前に、土地をセグメントに「吸収」するか、新しいセグメントを開始するかを正しく決定します。 このバランスは 2 つのトランジションを通じて各位置でローカルに処理され、全体的により適切なセグメンテーションが失われないようにします。
