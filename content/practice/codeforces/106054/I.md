 ## 解決策
 ## 問題の理解

 私たちは複数のラウンドにわたって繰り返される決定プロセスを与えられます。 各ラウンドには次のグループがあります。$N+1$選手：イネスと$N$その他。 各ラウンドでは、ゴールドを配布するための 2 つの可能なメカニズムが示されています。 

最初のメカニズムでは、プレイヤーの一部が「共有」することを選択します。 もし$k$合計プレイヤーがこの共有オプションを選択すると、合計プールは次のようになります。$X$、そしてそれらのそれぞれ$k$プレイヤーが受け取る$\lfloor X / k \rfloor$。 この値は、共有グループに参加するプレイヤーの数にのみ依存し、ID には依存しません。 

2番目のメカニズムでは、それを選択したプレイヤーは一定の金額を受け取ります$Y$、他から独立しています。 

各ラウンドで、他のラウンドが何であるかを知らされます。$N$プレイヤーが選択します。 イネスはその後、自分の選択肢を決定します。 彼女の決定はラウンドごとに純粋に貪欲です。彼女は、他の人の選択が固定されていると仮定して、オプション 1 とオプション 2 で自分の利益を比較し、より良い方を選択します。 どちらの選択肢でも彼女に同じ利益が得られる場合、彼女は共有を選択する必要があります。 

この戦略ですべてのラウンドをシミュレーションした後、イネスを含むすべてのプレイヤーが蓄積した合計ゴールドを計算する必要があります。 

制約$N, M \le 100$たとえ簡単なことであっても、$O(M \cdot N)$または$O(M \cdot (N+1))$シミュレーションで十分です。 ラウンドごとの直接評価以外の最適化は必要ありません。 

微妙な点は、イネスの決定が共有オプションにおける他の全員の報酬に影響を与えるということです。$k$。 これは、ラウンドごとに両方の仮想世界を評価する必要があることを意味します。1 つはイネスがオプション 1 を選択した場合、もう 1 つはイネスがオプション 2 を選択した場合です。 

素朴な推論を打ち破る可能性のあるエッジケースは、通常、再計算から発生します。$k$フロア分割が共有グループのすべての参加者に適用されることを間違っているか、忘れています。 

最小限の例外的な例としては、次のような場合があります。$X$共有者の数よりも少ないです。 たとえば、次の場合$X = 3$4人のプレーヤーが共有すると、全員が受け取ります$\lfloor 3/4 \rfloor = 0$。 フロアリングを忘れたり、プレイヤーごとに少なくとも 1 ユニットを想定した実装は間違っています。 

もう 1 つの例外的なケースはタイブレークです。 両方の選択肢がイネスに同等の利益をもたらす場合、彼女は選択肢 1 を選択する必要があります。これは将来の分配に影響するため、正確に実施する必要があります。 

## アプローチ

 直接的なアプローチは、コンセプトとして各ラウンドを 2 回シミュレートすることです。 特定のラウンドで、イネスがオプション 1 を選択して、共有に参加する合計プレイヤー数を計算し、プレイヤーごとの報酬を決定します。$\lfloor X/k \rfloor$。 次に、イネスの仮想ゲインを計算します。 オプション 2 についても同じことを行います。ここで、彼女の利益は単純に$Y$。 

この総当たり評価はラウンドごとにすでに十分です。$k$の数を数えているだけです$N$固定プレイヤーはオプション 1 を選択し、シナリオによってはイネス自身も選択する可能性があります。 つまり$O(N)$ラウンドごとに与える$O(MN)$総仕事量。 

以来$N, M \le 100$、せいぜいこれです$10^4$簡単な操作です。 

イネス以外のプレイヤーは決定を変更しないため、隠れた組み合わせの爆発はなく、イネスの選択が決定されると各ラウンドは独立します。 唯一の依存関係は、次の値を通る 1 ラウンド内にあります。$k$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(MN)$|$O(N)$| 承認済み |
 | 最適 |$O(MN)$|$O(N)$| 承認済み |

 実際には、「最適な」解決策は注意深くシミュレーションすることだけです。 

## アルゴリズムのチュートリアル

 各ラウンドを独立して処理し、すべてのプレイヤーの累積スコアを維持します。 

1. ラウンドごとに、次のことを読みます。$X$、$Y$、および選択肢の配列$N$選手たち。 これらのプレイヤーのうち何人がオプション 1 を選択するかをすぐに計算し、この値を呼び出します$c$。 この数によって、共有下のすべての結果が決まります。 
2. Inés がオプション 1 を選択したとします。この場合、共有者の数は次のようになります。$k = c + 1$。 イネスと選択肢 1 を持つすべてのプレイヤーを含むすべての共有者が受け取ります。$\lfloor X / k \rfloor$。 オプション 2 を選択したプレイヤーは、この分岐では何も受け取りません。 このシナリオの下でイネスの仮想ゲインを計算します。 
3. イネスがオプション 2 を選択したとします。ここで、彼女は次のメッセージを受け取ります。$Y$。 他のプレイヤーは、自分自身の選択に関して彼女の決定の影響を受けないため、分布を再計算する必要はありません。 意思決定において重要なのはイネスの見返りだけだ。 
4. 両方のシナリオでイネスの利益を比較します。 オプション 1 の方が高い値が得られる場合、彼女はそれを選択します。 オプション 2 の方が高い値が得られた場合、彼女はそれを選択します。 それらが等しい場合、タイブレーク ルールにより、彼女はオプション 1 を選択します。 
5. 彼女の決定が確定したら、そのラウンドの最終結果を計算し、各プレイヤーの合計に貢献度を加算します。 オプション 1 では、再び適切な$k$そして配布します$\lfloor X/k \rfloor$共有者の皆様へ。 オプション 2 の場合、イネスのみが利益を得る$Y$。 

重要な詳細は、共有結果をラウンドごとにシナリオごとに 1 回だけ再計算する必要があり、ラウンド間で段階的に再計算する必要はないということです。 

### なぜ効果があるのか

 イネス以外のプレイヤーによる固定の選択を除いて、各ラウンドは独立しているため、アルゴリズムは正しいです。 固定ラウンドの場合、イネスの決定は 2 つの決定的な値、つまり共有下での彼女の報酬と直接報酬下での報酬の比較のみに依存します。 共有の見返りは、両方の仮説ケースで事前にわかっている参加者の数によって完全に決定されます。 彼女の決定は今後のラウンド入力に影響を与えないため、局所的に最適なラウンドごとの決定により、正しい全体的な結果が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    ans = [0] * (N + 1)

    for _ in range(M):
        X, Y = map(int, input().split())
        A = list(map(int, input().split()))

        cnt1 = sum(1 for a in A if a == 1)

        # Option 1: Inés shares
        k1 = cnt1 + 1
        gain1 = X // k1

        # Option 2: Inés takes Y
        gain2 = Y

        if gain1 > gain2:
            take_share = True
        elif gain2 > gain1:
            take_share = False
        else:
            take_share = True

        if take_share:
            k = cnt1 + 1
            val = X // k
            for i in range(N):
                if A[i] == 1:
                    ans[i] += val
            ans[N] += val
        else:
            ans[N] += Y

            for i in range(N):
                if A[i] == 1:
                    ans[i] += 0

    print(*ans)

if __name__ == "__main__":
    solve()
```このソリューションは、各プレーヤーの現在までの合計を保持します。 各ラウンドで、最初に何人のプレイヤーがオプション 1 を選択したかをカウントします。これが必要な唯一のグローバル統計です。 次に、両方の選択の下でイネスの仮説上の利益を評価します。 タイブレークは、等しい場合に共有を優先することによって明示的に処理されます。 

最終決定を適用する際、共有ブランチはイネスを含むすべての参加プレーヤーに同じ値を分配します。 非共有ブランチは Inés のみを更新します。 

よくある実装上の間違いは、オプション 1 のシナリオで共有者のセットに Inés 自身が含まれていることを忘れていることです。これにより、分母が からずれてしまいます。$c$に$c+1$。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、グループ サイズが大きいために共有が非常に採算が悪くなる場合です。 たとえば、次の場合$X=1$すべてのプレイヤーが選択肢 1 を選択し、$k=N+1$整数の除算では 0 が生成され、すべての更新の一貫性が保たれるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、イネスだけがオプション 1 を選択し、他の全員がオプション 2 を選択する場合です。$k=1$、したがって、彼女は全額を受け取ります$X$。 この実装では、カウントに自分自身が正しく含まれ、ゼロによる除算や不正な分母が回避されます。 

最後の微妙なケースは、オプション間の平等です。 もし$X//(c+1) = Y$の場合でも、アルゴリズムは共有を選択する必要があります。 意思決定ブランチは明示的に等価性をチェックして共有パスを割り当て、下流の合計が問題の要件に一致することを保証します。
