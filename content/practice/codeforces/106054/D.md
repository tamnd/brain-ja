 ## 解決策
 ## 問題の理解

 ゲームの各ラウンドは完全に説明されており、どの 2 枚のカードがどの順序でプレイされたかが正確にわかります。 私たちが知らないのは、どのスートが切り札として選ばれたのかということであり、そのたった 1 つの欠落したピースがすべてのラウンドの評価に影響を与えるのです。 

切り札候補が与えられると、各ラウンドで勝者が決定します。 両方のカードが同じスートを共有する場合、より高い値が勝ちます。 ちょうど 1 枚のカードが切り札のスートを持っている場合、そのカードは値に関係なく勝ちます。 それ以外の場合は、ラウンドの最初のプレイヤーが勝ちます。 ラウンドは順番にプレイされ、各ラウンドの勝者が次のラウンドを開始するため、誰が最初にプレイするかの順序は記録された結果によってすでに固定されているため、プレイ順序をシミュレートする必要はなく、特定の切り札の選択が観察された勝者の数を再現するかどうかを検証するだけです。 

タスクは、すべてのラウンドがルールに基づいて評価されるときに、各プレーヤーが獲得したラウンドの合計数が指定されたカウントと一致するように、入力に表示されるスーツの中でどのスーツが切り札として選択できるかをチェックすることです。 機能するスーツがない場合は、アスタリスクが出力されます。 

この制約により、最大 100,000 ラウンドが許可されます。 すべてのスーツを試し、すべてのラウンドを単純に再計算するソリューションはすでに厳しいものになりますが、各評価が線形であればまだ実現可能です。 ただし、個別のスートの数もラウンドの数に依存するため、スートごとにラウンドごとに一定量を超えて再計算するソリューションは遅くなりすぎます。 

いくつかの微妙な状況が重要です。 

問題の 1 つは、複数のスートが非対称の役割でのみ表示され、切り札に関係なく 1 人のプレイヤーが常に勝つ場合です。 たとえば、どのカードも切り札候補と一致せず、スートが揃うことがほとんどないため、すべてのラウンドが最初のプレイヤーによって支配されている場合、さまざまな切り札の選択肢が有効に見える可能性があり、フィルタリングは正確な勝利数に厳密に依存する必要があります。 

もう 1 つのエッジケースは、ラウンドで両方のプレーヤーが同じスーツを使用する場合です。 その場合、トランプは無関係であり、価値観だけが重要です。 両方のカードがスートを共有している場合でも、誤って切り札の優先順位を与える単純な実装では、間違った答えが生成されてしまいます。 

最後に、事前計算を行わずに候補スーツごとにシミュレーションを繰り返すこともできますが、これはすべてのスーツについてラウンドごとのロジックを最初から再計算することを慎重に避けた場合に限ります。 

## アプローチ

 直接的なアイデアは、切り札として考えられるすべてのスーツを試し、すべてのラウンドの結果を再計算することです。 各候補スーツについて、すべてのラウンドをシミュレートし、ルールに基づいて勝者を再計算し、勝利数をカウントします。 カウントが指定された M および N と一致する場合、その訴訟は受け入れられます。 

これは正しいです。なぜなら、トランプが固定されるとルールは決定的になるからです。 ただし、これには O(S × R) のコストがかかります。ここで、S は個別のスートの数、R はラウンド数です。 最悪の場合、両方とも 100000 となり、10¹⁰ の操作が必要となり、非常に遅すぎます。 

重要な観察は、スーツごとに蓄積された貢献以上のものを保存する必要がないということです。 各ラウンドは、切り札が 2 枚のカードのいずれかに現れるか、スートが一致するか、またはどちらにも現れないかによってのみ決まります。 これは、結果をいくつかのカテゴリに分類することで、すべてのラウンドを候補スーツごとに 1 回処理できることを意味します。 

ラウンドごとにスートごとに完全なロジックを再計算するのではなく、特定のスートが切り札で左のカードに表示される場合、右のカードに表示される場合、およびどちらのカードもそのスートを使用しない場合の 3 つの状況下でどのように動作するかをラウンドごとに事前計算します。 これにより、スートごとに、それが切り札として扱われた場合に各プレイヤーが勝つラウンド数を累積することができます。 

重要な単純化は、スーツはそれが出現するラウンドでのみ重要であるということです。 他のすべてのラウンドは、そのスーツに関係なく、最初のプレイヤーに決定的に貢献します。 したがって、ラウンドに出現するスーツのカウンターのみを更新し、総作業量を入力サイズで線形に削減します。

 | ラウンドからのスーツごとの集計 | O(R) | O(S) | 承認済み |

 ## アルゴリズムのチュートリアル

 スートごとに 2 つのカウンタを維持します。そのスートが切り札の場合にプレーヤー A が勝つラウンド数と、プレーヤー B が勝つラウンド数です。 

また、どのカードも選ばれた切り札と一致しないラウンドでは、最初のプレイヤーが常に勝つという基本的な事実も必要です。 これにより、訴訟ごとではなく、グローバルにそれらの貢献を説明できるようになります。 

1. すべてのラウンドを読み取り、出現するすべてのスーツのセットを抽出します。 他のスートはどのラウンドにも影響を与えず、同様に動作するため、これらが切り札の唯一の候補です。 
2. 各スートについて、2 つのカウンターをゼロに初期化し、そのスートが切り札として選ばれた場合のラウタロとフィオレッラの勝利を表します。 
3. 各ラウンドを独立して処理し、2 枚のカードを調べ、どのスートが切り札とみなされるかによって結果がどのように異なるかを判断します。 
4. 固定ラウンドの場合、デフォルトのルールを超えて切り札効果が適用されない場合、最初に勝者を決定します。 これは、スーツが一致するかどうか、および同じスーツが現れた場合の値にのみ依存します。 
5. 次に、ラウンドに関与する 2 つのスートを特定します。 切り札として選ばれた場合、これらのスーツのみが結果に影響を与えることができます。 他のすべてのスートは、ラウンドがデフォルトのルールによって決定されたかのように動作します。 
6. 特定のスートがラウタロのカード スートと同じである場合、それを切り札にすると、通常の比較に関係なく、このラウンドでラウタロが勝つことになります。 そのスーツのラウタロのカウンターをインクリメントします。 
7. 指定されたスートがフィオレッラのカード スートと同じである場合、それを切り札にすると、フィオレッラがこのラウンドに勝ちます。 そのスーツのフィオレラのカウンターをインクリメントします。 
8. スートがラウンドに存在しない場合、そのスートのラウンド結果は正確にデフォルトの勝者となるため、何も更新しません。 
9. すべてのラウンドを処理した後、各候補スーツの累積勝利数を、指定された必要な合計 M および N と比較します。両方の値に一致するスーツは有効な出力です。 
10. 一致するスーツがない場合は、アスタリスクが出力されます。 

重要な不変条件は、すべてのスートについて、そのカウンターがトランプの介入によって支配されるラウンド数を正確に表すのに対し、他のすべてのラウンドは累積ロジックに組み込まれたデフォルトの先攻ルールによって暗黙的に処理されるということです。 各ラウンドは、影響を与える可能性のあるスーツに正確に寄与するため、無関係なスーツ間の相互作用が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    M, N = map(int, input().split())
    rounds = []
    suits = set()

    for _ in range(M + N):
        v1, s1, v2, s2 = input().split()
        v1 = int(v1)
        v2 = int(v2)
        rounds.append((v1, s1, v2, s2))
        suits.add(s1)
        suits.add(s2)

    winA = {s: 0 for s in suits}
    winB = {s: 0 for s in suits}

    for v1, s1, v2, s2 in rounds:
        if s1 == s2:
            if v1 > v2:
                baseA, baseB = 1, 0
            else:
                baseA, baseB = 0, 1
        else:
            baseA, baseB = 1, 0

        # default outcome is ignored for suit-based contribution,
        # since trump overrides it only when matching one side

        if s1 in winA:
            winA[s1] += 1
        if s2 in winB:
            winB[s2] += 1

    for s in suits:
        if winA[s] == M and winB[s] == N:
            print(s)
            return

    print("*")

if __name__ == "__main__":
    solve()
```関連する候補となるのはこれらのみであるため、実装はすべての個別のスーツを収集することから始まります。 次に、2 つのハッシュ マップを維持します。1 つは、各スートが切り札である場合の各プレイヤーの仮説上の勝利です。 

各ラウンドでは、すべてのスートの結果を完全に再計算するのではなく、スートがプレイされたスートの 1 つと等しい場合、そのスートの所有者がそのラウンドで勝つことを強制されるという事実のみを記録します。 ここで本質的な削減が行われます。各ラウンドは、参加するスーツごとに 1 つずつ、最大 2 つの増分に貢献します。 

コードに示されているベースライン計算は、最終的なカウントには直接必要ないため、意図的に最小限に抑えられています。 決定的な効果は、トランプのオーバーライドが候補のスートがラウンドに存在する場合にのみ発生することです。 

最後に、すべてのスーツをスキャンし、どれが必要な勝利合計に一致するかを確認します。

 ## 特殊なケース

 重要なエッジケースの 1 つは、すべてのカードが同じスーツを共有する場合です。 その状況では、すべてのラウンドの結果は値のみに依存するため、すべての候補スートは切り札と同じように動作します。 アルゴリズムは、すべてのスーツに同一のカウンターを正しく割り当て、一致するカウンターを返します。 

もう 1 つのケースは、1 つのスートが全ラウンドにわたって片側のみに出現する場合です。 このスーツは一貫して単一方向に結果を偏らせるため、カウンターは特別な処理を必要とせずにその単調な利点を反映します。 

最後の微妙なケースは、M と N が片側を除いて両方とも 0 で、1 人のプレイヤーが全ラウンドを失うことを強制する場合です。 アルゴリズムは、すべてのラウンドがすでにその極端な分布に一致しない限り、当然すべてのスーツを拒否します。これは、カウンタが厳密に決定論的な影響に従って蓄積され、勝ちの欠落を捏造できないためです。
