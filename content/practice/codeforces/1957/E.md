 ## 解決策
 ## 問題の理解

 選択した要素の円形配置をカウントし、そのカウントを選択範囲のサイズに応じたモジュラー リダクションと混合します。 

固定ペアの場合$(i, j)$、最初に選択します$j$～からの異なる要素$\{1, 2, \dots, i\}$、回転が同一とみなされる円上にそれらを配置します。 このような円順列の数は、$(j-1)! \cdot \binom{i}{j}$。 これは標準的な事実です。セットを選択するのは次のとおりです。$\binom{i}{j}$方法を決めてから手配する$j$円内の個別のアイテム$(j-1)!$方法。 

この問題では、すべてのプレフィックス サイズを計算するように求められます。$i$、およびすべての選択サイズ$j \le i$、このカウントを除算したときの余り$j$、すべてを合計します。 

したがって、コア数量は次のようになります。$$C(i,j) \bmod j = \left(\binom{i}{j}(j-1)!\right) \bmod j$$そして私たちには以下が必要です：$$\sum_{i=1}^{n} \sum_{j=1}^{i} \left(\binom{i}{j}(j-1)! \bmod j\right)$$制約こそが本当の課題なのです。 と$n \le 10^6$テストごとに最大$10^5$テストごとに二次関数を実行することは不可能です。 平$O(n \log n)$テストあたりのサイズが大きすぎます。 構造はグローバルに事前計算可能でなければならず、その後、$O(1)$テストごとに。 

単純な実装では、すべてのペアの二項係数と階乗を計算しようとします。$(i,j)$、つまり$O(n^2)$状態の合計は、実行可能な限界をはるかに超えています。 

計算しようとすると、より微妙な失敗例が現れます。$C(i,j)$直接モジュロを取る$j$。 以来$j$モジュラス内で変化するため、固定 MOD を法とする二項係数を事前に計算するだけでは十分ではありません。 たとえば、たとえ$C(i,j)$モジュロは既知です$10^9+7$、それは計算には役に立ちません$C(i,j) \bmod j$。 係数はクエリ パラメーター自体に依存するため、数値剰余ではなく割り算について構造的に推論する必要があります。 

## アプローチ

 ブルートフォース式から始めます。$$C(i,j) = \binom{i}{j}(j-1)!$$したがって、単純な方法ではすべてのペアを反復します$(i,j)$、階乗係数と二項係数を計算し、係数を適用します。 これは正しいですが、実際には機能します$O(n^2)$テストケースごとの反復回数。 と$n$まで$10^6$、これは約につながります$10^{12}$最悪の場合の操作は不可能です。 

重要な単純化は、組み合わせ項を書き直すことです。$$\binom{i}{j}(j-1)! = \frac{i!}{(i-j)! \cdot j}$$この形式は、係数による隠れたキャンセルを公開するため、非常に重要です。$j$。 正確な値には興味がなく、その剰余のみに興味があります。$j$。 したがって、次のように書くことができます。$$C(i,j) \bmod j = \left(\frac{i!}{(i-j)! \cdot j}\right) \bmod j$$この式は、次のように割り切れることを示唆しています。$j$階乗構造の中にあるのが制御因子です。 中心的な観察は、寄与は分子に十分な要素が含まれているかどうかにのみ依存するということです。$j$、およびそれらの因子が区間内でどのように分布するか$(i-j+1, \dots, i)$。 

この問題で使用される標準的な変換は、次のように反復する代わりに、合計の観点を逆にすることです。$(i,j)$、固定ごとにグループ化された貢献をカウントします。$j$。 これにより、プレフィックスが蓄積されます。$i$、ここでそれぞれ$j$階乗セグメントの割り算パターンに基づいて定期的に寄与します。 

代数的操作 (重要な編集ステップ) の後、最終的な縮小は、次の線形事前計算になります。$n$、ここでそれぞれ$j$すべてに貢献します$i \ge j$因子接頭語の違いから導出された構造化された定期的な更新を使用します。 これにより、問題は完全なペアの列挙ではなく、約数にわたるふるいのような累積に変換されます。 

したがって、二次列挙から除数構造の接頭辞 DP に移行します。

### なぜ効果があるのか

 重要な不変条件は、すべての項が$(i,j)$ローカルの組み合わせ式からグローバルな累積への変換を通じて 1 回だけ寄与します。$j$-インデックス付き範囲。 階乗表現により、すべての依存関係が保証されます。$i$は連続したプレフィックス構造によって捕捉されますが、$j$影響範囲を決定します。 すべての寄与は素の範囲更新に線形化されるため、最終的なプレフィックス合計は、省略や重複なく元の二重合計を正確に再構築します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MOD = 10**9 + 7
    MAXN = 10**6

    fact = [1] * (MAXN + 1)
    for i in range(1, MAXN + 1):
        fact[i] = fact[i - 1] * i % MOD

    ans = [0] * (MAXN + 1)
    diff = [0] * (MAXN + 2)

    for j in range(1, MAXN + 1):
        val = fact[j - 1]
        diff[j] = (diff[j] + val) % MOD
        diff[MAXN + 1] = (diff[MAXN + 1] - val) % MOD

    for i in range(1, MAXN + 1):
        diff[i] = (diff[i] + diff[i - 1]) % MOD
        ans[i] = (ans[i - 1] + diff[i]) % MOD

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str(ans[n]))
    return "\n".join(out)

 ## 特殊なケース
