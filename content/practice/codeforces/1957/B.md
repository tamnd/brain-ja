 ## 解決策
 ## 問題の理解

 長さの配列を構築するように求められます`n`合計が正確に一致する非負の整数で構成される`k`。 このようなすべての配列の中で、すべての要素のビット単位の OR で設定されるビットの数を最大化したいと考えています。 

OR 演算は「ビット結合」のように動作します。数値にビットが含まれると、最終結果ではそのビットが 1 になります。 したがって、本当の目的は、個々の値を直接扱うことではなく、最終的な OR でどのビット位置をアクティブ化できるかということです。 

合計に対する制約がこれを興味深いものにしています。 何らかの数値に設定した各ビットには少なくともコストがかかります`2^b`合計貢献度は配列内のどこかにあるため、固定予算を効果的に配分することになります。`k`できるだけ多くの個別のビット位置をアクティブにします。 

境界を見ると、テスト ケースごとに線形に近い解決策が必要であることがわかります。 合計から`n`テスト全体にわたって`2e5`、それ以上のソリューション`O(n log k)`または同様のものは安全ですが、テストごとに二次関数を実行することは不可能です。 単純なサブセットまたはビットマスク上の DP はすぐに失敗します。`k`まで上がります`1e9`、最大 30 ビットを意味します。 

単純な推論による微妙な失敗例は、常に次のようにする必要があると仮定することです。`k`1 つの数字と他の数字ではゼロです。 OR = が生成されます。`k`, しかし、これは最適とは程遠いことがよくあります。 たとえば、次の場合`k = 7`、1 つの数値で OR = が得られます。`111`(3 ビット)、ただし次のように分割`1,2,4`OR = を与える`111`同様に、次の場合に重要になる構造も使用しています。`n`が大きいため、残りの分配が必要です。 

本当の緊張感が現れるのは、`n > 1`: 値を自由に「拡散」して OR を形成できますが、合計の実現可能性を失ってはなりません。 

## アプローチ

 強引なアイデアでは、あらゆる配布方法を試すことになります。`k`の中へ`n`パーツを分割し、毎回 OR を計算します。 値を次のように制限したとしても、`0..k`、の作曲数`k`の中へ`n`パーツは天文学的に大きく、おおよその組み合わせのサイズであるため、これは直ちに不可能です。 

重要な観察は、OR は少なくとも 1 つの要素にどのビットが現れるかのみに依存するということです。 OR 内の 1 の数を最大化するには、アクティブ化するために「余裕がある」個別のビット位置の数を最大化する必要があります。 

少し活性化`b`少なくとも出費が必要`2^b`配列内のどこかにあります。 したがって、合計が次を超えない異なる 2 のべき乗のセットを選択したいと考えます。`k`そして、そのようなパワーを選択する数を最大化したいと考えています。 これは分解するのとまったく同じです`k`異なる 2 のべき乗の合計に変換されますが、非負性と合計の制約が尊重される限り、残りを任意に分配できるという特別な自由が与えられます。 

貪欲な戦略が自然になります：すべてのビットを取得します`k`バイナリ形式で。 これにより、すでに可能な限り最良の OR が得られます。これは、どの数値もそのバイナリ表現に存在するビットのみを寄与でき、値を分割しても合計バジェットに存在するビットを超えて新しいビットを作成できないためです。 

私たちが代表したら`k`2 のべき乗の合計として、各べき乗を個別の配列要素に割り当てます。 まだスロットが残っている場合は、それらをゼロで埋めます。 これにより、サイズ制約を満たしながら、OR が変更されなくなります。 

正確かどうかは、2 の累乗をより小さい値に分割しても個別の OR ビットの数を増やすことができないという事実にかかっています。 上位ビットのみが保存または破棄されます。

 ## アルゴリズムのチュートリアル

 1. 書くことから始めます`k`バイナリでビットが設定されているすべての位置を識別します。 このような各ビットは、配列内のどこかに割り当てる必要がある 2 のべき乗に対応します。 これにより、予算から可能な限り最大の独立したビット寄与を確実に抽出することができます。 
2. 設定されたビットごとに 1 つの配列要素を作成します。`k`、それに値を代入します`2^b`。 これにより、選択されたすべてのビットが最終的な OR に現れることが保証されます。 
3. 設定ビット数が大きい場合`n`、それぞれを独自のスロットに割り当てることはできません。 その場合、より小さな貢献を既存の数値に貪欲にマージする必要があります。 ビットを結合しても OR で上位ビットが失われることはなく、大きなビットをできるだけ長く分離して保持したいため、常に下位ビットを最初にマージします。 
4. 設定ビット数以下の場合`n`、それぞれを置きます`2^b`独自の位置に配置し、残りの位置をゼロで埋めます。 OR は、すべての設定ビットの OR のままになります。`k`。 
5. 初期値を配置した後、残った値を分配します。`k'`(正確なバイナリ分解を使用したため、この構築ではゼロになります) 新しい上位ビットを作成することなく、任意の 1 つの位置に変換されます。 実際には、バイナリ分解は既に次のように合計されるため、このステップは不要です。`k`。 

### なぜ効果があるのか

 OR の結果は、すべての数値にわたってどのビット位置が少なくとも 1 回出現するかによってのみ決まります。 代表する`k`in binary は、合計制約を超えずに表現できるビット位置の最大セットを与えます。 ビットを「シフト」または「マージ」しようとする代替表現では、既に存在するビット位置を超えて新しいビット位置を導入することはできません。`k`、ビット位置を増やすには少なくとも支出が必要なため`2^b`、これにより、予算からより小さな部分が削除されます。 したがって、バイナリ表現は達成可能なすべてのビット位置をすでに飽和させており、各ビットを個別に分散することで、OR の寄与を失わないようにすることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())

    bits = []
    for b in range(31):
        if k & (1 << b):
            bits.append(1 << b)

    if len(bits) > n:
        # merge smallest bits greedily into remaining slots
        # start with all ones
        res = bits[:]
        while len(res) > n:
            a = res.pop()
            b = res.pop()
            res.append(a + b)
        res += [0] * (n - len(res))
    else:
        res = bits + [0] * (n - len(bits))
        # put remaining sum into one slot (all consumed already by bits sum == k)

    print(*res)
```実装では、バイナリ表現を直接抽出します。`k`。 設定された各ビットは 1 つの配列要素になります。 要素がこれより少ない場合`n`、OR には影響しないゼロを埋め込みます。 

唯一の微妙な点は、ビットが多すぎるという仮定のケースですが、`k ≤ 1e9`、最大 30 ビットなので、このケースでは有効な制約が実際にトリガーされることはありません。`n ≥ 1`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(sys.stdin.readline())
    out = []
    for _ in range(t):
        n, k = map(int, sys.stdin.readline().split())
        bits = []
        for b in range(31):
            if k & (1 << b):
                bits.append(1 << b)
        res = bits + [0] * (n - len(bits))
        out.append(" ".join(map(str, res)))
    return "\n".join(out)

 ## 特殊なケース

 主なエッジケースは次のような場合です`k`は 2 の累乗です。 例えば、`n = 5, k = 8`。 分解結果は`[8]`、残りはゼロです。 OR は`1000`、再配置しないと、追加のセット ビットが導入される可能性があります。 アルゴリズムは、単一の非ゼロ要素とパディングを生成することでこれを自然に処理します。 

もう一つのケースは次のような場合です。`n = 1`。 唯一可能な配列は次のとおりです`[k]`、つまり OR は次と等しい`k`。 バイナリ分解では、制約に直接一致する単一の要素リストも生成されます。 

最後に、いつ`k`次のような多くのセットビットがあります`k = 2^0 + 2^1 + ...`、アルゴリズムは各ビットを個別に割り当てます。 いつでも`n`が大きい場合、ゼロのパディングは OR に影響を与えず、使用可能なビット位置はすべてすでに実現されているため、これ以上の改善は不可能です。
