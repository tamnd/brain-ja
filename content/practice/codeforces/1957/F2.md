 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$ノード。各ノードには整数値のラベルが付けられます。 ツリーはルート化されていませんが、概念的には、処理のためにどこにでもルート化できます。 クエリごとに、ツリー内の 2 つのパスに沿って複数の値のセットを比較するように求められます。 具体的には、いずれかのパスに沿って存在する個別の値ごとに、最初のパスでの出現回数をカウントします ($x_c$) および 2 番目のパス ($y_c$）。 クエリでは、以下まで報告するよう求められています。$k$これらのカウントが異なる値。 

制約は重要です。$n$そして$q$まで可能です$10^5$、各ノードの値は次のように大きくできます。$10^5$。 これにより、クエリごとにすべてのパスを明示的に列挙するソリューションが排除されます。$n$ノードと私たちは費やすことができます$O(n \cdot q) = 10^{10}$操作。 限界$k \le 10$すべての不一致値を見つける必要はなく、クエリごとに数個だけを見つける必要があるというヒントがあり、これが最適化の手段となります。 

見落としやすいエッジ ケースには、重複するパス、一方のパスが単一ノードであるクエリ、および両方のパスに沿ったすべての値が同一であり、0 が出力されるクエリなどがあります。たとえば、ツリーが値 [1,2,1] を持つ長さ 3 のチェーンである場合、ノード 1 から 3 および 2 から 3 のパスを比較するクエリには重複するノードがあり、重複が誤って処理されると単純なカウントでは二重カウントまたは過小カウントされる可能性があります。 

## アプローチ

 ブルート フォース ソリューションは、BFS または DFS を使用してノードの各ペア間のパスを計算し、値の複数セットを収集し、出現回数をカウントし、カウントを比較します。 各クエリには最大で次の費用がかかる可能性があります$O(n)$DFS がパスを抽出し、$O(n)$出現回数をカウントし、合計の複雑さを計算します。$O(nq) = 10^{10}$が遅すぎます。 

重要な観察は、ルート表現を使用すると、パス数をツリー内のプレフィックス数にまで減らすことができるということです。 任意のノードでツリーをルートすると、サブツリーのサイズ、親リンク、および最下位共通祖先 (LCA) クエリのバイナリ リフティング テーブルを前処理できます。 LCA 構造の準備が完了すると、パスに沿った複数の値のセットが作成されます。$u \rightarrow v$ルートから$u$そして$v$、LCA へのパスの 2 倍を減算し、LCA の値を加算します。 これにより、パス クエリがパス長の線形から次のように短縮されます。$O(k)$巧妙な確率的表現を使用すると、

 値にはランダムなハッシュを使用できます。 それぞれの一意の値にランダムな 64 ビット整数を割り当てます。 次に、パスに沿った XOR 合計により、そのパスに沿った値のマルチセットが (高い確率で) 一意に識別されます。 不一致の値を抽出するには、2 つのパス間のゼロ以外の XOR を持つ少数の値をチェックするだけで済みます。 制約$k \le 10$これにより、衝突が発生する可能性は低くなり、クエリごとに数回のチェックのみが必要になります。

 ## アルゴリズムのチュートリアル

 1. ツリーを任意にルート化し、LCA クエリの深さ、親リンク、およびバイナリ リフティング テーブルを前処理します。 これにより、任意の 2 つのノードの LCA を見つけることができます。$O(\log n)$時間。 
2. 各一意のノード値に 64 ビットのランダムな整数を割り当てます。 これは、その値を表すハッシュとして機能します。 
3. DFS を実行して、ノードごとに、ルートからそのノードまでのパスに沿ったすべてのハッシュの XOR を計算します。 させて`hash_to_root[node]`この XOR を保存します。 
4.パスの場合$u \rightarrow v$、パスに沿ったハッシュの XOR を次のように計算します。`hash_to_root[u] ^ hash_to_root[v] ^ hash_to_root[lca(u,v)] ^ hash_to_root[parent[lca(u,v)]]`。 これにより、パスに沿って複数の値のセットがコンパクトにエンコードされます。 
5. クエリごとに、2 つのパスのハッシュ値の XOR を計算します。 次に、いずれかのパス (またはサブセット) に沿ってすべてのノード値を反復処理します。$k$は小さい)、パスに沿ってハッシュを比較して、どれが異なるかを確認します。 最大出力$k$値が一致しません。 
6. ランダム化により、異なるマルチセットがほぼ確実に異なるハッシュを生成するため、競技プログラミングの実際の比較の信頼性が高まります。 64 ビットまたは 128 ビットのハッシュを使用すると、衝突の確率を極めて小さくすることができます。 

**なぜ効果があるのか**

 XOR ベースのハッシュでは、パスに沿ったハッシュの XOR によって、そのパスに沿った値のマルチセット (モジュロ衝突) が確実に一意に識別されます。 LCA へのパスを減算すると、2 つのノード間のパスに沿った値が正しく分離されます。 ランダム化されたハッシュにより、衝突の可能性は非常に低くなり、$k \le 10$バウンドを使用すると、各クエリに答えるために値の小さなサブセットのみをチェックできます。 LCA ベースの分解により、パス上のノードが二重にカウントされないことが保証されます。 

## Python ソリューション```python
import sys, random
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

n = int(input())
a = list(map(int, input().split()))
edges = [[] for _ in range(n)]
for _ in range(n-1):
    u,v = map(int,input().split())
    edges[u-1].append(v-1)
    edges[v-1].append(u-1)

# assign random 64-bit hash to each unique value
unique_vals = list(set(a))
val_hash = {v: random.getrandbits(64) for v in unique_vals}

# LCA preprocessing
LOGN = 20
up = [[-1]*LOGN for _ in range(n)]
depth = [0]*n
hash_to_root = [0]*n

def dfs(u,p):
    up[u][0] = p
    for i in range(1,LOGN):
        if up[u][i-1] != -1:
            up[u][i] = up[up[u][i-1]][i-1]
    hash_to_root[u] = val_hash[a[u]]
    if p != -1:
        depth[u] = depth[p]+1
        hash_to_root[u] ^= hash_to_root[p]
    for v in edges[u]:
        if v != p:
            dfs(v,u)

dfs(0,-1)

def lca(u,v):
    if depth[u] < depth[v]:
        u,v = v,u
    for i in reversed(range(LOGN)):
        if up[u][i] != -1 and depth[up[u][i]] >= depth[v]:
            u = up[u][i]
    if u == v:
        return u
    for i in reversed(range(LOGN)):
        if up[u][i] != -1 and up[u][i] != up[v][i]:
            u = up[u][i]
            v = up[v][i]
    return up[u][0]

q = int(input())
for _ in range(q):
    u1,v1,u2,v2,k = map(int,input().split())
    u1 -= 1; v1 -= 1; u2 -= 1; v2 -= 1
    l1 = lca(u1,v1)
    l2 = lca(u2,v2)
    # XOR along path
    xor1 = hash_to_root[u1] ^ hash_to_root[v1] ^ hash_to_root[l1] ^ (hash_to_root[up[l1][0]] if up[l1][0]!=-1 else 0)
    xor2 = hash_to_root[u2] ^ hash_to_root[v2] ^ hash_to_root[l2] ^ (hash_to_root[up[l2][0]] if up[l2][0]!=-1 else 0)
    # find differing values
    diffs = []
    for val in unique_vals:
        count1 = (hash_to_root[u1] ^ hash_to_root[l1] ^ (hash_to_root[up[l1][0]] if up[l1][0]!=-1 else 0)) & val_hash[val] != 0
        count2 = (hash_to_root[u2] ^ hash_to_root[l2] ^ (hash_to_root[up[l2][0]] if up[l2][0]!=-1 else 0)) & val_hash[val] != 0
        if count1 != count2:
            diffs.append(val)
            if len(diffs) == k:
                break
    print(len(diffs), *diffs)
```**説明**

 DFS は深さと LCA ジャンプ ポインターを計算し、同時にルートからの値ハッシュの XOR を蓄積します。 LCA 関数は標準のバイナリ リフティングを使用します。 クエリごとに、各パスに沿って XOR を計算します。 各一意の値のマスク比較により、パスに沿った不一致が検出されます。 の`k`不要な作業を避けるために、ループ内で制限が適用されます。 

微妙な点としては、ルートの親を -1 として処理すること、XOR が LCA の祖先を正しく除外することが含まれます。
