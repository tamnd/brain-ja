 ## 解決策
 ## 問題の理解

 この問題は次のように言い換えることができます。 ブラックさんの家には 2 組のドアがあり、それぞれが左右に別々の出口に通じています。 各ドアは最初は閉まっており、ブラック氏がドアを開ける正確な順序はわかっています。 少なくとも 1 つの出口のすべてのドアが開くと、彼は家を出ることができます。 課題は、それが可能になったときに、シーケンス内の最も早い点を見つけることです。 

入力は整数で構成されます`n`ドアの総数を表し、その後に次のリストが続きます。`n`整数 ここで、各整数は`0`ドアが左側の出口に属している場合、または`1`それが右側の出口に属している場合。 いずれかの出口のすべてのドアを開ける、このシーケンスの最小のプレフィックスを決定する必要があります。 出力はこのプレフィックス長です`k`。 

制約により、最大で`n = 200,000`ドア。 これにより、二次時間計算量を伴うアプローチは除外されます。`n^2`操作は 400 億回に達し、1 秒の制限時間をはるかに超えます。 線形または線形に近いソリューションが実現可能です。 考慮すべき主なエッジケースは、1 つの出口にドアが 1 つしかない場合です。 そのドアが最後に開かれた場合、単純なプレフィックス チェックのアプローチでは、最初の出口の機会が誤って報告される可能性があります。 

小さいながらもわかりやすい例は次のとおりです。`n = 3`シーケンス付き`1 0 0`。 左側の出口には 2 つのドアがあり、右側の出口には 1 つのドアがあります。 最初のドア (右の出口) を開いた後、ブラック氏はすでに出発できるため、正しい出力は次のようになります。`1`。 開いたドアの合計をカウントするか、最初に左側の出口からスキャンするだけの不注意なアプローチでは、誤って生成される可能性があります。`3`。 

## アプローチ

 ブルートフォース手法は簡単です。シーケンスの各プレフィックスについて、左側の出口のすべてのドアが開いているか、右側の出口のすべてのドアが開いているかを確認します。 これを実装するには、2 つのセットを維持します。1 つは左側の出口で閉じたままのドア用で、もう 1 つは右側の出口用です。 開いたドアごとに、それぞれのセットからドアを取り外します。 いずれかのセットが空になったら、現在のインデックスを出力します。 これは正しいですが、セットを構築し、すべてのステップで空であることを確認するには、大まかに次の作業が必要です。`O(n)`プレフィックスごとの演算により、`O(n^2)`合計。 と`n`200,000 までの場合、このアプローチは遅すぎます。 

最適なアプローチはカウントに依存します。 まず、左側の出口に属するドアの数と右側の出口に属するドアの数を数えます。 次に、シーケンスを反復しながら、各出口で開かれたドアのカウンターを維持します。 いずれかのカウンターがその出口のドアの総数に達した瞬間、その出口のすべてのドアが開いていることがわかり、すぐに現在の位置を答えとして返すことができます。 これは線形時間で動作します`O(n)`なぜなら、各ドアは 1 回だけ処理され、カウンター用に一定の追加スペースしか必要としないからです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの変数を初期化する`left_total`そして`right_total`各出口のドアの数を数えます。 入力を 1 回反復して、これらのカウントを設定します。 これは、出口のすべてのドアが開いているときの目標数を知るために必要です。 
2. 2 つのカウンターを初期化する`left_opened`そして`right_opened`ゼロに。 これらは、各出口でこれまでに開いたドアの数を追跡します。 
3. 単一パスを使用して、一連のドアを反復処理します。 ドアごとに、対応するカウンターをインクリメントします (`left_opened`のために`0`そして`right_opened`のために`1`）。 
4. カウンタを更新した後、その出口のドアの総数と等しいかどうかを確認します (`left_opened == left_total`または`right_opened == right_total`）。 初めてこの条件が成立したときは、現在のインデックス (1 から始まる) を出力して終了します。 
5. この問題では、最終的にはすべてのドアが開くことが保証されているため、シーケンスの最後に到達する前に解決策が見つかることが保証されています。 

なぜ効果があるのか​​: あらゆる段階で、`left_opened`そして`right_opened`各出口で現在開いているドアの数を正確に表します。 これらのいずれかがその出口のドアの総数と一致すると、その出口のすべてのドアが開いており、出口条件が満たされていることを意味します。 最初の出現時にすぐに戻るため、最小値が見つかることが保証されています。`k`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
doors = list(map(int, input().split()))

left_total = doors.count(0)
right_total = n - left_total

left_opened = 0
right_opened = 0

for i, door in enumerate(doors, start=1):
    if door == 0:
        left_opened += 1
    else:
        right_opened += 1
    if left_opened == left_total or right_opened == right_total:
        print(i)
        break
```この解決策は、各出口に属するドアの数を数えることから始まります。 開いたドアのカウンターは、シーケンスを繰り返すにつれて更新されます。 の`enumerate`関数は一緒に使用されます`start=1`必要な 1 から始まる出力と一致するようにします。 条件チェックにより、出口が完全に開いた最初の瞬間が即座に返されることが保証されます。 使用する`doors.count(0)`は、メイン ループに比べて無視できる単純な線形パスであり、全体の複雑さを線形に保ちます。 Off-by-one エラーは、1 から始まるインデックスによって回避されます。`enumerate`。 

## 実用的な例

 サンプル 1:`5`、 順序`0 0 1 0 0`。 

| 私 | ドア | 左開き | 右開き | 状態 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 0 | 偽 |
 | 2 | 0 | 2 | 0 | 偽 |
 | 3 | 1 | 2 | 1 | 本当 |

 3 番目のドアを開いた後、右側の出口のすべてのドア (1 つのドアのみ) が開いているため、出力は次のようになります。`3`。 

サンプル 2:`6`、 順序`1 0 1 0 0 1`。 

| 私 | ドア | 左開き | 右開き | 状態 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 1 | 偽 |
 | 2 | 0 | 1 | 1 | 偽 |
 | 3 | 1 | 1 | 2 | 偽 |

 5 番目のドア以降は左側のドア (合計 3 つ) がすべて開いているので、答えは次のようになります。`5`。 このトレースは、アルゴリズムがカウンタを正しく追跡し、最小限のプレフィックスを識別していることを確認します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    doors = list(map(int, input().split()))
    left_total = doors.count(0)
    right_total = n - left_total
    left_opened = right_opened = 0
    for i, door in enumerate(doors, start=1):
        if door == 0:
            left_opened += 1
        else:
            right_opened += 1
        if left_opened == left_total or right_opened == right_total:
            return str(i)

# provided samples
assert run("5\n0 0 1 0 0\n") == "3", "sample 1"
assert run("6\n1 0 1 0 0 1\n") == "5", "sample 2"

# custom cases
assert run("2\n0 1\n") == "1", "minimum size, either door first opens an exit"
assert run("4\n1 1 0 0\n") == "2", "first exit fully opened immediately"
assert run("5\n0 0 0 1 1\n") == "3", "left exit completes before right"
assert run("5\n1 1 1 0 0\n") == "3", "right exit completes before left"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2\n0 1 | 1 | 最小限のドア、すぐに出口 |
 | 4\n1 1 0 0 | 2 | 最初の出口は順番の早い段階で終了します。 
| 5\n0 0 0 1 1 | 3 | 左の出口が最初に完了し、右は未完了です。 
| 5\n1 1 1 0 0 | 3 | 右の出口が最初に完了し、左は未完了です。
