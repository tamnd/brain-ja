 ## 解決策
 ## 問題の理解

 (N) 個の文字列で表される (N \times N) 個のチェス盤があります。 あ`*`相手の駒ですが、`K`私たちの王であり、`-`ポーンが配置される可能性がある空の広場です。 ポーンは上に移動します。つまり、行 (r+1)、列 (c) のポーンが 2 つのマス目 ((r,c-1)) と ((r,c+1)) を攻撃します。 キングは、行と列がそのマス目と最大で 1 つ異なるすべてのマス目を攻撃します。 タスクは、追加のポーンをできるだけ少なく配置して、すべてのポーンを配置することです。`*`キングまたは新しいポーンのいずれかによって攻撃されます。 すでに占有されているマス目にポーンを置くことはできません。`*`または`K`。 公式問題には (8 \le N \le 1000) があり、制限時間は 1 秒、メモリ制限は 256 MB です。 

最初の有益な観察は、特定の列を攻撃するポーンは正確に次の列に配置されなければならないということです。 行 (r) のスターは行 (r+1) のポーンによってのみ攻撃でき、他の行のポーンによって攻撃されることはありません。 したがって、キングを考慮すると、すべての行を独立して解決できます。 (N) が最大 1000 の場合、ボード セルの数は最大 100 万個になるため、(O(N^2)) の解決策は完全に合理的です。 考えられるポーンの位置のサブセットを探索したり、すべてのスターを求めてボード全体を繰り返し検索したりするアプローチは、コストがかかりすぎます。 

いくつかの境界ケースにより、一見合理的であると思われる実装が間違っている可能性があります。 一番下の行のスターにはその下に行がないため、ポーンはそれを攻撃できません。 例えば、```

```答えがあります`-1`, スターはポーンによって攻撃できず、キングに隣接していないためです。 行境界をチェックせずに単に両方の対角列をチェックする不注意な実装では、無効なセルにアクセスしたり、ポーンを誤ってカウントしたりする可能性があります。

## アプローチ

 直接的なブルートフォース ソリューションでは、空のセルのすべてのサブセットをポーン位置の可能なコレクションとみなして、そのコレクションがすべてのスターを攻撃するかどうかをテストし、成功した最小のサブセットを保持することができます。 If there are (E) empty cells, there are (2^E) subsets, and checking one subset can require (O(N^2)) work. 最悪の場合、(E) は (N^2) に近く、おおよそ (O(N^2 2^{N^2})) 個の演算が行われます。 (N=1000) の場合、これは (10^6 2^{10^6}) のオーダーになりますが、これは遠隔的には実現可能ではありません。 

1 つの行のジオメトリに注目すると、はるかに優れた結果を得ることができます。 星が列 (c) にあるとします。 攻撃できるポーンは、次の行の列 (c-1) または (c+1) になければなりません。 同じ行の 2 つの星が列 (c) と (c+2) にある場合、次の行の列 (c+1) の四角形が両方を攻撃します。 Thus, after removing stars already attacked by the king, each row becomes a one-dimensional covering problem.

 便利な貪欲なルールは、星を左から右にスキャンすることです。 列 (c) で覆われていないスターに遭遇したら、まず列 (c+1) にポーンを置いてみます。 そのマスが空の場合、それを選択することは常に (c-1) を選択するのと少なくとも同じくらい良いです。(c+1) は現在の星を攻撃し、(c+2) の次の星も攻撃する可能性があるからです。 (c+1) が利用できない場合、残る可能性は (c-1) だけです。 If both are unavailable, the star cannot be attacked at all.

 この貪欲な選択が安全である理由は、ローカルにあります。 列 (c) を処理するとき、将来のスターは左側にありません。 (c-1) のポーンは現在のスターと既に処理された領域のみを助けることができますが、(c+1) のポーンは現在のスターと潜在的に次の未処理のスターを助けることができます。 Choosing the right-hand square never costs more and can only preserve more future coverage.

 行は独立しているため、この欲張りスキャンをすべての行に適用すると、(O(N^2)) アルゴリズムが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^2 2^{N^2})) | (O(N^2)) | 遅すぎる |
 | 最適 | (O(N^2)) | (O(N^2)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ボード全体を読み、キングを見つけます。 一部のスターではポーンをまったく必要としないため、キングの位置が必要になります。 
2. Scan every star and mark it as already covered whenever its row and column are both within one cell of the king. この条件を満たすスターはポーンの最適化に参加しません。 
3. 各基板行を個別に処理します。 A star in row (r) can only be attacked by a pawn in row (r+1), so choices made for one row cannot affect any other row.
 4. For each row, scan columns from left to right. When the current cell is not an uncovered star, continue to the next column.
 5. カバーされていないスターが列 (c) で見つかった場合、まず行 (r+1)、列 (c+1) のポーン候補マスを調べます。 そのセルが存在し、次の内容が含まれている場合`-`、そこにポーンを置き、答えを1つ増やします。 

右側の候補は、現在のスターを攻撃し、列 (c+2) の将来のスターも攻撃できるため、優先されます。 左の候補を選択しても、まだ処理されていないスターに新たな支援を提供することはできません。 
6. 右側の候補が利用できない場合は、行 (r+1)、列 (c-1) の左側の候補を検査します。 それが存在し、空の場合は、そこにポーンを置き、答えを増やします。 
7. どちらの候補も空のセルとして存在しない場合、現在のスターはどのポーンからも攻撃できません。 キングの対象外と決まっているので盤面全部は無理で答えは`-1`。 
8. すべての行が処理されるまで続行します。 累計されたポーン数が最小の答えになります。 

### なぜ効果があるのか

 カバーされていないすべてのスターについて、可能なポーン位置は次の行の 2 つの対角線上の正方形だけです。 スキャンがそのスターに到達すると、以前の決定はすべて左側にあるため、以前に選択されたポーンはその左側の候補にしか存在できません。 そのようなポーンが存在する場合、スターはすでにカバーされているため、新しいポーンは必要ありません。 それ以外の場合、適切な候補が空の場合、それを選択すると現在のスターがカバーされ、同じポーンで次のスターをカバーできる可能性が残ります。 左の候補を使用した解は、ポーンの数を増やすことなく、右の候補を使用した解に置き換えることができます。 右の候補がブロックされた場合、残された選択肢は左の候補だけになります。 両方がブロックされている場合、どの解決策も星を覆うことはできません。 したがって、すべての貪欲な決定は最適解と互換性があり、すべての行を個別に処理することでグローバル最小値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    board = [input().strip() for _ in range(n)]

    kr = kc = -1
    for r in range(n):
        pos = board[r].find('K')
        if pos != -1:
            kr, kc = r, pos
            break

    answer = 0

    for r in range(n):
        c = 0

        while c < n:
            if board[r][c] != '*':
                c += 1
                continue

            # Already attacked by the king.
            if abs(r - kr) <= 1 and abs(c - kc) <= 1:
                c += 1
                continue

            # A pawn must be in the row below the star.
            pr = r + 1

            # No row below means no pawn can attack this star.
            if pr == n:
                print(-1)
                return

            # Prefer the right candidate. It may also cover
            # a future star two columns to the right.
            if c + 1 < n and board[pr][c + 1] == '-':
                answer += 1
                c += 1
                continue

            # Otherwise try the left candidate.
            if c - 1 >= 0 and board[pr][c - 1] == '-':
                answer += 1
                c += 1
                continue

            # Neither possible pawn position is available.
            print(-1)
            return

    print(answer)

if __name__ == "__main__":
    solve()
```アルゴリズムは既存のピースを検査するだけでよいため、ボードは文字列のリストとして保存されます。 実際には、新しく配置されたポーンをボードに書き込む必要はありません。 左から右へのスキャン中、新しく選択されたポーンは現在のスターと直後の関連するスターにのみ影響を及ぼし、スキャンの位置はすでにその関係をキャプチャしています。 

キングは各行を検索することで 1 回見つかります。 すべての星について、条件は`abs(r - kr) <= 1 and abs(c - kc) <= 1`は、隣接する 8 つの正方形に、キング自身の行と列のオフセットを加えたものを正確に表します。 セル自体は星であるため、両方の座標で等しい場合は同時に発生することはできませんが、標準のチェビシェフ距離条件を使用すると、ロジックが単純になります。 

候補ポーン列は`r + 1`、 ない`r - 1`これは、入力の最初の行がボードの最上部であり、ポーンがより小さい行インデックスに向かって移動するためです。 スターを連続して攻撃するポーン`r`したがって、行内ではその下になければなりません`r + 1`。 

右の候補は左の候補より前にチェックされます。 この順序付けは、貪欲な選択の中心となります。 右側のマスが空いている場合は、それを使用すると、さらに 2 列右の星をカバーできます。 左の候補者にはそのような将来の利益はありません。 

コードが進みます`c`ポーンを置いた後、1つずつ。 ポーンは`c + 1`現在のスターを攻撃する`c`、そして別の星が発生した場合`c + 2`、スキャンが到達すると、そのスターにはこのポーンが表示されます。 それを飛び越えたり、別のカバレッジ配列を維持したりする必要はありません。 

Python の整数には任意の精度があるため、オーバーフローの心配はありません。 考えられる最大の答えは、最大でもボード セルの数で、わずか (10^6) です。
