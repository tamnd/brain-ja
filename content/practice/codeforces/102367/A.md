 ## 解決策
 ## 問題の理解

 1 つのケーキを少数の整数の重みに切り分ける必要があります。 ゲストの数は事前にはわかりません。正確には (A)、(B)、または (C) になります。 これら 3 つの可能性のそれぞれについて、すべての作品にはあらかじめ決められた受取人が必要であり、すべての作品を配布した後、すべてのゲストはまったく同じ合計重量を受け取る必要があります。 

出力では、各物理部分が 4 つの数字で説明されます。 1つ目はその重さです。 他の 3 つの数字は、(A)、(B)、または (C) のゲストがいるときに誰がそのピースを受け取るかを示します。 3 つのシナリオでは、同じ物理的ピースを異なる人に割り当てることができます。 

ケーキ自体の合計重量は (1) から (10^{18}) までなので、都合の良い合計を自由に選択できます。 3 つのゲスト数は最大 (1000) です。 そのため、(O(A+B+C)) 個の要素を含む構成は完全に実用的になりますが、最大 (10^9) 個の要素を含む構成は実用的ではありません。 5000 個という制限は、1 グラムあたり 1 個を構築するのではなく、圧縮された表現を検索するように指示する重要な制約です。 

有用なエッジケースは (A=B=C=1) です。 正しい出力には、3 つのシナリオすべてで人物 1 に割り当てられた重み 1 が 1 つ含まれているだけです。 内部境界に基づいた不注意な構築では、重複した境界を削除しないと、誤って重みがゼロの部分が作成される可能性があります。 

たとえば、入力の場合`1 1 1`、唯一の境界は 0 で、最後の境界は 1 です。間隔は 1 つだけあるため、出力は次のようになります。`1`に続く`1 1 1 1`。 重複排除を行わずに 3 つの境界セットを個別の配列として扱うと、同じ間隔が誤って数回カウントされる可能性があります。 

もう一つの境界ケースは、`1 2 3`。 最小公倍数は 6 です。3 つの等分境界は、1 人のゲストの場合は 0 と 6、2 人のゲストの場合は 0、3、6、3 人のゲストの場合は 0、2、4、6 です。 彼らの結合は、`0, 2, 3, 4, 6`、4つの部分を生成します。 サンプル出力は、まさにこれら 4 つの間隔を有効に実現したものです。 浮動小数点除算を使用する不注意な実装では、大きな値の境界を誤って認識する可能性があるため、すべての境界を整数演算で計算する必要があります。 

最後に、最大入力値は、選択した構造にとって依然として無害です。 (\operatorname{lcm}(A,B,C)) は (ABC) を除算するため、ケーキの重さは常に最大 (1000^3=10^9) で、それよりはるかに低い (10^{18}) で選択できます。 明確な内部境界の数は最大で ((A-1)+(B-1)+(C-1)) であるため、ピースの数は最大で (A+B+C-2)、つまり最大 2998 になります。したがって、5000 個の制限にはかなりの余裕があります。 

## アプローチ

 単純な構造は、ケーキの重量を (L=\operatorname{lcm}(A,B,C)) として選択し、すべてのグラムを別個の部分にすることです。 ユニットピースは(L)個あります。 (A) ゲスト シナリオの場合、(L/A) 個の連続したユニット ピースを各ゲストに割り当てます。 (B) と (C) についても同様のことを行います。 これは正しいです。(L) は 3 つのゲスト数すべてで割り切れるため、すべてのゲストはそれぞれ正確に (L/A)、(L/B)、または (L/C) グラムを受け取ります。 

問題は枚数です。 最悪の場合、(L) は (10^9) に近づく可能性があります。 たとえば、(A=997)、(B=998)、および (C=999) の最小公倍数は (994010994) です。 したがって、ユニットピース構造では 994010994 個の出力ラインが必要となり、これは 5000 の制限をはるかに超え、1 秒間に処理できる量をはるかに超えます。 

重要な観察は、実際にはグラムごとに個別の部分が必要ではないということです。 ゲスト数が固定の場合、ケーキを 0 から (L) までの連続した間隔として想像してください。 (A) 人のゲストがいる場合、ゲスト 1 には 0 から (L/A) までの間隔が必要で、ゲスト 2 には次の間隔が必要です。 受信者が変更できる唯一の場所は境界線です

 [
 0、\frac{L}{A}、\frac{2L}{A}、\ldots、L。 
]

 (B)と(C)についても同様に行います。 次に、これらすべての境界を結合して、そこでのみケーキをカットします。 

結果として得られるすべての部分は、1 つの (A) ゲスト間隔、1 つの (B) ゲスト間隔、および 1 つの (C) ゲスト間隔内に完全に収まります。 したがって、各シナリオの対応する受信者に部分全体を割り当てることができます。 これらの部分は、まさに 3 つの均等なパーティションの共通の改良版です。 

内部境界は最大で (A-1)、(B-1)、(C-1) 個であるため、それらの結合を取得した後は、最大で (A+B+C-2) 個の内部カットと最大で (A+B+C-1) 個のピース​​が存在します。 3 つの値すべてが最大 1000 であるため、これは最大 2999 個になります。

 ## アルゴリズムのチュートリアル

 1. (L=\operatorname{lcm}(A,B,C)) を計算します。 これにより、総重量を 3 つの可能なゲスト数のいずれかに均等に分割できるケーキが得られます。 
2. 0 と (L) を含むセットを作成します。 これらはケーキの両端です。 
3. 1 から (A-1) までのすべての整数 (i) に対して、(i(L/A)) をセットに挿入します。 これらはまさに、(A) ゲストがいるときに受け手が変わる場所です。 
4. (B) と (C) に対して同じプロセスを繰り返し、(i(L/B)) と (i(L/C)) を挿入します。 (L) は 3 つの値すべてで割り切れるため、すべての境界は整数になります。 
5. 結果として得られた境界セットを並べ替えます。 連続した値 (x<y) は、重量 (y-x) を持つ 1 つの物理的なケーキ片を定義します。 重複する境界はセットによってすでに削除されているため、すべての重みは正になります。 
6. (x) から始まる各間隔について、各シナリオでの受信者を計算します。 (A) ゲストの場合、(x) を含む区間はゲストに属します

 [
 \左\lフロア\frac{x}{L/A}\右\rフロア+1。 
]

 (B) と (C) に対応する式により、他の 2 人の受信者が得られます。 (x) 自体が和集合からの境界であるため、区間はどのシナリオにも属する別の境界を越えることはできません。 
7. すべてのピースをその重みとして出力し、その後に 3 つの受信者インデックスを出力します。 総重量はちょうど(L)、個数は5000個以下です。

### なぜ効果があるのか

 不変条件は、生成されたすべてのピースが、可能な 3 つのゲスト数のそれぞれについて 1 つの均等シェア間隔内に完全に収まることです。 (A)-ゲスト パーティションを考えてみましょう。 その境界はすべてグローバル境界セットに含まれているため、生成された部分は (A) ゲスト境界を超えることはできません。 したがって、すべての作品はちょうど 1 つの (A) ゲスト インターバルに属し、それをそのインターバルのゲストに割り当てます。 これらの間隔にはそれぞれ重量 (L/A) があるため、(A) 人のゲストはそれぞれ正確に (L/A) グラムを受け取ります。 同じ議論が (B) と (C) に独立して適用されます。 ピースは明確にソートされた境界から形成されており、その合計重量が (L) まで伸縮するため、ポジティブです。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def lcm(a, b):
    return a // gcd(a, b) * b

def solve():
    A, B, C = map(int, input().split())

    L = lcm(lcm(A, B), C)

    cuts = {0, L}

    part_a = L // A
    part_b = L // B
    part_c = L // C

    for i in range(1, A):
        cuts.add(i * part_a)

    for i in range(1, B):
        cuts.add(i * part_b)

    for i in range(1, C):
        cuts.add(i * part_c)

    cuts = sorted(cuts)

    ans = []

    for i in range(len(cuts) - 1):
        left = cuts[i]
        right = cuts[i + 1]
        weight = right - left

        a = left // part_a + 1
        b = left // part_b + 1
        c = left // part_c + 1

        ans.append((weight, a, b, c))

    out = [str(len(ans))]
    out.extend(f"{w} {a} {b} {c}" for w, a, b, c in ans)
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初のセクションでは、共通のケーキ重量を計算します。 入れ子になった`lcm`Python の整数には任意の精度があるため、呼び出しは安全ですが、この問題では結果の値がすでに (10^9) を下回っています。 

3人`part_*`変数は、各ゲストが受け取る必要がある正確な体重です。 これらは、考えられる 3 つのシナリオにおける等間隔の幅としても機能します。 

の`cuts`セットは構造の中心部分です。 受信者が変更される可能性のあるすべての場所が 1 回だけ挿入されます。 複数のパーティションで同じ境界が発生する可能性があるため、セットの使用は重要です。 たとえば、(A=2) および (B=4) の場合、中点 (L/2) は 4 つの (B) ゲスト間隔のうち 2 つの後の境界でもあります。 

ソート後、連続したカットが実際のピースを表します。 表現`right - left`重複したカットが削除されているため、常に正になります。 

受信者の計算では、浮動小数点ではなく整数の除算が使用されます。 もし`left`(A) パーティションの (j) 番目の区間にある場合、`left // part_a`は (j-1) であるため、1 を加算すると、0 から始まる間隔の数値が、必要な 1 から始まる人物インデックスに変換されます。 

Python ではオーバーフローの心配はありません。 固定幅の整数を使用する言語では、問題では最大 (10^{18}) までの合計が明示的に許可されており、ここでの構造はそれよりはるかに小さいため、64 ビット整数で十分です。

| 左 | 右 | 重量 | 受信者 | B 受信者 | C 受信者 |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O((A+B+C)\log(A+B+C))) | 最大 (A+B+C-1) 個の境界が挿入され、並べ替えられます。 
| スペース | (O(A+B+C)) | 境界セットと出力には (O(A+B+C)) 個の要素が含まれます。 

(A,B,C\le1000) なので、生産数は 3000 個未満になります。 この構築では、数千の算術演算と 1 つの小さなソートのみを実行するため、規定の 1 秒の時間制限と 256 MB のメモリ制限を容易に満たすことができます。 

## テストケース

 建設的な問題の正確なテキスト出力は、問題によって一意に決定されるわけではありません。 次のテストでは、上記の決定論的実装を使用し、受け入れられたすべての出力が満たさなければならない構造的条件を検証します。```python
import sys
import io
from math import gcd

def solve_data(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        A, B, C = map(int, sys.stdin.readline().split())

        def lcm(a, b):
            return a // gcd(a, b) * b

        L = lcm(lcm(A, B), C)

        cuts = {0, L}
        pa = L // A
        pb = L // B
        pc = L // C

        for i in range(1, A):
            cuts.add(i * pa)
        for i in range(1, B):
            cuts.add(i * pb)
        for i in range(1, C):
            cuts.add(i * pc)

        cuts = sorted(cuts)

        ans = []
        for i in range(len(cuts) - 1):
            x = cuts[i]
            y = cuts[i + 1]
            ans.append((
                y - x,
                x // pa + 1,
                x // pb + 1,
                x // pc + 1
            ))

        out = [str(len(ans))]
        out.extend(f"{w} {a} {b} {c}" for w, a, b, c in ans)
        return "\n".join(out)
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def validate(inp: str, output: str):
    A, B, C = map(int, inp.split())
    lines = output.strip().splitlines()

    K = int(lines[0])
    assert K == len(lines) - 1
    assert 1 <= K <= 5000

    pieces = []
    total = 0

    for line in lines[1:]:
        w, a, b, c = map(int, line.split())
        assert w > 0
        assert 1 <= a <= A
        assert 1 <= b <= B
        assert 1 <= c <= C
        pieces.append((w, a, b, c))
        total += w

    assert 1 <= total <= 10**18

    for count, column in ((A, 1), (B, 2), (C, 3)):
        sums = [0] * (count + 1)

        for w, a, b, c in pieces:
            person = (a, b, c)[column - 1]
            sums[person] += w

        assert len(set(sums[1:])) == 1

def run(inp: str) -> str:
    out = solve_data(inp)
    validate(inp, out)
    return out

# Provided sample
sample = run("1 2 3")
assert sample == (
    "4\n"
    "2 1 1 1\n"
    "1 1 1 2\n"
    "1 1 2 2\n"
    "2 1 2 3"
), "sample 1"

# Minimum-size input
out = run("1 1 1")
assert out == "1\n1 1 1 1", "minimum case"

# All values equal
out = run("7 7 7")
assert out == "7\n" + "\n".join(
    f"1 {i} {i} {i}" for i in range(1, 8)
), "all equal"

# Boundary-heavy case
out = run("2 3 4")
assert out == (
    "6\n"
    "3 1 1 1\n"
    "1 1 1 2\n"
    "2 1 2 2\n"
    "2 2 2 3\n"
    "1 2 3 3\n"
    "3 2 3 4"
), "boundary case"

# Maximum values
out = run("1000 999 997")
validate("1000 999 997", out)

 ## 特殊なケース

 のために`1 1 1`の場合、最小公倍数は 1 で、内部境界を生成する 3 つのループはすべて空です。 境界設定は単純に`{0, 1}`。 唯一の区間の重みは 1 で、3 つの受信者インデックスはすべて 1 です。このアルゴリズムでは、同じ境界の繰り返しコピーを含むリストではなくセットをソートするため、重みが 0 の部分は作成できません。 

のために`1 2 3`、ケーキの重さは 6 です。(A) パーティションには内部カットがありませんが、(B) パーティションには 3 のカットがあり、(C) パーティションには 2 と 4 にカットがあります。和集合は次のようになります。`0, 2, 3, 4, 6`したがって、4 つの出力重みは 2、1、1、および 2 です。単一 (A) ゲストは 4 つの部分すべてを受け取りますが、他の 2 つのシナリオはそれらの同じ部分を独自の境界で分割します。 

のために`2 3 4`、ケーキの重さは 12 です。(A) の境界は 0、6、12、(B) の境界は 0、4、8、12、(C) の境界は 0、3、6、9、12 です。結合された境界により 6 つのピースが生成されます。 受信者の割り当ては、幅 6、4、および 3 に対する整数除算によって決定されるため、すべてのゲストは、対応するシナリオでちょうど 6、4、または 3 グラムを受け取ります。 

大きいケースの場合`1000 999 997`、最小公倍数は (10^9) 未満ですが、アルゴリズムは (10^9) 個の部分を構築することはありません。 重複を削除する前に最大 (999+998+996+1=2994) 個の境界位置が作成されるため、最大 2993 個の部分が作成されます。 すべての境界は 3 つのパーティション幅のいずれかの正確な整数倍であるため、許容される最大の入力値であっても浮動小数点演算は必要ありません。
