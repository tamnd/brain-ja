 ## 問題の理解

 長さが与えられています$n$10 進数の文字列と、許可される隣接スワップの形式での桁間の一連の制約。 各制約は 2 つの異なる数字を接続します$u$そして$v$、そして、これらの 2 つの数字が数字の中で隣り合って現れるときはいつでも、それらを入れ替えることができると述べています。 

これらの許可された隣接スワップのシーケンスを使用して一方を他方に変換できる場合、2 つの数値は同等であるとみなされます。 目標は、与えられた 2 つの数値を比較することではなく、これらのスワップによって引き起こされる全体的な構造を理解することです。$10^n$数字文字列 (先頭のゼロは許可されます) を入力し、異なる同値クラスがいくつ存在するかを数えます。 

同様に、すべての長さで分割しています。$n$頂点が文字列であり、エッジが単一の有効なスワップ操作に対応するグラフの下の連結成分に数値文字列を変換します。 タスクは、そのようなコンポーネントがいくつ存在するかを法で計算することです。$998244353$。 

制約$n \le 50000$スワップを明示的にシミュレートしたり、個々のポジションについて推論しようとするアプローチはすべて除外されます。 数字はサイズ 10 の固定アルファベットに由来するため、管理可能な唯一の観点は、数字の構造を小さな状態空間に圧縮することです。 

重要なエッジケースは、許可されたスワップがまったくない場合に発生します。 次に、すべての数字が所定の位置に固定されるため、2 つの異なる文字列が同等になることはなく、答えは正確に次のようになります。$10^n$。 構造をあまりにも積極的に崩壊させる解決策 (たとえば、数字が常に自由に変更可能であると仮定する) は、この場合すぐに失敗します。 

もう 1 つの重要なエッジ ケースは、すべての桁がスワップ ルールによって完全に接続され、単一のコンポーネントを形成するときに発生します。 その場合、すべての桁はスワップを通じて任意に再配置できるため、桁の位置ではなく、複数の桁のセットのみが重要になります。 

## アプローチ

 直接的な強引なアプローチでは、それぞれの長さを処理します。$n$文字列をノードとして使用し、BFS または DFS オーバー スワップ操作を使用して、到達可能なすべての文字列を探索しようとします。 各文字列には最大$n-1$スワップ位置の可能性があるため、グラフは巨大になり、サイズも大きくなります$10^n$、これは非常に小さい場合でも完全に実行不可能になります$n$。 

重要な観察は、スワップは位置には依存せず、数字の同一性にのみ依存するということです。 数字を解釈できる$0$を通して$9$グラフの頂点として、許可されたスワップを表すエッジを持ちます。 このグラフで 2 つの数字がパスで接続されている場合、隣接するペアを繰り返し交換することで、文字列内でこれらの数字の出現順序を相互に相対的に並べ替えることができます。 

これは、数字のグラフが連結成分に分解され、各成分内で数字が再配置力に関して区別できないように動作することを意味します。 重要な単純化は、各数字の構成要素のメンバーシップのみが重要であり、数字自体の ID は重要ではないことです。 

数字を連結成分に圧縮すると、文字列内の各位置は効果的に次のいずれかでラベル付けされます。$c$コンポーネント ID。$c$は、桁グラフ内の連結成分の数です。 スワップによって引き起こされる再配置は、コンポーネント内でその桁の任意のスワップをシミュレートできるため、これらのコンポーネントのラベルを文字列に沿って自由に並べ替えることができます。 

したがって、問題は、長さの異なる文字列がいくつあるかを数えるということになります。$n$アルファベット以上の大きさ$c$位置が完全に順列になるまで存在します。これは、サイズのマルチセットを数えるのと同じです。$n$以上$c$種類。 これは典型的な星と棒の結果です。 

したがって、答えは弱い組成の数になります。$n$の中へ$c$部品。

 ## アルゴリズムのチュートリアル

 私たちは問題を、小さなグラフ内の連結成分を数字で数えて、組み合わせ公式を適用することに落とし込みます。 

### ステップ

 1. 頂点にグラフを構築する$0$を通して$9$、許可されたスワップ ペアごとに無向エッジを追加します。$(u, v)$。 

これは、1 回のスワップでどの桁が直接相互作用できるかを正確にエンコードします。 
2. 連結成分の数を計算する$c$このグラフでは DFS または Union-find を使用しています。 

これが機能する理由は、推移的な到達可能性によって、一連のスワップを通じてどの桁を互いに再シャッフルできるかが決まるためです。 
3. 最終的な長さの各位置を観察します。$n$文字列は、どの数字の構成要素に属するかによってのみ分類できます。 

コンポーネント内では、数字の ID を自由に再配置できるため、状態を区別できなくなります。 
4. 各文字列をある長さに短縮します。$n$一定のサイズのアルファベットにわたるシーケンス$c$。 

2 つの文字列は、コンポーネント ラベルの同じマルチセットを持つ場合、正確に等価です。 
5. サイズのマルチセットの数を数えます$n$から形成できます$c$種類。 

これは次のように与えられます。$$\binom{n + c - 1}{c - 1}$$6. この二項係数モジュロを計算します。$998244353$階乗事前計算とモジュラー逆行列を使用します。 

### なぜ効果があるのか

 重要な不変条件は、スワップによって各接続コンポーネント内の複数の桁のセットが変更されることはなく、コンポーネント内のこれらの桁の再配置は、許可されたスワップを使用してシミュレートできることです。 したがって、等価性が維持されるのは、各コンポーネントに割り当てられた位置の数のみであり、コンポーネント内の桁の内部配置ではありません。 これにより、各等価クラスが独自の弱い構成に分解されます。$n$の中へ$c$バケットを作成し、二項カウントが正確であることを確認します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

n = int(input().strip())
m = int(input().strip())

parent = list(range(10))

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

def union(a, b):
    ra, rb = find(a), find(b)
    if ra != rb:
        parent[rb] = ra

for _ in range(m):
    u, v = map(int, input().split())
    union(u, v)

# count components
roots = set(find(i) for i in range(10))
c = len(roots)

# precompute factorials up to n + 9
maxv = n + 9
fact = [1] * (maxv + 1)
invfact = [1] * (maxv + 1)

for i in range(1, maxv + 1):
    fact[i] = fact[i - 1] * i % MOD

invfact[maxv] = pow(fact[maxv], MOD - 2, MOD)
for i in range(maxv, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def C(a, b):
    if b < 0 or b > a:
        return 0
    return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

print(C(n + c - 1, c - 1))
```Union-find 構造体は、アルファベットがサイズ 10 に固定されているため、数字の接続性を定数時間で圧縮します。階乗は次まで計算されます。$n + 9$これはすべての二項評価に十分です。 

微妙な点は、答えは接続されたコンポーネントの数のみに依存し、内部構造やサイズには依存しないということです。 これが、union-find の結果がただちに 1 つの整数に還元される理由です。$c$、それ以上の桁レベルの分析は必要ありません。

 ## 特殊なケース

 スワップエッジがない場合、各桁は独自のコンポーネントとなり、答えは次のようになります。$10^n$。 Union-find 構造ではすべてのノードが分離されたままになるため、アルゴリズムはこれを処理します。$c = 10$、二項式はすべての弱い組成を正確にカウントします。 

すべての数字がスワップ ルールを通じて接続されると、すべての数字が 1 つのコンポーネントに集約されます。 その場合$c = 1$、そして式は次のようになります$\binom{n}{0} = 1$、すべての文字列が同等であることを意味します。 Union-find では単一のルートが生成されるため、アルゴリズムはこれを反映しています。 

いつ$n = 1$の場合、各桁は長さ 1 の異なる文字列を形成するため、端に関係なく、答えは常に 10 になります。 式は次のようになります$\binom{1 + c - 1}{c - 1} = \binom{c}{c-1} = c$、そしてそれ以来$c$完全にマージされない限り、桁は常に 10 になります。これは直接カウントと一致します。
