 ## 解決策
 ## 問題の理解

 このタスクでは、各セルが部屋であり、隣接する部屋が直接通過できる場合とできない場合がある、大きな格子状の迷路について説明します。 隣接するセルの間には、空きスペース、壁、または鍵のかかったドアが存在する場合があります。 ロボットは固定セルから開始し、いくつかの出口セルのいずれかに到達する必要があります。 

ロボットは環境と対話することもできます。特定のセルで見つかった鍵を拾うことができ、任意の鍵で任意のドアを開けることができますが、鍵は使用時に消費されます。 開いた通路の移動は自由ですが、壁は移動を完全に阻止し、ドアは鍵で開かれるまで移動を阻止します。 ロボットは、移動、ドアを開ける、鍵を取るなどの基本的なコマンドで構成されるプログラムを実行できます。 

隠れた目的は、グリッド内のパスを見つけることだけではなく、ルール システムの下で出口に到達することを保証する有効なコマンド シーケンスを生成することです。 これは構築上の問題であるため、正確かどうかは、生成されたコマンド シーケンスがロボットの実行モデルで考えられるすべての実行結果と一致しているかどうかにかかっています。 

グリッド サイズは最大 1000 x 1000 に達し、最大 10^5 のドアとキーが含まれます。 これにより、完全なコマンド実行を繰り返しシミュレートしたり、インタラクションごとに到達可能性を最初から再計算したりするアプローチは即座に除外されます。 グリッド全体にわたる単一の BFS でさえ、すでに上限に近づいているため、キーごとまたはドアごとに何かを繰り返すことは実行不可能になります。 

最も微妙な問題は、ドアが状態を導入することです。 パスは単なるセルのシーケンスではなく、キーを使用した後にのみ特定のエッジが通過可能になる一連の構成です。 グリッド上の単純な最短パスは、キーの使用法と将来の接続性の間の結合を無視するため、失敗します。 

いくつかの失敗例がすぐに現れます。 

ドアを壁として扱う単純な BFS は、近くに鍵が存在する場合でも失敗します。 たとえば、スタート地点が出口に直接つながるドアに隣接しており、鍵が 2 歩離れたところにあるとします。 キーを無視する BFS は、最初にキーを受け取り、ドアを開け、次に移動するという有効な順序が存在するにもかかわらず、出口に到達できないと結論付けます。 

2 番目の故障モードは、複数のドアが連続して存在する場合に発生します。 パスで 2 つのドアを開ける必要があるが、行き止まりの分岐にキーが 1 つしかない場合、最も近いキーを消費する貪欲な戦略により、正しいグローバル パスの到達可能性が破壊される可能性があります。 

3 番目の微妙なケースは、キーが必要以上に早く消費されるサイクルです。 できるだけ早くドアを開ける単純な戦略では、たとえ開く順序が異なっていても、迂回ドアに鍵を費やして、後でクリティカルエッジのための鍵を残さない可能性があります。 

これらの問題により、問題は、エッジが消費可能なリソースに依存する暗黙的なグラフ上の状態認識型最短パスに強制されます。 

## アプローチ

 ブルートフォースの観点は、グリッド内の位置、どのドアが開いているか、どのキーが残っているかというトリプルとして状態を扱うことです。 直接検索すると、鍵を取得するかドアを開けるかという考えられるすべての選択肢に分岐します。 これは、各キーがそれをいつどこで使用するかについて二者決定を導入し、ドアが可能な状態を乗算する依存関係を導入するため、急速に指数関数的になります。 

グリッド内の最短パスに注意を限定したとしても、依然として組み合わせ爆発に直面します。K 個のキーと D 個のドアを使用すると、ドアのサブセットが異なる順序で開く可能性があり、BFS はその状態をエンコードする必要があります。 最悪の場合、これは O(NM · 2^K) の動作につながりますが、これは完全に実行不可能です。 

重要な観察は、実際には、トラバース中にドアが開く正確な順序は気にしておらず、これまでに遭遇したすべての必要なドアのロックを解除するのに十分なキーがパス プレフィックスに沿って存在するかどうかだけを気にしているということです。 これにより、キー余剰によって集計すると、到達可能な構成の数において状態空間が指数関数から線形に崩壊します。

どの特定のドアが開かれたかを追跡するのではなく、収集した鍵の数から通過したドアの数を差し引いた数を追跡します。 グリッドの構造により、各エッジにコスト解釈がある最短パス検索を実行できます。鍵に遭遇するとリソースが増加し、ドアに遭遇するとリソースが消費されます。 これにより、問題は、単一の実行バランスに影響を与えるノードの重みを持つグリッド上の最短パスに変換されます。 

すべての移動はユニット遷移であり、キーバランスの実現可能性制約の下での出口の到達可能性のみが必要であるため、状態が現在のキー余剰で増強される BFS のようなトラバーサルを使用できます。 K と D は 10^5 によって制限され、各セルは実行可能な余剰範囲ごとに最大 1 回アクセスされるため、プロセス全体は、慎重なブックキーピングにより線形または線形に近い走査に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ドア/キーの完全な状態検索 | O(2^K) | O(2^K) | 遅すぎる |
 | 状態を無視するグリッド BFS | O(NM + D + K) | O(NM) | 不正解 |
 | グリッド上のリソース認識型 BFS | O(NM + D + K) | O(NM) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 動きを妨げる壁がない場合、各セルがその 4 つの隣接セルに接続するグラフとして迷路をモデル化します。 隣接ごとに、フリー、ドア、またはブロックに分類します。 これにより、横断できる静的な構造が得られます。 
2. すべてのキーと出口の位置を前処理して、ルックアップ構造 (通常はブール グリッド) にします。 これにより、セルに入るときのトラバース中に一定時間のチェックが可能になります。 
3. 開始セルから BFS を実行しますが、訪問した位置を保存するだけではなく、各セルで最もよく知られている「キー バランス」を維持します。 キーバランスは、キーセルに足を踏み入れると増加し、ドアを通過すると減少します。 
4. セルから隣接セルに拡張する場合、結果として生じるバランスを計算します。 エッジが壁の場合は、完全にスキップします。 ドアの場合は、通過する前にバランスが厳密に正であることを確認してください。 そうでなければ、その移動は実行不可能です。 
5. ネイバーにキーが含まれている場合は、入力後に残高をインクリメントします。 この順序は、後続のエッジで使用される前にキーが確実に収集されるため、重要です。 
6. BFS 層ごとに順序付けされたキューを維持します。 状態が以前に記録されたものよりも優れた、または同等のバランスを持つセルに到達したら、セルを更新して拡張を続けます。 これにより、支配された国家が再び訪れることを防ぎます。 
7. 出口セルに到達したら停止します。 BFS は、最初に出口に到達したときが制約の下で実行可能な走査に対応することを保証します。 

### なぜ効果があるのか

 核となる不変条件は、アルゴリズムがすべてのセルについて、最小限のステップでそのセルに到達するすべての有効なパス間で達成可能な最大のキー バランスを維持することです。 同じセルに到達するキーの数が少ないか等しいパスは、バランスがより高いパスよりも後でより多くのドアのロックを解除することはできないため、優先されます。 すべての遷移は段階的に単位コストであり、実現可能性においては単調であるため、BFS は出口への最初の成功した到着がすべてのドア制約を尊重する有効なシーケンスに対応することを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    sx, sy = map(int, input().split())

    grid_key = [[0] * m for _ in range(n)]
    grid_exit = [[0] * m for _ in range(n)]

    # walls and doors stored as adjacency maps
    wall = {}
    door = {}

    def edge_id(x1, y1, x2, y2):
        if x1 > x2 or y1 > y2:
            x1, y1, x2, y2 = x2, y2, x1, y1
        return (x1, y1, x2, y2)

    C = int(input())
    for _ in range(C):
        x1, y1, x2, y2 = map(int, input().split())
        wall[edge_id(x1, y1, x2, y2)] = 1

    D = int(input())
    for _ in range(D):
        x1, y1, x2, y2 = map(int, input().split())
        door[edge_id(x1, y1, x2, y2)] = 1

    K = int(input())
    for _ in range(K):
        x, y = map(int, input().split())
        grid_key[x][y] = 1

    E = int(input())
    exits = set()
    for _ in range(E):
        x, y = map(int, input().split())
        grid_exit[x][y] = 1
        exits.add((x, y))

    # best key balance seen at each cell
    best = [[-1] * m for _ in range(n)]

    dq = deque()
    init = 1 if grid_key[sx][sy] else 0
    dq.append((sx, sy, init))
    best[sx][sy] = init

    dirs = [(1,0), (-1,0), (0,1), (0,-1)]

    while dq:
        x, y, bal = dq.popleft()

        if grid_exit[x][y]:
            print("YES")
            return

        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if nx < 0 or nx >= n or ny < 0 or ny >= m:
                continue

            e = edge_id(x, y, nx, ny)
            if e in wall:
                continue

            nbal = bal
            if e in door:
                if nbal == 0:
                    continue
                nbal -= 1

            if grid_key[nx][ny]:
                nbal += 1

            if nbal <= best[nx][ny]:
                continue

            best[nx][ny] = nbal
            dq.append((nx, ny, nbal))

    print("NO")

if __name__ == "__main__":
    solve()
```このコードは、正規化された無向エッジ キーを使用して、壁とドアの明示的な構造を構築します。 これにより、(u, v) と (v, u) の間の混同が回避されます。 BFS 状態には、現在のキーバランスと、`best`配列により、支配的な状態が確実に枝刈りされます。 残高を更新する順序は意図的です。ドア コストは鍵の収集前に適用されるため、セルに足を踏み入れると、そこに使用済みの鍵が存在する場合はすぐに回収できます。 

微妙な点は、同じセルへの複数回の訪問は、バランスが改善される場合にのみ許可されることです。 これがないと、より多くの利用可能なリソースがある同じ場所に到達するパスが検索で途中で破棄される可能性があります。これは、後のドアの通過に不可欠です。 

## 実用的な例

 ### 例 1

 出口の前でドアを通過するために鍵が必要な小さな廊下を考えてみましょう。 

| ステップ | セル | バランス | アクション |
 | --- | --- | --- | --- |
 | 1 | (0,0) | 0→1 | 開始、キーを収集 |
 | 2 | (0,1) | 1 → 0 | ドアを通って移動 |
 | 3 | (0,2) | 0 | 出口に到達 |

 このトレースは、テンプがどのように振動するが、臨界エッジでゼロを下回らない様子を示しています。 

### 例 2

 鍵が行き止まりになっている分岐ケース。 

| ステップ | セル | バランス | アクション |
 | --- | --- | --- | --- |
 | 1 | 開始 | 0 | 開始 |
 | 2 | ブランチ A キー | 1 | キーを選択 |
 | 3 | 後戻り | 0 | 戻る |
 | 4 | 廊下 | 0 → 0 | ドアは必要ありません |
 | 5 | 終了 | 0 | 出口に到達 |

 これは、BFS が最初にキー ブランチを正しく探索しますが、セルごとのより良いバランスを維持するだけであるため、それにコミットしないことを示しています。 

ここで検証された重要な不変条件は、最初はより多くのステップが必要であっても、後でより高い残高を持つセルにアクセスすることが常に優先されるということです。

 ## 特殊なケース

 キーエッジケースとは、キーと出口が隣接しているものの、ドアによって隔てられている場合です。 残高はキーの収集後にのみ更新されるため、アルゴリズムはこれを正しく処理し、即時のドアの通過を可能にします。 

もう 1 つのエッジ ケースは、経路の後半に 1 つの鍵だけが配置された長いドアのチェーンです。 単純な BFS は早期に失敗しますが、バランスベースの BFS はキーが見つかるまで可能性を保持します。 

最後のエッジ ケースは、以前に低いバランスでセルを訪問した後、厳密に優れたバランスでセルを再訪問することです。 の`best`配列により、改善された状態のみが伝播されることが保証されるため、アルゴリズムは据え置きキーの使用に依存するパスを見逃すことはありません。
