 ## 解決策
 ## 問題の理解

 各セルまたはノードが迷路内の位置を表し、それらの間のいくつかの接続が可能な動きを定義するグラフとして解釈できる迷路のような構造が与えられます。 この構造に加えて、エッジや場合によっては移動の制約によって定義されたルールの下で、迷宮の一部に到達するか、その一部と対話することに関して特定の条件が当てはまるかどうかを尋ねる複数のクエリを受け取ります。 

この一連の高難易度タスクにおける「Labyrinth-13」の性質から、重要な抽象化は、単に単一の最短経路の計算を行っているわけではないということです。 代わりに、入力は大きな静的グラフを記述し、クエリごとに最初から再計算することを不可能にする制約の下での到達可能性や距離に関する多くの独立した質問に答えるように求めます。 

この制約は十分に大きいため、クエリごとに走査を再計算するアプローチでは、すぐに制限を超えることになります。 最大約 10^5 のノードと同様の数のクエリがある場合、クエリごとの線形 BFS であっても、最悪の場合はおよそ 10^10 の操作が発生し、これは 8 秒の制限をはるかに超えます。 これにより、前処理や繰り返しの計算を圧縮する構造が強制されます。 

この一連の問題における微妙なエッジ ケースは、切断された領域またはほとんど接続されていない領域から発生します。 たとえば、迷路がコンポーネントに分割されている場合、コンポーネントが事前にラベル付けされていないと、グローバルな到達可能性を前提としたクエリが通知なく失敗する可能性があります。 もう 1 つの典型的な落とし穴は、複数のクエリが同じ構造プロパティについて質問するのに、単純なソリューションがグラフ構造または可分性条件を繰り返し再計算する場合です。 

具体的な障害シナリオは、ソリューションがクエリごとに BFS を再計算するときに表示されます。 

入力:

 100000 個のノードからなる長いチェーン グラフと、ランダム ペア間の到達可能性を尋ねる 100000 個のクエリ。 

クエリごとの単純な BFS は論理的には正しいですが、完全にタイムアウトになります。 正しい出力は、両方のノードが同じ連結成分内にあるかどうかだけであり、これは一度事前計算する必要があります。 

したがって、この問題群は基本的に、グラフ構造のどの部分が静的であり、クエリ間で再利用可能であるかを認識することに関係しています。 

## アプローチ

 ブルート フォースのアイデアは簡単です。クエリごとに、ソース ノードから開始してグラフ トラバーサルを実行し、宛先ノードに到達できるかどうかを確認します。 これが機能するのは、BFS または DFS が重み付けされていないグラフ内の到達可能なすべてのノードを正しく調査し、質問に直接答えるためです。 

問題は、各走査のコストが O(n + m) であり、これを q クエリに対して繰り返すと O(q(n + m)) になることです。 すべてのパラメータが大きい場合、これはおよそ 10^10 の演算に縮退し、現実的ではありません。 

重要な観察点は、グラフ自体はクエリ間で変化しないことです。 これは、接続情報を一度だけ事前計算できることを意味します。 到達可能性を再計算する代わりに、接続されたコンポーネントごとに単一の BFS または DFS を使用して、各ノードにコンポーネント識別子を割り当てます。 この前処理の後、各クエリはコンポーネント ラベルの定数時間の比較に縮小されます。 

これにより、繰り返される走査がグラフ上の 1 回の線形スキャンに変換され、その後、すべてのクエリが簡単な検索になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース BFS/DFS | O(q(n + m)) | O(n + m) | 遅すぎる |
 | 接続されたコンポーネントの前処理 | O(n + m + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力エッジからグラフの隣接リストを作成します。 これにより、隣接する迷宮を効率的に探索できる迷路が直接表現されます。 
2. 配列を維持する`comp`ゼロに初期化されます。`comp[v]`ノードの接続コンポーネントIDを保存します`v`。 これは、到達可能性構造のメモ化として機能します。 
3. すべてのノードを反復処理します。 まだコンポーネントが割り当てられていないノードを見つけるたびに、そのノードから BFS または DFS を開始し、そこから到達可能なすべてのノードに新しいコンポーネント ID を割り当てます。 このステップでは、グラフを最大接続領域にグループ化します。 
4. 走査ごとに、訪問したすべてのノードに同じコンポーネント ID を割り当てます。 トラバーサルにより、前処理全体で各エッジを 1 回だけ探索することが保証されます。 
5. 前処理が完了したら、関連する 2 つのノードを読み取り、それらのコンポーネント ID を比較することによって各クエリを処理します。 それらが一致する場合、それらは到達可能です。 それ以外の場合はそうではありません。 
6. 各クエリに対する回答は、確認後すぐに出力されます。 

これが機能する理由は、BFS/DFS がグラフを到達可能性の等価クラスに分割するためです。 2 つのノードは、同じクラスに属している場合にのみ到達可能であり、この関係はコンポーネント ID によって完全にキャプチャされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    comp = [0] * (n + 1)
    cid = 0

    for i in range(1, n + 1):
        if comp[i]:
            continue
        cid += 1
        q = deque([i])
        comp[i] = cid

        while q:
            u = q.popleft()
            for v in g[u]:
                if comp[v] == 0:
                    comp[v] = cid
                    q.append(v)

    q = int(input())
    out = []

    for _ in range(q):
        a, b = map(int, input().split())
        out.append("YES" if comp[a] == comp[b] else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```隣接リストの構築は、高速な近隣反復をサポートするために必要です。 BFS はキューを使用して、各ノードが O(1) の償却時間で処理されるようにします。 コンポーネント配列は最適化の中心であり、反復された走査を定数時間のルックアップに置き換えます。 

実装の微妙な点は、クエリが処理される前にコンポーネントのラベル付けを行う必要があることです。 クエリ処理をトラバーサルに混ぜると、繰り返し作業が再び発生し、複雑さの利点が損なわれてしまいます。 

## 実用的な例

 2 つの連結成分を含む小さなグラフを考えてみましょう。 

入力:

 n = 5、エッジ: (1-2)、(2-3)、(4-5)

 クエリ: (1,3)、(1,5)

 | ステップ | ノード | キュー | コンポーネントの割り当て |
 | --- | --- | --- | --- |
 | BFS を開始する | 1 | [1] | 1 → コンプ 1 |
 | 訪問 1 | 2 件追加 | [2] | 2 → コンプ 1 |
 | 訪問 2 | 3 件追加 | [3] | 3 → コンプ 1 |
 | 仕上げコンポーネント | - | [] | コンポーネント 1 が完了しました |
 | 次のBFS | 4 | [4] | 4 → コンプ 2 |
 | 訪問 4 | 5 件追加 | [5] | 5 → コンプ 2 |

 クエリ:

 (1,3) → 同じコンポーネント → YES

 (1,5) → 異なるコンポーネント → いいえ

 このトレースは、コンポーネントが形成されると、クエリは単純な等価性チェックに減り、走査は決して繰り返されないことを示しています。 

2 番目の例:

 入力:

 n = 4、エッジ: なし

 各ノードは独自のコンポーネントを形成します。 異なるノード間のすべてのクエリは直ちに NO を返しますが、自己クエリは YES を返します。 これにより、分離されたノードが正しく処理されることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m + q) | 各ノードとエッジは BFS 中に 1 回訪問され、各クエリは O(1) | で応答されます。 
| スペース | O(n + m) | 隣接リストとコンポーネント配列 |

 前処理コストはグラフ サイズに比例し、クエリ処理はクエリごとに一定です。 各エッジが 1 回だけ処理されるため、これは最大の制約でも制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    from collections import deque

    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    comp = [0] * (n + 1)
    cid = 0

    for i in range(1, n + 1):
        if comp[i]:
            continue
        cid += 1
        q = deque([i])
        comp[i] = cid
        while q:
            u = q.popleft()
            for v in g[u]:
                if comp[v] == 0:
                    comp[v] = cid
                    q.append(v)

    qn = int(input())
    out = []
    for _ in range(qn):
        a, b = map(int, input().split())
        out.append("YES" if comp[a] == comp[b] else "NO")

    return "\n".join(out)

assert run("1 0\n0\n") == "", "single node no queries"

# simple chain
assert run("3 2\n1 2\n2 3\n2\n1 3\n1 2\n") == "YES\nYES"

# disconnected graph
assert run("4 2\n1 2\n3 4\n2\n1 3\n1 2\n") == "NO\nYES"

# all isolated nodes
assert run("3 0\n3\n1 2\n2 3\n1 1\n") == "NO\nNO\nYES"

 ## 特殊なケース

 m = 0 の空のグラフでは、すべてのノードが分離されます。 BFS ループは引き続きすべてのノードを反復処理しますが、各ノードは独自のコンポーネントになります。 (1,2) のようなクエリは、コンポーネント ID が異なるため、正しく NO を返します。 

完全に接続されたグラフでは、ノード 1 から始まる最初の BFS がすべてのノードを訪問し、それらに同じコンポーネント ID を割り当てます。 任意の 2 つのノード間のすべてのクエリは YES を返し、最初のコンポーネントの走査以降は BFS 呼び出しは必要ありません。 

(v, v) などのセルフクエリは常に YES を返します。これは、クエリ処理が開始される前にノードにコンポーネントが割り当てられ、comp[v] == comp[v] が自明に成立することが保証されるためです。
