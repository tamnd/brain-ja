[CF 442D - アダムとツリー](https://codeforces.com/problemset/problem/442/D)

 **評価:** 2600
 **タグ:** データ構造、ツリー
 **解決時間:** 3 分 49 秒
 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 ツリーは 1 つのルート頂点から始まります。 各操作により、既存の頂点に新しいリーフが 1 つ追加されます。 加算のたびに、次の数量の可能な最小値を計算する必要があります。 

木の端に色を付けます。 同じ色のエッジは 1 つの接続されたパスを形成する必要があり、頂点に同じ色の 2 つ以上のエッジが存在することはできません。 任意の頂点について、その頂点からルートまでのパスを調べ、そのパス上に表示される異なる色の数を数えます。 カラーリングのコストは、すべての頂点にわたるそのような最大数です。 コストは可能な限り最小限に抑えたいと考えています。 

入力は静的ツリーを記述していません。 一連の挿入について説明します。 もし`p[i] = v`、次に頂点`i + 1`の新しい子としてアタッチされます`v`。 各挿入後に、現在のツリーの最適コストを出力します。 

最大の困難は制約です`n ≤ 10^6`。 挿入のたびに重要なものを再計算するソリューションは直ちに除外されます。 平`O(height)`挿入ごとの作業が頻繁に発生すると危険になる可能性があります。 合計作業量は直線に非常に近い値を維持する必要があります。 

間違いやすい方法がいくつかあります。 

2 つの葉の子を持つルートを考えてみましょう。```
1
├─2
└─3
```答えは`2`、 ない`1`。 1 つの色を同時に両方のブランチに継続することはできません。 パスが同じように難しい 2 つのサブツリーに分割されると、どの色付けにも追加の色レベルが 1 つ必要になります。 

ここでチェーンを考えてみましょう。```
1
└─2
   └─3
      └─4
```答えはまだです`1`。 単一の色でチェーン全体をカバーできます。 深さまたは高さをカウントすると、誤って生成される`4`。 

別の微妙なケースは次のとおりです。```
1
├─2
│  └─4
└─3
```答えは`2`、 ない`3`。 深い枝は1本だけです。 太い枝に使用されている色は根まで続くため、同じくらい難しい枝が少なくとも 2 つない限り、難易度は上がりません。 

これらの例は、子の最大値とその最大値に達する子の数に依存する再帰的な量を示しています。 

## アプローチ

 ブルートフォースの観点は、挿入のたびにツリーを構築し、最適なカラーリングを最初から再計算することです。 

有益な観察は、すべてのカラー クラスがパスであるということです。 パスが分岐頂点に到達すると、最大 1 つの子を通過して続行できます。 他のすべての子サブツリーは、新しいカラー セグメントを開始する必要があります。 これにより、ツリーに対する再帰的な最適化が行われます。 

挿入のたびにすべてのノードの最適値を最初から計算すると、最悪のケースは 2 次式になります。 100 万件の挿入があるツリーでは、これは完全に不可能になります。 

重要な洞察は、最適コストはまさに根を張った木のホートン・ストララー数であるということです。 

させて`f(v)`をルートとするサブツリーの最適なコスト寄与になります。`v`。 

葉っぱに関しては、`f(v) = 1`。 

内部ノードの場合は、`m`その子の中での最大値になります。 

価値のある子が 1 人だけの場合`m`の場合、最適なカラー パスはその子を経由して続行できるため、次のようになります。```
f(v) = m
```少なくとも 2 人の子供に価値がある場合`m`の場合、カラー レベルを 1 つ追加することは避けられません。```
f(v) = m + 1
```これはまさにシュトララー回帰です。 

Strahler の数値は増加するだけなので、ダイナミックな部分がはるかに簡単になります。 木にはせいぜい`10^6 + 1`頂点、ストララー数が超えることはありません`21`、値を取得してから`k`少なくとも必要です`2^(k-1)`葉。 

子の値は、プロセス全体を通じてわずかな回数だけ変更されます。 これにより、合計更新数がほぼ直線的に計算されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n log n) が償却され、log n ≤ 21 | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての頂点について、現在の Strahler 値を保存します。`val[v]`。 
2. すべての頂点ストアについて`mx[v]`、その子の中で最大の Strahler 値。 
3. すべての頂点について、現在それぞれの可能な値を持つ子の数を維持します。 可能な最大値は最大ですので、`21`、小さな固定範囲で十分です。 
4. 新しいリーフが作成されると、その値は次のようになります。`1`。 
5. リーフを親にアタッチします。 親の観点から見ると、価値のある一人の子供`1`が現れた。 
6. 親のカウンターを更新し、その値を再計算します。 

もし`mx`は最大の子の値であり、`cnt[mx]`がそれを達成する子供の数である場合、次のようになります。```
val = 1                         if mx = 0
val = mx                        if cnt[mx] = 1
val = mx + 1                    if cnt[mx] ≥ 2
```7. 親の値が変化しなかった場合は、停止します。 それ以上のものは何も変えることができません。 
8. 親の値が次から変更された場合`old`に`new`、その親に移動します。 その祖先では、1 つの子の値が次から変更されました。`old`に`new`。 
9. 値が変わらないか、ルートに到達するまで繰り返します。 
10.挿入処理後、出力`val[root]`。 

これが効率的である理由は、値が増加するだけだからです。 頂点は、ツリーの存続期間全体にわたって最大約 20 個の異なる値を通過できるため、伝播される更新の総数は少なくなります。 

### なぜ効果があるのか

 Strahler の再帰は、色の制約を正確に捉えています。 

カラー パスは、最大 1 つの子サブツリーを経由して続行できます。 固有の最も難しい子がある場合、最適なパスはそれを通過し続けるため、追加のカラー レベルは必要ありません。 最も難しい子が 2 つ以上ある場合、現在のカラー パスを継承できるのは 1 つだけであり、その下のどこかに別のカラー レベルが強制されます。 これにより、必要な値が 1 つ増加します。 

維持されるカウンターは常に、現在の子値のマルチセットを表します。 すべての更新で子コントリビューションが 1 つだけ変更されるため、これらのカウンターから親を再計算すると、繰り返しが維持されます。 祖先は子の値のみに依存するため、値が変更された場合にのみ伝播するだけで十分です。 したがって、各挿入後のルート値がまさに最適なカラーリング コストになります。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    max_nodes = n + 2
    MAXR = 22  # Strahler number never exceeds 21 for n <= 1e6

    parent = array('I', [0]) * max_nodes
    val = bytearray(max_nodes)
    mx = bytearray(max_nodes)

    cnt = array('I', [0]) * (max_nodes * MAXR)

    val[1] = 1

    ans = []

    for node, par in enumerate(p, start=2):
        parent[node] = par
        val[node] = 1

        v = par
        old_child = 0
        new_child = 1

        while v:
            base = v * MAXR

            if old_child:
                cnt[base + old_child] -= 1

            cnt[base + new_child] += 1

            if new_child > mx[v]:
                mx[v] = new_child

            old_val = val[v]

            m = mx[v]
            if m == 0:
                new_val = 1
            else:
                new_val = m + (cnt[base + m] >= 2)

            if new_val == old_val:
                break

            val[v] = new_val

            old_child = old_val
            new_child = new_val
            v = parent[v]

        ans.append(str(val[1]))

    sys.stdout.write(" ".join(ans))
