 ## 解決策
 ## 問題の理解

 私たちには一連の友人が与えられ、各友人は独立して既知の確率でコンテストの問題を作成することに成功します。 アンドレイは、これらの友人の一部を招待します。 招待されると、各友達は他の友達とは関係なく、問題を投稿するか、投稿しません。 

私たちが気にする結果は非常に具体的です。アンドレイは、たった 1 人の友人が問題を引き起こした場合にのみ満足します。 誰も問題を起こさない場合、または 2 人以上の友人が成功した場合、彼は不幸です。 タスクは、成功した貢献者を 1 人だけ獲得する確率が最大になるように、どの友達を招待するかを選択することです。 

重要なオブジェクトは、個々の確率そのものではなく、サブセットを選択した後に成功した友人の数に対して引き起こされる分布です。 選択された各サブセットは独立したベルヌーイ変数の合計を定義し、この合計が正確に 1 に等しくなる確率を最大化したいと考えています。 

制限は小さく、友達は最大 100 人です。 これは、大幅に枝刈りされない限り、中程度の推論を超えるサブセットの指数関数的な列挙を即座に排除しますが、より重要なのは、O(n^2) または O(n^3) の動的アプローチが不要であることを示唆していることです。 O(n log n) または O(n) に近い解が期待されます。 

すべての確率が非常に小さい場合、微妙なエッジケースが発生します。 その場合、多くの友達を招待すると、少なくとも 1 回の成功の可能性が高まるため魅力的に見えますが、複数の成功の可能性も高まるため、これは禁止されています。 もう 1 つのエッジ ケースは、確率が 1 に近い非常に大きい場合に発生します。この場合、より多くの人を招待すると、複数の成功がほぼ保証され、有害になります。 

「友達は多ければ多いほど良い」という素朴な直感はすぐに崩れます。 たとえば、すべての確率が 0.8 の場合、2 人の友人を招待すると 1 回だけ成功する確率は 0.8 · 0.2 + 0.2 · 0.8 = 0.32 に等しくなりますが、1 人の友人を招待した場合は 0.8 になります。 したがって、追加するとターゲットの確率が低下する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、友人のすべてのサブセットが試行されます。 各サブセットについて、どの友人が成功するかに関するすべての選択肢を合計し、残りの友人の失敗の確率を乗算することによって、正確に 1 人の友人が成功する確率を計算します。 サイズ k のサブセットの場合、これには O(k) のコストがかかり、すべてのサブセットにわたって O(n・2^n) になります。これは、n = 30 の場合でも実現可能性をはるかに超えています。 

固定サブセットの式の構造を見ると、さらに便利なことがわかります。 部分集合 S を選択するとします。正確に 1 つの成功の確率は、pi の S の i の合計に、選択した他のすべての友人が失敗する確率を掛けたものとして書くことができます。 これにより、反復乗算構造が導入されます。つまり、すべての項がサブセット上の積に依存します。 

重要な観察は、友人を 1 人追加することで価値がどのように変化するかという観点から考えることです。 選択したセット S を現在の値 P(S) で維持し、確率 p で新しい友人を追加することを検討すると、新しい確率は (1 − p)・P(S) + p・product_of_failures(S) になります。 この形式は、友人の貢献が p だけでなく、現在の構造とどのように乗算的に相互作用するかにも依存することを示唆しています。 

目的を書き直すと、よりきれいなフォームが得られます。 集合 S に対して次のように定義すると、

 P(S) = S のうち 1 つだけが成功する確率

 次に、新しい友達を追加すると、次のようになります。 

P(S ∪ {i}) = P(S)・(1 − p_i) + (S の j に対する (1 − p_j) の積)・p_i

 これは、現在 1 人だけが成功する確率と、選択したすべての友人が失敗する確率という 2 つの合計量を維持することを示唆しています。 これらを使用すると、各友達の追加を貪欲に検討し、値が増加するかどうかを判断できます。

最適な戦略は、最終的には特定の順序で貪欲になります。p_i / (1 − p_i) を減少させることによって友人を並べ替えます。これは、1 つの成功だけを生み出すか、複数の成功をもたらすかのバランスにおいて、わずかな改善をもたらす友人を優先することに相当します。 

並べ替えたら、各友達を繰り返し追加して、確率が向上するかどうかを追跡します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・2^n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各確率 p_i を、その相対的な強さを反映する値、特に比率 p_i / (1 − p_i) に変換します。 これは、友人が失敗した場合と比べて成功する可能性がどの程度あるかを示します。これは、厳密に 1 つの結果のバランスを取る場合に重要になります。 
2. すべての友人をこの比率の降順に並べ替えます。 この順序では、衝突のリスクを過度に高めることなく、1 つの成功を生み出すためにより効率的に貢献する友人が優先されます。 
3. 2 つの変数を初期化します。1 つは選択したすべての友人が失敗する確率、もう 1 つは 1 人の友人だけが成功する確率です。 
4. ソートされた順序で友人を反復処理し、各友人について、その友人を含めた場合に何が起こるかを計算します。 失敗確率を乗算的に更新し、「この友人だけが成功する」プラス「既存の構造は有効であり、この友人は失敗する」という分解を使用して、正確に 1 つの確率を更新します。 
5. より早く停止することはサブセットを選択することに対応するため、この順序のすべてのプレフィックスにわたって見つかった最良の値を追跡します。 
6. 得られた最大確率を出力します。 

### なぜ効果があるのか

 どの時点でも、選択したサブセットの状態は 2 つの値によって完全に記述されます。サブセット内の誰も成功しない確率と、1 つだけが成功する確率です。 新しい要素は、これら 2 つの集合体を通じてのみサブセットと対話します。 これにより、サブセット構造が 1 次元の順序付け問題に還元され、ソートされた順序で隣接する要素のローカル交換引数から最適性が導き出されます。 2 つの隣接する友人が p/(1-p) に関して順序が狂っている場合、それらを交換しても結果の確率は改善されず、ソートによって最適なプレフィックスが得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(float, input().split()))
    
    # sort by p/(1-p) decreasing
    p.sort(key=lambda x: x/(1.0 - x) if x < 1.0 else float('inf'), reverse=True)
    
    best = 0.0
    prod_fail = 1.0  # product of (1 - p_i) in current set
    prob_one = 0.0   # probability exactly one success
    
    for x in p:
        new_prod_fail = prod_fail * (1 - x)
        new_prob_one = prob_one * (1 - x) + prod_fail * x
        
        prob_one = new_prob_one
        prod_fail = new_prod_fail
        
        if prob_one > best:
            best = prob_one
    
    print(f"{best:.12f}")

if __name__ == "__main__":
    solve()
```ソートのステップにより、成功と失敗の寄与率の観点から最も「効率的な」友人が最初に考慮されるようになります。 2 つの実行変数は現在のサブセットの完全な確率的状態を表すため、最初から再計算せずに各プレフィックスを評価するには、それらを更新するだけで十分です。 

よくある実装の落とし穴は、p が 1 に非常に近い場合、(1 − p) による浮動小数点除算が不安定になることを忘れていることです。コードは、p = 1 を無限の比率として扱い、そのような要素を強制的に前面に置くことでこれを処理します。 

## 実用的な例

 ### 例 1

 入力:```
4
0.1 0.2 0.3 0.8
```比率で並べ替えると、順序は次のようになります。 

0.8、0.3、0.2、0.1

 段階的に状態を追跡します。 

| ステップ | p_i | prod_fail | 確率1 | 最高 |
 | --- | --- | --- | --- | --- |
 | 初期化 | - | 1.0 | 0.0 | 0.0 |
 | 1 | 0.8 | 0.2 | 0.8 | 0.8 |
 | 2 | 0.3 | 0.14 | 0.44 | 0.8 |
 | 3 | 0.2 | 0.112 | 0.496 | 0.8 |
 | 4 | 0.1 | 0.1008 | 0.5064 | 0.8 |

 最初の友人のみを選択すると、最高の値が得られます。 これは、強い確率の後に弱い確率を追加すると、1 回だけ成功する可能性が減少することを裏付けています。 

### 例 2

 入力:```
3
0.5 0.5 0.5
```ソート順は変更されません。 

| ステップ | p_i | prod_fail | 確率1 | 最高 |
 | --- | --- | --- | --- | --- |
 | 1 | 0.5 | 0.5 | 0.5 | 0.5 |
 | 2 | 0.5 | 0.25 | 0.5 | 0.5 |
 | 3 | 0.5 | 0.125 | 0.375 | 0.5 |

 さらに追加すると衝突の可能性が高まるだけなので、最適な選択は 1 人の友人です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose
    
    data = inp.strip().split()
    n = int(data[0])
    p = list(map(float, data[1:]))

    p.sort(key=lambda x: x/(1.0 - x) if x < 1.0 else float('inf'), reverse=True)

    best = 0.0
    prod_fail = 1.0
    prob_one = 0.0

    for x in p:
        new_prod_fail = prod_fail * (1 - x)
        new_prob_one = prob_one * (1 - x) + prod_fail * x
        prod_fail, prob_one = new_prod_fail, new_prob_one
        best = max(best, prob_one)

    return f"{best:.10f}"

 ## 特殊なケース

 すべての確率がゼロの場合、すべてのサブセットで 1 回だけ成功する確率がゼロになります。 アルゴリズムは最適値をゼロに初期化し、決して増加しないため、出力は正しいままになります。 

確率がちょうど 1 の場合、そのような要素を複数含むサブセットは、ただちに 1 回だけ成功する確率がゼロになります。 貪欲な順序付けでは、無限の比率によりこれらが最初に配置され、アルゴリズムはそのような友人を 1 つだけ選択すると確率が 1 になると正しく評価します。 

1 つの値が 1 に近く、多数の小さい値があるなど、確率が極端に偏っている場合、接頭辞の評価により最初の要素で停止することが保証され、低品質の寄与者の追加による劣化が回避されます。
