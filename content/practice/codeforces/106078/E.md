 ## 解決策
 ## 問題の理解

 私たちは火星と地球の間を行き来するミルクジャグの小さなコレクションを管理しています。 宇宙船の旅は、火星から地球へ行くか、地球から火星へ行くかのどちらかです。 火星から地球への旅で水差しが地球に到着すると、すぐにいっぱいになります。 その牛乳を持ち帰るには、その満たされた水差しを後の地球から火星への旅行に割り当てなければなりません。 各宇宙船には最大でも 1 つの水差しを搭載できます。 

重要な部分は、ジョニーが最初に空の水差しを 2 つしか所有していないということです。 旅行中のジャグは利用できません。 火星への帰還に成功すると、水差しは再び空になり、再利用できます。 課題は、水差しいっぱいの牛乳をどれだけ火星に届けられるかを最大化することです。 

入力は最大 100,000 回の宇宙船旅行を記述します。 各旅行には開始時刻、終了時刻、および方向があります。 トリップの数が多いため、考えられるすべてのペアのトリップを試行するアプローチでは遅すぎます。 最大約 10^10 の可能なペアがあり、1 秒のスタイル制限には収まりません。 線形時間に近い移動を処理する必要があります。 

厄介なケースは、水差しが単なる選択された間隔ではなくリソースであるという事実によって引き起こされます。 便利そうに見える旅行でも、長時間水差しを占有し、より良いシーケンスを妨げる可能性があります。 

たとえば、次のことを考えてみましょう。```
3
0 100 0
1 2 0
3 4 1
```答えは`1`。 

不用意な解決策は、両方の地球旅行に参加することが常に最善であると考えるかもしれません。 ただし、利用可能な火星帰還は 1 つだけです。 長い旅行は時間 4 までに戻ることができないため、牛乳を生産できるのは短い旅行だけです。 

別のケース:```
4
0 5 0
1 2 0
3 4 1
6 7 1
```答えは`1`。 

互換性のある旅行のペアだけを数えると、両方の地球旅行が役立つと考えるかもしれません。 そうではありません。 短い地球旅行と最初の火星旅行で 1 サイクルを完了できます。 2 回目の地球旅行は、満席になる前にタイム 5 まで待たなければならないため、初期の火星旅行を逃します。 

ソリューションは時間順に決定を下し、利用可能なジャグの数を記憶する必要があります。 

## アプローチ

 直接的なアプローチでは、すべての火星から地球への旅行を、その後のすべての地球から火星への旅行と一致させようとします。 考えられる各ペアについて、最初の旅行が 2 番目の旅行が開始する前に終了するかどうか、および利用可能なジャグがこの選択を許可するかどうかを確認できます。 これは正しいです。考えられるインポートはすべて、まさにそのようなペアで表されるからです。 ただし、100,000 回のトリップの場合、すべてのペアをチェックするには約 10^10 の操作が必要となり、これは可能な作業をはるかに超えています。 

重要な観察は、唯一の限られたリソースは水差しの数であるということです。 どのジャグが無料であるかを知る必要はなく、いくつが無料であるかだけを知る必要があります。 イベントごとにこの数は変化します。 火星から地球への旅が始まるとき、空の水差しが出発する可能性があります。 地球に到達すると、中身が詰まった水差しとなって帰還を待ちます。 地球から火星への旅行が始まると、待っている満杯の水差しが出発する可能性があります。 火星に到達すると、水差しは再び空になります。 

これにより、問題はすべてのトリップ エンドポイントにわたるスイープに変わります。 欲張りな選択は、可能な限り早いイベントで利用可能なジャグを常に使用することです。 空になったジャグを早めに使用しても問題はありません。早めの旅行をスキップしても、そのジャグは後で使用されないままになるだけだからです。 より早く開始すると、ジャグがサイクルを完了するのに少なくとも同じ時間がかかります。 

同様に、帰りの便が利用可能な場合は、満杯のジャグをすぐに送ることが最適です。これは、空のジャグの数がすぐに増えるだけであるためです。 

この実装では、火星の空の水差しの数と、地球上で待機している満たされた水差しの数という 2 つのカウンターが保持されます。 最適なスケジュールをシミュレートするには、イベントを時系列に処理するだけで十分です。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適なスイープ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 宇宙船旅行ごとに 2 つのイベントを作成します。 開始イベントは宇宙船が出発する瞬間を表し、終了イベントは宇宙船が到着する瞬間を表します。 水差しは両方の時点で状態を変更するため、両方が必要です。 
2. すべてのイベントを時間順に並べ替えます。 毎回の値は一意であるため、変更の順序についてはあいまいさがありません。 
3. 火星上の空の水差しの数を維持する。 ジョニーは空の水差しを 2 つ所有しているため、最初はこの値は 2 です。 
4. 現在地球上で待機している満たされた水差しの数を維持します。 牛乳はまだ輸送されていないため、最初は 0 です。 
5. 火星から地球への出発が行われるときは、空の水差しがあればそれを使用してください。 水差しは火星を離れるので、空になった水差しの数は減ります。 
6. 同じ旅行が地球に到着すると、水差しは満杯になり、帰りの旅行を待っています。 満たされた水差しの数を増やします。 
7. 地球から火星への出発が起こったら、満たされた水差しがあればそれを送ります。 満たされたジャグの数を減らします。 
8. 帰りの船が火星に到着すると、牛乳は無事配達されています。 空の水差しの数を増やして答えを増やしてください。 

なぜ効果があるのか:

 不変条件は、すべてのイベントが処理された後、カウンターはその時点までのすべての決定後の可能な限り最良の状態を正確に表すということです。 火星から地球への旅行をより早く開始しても、利用可能な水差しを最終的にミルクを生成できる状態に移動させるだけなので、将来の可能性が減ることはありません。 満杯の水差しをできるだけ早く返却しても、リソースが早く解放されるだけです。 すべての選択は可能な限り早い時点で行われるため、将来のシーケンスでは、この貪欲なシミュレーションよりも多くの利用可能なリソースを持つことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    events = []

    for _ in range(n):
        l, r, t = map(int, input().split())
        if t == 0:
            events.append((l, 0, 0))
            events.append((r, 1, 0))
        else:
            events.append((l, 0, 1))
            events.append((r, 1, 1))

    events.sort()

    empty = 2
    filled = 0
    ans = 0

    for _, kind, direction in events:
        if kind == 0:
            if direction == 0:
                if empty > 0:
                    empty -= 1
            else:
                if filled > 0:
                    filled -= 1
        else:
            if direction == 0:
                filled += 1
            else:
                empty += 1
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、各旅行エンドポイントをイベントとして保存します。 3 番目のフィールドは元の旅行の方向を区別し、2 番目のフィールドは出発と到着を区別します。 

スイープ変数は実際の状況を直接表します。`empty`火星から地球への船に設置できる水差しを数えます。`filled`地球に到着し、戻ってくる準備ができている水差しを数えます。 帰還が到着すると、それが牛乳が火星に到着するまさにその瞬間であるため、答えは大きくなります。 

操作の順序は、すべてのイベントを並べ替えることによって処理されます。 すべての時間が異なるため、イベント間に同点の問題はありません。 カウンタは、対応する物理的なアクションが発生した後にのみ更新されるため、トリップ境界付近でのオフバイワンの間違いが回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 2n 個の生成されたイベントのソートがスイープを支配します。 
| スペース | O(n) | 旅行ごとに 2 つのイベントを保存します。 

このソリューションは、旅行を相互に比較することを避けるため、制約に適合します。 処理されるイベントの数は、入力されたトリップ数のわずか 2 倍です。

import sys
import io

def solve_data(data):
    sys.stdin = io.StringIO(data)
    input = sys.stdin.readline

    n = int(input())
    events = []

    for _ in range(n):
        l, r, t = map(int, input().split())
        if t == 0:
            events.append((l, 0, 0))
            events.append((r, 1, 0))

                empty -= 1
            elif direction == 1 and filled:

        else:
            if direction == 0:
                filled += 1
            else:
                empty += 1
                ans += 1

    return str(ans)

 ## 特殊なケース

 長い地球旅行が短い旅行を妨げる場合:```
3
0 100 0
1 2 0
3 4 1
```両方のジャグが空いているため、スイープは最初のトリップを時間 0 に開始し、2 番目のトリップを時間 1 に開始します。 短いトリップは時間 2 で満たされ、時間 4 で戻り、インポートが 1 回成功します。 長い旅行は、帰国の機会が過ぎた後の時間 100 でのみ満たされるため、最終的な答えは次のようになります。`1`。 

同じジャグを再利用する必要がある場合:```
4
0 2 0
4 6 0
1 3 1
5 7 1
```最初の水差しサイクルは時間 3 で完了します。解放された水差しは再び空としてカウントされ、2 番目のサイクルで使用できます。 答えは次のようになります`2`これは、アルゴリズムがジャグを 1 回限りのオブジェクトとして扱うのではなく、ジャグの寿命を追跡していることを示しています。
