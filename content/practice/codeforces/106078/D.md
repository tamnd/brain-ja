 ## 解決策
 ## 問題の理解

 私たちは一列に並べられた一連の石の塊を与えられます。 この行から、単一の連続セグメントを選択できます。 セグメントを選択したら、そのセグメント内の価値の分布に基づいてその「楽しさ」を評価します。 

選択したセグメントについては、等しい質量をグループ化します。 質量値の場合`m`表示されます`f`セグメント内で何度も貢献します`m * f`合計スコアに。 すべての出現は独自のグループ内で 1 回だけカウントされるため、この式は各要素の合計を単純化しますが、制約があります。すべてのサブ配列にわたって最適化しているのではなく、最大でも次の要素を含むセグメントに制限しています。`k`明確な価値観。 

したがって、タスクは最大でも以下のサブ配列を見つけることになります。`k`要素の合計を最大化する個別の数値。 

入力は整数のリストであり、distinct-count 制約の下ですべての有効な部分配列の最大可能合計を出力する必要があります。 

制約`n ≤ 10^5`すべての部分配列を列挙する二次手法は直ちに除外されます。 開始と終了にわたる二重ループは、おおよその結果を生成します。`n^2 / 2`セグメント、つまり`5 * 10^9`最悪の場合、1 ～ 2 秒の制限をはるかに超えて操作が可能になります。 これにより、線形または線形に近いスライディング ウィンドウ スタイルのソリューションが推進されます。 

微妙な点は、「周波数と値」の表現のため、スコア関数は最初は合計よりも複雑なもののように見えるかもしれないということです。 素朴な解釈では、すべてのウィンドウ内の周波数を追跡し、寄与を最初から再計算することを示唆するかもしれませんが、それはウィンドウの拡張ごとに作業を繰り返すことになります。 

単純な推論を打ち破るエッジケースは、ほとんどが明確な制約に関するものです。 

のようなケース`1 1 1 1`と`k = 1`は簡単です。配列全体が有効なので、選択する必要があります。 不注意な実装では、重複を個別の数が増加したものとして誤って処理した場合、ウィンドウを不必要に縮小しようとする可能性があります。 

さらに興味深いケースは、`1 2 3 1 2`と`k = 2`。 最適なウィンドウは、必ずしも最長のプレフィックスまたはサフィックスであるとは限りません。 古い要素を慎重に削除せずにアルゴリズムが貪欲に拡張すると、最終的に 3 つの異なる値が生成され、簿記の実行方法に応じてウィンドウを誤って受け入れたり拒否したりする可能性があります。 

## アプローチ

 ブルートフォース戦略は、すべてのサブ配列を考慮することです`[l, r]`、その中にある個別の値の数を計算し、それが最大であるかどうかを調べます。`k`、その合計を計算し、答えを更新します。 各ウィンドウの周波数マップを維持すると、個別のカウントを再計算できますが、合計を再計算したり、ウィンドウごとに周波数構造をリセットしたりする必要があります。`l`実装スタイルに応じて、3 次または 2 次の動作が発生します。 増分更新であっても、すべてを繰り返すと、`l`まだ力を入れています`O(n^2)`ウィンドウ拡張機能は遅すぎます`n = 10^5`。 

重要な観察は、合計と個別カウントの両方がスライディング ウィンドウの下で適切に動作することです。 右側の境界を拡張すると、合計と頻度の両方を一定時間で更新できます。 個別の値の数が超過した場合`k`、制約が復元されるまで、左側の境界を前方に移動できます。 これにより、問題は各位置で終了する最適な有効ウィンドウを維持することに変わります。 

ブルートフォース手法は、すべての候補を明示的にチェックするため機能しますが、重複する情報を繰り返し再計算するため失敗します。 スライディング ウィンドウのアプローチでは、各要素がウィンドウに出入りするのが最大 1 回になるようにすることで、この冗長性を排除します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | スライディングウィンドウ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在の合計と個別の要素の数とともに、現在ウィンドウ内の値の度数表を維持します。 

1. 2 つのポインタを初期化する`l = 0`、`r = 0`、 とともに`current_sum = 0`、`distinct = 0`、および空の周波数マップ。 常に有効な窓口を準備中です。 
2.移動`r`配列全体で左から右へ。 含めるたびに、`a[r]`、それを合計に追加し、頻度を更新します。 この値がウィンドウに初めて表示されると、個別のカウンターがインクリメントされます。 このステップにより、現在のウィンドウの正確な寄与を再計算することなく常に知ることができます。 
3.挿入後`a[r]`、ウィンドウが制約に違反しているかどうかを確認します。`distinct > k`。 そうなった場合は、移動してウィンドウを左から縮小します。`l`前方に移動し、合計から要素を削除し、頻度を更新します。 周波数がゼロに低下するたびに、個別のカウンターをデクリメントします。 制約が復元されるまで縮小を続けます。 これにより、ウィンドウが評価される前に常に有効であることが保証されます。 
4. ウィンドウが有効になったら、次のように答えを更新します。`current_sum`。 これは正しいです。なぜなら、正しいエンドポイントごとに`r`、制約を満たす可能な限り最良の左境界を検討します。 
5. までこのプロセスを続けます。`r`配列の最後に到達します。 

### なぜ効果があるのか

 任意の固定位置で`r`、アルゴリズムは可能な限り最小の左境界を維持します。`l`サブ配列が`[l, r]`多くても含まれる`k`明確な価値観。 次で終わるその他の有効なサブ配列`r`これまたはその右側から開始する必要があります`l`すべての数値が負ではないため、合計が減少するだけです。 したがって、アルゴリズムによって維持されるウィンドウがそのエンドポイントの最適な候補となり、すべてのエンドポイントの最大値を取ることですべての可能性がカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    freq = {}
    l = 0
    distinct = 0
    current_sum = 0
    best = 0

    for r in range(n):
        x = a[r]
        current_sum += x

        if x not in freq or freq[x] == 0:
            freq[x] = 1
            distinct += 1
        else:
            freq[x] += 1

        while distinct > k:
            y = a[l]
            freq[y] -= 1
            current_sum -= y
            if freq[y] == 0:
                distinct -= 1
            l += 1

        best = max(best, current_sum)

    print(best)

if __name__ == "__main__":
    solve()
```実装はスライディング ウィンドウ構造に直接に従います。 頻度辞書は、各値が何回出現するかを追跡します。`distinct`カウンタは、辞書サイズを繰り返し再計算することを避けます。 重要な点はアップデートです`current_sum`ウィンドウを拡大および縮小するときに対称的に計算されます。そうでない場合、答えは実際の部分配列の合計からずれてしまいます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各要素はウィンドウに出入りするのは最大 1 回であるため、すべてのポインターと頻度の更新は線形です。 
| スペース | O(n) | 頻度マップは、配列内の個別の値ごとに最大 1 つのエントリを保存します。 

線形の複雑さは、次の制約内に快適に適合します。`n ≤ 10^5`、メモリ使用量は個別の値の数によって制限され、これも最大で`n`。 したがって、このソリューションは両方の制限を余裕を持って満たします。

 ## 特殊なケース

 すべての要素が同一の場合、周波数マップは大きくなりますが、`distinct`1 を超えることはないため、ウィンドウは常に全長に拡張されます。 このアルゴリズムは単一の更新パスを正しく維持し、縮小をトリガーすることはありません。 

いつ`k`等しい`n`、制約は決してアクティブになりません。 ウィンドウが配列全体になり、アルゴリズムは、ポインタが左側に移動することなく正確性の保証を維持しながら、プレフィックスの合計を計算するように退化します。 

値が大きく交互に変化する場合、`k = 1`、すべての新しい要素は即座に縮小を強制します。 左ポインタは右ポインタを効果的に追跡し、ウィンドウ サイズが 1 を超えることはありません。これは、最悪の場合の振動入力でも縮小ロジックが有効性を正しく復元することを確認します。
