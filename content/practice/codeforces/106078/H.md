 ## 解決策
 ## 問題の理解

 各プローブは、2 つの制限とコストによって説明できます。 1 つの制限は、どのくらいの温度に耐えられるかということであり、もう 1 つは、どのくらいの風に耐えられるかということです。 プローブは、両方の条件を同時に処理する場合にのみ、その場所で使用できます。 あらゆる場所のクエリに対して、その場所の温度と風に十分な強度を備えた最も安価なプローブが必要です。 

より具体的に言えば、各プローブが隅のしきい値を定義する 2D 平面内に長方形のコレクションがあります。 プローブのしきい値ポイントがクエリ ポイントの右側にある場合、つまり両方の座標が少なくとも同じ大きさである場合、プローブはクエリに対して有効です。 このようなプローブの中で、コストは最小限に抑えたいと考えています。 

入力サイズは最大 10 万のプローブと 10 万のクエリに達します。 これにより、クエリごとにすべてのプローブをチェックすることは直ちに除外されます。これは、最悪の場合、比較が 10¹⁰ 程度になるためであり、これは 1 ～ 2 秒の制限で処理できる範囲をはるかに超えています。 許容可能なソリューションでは、プローブとクエリの両方をほぼ直線的な時間で処理する必要があります。 

実装時に失敗することが多い単純な解釈は、制約を独立して扱うことです。たとえば、最初に温度でフィルタリングし、次に風を線形にスキャンします。 両方の次元が相互作用すると、それは壊れます。 もう 1 つの微妙な失敗ケースは、複数のプローブが部分的に相互に優位になる場合に発生します。プローブは温度では優れているが風では劣る場合や、その逆の場合があるため、単一の次元による貪欲な順序付けは機能しません。 

ちょっとした失敗例: (5, 1, 100)、(1, 5, 1)、(3, 3, 2) というプローブ (温度、風、コスト) があるとします。 クエリ (3, 3) の場合、正しい答えは 2 です。温度だけで並べ替えて最初の有効な値を取得すると、風の制約を満たしていないにもかかわらず誤って (5,1,100) を選択する可能性があります。あるいは、フィルタリングが間違っている場合は、最適な中間のトレードオフ プローブを見逃してしまう可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。クエリごとにすべてのプローブをスキャンし、両方の制約が満たされているかどうかを確認し、最小コストを追跡します。 これは、妥当性の定義を直接評価するため、正しいです。 コストは、q 個のクエリごとに n 個のプローブをチェックし、n・q 個の操作を実行することになり、最悪の場合、10¹⁰ に達します。 その規模は大きすぎて制限時間内に終わらせることはできません。 

重要な観察は、両方の制約が単調であるということです。 プローブが特定の温度と風に対して機能する場合、より簡単なクエリ (より低い温度や風の要件) に対しても自動的に機能します。 この構造により、プローブを 2D 空間内の点として扱い、クエリを優勢チェックとして扱うことができます。 

プローブとクエリの両方を温度によって降順に並べ替えることができます。 高温から低温まで変化するにつれて、適格となるすべてのプローブが風によってキーイングされた構造に挿入されます。 いつでも、構造には、現在のクエリの温度要件を満たすプローブが正確に含まれています。 残りのタスクは、保存されているすべてのプローブの中で、少なくともクエリの風を伴うプローブの中で最小コストを見つけることです。 これは、圧縮された座標軸に対する標準的なプレフィックスまたはサフィックスの最小クエリです。 

これにより、問題は風速値に対するセグメント ツリーと組み合わせられたオフライン スイープ ラインに変わります。 各プローブは 1 回挿入され、各クエリは 1 つの範囲最小クエリをトリガーします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | スイープ + セグメント ツリー | O((n+q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちはこの問題を、プローブとクエリが温度に基づいて統一された順序で処理されるオフライン プロセスに変換します。

1. まず、すべてのプローブとクエリを収集し、いずれかに表示されるすべての風の値を抽出します。 セグメント ツリーは 10⁹ までの値を直接効率的に操作できないため、これらの値をより小さいインデックス範囲に圧縮します。 圧縮により順序が維持されます。これが必要な唯一のプロパティです。 
2. すべてのプローブを温度の降順に並べ替えます。 これにより、温度 T でクエリを処理するときに、これまでに挿入したすべてのプローブがすでに温度 ≥ T を満たしていることが保証されます。 
3. 後で出力順序を復元できるように、元のインデックスを維持しながら、すべてのクエリも温度の降順に並べ替えます。 
4. 圧縮された風軸上にセグメント ツリーを構築します。 各ノードは、そのセグメントに現在挿入されているすべてのプローブの最小コストを保存します。 
5. ソートされた順序でクエリをスイープします。 プローブの上にポインタを維持します。 クエリごとに、温度がクエリ温度以上であるすべてのプローブをセグメント ツリーに挿入し、最小コストで風に対応する位置を更新します。 このステップにより、構造が常にそのクエリの温度制約に対する有効なプローブ セットを正確に表すことが保証されます。 
6. 関連するすべてのプローブが挿入された後、クエリに必要な風から最大可能な風指数までの風の範囲についてセグメント ツリーをクエリします。 これにより、両方の制約を満たすすべてのプローブの中で最小コストが得られます。 
7. その範囲にプローブが存在しない場合、そのクエリに対して -1 を返します。 

正確性は、プローブが一度挿入されると、スイープ内の今後のすべてのクエリに対して有効なままであるという事実に依存します。これらのクエリは温度要件を下げるだけであるためです。 

### なぜ効果があるのか

 すべてのクエリ ステップで、セグメント ツリーには、温度制約が満たされるプローブのセットが正確に含まれます。 風況は範囲最小クエリによって強制されます。 両方の制約は独立して、ただしスイープ順序とセグメント ツリーを通じて一貫して適用されるため、すべてのプローブは有効になった時点で正確に考慮され、有効になったら除外されることはありません。 これにより、返される最小値が実行可能なプローブに正確に引き継がれることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = 1
        while self.n < n:
            self.n *= 2
        self.inf = 10**18
        self.t = [self.inf] * (2 * self.n)

    def update(self, i, val):
        i += self.n
        if val < self.t[i]:
            self.t[i] = val
            i //= 2
            while i:
                self.t[i] = min(self.t[2*i], self.t[2*i+1])
                i //= 2

    def query(self, l, r):
        res = self.inf
        l += self.n
        r += self.n
        while l <= r:
            if l % 2 == 1:
                res = min(res, self.t[l])
                l += 1
            if r % 2 == 0:
                res = min(res, self.t[r])
                r -= 1
            l //= 2
            r //= 2
        return res

def solve():
    n, q = map(int, input().split())
    probes = []
    wind_vals = []

    for _ in range(n):
        x, y, c = map(int, input().split())
        probes.append((x, y, c))
        wind_vals.append(y)

    queries = []
    for i in range(q):
        t, w = map(int, input().split())
        queries.append((t, w, i))
        wind_vals.append(w)

    wind_vals = sorted(set(wind_vals))
    comp = {v: i for i, v in enumerate(wind_vals)}

    probes.sort(reverse=True)
    queries.sort(reverse=True)

    seg = SegTree(len(wind_vals))

    ans = [-1] * q
    j = 0

    for t, w, idx in queries:
        while j < n and probes[j][0] >= t:
            _, y, c = probes[j]
            seg.update(comp[y], c)
            j += 1

        pos = comp[w]
        res = seg.query(pos, len(wind_vals) - 1)
        ans[idx] = -1 if res == seg.inf else res

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```このソリューションはスイープ順序を中心に構築されています。 プローブ リストは、一度プローブを通過すると、再び関連性がなくなるようにソートされています。 セグメント ツリーは風力バケットあたりの最小コストを保存し、減少する値のみを更新します。そのため、単純な最小伝播が機能します。 

Wind ≥ 必要な値が必要なため、クエリ ロジックは常にサフィックス クエリになり、圧縮インデックスからクエリを実行します。 

よくある実装の落とし穴は、圧縮後に複数のプローブが同じ風座標にマッピングされる可能性があることを忘れていることです。 セグメント ツリーの更新は、むやみに上書きするのではなく、最小限のコストで行う必要があります。

クエリ (3,3) では、温度 ≥ 3 のプローブのみが挿入されます: (5,1,100) および (3,3,2)。 風制約は有効な風 ≥ 3 から選択しますが、(3,3,2) のみが適格であるため、答えは 2 になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | 各プローブは 1 回挿入され、各クエリは log n 範囲の最小クエリを実行します。 
| スペース | O(n) | セグメント ツリーと座標圧縮配列 |

 対数係数は、圧縮された風の値に対するセグメント ツリーの演算から得られます。 n と q が最大 10⁵ であれば、これは Python の 2 秒間の一般的な制限内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf

    class SegTree:
        def __init__(self, n):
            self.n = 1
            while self.n < n:
                self.n *= 2
            self.inf = 10**18
            self.t = [self.inf] * (2 * self.n)

        def update(self, i, val):
            i += self.n
            self.t[i] = min(self.t[i], val)
            i //= 2
            while i:
                self.t[i] = min(self.t[2*i], self.t[2*i+1])
                i //= 2

        def query(self, l, r):
            res = self.inf
            l += self.n
            r += self.n
            while l <= r:
                if l % 2:
                    res = min(res, self.t[l])
                    l += 1
                if not r % 2:
                    res = min(res, self.t[r])
                    r -= 1
                l //= 2
                r //= 2
            return res

    def solve():
        n, q = map(int, input().split())
        probes = []
        vals = []
        for _ in range(n):
            x, y, c = map(int, input().split())
            probes.append((x, y, c))
            vals.append(y)

        queries = []
        for i in range(q):
            t, w = map(int, input().split())
            queries.append((t, w, i))
            vals.append(w)

        vals = sorted(set(vals))
        mp = {v:i for i,v in enumerate(vals)}

        probes.sort(reverse=True)
        queries.sort(reverse=True)

        seg = SegTree(len(vals))
        ans = [-1]*q
        j = 0

        for t, w, idx in queries:
            while j < n and probes[j][0] >= t:
                x, y, c = probes[j]
                seg.update(mp[y], c)
                j += 1

            res = seg.query(mp[w], len(vals)-1)
            ans[idx] = -1 if res == seg.inf else res

        return "\n".join(map(str, ans))

    return solve()

 ## 特殊なケース

 複数のプローブが同じ風力値を共有しているがコストが異なる場合、厄介な状況が発生します。 セグメント ツリーの更新では、常に最小限のコストを維持する必要があります。 上書きすると、より適切なプローブが誤って破棄されてしまいます。 

もう 1 つのエッジ ケースは、すべてのプローブが 1 つの制約に失敗する場合です。 その場合、セグメント ツリー クエリは無限大を返すため、出力は直接出力するのではなく、-1 に変換する必要があります。 

最後の微妙なケースは、クエリの風の値がすべての圧縮座標より小さいか、すべての圧縮座標より大きい場合です。 圧縮により常に正しくマッピングされますが、接尾辞の範囲全体を使用することを忘れると、有効な候補が暗黙的に削除されます。
