 ## 問題の理解

 すべての頂点に重みを持つ根付きツリーが与えられます。 ツリー構造は親配列によって記述されるため、ルートを除くすべてのノードには厳密に 1 つの親があり、グラフ全体が接続され、非循環になります。 

ハリネズミと呼ばれる有効な構造は、中心頂点を選択することによって定義されます。$v$次に、次から始まる少なくとも 2 つの単純なパスを選択します。$v$、それぞれが異なる隣接を通過します$v$、これらすべてのパスのエッジの長さがまったく同じである必要があります。 長さはゼロにすることができます。これは、移動せずに中心に留まることに相当します。 ハリネズミはこれらのパス上のすべての頂点の結合であり、その重みは含まれるすべての頂点の重みの合計であり、中心は 1 回カウントされます。 

タスクは、中心のすべての選択肢と等しい長さの枝のすべての有効な集合に対して、そのような構造の可能な最大の重みを見つけることです。 

制約は次のとおりです$n = 5 \cdot 10^5$、次の二次関数は即座に除外されます。$n$。 平$O(n \log^2 n)$ソリューションは慎重に扱う必要があり、単純な方法でノードごと、深さごとに繰り返し再計算するものは遅すぎます。 

いくつかの特殊なケースについては、覚えておく価値があります。 すべての重みが負の場合、長さ 0 の解釈が許可されていれば、最良のハリネズミは単一の頂点に崩壊する可能性があります。これは、依然として少なくとも 2 つのパスを選択する必要がありますが、それらは両方とも自明である可能性があるためです。 星型ツリーでは、最適解はルートの中心にあり、重みに応じて長さが 1 または 0 になることがよくあります。 チェーン上では構造が縮退し、2 つの等しい分岐を取得する唯一の有効な方法は通常、長さ 0 です。 

素朴なアプローチではあらゆるセンターを試すことになるだろう$v$、あらゆる長さ$L$、および異なる近隣からのブランチのペアごとに、最適なパスを個別に計算します。 これは、固定値に対する最適な下向きパスを計算することさえできないため、すぐに実行不可能になります。$v$全体的に$L$すでにノードごとに直線的な時間がかかります。 

## アプローチ

 中心的な難しさは固定センターの場合です$v$あらゆる深さについて知る必要があります$L$、から始まる最適なパス$v$隣接する各サブツリーに入ります。 それがわかったら、それに対する答えは$v$は、それぞれについて、$L$、隣接する値の中で最も大きい 2 つの値の合計に加え、$a[v]$。 

ブルート フォース アプローチでは、すべてのノードに対して計算が行われます。$v$、サブツリー内のすべての深さにわたる DP、ここで$dp[v][L]$最適なパスの長さの合計です$L$から始まる$v$。 この DP は当然、子に対するマージとして定義されます。つまり、各子の配列を 1 つずつシフトし、最大値を取得します。 問題は、これらの配列のサイズを変更できることです。$O(n)$チェーン状ツリー内のノードごとに処理されるため、合計作業量は次のようになります。$O(n^2)$。 

重要な観察は、結合後に子ごとに完全に分離する必要がないということです。 各ノードについて$v$、深さごとに$L$、すべての子の中で最も優れた 2 つの貢献のみを考慮します。 つまり、すべての子を個別に追跡するのではなく、ノードと深さごとに、異なるサブツリーからの上位 2 つの値のみを維持します。 

これにより、ツリー上で古典的な小規模から大規模のマージ DP が実現されます。この場合、各ノードは深さを最適なパス合計と 2 番目に最適なパス合計にマッピングする構造を保存します。 ノードを処理するとき、子を 1 つずつマージし、深さごとに 2 つの最良の値のみを維持しながら、常に子のシフトされた DP を現在の構造に挿入します。 

各サブツリー構造がより大きな構造にマージされるのは、償却された意味で対数回だけであるため、このアプローチは十分な高速性を維持します。$n = 5 \cdot 10^5$。

 ## アルゴリズムのチュートリアル

 ツリーをノード 1 にルートし (または指定された親関係を使用し)、ノードを事後順序で処理します。 

1. ノードごとに$v$、辞書のような構造を維持します。$dp[v]$それぞれの深さはどこですか$d$で始まるパスの最良の 2 つの値を保存します。$v$、そのサブツリーに下向きに進みます。$d$エッジ。 各値は、そのようなパスに沿ったノードの重みの合計を表します。 この構造は、すべての子コントリビューションを分離せずに圧縮します。 
2. 各ノードの初期化$v$だけで$dp[v][0] = (a[v], -\infty)$これは、長さ 0 のパスがノード自体のみで構成されることを意味します。 2 番目の値は、最初に自明なパスが 1 つだけ存在することを示すプレースホルダーです。 
3. の子を処理します。$v$一つ一つ。 子供のために$c$、最初にすべての深さをシフトします$dp[c]$からパスを延長してから 1 つずつ$c$上向きに$v$長さを 1 つ増やして追加します$a[v]$そのようなすべての道に。 これにより、次から始まるパスの候補寄与が生成されます。$v$そしてサブツリーに入ります$c$。 
4. これらのシフトされた値をマージします。$dp[v]$。 あらゆる深さに対して$d$、現在、さまざまな子供からの複数の候補者がいる可能性があります。 最終的なハリネズミでは 2 つのブランチのみが必要となるため、各深度で最良の 2 つの値のみを保持します。 
5. すべての子がマージされた後、以下を中心とする最良のハリネズミを計算します。$v$。 深さごとに$d$に格納されている上位 2 つの値を調べます。$dp[v][d]$、その合計で答えを更新します。 これは、同じ長さの 2 つの異なる枝を選択することに相当します。$d$。 
6. グローバルな答えは、すべてのノードおよびすべての深さにわたる最大値です。 

微妙な部分は、マージでは深さごとの上位 2 つの値のレベルで子間の分離を維持する必要があることです。 これにより、後で 2 つのブランチを選択するときに、それらが本当に異なるサブツリーからのものであることが保証されます。 

### なぜ効果があるのか

 任意の固定中心の場合$v$そして深さ$d$、有効なハリネズミは、異なる隣接パスから始まる 2 つの互いに素なパスを選択します。$v$。 このような各パスは、完全に 1 つの子サブツリー内にあります。 したがって、ハリネズミの貢献は次のとおりです。$(v, d)$は、その深さにおける 2 つの最大の独立した子の寄与の正確な合計です。 すべての子をマージした後、深さごとに上位 2 つの値を維持するため、最適な選択を再構築するために必要な情報が正確に保存されます。 他の情報は実現可能性や最適性に影響を与えません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    p = list(map(int, input().split()))
    a = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for i, par in enumerate(p, start=1):
        g[par - 1].append(i)

    sys.setrecursionlimit(10**7)
    ans = [-10**30]

    def dfs(u):
        dp = {0: [a[u], -10**30]}
        for v in g[u]:
            child = dfs(v)
            for d, (b1, b2) in child.items():
                nd = d + 1
                val = b1 + a[u]
                if nd not in dp:
                    dp[nd] = [val, -10**30]
                else:
                    if val > dp[nd][0]:
                        dp[nd][1] = dp[nd][0]
                        dp[nd][0] = val
                    elif val > dp[nd][1]:
                        dp[nd][1] = val

        for d, (b1, b2) in dp.items():
            if b2 != -10**30:
                ans[0] = max(ans[0], b1 + b2)
        return dp

    dfs(0)
    return str(ans[0])

 ## 特殊なケース

 中心に多くの子がある星型ツリーでは、アルゴリズムは複数の深さ 0 と深さ 1 の寄与を保存します。 マージ手順により、上位 2 つの子のみが重要になり、2 つの最良の値のいずれかを改善しない限り、余分な分岐はすべて無視されます。 

長いチェーンでは、エンドポイントを除くすべてのノードには下向きの継続が 1 つだけあるため、深さは 2 つの独立した寄与を蓄積することはありません。 したがって、dp 構造は有効なペアをトリガーすることはなく、答えは最適な単一ノード値になります。 

正と負の重みが混在するツリーでは、負の中間ノードが含まれている場合でも、深いパスの方が浅いパスよりもパフォーマンスが優れている可能性があります。 DP は、各ノードでのローカルな選択ではなく完全なパスの合計を常に考慮するため、これらを正しく実行します。
