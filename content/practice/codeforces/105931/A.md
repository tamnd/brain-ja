 ## 解決策
 ## 問題の理解

 大学は以下まで入学しています`n`生徒総数。 すべての生徒は 2 つのカテゴリーのいずれかに該当する必要があります。 

学生が授業料を支払う場合、一定額を寄付します`a`大学へ。 

学生が奨学金を受け取った場合、その資金はスポンサーから提供されます。 スポンサーがサポートするのはせいぜい`b`学生数が増加し、金額は直線的に減少します。最初の奨学金は`b`、2番目は与えます`b - 1`、k番目の奨学金が与えられるまで続きます。`b - k + 1`。 

学生の数は大学が決定します`k`合計のうち`n`奨学金受給者となりますが、以下の制限があります。`k`超えることはできません`b`。 残り全部`n - k`学生は学生にお金を払っています。 目標は選択することです`k`授業料とスポンサーシップから得られる合計金額が最大化されるようにします。 

出力は、この最大達成可能な総収益です。 

制約により許可されるのは、`n`、`a`、 そして`b`まで`10^9`。 これにより、考えられるすべての値を試行するアプローチは即座に除外されます。`k`そして結果を線形時間で再計算します。 すべてを繰り返しても`k`不可能だから`k`それ自体は最大です`10^9`。 

直接シミュレーションにも問題があります。なぜなら、奨学金の部分には減少する等差数列の合計が含まれており、この数列は二次関数的に増加するからです。`k`。 学生ごとの単純なシミュレーションでは遅すぎます。 

常にできるだけ多くの奨学金を受け取る、または常に有給の学生を優先するなど、欲深い推論を試みると、微妙な失敗例が現れます。 たとえば、次の場合`a`少額ですが、初期の価値観にとっては奨学金のほうがまだ良いかもしれません。`k`しかし、後になって限界奨学金がそれを下回るとさらに悪化します`a`。 これにより、単調な動作ではなく全体の利益にピークが生じるため、局所的な決定は失敗します。 

## アプローチ

 強引な手法では、可能な限りの数の奨学生を試すことになります。`k`から`0`に`min(n, b)`。 それぞれの選択肢について、収益を次のように計算します。`(n - k) * a`等差数列の和を加算したもの`b + (b - 1) + ... + (b - k + 1)`。 

O(k) の各合計を計算すると、最悪の場合、解は O(n^2) になりますが、これは大きすぎます。 等差級数の公式を使用して O(1) の各候補を計算したとしても、最大でテストする必要があります。`10^9`の値`k`、それは不可能です。 

重要な観察は、目的関数が任意ではないということです。 奨学金の額は二次関数です`k`、授業料部分は直線的です`k`。 合計関数は、次の凹二次関数になります。`k`。 つまり、ピークが 1 つだけあり、それを超えると値は減少するだけです。 

この構造により、範囲全体を検索する必要がなくなります。 すべての値を列挙する代わりに、ピークの位置を分析的に計算し、一定数の近くの候補と境界値のみをチェックします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(min(n, b)) またはそれ以上 | お(1) | 遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 総利益を次の関数として表現します。`k`、 どこ`k`奨学生数です。 残り`n - k`学生は授業料を支払い、寄付をする`(n - k) * a`。 奨学金寄付金は次の等差数列になります。`k`から始まる用語`b`。 
2. 奨学金の合計額を閉じた形式の式を使用して書き換えます。 合計は次のようになります`k * (2b - k + 1) / 2`。 これにより、反復の必要がなくなります。 
3. 両方の部分を 1 つの式に結合します。`k`。 単純化すると、問題は次の二次関数を最大化することに帰着します。`k`整数の範囲を超える`[0, min(n, b)]`。 
4. の係数が次のとおりであるため、関数が凹であることを確認します。`k^2`はマイナスです。 これにより、単一の最大点が保証されるため、徹底的に検索するのではなく、ピークを特定するだけで済みます。 
5. 微分アイデアを使用して実数値の最適点を計算します。`k* = (2b - 2a + 1) / 2`。 これは、奨学金による限界利得が固定授業料利得と釣り合うところを表しています。 
6.以来`k`整数でなければなりません。最も近い整数を考慮してください`k*`。 境界値も含める`0`そして`min(n, b)`最適値が実行可能な区間の外にあるか、制約によって切り取られる可能性があるためです。 
7. 各候補の利益を評価する`k`そして最大値を取る。 

### なぜ効果があるのか

 利益関数以上`k`は凹状の二次関数であり、単一のピークの両側で減少することを意味します。 整数の最大値は、実際の最適値の下限または上限、あるいは有効区間の境界になければなりません。 これらの点のみをチェックすることで、あらゆる可能性を列挙することなく、世界最大値を確実に捕捉します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def calc(n, a, b, k):
    # tuition part + scholarship part
    return (n - k) * a + k * (2 * b - k + 1) // 2

def solve():
    n = int(input())
    a = int(input())
    b = int(input())

    max_k = min(n, b)

    # continuous optimum
    k_star = (2 * b - 2 * a + 1) / 2

    candidates = set()

    for x in [0, max_k]:
        candidates.add(x)

    for x in [int(k_star), int(k_star) + 1]:
        candidates.add(x)

    best = 0
    for k in candidates:
        if 0 <= k <= max_k:
            best = max(best, calc(n, a, b, k))

    print(best)

if __name__ == "__main__":
    solve()
```機能`calc`シミュレーションを行わずに利益計算式を直接評価します。 生徒ごとにプロセスを拡大するのは不可能であるため、これは重要です。 

候補セットには、解析最適値の周囲の境界と近傍の両方が含まれます。 鋳造`k_star`整数に変換し、次の値もチェックすることで、フロアリング効果によって離散最大値を見逃さないようにします。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です`a`金額が非常に大きいため、奨学金を利用すると総利益がすぐに減少します。 例えば、`n = 5`、`a = 10`、`b = 3`。 での機能`k = 1`に比べてすでに減少しています`k = 0`。 アルゴリズムはこれを引き続き正しく処理します。`k = 0`が候補に明示的に含まれており、最大値が見逃されないことが保証されます。 

別のエッジケースが発生するのは次の場合です。`b`よりも小さいです`n`。 例えば、`n = 10`、`b = 3`、`a = 1`。 学生数が多い場合でも、奨学金は 3 名を超えることはできません。アルゴリズムは検索範囲を正しくクランプします。`min(n, b)`したがって、無効な値は決して評価されません。`k`。 

最後のエッジ ケースは、二次関数のピークが実行可能な区間の外側にある場合です。 たとえば、計算された場合、`k*`が負の場合など`a`に比べて非常に大きいです`b`、有効な最大値は次の時点で発生します。`k = 0`。 アルゴリズムは常に境界値をチェックするため、分析ピークに依存せずにこの状況を正しく処理します。
