 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられた候補のセットが与えられます。 各候補者は、AI の忠実な支持者から始まります。 さらに、c 人の未決定の有権者のプールがあり、何も変わらなければ、常に参加中の候補者のうち最小番号の候補者に投票します。 

ねじれは、候補者を失格にすることが許可されていることです。 候補者 i が失格になった場合、代わりにその AI 支持者全員が未定の有権者になります。 改宗した有権者は、選挙戦に残る最小番号の候補者にも投票することになる。 したがって、失格となった候補者は競合他社を排除すると同時に、以前の候補者の投票プールを増やすことができます。 

すべての候補者 i について、候補者 i がこれらの投票ルールに基づいて最終的に選挙に勝つために失格にする必要がある候補者の最小数を計算する必要があります。 

n が 200000 まで、ai が 10^9 までという制約は、候補者のすべてのサブセットを試したり、失格の選択肢を明示的にシミュレートしたりする解決策は不可能であることを意味します。 候補ごとの二次関数でさえ遅すぎるため、クエリごとに線形または対数に近い値、理想的には O(n log n) または O(n) が必要です。 

微妙なエッジ ケースは、まだ決定していない有権者が常に最小のアクティブなインデックスに移動することです。 これは、単一の低指数候補者を失格にすると、大量の票が完全に振り向けられ、局地的ではない方法で勝者が変わる可能性があることを意味します。 もう 1 つのエッジ ケースは、候補者 1 がすべての未決定の有権者を自動的に受け取るため、c だけですでに候補者 1 が勝つのに十分な場合です。 

たとえば、n = 3、c = 10、a = [0, 0, 0] の場合、候補者 1 は失格なしですでに勝利しています。 より強力な競合他社を排除することのみに焦点を当てた素朴なアイデアは、ここではまだ正しいでしょうが、未決定の投票を上方にシフトする効果を無視した解決策は、より構造化された入力では失敗します。 

## アプローチ

 強引な解釈は簡単です。固定された候補者 i の場合、候補者のすべてのサブセットを失格にして、その結果の選挙をシミュレートして、i が勝つかどうかを確認できます。 これには、各サブセットの選択後に投票合計を再計算することが含まれます。 サブセットの数は 2^n であり、小さなサイズ k のサブセットに制限しても O(n^k) の動作になりますが、n が 200000 までの場合はまったく実現不可能です。 

より構造化されたブルートフォースは、k を修正し、i を勝利させる一連の k 個の失格が存在するかどうかを尋ねることです。 その場合でも、組み合わせをチェックし、投票の再配分をシミュレートする必要がありますが、これは依然として組み合わせ的なものです。 

重要な観察は、候補者の失格には 2 つの効果しかないということです。1 つは競合他社を排除すること、もう 1 つは未決定のプール c を ai だけ増やすことです。 重要なのは、未決定の有権者は常に最小の残りのインデックスに流れるため、候補者 i の場合、非常に具体的な方法で重要なのは、インデックスが i よりも小さい候補だけです。つまり、候補者によって、私が間接的に獲得できる追加の未決定票の数が決まります。 

任意のサブセットの観点から考える代わりに、左から右へ貪欲に推論することができます。 候補者 i が勝つためには、i より大きいインデックスを持つすべての候補者は、i の最終投票総数を超える可能性がある場合に削除する必要がある可能性のある潜在的な競合者を除いて無関係です。 一方、i よりも小さいインデックスを持つ候補者は危険です。なぜなら、候補者が残った場合、未決定の有権者を獲得し、i が実質的に得るものを減らす可能性があるからです。 

中心的な削​​減は、問題を投票しきい値のバランスをとる行為として再解釈することです。候補者 i の最終投票数は、c に、インデックス < i を持つ失格となったすべての候補者からの ai の合計に依存します。 すべての候補者 j > i は固定 aj を持つ競合者であり続けるため、i が確実に勝つためには、そのような aj が i の最終累積投票総数を超えないようにする必要があります。

これは貪欲な選択の問題につながります。つまり、i の票を増やし、強力な競合他社を抑制するために、候補者の失格を最小限に抑えたいと考えています。 i に関連して候補をソートし、最適な除去を選択することが中心的なアイデアとなり、候補の強みの構造を維持し、i を最も助ける最小コストの除去を選択することで解決できます。

 ## アルゴリズムのチュートリアル

 各候補 i を個別に処理しますが、プレフィックスとサフィックスの寄与について推論することで、すべてを最初から再計算することを避けます。 

1. 候補 i を勝者候補として確定します。 他のすべての候補を 2 つのグループに分割します。インデックスが i より小さいグループとインデックスが i より大きいグループです。 
2. 失格者がいない場合の候補者 i のベースライン投票を計算します。 これは c に ai を加えたもので、現在未定の有権者が候補 1 に行くという効果を加えたものであるため、i > 1 の場合、候補 i は最初は c を受け取りません。 これにより、失格がなければ候補者 1 だけが未決定の有権者から恩恵を受けることができるため、より高いインデックスの候補者が c にアクセスするには構造的な変更が必要であることがわかります。 
3. i を競争力のあるものにするために、i が失格候補のプレフィックスの中で最も小さい残りのインデックスになるように、i より小さいインデックスを持ついくつかの候補を削除する必要があることに注目してください。 これが未決票の受け取りを開始できる唯一の方法です。 
4. 失格の数が k である場合、最適な戦略は常に、その除去が i に最大の利益をもたらす候補者を選択することです。 候補 j < i を削除すると、未決定のプールに利益 ai が与えられ、j が強い場合は潜在的な競合他社の影響も除去されます。 
5. k を最小化するために、すべての候補者 j ≠ i を、i の勝利に貢献する「有効性」に基づいて並べ替えます。 強力な競合他社であり、大規模な AI を備えている候補は、削除する価値が最も高くなります。 
6. 次に、「i の得票が残りすべての候補の票より厳密に大きい、またはタイブレーク支持 i」という条件が満たされるまで、利益の降順で候補者を貪欲に削除します。 
7. この貪欲なプロセスで使用される除去の数が、候補 i の答えになります。 

重要な不変条件は、貪欲な除去の各ステップで、除去あたりの i の勝ちマージンを最大化するために、残りの候補の可能な限り最良の構成を維持することです。 各除去は i の投票総数と競合相手のセットに単調な影響を与えるため、最も影響力の高い除去を最初に選択すると、k 個の除去で勝てる場合、貪欲なプロセスにより k ステップでそれが達成されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, c = map(int, input().split())
    a = list(map(int, input().split()))

    # We compute answers independently; this is the clean conceptual solution.
    # (Optimized versions exist, but this keeps logic faithful to the reasoning.)

    res = []

    for i in range(n):
        # candidate i
        need = 0

        # current vote for i if nobody removed:
        # only candidate 1 gets c, so i gets nothing unless i == 1
        votes_i = a[i]

        # simulate: we will greedily "activate" undecided votes by removing candidates < i
        gain_pool = c
        used = 0

        # collect all candidates except i
        others = []
        for j in range(n):
            if j == i:
                continue
            others.append((a[j], j))

        # sort by descending contribution heuristic:
        # removing someone gives us their ai into pool
        others.sort(reverse=True)

        current_i = a[i] + (c if i == 0 else 0)
        current_best = max(a[j] for j in range(n) if j != i)

        for val, j in others:
            if current_i > current_best or (current_i == current_best and i < j):
                break
            used += 1
            current_i += val
            current_best = max(current_best, 0)
            current_best = max([a[k] for k in range(n) if k != i and k != j] + [0])

        res.append(str(used))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```コードは貪欲な解釈に従います。各候補について、ai の降順で繰り返し候補を削除し、その支持者を候補 i に対する未決定のプール効果に蓄積します。 停止条件は、インデックスによるタイブレークなどのルールに従って i が厳密に優勢になるかどうかをチェックします。 

主な微妙な点は、未決定の有権者が常に最小のアクティブなインデックスに流れるという事実を正しくモデル化していることです。 これが、候補 1 が初期化時に異なる動作をする理由です。 実装では、候補 1 に最初の c 貢献を与えることでこれを扱いますが、他の候補は削除によってその貢献へのアクセスを獲得する必要があります。 

## 実用的な例

 ### 例 1

 入力:```
3 1
2 0 3
```各候補者を評価します。 

候補 1 の場合、すでに c = 1 の未決定票を受け取っているため、その合計は 3 ですが、他の候補は 0 と 3 です。タイブレークではインデックスが小さい方が有利であるため、候補 1 はすでに少なくとも必要なだけ強力であり、削除は必要ありません。 

候補者 2 の場合、値 3 で候補者 3 を上回る必要があります。候補者 3 を削除すると、その支持者が未定票に変換され、間接的に候補者 2 に十分な後押しが与えられます。 

候補者 3 については、すでに最大の直接の支持を得ていますが、当初は未定の票の恩恵を受けられないため、投票力学を変えるために以前の候補者を両方削除する必要があります。 

| 私 | 初期強度 | 主要な競争相手 | 削除 | 最終状態 |
 | --- | --- | --- | --- | --- |
 | 1 | 2 + 1 | 3 | 0 | 勝ちます |
 | 2 | 0 | 3 | 1 | シフト後の勝利 |
 | 3 | 3 | 2 | 2 | 孤立した勝利 |

 このトレースは、失格によって候補者へのアクセスが移らない限り、指数の低い候補者が自然に未決定の有権者を支配していることを示しています。 

### 例 2

 入力:```
2 3
0 10
```候補者 1 の場合、未決定の有権者はすべて候補者 1 に投票するため、すぐに 3 票になります。 候補 2 は 10 を持っていますが、候補 1 が削除されない限り c をまったく受け取りません。 候補者 1 を削除すると、すべての未決票が候補者 2 に移されるため、失格は 1 回で十分です。 

| 私 | 最初の i 票 | 競合他社 | 削除 | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | 3 | 10 | 0 | 負ける |
 | 2 | 10 | 3 | 1 | 勝ちます |

 これは重要なメカニズムを示しています。最小のインデックス候補を削除すると、未決定のプール全体が再割り当てされます。

 ## 特殊なケース

 重要なエッジケースは、c だけで既に勝者が決定されている場合です。 n = 5、c = 100、およびすべての ai = 0 のような入力の場合、候補 1 は失格なしで常に勝ちます。 候補 1 は c へのフル アクセスで開始され、その位置を改善するために削除する必要がないため、アルゴリズムはこれを反映しています。 

もう 1 つのエッジ ケースは、単一の非常に大きな AI が高いインデックスに存在する場合です。 たとえば、a[n] が非常に大きい場合、その前の候補者は失格の連鎖を引き起こして、未決定の有権者をリダイレクトし、その有力な競合他社を抑制する必要があります。 貪欲な除去オーダーは、最初に大きな AI 除去を優先することでこれに対処し、最も強力なブロッカーが早期に除去されるようにします。 

最後の微妙なケースは、タイブレークによって結果が決まる場合です。 候補者 i がより低い指数の候補者と得票数が同点の場合、i は負けます。 アルゴリズムは、停止条件をチェックするときに、単なる平等ではなく厳密な不平等を保証する必要があります。
