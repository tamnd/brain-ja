 ## アルゴリズムのチュートリアル

 1. まず、可能な最大変位を計算します。 これは順列を逆にすることで実現され、総コストは次のようになります。$\sum_{i=1}^{n} |(n-i+1) - i|$。 もし$k$この値より大きい場合は構築できません。 このチェックにより、不可能なターゲットに労力を費やすことがなくなります。 
2. もし$k = 0$の場合、すべての要素がそのインデックスに一致し、ゼロに寄与するため、恒等順列はすでに条件を満たしています。 
3. 順列を恒等配列として初期化します。$[1, 2, \dots, n]$。 分割して修正していきます。 
4. 左端のインデックスから繰り返します$i = 1$に$n$、各ポジションで、あるポジションとのスワップを適用するかどうかを決定します。$j > i$。 の選択$j$これを超過することなく引き続き使用できる残りの最大の貢献によって推進されます$k$。 
5. ポジションについて$i$、可能な限り遠いパートナーを使用するようにしてください$j = n - (i - 1)$、端から内側に向​​かって対称的なスワップを形成します。 間の交換$i$そして$j$貢献する$2 \cdot (j - i)$総変位に。 
6. この拠出額が残りの拠出額以下の場合$k$、スワップを実行し、この値をから減算します。$k$。 それ以外の場合は、この位置をスキップして、交換せずに先に進みます。 
7. すべてのポジションが処理されるか、残りのポジションが処理されるまで続行します。$k$ゼロになります。 もし最後に$k$はゼロではないため、構築は失敗しました。 

### なぜ効果があるのか

 このアルゴリズムが機能するのは、実行するすべてのスワップが、総変位への寄与が他のスワップから独立している、互いに素なセグメントに対応しているためです。 スワップを選択するたびに、連続した範囲がさらなる検討から削除され、重複が防止されます。 最大の有効なスワップを貪欲に選択することで、後で必要になる可能性のある大きな貢献を無駄にしないことが保証されます。 すべての寄与は均等であり、対称距離を中心に構造化されているため、達成可能な合計は、これらの互いに素なセグメント寄与の合計として表現できる必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    # maximum possible displacement
    max_k = 0
    for i in range(1, n + 1):
        max_k += abs(n - i + 1 - i)

    if k > max_k:
        print("No")
        return

    if k == 0:
        print("Yes")
        print(*range(1, n + 1))
        return

    p = list(range(1, n + 1))

    l, r = 0, n - 1

    while l < r:
        cost = 2 * (r - l)
        if cost <= k:
            p[l], p[r] = p[r], p[l]
            k -= cost
        l += 1
        r -= 1

    if k != 0:
        print("No")
    else:
        print("Yes")
        print(*p)

if __name__ == "__main__":
    solve()
```解決策は、逆順列に対応する、達成可能な変位の上限を計算することから始まります。 これにより、不可能な目標の建設を決して試みることはありません。 

構築フェーズでは、内側に移動する 2 つのポインターを使用します。 各対称スワップは、そのスワップの寄与をすべて使用するかスキップするかの 1 つの決定として評価されます。 の引き算$2 \cdot (r - l)$対称位置の交換によって生じる絶対差の正確な変化を反映します。 

正確かどうかは、各交換後に残りの構造が依然として対称的であり、以前の選択から独立しているという事実にかかっています。

 ## 特殊なケース

 のために$n = 1$の場合、アルゴリズムは最大変位を即座にゼロとして計算します。 もし$k = 0$、それは出力します$[1]$。 もし$k > 0$、拒否します。 ループには決して入らないため、無効なポインター ロジックが回避されます。 

最大限に$k$、スワップ ループは常にすべての対称スワップを受け入れます。 順列は完全に逆転し、累積コストは事前に計算された限界と正確に一致し、貪欲型が利用可能なすべての寄与を受け入れることが確認されます。 

小型用$k$これが最小のスワップ寄与よりも小さい場合、アルゴリズムはすべてのスワップをスキップします。 結果として生じる順列は同一性のままであり、$k$これ以上減らすことはできません。そうでない限り、不可能であると正しく結論付けます。$k = 0$。
