 ## 解決策
 ## 問題の理解

 これは、コイン両替問題を装った対話型の検索問題です。 

(1 \le X \le 10^6) を持つ未知の正の整数 (X) があります。 (n) 個のスポイトがあり、(i) 個のスポイトを使用すると、(a_i) 単位の液体が追加されます。 クエリでは非負の整数 (x_i) が選択されるため、テストされる数量は次のようになります。 

[
 q=\sum_{i=1}^{n} a_i x_i。 
]

 実験後、裁判官は、(q) が (X) より小さいか、(X) と等しいか、または (X) より大きいかを教えてくれます。 色は (q<X)、(q=X)、(q>X) に対応します。 

課題は、最大 30 回の実験内で (X) を決定することです。 観測値が (X) を別の可能な整数と区別できない場合は、(-1) を出力する必要があります。 

入力は (n) とそれに続く容量 (a_1,\ldots,a_n) で構成されます。 (X) は対話型ジャッジによって保持されるため、(X) を含む通常のバッチ入力はありません。 クエリのたびに、プログラムは結果の色を読み取ります。 

上限 (10^6) が中心的な計算上の制約です。 これは、(0) から (10^6) までのすべての量にわたる擬似多項式動的プログラムには十分小さいですが、ドロッパー カウントの考えられるすべてのベクトルを列挙するには大きすぎます。 (n\le100) なので、(n\cdot10^6) 個の遷移を持つ直接動的プログラムには最大 (10^8) 回の反復があります。 これは、最適化された C++ では妥当ですが、Python では不必要に重いため、以下の実装では、到達可能性 DP を Python 整数にパックし、ビット操作として遷移を実行します。 

30 回の実験という制限も、(X) の (10^6) 個の可能な値と比較すると寛大です。 実際に生産できるすべての数量を並べ替えると、通常の二分探索では最大でも

 [
 \lceil \log_2(10^6)\rceil=20
 ]

 クエリ。 残りの困難は、最終間隔に可能な整数が 1 つだけ含まれる時期を判断することです。 

不注意な実装では見逃される可能性のあるエッジケースがいくつかあります。 容量が (4,8) の場合、非表示の値が (10) であるとします。 (4)、(8)、(12) をクエリして、緑、緑、赤を取得できます。 この時点で (X) は (9)、(10)、または (11) になる可能性があるため、正解は (-1) になります。 単に中間点だからという理由で (10) を返すのは間違いです。 

下限では、唯一の容量が (2) で、非表示の値が (1) であると仮定します。 最小の正のクエリは (2) で、その応答は赤色です。 (X) が正なので、(2) 以下の値は (1) のみとなり、答えは一意に決まります。 両方の隣接する到達可能な値が存在することを期待する汎用の二分探索実装では、このケースが誤って処理される可能性があります。 

上限でも同じ問題が発生します。 到達可能な値が (999999) の場合、応答が緑色の場合は (X>999999) です。 (X\le10^6) なので、可能性は (10^6) だけです。 繰り返しますが、(X) を超えると、他のエンドポイントとして使用できる到達可能な値はありません。 

最後に、到達可能な値の隣接するペアは、正確に 2 だけ異なる場合があります。 2 つの値が (19) と (21) で、応答が (19<X<21) を示している場合、(20) 自体はドロッパーで生成できませんが、(X=20) は一意に決定されます。 黄色の応答のみを受け入れるソリューションは、誤って (-1) を返します。 

## アプローチ

 最も直接的なアプローチは、生産できるすべての量を列挙することです。 私たちは定義します`dp[s]`これは、スポイト容量の非負の組み合わせによって正確に (s) が生成されることを意味します。 から始まる`dp[0] = true`、ドロッパー容量 (a_i) ごとに、到達可能性を (s) から (s+a_i) に伝播します。 各スポイトは任意に何度でも使用できるため、少量から大量までの量の反復が可能です。 

同じ DP は、到達可能な数量ごとに先行データを保存することもできます。 もし`dp[s]`(s-a_i) により true になるため、(s-a_i) を覚えています。 これらの先行者に従うと、各ドロッパーがクエリに使用される必要がある実際の回数がわかります。 

到達可能なすべての量を計算した後、対話部分は通常の二分探索になります。 クエリの色は、(X) がクエリされた到達可能な値の前、後、または前にあるかどうかを示します。 公開されたコンテスト ソリューションは、まさにこの到達可能な量の DP とそれに続く二分探索を使用します。 

単純な実装では、(O(n\cdot10^6)) 個の DP 遷移が実行されます。 (n=100) の場合、最悪のケースは (100,000,000) 回の遷移であり、その後に、到達可能なすべての量を収集するための別の (10^6) 操作が続きます。 これが、特に Python において、単純な実装が魅力的ではなくなる点です。 

重要な観察は、DP にはブール情報のみが含まれていることです。 1 つの到達可能な量を 1 つの Python オブジェクトで表す代わりに、すべての到達可能な量を 1 つの大きな整数のビットとして同時に表すことができます。 数量が到達可能な場合、ビットは 1 になります。 

1 つの容量 (a) の場合、次の操作が行われます。 

[
 S \左矢印 S\カップ(S+a)
 ]

 に相当する```
bits |= bits << a
```1 つのアプリケーションで、現在のドロッパーをさらに 1 回使用できます。 効率的に任意に多く使用できるようにするために、利用可能なコピー数を 2 倍にします。 シフト (a、2a、4a、\ldots) を処理した後、(0) から必要な制限までのすべてのコピー数が使用可能になります。 したがって、各容量には (O(\log 10^6)) 個の大きな整数シフトだけが必要です。 

さらに、ビットが初めて到達可能になるたびに、先行データを記録します。 新しい値 (s) が以前の値を (k a_i) だけシフトすることによって作成された場合、その先行値は (s-k a_i) であり、再構築によりコピー数は ((s-\text{先行者})/a_i) として回復できます。 

結果として得られる検索は、ソートされた到達可能な数量に対して実行されます。 ジャッジが黄色を返した場合、正確な値がわかります。 検索が黄色なしで終了した場合、残りの可能性は 2 つの連続する到達可能な量の間にギャップを形成し、ギャップが許容範囲の境界に達した場合には特別な処理が行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 率直なDP | (O(nM))、ここで (M=10^6) | (O(M)) | 最適化された C++ で受け入れられますが、Python には重すぎます |
 | パックされたビットセット DP | (O(n\log M\cdot M/W + M)) 単語演算 | (O(M)) | 受け入れられ、Python に適しています |

 ここで (W) は、big-integer 表現によって内部的に使用されるマシンワードのサイズです。 Python の任意精度の整数は、最適化されたネイティブ コードで大きなシフトとビット単位の演算を実行します。 

## アルゴリズムのチュートリアル

 1. ドロッパーの数とその容量を読み取ります。 (X) の可能な最大値を (M=10^6) とします。 

考慮に値する唯一の数量は、容量から実際に形成できる合計です。 到達不可能な量をクエリすることは、プロトコルの下では不可能です。 
2. ビットセットを作成する`bits`ビット 0 のみが設定されています。 ビット (s) は、数量 (s) が到達可能であることを意味します。 

すべてのドロッパーをゼロ回使用することが許可されているため、数量ゼロに到達できます。 
3. すべての容量 (a_i) を処理します。 シフト (a_i,2a_i,4a_i,\ldots) の場合、次を使用して新しく到達可能なビットを計算します。 

[
 \text{new}=(\text{ビット}\ll\text{シフト})\setminus\text{ビット}。 
]

 倍増ステップごとに、追加できる現在のドロッパーのコピーの数が拡張されます。 シフト (a_i,2a_i,\ldots,2^ka_i) の後、0 から (2^{k+1}-1) までの必要なカウントがすべて利用可能になります。 
4. 新たに到達可能な値ごとに、遷移を担当する先行者とドロッパーのインデックスを保存します。 

もし`shift = 8`新しい値 (25) は (17) から取得され、格納されている先行値は (17) です。 再構築中、その差 (25-17=8) から、対応する容量の 1 つのコピーがこの移行で使用されたことがわかります。 より大きなシフトは同様に機能しますが、その違いはおそらく複数のコピーに相当します。 
5. 到達可能な正の数量をすべてソートされた配列に抽出します。`values`。 

ビットセット自体はすでに値を番号順に格納していますが、二分探索にはランクによるランダム アクセスが必要なので、到達可能な正の量のセットを具体化します。 
6. 到達可能な量の配列を二分探索します。 中間の量 (q) については、合計が正確に (q) になるドロッパー ベクトルを再構築し、クエリを出力し、色を読み取ります。 

赤色の応答は (q>X) を意味するため、(q) 以降の到達可能な数量はすべて破棄できます。 緑色の応答は (q<X) を意味するため、(q) 以降の到達可能な数量はすべて破棄できます。 黄色は (X=q) をすぐに識別します。 
7. 黄色がまったく発生しない場合は、`hi`(X) 以下であることがわかっている最後の到達可能な量とし、`lo`(X) を超えることがわかっている最初の到達可能な量になります。 

両方が存在し、`values[lo] - values[hi] == 2`、ちょうど 1 つの整数がそれらの間にあります。 その整数自体は到達不可能ですが、その整数は (X) です。 
8. 最終間隔を下回る到達可能な数量がない場合、唯一考えられる一意に識別可能な下限ケースは次のとおりです。`values[0] == 2`。 したがって、その下の正の整数は必ず (1) になります。 

たとえば、到達可能な最小量が (5) の場合、応答 red は (X) が (1,2,3,4) に属することのみを示すため、答えは (-1) でなければなりません。 
9. 上部境界に対称ルールを適用します。 到達可能な最大数量が (999999) で、その応答が緑色の場合、(X=10^6) になります。 
10. 固有のケースがどれも当てはまらない場合は、(-1) を出力します。 最後にprintコマンド`2`続いて決まった答え。 

### なぜ効果があるのか

 対話型二分探索中の不変条件は、すべての応答と一致する (X) のすべての値が残りの到達可能な量の間にあることです。 黄色の応答は、正確に到達可能な 1 つの数量を示します。 黄色がない場合、(X) は厳密に 2 つの連続する到達可能な量の間にあるか、2 つの境界のいずれかで到達可能な範囲の外側にある必要があります。 

2 つの連続した到達可能な量が 2 だけ異なる場合、それらの間にちょうど 1 つの整数が存在できるため、その整数は一意に決定されます。 それらの差が少なくとも 3 である場合、少なくとも 2 つの異なる整数は、到達可能なすべてのクエリに対してまったく同じ応答を生成するため、ジャッジの情報はそれらを区別できず、(-1) が正しいことになります。 境界ケースは、(X) が正の区間 ([1,10^6]) に制限されるという事実から導き出されます。 

ビットセットの構成は正しいです。遷移ごとに、現在の容量の非負倍数がすでに到達可能な合計に加算され、倍加シーケンスにより最終的に必要なすべてのコピー数が許可されるからです。 したがって、アルゴリズムによって設定されたすべてのビットは有効な組み合わせに対応し、すべての有効な組み合わせが最終的に表現されます。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

LIMIT = 10**6
MASK = (1 << (LIMIT + 1)) - 1

def build_reachable(a):
    n = len(a)

    # bit s = 1 iff s is reachable.
    bits = 1

    # Encodes predecessor * n + coin_index.
    # -1 is used only for value 0.
    parent = array('i', [-1]) * (LIMIT + 1)

    for coin, value in enumerate(a):
        shift = value

        while shift <= LIMIT:
            shifted = (bits << shift) & MASK
            new_bits = shifted & ~bits

            # Store one witness for every newly reachable sum.
            while new_bits:
                low = new_bits & -new_bits
                s = low.bit_length() - 1
                prev = s - shift
                parent[s] = prev * n + coin
                new_bits ^= low

            bits |= shifted

            if bits == MASK:
                break

            shift <<= 1

    values = []
    b = bits & ~1

    while b:
        low = b & -b
        values.append(low.bit_length() - 1)
        b ^= low

    return values, parent

def get_counts(total, a, parent):
    n = len(a)
    counts = [0] * n
    cur = total

    while cur:
        encoded = parent[cur]
        coin = encoded % n
        prev = encoded // n

        counts[coin] += (cur - prev) // a[coin]
        cur = prev

    return counts

def ask(total, a, parent):
    counts = get_counts(total, a, parent)

    print(1, flush=True)
    print(*counts, flush=True)

    response = input().strip()

    if not response:
        sys.exit(0)

    return response[0]

def main():
    n = int(input())
    a = list(map(int, input().split()))

    values, parent = build_reachable(a)

    left = 0
    right = len(values) - 1
    answer = -1

    last_mid = -1
    last_response = ''

    while left <= right:
        mid = (left + right) // 2
        last_mid = mid

        response = ask(values[mid], a, parent)
        last_response = response

        if response == 'y':
            answer = values[mid]
            break

        if response == 'g':
            left = mid + 1
        else:
            right = mid - 1

    if answer == -1:
        # X is smaller than every reachable positive quantity.
        if right < 0:
            if values[0] == 2 and last_response == 'r':
                answer = 1

        # X is larger than every reachable quantity.
        elif left == len(values):
            if values[-1] == LIMIT - 1 and last_response == 'g':
                answer = LIMIT

        # X is strictly between two consecutive reachable quantities.
        else:
            low = values[right]
            high = values[left]

            if high - low == 2:
                answer = low + 1

    print(2, flush=True)
    print(answer, flush=True)

if __name__ == "__main__":
    main()
```実装の最初の部分では、到達可能な数量セットを構築します。`bits`はビット位置が数量となる Python 整数です。`bits << shift`追加を表します`shift`現在到達可能なすべての数量に対する単位。 

倍増ループは注目に値します。 (a) のシフトを処理した後、現在のビットセットには、現在のドロッパーの 0 つまたは 1 つの新しいコピーを使用した合計が含まれます。 (2a) だけシフトすると、0 ～ 3 個のコピーが含まれます。 次のシフトでは、0 から 7 までのコピーが与えられます。 (2^{20}>10^6) であるため、1 つの容量に対して最大 20 のシフトが必要です。 

の`parent`配列には、初めて到達可能になったビットのみが書き込まれます。 前回の合計とドロッパー インデックスの両方を 1 つの整数に保存します。 エンコーディングでは、`prev * n + coin`、再構成では、整数の除算と剰余を使用してそれを逆にします。 

1 回の再構成ステップで使用されるコピーの数は、必ずしも 1 つである必要はありません。 (8a_i) のシフトを使用して値に到達した場合、先行する値は (8a_i) だけ異なります。`(cur - prev) // a[coin]`8 つのコピーを正しく回復します。 

インタラクティブなクエリ自体は意図的に次のように分離されています。`ask`。 正確なスポイト数を再構築し、コマンドを出力します。`1`、ベクトルを出力し、すぐにフラッシュします。 インタラクティブな問題は出力がバッファリングされていると簡単に失敗するため、ジャッジの応答を待つ前に両方の行がフラッシュされます。 

二分検索ではインデックスが使用されます。`values`、数値的な量そのものではありません。 到達できない量はクエリできないため、これが必要です。 到達可能なすべての量は整数であるため、色の比較は依然として通常の順序付き比較です。 

最終的な境界チェックにより、配列外のインデックス付けが回避されます。 盲目的にアクセスする汎用実装`values[left]`そして`values[right]`二分探索後、(X) が到達可能な最小量より下または最大値より上にある場合、無効な位置を読み取る可能性があります。 

Python の整数には任意の精度があるため、ビットセットのシフトで整数オーバーフローの問題は発生しません。 明示的な`MASK`ビットセットを (10^6) までの量に制限し、整数が不必要に大きくなるのを防ぎます。 

## 実用的な例

 最初のサンプルは容量 (1、2、5、10、20、50) に対応します。 相互作用により (X=10) を識別できます。 到達可能な量には (8)、(10)、および (12) が含まれるため、考えられる検索パスは答えをまとめて、最終的には (10) 自体をクエリすることができます。 

| クエリ数量 | 応答 | 検索効果 |
 | --- | --- | --- |
 | 25 | 赤 | (X<25) |
 | 8 | 緑 | (X>8) |
 | 10 | 黄色 | (X=10) |

 ここで重要な特性は、クエリされたすべての量が実際に構築可能であるということです。 たとえば、(25=5+20)、(8=2+2+2+2)、(10=10) などです。 黄色の応答は検索を直ちに終了します。 

2 番目のサンプルでは、​​容量 (4) と (8) を使用します。 非表示の値が (10) であるとします。 到達可能な正の量は (4,8,12,16,\ldots) です。 

| クエリ数量 | 応答 | 検索効果 |
 | --- | --- | --- |
 | 8 | 緑 | (X>8) |
 | 12 | 赤 | (X<12) |
 | 10 | 利用不可 | クエリできません |

 最初の 2 つの観測の後、(9)、(10)、および (11) の両方が依然として可能です。 (8) と (12) の間の量をクエリする方法はないため、正解は (-1) です。 これはまさに、「整数に対する二分探索」と「到達可能な量に対する二分探索」を区別する状況です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n\log M\cdot M/W + M)) 単語演算 | 各容量は (O(\log M)) 個のパックされたビットセット シフトを使用し、監視抽出​​では到達可能な各値に 1 回ずつアクセスします。 
| スペース | (O(M)) | 親配列は可能な量ごとに 1 つの整数を格納しますが、ビットセットは (O(M)) ビットを使用します。 

ここでは (M=10^6) です。 対話フェーズでは、正の候補量が最大 (10^6) 個しかないため、最大 20 回の実験が使用されます。 計算作業は擬似多項式到達可能性の計算が大部分を占めますが、実際の相互作用の数は対数になります。 

パックされた実装は、高価なビットセットのシフトと論理演算が (10^8) Python レベルのループ反復としてではなく、最適化されたネイティブ コードで実行されるため、Python で特に役立ちます。 

## テストケース

 これは対話型の問題であるため、サンプルは通常の決定的な入力/出力のペアではなく、対話の記録です。 フォームの通常のヘルパー`run(input) == output`プログラムは裁判官がすべての質問に答えることを期待しているため、それらを忠実にテストすることはできません。 次のテスト ハーネスは、内部での判断をシミュレートし、同じ二分探索および再構成ロジックを実行します。 

サンプル シナリオでは、インタラクション トランスクリプトに表示される容量を使用します。 最初の容量は (1,2,5,10,20,50) で、非表示の値は (10) です。 2 番目の値は容量 (4,8) で、隠された値は (10) で、正解は (-1) です。 3 番目の値は容量 (2,3) と隠れた値 (1) を持ちますが、これも一意に決定できません。```python
from array import array

LIMIT = 10**6
MASK = (1 << (LIMIT + 1)) - 1

def build_reachable(a):
    n = len(a)
    bits = 1
    parent = array('i', [-1]) * (LIMIT + 1)

    for coin, value in enumerate(a):
        shift = value

        while shift <= LIMIT:
            shifted = (bits << shift) & MASK
            new_bits = shifted & ~bits

            while new_bits:
                low = new_bits & -new_bits
                s = low.bit_length() - 1
                prev = s - shift
                parent[s] = prev * n + coin
                new_bits ^= low

            bits |= shifted

            if bits == MASK:
                break

            shift <<= 1

    values = []
    b = bits & ~1

    while b:
        low = b & -b
        values.append(low.bit_length() - 1)
        b ^= low

    return values, parent

def get_counts(total, a, parent):
    n = len(a)
    counts = [0] * n
    cur = total

    while cur:
        encoded = parent[cur]
        coin = encoded % n
        prev = encoded // n
        counts[coin] += (cur - prev) // a[coin]
        cur = prev

    return counts

def solve_hidden(a, hidden):
    values, parent = build_reachable(a)

    left = 0
    right = len(values) - 1

    last_query = None
    last_response = None

    while left <= right:
        mid = (left + right) // 2
        query = values[mid]

        counts = get_counts(query, a, parent)
        assert sum(x * y for x, y in zip(a, counts)) == query
        assert all(x >= 0 for x in counts)
        assert query <= LIMIT

        last_query = query

        if query < hidden:
            response = 'g'
        elif query > hidden:
            response = 'r'
        else:
            response = 'y'

        last_response = response

        if response == 'y':
            return query
        elif response == 'g':
            left = mid + 1
        else:
            right = mid - 1

    if right < 0:
        if values[0] == 2 and last_response == 'r':
            return 1
        return -1

    if left == len(values):
        if values[-1] == LIMIT - 1 and last_response == 'g':
            return LIMIT
        return -1

    low = values[right]
    high = values[left]

    if high - low == 2:
        return low + 1

    return -1

# Sample 1: capacities 1, 2, 5, 10, 20, 50, hidden X = 10.
assert solve_hidden([1, 2, 5, 10, 20, 50], 10) == 10

# Sample 2: capacities 4, 8, hidden X = 10.
# The observations cannot distinguish 9, 10, and 11.
assert solve_hidden([4, 8], 10) == -1

# Sample 3: capacities 2, 3, hidden X = 1.
# Both 1 and other values below the first useful query cannot be separated.
assert solve_hidden([2, 3], 1) == -1

# Minimum-size case. Capacity 1 can produce every possible X.
assert solve_hidden([1], 1) == 1

# Boundary case. With capacity 2, every integer is either reachable
# or lies between two consecutive even reachable quantities.
assert solve_hidden([2], 1_000_000) == 1_000_000

# All-equal capacities. This is outside the statement's "different
# capacities" condition, but it checks that duplicate capacities do
# not break the implementation.
assert solve_hidden([7, 7], 14) == 14

# A gap larger than two leaves several possible hidden values.
assert solve_hidden([7, 7], 15) == -1

# Maximum-size n. Because capacity 1 is present, every X is reachable.
assert solve_hidden(list(range(1, 101)), 999_999) == 999_999

 ## 特殊なケース

 容量 (2) と非表示の値 (1) の単一ドロッパーを考えてみましょう。 到達可能な正の量は (2,4,6,\ldots) です。 可能な範囲を超える最初のクエリは (2) で、応答は赤で表示されます。 (1) を除いて (2) より小さい正の整数はないため、アルゴリズムは (1) を返します。 下限チェック`values[0] == 2`まさにこの状況にぴったりです。 

非表示の値 (3) を持つ同じドロッパーを考えてみましょう。 (2) をクエリすると緑が得られ、(4) をクエリすると赤が得られます。 2 つの連続した到達可能な量は (2) だけ異なるため、それらの間の唯一の整数は (3) です。 正確に 3 つのユニットを使用できる実験はないにもかかわらず、アルゴリズムは (3) を返します。 

ここで、隠れた値 (10) を持つ容量 (4) と (8) を考えてみましょう。 (X) 付近の到達可能な値は (8) と (12) です。 それらの差は (4) であるため、3 つの整数 (9、10、11) が可能です。 考えられるすべてのクエリは (4) の倍数であるため、一連の比較クエリではこれらを区別できません。 アルゴリズムは正しく (-1) を返します。 

上限については、容量では (999999) が許容されるが、それと (10^6) の間に値はなく、(999999) への応答が緑色であるとします。 (X\le10^6) なので、(X) は (10^6) でなければなりません。 上限チェックでは、(X) より上の存在しない到達可能な数量を必要とせずにこれを認識します。 

黄色の応答が発生した場合、ギャップ分析は必要ありません。 黄色の結果は、テストされた数量が (X) に等しいことを意味するため、アルゴリズムはすぐにその到達可能な数量を返します。 これは、先行表現が正確な合計を生成する必要がある理由でもあります。 クエリ ベクトルの合計が 1 単位でも離れていると、裁判官の応答が変わり、二分探索が無効になります。 

最後に、再構築プロセスでは、負のドロッパー カウントが必要になることはありません。 保存されているすべての先行データは現在到達可能な値より小さく、各遷移は 1 つの容量の正の倍数を追加することによって作成されます。 先行者に従うと、ゼロに達するまで現在の合計が厳密に減少するため、再構成は常に有効な非負ベクトルで終了します。
