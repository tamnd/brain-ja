 ## 解決策
 ## 問題の理解

 各コースは有向グラフの頂点です。 もし`a[i] = j`、その後はもちろん`i`コース前に完了する必要があります`j`。 付きのコース`a[i] = 0`この前提関係では、その後にコースがありません。 

重要な構造上の制限は、すべてのコースが他のコースの前提条件になり得るのは最大 1 つであることです。 グラフの用語では、すべての頂点の出次数は最大 1 つです。 卒業が可能であることが保証されているため、該当するグラフには有向サイクルが含まれていません。 したがって、グラフは、エッジが最終コースを向いている木の集合になります。 

学期に含めることができるのは最大でも`k`コース、および学期に配置されるすべてのコースは、その前提条件をすべて前の学期に完了している必要があります。 課題は、すべてを完了するために必要な学期数を最小限に抑えることです。`n`コース。 

の値`n`到達できる`10^4`、 その間`k`せいぜい`10`。 これにより、すべてのコースでサブセット動的プログラミングが即座に除外されます。`2^10000`状態は 1 秒で実行できるものをはるかに超えています。 の小さな値`k`は、可能な学期の選択を説明するのに役立ちますが、利用可能なコースが依然として膨大な数に存在する可能性があるため、強引な方法は実用的ではありません。 

単純なトポロジソートで誤った答えが得られる可能性のある特殊なケースがいくつかあります。 まず、利用可能な任意のコースを受講するだけでは最適ではありません。 考慮する```
5 2
2 3 0 0 0
```コース`1 -> 2 -> 3`チェーンを形成しながら、コース`4`そして`5`独立しています。 答えは、`3`: コースを受講する`1,4`、 それから`2,5`、 それから`3`。 不用意なアルゴリズムでは、`4,5`最初は4学期必要になります。 

第二に、現在利用可能なすべてのコースを受講するのに十分な容量があるからといって、新しくロックが解除されたコースをすぐに受講できるわけではありません。 のために```
4 2
3 3 4 0
```コース`1`そして`2`ロック解除コース`3`、コースのロックが解除されます`4`。 答えは、`3`、 ない`2`。 学期中に完了したコースは、次の学期まで前提条件を満たすことができません。 

最後に、後継者がいないコースは、最初から利用できるとは限りません。 のために```
3 3
0 1 2
```エッジは`3 -> 2 -> 1`。 もちろんですが`1`最終コースです。コースが終了するまで受講できません`3`そして`2`完了しました。 答えは、`3`、 それでも`k = 3`。 

## アプローチ

 自然なブルートフォースソリューションは、すでに完了したコースのセットを表し、最大ですべての合法的な選択を再帰的に試みます。`k`現在次の学期に受講可能なコース。 これは正しいです。考えられるすべての有効なスケジュールが検索ツリーのどこかに表示されるため、すべてのスケジュールの最小値を取ると最適なスケジュールが得られます。 

問題は州の数です。 サブセット DP にはすでに`2^n`完了したコースの可能なセット。 のために`n = 10000`、つまり`2^10000`州。 学期中に受講できるコースのグループも列挙すると、最初の州だけでも、

 [
 \sum_{j=1}^{10} {10000 \choose j}
 ]

 可能な選択肢、最大の項`C(10000,10)`約`2.76 * 10^33`。 ブルートフォース手法は単に少し遅すぎるだけでなく、その状態空間は基本的に指数関数的です。 

グラフの制限により、スケジュールを推論するためのより強力な方法が得られます。 各コースには最大でも 1 つの後継者が存在するため、どのコースからも最終コースに至る独自のパスが存在します。 コースのレベルは、そのコースから始まり、前提条件に従って最終コースに至るまでの最長パスの長さとして定義します。 最終コースにはレベルがあります`0`、その直接の前提条件にはレベルがあります`1`、 等々。 

現在 2 つのコースが利用可能であるとします。 レベルが大きい場合は、それに従う必要があるコースのチェーンがさらに長くなるため、そのレベルを完了することがより緊急になります。 あるレベルで一学期を過ごす`0`レベルを残したまま独立コース`5`もちろんそのままにしておくと、重要な連鎖全体が遅れる可能性があります。 

これにより、最高レベル優先の貪欲アルゴリズムが実現します。 各学期の初めに、現在利用可能なすべてのコースのうち、最大でも`k`最大レベルのコース。 学期全体が終了したら、それらのコースをグラフから削除し、前提条件をすべて失ったすべてのコースを追加します。 

これは、ツリー内での単位時間スケジューリングのための古典的な最高レベル優先アルゴリズムです。すべてのコースには最大でも 1 つの後続コースがあるため、まさにここで得られた構造となります。 このアルゴリズムは、この特別な優先順位構造の最小メイクスパン スケジュールを生成することが知られています。 

ブルート フォースは、可能なすべてのスケジュールを明示的に考慮するため機能しますが、スケジュールの数が指数関数的に増加すると失敗します。 前提条件のグラフがツリー内フォレストであるという観察により、すべてのコースにクリティカル パス レベルを割り当て、スケジュールの列挙を優先キューに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 少なくとも指数関数的`O(2^n)`状態 |`O(2^n)`| 遅すぎる |
 | 最適 |`O(n log n)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 後継作品を読む`a[i]`すべてのコースの前提条件の数を計算します。 もちろん`v`、これはコースの数です`u`満足のいく`a[u] = v`。 前提条件カウントがゼロのコースが最初から利用可能です。 
2. 各コースのレベルを計算します。 前提条件のないすべてのコースから開始します。これらのコースは前提条件ツリーの葉であるためです。 それぞれのコースレベルを与える`0`、次にそれらをトポロジカルな順序で処理します。 コースのとき`u`を指す`v`、 アップデート`v`と`level[u] + 1`。 以来`v`すべての前提条件が処理された後にのみ使用可能になります。そのような最大値は、からの最長パスの長さと正確に一致します。`v`最終コースへ。 
3. 元の前提条件カウントを復元します。 最初のトポロジカル パスはレベルの計算のみを目的としており、2 番目のパスは実際の学期のスケジュールを表します。 
4. 最初に利用可能なすべてのコースを、そのレベルを優先度として使用して、最大優先度のキューに入れます。 パイソンの`heapq`は最小ヒープなので格納します`-level`その代わり。 
5. 各学期の初めに、最大でも削除します`k`優先キューからコースを抽出し、別のバッチに入れます。 このバッチによってロックが解除されたコースは同じ学期中に受講できないため、分離は重要です。 
6. バッチを選択したら、そのすべてのコースを完了としてマークします。 完了したコースごとに`u`、そのユニークな後継者を見てください`v`。 減少`v`の残りの前提条件の数。 ゼロになったら挿入`v`そのレベルでプライオリティ キューに追加されます。 
7. 学期数を増やし、すべてのコースが完了するまで繰り返します。 反復回数は最小学期数です。 

### なぜ効果があるのか

 重要な不変条件は、優先キューには常に、現在の学期の初めに合法的に利用可能なコースが、残りのクリティカル パスの長さの順に正確に含まれていることです。 

このグラフ構造では、より大きなレベルのコースが、まだ完了する必要がある長いチェーンの先頭にあります。 最高レベル優先のスケジューリングでは、延期が最終的な完了時間を延長する可能性が最も高いコースで各学期を埋めます。 すべてのコースには最大でも 1 つの後継者があり、すべてのコースにはちょうど 1 学期の作業がかかるため、優先順位の制約によってツリー内フォレストが形成され、これは最高レベルからのスケジューリングが最適な正確な設定になります。 したがって、可能な最小終了時間を増やすことなく、すべての貪欲な学期を選択することができ、すべてのコースが処理された後の結果の学期数は最適になります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve(stream):
    data = list(map(int, stream.read().split()))
    if not data:
        return ""

    it = iter(data)
    n = next(it)
    k = next(it)

    nxt = [next(it) - 1 for _ in range(n)]

    # indeg[v] = number of prerequisites of v.
    indeg = [0] * n
    for v in nxt:
        if v != -1:
            indeg[v] += 1

    # First topological pass: calculate the level of every course.
    # level[u] is the length of the longest path from u to a terminal course.
    rem = indeg[:]
    level = [0] * n
    q = []

    for u in range(n):
        if rem[u] == 0:
            q.append(u)

    head = 0
    while head < len(q):
        u = q[head]
        head += 1

        v = nxt[u]
        if v != -1:
            level[v] = max(level[v], level[u] + 1)
            rem[v] -= 1
            if rem[v] == 0:
                q.append(v)

    # Second pass: actually construct the optimal schedule.
    rem = indeg[:]

    pq = []
    for u in range(n):
        if rem[u] == 0:
            heapq.heappush(pq, (-level[u], u))

    completed = 0
    semesters = 0

    while completed < n:
        batch = []

        # Choose the courses for this semester before releasing
        # anything unlocked by them.
        take = min(k, len(pq))
        for _ in range(take):
            _, u = heapq.heappop(pq)
            batch.append(u)

        # Complete the whole batch simultaneously.
        for u in batch:
            completed += 1

        # Only now can successors become available.
        for u in batch:
            v = nxt[u]
            if v != -1:
                rem[v] -= 1
                if rem[v] == 0:
                    heapq.heappush(pq, (-level[v], v))

        semesters += 1

    return str(semesters)

def main():
    print(solve(sys.stdin))

if __name__ == "__main__":
    main()
```の最初の部分`solve`後続配列を​​読み取り、ビルドします`indeg`。 各コースには最大でも 1 つの後続者が存在するため、維持する隣接リストはありません。 単一の値`nxt[u]`ロックを解除できる唯一のコースを見つけるには十分です`u`完成しました。 

最初のトポロジ パスでは、というコピーが使用されます。`rem`。 すべての最初の葉には、`rem[u] == 0`, これでトラバースを開始できるようになります。 いつ`u`処理される、その後継者`v`の候補者レベルを取得します`level[u] + 1`。 コースには多くの前提条件があり、そのレベルはそのチェーンの中で最も長いものを考慮する必要があるため、最大値を取ることが必要です。 

2回目のパスのコピー`indeg`これも、最初のパスで前提条件のカウントが消費されたためです。 変更した配列を再利用すると、すべてのコースが利用可能になるのが早すぎます。 

プライオリティキューストア`(-level[u], u)`。 レベルを無効にすると、Python の最小ヒープが必要な最大ヒープに変わります。 コース番号は決定的なタイブレーカーとしてのみ使用され、正確さには影響しません。 

の`batch`配列は微妙ですが必要な詳細です。 まず、現在の学期のすべてのコースを削除してから、その後継コースを処理します。 各削除の直後に後継者がヒープに挿入され、ヒープが同じ反復で別のコースを提供できる場合、コースはその前提条件として同じ学期に受講できます。 別個のバッチにより、1 つずつずれたエラーが防止されます。 

Python では整数オーバーフローは発生せず、最大レベルは次のとおりです。`n - 1`。 ヒープには最大でも次のものが含まれます`n`したがって、メモリ使用量は線形のままです。

import io
import heapq

input = sys.stdin.readline

def solve(stream):
    data = list(map(int, stream.read().split()))
    if not data:
        return ""

    it = iter(data)
    n = next(it)
    k = next(it)
    nxt = [next(it) - 1 for _ in range(n)]

    indeg = [0] * n
    for v in nxt:
        if v != -1:
            indeg[v] += 1

    rem = indeg[:]
    level = [0] * n
    q = []

    for u in range(n):
        if rem[u] == 0:
            q.append(u)

    head = 0
    while head < len(q):
        u = q[head]
        head += 1

        v = nxt[u]
        if v != -1:
            level[v] = max(level[v], level[u] + 1)
            rem[v] -= 1
            if rem[v] == 0:
                q.append(v)

    rem = indeg[:]
    pq = []

    for u in range(n):
        if rem[u] == 0:
            heapq.heappush(pq, (-level[u], u))

    completed = 0
    semesters = 0

    while completed < n:
        batch = []

        for _ in range(min(k, len(pq))):
            _, u = heapq.heappop(pq)
            batch.append(u)

        completed += len(batch)

        for u in batch:
            v = nxt[u]
            if v != -1:
                rem[v] -= 1

        for u in batch:
            v = nxt[u]
            if v != -1 and rem[v] == 0:
                heapq.heappush(pq, (-level[v], v))

        semesters += 1

    return str(semesters)

def run(inp: str) -> str:
    return solve(io.StringIO(inp)).strip()

assert run("4 2\n3 3 4 0\n") == "3", "sample 1"
assert run("3 3\n0 1 2\n") == "3", "sample 2"

# Minimum-size input
assert run("1 1\n0\n") == "1", "single course"

# Maximum-size input, all values equal to zero
assert run("10000 10\n" + " ".join(["0"] * 10000) + "\n") == "1000", \
    "10000 independent courses with capacity 10"

# Capacity is large enough for all courses, but precedence still forces a chain
assert run("4 4\n2 3 4 0\n") == "4", \
    "large semester capacity cannot bypass prerequisites"

# Taking arbitrary available courses first would be suboptimal

    "highest-level priority is necessary"

## 特殊なケース

 単コースの場合```
1 1
0
```唯一のコースには前提条件カウント 0 とレベル 0 があります。 すぐに優先キューに入り、最初のバッチで選択され、完了数は 1 になります。 ループは 1 学期後に停止し、`1`。 

各コースが独立している場合は、```
6 2
0 0 0 0 0 0
```6 つのコースはすべてレベル 0 で、最初から利用可能です。 優先キューには 6 つのコースすべてが含まれており、アルゴリズムは一度に 2 つを実行します。 バッチには 2 つ、2 つ、2 つのコースが含まれているため、答えは次のようになります。`3`。 これはまさに`ceil(6 / 2)`。 

ロングチェーンで大容量のため、```
4 4
2 3 4 0
```理論的には 4 つのコースすべてが 1 学期に収まりますが、コースのみ`1`最初は利用可能です。 1学期終了後、コース`2`利用可能になり、その後コースが続きます`3`、そして最後にコース`4`。 すべてのバッチの前に優先順位制約がチェックされるため、このアルゴリズムでは 4 つの学期が生成されます。 

最も明らかなケースは、```
5 2
2 3 0 0 0
```当初はコース`1`、`4`、 そして`5`利用可能です。 彼らのレベルは、`2`、`0`、 そして`0`。 優先キューが選択するのは、`1`1 つの独立したコースと組み合わせて選択します`2`残りの独立したコースと合わせて、最終的に選択します`3`。 結果は３学期制です。 実装が利用可能なコースをキューの順序で消費するだけの場合は、次のいずれかを選択できます。`4`そして`5`まず 4 学期を取得してください。そのため、レベルの優先順位が重要です。

4 2
3 3 4 0
