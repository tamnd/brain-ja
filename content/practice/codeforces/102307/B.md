 ## 解決策
 ## 問題の理解

 空ではない文字列が 1 つあります`s`。 許可される操作は、右端に文字を追加することだけです。 目標は、結果の文字列全体が回文になるように、できるだけ少ない文字を追加することです。 

重要な制限は、すでに存在する文字を変更または削除できないことです。 次の接尾辞があるとします。`s`はすでに回文です。 その接尾辞を最後の回文の中心部分として保持すると、その逆を追加することによって、それより前のすべてをミラーリングできます。 たとえば、`helloworld`、最長の回文接尾辞は次のとおりです。`d`。 その前のプレフィックスは、`helloworl`、その逆は`lrowolleh`、したがって、答えは次のようになります`helloworldlrowolleh`。 

入力の長さは最大 5000 です。これは十分に小さいため、`O(n^2)`このアルゴリズムは潜在的に実用的ですが、線形ソリューションを簡単にし、Python 文字列操作の比較的寛大な定数要素に依存する必要性を排除します。 アン`O(n^3)`5,000 文字はすでに数十億の操作を意味するため、このアプローチは明らかに不適切です。 ターゲット ソリューションは使用します`O(n)`時間と`O(n)`メモリ。 

合理的な実装が間違っている可能性がある境界例がいくつかあります。 などの 1 文字入力の場合`a`、文字列はすでに回文であるため、正しい出力は次のようになります。`a`。 常に少なくとも 1 文字を追加する実装では、誤って長い文字列が生成されてしまいます。 

次のようなすでに回文文字列の場合`anitalavalatina`、何も追加しないでください。 正しい出力は正確に`anitalavalatina`。 適切な回文接尾辞のみを検索する実装では、誤って不要な文字が追加される可能性があります。 

接尾辞は 1 文字である必要はありません。 のために`aace`、最長の回文接尾辞は次のとおりです。`e`、したがって、答えは次のとおりです`aacecaa`。 文字列全体が回文であるかどうかだけをチェックし、それ以外の場合は逆文字列全体を追加する不用意なアプローチでは、次のような問題が発生します。`aaceecaa`これは有効ですが、最小限ではありません。 

最長の回文接尾辞は、文字列全体にならずに非常に長くなる場合もあります。 のために`abac`、接尾辞`c`は 1 文字より長い唯一の回文接尾辞であるため、答えは次のようになります。`abacaba`。 アルゴリズムは、候補が正しい順序で検査されない限り、最初の便利な回文で単純に停止するのではなく、そのような最長の接尾辞を見つける必要があります。 

## アプローチ

 直接的なアプローチは、文字列全体から始めてすべての接尾辞を試し、その接尾辞が回文であるかどうかを確認することです。 最初に見つかった回文接尾辞が最も長いものになります。 その長さが`k`、長さの接頭辞`n-k`はその接尾辞の一部ではないため、その逆を追加します。 これは正しいです。既存のサフィックスはすでに対称的ですが、プレフィックス内のすべての文字は右側に一致する文字を追加する必要があるからです。 

長さの接尾辞の回文チェック`k`多くてもかかります`floor(k/2)`キャラクターの比較。 すべての候補をチェックする必要があり、すべてのチェックが中間点に達した場合、比較の合計数は次のようになります。`sum(floor(k/2))`のために`k = 1 ... n`。 

のために`n = 5000`、まさにこれです`6,250,000`比較。 候補部分文字列の作成と反転では、追加のものも導入されます。`O(n^2)`キャラクターコピー。 したがって、このアプローチは最悪の場合でも 2 次になります。 この特定の制限を使用すると、多くの言語で渡すことができますが、問題の構造を利用することはできません。 

より迅速な観察は、最長の回文接尾辞を見つけることを標準的な接頭辞照合問題に変換できるということです。 文字列を反転して呼び出します`r`。 の接尾辞`s`が回文になるのは、対応する接頭辞が次の場合です。`r`同じ文字列です。 

たとえば、次のように考えてみましょう`s = abac`。 その逆は、`r = caba`。 接尾語`c`の`s`プレフィックスに対応します`c`の`r`。 より長い接尾辞の場合、`s`回文であり、その長い接頭辞は`r`の接尾辞と一致します`s`自体。 

この比較は、KMP プレフィックス関数を使用してエンコードできます。 構築する`r + '#' + s`。 

区切り文字は入力では出現しない文字であるため、接頭辞が誤って交差することはできません。`r`の中へ`s`。 KMP プレフィックス関数の最終値は、次の最長プレフィックスの長さを示します。`r`それも接尾辞です`s`。 という接頭辞があるため、`r`の接尾辞の逆です`s`、それらが等しいということは、この接尾辞が両方向で同じように読み取られることを意味します。 これはまさに、必要な回文接尾辞の中で最も長いものです。 

その長さがわかれば、残りはすぐに始まります。 最長の回文接尾辞に length がある場合`k`、追加`reverse(s[:n-k])`。

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取ります`s`そしてその逆を構築します`r`。 の回文接尾辞に興味があります。`s`、そしてそれらは逆の方向から見ると接頭辞になります。 
2. 結合された文字列を構築します`t = r + '#' + s`。 区切り文字は次の場所に存在してはなりません`s`これは、KMP プレフィックス関数が区切り文字の反対側にある文字を 1 つの候補一致の一部として扱ってはいけないためです。 
3. KMP プレフィックス関数を計算します。`pi`のために`t`。 それぞれのポジションごとに、`pi[i]`の最長の適切なプレフィックスの長さを格納します`t`これも位置で終わる接尾辞です`i`。 
4.テイク`k = pi[-1]`。 これは次の最長のプレフィックスです`r`それも接尾辞です`s`。 という接頭辞があるので、`r`の対応する接尾辞の逆です。`s`、等しいということは、この接尾辞が回文であることを意味します。 
5. 最初のものを保持する`n-k`の登場人物`s`まだ鏡像が必要な部分として。 それらの逆を追加します。`s[:n-k][::-1]`。 結果の文字列は回文です。 
6. 結果の文字列を出力します。 もし`s`それはすでに回文だった`k = n`、 それで`s[:n-k]`は空であり、何も追加されていません。 

### なぜ効果があるのか

 しましょう`P`～の最長の回文接尾辞である`s`、長さあり`k`。 なぜなら`P`は回文ですが、その逆はまだです`P`。 文字列全体を反転すると、この接尾辞が接頭辞になります。`r`、 それで`P`は同時に次の接頭辞でもあります`r`と接尾辞`s`。 KMP プレフィックス関数は、そのような最長のオーバーラップを見つけて、正確な値を返します。`k`。 

残りのプレフィックス`s[:n-k]`は最後の文字列の先頭に配置されます。 逆を追加すると反対側に一致する文字が与えられ、中央部分は一致します。`P`はすでに回文です。 したがって、構築された文字列は回文になります。 

最小性は、最長の回文接尾辞の選択から得られます。 有効な最終回文は、右側に新しい文字のみを追加できるため、元の文字列の何らかのサフィックスを回文の中心部分として残す必要があります。 短い回文接尾辞を使用すると、より多くの元の文字がミラーリングされることになり、より多くの挿入が必要になります。 したがって、最長の回文接尾辞により、追加される文字の最小数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_string(s):
    r = s[::-1]
    t = r + '#' + s

    pi = [0] * len(t)

    for i in range(1, len(t)):
        j = pi[i - 1]

        while j > 0 and t[i] != t[j]:
            j = pi[j - 1]

        if t[i] == t[j]:
            j += 1

        pi[i] = j

    k = pi[-1]
    return s + s[:len(s) - k][::-1]

def main():
    s = input().strip()
    print(solve_string(s))

if __name__ == "__main__":
    main()
```の`solve_string`関数が最初に作成する`r`、入力の逆。 結合された文字列`t`KMP がプレフィックスを比較するために必要な情報が含まれています。`r`接尾辞が付く`s`。 

プレフィックス配列`pi`標準的な方法で計算されます。 変数`j`現在の候補一致の長さを表します。 いつ`t[i]`一致しません`t[j]`、 続く`pi[j - 1]`ゼロから比較を再開するのではなく、次の可能な境界に直接ジャンプします。 これが、プレフィックスの計算を線形にする理由です。 

最終的な値`pi[-1]`最長の回文接尾辞の長さです。 もし`k`その長さであれば、追加する必要がある文字数は`len(s) - k`。 Python のスライスにより必要なプレフィックスが作成されます`s[:len(s) - k]`、 そして`[::-1]`右側に必要な文字を正確に指定します。 

セパレータ`#`問題の入力はスペースのない文字列であるため安全ですが、ステートメントはアルファベットを小文字に明示的に制限していません。 より防御的な実装では、入力に存在しない区切り文字を選択できます。 上記のコードは、この問題に対する通常の文字セットを想定しています。 実装をアルファベットから完全に独立させるために、代わりに短いループで区切り文字を選択できます。 

Python の整数は任意の精度であり、関係するインデックスのみが文字列の長さによって制限されるため、整数のオーバーフローの問題は発生しません。

 ## 特殊なケース

 1文字入力の場合`a`、反転した文字列も`a`。 最長の接頭辞と接尾辞の一致には長さがあります`1`、 それで`k = n`。 接頭語`s[:0]`が空の場合、アルゴリズムは戻ります`a`何も加えずに。 

次のようなすでに回文入力の場合`anitalavalatina`、反転された文字列は元の文字列と同一です。 KMP は全長の重複を検出するため、`k = n`。 これにより、追加されたプレフィックスが空になり、文字列の不要なコピーを追加するというよくある間違いを防ぐことができます。 

のために`aace`、接尾辞`e`は回文ですが、長い接尾辞はそうではありません。 KMP が見つけた`k = 1`。 接頭語`aac`に逆転しています`caa`、与える`aacecaa`。 中心人物`e`はそれ自体と一致しますが、元のプレフィックスはその周りにミラーリングされます。

4999 個のコピーで構成される最大長の入力の場合、`a`に続く`b`、決勝`b`は最長の回文接尾辞です。 KMP は引き続き、`2n + 1`結合された文字列内の文字。 アルゴリズムは、次の 4999 個のコピーを追加します。`a`これは、許容される最大の入力を実行すると同時に、実装が候補接尾辞を繰り返しスキャンすることなく非常に小さな回文接尾辞を処理することをチェックします。
