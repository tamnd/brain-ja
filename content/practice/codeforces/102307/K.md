 ## 解決策
 ## 問題の理解

 (F_1=F_2=1) および (F_{k+2}=F_{k+1}+F_k) として、1 からインデックス付けされたフィボナッチ数列があります。 特定の (n) の場合、利用可能な人間は最初 (n) のインデックス付きフィボナッチ値に対応します。 フィボナッチ値が 3 つの有効条件を満たす人間のペアを数える必要があります。つまり、gcd が 1、合計が奇数、合計自体がフィボナッチ数であるということです。 

「最初の (n) フィボナッチ数」という表現は、インデックスが重要であることを意味します。 特に、(F_1) と (F_2) は、両方の値が 1 に等しい場合でも 2 つの位置です。この小さな重複は、1 つの例外的なペアの原因となり、見落とされがちです。 公式サンプルには 6 つのクエリがあり、出力は (0、3、5、11、13、17) です。 

最大の (n) は (10^5) であり、多くのテスト ケースが存在する可能性があります。 二次アルゴリズムは次のことを調べます。 

[
 \frac{100000\cdot99999}{2}=4,999,950,000
 】

 最悪の場合はペアになります。 これは、たとえ 10 秒という寛大な制限があったとしても、コンテストのソリューションが試みるべきことをはるかに超えています。 追加の各ポジションを一定時間で処理できるように、フィボナッチ数の構造を活用する必要があります。 

不注意な実装が失敗する可能性がある小さなケースがいくつかあります。 入力用`1`、ペアはまったくないので、答えは次のようになります。`0`。 入力用`2`、唯一のペアは (F_1=1) と (F_2=1) で構成されますが、それらの合計は 2 であり、フィボナッチではないため、答えも次のようになります。`0`。 単純に連続するインデックスをカウントするソリューションでは、このペアが誤って受け入れられてしまう可能性があります。 

より微妙なケースが入力されます`3`。 ペア ((F_2,F_3)=(1,2)) と ((F_1,F_3)=(1,2)) は両方とも機能します。これらの合計は 3、gcd は 1、そして 3 はフィボナッチであるためです。 したがって、答えは次のとおりです`2`。 (1+1=2) であるため、ペア ((F_1,F_2)) は依然として機能しません。 すべての有効なペアが連続したインデックスを持つ必要があると仮定するソリューションでは、ペアが 1 つしか見つからず、間違った答えが生成されます。 

## アプローチ

 直接的なアプローチは、インデックスのすべてのペア (i<j) を (1\leq i,j\leq n) で列挙することです。 各ペアについて、gcd 条件をテストし、(F_i+F_j) が奇数かどうかを確認し、その合計がフィボナッチ数であるかどうかを判断できます。 事前に計算されたフィボナッチ メンバーシップ構造を使用すると、各ペアを定数時間または対数時間でチェックできます。 難しいのは個々のチェックではなく、ペアの数です。 (n=100000) では 4,999,950,000 個あるため、非常に安い小切手でも遅すぎます。 

重要な観察は、フィボナッチ回帰自体から得られます。 (i<j) および (j\geq4) と仮定します。 (F_2) 以降はフィボナッチ数が増加するため、

 [
 F_j < F_i+F_j < F_j+F_{j-1}=F_{j+1}
 】

 いつでも (i<j-1)。 (F_j) と (F_{j+1}) の間に厳密にはフィボナッチ数はないため、合計がフィボナッチになることはありません。 したがって、通常のインデックスの場合、有効なペアは (i=j-1) でなければなりません。 

(F_1=F_2) によって発生する例外が 1 つあります。 ペア ((1,3)) は、インデックスが連続していませんが、(1+2=3=F_4) を与えます。 この例外的なペアは個別にカウントする必要があります。 

これで、(i\geq2) の連続したペア ((i,i+1)) が残りました。 連続するフィボナッチ数は互いに素であるため、それらの gcd は自動的に 1 になります。 それらの合計は正確に (F_{i+2}) となるため、フィボナッチ和の条件も自動的に満たされます。 残る唯一の問題は、(F_{i+2}) が奇数かどうかです。 

フィボナッチパリティの繰り返しは次のようになります

 [
 1,1,0,1,1,0,\ldots
 】

 したがって、(k) が 3 で割り切れる場合、(F_k) は正確に偶数になります。 したがって、(i) で始まる連続ペアは、(i+2) が 3 で割り切れない場合、または同等の場合 (i\not\equiv1\pmod3) に有効です。 

したがって、問題全体は単純なプレフィックス数になります。 (n=3) から始まり、例外的なペア ((1,3)) があり、新しいフィボナッチ ポジションごとに 1 つの新しい連続候補が追加され、その開始インデックスが 1 を法とする 3 に一致しない限り受け入れられます。

 | 最適 | (O(\max n + T)) | (O(\max n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのテスト ケースを読み取り、クエリの最大値 (n) を見つけます。 この値までの回答のみが必要なので、すべてのクエリに対して 1 つのプレフィックス配列で十分です。 
2.初期化`ans[1] = 0`そして`ans[2] = 0`。 ポジションが 3 つ未満の場合、完璧なペアは存在しません。 
3.セット`ans[3] = 2`。 2 つの有効なペアは ((F_1,F_3)) と ((F_2,F_3)) で、どちらも値 (1) と (2) を表します。 ペア ((F_1,F_2)) は、合計が 2 であるため無効です。 
4. すべての (n\geq4) について、次から始めます。`ans[n] = ans[n-1]`。 古いペアはすべてすでにカウントされているため、考えられる新しいペアは ((F_{n-1},F_n)) のみです。 
5. ((n-1)\bmod3\neq1) の場合、その新しいペアを受け入れます。 その和は (F_{n+1}) であり、(n+1) が 3 で割り切れない場合、奇数になります。 (n+1\equiv n-2\pmod3) であるため、これは (n-1\not\equiv1\pmod3) と同等です。 
6. 条件が成立するたびに 1 を追加します。 これによりプレフィックス数が生成されるため、すべてのクエリに (O(1)) で応答できます。 

### なぜ効果があるのか

 特殊な等式 (F_1=F_2) を除いて、インデックス (i<j) を持つペアの場合、(i=j-1) を除き、フィボナッチ漸化式では (F_i+F_j) が厳密に (F_j) と (F_{j+1}) の間に配置されます。 したがって、例外ではない有効なペアはすべて連続しています。 連続するフィボナッチ数は互いに素であり、その和が次のフィボナッチ数となるため、パリティのみが残ります。 フィボナッチ数は 3 で割り切れるインデックスで正確に偶数であるため、開始インデックスが (1\bmod3) ではない連続するペアが正確に有効になります。 唯一の追加のペアは ((F_1,F_3)) であり、(n=3) での初期化に含まれます。 したがって、プレフィックス配列はすべての有効なペアを 1 回だけカウントし、無効なペアはカウントしません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    queries = [int(input()) for _ in range(t)]

    mx = max(queries)

    ans = [0] * (mx + 1)

    if mx >= 3:
        ans[3] = 2

    for n in range(4, mx + 1):
        ans[n] = ans[n - 1]

        # The new pair is (F[n-1], F[n]).
        # It is valid iff F[n+1] is odd.
        if (n - 1) % 3 != 1:
            ans[n] += 1

    sys.stdout.write("\n".join(str(ans[n]) for n in queries))

if __name__ == "__main__":
    solve()
```最初の部分では、前処理の前にすべてのクエリを読み取ります。これは、要求されたインデックスの最大値によってプレフィックス配列をどこまで構築する必要があるかが決まるためです。 これにより、複数のテスト ケースに対して同じ作業を個別に実行することがなくなります。 

での初期化`ans[3] = 2`重複値 (F_1=F_2=1) と (F_1) に関係する例外ペアの両方を処理します。 から始まる`n=4`メインの繰り返しをクリーンに保ち、特殊なケースのロジックがすべての反復に漏れるのを防ぎます。 

新しいものごとに`n`、存在しなかった唯一のペア`n-1`は ((F_{n-1},F_n)) です。 その合計は (F_{n+1}) であるため、合計が奇数かどうかをチェックすることは、(n+1) が 3 で割り切れないかどうかをチェックすることと同じです。コードでは同等の条件を使用します。`(n - 1) % 3 != 1`。 

フィボナッチ値自体を構築する必要はありません。 (n) が大きくなるにつれてそれらのサイズは巨大になりますが、証明により問題は完全にインデックス算術とフィボナッチパリティに帰着します。 これにより、Python での任意精度の整数の処理も回避されます。 

配列の長さは最大 100001 であるため、メモリ使用量は 256 MB の制限内に収まります。 出力は最終的な 1 つで生成されます。`join`、低速書き込みの繰り返しを回避します。

 ## 特殊なケース

 最初のエッジ ケースは (n=1) です。 入力```
1
1
```には (F_1=1) のみが含まれるため、2 人の異なる人間がカップルを形成することはできません。 アルゴリズムは (n=3) の初期化に入らず、そのまま残ります。`ans[1]`0 に等しく、これが正しい出力です。 

2 番目のエッジケースは (n=2) です。 唯一可能なペアは、1 を含む 2 つの位置です。それらの gcd は 1 ですが、それらの合計は 2 であり、これはフィボナッチ数ではありません。 アルゴリズムは終了します`ans[2]=0`, そのため、重複した値を誤って有効なフィボナッチ和として扱うことがなくなります。 

最も重要なインデックス作成のエッジ ケースは (n=3) です。 フィボナッチ値は (1,1,2) です。 位置 2 と 3 によって形成されるペアは合計 (1+2=3) を持ち、位置 1 と 3 によって形成されるペアはまったく同じ特性を持ちます。 したがって、答えは 2 です。初期化`ans[3] = 2`両方のペアをキャプチャします。 連続するインデックスのみに基づく式では、最初のインデックスが欠落します。 

モジュロ 3 境界の場合は、(n=5) を考慮します。 新しい連続ペアは ((F_4,F_5)=(3,5)) で、その和は 8 です。8 は偶数であるため、ペアは奇数和条件を満たしません。 ここ (n-1=4\equiv1\pmod3) は、アルゴリズムによって拒否された剰余です。 答えは 3 のままです。 

(n=6) では、新しいペアは ((F_5,F_6)=(5,8)) となり、その合計は 13 (奇数のフィボナッチ数) になります。 (n-1=5\not\equiv1\pmod3) であるため、アルゴリズムは答えを 3 から 4 に増やします。これらの 2 つの連続するケースは、条件がインデックス モジュロ 3 に基づく必要がある理由を示しています。 

最後に、(n=100000) では、2 から 99999 までの可能な通常の連続開始インデックスが 99998 あります。そのうちちょうど 33332 が 1 モジュロ 3 に一致し、パリティ条件に失敗し、66666 の有効な連続ペアが残ります。 例外的なペア ((F_1,F_3)) を追加すると、次のようになります。`66667`。 このアルゴリズムは、膨大な (100,000) 番目のフィボナッチ数を構築することなく、接頭辞の反復のみを使用してこの値に到達します。
