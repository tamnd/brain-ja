 ## 解決策
 ## 問題の理解

 私たちは2つのDNA鎖を持っています`A`そして`B`、両方の長さ`n`。 登場できるキャラクターは以下の通り`A`、`T`、`G`、 そして`C`。 共通部分列を構築する必要はありません。 可能な最大長が少なくとも以下であるかどうかを判断するだけで済みます。`0.99n`。 

条件を読み取る便利な方法は、共通部分列に何が欠落しているかを数えることです。 その長さが`L`、すると、元の各文字列は次のようになります。`n - L`その共通サブシーケンスで使用されていない文字。 要件`L >= 0.99n`と同等です`n - L <= 0.01n`。 

以来`n - L`は整数なので、最大でも損失が許容されます`floor(n / 100)`各文字列の文字。 させて`k = floor(n / 100)`。 

ターゲット LCS 長さは正確に次のようになります。`n - k`。 その長さの共通部分列を見つけることができれば、答えは肯定的です。 

長さの限界`10^5`普通を排除する`O(n^2)`LCS 動的プログラミング。 最大サイズでは、約`10^10`DP セル、1 秒の制限をはるかに超えています。 有用なパラメータは LCS の全長ではありません。`n`、しかし数は少ない`k`破棄できる文字の数。 で`n = 10^5`、`k`だけです`1000`。 

誤って処理されやすい境界ケースがいくつかあります。 いつ`n < 100`、 我々は持っています`k = 0`, したがって、どの文字も破棄される可能性はありません。 例えば、```
A
T
```LCS長さあり`0`、必要な長さは`1`したがって、正しい出力は次のようになります。`Not brothers :(`。 誤って丸めてしまうソリューション`0.99n`down はそれを誤って受け入れます。 

正確なしきい値は次の場合にも重要です。`n`の倍数です`100`。 例えば、```
AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA
AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAATA
```長さがある`100`、そのLCSは`99`。 以来`99 = 0.99 * 100`、正解は`Long lost brothers D:`。 よりも厳密に大きい長さを必要とする`0.99n`有効なケースを拒否することになります。 

もう 1 つの境界ケースはしきい値のすぐ下にあります。 と`n = 100`、LCS が`98`、各文字列から 2 文字を破棄する必要がありますが、すでに多すぎます。 不一致の数が最大 1 であるかどうかをチェックする不用意な実装は、位置の不一致と削除を混同し、シフトされた一致で失敗する可能性があります。 

## アプローチ

 簡単な解決策は、標準の LCS 動的プログラミングです。 定義する`lcs[i][j]`最初の部分列の最長の共通部分列として`i`の登場人物`A`そして最初の`j`の登場人物`B`。 現在の文字が一致する場合は、対角線の状態を拡張できます。 それ以外の場合は、どちらかの文字列から文字をスキップすることで得られるより良い結果が採用されます。 すべての共通サブシーケンスは現在の文字のペアを使用するか、少なくとも 1 つの文字をスキップするため、これは正しいです。 

問題はテーブルの大きさです。 がある`(n + 1)^2`州、つまり`n = 10^5`おおよそわかります`10^10`操作。 テーブル全体が格納される場合、メモリ要件も 2 次になります。 

重要な観察は、許容可能な共通部分列は削除のみを行うということです。`k = floor(n / 100)`いずれかの文字列の文字。 考えられるすべてのプレフィックスに対して LCS を要求する代わりに、各文字列からすでに削除された文字の数によって状態を記述することができます。 

させて`dp[i][j]`削除後にすでに一致する可能性のある文字の最大数を表します`i`からのキャラクター`A`そして`j`からのキャラクター`B`。 現在の状態に次のものがあるとします。`p = dp[i][j]`一致した文字。 一致した文字が最初の文字を占めます`i + p`の位置`A`そして最初の`j + p`の位置`B`。 したがって、次に比較する文字は次のようになります。`A[i + p]`そして`B[j + p]`。 

それらが等しい場合、それらのマッチングを停止する理由はありません。 共通のサブシーケンスをすぐに拡張し、次のペアが等しい間続行できます。 それらが異なる場合、この状態から続く共通のサブシーケンスは次の文字のいずれかを破棄する必要があります。`A`または次の文字`B`。 まさにこれら 2 つの移行です`dp[i + 1][j] = max(dp[i + 1][j], dp[i][j])`そして`dp[i][j + 1] = max(dp[i][j + 1], dp[i][j])`。 

これにより、プレフィックスでインデックス付けされた大きな LCS テーブルが、削除数のみでインデックス付けされたテーブルに変わります。 あるのは`(k + 1)^2`このような状態では、マッチング フェーズは文字列位置のすべてのペアを処理するのではなく、等しい実行を通じて直接移行します。 

この総当り的な解決策は、文字をスキップするあらゆる考えられる方法が通常の LCS の繰り返しによって表されるため機能しますが、削除数が最大の値まで考慮されるため失敗します。`n`。 受け入れられた回答は削除のみできるという観察`1%`文字数を増やすことで、小さな削除フロンティアだけを残すことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n^2)`|`O(n^2)`| 遅すぎる |
 | 最適 |`O(nk)`償却されます。`k = floor(n/100)`|`O(k^2)`| 承認済み |

 のために`n = 10^5`、便利なパラメータは次のとおりです。`k <= 1000`したがって、DP は 100 億のプレフィックス ペアではなく、約 100 万の削除状態で動作します。 一致する実行はフロンティアにわたって償却され、このアプローチに必要な制限が与えられます。 

## アルゴリズムのチュートリアル

 1. 2 つの DNA 文字列を読み取り、`n`が共通の長さになります。 コンピューティング`k = n // 100`なぜなら、受け入れられる共通部分シーケンスは、いずれかの文字列から最大でその数の文字を省略できるからです。 
2. 必要な共通部分列の長さを次のように計算します。`target = n - k`。 この整数形式では、次の浮動小数点比較が回避されます。`0.99`。 
3. もし`k`がゼロの場合、削除は許可されません。 唯一可能な長さの共通部分列`n`は文字列全体なので、答えは単純に次のとおりです。`A`そして`B`は同一です。 
4. 削除数によってインデックス付けされた DP テーブルを作成します。 最初は`dp[0][0] = 0`これは、何かを削除する前に、まだ一致する文字が存在しないことを意味します。 
5. プロセスの状態`(i, j)`昇順で。 ある状態で、`p = dp[i][j]`。 最初`i`から削除された文字`A`そして最初の`j`から削除された文字`B`、一緒に`p`一致した文字は、2 つの現在の位置を次の場所に置きます。`i + p`そして`j + p`。 
6. 両方の位置が文字列内にあり、文字が等しい場合、値を大きくします。`p`。 これらの等しい文字を貪欲に一致させることは、両側のすぐ次の文字であるため安全です。そのため、これらを保持しても削除のコストは発生せず、共通の部分シーケンスをさらに前に移動するだけです。 
7. 拡張された値を再び格納します。`dp[i][j]`。 届いていたら`target`、許容可能な共通部分列が見つかったので、すぐに受け入れることができます。 
8. もし`i < k`、現在の値をに伝播します。`dp[i + 1][j]`。 これは、次の不一致文字を削除することを表します。`A`。 もし`j < k`、それを伝播します`dp[i][j + 1]`、次の不一致文字の削除を表します。`B`。 それを超える国家は決して必要ありません`k`、以上のものを使用するソリューションであるため、`k`削除では必要な LCS 長を満たすことができません。 

不変条件とは、`dp[i][j]`最大で使用した有効なマッチングによって到達した最も遠いポイントを保存します。`i`からの削除`A`そしてせいぜい`j`からの削除`B`。 次の文字が一致する場合、その状態では常​​に一致を拡張することが最適です。 それらが一致しない場合、可能なすべての継続はこれら 2 つの文字の少なくとも 1 つをスキップする必要があり、2 つの遷移はそれらの可能性を正確に列挙します。 したがって、すべての共通サブシーケンスは最大でも`k`削除は何らかの DP パスによって表され、すべての DP パスは有効な共通サブシーケンスに対応します。 到達`n - k`したがって、一致した文字は元の条件を満たすことと同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

YES = "Long lost brothers D:"
NO = "Not brothers :("

def is_brothers(a: str, b: str) -> bool:
    n = len(a)
    k = n // 100
    target = n - k

    # If k == 0, we need an LCS of length n.
    if k == 0:
        return a == b

    # dp[i][j] = furthest number of characters matched after
    # deleting i characters from a and j characters from b.
    size = k + 2
    dp = [[0] * size for _ in range(size)]

    for i in range(k + 1):
        row = dp[i]

        for j in range(k + 1):
            p = row[j]

            x = i + p
            y = j + p

            while x < n and y < n and a[x] == b[y]:
                p += 1
                x += 1
                y += 1

            row[j] = p

            if p >= target:
                return True

            if i < k and p > dp[i + 1][j]:
                dp[i + 1][j] = p

            if j < k and p > row[j + 1]:
                row[j + 1] = p

    return False

def main() -> None:
    a = input().strip()
    b = input().strip()

    print(YES if is_brothers(a, b) else NO)

if __name__ == "__main__":
    main()
```の最初の部分`is_brothers`パーセンテージ要件を整数の削除予算に変換します。 以来`n - LCS`一体的であり、`k = n // 100`は、まさに削除できる最大文字数です。 

の`k == 0`ブランチは、以下の文字列よりも短いすべての文字列を処理します。`100`直接。 この場合、必要な LCS は文字列全体であるため、2 つの入力が等しいことが必要かつ十分です。 

DP テーブルにはディメンションがあります`(k + 2) x (k + 2)`。 追加の行と列により、次の場合に安全に遷移できます。`i`または`j`に等しい`k`。 引き続き次の状態のみを処理します`0`を通して`k`削除数が大きくなると、許容できる答えが得られなくなるためです。 

変数`x = i + p`そして`y = j + p`は、2 つの文字列内の実際の現在位置です。 一致する文字が消費されると、両方の位置と`p`一緒に前進します。 これは、ループ内で位置を最初から再計算するよりもエラーが発生しにくくなります。 

小切手`i < k`そして`j < k`別の削除状態に伝播する前に必要です。 これらがないと、コードはあたかも有効な状態であるかのように余分な境界行または列にアクセスし、許可されている削除数を超えて誤って使用してしまう可能性があります。 

浮動小数点演算は使用されません。 テスト`p >= n - n // 100`テストとまったく同じです`p >= 0.99n`、いつを含む`n`で割り切れない`100`。 

ここでは Python 整数にはオーバーフローの問題はなく、すべての DP 値は最大でも`n`。 メイン メモリのコストは、次の場合に約 100 万の DP エントリから発生します。`n = 100000`、メモリ制限を快適に下回ります。

## テストケース```python
import sys
import io

YES = "Long lost brothers D:"
NO = "Not brothers :("

def is_brothers(a: str, b: str) -> bool:
    n = len(a)
    k = n // 100
    target = n - k

    if k == 0:
        return a == b

    size = k + 2
    dp = [[0] * size for _ in range(size)]

    for i in range(k + 1):
        row = dp[i]

        for j in range(k + 1):
            p = row[j]

            x = i + p
            y = j + p

            while x < n and y < n and a[x] == b[y]:
                p += 1
                x += 1
                y += 1

            row[j] = p

            if p >= target:
                return True

            if i < k and p > dp[i + 1][j]:
                dp[i + 1][j] = p

            if j < k and p > row[j + 1]:
                row[j + 1] = p

    return False

def run(inp: str) -> str:
    old_stdin = sys.stdin
    try:
        sys.stdin = io.StringIO(inp)
        a = sys.stdin.readline().strip()
        b = sys.stdin.readline().strip()
        return YES if is_brothers(a, b) else NO
    finally:
        sys.stdin = old_stdin

# Provided sample 1
assert run(
    "GAATTGCGTACAATGC\n"
    "GAATTGCGTACAATGC\n"
) == YES, "sample 1"

# Provided sample 2
assert run(
    "CCATAGAGAA\n"
    "CGATAGAGAA\n"
) == NO, "sample 2"

# Minimum size, equal strings.
assert run("A\nA\n") == YES, "minimum equal strings"

# Minimum size, different strings. k = 0, so no deletion is allowed.
assert run("A\nT\n") == NO, "minimum different strings"

# n = 100 and exactly one deletion is enough.
a = "A" * 100
b = "A" * 50 + "T" + "A" * 49
assert run(a + "\n" + b + "\n") == YES, "one deletion boundary"

# n = 100 and two deletions are necessary, which exceeds the budget.
a = "A" * 100
b = "A" * 50 + "TT" + "A" * 48
assert run(a + "\n" + b + "\n") == NO, "two deletions boundary"

# Maximum-size all-equal input.
a = "A" * 100000
assert run(a + "\n" + a + "\n") == YES, "maximum all-equal input"
