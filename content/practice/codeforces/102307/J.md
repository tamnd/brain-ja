 ## 解決策
 ## 問題の理解

 (n) 個の壁の高さの配列があります。 破壊操作では、間隔 ([a,b]) を選択し、その間隔内のすべての壁から正確に (s) メートル除去します。ただし、壁がマイナスになることはありません。 つまり、影響を受けるすべての高さは (h_i) から (\max(0,h_i-s)) に変化します。 

クエリでは、指定された間隔内のすべての壁の残りの高さの合計が求められます。 操作はオンラインであるため、各クエリには、以前のすべての破棄操作によって生成された状態を使用して回答する必要があります。 

制約は、間隔内のすべての壁を更新することを除外するのに十分な大きさです。 (n,q\le 10^5) の場合、すべての操作にわたって (10^{10}) 個の位置が影響を受ける可能性があります。 (O(nq)) の解決策であっても、数秒で処理できる範囲をはるかに超えています。 通常、個々の壁に触れることなく区間全体を処理できるデータ構造が必要です。 

難しいのはゼロでの切り捨てです。 通常の遅延セグメント ツリーは、すべての値が同じ量だけ変化するため、(h_i\mathrel{-}=s) などの操作に対してすぐに機能します。 ここで、高い壁は減少し続ける一方で、一部の壁はゼロに達する可能性があるため、単一の均一な遅延値が常に十分であるとは限りません。 

いくつかの特殊なケースでこの問題が明らかになります。 

単一の壁を考えてみましょう。```
1 3
2
2 1 1 5
1 1 1
```壁の高さは (2) なので、(5) メートルを破壊すると高さ (0) が残ります。 出力は次のとおりです。```
0
```単純に (5) を減算する実装では (-3) が格納され、無効な答えが生成されます。 

次に、さまざまな高さを考えてみましょう。```
2 2
3 10
2 1 2 5
1 1 2
```攻撃後の高さは (0,5) なので、正しい出力は次のようになります。```
5
```セグメント全体から (5) を減算する遅延更新では、最初の壁がすでにゼロに達しているため、最初の壁を正しく表すことができません。 

等価性は別の境界ケースです。```
2 2
5 10
2 1 2 5
1 1 2
```結果の高さは (0,5) となり、答えは次のようになります。```
5
```実装では、(s=\text{正の最小高さ}) を、少なくとも 1 つの壁がゼロになる場合として扱う必要があります。 遅延減算は、(s) が正の最小の高さより厳密に小さい場合にのみ安全です。 

最後に、間隔にはすでにゼロになっている壁を含めることができます。```
3 3
2 5 1
2 1 1 3
2 1 3 2
1 1 3
```最初の攻撃後の配列は (0,5,1) になります。 2 番目以降は (0,3,0) なので、答えは次のようになります。```
3
```ゼロ値の壁は、将来の減算に参加してはなりません。 ゼロを通常の最小値として扱うと、データ構造は「すでに破壊されたもの」と「最小の正の壁」を区別できなくなります。 

## アプローチ

 直接的な解決策では、現在のすべての壁の高さが保存されます。 ([a,b]) の破棄操作の場合、その間隔内のすべてのインデックスを訪問し、(h_i=\max(0,h_i-s)) を実行します。 クエリも同様に間隔をスキャンし、すべての高さを加算します。 これは、問題で説明されている操作を正確に実行するため、正しいです。 

問題は最悪のケースだ。 すべての (q) 個の操作が配列全体に影響を与える場合、各操作は (n) 個の壁に触れ、(O(nq)) 個の仕事を与えます。 どちらの値も (10^5) と同じくらい大きいため、最大 (10^{10}) 個の個別の配列演算が必要になりますが、これは大きすぎます。 

通常の遅延セグメント ツリーは、間隔全体を一度に短縮できることが多いため、有望に思えます。 障害となるのはゼロ境界です。 セグメントに高さ (3,10,12) が含まれており、(5) を減算するとします。 結果は (0,5,7) です。 3 つの値すべてを正しく変換する単一の減算はありません。 

有益な観察は、高さの完全な分布を知る必要がないということです。 セグメントについては、その合計、正の壁の数、正の最小高さを維持します。 (s) がその最小の正の高さより小さい場合、すべての正の壁は攻撃に耐えます。 すべての正の値がまったく同じ変換を受けるため、セグメント全体を (s) だけ遅延的に減少させることができます。 

(s) が正の最小高さ以上の場合、少なくとも 1 つの壁がゼロになります。 これらの壁を個別に破壊できるまで、セグメントを再帰的に検査します。 これは潜在的に費用がかかるように思えますが、そのような強制降下はすべて、少なくとも 1 つのポジティブな壁を永久に取り除きます。 壁がゼロになるのは 1 回だけであるため、高価な部分は実行全体にわたって償却されます。 

同じセグメント ツリーは、標準 (O(\log n)) の方法で合計クエリに答えることができます。 したがって、このソリューションは、遅延伝播と償却された「最小の正の値を破棄する」戦略を組み合わせたものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(nq)) 最悪の場合 | (O(n)) | 遅すぎる |
 | 最適 | (O((n+q)\log n)) 償却 | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 壁の高さに合わせてセグメント ツリーを構築します。 すべてのノードについて、その間隔の合計、その間隔内の正の壁の数、および正の壁の最小の高さを保存します。 間隔全体がすでに破棄されている場合は、(+\infty) を最小値として保存します。 これら 3 つの値は、まさに破壊操作を遅延適用できるかどうかを判断するために必要なものです。 
2. ノード内の現在ポジティブなすべての壁から削除されたメーターを表す遅延値も保存します。 ノードに次の内容が含まれている場合`cnt`正の壁と (s) の遅延減算を受け取り、その合計が減少します`cnt * s`、その最小の正の高さは (s) だけ減少します。 ゼロの壁は影響を受けません。 
3. 完全にカバーされたノードでの破棄操作の場合は、最初にその合計がゼロかどうかを確認します。 もしそうなら、その区間全体はすでに破壊されており、何もすることがありません。 
4. ノードが完全に覆われており、正の最小高さよりも厳密に小さい場合は、減算を遅延適用します。 すべての正の壁は正のままであるため、実際にはすべてが正確に (s) メートル損失します。 
5. そうでない場合は、子供たちの中に降りてください。 条件 (s\ge\text{正の最小高さ}) は、少なくとも 1 つの正の壁がゼロに達することを意味するため、この操作は 1 つの均一な遅延減算では表現できません。 子が実際の現在の高さを確認できるように、降下する前に保留中の遅延値をプッシュします。 
6. リーフで、ゼロフロアで (s) を減算します。 この葉はハードケースを通って到達しているため、現在の高さは最大(s)であるため、ゼロになります。 正のカウントを 0 に設定し、最小値を (+\infty) に設定します。 
7. 子を更新した後、子をマージします。 新しい合計は子の合計の合計であり、正のカウントは子のカウントの合計であり、正の最小高さは小さい方の子の最小値です。 
8. 合計クエリの場合は、通常のセグメントツリー間隔トラバーサルを使用します。 子に格納された状態はまだ親の保留中の減算を待っている可能性があるため、子に入る前に遅延値をプッシュします。 

これが機能する理由: すべてのセグメント ツリー ノードは常に、その合計、正の数、および正の最小高さによってその間隔を正確に記述します。 (s) が正の最小の高さより小さい場合、ゼロに達する壁はないため、すべての正の壁から (s) を減算することはまさに必要な操作であり、遅延タグとして安全に保存できます。 (s) が最小値に達すると、均一な減算は有効ではなくなるため、影響を受ける壁を個別に処理できるようになるまでアルゴリズムが下降します。 すべてのリーフで、更新は正確に (h_i\leftarrow\max(0,h_i-s)) になります。 親情報は正しい子から再構築されるため、更新のたびに不変条件が保持されます。 クエリはこれらの正確なセグメント状態から合計を返すため、報告されるすべての間隔の合計は正確です。 

償却はハードケースから発生します。 完全にカバーされたノードを遅延更新できない場合は、そのノードの下のどこかで最小の正の壁が破壊されます。 各壁は一度だけ破壊できます。 破壊された壁の周囲の再帰には高さ (O(\log n)) があるため、すべての激しい降下は合わせて (O(n\log n)) に寄与します。 クエリ境界と遅延処理される更新によって引き起こされる通常の走査が原因となります (O(q\log n))。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    size = 4 * n + 5
    total = [0] * size
    mn = [INF] * size
    cnt = [0] * size
    lazy = [0] * size

    def build(node, left, right):
        if left == right:
            value = a[left]
            total[node] = value
            mn[node] = value
            cnt[node] = 1
            return

        mid = (left + right) // 2
        lc = node * 2
        rc = lc + 1

        build(lc, left, mid)
        build(rc, mid + 1, right)

        total[node] = total[lc] + total[rc]
        cnt[node] = cnt[lc] + cnt[rc]
        mn[node] = min(mn[lc], mn[rc])

    def apply(node, value):
        if cnt[node] == 0:
            return

        total[node] -= cnt[node] * value
        mn[node] -= value
        lazy[node] += value

    def push(node):
        value = lazy[node]
        if value == 0:
            return

        lc = node * 2
        rc = lc + 1

        apply(lc, value)
        apply(rc, value)

        lazy[node] = 0

    def pull(node):
        lc = node * 2
        rc = lc + 1

        total[node] = total[lc] + total[rc]
        cnt[node] = cnt[lc] + cnt[rc]
        mn[node] = min(mn[lc], mn[rc])

    def update(node, left, right, ql, qr, value):
        if qr < left or right < ql or total[node] == 0:
            return

        if ql <= left and right <= qr and value < mn[node]:
            apply(node, value)
            return

        if left == right:
            total[node] = 0
            cnt[node] = 0
            mn[node] = INF
            lazy[node] = 0
            return

        push(node)

        mid = (left + right) // 2
        lc = node * 2
        rc = lc + 1

        if ql <= mid:
            update(lc, left, mid, ql, qr, value)
        if qr > mid:
            update(rc, mid + 1, right, ql, qr, value)

        pull(node)

    def query(node, left, right, ql, qr):
        if qr < left or right < ql:
            return 0

        if ql <= left and right <= qr:
            return total[node]

        push(node)

        mid = (left + right) // 2

        result = 0
        if ql <= mid:
            result += query(node * 2, left, mid, ql, qr)
        if qr > mid:
            result += query(node * 2 + 1, mid + 1, right, ql, qr)

        return result

    build(1, 0, n - 1)

    output = []

    for _ in range(q):
        parts = list(map(int, input().split()))
        operation = parts[0]
        left = parts[1] - 1
        right = parts[2] - 1

        if operation == 1:
            output.append(str(query(1, 0, n - 1, left, right)))
        else:
            value = parts[3]
            update(1, 0, n - 1, left, right, value)

    sys.stdout.write("\n".join(output))

if __name__ == "__main__":
    solve()
```Python のオブジェクトが多いノード構造ではかなり多くのメモリが消費され、オーバーヘッドが増加するため、ツリーでは 4 つの配列が使用されます。`total[node]`残りの壁の高さの合計、`cnt[node]`ポジティブな壁をカウントします。`mn[node]`は正の最小の高さであり、`lazy[node]`保留中の減算を保存します。 

の`apply`関数は、すべての正の壁を正に保つ減算の場合にのみ有効です。 条件`value < mn[node]`まさにそれを保証します。 正の壁の数は変わらないため、合計は次のように減少します。`cnt[node] * value`そして最小値は次のように減少します`value`。 

完全に破壊されたノードは、`cnt[node] == 0`。 その最小値は次のように表されます。`INF`、ゼロではなく。 ゼロは「正ではない」ことを意味するのに対し、必要な最小値は具体的には正の壁の中での最小値であるため、この区別は不可欠です。 の`apply`関数は破壊されたノードを無視するため、保留中の減算はそれらのノードに影響を与えません。 

厳密な比較`value < mn[node]`これも重要な詳細です。 もし`value == mn[node]`、少なくとも 1 つの壁が正確にゼロに達するため、操作を再帰する必要があります。 等価性を遅延更新として扱うと、正の数と最小値が不正確なままになります。 

再帰的なハードケースが到達したリーフでは、壁は必然的にゼロになります。 リセットする`lazy[node]`ゼロ リーフは決して減算タグを未来に持ち越してはいけないため、これが必要です。 それ以外の場合は後で`push`保存されている最小値が誤って変更される可能性があります。 

実装では内部で 0 から始まるインデックスが使用されますが、入力では 1 から始まるインデックスが使用されます。 両方のクエリ エンドポイントを読み取った直後に 1 を減算すると、変換の繰り返しが回避され、セグメント ツリーの境界の一貫性が保たれます。 

Python の整数には任意の精度があるため、合計がオーバーフローすることはありません。 可能な合計の最大値は (10^5\cdot10^8=10^{13}) で、いずれにしても 64 ビット整数に収まります。 

## 実用的な例

 提供されたサンプルは、高さ (10) の 2 つの壁から始まります。 

| 操作 | 演算後の配列 | クエリされた合計 |
 | --- | --- | --- |
 |`1 1 2`|`[10, 10]`| 20 |

 セグメントの最小値は (5) より大きい (10) であるため、最初の攻撃は 1 回の遅延減算で表すことができます。 その更新後、セグメントの合計は (10) になり、その正の数は引き続き (2)、正の最小の高さは (5) になります。 

2 回目の攻撃は 2 番目の壁のみをターゲットにします。 現在の高さは (5) ですが、攻撃により (6) が削除されるため、厳密な遅延条件は失敗します。 再帰はそのリーフに到達し、完全に破壊します。 結果の合計は (5) になります。

その後、ポジション (1) ～ (2) への攻撃により (6) が除去されます。 最初の壁は (7) から (1) になりますが、2 番目の壁はすでにゼロです。 破壊された壁があるため、`cnt = 0`、減算には参加しません。

                result += query(node * 2, left, mid, ql, qr)
            if qr > mid:
                result += query(node * 2 + 1, mid + 1, right, ql, qr)

            return result

        build(1, 0, n - 1)

        output = []

        for _ in range(q):
            parts = list(map(int, sys.stdin.readline().split()))
            op = parts[0]
            l = parts[1] - 1
            r = parts[2] - 1

            if op == 1:
                output.append(str(query(1, 0, n - 1, l, r)))
            else:
                update(1, 0, n - 1, l, r, parts[3])

        return "\n".join(output)
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 特殊なケース

 壁よりも大きな破壊量がマイナスの高さを生み出すことはありません。 のために```
1 3
2
1 1 1
2 1 1 5
1 1 1
```最初のクエリは (2) を返します。 更新は高さ (2) のリーフに到達しますが、(5\ge2) であるため、ハード ケースによって完全に破壊されます。 最後のクエリは (0) を返します。 

アタック量と正の最小高さが正確に等しくなるには、再帰も必要です。 のために```
2 2
5 10
2 1 2 5
1 1 2
```正の高さの最小値は (5) で、アタック量とまったく同じです。 厳しい条件`value < mn[node]`失敗したため、ツリーは下降します。 最初の壁はゼロになり、2 番目の壁は (5) になり、正しい合計は (5) になります。 

すでに破壊された壁はそのままにしておく必要があります。 で```
3 3
2 5 1
2 1 1 3
2 1 3 2
1 1 3
```最初の操作では配列が次のように変更されます`[0,5,1]`。 2 回目の操作中に、ゼロの壁は`cnt = 0`したがって、遅延減算は正の壁にのみ適用されます。 最終的な状態は、`[0,3,0]`、答えは(3)です。 

単一位置の間隔も、特別な場合を除き、同じ再帰によって処理されます。 例えば、```
4 3
3 100 4 8
2 1 1 3
1 1 4
2 4 4 8
```最初の壁を (3) から (0) に変更し、次に最後の壁を (8) から (0) に変更します。 セグメント ツリーは、通常のインターバル トラバーサルを通じていずれかのリーフを分離できるため、個別のポイント更新の実装は必要ありません。 

フルレンジの場合は最適化が最も重要です。 すべての壁の最初の高さが (100000000) である場合、正確に (100000000) メートルを除去する攻撃は正確に最小値に達し、最終的にはすべての葉を破壊します。 各壁は 1 回だけ削除されるため、この特定の操作では再帰的な降下が必要ですが、同じ壁がゼロになった後に別のハード降下を引き起こすことはできません。 これは、(O((n+q)\log n)) 境界の後の償却です。
