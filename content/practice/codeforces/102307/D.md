 ## 解決策
 ## 問題の理解

 1 から (n) までのインデックスが付いた長さ (n) の文字列があり、(q) が更新されます。 更新では、開始位置 (i)、ステップ (a)、ステップ数 (k)、および文字 (c) を選択します。 影響を受ける位置は 1 つの等差数列を形成します。 

[
 i、\ i+a、\ i+2a、\ \ldots、\ i+ka。 
]

 影響を受けるすべてのキャラクターは (c) になります。 更新は指定された順序で適用されるため、複数の操作が同じ位置に触れた場合、最新の操作の文字のみが問題になります。 タスクは、すべての更新が適用された後に文字列を出力することです。 公式問題には (n,q\le 10^5) と 2 秒の制限時間があります。 

制約により、(nq) に比例する仕事の実行が除外されます。 両方の値が (10^5) に達すると、最大 (10^{10}) 個の位置が更新されることになります。 (O(nq)) アルゴリズムでさえ、利用可能な時間をはるかに超えているため、中心的なタスクは、すべての演算を文字通りに処理するのではなく、等差数列構造を活用することです。 

実装を静かに破壊する可能性のある境界ケースがいくつかあります。 まず、(k) がゼロになる可能性があるため、操作は 1 つの位置にのみ影響を与える可能性があります。 例えば、```
ab
1
2 1 0 c
```生成する```
ac
```最初の位置から開始し、別のステップが存在する間のみ実行されるループは、誤って更新をスキップします。 

2 番目の問題は、最終位置が含まれていることです。 例えば、```
abcde
1
2 3 1 x
```位置 2 と 5 を変更して、```
axcdx
```ハーフオープンエンドポイントを使用した実装が誤って処理している`i + k*a`除外されると生成される`axcde`。 

最後の微妙なケースは、異なるステップ サイズでの操作の重複です。 例えば、```
abc
2
1 1 2 x
2 1 0 y
```まずすべての位置を次のように変更します`x`、位置 2 を次のように変更します。`y`、したがって、答えは次のとおりです```
xyx
```ステップ サイズに応じて操作を個別に処理し、単に文字を上書きするだけでは十分ではありません。 各位置に触れた最新の操作のタイムスタンプを保存する必要があります。 

## アプローチ

 直接的な解決策は簡単です。 現在の文字列を保持し、操作ごとにウォークスルーします。 

[
 i、\ i+a、\ i+2a、\ldots、i+ka
 ]

 そして新しいキャラクターを割り当てます。 これらは操作で指定された位置とまったく同じであるため、これは正しいです。 

問題は課題の数です。 最悪の場合、操作が (10^5) 個の位置に触れる可能性があり、そのような操作が (10^5) 回存在する可能性があります。 のような構造```
i = 1, a = 1, k = 99999
```はすべての位置をタッチするため、総当たりアルゴリズムで (10^{10}) の代入を実行できます。 

有益な観察は積 (ka) から得られます。 すべての操作が満たされます

 [
 i+ka\le n.
 ]

 (\sqrt n) 付近のしきい値 (B) を選択するとします。 (k\le B) の場合、操作には最大でも (B+1) 個の位置が含まれるため、直接処理する方がコストがかかりません。 すべての (q) 操作にわたって、これには (O(qB)) のコストがかかります。 

難しい演算は(k>B)の演算です。 彼らにとって、

 [
 < \frac{n}{B}。 
]

 (B) が (\sqrt n) 付近の場合、それらのステップ サイズも小さくなります。 これは、負荷の高い操作に使用できるステップ サイズは (O(\sqrt n)) のみであることを意味します。 

次に、これらの長い操作を逆方向に処理します。 すべての長い演算が同じステップ (a) を持つと考えてください。 これらはまったく同じ位置チェーンに沿って移動します。 

[
 r、\ r+a、\ r+2a、\ldots
 ]

 固定 (a) の場合、後の操作によって位置が要求されると、同じ (a) を使用した以前の操作はその最終値を変更できません。 その位置を考慮から削除し、素の集合共用体構造を使用して次の削除されていない位置に直接ジャンプできます。 

したがって、固定された各小さい (a) について、すべての位置は最大 1 回削除されます。 1 つの (a) の合計作業量は (O(n\alpha(n))) であり、(a) の可能な値は (O(\sqrt n)) のみです。 これにより、標準 (O(n\sqrt n+q\sqrt n)) の解が得られます。 この問題に対する既知の解決策では、同じ平方根分割と DSU スキップ技術が使用されています。 

2 つのパーツをきれいに組み合わせるための追加の詳細が 1 つあります。 処理中に実際の文字列を変更する必要はありません。 その代わり、`last[pos]`その位置に影響を与えると判断された最新の操作のインデックスを格納します。 すべての操作が処理された後、`last[pos]`どのキャラクターがそこに属しているかを正確に教えてくれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(nq)) | (O(n)) | 遅すぎる |
 | 最適 | (O((n+q)\sqrt n)) | (O(n+q)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元の文字列とすべての操作を読み取ります。 すべての操作に 1 から始まる入力順序番号を付けます。順序番号は、複数の操作が同じ位置に触れたときにどの操作が勝つかを決定するのに十分です。 
2. (B=\lfloor\sqrt n\rfloor) を選択します。 演算に (k\le B) がある場合、その等差数列のすべての位置を直ちに処理し、設定します`last[position]`操作インデックスに。 操作には最大で (B+1) 個の位置が含まれるため、このような操作をすべて合わせると (O(qB)) のコストがかかります。 
3. 後の処理のために、すべての操作を (k>B) で保存します。 (ka<n)、つまり (a<n/(B+1)) であるため、このような演算のステップ サイズは小さくなります。 (B) が (\sqrt n) に近い場合、これは、これらの演算間で異なるステップ サイズが (O(\sqrt n)) だけ発生できることを意味します。 
4. 可能な小さなステップ サイズ (a) をそれぞれ個別に処理します。 要素が文字列の位置を表す DSU 構造体を作成します。 最初は、すべての位置がそれ自体を指します。これは、このステップ サイズを持つ最新の長い操作によってその位置をまだ要求できることを意味します。 
5. 固定 (a) については、その長い演算を逆の順序で調べます。 からのポジションをカバーする操作の場合`i`を通して`i + k*a`、以降のまだ利用可能な最初の位置から開始します。`i`、次に利用可能な位置に繰り返しジャンプします。 
6. 利用可能な位置に達したら、設定します。`last[position]`操作インデックスに追加し、この DSU チェーンからその位置を削除します。 位置の削除`p`の代表者にリダイレクトすることを意味します`p+a`、この等差数列に属する位置は正確に区切られているため、`a`。 
7. 代表者が操作のエンドポイントを超えるまで続行します。 同じステップによる後の操作で削除された位置は、前の操作で再度考慮する必要はありません。これが、DSU が長時間の操作を効率化する理由です。 
8. 結局のところ、短期および長期の操作は、`last`、文字列を 1 回スキャンします。 もし`last[p]`ゼロ、操作なしのタッチ位置`p`, そのため、元の性格が残ります。 それ以外の場合は、操作に属する文字に置き換えます`last[p]`。 

なぜ効果があるのか​​: あらゆるポジションにおいて、`last[p]`影響を与えるすべての処理された操作の中で最大の操作インデックスです。`p`。 短い操作では、影響を受けるすべての位置を明示的に訪問します。 ステップ サイズが固定された長い操作の場合、逆方向に処理することは、利用可能な位置に最初に遭遇したのが、そのステップに影響を与える最新の操作であることを意味します。 一度主張されると、そのステップの残りの操作はすべて以前のものとなるため、その位置は安全に削除できます。 最大の操作インデックスを取得すると、すべてのステップ サイズからの寄与が結合されるため、すべてを処理した後、`last[p]`まさに位置を変える最新の操作です`p`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    q = int(input())

    operations = []
    last = [0] * (n + 1)

    B = int(n ** 0.5)

    # Operations with small k are cheap enough to process directly.
    long_by_step = {}

    for op_id in range(1, q + 1):
        i, a, k, c = input().split()
        i = int(i)
        a = int(a)
        k = int(k)

        operations.append((i, a, k, c))

        if k <= B:
            pos = i
            end = i + k * a
            while pos <= end:
                last[pos] = op_id
                pos += a
        else:
            long_by_step.setdefault(a, []).append(op_id)

    # Process long operations in reverse order, separately for each step.
    for a, ids in long_by_step.items():
        # parent[x] exists only for positions that have already been removed.
        # If x is absent, x itself is currently available.
        parent = {}

        def find(x):
            root = x
            while root in parent:
                root = parent[root]

            while x in parent:
                nxt = parent[x]
                parent[x] = root
                x = nxt

            return root

        for op_id in reversed(ids):
            i, _, k, _ = operations[op_id - 1]
            end = i + k * a

            pos = find(i)

            while pos <= end:
                last[pos] = op_id

                nxt = find(pos + a) if pos + a <= n else n + 1
                parent[pos] = nxt
                pos = nxt

    result = list(s)

    for pos in range(1, n + 1):
        op_id = last[pos]
        if op_id:
            result[pos - 1] = operations[op_id - 1][3]

    sys.stdout.write(''.join(result) + '\n')

if __name__ == "__main__":
    solve()
```すべての入力が読み取られた後に長い操作を再度実行する必要があるため、入力は完全な操作として保存されます。 各操作では、元の 1 から始まるインデックスが保持され、それがタイムスタンプになります。 

短い操作の場合、`pos`から始まります`i`そして正確に進みます`a`それまで`i + k*a`。 の`<=`最終的な位置は操作の一部であるため、この条件は意図的に行われます。 

長時間の操作は次のようにグループ化されます。`a`。 削除された位置からのジャンプは正確に行われるため、DSU はステップ サイズごとに個別に作成されます。`a`。 1 つの DSU で複数の異なる算術数列を同時に表すことはできません。 

辞書ベースの DSU は、考えられるすべての小さなステップに対して (O(n)) Python リストを割り当てることを回避します。 ポジションが挿入されます`parent`現在のステップ サイズで削除された後にのみ。 各ポジションは特定の場合に最大 1 回削除できるため、`a`、1 ステップ サイズの処理中に、そのようなエントリは最大 (n) 個存在します。 

長い操作は逆方向に実行されます。 同じ内容の 2 つの長い操作を想定します。`a`両方のカバー位置`p`。 後の方が先に遭遇するので、`p`が割り当てられてから削除されます。 以前の操作を調べると、DSU が飛び越えます`p`これにより、前の操作が後の操作を誤って置き換えるのを防ぎます。 

Python では整数オーバーフローの問題はありません。 固定幅言語では、`i + k*a`これらの制約の下でも 32 ビット符号付き整数に快適に収まりますが、Python は特別な処理を行わずに自然に算術演算を処理します。 

最終的な文字列は、すべてのタイムスタンプがわかった後にのみ構築されます。 これにより、短い操作と長い操作が異なる順序で処理されるときに実際の文字を同期する必要がなくなります。 

## 実用的な例

 提供されたサンプルには (n=20) があるため、(B=4) になります。 最初の操作には (k=8) があり、長い操作になります。 他の 2 つは (k=4) と (k=2) であるため、直接処理されます。 

| 操作 | タイプ | 影響を受けるポジション |`last`変更点 |
 | --- | --- | --- | --- |

 |`6 3 4 c`| 短い | 6、9、12、15、18 | 6、9、12、15、18 は 2 になります |
 |`10 5 2 d`| 短い | 10、15、20 | 10、15、20 が 3 になります |

 長い操作は次に逆方向に処理されます。`a=2`。 位置 4、6、8、10、12、14、16、18、および 20 を要求します。短い操作にすでに大きなタイムスタンプがある場合、最後の操作は`max`は変わらないままです。 したがって、位置 6、12、および 18 は操作 2 を保持し、位置 10、15、および 20 は該当する場合は操作 3 を保持し、最初の操作の残りの位置は次の操作を受け取ります。`b`。 

最後の文字列は```
xaabacabcdacabdbacad
```トレースは、操作インデックスの保存がなぜ役立つかを示しています。 長い操作は、最終的にタイムスタンプによって比較されるため、短い操作とは別に処理できます。 

2 番目の例として、次のことを考えてみましょう。```
abcdefghij
3

```ここでは (n=10) と (B=3) です。 最初の操作は (k=9>B) であるため、ステップ サイズ 1 の DSU によって処理されます。他の 2 つの操作は短いです。 

| 操作 | タイプ | 影響を受けるポジション |`last`処理後 |
 | --- | --- | --- | --- |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O((n+q)\sqrt n)) | 短い操作では、それぞれ最大 (O(\sqrt n)) 個の位置を訪問しますが、長い操作では、小さなステップ サイズごとに各位置を最大 1 回削除します。 
| スペース | (O(n+q)) | 操作、タイムスタンプ、および 1 つの DSU 辞書が保存されます。 

(n,q\le 10^5) の場合、(\sqrt n) は約 316 です。平方根分解により、潜在的に巨大な (nq) 作業がアルゴリズムから除外されます。 DSU は、現在のステップ サイズですでに解決されている位置を繰り返し訪問することを防ぐため、長時間操作の部分は特に効率的です。 1 つのステップ サイズの DSU は次のステップ サイズを処理する前に破棄されるため、メモリ使用量は入力サイズに対して線形のままです。

    sys.stdin = io.StringIO(inp)

    try:

    finally:

 ## 特殊なケース

 ステップ数がゼロの場合、```
ab
1
2 1 0 c
```(k=0) があるため、影響を受ける唯一の位置は 2 です。 (k\le B) なので、短い操作ループは位置 2 から開始され、それを 1 回書き込み、位置 3 に進んだ直後に停止します。結果は次のようになります。`ac`。 包括的であるため、特別なケースは必要ありません。`while pos <= end`条件は単一位置の進行を自然に処理します。 

エンドポイントに依存した操作の場合、```
abcde
1
2 3 1 x
```エンドポイントは`2 + 1*3 = 5`。 ループは位置 2 を訪れ、次に位置 5 を訪れてから停止します。 結果は`axcdx`。 を使用したループ`< end`の代わりに`<= end`最後の文字を黙って見逃してしまうでしょう。 

重複した操作の場合、```
abcde
3
1 1 4 x
2 2 1 y
3 1 0 z
```最初の操作はすべての位置にタッチし、2 番目の操作は位置 2 と 4 にタッチし、3 番目の操作は位置 3 にタッチします。タイムスタンプは、位置 1 と 5 で 1、位置 2 と 4 で 2、位置 3 で 3 になります。最終結果は次のようになります。`xyzyx`。 アルゴリズムはこれを正しく実行します。`last[position]`最適化機構によって最後に処理された操作ではなく、最大の操作インデックスを記録します。 

長時間の操作の場合は、次の点を考慮してください。```
abcdefghij
3
1 1 9 x
3 2 2 y
2 3 2 z
```最初の操作は (k=9) なので時間がかかるため、延期されます。 短い操作では、最初にタイムスタンプ 2 と 3 が記録されます。ステップ 1 DSU が最初の操作を逆方向に処理するとき、すべての位置を正確に 1 回訪問し、タイムスタンプ 1 を割り当てます。タイムスタンプ 2 または 3 の位置は、より大きな値を保持します。 最終結果は`xzyzyxyxzx`。 

最大サイズのケースでも同じメカニズムが大規模に使用されます。 長さ 100000 の文字列と演算`1 1 99999 z`、すべての操作がすべての位置をカバーします。 逆方向に処理すると、最新の操作は最初のパスですべての位置を要求します。 初期のすべての操作は、DSU 代表者がすでに終了点を超えている位置から開始されるため、これらの操作は基本的に追加の位置作業を実行しません。 答えは100000です`z`文字を使用して、操作を逆にすることが最適化の重要な部分である理由を示しています。
