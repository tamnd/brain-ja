 ## 解決策
 ## 問題の理解

 各入力行は、分数、加算、減算、括弧から構成される算術式です。 式に現れる分数は、0 ～ 100 の分子と 1 ～ 20 の正の分母を持ちます。括弧は任意にネストできるため、次のような式になります。`1/2-(3/4-(1/5+1/10))`有効です。 

すべての式について、その正確な有理値が必要であり、その値を分母が正の約分数として出力する必要があります。 入力に現れるすべての分数の分子が負でない場合でも、結果自体が負になる場合があります。 

すべての入力行の合計文字数は最大で次のとおりです。`2 * 10^5`。 二次アルゴリズムは大まかに検査できるため、この境界では式を繰り返し再スキャンするアルゴリズムは除外されます。`2 * 10^10`最悪の場合の文字。 リニア スキャンが自然なターゲットです。 個々の分母は最大 20 であり、これにより、単に小さな入力トークンを持つよりもはるかに強力な特性が得られます。つまり、すべての分母が 1 つの固定された小さな公分母、つまり次の最小公倍数を割ります。`1, 2, ..., 20`。 

いくつかの特殊なケースでは、不注意な実装が失敗する可能性があります。 のために`1/5-2/10`、正しい結果は次のとおりです`0/1`。 減らない分母を維持すると、次のような結果が得られます。`0/10`、これは必要な既約表現を満たしていません。 

のために`1/2-(1/2-2/1)`、正しい結果は次のとおりです`2/1`。 左括弧の前にある記号を記憶せずに括弧を通常のグループ化として扱うパーサーは、式を誤って次のように評価する可能性があります。`-2/1`または`-1/1`。 

のために`1/2-3/2`、結果は`-1/1`。 すべての入力分数が非負であるため、最終分子が非負でなければならないと想定する実装は、ここで失敗します。 この制限は、式の値ではなく、入力の小数部に適用されます。 

のために`100/20`、結果は`5/1`。 分母の境界は包括的であるため、パーサーは誤って 19 を最大の分母として扱うのではなく、20 を受け入れる必要があります。 

## アプローチ

 単純な総当りのソリューションでは、最も内側の括弧で囲まれた式を繰り返し見つけて評価し、式全体をその結果の小数で置き換え、括弧がなくなるまで継続することができます。 選択された括弧内の式は周囲の式から独立しているため、各置換は数学的に正しいです。 

問題は繰り返しスキャンすることです。 ネストされた括弧の長いチェーンを含む式を考えてみましょう。 最初の検索では文字列のほぼ全体がスキャンされ、次の検索では短縮された文字列のほぼ全体がスキャンされます。 と`n`これに必要な文字数`Theta(n^2)`性格検査。 で`n = 2 * 10^5`、チェーンは大まかに次のような結果を引き起こす可能性があります`n^2 / 2`、 その周り`2 * 10^10`これは、1 秒のソリューションで実現できる範囲をはるかに超えています。 

再帰パーサーは、式のすべての部分を 1 回評価できるため、すでにはるかに優れています。 ただし、有効な式には次のようなものが含まれる可能性があるため、Python の再帰はここでは安全ではありません。`2 * 10^5`ネストされた括弧。 評価状態をスタック上に明示的に保持することで、再帰を完全に回避できます。 

便利な算術簡略化もあります。 すべての入力分母は 1 ～ 20 であるため、すべての分母は割り算されます。`L = lcm(1, 2, ..., 20) = 232792560`。 

すべての分数を個別の分子と分母として保存する代わりに、すべての入力分数を変換します。`a/b`整数に入れる`a * (L / b)`。 

この整数は、元の分数を乗算したものを表します。`L`。 加算と減算は線形であるため、整数の加算と減算のみを使用して式全体を評価できます。 括弧は、どの累積整数が符号を受け取るかにのみ影響するため、スタックで処理できます。 

完全な式が評価された後、スケーリングされた結果が次のようになったとします。`x`。 実際の値は`x/L`。 分割する`x`そして`L`それらの最大公約数により、必要な既約分数が得られます。 

ブルートフォース手法では同じ文字を繰り返し再利用しますが、最適手法では各文字を 1 回処理し、最後まですべての端数削減を延期します。

 ## アルゴリズムのチュートリアル

 1.セット`L = 232792560`、すべての可能な入力分母の最小公倍数。 すべての分数`a/b`整数として表すことができます`a * (L/b)`、その値はまさにその整数を で割ったものであるため、`L`。 
2. 式を左から右にスキャンします。 維持する`value`、現在の式の値 (単位:`1/L`、 そして`sign`、どちらかです`1`または`-1`そして、次の分数をどのように加算するかを教えてくれます。 
3. 分数が始まると、その分子と分母を文字列から直接読み取ります。 を使用して公分母に変換します。`numerator * (L // denominator)`を追加します。`sign * scaled_fraction`に`value`。 浮動小数点演算は必要ないので、丸め誤差はありません。 
4.`+`遭遇、設定`sign`に`1`。 とき`-`遭遇、設定`sign`に`-1`。 符号は次の項に属し、分数または括弧で囲まれた式全体のいずれかになります。 
5. いつ`(`が発生した場合は、電流を押します`value`そして`sign`スタック上に。 次に、括弧内で新しい式を開始します。`value = 0`そして`sign = 1`。 内部式全体の前に次の記号が付いている可能性があるため、保存された記号が必要です。`+`または`-`。 
6. いつ`)`が発生すると、内部式が終了します。 保存されている外側の値と外側の符号をポップします。 内部結果が次の場合`inner`、外側の状態を次のように置き換えます。`outer_value + outer_sign * inner`。 これにより、文法の要求どおりに、括弧で囲まれた式全体が 1 つの用語として扱われます。 
7. スキャンが完了すると、式に値が入ります。`value / L`。 コンピューティング`g = gcd(abs(value), L)`そして印刷する`value // g`以上`L // g`。 gcd で絶対値を使用すると、負の結果も正しく処理されます。 

### なぜ効果があるのか

 不変条件は、スキャンのすべての点で、`value / L`は、現在の式のすでに使用されている部分の値です。 の`sign`変数は、次の項への適用を待機している演算子を表します。 括弧を開くと完全な外部状態が保存され、独立した内部式が開始されます。 これを閉じるとその状態が復元され、評価された内部式が左括弧の前にある符号を正確に付けて追加されます。 すべての分数は同じ分母に変換されるため、`L`、すべての加算と減算では、次のように表される正確な値が保持されます。`value / L`。 最後に減らすのは、`value/L`gcd によって変更されるのは表現のみであり、数学的な値は変更されないため、出力された分数はまさに必要な答えとなります。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

L = 232792560

def evaluate(s):
    n = len(s)
    i = 0

    value = 0
    sign = 1

    # Each stack entry stores:
    # (value before '(', sign that preceded '(')
    stack = []

    while i < n:
        c = s[i]

        if c.isdigit():
            numerator = 0
            while i < n and s[i].isdigit():
                numerator = numerator * 10 + (ord(s[i]) - ord('0'))
                i += 1

            # Skip '/'
            i += 1

            denominator = 0
            while i < n and s[i].isdigit():
                denominator = denominator * 10 + (ord(s[i]) - ord('0'))
                i += 1

            scaled = numerator * (L // denominator)
            value += sign * scaled

        elif c == '+':
            sign = 1
            i += 1

        elif c == '-':
            sign = -1
            i += 1

        elif c == '(':
            stack.append((value, sign))
            value = 0
            sign = 1
            i += 1

        else:  # ')'
            outer_value, outer_sign = stack.pop()
            value = outer_value + outer_sign * value
            i += 1

    g = gcd(abs(value), L)
    return f"{value // g}/{L // g}"

def main():
    out = []

    for line in sys.stdin:
        s = line.strip()
        if s:
            out.append(evaluate(s))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```定数`L`中心的な算術最適化です。 すべての分母は最大 20 であるため、次の最小公倍数を割ります。`1`を通して`20`。 例えば、`1/6`になる`L/6`単位、一方`3/10`になる`3L/10`単位。 両方ともまったく同じ分母を使用する整数になりました`L`。 

パーサーはスキップする前に完全な分子を読み取ります。`/`、分母を読み取ります。 入力文法には単項マイナスがないため、マイナス記号は常に 2 つの有効な式の間の演算子として機能します。 

スタックには、開き括弧ごとに 2 つの値が格納されます。 1 つ目は括弧の前で計算されたすべてのもので、2 つ目は括弧で囲まれた式を待っていた符号です。 リセットする`value`ゼロに設定すると、内部式に独自のアキュムレータが与えられます。 

右括弧が処理されるとき、その中の式はすでに完全に評価されています。 ライン`value = outer_value + outer_sign * value`は、まさに周囲のコンテキストによって表される数学的演算です。 この操作の後、パーサーは通常どおり続行できます。 

Python の整数には任意の精度があるため、オーバーフローのリスクはありません。 さらに重要なことは、共通分母が固定されているため、累積分子が控えめなままであることです。 多くてもあります`O(n)`分数、それぞれが最大で寄与する`100L`、大きさが最大で分子を与える`O(nL)`、すべての入力分母の巨大な積ではありません。 

最終的な gcd は使用します`abs(value)`なぜなら`value`マイナスになることもあります。 もし`value`ゼロです、`gcd(0, L)`は`L`、結果は自動的に次のようになります`0/1`。

    value = 0

            sign = 1
            i += 1

            i += 1

            sign = 1
            i += 1

            value = outer_value + outer_sign * value
            i += 1

    old_stdin = sys.stdin
    try:
        sys.stdin = io.StringIO(inp)
        return "\n".join(
            evaluate(line.strip())
            for line in sys.stdin
            if line.strip()

    finally:

 ## 特殊なケース

 表現`1/5-2/10`テストをゼロに削減します。 両方の分数は分母付きの整数になります`L`、そしてそれらのスケーリングされた値が等しいため、アキュムレータはゼロになります。 最終的な gcd は`gcd(0, L) = L`、生産`0/1`減っていないものではなく`0/L`。 

表現`1/2-(1/2-2/1)`括弧で囲まれた式全体に付加された符号をテストします。 括弧に入る前に、スタックには外側の値が格納されます。`L/2`そしてサインしてください`-1`。 内部式は次のように評価されます。`L/2 - 2L = -3L/2`。 括弧を閉じると外側の状態が復元され、計算が行われます。`L/2 - (-3L/2) = 2L`、これは次のようになります。`2/1`。 同じメカニズムが、どのようなネストの深さでも機能します。 

表現`1/2-3/2`生成する`-1/1`。 アキュムレータは単純に次のようになります。`L/2 - 3L/2 = -L`、そして gcd リダクションでは分子の負の符号が保持されます。 否定的な表現に対する特別なケースは必要ありません。 

表現`100/20`最大許容値を直接チェックします。 以来`20`分割する`L`、スケーリングされた分数は`100 * (L/20) = 5L`、そして最終的な還元は次のようになります`5/1`。 変換`L // denominator`許可された分母はすべて の約数であるため、これは正確です。`L`。 

次のような深くネストされた式`1/1-(1/1-(1/1-(1/1)))`また、Python で再帰的解析よりも明示的なスタックが望ましい理由も示します。 各開き括弧は定数サイズのスタック エントリを 1 つ追加し、各閉じ括弧はそれを削除します。 パーサーは Python 呼び出しスタックに依存しないため、非常に深いネストを持つ有効な式であっても安全です。 

最後に、多くの分数から作成された非常に長い式で、実際の入力境界をテストします。 パーサーは式の再構築や再スキャンを繰り返し行わないため、その作業量は入力文字数に直接比例して増加します。 また、共通分母が固定されているため、評価中に分数の分母が大きくなるのを防ぎ、限界付近でも算術効率を維持します。`2 * 10^5`文字数制限。
