 ## 解決策
 ## 問題の理解

 私たちには (n) 個の発光体があり、それぞれは地球からの距離と地球の周りの角度位置によって記述されます。 天文台は、([x,x+d]) と書かれる任意の長さ (d) の半径間隔と、([\omega,\omega+\alpha]) と書かれる任意の長さ (\alpha) の角度間隔を選択できます。 角度座標は円形であるため、区間は (360^\circ) と交差し、(0^\circ) から継続することができます。 

タスクは、距離と角度が同時にその内側にある物体の数ができるだけ多くなるように、両方の間隔を選択することです。 答えは、捕獲された遺体の最大数です。 

入力には最大 (10^5) 個の物体が含まれ、距離は最大 (10^5) の整数で、すべての角度と (\alpha) は小数点以下 2 桁までです。 (10^5) 境界では、ボディのすべてのペアのチェックが除外されます。これは、(O(n^2)) アルゴリズムが最悪の場合に約 (10^{10}) 個の演算を実行するためです。 (O(n\log n)) に関する解決策は、2 秒の制限に適しています。 

角度の小数点以下 2 桁は、別の有用な境界を与えます。 すべての角度を (100) 倍すると、関連するすべての角度は (0) から (35999) までの整数になります。 これにより、サイズが (n) に依存する構造を構築する代わりに、可能な角度位置 (36000) のみに対してセグメント ツリーを使用できるようになります。 

最初の境界ケースは (\alpha=0) です。 例えば、```
1 10 0.00
5 20.00
```の答えは (1) です。長さがゼロの角度間隔でも、選択した角度で​​正確に物体を含めることができるからです。 長さゼロを空の間隔として扱う実装では、誤って (0) が返されます。 

2 番目の境界ケースは、角度区間の交差 (360^\circ) です。 例えば、```
2 10 20.00
5 350.00
5 10.00
```答えは(2)です。 角度間隔 ([350^\circ,10^\circ]) を選択すると、両方の物体がキャプチャされます。 線形、非循環間隔の実装では、そのうちの 1 つが欠落します。 

3 番目の境界ケースは包括性です。 例えば、```
2 10 10.00
1 0.00
11 10.00
```距離の端点と角度の端点の両方が含まれるため、答えは (2) になります。 (r > x) や (\theta < \omega+\alpha) などの厳密な比較では、端点上に正確に存在する本体が失われます。 

最後に、重複する位置はすべてカウントする必要があります。 例えば、```
3 5 0.00
10 25.00
10 25.00
10 25.00
```答えは(3)です。 ボディは、座標が同一であっても個別であるため、データ構造は入力ボディごとに 1 回の更新を実行する必要があります。 

## アプローチ

 直接的なアプローチは、可能なすべての半径方向の間隔とすべての可能な角度の間隔を列挙することです。 最初の部分をわずかに減らすことができます。最適な放射状間隔は、その右端点が何らかの物体の距離に達するまで移動できるため、関連する放射状ウィンドウは (n) のみであることがわかります。 ただし、そのようなウィンドウごとに、考えられるすべての角度の開始点または角度の終点のすべてのペアをチェックするには、依然として (O(n)) の作業がかかります。 最悪の場合、これは (n=10^5) に対して (10^{10}) 回程度の本体レベルの操作 (O(n^2)) となり、制限時間を大幅に超えます。 

キャプチャされたすべてのセットは 1 つの半径方向の間隔と 1 つの角度の間隔によって定義され、関連するすべての選択肢を試すと、最終的には最適なペアが検査されるため、強引な方法は正しいです。 問題は、半径方向の変更のたびに角度の問題が最初から再計算されることです。 

重要な観察は、半径方向の間隔をスイープできることです。 距離によって物体を並べ替え、その距離が現在のウィンドウ ([r-d,r]) に属する物体を正確に維持します。ここで、(r) は現在の右端の物体の距離です。 次の死体に移動すると、いくつかの死体がウィンドウに入り、いくつかの死体が窓から出ます。 各ボディは 1 回挿入され、1 回取り外されます。 

私たちは動的な角度に関する質問に答える必要があります。現在アクティブな物体の中で、長さ (\alpha) の角度間隔に含まれる最大数はいくつですか?

 すべての入力角度には小数点以下 2 桁があるため、角度を (100) でスケールします。 可能な 100 度の位置は (36000) のみです。 開始可能な各間隔でボディの数を直接保存するのではなく、1 つのボディが何に貢献しているかを考えてください。 

物体に角度 (\theta) があるとします。 (s) で始まる角度間隔は、正確にそれを捕捉します。 

[
 s \leq \theta \leq s+\alpha
 ]

 サークル上で。 並べ替えると

 [
 \theta-\alpha \leq s \leq \theta。 
]

 したがって、可能な間隔開始の観点から、1 つの物体は (\theta-\alpha) から (\theta) までの開始の円形範囲に (+1) 寄与します。 したがって、ボディの追加は循環範囲の追加であり、ボディの削除は循環範囲の減算です。 

セグメント ツリーは、範囲の加算と配列全体の最大値 (O(\log 36000)) をサポートできます。 そのルートには、現在アクティブな放射状ウィンドウの最適な角度間隔が常に保存されます。 これを距離スイープと組み合わせると、(O(n\log n+n\log 36000)) アルゴリズムが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n\log n+n\log 36000)) | (O(n+36000)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての角度と (\alpha) に (100) を掛けて、入力を正確な整数に変換します。 これにより、(10.00) と (10.01) などの境界での浮動小数点比較が回避されます。 
2. すべての物体を距離に基づいて並べ替えます。 これらを距離の増加順に処理し、現在のボディの距離をアクティブな放射状ウィンドウの右端点として使用します。 
3. (36000) 個の葉を持つセグメント ツリーを構築します。 リーフ (s) は、スケーリングされた角度 (s) で開始する角度間隔の選択を表します。 アクティブなボディがないため、最初はすべてのリーフにゼロが含まれます。 
4. スケールされた角度 (\theta) を持つボディがアクティブになると、円形の間隔 ([\theta-\alpha,\theta]) 内のすべての可能な開始点に (1) を追加します。 このような開始のたびにこのボディがキャプチャされるため、これらの値を正確に増やすと、影響を受ける角度間隔ごとにキャプチャ カウントが更新されます。 
5. 更新間隔がゼロを超える場合は、更新間隔を 2 つの通常の範囲に分割します。1 つは (35999) で終わり、もう 1 つはゼロで始まります。 ゼロを超えない場合は、通常の範囲更新を 1 回行うだけで十分です。 
6. 現在のボディを挿入した後、距離が (r-d) より小さいすべてのボディを削除します。ここで (r) は現在のボディの距離です。 半径方向の間隔が閉じているため、厳密な不等式は意図的に行われており、正確に (r-d) の位置にある物体はアクティブなままでなければなりません。 
7. セグメント ツリーのルートに保存されている最大値を読み取り、グローバル応答を更新します。 ルートは、現在の放射状ウィンドウのすべての開始点の中で最適な角度間隔を表します。 
8. すべてのボディを続けます。 すべての最適な放射状間隔は、その右端点が捕捉された天体のいずれかの距離に達するまでシフトできるため、これらのスイープ位置の 1 つが最適な放射状の選択を表します。 

### なぜ効果があるのか

 すべてのスイープ位置で、アクティブ セットは、距離が閉じた区間 ([r-d,r]) 内にある物体のセットとなります。 この固定動径セットの場合、セグメント ツリーのリーフに格納される値 (s) は、角度が円区間 ([s,s+\alpha]) 内にあるアクティブ ボディの数と正確に一致します。 これは、すべてのアクティブ ボディが、それをキャプチャするスタートに正確に 1 つの範囲更新に寄与するため、当てはまります。 したがって、セグメント ツリーのルートは、任意の角度間隔でキャプチャされたアクティブ ボディの最大数になります。 

半径間隔と角度間隔の最適なペアを検討します。 最適な放射間隔に少なくとも 1 つの物体が含まれている場合は、その右の端点がキャプチャされた最も遠い物体の距離に達するまで右に移動します。 この移動中にキャプチャされたボディが失われることはないため、右の終点が処理された距離の 1 つである同様に優れたソリューションが存在します。 そのスイープ位置で、セグメント ツリーはすべての可能な角度開始を考慮し、その半径の選択に対して可能な最大数を正確に捕捉する角度間隔を見つけます。 したがって、アルゴリズムは、少なくとも大域的最適値と同じくらい良好な解を検査しますが、計算された値は、有効な間隔のペアによって取得される数値を超えることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

ANGLE_COUNT = 36000
INF = 10**30

def parse_scaled(s):
    if '.' in s:
        whole, frac = s.split('.')
        frac = (frac + '00')[:2]
    else:
        whole, frac = s, '00'
    return int(whole) * 100 + int(frac)

class SegmentTree:
    def __init__(self, n):
        size = 1
        while size < n:
            size <<= 1
        self.size = size
        self.mx = [0] * (2 * size)
        self.lazy = [0] * (2 * size)

    def _apply(self, node, value):
        self.mx[node] += value
        self.lazy[node] += value

    def _push(self, node):
        value = self.lazy[node]
        if value:
            self._apply(node * 2, value)
            self._apply(node * 2 + 1, value)
            self.lazy[node] = 0

    def _add(self, node, left, right, ql, qr, value):
        if ql <= left and right <= qr:
            self._apply(node, value)
            return

        self._push(node)
        mid = (left + right) // 2

        if ql <= mid:
            self._add(node * 2, left, mid, ql, qr, value)
        if qr > mid:
            self._add(node * 2 + 1, mid + 1, right, ql, qr, value)

        self.mx[node] = max(self.mx[node * 2], self.mx[node * 2 + 1])

    def add(self, left, right, value):
        if left > right:
            return
        self._add(1, 0, self.size - 1, left, right, value)

    def maximum(self):
        return self.mx[1]

def solve():
    n, d, alpha_text = input().split()
    n = int(n)
    d = int(d)
    alpha = parse_scaled(alpha_text)

    points = []

    for _ in range(n):
        r_text, angle_text = input().split()
        r = int(r_text)
        angle = parse_scaled(angle_text)
        points.append((r, angle))

    points.sort()

    seg = SegmentTree(ANGLE_COUNT)

    def update_angle(theta, delta):
        if alpha == 0:
            seg.add(theta, theta, delta)
            return

        left = theta - alpha

        while left < 0:
            left += ANGLE_COUNT

        if left <= theta:
            seg.add(left, theta, delta)
        else:
            seg.add(left, ANGLE_COUNT - 1, delta)
            seg.add(0, theta, delta)

    left = 0
    answer = 0

    for right in range(n):
        r, theta = points[right]

        update_angle(theta, 1)

        while points[left][0] < r - d:
            old_theta = points[left][1]
            update_angle(old_theta, -1)
            left += 1

        answer = max(answer, seg.maximum())

    print(answer)

if __name__ == "__main__":
    solve()
```最初の解析の詳細は意図的に行われます。 Python の浮動小数点値は角度比較に使用しないでください。次のような 10 進数値が使用されるためです。`0.01`一般に、バイナリ浮動小数点では正確に表現されません。 入力には小数点以下 2 桁までがあるため、(100) を乗算すると正確な整数表現が得られます。 

の`points`配列は距離によってソートされ、スイープに 1 次元構造が与えられます。 ポインタ`left`常に、現在の放射状ウィンドウ内にまだある最初のボディをマークします。 

機能`update_angle`可能な角度開始に対する 1 つのボディの寄与を実装します。 斜めのボディの場合`theta`、有効な開始範囲は次のとおりです`theta - alpha`を通して`theta`。 この範囲がゼロの周りをラップする場合、それは 2 つのセグメント ツリーの更新によって表されます。 

特別な場合`alpha == 0`独自のブランチに値します。 有効な開始は正確に次のようになります`theta`したがって、更新は誤って大きなラップ間隔を作成するのではなく、1 つのリーフに影響を与える必要があります。 

解除条件は、`points[left][0] < r - d`。 まさに体`r-d`閉じた放射状区間に属しているため、削除してはなりません。 両方のエンドポイントが更新されるため、同じ包括的な解釈が角度範囲の更新にすでに組み込まれています。 

セグメント ツリーには、各ノードの遅延値が格納されます。 範囲更新は、そのノード全体の最大値を同じ量だけ変更するため、すべてのリーフに下降することなく適用できます。 したがって、ルートは、挿入と削除のたびに最適な角度間隔を提供します。 

Python では整数オーバーフローの懸念はありません。 固定幅言語では、最大カウントは (10^5) のみであるため、保存されるカウントには 32 ビットの符号付き整数ですでに十分です。

 ## 特殊なケース

 角度幅がゼロの場合は、次のように考慮します。```
1 1 0.00
1 0.00
```スケーリングされた角度幅はゼロです。 本体のみを挿入すると、`update`(0^\circ) を表す葉を正確に変更します。 セグメント ツリーの最大値は (1) になるため、アルゴリズムは (1) を返します。 正の長さの区間が誤って作成されることはありません。 

円形のラッピングの場合は、```
2 10 20.00
5 350.00
5 10.00
```最初のボディの場合、有効な開始間隔は (330^\circ) から (350^\circ) までです。 2 番目のボディの場合、それらの範囲は (350^\circ) から (10^\circ) までで、ゼロと交差します。 更新は範囲 ([350^\circ,359.99^\circ]) と ([0^\circ,10^\circ]) に分割されます。 したがって、(350^\circ) での開始は両方の寄与を受け取り、最大 (2) になります。 

包括的な距離の境界については、次の点を考慮してください。```
2 10 10.00
1 0.00
11 10.00
```現在の右距離が (11) の場合、放射状ウィンドウは ([1,11]) になります。 削除条件は、距離が厳密に (1) より小さいかどうかをチェックするため、距離 (1) にあるボディはアクティブのままになります。 両方の物体が角度間隔の端点に位置することもあるため、セグメント ツリーは両方をカウントして (2) を返します。 

ボディが重複している場合は、次の点を考慮してください。```
3 5 0.00
10 25.00
10 25.00
10 25.00
```3 つの更新すべてが同じリーフを対象としている場合でも、各入力行によって個別の範囲更新が行われます。 葉の値は (3) になり、その座標にある 3 つの異なる発光体を表します。 結果的には(3)となります。 

同じロジックで (\alpha=359.99) を処理します。 ボディは、幅 (0.01^\circ) の小さな相補角度間隔を除いて、すべての可能な開始に寄与します。 セグメント ツリーはすべて (36000) の 100 度の開始点を明示的に表すため、この極値では近似や浮動小数点の曖昧さはありません。
