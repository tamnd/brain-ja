 ## 解決策
 ## 問題の理解

 スペースを含まない 1 つのテキスト文字列が与えられます。 タスクは、文字がすべて 10 進数である文字列の最長のプレフィックスを見つけることです。 プレフィックスは空であってはなりません。 一番最初の文字が数字でない場合は、有効な接頭辞が存在しないため、次のように表示されます。`-1`。 

たとえば、`23082019UNAL`、頭文字`23082019`は数字、次の文字は`U`そうではありません。 結果的に答えは`23082019`。 で`ABC123`、最初の文字はすでに数字のみの条件を破っているため、答えは次のようになります。`-1`。 

文字列には最大でも次の内容が含まれます`2 * 10^5`文字。 このサイズは十分に大きいため、特に 1 秒の時間制限の下では、二次アルゴリズムは不適切です。 おおよそのパフォーマンスを発揮するソリューション`n^2`文字チェックは約に達する可能性があります`4 * 10^10`制限をはるかに超えた最大長での操作。 基本的に文字列を 1 回検査する必要があります。`O(n)`解決。 

単純な実装が失敗する原因となる可能性のある境界ケースがいくつかあります。 入力が`7`、文字列全体が有効な数値プレフィックスであるため、出力は次のようになります。`7`。 数字以外の終端記号を期待する実装では、このケースが誤って見逃されてしまいます。 

入力が`A123`、正しい出力は次のとおりです。`-1`有効なプレフィックスは最初の文字で始まる必要があるためです。 一連の数字を検索する不注意なソリューションでは、誤った結果が返される可能性があります。`123`。 

入力が`123A456`、答えは`123`、 ない`123456`。 最初の非数字が出現すると、それ以降の文字は必要なプレフィックスに属することができなくなります。 

入力が`0000X`、答えは`0000`。 プレフィックスは整数ではなく文字列であるため、先頭のゼロは保持する必要があります。 印刷前にプレフィックスを整数に変換すると、誤って生成される`0`。 

## アプローチ

 直接的な総当たりアプローチでは、考えられるすべてのプレフィックスを考慮し、そのプレフィックス内のすべての文字が数字であるかどうかを確認できます。 ある長さの文字列の場合`n`、 がある`n`空でないプレフィックスの可能性があります。 位置で終わるプレフィックスをチェックすると`i`毎回最初から、文字検査の合計数は`1 + 2 + 3 + ... + n = n(n + 1)/2`。 

で`n = 200000`、これについてです`2 * 10^10`検査。 ブルート フォース手法は、有効なプレフィックスの定義を明示的に検証するため、論理的には正しいですが、すでに数字であることがわかっている文字を繰り返しチェックします。 

問題の構造から、はるかに簡単な観察が得られます。 接頭辞は、最初から出現するすべての文字が数字である限り有効です。 最初の数字以外の文字は、回答を完全に終了します。 プレフィックスは文字をスキップできないため、以前の文字に到達した後で再考する必要はありません。 

これにより、左から右に 1 回スキャンできます。 各位置で、文字が数字の場合は続行します。 最初の非数字の位置で停止し、その位置より前のすべてを出力します。 スキャンが最後まで到達すると、文字列全体が答えになります。 これにより、作業が二次関数から線形関数に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列全体を読み取り、末尾の改行を削除します。 先頭のゼロは必要な出力の一部であるため、数値に変換せずに文字列として保持します。 
2. 最初の文字から文字列の末尾に向かってスキャンを開始します。 このスキャンは、これまでに数字のみが含まれていることが確認されている最長のプレフィックスを表します。 
3. 現在の文字が数字の場合、スキャンを続けます。 現在の位置より前のすべての文字はすでに検証されているため、プレフィックスを別の桁で拡張することは有効なままです。 
4. 現在の文字が数字でない場合は、すぐに停止し、この位置の前の部分文字列を出力します。 これより長いプレフィックスには同じ非数字文字が含まれるため、これが可能な最長の答えになります。 
5. 数字以外の文字列が見つからずにスキャンが終了した場合は、文字列全体を出力します。 すべての文字は数字として検証されているため、完全な文字列が最も長い有効なプレフィックスとなります。 
6. 最初の文字が数字以外の場合、停止位置はゼロで、その前の接頭辞は空になります。 この問題には空ではない接頭辞が必要なので、次のように出力します。`-1`その代わり。 

### なぜ効果があるのか

 位置の前の不変条件を維持します`i`、接頭辞のすべての文字`T[0:i]`は数字です。 もし`T[i]`も数字であるため、接頭辞を拡張すると不変式が保持されます。 もし`T[i]`は数字ではありません。すべてのプレフィックスは次の値より長くなります`T[0:i]`含まれています`T[i]`したがって、これらのプレフィックスはどれも有効ではありません。 したがって、最初の非数字の位置によって、最長の数値プレフィックスが一意に決まります。 そのような位置が存在しない場合、すべての文字が数字となり、文字列全体が答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    for i, ch in enumerate(s):
        if not ch.isdigit():
            if i == 0:
                print(-1)
            else:
                print(s[:i])
            return

    print(s)

if __name__ == "__main__":
    solve()
```入力行は 1 回読み取られ、`strip()`標準入力によって追加された改行を削除します。 文字列自体は整数に変換されることはなく、次のような先行ゼロが保持されます。`000123`。 

ループは文字を元の順序で検査します。 出来るだけ早く`isdigit()`false を返す場合、ループは数値プレフィックスとテキストの残りの部分の間の正確な境界を見つけました。 スライス`s[:i]`には、その境界より前の文字が正確に含まれます。 

の`i == 0`check は空ではない要件を処理します。 最初の文字が数字でない場合は、`s[:0]`空の文字列になるため、必要な出力は次のようになります。`-1`その代わり。 

ソリューションには整数演算がないため、整数のオーバーフローは無関係です。 重要な唯一の境界は、最初の無効な文字がインデックス 0 に出現するか、中間のどこかに出現するか、またはまったく出現しないかどうかです。

## テストケース```python
import sys
import io

def solve_string(s: str) -> str:
    for i, ch in enumerate(s):
        if not ch.isdigit():
            return "-1" if i == 0 else s[:i]
    return s

def run(inp: str) -> str:
    return solve_string(inp.strip())

# Provided samples
assert run("23082019UNAL") == "23082019", "sample 1"
assert run("UNAL") == "-1", "sample 2"

# Minimum-size inputs
assert run("7") == "7", "single digit"
assert run("A") == "-1", "single non-digit"

# Leading zeroes must be preserved
assert run("0000X") == "0000", "leading zeroes"

# Non-digit immediately after the numeric prefix
assert run("123A456") == "123", "prefix boundary"

# All characters are digits
assert run("999999") == "999999", "all digits"

# Maximum-size input, with the first non-digit at the very end
maximum = "7" * (2 * 10**5 - 1) + "X"
assert run(maximum) == "7" * (2 * 10**5 - 1), "maximum-size input"

# Maximum-size input with no valid prefix
maximum_invalid = "X" + "7" * (2 * 10**5 - 1)
assert run(maximum_invalid) == "-1", "maximum-size invalid prefix"

 ## 特殊なケース

 のために`A123`、アルゴリズムはインデックスを調べます`0`、それがわかります`A`数字ではないため、すぐに戻ります`-1`。 必要なオブジェクトは最初の文字で始まるプレフィックスであるため、それ以降の数値セグメントは検索されません。 

のために`123A456`、インデックス`0`、`1`、 そして`2`受け入れられます。 インデックス時`3`、キャラクター`A`桁テストに失敗したため、アルゴリズムは戻ります`s[:3]`、つまり`123`。 接尾語`456`プレフィックスはスキップできないため、意図的に無視されます。`A`。 

のために`0000X`、すべてのゼロが数字テストに合格し、スキャンは次の時点でのみ停止します。`X`。 返される部分文字列は次のとおりです`0000`、4 つのゼロすべてを保持します。 答えを整数として扱うと、問題で出力する必要がある情報が失われます。 

のために`7`、ループが非数字に遭遇することはありません。 最後に到達し、完全な文字列を返します`7`。 これは、終了する非数字文字がない場合を処理します。 

ある長さの文字列の場合`200000`完全に数字で構成される場合、すべての文字が 1 回処理され、完全な文字列が返されます。 このアルゴリズムには特別な最大長分岐が必要ないため、上部制約は自然に処理されます。 

最初の文字が数字以外で残りの文字が文字列の場合`199999`文字は数字ですが、アルゴリズムは 1 文字の後で停止し、戻ります。`-1`。 これは、答えがテキスト内のその後の数字の存在ではなく、最初の途切れることのない数字の連続にのみ依存する理由を示しています。
