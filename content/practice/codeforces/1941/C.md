 ## 解決策
 ## 問題の理解

 文字列が与えられているので、結果の文字列に次の文字列が含まれないように、最小限の文字を削除したいと考えています。`"pie"`または`"map"`部分文字列として。 

重要な点は、削除は任意の位置で発生する可能性があるということです。 キャラクターを並べ替えるのではなく、一部を削除するだけです。 あらゆる出来事が起こる`"pie"`または`"map"`何らかの形で壊れるはずです。 

すべてのテスト ケースにわたる文字列の長さは次のとおりです。`10^6`、二次関数は即座に除外されます。 アン`O(n^2)`ソリューションは次のように実行されます`10^12`最悪の場合、限界をはるかに超えて動作する可能性があります。 線形時間に近いものが必要です。 

最初の直感は、繰り返し検索することかもしれません。`"pie"`そして`"map"`各出現箇所から 1 文字を削除します。 これはほとんどの場合機能しますが、パターンが重複すると、1 つの削除で 2 つの不正な部分文字列が一度に破壊される可能性があるという注意が必要な状況が発生します。 

古典的な例は次のとおりです。```
mapie
```この文字列には両方が含まれています`"map"`そして`"pie"`:```
mapie
^^^
  ^^^
```不用意に貪欲な解決策を講じると、両方を別々にカウントして答えを返す可能性があります。`2`。 ただし、真ん中の文字を削除すると、`'p'`両方の部分文字列を一度に破棄するため、正しい答えは次のようになります。`1`。 

複数の不良部分文字列が部分的にのみ重なっている場合、別の特殊なケースが発生します。 考慮する：```
mapmap
```二人`"map"`出現は独立しています:```
mapmap
^^^
   ^^^
```1 つの削除で両方の出現を解除することはできないため、答えは次のようになります。`2`。 

非常に短い文字列も重要です。 入力の場合:```
p
```という長さの部分文字列はあり得ません`3`、したがって、答えは次のとおりです`0`。 盲目的にチェックする実装`s[i:i+3]`際限なく処理すると、ここで間違いが発生する可能性があります。 

最後の微妙なケースは、重複が繰り返されることです。```
pppiepieeee
```発生する現象は次のとおりです。```
pppiepieeee
  ^^^
     ^^^
```These do not overlap in a useful way, so we really need two deletions.

 ## アプローチ

 ブルートフォース戦略は、考えられるすべての削除セットを試し、結果の文字列が美しくなるかどうかを確認することです。 これはあらゆる可能性を検討するものであるため、明らかに正しいですが、完全に実行不可能です。 キャラクターごとに残すか削除するかを決めるだけでも、`2^n`可能性。 

より合理的な総当たりの改善策は、文字列を繰り返しスキャンして、`"pie"`そして`"map"`、文字が見つかるたびに 1 文字削除します。 それぞれの不良部分文字列には長さがあるため、`3`、その文字のいずれかを削除すると、その出現は破棄されます。 

問題はオーバーラップの処理です。 貪欲に加工すれば`"map"`まず内側`"mapie"`、削除させていただく場合がございます`'m'`または`'a'`、その後はまだあります`"pie"`残り。 結局、1 つではなく 2 つの削除を使用することになります。 

重要な洞察は、`"map"`そして`"pie"`特別なパターンです:```
mapie
```このパターン内では、1 回の削除で両方の不正な部分文字列を破壊するのに十分です。 具体的には、中央部分を外すと、`'p'`動作します。 

このケース以外では、次のようなことが起こるたびに、`"map"`または`"pie"`少なくとも 1 つの削除を独立して寄与する必要があります。 

したがって、最適な戦略は次のようになります。 

1. 文字列を左から右にスキャンします。 
2. まず次のことを確認します。`"mapie"`現在の位置から開始されます。 
3. 存在する場合は、1 つの削除をカウントし、パターン全体をスキップします。 
4. それ以外の場合は、`"map"`または`"pie"`そこから始まります。 
5. 「はい」の場合、削除を 1 つカウントし、その部分文字列をスキップします。 

これが機能する理由は、`"mapie"`これは、2 つのパターンを個別に処理する場合と比較して、1 回の削除で作業が節約できる唯一の重複部分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 貪欲なリニアスキャン | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 回答カウンターを次のように初期化します。`0`。 

この変数には、必要な削除の最小数が格納されます。 
2. インデックスを使用して文字列を左から右にスキャンします。`i`。 

各位置から始まる部分文字列を調べます。 
3. まず、次で始まる部分文字列が存在するかどうかを確認します。`i`は`"mapie"`。 

これは重大な重複ケースです。 加工すれば`"map"`または`"pie"`まず、誤って 1 つではなく 2 つの削除を使用してしまう可能性があります。 
4. もし`"mapie"`が見つかった場合、答えを増分します`1`そして移動します`i`までに進む`5`。 

1 回の削除で両方の不正な部分文字列が破壊されるため、このブロック内の文字を再検討する必要はありません。 
5. それ以外の場合は、次で始まる部分文字列が存在するかどうかを確認します。`i`は`"map"`または`"pie"`。 

そのような発生ごとに 1 つの削除が必要です。 
6. いずれかの部分文字列が見つかった場合は、答えを増分します。`1`そして移動します`i`までに進む`3`。 

この部分文字列から 1 文字を削除すると、出現全体が無害になります。 
7. 不正な部分文字列が次から始まっていない場合`i`、次の文字に移動します。 
8. スキャンが終了したら、回答を出力します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    s = input().strip()

    ans = 0
    i = 0

    while i < n:
        if i + 4 < n and s[i:i + 5] == "mapie":
            ans += 1
            i += 5
        elif i + 2 < n and (s[i:i + 3] == "map" or s[i:i + 3] == "pie"):
            ans += 1
            i += 3
        else:
            i += 1

    print(ans)
```この実装は、前述した貪欲スキャンの直後に続きます。 

最初の条件でチェックされるのは、`"mapie"`何よりもまず。 その順序が重要です。 確認してみたら`"map"`まず、それから`"mapie"`誤って 2 つの削除としてカウントされる可能性があります。 

境界チェックも重要です。```
i + 4 < n
```それを保証します`s[i:i+5]`チェックには有効です`"mapie"`。 

同様に:```
i + 2 < n
```長さ 3 の部分文字列チェックを保護します。 

スキップして先に進みます`5`または`3`処理された不正な部分文字列に既に属している文字の再処理を回避します。
