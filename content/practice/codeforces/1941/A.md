 ## 解決策
 ## 問題の理解

 この問題により、コインの値の 2 つの配列が得られます。 最初の配列はルドルフの左ポケットのコインを表し、2 番目の配列は右ポケットのコインを表します。 ルドルフは各ポケットからコインを 1 枚だけ選択する必要があります。これは、最初の配列の 1 つの要素と 2 番目の配列の 1 つの要素によって形成されるすべての可能なペアを考慮する必要があることを意味します。 

選択した 2 つのコインの合計が以下の場合、ペアは有効とみなされます。`k`。 タスクは、そのような有効なペアがいくつ存在するかを数えることです。 

より正式には、すべてのインデックスに対して`i`配列内`b`そしてあらゆるインデックス`j`配列内`c`、次の場合はペアをカウントする必要があります。$$b_i + c_j \le k$$各テスト ケースの答えは、単にこの条件を満たすインデックス ペアの数です。 

### 制約分析

 テストケースの数は最大で`100`、両方の配列サイズは次の条件を満たします。$$1 \le n, m \le 100$$これは非常に小さいです。 考えられるすべてのペアをチェックする場合でも、必要なのはせいぜい次のとおりです。$$100 \times 100 = 10{,}000$$テストケースごとの操作。 

すべてのテスト ケースにわたって、ペア チェックの合計数は最大で次のとおりです。$$100 \times 10{,}000 = 1{,}000{,}000$$これは、Python で 1 秒の制限時間内で簡単に管理できます。 

メモリ制限も寛大です。 最大でもサイズの小さい配列を 2 つだけ保存します`100`なので、メモリ使用量は無視できます。 

制約が非常に小さいため、直接の二重ループのソリューションはすでに十分に最適化されています。 高度なデータ構造や並べ替え技術は必要ありません。 

### 明らかではないエッジケース

 #### すべてのペアが無効です

 すべての可能なペアが次の値を超えた場合`k`、答えは次のようになります。`0`。 

例：```
b = [10, 20]
c = [30, 40]
k = 15
```どの金額も大きすぎます。 実装を不注意にすると、比較演算子が間違っているため、誤って何かをカウントしてしまう可能性があります。 

#### すべてのペアが有効です

 すべてのペアが条件を満たす場合、答えは次のようになります。$$n \times m$$例：```
b = [1, 1]
c = [1, 1, 1]
k = 10
```正しい答えは、`6`。 

#### コインの価値が重複しています

 この問題は、個別の値ではなく、インデックスのペアをカウントします。 

例：```
b = [1, 1]
c = [2]
```両方`(0,0)`そして`(1,0)`値が同じであっても、有効な選択肢は異なります。 

重複を削除する間違ったソリューションを使用すると、間違った結果が生成されます。 

#### 最小サイズ

 いつ`n = 1`そして`m = 1`、可能なペアは 1 つだけです。 アルゴリズムは、その単一の合計を正しくチェックする必要があります。 

#### 境界の等価性

 合計が正確に等しいペア`k`有効です。 

例：```
b = [3]
c = [5]
k = 8
```条件は以下を使用します`<=`、 ない`<`。 

厳密な不等式では、有効なペアが誤って拒否されてしまいます。 

## アプローチ

 ### ブルートフォース

 最も直接的なアプローチは、考えられるすべてのコインのペアを試してみることです。 左のポケットにある各コインについて、右のポケットにあるすべてのコインを反復処理して、その合計を計算します。 

合計が以下の場合`k`、答えをインクリメントします。 

このアプローチは、すべての有効な候補ペアを明示的に 1 回だけ検査するため、正しいことが保証されます。 すべてのペアが独立してチェックされるため、有効なペアが見逃されることはなく、無効なペアが誤ってカウントされることもありません。 

通常、配列が大きい場合、すべてのペアに対するブルート フォースが遅くなりすぎる可能性があります。 ただし、ここでは両方の配列のサイズが最大です`100`したがって、テスト ケースごとのチェックの最大数は`10,000`。 これは全く問題ありません。 

したがって、ブルート フォース ソリューションは単純であるだけでなく、特定の制約に対して完全に効率的です。 

### 最適なアプローチ

 重要な観察は、制約が非常に小さいということです。 以来`n`そして`m`それぞれせいぜい`100`、並べ替え、二分探索、または 2 つのポインターは必要ありません。 

単純なネストされたループはすでに制限内で快適に実行されます。 

アルゴリズムは次のように機能します。 

1. 左ポケット内のすべてのコインを繰り返します。 
2. このようなコインごとに、右ポケット内のすべてのコインを反復処理します。 
3. それらの合計が最大かどうかを確認します`k`。 
4. 「はい」の場合、カウンタをインクリメントします。 

これは問題定義と直接一致し、不必要な複雑さを回避します。 

### 比較

 | アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`、`m`、 そして`k`。 
3. 配列を読み取る`b`左ポケットのコインを表します。 
4. 配列を読み取る`c`右ポケットのコインを表します。 
5. カウンタの初期化`ans = 0`。 
6. すべての値を反復処理する`x`で`b`。 
7. それぞれについて`x`、すべての値を反復処理します`y`で`c`。 
8. コンピューティング`x + y`。 合計が以下の場合`k`、増分`ans`。 
9. すべてのペアがチェックされたら、印刷します。`ans`。 

これは、考えられるすべてのペアが 1 回だけ検査されるため機能します。 

## Python ソリューション```
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, m, k = map(int, input().split())

    b = list(map(int, input().split()))
    c = list(map(int, input().split()))

    ans = 0

    for x in b:
        for y in c:
            if x + y <= k:
                ans += 1

    print(ans)
```プログラムはまずテスト ケースの数を読み取ります。 テスト ケースごとに、コイン値の 2 つの配列が保存されます。 

変数`ans`見つかった有効なペアの数を追跡します。 

ネストされたループは、左ポケットのコイン 1 枚と右ポケット 1 枚のコインのあらゆる可能な組み合わせを生成します。 合計が条件を満たすたびに`x + y <= k`、答えは 1 つ増えます。 

最後に、現在のテスト ケースの答えが出力されます。 

重要な実装の詳細は、問題が個別の値ではなくインデックスのペアをカウントすることです。 すべての配列要素を直接反復処理するため、重複した値は自動的に正しく処理されます。
