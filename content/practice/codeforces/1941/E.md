 ## 解決策
 ## 問題の理解

 川の各行は独立して処理できます。 選択した行に沿って、最初と最後の列に常にサポートが含まれるように、いくつかの列にサポートを配置し、隣接する 2 つのサポート間でスキップされるセルの数が最大 2 個になるようにします。`d`。 

柱にサポートを配置する場合`j1`そして`j2`、ギャップ条件は次のとおりです。$$|j_1 - j_2| - 1 \le d$$これは次と同等です。$$|j_1 - j_2| \le d + 1$$柱にサポートを取り付ける`j`費用`a[i][j] + 1`。 

すべての行について、可能な限り最小限のブリッジ コストが必要です。 その後、私たちは選択しなければなりません`k`ブリッジコストの合計が最小となる連続した行。 

この構造は自然に 2 つのサブ問題に分かれます。 

1. 単一行の最適なブリッジ コストを計算します。 
2. 連続するすべてのグループの最小合計を求めます。`k`行。 

制約はソリューションを大きく左右します。 すべてのテスト ケースにわたるセルの合計数は最大で`2 * 10^5`したがって、入力サイズは線形に近いものが期待されます。 列に対する 2 次アルゴリズムは、単一の行に次の内容が含まれる可能性があるため失敗します。`2 * 10^5`列。 平`O(m * d)`危険になるとき`d`大きいです。 

難しいのは、1列での橋の建設です。 不注意で貪欲なアプローチは失敗します。今すぐ近くで最も安価なサポートを選択すると、後で多くの高価なサポートを強いられる可能性があるからです。 

次の行を考えてみましょう。```
0 1 100 1 0
```と`d = 1`。 

列から直接ジャンプすることはできません`1`列へ`5`サポート間の距離により 3 セルがスキップされるためです。 最適なソリューションでは中間サポートを使用する必要があります。 

別の微妙なケースが現れるのは、`d`とても大きいです。 

例：```
0 5 7 2 0
```と`d = 10`。 

最初と最後のサポートだけですでに距離条件を満たしているため、答えは簡単です。```
1 + 1 = 2
```バグのある実装では、依然として不要な中間サポートが強制される可能性があります。 

もう 1 つの簡単なオフバイワン トラップは、距離の定義から生じます。 この問題では、絶対的な列の差ではなく、スキップされたセルとして距離を定義します。 

もし`d = 1`、サポートは最大で異なる場合があります`2`in column index.

 例えば：```
0 4 0
```と`d = 1`。 

柱のサポート`1`そして`3`は、ちょうど 1 つのセルをスキップするため有効です。 

を使用した解決策`|j1 - j2| <= d`はこれを誤って拒否してしまいます。 

## アプローチ

 この強引なアイデアは、単純な動的プログラミングです。 

させて`dp[j]`柱にサポートを配置するための最小コストになります`j`。 それから：$$dp[j] = cost(j) + \min(dp[t])$$どこ`t`接続できる以前のすべてのサポート位置をカバーします。`j`。 

サポートは最大でも異なる可能性があるため、`d + 1`列インデックス内:$$j - (d+1) \le t < j$$すべての列について、すべての有効な以前の列をスキャンし、最小値を取得します。 

それは次のようになります:$$O(m \cdot d)$$1行の時間。 

最悪の場合、`d`できる`m`、これは次のようになります`O(m^2)`。 と`m = 2 * 10^5`、これはまったく不可能です。 

重要な観察は、遷移ではスライディング ウィンドウ内の最小値のみが要求されるということです。 

コラム用`j`、次のものが必要です。$$\min(dp[j-d-1], \dots, dp[j-1])$$として`j`増加すると、この範囲も右にスライドします。 スライディング ウィンドウ最小問題は、まさに単調キューが効率的に解決するものです。 

毎回最小値を再計算する代わりに、増加する候補列を含む両端キューを維持します。`dp`価値観。 フロントには常に最小の有効な値が格納されます。`dp`。 

これにより、行ごとの複雑さが 2 次から線形に軽減されます。 

すべての行の最適なブリッジ コストを計算した後は、第 2 フェーズは簡単です。 最小限の合計が必要です`k`連続行コスト、これもスライディング ウィンドウです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・m・d) | O(m) | 遅すぎる |
 | 最適 | O(n・m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 行ごとに、DP 配列を作成します。`dp[j]`最後に設置されたサポートが列にある場合の最小総コストを表します。`j`。 
2. 最初の列を初期化します。 

最初のサポートは必須であり、そのコストは次のとおりです。$$a[i][1] + 1 = 1$$それで：$$dp[0] = 1$$1. 候補の前の位置を格納する単調デキューを維持します。 

デックにはインデックスが保持されます。`dp`値が増加しています。 フロントには常に最小値が含まれます`dp`現在到達可能な列の間。 
2. 列を左から右に処理します。 

コラム用`j`、インデックスが遠すぎる場合は、先頭からインデックスを削除します。$$idx < j - (d + 1)$$それらのサポートはもう接続できないため、`j`。 

1. 遷移を計算します。 

以前の最良のサポートは deque フロントにあります。$$dp[j] = dp[best] + a[i][j] + 1$$1. 現在の列を両端キューに挿入します。 

背面には`dp`以上の値`dp[j]`、削除します。 現在のポジションは安くて新しいため、そのようなポジションは二度と役に立ちません。 
2.列を終えたら、保管します`dp[m-1]`その行の最小ブリッジコストとして。 
3. すべての行コストがわかったら、次の最小合計を計算します。`k`スライディング ウィンドウを使用した連続行。 
4. 最小のウィンドウ合計を出力します。 

### なぜ効果があるのか

 すべての有効なブリッジが列で終わるため、DP は正しいです。`j`遠くにいる以前のサポートから来ている必要があります`d + 1`。 再発では、そのような可能性をすべてチェックし、最も安価なものを選択します。 

デキューには常に、現在の位置の有効な前の列が正確に含まれており、最小になるように順序付けされています。`dp`先頭に留まります。 無効な位置はすぐに削除され、優勢な位置は後ろから破棄されるため、デクの最小値は常に正確です。 

すべての列が両端キューに出入りするのは最大 1 回であるため、合計作業量は線形のままです。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n, m, k, d = map(int, input().split())
        grid = [list(map(int, input().split())) for _ in range(n)]

        row_costs = []

        for row in grid:
            dp = [0] * m
            dp[0] = 1

            dq = deque([0])

            for j in range(1, m):
                while dq and dq[0] < j - (d + 1):
                    dq.popleft()

                best = dq[0]
                dp[j] = dp[best] + row[j] + 1

                while dq and dp[dq[-1]] >= dp[j]:
                    dq.pop()

                dq.append(j)

            row_costs.append(dp[-1])

        current = sum(row_costs[:k])
        answer = current

        for i in range(k, n):
            current += row_costs[i]
            current -= row_costs[i - k]
            answer = min(answer, current)

        print(answer)

solve()
```最初のフェーズでは、行ごとに最適なブリッジ コストを個別に計算します。`dp[j]`柱にサポートを配置した場合の最小総コストを格納します`j`。 最初の列には常にサポートが含まれている必要があるため、`dp[0] = 1`。 

デキューには、遷移の前の列の候補が格納されます。 処理前カラム`j`、法的に接続するには遠すぎる列を削除します。 

移行:```
dp[j] = dp[best] + row[j] + 1
```到達可能な最小の前の状態を使用します。 

単調特性は次のように維持されます。```
while dq and dp[dq[-1]] >= dp[j]:
    dq.pop()
```これにより、デックが増加し続けます`dp`値を調整するため、前面が常に最適になります。 

微妙な詳細の 1 つは有効性条件です。```
dq[0] < j - (d + 1)
```ブリッジでは最大でもスキップが可能です`d`セル、つまりサポートは最大で異なる可能性があります`d + 1`インデックスで。 

第 2 フェーズでは、行コストに対して標準のスライディング ウィンドウを使用します。 必要なのは連続した行のみであるため、プレフィックス合計またはローリング合計は両方とも機能します。

 ## 特殊なケース

 中間サポートが必要ない場合を考えてみましょう。 

入力：```
1
1 5 1 10
0 9 9 9 0
```最初のサポートは列 1 にあり、最後のサポートは列 5 にあります。それらの差は 4 であるため、スキップされたセルは 3 に等しく、これは範囲内です。`d = 10`。 

DP 中に、列 5 は列 1 から直接遷移できます。その理由は次のとおりです。```
5 - 1 <= d + 1
```アルゴリズムは正しく次の値を返します。```
1 + 1 = 2
```次にオフバイワントラップを考えてみましょう。 

入力：```
1
1 3 1 1
0 100 0
```列 1 と列 3 のサポートはちょうど 1 つのセルをスキップするため、有効です。 

DPウィンドウサイズは`d + 1 = 2`、これによりこの移行が可能になります。 アルゴリズムは以下を計算します。```
1 + 1 = 2
```ウィンドウサイズを使用したバグのある実装`d`高価な中間サポートを誤って強制することになります。 

最後に、貪欲な選択が失敗した場合を考えてみましょう。 

入力：```
1
1 6 1 1
0 1 100 1 100 0
```ローカルの貪欲な戦略では、列 2 で安価なサポートを選択し、その後列 4、最後に列 6 に強制的に入れられる可能性があります。 

代わりに、DP は、到達可能なすべての以前のサポートを評価し、全体的に最適なチェーンを見つけます。 デキューにより、これらの遷移が正確さを失うことなく効率的に処理されることが保証されます。
