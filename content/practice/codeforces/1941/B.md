 ## 解決策
 # 問題の理解

 負ではない整数の配列が与えられます。 1 回の操作でインデックスを選択します$i$そのような$2 \le i \le n-1$、次の方法で 3 つの連続する要素を減らします。$$a_{i-1} \mathrel{-}= 1,\quad a_i \mathrel{-}= 2,\quad a_{i+1} \mathrel{-}= 1$$この操作は、有効なインデックスに対して何度でも使用できます。 目的は、配列全体をすべてゼロにできるかどうかを判断することです。 

重要な点は、すべての操作で値が減算されるだけであるということです。 要素を増やすことは決して許可されません。 したがって、要素がマイナスになると処理は無効になります。 正しい解決策では、負の値を必要とせずに配列を正確にすべてゼロに変換する一連の操作が存在するかどうかを判断する必要があります。 

制約が十分に大きいため、効率が重要になります。 

| 制約 | 意味 |
 | --- | --- |
 |$t \le 10^4$| 多くのテスト ケースを効率的に処理する必要があります。 |
 |$\sum n \le 2 \cdot 10^5$| アン$O(n)$または$O(n \log n)$テストケースごとのソリューションは安全です。 |
 |$a_i \le 10^9$| 操作の数が膨大になると、操作を 1 つずつシミュレートすることはできません。 |
 | 制限時間：2秒 | すべてのテスト ケースにわたる合計作業量は、ほぼ線形にとどまる必要があります。 |
 | メモリ制限: 256 MB | 配列といくつかの補助変数を保存することはまったく問題ありません。 |

 要素が次のような大きさになる可能性があるため、操作を繰り返し適用する単純なシミュレーションは失敗します。$10^9$、数十億の操作につながります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

### 配列はすでにゼロに等しい

 すべての要素がすでにゼロである場合、答えはすぐに「YES」になるはずです。 不注意な実装では、依然として操作を実行しようとして、誤ってケースを拒否する可能性があります。 

### 小さな配列

 最小サイズは$n=3$。 この状況では、中央のインデックスのみを選択できます。 ソリューションでは、操作場所が 1 つだけ存在する配列を正しく処理する必要があります。 

### 貪欲な処理中の負の値

 左から右に値を削除しようとするとします。 ある時点で、必要な操作数が隣接する要素で使用可能な量を超えると、そのうちの 1 つが負になります。 これは、構成が不可能であることを直ちに証明します。 

例えば：$$[1,1,1,1]$$最初の要素を削除するには、インデックス 2 で 1 回の操作が必要ですが、これにより 2 番目の要素が 2 減り、負の値になります。 

### ゼロ以外のテール要素

 左辺が正常にゼロになったとしても、最後の 2 つの要素はゼロ以外のままになる可能性があります。 操作は連続する 3 つの位置に影響するため、左側の処理が完了すると、尾部を個別に修正する方法はありません。 正しいアルゴリズムでは、最終的な配列を明示的に検証する必要があります。 

# アプローチ

 ## ブルートフォース

 簡単なアイデアは、有効な操作を繰り返し検索し、それ以上の操作ができなくなるまで適用することです。 たとえば、任意のインデックスを選択するとします。$i$どこ：$$a_{i-1} \ge 1,\quad a_i \ge 2,\quad a_{i+1} \ge 1$$そして引き算を続けます。 

このアプローチは論理的には正しいです。すべての操作で配列の合計が厳密に減少するため、プロセスは最終的に終了します。 すべてゼロに達した場合、答えは「YES」です。 それ以外の場合は「NO」です。 

問題は効率です。 以下の値を含む配列を考えてみましょう。$10^9$。 手術の数も近くなる可能性があります$10^9$、制限時間内に直接シミュレーションすることは不可能になります。 

したがって、ブルート フォースでは遅すぎるのです。 

## 最適なアプローチ

 重要な観察は、操作構造が自然な左から右への貪欲な戦略を強制するということです。 

現在位置を検討しているとします。$i$。 減らすことができる唯一の操作$a_i$右側の要素には影響を及ぼしますが、操作の中心は次のとおりです。$i+1$。 

つまり、インデックスを越えると$i$、二度と変更できなくなります。 したがって、もし$a_i$その時点で がゼロではない場合、唯一の有効な選択肢は、その時点で演算を適用することです。$i+1$その通り$a_i$回。 

これにより、決定論的なプロセスが作成されます。 

操作を適用すると$x=a_i$センターでの回数$i+1$:$$a_i \mathrel{-}= x$$

$$a_{i+1} \mathrel{-}= 2x$$

$$a_{i+2} \mathrel{-}= x$$以来$x=a_i$、現在の要素はすぐにゼロになります。 

隣接する値のいずれかが負になる場合、有効なシーケンスは存在しません。 

左から右に処理することで、各要素が永久に固定される場合は、貪欲に正確に削除します。 最終的に、すべての要素がゼロであれば、変換は可能です。

 # アルゴリズムのチュートリアル

 1. 配列を読み取ります。 
2. インデックスを左から右に、具体的には$0$に$n-3$。 
3. 各ポジションで$i$、 させて：$$x = a_i$$今後の操作は変更できないため、$a_i$を中心とした操作を除いて$i+1$、今すぐ排除しなければなりません。 
4. 操作を適用する$x$概念的には次のようになります。$$a_i \mathrel{-}= x$$

$$a_{i+1} \mathrel{-}= 2x$$

$$a_{i+2} \mathrel{-}= x$$5. 更新後、次のいずれかを確認します。$$a_{i+1} < 0 \quad \text{or} \quad a_{i+2} < 0$$その場合は「NO」を出力します。 
6. インデックスが作成されるまで処理を続行します$n-3$。 
7. すべての操作が終了したら、すべての要素がゼロに等しいことを確認します。 
8. 配列全体がゼロの場合は、「YES」を出力します。 それ以外の場合は「NO」を出力します。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    possible = True

    for i in range(n - 2):
        x = a[i]

        a[i] -= x
        a[i + 1] -= 2 * x
        a[i + 2] -= x

        if a[i + 1] < 0 or a[i + 2] < 0:
            possible = False
            break

    if possible and all(v == 0 for v in a):
        print("YES")
    else:
        print("NO")
```合計入力サイズが次の値に達する可能性があるため、プログラムは高速 I/O から始まります。$2 \cdot 10^5$。 

各テスト ケースについて、左から右に繰り返します。 位置で`i`、現在の値`a[i]`適用する必要がある操作の数を正確に決定します。 この値を次の場所に保存します`x`。 

更新内容:```
a[i + 1] -= 2 * x
a[i + 2] -= x
```操作の実行をシミュレートする`x`回。 

どちらかの更新値がマイナスになった場合は設定が不可能となるため、早期に終了します。 

最後に、すべての要素が正確にゼロであることを確認します。 使用できる操作がなくなっても、最後の 2 つの要素が正の値のままになる可能性があるため、この最後のチェックは不可欠です。
