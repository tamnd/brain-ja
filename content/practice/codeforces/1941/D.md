 ## 解決策
 ## 問題の理解

 私たちにはサークルがあります`n`1 から 1 までの番号が付けられたプレーヤー`n`時計回りに。 ボールはプレーヤーから始まります`x`。 がある`m`投げるたびに距離がある`r_i`そして思い出した方向性`c_i`。 方向は時計回りにすることができます (`0`)、反時計回り (`1`)、または不明 (`?`）。 結局`m`情報が与えられた場合、ボールを保持できる可能性のあるすべてのプレーヤーを見つける必要があります。 

概念的には、これを円上の一連の位置としてモデル化できます。 最初は、セットには開始プレイヤーのみが含まれます。 投げるたびに、現在の可能な位置を時計回りに移動します。`r_i`、反時計回りに`r_i`、または方向が不明な場合は両方。 最後に、セットには可能なすべての終了位置が含まれます。 

制約は中程度です。`n`そして`m`最大でも 1000 であり、すべての合計`n*m`テスト ケース全体で ≤ 2×10^5 です。 これにより、テスト ケースごとに O(n * m) よりも悪いアルゴリズムが除外されます。 

注意すべきエッジケースには以下のような場合があります。`c_i`は不明です(`?`) すべてのスローに対して、可能なエンド ポジションの数が爆発的に増加する可能性があることを意味します。 もう 1 つの微妙な点は、円周のモジュラー演算です。 プレーヤー番号は 1 から始まるので、距離を加算または減算するときは、正しくラップアラウンドする必要があります。 たとえば、移動する`-1`プレイヤーから`1`プレイヤーの上に着地する`n`、 ない`0`。 同様に移動すると、`+1`から`n`戻って着地する`1`。 

モジュラー算術を忘れた単純な実装では、無効な位置が暗黙的に生成され、`?`誤って有効な可能性を見逃す可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのパスをシミュレートします。 最初のプレーヤーから開始し、スローごとに、方向に従ってすべての新しいポジションを生成します。 投げが不明な場合は、状態を時計回りと反時計回りの動きに分割します。 後`m`スローし、結果として得られるすべてのポジションを収集します。 それは正しいのですが、最悪の場合、`?`投げるたびに、ステップごとにポジションの数が 2 倍になります。 つまり O(2^m * m) ですが、これは次の場合には実行不可能です。`m`は1000までです。 

重要な洞察は、_個別のパス_を追跡する必要がないということです。 ボールの位置のモジュロ`n`時計回りの動きから反時計回りの動きを引いた合計にのみ依存します。 スローの方向が不明な場合は両方の可能性が許容されますが、一連の位置を伝播することで到達可能なすべての位置を計算できます。 具体的には、ブール配列を維持できます。`reachable[1..n]`各投球後にどのポジションが可能かをマークします。 既知の方向ごとに、現在の到達可能な位置をそれに応じて移動します。 のために`?`、時計回りと反時計回りの両方のシフトをマークします。 モジュラー演算とセットの伝播を使用すると、各スローには O(n) 時間がかかり、テスト ケースごとに全体で O(n*m) が得られ、制約に適合します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m * m) | O(2^m) | 遅すぎる |
 | 最適 (伝播/DP の設定) | O(n * m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ブール配列を初期化する`reachable[1..n]`以下を除いてすべて誤りです`reachable[x] = True`、 どこ`x`スターティングプレイヤーです。 これは、現在ボールを保持している可能性のあるプレーヤーを表します。 
2. 各スローを反復処理する`(r_i, c_i)`:

 - 時計回りに投げる場合 (`c_i == '0'`)、現在アクセス可能なプレーヤーごとに新しいブール配列を作成します。`p`、 マーク`(p + r_i - 1) % n + 1`到達可能なものとして。 
- 左投げの場合（`c_i == '1'`）、 マーク`(p - r_i - 1 + n) % n + 1`到達可能なものとして。 
- 不明なスローの場合 (`c_i == '?'`)、時計回りと反時計回りの両方の目的地を到達可能としてマークします。 
3. すべてのスローを処理した後、到達可能としてマークされたすべての位置を収集します。 出力のために昇順に並べ替えます。 
4. 可能な位置の数とソートされたリストを出力します。 

機能する理由: ブール配列不変式により、どのステップでも、`reachable[p]`ボールがプレーヤーのところにある場合にのみ true`p`その瞬間。 両方の遷移を同時に許可することで未知の方向を処理するため、可能な終了位置が省略されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, x = map(int, input().split())
        reachable = [False] * (n + 1)
        reachable[x] = True
        
        for _ in range(m):
            r, c = input().split()
            r = int(r)
            new_reachable = [False] * (n + 1)
            for i in range(1, n + 1):
                if not reachable[i]:
                    continue
                if c == '0' or c == '?':
                    new_pos = (i + r - 1) % n + 1
                    new_reachable[new_pos] = True
                if c == '1' or c == '?':
                    new_pos = (i - r - 1 + n) % n + 1
                    new_reachable[new_pos] = True
            reachable = new_reachable
        
        result = [i for i in range(1, n + 1) if reachable[i]]
        print(len(result))
        print(' '.join(map(str, result)))

if __name__ == "__main__":
    solve()
```実装メモ:`(i + r - 1) % n + 1`時計回りの動きの場合、`(i - r - 1 + n) % n + 1`反時計回りにすると、1 ベースのインデックス付けとモジュラー ラッピングが処理されます。 別個の`new_reachable`配列は、同じステップ内の位置の上書きを回避しますが、これは重要です。
