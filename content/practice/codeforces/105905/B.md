 ## 解決策
 ## 問題の理解

 小文字の文字列が与えられます。 1 回の操作で、現在の文字列の端に関して鏡像である 2 つの文字を削除できます。 つまり、1 つの文字が左から k 番目の文字である場合、もう 1 つの文字は右から k 番目の文字である必要があります。 この操作は、これら 2 つの文字が等しい場合にのみ許可されます。 

ペアを取り外した後、紐の残りの部分を接着します。 任意の数の操作を実行する可能性があるため、最終的な長さを可能な限り最小限に抑える必要があります。 

文字列の長さは次のとおりです。$10^5$これにより、文字列を繰り返し再構築したり、さまざまな操作順序を探索したりするシミュレーションは直ちに除外されます。 アン$O(n^2)$ソリューションはすでに遅すぎるため、単一のリニア スキャンを目指す必要があります。 

微妙な点は、ミラーリングされたペアを 1 つ削除すると現在の文字列が変更されるため、新しい削除の機会が後で現れるかもしれないと考えたくなることです。 不用意に実装すると、操作を動的にシミュレートしようとして、不必要な複雑さが生じる可能性があります。 

次の文字列を考えてみましょう。```
abba
```ミラーリングされたペアは次のとおりです。`(a,a)`そして`(b,b)`。 どちらのペアも削除できるため、答えは次のようになります。```
0
```ここで次のことを考えてみましょう。```
abca
```外側のペア`(a,a)`取り外しも可能ですが、`(b,c)`できません。 最小の長さは次のとおりです。```
2
```もう 1 つの重要な例は次のとおりです。```
abcde
```ミラー化された各ペアには異なる文字が含まれているため、操作は不可能であり、答えは次のようになります。```
5
```重要な観察点は、元のミラーリングされた位置が互いに対応する操作は決して変更されないということです。 それによって解決策が完全に決まります。 

## アプローチ

 ブルートフォースのアイデアは、取り外し可能なミラーリングされたペアを繰り返し検索し、そのうちの 1 つを削除し、文字列を再構築して続行することです。 削除するたびにインデックスが変更されるため、現在の文字列を明示的に維持する必要があります。 最悪の場合、操作のたびに文字列を再構築すると、二次的な動作が発生します。 

画期的な進歩は、文字列をミラーリングされたペアの集合として見ることから生まれます。 

あらゆるポジションについて`i`左半分には、ミラーリングされた位置が 1 つだけあります`n - 1 - i`右半分にあります。 これをミラーリングされたペアと呼びます。 

ミラーリングされたペアに等しい文字が含まれているとします。 その後、そのペアは最終的に削除できます。 

ミラーリングされたペアに異なる文字が含まれているとします。 いずれの操作も削除できません。 その理由は、すべての操作で 1 つの完全なミラー化ペアが削除されるためです。 他のミラーリングされたペアを削除しても、これら 2 つの文字が互いにペアのままであるという事実は変わりません。 

これは、ミラー化された各ペアが完全に独立していることを意味します。 

2 つの文字が等しい場合、両方とも消えます。 

2 つの文字が異なる場合、両方とも永久に残ります。 

奇数長の文字列の場合、中央の文字にはパートナーがなく、削除することはできません。 

したがって、答えは簡単です。```
2 × (number of mismatched mirrored pairs)
+ (1 if the length is odd else 0)
```| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n²) 以上 | O(n) | 遅すぎる |
 | ミラーリングされた不一致をカウントする | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取り、その長さを次のようにします。`n`。 
2. カウンタの初期化`bad = 0`。 
3. インデックスごとに`i`から`0`に`n // 2 - 1`、 比較する：```
s[i]
s[n - 1 - i]
```4. 文字が異なる場合は、インクリメントします。`bad`。 

このようなミラー化されたペアはそれぞれ削除できないため、両方の文字が最終的な文字列に残される必要があります。 
5. すべてのミラーリングされたペアを処理した後、次を計算します。```
answer = 2 * bad + (n % 2)
```用語`2 * bad`不一致のミラーリングされたペアに属するすべての文字をカウントします。 

用語`n % 2`長さが奇数の場合、中央の文字が考慮されます。 
6. 答えを出力します。 

### なぜ効果があるのか

 すべての操作では、文字が等しいミラーリングされたペアを 1 つだけ削除します。 

ミラーリングされたペアを削除しても、残りのミラーリングされたペアのペア関係は変更されません。 として始まったペア`(x, y)`最後までペアのままです。 

そのため、ミラー化されたすべてのペアを個別に分析できます。 

同等のミラーリングされたペアは完全に削除できます。 

等しくないミラーリングされたペアは削除できません。 

奇数長の文字列の中央の文字にはパートナーが存在しないため、常に存続します。 

このアルゴリズムは、考えられるすべての削除後に残すべき文字数 (達成可能な最小長) を正確にカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

bad = 0

for i in range(n // 2):
    if s[i] != s[n - 1 - i]:
        bad += 1

print(2 * bad + (n % 2))
```実装は数学的観察に直接従います。 

ループは文字列の左半分のみを訪問します。 ポジションごとに、キャラクターと右側のミラーリングされたパートナーを比較します。 

すべての不一致は、正確に 2 つの避けられない文字を答えにもたらします。 両方の文字は削除できるため、一致するすべてのペアはゼロになります。 

表現`n % 2`中央の文字を自動的に処理します。 偶数の長さの場合は 0 が寄与し、奇数の長さの場合は 1 が寄与します。 

ループはミラーリングされたペア上を正確に実行し、中心位置に触れることはないため、オフバイワンの問題はありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    s = input().strip()
    n = len(s)

    bad = 0
    for i in range(n // 2):
        if s[i] != s[n - 1 - i]:
            bad += 1

    print(2 * bad + (n % 2))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided samples
assert run("abba\n") == "0\n", "sample 1"
assert run("abcde\n") == "5\n", "sample 2"
assert run("aabaa\n") == "1\n", "sample 3"

# custom cases
assert run("a\n") == "1\n", "single character"
assert run("aa\n") == "0\n", "smallest removable pair"
assert run("ab\n") == "2\n", "single mismatched pair"
assert run("aaaaaa\n") == "0\n", "all equal characters"
assert run("abccba\n") == "0\n", "full palindrome"
assert run("abcdef\n") == "6\n", "all mirrored pairs mismatch"
