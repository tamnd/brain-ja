 ## 解決策
 ## 問題の理解

 この問題は上院議員のグループについて説明しています。 各上院議員には強さの値と現在の忠誠率があります。 投票開始前に、数量限定のキャンディーを配布する場合がございます。 上院議員にキャンディーが与えられるたびに、その上院議員の忠誠心は 10% 増加しますが、100% を超えることはできません。 配布後、各上院議員は最終的な忠誠確率に応じて個別に賛成または反対の投票を行います。 

上院議員の半数以上が私たちに賛成票を投じれば、私たちは直ちに成功します。 そうでない場合は、私たちに反対票を投じた上院議員を正確に排除しようとすることもできます。 グループを排除する可能性は、私たち自身の力と、排除された上院議員の総力に依存します。 最終的な成功確率を最大化するキャンディーの配分を選択する必要があります。 

上院議員の数が少ないため、戦略全体が変わります。 上院議員が最大 8 人であれば、可能な最終的な忠誠構成の総数は管理可能です。 上院議員のサブセットを反復処理するソリューションは現実的ですが、はるかに大きなグループに対して考えられるすべての投票結果を試すソリューションは拡張できません。 

お菓子の数も少ないです。 各キャンディーはロイヤルティ値を 10% ずつ変更するだけであるため、決定は少数の個別のアップグレードを割り当てることとして表すことができます。 考えられるすべてのキャンディー分布の単純なシミュレーションが可能になるのは、入力サイズが小さいためです。 上院議員の数が約 10^5 である場合、線形パスさえも唯一の合理的な方向となり、指数列挙はすぐに失敗します。 

いくつかの特殊なケースは見落とされがちです。 上院議員がすでに 100% の忠誠心を持っている場合、さらにキャンディーを与えても効果はありません。 例えば：```
1 3 20
20 100
```正しい出力は次のとおりです。```
1.0000000000
```すべてのキャンディーを忠誠度の増加として盲目的に扱う不注意な実装では、100 パーセントを超える不可能な確率が発生する可能性があります。 

十分な票が得られず、反対派を排除することに頼らなければならない場合には、別の特殊なケースが発生します。 例えば：```
1 0 10
20 0
```唯一の上院議員はいつも我々に反対票を投じる。 確率的にその上院議員を削除します。```
10 / (10 + 20) = 1 / 3
```したがって、答えは次のとおりです。```
0.3333333333
```過半数の票を獲得できるかどうかだけをチェックするソリューションでは、誤ってゼロが返されてしまいます。 

## アプローチ

 最初のアプローチは、すべてのキャンディーの配布を直接試してみることです。 すべてのキャンディーは上院議員の 1 人に割り当てられるため、各キャンディーの行き先を再帰的に選択できます。 1 つの分布を生成した後、新しい忠誠度を計算し、勝つ確率を評価します。 

キャンディーのあらゆる消費方法が考慮されているため、このアプローチは正しいです。 分布ごとに、考えられるすべての投票マスクを反復処理することで確率を計算できます。 n 人の上院議員の場合、2^n 通りの投票結果が考えられます。 すべてのマスクについて、すでに十分な肯定的な票が得られているかどうかを判断します。 そうでない場合は、負けた上院議員をすべて排除する確率を計算します。 

問題は、お菓子の配布数が急速に増加することです。 k 個のキャンディーと n 個の上院議員がある場合、割り当ての数はおよそ n^k になります。 上院議員が 8 人しかいない場合でも、k を増やすと、このアプローチは高価になります。 合計の作業量は約 O(n^k * 2^n) となり、同じ投票計算を何度も繰り返します。 

重要な観察は、キャンディーは各上院議員の最終的な忠誠心にのみ影響を与えるということです。 キャンディーが与えられる正確な順序は気にしません。 上院議員の最終的な状態だけで十分です。 n と k は両方とも非常に小さいため、キャンディーを使用する代わりに動的プログラミングを使用できます。 

キャンディーを 1 つずつ処理し、到達可能なすべてのロイヤルティ状態を保存します。 州は、キャンディーが配布された後に各上院議員が持つ忠誠度によって表されます。 各上院議員の忠誠度の値は 0、10、20、最大 100 の 11 個しかないため、可能な州の数は限られています。すべてのキャンディーが割り当てられた後、到達可能なすべての州を評価し、最良の確率を維持します。 

移行は簡単です。 現在の状態から、まだ 100 パーセントに達していない上院議員には、もう 1 つのキャンディーを与えることができます。 新しいステートが次のレイヤーに追加されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^k * 2^n * n) | O(n) | k が大きいと遅すぎる |
 | 最適 | O(k * S * n + S * 2^n * n) | O(S) | 承認済み |

 ここで、S は到達可能なロイヤルティ状態の数です。 n = 8 では、可能な状態の最大数は十分に小さいです。 

## アルゴリズムのチュートリアル

 1. 上院議員の意見を読み、すべての忠誠率を 10 パーセントのブロック数を表す整数に変換します。 忠誠度 70 は 7 になります。これにより、キャンディー 1 つを 1 つ追加するだけなので、キャンディーの操作が簡単になります。 
2. 初期ロイヤルティ値を含み、キャンディーは使用されていない単一の状態から開始します。 これは、選択を行う前に考えられる唯一の状況を表しています。 
3. 各キャンディーについて、考えられるすべての新しい状態を作成します。 現在のすべての州で、忠誠心がまだ 100% に満たないすべての上院議員にキャンディを贈ってみてください。 その上院議員の忠誠度を 1 ブロック増加させ、その結果の状態を保存します。 
4. すべてのキャンディーが処理されたら、すべての最終的なロイヤルティ状態を調べます。 状態ごとに、考えられるすべての投票マスクを反復して成功の確率を計算します。 マスクによって過半数が得られる場合、その確率が直接寄与します。 それ以外の場合は、負けたすべての上院議員を排除する確率を計算し、その寄与を加算します。 
5. すべての最終状態にわたって最大確率を計算します。 これが答えです。考えられるすべてのキャンディーの分布が、生成された状態のいずれかにつながるからです。 

機能する理由: 動的プログラミングは、将来の決定に影響を与える情報を正確に保持します。 キャンディーが変化するのは各上院議員の現在の忠誠心だけであるため、同じ忠誠ベクトルに到達する 2 つの異なる歴史には、同じ将来の可能性があります。 評価ステップでは、考えられるすべての投票結果をチェックします。これは、最終状態の正確な成功確率を計算することを意味します。 あらゆる最終状態が生成されるため、その中の最大値が最適解となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    first = input().split()
    if not first:
        return
    n, k, A = map(int, first)

    senators = []
    for _ in range(n):
        b, l = map(int, input().split())
        senators.append((b, l // 10))

    start = tuple(x[1] for x in senators)
    states = {start}

    for _ in range(k):
        nxt = set()
        for state in states:
            for i in range(n):
                if state[i] < 10:
                    arr = list(state)
                    arr[i] += 1
                    nxt.add(tuple(arr))
        states = nxt

    total_masks = 1 << n
    answer = 0.0

    for state in states:
        cur = 0.0
        for mask in range(total_masks):
            prob = 1.0
            bad_sum = 0
            good = 0

            for i in range(n):
                p = state[i] / 10.0
                if mask & (1 << i):
                    good += 1
                    prob *= p
                else:
                    prob *= (1.0 - p)
                    bad_sum += senators[i][0]

            if good > n // 2:
                cur += prob
            else:
                cur += prob * (A / (A + bad_sum))

        if cur > answer:
            answer = cur

    print("{:.10f}".format(answer))

if __name__ == "__main__":
    solve()
```コードの最初の部分には、各上院議員の忠誠度が 10 パーセント単位で保存されます。 これにより、状態生成段階での浮動小数点の変更が回避されます。 という名前のセット`states`加工されたキャンディーを使用した後に到達できるすべての忠誠度ベクトルが含まれています。 

遷移ループは、アルゴリズムの 3 番目のステップの後に続きます。 忠誠度値 10 の上院議員はすでに 100% を表しているため、これを増やすと無効な状態が作成されます。 これは動的計画法における主な境界条件です。 

評価ループは、肯定的に投票した上院議員の可能なすべてのサブセットをチェックします。 ビットマスクは、どの上院議員が私たちに投票したかを示します。 独立した投票確率を乗算して、その正確な結果の確率を取得します。 結果が過半数に達しない場合、コードは負けた上院議員の強さを計算し、除去確率を適用します。 

表現`A / (A + bad_sum)`は浮動小数点除算を使用して計算されます。 値は十分小さいため、必要な出力には Python の浮動小数点精度で十分です。 

## 実用的な例

 最初のサンプルでは、すべてのキャンディーを最適に与えた後のロイヤルティ状態は次のようになります。 

| ステップ | 忠誠度の状態 | 現在の最良の説明 |
 | --- | --- | --- |

 最終州では上院議員３人が確実な支持者となっている。 それはすでに過半数にとって十分であるため、重要な投票結果はすべて成功します。 

3 番目のサンプルの場合:```

```上院議員は 3 つのキャンディーをすべて受け取ることができます。 

| ステップ | 忠誠度の状態 | 成功の確率 |

 残りの確率は、上院議員が除名される投票失敗のケースから得られます。 DP はこの最終状態を考慮し、正確な確率を 0.7500000000 として計算します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k * S * n + S * 2^n * n) | キャンディー遷移を通じて状態を生成し、各最終状態を評価します。 
| スペース | O(S) | ロイヤルティ状態の現在のレイヤーのみを保存します。 

上院議員の数は最大 8 人であるため、すべての投票マスクを反復処理してもコストはかかりません。 到達可能なロイヤルティ状態の数も、少数のロイヤルティ レベルとキャンディーによって制限されるため、このソリューションは意図した制限に簡単に適合します。 

## テストケース```python
import sys
import io

def solve(data):
    sys.stdin = io.StringIO(data)
    input = sys.stdin.readline

    first = input().split()
    n, k, A = map(int, first)

    senators = []
    for _ in range(n):
        b, l = map(int, input().split())
        senators.append((b, l // 10))

    states = {tuple(x[1] for x in senators)}

    for _ in range(k):
        nxt = set()
        for state in states:
            for i in range(n):
                if state[i] < 10:
                    arr = list(state)
                    arr[i] += 1
                    nxt.add(tuple(arr))
        states = nxt

    ans = 0.0
    for state in states:
        cur = 0.0
        for mask in range(1 << n):
            p = 1.0
            bad = 0
            good = 0
            for i in range(n):
                if mask >> i & 1:
                    good += 1
                    p *= state[i] / 10.0
                else:
                    p *= 1.0 - state[i] / 10.0
                    bad += senators[i][0]
            if good > n // 2:
                cur += p
            else:
                cur += p * A / (A + bad)
        ans = max(ans, cur)

    return f"{ans:.10f}\n"

 ## 特殊なケース

 上院議員がすでに最大の忠誠心を持っている場合、移行ではその上院議員を無視する必要があります。 入力の場合:```
1 3 20
20 100
```生成される唯一の状態は忠誠度 10 のままです。投票確率は 1 なので、答えは正確に 1 になります。忠誠度 10 を超える状態は決して作成されないため、アルゴリズムがこれを処理します。 

誰も私たちをサポートしてくれず、除去に頼らなければならない場合でも、評価フェーズは機能します。 のために：```
1 0 10
20 0
```唯一の投票マスクは負け票です。 上院議員の強さは 20 なので、除名される可能性は 10 / 30 です。アルゴリズムは投票確率にこの値を乗算し、0.3333333333 を返します。 

キャンディーが複数の上院議員に分配されると、異なる命令によって同じ最終的な忠誠ベクトルが作成される可能性があります。 一連の状態によってこれらの重複が削除されるため、アルゴリズムは同一の状況を再計算するのに時間を無駄にすることがなくなります。 これは、動的プログラミングのアプローチを効率化する特性です。
