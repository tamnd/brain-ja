 ## アルゴリズムのチュートリアル

 1. 両方の文字列を同じ連続文字のグループに分割します。 たとえば、`"LLLRR"`ブロックになる`("L", 3)`そして`("R", 2)`。 これらのブロックは、隣り合って表示される同じドラム タイプの個々のヒットを表します。 
2. 2 つの文字列のブロック数を比較します。 違っていればすぐに答えが出る`NO`。 内の各ブロック`p`内の 1 つのブロックと正確に一致する必要があります`s`なぜなら、許可される唯一の変更は同じ文字を繰り返すことだからです。 
3. 一致するブロックのすべてのペアについて、それらの文字が等しいことを確認します。 左を叩いても右の音になることはありませんし、右を叩いても左の音になることはありません。 
4. ブロックの各ペアの長さを比較します。 録音したブロック長が元のブロック長より小さい場合、録音は音切れとなり無効となります。 元の長さの 2 倍より大きい場合は、使用可能なヒットに対してサウンドが多すぎます。 それ以外の場合、このブロックは有効です。 
5. すべてのブロックがチェックに合格した場合、出力します。`YES`。 

これが機能する理由は、圧縮によって変換に関連する情報が正確に保存されるためです。 1 つのブロック内では、すべての元のヒットは同じタイプのドラム ヒットです。 唯一可能な変更はコピーを 1 つ追加することです。そのため、ブロック全体は 1 から 2 の間の係数でしか拡大縮小できません。 ドラムヒットの順序が変わるため、異なるブロックを結合または分割することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def compress(s):
    res = []
    i = 0
    n = len(s)
    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1
        res.append((s[i], j - i))
        i = j
    return res

def solve():
    t = int(input())
    ans = []
    for _ in range(t):
        p = input().strip()
        s = input().strip()

        a = compress(p)
        b = compress(s)

        if len(a) != len(b):
            ans.append("NO")
            continue

        ok = True
        for (c1, x), (c2, y) in zip(a, b):
            if c1 != c2 or y < x or y > 2 * x:
                ok = False
                break

        ans.append("YES" if ok else "NO")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```の`compress`関数は文字列を 1 回調べて、連続したブロックを構築します。 次の 2 つのポインターを使用します。`i`ブロックの開始をマークし、`j`キャラクターが変わるまで動きます。 これにより、スライスの繰り返しが回避され、全体の作業が直線的に保たれます。 

メインループは最初にブロックの数を比較します。 これにより、元のブロックなど、ブロック境界が欠落しているケースが捕捉されます。`"LR"`なろうとしている`"LRL"`。 その後、ペアになったブロックがチェックされます。 条件`y > 2 * x`ブロックは 2 倍までは認められますが、それ以上は認められないため、オフバイ 1 のミスが最も起こりやすい場所です。 

Python の整数はここではオーバーフローしません。これは、算術演算に関係するのは文字列の長さ (最大でも数十万) だけであるためです。

 ## 特殊なケース

 のために`p = "LR"`そして`s = "LLLR"`、圧縮すると、`(L,1),(R,1)`そして`(L,3),(R,1)`。 最初のペアは、記録された長さが元の長さの 2 倍を超えているため失敗します。 アルゴリズムは戻ります`NO`、治療上の間違いを避ける`p`続編として。 

のために`p = "LL"`そして`s = "L"`、圧縮された形式は次のとおりです。`(L,2)`そして`(L,1)`。 2 つの別々のヒットで少なくとも 2 つのサウンドを生成する必要があるため、2 番目の文字列は短すぎます。 長さの比較により、これがすぐにわかります。 

のために`p = "R"`そして`s = "RR"`、ブロックは`(R,1)`そして`(R,2)`。 記録されたサイズは正確に許容最大値であるため、アルゴリズムはそれを受け入れます。 これにより、上限条件が検証されます。 

のために`p = "LR"`そして`s = "LRL"`、2 番目の文字列の圧縮形式には 3 つのブロックがあり、最初の文字列には 2 つのブロックがあります。 単一の元のブロックを別のドラムの別のブロックに分割することはできないため、アルゴリズムは長さのチェックを行う前にブロックを拒否します。
