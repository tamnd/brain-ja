 ## 解決策
 ## 問題の理解

 私たちは、Raze と Breach という 2 人のエージェント間の単純なターンベースの数字ゲームをシミュレートするように求められています。 各ゲームは次の正の整数で始まります。$n$数字。 数字には、1 から始まる左から右の番号が付けられます。Raze は奇数の位置の数字のみをマークでき、Breach は偶数の位置の数字のみをマークできます。 1 桁だけが残るまで、交互に数字をマークします。 勝者は最後の桁のパリティによって決まります。奇数の場合は Raze が勝ち、そうでない場合は Raze が勝ちます。 偶数の場合は、Breach が勝ちます。 レイズは常に最初に動きます。 入力は次のもので構成されます$t$独立したゲームなので、ゲームごとに誰が勝ったかを出力する必要があります。 

制約は中程度です。 各数字には最大 1000 桁を含めることができ、最大 100 のゲームが存在します。 これにより、マーキング数字のすべてのターンをシミュレートしようとするアルゴリズムは除外されます。$n$ゲームごとの操作は許容範囲ですが、完全なシミュレーションを行わずに最後の桁について推論することで、より適切な結果を得ることができます。 

エッジケースはどこにあるのか$n = 1$、つまり、桁が 1 つしかなく、移動できないことを意味します。 その場合、最後の桁がすぐに勝者の決定要因となります。 たとえば、入力`1\n2`出力する必要があります`2`一桁が偶数だからです。 もう 1 つの微妙なケースは、プレーヤーがアクセスできるすべての数字のパリティが間違っており、最適ではないマーキング シーケンスに強制される場合です。 これらのシナリオを早期に認識することで、すべての手をシミュレーションすることなく勝者を計算できます。 

## アプローチ

 ブルートフォースアプローチでは、各ターンをシミュレートします。どの数字がマークされていないかを追跡し、Raze と Breach が交互に有効な数字をマークし、1 つの数字が残るまで継続します。 その時点で、そのパリティを検査します。 このアプローチは正しいですが、次のことが含まれます。$O(n)$ゲームごとの操作。 それぞれ 1000 桁のゲームが最大 100 回あるため、約 100,000 回の操作が発生します。これは許容できますが、必須ではありません。 また、交互回転とインデックス付けを慎重に行う必要があるため、エラーが発生しやすくなります。 

最適なアプローチは、最後の桁だけが重要であることを観察することから生まれます。 各プレイヤーは常に、最後に残った桁を勝ちのパリティに強制的に入れようとします。 したがって、重要なのは、最後に移動するプレーヤーが、優先パリティのマークを付けずに残せる数字を少なくとも 1 つ持っているかどうかを確認することです。 奇数長の数値の場合、Raze は奇数の位置で最後に移動するため、奇数の位置に奇数の桁があるかどうかを確認します。 「はい」の場合、Raze は最後の桁が奇数であることを確認できます。 それ以外の場合は、違反が勝ちます。 同様に、偶数長の数値の場合、Breach は偶数位置で最後に移動するため、偶数位置の偶数桁をチェックします。 この推論により、直接的な$O(n)$ターンをシミュレートせずに、ゲームごとに数字を 1 回スキャンしてチェックします。

 | --- | --- | --- | --- |
 | ブルートフォース | ゲームあたり O(n) | O(n) | 受け入れられるが不要 |
 | 最適 | ゲームあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.ゲーム数を読む$t$。 ゲームごとに桁数を読み取ります$n$整数を表す文字列。 
2. 次のことを判断します。$n$奇数か偶数です。 もし$n$が奇数の場合、Raze は奇数の位置に関連する最終的な動きをします。 もし$n$が偶数の場合、ブリーチは偶数の位置に関連する最終的な動きをします。 
3. もし$n$が奇数の場合は、奇数の位置 (1、3、5、...) にあるすべての数字をスキャンし、それらのいずれかが奇数かどうかを確認します。 少なくとも 1 つが奇数であれば、Raze は残りの最後の桁が奇数であることを確認できるため、Raze が勝ちます。 それ以外の場合は、違反が勝ちます。 
4. もし$n$が偶数の場合は、偶数の位置 (2、4、6、...) にあるすべての数字をスキャンし、それらのいずれかが偶数であるかどうかを確認します。 少なくとも 1 つが偶数であれば、Breach は残りの最後の桁が偶数であることを保証できるため、Breach が勝ちます。 そうでなければ、Raze が勝ちます。 
5. 出力`1`Razeが勝った場合、または`2`ブリーチが各ゲームで勝利した場合。 

機能する理由: 最後に残った桁が勝者を決定し、各プレイヤーはアクセス可能な位置を最適に制御できます。 最後に移動するプレイヤーが許可された位置で利用可能な勝ち桁を持っているかどうかをチェックすることで、各ターンをシミュレートすることなく正しい結果を保証します。 唯一の勝利の選択肢が存在する場合、相手プレイヤーはそれを削除できないため、一連の動きはこれを無効にすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    if n % 2 == 1:
        # Raze has the final move on odd positions
        for i in range(0, n, 2):  # odd positions in 0-based indexing
            if int(s[i]) % 2 == 1:
                print(1)
                break
        else:
            print(2)
    else:
        # Breach has the final move on even positions
        for i in range(1, n, 2):  # even positions in 0-based indexing
            if int(s[i]) % 2 == 0:
                print(2)
                break
        else:
            print(1)
```位置の処理を簡素化するために、ゼロベースのインデックスを使用します。 ループ`for i in range(0, n, 2)`1 ベースのインデックス付けで位置 1、3、5 を訪問します。 の`else`for ループの句は、ループが中断されなかった場合、つまり勝ち桁が見つからなかった場合に実行されます。 これにより、別個のフラグ変数の導入が回避されます。 入力文字列を削除して末尾の改行を削除します。`input()`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    # solution
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        if n % 2 == 1:
            for i in range(0, n, 2):
                if int(s[i]) % 2 == 1:
                    print(1)
                    break
            else:
                print(2)
        else:
            for i in range(1, n, 2):
                if int(s[i]) % 2 == 0:
                    print(2)
                    break
            else:
                print(1)
    return output.getvalue().strip()
