 ## 解決策
 ## 問題の理解

 階段$n$列には高さの列が含まれています$1,2,\dots,n$。 このような階段内のセルの総数は次のようになります。$$1+2+\cdots+n=\frac{n(n+1)}2.$$この問題は、「素敵な」階段のみを考慮しています。 重要な幾何学的事実は、素敵な階段には常に非常に特定の数の階段があるということです。 最小の素敵な階段から始めて、より大きな階段を繰り返し構築すると、階段の数も増えていきます。$$1,\ 3,\ 7,\ 15,\dots$$それは$$2^k-1.$$階段の場合$2^k-1$階段、セルの数は$$1+2+\cdots+(2^k-1) = \frac{(2^k-1)2^k}{2}.$$させて$$c_k=\frac{(2^k-1)2^k}{2}.$$利用可能なセル$x$いくつかの異なる素敵な階段を構築するために使用できます。 この問題ではさまざまな素敵な階段が求められるため、各タイプの階段は最大 1 回しか構築できません。 合計コストが超えない階段タイプの最大数が必要です。$x$。 

の値$x$と同じ大きさにすることができます$10^{18}$。 までのすべての数値を反復するアルゴリズム$x$不可能です。 平$O(\sqrt{x})$大きすぎるでしょう。 私たちは、機能が、可能性のある素敵な階段の数ではなく、数にのみ依存するソリューションを必要としています。$x$自体。 

微妙な点は、最初に最大の階段を構築することが常に最適であるとは限らないということです。 例えば：```
x = 8
```階段費用は以下の通りです。```
1, 6, 28, ...
```コストを取る$6$最初の葉$2$、コストをさらに 1 段階上げることができます$1$、合計 2 つの階段です。 階段数ではなく使用済みセルを最大化しようとする戦略は、間違った選択をする可能性があります。 

もう 1 つの簡単な間違いは、考慮すべき階段のサイズが多数あると想定することです。 コストはおおよそ次のように増加します$4^k$、それで、$x \le 10^{18}$有効な階段タイプは約 30 種類しかありません。 この成長を活用することが全体的な解決策です。 

## アプローチ

 最も直接的なアイデアは、すべての適切な階段コストを生成し、すべてのサブセットを試して、合計コストが以下を超えない最大の数を見つけることです。$x$。 これは正しいです。なぜなら、すべての階段タイプが選択される場合と選択されない場合があるからです。 

問題は、階段タイプが 30 種類であっても、おおよその結果が得られることです。$2^{30}$サブセット、10 億以上の可能性。 それはまったく不可能です。 

重要な観察は、階段のコストが非常に急速に増加するということです。$$1,\ 6,\ 28,\ 120,\ 496,\dots$$それぞれのコストは、以前のすべてのコストの合計よりもはるかに大きくなります。 例えば、$$28 > 1+6,$$

$$120 > 1+6+28.$$実際、あらゆるものについて、$k$、$$c_k > \sum_{i<k} c_i.$$これは、シーケンスが超増加していることを意味します。 

最大数の階段が必要だとします。 コストに合った最大の階段なら$c_k$、次にスキップする解決策$c_k$より小さなコストをすべて合わせたとしても、より小さな階段を使用することで補うことはできません$c_k$。 取る$c_k$それが適合する場合は常に最良の選択です。 

これにより、貪欲なアルゴリズムがすぐに得られます。 

残りのセルを超えない最大の階段コストを減算し続けます。 これが何回可能であるかを数えてください。 

までの階段費用は30ほどしかないので、$10^{18}$、アルゴリズムは小さく、非常に高速です。

## アルゴリズムのチュートリアル

 1. すべての素敵な階段のコストを事前計算する$$c_k=\frac{(2^k-1)2^k}{2}$$その間$c_k \le 10^{18}$。 
2. 各テスト ケースでは、指定された数のセルから開始します。$x$。 
3. 現在のコストを超えない最大の階段コストを見つけます。$x$。 
4. そのコストを次から差し引きます。$x$そして答えを1つ増やします。 

すべてのコストはすべての小さいコストの合計よりも大きいため、これは正しい選択です。 
5. 階段コストの一部が残りのセルに収まるまで繰り返します。 
6. 選択した階段の数を出力します。 

### なぜ効果があるのか

 階段コストは超増加シーケンスを形成します。$$c_k > \sum_{i<k} c_i.$$最大のコストを考慮する$c_k$それは現在の予算内に収まります。 を使用しないソリューション$c_k$せいぜい費やすことができる$$\sum_{i<k} c_i,$$これは厳密に以下よりも小さいです$c_k$。 交換中$c_k$小さな階段を集めても、将来の選択の数を増やすためのより良い機会は決して得られません。 

選択した後$c_k$、残りの問題は、より少ない予算でも同じです。 同じ議論を再帰的に繰り返すことは、貪欲な選択が常に最適であることを証明します。 

## Python ソリューション```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

# precompute staircase costs
costs = []
k = 1
LIMIT = 10 ** 18

while True:
    p = 1 << k
    cost = (p - 1) * p // 2
    if cost > LIMIT:
        break
    costs.append(cost)
    k += 1

t = int(input())
ans = []

for _ in range(t):
    x = int(input())
    cnt = 0

    while True:
        idx = bisect_right(costs, x) - 1
        if idx < 0:
            break
        x -= costs[idx]
        cnt += 1

    ans.append(str(cnt))

sys.stdout.write("\n".join(ans))
```事前計算段階では、関連する可能性のあるすべての素敵な階段コストが生成されます。 コストが急激に増加するため、約 30 個の値のみが保存されます。 

テストケースごとに、`bisect_right`現在の予算を超えない最大のコストを見つけます。 そのコストが差し引かれ、プロセスが繰り返されます。 

リストが小さいため、バイナリ検索を使用することは必ずしも必要ではありませんが、バイナリ検索を使用すると実装がクリーンに保たれ、意図が明確になります。 

すべての算術演算では Python の整数が使用されるため、近くであってもオーバーフローのリスクはありません。$10^{18}$。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io
from bisect import bisect_right

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    costs = []
    k = 1
    LIMIT = 10 ** 18

    while True:
        p = 1 << k
        cost = (p - 1) * p // 2
        if cost > LIMIT:
            break
        costs.append(cost)
        k += 1

    t = int(input())
    out = []

    for _ in range(t):
        x = int(input())
        cnt = 0

        while True:
            idx = bisect_right(costs, x) - 1
            if idx < 0:
                break
            x -= costs[idx]
            cnt += 1

        out.append(str(cnt))

    return "\n".join(out)

# provided samples
assert run(
    "4\n1\n8\n6\n1000000000000000000\n"
) == "1\n3\n1\n30"

# custom cases

assert run("1\n5\n") == "5", "repeated use of size-1 staircase"
assert run("1\n28\n") == "1", "exactly one larger staircase"
assert run("1\n29\n") == "2", "boundary just above 28"
assert run("1\n1000000000000000000\n") == "30", "maximum input"
