 ## 解決策
 ## 問題の理解

 氷球には個別の価格が与えられており、任意の順序で並べ替えることができます。 球が安いとみなされるのは、球に左近傍と右近傍の両方があり、その価格が両方より厳密に小さい場合のみです。 最初と最後のポジションは決して貢献できません。 

タスクは、極小となる位置の数を最大化する配置を構築し、その最大数と ​​1 つの有効な順序の両方を出力することです。 

入力サイズが到達しました$10^5$つまり、すべての順列を検査するアルゴリズムは絶望的です。 平$O(n^2)$周りでパフォーマンスするだろう$10^{10}$最悪の場合、制限時間を大幅に超えて操作が行われる可能性があります。 仕分けには費用がかかります$O(n \log n)$、このサイズとしては手頃な価格です。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

元素が非常に少ない場合、安価な球体は存在できません。 例えば```
1
7
```生産しなければならない```
0
7
```唯一の球体が終点でもあるからです。 

3 つの値を使用すると、```
3
1 2 3
```正しい答えは```
1
2 1 3
```位置 2 が両方の隣よりも小さくなるためです。 内部位置が 1 つしか存在しないため、複数の極小値を配置しようとすることは不可能です。 

別の微妙なケースが均等な長さで表示されます。 のために```
4
1 2 3 4
```答えは```
1
3 1 4 2
```不用意に交互に配置すると、2 つの極小値が誤って期待される可能性がありますが、最後の位置には隣接する位置が 1 つしかないため、位置 2 と 4 が両方とも谷になることはあり得ません。 

## アプローチ

 ブルートフォースソリューションでは、すべての順列を生成し、条件を満たすインデックスの数を数えます。```
a[i] < a[i - 1] and a[i] < a[i + 1]
```そしてベストな配置を保ちます。 これが機能するのは、考えられるすべての順序を明示的にチェックするためです。 残念ながら、あります$n!$順列。 たとえ$n=12$、これはすでに 4 億 7,900 万件の取り決めを超えており、このアプローチは使用できなくなりました。 

極小値の構造は、より良いアイデアを与えてくれます。 すべての安価な球体は、2 つの大きな球体の間に位置する必要があります。 すべての数値は個別であるため、最小値が谷の最良の候補となります。 

配列をソートするとします。 奇数の位置に大きな値をいくつか配置し、それらの間に小さな値を挿入すると、挿入された各要素は自動的に隣接する 2 つの要素よりも小さくなります。 唯一の問題は、そのような谷がいくつ当てはまるかです。 

あれば$k$谷では、次のものが必要です。```
large small large small ... large
```を使用する$k+1$大きな要素と$k$小さな要素の合計$2k+1$ポジション。 したがって$$2k+1 \le n$$可能な最大値は$$k=\left\lfloor \frac{n-1}{2}\right\rfloor.$$並べ替えた後は、大きい半分を最初に配置し、次に小さい半分を 1 つおきの位置に挿入するだけです。 これにより、まさに最大数の谷が作成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n!\cdot n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を昇順に並べ替えます。 
2. コンピューティング$$k=\left\lfloor\frac{n-1}{2}\right\rfloor.$$各谷には隣接する 2 つのピークが必要であるため、これが可能な谷の最大数です。 
3. ソートされた配列を 2 つの部分に分割します。 

最初の部分には最小のものが含まれます$k$価値観。 これらは谷になります。 

2 番目の部分には残りの値が含まれます。 これらはピークとして機能します。 
4. 2 番目の部分のすべての値を使用して回答配列を開始します。 

より大きな数値がすでに配置されていると、挿入されたより小さな数値がその隣の数値よりも小さくなることが保証されます。 
5. 小さい値を応答配列の位置 1、3、5、... に挿入します。 

2 番目の部分は最初の部分より全体的に大きいため、挿入された各値は 2 つのより大きな値の間にあります。 
6. 出力$k$そして出来上がったアレンジメント。 

### なぜ効果があるのか

 ソート順序により、谷として選択されたすべての要素がすべてのピーク要素よりも小さいことが保証されます。 谷要素を奇数の位置に挿入すると、それぞれの要素のすぐ左とすぐ右の値が大きくなります。 したがって、これらの位置はすべて極小値です。 

アレンジメントには以下のものを含めることはできません$\lfloor (n-1)/2 \rfloor$すべての谷が 2 つの隣接する位置を消費するためです。 この構造はまさにその数値を達成するため、最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

a.sort()

k = (n - 1) // 2

small = a[:k]
large = a[k:]

ans = large[:]

for i in range(k):
    ans.insert(2 * i + 1, small[i])

print(k)
print(*ans)
```最初の部分では、価格を並べ替え、理論上の谷の最大数を計算します。 

最小の`k`値はに保存されます`small`、残りは`large`。 のすべての要素があるため、`large`～のあらゆる要素を超えている`small`、挿入された小さな値は自動的に極小値になります。 

回答には、最初はすべての大きな値が含まれています。 このループは、谷の候補を位置 1、3、5 などに挿入します。 これらは 0 から始まるインデックスで、1 から始まるインデックスの 2 番目、4 番目、6 番目の位置に対応します。 

よくある間違いは、次のように使用することです。`n // 2`の代わりに`(n - 1) // 2`。 長さが偶数の場合、谷の数が過大評価されます。 たとえば、`n=4`、最大でも 1 つの極小値が存在します。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    a.sort()
    k = (n - 1) // 2

    small = a[:k]
    large = a[k:]

    ans = large[:]
    for i in range(k):
        ans.insert(2 * i + 1, small[i])

    return str(k) + "\n" + " ".join(map(str, ans))

# provided sample
assert run("5\n1 2 3 4 5\n") == "2\n3 1 4 2 5"

# minimum size
assert run("1\n7\n") == "0\n7"

# size two
assert run("2\n10 5\n") == "0\n5 10"

# odd length
assert run("3\n1 2 3\n") == "1\n2 1 3"

# even length
assert run("4\n1 2 3 4\n") == "1\n2 1 3 4"

# larger case
assert run("7\n7 1 6 2 5 3 4\n") == "3\n4 1 5 2 6 3 7"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 7`|`0 / 7`| 単一要素の場合 |
 |`2 / 10 5`|`0 / 5 10`| 内部ポジションなし |
