 ## 解決策
 ## 問題の理解

 ダイヤモンドの形を含む奇数サイズの正方形グリッドを印刷する必要があります。 ダイヤモンドに属するすべてのセルは文字で表されます。`D`、1 つおきのセルは次のように表されます。`*`。 

入力には単一の奇数整数が含まれています`n`。 出力は正確に次のように構成されている必要があります`n`行、それぞれに正確に含まれる行`n`文字。 ダイヤモンドはグリッドの中心にあり、中央の列に向かって拡大し、その後対称的に縮小します。 

制約は非常に小さいです。 可能な最大のグリッドは次のとおりです。`101 × 101`、10,201 個のセルが含まれています。 すべてのセルを個別に検査するアルゴリズムでも、1 秒の制限内で十分に高速です。 高度な最適化は必要ありません。 

主な課題はパフォーマンスではなく、ダイヤモンド パターンを正しく構築することです。 

簡単な間違いの 1 つは、上半分と下半分の間のトランジションを正しく処理しないことです。 

たとえば:

 入力:```
5
```正しい出力:```
**D**
*DDD*
DDDDD
*DDD*
**D**
```不注意に実装すると、中央の行の後で幅が増加し続けたり、1 行早く減少し始めたりする可能性があります。 

もう 1 つのよくある間違いは、合計の長さが間違った行を作成することです。 

たとえば、サイズ 5 の結晶の最初の行は次のようになっている必要があります。```
**D**
```行には 2 つの星が含まれ、次に 1 つが含まれます`D`、次に 2 つ星、合計の長さは 5 になります。後続の星を忘れると、次のようになります。```
**D
```すべての行に正確に含まれている必要があるため、これは無効です`n`文字。 

最小の有効な入力もチェックする価値があります。 

入力：```
3
```出力：```
*D*
DDD
*D*
```中央の行はすでに幅全体を占めているため、ひし形が両方の端に達しても境界の計算は機能する必要があります。 

## アプローチ

 問題を解決する簡単な方法は、すべての位置を調べることです`(row, column)`グリッド内でそのセルがダイヤモンドに属するかどうかを決定します。 ダイヤモンドは中央に配置されているため、中央の行と中央の列からの距離を計算し、それに応じてセルにマークを付けることができます。 すべてのセルは独立して分類されるため、このアプローチは正しいです。 実行します`n²`checks, which is at most 10,201 operations for the given constraints.

 さらに単純な観察もあります。 実際にはセルごとに決定する必要はありません。 If we know how many`D`文字が 1 行に属している場合、残りの位置は星でなければなりません。 

ダイヤモンドは、中心に達するまで、1 行あたり 2 セルずつ成長します。```
1, 3, 5, ..., n
```中央の行の後は、対称的に縮小します。```
..., 5, 3, 1
```各行について、次の数を 1 回、`D`文字がわかっている場合、各側の星の数は次のとおりです。```
(n - D_count) / 2
```行全体を次のように直接構築できます。```
stars + Ds + stars
```これにより、個々のセルについて考える必要がなくなり、ダイヤモンドの幾何学的構造と一致します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 承認済み |
 | 最適 | O(n²) | お(1) | 承認済み |

 どちらのアプローチも漸近的に複雑さは同じですが、このパターン印刷タスクでは、行を直接構築する方が簡単で自然です。 

## アルゴリズムのチュートリアル

 1. 奇数の整数を読み取る`n`。 
2. 中央の行インデックスを次のように計算します。`mid = n // 2`。 
3. すべての行インデックスを反復処理します。`i`から`0`に`n - 1`。 
4. 中央の行からの距離を計算します。```
dist = abs(i - mid)
```ダイヤモンドは対称であるため、中心から等距離にある行は同一に見える必要があります。 
5. 数を決定する`D`文字は次の行に属します。```
d = n - 2 * dist
```中心から1歩離れるごとに1つ削除されます`D`左側から 1 つ、右側から 1 つ。 
6. 各辺の星の数を計算します。```
stars = (n - d) // 2
```7. 行を作成します。```
"*" * stars + "D" * d + "*" * stars
```8. 行を出力します。 

### なぜ効果があるのか

 離れた列の場合`dist`中心から見ると、ダイヤモンドは両側でちょうど 1 つのセル分だけ狭くなります。 ダイヤモンドの幅は次のように減少します。`2 × dist`、与える`n - 2 × dist`ダイヤモンドセル。 図は中央の列を中心に対称であるため、残りの位置は左右に均等に分割されます。 アルゴリズムによって生成された各行には、正確に正しい数の星の数が含まれており、`D`したがって、結果として得られるグリッドはまさに必要なダイヤモンドです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

mid = n // 2

for i in range(n):
    dist = abs(i - mid)
    d = n - 2 * dist
    stars = (n - d) // 2
    print("*" * stars + "D" * d + "*" * stars)
```解決策は、中央の行を見つけることから始まります。 1 行おきの行は、その中心からの距離によって完全に記述されます。 

値`d`連続した回数を格納します`D`現在の行の文字。 中央列には、`dist = 0`、 それで`d = n`、行全体が次のもので構成されることを意味します`D`文字。 1 行離れると幅が 2 つ減少し、ひし形の形状と一致します。 

値`stars`未使用の位置から計算されます。 パターンは対称であるため、それらの位置の半分が左側に表示され、半分が右側に表示されます。 

使用する`abs(i - mid)`上半分と下半分の個別のロジックを回避します。 同じ計算式がダイヤモンドの両側を自動的に処理し、多くのよくあるオフバイワンの間違いを排除します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(sys.stdin.readline())
    mid = n // 2

    out = []
    for i in range(n):
        dist = abs(i - mid)
        d = n - 2 * dist
        stars = (n - d) // 2
        out.append("*" * stars + "D" * d + "*" * stars)

    return "\n".join(out) + "\n"

# provided sample
assert run("3\n") == "*D*\nDDD\n*D*\n", "sample 1"

# minimum valid size
assert run("3\n") == "*D*\nDDD\n*D*\n", "minimum size"

# small symmetric case
assert run("5\n") == "**D**\n*DDD*\nDDDDD\n*DDD*\n**D**\n", "size 5"

# larger odd size
assert run("7\n") == "***D***\n**DDD**\n*DDDDD*\nDDDDDDD\n*DDDDD*\n**DDD**\n***D***\n", "size 7"

# maximum size, verify dimensions
res = run("101\n").splitlines()
assert len(res) == 101
assert all(len(row) == 101 for row in res)
assert res[50] == "D" * 101
