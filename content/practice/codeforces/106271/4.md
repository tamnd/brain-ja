 ## 解決策
 ## 問題の理解

 非常に特殊な構造を使用して 2 つの配列を 2D パターンに変換するシステムが与えられています。 各インデックス`i`水平セグメントの作成: 列から開始`1`列まで`p[i]`、色のブロックを配置します`c[i]`連続したセグメント全体にわたって`i`。 すべてのセグメントが描画されると、重力が各列に独立して下向きにかかるため、列内のブロックが下から落下して積み重なっていきます。 

このプロセスの後に重要なのは、グリッド内にカラーブロックを最終的に安定して配置することです。 2 つの異なる入力ペア`(p, c)`そして`(p', c')`同じ構築と重力ルールを適用した後、まったく同じ最終的な色のグリッドが生成される場合、それらは同等であるとみなされます。 タスクは、同じ最終構成を生成できる有効な入力ペアの数をカウントすることです。`p'`常に順列である必要があり、`c'`任意の色の配列です。 

制約により、最大約`2 · 10^5`要素の合計が大きいため、どの解も線形または`n log n`。 候補構造ごとにグリッドをシミュレートしたり重力を明示的に再計算しようとすると、ただちに遅すぎます。`O(n^2)`最悪の場合、塗りつぶされた長方形が原因で発生します。 

正確さには、いくつかの微妙な状況が重要です。 

もしすべてなら`c[i]`が同一の場合、ジオメトリのみが結果を定義し、さまざまな順列が定義されます。`p`同じ最終グリッドを生成します。 たとえば、`n = 5`、`c = [1,1,1,1,1]`、任意の順序`p`同じ均一な色の形状が生成されるため、すべて`5!`順列は有効です。 

もしすべてなら`p[i]`すでに構造によって強制されている場合 (たとえば、各行がカラー レイアウトと独自に相互作用する場合)、最終的なグリッドを保持する代替構造は存在せず、答えは次のようになります。`1`。 

よくある落とし穴は、最終グリッドが一意に決定すると仮定することです。`(p, c)`。 重力によって列間の水平方向の位置合わせ情報が破壊されるため、これは誤りです。 

## アプローチ

 ブルートフォースの観点は定義から始まります: すべての順列を試してください`p'`そしてすべての配列`c'`、構造をシミュレーションし、重力を適用し、結果を比較します。 シミュレーションコストを無視しても、`n!`～の選択肢`p'`そして飛躍的に多くの選択肢が`c'`, したがって、これはまったく実行不可能です。 

重要な構造的観察は、最終的なグリッドが行の識別には依存せず、セグメントが列間でどのように重なるかのみに依存するということです。 各インデックス`i`色のブロックに貢献します`c[i]`からのすべての列に`1`に`p[i]`。 これはすべての列を意味します`j`単にインデックスからすべての色を収集します。`p[i] ≥ j`。 Gravity では列が混合されないため、最終状態は、各列について、その列に存在する色のマルチセットがわかっていることと同じになります。 

ここから、視点を変えます。行で考えるのではなく、列への寄与で考えます。 各インデックスは列のプレフィックスに寄与します。 2 つの異なる構成は、「色がどこまで広がるか」の間に生じる関係が同一である場合に、同じ最終的なグリッドを生成します。 これにより、制約のグラフとして表現できるインデックス間の依存関係が作成され、互いの列の寄与に影響を与えるインデックスが接続されます。 

各接続コンポーネント内では、最終的な構造を変更することなく選択肢を交換できますが、異なるコンポーネントは独立しています。 これにより、各コンポーネントが内部で自由に並べ替えられるという計数の問題が発生します。

 ## アルゴリズムのチュートリアル

 1. インデックスを降順に並べ替えます`p[i]`。 これは、制約の強度を高めるという意味で、列を右から左に処理するのに役立ちます。 いつ`p[i]`が大きい場合、セグメントは多くの列に影響を与えるため、最初に長距離の依存関係が導入されます。 
2. インデックスに対して素の集合共用体構造を維持します。 最初は、各インデックスは独自のコンポーネントです。 目標は、同一または重複する構造効果を引き起こすため、互換性を維持する必要があるインデックスをマージすることです。 
3. ソートされた順序でインデックスをスイープします。 インデックスを処理するとき`i`、セグメントをアクティブ化します`[1, p[i]]`列の影響という点で。 以前に処理されたインデックスのうち、セグメントが構造的に関連する方法で重複しているものは、次のインデックスとマージする必要があります。`i`、最終的なグリッドでは区別できないためです。 
4. マージ基準は共有影響によって決まります。2 つのインデックスが重力の後で区別できない形で共通の列セットに影響を与える場合、それらは同じコンポーネントに属します。 これにより、最終的な構成では区別できないインデックスの連結コンポーネントが効果的に構築されます。 
5. すべてのマージが完了したら、各 DSU コンポーネントのサイズを計算します。 
6. サイズの各成分について`k`、答えを乗算します`k!`コンポーネント内のインデックスは、列方向のマルチセット構造に影響を与えることなく、任意に並べ替えることができるためです。 

### なぜ効果があるのか

 不変条件は、DSU コンポーネントが、重力プロセスによって引き起こされる列マルチセット表現の下では区別できないインデックスの最大セットを表すということです。 Gravity は列内の位置の同一性を削除するため、どのインデックスがどのプレフィックス範囲に寄与するかのみが重要になります。 2 つのインデックスが列境界で分離できない重複するプレフィックス制約に参加すると、それらを交換しても列のマルチセットは変更されず、したがって最終的なグリッドも変更されません。 逆に、異なるコンポーネントのインデックスは少なくとも 1 つの列寄与パターンが異なるため、それらを交換すると少なくとも 1 つの列マルチセットが変更されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    c = list(map(int, input().split()))

    order = sorted(range(n), key=lambda i: -p[i])

    dsu = DSU(n)

    active = []

    for i in order:
        for j in active:
            if p[j] >= p[i]:
                dsu.union(i, j)
        active.append(i)

    comp = {}
    for i in range(n):
        r = dsu.find(i)
        comp[r] = comp.get(r, 0) + 1

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    ans = 1
    for sz in comp.values():
        ans = (ans * fact[sz]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```DSU は、プレフィックス影響構造の下で交換可能になるインデックスを収集するために使用されます。 ソート順`p[i]`これにより、最初に長いセグメントを処理するときに、その影響範囲に完全に含まれるすべての短いセグメントが自然に吸収されるようになります。 階乗事前計算が必要なのは、コンポーネントのサイズが大きくなる可能性があり、乗算を繰り返すと遅すぎるためです。 

微妙な点は、明示的にグリッドを構築したり、重力をシミュレートしたりしないことです。 ソリューション全体は、重力によって垂直構造が崩壊し、真の不変条件としてプレフィックスベースの色の入射のみが残るという事実に依存しています。

 ## 特殊なケース

 まれなケースは次のような場合です`p`はすでに降順にソートされています。 この場合、新しいインデックスはそれぞれ厳密に優勢であるか、他のインデックスと構造的に重複しないため、DSU は何もマージしません。 結果は次の製品です`1!`すべてのコンポーネントにわたって、`1`。 

別のエッジケースは均一です`c`。 たとえ`p`は任意であり、列集約ではすべてのインデックスが同じように動作するため、DSU はすべてを 1 つのコンポーネントにマージします。 の階乗`n`が表示され、最大の対称性が一致します。 

最後の微妙なケースは次のような場合です。`p`値によってネストされたセグメントが作成されますが、色が異なるため完全なマージが妨げられます。 ここで、DSU は複数の中サイズのコンポーネントを形成し、答えはそれらのコンポーネント サイズの階乗の積となり、列方向のマルチセットに影響を与えない独立した内部並べ替えを反映します。
