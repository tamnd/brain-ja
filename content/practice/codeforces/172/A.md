 ## 解決策
 ## 問題の理解

 私たちはある都市の友人から電話番号のリストを渡されました。 各電話番号は一連の数字であり、すべての番号は同じ長さです。 課題は市の電話番号を見つけることです。Polycarpus は、市の電話番号をこれらすべての番号で共有される最長の共通プレフィックスとして定義しています。 言い換えれば、市外局番は、最初の不一致が発生する前のすべての番号の先頭にある一連の数字です。 出力は、プレフィックス自体ではなく、このプレフィックスの長さです。 

この制約により、それぞれ最大 20 桁の長さの数値を最大 30,000 個まで指定できることがわかります。 これは、合計の比較が最大 30,000 掛ける 20、つまり 600,000 回の操作であり、2 秒の制限内で快適に行えるため、すべての数値を 1 文字ずつ比較するソリューションは実行可能であることを意味します。 すべての数値が同じ長さで明確であることが保証され、曖昧さがなくなりますが、数値が共通のプレフィックスをまったく共有しない可能性を処理する必要があります。 たとえば、数値が次の場合、`123`そして`987`、正しい出力は 0 です。最初の文字が常に一致すると仮定する単純なアプローチでは、誤って間違った答えが生成される可能性があります。 

もう 1 つの特殊なケースは、最後の文字を除いてすべての数字が同一である場合です。 例えば、`5550`、`5551`、`5552`。 最も長い共通プレフィックスは次のとおりです。`555`、長さは 3 です。不注意な実装では、すべての数値の文字の等価性が正しくチェックされない場合、過大カウントまたは過少カウントが発生する可能性があります。 

## アプローチ

 最も単純なアプローチはブルートフォースです。 最初の数値を基準として取り、各文字インデックスを反復処理して、その文字を他のすべての数値の対応する文字と比較します。 最初の不一致で停止します。 このアプローチは、不一致が見つかるまで文字を比較するだけなので機能します。 最悪の場合、すべての数字のすべての文字が一致するため、次のように実行します。`n * length`比較は、制約があれば管理可能です。 

もう少し構造化された方法は、ペアワイズ リダクションを使用することです。 最初の数値を現在のプレフィックスとして開始し、その数値の先頭と一致するまで後続の各数値と比較して繰り返し短縮します。 この手法により、以前の位置で異なることがすでにわかっている文字を繰り返しチェックする必要がなくなりますが、このような短い長さの場合、パフォーマンスの向上は最小限です。 

重要な洞察は、文字列が短い (最大 20 桁) ため、効率を心配することなく、すべての数値にわたって 1 文字ずつ安全に比較できるということです。 問題の構造 (固定長の文字列、保証された数字の内容、および小さい最大長) により、総当たりアプローチが本質的に最適になります。

 ## アルゴリズムのチュートリアル

 1.友達の数を読み取る`n`そして電話番号のリスト。 すべての数値は同じ長さです`m`。 
2. 最初の電話番号を最初の参照プレフィックスとして使用します。 
3. 変数を初期化する`prefix_length`全長まで`m`。 これは、可能な最大のプレフィックスを表します。 
4. 残りの電話番号を繰り返し処理します。 
5. 各数値について、先頭から現在の数値まで 1 文字ずつ繰り返します。`prefix_length`。 
6. 同じ位置にある文字を参照番号と比較します。 不一致が発生した場合は、削減します`prefix_length`不一致のインデックスに移動し、内側のループから抜け出します。 
7. 次の番号に進み、さらに減らします。`prefix_length`必要に応じて。 
8. すべての数値を処理した後、`prefix_length`最長の共通プレフィックスの長さを保持します。 印刷してください。 

不変条件は、各数値を処理した後、`prefix_length`これまでに処理されたすべての番号で共有される最長のプレフィックスを常に反映します。 それを超えるキャラクターはありません`prefix_length`有効な共通プレフィックスの一部にすることができ、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
numbers = [input().strip() for _ in range(n)]

prefix_length = len(numbers[0])

for num in numbers[1:]:
    for i in range(prefix_length):
        if num[i] != numbers[0][i]:
            prefix_length = i
            break

print(prefix_length)
```まず、すべての入力数値を読み取り、改行文字を取り除きます。 最初の番号には可能な限り最大のプレフィックスが付いていると仮定します。 後続の各番号については、以下までのみチェックします。`prefix_length`それを超える文字は共通の接頭辞の一部になることができないためです。 不一致が発生するとループが直ちに中断され、不必要な比較が防止されます。 最後に、プレフィックスの長さを出力します。これはまさに問題が求めているものです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    numbers = [input().strip() for _ in range(n)]
    prefix_length = len(numbers[0])
    for num in numbers[1:]:
        for i in range(prefix_length):
            if num[i] != numbers[0][i]:
                prefix_length = i
                break
    return str(prefix_length)

# Provided samples
assert run("4\n00209\n00219\n00999\n00909\n") == "2", "sample 1"
assert run("2\n123\n987\n") == "0", "sample 2"

# Custom cases
assert run("3\n5550\n5551\n5552\n") == "3", "common prefix just before last digit"
assert run("2\n1\n1\n") == "1", "single-digit identical numbers"
assert run("3\n12345678901234567890\n12345678901234567891\n12345678901234567892\n") == "19", "max length numbers differing at last digit"
assert run("2\n99999\n99999\n") == "5", "all numbers identical"
assert run("2\n0000\n1111\n") == "0", "no common prefix at all"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |

| 1、1 | 1 | 1 桁のエッジケース |
 | 最後の桁が異なる長い数値 | 19 | 最大長の入力境界の処理 |
 | 同じ数字 | 5 | 文字列全体が一致します |
 | 0000、1111 | 0 | 共通のプレフィックスはありません |

 ## 特殊なケース

 最後の文字を除いてすべての数値が同一である場合、アルゴリズムは各数値の最初の不一致で比較を正しく停止します。 例えば、`5550`、`5551`、`5552`結果として`prefix_length`= 3. 次のような完全に重複しない数値の場合`123`そして`987`、アルゴリズムは最初の文字ですぐに不一致を検出し、設定します。`prefix_length`= 0。1 桁の数値の場合、アルゴリズムは一致シナリオと不一致シナリオの両方を自然に処理し、1 または 0 を返します。すべてのエッジ ケースは、不一致の早期ブレークを備えた文字ごとの比較ループによって正しく処理されます。
