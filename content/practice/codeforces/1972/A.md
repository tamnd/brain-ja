 ## 解決策
 ## 問題の理解

 とのコンテストが与えられました`n`それぞれに提案された難易度を持つ問題`a_i`そして予想される最大難易度`b_i`。 両方のシーケンスは、降順ではない順序でソートされます。 目標は、すべての問題が満足できるように、提案された難易度を調整することです。`a_i ≤ b_i`。 

唯一許可されている操作は、任意の難易度で新しい問題を提案することです`w`。 提案後、新しい問題が配列に挿入されます`a`、配列がソートされ、最大の要素が削除されます。 事実上、より困難な問題の 1 つを、制御可能な新しい問題に置き換えることになります。 

出力は、条件を満たすために提案する必要がある新しい問題の最小数です。`a_i ≤ b_i`みんなのために`i`。 

制約は小さいです。`n`最大 100 まで指定でき、テスト ケースは最大 100 個あります。 これは、`O(n^2)`テストケースごとのソリューションは許容されます。`100*100^2 = 10^6`操作は1秒で簡単に処理できます。 

明らかではないエッジケースには、提案されたすべての困難が予想を超えるシーケンスが含まれます。`a = [5,6,7]`そして`b = [1,2,3]`、すべての不一致に対して新しい問題を提案する必要があります。 もう 1 つの微妙なケースは、次の最初のいくつかの要素だけが含まれる場合です。`a`超える`b`ただし、貪欲なアプローチでは最初に最も初期の不一致をターゲットにする必要があるため、残りは問題ありません。 

## アプローチ

 単純な総当たり手法では、あらゆる可能性のある新しい問題の挿入をシミュレートし、可能な限りすべてのことを試します。`w`から`1`に`max(a_i,b_i)`条件が満たされるまで。 これが機能するのは、各挿入後に最大の要素が削除され、最終的にはすべての要素を削減できるためです。 ただし、候補者の数は、`w`値が巨大です (`10^9`）、ブルートフォースは非現実的になります。 

重要な洞察は、配列がソートされていることです。 任意の値を試す必要はありません。 最も簡単な問題から最も難しい問題まで処理する場合、提案する最小の新しい問題は、単に条件に違反する最初の問題の予想される難易度になります。 これを挿入すると、最大の要素が置き換えられ、配列がゴールに近づくように移動します。 この方法で各違反を貪欲に修正できます。 

したがって、最適なアプローチは貪欲な 2 ポインター法です。 ポインタを維持します`a`そして`b`左から右へ。 いつでも`a[i] > b[i]`、私たちはそれを必要な新しい問題として数えます。 新たな問題の数は、そのような違反の数です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * max(a_i,b_i)) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`ops = 0`必要な新しい問題の数を追跡します。 
2. 両方の配列を反復処理します。`a`そして`b`最初の問題から最後まで。 
3. インデックスごとに`i`、 比較する`a[i]`と`b[i]`。 
4. もし`a[i] > b[i]`、増分`ops`by 1. これは、難しすぎる問題を置き換えるために提案しなければならない新しい問題の数を数えます。 
5. すべてのインデックスを処理した後、出力します。`ops`。 

配列はソートされているため、貪欲な選択は正当化されます。 いつ`a[i] > b[i]`の場合、右側の要素は、より大きな要素を置き換えずに違反を修正できません。 各操作で最大の要素が置き換えられ、最初に左端の違反を確実に減らすことができます。 不変条件は次のとおりです`ops`操作、最初の`n - ops`の要素`a`すでに ≤ の対応する要素である`b`残りを交換するだけで済みます`ops`要素。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    ops = 0
    for i in range(n):
        if a[i] > b[i]:
            ops += 1
    print(ops)
```このソリューションは、次を使用して複数のテスト ケースを効率的に読み取ります。`sys.stdin.readline`。 各インデックスを反復処理して、違反をカウントします。 入力配列はすでにソートされているため、ソートは必要ありません。 比較は簡単なので、1 つずつ異なるエラーが回避されます。 インクリメント`ops`新しい問題を提案することに直接対応します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        ops = 0
        for i in range(n):
            if a[i] > b[i]:
                ops += 1
        print(ops)
    
    return output.getvalue().strip()

# provided samples
assert run("2\n6\n1000 1400 2000 2000 2200 2700\n800 1200 1500 1800 2200 3000\n6\n4 5 6 7 8 9\n1 2 3 4 5 6\n") == "2\n3", "sample 1"

# custom tests
assert run("1\n3\n1 2 3\n1 2 3\n") == "0", "all equal, no ops"
assert run("1\n3\n5 6 7\n1 2 3\n") == "3", "all a > b"
assert run("1\n5\n1 2 3 4 5\n5 5 5 5 5\n") == "0", "all a < b"
assert run("1\n4\n10 20 30 40\n5 15 35 45\n") == "2", "mixed case"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 2 3`/`1 2 3`| 0 | 配列が等しい場合は操作は必要ありません。 
|`5 6 7`/`1 2 3`| 3 | すべての要素を交換する必要があります |
 |`1 2 3 4 5`/`5 5 5 5 5`| 0 | 全て`a_i`すでに ≤`b_i`|

## 特殊なケース

 提案されたすべての問題が予想よりも大きいというエッジケースの場合、`a = [10,20,30]`そして`b = [1,2,3]`、アルゴリズムは正しくカウントします`3`操作。 各反復で識別されるのは、`a[i] > b[i]`そしてカウンターをインクリメントします。 値が大きくても(`10^9`)、比較はオーバーフローしません。 

最小サイズの入力の場合`n=1`と`a = [5]`そして`b = [5]`、操作はカウントされず、アルゴリズムが単一要素配列をエラーなしで処理することを示しています。 

一部の初期要素のみが条件に違反する配列の場合、貪欲なカウントにより、必要な置換のみが考慮されることが保証されます。 のために`a = [1,5,6]`そして`b = [2,4,6]`、アルゴリズムは 2 をカウントします
