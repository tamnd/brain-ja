 ## 解決策
 ## 問題の理解

 複数のカードのセットが与えられ、それぞれに 1 から 1 までの整数がラベル付けされています。$n$、およびタイプごとに$i$私たちはカードの枚数を知っています$a_i$私たちはすでに所有しています。 私たちも持っています$k$追加のカードを購入するためのコインがあり、ショップには各タイプのカードが無制限に供給されます。 カードを購入したら、すべてのカードを一列に並べます。 目標は、同じ長さの連続する部分配列の数を最大化することです。$n$それは次の順列です$[1, 2, \ldots, n]$。 各テスト ケースの出力は、この可能な最大数です。 

重要な課題は、$n$まで可能です$2 \cdot 10^5$そして$a_i$そして$k$と同じ大きさにすることができます$10^{12}$。 すべてのサブ配列を生成したり、配置を明示的にシミュレートしようとしたソリューションは、非常に遅すぎます。 この制約により、完全な配列を構築する必要のない数学的または貪欲なアプローチが求められます。 また、複数のテスト ケースを効率的に処理する必要もあります。$n$すべてのテストで最大でも$5 \cdot 10^5$。 

明らかではないエッジケースが発生する場合$k$すべてのカード枚数を均等にするか、一部のカード枚数が極端に不均衡な場合に十分な大きさです。 たとえば、次の場合$n = 3$、$k = 5$、初期カウントは次のとおりです。$[1, 1, 1]$、さらに 5 枚のカードを追加できます。 最適な戦略は、すべての数値が同じ頻度で出現するようにカウントのバランスをとることです。$n$カードは 1 つの順列に寄与します。 既存のカウントのみを確認するか、すべてのコインを現在最小のカード タイプに追加する単純なソリューションでは、最大スコアが過小評価される可能性があります。 

## アプローチ

 ブルートフォースアプローチは、カードの可能なすべての追加と再配置をシミュレートし、長さの数を数えることです。$n$結果の配列内の順列。 これは原理的には正しいですが、配列サイズが超過する可能性があるため現実的ではありません。$10^{12}$、すべての部分配列を生成することは不可能です。 1 つのテスト ケースでも操作数は膨大になります。 

重要な洞察は、並べ替えの数が、コイン配布後のコピー数が最も少ないカードの種類によって制限されるということです。 各順列には各カード タイプが 1 枚必要となるため、スコアはすべてのカード タイプの最小数によって決まります。 したがって、最適な戦略は、コインを使用してカード数をできるだけ均等にし、カードの少ないタイプを優先することです。 これにより、問題は「最小値の最大化」問題に変換されます。つまり、最大の整数が必要になります。$x$コインを追加した後、各カード タイプには少なくとも$x$コピー。 貪欲なアプローチまたは二分探索を使用すると、これを効率的に解決できます。なぜなら、関数は「達成することが可能であるため」です。$x$全種類コピー?」はモノトーンです$x$。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$、$k$、および初期カウント$a_1, a_2, \ldots, a_n$。 これらは、最初に各タイプのカードが何枚あるかを表します。 
2. カウントの配列を並べ替えます。 これにより、すべての小さなカウントを目標レベルまで引き上げるのに必要なコインの数を効率的に計算できます。 
3. 目標の最小コピー数に対して二分探索を使用します。$x$、すべてのタイプにわたって。 下限を 0、上限を 0 として検索を初期化します。$\max(a) + k + 1$, これは、1 つのタイプにすべてのコインを費やした場合に達成可能な最大数です。 
4. 候補者にとって$x$、以下のすべてのカウントを上げるために必要なコインの数を計算します。$x$まで$x$。 これは単純に全体の合計です$i$の$\max(0, x - a_i)$。 
5. 必要コイン数を超えた場合$k$、 それから$x$が高すぎるため、二分探索の上限を調整します。 さもないと、$x$は達成可能であるため、下限を調整します。 
6. 収束するまで二分探索を続けます。 達成可能な最大値$x$は最終的な下限です。 
7. 1回$x$が決定された場合、最大スコアはすべてのカウントの合計からマイナスされた値になります。$x \cdot (n-1)$カードの線の上に。 もっと簡単に言えば、各順列では各タイプのカードが 1 枚ずつ使用されるため、完全な順列の合計数は、コインを追加した後のすべてのタイプの中での最小数となります。 

機能する理由: 最小カウントのカード タイプにより、形成できる完全な順列の数が常に制限されます。 すべてのタイプに少なくとも$x$コピーの場合、正確に保証します$x$完全な順列を形成することができます。 再配置によって、すべてのカード タイプが利用可能な回数より多くの順列が生成されることはないため、この貪欲/二分探索アプローチが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_permutations(n, k, a):
    a.sort()
    left, right = 0, max(a) + k + 1
    while left < right:
        mid = (left + right) // 2
        required = sum(max(0, mid - count) for count in a)
        if required <= k:
            left = mid + 1
        else:
            right = mid
    # left overshoots by 1
    return left - 1

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    print(max_permutations(n, k, a))
```コードは最初にカードの枚数を並べ替えます。これにより、候補の最小値に達するために必要なコインを計算するときに、1 回のパスだけで済むことが保証されます。 二分探索により、達成可能な最小カウントの最大値と、候補の不足の合計が効率的に絞り込まれます。$x$実現可能性を決定します。 非常に大きなケースなどの特殊なケース$k$二分探索では正しい達成可能な範囲が探索されるため、均一な初期カウントは自然に処理されます。
