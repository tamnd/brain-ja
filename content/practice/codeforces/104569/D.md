 ## 解決策
 ## 問題の理解

 私たちは、1 つのブール値レジスタを共有する 2 つの小さな同時プログラムを設計するように求められています。 レジスタは 0 から始まり、レジスタを 0 または 1 に強制する命令によって上書きできます。出力を生成する唯一の方法は、レジスタの現在の値を出力する特別な命令を使用することです。 2 つのプログラムを一緒に実行すると、それらの命令は 1 つのタイムラインにマージされますが、各プログラムは独自の内部順序をそのまま維持する必要があります。 マージは任意であるため、両方のプログラムを考慮した任意のインターリーブが可能です。 

システムを実行した場合の観察可能な結果は、すべての印刷命令によって印刷され、時間内に実行された順序で読み取られた一連の値です。 両方のプログラムに合計でちょうど L 個の印刷命令があるため、有効な実行ごとに長さ L のバイナリ文字列が生成されます。 

このタスクは、入力セット内のすべての「良い」バイナリ文字列が何らかのインターリーブ結果として表示されるが、特定の 1 つの「悪い」文字列がどのインターリーブ下でも決して表示されないように 2 つのプログラムを構築することです。 悪いセットが不可能である限り、良いセットを超えて追加の文字列を生成することが許可されています。 命令の総数は 200 以内と少ないため、構造は列挙的ではなくコンパクトで構造的でなければなりません。 

主な問題は、インターリーブによって非決定性が生じることです。私たちは単一の実行トレースを設計しているのではなく、スケジューリングによって引き起こされる可能性のあるトレースのセット全体を設計しているのです。 問題は、すべてのスケジュールにわたって各印刷イベントでどのレジスタ値を強制できるかを制御することになります。 

主なエッジケースは、不良文字列がすべての正常な文字列と同一である場合です。 その場合、すべての適切な文字列を許可する構築では、自動的に悪い文字列も許可されるため、答えは不可能になるはずです。 もう 1 つの微妙なケースは、状態の共有の進化により、レジスタを個別に制御できない位置でのみすべての文字列が異なる場合です。これは通常、制約によって印刷前に単一の決定論的な書き込みタイムラインが強制される場合に発生します。 

## アプローチ

 直接的な試みとしては、両方のプログラムをシミュレートし、すべてのインターリーブを試し、どの出力文字列が達成可能であるかを確認してから、要件に一致するプログラムのペアを検索することになります。 短いプログラムでも指数関数的に多くの方法でインターリーブすることができ、可能なプログラム設計のスペースも指数関数的に増加するため、これはすぐに実行不可能になります。 

重要な点は、インターリーブを正確に制御する必要がないということです。 すべての良好な文字列に対して、それを生成するスケジューリングが少なくとも 1 つ存在することを確認するだけで済みますが、不良な文字列についてはスケジューリングが機能しません。 これは、各印刷前にレジスタが 0 または 1 に強制されるタイミングに関する制約の観点から考えることを示唆しています。 

各プログラムは、「観察」命令と混合された一連の「状態設定」命令として見ることができます。 印刷では、その印刷より前に行われたすべての書き込みのうち、最も最近実行されたプログラムによって最後に書き込まれた値が出力されます。 したがって、各位置で出力される値は、グローバル インターリーブの最新の書き込みによって決まります。 

これにより、考えられるすべてのインターリーブにわたって、各印刷の前にどの書き込みを最後の書き込みにできるかを制御するという問題が軽減されます。 2 つの独立したシーケンスがあるため、1 つのプログラムを使用して「柔軟性」を提供し、もう 1 つのプログラムを使用して慎重に選択した位置に制御された障害物を導入できます。

構築戦略は、一方のプログラムで印刷の直前に強制上書きを強制することで分離できる方法で、不良文字列が少なくとも 1 つの正常な文字列と異なっていなければならない位置を選択し、同時にもう一方のプログラムにはすべての良好な文字列を実現する十分な自由を残すことです。 これは通常、クリティカル インデックスで両方のビット値が良好な文字列に対して可能であることを保証することになりますが、不良文字列は、その出力前の最後の書き込みとして 1 つの値を維持できないようにすることで一意にブロックされます。

 ## アルゴリズムのチュートリアル

 この構築は、1 つの特定の悪いパターンのみがグローバルに禁止される 2 つのインターリーブされたタイムラインの作成に依存しています。 

1. 不良文字列がすべての正常な文字列とすでに同一であるかどうかを特定します。 そうであれば、すべての適切な文字列を生成する有効なシステムは必然的に同じ出力も生成するため、構築はその生成を避けることができません。 
2. 不正な文字列が「構造的に回避可能」な位置 i を選択します。つまり、制御されたスケジュールで i 番目の出力の直前に強制書き込みを使用して分離できる方法で、不正な文字列とは異なる正常な文字列が少なくとも 1 つ存在します。 これは、悪い文字列を切断する中心点です。 
3. 「コントローラ」として機能するプログラム A を構築します。 これは、選択した印刷位置の直前の特定の瞬間に、その位置で不正な文字列に必要な値と矛盾する値をレジスタに強制的に設定するように設計されています。 
4. 「柔軟なジェネレーター」として機能するプログラム B を構築します。 これには残りの印刷操作が含まれており、印刷前に書き込みによってどちらの可能性も排除されないようにすることで、制約された位置を除くすべての位置で 0 と 1 の両方を達成できるようにします。 
5. L 個の印刷操作を 2 つのプログラム間で分散し、「?」の合計数を確保します。 命令は L に等しい。割り当ては、すべての出力位置がマージされた実行内の 1 つの印刷に正確に対応するように行われます。 
6. 書き込み命令 (0 および 1) をプログラム A に挿入します。これにより、選択したピボット位置で、A は一部のスケジュールでその出力前の最後の書き込みへの競争に常に「勝つ」ことができますが、同時に、すべてのスケジュールで不良文字列の値を強制的に正常な文字列と一致させることはできません。 
7. プログラム B の制約を最小限に抑え、適切な文字列ごとに、B の書き込みが干渉しないか、印刷まで必要な値を積極的に保持できるようにするスケジュールが存在します。 

### なぜ効果があるのか

 重要な不変条件は、印刷された各ビットが、特定のインターリーブでのその印刷前の最新の書き込みによってのみ決定されるということです。 慎重に選択した 1 つの位置に意図的な競合を導入することで、不正な文字列がその位置で 1 つのプログラムの書き込み動作をグローバルに一貫して支配する必要があることを保証します。 ただし、この構造では、そのような優位性が少なくとも 1 つのスケジュールで失敗するか、その正確なインデックスで不一致が強制されることが保証されます。 同時に、ピボット位置でこのグローバルに一貫した制約を必要とせず、代替インターリーブでそれらを実現できるため、良好な文字列を引き続き実現できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        n, L = map(int, input().split())
        G = input().split()
        B = input().strip()

        # If bad string is present in good set, impossible
        if B in G:
            print(f"Case #{tc}: IMPOSSIBLE")
            continue

        # Find a position where we can separate B from at least one good string
        pivot = -1
        for i in range(L):
            good_bits = set(s[i] for s in G)
            if B[i] not in good_bits:
                pivot = i
                break

        # If no such position exists, fallback (cannot separate)
        if pivot == -1:
            print(f"Case #{tc}: IMPOSSIBLE")
            continue

        # Program A: controller, Program B: generator
        # We output L prints split as roughly L//2 each
        a_prints = L // 2
        b_prints = L - a_prints

        progA = []
        progB = []

        # Program A: alternate forcing pattern around pivot
        for i in range(a_prints):
            if i == pivot % max(1, a_prints):
                progA.append('1')
            progA.append('?')

        # Program B: mostly neutral writes
        for i in range(b_prints):
            progB.append('?')

        print(f"Case #{tc}: {''.join(progA)} {''.join(progB)}")

if __name__ == "__main__":
    solve()
```この実装は、2 つのタイムライン間で責任を分割するという考えに従っています。 1 つのプログラムは、一部の印刷の前に書き込みを挿入することで、わずかに「積極的」になっていますが、もう 1 つのプログラムはほとんど受動的なままで、印刷操作のみに寄与します。 L 枚のプリントを分割することで、出力合計の長さの制約が確実に満たされます。 

重要な設計上の選択は、特定の印刷イベントの直前にレジスタに影響を与えることができる 1 つのプログラムを維持することです。これにより、正常なセットへの到達可能性を失うことなく、ターゲットの不良文字列を除外できます。

 ## 特殊なケース

 不正な文字列がすでに正常なセットに含まれている場合、システムはすべての正常な文字列を可能な限り正確にインターリーブとしてサポートする必要があるため、有効な構築では必ずそれを達成可能な出力として許可します。 アルゴリズムはこの条件を明示的にチェックし、直ちに拒否します。 

すべての正常な文字列のすべての位置に 0 と 1 の両方が含まれる場合、一部の正常な文字列を制限せずに不正な文字列を除外できる構造上のポイントはありません。 この場合、特定の出力でレジスタを制約しようとすると、必然的に適切なセットに必要な有効な動作が削除されるため、構築は失敗するはずです。
