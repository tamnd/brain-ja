 ## 解決策
 ## 問題の理解

 色付けタスクというよりは、グリッド内に隠されたグラフ上の有向伝播システムのように動作するグリッド問題が与えられます。 

の各セル$n \times n$グリッドには、水平または垂直の方向が含まれます。 選択したセルから、その方向に応じた操作を実行します。セルが水平を示している場合はその行全体がアクティブになり、垂直を示している場合はその列全体がアクティブになります。 目標は、グリッド内のすべてのセルが少なくとも 1 回アクティブになるようにセルのシーケンスを選択することであり、そのような選択の数を最小限に抑えたいと考えています。 

これを言い換えると、各操作でノードが選択され、そのノードはタイプに応じてその行のすべてのノードまたはその列のすべてのノードを「カバー」するということです。 課題は、すべてを確実にカバーすることです。$n^2$可能な限り少ない選択を使用するノード。 

ここでは入力サイズの制約が重要です。すべてのテスト ケースにわたるグリッド領域の合計は最大でも約 2 です。$10^3$、各グリッドは最大$1000 \times 1000$。 これにより、二次関数は即座に除外されます。$n^2$、それはすでにそうなっているので、$10^6$テストケースごとに実行され、複数のケースにわたって乗算すると遅すぎます。 平$O(n^3)$アプローチは実行不可能です。 ソリューションは基本的にグリッドを一定の回数検査し、貪欲に、または構造分解を通じて答えを構築する必要があります。 

単純な推論を破る傾向がある重要なエッジ ケースは、ローカルの貪欲な選択により、カバーされていないセルが削減されているように見えても、実際には後で追加の操作が強制される場合です。 たとえば、行が垂直方向の選択によってほぼ完全にカバー可能であるにもかかわらず、1 つのセルの位置がずれている場合、貪欲なソルバーはその行を早期に「修正」する操作を選択し、追加の列操作が必要になる可能性があります。 

これを示す小さな例は次のとおりです。```
n = 2
VH
HV
```素朴な貪欲なアプローチでは、行 1 と列 1 の両方に役立つと考えて (1,1) を選択し、次に (2,2) を選択する可能性があります。しかし、カバレッジの方向の解釈によっては、カウントしすぎたり、単一の操作の最適な再利用を見逃したりする可能性があります。 正しい答えは 2 ですが、多くの貪欲なバリアントでは、行と列の決定を結合された構造としてではなく独立して扱うため、誤って 3 が生成されます。 

さらに深刻な問題は、各セルが単なるターゲットではなく、「カバレッジの方向」の選択でもあり、それらの方向がグローバルに相互作用することです。 

## アプローチ

 ブルート フォースのアイデアは単純です。各セルを可能な操作として扱い、操作のすべてのサブセットをシミュレートします。 各サブセットはアクティブになる行または列のセットを定義し、これらの結合がグリッド全体をカバーするかどうかを確認します。 これは、考えられるすべての選択を徹底的に調査するため、正しいです。 

However, the state space is$2^{n^2}$、そしてさらには$n = 10$、これはすでに天文学的な規模です。 正確に選択することに限定しても$k$オペレーションは依然として～につながる$\binom{n^2}{k}$、管理不能です。 

重要な構造的観察は、グリッドが 2 つの独立したカバレッジ システム (水平セルによって引き起こされる行カバレッジと垂直セルによって引き起こされる列カバレッジ) に分解されることです。 各操作は、カバレッジの 1 つの軸にのみ影響します。つまり、この問題は、すべての行と列が少なくとも 1 つの互換性のある方法で「タッチ」されることを保証することに相当します。 これが確認されると、グリッドは 2D オブジェクトではなくなり、行と列の間の 2 部構成の相互作用になります。 

セルをカバーするという観点から考えるのではなく、すべての行または列に少なくとも 1 つの有効な「アクティブ化セル」があることを確認することに移行します。 これにより、問題は代表的なアクティベーションの最小セットの選択に変わります。方向の一貫性が確保されれば、各行または列を独立して満たすことができるため、貪欲に構築できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース |$O(2^{n^2} \cdot n^2)$|$O(n^2)$| 遅すぎる |
 | 構造的な貪欲な構築 |$O(n^2)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 この構築は、グリッドをスキャンし、制御された方法で行または列のいずれかをカバーすることを「約束する」操作を決定することに依存しています。 

1. まず、行カバレッジに寄与するか列カバレッジに寄与するかに基づいて各セルを分類します。 水平セルはその行をアクティブ化できる候補として扱われ、垂直セルはその列をアクティブ化できる候補として扱われます。 各操作の影響の方向が固定されているため、この分離が必要です。 
2. 次に、どの行と列がまだカバレッジを必要としているかを追跡します。 まだ操作が実行されていないため、最初はすべての行と列が表示されます。 
3. グリッドを繰り返し処理し、覆われていない構造をカバーできる方向のセルに遭遇するたびに、それを操作として選択します。 水平の場合、その行をカバー済みとしてマークします。 垂直の場合、その列をカバー済みとしてマークします。 
4. 操作を選択した後、概念的にその効果を直ちに伝達します。つまり、その行または列内のすべてのセルを明示的に更新するわけではありません。 代わりに、対象となる行と列の簿記セットを維持します。 
5. すべての行または列が間接的にすべてのセルに到達することが保証される方法でカバーされるまで、このプロセスを続けます。 

重要な考え方は、すでに満足した構造を決して再検討しないことであり、これにより冗長な操作が防止されます。 

### なぜ効果があるのか

 不変条件は、どの時点においても、カバーされていないすべての行または列には、前の選択と矛盾することなく条件を満たすことができる候補セルが少なくとも 1 つあるということです。 各操作は、システムから行または列のいずれか 1 つの自由度を正確に削除し、その必要性が再導入されることはありません。 行と列は、一度コミットされると依存関係のサイクルがない 2 部構成のカバー システムを形成するため、貪欲な選択によって後で追加の操作が必要になるという罠に陥ることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [input().strip() for _ in range(n)]

    row_used = [False] * n
    col_used = [False] * n
    ops = []

    for i in range(n):
        for j in range(n):
            if g[i][j] == 'H':
                if not row_used[i]:
                    row_used[i] = True
                    ops.append((i + 1, j + 1))
            else:
                if not col_used[j]:
                    col_used[j] = True
                    ops.append((i + 1, j + 1))

    print(len(ops))
    for x, y in ops:
        print(x, y)

if __name__ == "__main__":
    solve()
```この実装は、各行と列に必要なトリガー操作が 1 つだけであるという事実に依存しています。 ブール配列により、同じ構造要件の重複選択が防止されます。 

最もデリケートな部分は、過剰な選択を避けることです。`row_used`そして`col_used`の場合、アルゴリズムは行または列ごとに複数のセルを選択し、カバレッジを向上させることなく答えを水増しします。 

インデックス作成もエラーの一般的な原因です。 出力は 1 ベースですが、内部処理は 0 ベースなので、放出時にすべての座標を一貫して調整する必要があります。

 ## 特殊なケース

 まれなケースとして、行と列の両方が矛盾する方向で繰り返し表示される場合が発生します。 アルゴリズムは競合を「解決」しようとせず、行または列ごとに最初に成功したトリガーのみを記録するため、このアルゴリズムは引き続きこれを正しく処理します。 行に多くの水平セルが含まれている場合でも、必要なのは 1 つだけであり、後続のセルは無視されます。 

もう 1 つのエッジ ケースは、完全に垂直セルまたは完全に水平セルで埋められたグリッドです。 垂直のみの場合は、すべての列に 1 回の操作が適用され、同様に水平のみのグリッドの場合は、すべての行が 1 回処理されます。 各構造単位は最初のアクティブ化の直後に使用済みとしてマークされるため、アルゴリズムはオーバーカウントしません。 

最後のケースは、すべてのセルの向きが交互になる市松模様のパターンです。 アルゴリズムは行トリガーと列トリガーを交互に実行しますが、`used`配列により、行や列が 2 回アクティブ化されないことが保証され、演算の二次爆発が防止されます。
