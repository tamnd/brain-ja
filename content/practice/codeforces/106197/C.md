 ## 解決策
 ## 問題の理解

 この問題は、割り算の順序に従って指定された整数のすべての約数によって形成される構造を中心に展開します。 数値を取得し、それを割るすべての整数をリストすると、これらの約数は自然にグラフのような構造を形成します。各約数は、単一の素因数のべき乗を増加することによって得られる「より大きな」約数に接続できます。 

より具体的には、約数を、各軸が数値の素因数に対応するグリッド内の点として考えます。 各約数は、その中に各素数が何回出現するかによって表されます。 ある約数から別の約数への移動は、他のすべての指数を変更せずに、正確に 1 つの素数の指数を 1 ステップずつ増加する場合にのみ許可されます。 タスクは、このような直接的な「1 段階の増加」がこの構造内にいくつ存在するかを計算することです。 

入力は 1 つの整数で構成され、その約数構造を分析している数値です。 出力は、この除数グラフのエッジの数を表す 1 つの整数です。因数分解の範囲内でまだ利用可能な 1 つの素因数を正確に乗算することで一方の除数をもう一方の除数から取得できる場合、エッジは 2 つの約数を接続します。 

主な制約の意味は、数値自体が大きくなり、すべての約数を明示的に列挙することが不可能になる可能性があることです。 中程度の値であっても、除数の数は倍増する可能性があり、完全な除数グラフを構築するには、そのサイズに比例して時間がかかります。 これにより、約数を列挙するのではなく、素因数分解を直接操作するようになります。 

いくつかのエッジケースは、素朴な思考が失敗する場所を明らかにします。 数値が素数の場合、たとえば 13 の場合、約数は 1 と 13 の 2 つだけで、それらの間にはエッジが 1 つだけあります。 より多くの構造を想定する単純なアプローチでは、複数の遷移が誤ってカウントされる可能性がありますが、可能となるのは 1 つの素因数の増加のみです。 

2⁴ である 16 のような数値の場合、約数は 1、2、4、8、16 です。構造は単純なチェーンであり、エッジがちょうど 4 つあります。 誤って約数を指数の増分ではなく独立した組み合わせとして扱うアプローチは、線形構造を誤ってカウントすることになります。 

12 = 2² · 3¹ のような帯分数の場合、約数構造は 2 次元になります。 除数ごとに乗算の選択肢のみをカウントするが、各状態が複数の出力エッジに寄与することを忘れた単純な方法では、アンダーカウントされてしまいます。 

## アプローチ

 ブルートフォースアプローチでは、数値のすべての約数を明示的に生成し、各約数に対して、結果を元の数値内に維持するすべての素数の乗算を試みます。 これには、最初に約数を列挙する必要があり、これ自体に O(d(n)) 時間がかかります (d(n) は約数の数です)。 各約数について、遷移のチェックには最大 O(log n) かかる可能性があり、総コストは約 O(d(n) log n) になります。 高度に合成された数などの最悪のケースでは、d(n) が大きくなり、これが実行不可能になります。 

重要な構造的洞察は、除数のセットが任意ではないということです。 数値が素因数分解形式で書き込まれると、すべての約数が各素数の指数の選択に対応します。 グラフのエッジは、まさにこれらの指数ベクトルの増分です。 グラフを構築する代わりに、遷移を組み合わせてカウントすることができます。 

指数 aᵢ を持つ素因数 pᵢ の場合、すべての約数は pᵢ の指数を 0 から aᵢ − 1 まで増加させることができます。そのような選択ごとに、他の素数は固定されたままであり、独立した組み合わせに寄与します。 これにより、問題はデカルト積の次元にわたる寄与の合計に変わり、明示的な列挙の必要性がなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(d(n) log n) | O(d(n)) | 遅すぎる |
 | 最適 | O(√n + k²) (or Pollard Rho factorization) | O(k) | 承認済み |

ここで、k は異なる素因数の数です。 

## アルゴリズムのチュートリアル

 1. 入力数値を素数累乗 n = p₁ᵃ¹ · p₂ᵃ² · ... · p_kᵃᵏ に因数分解します。 

これは、約数の構造全体がこれらの指数にのみ依存するため必要です。 
2. 各素因数 pᵢ について、エッジへの寄与を aᵢ に他のすべての素数の指数を選択する方法の数 (Π_{j ≠ i} (aⱼ + 1)) を乗算して計算します。 

これは、除数の状態を固定し、pᵢ の指数を何回増分できるかをカウントすることに対応します。 
3. すべての素因数にわたるこれらの寄与の合計を累積します。 
4. 最終的な合計を出力します。 

ステップ 2 が有効である理由は、各エッジが、指数がまだ最大になっていない約数と素数の選択に一意に対応するためです。 このようなすべての選択は、正確に 1 つの有効な隣接除数に対応し、増加する素指数が遷移を一意に識別するため、エッジが 2 回カウントされることはありません。 

### なぜ効果があるのか

 各約数は、指数ベクトル (x₁、x₂、...、x_k) によって完全に決定されます。 エッジは、境界内に留まりながら 1 つの座標を正確に 1 増やすことによって、あるベクトルから別のベクトルに移動するときに存在します。 固定座標 i の場合、すべての有効な開始ベクトルは [0, aᵢ − 1] に xᵢ を持ち、他のすべての座標はその範囲内で自由になります。 これにより、次元 i に対して正確に aᵢ · Π_{j≠i}(aⱼ+1) 個の有効なエッジが作成されます。 すべての次元を合計すると、すべての可能なエッジが 1 回だけカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def factorize(n: int):
    res = {}
    d = 2
    while d * d <= n:
        while n % d == 0:
            res[d] = res.get(d, 0) + 1
            n //= d
        d += 1
    if n > 1:
        res[n] = res.get(n, 0) + 1
    return res

def solve():
    n = int(input().strip())
    pf = factorize(n)

    exps = list(pf.values())
    k = len(exps)

    ans = 0
    for i in range(k):
        contrib = exps[i]
        for j in range(k):
            if i != j:
                contrib *= (exps[j] + 1)
        ans += contrib

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、試行除算を使用して数値を因数分解することから始まります。 入力サイズが中程度であると仮定すると、これで十分です。 制約が大きい場合は、残りのロジックを変更せずに、より高速な因数分解メソッドがこのステップを置き換えます。 

指数が抽出されると、コードは組み合わせ式を直接実装します。 各素数指数について、他のすべての素数に対する (aⱼ + 1) の積を計算し、aᵢ を掛けます。 これは、素数をインクリメントできる有効な除数の状態を選択する方法の数を反映しています。 

微妙な点は、除数や辺を明示的に構築しないことです。 すべてのカウントは指数空間で行われるため、組み合わせ爆発が回避されます。 

## 実用的な例

 ### 例 1: n = 12

 ここで 12 = 2² · 3¹ なので、指数は [2, 1] になります。 

| ステップ | 素数インデックス i | 貢献度計算式 | 値 |
 | --- | --- | --- | --- |
 | 1 | 2 | 2 * (1 + 1) | 4 |
 | 2 | 3 | 1 * (2 + 1) | 3 |

 合計の答え = 7。 

このトレースは、各素数次元がどのように独立して寄与するか、また他の次元が乗法選択要素としてどのように機能するかを示します。 

### 例 2: n = 16

 ここで 16 = 2⁴ なので、指数は [4] です。 

| ステップ | 素数インデックス i | 貢献度計算式 | 値 |
 | --- | --- | --- | --- |
 | 1 | 2 | 4 | 4 |

 合計の答え = 4。 

これは、除数格子が単純なチェーンになる、縮退した 1 次元のケースを裏付けます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(√n + k²) | 試行除算因数分解とペアワイズ指数集計 |

    return solve()

 ## 特殊なケース

 n = 1 の場合、因数分解は空であるため、指数次元はありません。 このアルゴリズムは空の合計を生成し、正しく 0 を返します。これは、除数格子には単一のノードがありエッジがないという事実と一致します。 

17 のような素数の場合、因数分解には 1 つの指数が含まれます [1]。 唯一の寄与は 1 で、これは 1 から 17 までの単一のエッジに対応します。ループは、特別なケースを使用せずにこれを適切に処理します。 

2³ · 3² のような数値の場合、アルゴリズムは両方の次元からの寄与を明示的にカウントします。 2 に注目すると、2 つの遷移については 3 つの指数の選択肢があり、3 次元については 3 つの選択肢があり、2 によって寄与される 3 · 3 = 9 つのエッジが得られます。対称的に、3 次元は 2 · 4 = 8 つのエッジに寄与します。 各エッジはどの座標が変化するかによって一意に識別されるため、合計は重複することなく遷移の完全なグリッドをキャプチャします。
