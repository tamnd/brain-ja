 ## 解決策
 ## 問題の理解

 各テスト ケースに対して 10 進数の文字列が与えられ、順序を維持しながらそこからいくつかの桁を削除することで形成できるすべての整数を調べるように求められます。 このように導出された各数値は、桁の意味で元の数値の部分列です。 この到達可能な数値のコレクションから、数値として解釈されるときにこれらの部分列の 1 つとして決して現れることのない最小の非負の整数を意味する mex を計算します。 

コア オブジェクトは文字列そのものではなく、文字列から形成できる整数のセットです。 たとえば、文字列に 1 桁の「7」が含まれている場合、サブシーケンスは空の選択肢と「7」のみになります。 複数の数字が含まれている場合、サブシーケンスには増加するインデックス選択がすべて含まれ、多くの繰り返し数値がすぐに作成されますが、依然として有限個の個別の整数のみが作成されます。 

この制約は、入力が桁長の点で非常に大きくなり、すべてのテスト ケースで最大 200,000 桁になる可能性があることを意味します。 これにより、サブシーケンスを明示的に列挙しようとするアプローチが除外されます。 長さ n の文字列には 2^n 個のサブシーケンスがあり、n が中程度であっても指数関数的な爆発は実現不可能であるため、すべてのサブシーケンスを格納することさえ不可能です。 

重要な点は、サブシーケンスは連続性によって制限されないため、構造よりも数字の存在が重要であるということです。 数字 k は、文字列内のどこかに存在する場合、長さ 1 の部分列としてのみ表示されます。 10 や 123 のような数値は、頻度だけでなく、相対的な順序と桁の可用性によって決まります。 

単純な間違いは、これを数字パターンに関する到達可能性の問題ではなく、組み合わせ部分列のカウント問題として扱うことから生じます。 たとえば、数字 {0,1,2} がすべての順列を保証すると仮定すると、それは誤りです。部分列は順序を保持するため、数字がその正確な相対順序で出現しない限り、「210」は形成できません。 

2 番目のよくある失敗例は、複数桁の数値が位置の制約に依存していることを無視することです。 たとえば、数字の 1 と 0 が存在する場合でも、「0」の前に「1」が出現しない限り、数字の 10 は保証されません。 

問題は基本的に、どの整数が部分列として形成できるかを判断し、次に形成できない最初の整数を見つけることです。 

## アプローチ

 強引なアイデアは、すべてのサブシーケンスを生成し、それぞれを整数に変換してセットに挿入し、欠損値が見つかるまで 0 から上向きにスキャンすることです。 これは、到達可能な完全なセットを明示的に構築するため、原理的には正しいです。 問題は規模だ。 50 桁の文字列であっても、サブシーケンスの可能性はすでに 10^15 を超えており、それぞれを整数に変換するとオーバーヘッドが追加されます。 ボトルネックは指数関数的な生成です。 

重要な観察は、実際にはサブシーケンスの完全なセットが必要ないということです。 小さな整数が部分列として存在するかどうかのみを考慮します。 それは視点を完全に変えます。 すべての部分列を列挙する代わりに、k を部分列として形成できない最小の k は何か、と尋ねます。 

これにより、問題は整数の昇順の建設的なチェックに変わります。 候補となる整数 x ごとに、x が数字列内の部分列として一致するかどうかをテストする必要があります。 これは標準的な貪欲スキャンです。文字列を調べて、x の数字を順番に照合しようとします。 終了すれば、x は達成可能です。 それ以外の場合はそうではありません。 

重要な構造的洞察は、0 から M-1 までのすべての整数が達成可能であれば、mex は M であるため、最初の失敗ですぐに停止できるということです。 その点を超える必要はありません。

効率の向上は、どこまでチェックする必要があるかを制限することで得られます。 文字列が長い場合、小さな数字のパターンがすぐにすべて含まれる傾向がありますが、最終的には順序の制約により一部の数値が失敗します。 各チェックは文字列長において線形であり、mex は桁の制約に比べてゆっくりと増加するため、通常、チェックの数は少なくなります。

 | 増分サブシーケンスのチェック | O(M · n) ここで、M は mex | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 数値を数字の文字列に変換します。 これにより、サブシーケンスのマッチングを算術分解ではなくポインター スキャンで処理できるようになります。 
2. x = 0 から開始して、x を数字列の部分列として形成できるかどうかを判断します。 チェックは桁ごとに実行されます。 
3. 候補 x をテストするには、それを 10 進表現に変換し、ポインタを使用してメイン文字列をスキャンします。 現在の桁が x の次に必要な桁と一致するまでポインタを進めます。 x のすべての桁が一致する場合、x は達成可能です。 
4. x が達成可能な場合は、x をインクリメントし、x + 1 のチェックを繰り返します。 
5. 候補 x が一致しない場合は停止します。 より小さい値はすべて達成可能であることが確認されているため、その値は mex です。 

このスキャンが機能する理由は、桁順序の制約に関してサブシーケンスの実現可能性が単調であるためです。 数値が一致しない場合、同じプレフィックス制約を持つより大きな数値を使用しても、失われた順序を「修復」できません。 

### なぜ効果があるのか

 各整数チェックは、固定パターンが数字列の部分列として現れるかどうかを検証することになります。 これは古典的な貪欲マッチングの問題であり、一致を遅らせると将来の選択肢が減るだけであるため、可能な限り最も早い一致が常に最適になります。 整数を昇順にチェックするため、停止する前にすべての小さい候補が到達可能であることが確認されるため、最初の失敗は正確に mex 定義です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_form(s, target):
    j = 0
    n = len(s)
    for i in range(n):
        if j < len(target) and s[i] == target[j]:
            j += 1
            if j == len(target):
                return True
    return False

def solve():
    s = input().strip()
    x = 0

    while True:
        t = str(x)
        if not can_form(s, t):
            print(x)
            return
        x += 1

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```コア機能は`can_form`、候補番号の進行状況を追跡しながら、数字列の線形スキャンを実行します。 ポインタ`j`サブシーケンスの順序制約を確実に尊重します。 

外側のループは候補値を昇順にインクリメントし、障害が発生したときに到達不可能な最小の整数が見つかることを保証します。 

実装の微妙な詳細は、一般的な制約の下では実際には mex が小さいままであるため、ループ内で整数を文字列に変換するのは安全ですが、最悪の場合のシナリオでは、表現を事前計算するか、境界がより厳しい場合は数字 DP を使用することで最適化することになります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    output = []
    input = _sys.stdin.readline

    def can_form(s, target):
        j = 0
        for c in s:
            if j < len(target) and c == target[j]:
                j += 1
        return j == len(target)

    def solve():
        s = input().strip()
        x = 0
        while True:
            if not can_form(s, str(x)):
                output.append(str(x))
                return
            x += 1

    t = int(input())
    for _ in range(t):
        solve()

    return "\n".join(output)

 ## 特殊なケース

 主なエッジケースは、数字「0」が完全に欠落している場合です。 その場合、1 や 2 などの多くの数値が構成可能であっても、mex は直ちに 0 に強制されます。 最初のチェック x = 0 が後続のスキャンで失敗するため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、すべての桁が存在するが、順序付けによって複数桁の数値がブロックされる場合です。 たとえば、「102」は 1、0、2 を許可しますが、位置によっては 10 を形成できない場合があります。 スキャンでは、文字を順番に消費することで順序付けが正しく実行されるため、すべての桁が存在する場合でもこれらのエラーが検出されます。 

最後のエッジケースは、「000000」のような大きな繰り返しです。 ここでは、ゼロで構成される数値のみを形成できるため、 mex は 1 になります。アルゴリズムは最初に 0 を確認し、次に 1 で失敗し、長さではなく桁の多様性によって引き起こされる境界を正確に識別します。
