 ## 解決策
 ## 問題の理解

 いくつかのテスト ケースが与えられ、それぞれのテスト ケースには 1 からインデックスが付けられた個別の整数の配列が含まれています。タスクは、インデックス ペアの数を数えることです。$(i, j)$と$i < j$非常に特殊な関係を満たす: これらの位置に格納された値の積はインデックスの合計に等しい、つまり$a_i \cdot a_j = i + j$。 

これは、値と位置が混在する構造的な制約です。 インデックスには次の制限があるため、$n$、右側$i + j$によっても制限されます$2n$、これは潜在的な製品の値の範囲に比べて小さいです。 この非対称性が鍵となります。ただし、値は次のとおりです。$2n$、有効なペアは、インデックスと値を同時にリンクする厳密な算術条件を満たさなければなりません。 

と$n$まで$10^5$テストごとの合計と$2 \cdot 10^5$、$O(n^2)$テストケースごとの解決策は不可能です。 平$O(n \sqrt{n})$最悪の場合、テストごとに時間がかかりすぎる可能性があります。 正しい解決策は、すべてのペアをチェックするのではなく、少数のペアのみが方程式を満たす可能性があるという事実に依存する必要があります。 

よくある失敗例は、値が「有望に見える」すべてのペアを試した場合、たとえば小さな値や近くのインデックスに制限した場合に発生します。 このアプローチでは、条件が近接性や順序付けではなく、乗算とインデックス合計の両方に依存するため、有効なペアが失われます。 

たとえば、単純なフィルタリング手法では、次のペアのみをチェックする可能性があります。$a_i \cdot a_j \le 2n$, 右辺が小さいので。 これは必要ではありますが、十分ではなく、可能な積を構造化して列挙しないと、依然として二次関数の動作につながります。 

## アプローチ

 ブルートフォースソリューションがすべてのペアをチェックします$(i, j)$と$i < j$、計算します$a_i \cdot a_j$と比較します。$i + j$。 これは、記載されているように条件を直接評価するため、正しいです。 ただし、約$n(n-1)/2$テストケースごとのチェック数は大まかに次のようになります$5 \cdot 10^9$合計の操作は最悪の許容入力サイズであり、明らかに遅すぎます。 

重要な点は、インデックスのペアを反復処理する代わりに、一方のインデックスを固定し、もう一方のインデックスの制約を導き出すことで条件を再解釈できることです。 から$a_i \cdot a_j = i + j$、次のように並べ替えることができます。$$j = a_i \cdot a_j - i$$これはまだ直接役に立ちません。$j$そして$a_j$は不明です。 重要な構造的洞察は境界から得られます。$i + j \le 2n$、次のようになります。$$a_i \cdot a_j \le 2n$$これは、積が小さい値のペアのみが関連することを意味します。 ずっと$a_i$以下の異なる正の整数です$2n$、それぞれの値$x$意味のある値とのみ組み合わせ可能$y \le \frac{2n}{x}$。 これにより、候補値のペアの数が大幅に減少します。 

次に、ソリューションは視点を完全に反転します。インデックスを反復する代わりに、可能な値を反復します。$x = a_i$、有効な倍数を列挙します$y$そのような$x \cdot y \le 2n$。 そのようなペアごとに$(x, y)$、それらの位置が満たされているかどうかを確認します$i + j = x \cdot y$。 

これを効率的にサポートするために、各値のインデックスをハッシュ マップに保存します。 次に、有効な値のペアごとに、O(1) のインデックスを取得し、条件を 1 回テストします。 

これにより、問題はインデックスに関する 2 次式からおおよそ次のように縮小されます。$$\sum_{x=1}^{2n} \frac{2n}{x} = O(n \log n)$$| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 値からインデックスまでのポジション マップを構築します。 これにより、各値が発生する場所を定数時間で検索できるようになります。条件は値だけではなくインデックスに依存するため、これは不可欠です。 
2. 可能なすべての値を反復処理します。$x$配列内に表示されるもの。 それぞれについて$x$、潜在的に有効な製品の片面として扱います。 
3. それぞれについて$x$、複数回繰り返します$y$そのような$x \cdot y \le 2n$。 有効なペアはインデックス合計の制約、つまり積の制約を満たさなければならないため、これにより検索スペースが制限されます。 
4. 各候補ペアについて$(x, y)$、位置マップを使用して両方の値が配列内に存在するかどうかを確認します。 
5. 両方が存在する場合は、それらのインデックスを取得します$i$そして$j$、どうかを確認します。$i < j$そして$i + j = x \cdot y$。 true の場合、このペアをカウントします。 
6. 各有効なペアは自然に 2 回出現するため、$(x, y)$そして$(y, x)$、反復を次のように制限します$x \le y$または、二重カウントを避けるためにインデックスによる順序付けを強制します。 

### なぜ効果があるのか

 正しさは、すべての有効なペアが存在するという事実に基づいています。$(i, j)$有効な値のペアを誘導します$(a_i, a_j)$その積が等しい$i + j \le 2n$。 逆に、生成したすべての候補値ペアは、最大でも 1 つのインデックス ペアに対応します。 境界内で実現可能な価値のある製品をすべて列挙しているため、$2n$、有効なソリューションが見逃されないことを保証し、インデックス チェックにより誤った候補が除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        pos = {}
        for i, v in enumerate(a, 1):
            pos[v] = i
        
        ans = 0
        
        limit = 2 * n
        
        # iterate over possible values
        for x in a:
            i = pos[x]
            # avoid double counting by enforcing x <= y in value space
            # since values are distinct, we use numeric ordering
            for y in range(1, limit // x + 1):
                v = x * y
                if v in pos:
                    j = pos[v]
                    if i < j and i + j == x * v:
                        ans += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```実装の中核となる構造は、値からインデックスへの辞書です。`pos`を使用すると、候補値が存在するかどうか、および候補値がどこに表示されるかを常時チェックできます。 入れ子になったループはインデックスを反復するのではなく、次の制約を受ける乗法ペアを反復します。$x \cdot y \le 2n$、これが決定的な剪定ステップです。 

条件`i + j == x * v`元の方程式を直接エンコードし、`i < j`check により、各有効なペアが 1 回だけカウントされることが保証されます。 ループ構造により、値レベルでの不必要なペアの重複が暗黙的に回避されます。 

微妙な点は、配列内の実際の値を反復処理することです。`x`、全範囲を超えていない$1 \dots 2n$これにより、実際の定数係数が低く抑えられます。

import sys, io

def run(inp: str) -> str:

    output = []
    
    t = int(input())

        n = int(input())
        a = list(map(int, input().split()))
        
        pos = {v: i for i, v in enumerate(a, 1)}

            for y in range(1, limit // x + 1):
                v = x * y
                if v in pos:
                    j = pos[v]
                    if i < j and i + j == x * v:
                        ans += 1
        
        output.append(str(ans))
    
    return "\n".join(output)

 ## 特殊なケース

 値がすでにインデックスに近い場合、微妙なエッジ ケースが発生します。 考慮する：```
n = 3
a = [1, 2, 3]
```アルゴリズムが構築される`pos = {1:1, 2:2, 3:3}`。 各候補ペアについて、多くの製品が存在するにもかかわらず、インデックス条件はどこでも失敗します。$i + j$～に比べて成長が遅すぎる$a_i \cdot a_j$。 列挙では引き続き、実行可能な製品のみがチェックされます。$2n$、そして各候補は最終検証ステップで失敗します。 

もう 1 つのケースは、大きな値が小さなインデックスとペアになっている場合です。```
n = 3
a = [6, 1, 2]
```ここで唯一考えられる製品は、$1 \cdot 2 = 2$ですが、インデックスの合計はどのペアでも少なくとも 3 であるため、一致は発生しません。 値マップ内にペアが存在するため、アルゴリズムは引き続きそのペアを考慮しますが、等価性チェックでは拒否し、特別なケースを使用せずに正確さを保証します。
