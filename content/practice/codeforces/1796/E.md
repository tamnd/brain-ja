 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$頂点、任意の頂点を選択できます$r$根として。 ルートが固定されると、すべての頂点に距離ラベルが付けられます$d_v$、これは単純にそこからどれだけ離れているかを表します。$r$。 

この後、2 つの制約の下で頂点に色を割り当てます。 まず、同じ色の頂点がツリー内で接続されたサブグラフを形成する必要があります。 次に、単一のカラー クラス内では、すべての頂点が選択したルートから明確な距離を持たなければなりません。 

各カラー クラスにはサイズがあり、カラーリングの「コスト」は、使用されるすべてのカラーの中で最小のサイズとして定義されます。 目標は、ルートとカラーリングの両方を選択して、この最小カラー サイズを最大化することです。 

これについて考えると便利な方法は、同じカラー内では距離を再利用できないため、各カラー クラスはルートからの距離に関してパスのような構造のように動作する接続された頂点のセットであるということです。 

制約は厳しいです。$n$すべてのテストケースにわたって、$2 \cdot 10^5$。 これにより、ルートごとまたはカラー設定ごとにグローバル プロパティを再計算するものはすべて即座に除外されます。 二次関数の何か$n$テストごとの速度が遅すぎます。 期待すべきことは、$O(n)$または$O(n \log n)$試験溶液ごとに。 

ツリーが単純なパスである場合、微妙なエッジ ケースが発生します。 中間の頂点をルートとして選択すると、距離は対称的に繰り返され、多くの色が強制的に小さな断片になります。 ルートの選択は距離レイヤーの分布を直接制御するため、ルートの選択を無視する単純な貪欲はここでは失敗します。 

もう 1 つのエッジケースはスターです。 中心をルートとして選択すると、すべての葉が距離 1 を共有し、中心構造の制約が含まれている場合、各色に最大 1 つの葉が含まれるようになります。 しかし、ルートとして葉を選択すると、分布が完全に変わり、より大きなバランスの取れたカラー クラスが可能になります。 

これらの例は、根本的な選択が表面的なものではなく、許可されるカラー グループの組み合わせ構造を変更することを示しています。 

## アプローチ

 直接的な試みでは、ルートを修正してから、頂点を有効なカラー グループに貪欲に割り当てようとします。 特定のルートについては、すべての距離がわかります。 単純な戦略では、距離が繰り返されないようにしながら、色のない頂点から開始してエッジに沿って拡張することで各カラー クラスを構築しようとする可能性があります。 

このアプローチは原理的には正しいですが、効率の面では失敗します。 固定ルートの場合、最適なグループを構築するには、接続性と距離の制約をグローバルに追跡する必要があり、最適なグループ化を保証するローカルの貪欲なルールはありません。 1 つのルートに対して最適なカラーリングを計算できると仮定しても、$O(n)$、これを全員に繰り返します$n$根が導く$O(n^2)$、それは限界をはるかに超えています。 

重要な観察は、2 番目の制約である「カラー内の個別の距離」により、各カラー クラスがルートから各 BFS レイヤーから最大 1 つの頂点を選択することを強制していることです。 したがって、すべての色は複数の距離レイヤーにまたがる構造のように動作しますが、レイヤーごとに複数の頂点を取ることはできません。 

ここで視点を反転します。色を構築する代わりに、最小色のサイズを制限するものについて考えてください。 ルートを修正するとします。 どの色を見ても、増加する距離レベルにわたって頂点を選択する必要がありますが、接続性により、これらの頂点は根から葉までのパスに沿って一貫した方法で配置されなければなりません。 これにより、問題は、根から葉までの互いに素な「距離チェーン」をどれだけ埋め込むことができるかを理解することに変わります。 

重要な単純化は、任意のカラーリングについて考えるのをやめ、代わりに「固定ルートの場合、達成可能な最適な最小カラー サイズはどれか?」と考えることです。 この値は、根元の木の深さの分布にのみ依存することがわかります。$r$。 具体的には、各カラー クラスはルートから外側に向かう頂点のパス状の選択に対応する必要があり、制限要因は各深度レベルにいくつの頂点が存在するかになります。 

最適な戦略は、最小限の深さのレイヤーを最大化する方法でサブツリー サイズのバランスをとるルートを選択することになります。 これは木の重心に直接つながります。 

ルートとして重心を選択した場合、サブツリーは次の値を超えません。$n/2$これにより、距離レイヤーがバランスよく配置され、小さなカラー クラスを強制的に支配するレイヤーが存在しないことが保証されます。 答えは重心補体の最大サブツリーのサイズとなり、最終結果は実行可能な最小グループ化サイズの可能なルートの最大値になります。これは単純化すると次のようになります。$n$重心を削除した後の最大コンポーネントのサイズを引いたもの。 

したがって、問題は重心を見つけてその最大のサブツリーを評価することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 根を超えるブルートフォース + カラーリングシミュレーション |$O(n^2)$|$O(n)$| 遅すぎる |
 | 重心ベースの評価 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを任意に (たとえばノード 1 で) ルートし、DFS を使用してサブツリーのサイズを計算します。 これにより、ツリー構造のバランスを推論することができます。 
2. 木の重心を見つけます。 重心は、削除後に形成された接続コンポーネントが次の要素を超えていないノードです。$n/2$頂点。 これにより、その時点からツリーのバランスが可能な限り保たれます。 
3. 重心について、隣接するすべてのサブツリーのサイズを計算します。 重心が削除されると、各近傍は 1 つの連結成分を定義します。 
4. そのような最大のコンポーネントを特定します。 これは、重心から最も「アンバランスな」方向を表します。 
5. 答えを次のように計算します。$n$この最大のコンポーネントのサイズを引いたものです。 これは、すべてのカラー クラスにわたって保証される均一寄与の最大値に相当します。 

### なぜ効果があるのか

 重心は、すべての可能なルートの中でサブツリーの最大サイズを最小化します。 有効なカラーリングはルートからの距離レイヤー全体に頂点がどのように分布するかによって制限されるため、サブツリー サイズの不均衡が最悪になると、最小カラー クラスのサイズが直接制限されます。 非重心ルートは厳密に大きなコンポーネントを作成するため、少なくとも 1 つのカラー クラスが強制的に小さくなります。 したがって、重心は最適なバランス ポイントを達成し、ボトルネックは常に最大の隣接サブツリーになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * n
    order = []
    stack = [0]
    parent[0] = -2

    while stack:
        v = stack.pop()
        order.append(v)
        for to in g[v]:
            if to == parent[v]:
                continue
            if parent[to] != -1:
                continue
            parent[to] = v
            stack.append(to)

    sz = [1] * n
    for v in reversed(order):
        for to in g[v]:
            if to == parent[v]:
                continue
            sz[v] += sz[to]

    centroid = 0
    best = n
    for v in range(n):
        max_part = n - sz[v]
        for to in g[v]:
            if parent[to] == v:
                max_part = max(max_part, sz[to])
            elif parent[v] == to:
                max_part = max(max_part, n - sz[v])
        if max_part < best:
            best = max_part
            centroid = v

    if len(g[centroid]) == 0:
        print(1)
        return

    largest = 0
    for to in g[centroid]:
        if parent[to] == centroid:
            largest = max(largest, sz[to])
        else:
            largest = max(largest, n - sz[centroid])

    print(n - largest)

t = int(input())
for _ in range(t):
    solve()
```コードは最初にツリーを構築し、再帰の深さの問題を回避するために反復 DFS 順序を使用してサブツリーのサイズを計算します。 の`sz`配列には、ノード 0 の初期ルートに相対的なサブツリー サイズが格納されます。 

次に、重心検索では、そのノードが削除された場合に残る最大コンポーネント サイズを計算することによって各ノードを評価します。 これは、サブツリー サイズと補数サイズを使用して行われます。 この値を最小にするノードが重心として選択されます。 

最後に、重心が特定されたら、それに隣接するすべてのコンポーネントのサイズを計算し、最大のものを次の値から差し引きます。$n$、答えが得られます。 

微妙な点は、重心サブツリーの補数を正しく処理することです。 隣接要素を反復する場合、隣接要素が DFS ツリーの子であるか親側であるかを区別します。これにより、コンポーネントのサイズが決まるためです。`sz[to]`または`n - sz[centroid]`。

 ## 特殊なケース

 パス形状のツリーは、重心処理が中間ノードの 1 つを正しく識別するかどうかをテストします。 DFS ベースの計算により、サブツリーのサイズがチェーン構造を確実に反映し、最大のコンポーネントがチェーンの大きい半分となり、正しい分割が生成されます。

最後の微妙なケースは次のような場合です。$n = 3$。 すべてのノードは重心またはほぼ重心のいずれかであり、アルゴリズムは、中央のノードを削除するとサイズ 1 の 2 つの成分が得られ、答え 2 が得られることを正しく計算する必要があります。
