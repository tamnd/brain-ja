 ## 解決策
 ## 問題の理解

 私たちは、文字ごとに直接構築されるのではなく、正の整数から順番に生成される無限の文字列について推論するように求められます。 各整数について$i = 1, 2, 3, \dots$、割り算に応じて文字を追加します。`F`もし$i$は 3 で割り切れるので、追加します`B`もし$i$は 5 で割り切れます。数値が 3 と 5 の両方で割り切れる場合、両方の文字がその順序で追加されます。`F`最初にそしてそれから`B`。 

これにより、アルファベット上に単一の無限シーケンスが生成されます。`{F, B}`。 各整数は 0、1、または 2 文字のいずれかを提供するため、文字列は不均一ではありますが、決定的に増加します。 

各クエリは短い文字列を返します$s$長さは最大 10 であり、この無限に生成された文字列のどこかに連続したセグメントとして現れるかどうかを判断する必要があります。 

という制約が$k \le 10$重要な構造上のヒントです。 このように短い部分文字列では、構造を深く調査する必要はありません。 局所的なパターンは定期的に繰り返されるため、正しい解は無限シーケンスの境界部分を理解するだけで済みます。 

単純な試みでは、広範囲の整数のプロセスをシミュレートしようとするかもしれませんが、3 と 5 で割り切れる可能性は$i \bmod 15$。 

境界を越える部分文字列の重複を処理せずに、単一の小さな整数プレフィックス内のみをチェックすると、微妙な間違いが発生します。 たとえば、パターンは 15 個の整数からなる 1 つのブロックの終わり近くで始まり、次のブロックに続く可能性があります。 もう 1 つの失敗モードは、プロセスを出力された文字ごとではなく整数ごとのシーケンスとして扱うことです。これにより、不正確な部分文字列の位置合わせが発生します。 

## アプローチ

 ブルートフォースのアイデアは、文字列が「十分に長く」なるまで、通常はクエリの長さの倍数を超えるまで、整数を反復処理して文字を追加することで、FB 文字列の構築をシミュレートすることです。 各整数は最大 2 文字を生成するため、$k \le 10$場合、テスト ケースごとにおそらく数百の整数を安全にシミュレートし、部分文字列チェックを実行できます。 

このアプローチは、定義を忠実に再構成するため、正しいです。 ただし、構造が決定論的に繰り返される場合でも、各テスト ケースで多くの整数を繰り返しシミュレートすることになるため、スケールアップすると非効率になります。 

重要な観察点は周期性です。 各整数の寄与は、その整数が 3 と 5 で割り切れるかどうかによってのみ決まります。これは、15 を法とした余りによって完全に決まります。15 個の連続する整数の各ブロックは、まったく同じ追加文字シーケンスを生成します。 これは、無限の FB 文字列全体が、整数 1 ～ 15 に対応する固定の有限文字列の繰り返しであることを意味します。 

基本ブロックを取得したら、十分に繰り返されたバージョン内を検索することで、無限文字列の部分文字列を見つけることができます。 クエリの最大長は 10 であるため、ベース ブロックを少数回複製することで、境界を越える部分文字列を決して見逃さないことが保証されます。

 ## アルゴリズムのチュートリアル

 1 から 15 までの整数をシミュレートすることによって、FB 文字列の 1 つの完全な期間を構築します。次に、このブロックを数回繰り返して、境界をまたぐ部分文字列を安全にカバーします。 最後に、この展開された文字列内にクエリ文字列が表示されるかどうかを確認します。 

1. 1 ～ 15 の整数を繰り返し、基本文字列を構築します。 

整数ごとに追加します`F`3で割り切れる場合は追加します`B`5で割り切れる場合はその順序で。 これにより、基本的な繰り返しブロックが生成されます。 
2. ブロックを数回、たとえば 3 回繰り返します。 

これにより、長さ 10 以内の部分文字列が 2 つのブロック間の境界を越える場合でも完全に含まれることが保証されます。 
3. 各クエリ文字列について、それがこの構築された有限文字列の部分文字列であるかどうかを確認します。 
4. 出力`YES`見つかった場合、そうでない場合`NO`。 

### なぜ効果があるのか

 この構築は 3 と 5 の割り算のみに依存し、これが整数に対して周期 15 で繰り返されます。 各整数はこのプロパティのみに基づいて独立して寄与するため、出力される文字シーケンスは 15 整数ごとに正確に繰り返されます。 したがって、無限文字列の部分文字列は、固定された有限ブロックの繰り返しコピー内に含まれます。 ブロックを 1 ピリオドをわずかに超えて拡張すると、境界をまたぐ部分文字列も確実にキャプチャされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# build one period (1..15)
base = []
for i in range(1, 16):
    if i % 3 == 0:
        base.append("F")
    if i % 5 == 0:
        base.append("B")

base = "".join(base)

# repeat enough to cover substrings up to length 10 crossing boundaries
text = base * 3

t = int(input())
for _ in range(t):
    k = int(input())
    s = input().strip()
    if s in text:
        print("YES")
    else:
        print("NO")
```このソリューションは、まず 1 ～ 15 の整数インデックスにわたる FB 文字列の最小繰り返し単位を構築します。次に、この単位を 3 回繰り返して、1 つの期間の終わりと別の期間の始まりにまたがる場合でも、長さ 10 までの部分文字列が完全に表現されるようにします。 各クエリは直接部分文字列チェックを使用して回答されます。これは、テキストとパターンの両方が小さく、サイズが固定されているため効率的です。 

唯一の微妙な点は、整数が 3 と 5 の両方で割り切れる場合に、追加される文字の正しい順序を保証することです。コードは、これを追加することによってこれを保持します。`F`まずそして`B`2番。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    base = []
    for i in range(1, 16):
        if i % 3 == 0:
            base.append("F")
        if i % 5 == 0:
            base.append("B")
    base = "".join(base)
    text = base * 3

    t = int(input())
    out = []
    for _ in range(t):
        k = int(input())
        s = input().strip()
        out.append("YES" if s in text else "NO")
    return "\n".join(out)

# provided samples
assert run("""3
3
FFB
8
BFFBFFBF
3
BBB
""") == """YES
YES
NO"""

# minimum size
assert run("""1
1
F
""") == "YES"

# simple B case
assert run("""1
1
B
""") == "YES"

# boundary-crossing style case
assert run("""1
2
FB
""") == "YES"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 厄介なケースは、部分文字列が 15 整数サイクルの終わり近くで始まり、次のサイクルに続く場合です。 構築が繰り返されるため、アルゴリズムがこれを処理します。`base * 3`すべての境界領域が有限表現内に完全に表示されることを保証します。 

たとえば、パターンが 1 つのブロックの最後の文字で始まり、次のブロックに続く場合、構築された文字列には、繰り返しの中央のコピーに重複する部分が含まれています。 部分文字列チェックでは、インデックスや整数のアライメントの特別な処理を必要とせずに、それが直接検出されます。
