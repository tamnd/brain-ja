 ## 解決策
 ## 問題の理解

 私たちには少人数のグループと、一緒に作業できないペアのリストが与えられます。 選択したグループ内のすべてのペアに互換性があるように、可能な限り最大のサブセットを選択する必要があります。 

これは当然グラフの問題です。 各ボランティアを頂点として考えてください。 2 人がお互いを嫌っている場合、私たちはそれらの間にエッジを追加します。 タスクは、どの 2 つの頂点の間にもエッジがない頂点の最大のサブセットを見つけることになります。 グラフ理論では、これを最大独立集合と呼びます。 

ボランティアの数が多くても16人ということで、問題の考え方が全く変わってきます。 一般的な最大独立集合問題は NP 困難ですが、頂点が 16 個だけあれば、すべてのサブセットを網羅的に探索することができます。 あるのは$2^{16} = 65536$サブセットは、最新のハードウェアとしては小さいです。 各サブセットのチェックに数百の操作を費やしたとしても、合計作業量は制限時間内に簡単に収まります。 

枝刈りを行わない素朴な再帰的バックトラッキング手法は、重複する状態間の互換性チェックを繰り返し再計算するため、依然として厄介になる可能性があります。 検索スペースはすでに十分に小さいため、すべてのビットマスクを直接反復処理する方が簡単かつ安全です。 

実装を静かに破壊する可能性のあるエッジケースがいくつかあります。 

よくある間違いの 1 つは、非互換性の関係を方向性のないものではなく、方向性のあるものとして扱うことです。 

入力：```
2 1
Alice
Bob
Alice Bob
```正解は任意の 1 人です。 マークするだけなら`Alice -> Bob`でも忘れてください`Bob -> Alice`、次にサブセット`{Bob, Alice}`反復順序によっては、誤って有効に見える場合があります。 

もう 1 つの簡単なバグは、名前の大文字と小文字が区別されることを忘れていることです。 

入力：```
2 0
Petya
petya
```これらは別の人です。 正解には両方の名前が含まれています。 名前を小文字に変換すると、名前が正しく結合されません。 

サブセットが有効かどうかを確認するときに、さらに微妙な問題が発生します。 選択したすべてのノードに少なくとも 1 つの互換性のある隣接ノードがあることだけを確認するとします。 すべてのペアで互換性が維持される必要があるため、この条件は無意味です。 

入力：```
3 2
A
B
C
A B
B C
```有効な最大チームは次のとおりです。`{A, C}`サイズ 2 です。ローカル チェックを不注意に行うと、3 つすべてが誤って許可される可能性があります。 

最後に、出力を辞書順に並べ替える必要があります。 内部インデックス付けの順序は任意であり、入力順序に依存するため、選択した名前をインデックスから直接印刷すると、間違った形式が生成される可能性があります。 

## アプローチ

 最も直接的な解決策は、人々のすべてのサブセットに対するブルートフォースです。 

すべてのサブセットについて、選択されたすべてのメンバーがペアごとに互換性があるかどうかをテストします。 「はい」の場合、そのサイズをこれまでに見つかった最良の回答と比較します。 

最も単純な互換性チェックでは、サブセット内のすべてのペアが検査されます。 と$n = 16$、 がある$2^{16}$サブセット、最大でも$16^2$サブセットごとのペアチェック。 それはおおよそ次のようになります:$$2^{16} \times 16^2 \approx 1.6 \times 10^7$$これは Python ではすでに受け入れられています。 

制約が非常に小さいため、強引な方法が機能します。 問題は漸近的な実行不可能性ではなく、実装のクリーンさと不必要な繰り返しチェックの回避です。 

重要な観察は、サブセットが自然にビットマスクとして表現されるということです。 一人一人が1ビットに対応します。 また、各人について、対立する人々のビットマスクを保存することもできます。 

サブセットの検証が非常に高速になりました。 選ばれた人のために`i`、 もし：$$mask \& bad[i] \neq 0$$その場合、サブセットには互換性のない誰かが含まれています`i`したがって、サブセットは無効です。 

これにより、ペアごとのチェックがコンパクトなビット操作に変換されます。 

この問題構造により、次の理由からビットマスキングが理想的になります。 

1. 宇宙のサイズは小さい。 
2. とにかくすべてのサブセットを考慮する必要があります。 
3. 互換性関係は静的です。 
4. ビット演算が非常に高速です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ペアチェックによるブルートフォース |$O(2^n \cdot n^2)$|$O(n^2)$| 承認済み |
 | ビットマスクの最適化 |$O(2^n \cdot n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての名前を読み取り、各人にインデックスを割り当てます。`0`に`n-1`。 

整数インデックスを使用すると、計算中に文字列の代わりにコンパクトなビットマスクを使用できるようになります。 
2. 名前からインデックスへのマッピングを構築します。 

これにより、非互換性のペアを文字列から数値の頂点 ID に効率的に変換できます。 
3. 配列を作成する`bad`どこ`bad[i]`人と互換性のないみんなのビットマスクです`i`。 

もし人`i`嫌いな人`j`、ビットを設定します`j`内部`bad[i]`、ビットも設定`i`内部`bad[j]`。 
4. すべてのサブセットを反復処理する`mask`から`0`に`(1 << n) - 1`。 

各ビットマスクは 1 つの可能なチームを表します。 
5. 各サブセットについて、それが有効かどうかを確認します。 

すべての人を反復処理する`i`。 もし人`i`がサブセット内にあり、かつ:$$mask \& bad[i] \neq 0$$この場合、互換性のないチームメイトもサブセット内に存在するため、このサブセットは使用できません。 
6. サブセットが有効な場合は、そのサイズを現在の最良の回答と比較します。 

使用`mask.bit_count()`チームの規模を効率的に計算します。 
7. 見つかった最適なサブセットを保存します。 

任意の最大解が許容されるため、同点は重要ではありません。 
8. 最適なサブセットに属する名前を抽出します。 

この問題ではソートされた出力が必要なため、印刷する前に辞書順にソートしてください。 

### なぜ効果があるのか

 サブセットは、その中に互換性のないペアが一緒に存在しない場合にのみ有効です。 

配列`bad[i]`～と対立するすべての人が含まれる`i`。 検証中の式は次のとおりです。$$mask \& bad[i]$$現在のサブセットに互換性のないパートナーが含まれているかどうかを確認します。`i`。 

選択した人に対してこの式がゼロ以外の場合`i`の場合、サブセットは要件に違反しているため、拒否する必要があります。 

選択したすべての人物に対して式が 0 である場合、サブセット内のどこにも競合するペアは存在しないため、サブセットは有効です。 

アルゴリズムは考えられるすべてのサブセットを検査するため、見つかった最大の有効なサブセットが最適であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    names = [input().strip() for _ in range(n)]

    idx = {}
    for i, name in enumerate(names):
        idx[name] = i

    bad = [0] * n

    for _ in range(m):
        a, b = input().split()

        u = idx[a]
        v = idx[b]

        bad[u] |= (1 << v)
        bad[v] |= (1 << u)

    best_mask = 0
    best_size = 0

    for mask in range(1 << n):
        ok = True

        for i in range(n):
            if (mask >> i) & 1:
                if mask & bad[i]:
                    ok = False
                    break

        if ok:
            size = mask.bit_count()

            if size > best_size:
                best_size = size
                best_mask = mask

    ans = []

    for i in range(n):
        if (best_mask >> i) & 1:
            ans.append(names[i])

    ans.sort()

    print(best_size)
    print(*ans, sep="\n")

solve()
```最初のセクションでは、名前を読み取り、整数のインデックスに変換します。 ビットマスク操作は数値 ID に対してのみ適切に機能するため、これは不可欠です。 

の`bad`配列には非互換性マスクが格納されます。 もし`bad[3]`ビット 1 と 5 が設定されている場合、人 3 は人 1 と 5 と一緒に作業できません。 

サブセット ループは、考えられるすべてのチームを列挙します。 以来`n <= 16`、サブセットの総数はわずか 65536 です。 

検証ステップはソリューションの中核です。 選ばれた人ごとに`i`、禁止されたチームメイトもサブセットに存在するかどうかをテストします。 表現:```
mask & bad[i]
```少なくとも 1 人の競合する人物が存在する場合、ゼロ以外の整数を正確に返します。 

実装では、選択されたすべての頂点が個別にチェックされます。 これにより、同じ不良ペアが 2 回検出される可能性がありますが、定数係数は小さく、ロジックは非常に明確です。 

出力フェーズでは、選択された名前が収集され、辞書順に並べ替えられます。 内部サブセットの順序は辞書の順序ではなく入力の順序に従うため、この詳細は忘れられがちです。

        for i, name in enumerate(names):
            idx[name] = i

            v = idx[b]

            bad[v] |= (1 << u)

        best_size = 0

            ok = True

 ## 特殊なケース

 非互換性が誤って指示どおりに処理された場合を考えてみましょう。 

入力：```
2 1
Alice
Bob
Alice Bob
```アルゴリズムは次の両方を保存します。```
bad[Alice] |= Bob
bad[Bob] |= Alice
```サブセットをチェックするとき`{Alice, Bob}`の場合、両方の人が競合を検出するため、サブセットは正しく拒否されます。 

名前の大文字と小文字を区別することを考慮してください。 

入力：```
2 0
Petya
petya
```マッピング ディクショナリには、次の 2 つの個別のキーが格納されます。```
{
    "Petya": 0,
    "petya": 1
}
```競合が存在しないため、サブセット`11`は有効であり、両方の名前が回答に表示されます。 

間接的な接続が問題にならないグラフを考えてみましょう。 

入力：```
3 2
A
B
C
A B
B C
```サブセット`{A, C}`マスクに対応`101`。 

のために`A`:```
mask & bad[A] = 101 & 010 = 0
```のために`C`:```
mask & bad[C] = 101 & 010 = 0
```直接的な非互換性のみが問題となるため、サブセットは有効です。 

最後に、完全に切り離されたグラフを考えてみましょう。 

入力：```
4 0
A
B
C
D
```全て`bad[i]`マスクはゼロです。 すべてのサブセットが検証に合格し、アルゴリズムが最終的にマスクを選択します`1111`、4人全員が含まれています。
