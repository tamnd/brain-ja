 ## 解決策
 ## 問題の理解

 長方形のクッキーがいくつか与えられます。 各クッキーは、その周長が合計の「サクサク度スコア」に寄与し、焼く前にオプションで各クッキーを変更することができます。 変更は、長方形の中心を通る 1 つの直線カットであり、等しい面積の 2 つの部分が生成されます。 これらの部分は長方形のままである必要はありませんが、周囲は明確に定義されています。 

目標は、クッキーごとに、クッキーを変更しないままにするか、この単一のカットを適用するかを選択し、結果として得られるすべての部分の周囲長の合計が目標値を超えずにできるだけ大きくなるようにすることです。$P$。 初期構成ではすでに最大でも全周が設定されています$P$したがって、常に有効なベースラインが得られます。 

重要な量は、長方形を 1 回切断することでどのくらいの余分な周囲長が得られるかです。 各 Cookie は個別に選択肢を提供します。基本境界を取得するか、「コスト」を支払ってより大きな境界にアップグレードするかです。 全体的な問題は、ナップザックのような制約の下でこれらのアップグレードのサブセットを選択することになります。ただし、容量は、合計の境界を最大でどれだけ増やすことができるかという正確な点を除きます。$P$。 

この制約は、最大 100 個のテスト ケースと、ケースごとに最大 100 個の Cookie を意味します。 すべてのカットの組み合わせに対する単純な指数関数的な検索には、以下が含まれます。$2^{100}$状態、それは実行不可能です。 容量のある擬似多項式ナップザックでも$10^8$直接的には不可能であるため、唯一の実行可能なアプローチは、ゲイン値の構造を使用して状態空間を圧縮することです。 

長方形が非常に薄いか非常に歪んでいる場合、微妙なエッジケースが発生します。 このような場合、切断により周囲に比べて大きなゲインが生じる可能性があり、浮動小数点の精度が重要になります。 もう 1 つの特殊なケースは、削減を行わないと何も改善されない場合、または最適なソリューションが予算をすべて使用しないにもかかわらず、依然として予算を正確に達成できない場合です。 

## アプローチ

 直接的なアプローチでは、各クッキーを独立して扱い、それをカットするかどうかを検討します。 Cookie のすべてのサブセットをカットしようとすると、合計周長が計算され、その範囲内に収まるかどうかが確認されます。$P$。 これは正しいですが、すべてを調べる必要があります$2^N$サブセットは指数関数的に増加し、次の時点ですぐに壊れます。$N=100$。 

代わりに、問題をナップザックの変形として再定式化します。 各 Cookie は基本値を提供します$B_i = 2(W_i + H_i)$。 切断すると新しい価値に置き換わります$C_i$したがって、ゲインは次のようになります。$G_i = C_i - B_i$。 すべての Cookie は最大でも 1 つのアップグレードされた状態で使用できるため、予算を超えずに総増加量を最大化するために利益のサブセットを選択しています。$P - \sum B_i$。 

重要な構造的洞察は、切断後の形状は不規則であるが、結果として得られる 2 つの等しい面積の部分の周囲長は元の長方形の寸法のみに依存し、軸が整列した長方形の場合、この値は固定関数であるということです。 したがって、各 Cookie は、既知の利益を持つ 1 つの独立した「ボーナス オプション」に寄与します。 これにより、ジオメトリが純粋に組み合わせ選択問題に分解されます。 

ここでのタスクは次のようになります。合計ができるだけ大きく、かつ目標容量を超えない、最大 100 個の正のゲイン値のサブセットを選択します。$K$。 以来$K$まで可能です$10^8$、和を超える古典的なDPは不可能です。 ただし、ゲインはジオメトリ (長方形の周囲と対角線から導出される) によって制限され、その構造により、精度の処理に応じて、シフトされた範囲にわたってビットセットベースのサブセット合計を使用したり、ソート後に貪欲 + 枝刈りアプローチを使用したりすることができます。 

実際には、すべてのゲインを計算し、正でないものを破棄し、並べ替えて、インデックスが達成可能な追加の境界を表すビットセットを使用して、達成可能な合計の実行セットを維持します。 次に、以下を超えない達成可能な最大値を見つけます。$K$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット |$O(2^N)$|$O(N)$| 遅すぎる |
 | ゲインのビットセット サブセット合計 |$O(N \cdot K / word)$|$O(K)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ## 1. 基本境界と残りの予算を計算します

 まず、カットを行わずに合計周囲長を計算します。$$B = \sum 2(W_i + H_i)$$すると、残りの予算は次のようになります。$$K = P - B$$これにより、問題は、超過することなく達成可能な最良の追加ゲインを見つけることに変換されます。$K$。 

## 2. 各長方形のカットからのゲインを計算します

 各長方形について、最適な単一の中心カットの後に周囲長を計算します。 これは、長方形を 2 つの等しい面積の形状に分割するジオメトリによって異なります。 結果の周囲長は次の固定関数になります。$W$そして$H$, したがって、次のように導き出されます。$$G_i = C_i - B_i$$もし$G_i \le 0$、決して役に立たないので無視します。 

このステップが機能する理由は、各 Cookie が独立しており、カットの決定が他の Cookie に影響を与えないためです。 

## 3. ゲインに対するサブセット合計の状態を構築する

 ビットセットを保守します`dp`どこ`dp[s]`余分な周囲を正確に達成できるかどうかを示します$s$。 当初は、`dp[0] = True`。 

それぞれのゲインについて$g$、更新します:$$dp = dp \, \text{OR} \, (dp \ll g)$$これにより、現在のゲインを加算することによって、以前に到達可能なすべての合計が遷移します。 

これが機能するのは、各 Cookie が 0/1 ナップザック構造に一致して最大 1 回使用できるためです。 

## 4. 実現可能な最良の答えを抽出する

 からスキャンします$K$下に向かって最大のものを選択します$s$そのような`dp[s]`それは本当です。 最終的な答えは、$B + s$。 

逆スキャンにより、制限を超えることなく合計周囲長が最大化されます。 

## なぜ機能するのか

 重要な不変条件は、最初の処理後、$i$Cookie を使用すると、ビットセットはそれらの Cookie のみを使用して、達成可能なすべてのゲイン合計を正確にエンコードします。 各更新では、現在の Cookie を 1 回だけ除外または含めて、問題の制約に一致するため、正確さが維持されます。 すべての構成はカットの一意のサブセットに対応し、すべてのサブセットは遷移を通じて表現できるため、最終状態にはすべての有効なソリューションが含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N, P = map(int, input().split())
        
        base = 0
        gains = []
        
        for _ in range(N):
            w, h = map(int, input().split())
            base += 2 * (w + h)
            
            # gain from optimal single center cut
            # splitting rectangle into two equal-area shapes increases perimeter
            # derived formula: +2 * sqrt(w^2 + h^2) - 2 * min(w, h)
            import math
            cut_perimeter = 2 * (w + h) + 2 * math.sqrt(w * w + h * h) - 2 * min(w, h)
            gain = cut_perimeter - 2 * (w + h)
            
            if gain > 1e-12:
                gains.append(gain)
        
        K = P - base
        if K <= 0:
            print(f"Case #{tc}: {base:.6f}")
            continue
        
        # scale to integers for stability
        scale = 1000000
        K = int(K * scale + 1e-9)
        int_gains = [int(g * scale + 1e-9) for g in gains]
        
        dp = 1
        for g in int_gains:
            dp |= (dp << g)
        
        best = 0
        while best <= K and (dp >> best) & 1:
            best += 1
        best -= 1
        
        ans = base + best / scale
        print(f"Case #{tc}: {ans:.6f}")

if __name__ == "__main__":
    solve()
```この実装では、まずベースライン境界を累積し、次に問題を独立ゲインのサブセットの選択に変換します。 ビットセットのシフト中の精度のドリフトを避けるために、浮動小数点値は整数にスケーリングされます。 

ビットセット`dp`は整数として保存され、Python の任意精度整数を利用してパックされたビットセットを効率的にシミュレートします。 シフトアンドオア更新は、標準のサブセット合計遷移をエンコードします。 

0 から上の最​​終スキャンでは、予算を超えない達成可能な最大のゲインが見つかります。

 ## 特殊なケース

 重要なエッジケースは、すべてのゲインが負またはゼロの場合です。 この場合、DP はゼロを超えて拡張されることはなく、アルゴリズムは変更されていない基本周長を正しく返します。 

もう 1 つのケースは、残りの容量が存在するにもかかわらず、最適なソリューションがすべての予算を使用しない場合です。 到達可能な合計を逆スキャンすることで、正確な飽和を強制することなく、実現可能な最大値が確実に選択されます。 

最後に、浮動小数点の不安定性により、ゲインの順序が正しくなくなる可能性があります。 スケーリング ステップにより、すべての比較と DP 遷移が整数空間で行われるようになり、テスト ケース全体で一貫性が維持されます。
