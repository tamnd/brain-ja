 ## 解決策
 ## 問題の理解

 サイズ R × C のグリッドが与えられます。各セルは空であるか、チョコレート チップが含まれています。 このグリッドは、正確に H の水平カットと正確に V の垂直カットを使用してカットする必要があります。 各カットはその方​​向のグリッドの全長に及ぶため、すべてのカットが完了すると、(H + 1) × (V + 1) 個の部分にワッフルが長方形に分割されます。 

要件は、これらの部品の形状やサイズに関するものではありません。 この制約は純粋に配分に関するものです。結果として得られるすべてのピースには、まったく同じ数のチョコレート チップが含まれている必要があります。 

この問題を言い換える重要な方法は、固定の行と列の境界を使用してグリッドを等しい和の部分行列に分割しようとしているということです。各部分行列は '@' セルの合計が同じでなければなりません。 

この制約により、非表示のテスト セットでは R、C が最大 100 まで許可されます。 これは、考えられるすべてのカット位置に対する単純な検索がすでに大規模であることを意味します。個別に実行した場合、各カット構成には O(R^H * C^V) または O(RC) の選択肢があり、H = V = 99 であってもこれは完全に実行不可能です。 すべてのカットの配置を列挙するだけでも膨大です。 明示的にカットを試みるのではなく、プレフィックスの合計について推論するソリューションが必要です。 

いくつかの微妙なケースが重要です。 

グリッド内にチョコレート チップがない場合は、すべてのピースにチップが含まれていないため、どのカット構成も有効です。 不注意な実装でも合計を除算しようとしますが、ゼロ除算または不正な分割ロジックが原因で失敗する可能性があります。 

チップの総数が (H + 1)(V + 1) で割り切れない場合、答えは直ちに不可能になります。 ローカルでパーティションをチェックするだけの単純なアプローチでは、このグローバルに必要な条件が見逃される可能性があります。 

チップが単一の行または列に集中している場合、別の厄介な状況が発生します。 合計が割り切れる場合でも、カットは両方の次元にわたるグローバルな制約であるため、すべてのセグメントが等しい寄与を受けるようにカットを調整することは不可能な場合があります。 

## アプローチ

 ブルートフォースアプローチでは、R − 1 ギャップ間に H 個の水平カットを配置し、C − 1 ギャップ間に V 個の垂直カットを配置するために、考えられるすべての方法が試行されます。 各構成について、結果として得られるすべての長方形内のチップの合計を計算し、すべての (H + 1)(V + 1) の値が一致するかどうかを確認します。 

これは条件を直接検証するため、正しいです。 問題はコストです。水平カットのみを選択することは C(R − 1, H) 程度の組み合わせであり、垂直カットの場合も同様です。 構成ごとに同等性を検証するには、すべてのセルをスキャンするか、少なくとも部分行列の合計を再計算する必要があり、構成ごとに少なくとも O(RC) になります。 これは、R、C = 100 の場合でも限界をはるかに超えて爆発します。 

重要な観察は、最後の要件により、プレフィックス合計に非常に厳格な構造が強制されるということです。 長方形の観点から直接考えるのではなく、行と列に沿った累積チップ数を個別に考える必要があります。 チップの総数がわかったら、各水平ストライプには合計の固定部分が正確に含まれている必要があり、垂直ストライプについても同様です。 これにより、プレフィックスの合計が正確なターゲットに達するカット位置を見つけるという問題が軽減されます。 

グリッドを 2D プレフィックス合計構造に変換し、行累積と列累積を独立した 1D 分割問題として扱います。 これらのパーティションの交差により、両方の次元が総質量の一貫した分割を強制するため、すべてのサブ長方形の合計が同じになることが自動的に保証されます。

 ## アルゴリズムのチュートリアル

1. グリッド内のチップの総数を計算します。 この合計がゼロの場合、すべての構成は有効であるため、すぐに POSSIBLE を返します。 その理由は、すべての部分四角形の合計が自明に同じになるためです。 
2. 必要な個数 (H + 1) × (V + 1) を計算します。 チップの合計がこの値で割り切れない場合は、すべてのピースに均等に分配することは代数的に不可能であるため、IMPOSSIBLE を返します。 
3. 各最終ピースには、target = total_chips / ((H + 1)(V + 1)) チップが含まれている必要があります。 この値は、各長方形が耐えなければならない正確な荷重を定義します。 
4. 水平分割の場合、各行の合計チップを計算し、上から下にスキャンして累計を累積します。 累計がターゲット × (V + 1) の倍数に達するたびに、水平カットを配置します。 各水平ストライプには (V + 1) 個の最終ピースが含まれるため、乗数が表示されます。 
5. 各ストライプが等しいチップ質量を持つように正確に H 個の水平カットを配置できない場合、その構成は無効です。 それ以外の場合は、行の境界を記録します。 
6. 列合計を使用した垂直分割についても同じロジックを繰り返し、各垂直ストライプがターゲット × (H + 1) 個のチップを確実に運ぶようにします。 
7. 行と列の両方のパーティションが成功した場合は POSSIBLE を返し、それ以外の場合は IMPOSSIBLE を返します。 

これが機能する理由は、チップの寄与が長方形に対して加算されるという事実に基づいています。 すべての水平ストライプの合計が正しく、すべての垂直ストライプの合計が正しい場合、それらの交差セルの合計は必ず同じ値になる必要があります。これは、各部分が 1 つの水平マス スライスと 1 つの垂直マス スライスを交差させることによって形成され、両方が一貫した合計に制約されているためです。 これにより、すべての (H + 1)(V + 1) 個の部分長方形にわたって均一性が強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    R, C, H, V = map(int, input().split())
    grid = [input().strip() for _ in range(R)]

    chips = sum(row.count('@') for row in grid)

    pieces = (H + 1) * (V + 1)
    if chips == 0:
        return "POSSIBLE"
    if chips % pieces != 0:
        return "IMPOSSIBLE"

    target = chips // pieces

    row_sum = [row.count('@') for row in grid]
    col_sum = [sum(grid[i][j] == '@' for i in range(R)) for j in range(C)]

    # horizontal cuts
    need_row = target * (V + 1)
    cuts = 0
    acc = 0
    for i in range(R):
        acc += row_sum[i]
        if acc == need_row:
            cuts += 1
            acc = 0
        elif acc > need_row:
            return "IMPOSSIBLE"

    if cuts != H + 1:
        return "IMPOSSIBLE"

    # vertical cuts
    need_col = target * (H + 1)
    cuts = 0
    acc = 0
    for j in range(C):
        acc += col_sum[j]
        if acc == need_col:
            cuts += 1
            acc = 0
        elif acc > need_col:
            return "IMPOSSIBLE"

    if cuts != V + 1:
        return "IMPOSSIBLE"

    return "POSSIBLE"

def main():
    T = int(input())
    for tc in range(1, T + 1):
        print(f"Case #{tc}: {solve()}")

if __name__ == "__main__":
    main()
```このソリューションでは、まずグリッドを行と列のチップ数に減らします。 これにより、2D 合計を繰り返し再計算する必要がなくなります。 水平スキャンにより、カットが許可される前に、各ストライプに必要な数のチップが正確に蓄積されるようになります。 同じロジックが列にも適用されます。 

微妙な点は、蓄積時の均等性チェックです。 累計が必要なしきい値を超える場合は、チップをカット全体に分割できないため、有効なカット境界がそこに存在しないことを意味します。 正確なしきい値に達した場合にのみアキュムレータをリセットすることで、カットを有効な境界に正確に揃えることができます。

 ## 特殊なケース

 ゼロチップグリッドは早期リターンをトリガーします。 制約に違反できないため、アルゴリズムはすべてのパーティション ロジックを正しくバイパスし、POSSIBLE を返します。 

チップが存在しても必要な個数より少ない場合は、割り算チェックで失敗します。 このアルゴリズムはカットを配置しようとしないため、誤解を招く部分的なパーティションの試行を防ぎます。 

1 つの列内のすべてのチップなどの集中構成は、垂直スキャン中に失敗します。 アキュムレータは、有効なカット境界に到達する前に必要なセグメントの合計を超えるため、即時に拒否されます。
