 ## 解決策
 ## 問題の理解

 私たちには、ロボットのグループ、ビットと呼ばれる区別できないアイテムのコレクション、および数人のレジ係が与えられます。 各ロボットは 1 つのレジ係に正確に割り当てる必要があり、各レジ​​係は最大 1 つのロボットにサービスを提供できます。 その割り当ての前に、各ビットは分割できず、参加する各ロボットは少なくとも 1 ビットを受け取る必要があるという制限付きで、ロボット間でビットを分配する方法も決定します。 すべてのアクティブなロボットに分散されるビットの合計数は、完全な入力量と等しくなければなりません。 

各レジ係には 3 つのパラメータがあります。 まず、1 台のロボットがそのレジ係に持ち込めるビット数を制限する最大容量 Mi です。 第二に、ビットあたりの処理時間Si。 3 番目に、固定オーバーヘッド Pi は、ビット数に関係なく、ロボットごとに 1 回適用されます (少なくとも 1 つ、最大で Mi である限り)。 ロボットがレジ係 i に N ビットを与える場合、そのロボットの完了時間は Si × N + Pi になります。 

すべてのロボットは時間 0 に並行して開始され、目的は最後のロボットが終了する時間を最小限に抑えることです。 ロボットは割り当てられた後に対話しないため、これは作業 (ビット) の分割方法とプロセッサー (レジ担当者) の割り当て方法との間に関連するスケジューリングの問題です。 

この制約は、代入に対する単純な列挙が不可能であることを直ちに示唆します。 最大 1000 のキャッシャーと最大 10^9 ビットを使用すると、すべての分布またはすべての割り当てを明示的に試行するアプローチは、組み合わせ的に爆発的に増加します。 私たちが利用しなければならない構造は、ビット B やレジ係 C の数ではなく、ロボットの数 R が真のボトルネックであるということです。 

微妙な失敗例は、レジ係が小さな荷物には優れているが、大きな荷物にはひどい場合に現れます。 たとえば、Si が小さく Pi が大きいレジ係は、多くの小さな割り当てには最適かもしれませんが、大きな束は処理できません。 もう 1 つのエッジ ケースは、多くのレジ係で Mi が 1 である場合で、ロボットごとに 1 ビットという厳密な制約が強制され、問題が純粋な割り当ての順序付けに変わります。 

## アプローチ

 直接的なブルートフォース解釈は、各 B ビットを R ロボットの 1 つに割り当て、次に各ロボットを個別のレジ係に割り当てることになります。 レジ係の割り当てを修正したとしても、B 個の区別できないアイテムを容量のある R 個の箱に分配することは、B では指数関数的であり、およそ R^B のオーダーになります。 B が 10^9 に達すると、これは直ちに実行不可能になります。 

ビット配分を無視してロボットをレジ係に割り当てることだけに焦点を当てたとしても、依然として組み合わせマッチングの問題に直面します。 重要な問題は、レジ係のコストが受信するビット数に依存するため、レジ係ごとに単一の重みを事前計算できないことです。 

重要な観察は、R が C に比べて十分小さいため、R 個のレジを選択し、それぞれが受け取るビット数を決定するという観点から考えることができるということです。 ビットを直接割り当てる代わりに、レジ担当者がさまざまな可能性のあるロードにかかる合計時間を推論します。 固定のレジ係 i と目標時間 T の場合、時間 T 以内に終了するまでに何ビットを処理できるかを尋ねることができます。その不等式は Si × N + Pi ≤ T であり、N ≤ (T − Pi) / Si と N ≤ Mi が得られます。 したがって、期限 T の下でのレジ担当者 i の有効容量は T の単調関数です。 

これは問題を実現可能性チェックに変換します。候補時間 T が与えられた場合、各レジ担当者 i が最大で cap_i(T) ビットを受け取るように、選択された最大 R 個のレジ担当者に B ビットを割り当てることができるでしょうか? これに答えることができれば、T に対する二分探索ができます。 

残りの困難は、どの R レジを使用するかを選択することです。 固定 T の場合、各レジ係は容量 cap_i(T) を提供します。 最大の R 容量の合計が少なくとも B であることが必要です。最適な割り当てでは期限内にほとんどのビットを処理できる R キャッシャーが使用されるため、これが最適です。

したがって、ソリューションは時間通りの二分探索となり、各チェックの計算能力とソートによって上位 R が取得されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース割り当て | O(C^R・B) | お(1) | 遅すぎる |
 | 二分探索 + 貪欲な容量チェック | O(C log maxT log C) | O(C) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのロボットの最大許容完了時間を表す候補解答 T を修正します。 目標は、すべてのロボットが T 以内に終了するように、すべての B ビットを割り当てることができるかどうかをテストすることです。 
2. 各レジ係 i について、ロボットが時間 T 内に終了するまでに持ち込めるビット数を計算します。これは、N_i = min(Mi, max(0, (T − Pi) // Si)) です。 T < Pi の場合、レジ係はどのロボットにもサービスを提供できないため、その能力はゼロになります。 
3. N_i を、期限 T の下でのレジ係 i の使用可能な容量として扱います。各レジ係は最大 1 回使用できるため、最大 R 個のレジ係を選択し、その容量を合計します。 
4. すべての N_i 値を降順に並べ替えます。 
5. 上位 R 値を取得し、それらの合計 S(T) を計算します。 S(T) ≥ B の場合、時間 T 内にすべてのビットを分配することが可能です。 そうでなければ不可能です。 
6. T に対して二分探索を使用します。下限は 0 から開始でき、上限はすべてのレジで安全に max(Pi + Mi × Si) に設定できます。 
7. 実現可能性が成立する最小の T が答えです。 

### なぜ効果があるのか

 固定 T の場合、各レジ担当者はサポートできる最大負荷を個別に定義します。 ロボットとレジ係は多くても 1 回しか使用されないため、問題はビットの合計カバレッジを最大化するために最大 R までの独立した容量を選択することになります。 選択したレジをより大容量の未使用のレジに置き換えても実現可能性が低下することはないため、最適なソリューションでは R の最大容量を使用する必要があります。 この交換引数により、実行可能性チェックに貪欲な選択が最適であることが保証されます。 T の単調性により、二分探索の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(T, R, B, cashiers):
    caps = []
    for m, s, p in cashiers:
        if T < p:
            caps.append(0)
        else:
            caps.append(min(m, (T - p) // s))
    caps.sort(reverse=True)
    return sum(caps[:R]) >= B

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        R, B, C = map(int, input().split())
        cashiers = [tuple(map(int, input().split())) for _ in range(C)]

        lo, hi = 0, 0
        for m, s, p in cashiers:
            hi = max(hi, p + m * s)

        while lo < hi:
            mid = (lo + hi) // 2
            if can(mid, R, B, cashiers):
                hi = mid
            else:
                lo = mid + 1

        print(f"Case #{tc}: {lo}")

if __name__ == "__main__":
    solve()
```実現可能性チェックは次のように実装されます。`can`。 各レジ担当者を時間 T での容量に変換し、最適な R を貪欲に選択します。実行可能性が単調であるため、二分探索は回答空間に対して実行されます。時間 T が機能する場合、それより大きな時間も機能します。 

よくある落とし穴は、容量を計算するときに Mi 制約を忘れることです。 もう 1 つは、T < Pi の場合に整数の除算を誤って使用することであり、明示的にゼロにクランプする必要があります。 上限には Pi と Mi × Si の両方を含める必要があります。 そうしないと、二分探索で正しい範囲が見つからなくなる可能性があります。

 ## 特殊なケース

 1 つのエッジ ケースは、すべてのレジ係について T が Pi より小さい場合に発生します。 その状況では、すべての容量がゼロになり、上位 R の容量の合計がゼロになるため、アルゴリズムは正しく実行不可能を返します。 これにより、割り当てが途中で受け入れられることがなくなります。 

もう 1 つのケースは、Mi が非常に大きいが Si も大きい場合です。 レジ係が技術的には多くのビットを取得できる場合でも、T が小さい場合は時間制約により実効容量が抑制されます。実現可能性チェックでは、式 (T − Pi) // Si を通じてこれを自然に処理します。この式は、T が Pi と交差するまでゼロになります。 

最後のケースは、B が、あるしきい値 T における R の最良のレジのキャパシティの合計に正確に等しい場合です。チェックでは以上か等しいを使用するため、等価性は正しく実行可能として扱われ、二分探索がオーバーシュートではなく最小有効時間に収束することが保証されます。
