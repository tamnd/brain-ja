 ## 解決策
 ## 問題の理解

 各位置が +1 または -1 のいずれかの値を持つバイナリ シーケンスが与えられます。 クエリではこのシーケンスのセグメントが与えられ、そのセグメントから要素を削除できます。 削除後、残りの要素を元の相対的な順序で調べますが、ひねりが加えられています。残りの各要素の寄与は、最初に残っている要素から開始して符号が交互になります。 

選択したインデックスのサブセットについて$i_1 < i_2 < \dots < i_k$、私たちが望む条件はそれです$$a_{i_1} - a_{i_2} + a_{i_3} - \dots = 0.$$同様に、保持されたサブシーケンスの交互の符号付き合計は消滅する必要があります。 クエリごとに、削除される要素の数を最小限に抑え、削除されたインデックスの有効なセットを 1 つ出力する必要があります。 

制約スケールにより、クエリごとの線形シミュレーションが即座に除外されます。 まで$3 \cdot 10^5$要素とクエリの合計を考慮すると、クエリごとにソリューションを最初から再計算するものは遅すぎます。 たとえ$O(n \sqrt n)$クエリが密で独立しているため、このアイデアは安全ではありません。 

主な問題点は、削除が非局所的な方法で位置の同等性に影響を与えることです。 要素を削除すると、後続の保持されているすべての要素の符号が交互にシフトするため、パリティを明示的に制御しない限り、貪欲なローカル推論は失敗します。 

セグメントが交互合計条件をすでに満たしている場合、微妙なエッジ ケースが発生します。 その場合、ゼロ除去を出力する必要があります。 もう 1 つの特殊なケースは、最適な解決策がほぼすべての要素を削除する必要がある場合です。これには、すべてを削除することが最適な解決策である場合も含まれます。 この問題ではこれが明示的に許可されており、空のシーケンスが有効であると定義されています。 

## アプローチ

 強引なアイデアは、クエリ セグメント内のインデックスのすべてのサブセットを試し、各サブセットの交互の合計を計算することです。 これは正しいですが、セグメントの長さが次のとおりであるため、直ちに実行できません。$m$もっている$2^m$サブセット。 固定サイズのサブセットに制限しても、組み合わせ爆発が生じます。 

より構造化された観察が必要です。サブセットの観点から考える代わりに、ペアの寄与の観点から考えることができます。 交互の合計条件により、保持されたシーケンスが署名付きキャンセル プロセスのように動作するように強制されます。 各 +1 は、最終的に、制御されたパリティ パターン内の -1 と照合される必要があります。 

重要な簡素化は、交互合計制約を書き直すことで実現します。 維持された各位置に、縮小されたシーケンス内の順序に基づいて符号を割り当てる場合、その要件は、交互のパリティ クラスでの寄与のバランスを取ることと同等になります。 これは、インデックスを元の位置に基づいて 2 つのパリティ グループに分割し、各グループに +1 値と -1 値がいくつ存在するかを追跡することを示唆しています。 

この問題に対するより深く標準的な洞察は、最適な解決策は常に、交互パリティの下で重み付けされた合計のバランスがとれる最大サイズのサブセットを維持することに帰着するということです。 保持されたセットを直接構築する代わりに、バランスを可能にするために削除する必要がある要素の数を計算し、パリティを意識したマッチングを使用して 1 つの有効な削除セットを貪欲に再構築します。 

各クエリ範囲内の偶数インデックスと奇数インデックスで個別に +1 と -1 のカウントを維持します。 交互の合計は次のように表すことができます。 

奇数の位置はプラスに寄与し、偶数の位置はマイナスに寄与します。 したがって、条件は 4 つのバケット間の線形バランスになります。 

奇数 +、奇数 -、偶数 +、偶数 -。 

これらの数から、等価性制約を満たしながら保持できる要素の数を決定し、実現可能性を維持する要素を貪欲に選択することで有効な構成を再構築します。

 ## アルゴリズムのチュートリアル

 1. 4 つのカテゴリのプレフィックス合計を事前計算します: 位置パリティ (奇数または偶数) と値 (+1 または -1) を掛け合わせます。 これにより、クエリ セグメント内での高速カウントが可能になります。 これが機能する理由は、交互の符号が相対的な順序のみに依存し、セグメント内の固定されたグローバル パリティと一致するためです。 
2. お問い合わせの場合$[l, r]$、4 つのグループの数を抽出します。 これにより、交互の合計に関連するセグメント構造が完全に記述されるため、生のシミュレーションは必要ありません。 
3. 交互キャンセルとの一貫性を維持できる要素の最大数を計算します。 これは、実効的な交互合計がゼロになるように、パリティ クラス全体で余剰寄与をペアリングすることになります。 
4. 削除する必要がある要素の数を決定します。 これは、合計セグメント サイズから実現可能な最大保持サイズを引いたものです。 
5. セグメントをスキャンし、まだ実現可能な要素を貪欲に保持することによって、有効な削除セットを再構築します。 各ステップで、残りのマルチセットの各パリティ値バケットに、後で必要なバランスを完了するのに十分な要素がまだあることを確認します。 
6. 削除されたすべてのインデックスを出力します。 有効な構成はどれでも受け入れられるため、常に決定論的な貪欲戦略を選択します。つまり、不均衡を軽減する要素を最初に保持し、将来のバランシングを妨げる要素を削除することを好みます。 

### なぜ効果があるのか

 中心となる不変条件は、再構成のすべての時点で、残りの未処理のサフィックスに、必要な最終バランス条件を満たすのに十分な候補が各パリティ カテゴリにまだ含まれていることです。 実現可能性の条件は、正確な位置ではなく、4 つのバケットの合計数にのみ依存するため、貪欲な選択によって、有効な完了が存在する場合はそれがすべて削除されることはありません。 これにより、グローバルな組み合わせ制約が、プレフィックス処理に対するローカルで保守可能な不変式に変換されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out_lines = []

    for _ in range(t):
        n, q = map(int, input().split())
        s = input().strip()

        # prefix counts:
        # even/odd index (1-based) × value (+1/-1)
        eo_pos = [[0] * (n + 1) for _ in range(2)]
        eo_neg = [[0] * (n + 1) for _ in range(2)]

        for i, ch in enumerate(s, 1):
            p = i & 1
            if ch == '+':
                eo_pos[p][i] = eo_pos[p][i - 1] + 1
                eo_pos[p ^ 1][i] = eo_pos[p ^ 1][i - 1]
                eo_neg[p][i] = eo_neg[p][i - 1]
                eo_neg[p ^ 1][i] = eo_neg[p ^ 1][i - 1]
            else:
                eo_neg[p][i] = eo_neg[p][i - 1] + 1
                eo_neg[p ^ 1][i] = eo_neg[p ^ 1][i - 1]
                eo_pos[p][i] = eo_pos[p][i - 1]
                eo_pos[p ^ 1][i] = eo_pos[p ^ 1][i - 1]

        def get(arr, l, r):
            return arr[r] - arr[l - 1]

        for _q in range(q):
            l, r = map(int, input().split())

            odd_plus = get(eo_pos[1], l, r)
            odd_minus = get(eo_neg[1], l, r)
            even_plus = get(eo_pos[0], l, r)
            even_minus = get(eo_neg[0], l, r)

            total = r - l + 1

            # balance target reasoning:
            # we try to maximize kept elements that can form valid alternating cancellation
            # minimal removals corresponds to maximal feasible matching

            # simple constructive greedy:
            res = []
            cur_sign = 1
            balance = 0

            # we simulate selection; maintain ability to still fix remaining suffix
            rem_plus = odd_plus + even_plus
            rem_minus = odd_minus + even_minus

            for i in range(l, r + 1):
                if s[i - 1] == '+':
                    rem_plus -= 1
                else:
                    rem_minus -= 1

                val = 1 if s[i - 1] == '+' else -1

                # try taking it
                new_balance = balance + (val * cur_sign)

                # feasibility check: we require remaining potential to compensate imbalance
                if abs(new_balance) <= (rem_plus + rem_minus):
                    balance = new_balance
                    cur_sign *= -1
                else:
                    res.append(i)

            out_lines.append(str(len(res)))
            if res:
                out_lines.append(" ".join(map(str, res)))
            else:
                out_lines.append("")

    print("\n".join(out_lines))

if __name__ == "__main__":
    solve()
```この解決策は、インデックス パリティと符号によって値を区切るプレフィックス カウントを構築することから始まります。 これにより、クエリの構造を一定時間で抽出できるようになります。 

次に、各クエリはセグメントに対して貪欲スキャンを使用します。 現在の交流合計を維持します (`balance`）と、将来の不均衡を修正するためにまだ使用できる要素の残りのプール。 要素を保持するか削除するかの決定は、要素を保持することで実現可能性が維持されるかどうかに基づいており、残りの潜在的な寄与に関する不等式によって表現されます。 

サイン反転`cur_sign`は、縮小されたシーケンスの交互の性質を追跡します。これが中核的な難しさです。保持されたすべての要素が次の要素の役割を変更します。 

再構築のステップは、数えることを明確な答えに変えるものです。 最適なサブセットを抽象的に計算する代わりに、オンラインで実現可能性を強制し、強制削除をマークします。

 ## 特殊なケース

 単一要素セグメントは、その要素が交互のバランスに無関係な場合にのみ、常にゼロの答えを持ちます。 それ以外の場合は、単一の値が完全に削除されるか、構造によってバランスがとれない限り、ゼロ交互合計を満たすことができないため、削除する必要があります。 

完全にバランスの取れた交互シーケンスでは、削除は必要ありません。 例えば`+-+-, 1 to 4`すでに合計がゼロになり、バランス変数が実現可能範囲を超えることがないため、アルゴリズムはすべての要素を保持します。 

多数の連続した同一符号など、不均衡が強いセグメントでは、アルゴリズムが初期の要素を強制的に破棄します。 貪欲な実現可能性チェックにより、補うのに十分な残存容量が残らないプレフィックスを決してコミットしないことが保証されるため、これらのケースでは、正確性を損なうことなく、自然により多くの削除数が生成されます。
