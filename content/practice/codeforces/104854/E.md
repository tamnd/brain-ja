 ## 解決策
 ## 問題の理解

 開始括弧、終了括弧、およびワイルドカード記号の 3 つの可能な文字で構成される文字列が与えられます。 各ワイルドカードは、後で開始括弧または終了括弧のいずれかに個別に置き換えることができます。 すべての置換を行った後、結果の文字列は有効な括弧サブシーケンスのセットを定義します。そして、その「美しさ」と呼ばれる単一の量に注目します。 

美しさは、正しい括弧シーケンスを形成するサブシーケンスの可能な最大長として定義されます。 正しい順序とは、括弧のバランスが取れており、どの接頭辞にも開き括弧よりも閉じ括弧が多く存在しない順序です。 重要なのは、部分文字列ではなくサブシーケンスを取得しているため、最適な有効な構造を形成するときに途中の文字を任意に削除できることです。 

タスクは、この達成可能な最もバランスの取れたサブシーケンスが可能な限り小さくなるように、各ワイルドカードをブラケット タイプに割り当てることです。 

n が 4 · 10^6 までの制約により、線形または線形に近い時間に強制されます。 二次関数、または大きな定数を含む n log n であっても、生の入力サイズだけが原因でタイムアウトになる危険性があります。 この構造は、多くの代入に対してサブシーケンスのマッチングを繰り返しシミュレートするアプローチを避けるべきであることも示唆しています。 

微妙な点は、サブシーケンスの最適性が相対位置を超えた順序制限を無視することです。 文字列が局所的に非常に不均衡である場合でも、文字をスキップすることでバランスの取れたサブシーケンスを抽出できる場合があります。 これは、どれだけの括弧をペアにできるかを慎重に検討しない限り、最終文字列に対する素朴な貪欲なシミュレーションでは十分ではないことを意味します。 

ワイルドカードが末尾に集中している場合、または文字列にすでに強い不均衡がある場合、エッジ ケースが発生します。 たとえば、文字列がすでにワイルドカードを除くすべて左括弧である場合、最適な割り当てにより、使用可能なペアが意図的に削減される可能性があります。 文字を修正した後に「常に可能な限りバランスをとる」といった単純な考えは失敗します。これは、最終的に達成可能な一致を最小限に抑えるために、敵対的に割り当てを選択しているためです。 

## アプローチ

 直接的な総当たり戦略は、各ワイルドカードを個別に扱い、両方の選択肢を試し、結果として得られる完全に固定された文字列の美しさを計算することです。 完成した文字列ごとに、最も長い正しい括弧のサブシーケンスを計算します。これは、スタック カウンターまたはバランス カウンターを使用して貪欲に括弧を一致させることと同等です。 k 個のワイルドカードを使用すると、2^k の可能性が得られ、各評価のコストは O(n) となるため、最悪のケースは O(n 2^n) となり、指定されたスケールでは完全に実行不可能になります。 

重要な観察は、代入後に正確に一致する部分配列構造を実際に知る必要がないということです。 固定文字列の美しさは、非負の接頭辞の意味で、開始括弧と閉じ括弧をいくつ組み合わせられるかによってのみ決まります。これは、接頭辞の不均衡の動作によって決まります。 ワイルドカードの決定は、プレフィックス全体に分散できるオープン数とクローズ数にのみ影響します。 

マッチングをシミュレートする代わりに、最適なサブシーケンスが左から右にできるだけ多くの有効なペアを貪欲に取得することを尊重しながら、オープンとクローズの最終的なカウントを制御するものとして問題を再解釈できます。 これにより、問題は組み合わせによる割り当てからプレフィックス容量のバランスに変わります。つまり、早期に利用可能な「開始供給」の量と、後で現れる「終了需要」の量を効果的に決定することになります。 

再フレーム化されると、構造は古典的なプレフィックス実現可能性最小化問題になります。スタック可能なペアの最大数が最小化されるように、一致しないクローズをできるだけ多く強制したいと考えます。 これにより、早期のオーバー クロージングを防ぐためにまだ配置しなければならないオープンの数と強制制約がどれだけ残っているかを追跡しながら、各ワイルドカードの最終的なブラケット タイプを決定する貪欲な構築が可能になります。

最適な解決策は、文字列を 1 回スキャンし、固定文字と未決定のワイルドカードからまだ「利用可能な」オープンとクローズの数を維持し、その後、将来のマッチングに可能な限り害を及ぼさない方法でワイルドカードを割り当てることです。

 ## アルゴリズムのチュートリアル

 固定文字と残りのワイルドカードの両方から配置できる開始部分と終了部分の数を維持しながら、文字列を処理します。 重要な考え方は、ワイルドカードに遭遇するたびに、将来有効なペアを形成する能力を低下させたいかどうかに基づいてそのタイプを選択するということです。 

私たちは 2 つのカウンタを維持します。まだ配置できる残りのオープンと、残りのクローズです。 これらはグローバル合計から取得されます。「(」が増加するたびに開き、「)」が増加するたびに閉じられ、それぞれの「?」が増加します。 1 つの柔軟なユニットに貢献します。 

また、実行バランスの制約も維持します。有効なサブシーケンスはプレフィックスの実現可能性を考慮する必要があるため、可能な限り最良のマッチングは、文字がスタックに寄与していると解釈しようとする場合にプレフィックスが負にならない回数によって制限されます。 

貪欲な戦略は、次のようにワイルドカードを割り当てることです。 

1. 固定「(」と「)」の合計数と合計「?」を計算します。 
2. 最終的に一致するペアの数を最小限に抑えるために、ワイルドカードをオープンとクローズに分割する方法を決定します。 一致するペアには 1 つのオープンと 1 つのクローズが必要であるため、敵対者は制限側をできるだけ小さくしたいと考えます。 
3. 文字列を左から右に処理し、各「?」を割り当てます。 '(' または ')' を使用して、プレフィックスを有効なサブシーケンス構造として解釈できなくなるのを避けるために、割り当てる必要があるオープンの数を追跡します。 
4. 代入するときは常に、余裕ができたらできるだけ早く ')' を配置することを優先します。これは、シンボルを早く閉じると、後で長く有効なサブシーケンスを形成する能力が低下するためです。 
5. 構築された不均衡を考慮して、可能性のある強制一致の数を追跡することにより、可能な限り最適なサブシーケンス長を暗黙的にシミュレートします。 

この実装は、事実上、敵対的割り当ての下でいくつのブラケットをペアにできるかを計算することになり、プレフィックスの実現可能性制約の下で達成可能な制約付き最小値 min(opens, closes) を計算することに変わります。 

### なぜ効果があるのか

 正しいブラケットのサブシーケンスは、接頭辞制約が保持されるように、開始部分とその後の終了部分のペアに対応します。 これは、最終的な答えは基本的に、クローズが多くなりすぎる前に「使用可能な」状態を維持できるオープンの数によって制限されることを意味します。 敵の役割は、できるだけ早くこのバランスを破壊することです。 

左から右にスキャンしながら、オープンとクローズの利用可能なバジェットの観点から常に推論することにより、残りの不一致の可能性が将来の可能な限り最良のペアリングを反映するという不変条件を維持します。 貪欲な選択とは異なるワイルドカードの代替割り当ては、クロージングを遅らせるか、オープニングを早く消費するかのいずれかであり、どちらも最終的に一致するペアの数を増やすだけです。 これにより、達成可能なサブシーケンス長を最小限に抑えるためには、貪欲な割り当てが極端であることが確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    fixed_open = s.count('(')
    fixed_close = s.count(')')
    q = s.count('?')

    # We want to minimize the maximum number of matched pairs.
    # Each pair consumes one '(' and one ')'.
    # So we reason in terms of how many effective opens/closes we can force.

    # Let total opens we will end up with:
    # fixed_open + x
    # closes: fixed_close + (q - x)

    # matched pairs is limited by min(opens, closes).
    # So we want to choose x to minimize min(fixed_open + x, fixed_close + q - x).

    # This is a classic V-shape minimum; optimal occurs when we push imbalance.

    # We try both extreme allocations and pick worst (since we are minimizing match capacity).
    # But adversary chooses x implicitly; we compute best achievable minimum.

    # The function is concave in x for min, so optimal at boundary:
    # x = 0 or x = q

    option1 = min(fixed_open, fixed_close + q)
    option2 = min(fixed_open + q, fixed_close)

    print(max(option1, option2))

if __name__ == "__main__":
    solve()
```このコードは、問題全体を固定括弧とワイルドカードのカウントに圧縮し、すべてのワイルドカードの 2 つの極端な割り当てを開始または終了として評価します。 極値のみが重要となる理由は、x の 2 つの線形関数の最小値がエンドポイントで最大化されるため、達成可能な最良のペアを最小化することが目標の場合、混合割り当ては完全に歪んだ割り当てに勝てないためです。 

最終的な答えは、すべての柔軟性を一方の方向または他方の方向に押し出すことに対応する、2 つの最悪の場合のマッチング容量の最大値です。 

よくある落とし穴は、サブシーケンスを直接シミュレートしようとすることです。 敵対的な構築ではサブシーケンスの最適性が全体的なカウントに崩壊するため、これは重要ではない構造を過大カウントすることになります。 

## 実用的な例

 インプットを考慮する`((??)))))`。 2 つのワイルドカードを使用して、固定オープンを 2 としてカウントし、固定クローズを 5 としてカウントします。 

| x (ワイルドカードは '(') | 開く | 閉じる | min(開く, 閉じる) |
 | --- | --- | --- | --- |
 | 0 | 2 | 7 | 2 |
 | 2 | 4 | 5 | 4 |

 敵対的な最適な選択は、より大きな最小値に向かってバランスをとることで、4 になります。これは、不均衡にもかかわらず形成できるペアの数を最大化することに対応します。 

ここで考えてみましょう`()??)((?)?)()()?)??)?`単純化された推論ビューで。 文字列はローカルではすでにかなりバランスが取れていますが、ワイルドカードを使用すると不均衡を変更できます。 すべてのワイルドカードを 1 つのブラケット タイプに押し込むと、開始部分または終了部分が飽和し、一致するボトルネックが一方的になります。 この式は両方の極値を評価し、最適な割り当て後に達成可能な最悪のペアリングを反映して、より強力な制限ケースを選択します。 

これらの例は、サブシーケンスの柔軟性が順序付けの制約を吸収するため、文字列の内部構造はカウントを超えて重要ではないことを示しています。

 ## 特殊なケース

 特殊なケースの 1 つは、文字列にワイルドカードが含まれていない場合です。 のような入力の場合`((()))`の場合、アルゴリズムはすぐに固定カウントに減少し、両方の極端な割り当てが一致します。 バランスを悪化または改善する柔軟性が存在しないため、計算された最小値は変更されません。 

もう 1 つの特殊なケースは、すべての文字がワイルドカードである場合です。 のために`??????`、2 つの極端な割り当ては、すべてオープンまたはすべてクローズに崩壊します。 どちらも、敵対的に解釈された場合、最悪のサブシーケンスの意味で使用可能なペアがゼロになり、式は対称制限を正しく捉えています。 

3 番目のケースは、次のような大きく偏ったプレフィックスです。`((((((????`。 ここで、すべてのワイルドカードを ')' として割り当てると部分的にバランスが修復されますが、'(' として割り当てるとバランスが悪化します。アルゴリズムは両方の極端な値をテストし、プレフィックスのシミュレーションを必要とせずに、強制できる最善の値が完全に強い側の不均衡によって支配されることを正確に識別します。
