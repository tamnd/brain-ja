 ## 解決策
 ## 問題の理解

 私たちには、水平線によって 2 つの運動領域に分割された 2D 連続世界が与えられています。$y = 0$。 ポイント付き$y \ge 0$ケンが高速で移動する土地です$v_{run}$、およびポイント$y < 0$彼が高速で移動する場所は海です$v_{swim}$、 と$v_{run} \ge v_{swim}$。 ケンは 1 つの座標からスタートし、アイスクリーム スタンドという固定の目的地があります。 海の中には、$n \le 15$静止した水泳選手は全員アイスクリームスタンドまで運ばなければなりません。 ケンはせいぜい運べる$s$つまり、海で子供たちを拾い、一緒に運び、アイスクリームスタンドに降ろすだけで済みます。 

このタスクは、ケンがすべての水泳選手をアイスクリーム スタンドに連れて行くのに必要な最小時間を計算することです。ケンの移動時間は、経路の各部分が陸か海か、また荷物を運んでいるかどうかによって異なります。 

主な難点は、移動が継続的であり、コストが水平境界の上または下にパスがどの程度あるかによって異なることです。 境界を越えると速度が変化するため、直線のユークリッド パスは一般に最適ではありません。 また、水泳選手を最大サイズのグループに割り当てます。$s$さまざまなグループが海と陸の間の繰り返しの移動の構造を変化させます。 

この制約は、指数関数的な依存が水泳選手のサブセットに限定されなければならないことを直ちに示唆しています。 以来$n \le 15$、$O(3^n)$または$O(n^2 2^n)$スタイル状態の圧縮は妥当です。 座標値は大きいですが、幾何学的距離にのみ影響するため、遷移中の動的な幾何学的推論ではなく、ペアごとの移動コストの事前計算が期待されます。 

連続的な移動をシミュレートしたり、各ルートの最短パスを再計算しようとする単純なアプローチは、ジオメトリが連続的でパスに依存するため、失敗します。 もう 1 つの微妙な問題は、この 2 速度の半平面の 2 点間の最適な経路が必ずしも直線であるとは限らないことです。これは、境界に沿って移動する方が有益な場合があるためです。$y = 0$より速い地上速度を利用するため。 

エッジケースは、水泳者が境界線の真上または近くにいるときに発生します。 たとえば、ケンが水中でスタートし、アイスクリーム スタンドが陸上にある場合、速度比に応じて、最適なルートは境界を 1 回ではなく複数回通過する可能性があります。 

## アプローチ

 ブルートフォースの観点は、ケンが最大でも次のサブセットを繰り返し選択することを考えることです。$s$スイマーは、現在の位置から順に1つずつ回収し、アイスクリームスタンドに戻ります。 サブセットを修正したとしても、ピックアップの順序と連続空間内の正確なパスを区分的な速度で決定する必要があります。 これは、サブセットごとに水泳選手の順列と、境界上の異なる交差点の可能性を考慮することになるため、すぐに手に負えなくなります。 

ただし、固定されたポイントのペアの場合、2 つの一定速度でのこの半平面での最適な移動時間は既知の構造になります。つまり、経路は、海の中の最大 1 つの直線セグメント、境界に沿ったセグメント、および陸上の直線セグメントで構成されます。 これにより、各移動コストが完全なパス検索ではなく、エンドポイントの計算可能な関数に削減されます。 

関数を計算できるようになると、$dist(a, b)$任意の 2 点間の最適な移動時間を表すと、問題は組み合わせになります。 各アクションは次のとおりです: ある地点 (ケンのスタートまたはアイスクリームスタンドのいずれか) から開始し、水泳選手のサブセット (サイズ) を選択します。$\le s$）、順番に訪問し、最後にアイスクリームスタンドで終わります。 グループのコストは順列全体で最小になりますが、$n \le 15$を使用すると、出発点から目的地で終わるサブセットまでの移動にかかる最適なコストを事前計算できます。 

重要な洞察は、すべての幾何学的複雑さをペアごとの移動時間に圧縮し、残りをスイマーのサブセットに対するビットマスク DP として扱うことです。トランジションは、最大 1 つのバッチを提供することに対応します。$s$水泳選手。 

水泳選手がすでに配達された状態と、最後の「位置コンテキスト」（ケンのスタートまたは配達後のアイスクリームスタンドのいずれか）を定義します。 すべてのバッチがアイスクリーム スタンドで終了するため、DP 遷移は常に固定アンカーに戻るため、構造が簡素化されます。 

以下を事前計算します。 

- スタートからスイマーまたはスタンドまでの費用、
 - 水泳選手間のコスト、
 - 水泳選手からスタンドまでのコスト、

 すべて最適な半平面移動のもとで行われます。 

次に、サブセットごとに$mask$、最大サイズのグループを選択する最適な方法を計算します。$s$、スタンドから開始して (または最初のバッチから開始して) サービスを提供するための最小移動コストを計算し、サブセット パーティションにわたる DP を緩和します。 

これにより、連続ジオメトリの問題がサブセット パーティションにわたる最短パスに短縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (パス + 順列) | 指数関数的に超える$n!$と連続 | 高い | 遅すぎる |
 | 最適 (ジオメトリ + ビットマスク DP) |$O(n^2 2^n + 2^n \cdot 2^s)$|$O(2^n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの速度を次のように分割して、平面内の任意の 2 点間の最適な移動時間を与える関数を事前計算します。$y=0$。 これは、境界上の考えられる交差点を最小化することによって行われます。$y=0$最適なパスは境界を越えるときにのみ速度が変化するためです。 決定変数は交差点の x 座標となり、三分探索を使用して 1D で最適化できます。 
2. 関連するすべてのポイントのリストを作成します: ケンのスタート、アイスクリーム スタンド、およびすべての水泳選手。 ステップ 1 の関数を使用して、これらのポイントのすべてのペア間のペアごとの移動時間を計算します。 
3. スイマーのサブセットに対して DP 配列を定義します。 させて$dp[mask]$水泳選手を正確に送り届けるための最短時間を表します。$mask$そしてアイスクリームスタンドで終わります。 
4.初期化$dp[0]$これは、ケンが開始位置から誰も乗せずにアイスクリーム スタンドまで移動する時間です。これが最初の「アンカー リセット」状態であるためです。 
5. サブセットごとに$mask$、すべてのサブマスクを考慮します$sub$の$mask$そのような$1 \le |sub| \le s$。 これは、1 回の旅行で配送する次の水泳選手のグループを選択することを表します。 
6. それぞれのバッチについて$sub$、すべての水泳選手を迎えに行くコストを計算します。$sub$アイスクリームスタンドから出発し、移動時間を最小にする順序で訪問し、アイスクリームスタンドに戻ります。 以来$s \le 15$、サイズのサブセットにわたる小さな DP を使用して、このコストを事前計算できます。$s$。 
7. 設定により DP トランジションを緩和します。$dp[mask] = \min(dp[mask], dp[mask \setminus sub] + cost[sub])$。 
8. 答えは次のとおりです。$dp[(1 << n) - 1]$なぜなら、それはすべての水泳選手を引き渡すことを意味するからです。 

それが機能する理由は、おそらくケンの最初の位置からの最初の動作を除いて、すべての有効な戦略がアイスクリーム スタンドで始まりアイスクリーム スタンドで終わる独立した移動に分解できるという観察から来ています。 各旅行は、結合されていない水泳選手のサブセットを処理し、旅行内の順序は、事前に計算されたサブセットの旅行コストによって捕捉されます。 DP はスイマーのすべてのパーティションをバッチに列挙し、サブマスク遷移により、すべてのパーティションに 1 回だけ到達できることが保証されます。 幾何学的最適性は、事前に計算されたペアごとのコストとサブセット コストに完全に含まれているため、DP は幾何学ではなく、グループ化の組み合わせ論のみを推論します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import hypot

# We compute optimal travel time between two points in half-plane with different speeds.
# We model boundary crossing at y = 0 with a single crossing point x.

def dist(a, b, v_land, v_sea):
    (x1, y1) = a
    (x2, y2) = b

    if y1 >= 0:
        v1 = v_land
    else:
        v1 = v_sea

    if y2 >= 0:
        v2 = v_land
    else:
        v2 = v_sea

    # If both on same side, straight line
    if (y1 >= 0) == (y2 >= 0):
        return hypot(x1 - x2, y1 - y2) / v1

    # crossing boundary y=0 at (t, 0)
    def f(t):
        d1 = hypot(x1 - t, y1)
        d2 = hypot(x2 - t, y2)
        return d1 / v1 + d2 / v2

    # ternary search on real line
    lo, hi = -1e7, 1e7
    for _ in range(80):
        m1 = (2 * lo + hi) / 3
        m2 = (lo + 2 * hi) / 3
        if f(m1) < f(m2):
            hi = m2
        else:
            lo = m1
    return f((lo + hi) / 2)

def solve():
    xk, yk = map(int, input().split())
    xi, yi = map(int, input().split())
    vrun, vswim = map(int, input().split())
    n, s = map(int, input().split())

    pts = [(xk, yk), (xi, yi)]
    swimmers = []
    for _ in range(n):
        swimmers.append(tuple(map(int, input().split())))
        pts.append(swimmers[-1])

    m = n + 2

    # precompute pairwise distances
    d = [[0.0] * m for _ in range(m)]
    for i in range(m):
        for j in range(m):
            d[i][j] = dist(pts[i], pts[j], vrun, vswim)

    start = 0
    goal = 1

    # cost to serve a subset starting and ending at goal
    # include start->first handled separately for dp initial step

    subset_cost = [0.0] * (1 << n)

    # precompute cost of visiting subset and returning to goal
    for mask in range(1 << n):
        nodes = [goal]
        for i in range(n):
            if mask & (1 << i):
                nodes.append(i + 2)

        k = len(nodes)
        if k == 1:
            subset_cost[mask] = 0.0
            continue

        dp = [[float('inf')] * k for _ in range(1 << k)]
        dp[1][0] = 0.0

        for state in range(1 << k):
            for i in range(k):
                if not (state & (1 << i)):
                    continue
                cur = dp[state][i]
                if cur == float('inf'):
                    continue
                for j in range(k):
                    if state & (1 << j):
                        continue
                    ns = state | (1 << j)
                    dp[ns][j] = min(dp[ns][j], cur + d[nodes[i]][nodes[j]])

        full = (1 << k) - 1
        best = float('inf')
        for i in range(k):
            best = min(best, dp[full][i] + d[nodes[i]][goal])
        subset_cost[mask] = best

    INF = float('inf')
    dp = [INF] * (1 << n)
    dp[0] = d[start][goal]

    for mask in range(1 << n):
        if dp[mask] == INF:
            continue
        rem = ((1 << n) - 1) ^ mask
        sub = rem
        while sub:
            if sub.bit_count() <= s:
                new_mask = mask | sub
                dp[new_mask] = min(dp[new_mask], dp[mask] + subset_cost[sub])
            sub = (sub - 1) & rem

    print(dp[(1 << n) - 1])

if __name__ == "__main__":
    solve()
```この実装では、まず境界交差最小化を使用してジオメトリを距離行列に圧縮します。 三分探索は、終点が水線の異なる側にある場合にのみ適用されます。その場合、最適なパスは境界を越える場所を選択する必要があるからです。 

次に、各エントリがアイスクリーム スタンドから始まり、まさにそのサブセットの水泳選手を訪問し、スタンドに戻る最適なツアーを表すサブセット コスト テーブルを作成します。 これは本質的に、最大 17 ノードにわたる小規模な巡回セールスマン DP です。 

最後に、グローバル DP は、スイマーのパーティションを最大サイズのバッチに列挙します。$s$、サブセットコストを累積します。 各トランジションは、アイスクリーム スタンドからの 1 回の完全な「旅行」を表します。 

微妙な点は初期化です。ケンの開始位置からの最初の移動は、アイスクリーム スタンドへの直接コストとして含まれます。これは、すべての戦略が最初にスタンドに到達し、次に完全な配達サイクルを実行すると見なすことができるためです。

 ## 特殊なケース

 重要なケースの 1 つは、ケンが境界線から正確に開始した場合です。$y = 0$。 その状況では、速度は移動方向に即座に依存するため、最適なパスの計算では初期媒体を想定してはなりません。 距離関数はエンドポイントを個別に分類するため引き続き機能しますが、単純な「常に陸地から開始する」という仮定では対称性が崩れます。 

もう 1 つの微妙なケースは、すべての水泳選手が海中で互いに非常に近くに横たわっている場合です。 最も近い泳ぎ者を最初に選ぶという貪欲な戦略は、アイスクリームスタンドに余分な利益をもたらす可能性があるため、失敗する可能性があります。 DP は、次の場合にそれらを単一のサブセットに正しくグループ化します。$s$を可能にし、不必要なラウンドトリップを排除します。 

最後に、いつ$v_{run} = v_{swim}$、境界は無関係になり、三分探索は直線ユークリッド距離に退化します。 最適化が平坦な最小値を持つ凸対称関数に還元され、三分探索が有効な交差点に収束するため、実装は引き続き機能します。
