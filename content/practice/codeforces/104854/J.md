 ## 問題の理解

 この状況は、各ギフト タイプがノードであり、考えられる各交換が労力を表す正のコストを持つ有向エッジである有向グラフとして考えることができます。 1 回の交換は 1 つのエッジに沿って移動することを意味し、複数の交換を行うことは、有向パスに沿って歩き、エッジの重みを蓄積することに相当します。 

重要な詳細は、開始ギフトが不明であることです。 友人は任意のノードから開始し、任意の数の交換を実行し (同じ交換を繰り返す可能性があります)、最終的には既知のギフトで終了します。$y$。 私たちは何も再構築するよう求められず、単に次で終わる一連の交換が存在するかどうかを判断するだけです。$y$その総努力が少なくとも$k$。 

したがって、実際の質問は次のようになります。有向重み付きグラフでは、ノードで終了するウォークはありますか?$y$少なくとも総重量があれば$k$、開始ノードは制限されておらず、エッジは再利用できます。 

制約は以下を意味します$10^5$すべてのテスト ケースにわたってノードとエッジを実行するため、ソリューションはテスト ケースごとに本質的に線形またはほぼ線形の時間で実行する必要があります。 これにより、すべてのパスを列挙したり、すべての歩行距離をブルートフォースしようとしたりするような行為が即座に除外されます。 構造のないすべてのパスにわたる動的プログラミングでさえ、サイクルでは無限に多くのウォークが可能になるため、爆発するでしょう。 

微妙な問題はサイクルに起因します。 すべてのエッジの重みは正であるため、任意のサイクルを繰り返し走査して総エフォートを任意に増やすことができます。 これは、グラフ内に最終的に次のようなサイクルが存在する場合、$y$とすると、答えはどの項目に対しても自明に「YES」になります。$k$、サイクルは、目的地に向かう前に必要なだけポンプで汲み上げることができるためです。$y$。 

2 番目のエッジ ケースは、有用なサイクルがない場合に発生します。 到達可能なすべての構造が非巡回である場合、私たちができる最善のことは、最大パス合計を計算することです。$y$と比較してください。$k$。 サイクルを無視したり、単純なパスを想定した単純なアプローチは、次のような場合に黙って失敗する可能性があります。 

入力:```

```ここでは、ノード 1 と 2 がサイクルを形成します。 このサイクルから、3 に進む前にループして任意の大きな労力を蓄積できます。正しい出力は「YES」です。 最短または最長の単純なパスのみを計算するアプローチでは、値が誤って制限されてしまいます。 

別の失敗ケースは、サイクルが存在するが、そのパス上にない場合に発生します。$y$。 これらのサイクルは役に立たないため、無視する必要があります。 

## アプローチ

 直接的な強引なアイデアは、次で終了するすべての可能なウォークを考慮することです。$y$、累積重量を追跡します。 ウォークではノードを再訪問できるため、これは実質的に無限状態の検索になります。 たとえ検索深さに上限を設けたとしても、分岐要素とサイクルの組み合わせにより指数関数的な爆発が起こります。 までの長さの個別の歩行の数$L$実行可能な限界を簡単に超えてしまう可能性がある$m$大きいです。 

重要な観察は、重要な構造上の特徴は 2 つだけであるということです。1 つはサイクルを使用して任意に重量を増やすことができるかどうか、もう 1 つは達成可能な最大重量はいくらかということです。$y$は。 

サイクルは重要なオブジェクトです。 すべての重みが正であるため、最終的に到達できるルート上で到達可能なサイクルはすべて$y$ポンプのように機能し、無制限の蓄積を可能にします。 これは、グラフを強く接続されたコンポーネントに圧縮することを示唆しています。 強く接続されたコンポーネント内では、すべてのノードが他のすべてのノードに到達できるため、どのサイクルも 1 より大きいサイズのコンポーネント (または自己ループ) に対応します。 

凝縮後、グラフは有向非巡回グラフになります。 到達可能な部分に部品があれば、$y$サイクルが含まれている場合、答えはすぐに「YES」になります。 そうでない場合、問題は、次のコンポーネントで終了する DAG 内の最大パス合計を見つけることになります。$y$、これは位相順序の動的計画法で解くことができます。

 ## アルゴリズムのチュートリアル

 まず、すべての内部サイクルが局所化されるように、グラフを強く接続されたコンポーネントに分割します。 

1. 有向グラフの強接続成分を計算します。 各ノードにはコンポーネント ID が割り当てられ、そのコンポーネントにサイクルが含まれているかどうかも判断されます。 コンポーネントに複数のノードがある場合、または自己ループ エッジがある場合、コンポーネントは循環的です。 
2. 各コンポーネントが 1 つのノードになり、コンポーネント間のすべてのエッジがその重みとともに保持される凝縮グラフを構築します。 平行なエッジは関係ありません。 
3. ターゲット ノードを含むコンポーネントを特定する$y$。 圧縮されたグラフ内のこのターゲット コンポーネントに到達できるコンポーネントのみを考慮します。 
4. ターゲット コンポーネントから開始して逆到達可能性検索を実行し、最終的にターゲット コンポーネントに到達できるすべてのコンポーネントをマークします。 マークされていないコンポーネントは次で終了できないため無関係です。$y$。 
5. マークされたコンポーネントが循環している場合は、すぐに「YES」を返します。 その理由は、そのようなコンポーネントが何らかのルート上にあるためです。$y$、そしてそのサイクルにより、目標に向かって進む前に任意に大きな努力を蓄積することができます。 
6. そのような循環コンポーネントが存在しない場合、到達可能なサブグラフは DAG です。 次に、DAG 上で逆トポロジー順序で動的プログラミングを使用して、ターゲット コンポーネントへの可能な最大累積重みを計算します。 
7. 計算された最大値が少なくとも次の場合、最終的な答えは「はい」です。$k$、そうでない場合は「いいえ」。 

### なぜ効果があるのか

 結露後、終了するすべての散歩は、$y$はコンポーネント DAG 内のパスに対応しますが、循環コンポーネント内では任意に何度もループできる点が異なります。 すべての重みは厳密に正であるため、すべてのサイクルは厳密に合計コストを増加させるため、パス上のサイクルの存在は無視されます。$y$無制限の達成可能なコストを意味します。 これらのコンポーネントが除外されると、残りの構造は非循環となるため、すべてのパスは有限であり、明確に定義された最大合計値を持ちます。 したがって、DAG 上の DP は、達成可能な最適な労力を正確に取得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def kosaraju(n, g, gr):
    visited = [False] * n
    order = []

    def dfs1(v):
        visited[v] = True
        for to, _ in g[v]:
            if not visited[to]:
                dfs1(to)
        order.append(v)

    for i in range(n):
        if not visited[i]:
            dfs1(i)

    comp = [-1] * n
    cid = 0

    def dfs2(v):
        comp[v] = cid
        for to, _ in gr[v]:
            if comp[to] == -1:
                dfs2(to)

    for v in reversed(order):
        if comp[v] == -1:
            dfs2(v)
            cid += 1

    return comp, cid

def solve():
    n, m, k, y = map(int, input().split())
    y -= 1

    g = [[] for _ in range(n)]
    gr = [[] for _ in range(n)]
    edges = []

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, w))
        gr[v].append((u, w))
        edges.append((u, v, w))

    comp, c = kosaraju(n, g, gr)

    comp_g = [[] for _ in range(c)]
    comp_gr = [[] for _ in range(c)]
    comp_has_cycle = [False] * c

    for u, v, w in edges:
        cu, cv = comp[u], comp[v]
        if cu == cv:
            if u == v:
                comp_has_cycle[cu] = True
        else:
            comp_g[cu].append((cv, w))
            comp_gr[cv].append((cu, w))

    y_comp = comp[y]

    # mark reachable to y in condensed graph (reverse edges)
    stack = [y_comp]
    vis = [False] * c
    vis[y_comp] = True

    for v in stack:
        for to, _ in comp_gr[v]:
            if not vis[to]:
                vis[to] = True
                stack.append(to)

    for i in range(c):
        if vis[i] and comp_has_cycle[i]:
            print("YES")
            return

    # DAG DP for longest path to y_comp
    indeg = [0] * c
    for v in range(c):
        for to, w in comp_g[v]:
            indeg[to] += 1

    from collections import deque
    q = deque([i for i in range(c) if indeg[i] == 0])

    topo = []
    while q:
        v = q.popleft()
        topo.append(v)
        for to, _ in comp_g[v]:
            indeg[to] -= 1
            if indeg[to] == 0:
                q.append(to)

    dist = [-10**30] * c
    dist[y_comp] = 0

    for v in reversed(topo):
        if dist[v] < 0:
            continue
        for to, w in comp_g[v]:
            if dist[to] < dist[v] + w:
                dist[to] = dist[v] + w

    ans = max(dist[i] for i in range(c) if vis[i])
    print("YES" if ans >= k else "NO")

if __name__ == "__main__":
    solve()
```実装は、Kosaraju のアルゴリズムを使用して強接続コンポーネントを計算することから始まります。 これにより、周期的な動作が非周期的な構造から分離されます。 次に、圧縮グラフを構築し、各コンポーネントにサイクルが含まれているかどうかを明示的に記録します。これにより、重みを任意にポンピングできるかどうかが決まります。 

ターゲット コンポーネントからの逆到達可能性検索により、グラフの無関係な部分がすべて除外されます。 実際に到達できるコンポーネントのみ$y$サイクルのチェックやパスの計算時に考慮されます。 

このフィルタリングされた領域にサイクルが存在する場合は、すぐに「YES」を出力します。 それ以外の場合は、DAG 上で最長パスの動的プログラミング パスを実行します。 逆トポロジトラバーサルにより、ノードを更新するときに、その後続ノードからターゲットへのすべての貢献がすでに既知であることが保証されます。 

実装でよくある落とし穴は、「開始ノードは任意である」ということを忘れることです。つまり、到達できるすべてのコンポーネントを考慮する必要があります。$y$固定ソースから到達可能なものだけではありません。
