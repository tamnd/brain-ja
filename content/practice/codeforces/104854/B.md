 ## 解決策
 ## 問題の理解

 私たちは動的な複数の問題セットを管理します。 各問題には難易度の値と美しさの値があり、操作では特定の問題のインスタンスを挿入または削除します。 更新のたびに、有効な「コンテスト」の可能な最大の総合的な美しさを計算するように求められます。 

コンテストは、選択された問題を順序立てて並べたものであり、その構造は厳格です。問題が難しい場合は、`d`別の問題が続いている、次の問題はまさに難しいに違いない`⌊d / 2⌋`。 これにより、強制的な困難の連鎖が生じます。 開始難易度を選択すると、残りのシーケンスは、必要な次の難易度が利用できないために続行できなくなるまで、整数を 2 で割る繰り返しとして一意に決定されます。 

したがって、実際のタスクは次のとおりです。現在のマルチセットに存在する可能性のあるすべての開始困難の中から、常に半分に繰り返されるチェーンを選択し、そのチェーンに沿った美しさの合計を最大化します。 

入力サイズは最大 200,000 操作です。 これにより、更新のたびに最適なチェーンを最初から再計算する必要が直ちに排除されます。 単純な再計算では、すべての問題をスキャンし、チェーンを繰り返しシミュレートする必要がありますが、各操作にはすべてのアクティブな要素にわたって直線的な時間がかかる可能性があるため、最悪の場合には非常に遅くなります。 

主な問題点は、更新がクエリとインターリーブされ、単一の問題が多くのより高い難易度から始まるチェーンに参加するため、更新ごとに複数の潜在的なチェーンが変更される可能性があることです。 

ネガティブな美しさからは、微妙な特殊なケースが発生します。 スキップが許可されている場合、チェーンには到達可能なすべてのノードが強制的に含まれる必要はありませんが、ここでは開始を選択すると、その構造は厳密にシーケンシャルになります。 ただし、合計を最大化しているため、負の末尾は合計値を減らす可能性があるため、論理的に長い継続が存在する場合でも、単に悪いサフィックスにつながる開始ノードを選択しないことによって、最適なチェーンが早期に停止する可能性があります。 

もう 1 つの特殊なケースは、異なる美しさを持つ複数の同一の困難です。 問題は個別のエンティティであるため、1 つのインスタンスを削除することで集合効果が誤って削除されてはなりません。そのため、難易度ごとにマルチセットのような動作をサポートする構造が必要です。 

## アプローチ

 ブルートフォースアプローチでは、すべての既存の問題を反復し、それぞれを可能な開始点として扱うことにより、各更新後に最良のコンテストを再計算します。 開始問題から、次に必要な難易度を繰り返し計算し、一致する問題を検索し、毎回利用可能な最適な継続を選択します。 これは正しいです。有効なコンテストはすべて、その最初の要素によって完全に決定されるからです。 

ただし、これは高価です。 あれば`n`操作と最大`n`アクティブな問題の場合、再計算ごとにすべての問題をスキャンし、開始点ごとに長さのチェーンをたどることができます。`O(log maxD)`。 これはおおよそ次のことにつながります`O(n^2)`密集した場合の行動は限界をはるかに超えています。 

重要な観察点は、移行構造が固定的かつ決定的であるということです。各困難は正確に 1 つの先行者のみを指します。`2*d`、そして後継者1名、`d//2`。 これにより、困難を乗り越える連鎖の森が形成されます。 個々の問題の観点から考えるのではなく、難易度ごとに集計し、各難易度で達成可能な最良のチェーン終了を維持します。 

DP のような値を定義します`dp[d]`困難で終わる有効な連鎖の最大の美しさとして`d`。 で終わるチェーンはどれも`d`で終わるチェーンから来ている必要があります`2*d`、さらに難易度の問題を選択します`d`。 したがって、`dp[d]`のみに依存する`dp[2*d]`そして入手可能な最高の美しさ`d`。 これにより、各ノードが 1 つの親に依存する構造化グラフ全体で動的最大値を維持するという問題が軽減されます。 

それぞれの難易度において、現在進行中の問題の中で最高の美しさを維持します。 次に、DP 値を高い値から低い値まで維持するか、影響を受けるパスに沿って遅延再計算します。 各更新は 1 つの難易度にのみ影響するため、半分のチェーンに沿って上または下に、それぞれの長さを更新するだけで済みます。`O(log maxD)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log n) | O(n) | 遅すぎる |
 | 最適 | O(n log A) | O(A) | 承認済み |

 どこ`A`は最大の難易度です (≤ 1e6)。 

## アルゴリズムのチュートリアル

 私たちは 2 つの主要な構造を維持します。1 つは難易度ごとの美しさのマルチセットのような頻度マップ、もう 1 つは配列です。`best[d]`難易度に対して現在利用可能な最大の美しさを保存する`d`。 メンテナンスも行っております`dp[d]`、で終わる最高のチェーン`d`、そしてグローバルな答え。 

1. 配列を初期化する`best`そして`dp`1e6 までのあらゆる困難に対応。 最初はすべてが空ですので、`best[d] = -∞`そして`dp[d] = 0`。 
2. 操作ごとに、問題を挿入または削除します。`(d, b)`。 保存されている最高の美しさを難易度ごとに更新します`d`マルチセット構造に挿入または削除することによって。 更新後に再計算する`best[d]`残された最大限の美しさとして、または`-∞`空の場合。 
3. この更新されたノードから`d`、再計算します`dp`チェーンに沿った値`d, d//2, d//4, ...`。 各ステップで設定します。`dp[x] = max(dp[2*x] + best[x], dp[x])`ただし、依存関係は上位から下位にのみ流れるため、次のようにきれいに再計算します。`dp[x] = best[x] + dp[2*x]`もし`best[x]`存在する、それ以外の場合`0`。 
4. ゼロに達するまで上向きに伝播を続けます。 
5. 更新後、全体的な答えを最大値として再計算します。`dp[d]`すべての困難を乗り越えますが、伝播中に影響を受けるノードを追跡することで段階的に維持します。 

伝播がローカルで機能する理由は、`d`の変更の影響を受ける可能性があります`d`、それらのチェーンのみが含まれるため、`d`接尾辞に。 

### なぜ効果があるのか

 有効な各コンテストは開始難易度の選択に対応します`s`そして決定論的に従う`s, ⌊s/2⌋, ⌊s/4⌋, ...`。 固定の場合`s`、可能な限り最高の価値は、各ステップで利用可能な最高の美しさによって完全に決定されます。 したがって、で終わるサフィックスの最適な値は、`x`のみに依存する`2x`。 これにより、サイクルのない厳密な依存関係ツリーが作成されます。つまり、更新は曖昧さなく上方に伝播します。 影響を受けるすべての DP 状態は単一の長さのチェーン上に存在するため、`O(log A)`、再計算は制限されたままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXA = 10**6 + 5

# store multiset via dict of dicts or frequency maps
from collections import defaultdict

best = [0] * MAXA
cnt = defaultdict(lambda: defaultdict(int))

def recompute_best(x):
    if cnt[x]:
        best[x] = max(cnt[x].values())
    else:
        best[x] = 0

dp = [0] * MAXA

def recompute_chain(x):
    while x > 0:
        parent = x * 2
        if parent < MAXA:
            dp[x] = best[x] + dp[parent]
        else:
            dp[x] = best[x]
        x //= 2

n = int(input())
for _ in range(n):
    t, d, b = map(int, input().split())

    if t == 1:
        cnt[d][b] += 1
    else:
        cnt[d][b] -= 1
        if cnt[d][b] == 0:
            del cnt[d][b]

    recompute_best(d)
    recompute_chain(d)

    ans = max(dp)
    print(ans)
```実装では難易度ごとの頻度マップが保持されるため、重複があっても除去が安全に処理されます。 アップデートのたびに、その難易度に最適な美しさを再計算します。 DP の伝播は、半減チェーンを上向きにたどります。 

微妙な点は、`best[x] = 0`空のノードの場合。 これは、チェーンを停止することを選択できることを前提としています。これは正しいことです。コンテストは空であるか、継続を必要とせずに任意の時点で終了する可能性があるためです。 

DP 遷移は、ノードがその double にのみ依存するという事実を利用するため、再計算では無関係なブランチを再訪する必要がありません。 

## 実用的な例

 小さなシーケンスを考えてみましょう。

```挿入するたびに追跡します`best`そして`dp`。

次に、削除を含む 2 番目の例を示します。 

入力:```

2 2 10
```| ステップ | 操作 | 最高の変化 | dp チェーンの更新 | グローバルマックス |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log A) | 各更新は、長さ log A | の半分のチェーンに沿って再計算されます。 
| スペース | O(A) | すべての難易度にわたる最高および dp の配列 |

 と`n ≤ 2×10^5`そして`A ≤ 10^6`、各操作で約 20 件の更新しかトリガーされないため、これは制限内に問題なく収まります。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from collections import defaultdict

    MAXA = 10**6 + 5
    best = [0] * MAXA
    cnt = defaultdict(lambda: defaultdict(int))
    dp = [0] * MAXA

    def recompute_best(x):
        if cnt[x]:
            best[x] = max(cnt[x].values())
        else:
            best[x] = 0

    def recompute_chain(x):
        while x > 0:
            parent = x * 2
            if parent < MAXA:
                dp[x] = best[x] + dp[parent]
            else:
                dp[x] = best[x]
            x //= 2

    out = []

        recompute_chain(d)

 ## 特殊なケース

 主なエッジケースは、複数の問題が同じ難しさを共有しているものの、異なる美しさがある場合です。 たとえば、`(4, 5)`そして`(4, 10)`確保する必要があります`best[4] = 10`。 もし`(4, 10)`後で削除されますが、`best[4]`に戻らなければなりません`5`、ゼロではありません。 マルチセットベースの周波数マップは、美しさごとの数を追跡することでこれを保証します。 

もう 1 つのケースは、難易度の最後の要素を削除する場合です。 だけあったとします`(2, 10)`そして`(1, 7)`を削除します`(2, 10)`。 以前に 17 を提供していたチェーンは、即座に 7 に低下する必要があります。ノード 2 からの上向きの再計算により、次のことが保証されます。`dp[2]`次のように再計算されます`0 + dp[4]`、正しく伝播します。 

最後のケースは、困難がまばらであることです。 もしそうなら`d = 10^6`アクティブですが、再計算はまだチェーンをたどります`10^6 → 5×10^5 → ...`、対数のままです。 これにより、最悪の場合のスパース更新でもパフォーマンスが低下しないことが保証されます。
