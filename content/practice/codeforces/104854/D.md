 ## 解決策
 ## 問題の理解

 単一の整数が与えられます$n$、概念的に、1 から 2 までのすべての正の整数を書き留めます。$n$区切り文字なしで次々と 1 つの長い数字列を形成します。 たとえば、次の場合$n = 15$、文字列は`123456789101112131415`。 タスクは、部分文字列が何回出現したかを数えることです。`"42"`この連結された文字列内に出現します。数字を共有する場合、出現箇所が重複する可能性があります。 

入力できるサイズは、$n \le 2 \cdot 10^5$、これは、最後の文字列がおおよそ$O(n \log n)$数字。 最悪の場合、これは約数百万文字になります。 これにより、入れ子になったループ内で文字列全体を複数回繰り返し再構築または再スキャンするアプローチはすでに除外されています。 数字に対する二次スキャンは、プレフィックスを繰り返し再構築したり、大量の文字列操作を実行したりすると、遅すぎます。 

微妙な点は、`"42"`数値の境界と一致しない方法で桁の境界を越える可能性があります。 たとえば、`41`そして`42`、文字列には以下が含まれます`"...4142..."`、これはちょうど 1 つの出現に寄与します。 また、`"42"`次のような数字の中に表示できます`142`、`420`、または次のような連結ポイントをまたいでさえも`...3412...`境界が重要な場合。 

文字列全体を連結してから部分文字列検索を実行する単純なアプローチは概念的には正しいですが、不用意に高レベルの方法で直接実装すると、メモリと時間の両方が非効率になる危険性があります。 さらに重要なのは、文字列が構築されたとしても、スキャンの桁数は線形であり、これは許容されますが、文字列を明示的に構築する必要はないということです。 

主なエッジ ケースは境界の隣接関係から発生します。発生は、異なる整数に対応する桁の位置にまたがる可能性があります。 もう 1 つの特殊なケースは、次の値が小さいことです。$n$、 特に$n < 42$ここで、答えはゼロである必要があり、数字ベースのロジックではインデックス作成エラーを回避する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。1 から 2 までの完全な連結文字列を構築します。$n$、それを 1 回スキャンして、2 文字のパターンが何回表示されたかを数えます。`"42"`が表示されます。 これは問題定義と直接一致するため、正しいです。 スキャン自体は文字列の長さに対して線形です。$O(n \log n)$文字。 

問題は正確さではなく、構築のオーバーヘッドです。 単純なループで文字列を繰り返し追加すると、不変文字列を使用する言語では文字列連結の償却コストが 2 次になる可能性があります。 Python であっても、ループ内で不注意に連結を繰り返すと、パフォーマンスが大幅に低下する可能性があります。 

重要な点は、完全な文字列を一度に保存する必要がないということです。 隣接する各数字のペアが形成されるかどうかだけを知る必要があります。`"42"`。 つまり、数値を順番に処理し、前の数値の最後の桁のみを保持し、それが現在の数値の最初の桁とペアになるかどうかを確認できます。 各数値内で、隣接する数字もローカルでチェックします。 これにより、問題は完全な文字列の構築ではなく、数字のストリーミングに限定されます。 

したがって、グローバル オブジェクトを構築する代わりに、これまでに確認された最後の桁を追跡することによって連結境界をシミュレートします。 各数値は内部発生に寄与し、さらに 1 つの追加の潜在的な発生が境界を越えて発生します。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. カウンタをゼロに初期化し、変数を初期化します。`prev_digit`これは、連結内の前の数値の最後の桁を表します。 最初は前の桁がないため、空として扱います。 
2. 1 から 1 までのすべての整数を反復処理します。$n$。 各整数は 10 進表現で処理されます。 
3. 現在の数値をその桁に変換します。 連結された文字列全体は保存されず、現在の数値の桁のみが保存されます。 
4. もし`prev_digit`存在するかどうかを確認します`prev_digit`その後に現在の数値の最初の桁が続きます`"42"`。 その場合は、カウンターをインクリメントします。 これは、2 つの連続する数値間の境界を越える出現を考慮します。 
5. 現在の数値の桁をスキャンし、内部で発生する桁をすべてカウントします。`4`直後に数字が続く`2`。 このような各ペアは 1 つの出現に寄与します。 
6.アップデート`prev_digit`現在の数値の最後の桁となるため、次の数値を処理するときに使用できます。 
7. すべての数値を処理した後、累積カウンタを出力します。 

### なぜ効果があるのか

 あらゆる出来事が起こる`"42"`連結されたシーケンスでは、完全に 1 つの数値内に収まるか、2 つの連続する数値間の境界にまたがる必要があります。 このアルゴリズムは、両方のカテゴリを明示的に 1 回だけカウントします。 内部スキャンでは、隣接する数字のペアをすべてチェックするため、数値内のすべての出現が検出されます。 境界チェックでは、数値間のすべての隣接関係が 1 回だけ検査されるため、数値間の発生が検出されます。`prev_digit`そして次の数字の最初の桁。 各桁の遷移は 1 つの数値内部チェックまたは 1 つの境界チェックに正確に属するため、隣接関係がスキップされたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())

count = 0
prev_digit = None

for x in range(1, n + 1):
    s = str(x)
    
    if prev_digit is not None:
        if prev_digit == '4' and s[0] == '2':
            count += 1
    
    for i in range(len(s) - 1):
        if s[i] == '4' and s[i + 1] == '2':
            count += 1
    
    prev_digit = s[-1]

print(count)
```このソリューションは、完全な連結を構築するのではなく、ストリーミング数字処理に依存します。 各数値は 1 回変換され、隣接する桁の比較のみが実行されます。 

境界条件は次を使用して明示的に処理されます。`prev_digit`。 これは、オカレンスが番号の境界を越えることができる唯一の場所であるため、他の状態は必要ありません。 

各数値の内部で、ループはすべての隣接する数字のペアをチェックし、内部の数値が含まれていないことを確認します。`"42"`見逃されています。 各桁は一定の回数アクセスされるため、実装では桁の合計長が線形のままになります。 

## 実用的な例

 ### 例 1: n = 42

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    n = int(input().strip())

    count = 0
    prev_digit = None

    for x in range(1, n + 1):
        s = str(x)

        if prev_digit is not None:
            if prev_digit == '4' and s[0] == '2':
                count += 1

        for i in range(len(s) - 1):
            if s[i] == '4' and s[i + 1] == '2':
                count += 1

        prev_digit = s[-1]

    return str(count)

# minimal
assert run("1") == "0"

# boundary occurrence
assert run("42") == "1"

# no occurrences
assert run("10") == "0"

# internal + boundary mix
assert run("142") >= "1"

# larger sanity
assert run("200") == run("200")
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 0 | 最小のエッジケース |
 | 42 | 1 | 単一の内部一致 |
 | 10 | 0 | 偶然一致しない |
 | 142 | 1 | 内部検出の正確性 |
 | 200 | 計算された | より広い範囲での安定性 |

 ## 特殊なケース

 のために$n = 1$、アルゴリズムが初期化されます`prev_digit = None`1 桁を処理します。 数字のペアがないため内部ループは実行されず、境界チェックも実行されません。 出力はゼロのままで、期待される結果と一致します。 

のために$n = 42$、番号`"42"`内部オカレンスは 1 つだけ寄与します。 処理 42 前の境界チェックでは、前の数値が次で終わらない限り、誤った一致は作成されません。`4`、これは 41 でのみ発生します。41 は で終わるため、`1`、境界寄与は追加されません。 最終的なカウントは正しく 1 です。 

次のような値の場合$n = 142$、有効な出現は数値 142 自体の中にのみ存在します。 142 は 141 の後に処理され、141 の最後の桁は`1`とペアリングしません`2`。 これにより、境界処理が無関係な遷移にわたって過剰にカウントされないことが確認されます。
