 ## 問題の理解

 単一の整数が与えられます$x$。 私たちの仕事は最大の数を見つけることです$y$を超えないもの$x$、同時に 2 つのプロパティを持ちます。 初め、$y$素数でなければなりません。 2番、$y$整数の階乗としても表現可能でなければなりません。つまり、正の整数が存在します。$z$そのような$y = z!$。 

したがって、次の形式の番号を探しています$1!, 2!, 3!, \dots$これらも素数であり、その中で最大のものを求めます。$x$。 そのような数値が存在しない場合は、次のように出力します。$-1$。 

制約$x \le 10^5$は競技プログラミング標準としては非常に小さいため、高度なデータ構造や漸近的に最適化された数論機構は必要ないことがすぐにわかります。 候補のセットが小さい場合は、一定サイズの事前計算でも十分です。 

階乗成長の理解には重要な微妙な点があります。 階乗は非常に急速に増加するため、非常に小さな値のみが増加します。$z$入力範囲内の結果が生成されます。 これにより、検索スペースが大幅に制限されます。 

潜在的な間違いの 1 つは、問題を以下の素数を検索するものと解釈することです。$x$隠れた階乗表現を持っています。 階乗値自体は非常にまばらであり、一般に素数をフィルタリングするのではなく、階乗数のみをフィルタリングするため、これは不正確です。 

これを例を挙げて根拠付けるには、次のようにします。$x = 10$、階乗は次のようになります。$1, 2, 6, 24, \dots$。 このうち素数は、$2$のみ。 したがって、答えは次のとおりです$2$。 もし$x = 1$、どの階乗も素数であり、意味のある意味で有効ではないため、答えは次のようになります。$-1$。 

## アプローチ

 直接的な総当たりアプローチでは階乗が順番に生成されます。$1! = 1$、次に計算します$2!, 3!, \dots$その値を超えるまで$x$。 各階乗値について、それが素数であるかどうかを確認します。 The largest valid one not exceeding$x$が答えになります。 

これが機能するのは、階乗の成長が十分に速く、上限に達しても少数の値しか評価できないためです。$10^5$。 実際には、$5! = 120$すでに限界を超えているので、$1!$を通して$5!$常に関連性があります。 

素朴な考え方のボトルネックは、次の値までのすべての数値の素数をテストする必要があると考えることです。$x$、それは$O(x \sqrt{x})$あるいはさらに悪いことに。 階乗値は密ではないため、これは不要です。 最大でも 5 つの候補のみをチェックします。 

重要な観察は、次の階乗を超えていることです。$5!$はサイズにより無関係であり、小さな階乗のうち、素数性は検査または直接チェックによって簡単に検証できます。 

ここで、階乗値とその素数性を明示的にリストします。$1! = 1$、プライムではない$2! = 2$、プライム$3! = 6$、プライムではない$4! = 24$、プライムではない$5! = 120$、プライムではない

 これを超えると、すべての階乗は偶数で 2 より大きいため、素数になることはできません。 これにより、問題は完全に、一定の候補セットのチェックに集約されます。 

したがって、有効な値は次のとおりです。$2$、 提供された$x \ge 2$。 そうでなければ、解決策は存在しません。

 ## アルゴリズムのチュートリアル

 1. 制約範囲内または制約範囲に近い可能性のあるすべての階乗値を特定します。 1 から値が を超えるまで階乗を計算します。$x$, しかし、いくつかのステップを踏むと、その順序が無関係になることがすぐにわかります。 このステップにより、検証せずに構造について過度に仮定することがなくなります。 
2. これらの階乗値のうちどれが素数であるかを確認します。 これは中心的なフィルタリング ステップであり、問​​題の両方の条件を同時に適用します。 
3. 素数と素数の両方である最大階乗値を追跡します。$\le x$。 階乗は増加しているため、当然、これが最後に見つかった有効な階乗になります。 
4. 値が存在する場合はその値を出力し、存在しない場合は出力します$-1$。 これは、素数を満たす階乗がない場合を処理します。 

これらのステップをより直接的に改良すると、次のことだけが認識されます。$2! = 2$フィルタリングプロセスを通過しても残ります。 

### なぜ効果があるのか

 階乗は単調増加し、素数は非常に厳しい制約を課します。2 を除くすべての階乗は、$n!$のために$n \ge 3$は 2 と別の整数で割り切れるため、合成になります。 これは、階乗のセットと素数のセットの共通部分に含まれる要素が最大 1 つであることを意味します。 その要素を特定したら、それ以上の検索は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_prime(n: int) -> bool:
    if n < 2:
        return False
    if n % 2 == 0:
        return n == 2
    d = 3
    while d * d <= n:
        if n % d == 0:
            return False
        d += 2
    return True

def solve():
    x = int(input().strip())

    fact = 1
    best = -1
    z = 1

    while fact <= x:
        if is_prime(fact):
            best = fact
        z += 1
        fact *= z

    print(best)

if __name__ == "__main__":
    solve()
```このソリューションは、実行中の積を使用して段階的に階乗を構築します。 ループ条件により、以下の値を決して考慮しないことが保証されます。$x$、これにより計算が制限されます。 実際にのみですが、各階乗の素数性がテストされます。$2$通ります。 

素数チェックは標準で書かれています$O(\sqrt{n})$形状。 このような小さな値では過剰ですが、推論を一般的に保ち、ハードコーディングの仮定を回避します。 

実装の微妙な詳細は更新の順序です。インクリメントした後に乗算します。$z$、正しく生成することを保証します$2!, 3!, 4!$、など、値をスキップせずに実行できます。

 ## 特殊なケース

 ### ケース: x = 1

 のために$x = 1$、から始めます$1! = 1$。 アルゴリズムはそれを評価し、素数ではないことを確認し、有効な候補がないことを確認した後、直ちにループを終了します。 出力はそのまま残ります$-1$、1 以下の階乗素数が存在しないという要件に一致します。 

### ケース: x ≥ 2

 どれについても$x \ge 2$、アルゴリズムが生成する$1! = 1$、 それから$2! = 2$。 で$2$、素数性が確認され、best が 2 に更新されます。その後階乗が生成されても、すぐに 2 を超えて素数ではありません。 アルゴリズムは最終的な答えとして 2 を保持します。これは、入力サイズに関係なく、唯一生き残った候補が一貫して選択されることを示しています。
