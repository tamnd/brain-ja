 ## 問題の理解

 サイズが固定された埋め込みスペースが与えられます$k$。 私たちが構築するすべての文は一連の単語であり、各単語はこの埋め込みベクトルに対する一連の決定的な「書き込み操作」のように機能します。 

長さゼロのベクトルから開始します$k$。 文の中に単語を配置すると、特定の座標が上書きされます。各単語には複数のペアがあります。$(p, v)$、その単語が使用されるとき、調整することを意味します。$p$値に設定されています$v$、以前に存在していたものを置き換えます。 単語は厳密に左から右に処理されるため、後の単語で前の単語が上書きされる可能性があります。 

タスクは、与えられた単語の一部を、各単語を最大 1 回使用して、最終的な埋め込みが正確にターゲット ベクトルになるシーケンスに配置できるかどうかを決定することです。$t$。 単語の任意のサブセットと順序を使用できます。 

重要な構造上の詳細は、操作が加算的ではないということです。 それらは課題です。 これにより、各座標の最後のライターを選択するという根本的な問題が生じます。 

制約$k, w \le 100$を含むあらゆるアプローチを示します。$O(w^2)$または$O(wk)$は簡単に問題ありませんが、すべての順列の指数関数的順序付けは問題ありません。 すべての語順を試す素朴な試みには、$w!$、これはたとえ$w = 15$、ましてや100。 

微妙なエッジ ケースは、上書きインタラクションから発生します。 座標を定める言葉$p$正しくは、後で同様に触れる別の単語によって上書きされる可能性があります$p$。 逆に、局所的に間違っているように見える単語が、矛盾する割り当ての後に配置されると、正しくなる可能性があります。 

もう 1 つの重要なエッジ ケースは、複数の座標を一度に上書きする単語です。 1 つの単語が一部の座標を満たす一方で他の座標を破壊する場合があります。つまり、座標ごとに貪欲にではなく全体的に推論する必要があることを意味します。 

## アプローチ

 強引な解釈では、単語のすべてのサブセットのすべての順序を試します。 各候補配列について、埋め込み構築をシミュレーションし、ターゲットと一致するかどうかを確認します。 これはプロセスのルールに直接従うため、正しいです。 問題は規模です。$w!$すべての単語の順列、およびサブセットに制限しても依然として残ります$2^w \cdot w!$、それは限界をはるかに超えています。 

構造的なブレークスルーは、問題を単語の順序として考えるのをやめ、代わりに各座標に責任を割り当てると考えることです。 各ポジションの最終値なので$p$まさにそうでなければなりません$t_p$、影響を与える最後の言葉$p$正しく設定する必要があります。 これは、どの単語が各座標の最終的な書き手であるかのみを考慮していることを示唆しています。 

すべての座標について、どの単語がその最終値の原因となるかを固定すると、順序付けの制約はローカルになります。$A$コーディネートを担当します$p$、そして単語$B$コーディネートを担当します$q$、単語が複数の座標を記述する場合、一貫性を確保する必要があります。 これにより、すべての座標を一貫して「説明」できる一連の単語を選択するという問題に変わります。 

一貫性を強制する自然な方法は、各単語を候補「プロファイル」として考慮することです。単語は部分的な割り当てに寄与し、そのすべての寄与は、責任を負うために選択されたターゲットと一致する必要があります。 次に、問題は、すべての座標が、それを正しく書く少なくとも 1 つの単語によってカバーされ、矛盾が生じないように、単語のサブセットを選択することになります。 

重要な観察は、各単語が固定の座標セットを書き込むため、単語が使用される場合、その単語が書き込むすべての座標でターゲットと互換性がなければならないということです。 そうしないと、それらの座標の最後の書き込み者になることはできず、非最終的なフィラーとしてのみ機能しますが、上書きは常に可能であり不要であるため、これは無意味です。 

したがって、使用可能なすべての単語は「ローカルで一貫性がある」必要があります。$(p, v)$それは次のいずれかを定義します$v = t_p$、またはその座標の最終的な貢献者として使用することはできません。 しかし、局所的に一貫性があるとしても、やはりカバレッジが必要です。すべての座標には、それを正しく記述する単語が少なくとも 1 つ必要です。 

これにより、問題は、すべての座標に対して次のような単語を選択できるかどうかを確認することに帰着します。$p$、と書く単語が少なくとも 1 つ存在します。$p$として$t_p$。 このようなカバレッジが存在する場合、競合は発生しないため、選択した単語を任意の順序で配置することで有効な順序を構築できます。つまり、選択した割り当てはすべてターゲットと一致します。

 ## アルゴリズムのチュートリアル

 単語と座標の間に二部形式のカバレッジ構造を構築します。 

1. 各単語について、そのすべてをスキャンします。$(p, v)$ペア。 単語がそれらの座標のターゲットと互換性があるかどうかをマークします。 ワードがコーディネートに対応$p$どちらかが書かれていない場合$p$、または正確に書きます$t_p$。 

これにより、接触した座標を永久に破壊するような単語を考慮することがなくなります。 
2. 書かれた座標上でターゲットと直接矛盾する単語はすべて破棄します。 

単語が破棄されると、その単語が変更する座標の最後の書き込み者になることはできないため、有効な構文に出現することはできなくなります。 
3. 残りの各単語について、どの座標を正しく設定できるかを記録します。つまり、すべての単語が正しく設定されます。$p$その値が次と等しくなるように$t_p$。 
4. すべての座標が次のとおりであるかどうかを確認します。$p$正しく設定できる単語が少なくとも 1 つ残っています。 

これが実現可能性の中核条件です。つまり、$p$何らかの単語から来ている必要があるため、少なくとも 1 つの候補ソースが必要です。 
5. 座標の候補がゼロの場合は、直ちに不可能であると結論付けます。 
6. それ以外の場合は、残りの単語をすべて選択して出力を構築します。 彼らが実行するすべての割り当ては目標と一致しているため、その順序は無関係です。 

選択されたすべての単語は正しい値のみを書き込むため、構築ステップは安全です。そのため、どの順序でも正確さが保たれます。 

### なぜ効果があるのか

 埋め込みプロセスは一連の上書きですが、各座標の最終値は、それに接触する最後の単語にのみ依存します。 使用されるすべての単語がターゲットと一致する値のみを割り当てる場合、どの座標もそのターゲット値から強制的に離れることはできません。 逆に、ある座標にそれを正しく割り当てることができるワードがない場合、その座標に対する最後の書き込み者は存在せず、ターゲットに到達できなくなります。 これにより、座標ごとに必要かつ十分なカバレッジ条件が作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k, w = map(int, input().split())
    t = list(map(int, input().split()))

    words = []
    valid = [True] * w

    for i in range(w):
        parts = input().split()
        name = parts[0]
        mi = int(parts[1])
        writes = []
        ok = True

        idx = 2
        for _ in range(mi):
            p = int(parts[idx]) - 1
            v = int(parts[idx + 1])
            idx += 2

            writes.append((p, v))
            if v != t[p]:
                ok = False

        valid[i] = ok
        words.append((name, writes))

    if not any(valid):
        print("IMPOSSIBLE")
        return

    covered = [False] * k

    for i in range(w):
        if not valid[i]:
            continue
        for p, v in words[i][1]:
            covered[p] = True

    for i in range(k):
        if not covered[i]:
            print("IMPOSSIBLE")
            return

    res = []
    for i in range(w):
        if valid[i]:
            res.append(words[i][0])

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```この実装では、まず、明示的に書き込まれた座標上でターゲットと直接矛盾する単語がフィルタリングされます。 これは、単語レベルで強制する必要がある唯一のグローバル制約です。矛盾があると、その単語がその座標の最終的なライターになることが不可能になるためです。 

フィルタリング後、座標上のカバレッジを計算します。 少なくとも 1 つの生き残った単語が正しい値を書き込んでいる場合、その座標は達成可能であるとみなされます。 これにより、すべてのポジションに潜在的な最終割り当てソースが確保されます。 

最後に、残っているすべての単語を任意の順序で出力します。 競合する割り当てを引き起こす生き残った単語がないため、順序は重要ではありません。 

ここでよくある間違いは、実際の最小シーケンスを再構築しようとしたり、貪欲な配置を実行しようとしたりすることです。 実現可能性は互換性のあるライターの存在のみに依存し、ライター間の順序付けの制約には依存しないため、これは不要です。

 ## 特殊なケース

 単語が複数の座標を書き、ターゲットに一致するものと一致しないものがある場合、厄介な状況が発生します。 たとえば、単語が設定されている場合、$p_1$正しくはありますが、$p_2$間違った場合、矛盾を強制するため、まったく使用できません。$p_2$最後に配置すると、中間状態も破損します。 

もう 1 つの特殊なケースは、座標が他の場所でも競合する単語によってのみ記述されている場合です。 各座標に個別に候補がある場合でも、他の座標のせいですべての候補が全体的に無効である場合は、単語を完全に削除する必要があります。 フィルタリング ステップでは、座標ごとの許容性ではなく、不一致に基づいて単語を拒否することでこれを処理します。 

最後に、順序制約に依存しないため、複数の単語が重なり合う場合でも安全です。 残りのすべての単語は、書かれたすべての座標でターゲットと一致するため、プロセスが一般に数学的に可換ではない場合でも、それらの相互作用は正確さに関して可換です。
