 ## 問題の理解

 大きな整数が与えられます$p$。 各テスト ケースでは、すべての因数分解を調べることが求められます。$p = a \cdot b$、ここで両方とも$a$そして$b$は正の整数です。 このようなペアごとに、次から特別なシーケンスが構築されます。$(a,b)$両方の数値を一緒にシフトすることによって: ステップで$n$、値は分数のような式です$\frac{a+n}{b+n}$。 この問題は、これらの値が整数であるかどうかのみを考慮します。 

このシーケンス内の用語は、次の場合に「良好」とみなされます。$(a+n)$で割り切れます$(b+n)$。 の「誠実さ」$(a,b)$から始まる最大プレフィックス長です。$n=0$そのプレフィックス内のすべての項が整数になるようにします。 因数分解の数を数えるように求められます$p = a \cdot b$少なくとも 3 の整合性を生成し、それらの因数分解に対して対応する出力を出力します。$b$ソートされた順序での値。 

重要な制約は、$p \le 10^{18}$したがって、すべてのペアを列挙します$(a,b)$約で除数を列挙することによってのみ実現可能です$O(\sqrt{p})$テストケースごとに。 以来$t \le 20$、 平$O(\sqrt{p})$許容されますが、すべてのペアをチェックするようなものは、$p$または、すべての約数についてシーケンスを深くシミュレートすると失敗します。 

微妙な点は、この条件に 3 つの連続したシフトが含まれていることです。$n=0,1,2$。 単純な間違いは、チェックだけを想定することです。$n=0$またはのみ$n=0,1$で十分です。 そうではありません。なぜなら、割り算の制約がシフトされたペアを通じて自明ではない方法で伝播するからです。 

不注意な推論を打ち破るエッジケース:

 もし$p=16$、 考慮する$(a,b)=(8,2)$。 それから$n=0$:$8/2=4$、整数。$n=1$:$9/3=3$、整数。$n=2$:$10/4=2.5$、整数ではないため、整合性は 3 ではなく、正確に 2 になります。最初の 2 つのステップのみをチェックするソリューションでは、このペアが誤ってカウントされます。 

もし$p$が素数の場合、因数ペアは のみです$(p,1)$そして$(1,p)$、そして通常、どちらも 2 番目の条件さえも存続しないため、出力はゼロでなければなりません。 これを怠ると、無効な候補に対して不必要な計算が行われることになります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアに対して反復処理が行われます。$(a,b)$そのような$ab=p$。 各ペアについて、シーケンスを段階的にシミュレートします。$(a+n)\bmod(b+n)=0$のために$n=0,1,2$。 各チェックは一定時間であるため、ペアごとのコストは一定です。 

問題は因子のペアの数です。 最悪の場合、次のような高度に合成された数が発生します。$10^{18}$のオーダーで持つことができます$10^5$約数、約の意味$10^5$ペア。 これは境界線ですが、それでも問題ありません。 ただし、ネストされたループを介してすべてのペアを生成することは不可能です。 約数を列挙する必要があります$O(\sqrt{p})$。 

重要な観察は、一度修正すると、$b$、の値$a$は次のように決定されます$a = p/b$。 したがって、問題全体は、除数の反復に帰着します。$b$の$p$、一定数の算術条件をチェックします。 

各約数について$b$、テストします:$$\frac{p/b + n}{b+n} \in \mathbb{Z} \quad \text{for } n=0,1,2$$これは単なるモジュラー算術チェックであり、シミュレーションは必要ありません。

 | 除数の列挙 + 定数のチェック |$O(\sqrt{p})$テストケースごと |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. すべての約数を列挙します$b$の$p$繰り返します$i$1から$\sqrt{p}$。 もし$i$分割する$p$そうすると、候補が 2 つ得られます$b=i$そして$b=p/i$。 このステップにより、すべての有効な因子ペアを 1 回だけ考慮することが保証されます。 

### 2. 各約数について$b$、計算する$a = p / b$以来$ab=p$、これによりペアが一意に修正されます。 もう自由はない、すべての条件はこれだけに依存する$b$。 

### 3. 最初の条件を確認します$n=0$私たちは次のことを要求します:$$\frac{a}{b} \in \mathbb{Z} \quad \Leftrightarrow \quad a \bmod b = 0$$これは以下と同等です$b^2 \mid p$。 これが失敗した場合、整合性はすでにゼロであるため、ペアは直ちに破棄されます。 

### 4. 2 番目の条件を確認します。$n=1$私たちは次のことを要求します:$$(a+1) \bmod (b+1) = 0$$これは、以前に計算された値を使用した直接算術チェックです。$a$。 

### 5. 3 番目の条件を確認します$n=2$私たちは次のことを要求します:$$(a+2) \bmod (b+2) = 0$$3 つの条件がすべて当てはまれば、$b$有効な答えとして。 

### 6. 並べ替えてすべて有効なものを出力します$b$約数は順序が保証されていないペアで生成されるため、印刷する前に最終的なリストを並べ替えます。 

### なぜ効果があるのか

 整合性条件は、長さ 3 の固定有限プレフィックスにのみ依存します。各条件は、次の要素のみを含む独立した割り算制約です。$a$そして$b$。 一度$a$因数分解で決まる$p=b\cdot a$、異なる約数間で隠れた依存関係は存在しません。 したがって、各候補を個別にチェックするだけで十分であり、すべての約数を列挙することで重複のない完全性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def valid(a, b):
    # check n = 0
    if a % b != 0:
        return False
    # n = 1
    if (a + 1) % (b + 1) != 0:
        return False
    # n = 2
    if (a + 2) % (b + 2) != 0:
        return False
    return True

def solve():
    t = int(input())
    for _ in range(t):
        p = int(input())
        res = []
        
        i = 1
        while i * i <= p:
            if p % i == 0:
                b1 = i
                a1 = p // i
                if valid(a1, b1):
                    res.append(b1)

                if i != p // i:
                    b2 = p // i
                    a2 = i
                    if valid(a2, b2):
                        res.append(b2)
            i += 1
        
        res.sort()
        print(len(res))
        if res:
            print(*res)

if __name__ == "__main__":
    solve()
```コードはアルゴリズム構造に直接続きます。 ヘルパー関数は整合性チェックを分離して、各約数候補がクリーンかつ定時間の方法で評価されるようにします。 除数ループは、次の場合に二重カウントを注意深く回避します。$i = p/i$、それは次のときに起こります。$p$は完全な正方形です。 

よくある実装上の落とし穴は、除数のペアの両方の方向を次のように考慮する必要があることを忘れていることです。$(a,b)$、だけではありません$(b,a)$。 別の人は、次のように誤って仮定しています。$b$の約数である必要があります$a$; 正しい条件は、シフトされた可分性チェックに厳密に基づいています。

 ## 特殊なケース

 プライムの場合$p$、除数セットは非常に小さいです。 例えば$p=13$だけを生成します$(1,13)$そして$(13,1)$。 どちらも失敗します$n=1$すぐに確認してください。$(a+1)$と調整できません$(b+1)$このような非対称のペアでは。 

完全二乗の場合、約数のペアが 1 つの候補に折りたたまれる可能性があり、等しい場合は簡単に二重カウントされます。$i = p/i$丁寧に扱われていない。 のために$p=36$、除数$6$は 1 回だけ表示されるため、複製すると結果が大きくカウントされます。 

非常に大きい場合$p$に近い$10^{18}$、算術安全性が重要です。 すべての操作は 64 ビット整数の範囲内に収まる必要がありますが、Python はこれを自然に処理します。 固定幅の整数を使用する言語では、処理中にオーバーフローが発生します。$a+2$または$b+2$微妙なバグの原因です。
