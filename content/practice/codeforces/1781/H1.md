 ## 解決策
 ## 問題の理解

 私たちに与えられた建物は、$h$床と$w$各階に格子状の窓があり、$h \times w$。 永久にオフになっている最大 2 つの壊れたウィンドウを除いて、すべてのウィンドウはオンまたはオフにすることができます。 信号として船に送信できる個別の光のパターンが何個あるかを数える必要があります。 一方を水平または垂直に移動してもう一方になる場合、2 つのパターンは同一とみなされます。 ライトがまったく点灯しない構成は無効です。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、建物の寸法、割れた窓の数、割れた窓がある場合はその位置が示されます。 出力は個別の信号の数を法で表したものです。$998{,}244{,}353$。 

制約は小さいです。$h, w \le 40$、壊れた窓は最大でも2枚です。 すべてのテスト ケースのセルの総数は最大 1600 です。これは、冗長な作業を慎重に回避する限り、セル数が指数関数的に複雑になるあらゆるソリューションがこれらの範囲内で実行可能であることを示しています。 

エッジ ケースには、すべてのウィンドウが機能している、壊れているウィンドウが 1 つまたは 2 つだけある、単一行または単一列がある、グリッド全体が小さすぎてシフトに対応できないなどがあります。 すべてを列挙する素朴なアプローチ$2^{h\cdot w}$サブセットは一般に実現可能ではありませんが、ここではサイズが小さいため、いくつかの組み合わせ手法が可能になります。 壊れたウィンドウは非対称性をもたらします。そうでなければ変換下では同等であるはずの構成がブロックされる可能性があります。 

## アプローチ

 ブルートフォース手法では、ウィンドウのすべてのサブセットを生成し、壊れたウィンドウを含むサブセットを削除してから、各サブセットをできるだけ上と左にシフトして正規化します。 正規化されたセットをハッシュ セットに保存することで、一意のパターンをカウントできます。 のために$h\cdot w \approx 1600$、これには反復処理が必要になります$2^{1600}$構成は天文学的に大規模です。 ブルートフォースは変換によって等価性を定義できるため機能しますが、構成の数が指数関数的に増加するため失敗します。 

重要な洞察は、少数の壊れたウィンドウと翻訳の不変性を利用することです。 壊れた窓がなければ、異なるパターンの数は$(h+1)(w+1)-1$: 空でない限り、グリッド内の任意の原点から開始し、任意の位置にシフトされたライトの長方形のブロックを選択できます。 壊れたウィンドウが 1 つある場合、ブロックに壊れたウィンドウが含まれている場合にのみパターンをブロックできます。 2 つの壊れたウィンドウの場合、それらの相対的な位置によってどのブロックが禁止されるかが決まります。 ライトの長方形の左上のオフセットをすべて列挙し、壊れたウィンドウを含むものを減算し、包含排除を使用して個別の信号の数を効率的に計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^{h\cdot w})$|$O(2^{h\cdot w})$| 遅すぎる |
 | 包含-除外 / 組み合わせ |$O(h^2 w^2)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$h$、$w$、$k$、壊れたウィンドウの座標 (存在する場合)。 わかりやすくするために、座標を 0 から始まるインデックスに調整します。 
2. 個別の信号の数のカウンターをゼロとして初期化します。 
3. 高さによって定義されるライトの可能なすべての長方形を反復処理します。$rh$と幅$rw$、 と$1 \le rh \le h$そして$1 \le rw \le w$。 各長方形は、連続したブロック内のライトのパターンを表します。 
4. 各長方形について、その左上隅を配置できるすべての位置を繰り返します。 がある$(h-rh+1) \times (w-rw+1)$そういったポジション。 これは、平行移動の不変性を説明します。同じ四角形のシフトは同じパターンとしてカウントされます。 
5. 各長方形の位置について、壊れた窓をカバーしているかどうかを確認します。 その場合は破棄してください。 そうでない場合は、カウントを増やします。 これにより、禁止された位置がカウントから除外されます。 
6. すべての四角形のサイズと位置を反復した後、カウントはこのテスト ケースのすべての有効なパターンを表します。 モジュロを適用する$998244353$。 
7. カウントを出力します。 

機能する理由: 考えられるすべての四角形サイズを反復処理し、その配置オフセットを考慮することで、変換までの各固有の構成を 1 回だけ生成します。 壊れたウィンドウは、二重にカウントすることなく無効なパターンを排除します。 壊れたウィンドウの制約が四角形の配置ごとにチェックされるため、包含/除外の原則が暗黙的に処理され、重複する禁止された構成が複数回カウントされるのを防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        h, w, k = map(int, input().split())
        broken = set()
        for _ in range(k):
            r, c = map(int, input().split())
            broken.add((r-1, c-1))
        total = 0
        for rh in range(1, h+1):
            for rw in range(1, w+1):
                count = 0
                for r0 in range(h - rh + 1):
                    for c0 in range(w - rw + 1):
                        ok = True
                        for (br, bc) in broken:
                            if r0 <= br < r0+rh and c0 <= bc < c0+rw:
                                ok = False
                                break
                        if ok:
                            count += 1
                total = (total + count) % MOD
        print(total)
        
if __name__ == "__main__":
    solve()
```コードは、テスト ケースの数を読み取り、壊れたウィンドウのセットを初期化することから始まります。 四角形のサイズごとに、壊れたウィンドウが四角形の内側にあるかどうかを確認して、有効な配置をカウントします。 高さと幅にわたってネストされたループを使用すると、すべての固有の変換されたパターンが効率的に列挙されます。 オーバーフローを防ぐために最後にモジュロが適用されます。 0 から始まるインデックスにより比較が簡素化されます。

 ## 特殊なケース

 ライトが壊れた 1 つのウィンドウ グリッドの場合、壊れたセルを回避できる四角形がないため、アルゴリズムは正しく 0 を返します。 2 つの壊れたウィンドウの場合、アルゴリズムは四角形の配置ごとに両方の壊れたセルをチェックし、どちらかを覆う四角形を除外します。 両方を回避する長方形は正確に 1 回カウントされ、平行移動不変のカウントが正確であることがわかります。 モジュロにより大きな金額が保証されます
