 ## 解決策
 ## 問題の理解

 人にはそれぞれ閾値がある$a_i$。 彼らの決定は、最終的に映画館に足を運ぶ人の数によって完全に決まります。 

正確に仮定してください$k$人々は行きます。 

閾値のある人$a_i$自分の行動が自分のルールに一致する場合にのみ満足します。 

彼らが行くなら、少なくともあるはずだ$a_i$他の出席者も必要なので、$k-1 \ge a_i$。 

彼らが家にいるなら、人はもっと少なくなるはずだ$a_i$他の出席者も必要なので、$k < a_i$。 

私たちは、すべての人を同時に幸せにするさまざまな出席セットが何セットあるかを数えなければなりません。 

この制約は、すべてのサブセットを検査できないことを直ちに示唆しています。 たとえ$n=40$、すでに 1 兆を超えるサブセットがあり、ここに$n$到達できる$2 \cdot 10^5$テストケース全体で。 指数関数的な解決は不可能です。 すべてのテストケースの合計サイズはわずかであるため、$2 \cdot 10^5$、$O(n \log n)$テストケースごとのソリューションは完全に安全ですが、$O(n^2)$最悪の場合は遅すぎるでしょう。 

主な難点は、幸福度は個々の選択に左右されるのではなく、参加者の総数に左右されるということです。 単純な実装では、このグローバルな依存関係を簡単に見逃してしまう可能性があります。 

次の入力を考えてみましょう。```
2
1 1
```ちょうど 1 人が参加した場合、出席者は次のことを確認します。$0$他の出席者、これより少ない$1$、だから彼らは不幸です。 不参加者も見る$1$出席者、少なくとも$1$、だから彼らも不幸です。 正解は 2 で、「みんなが行く」と「誰も行かない」に相当します。 

別の微妙なケースは次のとおりです。```
3
0 0 0
```Anyone with threshold 0 must attend whenever the attendance count is at least 0, which is always true. The only valid choice is that all three people go. A careless solution might think every subset works because the thresholds are small.

 3 番目のエッジケースは次のとおりです。```
3
2 2 2
```他に2名以上の参加者がいない限り参加できません。 有効な構成は、「全員が参加する」と「誰も参加しない」のみで、答え 2 が得られます。これは、両方の極端な設定が同時に有効である可能性があることを示しています。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての人々のサブセットを列挙し、出席者数を計算し、その出席者数の下ですべての人が満足しているかどうかを確認します。 これは、定義を直接テストするため、正しいです。 

問題はサブセットの数です。 がある$2^n$可能性。 のために$n=200000$、これは想像を絶するほど大きいため、まったく異なる視点が必要です。 

重要な観察は、有効な出席セットはそのサイズによって完全に決定されるということです。 

正確に仮定してください$k$人が参加します。 

参加者は次の条件を満たす必要があります。$$a_i \le k-1$$家にいる人は誰でも次のことを満たさなければなりません。$$a_i > k-1$$これら 2 つの条件により、人々は 2 つのグループに分けられます。 持っているすべての人$a_i \le k-1$必ず参加しなければなりません。$a_i > k-1$家にいなければなりません。 

つまり、出席者数の設定はもはや恣意的ではなくなります。 一度$k$が固定されている場合、集合は一意に決定されます。 

しきい値を並べ替えてみましょう。 

まさに$k$人々が出席し、分類した後、最初の$k$値は最大でも$k-1$、残りの値はすべて より大きくなければなりません$k-1$。 

ソート順に並べると、次のようになります。$$a_k \le k-1$$そして$$a_{k+1} > k-1$$1 から始まるインデックスを使用します。 

のすべての値$k$これらの不等式を満たすと、正確に 1 つの有効な出席セットが得られます。 

並べ替えたら、すべてをテストするだけです$k$から$0$に$n$。

 | ブルートフォース |$O(n2^n)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. しきい値の配列を降順でない順序で並べ替えます。 
2. あらゆる出席者数を考慮する$k$から$0$に$n$。 
3. のために$k=0$、誰も参加しません。 これは、すべてのしきい値が厳密に正の場合にのみ有効です。 ソート順に並べると、つまり、$a_1 > 0$。 
4. のために$k=n$、全員が出席します。 これは、すべてのしきい値が最大でも次の場合にのみ有効です。$n-1$、入力制約があるため、これは常に true です。 したがって$k=n$は常に有効です。 
5. のために$1 \le k \le n-1$、次のことを確認します。$$a_k \le k-1$$そして$$a_{k+1} > k-1.$$6. 両方の条件が当てはまる場合、答えを 1 増やします。 
7. 合計カウントを出力します。 

### なぜ効果があるのか

 値を修正する$k$。 

最大でも閾値を持つ人なら誰でも$k-1$家にいると不幸になるから出席しなければならない。 閾値を超える人$k-1$出席すると不幸になるので、家にいなければなりません。 

正確に指定された有効な構成$k$出席者は、正確に存在する場合にのみ存在します。$k$閾値が最大以下の人$k-1$。 並べ替えた後、これは最初に言うのと同じです$k$値は最大でも$k-1$残りの値は$k-1$。 

このような不平等が存在する場合、出席者セットは一意に決定され、全​​員が満足します。 失敗するたびに、少なくとも 1 人が条件に違反する必要があります。 したがって、有効な出席セットはすべて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()

        cur = 0

        if a[0] > 0:
            cur += 1

        for k in range(1, n):
            if a[k - 1] <= k - 1 and a[k] > k - 1:
                cur += 1

        cur += 1  # k = n is always valid

        ans.append(str(cur))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```ソートされた配列は中心的なデータ構造です。 しきい値を並べ替えたら、正確かどうかを確認します。$k$参加すべき人はポジション間の境界テストとなる$k$そして$k+1$。 

ケース$k=0$境界の前に要素がないため、別の処理が必要です。 すべてのしきい値が正の場合にのみ誰も出席しません。これは、並べ替えられた順序で最小値が正であることを意味します。 

ループはすべての内部値を処理します$1 \le k \le n-1$。 ゼロベースのインデックスを使用すると、$a[k-1]$最初のしきい値の中で最大のしきい値です$k$人々と$a[k]$残りの人々の中で最も小さい閾値です。 

ケース$k=n$は常に有効です。 すべてのしきい値が満たされる$a_i \le n-1$入力の定義により、要件に違反することなく誰もが参加できます。 

よくある間違いは、次のものと比較することです。$k$の代わりに$k-1$。 条件は、_other_ 出席者の数を指します。$k$人々が参加すると、各参加者が正確に見ることができます$k-1$その他。
