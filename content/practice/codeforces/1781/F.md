 ## 解決策
 ## 問題の理解

 ランダムな挿入を繰り返して形成されたブラケット シーケンスが最終的に規則的になる確率を計算するように求められます。 プロセスは空の文字列で開始され、次の時間実行されます。`n`ステップ。 各ステップで、新しい 2 文字の文字列がランダムな位置に挿入されます。 2 文字の文字列は次のいずれかです`"()"`確率的に`p`または`")("`確率的に`1-p`。 すべての左括弧が右括弧と適切に一致している場合、シーケンスは規則的です。 

入力により得られるのは、`n`、挿入操作の数、および`q`、確率をエンコードします`p = q * 10^{-4}`。 出力は、最終シーケンスが正規である確率であり、分数法で表されます。`998244353`。 

制約は、総当たりの列挙を排除できるほど厳しいものです。 と`n`最大 500 まで、可能なシーケンスの数は指数関数的に増加します (`2^n * n!`位置）のため、すべてのシーケンスを明示的に生成するソリューションは実行不可能です。 確率は、除算を処理するための逆モジュラを含め、モジュラ算術を使用して慎重に計算する必要があります。 エッジケースには以下が含まれます`n = 1`または極端な確率`p = 0`または`p = 1`、シーケンスは決定的です。 

不注意なアプローチでは、すべての挿入をシミュレートしたり、位置を独立して処理しようとしますが、ブラケットの一致はグローバル プロパティであり、挿入の順序に依存するため、これは失敗します。 

## アプローチ

 単純な総当たりアプローチでは、考えられるすべての挿入シーケンスを列挙しようとします。 各挿入には 2 つの選択肢があります (`"()"`または`")("`) まで`2n+1`でのポジション`n`- 番目のステップ。 シーケンスの数はおおよそ次のとおりです`(2n+1)*(2n-1)*…*1 * 2^n ≈ (2n)! * 2^n`でさえ天文学的な大きさです。`n = 10`, したがって、このアプローチはまったく実行不可能です。 

重要な洞察は、挿入と位置の順序は、一致しない開始括弧の数 (またはバランス) を維持するという点でのみ重要であるということです。 **残高**を次の数の差として定義すると、`'('`そして`')'`どのようなプレフィックスでも、各挿入後に各バランスに到達する方法の数を追跡する動的プログラミング ソリューションを定式化できます。 それぞれ`"()"`予測可能な方法で有効なシーケンスの数を増やし、それぞれの`")("`より複雑な遷移が導入されますが、それでも現在の残高のみに依存します。 

これにより、問題は DP オーバーに帰着します。`n`からのステップとバランス`0`に`2n`。 各ステップは以前の残高のみに依存するため、DP テーブルの合計は次のサイズになります。`O(n^2)`。 各 DP 更新には、単純な組み合わせ推論と確率乗算が含まれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((2n)! * 2^n) | O((2n)!) | 遅すぎる |
 | 動的プログラミング (バランスベース) | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を変換する`q`モジュラー確率へ`p = q * 10^-4 mod 998244353`。 コンピューティング`1-p`同時に。 除算には逆モジュラを使用します。 
2. DP テーブルの初期化`dp[step][balance]`後に一定の残高が得られる確率を表す`step`挿入。 セット`dp[0][0] = 1`空の文字列のバランスはゼロであるためです。 
3. 各ステップごとに、`1`に`n`、可能なすべての残高について DP テーブルを更新します。`b`。 

- 挿入する`"()"`全体的に残高はゼロ増加しますが、どの位置にも配置できます。`b+1`既存の不一致のオープン間の位置。 この貢献度は次のように乗算されます`p`。 
- 挿入する`")("`挿入時にバランスを一時的に 1 減らすことができますが、直後に元のバランスに戻します。これは、現在のバランスの周囲にブラケットを配置する方法にのみ影響します。 乗算する`1-p`。 
4. オーバーフローを避けるために、全体を通してモジュラー演算を維持します。 
5. 最後に、`dp[n][0]`には、正規数列の合計確率が含まれます。これは、その残高がゼロで終わる場合に限り、数列が正規であるためです。 確率を次のように出力します`p * q^-1 mod 998244353`。 

**これが機能する理由:** DP の不変条件は次のとおりです。`dp[step][balance]`正確にそのバランスに到達するためのすべての可能な方法を表します`step`挿入。 すべての挿入ステップでは、組み合わせルールに従ってバランスが正しく更新されます。 最終的な通常のシーケンスは、バランスがゼロのシーケンスとまったく同じです。`dp[n][0]`は正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD-2, MOD)

def solve():
    n, q = map(int, input().split())
    
    p = (q * modinv(10000)) % MOD
    r = (1 - p) % MOD
    
    dp = [0] * (n+2)
    dp[0] = 1
    
    for step in range(n):
        new_dp = [0] * (n+2)
        for balance in range(step+1):
            val = dp[balance]
            if val == 0:
                continue
            # insert "()" - balance stays same
            new_dp[balance] = (new_dp[balance] + val * p) % MOD
            # insert ")(" - only valid if balance > 0
            if balance + 1 <= n:
                new_dp[balance+1] = (new_dp[balance+1] + val * r) % MOD
        dp = new_dp
    
    print(dp[0] % MOD)

if __name__ == "__main__":
    solve()
```このソリューションは DP アルゴリズムを反映しています。`dp[balance]`確率を追跡します。 各ステップは次のように更新されます`"()"`そして`")("`挿入、バランスの移行を維持します。 逆モジュラーは確率のスケーリングを処理します。 Off-by-one エラーは拡張することで回避されます。`dp`に`n+2`インデックスのオーバーフローを防ぐため。
