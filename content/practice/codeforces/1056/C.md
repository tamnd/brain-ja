 ## 解決策
 ## 問題の理解

 2 人のプレイヤーが、共通のプールからヒーローを交互に選択して、同じサイズの 2 つのチームを構築します。$2n$候補者たち。 各ヒーローには固定の強さがあり、一度奪われるとゲームから消えます。 これに加えて、一部のヒーローは特別なペアで提供されます。そのようなペアの一方のヒーローが選択されると、ペアのもう一方のエンドポイントは、次の動きで反対側のプレイヤーによって即座に強制的に選択されます。 これは、ペアの一方のメンバーを選択すると、単一のアイテムが削除されるだけでなく、将来の決定から両方のエンドポイントが効果的に削除され、同時に移動順序に応じてそれらの 1 つが各プレイヤーに割り当てられることを意味します。 

あなたの側の目標は、最終的に得られるヒーローの強さの合計を最大化することであり、一方、対戦相手も同じルールに従い、可能な限り多くを得ようとします。 インタラクションの側面は重要です。対戦相手の選択に反応し、強制的なペアの制約を尊重しながら、自分の手を 1 つずつ出力する必要があります。 

制約が非常に厳しいため、すべての動きシーケンスを検索したり、ゲーム ツリーをシミュレートしたりするアプローチは不可能です。 まで$2n \le 2000$、たとえ$O(n^2)$シミュレーションは境界線にありますが、移動ごとに非常に単純な場合にのみ実行可能です。 ただし、強制ペアの構造により、動的に縮小するセットに対するはるかに単純な貪欲なプロセスにゲームが縮小されるため、完全なミニマックス戦略は必要ありません。 

強制的な削除を考慮せずに局所的にのみ推論しようとすると、微妙な失敗例が発生します。 たとえば、価値の低いヒーローが非常に価値の高いヒーローとペアになった場合、組み合わせを無視する単純で貪欲な戦略では、価値の低いヒーローを早く選択しすぎて、後で対戦相手が価値の高いエンドポイントを奪うことを可能にする可能性があります。 

次の構成を考えてみましょう。 

入力:```
n = 2
p = [10, 1, 9, 2]
pair: (1, 3)
```単純な戦略がインタラクションのタイミングを考慮せずに、最も見栄えの良い利用可能な手を選択した場合、対戦相手が 9 を取るのに 10 かかる可能性があり、その後の強制的な構成により最適ではない割り当てが発生する可能性があります。 正しい動作は、1 つのエンドポイントを取得するとペア全体がシステムから削除されることを理解しているかどうかに依存します。 

## アプローチ

 ゲームを考える強引な方法は、考えられるすべての動きのシーケンスをシミュレートし、誰のターンであるかを追跡し、ペアの一方のエンドポイントを選択すると、相手の次の動きでもう一方のエンドポイントを強制的に除去するという制約を維持することです。 これによりすぐに分岐プロセスが発生します。各ステップで最大$O(n)$可能な動きと深さは$2n$、指数関数的な数の状態が生成されます。 メモ化を行ったとしても、インタラクションの状態は正確に残っているセットに依存するため、これは扱いにくいものになります。 

重要な観察は、強制ペア ルールは選択の複雑さを導入せず、削除のタイミングを変更するだけであるということです。 ヒーローが選択されると、そのペア (存在する場合) は次の動きですぐに解決されます。つまり、戦略に関係なく、両方のエンドポイントが隣接するターンでゲームから離れます。 将来の意思決定の観点から見ると、すべてのアクションはプールから最大 2 つの頂点を削除するだけですが、削除の順序によって、誰がどのエンドポイントを取得するかという長期的な戦略構造が作成されるわけではありません。 

これにより、問題は動的セットにおける古典的な貪欲なプロセスに帰着します。各ターンで、現在利用可能なヒーローを 1 人選択すると、対戦相手は強制パートナーまたは任意の利用可能なヒーローを選択することで応答します。 両陣営は常に同じ残りのヒーローのプールを使用して行動するため、唯一の安定した戦略は、自分の番が来たときはいつでも、常に利用可能な最も価値の高いヒーローを選択することです。 削除は隠れた将来の利益を保持しないため、いかなる逸脱も将来の利益を補償することなく、高価値のピックをより低いピックに置き換えることしかできません。 

したがって、ゲームはターン順に最大残存値を繰り返し抽出することになります。

 ## アルゴリズムのチュートリアル

 私たちは、まだ取得されていない最高値のヒーローを常に照会できる構造を維持しています。 

1. すべてのヒーローとその値を読み取り、どのヒーローがペアになっているかを記録します。 これは妥当性を確実に尊重するためにのみ必要であり、意思決定のために必要ではありません。 
2. すべてのヒーローをパワーの降順に並べ替えた構造に挿入します。 これは、それらを消費する順序を定義します。 
3. 各ヒーローがすでに取得されているかどうかをマークするブール配列を維持します。 
4. 自分の番では、まだ利用可能な最も価値の高いヒーローを繰り返し選択します。 
5. 選択肢を出力した後、相手の応答を待ち、そのヒーローも選択済みとしてマークします。 
6. すべてのヒーローが消費されるまで交互に続け、各選択で常に最良の残りのオプションが選択されるようにします。 

唯一の微妙な点は、「利用可能」には直接選択とペアの制約による強制削除の両方を反映する必要があることです。 ただし、削除されたヒーローはすべてすぐに使用不可としてマークされるため、後の選択で誤って再利用することはありません。 

### なぜ効果があるのか

 あらゆる瞬間において、残りのヒーローのセットは将来のあらゆる可能性を完全に捉えています。 ペア制約の効果は純粋にローカルです。ヒーローを選択するとそのパートナーが削除される可能性がありますが、これによって残りのグラフに追加の構造が保存または作成されることはありません。 したがって、各ステップで唯一意味のある決定は、どの利用可能な値をすぐに採用するかということです。 可用性は再配置やロック解除によってではなく削除によってのみ進化するため、利用可能なより高い価値のヒーローをスキップしてより低いヒーローを優先する戦略は、将来の可用性を補う形で改善することなく、最終的な合計を厳密に減らします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
p = list(map(int, input().split()))

pair = [-1] * (2 * n)
for _ in range(m):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    pair[a] = b
    pair[b] = a

t = int(input())

used = [False] * (2 * n)

order = sorted(range(2 * n), key=lambda i: p[i], reverse=True)

ptr = 0

def get_best():
    global ptr
    while ptr < 2 * n and used[order[ptr]]:
        ptr += 1
    return order[ptr] if ptr < 2 * n else -1

for turn in range(2 * n):
    if (turn % 2 == 0 and t == 1) or (turn % 2 == 1 and t == 2):
        x = get_best()
        used[x] = True
        print(x + 1, flush=True)

        if pair[x] != -1:
            used[pair[x]] = True
    else:
        x = int(input())
        if x == -1:
            exit(0)
        x -= 1
        used[x] = True

        if pair[x] != -1:
            used[pair[x]] = True
```このコードは、ヒーローの強さによるグローバルな順序付けと、常に次の未使用の候補に進むポインターを維持します。 私たちの番が来るたびに、まだ利用可能な最強のヒーローを選びます。 ヒーローがどちらかの側に取られた場合、強制ルールを反映して、そのペアのパートナーもすぐに使用不可としてマークします。 

ポインターベースのスキャンにより、リスト全体の繰り返しの並べ替えやスキャンが回避され、選択の効率が維持されます。 

よくある間違いは、ペアのどのエンドポイントを最初に選択するかを積極的に推論しようとすることです。 実装ではそれを完全に回避します。グローバルな順序付けにより、常に最も強力な残りの手を試行することがすでに保証されており、強制削除を通じてペアの相互作用が暗黙的に処理されます。

 ## 特殊なケース

 重大なエッジケースは、非常に価値の高いヒーローが価値の低いヒーローとペアになり、対戦相手が先に動く場合です。 そのような状況では、対戦相手がすぐに高価値のエンドポイントを取得し、後で低価値のエンドポイントを受け取ることを強制される可能性があります。 両方のエンドポイントは対戦相手の移動直後に削除され、グリーディ ポインターは決してそれらを再利用しようとしないため、アルゴリズムはこれを自然に処理します。 この結果は、最適化の機会を逃したというよりも、避けられない損失を反映しています。 

もう 1 つのケースは、すべてのヒーローがペアになっていない場合です。 このアルゴリズムは、単純に降順の値を交互に選択するものであり、ポインタにより、各側が干渉することなく常に次に最適な利用可能な値を取得することが保証されます。 

最後に、複数のペアが存在する場合、各ヒーローは最大でも 1 つのペアに属しているため、チェーン インタラクションは発生しません。 これにより、ペアになったパートナーを使用済みとしてマークしても再帰的な依存関係がトリガーされないことが保証され、シミュレーションの動作が厳密に線形に保たれます。
