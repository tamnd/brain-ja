 ## 解決策
 ## 問題の理解

 都市は、交差点が頂点であり、道路が方向のないエッジであるグラフです。 このグラフでは各乗り物は単純なパスであり、ドライバーがその乗り物内の頂点を再訪問することはありません。 すべての乗り物で、このような単純な道がたくさん見られます。 

問題は、グラフに一貫性があるかどうかや、乗車が有効かどうかではありません。 代わりに、ルーティングの一意性が重要です。 順序付けられた頂点のペアごとに$a, b$、ドライバーがそこから去った可能性のあるすべての方法を検討してください。$a$に$b$記録された乗車の一部として。 同じ順序ペア間に 2 つの異なる単純なパスが存在する場合、ドライバーは人間であると宣言されます。 順序付けられたペアごとにパスが効果的に強制され、一意である場合、ドライバーはロボットである可能性があります。 

重要な微妙な点は、記録された乗車ではすべてのペア間で直接クエリが行われないことです。 それらは長くて単純なパスを提供するだけであり、そこからグローバルな一貫性の制約を推測する必要があります。 

制約が十分に大きいため、頂点またはライド上の二次関数は不可能です。 すべてのパスの長さの合計は次のように制限されます。$3 \cdot 10^5$したがって、いかなる解も入力サイズにおいて本質的に線形または線形に近いものでなければなりません。 これにより、パスのすべてのペアを比較したり、すべてのペアの接続構造を明示的に計算したりするアプローチは即座に除外されます。 

単純な失敗例は、複数の乗り物が部分的に重なっているが、後で分岐する場合に発生します。 

たとえば、1 つの乗り物に次の内容が含まれる場合、$1 \to 2 \to 3 \to 4$そしてもう一つには含まれています$1 \to 2 \to 5 \to 4$の場合、間には 2 つの異なる単純なパスが存在します。$2$そして$4$、人間的な答えを押し付けます。 各乗り物が単独で有効な単純なパスであるため、各乗り物が個別に有効であるかどうかのみをチェックする単純なアプローチでは、これを完全に見逃してしまいます。 

もう 1 つの微妙なケースはサイクルです。 ライドが集合的に、複数の方向または複数のコード構造でサイクルを横断できる場合、パスの一意性は失われます。 課題は、すべての乗り物の結合が、すべてのペアを明示的に列挙することなく、あるペア間の複数の単純なルートを意味する場合を検出することです。 

## アプローチ

 ブルートフォース解釈では、すべてのパスを再構築し、頂点のすべてのペアを比較しようとします。$a, b$すべての乗り物にわたって、複数の単純なパスが存在するかどうかを確認します。 各乗り物を一連のエッジとして表したとしても、サブパスの数は乗り物ごとに二次関数となり、爆発的に増加します。$O(\sum k^2)$、これは大きすぎます$3 \cdot 10^5$全長。 

より良い視点は、問題を裏返すことから生まれます。 頂点のペアについて考える代わりに、乗り物の連続するエッジによって課される局所的な構造制約に注目します。 各乗り物は「頂点」という形式の制約に影響します。$v$頂点が、単一のチェーン状構造に整列していない 3 つ以上の独立した継続に強制的に接続される場合、複数の単純なパスがシステム内のどこかに存在する必要があります。 

これは核心的な観察につながります。つまり、任意の 2 つの頂点間の単純なパスの一意性を保証する構造は、本質的には頂点が分離した単純なパスの集合であり、おそらく単一の線状の構造を形成しており、暗黙の制約グラフではすべての内部頂点の次数が最大 2 です。 単一のパスの順序と矛盾する形で頂点が分岐点のように動作することを強制されると、あいまいさが生じます。 

ライドを処理し、連続する頂点によって引き起こされる隣接制約を構築します。 次に、固有のパス構造と互換性のない分岐や循環を意味する矛盾する順序制約が頂点に強制されているかどうかを検出します。 問題は、結果として得られる制約グラフが一貫した順序を持つ一連の素なチェーンのように動作するかどうかをチェックすることに帰着します。 

重要なトリックは、各乗り物を隣接制約を誘発するものとして扱い、誘発された構造を矛盾なく一連のパスに方向付けることができるかどうかを検証することです。 これは、次数制約と近傍順序の一貫性を使用して実行できます。

 ## アルゴリズムのチュートリアル

 すべてのライドを連続する頂点間の無向隣接情報に変換します。 

1. 乗車ごとに、連続するペアを反復処理します。$(c_i, c_{i+1})$、これら 2 つの頂点が制約の意味で直接接続されていることを記録します。 これにより、観察されたパス内のすべてのローカル強制遷移がキャプチャされます。 
2. 各頂点について、接続が制約されている隣接頂点のセット (またはハッシュ構造) を維持します。 私たちは元のグラフを構築しているのではなく、すべての強制された遷移の結合を構築しています。 
3. 各頂点について、この制約構造内に異なる隣接頂点がいくつあるかを確認します。 頂点に 2 つ以上の異なる隣接点がある場合、ドライバーは人間であるとすぐに結論付けられます。 その理由は、頂点のすべてのペアが一意の単純なパスを持つ構造では、誘導された構造はパスの集合のように動作する必要があり、パスの頂点の次数は最大 2 であるためです。 
4. さらに、乗車によって引き起こされる注文の一貫性を確保する必要があります。 頂点が複数のライドに表示される場合、その隣接関係が分岐の曖昧さを暗示しないことを確認することで、トラバーサル制約をシミュレートします。 実際には、すべての乗り物が処理されると、制約グラフは最大次数 2 の擬似森林になる必要があります。 
5. 次数制約に違反する頂点がない場合、その構造は決定論的なパスのような構成と一致していると判断し、ロボットを出力します。 

重要な考え方は、すべてのライドでローカルな連続性が強制され、「頂点ごとに最大 2 方向」に違反すると、頂点のペア間を横断する可能性のある複数の方法が作成されるということです。 

### なぜ効果があるのか

 誘導された制約構造内ですべての頂点に最大 2 つの近傍がある場合、各連結コンポーネントは単純なパスまたはサイクルのいずれかになります。 ただし、サイクルはその上の 2 つの頂点間に 2 つの異なる単純なパスを即座に作成するため、一意性条件によりサイクルは許可されません。 したがって、ドライバーがロボットであるためには、その構造は実際には分岐やサイクルのない単純なパスの集合でなければなりません。 この構築により、暗黙の遷移にサイクルまたは分岐が存在する場合、制約グラフ内で頂点の次数が少なくとも 3 になることが保証されます。これはまさに検出されたものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        q = int(input())
        
        deg = [0] * (n + 1)
        seen_edges = set()

        bad = False

        for _ in range(q):
            tmp = list(map(int, input().split()))
            k = tmp[0]
            path = tmp[1:]
            
            for i in range(k - 1):
                a, b = path[i], path[i + 1]
                if a > b:
                    a, b = b, a
                if (a, b) not in seen_edges:
                    seen_edges.add((a, b))
                    deg[a] += 1
                    deg[b] += 1
                    if deg[a] > 2 or deg[b] > 2:
                        bad = True

        print("Human" if bad else "Robot")

if __name__ == "__main__":
    solve()
```このコードは、エッジ セットを使用して隣接制約のコンパクトな表現を構築し、乗車間で繰り返される遷移の二重カウントを回避します。 次数配列は、各頂点が強制的に接続される個別の近傍の数を追跡します。 早期終了条件は、いずれかの頂点が 2 つの別個の隣接頂点を超えるとすぐにトリガーされます。これは、一意性を壊す構造分岐がすでに保証されているためです。 

順序の正規化`(a, b) = sorted pair`ライドのトラバース方向に関係なく、方向のないエッジが二重にカウントされないようにします。 乗り物はエッジを両方向に横断できるため、これは不可欠ですが、ここでは方向ではなく構造的な接続のみを考慮します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(\sum k)$| ライド内の連続する各ペアは 1 回処理され、ハッシュ セットに保存されます。 
| スペース |$O(n + \sum k)$| それぞれの個別の隣接関係を格納する次数配列とエッジ セット |

 トランジションの総数は次のように制限されます。$3 \cdot 10^5$したがって、ソリューションは制限内で快適に実行されます。 ハッシュベースのエッジ重複排除により、同じセグメントが繰り返し出現して複雑さが増大することがなくなります。

 ## 特殊なケース

 重要なエッジケースは、複数の乗り物にわたって同じセグメントを繰り返し通過することです。 アルゴリズムはこれを次のように処理します。`seen_edges`を設定し、エッジを再訪しても人為的に度数が大きくならないようにします。 これがないと、単一の有効なチェーンが誤って次数境界を超える可能性があります。 

もう 1 つのエッジ ケースは、異なるライド間で複数回表示される頂点ですが、2 つの一貫した隣接点がある場合にのみ発生します。 次数ベースの条件は、一意性が出現頻度ではなく明確な近傍に依存するため、条件を正しく有効に保ちます。 

最後のエッジ ケースは、1 つの頂点が多くのパスに接続する大きな星型の構造です。 3 番目の別個の近隣ノードが現れるとすぐに、アルゴリズムはそれを人間としてマークし、エンドポイント間の複数の単純なルートが可能になる最初のポイントを正確に捕捉します。
