 ## 問題の理解

 バイナリのテンプレート文字列が与えられます`s`、各文字は次のいずれかです`0`または`1`、およびターゲット文字列`t`小文字で構成されます。 課題は、すべてのことを想像することです。`0`で`s`空ではない固定文字列に置き換えられます`r0`、そしてすべての`1`空ではない別の固定文字列に置き換えられます`r1`。 これらの置換を実行し、結果を順番に連結すると、新しい文字列が得られます。 空ではない個別の文字列の順序付けされたペアが何組あるかを数えたいとします。`(r0, r1)`正確に生産できる`t`。 

重要な問題は同じパターンであることです`s`概念的に繰り返されますが、シンボルから文字列へのマッピングはグローバルで一貫性があります。`0`すべて同じ文字列を使用します`1`別の固定文字列を使用します。 

制約は十分に大きいため、すべての候補文字列ペアを直接試行することは不可能です。 長さ`t`は 100 万に達する可能性があるため、単一の候補ペアをテストする場合でもほぼ線形である必要があり、潜在的な分割の数は列挙するには多すぎます。 

シンボルの 1 つが数回しか出現しない場合、微妙な失敗のケースが発生します。`s`。 長さを仮定すると、`r0`そして`r1`注意深く一貫性をチェックしないと、再構築する場合に分解を受け入れる可能性があります。`t`ある境界で失敗します。 もう 1 つの失敗モードは、繰り返し構造によって暗示される実際の文字列の等価性制約を検証せずに、長さだけを十分なものとして扱うことです。 

たとえば、次の場合`s = 01`そして`t = "aaaaaa"`、分割を確実にする必要があります。`t`2つの長さに分けて`len(r0)`そして`len(r1)`の構造全体で一貫した繰り返し回数が得られます。`s`。 繰り返しの一貫性を無視した単純な分割では、無効な分解が過剰にカウントされてしまいます。 

## アプローチ

 直接的な強引なアプローチでは、長さを選択します。`r0`、次に長さ`r1`、次に建物のシミュレーションを試みます`t`通り抜けることで`s`それに応じて部分文字列をスライスします。 長さは最大まで伸ばすことができるので、`|t|`、これはおおよそ次のことにつながります$O(|t|^2)$最悪の場合の可能性と各チェックのコスト$O(|t|)$、これは実現可能な限界をはるかに超えています。 

重要な構造的洞察は次のとおりです。`r0`そして`r1`未知の文字列である場合、その動作はその長さと出現方法によって完全に決定されます。`0`そして`1`蓄積する。 直したら`len(r0) = a`そして`len(r1) = b`、そして通り抜けます`s`のプレフィックス位置のシーケンスを定義します`t`。 All occurrences of`0`サイズのジャンプに対応`a`、および次のすべての出現`1`サイズのジャンプに対応`b`。 これは、有効なペアに対して、`(a, b)`、最終位置は正確に着地する必要があります。`|t|`、同じシンボルに対応するすべてのセグメントが一貫して一致する必要があります。 

重要な削減は、修正した後に次のことを観察することです。`a`、の値`b`は全長の方程式によって強制されます。$$cnt_0 \cdot a + cnt_1 \cdot b = |t|$$それで$$b = \frac{|t| - cnt_0 \cdot a}{cnt_1}$$したがって、次の値を試すだけで済みます。`a`、計算する`b`、そして、誘導されたマッピングが一貫したパーティションを生成するかどうかを検証します。`t`。 

一貫性は、各シンボルを割り当てることでチェックされます。`s`の部分文字列`t`それはすべてにマッピングされ、すべてを保証します`0`出現箇所は同じ部分文字列を共有し、すべて`1`出現箇所は同じ部分文字列を共有します。 2 つの部分文字列も異なっていなければなりません。 

これにより、問題は可能な限り反復されるようになります。`a`までの値`|t| / cnt_0`、結果は$O(|t|)$または$O(\sqrt{|t|})$実装の詳細に応じて効果的なスキャンを実行し、候補ごとの線形検証をハッシュまたは早期拒否による直接スライスによって効率化します。

 ## アルゴリズムのチュートリアル

 まず、プレフィックス ハッシュを事前計算します。`t`そのため、あらゆる部分文字列の比較を一定時間内に行うことができます。 また、0 と 1 が何個あるかも数えます。`s`、これらは長さ間の線形制約を決定するためです。 

1. 数える`c0`そして`c1`、の数`0`そして`1`で`s`。 保証されているため、両方とも非ゼロであると仮定します。 
2. 可能なすべての長さにわたって反復します。`a`のために`r0`。 それぞれなので`0`貢献する`a`文字が必要です`c0 * a < |t|`そうでない場合は、スペースが残りません。`r1`。 
3. それぞれについて`a`、残りの長さを計算します`rem = |t| - c0 * a`。 もし`rem <= 0`、スキップします。 
4. 次のことを確認します。`rem`で割り切れます`c1`。 そうでない場合は無効です`b`このために存在する`a`。 
5.セット`b = rem // c1`。 もし`b == 0`、文字列は空ではない必要があるためスキップします。 
6. 通り抜けをシミュレートする`s`、ポインタを維持する`t`。 初めて遭遇したとき`0`、レコードの部分文字列`r0`; 同様に記録する`r1`のために`1`。 
7. 以降の各発生ごとに、`0`または`1`、ハッシュを使用して、その部分文字列を保存されたパターンと比較します。 不一致が発生した場合、これを破棄します`(a, b)`。 
8. 次のことを確認します。`r0 != r1`ハッシュ比較を使用します。 等しい場合は破棄します。 
9. すべてのチェックに合格した場合、応答をインクリメントします。 

正しさは、次の構造に依存します。`s`のセグメンテーション境界を完全に決定します`t`長さが決まったら。 不一致は、同じシンボルの繰り返しの不一致として現れる必要があるため、一貫性をチェックすることは必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_hash(s, base=91138233, mod=10**9+7):
    n = len(s)
    h = [0] * (n + 1)
    p = [1] * (n + 1)
    for i, ch in enumerate(s):
        h[i+1] = (h[i] * base + (ord(ch) - 96)) % mod
        p[i+1] = (p[i] * base) % mod
    return h, p

def get_hash(h, p, l, r, mod=10**9+7):
    return (h[r] - h[l] * p[r - l]) % mod

def solve():
    s = input().strip()
    t = input().strip()

    n = len(s)
    m = len(t)

    c0 = s.count('0')
    c1 = n - c0

    ht, pt = build_hash(t)

    ans = 0

    for len0 in range(1, m + 1):
        rem = m - c0 * len0
        if rem <= 0:
            break
        if rem % c1 != 0:
            continue

        len1 = rem // c1
        if len1 <= 0:
            continue

        pos = 0
        r0_hash = r1_hash = None
        ok = True

        for ch in s:
            if ch == '0':
                cur_hash = get_hash(ht, pt, pos, pos + len0)
                if r0_hash is None:
                    r0_hash = cur_hash
                elif r0_hash != cur_hash:
                    ok = False
                    break
                pos += len0
            else:
                cur_hash = get_hash(ht, pt, pos, pos + len1)
                if r1_hash is None:
                    r1_hash = cur_hash
                elif r1_hash != cur_hash:
                    ok = False
                    break
                pos += len1

        if ok and r0_hash != r1_hash:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装では、問題を長さの列挙フェーズと一貫性検証フェーズに分割します。 ローリング ハッシュを使用すると、一定時間での部分文字列の比較が可能になります。これは、最大 100 万文字までの直接スライスでは遅すぎるため、不可欠です。 

実装の微妙な点は、明示的に構築することがないことです。`r0`または`r1`。 ハッシュ値を通じてのみ部分文字列を比較します。 もう 1 つの微妙な点は、早めの休憩です。`c0 * len0`を超える`m`不必要な反復を防ぎます。

 ## 特殊なケース

 重要なエッジ ケースは、1 つのシンボルのすべての出現が非常に短い部分文字列にマップされ、他のシンボルの長さがターゲット文字列のほぼ全体を支配することになる場合に発生します。 このような場合、誤った実装では、残りの長さが 2 番目のカウントで割り切れる必要があることを検出できないことがよくあります。 

もう一つの微妙なケースは次のような場合です。`r0`そして`r1`結局同じになります。 すべての構造チェックに合格した場合でも、アルゴリズムはこれを明示的に除外する必要があります。 最後のハッシュ比較ではこの制約が適用され、繰り返される同一の部分文字列にマッピングされた交互のバイナリ文字列などの完全に対称なパターンでの過剰カウントが防止されます。
