 ## 解決策
 ## 問題の理解

 内の各セル$n \times n$グリッドは次の数のキャンディーを定義します$i^2 + j^2$、 どこ$i$そして$j$は行と列のインデックスです。 すべての細胞について、同じキャンディーをたくさん取り出して、それらを均等に分割しようとすることを想像します。$m$友達。 セルは、そのキャンディー数が次の値で割り切れる場合にのみカウントされます。$m$、つまりキャンディーを次のように分けることができます。$m$残りのない等しい整数部分。 

タスクはペアの数を数える事です$(i, j)$と$1 \le i, j \le n$満足する$$i^2 + j^2 \equiv 0 \pmod m.$$入力サイズにより、直接の列挙が直ちに除外されます。 以来$n$まで可能です$10^9$、すべてを反復します$n^2$ペアは無理です。 すべてを繰り返しても$i, j$ペアは時間制限をはるかに超えているため、解決策は実際の値ではなくモジュール構造のみに依存する必要があります。 

単純な試みでは、すべてのセルをチェックして和の剰余を計算することになります。$m$、しかしそれには必要があります$O(n^2)$操作。 と$n = 10^9$、これは天文学的な大きさです。 

2 番目の微妙な落とし穴は、対称性だけで作業が十分に軽減されると想定していることです。 その間$i^2 + j^2$対称的です、対称性はまだ残っています$O(n^2)$ペアなので、複雑さは変わりません。 

次の場合には、別のエッジケースが発生します。$m = 1$。 すべての数字は 1 で割り切れるので、答えは次のようになります。$n^2$。 モジュラー推論では、偶発的な除算ロジックが発生することなく、この自明なケースを保存する必要があります。 

## アプローチ

 ブルートフォース手法は簡単です。すべてを反復処理します。$i$そして$j$、計算する$i^2 + j^2$、そして次によって割り算をチェックします$m$。 これは条件の定義に直接従うため、正しく機能します。 ただし、実行します$n^2$チェックは、次の場合には完全に実行不可能です。$n$大きいです。 

重要な観察は、割り算は剰余の剰余にのみ依存するということです。$m$。 以来$$i^2 + j^2 \equiv (i \bmod m)^2 + (j \bmod m)^2 \pmod m,$$の値のみを考慮する必要があります。$i$そして$j$周期全体の長さまで$m$。 あらゆるサイズの完全なブロック$m$同じ残基パターンを繰り返します。 

したがって、座標の観点から考える代わりに、剰余クラスに切り替えます。 させて$f[r]$は何個の整数になるか$[1, n]$残りがある$r$モジュロ$m$。 次に、残基のペアを数えます$(a, b)$次のような:$$a^2 + b^2 \equiv 0 \pmod m,$$各残基ペアを形成できる方法が何通りあるかを乗算します。$$f[a] \cdot f[b].$$これにより問題は次のように縮小されます$O(m^2)$、これは許容されます。$m \le 1000$。

 ## アルゴリズムのチュートリアル

 1. 問題を数字の剰余頻度のカウントに落とし込みます。$1$に$n$モジュロ$m$。 各剰余クラスは、全範囲にわたる繰り返しパターンを表します。 
2. アレイを構築する`cnt`サイズの$m$、 どこ`cnt[r]`内の整数の数です$[1, n]$そのような$i \bmod m = r$。 これが機能するのは、数値が長さのサイクル全体に均等に分布しているためです。$m$、残りのセグメントがあります。 
3. 残基のすべてのペアを反復処理します。$(a, b)$から$0$に$m-1$。 
4. 各ペアについて、次を計算します。$(a^2 + b^2) \bmod m$。 それがゼロに等しい場合、この残基ペアは有効なセルに寄与します。 
5. 貢献を追加する`cnt[a] * cnt[b]`答えに。 これは、行残差が次のとおりであるすべてのグリッド セルをカウントします。$a$カラム残留物は$b$。 
6. 累積合計を返します。 

### なぜ効果があるのか

 内のすべての整数$[1, n]$正確に 1 つの剰余クラスのモジュロに属します$m$、同じクラス内のすべての整数は、二乗モジュロに関して同じように動作します。$m$。 したがって、すべてのグリッドセルは、$(i, j)$ペアによって完全に決定されます$(i \bmod m, j \bmod m)$。 このアルゴリズムは、そのようなすべての残基ペアを正確な多重度で 1 回だけ列挙するため、有効なペアが見逃されることも、無効なペアが含まれることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    cnt = [0] * m

    # count how many numbers in [1..n] fall into each residue class mod m
    for r in range(m):
        # first number with residue r is r (or r+m if r==0 and starting from 1)
        # easier: shift range [1..n] -> [0..n-1] then adjust
        # compute count of x in [0..n-1] with x % m == r
        cnt[r] = (n - r + m - 1) // m

    ans = 0

    for a in range(m):
        for b in range(m):
            if (a * a + b * b) % m == 0:
                ans += cnt[a] * cnt[b]

    print(ans)

if __name__ == "__main__":
    solve()
```の`cnt[r]`計算では、次の整数がいくつあるかを数えます。$1$に$n$残りがある$r$モジュロ$m$、範囲を効果的にシフトし、等差数列カウントを使用することによって。 各残基はほぼ均一な分布を形成し、最大でも 1 つの要素が異なります。 

残基に対するネストされたループはすべてをチェックします。$m^2$モジュラー条件が成立する場合にのみ、組み合わせて寄与分を蓄積します。 これはグリッドを直接ミラーリングしますが、圧縮された残差空間内にあります。 

ここでよくある間違いは、剰余をゼロとして誤って処理することです。 範囲を次のように扱う$0 \ldots n$の代わりに$1 \ldots n$オフバイワンエラーが発生する`cnt[0]`、その後、不正確なペア数に伝播します。

 ## 特殊なケース

 いつ$m = 1$、すべての数値は 1 で割り切れるので、すべて$n^2$グリッドセルをカウントする必要があります。 唯一の剰余クラスが 0 であるため、アルゴリズムはこれを自然に処理します。$0^2 + 0^2 \equiv 0$。 

いつ$n < m$、残留物カウントはまばらで不均一です。 例えば、$n = 3, m = 5$生成する`cnt = [1,1,1,0,0]`。 このアルゴリズムは、完全なサイクルを想定するのではなく、正確な出現をカウントするため、引き続き機能します。 

微妙なケースが発生するのは、$n$は正確に割り切れます$m$。 すると、すべての剰余の頻度が同じになります$n/m$となり、計算は完全に均一になります。 この公式は明示的に均一性を仮定することがなく、等差数列のみが考慮されるため、依然として有効です。
