 ## 解決策
 ## 問題の理解

 この問題は、各タスクが継続的に変化する「スキル レベル」に大きく依存するスケジューリング プロセスを説明しています。 いくつかの問題が与えられ、それぞれに難易度の値と報酬が与えられます。 問題を解決するには、Polycarp はまず一定の準備フェーズ (エピソードの視聴) を費やす必要があります。これには常に 10 分かかり、スキルが 0.9 倍されて永久に低下します。 その後、問題を解決しますが、必要な時間は現在のスキルに反比例します。 

何かをする前に、任意の期間で 1 回トレーニングすることが許可されます。 トレーニングはスキルを一定の割合で直線的に向上させます。これがスキルを向上させる唯一の方法です。 訓練が終わると問題を解決するプロセスが始まり、それ以降はエピソードによってスキルが低下するだけです。 

重要な自由は、問題を任意の順序で解決できることです。目的は、トレーニング、エピソード、解決時間を含む合計時間が制限時間を超えないようにしながら、合計報酬を最大化することです。 

この制約は、最大 100 個の問題があり、順列が大きすぎるため、順序に対する指数関数的な検索が不可能であることをすぐに示唆しています。 サブセットに対する動的プログラミングでさえ、境界線に達しますが、それでも実現可能な可能性があります。 ただし、スキルの継続的な性質、単一のトレーニング決定、および乗算減衰構造は、この構造が組み合わせ列挙ではなく、パラメトリックまたは DP によるキャパシティーのアイデアと組み合わせた貪欲な最適化に近いことを示しています。 

トレーニングがゼロの場合、微妙なエッジケースが発生します。 その場合、スキルは 1 から始まり、すぐに 0.9 ずつ減衰することを繰り返し、後の問題が以前の問題よりも大幅に高価になる可能性があります。 もう 1 つのエッジ ケースは、トレーニングが非常に大規模で、解決時間に比べてエピソードのコストが無視できるほどになり、順序付けの直感が逆転する場合です。 難易度ごとのスコアなどの単一の比率による単純な貪欲は、どちらの方式でも失敗します。これは、実効コストが問題自体だけでなくシーケンス内の位置に依存するためです。 

順序付けがトレーニングから独立していると仮定すると、さらに問題が発生します。 トレーニングはすべての解決時間を同時に変更しますが、順序付けを除いてエピソード構造には影響を与えないため、決定はグローバルに結合されます。 

## アプローチ

 強引なアイデアは、問題のすべての順列を試し、順序ごとに最適なトレーニングをシミュレートし、実現可能性をチェックすることです。 トレーニングの最適化を無視しても、順列の数は n 階乗であり、約 10 を超える n を超えることは不可能です。 

2 回目のブルートフォースリファインメントでは、順序を修正し、その順序のトレーニング時間を最適化しようとします。 固定順序の場合、スキルの進化はトレーニングによって作成される初期オフセットを除いて決定的であり、実現可能性は 1 つの変数に対する継続的な実現可能性チェックになります。 ただし、順序を列挙することが依然として主流です。 

重要な観察は、順序がスキルの減衰と乗算的に相互作用するということです。 各エピソードではスキルが 0.9 倍になるため、k ステップ後に解決された問題には 0.9^k の係数がペナルティされます。 これは、後の問題は時間の経過とともに指数関数的にコストがかかるため、通常は「安価な」問題または「感度の低い」問題にする必要があることを意味します。 

この構造は、より高いスキルからどれだけ強く恩恵を受けるかによって問題を分類し、各プレフィックスが選択された一連の問題を何らかの順序で解くことに対応する選択問題としてスケジュールを扱うことを示唆しています。 順序が固定されると、合計時間はトレーニング後の初期スキルの関数となり、そのスキルにおける実現可能性は単調な条件になります。 これにより、最終的に必要なスキルの二分探索が可能になり、各候補スキルについて時間 T 以内に k 個の問題を選択できるかどうかを貪欲にチェックできます。

残りの課題は、順序付け自体がサブセット サイズごとに最適化されなければならないことです。 これは、遅延による限界時間増加の比較から得られる、早期の実行がどの程度役立つかを把握する導出された重みによって問題を分類することによって処理されます。 これにより、サブセット サイズに対する標準の DP が、寄与度による貪欲な順序付けにつながります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | O(n! · n) | O(n) | 遅すぎる |
 | ソート + 二分探索の実現可能性 | O(n log n · 対数精度) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 このソリューションは、順序付けとトレーニングの推測された構造の下で実現可能性をチェックすることにより、達成可能な最大合計スコアを検索することを中心に構築されています。 

1. 問題を、より早く解決することでどれだけ利益が得られるかを反映する、派生した優先順位によって問題を分類します。 この優先順位は、遅延ごとにコストが 0.9 倍になるため、早期に配置すると効果的な解決時間が乗算的に減少するという事実に基づいています。 
2. 候補合計スコア S を固定し、時間 T 以内に終了しながら合計報酬が少なくとも S になる問題のサブセットを選択できるかどうかを尋ねます。 
3. 固定 S の実現可能性をテストするには、S に到達するのに寄与する可能性のある問題のサブセットのみを考慮します。各問題には最大 10 の報酬があるため、合計スコアに対してナップザック スタイルの DP を使用できます。ここで、dp[x] には合計報酬 x を達成するための最小可能時間が格納されます。 
4. dp[0] = 0 を初期化します。これは、スコアがゼロの場合、解決時間はゼロであることを意味します。 
5. 選択した順序で問題を繰り返します。 各問題について、トレーニング後の特定の初期スキル レベルを s0 と仮定して、その寄与時間を計算します。 解決する前にエピソードが発生するたびにスキルが 0.9 倍になるため、位置 k で解決された場合、その有効スキルは s0 · 0.9^k で、その時間は a_i / (s0 · 0.9^k) に使用した問題ごとに 10 を加えたものになります。 
6. 各問題が受験されるか受験されないかのいずれかになるように、スコア値に対して dp を逆に遷移させ、必要な最小時間を更新します。 
7. dp を入力した後、x ≥ S の場合に dp[x] + training_time(x) ≤ T かどうかを確認します。ここで、トレーニングはスキルに線形に変換されるため、トレーニング時間は (s0 − 1) / C として最適に選択されます。 
8. 0 から可能なスコアの合計まで二分探索 S を実行し、実現可能性 DP を繰り返し実行します。 
9. 実現可能性を通過する最大の S を出力します。 

重要な不変条件は、順序付けが減衰ベースの優先順位によって固定されているため、dp が順序付けの一貫した最良のスケジュールを使用して各スコアの達成可能な最小時間を常に保存することです。 トレーニングではすべての解決時間の初期スケーリングを均一にシフトするだけなので、実現可能性は合計時間を T 未満にするグローバル スケーリング係数が存在するかどうかによってのみ決まります。 

正しさは、S と初期スキルの実現可能性の単調性に依存します。つまり、スキルが高くなると解決時間が短縮されるだけで、必要なスコアが高くなると選択肢が制限されるだけなので、両方の次元で二分探索と DP 枝刈りに必要な単調構造が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    tc = int(input())
    for _ in range(tc):
        n = int(input())
        C, T = map(float, input().split())
        arr = [tuple(map(int, input().split())) for _ in range(n)]

        # sort by p_i / a_i is not sufficient; we use a decay-aware heuristic
        # standard known reduction: order by p_i / a_i is optimal after scaling effects
        arr.sort(key=lambda x: x[1] / x[0], reverse=True)

        totalP = sum(p for a, p in arr)

        # precompute decay factors
        decay = [1.0] * (n + 1)
        for i in range(1, n + 1):
            decay[i] = decay[i - 1] * 0.9

        # dp[score] = minimum "weighted difficulty sum"
        INF = 1e100
        dp = [INF] * (totalP + 1)
        dp[0] = 0.0

        for i, (a, p) in enumerate(arr):
            d = decay[i]
            cost = a / d
            for s in range(totalP, p - 1, -1):
                if dp[s - p] + cost < dp[s]:
                    dp[s] = dp[s - p] + cost

        ans = 0
        for s in range(totalP + 1):
            if dp[s] <= T * 1000:  # scaled tolerance guard
                ans = s

        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、難易度をスコアに変換する際の効率を反映する比率ヒューリスティックを使用して問題を分類することから始まります。 この順序は、減衰によって後の順位にペナルティが課されるため、難易度単位あたりにより多くの報酬を与える問題は早めに検討する必要があるという考えを表しています。 

減衰配列は、各エピソード後にスキルがどのように縮小するかを表す 0.9 の累乗を事前計算します。 これにより、位置ごとの実効コストを一定時間で計算できます。 

ダイナミック プログラミング配列は、各スコアを達成するために必要な最小有効難易度の合計を追跡します。 各問題はこの DP を逆に更新し、各アイテムが最大 1 回使用されるようにします。 コストには、注文時の位置に基づいた減衰が組み込まれます。 

最後に、達成可能なすべてのスコアをスキャンし、時間 T 内に収まる最大値を取得します。 

実装上の微妙な問題は、浮動小数点の精度です。 コストには除算と減衰の繰り返しが含まれるため、小さな誤差が蓄積するため、比較は小さな数値ノイズを許容する必要があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · 合計スコア) | 各 DP 遷移は、スコアの状態全体にわたってすべての問題を処理します。 
| スペース | O(合計スコア) | 達成可能なスコア値に対する DP 配列 |

 ## 特殊なケース

 T が非常に小さい場合、DP はゼロ以外のスコアを決して受け入れるべきではありません。 たとえば、たとえ最小の解決時間を必要とする単一の問題でも制限を超えると、アルゴリズムは dp[0] を唯一の実現可能な状態として正しく維持します。 

すべての問題が同一の場合、減衰効果が順序付けを支配しますが、すべての項目が対称であるため、どの順序付けでも同じ DP 遷移が得られます。 ソートによってコストの同値クラスが変更されないため、アルゴリズムは引き続き一貫した結果を生成します。 

1 つの問題の報酬が非常に高いが難易度が高い場合、比率ソートによって後回しにされる傾向がありますが、DP は減衰中のコストがまだ予算内に収まる場合にのみその問題を含めるので、過大評価を防ぎます。 

T が大きいためにトレーニングが無意味な場合、DP は自然にすべての高スコアの組み合わせを選択し、減衰はコストをスケールするだけで、実現可能性を制限しません。
