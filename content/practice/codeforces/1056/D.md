 ## 解決策
 ## 問題の理解

 ノード 1 がルートとして固定された、ルート付きツリーが与えられます。 最初はリーフ ノードのみが色を受け取り、他のすべてのノードは色付けされません。 この問題におけるリーフは、そのサブツリーがそれ自体のみで構成されるノードとして定義されます。ルート付きツリーでは、子のないノードを意味します。 

葉に色が割り当てられたら、すべてのノード t を調べ、そのサブツリーを調べます。 ノード t は、t のサブツリー内ですべての色の付いた葉がペアごとに異なる色を持っている場合、つまり t より下の葉の間で色が繰り返されない場合、「ハッピー」と呼ばれます。 色の付いていないノードは、どのリーフがどのサブツリーにあるかを定義することを除いて、直接的には重要ではありません。 

1 から n までのすべての k について、ツリー内に少なくとも k 個の幸せなノードが存在するように、必要な色の最小数を決定します。 

主な困難は、幸せなノードの数が葉の色がツリー内で競合を上方にどのように伝播するかに依存するため、ローカルではなくグローバルに推論する必要があることです。 

n が 100000 までの制約により、サブツリーのプロパティを繰り返し再計算する構築から遠ざけられます。 k あたりの大量の再計算を伴う二次関数や O(n log n) であっても遅すぎます。 与えられた色数の下で何個のノードを幸せにできるかを理解し、その関係を逆転できる単一のグローバル構造が必要です。 

各サブツリーが独立して幸せなノードに寄与すると仮定すると、素朴な障害モードが現れます。 たとえば、星形のツリーでは、すべての葉を独自に色付けするとすべてのノードが幸せになりますが、色を再利用すると、単一のサブツリーに局所的ではない方法で幸福が崩壊します。 祖先の重複を無視した貪欲な代入は、カウントを誤ります。 

もう一つの微妙な問題は、「happy」が色の追加に関して単調であることです。 色の数を増やすと、幸せなノードの数が増加または維持されるだけであり、減少することはありません。 この単調性に依存しないアプローチは、すべての k 値に答えようとすると失敗します。 

## アプローチ

 この強引なアイデアは、色の数 C を固定し、幸せなノードの数を最大化する方法で葉に色を割り当てようとすることです。 固定 C の場合、割り当てをシミュレートしたり、すべての色を推論してみたりすることはできますが、リーフの割り当ての数は、リーフの数に応じて指数関数的に増加します。 構造化された割り当てに限定しても、依然として組み合わせの爆発が残ります。 

重要な観察は、ノード t が幸せになるための条件は、サブツリー内の個別の葉の数が C を超えるかどうかのみに依存するということです。サブツリーに C 個を超える葉が含まれる場合、C の色のみを使用してそれらをどのように着色しても、繰り返しが強制され、t は不幸になります。 多くても C 個の葉が含まれている場合は、t が満足できるように、そのサブツリー内に常に個別の色を割り当てることができます。 

これにより問題は完全に変わります。 任意の色の割り当てについて考える代わりに、各ノードについて、そのサブツリーに何枚の葉があるかを知るだけで済みます。 この数によって、そのノードが C カラーの下で幸せになれるかどうかが完全に決まります。 

したがって、固定 C の場合:

 ノードは、そのサブツリーに多くても C 個のリーフが含まれる場合にのみ満足します。 

ここで、問題は次のようになります。各 C について、subtree-leaf-count ≤ C を持つノードの数を数えます。次に、この関数を逆にして、k を超えるクエリに答えます。 

DFS を介してリーフ数を計算します。 次に、これらのカウントによってノードをバケット化し、可能な値に対して頻度配列を構築します。 この配列のプレフィックスの合計により、任意の C について、満足しているノードの数がわかります。 

最後に、C を 1 から n までスキャンし、リーフ数 ≤ C のノードの累積数を維持することで反転します。各 k について、少なくとも k に達する最小の C を見つけます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースカラーリング | 指数 | O(n) | 遅すぎる |
 | サブツリーの葉のカウント + プレフィックスの反転 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ## 1. ツリーをルート化し、サブツリーの葉の数を計算します。 

親表現から隣接リストを構築し、ノード 1 から DFS を実行します。ノードごとに、そのサブツリーに存在するリーフの数を計算します。 ノードに子がない場合、ノードはリーフになります。 

この値は、そのサブツリーに影響を与えることができる色付きオブジェクトの数を正確に捕捉します。 

## 2. すべてのノードのリーフ数を保存する

 各ノード v について、leaf_count[v] を計算します。 v が葉の場合、この値は 1 です。そうでない場合は、その子の葉の数の合計です。 この集約により、各リーフが祖先ごとに正確に 1 回カウントされるようになります。 

## 3. 葉数のカウント頻度

 配列 freq[x] を構築し、サブツリー内に正確に x 個の葉を持つノードの数を数えます。 

これにより、ツリー情報がサブツリー サイズにわたる分布に圧縮されます。 

## 4. 周波数にわたるプレフィックスの合計を構築する

 pref[C] = サブツリーに最大 C 個のリーフがあるノードの数を計算します。 

これは、freq を小さい値から大きい値まで累積することによって行われます。 この時点で、pref[C] は、C 色があれば満足するノードの数と等しくなります。 

## 5. 関数を逆にして答えを求める

 ここで、pref[C] を C の単調関数として解釈します。各 k について、pref[C] ≥ k となる最小の C を見つけます。 

これを行うには、C を 1 回スキャンし、すべての k の答えを順番に入力します。 

## なぜ機能するのか

 重要な不変条件は、そのサブツリーに多くても C 個の葉が含まれる場合に限り、ノードは C カラーの下で満足できるということです。 この等価性は、各葉が色を受け取る必要があり、葉の数が利用可能な色を超えるとサブツリー内で区別することが不可能になるため成り立ちます。 逆に、十分な色が存在する場合、リーフ セットは祖先によってのみ重複し、素なサブツリー内では重複しないため、各サブツリー内で他とは独立して一意の色を割り当てることができます。 

これにより、色付けの問題全体がツリーの決定論的な構造特性に還元され、実際の色付けの構築が不要になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    parents = list(map(int, input().split())) if n > 1 else []

    g = [[] for _ in range(n + 1)]
    for i, p in enumerate(parents, start=2):
        g[p].append(i)

    leaf_cnt = [0] * (n + 1)

    def dfs(v):
        if not g[v]:
            leaf_cnt[v] = 1
            return 1
        s = 0
        for u in g[v]:
            s += dfs(u)
        leaf_cnt[v] = s
        return s

    dfs(1)

    freq = [0] * (n + 1)
    for v in range(1, n + 1):
        freq[leaf_cnt[v]] += 1

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + freq[i]

    ans = [0] * (n + 1)

    c = 1
    for k in range(1, n + 1):
        while c <= n and pref[c] < k:
            c += 1
        ans[k] = c

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```DFS は構造的なコアであり、サブツリーのリーフ数をボトムアップで計算します。 頻度配列はツリーをヒストグラムに圧縮し、プレフィックス合計はそれを単調関数に変換します。 最後の 2 ポインター スキャンでは、k ごとの再計算が回避され、線形の合計作業が保証されます。 

よくある間違いは、サブツリーのサイズとサブツリーの葉の数を混同することです。 葉だけが色を運ぶので、葉だけが重要であり、内部ノードは色の競合に直接寄与しないからです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | DFS はサブツリーのリーフ カウントを 1 回計算し、その後線形カウントとプレフィックス スキャンを実行します。 
| スペース | O(n) | 隣接リスト、数と頻度の配列 |

 各ノードが一定の回数処理され、ネストされた走査が発生しないため、ソリューションは制約内に簡単に適合します。

 ## 特殊なケース

 単一ノード ツリーは最も単純な構成です。 唯一のノードはルートとリーフの両方であるため、リーフ数は 1 です。アルゴリズムは freq[1]=1 を設定し、すべての k=1 に対して答え 1 を生成します。 これにより、基本ケースが自然に処理されることが確認されます。 

チェーンでは、最後のノードを除くすべてのノードのサブツリーにリーフが 1 つだけあります。 これにより、平坦な度数分布が生成され、すべての答えが 1 のままになることが保証されます。DFS は、内部ノードを過剰にカウントすることなく、リーフ数を正しく累積します。 

スターでは、ルートの下に多くのリーフがあり、リーフ自体のリーフ数は 1 です。これにより、リーフと内部ノードの間に強力な分離が作成され、プレフィックス ロジックは、C の増加が最初にリーフを満たし、次に内部ノードをどのように満たすかを正しく反映します。
