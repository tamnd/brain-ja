 ## 解決策
 ## 問題の理解

 私たちは路面電車に乗っている間に一連の瞬間を与えられますが、各瞬間は停留所に対応しており、アルカディはどの路面電車の路線がその停留所に通っているのかを簡単に観察しました。 各停留所には一連の路線識別子がリストされており、Arkady は観察されたすべての停留所で完全なセットを記憶しています。 

課題は、アルカディがどの路面電車に乗っていた可能性があるかを特定することです。 路面電車はアルカディが見たすべての停留所を通過する必要があるため、その線は観察されたすべての停留所の交差点に存在する必要があるため、その線は観測されたすべての停留所に表示される場合に有効です。 

入力は複数の整数セットを提供し、それぞれが特定の停留所で利用可能な路線を表します。 出力は、すべてのセットに共通するすべての整数の任意の順序です。 

制約は小さく、ストップ数は最大 100 で、各ストップには 1 から 100 までの範囲のライン識別子が最大 100 個あります。これにより、単純なセット交差を超える高度なデータ構造や最適化の必要性が即座に排除されます。 O(n * r) または O(100 * 100) の解であっても、1 秒の制限の下では自明です。 

実装でつまずく可能性がある微妙な問題は、交差ではなく和集合を想定していることです。 たとえば、停留所全体で表示されたすべての路線を誤って収集した場合、1 回しか表示されない路線が出力される可能性があります。 もう 1 つの落とし穴は、交差点を適切に初期化できないことです。 空のセットから開始して交差すると、常に空の結果が得られますが、最初のストップから開始するのは正しいです。 

単純な結合ベースのアイデアの具体的な失敗例:

 入力:```
2
2 1 2
2 2 3
```組合アプローチは次のことを生み出すだろう`{1,2,3}`ですが、正解は`{2}`どちらの停留所にも 2 番線しか現れないためです。 

## アプローチ

 この強引なアイデアは、1 から 100 までの可能なすべての路面電車路線を検討し、それがすべての停留所のリストに含まれるかどうかを確認することです。 候補路線ごとに、すべての停留所をスキャンし、メンバーシップを確認します。 n 個のストップがあり、各チェックが最大 100 個の値をスキャンする場合、複雑さは O(100 * n * 100) になります。これはここではまだ小さいですが、概念的には冗長です。 

問題の構造は、より単純なアプローチを示唆しています。つまり、各候補線をテストする代わりに、すべてのセットの交差を直接計算します。 最初のストップは、可能なラインのベースライン セットを提供します。 後続の各停留所は、その停留所に存在しない行を削除することによってこのセットをフィルタリングします。 すべての停留所を処理した後、残りのセットは正確に有効な路面電車のセットになります。 

これが機能するのは、有効な行がすべてのフィルタリング ステップで生き残る必要があるためです。 各ストップは制約として機能し、交差点は自然に「すべての制約を同時に満たさなければならない」ことをエンコードします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての行をチェック) | O(100 * n * 100) | O(1) おまけ | 承認済み |
 | 最適 (交差を設定) | O(n * 100) | O(100) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての停留所を、路面電車の路線を表す整数のセットとして読み取ります。 
2. 最初のストップを使用して候補セットを初期化します。 これは、最初に観察された制約をすでに満たしているため、唯一の正しい開始点です。 
3. 後続の各ストップについて、候補セットを現在のストップのセットとの交差部分に置き換えます。 このステップでは、その停留所に存在しない路線がすべて削除されます。 
4. すべての停止を処理した後、候補セットの残りの要素を任意の順序で出力します。 

### なぜ効果があるのか

 すべてのステップで、候補セットは、これまでに処理されたすべてのストップに表示されるラインを正確に表します。 この不変式は、共通部分が両方のセットに存在する要素のメンバーシップのみを保持するため成り立ちます。 最初のストップから開始するため、不変条件は最初は true です。 新しいストップはそれぞれ、新しい行を導入せずに無効な行をフィルターで除外することで正確さを維持します。 すべてのストップを処理した後、不変式は入力全体に拡張されます。これは、最終セットが正確にすべてのストップに共通するラインのセットであることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())

first = set(map(int, input().split()[1:]))

for _ in range(n - 1):
    parts = list(map(int, input().split()))
    s = set(parts[1:])
    first &= s

print(*first)
```解決策は、ストップの数を読み取ることから始まります。 最初の停止では、最初の有効な候補が定義されるため、ワーキング セットが初期化されます。 後続の各行は、最初の数値 (そのストップ内の要素の数にすぎません) をスキップし、残りの値をセットに変換することによって解析されます。 

キー操作は、`first &= s`、インプレイス交差を実行します。 これにより、両方のセットに存在する行のみが存続することが保証されます。 インプレース交差を使用すると、不必要なメモリ割り当てが回避され、実装がコンパクトに保たれます。 

よくある間違いは、各行の最初の整数をスキップするのを忘れることです。これは、行識別子ではなくセットのサイズを表します。 もう 1 つの間違いは、ループ内で候補セットを再初期化することです。これにより、以前の制約が破棄されてしまいます。

これにより、すべての観測値にわたって一貫して存在するラインのみが、繰り返しのフィルター処理に耐えられることが確認されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * 100) | 各交差点には最大 100 個の要素が含まれ、最大 100 個のストップで繰り返されます。 
| スペース | O(100) | 可能な路面電車路線の現在の候補セットのみを保存します。 

制約は厳しいですが、設定操作を繰り返すことさえ簡単にできるほど十分に小さいです。 このソリューションは、時間とメモリの制限内で快適に実行されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    import sys as _sys

    input = _sys.stdin.readline

    n = int(input().strip())
    first = set(map(int, input().split()[1:]))

    for _ in range(n - 1):
        parts = list(map(int, input().split()))
        s = set(parts[1:])
        first &= s

    return " ".join(map(str, first)).strip()

# provided sample
assert run("""3
3 1 4 6
2 1 4
5 10 5 6 4 1
""") == "1 4", "sample 1"

# all identical
assert run("""2
3 1 2 3
3 1 2 3
""") in ["1 2 3", "3 2 1"], "all equal"

# disjoint except one
assert run("""3
2 1 2
2 2 3
2 2 4
""") == "2", "single common element"

# single possible line repeated
assert run("""2
1 42
3 42 1 2
""") == "42", "forced line"

# minimal overlap
assert run("""2
2 1 100
2 50 1
""") == "1", "boundary overlap"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 同一のセット | すべての要素 | 交差点が何もしないときの安定性 |
 | 1 つを除いて素です | 単一の値 | 正しい消去 |
 | 強制ライン | 42 | シングルトン交差の処理 |
 | 境界の重なり | 1 | まばらな重なりの下での正確性 |

 ## 特殊なケース

 エッジ ケースの 1 つは、最初のストップには多くの行が含まれているが、後のストップでは徐々にセットが 1 つの要素に減らされる場合です。 交差は単調に増加しないため、アルゴリズムはこれを自然に処理します。 

例えば：```
3
5 1 2 3 4 5
3 2 4 6
2 2 7
```段階的に:

 最初のセットは、`{1,2,3,4,5}`。 

2回目の停車後`{2,4}`残っています。 

3回目の停車後`{2}`残っています。 

不変条件は、候補セットには常に、処理されたすべてのストップに対して有効な行が正確に含まれるため、縮小は安全で元に戻せないということです。 

もう 1 つの特殊なケースは、すべての停留所が複数の路線を共有する場合です。 どのステップも有効な共通要素を削除しないため、交差部分は特別な処理を必要とせずにすべてを保持します。
