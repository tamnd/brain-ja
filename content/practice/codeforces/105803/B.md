 ## 解決策
 ## 問題の理解

 私たちは、`n x n`ビーチグリッド。 最後の穴を除くすべてのセルには、水が次にどこに行くかを示す矢印が含まれています。 水は左上のセルから入り、すべてのセルを 1 回だけ訪問し、最後に でマークされた左下のセルから出ます。`X`。 グリッド内のちょうど 1 つの矢印が変更されたので、そのセルとそれに含まれる方向を見つける必要があります。 

グリッド座標は行と列に基づいています。 答えは、間違った矢印と正しい文字の位置です。`L`、`R`、`U`、 そして`D`。 

制限は十分に大きいため、解は線形に近くなければなりません。 入力に対するすべてのグリッド セルの合計は`10^6`、すべてのセルを 1 回検査する余裕はありますが、考えられるすべてのパスを試したり、多数の候補をシミュレートしたりすると、時間がかかりすぎます。 意図したソリューションのニーズ`O(n^2)`入力自体がすでに持っているため、テストケースごとに機能します。`n^2`文字。 

主な観察は、これらの固定された開始セルと終了セルを持つハミルトニアン パスが強制的な形状を持つということです。 パスは、ヘビのようにグリッドを 1 行ずつスイープする必要があります。 最初の行を右に移動してから 1 セル下に移動し、次に 2 行目を左に移動してから再び下に移動し、左下のセルに到達するまで方向を変えます。 

いくつかのケースでは、不注意な実装が壊れる可能性があります。 

のために`2 x 2`グリッド：```
LD
XL
```答えは次のとおりです。```
1 1 R
```最初の行は最初のセルから 2 番目のセルに移動する必要があるため、最初の文字を移動することはできません。`L`。 

のために`3 x 3`グリッド：```
RRD
LUD
XLL
```答えは次のとおりです。```
2 2 L
```2 行目は右から左に移動するため、その行の中央のセルは左を指す必要があります。 すべての行が右に移動すると仮定したソリューションは、ここでは失敗します。 

もう 1 つのよくある間違いは、最後のセルを通常の矢印のように扱うことです。 左下のセルは常に宛先であり、次の内容が含まれます。`X`, したがって、ヘビパターンと照合してはなりません。 

## アプローチ

 直接的なアプローチは、水の動きをシミュレートすることです。`(1,1)`、道が途切れる場所を見つけたいと思っています。 これは何かが間違っていることを検出するためには機能しますが、欠けている矢印が何であるべきかをすぐには教えてくれません。 間違った矢印を使用すると、パスの後半に水が流れ込み、部分的には有効に見えるトラバースが作成される可能性があります。 

ブルートフォース修復方法では、すべてのセルをあらゆる方向に変更して、毎回パス全体をシミュレートすることができます。 がある`n^2`セルと最大 4 つの可能な方向、およびすべてのシミュレーションのコスト`O(n^2)`、与える`O(n^4)`操作。 と`n`到達`1000`、それはその辺です`10^12`操作、それは不可能です。 

重要な点は、必要なパスが任意ではないということです。 パスは左上から開始して左下で終了する間にすべてのセルを 1 回だけカバーする必要があるため、次の行に移動する前に各行を完全に横断する必要があります。 唯一可能なアレンジはおなじみのスネークパターンです。 

総当たりは可能性を探ることで道を見つけようとします。 観察によりすべての可能性が排除されます。すべてのセルに対して期待される矢印は 1 つだけです。 指定されたグリッドをそのパターンと比較し、単一の不一致を見つけるだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n⁴) | O(n²) | 遅すぎる |
 | 最適 | O(n²) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取り、最後のセルを除くすべてのセルを調べます。`X`細胞。 

タスク全体は、各矢印が唯一の可能な有効なパスと一致するかどうかをチェックすることに要約されます。 
2. 現在の位置に予想される矢印を決定します。 

最後の行を除くすべての行について、0 から始まるインデックスの偶数行は右に移動し、奇数行は左に移動します。 各行の最後のセルは下を指し、ヘビを次の行に続けます。 
3. 予想される矢印と指定された文字を比較します。 

正確に 1 つのセルが間違っているため、最初の不一致が答えになります。 
4. 行、列、および正しい方向を出力します。 

回答内の座標では 1 から始まるインデックスが使用されるため、印刷前に両方のインデックスが増加します。 

なぜ効果があるのか:

 不変条件は、任意のセルを処理した後、チェックされたすべての位置が、必要な開始点と終了点を接続できる唯一のハミルトニアン パスと一致することです。 スネーク構造はすべてのセルを正確に 1 回訪問し、必要な目的地に到達します。 入力は矢印が 1 つだけこの有効な構造と異なるため、スキャンで見つかった唯一の不一致は破損したセルであるはずで、予期された文字は修正が必要です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        grid = [input().strip() for _ in range(n)]

        for r in range(n):
            for c in range(n):
                if r == n - 1 and c == 0:
                    continue

                if r % 2 == 0:
                    if c == n - 1:
                        need = 'D'
                    else:
                        need = 'R'
                else:
                    if c == 0:
                        need = 'D'
                    else:
                        need = 'L'

                if grid[r][c] != need:
                    ans.append(f"{r + 1} {c + 1} {need}")
                    break
            else:
                continue
            break

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```外側のループは各テスト ケースを独立して処理します。 セルを比較する際にランダム アクセスが必要なため、グリッドが保存されます。 

ネストされたループは、予想されるスネークの方向を直接生成します。 偶数行では、パスは左から右に移動します。 このような行の最後のセルはグリッドから外れてしまうため右に進むことができないため、代わりに下向きになります。 奇数行は対称的に機能し、右から左に移動し、最初の列を使用して下に移動します。 

左下のセルは常に存在するためスキップされます。`X`、矢印ではありません。 これにより、宛先が損傷したセルとして誤って扱われることがなくなります。 

不一致が見つかると、ステートメントでは正しくない矢印が 1 つだけ存在することが保証されるため、検索は直ちに停止します。 1 ベースの変換は印刷時にのみ適用され、0 ベースのループ内での座標の間違いを防ぎます。

## 特殊なケース

 のために`2 x 2`例：```
LD
XL
```アルゴリズムはセルをチェックします`(1,1)`。 列以来`0`左から右に移動すると、期待値は`R`、 ない`L`。 すぐに次のように出力されます。```
1 1 R
```反対方向に移動する行の場合:```
RRD
RUL
XLL
```2 行目は右から左に移動する必要があります。 細胞`(2,3)`3 行目に入るには下を向く必要がありますが、現在は左を向いています。 アルゴリズムは、以前のヘビの位置を検証した後、このセルに到達し、出力します。```
2 3 D
```最後のセルの場合:```
X
```左下隅では、アルゴリズムはそれを完全にスキップします。 これにより、目的地マーカーが壊れた方向として扱われるのを防ぎます。 

可能な最大のグリッドの場合、アルゴリズムはパスを構築したり、シミュレーションを繰り返し実行したりすることはありません。 セルごとに予期される文字を 1 つだけ計算するため、実行時間は入力サイズに応じて正確に増加します。
