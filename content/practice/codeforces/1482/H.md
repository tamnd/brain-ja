 ## 解決策
 ## 問題の理解

 忍者の個別の名前のリストが与えられ、これから起こる戦いの数を数える必要があります。 一方の忍者の名前がもう一方の忍者の名前の部分文字列であり、名前が大きい方の名前の部分文字列であり、小さい方の名前を部分文字列として含む 3 番目の忍者が存在しない場合、2 人の忍者の間で戦いが発生します。 言い換えれば、戦いは、ある名前が別の名前の「直接の部分文字列」であり、間に中間名がネストされていない場合にのみ発生します。 

入力は最大 100 万個の名前で構成され、すべての名前の合計長も 100 万文字に制限されます。 これは、二次関数の演算を実行するアルゴリズムはすべて、`n`または、文字列の合計長がタイムアウトになる可能性があります。 各文字を少数回タッチする操作、または効率的な文字列処理を使用する操作は許容されます。 

複数の名前が部分文字列のチェーンを形成する場合、微妙な特殊なケースが発生します。 たとえば、名前が次の場合、`a`、`ba`、`cba`、喧嘩関係はあくまで`ba`対`a`そして`cba`対`ba`。 すべてのペアを比較する単純な部分文字列チェックは重要です`cba`対`a`戦いとしては間違っている、なぜなら`ba`は中間名です。 

もう 1 つのエッジ ケースは、他の名前のプレフィックスまたはサフィックスであるが、直接の部分文字列接続を持たない名前です。 例えば、`abc`そして`ac`部分文字列なので戦いではありません`ac`スキップする`b`で`abc`、 しかし`ac`技術的にはまだサブシーケンスです。 ここでは、指定された部分文字列の定義が必要です。文字は順番に連続している必要があります。 

## アプローチ

 ブルートフォース手法では、名前のすべてのペアを反復処理し、一方が他方の部分文字列であるかどうかをチェックし、チェーンを形成する中間名がないことを確認します。 概念的には単純ですが、これには次のことが必要です`O(n^2 * L)`どこでの操作`L`名前の平均的な長さです。 と`n`まで`10^6`、これはまったく不可能です。 

重要な洞察は、部分文字列の関係がトライまたは一般化された接尾辞オートマトンを使用して効率的に表現できることを認識することから得られます。 すべての名前を反転してトライに挿入すると、すべてのノードが何らかの名前の接尾辞を表します。 直接部分文字列条件は、ノードに完全な名前に対応する子が 1 つだけ存在するかどうかをチェックすることになります。この子は親と競合します。 

名前を長さによってソートし、トライ内で最短のものから最長のものまで処理することにより、中間の部分文字列制約を体系的に考慮することができます。 次に問題は、一意性制約を満たす親子エッジに対応する接尾辞ツリー状の構造のトラバースになります。 

最適なアプローチでは、逆トライを使用して接尾辞の関係をキャプチャし、中間名を持たずに名前のすぐ後に別の名前が続くエッジをカウントします。 各ノードは、それが正確な名前であるかどうか、および正確な名前の子孫がいくつ存在するかを格納します。 正確に 1 つの正確な名前の子孫を持つノードのみが戦いに貢献します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 * L) | O(n * L) | 遅すぎる |
 | 逆トライ / サフィックス ツリー | O(合計文字数) | O(合計文字数) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての名前を逆にします。 これにより、部分文字列の問題が接尾辞と接頭辞の問題に変わり、トライ内の接頭辞をチェックするだけで済みます。 
2. それぞれの逆順の名前をトライに挿入します。 各ノードは文字に対応し、完全な名前を表すノードにマークを付けます。 
3. トライを再帰的に走査します。 各ノードについて、正確な名前の子の数を数えます。 
4. ノードが完全な名前を表し、正確に名前が一致する子孫が 1 つだけある場合、これは有効な戦いに相当します。 グローバルファイトカウンターを増加させます。 
5. トラバースを続行して、すべてのノードとその子孫を処理します。 
6. 合計戦闘数を出力します。 

機能する理由: 名前を逆にすることで、部分文字列の包含がトライ内の単純な接頭辞チェックになります。 親子関係は自然に直接の部分文字列関係を捕捉し、正確な名前の子をカウントすることで、中間名が部分文字列チェーンを壊すことがないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**6)

class TrieNode:
    __slots__ = ['children', 'is_name']
    def __init__(self):
        self.children = {}
        self.is_name = False

def main():
    n = int(input())
    names = [input().strip()[::-1] for _ in range(n)]
    
    root = TrieNode()
    
    # Insert all names
    for name in names:
        node = root
        for c in name:
            if c not in node.children:
                node.children[c] = TrieNode()
            node = node.children[c]
        node.is_name = True

    fight_count = 0

    def dfs(node):
        nonlocal fight_count
        exact_children = 0
        for child in node.children.values():
            if dfs(child):
                exact_children += 1
        if node.is_name and exact_children == 1:
            fight_count += 1
        return node.is_name

    dfs(root)
    print(fight_count)

if __name__ == "__main__":
    main()
```トライ挿入により、各名前の各文字が 1 回だけタッチされるようになり、文字全体に対して線形パスが与えられます。 DFS は、正確な名前の子供を正確にカウントし、問題の制約に従って喧嘩を識別します。 名前を逆にすると、部分文字列チェックが接頭辞チェックに変わります。 使用する`__slots__`大量の入力に対するメモリのオーバーヘッドを削減します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

## 特殊なケース

 ネストされたチェーンの場合`a`、`ba`、`cba`、トライパスは次のとおりです。`a`、`ab`、`abc`。 DFS は試合を正しくカウントします。`ba`対`a`そして`cba`対`ba`。 間に争いはない`cba`そして`a`なぜなら`ba`は中間の正確な名前の子であり、アルゴリズムが非中間制約を尊重していることを示しています。 同様に、完全に異なる文字を含む名前では、トライ内に親子の正確な名前のエッジがないため、争いは発生しません。
