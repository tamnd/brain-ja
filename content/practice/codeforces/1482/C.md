 ## 解決策
 ## 問題の理解

 私たちは持っています`m`日々。 毎日、特定の友人のセットが利用可能であり、その日に利用可能な友人を 1 人だけ選択する必要があります。 

割り当ては公平性条件を満たしている必要があります。 させて`limit = ceil(m / 2)`。 以下の友人を選択することはできません`limit`一日を通しての回数。 

毎日、入力により、その日にプレイできる友達のリストが提供されます。 私たちの仕事は、有効な割り当てを構築するか、何も存在しないと判断することです。 

制約は、解決策が複雑ではないことを示す最初の手がかりです。 すべてのテスト ケースの合計日数は最大で`100000`、すべてのリストにわたる可用性エントリの合計数は最大で`200000`。 これは、各可用性リストを一定の回数だけ処理するソリューションを目指す必要があることを意味します。 指数関数的なものは即座に不可能であり、二次関数さえも不可能です。`m`限界を超えてしまうだろう。 

難しいのは、選択肢が独立していないことです。 今日友達を選択することは、最大頻度の制約に違反せずにその友達を明日も使用できるかどうかに影響します。 

いくつかの特殊なケースは注目に値します。 

毎日、利用できる友人が 1 人だけである場合を考えてみましょう。```
m = 3

Day 1: {1}
Day 2: {1}
Day 3: {1}
```唯一可能な割り当ては友人です`1`3回。 以来`ceil(3/2)=2`、友人`1`許可された制限を超えて選択される可能性があります。 正しい答えは、`NO`。 

もう 1 つの微妙なケースは、1 人の友人が多くのリストに表示されているが、それらのリストには別の友人も含まれている場合です。```
m = 5

{1}
{1,2}
{1,2}
{1,3}
{1,4}
```常に最初に利用可能な友人を選択する貪欲な戦略では、友人が選択されます。`1`5回やって失敗。 有効な割り当ては、一部の柔軟な日を他の友人にリダイレクトすることによって存在します。 

最後の重要なシナリオは、最初の割り当て後に 1 人の友人だけが制限を超えた場合です。```
m = 6

{1}
{1}
{1}
{1,2}
{1,3}
{1,4}
```ここ`limit = 3`。 友達`1`最初の 3 日間は強制的に選択され、最初は 6 日間すべてに選択されます。 再割り当てできるのは複数のオプションがある日のみであることを認識する必要があります。 そのような日が十分にあれば、答えは可能です。 そうでなければ不可能です。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるすべての割り当てが試行されます。 毎日、利用可能な友人を 1 人選択し、再帰的に続行します。 1 日に以下の内容が含まれる場合、`n`候補の検索スペースはおおよそ次のようになります。$$\prod_{i=1}^{m} k_i$$これは日数で指数関数的に増加します。 わずか 20 日間で 1 日あたり 2 つのオプションがあるとしても、検討すべき課題はすでに 100 万件以上あります。 最大 10 万日かかるため、このアプローチはまったく実行不可能です。 

重要な観察は、実際に何が失敗の原因になるかを尋ねることから得られます。 

最初に、連絡可能リストの最初の友人に毎日を割り当てるとします。 各友達が何回選ばれたかを数えてください。 

友達が超えていない場合`ceil(m/2)`、もう終わりです。 

さて、誰かの友人を想定してください`x`限界を超えています。 複数の友達が同時に制限を超えることはできますか?

 いいえ、2 人の異なる友人がそれぞれ 2 回以上登場した場合、`m/2`回、それらの合計発生回数は`m`、しかないので不可能です。`m`日々。 

これにより、問題が大幅に単純化されます。 制限に違反できる友人は最大 1 人です。 

友達になる`x`選ばれすぎです。 減らす唯一の方法`x`のカウントは、現在割り当てられている日を変更することです`x`。 参加可能な友人が 1 人いる日は変更できません。 空き状況リストに追加の友人が含まれている日は、他の人に再割り当てできます。 

したがって、戦略は次のようになります。 

1. 最初に、最初にリストされている友人に毎日を割り当てます。 
2. 友達かどうかを調べる`x`限界を超えています。 
3. そうでない場合は、答えてください`YES`。 
4. それ以外の場合は、割り当てられた柔軟な日を繰り返し移動します。`x`まで、別の利用可能な友人に向けて`x`のカウントが限界に達します。 
5. 制限に達する前に柔軟な日数がなくなった場合は、次のように答えます。`NO`。 

これが機能する理由は、問題となるのは 1 人の友人だけであり、その友人から 1 日離れて変更しても、他の友人の数はすでに制限に達していた値からしか増加しないため、新たな違反が発生することはないからです。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数再帰/状態 | 遅すぎる |
 | 最適 | O(Σkᵢ) | O(m + n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. しましょう`limit = (m + 1) // 2`。 
2. 毎日、最初に、その日の空き状況リストにリストされている最初の友人を選択します。 
3. 各友達が現在選択されている回数を数えます。 
4. 友達を探す`x`カウントを超えた人`limit`。 
5. そのような友人が存在しない場合は、印刷します`YES`そして現在の任務。 
6. それ以外の場合は計算します```
excess = count[x] - limit
```これは、友人から遠ざける必要がある選択の数です`x`。 
7. 一日中スキャンします。 

現在その日が割り当てられている場合は、`x`その日に少なくとも 2 人の利用可能な友人がいる場合は、その日を他の利用可能な友人、たとえばリストの 2 番目の友人に再割り当てします。 
8. 再割り当てのたびに、減少します`excess`1つずつ。 
9. 一旦停止`excess`ゼロになります。 
10. もし`excess`数日間検査しても陽性が続いている、印刷する`NO`。 
11. それ以外の場合は印刷します`YES`そして最後の課題。 

### なぜ効果があるのか

 最初の割り当ては、最大 1 人の友人の制限に違反する可能性があります。 その友達にさせてください`x`。 

有効な解決策はすべて、回数を減らす必要があります。`x`正確に選択されます`count[x] - limit`。 役立つのは、割り当てられた日だけです。`x`複数の選択肢があるもの。 そのような日を再割り当てすると減少します`x`は 1 つ数えます。 

再割り当てによって新たな違反が発生することはありません。 変更前は、以外のすべてのフレンド`x`せいぜいすでに登場している`limit`回。 プロセス中にそれらの数は増加しますが、増加の合計数は正確に`x`限界を超えました。 一度`x`制限に達しても、他の友達は依然として制限内のままです。 

したがって、十分な柔軟な日があれば、建設は成功します。 十分な柔軟な日数が存在しない場合、必要な削減が行われないため、解決策は存在しません。`x`不可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())

        days = []
        ans = []
        cnt = [0] * (n + 1)

        for _ in range(m):
            arr = list(map(int, input().split()))
            k = arr[0]
            friends = arr[1:]

            days.append(friends)

            chosen = friends[0]
            ans.append(chosen)
            cnt[chosen] += 1

        limit = (m + 1) // 2

        bad = -1
        for friend in range(1, n + 1):
            if cnt[friend] > limit:
                bad = friend
                break

        if bad == -1:
            print("YES")
            print(*ans)
            continue

        need = cnt[bad] - limit

        for i in range(m):
            if need == 0:
                break

            friends = days[i]

            if ans[i] == bad and len(friends) > 1:
                cnt[bad] -= 1
                ans[i] = friends[1]
                need -= 1

        if need > 0:
            print("NO")
        else:
            print("YES")
            print(*ans)

solve()
```実装は証明にほぼ直接従います。 

すべての対応可能リストの最初の友人が一時的な割り当てになります。 これは、具体的な出発点を与え、問題を引き起こす可能性があるのは 1 人の友人だけであることが保証されるため、重要です。 

頻度をカウントした後、カウントが制限を超えている友人を特定します。 そのような友人が存在しない場合、現在の割り当てはすでに有効です。 

問題のある友人が存在する場合、その友人に現在割り当てられている日のみを検査します。 利用可能なオプションが 1 つしかない日は、変更が不可能なため役に立ちません。 フレキシブルな一日の場合は、リストの 2 番目の友人を割り当てるだけで十分です。 問題のある友人の数を減らすことだけが重要であることが証明されているため、最適な代替者を探す必要はありません。 

変数`need`使いすぎた友人からさらに何個の選択を移動する必要があるかを正確に追跡します。 ゼロに達すると、割り当ては周波数制約を満たします。

# helper: run solution on input string, return output string

import sys
import io

def run(inp: str) -> str:
    from collections import defaultdict

    data = inp.strip().split()
    p = 0
    t = int(data[p])
    p += 1

    out = []

    for _ in range(t):
        n = int(data[p]); p += 1
        m = int(data[p]); p += 1

        days = []
        ans = []
        cnt = [0] * (n + 1)

        for _ in range(m):
            k = int(data[p]); p += 1
            cur = list(map(int, data[p:p+k]))
            p += k

            days.append(cur)
            ans.append(cur[0])
            cnt[cur[0]] += 1

        limit = (m + 1) // 2

        bad = -1
        for i in range(1, n + 1):
            if cnt[i] > limit:
                bad = i
                break

            out.append("YES")
            out.append(" ".join(map(str, ans)))

                ans[i] = days[i][1]
                need -= 1

        if need:
            out.append("NO")
        else:
            out.append("YES")
            out.append(" ".join(map(str, ans)))

    return "\n".join(out)
