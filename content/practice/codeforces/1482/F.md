 ## 解決策
 ## 問題の理解

 最大 600 個の頂点と最大約 180,000 個のエッジを備えた無向重み付きグラフが与えられます。各エッジには正の重みが与えられます。 次に、クエリのリストが与えられます。各クエリは頂点のペアで構成されます。$u$そして$v$そして数字$l$。 いくつかのクエリ ペア間にパスが存在する場合、エッジは「有用」であるとみなされます。$(u, v)$総重量が以下のもの$l$そしてそれはこの端を通過します。 目的は、有用なエッジの数を数えることです。 

制約を考慮すると、パスの数が指数関数的に増加するため、クエリごとにすべてのパスをチェックする単純なアプローチは実行できません。 の上限$n = 600$アルゴリズムが$O(n^3)$複雑さは許容されます。$600^3 \approx 2 \times 10^8$5 秒間の操作は妥当な制限内に収まります。 エッジの重みとクエリの制限が大きい ($10^9$)、そのため、すべてのパスを明示的に構築するか、そのサイズの重みベースの配列を使用することに依存するアルゴリズムは避けなければなりません。 

明らかではないエッジ ケースには、最小パスが長さを超えないように頂点を複数回ループするクエリが含まれます。$l$。 たとえば、三角形を形成するグラフ$1-2-3-1$重み 2、2、3 とクエリを使用$(1,3,4)$次のようなパスを考慮する必要があります$1-2-3$合計は 4 になります。距離を再結合せずに最短パスのみを考慮する不注意な実装では、これを見逃す可能性があります。 

もう 1 つの微妙な点は、同じエッジの有用性に影響を与える複数のクエリを入力に含めることができ、単一のクエリで複数のエッジを同時に有用にすることができることです。 

## アプローチ

 ブルートフォース手法は、各クエリを個別に処理し、完全な検索 (ダイクストラや BFS など) を実行することです。$u$長さの下で到達可能なすべてのパスを検索します$l$、それらのパスに沿ったすべてのエッジを有用なものとしてマークします。 これは原理的には機能しますが、遅すぎます。 各ダイクストラ呼び出しは、$O(m + n \log n)$、そして最大で$q = 180,000$クエリ、これは簡単に超える可能性があります$10^{10}$操作。 

これを高速化するための重要な観察は、各エッジについてのみ知る必要があるということです。$(a, b)$、どのパスでも参加できる場合$u \to v$せいぜい長さの$l$。 Floyd-Warshall アルゴリズムを使用すると、すべてのペアの最短経路を事前に計算できます。$n \le 600$。 させて$dist[x][y]$～からの最短距離を表す$x$に$y$。 次に、エッジについては、$(a,b,w)$、クエリに役立ちます$(u,v,l)$どちらかであれば$dist[u][a] + w + dist[b][v] \le l$または$dist[u][b] + w + dist[a][v] \le l$。 これが機能するのは、有用性に寄与するパスは、エンドポイントを接続する最短パスより短くてはいけないためです。 すべてのクエリに対してすべてのエッジのこの条件をチェックすることは実現可能です。$O(n^2 + q \cdot m)$制限時間内に収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * (n + m log n)) | O(n + m) | 遅すぎる |
 | 最適 | O(n^3 + m * n) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフのエッジを読み取り、隣接行列または距離行列を構築します。`dist[i][j]`対角の 0 を除いて、最初は無限大です。 接続された頂点間の直接エッジの重みを入力します。 
2. Floyd-Warshall を実行します。各中間頂点を反復処理します。`k`、そしてすべてのペアについて`(i,j)`、 アップデート`dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`。 これにより、`dist[i][j]`頂点間の最短距離になります`i`そして`j`。 
3. アレイを準備する`best[i]`頂点ごとに`i`、許容最大値を追跡します`l - dist[i][v]`関係するすべてのクエリにわたって`v`。 これは基本的に、隣接するエッジでどれだけの残りの距離を「費やせる」かということです。`i`に向かう途中で`v`。 
4. 各クエリを反復処理する`(u, v, l)`。 頂点ごとに`a`、 アップデート`best[a] = max(best[a], l - dist[v][a])`。 つまり、頂点から`a`、につながるエッジ`v`クエリを満たすには、この残りの距離を超えてはなりません。 
5. 次に、すべてのエッジを反復処理します。`(a,b,w)`。 エッジが有効であるためには、頂点が存在する必要があります`i`そのような`best[a] >= w`または`best[b] >= w`。 これにより、このエッジがクエリを満たすパスに参加できるかどうかがチェックされます。 そのようなエッジをすべて数えます。 
6. 有効エッジの総数を出力します。 

なぜ機能するのか: Floyd-Warshall アルゴリズムは次のことを保証します。`dist[i][j]`は最短経路距離です。 最大許容残存パス長を追跡することにより (`best[a]`)、どのエッジがクエリの有効なパスの一部となり得るかを正確にキャプチャします。 この条件を満たさないエッジは、クエリの制限内のパスに含めることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
INF = 10**18

edges = []
dist = [[INF]*n for _ in range(n)]
for i in range(n):
    dist[i][i] = 0

for _ in range(m):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1
    edges.append((u, v, w))
    dist[u][v] = w
    dist[v][u] = w

q = int(input())
queries = []
for _ in range(q):
    u, v, l = map(int, input().split())
    u -= 1
    v -= 1
    queries.append((u, v, l))

# Floyd-Warshall
for k in range(n):
    for i in range(n):
        for j in range(n):
            if dist[i][j] > dist[i][k] + dist[k][j]:
                dist[i][j] = dist[i][k] + dist[k][j]

# Prepare best residual distances
best = [-10**18]*n
for u, v, l in queries:
    for i in range(n):
        best[i] = max(best[i], l - dist[v][i])

count = 0
for a, b, w in edges:
    if best[a] >= w or best[b] >= w:
        count += 1

print(count)
```コードはグラフとクエリを読み取り、すべてのペアの最短パスを計算して、最大残り距離を計算します。`best[i]`頂点ごとに。 最後に、各エッジがテストされます。`best`有用性を判断するため。 微妙な実装ポイントには、大きな初期値を使用することが含まれます。`INF`オーバーフローを回避し、Python リストの 1 ベースのインデックスを 0 ベースに変換します。
