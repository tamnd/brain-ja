 ## 解決策
 ## 問題の理解

 サイズの正方形のボードがあります`2n × 2n`、単位セルに分割されます。 1 つのセルがマークされます。 グリッド線に沿って切断パスを描画し、回転後に基板が 2 つの一致する部分に分割され、切断パスがマークされたセルに触れないようにできるかどうかを知りたいと考えています。 

重要な点は、回転後に結果として得られる 2 つの部分が同一になる必要があるということです。 辺の長さが等しい正方形の場合、自然な回転対称性はボードの中央に集中します。 

入力は辺の長さを与えます`2n`そして座標`(x, y)`マークされたセルの。 行と列には 1 から始まるインデックスが付けられます。 印刷しなければなりません`"YES"`そのようなカットが存在する場合、そうでない場合`"NO"`。 

制約は小さく、辺の長さは最大でも 100 であるため、ここではパフォーマンスは問題になりません。 難しいのは、ステートメントに隠された幾何学的な観察を認識することです。 強引な幾何学的構築は不必要であり、エラーが発生しやすくなります。 

明らかではない部分は、有効な対称カットごとにどのセルが避けられないのかを理解することです。 

最も小さな興味深いケースを考えてみましょう。```
4 2 2
```広場は`4 × 4`。 中央領域は 4 つのセルで構成されます。```
(2,2) (2,3)
(3,2) (3,3)
```マークされたセルがこれら 4 つのセルのいずれかである場合、答えは次のようになります。`"NO"`。 

なぜ？ 正方形を回転方向に等価な 2 つの半分に分割する有効なカットは、ボードの正確な中心を通過する必要があります。 均等なサイズのグリッドでは、中心はこれら 4 つのセルの交点にあるため、考えられるすべての対称分割パスはその中心に触れます。`2 × 2`ブロック。 

不注意な解決法では、正確な中心点のみをチェックし、均等なサイズのグリッドには 1 つではなく 4 つの中心セルがあることを忘れる可能性があります。 

もう 1 つの簡単な間違いは、1 ベースの座標で 0 ベースの推論を使用することです。 のために`6 × 6`ボードの中央セルは次のとおりです。```
(3,3) (3,4)
(4,3) (4,4)
```ない`(2,2)`そして`(3,3)`。 

例えば：```
6 3 4
```生産しなければならない`"NO"`なぜなら`(3,4)`中央ブロック内にあります。 

しかし：```
6 2 4
```生成する`"YES"`マークされたセルがその避けられない領域の外側にあるためです。 

## アプローチ

 強引な解釈では、グリッドのエッジに沿って可能なすべての切断線を明示的に構築し、ボードが回転方向に等しく一致する領域に分割されていることを確認し、パスがマークされたセルに触れているかどうかを確認しようとします。 

たとえ`100 × 100`ボードでは、可能な格子パスの数は膨大です。 すべてのグリッド交差点でパスが複数の方向に分岐する可能性があるため、検索空間は指数関数的に増加します。 このアプローチはすぐに実行不可能になります。 

ブルートフォースが自然に感じられる理由は、このステートメントが単純な算術条件ではなく、幾何学的なカットについて語っているからです。 しかし、ここのジオメトリは非常に硬いです。 

重要な点は、有効なパーティションはすべて、正方形の中心を中心とした 180 度の回転対称性を尊重する必要があるということです。 辺の長さが等しい場合、中心は 4 つのセルの間にあります。 対称的な分割パスはすべて、その中央領域を通過する必要があります。 

つまり、絶対に回避できない唯一のセルは中央の 4 つのセルです。```
(n,n)
(n,n+1)
(n+1,n)
(n+1,n+1)
```マークされたセルがそれらのセルの 1 つである場合、有効なカットはすべてそのセルと交差するため、答えは次のようになります。`"NO"`。 

1 つおきのセルについては、マークされた位置を避ける適切な対称カットを描画できるため、答えは次のようになります。`"YES"`。 

問題全体は、次のことを確認することに帰着します。`(x, y)`中央に所属する`2 × 2`ブロック。

 ## アルゴリズムのチュートリアル

 1.辺の長さを読み取る`2n`そしてセル座標`(x, y)`。 
2. コンピューティング`n = side_length // 2`。 

避けられない 4 つの中央セルは、完全にこの値によって決定されます。 
3. マークされたセルが中央のセル内にあるかどうかを確認します。`2 × 2`ブロック。 

これはまさに次の場合に発生します。```
x is either n or n+1
and
y is either n or n+1
```4. 両方の条件が当てはまる場合、印刷します。`"NO"`。 

すべての対称カットはこの領域を通過する必要があります。 
5. それ以外の場合は、印刷します`"YES"`。 

中央のブロックの外側には、マークされたセルを回避する有効な対称パーティションが存在します。 

### なぜ効果があるのか

 有効なカットでは、正方形が 2 つの部分に分割され、回転後には同一になります。 このような対称性により、分割パスは正方形の幾何学的中心を通過するようになります。 

辺の長さが均等であるため、幾何学的中心は 4 つのセルの間にあります。 中心を通るパスは必ず中心に接触します。`2 × 2`ブロック。 これら 4 つのセルは避けられません。 

適切な対称カットを選択することで、1 つおきのセルを回避できます。 したがって、答えは次のとおりです`"NO"`まさに 4 つの中央セルに対して、`"YES"`他のどこでも。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

side, x, y = map(int, input().split())

n = side // 2

if (x == n or x == n + 1) and (y == n or y == n + 1):
    print("NO")
else:
    print("YES")
```実装は数学的観察に直接従います。 

まず計算します`n`、ボードの中央を識別します。 辺の長さは常に均等であるため、中心は 1 つではなく 4 つのセルで構成されます。 

条件:```
(x == n or x == n + 1)
```行が中央の行のペアに属しているかどうかを確認します。 同じロジックが列にも適用されます。 

マークされたセルが中央のセル内にあるには、両方の条件が同時に満たされる必要があります。`2 × 2`ブロック。 

よくある間違いは、グリッドが 1 から始まるインデックスを使用していることを忘れることです。 のために`4 × 4`ボードの中央の行は`2`そして`3`、 ない`1`そして`2`。 

このソリューションでは、定数時間と定数メモリを使用します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    side, x, y = map(int, input().split())

    n = side // 2

    if (x == n or x == n + 1) and (y == n or y == n + 1):
        print("NO")
    else:
        print("YES")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output.strip()

# provided sample
assert run("4 1 1\n") == "YES", "sample 1"

# minimum valid size, central cell
assert run("2 1 1\n") == "NO", "minimum size central cell"

# minimum valid size, another central cell
assert run("2 2 2\n") == "NO", "all cells are central in 2x2"

# outside center block
assert run("6 2 4\n") == "YES", "outside forbidden region"

# exact center boundary
assert run("6 3 4\n") == "NO", "central block detection"

# maximum size edge position
assert run("100 1 100\n") == "YES", "large board edge cell"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 1 1`|`NO`| 最小のボード、すべてのセルが中心 |
 |`2 2 2`|`NO`| 4 つのセルすべてが禁止されていることを確認します`2 × 2`|
 |`6 2 4`|`YES`| 中心に隣接しているがまだ有効なセル |
 |`6 3 4`|`NO`| 中央ブロックの正しい識別 |
 |`100 1 100`|`YES`| 大きな境界座標 |

 ## 特殊なケース

 可能な限り最小の基板を考えてみましょう。```
2 1 1
```ここ`n = 1`したがって、中央のブロックは次のようになります。```
(1,1) (1,2)
(2,1) (2,2)
```マークされたセルはこのブロックに属しているため、アルゴリズムは次のように出力します。`"NO"`。 

このケースは、実装で中央セルが 1 つだけであると想定されている場合、誤って処理されやすくなります。 

ここで次のことを考えてみましょう。```
6 2 3
```次のように計算します。```
n = 3
```禁止されたセルは次のとおりです。```
(3,3) (3,4)
(4,3) (4,4)
```マークされたセル`(2,3)`センターブロックの真上にありますが、その中にはありません。 アルゴリズムは正しく印刷します`"YES"`。 

これにより、プログラマーが誤って実際の領域を超えて禁止領域を拡張するというオフバイワンの間違いを捕らえます。`2 × 2`中心。 

最後に、次のことを考慮してください。```
100 50 51
```ここ：```
n = 50
```中心セルは次のとおりです。```
(50,50) (50,51)
(51,50) (51,51)
```マークされたセル`(50,51)`はブロック内にあるため、アルゴリズムは次のように出力します。`"NO"`。 

これにより、特別な処理を行わなくても、ロジックが最大入力サイズに合わせて正しくスケーリングされることが検証されます。
