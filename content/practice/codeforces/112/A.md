 ## 解決策
 ## 問題の理解

 英語の文字で構成される 2 つの文字列が与えられます。 どちらの文字列も同じ長さですが、文字は大文字でも小文字でも表示されます。 タスクは、大文字と小文字を完全に無視して、2 つの文字列を辞書編集的に比較することです。 

大文字と小文字を区別しないということは、`'A'`そして`'a'`同一の文字として扱う必要があります。 比較後、次のように出力します。 

-`-1`最初の文字列が辞書編集的に小さい場合
 -`1`最初の文字列が辞書編集的に大きい場合
 -`0`両方の文字列が等しい場合

 文字列は非常に小さく、最大でも 100 です。非効率な 1 文字ずつのソリューションでも、簡単に制限内に収まります。 本当の課題はパフォーマンスではなく、比較の前に大文字と小文字の変換を正しく処理することです。 

よくある間違いは、元の文字列を直接比較することです。 Python は、ASCII 値を使用して大文字と小文字を比較します。大文字は小文字の前に来ます。 それにより、この問題に対して不正確な答えが生成されます。 

次の入力を考えてみましょう。```
aaaa
aaaA
```正しい出力は次のとおりです。```
0
```大文字と小文字を変換せずに直接比較すると、正しく処理されません。`'a'`そして`'A'`違うものとして。 

もう 1 つの簡単な間違いは、1 つの文字列だけを小文字に変換することです。 

例：```
aBc
ABC
```正しい出力は次のとおりです。```
0
```最初の文字列のみが変換される場合、比較は次のようになります。`"abc"`対`"ABC"`、大文字と小文字の ASCII 値が異なるため、それでも失敗します。 

もう 1 つの特殊なケースは、文字列が終わり近くでのみ異なる場合に発生します。 

例：```
abcz
abca
```正しい出力は次のとおりです。```
1
```不用意に実装を開始するのが早すぎたり、プレフィックスのみを比較したりすると、最後の異なる文字を見逃す可能性があります。 

## アプローチ

 最も直接的な解決策は、文字列を 1 文字ずつ比較することです。 位置ごとに、両方の文字を同じ大文字と小文字に手動で変換し、どちらの文字列が大きいかを判断できます。 最初の異なる位置によって答えが決まります。 

この強引な方法はすでに十分に高速です。 各文字列には最大 100 文字が含まれるため、最大 100 回の比較が実行されます。 それは事実上即時です。 

Python が辞書編集上の文字列比較をすでにサポートしていることを確認することで、実装をさらに簡素化できます。 唯一の問題は大文字と小文字の区別です。 両方の文字列が完全に小文字に変換されると、組み込みの比較は要求どおりに正確に動作します。 

辞書編集上の順序は最初の異なる文字のみに依存するため、総当たりバージョンが機能します。 両方の文字列を同じ大文字と小文字に変換すると、大文字と小文字の違いが完全に削除されながら、相対的なアルファベット順が維持されるため、よりクリーンなソリューションが機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | 承認済み |
 | 最適 | O(n) | O(n) | 承認済み |

 ここ、`n`文字列の長さです。 

## アルゴリズムのチュートリアル

 1. 入力から最初の文字列を読み取ります。 
2. 入力から 2 番目の文字列を読み取ります。 
3. 両方の文字列を小文字に変換します。 

これにより、大文字と小文字のみによって引き起こされるすべての違いが削除されます。 
4. 小文字の文字列を辞書順に比較します。 
5. 最初の文字列が小さい場合は、次のように出力します。`-1`。 
6. 最初の文字列の方が大きい場合は、次のように出力します。`1`。 
7. それ以外の場合は、印刷します`0`。 

### なぜ効果があるのか

 辞書編集上の比較は、左から右への文字の相対的な順序に依存します。 両方の文字列を小文字に変換すると、アルファベット順が維持され、同じ文字の大文字と小文字のバージョンが同一になります。 変換後、通常の文字列比較により、必要な結果が正確に得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s1 = input().strip().lower()
s2 = input().strip().lower()

if s1 < s2:
    print(-1)
elif s1 > s2:
    print(1)
else:
    print(0)
```最初のステップでは、両方の文字列を読み取り、次のコマンドを使用してすぐに小文字に変換します。`.lower()`。 変換を早めに行うと、残りのロジックが単純になり、後で文字処理を繰り返す必要がなくなります。 

使用する`.strip()`重要なので`input()`末尾の改行文字も含まれます。 それを削除しないと、比較には次のものが含まれます。`'\n'`、誤った結果が生成されます。 

Python はすでに辞書編集上の文字列比較を正しく実行しています。 文字を左から右に比較し、最初の不一致で停止します。 これは、問題で必要とされる定義と正確に一致します。 

3 つの比較ブランチは、必要な出力に直接マッピングされます。 Python が内部で比較を処理するため、手動ループは必要ありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各文字は、小文字の変換および比較中に 1 回処理されます。 
| スペース | O(n) | 小文字の文字列のコピーが作成されます。 

制約は非常に小さく、文字列の長さは最大 100 です。O(n) ソリューションは、時間とメモリの制限の両方に簡単に収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    s1 = input().strip().lower()
    s2 = input().strip().lower()

    if s1 < s2:
        print(-1)
    elif s1 > s2:
        print(1)
    else:
        print(0)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    return sys.stdout.getvalue()

# provided sample
assert run("aaaa\naaaA\n") == "0\n", "sample 1"

# custom cases
assert run("a\nb\n") == "-1\n", "single character smaller"
assert run("Z\na\n") == "1\n", "uppercase handling"
assert run("Codeforces\ncodeforces\n") == "0\n", "all equal ignoring case"
assert run("abcz\nabca\n") == "1\n", "difference at last character"

# maximum-size style case
s1 = "A" * 100
s2 = "a" * 100
assert run(f"{s1}\n{s2}\n") == "0\n", "maximum equal strings"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`a / b`|`-1`| 最小サイズの比較 |
 |`Z / a`|`1`| 正しい大文字の正規化 |
 |`Codeforces / codeforces`|`0`| 大文字と小文字を区別しない等価性 |
 |`abcz / abca`|`1`| 最終位置の差 |
 | 大文字と小文字が混合された 100 個の同一の文字 |`0`| 最大長の処理 |

```アルゴリズムは両方の文字列を小文字に変換します。```
abc
abc
```文字列は同一になるため、出力は次のようになります。```
0
```正規化を行わないと、ASCII 比較で大文字が誤って別の方法で扱われてしまいます。 

次に、最後の文字の不一致について考えてみましょう。 

入力：```

abcz
```変換後:```

abcz
```最初の 3 つの位置は一致します。 最終的な位置では、`'y' < 'z'`したがって、アルゴリズムは次のように出力します。```
-1
```これにより、最初の実際の違いが現れるまで比較が継続されることが確認されます。 

最後に、単一文字の文字列について考えてみましょう。 

入力：```
B
a
```小文字変換後:```
b
a
```以来`'b' > 'a'`の場合、出力は次のようになります。```
1
```これにより、最小入力サイズでもアルゴリズムが正しく動作することが検証されます。
