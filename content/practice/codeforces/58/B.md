 ## 解決策
 ## 問題の理解

 最大額面の硬貨の価値が与えられていますが、`n`。 すべての大きなコインがすべての小さなコインで割り切れるように、一連の個別のコインの値を構築する必要があります。 すべての有効なシーケンスの中で、可能な最大数のコインを含むシーケンスが必要です。 

出力には、額面を最大額から最小額までリストする必要があります。 

割り切れる条件により連鎖構造が形成されます。 コインが次の場合:```
a1 > a2 > a3 > ...
```その場合、以前の値はすべて、後の値で割り切れる必要があります。 特に：```
a1 % a2 == 0
a2 % a3 == 0
a1 % a3 == 0
```等々。 

限界はただ`10^6`、これは試行的な除算や繰り返しの因数演算には十分小さいです。 たとえ`O(sqrt(n))`このアルゴリズムは 2 秒以内で十分に高速です。 一方、すべてのサブセットまたはすべての除数チェーンを生成してチェックすると、組み合わせ論的に爆発するため、不要です。 

難しいのは、「コインの最大数」が実際に何を意味するのかを理解することです。 不注意な解決策は、から直接ジャンプしようとする可能性があります。`n`に`1`、しかしそれは中間約数を挿入する機会を無駄にします。 

たとえば:

 入力:```
12
```有効なシーケンスは次のとおりです。```
12 1
```しかしそれは最大ではありません。 さらに値を挿入できます。```
12 6 3 1
```Another common mistake is dividing by arbitrary divisors instead of the smallest possible prime factor. から始めるとしましょう`60`。 

積極的に分割すると:```
60 -> 10 -> 1
```コインは3枚しか得られません。 

If we remove factors one at a time:```
60 -> 30 -> 15 -> 5 -> 1
```チェーンが長くなります。 

The edge case`n = 1`誤った取り扱いもされやすいです。 これより小さい正の約数を追加することはできないため、答えは単純に次のようになります。```
1
```## アプローチ

 ブルートフォースアプローチでは、次のすべての約数を生成しようとします。`n`を選択し、その中で最も長い可分性連鎖を検索します。 Since every pair in the chain must divide correctly, we could sort divisors and run dynamic programming similar to longest increasing subsequence.

 これが機能するのは、可分性関係が半順序を形成するためです。 もし`a`分割する`b`、 それから`a`後に現れる可能性があります`b`シーケンスで。 

問題は、このアプローチでは必要以上に難しい問題を解決してしまうことです。 それでも`n ≤ 10^6`除数の数を管理しやすく保ちますが、すべてのチェーンと遷移を構築するのは依然として不必要な作業です。 

重要な観察は、コインの数を最大化するには、できるだけゆっくりと数を減らす必要があることを意味します。 

現在のコインが`x`。 次のコインは適切な約数でなければなりません`x`。 残っているステップ数を最大化するには、次の値をできるだけ大きくしながらも、次の値よりも小さくする必要があります。`x`。 

最善の策は、次の最小の素因数で割ることです。`x`。 

例えば：```
60 -> 30
```は以下よりも優れています:```
60 -> 20
```素因数を 1 つだけ削除すると、後でより多くの割り算ステップが保存されるためです。 

各演算では、数値の因数分解から 1 つの素因数だけが削除されます。 因数分解した数値なので```
n = p1^a1 * p2^a2 * ...
```正確に含まれています`a1 + a2 + ...`多重度をカウントする素因数。可能な限り長いチェーンは、到達するまで一度に 1 つずつ削除します。`1`。 

したがって、アルゴリズムは単純になります。 

から開始`n`。 最小の素因数で繰り返し除算し、各中間値を出力します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(d²) ここで、d は約数の数です | O(d) | 不必要に複雑 |
 | 最適 | O(sqrt(n)) | O(1) 出力を除く | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`。 
2. 現在の値を出力します。`n`順序は最大額面から開始する必要があるためです。 
3. その間`n`より大きい`1`、の最小の約数を見つけます`n`より大きい`1`。 

から探す`2`除数が見つかるまで上向きに進みます。 最初に見つかった約数は常に最小の素因数です。 
4. 分割`n`この最小の素因数によって計算されます。 

これにより、数値から素因数が 1 つだけ削除され、減少が可能な限り遅くなり、残りのチェーンの長さが最大化されます。 
5. の新しい値を出力します。`n`。 
6. まで繰り返します。`n`になる`1`。 

新しい値は整数係数で除算することによって取得されるため、すべてのステップで前の値を除算します。 割り算は推移的であるため、大きなコインはすべて、後続の小さなコインによって割り切れる可能性があります。 

### なぜ効果があるのか

 最長の連鎖は、素因数を一度に 1 つずつ削除することによって得られます。 

現在の番号があるとします。`x`。 次の値は次のようにする必要があります。```
x / d
```どこ`d`より大きい約数です`1`。 

もし`d`is composite, then removing it discards multiple prime factors at once. That shortens the possible chain because fewer intermediate divisors remain.

 Dividing by the smallest prime factor removes exactly one prime factor and keeps the next number as large as possible. Repeating this process guarantees that every prime factor contributes one extra coin to the sequence, which is the maximum achievable length.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

ans = []

while True:
    ans.append(str(n))

    if n == 1:
        break

    for d in range(2, int(n ** 0.5) + 1):
        if n % d == 0:
            n //= d
            break
    else:
        n = 1

print(" ".join(ans))
```このソリューションでは、現在の額面が維持されます。`n`そしてそれを回答シーケンスに繰り返し追加します。 

ループは印刷後にのみ停止します`1`、 以来`1`最後のコインとしても表示される必要があります。 

内側のループは、次から始まる最小の約数を検索します。`2`。 最初に見つかった約数が自動的に最小の素因数になります。 これで割ると、因数分解からちょうど 1 つの素因数が削除されます。 

の`else`に付属の`for`ループが重要です。 除数が見つからなかった場合にのみ実行されます。 つまり現在は`n`プライムです。 素数には適切な約数が 1 つだけあります。`1`したがって、次のステップは次のようになります。`1`。 

よくある間違いは、除算を開始する前に初期値を出力するのを忘れることです。 もう 1 つの簡単なバグは、次の場合にすぐに停止してしまうことです。`n`素数になると、最後の部分がスキップされます`1`。 

平方根境界により、除数検索の効率が維持されます。 以来`n`ステップごとに縮小するため、合計実行時間は非常に短いままです。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())

    ans = []

    while True:
        ans.append(str(n))

        if n == 1:
            break

        for d in range(2, int(n ** 0.5) + 1):
            if n % d == 0:
                n //= d
                break
        else:
            n = 1

    return " ".join(ans)

# provided sample
assert run("10\n") == "10 5 1", "sample 1"

# minimum value
assert run("1\n") == "1", "n = 1"

# prime number
assert run("13\n") == "13 1", "prime input"

# power of two
assert run("16\n") == "16 8 4 2 1", "repeated smallest factor"

# mixed prime factors
assert run("60\n") == "60 30 15 5 1", "multiple distinct factors"

# maximum bound style case
out = run("1000000\n")
assert out.startswith("1000000 "), "large input handled"
```| テスト入力 | 期待される出力 | 検証内容 |

```ここで素数を考えてみましょう。```

```除数検索では、次のすべての整数がチェックされます。`2`に`sqrt(13)`そして何も見つかりません。 の`for-else`分岐トリガー、次の値を設定`1`。 

シーケンスは次のようになります。```

```素数には 以外の約数がないため、これは最適です。`1`。 

最後に、多くの繰り返し因数を含む数値を考えてみましょう。```
