 ## 解決策
 ## 問題の理解

 正の整数の順序ペアが何組あるかを数えるように求められます。$(a, b)$最小公倍数と最大公約数を混合する単一の算術制約を満たします。 各テスト ケースについて、3 つの整数$c$、$d$、 そして$x$が与えられているので、正確に生成されるペアの数を数えなければなりません$c \cdot \mathrm{lcm}(a,b) - d \cdot \gcd(a,b) = x$。 

式の構造から、重要な問題はペアを直接列挙することではなく、その方法を理解することであることがわかります。$\gcd$そして$\mathrm{lcm}$交流する。 以来$\mathrm{lcm}(a,b)$そして$\gcd(a,b)$密結合しているため、単純な検索を行うと$a$そして$b$大きな値までは直ちに実行できなくなります。 両方を制限しても$\sqrt{x}$または同様の境界は役に立ちません。$\mathrm{lcm}$gcd 構造の変動が小さい場合でも、大きくなる可能性があります。 

制約により、最大で$10^4$値が最大のテスト ケース$10^7$。 二次関数または偶数$O(n \sqrt{n})$テストソリューションごとに失敗する可能性があります。 唯一の実行可能な方向は、問題を約数に依存するものに減らすことです。$x$またはテスト ケースごとの派生値。 

重要なエッジ状況が現れるのは、$x$小さいとき、または$c \cdot \mathrm{lcm}(a,b)$そして$d \cdot \gcd(a,b)$ほぼキャンセル。 たとえば、次の場合$c = d$そして$x = 0$、方程式は次のようになります$\mathrm{lcm}(a,b) = \gcd(a,b)$、強制的に$a = b$。 整数制約を強制せずに比率を操作しようとする単純なソルバーでは、非整数の組み合わせが誤って含まれたり、この縮退を完全に見逃したりする可能性があります。 

もう一つの微妙なケースは次のような場合です。$a$そして$b$は互いに素である。 それから$\gcd(a,b) = 1$そして$\mathrm{lcm}(a,b) = ab$なので、方程式は次のようになります。$c \cdot ab - d = x$、実現可能な製品が大幅に制限されます。 すべてのペアの反復を回避するには、直接因数分解アプローチが必要です。 

## アプローチ

 ブルートフォース戦略ではすべてのペアを試します$(a, b)$ある限界まで計算してください$\gcd$そして$\mathrm{lcm}$直接。 これは正しいですが、根本的には実行不可能です。 仮定しても$a, b \le 10^7$、検索空間は$10^{14}$、さらには$x$-依存境界では、テスト ケースごとに依然として多すぎる候補が残ります。 

重要な観察は、次の構造を分離することです。$\gcd$そして$\mathrm{lcm}$。 させて$g = \gcd(a,b)$、と書きます$a = g \cdot a'$、$b = g \cdot b'$と$\gcd(a', b') = 1$。 それから$\mathrm{lcm}(a,b) = g \cdot a' \cdot b'$。 方程式に代入すると次のようになります。$$c \cdot g a' b' - d \cdot g = x$$因数分解$g$:$$g (c a' b' - d) = x$$これにより、問題は構造化された約数列挙問題に変換されます。 考えられるそれぞれの gcd 値について$g$分割する$x$、方程式を次のように簡略化します。$$c a' b' - d = \frac{x}{g}$$または$$c a' b' = \frac{x}{g} + d$$したがって：$$a' b' = \frac{\frac{x}{g} + d}{c}$$これには 2 つの厳しい条件が課されます。 初め、$(x/g + d)$で割り切れる必要があります$c$。 次に、定義すると、$k = (x/g + d)/c$、互いに素な因数のペアの数を数えなければなりません$(a', b')$そのような$a' b' = k$。 

2 番目の部分は古典的なものです。$a'$そして$b'$は互いに素であり、その積は$k$、次にそれぞれの素因数$k$完全にどちらかの側に行かなければなりません。 これは、順序付けられた互いに素な因数のペアの数が次のとおりであることを意味します。$2^{\omega(k)}$、 どこ$\omega(k)$は、次の異なる素因数の数です。$k$。 

問題は、次の約数を反復することに帰着します。$x$、割り算チェックを実行し、約数を因数分解し、素数署名の 2 の累乗を累積します。

 ## アルゴリズムのチュートリアル

 1. すべての約数を反復処理します。$g$の$x$。 これが必要な理由は、$g$を表します$\gcd(a,b)$、左側の構造を分割する必要があります。 
2. それぞれについて$g$、計算する$t = x / g + d$。 これにより、gcd を因数分解した後に内部式が再構築されます。 
3. かどうかを確認します。$t$で割り切れます$c$。 そうでない場合は、これを破棄します$g$、整数のペアがないため$(a,b)$という方程式を満たすことができます。 
4. 定義する$k = t / c$。 これは製品を表します$a' b'$gcd スケーリングを削除した後。 
5. 要因$k$主要な分解に進みます。 それぞれの異なる素数は、要素間での因子の分配に独立して寄与します。$a'$そして$b'$。 
6. 順序付けられた互いに素な因数のペアの数を次のように計算します。$2^{\omega(k)}$、 どこ$\omega(k)$内の異なる素数の数です。$k$。 
7. この値を現在のテスト ケースの答えに追加します。 

### なぜ効果があるのか

 すべてのペア$(a,b)$gcd 部分に一意に分解できます$g$そして共素のペア$(a',b')$。 この分解は全単射であるため、ペアが 2 回カウントされたり、見逃されたりすることはありません。 という観点で書き直すと、$g$の場合、方程式は次の単一の値を強制します。$a'b'$。 共素性条件により、素因数が共有できないことが保証され、それぞれの異なる素数が二者択一で選択されます。$a'$または$b'$。 この独立性により、カウントが正確であることが保証されます。$2^{\omega(k)}$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# precompute primes up to 10^7 is too large per test, so we factor on demand using trial division up to sqrt

def factor_count_distinct(n):
    cnt = 0
    p = 2
    if n % p == 0:
        cnt += 1
        while n % p == 0:
            n //= p
    p = 3
    while p * p <= n:
        if n % p == 0:
            cnt += 1
            while n % p == 0:
                n //= p
        p += 2
    if n > 1:
        cnt += 1
    return cnt

t = int(input())
for _ in range(t):
    c, d, x = map(int, input().split())
    ans = 0

    g = 1
    while g * g <= x:
        if x % g == 0:
            for div in (g, x // g):
                tval = x // div + d
                if tval % c == 0:
                    k = tval // c
                    if k > 0:
                        cnt = factor_count_distinct(k)
                        ans += 1 << cnt
        g += 1

    print(ans)
```実装では約数を明示的に列挙します$g$の$x$それぞれを次の gcd の候補として扱います。$(a,b)$。 約数ごとに、必要な積を再構築します。$k$そして、次のように割り切れることを検証します。$c$。 因子カウント ルーチンは、次の要素にいくつの異なる素数が現れるかを計算します。$k$、これは有効な互いに素な順序の分割の数を直接決定します。 

除数の列挙には注意が必要です: 各除数のペア$(g, x/g)$テスト ケースごとに 1 回だけ処理する必要があります。 ビットシフト$1 << cnt$エンコードする$2^{\omega(k)}$、独立した素数割り当てに対応します。

 ## 特殊なケース

 エッジケースの 1 つが発生するのは、$k = 1$、つまり、共素積は強制的に 1 になります。この場合、両方とも$a'$そして$b'$は 1 でなければならないため、割り当ては 1 つだけになります。 アルゴリズムはこれを自然に処理します。$\omega(1) = 0$、 それで$2^{\omega(k)} = 1$。 たとえば、次の場合$c = 4$、$d = 2$、$x = 6$、そして除数は次のようになります$k = 1$、ちょうど 1 つのペアに寄与します。 

別の微妙なケースが発生する場合$x$プライムです。 次に、除数の列挙は次のものだけを生成します$g = 1$そして$g = x$。 各パスは有効な整数を生成します。$k$または割り算によって拒否されます。 このアルゴリズムは、各約数が独立して処理され、一意の gcd 分解にマップされ、ブランチ間で重複がないようにするため、過剰カウントを正しく回避します。
