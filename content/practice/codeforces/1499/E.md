 ## 解決策
 ## 問題の理解

 2 つの文字列が与えられ、それぞれの文字列から部分文字列を取り出し、各部分文字列内の内部順序を維持しながら文字をインターリーブすることを想像します。 インターリーブはバイナリ シーケンスによって制御されます。0 は最初の文字列の選択された部分文字列から次の文字を取得することを意味し、1 は 2 番目の文字列の選択された部分文字列から取得することを意味します。 このようなバイナリ シーケンスはすべて、選択された 2 つの部分文字列の前の文字を消費することによって、マージされた文字列を生成します。 

マージされた文字列は、交互している場合、つまり隣接する 2 つの文字が等しくない場合にのみ有効とみなされます。 このタスクは、固定された部分文字列ペアの有効なマージをカウントするだけではなく、空ではないすべての可能な部分文字列ペアのカウントを合計することです。 

両方の文字列の長さが最大 ​​1000 であるという制約がキー信号です。 すべての部分文字列ペアを直接列挙すると、すでに約$10^6$ペアごとに、単純なマージには指数関数的または組み合わせ的な動作が含まれます。 動的プログラミングを使用して各ペアを個別に処理しようとするソリューションでも、各ペアがほぼ一定時間または対数時間で処理されない限り、制限時間を超える可能性があります。 これにより、ペアごとの計算ではなく、グローバルなカウントの観点に進むことができます。 

単純な考えを簡単に打ち破る微妙な点は、有効性の条件が、より深い構造ではなく、_これまでに選択された最後に選択された文字_のみに依存するということです。 たとえば、部分文字列を選択すると、`"aa"`そして`"b"`の場合、同じ文字列内の繰り返し文字が順序に応じてマージ内に連続して表示されるため、多くのインターリーブは直ちに無効になります。 不注意なアプローチでは、すべてのマージをマルチセットの順列として処理しようとする可能性がありますが、各部分文字列の内部順序は固定されているため、これは正しくありません。 

もう 1 つのエッジ ケースは、両方の部分文字列に繰り返し文字が含まれている場合でも、慎重に交互に行えば有効なマージが行われる可能性があることです。 例えば、`"aa"`そして`"bb"`次のような交互シーケンスも引き続き許可されます`0101`または`1010`ただし、長さが適切に一致する場合に限ります。 これは、実現可能性が単にカウントの組み合わせによるものではなく、順序付けの制約に依存することを示しています。 

## アプローチ

 ブルートフォースアプローチは部分文字列を修正することから始まります$x[l_1,r_1]$そして$y[l_2,r_2]$。 このようなペアごとに、次の長さのバイナリ シーケンスをすべて試します。$(r_1-l_1+1) + (r_2-l_2+1)$マージをシミュレートし、結果の文字列が交互になっているかどうかを確認します。 これはすでに与えられています$2^{a+b}$これは完全に不可能です。 

最初の改善点は、シーケンスの有効性が隣接する選択された文字が等しいかどうかのみに依存することに気づくことです。 したがって、各部分文字列のペアに対して動的プログラミングを試みることができます: 各文字列から取得された文字数と最後に取得された文字に関する dp 。 これにより、指数係数が 1 つ減少しますが、それでも次のような結果が得られます。$O(n^4)$すべての部分文字列ペアにわたる状態は次のとおりです。$O(n^2)$文字列ごとの部分文字列。 

重要な構造上の観察は、部分文字列の単一のペアについて質問されていないことです。 すべてのペアを合計するように求められます。 これは、文字が出現するすべてのことを意味します。$x$の文字が出現するたびに相互作用します。$y$、そしてそれ自体を異なる部分文字列コンテキストで使用することもできます。 これは視点を反転することを示唆しています。部分文字列を固定する代わりに、最終的なマージで位置を固定し、それが実現できる方法が何通りあるかを数えてください。 

カオス的マージでは、最終的な文字列が強制的に代替文字になります。 つまり、文字は厳密に交互に配置されるため、マージされた文字列はその開始文字とソース選択の順序によって完全に決定されます。 したがって、唯一の本当の制約は、次から文字を選択できるかどうかです。$x$そして$y$交互を尊重しながら、相対インデックスと一致する順序で。 

これにより、開始位置のすべてのペアについて再定式化が行われます。$(i, j)$、交互インターリーブが何回開始できるかを数えます。$x[i]$そして$y[j]$、そして、交互を維持し、部分文字列の境界を使い果たさない限り延長します。 すべての部分文字列の合計は、すべての可能な開始制約と終了制約の合計となり、実行と遷移のプレフィックスベースのカウントで処理できます。 

中心的な単純化は、有効性が同じ文字の連続にのみ依存することです。$x$そして$y$。 文字が選択されると、代替が必要な場合は、次の強制選択は他の文字列から行われる必要があり、実現可能性は、インデックスの増加が有効な範囲内にあるかどうかを確認することになります。 

これにより、単調な制約を持つ位置のグリッド上の交互のパスをカウントするという問題が軽減されます。これは、インデックスと文字状態に対する動的プログラミングを使用して計算できます。

 ## アルゴリズムのチュートリアル

 部分文字列ペアを明示的に合計するのではなく、有効な交互マージを構築するすべての方法からの寄与をカウントする定式化に切り替えます。 

1. 1 対の位置で交互マージを終了できる方法が何通りあるかを追跡する DP 状態を定義します。$(i, j)$、最後に取得された文字は次のいずれかから来ました。$x[i]$または$y[j]$。 これは、構造と有効性の両方を単一の状態でエンコードします。 
2. すべての有効な開始選択肢に対して DP を初期化します。 すべてのペア$(i, j)$マージを開始する場所によって、考えられる 2 つの初期状態が決まります。$x[i]$またはから始まる$y[j]$代替（最初の文字は空です）に違反しない限り。 
3.最後の文字が来た状態から$x[i]$、次の文字は次の文字から来なければなりません$y[j']$そのような$j' > j$、文字は次のものとは異なる必要があります$x[i]$。 これにより、部分文字列の順序と代替制約の両方が保証されます。 
4. 同様に、末尾が「」の状態から、$y[j]$、ポジションに移行します$i' > i$で$x$、やはり性格の不平等が必要です。 
5. すべての遷移を素朴に反復する代わりに、両方の文字列内の各文字の次の出現を事前計算します。 これにより、次の有効なインデックスに効率的にジャンプできるようになり、遷移では有効な代替拡張のみが考慮されるようになります。 
6. 各状態は、一部の部分文字列ペアに対する有効な交互マージに対応するため、各 DP 状態の寄与を最終的な答えに累積します。 

### なぜ効果があるのか

 DP は厳密な不変条件を維持します。つまり、すべての状態が現在のエンドポイントまで有効なマージを表し、最後の文字が明示的に追跡されるため、無効な隣接関係が導入されることはありません。 単調なインデックスの移動により、各文字列内で最初と最後に使用される位置を固定すると、部分文字列が一意に決定されるため、各マージが正確に 1 組の部分文字列に対応することが保証されます。 これにより、過剰なカウントが防止され、すべての有効なマージ シーケンスが最終状態に達したときに正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    x = input().strip()
    y = input().strip()
    n, m = len(x), len(y)

    # next occurrence arrays
    nxtx = [[n] * 26 for _ in range(n + 1)]
    nxty = [[m] * 26 for _ in range(m + 1)]

    for c in range(26):
        nxtx[n][c] = n
        nxty[m][c] = m

    for i in range(n - 1, -1, -1):
        for c in range(26):
            nxtx[i][c] = nxtx[i + 1][c]
        nxtx[i][ord(x[i]) - 97] = i

    for j in range(m - 1, -1, -1):
        for c in range(26):
            nxty[j][c] = nxty[j + 1][c]
        nxty[j][ord(y[j]) - 97] = j

    # dp[i][j][t]: number of ways ending at i,j, last taken from t (0=x,1=y)
    dp = [[[0, 0] for _ in range(m + 1)] for __ in range(n + 1)]

    ans = 0

    # initialize: start from any pair
    for i in range(n):
        for j in range(m):
            dp[i][j][0] = 1
            dp[i][j][1] = 1
            ans += 2

    ans %= MOD

    # transitions
    for i in range(n):
        for j in range(m):
            for t in range(2):
                cur = dp[i][j][t]
                if not cur:
                    continue

                if t == 0:
                    # last from x[i], go to y
                    c = ord(x[i]) - 97
                    j2 = nxty[j + 1][c]
                    if j2 < m:
                        dp[i][j2][1] = (dp[i][j2][1] + cur) % MOD
                        ans = (ans + cur) % MOD
                else:
                    # last from y[j], go to x
                    c = ord(y[j]) - 97
                    i2 = nxtx[i + 1][c]
                    if i2 < n:
                        dp[i2][j][0] = (dp[i2][j][0] + cur) % MOD
                        ans = (ans + cur) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```このソリューションは、いずれかの文字列内の次の文字へのジャンプを可能にするヘルパー テーブルを構築します。 これにより、すべての遷移に対して線形に順方向にスキャンすることが回避されます。 DP テーブルは、現在の位置と最後の文字を提供した文字列の両方をエンコードします。これは、変更が位置だけでなく前の選択に依存するため必要です。 

実装の微妙な詳細は、すべての DP 状態が部分文字列ペアの寄与の有効な開始として扱われることです。 これが、初期化によって両方の方向が均等に追加される理由です。 もう 1 つの重要な詳細は、遷移は常にインデックス内で前方に移動することです。これにより、部分文字列のエンドポイントは最初と最後に訪問した位置によって暗黙的に定義されるため、各部分文字列のペアが 1 回カウントされることが保証されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、両方の文字列が同じ繰り返し文字で構成されている場合です。`"aaa"`そして`"aaa"`。 この場合、すべての遷移が同じ文字を繰り返して制約に違反するため、単一ステップを超えて変更することは不可能です。 同じ文字の次の出現は依然として存在しますが、代替を中断することなく使用することはできないため、DP は当然、さらなる遷移を防ぎます。 

もう 1 つの特殊なケースは、一方の文字列が他方の文字列よりもはるかに長い場合です。 例えば`"aaaaa"`そして`"b"`。 ここで、有効なマージはすべて、短い文字列が使い果たされるまで厳密に交互に実行する必要があり、それ以降は拡張が不可能になります。 一方の側に有効な次のインデックスがなくなると遷移が停止し、より長い部分文字列からのオーバーカウントが確実になくなるため、DP はこれを正しくキャプチャします。
