 ## 解決策
 ## 問題の理解

 グリッドの左下隅から右上隅まで単調なパスを構築していますが、このパスは単なる単位ステップの単純なシーケンスではありません。 代わりに、それは少数の直線セグメントで構成されており、各セグメントは完全に右または完全に上に進み、連続するセグメントは方向を変える必要があります。 

各セグメントには 2 つの独立した選択肢があります。1 つは正の整数である長さ、もう 1 つはリスト c として事前に与えられるコスト係数です。 セグメントの長さが L で係数 c_i を使用する場合、総コストへの寄与は c_i に L を乗算したものになります。パスは合計で右にちょうど n ユニット、上に合計でちょうど n ユニット移動する必要があるため、水平セグメントの長さの合計は n で、垂直セグメントの長さの合計も n になります。 

目標は、使用するセグメントの数、それらを交互に配置する方法、および加重合計コストを最小限に抑えるためにセグメント全体に長さを分散する方法を選択することです。 

セグメントの数が最大 n 個であるという制約は、難しい部分ではありません。 実際の構造は、セグメント i が水平セグメントになるか垂直セグメントになるかに関係なく、常に係数 c_i を順番に使用するという事実から来ています。 これは、係数を方向に恣意的に割り当てているのではなく、係数の固定シーケンスに方向を割り当ててから、長さを分配する方法を選択していることを意味します。 

入力サイズでは、最大 1000 のテスト ケースと合計 100000 の係数が許可されます。 考えられるすべてのセグメント分割を試行したり、二次時間でコストを再計算したりするソリューションは失敗するため、ソリューションはテスト ケースごとに線形時間で答えを計算する必要があります。 

単純な考えは、シーケンスをセグメントに分割し、長さを割り当てるあらゆる方法を試してみることです。 これは、分割する場所を選択するだけでもすでに指数関数的に多くの構成が必要になるため、失敗します。 

さらに微妙な失敗例は、先を見ずに貪欲にセグメントを拡張しようとした場合に発生します。 係数が小さい場合は常に現在のセグメントを長くすると、将来のセグメントが長い距離を割り当てられることでより多くのメリットが得られる場合でも、係数がさらに小さい将来のセグメントが大きな長さを取得することがブロックされる可能性があります。 

## アプローチ

 直接的な強引な解釈は、セグメント k の数を選択し、開始方向を選択し、次に水平方向と垂直方向の動きを正しく合計する正の整数としてすべてのセグメントの長さを選択することです。 各構成の計算コストは​​単純です。 n 個のユニットを k 個の正の部分に分割する方法の数は組み合わせによって増加し、すべての k を合計すると、n が小さい場合でもこれは完全に不可能になります。 

重要な観察は、係数のシーケンスが固定されると、問題となる唯一の自由は、合計水平距離 n と合計垂直距離 n が奇数および偶数のインデックス付きセグメントにどのように分散されるかということです。 水平方向または垂直方向のどちらの動きから開始するかに応じて、奇数のインデックスが付いたすべてのセグメントが 1 つの軸に寄与し、偶数のインデックスが付いたすべてのセグメントがもう一方の軸に寄与します。 

これにより、問題はリソース割り当ての問題に変換されます。 固定数のセグメント k の場合、奇数の位置は ceil(k/2) セグメントに分割された n の合計長バジェットを持ち、偶数の位置は Floor(k/2) と同じ構造になります。 コストはセグメント長に対して線形であるため、各パリティ グループ内では、最初にすべてのセグメントに長さ 1 を与え、その後、残りのすべての長さをそのグループ内で最小の係数を持つセグメントに分配することが常に最適です。

したがって、任意の固定 k について、k までの奇数および偶数の位置での最小係数がわかれば、最適な構造は決定的になります。 残りの課題は、最適な k を効率的に計算することです。これは、プレフィックスの合計とプレフィックスの最小値を維持しながら、k を 1 から n までスキャンすることで実行できます。

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、考えられるすべての数のセグメント k を試して答えを計算します。 

1. 係数配列に対してプレフィックス情報を事前計算します。 奇数インデックスと偶数インデックスのプレフィックス合計を別々に維持し、奇数位置と偶数位置でこれまでに確認された最小係数も追跡します。 これにより、任意のプレフィックス長 k を定数時間で評価できるようになります。 
2. 1 から n までの考えられる k ごとに、最初の k 係数を k セグメントを定義するものとして解釈します。 シーケンス内の位置に応じて、奇数のインデックスが付いたグループと偶数のインデックスが付いたグループに分割します。 
3. パスが水平セグメントで始まる場合を考えてみましょう。 この場合、奇数のインデックスが付いたセグメントは水平移動に対応し、偶数のインデックスが付いたセグメントは垂直移動に対応します。 
4. この構成では、各セグメントの単位長を乗算したすべての係数の合計として基本コストを計算します。 次に、余分な長さの配分を考慮します。合計の水平距離は n なので、各水平セグメントの長さを 1 に指定した後、残りの長さを水平セグメント間で配分する必要があります。 この余分なコストは、残りの水平長すべてを水平セグメントの中で最小の係数に割り当てることによって最小限に抑えられます。 同じロジックが垂直セグメントにも適用されます。 
5. パスが垂直に始まる場合にも同じ計算を繰り返します。これにより、奇数位置と偶数位置の役割が入れ替わります。 
6. すべての k および両方の開始方向の最小値を取得します。 

この正しさは、任意の固定 k および固定開始方向について、問題が 2 つのグループにわたる 2 つの独立した線形コスト最適化に分解されるという事実から得られます。 各グループ内では、コストは長さが線形であり、固定和制約による場合を除いてセグメント間に相互作用がないため、余分な長さをすべて最小係数に集中させることが常に最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        c = list(map(int, input().split()))

        # prefix sums and minima for odd/even indices
        odd_sum = [0] * (n + 1)
        even_sum = [0] * (n + 1)
        odd_min = [10**18] * (n + 1)
        even_min = [10**18] * (n + 1)

        for i in range(1, n + 1):
            val = c[i - 1]

            odd_sum[i] = odd_sum[i - 1]
            even_sum[i] = even_sum[i - 1]
            odd_min[i] = odd_min[i - 1]
            even_min[i] = even_min[i - 1]

            if i % 2 == 1:
                odd_sum[i] += val
                odd_min[i] = min(odd_min[i], val)
            else:
                even_sum[i] += val
                even_min[i] = min(even_min[i], val)

        ans = 10**30

        for k in range(1, n + 1):
            odd_cnt = (k + 1) // 2
            even_cnt = k // 2

            # start horizontal: odd -> H, even -> V
            h_cost = odd_sum[k] + (n - odd_cnt) * odd_min[k]
            v_cost = even_sum[k] + (n - even_cnt) * even_min[k]
            ans = min(ans, h_cost + v_cost)

            # start vertical: swap roles
            h_cost = even_sum[k] + (n - even_cnt) * even_min[k]
            v_cost = odd_sum[k] + (n - odd_cnt) * odd_min[k]
            ans = min(ans, h_cost + v_cost)

        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、任意のプレフィックス長 k を定数時間で評価できるように、奇数位置と偶数位置のプレフィックス情報が分離されます。 唯一の微妙な点は、各パリティ クラスに属するセグメントの数を正確に計算することです。これにより、残りの長さをどれだけ分散する必要があるかが決まります。 

2 つの方向のケースは、どのパリティが水平方向の動きに対応するかを交換することによって対称的に処理されます。 

## 実用的な例

 2 番目のサンプル入力、係数 [2, 3, 1] を持つ n = 3 を考えてみましょう。 

プレフィックス データを計算します。 

| k | 奇数合計 | 偶数合計 | 奇数分 | 偶数分 | 奇数cnt | 偶数cnt |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 2 | 0 | 2 | インフ | 1 | 0 |
 | 2 | 2 | 3 | 2 | 3 | 1 | 1 |
 | 3 | 3 | 3 | 1 | 3 | 2 | 1 |

 k = 3 で水平方向に開始する場合、奇数のセグメントは水平方向、偶数のセグメントは垂直方向になります。 水平方向の基本コストは 3、垂直方向の基本コストは 3 です。残りの水平方向の長さは 3 - 2 = 1 で、最小奇数の 1 に割り当てられ、残りの垂直方向の長さは 3 - 1 = 2 で最小偶数の 3 に割り当てられます。これにより、合計は 3 + 3 + 1 + 6 = 13 となります。 

このトレースは、最適解が残りの長さを拡散するのではなく、各パリティ グループの最小係数にどのように集中させるかを示しています。 

ここで、係数が減少する場合を考えてみましょう: [5, 4, 3, 2]。 アルゴリズムはすべてのプレフィックスを評価し、後の係数が小さいほど余分な長さを割り当てるコストが削減されるため、最適なソリューションは長いプレフィックスを使用する方向に移行します。これは、プレフィックスの最小項によって捕捉されます。

 ## 特殊なケース

 微妙なケースの 1 つは、最適解が一方向グループ内の 1 つのセグメントのみを使用する場合です。これは、ほぼすべての長さが 1 つの係数に割り当てられることを意味します。 [10, 1, 10, 1] のような入力の場合、アルゴリズムは、各パリティ クラスの最小係数の寄与を最大化することが最良の選択であることを自然に認識します。 プレフィックスの最小値により、1 が出現すると、それ以降のすべてのプレフィックスが残りの長さのほとんどを吸収できることが確実に反映されます。 

もう 1 つのエッジ ケースは、初期の係数は小さいが、後の係数はさらに小さい場合です。 [3, 1, 2, 0.5] の場合、プレフィックス スキャンにより、0.5 が表示されるポイントを超えて拡張する k が最小更新であるため、実効コストが即座に減少することが保証され、アルゴリズムは再計算やバックトラッキングを必要とせず、それに応じて重み分布をシフトします。
