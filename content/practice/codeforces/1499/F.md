 ## 解決策
 ## 問題の理解

 私たちは、最初からすべてのエッジが存在するツリーを扱っています。 エッジのサブセットを削除することができます。これにより、ツリーがいくつかの接続されたコンポーネントに分割されます。 結果として得られる各コンポーネントは依然としてツリーです。 

強制する必要がある条件は、結果として得られる各コンポーネントに対してローカルです。つまり、すべてのコンポーネントの直径が固定値を超えてはなりません。`k`。 ここでの直径は、そのコンポーネント内の 2 つの頂点間の最長の最短経路を意味します。 

課題は、エッジを除去する 1 つの有効な方法を構築することではなく、「小径」コンポーネントのみを生成するエッジの異なるサブセットがいくつあるかを数えることです。 すべてのエッジは独立して残るか切断されますが、結果として得られるパーティションは、接続されたすべてのピースの直径制約を満たさなければなりません。 

ツリーのサイズは最大 5000 ノードになります。 これにより、エッジ サブセットを直接列挙するソリューションは除外されます。`2^(n-1)`可能性。 サブセットごとに直径を素朴に再計算しようとするアプローチであっても、実現可能性をはるかに超えています。 

重要な点は、エッジを切断しても、そのエッジにのみ局所的な制約が課されるわけではないということです。 単一のカットによりコンポーネントの構造がグローバルに変更され、直径はコンポーネントのグローバルなプロパティです。 これが、問題を局所的な組み合わせ論ではなく本質的にツリー DP にする理由です。 

よくある失敗例は、各エッジが局所的な深さに基づいて独立して決定できると想定している場合です。 たとえば、スター ツリーでは、スポークを切断または保持すると、局所的ではない方法で直径に影響します。2 本の長い枝を一緒に保持すると、それぞれの枝だけでは問題ない場合でも、直径の制約に違反する可能性があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。エッジのすべてのサブセットを反復処理し、結果として得られるフォレストを構築し、2 つの BFS または DFS パスを使用して各コンポーネントの直径を計算し、すべてのコンポーネントが境界を満たしているかどうかを確認します。 これは、定義を直接適用するため、正しいです。 ただし、サブセットの数は指数関数的です。`n`、各検証にはツリー サイズの線形時間がかかり、おおよそ次のようになります。`O(2^n * n)`すぐに崩壊する行動`n = 5000`。 

重要な観察は、制約がコンポーネント内部の直径に関するものであるということです。これは、ルート化されたサブツリー内で 2 つの「アクティブな境界端点」が互いにどれだけ離れていてもよいかという観点から言い換えることができます。 どのエッジがカットされるかという観点から考えるのではなく、視点を反転します。つまり、ツリーを根付けてボトムアップで処理し、直径の制限に違反することなく情報が上にどこまで伝播できるかを維持します。 

親を介して 2 つの子サブツリーを結合する場合、違反が発生する唯一の方法は、異なる子からの 2 つの最も深いパスが一致して長さを超えた場合です。`k`。 これにより、問題は、ノードを通じて共存できる「オープン パス状態」の数を管理することになります。 

各ノードで、上向きに通過するすべての部分パスの長さが最大になるように子構成をマージできる方法が何通りあるかを効率的に数えています。`k`、ノードを介してマージされた 2 つのパスは次を超えません。`k`組み合わせると。 これにより、各サブツリーが考えられる「深さプロファイル」の分布に寄与する DP が得られ、深さに関するナップザックのような畳み込みを使用してそれらを結合し、以下に基づいて枝刈りを行います。`k`。 

重要な構造の簡素化は、ノードごとに、そのサブツリーが指定された長さ以上に上向きの「単一のアクティブ パス」を生成できる方法の数を追跡するだけでよいことです。 直径を侵害する可能性のある 2 つの独立した長いアームを作成する構成は、マージ時に許可されません。 これにより、問題は状態サイズが制限されたツリー DP に変換されます。`O(k)`ノードごとに。

 | ツリー DP (深度マージ) | O(n · k^2) | O(n · k) | 承認済み |

 ## アルゴリズムのチュートリアル

 ノード 1 でツリーをルートします。各ノードの DP は、単一の「上向きパス長」をその親に公開しながら、サブツリーを構造化できる有効な方法がいくつあるかを記述します。 

私たちは定義します`dp[u][d]`サブツリーのウェイの数として`u`からのアクティブなパスが 1 つだけ存在するようにします。`u`親に向かって上向きに進み、このパスには長さがあります`d`。 ケース`d = -1`概念的には、パスが上に渡されないことを表します (すべてのコンポーネントがサブツリー内で閉じられています)。 

### ステップ

 1. ノード 1 でツリーを任意にルートし、DFS を使用して子リストを計算します。 
2. 各ノードでの DP の初期化`u`サブツリーにのみ含まれる基本状態を持つ`u`。 これは、空の状態に対応する、上向きのパスが必要ない 1 つの構成に貢献します。 
3. 子を 1 つずつ処理し、その DP テーブルを現在のノードにマージします。 

子を結合するとき`v`の中へ`u`、私たちは 2 つの可能性を検討します: エッジをカットするか`(u, v)`、この場合、`v`内部に留まり、閉じたコンポーネントとして寄与するか、エッジを維持します。この場合、上向きのパスは`v`～まで広がる可能性があります`u`。 

切断は治療に相当します`v`のサブツリーを独立して計算し、カウントを直接乗算します。 維持することは、パスの長さを 1 増やすことに相当します。 
4. マージ中、状態のペアごとに`(du, dv)`現在のノードと子を接続すると、結果のパスの長さは次のようになります。`dv + 1`。 複数の子を結合するときは、次の位置で交わる 2 つの上向きパスが存在することを確認する必要があります。`u`を超えないでください`k`。 これにより、2 つの最大の露出深度の組み合わせは次のとおりであるという制約が課されます。`u`満たさなければなりません`d1 + d2 <= k`。 
5. これを効率的に実施するために、新しい DP 状態の一時配列を維持します。 各子について、最初に深さをシフトすることによって「キープエッジ」寄与を計算し、次に無効な組み合わせを削除しながら、既存のすべての深さの畳み込みを使用してマージします。 
6. すべての子を処理した後、ルートにはパスを渡す親がないため、ルートの DP がすべての有効な状態にわたって合計されます。 

### なぜ効果があるのか

 DP の不変条件は、ルートとなるサブツリーを処理した後、`u`、すべての構成がカウントされます`dp[u]`は、そのサブツリー内の有効なフォレストと、その境界を横切る部分的に開いたすべてのパスを表します。`u`単一の長さの値によって完全に特徴付けられます。 直径違反は 2 つのパスが交わる最下位の共通祖先で発生する必要があり、DP は明示的に`k`すべてのマージ ポイントで制約を適用し、そのような違反が形成されるのを防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
sys.setrecursionlimit(10**7)

def solve():
    n, k = map(int, input().split())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    # dp[u] is list where dp[u][d] = ways, d is upward path length
    # we also allow "no open path" as empty list entry handled separately
    def dfs(u, p):
        dp = [0] * (k + 1)
        dp[0] = 1  # no open path from u initially

        for v in g[u]:
            if v == p:
                continue
            child = dfs(v, u)

            newdp = [0] * (k + 1)

            for du in range(k + 1):
                if dp[du] == 0:
                    continue

                # case 1: cut edge u-v, child becomes independent
                # multiply by sum of all child internal configurations
                cut_sum = sum(child) % MOD

                for dv in range(k + 1):
                    # case 2: keep edge and extend path
                    if dv + 1 <= k:
                        if du + dv + 1 <= k:
                            newdp[max(du, dv + 1)] = (newdp[max(du, dv + 1)] +
                                                      dp[du] * child[dv]) % MOD

                # add cut contribution
                newdp[du] = (newdp[du] + dp[du] * cut_sum) % MOD

            dp = newdp

        return dp

    root = dfs(0, -1)
    print(sum(root) % MOD)

if __name__ == "__main__":
    solve()
```実装は DP のアイデアに直接準拠しています。 配列`dp[u]`未解決のパスがどこまで上向きに伸びるかを追跡します。`u`。 マージ ステップでは、各子エッジをカットするか保持するかを慎重に検討します。 切断は、子サブツリーのすべての有効な内部構成に等しい乗算係数に寄与しますが、単一のパスを上方に延長する試みを維持し、2 つのパスが次の位置で交わる場合に直径の制約を強制します。`u`。 

微妙な部分はコンディションです`du + dv + 1 <= k`、これは、下からのパスが 1 つある場合、という事実をエンコードします。`u`長さがある`du`そして子供を通じての別の貢献も貢献します`dv + 1`、それらの組み合わせは`u`許容直径を超えてはなりません。 DP は、この制約がすべてのマージ ポイントで強制されることを保証します。これは、グローバルな有効性を保証するのに十分です。

 ## 特殊なケース

 主なエッジケースは次のような場合です`k = 0`。 この場合、すべてのコンポーネントの直径はゼロである必要があります。つまり、すべてのコンポーネントは単一の頂点のみであることができます。 保持されたエッジは、直ちにサイズ 2 以上のコンポーネントを作成し、制約に違反します。 パスを延長する遷移は少なくとも 1 の長さを持ち、破棄され、すべてのエッジがカットされた構成のみが残るため、DP はこれを自然に処理します。 

もう 1 つのエッジ ケースは、大きな星形グラフです。`k`。 ここでは、複数の子サブツリーがルートでマージされ、DP は 2 つの上向きパスが結合して次の値を超えないようにする必要があります。`k`。 各リーフは深さ 0 を提供するため、組み合わせは安全であり、DP はすべてを正確にカウントします。`2^(n-1)`サブセット。 

最後の微妙なケースは次のような場合です。`k`に近いです`n-1`、本質的に制約がバインドされません。 DP は引き続き正しく動作します。`du + dv + 1 <= k`は常に満たされ、エッジ上の独立した乗算への遷移が減少し、完全なサブセット数と一致します。
