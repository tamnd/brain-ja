 ## 解決策
 ## 問題の理解

 同じパーティー内に複数の敵がいる馬がないように、馬のグループを 2 つのパーティーに分割するように求められます。 入力には馬の数がリストされます`n`そして多数の敵ペア`m`、 に続く`m`相互の敵意を示す馬のインデックスのペア。 出力では、各馬を 0 と 1 の文字列として表される 2 つのパーティのいずれかに割り当てる必要があります。有効なパーティションが存在しない場合は -1 を返します。 

重要な制約は、各馬に最大 3 人の敵がいることです。 これにより、競合グラフの構造が大幅に制限されます。 敵が 3 人を超える馬はないため、グラフのすべての接続コンポーネントの次数は非常に限られており、これによって任意に複雑なサイクルが回避され、グラフ全体ではなく小さな局所的なパターンについて推論できるようになります。 

不注意なアプローチでは、これを標準的なグラフの二分割問題として扱おうとする可能性があります。 単純な二分割では、馬は同じセット内の他の馬に隣接することはできません。 ただし、ここでは馬のパーティーに 1 人の敵を含めることができます。 たとえば、相互に敵意を持つ 3 頭の馬の三角形は次のように分割できます。`[0,0,1]`または`[1,0,0]`しかし、単純な二分割ではそれは不可能であると誤って結論付けてしまいます。 もう 1 つの微妙な点は、コンポーネントが切断されていることです。コンポーネント内の 1 つのパーティが他のパーティに影響を与えずに空になる可能性があるため、それぞれを独立して処理する必要があります。 

## アプローチ

 強引なアプローチでは、2 つのパーティへの可能な限りの馬の割り当てを試し、各馬のパーティに最大 1 頭の敵がいるかどうかを確認します。 がある$2^n$明らかに実行不可能な割り当て$n$まで$10^5$。 

重要な洞察は、次数の制約から得られます。各馬には最大 3 人の敵がいます。 これは、敵のグラフの連結コンポーネントが非常に小さいことを意味します。各連結コンポーネントは、1 頭の馬、馬の鎖、三角形、「Y」字形、または 1 つの余分なエッジを持つ 4 サイクルのいずれかです。 このような低次数のグラフでは、コンポーネントの有効な色をすべて効率的に列挙できます。 各コンポーネントについて、馬に再帰的に 0/1 の値を割り当て、同じ色の隣の馬が複数になる馬がないことを確認します。 矛盾が生じた場合、私たちは後戻りします。 これは本質的に枝刈りを伴う DFS ですが、次数が限られているため、実際には再帰が指数関数的になることはありません。 

別の方法は、各コンポーネントをそのトポロジによって分類することです。ノードの次数が 3 の場合、どの馬にも複数の同じパーティの敵が存在しないように、その 3 つの隣接ノードを反対側のパーティに割り当てる必要があります。 最大次数は 3 であるため、コンポーネントごとに有効なパターンはわずかしかありません。 コンポーネントごとにすべてのパターンを試し、結果を結合することで、完全なソリューションを構築できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n + m) | 遅すぎる |
 | DFS / コンポーネントごとのバックトラッキング | O(n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各馬が敵を指すグラフの隣接リストを作成します。 
2. 配列を初期化する`party`サイズの`n`すべての値が -1 に設定され、割り当てられていない馬を表します。 
3. すべての馬を反復処理します。 馬が割り当てられていない場合は、その馬から DFS を開始して、接続されているコンポーネント内のパーティを割り当てます。 
4. DFS で、現在の馬をパーティ 0 に割り当ててみます。各隣接者について、その隣接者の何人の隣接者が既にパーティ 0 に存在するかを数えます。0 を割り当てると隣接者に複数の同じパーティの敵が与えられる場合は、バックトラックしてパーティ 1 を試します。これを再帰的に繰り返します。 
5. パーティ 0 とパーティ 1 の両方がノードで失敗した場合、コンポーネントを不可能としてマークし、-1 を返します。 
6. すべての馬が競合せずに割り当てられた場合、パーティー配列を 0 と 1 の文字列として出力します。 

これが機能する理由: 不変条件は、これまで処理されたすべての馬には同じパーティの敵が最大 1 人しかいないということです。 各再帰ステップでは、このプロパティが保持されます。 各ノードには最大でも 3 つの隣接ノードがあるため、DFS 内のすべての有効な割り当てをチェックしても組み合わせが爆発的に行われることはありません。 ノードに割り当てが機能しない場合は、条件を満たすことができないため、-1 を返すのが正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n)]
    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        adj[a].append(b)
        adj[b].append(a)

    party = [-1] * n

    def dfs(u):
        if party[u] != -1:
            return True
        for val in [0, 1]:
            party[u] = val
            valid = True
            for v in adj[u]:
                if party[v] == val:
                    count = sum(1 for w in adj[v] if party[w] == val)
                    if count >= 1:
                        valid = False
                        break
            if not valid:
                party[u] = -1
                continue
            for v in adj[u]:
                if party[v] == -1 and not dfs(v):
                    valid = False
                    break
            if valid:
                return True
            party[u] = -1
        return False

    for i in range(n):
        if party[i] == -1 and not dfs(i):
            print(-1)
            return
    print("".join(map(str, party)))

if __name__ == "__main__":
    solve()
```隣接リストは敵を効率的に格納します。 DFS は、割り当てられていない馬ごとに双方の割り当てを試みます。 有効性をチェックするときは、同じパーティ内の隣接パーティの数をカウントし、それが 1 を超えないようにします。 リセットします`party[u] = -1`後戻りするとき。 最上位のループは、切断されたコンポーネントを処理します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各馬には最大 3 つの隣接馬がいます。 DFS は各エッジを 1 回ずつ探索します。 
| スペース | O(n + m) | 隣接リスト + パーティ配列 |

 再帰の深さは次のように制限されます。`n`、各 DFS 呼び出しは最大 3 つのネイバーを処理します。 アルゴリズムは 2 秒および 256MB 以内に快適に収まります。`n`最大 10^5。
