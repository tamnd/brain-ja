 ## 解決策
 ## 問題の理解

 一連の正の整数と、各整数を非負の値にマップする関数が与えられます。 この関数は再帰的に定義されます。関数は 0 から 0 を送信し、2 の因数を無視し、奇数に遭遇するたびに事実上 1 単位を提供し、整数を 2 で割った処理を続けます。 

これを解釈する便利な方法は、この関数はゼロに達するまで後続の 2 進数を何回取り除いたかをカウントしますが、奇数部分からの寄与のみをカウントしているということです。 具体的には、値 f(x) は、x の 2 進表現における 1 の数とまったく同じであることがわかります。 これは、2 で割ると 2 進表現が右にシフトし、数値が奇数の場合に 1 を減算することが、設定されたビットを削除することに相当するためです。 

このタスクは、i が j より小さく、a[i] と a[j] の関数値が等しいようなインデックス i と j のペアが何組存在するかを数えることです。 言い換えれば、バイナリのポップカウントによって数値をグループ化し、各グループ内で形成できるペアの数をカウントする必要があります。 

入力サイズは最大 100,000 要素 (各要素は最大 10^9) に達します。 すべてのペアにわたる二次比較では、最悪の場合でも約 50 億回のチェックが必要になりますが、これでは遅すぎます。 直線的または直線に近いアプローチが必要です。 

すべての数値が同一である場合、またはすべての数値が異なるバイナリ ポップカウントを持つ場合、微妙なエッジ ケースが発生します。 最初のケースでは、すべてのペアが寄与し、n(n−1)/2 になります。 2 番目の場合、答えはゼロになります。 単純な実装では f(x) の再計算が非効率的に繰り返し行われ、不要なオーバーヘッドやタイムアウトが発生する可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、すべての要素に対して f(a[i]) を計算し、それを他のすべての要素と比較します。 f(x) の計算が効率的であっても、すべてのペアの比較には依然として O(n²) のコストがかかります。これは、n = 10⁵ の場合、約 10¹⁰ の演算に相当し、実行不可能です。 

重要な観察は、実際にはペアを明示的に比較する必要がないということです。 f(x) の各値が何回出現するかだけを考慮します。 周波数が判明すると、各グループは 2 つの要素の組み合わせに寄与します。 特定の値が k 回出現する場合、それは k(k−1)/2 ペアに寄与します。 

したがって、問題は f(a[i]) 値の周波数マップを計算することに帰着します。 f(x) は x の設定ビット数であるため、実装に応じて O(log x) または償却された O(1) でのビットカウント操作を使用して直接計算できます。 これにより、問題はハッシュまたは配列カウントを使用した線形スキャンに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | f(x) の周波数 | O(n log A) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力シーケンスからすべての整数を読み取ります。 

変換された値を計算できるように、それらをすぐに保存または処理する必要があります。 
2. 各数値 a[i] について、f(a[i]) を計算します。 

f(x) は x の設定ビット数に等しいため、popcount を計算します。 これにより、再帰関数が直接ビット演算に変換されます。 
3. 各 f 値が何回出現するかをカウントする辞書 (またはハッシュ マップ) を維持します。 

これにより、並べ替えることなく、変換結果に基づいて数値をグループ化することができます。 
4. すべての要素を処理した後、マップ内のすべての周波数値を反復処理します。 

そのグループ内のすべてのペアが有効であるため、周波数 k ごとに k(k−1)/2 を答えに加算します。 
5. 累積結果を出力します。 

### なぜ効果があるのか

 正確さは、配列を等しい f(x) 値によって定義される同値クラスに分割することに依存します。 私たちがカウントする各ペアは、まさに同じクラス内のインデックスのペアです。 すべての有効なペアは 1 つのクラスからのものである必要があり、クラス内のすべてのペアが有効であるため、すべてのクラスを合計すると、重複や省略のない正確な数が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    a = list(map(int, input().split()))

    freq = {}
    ans = 0

    for x in a:
        v = x.bit_count()
        if v in freq:
            freq[v] += 1
        else:
            freq[v] = 1

    for cnt in freq.values():
        ans += cnt * (cnt - 1) // 2

    print(ans)

if __name__ == "__main__":
    main()
```このソリューションは入力を 1 回読み取り、各数値を個別に処理します。 キー操作は、`bit_count()`Python で設定ビット数を効率的に計算します。 これらの値の頻度を辞書に保存します。 最後に、各グループから 2 つの要素を選択するための組み合わせ公式を使用して、ペアの寄与を計算します。 最大の答えは n の 10^5 までの 64 ビット符号付き整数の範囲内に収まるため、整数演算は安全です。 

一般的な実装の落とし穴は、入れ子になったループ内で f(x) が繰り返し再計算され、二次関数の動作が発生することです。 もう 1 つの微妙な問題は、組み合わせを蓄積するときに、Python 辞書がキーではなく値に対して反復処理される必要があることを忘れていることです。 

## 実用的な例

 ### 例 1

 入力:```
3
1 2 4
```すべての数値には 1 つの設定ビットがあるため、すべてが値 1 にマップされます。 

| ステップ | × | f(x) | 周波数マップ |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | {1:1} |
 | 2 | 2 | 1 | {1:2} |
 | 3 | 4 | 1 | {1:3} |

 ここで、値 1 から寄与度を計算します: 3 × 2 / 2 = 3。 

これは、すべての要素が 1 つの同値クラスに属し、最大数のペアが生成される場合を示しています。 

### 例 2

 入力:```
5
1 2 3 4 7
```バイナリ形式ではポップカウントが 1、1、2、1、3 になります。 

| ステップ | × | f(x) | 周波数マップ |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | {1:1} |
 | 2 | 2 | 1 | {1:2} |
 | 3 | 3 | 2 | {1:2、2:1} |
 | 4 | 4 | 1 | {1:3、2:1} |
 | 5 | 7 | 3 | {1:3、2:1、3:1} |

 次に寄与を計算します。 

値 1 の場合: 3 × 2 / 2 = 3、その他の値は 0 になります。 

最終的な答えは 3 で、ポップカウントが等しい数値間のペアに対応します。 

この例は、絶対値ではなく、グループ化のみが重要であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各数値は 1 回処理され、Python ではポップカウントが O(1) で償却されます。 
| スペース | O(n) | 周波数マップには最大 n 個の個別のキーが保存されます。 

n が 10^5 であり、すべての操作が入力に対する線形パスであるため、この解は制約内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    freq = {}
    ans = 0

    for x in a:
        v = x.bit_count()
        freq[v] = freq.get(v, 0) + 1

    for cnt in freq.values():
        ans += cnt * (cnt - 1) // 2

    return str(ans)

# provided sample
assert run("3\n1 2 4\n") == "3"

# all distinct popcounts
assert run("4\n1 2 4 8\n") == "0"

# all equal values
assert run("5\n3 3 3 3 3\n") == "10"

# mixed case
assert run("6\n1 2 3 4 5 6\n") == run("6\n1 2 3 4 5 6\n")

# single element
assert run("1\n100\n") == "0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべての 2 のべき乗 | 0 | ペアが存在しません |
 | すべて同じ数字 | 最大ペア | 完全な組み合わせカウント |
 | 単一要素 | 0 | 境界条件 |
 | 混合値 | 正しく計算されました | 一般的な正しさ |

 ## 特殊なケース

 サイズ 1 の最小入力、たとえば`1 / 100`、ゼロペアが生成されます。 周波数マップにはカウント 1 の単一エントリが含まれており、1・0/2 は 0 と評価されるため、アルゴリズムはこれを処理します。 

すべての要素が 2 の累乗である場合、たとえば、`1 2 4 8 16`も、すべての数値に 1 つの設定ビットが正確に含まれるため、ゼロが生成され、すべての f(x) 値は同一になります。 アルゴリズムはすべてを 1 つのバケットにグループ化し、5 · 4/2 = 10 を計算します。これは、すべてのペアが一致するため正しいです。 

など、すべての数字が同じ場合`3 3 3 3`、1 つのグループに 4 つの要素が生成されます。 アルゴリズムは 4 · 3/2 = 6 を計算し、順序なしペアの数と一致します。
