 ## 解決策

 ## 問題の理解

 私たちは電車の中で一列の座席を与えられます。 いくつかの席はすでに埋まっており、残りは空席です。 私たちは空いた席にできるだけ多くの学生を配置したいと考えています。 各学生は 2 つのタイプのいずれかに属し、制限は単純ですが厳格です。隣接する 2 つの座席に同じタイプの学生を置くことはできません。 ただし、アスリートの隣にプログラマがいることは許可されるため、禁止される隣接関係は同一タイプのみです。 

座席がブロックされていると、列が連続する空のセルの独立したセグメントに分割されます。 各セグメント内で、配置する生徒の数と、タイプを交互に配置する方法を決定します。 学生はタイプを除いて交換可能であるため、問題は 2 つのタイプの利用可能な数を尊重しながら各セグメントを貪欲に埋めることになります。 

制約は最大 200,000 シートに達するため、すべての配置を試したり、割り当てをバックトラッキングしたりするソリューションは遅すぎます。 セグメントまたは構成に対する二次または指数関数的なアプローチは生き残れません。 各セグメントを 1 回処理して局所的に最適な決定を行うリニア スキャンまたは貪欲な構築が必要です。 

セグメントが長く、1 つのタイプが早期に使い果たされる場合、微妙なエッジ ケースが発生します。 たとえば、長い空きブロックがあり、生徒のタイプが 1 つだけの場合、そのブロックに複数の座席を埋めることはできません。そうしないと隣接関係に違反してしまうためです。 もう 1 つのエッジ ケースは、セグメントが短いか孤立している場合です。この場合、貪欲な充填は些細に見えるかもしれませんが、依然として残りのグローバル カウントと相互作用します。 

## アプローチ

 強引なアイデアは、各空のセグメントを処理し、隣接ルールを尊重しながら、そのセグメントを A と B の生徒で埋めるあらゆる方法を試すことです。 長さ k のセグメントの場合、各座席は A または B になりますが、隣接する座席によって制約されるため、最悪の場合、状態空間は 2^k のように拡大します。 残数 a と b に基づいて枝刈りを行っても、k が大きい場合には構成数が不可能になります。 

重要な観察は、どのセグメント内でも、最初の生徒を決定すると、それを最大限に活用すると、セグメントの残りの生徒が交互のパターンに強制されるということです。 これにより、組み合わせによる配置の問題がスロットの貪欲な消費に軽減されます。 構成を検討する代わりに、各セグメントをただ見ていき、可能であれば常に生徒を配置し、隣接関係に違反せず、カウンターでまだ利用可能なタイプを選択します。 

唯一の制約はローカル隣接性と残りのカウントであるため、現在のシートを超えて先を見る必要はありません。 これにより、問題は文字列全体にわたる線形貪欲スキャンになります。

 ## アルゴリズムのチュートリアル

 文字列を左から右に処理し、ブロックされた位置で区切られた空席の連続ブロックを処理します。

1. 文字列をスキャンし、連続する「.」のセグメントを特定します。 文字。 「*」は境界を越えた隣接を防ぐ区切り文字として機能するため、各セグメントは独立して処理できます。 
2. 各セグメントでは、座席ごとに座席を埋めるように努めます。 それぞれのポジションで、どのタイプの学生を配置するかを決定します。 
3. セグメントの開始時に、前の座席は事実上「ブロックされている」か空であると見なされるため、生徒が残っている限り、どちらのタイプを自由に選択できます。 
4. セグメントの各座席に学生を配置しようとします。 両方のタイプが利用可能な場合は、将来の柔軟性を維持する方を選択しますが、より単純で正しい戦略は、カウントを尊重しながら貪欲に切り替えることです。 実際には、座席ごとに 1 人の生徒を配置し、まだ利用可能なタイプを使用し、前に配置した生徒と同じタイプを配置しないようにするだけです。 
5. 同じタイプの生徒の連続配置は禁止されているため、いずれかのタイプがなくなった場合、残席があっても配置をスキップする場合があります。 その場合、スキャンは続行されますが、有効な場合にのみ配置されます。 
6. すべてのセグメントにわたる配置された生徒の合計数を累積して出力します。 

重要な考え方は、セグメント内では最後に配置された生徒タイプと残りの数のみに依存するということです。 これにより、以前の決定を修正する必要がなくなります。 

### なぜ効果があるのか

 このアルゴリズムでは、どのセグメント内でも、構築されたシーケンスには 2 つの隣接する同一タイプが含まれないことが維持されます。 各配置は、構造上の隣接制約を尊重します。 さらに、すべての配置では利用可能な学生が 1 人だけ消費され、両方の制約 (可用性と隣接性) が許可する場合にのみ配置されます。 セグメントは独立しており、可能な場合は有効な配置をスキップしないため、グローバル制約の下で各セグメントの結果が最大になります。 

可能な場合に有効な学生を配置することから逸脱すると、総数が減るだけであり、有効な学生タイプの欠如によって強制されない限り、席を空のままにしておくメリットはないため、貪欲な性質は安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    s = input().strip()

    def take(prev, a, b):
        # returns which type to take, or None
        if prev == 'A':
            if b > 0:
                return 'B'
            if a > 0:
                return 'A'
        else:
            if a > 0:
                return 'A'
            if b > 0:
                return 'B'
        return None

    ans = 0
    i = 0

    while i < n:
        if s[i] == '*':
            i += 1
            continue

        # process segment
        j = i
        while j < n and s[j] == '.':
            j += 1

        prev = None
        for k in range(i, j):
            if a == 0 and b == 0:
                break

            if prev is None:
                if a >= b and a > 0:
                    prev = 'A'
                    a -= 1
                elif b > 0:
                    prev = 'B'
                    b -= 1
                elif a > 0:
                    prev = 'A'
                    a -= 1
                else:
                    break
                ans += 1
            else:
                if prev == 'A':
                    if b > 0:
                        prev = 'B'
                        b -= 1
                        ans += 1
                    else:
                        break
                else:
                    if a > 0:
                        prev = 'A'
                        a -= 1
                        ans += 1
                    else:
                        break

        i = j

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、列を空席のセグメントに分割します。 セグメントごとに、有効な交互シーケンスを貪欲に構築します。 の`prev`変数は最後に配置されたタイプを追跡するため、同一の生徒を隣接して配置することはありません。 最初の選択は、より大きな残りのプールに偏り、これにより、長いセグメントで 1 つのタイプが早期に使い果たされることを回避できます。 ロジックの残りの部分は、残りのカウントを尊重しながら厳密な変更を強制します。 

よくある微妙な点は、どちらの有効なタイプも配置できなくなったらすぐにセグメントへの配置を停止することです。 もう1つは正しくリセットされています`prev`新しいセグメントごとに、ブロックされた座席は隣接を完全に壊すためです。

 ## 特殊なケース

 文字列にブロックされたシートのみが含まれている場合、セグメントが形成されないため、アルゴリズムはすぐにすべての文字をスキップし、ゼロを出力します。 例えば、`n = 5, s = "*****"`セグメント ループ内では反復が発生しないため、答えは 0 のままになります。
