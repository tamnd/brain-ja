 ## 解決策

 ## 問題の理解

 左から右に並べられた一連の整数が与えられます。 このプロセスでは、少なくとも 2 回出現する値が繰り返し検索されますが、それらが恣意的に選択されるわけではありません。 代わりに、現在重複しているすべての値の中で、常に最小の値が選択されます。 値が選択されると、現在の配列順序でその値の最初の 2 つの出現が調べられます。 左側は完全に削除され、右側は値を 2 倍にして置き換えられます。 

これは、配列が継続的に縮小しながら、時折、後でマージの候補となる可能性のあるより大きな値を作成することを意味します。 

入力サイズは最大 150,000 要素にすることができ、単純な配列操作で各削除をシミュレートするアプローチは除外されます。 単純なリストベースのシミュレーションでは、要素を繰り返しシフトする必要があり、最悪の場合、これは二次関数になります。 出現順序が重要であり、マージのたびに構造が変化するため、頻度を維持するだけでも十分ではありません。 

値の複数のコピーが分散されている場合、微妙な問題が発生します。 たとえば、値が何度も出現する場合、最初の 2 つを削除すると、その数が減るだけでなく、以降のステップでどの出現が「最初」と見なされるかが変わります。 カウントのみを追跡し、位置を無視する素朴なアプローチは、マージが異なる値の間でインターリーブする場合には失敗します。 

もう 1 つの隠れた落とし穴は、新しく作成された値の再処理です。 値 x が 2x にマージされると、新しい値がすぐに最小の重複値になるか、他の候補をブロックする可能性があります。 正しいソリューションでは、各マージ後に「値のサイズによる重複値」のグローバルな順序付けを効率的に更新する必要があります。 

## アプローチ

 この強引なアイデアは、文字通りアレイ上でプロセスをシミュレートすることです。 各ステップで、配列をスキャンし、頻度を計算し、少なくとも 2 回出現する最小値を見つけて、最初の 2 つの出現箇所を見つけて、削除と置換を実行します。 これは概念的に単純であり、ルールに正確に従っているため、明らかに正しいです。 

問題はコストです。 各ステップでは、配列全体をスキャンするか、順序付けられた出現構造を維持する必要があります。 O(n) 個のマージが存在する可能性があり、各マージでは位置の検索や構造の更新に O(n) のコストがかかる可能性があります。 これにより、O(n²) の動作が発生し、150,000 個の要素にとっては遅すぎます。 

重要な点は、配列全体を繰り返しスキャンする必要がないということです。 本当に必要なのは、現在少なくとも 2 回出現する値をすばやく知り、その中で最小のものを選択する方法です。 また、各値について、現在の配列内の最初の 2 つの位置を知る必要もあります。 

これは、2 つの構造を同時に維持していることを示唆しています。 まず、値の頻度マップです。 次に、各値について、現在の配列順序でその値が表示される位置のキューです。 2 つの x をマージする場合、そのキューから最初の 2 つの位置を消費し、2x を保持するように 2 番目の位置を更新します。 次に、その新しい位置を 2x のキューに追加します。 

常に最小の有効な x を効率的に抽出するために、現在少なくとも 2 の頻度を持つ値に対して最小ヒープを維持します。 値の頻度が 2 に達するたびに、それをプッシュします。 ヒープからポップするときは、古いエントリが存在する可能性があるため、ヒープに少なくとも 2 つの出現があることを確認する必要があります。 

これにより、繰り返されるスキャンが対数ヒープ操作に変換されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 (ヒープ + 位置キュー) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 発生位置を注意深く追跡しながらプロセスをシミュレーションします。

1. すべての値を読み取り、各値を動的構造内の現在の位置を表す「ノード」に割り当てます。 各値には、これらのノードのキューが左から右の順序で格納されます。 これにより、O(1) の最初の 2 つの出現箇所に常にアクセスできるようになります。 
2. 初期頻度を計算し、少なくとも 2 つの頻度を持つすべての値を最小ヒープにプッシュします。 このヒープは、現在適格なすべてのマージ候補を値順に表します。 
3. ヒープから最小値 x を繰り返し抽出します。 現在の頻度が 2 未満の場合、それを破棄して続行します。 以前のマージにより可用性が低下した可能性があるため、この手順が必要です。 
4. 有効な x の場合、そのキューから最初の 2 つのノードを取得します。 左側のノードが構造から削除されます。 右側のノードは値 2x に更新されます。 
5. 次に、この右側のノードを x のキューから削除し、2x のキューに挿入します。 それに応じて周波数が更新されます。x は 2 減少し、2x は 1 増加します。 
6. 更新後、2x の頻度が少なくとも 2 になった場合は、ヒープにプッシュされます。 
7. ヒープ内に少なくとも 2 の頻度を持つ値がなくなるまで続行します。 

すべての操作の後、残りのノードは左から右の順序で最終的な配列を表します。 

重要な考え方は、ヒープは次にどの値を処理するかを決定するだけであり、キューは位置構造を保持するので、常に正しい値を選択できるということです。 

### なぜ効果があるのか

 いつでも、各値 x について、そのキューには、位置のソートされた順序で現在発生する x が正確に含まれます。 マージのたびに x の最初の 2 つの出現が削除されるため、キューは常にプロセス定義との一貫性を保ちます。 ヒープは常に、現在少なくとも 2 回出現する最小の x を選択します。 ヒープに古いエントリが含まれている場合でも、無効なエントリはすべて使用前に破棄され、有効な候補がスキップされることはありません。 これにより、シミュレーションが常に必要な貪欲ルールを反映するようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq
from collections import defaultdict, deque

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pos = defaultdict(deque)
    freq = defaultdict(int)

    # Each element is represented by its index; we mutate values in-place
    for i, v in enumerate(a):
        pos[v].append(i)
        freq[v] += 1

    heap = []
    for v in freq:
        if freq[v] >= 2:
            heapq.heappush(heap, v)

    alive = [True] * n

    while heap:
        x = heapq.heappop(heap)
        if freq[x] < 2:
            continue

        # take first two occurrences
        i1 = pos[x].popleft()
        i2 = pos[x].popleft()

        alive[i1] = False

        # update second occurrence
        a[i2] = 2 * x

        freq[x] -= 2
        freq[2 * x] += 1

        pos[2 * x].append(i2)

        if freq[2 * x] == 2:
            heapq.heappush(heap, 2 * x)
        if freq[x] >= 2:
            heapq.heappush(heap, x)

    result = []
    for i in range(n):
        if alive[i]:
            result.append(a[i])

    print(len(result))
    print(*result)

if __name__ == "__main__":
    solve()
```この実装では、固定インデックス配列を保持し、ブール値のアライブ マーカーを使用して削除をシミュレートします。 これにより、コストのかかる移行が回避されます。 位置キューにより、最初の 2 つの出現にどのインデックスが対応するかを常に把握できます。 

微妙な点は、2 番目の出現インデックスを更新するときです。`i2`、その値をその場で上書きし、別の値バケットに再分類します。 元の値は、配列を物理的に移動することなく、その位置から効果的に削除されます。 

ヒープの重複は遅延処理されます。値を複数回プッシュする可能性がありますが、その頻度がまだ有効な場合にのみ処理されます。

def run(inp: str) -> str:

    from collections import defaultdict, deque
    import heapq

    a = list(map(int, input().split()))

    pos = defaultdict(deque)
    freq = defaultdict(int)

    for i, v in enumerate(a):
        pos[v].append(i)
        freq[v] += 1

    for v in freq:
        if freq[v] >= 2:
            heapq.heappush(heap, v)

    alive = [True] * n

    while heap:
        x = heapq.heappop(heap)
        if freq[x] < 2:
            continue
        i1 = pos[x].popleft()
        i2 = pos[x].popleft()

        a[i2] = 2 * x
        freq[x] -= 2
        freq[2 * x] += 1
        pos[2 * x].append(i2)
        if freq[2 * x] == 2:

        if freq[x] >= 2:
            heapq.heappush(heap, x)

    res = [a[i] for i in range(n) if alive[i]]

 ## 特殊なケース

 主なエッジケースは、マージを繰り返すとすぐに新しい重複が作成される場合です。 たとえば、次のように始めます。`[1,1,1,1]`、最初のマージ後に導入します`2`、何よりも先に対象となる可能性があります`1`が処理されます。 ヒープにより、常に最小の有効な値が選択されることが保証されるため、たとえ`2`早期に利用可能になると、その間は選択されません`1`まだ 2 件発生しています。 

もう 1 つのケースは、古いヒープ エントリが表示される場合です。 値は複数回プッシュされる可能性がありますが、処理されるまでにその頻度が 2 未満になる可能性があります。 明示的な頻度チェックにより、誤ったマージが防止されます。 

3 番目のエッジ ケースは、値が指数関数的に増加する長いチェーンです。 マージごとに合計要素数が 1 つ減るため、プロセスは常に終了しますが、中間値が大きくなる可能性があります。 Python の整数を使用すると、オーバーフローの問題が回避され、算術演算が安全に保たれます。
