 ## 解決策

 ## 問題の理解

 数直線上の一連の点が与えられます。各点は、バイトランド、バーランド、紛争地域の 3 つのタイプのいずれかの都市になります。 任意の都市のペアをケーブルで接続することが許可されており、ケーブルのコストは 2 つの座標間の距離にすぎません。 

要件は、単一のグローバル接続条件ではありません。 代わりに、両方を同時に保持する必要がある 2 つの別個の接続制約があります。 バーランドのすべての都市を無視した場合でも、残りのすべての都市 (バイトランドと係争中の都市) は、選択したケーブルを介して接続する必要があります。 対称的に、バイトランドのすべての都市を無視した場合、残りのすべての都市 (バーランドと係争中の都市) も接続されたままでなければなりません。 

目標は、都市間の無向エッジのセットを選択して、選択されたすべてのエッジの合計長を最小限に抑えながら、両方の誘導サブグラフが接続されるようにすることです。 

主要な構造的制約は、すべての都市が一定の順序で直線上に並んでいるという事実から来ています。 これにより、ジオメトリの組み合わせの自由が排除されます。あらゆる有用な接続は、任意の組み合わせではなく、順序と隣接性の観点から理解できます。 

n が 2⋅10^5 までの制約により、線形または線形に近い解が強制されます。 都市のすべてのペアを考慮しようとするアプローチや、エッジのサブセットに対するグローバルな最適化を考慮しようとするアプローチは、O(n²) の演算が大きすぎるため、すぐに失敗します。 

主要なタイプの 1 つが完全に欠落している場合、微妙なエッジケースが発生します。 Byteland の都市が存在しない場合、最初の接続要件は些細なものとなり、Berland と係争中の事項だけが必要となります。 ベルランドの都市がない場合も同様です。 もう 1 つのエッジ ケースは、すべての都市が紛争になっている場合です。この場合、隣接する点にまたがるスパニング ツリーだけで十分であり、問​​題は単純なパスに分割されます。 

本当の難しさは、2 つの接続要件が係争中の都市で重なっていることです。つまり、一部のエッジが両方の制約を満たすのに同時に役立つ可能性があることを意味します。 

## アプローチ

 直接的なアプローチは、グラフを構築し、2 つの異なる接続制約を満たす最小のスパニング構造を検索するという観点から考えることです。 完全なグラフに対して最短スパニング ツリー アルゴリズムを実行しようとするかもしれませんが、そのグラフには O(n²) 個のエッジがあるため、実行できません。 

より具体的な観察は、ラインの形状から得られます。 エッジ コストが距離に等しい線上の点で接続されたグラフでは、最適な構造では、中間の頂点を不必要にスキップする交差ショートカットは使用されません。 その理由は、長いエッジ (u、v) をラインに沿った連続したエッジに置き換えてもコストが増加することはなく、接続構造が維持または改善されるためです。 

これは、意味のあるエッジのみがソートされた順序で連続するポイント間にあることを示唆しています。 隣接するペアに注目を限定すると、最終的な構造にどの隣接するエッジを含めるかを選択することが問題になります。 

ここで、それぞれの接続要件が実際に何を要求しているのかを考えてみましょう。 バイトランドと係争都市の場合、B 点と P 点のみのシーケンスを順番に見ると、連続するそのような点のペアはすべて何らかの方法で接続されている必要があり、そのため、それらの間のすべての中間隣接セグメントがエッジで覆われます。 同じロジックがベルランドと紛争都市にも当てはまり、R ポイントと P ポイントのみを考慮します。 

これにより、各要件が、フィルタリングされたバージョンのライン上の要件に変換されます。 各条件は独立して、それぞれのフィルター処理されたシーケンス内のすべての隣接エッジを取得するように強制されます。 これら 2 つの構造間の唯一の重複は P-to-P 隣接で発生し、両方のフィルタリングされたシーケンスに現れます。

したがって、解決策は、2 つの制約にわたって隣接する各セグメントが何回必要になるかを注意深く数え、共有された寄与をマージすることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのエッジ サブセットに対するブルート フォース | 指数 | O(n²) | 遅すぎる |
 | 完全なグラフ + MST を構築 | O(n² log n) | O(n²) | 遅すぎる |
 | フィルタリングされた隣接関係の分解 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 すでに与えられている座標の昇順で都市を処理します。 

1. 隣接距離のベースライン リストを作成します。 都市 i と i+1 の連続するペアごとに、それらの間の距離を計算します。 これらは、線構造への縮小後に考えられるすべての有用なエッジを表します。 
2. すべてのバイトランドと係争中の都市を接続することに相当するコストを計算します。 これは、ベルランドの都市が存在しないふりをすることによって行われます。 残りのシーケンスでは、元の順序でベルランド以外の 2 つの連続する都市が表示されるたびに、それらの間の完全なチェーンを介してそれらの都市を接続する必要があります。これは、ベルランド ブレークポイントを含まないすべての隣接するペアにわたる距離の合計に変換されます。 
3. バイトランドの都市を無視し、連続する非バイトランド ポイント間にあるすべての隣接距離を合計することにより、バーランドと係争中の都市の対称コストを計算します。 
4. Byteland と Berland の両方を無視して、係争中の都市のみを接続するための 3 番目のコストを計算します。 これにより、以前の両方の構築間で共有される隣接関係の寄与が取得されます。 
5. 包含-除外ロジックを使用して結果を結合します。バイトランド + 係争中のコストとバーランド + 係争中のコストの両方に、係争中の都市を内部的に接続するための全コストが含まれるため、その部分は 2 回カウントされ、1 回減算する必要があります。 

### なぜ効果があるのか

 有効な各ソリューションは、B+P ノードに限定される場合、接続された構造を誘導する必要があります。 線上では、これにより、連続する B ポイントまたは P ポイント間のすべてのギャップが、そのギャップにまたがるエッジによって強制的にブリッジされます。これは、それらの間隔内のすべての隣接セグメントの料金を支払うことと同じです。 同じ理由が R+P にも当てはまります。 

係争中の都市は共有コネクタとして機能するため、両方のフィルタリングされたビューで係争中の 2 つの都市間の隣接関係が必要です。 最後の減算により、この二重カウントが修正されます。 必要な隣接関係はすべて結合後に 1 回だけ計算され、不必要な長いエッジがまったく導入されないため、結果として生じるコストは最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    x = []
    c = []
    
    for _ in range(n):
        xi, ci = input().split()
        x.append(int(xi))
        c.append(ci)
    
    if n == 1:
        print(0)
        return
    
    def calc(ignore_type):
        total = 0
        prev_idx = -1
        
        for i in range(n):
            if c[i] == ignore_type:
                continue
            if prev_idx != -1:
                total += abs(x[i] - x[prev_idx])
            prev_idx = i
        
        return total
    
    cost_BP = calc('R')
    cost_RP = calc('B')
    cost_PP = calc('X')
    
    print(cost_BP + cost_RP - cost_PP)

if __name__ == "__main__":
    solve()
```機能`calc(ignore_type)`ソートされた順序で連続する残りの都市間の距離を合計することにより、特定のタイプの都市を除くすべての都市を接続する総コストを計算します。 入力はすでに座標によってソートされているため、これにより、その誘導されたサブセットに必要なチェーン接続が直接キャプチャされます。 

バイトランドと係争都市の接続コスト、バーランドと係争都市の接続コスト、係争のみのチェーンの 3 つの量を計算します。 最後の式は、係争中のみの接続の重複した寄与を削除します。 

よくある落とし穴は、タイプ フィルタリングを無視して最近傍のみをグローバルに接続しようとすることです。これは、1 つのタイプを削除すると重要な隣接関係が変わるという事実を見逃してしまいます。

 ## 特殊なケース

 主なエッジケースは、いずれかの色が完全に消える場合です。 たとえば、バーランドの都市がない場合、バイトランドと係争中の計算は、残りのすべてのポイントにわたる完全なチェーンにすでに等しくなります。 係争中のみのコストが 2 回追加されるコンポーネントの 1 つと正確に一致するため、減算は依然として正しく動作します。 

もう 1 つのエッジケースは、すべての都市が紛争になっている場合です。 その状況では、フィルタリングされた両方の計算が同一になり、減算によって完全なコピーが 1 つだけ削除され、すべてのポイントにわたる単一のスパニング チェーンが残ります。これは最適です。 

最後に、タイプが頻繁に切り替わる場合、フィルタリングされたスキャンの少なくとも 1 つで隣接するすべてのセグメントがカウントされ、オーバーラップ減算によりセグメントがオーバーカウントされないことが保証され、最大限にインターリーブされた構成でも正確さが維持されます。
