 ## 問題の理解

 左から右にインデックスが付けられた部屋の列があります。 特別な立場`k`中心的な役割を果たします。 特定の日に「ディレクター イベント」が発生し、そのようなイベントごとに、どの部屋が朝の演習に参加するかについての時間依存のパターンがトリガーされます。 

当日のディレクター訪問直後`d`、全員が参加します。 翌日以降、参加者は部屋を中心に対称的に縮小します`k`。 当日`d + y`、参加をやめる一連のルームは、以下を中心として成長する間隔を形成します。`k`、各方向に 1 日あたり 1 部屋ずつ拡張されます。 同様に、部屋から離れるほど、`k`、最後のディレクターの訪問後、参加し続ける時間が長くなり、最終的には次のディレクターの訪問でシステムがリセットされるまで永久にドロップアウトします。 

重要なのは、日に複数のディレクターが訪問することです`d1 < d2 < ... < dq`。 訪問するたびにプロセスがリセットされます。 連続する 2 回の訪問の間の参加の「減衰」は、最も最近の訪問にのみ依存します。 最後の訪問の後、すべての部屋が最終的に参加しなくなるまで、同じ衰退が永遠に続きます。 

タスクは、ルームごとに、タイムライン全体で合計何日参加しているかを計算することです。 

制約は大きく、最大で`3 · 10^5`ルームやディレクターのイベントはもちろん、日数自体は`10^12`。 これにより、数日にわたるシミュレーションは即座に除外されます。 どのようなソリューションでも、毎日の反復を避け、代わりに各ディレクター イベントの影響を集計された貢献に圧縮する必要があります。 

ディレクターの最後の訪問後に、微妙な特殊なケースが発生します。 プロセスはそこで終わりません。 代わりに、すべての部屋が除外されるまで縮小が続きます。 有限の終了日を想定したり、安定化するまで先のシミュレーションを試みたりする単純なアプローチでは、寄与を逃すか、実行不可能になります。 

もう 1 つのよくある落とし穴は、毎日を独立して扱うことです。 状態は、以前のすべての訪問ではなく、最新のディレクターの訪問のみに依存するため、単純なシミュレーションが重複すると、誤って二重にカウントされたり、法外な再計算が必要になったりする可能性があります。 

## アプローチ

 直接シミュレーションでは、ディレクターの最後の訪問に基づいて、どの部屋がアクティブであるかを毎日追跡します。 各ディレクター イベントでは、次のイベントまでの将来のすべての日を更新し、毎日、アクティブな範囲を再計算する必要がある可能性があります。 これはおおよそ次のことにつながります`O(n * max_gap)`さらに悪いことに、指定された制約の下では崩壊します。`n`イベントの数が多く、日のずれが非常に大きくなる場合があります。 

重要な観察は、各ディレクター イベントが独立して、ポジションを中心とした構造化された対称的な「ライフスパン」パターンに寄与しているということです。`k`、このパターンはからの距離のみに依存します。`k`そして次のイベントまでの時間差。 日数で考えるのではなく、視点を逆転させます。固定された部屋の場合、その動作は距離によって完全に決まります。`d = |i - k|`。 ディレクター間隔ごとに`[di, di+1)`、部屋への貢献度は以下にのみ依存します。`d`そしてインターバルの長さ`L = di+1 - di`。 

各間隔は次の関数に寄与します。`d`形の`min(L, d + 1)`。 これは区分的に線形です。短い距離では線形に増加し、長い距離では飽和します。 この構造により、問題を範囲更新に変換できるようになります。`d`。 

間隔ごとにルームを反復処理する代わりに、`d`を主軸として使用し、線形成分と定数成分の差分配列を使用してすべての間隔にわたる寄与を累積します。

 ## アルゴリズムのチュートリアル

 ### 最適なアイデア: からの距離を考慮して作業する`k`1. 部屋ごとのインデックスを変換する`i`遠くへ`d = |i - k|`。 同じ距離にある部屋は同じように動作するため、距離の答えを計算するだけで済みます。`0 ... max(n)`そしてそれらを両側にミラーリングして戻します`k`。 
2. 連続する取締役日のペアごとに`(di, di+1)`、間隔の長さを定義します`L = di+1 - di`。 ディレクターの最後の日の場合、間隔は無制限として扱います。 事実上、次のように動作します`L`は無限ですが、貢献は依然として自然に制限されます。 
3. 単一の間隔と単一の距離を固定します`d`。 この間隔によって寄与されるアクティブな日数は、次の 2 つの範囲間の重複です。 

間隔`[di, di+L-1]`そしてアクティブなウィンドウ`[di, di+d]`。 

このオーバーラップ サイズは次のように単純化されます。`min(L, d+1)`。 

これは重要な短縮です。複雑な時間プロセスが距離の単純な関数になります。 
4. ここで書き直します`min(L, d+1)`全体的に効率的に集約できる形で`d`：

のために`d < L`、貢献度は`d + 1`、そしてのために`d >= L`、貢献度は`L`。 

したがって、各間隔は次の線形関数を生成します。`L-1`そしてその後はフラット。 
5. これをすべてに個別に適用するのではなく、`d`、距離を超えて 2 つの配列を維持します。 

の傾きを何回追加するかを追跡します。`1`各インターバルから開始して、

 他のトラックは一定のオフセットを追跡します。 

各間隔について:

 一次関数を追加します`(d + 1)`以上`[0, L-1]`、および定数`L`以上`[L, max_distance]`。 

これは、差分配列を使用して実装できます。 

範囲の追加`+1`傾斜と`+1`インターセプトオン`[0, L-1]`、

 および定数の範囲加算`L`の上`[L, n]`。 
6. すべての間隔を処理した後、各距離の最終値を再構築します。`d`として：`answer[d] = d * slope_sum[d] + const_sum[d]`。 
7. 最後に、各部屋のマップを作成します`i`その距離に戻って`d = |i - k|`そして出力`answer[d]`。 

### なぜ効果があるのか

 各部屋の参加は、部屋からの距離によって完全に決定されます。`k`各ディレクター期間からの独立した貢献。 各間隔は追加的に寄与し、寄与関数は以下にのみ依存します。`d`単調な区分的直線的な方法で。 すべての間隔効果を範囲更新に変換するため、`d`、部屋ごと、間隔ごとの計算を回避しながら、正確な部屋ごとの合計を保持します。 集計の直線性により、すべての間隔を結合するときの正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q, k = map(int, input().split())
    d = list(map(int, input().split()))
    
    # convert to 0-based for convenience in distance handling
    k -= 1
    
    # we work with distances 0..n-1
    max_d = max(k, n - 1 - k)
    
    # difference arrays for slope and constant
    slope = [0] * (n + 5)
    const = [0] * (n + 5)
    
    # helper to apply range add on slope/const
    def add(l, r, s_val, c_val):
        if l > r:
            return
        slope[l] += s_val
        slope[r + 1] -= s_val
        const[l] += c_val
        const[r + 1] -= c_val
    
    # process intervals
    for i in range(q):
        start = d[i]
        if i + 1 < q:
            L = d[i + 1] - d[i]
        else:
            L = 10**18  # effectively infinite
        
        # we only care up to distance n
        # piecewise:
        # d in [0, L-1]: add (d+1)
        # d >= L: add L
        
        r1 = min(n - 1, L - 1)
        if r1 >= 0:
            # add (d + 1) on [0, r1]
            # slope +1, const +1
            add(0, r1, 1, 1)
        
        if L <= n - 1:
            # add constant L on [L, n-1]
            add(L, n - 1, 0, L)
    
    # build prefix sums
    for i in range(1, n):
        slope[i] += slope[i - 1]
        const[i] += const[i - 1]
    
    # compute answers by distance
    ans = [0] * n
    for i in range(n):
        d_i = abs(i - k)
        ans[i] = slope[d_i] * d_i + const[d_i]
    
    print(*ans)

if __name__ == "__main__":
    solve()
```この実装では、各区間が 2 つの構造的寄与 (線形セグメントと平坦セグメント) に分離されます。 差分配列トリックを使用して、間隔ごとに O(1) で両方の効果を適用します。 プレフィックス合計後の各距離`d`一定時間で直接評価できます。 

微妙な点は、次のディレクターの訪問がない最後のインターバルの処理です。 線形から飽和への移行のみが重要となるように、その長さを事実上無限として扱います。 実際には、関数は次の値で飽和するため、十分に大きな値に制限します。`d + 1`。 

もう 1 つの重要な詳細は、部屋をからの距離にマッピングすることです。`k`。 この対称性により、全体の削減が可能になります。 それがなければ、問題は位置と時間の両方にわたって 2 次元のままになります。

 ## 特殊なケース

 特殊なケースの 1 つは、ディレクターが 1 人しか訪問しない場合です。 この状況ではリセットは行われず、すべてのルームが参加を停止するまで減衰が続きます。 アルゴリズムは、最後の間隔を無制限として扱うことでこれを処理し、自動的に正しい有限寄与を生成します。`d + 1`距離ごとに。 

もう 1 つのエッジケースは、部屋が正確な位置にある場合です。`k`。 その距離はゼロであるため、間隔ごとの寄与は常に次のようになります。`min(L, 1)`つまり、ギャップ サイズに関係なく、間隔ごとに 1 日だけ参加します。 距離ベースの定式化は、特別なケースを必要とせずに、これを自然に捉えます。 

最後の微妙なケースは、ディレクターの訪問間隔が極端に大きい場合に発生します。 単純なシミュレーションでは、これらのギャップを反復しようとしますが、距離公式により、一度`L`を超える`n`、すべての寄与はすぐに飽和し、追加の構造変化は発生しません。
