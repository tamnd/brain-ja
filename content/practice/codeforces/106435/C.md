 ## 解決策
 ## 問題の理解

 私たちは時間から睡眠間隔を与えられています`a`時間まで`b`。 この間隔内には、`n`悪夢が起こる瞬間を固定し、そのたびにウラジミールが短時間目覚めます。 こうした瞬間は確実に増加しています。 

最大でも削除が許可されています`k`これらの悪夢の瞬間。 それらのいくつかを取り除いた後、残りの悪夢が間隔全体を分割しました`[a, b]`中断のない睡眠セグメントに移行します。 各セグメントは、境界を含む、連続して残っている悪夢の間の時間です。`a`そして`b`。 

目標はどちらを選択するかです`k`悪夢を取り除くことで、最長の連続睡眠セグメントができるだけ長くなります。 

制約は大きく、最大で`n = 5e5`したがって、すべてのサブセットを試行したり、間隔を繰り返し再計算したりするソリューションは遅すぎます。 重要な要件は、ソートされた配列を線形または線形に近い時間で処理することです。 

境界セグメントから微妙な問題が発生します。 最良のセグメントは先頭にある可能性があります`[a, t_i]`、 最後に`[t_i, b]`、または 2 つの悪夢の間で発生するため、これらすべてを均一に扱う必要があります。 

単純に削除すればよいと考えるのは単純な間違いです。`k`最小のギャップまたは`k`しかし、悪夢を削除すると隣接するギャップが変更され、非局所的な方法で間隔がマージされる可能性があるため、これは失敗します。 

グリーディバイギャップの具体的な失敗例:```
a = 0, b = 10
t = [2, 3, 8, 9], k = 1
```最小のギャップ (2 と 3 の間) を削除すると、セグメントが得られます。`[0,2]`、`[2,8]`、`[8,10]`そして最高は6です。 

しかし、代わりに 8 を削除するとセグメントが得られます`[0,2]`、`[2,3]`、`[3,9]`、`[9,10]`同様に最高は 6 ですが、他の構築では貪欲な選択はさらに悪いことになる可能性があります。 実際の構造は、ローカル ギャップではなく、選択した保持ウィンドウのエンドポイントに依存します。 

本当の難しさは、悪夢を効果的に除去することで隣接するセグメントを「マージ」できるようになり、最適な答えは残りのポイントの連続ブロックの選択に依存することです。 

## アプローチ

 どの悪夢が残るかを修正すれば、答えは簡単です。次のような、連続する残りの点間の最大距離を計算します。`a`そして`b`。 まで除去できるので、`k`、等価的に維持します`m = n - k`ポイント。 

そこで問題は次のとおりです。`m`のうちのインデックス`n`連続して選択された点（境界線を含む）間の最大ギャップが最小化されるような（順序の維持）? 正確には最小化されていません。 選択したセットによって引き起こされる最適なセグメントを最大化したいと考えています。 

重要な観察は、答えはブロックを選択することによって決定されるということです。`m`元の順序で連続的に保持された悪夢。 キープセットを決定したら、最良の連続睡眠セグメントは 2 つの連続したキープポイントの間になければなりません。 逆に考えてみると、取り除くと、`k`ポイントは、次のサイズのウィンドウを選択することに相当します。`m = n - k`ソートされた配列内で発生したギャップを調べます。 

固定窓の場合`[i, i + m - 1]`、その中の中断されない最良の睡眠セグメントは、次の中で最大です。 

左側の境界セグメント`t[i] - a`、右側の境界セグメント`b - t[i + m - 1]`、およびすべての内部ギャップ`t[j] - t[j - 1]`のために`j`窓の中。 

すべてのウィンドウでこの値を最大化したいと考えています。 

残りの課題は、各スライディング ウィンドウの最大ギャップを効率的に計算することです。 これは、ギャップの配列に対する古典的なスライディング ウィンドウ最大問題であり、線形時間でのデキューを使用して実行できます。 

ブルート フォース アプローチでは、すべてのウィンドウを列挙して内部ギャップをスキャンし、O(nm) のコストがかかりますが、n が 500000 まででは遅すぎます。スライディング ウィンドウ構造により、ステップごとに償却される最大ギャップを O(1) に維持することで、繰り返しの再計算が削減されます。

 ## アルゴリズムのチュートリアル

 問題をギャップの派生配列を扱うように変換し、固定サイズのウィンドウをその上にスライドさせます。 

1. ギャップの配列を構築する`g`、 どこ`g[0] = t[0] - a`、`g[i] = t[i] - t[i-1]`のために`1 <= i < n`、 そして`g[n] = b - t[n-1]`。 これらは、削除が行われなかった場合に考えられるすべての中断されないセグメントを表します。 

この変換は、削除によって隣接するギャップがマージされるだけなので、すべての候補の答えが次の連続要素の合計として表現できるため便利です。`g`。 
2. 正確に選びたい`m = n - k`ポイントを守った。 これは、連続した元の点のブロックを選択することに対応し、内部ギャップ上のウィンドウを選択することに対応します。 
3. 保持されたポイントの固定ウィンドウの場合`[i, i + m - 1]`、中断されないセグメントの最大値は、次の最大値と等しくなります。 

左側の境界ギャップ`t[i] - a`、右側の境界ギャップ`b - t[i + m - 1]`、および連続して選択されたポイント間のすべての内部ギャップ。 

内部ギャップは以下に対応します`t[j] - t[j - 1]`のために`j in (i+1 ... i+m-1)`。 
4. すべての内部ギャップを事前計算します`d[i] = t[i] - t[i-1]`のために`1 <= i < n`。 次に、各ウィンドウごとに`t`、注目する内部ギャップは部分配列を形成します。`d`。 
5. デクを維持する`d`サイズの各スライディング ウィンドウで最大のクエリをサポートするため`m - 1`。 スタートポジションごとに`i`の最大内部ギャップをクエリします。`d[i+1 ... i+m-1]`。 
6. 各ウィンドウの結果を結合します。 

候補の回答を次のように計算します`max(t[i] - a, b - t[i+m-1], max_internal_gap)`そしてグローバル最大値を更新します。 
7. 操作ごとにデクを償却 O(1) に維持しながら、ウィンドウを 1 ステップずつスライドさせます。 

### なぜ効果があるのか

 核となる不変条件は、どのような削除の選択であっても、`k`要素により、問題は連続するブロックの選択に軽減されます。`m`ソートされた順序で位置が維持されます。 このようなブロック内では、中断されないすべてのスリープ間隔は、正確に境界ギャップと内部連続差分を加算したものになります。 すべての有効な構成はまさに 1 つのそのようなブロックに対応し、すべてのブロックは有効な削除パターンに対応するため、すべてのブロックを列挙することで、重複や省略なしにすべての可能性がカバーされます。 スライディング ウィンドウ構造により、内部ギャップの正しい最大値を維持しながらすべてのブロックを評価できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, k, a, b = map(int, input().split())
    t = list(map(int, input().split()))

    m = n - k

    # edge: if we keep no internal points, whole interval is uninterrupted
    if m == 0:
        print(b - a)
        return

    # boundary-only case
    if m == 1:
        # keep exactly one point
        best = 0
        for x in t:
            best = max(best, x - a, b - x)
        print(best)
        return

    # internal gaps
    d = [t[i] - t[i - 1] for i in range(1, n)]

    dq = deque()
    ans = 0

    # initial window over d: indices [0 .. m-2]
    for i in range(m - 1):
        while dq and d[dq[-1]] <= d[i]:
            dq.pop()
        dq.append(i)

    def get_max():
        return d[dq[0]]

    for i in range(n - m + 1):
        left = t[i] - a
        right = b - t[i + m - 1]
        mid = get_max() if m > 1 else 0
        ans = max(ans, left, right, mid)

        # slide window
        if i + m - 1 < n - 1:
            # remove old index i from window [i+1 .. i+m-1]
            if dq and dq[0] == i:
                dq.popleft()

            nxt = i + m - 1
            if nxt < n - 1:
                while dq and d[dq[-1]] <= d[nxt]:
                    dq.pop()
                dq.append(nxt)

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、保持されるポイントの数が非常に少ない場合に、些細な削減を処理することから始まります。 一般的なケースでは、連続する悪夢の差分配列を構築します。 デキューは、この差分配列のスライディング ウィンドウのインデックスを維持し、前が最大になるように常に減少するシーケンスを格納します。 

保持されたポイントの候補ブロックごとに、左境界、右境界、O(1) の最大内部ギャップを計算し、デキューを更新しながら前方にスライドします。 

インデックスの位置合わせには注意が必要です: ウィンドウオーバー`t`長さの`m`上の窓に相当します`d`長さの`m-1`、から始まります`i`そして終わる`i+m-2`。

 ## 特殊なケース

 いつ`k = n`、すべての悪夢を取り除くことができ、アルゴリズムは単一の中断のない間隔に短縮されます。`[a, b]`。 実装は明示的に返します`b - a`これは、内部セグメンテーションが残っていないという事実と一致します。 

いつ`m = 1`, only one nightmare is kept. この構造は、候補点ごとに 2 つの境界セグメントをチェックするように分解され、内部ギャップは無関係です。 コードは無効な両端キューの使用を避けるためにこれを個別に処理します。 

いつすべて`t_i`密にクラスター化されており、内部ギャップは小さく、最良の答えは境界距離から得られます。 スライディング ウィンドウは、内部構造とは独立して左右の境界を考慮するため、これらを正しく評価します。
