 ## 解決策
 ## 問題の理解

 私たちは与えられています$n$ラベルが貼られた円形のテーブルの周りに座っている人々$1$に$n$時計回りの順序で。 すべての人が最終的に他のすべての人とアイテムを交換する必要があるため、私たちはすべての人に効果的に対処しています。$\binom{n}{2}$ペア。 

ただし、同じラウンド内で任意に交換を行うことはできません。 ラウンドは一連の素なペアで構成されます。つまり、各人はそのラウンドで最大 1 つの交換に参加することになります。 さらに、各交換を円の内側の直線のコードとして描画すると、同じラウンド内の 2 つのコードが交差することは許可されません。 

したがって、各ラウンドは凸面上の非交差マッチングです。$n$-gon: 幾何学的表現が交差しない、互いに素なエッジのセット。 

出力では、そのようなラウンドの数を最小限に抑え、各ラウンドのすべてのペアを明示的に構築する必要があります。 

制約$n \le 10^3$エッジの総数が最大で約であることを意味します$5 \cdot 10^5$。 これにより、エッジごとの幾何学的シミュレーションやラウンドごとのグローバルな再計算がすでに排除されています。 代わりに、ソリューションは完全なグラフを少数の非交差マッチングに構造化して分解することに依存する必要があります。 

微妙な失敗モードは、「任意のマッチングが機能する」、または残りの頂点を貪欲にペアリングできると想定することで発生します。 たとえば、$n=4$、ペアリング$1\!-\!3$その後$2\!-\!4$たとえ両方のペアが素であっても、コードが交差するため、同じラウンドでのは無効です。 

もう 1 つの落とし穴は、最小ラウンド数がエッジの色数であると仮定していることです。$K_n$、つまり$n-1$または$n$。 これは、各カラー クラスに追加の構造を強制する幾何学的制約を無視します。 

## アプローチ

 ブルートフォースアプローチでは、それぞれの$\binom{n}{2}$エッジを 1 つずつラウンドに変換し、挿入のたびに現在のラウンドが非交差マッチングのままであることを維持します。 新しいエッジがラウンド内の既存のエッジと交差するかどうかを確認するには、$O(n)$、そして、あります$O(n^2)$エッジがあるため、単純な貪欲な割り当てでも時間がかかります$O(n^3)$。 と$n=1000$、これでは遅すぎます。 

重要な点は、単に任意の一致を詰め込んでいるわけではないということです。 凸多角形上に描かれた完全なグラフのエッジを、最小数の外側平面のマッチングに詰め込んでいます。 この構造は厳格です。1 つのエッジがラウンド内に配置されると、その同じラウンド内に他のどのエッジを表示できるかが大幅に制限されます。 

重要な単純化は、エッジの観点から考えるのをやめ、代わりに対角線の「層」の観点から考えることです。 頂点を固定すると$i$、に付随するエッジ$i$頂点の周囲でファンのように動作し、異なる頂点からのファンをインターリーブして、各レイヤーが交差しないようにすることができます。 これにより、各ラウンドが慎重に回転されたラベル内の 1 つの「対角長クラス」に対応する系統的なスイープ構築が可能になり、同じクラスで選択された 2 つのエッジが交差しないことが保証されます。 

これを達成する標準的な方法は、次のように構築することです。$n$構造化マッチング ($n>2$）ベースの非交差パターンを円上で回転させます。 各マッチングは完全または完璧に近いマッチングであり、この構造により、頂点のすべてのペアがすべてのラウンドにわたって正確に 1 回出現することが保証されます。 

これにより、下限に一致する最適な分解が得られます。$\Theta(n)$、各ラウンドには最大でも次の内容を含めることができるため、$\lfloor n/2 \rfloor$エッジ。

 ## アルゴリズムのチュートリアル

 すべてのペアを系統的に分解してソリューションを構築します。$n$ラウンド（$n \ge 3$）。 各ラウンドは、固定された周期パターンで頂点をペアにすることによって形成されるマッチングです。 

1.循環順序を修正する$1,2,\dots,n$。 ラウンドを 1 つずつ構築し、すべてのペアを確実にします$(i,j)$は 1 回だけ表示されます。 
2. ラウンドごとに$r$から$0$に$n-1$、巡回シフト規則に基づいて頂点をペアにすることでマッチングを構築します。 

私たちはペアを組む$i$と$j$そのような$i < j$そして$j \equiv i + r \pmod n$、インデックスのモジュロを解釈する$n$範囲内で$1..n$。 

このルールにより、固定オフセットによるシフトにより円が分割されるため、すべての頂点がラウンドごとに 1 回だけ使用されることが保証されます。 
3. このラウンドで形成されたすべてのペアを出力します。 
4. 無効なセルフペアリングと重複を強制的にスキップします。$i < j$。 
5. すべてのラウンドで繰り返し、生成します$n$合計のマッチング。 

幾何学的な直観は、各ラウンドが一定の周期的な「距離」で頂点を接続するということです。 これらの弦は頂点ごとに異なって見えますが、1 つの固定オフセット内では交差しない構造を形成します。つまり、すべてのエッジは周期的な意味で平行であり、交差することはできません。 

### なぜ効果があるのか

 不変条件は、各ラウンドが頂点の順列を定義し、すべての頂点が他の 1 つの頂点に正確に一致し、循環オフセット構造によりエンドポイントのインターリーブが防止されることです。 凸多角形の場合、2つの弦$(a,b)$そして$(c,d)$エンドポイントが循環順序でインターリーブする場合にのみ交差します。 この構造により、固定ラウンドではすべてのペアが一貫した順序付け制約を遵守するため、インターリーブ パターンが発生することはありません。 それぞれの$\binom{n}{2}$エッジが 1 回だけ割り当てられると、分解は完了します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    if n == 2:
        print(1)
        print(1)
        print(1, 2)
        return

    rounds = n
    print(rounds)

    # 1-indexed convenience
    for r in range(n):
        pairs = []
        used = [False] * (n + 1)

        for i in range(1, n + 1):
            if used[i]:
                continue
            j = (i + r)
            j = (j - 1) % n + 1

            if j == i:
                continue

            if not used[j]:
                used[i] = used[j] = True
                pairs.append((i, j))

        print(len(pairs))
        for a, b in pairs:
            print(a, b)

if __name__ == "__main__":
    solve()
```コードは各ラウンドを独立してビルドします。 の`used`配列は、各頂点がラウンドごとに最大 1 つの交換に参加することを保証し、マッチング制約を強制します。 循環シフト`(i + r)`一貫した構造でパートナー候補を生成し、モジュロ演算によってインデックスが円の周囲にラップされます。 

特別な場合$n=2$一般的な構造は引き続き機能しますが、出力形式がより単純になり、構造が 1 つのペアに縮退するため、個別に処理されます。 

よくある実装上の間違いは、一致制約を明示的に適用するのを忘れることです。 理論的な構造がそれを暗示している場合でも、偶発的な二重代入を避けるために、コードではラウンドごとの使用状況を追跡する方が安全です。

 ## 特殊なケース

 のために$n=2$、可能な交換は 1 つだけであるため、アルゴリズムはペアを含む 1 つのラウンドを直接出力します。$(1,2)$。 一般的な循環構築でもこのペアは正しく割り当てられますが、明示的な分岐により不必要な構造が回避されます。 

奇数の場合$n$、パリティのため、各ラウンドの 1 つの頂点が一致しないままになります。 循環ペアリングにより、ラウンドごとに 1 つの頂点が未使用のまま残されることが保証され、すべてのラウンドにわたって、すべての頂点が必要なすべてのペアリングに 1 回だけ参加します。 

のために$n=4$、ジオメトリでは多くの無効なペアの組み合わせが許可されるため、交差の回避は最もデリケートです。 この構造では、ラウンド内のエンドポイントのインターリーブを回避するため、次のようなペアになります。$(1,3)$そして$(2,4)$順序制約に違反するような構成にまとめて配置することはできません。
