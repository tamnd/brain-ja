 ## 解決策
 ## 問題の理解

 長さの順列を構築するように求められます$n$バイナリ文字列によって決定される位置の最大制約を満たす$s$そして整数$k$。 あらゆるポジションについて$i$どこ$s_i = 1$を確保する必要があります。$p_i$少なくとも次の長さの連続する部分配列の最大値になることはありません$k$含まれている$i$。 とのポジション$s_i = 0$制限はありません。 そのような順列が存在できない場合は、「いいえ」と報告します。 

制約により許可されるのは、$n$まで$2 \cdot 10^5$複数のテストケースにわたって。 これにより、次のようなアルゴリズムが除外されます。$O(n^2)$最悪の場合の合計操作数が超過する可能性があるため、$10^{10}$。 必要なのは$O(n \log n)$あるいはそれ以上の、理想的には$O(n)$、テストケースごとのソリューション。 

連続する 1 が多すぎる場合、微妙なエッジケースが発生します。$k$。 たとえば、次の場合$s = 1111$そして$k = 3$、4 つの 1 のブロック内の要素はいずれも、長さ 3 以上の間隔内にあり、割り当てられた要素が連続している場合、そのうちの 1 つが必然的にある間隔の最大値になります。 これにより、並べ替えが不可能になる可能性があります。 もう 1 つのエッジケースは次のような場合です$k = 1$; すべての要素に$s_i = 1$は長さ 1 の間隔内にあり、自明のことながらそれ自体が含まれますが、問題により許容されます。$p_i$長さ 1 の間隔の最大値にならないようにしてください。 これは、最大値と最小値の割り当て方法を変更するため重要です。 

## アプローチ

 ブルートフォースアプローチでは、すべての順列を試し、少なくとも長さのすべてのサブ配列をチェックします。$k$これは明らかに実行不可能です。順列ごとに、$n!$可能性があり、すべての間隔を確認するには時間がかかる可能性があります$O(n^2)$。 ですから、たとえ小さなものであっても、$n$これでは遅すぎます。 

重要な観察は、制約が 1 の場合にのみ重要であるということです。 0 には、任意の番号を自由に割り当てることができます。 どのような長さの区間でも 1 が最大値にならないようにするため$\ge k$それが含まれている場合、すべての 1 の位置に比較的小さな数値を割り当て、すべての 0 の位置に比較的大きな数値を割り当てることができます。 次に、任意の長さの間隔で$k$それ以上の場合、1 の位置の数値よりも大きい数値を持つ 0 が少なくとも 1 つ存在し、最大の 1 がないことが保証されます。 

ただし、限界があります。 連続する 1 のブロックの長さが次の値を超える場合$k$、その場合、長さが存在します-$k$間隔は完全にこのブロック内にあります。 その間隔内の数値はすべて小さいため、最大値は必然的に 1 のいずれかになります。 したがって、1 の最長連続ブロックが次の値より小さいかどうかを確認する必要があります。$k$。 そうであれば、有効な割り当てが可能です。 そうでなければ不可能です。 

これは建設的なアプローチを提供します。つまり、最小の数値を順番に 1 に割り当て、最大の数値を順番に 0 に割り当てます。 文字列を反復処理して数値のリストを埋めるだけです。

 ## アルゴリズムのチュートリアル

 1. バイナリ文字列を反復処理します。$s$そして、1 の最も長い連続セグメントの長さを見つけます。 この長さなら$\ge k$、常に長さが存在するため、「NO」を出力します。$k$1 の間隔で、そのうちの 1 つが最大になります。 
2. 1 の最長セグメントが以下の場合$k$、「YES」を出力します。 順列を構築できます。 
3. 2 つのリストを準備します。1 つは 1 に割り当てる番号 (1 から始まる) で、もう 1 つは 0 に割り当てる番号 (0 から始まる) です。$n$下向き）。 
4. 反復処理する$s$順番に。 ポジションごとに$i$、 もし$s_i = 1$、次に小さい未使用の番号を割り当てます。 もし$s_i = 0$、次に大きい未使用の番号を割り当てます。 
5. 構築された順列を出力します。 

機能する理由: 小さい数値を 1 に割り当て、大きい数値を 0 に割り当てることで、少なくとも任意の長さの間隔が得られます。$k$少なくとも 1 つの 0 が含まれる場合、0 の数値が 1 の数値より大きくなり、最大の 1 が存在しないことが保証されます。 連続する最長の 1 ブロックは次の値より小さいため、$k$、任意の長さの間隔$k$or more には、少なくとも 1 つの 0 が含まれている必要があります。したがって、構築は常に制約を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    s = input().strip()
    
    # Step 1: check longest consecutive 1s
    max_ones = 0
    cur = 0
    for ch in s:
        if ch == '1':
            cur += 1
            max_ones = max(max_ones, cur)
        else:
            cur = 0
    
    if max_ones >= k:
        print("NO")
        continue
    
    # Step 2: construct permutation
    perm = [0] * n
    low = 1
    high = n
    for i, ch in enumerate(s):
        if ch == '1':
            perm[i] = low
            low += 1
        else:
            perm[i] = high
            high -= 1
    print("YES")
    print(' '.join(map(str, perm)))
```最初の部分では、文字列を反復処理して、最も長く連続する 1 のブロックを見つけます。 これは、順列が不可能である可能性がある唯一の点です。 2 番目の部分は建設的な割り当てです。2 つのポインター (low と high) を使用すると、すべての数値が 1 回だけ使用され、1 が最小の数値を取得し、0 が最大の数値を取得します。 off-by-one エラーは、low = 1 および high = n を注意深く初期化し、割り当ての直後にインクリメントまたはデクリメントすることで回避されます。
