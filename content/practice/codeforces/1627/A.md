 ## 解決策
 ## 問題の理解

 最大 50 x 50 のサイズの小さなグリッドが与えられ、各セルは黒または白になります。 任意の黒いセルから、非常に特殊な方法で黒を広げる操作を実行できます。つまり、1 つの黒いセルを選択し、その行全体を黒くペイントするか、その列全体を黒くペイントします。 このようなアクションごとに 1 回の移動が必要になります。 

目標は、できるだけ少ない操作で特定のターゲット セルを黒にすることです。 グリッド全体を再描画するように求められるのではなく、これらの拡散操作を適用した後に 1 つの固定座標が確実に黒になるようにするだけです。 

制約が十分小さいため、テスト ケースごとに多くの可能性をチェックすることも可能です。 最大 100 個のテスト ケースと最大 50 x 50 のサイズのグリッドでは、$O(nm)$あるいは$O(nm(n+m))$解決策は十分に速いでしょう。 

主な微妙な点は、操作は既存の黒いセルからのみトリガーできることです。 これにより依存関係が作成されます。行または列に黒いセルが含まれていない場合、それを使用して何も展開することはできません。 

間違いやすいいくつかの危険な状況があります。 

ターゲットのセルがすでに黒である場合、答えは自明のことながらゼロです。 常に「拡散」しようとする単純なソリューションでは、操作が必要ない場合でも、誤って 1 を返す可能性があります。 

ターゲット行にもターゲット列にも黒のセルがない場合、どの操作もターゲット セルに影響を与えることはできません。 例えば：```
3 3
WWW
WWW
WWW
target = (2,2)
```どこにも黒いセルがないため、操作を開始することさえできないため、正解は -1 です。 

より微妙なケースは、ターゲット セルが白であるが、その行と列の両方にすでに黒のセルが含まれている場合です。 答えは自動的に 1 か 2 になるわけではありません。 それらの黒細胞がどこにあるのかという構造が重要です。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての操作シーケンスをシミュレートしようとします。 すべての黒いセルから、その行または列を展開して、新しいグリッド状態を生成できます。 対象のセルが黒くなるまでこれを繰り返します。 これは事実上、グリッド構成上の BFS です。 

問題は、各操作によってグリッドが大幅に変更される可能性があり、可能な状態の数が非常に急速に増加することです。 グリッドが小さい場合でも、状態空間の操作数は指数関数的に増加するため、このアプローチは実行不可能になります。 

重要な観察は、完全なグリッド状態を追跡する必要がまったくないということです。 重要なのは、行または列にターゲットを「カバー」できる黒いセルが含まれる構成に到達できるかどうかだけです。 

ターゲットセルがすでに黒であれば、作業は完了です。 

そうでない場合は、ターゲットと同じ行またはターゲットと同じ列に黒セルが存在するかどうかを確認します。 そのようなセルが存在する場合は、1 つの操作で十分です。そのセルを選択し、その行または列をペイントしてターゲットをカバーします。 

ターゲット行にもターゲット列にも黒セルが含まれていない場合は、いくら操作を行っても、ターゲットに合わせて黒セルを導入する方法はありません。 その場合、回答は不可能です。 

これにより、問題はターゲットの行と列の単純な存在チェックに軽減されます。

 | ブルート フォース (状態 BFS) | 指数 | 指数 | 遅すぎる |
 | 最適 (行/列スキャン) |$O(nm)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取り、ターゲットセルを見つけます。$(r, c)$。 便宜上、インデックスをゼロベースに調整します。 これにより、配列への直接アクセスが可能になります。 
2. ターゲットセルがすでに黒である場合、0 を出力します。目標はすでに満たされているため、操作は必要ありません。 
3. 行全体をスキャンします$r$。 その行の少なくとも 1 つのセルが黒である場合は、その行に使用可能なソースがあることを記録します。 
4. 列全体をスキャンします$c$。 その列の少なくとも 1 つのセルが黒である場合は、その列に使用可能なソースがあることを記録します。 
5. 行にも列にも黒いセルが含まれていない場合は、-1 を出力します。 ターゲットの位置に影響を与える可能性のある開始点はありません。 
6. それ以外の場合は、1 を出力します。同じ行または列の黒セルはターゲットに直接広がる可能性があるため、1 回の操作で十分です。 

### なぜ効果があるのか

 すべての操作は黒いセルから開始する必要があります。 1 回の移動でターゲット セルに影響を与える唯一の方法は、その行または列を共有する黒のセルを選択することです。これは、その行を介して伝播される操作がこれらのみであるためです。 このような黒いセルが存在する場合、1 回の操作でターゲットが即座に黒になります。 どちらの次元にも存在しない場合、操作によってすでに到達可能な行または列の外側に黒いセルが導入されることはないため、一連の操作によって必要な位置合わせを作成することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m, r, c = map(int, input().split())
    r -= 1
    c -= 1

    grid = [input().strip() for _ in range(n)]

    if grid[r][c] == 'B':
        print(0)
        continue

    row_has_black = any(ch == 'B' for ch in grid[r])
    col_has_black = any(grid[i][c] == 'B' for i in range(n))

    if row_has_black or col_has_black:
        print(1)
    else:
        print(-1)
```実装はアルゴリズムに直接従います。 最初のチェックは、作業が必要ない簡単なケースを処理します。 行と列のスキャンは単純な線形パスです。 重要な決定は最終条件です。黒のセルを操作のソースとして選択できるため、いずれかの次元に存在していれば、単一の操作で十分であることが保証されます。 

入力では 1 から始まる座標が使用されるため、インデックス付けには注意が必要です。 早期に変換すると、調整を繰り返す必要がなくなります。

    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, m, r, c = map(int, input().split())
        r -= 1
        c -= 1
        grid = [input().strip() for _ in range(n)]

            out.append("0")
            continue

        row_has = any(ch == 'B' for ch in grid[r])
        col_has = any(grid[i][c] == 'B' for i in range(n))

        if row_has or col_has:
            out.append("1")
        else:
            out.append("-1")

    return "\n".join(out)

 ## 特殊なケース

 黒いセルのないグリッドは、既存のソースに厳密に依存していることを示しています。 アルゴリズムは行と列の両方を正しくチェックしますが、どちらも見つからず、-1 が生成されます。 

ターゲット自体が黒であるグリッドは、スキャンの前に一定時間で処理され、不必要な計算が防止されます。 

列のみが黒いセルを含むグリッドでも、そのセルを選択してその列をペイントするとターゲットに直接影響するため、有効な操作が可能になります。 カラムのスキャンにより、このシナリオの検出が保証されます。 

黒のセルが存在するが、ターゲットの行と列の両方から離れて孤立しているグリッドは、許可された移動の下ではどの操作もそのギャップを埋めることができないため、正しく -1 を返します。
