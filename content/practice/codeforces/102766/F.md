 ## 解決策
 ## 問題の理解

 可能なキーが 2 つしかないキーボードがありますが、`a`そして`b`。 キーが押されたとき、キーボードは文字を一度も出力しません。 代わりに、その文字のコピーが 2 つまたは 3 つ印刷されます。 Singhal が押すキーの順序を考えると、最終的にいくつの異なる文字列が表示されるかを数える必要があります。 

入力にはいくつかの元の文字列が含まれています。 各文字列には次の内容のみが含まれます`a`そして`b`、それぞれの出力は、生成できる個別の文字列の数を法で表したものになります。`10^9 + 7`。 

主な問題は、展開の選択が異なると、最終的な文字列が同じになる可能性があることです。 たとえば、`a`2回生産できる`aaaa`、`aaaaa`、 または`aaaaaa`。 結果`aaaaa`最初のものを展開することで作成できます`a`長さ 2 に、2 番目の長さは 3、またはその逆です。 結果の文字列は 1 回だけカウントされます。 

すべての入力文字列の合計の長さは最大でも`10^5`。 組み合わせの数が指数関数的に増加するため、これにより、考えられるすべての出力が生成されなくなります。 文字列に長さがある場合`n`、すでにあります`2^n`各キーを押すと 2 文字になるか 3 文字になるかを選択できます。 中程度の場合でも`n`、これは 1 秒のソリューションで処理できる範囲をはるかに超えています。 各文字を一定の回数処理するカウント式を見つける必要があります。 

トリッキーなケースは、連続する等しい文字から発生します。 単純なアプローチでは、すべてのキー押下を独立して処理し、文字ごとに 2 つの選択肢を掛け合わせる可能性があります。 最終的な文字列では隣接する等しい文字が 1 つの連続したブロックを形成するため、この値は大きくなります。 

例えば：```
Input:
aa

Correct output:
3
```可能な出力は次のとおりです。`aaaa`、`aaaaa`、 そして`aaaaaa`。 2 つの独立した選択肢を乗算すると 4 つの可能性が得られますが、2 つの異なる展開選択肢では同じ中央の文字列が生成されます。 

もう 1 つの重要なケースは、すべてのキャラクターが近隣のキャラクターと異なる場合です。```
Input:
aba

Correct output:
8
```各文字は独自の個別のブロックを作成するため、選択するたびに最終的な文字列が変わります。 可能なブロック長は 2 または 3 として独立して選択され、次のようになります。`2 * 2 * 2 = 8`結果。 

最後のエッジケースは単一の文字です。```
Input:
b

Correct output:
2
```唯一の可能性は、`bb`そして`bbb`。 アルゴリズムは、1 回のみ実行された文字列を正しく処理する必要があります。 

## アプローチ

 ブルートフォース手法では、考えられるすべてのキーボード動作をシミュレートします。 すべての文字について、長さを 2 に拡張するか 3 に拡張するかを選択し、結果の文字列を構築して、すべての結果をセットに保存します。 セットは重複を自動的に削除するため、これは正しいです。 

ただし、ある長さの文字列の場合、`n`、 がある`2^n`拡張の選択肢。 長さの文字列`50`すでに 1,000 兆を超える可能性が生じているため、この方法は制約の下では機能しません。 

有益な観察は、同じ文字の連続を観察することで得られます。 長さのある同じ文字の連続したブロックを考慮します。`k`。 このブロック内のすべての文字は 2 つまたは 3 つのコピーに展開されるため、ブロックの合計の長さは次のいずれかの値になります。`2k`に`3k`。 各文字が 2 文字、または 2 文字と 1 文字の追加文字に寄与するため、この間隔のあらゆる長さが可能です。 

このブロックで可能な最終的な長さの数は次のとおりです。```
3k - 2k + 1 = k + 1
```隣接するブロックには異なる文字が含まれるため、異なる文字ブロックが互いに干渉することはできません。 最終的な文字列は、各ブロックの拡張された長さによって完全に決定されます。 したがって、可能な文字列の数は、実行ごとの選択肢の数の積になります。 

この総当たり法は、すべての展開の選択肢が個別に考慮されるため機能しますが、多くの選択肢が同じランレングスに集約されるため失敗します。 文字列をランに圧縮すると、この重複が削除され、問題が単純な乗算に軽減されます。

 ## アルゴリズムのチュートリアル

 1. 文字列を左から右にスキャンし、等しい文字の連続するグループを特定します。 グループは 1 つのブロックを表し、展開後も 1 つの文字ブロックのままになります。 
2. 長さのあるグループごとに`k`、答えを乗算します`k + 1`。 この値は、このブロックの可能なすべての最終長さを表します。`2k`を通して`3k`。 
3. すべてのグループが処理されるまで続行します。 乗算をモジュロの下に保つ`10^9 + 7`可能な文字列の数が非常に多くなる可能性があるためです。 

なぜ効果があるのか:

 最終的な文字列は、元の文字列の拡張された長さによって一意に記述することができます。 異なるランのキャラクターが交互に登場するため、各ランの長さを知ることで、各キャラクターがどこで変化するかを正確に知ることができます。 長いラン`k`まさに`k + 1`拡張可能な長さ。 各実行はその長さを独立して選択できるため、これらの値を乗算すると、考えられるすべての最終文字列が 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        s = input().strip()

        result = 1
        current = 1

        for i in range(1, len(s)):
            if s[i] == s[i - 1]:
                current += 1
            else:
                result = (result * (current + 1)) % MOD
                current = 1

        result = (result * (current + 1)) % MOD
        ans.append(str(result))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```変数`current`現在の実行のサイズを保存します。 キャラクターが変わるたびに、その実行は終了し、その要因に寄与します。`current + 1`。 

乗算をトリガーする次の文字がないため、最後の実行ではループの後に別の処理が必要になります。 このステップを忘れると、間違った答えが生まれる可能性が高くなります。 

モジュロ演算は、乗算のたびに適用されます。 Python の整数はオーバーフローしませんが、値を減らしたままにすることで不必要な増大を防ぎ、必要な出力と一致します。 

このアルゴリズムは実行のみをカウントするため、展開された文字列や実行構造さえも保存する必要はありません。 入出力ストレージとは別に、一定の追加メモリを使用します。

## テストケース```python
import sys
import io

MOD = 10 ** 9 + 7

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        s = input().strip()

        ans = 1
        run = 1

        for i in range(1, len(s)):
            if s[i] == s[i - 1]:
                run += 1
            else:
                ans = ans * (run + 1) % MOD
                run = 1

        ans = ans * (run + 1) % MOD
        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 入力の場合:```
aa
```アルゴリズムは 1 つの長さの実行を認識します`2`。 答えを乗算します`2 + 1`、生産`3`。 可能な 3 つの最終文字列は次のとおりです。`aaaa`、`aaaaa`、 そして`aaaaaa`。 合計ランレングスのみが重要であるため、異なる展開次数は個別にカウントされません。 

入力の場合:```
aba
```アルゴリズムは 3 つの長さのランを処理します`1`。 それぞれが次の要因に寄与します`2 +?`修正: 長さの各ラン`1`貢献する`1 + 1 = 2`、したがって、答えは次のようになります`2 * 2 * 2 = 8`。 実行には異なる文字が含まれるため、2 つの選択肢を最終的に同じ文字列にマージすることはできません。 

入力の場合:```
b
```長さのあるランが 1 つあります`1`。 可能な長さは次のとおりです。`2`そして`3`、因数を与える`1 + 1 = 2`。 スキャン終了後に最後の実行が乗算されるため、アルゴリズムはこのケースを処理します。
