 ## 解決策
 ## 問題の理解

 左括弧のみで構成される文字列が与えられます`(`そして閉じ括弧`)`。 これを通常の括弧シーケンスに変換したいと思います。 許可されている 2 つの操作には異なる効果があります。文字を削除すると 1 つの括弧が完全に削除されますが、文字を最後に移動すると括弧は保持されますが、その位置は変更されます。 

通常の括弧シーケンスには 2 つの要件があります。 開き括弧と閉じ括弧の合計数は等しくなければなりません。シーケンスを左から右に読んでいる間、これまでに表示された開き括弧の数が閉じ括弧の数より小さくなることはありません。 入力にはいくつかの独立したケースが含まれており、それぞれに文字列の長さと 2 つの操作のコストが含まれ、その後に括弧文字列が続きます。 出力は、すべてのケースを有効にするために必要な最小コストです。 

すべての文字列の合計の長さは最大でも$10^5$したがって、解は線形に近いものでなければなりません。 二次関数の解法はすでに遅すぎます。$10^5$周りに作成します$10^{10}$調べる位置のペア。 コストの値が大きいということは、応答が 32 ビット整数の範囲を超える可能性があるため、実装では 64 ビット整数を使用する必要があることも意味します。 

いくつかのケースでは、誤って対処されやすいものがあります。 文字列がすでに有効である場合、答えはゼロです。 

例えば：```
Input:
4 5 10
()()
```正しい出力は次のとおりです。```
0
```文字列を「修正」するために常に何らかの操作を実行するソリューションは、ここでは失敗します。 

もう 1 つの重要なケースは、文字列に含まれる括弧の種類の数が間違っている場合です。```
Input:

```正しい出力は次のとおりです。```
5000000000
```追加の閉じ括弧が 5 つあります。 それらを移動してもカウントは変わらないため、唯一の解決策は 5 つすべてを削除することです。 順序付けの問題のみをカウントする不用意なソリューションでは、誤ってはるかに小さい値が返される可能性があります。 

3 番目の注意が必要なケースは、削除よりも移動の方が安い場合です。```
Input:

```正しい出力は次のとおりです。```

```シーケンスには各括弧の番号が正しいですが、順序が無効です。 削除すると、最初のものを移動するよりもはるかに費用がかかります`)`最後まで。 

## アプローチ

 直接的な総当たりアプローチでは、移動可能なすべての文字セットと削除可能なすべての文字セットを試行し、残りのシーケンスが規則的であるかどうかを確認します。 これは、考えられるすべての操作シーケンスが表現されているため正しいですが、完全に非現実的です。 どのキャラクターを動かすかを決めるだけでも、すでに$2^n$可能性があり、すべての可能性をチェックすることは不可能です$n=10^5$。 

重要な観察結果は、2 つの運用コストを比較することで得られます。 削除の方が移動よりもコストが高くない場合、ブラケットを移動する理由はありません。 移動によって変更されるのはブラケットの位置だけであり、少なくともブラケットを取り外すのと同じくらいの費用がかかります。 最も安価な戦略は、シーケンスが規則的になるのを妨げる括弧を単純に削除することです。 

引越しの方が安い場合は、注文だけの問題であれば引越しを利用すべきです。 ただし、移動によって開始括弧と終了括弧の数を変更することはできないため、2 つの数の差は削除によって削除する必要があります。 

必要な削除を行った後、残りの文字列には両方の括弧の数が同じになります。 このような文字列の場合、必要な最小移動数は、左から右へのスキャン中に見つかった一致しない閉じ括弧の数とまったく同じです。 このようなすべての閉じ括弧は、残高がマイナスになるプレフィックスを作成し、これらの閉じ括弧を最後に移動すると、プレフィックスの順序が固定されます。 すべてのマイナス点は、問題のある閉じ括弧をプレフィックスから 1 つ削除する必要があるため、これ以上多くの手を実行することはできません。 

残る問題は、引っ越しの際にどちらのブラケットを削除した方が安くなるかということです。 開始括弧が多すぎる場合は、影響を受けるプレフィックスが最小限に抑えられるため、末尾近くの開始括弧を削除するのが最適です。 閉じ括弧が多すぎる場合は、先頭近くの閉じ括弧を削除するのが最適です。これにより、後のバランスができるだけ大きくなります。 これらの選択により、可能な限りバランスが保たれ、必要な移動の数が最小限に抑えられます。

 ## アルゴリズムのチュートリアル

 1. 開き括弧と閉じ括弧の数を数えます。 削除する方が移動するよりも安いか同等である場合は、一致しない開始括弧と終了括弧を直接カウントします。 答えは、削除の数と削除のコストを掛けたものです。 
2. 引っ越しの方が安い場合は、まずやむを得ず余ったブラケットを取り外します。 さらに開始ブラケットがある場合は、端から余分な開始ブラケットを削除します。 さらに閉じ括弧がある場合は、最初から余分な閉じ括弧を削除します。 これにより、可能な限り最大のプレフィックスバランスが残ります。 
3. 残りのシーケンスをスキャンし、ランニングバランスを維持します。`(`1つ追加して、`)`1を減算します。 残高がマイナスになるたびに、右括弧を 1 つ最後に移動する必要があります。 これが何回起こるかを数えてください。 
4. 移動回数に移動コストを掛け、最初のステップからの削除コストを加算します。 

これが機能する理由: 必要な削除を行った後、残りの文字列には同じ数の左括弧と右括弧が含まれます。 通常の括弧シーケンスは、プレフィックスに含まれる閉じ括弧が多すぎる場合にのみ失敗します。 余分な閉じ括弧を正確に最後に移動すると、そのようなすべての違反が削除され、各違反はプレフィックスを残す必要がある個別の閉じ括弧に対応します。 削除を選択すると、可能な限り最大のプレフィックスバランスが維持されるため、後で必要な移動の数が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, a, b, s):
    opens = s.count('(')
    closes = n - opens

    if a <= b:
        balance = 0
        bad_close = 0
        for c in s:
            if c == '(':
                balance += 1
            else:
                balance -= 1
                if balance < 0:
                    bad_close += 1
                    balance = 0
        bad_open = balance
        return (bad_close + bad_open) * a

    if opens > closes:
        extra = opens - closes
        removed = 0
        chars = []
        for c in reversed(s):
            if c == '(' and removed < extra:
                removed += 1
            else:
                chars.append(c)
        chars.reverse()
        s = ''.join(chars)

        balance = 0
        moves = 0
        for c in s:
            if c == '(':
                balance += 1
            else:
                balance -= 1
                if balance < 0:
                    moves += 1
                    balance = 0

        return extra * a + moves * b

    if closes > opens:
        extra = closes - opens
        removed = 0
        chars = []
        for c in s:
            if c == ')' and removed < extra:
                removed += 1
            else:
                chars.append(c)
        s = ''.join(chars)

        balance = 0
        moves = 0
        for c in s:
            if c == '(':
                balance += 1
            else:
                balance -= 1
                if balance < 0:
                    moves += 1
                    balance = 0

        return extra * a + moves * b

    balance = 0
    moves = 0
    for c in s:
        if c == '(':
            balance += 1
        else:
            balance -= 1
            if balance < 0:
                moves += 1
                balance = 0

    return moves * b

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        n, a, b = map(int, input().split())
        s = input().strip()
        ans.append(str(solve_case(n, a, b, s)))
    print('\n'.join(ans))

if __name__ == "__main__":
    main()
```最初のブランチは、削除が優勢な場合を処理します。 スキャンでは、開始括弧が十分に存在する前に出現する閉じ括弧がカウントされ、スキャン後の残りの残高は、一致しない開始括弧の数とまったく同じになります。 

移動の方が安い場合、コードは最初に避けられない余分なブラケットのみを削除します。 取り外す方向が重要です。 余分な左括弧は右側から削除されます。これは、これらを先に削除すると多くのプレフィックスのバランスが低下するためです。 余分な閉じ括弧はプレフィックスに最も悪影響を与えるものであるため、左側から削除されます。 

最終スキャンでは、必要な移動数がカウントされます。 負の値が見つかった後は、一致しない右括弧が移動されるため、残高はゼロにリセットされます。 費用は以下に達する可能性があります$5 \times 10^{13}$したがって、Python の整数は必要な範囲を自然に処理します。
