 ## 解決策
 ## 問題の理解

 文字列には小文字が含まれており、出現するすべての文字の頻度がまったく同じになるまで文字列を変更することが目標です。 1 回の操作で、既存の 1 文字が他の小文字に変更されます。 タスクは、必要なそのような変更の最小数を見つけることです。 

たとえば、文字列にカウントがある場合、`a = 5`、`b = 2`、 そして`c = 1`では、一部の文字を他の既存の文字に変換して削除することも、新しい文字を作成することもできます。 最後の文字列には、任意の数の個別の文字を含めることができますが、残りのすべての文字は同じ数でなければなりません。 

入力には複数の独立した文字列が含まれています。 テスト ケースの数は次のように大きくなります。`10^5`、すべての文字列の長さの合計も最大で`10^5`。 これは、解が合計入力サイズにおいて線形に近い必要があることを意味します。 多くの変更を試みたり、変換された文字列をすべてスキャンしたりするソリューションは不可能ですが、文字ごとに少量の作業を行うアプローチは簡単に適合します。 

いくつかのケースでは注意が必要です。 すべての文字がすでに等しい頻度を持っている場合は、操作は必要ありません。 入力の場合:```
1
aabb
```答えは`0`両方の文字がすでに 2 回出現しているためです。 常にすべてを 1 つの文字にマージしようとするメソッドは、誤った結果を返します。`2`。 

1 文字を含む文字列は別の境界ケースです。```
1
aaaa
```答えは`0`。 文字列にはすでに 1 つの異なる文字が含まれており、すべての異なる文字、つまり 1 つだけを意味するため、条件は満たされます。`a`、同じ周波数を持っています。 

それほど明白ではないケースは、最良の回答に元の文字列とは異なる数の個別の文字が導入される場合です。 のために：```
1
aba
```答えは`1`。 私たちは変えることができる`b`の中へ`a`そして手に入れる`aaa`、またはいずれかを変更します`a`の中へ`c`そして手に入れる`abc`。 現在存在する文字のバランスを取るだけのソリューションでは、個別の文字を追加または削除する可能性が失われます。 

## アプローチ

 直接的なアプローチは、個別の文字の最終的な数、残る文字、およびそれらの目標頻度を推測することです。 推測ごとに、希望する最終的な配置にすでに一致する文字の数を数え、残りを変更できます。 考えられるすべての最終状態が考慮されるため、これは正しいですが、考えられる状態の数が多すぎます。 

重要な観察は、使用できる小文字が 26 個しかないという事実から来ています。 個別の文字の最終的な数は、文字列の長さの約数でなければなりません。`k`登場人物とそれぞれの登場人物`x`回、それから`k * x = |S|`。 以来`k`26 を超えることはできないため、非常に少数の可能性をチェックするだけで済みます。 

選択するとします`k`最後の文字。 必要な頻度は`|S| / k`。 現在の周波数で選択された文字`c`せいぜい貢献できる`min(c, |S| / k)`変わらない文字たち。 目標頻度を超えるキャラクターを保持する場合は、余分なコピーを変更する必要があります。 コピー数が少ない場合は、他の文字からの変更を使用して追加のコピーを作成する必要があります。 

固定の場合`k`、最良の選択は、`k`可能な限り最大の貢献をした手紙。 変更しないことができるポジションの最大数を計算した後、残りのポジションがまさに必要な操作になります。 

ブルート フォースは、可能な最終構成を調べるため機能しますが、26 文字を巨大な検索スペースが作成されるかのように扱うため、失敗します。 異なる文字の最終的な数のみが重要であるという観察により、問題は最大 26 個のケースをチェックすることになります。

 | --- | --- | --- | --- |
 | ブルートフォース | 可能な最終状態の数の指数関数 | お(26) | 遅すぎる |
 | 最適 | 文字列ごとに O(26 × 26) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列内のすべての小文字の頻度を数えます。 アルファベットのサイズは固定されているため、必要なカウンターは 26 個だけです。 
2. 可能な限りすべての数の最終的な個別の文字を試します`k`から`1`に`26`。 の値を無視します`k`これは文字列の長さを分割しません。それ以外の場合は、等しい度数の合計を合計した長さにすることができないためです。 
3. 有効な場合`k`、ターゲット周波数を計算します`need = length / k`。 すべての文字について、この文字が最終文字の 1 つである場合に、現在出現している文字のうち何個が変更されないままになるかを計算します。`k`手紙。 この値は`min(current_frequency, need)`。 
4. これら 26 個の寄与値を並べ替えて、最大のものを取得します。`k`彼らのうち。 これらは最高のものを表します`k`最終文字列に保持する文字。 
5. 変更されていないポジションの数は、これらの選択された寄与の合計です。 この選択に必要な操作は次のとおりです。`length - unchanged_positions`。 有効なすべての値の中で最小値を維持します`k`。 

これが機能する理由: 選択した最終文字数に対して、すべての最終文字は正確に一致する必要があります。`need`出来事。 キャラクターはそれ以上のものを保持することはできません`need`別のキャラクターがそれらの保存された位置を使用する可能性があるため、保存する数を減らしても決して有益ではありません。 最大のものを選択する`k`貢献度は、そのターゲットに対して変更されずに存続できるポジションの最大数を示します。 考えられる有効な最終文字数がすべてチェックされるため、見つかった最小の答えが真の最適値となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        s = input().strip()
        n = len(s)

        cnt = [0] * 26
        for ch in s:
            cnt[ord(ch) - ord('a')] += 1

        best = n

        for k in range(1, 27):
            if n % k != 0:
                continue

            need = n // k
            keep = []

            for c in cnt:
                keep.append(min(c, need))

            keep.sort(reverse=True)
            unchanged = sum(keep[:k])

            best = min(best, n - unchanged)

        ans.append(str(best))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```文字数だけが答えに影響するため、頻度配列には入力の完全な状態が保存されます。 ループオーバー`k`最終的なアルファベットの可能なすべてのサイズをチェックします。 文字列の長さを分割できない値は、等しいグループを形成できないためスキップされます。 

それぞれの有効な`k`、コードは、変更せずに各文字が貢献できる量を構築します。 並べ替えでは最も有用な文字が最初に配置されるため、最初の文字を取得します。`k`値は、保持するのに最適な文字セットを提供します。 答えは、全長からこれらの保存された位置を差し引いたものです。 

すべての文字は次の値に変換されるため、インデックス作成の問題はありません。`0`に`25`。 Python の整数では、実際の値は小さいですが、オーバーフローの懸念も解消されます。

 ## 特殊なケース

 のために`aabb`、アルゴリズムがチェックします`k = 1`そして`k = 2`。 いつ`k = 2`、ターゲット周波数は`2`、両方の文字が貢献します`2`、4 つの位置はすべて変更されません。 答えは`0`, 文字列を無理に 1 文字にまとめてしまうという間違いを避けることができます。 

のために`aaaa`、1文字しか存在しませんが、`k = 1`長さが 1 で割り切れるため、有効です。 目標周波数は、`4`、そして文字は 4 つの位置すべてに貢献します。 アルゴリズムは戻ります`0`。 

のために`aba`、アルゴリズムは両方を考慮します`k = 1`そして`k = 3`。 と`k = 1`、最高の貢献度は変化しない 2 つです`a`文字。 と`k = 3`、最高の貢献は 1 つです`a`そして1つ`b`, 作成すべきキャラクターが 1 つ残っています。 どちらの選択肢も 1 回の操作が必要なので、最終的な答えは次のようになります。`1`。 

のために`abbbc`、有効な選択肢は次のとおりです。`k = 1`そして`k = 5`。 最初の選択は 3 つを保持します`b`文字を変更し、残りの 2 つを変更します。 2 番目の選択肢では、使用可能な各文字のコピーを 1 つ保持し、2 つの位置を変更して欠落している文字を作成します。 どちらも 2 つの操作につながり、文字の削除と文字の追加が同等に適切なケースをアルゴリズムが処理していることが確認されます。
