 ## 解決策
 ## 問題の理解

 いくつかの連続した整数を並べて書くことによって作成された文字列が与えられます。 整数は元々、ある開始値からの範囲を形成していました`n`終了値まで`m`、範囲内に少なくとも 3 つの数値が含まれます。 この範囲の中央のちょうど 1 つの整数が連結前にスキップされました。 タスクは、スキップされた整数を回復し、複数の範囲で文字列を説明できる場合は、可能な限り最小の欠損値を返すことです。 

たとえば、次の文字列`1314151718`次のように分割できます`13, 14, 15, 17, 18`、連続した範囲から取得されます。`13`に`18`と`16`削除されました。 答えは、残りのシーケンスではなく、欠落している値です。 

数値の上限は大きく、最大で`10^9`, したがって、範囲全体を生成することは不可能です。 範囲には膨大な数の整数を含めることができますが、入力文字列自体は長さのみを持ちます`10^5`。 合計入力サイズも次のように制限されます。`10^5`これは、ソリューションが各文字列の長さに対してほぼ直線的な時間で機能する必要があることを意味します。 考えられるすべての開始番号と終了番号を試すのはコストがかかりすぎます。 

トリッキーなケースは、文字列の先頭のあいまいさに起因します。 最初の数値が実際の開始値である場合もあれば、欠落している数値が範囲の最初の値である場合もあります。 たとえば、入力`13`数字を表すことができる`1, 2, 3`と`2`が足りないので、答えは`2`。 最初の数字列を常に最初の既存の数値として扱うソリューションでは、この可能性が失われます。 

もう 1 つの特殊なケースは、欠落している数値が範囲の末尾にある場合です。 たとえば、入力`123`表すことができた`1,2,3,4`と`4`ない。 隣接する解析された数値間のジャンプをチェックするだけのパーサーは、欠損値を決して検出せず、シーケンスを誤って拒否します。 

3 番目のケースは、桁の長さの変更です。 例えば、`899100101`を表します`89,90,91,101`分割が間違って選択された場合のみですが、有効な解釈には、2 桁から 3 桁への移行付近で欠落している数値が含まれる可能性があります。 パーサーは、固定桁数を仮定するのではなく、予想される数値全体を比較する必要があります。 

## アプローチ

 直接的なアプローチは、完全な連続シーケンスを推測することです。 考えられるすべての最初の数値を試し、文字列を繰り返し増加する整数に分割し、正確に 1 つの値がスキップされたかどうかを確認できます。 これは正しいです。有効な答えは、そのような連続したシーケンスから得られる必要があるからです。 問題は検索スペースです。 最初の数は大きくなる可能性があり、可能な分割はすぐに大きくなります。 ある長さの文字列のすべてのパーティションを探索する`10^5`現実的ではありません。 

有益な観察は、最初に存在する数値が文字列の先頭に現れる必要があるということです。 答えのすべての数値は以下より小さいため、`10^9`、最初の数字は最大 9 桁です。 これらのいくつかの考えられるプレフィックスを最初の番号の候補としてテストするだけで済みます。 

選択された開始番号について、シーケンスの残りの部分は決定的です。 私たちは次にどの数字が来るべきかを常に知っています。 文字列の次の部分が予想される数値と一致する場合、それを消費します。 一致しない場合、唯一許可される説明は、この予期された数値が欠落しており、文字列の現在の部分が次の数値である必要があるということです。 その後、欠損値はすでに使用されているため、以降のすべての数値は正確に一致する必要があります。 

これにより、問題は、多くのパーティションを検索することから、少数の可能な開始をそれぞれ線形時間でチェックすることに変換されます。

 ## アルゴリズムのチュートリアル

 1. 考えられるすべてのプレフィックス長を試します。`1`に`9`最初の数字として。 欠損値が以下であることが保証されているため、9 桁を超える接頭辞は有効な数値を表すことができません。`10^9`。 
2. 開始番号の候補ごとに、連続する整数を期待しながら残りの文字列を解析します。 最初の数値自体はシーケンスの開始を定義するため、すぐに使用されます。 
3. 次に期待される整数と、欠落している数値がすでに見つかっているかどうかを示すフラグを維持します。 次の文字が期待される整数と一致すると、それらを消費して期待値を増加させます。 
4. 期待される整数が文字列の現在の部分と一致しない場合は、その期待される整数を欠損値として扱います。 現在の部分はその後の番号と一致する必要があります。 このジャンプが複数回発生した場合、開始候補は無効になります。 
5. 文字列全体が消費された後、1 つの数字だけがスキップされたかどうかを確認します。 シーケンスが最後の既存の数値の直後に終了した場合、欠損値は次に期待される数値になります。 
6. すべての有効な候補の中で、最小の欠損値を返します。 

機能する理由: 開始番号が固定されている場合、表示される番号の順序は完全に決定されます。 すべての位置で、予想される数値が表示されるか、問題で許容される唯一の違いは、この予想される数値が省略されたことです。 省略が許可されるのは 1 つだけであるため、貪欲な解析では間違った番号をスキップすることはできません。 最初に存在する数値は範囲の真の開始値であるか、欠落している最初の値の直後の数値であるため、考えられるすべての最初の数値をテストすると、すべての有効な構成がカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(s):
    ans = 10**9

    def check(start):
        pos = 0
        cur = start
        missing = None

        first = str(start)
        if not s.startswith(first):
            return None
        pos += len(first)
        cur += 1

        while pos < len(s):
            expected = str(cur)
            if s.startswith(expected, pos):
                pos += len(expected)
                cur += 1
            else:
                if missing is not None:
                    return None
                nxt = str(cur + 1)
                if not s.startswith(nxt, pos):
                    return None
                missing = cur
                pos += len(nxt)
                cur += 2

        if missing is None:
            missing = cur

        return missing

    for length in range(1, min(9, len(s)) + 1):
        if length > 1 and s[0] == '0':
            continue
        start = int(s[:length])
        value = check(start)
        if value is not None:
            ans = min(ans, value)

    return str(ans)

def main():
    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        out.append(solve_case(s))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```この解決策では、まず最初の数値の可能な長さをすべて試します。 有効な数値は以下であるため、可能性は 9 つだけです`10^9`。 

の`check`関数は貪欲スキャンを実行します。 変数`cur`次に表示される番号を格納します。 文字列に次のものが含まれる場合`cur`、スキャンは正常に移動します。 そうでない場合、関数は次のことを検証します。`cur + 1`代わりに表示され、記録されます`cur`欠落番号として。 

最終条件は、欠落している最後の番号を処理します。 ギャップが見つからずにスキャンが終了した場合、唯一残っている可能性は、次に期待される番号が書き込まれなかったということです。 この実装では、Python の整数は自動的に増加するため、整数のオーバーフローが回避されますが、ここでの最大値は標準の 64 ビット整数にとっても十分小さいものです。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().split()
    sys.stdin = old

    def solve_case(s):
        ans = 10**9

        def check(start):
            pos = 0
            cur = start
            missing = None

            if not s.startswith(str(start)):
                return None
            pos += len(str(start))
            cur += 1

            while pos < len(s):
                if s.startswith(str(cur), pos):
                    pos += len(str(cur))
                    cur += 1
                else:
                    if missing is not None:
                        return None
                    if not s.startswith(str(cur + 1), pos):
                        return None
                    missing = cur
                    pos += len(str(cur + 1))
                    cur += 2

            return cur if missing is None else missing

        for i in range(1, min(9, len(s)) + 1):
            v = check(int(s[:i]))
            if v is not None:
                ans = min(ans, v)
        return str(ans)

    res = []
    for x in data[1:]:
        res.append(solve_case(x))
    return "\n".join(res)

 ## 特殊なケース

 欠落している数値が最初の値である場合、最初に存在する数値が欠落した数値の後の数値である可能性があるため、アルゴリズムはそれを処理します。 入力用`13`、候補スタート`1`シーケンスを次のように解析します`1,3`、欠損値は次のように検出されます。`2`。 候補者スタート`13`は無効であるか、より大きな解釈を与えるため、最小限の答えが残ります`2`。 

欠落している数値が最終値である場合、文字列内に目に見えるジャンプはありません。 入力用`123`、シーケンスは次のようになります。`1,2,3,4`と`4`ない。 パーサーは読み取り後に終了します`3`、ギャップが記録されていないことを確認し、次に期待される数値を欠損値として割り当てます。 

シーケンスが桁の長さをまたぐ場合、たとえば、`1314151718`、パーサーは固定幅のチャンクに依存しません。 すべてのステップで予想される数値の正確な 10 進表現を比較し、特別な処理を行わずに 2 桁と 3 桁の値の間で遷移できるようにします。
