 ## 解決策
 ## 問題の理解

 整数の配列が与えられているので、長さのサブシーケンスが正確にいくつあるかを数えなければなりません。`k`ラッキーナンバーに関する特別な制限を満たしていること。 

すべての 10 進数字が次のいずれかに該当する場合、その数字は幸運です。`4`または`7`。 例としては、`4`、`47`、 そして`744`。 のような数字`5`、`17`、 そして`467`幸運ではありません。 

サブシーケンスは、配列からインデックスを選択することによって形成されます。 2 つのサブシーケンスは、値が同じであっても、選択したインデックス セットが異なる場合は異なります。 

The restriction is subtle. ラッキー値は、選択したサブシーケンス内に最大 1 回出現する可能性があります。 Unlucky values may repeat any number of times.

 配列が次のようになっているとします。```
[4, 4, 10]
```そして`k = 2`。 

インデックスによって形成される部分列`{1,2}`2 つの等しいラッキーナンバーが含まれているため、無効です。`4`。 

サブシーケンス`{1,3}`そして`{2,3}`有効です。 

配列サイズが次の値に達しました`10^5`したがって、すべてのサブシーケンスを列挙することは不可能です。 がある`2^n`合計のサブシーケンス、さらにはサイズのすべてのサブシーケンスをチェックする`k`おおよそ必要になります`C(100000, 50000)`最悪の場合の操作は天文学的に大規模になります。 

この制約は、次のようなものが必要であることを強く示唆しています。`O(n log n)`または`O(nk)`小さな定数を使用します。 以来`k`もできます`10^5`、 平`O(nk)`有効状態空間が以下よりもはるかに小さい場合を除き、危険になります。`n`。 

重要な構造的観察は、次のような明確な幸運の数字がほとんど存在しないということです。`10^9`。 すべてのラッキーナンバーは数字のみで構成されています`4`そして`7`、最大 10 桁です。 合計数は次のとおりです。$\sum_{i=1}^{10} 2^i = 2046$したがって、配列には次のものが含まれる場合がありますが、`100000`要素、個別の幸運値の数は最大でも`2046`。 

いくつかのエッジケースでは、単純な実装が静かに破壊される可能性があります。 

考慮する：```
3 2
4 4 4
```正しい答えは、`0`。 

A careless solution might say there are`C(3,2)=3`サブシーケンスですが、すべてのペアに重複したラッキー値が含まれています`4`, したがって、すべて無効です。 

ここで次のことを考えてみましょう。```
4 2
10 10 10 10
```正しい答えは次のとおりです。$\binom{4}{2}=6$Unlucky 値には一意性の制限がないため、重複は完全に許可されます。 

もう 1 つの注意が必要なケースは次のとおりです。```
5 3
4 4 7 10 10
```有効なサブシーケンスには最大 1 つのサブシーケンスが含まれている必要があります`4`そして多くても1つ`7`。 

有効な選択肢は次のとおりです。```
{4(first),7,10(first)}
{4(first),7,10(second)}
{4(second),7,10(first)}
{4(second),7,10(second)}
```答えは`4`。 

個別の幸運の値を個別に追跡するのではなく、数字が幸運であるかどうかだけを追跡する単純な実装では、カウントを誤る可能性があります。 

## アプローチ

 ブルートフォースソリューションは概念的には単純です。 サイズのすべての部分列を列挙します`k`、その幸運な要素を検査し、何らかの幸運な値が 2 回出現する場合はそれを拒否します。 

これが機能するのは、定義がローカルであり、検証が簡単であるためです。 選択したインデックスのサブセットごとに、幸運な数字の頻度マップを構築し、すべての頻度が最大 1 であるかどうかを確認できます。 

問題はサブセットの数です。 最悪の場合、次のことを調べます。$\binom{100000}{50000}$それは完全に不可能です。 

次に自然な試みは、ポジションに対する動的プログラミングです。 各要素について、それを取得するかスキップします。 しかし、どの幸運の値がすでに使用されているかを正確に追跡すると、状態空間は個別の幸運の数の数において指数関数的になります。 

突破口は、幸運な要素と不運な要素を分離することから生まれます。 

不吉な数字は簡単です。 それらにはまったく制限がありません。 あれば`u`不運な要素があり、正確に取ることにしました`t`それらのうち、方法の数は単純に次のとおりです。$\binom{u}{t}$ラッキーナンバーは異なります。 幸運な値を仮定します`x`表示されます`cnt[x]`回。 次のいずれかを行うことができます。 

1. スキップ値`x`完全に。 
2. 出現するものを 1 つだけ選択します。`x`。 

それを選ぶとしたら、次のようなものがあります。`cnt[x]`異なるインデックスの選択。 

これにより、問題はグループ化されたナップザック スタイルの DP に変換されます。 

それぞれの個別のラッキー値は、次のいずれかに寄与するアイテム グループのように動作します。```
0 chosen elements, 1 way
1 chosen element, cnt[x] ways
```あれば`m`異なる幸運の値がある場合、これらのグループに対して DP を実行します。```
dp[j] = number of ways to choose j lucky elements
```幸運な寄与を計算した後、それを不運な寄与と組み合わせます。 

私たちが選んだなら`j`幸運な要素、まだ必要です`k-j`不運な要素。 貢献度の合計は次のようになります。$dp[j] \cdot \binom{u}{k-j}$有効なすべての合計`j`答えを出します。 

重要な削減点は、DP サイズが最大でも個別の幸運の値の数に依存することです。`2046`、 の代わりに`n`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n + m・k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、すべての数字を幸運か不運に分類します。 

すべての 10 進数字が次のいずれかに該当する場合、その数字は幸運です。`4`または`7`。 
2. それぞれの幸運な値が何回出現したかを数えます。 

周波数をハッシュマップに保存します。 値の場合`47`が 5 回表示された場合、これら 5 つの位置のうち 1 つを正確に選択できることを思い出してください。 
3. 不運な要素の総数を数えます。 

これらの要素には制限がないため、後で必要になるのは組み合わせだけです。 
4. 階乗および逆階乗モジュロを事前計算する`10^9+7`。 

これにより、組み合わせの定数時間計算が可能になります。$\binom{n}{r}=\frac{n!}{r!(n-r)!}$5. DP を初期化します。 

させて：```
dp[j] = number of ways to choose exactly j lucky elements
```最初に:```
dp[0] = 1
```なぜなら、何も選択しないことはいつでも可能だからです。 
6. それぞれの異なる幸運の値を個別に処理します。 

現在の周波数が`c`。 

繰り返します`j`逆方向に更新してください:```
dp[j+1] += dp[j] * c
```の乗算`c`なぜなら、その幸運な値の出現を 1 つ選択できるからです。 

逆方向反復により、同じラッキー値を複数回使用することがなくなります。 
7. 幸運な選択と不運な選択を組み合わせます。 

あらゆる可能なカウントに対して`j`選ばれた幸運の要素:```
need = k - j
```もし`0 <= need <= unlucky_count`、 追加：$dp[j] \cdot \binom{unlucky}{need}$8. 最終的な合計モジュロを出力します。`10^9+7`。 

### なぜ効果があるのか

 DP の不変条件は次のとおりです。```
dp[j] = number of valid ways to choose exactly j elements
        from the processed lucky-value groups,
        using at most one occurrence from each group
```それぞれの個別のラッキー値は 1 回処理されます。 遷移中は、値をスキップするか、出現する値の 1 つを正確に選択します。 更新は後方に進むため、同じラッキー値が 1 つの状態に 2 回寄与することはできません。 

すべてのラッキー グループが処理された後、すべての有効なラッキー要素構成が 1 回だけカウントされます。 

Unlucky 要素は一意性の制限から独立しているため、使用される Lucky 要素の数を固定したら、残りの位置を任意の Unlucky 要素で埋めることができます。 組み合わせ数は、そのようなすべての選択肢を正確にカウントします。 

すべての有効なサブシーケンスは、幸運な選択と不運な選択に一意に分解されるため、最終的な合計では、すべての有効なサブシーケンスが 1 回だけカウントされます。 

## Python ソリューション```python
import sys
from collections import Counter

input = sys.stdin.readline

MOD = 10**9 + 7

def is_lucky(x):
    while x > 0:
        d = x % 10
        if d != 4 and d != 7:
            return False
        x //= 10
    return True

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))

    lucky_freq = Counter()
    unlucky = 0

    for x in arr:
        if is_lucky(x):
            lucky_freq[x] += 1
        else:
            unlucky += 1

    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)

    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[n] = pow(fact[n], MOD - 2, MOD)

    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def comb(a, b):
        if b < 0 or b > a:
            return 0
        return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

    dp = [0] * (k + 1)
    dp[0] = 1

    for cnt in lucky_freq.values():
        for j in range(k - 1, -1, -1):
            dp[j + 1] = (dp[j + 1] + dp[j] * cnt) % MOD

    ans = 0

    for lucky_taken in range(k + 1):
        need_unlucky = k - lucky_taken

        if need_unlucky <= unlucky:
            ways = dp[lucky_taken]
            ways = ways * comb(unlucky, need_unlucky) % MOD
            ans = (ans + ways) % MOD

    print(ans)

solve()
```最初のセクションでは、幸運な値と不運な値が分かれています。 の`Counter`同じ幸運の値の重複が両方とも有効なサブシーケンスに出現することはできないため、別個の幸運の数値の頻度を格納します。 

階乗配列と逆階乗配列は、高速な組み合わせクエリをサポートします。 逆モジュラーを繰り返してオンデマンドで組み合わせを計算するのは、何度も実行すると非常に遅くなります。 

各ラッキー値は 1 回だけ処理されるため、DP 配列は 1 次元です。 後方反復が不可欠です。 順方向に繰り返すと、単一の移行フェーズ中に同じラッキー値が複数回使用される可能性があります。 

仮定する`cnt = 5`。 移行:```
dp[j + 1] += dp[j] * 5
```5 つの同一のラッキーナンバーの中から 1 つを選択することを意味します。 

最後のループでは、幸運な選択と不運な選択が組み合わされます。 それを確認しなければなりません`need_unlucky`は組み合わせを計算する前に有効です。 この境界チェックを忘れると、誤った回答が発生する可能性が高くなります。 

すべての算術はモジュロで実行されます`10^9+7`, 中間値が非常に大きくなるためです。

最悪の場合でも、おおよそ`2046 × 100000`DP 遷移は、操作が非常に小さくキャッシュに適しているため、Python で管理できます。 The memory usage is tiny compared to the`256 MB`限界。

 ## 特殊なケース

 次のことを考慮してください。```
3 2
4 4 4
```このアルゴリズムは、幸運なグループを 1 つ作成します。```
freq[4] = 3
```DP は次のようになります。 

| ステップ | DP |
 | --- | --- |
 | イニシャル | [1,0,0] |
 | 処理頻度 3 | [1,3,0] |

 到達する方法はありません`dp[2]`, 同じラッキー値を二度選択することはできないためです。 不吉な数字はないので、最終的な答えは、`0`。 

ここで次のことを考えてみましょう。```
4 2
10 10 10 10
```幸運なグループはまったくありません。```
dp = [1,0,0]
unlucky = 4
```答えは次のようになります。$\binom{4}{2}=6$これにより、不運な値の繰り返しが制限されないことが確認されます。 

最後に、次のことを考慮してください。```
5 2
4 7 47 74 10
```すべての幸運の値は異なります。 

DP は次のように進化します。 

| 処理後 | DP |
 | --- | --- |
 | 4 | [1,1,0] |
 | 7 | [1,2,1] |
 | 47 | [1,3,3] |
 | 74 | [1,4,6] |

 不運な値が 1 つあります。 

最終的な答えは次のとおりです。```
dp[2] * C(1,0) + dp[1] * C(1,1)
= 6 + 4
= 10
```異なる幸運の値のすべてのペアは有効であり、各幸運の値は不吉な数字とペアになることもあります。
