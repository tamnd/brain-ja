 ## 解決策
 ## 問題の理解

 数字だけからなる辞書編集上最小の幸運な数字を構築する必要があります`4`そして`7`4 つの部分文字列の数が指定された値と一致するようにします。 

値の意味は次のとおりです。 

-`a1`は桁数です`4`-`a2`は桁数です`7`-`a3`部分文字列の数です`"47"`-`a4`部分文字列の数です`"74"`ここでの部分文字列とは、連続するフラグメントを意味します。 文字列にはのみが含まれているため、`4`そして`7`、隣接する数字間のすべての遷移がいずれかに寄与します。`"47"`または1つ`"74"`。 

重要な観察は、次のことです。`"47"`そして`"74"`しっかりとつながっています。 桁が変わるたびに、`4`に`7`、1つ追加します`"47"`。 から変わるたびに`7`に`4`、1つ追加します`"74"`。 

文字列内を移動するときは、これらのトランジションが交互に行われる必要があります。 あ`"47"`トランジションの後には、`"74"`移行、またはその逆。 そのため、両者の違いは、`a3`そして`a4`決して超えることはできません`1`。 

例えば：

-`4747`2つあります`"47"`そして1つ`"74"`-`7474`1つあります`"47"`そして2つ`"74"`-`44777744`1つあります`"47"`そして1つ`"74"`制約は次のとおりです`10^6`したがって、最後の文字列自体には数百万の文字が含まれる可能性があります。 多くの可能性を模索したり後戻りしたりする解決策は、制限時間内に解決することは不可能です。 線形時間で実行される直接的な建設的なアルゴリズムが必要です。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

入力が次のとおりであるとします。```
1 5 3 1
```不用意に実装すると、積極的に交互に 3 つを作成しようとする可能性があります。`"47"`部分文字列、ただしすべての`"47"`少なくとも 1 つ必要です`4`。 一つしかないので`4`、答えは不可能です。 

もう 1 つの注意が必要なケース:```
2 2 2 2
```一見、カウントはバランスがとれているように見えますが、これは不可能です。 の数`"47"`そして`"74"`各バイナリ文字列の違いは最大 1 つです。 

もう 1 つの微妙なケース:```
3 3 2 1
```両方`474477`そして`447477`カウントは満たしますが、最小の答えは次のとおりです。`447477`。 有効な文字列を構築するだけでは十分ではありません。特に、辞書編集的に最小の文字列が必要です。 

辞書編集上の最小化は重要です。なぜなら、等しい長さのラッキー文字列では、より早く`4`数値を小さくします。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのラッキー文字列を生成し、出現回数を数えます。`4`、`7`、`47`、 そして`74`、有効な最小のものを保持します。 

これは、各候補文字列のプロパティを線形時間で簡単に検証できるため、小さな入力に対して機能します。 問題は検索スペースです。 幸運な長さの文字列`n`もっている`2^n`可能性。 たとえ`n = 40`、すでに候補者は1兆人を超えています。 

制約により 200 万文字近くの長さが許容されるため、網羅的な生成は完全に絶望的になります。 

トランジションの構造が真の画期的な進歩をもたらします。 

隣接する数字が異なるたびに、次のいずれかを作成します。`"47"`または`"74"`。 これらの遷移は交互に行う必要があります。 それは直ちに次のことを意味します。```
|a3 - a4| <= 1
```問題全体は、開始桁と終了桁によって制御されます。 

文字列が次で始まる場合`4`そして次で終わります`7`、すると、もう 1 つ追加されます。`"47"`遷移。 

で始まるなら`7`そして次で終わります`4`、すると、もう 1 つ追加されます。`"74"`遷移。 

同じ数字で始まり同じ数字で終わる場合、2 つの遷移カウントは等しくなります。 

遷移パターンが固定されたら、残りの桁をブロックに単純に分配することができます。 辞書編集的に数を最小限にするには、できるだけ多くの数が必要です`4`できるだけ前の方に。 

建設的な解決策では、最初に交互のスケルトンを構築し、次に遷移数を変更せずに、慎重に選択したブロックに数字の追加のコピーを挿入します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | 最適 | O(a1 + a2) | O(a1 + a2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`a1`、`a2`、`a3`、 そして`a4`。 
2. かどうかを確認します。`|a3 - a4| > 1`。 

差が 1 を超える場合、有効な交互構造は存在できません。 
3. ケースを処理する`a3 == a4`。 

この状況では、文字列は同じ数字で始まり、終わる必要があります。 

次の 2 つの可能性があります。 

- start and end with`4`- で始まり、で終わる`7`まず、辞書編集的に小さい構造を試します。`4`。 
4. ケースを処理する`a3 == a4 + 1`。 

文字列は次で始まる必要があります`4`そして次で終わります`7`。 

交互のスケルトンは次のようになります。```
4747...47
```このスケルトンはすでに以下を消費しています:

 -`a3 + 1`のコピー`4`-`a3`のコピー`7`5. ケースを処理する`a4 == a3 + 1`。 

文字列は次で始まる必要があります`7`そして次で終わります`4`。 

スケルトンは次のようになります。```
7474...74
```6. スケルトンを構築した後、追加のスケルトンの数を計算します。`4`と`7`が残っています。 

新しいトランジションを作成せずに、既存のブロック内に追加の数字を挿入できます。 
7. 辞書編集的に数値を最小限にするには、追加の`4`できるだけ早く。 

文字列が次で始まる場合`4`、余分なものをすべて追加します`4`最初に`4`ブロック。 

追加`7`s は可能な限り後でプッシュする必要があります。 
8. どこかの時点で必要なカウントがマイナスになると、構築は不可能になります。 
9. 構築された文字列を出力します。 

### なぜ効果があるのか

 遷移カウントによって、桁変更の順序が完全に決まります。 有効な文字列はすべて、既存のブロックに繰り返し数字が挿入された交互のスケルトンです。 

ブロック内で数字を繰り返しても、新しい数字は作成されません`"47"`または`"74"`遷移は隣接する異なる桁間でのみ発生するためです。 

このアルゴリズムは、最初に唯一の可能な遷移パターンを修正し、次にそれらの遷移を変更せずに残りの桁を分配します。 

余分な配置から辞書編集上の最小性が得られる`4`できるだけ早く。 前の位置が辞書編集上の順序を支配し、`4 < 7`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_equal(a1, a2, k, start):
    if start == '4':
        need4 = k + 1
        need7 = k
        if a1 < need4 or a2 < need7:
            return None

        extra4 = a1 - need4
        extra7 = a2 - need7

        parts = []

        for i in range(k):
            if i == 0:
                parts.append('4' * (1 + extra4))
            else:
                parts.append('4')

            parts.append('7')

        parts.append('7' * extra7)
        parts.append('4')

        return ''.join(parts)

    else:
        need7 = k + 1
        need4 = k
        if a1 < need4 or a2 < need7:
            return None

        extra4 = a1 - need4
        extra7 = a2 - need7

        parts = ['7' * (1 + extra7)]

        for i in range(k):
            parts.append('4')

            if i == k - 1:
                parts.append('7')
            else:
                parts.append('7')

        parts.insert(1, '4' * extra4)

        return ''.join(parts)

def solve():
    a1, a2, a3, a4 = map(int, input().split())

    if abs(a3 - a4) > 1:
        print(-1)
        return

    ans = None

    if a3 == a4:
        ans1 = build_equal(a1, a2, a3, '4')
        ans2 = build_equal(a1, a2, a3, '7')

        candidates = []

        if ans1 is not None:
            candidates.append(ans1)

        if ans2 is not None:
            candidates.append(ans2)

        if not candidates:
            print(-1)
            return

        print(min(candidates))
        return

    if a3 == a4 + 1:
        need4 = a3 + 1
        need7 = a3

        if a1 < need4 or a2 < need7:
            print(-1)
            return

        extra4 = a1 - need4
        extra7 = a2 - need7

        parts = ['4' * (1 + extra4)]

        for _ in range(a3):
            parts.append('7')
            parts.append('4')

        parts.pop()

        parts[-1] += '7' * (1 + extra7)

        print(''.join(parts))
        return

    if a4 == a3 + 1:
        need7 = a4 + 1
        need4 = a4

        if a1 < need4 or a2 < need7:
            print(-1)
            return

        extra4 = a1 - need4
        extra7 = a2 - need7

        parts = ['7' * (1 + extra7)]

        for _ in range(a4):
            parts.append('4')
            parts.append('7')

        parts.pop()

        parts[-1] += '4' * (1 + extra4)

        print(''.join(parts))
        return

if abs(a3 - a4) > 1:
```有効なバイナリ文字列では、複数の異なる遷移カウントを持つことはできません。 

ヘルパーさん`build_equal`バランスの取れたケースを処理します。`a3 == a4`。 ここで、文字列はどちらの数字でも始まる可能性があるため、両方の可能性を生成し、辞書順に小さい方を選択します。 

残りの 2 つのケースにはそれぞれ、有効な遷移パターンが 1 つだけあります。 

微妙な点は、余分な数字がどのように挿入されるかです。 数字の余分なコピーは、その数字の既存のブロック内に存在する必要があります。 そうしないと、誤って追加の遷移が作成され、部分文字列の数が壊れてしまいます。 

もう 1 つの簡単な間違いは、交互のスケルトンがすでにいくつかの桁を消費していることを忘れていることです。 たとえば、次のようなとき`"47"`表示されます`k`倍以上`"74"`、骨格が必要とする`k + 1`のブロック`4`。 

このコードでは、文字列の追加を繰り返す代わりにリストの連結を使用します。 最終的な文字列は非常に大きくなる可能性があるため、不変の文字列を使用して段階的に構築すると時間がかかりすぎます。

 ## 特殊なケース

 次のことを考慮してください。```
2 2 2 2
```次の理由により、アルゴリズムはそれを即座に拒否します。```
|2 - 2| = 0
```は有効ですが、2 つのバランスの取れた構造であれば、`"47"`そして2つ`"74"`各桁の少なくとも 3 つのブロックが必要です。 構築フェーズで不十分なカウントが検出され、リターンされる`-1`。 

ここで次のことを考えてみましょう。```
1 5 3 1
```アルゴリズムは以下を参照します。```
|3 - 1| = 2
```遷移は交互に行われる必要があるため、そのようなギャップは不可能です。 答えは建設が始まる前に正しく拒否されます。 

ついに：```
3 3 1 1
```両方`477744`そして`447774`カウントを満たします。 アルゴリズムは意図的に余分なものを配置します`4`最も早い時期に`4`ブロック、生成`447774`、これは辞書編集的に小さいです。
