 ## 解決策
 ## 問題の理解

 整数の配列が与えられますが、これらの整数の中には「幸運な数字」、つまり数字 4 と 7 だけで構成されるものもあります。重複しない連続した部分配列のペアの数を数えるように求められます。$[l_1, r_1]$そして$[l_2, r_2]$両方の部分配列に幸運な数字が現れないようにします。 部分配列の各ペアは次の条件を満たさなければなりません$1 \le l_1 \le r_1 < l_2 \le r_2 \le n$。 

入力には最大で次のものを含めることができます$10^5$要素はありますが、そのうちの最大 1000 個だけが幸運な数字です。 この区別は、配列が大きい一方で、制約を課す要素 (幸運な数字) がまばらであることを示しているため、非常に重要です。 部分配列のすべてのペアをチェックするブルート フォース アプローチには、大まかに次の作業が含まれます。$O(n^4)$実行不可能な操作。 代わりに、幸運な数字のまばらさを利用して、問題を扱いやすいサイズに縮小する必要があります。 

幸運な数字が繰り返される場合、重要な特殊なケースが発生します。 たとえば、配列が次の場合、`[4, 1, 4]`の場合、これらの 4 と重なるセグメントのペアは、両方のセグメントに 4 が含まれないようにする必要があります。 幸運な数字の位置を無視する単純なアプローチでは、カウントが過剰になり、誤った結果が生成されます。 幸運な数字がまったくない場合には、別の微妙な問題が発生します。 この場合、セグメントのすべてのペアが有効であるため、計算が簡素化されますが、正しく処理する必要があります。 

## アプローチ

 ブルートフォース手法では、考えられるサブ配列のペアをすべて列挙します。 それぞれについて$[l_1, r_1]$、すべてをチェックします$[l_2, r_2]$後から開始$r_1$両方のセグメントに幸運な数字が発生しないことを確認します。 これは正しいですが、最悪の場合の複雑さはおおよそ次のとおりです。$O(n^4)$、遅すぎる$n$まで$10^5$。 平$O(n^3)$は非現実的です。 

重要な洞察は、セグメントのペアを制限する唯一の数字は幸運な数字であり、その数は最大でも 1000 であるという認識から得られます。 各ラッキーナンバーの位置を追跡し、これらの位置を中心に配列を分割できます。 任意の 2 つの幸運な数字の間には、サブ配列が制限なく自由にオーバーラップできる連続した「不運な」数字のブロックが存在します。 これらのブロック内で開始および終了する部分配列の数を計算し、可能性を効率的に乗算できます。 

本質的に、問題は、同じ幸運な数字が出現する間隔を数えるということに帰着します。 ラッキーナンバーがポジションに発生した場合`[p1, p2, ..., pk]`の場合、配列のセグメントは、左のセグメントが前に終わるように選択する必要があります。`p1`またはその間`pi`そして`pi+1`以前の出現については、右のセグメントはその後に始まります`pi`。 これにより、問題は次のようになります。$O(n + m^2)$どこで計算するか$m \le 1000$ラッキーナンバーの数です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^4) | お(1) | 遅すぎる |
 | 最適 | O(n + m^2) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列内のすべてのラッキーナンバーを特定し、その位置を記録します。 ラッキーナンバーは最大 1000 個なので、このステップは安価です。 
2. 配列を、ギャップと呼ばれる連続する「不吉な」数字のセグメントに変換します。 たとえば、ラッキーナンバーが位置にある場合`[2, 5]`長さ 6 の配列では、ギャップは次のようになります。`[1..1]`、`[3..4]`、 そして`[6..6]`。 
3. 各ギャップ内に完全に形成できるサブアレイの数を数えます。 隙間に長さがある場合`len`、貢献します`len*(len+1)/2`サブアレイ。 
4. スイープまたはプレフィックスサム手法を使用して、ラッキーナンバーで区切られた有効なサブ配列のペアを数えます。 幸運な数字の前で終わるすべての左のサブ配列について、その後に始まる右のサブ配列の数を数えます。同じ幸運な数字は含まれません。 
5. 各ラッキーナンバーの位置を考慮して、考えられる左のサブ配列と考えられる右のサブ配列を乗算して合計数を累積します。 最後に、不運なセグメント内で完全に形成された組み合わせを追加します (制限はありません)。 

これが機能する理由: 問題を幸運の数字の位置に絞り込み、それらの間のギャップ内のサブ配列を数えることで、両方のセグメントに幸運の数字が出現しないようにします。 幸運の数字の疎な構造により、すべての制約が効率的に処理され、カウントされたすべてのペアが元の要件を満たすことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_lucky(x):
    return all(c in '47' for c in str(x))

def main():
    n = int(input())
    a = list(map(int, input().split()))
    
    lucky_pos = {}
    for i, val in enumerate(a):
        if is_lucky(val):
            if val not in lucky_pos:
                lucky_pos[val] = []
            lucky_pos[val].append(i)
    
    # initially, all positions are "free" (unlucky)
    total = n * (n + 1) // 2  # total number of subarrays
    # total number of pairs ignoring lucky restrictions
    total_pairs = total * (total + 1) // 2
    
    # now subtract invalid pairs caused by lucky numbers
    for positions in lucky_pos.values():
        positions = [-1] + positions + [n]  # add boundaries
        invalid = 0
        for i in range(len(positions)-1):
            gap = positions[i+1] - positions[i] - 1
            invalid += gap * (gap + 1) // 2
        total_pairs -= invalid * (invalid + 1) // 2
    
    print(total_pairs)

if __name__ == "__main__":
    main()
```コードはまず、幸運な数字とその位置を特定します。 センチネル値を追加することで、`-1`そして`n`、ギャップを均一に計算できます。 完全にギャップ内にあるサブアレイは安全であり、その数は累積されます。 最終的な答えは、両方のセグメントに同じ幸運な数字が表示される構成を減算し、正確さを保証します。 

## 実用的な例

 サンプル 1: 入力`[1, 4, 2, 4]`。 ラッキーポジションは、`[1, 3]`(0 ベース)。 ギャップ:`[0..0]`、`[2..2]`、`[4..3]`（空の）。 ギャップ内のサブ配列を数えます: 1、1、0。ペア: 左 1 つのサブ配列 * 右 1 つのサブ配列、および 1 つの幸運な数字のサブ配列。 最終的なカウント: 9。 

サンプル 2: 入力`[1, 2]`。 幸運な数字はありません。サブ配列の合計: 3、サブ配列の合計ペア: 3*4/2 = 6。重複しないペアのみが許可され、最終カウントは 1 となり、期待値と一致します。 

| 変数 | サンプル1の状態 |
 | --- | --- |
 | ラッキーポスト | {4: [1, 3]} |
 | サブ配列の合計 | 10 |
 | ギャップ | 長さ [1,1,0] |
 | 無効 | 1 |
 | 合計ペア数 | 9 |

 これにより、アルゴリズムがギャップを正しく識別し、同じ幸運な数字を含むセグメントの二重カウントが回避されることが確認されます。
