 ## 問題の理解

 テーブルがあります`m`行と`n`列。 各行は 1 人のロボット参加者に属し、各行には独自のブール プログラムがあります。 すべての列の値は次の順列です。`0, 1, ..., m - 1`したがって、すべての値はその列に 1 回だけ出現します。 

各列ごとに`j`、閾値を選択します`z[j]`間`0`そして`m`。 行の入力`i`その列の値はブール値になります`x[i][j] < z[j]`。 

次に、行はこれらを評価します。`n`指定されたシーケンスによるブール入力`and`そして`or`説明書。 プログラムは単調で、特別な非反復特性を持っています。すべての中間値は、最大でも 1 つの後続の命令への入力として使用されます。 各行の最終値は、その行のプログラムの結果です。 タスクは、正確に`s`の`m`最終結果は`1`。 このステートメントは、そのようなしきい値が常に存在することを保証します。 

制約`n * m <= 3 * 10^5`は重要な数値境界です。 私たちにはそれに近いものを買う余裕はありません`O(nm * n)`または`O(nm * m)`最悪の場合。 合計入力サイズが本質的に線形であるアルゴリズムが必要です。 個人の限界は`n`そして`m`それぞれが到達できるか`3 * 10^5`しかし、彼らの製品は依然として小規模であるため、適切な複雑さの目標は次のとおりです。`O(nm)`。 

実装を静かに破壊する可能性のあるエッジケースがいくつかあります。 

いつ`s = 0`、すべてのプログラムはゼロのままでなければなりません。 正しい答えは、単にすべてのしきい値がゼロに等しいということです。 例えば、```

ケース`s = m`反対側の境界です。 すべてのプログラムは一つにならなければなりません。 例えば、```

```正しい出力がある```

ケース`n = 1`ブール命令はまったくありません。 各プログラムは単一の入力のみで構成されます。 すべての列は順列であるため、`z[1] = s`値を含む行を正確に作成します`0, 1, ..., s - 1`1に等しい。 例えば、```

より微妙なケースとしては、`and`最初の入力が 1 になる一方で、2 番目の入力がまだ 0 であるゲート。 ゲートはゼロのままでなければならないため、伝播は直ちに停止する必要があります。 たとえば、```

逆の状況が発生するのは、`or`: 出力が以前に 0 だった場合、1 つの入力を 0 から 1 に変更すると、ゲートがすぐにアクティブになります。 伝播ロジックでは、これら 2 つの操作を区別する必要があります。 

## アプローチ

 最も直接的な解決策は、しきい値を 1 つずつ増やすことです。 最初はすべてのしきい値がゼロであるため、すべての比較が`x[i][j] < z[j]`は誤りです。 いくつかのしきい値を 1 つ増やし、影響を受けるすべてのブール プログラムを再計算し、正確な値になるまで続行できます。`s`プログラムは 1 を返します。 

これは正しいです。すべてのしきい値は増加するだけなので、すべての入力は 0 から 1 に 1 回だけ変更できます。 の単調性`and`そして`or`つまり、プログラム出力も 0 から 1 までしか移動できないということです。 すべての閾値は最終的には到達するので、`m`、すべての入力は最終的に 1 になり、すべてのプログラムは最終的に 1 を返します。 したがって、途中で目的のカウントに遭遇する必要があります。 これらの観察は、公式ソリューションの基礎でもあります。 

単純な実装の問題は、再計算の量です。 がある`nm`しきい値が増加します。 すべての増分によってプログラム全体が評価される場合、`O(n)`指示、最悪の場合は`O(n^2m)`、大きすぎます。 と`n * m = 3 * 10^5`、さらに追加の要素`n`は受け入れられません。 

1 つのしきい値の増分が 1 つの行の 1 つの入力だけを変更することを観察することで、これを改善できます。 すべての列の順列プロパティにより、これが無料で提供されます。 もし`z[j]`からの変更`t`に`t + 1`、列内の唯一の新しい真の比較`j`値を含む行です`t`。 

この 1 ビットの変更後にプログラム全体を繰り返し評価するため、ブルートフォース ソリューションは機能します。 しかし、その作業のほとんどは不要です。 その変更された値に依存する命令のみが変更される可能性があります。 

非反復条件により、重要な最終的な単純化が行われます。 命令によって生成されるすべての値は、最終結果を除き、後の 1 つの命令の入力として使用されます。 したがって、入力が 0 から 1 に変化した後、変化が伝播する可能性のあるパスは 1 つだけです。 各命令自体は、アルゴリズム全体で最大 1 回だけ 0 から 1 に変更できます。 したがって、全体的に、`m`せいぜいプログラム`O(nm)`指示値は常に変化します。 

このパスは次のように明示的に表すことができます。`parent`配列。 命令のすべての入力値に対して、`parent[value]`どの命令がそれを消費するかを示します。 値が 1 になると、その親を検査します。 その親がゼロのままの場合、伝播は停止します。 その出力が 1 になると、その出力から続行します。 すべての中間値には親が 1 つだけあるため、グラフの走査や再計算の繰り返しは必要ありません。

 ## アルゴリズムのチュートリアル

 1. すべてのしきい値をゼロから開始します。 すべてのテーブル値は負ではないため、すべての比較は`x[i][j] < 0`は誤りです。 したがって、すべてのプログラムは値 0 から始まります。 
2. すべての入力およびすべての中間命令の現在のブール値を保持します。 最初はこれらの値はすべてゼロです。 
3. すべての入力値について、その一意の親命令を保存します。 入力制限により、値が 2 回使用されないことが保証されるため、この親は一意になります。 
4. 列を一度に 1 つずつ処理します。 固定列の場合`j`、そのしきい値をゼロから`m`。 しきい値が から変化したとき`t`に`t + 1`、この列の値が次である一意の行を見つけます。`t`。 
5. 列に対応する行の入力を変更します`j`ゼロから１へ。 列は次の順列であるため、この操作中に他の行や列は変更されません。`0, ..., m - 1`。 
6. 変更された値の親をたどります。 親がない場合は、値自体が最終出力となります。 これは次の場合にのみ直接発生します。`n = 1`。 
7. それ以外の場合は、2 つの入力を使用して親命令を評価します。 それが`and`、その出力は両方の入力が 1 の場合にのみ 1 になります。 それが`or`、少なくとも 1 つの入力が 1 になるとすぐに、その出力は 1 になります。 
8. 命令の出力がゼロのままの場合は、伝播を停止します。 他の場所で将来のしきい値が変更されると影響を受ける可能性がありますが、現在の変更はそれ以上進むことはできません。 
9. 命令の出力が 0 から 1 に変化した場合、それを 1 としてマークし、その出力から親命令まで続行します。 命令を 0 から 1 に 2 回変更する必要はありません。 
10. 行の最終値が 0 から 1 に変化するたびに、成功したプログラムのグローバル数を増やします。 このカウントがこうなったら`s`、現在のしきい値をすぐに出力します。 
11. もし`s = 0`、すべてゼロのしきい値をすぐに出力します。 もし`n = 1`、問題には指示がなく、答えは単純です。`z[1] = s`。 

### なぜ効果があるのか

 不変条件は、処理されたしきい値が増加するたびに、保存されたすべてのしきい値が増加することです。`val`は、現在のしきい値に対してすべてのプログラムの対応する部分によって生成される値とまったく同じです。 

最初は、すべての入力とすべての命令出力がゼロであるため、不変式が成り立ちます。 インクリメント中に、正確に 1 つの入力が 0 から 1 に変化します。 その入力から到達できないすべての命令は影響を受けません。 変更された値の一意の親については、その出力をその操作に従って正確に再計算します。 出力が変更されると、同じ引数がその一意の親に適用されます。 したがって、影響を受ける可能性のあるすべての値は更新されますが、影響を受けないすべての値は正しいままになります。 

なぜなら`and`そして`or`単調なので、値は 1 から 0 に戻ることはありません。 プログラムは反復しないため、すべての中間値には最大 1 つの親があり、各値を最大 1 回だけ伝播できます。 最終出力が変化すると、ちょうど 1 つのプログラムが 0 から 1 に変化します。 したがって、維持されるカウントは常に 1 を返すプログラムの真の数になります。 

しきい値がすべてゼロに等しい場合、カウントはゼロですが、しきい値がすべてゼロに等しい場合、カウントはゼロになります。`m`すべての入力は 1 であり、すべてのプログラムは 1 を返します。 個々の更新ごとにカウントが最大 1 増加する可能性があるため、すべてのターゲットは 0 から 0 までカウントされます。`m`に遭遇します。 アルゴリズムはカウントが正確に終了したときに停止します。`s`。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve():
    n, m, target = map(int, input().split())

    # n == 1 means every program consists of its only input.
    # Since each column is a permutation of 0..m-1, z[0] = target
    # makes exactly target rows true.
    if n == 1:
        for _ in range(m):
            input()
        print(target)
        return

    inst_count = n - 1
    width = 2 * n - 1
    total_values = m * width
    total_instructions = m * inst_count
    total_cells = n * m

    # For instruction k of row r:
    # left[r * inst_count + k]
    # right[r * inst_count + k]
    # op[r * inst_count + k]
    left = array('i')
    right = array('i')
    op = array('b')

    # parent[base + value - 1] is the local value number
    # of the instruction consuming that value.
    parent = array('i', [0]) * total_values

    for row in range(m):
        base = row * width
        ibase = row * inst_count

        for p in range(1, n):
            a, b, operation = map(int, input().split())

            idx = ibase + p - 1
            left.append(a)
            right.append(b)
            op.append(operation)

            out = n + p
            parent[base + a - 1] = out
            parent[base + b - 1] = out

    # events[col * m + value] = row containing that value in this column.
    # When z[col] grows from value to value + 1, this row's input changes.
    events = array('i', [0]) * total_cells

    for row in range(m):
        values = list(map(int, input().split()))
        for col, value in enumerate(values):
            events[col * m + value] = row

    if target == 0:
        print(*([0] * n))
        return

    thresholds = [0] * n

    # Current values of all inputs and intermediate results.
    vals = bytearray(total_values)

    active = 0

    for col in range(n):
        event_base = col * m
        local_input = col + 1

        for value in range(m):
            row = events[event_base + value]
            thresholds[col] = value + 1

            base = row * width
            current = local_input

            while True:
                # For n > 1, every input has a parent.
                out = parent[base + current - 1]

                if out == 0:
                    break

                out_pos = base + out - 1

                # This instruction has already become one.
                if vals[out_pos]:
                    break

                instruction = out - n
                idx = row * inst_count + instruction - 1

                a = left[idx]
                b = right[idx]

                if op[idx] == 1:
                    new_value = vals[base + a - 1] & vals[base + b - 1]
                else:
                    new_value = vals[base + a - 1] | vals[base + b - 1]

                if not new_value:
                    break

                vals[out_pos] = 1

                if out == width:
                    active += 1
                    break

                current = out

            if active == target:
                print(*thresholds)
                return

    # The statement guarantees that a solution exists.
    print(*thresholds)

if __name__ == "__main__":
    solve()
```最初の特殊ケースハンドル`n = 1`。 このようなプログラムには命令がないため、最終結果は単に比較のみになります。 列には 0 から 0 までのすべての値が含まれているため、`m - 1`、 しきい値`s`正確に活性化する`s`行。 

のために`n > 1`、`width = 2n - 1`1 つのプログラム内の値の数です。 配列`left`、`right`、 そして`op`すべての命令を行ごとに連続して格納します。 フラット配列を使用すると、次のいずれかの場合に数十万の小さな Python リストを作成することを回避できます。`n`または`m`大きいです。 

の`parent`配列には、行とローカル値番号によってインデックスが付けられます。 命令を読み取るとき、その両方のオペランドは命令の出力を親として受け取ります。 非反復条件により、これらの割り当てが決して競合しないことが保証されます。 最終出力には親がないため、親エントリはゼロのままです。 

の`events`配列には、すべての列の逆順列が格納されます。 テーブル全体を保持して列の値を繰り返し検索する代わりに`t`を含む行を直接取得します。`t`で`O(1)`。 そのフラットインデックスは`col * m + value`。 

伝播ループはソリューションの中核です。`current`は 1 に変更されたばかりのローカル値です。 その親命令は次から取得されます。`parent`。 出力がすでに 1 つである場合、それ以上伝播するものはありません。 それ以外の場合、命令は 2 つの現在の入力から評価されます。 

操作のエンコードはステートメントの後に続きます。`1`手段`and`そして`2`手段`or`。 すべての値は 0 から 1 にのみ移動するため、命令は実行全体でそのような遷移を 1 回だけ行うことができます。 

最終出力にはローカルインデックスが含まれます`2n - 1`、まさにその通りです`width`。 この値が 1 に変化すると、対応するプログラムが成功したばかりであるため、`active`増加します。 

Python では整数オーバーフローの懸念はありません。 実装では、`array('i')`インデックスとオペランドをコンパクトに保存するために使用されます。`bytearray`それぞれ 1 バイトを使用してブール値を格納します。 

しきい値が割り当てられます`value + 1`比較は厳密であるため、伝播前に行われます。 以下に等しいテーブル値`value`しきい値に達したときに正確に真になります`value + 1`。 この厳密な不等式を忘れると、しきい値スイープで 1 つずれたエラーが発生する可能性が最も高くなります。

 制約`n * m <= 3 * 10^5`線形境界が適切になります。 また、実装では、ネストされた Python オブジェクトの大規模なコレクションではなく、コンパクトな整数配列が使用され、問題で指定された 512 MB の制限内で快適なメモリ使用量が維持されます。 

## テストケース

 以下のテスト ハーネスは、提出されたソリューションと同じ伝播アルゴリズムを使用し、生成されたしきい値を 1 つの固定出力と比較するのではなく検証します。 この問題では有効なしきい値ベクトルが明示的に許可されているため、これが必要になります。```python
import io
import sys
from array import array

def solve_data(inp: str) -> str:
    data = io.StringIO(inp)
    readline = data.readline

    n, m, target = map(int, readline().split())

    if n == 1:
        for _ in range(m):
            readline()
        return str(target)

    inst_count = n - 1
    width = 2 * n - 1
    total_values = m * width
    total_cells = n * m

    left = array('i')
    right = array('i')
    op = array('b')
    parent = array('i', [0]) * total_values

    for row in range(m):
        base = row * width

        for p in range(1, n):
            a, b, operation = map(int, readline().split())

            left.append(a)
            right.append(b)
            op.append(operation)

            out = n + p
            parent[base + a - 1] = out
            parent[base + b - 1] = out

    events = array('i', [0]) * total_cells

    for row in range(m):
        values = list(map(int, readline().split()))
        for col, value in enumerate(values):
            events[col * m + value] = row

    if target == 0:
        return " ".join(["0"] * n)

    thresholds = [0] * n
    vals = bytearray(total_values)
    active = 0

    for col in range(n):
        event_base = col * m
        local_input = col + 1

        for value in range(m):
            row = events[event_base + value]
            thresholds[col] = value + 1

            base = row * width
            current = local_input

            while True:
                out = parent[base + current - 1]

                if out == 0:
                    break

                out_pos = base + out - 1

                if vals[out_pos]:
                    break

                instruction = out - n
                idx = row * inst_count + instruction - 1

                a = left[idx]
                b = right[idx]

                if op[idx] == 1:
                    new_value = vals[base + a - 1] & vals[base + b - 1]
                else:
                    new_value = vals[base + a - 1] | vals[base + b - 1]

                if not new_value:
                    break

                vals[out_pos] = 1

                if out == width:
                    active += 1
                    break

                current = out

            if active == target:
                return " ".join(map(str, thresholds))

    return " ".join(map(str, thresholds))

def run(inp: str) -> str:
    return solve_data(inp).strip()

def check(inp: str):
    out = list(map(int, run(inp).split()))

    first = inp.splitlines()
    n, m, s = map(int, first[0].split())

    assert len(out) == n
    assert all(0 <= z <= m for z in out)

    # Parse the input again and directly evaluate every program.
    pos = 1
    programs = []

    for _ in range(m):
        prog = []
        for _ in range(n - 1):
            a, b, operation = map(int, first[pos].split())
            pos += 1
            prog.append((a, b, operation))
        programs.append(prog)

    table = []
    for _ in range(m):
        table.append(list(map(int, first[pos].split())))
        pos += 1

    count = 0

    for row in range(m):
        vals = [False] * (2 * n)

        for j in range(n):
            vals[j + 1] = table[row][j] < out[j]

        for p, (a, b, operation) in enumerate(programs[row], start=1):
            if operation == 1:
                vals[n + p] = vals[a] and vals[b]
            else:
                vals[n + p] = vals[a] or vals[b]

        if vals[2 * n - 1]:
            count += 1

    assert count == s
    return out

 「すべてが等しい値」という表現には、ここで 1 つの条件が必要です。 このステートメントではすべての列が次の順列である必要があるため、列全体に同じ値を含めることはできません。`0, ..., m - 1`。 最も近い有効なストレス ケースは、行など、すべての行が列全体で同じパターンを持つテーブルです。`i`含む`i`すべての列に。 上記の AND テストと OR テストでは、まさにその構造が使用されています。 

## 特殊なケース

 のために`s = 0`の場合、アルゴリズムはしきい値の増加を実行する前に戻ります。 すべてのしきい値はゼロであるため、すべての入力比較は false となり、すべての単調プログラムはゼロを返します。 例えば、```
1 3 0
0
1
2
```生成する`0`、これは、成功するプログラムの必要な数とまったく同じです。 

のために`s = m`、アルゴリズムはすべてのプログラムが 1 つになるまで増分処理を続けます。 処理されたすべての列の最終しきい値に達する可能性があります`m`。 のために```
2 3 3
1 2 1
1 2 1
1 2 1
0 0
1 1
2 2
```最初のしきい値は最終的に`3`ですが、2 番目の入力がまだ 0 であるため、AND 出力はまだ 1 になっていません。 その後、2 番目のしきい値に達します`1`、`2`、そして最後に`3`。 各行の 2 番目の入力は、対応するイベントで 1 になり、3 つの最終出力はすべて 1 になります。 返されるベクトルは、`3 3`。 

のために`n = 1`、伝播ツリーはありません。 すべてのプログラムの唯一の値はその入力です。 と```
1 4 2
0
1
2
3
```しきい値`2`最初の 2 つの比較が正確に真になります。 アルゴリズムは戻ります`2`直接。 

AND ゲートの場合、単一の変更された入力は効果がない場合があります。 で```
2 3 1
1 2 1
1 2 1
1 2 1
0 0
1 1
2 2
```最初の列がしきい値に達した後`3`、最初の入力はすべて 1 ですが、2 番目の入力はすべて 0 のままです。 3 つの AND 出力はすべてゼロのままです。 2 番目の列がしきい値に達したとき`1`、最初の行の 2 番目の入力が 1 に変化し、その AND 出力が 1 に変化し、グローバル カウントが 1 になります。 伝播コードはまさにこの依存関係を処理します。 

OR ゲートの場合、1 つの変更された入力で十分です。 で```
2 3 2
1 2 2
1 2 2
1 2 2
0 0
1 1
2 2
```最初のしきい値を 0 から 1 に上げると、行 1 が 0 から 1 に変化します。`0 or 0`に`1 or 0`、したがって、その最終結果はすぐに 1 になります。 これを 2 に増やすと、行 2 もアクティブになり、2 番目のしきい値に触れることなく、必要なカウント 2 が得られます。 

最後の微妙なケースは、出力がすでに 1 になっている命令です。 プログラムが繰り返し入力を許可している場合にのみ、後の入力変更が別の依存関係を通じて同じ命令に到達する可能性がありますが、この問題ではそれが明示的に禁止されています。 この制限に頼らなくても、`vals[out_pos]`再計算前は有用な防御ロジックです。 命令が 1 になると、単調性により、その後の変更によってその命令が 0 にならないことが保証されるため、その命令による伝播が停止する可能性があります。
