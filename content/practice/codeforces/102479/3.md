 ## 問題の理解

 シーケンスがあります`a[1..n]`、 どこ`a[i]`その日に行われる作業の種類です`i`。 あらゆる長さに対して`d`から`1`に`n`、すべての連続セグメントを正確に考慮します。`d`日々。 このようなセグメントごとに、そのセグメント内で発生するさまざまな作業タイプの数を数え、これらの数を合計します。 結果の値は次のとおりです。`S_d`。 

必要な出力はプロファイル全体です`S_1, S_2, ..., S_n`。 

たとえば、```
5
1 3 2 1 2
```長さ 1 のセグメントが 5 つあり、それぞれに 1 つの異なるタイプが含まれているため、`S_1 = 5`。 長さが 2 の場合、各セグメントには 2 つの異なるタイプが含まれます。`S_2 = 8`。 公式のサンプル出力は次のとおりです`5 8 8 6 3`。 

制約は、直接の列挙を超えて検討することを強制する部分です。 私たちは持つことができます`n = 2 * 10^5`、制限時間はわずか 1 秒、メモリ制限は 512 MB です。 アルゴリズム取得`O(n^2)`操作にはすでに約が必要です`2 * 10^10`最悪の場合、基本的なウィンドウ操作が多すぎます。 必要なのは`O(n)`またはそれに近い`O(n)`解決。 

価値観`a[i]`と同じ大きさにすることができます`10^9`したがって、値自体を直接配列インデックスとして使用することはできません。 各ワークタイプの前の位置を覚えていればよいので、辞書で十分です。 

表面的に合理的な実装が失敗する可能性があるエッジケースがいくつかあります。 のために`n = 1`、 例えば、```

## アプローチ

 最も直接的な解決策は、すべてのセグメントを列挙することです。 それぞれの長さごとに`d`、すべてを調べることができます`n-d+1`セグメントを作成し、その要素をセットに挿入し、セットのサイズを`S_d`。 これは定義に直接従うため、明らかに正しいです。 

問題は繰り返し作業の量です。 すべてのセグメントのすべての要素を文字通り検査すると、検査される要素の総数は次のようになります。`1 + 2 + ... + n`考えられるすべてのセグメントの長さと位置にわたって、つまり`n(n+1)(n+2)/6`。 

で`n = 200000`、これについてです`1.33 * 10^15`要素の訪問。 スライディング ウィンドウを使用して実装を改善しても、単純な方法では次のような結果しか得られません。`O(n^2)`、あるので`n(n+1)/2`、 について`2 * 10^10`合計 , 窓。 

重要な観察は、個別の値の数を値ごとに独立してカウントできることです。 各ウィンドウ内に個別の値がいくつあるかを尋ねる代わりに、1 つの特定の値を修正します`x`そしてもっと単純な質問をしてください: 長さはどれくらいですか?`d`窓はそうします`x`少なくとも一度は発生しますか？ 

すべてのウィンドウは、ウィンドウ内で発生する値の個別のカウントに 1 を与えます。 したがって、各値を含むウィンドウの数を合計すると、正確に次のようになります。`S_d`。 

次に、固定値が存在するすべての位置を考えます。`x`が発生します。 2 つの連続した出現の間には、何も含まれていないギャップがあります。`x`。 窓が避ける`x`正確には、最初に出現する前のギャップと最後の出現後のギャップを含む、ウィンドウ全体がこれらのギャップの 1 つの内側にあるときです。 

ギャップが含まれている場合`L`位置、次に長さの数 -`d`完全に内側に収まる窓は`max(0, L-d+1)`。 

がある`n-d+1`ウィンドウの合計の長さ`d`。 シーケンスに次のものが含まれる場合、`K`個別の値の場合、最初にカウントします`K(n-d+1)`値ウィンドウのペア。 対応する値を回避するすべてのウィンドウを減算する必要があります。 

したがって、取得します`S_d = K(n-d+1) - Σ max(0, L-d+1)`、

 ここで、合計はすべての値の空でないすべてのギャップにまたがります。 

これにより、元の問題がギャップ長に関する周波数の問題に変わります。 もし`cnt[L]`正確な長さのギャップの数です`L`、それでは必要です`Σ_{L>=d} cnt[L](L-d+1)`。 

固定の場合`d`、これは次のように書き換えることができます`Σ_{L>=d} cnt[L](L+1) - d Σ_{L>=d} cnt[L]`。 

両方の合計は次の接尾辞の合計です`L`、それですべて`S_d`1 回の逆パスで計算できます。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、左から右にスキャンします。 あらゆる種類の作業について、最後に作業が行われた位置を覚えておいてください。 

ゼロベースの位置で初めて値を確認したとき`i`、前の位置`i`長さの隙間を形成する`i`。 このギャップが正の場合、増分します`cnt[i]`。 

以前にその位置で値を見たとき`last`、厳密に間の位置`last`そして`i`この値は含まれていません。 それらの長さは`i-last-1`, したがって、インクリメントします`cnt[i-last-1]`この長さが正の場合。 
2. 配列全体を処理した後、すべての値の最後の出現の後にサフィックス ギャップを追加します。 最後に出現したものが位置にある場合`last`、サフィックスギャップには長さがあります`n-last-1`。 

また、個別の値がいくつ発生するかも数えます。 この番号に電話してください`K`。 これらの値はそれぞれ、それを含むすべてのウィンドウに 1 つの可能な個別のタイプを提供します。 
3. 可能なウィンドウ長を処理する`d`から`n`まで`1`。 2 つのサフィックス数量を維持します。 

させて`gap_count`少なくとも長さのあるギャップの数である`d`。 させて`gap_weight`の合計になる`L+1`そのようなギャップすべてを乗り越えます。 

から移動するとき`d+1`に`d`、長さが正確に一致するギャップを追加するだけで済みます。`d`したがって、両方の量を一定時間で更新できます。 
4. 長さのウィンドウの数を計算します。`d`対応する値を回避します。 

長さのあらゆるギャップに対して`L >= d`、含まれています`L-d+1`長さのある窓`d`。 関連するすべてのギャップを合計すると、次のようになります。`gap_weight - d * gap_count`。 
5. あります`n-d+1`長さのある窓`d`、 そして`K`明確な価値観。 したがって、欠落している値を削除する前の値とウィンドウのペアの数は次のようになります。`K(n-d+1)`。 

ウィンドウに値が存在しないペアの数を減算します。`S_d = K(n-d+1) - gap_weight + d*gap_count`。 
6. この値を保存し、次に小さい値で続行します。`d`。 到達後`d=1`、すべての計算値を昇順に出力します。 

### なぜ効果があるのか

 値を修正する`x`。 あらゆる長さ-`d`ウィンドウには次のいずれかが含まれます`x`またはそうではありません。 すべてを数えることから始めると`n-d+1`のための窓`x`を含むウィンドウを正確に数えます。`x`加えて窓を避ける`x`。 窓避け`x`が発生する間のギャップ内に完全に存在する必要があります。`x`、2 つの境界ギャップを含みます。 長さのギャップ`L`正確に含まれています`max(0,L-d+1)`そんな窓。 したがって、この式は、次の内容を含むウィンドウの数を正確にカウントします。`x`。 

すべての個別の値についてこの数量を合計すると、各ウィンドウは、その中に存在する個別の値ごとに 1 回カウントされます。 それはまさにウィンドウの貢献の定義です。`S_d`。 すべてのギャップはその値の連続出現から生成され、空でないギャップはすべて 1 回カウントされるため、サフィックス集計ではすべてのギャップについて正確な減算が計算されます。`d`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    last = {}
    gap_cnt = [0] * (n + 1)
    distinct = 0

    for i, x in enumerate(a):
        if x not in last:
            distinct += 1

            # Gap before the first occurrence of x.
            gap = i
            if gap > 0:
                gap_cnt[gap] += 1
        else:
            # Gap between two consecutive occurrences of x.
            gap = i - last[x] - 1
            if gap > 0:
                gap_cnt[gap] += 1

        last[x] = i

    # Gap after the last occurrence of every value.
    for pos in last.values():
        gap = n - pos - 1
        if gap > 0:
            gap_cnt[gap] += 1

    ans = [0] * n

    gap_count = 0
    gap_weight = 0

    for d in range(n, 0, -1):
        gap_count += gap_cnt[d]
        gap_weight += gap_cnt[d] * (d + 1)

        windows = n - d + 1
        avoiding = gap_weight - d * gap_count

        ans[d - 1] = distinct * windows - avoiding

    return " ".join(map(str, ans))

if __name__ == "__main__":
    print(solve())
```辞書`last`各値の最新の発生のみを保存します。 すべてのギャップは 2 つの連続する出現によって決定され、左から右にスキャンしている間、前の出現はまさに必要なものであるため、これで十分です。 

最初に出現するとプレフィックス ギャップが作成されます。 前の出現はまだ保存されているため、以降の出現ごとにその直前にギャップが作成されます`last`。 サフィックスのギャップはスキャンが完了するまで分からないため、反復して追加されます。`last.values()`その後。 

配列`gap_cnt`サイズがあります`n+1`ギャップには最大でも含めることができるため、`n-1`ポジション。 長さゼロのギャップには正の長さのウィンドウを含めることができないため、無視します。 

逆ループでは、二次関数のように見える合計が消えます。 特定の場所で`d`、`gap_count`とのギャップの数が含まれます`L >= d`、 その間`gap_weight`の合計が含まれます`L+1`まさにそれらのギャップを超えて。 したがって、`gap_weight - d*gap_count`まさに`Σ(L+1-d) = Σ(L-d+1)`。 

Python の整数はオーバーフローしません。これは重要です。`S_d`よりもはるかに大きくなる可能性があります`n`。 たとえば、多くの個別の値を使用すると、答えは次のようになります。`n²`。 

インデックス付けは、位置については意図的に 0 から始まりますが、ウィンドウの長さについては 1 から始まります。 ゼロから始まる位置での出現前のギャップ`i`長さがある`i`、ポジションの後にギャップがある間`i`長さがある`n-i-1`。

```価値`1`長さ 1 の内部ギャップが 1 つあり、値`2`長さ 1 のプレフィックス ギャップと長さ 1 のサフィックス ギャップがあります。 したがって、`cnt[1] = 3`そして 2 つの異なる値があります。 のために`d=2`、減算の前には 2 つのウィンドウと 3 つの値とウィンドウのペアがあります。 長さ 1 の各ギャップはゼロ回避ウィンドウに寄与します。`S_2 = 2 * 2 = 4`。 のために`d=1`、すべてのギャップが 1 つの回避ウィンドウに寄与し、次のようになります。`S_1 = 3 * 2 - 3 = 3`。 結果は`3 4 2`。

```すべての値は 1 回だけ出現します。 長さのある窓`d`正確に含まれています`d`明確な価値観があり、`n-d+1`そんな窓。 したがって`S_d = d(n-d+1)`、生産`4 6 6 4`。 ギャップの定式化では、各値にはプレフィックスとサフィックスのギャップがあり、さらに、その存在しない繰り返し出現間のギャップは存在しません。 減算の結果、まったく同じ値が得られます。
