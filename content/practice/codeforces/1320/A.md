 ## 解決策

 ## 問題の理解

 都市の列が与えられ、各都市には左から右へのインデックスと、それに関連する美しさの値が与えられます。 インデックスが厳密に増加するように、訪問する都市の順序を選択する必要があります。 重要な制限は、連続して選択される都市は任意ではないということです。位置の増加は美しさの増加と一致する必要があります。 正式に市内から転居した場合$i$街へ$j$の場合、インデックスの差は、美しさの値の差に等しい必要があります。 

この条件は、より構造的な方法で書き直すことができます。 並べ替える$$j - i = b_j - b_i$$与える$$b_j - j = b_i - i$$したがって、有効な旅程内のすべての都市は、同じ値を共有する必要があります。$b_i - i$。 この 1 つの観察により、問題は派生キーによるグループ化に変わります。 

目標は、有効な都市グループ (同じキー) を選択し、それらの美しさの値の合計を最大化することです。 グループは 1 つの都市で構成され、常に有効です。 

制約$n \le 2 \cdot 10^5$都市の二次ペアを除外します。 すべてのペアを試行したり、すべての有効なエッジ間の遷移を構築したりするソリューションは、次のように性能が低下します。$O(n^2)$最悪の場合、遅すぎる場合もあります。 線形または線形に近いグループ化戦略が必要です。 

すべての都市に明確な特徴がある場合、微妙なエッジケースが現れます。$b_i - i$価値観。 この場合、有効なすべての行程の長さは 1 であるため、答えは単純に最大値になります。$b_i$。 少なくとも 1 つの有効な遷移を想定する単純なアプローチでは、存在しないチェーンを誤って拡張しようとする可能性があります。 

もう 1 つのエッジケースは、多くの都市が同じものを共有している場合です。$b_i - i$しかし連続していません。 この条件では、配列内の隣接性は必要なく、派生キーの同等性のみが必要となるため、順序が維持される限りインデックスのスキップは有効です。 

## アプローチ

 ブルートフォース戦略は、すべての都市から開始して、有効な次の都市すべてに拡張しようとします。 都市から$i$、すべてを試すことができます$j > i$遷移条件が成立するかどうかを確認します。 遷移が成功するたびに、再帰的または DP 拡張が行われます。 これは制約を直接強制するため論理的に機能しますが、都市ごとに後のすべての都市をスキャンする可能性があるため、$O(n^2)$トランジション。 と$2 \cdot 10^5$都市、これは次の順序です$4 \cdot 10^{10}$チェックしますが、それは不可能です。 

重要な構造の簡素化は、制約を書き直すことで実現します。 連続する都市の条件は、次の条件が等しいかどうかにのみ依存します。$b_i - i$。 これは、問題全体が、この値によってインデックス付けされた独立したグループに分解されることを意味します。 一度グループ化されると、異なるグループ間に相互作用はなくなり、グループ内ではインデックスの増加に関するすべてのサブセットが有効になります。 

これにより、問題はキーごとに単純な累積タスクに変わります。$b_i - i$、対応するすべての合計$b_i$値を計算し、すべてのグループの最大値を取得します。

 ## アルゴリズムのチュートリアル

 1.各都市ごと$i$、値を計算します$key = b_i - i$。 これにより、制約がグループ化ルールに変換されます。 これが機能する理由は、隣接する都市間の元の条件がこの式の平等になるためです。 
2. 各キーからそのキーを持つすべての都市の美しさの値の合計までのハッシュ マップを維持します。 各都市はそのグループに独自に貢献しています。 
3. すべての都市を繰り返し、追加します。$b_i$に相当する合計に$b_i - i$。 これにより、有効なすべての旅行グループの合計貢献度が計算されます。 
4. すべてのキーの最大合計を追跡します。 有効な行程は完全に 1 つのキー グループ内に存在する必要があるため、これは可能な限り有効な行程を選択することを表します。 
5. 見つかった最大値を出力します。 

### なぜ効果があるのか

 変革$j - i = b_j - b_i$の不変性を意味します$b_i - i$連続するすべてのステップ、つまりシーケンス全体にわたって。 これにより、都市が互いに素なクラスに分割され、遷移は内部では常に有効ですが、外部では不可能になります。 あらゆる有効な旅はまさにそのようなクラス内の部分的なものであり、その全体的な美しさは単にその要素の合計です。 クラス内のサブセットを自由に選択できるため、そのクラス内のすべての要素を取得すると合計が最大になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    b = list(map(int, input().split()))
    
    mp = {}
    ans = 0
    
    for i, val in enumerate(b, start=1):
        key = val - i
        if key in mp:
            mp[key] += val
        else:
            mp[key] = val
        if mp[key] > ans:
            ans = mp[key]
    
    print(ans)

if __name__ == "__main__":
    solve()
```コードはグループ化のアイデアを直接実装しています。 列挙は、問題の都市インデックスと一致するように 1 から始まります。 辞書にはキーごとの累積合計が保存され、2 回目のパスを避けるために答えがその場で更新されます。 

よくある落とし穴は、主要な計算ではインデックスが 1 から始まることを忘れることです。 0 から始まるインデックスを使用すると、すべてのグループがシフトされ、関連のない都市が誤って結合されます。

 ## 特殊なケース

 いつ$n = 1$の場合、組み合わせるものが何もないため、アルゴリズムは単一のキーを割り当て、その単一の値を返します。 入力用`[100]`、鍵は$100 - 1 = 99$、答えはそのまま100です。 

いつすべて$b_i - i$値は異なりますが、各グループのサイズは 1 です。 例えば、`[10, 1, 100]`キーを生成する`9, -1, 97`したがって、マージは行われず、単一の最大値が返されます。 各キーが辞書内で分離されているため、このアルゴリズムにより、誤った集計が自然に回避されます。 

すべての都市が同じキーを共有する場合、たとえば`[1,2,3,4]`、すべての都市が 1 つのアキュムレーターに寄与し、アルゴリズムは効率的に配列全体を合計します。 これは、シーケンスを明示的に構築しなくても、長い有効なチェーンが完全にキャプチャされることを示しています。
