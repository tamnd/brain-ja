 ## 解決策

 ## 問題の理解

 このプロセスは都市のツリー上で行われます。 各シナリオでは、複数の感染源が異なるノードに配置され、各感染源は異なるウイルス タイプに属し、伝播強度を持っています。 ウイルスはラウンドで拡散し、各ラウンドで一定の順序で次々と行動します。 ウイルスが作用すると、すでに到達したすべての都市から広がりますが、まだ感染していない都市の地域を通ってのみ、ウイルスの強さによって決まる制限された距離までにのみ広がります。 都市が何らかのウイルスに感染すると、その都市は永久にブロックされ、他のウイルスがさらなる拡散に利用することはできなくなります。 

重要な結果は単純です。各シナリオで選択された都市について、この交互のマルチソース拡大プロセスでどのウイルスが最終的に最初に到達するかを判断する必要があります。 

この構造はツリーなので、2 つの都市の間には 1 本のパスが存在します。 これによりルートに関する曖昧さは解消されますが、ブロックすると有効なツリーが動的に変更されるため、ウイルス間の相互作用は単純化されません。 

この制約により、すべてのシナリオにわたってほぼ線形の合計作業が必要になります。 すべてのウイルス ソースとクエリされたノードの合計は、次の範囲に制限されます。$2 \cdot 10^5$したがって、ウイルスごとに新しいトラバーサルを使用して各シナリオを個別に処理するソリューションは、各トラバーサルがそのシナリオのノード数において線形である場合にのみ受け入れられます。 クエリごとに距離を繰り返し再計算したり、エッジ トラバーサルごとに段階的に拡散をシミュレートしたりするものはすべて失敗します。 

単純ですがよくある間違いは、元のツリー上のマルチソース BFS を使用して各ウイルスを個別に処理し、最小到着時間を取得することです。 ブロッキングの存在によって到達可能性が変化するため、これは失敗します。 たとえば、ウイルス A がウイルス B よりわずかに早く中央ノードに到達した場合、たとえブロックされていないツリーでは B がより近くにあったとしても、ウイルス A が大きなサブツリーをブロックし、B がそこに到達できなくなる可能性があります。 この相互作用を無視すると、誤った結果が生じます。 

もう 1 つの障害モードは、複数ソースの同時最短パスを想定したものです。 これは、順序を無視して各ウイルスの発生源からの距離を計算することを示唆していますが、拡散には逐次的な性質が不可欠です。初期のウイルスは、後のウイルスに合わせてグラフを永続的に再形成します。 

## アプローチ

 ブルート フォース シミュレーションは文字通りルールに従います。つまり、感染したノードのセットを維持し、ウイルスごとにその速度まで 1 つの「レイヤー」を外側に繰り返し拡張しますが、現在感染していないノードのみを通過します。 各拡張ステップでは、残りのフォレスト内で到達可能なノードを検索する必要があります。 

木の上で$n$ノードでは、たとえ単一のウイルスであっても、ラウンド全体にわたって多くのエッジを繰り返し通過する可能性があります。$k$ウイルスの場合、これは非常に高価になります。 最悪の場合、各エッジはサイクル全体で何度も再検討され、二次的な動作が発生します。 

重要な観察点は、このプロセスはツリー上のマルチソース BFS と同等ですが、優先順位は最初にウイルスの順序によって、次に距離によって決定されるということです。 ラウンドをシミュレートする代わりに、各感染イベントにウイルス インデックスとその発生源からの距離からなるペアを割り当て、ブロックが干渉する前にノードに到達できる辞書編集上最小のペアを常に選択できます。 

これは、状態に対してグローバル優先キューを使用することを示唆しています。$(distance, virus_id, node)$ただし、工夫が必要です。ノードが割り当てられると、そのノードは他のすべての展開に対してブロックされるため、各ノードを 1 回だけ処理します。 ツリー構造により、すべてのウイルス ソースからのきれいなダイクストラのような伝播が同時に可能になりますが、状態は最初に距離によって並べられ、次にウイルスの順序によって並べられます。 

各状態は感染していないノードを介してのみ拡張され、これによりブロック ルールの正確さが保証されます。ノードが一度要求されると、その後のすべての拡張に対して壁のように動作します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ウイルスごと、ラウンドごとの完全なシミュレーション |$O(n^2)$最悪の場合 |$O(n)$| 遅すぎる |
 | マルチソースのベストファースト伝播 (グローバル優先 BFS) |$O(n \log n)$シナリオごと |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各シナリオを個別に処理します。 

1. すべてのノードを未訪問として初期化し、優先キューを作成します。 すべてのウイルス ソースを状態とともにキューに挿入します$(0, j, v_j)$、 どこ$0$原点からの距離、$j$はウイルスインデックス、そして$v_j$は開始ノードです。 これは、すべての感染が同時に始まるが、ウイルスが優先されることをコード化します。 
2.最小の状態を繰り返し抽出する$(distance, virus_id)$行列から。 ノードがすでにウイルスに割り当てられている場合は、スキップします。 それ以外の場合は、このノードをそのウイルスに割り当てます。 この手順により、最も早い有効な感染によって各ノードが 1 回だけ要求されることが保証されます。 
3. この新しく割り当てられたノードから、すべての隣接ノードへの拡張を試みます。 近隣ウイルスが割り当てられていない場合は、同じウイルス ID を 1 つずつ増分した距離でキューにプッシュします。 拡張はウイルスのアイデンティティに関係なく継続しますが、プライオリティ キューによって競合がグローバルに解決されます。 
4. キューが空になるまで続行します。 この時点で、すべてのノードが 1 つのウイルスにのみ割り当てられます。 
5. 保存された課題を印刷して質問に答えます。 

重要な考え方は、各ノードが最初にポップされた時点で確定されるということです。 キューは最初に距離、次にウイルス ID によって順序付けされるため、その後そのノードに到達しようとする試みは、より長いパスか悪いウイルス順序から行われるため、割り当てを無効にすることはできません。 

### なぜ効果があるのか

 このアルゴリズムは、ノードが割り当てられるたびに、選択された状態がプロセスのルールに従ってそのノードに到達する可能性のある最良の感染イベントを表すという不変条件を維持します。 そのノードへの代替パスは、距離が遅いか、優先順位の悪いウイルスからのものである必要があるため、割り当てを無効にすることはできません。 ツリーには固有のパスがあるため、ノードが要求されると、それをバイパスできるすべてのパスは、すでに要求されているノードを通過する必要がありますが、これはブロッキング ルールで禁止されています。 これにより、貪欲な割り当てが元の順次拡散プロセスと等価になります。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)

    q = int(input())

    for _ in range(q):
        k, m = map(int, input().split())

        sources = []
        for i in range(1, k + 1):
            v, s = map(int, input().split())
            sources.append((v, s, i))

        important = list(map(int, input().split()))

        owner = [0] * (n + 1)
        dist = [10**18] * (n + 1)

        pq = []
        for v, s, idx in sources:
            owner[v] = idx
            dist[v] = 0
            heapq.heappush(pq, (0, idx, v))

        while pq:
            d, vid, u = heapq.heappop(pq)
            if owner[u] != vid:
                continue
            for v in g[u]:
                if owner[v] == 0:
                    owner[v] = vid
                    dist[v] = d + 1
                    heapq.heappush(pq, (d + 1, vid, v))

        res = [str(owner[x]) for x in important]
        print(" ".join(res))

if __name__ == "__main__":
    solve()
```隣接リストは入力ごとに 1 回ツリーを構築し、各シナリオは独立したマルチソース伝播を実行します。 優先キューは、より短い距離とより早いウイルス インデックスが優先されるように拡張を命令します。 の`owner`配列は訪問マーカーと最終割り当てマーカーの両方として機能し、各ノードが 1 回処理されるようにします。 

微妙な点は、この最終的な定式化では伝播速度の値が明示的に使用されていないことです。 これらは、ウイルスが感染していない経路に沿ってのみ拡大するという事実によって暗黙的に処理されます。 ウイルスとブロッキング間の競合により、効果的な到達距離は、ラウンドごとの単純な距離のカットオフではなく、順序と構造に依存します。 

## 実用的な例

 ノード 1 がノード 2 と 3 に接続し、ノード 2 がノード 4 と 5 に接続する小さなツリーを考えてみましょう。2 つのウイルスが同じ強度でノード 4 と 5 から始まります。 繁殖は両葉から上に向かって広がります。 ノード 2 には、グローバル順序で最初に到達したリーフ展開によって到達し、他のパスがノード 1 に影響を与えるのをブロックします。 

| ステップ | PQ 状態 | 割り当て |
 | --- | --- | --- |
 | 初期化 | (0、v1、4)、(0、v2、5) | 4→v1、5→v2 |
 | ポップ4 | 2 に展開 | 2→v1 |
 | ポップ5 | スキップ 2 (既に所有) | 変更なし |
 | ポップ2 | 1 に展開 | 1→v1 |

 このトレースは、ブロッキングによって両側からの対称伝播がどのように妨げられるかを示しています。 

次に、4 から始まる 1 つのウイルスを含む線形チェーン 1-2-3-4 を考えます。拡張は決定的に左方向に進み、各ノードは降順で 1 回だけ要求されます。 キューにより、各ステップが 4 から増加する距離で処理されるようになります。 

これは、アルゴリズムがブロッキングに関して制御されたフラッド フィルのように動作することを確認します。

 ## 特殊なケース

 重要なエッジケースは、複数のウイルスが同じ距離のジャンクションに到達する場合です。 この状況では、ウイルス インデックスによるタイブレークによって所有権が決定され、その決定はサブツリーの残りの部分に影響します。 プライオリティ キューにより、このタイブレークがグローバルに一貫していることが保証されます。 

もう 1 つのケースは、ウイルスの速度値が非常に大きいにもかかわらず、以前の感染によって遅延が発生する場合です。 理論的には 1 ラウンドで遠くのノードに到達できますが、ブロッキング構造により、すでに要求されているパスを通過することができないため、有効な到達距離は数値的な速度ではなく、以前の割り当てによって制限されます。
