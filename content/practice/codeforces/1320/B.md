 ## 解決策
 ## 問題の理解

 交差点がノード、道路が一方通行のエッジである有向グラフが与えられます。 また、ポリカルプが自宅から職場まで実際に運転する、固定された単純なルートもわかっています。 このルートは、連続するすべての交差点のペアが道路で接続されているという意味では有効ですが、エッジの数の点で必ずしも最短ルートであるとは限りません。 

これに加えて、現在位置から目的地までの最短経路を維持しようとするナビゲーション システムもあります。 システムは最初に、出発地から目的地までの最短パスを選択します。 Polycarp が次に推奨されるエッジに従うときは常に、システムは現在の計画を維持します。 逸脱するたびに、システムは古い計画を破棄し、新しい位置から目的地までの最短経路を再計算します。 

必要な量は、リビルドと呼ばれるこの再計算が何回行われるかです。 複数の最短経路が存在する場合、ナビゲーション システムは任意の最短経路を自由に選択でき、Polycarp のルートは固定されているため、答えは一意ではありません。 システムによって行われたすべての有効な選択に対して、最小可能な再構築数と最大可能な再構築数の両方を計算する必要があります。 

制約は最大 20 万の交差点と道路に適用され、各ステップで最短経路を最初から再計算するソリューションは除外されます。 ステップごとの新しい BFS は、最悪の場合は 2 次となり、合格しません。 この構造は、最短距離を 1 回前処理してから、Polycarp のパスの各ステップを一定時間で評価する必要があることを示唆しています。 

複数の最短パスが存在する場合、微妙な問題が発生します。 それらの中からナビゲーション システムが選択することによって、Polycarp の次のステップが推奨ルートと一致するか、再構築を強制されるかが決まります。 これは、答えが距離だけでなく、各ノードから目的地までの最短経路に沿った「有効な次のステップ」がいくつ存在するかにも依存することを意味します。 

単純な推論を露呈する特殊なケースの 1 つは、すべての出力最短エッジが同じ次のノードにつながる場合です。 その場合、グローバルには複数の最短パスが存在する可能性がありますが、ローカルではシステムに柔軟性がなく、Polycarp は強制エッジに一致するか、彼の動きに応じて再構築をトリガーします。 

## アプローチ

 直接シミュレーションでは、すべてのステップで最短経路を再構築し、Polycarp の決定をシミュレートしようとします。 各再計算にはグラフの走査が含まれ、最大 n 個のステップが存在する可能性があるため、これはすぐにコストが高くなります。 最悪のケースでは、大きなグラフに対して BFS が繰り返し実行され、3 次または 2 次に近い動作が発生します。 

重要な観察は、完全な最短パス構造は決して必要ないということです。 任意のノード u について、u から目的地 t までの最短パス上で次のノードとしてどの隣接ノードが現れるかを知る必要があるだけです。 これは、反転グラフ上で反転 BFS を使用してすべてのノードから t までの最短距離を計算することによって 1 回で導出できます。 

dist[x] がわかると、dist[u] = dist[v] + 1 のとき、有向エッジ u → v は u から t への最短経路の一部になります。これにより、ナビゲーション システムの動作がローカル ルールに変わります。つまり、各ステップで、この等式を満たす出力エッジの中からのみ選択できます。 

ここで、p[i] から p[i+1] に移動する Polycarp を考えてみましょう。 このエッジが最短距離条件と一致しない場合、システムの選択に関係なく、Polycarp は逸脱を強制し、再構築を強制します。 一貫性がある場合、再構築が行われるかどうかは、システムが代わりに別の有効な最短エッジを選択できたかどうかに完全に依存します。

最小限の再構築回数については、システムが協調的であると仮定します。 有効な最短ステップ近傍である場合は常に p[i+1] を選択し、不必要な発散を回避します。 リビルドは、p[i+1] が最短ステップの移動ではない場合にのみ発生します。 

再構築の最大数に対して、システムは敵対的に動作します。 p[i+1] とは異なる代替の最短ステップ近傍が存在する場合は常に、システムはそのような近傍を選択し、Polycarp に強制的に逸脱させ、次のステップで再構築をトリガーできます。 p[i+1] が固有の有効な最短ステップ近傍である場合にのみ、システムはそれに従うことを強制され、再構築が妨げられます。 

これにより、問題全体が、ステップごとに、次の手が有効な最短ステップ エッジであるかどうか、また、そのようなエッジの中で一意であるかどうかを数えることに集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 最短パスを繰り返すブルート フォース シミュレーション | O(k · (n + m)) | O(n + m) | 遅すぎる |
 | BFS 距離 + ローカル最短エッジ チェック | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのエッジを反転し、t から開始する BFS を実行して、すべてのノード x から宛先までの最短距離である dist[x] を計算します。 これが機能するのは、反転したグラフでは、最短距離を t から逆方向に効果的に伝播しているためです。 
2. 各ノード u について、dist[u] = dist[v] + 1 を満たす発信近隣 v の数を決定します。この数は、u に座っているときにナビゲーション システムが持つ有効な選択肢の数を表します。 
3. 最小および最大再構築用の 2 つのカウンターをゼロに初期化します。 
4. Polycarp のパスを p[1] から p[k] までたどります。 p[i] から p[i+1] への各遷移について、dist[p[i]] = dist[p[i+1]] + 1 かどうかを確認します。この等式が成り立たない場合、その移動は p[i] から t への最短パスに属することができず、最小の場合の再構築が強制されます。 
5. 最大数については、p[i] の有効な最短ステップ近傍の数が 1 より大きいかどうか、または唯一の有効な近傍が p[i+1] ではないかどうかを確認します。 これらの状況のいずれでも、ナビゲーション システムは代替の最短移動を選択し、Polycarp を推奨パスから強制的に外し、再構築を引き起こす可能性があります。 
6. パス内のすべてのエッジにわたってこれらの条件を累積して、最終的な最小カウントと最大カウントを取得します。 

正しさは、最短経路が t からの距離に応じて層状構造を形成するという事実にかかっています。 最適な移動を行うたびに、この距離が厳密に 1 だけ減少します。 ナビゲーション システムの自由度はまさにこの層状グラフ内の分岐要素であり、Polycarp のパスはこれらの層の 1 つをたどるか、層の外にジャンプして再計算を強制します。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

n, m = map(int, input().split())
g_rev = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v = map(int, input().split())
    g_rev[v].append(u)

k = int(input())
p = list(map(int, input().split()))

INF = 10**18
dist = [INF] * (n + 1)

# BFS from destination
t = p[-1]
q = deque([t])
dist[t] = 0

while q:
    u = q.popleft()
    for v in g_rev[u]:
        if dist[v] == INF:
            dist[v] = dist[u] + 1
            q.append(v)

# count valid next steps on shortest paths
good_cnt = [0] * (n + 1)

for u in range(1, n + 1):
    for v in g_rev[u]:
        # reversed graph: v -> u in original, so check original condition via reverse logic
        if dist[v] == dist[u] + 1:
            good_cnt[u] += 1

mn = 0
mx = 0

for i in range(k - 1):
    u = p[i]
    v = p[i + 1]

    on_shortest = (dist[u] == dist[v] + 1)

    if not on_shortest:
        mn += 1
        mx += 1
    else:
        if good_cnt[u] > 1:
            mx += 1

print(mn, mx)
```BFS は、反転グラフ上ですべてのノードから目的地までの最短距離を線形時間で計算します。 必要なグローバル情報はこれだけです。 他のすべては、発信最短パス エッジを検査することによってローカルに決定されます。 

の`good_cnt`配列は、ナビゲーション システムが最短経路に沿って何通りの方法で続行できるかを測定します。 これは、Polycarp を推奨ルートから強制的に外せるかどうかを決定するため、最大限の計算を行うために非常に重要です。 

指定されたパスの走査中に、各ステップは強制再構築 (エッジがどの最短パスとも互換性がない場合) か、分岐のみが最大値を決定する潜在的に回避可能なステップとして分類されます。 

## 実用的な例

 中間ノードと目的地の間に複数の最短ルートが存在し、Polycarp が最短構造をたどったり、最短構造から逸脱したりする小さなグラフを考えてみましょう。 まず目的地からの距離を計算し、次に距離が 1 減少するかどうかによって各ステップを分類します。 

サンプル入力では、最初のトランジションで、移動が距離レイヤリングと一致しているかどうかを確認します。 そうでない場合は、システムを再構築する必要があるため、最小カウントと最大カウントの両方がすぐに増加します。 後のステップでは、移動が一貫している場合でも、代替の有効な近傍の存在によって、最大カウントが増加するかどうかが決まります。 

| ステップ | 現在のユーザー | 次のv | 距離[u] | 距離[v] | 最短で | 良い_cnt[u] | ん | MX |
 | --- | --- | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 2 | 3 | 2 | はい | >1 | 0 | 1 |
 | 2 | 2 | 3 | 2 | 1 | はい | 1 | 0 | 1 |
 | 3 | 3 | 4 | 1 | 0 | はい | 1 | 0 | 1 |

 このトレースは、最短パス遷移に分岐が存在する場合にのみ、最小値と最大値がどのように発散するかを示します。 グラフが単一の最短継続を強制すると、両方の値が一致します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 反転グラフ上の BFS に加えて、ノードとパス上の 1 つのパス |
 | スペース | O(n + m) | 隣接リストと距離配列 |

 前処理はグラフのサイズにおいて線形であり、パス スキャンは k において線形です。 総制約が最大 200,000 であるため、これは制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n, m = map(int, input().split())
    g_rev = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        g_rev[v].append(u)

    k = int(input())
    p = list(map(int, input().split()))

    INF = 10**18
    dist = [INF] * (n + 1)

    t = p[-1]
    q = deque([t])
    dist[t] = 0

    while q:
        u = q.popleft()
        for v in g_rev[u]:
            if dist[v] == INF:
                dist[v] = dist[u] + 1
                q.append(v)

    good_cnt = [0] * (n + 1)
    for u in range(1, n + 1):
        for v in g_rev[u]:
            if dist[v] == dist[u] + 1:
                good_cnt[u] += 1

    mn = mx = 0
    for i in range(k - 1):
        u, v = p[i], p[i + 1]
        if dist[u] != dist[v] + 1:
            mn += 1
            mx += 1
        else:
            if good_cnt[u] > 1:
                mx += 1

    return f"{mn} {mx}"

## 特殊なケース

 重要なエッジ ケースは、Polycarp の次のステップがまだ最短パス上にあるものの、可能な唯一の最短継続ではない場合に発生します。 この状況では、システムは連携できるため最小カウントは増加しませんが、システムが別の有効な継続を意図的に選択して再構築を強制できるため、最大カウントは増加します。 この分離は、パス自体が最短一貫性を保っている場合でも、そのノードで Good_cnt[u] が 1 より大きいかどうかによって完全に決まります。
