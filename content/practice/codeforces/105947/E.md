 ## 解決策
 ## 問題の理解

 それぞれが整数配列で構成されるいくつかのテスト ケースが与えられています。 各配列について、タスクは、正確に含まれる連続するサブ配列の数を数えることです。`k`明確な価値観。 

連続した部分配列は、要素を並べ替えずに左側の境界と右側の境界を選択することによって形成された配列のスライスです。 「正確に k 個の個別の値」とは、そのスライス内のすべての要素を調べた場合、そこに現れる一意の数値の数が正確に同じであることを意味します。`k`。 

したがって、各テスト ケースの出力は単一の数値、つまりそのような部分配列の合計数になります。 

この制約は、古典的なサブ配列カウント設定を意味します。 すべてのテスト ケースの合計の長さは最大約`2 · 10^5`これにより、テスト ケースごとに 2 次の解が除外されます。 すべての部分配列の単純な O(n²) 列挙では、最悪の場合、約 2e10 回の演算が実行されますが、これは制限をはるかに超えています。 これにより、私たちは線形または線形に近い手法、通常はスライディング ウィンドウまたは 2 つのポインターを使用するようになりました。 

不適切なソリューションを壊すことがよくある微妙なエッジケースがいくつかあります。 

すべての要素が等しい場合、`k = 1`、すべての部分配列が有効です。 例えば、`[5, 5, 5]`6 つの有効な部分配列が生成されるはずです。 誤って最大セグメントのみをカウントする単純な解決策では、過小カウントされてしまいます。 

もし`k` is larger than the number of distinct elements in the whole array, the answer must be zero. For instance, `[1, 2, 1]`と`k = 3`すべての部分配列には最大 2 つの異なる値がありますが、有効な部分配列がありません。 

もう 1 つの注意が必要な状況は、重複がインターリーブされている場合です。 例えば、`[1, 2, 1, 2]`と`k = 2`には有効な部分配列が多数あり、カウントには境界を慎重に処理する必要があります。 適切に縮小せずに単に個別のカウントを追跡すると、重複するウィンドウが過剰にカウントされることになります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての左のエンドポイントを反復し、右のエンドポイントを展開し、個別の値をカウントするための要素のセットを維持します。 右ポインタを拡張するたびに、セットを再計算または更新し、個別の値の数が正確であるかどうかを確認します。`k`。 これは、考えられるすべてのセグメントを直接チェックするため、すべての有効なサブ配列を正確にカウントします。 

問題はパフォーマンスです。 展開ごとのセットの維持は O(1) で償却されますが、最悪の場合でもテスト ケースごとに O(n²) 個の部分配列を検査します。 合計入力サイズが 2e5 の場合、これは実行不可能になります。 

重要な観察は、実際には「正確に k」を直接カウントする必要はないということです。 代わりに、「最大 k」個の個別の値を数える方がはるかに簡単です。 標準的なスライディング ウィンドウ技術により、ウィンドウを維持できます。`[l, r]`常に最大でも次の内容が含まれるようにする`k`独特の要素。 それぞれについて`r`、で終わるすべてのサブ配列`r`そしてどこからでも始めてください`l`に`r`はこの制約の下で有効であり、貢献します`(r - l + 1)`サブアレイ。 

計算できるようになると`atMost(k)`、この問題を 2 つのより簡単な問題の差に変換できます。`k`個別の値が等しい`atMost(k) - atMost(k - 1)`。 これは、すべてのサブ配列が正確に一致するため機能します。`k`個別の値が含まれています`atMost(k)`ただし除外される`atMost(k - 1)`。 

これにより、問題は 2 つの線形スライディング ウィンドウ パスに変換されます。

 ## アルゴリズムのチュートリアル

 ヘルパー関数を構築します`at_most(k)`サブ配列を最大で数えます`k`明確な価値観。 

1. 2 つのポインタを初期化する`l = 0`そして`result = 0`。 周波数マップも維持します`freq`そして変数`distinct = 0`。 マップは、各値が現在のウィンドウに表示される回数を追跡します。 
2. 右ポインタを展開します`r`から`0`に`n - 1`、追加`a[r]`窓へ。 この値が以前に存在しなかった場合は、値を増やします。`distinct`。 マップ内の頻度を更新します。 
3. もし`distinct`を超える`k`、ウィンドウを左から縮小します。 動く`l`周波数を減少させながら前進します。 周波数がゼロになると減少します`distinct`。 これにより、ウィンドウが持つ最大の不変条件が復元されます。`k`明確な価値観。 
4. ウィンドウが有効になった後、次で終わるすべてのサブ配列が削除されます。`r`との間で始まります`l`そして`r`有効です。 追加`(r - l + 1)`に`result`。 これは、そのようなすべてのサブ配列が現在の有効なウィンドウ内にまだ存在するため、機能します。 
5. 戻る`result`。 

最終的な答えを求めるには、次のように計算します。`at_most(k) - at_most(k - 1)`。 

### なぜ効果があるのか

 あらゆるステップで、窓が`[l, r]`部分配列が次で終わるような最小の左境界です。`r`多くても含まれる`k`明確な価値観。 左側の境界が小さいと制約に違反し、左側の境界が大きいと有効な部分配列が失われます。 これにより、各サブ配列が次で終わるため、寄与のカウントが正確になります。`r`右のエンドポイントが処理されるときに 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def at_most(a, k):
    if k < 0:
        return 0
    freq = defaultdict(int)
    l = 0
    distinct = 0
    res = 0

    for r, x in enumerate(a):
        if freq[x] == 0:
            distinct += 1
        freq[x] += 1

        while distinct > k:
            y = a[l]
            freq[y] -= 1
            if freq[y] == 0:
                distinct -= 1
            l += 1

        res += r - l + 1

    return res

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    print(at_most(a, k) - at_most(a, k - 1))
```中心的な構造は 2 ポインタ スライディング ウィンドウです。 頻度辞書は、現在のウィンドウ内の発生を追跡します。`distinct`一意の要素の数を最初から再計算する必要がなくなります。 

よくある間違いは、それぞれのセットを再計算することです。`r`、黙って解を二次関数に変換します。 もう 1 つは、制約が再び満たされるまで縮小を続けなければならないことを忘れていることです。 単一の条件付き縮小だけでは十分ではありません。 

最後の引き算が重要です。 それなし`at_most(k - 1)`の場合、関数は以下のサブ配列をすべてカウントします。`k`独特の価値観も。

## テストケース```python
import sys, io
from collections import defaultdict

def solve():
    input = sys.stdin.readline
    def at_most(a, k):
        if k < 0:
            return 0
        freq = defaultdict(int)
        l = 0
        distinct = 0
        res = 0
        for r, x in enumerate(a):
            if freq[x] == 0:
                distinct += 1
            freq[x] += 1
            while distinct > k:
                y = a[l]
                freq[y] -= 1
                if freq[y] == 0:
                    distinct -= 1
                l += 1
            res += r - l + 1
        return res

    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        out.append(str(at_most(a, k) - at_most(a, k - 1)))
    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

 ## 特殊なケース

 すべての要素が同一である場合、`k = 1`、ウィンドウは決して縮小しません。`distinct`アルゴリズムは各位置で終わるすべてのプレフィックスをカウントします。これにより、自然に完全な三角数のサブ配列が生成されます。 のために`[5, 5, 5]`、寄与度は 1、2、3 で、合計は 6 となり、正しいカウントと一致します。 

いつ`k = 0`、ヘルパー`at_most(k - 1)`になる`at_most(-1)`これはゼロとして定義されているため、結果もゼロになります。 これにより、サブ配列がゼロの個別の値を持つことができない、特殊な無効な構成が回避されます。 

すべての要素が個別である場合、`k = 2`、ウィンドウは積極的に縮小します。 のために`[1,2,3,4]`、ポジションごとの有効な貢献度は 1、2、2、2 で、7 が与えられます。`at_most(2)`、そして減算`at_most(1)`単一要素の部分配列を削除し、2 つの異なる値を持つ部分配列をそのまま残します。
