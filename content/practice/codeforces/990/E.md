 ## 解決策
 ## 問題の理解

 位置 0 から位置 n まで伸びる 1 次元の通りに沿ってランプを配置しています。 一部の位置は禁止されています。つまり、そこにランプを配置することはできませんが、それ以外の場合は、許可されている任意の位置をベースとして選択できます。 

各ランプのタイプは、単一の整数乗 l によって定義されます。 位置 x に置かれたランプは、x から x + l までのすべてを照らします。 主な制限は、購入全体でランプ タイプを 1 つだけ選択する必要があることですが、そのタイプのランプを必要なだけ購入し、有効な場所に配置することができます。 

目標は、最適なランプ タイプを選択し、間隔 [0, n] 内のすべての点が少なくとも 1 つのランプの照明間隔でカバーされるように、そのタイプの十分な数のランプを配置することです。 コストは選択したタイプにのみ依存するため、電力 l を固定すると、すべてのランプのコストは a_l になり、総コストは必要なランプの数に比例します。 

制約は大きく、n は最大 1e6 まで可能です。 これにより、すべての配置を明示的に試行したり、二次的な方法でカバレッジをシミュレートしたりするソリューションは即座に除外されます。 n と k には線形または線形に近いものが必要です。 

この問題の微妙な側面は、ブロックされた位置はランプを配置できる場所にのみ影響し、カバレッジの定義方法には影響しないことです。 一般的な失敗例は、ブロックされた位置によって長いギャップが生じ、カバレッジの長さがそうでないことを示唆していても、貪欲な配置が不可能になる可能性がある場合に発生します。 

たとえば、すべての有効な位置が大きなブロックされたプレフィックスの後にクラスター化されている場合、合計距離が十分であるように見えても、左側をカバーできない可能性があります。 もう 1 つのエッジ ケースは、ランプの範囲が n を超えて広がる場合です。これは許可されており、推論において人為的に切り詰めてはなりません。 

## アプローチ

 素朴なアプローチは、ランプ電力 l を固定し、左から右への配置を貪欲にシミュレートすることです。 現在カバーされていない位置 x で、y がブロックされないように、到達可能な最も遠い有効な位置 y ≤ x + l にランプを配置してから、カバレッジを y + l にジャンプします。 そのような y が存在しない場合、この累乗は無効です。 これをすべての k 乗について繰り返すと、答えの候補が得られます。 

このアプローチは正しいです。固定電力の場合、現在の覆われていないポイントをカバーしながら、各ランプをできるだけ右端に配置することが常に最良の戦略であるためです。 ただし、単純に実装するとコストがかかります。 カバレッジ ステップごとに、最大 n 個の位置を逆方向または前方向にスキャンすることができ、k 値にわたってこれは O(nk) になります。これは、1e6 までの n に対しては遅すぎます。 

重要な観察は、構造が電力において単調であるということです。 特定の電力 l が機能する場合、各ランプがより長い距離をカバーできるため、必要なランプの数という点では電力が大きい方が少なくとも同等の効果があります。 必要なランプの数は、基本的に、最適な配置を妨げる位置がブロックされているために必要な「強制ジャンプ」の数によって決まります。 

ブロックされた位置をブール配列に前処理し、プレフィックス ジャンプを使用して各位置に対して次の有効な配置機会を効率的に事前計算できます。 さらに重要なのは、ブロックされた位置をスキップしながら配列を貪欲に探索することで、固定 l に対して O(n) に必要なセグメントの数を計算できることです。 

したがって、各 l について O(n) で最初から再計算するのではなく、各 l について必要なのは線形スキャンのみで、全体の複雑さは O(nk) になるという事実を利用します。これは、不可能な場合に早期に終了する Python で慎重に実装されていれば、制約の下で許容可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 電力ごとのブルート フォース シミュレーション | O(nk) 最悪の場合 | O(n) | 単純な形式では遅すぎるが、最適化されたスキャン パス |
 | 電力あたりの貪欲さを最適化 | O(nk) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ランプ電力 l を固定し、[0, n] をカバーするために必要なランプの数を計算します。

1. 禁止位置をマークするサイズ n のブロック化されたブール配列を構築します。 これにより、配置決定中に O(1) チェックが可能になります。 
2. カバーされていない左端の位置を表すポインタ x = 0、およびカウンター ランプ = 0 を初期化します。 
3. x < n の場合、x を覆うランプを配置しようとします。 まず、y ≤ x + l であり、y がブロックされない、右端の有効な配置位置 y を見つける必要があります。 
4. そのような y を見つけるには、ブロックされていない位置に到達するか範囲を使い果たすまで、min(x + l, n - 1) から逆方向にスキャンします。 有効な y が存在しない場合、この力 l は通りをカバーできません。 
5. y が見つかったら、y にランプを配置します。 これは y + l までをカバーするため、x = y + l + 1 を更新し、ランプを 1 ずつ増やします。 
6. 間隔全体がカバーされるまで繰り返します。 
7. すべての有効な電力 l にわたるランプ * a_l の最小値を追跡します。 

常に右端の有効な y を選択する理由は、ランプをさらに右に配置すると、カバレッジを拡大するか、カバレッジを等しく保つだけであり、決して減らすことができないためです。 早期に配置しても、後で必要となるランプの数が増えるだけです。 

### なぜ効果があるのか

 固定べき乗 l の場合、最初のカバーされていない位置 x での貪欲な選択を考えてみましょう。 有効な解決策では、左端点が y ≤ x + l であり、y がブロックされていないランプを配置する必要があります。 このようなすべての配置の中で、可能な最大の y を選択すると、次にカバーされるフロンティア y + l が最大になります。 これにより、各ステップ後にカバーされないプレフィックスが可能な限り小さくなり、ステップ数が最小限に抑えられます。 各ステップは局所的に最適であり、問​​題を厳密に小さいプレフィックスに縮小するため、このプロセスにより、その電力に対して最小数のランプが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    blocked = [False] * n
    if m:
        s = list(map(int, input().split()))
        for x in s:
            blocked[x] = True
    else:
        input()

    a = list(map(int, input().split()))

    INF = 10**18
    ans = INF

    for l in range(1, k + 1):
        x = 0
        lamps = 0
        ok = True

        while x < n:
            start = min(n - 1, x + l)

            y = start
            while y >= x and blocked[y]:
                y -= 1

            if y < x:
                ok = False
                break

            lamps += 1
            x = y + l + 1

        if ok:
            ans = min(ans, lamps * a[l - 1])

    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、スキャン中の実行可能性チェックが一定時間になるように、ブロックされた位置を直接検索配列にエンコードします。 パワーごとにカバレッジを貪欲にシミュレートし、常に手の届く範囲で最も遠い有効な配置を選択します。 内部逆方向スキャンにより、複雑な前処理を必要とせずに、ブロックされた位置が確実に尊重されます。 

更新ステップ x = y + l + 1 は重要です。これにより、カバーされていないフロンティアがランプのカバー範囲を厳密に超えて移動します。 ここでの 1 つ違いの間違いはよくあることですが、+1 により位置 y + l が完全にカバーされることが保証されます。

 ## 特殊なケース

 重大なエッジ ケースは、現在の位置 x 自体が x + l までのブロックされた位置に囲まれている場合です。 例えば：```
n = 5, blocked = [0,1,2], l = 1
```x = 0 の場合、アルゴリズムは [0,1] で有効な配置を見つけようとしますが、両方ともブロックされます。 逆方向スキャンはすぐに失敗し、この電力は無効とマークされます。 これにより、距離だけでカバレッジが保証されるという誤った想定を防ぐことができます。 

もう 1 つのケースは、最後のランプが n を超えて伸びている場合です。 例えば：```
x = n-2, y = n-2, l = 5
```更新 x = y + l + 1 は、x を n を超えて正しく移動し、カバレッジが境界を超えている場合でも完了をマークします。
