 ## 解決策
 ## 問題の理解

 コメントボックスの初期数と必要な代表者数が与えられています。 すべての委任は正確に同じ数のボックスを受け取る必要があり、アイドル状態のままにならないように既存のすべてのボックスを使用する必要があります。 この要件は、単一の算術条件に変換されます。最終的なボックスの数は、委任の数で割り切れる必要があります。 

新しいボックスを構築するか、既存のボックスを取り壊すことにより、現在のボックスの数を変更することができます。 建設するとコストがかかりカウントが 1 増加します`a`、破壊するとコストが1つ減少しますが`b`。 目標は、次の数で割り切れる非負の数に到達することです。`m`最小限の総コストで。 

制約は極めて大きい`n`そして`m`、最大 10^12 で、すべての可能性を試したり、調整を 1 つずつシミュレートしたりするアプローチは直ちに除外されます。 唯一の実行可能な戦略は、純粋にモジュラー算術と最近接倍数の観点から推論することです。 

単純な間違いは、コストを適切に比較せずに、常に次の倍数に上方に移動したり、常に前の倍数に下方に移動したりして、貪欲に割り算を「修正」しようとすることから発生することがよくあります。 もう 1 つの微妙な失敗例は、ゼロまで下げることが常にオプションであり、場合によってはわずかに調整するよりも安価であることを無視していることです。 

## アプローチ

 強引なアイデアは、ボックスの可能な最終的な数をすべてチェックし、それに到達するまでのコストを計算することです。 各候補の最終値について`x`の場合、いくつのボックスを構築する必要があるかを計算します。`x > n`または取り壊される場合`x < n`、そして最高のものを選ぶ`x`で割り切れる`m`。 問題は、検索空間が 10^12 まで無制限であるため、複数回繰り返しても`m`は大きすぎます。 最悪の場合、`m = 1`、最大 10^12 の状態を考慮します。 

重要な観察は、最適な最終的な数値は、次の最も近い倍数の 1 つでなければならないということです。`m`その周り`n`。 コストは距離に応じて直線的に増加し、近い倍数を省略してもメリットがないため、最適なソリューションは遠く離れた場所に存在することはできません。 

したがって、問題は 2 つの候補のみをチェックすることになります。`m`以下`n`、および次の最小倍数`m`以上`n`。 さらに、すべてを取り壊す方が、近くの複数の建物に調整するよりも安価になる可能性があるため、ゼロになる可能性も考慮する必要があります。 

から`n`、剰余を計算します`r = n % m`。 次に:

 - 下げるということは削除することを意味します`r`箱。 
- 上がるということは追加することを意味します`m - r`ボックス（そうでない場合）`r = 0`）。 

各オプションには直接コストがかかり、最小値を採用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのターゲットに対するブルートフォース | O(n) | お(1) | 遅すぎる |
 | 最も近い倍数を確認する | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 剰余を計算する`r = n % m`。 これにより、どのくらいの距離であるかがわかります`n`で割り切れることから`m`。 
2. 削減コストを考慮する`n`最も近い下限の倍数まで`m`、つまり`r * b`。 削除されたボックスごとにコストがかかります`b`。 
3. 増加コストを考慮する`n`の最も近い高い倍数まで`m`、つまり`(m - r) * a`いつ`r != 0`。 追加されるボックスごとにコストがかかります`a`。 
4. コストをゼロまで削減することも検討してください。`n * b`。 Zero is always divisible by`m`, so it is a valid endpoint.
 5. Take the minimum among these options.

 重要な点は、ステップ 3 は次の場合にのみ意味があるということです。`r > 0`、しかし、それを一律に書くと、`(m - r) % m * a`特殊なケースを避けます。 

### なぜ効果があるのか

 有効な最終数値は次の形式でなければなりません。`k * m`。 このようなすべての値の中で、コスト関数は次の距離に沿って線形になります。`n`、増加または減少のいずれかです。 どちらの方向にも最も近い倍数に移動しない場合は、必然的に近い倍数を最初に通過することになり、ユニット ステップ コストにより、コストが低くなるか同等になります。 これにより、最も近い下位倍数と最も近い上位倍数のみをチェックする必要があります。 ゼロを含めると、最適な倍数がはるかに下回る境界ケースが処理されます。`n`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, a, b = map(int, input().split())

r = n % m

# move down to nearest multiple
cost_down = r * b

# move up to nearest multiple
cost_up = (m - r) * a if r != 0 else 0

# also consider going to 0
cost_zero = n * b

print(min(cost_down, cost_up, cost_zero))
```このソリューションでは、剰余を一度計算し、意味のある調整コストのみを直接評価します。 上向きの動きは慎重にガードされているため、`n`はすでに割り切れます`m`の完全なサイクルを誤って追加することはありません。`m`箱。 

の包含`cost_zero`パスは、特に完全な解体が最適なケースの欠落を防ぐものです。`b`に比べて非常に小さいです`a`。 

## 実用的な例

 ### 例 1

 入力:```
9 7 3 8
```ここ`r = 9 % 7 = 2`。 

| ステップ | r | コストダウン | コストアップ | コストゼロ | 答え |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | 2 | 2×8=16 | (7-2)×3=15 | 9×8=72 | - |
 | 最終 | 2 | 16 | 15 | 72 | 15 |

 最適な選択は、最大 14 個のボックスを移動することです (コストは 15)。 

この例は、ユニットを追加する必要がある場合でも、操作ごとのコストが異なるため、上向きに移動する方が下向きに移動するよりもコストが安くなる可能性があることを示しています。

これは、調整の方向が距離だけではなく、単位当たりのコストによって完全に決定されることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m, a, b = map(int, input().split())
    r = n % m
    cost_down = r * b
    cost_up = (m - r) * a if r != 0 else 0
    cost_zero = n * b
    return str(min(cost_down, cost_up, cost_zero))

# provided sample
assert run("9 7 3 8") == "15"

# n already divisible
assert run("14 7 5 2") == "0"

# cheap demolition to zero
assert run("10 6 100 1") == "10"

# cheap building upward
assert run("10 6 1 100") == "2"

# large balanced case
assert run("1000000000000 7 3 8") == str(min((1000000000000%7)*8, (7-1000000000000%7)%7*3, 1000000000000*8))

 ## 特殊なケース

 いつ`n`はすでに割り切れます`m`、残りはゼロであり、上方調整と下方調整の両方がゼロに評価されるか、正しく無視される必要があります。 入力用`n = 14, m = 7`、私たちは得ます`r = 0`、 それで`cost_down = 0`、`cost_up = 0`、答えは正しくゼロであり、操作が必要ないことを示しています。 

解体費用が非常に安い場合、最適な戦略はすべてを削除することかもしれません。 のために`n = 10, m = 6, a = 100, b = 1`、私たちは得ます`cost_zero = 10`、これは近くの倍数の両方を上回るため、アルゴリズムは完全な解体を正しく選択します。 

建設が解体よりもはるかに安価な場合、たとえより多くのステップが必要であっても、ソリューションは上向きに進みます。 のために`n = 10, m = 6, a = 1, b = 100`、上方調整コストは`2`、下向きは`400`したがって、アルゴリズムは正しく 12 に増やすことを好みます。 

これらのケースでは、最も近い倍数にゼロを加えたもののみをチェックするだけで十分であり、すべてのコスト構成で安定していることが確認されています。
