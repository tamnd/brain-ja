 ## 解決策

 ## 問題の理解

 頂点としてジャンクション、エッジとしてパイプを持つ接続された無向グラフが与えられます。 各エッジには整数の流量値を割り当てる必要があり、その値は方向を指定して解釈できます。正の場合は流量が最初の終点から 2 番目の終点に向かうことを意味し、負の場合はその逆になります。 

すべてのジャンクションには、必要なネットバランス値があります。 値が正の場合、ノードは送信するユニットよりも多くのユニットを受信する必要があります。 負の場合は、受信するユニットよりも多くのユニットを送信する必要があります。 言い換えれば、すべてのノードについて、すべての入射エッジにわたる着信フローから発信フローを差し引いた合計が、指定された値に等しくなければなりません。 

タスクは、すべてのノードのバランスが同時に満たされるように整数フローをエッジに割り当てることができるかどうかを判断し、満たされる場合は 1 つの有効な割り当てを構築することです。 

制約は大きく、最大 200,000 のノードとエッジがあるため、どのソリューションも基本的にグラフのサイズが線形である必要があります。 二次または偶数$O(n \log n)$重い定数を使用するとタイムアウトになる危険性があります。 グラフは接続されていることが保証されているため、複数のコンポーネントを個別に処理する必要がなくなりますが、同時に制約が構造全体にわたってグローバルにバランスをとる必要があることも意味します。 

重要な暗黙の制約は、流れの保存です。 すべてのノードのバランスを合計すると、すべてのエッジが受信として 1 回、送信として 1 回寄与するため、すべてのノードの合計は$s_i$ゼロでなければなりません。 そうでない場合、答えは直ちに不可能です。 

単純なアプローチがグローバル バランスの伝播を考慮せずに貪欲にフローを割り当てようとすると、微妙なエッジ ケースが発生します。 たとえば、ツリー状の構造では、葉から余分なものを上に押し出すことが機能しますが、サイクルを含むグラフでは、スパニング ツリーとサイクル処理を通じて慎重に構造化されていない限り、単純な貪欲なキャンセルによって矛盾が生じる可能性があります。 

別の失敗ケースは、ノードの需要がゼロではないが、以前の貪欲なステップによってすでに「完全に決定」されているエッジを介してのみ接続されている場合に発生します。 これは通常、グローバル保存の不変式を強制するのではなく、エッジを独立して処理するときに発生します。 

## アプローチ

 ブルートフォースの観点は、各エッジ フローを未知の変数として扱い、ノードごとに 1 つの線形方程式を記述することです。 これにより、次のようなシステムが生成されます。$n$との一次方程式$m$変数。 整数に対するガウス消去法を介して直接これを解くことは概念的には機能しますが、その複雑さは次のとおりです。$O(n^3)$最悪の場合、指定された制限では完全に実行不可能になります。 システム構造は純粋にツリー状ではないため、疎な最適化でもあまり役に立ちません。 

重要な観察は、制約がまさに無向接続グラフ上のフロー保存システムであるということです。 これは、有効な解の空間が任意ではないことを意味します。ノード制約を満たすフローの割り当ては、スパニング ツリーを固定し、ツリー内にないエッジを使用してローカル循環を調整することによって構築できます。 

より建設的な観点は、スパニング ツリーをルート化し、問題をツリーを通じて「過剰な需要」を押し出すものとして扱うことです。 各ノードは最初は不均衡を持っています$s_i$。 DFS ツリー上でノードをボトムアップで処理する場合、各サブツリーはその合計の不均衡を計算でき、その不均衡は親エッジを介してプッシュされる必要があります。 これにより、サブツリーの合計を正確にキャンセルするツリーのエッジにフローを割り当てるという問題が軽減されます。 

ただし、元のグラフにはサイクルが含まれている可能性があるため、非ツリー エッジに値を割り当てる必要があります。 重要な洞察は、これらのエッジは任意の循環を運ぶことができ、ツリーベースの構造が元のエッジ セットで有効なままであることを保証するためにのみ使用されるということです。 すべてのノードのバランスを満たすようにツリーのエッジが固定されると、正確さに影響を与えることなく、残りのすべてのエッジをゼロに設定できます。 

これが機能するのは、接続されたグラフ内のすべてのネット不均衡をルーティングするにはスパニング ツリーだけで十分であるためです。

 | ブルートフォースリニアシステム | O(n^3) | O(n^2) | 遅すぎる |
 | DFS スパニング ツリー + バランス伝播 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 スパニング ツリーを構築し、それを使用してバランス値を伝播します。 

1. すべての合計が$s_i$はゼロです。 そうでない場合、すべてのエッジがエンドポイント間で内部的にキャンセルされるため、どのフロー割り当ても保存を満たすことができません。 
2. グラフの隣接リストを作成し、任意のルート (ノード 1 など) を選択します。 
3. DFS を実行して親アレイを構築し、スパニング ツリーを記録します。 トラバース中は、循環を防ぐために親を再訪問しないようにしてください。 これにより、正確に取得することが保証されます$n-1$すべてのノードを接続するツリーのエッジ。 
4. DFS が終了したら、事後順序でサブツリーの不均衡を計算します。 各ノードに対して、それ自体の値と等しい値を定義します。$s_i$さらに子供たちから受け取ったすべての寄付金。 
5.お子様から帰った場合$v$その親に$u$、木のエッジを割り当てます$(u, v)$サブツリーの不均衡に等しいフロー$v$からの指示$v$に$u$。 この選択が行われるのは、そのフローが、ルートとなるサブツリーの正味の過剰または不足を正確にキャンセルするためです。$v$内部的にバランスが取れていることを確認します。 
6. 不均衡が上方に転送されるため、子の寄与分を追加して親の累積不均衡を更新します。 
7. DFS が完了すると、すべてのツリー エッジにフローが割り当てられ、すべてのサブツリーがルートまでバランスが保たれ、合計がゼロになるためルートのバランスが保たれることが保証されます。 
8. すべての非ツリー エッジには、ノード バランスを維持する必要がないため、フロー ゼロを割り当てます。 

### なぜ効果があるのか

 このアルゴリズムは、サブツリーの処理後、唯一残っている不均衡が 1 つのエッジを通して上方に押し上げられるという不変条件を維持します。 各サブツリーはその親への総需要を寄与しており、内部の不均衡が考慮されないままになることはありません。 グラフは接続されているため、すべてのノードの不均衡は最終的にルートにルーティングされ、ルートは総和ゼロを受け取り、一貫性が保証されます。 すべてのエッジはサブツリー フローを 1 つだけ運ぶか、ゼロを運ぶため、すべてのノード方程式が 1 回だけ満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n = int(input())
s = list(map(int, input().split()))
m = int(input())

g = [[] for _ in range(n)]
edges = []

for i in range(m):
    x, y = map(int, input().split())
    x -= 1
    y -= 1
    g[x].append((y, i))
    g[y].append((x, i))
    edges.append((x, y))

if sum(s) != 0:
    print("Impossible")
    sys.exit()

parent = [-1] * n
parent_edge = [-1] * n
vis = [False] * n
ans = [0] * m

def dfs(u):
    vis[u] = True
    for v, eid in g[u]:
        if not vis[v]:
            parent[v] = u
            parent_edge[v] = eid
            dfs(v)

dfs(0)

def solve(u):
    for v, eid in g[u]:
        if parent[v] == u:
            solve(v)
            s[u] += s[v]
            ans[eid] = s[v]

solve(0)

print("Possible")
print("\n".join(map(str, ans)))
```このソリューションでは、まず需要の合計をチェックすることで全体的な実現可能性を検証します。 次に、DFS を使用してスパニング ツリーを構築し、各ノードをその親に接続するエッジを保存します。 2 番目の DFS はサブツリーのバランスを計算し、各ツリー エッジにその子ノードのサブツリーの合計に等しいフローを、親に向かって上向きに割り当てます。 

実装の微妙な点は、ツリー エッジと非ツリー エッジを区別する必要があることです。 この実装では、DFS 親関係を通じて検出されたエッジのみに意味のあるフロー値が割り当てられます。 他のものは暗黙的にゼロのままです。 グラフが深くなり、チェーンに縮退する可能性があるため、再帰制限が増加します。

```ノード 1 から始まる DFS ツリーを構築します。トラバーサルによってエッジ (1-2)、(2-4)、(2-3) に沿って親リンクが構築されるとします。 サブツリーの合計は上向きに伝播します。 

| ノード | イニシャル | 子供の合計 | 最終的なサブツリーの合計 |
 | --- | --- | --- | --- |

 | 2 | -10 | 6 + 1 | -3 |
 | 1 | 3 | -3 | 0 |

 エッジには、子サブツリーの合計に等しいフローが割り当てられます。 

- (2,3) = 6
 - (2,4) = 1
 - (1,2) = -3

 これは、各サブツリーの不均衡が正確に上向きに伝達され、ルートでキャンセルされることを示しています。 

次に、単純な折れ線グラフを考えてみましょう。

```DFS ツリーはグラフそのものです。 サブツリーの合計:

 エッジの割り当て:

 - (2,3) = 1
 - (1,2) = -1

 各ノードのバランス条件が正確に満たされており、最小チェーンのケースでの正しさが確認されます。

 ## 特殊なケース

 重要なエッジ ケースは、すべての要求の合計がゼロになるにもかかわらず、長い伝播チェーンを強制する方法で分散される場合です。 最初のノードが大きな正の値を吸収する必要があり、最後のノードが等しい負の値を持つ折れ線グラフでは、アルゴリズムはルートに到達するまで不均衡を段階的に正しく押し上げます。 各中間ノードは累積値を変更せずに単純に中継するため、局所的な矛盾が防止されます。 

もう 1 つのエッジ ケースは、多くのリーフにゼロ以外の要求があるスター グラフです。 各リーフの不均衡はセンターに直接送信され、集約されます。 センターはバランシングハブとなり、総和はゼロとなるため、まさに自身の需要をキャンセルすることになる。 

最後に、伝播にはスパニング ツリーのみが使用されるため、多くのサイクルを含む密なグラフは依然として正しく動作します。 余分なエッジはゼロ以外の流れを運ぶ必要がないため干渉せず、サイクル循環のあいまいさを回避します。
