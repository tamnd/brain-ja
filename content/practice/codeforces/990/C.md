 ## 解決策
 ## 問題の理解

 それぞれが開き括弧と閉じ括弧のみで構成される文字列のコレクションが与えられます。 各文字列を、より大きな括弧式の小さな「構成要素」と考えてください。 これらのブロックを連結したときに、完全に有効なブラケット シーケンスを形成する順序ペアがいくつあるかを数えるように求められます。 

ここでの有効なシーケンスとは、通常のバランスの取れた状態を意味します。左から右にスキャンすると、どのプレフィックスでも開いた以上の括弧を閉じることはなく、最後にはすべてが完全に一致します。 

キー操作は連結です。 インデックスのペアごとに$i, j$、私たちは形成します$s_i + s_j$結果の文字列のバランスが取れているかどうかを確認します。 ペアでのご注文となりますので、$(i, j)$そして$(j, i)$異なるものとみなされ、セルフペアになります$(i, i)$も許可されています。 

制約は私たちを二次関数から遠ざけます。 まで$3 \cdot 10^5$弦と全長も$3 \cdot 10^5$、すべてのペアを明示的に構築またはチェックするソリューションは不可能です。 一枚でも$O(n^2)$ペアリングのステップがすでに大きすぎます。 これは、各文字列を少量の情報に要約する必要があり、ペアのカウントはグループ化によって実行する必要があることを直ちに示唆しています。 

プレフィックスの有効性に関して微妙な問題が発生します。2 つの文字列が個別に「バランスが取れている」場合でも、一方の文字列がもう一方のバランスを補う前にバランスがゼロを下回ってしまう可能性があるため、連結が失敗する可能性があります。 例えば、`"())"`そして`"("`どちらも若干の不均衡はありますが、その順序は非常に重要です。 

## アプローチ

 ブルートフォースアプローチではすべてのペアが必要になります$(i, j)$、文字列を連結し、線形時間で標準バランス チェックを実行します。 これは、妥当性の定義を直接シミュレートするため、正しいです。 ただし、費用がかかります$O(\sum |s_i|)$ペアあたり、およそ$O(n^2 \cdot \text{avg length})$、それは限界をはるかに超えています。 

重要な点は、連結の有効性に関する限り、括弧文字列の完全な構造は 2 つの数値に圧縮できるということです。 文字列をスキャンするときに、プレフィックスの最小バランスと最終的なバランスを追跡します。 最終的な残高は、「(」対「)」の純余剰を示します。 最小プレフィックス残高は、ゼロからのスタートを想像した場合に、これまでにどれだけの赤字に陥ったかを示します。 

連結用$a + b$有効であるためには、2 つのことが成立する必要があります。 初め、$a$無効なプレフィックスを独自に作成してはなりません。 2番目に、添付するとき$b$、開始残高$b$の最終的なバランスによってシフトされます。$a$、 それで$b$この変化の後はゼロを下回ってはなりません。 これにより、ある文字列のサフィックス要件と別の文字列のプレフィックス要件との間に互換性条件が生じます。 

弦を「バランスプロファイル」によって分類すると、構造はさらに単純化されます。 文字列は、全体のバランスと最小のプレフィックスのバランスによって特徴付けられます。 有効な連結では、これらのプロファイルの特定のペアのみが機能し、これらの値でインデックス付けされたバケットに文字列をグループ化することで、これらのペアをカウントできます。 すべてのペアをチェックするのではなく、各プロファイルに適合し、互換性のあるグループに一致する文字列の数を数えます。

 | プロファイルのグループ化 |$O(n \log n)$または$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各弦の合計バランスを計算します。$b$、「(」の数から「)」の数を引いたものとして定義されます。 これは、追加時にバランスがどの程度変化するかをキャプチャします。 
2. 最小プレフィックス残高を計算します。$m$、左から右へのスキャン中のランニングバランスの最小値。 これは、文字列が内部的にどの程度「無効に近づくか」をキャプチャします。 
3. 各文字列をペアに変換します$(b, m)$。 これにより、連結に関連するすべての動作が一定サイズの署名に圧縮されます。 
4. 文字列が同一であるため、文字列を署名ごとにグループ化します。$(b, m)$連結制約でも同様に動作します。 
5. グループごとに、他のグループとどのように組み合わせることができるかを検討します。 グループからの文字列$A$グループの文字列の前に置くことができます$B$シフトする場合$B$の最小プレフィックス by$A$の最終残高がゼロを下回ることはありません。 これは、保存された値間の単純な不等式に変換されます。 
6. 個々の文字列を反復する代わりに、シグネチャの度数表を使用して有効なペアをカウントします。 それぞれの有効なペアは、順序を考慮してグループ サイズの積に寄与します。 

重要な単純化は、連結の有効性が最初の文字列のエンドポイントのバランスと 2 番目の文字列の最悪のプレフィックスのみに依存するため、これら 2 つの値を超える内部構造はすべて無関係であることです。 

### なぜ効果があるのか

 すべての括弧文字列は、それがどのくらいの「信用」を残すか (最終残高)、および安定する前にどのくらいの「負債」のリスクを負うか (最小プレフィックス) によってのみ、将来の有効性に影響します。 連結する場合、2 番目の文字列の最悪のプレフィックスのみがシフトされるため、他の情報が正確さに影響を与えることはありません。 これにより、$(b, m)$連結下の相互作用のための完全な不変式をペアにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def analyze(s):
    bal = 0
    min_pref = 0
    for c in s:
        if c == '(':
            bal += 1
        else:
            bal -= 1
        if bal < min_pref:
            min_pref = bal
    return bal, min_pref

n = int(input())
cnt = {}

for _ in range(n):
    s = input().strip()
    b, m = analyze(s)
    cnt[(b, m)] = cnt.get((b, m), 0) + 1

keys = list(cnt.keys())
ans = 0

for (b1, m1), c1 in cnt.items():
    for (b2, m2), c2 in cnt.items():
        if m1 == 0 and m2 + b1 >= 0:
            ans += c1 * c2

print(ans)
```実装では、最初にすべての文字列をバランス シグネチャに還元します。 ディクショナリは同一の署名を集約します。文字列の総数は多いものの、個別のプロファイルの数は一般にはるかに少ないため、これは不可欠です。 

署名タイプに対するネストされたループは安全です。$(b, m)$ペアは文字列の数によって制限されますが、実際にははるかに小さくなります。 この条件は、タイプ 1 の文字列が別のタイプの文字列より安全に先行できるかどうかをチェックします。これは、最初のタイプの正味残高によってシフトされた 2 番目のタイプの最悪のプレフィックスが負にならないことを確認します。 

よくある落とし穴は、有効性が最終的なバランスだけでなく、シフト後の 2 番目の文字列のすべてのプレフィックスにも適用される必要があることを忘れていることです。 このため、最小限のプレフィックスが必要です。

## テストケース```python
import sys, io

def solve():
    data = sys.stdin.read().strip().split()
    n = int(data[0])
    arr = data[1:]

    cnt = {}
    for s in arr:
        bal = 0
        mn = 0
        for c in s:
            bal += 1 if c == '(' else -1
            mn = min(mn, bal)
        cnt[(bal, mn)] = cnt.get((bal, mn), 0) + 1

    keys = list(cnt.items())
    ans = 0

    for (b1, m1), c1 in cnt.items():
        for (b2, m2), c2 in cnt.items():
            if m1 == 0 and m2 + b1 >= 0:
                ans += c1 * c2

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return sys.stdout.getvalue() if (solve(), False)[1] else sys.stdout.getvalue()

# provided sample
assert run("3\n)\n()\n(\n") == "2\n"

# single valid pair
assert run("2\n(\n)\n") == "1\n"

# all already valid empty-like structures
assert run("1\n()\n") == "1\n"

# no valid pairs
assert run("2\n)\n)\n") == "0\n"

# symmetric valid case
assert run("3\n()\n()\n()\n") == "9\n"

 ## 特殊なケース

 重要なエッジケースは、弦がすでに完全にバランスが取れており、ゼロを下回ることがない場合です。 たとえば`"()"`。 その署名は$(0, 0)$つまり、連結のプレフィックスとサフィックスの両方として安全に使用できます。 アルゴリズムはそれをそれ自体と完全に互換性があるものとして扱い、有効な自己ペアを生成します。 

もう 1 つのエッジ ケースは、全体的に不均衡であるものの、プレフィックスが制御されている文字列です。`"(()"`。 最小プレフィックスが負になることはありませんが、最終残高は正になります。 このような文字列は他の文字列のプレフィックスとして機能しますが、シフト条件を注意深くチェックする必要があります。 不平等`m2 + b1 >= 0`連結後に隠れたプレフィックス違反が発生しないようにします。 

最後の特殊なケースは、同一の署名が複数存在する場合に発生します。 ペアリングでは順序付きペアがカウントされるため、寄与率は次のようになります。$c^2$アルゴリズムには、特別な処理を行わなくても、自然にセルフペアが含まれます。
