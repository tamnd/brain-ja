 ## 解決策

 ## 問題の理解

 私たちには、それぞれが固定サイズの細菌のコレクションが与えられています。 より大きな細菌がより小さな細菌を消費できるのは、相互作用の瞬間に 2 つの条件が成立する場合に限られます。つまり、細菌は厳密に大きくなければならず、同時に獲物に比べて大きすぎてはなりません。具体的には、そのサイズが獲物のサイズを所定の定数を超えて超えてはなりません。$K$。 食べた後は食べる人だけが残り、大きさは変わりません。 

生き残った各細菌は他の細菌を繰り返し食べる可能性があるため、ペアごとのサイズの違いに依存する制約の下で要素を削除することが事実上許可されます。 課題は、最後にできるだけ少ない細菌が残るような欠失の順序を選択することです。 

入力サイズは最大です$2 \cdot 10^5$これにより、すべてのペアを繰り返しスキャンまたは試行するシミュレーションは直ちに除外されます。 二次関数の何か$n$失敗するだろうし、さらには$O(n \log^2 n)$危険です。 一度ソートしてから配列を線形に処理する戦略を期待する必要があります。 

微妙な難しさは、食事が純粋に「並べ替えられた順序で隣接するものをマージする」わけではないという事実から生じます。 大きな細菌は、たとえそれがはるかに大きかったとしても、任意に小さな細菌を食べることはできません。 上限によってブロックされています$a_i \le a_j + K$。 これにより、境界のある対話ウィンドウが作成され、単純な貪欲な戦略が簡単に誤って処理してしまう可能性があります。 

たとえば、サイズを考慮してください。$[100, 1]$と$K = 10$。 大きな細菌は小さな細菌を食べることができないので、$100 > 1$成り立つが、$100 \le 11$失敗します。 「最大のものが常に小さなものをすべて食べる」という素朴な直感は、単一の生存者を誤って予測するでしょう。 正解は2人の生存者です。 

順方向で連鎖を試みると、別の障害モードが表示されます。 ソート後に隣接する要素を繰り返しマージしようとするとします。 ローカルで有効なマージは、異なる選択順序の下では可能だった将来のマージをブロックする可能性があるため、貪欲な隣接マージは安全ではありません。 

主な課題は、実行できる削除の数を最大化しながら、すべての削除が有効な食べる者と獲物のペアに対応するように削除を構造化することです。 

## アプローチ

 ブルート フォース ビューではプロセスをシミュレートし、有効なペアを繰り返し選択します。$(i, j)$、 消去$j$、移動がなくなるまで続けます。 これは原理的には正しいですが、各ステップでは有効なペアをスキャンする必要があり、$O(n)$削除が発生し、$O(n^2)$またはより悪い行動。 と$n = 2 \cdot 10^5$、これでは遅すぎます。 

重要な観察は、最終的な答えは、細菌をどのようにグループに分割し、各グループを 1 人の生存者によって「一掃」できるかによってのみ決まるということです。 1 つの細菌がグループの生存者として選択された場合、その細菌は、そのサイズに対して特定の範囲内にあるサイズの細菌のみを除去できます。$a_i - K$まで$a_i - 1$。 以下のもの$a_i - K$その生存者は到達できないため、別のグループに属している必要があります。 

これは、アレイをソートし、常に最大の残りの細菌を次のグループの代表として使用しようとすることを示唆しています。 この選択は、潜在的に削除できる要素の数を最大化するため、強力です。 この最大の要素を修正すると、その直下の許容範囲内のすべての細菌を除去でき、残った要素に対してこのプロセスを繰り返します。 

これにより、問題は、現在の最大値に固定された「ウィンドウ」を繰り返し剥がすという問題に変わります。これは、ソートされた配列に対する 1 回のパスで実行できます。

 ## アルゴリズムのチュートリアル

 すべての比較が局所的になるように、最初に細菌のサイズを昇順に並べ替えます。 

1. 配列をソートする$a$昇順で。 これにより、連続したセグメントを使用して有効な食べられる範囲を推論することができます。 
2. 残っている最大の要素から開始します。 この要素は他の要素を食べる可能性が最も高いため、現在のグループの生き残りとして扱います。 
3. この生存菌を答えの最後の 1 つの細菌として数えます。 
4. この最大の要素から左に移動し、少なくとも次のサイズの要素をすべて削除します。$a[i] - K$。 これらは、それより小さいが小さすぎるわけではないため、まさに合法的に食べることができるバクテリアです。 
5. 左側の次の未処理要素からプロセスを続行し、それを新しい生存要素として再度選択し、削除手順を繰り返します。 

各ステップでは、単一の生存者の下でできるだけ多くの要素を削除し、潜在的な食べる人を決して無駄にしないようにします。 

### なぜ効果があるのか

 ソートされた構造により、残っている最大の要素を選択すると、残りのすべての要素が食べられる範囲内にあるか、小さすぎて食べられないことが保証されます。 要素が現在の生存者にとって小さすぎる場合、将来の生存者は値が小さいか等しいだけであるため、配列のこの領域で選択される将来の生存者にとっても小さすぎます。 これにより、そのような要素は強制的に新しいグループを開始します。 

これにより、配列が最小数のグループに分割されます。各グループには、そのグループ内の他のすべての要素を削除できる有効な「最大要素」が含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()
    
    ans = 0
    i = n - 1
    
    while i >= 0:
        ans += 1
        current = a[i]
        
        i -= 1
        while i >= 0 and a[i] >= current - k:
            i -= 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、残っている最大の細菌を繰り返し選択し、その有効な食事間隔内にすべてを消費するというアイデアに直接基づいています。 外側のループはソートされた配列を右から左に移動し、各反復で 1 つの存続グループが定義されるようにします。 

内側のループは重要な部分です。現在の生存者が食べる可能性のあるすべてのバクテリアをスキップします。 条件$a[i] \ge current - K$食べられる範囲の下限を正確にエンコードします。 このしきい値を下回るものは消費できないため、後で処理する必要があります。 

よくある間違いは、複数のポインタを維持して前進しようとすることです。 グループ化は本質的に最小値ではなく最大値に固定されているため、要素が二重にカウントされたり、要素が欠落したりする傾向があります。

 ## 特殊なケース

 重要なエッジケースは、すべての細菌が同じサイズである場合です。 その場合、厳密な不等式が成り立つため、どの細菌も他の細菌を食べることはできません。$a_i > a_j$失敗します。 最後からスキャンするとすべての要素が独自の生き残りとなるため、アルゴリズムはこれを正しく処理します。 内側のループでは削除は発生しません。 

別のエッジケースが発生するのは次の場合です。$K = 0$。 ここで、バクテリアは厳密に小さいものしか食べることができませんが、2 番目の条件により強制的に食べられます。$a_i \le a_j$を同時に保持することはできません。 内部ループの削除が発生しないため、アルゴリズムでは要素ごとに 1 つの生存者が自然に生成されます。 

3 番目のケースには、次のような大きなギャップが含まれます。$[1, 2, 3, 1000]$小さいもので$K$。 大きな要素は独自のグループを形成し、小さな要素は到達範囲外にあるため別のグループを形成します。 ソートされたスキャンにより、以下を通過すると、$a[i] - K$、私たちは消費をやめ、新しいグループを正しく開始します。
