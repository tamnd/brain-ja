 ## 解決策

 ## 問題の理解

 各頂点が整数値を保持するツリーが与えられます。 任意の 2 つの頂点について、それらの間の一意の単純なパスを考慮し、そのパスに沿ったすべての値の最大公約数を取得します。 このタスクは、接続パスを見たときに正確な gcd を生成する頂点ペアの数を、考えられるすべての整数値について数えることです。 

出力について考えるのに役立つ方法は、両方の端点が同じ頂点である場合を含む、順序付けされていない頂点のペアはすべて、パスに沿った値の gcd である 1 つの値のみを提供するということです。 このようなすべてのペアにわたるこれらの gcd 結果の頻度表が必要です。 

頂点の数と値の両方が最大 200,000 であるという制約により、頂点のすべてのペアを明示的に検査するアプローチは直ちに除外されます。 ペアに対する 2 次列挙はすでに時間制限を数桁超えており、各ペアがツリー内のパス クエリを必要とするため、さらに時間がかかります。 

さらに微妙な問題は、gcd 値が非局所的に動作するという事実から生じます。 同様のエンドポイントを持つ 2 つのパスでも、中間ノードに応じて異なる gcd が生成される可能性があるため、パスに沿って gcd がどのように変化するかを注意深く追跡しない限り、ツリーを単純な静的構造に圧縮することはできません。 

よくある落とし穴は、ルートを修正して、ルートからノードへのパスのみの gcd を計算しようとすることです。 これは、LCA 構造によるオーバーラップキャンセルを明示的に考慮しない限り、2 つのノード間の一般パスの gcd が個々のルート パスによって決定されないため、失敗します。 

もう 1 つの障害モードは、パスに沿った gcd 値がツリーのセグメント間で独立して動作すると仮定することです。 たとえば、12-18-6 のようなチェーンでは、エンドポイントの gcd は 6 ですが、サブパスの中間的な組み合わせにより、単純なローカル集約では見逃される異なる gcd 分布が生成されます。 

## アプローチ

 ブルート フォース ソリューションでは、頂点のすべてのペアを反復処理し、ツリーをたどるか、パスを明示的に計算し、途中で gcd を計算します。 LCA 技術を使用して各パス クエリが対数時間に最適化されたとしても、依然としておよそ n² のペアに直面することになり、最悪のケースでは約 4×10¹⁰ の演算が必要になりますが、これは実行不可能です。 

重要な構造的洞察は、パスに沿った gcd 値が恣意的に変化しないことです。 固定ノードを取得し、そこから開始してそのサブツリーに下降するすべてのパスを確認すると、表示される個別の gcd 値のセットは非常に小さくなります。 ノードを 1 つ追加してパスを拡張すると、gcd は変わらないか約数まで減少しますが、1 に達するまでに減少できるのは対数倍だけです。 

これは、各ノードについて、そのノードから始まりそのサブツリーに至るパスのすべての gcd 値のコンパクトな概要を維持する、ツリーに対する動的プログラミング戦略を示唆しています。 子を結合するときは、これらのサマリーをマージし、各 gcd を生成するクロスサブツリー ペアの数を数えます。 

重要なメカニズムは、各ノードがその子からマップを集約するポストオーダー トラバーサルです。 各マップには、そのノードから始まるパスの gcd 値の頻度が格納されます。 現在のノードを介して 2 つの子マップを結合する場合、異なるサブツリー内のノードのペアは現在のノードを通過するパスを形成するため、gcd 状態のすべてのペア間の寄与を計算します。 

この効率は、各ノードのマップが小さいままであり、マージが gcd 圧縮を通じて暗黙的に大規模から小までの動作を使用して行われるという事実から来ています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log A) | O(n) | 遅すぎる |
 | 最適 | O(n log² A) | O(n log A) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべてのサブツリーが明確に定義されるように、任意のノード (たとえばノード 1) でツリーをルートします。 これにより、結果をボトムアップで組み合わせることができます。 
2. 各ノードに対して、このノードから下に向かって特定の gcd を持つパスがいくつあるかを格納するディクショナリを定義します。 最初は、各ノードだけが、それ自体の値に等しい gcd を持つ 1 つのパスに寄与します。 これは長さ 1 のパスに対応します。 
3. 深さ優先検索を実行します。 子から返されるときに、その gcd 分布マップを受け取ります。 現在のノードにマージする前に、gcd を現在のノードの値で取得することにより、その子マップ内のすべての gcd 値を更新します。 これにより、親ノードが含まれることにより、すべてのパスが上向きに正しく拡張されます。 
4. 現在のノードの実行中の集約マップを維持します。 新しい子マップを処理する場合、現在の集約からの 1 つの gcd 状態と子からの 1 つで構成されるすべてのペアは、エンドポイントが異なるサブツリーにあるパスを表します。 そのパスの gcd は、保存されている 2 つの gcd 値の gcd です。 
5. このような gcd 値のペアごとに、その寄与を結果の gcd によってインデックス付けされたグローバル応答配列に累積します。 これは、さまざまな子サブツリー内のエンドポイントを持つ現在のノードを通過するすべてのパスを考慮します。 
6. すべての子を処理した後、現在のノード自身の単一ノードのコントリビューションをそのマップに挿入し、親に返します。 

### なぜ効果があるのか

 すべてのノードで、ツリー上の最高点がそのノードであるすべてのパスの完全な説明を維持します。 ツリー内のすべてのパスには固有の最高 LCA があり、マージ プロセスにより、ノードのすべてのペアがその LCA で正確にカウントされるようになります。 各マップ エントリに格納されている gcd は常にノードから子孫までの完全なパスを反映しているため、2 つのエントリを結合すると、それらの子孫間の完全なパスの gcd が正しく再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

from collections import defaultdict

n = int(input())
a = list(map(int, input().split()))

g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

ans = defaultdict(int)

def dfs(u, p):
    cur = defaultdict(int)
    cur[a[u]] = 1

    for v in g[u]:
        if v == p:
            continue
        child = dfs(v, u)

        new_child = defaultdict(int)
        for gv, cnt in child.items():
            ng = gcd(gv, a[u])
            new_child[ng] += cnt

        for g1, c1 in cur.items():
            for g2, c2 in new_child.items():
                ans[math_gcd(g1, g2)] += c1 * c2

        for k, vcnt in new_child.items():
            cur[k] += vcnt

    return cur

import math
def math_gcd(x, y):
    return math.gcd(x, y)

dfs(0, -1)

# add single-node paths already included in dfs, but they need to be counted as pairs (x,x)
for i in range(n):
    ans[a[i]] += 1

out = []
for k in sorted(ans):
    if 1 <= k <= 200000 and ans[k] > 0:
        out.append(f"{k} {ans[k]}")
print("\n".join(out))
```コア構造は、サブツリーごとの gcd 状態の圧縮辞書を返す DFS です。 子の寄与を上方に拡張するたびに、親の値を使用して gcds を再計算し、保存されたすべての状態が常に現在のノードから始まるパスを表すようにします。 

ダブルループオーバー`cur`そして`new_child`サブツリー間のパスがカウントされる場所です。 これは、gcd 圧縮により両方の辞書が実際には小さいままであり、各マージがツリーのエッジに沿ってのみ発生し、総作業量が対数係数まで線形に保たれるため、安全です。 

最後のループでは、各頂点がそれ自体と有効なペアを形成するため、単一ノードの寄与が追加されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math
    from collections import defaultdict

    n = int(input())
    a = list(map(int, input().split()))
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1; v -= 1
        g[u].append(v)
        g[v].append(u)

    ans = defaultdict(int)

    def dfs(u, p):
        cur = defaultdict(int)
        cur[a[u]] = 1
        for v in g[u]:
            if v == p:
                continue
            child = dfs(v, u)
            new_child = defaultdict(int)
            for gv, cnt in child.items():
                new_child[math.gcd(gv, a[u])] += cnt
            for g1, c1 in cur.items():
                for g2, c2 in new_child.items():
                    ans[math.gcd(g1, g2)] += c1 * c2
            for k, vcnt in new_child.items():
                cur[k] += vcnt
        return cur

    dfs(0, -1)
    for i in range(n):
        ans[a[i]] += 1

    out = []
    for k in sorted(ans):
        if ans[k] > 0:
            out.append(f"{k} {ans[k]}")
    return "\n".join(out)

 ## 特殊なケース

 すべてのノードが同じ値を持つ星型ツリーの場合、すべてのペアが同じ gcd を提供します。 このアルゴリズムは、各子で同一の gcd マップを作成し、ペアの組み合わせ数と一致するルートですべての交差組み合わせをカウントすることでこれを処理します。 

線形チェーンの場合、各マージは順番に発生し、サブツリー間の爆発は発生しません。 各ステップは単に gcd 状態を上方に拡張するだけであり、アルゴリズムが縮退した木の高さを正しく処理していることを示しています。 

値がペアごとに互いに素であるツリーの場合、ほとんどの gcd マージはすぐに 1 に崩壊します。マップは積極的に縮小しますが、すべての交差結合が正しい LCA で gcd 1 に減少するため、アルゴリズムは引き続きすべてのペアを正しくカウントします。
