 ## 問題の理解

 私たちは持っています`N`提出された解決策。 解決`i`最悪の場合の実行時間を測定しました`T[i]`。 クエリごとに、文字列`S`すべての解決策を悪いものとして分類します (`0`）、 良い （`1`)、または不確かな (`?`）。 

最小の正の整数の時間制限が必要です`X`実際に制限を課すすべての分類を満たしていること。 悪い解決策は少なくとも制限の 2 倍を取る必要があるため、すべてのポジションに対して`S[i] = '0'`私たちは必要です`T[i] >= 2X`。 

適切なソリューションは制限の半分以内に収まる必要があるため、すべてのポジションで`S[i] = '1'`私たちは必要です`T[i] <= X / 2`、

 これは以下と同等です`X >= 2T[i]`。 

疑問符には何の条件も課されません。 正の整数がない場合`X`これらすべての不等式を満たせば、答えは次のようになります。`-1`。 

クエリごとに、入力により次の長さの分類文字列が 1 つ与えられます。`N`。 出力は 1 つの整数、最小有効時間制限、または`-1`分類が互いに矛盾する場合。 

ここ`N`そして`Q`せいぜい両方です`1000`したがって、すべてのクエリに対してすべてのソリューションをチェックする必要があるのは、最大でも`10^6`文字時間の比較。 これは、単純な整数演算で実装された場合、Python で 1 秒の制限内に余裕で収まります。 高度なデータ構造やサブリニア クエリ アルゴリズムは必要ありません。 各ソリューションの最大実行時間はわずかです。`10^6`したがって、通常の Python 整数でも十分です。 

主なエッジ ケースは、1 種類の制約付きソリューションのみを含む分類から得られます。 考慮する```
1
10
1
0
```悪い解決策は満足する必要があります`10 >= 2X`、 それで`X <= 5`。 最小の正の値は`1`、そして答えは`1`。 下限と上限の両方が存在すると仮定する不用意な実装は、このケースを誤って拒否する可能性があります。 

ここで考えてみましょう```

```優れたソリューションには次のことが必要です`X >= 20`、したがって、答えは次のとおりです`20`。 ここには上限はありません。 上限をゼロに初期化する実装では、答えが存在しないと誤って結論付けられてしまいます。 

もう 1 つの重要なケースは、境界における平等です。```
2
10 20
1
01
```悪い解決策には時間があります`10`、与える`X <= 5`良い解決策には時間があるうちに`20`、与える`X >= 40`。 これらの間隔は交わらないので、答えは次のようになります。`-1`。 不等式は包括的であるため、次のような場合`T = 10`そして`X = 5`置き換える間、悪い解決策には有効です`>=`による`>`off-by-one エラーが発生します。 

最後に、疑問符を使用するとすべての制限を削除できます。```

## アプローチ

 直接的なアプローチは、1 つのクエリを独立して処理することです。 あらゆるポジションについて、その性格を調べてください。 もしそうなら`0`、不等式`T[i] >= 2X`上限を与える`X <= floor(T[i] / 2)`。 もしそうなら`1`、不等式`T[i] <= X / 2`下限を与える`X >= 2T[i]`。 最も強い下限と最も強い上限を維持します。 文字列全体をスキャンした後、結果の間隔内の最小の正の整数が答えになります。 

このブルートフォース記述は、指定された制約に対してすでに最適です。 考えられるすべての肯定的な方法を試すことで、さらに文字通りの総当りアルゴリズムを作成することもできます。`X`そしてすべてをチェックする`N`ソリューション。 以来`T[i] <= 10^6`、おおよそを超える値を試す理由はありません`2 * 10^6`、ただし、最悪の場合でも、これにはまだ必要になります`10^9`全体をチェックします`1000`クエリが遅すぎます。 

重要な観察は、条件が恣意的ではないということです。 優れたソリューションはすべて、次のことだけを述べています。`X`十分な大きさでなければならず、悪い解決策はすべて次のことだけを示しています。`X`十分に小さい必要があります。 したがって、クエリ全体は、最大の下限と最小の上限という 2 つの数値だけで表されます。 

個々の制約は簡単に検証できるため、総当り攻撃は機能しますが、次の候補値を検索すると失敗します。`X`。 すべての制約を 1 つの下限と 1 つの上限に圧縮できるという観察により、クエリの 1 回のスキャンで答えを決定できます。 以来`NQ <= 10^6`、この直接スキャンは簡単に十分に高速です。

 | 境界交差点 |`O(QN)`|`O(1)`入力以外にも | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在のクエリについて、下限を初期化します。`L`に`1`。 これは、制限時間は正の整数でなければならないという要件を表します。 上限を初期化する`R`無限大まで、最初はそれを妨げる制限がないため、`X`大きいことから。 
2. すべてスキャンする`N`クエリ文字列の位置と実行時間。 
3. 現在のキャラクターが`1`、解は次の条件を満たす必要があります。`T[i] <= X / 2`。 2 を掛けると次のようになります`X >= 2T[i]`ので、更新します`L`に`max(L, 2T[i])`。 すべての優れたソリューションは同時に満たされる必要があるため、最大値を維持します。 
4. 現在のキャラクターが`0`、条件は`T[i] >= 2X`、与える`X <= T[i] / 2`。 以来`X`は整数、つまり`X <= floor(T[i] / 2)`。 アップデート`R`に`min(R, T[i] // 2)`なぜなら、すべての悪い解決策は上限に影響を与えるからです。 
5. すべて無視する`?`。 このような解決策は時間制限を制限しません。 
6. クエリをスキャンした後、比較します。`L`そして`R`。 もし`L <= R`、有効な整数値は正確に次の整数です。`L`を通して`R`したがって、有効な最小値は次のようになります。`L`。 もし`L > R`、必要な間隔は空であり、答えは次のようになります。`-1`。 

### なぜ効果があるのか

 クエリのプレフィックスを処理した後、`L`の最小値です`X`これまでに見られたすべての適切な解の制約を満たしながら、`R`は、これまでに確認されたすべての不良解制約を満たす最大値です。 優れたソリューションは増加するだけです`L`、そして悪い解決策は減少するだけです`R`したがって、スキャンが完了した後の間隔は`[L, R]`すべての制約を満たす整数値が正確に含まれます。 間隔が空でない場合は、`L`より小さい正の整数はすべて、少なくとも 1 つの適切な解の制約に違反するため、これは最適です。 間隔が空の場合、すべての制約を満たす値はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    n = int(input())
    t = list(map(int, input().split()))

    q = int(input())
    answers = []

    for _ in range(q):
        s = input().strip()

        lower = 1
        upper = INF

        for ti, c in zip(t, s):
            if c == '1':
                lower = max(lower, 2 * ti)
            elif c == '0':
                upper = min(upper, ti // 2)

        if lower <= upper:
            answers.append(str(lower))
        else:
            answers.append("-1")

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```最初の 2 つの入力行は、ソリューションの数とその実行時間を示します。 実行時間はすべてのクエリで共有されるため、一度保存されます。 

クエリごとに、`lower`から始まります`1`時間制限は正の値でなければならないため、ゼロではありません。`upper`クエリには悪い解決策がまったく含まれていない可能性があるため、十分に大きな値から開始します。 

良い解決策としては、`2 * ti`は正確な下限です。 悪い解決策としては、`ti // 2`正確な整数の上限です。 フロア分割が必要な理由は、`X`それ自体は整数でなければなりません。 たとえば、次の場合`ti = 7`、条件`7 >= 2X`許可します`X <= 3`、 ない`X <= 3.5`。 

コードは境界のみを更新します`0`そして`1`。 疑問符は、どちらかのタイプを割り当てると、クエリで実際には必要のない制約が導入されるため、意図的に無視されます。 

Python にはオーバーフローの問題はなく、固定幅言語であっても、ここでの最大境界は`2 * 10^6`。 の`zip`ループは正確に処理します`N`実行時配列とクエリ文字列の対応する位置。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(QN)`| すべてのクエリはそのクエリをスキャンします`N`文字を 1 回だけ |
 | スペース |`O(N + Q)`|`N`実行時間と収集された出力文字列が保存されます。 

と`N <= 1000`そして`Q <= 1000`、せいぜいあります`10^6`内側のループの繰り返し。 各反復では文字比較と一定数の整数演算のみが実行されるため、ソリューションは 1 秒の制限時間に問題なく適合します。 メモリ使用量も、256 MB の制限に比べてわずかです。
