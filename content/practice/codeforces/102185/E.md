 ## 解決策
 ## 問題の理解

 私たちは (N) 個の完全な単語の辞書を持っています。 次に、テキストから (M) 個の単語を受け取ります。 テキスト単語は、辞書の 1 つの単語から文字を削除することによって取得でき、他の辞書の単語にその単語が部分列として含まれていない場合、略語とみなされます。 辞書の単語が 1 つだけ含まれている場合は、テキストの単語をその辞書の単語で置き換えます。 辞書の単語が 0 つまたは少なくとも 2 つ含まれている場合、テキストの単語は変更されません。 

したがって、中心となる操作はサブシーケンス テストです。 例えば、`sti`の続きです`strtoint`、選択できるので`s`、 それから`t`、 それから`i`。 一方で、`aa`両方の続きです`aba`そして`ababa`、曖昧なので置き換えてはいけません。 

辞書の単語は (500) 個しかありませんが、合計の長さは (2\cdot10^6) に達することがあります。 テキストには最大 (2000) 語が含まれており、各テキスト単語の長さは最大 (10) です。 短いクエリの長​​さが重要な制約です。 これは、辞書の単語内で要求された文字の次の出現をすぐに見つけることができれば、1 つのテキスト単語をチェックするのに必要な操作はほんの数回だけであることを意味します。 

直接スキャンは高価すぎます。 辞書の全長が (2\cdot10^6) の場合、1 つのテキスト単語をすべての辞書単語に対してテストすると、すべての (2\cdot10^6) 個の辞書文字を検査できます。 (2000) 個の個別のテキスト ワードを使用すると、(4\cdot10^9) 個の文字チェックに達し、1.5 秒の制限をはるかに超えます。 

一見合理的な実装が失敗する可能性があるエッジケースがいくつかあります。 1つ目は曖昧さです。 考慮する```
2
aba
ababa
1
aa
```どちらの辞書の単語にも含まれています`aa`サブシーケンスとして出力されるため、正しい出力は次のようになります。```
aa
```最初に一致した辞書の単語で停止する不注意な実装では、誤って出力されてしまいます。`aba`。 

2 番目のケースは、辞書の単語とまったく同じです。 考慮する```
1
abc
1
abc
```正しい出力は次のとおりです```
abc
```この定義ではゼロ文字の削除が許可されているため、辞書の単語自体がその辞書エントリの部分列になります。 少なくとも 1 つの削除文字を必要とする実装では、これが間違ってしまいます。 

3 番目のケースは、略語が辞書単語内で連続しない位置に出現する可能性があることです。 例えば、```
1
strtoint
1
sti
```生成する```
strtoint
```登場人物たち`s`、`t`、 そして`i`連続した部分文字列を形成する必要はありません。 部分文字列のみを検索すると、誤って終了してしまう`sti`変わらない。 

最後の微妙なケースは、辞書エントリの重複です。 のために```
2
abc
abc
1
abc
```答えは```
abc
```これは、それらのエントリの内容が等しいにもかかわらず、テキスト単語が 2 つの異なる辞書エントリに含まれているためです。 単に個別の辞書文字列ではなく、辞書の位置をカウントする必要があります。 

## アプローチ

 ブルートフォースの解決策は簡単です。 すべてのテキスト単語について、すべての辞書単語をスキャンし、標準の 2 ポインター サブシーケンス チェックを実行します。 このチェックでは、短いテキストの単語へのポインタを保持し、現在の辞書の文字が次に必要な文字と一致するたびにポインタを進めます。 すべての文字が見つかると、辞書の単語が一致します。 

これは正しいです。貪欲なサブシーケンス チェックでは、必要なすべての文字に対して常に最も早い位置が検索されるからです。 欲張りプロシージャが次の文字を見つけられない場合、その後の選択によってクエリが適合する可能性はありません。 

問題は繰り返し作業の量です。 辞書の合計長が (D) であるとします。 1 つのクエリでは (O(D)) 文字検査が必要になる場合があります。 (U) 個の個別のテキスト単語 (U\le2000) の場合、最悪のケースは (O(UD)=O(4\cdot10^9)) の文字チェックです。 個々のクエリの長​​さが最大 ​​(10) であるという事実は、辞書の単語が合計で数百万文字になる可能性があるため、ブルート フォース スキャンには役に立ちません。 

有益な観察は、クエリが短いにもかかわらず、同じ辞書の単語が何度もクエリされるということです。 クエリごとに辞書の単語を最初からスキャンするのではなく、その単語内の各文字が出現する場所を前処理します。 

1 つの辞書単語について、各文字の位置のソートされたリストを保存します。 次に出現する文字を検索するには`c`ポジションの後`p`、その位置リストを二分探索します。 次の位置が存在する場合は、そこからサブシーケンスのテストを続行します。 クエリには最大 10 文字が含まれるため、1 つの辞書単語には最大 10 個の二分検索が必要になります。 

これにより、繰り返し部分が辞書単語全体のスキャンから最大 10 個の対数検索を実行するように変更されます。 前処理は辞書全体の長さに対して線形です。 

もう 1 つ便利な最適化があります。 テキストには同じ単語が何度も含まれている可能性があり、その答えは常に同じです。 まず個別のテキスト単語を収集し、それぞれを 1 回解決してから、結果を再利用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(UD)) | (O(D)) | 遅すぎる |
 | 最適 | (O(D+UNK\log L)) | (O(D+UN)) | 承認済み |

 ここで、(D) は辞書の合計長、(U\le2000) は個別のテキスト単語の数、(N\le500) は辞書のサイズ、(K\le10) は最大クエリ長、(L) は辞書の最大単語長です。 

## アルゴリズムのチュートリアル

 1. 辞書の単語をすべて読み、各単語の各文字の位置リストを作成します。 辞書の単語の場合、次のようなものがあります。`abac`、ポジションリストには以下が含まれます`a: [0, 2]`、`b: [1]`、 そして`c: [3]`。 単語は左から右にスキャンされるため、リストは自然にソートされます。 
2. テキストを読み、その中の明確な単語のみを書き留めます。 同じテキスト単語が出現するたびに、一致する辞書エントリのセットがまったく同じになるため、繰り返し解くのは時間を無駄にするだけです。 
3. 1 つのクエリと 1 つの辞書単語の場合、現在位置を辞書単語の先頭より前に設定します。 クエリ文字を左から右に処理します。 
4. 現在のクエリ文字について、その位置リストをバイナリ検索して、現在の位置より厳密に大きい最初の位置を探します。 これはまさに、サブシーケンスで使用できる次の文字です。 
5. そのような位置が存在しない場合、クエリはこの辞書単語の部分列ではありません。 この辞書の単語を調べるのをすぐにやめてください。 
6. すべてのクエリ文字が見つかった場合、辞書の単語は一致します。 一致する辞書項目の数を増やし、対応する単語を覚えてください。 
7. 一致するものが 2 つ見つかったら停止します。 クエリがあいまいであり、変更しない必要があるため、2 番目の一致の正確な ID は重要ではなくなりました。 
8. 辞書の単語が 1 つだけ一致した場合は、クエリをその単語で置き換えます。 0 個または少なくとも 2 個が一致した場合は、元のクエリを保持します。 後で同じテキスト単語が表示されたときに再利用できるように、この結果を保存します。 
9. 変換されたテキストを元の順序で印刷します。 置換保証では合計出力サイズが (2\cdot10^6) によって制限されるため、出力を文字列のリストとして構築しても安全です。 

これが機能する理由: すべての辞書単語について、各クエリ文字に対して選択される位置は、以前に選択された位置の次に可能な限り早く出現します。 前の出現を選択しても、残りのクエリの一致が難しくなることはありません。そのため、クエリがサブシーケンスである場合、貪欲なプロシージャは正確に成功します。 すべての辞書エントリをテストするため、一致数はクエリを含む辞書エントリの数と正確に一致します。 したがって、クエリはカウントが 1 のときに正確に置き換えられます。 

## Python ソリューション```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

def solve():
    n = int(input())

    dictionary = []
    positions = []

    for _ in range(n):
        word = input().strip()
        dictionary.append(word)

        pos = [[] for _ in range(26)]
        for i, ch in enumerate(word):
            pos[ord(ch) - 97].append(i)
        positions.append(pos)

    m = int(input())
    text = [input().strip() for _ in range(m)]

    cache = {}

    for query in set(text):
        matches = 0
        replacement = None

        for idx in range(n):
            pos = positions[idx]
            current = -1
            ok = True

            for ch in query:
                arr = pos[ord(ch) - 97]
                j = bisect_right(arr, current)

                if j == len(arr):
                    ok = False
                    break

                current = arr[j]

            if ok:
                matches += 1
                replacement = dictionary[idx]

                if matches == 2:
                    break

        if matches == 1:
            cache[query] = replacement
        else:
            cache[query] = query

    sys.stdout.write("\n".join(cache[word] for word in text))

if __name__ == "__main__":
    solve()
```最初のループは辞書を読み取り、位置インデックスを構築します。 位置はその単語内でのみ意味があるため、インデックスは辞書の単語ごとに個別に保存されます。 

クエリ中に、`current`すでに選択されている最後の文字の位置です。`bisect_right(arr, current)`厳密にその後の最初の出現を返します。 辞書の位置を 2 つの異なるクエリ文字に対して 2 回使用することはできないため、厳密に after が必要です。 

コードは 2 回目の一致後に停止します。 出力は一致の数が 0、1、または少なくとも 2 であるかどうかのみに依存するため、これは安全です。 

の`cache`辞書は繰り返されるテキスト単語を処理します。 表現`cache[word]`出力時には、個別のクエリが任意の設定順序で処理された場合でも、元のテキストの順序が保持されます。 

Python には整数オーバーフローの問題はなく、最大の出力はステートメントによって制限されます。 メイン メモリのコストは保存された出現位置であり、その総数は正確に辞書の合計長になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(D+UNK\log L)) | 建設位置コスト (O(D))。 (U) 個の個別のクエリはそれぞれ、単語ごとに最大 (N) 個の単語と最大 (K\le10) 文字をチェックします。 
| スペース | (O(D+UN+M)) | 文字位置には (D) 個のエントリが含まれますが、クエリ キャッシュと入力テキストには最大で (O(UN+M)) 個の追加参照が含まれます。
