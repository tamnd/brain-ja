 ## 解決策
 ## 問題の理解

 K 色ごとに正確に N 個の鉛直を含む行があるため、全長は N の K 倍になります。唯一許可される操作は、行から既存の鉛直を 1 つ取り出し、それを一番左または一番右に挿入することです。 目標は、すべての色が 1 つの連続したブロックを占めるようにすることです。 これらのカラー ブロックの順序は任意です。 

重要な問題は、操作で任意のスワップが許可されていないことです。 私たちが決して動かさないすべての鉛管は、他のすべての動かない鉛管との相対的な秩序を保ちます。 移動した鉛管は最終的に両端に配置され、手つかずの鉛管は最終列の中央部分を形成します。 

答えは、移動する鉛直バスの最小数です。 同様に、私たちはその場所に留まることができる梅バスの数を最大化したいと考えています。 

制約により N,K は最大 1000 になりますが、配列自体には 1,000,000 個の要素を含めることができます。 O(NK 倍 K) 回の作業を実行するアルゴリズムでも、最悪の場合、すでに 10^9 回程度の演算が必要となり、使用できなくなります。 基本的に配列の線形作業に加えて、色数の最大でも二次作業が必要です。 O(NK + K^2) は十分小さいので、メモリ制限により元の配列を保存することもできます。 

実装を欺く可能性のある境界ケースがいくつかあります。 

N=1 および K=1 の場合、```
1 1
1
```答えは 0 です。色は 1 つだけで、その 1 つの鉛直がすでに有効なグループを形成しています。 2 つの異なるエンドポイントの色が存在すると想定する実装では、移動が誤ってカウントされる可能性があります。 

N=2 および K=2 の場合、```
2 2
1 2 1 2
```答えは 2 です。完全な色を 1 つだけ保持すると、2 つの鉛はそのまま残るため、2 つの移動で十分です。 すでに連続しているカラー ブロックのみを考慮する不注意な解決策では、この可能性を見逃してしまう可能性があります。 

より微妙なケースは、```
3 2
1 1 2 2 1 2
```その答えは 2 です。最初の 2 つの 1 と最初の 2 つの 2 はすでにグループ化されており、残りの 1 と 2 を適切な端に移動すると、両方のグループが完成します。 一部の色を完全に保持する必要があると主張するソリューションでは、この種の最適化を逃す可能性があります。これは、この場合、最良の手つかずの中間が 2 つの部分的なエンドポイント カラーで構成されている可能性があるためです。 

## アプローチ

 直接的なブルートフォースでは、どの鉛直バスを移動し、どれを残すかを選択し、残りの鉛直バスが有効な最終配置の中央を形成できるかどうかをチェックします。 これは正しいです。なぜなら、操作のすべての正当なシーケンスは、変更されていない要素に関する限り、移動された要素のセットによって完全に決定されるからです。 ただし、2^(NK) 個の可能なサブセットが存在します。 NK の規模が 100 万にも達すると、すべての候補者を書き出すことさえ不可能です。 K のカラー ブロックの順列を列挙することも絶望的です。 K=1000 ではすでに巨大です。 

有益な観察は、動かされていない鉛管を観察することです。 それらの相対的な順序は決して変更されず、移動されたすべての要素は最終的にそれらの外側に配置されます。 したがって、手付かずの梅は、各色が最大 1 つのランを形成する 1 つの中間シーケンスとして最終行に表示されなければなりません。 

その手つかずのシーケンスの内部のどこかに色が現れたとします。 N 個の鉛管のうち 1 つが移動されている場合、その移動された鉛管は行全体の両端のいずれかに配置される必要があります。 この内部グループの次に戻ることはできませんでした。 したがって、内部カラーは、その N 個の出現がすべて変更されていない必要があります。 

部分的なものにできるのは、変更されていないシーケンスの最初と最後のカラー グループのみです。 一部のオカレンスを対応する外側の端に移動させることができます。 したがって、すべての最適解は次の構造になります。```
partial left color
complete color
complete color
...
complete color
partial right color
```2 つの部分的な色が存在しない場合もあります。 完全な色がまったくない場合、未処理のシーケンスは、左側の部分色とそれに続く右側の部分色で構成されます。 

ここで、完全に保持される色 c を考えます。 first[c] と last[c] を元の配列の最初と最後の位置とします。 別の色 d も c の前に完全に保持されている場合、d の出現はすべて c の出現よりも前になければなりません。 正確な条件は```
last[d] < first[c].
```したがって、完全な色は、重複しない間隔のチェーン [first[c], last[c]] を形成します。 すべての完全な色はちょうど N 個の未処理の鉛管に寄与するため、問題はこれらの色間隔にわたる動的計画法の問題になります。 

もう 1 つ詳細があります。 c が最初の完全な色の場合、first[c] の前に別の色のいくつかの出現をさらに保持することができます。 そのような最良の色は、単にその接頭語で最も頻繁に出現する色です。 同様に、最後の完全な色の後、最も頻繁に使用される色をサフィックスに保持することができます。 

これらのエンドポイントの色の数だけでなく、その正体を覚えておく必要があります。 同じ色を両側で使用することはできません。その場合、その色が保持されると 2 つの別々のグループが形成されるためです。 この対立を解決するには、それぞれの陣営に 2 人の最良の候補者を維持するだけで十分です。 

全色が揃っていない場合は別扱いとなります。 2 つの位置の間のカットごとに、左側の接頭辞の色と右側の接尾辞の色で構成される最適な 2 つの異なる色が見つかります。 順方向スキャンでは、最も頻繁に使用される 2 つのプレフィックス カラーを維持できます。 逆スキャンでは、最も頻繁に使用される 2 つの接尾辞の色を維持できます。 プレフィックス情報は、逆スキャンが同じカットに到達するときに必要になるため、コンパクトな配列に格納されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(NK)・NK) | O(NK) | 遅すぎる |
 | 最適 | O(NK + K²) | O(NK) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取って記録する`first[c]`そして`last[c]`あらゆる色に。 これら 2 つの位置は、完全に手付かずの色が発生する可能性がある場所を正確に示しています。 
2. プレフィックス内の各色の出現数を維持しながら、配列を左から右にスキャンします。 最初に出現する色 c に到達したら、最も頻繁に出現する 2 つの色を前の位置に保存します。`first[c]`。 これらは、完全なブロック c の左側の部分色として機能できる唯一の候補です。 
3. 同じ順方向スキャン中に、可能なすべてのカットの後に最も頻繁に使用される 2 つの色を保存します。 唯一禁止されている状況は両側で同じ色を選択することであるため、最良の候補 2 つだけが必要です。 
4. アレイを右から左にスキャンします。 色 c の最後の出現を処理する前に、現在のカウントは後のサフィックスを正確に表します。`last[c]`。 その 2 つの最良の色を、c で終わるチェーンの可能な右端点の色として保存します。 
5. すべての色を最初に出現する順に並べ替えます。 各色 c について、c で終わる完全な色のチェーンを表す DP 状態を作成します。 初期状態は、c 自体と、前の 2 つの最良の左エンドポイント候補の 1 つで構成されます。`first[c]`。 
6. d で終わるチェーンを色 c で延長するには、次のようにします。`last[d] < first[c]`。 これは、d の出現はすべて c の出現の前にあるため、両方の色が完全に影響を受けないままであることを意味します。 c を追加すると、未処理の鉛直の数がちょうど N 個増加します。 
7. すべての終了色 c について、異なる左端点の色を持つ 2 つの最良の DP 状態を保持します。 右のエンドポイントが選択された場合、禁止されるのは左の 1 色だけであるため、2 つの状態で十分です。 
8. c で終わるすべての DP 状態を、次の 2 つの最良のサフィックス候補と結合します。`last[c]`。 両方のエンドポイントの色が同じ非ゼロ色の場合にのみ、組み合わせを拒否します。 結果として得られる値は、少なくとも 1 つの完全な色を含むソリューションの未処理の鉛直の最大数です。 
9. 保存されているプレフィックス候補と動的に維持されているサフィックス候補を使用して、すべてのカットを個別に処理します。 これは、未処理のシーケンス全体が 2 つの部分的なエンドポイント カラーで構成される、完全な色を含まないソリューションを処理します。 
10. しましょう`best`両方の場合における未処理の鉛直の最大数になります。 必要な答えは、`N*K - best`なぜなら、手付かずとしてカウントされないすべての鉛直バスは、正確に 1 回移動する必要があるからです。 

### なぜ効果があるのか

 操作の最適なシーケンスを検討し、移動されなかった鉛管のみに注目します。 それらの相対的な順序は変更されないため、最終的な配置では 1 つの中央のシーケンスとして表示されます。 そのシーケンス内に現れるすべての色には、その元の N 個の出現がすべて含まれている必要があります。そうでない場合、その色の移動された出現は、その独自のグループに戻るために無関係なグループを横切る必要があります。 部分的になることができるのは、中央のシーケンスの最初と最後のグループだけです。 

したがって、すべての最適解は、両側に最大 1 つの部分色を含む完全な色のチェーン、または完全な色を持たない 2 つの部分的な色のいずれかによって表されます。 間隔条件`last[d] < first[c]`2 つの色が両方とも完成し、その順序で現れる場合を正確に特徴づけます。 DP はこの条件を満たすすべての可能なチェーンを列挙し、一方、保存されたエンドポイント候補はその周囲の可能な限り最良の部分色を列挙します。 別のカット スキャンは、残りの完全なカラーでないケースをカバーします。 すべての有効な未処理の構成はこれら 2 つの形式のいずれかに属するため、アルゴリズムによって検出される未処理の鉛直バスの最大数が最適になります。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

BASE = 1024
BITS = 10
MASK = BASE - 1
PAIR_BITS = 20

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    m = n * k

    first = [m] * k
    last = [-1] * k

    for i, x in enumerate(a):
        c = x - 1
        if first[c] == m:
            first[c] = i
        last[c] = i

    order = sorted(range(k), key=first.__getitem__)

    pref1 = [0] * k
    pref2 = [0] * k

    cnt = [0] * k
    t1 = 0
    id1 = 0
    t2 = 0
    id2 = 0

    # packed[i] stores the two best prefix candidates before position i.
    # Each candidate is encoded as count * BASE + color.
    packed = array('Q')
    packed.append(0)

    for i, x in enumerate(a):
        c = x - 1
        cid = c + 1

        if i == first[c]:
            pref1[c] = t1 * BASE + id1
            pref2[c] = t2 * BASE + id2

        cnt[c] += 1
        v = cnt[c]

        if cid == id1:
            t1 = v
        elif cid == id2:
            t2 = v
            if t2 > t1:
                t1, t2 = t2, t1
                id1, id2 = id2, id1
        elif v > t1:
            t2, id2 = t1, id1
            t1, id1 = v, cid
        elif v > t2:
            t2, id2 = v, cid

        e1 = t1 * BASE + id1
        e2 = t2 * BASE + id2
        packed.append((e1 << PAIR_BITS) | e2)

    # Suffix candidates for every color.
    suf1 = [0] * k
    suf2 = [0] * k

    cnt = [0] * k
    t1 = 0
    id1 = 0
    t2 = 0
    id2 = 0

    # No-complete-color case.
    best_no_full = 0

    # Cut m, where the suffix is empty.
    p = packed[m]
    pe1 = p >> PAIR_BITS
    pe2 = p & ((1 << PAIR_BITS) - 1)

    pc1 = pe1 >> BITS
    pi1 = pe1 & MASK
    pc2 = pe2 >> BITS
    pi2 = pe2 & MASK

    best_no_full = max(
        pc1,
        pc2,
    )

    for i in range(m - 1, -1, -1):
        c = a[i] - 1
        cid = c + 1

        if i == last[c]:
            suf1[c] = t1 * BASE + id1
            suf2[c] = t2 * BASE + id2

        cnt[c] += 1
        v = cnt[c]

        if cid == id1:
            t1 = v
        elif cid == id2:
            t2 = v
            if t2 > t1:
                t1, t2 = t2, t1
                id1, id2 = id2, id1
        elif v > t1:
            t2, id2 = t1, id1
            t1, id1 = v, cid
        elif v > t2:
            t2, id2 = v, cid

        # The current suffix is [i, m).
        p = packed[i]
        pe1 = p >> PAIR_BITS
        pe2 = p & ((1 << PAIR_BITS) - 1)

        pc1 = pe1 >> BITS
        pi1 = pe1 & MASK
        pc2 = pe2 >> BITS
        pi2 = pe2 & MASK

        # Combine the two best prefix and suffix colors.
        if pi1 == 0 or id1 == 0 or pi1 != id1:
            best_no_full = max(best_no_full, pc1 + t1)

        if pi1 == 0 or id2 == 0 or pi1 != id2:
            best_no_full = max(best_no_full, pc1 + t2)

        if pi2 != 0 and pi2 != id1:
            best_no_full = max(best_no_full, pc2 + t1)

        if pi2 != 0 and pi2 != id2:
            best_no_full = max(best_no_full, pc2 + t2)

    # DP states:
    # dp1[c], dp2[c] are the best two states ending with color c.
    # The second component is the color used as the left partial endpoint.
    dp1_val = [0] * k
    dp1_id = [0] * k
    dp2_val = [0] * k
    dp2_id = [0] * k

    for c in order:
        e1 = pref1[c]
        e2 = pref2[c]

        v1 = n + (e1 >> BITS)
        q1 = e1 & MASK

        v2 = n + (e2 >> BITS)
        q2 = e2 & MASK

        b1v = v1
        b1q = q1
        b2v = -1
        b2q = -1

        if q2 != q1:
            if v2 > b1v:
                b2v, b2q = b1v, b1q
                b1v, b1q = v2, q2
            else:
                b2v, b2q = v2, q2

        # Try every earlier complete color.
        for d in order:
            if first[d] >= first[c]:
                break
            if last[d] >= first[c]:
                continue

            v = dp1_val[d] + n
            q = dp1_id[d]

            if q == b1q:
                if v > b1v:
                    b1v = v
            elif q == b2q:
                if v > b2v:
                    b2v = v
            elif v > b1v:
                b2v, b2q = b1v, b1q
                b1v, b1q = v, q
            elif v > b2v:
                b2v, b2q = v, q

            v = dp2_val[d] + n
            q = dp2_id[d]

            if q == 0 and dp2_val[d] == 0:
                continue

            if q == b1q:
                if v > b1v:
                    b1v = v
            elif q == b2q:
                if v > b2v:
                    b2v = v
            elif v > b1v:
                b2v, b2q = b1v, b1q
                b1v, b1q = v, q
            elif v > b2v:
                b2v, b2q = v, q

        dp1_val[c] = b1v
        dp1_id[c] = b1q
        dp2_val[c] = b2v if b2v >= 0 else 0
        dp2_id[c] = b2q if b2v >= 0 else 0

    best = best_no_full

    for c in range(k):
        s1 = suf1[c]
        s2 = suf2[c]

        sc1 = s1 >> BITS
        si1 = s1 & MASK
        sc2 = s2 >> BITS
        si2 = s2 & MASK

        for dv, di in (
            (dp1_val[c], dp1_id[c]),
            (dp2_val[c], dp2_id[c]),
        ):
            if dv == 0:
                continue

            if di == 0 or si1 == 0 or di != si1:
                best = max(best, dv + sc1)

            if di == 0 or si2 == 0 or di != si2:
                best = max(best, dv + sc2)

    answer = m - best
    return str(answer)

if __name__ == "__main__":
    print(solve())
```最初のスキャンでは、すべての色の最初と最後の出現が計算されます。 これらの境界は、2 つの色を両方とも完全に維持できるかどうかを判断するために必要な唯一の情報です。 

転送カウントのメンテナンスには 2 つの目的があります。 色が最初に出現したとき、現在のカウントはその色の前の接頭語を正確に表します。 すべてのカットで、パックされた値には 2 つの最適なプレフィックス カラーが格納されます。これは、後で完全なカラーがない場合に必要になります。 

K は最大 1000 であるため、パッキングでは色識別子に 10 ビットが使用されます。別の 10 ビットには、最大 N であるそのカウントが格納されます。このような 2 つの候補は、64 ビット整数に快適に収まります。 使用する`array('Q')`100 万カットが発生する可能性がある場合でも、メモリ使用量は少なく抑えられます。 

逆スキャンではサフィックス候補が計算されます。 位置 i を処理する前のサフィックスの状態は、i の後の位置を記述します。これは、まさに次の場合に必要なものです。`i`色の最後の出現です。 位置 i を追加した後、サフィックス状態は i より前のカットに対応し、すでに保存されているプレフィックス状態と組み合わせることができます。 

DP は、終了色ごとに 1 つではなく 2 つの状態を保存します。 その理由は、最良の左エンドポイントの色が最良の右エンドポイントの色と偶然に等しくなる可能性があるためです。 2 つの異なる左側の色を維持すると、正しいエンドポイントを選択するときに競合する状態を破棄できることが保証されます。 

ここでは Python の整数はオーバーフローしません。 未処理の梅の最大数は N 倍 K、最大 1,000,000 です。 エンコードされた候補値も 64 ビット整数内に収まります。 

## 実用的な例

 ### サンプル 1

 入力は```
3 3
1 2 3 3 2 1 1 2 3
```関連する色の間隔は次のとおりです。```
color 1: [1, 7]
color 2: [2, 8]
color 3: [3, 9]
```2 つの間隔が互いに素であることはなく、2 つの色が両方とも完全であることはありません。 便利な選択は、完全な中間グループとしての色 2 です。 色 1 はその前に 1 つ、色 3 はその後に 1 つ保持できます。 

| 状態 | 値 |
 | --- | --- |
 | コンプリートカラー2 | 3 |
 | ベスト左部分色 1 | 1 |
 | ベスト右部分カラー3 | 1 |
 | 手つかずの合計 | 5 |
 | 配管の合計 | 9 |
 | 移動 | 4 |

 5 つの手つかずの梅は次のように表示されます。`1 2 2 2 3`。 残りの 4 つはすべて両端に移動できます。 DP は手つかずの要素を 5 つ検出するため、答えは 9 から 5 を引いて 4 になります。 

### サンプル 2

 入力は```
2 4
3 3 1 1 4 4 2 2
```すべての色がすでに 1 つの完全なブロックを形成しています。 

| 色 | 最初 | 最後 | DP の役割 |
 | --- | --- | --- | --- |
 | 3 | 1 | 2 | 最初の完全なカラー |
 | 1 | 3 | 4 | チェーンを延長します |
 | 4 | 5 | 6 | チェーンを延長します |
 | 2 | 7 | 8 | チェーンを延長します |

 インターバル条件はすべての遷移で成立するため、4 色すべてを完全に維持できます。 

| 状態 | 値 |
 | --- | --- |
 | 完全な色 | 4 |
 | 色ごとの梅の花 | 2 |
 | 手つかずの合計 | 8 |
 | 配管の合計 | 8 |
 | 移動 | 0 |

 結果はゼロであり、元の配置がすでに有効である場合に DP が不必要なエンドポイントの移動を強制しないことも確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(NK + K²) | 配列は一定の回数スキャンされ、カラー DP は最大で K² ペアをチェックします。 |
 | スペース | O(NK + K) | 元の配列と 1 つのパックされたプレフィックス状態が、O(K) カラーおよび DP データとともに保存されます。 |

 最大の配列には 1,000,000 個の梅バスが含まれているため、線形部分は数百万の単純な演算のみを実行します。 二次 DP には、最大 1,000,000 のカラー ペア チェックが含まれます。 このアルゴリズムは、色の順列や個々の鉛直のサブセットへの依存を回避します。

 ## 特殊なケース

 単色の場合```
1 1
1
```DP は色 1 を完全なグループと見なし、N=1 の垂直線を維持します。 左または右の部分的な色は必要ないため、触れられていない梅の最大数は 1 で、答えは 0 です。 

交互の場合```
2 2
1 2 1 2
```間隔は`[1,3]`カラー 1 と`[2,4]`カラー 2 の場合。これらは重なっているため、両方を完成させることはできません。 DP はどちらかの完全なカラーを維持し、2 つの鉛直を保持し、残りの 2 つは端に移動されます。 答えは 2 です。 

2色塗りの場合```
3 2
1 1 2 2 1 2
```最初の 4 つの要素の後にカットがあります。 接頭辞には 2 つの 1 が含まれ、接尾辞には 1 と 2 が 1 つずつ含まれていますが、最後の 1 と最後の 2 を移動して、残りの部分を移動することで最適な有効な配置が得られます。`1 1 2 2`手付かずの。 これらはすでに 2 つの完全なグループであるため、2 つの操作で十分です。 非完全カラー DP もチェックされますが、フルグループ表現では最適値 2 が得られます。 

最大サイズの交互の場合、N=1000 および K=2 の場合、配列には 2000 個の要素が含まれます。 2 つの色の間隔は完全に重なっているため、両方を完全なままにすることはできません。 どちらかの色を完全に保持すると 1000 個の梅が保存されますが、他の 1000 個は移動する必要があります。 このアルゴリズムは、配列長の K 倍に比例する演算を実行せずに 1000 を返します。 

エンドポイントの競合ケースには特に注意が必要です。 最適なプレフィックス カラーと最適なサフィックス カラーが両方ともカラー 1 であるとします。両方を維持すると、カラー 1 の 2 つの別々のグループが作成され、これは不正です。 アルゴリズムは各側で 2 つの最良の候補を保存し、両方の選択を試みます。 最良の候補者が衝突した場合、一方の側で 2 番目に良い候補者が選択されることがあります。 明確な候補が存在しない場合、対応するエンドポイントは単に空のままになります。
