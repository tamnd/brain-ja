 ## 問題の理解

 ストアには 1 つの固定価格があります`P`。 製品ごとに必要なユニット数がわかっています`A`そして1個あたりの市場価格`S`。 

ストアの動作は、1 つのユニットが少なくとも少なくとも価値があるかどうかに応じて異なります。`P`。 もし`S >= P`、個別のユニットが利用可能で、それぞれのコストが正確です`P`。 少なくとも取得するには`A`ユニットを購入するだけです`A`単位なのでコストは`A * P`。 

もし`S < P`、単体での購入はできません。 代わりに、1 つのパッケージに料金がかかります`P`そして含まれています`ceil(P / S)`単位。 完全なパッケージを任意の数購入できるため、タスクは合計ユニット数が少なくとも である最小数のパッケージを見つけることになります。`A`。 

たとえば、`P = 100`そして`S = 51`、1パッケージに含まれるもの`ceil(100 / 51) = 2`単位。 少なくとも取得するには`6`単位が必要です`ceil(6 / 2) = 3`パッケージ、原価計算`300`。 

多くてもあります`1000`製品、そしてあらゆるもの`A`そして`S`せいぜい`1000`。 これらの境界は十分に小さいため、シミュレーションでも最大で`1000`プロダクトあたりの反復回数は最大でも約`10^6`繰り返し。 そのような解決策は快適に通過するでしょう。 ただし、購入ルールの構造により、すべての製品を一定時間で解決できるため、特に単純な結果が得られます。`O(N)`解決。 

主なエッジケースは、2 つの価格設定ルールの境界から生じます。 いつ`S = P`、商品は単品での販売となりますので、入力用```
1 1004 100
```答えは`400`。 パッケージ式を使用した不注意な実装により、パッケージ サイズが計算される可能性があります。`1`それでもたまたま同じ結果が得られますが、治療`S = P`パッケージに複数のユニットが含まれると実装が想定している場合、パッケージのケースによって実際のルールがわかりにくくなり、エラーが発生する可能性があるためです。 

2 番目のエッジケースは次のような場合です。`P`で割り切れない`S`。 のために```
1 1006 30
```1つのパッケージに含まれるもの`ceil(100 / 30) = 4`単位。 2つのパッケージで提供される`8`単位なので、答えは`200`。 整数除算の使用`100 // 30 = 3`パッケージには 3 つのユニットしか含まれていないと誤って判断し、`200`ここでは偶然に必要な 6 つのユニットが揃っていますが、```
1 1007 30
```正解はまだです`200`一方、間違ったパッケージ サイズ 3 を使用すると、`300`。 

3 番目の境界は、必要な数量がすでに 1 パッケージよりも少ない場合に発生します。 のために```
1 1001 40
```1つのパッケージに含まれるもの`ceil(100 / 40) = 3`ユニットなので、1 つのパッケージを購入すれば十分です。その答えは、`100`。 必要な数量に固定価格を乗算すると、誤った結果が得られます。`40`パッケージ数の観点から、または`100`区別が正しく処理された場合に限ります。 

## アプローチ

 直接シミュレーションでは、累積ユニット数に達するまで 1 つのパッケージを繰り返し追加することで問題を解決できます。`A`。 が付いている商品の場合`S < P`、最初にパッケージのサイズを計算します`K = ceil(P / S)`を繰り返し追加します。`K`十分なユニットが揃うまで。 最悪の場合、`K = 1`したがって、このループのパフォーマンスは最大でも`A <= 1000`1 つの製品の反復。 と`N <= 1000`、それはせいぜい`10^6`合計の反復回数。 したがって、この総当たりシミュレーションは、実際には、指定された制約に対して十分に高速です。 

ループを取り除く観察は、すべてのパッケージのサイズと価格がまったく同じであるということです。 各パッケージが貢献する場合`K`ユニット、購入後`x`まさに私たちが持っているパッケージ`xK`単位。 最小の整数が必要です`x`満足のいく`xK >= A`、まさにそれです`ceil(A / K)`。 したがって、シミュレーション全体を 1 つの天井分割に置き換えることができます。 

2 つのケースを組み合わせて、非常に小さな計算を行うことができます。 もし`S >= P`, 1回の購入で1単位となりますので、購入数は`A`。 それ以外の場合は、1 回の購入で`K = ceil(P / S)`ユニットなので、購入数は`ceil(A / K)`。 購入ごとに費用がかかる`P`。

## Python ソリューション```python

def solve():    n, p = map(int, input().split())    ans = []
    for _ in range(n):        a, s = map(int, input().split())
        if s >= p:            purchases = a        else:            package_size = (p + s - 1) // s            purchases = (a + package_size - 1) // package_size
        ans.append(purchases * p)
    print(*ans)

if __name__ == "__main__":    solve()
