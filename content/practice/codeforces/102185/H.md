 ## 解決策
 ## 問題の理解

 ログは、スペースで区切られた一連の数字グループです。 元の非負の整数はそれぞれ、通常の 10 進表現を使用し、右から 3 桁ごとに区切り文字を挿入することによって出力されます。 すべての整数が (10^K) より厳密に小さい場合に、元の整数の異なるシーケンスが正確にこのグループのシーケンスをいくつ生成できるかを回復する必要があります。 

入力により、(N) 個のグループが正確な順序で指定され、桁制限 (K) が与えられます。 数値自体を再構築するわけではありません。 私たちは、結果として得られるすべてのブロックが有効な書式設定された 10 進整数になり、最大 (K) 桁を含むように、隣接するグループ間に境界を配置する可能な方法を数えています。 

1 つの整数を表すブロックは非常に特殊な形状をしています。 最初のグループには 1、2、または 3 桁の数字が含まれますが、先頭のゼロは禁止されており、後続のグループはすべて正確に 3 桁でなければなりません。 ゼロを含む唯一の例外は整数です。`0`、その表現は単一のグループで構成されます`0`。 次のような最初のグループを持つブロック`003`たとえそれが不可能であっても`003`は、別のグループの後のグループとして完全に有効です。 整数は厳密に (10^K) より小さいため、ブロック内の合計桁数も最大 (K) である必要があります。 

この制約により、二次動的計画法は除外されます。 (N=2\cdot10^5) の場合、(O(N^2)) 個の遷移ループは、最悪の場合、1 秒の制限をはるかに超えて、約 (N^2/2=2\cdot10^{10}) 個のチェックを実行します。 目的のソリューションでは、(O(N)) アルゴリズムを使用して、各入力グループを一定の回数だけ処理する必要があります。 

いくつかの境界ケースは誤って処理されやすいものです。 考慮する```
1 3
0
```考えられる整数列は 1 つだけ、つまり 1 つの整数 0 だけなので、答えは次のようになります。`1`。 治療中`0`通常の最初のグループの後に 3 桁のグループが続くと、非正規表現が誤って許可されてしまうのと同様です。 

継続グループ内の先頭のゼロは許可されます。 例えば、```
2 4
1 000
```答えがあります`1`、2 つのグループが整数を形成するため、`1000`。 先行ゼロを含むすべてのグループを拒否するソリューションでは、このケースは誤って拒否されます。 

桁制限は正確です。 のために```
2 5
999 999
```6 桁が必要となるため、2 つのグループで 1 つの数値を形成することはできません。 これらは 2 つの別々の整数でなければならないため、答えは次のようになります。`1`。 (K=6) の場合、分割と結合の両方が可能であり、答えが得られます。`2`。 

3 桁未満のグループを連続にすることはできません。 例えば、```
3 7
10 500 4
```次のようにのみ分割できます`10 500`そして`4`、したがって、答えは次のとおりです`1`。 合計桁数のみをチェックし、3 桁の継続ルールを忘れた遷移では、3 つのグループすべてを含む 1 つの数値が誤ってカウントされます。 

## アプローチ

 直接動的計画法は、最初の (i) グループを表す方法の数である (dp[i]) から始まります。 すべての位置 (i) について、最後の整数のすべての可能な開始位置 (j) を試すことができます。 次に、グループ (j,\ldots,i) が法的な表現を形成しているかどうか、およびその桁数が最大 (K) であるかどうかを確認します。 存在する場合、(dp[j-1]) を (dp[i]) に追加します。 

これは正しいです。プレフィックスのすべての表現には最後の整数が 1 つだけ含まれているため、その整数の可能な開始位置によってすべての解が素のケースに分割されます。 問題はトランジションの回数です。 (\Theta(N^2)) 個のペア ((j,i)) が存在する可能性があり、(N=2\cdot10^5) の場合、およそ (2\cdot10^{10}) 個のチェックになります。 

フォーマットされた整数の構造により、不足している最適化が可能になります。 整数の最初のグループが選択されると、その後のグループはすべて正確に 3 桁の数字を持つ必要があります。 したがって、3 桁のグループの連続実行をスキャンする際、可能な開始位置は連続した範囲を形成します。 また、桁制限により、この範囲がグループの固定最大数に制限されます。 

このようなラン内で 3 桁未満の可能な開始位置は最大 1 つです。 ３桁グループのラン直前のグループです。 その貢献は個別に処理できます。 他のすべての可能な開始値は 3 桁のグループであり、それらの寄与は (dp[j-1]) 値のスライド間隔を形成します。 プレフィックスの合計を使用すると、その間隔全体を一定時間で取得できます。 

ブルートフォース DP は、考えられるすべての以前の境界が考慮されるため機能します。 検査する境界が多すぎるため、失敗します。 法的な継続が 3 桁にならざるを得ないという観察により、これらの多くの遷移が範囲の合計に変換され、計算全体が線形時間に短縮されます。

 | 以前のすべての境界を超えるブルート フォース DP | (O(N^2)) | (O(N)) | 遅すぎる |
 | 有効な 3 桁の先頭のプレフィックスの合計 | (O(N)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (dp[i]) を、フォーマットされた出力が正確に最初の (i) グループである有効な元の整数シーケンスの数として定義します。 Set (dp[0]=1)、空のプレフィックスを表します。 
2. グループを左から右に処理します。 現在のグループの桁数が 3 桁未満の場合、以前に開始された整数を継続することはできません。 これは新しい整数の完全な表現である必要があるため、グループが有効なスタンドアロン 10 進数表現である場合、(dp[i]) は (dp[i-1])、それ以外の場合はゼロになります。 
3. 長さが 3 ではない最新のグループを思い出してください。 その位置と現在の位置の間は、すべてのグループが 3 桁になります。 現在のグループが 3 桁の場合、ここで終わる整数は、この実行の 3 桁のグループの 1 つで始まるか、記憶されている短いグループで始まります。 
4. 位置 (j) の 3 桁の開始グループの場合、(j) から (i) までのグループの数は (i-j+1) です。 すべてのグループは 3 桁の数字を提供するため、次の場合に整数が許可されます。 
[
 3(i-j+1)\le K.
 】
 したがって、有効な 3 桁の開始は次の条件を満たします。 
[
 j\ge i-\left\lfloor\frac K3\right\rfloor+1。 
】
 現在の連続する 3 桁のグループ内の開始部分のみが関係します。 
5. 3 桁のグループは、最初の文字がゼロ以外の場合にのみ最初のグループになれます。 プレフィックス合計内のそのような位置 (j) ごとに (dp[j-1]) を格納します。 現在有効な 3 桁の開始値すべての合計が一定時間で取得されます。 
6. 現在の実行の直前にある 1 つ短いグループを個別に処理します。 長さが (L<3) の場合、そこから整数を開始し、(i) で終了する必要があります。 
[
 L+3(i-j)\le K、
 】
 ここで、(j) はその短いグループの位置です。 このようなグループは、それが正当なスタンドアロン 10 進接頭辞である場合にのみ有効な最初のグループとなり、そうでない場合に限ります。`0`、 なぜなら`0`それ以上のグループがフォローすることはできません。 
7. 有効な 3 桁の開始値と、可能なより短い開始値からの寄与を加算します。 結果の合計は (dp[i]) になります。 それを剰余 (10^9+7) で削減します。 
8. 出力 (dp[N])。ログ全体にわたる整数境界の有効な配置をすべてカウントします。 

不変条件は、位置 (i) を処理した後、(dp[i]) が最初の (i) グループを分割する有効な方法を正確にカウントすることです。 考えられる最後の整数はすべて、最初のグループによって一意に分類されます。 最初のグループが 3 桁の場合、それは維持されている 3 桁の範囲に属します。 それ以外の場合は、最新の短いグループである必要があります。 プレフィックスの合計には、書式設定ルールと (K) 桁境界の両方を満たす 3 桁の開始が正確に含まれますが、残りの唯一の可能性は別の短いグループ チェックによって処理されます。 したがって、有効なパーティションは省略されず、無効なパーティションはカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    n, k = map(int, input().split())
    a = input().split()

    dp = [0] * (n + 1)

    # pref[i] = sum of dp[j - 1] for valid three-digit starts j <= i.
    pref = [0] * (n + 1)

    dp[0] = 1

    # Last position whose group has length different from 3.
    last_short = 0

    max_three_groups = k // 3

    for i in range(1, n + 1):
        s = a[i - 1]
        length = len(s)

        if length == 3:
            # This position may be the first group of an integer only
            # if it does not start with zero.
            if s[0] != '0':
                pref[i] = (pref[i - 1] + dp[i - 1]) % MOD
            else:
                pref[i] = pref[i - 1]

            # All three-digit starts must lie in the current run.
            left = max(last_short + 1, i - max_three_groups + 1)

            ways = (pref[i] - pref[left - 1]) % MOD

            # The group immediately before this run may itself be
            # the first group of the integer.
            if last_short:
                t = a[last_short - 1]
                tlen = len(t)

                # "0" can only represent the integer zero by itself.
                valid_as_first = t != "0" and t[0] != '0'

                if valid_as_first:
                    digits = tlen + 3 * (i - last_short)
                    if digits <= k:
                        ways += dp[last_short - 1]
                        ways %= MOD

            dp[i] = ways

        else:
            # A group shorter than three digits cannot continue a
            # previously started integer.
            if s == "0" or s[0] != '0':
                dp[i] = dp[i - 1]
            else:
                dp[i] = 0

            pref[i] = pref[i - 1]
            last_short = i

    print(dp[n] % MOD)

if __name__ == "__main__":
    solve()
```配列`dp`ウォークスルーから動的プログラミング状態を実装します。 値`dp[i-1]`は位置 (i) が処理される時点ですでにわかっているため、(i) から始まる新しい整数の寄与としてすぐに使用できます。 

の`pref`配列には、正当な最初のグループである 3 桁のグループからの寄与のみが格納されます。 位置 (j) では、寄与は次のようになります。`dp[j - 1]`これは、(j) より前のすべてがすでにパーティション化されており、新しい整数が (j) から始まるためです。 

下限`left`2 つの独立した制限を組み合わせます。`last_short + 1`候補者が 3 桁未満のグループにまたがることを防ぎます。`i - max_three_groups + 1`最初のグループも 3 桁である数値に対して (K) 桁の制限を適用します。 

現在の 3 桁のランの前の短いグループが個別にチェックされます。 最初のグループの長さは 1 または 2 であるため、後続の 3 桁のグループの最大数は、単純に長さではなく、その正確な長さに依存します。`K // 3`。 

特別な扱いは、`"0"`ゼロの 10 進表現には追加のグループが含まれないため、これが必要です。 次のようなトークン`"000"`は数値内で使用できますが、最初のグループにすることはできません。 

Python の整数はオーバーフローしませんが、すべての DP とプレフィックス合計の加算はモジュロ (10^9+7) で削減されるため、格納される値は小さいままになります。 すべての配列は DP 位置に対して 1 から始まるインデックスを使用します。`dp[j - 1]`グループ (j) での可能な開始に直接対応します。

 ## 特殊なケース

 ゼロの場合、```
1 3
0
```グループの長さは 3 未満であり、有効なスタンドアロン表現として認識されます。 アルゴリズムセット`dp[1]=dp[0]=1`。 治療はしません`0`後の 3 桁のグループの短いプレフィックスの候補として、次のような非正規表現が使用されます。`0 123`決してカウントされません。 

先行ゼロ継続の場合、```
2 4
1 000
```最初のグループ`1`有効なショートスタートです。 2番目の位置では、`000`新しい整数を指定することはできませんが、次の整数を続けることはできます。`1`。 全長は(1+3=4)で制限内なので、`dp[2]=1`。 

正確な境界については、```
2 6
999 999
```(3\cdot2=6) ため、3 桁の開始ウィンドウでは 2 つのグループが許可されます。 開始可能な 2 つのグループは最初と 2 番目のグループで、2 つのパーティションが生成されます。`[999,999]`そして`[999] [999]`。 したがって`dp[2]=2`。 

代わりに (K=5) とすると、```
2 5
999 999
```2 つの 3 桁のグループには 6 桁が必要となるため、最初のグループは 2 番目のグループを吸収できません。 分割されたパーティションだけが残り、`dp[2]=1`。 下限`i - K//3 + 1`2 つのグループの遷移が正しく削除されます。 

境界を強制する短いグループの場合、```
3 7
