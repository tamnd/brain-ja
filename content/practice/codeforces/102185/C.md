 ## 問題の理解

 接続された無向サボテン グラフがあります。 ここのサボテンには、すべての頂点が最大 1 つの単純なサイクルに属し、すべてのサイクルの長さが均等であるという、より強力な特性があります。 都市 1 には最初は工場があります。 列車は工場から最短距離であらゆる目的地に到着します。 複数の最短パスが存在する場合、それらのいずれかを選択できます。 

初期ファクトリーの場合、グラフには、すべての鉄道エッジがすべての可能な最短ルートによって一方向にのみ使用されるという便利な特性があります。 ファクトリを追加すると、これが当てはまらなくなる可能性があります。 どこかの端に両方向に列車が走る可能性がある場合は、そこに並行する鉄道を 1 本追加して建設し、2 つの線路で反対方向を規定する必要があります。 

入力では、都市、既存の鉄道、工場が建設された順序で説明されます。 新しい工場ごとに、その時点で必要な新しい線路の数を出力する必要があります。 以前にすでに建設されていた工場は、再度何も必要ありません。 

グラフには最大で (10^5) 個の頂点と最大で (N-1+N/4) 個のエッジがあります。 2 番目の境界は、合計で (O(N)) 個のエッジしかないことを意味するため、線形または (N\log N) 個の解が現実的です。 (10^5) ファクトリの場合、すべてのファクトリのグラフ全体をスキャンするアルゴリズムは、最悪の場合、2 秒の制限をはるかに超える (10^{10}) 程度のエッジ操作を実行します。 サボテン構造は任意のグラフよりもはるかに多くの情報を提供するため、二次前処理も不要です。 

単純な実装で間違いが明らかになる簡単なケースがいくつかあります。 1 つのエッジで構成されるグラフ上で、クエリが`2 2 1`、答えは`1 0 0`。 2 番目のファクトリは最初の新しいファクトリの複製であり、最後のクエリは都市 1 にある元のファクトリであるため、すべてのクエリを新しい競合として扱うのは間違っています。 

偶数サイクルも重要なケースです。 のために```
4 4
1 2
2 3
3 4
4 1
1
3
```答えは`4`。 都市 1 と都市 3 はサイクル上で反対側にあります。 4 つの鉄道端はすべて、2 つの工場からの最短ルートで反対方向に使用できるため、木のように均等なサイクルを扱うと、答えが過小評価されてしまいます。 

都市 1 でのクエリでもゼロが返される必要があります。 例えば、```
2 1
1 2
3
1 1 1
```生成する`0 0 0`。 同じ都市にある最初の工場とその後の工場は、まったく同じ最短経路方向を誘導します。 

## アプローチ

 直接的なアプローチは、新しい工場ごとに最短パス構造を再計算することです。 新しいファクトリから BFS を実行し、すべての頂点までの距離を取得し、すべてのエッジを検査します。 エッジ (u v) の場合、ソースから (u) までの距離が小さい場合、最短ルートではエッジを (u\to v) として使用し、(v\to u) に対して対称的に使用できます。 この方向を既存の方向と比較すると、別の鉄道が必要かどうかがわかります。 

これは正しいです。最短経路の距離によって、エッジのどの端点が最短ルート上で他の端点に先行できるかが完全に特徴付けられるからです。 問題は繰り返し作業です。 1 つの BFS とエッジの 1 回のスキャンにはコストがかかり (O(N+M)=O(N))、それを (K) 個のファクトリに対して実行するとコストがかかります (O(KN))。 両方のパラメーターが (10^5) に等しい場合、これはおよそ (10^{10}) の演算になります。 

有益な観察は、偶数のサボテンは部分的な立方体であるということです。 部分立方体の関連部分を使用するために、部分立方体の一般理論は必要ありません。 すべてのブリッジは、その単一のエッジから構成される 1 つの独立したクラスを形成します。 偶数サイクル内では、反対側のエッジがペアを形成します。 このような反対のペアを 1 つ削除すると、グラフが正確に 2 つの側面に分離されます。 ペアの 2 つのエッジは、最短経路方向に関して常に一緒に動作します。 

したがって、グラフのエッジを独立したクラスに分割できます。 ブリッジ クラスの重みは 1 ですが、偶数サイクルの反対側のエッジのペアの重みは 2 です。クラスは、対応するカットの両側に工場が出現したときに正確に衝突を引き起こします。 両方の側にファクトリが含まれると、そのクラスは永続的に固定され、二度と貢献することはありません。 

サボテン特有の簡略化がもう 1 つあります。 グラフのルートを都市 1 に設定します。すべてのクラスには、まさにルート化されたサブツリーである側面があります。 ブリッジの場合、これはブリッジの下のサブツリーです。 サイクルの場合、DFS ツリーに沿った頂点が

 [
 c_0,c_1,\ldots,c_{2h-1},
 】

 (c_0) がサイクルの最高頂点である場合、(1\le i\le h) のエッジ (c_{i-1}c_i) を含む反対側のエッジ クラスは、非ルート側として正確に (c_i) のサブツリーを持ちます。 

最初のファクトリはルートにあるため、このようなすべてのカットの反対側には時間 0 でファクトリがすでに含まれています。 したがって、クラスは、最初の将来のファクトリがルート化されたサブツリー側に入った瞬間に 1 回だけ貢献します。 すべてのサブツリーに対して初めてそれを計算し、その答えにクラスの重みを追加できます。 

ブルートフォース手法は、すべてのソースの方向情報を明示的に再構築するため機能します。 ほぼすべての情報が繰り返されるため、失敗します。 関連情報が実際には独立したブリッジ クラスと反対側のエッジのペアによって伝送されるという観察により、問題全体がサブツリーの最小値に縮小されます。

 | ブルートフォース | (O(K(N+M))) | (O(N+M)) | 遅すぎる |
 | 最適 | (O(N+M+K)) | (O(N+M+K)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DFS スパニング ツリーを使用して、都市 1 にサボテンをルートします。 店`parent`、`depth`、およびすべての頂点の親エッジ。 DFS ツリーは、ルート化されたすべてのサブツリーに自然な意味を与えます。 
2. 最初にすべてのツリー エッジに重み 1 を与えます。そのようなエッジは、後でサイクルに属していることが判明しない限り、ブリッジ クラスを表します。 頂点`v`からの木の端を表します`parent[v]`に`v`。 
3. ツリー以外のエッジをすべて見つけます。 サボテンの無向 DFS では、このようなすべてのエッジが子孫を祖先に接続し、ちょうど 1 つのサイクルを閉じます。 子孫から親ポインターを通って、祖先に到達するまで上向きに進みます。 サボテン内のサイクルは最大でも 1 つの頂点を共有するため、これらすべての歩行の合計長は (O(N)) になります。 
4. 発見されたサイクルに頂点 (c_0,c_1,\ldots,c_{2h-1}) があるとします。ここで (c_0) は祖先であり、最後のエッジ (c_{2h-1}c_0) は非ツリー エッジです。 その反対側のエッジ クラスは次のとおりです。 
[
 (e_i,e_{i+h}),\qquad 0\le i<h.
 】
 (e_{i-1}=c_{i-1}c_i) を含むクラスの場合、ルートから離れた側はまさに (c_i) のサブツリーになります。 そのサブツリーに代表的な重み 2 を与えます。サイクルの残りのツリー エッジはこれらのペアの反対のメンバーであるため、重み 0 を受け取り、別のクラスとして扱ってはなりません。 
5. すべての都市について、その都市に初めて工場が建設された時間を記録します。 都市 1 の工場はすでに存在しているため、時間は 0 になります。 クエリ シーケンス内で同じ都市が複数回出現する場合は、その最初のクエリのみがクラスの計算に関係します。 
6. コンピューティング`first[v]`、ルート化されたサブツリー内の任意の場所の最も早い工場時刻。`v`。 DFS 順序を逆方向に処理し、すべての子の最小値をその親に伝播します。 これにより、「工場が最初にこのカット側に入るのはいつですか?」という質問が変わります。 1 つの保存された値に変換されます。 
7. クラス重みがゼロ以外のすべての頂点について、次のようにします。`t = first[v]`。 もし`t`は有限であるため、クラスの重みを追加して答えます`t`。 このクラスは、最初の工場がそのサブツリー側に入るときに問題になります。これは、都市 1 がすでに反対側に存在しているためです。 
8. クエリ回数 1 ～ (K) の累積値を出力します。 関連するサブツリーに以前のファクトリがすでに含まれている場合、クエリを繰り返しても何も影響しません。 

不変条件は、すべての独立した方向の競合が 1 つのクラスによって表され、すべてのクラスが 1 つのルート付きサブツリーによって表されるということです。 最初のファクトリがそのサブツリーに入る前は、すべてのファクトリが反対側にあるため、競合は発生しません。 最初のエントリでは、両側にファクトリが含まれており、そのクラスのすべてのエッジを 2 倍にする必要があります。 その後、クラスはすでに永続的に固定されます。 クラスは関連するすべてのエッジを分割するため、それらの重みを合計すると、追加トラックの最小数が正確に得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n)]
    edges = []

    for eid in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        edges.append((a, b))
        graph[a].append((b, eid))
        graph[b].append((a, eid))

    k = int(input())
    queries = [int(x) - 1 for x in input().split()]

    # Build an actual DFS tree iteratively.
    parent = [-1] * n
    parent_edge = [-1] * n
    depth = [0] * n
    order = [0]
    parent[0] = 0

    it = [0] * n
    stack = [0]
    back_edges = []

    while stack:
        v = stack[-1]

        if it[v] == len(graph[v]):
            stack.pop()
            continue

        u, eid = graph[v][it[v]]
        it[v] += 1

        if eid == parent_edge[v]:
            continue

        if parent[u] == -1:
            parent[u] = v
            parent_edge[u] = eid
            depth[u] = depth[v] + 1
            order.append(u)
            stack.append(u)
        else:
            # In an undirected DFS of a cactus, a non-tree edge
            # goes between a vertex and one of its ancestors.
            if depth[u] < depth[v]:
                back_edges.append((v, u, eid))

    # weight[v] describes the edge parent[v] -> v.
    # Initially every tree edge is a bridge class of weight 1.
    weight = [0] * n
    for v in range(1, n):
        weight[v] = 1

    # Each even cycle contributes h classes of weight 2.
    # The first h tree edges on the ancestor-to-descendant path
    # represent these classes. The remaining tree edges are their
    # opposite partners and must not form separate classes.
    for descendant, ancestor, _ in back_edges:
        path = []
        cur = descendant

        while cur != ancestor:
            path.append(cur)
            cur = parent[cur]

        path.reverse()

        # The cycle has len(path) tree edges plus the back edge.
        cycle_len = len(path) + 1
        half = cycle_len // 2

        for i, child in enumerate(path):
            if i < half:
                weight[child] = 2
            else:
                weight[child] = 0

    INF = k + 1

    # first_at[v] is the first factory time exactly at v.
    first_at = [INF] * n
    first_at[0] = 0

    for t, v in enumerate(queries, 1):
        if first_at[v] == INF:
            first_at[v] = t

    # first[v] becomes the first factory time anywhere in subtree(v).
    first = first_at[:]

    for v in reversed(order[1:]):
        p = parent[v]
        if first[v] < first[p]:
            first[p] = first[v]

    answer = [0] * (k + 1)

    # Every nonzero-weight class is represented by one subtree.
    # Its opposite side already contains city 1 at time zero.
    # Thus the class contributes exactly when its subtree gets
    # its first factory.
    for v in range(1, n):
        if weight[v] and first[v] <= k:
            answer[first[v]] += weight[v]

    print(*answer[1:])

if __name__ == "__main__":
    solve()
```隣接リストには、エンドポイントとエッジ識別子の両方が保存されます。 エッジ識別子は、親エッジを、すでに訪問した頂点につながる別のエッジから区別するために必要です。 

反復 DFS は、(10^5) 個の頂点を含むパスでの Python 再帰深さの問題を回避します。 の`it`配列は、検査する次の隣接エントリを記録します。これにより、Python 呼び出しスタックに依存せずに、再帰的 DFS と同じ走査順序が与えられます。 

DFS の後、すべてのツリー エッジは最初に重み 1 を受け取ります。バック エッジがサイクルを閉じると、その祖先から子孫へのツリー パスが次の方法で復元されます。`parent`。 サイクル長が (2h) の場合、その最初の (h) ツリー エッジは、それぞれ物理サイズ 2 の (h) 個の反対側のエッジ クラスを表します。 残りのツリー エッジは、反対側のメンバーと同じクラスに属しているため、重み 0 を割り当てることで二重カウントを防ぎます。 

自転車道を歩くのに費やされる総作業量は直線的です。 グラフは頂点サボテンであるため、共有アーティキュレーション ポイントとしての場合を除き、頂点は 1 サイクルでのみ発生します。 したがって、回復されたすべてのサイクルの長さは合計で (O(N)) になります。 

クエリ処理は、サブツリー集約の前に意図的に実行されます。`first_at[v]`は正確な頂点にある最も古いファクトリーのみを表しますが、`first[v]`逆走査の後は、その頂点の下にある最も古いファクトリを表します。 都市 1 の時間はゼロであるため、適切なサブツリーで表されるすべてのクラスには、補完側にファクトリがすでに存在します。 

Python には整数オーバーフローの問題はありません。 C++ では、最大 (M\le 125000) 個の物理エッジを追加できるため、答えには 32 ビット整数でも十分ですが、Python の整数型ではその懸念が完全に解消されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(N+M+K)) | DFS、サイクル再構築、サブツリー最小伝播、およびクエリ処理はすべて線形です。 
| スペース | (O(N+M+K)) | 隣接リスト、DFS 配列、クエリ シーケンス、および応答配列 |

 制約により (M=O(N)) が与えられるため、合計の複雑さは実質的に (O(N+K)) になります。 (N) と (K) の両方が (10^5) で区切られているため、これは意図した制限内に問題なく収まりますが、ブルートフォース (O(KN)) アプローチでは、約 (10^{10}) 個の操作が必要になります。

    for v in range(1, n):
        weight[v] = 1

    for descendant, ancestor in back_edges:
        path = []
        cur = descendant

        while cur != ancestor:
            path.append(cur)
            cur = parent[cur]

        path.reverse()

        cycle_len = len(path) + 1
        half = cycle_len // 2

        for i, child in enumerate(path):
            if i < half:
                weight[child] = 2
            else:
                weight[child] = 0

    INF = k + 1
    first = [INF] * n
    first[0] = 0

    for t, v in enumerate(queries, 1):
        if first[v] == INF:
            first[v] = t

    for v in reversed(order[1:]):
        p = parent[v]
        first[p] = min(first[p], first[v])

    ans = [0] * (k + 1)

    for v in range(1, n):
        if weight[v] and first[v] <= k:
            ans[first[v]] += weight[v]

    return " ".join(map(str, ans[1:]))

def run(inp: str) -> str:
    global solve
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 特殊なケース

 最小のグラフの場合```
2 1
1 2
3
2 2 1
```唯一のクラスはサブツリー 2 で表されるブリッジです。その最初のファクトリータイムは 1 であるため、その重み 1 が応答 1 に追加されます。2 番目のクエリは依然として同じサブツリー内にありますが、最初のファクトリータイムはすでに 1 であるため、何も追加されません。 3 番目のクエリは都市 1 で、そのサブツリーの外側にあるため、これも何も追加しません。 結果は`1 0 0`。 

4サイクルの場合```
4 4
1 2
2 3
3 4
4 1
1
3
```サイクルには 2 つの反対側のエッジ クラスが含まれます。 DFS のルートが 1 の場合、それらの代表は頂点 2 と 3 で、それぞれの重みは 2 です。都市 3 は両方の代表サブツリーの内側にあるため、両方のクラスは最初のファクトリー時間 1 を受け取ります。答えは (2+2=4) です。 これはまさに、すべてのサイクル エッジを独立したブリッジとして扱うと誤って処理されるケースです。 

繰り返し行われる工場の場合は、次のことを考慮してください。```

1 2
4
1 1 1 1
```唯一のクラスはサブツリー 2 で表され、クエリはそのサブツリーに入りません。 初回は無限であるため、寄与することはありません。 すべての答えはゼロです。

3 4

最大サイズのパスには (99999) 個のブリッジ クラスが含まれます。 都市 100000 の工場はすべての適切なサブツリーの最初の工場であるため、最初の答えは (99999) になります。 その都市を繰り返しても、新しいクラスはアクティブになりません。 実装では、グラフ全体とすべてのクエリが線形作業で処理されます。これはまさに制約によって要求される動作です。 

中心的な考え方は、問題は実際には最短経路を再計算することを求めているわけではないということです。 偶数のサボテンでは、最短パス方向の競合はブリッジ クラスと反対側のエッジのペアに編成されます。 都市 1 をルートとした後、そのようなすべてのクラスは単一のサブツリー代表を持ち、各クエリの答えは単純に、そのクエリ時にその代表サブツリーが最初のファクトリを受け取るクラスの合計重みになります。
