 ## 解決策
 ## 問題の理解

 整数格子点上に配置された単位立方体で構成される 3D 構造が与えられます。 各列の位置$(x, y)$から始まる垂直スタックを形成します$z = 0$、立方体が高さに存在する場合、重力によりスタックは下から固体になるように強制されます。$z$、その後、その下にあるすべての位置が同じになります$(x, y)$列にはキューブも含まれている必要があります。 

完全な構造の代わりに、2 つの直交投影のみが与えられます。 

X ビューと呼ばれる最初の投影は、バイナリ グリッドです。$(y, z)$。 X 軸に沿った少なくとも 1 つの列にその高さに達するスタックがある場合、セルはマークされます。$(y, z)$位置。 直観的には、正の x 方向から見ると、すべての x 座標が折りたたまれ、それぞれの高さに立方体が存在するかどうかだけが記憶されます。$(y, z)$。 

2 番目の投影である y ビューは対称です。これは、上のバイナリ グリッドです。$(x, z)$、y 軸に沿った少なくとも 1 つのスタックが高さに達しているかどうかを示します。$z$位置で$x$。 

私たちにも限界が与えられている$x \le a$、$y \le b$、$z \le c$, そのため、グリッドのサイズは固定されています。 

このタスクは、投影と重力の両方に一致する有効な 3D 構成が存在するかどうかを判断し、存在する場合は、すべての有効な構成にわたって可能な最小および最大の立方体の合計数を計算することです。 

制約が十分に大きいため、3D グリッドを明示的にシミュレートしたり、すべての構成を試したりするアプローチは不可能です。 テスト ケース全体の入力サイズの合計は約$2 \cdot 10^6$したがって、どのような解も線形に近いか、最大でも線形でなければなりません。$O(n \log n)$。 

いくつかの障害モードがすぐに表示されます。 

1 つは、一貫性のない予測です。 たとえば、X ビューで高さのセルが必要な場合、$z = 5$一部の人にとっては$y$、しかし、y ビューでは、どのようなことも不可能になります。$x$互換性のある場所で高さ 5 に到達すると、構造物は存在できなくなります。 

もう 1 つの微妙な問題は、重力の結合です。 高さ 5 の立方体は、同じ列内にそれより低いすべての高さの立方体を暗黙的に作成します。 各高さを個別に扱う単純なアプローチでは、有効なスタックを過大にカウントしたり、過少カウントしたりすることになります。 

最後に、射影制約はセルごとではなく存在的なものです。X ビュー内の 1 つの「1」には、すべてではなく、少なくとも 1 つのサポート列のみが必要です。 この区別が、素朴な貪欲な推論を難しくしているものです。 

## アプローチ

 直接的な総当たり戦略では、高さを割り当てます。$h[x][y]$すべての列について、両方の投影が一致するかどうかを確認します。 それぞれ$h[x][y]$からの範囲が可能です$0$に$c$、あります。$(c+1)^{ab}$可能性。 非常に小さなグリッドであっても、これはすぐに爆発します。 

重要な観察は、投影が部分的にのみ分離しているということです。 各列$(x, y)$は垂直セグメントに寄与し、どちらのビューも行または列の少なくとも 1 つの列が特定の高さに達するかどうかのみを考慮します。 これにより、問題は高さの選択に変わります。$a \times b$行方向および列方向の存在制約の下にあるグリッド。 

高さを直接決定するよりも、投影図で必要な「もの」がカバーされているかどうかを考慮する方が簡単です。 それぞれの細胞$(y, z)$X ビューでは 1 は、少なくとも 1 つで「覆われている」必要があります。$x$- 列の高さは$y$少なくとも$z$。 y ビューについても同様です。 

これは建設的な貪欲な解釈につながります。 候補列を維持し、必要な投影セルがすべてカバーされるように、積み重ねられた総体積を最小化または最大化しながら高さを段階的に割り当てます。 

最小の答えと最大の答えの違いは、単一の高い列をどれだけ積極的に再利用するかによって決まります。 最小限に抑えるために、高くなるスタックが少なくなるように、列をできる限り再利用するように努めます。 最大限の効果を得るために、多くの列が個別に大きくなるように再利用を避けるように努めます。

 ## アルゴリズムのチュートリアル

 グリッドを次のように扱います。$a \times b$列の配列。各列は高さを持つ$h[x][y]$。 

### キューブの最小数

 1. それぞれについて$(x, y)$、Y ビュー制約から許可される最大の高さを計算します。 Y ビューの位置の場合$(x, z)$0 がある場合は列がありません$x$高さに到達できる$z$, したがって、上限が得られます。$H_x[x]$。 同様に X ビューから得られるのは$H_y[y]$。 各セルにはハードキャップが付けられます$cap[x][y] = \min(H_x[x], H_y[y])$。 これにより、割り当てがゼロ制約に違反しないことが保証されます。 
2. すべての「1」セルの実現可能性を確認します。 あらゆる人にとって$(y, z)$X ビューでは 1 です。少なくとも 1 つは存在する必要があります。$x$そのような$cap[x][y] \ge z$。 そうでなければ、即答は不可能です。 同じチェックが y ビューにも対称的に適用されます。 
3. 固定ごとに$y$、今度は全体の高さを決定します$x$。 高さを加工します$z = 1$に$c$。 要件を見たとき$(y, z) = 1$、少なくとも 1 つの列を確保する必要があります。$x$この時点で$y$高さに達する$z$。 
4. 立方体の総数を最小限に抑えるために、この要件を常に現在最小の高さを持ちながらも到達できる列に割り当てます。$z$。 列を高くすると、その列内のすべての低い高さが自動的にカバーされるため、複数の列を不必要に繰り返し増やすことは避けられます。 
5.すべての処理が完了したら$z$、それぞれの最終的な高さ$(x, y)$割り当てられる最大要件です。 すべての高さの合計により、最小立方体数が求められます。 

### キューブの最大数

 1. 同じ実現可能性チェックとキャップを再利用します。 
2. 要件ごとに$(y, z) = 1$、既存の背の高い柱を再利用する代わりに、まだ高くなっていない柱、または現在の高さは最小限だが、それでも到達できる柱に割り当てようとします。$z$。 
3. 目標は、複数の要件を同じ列にマージしないようにすることです。 各列は、制約が許す限り独立して増加します。 
4. 結果として得られるすべての高さの最終合計により、可能な最大立方体数が得られます。 

### なぜ効果があるのか

 このアルゴリズムは、必要なすべての射影制約を確実にカバーすることによって、各射影制約が正確に満たされるという不変式に依存します。$(\text{row}, z)$少なくとも 1 つの列でペアにします。 重力によって単調な積み重ねが強制されるため、柱が高さまで上昇すると、$z$の場合、下位の要件はすべて自動的に満たされるため、割り当てでは列ごとに割り当てられた最大レベルを追跡するだけで済みます。 

すべての有効な構造は、必要な各投影セルの支持柱への割り当てに対応しており、そのようなすべての割り当てにより固有の誘導高さグリッドが生成されます。 貪欲な戦略は、実現可能性を損なうことなく、誘導される高さの合計を最小化または最大化する有効な割り当ての中から選択します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c = map(int, input().split())

        x_view = [input().strip() for _ in range(c)]
        y_view = [input().strip() for _ in range(c)]

        # convert to easier indexing: z from 1..c
        # x_view[i][j] corresponds to z = c-i-1, y = j
        # y_view[i][j] corresponds to z = c-i-1, x = j

        INF = 10**9

        # upper bounds per y from x-view zeros
        hy = [c] * b
        for i in range(c):
            z = c - i
            for y in range(b):
                if x_view[i][y] == '0':
                    hy[y] = min(hy[y], z - 1)

        # upper bounds per x from y-view zeros
        hx = [c] * a
        for i in range(c):
            z = c - i
            for x in range(a):
                if y_view[i][x] == '0':
                    hx[x] = min(hx[x], z - 1)

        cap = [[0] * b for _ in range(a)]
        for x in range(a):
            for y in range(b):
                cap[x][y] = min(hx[x], hy[y])

        # feasibility check + collect requirements
        req_y = [[] for _ in range(b)]
        req_x = [[] for _ in range(a)]

        ok = True

        for i in range(c):
            z = c - i
            for y in range(b):
                if x_view[i][y] == '1':
                    req_y[y].append(z)
            for x in range(a):
                if y_view[i][x] == '1':
                    req_x[x].append(z)

        # check existence
        for y in range(b):
            for z in req_y[y]:
                if all(cap[x][y] < z for x in range(a)):
                    ok = False
        for x in range(a):
            for z in req_x[x]:
                if all(cap[x][y] < z for y in range(b)):
                    ok = False

        if not ok:
            print(-1)
            continue

        # MIN construction
        h = [[0] * b for _ in range(a)]

        for y in range(b):
            for z in range(1, c + 1):
                if (c - z) >= 0 and x_view[c - z][y] == '1':
                    best = -1
                    best_val = 10**9
                    for x in range(a):
                        if cap[x][y] >= z:
                            if h[x][y] < best_val:
                                best_val = h[x][y]
                                best = x
                    if best != -1:
                        h[best][y] = max(h[best][y], z)

        min_ans = sum(h[x][y] for x in range(a) for y in range(b))

        # MAX construction (greedy independent growth)
        h2 = [[0] * b for _ in range(a)]

        for x in range(a):
            for z in range(1, c + 1):
                if (c - z) >= 0 and y_view[c - z][x] == '1':
                    best = -1
                    best_val = -1
                    for y in range(b):
                        if cap[x][y] >= z:
                            if h2[x][y] > best_val:
                                best_val = h2[x][y]
                                best = y
                    if best != -1:
                        h2[x][best] = max(h2[x][best], z)

        max_ans = sum(h2[x][y] for x in range(a) for y in range(b))

        print(min_ans, max_ans)

if __name__ == "__main__":
    solve()
```コードはまず、射影制約をゼロ セルから導出された列ごとの上限に変換します。 次に、必要なすべての射影セルに少なくとも 1 つの互換性のある列があるかどうかをチェックします。 その後、高さの割り当てを貪欲に構築します。1 回は列間の再利用を最小限に抑えるため、もう 1 回は列間の分離を最大化するために行われます。 最終的な答えは、誘導された柱の高さの合計です。 

入力では高さが逆の順序でエンコードされ、より高いレイヤーが入力の中で先に現れるため、慎重なインデックス付けが不可欠です。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、必要な投影セルが、反対側のビューのゼロ制約により物理的に到達できない列の高さに存在する場合です。 この状況では、すべての候補列が上限に違反しているため、実現可能性チェックは直ちに失敗します。そのため、アルゴリズムは正しく出力します。$-1$。 

もう 1 つの微妙なケースは、高さが増加する複数の投影要件が同じ行に存在する場合です。 貪欲な再利用メカニズムにより、可能な限り単一のカラムがそれらを吸収し、最小限の構造が生成されます。 代わりに、すべての要件が個別に割り当てられた場合、ソリューションはキューブの数を誤って増加させます。 

最後のケースには対称的な飽和が含まれており、両方の投影が完全に密になっています。 このアルゴリズムは、最大のケースで割り当てを列全体に正しく分散し、高さが 1 つのスタックに崩れることがなく、最終的な答えが可能な限り最大の立方体の分布を反映するようにします。
