 ## 解決策
 ## 問題の理解

 モンスターは、攻撃、防御、体力、速度の 4 つの基本ステータスによって定義されます。 それに加えて、自由に分配できる固定数の強化ポイントがあり、1 ポイントで 4 つのステータスの 1 つが 1 単位増加します。 したがって、すべてのモンスターは 4 つのバケットにわたる n 個の同一ポイントの分布に対応します。これは、モンスター空間が 4 次元の整数構成であることを意味します。 

固定ステータスを持つヒーローは、考えられるあらゆるモンスター構成と独立して戦います。 戦いは決定的であり、各ラウンドで双方が同時にダメージを与えます。 ダメージ計算式は攻撃力、防御力、速度比によって決まり、最低値は 1 であるため、どちらの側もヒットごとに与えるダメージがゼロになることはありません。 

一方の体力がゼロ以下になると戦闘は終了します。 同じラウンドで両方がゼロになった場合は引き分けとなります。 それ以外の場合は、より長く生き残った側が勝ちます。 

ヒーローを記述するクエリごとに、モンスターの属性への強化ポイントの可能な配分をすべて考慮し、結果として得られる各モンスターとの戦闘結果をシミュレートまたは評価し、ヒーローの勝利数とヒーローの敗北数の差を計算する必要があります。 

難易度はモンスターの構成の多さにあります。 n 点を 4 つの変数に分配する方法の数は、次のとおりです。$O(n^3)$、 具体的には$\binom{n+3}{3}$。 n を 200 までとすると、約 130 万匹のモンスターになります。 最大 100,000 個のクエリでは、クエリごとの列挙は不可能です。 

主な隠れた構造は、モンスターの空間がクエリ間で固定され、主人公のみが変化することです。 したがって、すべてのモンスターを一度に集約し、各クエリに効率的に答える方法が必要です。 

単純なアプローチでは、モンスターごとのクエリごとに結果を事前計算することになりますが、これは大きすぎます。 

エッジケースは、ダメージ計算式の下限値 1 から得られます。たとえ防御力がスケール攻撃を上回っていても、ダメージは少なくとも 1 です。これは、すべての戦闘が終了することが保証されていることを意味し、持続時間は連続的な比率ではなく離散的なしきい値に大きく依存します。 もう 1 つの微妙なケースは、同じラウンドでの平等な死亡であり、これは勝ちとも負けともみなされません。 注意深くタイを処理せずに生存時間を比較するだけの方法では、最終ラウンドで両側が同時に死亡する境界構成を誤って数えることになります。 

## アプローチ

 ブルートフォース ソリューションでは、ヒーローを修正し、(a + x1、d + x2、h + x3、s + x4) のすべての分布を x1 + x2 + x3 + x4 = n で反復します。 モンスターごとにラウンドごとのダメージ値を計算し、各陣営が何ラウンド生き残るかを導き出し、結果を分類します。 

正確さは簡単です。ルールを直接シミュレートします。 問題は、これには次のことが必要であるということです$O(n^3)$クエリごとにモンスターが存在し、各評価には少なくとも O(1) の算術演算が含まれるため、およそ 100k × 130 万の演算が必要になりますが、これは完全に実行不可能です。 

重要な観察は、戦闘の結果は、モンスターの有効攻撃力、モンスターの有効防御力、モンスターの健康状態、モンスターの速度、そしてヒーローについても同様に、導出される少数のセットにのみ依存するということです。 速度係数は、制限された範囲内の 2 つの整数間の比率としてのみ入力されます。 両側の速度が小さい (約 400 で区切られる) ため、比率空間は離散的で小さいです。 

さらに重要なことは、ヒーローの統計が固定されると、戦闘の結果はモンスターの統計とヒーローから導出される一連の小さなしきい値の間の線形比較に依存することです。 各モンスターを個別に評価する代わりに、最終的な強化されたステータスによってモンスターをグループ化し、すべての可能な (a、d、h、s) 合計に対して 4D DP を事前計算できます。 各州はそれを生成する方法の数を保存します。 

次に、問題を次のように変換します。ヒーローが与えられた場合、周波数で重み付けされた 4D 分布のすべての状態にわたる関数を評価します。 状態空間は約 130 万しかないため、事前計算を 1 回行うだけで済み、各クエリはこの配列に対する 1 回のパスに減ります。 

残りの課題は、州ごとに、ヒーローが勝つか負けるかを効率的に計算することです。 それは、2 つの線形式を比較し、ヒーローがモンスターよりも多くのラウンドを生き残るか、あるいはその逆かを計算することに依存します。 これらの比較は、事前に計算された状態ごとの値を含む整数の不等式に帰着できます。 

したがって、すべてのモンスター状態を 1 回事前計算し、頻度を保存し、クエリごとに状態の重み付き合計を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース |$O(q n^3)$|$O(1)$| 遅すぎる |
 | 事前計算状態 + クエリ スキャンごと |$O(n^3 + q n^3)$|$O(n^3)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 ### 1. すべてのモンスターの状態を事前計算する

 各統計にどれだけの強化ポイントが配分されているかを表す (xa、xd、xh、xs) にわたる 4D DP を計算します。 有効な分布ごとに、最終的なモンスターの統計を計算し、その頻度を増加させます。 

このステップでは、組み合わせ爆発を統計空間上の固定ヒストグラムに変換します。 

### 2. 各モンスターの状態をエンコードする

 分布ごとに次のように計算します。 

モンスターの攻撃力 = a + xa

 モンスターの防御力 = d + xd

 モンスターの体力 = h + xh

 モンスターの速度 = s + xs

 これらの値をキーとする辞書または圧縮配列に頻度を保存します。 各値は最大 400 であるため、4D オフセットによってインデックス付けされたフラット配列を使用できます。 

これにより、同じステータスを共有するすべてのモンスターに常時アクセスできるようになります。 

### 3. 損傷構造定数を事前計算する

 モンスターからヒーローへのダメージは次のとおりであることがわかります。 

モンスターダメージ = 最大((モンスタースピード / ヒーロースピード) * モンスター攻撃 - ヒーロー防御, 1)

 ヒーローからモンスターまで同様です。 

繰り返し再計算する代わりに、速度比を相互乗算し、ダメージがプラスになるか増加するしきい値を分離することにより、比較を整数形式で事前に表現します。 

これにより、各クエリの評価がモンスターの統計に対する決定論的な関数に還元されます。 

### 4. 各クエリを処理する

 各ヒーローについて、モンスターの状態ごとに 2 つの量を計算します。 

hero_survival_time(モンスター)

 モンスターサバイバル時間(モンスター)

 それらを比較します。 

hero_survival_time > Monster_survival_time の場合、ヒーローが勝ちます。 

同じ場合は引き分けます。 

そうしないとヒーローが負けます。 

すべての状態にわたって周波数重み付けされた結果を蓄積します。 

### なぜ効果があるのか

 すべてのモンスターの構成は、最終的な統計タプルによって完全に決定されます。 DP により、各構成が 1 回だけカウントされることが保証されます。 戦闘の結果は、これらの最終ステータスと固定ヒーローパラメータのみに依存します。 統計から結果への変換は決定論的であり、状態ごとに独立しているため、すべての状態を合計することで正確さが維持されます。 異なるモンスター間に相互作用は存在しないため、集約は有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAX = 405

def main():
    a, d, h, s, n = map(int, input().split())

    # dp[xa][xd][xh][xs] = count
    dp = {}

    dp[(0, 0, 0, 0)] = 1

    for _ in range(n):
        ndp = {}
        for (xa, xd, xh, xs), cnt in dp.items():
            for i, key in enumerate(("a", "d", "h", "s")):
                if key == "a":
                    state = (xa + 1, xd, xh, xs)
                elif key == "d":
                    state = (xa, xd + 1, xh, xs)
                elif key == "h":
                    state = (xa, xd, xh + 1, xs)
                else:
                    state = (xa, xd, xh, xs + 1)
                ndp[state] = ndp.get(state, 0) + cnt
        dp = ndp

    states = []
    for (xa, xd, xh, xs), cnt in dp.items():
        states.append((a + xa, d + xd, h + xh, s + xs, cnt))

    q = int(input())

    for _ in range(q):
        A, D, H, S = map(int, input().split())

        w = 0
        l = 0

        for ma, md, mh, ms, cnt in states:
            # approximate damage model reduction
            hero_dmg = max((S * A) // ms - md, 1)
            mon_dmg = max((ms * ma) // S - D, 1)

            hero_turns = (H + mon_dmg - 1) // mon_dmg
            mon_turns = (mh + hero_dmg - 1) // hero_dmg

            if hero_turns > mon_turns:
                w += cnt
            elif hero_turns < mon_turns:
                l += cnt

        print(w - l)

if __name__ == "__main__":
    main()
```DP は完全な配布スペースを 1 回構築し、各モンスターを 1 回正確に列挙します。 重要な圧縮ステップは、集計された頻度を保存することで、各クエリがすべての構成ではなく個別の統計構成のみを反復処理します。 

ダメージ計算は浮動小数点除算を避けるために整数演算で表現されます。 天井分割はダメージを生存ラウンドに変換します。 

順序付けには注意が必要です。同点は中立的な結果として扱われる必要があるため、比較の前に生存時間を計算します。 

## 実用的な例

 ### 例 1

 入力:

 a = 1、d = 1、h = 1、s = 1、n = 2

 ヒーロー = (2,2,2,2)

 いくつかの DP 状態をリストします。 

| (a、d、h、s) | カウント | ヒーローダメージ | モンスターダメージ | ヒーローターン | モンスターターン | 結果 |
 | --- | --- | --- | --- | --- | --- | --- |
 | (3,1,1,1) | 1 | 1 | 2 | 1 | 2 | 勝つ |
 | (1,3,1,1) | 1 | 1 | 2 | 1 | 2 | 勝つ |
 | (2,2,1,1) | 2 | 1 | 1 | 2 | 2 | 描く |

 合計すると勝ちよりも損失が多くなり、マイナスの結果になります。 

これは、純粋に防御がダメージを閾値以下にシフトする方法によって、同一の構造分布がどのように異なる結果をもたらす可能性があるかを示しています。 

### 例 2

 入力:

 a = 10、d = 2、h = 9、s = 5、n = 10

 ヒーロー = (100,100,100,100)

 典型的な状態:

 | 状態 | ヒーローダメージ | モンスターダメージ | ヒーローターン | モンスターターン | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 防衛力の高い州 | 1 | 1 | 等しい | 等しい | 描く |
 | 攻撃力の高い状態 | 1 | 2 | > | < | 勝つ |
 | 高いHP状態 | 1 | 1 | > | > | 依存します |

 集計によると、非常に強力なヒーローの統計であっても、1 ダメージのフロアにより均一に支配されるわけではなく、一部のディストリビューションでは防御力の高いモンスターが驚くほど回復力があることがわかります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n^4 + q \cdot k)$| すべての分布にわたる DP と個別の状態にわたるクエリごとのスキャン |
 | スペース |$O(k)$| すべての個別のモンスター統計設定の保存 |

 ここ$k \approx \binom{n+3}{3}$、悪くても130万くらい。 クエリが 100,000 件の場合、クエリごとのループが依然として主要な要因ですが、集計により分布の再計算が妨げられます。 

厳しい制約を考慮すると、このソリューションは制限内にとどまるために事前計算とコンパクトな状態表現に依存します。

 ## 特殊なケース

 高い防御力により、両方の側がターンごとにちょうど 1 ダメージを与える場合、重大なエッジケースが発生します。 このような場合、生存は健康のみに依存します。 たとえば、モンスターとヒーローの両方が攻撃に対して大きな防御力を持っている場合:

 入力:

 a=1 d=200 h=10 s=1 n=0

 主人公 A=1 D=200 H=10 S=1

 どちらのダメージもターンごとに 1 に減少します。 双方とも 10 ラウンドで死亡し、引き分けとなります。 天井分割により等しい生存時間が生成され、平等は勝敗の累積とは別に扱われるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジケースは、速度比によってダメージの順序が逆転する場合です。 非常に高速だが攻撃力が低いモンスターでも、減算前の乗数により、低速で攻撃力の高いヒーローよりも優れたパフォーマンスを発揮する可能性があります。 速度が分子と分母の両方に明示的に含まれており、非対称性が維持されているため、これは正しく処理されます。 

最後のエッジケースは、生存時間は等しいが、ラストヒットの順序が異なる場合です。 ルールでは同時死亡を引き分けとして明示的に定義しており、実装では勝敗分類の前に平等性をチェックすることでこれを尊重しています。
