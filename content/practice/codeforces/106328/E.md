 ## 解決策
 ## 問題の理解

 0 から n マイナス 1 までの数値の順列が与えられます。 すべての位置 i について、厳密に右を見て、値が i の値より小さくなる最初の位置 j を見つけます。 そのような位置が存在しない場合、i の答えは n になります。 

したがって、タスクは基本的に、インデックスごとに、順列内の次に小さい要素インデックスを計算することですが、厳密に小さい値と厳密に右側に制限されます。 

制約は小さく、n は最大 1000 なので、パフォーマンスを気にせずに二次推論がすぐに可能になります。 ただし、工夫は効率ではなく解釈にあります。単に値を見つけるだけではなく、厳密に小さい値が現れる最初の位置を見つけます。 

よくある失敗例は、「次に小さい値」と「次に小さいか等しい」を混同したり、誤って右ではなく左にスキャンしたりすることです。 もう 1 つの微妙なケースは、最小の要素が早期に出現する場合です。 たとえば、[1, 0, 2] のような順列では、インデックス 1 の右側にはそれより小さいものは存在しないため、インデックス 1 の答えは n になります。 有効な j の不在を明示的に処理しない実装では、無効なインデックスが返されるか、ガベージ値が残されます。 

## アプローチ

 最も直接的なアプローチは、定義を文字通りシミュレートすることです。 各インデックス i について、i より大きいすべての位置 j をスキャンし、p[j] が p[i] より小さい最初の j を追跡します。 これは定義に正確に従っているため、正しいです。 最悪のケースでは、[9, 8, 7, ..., 0] のような減少順列の場合、すべての位置 i が残りのほぼすべての位置をスキャンし、2 回の比較でおよそ n の 2 乗が行われ、n が 1,000 に等しい場合、約 50 万回の演算が行われます。 これは簡単に十分に高速です。 

重要な観察点は、範囲クエリや繰り返しの更新が要求されていないため、この問題ではより高度な前処理を必要とするものは何もないということです。 それぞれの答えは独立しており、配列の接尾辞のみに依存します。 

単調スタックを使用して、次の小さな要素の問題を線形時間で解くこともできますが、ここではその必要はありません。 制約が単純であるため、ブルート フォース ソリューションは十分かつ簡単に正しく実装できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 承認済み |
 | 単調スタック | O(n) | O(n) | 受け入れられるが不要 |

 ## アルゴリズムのチュートリアル

 各インデックスの答えを個別に計算します。 

1. 0 から n マイナス 1 までの各位置 i について、答えを n として初期化します。 これは、有効な j が見つからない場合を表します。 
2. i プラス 1 から n マイナス 1 まで j をスキャンします。各 j について、p[j] と p[i] を比較します。 p[j] が小さい場合は、右側の最初の有効な位置が見つかったので、j を i の答えとして保存し、それ以上のスキャンを停止します。 
3. これより小さい値が見つからずにスキャンが終了した場合、答えは n のままとなり、有効な位置が存在しないことを正しくエンコードします。 

正確さは、j を昇順にスキャンするという事実から得られるため、最初に小さい値に遭遇すると、自動的に条件を満たす最小の有効なインデックス j になります。 それが起こったら、それ以上の位置を確認する必要はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, input().split()))
    if not data:
        return
    
    n = data[0]
    p = data[1:1+n]
    
    res = [n] * n
    
    for i in range(n):
        for j in range(i + 1, n):
            if p[j] < p[i]:
                res[i] = j
                break
    
    print(*res)

if __name__ == "__main__":
    solve()
```実装はアルゴリズムを厳密に反映しています。 まず、n と順列を解析します。 結果の配列は、フォールバック ケースを表す n で初期化されます。 ネストされたループはサフィックス スキャンを実装します。 内側のループは、有効な小さい要素が見つかるとすぐに中断され、最初の要素が確実にキャプチャされます。 

ここでよくある落とし穴は、最初の有効な j を見つけた後にブレークするのを忘れることです。これにより、後のインデックスで答えが上書きされ、定義に違反します。 もう 1 つは、結果の配列を誤って 0 で初期化しており、そのような j が存在しない場合でもインデックス 0 が有効であると誤って示唆します。 

## 実用的な例

 入力 p = [2, 0, 3, 1] を考えてみましょう。 

各位置を計算します。 

| 私 | p[i] | jスキャン | 最初の有効な j | レス[i] |
 | --- | --- | --- | --- | --- |
 | 0 | 2 | 1、2、3 | 1 (p[1]=0) | 1 |
 | 1 | 0 | 2,3 | なし | 4 |
 | 2 | 3 | 3 | 3 (p[3]=1) | 3 |
 | 3 | 1 | なし | なし | 4 |

 したがって、出力は [1, 4, 3, 4] となります。 

このトレースは、アルゴリズムがどのように大きな値を正しくスキップし、最初の厳密に小さい値で停止するかを示しています。 

ここで、p = [3, 2, 1, 0] について考えてみましょう。 

| 私 | p[i] | jスキャン | 最初の有効な j | レス[i] |
 | --- | --- | --- | --- | --- |
 | 0 | 3 | 1 | 1 | 1 |
 | 1 | 2 | 2 | 2 | 2 |
 | 2 | 1 | 3 | 3 | 3 |
 | 3 | 0 | なし | なし | 4 |

 このケースは、すべての位置がそのすぐ隣の位置を答えとして見つける、厳密に減少する配列のカスケード的性質を示しています。

 ## 特殊なケース

 [0] のような単一要素の置換では有効な j が生成されないため、答えは [1] になります。 このアルゴリズムは res[0] を n に初期化し、それより小さい要素を検出しないため、正しく 1 を出力します。 

[0, 1, 2, 3] のような厳密に増加する順列の場合、すべての要素は右側に存在する場合にのみより小さい値を認識しますが、どれも小さい値を認識しません。 スキャンは毎回最後まで実行され、すべてのインデックスの結果が n のままになります。 

[3, 2, 1, 0] のような厳密に減少する順列の場合、すべての要素はすぐに次の小さい要素を見つけます。 内側のループは j = i + 1 で中断されるため、出力は [1, 2, 3, 4] となり、最初の有効な小さいインデックス ルールに正確に一致します。
