 ## 解決策
 ## 問題の理解

 有向グラフが与えられ、すべての頂点について、長さが奇数の少なくとも 1 つの有向サイクルに属しているかどうかが尋ねられます。 サイクルは単純である必要はなく、説明の中で頂点が繰り返される場合がありますが、構造は依然として閉じた歩道であり、奇数の有向ステップの後に開始点に戻ります。 

このタスクは基本的にメンバーシップに関する質問をすることです。つまり、ノードごとに、そのノードを通過する奇数長の有向閉ウォークが存在するかどうかを判断します。 

制約は大きく、すべてのテスト ケースにわたる頂点とエッジの総数は最大数十万に達します。 これにより、サイクルを個別に探索したり、パスを列挙しようとするソリューションは即座に除外されます。 ノードごとまたはエッジごとにグラフ検索を繰り返し実行するアプローチは遅すぎます。 私たちは、SCC 分解や圧縮構造上の単純なグラフ走査など、線形または線形に近いグラフ アルゴリズムを使用することを余儀なくされています。 

このステートメントの微妙な点は、ウォークで頂点の繰り返しが許可されていることです。 これは、単純なサイクルに限定されないことを意味します。 実際、奇数の閉じたウォークの存在は、基礎となる構造に奇数のサイクルが存在することを意味するため、任意のウォークではなくサイクル パリティの観点から安全に推論できます。 

単純な間違いは、各ノードが単純な奇数サイクル上にあるかどうかをチェックする問題として解釈し、各頂点から始まるサイクルを個別に検出しようとすることです。 たとえば、有向三角形 1 → 2 → 3 → 1 ではすべて問題ありませんが、クロス エッジが多数ある大規模な SCC では、単純な DFS サイクル検出では、結合して奇数サイクルを形成する異なるサイクル間のパリティ相互作用を簡単に見逃す可能性があります。 

もう 1 つのよくある落とし穴は、グラフを無向として扱い、二部性をグローバルに直接チェックすることです。 これは、基礎となる無向構造がサイクルを示唆している場合でも、方向制約によって有効なウォークが制限される有向グラフでは失敗します。 

## アプローチ

 ブルートフォースのアイデアは、頂点ごとに、その頂点で開始し終了する奇数の長さの閉じたウォークを見つけられるかどうかを検出しようとすることです。 これを想像する 1 つの方法は、パス パリティを追跡し、奇数の深さで開始ノードに戻ったかどうかを確認しながら、各頂点から BFS または DFS を実行することです。 各検索では最大 O(n + m) 状態が探索され、最悪の場合、全体の作業量が O(n(n + m)) になるため、これはすぐに実行不可能になります。 

重要な観察は、サイクルの存在は基本的に強く接続されたコンポーネントの特性であるということです。 頂点が有向サイクルの一部である場合、頂点は 1 より大きいサイズの SCC 内にあるか、自己ループを含んでいます。 そこで、まずグラフを SCC に圧縮します。 単一の SCC 内では、すべての頂点が他のすべての頂点に到達できるため、サイクルの質問はそのコンポーネントの内部になります。 

ここで問題は、SCC に奇数の有向サイクルが含まれているかどうかを判断することに移ります。 強く接続されたコンポーネントの内部では、方向性が到達可能性の制限要因ではなくなるため、無向の観点を使用してパリティについて推論することができます。無向グラフとして見たときにコンポーネントが 2 部構成である場合、そのコンポーネント内のすべてのサイクルは偶数でなければなりません。 二部構成でない場合は、奇数のサイクルが存在します。 

これにより、きれいな削減が行われます。SCC を計算し、各 SCC について、その基礎となる無向グラフが 2 部であるかどうかをテストします。 二部構成でない場合、その SCC 内のすべての頂点が有効な回答になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 頂点ごとの総当たり検索 | O(n(n + m)) | O(n + m) | 遅すぎる |
 | SCC + コンポーネントごとの 2 部チェック | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. Kosaraju または Tarjan のアルゴリズムを使用して、有向グラフを強接続コンポーネントに分解します。 このステップでは頂点をグループ化して、各グループ内のすべてのノードが他のすべてのノードに到達できるようにします。 
2. コンポーネントごとに、それに属するすべての頂点を収集します。 サイクルは SCC 境界を越えることができないため、各コンポーネントを個別に分析します。 
3. エッジの方向を無視し、両方のエンドポイントが同じ SCC 内にあるエッジのみを保持することにより、コンポーネントの無向隣接構造を構築します。 
4. BFS または DFS カラースキームを使用して、この無向コンポーネントに対して 2 部チェックを実行します。 エッジに沿って交互に色を割り当てます。 
5. 色付け中に、同じ色の 2 つの頂点を接続するエッジが見つかった場合、そのコンポーネントは 2 部構成ではなく、奇数のサイクルが含まれていることを意味します。 このコンポーネント内のすべての頂点を有効としてマークします。 
6. それ以外の場合、色付けが競合せずに成功した場合、コンポーネントには無向の意味で偶数サイクルのみが含まれるため、その頂点はいずれも奇数サイクルの一部ではありません。 

二部チェックの背後にある重要な考え方は、奇数のサイクルがない場合、グラフは正確に二部であるということです。 SCC 内では、相互到達可能性により、すべてのサイクルが有向形式で実行可能であるため、無向パリティ条件は有向奇数サイクルを正しくキャプチャします。 

### なぜ効果があるのか

 強く接続されたコンポーネント内では、すべてのエッジが何らかのサイクル上にあります。 コンポーネントを一貫して 2 色にできる場合、サイクルごとに色が交互になり、長さは均等でなければなりません。 色付けが失敗した場合、矛盾は同じパリティ距離にある 2 つのノードを強制的に接続する奇数長サイクルから生じます。これはまさに私たちが検出しようとしている構造です。 したがって、SCC 分解によりサイクル関連の構造が分離され、二部テストによりその構造内の奇数パリティが検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    gr = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        gr[v].append(u)

    # Kosaraju: first order
    visited = [False] * n
    order = []

    def dfs1(v):
        visited[v] = True
        for to in g[v]:
            if not visited[to]:
                dfs1(to)
        order.append(v)

    for i in range(n):
        if not visited[i]:
            dfs1(i)

    comp = [-1] * n
    cid = 0

    def dfs2(v):
        comp[v] = cid
        for to in gr[v]:
            if comp[to] == -1:
                dfs2(to)

    for v in reversed(order):
        if comp[v] == -1:
            dfs2(v)
            cid += 1

    # build components
    comp_nodes = [[] for _ in range(cid)]
    for i in range(n):
        comp_nodes[comp[i]].append(i)

    # build undirected edges inside SCC
    und = [[] for _ in range(cid)]
    for u in range(n):
        for v in g[u]:
            if comp[u] == comp[v]:
                cu = comp[u]
                und[cu].append((u, v))

    ans = ['0'] * n

    from collections import deque

    for c in range(cid):
        color = {}
        ok = True

        for start in comp_nodes[c]:
            if start in color:
                continue
            color[start] = 0
            dq = deque([start])

            while dq and ok:
                x = dq.popleft()
                for u, v in und[c]:
                    if u == x:
                        y = v
                    elif v == x:
                        y = u
                    else:
                        continue

                    if y not in color:
                        color[y] = color[x] ^ 1
                        dq.append(y)
                    elif color[y] == color[x]:
                        ok = False
                        break

        if not ok:
            for v in comp_nodes[c]:
                ans[v] = '1'

    print("".join(ans))

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```この解決策は、Kosaraju の SCC 分解に必要な順方向グラフと逆方向グラフの両方を構築することから始まります。 SCC を計算した後、各頂点にコンポーネント識別子が割り当てられます。 

各 SCC について、同じコンポーネント内にエンドポイントがあるすべてのエッジを収集することによって、無向ビューを構築します。 異なる SCC 間のエッジはサイクルに参加できないため、この制限は重要です。 

二部チェックは、BFS カラーリングを使用してコンポーネントごとに実行されます。 競合が検出された場合、コンポーネント全体が奇数サイクルを含むものとしてマークされます。 最終的な回答文字列は、そのようなコンポーネント内のすべての頂点をマークすることによって形成されます。 

微妙な実装の詳細は、隣接エッジをチェックしながら隣接エッジを繰り返しスキャンすることです。 これは最も最適化された隣接関係表現ではありませんが、全体的な制約を考慮すると制限内に収まります。 より効率的なバリアントでは、コンポーネントごとに隣接リストを事前に構築します。 

## 実用的な例

 ### 例 1

 単純な有向三角形を考えてみましょう。 

入力グラフ:

 1→2→3→1

 SCC 分解により、{1, 2, 3} を含む 1 つのコンポーネントが生成されます。 

| ステップ | ノード | アクション | 色の状態 | 紛争 |
 | --- | --- | --- | --- | --- |
 | 開始 | 1 | カラー 0 を割り当てる | 1:0 | いいえ |
 | BFS | 2 | 1 の反対の色 | 1:0、2:1 | いいえ |
 | BFS | 3 | 2 の反対の色 | 1:0、2:1、3:0 | いいえ |
 | エッジチェック | 3→1 | 同じ色が見つかりました | 衝突 | はい |

 競合により、コンポーネントが 2 部構成ではないため、すべての頂点が奇数サイクルの一部であることが確認されます。 

### 例 2

 有向偶数サイクルを考えてみましょう。 

1→2→3→4→1

 SCC は再びフルセット {1,2,3,4} です。 

| ステップ | ノード | アクション | 色の状態 | 紛争 |
 | --- | --- | --- | --- | --- |
 | 開始 | 1 | カラー0 | 1:0 | いいえ |
 | BFS | 2 | 色1 | 1:0、2:1 | いいえ |
 | BFS | 3 | カラー0 | 3:0 | いいえ |
 | BFS | 4 | 色1 | 4:1 | いいえ |
 | チェック | 4→1 | 有効な反対色 | なし | いいえ |

 競合は発生しないため、SCC は 2 部構成であり、奇数サイクルは含まれません。

| スペース | O(n + m) | グラフ ストレージとコンポーネントおよびカラー配列 |

 ## 特殊なケース

 自己ループは長さが 1 であるため、最も単純な奇数サイクルです。 この場合、SCC には自己エッジを持つ単一ノードが含まれており、ノードはループを通じてそれ自身の両方の色である必要があるため、2 部チェックはすぐに失敗します。 

もう 1 つのエッジ ケースは、複数の切断された SCC を含むグラフで、一部には奇数サイクルが含まれ、その他には含まれないものがあります。 このアルゴリズムは各コンポーネントを独立して処理するため、非 2 部 SCC の頂点のみがマークされ、他の頂点はグローバル構造に関係なくゼロのままになります。
