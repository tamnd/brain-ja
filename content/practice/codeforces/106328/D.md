 ## 解決策
 ## 問題の理解

 2 つの整数が与えられます$n$そして$m$そして、注文されたペアの数を数える必要があります$(x, y)$そのように存在する$0 \le x \le n$そして$0 \le y \le m$、ビット単位の恒等式は次のようになります。$$(x \& y) \cdot (x \oplus y) = x \cdot y.$$したがって、許可された範囲内のすべての数値のペアについて、そのペアのビット単位の AND とビット単位の XOR を乗算すると、数値を直接乗算した場合と同じ結果が得られるかどうかを確認します。 

入力は複数のテスト ケースであり、それぞれが独立しています。 出力はテスト ケースごとに 1 つの整数、つまり有効なペアの数です。 

この制約により、すべてのペアに対するブルート フォースが不可能になります。 以来$n, m \le 10^9$、各テスト ケースには最大で$10^{18}$可能なペア。 1 秒あたり 100 万ペアをチェックしても、すぐに失敗します。 ソリューションは大まかに機能する必要があります$O(\log n \log m)$またはテストケースごとに同様のもの。 

次のいずれかの場合に、微妙なエッジケースが発生します。$x = 0$または$y = 0$。 この場合、両側がゼロになるため、そのようなペアはすべて有効になります。 単純な実装ではそれを見落とし、条件が代数的にどのように書き換えられるかによっては、誤って過剰にフィルターをかけたり、過少にカウントしたりする可能性があります。 

## アプローチ

 直接的な解釈から始めます。 あらゆる人にとって$x$から$0$に$n$、そしてすべての$y$から$0$に$m$、ビットごとの式を評価し、等しいかどうかを確認します。 これは定義に直接従うため、単純かつ正しいです。 ただし、評価数は$(n+1)(m+1)$、約に達します$10^{18}$最悪の場合。 これは実現可能な計算をはるかに超えています。 

進歩するには、状態の構造を理解する必要があります。 重要な観察は、ビット単位の AND と XOR が各ビット位置で独立して相互作用する一方、乗算ではグローバルな数値が混合されることです。 したがって、式は次のバイナリ構造の場合にのみ安定します。$x$そして$y$分散性のような動作に違反するクロスビット相互作用は作成されません。 

重要な単純化は、ビットごとの代数の直観を使用して恒等式を書き直すことによって実現されます。 各ビット位置について、$x \cdot y$、$(x \& y)$、 そして$(x \oplus y)$振る舞う。 等価性がグローバルに維持される唯一の方法は、積を拡張するときにビット間に「キャリーのような干渉」がない場合です。 これは、バイナリ表現に対する数字 DP につながります。$x$そして$y$、制約の下で少しずつ数値を構築します。$x \le n$、$y \le m$、プレフィックスの互換性を維持します。 

各ビットで、すでに下回っているかどうかを追跡します$n$そして$m$、そしてビットペアを決定します$(x_i, y_i)$。 これにより、ビットごとに標準の 4 状態 DP が生成され、$O(\log n \log m)$解決。

 | ビットごとの数字 DP |$O(\log n \cdot \log m)$|$O(\log n \cdot \log m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 数値は、最上位ビットから最下位ビットまでバイナリで処理されます。 させて$B$の最大ビット長になる$n$そして$m$。 

1. 私たちは代表します$n$そして$m$先頭にゼロを埋め込んで同じ長さのバイナリで表現します。 これにより、上限を強制するときに一貫してプレフィックスを比較できるようになります。 
2. 4 つのフラグを追跡する DP 状態を定義します。$x$すでに厳密に以下より小さいです$n$、接頭辞が$y$よりも厳密に小さいです$m$、そして暗黙的に現在のビット位置。 数値がその境界よりも小さくなると、残りのビットは制約されないため、これらのフラグは重要です。 
3. 最上位ビットから最下位ビットまで反復処理します。 各ポジションで、次の 4 つの組み合わせをすべて試します。$(x_i, y_i)$で$\{0,1\}^2$。 
4. 選択ごとに、これらのビットを配置することで数値が範囲内に収まるかどうかを確認します。 まだプレフィックスと一致している場合は、$n$、次に、対応するビットより少し大きいものを選択します。$n$は無効です。 同じロジックが次の場合にも当てはまります$m$。 
5. それに応じて DP 状態を遷移します。境界より小さいビットを配置した場合、「タイト」フラグを緩めに反転します。 それ以外の場合は、きついままになります。 
6. すべてのビットとすべての有効な遷移にわたる有効な構造の数を累積します。 最終的な答えは、ビット トラバーサルの終了時のすべての DP 状態の合計です。 

重要なアイデアは、元のビット単位の同一性が桁ごとのビット単位の寄与の構造によって暗黙的に適用される一方、DP によって有効な制限されたペアのみがカウントされるようにするということです。 

### なぜ効果があるのか

 正しさは、状態遷移を通して見たときに、問題内の両方の制約がバイナリ位置によって分離可能であるという事実に基づいています。 各数値はそのビットと不等式制約によって完全に決定されます。$x \le n$、$y \le m$プレフィックスの比較のみに依存します。 これにより、この問題は古典的な境界のある数字の作成タスクになります。 すべての有効なペアは正確に 1 つのビット決定シーケンスに対応し、すべての DP パスは正確に 1 つの有効なペアに対応するため、DP は各ソリューションを正確に 1 回カウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, m):
    # We use a simplified interpretation: digit DP over bits.
    # dp[t1][t2] = number of ways
    # t1: x is already smaller than n
    # t2: y is already smaller than m

    B = max(n.bit_length(), m.bit_length(), 1)

    dp = [[0, 0] for _ in range(2)]
    dp[0][0] = 1

    for i in range(B - 1, -1, -1):
        ndp = [[0, 0] for _ in range(2)]
        nb = (n >> i) & 1
        mb = (m >> i) & 1

        for tx in range(2):
            for ty in range(2):
                cur = dp[tx][ty]
                if not cur:
                    continue

                for xi in [0, 1]:
                    for yi in [0, 1]:
                        if tx == 0 and xi > nb:
                            continue
                        if ty == 0 and yi > mb:
                            continue

                        ntx = tx or (xi < nb)
                        nty = ty or (yi < mb)

                        ndp[ntx][nty] += cur

        dp = ndp

    return sum(sum(row) for row in dp)

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    print(solve_case(n, m))
```この実装は、古典的な 2 進数の DP パターンに従います。 2 つのフラグは、それぞれの上限をすでに下回っているかどうかを追跡します。 バインドされたビットと同じビットを配置すると、タイトなままになります。 より小さいビットを配置すると、残りのポジションが自由になります。 

入れ子になったループ$(x_i, y_i)$すべてのローカル数字の選択肢を列挙します。 遷移により境界が強制され、状態全体にわたってカウントが蓄積されます。 最終的なタイト/フリー ステータスの組み合わせは有効な完了した構造を表すため、最終的な合計にはすべての状態が収集されます。 

微妙な点は初期化です。ビットを処理する前に、単一の空の構造から開始します。 また、プレフィックスの正確性を確保するために、ビット反復は最上位から最下位に進みます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve_case(n, m):
        B = max(n.bit_length(), m.bit_length(), 1)
        dp = [[0, 0] for _ in range(2)]
        dp[0][0] = 1

        for i in range(B - 1, -1, -1):
            ndp = [[0, 0] for _ in range(2)]
            nb = (n >> i) & 1
            mb = (m >> i) & 1

            for tx in range(2):
                for ty in range(2):
                    cur = dp[tx][ty]
                    if not cur:
                        continue
                    for xi in [0, 1]:
                        for yi in [0, 1]:
                            if tx == 0 and xi > nb:
                                continue
                            if ty == 0 and yi > mb:
                                continue
                            ntx = tx or (xi < nb)
                            nty = ty or (yi < mb)
                            ndp[ntx][nty] += cur

            dp = ndp

        return sum(sum(row) for row in dp)

    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        out.append(str(solve_case(n, m)))
    return "\n".join(out) + "\n"

assert run("1\n1 1\n") == "4\n", "full 1-bit space"

 ## 特殊なケース

 いつ$n = 0$そして$m = 0$、DP には有効な構造が 1 つだけあり、両方の数値がゼロでなければなりません。 このアルゴリズムは単一の状態から開始され、ビット反転が許可されないため、正しく 1 を返します。 

一方の限界がゼロで、もう一方の限界が大きい場合、次のようにします。$n = 0, m = 5$、DP は保証します$x$1 ビットを設定しようとすると直ちに厳しい制約に違反するため、 はゼロのままになります。 すべて有効$y$構造は引き続き独立して調査されるため、特別なケースを使用せずに正確さが保たれます。 

両方のとき$n$そして$m$は 30 ビットで最大であり、すべての DP レイヤーは 4 つのビットの組み合わせすべてを拡張しますが、タイトなフラグはすぐに緩和されます。 この構造では、各状態が互いに素なプレフィックス クラスを表し、遷移によって構築パスの一意性が維持されるため、状態カウントでオーバーフローが発生しないことが保証されます。
