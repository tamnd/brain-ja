 ## 問題の理解

 頂点 1 にルートを持つルート付きツリーが与えられています。各頂点にはルートを除く親があり、深さは標準的な方法でルートからの距離として定義されます。 

We consider ordered pairs of vertices$(u, v)$3つの制限があります。 初め、$u \neq v$。 2番、$u \neq 1$したがって、ルートが移動された頂点として選択されることはありません。 三番目、$u$～の先祖であってはなりません$v$、これは次のことを言うのと同じです$v$のサブツリー内にありません$u$。 

そのようなペアについては、構造変更を実行します。$u$親から接続してから接続します$u$直下$v$。 これにより、サブツリー全体を移動し、それ自体の外側の有効な位置に再接続するため、構造がツリーに保たれます。 

この変更後、ツリーの深さを再計算し、$f(u, v)$根元からの最大深さとして。 

タスクは次の合計を計算することです$f(u, v)$すべての有効なペアにわたって。 

制約が非常に厳しいため、すべてのペアを反復処理することは不可能です。 と$n$まで$2 \cdot 10^5$テスト ケース全体で、二次列挙には次のオーダーが必要になります。$10^{10}$これは実行可能な限界をはるかに超えています。 たとえ$O(n \log n)$ソリューションは、サブツリー操作における隠れた 2 次の動作を避けるために慎重に設計する必要があります。 

単純な試みは、時間だけでなく、より微妙な方法で失敗する傾向もあります。 BFS または DFS を使用してエッジを再接続するたびにツリーの深さを再計算しようとすると、$O(n)$ペアごとの再計算はタイムアウトに直接つながります。 

不用意な推論を打ち破る構造的なエッジケースが 2 つあります。 

ツリーがチェーンの場合、ほぼすべてのペアが$(u, v)$次の場合を除いて有効です$v$上にある$u$。 ノード間の独立性を前提としたり、サブツリーの除外を無視したソリューションでは、有効なノードのカウントが誤ります。$v$。 

ツリーがルート 1 のスターである場合、ルート以外のすべてのノードはリーフになります。 リーフを別のリーフの下に移動しても深さは何も変わりませんが、サブツリーの高さが増加することを常に想定する単純な式では、寄与分が大幅に過大評価される可能性があります。 

これらのケースでは、サブツリーの移動によってどのようにツリーの一部だけが変更され、他の部分はそのまま残されるのかを正確に推論する必要があります。 

## アプローチ

 直接的な総当たり戦略により、すべての有効なペアが選択されます$(u, v)$、エッジのスワップを実行し、ツリーの深さを最初から再計算します。 これは簡単です。ツリーを変更した後、ルートから DFS を実行し、最大距離を計算します。 文字通り定義をシミュレートするため、正確さがすぐにわかります。 

問題はコストです。 がある$O(n^2)$最悪の場合のペアであり、各再計算は次のようになります。$O(n)$、につながる$O(n^3)$。 再計算を最適化したとしても$O(n)$増分更新によるペアごとの合計作業量は、依然として最終的には$O(n^2)$、これは大きすぎます$2 \cdot 10^5$。 

重要な観察は、この操作がサブツリー内の距離にのみ影響するということです。$u$。 他のすべてのノードは、ルートからの元の距離を維持します。 したがって、新しいツリーの深さは、古いグローバルの深さと、サブツリーが再接続された後の移動されたサブツリー内の最も深いノードとの間の競合によって決定されます。$v$。 

と表すと$D$元のツリーの深さとして、$d[v]$の深さとして$v$、 そして$h[u]$ノードの高さとして$u$のサブツリー、次に移動後、サブツリー内の最も深いノード$u$になる$d[v] + 1 + h[u]$。 それ以外のものはせいぜい深さに留まります$D$。 したがって、結果として得られる深さは、$$f(u, v) = \max(D, d[v] + 1 + h[u]).$$問題は、すべての有効なペアについてこの式を合計することに帰着します。 という制限は、$v$のサブツリー内にあってはなりません$u$どちらにのみ影響します$v$は、式自体ではなく、合計に含まれます。 

残りの課題は、それぞれの$u$、すべてを合計しなければなりません$v$サブツリーの外側にありますが、貢献度は次のいずれかによって異なります。$d[v]$によって決定されるしきい値を上回るか下回るか$h[u]$。 これにより、グローバルと各サブツリー内の両方で、深さによってノードがカウントされることになります。 

私たちは深度の頻度分布をグローバルおよびサブツリーごとに維持します。 これにより、それぞれについて答えることができます$u$、有効な数$v$しきい値を上回るか下回る深さ、およびそれらの深さの合計を持ちます。

 ## アルゴリズムのチュートリアル

 ツリーのルートを 1 に設定し、DFS を使用してすべてのノードの深さとサブツリーの高さを計算します。 

グローバル最大深度も計算します$D$、この値は操作後のベースラインの深さになるためです。 

次に、深度にわたるグローバル頻度テーブルを構築し、各深度に存在するノードの数とそれらの深さの合計を保存します。 

次に各ノードを処理します$u$ツリー戦略で DFS ベースの DSU を使用し、各ノードがそのサブツリー内の深さの頻度テーブルを維持します。 

1. DFS を実行して深さとサブツリーのサイズを計算し、サブツリーの高さも計算します。 高さは、葉までの最大距離としてボトムアップで計算されます。 
2. 各深度に出現するノードの数をカウントする各サブツリーの頻度マップを維持します。 
3. DFS 中に、重度から軽度へのマージ戦略を使用して、子の周波数マップを親にマージし、全体の複雑さが線形対数のままになるようにします。 
4. ノードのサブツリー周波数マップが完成したら$u$が完了したら、深さにわたるプレフィックス バージョンを計算して、「このセット内の深さ ≤ T を持つノードの数」をすぐに答えられるようにします。 
5.ノードの場合$u$、しきい値を計算します$T = D - 1 - h[u]$。 これは取り付け部分のカットオフです$u$下$v$元の深さよりも悪くならなくなります。 
6. カウントと深さ合計の両方について、グローバル頻度からサブツリー頻度を減算することにより、サブツリーの補数を構築します。 
7. スプリット有効$v$2 つのグループに分類: 深さ ≤ のもの$T$、答えが貢献する場所$D$、深さのあるもの >$T$、答えが貢献する場所$d[v] + 1 + h[u]$。 
8. グローバル構造とサブツリー構造の両方のプレフィックス合計を使用して寄与を蓄積し、その結果をノードに追加します$u$最終的な答えに導きます。 

正確さは、すべての有効なペアが 1 回、可能な限りすべて分類されるという事実に基づいています。$v$深さだけに依存する単一の決定論的な公式に従って寄与し、$h[u]$。 

不変条件は、現時点でノードを計算することです。$u$、そのサブツリー内の深さの正確な頻度分布と固定されたグローバル分布が得られます。 すべての有効な$v$はサブツリー内またはサブツリーの外側のいずれかであり、外側のノードのみが考慮されます。 しきい値による分割により、それぞれの$v$重複することなく正しい形式の貢献が割り当てられています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    parent = [0] * (n + 1)
    depth = [0] * (n + 1)
    order = []
    
    # iterative DFS to avoid recursion depth issues
    stack = [1]
    parent[1] = -1
    depth[1] = 0

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            depth[v] = depth[u] + 1
            stack.append(v)

    children = [[] for _ in range(n + 1)]
    for v in range(2, n + 1):
        children[parent[v]].append(v)

    # subtree size order reversed for DP
    subtree_order = order[::-1]

    height = [0] * (n + 1)
    for u in subtree_order:
        for v in children[u]:
            height[u] = max(height[u], height[v] + 1)

    D = max(depth)

    MAXD = D
    global_cnt = [0] * (MAXD + 2)
    global_sum = [0] * (MAXD + 2)

    for i in range(1, n + 1):
        global_cnt[depth[i]] += 1
        global_sum[depth[i]] += depth[i]

    for i in range(1, MAXD + 1):
        global_cnt[i] += global_cnt[i - 1]
        global_sum[i] += global_sum[i - 1]

    ans = 0

    def dfs(u):
        nonlocal ans
        cnt = [0] * (MAXD + 2)
        sm = [0] * (MAXD + 2)

        cnt[depth[u]] = 1
        sm[depth[u]] = depth[u]

        for v in children[u]:
            c2, s2 = dfs(v)
            if len(c2) > len(cnt):
                cnt, c2 = c2, cnt
                sm, s2 = s2, sm
            for i in range(MAXD + 1):
                cnt[i] += c2[i]
                sm[i] += s2[i]

        # prefix already global; build subtree prefix
        cnt_sub = cnt
        sum_sub = sm

        T = D - 1 - height[u]

        # compute S_u = global - subtree
        # prefix helper inline
        cnt_le = 0
        sum_le = 0
        cnt_sub_le = 0
        sum_sub_le = 0

        if T >= 0:
            cnt_le = global_cnt[T]
            sum_le = global_sum[T]
            cnt_sub_le = cnt_sub[T]
            sum_sub_le = sum_sub[T]

        cnt_gt = (n - cnt_sub[depth[u]]) - cnt_le
        sum_gt = (global_sum[MAXD] - sum_sub[MAXD]) - sum_le

        cnt_s = (n - cnt_sub[depth[u]])
        sum_s = (global_sum[MAXD] - sum_sub[MAXD])

        ans += cnt_le * D + sum_gt + cnt_gt * (1 + height[u])

        return cnt, sm

    dfs(1)
    print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```DFS はサブツリーの深さの分布をボトムアップで構築します。 各ノードは、その子からマージされたサブツリー内の深さにわたる周波数配列を維持します。 グローバル配列は、すべてのノードのプレフィックス数と合計を提供します。 しきい値$T$寄与度を 2 つのケースに分割し、最終的な式ではサブツリーの外側のノードからの寄与度を集計します。 

微妙な点は、サブツリー周波数配列を異なるブランチ間で誤って再利用してはいけないということです。そのため、複雑さを制御するためにマージはスワップを使用して慎重に行われます。 

## 実用的な例

 3 つのノードからなる単純なチェーンを考えてみましょう。$1 - 2 - 3$ルートは 1 です。 

私たちには深みがある$d[1]=0$、$d[2]=1$、$d[3]=2$。 ノード 2 の高さは 1、ノード 3 の高さは 0 です。グローバルな深さは次のとおりです。$D=2$。 

のために$u=2$、 有効$v$だけです$v=1$。 2 を 1 の下に移動しても構造的には何も起こらないため、深さは 2 のままです。 

| あなた | v | 身長[u] | d[v] | しきい値 | 貢献 |
 | --- | --- | --- | --- | --- | --- |
 | 2 | 1 | 1 | 0 | 0 | 2 |

 これにより、アタッチメントによって何も増加しない場合、式が元の深さまで正しく減少することが確認されます。 

次に、ノードが 1 をルートとするスターを考えます。$1$に接続されています$2,3,4$。 すべてのリーフの高さは 0、深さは 1 ですが、$D=1$。 

どのペアでも$u$葉と$v$別の葉、添付$u$下$v$長さ 2 のチェーンが生成されるため、深さは 2 になります。 

| あなた | v | 身長[u] | d[v] | しきい値 | 貢献 |
 | --- | --- | --- | --- | --- | --- |
 | 2 | 3 | 0 | 1 | 0 | 2 |
 | 2 | 4 | 0 | 1 | 0 | 2 |

 これは、式が 2 つの葉の連鎖によって引き起こされる増加を一貫して捉えていることを示しています。

 ## 特殊なケース

 チェーン形状のツリーの場合、ルートを除くすべてのノードのサブツリーの高さが高くなります。 アルゴリズムは高いしきい値を正確に割り当てます。$v$「深さの増加」カテゴリに分類されます。 サブツリー頻度構造により、上位のノードが確実に$u$は有効対象外となります$v$。 

星型ツリーの場合、すべてのサブツリーの高さは 0 です。しきい値はノード間で同一になり、すべての有効なペアが同じ定数式に寄与します。 サブツリー頻度を減算すると、次のことが保証されます。$v=u$そして無効なペアが補集合に含まれることはありません。 

1 つのブランチが深く、他のブランチが浅い偏ったツリーの場合でも、DSU マージによって各ノードのサブツリーの深さの分布が正しいことが保証され、しきい値分割によって深い接続ポイントと浅い接続ポイントが正しく分離されます。
