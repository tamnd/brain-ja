 ## 解決策
 ## 問題の理解

 1 から最大値までの一連の個別の整数が与えられます。`m`。 毎秒、ランダムな要素を削除します`x`セットから。 取り外したあとの場合は、`x+1`範囲内にあり、まだセットに含まれていない場合は、追加します`x+1`。 この質問では、セットが空になるまでの予想秒数を尋ねます。 

入力は、初期セットのサイズ、許可される最大値、およびソートされた順序での要素自体を提供します。 出力は、1,000,000,007 を法とする分数の形式で予想される秒数である必要があり、これには逆剰余の計算が必要です。 

と`n`そして`m`500 までは、ブルート フォース シミュレーションは実行できません。 すべての可能な状態を明示的に保存するだけでもコストがかかりすぎます。`2^500`サブセット。 課題は、確率的な遷移を考慮しながら、進化する状態を効率的に捕捉することにあります。 

エッジケースには、最大の要素のみを含むセットが含まれます`m`。 これを削除しても、新しい要素は生成されません。 例えば、`n=1, m=5, S=[5]`1 回削除したらすぐに終了する必要があります。 もう 1 つの微妙なケースは、連続した要素です。 セットの場合`[2,3]`そして私たちは削除します`2`、追加します`3`そこになかったら戻ってきますが、`3`はすでに存在します。 常に追加する不注意な実装`x+1`要素を二重にカウントし、予想される時間を過大評価する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる可能性を再帰的にシミュレートしようとします。 のサブセットごとに、`[1..m]`、予想されるステップ数を再帰的に計算できます。 これは原理的には正しいですが、扱いが困難です。 と`m=500`、サブセットの数は天文学的です (`2^500`）。 ビットマスクによる状態のメモ化ですら、メモリの制限をはるかに超えています。 

重要な洞察は、プロセスが正確なセット自体ではなく、**数値間のギャップ**に依存しているということです。 セットを並べ替えてみましょう`dp[x]`すべての要素が取得されるまでの予想秒数です。`x`に`m`がなくなった場合は、動的計画法を使用してこれらの値を計算できます。 各ステップで数値を削除すると効果が得られます`1`2 番目に新しいセットの期待値を加えたもので、次の数値が欠落している場合は同じままか 1 ずつ増加します。 から働くことで`m`1 まで下げると、状態の再計算を回避し、問題を次のように削減します。`O(m^2)`計算。 

もう 1 つの重要な観察は、期待の直線性です。 すべての削除シーケンスの確率を追跡する必要はありません。 次の数値までの距離に基づいて、各要素の期待される寄与を個別に計算できます。 これにより、DP の繰り返しを書くことができます。`dp[i]`に依存します`dp[j]`のために`j>i`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m * n) | O(2^m) | 遅すぎる |
 | ギャップによる DP / 期待値の直線性 | O(m^2) | O(m^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. セットをサイズのブール配列として表現します。`m+1`番号が存在するかどうかをすばやく確認します。 これにより、O(1) ルックアップが可能になります。`x+1`が存在します。 
2. DP テーブルの初期化`dp[l][r]`間隔内のすべての要素を空にするために必要な予想されるステップ数を表します`[l..r]`外側の数字がすべて無関係な場合。 
3. 埋める`dp[l][r]`より小さな間隔からより大きな間隔まで。 インターバル用`[l..r]`、区間内の各要素は確率で削除できます`1/(r-l+1)`。 
4. 各候補要素について`x`で`[l..r]`を削除した場合の期待値を計算します。`x`。 削除中`x`常に追加します`1`。 もし`x+1`が行方不明であり、`x+1 <= r`、それを将来のステップの間隔に効果的に含めます。 それ以外の場合、間隔は次のように減少します。`[l..r]`マイナス`x`。 
5.全員の貢献度を合計する`x`で`[l..r]`要素の数で割って、間隔の平均期待値を取得します。`[l..r]`。 
6. 戻る`dp[min(S)][max(S)]`式には割り算が含まれるため、答えはモジュラー逆算で調整されます。 

機能する理由: DP テーブルは、間隔内の要素のすべての可能な削除順序を正確にキャプチャします。 期待値の線形性を使用すると、各要素の期待される寄与を、次に選択する確率で重み付けして独立して扱うことができます。 繰り返しにより、間隔サイズの増加に応じてすべての依存関係が確実に解決されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

def modinv(a):
    return pow(a, MOD-2, MOD)

def solve():
    n, m = map(int, input().split())
    S = list(map(int, input().split()))
    exists = [0]*(m+2)
    for x in S:
        exists[x] = 1

    dp = [0]*(m+2)
    for i in range(m, 0, -1):
        if exists[i] == 0:
            dp[i] = 0
        else:
            total = 1  # current removal
            count = 0
            for j in range(i, m+1):
                if exists[j]:
                    count += 1
                    if j+1 <= m and not exists[j+1]:
                        exists[j+1] = 1
                        total += dp[j+1]
                        exists[j+1] = 0
                    else:
                        total += dp[j+1]
            dp[i] = total * modinv(count) % MOD

    print(dp[S[0]] % MOD)

solve()
```コードは、入力を読み取り、数値が存在するかどうかを O(1) チェックするための存在配列を作成することから始まります。 の`modinv`関数は、フェルマーの小定理を使用してモジュラー逆行列を計算します。 DP テーブル`dp[i]`要素から始まる予想されるステップ数を格納します`i`。 から反復します`m`まで`1`すべての依存関係が計算されていることを確認します。 ループオーバー`j`可能な削除ごとに予想されるステップを累積します。 の一時的な変更`exists`配列ハンドル`x+1`永続的な突然変異を伴わない追加の場合。 ついに、`dp[S[0]]`答えのモジュロとして出力されます`10^9+7`。

def run(inp: str) -> str:

        solve()
    return out.getvalue().strip()
