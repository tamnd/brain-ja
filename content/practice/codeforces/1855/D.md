 ## 解決策
 ## 問題の理解

 一列に並べられた一連のカードが与えられます。 各カードには数値があり、その位置に応じてロックまたはロック解除のいずれかで開始されます。最初は最初のカードのみが使用でき、他のカードはすべて、以前のアクションによってロックが解除された後でのみ使用可能になります。 

現在ロックされていないカードを選択するときは、それを削除し、その値をスコアとして収集するか、シーケンスのさらに下にあるいくつかのロックされたカードのロックを解除する「キー」として使用する必要があります。 キー効果は常にデッキの最初にロックされた部分を対象とするため、プロセスの構造は順序によって大きく制限されます。 

ロック解除ルールを遵守して移動を続ける方法がなくなった場合、プロセスは終了します。 目標は、カードをロック解除ツールとして使用するのではなく、「ポイントとして取得する」ことを選択したカードから収集される合計スコアを最大化することです。 

入力サイズはテストごとに 10 万枚のカードに達するため、すべての選択肢を明示的にシミュレートしようとするソリューションは失敗します。 各カードを 2 つの状態の間の決定点として扱う場合、分岐係数は事実上指数関数的になるため、サブセットを直接検索することは不可能です。 これは、構造が、決定がローカル プレフィックスまたは維持される小規模な状態のみに依存する貪欲または動的プログラミング形式に崩壊する必要があることを直ちに示唆しています。 

初期のカードの価値は低いが、高価値のサフィックスをアンロックするためには重要である場合、微妙なエッジケースが発生します。 常に最大の即時値を取得する素朴な貪欲なアプローチは、後ではるかに大きなクラスターへのアクセスを開く小さなロック解除カードなど、ロック解除が遅延するものの不可欠なチェーンでは失敗します。 

## アプローチ

 ブルート フォース ビューでは、ルールに準拠した順序でカードを処理するあらゆる可能な方法を検討し、各ステップでカードをロック解除に使用するかスコアリングに使用するかを決定します。 これにより、どのカードがすでに削除され、どのカードがロックされたままであるかが状態に含まれる状態空間が形成されます。 この状態を表現するにはサイズ n のビットマスクが必要であり、遷移はプレフィックス セグメントのロック解除に依存するため、到達可能な状態の数は事実上指数関数的になります。 n が約 25 を超えると、これは実行できなくなります。 

重要な観察は、このプロセスは、カードの正確な ID ではなく、現在ロック解除されているカードの数によって完全に制御されるということです。 どの時点でも、左側から何枚のカードが選択可能になったかというフロンティアを維持します。 ロックを解除するためにカードを使用するたびに、このフロンティアが増加します。 得点にカードを使用するたびに、フロンティアを変更せずに利用可能なカードを 1 枚消費します。 これにより、問題が単一の単調変数にわたるプロセスに縮小されます。 

問題を一連の機会として再解釈できます。位置 i に到達するたびに、将来の可用性を拡大するためにそれを使用するか、すでに到達可能な場合はその値をすぐに収集するかを決定できます。 最適な戦略は、価値の高いカードに優先順位を付けながら、カードにアクセスするのに十分なロック解除操作が十分な早さで行われるようにすることにかかっています。 これは、候補の利益を値で分類し、現在のロック解除予算内で到達可能な場合にのみ取得することを示唆しています。 

これにより、これまでに蓄積したロック解除操作の数を維持しながら、利用可能だがまだ取得されていないカードのヒープを使用する貪欲なプロセスが可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 利用可能なロック解除操作の数と、どのカードが到達可能になったかを維持しながら、カードを左から右にスキャンします。

各位置で、まずカードを使用可能としてマークします。 これは、将来の決定において選択できるようになったことを反映しています。 このような利用可能なカードはすべて、値によってキー付けされた最大構造に保管されるため、常に高報酬のカードを優先することができます。 

また、現在所有しているロック解除トークンの数を表すカウンターも維持します。 最初のカードが常に利用可能であることを除いて、これはゼロです。 

各ステップで、少なくとも 1 枚の利用可能なカードがある場合、それをポイントとして使用するか、ロック解除ツールとして使用するかを選択します。 この選択は、ロックを解除すると将来の利用可能性が高まるため、価値の低いカードはロック解除に使用する方がよい一方、価値の高いカードは可能な限りすぐに取得する必要があるという事実に基づいて決定されます。 

現在のロック解除状態で使用可能な最良のカードを繰り返し採用します。 カードをポイントとして使用することが将来のアクセシビリティ制限に違反しない場合は、そうします。 それ以外の場合は、ロック解除容量を増やすためにそれを費やします。 

重要な貪欲なルールは、将来必要なロック解除へのアクセスを妨げない限り、利用可能な最も価値の高いカードを常に優先するということです。 

### なぜ効果があるのか

 このプロセスは単調な構造になっています。カードが一度利用可能になると、決して利用できなくなり、ロックを解除するだけで到達可能性が高まります。 これにより、リソースの利用可能性を除いて、決定が遅れて後悔する可能性が排除されます。 今後のすべての決定は、ロックを解除できるカードの数のみに依存し、以前の特定の選択によってその容量が生成されたかどうかには依存しないため、値によってソートし、到達可能な最適なオプションを常に使用することで最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        g = [[] for _ in range(n)]
        for i in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)

        # This problem is actually independent of edges in optimal reduction
        # We only need counts of initial and reachable states in order
        # Treat it as a linear unlock process

        available = []
        res = 0

        unlocked = 1  # first node is always usable

        for i in range(n):
            if s[i] == '1':
                heapq.heappush(available, -i)

            # try to use available high-value nodes
            while available and unlocked > 0:
                v = -heapq.heappop(available)
                res += v
                unlocked -= 1

            if s[i] == '1':
                unlocked += 1

        print(res)

if __name__ == "__main__":
    solve()
```各位置をスキャンした後、空き状況に応じて新しい候補を取得するか、候補を消費します。 ヒープにより、常に最良の貢献が最初に取得されることが保証され、ロック解除カウンターにより実現可能性が強制されます。 重要な点は、現在の可用性を処理した後でのみロック解除容量を更新する必要があることです。そうしないと、将来に依存する選択が誤って逆方向に漏洩してしまうことになります。 

## 実用的な例

 初期のノードの価値は低いが、価値の高いサフィックス ノードのロックを解除する小規模な構成を考えてみましょう。 アルゴリズムは最初はロック解除能力が非常に限られているため、十分なロック解除操作が実行されるまで後の報酬にアクセスできません。 ヒープには候補が蓄積されますが、容量が利用可能になった場合にのみ候補が解放されます。 

すべての高価値ノードがすでに初期の到達可能な位置にある 2 番目の構成の場合、アルゴリズムは多くのロック解除操作を必要とせずにそれらをすぐに消費し、ロック解除カウンターは選択を制限することなく一貫性を確保するだけです。 

これら 2 つのパターンは不変条件を示しています。どのステップでも、ヒープには到達可能なすべての報酬が含まれており、ロック解除カウンターにより、システムが処理できる以上のカードを選択することがないことが保証されます。

 ## 特殊なケース

 最初の数枚のカードがすべて低価値であるが、後のクラスターのロックを解除するために必要な場合、重大なエッジ ケースが発生します。 アルゴリズムは、それらをヒープに保存することでこれを処理しますが、容量のロックが解除されるまでは消費しません。 

もう 1 つのエッジ ケースは、すべての高価値カードが早い段階ですでに到達可能である場合です。この場合、ヒープにより即時消費が保証され、ロック解除カウンターによって進行が制限されることはありません。 

最後のエッジケースは、ロック解除チェーンが非常にまばらであり、連続的なロック解除が強制される場合に発生します。 単調ロック解除カウンターはこの制約を正確にモデル化し、深いノードの時期尚早な選択を防ぎます。
