 ## 解決策
 ## 問題の理解

 正の整数を扱うように求められます$n$連続する最長の範囲の正の整数を見つけます$[l, r]$この区間内の各数値が分割されるように$n$。 つまり、すべての整数に対して$i$間$l$そして$r$、$n \bmod i = 0$。 出力は、この範囲内の整数の数です。つまり、$r - l + 1$。 

入力は最大で構成されます$10^4$テスト ケース、それぞれが与える$n$まで$10^{18}$。 大きな値$n$すべての約数を反復処理したり、すべての可能な間隔を順番にテストしたりする素朴な解決策は直ちに除外されます。 膨大な数を効率的に処理するアプローチが必要です。 

次の場合、微妙なエッジケースが発生します。$n = 1$。 約数は 1 だけなので、間隔は次のようになります。$[1, 1]$サイズは 1 です。同様に、次の場合$n$が素数である場合、有効な間隔は次のとおりです。$[1, 1]$そして$[n, n]$; 数値が大きくなると割り算がどのように減少するかを考慮せずに間隔を延長しようとする素朴な試みのほとんどは、過大なカウントを引き起こします。 

明らかではない課題は、非常に大きな数の場合、単純に約数を列挙する余裕がないことです。 すべての約数を生成せずに、最長の連続する約数間隔を特定する戦略が必要です。 

## アプローチ

 ブルートフォースアプローチは、次のすべての約数を生成することから始まります。$n$。 すべての約数をソートしたら、それらをスキャンして、連続する各約数がちょうど 1 だけ異なる、最長の連続部分列を探します。これが機能するのは、すべての有効な間隔が、分割する連続した整数で構成されている必要があるためです。$n$。 

ただし、次の数までのすべての約数を生成すると、$10^{18}$遅すぎます。 数字$n$近く$10^{18}$およそ最大まで持つことができます$10^6$最悪の場合は約数を計算し、それらを繰り返し処理します。$10^4$テストケースは法外なものになります。 因数分解でも$n$高価になる可能性があります。 

重要な洞察は、連続する約数の最大間隔は次から始まる必要があるということです。$n // k$いくつかの小さなもののために$k$より大きな約数は疎であり、小さな約数は密であるためです。 たとえば、すぐ下の数字は、$n / 2$または$n / 3$多くの場合、連続する約数の小さなクラスターを形成します。 全部試してみることで$k$まで$\sqrt{n}$（または少し大きい、など）$10^6$）を使用すると、区間開始点の候補を効率的に列挙できます。 次に、連続する整数が分割されるまでの間隔の長さを確認します。$n$。 これにより、問題はすべての約数にわたる反復から、はるかに小さい潜在的な間隔の始まりのセットにわたる反復に軽減されます。 

ブルートフォースアプローチは正しいですが、遅すぎます。 最適化されたアプローチは、連続する約数は次の商の近くにしか現れないという観察を活用しています。$n$小さな整数で区切ることで、最大間隔の開始点の管理可能な数を確認できます。

 | 最適化済み (n//k、k ≤ 10^6 をチェック) | O(10^6 * log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、次の内容を読んでください。$n$。 
3. 変数を初期化する`best`少なくとも間隔 [1, 1] は常に有効であるため、1 に設定されます。 
4. 整数の反復処理$k = 1$に$10^6$。 それぞれについて$k$、区間の開始点を考慮します。$l = n // k - k + 1$。 この公式は、連続する約数が近くに集まる必要があるという観察から生まれました。$n // k$。 
5. もし$l \le 0$、この候補をスキップします。 
6.初期化`length`を 0 まで増分チェックします。$n \bmod (l + i) = 0$のために$i = 0, 1, 2, …$失敗するまで。 連続する数字が何個割られるかを数えます (n`.
 7.アップデート`best`この長さが現在を超える場合`best`。 
8. すべてを繰り返した後$k$、印刷`best`現在のテストケースの場合。 

機能する理由: 連続する約数の各クラスターは近くに表示される必要があります。$n / k$いくつかの小さなもののために$k$。 すべてを繰り返すことで$k$まで$10^6$、すべての妥当な間隔がテストされることを保証します。 間隔は割り算に対して直接チェックされるため、有効なシーケンスが失われることはなく、長さは正しく計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_divisor_interval(n):
    best = 1
    for k in range(1, 10**6 + 1):
        l = n // k - k + 1
        if l <= 0:
            continue
        length = 0
        while l + length <= n and n % (l + length) == 0:
            length += 1
        best = max(best, length)
    return best

t = int(input())
for _ in range(t):
    n = int(input())
    print(max_divisor_interval(n))
```まず、入力を効率的に読み取ることから始めます。`sys.stdin.readline`。 機能`max_divisor_interval`潜在的な開始点をそれぞれチェックします`l`式から導き出される$l = n // k - k + 1$。 内側の while ループは、連続する整数が何回除算されるかをカウントします。$n$、間隔のサイズを直接与えます。 使用する`best = max(best, length)`最長の間隔を確実に追跡します。 境界条件`l <= 0`1 より前から始まる無効な間隔を回避します。
