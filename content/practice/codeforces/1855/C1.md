 ## 解決策
 ## 問題の理解

 配列内の 2 つの位置を繰り返し選択し、1 つの位置の値を別の位置に加算することができます。 ソース要素は使用時に消費または変更されないため、操作はインデックス間での再利用可能な「値の転送」のように動作します。 

目標は、スワップによって配列をソートすることではなく、最大 50 回のそのような加算の後、最終的な配列が単調で非減少になるように値を再形成することです。 値は負、正、ゼロのいずれかになる可能性があるため、要素を直接順序付けするのではなく、加算的な更新のみを使用して要素の大きさを制御することが困難です。 

この制約により、構造は非常に小さくなります。 各テストには最大 20 個の要素があり、各要素はマイナス 20 から 20 の間です。 これは、最適化や検索ではなく構築を強く示唆しています。 どのソリューションでも、テスト ケースごとに 50 操作という固定上限内に収まっている限り、操作数において 2 次または緩やかな 3 次の動作を実現できます。 

主な微妙な点は、単純な「違反をローカルで修正する」アプローチでは操作の制限を簡単に超えてしまう可能性があるという事実にあります。 たとえば、値が変動する場合、隣接する反転を 1 つずつ繰り返し修正すると、大量のステップが必要になる可能性があります。 もう 1 つの落とし穴は、各操作がグローバル構造に寄与することを保証せずに、貪欲に値をバブルさせようとすることです。 このようなアプローチは、値の符号が交互になると停滞する可能性があります。 

正しい戦略では、正確な初期配置とは無関係に、一定数のフェーズでグローバルな単調構造を作成する必要があります。 

## アプローチ

 ブルートフォース的な考え方は、反転を直接修復しようとするでしょう。 配列をスキャンし、ペアが満足するたびに$a_i > a_{i+1}$、慎重に選択した値を追加することで削減を試みます。 ローカル修正によって以前の位置が破壊される可能性があり、繰り返されるパスが 50 回の操作以内に収束するという保証はないため、これはすぐに不安定になります。 最悪の場合、値が正の状態と負の状態の間で変動し、無制限の修復サイクルが発生します。 

重要な観察は、隣接する操作や値の保存に制限されていないということです。 再利用可能な「影響力」のソースとして任意のインデックスを選択し、その値を配列全体にプッシュできます。 これは、他のすべてのエントリを 1 ステップで制御するのに十分な大きさの支配的なピボット要素を構築することを示唆しています。 

このようなピボットが存在すると、そのピボットを基準にして配列全体の符号を 1 回のパスで均一化できます。 その後、プレフィックスまたはサフィックスの累積によって単調性を強制できるため、配列をソートされた構造に変換することが容易になります。 

重要な構造的洞察は、すべての数値が負でない場合、プレフィックスの合計により非減少シーケンスが自動的に生成されるということです。 対称的に、すべての数値が非正の場合、接尾辞の累積では非減少シーケンスも生成されます。これは、負に増加する部分和が右から左に伝播されるときに順序付けが依然として考慮されるためです。 

したがって、問題は 2 つのフェーズに分かれます。まず、すべての要素をゼロの片側に強制的に配置し、次に順序を伝播します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ローカル反転修正 | O(操作) ですが、最悪の場合は制限がありません | お(1) | 遅すぎる |
 | ピボット記号の正規化 + 接頭辞/接尾辞の構築 | O(n) オペレーション | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 単一のピボットインデックスを選択します$p$、配列内の最大絶対値を持つ要素の位置。 

1.特定する$p$そのような$|a_p|$はすべての要素の中で最大です。 これにより、$a_p$大きさにおいて他のすべての値を支配します。 
2. もし$a_p \ge 0$、すべての要素が非負になるように強制します。 それぞれについて$i \ne p$、ワンオペレーションを実行します$a_i := a_i + a_p$。 の優位性$a_p$可能な限り小さい値であっても保証します$a_i = -a_p$この操作の後、 はゼロになります。 
3. もし$a_p < 0$代わりに、すべての要素が非正になるように強制します。 改めてそれぞれに$i \ne p$、私たちは実行します$a_i := a_i + a_p$。 以来$a_p$最も負の値、任意の正の要素$a_i \le |a_p|$1 回追加すると非正になります。 

この時点で、配列は 2 つの対称的なケースに分割されます。 

1. すべての要素が負でない場合、プレフィックス累積を使用して非減少シーケンスを構築します。 それぞれについて$i$から$2$に$n$、私たちは実行します$a_i := a_i + a_{i-1}$。 非負のプレフィックスを追加しても値を減らすことができないため、各ステップでは順序が維持され、以前の増加も前方に伝播されます。 
2. すべての要素が正でない場合、シーケンスは右から左に構築されます。 それぞれについて$i$から$n-1$まで$1$、私たちは実行します$a_i := a_i + a_{i+1}$。 各演算により、より多くの負の質量が左に押し出され、両方のオペランドが正ではないため、不等式は$a_i \le a_{i+1}$各ステップの後も有効なままです。 

### なぜ効果があるのか

 フェーズ 1 以降の不変条件は、すべての要素が完全にゼロの片側に位置し、すべての要素の大きさがピボットによって制限されることです。 これにより、配列全体の符号の一貫性を反転するには、ピボットを 1 回加算するだけで十分であることが保証されます。 

フェーズ 2 では、不変条件は、固定符号を持つシーケンスに対して累積和を繰り返し適用することです。 非負の場合、各要素は増加する接頭辞の合計になるため、接頭辞の合計は単調性を保ちます。 非正の場合、各要素は縮小する接尾辞の合計になり、より多くの負の累積は常に後の要素以下になるため、接尾辞の合計は単調性を維持します。 

この構築では、すべての操作が局所的な不一致を修復するのではなく、グローバルな順序付けの方向を強化するだけであるため、以前の構造への復帰が回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    p = 0
    for i in range(n):
        if abs(a[i]) > abs(a[p]):
            p = i

    ops = []

    if a[p] >= 0:
        for i in range(n):
            if i != p:
                ops.append((i + 1, p + 1))
                a[i] += a[p]

        for i in range(1, n):
            ops.append((i + 1, i))
            a[i] += a[i - 1]

    else:
        for i in range(n):
            if i != p:
                ops.append((i + 1, p + 1))
                a[i] += a[p]

        for i in range(n - 2, -1, -1):
            ops.append((i + 1, i + 2))
            a[i] += a[i + 1]

    print(len(ops))
    for i, j in ops:
        print(i, j)
```実装は 2 フェーズ構造に直接従います。 最初のループでは、絶対値によって支配的なピボットを選択します。 最初の構築ループは、非ピボット要素ごとに 1 つの操作を正確に適用し、均一な符号制御を保証します。 2 番目のフェーズでは、ピボット符号に応じてプレフィックス伝播とサフィックス伝播が切り替わります。 この問題では、コードが 0 から始まる配列で動作する一方で、1 から始まるインデックスが使用されるため、インデックス処理がここでの off-by-one エラーの主な原因となります。 

## 実用的な例

 ### 例:`[2, 1]`ピボットを選択します`2`インデックス 1 にあります。正であるため、最初に非負であることを確認しますが、配列はすでに非負であるため、変更は必要ありません。 次に、プレフィックス伝播を適用します。 

| ステップ | 配列状態 | 操作 |
 | --- | --- | --- |
 | 開始 | [2, 1] | なし |
 | 接頭辞 i=2 | [2、3] | a2 += a1 |

 プレフィックスの合計が順序を累積と一致させるため、配列はすぐに非減少になります。 

これは、単一の支配的なポジティブ ピボットによって問題が単純な累積プロセスにどのように還元されるかを示しています。 

＃＃＃ 例：`[3, 10, -20, 5]`ピボットは`-20`(最大の絶対値)。 負であるため、最初にすべての値を非正にプッシュします。 

| ステップ | 配列状態 | 操作 |
 | --- | --- | --- |
 | 開始 | [3、10、-20、5] | なし |
 | i=1 | [-17、10、-20、5] | a1 += a3 |
 | i=2 | [-17、-10、-20、5] | a2 += a3 |
 | i=4 | [-17、-10、-20、-15] | a4 += a3 |

 これで、すべての要素が非正になります。 サフィックス蓄積を行います。 

| ステップ | 配列状態 | 操作 |
 | --- | --- | --- |
 | i=3 | [-17、-10、-35、-15] | a3 += a4 |
 | i=2 | [-17、-45、-35、-15] | a2 += a3 |
 | i=1 | [-62、-45、-35、-15] | a1 += a2 |

 最終的な配列は減少しません。 

このトレースは、非正の配列を操作するときにサフィックスの方向が重要である理由を強調しています。累積方向は符号構造と一致する必要があります。

| スペース | O(1) おまけ | ストア操作リストのみ |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out_lines = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        p = 0
        for i in range(n):
            if abs(a[i]) > abs(a[p]):
                p = i

        ops = []

        if a[p] >= 0:
            for i in range(n):
                if i != p:
                    ops.append((i + 1, p + 1))
                    a[i] += a[p]
            for i in range(1, n):
                ops.append((i + 1, i))
                a[i] += a[i - 1]
        else:
            for i in range(n):
                if i != p:
                    ops.append((i + 1, p + 1))
                    a[i] += a[p]
            for i in range(n - 2, -1, -1):
                ops.append((i + 1, i + 2))
                a[i] += a[i + 1]

        out_lines.append(str(len(ops)))
        for i, j in ops:
            out_lines.append(f"{i} {j}")

    return "\n".join(out_lines)

# minimal
assert run("1\n1\n5\n") == "0"

# already sorted
assert run("1\n3\n1 2 3\n").split()[0] <= "4"

# all negative
assert run("1\n3\n-1 -2 -3\n") != ""

# mixed
assert run("1\n4\n2 -1 3 -2\n") != ""

 | 混合標識 | 有効な構造 | ピボット正規化の正確性 |
