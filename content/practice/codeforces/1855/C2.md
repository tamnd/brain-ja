 ## 解決策
 ## 問題の理解

 正、負、またはゼロの整数の配列が与えられます。タスクは、この配列を非減少シーケンスに変換することです。 許可される唯一の操作は、2 つのインデックスを選択することです$i$そして$j$そして値を追加します$a_j$に$a_i$。 目標は、長さ 20 までの配列に対して最大 31 回の演算でこれを達成することです。演算数を最小限に抑える必要はなく、配列が最終的に減少しないことを確認するだけです。 

この制約は、考えられるすべての操作を総当たりで探索することは、たとえ$n=20$なぜなら、一連の操作の数が指数関数的に増加するからです。 ただし、小さいものは、$n$これにより、建設的な推論が可能になり、すべてのシーケンスを試すのではなく、目標に向かって確実に進む操作を選択できるようになります。 単純な実装は、配列に大きな負の数値またはゼロが含まれている場合、または最大値が配列の末尾にない場合に失敗する可能性があります。これは、隣接する要素を順番に追加するだけで一部のエントリが負または減少する可能性があるためです。 

エッジ ケースには、すでに減少していない配列、すべての要素が負である配列、または大きな正と負の数値が混在している配列が含まれます。 たとえば、入力`[1, -5, 2]`この問題は、最初に最大の正の数を利用して負の値を相殺することなく、近傍を順次追加することによって解決することはできません。 

## アプローチ

 ブルートフォース手法では、考えられるすべてのペアが試行されます。$i, j$各ステップで、配列が減少しなくなるまで加算のシーケンスを追跡します。 このアプローチは、値の加算では常に整数演算が保持されるため、原理的には機能しますが、非常に遅すぎます。$n=20$最大 31 の操作があります。$20^{62}$シーケンスを考慮する必要がありますが、これは実行不可能です。 

重要な洞察は、配列全体の符号パターンに応じて最大または最小の要素に焦点を当てることです。 配列に大きな正の数値が含まれている場合、最大の数値を他のエントリに繰り返し加算することで、すべての要素が左から右に減少していないことをすぐに確認できます。 すべての要素が負の場合、最小の (最も負の) 要素を使用すると、同様に逆方向に機能します。 基本的に、単一の要素を「ピボット」として利用して、配列の残りの部分を順番に動かします。 

これにより、問題は、最大要素または最小要素のいずれかを選択し、他のすべての要素に正しい方向で繰り返し加算を実行するという問題に軽減されます。 次に、非減少特性を保証するために、1 回のパスで配列全体を伝播します。 この戦略では、最大 31 回の演算で常に配列を非減少にできることが保証されます。$n \le 20$というのは、数値を繰り返し 2 倍にすることで、最終的にはすべての要素がその前の要素を確実に超えるからです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n^2)^k) | O(n + k) | 遅すぎる |
 | 建設的なピボットの追加 | O(n^2) | O(n + k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列内の最大絶対値を持つ要素を特定します。 これはピボット要素です。これを他の要素に追加すると、配列を非降順にシフトする効果が最も大きくなります。 
2. ピボットが正の場合、この最大値を小さな要素に繰り返し加算することで、すべての要素を大きくするか等しくすることを計画します。 ピボットが負の場合、減少を防ぐために逆の順序で他の要素に追加しますが、実際には、与えられた制約に対しては正の最大値を使用するだけで十分です。 
3. インデックスごとにピボットを配列全体に伝播します。$i$1から$n$、 もし$a[i]$未満です$a[i-1]$、加算を実行します$a[i] := a[i] + a[i-1]$。 必要に応じて繰り返します。 ピボットにより、各追加が確実に進行するため、最大でも前の要素の下に要素が残ることはありません。$n$要素ごとの追加。 
4. すべての操作を実行された順序で出力します。 各操作は、どの要素にどの要素を追加するかを示すインデックスのペアにすぎません。 
5. すべての演算後、配列が減少していないことを確認します。 構造上、これは保証されています。 

機能する理由: このアルゴリズムは、各操作の後、現在のインデックスまでのすべての要素が少なくともその前の要素と同じ大きさであるという不変条件を維持します。 ピボットを使用すると、追加によって要素が必要な順序に厳密に移動することが保証されます。 加算の繰り返しは次の制限を受けます。$n^2$、これは小さな配列に許可される 31 の演算の範囲内です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ops = []

        # find index of maximum absolute element
        max_val = max(a)
        max_idx = a.index(max_val)

        # step 1: propagate the max value rightwards to enforce non-decreasing order
        for i in range(n):
            while a[i] < a[i-1] if i > 0 else False:
                a[i] += a[i-1]
                ops.append((i+1, i))  # convert 0-index to 1-index

        # alternate simple approach using max element addition
        for i in range(n):
            if i != max_idx:
                ops.append((i+1, max_idx+1))
                a[i] += a[max_idx]

        print(len(ops))
        for x, y in ops:
            print(x, y)

if __name__ == "__main__":
    solve()
```最初の部分は入力を読み取り、操作リストを初期化します。 最大要素をピボットとして特定し、加算を実行して他のすべての要素を非減少シーケンスに近づけます。 各操作は出力用に 1 インデックス形式で追加されます。 この解決策は、配列のサイズが小さいことと、正確性を確保するために 31 回の演算という制約に依存しています。 重要な点は、任意の要素にピボットを追加すると、その値が正しい方向に厳密に増加し、回帰が防止されることです。 

## 実用的な例

 サンプル入力`[2, 1]`:

 | ステップ | 配列 | 操作 |
 | --- | --- | --- |
 | 0 | [2, 1] | - |
 | 1 | [2、3] | a1 を a2 に追加する |

 ここで、最初の要素を 2 番目の要素に追加すると、配列は非減少になります。 必要な操作は 1 つだけです。 

サンプル入力`[1, 2, -10, 3]`:

 | ステップ | 配列 | 操作 |
 | --- | --- | --- |
 | 0 | [1、2、-10、3] | - |
 | 1 | [1、2、-7、3] | a4 を a3 に追加する |
 | 2 | [1、2、-4、3] | a4 を a3 に追加する |
 | 3 | [1、2、-1、3] | a4 を a3 に追加する |
 | 4 | [1、2、2、3] | a3 を a3 に追加する |

 これらの手順の後、配列は減少しません。 これは、ピボットの追加を繰り返して負の値を処理する方法を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | 各要素は、要素ごとに最大 n 個のピボットまたは先行要素からの追加を必要とする場合があります。 
| スペース | O(n + k) | 長さ n の配列と長さ ≤31 の演算リスト |

 与えられた$n \le 20$および 31 の操作があるため、このソリューションは時間とメモリの制限内に問題なく収まります。

 ## 特殊なケース

 のような配列の場合`[0, -1, 1]`、ピボットは 1 です。2 番目の要素に 1 を追加すると、-1 から 0 になり、さらに 1 になります。配列は次のようになります。`[0, 0, 1]`そして最後に`[0, 1, 1]`、ピボットの追加を繰り返すと最初の負のエントリが修正されることを示しています。 これにより、アルゴリズムが正と負の混合数値を正しく処理していることが確認できます。
