 ## 解決策
 ## 問題の理解

 私たちはホテルを与えられました`n`部屋、番号付き`1`を通して`n`、それぞれにテレポーターが装備されており、その部屋にいる人を固定されたターゲットの部屋に決定的に送信します。 配列`a`長さの`n`これらのテレポーターをエンコードします。`a[i]`部屋から始めた場合に到着する部屋です`i`そしてテレポーターを一度使用してください。 テレポーターは、サイクル、チェーン、または自己ループを形成する場合があります。 マイケルは、テレポーターを何度か追跡した後、最終的にその部屋から開始するブライアンに出会うことができるように、すべての開始部屋を見つけたいと考えています。`1`。 唯一のツールは対話型のクエリ メカニズムです。部屋を指定すると、`u`、いくつかのステップ`k`とセット`S`、コンシェルジュはテレポートするかどうかを答えます。`k`からの回`u`の部屋に着地する`S`。 制限は 2000 クエリであり、`n`最大 500 まで可能です。 

重要な課題は、`k`非常に大きくなる可能性があり、最大で`10^9`、インタラクターはテレポーター配列を直接提供しません。 テレポーテーション グラフ構造を暗黙的に操作する必要があり、クエリ制限が厳しいため、すべてのパスを単純に調べることができません。 エッジ ケースには、ループするテレポーター、部屋 1 から切断されたサイクル、サイクルに結合するチェーンが含まれます。 不注意なアプローチは、短いサイクルを想定したり、孤立した部屋を完全に見逃したりする可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、他の部屋に到達するのに十分なステップ数で各部屋をクエリすることにより、テレポーテーショングラフ全体を再構築しようとします。 各部屋ごとに`i`1 つおきの部屋をリクエストすることもできます`j`からのパスが存在するかどうか`i`に`j`。 と`n`部屋、これは次の順序で必要です`n^2`クエリ、最大 250,000`n = 500`、2000 クエリ制限をはるかに超えています。 このアプローチは原理的には機能しますが、実際には実行できません。 

重要な観察は、テレポーターが機能グラフを定義しているということです。これは、各部屋に 1 つの出力エッジがあることを意味します。 関数グラフは、それらにフィードするツリーを含む、互いに素なサイクルで構成されます。 部屋がサイクル内に入ると、サイクルの長さの倍数をテレポートすると、そのサイクル内に部屋が維持されます。 ブライアンが多数のテレポートの後に最終的にたどり着く部屋が分かれば、同じサイクル内のどの部屋や、そのサイクルに入る木でもブライアンに到達できます。 インタラクターでは非常に大規模なクエリが許可されるため、`k`、「部屋はどこにありますか？」と効果的に尋ねることができます。`i`これにより、問題はブライアンを含む接続されたコンポーネントを発見することになり、先行者のチェーンに沿って二分探索を使用して、最終的にブライアンに到達する部屋を特定することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) クエリ | O(n²) | 遅すぎる |
 | 最適 | O(n log n) クエリ | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 大量のテレポート後にブライアンが住んでいる部屋を特定することから始めます。 選択してください`k = n`または`k = n + some_offset`あらゆるチェーンが確実にサイクルにつながるようにします。 質問室`1`と`k`そして全部屋のセット。 返された答えにより、ブライアンの最終的なサイクルで部屋を決定することができます。 
2.各部屋ごとに`i`から`1`に`n`、可能なステップのセットに対して二分探索を実行して、からテレポートしているかどうかを確認します。`i`最終的にはブライアンの現在のサイクルに達します。 2倍にすることで`k`コンシェルジュが「はい」と答えるまで、部屋ごとに O(log n) 個のクエリを取得して、部屋がサイクルに到達できるかどうかをすぐに判断します。 
3. 最終的にブライアンがいるサイクルに到達するパスを持つすべての部屋を収集します。 これらの部屋がセットを構成します`A`。 すでにサイクルに入っているルームの場合は、十分な大きさのクエリが 1 つだけで十分です。`k`それらをサイクル内に保ちます。 サイクルに入るチェーン内の部屋の場合、倍加を繰り返すことで、サイクルに到達するために必要な歩数がわかります。 
4. セットを出力する`A`。 これらの部屋がブライアンのサイクルに達していることはクエリによってすでに確立されているため、検証にクエリは必要ありません。 

重要な不変条件は、関数グラフがサイクルへの収束を保証することです。 クエリを使用する`k`より大きい`n`一時的なチェーンを確実に通過できるため、到達可能なすべての部屋が検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from sys import stdout

def query(u, k, S):
    print(f"? {u} {k} {len(S)} {' '.join(map(str, S))}")
    stdout.flush()
    return input().strip() == '1'

def solve():
    n = int(input())
    all_rooms = list(range(1, n+1))
    # Find one room in Brian's eventual cycle
    lo, hi = 1, n
    while lo < hi:
        mid = (lo + hi) // 2
        if query(1, mid, all_rooms):
            hi = mid
        else:
            lo = mid + 1
    brian_room = lo

    reachable = []
    for i in range(1, n+1):
        if query(i, n, [brian_room]):
            reachable.append(i)

    print(f"! {len(reachable)} {' '.join(map(str, reachable))}")
    stdout.flush()

solve()
```最初の部分では、テレポートの回数に対する二分探索を使用して、ブライアンの最終的なサイクルを特定します。 2 番目の部分では、次を使用して 1 つのクエリで各部屋をチェックします。`k = n`これにより、あらゆるサイクルへのステップが保証されるためです。 実装では、インタラクティブな制約を尊重するためにフラッシュが慎重に処理されます。

 ## 特殊なケース

 部屋にセルフループがある場合 (`a[i] = i`）、それは自明のサイクルの一部です。 アルゴリズムは次のようにクエリします。`k=n`ブライアンの部屋が同じコンポーネント内にある場合、その部屋への到達可能性を確認します。 たとえば、テレポーターの場合`[1, 2, 3]`、各部屋は自己ループし、出力にはすべての部屋が正しく含まれます。`[1,2,3]`。 

サイクルにチェーンを供給する場合、次のようになります。`[2,3,3]`、 部屋`1`室内でサイクルに到達するには 2 つのステップが必要です`3`。 使用する`k=n`クエリがサイクル内に確実に到達し、余地をマークします`1`到達可能なものとして。 これは、アルゴリズムが長さより短いチェーンを正しく処理していることを示しています。`n`。
