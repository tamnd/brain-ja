 ## 解決策
 ## 問題の理解

 0 から L までの 1 次元の線分と考えることができる直線のプラットフォームが与えられています。いくつかのクリボーは、厳密にこの線分内の異なる整数の位置から開始します。 各クリボーには左または右に移動する初期方向があり、すべてのクリボーが 1 秒あたり 1 ユニットの同じ一定速度で移動します。 

このモーションには 3 つの相互作用するルールがあります。 クリボーは現在の方向に継続的に移動します。 セグメントのいずれかの端点に到達すると、すぐに落下して削除されます。 2 つのクリボーが同じ位置で衝突すると、両方とも瞬時に方向を反転し、同じ速度で移動を続けます。 

このタスクは、個々のクリボーをシミュレートすることではなく、最後のクリボーがセグメントから離れる瞬間、つまりシステムが空になる瞬間を計算することです。 

重要な問題は衝突ルールにあります。 素朴な解釈では、衝突は方向を変え、将来の相互作用の連鎖を生み出す可能性があるため、ペアごとの相互作用をシミュレートする必要があることを示唆しています。 その解釈はすぐに計算上不可能になります。 

制約は最大約 10⁴ クリボーと、最大 10¹⁶ までの非常に大きな L を示しています。 イベントごとのシミュレーションやペアごとの相互作用の追跡を試みるソリューションは、密な場合に O(G²) の動作に遭遇しますが、これはすでに境界線にあり、さらに重要なことに、要求される最終量には不必要な慎重なイベント管理が必要になります。 

複数のクリボーが同じ点で出会う対称的な構成からは、微妙なエッジケースが発生します。 たとえば、複数のクリボーが同時に 1 つの位置に集まると、すべてのクリボーが同時に方向を反転します。 単純なシミュレーターは、ペアごとの衝突を任意の順序で処理し、同時イベントを誤って分割する可能性があります。 

もう 1 つのエッジ ケースは、2 つのクリボーが別のクリボーと衝突するのと同時にエンドポイントに到達する場合です。 イベントの順序によっては、たとえすべてのインタラクションが物理的に同じ瞬間に起こったとしても、単純なシミュレーションでは誤ってクリボーが生き残ったり、早すぎて消滅したりする可能性があります。 

## アプローチ

 中心的な観察は、すべてのクリボーが消えるまでの間、衝突ルールは実際には重要ではないということです。 2 匹のクリボーが衝突して方向が逆転する場合、位置と消滅時間だけを考慮すると、これはクリボーがお互いをすり抜けているのと同じです。 

すべてのクリボーが同じ速度と対称的な動作をするため、この等価性は機能します。 クリボーを、跳ねるのではなく相互に通過する区別できない粒子として想像すると、その軌道は独立した直線になります。 各クリボーは、終点に到達するまで左または右に移動するだけです。 

この変換では、衝突はアイデンティティのみを交換し、軌道は交換しません。 プラットフォームがいつ空になるかだけを考慮しているため、アイデンティティは無関係です。 

そこで、インタラクションをシミュレートする代わりに、各クリボーについて、最初の方向が与えられたエンドポイントに到達するまでにどれくらいの時間がかかるかを計算することに問題を落とし込みます。 答えは、これらの個々の終了時間の最大値です。 

ブルート フォース アプローチでは、小さなタイム ステップで移動を明示的にシミュレートするか、優先キューで衝突イベントを処理します。 衝突のたびに位置を更新し、場合によっては将来のイベントのスケジュールを変更する必要があります。 G が 10⁴ までの場合、最悪の場合の相互作用密度は O(G²) に達する可能性があり、このアプローチは非常に遅くなり、不必要に複雑になります。 

最適なアプローチでは、インタラクション ロジックを 1 つの変換で置き換えます。つまり、衝突を無視し、クリボーを独立したウォーカーとして扱います。 答えは、方向に基づいて最も近い境界までの直線距離にわたる単純な最大値になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(G² log G) | O(G) | 遅すぎる |
 | 独立した軌道 | O(G) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 長さ L とクリボーの数 G を読み取ります。また、各クリボーの位置 p と方向 d を読み取ります。 
2. 各クリボーについて、単独で移動すると仮定して退出時間を決定します。 左に移動している場合、p ステップ後に位置 0 に到達するため、終了時間は p 秒です。 右に移動している場合、その時間後に L に達するため、終了時間は L − p 秒です。 
3. 計算されたすべての終了時間にわたって実行最大値を維持します。 
4. すべてのクリボーを処理した後、最大値を出力します。 

ステップ 2 の背後にある理由は、重要な単純化です。 等価性によって衝突が無視されると、各クリボーは固定された境界ターゲットを持つ直線運動の問題になります。 

### なぜ効果があるのか

 不変条件は、衝突によってクリボーの位置のマルチセットが時間の経過とともに変化するのではなく、クリボーのアイデンティティのみが変化するということです。 すべての衝突は、2 匹のクリボーがお互いを通過し、直線を続けていると解釈できます。 すべてのクリボーの速度と動作は同一であるため、ポジションが空になったときにアイデンティティを交換しても影響はありません。 したがって、クリボーが最後に境界に到達するのは、まさにプラットフォームが空になるときです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    L, G = map(int, input().split())
    ans = 0

    for _ in range(G):
        p, d = map(int, input().split())
        if d == 0:
            ans = max(ans, p)
        else:
            ans = max(ans, L - p)

    print(ans)

if __name__ == "__main__":
    solve()
```変換により対話の複雑さがすべて取り除かれるため、実装は意図的に最小限に抑えられています。 唯一の微妙な点は、方向を正しく解釈することです。左の動きは 0 からの距離に直接対応し、右の動きは L からの距離に対応します。 

各クリボーは最終的な最大値に独立して寄与するため、並べ替えやイベント構造は必要ありません。

 ## 特殊なケース

 すべてのクリボーが同じ方向に移動する場合、まれなケースが発生します。 たとえば、すべてが右に移動した場合、システムは L に向かう独立した粒子として動作し、最後の粒子は右の端点から最大距離で退出します。 インタラクションによって終了の順序やタイミングが変更されることはないため、変換は依然として維持されます。 

もう 1 つの特殊なケースは、複数のクリボーが同じ時点および時刻に衝突する場合です。 たとえば、位置 1 と L-1 のような対称的な配置が互いに向かって移動すると、中点で衝突が発生します。 独立軌道モデルでは、それらは単に相互に通過します。 終了時間は変更されず、最大値は依然として境界距離のみによって決定されます。 

最後に、クリボーがエンドポイントの非常に近くで開始する場合 (p = 1 や p = L−1 など)、ソリューションが最小限の移動時間を正しく処理していることが確認されます。 これらのクリボーはすぐに対話する可能性がありますが、境界の終了時間は依然として 1 として正しくキャプチャされます。
