 ## 解決策
 ## 問題の理解

 このシステムは、バイクが移動するたびに常に同じ角度で一緒に回転する 2 つの円形ホイールで構成されています。 各ホイールは正多角形であるかのように装飾されています。$F$側面ともう一方は$B$側面ですが、実際には両方とも下に連続した円があります。 視覚的な目標は、特定の瞬間に両方のホイールが「整列」しているように見えること、つまり、各多角形パターンの辺が下部の位置で完全に水平になるようにすることです。 

ホイール上の各完全なパターンは、毎回繰り返されます。$\frac{360}{k}$ホイールに度がある場合$k$そのため、有効な「整列状態」がホイールの回転に伴って定期的に発生します。 両方の車輪が一緒に回転するため、システムは回転角度が同時に両方の周期の倍数である場合にのみ有効な視覚状態になります。 

この幾何学的制約に加えて、自転車は一定の距離を移動しなければなりません$S$。 各ホイールには円周があります$C$、自転車を前に動かす$C$は正確に 1 回転に相当し、部分的な距離は回転に比例します。 この問題では、「回転」を車輪の 30 度の回転に相当する回転エネルギーの固定単位として定義します。 両方の車輪は常に一緒に回転するため、回転数は両方とも同じになります。 

タスクは、バイクが少なくとも距離をカバーするために必要なこれらの 30 度のターンの最小回数を計算することです。$S$、そしてまさにその瞬間、両方の車輪は有効な位置合わせされた構成になります。 

制約は以下を意味します$10^5$したがって、各ケースは定数時間または対数時間で解決する必要があります。 の値$C$小規模 (最大 1000) ですが、$S$大きくなる可能性があります（最大$10^9$)、そのため、運動のシミュレーションではなく、分数またはモジュラー推論を使用した算術が必要です。 

単純なシミュレーションでは、両方の条件が一致するまでターンバイターンを繰り返すと失敗します。 最悪の場合、位置合わせは、次の最小公倍数に比例する期間の後に発生します。$F$そして$B$、距離の制約によりこれを超える可能性があります$10^9$テストごとの操作。 

アライメントが頻繁に発生するが距離要件が優先される場合、微妙なエッジ ケースが発生します。 たとえば、次の場合$F = B = 3$、位置合わせは回転ステップごとに行われますが、$S$が非常に大きい場合、答えは幾何学ではなく純粋に距離によって決まります。 逆に、もし$F$そして$B$は互いに素な大きな値であり、位置合わせは非常にまれであり、解は移動距離ではなく同期によって決まります。 

## アプローチ

 アライメント要件を無視すると、問題は距離を回転数に変換することになります。 1 回転が次の値に相当します。$C$距離の単位であり、1 ターンは$30^\circ$、つまり、$1/12$フル回転の。 したがって、12 回転ごとが 1 回転に相当します。これは、距離と回転の間に直接変換が存在することを意味します。 

これにより、単純なベースラインが得られます。カバーするために必要な完全な回転数を計算します。$S$、それをターンに変換し、切り上げます。 

ただし、これは重要な制約を無視しています。システムは、両方のホイールが同時に位置合わせされたポリゴン状態にある瞬間にのみ停止しなければなりません。 これにより、許容される回転角度に周期性の制約が導入されます。 

各ホイールには$k$側面には有効な向きがあります$\frac{1}{k}$フル回転の。 したがって、このシステムは、総回転数が両方の倍数である場合にのみ有効です。$\frac{1}{F}$そして$\frac{1}{B}$、回転は次の倍数である必要があることを意味します。$\frac{1}{\mathrm{lcm}(F,B)}$。 

これにより、問題は 2 つの周期システム間の同期問題に変わります。つまり、距離によって駆動される連続的な進行と、ポリゴン周期の最小公倍数によって決定される許容停止点の離散セットです。 

まず、距離を満たすために必要な最小回転を計算し、それを次の有効な位置合わせステップに切り上げます。$\frac{1}{\mathrm{lcm}(F,B)}$グリッド。 この丸めがすべての難しさです。私たちは連続要件を離散周期格子に投影しています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ターンの総当りシミュレーション |$O(T \cdot ans)$|$O(1)$| 遅すぎる |
 | LCM ベースの有効な回転状態への丸め |$O(T \log \min(F,B))$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは完全に「ターン」という単位で作業します。1 ターンは 30 度の固定回転に相当します。 

1. 距離要件を必要なホイール回転数に変換します。 1回転が距離に相当するので$C$、バイクは少なくともパフォーマンスを発揮する必要があります$\frac{S}{C}$回転。 精度の低下を避けるために、これを分数として保持します。 
2. 回転をターンに変換します。 1 回転は 12 回転なので、距離に応じて必要な最小限の回転は次のようになります。$x = 12 \cdot \frac{S}{C}$。 
3. 周期的アライメント制約を計算します。 両方の車輪がポリゴンのエッジが地面と一致する状態に戻るたびに、有効な構成が行われます。 付きホイールの場合$k$側面、これは毎回起こります$\frac{1}{k}$回転、または同等の間隔$\frac{12}{k}$曲がる。 したがって、システム調整期間は順番に次の最小公倍数になります。$\frac{12}{F}$そして$\frac{12}{B}$、これを単純化すると、$\frac{12}{\gcd(F,B)}$。 
4. 少なくとも次のアライメント期間の最小倍数を見つけます。$x$。 これは標準的な上限区分です。期間が$p$、計算します$\lceil x/p \rceil \cdot p$。 
5. その値を答えとして返します。 

重要な決定はステップ 3 です。ポリゴンの配置をモーションと同じ単位系の gcd ベースの周期構造に変換します。 

### なぜ効果があるのか

 システムは回転角度の 1 次元円上で展開しますが、停止には角度の離散サブセットのみが有効です。 そのサブセットは周期的であり、周期性は個々のホイール周期の最大公約数によって完全に特徴付けられます。 すべての有効な構成は、この循環構造内の格子点です。 動きは交互に単調であるため、必要な距離に到達した後の実現可能な最も早い停止時間は、正確に距離のしきい値を超えた最初の格子点になります。 それより前の点は、距離要件に違反するか、位置合わせの周期性を損なうため、両方の制約を満たすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ceil_div(a, b):
    return (a + b - 1) // b

T = int(input())
for _ in range(T):
    C, F, B, S = map(int, input().split())

    # convert required distance to turns:
    # 1 rotation = C distance = 12 turns
    need = S * 12

    # minimal turns ignoring alignment
    # (we work in rational form: need / C)
    # multiply first to keep integer arithmetic
    base_num = need
    base_den = C

    # alignment period in turns is 12 / gcd(F, B)
    import math
    g = math.gcd(F, B)
    period_num = 12
    period_den = g

    # we want smallest t >= base such that t is multiple of period
    # convert both to common denominator:
    # t = k * period
    # need <= k * period
    # k >= need / period
    # need in turns = base_num/base_den

    # inequality:
    # base_num/base_den <= k * period_num/period_den
    # k >= base_num * period_den / (base_den * period_num)

    num = base_num * period_den
    den = base_den * period_num

    k = ceil_div(num, den)
    ans = k * period_num // period_den

    print(ans)
```この実装では、浮動小数点ドリフトを避けるために、すべてが整数に保たれます。 重要なステップは、距離条件とアライメント条件の両方を共有線形スケールに順番に変換し、天井分割を実行して結果を有効な周期グリッドにスナップすることです。 

よくある間違いは、回転と位置合わせを別々に計算し、後でそれらをマージしようとすることです。 アライメント制約は距離の累積に依存しないため、これは問題になります。 gcd ベースのリダクションにより、両方の制約が同じ単位系で表現されることが保証されます。

## テストケース```python
import sys, io
import math

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    T = int(input())
    out = []
    for _ in range(T):
        C, F, B, S = map(int, input().split())

        need = S * 12
        base_num = need
        base_den = C

        g = math.gcd(F, B)
        period_num = 12
        period_den = g

        num = base_num * period_den
        den = base_den * period_num

        k = (num + den - 1) // den
        ans = k * period_num // period_den
        out.append(str(ans))

    return "\n".join(out)

# sample
assert solve("1\n2 8 4 10\n") == "60"

# minimum values
assert solve("1\n1 3 3 1\n") is not None

# already aligned
assert solve("1\n10 4 4 10\n") == "12"

# coprime wheels forcing snapping
assert solve("1\n3 5 7 20\n") == "84"

# large distance
assert solve("1\n1000 12 18 1000000000\n") is not None
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 小さい整列 | 60 | 丸めなしの完全一致 |
 | コプライムケース | 84 | 次の位置合わせにスナップ |
 | 等しい車輪 | 正確 | gcd = 完全な周期性 |
 | 大きいS | 有効 | オーバーフローセーフな算術 |

 ## 特殊なケース

 微妙なケースの 1 つは、両方の車輪の側面の数が同じである場合です。 例えば$F = B = 6$。 この状況では、一方のホイールのすべての有効な状態が他方のホイールにも有効であるため、アライメント期間は最小限になります。 アルゴリズムはこれを次のように削減します。$g = 6$、ピリオドを作る$\frac{12}{6} = 2$曲がる。 正確に計算すると、非常に頻繁な停止ポイントが許可されるため、重要なのは距離だけです。 

もう一つのケースは次のような場合です。$F$そして$B$は互いに素である。 例えば$F = 7, B = 9$。 それから$g = 1$, したがって、位置合わせは 12 ターンごとにのみ発生します。 距離が早く停止することを示唆している場合でも、アルゴリズムは次の 12 の倍数に強制的に切り上げます。これは、両方のポリゴンの位置合わせを同時に満たす中間角度がないという事実と一致します。 

最後のエッジケースが現れるのは、$S$は非常に小さく、1 回転よりも小さい可能性があります。 整数スケールのターンで動作するため、変換は引き続き機能します。 小数距離であっても、共有単位系にマッピングされた後は正しく切り上げられます。
