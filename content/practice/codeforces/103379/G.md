 ## 解決策
 ## 問題の理解

 原点から始まる 2D 平面内の一連の位置が与えられます。 サンタさんのそりはもう方向を自由に選べません。 代わりに、4 つの基本方向で構成される文字列によって与えられる固定の動作パターンを繰り返し実行します。 

概念的には、サンタが位置 (0, 0) に立って、左から右に文字列を適用していると想像します。 一度弦を終えた後、すぐにもう一度それを繰り返し、これが無限に続きます。 繰り返しのたびに決定論的な変位ベクトルが生成されるため、動きの構造は周期的になります。 

質問は、この無限の歩行のいずれかの時点で、サンタがターゲット座標 (x, y) に正確に着陸するかどうかを尋ねます。 これは文字列の全サイクルの終わりに限定されず、繰り返し内の任意の中間ステップで発生する可能性があります。 

制約は 2 つの点で重要です。 座標境界は 10^18 スケールに達するため、ステップを直接シミュレートすることは不可能です。 文字列の長さは最大 100,000 になる可能性があるため、単一パスでもすでに十分な長さがあるため、サイクルごとに O(n^2) または繰り返しシミュレーションを行うと遅すぎます。 唯一実行可能な方向は、1 つの完全な文字列実行を変換として扱い、繰り返し適用されるアプリケーションについて代数的に推論することです。 

1 つの完全な文字列の後の正味変位がゼロになる場合、微妙なエッジ ケースが発生します。 その場合、スレッドは境界のある軌道内に閉じ込められ、最初のサイクルで訪れた位置のみが問題となります。 これを無視して周期的なシフトを仮定すると、実際には訪れたことのない座標への到達可能性を誤って主張する可能性があります。 

別のエッジ ケースは、ターゲット座標がサイクル境界ではなく、サイクルの中間セグメントでのみ到達可能である場合に発生します。 たとえば、文字列が「UR」の場合、訪問する位置は (0,0)、(0,1)、(1,1) となり、これを繰り返します。 (0,1) のようなターゲットは、正味変位推論だけではなく、サイクル内で検出する必要があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。スレッドを段階的にシミュレートし、訪問したすべての座標を保存し、(x, y) が表示されるかどうかを確認します。 これは正しいです。なぜなら、動きは決定論的で周期的であるため、最終的にはターゲットが見えるか見えないかのどちらかになるからです。 問題は、パスが無限であるため、ブルートフォースはある程度のステップ数の後に人為的に停止する必要があることです。 

自然なカットオフは、C がすべての可能なオフセットを「カバーする」のに十分な大きさである場合、O(n * C) ステップなど、ある程度の多数のサイクルまでシミュレートすることです。 ただし、座標は 10^18 まで大きくなる可能性があるため、必要なサイクル数に安全な制限はありません。 数百万サイクルでも制限時間を超えてしまいます。 

重要な洞察は、各完全な文字列アプリケーションが固定変位ベクトルに寄与するということです。 その変位を (dx, dy) とします。 k 個の完全なサイクル後の位置は、k * (dx, dy) に現在のサイクル内の位置を加えたものになります。 これにより、無限ウォークが点の等差数列のチェックに減ります。 

次に視点を逆転させます。 (x, y) が訪問されたかどうかを尋ねる代わりに、i での接頭辞の変位に全サイクルの変位を k 倍したものが (x, y) に等しくなるような、文字列内にサイクル インデックス k と接頭辞の位置 i が存在するかどうかを尋ねます。 これにより、問題は、プレフィックス状態の小さなセットに対する線形ディオファントス条件のチェックに変換されます。 

(dx, dy) が (0, 0) でない場合、k はプレフィックス候補ごとに一意に決定され、k が両方の座標で矛盾しない非負の整数であるかどうかを確認するだけで済みます。 (dx, dy) が (0, 0) の場合、サイクル間でシフトは発生しないため、1 つのサイクルのみが重要となり、ターゲットがプレフィックス トラバーサルに表示されるかどうかを直接チェックします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(無限または有界 O(n·C)) | O(n) | 遅すぎる/不完全 |
 | プレフィックス + サイクル分解 | O(n) | O(n) | 承認済み |

## アルゴリズムのチュートリアル

 1. (0, 0) から始まる文字列内の各文字の後のスレッドのプレフィックス位置を計算します。 これにより、1 サイクル内の各ステップ後の正確な位置が得られます。 これはサイクルの途中で目標に到達する可能性があるため必要です。 
2. 文字列全体を処理した後の最後のプレフィックス位置を取得して、1 サイクルの合計変位を (dx, dy) として計算します。 これは、1 回の繰り返し後にパターン全体がどのようにスペースを移動するかをキャプチャします。 
3. 文字列内のインデックス i に対応するプレフィックス位置 (px、py) (最初の (0, 0) を含む) ごとに、ターゲット (x, y) が完全なサイクル数の後にこの状態と一致するかどうかを検討します。 これは、k ≥ 0 の整数について、(x - px, y - py) が k * (dx, dy) として表現できるかどうかを確認することを意味します。 
4. dx がゼロ以外の場合、k を (x - px) / dx として計算し、それが整数であることを確認します。 また、これを y に適用すると一貫性が得られることを確認します。(y - py) は k * dy に等しくなければなりません。 これにより、dx と dy が一致していない場合のスケーリングの不一致が防止されます。 
5. dx が 0 であるが dy が 0 ではない場合、水平移動はサイクル間で変化しないため、y 座標のみを使用して対称チェックを実行します。 
6. dx と dy の両方がゼロの場合、サイクルはスレッドをまったく動かしません。 この場合、重要なのは最初のサイクルのみであるため、プレフィックス位置がターゲットと等しいかどうかを単純にチェックします。 
7. いずれかのプレフィックス位置が条件を満たす場合は、「Yes」を返します。 それ以外の場合は「いいえ」を返します。 

これが機能する理由は、無限ウォーク内のすべての訪問点は、1 サイクルに整数の全サイクル シフトを加えた範囲内でプレフィックス状態に一意に分解できるという不変条件に基づいています。 プレフィックス列挙はすべてのサイクル内の可能性をカバーし、(dx, dy) による線形スケーリングはすべてのサイクル間の動きを捕捉します。 これらの組み合わせを超える他の点は軌道内に存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())
    s = input().strip()

    # prefix positions
    px = py = 0
    pref = [(0, 0)]

    for c in s:
        if c == 'U':
            py += 1
        elif c == 'D':
            py -= 1
        elif c == 'L':
            px -= 1
        else:
            px += 1
        pref.append((px, py))

    dx, dy = pref[-1]

    for i, (cx, cy) in enumerate(pref):
        tx = x - cx
        ty = y - cy

        if dx == 0 and dy == 0:
            if tx == 0 and ty == 0:
                print("Yes")
                return
            continue

        if dx == 0:
            if tx == 0 and dy != 0 and ty % dy == 0:
                k = ty // dy
                if k >= 0 and cy + k * dy == y:
                    print("Yes")
                    return
            continue

        if dy == 0:
            if ty == 0 and dx != 0 and tx % dx == 0:
                k = tx // dx
                if k >= 0 and cx + k * dx == x:
                    print("Yes")
                    return
            continue

        if tx % dx == 0:
            k = tx // dx
            if k >= 0 and cy + k * dy == y:
                print("Yes")
                return

    print("No")

if __name__ == "__main__":
    solve()
```プレフィックス構造は、可能なすべてのサイクル内エンドポイントを直接エンコードします。 最終的な変位`(dx, dy)`繰り返し構造を捉えます。 各条件付きブロックは、一方または両方の軸がサイクル間で変化しない縮退を処理します。そうしないと、ゼロによる除算や無効な整数の仮定が発生します。 重要な実装の詳細は、1 つの座標だけでなく、両方の座標の一貫性を常に検証することです。 

## 実用的な例

 次の入力を考えてみましょう。```
2 2
UR
```プレフィックスの状態は次のとおりです。 

| 私 | 移動 | 位置 |
 | --- | --- | --- |
 | 0 | 開始 | (0, 0) |
 | 1 | う | (0, 1) |
 | 2 | R | (1, 1) |

 サイクル変位は (1, 1) です。 ターゲット (2, 2) は、k = 2 サイクルでプレフィックス (0, 0) と一致するため、到達可能です。 

これは、到達可能性がサイクル境界で正確に発生する可能性があり、プレフィックス (0, 0) を常に考慮する必要があることを示しています。 

ここで次のことを考えてみましょう。```
1 2
RU
```プレフィックス:

 | 私 | 移動 | 位置 |
 | --- | --- | --- |
 | 0 | 開始 | (0, 0) |
 | 1 | R | (1, 0) |
 | 2 | う | (1, 1) |

 サイクル変位は (1, 1) です。 ターゲット (1, 2) は、プレフィックスと (1, 1) の整数倍として表現できないため、到達できません。 

これは、x と y の間の方向の結合が重要であるため、距離の大きさまたは単純な周期性のみをチェックすることが失敗する理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 1 つのパスでプレフィックス位置を構築し、1 つのパスでそれらをテストします。 
| スペース | O(n) | サイクル内の各位置のプレフィックス座標の保存 |

 n が最大 100,000 であり、すべての演算が文字ごとの定数時間演算であるため、この解は制約内に簡単に適合します。 メモリ フットプリントは文字列サイズに線形であり、一般的な 256 MB の制限内では許容されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、文字列全体の変位ベクトルが 0 である場合です。 この状況では、スレッドはサイクル間で移動しないため、到達可能なポイントはストリングの最初のトラバースのポイントのみになります。 このアルゴリズムは、問題をただちに単一サイクルのプレフィックス チェックに削減することでこれに対処し、サイクル間で不正確な外挿が発生しないようにします。 

dx または dy がゼロの場合、別のエッジ ケースが発生します。 dx がゼロの場合、水平位置はサイクル間で変化しないため、dx で除算する試みは無効になります。 アルゴリズムはこのケースを明示的に分離し、実際に変更される軸の有効性チェックのみを実行します。 

最後の微妙なケースは、ターゲットが先頭 (0, 0) でのみ到達可能な場合です。 これは、プレフィックス リストに移動前の初期位置が含まれているためカバーされており、アルゴリズムはサイクル推論を必要とせずに即時の成功を正しく識別します。
