 ## 解決策
 ## 問題の理解

 長さの順列が与えられています$n$、つまり、次の数値を並べ替えたものです。$1$に$n$。 この順列から、より短い長さのシーケンスを最終的に得たいと考えています。$m$、個別の値で構成されており、どの値が存続する必要があるかが正確に通知されます。 

要素を削除する唯一の方法は、ツールと呼ばれる特別な操作を使用することです。 各ツールは長さに関連付けられています$l_i$、使用すると、長さが正確に一致する連続した部分配列から最大の要素を削除できます。$l_i$。 各ツールは最大 1 回使用でき、適用するときに配列内の位置を選択できます。 

問題は、利用可能なツールを使用して要素を削除して、最終的に残りの要素が正確に指定されたターゲット セットになるようにできるかどうかです (順列からの削除を処理しているため、相対的な順序は暗黙的に保持されます)。 

主な問題点は、各ツールが最大一定の間隔を削除するため、任意の要素を直接削除するわけではないことです。 代わりに、欠失は、選択されたセグメント内の極大構造によって制限されます。 

制約は大きく、すべてのテスト ケースにわたって、$n$そして$k$合計すると最大で$2 \cdot 10^5$。 これにより、すべての間隔またはすべての削除にわたる二次シミュレーションや単純なシミュレーションさえも即座に除外されます。 すべてのソリューションは、慎重にグローバル ブックキーピングを行い、テスト ケースごとにほぼ線形または線形である必要があります。 

単純な間違いは、操作のたびに削除可能な最大値をスキャンすることで、貪欲に削除をシミュレートすることです。 たとえば、ターゲット要素に多くの大きな値がインターリーブされる順列を考えてみましょう。 貪欲な削除では、後で別の必要な要素を分離するために重要になるサブ配列内の最大値が早期に削除される可能性があります。 この間違いは、最大値を削除すると将来のすべての有効な間隔の構造が変更されるため、グローバル構造を持たないローカルで貪欲な選択は失敗する可能性があるということを無視していることから生じます。 

もう 1 つの微妙な失敗例は、必要な削除をそれぞれ独立して十分なサイズのツールに常に割り当てることができると仮定していることです。 たとえば、ある長さのツールがある場合、$[3, 3]$そして、それぞれ長さの互いに素な間隔を必要とする 2 つの要素を削除する必要があります。$3$ただし、順列構造により、同時に満たすことができない制約の重複が強制される場合は、依然として失敗する可能性があります。 

## アプローチ

 ブルート フォース ビューでは、ツールと間隔を選択するすべての可能な方法をシミュレートし、ターゲット セットのみが残るまで要素を削除しようとします。 各ツールは次の場所に配置できます。$O(n)$各配置では、セグメント内の最大値を見つける必要があります。これは別の作業です。$O(n)$前処理しないと動作しません。 前処理を行った場合でも、ツールは最大 1 回しか使用されませんが、任意の順序で対話できるため、構成の数は組み合わせ的に増加します。 これにより、実行可能な限界をはるかに超えた爆発が起こり、事実上指数関数的に増加します。$k$。 

重要な観察は、実際には恣意的な削除を気にしていないということです。 私たちは、十分な長さの利用可能なツールを使用して、ターゲット以外の各要素が最大となる一定の間隔で「カバー」できるかどうかを考慮します。 ツールは選択した間隔の最大値のみを削除するため、すべての削除は、その要素が削除の時点でそのセグメント内に残っている最大値であるセグメントを選択することに対応します。 

これにより、「削除のシミュレーション」から「各取り外し可能な要素を、最大の間隔をサポートできるツール長さに合わせる」という視点に変わります。 順列構造は非常に重要です。各値の位置は固定されており、ターゲットにない要素のセットは何らかの順序で削除する必要があります。 固定要素の場合、それを最大にすることができる最小間隔は、両側の最も近いより大きな要素によって決まります。 

したがって、各非ターゲット要素は、必要な最小間隔長、つまりその周囲の最も近いより大きな要素の間の間隔を引き起こします。 削除に使用するツールは、少なくともそのスパンの長さが必要です。 このような必要な長さをすべて計算した後、問題は複数セットの工具長がすべての要件をカバーできるかどうかを確認することになります。これは、並べ替え後の貪欲なマッチングの問題です。

 ## アルゴリズムのチュートリアル

 削除の実現可能性を、必要な間隔サイズと利用可能なツール サイズの間のマッチング問題に変換することにより、各テスト ケースを処理します。 

1. まず、順列内のすべての値の位置を保存します。 これにより、位置空間の間隔を推論するために必要な、各数値が出現する場所の定時間検索が可能になります。 
2. 最終的な配列にどの値を残す必要があるかを特定します。 それ以外はすべて削除の候補です。 必須ではない要素のみにツールを割り当てる必要があるため、この分離は重要です。 
3. 順列内のすべての値について、値順に配置された順列に対する単調スタックを使用して、値の順序に関して左と右に最も近い大きい要素を計算します。 このステップでは、特定の要素を最大にするために間隔をどこまで拡張する必要があるかを決定する構造境界を確立します。 
4. 最終的に必要なセットに含まれていない各要素について、その左右の「ブロックする」大きい要素の間の距離として、実行可能な最小の削除間隔の長さを計算します。 この間隔は、この要素が最大になり得る最小のセグメントです。これより小さいセグメントには、最大であることを無効にする大きな要素が含まれるためです。 
5. これらの必要な間隔の長さをすべてリストにまとめます。 これらは、ツールが満たさなければならない制約を表します。 
6. 必要な間隔リストと利用可能な工具長の両方を並べ替えます。 これにより、最小の要件から最小の十分なツールまで貪欲に割り当てることができます。 
7. 必要な間隔で繰り返し、十分な大きさの最小の未使用ツールと各間隔を一致させます。 いずれかの時点で要件を満たすツールがない場合、答えは不可能です。 

### なぜ効果があるのか

 正確さは、各削除が間隔要件に帰着すると独立しているという事実に基づいています。すべての非ターゲット要素は正確に 1 回削除する必要があり、各削除には、その要素が最大になる最小間隔以上の長さのツールのみが必要です。 より大きなツールは厳密には優れているか同等であるため、十分な最小のツールを並べ替えて貪欲に割り当てても、将来の実現可能性が損なわれることはありません。 単調スタック構造により、計算される間隔が最小であることが保証されるため、有効なソリューションでは計算よりも小さい要件を使用することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = set(map(int, input().split()))
    tools = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(a):
        pos[v] = i

    # compute next greater on value-axis for each position
    left = [-1] * n
    right = [n] * n

    stack = []
    for i, v in enumerate(a):
        while stack and a[stack[-1]] < v:
            stack.pop()
        if stack:
            left[i] = stack[-1]
        stack.append(i)

    stack = []
    for i in range(n - 1, -1, -1):
        v = a[i]
        while stack and a[stack[-1]] < v:
            stack.pop()
        if stack:
            right[i] = stack[-1]
        stack.append(i)

    req = []
    for i, v in enumerate(a):
        if v in b:
            continue
        L = left[i]
        R = right[i]
        if L == -1:
            L = -1
        if R == n:
            R = n
        req.append(R - L - 1)

    req.sort()
    tools.sort()

    i = j = 0
    while i < len(req) and j < len(tools):
        if tools[j] >= req[i]:
            i += 1
            j += 1
        else:
            j += 1

    print("YES" if i == len(req) else "NO")

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```実装は、各値をその位置にマッピングすることから始まります。これは、構造上の制約について推論するために必要です。 2 つの単調スタック パスは、最も近い大きい要素を計算します。これは、最大値として機能する各要素の最大セグメント境界を定義します。 要件の長さは、これらの境界間のスパンとして導出されます。 要件とツールの両方をソートすると、残りの最小の制約を満たすことができる最小のツールを常に割り当てる貪欲なスイープが可能になります。 

実装の微妙な詳細は、境界条件の処理です。片側にそれ以上の要素が存在しない場合、境界を配列の端まで拡張します。 これにより、エッジ要素が必要に応じてフルスパン間隔を正しく取得できるようになります。

 ## 特殊なケース

 重大なエッジ ケースは、要素の値がグローバル最大値に近いにもかかわらず、ターゲット セットに含まれていない場合に発生します。 このような場合、それより大きな要素が境界を定めないため、そのスパンは配列全体になります。 アルゴリズムは、以下に等しい要件を正しく割り当てます。$n$、利用可能な最大のツールを強制的に消費し、そのようなツールが存在しないケースを正しく拒否します。 

もう 1 つのエッジ ケースは、複数の削除で必要なスパンが同一である場合です。 ソートにより同一の制約が確実に均一に処理され、ツールの再利用制約がポインタの前進を通じて尊重されるため、貪欲なマッチングは引き続き機能します。 

最後の微妙なケースは、残りの必須要素がすべてクラスター化され、概念的な間隔が重複する場合です。 独立したスパン要件に削減することで、各削除が幾何学的な削除プロセスではなくカバレッジ要件として独立して処理されるため、重複が問題にならないことが保証されます。
