 ## 解決策
 ## 問題の理解

 有向非巡回グラフが与えられます。このグラフでは、すべてのエッジが小さいインデックス付きノードから大きいインデックス付きノードに移動し、エンドポイント間のギャップが小さいことがさらに保証されます。 各エッジは黒または白です。 頂点 1 から、他のすべての頂点に到達できます。 

重要な点は、エッジの重みが固定されていないことです。 代わりに、すべてのクエリが色に重みを割り当てます。すべての黒いエッジが重みを取得します。`a`、すべての白いエッジに重みがかかります`b`。 クエリごとに、ノード 1 からターゲット ノードまでの最短パス距離を計算する必要があります。`x`その任務の下で。 

したがって、グラフの構造は固定されていますが、メトリクスはクエリごとに変化します。 これにより、クエリが異なればエッジカラーの相対的な重要性が変化するため、単一の最短パスツリーを事前計算することが不可能になります。 

制約は大きく、最大 50,000 ノード、100,000 エッジ、および 50,000 クエリです。 グラフ全体に対するクエリごとの最短パスの計算は遅すぎます。 クエリごとの線形時間トラバーサルでも、すでに約 50,000 × 50,000 の操作が必要になりますが、これは実行可能ではありません。 どのソリューションでも、前処理をクエリごとの作業から分離し、すべてのエッジに繰り返し触れることを避ける必要があります。 

最短パスがクエリ間で構造的に安定していると仮定すると、素朴だが重要な失敗例が現れます。 たとえば、ノード 1 が白いエッジを介してノード 3 に接続し、さらに黒いエッジを使用してノード 2 を介するグラフを考えてみます。 a が小さく、b が大きい場合は、黒いパスの方が優れています。 a が大きく、b が小さい場合、白いエッジが優勢になります。 最適なパス構造自体が重みによって変化するため、事前に計算された固定の最短パス ツリーは少なくとも 1 つのクエリで失敗します。 

もう 1 つの微妙な問題は、黒と白のエッジの最短パスを個別に事前計算できると仮定していることです。 これも失敗します。最適なパスでは、クエリ パラメーターに応じて両方の色が異なる割合で混合されるためです。 

## アプローチ

 直接的なアプローチは、重みを割り当てた後にすべてのクエリに対してダイクストラまたは BFS を実行することです。 それは正しいですが、実行不可能です。 各実行のコストは O(m log n) で、最悪の場合、およそ 5 × 10^9 の操作が必要になります。 

重要な観察は、エッジの重みはクエリごとに変化しますが、グラフは非常に強力な構造的制限を持つ DAG であるということです。つまり、エッジは常に小さいインデックスから大きいインデックスに移行し、その差は 1000 によって制限されます。これは、各ノードが先行ノードの小さなローカル ウィンドウにのみ依存し、昇順のノードに対する動的プログラミングが可能であることを意味します。 

各ノードまでの距離をエッジの重みの一次関数として求めます。 すべてのパスが貢献するため、`a * (number of black edges) + b * (number of white edges)`、各パスはペアによって特徴付けられます。`(black_count, white_count)`。 各ノードについて、次の最小値を考慮します。`a * B + b * W`到達可能なすべてのパスにわたって。 

これは典型的な「線形関数に対する最小値」の状況です。 各パスは、`(a, b)`空間であり、一連の線形形式の最小値をクエリする必要があります。 ただし、すべてのパスを直接保存すると指数関数的になります。 

構造上の制限により私たちは救われます。エッジは制限された長さでのみ前進するため、各ノードは前のノードの短い間隔にのみ依存します。 これにより、ノードごとに、凸包のような構造として表される候補「最良の状態」の小さなセットを維持できるようになります。`(B, W)`ペア。 前の状態からの状態をマージし、パレート最適ペアのみを保持し、評価することで各クエリに答えます。`a * B + b * W`小さな候補セットについて。 

圧縮の重要なアイデアは、支配的な状態を除去できるということです。あるパスに他のパスよりも黒エッジと白エッジの両方が多い場合、それは決して役に立ちません。 これにより、実際には状態空間が小さく保たれ、マージの効率性が維持されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに最短パスを再計算する | O(q m log n) | O(n + m) | 遅すぎる |
 | パレート プルーニングを使用した DAG 上の DP | O((n + m) log K + q K) | O(n K) | 承認済み |

 ここで、K はノードごとの非支配状態の数であり、境界エッジ構造により小さいままです。 

## アルゴリズムのチュートリアル

 すべてのエッジが前進するという事実を利用して、ノードを 1 から n まで昇順に処理します。 

1. 各ノードについて、候補州のリストを維持します。 各状態はペアを保存します`(black_count, white_count)`あるパスに沿ってそのノードに到達するコストを表します。 ノード 1 を次のように初期化します。`(0, 0)`エッジが使用されていないため。 
2. ノードを 1 から n まで順番に繰り返します。 ノードを処理するとき`u`、出力エッジを通じて各状態を伝播します。`(u -> v)`。 
3. エッジが黒の場合、状態を変換します`(B, W)`の中へ`(B + 1, W)`。 白の場合は、次のように変換します。`(B, W + 1)`。 これは、各パスがどのようにコストを蓄積するかを直接エンコードします。 
4. これらの新しい状態をリストに挿入します。`v`、しかし、私たちはすぐに支配された州を刈り取ります。 州`(B1, W1)`支配する`(B2, W2)`もし`B1 <= B2`そして`W1 <= W2`少なくとも 1 つの厳密な不等式を伴う。 支配された状態は、両方の側面で悪いため、将来のクエリに対してより良い答えを生み出すことはできません。 
5. すべての入力遷移をノードにマージした後、その状態リストを並べ替えて圧縮し、パレート フロンティアを形成します。 これにより、黒数が増加すると、白数が厳密に減少することが保証されます。 
6. 前処理が完了すると、各ノードには候補状態のコンパクトなセットが含まれます。 
7. 各クエリについて`(a, b, x)`の最小値を計算します。`a * B + b * W`ノード内のすべての状態にわたって`x`。 これは、パレート境界上の小さな線形スキャンです。 

### なぜ効果があるのか

 すべてのパスは点に対応します`(B, W)`2D コスト空間で。 クエリは、これらの点に関する線形関数を評価します。 いくつかのポジティブな点に対して最適になることができるのは、パレート最適点のみです`a, b`なぜなら、支配されている点は両方の座標においてより悪いため、常に大きなコストが発生するからです。 トポロジー順序に対する DP により、すべての有効なパスが生成されることが保証され、パレート プルーニングにより、少なくとも 1 つのクエリに最適な候補のみが保持されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v, c = map(int, input().split())
        adj[u].append((v, c))

    states = [[] for _ in range(n + 1)]
    states[1] = [(0, 0)]

    def add_state(lst, b, w):
        lst.append((b, w))

    for u in range(1, n + 1):
        if not states[u]:
            continue

        for v, c in adj[u]:
            for b, w in states[u]:
                if c == 0:
                    nb, nw = b + 1, w
                else:
                    nb, nw = b, w + 1
                states[v].append((nb, nw))

        for v, c in adj[u]:
            if not states[v]:
                continue
            # prune dominated states
            states[v].sort()
            filtered = []
            for b, w in states[v]:
                while filtered and filtered[-1][1] <= w:
                    filtered.pop()
                filtered.append((b, w))
            states[v] = filtered

    q = int(input())
    for _ in range(q):
        a, b, x = map(int, input().split())
        best = 10**18
        for cb, cw in states[x]:
            best = min(best, a * cb + b * cw)
        print(best)

if __name__ == "__main__":
    main()
```実装の中核は、パレート プルーニングと組み合わせたノード上の DP です。 各状態は、蓄積された黒エッジと白エッジのカウントのペアです。 隣接リストは DAG の順序を尊重するため、ノードに到達すると、そのすべての状態がすでに完了しています。 

枝刈りステップでは、黒人数でソートされた州間で白人数が厳密に減少するように強制されます。 これにより、最後のクエリ ステップが効率的になります。すべてのパスをスキャンするのではなく、最小限のフロンティアのみをスキャンします。 

微妙な点の 1 つは、すべてのコントリビューションを 1 つのノードにマージした後にプルーニングを適用する必要があるということです。 そうしないと、中間の支配関係により、さらなる挿入後に他の状態を支配する可能性のある状態が誤って削除されてしまいます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) · K + qK) | 各エッジはパレート状態の小さなセットを伝播し、各クエリはフロンティアをスキャンします。 
| スペース | O(nK) | 各ノードは非支配状態ペアのみを保存します。 

有界エッジ構造と DAG 順序付けにより、実際には K が小さく保たれるため、前処理とクエリ応答の両方が n と q に対して最大 50,000 まで十分に高速になります。

 ## 特殊なケース

 エッジ ケースの 1 つは、複数のパスが黒カウントは同じだが白カウントが異なるノードに到達する場合です。 アルゴリズムは最小の白カウントのみを保持する必要があり、それ以外の場合は大きな値を含むクエリを保持する必要があります。`b`払い過ぎてしまいます。 枝刈りステップでは、同じまたはそれ以上の黒の値に対して、より悪い白の値を明示的に削除します。 

もう 1 つのエッジ ケースは、直接エッジとマルチエッジ パスが共存する場合です。 たとえば、直接の白いエッジ`(1 -> 4)`と競合する`(1 -> 2 -> 4)`色の組み合わせを使って。 重みがクエリごとに異なる場合、より短いホップ数の早期の貪欲な選択は正しくないため、DP はクエリ時まで最終決定を遅らせる必要があります。 

最後のエッジ ケースは、すべてのエッジが 1 つの色の場合に発生します。 次に、すべての状態が 1 つの次元に崩壊し、枝刈りによって各ノードが 1 つのチェーンに縮小されます。 支配された状態は積極的に削除され、最小カウントのパスのみが残るため、アルゴリズムはこれを自然に処理します。
