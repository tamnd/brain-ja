 ## 解決策
 ## 問題の理解

 一列に配置された n 羽のガチョウのシーケンスが与えられ、各ガチョウはタスク タイプ ai に関連付けられます。 「計画」は、間隔 [l, r] を意味するガチョウの連続したセグメントを選択することによって選択され、それらのガチョウだけがタスクの完了に参加します。 

ガチョウが間隔を選択した後、アヒルはタスクの場所を確認します。 タスクの場所は単なる値 x であり、選択した間隔内で ai = x を持つガチョウの数を数えます。 アヒルは、選択された間隔で正確に k 羽のガチョウがそのタスクに取り組んだ場合にのみ、そのタスクの場所で待ち伏せすることが許可されます。 このようなタスクが選択した間隔で存在する場合、その計画は危険であると見なされます。 

目標は、間隔 [l, r] が間隔内の頻度が正確に k であるタスク値を生成しない間隔がいくつあるかをカウントすることです。 

入力サイズは n = 10^6 に達するため、すべての O(n^2) 間隔を試行するソリューションは直ちに実行不可能になります。 O(n sqrt n) でさえ、定数が大きいこととメモリの局所性の問題により、最悪の場合にはすでに遅すぎます。 この問題の構造は、「区間内で正確に k 回出現する値がない」という条件を、すべての区間にわたるグローバルな計数問題に変換する必要があることを強く示唆しています。 

k = 1 の場合、微妙なエッジ ケースが発生します。この場合、区間内に 1 回だけ出現する値は危険であるため、完全に個別の要素で構成される区間は無効になります。 重複のみを追跡する単純なアプローチでは、重複が問題ではなく、単一の発生が問題となるため、これを完全に見逃してしまいます。 

もう 1 つの特殊なケースは、すべての値が同一である場合です。 その場合、ちょうど k の長さのすべての区間は直ちに危険であるため、答えは区間の総数からそれらの特定の区間を差し引いたものになりますが、これは k が n に対して十分に小さい場合に限ります。 

## アプローチ

 この問題に直接アプローチする方法は、すべての区間 [l, r] を列挙し、その中のすべての ai の周波数を計算し、いずれかの周波数が k に等しいかどうかを確認することです。 これは、l ごとに r を展開しながら頻度表を維持することによって実行できます。 カウントを維持する場合、間隔ごとのチェックは O(1) ですが、各 r の頻度を更新すると、全体としては O(n^2) 個の遷移が発生します。 n が最大 10^6 であるため、これは制限をはるかに超えています。 

重要な観察は、この条件が、ある値が区間内の周波数に正確に k に達するかどうかのみに依存するということです。 すべての頻度をグローバルに追跡する代わりに、値を「危険」にするものに焦点を当てることができます。間隔内の値 x の出現に、x の k 個の出現の連続ブロックが含まれる場合、値 x はその区間内で危険になります (インデックス空間内で連続している必要はありませんが、セグメント内の出現順序では連続しています)。 これは、各値の出現が追跡される構造に配列を変換することを示唆しており、間隔が同じ値の k 個の出現をどのように捕捉するかを推論します。 

各値 x について、その出現位置 pos[x][i] を考慮します。 pos[x][i] が [l, r] 内で k 番目に出現するエンドポイントとなるインデックス i が存在する場合、区間 [l, r] にはちょうど k 回の x が含まれます。これは次のことを意味します。 

pos[x][i] - pos[x][i-k+1] は、前後の x の出現が干渉することなく、間隔に k 個の出現が正確に含まれる有効なウィンドウに寄与します。 

言い換えると、各値 x は次の形式の複数の「不正な間隔制約」を生成します。 

区間 [pos[x][i-k+1], pos[x][i]] は、危険な状態を生じない限り、[l, r] に完全に含まれてはならないウィットネス セグメントです。 

したがって、問題は、これらの禁止された目撃セグメントのいずれかを完全に含むことを避ける間隔をカウントすることになります。 各出現はそのようなセグメントを最大 1 つだけ寄与するため、セグメントの総数は O(n) になります。 次に、禁止されたセグメントが完全に含まれないようにする間隔をカウントします。

この問題を古典的な区間包含除外問題に変換します。 右端点 r ごとに、ある l しきい値の後に始まる最も近い禁止セグメントを維持し、スイープ ラインまたは最後に出現した境界構造を使用して、有効な l の数を計算します。 

より直接的な方法は、r を左から右に処理することです。 各 r について、各値 x の最後の k 個の出現を維持し、各 r について、[l, r] 内の値を正確に k にする最も古い l を維持します。 これにより、そのようなすべての「アクティブ化ポイント」にわたって l > min という制約が生じます。 次に、固定 r に対するすべての有効な l がプレフィックスを形成するため、r ごとに O(1) の寄与をカウントできます。 

これにより、値ごとに k 番目に最後に出現するスライディング ウィンドウを維持するという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 間隔を超えた総当たり攻撃 | O(n^2) | O(n) | 遅すぎる |
 | 発生ウィンドウ + スイープ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各値の出現リストを維持しながら、配列を左から右に処理します。 

1. 各値 x について、最新の k 回の出現のキューを保存します。 

これにより、現在位置で終了するオカレンスが正確に k 個あるときがわかります。 
2. 位置 r を処理するときに、r を a[r] の出現リストに追加します。 

リストのサイズが k を超える場合は、r で終わる k ウィンドウが定義されなくなるため、最も古いリストを削除します。 
3. リストのサイズが正確に k である場合、このリストの最初と最後の位置によって形成されるセグメントが「不正な証人セグメント」の候補になります。 これは、区間 [l, r] にこのセグメントが完全に含まれている場合、x の中に r で終わる x が少なくとも k 個存在することを意味します。 
4. 1 として初期化された配列 bestL[r] を維持します。これは、位置 r の任意の値によって強制される最大の下限を表します。 r で終わる k 個の値ごとに、次のように更新します。 

bestL[r] = max(bestL[r], pos[x][i-k+1] + 1)

 これにより、pos[x][i-k+1] 以降の開始には、安全性に違反する方法で正確に k 回の出現が含まれることが保証されます。 
5. 各 r について、すべての有効な l は [bestL[r], r] の範囲内にあります。 したがって、r で終わる安全区間の数は、r - bestL[r] + 1 となります。 
6. すべての r を合計します。 

これが機能する理由は、すべての危険な構成が、ある値の k 番目の出現ウィンドウによって一意に識別されるためです。 間隔にその完全なウィンドウが含まれる場合、ある時点で k に正​​確に等しい頻度が必然的にトリガーされるため、計画は危険になります。 l がそのようなすべての左境界よりも大きくなければならないことを強制することで、すべての無効な区間を 1 回だけ除外します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    pos = {}
    from collections import deque

    dq = {}
    bestL = 1
    ans = 0

    # We maintain for each value a deque of last k positions
    occ = {}

    for r in range(n):
        x = a[r]
        if x not in occ:
            occ[x] = deque()

        occ[x].append(r + 1)

        if len(occ[x]) > k:
            occ[x].popleft()

        if len(occ[x]) == k:
            l_bound = occ[x][0]
            # interval must start after this to avoid exactly k occurrence window
            bestL = max(bestL, l_bound + 1)

        # count valid l for this r
        if bestL <= r + 1:
            ans += (r + 1) - bestL + 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、値ごとに、その最後の k 個の出現のスライディング デキューが保持されます。 この構造により、r で終わる k 個の出現が表示されるたびに、それらの左端が r で終わる間隔に対して最も厳しい制約を定義することが保証されます。 

この実装では、変数 bestL は r 全体にわたってグローバルですが、これは微妙な単純化です。完全に厳密な定式化では、制約は r ごとに再計算される必要があります。 ただし、制約は r が増加するときにのみ右に移動するため、bestL は単調であり、必要な制約をすべて安全に蓄積します。 

間隔計算での 1 から始まるインデックス付けには注意が必要です。 このコードは、カウントを計算するときにわかりやすくするために位置を 1 ベースに変換します。

 ### 例 1

 入力:```
6 2
1 2 2 1 3 3
```発生状況を追跡します。 

| r | 値 | occ[1] | occ[2] | occ[3] | ベストL | 有効な l カウント |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | [1] | [] | [] | 1 | 1 |

 最終的な答えは、有効な l カウントの合計です。これは、値が正確に 2 回出現するセグメントを完全には含まないすべての間隔に対応します。 

### 例 2

 入力:```
6 1
1 2 3 4 5 6
```ここでは、すべての値が 1 回出現します。 少なくとも 1 の長さの間隔には、頻度がちょうど 1 の値が直ちに含まれます。そのため、要素をまったく含めないようにする間隔を除いて、すべての間隔は危険です。空でない間隔ではこれは不可能です。 したがって、答えは 0 です。 

アルゴリズムは、有効な間隔を残さず、各ステップで bestL を r+1 に更新し、期待される結果と一致します。

 ## 特殊なケース

 k = 1 の場合、あらゆる出来事が即座に危険な状態を形成します。 このアルゴリズムは、すべてのステップで bestL を r+1 に設定し、すべての間隔を削除します。 入力用`1 1 / 1`、r = 1 では、occ サイズは k に等しいため、bestL は 2 になり、l ≤ r を満たす l はなく、期待どおり出力 0 が生成されます。 

すべての要素が同一で、k が小さい場合、次のようにします。`1 1 1 1 1`k = 2 の場合、2 つの出現がある各 r により、bestL が増加します。 r = 2 では bestL は 1 になり、r = 3 では 2 になり、というように、完全な k ブロックを回避したものだけが残るまで、有効な間隔が徐々に縮小していきます。 各デキュー ウィンドウは回避する必要がある個別の k 回出現範囲を表すため、このアルゴリズムは制約を正しく累積します。
