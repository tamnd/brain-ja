 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 「値を、選択した正の整数で割ったときの余りで置き換える」という形式の操作を使用して、個々の要素を繰り返し変更することができます。 この操作は任意の要素に何度でも適用できますが、要素をゼロにすることは禁じられています。 

このような一連の操作を実行した後、結果の配列を確認し、通常の意味で GCD を計算します。 私たちの目標は、この最終的な GCD を最大化する方法で操作を選択することです。 

重要な問題は、この操作が単純に数字を恣意的に減らすわけではないことです。 剰余演算では構造上の制約が維持され、特定の開始値からすべての小さな値に必ずしも到達できるわけではありません。 

この制約では、最大 1e9 までの値を持つ最大 100,000 個の要素が許可されるため、要素ごとに変換をシミュレートしたり、考えられるすべての最終状態をテストしようとするソリューションは直ちに実行不可能になります。 n と値の両方が大きいため、O(n sqrt A) アプローチでも遅すぎます。 

「ゼロは許可されない」ルールから、微妙な特殊なケースが発生します。 たとえば、要素が 2 の場合、それをさらに減らそうとすると、多くの場合ゼロが生成され、不正になります。 特に、有効な演算シーケンスを使用しても 2 から 1 に到達することはできません。これは、すべてのモジュロを選択すると 2 が維持されるか、0 が生成されるためです。 

もう 1 つの特殊なケースは、値が小さい場合でも、すべての中間数値に自由に還元できない可能性があることです。 たとえば、4 は 1 には到達できますが、2 や 3 には到達できません。この不均一な到達可能性が、単純で貪欲な「すべてをターゲット GCD に削減するだけ」アプローチが失敗する主な理由です。 

## アプローチ

 ブルートフォース解釈では、各要素の可能な最終値をすべて考慮し、すべての組み合わせに対して可能な限り最良の GCD を計算します。 各要素は到達可能な多くの状態に分岐する可能性があり、n 個の要素にわたる選択肢を組み合わせるのは困難であるため、これはすぐに指数関数的になります。 

より構造化された見方は、問題を逆転させることです。 変換後にどのような GCD が形成されるかを問うのではなく、最終的な配列で共通の値としてどのような値 d が現れるかを尋ねます。 すべての要素を厳密に d にすることができれば、GCD は少なくとも d になります。 GCD は選択された最小値によって上限が制限されるため、均一なターゲットを最大化することが最も強力な戦略です。 

これにより、問題は到達可能性を理解することになります。つまり、固定要素 a について、ゼロに到達することなく繰り返しモジュロ演算を使用してどの値に変換できるかということになります。 

重要な観察は、値 a から厳密に a/2 より大きく、a 未満の数値に到達することは不可能ですが、1 から Floor((a − 1) / 2) までのすべての値は最大 1 回の操作で到達可能であり、その範囲を超える値は変更されないままであるか、到達不能領域に入るということです。 これにより、明確な構造上の制約が作成されます。つまり、各要素はそれ自体のままであるか、比較的小さな値までしか減らすことができませんが、間隔全体をスムーズにカバーすることはできません。 

これにより、ターゲット候補に対するグローバル制約が生じます。 すべての要素を正確に d にしたい場合は、要素 a について、a がすでに d に等しいか、a がリダクションによって d に達するのに十分な大きさでなければなりません。 それには、a ≥ 2d + 1 が必要です。そうでない場合、d が禁止された中間領域 (a/2 と a の間) にある場合、d を生成することはできません。 

したがって、問題は、どの値 d がすべての配列要素に対して同時に「安全」であるかを確認することになります。 

d ごとの直接検証は依然として遅すぎますが、配列をソートするとより単純な構造が明らかになります。 候補 d に対する唯一の障害は、d < a ≤ 2d であり、a が d に等しくないような値 a が存在することです。 このような値は d に変換できないため、構築がブロックされます。 

これにより、ソートされた一意の値を単純にスイープすることになります。

 ## アルゴリズムのチュートリアル

 ### アルゴリズムのチュートリアル

 1. 配列をソートし、個別の値のリストに圧縮します。 

唯一の危険な状況は、インデックスではなく、値空間内の隣接する値に依存するため、並べ替えが必要です。 
2. 昇順の個別の値 d ごとに、それを最終 GCD 候補とみなします。 

すべての要素を d に等しくすることができれば、d は配列 GCD として実現可能です。 
3. 間隔 (d, 2d] に値が存在するかどうかを確認します。

 そのような値が存在し、それが d 自体と等しくない場合、d は不可能です。 その理由は、許可されている操作ではこの値を d まで減らすことができないためです。 
4. d の後の次の個別の値が 2d より大きい場合、禁止区間にはブロック値が存在しないため、d は有効です。 
5. すべての候補にわたる最大有効 d を追跡し、それを出力します。 

### なぜ効果があるのか

 各要素は、それ自体、または現在の大きさの半分以下の比較的小さい値のいずれかである最終値にのみ寄与できます。 これにより、厳密な境界が作成されます。つまり、区間 (d, 2d] 内の値は、既に d に等しくない限り、すべてを d に折りたたむことができないという意味で「固定」されます。

 したがって、値セットにその区間内に避けられない障害物が含まれていない場合、あらゆる候補 d が有効になります。 障害物は (d, 2d] の内側にある次に大きな要素として表示されるため、ソートされた順序で隣接する値をチェックするだけで十分です。

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort()
    
    # compress distinct values
    vals = []
    for x in a:
        if not vals or vals[-1] != x:
            vals.append(x)
    
    ans = 1
    
    m = len(vals)
    for i, d in enumerate(vals):
        if i < m - 1:
            nxt = vals[i + 1]
            if nxt <= 2 * d:
                continue
        ans = max(ans, d)
    
    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、重複を並べ替えて圧縮することから始まり、明確な大きさのみについて推論できるようになります。 各候補値 d について、次の個別の値のみを調べます。 その次の値が 2d 内にある場合、モジュロリダクション ルールの下では d に変換できない中間数値が存在するため、d は拒否されます。 それ以外の場合は d が実現可能であり、回答候補になります。 

最終的な答えは、実現可能な最大の d です。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての要素が等しい場合です。 その場合、変換は必要なく、すべてを変更せずに維持することで GCD が最大化されるため、答えは自明のことです。 

もう 1 つのケースは、4、5、6 など、値が非常に小さく密に詰め込まれている場合です。ここでは、各値が 2 倍間隔内に近傍を持つため、最大のものを除くすべての候補がブロックされます。 アルゴリズムは 4 と 5 を正しく拒否し、6 を選択します。 

最後のケースは、10、25、100 など、値の間隔が広い場合です。ここでは、他の値の禁止間隔に該当する値がないため、ほとんどの候補が有効であり、アルゴリズムは最大値を達成可能な最良の GCD として正しく識別します。
