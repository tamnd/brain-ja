 ## 解決策
 ## 問題の理解

 次のシーケンスがあります`n`敷石にはそれぞれ色があります`a[i]`。 すべての敷石がまったく同じ色の空でないポジションのサブセットをすべてカウントする必要があります。 位置は異なるため、異なる敷石を選択すると、色が同じであっても異なるサブセットが得られます。 

特定の色が現れたとします。`c`回。 この色を使用するすべての有効なサブセットは、単にそれらの空でないサブセットです。`c`敷石。 がある`2^c`空のサブセットを含む合計サブセットなので、この色が寄与します`2^c - 1`有効な選択肢。 最終的な答えは、表示されるすべての色のこの量の合計です。 

シーケンスには最大で次のものを含めることができます`10^5`敷石、各色は最大でも`10^5`。 この入力サイズでは、すべてのサブセットを検査するアルゴリズムは不可能です。`2^100000 - 1`空ではないサブセット。 たとえ`O(n^2)`ソリューションは次のように実行されます`10^10`最悪の場合、競技プログラミングの制限である約 2 秒がサポートできる範囲をはるかに超えます。 基本的に敷石の数が線形になるアルゴリズムが必要です。 

不注意な実装が失敗する可能性のあるエッジケースがいくつかあります。 一枚の敷石で、`1`に続く`5`、有効なサブセットは 1 つだけ、つまり敷石そのものです。 空のサブセットを削除し忘れた数式は次の結果を返します。`2`の代わりに`1`。 

すべての色が異なる場合、たとえば`3`に続く`1 2 3`、すべての有効なサブセットには 1 つの敷石が含まれるため、答えは次のようになります。`3`。 色ごとにグループ化せずにすべてのサブセットをカウントするソリューションには、次のような混合色のサブセットが誤って含まれてしまいます。`{1, 2}`。 

色を繰り返すと、次のようになります。`5`に続く`5 5 1 2 3`、2つの敷石は色付きです`5`3 つの有効なサブセット (そのうちの 1 つ、または両方を一緒に) を生成します。 合計は`3 + 1 + 1 + 1 = 6`。 色ごとに 1 つのサブセットのみをカウントすると、その色の複数の敷石を選択して形成された組み合わせが失われます。 

最後に、色は最大許容値で発生する可能性があります。 例えば、`2`に続く`1 100000`答えがあります`2`、両方の色が一度だけ出現するためです。 より小さい周波数配列を割り当てる実装`100001`意図した範囲外にアクセスしてしまう可能性があります。 

## アプローチ

 直接的なアプローチは、空でないすべてのサブセットを考慮することです。`n`ポジション。 まさにあります`2^n - 1`そのようなサブセット。 各サブセットについて、選択した敷石を検査し、それらの色がすべて等しいかどうかを確認できます。 これは正しいです。なぜなら、考えられるすべてのサブセットが検査され、条件を満たす場合に正確に受け入れられるからです。 

問題はサブセットの数です。 いつ`n = 100000`、 がある`2^100000 - 1`空ではないサブセットですが、これはすでに実行可能な作業量をはるかに超えています。 サブセットをチェックするために最大の内容を確認する必要がある場合は、`n`ポジションの場合、最悪の場合の総仕事量は`Θ(n 2^n)`。 チェックコストを削減するより賢いサブセット表現を使用したとしても、`2^n`列挙自体がすでに不可能です。 

有益な観察は、各色が何回出現するかが分かれば、敷石の実際の位置は問題ではないということです。 色の場合`x`表示されます`c`回、色が次の有効なサブセットごとに`x`まさにそれらの中から空ではないコレクションを選択する必要があります`c`ポジション。 このようなコレクションを選択する方法は次のとおりです。`2^c - 1`。 

これにより、元のサブセット問題が頻度カウント問題に変わります。 まず各色の敷石が何枚あるかを数えてから計算します。`2^c - 1`各周波数に対してそれらの寄与をモジュロで加算します`10^9 + 7`。 

たとえば、`3 5 5 1 2`、 色`3`一度発生して寄与する`1`、 色`5`2回発生して寄与する`3`、 色`1`一度発生して寄与する`1`、色`2`一度発生して寄与する`1`。 合計は`1 + 3 + 1 + 1 = 6`。

 ## アルゴリズムのチュートリアル

 1. 各色の敷石の数を記録する頻度構造を作成します。 どの色も中間にあるので、`1`そして`100000`、サイズの配列`100001`で十分です。 周波数をカウントするには、入力を 1 回通過します。 
2. から 2 の累乗を事前計算します。`2^0`を通して`2^n`、常に結果の剰余を取得します`10^9 + 7`。 必要です`2^c`あらゆる可能な周波数に対して`c`、それ以上の色は発生しません。`n`回。 
3. 色を繰り返し、その頻度を調べます。 色が発生した場合`c`時々、あります`2^c`これらの敷石のサブセットを選択する方法は、それぞれ`c`位置には独立して、選択するか選択しないかの 2 つの選択肢があります。 
4. から 1 を引きます。`2^c`空のサブセットを除外します。 したがって、この色の寄与は次のようになります。`2^c - 1`。 
5. すべての色の寄与を答えのモジュロに加算します。`10^9 + 7`。 頻度がゼロの色は何も寄与しないため、単純にスキップできます。 

### なぜ効果があるのか

 すべての色について`x`、その周波数を`c`。 すべての敷石に色があるサブセット`x`のみを含めることができます`c`ポジションを運ぶ`x`。 これらのポジションにはそれぞれ 2 つの独立した選択肢があるため、正確には`2^c`これらのポジションのサブセット。 そのうちの 1 つだけが空で、残りは`2^c - 1`空ではない有効なサブセット。 

すべての有効なサブセットは 1 つの色だけを持つため、1 つの色の寄与に属します。 逆に、すべてのサブセットは色によってカウントされます。`2^c - 1`この用語にはその色の敷石のみが含まれるため、有効です。 したがって、寄与分は互いに素であり、集合的にすべての有効なサブセットが 1 回だけ含まれており、その合計が必要な答えであることが証明されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
MAX_COLOR = 100000

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    freq = [0] * (MAX_COLOR + 1)

    for color in a:
        freq[color] += 1

    pow2 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow2[i] = (pow2[i - 1] * 2) % MOD

    ans = 0

    for color in range(1, MAX_COLOR + 1):
        c = freq[color]
        if c:
            ans = (ans + pow2[c] - 1) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```の最初の部分`solve`敷石の数とその色を読み取ります。 周波数配列は次の事実を利用します。`a[i]`せいぜい`100000`、 それで`freq[color]`その色の出現数を直接保存します。 

の`pow2`配列には、必要なすべての 2 のべき乗が含まれます。`pow2[0]`は`1`、後の各値は、前の値を 2 倍して法的に取得します。`MOD`。 これにより、電力を繰り返し再計算することがなくなり、格納されるすべての整数が小さく保たれます。 

応答ループでは、`pow2[c] - 1`、組み合わせ引数と正確に一致します。 減算は式の最後のモジュロ演算の前に実行されますが、累積された結果は次のように正規化されます。`% MOD`反復ごとに。 Python の整数はオーバーフローしませんが、要求された答えは明示的にモジュロであるため、モジュラー算術は依然として必要です。`10^9 + 7`。 

周波数条件`if c:`表示されない色については何も追加できなくなります。 ループは次から始まります`1`そしてで終わります`100000`, そのため、許容される色の範囲の両端が処理されます。 

この問題にはテスト ケースが 1 つしかないため、テスト ケースのループはありません。 提供されたステートメントの表示サンプルの書式設定が一貫していませんが、意図されたサンプルは次のとおりです。`n = 5`色付き`3 5 5 1 2`。

def solve():

## 特殊なケース

 単一の敷石は可能な限り最小の投入量です。 のために`n = 1`そして配列`1`、色の周波数`1`は`1`、したがって、その貢献度は`2^1 - 1 = 1`。 アルゴリズムは出力します`1`。 バイナリ選択によって生成される 2 番目のサブセットは空のサブセットであり、これは許可されていないため、ここでは 1 による減算が不可欠です。 

たとえば、すべての色がはっきりと区別できる場合、`4`に続く`1 2 3 4`、すべての周波数は`1`。 それぞれの色が貢献します`2^1 - 1 = 1`、合計を与えます`4`。 2 つの異なる位置を含むサブセットは、単一の色がそのようなサブセットを受け取らないため、周波数ベースのカウントによって自動的に拒否されます。 

たとえば、すべての敷石が同じ色である場合、`5`に続く`7 7 7 7 7`、全体の問題は、5 つの位置の空でないサブセットを選択することに帰着します。 がある`2^5 - 1 = 31`このようなサブセットを使用すると、アルゴリズムは単一周波数から正確にその値を取得します。`c = 5`。 

境界色については、次の点を考慮してください。`6`に続く`1 100000 100000 1 100000 1`。 色`1`3回出演して貢献`7`、色を付けながら`100000`も3回登場し、さらに貢献します`7`。 答えは、`14`。 周波数配列にはインデックスがあります。`100000`したがって、両方の境界値が正しく表現されます。 

最大入力サイズの場合、すべて`100000`敷石が同じ色である場合、アルゴリズムはサブセットを列挙しません。 周波数を保存します`100000`、計算します`2^100000`モジュロ`10^9 + 7`、1を引いて返します`607723519`。 有効なサブセットの数学的数が約 30,000 桁の 10 進数であっても、実行は線形のままです。
