 ## 解決策
 ## 問題の理解

 各プレーヤーは長さの配列を所有します`n`。 固定目標金額の場合`k`、ポジションのペア`(i, j)`いつでもいいです`i < j`2 つの値を合計すると、`k`。 マフムードの配列とバシャールの配列で良好なペアを個別にカウントし、2 つのカウントを比較する必要があります。 より多くの良いペアを持っているプレーヤーが勝ち、同じ数の場合は引き分けとなります。 

注文条件`i < j`ペアを数えるときに位置が重要であることを意味します。 たとえば、`[1, 2]`と`k = 3`、適切なペアが 1 つだけ存在します。 で`[1, 2, 1]`、良いペアが 2 つあります。`(1, 2)`そして`(2, 3)`。 個別の値の組み合わせだけではなく、位置のペアを数えます。 

配列の長さは次のとおりです`10^5`したがって、位置のすべてのペアを検査するアルゴリズムは約`n(n-1)/2`小切手。 最大サイズだとこんな感じ`4,999,950,000`これは、競技プログラミングの制限である約 1.5 秒がサポートできる速度をはるかに超えています。 仕事が次のようにほぼ直線的に増加するソリューションが必要です。`n`。 

値自体も次の制限を受けます。`10^5`, しかし、実際には、考えられるすべての値を反復処理する必要はありません。 配列の処理中に役立つ情報は、各値が以前に出現した回数です。 

いくつかの特殊なケースでは、不注意な実装が簡単に壊れてしまう可能性があります。 まず、値はそれ自体とペアになることができます。 例えば：```
1 2
1
1
```位置は 1 つだけなので、正しい結果は次のようになります。`Draw`、ペア数が 1 ではありません。 より一般的には、`[1, 1]`そして`k = 2`、2 つの等しい値は正確に 1 つのペアを形成します。`(1, 2)`は区別されます。 

次に、同じ値を 2 回カウントしてはなりません。 のために`[1, 2]`と`k = 3`、値のペア`1`そして`2`2 つではなく 1 つのペアです。 両方を計算する周波数ベースのソリューション`cnt[1] * cnt[2]`そして`cnt[2] * cnt[1]`どの補数を処理するかを制限しないと、処理は 2 回カウントされます。 

第三に、ポジションの順序は尊重されなければなりません。 のために`[2, 1]`そして`k = 3`、ペア`(1, 2)`最初の位置に次が含まれているため、これはまだ有効です。`2`2番目には次の内容が含まれます`1`。 値は昇順に表示する必要はありません。 重要なのは、最初の位置が 2 番目の位置より前に処理されるということです。 

最後に、ペアの数は、`n`。 と`n = 100000`、それ自体とペアになる値のみを含む配列には次の値を含めることができます。`4,999,950,000`良いペア。 固定幅整数を使用する言語では、32 ビット整数はこのような結果でオーバーフローするため、カウント変数には十分に大きな整数型を使用する必要があります。 Python の整数はこれを自動的に処理します。 

## アプローチ

 直接的な解決策は定義に正確に従います。 あらゆるポジションについて`i`、その後の位置をすべてチェックします`j`かどうかをテストします`a[i] + a[j] == k`。 考慮するのはすべての有効なペアだけなので、正確に 1 回カウントされます。`j > i`。 これですぐに正しい答えが得られますが、`n(n-1)/2`検査するペア。 いつ`n = 100000`、つまり`4,999,950,000`チェックが行われ、アプローチが使用できなくなります。 

条件の構造により、カウントするためのはるかに優れた方法が得られます。 現在値を処理しているとします。`x`。 以前の位置は、その前の値が次のとおりであるときに、その位置と適切なペアを形成します。`k - x`。 個別にポジションを知る必要はありません。 何回かだけを知る必要があります`k - x`すでに登場しています。 

これは、ワンパス周波数法につながります。 維持する`seen[v]`、値の出現数`v`すでに処理されたポジションの間で。 現在値が`x`、まさにあります`seen[k - x]`それと良いペアを形成する初期のポジション。 その数字を答えに加えて、さらに増やします`seen[x]`。 

注文条件`i < j`配列を左から右に処理することで自然に処理されます。 すべてのペアは、2 番目のエンドポイントに遭遇したときにカウントされます。 これにより、値が等しい場合も自動的に解決されます。 もし`x == k - x`、以前の出現のみがカウントされるため、出現がそれ自体とペアになることはありません。 

同じ手順が両方のアレイに独立して適用されます。 次に、2 つのカウントを比較します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 周波数計数 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして目標金額`k`、続いてマフムードとバシャールのアレイ。 
2. 1 つの配列内の適切なペアをカウントするには、頻度マップを作成します`seen`これまでに遭遇した値が含まれています。 ポジションが処理されていないため、最初は空です。 
3. 配列を左から右に処理します。 現在の値については`x`、必要なパートナーを次のように計算します。`k - x`。 
4.追加`seen[k - x]`答えに。 そこに記録されたすべての発生は以前の位置に属しているため、これらの発生のそれぞれが現在の位置との有効なペアを 1 つだけ作成します。 
5.増加`seen[x]`1つずつ。 現在の位置は、以降のすべての要素の前の位置として使用できるようにする必要がありますが、それ自体とペアにするために使用してはなりません。 
6. バシャールアレイについても同じカウント手順を繰り返します。 
7. 2 つのペア数を比較します。 Mahmoud のカウントの方が大きい場合は、印刷します`Mahmoud`。 バシャールのカウントの方が大きい場合は、印刷してください`Bashar`。 それ以外の場合は、印刷します`Draw`。 

### なぜ効果があるのか

 配列のプレフィックスを処理した後、`seen[v]`値が次のプレフィックス内の位置の数に等しい`v`。 次の値を処理するとき`x`、現在位置で終わるすべての適切なペアは、次の値に等しい以前の値を持っている必要があります。`k - x`、そしてまさにあります`seen[k - x]`そういったポジション。 したがって、アルゴリズムは、新しく完成した良好なペアをすべて 1 回だけ追加します。 現在の値が挿入されるため、`seen`パートナーを数えた後にのみ、ポジションはそれ自体とペアになることができません。 すべてのペアには後のエンドポイントが 1 つだけあるため、すべての良好なペアは 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_pairs(arr, k):
    seen = {}
    pairs = 0

    for x in arr:
        pairs += seen.get(k - x, 0)
        seen[x] = seen.get(x, 0) + 1

    return pairs

def solve():
    n, k = map(int, input().split())
    mahmoud = list(map(int, input().split()))
    bashar = list(map(int, input().split()))

    mahmoud_pairs = count_pairs(mahmoud, k)
    bashar_pairs = count_pairs(bashar, k)

    if mahmoud_pairs > bashar_pairs:
        print("Mahmoud")
    elif bashar_pairs > mahmoud_pairs:
        print("Bashar")
    else:
        print("Draw")

if __name__ == "__main__":
    solve()
```の`count_pairs`関数は、アルゴリズムから左から右への不変式を実装します。`seen[x]`含まれる以前の位置の数を格納します。`x`、 その間`pairs`2 つのエンドポイントがすでに処理されている正常なペアの数を格納します。 

ルックアップ`seen.get(k - x, 0)`必要な補数がまだ出現していない場合はゼロです。 これにより、配列のサイズは固定されていますが、すべての可能な値に対して周波数配列を初期化する必要がなくなります。`100001`入力値が制限されているため、これも機能します。 

ループ内の 2 つのステートメントの順序は重要です。 私たちは数えます`seen[k - x]`増加する前に`seen[x]`。 増分が最初に発生した場合、いつ`x == k - x`を使用すると、現在の位置が誤って自身のパートナーとしてカウントされてしまいます。 

Python の任意精度の整数は、オーバーフローすることなく可能な最大ペア数も処理します。 特別な治療は必要ありません`x == k - x`現在の値の周波数には以前の位置のみが含まれるためです。 

2 つの配列は別々にカウントされるため、マフムードの配列の出現がバシャールの配列の出現と相互作用することはありません。

import io

def count_pairs(arr, k):
    seen = {}
    pairs = 0

    for x in arr:
        pairs += seen.get(k - x, 0)
        seen[x] = seen.get(x, 0) + 1

    return pairs

def solve():
    n, k = map(int, input().split())
    mahmoud = list(map(int, input().split()))
    bashar = list(map(int, input().split()))

    m = count_pairs(mahmoud, k)
    b = count_pairs(bashar, k)

    if m > b:
        print("Mahmoud")
    elif b > m:
        print("Bashar")
    else:
        print("Draw")

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_input = input

    try:
        sys.stdin = io.StringIO(inp)
        input = sys.stdin.readline

        output = io.StringIO()
        old_stdout = sys.stdout
        sys.stdout = output

        try:
            solve()
        finally:
            sys.stdout = old_stdout

        return output.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        input = old_input

assert run(
    """7 3
1 1 2 3 4 1 2
2 2 2 1 1 1 2
"""
) == "Bashar", "sample 1"

# Minimum size, no pair is possible.
assert run(
    """1 2
1
1
"""
) == "Draw", "single element"

# All values are equal and every distinct-position pair is valid.
assert run(
    """3 2
1 1 1
1 1 1
"""
) == "Draw", "all equal"

# Boundary values: 1 + 100000 = 100001.

    """4 100001
1 100000 1 100000
1 1 100000 100000
"""

# Equal values must be counted as combinations of distinct positions.

# Maximum pair count still fits in Python's integer type.

 ## 特殊なケース

 配列に要素が 1 つだけ含まれている場合、2 つの異なる位置が必要であるため、ペアは存在できません。 例えば：```
1 2
1
1
```カウントループは次のようになります。`1`、探します`1`以前の位置の中でゼロの出現を見つけてからのみ、現在の位置を記録します。`1`。 どちらの配列もゼロペアを受け取るため、答えは次のようになります。`Draw`。 

値がそれ自体の補数である場合、アルゴリズムは、出現をそれ自体とペアにすることなく、異なる出現間のペアをカウントする必要があります。 考慮する：```
2 2
1 1
1 1
```まず最初に`1`、`seen[1]`はゼロなので、貢献度はゼロです。 挿入したら2本目`1`前の 1 つを見つける`1`そして1ペアを提供します。 両方のプレーヤーが正確に 1 つのペアを持っており、`Draw`。 検索と挿入の順序によって、これが正しく行われます。 

値が入力範囲の限界にある場合でも、特別な場合を除いて必要な補数を処理できます。 考慮する：```
2 100001
1 100000
1 1
```マフムードの 2 番目の値は、`100000`、その補数は`1`。 一つ前`1`が存在するため、Mahmoud は適切なペアを 1 つ入手します。 バシャールには無い`100000`, したがって、ゼロになります。 結果は`Mahmoud`。 

同じ値が何度も出現する場合、アルゴリズム自体は線形のままであっても、ペアの数は二次関数的に増加します。 のために：```
4 10
5 5 5 5
5 5 5 4
```マフムードは`C(4, 2) = 6`2 つすべてが異なるため、良いペア`5`ポジションの合計は`10`。 バシャールは`C(3, 2) = 3`そんなペアたち。 アルゴリズムは、これらのカウントを次のように増分的に生成します。`0 + 1 + 2 + 3`そして`0 + 1 + 2`、それぞれ与える`Mahmoud`。 

最後に、最大配列サイズにより、約 50 億の良好なペアを生成できます。 と`100000`のコピー`1`そして`k = 2`、どのペアも良いです、与える`100000 * 99999 / 2 = 4,999,950,000`ペア。 アルゴリズムは引き続き実行されます`100000`Python の整数演算は結果のカウントを安全に保存します。
