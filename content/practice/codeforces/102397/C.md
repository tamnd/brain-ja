 ## 解決策
 ## 問題の理解

 グリッド点から開始します`(x, y)`ユニットの一連の移動を説明する文字列を受け取ります。 各文字は 1 つの座標を正確に変更します。`U`増加する`y`、`D`減少する`y`、`L`減少する`x`、 そして`R`増加する`x`。 

タスクは、すべての動きを指定された順序で適用し、最終的なグリッド ポイントを印刷するだけです。 パス自体は、その動きが処理された後は必要ありません。 答えには負の座標を含めることが許可されているため、強制する必要があるグリッド上の境界はありません。 

開始座標は次の条件を満たします`1 <= x, y <= 100`、パスの長さは最大で`100`。 これらの制限は非常に小さいため、文字ごとに数回の操作を行うアルゴリズムでも十分に高速になります。 さらに重要なことは、問題の構造が明らかな線形の解決策を示していることです。すべての文字は 1 つの座標に対する 1 つの独立した変更に寄与するため、前の文字を再検討したり、可能なパスを検索したりする必要はありません。 

不注意な実装は、いくつかの境界ケースで失敗する可能性があります。 たとえば、次のように考えてみましょう```
1 1
L
```正しい答えは、```
0 1
```なぜなら`L`減少する`x`1つずつ。 座標が正のままでなければならないと想定する実装では、結果が誤って拒否またはクランプされる可能性があります。 

別の例は```
5 5
DDDDD
```生み出すのは```
5 0
```座標はゼロになることが許可されていますが、負になる可能性もあります。 治療中`1`ウォーク後に下限を設定すると、誤った結果が生成される可能性があるためです。 

移動は互いにキャンセルすることもできます。 のために```
3 4
LRUD
```最終的な位置は```
3 4
```なぜなら`L`そして`R`でキャンセル`x`コーディネートしながら、`U`そして`D`でキャンセル`y`座標。 方向を考慮せずに手の数だけをカウントするソリューションでは、この情報が失われます。 

## アプローチ

 単純だが不必要にコストがかかるアプローチは、パスのすべてのプレフィックスの後の位置を、開始点からそのプレフィックスをスキャンして決定することです。 最初の文字を処理した後、1 文字をスキャンします。 2 番目の文字を処理した後、再度 2 文字をスキャンし、以下同様に処理します。 これは正しいです。各スキャンは対応するプレフィックスを直接シミュレートしますが、同じ動きが繰り返し処理されるからです。 

パスに長さがある場合`n`、これは実行します`1 + 2 + 3 + ... + n = n(n + 1)/2`キャラクター操作。 と`n = 100`、つまり`5050`操作でも、指定された制限を簡単に満たすことができます。 この弱点は、これらの制約に対する実際的なものというより概念的なものであり、まったく不必要な作業を繰り返し実行します。 

重要な観察は、終点が各座標の合計変位のみに依存するということです。 現在の位置を維持したままパスを一度処理できます。 私たちが見るたびに`U`または`D`、更新します`y`; 私たちが見るたびに`L`または`R`、更新します`x`。 各キャラクターは 1 回だけ消費されます。 

ブルート フォース バージョンは、プレフィックスを繰り返しシミュレートすることで最終的に正しいエンドポイントが得られるため機能しますが、現在の位置には以前の動きから取得したすべての情報がすでに含まれているという事実を利用できません。 単一の現在の座標ペアで十分であるという観察により、繰り返されるプレフィックス スキャンを 1 つの直接トラバーサルに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | これらの制約は受け入れられますが、不必要に繰り返します。 
| 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 開始座標を読み取る`x`そして`y`。 これらの値は、動きが起こる前の位置を表します。 
2. パス文字列を読み取ります`s`。 動きの順序によってエンドポイントが決まるため、文字を左から右に処理します。 
3. のすべての文字について`s`、ちょうど 1 つの座標を更新します。 のために`U`、 増加`y`1つずつ。 のために`D`、 減少`y`1つずつ。 のために`L`、 減少`x`1つずつ。 のために`R`、 増加`x`1つずつ。 すべての動きは正確に 1 単位だけ水平または垂直であるため、他の座標は変更されるべきではありません。 
4. すべての文字が処理された後、結果を印刷します。`x`そして`y`。 この時点で、あらゆる動きが座標への変位に寄与しているため、現在のペアがカフェテリアの位置になります。 

### なぜ効果があるのか

 パスのプレフィックスを処理した後、次の不変条件を維持します。`(x, y)`は、元の開始点からそのプレフィックスを実行した後に到達する正確な位置です。 最初はプレフィックスが空であるため、不変式は true になります。`(x, y)`が開始位置です。 次の各文字は、その文字によって定義された動きに従って現在の位置を変更するため、反復のたびに不変条件は true のままになります。 文字列全体が処理されると、プレフィックスは完全なパスになります。`(x, y)`まさに必要な終了点です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())
    s = input().strip()

    for move in s:
        if move == 'U':
            y += 1
        elif move == 'D':
            y -= 1
        elif move == 'L':
            x -= 1
        else:  # move == 'R'
            x += 1

    print(x, y)

if __name__ == "__main__":
    solve()
```最初の行は開始点を直接読み取ります。`x`そして`y`、移動ルールで使用される座標系と一致します。 

反復の前に、パスの末尾の改行が削除されます。 次に、ループは各動きを 1 回だけ検査します。 4 つのケースは 4 つの可能な変更に直接対応するため、維持する必要のあるルックアップ テーブルや補助データ構造はありません。 

この問題では最終座標が負になることが明示的に許可されているため、境界チェックは行われません。 などの条件を追加すると、`if x > 0`左に移動すると問題が変わり、間違った答えが生成される可能性があります。 

Python では整数オーバーフローのリスクもありません。 最大パス長が`100`、各座標は最大で変化します`100`開始値から変化するため、実際の値は非常に小さくなります。 

## 実用的な例

 ### サンプル 1

 入力は```
5 3
UUUDLRLRLRR
```から始まる`(5, 3)`、各動きを順番に処理します。

 | 6 | R | 5 | 5 |

## テストケース```python
import sys
import io

def solve():
    x, y = map(int, input().split())
    s = input().strip()

    for move in s:
        if move == 'U':
            y += 1
        elif move == 'D':
            y -= 1
        elif move == 'L':
            x -= 1
        else:
            x += 1

    print(x, y)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
assert run("5 3\nUUUDLRLRLRR\n") == "6 5", "sample 1"

# Minimum-size input
assert run("1 1\nU\n") == "1 2", "single upward move"

# All moves are equal
assert run("5 5\nLLLLLLLLLL\n") == "-5 5", "ten left moves"

# Boundary and negative coordinate
assert run("1 1\nDDDD\n") == "1 -3", "negative y coordinate"

# Cancellation and order
assert run("100 100\nLRUD\n") == "100 100", "complete cancellation"

# Maximum-size path
assert run("100 100\n" + "R" * 100 + "\n") == "200 100", "maximum path length"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1`と`U`|`1 2`| 最小サイズのパスと単一座標の更新 |
 |`5 5`10個で`L`動く |`-5 5`| 繰り返しの動きとマイナス`x`|
 |`1 1`4つで`D`動く |`1 -3`| 氷点下の交差点 | 氷点下の交差点
 |`100 100`と`LRUD`|`100 100`| 反対の動きの正確なキャンセル |
 |`100 100`100で`R`動く |`200 100`| 最大パス長と繰り返される更新 |

 ## 特殊なケース

 最初のエッジケースは、位置をゼロ以下にする動きです。 のために```
1 1
L
```アルゴリズムはで始まります`(1, 1)`、プロセス`L`、および変更`x`に`0`。 It prints`0 1`。 歩行中に境界制限がないため、ゼロ座標は有効です。 

2 番目のエッジ ケースは、正の開始領域を数回超えて移動しています。 のために```
1 1
DDDD
```連続した`y`値は`0`、`-1`、`-2`、 そして`-3`。 最終的な答えは、`1 -3`。 座標が負になるのを防ぐソリューションでは、パスの適用が誤って停止されてしまいます。 

3 番目のエッジケースは完全なキャンセルです。 と```
3 4
LRUD
```最初の 2 つの動きが変化します`x`から`3`に`2`そしてまた戻る`3`。 次の 2 つの手が変化します`y`から`4`に`5`そしてまた戻る`4`。 最終的な結果は、`3 4`、まさに出発点です。 これにより、不変式が単に動きをカウントするのではなく、実際の現在位置を追跡していることが確認されます。 

最後に、一方向のみを含むパスには特別なケースは必要ありません。 のために```
100 100
RRRR
```四人`R`操作が増えるだけ`x`から`100`に`104`、生産`104 100`。 同じ更新ルールは、単一の移動、繰り返しの移動、および混合パスを処理します。そのため、正確さを犠牲にすることなく実装が小規模に保たれます。
