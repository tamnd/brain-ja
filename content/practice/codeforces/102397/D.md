 ## 解決策
 ## 問題の理解

 あります`n`並んだ家と家`i`含まれています`a[i]`コイン。 バシャールは出発点として任意の家を選択し、終点として任意の家を選択することができます。 それらの間を歩きながら、彼はそのセグメント上のすべての家を訪問し、すべてのコインを集めます。 

タスクは、少なくとも収集するのに必要な最小歩行距離を見つけることです。`x`コイン。 選択したセグメントが家から始まる場合`l`そして家で終わる`r`、徒歩圏内は`r - l`, 隣接する家は1単位離れているためです。 どのセグメントにも十分なコインが含まれていない場合、答えは次のようになります。`-1`。 

入力には以下が含まれます`x`そして`n`、続いて`n`コインの価値。 制約には、`n <= 1000`、したがって、`O(n^2)`アルゴリズムは最大で約 50 万回のセグメント チェックを実行しますが、これは簡単に管理できます。 制約が小さいため総当り的な解決が可能ですが、問題の構造により、`O(n)`解決。 

すべての`a[i]`が正であることが重要なプロパティです。 セグメントに別の家を追加すると合計は増加するだけであり、左側から家を削除すると合計は減少するだけです。 この単調な動作により、考えられるエンドポイントのすべてのペアを再検討することなく、移動間隔を維持できます。 

不適切な実装によって誤った距離が暗黙的に返される可能性のある境界ケースがいくつかあります。 たとえば、1 つの家にすでに十分なコインがある場合、```
5 1
5
```答えは`0`, なぜなら、バシャールは同じハウスからスタートしてストップすることができるからです。 少なくとも次の答えを初期化する実装`1`それは間違いでしょう。 

2 番目のケースは、配列全体がまだ不十分な場合です。```
6 5
1 1 1 1 1
```合計はたったの`5`したがって、正しい出力は次のようになります。`-1`。 不用意にスライディング ウィンドウを実装すると、最初の答えが変更されず、無効な距離が出力される可能性があります。 

3 番目のケースでは、距離と家の数をテストします。 のために```
7 3
2 5 1
```最初の 2 つの家を含むセグメントには、`7`コイン。 そこには2つの家が含まれていますが、バシャールは家からのみ歩きます`1`家へ`2`、したがって、答えは次のとおりです`1`、 ない`2`。 

## アプローチ

 直接的なアプローチは、可能な限りすべての開始ハウスを試し、終了ハウスを一度に 1 位置ずつ拡張することです。 エンドポイントの各ペアについて、合計を計算または維持し、その合計が次の値に達するかどうかを確認できます。`x`。 がある`n(n+1)/2`セグメントが連続しているため、最悪の場合はおおよそ次のようになります。`500,500`セグメントの場合`n = 1000`。 プレフィックス合計を使用すると、各セグメントを一定時間でチェックでき、`O(n^2)`アルゴリズム。 これは正しいです。考えられるすべての間隔が明示的に考慮され、最小の有効な間隔が選択されるからです。 

ブルートフォース手法が機能するのは、答えが連続したセグメントの 1 つであることが保証されているためです。 ただし、多くの間隔が重なるため、不要な作業が行われます。 間隔があれば`[l, r]`すでに十分なコインがあるため、これ以上右に延長しても歩行距離は改善されません。 さらに重要なことは、すべてのコインの値が正であるため、ウィンドウが必要な合計に達したら、その左側の境界を安全に前方に移動して、ウィンドウが短くなるかどうかを確認できることです。 

これにより、スライディング ウィンドウのソリューションが得られます。 窓口を整備しております`[left, right]`と現在のコインの合計。 として`right`先に進むと、ウィンドウに新しい家を追加します。 合計が少なくとも`x`、現在のウィンドウは有効なので、その距離を記録し、ウィンドウが有効なまま左側から家を繰り返し削除します。 このプロセスでは、すべての家を一定の回数だけ検査するため、複雑さが軽減されます。`O(n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 簡単な制約のために受け入れられます |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`left = 0`、`current_sum = 0`、 そして`answer = n`可能なすべての歩行距離よりも大きな値として。 窓は次の家を表します。`left`現在の右エンドポイントを経由します。 
2.移動`right`から`0`を通して`n - 1`。 追加`a[right]`に`current_sum`これは、新しい右のエンドポイントがアクティブ ウィンドウに入ったばかりであるためです。 
3. その間`current_sum >= x`、現在のウィンドウにはすでに十分なコインが含まれています。 Its walking distance is`right - left`ので、更新します`answer`現在の答えとこの距離の小さい方を使用します。 
4. 削除する`a[left]`から`current_sum`そして増加します`left`。 これは、有効なウィンドウを短くしようとします。 残りのウィンドウに少なくとも次の内容が含まれている間、これを続けます。`x`コイン。 
5. 考えられるすべての正しいエンドポイントを処理した後、次のことを確認します。`answer`が更新されました。 そうでない場合は、連続セグメントに到達しません`x`ので、印刷します`-1`; それ以外の場合は印刷します`answer`。 

古い左側のエンドポイントを永久に破棄できる理由は、すべてのコインの値が正であるためです。 一度`[left, right]`十分なコインがある、維持する`left`伸ばしながら固定`right`すでに見つかった間隔よりも短い間隔を生成することはできません。 移動`left`前に進むことが距離を伸ばす唯一の方法です。 

### なぜ効果があるのか

 あらゆる点で、`current_sum`現在のウィンドウ内の住宅の合計とまったく同じです`[left, right]`。 その金額に達するたびに`x`、ウィンドウは有効であり、その距離を記録します。 それから移動します`left`有効性を維持しながら可能な限り前方に進めるため、この特定の`right`、結果のウィンドウは、で終了する最も短い有効なウィンドウです。`right`。 考えられるすべての正しいエンドポイントが処理されるため、グローバルに最も短い有効なセグメントを考慮する必要があります。 すべての値が正であるため、破棄された左端点は、右端点が前進した後に後で役立つことはありません。これが、ワンパス アルゴリズムを正しくする理由です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, n = map(int, input().split())
    a = list(map(int, input().split()))

    left = 0
    current_sum = 0
    answer = n

    for right in range(n):
        current_sum += a[right]

        while current_sum >= x:
            answer = min(answer, right - left)
            current_sum -= a[left]
            left += 1

    if answer == n:
        print(-1)
    else:
        print(answer)

if __name__ == "__main__":
    solve()
```最初の行には、必要なコインの数と家の数が表示されます。 次に、配列は、スライディング ウィンドウが左側の境界から一定時間内に値を削除できるように保存されます。 

メインループは追加します`a[right]`まさに家にいるとき`right`窓に入ります。 内側の`while`ループは、現在のセグメントに十分なコインがある間のみ実行されます。 取り外す前に`a[left]`、現在の距離を記録します`right - left`、これは 2 つのエンドポイント ハウス間の距離です。 

ここでの順序は重要です。 一番左の家を削除する前に、有効なウィンドウを評価する必要があります。 そうしないと、ワンハウスソリューションがスキップされる可能性があります。 たとえば、次の場合`a[left] >= x`、正しい距離は次のとおりです。`0`、その値は家を撤去する前に記録する必要があります。 

最初の答えは`n`。 可能な最大距離は`n - 1`、 それで`n`安全に実際の答えの範囲外です。 スキャン後、値が変化しない場合は、有効なウィンドウが見つからなかったことを意味します。 

Python の整数はオーバーフローせず、可能な最大合計は`1000 * 1000 = 10^6`ともかく。

 ## 特殊なケース

 十分なコインが入った 1 つの家は距離を生み出す必要があります`0`。 のために```
7 1
7
```アルゴリズムは値のみを追加し、合計が少なくとも以下であることを確認します。`7`、レコード`right - left = 0`、そしてその家を撤去します。 最終的な答えは、`0`。 

金の総量が不十分な場合、縮小ループに入るウィンドウは存在しません。 のために```
6 5
1 1 1 1 1
```最終的な合計額は次のとおりです`5`、 それで`answer`初期値のままです`n`。 アルゴリズムは出力します`-1`。 

有効なウィンドウは配列の最後に現れることがあります。 のために```
7 4
1 1 4 3
```最後の2つの家には次のものが含まれています`4 + 3 = 7`。 いつ`right = 3`、ウィンドウは最終的に次のように縮小します。`[2, 3]`、記録された距離は`3 - 2 = 1`。 これにより、最終ハウスを処理する前に誤って停止する実装が捕捉されます。 

距離はセグメント内の家の数より 1 つ減ります。 のために```
10 4
1 2 3 4
```それらの合計は正確に一致するため、4 つの家すべてが必要です。`10`。 アルゴリズムの記録`right - left = 3`、 ない`4`。 バシャールは家そのものを数えるのではなく、家の間を歩くので、この区別は不可欠です。 

最後に、完全一致を有効なものとして扱う必要があります。 のために```
9 5
2 3 4 1 1
```最初の 3 つの家には正確に次のものが含まれます`9`コインなので、アルゴリズムが距離を記録します`2`。 使用する`>`の代わりに`>=`このセグメントは誤って拒否され、スライディング ウィンドウの実装でよくある境界エラーです。
