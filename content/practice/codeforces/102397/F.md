 ## 問題の理解

 あります`n`カップケーキがテーブルの上に置かれ、マフムードが最初の行動をとります。 各ターンで、現在のプレイヤーはカップケーキを 1 つだけ食べることができます。 現在のカップケーキの数が偶数の場合、プレイヤーはちょうど半分を食べるオプションもあります。 ちょうど 1 つのカップケーキに直面したプレイヤーはすぐに負けとなるため、ターンが開始されるとゲームは終了します。`1`。 

タスクは、両方のプレイヤーが最適な動きを選択したときにどちらのプレイヤーが勝つかを決定することです。 入力には 1 つの整数が含まれています`n`、カップケーキの初期数を表します。 出力は`Mahmoud`最初のプレイヤーが勝利戦略を持っている場合、そして`Bashar`さもないと。 

制約`n <= 10^9`が重要な難易度です。 すべての値を検査するソリューション`1`を通して`n`これには最大 10 億の州が必要ですが、これは 1.5 秒の制限時間でサポートできる範囲をはるかに超えています。 たとえ`O(n)`ここでは動的プログラムが遅すぎます。 ゲームを定数時間の特性に還元する必要があります。`n`。 

最小の状態では、直接実装を欺く可能性のあるいくつかのエッジ ケースが明らかになります。 のために`n = 1`、開始位置にすでに 1 つのカップケーキが含まれているため、マフムードはすぐに負けます。そのため、正しい出力は次のようになります。`Bashar`。 最初に手を動かそうとする不注意な実装では、これを通常のゲーム状態として誤って扱うことになります。 

のために`n = 2`、マフムードはカップケーキを1つ食べて去ることができます`1`, つまり、バシャールは負けてしまい、答えはこうなります。`Mahmoud`。 ここにもハーフ演算が存在しますが、同じ状態が生成されます。つまり、ハーフ演算が常に意味のあるものと異なると想定する実装では、この境界を誤って処理する可能性があります。 

のために`n = 3`、マフムードはカップケーキを1つしか食べることができず、`2`。 バシャールはその後去ります`1`、したがってマフムードは負けます。 正しい出力は次のとおりです`Bashar`。 これは、その後の最小の奇数損失ポジションです。`1`かどうかだけをチェックするソリューションを見つけるのに役立ちます。`n`は 1 より大きいです。 

のために`n = 4`、正解は`Mahmoud`。 マフムードはカップケーキを一つ食べて帰ることができる`3`。 その後バシャールは退場を余儀なくされる`2`、そしてマフムードは去ります`1`。 重要な点は、マフムードがハーフ オペレーションを使用する必要がないことです。 常に選ばれるソリューション`n / 2`可能であれば、間違った勝者を生み出す可能性があります。 

## アプローチ

 直接的なアプローチは、カップケーキのすべての数を勝ちか負けとして分類することです。 すべての合法的な手が相手に勝ちのポジションを与える場合、そのポジションは負けています。 少なくとも 1 つの合法的な手が相手に負けの立場を与えた場合、勝利となります。 から始まる`1`負けた場合、答えを計算できます。`2, 3, ..., n`。 

この動的プログラムは正しいです。`x`どちらかの数値が小さくなります`x - 1`または`x / 2`。 したがって、処理するときに、`x`、考えられるすべての目的地の結果はすでにわかっています。 ただし、以下までの検討が必要です。`n`州。 のために`n = 10^9`これは、約 10 億回の状態評価を意味し、利用可能な遷移をチェックする作業は 20 億回近くの遷移チェックに及ぶ可能性があります。 メモリ要件も次のようになります。`O(n)`テーブル全体が保存されている場合。 

ゲーム グラフは常に小さい数値に向かって移動するため、総当たり計算は機能しますが、上限が大きすぎるため失敗します。 より迅速な解決策を明らかにする観察は、ポジションの同等性を観察することで得られます。 位置`1`負けています。 より大きいすべての奇数`1`可能な手は 1 つだけです。`x`に`x - 1`、これは偶数です。 すべての偶数には次への移動があります。`x - 1`、これは奇妙です。 すべての奇数ポジションが負けていて、すべての偶数ポジションが勝ちである場合、この関係は、より大きな数字ごとに再現されます。 

したがって、奇数のポジションは、その唯一の手が偶数の勝ちのポジションにつながるため、負けになります。 カップケーキを 1 つ食べると奇数の負けにつながるため、偶数のポジションが勝ちとなります。 半分の演算はこの分類を妨げません。偶数が半分になると、結果は偶数か奇数のいずれかになりますが、偶数の位置にはすでに勝ち手があります。`n - 1`, したがって、追加の動きによって負けることはありません。 

したがって、ゲーム全体は、カップケーキの初期数が奇数か偶数かによってのみ決まります。 もし`n`が互角の場合、マフムードが勝ちます。 もし`n`奇妙です、バシャールが勝ちます。

 ## アルゴリズムのチュートリアル

 1. カップケーキの初期数を読み取ります。`n`。 ゲーム パターンを導出した後に必要な唯一のプロパティは、そのパリティです。 
2. もし`n`偶数、出力`Mahmoud`。 マフムードはカップケーキをちょうど 1 つ食べて立ち去ることができるため、偶数の立場が勝ちです。`n - 1`、これは奇妙であるため、次のプレイヤーが負けます。 
3. もし`n`奇数です、出力`Bashar`。 マフムードは奇数からのみ移動できます`n`偶数に`n - 1`、均等の位置は、それを受け取ったプレーヤーの勝ちです。 
4. 特殊なケース`n = 1`すでに奇妙なケースでカバーされています。 Mahmoud は 1 つのカップケーキから開始して負けたため、出力は次のようになります。`Bashar`。 

### なぜ効果があるのか

 不変条件は、カップケーキのすべての奇数が負けの位置であり、すべての偶数が勝ちの位置であるということです。 基本的なケース`1`負けています。 奇数のために`n > 1`、唯一の合法的な措置は、`n - 1`、これは互角なので、相手の勝ちです。 したがって、奇数ポジションは負けています。 偶数の場合`n`、カップケーキを 1 つ食べると、`n - 1`、これは奇数であるため、相手にとっては負けなので、偶数の位置が勝ちです。 これは、以下の全範囲を含むすべての正の整数の分類を証明します。`10^9`。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())

    if n % 2 == 0:
        print("Mahmoud")
    else:
        print("Bashar")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("4\n") == "Mahmoud", "sample 1"
assert run("3\n") == "Bashar", "sample 2"

# Minimum-size input
assert run("1\n") == "Bashar", "n = 1 is immediately losing"

# Smallest even input
assert run("2\n") == "Mahmoud", "n = 2 is winning"

# Odd boundary
assert run("999999999\n") == "Bashar", "large odd input"

# Maximum-size input
assert run("1000000000\n") == "Mahmoud", "maximum even input"
