 ## 解決策
 ## 問題の理解

 私たちは持っています`n`ソリューション ファイル、およびすべてのファイルが正確に占有します`x`GB。 A single flash memory can hold at most`a`GB であり、ファイルは完全に 1 つのメモリ内に留まる必要があります。 目標は、すべてを保存するために必要なフラッシュ メモリの最小数を見つけることです。`n`ファイル。 

重要な数量は、1 つのメモリ単独の総ストレージ容量ではなく、メモリ内に収まる完全なファイルの数です。 すべてのファイルは同じサイズなので、1 つのメモリに正確に保存できます。`floor(a / x)`ファイル。 この数がわかったら、問題は、すべてを含めるにはそのサイズのグループがいくつ必要かということになります。`n`ファイル。 

制約`n <= 10^5`これは、線形アルゴリズムであっても 1.5​​ 秒の制限内であれば十分に高速であることを意味します。 ただし、問題の構造は一般的な充填問題に比べて非常に単純なので、一定時間で解くことができます。 の境界`x`そして`a`また、通常の整数演算には十分小さいので、Python の整数にはオーバーフローの心配はありません。 

不正な実装が露呈する可能性のある境界ケースがいくつかあります。 考慮する`1 5 5`。 1 つのファイルが 1 つのメモリを正確に埋めるため、答えは次のようになります。`1`。 等価性を許可する代わりに厳密な等価性を使用する不注意な実装では、ファイルが誤って拒否される可能性があります。 

もう一つの重要な事例は、`5 2 5`。 それぞれの思い出が残っている`floor(5 / 2) = 2`ファイルなので 3 つのメモリが必要です。 正しい出力は次のとおりです`3`。 単純に合計ファイルサイズをメモリ容量で割ると、`ceil(10 / 5) = 2`これは、各メモリの未使用の 1 GB を結合してファイルを保存することができないため、間違っています。 

最後に、いつ`x = a`、 例えば`4 7 7`、各メモリには 1 つのファイルだけを保持できるため、答えは次のようになります。`4`。 整数の丸めにより複数のファイルが適合すると誤って仮定した数式は、この境界で失敗します。 

## アプローチ

 完全に一般的な総当たりの解決策では、問題をパッキングの問題として扱い、メモリへのファイルの可能な割り当てを試みることができます。 固定番号の場合`k`思い出のひとつひとつ、`n`ファイルは最初はそれらのいずれかに割り当てることができます`k`思い出、与えること`k^n`可能な割り当て。 あらゆる可能性を試す`k`から`1`を通して`n`合計が生成されます`1^n + 2^n + ... + n^n`課題。 最悪の場合`n = 10^5`、これは天文学的に大きく、おおよそ次のものによって支配されています。`10^(500000)`、したがって、そのようなアプローチは完全に実行不可能です。 

この強引なアプローチは、ファイルを配布するあらゆる可能な方法を考慮し、有効なパッキングが存在するかどうかを識別できるため、正しいです。 問題は、すべてのファイルがまったく同じサイズであるという最も強力な構造特性を無視していることです。 

すべてのファイルは等しいため、個々のファイルの保存先を決定する必要はありません。 1 つのメモリに収まる完全なファイルの最大数を知る必要があるだけです。 その数字が`k = floor(a / x)`の場合、すべてのメモリには最大でも収容できます。`k`ファイルを常に正確に達成できます`k`十分なファイルが残っている場合は必ずメモリ内にファイルを追加します。 したがって`n`ファイルには上限が必要です`n / k`思い出。 

上限分割は次のように整数演算で計算できます。`(n + k - 1) // k`。 以来`x <= a`、私たちはいつも持っています`k >= 1`, したがって、割り算は有効です。 

ブルート フォースは有効なパッキングを明示的に検索するため機能しますが、可能な代入の数が膨大になると失敗します。 すべてのファイルのサイズが同じであるという観察により、ファイルのアイデンティティを完全に破棄し、問題を 1 つの整数の除算に減らすことができます。

 ## アルゴリズムのチュートリアル

 1.読む`n`、`x`、 そして`a`。 ここ`n`はファイルの数、`x`は各ファイルのサイズであり、`a`フラッシュメモリ1枚の容量です。 
2. コンピューティング`files_per_memory = a // x`。 これは、1 つのメモリに収まる完全なファイルの最大の整数です。 ファイルを分割できないため、容量の端数の残りは使用できません。 
3. 天井除算を使用してメモリの数を計算します。`answer = (n + files_per_memory - 1) // files_per_memory`。 これでラウンド`n / files_per_memory`最終メモリに含まれるファイルの数が他のメモリよりも少ない可能性があるためです。 
4. 印刷`answer`。 

### なぜ効果があるのか

 しましょう`k = floor(a / x)`。 メモリにはこれ以上のものを含めることはできません`k`ファイル、なぜなら`k + 1`ファイルに必要となるのは`(k + 1) * x > a`GB。 同時に、最大でもどのグループでも、`k`ファイルが適合するため`k * x <= a`。 したがって、ファイルは常に最大で 1 つのグループに分割できます。`k`ファイル、およびそのようなグループの最小数は正確に`ceil(n / k)`。 このアルゴリズムはこれら 2 つの量を正確に計算するため、可能な限り最小限のメモリを生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, x, a = map(int, input().split())

files_per_memory = a // x
answer = (n + files_per_memory - 1) // files_per_memory

print(answer)
```最初の行は 3 つの入力値をすべて読み取ります。 テスト ケースは 1 つだけであるため、テスト ケースをループする必要はありません。 

表現`a // x`重要なフロア分割を使用します。 たとえば、メモリに容量がある場合、`7`GB と各ファイルの使用量`2`GB、`7 // 2`は`3`つまり、3 つの完全なファイルのみが適合します。 残りの 1 GB を 4 番目のファイルに使用することはできません。 

最後の式は、浮動小数点演算を使用せずに上限除算を実行します。 使用する`(n + files_per_memory - 1) // files_per_memory`精度の問題を回避し、正確な割り算を正しく処理します。 例えば、`10`を含むファイル`3`メモリあたりのファイル数は`(10 + 3 - 1) // 3 = 4`、 その間`9`ファイルが与える`(9 + 3 - 1) // 3 = 3`。 

Python には整数オーバーフローの問題はなく、ここでの最大中間値は Python の整数容量と比較すると小さいです。 

## 実用的な例

 最初のサンプルの入力は次のとおりです。`10 2 7`。 

|`n`|`x`|`a`|`a // x`| 答え |
 | --- | --- | --- | --- | --- |
 | 10 | 2 | 7 | 3 | 4 |

 各メモリには最大 3 つのファイルが保持されます。`3 * 2 = 6`GBはフィットしますが、`4 * 2 = 8`GBはそうではありません。 10 個のファイルは、3 つのファイルと残り 1 つのファイルからなる 3 つの完全なグループを形成するため、4 つのメモリが必要になります。 これは、メモリの未使用容量を別のメモリと結合できない理由を示しています。 

2 番目のサンプルの入力は次のとおりです。`3 5 15`。 

|`n`|`x`|`a`|`a // x`| 答え |
 | --- | --- | --- | --- | --- |
 | 3 | 5 | 15 | 3 | 1 |

 1 つのメモリにちょうど 3 つのファイルを保存できるのは、`3 * 5 = 15`GB。 したがって、3 つのファイルはすべて 1 つのメモリに収まります。 これにより、容量との等価性が許可され、天井分割が正しく返されることが確認されます。`1`ファイル数がメモリあたりの容量で正確に割り切れる場合。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n, x, a = map(int, input().split())

    files_per_memory = a // x
    answer = (n + files_per_memory - 1) // files_per_memory

    print(answer)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    output = sys.stdout.getvalue().strip()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return output

# Provided samples
assert run("10 2 7\n") == "4", "sample 1"
assert run("3 5 15\n") == "1", "sample 2"

# Minimum-size input
assert run("1 1 1\n") == "1", "minimum values"

# Every file exactly fills one memory
assert run("100000 100000 100000\n") == "100000", "x equals a"

# Exact divisibility
assert run("12 3 10\n") == "4", "exact number of groups"

# Remainder after full groups
assert run("10 2 5\n") == "4", "off-by-one remainder case"

# Maximum n with one file per memory
assert run("100000 99999 99999\n") == "100000", "maximum n boundary"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1 1`|`1`| 最小サイズの入力 |
 |`100000 100000 100000`|`100000`| 最大`n`そして`x = a`|
 |`12 3 10`|`4`| 4 つのグループへの正確な分割 |
 |`10 2 5`|`4`| 残容量と天井区分 |
 |`100000 99999 99999`|`100000`| メモリごとに 1 つのファイルを持つ大きな境界 |

 ## 特殊なケース

 ファイルがメモリ容量と正確に一致する場合、アルゴリズムはそれを正しく許可します。 入力用`1 5 5`、`a // x`は`5 // 5 = 1`、 それで`(1 + 1 - 1) // 1 = 1`。 出力は`1`。 これにより、誤って使用する実装が捕捉されます。`<`の代わりに`<=`容量について推論するとき。 

メモリに別のファイルを入れるには小さすぎる未使用スペースがある場合、そのスペースは他のメモリには役立ちません。 入力用`5 2 5`、それぞれの記憶が保持します`5 // 2 = 2`ファイル。 計算は次のようになります`(5 + 2 - 1) // 2 = 3`したがって、出力は次のようになります`3`。 2 つのメモリには 4 つのファイル用のスペースがあり、5 番目のファイルには 3 番目のメモリが必要です。 

いつ`x = a`、各メモリに収まるファイルは 1 つだけです。 入力用`4 7 7`、`a // x = 1`、したがって、答えは次のとおりです`(4 + 1 - 1) // 1 = 4`。 すべてのファイルには独自のメモリが必要であり、これはまさにアルゴリズムが報告するものです。 

すべてのファイルが 1 つのメモリに収まる場合、天井分割は自然に 1 を返します。 入力用`3 5 15`、メモリあたりの容量は`15 // 5 = 3`、与える`(3 + 3 - 1) // 3 = 1`。 この状況では特別なケースは必要ありませんが、これはこの式の便利な特性です。
