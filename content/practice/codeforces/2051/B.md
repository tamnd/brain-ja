 ## 解決策
 ## 問題の理解

 Monocarp は数日間のハイキングに出かけており、毎日の距離の繰り返しパターンがあります。彼は歩きます。`a`初日はキロメートル、`b`2番目に、`c`3 番目では、そのサイクルが無限に繰り返されます。 目標の合計距離が与えられた場合`n`、Monocarp が到達またはそれを超える正確な日を決定するように求められます。`n`累計でキロメートル。 各テスト ケースでは、次の 4 つの整数が与えられます: ターゲット距離`n`と 3 日サイクルの距離`a`、`b`、`c`。 出力は単に Monocarp が旅を完了した日の番号です。 

この制約により、最大 10,000 のテスト ケースが許可されます。`n`最大 10 億、毎日の距離は最大 100 万です。 これは、毎日 1 つずつシミュレーションする単純なアプローチでは、1 つのテスト ケースに対して最大 10 億の操作を実行できることを意味しますが、これでは遅すぎます。 どのようなアプローチでも、繰り返されるパターンと非常に大規模な問題が発生する可能性を考慮する必要があります。`n`毎日を個別に繰り返す必要はありません。 

エッジケースは、移動が最初のサイクル内で完了する場合、特に初日自体に発生します。 たとえば、次の場合`n = 6`そして初日の距離`a = 6`, モノカープはすぐに終了します。 もう 1 つのエッジケースは次のような場合です`n`が非常に大きいため、最後の部分サイクルが到達に寄与する前に、多くの完全なサイクルが強制されます。`n`。 不用意に実装すると、毎日反復しようとして、タイムアウトになったり、部分的なサイクルの終わりにオフバイ 1 カウントが誤って処理されたりする可能性があります。 

## アプローチ

 ブルートフォース ソリューションでは、移動距離を毎日シミュレートし、現在の合計距離を維持し、合計距離がそれに達するか超えると停止します。`n`。 これは正しいですが、最悪のケースは次のような場合に発生します。`n = 10^9`1 日あたりの距離が短い (たとえば、`a = b = c = 1`）。 このアルゴリズムには約 10 億回の反復が必要ですが、1 秒以内には実行できません。 

重要な観察は、距離が 3 日のサイクルで繰り返されるということです。 全サイクルの合計は次のようになります。`cycle_sum = a + b + c`。 に到達するまでに必要な完全なサイクルの数を計算できれば、`n`、毎日繰り返すのではなく、3 日の倍数でジャンプできます。 完全なサイクルを完了した後、到達まであと最大 3 日チェックするだけで済みます。`n`。 これにより、問題は潜在的に数十億回の反復から、テスト ケースあたり最大でも数回の単純な算術演算に軽減されます。 

ブルート フォース アプローチは概念的にはシンプルですが時間がかかります。一方、最適化されたアプローチはシーケンスの周期性を利用して計算を大幅に削減します。 単純な計算と、最後の部分サイクルの条件付きチェックを組み合わせることができます。

 ## アルゴリズムのチュートリアル

 1. 入力値の読み取り`n`、`a`、`b`、`c`単一のテストケースの場合。 これらは目標距離と 3 日間の歩行距離を表します。 
2. 1 つの丸 3 日サイクルの合計を計算します。`cycle_sum = a + b + c`。 これは、Monocarp が 3 日間で歩く合計距離を表します。 
3. 超過する前に収まる完全な 3 日サイクルの数を計算します。`n`:`full_cycles = (n - 1) // cycle_sum`。 の`-1`正確な合計がサイクル境界に達した場合に、最終日を正しく計算できるようになります。 乗算する`full_cycles`3までに入手`days = full_cycles * 3`。 これは、すべての完全なサイクル後の日数です。 
4. 全サイクル後の累積距離を計算します。`distance_so_far = full_cycles * cycle_sum`。 
5. サイクル内の次の日にわたって繰り返します (最大 3 日間:`a`、`b`、`c`)、毎日の距離を次のように加算します。`distance_so_far`。 追加するたびに、次のことを確認します。`distance_so_far >= n`。 この条件を満たす最初の日が答えです。 インクリメント`days`日が増すごとに。 
6. 出力`days`Monocarpが少なくとも到達する日として`n`キロメートル。 

機能する理由: 歩行距離の周期性を利用することで、日ごとのシミュレーションを個別に必要とせずに、3 日のサイクル全体を飛び越えることができます。 部分的なサイクルはわずか 3 日と小さいため、それを繰り返すのは無視できます。 不変条件は、全サイクルを考慮した後、`distance_so_far`は常に未満です`n`、および合計を上回る次の部分サイクルの初日`n`正確な完了日であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, a, b, c = map(int, input().split())
    cycle_sum = a + b + c
    
    # number of full cycles
    full_cycles = (n - 1) // cycle_sum
    days = full_cycles * 3
    distance_so_far = full_cycles * cycle_sum
    
    for d in [a, b, c]:
        if distance_so_far >= n:
            break
        distance_so_far += d
        days += 1
    
    print(days)
```コードは最初にテスト ケースの数を読み取ります。 テスト ケースごとに、3 日サイクルの合計とジャンプする完全なサイクル数が計算されます。 次に、次の部分サイクルから日数を追加し、追加するたびに合計距離が以下に達したかどうかを確認します。`n`。 反復が終わった`[a, b, c]`追加チェックが 3 回を超えないようにします。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n, a, b, c = map(int, input().split())
        cycle_sum = a + b + c
        full_cycles = (n - 1) // cycle_sum
        days = full_cycles * 3
        distance_so_far = full_cycles * cycle_sum
        for d in [a, b, c]:
            if distance_so_far >= n:
                break
            distance_so_far += d
            days += 1
        output.append(str(days))
    return "\n".join(output)
