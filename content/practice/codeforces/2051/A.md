 ## 解決策
 ## 問題の理解

 長さの 2 つの配列が与えられます`n`1 つは Monocarp が毎日解決できる問題の数を表し、もう 1 つは Stereocarp がトレーニングした場合に毎日解決できる問題の数を表します。 

Monocarp は、トレーニングする日のサブセットを完全に自由に選択できます。 ただし、Stereocarp のスケジュールは事後対応です。Monocarp がその日にトレーニングするたびに行われます。`i`そして`i < n`, ステレオカープは日中訓練を強いられます`i + 1`。 これは、Stereocarp のトレーニング日は Monocarp の選択によって完全に決定されますが、常に 1 日前倒しされることを意味します。 

スコアの差は、Monocarp が解決した問題の合計から Stereocarp が解決した問題の合計を引いたものとして定義されます。 課題は、この差を最大化するように Monocarp のトレーニング日を選択することです。 

日間の相互作用はローカルです: 日の選択`i`Monocarp に直接影響を与える`a[i]`、当日に費用が発生する場合もあります`i+1`経由`b[i+1]`。 この依存関係構造が重要な制約です。 

入力サイズは小さく、`n ≤ 100`そして`t ≤ 1000`。 これにより、おおよその範囲を超えるものは即座に除外されます`O(n^3)`実際のテストケースごとに。 平`O(n^2)`快適です。 

単純な落とし穴は、Monocarp と Stereocarp を個別に扱うことです。 たとえば、すべてのポジティブを選択すると、`a[i]`そしてすべてを差し引く`b[i]`Stereocarp の参加は独立していないので、それは間違っています。 それはモノカープの選択によって引き起こされます。 

最終日には、別の微妙な特殊なケースが発生します。 Monocarpが当日にトレーニングする場合`n`, 立体果皮は反応しないので、`a[n]`それは「フリーゲイン」です。 境界効果を無視した貪欲な戦略は、この立場を誤って評価することになります。 

## アプローチ

 この強引なアイデアは、Monocarp の日のすべてのサブセットを試してみることです。 サブセットごとに、Stereocarp の強制的な動作を次のようにシミュレートします。`i`選ばれた場合、マークします`i+1`Stereocarp のトレーニング日が存在する場合は、その結果の差を計算します。 これはルールに直接従うため、正しいです。 ただし、`2^n`サブセット、そしてそれぞれに必要な場合があります`O(n)`シミュレーション、与える`O(n·2^n)`それは、たとえ`n = 100`。 

重要な簡素化は、決定が 1 ステップしか前進しないことに気づくことから生まれます。 Stereocarp が当日トレーニングするかどうか`i`Monocarpがその日にトレーニングしたかどうかのみに依存します`i-1`。 これは、前の選択の効果を維持しながら、左から右に処理することを示唆しています。 

毎日、昨日のせいで Stereocarp が今日のトレーニングを「すでに強制されている」かどうかを知る必要があるだけです。 これにより、2 状態の動的システムが作成されます。Stereocarp が今日トレーニングするかしないか、Monocarp が今日トレーニングするかどうかを決定します。 遷移はローカルであるため、数日間にわたる動的プログラミングが可能になります。 

Stereocarp が当日に強制されるかどうかをキャプチャする DP 状態を定義します。 そこから、Monocarp がトレーニングするかどうかを決定します。これは、現在のゲインと次の状態の両方に影響します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n · 2^n) | O(n) | 遅すぎる |
 | DP (日ごとの状態 + 強制フラグ) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 Stereocarp が当日にトレーニングを強制されているかどうかを追跡しながら、左から右に日を処理します。 

1. DP テーブルを定義する`dp[i][f]`、 どこ`i`は現在の日であり、`f`Stereocarp がその日にトレーニングを強制されるかどうかです`i`。 この値には、日からの達成可能な最大の差が格納されます。`i`これからも。 
2.初期化`dp[n+1][0] = dp[n+1][1] = 0`最終日を過ぎると、それ以上の寄付はありません。 
3. 毎日について`i`から`n`まで`1`、両方の状態の遷移を計算します`f = 0`そして`f = 1`。 
4. Monocarp が当日トレーニングしない場合`i`、その後:

 - その日は何も得られない`i`- Sterecarp は次の場合にのみトレーニングします。`f = 1`、貢献`-b[i]`スコアに合わせて
 - 次の状態は次のようになります`0`新たな強制が導入されないため
 5. Monocarp が当日にトレーニングする場合`i`、その後:

 - 彼は得をする`a[i]`- もし`f = 1`、ステレオカープも当日トレーニングします`i`、貢献`-b[i]`- さらに、Monocarp は Stereocarp にその日のトレーニングを強制します`i+1`、次の状態は次のようになります`1`6. それぞれの「トレイン」および「スキップ」オプションを最大限に活用します。`(i, f)`。 
7. 答えは次のとおりです。`dp[1][0]`なぜなら、最初は Stereocarp はトレーニングを強制されていないからです。 

### なぜ効果があるのか

 DP 状態は、唯一の関連する歴史的依存関係、つまり以前の Monocarp のアクションが今日 Stereocarp を強制するかどうかを完全に捕捉します。 このわずかな情報以外に、これより前の日は現在の決定に影響を与えることはできません。 これにより、問題は数日間にわたるマルコフ プロセスとなり、最適な下部構造が保持され、状態間の遷移時に相互作用が失われないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = [0] + list(map(int, input().split()))
        b = [0] + list(map(int, input().split()))

        dp = [[0] * 2 for _ in range(n + 2)]

        for i in range(n, 0, -1):
            for f in range(2):
                skip = dp[i + 1][0] - (b[i] if f else 0)

                force_next = 1 if i < n else 0
                take = a[i]
                if f:
                    take -= b[i]
                take += dp[i + 1][force_next]

                dp[i][f] = max(skip, take)

        print(dp[1][0])

if __name__ == "__main__":
    solve()
```この実装では配列にパディングを行うため、インデックス付けがクリーンになり、off-by-one エラーが回避されます。 DPはボトムアップなので、`dp[i+1]`は常に前に計算されます`dp[i]`。 唯一の微妙な点は、Monocarp がトレーニングするときの遷移です。`force_next = 1`もし`i < n`、その日だから`n`効果は伝わりません。

 ## 特殊なケース

 重大なエッジケースは最終日です。 Monocarpが当日にトレーニングする場合`n`, 立体果肉は反応しません。 DP は設定によってこれを明示的に処理します。`force_next = 0`いつ`i = n`。 これにより、境界を超えた誤った伝播が防止されます。 

別のケースは、すべてが`a[i]`大きくてすべて`b[i]`小さいです。 最適な解決策は「すべてを取る」となり、すべての強制ペナルティは利益によって支配されるため、DP はこれを確認します。 

3番目のケースは交互に大きくなります`b[i]`価値観。 ここで、最適解は、Stereocarp のアクティブ化を回避するために戦略的にスキップされることがよくありますが、強制フラグによって以前の決定のコストが 1 ステップだけ前方に持ち込まれるため、DP はこれを正しく捕捉します。
