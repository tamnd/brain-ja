 ## 解決策
 ## 問題の理解

 正の整数の配列とターゲット間隔が与えられます。$[x, y]$。 配列から正確に 2 つの異なる要素を削除することができます。 それらを削除した後、残っているものの合計を確認し、この残りの合計が指定された間隔内に収まるようにします。 

同様に、配列の合計が$S$、位置にある要素を削除します$i$そして$j$合計が残ります$S - a_i - a_j$。 条件は次のようになります。$$x \le S - a_i - a_j \le y$$並べ替えると次のようになります。$$S - y \le a_i + a_j \le S - x$$つまり、タスクは純粋にペアを数えるということです$(i, j)$その合計は合計によって決定される一定の範囲内にあります。 

入力サイズはテスト ケース全体で大きく、最大で$2 \cdot 10^5$合計要素。 どれでも$O(n^2)$テストケースごとのアプローチはすぐに失敗します。$n = 2 \cdot 10^5$について暗示するでしょう$2 \cdot 10^{10}$ペアチェック。 これが私たちを後押しします$O(n \log n)$または$O(n)$テスト ケースごとに、通常は 2 つのポインターによる並べ替えまたは二分検索を使用します。 

微妙な失敗のケースは、変換された境界を正しく処理することで発生します。 残額の条件をペアの和の条件に変換するため、混同すると間違いが起こりやすい$x, y$または、テスト ケースごとの境界を再計算するのを忘れます。 

具体的なエッジケースは、すべての要素が同一で、有効範囲が非常に狭い場合です。 たとえば、次の場合$a = [3, 3, 3]$、$x = 4$、$y = 4$、合計は 9 なので、$5 \le a_i + a_j \le 5$、それは不可能です。 正しく減算することを忘れた単純な実装では、ペアを誤ってカウントする可能性があります。 

もう 1 つの特殊なケースは、変換後に境界が負になるか、非常に大きくなる場合です。 以来$a_i \ge 1$、合計は常に正であるため、範囲クリッピング ロジックは特別なケースを使用せずに正しく動作する必要があります。 

## アプローチ

 強引なアイデアは簡単です。すべてのペアを試してください。$(i, j)$、それらを削除した後の残りの合計を計算し、それが次の場所にあるかどうかを確認します。$[x, y]$。 これは定義に直接従うため、正しいです。 ただし確認が必要です$\frac{n(n-1)}{2}$テストケースあたりのペア数は、中程度の場合でも実行不可能になります。$n$。 

重要な観察は、2 つの要素の削除は位置ではなく合計にのみ依存するということです。 条件を次のように書き換えると、$a_i + a_j$の場合、問題は古典的な制約付きペア合計カウント タスクになります。つまり、値の範囲内にあるペアの数をカウントします。 

配列をソートした後、合計を使用してペアをカウントできます$\le R$線形時間での 2 ポインター スイープを使用します。 2 つの境界のカウントを計算して減算することで、答えが得られます。 

制約がペアごとにローカルであるため、ブルート フォースは機能しますが、二次スケーリングが原因で失敗します。 ペア合計範囲への変換により、問題がソートと単調なカウント構造に軽減され、2 つのポインターが有効になります。

 ## アルゴリズムのチュートリアル

 まず問題をペア和制約に変換します。 

1. 合計値を計算する$S$配列の。 除去後に何が残っているかによって状態が異なるため、これが必要になります。 
2. 残りの合計に関する条件を、削除されたペアの合計に関する条件に変換します。$$L = S - y,\quad R = S - x$$有効なペアはすべて次の条件を満たす必要があります$L \le a_i + a_j \le R$。 
3. 配列をソートします。 ソートは、ペアの合計を単調に推論できるため、不可欠です。 
4. 合計が得られるペアの数を数えます$\le R$。 これは 2 ポインタ手法を使用して行われます。1 つのポインタは左から開始し、もう 1 つのポインタは右から開始し、現在の合計が大きすぎるかどうかに基づいて縮小または拡張します。 
5. 合計が得られるペアの数を数えます$< L$、または同等に合計でペアをカウントします$\le L - 1$。 
6. 減算: 有効なペア = count($\le R$) − カウント($\le L - 1$）。 

2 ポインターのカウントが機能するのは、固定右ポインターの場合、特定のインデックスまでのすべての左位置が有効なペアを形成するためです。そのため、個別にチェックするのではなく、カウントを一括で蓄積できます。 

### なぜ効果があるのか

 ソート後、配列には、右のインデックスを増加してもペアの合計のみが増加するという特性があります。 この単調性により、各固定値に対して次のことが保証されます。$r$、境界インデックスがあります$l$すべてがそうなるように$i < l$満足する$a_i + a_r \le X$。 これにより、連続した有効なセグメントが作成され、線形カウントが可能になります。 すべてのペアは、すべての正しいエンドポイントにわたって正確に 1 回カウントされ、正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_leq(a, bound):
    n = len(a)
    l, r = 0, n - 1
    res = 0
    while l < r:
        if a[l] + a[r] <= bound:
            res += r - l
            l += 1
        else:
            r -= 1
    return res

def solve():
    t = int(input())
    for _ in range(t):
        n, x, y = map(int, input().split())
        a = list(map(int, input().split()))
        s = sum(a)

        L = s - y
        R = s - x

        a.sort()

        ans = count_leq(a, R) - count_leq(a, L - 1)
        print(ans)

if __name__ == "__main__":
    solve()
```中心となる実装の詳細は、合計がしきい値を超えるペアをカウントするヘルパー関数です。 両端から縮小ウィンドウを使用します。 合計が十分に小さい場合、間にあるすべての要素が`l`そして`r`とペアになった`l`は有効なので追加します`r - l`ワンステップで。 

引き算のステップが重要です。 包含範囲を計算します$[L, R]$2 つのプレフィックス スタイル カウントの差によって計算されます。 を忘れて`L - 1`調整はオフバイワンエラーの一般的な原因です。

 ## 特殊なケース

 重大なエッジ ケースは、変換された境界が負になる場合です。 考慮する：```
n=3, x=8, y=10
a=[3,2,1]
```ここ$L=-4$、$R=-2$。 アルゴリズムは引き続き正常に実行されますが、すべてのペアの合計が正であるため、両方のカウント関数は 0 を返します。これにより、無効な範囲に対して特殊な場合のフィルタリングが必要ないことが確認されます。 

もう 1 つのケースは、すべての要素が同一である場合です。```
n=5, x=1, y=1
a=[1,1,1,1,1]
```合計の合計は 5 なので、必要なペアの合計は正確に 4 になります。すべてのペアは 2 を寄与するため、どれも条件を満たすものはありません。 2 ポインター法では、すべての合計が一貫して境界を下回ったり上回ったりするため、ゼロが正しくカウントされ、減算では調整エラーがなくゼロが得られます。 

最後の微妙なケースは、有効な間隔が非常に広く、事実上すべてのペアを許可する場合です。 アルゴリズムはすべてをカウントします$\frac{n(n-1)}{2}$経由でペアリングします$\le R$関数を使用し、下限からゼロを減算すると完全な組み合わせカウントが生成され、二重カウントやペアの欠落がないことが確認されます。
