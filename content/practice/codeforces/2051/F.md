 ## 解決策
 ## 問題の理解

 私たちは、特別なカードであるジョーカーの相対的な位置のみが重要となるトランプのデッキを扱っています。 最初はジョーカーがその位置に座っています`m`一列に並んで`n`カード。 次に、一連の操作を実行します。 各操作で位置を選択します`a_i`現在のデッキのその位置にあるカードを取り出し、一番上または一番下のいずれかに挿入します。 

ジョーカー自体は直接動かされることはありませんが、カードがジョーカーの前から取り除かれたり、ジョーカーの前に挿入されたりすると、その位置は間接的に変わります。 すべての操作の後、ジョーカーの最終的な 1 つの位置を尋ねられるのではなく、各ステップで選択したカードを一番上または一番下に移動するすべての選択肢に応じて、ジョーカーが占める可能性のある異なる位置がいくつあるかを尋ねられます。 

つまり、状態は 1 つのデッキではなく、成長し続ける可能なデッキのセットです。 これらすべての考えられる結果にわたって、各操作後にジョーカーがどのインデックスに位置するかを追跡し、そのセットのサイズを出力するだけです。 

ここでの重要なシグナルは制約です。 デッキサイズ`n`は 10^9 まで大きくなる可能性があるため、デッキをシミュレートしたり、位置によってインデックス付けされた明示的な構造を維持したりすることはできません。 テストあたりの演算数はテスト全体で合計最大 2·10^5 であり、最悪の場合でもテスト ソリューションごとに O(q) または O(q log q) が強制されます。 配列の再構築や順列のシミュレーションを伴うものは、直ちに不可能になります。 

主な微妙な点は、各操作が 2 つの可能性に分岐するため、2^q 構成にわたる単純な状態の爆発は完全に不可能であることです。 ジョーカーの位置の完全なセットを追跡するだけでも O(n) メモリが必要ですが、n が巨大であるためこれも不可能です。 

素朴な推論では、いくつかの故障モードが現れます。 

よくある間違いの 1 つは、ジョーカーの位置が常にただ拡大する単一の間隔であると想定することです。 たとえば、ジョーカーが次から始まる場合、`m=3`小さなデッキで、その周りでカードを繰り返し移動させると、左右から移動できる要素の数に影響される境界を慎重に維持せずに、その可能な位置が連続したセグメントのままであると仮定したくなります。 

もう 1 つの間違いは、移動された要素がジョーカーのどちら側に配置されるかは以前の操作によってすでに決定されており、これが非対称に蓄積されるという事実を無視して、各操作を独立して扱うことです。 

3 番目の間違いは、ステップごとに貪欲な選択を 1 つだけシミュレートすることです (常に前に押すか、常に後ろに押す)。どちらの選択もジョーカーに反対方向に影響を与える可能性があるため、実際に到達可能な位置が過小評価されます。 

## アプローチ

 ブルートフォースのアイデアは単純です。デック全体を維持し、各操作で 2 つのデックに分岐します。1 つは選択された要素が前面に移動し、もう 1 つは選択された要素が背面に移動します。 結果として得られたデッキごとに、ジョーカーの位置を追跡します。 q 操作後、考えられるジョーカーの位置をすべて収集します。 

これは、すべての有効な選択シーケンスを調査するため、原則として正しいです。 ただし、各操作により状態の数は 2 倍になります。 q の演算後は 2^q 個の状態があり、q が約 40 の場合でもこれは不可能になります。 ここで、q は最大 2・10^5 になる可能性があるため、このアプローチはすぐに失敗します。 

重要な観察は、実際にはデッキの完全な順列を気にすることはなく、ジョーカーの前後にどれだけの要素が配置されるかだけを気にするということです。 各操作は、選択された位置が何らかの実現においてその左側または右側にある場合にのみジョーカーに影響を与えます。重要なのは、可能なすべての分岐にわたってどれだけ多くの位置がジョーカーを「横切る」ことができるかだけです。 

完全な順列を追跡する代わりに、ジョーカーの左側にある可能性のある要素の可能な数の範囲を追跡します。 各操作は、削除された要素がさまざまなシナリオでどちらの側にあるかどうかに応じてこの範囲を拡大または縮小し、前または後ろに挿入すると、予測可能な方法で相対的な順序がシフトされます。 

主要な削減点は、ジョーカーの可能な位置が常に連続した間隔を形成し、その左右の端点を維持するだけでよいということです。 各操作は、削除されたインデックスが現在の不確実性区間全体で厳密に左にあるのか、厳密に右にあるのか、あるいは両方にあるのかに基づいて、O(1) でこれらのエンドポイントを更新します。 

これにより、問題は指数関数的な状態の爆発から、間隔の境界を維持する線形スキャンに軽減されます。

 | ブルートフォース | O(2^q · n) | O(2^q · n) | 遅すぎる |
 | 最適 | O(q) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 間隔をあけております`[L, R]`各操作後のジョーカーのすべての可能な位置を表します。 

1. 間隔を次のように初期化します。`[m, m]`なぜなら、最初はジョーカーは固定位置にあるからです。 
2. インデックスを使用した各操作について`a`:

 選択した位置がすべての可能なジョーカー位置の左側にあるのか、右側にあるのか、あるいは以前の不確実性により重複する可能性があるのかを検討します。 位置のみを追跡するため、これを次のように解釈します。`a`ジョーカーの前の要素の数に影響を与える可能性があります。 
3. 削除された位置が厳密にジョーカー間隔の左側にあることが保証されている場合、そのカードを削除すると、すべてのシナリオでジョーカーの前の要素の数が減少するため、両方の境界が 1 だけ左にシフトします。 
4. 厳密に正しいことが保証されている場合、それを削除しても、どのシナリオでもジョーカーの位置に影響はありません。`[L, R]`変わらないままです。 
5. 構成に応じて両側に配置できる場合、一方のブランチはそれを左として扱い、もう一方のブランチを右として扱います。 これにより、間隔が両側で 1 ずつ拡張されます。`L = max(1, L-1)`そして`R = min(n, R+1)`。 
6. 間隔を更新した後、このステップの答えは次のようになります。`R - L + 1`。 

### なぜ効果があるのか

 重要な不変条件は、すべての操作の後、すべての可能なジョーカー位置のセットが連続した間隔として正確に表現できることです。 各操作は 1 つの要素の相対的な順序を変更するだけであり、その要素がその前で終わるか後ろで終わるかに応じて、ジョーカーのランクをいずれかの方向に最大 1 だけシフトできます。 すべての分岐選択肢は、その要素を極値に移動することによってのみ異なるため、結果として生じるすべての順列は、ジョーカー ランクに対する最大 2 つの極値効果に崩壊し、中間値は、以前のステップ全体で一貫した選択によって常に達成可能です。 これにより、到達可能なセット内のギャップが防止され、間隔構造が全体にわたって確実に保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, q = map(int, input().split())
        a = list(map(int, input().split()))

        L = R = m

        for x in a:
            if x < L:
                L = max(1, L - 1)
                R = max(1, R - 1)
            elif x > R:
                continue
            else:
                L = max(1, L - 1)
                R = min(n, R + 1)

            print(R - L + 1, end=" ")
        print()

if __name__ == "__main__":
    solve()
```実装ではローリング間隔が維持されます`[L, R]`考えられるジョーカーのポジション。 3 つのケースは、削除されたインデックスがすべての可能なジョーカー配置に対して常に前にあるのか、常に後なのか、または曖昧に配置されているかに直接対応します。 更新ルールは、到達可能なすべての状態がカバーされるという不変条件を維持するために、両方のエンドポイントを一貫して調整します。 

微妙な詳細は、次を使用した境界クランプです。`max(1, ...)`そして`min(n, ...)`, ジョーカーのポジションはデッキから離れることができないためです。 もう 1 つの微妙な点は、更新が対称的であることです。削除された位置が確実に左にある場合、すべての構成でジョーカーの前の 1 つの要素が失われるため、両方のエンドポイントが左にシフトします。 同様に、曖昧さがあると間隔が両方向に拡張されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ジョーカーが位置 1 または n から始まる場合です。 このような状況では、拡張の試みはすべて中止される必要があります。 たとえば、次のように始めます。`m = 1`また、あいまいな操作を適用すると、間隔が 1 未満に縮小することはできません。更新ルール`L = max(1, L - 1)`これを保証します。 

もう 1 つのケースは、すべての操作が厳密に現在の間隔の右側にある場合です。 たとえば、次の場合`m = 2`そしてすべて`a_i`が大きい場合、間隔は変わりません。 すべての操作がジョーカーに影響を与えると仮定した単純なシミュレーションでは、範囲が誤って拡大されてしまいます。 

最後のケースは、間隔がすでにデック全体に広がっているときにあいまいな操作が繰り返されることです。 一度`[L, R] = [1, n]`、さらに拡張しても変更されないはずです。 によるクランプ`min(n, R + 1)`安定性を保証し、有効な位置を超えるオーバーフローを防ぎます。
