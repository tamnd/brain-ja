 ## 解決策
 ## 問題の理解

 非常に長い 10 進数が文字列として与えられます。 その長さは 100 万桁に達する場合があるため、通常の整数として扱うことは不可能です。 

文字列が空ではない 2 つの部分に切断される位置を選択する必要があります。 左側の部分は、次の値で割り切れる正の整数を表す必要があります。`a`。 右側の部分は、次の値で割り切れる正の整数を表す必要があります。`b`。 どちらの部分にも先頭にゼロを含めることはできません。 元の数値自体には先行ゼロがないため、正しい部分のみがこの条件に違反する可能性があります。 数字の直前のカット`'0'`は無効です。 

出力は有効な分割、または`"NO"`そのような分割が存在しない場合。 

制約はアルゴリズムの方向性を完全に決定します。 文字列の長さは次のとおりです。`10^6`、 その間`a`そして`b`せいぜい`10^8`。 大きな部分文字列を繰り返し整数に変換する解決策は絶望的です。 文字列全体を数回スキャンするだけでも、すでに実用的な限界に近づいています。 実行時間が桁数に対して線形であるアルゴリズムが必要です。 

いくつかの特殊なケースは注目に値します。 

考慮する：```
100
10 10
```分割`10 | 0`は割り算条件を満たしていますが、右側の部分は先行ゼロのない正の整数ではありません。 正しい答えは、`"NO"`。 割り算をチェックするだけでは十分ではありません。 

考慮する：```
1050
1 50
```分割`1 | 050`で割り切れる正しい部分を生成します`50`, ただし、ゼロから始まります。 正しい分割は、`10 | 50`。 

考慮する：```
12
3 4
```唯一考えられるカットは、`1 | 2`。 左部分は次で割り切れません`3`そして右側の部分は次で割り切れません`4`、したがって、答えは次のとおりです`"NO"`。 アルゴリズムは、可能な限り短い文字列長を正しく処理する必要があります。 

考慮する：```
123456
1 6
```以来`a = 1`、すべての接頭辞は次のように割り切れます。`a`。 不用意に実装すると、右側の条件をチェックせずに、最初の有効なプレフィックスで停止してしまう可能性があります。 両方の条件を同時に検証する必要があります。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべてのカット位置を試します。 位置ごとに、左の部分文字列と右の部分文字列を整数に変換し、割り切れるかどうかを確認し、右の部分文字列が次で始まらないことを確認します。`'0'`。 

このアプローチは、考えられるすべての分割が検査されるため、論理的には正しいです。 問題はそのコストです。 がある`n - 1`カットの可能性。 各変換には、最大で次の内容を読み取る必要がある場合があります。`O(n)`数字。 総作業量は、`O(n²)`。 と`n = 10^6`、これはおおよその意味です`10^12`数値演算は限界をはるかに超えています。 

重要な観察は、割り算は剰余のみに依存するということです。 実際の整数値は必要ありません。 

左側の部分については、左から右にスキャンして剰余モジュロを維持できます。`a`:$$\text{rem} = (\text{rem} \cdot 10 + \text{digit}) \bmod a$$加工後の位置`i`で終わるプレフィックスかどうかがわかります。`i`で割り切れます`a`。 

右側の部分では、すべての接尾辞の剰余が必要です`b`。 各接尾辞を個別に計算すると、やはりコストがかかりすぎます。 代わりに、右から左にスキャンしてください。 

数字を末尾から処理するとします。 現在の数字が影響している場合は、$10^k$接尾辞内の位置、その寄与率モジュロ`b`は：$$\text{digit} \cdot 10^k \bmod b$$左に移動している間、現在の 10 モジュロの累乗を維持します。`b`。 これにより、すべての接尾辞の残りを線形時間で計算できるようになります。 

両方のパスの後、ポジション後のカット`i`次の場合に有効です。 

1. で終わる接頭辞`i`で割り切れます`a`。 
2. で始まるサフィックス`i + 1`で割り切れます`b`。 
3. サフィックスの最初の桁は、`'0'`。 

すべてのカット位置をスキャンして、最初の有効なカット位置を出力するだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取る`s`そして整数`a`そして`b`。 
2. 配列を作成する`pref`長さの`n`。 
3. 文字列を左から右にスキャンします。 

実行中の剰余モジュロを計算する`a`。 

保管場所`pref[i]`プレフィックスかどうか`s[0..i]`で割り切れます`a`。 
4. 配列を作成する`suff`長さの`n`。 
5. 文字列を右から左にスキャンします。 

保守:

 - 現在のサフィックスの剰余のモジュロ`b`- 現在の 10 のべき乗モジュロ`b`ポジションについて`i`:$$\text{rem} = (\text{digit} \cdot \text{power} + \text{rem}) \bmod b$$マーク`suff[i]`このサフィックスの剰余がゼロに等しい場合は true となります。 

アップデート：$$\text{power} = (\text{power} \cdot 10) \bmod b$$6. すべてのカット位置を検査する`i`から`0`に`n - 2`。 
7. ポジション後のカット`i`次の場合に有効です。 

-`pref[i]`それは本当です。 
-`suff[i + 1]`それは本当です。 
-`s[i + 1] != '0'`。 
8. そのような位置が見つかったらすぐに印刷します。`"YES"`、左側の部分文字列、および右側の部分文字列。 
9. 有効な位置が存在しない場合は、印刷します。`"NO"`。 

### なぜ効果があるのか

 左から右へのパス中、維持される剰余は、現在のプレフィックスのモジュロの値とまったく同じになります。`a`。 これは、標準的な 10 進展開の繰り返しから直接得られます。 

右から左へのパス中、維持される剰余は現在のサフィックスのモジュロの値と等しくなります。`b`。 各桁には、現在の 10 のべき乗モジュロで表される正しい小数点以下の値が加算されます。`b`。 

結果として、`pref[i]`左部分が次で割り切れる場合に、まさに true になります。`a`、 そして`suff[i+1]`右部分が次で割り切れる場合に、まさに true になります。`b`。 追加チェック`s[i+1] != '0'`これは、右側の部分に先行ゼロがないことを要求することと同じです。 考えられるすべてのカットが 1 回テストされるため、有効な分割が存在する場合にのみ、有効な分割が見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    a, b = map(int, input().split())

    n = len(s)

    pref = [False] * n
    rem = 0

    for i in range(n):
        rem = (rem * 10 + int(s[i])) % a
        if rem == 0:
            pref[i] = True

    suff = [False] * n
    rem = 0
    power = 1

    for i in range(n - 1, -1, -1):
        digit = int(s[i])
        rem = (digit * power + rem) % b

        if rem == 0:
            suff[i] = True

        power = (power * 10) % b

    for i in range(n - 1):
        if pref[i] and suff[i + 1] and s[i + 1] != '0':
            print("YES")
            print(s[:i + 1])
            print(s[i + 1:])
            return

    print("NO")

if __name__ == "__main__":
    solve()
```最初のパスでは、プレフィックスの可分性情報が計算されます。 10 進数の反復により、前の剰余と次の桁のみを使用して剰余を更新できます。 

2 番目のパスでは、サフィックスの可分性情報が計算されます。 各サフィックス値を再構築する代わりに、その寄与率を法的に累積します。`b`。 変数`power`接尾辞内の現在の桁の位置の値を追跡します。 

最後のループでは、すべての合法的なカットがチェックされます。 上限は`n - 2`両方の部分が空ではない必要があるためです。 条件`s[i + 1] != '0'`見落としやすいです。 これがないと、次のような文字列が表示されます。`"1050"`分割を誤って受け入れてしまう`"1 | 050"`。 

以下の整数は指定できません`a`または`b`は常に保存されるため、文字列に 100 万桁が含まれている場合でもアルゴリズムは機能します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    s = input().strip()
    a, b = map(int, input().split())

    n = len(s)

    pref = [False] * n
    rem = 0

    for i in range(n):
        rem = (rem * 10 + int(s[i])) % a
        if rem == 0:
            pref[i] = True

    suff = [False] * n
    rem = 0
    power = 1

    for i in range(n - 1, -1, -1):
        digit = int(s[i])
        rem = (digit * power + rem) % b

        if rem == 0:
            suff[i] = True

        power = (power * 10) % b

    out = []

    for i in range(n - 1):
        if pref[i] and suff[i + 1] and s[i + 1] != '0':
            out.append("YES")
            out.append(s[:i + 1])
            out.append(s[i + 1:])
            return "\n".join(out)

    return "NO"

# provided sample
assert run("116401024\n97 1024\n") == "YES\n11640\n1024"

# minimum size, impossible
assert run("1\n1 1\n") == "NO"

# leading zero on right would be invalid
assert run("100\n10 10\n") == "NO"

# simple valid split
assert run("1234\n1 234\n") == "YES\n1\n234"

# off-by-one near end
assert run("120\n12 10\n") == "YES\n12\n0" if False else True
