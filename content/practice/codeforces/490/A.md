 ## 解決策
 ## 問題の理解

 私たちには、プログラミング (1)、数学 (2)、体育 (3) などのスキルを示す番号でそれぞれ識別される子供たちのリストが渡されます。 課題は、各チームに各スキルの子が 1 人だけ含まれる 3 人からなるチームをできるだけ多く形成することです。 出力では、最初にチームの数を示し、次に各チームを構成する子のインデックスをリストする必要があります。 各子供は 1 つのチームにのみ参加できます。 

重要な制約は、$n \le 5000$。 これは、データの線形または線形に近いスキャンを可能にするのに十分な大きさであり、すべての子に対する単純な操作を複数回実行することもできます。 インデックスは出力目的で元の入力に従って保存する必要がありますが、必要に応じて内部的に自由に並べ替えたり保存したりできます。 

1 つのスキルが過小評価されている場合、明らかではないエッジケースが発生します。 たとえば、入力の場合`1 1 2 2 2 3`、プログラマーが 3 人、数学者が 3 人、スポーツマンが 1 人います。 各スキルの子を 1 つだけ持つ複数のチームを形成することはできないため、チームの最大数は明らかに 1 です。 子供たちを順番にマッチングさせようとする単純なアプローチでは、誤って 2 つのチームを作成しようとする可能性があり、スキル要件を満たせなくなります。 

## アプローチ

 ブルートフォースアプローチでは、3 人の子供の可能な組み合わせをすべて試し、有効なチームを形成しているかどうかを確認しようとします。 最大 5000 人の子供の場合、可能な三つ子の数は次のとおりです。$\binom{5000}{3}$、およそ200億ですが、これは明らかに実行不可能です。 これはすべての組み合わせをチェックするため理論上は機能しますが、次の場合には失敗します。$n$数十を超えて成長します。 

重要な洞察は、子供たちをスキルごとに分けることです。 プログラマー用、数学者用、スポーツ選手用の 3 つのリストができたら、チームの最大数は最小のリストによって制限されます。これは、各スキルに少なくとも 1 人の子供がいないとチームを編成できないためです。 次に、各リストの先頭から子供たちを取り出し、順番にチームを編成します。 これにより、すべてのチームが明確なスキルを持つことが保証され、子供ごとに 1 チームという制約が当然尊重されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 3 つの空のリストを初期化します。`prog`プログラマーにとって、`maths`数学者にとって、そして`pe`スポーツマン向け。 これらには、各スキルを持つ子のインデックスが保存されます。 
2. 子のリストを繰り返し処理します。 各子について、スキルに応じて、1 から始まるインデックスを適切なリストに追加します。 
3. 3 つのリストの最小の長さを計算します。 この数字、`w`, は編成できるチームの最大数です。 
4. 各整数について`i`0から`w-1`、から構成されるチームを出力します。`i`- 番目の要素`prog`、`maths`、 そして`pe`。 これにより、各チームに各スキルの子が 1 つだけ存在し、重複する子が存在しないことが保証されます。 
5. 印刷`w`まず、各チームを別の行に印刷します。 

機能する理由: すべてのステップで、各スキルから 1 人の子だけを取り出します。 3 つのスキル グループの最小数まで繰り返すことで、どのスキルでも利用可能な子の数を決して超えないことが保証されます。 これにより、有効なチームの最大数が生成され、インデックスを直接追跡するため、出力の正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
skills = list(map(int, input().split()))

prog = []
maths = []
pe = []

for idx, s in enumerate(skills, 1):
    if s == 1:
        prog.append(idx)
    elif s == 2:
        maths.append(idx)
    else:
        pe.append(idx)

w = min(len(prog), len(maths), len(pe))
print(w)

for i in range(w):
    print(prog[i], maths[i], pe[i])
```このソリューションは、子供の数とそのスキルを読み取ります。 スキルに基づいてインデックスを 3 つのリストに分けます。 次に、3 つのリストの長さの最小値としてチームの最大数を計算します。 最後に、印刷します`w`そして、各スキルリストからインデックスを１つずつ取り出してチーム毎に出力する。 問題では 1 から始まるインデックスが必要となるため、1 から始まるインデックスを使用することが重要です。

 サンプル入力 1:```

 最小のスキル グループであるため、2 つのチームを採用します (`maths`そして`pe`）にはそれぞれ子供が2人います。 この表は、インデックスが各リストからどのように順番に選択されるかを示しています。

4

```| プログレ | 数学 | ペ | w | チームが結成されました |

 チームは 1 つだけ結成でき、数学者とスポーツ選手の数によって制限されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 子のリストを 1 回繰り返してインデックスを分割し、次まで繰り返します。`w`(≤ n) でチームを形成します。 |
 | スペース | O(n) | インデックスを 3 つの個別のリストに格納します。それぞれのリストには合計 n 個の要素が含まれます。 |

 このソリューションは、n ≤ 5000 の 1 秒の時間制限と 256 MB のメモリ制限内に簡単に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    # solution
    n = int(input())
    skills = list(map(int, input().split()))
    prog, maths, pe = [], [], []
    for idx, s in enumerate(skills, 1):
        if s == 1:
            prog.append(idx)
        elif s == 2:
            maths.append(idx)
        else:
            pe.append(idx)
    w = min(len(prog), len(maths), len(pe))
    print(w)
    for i in range(w):
        print(prog[i], maths[i], pe[i])
    return output.getvalue().strip()

# provided sample
assert run("7\n1 3 1 3 2 1 2\n") == "2\n1 5 2\n3 7 4", "sample 1"

# custom cases
assert run("4\n1 1 2 3\n") == "1\n1 3 4", "minimum teams"
assert run("6\n1 1 1 2 2 3\n") == "1\n1 4 6", "one team only"
assert run("3\n1 2 3\n") == "1\n1 2 3", "exactly one team"
assert run("5\n1 2 3 1 2\n") == "1\n1 2 3", "extra children in skill groups"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 4\n1 1 2 3 | 1\n1 3 4 | チームは 1 つだけ作成できます |
 | 6\n1 1 1 2 2 3 | 1\n1 4 6 | 最小数がチームを決定します |
 | 3\n1 2 3 | 1\n1 2 3 | 単一チームのエッジケース |
 | 5\n1 2 3 1 2 | 1\n1 2 3 | 追加の子は追加のチームを作成しません。 

## 特殊なケース

 たとえば、あるスキルに子がない場合、`3\n1 1 2`、するとリストは次のようになります`prog=[1,2]`、`maths=[3]`、`pe=[]`。 長さの最小値は 0 であるため、チームを形成できません。 アルゴリズムは 0 を正しく出力します。これは、min 操作によって自然に強制されるため、特別なチェックを行わずにエッジ ケースを処理します。
