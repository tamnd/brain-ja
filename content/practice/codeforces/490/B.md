 ## 解決策
 ## 問題の理解

 各入力行は 1 人の生徒を表しますが、生徒自身の ID は直接与えられません。 代わりに、すぐ前に立っている学生の ID と、すぐ後ろに立っている学生の ID が伝えられます。 すべての生徒がキューに 1 回だけ現れるため、これらの隣接関係によって 1 つのチェーンが完全に決まります。 

生徒の前に誰もいない場合、前の ID は次のとおりです。`0`。 その学生は列の最初の人です。 生徒の後ろに誰もいない場合、裏 ID は次のとおりです。`0`。 その学生は列の最後の人です。 

課題は、レコードが任意の順序で与えられることです。 最初の生徒から最後の生徒までキュー全体を再構築する必要があります。 

生徒数はこれほど多く、`2 · 10^5`。 次の生徒を探しているすべての生徒を繰り返しスキャンするアルゴリズムでは、おおよその要件が必要になります。`n²`仕事。 と`n = 200000`これは約 400 億の演算となり、2 秒の制限をはるかに超えています。 線形時間に近いものが必要です。 

ID 自体は次のような大きさにすることができます。`10^6`, そのため、学生 ID でインデックス付けされた配列は使用できません。 ハッシュ マップは自然な選択です。 

この問題の厄介な点は、最初の要素からの「次の」ポインタを単純にたどるだけではキューが再構築されないことです。 入力はペアのみを提供します`(front, back)`。 まず、これらの関係が実際の順序をどのようにエンコードするかを発見する必要があります。 

次の小さなキューを考えてみましょう。```
10 20 30
```記録は次のとおりです。```
0 20
10 30
20 0
```不用意に実装すると、2 番目の数値が次の要素として扱われ、次のように出力される可能性があります。```
20 30
```レコードから始まるので`front = 0`。 本当の最初の生徒は、`10`、そのレコードに明示的に現れることはありません。 学生の ID を正しく回復することが主な課題です。 

もう 1 つの微妙なケースは、キューが奇数位置と偶数位置の間で交互に配置される場合です。 例えば：```
1 2 3 4 5
```受け入れられているソリューションで使用される再構成方法は、最初に奇数の位置を構築し、次に偶数の位置を埋めます。 この構造を正しく理解していないと、簡単に次のような結果が得られます。```
1 3 5 2 4
```これにはすべての学生が含まれますが、キュー順に並んでいません。 

## アプローチ

 ブルートフォース ソリューションは、最初の生徒から開始し、すべての記録を繰り返し検索して、次に来る生徒を見つけます。 あるので`n`位置と各検索で調べることができます`n`レコードの場合、最悪の場合の複雑さは次のとおりです。`O(n²)`。 

のために`n = 200000`、これはおよそ次のことを意味します。```
200000 × 200000 = 4 × 10^10
```操作。 

それは遅すぎます。 

より迅速なアプローチを見つけるには、入力に隠された構造を理解する必要があります。 

生徒の記録を残しましょう`(a, b)`、 どこ`a`は先頭の ID で、`b`後ろのIDです。 

学生だとします`x`行列のどこかに立っています。 それから：```
a <- x -> b
```後ろの生徒`x`は`b`。 

次に、学生の記録を見てください。`b`。 その正面の隣人は次のとおりである必要があります`x`。 

それはマッピングを意味します```
x -> b
```関係から復元できます。```
front_of[b] = x
```受け入れられているソリューションは、情報を少し異なる方法で保存します。 

定義する：```
next[a] = b
```すべてのレコードに対して`(a, b)`。 

キューの場合```
p1 p2 p3 p4 p5 ...
```このマッピングは、すべての奇数順位の生徒を次の奇数順位の生徒にリンクします。```
p1 -> p3 -> p5 -> ...
```学生時代`0`2 番目の位置にリンクします。```
0 -> p2 -> p4 -> ...
```これにより、2 つのインターリーブされたチェーンが作成されます。 

重要な観察は、最初の生徒がその前の隣人であるということです。`0`。 最初の位置がわかったら、奇数位置のチェーンをたどると、すべての奇数位置が再構築されます。 から始まるチェーンをたどる`0`すべての偶数の位置を再構築します。 

両方のチェーンがわかったら、それらをインターリーブして元のキューを復元します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのペアを読み取ります`(a, b)`。 
2. 関係を保存します。```
next[a] = b
```これは、承認されたソリューションで使用されるコア構造です。 
3. 最初の生徒を検出します。 

最初の生徒は、前の隣人が等しい生徒です`0`。 レコードがある場合`(0, x)`の場合、そのレコードで記述されている学生がキューの最初の人になります。 
4. 長さの回答配列を作成します。`n`。 
5. 最初の生徒を所定の位置に配置します`0`。 
6. 最初に奇数番号のキュー位置を埋めます。 

最初の生徒から始めて、次の手順を繰り返します。```
current = next[current]
```そして、訪問した学生を所定の位置に配置します。```
0, 2, 4, 6, ...
```これらは、元のキューの奇数の位置です (1 ベースのインデックスを使用)。 
7. 偶数番号のキューの位置を埋めます。 

以下から開始します:```
current = next[0]
```そして、訪問した学生を所定の位置に配置します。```
1, 3, 5, 7, ...
```これらは、元のキューの偶数の位置を形成します。 
8. 再構成された配列を出力します。 

### なぜ効果があるのか

 実際のキューを次のようにします。```
p1, p2, p3, ..., pn
```すべての生徒にとって`pi`、記録は次のとおりです。```
(pi-1, pi+1)
```欠けている隣人が代わりに`0`。 

保管する場合:```
next[a] = b
```の記録`pi`貢献します:```
next[pi-1] = pi+1
```したがって：```
next[p1] = p3
next[p3] = p5
...
```これにより、奇数の位置のチェーンが形成されます。 

同様に:```
next[0] = p2
next[p2] = p4
...
```これにより偶数の位置のチェーンが形成されます。 

最初の生徒は、前隣にある生徒によって一意に識別されます。`0`、だから私たちは知っています`p1`。 奇数位置のチェーンをたどるとすべての奇数位置が再構築され、次から始まるチェーンをたどります。`0`すべての偶数の位置を再構築します。 これら 2 つのチェーンをインターリーブすると、正確に次のようになります。```
p1, p2, p3, p4, ...
```これが元のキューです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    nxt = {}
    first = None

    for _ in range(n):
        a, b = map(int, input().split())
        nxt[a] = b

        if a == 0:
            first = b

    ans = [0] * n

    cur = first
    idx = 0
    while cur != 0 and idx < n:
        ans[idx] = cur
        cur = nxt.get(cur, 0)
        idx += 2

    cur = nxt.get(0, 0)
    idx = 1
    while cur != 0 and idx < n:
        ans[idx] = cur
        cur = nxt.get(cur, 0)
        idx += 2

    print(*ans)

solve()
```辞書`nxt`変換を保存します`next[a] = b`入力レコードから直接派生します。 

見つける`first`簡単です。 フロントネイバーが次のペアであるペアに遭遇するたびに、`0`、2 番目の値はキュー内の最初の生徒の ID です。 

最初のループはポジションを埋めます`0, 2, 4, ...`。 これらはキューの位置に対応します`1, 3, 5, ...`1 ベースのインデックス付け。 続く`nxt[cur]`ある奇数の位置から次の奇数の位置に移動します。 

2 番目のループは次から始まります`nxt[0]`、これはキューの 2 番目の生徒です。 同じマッピングに従って位置を横断します`2, 4, 6, ...`1 から始まるインデックス付けで、配列インデックスに書き込まれます。`1, 3, 5, ...`。 

使用する`dict.get(key, 0)`チェーンが終わりに達したときの重要なエラーを回避します。

 ## 特殊なケース

 ### 長さ 2 のキュー

 入力:```
2
0 20
10 0
```最初の生徒さんは、`10`。 奇数位置のチェーンには、`10`、偶数位置のチェーンには、`20`。 

アルゴリズムにより次のものが生成されます。```
10 20
```特別な取り扱いは必要ありません。 

### 奇数の生徒数

 入力:```
5
0 2
1 3
2 4
3 5
4 0
```奇数位置のチェーンは次のとおりです。```
1 -> 3 -> 5
```偶数位置チェーンは次のとおりです。```
2 -> 4
```最初のチェーンは 1 要素分長くなります。これは、キューの長さが奇数である場合に常に予想されます。 交互の書き込みにより、配列のすべての位置が 1 回だけ埋められます。 

### 非常に大きな学生証

 入力:```
3
0 900000
123456 0
900000 123456
```学生 ID が最大許容値に近づいています。 この実装ではインデックス付き配列ではなくハッシュ マップが使用されるため、ID の大きさは正確さや複雑さに影響を与えません。 

再構築されたキューは次のとおりです。```
900000 123456 0
```トラバースロジックは変更されません。
