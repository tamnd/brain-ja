 ## 解決策
 ## 問題の理解

 私たちには、各都市に人口が存在する都市のツリーが与えられています。 道路は、2 つの都市間に 1 つの単純な経路が存在するように都市を接続します。 バンドは、コンサートが開催される都市の人口が厳密に増加するように、ある経路に沿って一連の都市で演奏したいと考えています。 目標は、コンサートの数を最大化することです。これは、ツリー内の任意のパスに沿って都市人口が厳密に増加する最長のサブシーケンスを意味します。 

入力により、都市の数、人口、都市を接続する道路のリストが得られます。 出力は単一の整数、つまり可能なコンサートの最大数です。 

ツリー構造はサイクルがないことを意味します。$n$最大 6000 まで可能で、2 次または 3 次の複雑さのアルゴリズムも実現可能ですが、それより悪いもの (たとえば、$O(n^4)$) はすぐに遅すぎます。 各都市の人口範囲は最大で次のとおりです。$10^6$したがって、単純な値ベースのインデックス付けはマップを使用する場合にのみ可能ですが、サイズ 10^6 の直接配列は無駄です。 また、複数の都市に同じ人口が存在する可能性があることも考慮する必要があります。 

微妙なエッジ ケースは、パスに沿った複数の都市の人口が同じである場合です。 シーケンスは厳密に増加する必要があるため、2 つの等しい人口が両方ともコンサートを主催することはできません。 もう 1 つのエッジ ケースは、1 つの中心ノードが多数の葉に接続する星型ツリーです。 単一のブランチのみを調べる単純な DFS では、あるリーフから中心を通って別のリーフに至る最適なパスを見逃してしまう可能性があります。 

たとえば、3 つの都市のツリーを考えてみましょう。人口`[1, 2, 1]`エッジ付き`1-2, 2-3`。 最適な順序は、`[1, 2]`または`[2, 3]`シーケンスは厳密に増加する必要があるため、コンサートは 3 つではなく 2 つです。 

## アプローチ

 ブルートフォース手法では、ツリー内のすべての単純なパスを列挙し、各パスの都市人口のすべてのサブシーケンスを生成し、最も長く厳密に増加するシーケンスを追跡します。 がある$O(n^2)$ツリー内にパスがあり、各パスには最大でも$n$都市、大まかに言うと$O(n^3)$考慮すべきシーケンス。 各パス内でサブシーケンスを生成すると、このアプローチはパスごとに指数関数的になりますが、これは完全に実行不可能です。$n = 6000$。 

重要な観察は、問題がツリー内のパスに沿った最長増加部分列 (LIS) の計算に帰着するということです。 各ノードを潜在的なルートとみなして、動的プログラミングを介して LIS 情報をその子に伝播すると、すべてのパスを列挙することを回避できます。 ツリーにはサイクルがないため、DFS を使用すると、ノードの母集団と子の母集団を比較することによって、各ノードから開始して LIS を計算できます。 各都市は、特定の人口について、最後のコンサートがその人口で行われた場合に可能なコンサートの最大数を知る必要があるだけです。 これにより、$O(n^2)$アルゴリズム、これは許容されます$n = 6000$。 

各都市で終わる最大の LIS のみを保存し、親ノードと子ノードの間で情報をマージすることで、さらに最適化できます。 これにより、都市のペアごとに LIS を最初から再計算する必要がなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n^2) | O(n^2) | 遅すぎる |
 | ツリー DP / LIS 伝播 | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 都市の数と人口を読み取り、道路接続からツリーの隣接リストを作成します。 隣接リストを使用すると、DFS 中に近隣ノードを高速に走査できます。 
2. DP テーブルの初期化`dp[u][v]`ノードから始まるパスに沿ってコンサートの最大数を保存します。`u`そしてノードで終わる`v`での最後のコンサートで、`v`。 厳密に増加するシーケンスのみを考慮しているため、次のノードの母集団が最後のコンサートの母集団よりも大きい場合にのみ LIS 情報を伝播します。 
3. すべてのノードから DFS を実行します。`u`出発点として。 隣人ごとに`v`の`u`まだ訪問されていない場合は、次で終わる LIS を再帰的に計算します。`v`。 もし`r[v] > r[u]`でコンサートを行うことで LIS を拡張できます。`v`。 見つかった最大長で DP テーブルを更新します。 
4. DFS 中に値を伝播する間、グローバル最大値を維持します。`answer`すべての開始点で見つかったコンサートの最大数を追跡します。 DP 値が更新されるたびに、それを次と比較します。`answer`それに応じて更新します。 
5. すべてのノードで DFS が完了したら、`answer`バンドがツリー内の任意のパスに沿って実行できるコンサートの最大数が含まれます。 

機能する理由: DFS により、都市を再度訪問することなくすべてのパスを探索できるようになり、DP テーブルにより、特定の最後のコンサート人口を持つ都市で終わるパスごとに、達成可能なコンサートの最大数が保存されることが保証されます。 ツリーにはサイクルがないため、パスが失われることはなく、厳密に増加する条件が各ステップで強制されます。 子からの DP 値をマージすると、各ノードからの上向きパスと下向きパスの両方が考慮されるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10000)

n = int(input())
r = list(map(int, input().split()))
adj = [[] for _ in range(n)]
for _ in range(n-1):
    a, b = map(int, input().split())
    adj[a-1].append(b-1)
    adj[b-1].append(a-1)

dp = [1] * n  # dp[u]: max concerts ending at u
answer = 1

def dfs(u, parent):
    global answer
    for v in adj[u]:
        if v == parent:
            continue
        dfs(v, u)
        if r[v] > r[u]:
            dp[v] = max(dp[v], dp[u] + 1)
            answer = max(answer, dp[v])

for i in range(n):
    dfs(i, -1)

print(answer)
```このソリューションでは、まず隣接リストを設定し、DP 配列を初期化します。`dp`各都市で終了するコンサートの最大数を表します。 DFS は各都市からルートとして実行され、そのノードから始まるすべてのパスが確実に探索されます。 DFS 中は、厳密に増加するトランジションのみが許可され、コンサート ルールが適用されます。 の`answer`変数は、より長いシーケンスが見つかるたびに更新されます。 6000 ノードの上限に近い深いツリーを処理するために、再帰制限が増加しました。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | 各ノードは、他のすべてのノードにアクセスできる DFS を開始し、DP の更新はエッジごとに O(1) です。 n ≤ 6000 の場合、n^2 ≤ 36,000,000 回の操作が 5 秒の時間制限に適合します。 |
 | スペース | O(n^2) | DP 配列のサイズは n です。 隣接リストは O(n) です。 再帰スタックは最大 n まで。 256 MB の制限に適合します。 |

 これにより、許容される最大の入力サイズに対してアルゴリズムが効率的に実行されます。 

## テストケース```python

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.setrecursionlimit(10000)
    
    n = int(input())
    r = list(map(int, input().split()))
    adj = [[] for _ in range(n)]
    for _ in range(n-1):
        a, b = map(int, input().split())
        adj[a-1].append(b-1)
        adj[b-1].append(a-1)

    dp = [1] * n
    answer = 1

    def dfs(u, parent):
        nonlocal answer
        for v in adj[u]:
            if v == parent:
                continue
            dfs(v, u)
            if r[v] > r[u]:
                dp[v] = max(dp[v], dp[u] + 1)
                answer = max(answer, dp[v])

    for i in range(n):
        dfs(i, -1)

    return str(answer)
