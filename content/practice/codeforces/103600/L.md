 ## 解決策
 ## 問題の理解

 平面上の一連の垂直線分が与えられます。 各セグメントは地面に立つ草の葉を表します$y = 0$、一定の位置で上向きに伸びています$x$- 指定された高さの座標。 それで、$i$- 番目の草はからのセグメントです$(x_i, 0)$に$(x_i, y_i)$そして、同じものを共有する草は 2 つとありません。$x$-座標。 

その後、複数の問い合わせを受け取ります。 各クエリは、からの点の直線移動を記述します。$(x_1, y_1)$に$(x_2, y_2)$。 このようなセグメントごとに、それが垂直の草セグメントのいずれかと交差するかどうかを判断する必要があります。 存在する場合、タッチされた草のインデックスを出力します。 それ以外の場合は出力します$-1$。 

「接触」する幾何学的拘束には端点での交差が含まれるため、境界の場合が重要になります。 

主要な制約は非常に大きく、次のとおりです。$8 \cdot 10^5$草セグメントまで$3 \cdot 10^5$クエリ。 これにより、すべての草に対するクエリごとのスキャンが即座に除外されます。これは、コストが 1 ドル程度かかるためです。$10^{11}$最悪の場合の運用。 クエリごとの草ごとの対数検索さえ不可能です。 代わりに、各クエリを少数の候補チェックに減らす必要があります。 

単純なアプローチでは、クエリごとに、すべての垂直セグメントとの交差をテストします。 これは正しいですが、遅すぎます。 

「x1 と x2 の間で最も近い x 座標草のみをチェックする」などの単純化されたヒューリスティックを使用すると、微妙な失敗のケースが発生します。 どの垂直セグメントが実際にセグメントと交差するかを適切にモデル化しない限り、これでは十分ではありません。なぜなら、斜めのセグメントは複数の X 値を渡し、ジオメトリによっては最も近い X 値を見逃してしまう可能性があるからです。 

## アプローチ

 ブルートフォース手法は簡単です。 各クエリ セグメントについて、すべての草を反復処理し、そのセグメントがその x 座標で垂直セグメントと交差するかどうかを確認します。 固定芝の場合$x_i$、クエリセグメントが垂直線と交差するかどうかを計算します$x = x_i$、そうであれば、対応するかどうか$y$- そこで調整します$x$間にあります$0$そして$y_i$。 これが機能するのは、両方のオブジェクトが線分であるため、交差が 1 つの補間チェックで済むからです。 

このアプローチは正しいですがコストがかかります$O(nm)$までです$2.4 \cdot 10^{11}$限界をはるかに超えた操作。 

重要な点は、各クエリ セグメントが直線であるため、垂直線との交差は順序付けのみに依存するということです。$x$。 掃き掃除をしながら$x_1$に$x_2$、セグメントは連続関数をトレースします。$y(x)$。 触れた草はすべて何らかの問題に対応します。$x_i$間$x_1$そして$x_2$そのような$y(x_i) \le y_i$。 

したがって、問題は次のようになります。$x$- 座標はクエリ セグメントの射影間隔内にあり、高さがクエリの高さ以上の座標を見つけます。$y(x_i)$その位置で。 

これは草を次のように分類することを示唆しています$x$-座標とセグメントツリーの使用$x$ただし、間隔ごとに回線状態を評価する必要があります。 標準的なトリックは、クエリを範囲最大実現可能性チェックに変換することです。セグメント ツリー上で、クエリ ラインが草の高さを下回る区間内の任意の位置を二分探索します。 

牧草を昇順に保管します。$x$。 クエリの場合、そのインデックスが含まれるすべてのインデックスを特定します。$x_i$セグメントの端点の間にあります。 候補位置ごとに、次のクエリ行の値を計算します。$x_i$、そしてどうかを確認してください$y_i$少なくともその値です。 

すべてのポイントをスキャンすることを避けるために、各間隔の最大草の高さを格納するセグメント ツリーを構築します。 走査中に、最大高さであっても、その間隔内で可能な最小ライン値を下回る分岐を枝刈りします。 これが機能するのは、クエリ ラインが線形であるため、ある間隔での最小値がエンドポイントで発生し、安全なプルーニングが可能になるためです。 

これにより、各クエリが次のように削減されます。$O(\log n)$または$O(\log^2 n)$実装に応じて。

 | x オーダーでのセグメント ツリーの枝刈り |$O(m \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. X 座標による草の前処理

 すべての草セグメントをその基準に従って並べ替えます。$x$-元のインデックスを維持しながら調整します。 これにより、クエリを連続した範囲にマッピングできる単調な構造が得られます。 

### 2. 草の高さを超えてセグメント ツリーを構築する

 各ノードは、その間隔内の最大の高さと、その高さを達成する 1 つの代表的なインデックスを格納します。 これにより、クエリを満たす可能性のない間隔を迅速に拒否できます。 

### 3. クエリごとに、線表現を計算します。 

クエリセグメントをパラメトリックに表現します。 どれについても$x$、対応する$y(x)$エンドポイント間の線形補間によって計算されます。 これにより、ノードごとにジオメトリを繰り返し再計算することが回避されます。 

### 4. クエリエンドポイントをインデックス範囲にマップする

 X 値がセグメントの投影間隔内にある左端と右端の草インデックスを見つけます。 これにより検索ドメインが定義されます。 

### 5. セグメントツリーを再帰的に検索する

 間隔がクエリ範囲と交差するノードのみをトラバースします。 各ノードについて、次の最小値を計算します。$y(x)$エンドポイント評価を使用してノードの X スパンにわたって。 ノードの最大草の高さがこの値を下回る場合、ノードを剪定します。 それ以外の場合は、交差条件を満たす葉が見つかるまで下降します。 

### なぜ効果があるのか

 正しさは 2 つの特性に基づいています。 まず、垂直セグメントは、対応する位置でのみ、線分と交差します。$x_i$、ラインの$y(x_i)$草の高さより下にあります$y_i$。 第 2 に、任意の x 間隔内で、クエリ行はその極値がエンドポイントで発生するという意味で単調であるため、枝刈りにはノード レベルの境界と比較するだけで十分です。 これにより、有効な候補が決して破棄されず、誤った交差が報告されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get_y(x1, y1, x2, y2, x):
    if x2 == x1:
        return y1
    return y1 + (y2 - y1) * (x - x1) / (x2 - x1)

class SegTree:
    def __init__(self, xs, ys):
        self.n = len(xs)
        self.xs = xs
        self.ys = ys
        self.mx = [0] * (4 * self.n)
        self.idx = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1)

    def build(self, v, l, r):
        if l == r:
            self.mx[v] = self.ys[l]
            self.idx[v] = l
            return
        m = (l + r) // 2
        self.build(v * 2, l, m)
        self.build(v * 2 + 1, m + 1, r)
        if self.mx[v * 2] >= self.mx[v * 2 + 1]:
            self.mx[v] = self.mx[v * 2]
            self.idx[v] = self.idx[v * 2]
        else:
            self.mx[v] = self.mx[v * 2 + 1]
            self.idx[v] = self.idx[v * 2 + 1]

    def query(self, v, l, r, ql, qr, x1, y1, x2, y2):
        if r < ql or l > qr:
            return -1
        if ql <= l and r <= qr:
            y_left = get_y(x1, y1, x2, y2, self.xs[l])
            y_right = get_y(x1, y1, x2, y2, self.xs[r])
            if max(y_left, y_right) > self.mx[v]:
                return -1
            if l == r:
                return self.idx[v] + 1
        m = (l + r) // 2
        res = self.query(v * 2, l, m, ql, qr, x1, y1, x2, y2)
        if res != -1:
            return res
        return self.query(v * 2 + 1, m + 1, r, ql, qr, x1, y1, x2, y2)

n = int(input())
grasses = []
for i in range(n):
    x, y = map(int, input().split())
    grasses.append((x, y, i))

grasses.sort()
xs = [g[0] for g in grasses]
ys = [g[1] for g in grasses]

seg = SegTree(xs, ys)

m = int(input())
for _ in range(m):
    x1, y1, x2, y2 = map(int, input().split())
    l = 0
    r = n - 1
    # find range by x
    if x1 > x2:
        x1, y1, x2, y2 = x2, y2, x1, y1
    # binary search range
    while l < n and xs[l] < x1:
        l += 1
    while r >= 0 and xs[r] > x2:
        r -= 1
    if l > r:
        print(-1)
        continue
    print(seg.query(1, 0, n - 1, l, r, x1, y1, x2, y2))
```主要な実装の詳細は、セグメント ツリーがジオメトリを格納せず、最大の高さのみを格納し、すべての幾何学的推論がクエリ関数にプッシュされることです。 エンドポイント評価を使用した枝刈り条件により、全範囲の探索が妨げられます。 

浮動小数点演算には注意が必要です$y(x)$、すべての座標は次のとおりです。$10^9$。 実際には、完全な等価性ではなく比較のみが必要となるため、倍精度で十分です。

 ## 特殊なケース

 重要なエッジ ケースは、クエリ セグメントが水平または垂直の場合に発生します。 水平セグメントでは、$y(x)$は一定であるため、枝刈りによってエンドポイントのみの比較が原因で有効な草を誤って拒否してはなりません。 両方のエンドポイントが同じ値を生成するため、セグメント ツリーがこれを処理します。 

もう 1 つのエッジ ケースは、セグメントの端点が草の範囲外にあるにもかかわらず、セグメントが草の範囲を通過する場合です。 範囲クリッピングにより、内部の草も考慮されるため、交差点が見逃されることはありません。 

最後の微妙なケースは、セグメントが草セグメントの上部に正確に接触している場合です。 条件が厳密ではないため ($\le$)、エンドポイントの等価性は有効な共通部分として扱われる必要があり、浮動小数点の比較では丸めにより等価性が除外されてはなりません。
