 ## 解決策
 ## 問題の理解

 私たちには 2 つのサッカー チームがあり、それぞれが`n`選手たち。 チーム A がチーム B のゴールキーパーに対してシュートを放つ。`k`。 チーム B がチーム A のゴールキーパーに対してシュートを放つ。`m`。 

プレーヤーのシュート力が相手ゴールキーパーの身長の半分以上の場合、プレーヤーは得点します。 比較は直接実行されます。`height / 2`, つまりパワーのある選手`x`いつ得点するか`2 * x >= height`。 

勝者は2段階で決定されます。 まず、各チームが獲得した合計ゴール数を比較します。 どちらかのチームがより多くのゴ​​ールを決めれば、そのチームが勝ちます。 両チームが同じゴール数を獲得した場合、各チームの全選手の最大シュート力を比較します。 最大パワーが大きいチームが勝ちます。 

アリスはチームAが勝つと予想します。 ボブはチーム B が勝つと予想します。 アウトプットしなければなりません`"Alice"`上記のルールに従ってチーム A が勝った場合、そうでない場合は出力`"Bob"`。 

制限は非常に小さいです。 テスト ケースは最大 500 件あり、各チームのプレーヤーは最大 100 人です。 すべてのプレーヤーを単純にスキャンするだけでも、数万回の操作にすぎません。 高度なアルゴリズムは必要ありません。 

微妙な点は得点条件だ。 声明によると、プレーヤーは自分のパワーがゴールキーパーの身長の半分以上の場合に得点するという。 ゴールキーパーの身長が奇数の場合、半分は整数ではありません。 

考慮する：```
1
1 5 3
2
1
```チームAが高さに対してシュートを放つ`3`。 以来`2 >= 1.5`, チームAが得点します。 

整数の除算を使用した不注意な実装は、`2 >= 3 // 2 = 1`、ここではたまたま機能しますが、他の場合は失敗します。 

例えば：```
1
1 5 5
2
1
```正しいしきい値は次のとおりです`2.5`、だからパワー`2`見逃すべきだ。 使用する`5 // 2 = 2`誤ってそれを目標としてカウントしてしまいます。 

ゴール数が同点の場合、別のエッジケースが発生します。```
1
2 4 4
2 10
3 9
```両チームは同じ数のゴールを獲得します。 チームAの最大パワーは`10`, チームBは`9`, したがって、チームAが勝ちます。 ゴール数のみを比較するソリューションでは、間違った答えが得られます。 

このステートメントは、すべてのシュート力が異なることを保証するため、ゴール数が同点の場合、最大シュート力が等しくなることはありません。 タイブレークでは常に唯一の勝者が生まれます。 

## アプローチ

 最も直接的なアプローチは、ルールに記述されている内容を正確にシミュレートすることです。 

チーム A の場合、何人のプレーヤーが満足したか数えてください`2 * a[i] >= k`チームBの高身長ゴールキーパー相手にシュートを打っているからです。`k`。 

チーム B の場合、何人のプレーヤーが満足したか数えてください`2 * b[i] >= m`、チームAの高身長ゴールキーパー相手にシュートを打っているからです。`m`。 

両方のゴール数を取得したら、それらを比較します。 チーム A がより多くのゴ​​ールを持っている場合、アリスは正しいです。 チーム B がより多くのゴ​​ールを持っている場合、ボブは正しいです。 カウントが等しい場合、2 つのチームの最大シュート力を比較し、最大値が大きいチームを勝者として宣言します。 

すべてのプレイヤーが 1 回検査されるため、実行時間は直線的です。`n`。 制約を考慮すると、これは十分すぎる速度です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 この問題では、ルール自体がすべてのプレイヤーを少なくとも 1 回検査する必要があるため、ブルート フォース シミュレーションがすでに最適になっています。 

## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 
2. 各テスト ケースについて、次の内容を読んでください。`n`、`m`、 そして`k`。 
3. チーム A のシュート力とチーム B のシュート力を読み取ります。 
4. すべての値をチェックしてチーム A のゴールを数えます`a[i]`。 ゴールが決まるのは、`2 * a[i] >= k`。 
5. すべての値をチェックしてチーム B のゴールを数えます`b[i]`。 ゴールが決まるのは、`2 * b[i] >= m`。 
6. チーム A のゴール数が大きい場合は、次のように出力します。`"Alice"`。 
7. チーム B のゴール数が大きい場合は、次のように出力します。`"Bob"`。 
8. ゴール数が等しい場合は、次のように計算します。`max(a)`そして`max(b)`。 チームAの最大値が大きい場合は印刷`"Alice"`、それ以外の場合は印刷します`"Bob"`。 

### なぜ効果があるのか

 アルゴリズムは一致ルールに正確に従います。 

すべてのプレーヤーが必要な得点条件に照らしてチェックされるため、ステップ 4 と 5 で計算されたカウントは、正確に各チームのペナルティーキックの成功数となります。 カウントが異なる場合は、定義上、より多くのゴ​​ールを獲得したチームが勝つ必要があります。 

カウントが同じ場合、ルールでは、個人のシュート力が最も高い人が勝者を決定すると規定されています。 比較する`max(a)`そして`max(b)`このタイブレークを正確に再現します。 すべての決定が仕様と一致するため、アルゴリズムは常に正しい勝者を返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, m, k = map(int, input().split())

    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    goals_a = sum(1 for x in a if 2 * x >= k)
    goals_b = sum(1 for x in b if 2 * x >= m)

    if goals_a > goals_b:
        print("Alice")
    elif goals_b > goals_a:
        print("Bob")
    else:
        if max(a) > max(b):
            print("Alice")
        else:
            print("Bob")
```最初のループは、各テスト ケースを独立して処理します。 

ゴール数の計算には次のものを使用します。`2 * x >= height`比較するのではなく`height / 2`。 これにより、浮動小数点演算が回避され、奇数のゴールキーパーの高さが正しく処理されます。 

タイブレークはゴール数が等しい場合にのみ評価されます。 すべてのシュート力は異なるため、最大値が同じになることはなく、比較では常に 1 つのチームが勝ちます。 

入力値を保存する以外に追加の配列やデータ構造は必要ありません。

import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    t = int(input())
    out = []

    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        ga = sum(1 for x in a if 2 * x >= k)
        gb = sum(1 for x in b if 2 * x >= m)

        if ga > gb:
            out.append("Alice")
        elif gb > ga:
            out.append("Bob")
        else:
            out.append("Alice" if max(a) > max(b) else "Bob")

    return "\n".join(out)

 高さのしきい値が奇数の場合を考えてみましょう。```
1

アルゴリズムは以下を評価します。```

4 >= 5

```したがって、チーム A の得点は 0 です。 

チームBが高さに対してシュートを放つ`5`同じように：```

```チームBも0得点。 

タイブレークは最大値を比較します。`2`対`1`, したがって、チームAが勝ちます。 このアルゴリズムは、べき乗を誤って計算する原因となる整数の除算の間違いを回避します。`2`目標として。 

次に、同点のスコアラインを考えてみましょう。```
1
2 4 4
2 10
3 9
```すべてのプレーヤーのパワーが少なくとも`2`。 

アルゴリズムはタイブレーク段階に到達します。```
max(A) = 10
max(B) = 9
```以来`10 > 9`、印刷されます`"Alice"`。 

ゴール数のみを比較するソリューションでは、この状況が未解決として誤って扱われてしまいます。 

最後に、可能な最小の入力を検討します。```
1
1 1 1
1
2
```両方のプレーヤーが得点したのは、`1`は`0.5`。 

ゴール数は 1 で結ばれます。最大値は次のとおりです。`1`そして`2`、チーム B が勝ち、アルゴリズムが出力します。`"Bob"`。 

これにより、実装がすべての制約の下限を正しく処理していることが確認されます。
