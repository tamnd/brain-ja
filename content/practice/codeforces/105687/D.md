 ## 解決策
 ## 問題の理解

 小文字の文字列と多くの部分文字列のクエリが与えられます。 クエリ間隔ごとに$[l, r]$、その部分文字列のみを調べます。 

2 つの等しい文字で一致を形成でき、すべての文字が最大 1 つの一致に属することができます。 目標は、選択した部分文字列内で可能な限り多くの一致を達成することです。 一致を作成する前に、文字を変更して、任意の位置を任意の小文字に置き換えることができます。 

クエリごとに、部分文字列が可能な最大数の一致を達成できるように、必要な文字変更の最小数を見つける必要があります。 

部分文字列に長さがある場合$m$、素のペアの可能な最大数は次のとおりです。$\lfloor m/2 \rfloor$。 有効な最終的な配置では、ペアになっていない文字を最大 1 つ残す必要があります。 

入力サイズが大きいです。 すべてのテスト ケースにわたる合計値は、$n + q$せいぜい$2 \cdot 10^5$。 クエリされたすべての部分文字列のすべての文字をスキャンするソリューションには、次のものが必要です。$O(nq)$最悪の場合、動作が遅すぎます。 に近いものが必要です$O(1)$または$O(\text{alphabet size})$クエリごとに。 

誤って対処しやすい状況がいくつかあります。 

考慮する：```
substring = "abcdef"
```すべての周波数は 1 です。長さは 6 なので、3 つのペアが必要です。 たとえば、次のように 3 つの変更を正確に実行する必要があります。```
abcdef -> aabbcc
```A greedy idea such as "change characters until all letters become equal" would use many more operations than necessary.

 考慮する：```
substring = "aaabbb"
```周波数は次のとおりです。$3$そして$3$。 すでに 2 つのペアがあります。```
aaa -> one pair + one leftover
bbb -> one pair + one leftover
```追加のペアが 1 つだけ不足しているため、答えは 1 になります。 

次のことを考慮してください。```
substring = "abcde"
```長さが奇数です。 1 文字は一致しないままにすることができます。 答えは 3 ではなく 2 です。```
abcde -> aabcd
```ここで、多くの実装がすべての文字をペアにしようとして間違いを犯します。 

## アプローチ

 ブルート フォース ビューでは、クエリされた部分文字列を検査し、頻度をカウントし、完全にペアリング可能な構成に到達するために必要な最小限の編集数を何らかの方法で検索します。 これはすぐに非現実的になります。$10^5$テストケースごとのクエリ。 クエリごとに頻度を最初から再計算するだけでもコストがかかります$O(nq)$最悪の場合の運用。 

重要な観察は、パリティを観察することから得られます。 

手紙が出てきたとします$c$回。 貢献します$\lfloor c/2 \rfloor$既存のペア。 すべての文字を合計すると、すでに存在するペアの数が得られます。 

部分文字列の長さを次のようにします$m$、そしてさせてください`odd`頻度が奇数の文字の数になります。 

使用する$$\sum \left\lfloor \frac{c_i}{2} \right\rfloor
=
\frac{m - \text{odd}}{2},$$現在のペアの数は、奇数の周波数の数によって完全に決まります。 

可能なペアの最大数は次のとおりです。$\lfloor m/2 \rfloor$。 不足しているペアの数は、$$\left\lfloor \frac{m}{2} \right\rfloor
-
\frac{m-\text{odd}}{2}.$$この式を評価すると次のようになります。 

偶数の場合$m$:$$\frac{\text{odd}}{2}$$奇数の場合$m$:$$\frac{\text{odd}-1}{2}$$どちらの場合もまさにそうです$$\left\lfloor \frac{\text{odd}}{2} \right\rfloor.$$次に、1 つの文字変更について考えてみましょう。 1 つの奇数頻度の文字から残った文字を取り出し、それを別の奇数頻度の文字に変換して、2 つの奇数を削除し、追加のペアを 1 つ作成できます。 したがって、必要な追加ペアごとに 1 回の変更が必要になります。 

問題は、クエリされたすべての部分文字列内の奇数の周波数の数を見つけることに帰着します。 

アルファベットには 26 個の小文字しか含まれていないため、プレフィックス頻度配列を構築できます。 次に、各クエリは 26 の周波数を再構築します。$O(26)$時間と奇数の数を数えます。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(n)$クエリごと |$O(1)$| 遅すぎる |
 | 最適 |$O(26)$クエリごと |$O(26n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 26 個すべての小文字のプレフィックス頻度カウントを作成します。 
2. クエリごとに$[l, r]$、接頭辞の違いを使用して、部分文字列内のすべての文字の頻度を計算します。 
3. これら 26 個の周波数のうち、奇数の周波数がいくつあるかを数えます。 この値を呼び出します`odd`。 
4. 出力`odd // 2`。 

ステップ 4 が機能する理由は、すべての変更が 2 つの奇数周波数グループを 1 つの追加のペアにマージできるためです。 あれば`odd`奇数の数がある場合は、多くても 1 つを除いてすべてを削除する必要があります。 必要な消去数は正確に`odd // 2`。 

### なぜ効果があるのか

 不変条件は、偶数パリティの周波数では不一致文字が発生しないのに対し、奇数パリティの周波数では不一致文字が 1 つだけ発生するということです。 

次の部分文字列`odd`奇数頻度の文字は正確に`odd`比類のないキャラクター。 最大限の一致を実現するために、一致しない文字が最大 1 つ残ることがあります。 編集するたびに、1 つの文字を 1 つの奇数グループから別の奇数グループに移動するため、一致しない文字の数を 2 つ減らすことができます。 したがって、必要な編集の最小数は正確に次のとおりです。`odd // 2`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, q = map(int, input().split())
        s = input().strip()

        pref = [[0] * (n + 1) for _ in range(26)]

        for i, ch in enumerate(s, 1):
            idx = ord(ch) - ord('a')

            for c in range(26):
                pref[c][i] = pref[c][i - 1]

            pref[idx][i] += 1

        ans = []

        for _ in range(q):
            l, r = map(int, input().split())

            odd = 0

            for c in range(26):
                freq = pref[c][r] - pref[c][l - 1]
                odd += freq & 1

            ans.append(str(odd // 2))

        sys.stdout.write("\n".join(ans) + "\n")

solve()
```プレフィックス配列には、すべての文字の累積数が保存されます。 クエリ間隔内の文字の頻度は、2 つのプレフィックス値を減算することによって取得されます。 

各クエリについて、部分文字列自体を検査することはありません。 26 文字の数のみを検査します。 答えは、これらのカウントのうち奇数がいくつあるかによって決まります。 

最も一般的な実装上の間違いは、クエリのインデックスが 1 であることを忘れることです。 使用する`pref[c][r] - pref[c][l - 1]`1 つずつずれたエラーを回避します。 

もう 1 つの微妙な点は、答えが部分文字列の長さに基づいていないことです。 周波数がわかったら、重要なのはパリティ パターンだけです。 長さがまったく異なる 2 つの部分文字列でも、奇数頻度の文字の数が同じであれば、同じ答えが得られます。
