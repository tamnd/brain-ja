 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、カード値の配列とパラメーターがあります。$k$。 これらのカードから、いくつかのサブシーケンスを選択することができますが、選択が最適化しようとしているものを解釈すると、実際の順序制約は無関係であることがわかります。 主要な制限は、選択された選択が、関連するグループ化構造を効果的に尊重する必要があるということです。$k$つまり、有用な構造は、サイズの完全なグループがいくつあるかということです。$k$私たちが形成できるものと、そこからどのような価値を抽出できるのか。 

タスクは、選択したカードから導き出される合計スコアを最大化することであり、重要な隠れた単純化は、元の配列内のカードの位置が、選択する枚数を超えて最適性を制限しないことです。 重要なのは、含める値と、選択範囲がサイズの塊で効果的に処理されるという事実だけです。$k$。 

入力は複数のテスト ケースで構成され、それぞれが整数を与えます$n$、整数$k$、および配列$n$カードの値を表す整数。 各テスト ケースの出力は、選択ルールに基づいて達成可能な最大スコアを表す単一の整数です。 

制約の議論から重要な意味は次のとおりです。$n$すべてのテスト ケースで大きくなる可能性があり、最大で$10^5$、複数のテスト ケースが存在する可能性があります。 両方に依存する素朴な DP$n$そして$k$テスト ケースごとに、おおよそ次のような複雑さが生じます。$O(t \cdot n \cdot k)$、約に縮退します$10^9$最悪の場合の運用。 これはすでに一般的な制限を超えているため、位置とグループ数にわたって 2 次元の状態を維持するソリューションは合格しません。 

サブシーケンスの選択によって順序の関連性が維持されると仮定すると、微妙な落とし穴が現れます。 たとえば、値について考えてみましょう。$[1, 100, 2, 99]$と$k = 2$。 不用意なアプローチでは、インデックスを考慮してペアの選択をシミュレートしようとする可能性がありますが、合計の寄与のみが重要であるため、最良の解決策は、隣接性や元の位置を気にせずに単純に上位の値を選択することです。 元の順序制約を誤って保持するアルゴリズムでは、選択が過少にカウントされたり、過度に複雑になったりします。 

## アプローチ

 最も直接的な定式化は、配列に対する動的プログラミングの観点から、これまでに取得した項目の数を考えることです。 次のような状態を定義できます$dp[i][j]$、インデックスにいることを意味します$i$そして選択した$j$要素、完全なサイズのグループのみというルールに基づいて合計を最大化しようとします$k$貢献する。 遷移では、各要素を取得するかスキップするかを考慮します。 

このアプローチは、すべての制約を明示的に尊重するため正しいですが、すぐにコストが高くなります。 状態の数は$O(n \cdot n)$最悪の解釈で、少なくとも$O(n \cdot k)$、各遷移は一定であり、テスト ケースごとに 2 次または疑似 2 次の動作が生じます。 入力サイズが大きい場合、これはすぐに実行不可能になります。 

重要な構造的観察は、元の配列の隣接性が最終スコアに影響を与えないことです。 選択は部分的なものであるため、思考を自由に並べ替えることができます。重要なのは、どの値が選択されたかだけであり、その値がどこから来たのかではありません。 これにより、問題は純粋に値ベースの最適化に変わります。 

順序が無関係になると、配列を降順に並べ替えるのが自然な戦略になります。 並べ替え後、最適解は利用可能な最大値を最初に取得する必要があります。これより小さな値は、代わりに大きな値で形成される可能性のあるグループを改善することはできないためです。 貢献は要素をサイズの塊として取得することに結びついているため、$k$、このソートされた配列の接頭辞の合計を評価し、選択された要素の数が次の倍数である位置のみを考慮します。$k$。 これらの有効なプレフィックスのうち、最大のプレフィックス合計が答えになります。 

これが機能するのは、すべての有効な解がある程度の数の要素を選択することに対応しており、固定数の場合、利用可能な最大の要素を選択すると合計が最大化されるためです。

 ## アルゴリズムのチュートリアル

 1. テスト ケースのすべての値を読み取り、配列に格納します。 これにより、再解釈後の隣接性に依存する制約がないため、元の位置を無視する完全な自由が得られます。 
2. 配列を降順に並べ替えます。 これにより、要素の取得を検討するときは常に、最も価値のあるものを最初に優先することが保証されます。 
3. ソートされた配列に対してプレフィックスの合計を計算します。 位置のプレフィックスの合計$i$正確に上部を取得した場合、可能な限り最高の合計を表します$i$要素。 
4. インデックスのみを考慮する$i$そのような$i$の倍数です$k$。 これらの位置は、サイズの完全なグループの形成に対応します$k$、スコアリング構造にとって意味のあるチェックポイントはこれだけです。 
5. これらの有効な位置の中で最大のプレフィックス合計を追跡し、それを答えとして出力します。 

### なぜ効果があるのか

 有効な解決策はすべて、サイズの一部の選択に対応します。$m$、その値は選択された要素の合計です。 固定の場合$m$、最適なサブセットは常に$m$選択された小さい要素を選択されていない大きい要素に置き換えると、厳密に合計が増加するため、最大の要素が使用されます。 グループ化制約は以下にのみ依存するため、$m \bmod k = 0$の倍数のみを評価します。$k$。 ソートされたプレフィックスにより、サイズごとに可能な限り最良のサブセットが常に評価されることが保証されるため、これらの候補の中から最良のものを選択することで、全体的な最適値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        a.sort(reverse=True)
        
        prefix = 0
        best = 0
        
        for i in range(n):
            prefix += a[i]
            if (i + 1) % k == 0:
                best = max(best, prefix)
        
        print(best)

if __name__ == "__main__":
    solve()
```この解決策は、すべてのプレフィックスが指定されたサイズの最適な選択肢を表すように、配列を降順に並べ替えることから始まります。 プレフィックス合計変数は、選択したカードの現在までの合計を累積します。 

重要な実装の詳細はチェックです`(i + 1) % k == 0`。 Python はゼロベースのインデックスを使用するため、長さの接頭辞は$i+1$の倍数になったら完成です$k$。 これらの時点でのみ、グループ化制約によって有効な構成を評価できます。 

変数`best`すべての有効なプレフィックス長の最大合計を追跡します。 負の値が可能である場合、または制約で空の選択が許可されている場合、要素を取得しないことが常に有効なベースラインとなるため、これをゼロに初期化します。

 ## 特殊なケース

 重要なエッジケースは、すべての値が負の場合です。 たとえば、次のことを考えてみましょう。```
1
3 2
-1 -2 -3
```並べ替えると、次のようになります$[-1, -2, -3]$。 プレフィックスの合計は次のとおりです。$-1, -3, -6$。 長さ 2 のプレフィックスのみが有効です。$2$の唯一の倍数です$k$以下$n$、その和は$-3$。 ただし、解釈によっては何も選択しないことが暗黙的に許可される場合があるため、アルゴリズムは初期化します。`best = 0`、答えが否定的にならないようにします。 

もう 1 つのエッジケースは次のような場合です$n < k$。 この場合、空の選択以外に有効なプレフィックスが存在しないため、結果は 0 のままです。条件を満たすインデックスがないため、並べ替えとスキャンによってこれが自然に処理されます。`(i+1) % k == 0`、出発`best`変わらない。
