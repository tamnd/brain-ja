 ## 解決策
 ## 問題の理解

 ビットランドのソーセージを表す単一の整数配列が与えられます。 目標は、このソーセージを 2 つの重ならないセグメント (BitHaval の接頭辞と BitAryo の接尾辞) に切断することです。 どちらのセグメントも空にすることができます。 各人の「おいしさ」はセグメント内の整数のビット単位の XOR であり、その人の総合的な喜びは 2 つのおいしさの値の XOR です。 私たちはこの喜びを最大化したいと考えています。 

入力サイズは最大 100,000 個の整数であり、各整数は以下のサイズにすることができます。$10^{12}$。 これは、考えられるすべてのプレフィックスとサフィックスの分割にわたってネストされたループを含むソリューションは遅すぎることをすぐに示します。プレフィックスとサフィックスの終わりのすべてのペアを反復処理すると、次のようになります。$O(n^2)$のオーダーです。$10^{10}$操作。 線形に近いか、せいぜい線形演算的なものが必要です。$n$。 

ここでのエッジケースは微妙です。 最も単純なケースは、配列の長さが 1 の場合です。この場合、空でないセグメントは要素自体だけであり、他の人は何も取得しません。 もう 1 つのエッジ ケースは、すべての要素が 0 である場合です。この場合、すべてのセグメントの XOR が 0 になります。 不注意なアプローチでは、両方のセグメントが空ではないと仮定する可能性がありますが、問題では空のセグメントが許容され、それらの XOR がゼロになるため、最適な分割が変更される可能性があります。 

## アプローチ

 ブルートフォース手法では、プレフィックスの終わりごとに、考えられるすべての分割を反復します。$i$0から$n$、プレフィックスの XOR とサフィックスの XOR を計算し、それらの XOR を取得します。 毎回プレフィックスとサフィックスの XOR を最初から計算するのは$O(n)$、全体的な結果につながります$O(n^2)$複雑。 これは小さな配列では機能しますが、遅すぎます。$n = 10^5$。 

XOR には結合性があり、次のプロパティがあることがわかります。$a \oplus b = c \Rightarrow a = b \oplus c$。 プレフィックス XOR 配列を事前計算すると、$\text{px}[i] = a[0] \oplus a[1] \oplus \dots \oplus a[i]$、その後、位置で始まる任意のサフィックスの XOR$j$次のように書くことができます$\text{px}[n-1] \oplus \text{px}[j-1]$のために$j > 0$、そして単純に$\text{px}[n-1]$のために$j = 0$。 これにより、繰り返しの計算が削減されます。 

次の洞察は、問題が次のように要約されることです。プレフィックス XOR のリストが与えられた場合、それらの XOR の XOR が最大化されるような 2 つの重複しないセグメントを見つけます。 これは、配列内の任意の 2 つの数値の最大の XOR を見つけるという古典的な問題と同等です。 これは、バイナリ トライまたは独立したビット ベクトルの基底 (線形基底とも呼ばれる) を使用して解決できます。 各プレフィックス XOR は基底に挿入でき、現在のプレフィックスと以前のプレフィックスの最大 XOR は基底をクエリすることによって取得されます。 これにより、$O(n \cdot \log M)$解決策、ここで$M$可能な最大の整数です ($10^{12}$、 それで$\log M \approx 40$）。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | プレフィックス XOR + 線形基底 | O(n log M) | O(log M) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレフィックス XOR 配列を計算します。 させて$\text{px}[i] = a[0] \oplus a[1] \oplus \dots \oplus a[i]$。 これにより、任意のプレフィックス XOR の O(1) 計算が可能になります。 
2. XOR 最大化のための空の線形基底を初期化します。 線形基底とは、各数値が XOR に関して線形に独立しているような数値のセットです。つまり、基底内で他の数値を XOR することによって数値を形成することはできません。 
3. プレフィックス XOR を繰り返します。 それぞれのステップで$i$、私たちは治療します$\text{px}[i]$BitAryo のセグメントの潜在的な XOR として、以前のプレフィックス (潜在的な BitHaval セグメント) との XOR を最大化したいと考えています。 現在の基底をクエリして、最大化する数値を見つけます。$\text{px}[i] \oplus \text{basis element}$。 
4. クエリを実行した後、次のように挿入します。$\text{px}[i]$基礎に。 これにより、将来のサフィックスは、このプレフィックス XOR を最大 XOR の候補として使用できるようになります。 
5. これらの反復中に見つかったグローバル最大 XOR を追跡し、それを出力します。 

機能する理由: プレフィックス XOR 配列は、考えられるすべてのプレフィックスとサフィックス XOR が表現されることを保証します。 線形基礎により、以前のプレフィックス XOR のサブセットから可能な限り最大の XOR を構築できることが保証されます。 XOR は結合的で可逆であるため、このメソッドはすべての有効なプレフィックスとサフィックスの分割を暗黙的に検査します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class LinearBasis:
    def __init__(self):
        self.basis = [0] * 64

    def insert(self, x):
        for i in reversed(range(64)):
            if x & (1 << i):
                if self.basis[i]:
                    x ^= self.basis[i]
                else:
                    self.basis[i] = x
                    return

    def query_max(self, x):
        res = x
        for i in reversed(range(64)):
            if self.basis[i]:
                res = max(res, res ^ self.basis[i])
        return res

def main():
    n = int(input())
    a = list(map(int, input().split()))
    
    px = [0] * n
    px[0] = a[0]
    for i in range(1, n):
        px[i] = px[i-1] ^ a[i]

    lb = LinearBasis()
    max_pleasure = 0
    lb.insert(0)  # include empty prefix
    for val in px:
        max_pleasure = max(max_pleasure, lb.query_max(val))
        lb.insert(val)
    print(max_pleasure)

if __name__ == "__main__":
    main()
```コードは最初にプレフィックス XOR を計算します。 次に、線形基礎を維持して、現在のプレフィックス XOR との XOR を最大化する数値をすばやく見つけます。 最初に 0 を挿入すると、空のプレフィックスの場合が処理されます。 プレフィックス XOR のループにより、重複しないプレフィックスとサフィックスの分割がすべて暗黙的に考慮されるようになります。
