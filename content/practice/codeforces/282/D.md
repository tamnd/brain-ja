 ## 解決策
 ## 問題の理解

 私たちは、2 人のプレーヤーが交互に手を動かす、非常に小さな整数のシーケンスを使用したターンベースのゲームで勝者を決定するように求められます。 各ターンで、プレイヤーは単一の要素を任意の正の量だけ減らすか、すべての要素を同じ正の量だけ減らすことができます。 最初に行動できなかったプレイヤーが負けとなります。 入力は要素の数を提供します`n`(1 と 3 の間) とシーケンスの初期値。それぞれ厳密に 300 未満です。出力は単に、完璧なプレイで勝利をもたらすことができるプレイヤーの名前です。 

なぜなら`n`が最大 3 である場合、非常に小さなゲーム状態空間を扱っていることになります。 それぞれ`a_i`は 300 未満であるため、単純な再帰的アプローチを試みたとしても、状態の総数は最大でも 300³ = 27,000 であり、これは容易に管理できます。 これは十分に小さいため、すべての可能な動きを徹底的に調査することが可能です。 問題の制約は基本的に、ソリューションがそれ以上のパフォーマンスを心配することなく、組み合わせまたは動的プログラミングのアプローチを提供できることを示唆しています。 

プレイヤーはゼロ要素を正の数で減らすことができないため、明らかではないエッジ ケースにはゼロを含むシーケンスが含まれます。 たとえば、入力の場合`1 0 0`、他の 2 つは個別に、または正の減算でまとめて選択できないため、最初のプレイヤーは最初の要素のみを減らさなければなりません。 グローバルな手のルールを誤解すると、手が常に可能であると思い込み、勝者の予測が不正確になる可能性があります。 

すべての数値が等しい場合、別の微妙なケースが発生します。 のために`2 2 2`、プレイヤーは任意の 1 つの要素から 1 を減算する誘惑に駆られるかもしれませんが、すべての要素から同時に 1 を引く方が戦略的により重要になる可能性があります。 単一要素の移動とグローバルな移動の両方を正しく処理することが重要です。 

## アプローチ

 ブルートフォース手法では、すべての有効な手を再帰的に列挙します。 特定の状態に対して`(a1, a2, a3)`では、1 から現在の値までのすべての単一要素の減算と、1 から最小の要素までのすべてのグローバルな減算を試みます。 結果として得られる各状態について、次のプレイヤーが勝つことができるかどうかを再帰的に判断します。 対戦相手を負け状態に追い込む手が少なくとも 1 つ存在すれば、プレイヤーは勝つことができます。 これにより、すべての正当な動きのシーケンスが調査されるため、正確さが保証されます。 欠点は、メモ化を行わないと、状態空間が十分に小さいため、単純な再帰でも妥当な時間内に実行されるにもかかわらず、アルゴリズムが同じ状態の計算を複数回繰り返すことです。 

最適なアプローチでは、ゲームが Nim ゲームのバリエーションと同等であると認識されます。 のために`n=1`、単一の数字が勝者を自明に決定します。正の数字があれば、最初のプレイヤーはそれをゼロに減らして勝つことができます。 のために`n=2`、Sprague-Grundy 値は次のとおりであることが知られています。`(a, b)`グローバルな減算が存在する場合、数値の XOR と等しくなります。 のために`n=3`、同じ原理が少し変更を加えて適用されます。単一要素とグローバル ムーブの各組み合わせは 3 次元の Sprague-Grundy 値として表すことができ、勝利条件はグローバル ムーブを考慮した後で数値の XOR を計算することになります。 

言い換えれば、各状態のグランディ数を、可能性のあるグローバルな減算のために調整された個々の数値の XOR として慎重に定義することによって、問題は古典的な公平なゲーム計算になります。 メモ化により、状態をキャッシュし、冗長な計算を回避できます。

 ## アルゴリズムのチュートリアル

 1. 各ゲーム状態をタプルとして表現します`(a1, a2, a3)`。 もし`n`が 2 または 1 の場合は、均一性を維持するためにタプルにゼロを埋め込みます。 これにより、一貫した DP/メモ化構造が可能になります。 
2. 各状態をその勝利状態にマッピングするメモ化テーブルを定義します。 重要な洞察は、どの手が相手の負け状態につながるかわからない場合、その状態は負けているということです。 それ以外の場合は勝ちです。 
3. 特定の状態について、すべての単一要素の移動を繰り返します。 ゼロより大きい各要素について、可能なすべての要素を減算します。`x`1 から現在の値まで変化し、新しい状態を形成します。 この状態を再帰的に評価します。 
4. 次に、世界的な動きを検討します。 許容される減算の最大値は、現在の状態の最小要素です。 それぞれについて`x`1 からこの最小値まで、減算します`x`すべての要素から取得し、結果の状態を再帰的に評価します。 
5. 何らかの手が相手の負けの状態につながる場合、現在の状態を勝ちとしてマークします。 すべての手が相手の勝利状態につながる場合、現在の状態を負けとしてマークします。 
6. 基本ケースはすべての要素がゼロの場合に発生します。これは、移動が不可能であるため、自動的に負けになります。 
7. 入力状態から再帰を初期化します。 状態が勝利している場合、最初のプレーヤー (BitLGM) は強制的に勝利をもたらすことができます。 それ以外の場合は、2 番目のプレーヤー (BitAryo) が勝ちます。 

機能する理由: グランディ数の原理により、通常のプレイにおけるすべての公平なゲームが再帰的に評価できることが保証されます。 再帰ではすべての手が考慮され、メモ化により各状態が 1 回だけ計算されることが保証されるため、勝利条件は正しく伝播され、組み合わせの爆発を防ぎ、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1000000)

n = int(input())
a = list(map(int, input().split()))
while len(a) < 3:
    a.append(0)

memo = {}

def can_win(state):
    state = tuple(state)
    if state in memo:
        return memo[state]
    if all(x == 0 for x in state):
        memo[state] = False
        return False
    
    for i in range(3):
        for x in range(1, state[i] + 1):
            new_state = list(state)
            new_state[i] -= x
            if not can_win(new_state):
                memo[state] = True
                return True
    
    min_val = min(state)
    for x in range(1, min_val + 1):
        new_state = [v - x for v in state]
        if not can_win(new_state):
            memo[state] = True
            return True

    memo[state] = False
    return False

winner = "BitLGM" if can_win(a) else "BitAryo"
print(winner)
```この解決策では、均一に処理するために、まずシーケンスを 3 つの要素に正規化します。 の`can_win`関数は、個別およびグローバルの両方のすべての有効な手を再帰的に評価します。 メモ化により、冗長な作業が回避されます。 基本ケースでは、すべてのゼロがチェックされ、負けステータスが返されます。 最終的には初期状態が勝っているかどうかで勝敗が決まります。
