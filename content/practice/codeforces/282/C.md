 ## 解決策
 ## 問題の理解

 2 つのバイナリ文字列が与えられます。 演算により、隣接するビットのペアが選択されます。 ペアの場合`(x, y)`、次のように計算します。 

-`p = x xor y`-`q = x or y`それから書きます`p`1つの位置に配置され、`q`どちらかの順序で他の位置に移動します。 

文字列の長さは決して変わりません。 文字列から始める`a`、そのような操作のシーケンスによって文字列に変換できるかどうかを判断する必要があります。`b`。 

文字列の長さは 100 万文字までです。 これにより、変換をシミュレートしたり、到達可能な状態を検索しようとするアプローチは即座に排除されます。 リニア スキャンでもすでに 100 万文字を処理しているため、目標の複雑さは次のようになります。`O(n)`。 

難しいのは、操作によってどのような情報が保持され、どのような情報が変更される可能性があるかを理解することです。 

最初の明白ではないエッジケースは、長さが異なる場合です。 

入力：```
1
11
```出力：```
NO
```すべての操作は 2 つの既存の位置に作用し、文字の挿入や削除は行われません。 長さは不変であるため、異なる長さの文字列を相互に変換することはできません。 

もう 1 つの重要なケースは、1 つの文字列にゼロのみが含まれる場合です。 

入力：```
000
001
```出力：```
NO
```すべてゼロから始まり、すべての隣接するペアは次のようになります。`(0,0)`。 操作により生成されるのは、`(0 xor 0, 0 or 0) = (0,0)`, したがって、文字列は決して変更されません。 長さだけをチェックする不注意な解決策では、誤って「YES」と答えることになります。 

より微妙なケースは次のとおりです。 

入力:```
10
01
```出力：```
YES
```での操作`(1,0)`与える`(1,1)`そして`(0,1)`可能な出力として。 2 番目の配置を選択すると、直接次の結果が得られます。`01`。 オブジェクトの正確な位置を追跡するソリューションは、オブジェクトが動き回る可能性があるため失敗します。 

別のエッジケースは次のとおりです。 

入力:```
111
000
```出力：```
NO
```操作によって 1 の数を減らすことはできますが、最後に残った 1 を削除することはできません。 少なくとも 1 つの存在`1`が重要な不変式であることがわかります。 

## アプローチ

 ブルート フォース アプローチでは、固定長のすべてのバイナリ文字列を状態として表示し、到達可能なすべての状態に対してグラフ検索を実行します。 長さに関しては`n`、 がある`2^n`可能な文字列。 たとえ`n = 50`、その数はすでに天文学的に大きく、実際の制限は`10^6`。 状態空間の探査は完全に不可能です。 

より良い解決策を見つけるには、操作が実際に何を行うのかを理解する必要があります。 

考えられるすべての隣接ペアを考慮します。 

| オリジナル | xor | または |
 | --- | --- | --- |
 | 00 | 0 | 0 |
 | 01 | 1 | 1 |
 | 10 | 1 | 1 |
 | 11 | 0 | 1 |

 重要な観察は、操作後のペアには、`1`元のペアに`1`。 

のために`00`、結果はまだです`00`。 

のために`01`そして`10`、結果は 2 ビットになり、その値は次のとおりです。`{1,1}`。 

のために`11`、結果は次のようになります`{0,1}`。 

いずれの場合も、少なくとも 1 つを含むペア`1`少なくとも 1 つを含み続ける`1`。 なしのペア`1`決して1つも得られません。 

これは、文字列全体が最後の残りを失うことがないことを意味します。`1`、すべてゼロの文字列は決して作成できません`1`。 

次の問題は、それが唯一の制限であるかどうかです。 

文字列に少なくとも 1 つが含まれていると仮定します。`1`。 その後、操作を繰り返し使用してそれを移動できます`1`周囲に配置して、0 と 1 の任意の配置を作成します。 実際、同じ長さの 2 つの文字列で、両方に少なくとも 1 つが含まれているものは、`1`相互に到達可能です。 これが問題の背後にある重要な定理です。 

したがって、変換の質問は 2 つのチェックのみに減ります。 

1. 長さは等しくなければなりません。 
2. 両方の文字列に少なくとも 1 つが含まれるか、`1`、または両方の文字列に何も含まれていません`1`。 

これにより、単純な線形時間の解決策が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(2^n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取る`a`そして`b`。 
2. 長さが異なる場合は印刷します。`"NO"`。 

この操作では位置の数が変更されることはないため、異なる長さは不可能です。 
3. かどうかを確認します。`a`少なくとも 1 つ含まれています`'1'`。 
4. かどうかを確認します。`b`少なくとも 1 つ含まれています`'1'`。 
5. 両方のチェックの結果が同じ場合は、次のように出力します。`"YES"`。 

これには次の 2 つの状況が含まれます。 

- 両方の文字列がすべてゼロです。 
- 両方の文字列に少なくとも 1 つが含まれます`1`。 
6. それ以外の場合は印刷します`"NO"`。 

### なぜ効果があるのか

 この操作では、「この文字列には少なくとも 1 つの文字列が含まれているか」というプロパティが保存されます。`1`?"。すべてゼロの文字列は、すべての操作が実行されるため、永久にすべてゼロのままです。`00`生成する`00`。 逆に、文字列に`1`、すべての操作で少なくとも 1 つの存在が維持されます。`1`で、最終回`1`決して消えることはありません。 

さらに深い事実は、文字列に少なくとも 1 つの文字列が含まれると、`1`、 それ`1`文字列を通じて伝播および移動できます。 繰り返し操作を使用すると、ゼロ以外のバイナリ文字列を、同じ長さの他のゼロ以外のバイナリ文字列に変換できます。 したがって、固定長の文字列の中には、すべて 0 の文字列と、少なくとも 1 つを含むすべての文字列の 2 つの連結コンポーネントが存在します。`1`。 

アルゴリズムはこれらの不変条件を正確にチェックするため、必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a = input().strip()
b = input().strip()

if len(a) != len(b):
    print("NO")
elif ('1' in a) == ('1' in b):
    print("YES")
else:
    print("NO")
```最初の条件は、長さが決して変わらないという不変条件を処理します。 

2 番目の条件は、両方の文字列が同じ到達可能性クラスに属しているかどうかを確認します。 表現`('1' in a)`と評価される`True`文字列に少なくとも 1 つの 1 ビットが含まれている場合、および`False`さもないと。 到達可能性を実現するには、これらの値が一致する必要があります。 

シミュレーションは必要ありません。 ソリューション全体は、操作の構造特性に基づいています。 

よくある間違いは、1 の数を比較しようとすることです。 1 の数は保存されません。 例えば、`11`なることができる`01`、カウントが 2 から 1 に減ります。 唯一保持されるプロパティは、カウントがゼロか正かどうかです。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    a = input().strip()
    b = input().strip()

    if len(a) != len(b):
        print("NO")
    elif ('1' in a) == ('1' in b):
        print("YES")
    else:
        print("NO")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue().strip()

# provided sample
assert run("11\n10\n") == "YES", "sample 1"

# minimum size
assert run("0\n0\n") == "YES", "single zero"

# minimum size, different classes
assert run("0\n1\n") == "NO", "cannot create a one"

# all-zero strings
assert run("00000\n00000\n") == "YES", "all-zero component"

# same length, both non-zero
assert run("1000\n0001\n") == "YES", "all non-zero strings are connected"

# different lengths
assert run("1\n11\n") == "NO", "length is invariant"

# large-style boundary case
assert run(("1" + "0" * 20) + "\n" + ("0" * 20 + "1") + "\n") == "YES", "non-zero strings"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`0 / 0`| はい | 可能な最小の有効な入力 |
 |`0 / 1`| いいえ | 1 つを作成することは不可能です |
 |`00000 / 00000`| はい | オールゼロコンポーネント |
 |`1000 / 0001`| はい | 1 の位置は関係ありません。
