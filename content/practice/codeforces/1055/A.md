 ## 解決策
 ## 問題の理解

 地下鉄システムは 1 から n までの駅の列として見ることができ、2 つの方向性のある移動方法があります。 1 つのトラックでは小さいインデックスから大きいインデックスへの移動が可能になり、もう 1 つのトラックでは反対方向への移動が可能になります。 ボブはステーション 1 から出発し、ステーション s に到達したいと考えています。 

複雑なのは、各駅が各方向への停車を個別に許可する場合と許可しない場合があることです。 電車が駅を通過する場合でも、ボブはその駅がその線路方向に開いている場合にのみ、乗り換えまたは停車地点として使用できます。 駅が閉鎖されている場合でも、列車は通過しますが、ボブはその方向への乗り降りができなくなり、事実上、その駅がその誘導された軌道上で使用可能なノードとして削除されます。 

このタスクは、駅 1 から駅 s への移動を可能にする、到達可能な駅での有効な乗車と可能な乗り換えのシーケンスが存在するかどうかを判断することです。 

入力サイズ n は最大 1000 です。これは、O(n^2) の走査、または O(n) ノードと O(n) エッジにわたる単純なグラフ検索でも十分であることを意味します。 指数関数的なものは必要ありませんが、単純な BFS や隣接関係を介したシミュレーションでも十分に高速です。 

微妙なエッジ ケースは、ボブが最初にステーション 1 で順方向にアクセスできないときに発生します。その場合、最初に逆方向に進み、次に方向を切り替えることで有効なパスが存在する場合でも、単調な移動を想定したり、方向の切り替えを無視したりすると、パスが失われる可能性があります。 

別のケースとして、駅 s に到達するには、遠方の駅まで迂回してから逆方向に戻る必要がある場合が発生します。 たとえば、順方向が早期にブロックされているが、逆方向が開いている場合、ボブは最初に右端の到達可能なステーションに移動する必要がある可能性があります。 

## アプローチ

 この構造は、各ステーションがノードとなる有向グラフを自然に形成します。 ステーション i から、ボブは最初の線路が i で開いていれば i+1 に移動でき、2 番目の線路が i で開いていれば i-1 に移動できます。 問題は、ノード 1 からノード s への到達可能性に帰着します。 

ブルートフォースアプローチでは、考えられるすべてのルートを列挙しようとし、場合によっては繰り返し再訪問してパスを探索します。 これは正しいですが、サイクルを含むグラフ内のウォーク数が指数関数的に増加するため、複雑さが爆発する可能性があります。 n が最大 1000 であっても、単純なパスの列挙は実行できません。 

重要な観察は、これが n 個のノードと最大 2n 個のエッジを持つグラフにおける標準的な到達可能性の問題であるということです。 正しくモデル化されれば、単純な BFS または DFS で十分です。各ステーションには最大 2 つの発信遷移 (順方向と逆方向に 1 つ) しかないからです。 この制約により、各ノードに 1 回アクセスすれば十分であることが保証されます。 

すべての遷移がローカルで決定的であるため、ブルート フォースは機能しますが、再訪によって繰り返される状態が爆発的に増加すると失敗します。 ノードにどのように到達するかではなく、ノードが到達可能かどうかだけを気にするという観察により、問題はグラフの走査に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパス | O(2^n) | O(n) 再帰スタック | 遅すぎる |
 | BFS/DFS の到達可能性 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ステーションをグラフ内のノードとしてモデル化します。

1. 許可された移動に基づいて隣接関係を構築します。 駅 i から、i + 1 ≤ n および a[i] = 1 の場合、i から i + 1 にエッジを追加します。i − 1 ≥ 1 および b[i] = 1 の場合、i から i − 1 にエッジを追加します。これらのエッジは、ボブがその方向に進む電車に物理的に乗車して次の駅に停止できるかどうかを表します。 
2. どのステーションがすでに処理されているかを追跡するために、サイズ n + 1 の訪問済み配列を初期化します。 これにより、同じステーションを複数回再訪問することがなくなり、冗長な探索が発生する可能性があります。 
3. ステーション 1 から BFS (または DFS) を開始し、訪問済みとしてマークします。 ステーション 1 は常にボブの出発点であるため、簡単に到達できます。 
4. BFS キューに未処理のステーションがある間に、1 つのステーション u を削除し、許可されたエッジ経由で到達可能なすべての隣接ステーション v を探索します。 v が訪問されていない場合は、v にマークを付けてキューに追加します。 
5. トラバースが終了したら、ステーション s が訪問されたかどうかを確認します。 「はい」の場合は「YES」を出力します。 それ以外の場合は「NO」を出力します。 

### なぜ効果があるのか

 BFS は常に、有効な遷移を使用してすべての訪問ステーションがステーション 1 から到達可能であるという不変条件を維持します。 すべてのエッジは駅と線路の制約の下での合法的な移動に対応するため、新しく発見された駅にも到達可能です。 BFS は、到達可能なすべての状態を反復せずに探索するため、最終的に 1 から到達可能なすべてのステーションを検出します。ステーション s がその中に含まれない場合、有効な一連の移動はそのステーションに到達できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, s = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    adj = [[] for _ in range(n + 1)]

    for i in range(n):
        if i + 1 < n and a[i] == 1:
            adj[i + 1].append(i + 2)
        if i - 1 >= 0 and b[i] == 1:
            adj[i + 1].append(i)

    visited = [False] * (n + 1)
    q = deque([1])
    visited[1] = True

    while q:
        u = q.popleft()
        for v in adj[u]:
            if not visited[v]:
                visited[v] = True
                q.append(v)

    print("YES" if visited[s] else "NO")

if __name__ == "__main__":
    solve()
```隣接構造は方向制約をエッジに直接エンコードするため、BFS は標準グラフ上で動作します。 前方エッジは、i から i + 1 への移動に対応するため、a[i] を使用します。後方エッジは、i から i − 1 への移動に対応するため、b[i] を使用します。 

一般的な実装の落とし穴は、入力は 1 から始まりますが、配列は 0 から始まることが多いため、off-by-one インデックス付けです。 ここでは、i + 1 をノード インデックスとして使用して隣接関係が構築されるため、すべてのグラフ ノードは一貫して 1 から始まり、混乱が回避されます。 

もう 1 つの微妙な問題は、移動が目的地の駅ではなく、現在の駅に依存するということを忘れていることです。 エッジを追加する前に、i で条件をチェックする必要があります。
