 ## 問題の理解

 位置のライン上で一連のヘアの長さを維持しており、一部の位置が成長するにつれてシステムは時間の経過とともに進化します。 いつでも、私たちは仮想のヘアカット操作を想像することができます。つまり、髪が固定のしきい値よりも厳密に長いすべてのポジションです。$l$正確に削減する必要があります$l$, ただし、ヘアカットツールには制限があります。 1 つの操作は連続したセグメントに対してのみ作用し、そのセグメント内のすべての位置が現在次の値を超えている場合にのみ機能します。$l$。 理髪店の目標は、すべての値を最大値まで下げるために必要なセグメント操作の数を最小限に抑えることです。$l$。 タイプ 0 の各クエリは、現在の状態でこの最小数の操作を要求しますが、タイプ 1 のクエリは単一の位置を永続的に増加します。 

キーオブジェクトは正確な値そのものではなく、インデックスが現在超過しているパターンです。$l$。 以下の任意のインデックス$l$触れる必要がなく、セグメントも切断されるため、切断には無関係です。 重要なのは、インデックスの連続ブロックがどれだけ多くの条件を満たすかです。$a_i > l$なぜなら、そのような各ブロックは 1 回の操作で削除できるからです。 

この制約により、直線に近い複雑さのオンライン ソリューションが求められます。 まで$10^5$更新とクエリの場合、タイプ 0 のクエリごとに答えを最初から再計算するには、毎回配列全体をスキャンする必要があり、$O(nm)$が遅すぎます。 

更新によって値が増加するだけであるという事実から、微妙な問題が発生します。 この単調さが重要です。 すでに上のポジション$l$ステータスを再度変更することはなく、以下の位置または同等の位置にあります。$l$非アクティブからアクティブに 1 回だけ反転できますが、元に戻ることはありません。 

単純な間違いは、変更された領域のみをスキャンしたり、マージを適切に処理せずにグローバル セグメントのエンドポイントを維持しようとしたりして、セグメントの数を再計算することです。 たとえば、次のような構成を考えてみましょう。$[1, 5, 1, 5]$と$l = 3$。 正解は 2 つのセグメントです。 各アクティブな位置が独立して 1 つの操作に寄与すると誤って仮定すると、隣接性を完全に無視して 4 が出力されることになります。 

もう 1 つの失敗モードは、単一の位置をアクティブにすると、以前は別々だった 2 つのセグメントがマージされる可能性があることを忘れることから発生します。 たとえば、インデックスにアクティブなポジションがある場合、$1$そして$3$、答えは 2 つのセグメントです。 インデックスの場合$2$がアクティブになると、正解は 1 になりますが、カウンターを増加させるだけのローカル更新アプローチでは、この減少を見逃してしまいます。 

## アプローチ

 ブルートフォース戦略は簡単です。 タイプ 0 の各クエリについて、配列全体をスキャンし、各位置が次の値を超えているかどうかを示すブール配列を構築します。$l$。 次に、偽の値の直後に真の値が出現する回数を数えます。最初のアクティブなセグメントが存在する場合は 1 回を加えます。 これにより、連続するブロックの数が正しく計算されますが、各クエリにはコストがかかります$O(n)$、全体的に複雑になります$O(nm)$、最悪の場合には遅すぎます。 

重要な観察は、各位置の状態が 1 回限りの遷移を伴うバイナリであるということです。 値が交差すると$l$、上に残ります$l$永遠に。 これは、任意の動的間隔を扱っているのではなく、ポイントの増分アクティブ化を扱っていることを意味します。 私たちが維持する構造は、ライン上のアクティブなインデックスの動的セット内の接続されたコンポーネントの数です。 アクティベーションごとに、新しいコンポーネントが作成されるか、2 つの既存のコンポーネントがマージされます。 

これにより、折れ線グラフでのポイント挿入時の接続コンポーネントの数を維持するという問題が軽減されます。 隣接関係は 1 次元であるため、素セット共用体構造または単純な近傍チェックで十分です。

 ## アルゴリズムのチュートリアル

 すべてのインデックスを非アクティブ (値$\le l$) またはアクティブ (値$> l$）。 連続したアクティブ ブロックがいくつ存在するかを維持します。 

1. 配列を初期化する`active`どこ`active[i] = 1`もし$a_i > l$、それ以外の場合は 0。 

これはセグメントの初期構造を表します。 
2. 配列を 1 回走査し、新しいアクティブ セグメントを開始するインデックスの数を数えます。 

位置がアクティブで、それが最初のインデックスであるか、前のインデックスが非アクティブである場合、その位置はセグメントを開始します。 

これにより、セグメントの初期数が得られます。 
3. 変数を維持する`segments`現在のアクティブなブロック数を保存します。 
4. 掲載位置を増やす更新クエリごとに$p$, まず、このポジションがすでにアクティブかどうかを確認します。 そうであれば、構造的には何も変わりません。 
5. そのポジションが初めてアクティブになった場合は、そのポジションをアクティブとしてマークし、それが接続にどのような影響を与えるかを決定します。 

両方の隣接ブロックが非アクティブな場合、この位置は新しい孤立したブロックを作成し、増加します。`segments`1つずつ。 

ちょうど 1 つの近隣がアクティブな場合、その近隣はそのブロックに接続され、カウントは変更されません。 

両方の隣接ブロックがアクティブな場合、2 つの既存のブロックが 1 つにマージされ、`segments`1つずつ。 
6. タイプ 0 のクエリごとに、次の現在の値を出力します。`segments`。 

重要な不変条件は次のとおりです`segments`インデックスのセット内の連結成分の数と常に等しくなります$i$そのような$a_i > l$。 アクティブ化はローカル隣接関係のみに影響するため、各更新ではこの不変条件が維持されます。 境界点がアクティブ化されない限り、非アクティブな領域が分割または結合されることはなく、その効果は 2 つの隣接領域をチェックすることによって完全にキャプチャされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, l = map(int, input().split())
    a = list(map(int, input().split()))

    active = [0] * n
    segments = 0

    for i in range(n):
        if a[i] > l:
            active[i] = 1
            if i == 0 or active[i - 1] == 0:
                segments += 1

    for _ in range(m):
        tmp = input().split()
        t = int(tmp[0])

        if t == 0:
            print(segments)
        else:
            p = int(tmp[1]) - 1
            d = int(tmp[2])

            was = active[p]
            a[p] += d

            if was == 0 and a[p] > l:
                active[p] = 1

                left = active[p - 1] if p > 0 else 0
                right = active[p + 1] if p < n - 1 else 0

                if left and right:
                    segments -= 1
                elif not left and not right:
                    segments += 1
                # else: merges with one side, no change

solve()
```この解決策は、初期配列をバイナリ アクティベーション配列に変換することから始まります。 次に、位置がアクティブであり、前のセグメントがアクティブではないときに新しいセグメントが正確に開始されるという事実を利用して、単一パス内のアクティブなセグメントの数を計算します。 

各更新では、最大 1 つの位置が非アクティブからアクティブに変更されます。 コードは、セグメント構造を更新する前に、この遷移を注意深くチェックします。 1 次元ライン内の接続コンポーネントの数を変更できるのはローカル隣接のみであるため、近隣検査で十分です。 

## 実用的な例

 次のサンプル入力を考えてみましょう。 

初期状態は$[1, 2, 3, 4]$と$l = 3$。 インデックス 4 のみがアクティブであるため、セグメントが 1 つあります。 

| ステップ | 配列 | アクティブなパターン | セグメント |
 | --- | --- | --- | --- |
 | 開始 | 1 2 3 4 | 0 0 0 1 | 1 |
 | + (2, +3) | 1 5 3 4 | 0 1 0 1 | 2 |
 | クエリ | - | - | 2 |
 | + (1, +3) | 4 5 3 4 | 1 1 0 1 | 2 |
 | クエリ | - | - | 2 |
 | + (3, +1) | 4 5 4 4 | 1 1 1 1 | 1 |
 | クエリ | - | - | 1 |

 最初の更新では、インデックス 2 に新しい分離アクティブ ポジションが作成され、2 つのセグメントが生成されます。 2 番目の更新では、左側が既存のブロックにマージされますが、セグメントの数は変更されません。 最後の更新では、すべてのアクティブな領域間のギャップが埋められ、すべてが 1 つの連続したブロックにマージされます。 

このトレースは、境界のアクティブ化のみが重要であることを示しています。 すでに活性化している領域内の内部成長は構造に影響を与えません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 |$O(n + m)$| 各インデックスは最大 1 回アクティブになり、各クエリは一定時間で処理されます。 
| スペース |$O(n)$| 各位置のアクティベーション状態を保存します |
