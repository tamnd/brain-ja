 ## 問題の理解

 直線上に配置された値の配列と、その直線上の候補区間のコレクションが与えられます。 これらの間隔から正確に選択する必要があります$m$彼らのうち。 選択されると、これらの間隔は配列の一部のインデックスをカバーし、少なくとも 1 つの選択された間隔にあるすべての配列値を取得して、マルチセットを形成します。 

このマルチセットから、適切な位置に表示される要素を確認します。$k$カバーされた値を並べ替えた場合。 タスクは、$m$このように間隔をあけます$k$- 番目の最小のカバー値は可能な限り小さいか、少なくとも達成されることを報告します$k$カバーされた要素は不可能です。 

主な困難は、区間の選択が組み合わせによるものであるのに対し、目的はカバーされたセット内の値の相対的な順序のみに依存し、値の合計や構造には依存しないことです。 選択は、カバレッジを通じて配列値と相互作用します。位置は、少なくとも 1 つの選択されたセグメントによってカバーされている場合にのみ、答えに寄与します。 

制約は十分小さいので、$n, s, m \le 1500$。 これは、セグメントに対する 2 次または 3 次動的計画法は許容されるが、指数サブセット列挙は許容されないことを直ちに示唆しています。 セグメントのすべてのサブセットを試すソリューションには、大まかに次のものが必要になります。$\binom{1500}{750}$最悪のシナリオの場合もありますが、これは完全に不可能です。 サイズのすべてのサブセットを反復処理する場合でも$m$すでに天文学的な規模になっています。 

より微妙な制約は、セグメントの数と配列の長さの両方が同様であるということです。 これは多くの場合、答えに対する二分探索と実行可能性チェックを組み合わせた解決策を示します。$O(n^2)$または$O(nm)$。 

単純な間違いは、重複するセグメントの選択を独立して処理できると考えることです。 たとえば、1 つのセグメントがカバーする場合、$[1,5]$そしてもう一つのカバー$[3,7]$それらを個別に扱い、それらの寄与を合計すると、位置 3 ～ 5 が 2 倍にカウントされます。正しい解決策では、カバレッジがインデックスごとに 1 回だけカウントされるようにする必要があります。 

次の場合、別の微妙な問題が発生します。$k$大きいです。 すべてのセグメントを結合しても少なくともカバーできない場合は、$k$インデックスの場合、値がどれほど小さいかに関係なく、答えはすぐに不可能になります。 不注意な実装では、実行不可能性を検出する代わりにバイナリ検索を試行し、間違った値を返す可能性があります。 

## アプローチ

 直接的なアプローチは、あらゆる選択方法を試すことです。$m$セグメントを作成し、カバーされたインデックスの和集合を計算し、その値を抽出し、並べ替えて、$k$- 番目に小さい。 これは概念的には単純で正しいですが、セグメントの組み合わせの数が多いため、使用できなくなります。 1 つの選択に対するカバレッジの計算にもコストがかかります$O(n + s)$したがって、合計は実現可能な限界を超えて爆発的に増加します。 

重要な観察は、答えは少なくともカバーできるかどうかによってのみ決まるということです。$k$値がしきい値を下回る位置。 これは単調な構造を示唆しています。$k$最大で - 番目に小さい値$x$であれば、さらに大きなサイズでもそれを達成できます。$x$。 This monotonicity enables binary search over the value of the answer.

現在のタスクは、間隔を指定した最大カバレッジの問題であり、正確に選択するように制約されています。$m$間隔。 なぜなら$s \le 1500$、セグメントにわたる動的プログラミングで十分です。 

セグメントを正しいエンドポイントで並べ替えます。 させて$prev[i]$セグメントと重ならない最後のセグメントを示します$i$。 各セグメントを取得するかスキップするかを決定する DP を定義し、選択したセグメントがインデックス範囲内で重複しないようにします。 この制限は、オーバーラップによってカバレッジが増加することはなく、カバーされるインデックスの最適性を失うことなく、オーバーラップしないコントリビューションに再配置できるため、安全です。

 ## アルゴリズムのチュートリアル

 ソリューションは 2 つの層で構築されます。答えに対する二分探索と、固定しきい値の実現可能性チェックです。 

1. 閾値を決めて概念的に配列値を並べ替える$x$、次に、次の場合に各位置を良好としてマークします。$a_i \le x$。 あらゆるセグメントを一定時間で評価できるように、これらの適切なマーカーのプレフィックス合計を事前計算します。 
2. セグメントを正しいエンドポイントで並べ替えます。 各セグメントごとに$i$、計算する$prev[i]$、直前に終了する最新のセグメント$l_i$。 これにより、DP を使用してソリューションを構築するときに、選択したセグメントの重複を確実に回避できます。 
3. DP 状態を定義します。$dp[i][j]$最初のパラメータを使用してカバーできる良好なポジションの最大数です。$i$セグメントを正確に選択しながら$j$それらのうち、非重複制限の下にあります。 
4. 2 つの方法で移行: セグメントをスキップするか$i$、継承する$dp[i-1][j]$、またはセグメントを取得します$i$この場合、以前の互換性のある状態と組み合わせます。$dp[prev[i]][j-1]$セグメント内の良好なポジションの数を追加します$i$。 
5. セグメント内の値は、バイナリの良好な配列に対するプレフィックスの合計を使用して計算されるため、任意の間隔に良好なインデックスがいくつあるかをすぐに評価できます。 
6. 固定しきい値の DP を計算した後、次のことを確認します。$dp[s][m] \ge k$。 「はい」の場合、そのしきい値は実現可能です。 
7. この実行可能性テストに合格する最小のしきい値を二分探索します。 

正確さは、DP が常に重複しないセグメントのセットを構築するため、各インデックスが最大 1 回カウントされるという事実に依存します。 重複するセグメントは結合を超えてカバレッジを増やすことができないため、重複しない選択に制限しても、達成可能な最適なカバレッジは減少しません。 

二分探索が有効なのは、しきい値を増やすと適切な位置のセットが増えるだけで、減少することはないため、実現可能性は単調です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, s, m, k, a, segs):
    # sort segments by right endpoint
    segs = sorted([(l-1, r-1) for l, r in segs], key=lambda x: x[1])

    # compute prev array (last non-overlapping segment)
    ends = [r for l, r in segs]
    prev = [0] * s
    for i in range(s):
        l, r = segs[i]
        j = i - 1
        while j >= 0 and segs[j][1] >= l:
            j -= 1
        prev[i] = j

    def check(x):
        good = [1 if v <= x else 0 for v in a]
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + good[i]

        def seg_good(l, r):
            return pref[r + 1] - pref[l]

        dp = [[-10**9] * (m + 1) for _ in range(s + 1)]
        for i in range(s + 1):
            dp[i][0] = 0

        for i in range(1, s + 1):
            l, r = segs[i - 1]
            gain = seg_good(l, r)
            p = prev[i - 1] + 1

            for j in range(m + 1):
                dp[i][j] = max(dp[i][j], dp[i - 1][j])
                if j > 0 and p >= 0:
                    dp[i][j] = max(dp[i][j], dp[p][j - 1] + gain)
                elif j > 0 and p < 0:
                    dp[i][j] = max(dp[i][j], gain)

        return dp[s][m] >= k

    lo, hi = 1, max(a)
    ans = -1

    if not check(hi):
        return -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if check(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    return ans

def main():
    n, s, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    segs = [tuple(map(int, input().split())) for _ in range(s)]
    print(solve_case(n, s, m, k, a, segs))

if __name__ == "__main__":
    main()
```DP セクションでは、適切なエンドポイントでソートされたセグメントに対して段階的にソリューションを構築します。 トランジションは、次の位置にジャンプすることで重複を慎重に避けます。`prev[i]`、以前に選択したセグメントが現在のセグメントと交差しないようにします。 プレフィックス合計配列を使用すると、各セグメントの寄与を一定時間で計算できます。 

二分探索では、この実現可能性チェックがラップされ、最小の有効なしきい値が見つかるまで値の候補範囲が縮小されます。

 ## 特殊なケース

 すべてのセグメントの和集合がまだ一致しない場合、失敗ケースが発生します。$k$特定のしきい値に適した要素をカバーしました。 その状況では、DP は正しく次の値よりも小さい値を返します。$k$となり、二分探索でしきい値が拒否されます。 

多くのセグメントが重なり合う場合、別の微妙なケースが発生します。 素朴な貪欲な選択では、カバレッジが追加されると考えて重複するセグメントを繰り返し選択することになりますが、DP は重複しないチェーンに構造を適用することで二重カウントを防ぎます。
