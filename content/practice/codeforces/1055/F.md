 ## 解決策
 ## 問題の理解

 ツリーは、すべての頂点に値、つまり任意のルート (頂点 1 など) からその頂点までのパス上のエッジの重みの XOR を割り当てることができるシステムを提供します。 これらの値が固定されると、任意の 2 つの頂点間の XOR は非常に単純な式になります。これは、割り当てられた値の単なる XOR です。 

したがって、パスについて考える代わりに、問題は次のようになります。配列が与えられるということです。`a[1..n]`、すべての順序ペアを考慮する必要があります`(i, j)`そして計算する`a[i] XOR a[j]`。 結果として得られたものの中に、`n^2`のゼロを含む値`i = j`、k 番目に小さいものを見つける必要があります。 

制約により、解は二次概念から遠く離れたものになります。 と`n`最大 10^6 の場合、すべてのペアを書き込むことさえ不可能です。 単一の固定の値を計算する場合でも`i`すべてに対して`j`すでに 10^6 回の操作が必要であり、これをすべての操作に対して実行すると、`i`は 10^12 ですが、これはまったく実行不可能です。 どのソリューションでも、ペアの列挙を完全に回避し、代わりにセットに対して XOR がどのように動作するかの構造を利用する必要があります。 

微妙なエッジケースは、順序付けされたペアによって引き起こされる大量の重複です。 たとえば、すべての値が等しい場合、すべての XOR は 0 になるため、k に関係なく、答えは常に 0 になります。 もう 1 つのコーナーは、値が小さくてクラスター化されている場合で、多くのペアが同一の XOR 結果を繰り返します。 単純な並べ替えベースのペア生成では、完了に達するずっと前にオーバーカウントまたはタイムアウトになってしまいます。 

## アプローチ

 ブルートフォースのアイデアは単純です。ルートからノードへのすべての XOR 値を計算し、すべてのペアごとの XOR 結果を構築して並べ替えます。 パス XOR 構造は頂点値 XOR に折りたたまれるため、これは正しいです。 ただし、生成されるためすぐに失敗します。`n^2`値はすでに制限を超えています`n = 10^6`。 

より構造的な観察は、任意のペアごとの値を扱っているのではなく、固定された整数セットに対する XOR を扱っているということです。 これは、XOR 比較はビットごとに分解できるため、ビットに対してバイナリ トライを使用することを示唆しています。 重要な変化は、個々のペアについて考えるのをやめ、代わりに、指定されたプレフィックスで結果を生成するペアの数を考えることです。 

バイナリ トライは、すべての値をビット単位の形式で保存します。 ペアの数を効率的に数えることができたら`(i, j)`ある値以下の XOR を生成すると、答えを二分探索できます。 しかし、そのアプローチでもビットのせいで複雑さが約 60 倍になり、10^6 要素には遅すぎます。 

決定的な改善点は、二分探索を完全に回避し、代わりにトライ自体を使用して少しずつ答えを構築することです。 各ビット位置で、結果の XOR のそのビットに 0 が含まれるか 1 が含まれるかに従って、すべてのペアを分割します。 トライのサブツリー サイズを使用して各カテゴリに該当するペアの数を計算できるため、k 番目に小さいものが「0 ビット」グループにあるか「1 ビット」グループにあるかを直接決定し、それに応じて降順することができます。 

これにより、問題は 2 つのトライの積をナビゲートすることに変換されます。各状態はトライ ノードのペアを表し、既知の数の順序付きペアに寄与します。

 | バイナリトライ + 二分探索 | O(n log C log C) | O(n log C) | 遅すぎる |
 | トライペア DFS (ビットごとの選択) | O(n log C) | O(n log C) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、各ノードをそのルート XOR 値に変換します。 これはルートからの単一の DFS で行われ、伝播します。`xor_to_node[v] = xor_to_parent + edge_weight`。 

次に、これらの値に対してバイナリ トライを構築します。 各トライ ノードは、通過する数値の数と、ビット 0 とビット 1 を表す子へのポインタを格納します。 

ここで、答えは最上位ビットからビット 0 まで構築されると解釈します。 

1. すべてを含むトライを構築します。`a[i]`、サブツリーのサイズをすべてのノードに保存します。 サイズは、そのサブツリー内にある値の数を表します。 
2. トライノードのペアに対する再帰的プロセスを定義します`(u, v)`。 このペアはすべての順序付きペアを表します`(x, y)`どこ`x`サブツリーにあります`u`そして`y`サブツリーにあります`v`。 
3. 指定されたビット位置で、次の寄与を分割します。`(u, v)`2つのグループに分けます。 選択された両方のビットが等しい場合、XOR ビットは 0 になります。つまり、`(u0, v0)`または`(u1, v1)`。 それらが異なる場合、XOR ビットは 1 になります。つまり、`(u0, v1)`または`(u1, v0)`。 
4. We compute how many ordered pairs fall into the XOR-bit-0 group using subtree sizes:

 カウントは`size(u0)*size(v0) + size(u1)*size(v1)`。 
5. もし`k`がこのカウント以下である場合、答えの現在のビットは 0 であり、ゼログループのペアのみに再帰されます。 
6. それ以外の場合は、このカウントを次から減算します。`k`、現在のビットを 1 に設定し、クロスペアに再帰します。`(u0, v1)`そして`(u1, v0)`。 
7. このプロセスをビット 60 からビット 0 まで継続し、次の不変条件を維持します。`(u, v)`は常に残りの候補ペアを正確に表します。 

### なぜ効果があるのか

 トライは、すべてのビット位置で、接頭辞に基づいてすべての数値を互いに素なグループに分割します。 ペアをカウントするステップでは、考えられる各 XOR プレフィックス拡張を生成するペアの数を正確に計算します。 すべてのペアが各ビットで 1 つの結果に寄与するため、左または右の決定により正確さが保たれます。 このプロセスは事実上、ビットの重要度によって引き起こされるすべての XOR 値に対する辞書編集的な選択であり、明示的に値を列挙することなく、k 番目に小さい値が確実に選択されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class Node:
    __slots__ = ("ch", "cnt")
    def __init__(self):
        self.ch = [-1, -1]
        self.cnt = 0

def add(root, x, nodes):
    v = root
    nodes[v].cnt += 1
    for b in range(61, -1, -1):
        bit = (x >> b) & 1
        if nodes[v].ch[bit] == -1:
            nodes[v].ch[bit] = len(nodes)
            nodes.append(Node())
        v = nodes[v].ch[bit]
        nodes[v].cnt += 1

def solve_pair(u, v, bit, k, nodes):
    if bit < 0:
        return 0

    u0 = nodes[u].ch[0]
    u1 = nodes[u].ch[1]
    v0 = nodes[v].ch[0]
    v1 = nodes[v].ch[1]

    def get_size(x):
        return 0 if x == -1 else nodes[x].cnt

    # count pairs with XOR bit = 0
    zero = 0
    if u0 != -1 and v0 != -1:
        zero += nodes[u0].cnt * nodes[v0].cnt
    if u1 != -1 and v1 != -1:
        zero += nodes[u1].cnt * nodes[v1].cnt

    if k <= zero:
        res = solve_pair(u0 if u0 != -1 else u, v0 if v0 != -1 else v, bit - 1, k, nodes) if (u0 != -1 and v0 != -1) else \
              solve_pair(u1 if u1 != -1 else u, v1 if v1 != -1 else v, bit - 1, k, nodes)
        return res

    k -= zero

    # XOR bit = 1
    one = 0
    if u0 != -1 and v1 != -1:
        one += nodes[u0].cnt * nodes[v1].cnt
    if u1 != -1 and v0 != -1:
        one += nodes[u1].cnt * nodes[v0].cnt

    # we are guaranteed k <= one here
    if u0 != -1 and v1 != -1:
        if k <= nodes[u0].cnt * nodes[v1].cnt:
            return (1 << bit) | solve_pair(u0, v1, bit - 1, k, nodes)
        k -= nodes[u0].cnt * nodes[v1].cnt

    return (1 << bit) | solve_pair(u1, v0, bit - 1, k, nodes)

n, k = map(int, input().split())
g = [[] for _ in range(n + 1)]

xorv = [0] * (n + 1)

for i in range(2, n + 1):
    p, w = map(int, input().split())
    g[p].append((i, w))

stack = [1]
order = [1]

while stack:
    v = stack.pop()
    for to, w in g[v]:
        xorv[to] = xorv[v] ^ w
        stack.append(to)

nodes = [Node()]
for i in range(1, n + 1):
    add(0, xorv[i], nodes)

print(solve_pair(0, 0, 61, k, nodes))
```この解決策は、ルートからのトラバーサルを使用してツリーをルート XOR 値に変換することから始まります。 次に、各ノードが通過する値の数を集計するバイナリ トライを構築します。これは、各 XOR カテゴリに含まれるペアの数をカウントするために重要です。 

再帰関数`solve_pair`2 つのトライ ノードを同時にナビゲートし、各ビットで、k 番目に小さい XOR がビット 0 またはビット 1 を生成するグループにあるかどうかを決定します。各決定では、明示的な列挙を避けるためにサブツリー カウントが使用されます。 

## 実用的な例

 概念的な小さな例を考えてみましょう: 値`[1, 2]`。 

トライルートには 2 つの数値があります。 最上位の異なるビットで、ペアは XOR 0 ペアに分割されます`(1,1)`そして`(2,2)`と XOR 3 ペア`(1,2)`そして`(2,1)`。 アルゴリズムは最初に 2 つのゼロの結果を数え、次に正しい順序で 1 の結果に進みます。`[0, 0, 3, 3]`。 

ここで考えてみましょう`[0, 1, 3]`。 トライは値を最上位ビットごとにグループ化し、各レベルのペア数はそのビットを保持または反転する組み合わせの数を反映します。 再帰ではビットが上位から下位まで貪欲に選択され、XOR 順序付けにおける辞書編集上の正確さが保証されます。

 ## 特殊なケース

 すべてのエッジの重みが 0 であるツリーの場合、すべてのノードの XOR 値は 0 になります。 トライには同一の値のみが含まれるため、すべてのペアの寄与はゼロになります。 再帰では、すべてのビットでゼログループが優勢であることが常にわかり、答えは k に関係なくゼロのままで、予想される動作と一致します。
