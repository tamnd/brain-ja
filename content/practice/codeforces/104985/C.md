 ## 解決策
 ## 問題の理解

 各セルがその場所で安全に動作するために必要な高度として解釈できる地形値を持つグリッドが与えられます。 ヘリコプターはあるセルから出発し、グリッドを横切って移動し、セルを 4 方向に変更する必要があります。 重要な問題は、移動が自由ではないことです。ヘリコプターは一定の飛行高度を維持する必要があり、高度を変更すると燃料が消費されます。一方、水平方向の移動は、現在の高度が現在のセルと目的地のセルの両方にとって十分であるかどうかにも依存します。 

タスクは、セルの高さによって課せられる制約と、上昇、下降、飛行のコスト モデルを考慮して、このグリッド上で開始構成からターゲット構成に移動するために必要な最小燃料を計算することです。 

グリッド サイズが十分に大きいため、各位置を個別に処理するソリューションでは不十分です。 各セルと高さを状態として扱う場合、状態空間はグリッド サイズと可能な高さの積にほぼ比例します。 これは、構造的な単純化を見つけない限り、すべての状態にわたる単純な最短パスまたは動的プログラミングが遅すぎることを直ちに示唆しています。 

直接解釈すると、各ノードが位置と高度のペアであるグラフが得られます。 適度な範囲であっても、これは O(n m A) のような値に爆発し、状態間の遷移によって A の別の要素が導入される可能性があります。これにより、A が非常に小さいか遷移が高度に最適化されていない限り、単純な最短経路法は実行不可能になります。 

高さが非常に異なる 2 つの隣接するセル間を移動する場合、微妙なエッジ ケースが発生します。 単純なアプローチでは、より高い高度に到達するためのコストの全額を常に移動前に別途支払うと仮定するかもしれませんが、実際には、最適な動作には、多くの場合、移動前ではなく移動中に高度を調整することが含まれます。 たとえば、隣接する 2 つのセルが高さ 1 と 100 を必要とする場合、移動前に高度を完全に上げることは、調整を行う場合と比べて無駄です。 

もう 1 つの重要な失敗例は、パスが行または列を再訪問するときに発生します。 一部の部分 DP アプローチは単調な動きを前提としていますが、横方向の動きが許可されている場合、最適なパスによって一時的にコストが増加し、将来の上昇コストが削減される可能性があります。 

## アプローチ

 この強引なアイデアは、考えられるあらゆるヘリコプターの構成をモデル化します。つまり、各状態は位置と現在の高度の 3 倍になります。 各状態から、高度を上下に変更すること、および現在の高度が両方のエンドポイントにとって十分に高い場合に隣接するセルに移動することの 3 種類の遷移をシミュレートします。 これにより、すべての制約が明示的にエンコードされるため、問題が正しくモデル化されます。 

ただし、このグラフには O(n m A) 個の状態があり、各状態は O(A + 4) 個の他の状態に遷移できます。 0-1 BFS またはダイクストラ バリアントを使用した場合でも、遷移の総数は O(n m A^2) になります。これは、A が極端に小さい場合を除き、一般的な制約としては大きすぎます。 

重要な観察は、セル間の移動は任意の中間高度からは決して恩恵を受けないということです。 セル u から v に移動しており、必要な安全高度が max(au, av) である場合、これを超える高度はコストが増加するだけで、実現可能性は向上しません。 より高度な飛行セグメントは、総コストを増加させることなく「降下、移動、上昇」に分解できます。 これは、最適なパスでは各移動に必要な最低高度のみを考慮する必要があることを意味します。 

高度が状態ごとに自由に変動するのではなく、エッジに関連付けられると、問題は変換されたグラフ上の最短経路の問題になります。 私たちはもはや任意の高さを継続的に追跡しません。 代わりに、エッジによって引き起こされる必要な高さの変化のみを考慮します。 

この削減により、階層化された状態グラフから、連続的な高度状態ではなくセル間の遷移にコストが関連付けられる、より小さなグラフに移行することができます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | (セル、高さ) にわたる完全な状態の最短パス | O(n m A^2) | O(nmA) | 遅すぎる |
 | 制約された高度遷移にわたって最適化されたグラフ | O(n m log(n m)) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各グリッド セルをグラフ内のノードとしてモデル化しますが、任意の高度状態を直接関連付けないでください。 代わりに、動きを、各エッジがその端点によって決定される最小必要飛行高さを持つエッジ プロセスとして解釈します。 これにより、連続的な高度の決定が個別のエッジ コストに削減されます。 
2. 隣接するセルの各ペアについて、地形値の最大値として最小安全飛行高度を計算します。 この値は、ヘリコプターが追加の制約なしでそのエッジを安全に通過できる最低高度を表します。 
3. 各移動は、現在のセル内の高度を調整し、必要なエッジ高度で飛行を実行するという 2 つの概念的な部分で構成されると解釈します。 最適性を損なうことなく、上昇または下降を同じコスト計算に吸収できるため、移動のコストは正確にそのエッジの必要な高度になります。 
4. 頂点が位置 (または、方向制約に必要な場合は、より豊富な状態の変化) を表し、エッジが、前に計算した必要な飛行高度に等しい重みを持つ有効な動きを表すグラフを構築します。 これにより、問題は最短経路問題に変換されます。 
5. ダイクストラのアルゴリズムを開始状態から実行します。 各緩和ステップは、移動する次のセルの選択と、対応する最小安全高度コストの支払いに対応します。 
6. 各ノードの距離を維持し、優先キューを使用して距離を更新します。 エッジの重みは負ではないため、ダイクストラは最適解を正しく生成します。 

### なぜ効果があるのか

 正確さは、高度の動作をエッジの重みに圧縮することに依存します。 任意の高度変更を伴う実行可能な軌道は、総コストを増加させることなく、各移動がその移動に必要な最小高度で正確に実行される軌道に変換できます。 これにより、冗長な高高度セグメントが排除され、位置だけでの検索スペースが十分になることが保証されます。 残りのすべての決定は非負の重みを持つローカル エッジの選択であるため、ダイクストラの貪欲な選択により最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    INF = 10**18
    dist = [[INF] * m for _ in range(n)]
    dist[0][0] = a[0][0]

    pq = [(a[0][0], 0, 0)]

    dirs = [(1,0), (-1,0), (0,1), (0,-1)]

    while pq:
        d, x, y = heapq.heappop(pq)
        if d != dist[x][y]:
            continue

        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m:
                cost = max(a[x][y], a[nx][ny])
                nd = d + cost
                if nd < dist[nx][ny]:
                    dist[nx][ny] = nd
                    heapq.heappush(pq, (nd, nx, ny))

    print(dist[n-1][m-1])

if __name__ == "__main__":
    solve()
```この実装では、グリッド セル上でダイクストラを使用します。各エッジの重みは、2 つの隣接するセル間を移動するために必要な最小限の安全高度です。 優先キューにより、現在最も安価で到達可能なセルが常に拡張されます。 

重要な点は、エッジの重みの定義です。これは、目的のセルの高さだけではなく、両方の端点の最大値でもあります。これは、飛行中に両方の端点を安全にカバーする必要があるためです。 

また、明示的な高度追跡も回避します。これは、状態空間をグリッド サイズで線形に保つための重要な削減です。

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 単一セル グリッドは、不必要な遷移を行わずに、アルゴリズムが開始地点をすでに目的地として正しく扱うかどうかをテストします。 距離はセル値から直接初期化されるため、緩和は発生しません。 

低い値で囲まれた非常に大きなピークを持つグリッドは、アルゴリズムがピーク コストの複数回の支払いを回避するパスを正しく選択するかどうかをテストします。 エッジの重みはエンドポイントの最大値を使用するため、ピークはそれを通過するたびに 1 回だけ支払われます。 

厳密に増加するグリッドは、アルゴリズムが単調な条件下で一貫して動作するかどうかをテストします。 この場合、最短パスは唯一の実現可能な方向に従うように強制され、ダイクストラは代替緩和なしで予測可能な順序でノードを処理します。
