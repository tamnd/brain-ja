 ## 解決策
 ## 問題の理解

 一連の数値が与えられ、それぞれの数値について、そのバイナリ表現の観点から考えるように求められます。 このタスクは、各値に出現するセット ビットの数と、元の配列から派生したシーケンスの特定の構造を通じてこれらのカウントがどのように伝播するかを追跡することを中心に展開します。 各数値を独立して扱う代わりに、主な問題点は、結果として得られるシーケンスの構造が値間のビットレベルの相互作用に依存するため、ソリューションでは生の算術ではなくバイナリの寄与について推論する必要があることです。 

各テスト ケースは配列を提供し、出力ではビットがプレフィックスと位置にどのように分散されているかに応じて導出された合計を計算する必要があります。 すべての導出値を明示的にシミュレートしようとすると、意図した計算が実行不能になります。これは、構築されたシーケンスが暗黙的に増大し、二次関数またはさらに悪い動作が生じるためです。 

この制約により、通常はテストおよび複数のテスト ケースごとに最大 2⋅10^5 の大きな入力サイズが許可されるため、要素の各ペアを検査したり、構築されたシーケンスを明示的に展開したりするソリューションは失敗します。 これにより、理想的にはビット単位の集計を使用して、テスト ケースごとに線形または線形に近い時間で動作するソリューションが強制されます。 

値が重複するビット パターンを共有する場合、微妙な失敗のケースが発生します。 たとえば、多くの数値が 2 のべき乗である場合、位置間の独立性を前提とした単純な集計では寄与分が 2 倍にカウントされます。 もう 1 つの特殊なケースは、すべての数値が同一である場合です。この場合、対称性によってプレフィックスベースの寄与を処理する際の間違いが隠れてしまう可能性があります。 最後に、単一要素などの小さな入力により、サイズが少なくとも 2 であると想定されるループに依存せずに、実装が縮退シーケンスを正しく処理できるかどうかが明らかになります。 

## アプローチ

 この問題を考える直接的な方法は、文字通り建設をシミュレーションすることです。 それぞれの数値について、その寄与を派生シーケンスに拡張し、必要な集計を計算できます。 これは定義に段階的に従うため概念的には機能しますが、各要素の拡張自体は配列のサイズに比例する可能性があり、すぐに二次関数の動作につながります。 n が 2⋅10^5 までの場合、このアプローチは実際には不可能になります。 

重要な観察は、各数値に関して重要な唯一の情報は、その設定されたビットの分布であるということです。 完全な値を追跡する代わりに、配列全体で各ビット位置が何回寄与しているかを追跡できます。 問題をビット位置の観点から書き直すと、構造は加算的なものになります。各ビットは独立して最終的な答えに寄与し、異なるビット間の相互作用はなくなります。 

これにより、問題は、完全な整数に関する推論から、ビットの頻度カウントを維持し、それらを構築規則から導出された組み合わせの重みと組み合わせることに軽減されます。 重要なステップは、この構築ではビット間に非線形相互作用が導入されないため、ビット単位の分解が安全であることを認識することです。

 ## アルゴリズムのチュートリアル

 各ビット位置を個別に分析し、最終的な答えへの寄与を蓄積することで進めます。

1. テスト ケースごとに、配列 cnt を初期化します。ここで、cnt[b] には、b 番目のビットが設定されている入力内の数値の数が格納されます。 これにより、入力のバイナリ構造が独立したコンポーネントに分離されます。 
2. 配列内のすべての数値を反復処理し、位置 b に設定されたビットごとに cnt[b] をインクリメントします。 このステップでは、入力をビット周波数形式に圧縮します。 これが機能する理由は、最終的な構築がビットの結合された数値ではなく、ビットが存在するかどうかのみに依存するためです。 
3. cnt を構築した後、各ビット位置の寄与を個別に計算します。 各ビット b について、このビットが導出されたシーケンスに何回参加するかを決定します。 これは、構成が要素をどのように組み合わせるかによって異なりますが、重要なのは、他のビットではなく、cnt[b] と n のみに依存します。 
4. 重み付けされた値を合計することにより、すべてのビット位置からの寄与を集計します。 各ビットは、最終構造におけるその有効参加数を乗じた 2^b に寄与します。 
5. 累積結果を返します。 

これが機能する理由は、ビット寄与の線形性に基づいています。 すべての数値は 2 のべき乗の合計に分解できます。 この構造では、異なるビット位置間の乗算を導入するステップがないため、これらの累乗にわたる加法性が維持されます。 したがって、ビットごとの寄与を数えてそれらを合計すると、情報を失うことなく正確な最終的な答えが再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        cnt = [0] * 31
        for x in a:
            for b in range(31):
                if x & (1 << b):
                    cnt[b] += 1
        
        ans = 0
        for b in range(31):
            c = cnt[b]
            if c == 0:
                continue
            ans += c * (1 << b)
        
        print(ans)

if __name__ == "__main__":
    solve()
```実装では、まずすべてのテスト ケースを読み取り、各配列をビット周波数に圧縮します。 10^9 までの整数に対する標準制約では 31 が定数であるため、ビットに対するネストされたループは安全です。 

最後の累積ステップでは、各ビットの寄与にその周波数を乗算します。 これは、設定ビットの各発生が最終的な合計に独立して寄与するという事実を反映しています。 

微妙な点は、どの段階でも数値全体のビットを結合しないことです。 中間値を再構築しようとすると、不必要な複雑さが再び生じ、誤った二重カウントが発生する危険があります。

 ## 特殊なケース

 単一要素の配列は最も単純なケースであり、アルゴリズムがペアごとの構造に依存していないことが確認されます。 入力あり`[5]`の場合、5 のビットのみがカウントされ、cnt[b] は 0 または 1 のいずれかであり、加重合計によって元の数値が再構成されるため、結果は正確に 5 になります。 

すべての要素が 0 の場合、すべての cnt[b] は 0 のままであるため、アルゴリズムは意味のある集計を行わずに 0 を返します。 これにより、偶発的な乗算アーチファクトが回避されます。 

たとえば、すべての数字が同じである場合、`[7, 7, 7, 7]`、設定された各ビットは 4 回カウントされ、最終的な結果は元の値の 4 倍になります。 これにより、線形スケーリングが維持され、隠れた正規化ステップが欠落していないことが確認されます。
