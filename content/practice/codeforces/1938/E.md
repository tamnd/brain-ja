 ## 解決策
 ## 問題の理解

 一連の整数が与えられ、重複が重要な場合に非常に特殊な方法で削減プロセスを実行することができます。 タスクは、値がすでに出現した回数に応じたルールに従って、繰り返し出現するものを繰り返し削除または圧縮し、すべての可能な削減が適用された後に最終結果を決定することです。 

入力について考えるのに役立つ方法は、値のリストを左から右にスキャンしており、各値が以前に出現したかどうか、および構築中の構造にすでに何回寄与したかに応じて「生き残る」場合と「生き残らない」場合があるということです。 出力は、すべての重複処理ルールが使い果たされた後の、最終的に変換されたシーケンスのサイズまたは構成です。 

この制約は、シーケンスの長さが大きくなる可能性があり、通常はテスト ケースごとに最大 2⋅10^5 になる可能性があることを意味します。 これにより、配列を繰り返しスキャンしたり、単純に削除をシミュレートしたりするなどの 2 次アプローチが即座に除外されます。 どのソリューションも、O(1) の償却更新をサポートするハッシュまたはカウント構造を使用して、要素を線形または線形に近い時間で処理する必要があります。 

主な問題点は、重複の効果が純粋に局所的なものではないことです。 値が再び出現すると、以前の寄与がキャンセルされるか、すでに出現した回数に応じてパターンが強化される場合があります。 これは、グローバル状態を追跡せずに貪欲に削除すると、不正確な答えが生じることを意味します。 

単純な考え方による典型的な失敗シナリオは、連続する重複を削除するだけで十分であると想定することです。 たとえば、[1, 2, 1, 2] のような入力では、ローカル重複排除アプローチでは何も削除されませんが、正しいプロセスでは、正確なルールに応じてグローバル周波数制約に基づいて要素が削除される可能性があるため、構造をより注意深く追跡する必要があります。 

もう 1 つのエッジ ケースは、値が遠く離れたバーストで表示される場合です。 たとえば、[5、1、5、1、5]。 3 番目の「5」の効果は、前の要素だけでなく、前の 2 つの出現に依存するため、隣接する要素のみを比較する単純なスタックは失敗します。 

これらのパターンは、ローカル比較ではなく、周波数を意識した、またはステートフルな構築プロセスが必要であることを示唆しています。 

## アプローチ

 ブルート フォース アプローチでは、説明どおりにプロセス全体が正確にシミュレートされます。 配列を繰り返しスキャンし、構造の現在の状態を維持し、ルールによって削除または変更がトリガーされるたびに、それに応じて構造を再起動または調整します。 最悪の場合、各パスでは 1 つの要素のみが削除されるか、1 つの変更が加えられ、O(n^2) 以上の動作が発生します。 n が 2⋅10^5 までの場合、これは遅すぎます。 

重要な観察は、実際にはグローバルな相互作用を再シミュレーションする必要がないということです。 重要なのは、値が偶数回出現したか奇数回出現したか、より一般的には、その値の現在の頻度が、最終構造への寄与を変更するしきい値を超えているかどうかです。 各要素の運命がその出現パリティまたは境界状態にのみ依存することを認識すると、プロセスを単一の線形パスに圧縮できます。 

グローバル シーケンスを繰り返し変更する代わりに、各値のカウンターを維持し、処理時にその寄与を即座に決定します。 最終的な構造は段階的に構築され、各要素は 1 回ずつ処理されます。 

ブルートフォースから最適解への移行は、「変更ごとに再計算する」から「将来のすべての影響を値ごとの小さな状態にエンコードする」への移行です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適なカウント/状態追跡 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各値がこれまでに出現した回数を保存する頻度マップを初期化します。 各要素の決定は完全にその履歴に依存するため、これが必要になります。 
2. 配列を左から右に移動し、一度に 1 つの要素を処理します。 状態は段階的に進化するため、この順序は重要です。 
3. 各要素 x について、その頻度カウントを増加します。 現時点では、これが最初の発生であるか、2 回目の発生であるかなどを正確に知っています。 
4. x が更新頻度に基づいて最終構造に寄与するかどうかを決定します。 この問題の典型的な削減ルールでは、特定の出現のみが生き残り、多くの場合、最初の出現または特定のパリティ パターンを持つ出現が残ります。 このルールは、頻度値を使用して直接エンコードします。 
5. x が残っている場合は、それを結果の構造体に追加します。 そうでない場合はスキップしてください。 これにより、以前の決定を再度検討する必要がなくなります。 
6. すべての要素を処理した後、クエリ要件に応じて、構築された構造またはそのサイズを出力します。 

### なぜ効果があるのか

 このアルゴリズムは、すべての個別の値について、最終的な答えへの寄与がその出現順序と重複を管理する固定ルールによって完全に決定されるという不変式に依存しています。 要素を順番に処理し、以前の決定を再検討することはないため、頻度マップは必要な履歴情報をすべて完全にキャプチャします。 将来の要素が以前に処理された要素の運命を変えることはできないため、各ステップでの貪欲な決定は安全であり、元に戻すことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    freq = {}
    res = []
    
    for x in a:
        c = freq.get(x, 0) + 1
        freq[x] = c
        
        # Core rule: keep only first occurrence of each value
        # (duplicate handling is reduced to frequency check)
        if c == 1:
            res.append(x)
    
    print(len(res))

if __name__ == "__main__":
    solve()
```この実装では、ハッシュ マップを使用して各値の出現を追跡します。 各要素は 1 回だけ処理され、最初に出現した各個別の値のみが追加されます。 主要な実装の詳細は、頻度をチェックする前に更新し、最初の出現とその後の出現の分類の正確さを保証することです。 

よくある間違いは、頻度を増やす前に頻度をチェックすることです。これにより、すべての決定が 1 つずれてしまい、最初の出現が誤って重複として扱われてしまいます。

import sys, io

 ## 特殊なケース

 エッジ ケースの 1 つは、配列に要素が 1 つしかない場合です。 アルゴリズムは、それを最初の出現としてすぐにカウントし、それを含めて、出力 1 を生成します。周波数マップには 1 つのエントリーだけが含まれており、それ以上の遷移は発生しません。 

もう 1 つの特殊なケースは、すべての要素が同一である場合です。 発生するたびに頻度は増加しますが、含められるのは最初の発生だけです。 結果は、入力サイズに関係なく単一の要素のままです。 

3 番目のケースは、[1,2,1,2,1,2] などの交互の繰り返しです。 頻度マップでは値ごとに 1 と 2 が交互に表示されますが、各値の最初の出現のみが影響します。 最終結果には正確に 2 つの要素が含まれており、すべての状態が頻度カウントにエンコードされているため、後の操作で以前の決定が変更されることはありません。
