 ## 解決策
 ## 問題の理解

 私たちには、生徒の一覧表と、一定の質問に対する生徒の回答が与えられます。 各生徒の応答は長さの文字列です$m$, ここで、各位置は、選択した回答を表す大文字、または学生がその質問をスキップしたことを意味するドットのいずれかです。 

少なくとも選択できれば、2 人の学生は互換性があるとみなされます$k$両方がそれらの質問に答え、選択されたすべての質問について、答えが完全に一致するような質問です。 言い換えれば、少なくとも以下の点を共有する学生のペアを探しています。$k$同じインデックスでの同一のスキップされていない回答。 

課題は、そのような学生のペアを見つけることです。 複数のペアが存在する場合は、2 番目のインデックスが最も小さいペアが優先されます。$b$、まだ同点がある場合は、最初のインデックスが最も大きいもの$a$。 

この制約により、すべての生徒のペアに対するすべての質問の単純なペアごとの比較が直接的な方法で排除されます。 まで$n = 5000$学生と$m = 3000$、すべてのペアのコストを直接比較します。$O(n^2 m)$、これは大きすぎます。 平$n^2$ペアだけでもすでに 2,500 万ペアあるため、ペアごとのリニア スキャンは受け入れられません。 

その隠された構造とは、$k \le 5$、非常に小さいです。 これが問題の核心です。大きな交差点について推論する必要はなく、少なくとも少数の一致する位置が存在するかどうかだけを考慮する必要があります。 これにより、完全な比較ではなく、小さなサブセットの組み合わせ列挙が可能になります。 

素朴だが重要なエッジケースは、ほとんどの答えがドットである場合に現れます。 たとえば、2 人の生徒が共通のドット以外の答えを 1 つだけ持っているとしますが、$k = 2$、たとえ視覚的に「似ている」としても、似ているとみなしてはいけません。 選択した各位置で厳密な均等性を強制せずに重複するインデックスをカウントするソリューションは、オーバーカウントになります。 

もう 1 つの微妙な落とし穴は、複数の生徒が多くの部分的な重複を共有しているにもかかわらず、単一のペアが到達できない場合に発生します。$k$。 インデックスごとに最初に一致する生徒を選択する貪欲なアプローチでは、すべてを検証しないと、ペアが早すぎて誤って報告される可能性があります。$k$一貫してポジションを維持します。 

## アプローチ

 ブルートフォースアプローチでは、生徒のすべてのペアを比較し、両方がドットではなく等しい一致する位置の数を計算します。 各ペアについて、すべてをスキャンします$m$質問と一致のカウント。 これは正しいですが、最悪の場合の複雑さは次のとおりです。$O(n^2 m)$、これはおおよそ次のことにつながります$5000^2 \cdot 3000 \approx 7.5 \times 10^{10}$実行可能な限界をはるかに超えた操作。 

重要な観察は次のとおりです$k$すべてのペアの一致する位置をすべてチェックする代わりに、視点を逆にすることができます。サイズのサブセットのみを考慮する場合、各生徒は限られた数の意味のある「特徴」のみを提供します。$k$。 

各生徒について、実際に何か答えたすべての質問を検討します。 2 人の学生間の有効な類似性は、次の選択によって判断されます。$k$両方に一致する文字があるインデックス。 したがって、学生を直接比較するのではなく、選択するすべての方法を列挙します。$k$各生徒のポジションに答え、それぞれを扱います$k$-タプルを署名として使用します。 

2 人の生徒が同じものを共有する場合$k$-タプル署名の場合、それらは似ています。 課題は、列挙を管理しやすくしながら、有効な組み合わせを過剰にカウントしたり見逃したりしないようにすることです。 なぜなら$k \le 5$、生徒あたりの組み合わせの数は次の制限を受けます。$\binom{m}{k}$, ただし、グローバルにすべてのポジションを列挙するわけではありません。 学生が文字を持っている位置のみを列挙し、ハッシュ化と組み合わせの増分構築を使用して慎重にプルーニングします。 

これを効率的に行うために、署名を段階的に構築します。 各生徒の解答位置をスキャンし、再帰的または反復的な組み合わせ生成を深度まで使用します。$k$、部分的な状態をハッシュ マップに保存します。 繰り返されるシグネチャを検出するとすぐに、必要な順序付け制約を尊重しながら、ペアを再構築して停止できます。$b$そして$a$。

 ## アルゴリズムのチュートリアル

 1. 各生徒について、ドット以外の回答があるインデックスのリストとそのインデックスの文字を収集します。 これにより、ドットは有効な交差に寄与できないため、無関係な位置が直ちに削減されます。 
2. 各生徒について、サイズのすべての組み合わせを生成します。$k$答えられた立場から。 各組み合わせは、ペアで構成される正規化された署名として表されます。$(index, character)$インデックス順に並べ替えます。 この順序付けは、生成順序に関係なく、同一のセットが同一の表現を生成するために必要です。 
3. 各署名を、それを生成した最初の学生インデックスにマッピングする辞書を維持します。 
4. 生徒の処理中に、生成されたすべての署名について、その署名が辞書にすでに存在するかどうかを確認します。 そうであれば、少なくとも 2 人の学生が共有していることがわかりました。$k$それらの位置では同じ答えが得られます。 直ちにペアを返し、反復順序の構築によって問題の順序制約の下での正確性を保証します。 
5. すべての生徒に署名が繰り返されない場合は、-1 を出力します。 

これが機能する主な理由は、有効な学生ペアが何らかのセットを共有する必要があることです。$k$同じ答えを持つ立場。 そのセットは、両方の生徒の組み合わせの 1 つとして生成されます。 したがって、重複した署名を初めて確認した時点で、類似性が正確に証明されたことになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from itertools import combinations

def solve():
    n, m, k = map(int, input().split())
    s = [input().strip() for _ in range(n)]

    # store first occurrence of each signature
    seen = {}

    for i in range(n):
        pos = [(j, s[i][j]) for j in range(m) if s[i][j] != '.']

        if len(pos) < k:
            continue

        for comb in combinations(pos, k):
            # normalize signature
            key = tuple(comb)
            if key in seen:
                print(seen[key] + 1, i + 1)
                return
            seen[key] = i

    print(-1)

if __name__ == "__main__":
    solve()
```このコードは、各生徒を意味のある回答位置に圧縮し、すべてのサイズを列挙するというアイデアを直接実装しています。$k$サブセット。 辞書を使用すると、繰り返されるシグネチャを確実に一定時間検出できます。 各署名の最初の出現のみを保存するため、順序付けの要件は自然に処理されます。 

実装の微妙な点は、ドットの位置を考慮する必要がないことです。 これらを含めると組み合わせの数が爆発的に増加し、無効な一致も生成されます。 

## 実用的な例

 3 人の生徒がいる小さな例を考えてみましょう。$k = 2$。 生成された署名のみを追跡します。 

| 学生 | 解答位置 | 生成された$k$-組み合わせ |

 | 1 | (0,A)、(1,B)、(2,C) | ((0,A),(1,B)), ((0,A),(2,C)), ((1,B),(2,C)) |
 | 2 | (1,B)、(2,C) | ((1,B),(2,C)) |

 生徒 1 を処理するとき、そのすべての署名が挿入されます。 生徒 2 を処理するとき、署名 ((1,B),(2,C)) はすでに存在するため、ペア (1,2) がすぐに検出されます。 

これは、この方法が、共有された有効なサブセットが出現した瞬間に類似性を正確に捕捉していることを裏付けています。 

次に、一致するペアがない場合を考えてみましょう。 

| 学生 | 解答位置 | 生成された$k$-組み合わせ |
