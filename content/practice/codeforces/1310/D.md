 ## 解決策
 ## 問題の理解

 順序付けられた異なる都市のすべてのペアに旅行コストがかかる、都市の完全な有向グラフが与えられます。 都市 1 から始めて、正確に実行する必要があります$k$移動し、再び都市 1 で終了します。各移動は、有向エッジを選択し、そのコストを支払うだけです。 都市を再訪問したり、エッジを再利用したりすることは許可されています。 

追加の制約は、組み合わせによるものではなく構造的なものです。考えられるすべての長さの中で、$k$1 で始まり 1 で終わる閉じたウォークでは、ウォークで使用されるエッジに限定される場合、奇数の長さのサイクルを形成するサブウォークの一部となる頂点は存在できないという意味で、「奇数サイクル」動作を含まないもののみを選択できます。 

この制約をより操作的に読み取る方法は、歩行がステップのパリティによって引き起こされる 2 部構造と一貫性を保たなければならないということです。 なぜなら$k$が偶数である場合、有効な構築はいずれも、頂点を再訪する際にパリティの一貫性を考慮する必要がある 2 部ウォークの交互のレイヤーのように動作することになります。 これはまさに、任意のパス列挙ではなく、パリティを意識した状態での動的プログラミングの定式化を可能にするものです。 

入力サイズはノード数では最大 80 と小さいですが、$k$は最大でも 10 です。これは、状態空間が多項式である DP を許容できるほど十分に小さいです。$n$そして直線的に$k$、しかし指数関数的なものは何でも$n$または指数関数的に$k$超えて$2^k$不要でしょう。 重要な制約は、グラフが密であるため、隣接リストは役に立たないということです。 私たちは直接マトリックス遷移に依存しています。 

単純な推論を破るエッジケースには、最も安価なパスが局所的に奇妙なサイクル構造を作成する状況が含まれます。 たとえば、最も安価なエッジが長さ 3 のサイクルを形成する三角形について考えてみましょう。貪欲なアプローチまたはステップごとの最短パスのアプローチでは、これらのエッジを繰り返し使用して安価に戻る可能性がありますが、これによりウォーク内に奇妙なサイクルが形成され、制約に違反します。 別の故障モードは、これを標準的な最短距離の歩行として扱うことです。$k$パリティ制約を無視すると、不一致のステップ パリティで頂点が一貫性なく再訪される可能性があります。 

したがって、正しいソリューションでは、頂点の再訪によって奇数サイクルの不整合が生じないように、実行されたステップ数と現在の構造のパリティ クラスの両方を追跡する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのシーケンスを列挙します。$k$都市 1 から開始して移動し、歩行をシミュレートし、奇数サイクル制限の下で有効かどうかを確認します。 各ステップは次のように分岐します。$n$可能性があるため、歩行の数は$n^k$。 と$n = 80$そして$k = 10$、これは天文学的に大きく、検証前であっても完全に実行不可能です。 

問題の構造は、明示的な列挙ではなく、ウォークに関する動的プログラミングを示唆しています。 以来$k$小さくて固定されているため、階層化ディメンションとして扱うことができます。 中心的な観察は、奇数サイクルに関する制約により、ウォーク内の偶数位置と奇数位置にわたる頂点の使用の一貫性が強制されるということです。 これは当然、状態が現在の頂点とステップ数だけでなく、訪問した頂点のパリティ一貫性のあるペアリング構造もエンコードする DP につながります。 

私たちは問題を長い散歩の構築として再定式化します$k$どこに位置しますか$i$そして$k-i$奇数サイクルを避けるように対称的に動作します。 この対称性は、ウォークが階層化された DP のペアの遷移として構築できることを意味し、ウォークの構築を中央で交わる 2 つのミラーリングされた半分に効果的に分割します。 

高いレベルでは、長さの部分的なウォークにわたって DP 状態を定義します。$t$、部分的に構築された対称パスの現在のエンドポイントを追跡します。 各拡張部は対称性を維持する方法で 2 つのエッジを追加し、形成されるサイクルが均等になるようにします。 

これにより、指数関数的な分岐が減少します。$n^k$の多項式因数に$n^3 k$、遷移はエンドポイントのペアと中間の会議頂点に依存するためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 |$O(n^k)$|$O(k)$| 遅すぎる |
 | エンドポイント上の対称 DP |$O(k \cdot n^3)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1.長さの歩行を解釈します$k$両端から中央に向かって対称的に構成されています。 以来$k$は偶数です、正確にあります$k/2$ペアの構築ステップ。 
2. DP 状態を定義します$dp[t][u][v]$深さの部分対称ウォークを構築するための最小コストとして$t$、片側が都市で終わるところ$u$そして反対側は市で終わります$v$。 これは、最終ウォークのプレフィックスとサフィックスを同時に構築することを表します。 
3. 初期化セット$dp[0][1][1] = 0$, because at step zero both ends are at the starting city.
 4. レイヤーごとに$t$、両端を同時に伸ばそうとします。 州から$(u, v)$、中間都市を選択します$x$そして$y$片側を延長する$u \to x$そしてもう一つは経由$v \to y$、貢献コスト$cost[u][x] + cost[y][v]$。 これにより、両端が 1 ステップずつ内側に移動するため、対称性が維持されます。 
5. 構築時に暗黙的に奇妙なサイクルが導入されないようにすることで、一貫性を確保します。 対称的なペアリングにより、すべての前方への移動が後方への移動によって反映されるため、形成される閉ループの長さが均等になります。 
6.演奏後$k/2$延長すると、両端が中央で交わります。 最終的な答えは、次の状態にある州の最小値です。$u = v = 1$、つまり両半分がスタートに戻ることを意味します。 

### なぜ効果があるのか

 DP は、2 つのミラーリングされたハーフパスとしてウォークを構築します。 結果として得られるウォーク内のサイクルは、前方セグメントとそのミラーリングされた後方セグメントで構成されている必要があり、これによりすべてのサイクルの長さが強制的に均等になります。 状態表現は、すべての頂点の出現が構築の中間点でペアになっているため、異なるパリティでの不一致の再訪を防ぎます。 すべての遷移はこのペアリング構造を保持するため、奇数のサイクルが形成されることはなく、すべての有効な対称ウォークが DP で表現可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    cost = [list(map(int, input().split())) for _ in range(n)]

    INF = 10**30
    half = k // 2

    dp = [[INF] * n for _ in range(n)]
    dp[0][0] = 0

    for _ in range(half):
        ndp = [[INF] * n for _ in range(n)]
        for u in range(n):
            for v in range(n):
                cur = dp[u][v]
                if cur == INF:
                    continue
                for x in range(n):
                    for y in range(n):
                        val = cur + cost[u][x] + cost[y][v]
                        if val < ndp[x][y]:
                            ndp[x][y] = val
        dp = ndp

    print(dp[0][0])

if __name__ == "__main__":
    solve()
```DP 配列には、エンドポイントのペアの最適コストが保存されます。 各遷移は同時に両方のエンドポイントを内側に進め、2 つの有向エッジのコストを支払います。 初期化は都市 1 から始まる両端に対応し、0 としてインデックス付けされます。$k/2$拡張の場合、両端は都市 1 に戻る必要があります。 

両方のエンドポイントが次の中間都市を独立して選択するため、移行における 4 つのネストされたループは不可欠です。 グラフは完全に有向で非対称であるため、これを減らすと正確さが失われます。 

## 実用的な例

 ### サンプル 1

 各ハーフステップ後の意味のある DP 状態のみを追跡します。 説明では都市のインデックスは 1 から始まりますが、DP では 0 から始まります。 

初期状態:$dp[1,1] = 0$| ステップ | (u, v) 状態 | 移行コスト |
 | --- | --- | --- |
 | 0 | (1,1) | 0 |
 | 1 | 拡張後の最良のペア | 1 |
 | 2 | 拡張後の最良のペア | 2 |

 4 回の拡張後 (k = 8、half = 4 であるため)、DP は 2 を返します。 

このトレースは、アルゴリズムが単一のパスを貪欲に選択しているのではなく、合計の対称コストを最小限に抑えるためにエンドポイントのペアを繰り返し再結合していることを示しています。

 ## 特殊なケース

 一般的なコーナーケースは、最も安価なエッジが非常に低コストで有向三角形を形成する場合ですが、これを使用するとウォーク内で 3 サイクルが強制されることになります。 DP は単一の不対トラバーサルを決して構築しないため、これを回避します。 すべての動きがミラーリングされ、奇数の長さの内部サイクルの形成が防止されます。 

もう 1 つの微妙なケースは、最適なウォークが繰り返し中間ノードを再訪問する場合です。 k ステップ内の最短パスの単純なアプローチでは、再訪問に不当なペナルティが課されたり、再訪問が一貫性なく扱われたりする可能性があります。 ペア状態 DP では、両方のエンドポイントが一貫している限り、自由に再訪でき、繰り返し構造に関係なく正確性が保証されます。
