 ## 解決策
 ## 問題の理解

 最大 100 個のアイテムのセットが与えられます。 各アイテムは、0 ～ 1 のマトリックスで表される 10 日間のサブセットで利用可能です。 10 日ごとに、ヨランダが店を訪れるかどうかを決定するため、有効な戦略は単に日の一部です。 

固定戦略の場合、最終的に各アイテムはある程度の訪問日数で表示されますが、在庫がある日数のみがカウントされます。 それでアイテムに関しては$i$、その貢献は以下にのみ依存します。$c_i$、その日の日数$j$両方が訪問されており、$F_{i,j} = 1$。 

わかったら$c_i$、配列を取得します$P$範囲の XOR 値を計算します。$[P_1, P_{c_i}]$、必要に応じてエンドポイントを交換できるという規則があります。 最終的なスコアは、すべての項目にわたるこれらの値の合計です。 

私たちは 10 日ごとに二者決定を管理します。$2^{10} = 1024$考えられる訪問パターン。 パターンごとにすべてを計算できます$c_i$そして合計スコアを評価します。 

ソリューションを形成する主な制約は、日数が非常に短いことです。 これにより、アイテムに対して最適化を試みたり、アイテムに対して大量の動的プログラミングを使用したりするアプローチは即座に排除されます。$N$。 代わりに、各評価が十分に効率的であれば、日のサブセットに対するブルートフォースが許容されます。 

微妙な点としては、$XOR\_range(a,b)$はどちらの引数でも単調ではなく、XOR プレフィックス合計のパリティ構造に応じて動作が異なります。 線形性を仮定したり、項目ごとに貪欲に日数を割り当てようとした単純な試みは、毎日の決定がすべての項目に同時に影響するため、失敗します。 

2 番目の落とし穴は、間隔を誤解することです。$[P_1, P_{c_i}]$いつ$c_i = 0$。 この問題では、引数がサンプル内で順序付けされていない可能性があるため、順序に関係なく、2 つの値間の包括的な整数間隔の XOR が正しい解釈となります。 

エッジケースには次のようなものがあります。 

すべてが$F_{i,j} = 0$。 それから毎回$c_i = 0$、すべてのアイテムが貢献します$XOR\_range(P_1, P_0)$。 を前提とした素朴な実装$c_i \ge 1$インデックスが正しく作成されなかったり、投稿がスキップされたりする可能性があります。 

全日を選択した場合。 それから$c_i$行にある 1 の数に等しい$i$。 これは、単に行の値を合計するのではなく、交差のカウントの正確さをテストします。 

2 つの戦略が同じマルチセットを生成するケース$c_i$ただしアイテムごとに分布が異なります。 目的は一度アイテムごとに分けられるので$c_i$は固定されており、カウントのみが重要であり、どの特定の日にカウントされるかは問題ではありません。 

## アプローチ

 ブルートフォースの見方は簡単です。 10 日間のすべてのサブセットを列挙します。 サブセットごとに、次のように計算します。$c_i$すべてのアイテムについて、選択されている日と在庫がある日を確認してください。 次に、XOR 範囲関数を使用して各項目の寄与を計算し、それらを合計します。 

コンピューティング$c_i$すべてのアイテムにかかる費用$O(10N)$サブセットごとなので安価です。 主なコストはサブセットの列挙です: 1024 通りの可能性があります。 したがって、合計作業量は約$1024 \cdot 100 \cdot 10$、十分に制限内です。 

残る唯一の技術的課題は評価です$XOR\_range(l,r)$素早く。 値が上がるので、$10^9$、すべての範囲を事前計算することはできません。 代わりに、標準のプレフィックス XOR ID を使用します。$$XOR\_range(a,b) = pref(b) \oplus pref(a-1)$$どこ$pref(x)$1 から x までのすべての整数の XOR です。 これにより、各クエリが O(1) に削減されます。 

したがって、問題は 10 ビットのすべてのサブセットを列挙し、単純な O(N) スコアリング関数を評価することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | O(2^{10}・N・10) | O(N) | 承認済み |
 | 最適 (同じアイデア + XOR プレフィックス) | O(2^{10} · N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレフィックス間隔の XOR を評価する関数を事前計算します。$[1, x]$。 これにより、一定時間範囲の XOR クエリが可能になります。 
2. 10 日のうちどの日が選択されるかを表す、0 ～ 1023 のすべてのマスクを繰り返します。 それぞれのビットはその日の訪問に対応します。 
3. マスクごとに、次の値を計算します。$c_i$10 日間をスキャンし、マスクと在庫マトリクスの両方が 1 を持つ位置をカウントすることによって、すべてのアイテムを対象にします。このステップでは、このスケジュールに基づいて各アイテムの有効エクスポージャを構築します。 
4. 各項目について、その寄与度を次のように計算します。$XOR\_range(P_1, P_{c_i})$、順序を正規化することでエンドポイントが暗黙的に逆転する場合を処理します。 
5. このマスクのすべての項目にわたる寄与を合計します。 
6. すべてのマスクの最大合計を追跡し、出力します。 

機能する理由: すべての有効な戦略は 10 日間の 1 つのサブセットであるため、列挙は考えられるすべての決定をカバーします。 各固定サブセットについて、次の計算が行われます。$c_i$選択した日と在庫状況が交差する部分を直接カウントするため、正確です。 目的関数はのみに依存するため、$c_i$項目ごとに独立しており、項目間で独立しているため、項目を個別に評価してもインタラクションが失われることはありません。 したがって、すべてのサブセットにわたる最大値により、全体的な最適値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def xor_upto(x):
    # XOR of all integers from 1 to x
    # pattern repeats every 4
    if x <= 0:
        return 0
    r = x % 4
    if r == 0:
        return x
    if r == 1:
        return 1
    if r == 2:
        return x + 1
    return 0

def xor_range(a, b):
    if a > b:
        a, b = b, a
    return xor_upto(b) ^ xor_upto(a - 1)

n = int(input())
F = [list(map(int, input().split())) for _ in range(n)]
P = list(map(int, input().split()))

# assume P[1..10] relevant, P[0] unused or extra
# but problem states P1..Pc so we shift accordingly if needed
P = [0] + P

ans = 0

for mask in range(1 << 10):
    total = 0

    for i in range(n):
        c = 0
        for d in range(10):
            if (mask >> d) & 1 and F[i][d]:
                c += 1

        total += xor_range(P[1], P[c] if c < len(P) else P[-1])

    ans = max(ans, total)

print(ans)
```実装は列挙の後に直接続きます。 内側のループは、選択した日と株価パターンの間の交差をカウントします。これはまさに次の定義です。$c_i$。 

XOR 範囲の計算はプレフィックス XOR ヘルパーに分離され、間隔を超えて繰り返されるループを回避します。 この問題によりエンドポイントの解釈が逆になることが明示的に許可されるため、唯一の注意点は range 関数内での順序付けの処理です。 

マスク ループはソリューションの中核であり、その正確性は完全に 10 日しか存在しないという事実に依存しており、徹底的な検索が可能になります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def xor_upto(x):
        if x <= 0:
            return 0
        r = x % 4
        if r == 0:
            return x
        if r == 1:
            return 1
        if r == 2:
            return x + 1
        return 0

    def xor_range(a, b):
        if a > b:
            a, b = b, a
        return xor_upto(b) ^ xor_upto(a - 1)

    n = int(input())

 ## 特殊なケース

 完全に空の株式マトリックスは、$c_i = 0$。 アルゴリズムは引き続きすべてのマスクを評価しますが、各項目は常に同じ値を提供します。$XOR\_range(P_1, P_0)$。 これはマスク全体で一定であるため、スケジューリングに依存せずに最大値が正しく返されます。 

完全に完全な在庫マトリックスにより、$c_i$各アイテムの訪問日数に等しい。 次に、マスクの列挙によりカウントの分布が効果的に検索され、アルゴリズムは選択された日数に基づいて戦略を正確に区別します。 

いつ$c_i$0 または 10 になり、境界インデックスが次のようになります。$P$有効なままにしておく必要があります。 実装では、安全なアクセス パターンを使用し、次の制約に依存することでこれを保証します。$c_i \le 10$。
