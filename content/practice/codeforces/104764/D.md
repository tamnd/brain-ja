 ## 解決策
 ## 問題の理解

 直線上の一連の個別の整数位置が与えられ、それぞれがクラゲを表します。 これらの立場から正確に選択する必要があります$K$それらのうち、選択された点のみを考慮します。 考えられるすべての選択肢の中で、$K$ポイントの場合、選択した 2 つのポイント間の最大距離に注目し、その量をできるだけ小さくしたいと考えます。 

サブセットが選択されると、ジェリーはどこにでも立つことができますが、グループの広がりが選択された左端と右端のクラゲによってのみ決定されるという事実は変わりません。 選択したセット内の最大距離は、単純にその最大要素と最小要素の差です。 したがって、タスクはサイズのサブセットを選択することになります。$K$それは範囲を最小限に抑えます。 

入力サイズが到達しました$2 \cdot 10^5$したがって、すべてのサブセット、さらにはすべての組み合わせを試すような解決策は、直ちに不可能になります。 ペアまたはサブセットにわたる二次スキャンには、次のオーダーが必要になります。$10^{10}$最悪の場合、1 秒の制限をはるかに超える操作が行われなくなります。 せいぜい線形に近い、または$N \log N$解決。 

素朴な落とし穴は、選ばれた両極端だけが重要であるということを忘れることです。 たとえば、ポジションが$[1, 2, 10, 11]$そして$K = 3$、選択する$\{1, 2, 11\}$範囲は 10 になりますが、$\{1, 2, 10\}$両方に同じ小さな要素が含まれているにもかかわらず、範囲 9 が得られます。 構造は、ソートされた順序でどの 3 つの連続する点が選択されるかに完全に依存します。 

もう 1 つの微妙な問題は、距離に関してジェリーの位置が重要であると仮定することです。 そうではありません。 この問題はクラゲ間の最大距離のみを求めているため、ジェリーは目的関数とは無関係です。 

## アプローチ

 強引なアイデアは、サイズのすべてのサブセットを列挙することです。$K$、その最小要素と最大要素を計算し、可能な限り最小の差を取得します。 目的の定義はサブセットに対する純粋な組み合わせであるため、これは正しいです。 ただし、そのようなサブセットの数は$\binom{N}{K}$, これは、中程度の値であっても巨大になります。$N$。 のために$N = 200000$、これは完全に不可能であり、$N = 40$すでに大きすぎます。 

重要な構造的観察は、位置がソートされると、サイズの最適なサブセットが$K$で構成されなければなりません$K$ソートされた順序で連続する要素。 サブセットがそのスパン内の要素をスキップする場合、選択された大きい要素をスキップされた小さい要素で置き換えても、範囲を縮小するか、範囲を変更しないで済むだけです。 この単調性により、検索空間がウィンドウ上で組み合わせから線形に崩壊します。 

したがって、ソート後、問題は、ある長さの連続するウィンドウをすべてスキャンすることになります。$K$そしてエンドポイント間の差異を計算します。

 | ソートされた配列のスライディング ウィンドウ |$O(N \log N)$|$O(1)$番外編 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのクラゲの位置を昇順に並べ替えます。 これにより、任意のグループのスプレッドが、恣意的な選択ではなく、この順序の連続した構造によって決定されることが保証されます。 
2. 応答変数を非常に大きな値で初期化します。 これにより、発生した最良 (最小) 範囲が追跡されます。 
3. すべてのインデックスを反復処理します。$i$ウィンドウのサイズが$K$から始まる$i$配列内に収まります。 それぞれについて$i$の要素によって形成されるグループを考えます。$i$に$i + K - 1$。 
4. このグループの範囲を次のように計算します。$a[i + K - 1] - a[i]$。 これは、ソートされた配列内では、連続するセグメントの最大値と最小値がそのエンドポイントであるため、有効です。 
5. そのようなすべてのウィンドウにわたる最小値で答えを更新します。 

スキャン終了後、保存される回答は可能な限り最小の範囲になります。 

### なぜ効果があるのか

 ソート後、最適なサブセットがインデックス順に連続していないとします。 この場合、最小値と最大値の間の間隔内に、選択されていない要素が少なくとも 1 つ存在します。 選択した極端な要素の 1 つをこの欠落している内部要素で置き換えても、端点が内側に移動するか、変更されないままになるため、範囲を広げることはできません。 この引数を繰り返すと、目的の値を悪化させることなく、最適なサブセットが連続ブロックに変換されます。 したがって、注意を連続セグメントに限定しても最適性は失われません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort()
    
    ans = float('inf')
    
    for i in range(n - k + 1):
        ans = min(ans, a[i + k - 1] - a[i])
    
    print(ans)

if __name__ == "__main__":
    main()
```この解決策は、入力を読み取り、位置リストを並べ替えることから始まります。 並べ替えは、直線上の幾何学的問題を、ウィンドウが候補グループを表す構造化配列問題に変換するため、不可欠です。 

開始インデックスのループは、すべての有効なサイズを列挙します。$K$セグメント。 各セグメントについて、エンドポイントから直接そのスプレッドを計算します。 このようなスプレッドすべての最小値が保存されます。 シングルパスの使用により、ソート後のリニアスキャンが保証されます。 

よくある間違いは、最初に並べ替えずに動的ウィンドウを維持しようとすることです。 これにより、エンドポイントのプロパティが壊れ、範囲の計算が正しく行われなくなります。 もう 1 つの間違いは、インデックスの計算ミスです。特に、最後の有効な開始が次であることを忘れています。$n - k$。

 ## 特殊なケース

 主なエッジケースは次のような場合です$K = 1$。 単一要素の範囲はゼロであり、サイズ 1 のすべてのウィンドウが生成するため、アルゴリズムはこれを処理します。$a[i] - a[i] = 0$。 

もう 1 つのケースは、ステートメントでは異なる位置が保証されているにもかかわらず、すべての値が同一である場合です。 この制限が削除された場合でも、スライディング ウィンドウは、どのような場合でも正しくゼロを返します。$K$、すべてのエンドポイントが一致するためです。 

クラスター間の大きなギャップは、アルゴリズムが端の選択を正しく回避するかどうかをテストします。 例えば、$[1, 2, 3, 100, 101]$と$K = 3$最適なウィンドウを生成します$[1,2,3]$または$[100,101, \text{(invalid)}]$位置に応じてスキャンが行われ、範囲全体にわたるエンドポイントではなく、密な領域が正しく選択されます。 

すべての候補は並べ替え後のエンドポイントの違いを通じて均一に評価されるため、アルゴリズムはこれらすべてを自然に処理します。
