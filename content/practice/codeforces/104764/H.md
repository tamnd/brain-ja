 ## 問題の理解

 一連のクラゲが与えられ、それぞれが触手の数を表す正の整数に関連付けられています。 最初のクラゲは指定された値から始まります$a_1$。 後続のすべてのクラゲは、非常に特殊な方法で以前のすべてのクラゲから構築されます。$a_i$、まず以前のすべての値の積を取得します。$a_1 \cdot a_2 \cdots a_{i-1}$、次に単一の素数、具体的には前の積を除算しない最小の素数を掛けます。 

各ステップでは、新しい素因数が 1 つだけシステムに導入され、その素数は、現在のグローバル積と比較して、未使用の (割り算の意味で) 最小の素数として貪欲に選択されます。 

タスクは、シーケンス自体を明示的に計算することではなく、生成されたすべての約数の最大値を決定することです。$a_i$、モジュロを取った$998244353$。 

出力は、素因数が反復全体でどのように蓄積されるかのみに依存し、生の大きさには依存しません。$a_i$。 約数関数は素数べき乗に対して乗算されるため、最終的に重要なのは指数の構造です。 

制約$n, a_1 \le 10^5$これは、反復までのすべての数値の単純な構築を意味します。$n$不可能です。 それぞれを代表しても$a_i$直接使用すると、値のサイズと素因数の数が指数関数的に増加するため、オーバーフローとパフォーマンスの問題が発生します。 有効な解決策は、実際の整数ではなく因数分解構造を追跡することによって機能する必要があります。 

重要な微妙な点は、答えは最終的な数値の約数や中間数値の剰余ではなく、すべての中間値の最大の約数であることです。 これらを混同すると、モジュラー演算により除数のカウントに必要な乗算構造が破壊されるため、間違った解が生成されます。 

典型的な失敗例は、実際の値を剰余として維持しようとしたときに発生します。$998244353$。 たとえば、2 つの数値が mod を法として等しい場合でも、それらの素因数分解は完全に異なるため、約数の数は異なります。 これにより、剰余演算による直接シミュレーションが無効になります。 

次の場合には、別のエッジケースが発生します。$a_1 = 1$。 この場合、最初の積には素因数がないため、欠落している素数の最小値は次のようになります。$2$、そしてシーケンスは素数を順番に導入するように動作します。 この例外的なケースにより、「欠落している最小の素約数」を検出するロジックが空の因子セットを正しく処理する必要があります。 

## アプローチ

 直接シミュレーションのアプローチにより、完全な製品が維持されます。$P_i = a_1 a_2 \cdots a_i$そして、各ステップで素数をスキャンして、分割しない最小のものを見つけます。$P_{i-1}$。 見つかったら構築します$a_i = P_{i-1} \cdot p$、積を更新し、それぞれの約数の数を計算します。$a_i$その因数分解を使用します。 

これは原理的には正しいですが、すぐに実行不可能になります。 積は指数関数的に増大し、明示的な乗算から直接因数カウントを維持する場合でも、膨大な数を因数分解するか、動的な因数分解構造を維持する必要がありますが、それでもまだ遅すぎます。$n = 10^5$。 ボトルネックは、欠落している素数を見つけることと、除数の数を繰り返し再計算することの両方です。 

重要な構造的観察は、実際の値は決して必要ないということです。$a_i$。 重要なのは、素指数がどのように発展するかということだけです。 以前のすべての項の積を乗算するたびに、高度に構造化された方法で、これまでに確認されたすべての素数の指数寄与が効果的に累積されます。 

より注意深く再定式化すると、このプロセスは、素数ごとに、素数が最初に出現したときに駆動される予測可能な組み合わせパターンに従って増加する指数を維持することと同等であることがわかります。 「プレフィックス積を分割しない最小の素数」ルールにより、素数が昇順に導入されることが保証され、一度導入されると、それらはグローバル積に永久に存在し、構造化された累積的な方法で指数が着実に増加します。 

これにより、問題は、素数ごとに、それが将来の数の指数に何回寄与するかを追跡することになります。 それぞれの素数の指数がわかったら、$a_i$、除数の数は単純に次のようになります。$$d(a_i) = \prod (e_p + 1)$$次に、この値の最大値を追跡します。 

製品をシミュレートする代わりに、各素数が何回出現するか、および指数の寄与がどのように蓄積されるかをシミュレートします。 これは、素数を事前に計算し、各素数がシステムに入るときの実行スケジュールを維持し、その後、接頭辞の組み合わせの方法で指数の寄与を更新することによって実行できます。

 ## アルゴリズムのチュートリアル

 中心的な考え方は、プロセスを素数の漸進的な導入と時間の経過に伴う指数寄与の蓄積として扱うことです。 

## アルゴリズムのチュートリアル

 1. 以下のすべての素数を事前計算します。$n$ふるいを使って。 各ステップでは累積積をまだ分割していない最小の素数が選択されるため、素数を導入するプロセスは常に昇順に従います。 
2. 素数がシステムに導入される順序を記録するリストを維持します。 各ステップで新しい素数が 1 つだけ導入されるため、最初の$n$素数は連続して使用され、次のように切り捨てられます。$a_1$の初期因数分解。 
3. 因数分解$a_1$そしてその素数の指数カウントを初期化します。 これらのプライムは時間ゼロの時点でシステム内ですでに「アクティブ」になっているため、後続のすべての製品に即座に寄与し始めます。 
4. 各アクティブな素数が将来の指数に何回寄与するかを追跡する配列を維持する$a_i$。 重要な洞察は、新しい$a_i$形成されると、それまでのすべてを乗算します$a_j$、したがって、指数寄与は時間インデックスの累積和のように動作します。 
5. 各ステップごとに$i$、プレフィックス累積を使用して間接的に指数ベクトルを計算します。 完全な因数分解を再計算する代わりに、アクティブ化時間が以下の素数の寄与カウンターを更新します。$i$。 
6. それぞれの除数の数を計算します。$a_i$累積された指数に対して乗算式を使用し、表示された最大値を追跡します。 

微妙な点は、指数の増加がステップごとに独立していないことです。 初期の素数はその後のすべての積で繰り返し乗算されるため、それらの指数の寄与は時間の経過とともに線形ではなく二次関数的に増加します。 これが、独立したステップごとの更新ではなく、プレフィックスの蓄積が必要な理由です。 

### なぜ効果があるのか

 どの段階でも$i$の構造$a_i$は、そのステップの前に各素数が累積積プレフィックスに何回含まれているかによって完全に決定されます。 構築ルールによって素数の導入順序が決定論的に保証され、素数が削除されることがないため、システムは、起動時間と累積寄与数を追跡することで完全に把握できる方法で単調に進化します。 

この不変条件は、すべてのステップで、素数の指数がその素数が関与したプレフィックスの数と正確に一致することを保証するため、これらのカウントから指数を再構成することは正確であり、除数のカウントを計算するのに十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def sieve(n):
    is_p = [True] * (n + 1)
    is_p[0] = is_p[1] = False
    for i in range(2, int(n ** 0.5) + 1):
        if is_p[i]:
            step = i
            start = i * i
            for j in range(start, n + 1, step):
                is_p[j] = False
    return [i for i, v in enumerate(is_p) if v]

def factorize(x, primes):
    res = {}
    for p in primes:
        if p * p > x:
            break
        if x % p == 0:
            cnt = 0
            while x % p == 0:
                x //= p
                cnt += 1
            res[p] = cnt
    if x > 1:
        res[x] = res.get(x, 0) + 1
    return res

def solve():
    n, a1 = map(int, input().split())

    primes = sieve(100000)

    base = factorize(a1, primes)

    max_div = 1
    MOD = 998244353

    # exponent contribution map
    exp = base.copy()

    # simulate introduction of new primes
    used = set(base.keys())
    prime_iter = [p for p in primes if p not in used]

    # prefix product exponent growth simulation
    prefix_count = 1

    for i in range(2, n + 1):
        # introduce next smallest unused prime
        if prime_iter:
            new_p = prime_iter.pop(0)
            exp[new_p] = exp.get(new_p, 0) + 1

        # all existing primes get multiplied by current prefix product
        # simulate effect: each step increases exponents cumulatively
        for p in list(exp.keys()):
            exp[p] += exp[p]

        # compute divisor count
        div = 1
        for v in exp.values():
            div = (div * (v + 1)) % MOD

        max_div = max(max_div, div)

    return max_div

if __name__ == "__main__":
    print(solve())
```実装は、以下の素数を生成することから始まります。$10^5$、これは両方の因数分解に十分です$a_1$そして素数の候補を順番に列挙します。 因数分解ステップでは、後のすべての計算のシードを形成する初期指数構造が抽出されます。 

次に、シミュレーション ループは、素数ごとの指数カウントを維持することによって、再帰的な乗算の動作をモデル化しようとします。 新しい素数は、「最小の未使用素数」ルールを反映して昇順に追加されます。 既存の素数は、接頭辞積に繰り返し含まれることを反映するように指数が更新されます。 

除数の計算には標準の公式を使用し、乗算します。$(e_p + 1)$すべての素数にわたってモジュロを取る$998244353$。 最大値はすべての反復にわたって追跡されます。

 ## 特殊なケース

 のために$a_1 = 1$の場合、因数分解マップは空であるため、アルゴリズムはすぐに 2 以降の素数の導入を開始します。 これにより、各ステップが初期バイアスなしで新しい素因数を追加するかのように動作するクリーンなシーケンスが生成されます。 指数追跡はゼロから始まり、導入された素数のみから増加するため、除数関数は単調増加します。 

高度な複合材料向け$a_1$、 のような$a_1 = 2^{10} \cdot 3^5 \cdot 5^3$、初期指数マップはすでに密になっています。 アルゴリズムはこれらすべての素数をステップ 1 からアクティブなものとして扱うため、すべてのプレフィックス乗算に直ちに参加します。 これにより、シーケンスの初期段階で除数の数がより速く増加し、多くの場合、多くの新しい素数が導入される前に最大値が発生します。
