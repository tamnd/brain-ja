 ## 解決策
 ## 問題の理解

 一定の昼食時間内に毎分何匹のクラゲが食べられるかを表す一連の整数が与えられます。 タスクは、そのセグメント内で食べられたクラゲの総数が奇数になるような連続した分のセグメントを見つけることであり、そのようなすべてのセグメントの中で可能な限り最大の長さが必要です。 そのようなセグメントが存在しない場合は、その事実を報告する必要があります。 

重要な出力は、合計そのものではなく、合計が奇数パリティを持つ最長の部分配列の長さです。 

制約により、最大で$2 \cdot 10^5$要素により、部分配列の 2 次または 3 次の列挙が即座に除外されます。 すべてのサブ配列をチェックするソリューションには、次のようなものが必要になります。$N^2$セグメント合計、約$4 \cdot 10^{10}$最悪の場合、1 秒の制限をはるかに超えて操作が行われる可能性があります。 

の値$j_i$は大きくなる可能性がありますが、合計が奇数であるか偶数であるかのみを考慮するため、この条件ではパリティのみが重要です。 これは、配列をパリティ情報に縮小するだけで十分であることを示唆しています。 

いくつかの特殊なケースが重要です。 

すべての要素が偶数であるシーケンスでは、すべての部分配列の合計が偶数になります。 たとえば、入力`[2, 4, 6]`有効なセグメントが得られないため、答えは次のようになります。`-1`。 

奇数の要素を 1 つだけ含むシーケンスでも、長い有効なセグメントを生成できます。これは、奇数の奇数の要素を含むセグメントの和が奇数になるためです。 例えば、`[2, 1, 2]`完全な配列を許可します。合計は奇数です。 

微妙なケースとしては、配列全体の合計が偶数であるが、プレフィックスまたはサフィックスを削除すると、有効な奇数合計セグメントが作成される場合があります。 例えば`[1, 2, 3, 4]`の合計は偶数ですが、最良のセグメントは依然として配列全体または大きなサブ配列である可能性があります。 

## アプローチ

 直接的なブルート フォース手法では、考えられるすべてのサブ配列をチェックし、その合計を計算し、合計が奇数のサブ配列の最大長を記録します。 これは概念的に、すべての間隔を列挙することで機能します。$[l, r]$、コンピューティング$\sum_{i=l}^{r} j_i$、パリティをチェックします。 

部分配列の数は$O(N^2)$、さらにプレフィックス合計を使用しても、合計の計算が次のように削減されます。$O(1)$、列挙自体が支配的です。 のために$N = 2 \cdot 10^5$、これは約につながります$2 \cdot 10^{10}$繰り返しですが、これは不可能です。 

重要な観察は、和のパリティが 2 を法として加法的に動作することです。完全な和を追跡する代わりに、プレフィックス パリティのみが必要です。 させて$p_i$インデックスまでのプレフィックスの合計のパリティになります$i$。 次に、セグメントの合計$[l, r]$まさにそのときが奇妙だ$p_{l-1} \neq p_r$。 

これにより、問題は最も遠いインデックスのペアを見つけることになります。$l-1$そして$r$プレフィックスパリティが異なるなど。 ポジションごとに$r$、両方のパリティ状態の最も早い出現がわかっていれば、セグメントの長さを最大化できます。 

これにより、問題は、プレフィックス配列内で最初に出現したパリティ 0 とパリティ 1 を追跡し、それらを可能な最新のインデックスと組み合わせるという問題に変換されます。

 | 最適 (プレフィックス パリティ追跡) |$O(N)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 合計のプレフィックスパリティの観点から配列を書き換えます。 

1. 配列を左から右にスキャンしながら、実行中のパリティ値を計算します。 この値は 0 または 1 のいずれかで、現在のインデックスまでの合計が偶数か奇数かを表します。 
2. 各パリティ値 (0 または 1) が確認された最も古いインデックスを格納する 2 つの配列または変数を維持します。 最初は、要素を処理する前に、パリティ 0 がインデックス 0 に表示されます。 
3. 配列内を移動しながら、プレフィックス パリティを更新します。 
4. 各ポジションで$i$、現在のパリティが$p$、その後、パリティがあった前の位置$1 - p$で終わる有効な部分配列を形成します$i$奇数の合計で。 
5. 長さを計算します$i - earliest[1 - p]$そして最大の答えを更新します。 
6. アレイの終わりまでこのプロセスを続けます。 
7. 有効なサブ配列が見つからなかった場合は、-1 を返します。 

重要な考え方は、各パリティが最初に出現する場所がわかれば、今後出現するたびに有効なセグメントを可能な限り拡張できるようになり、距離を最大化することのみを考慮するということです。 

### なぜ効果があるのか

 プレフィックス パリティは、減算モジュロ 2 を通じてサブ配列合計のパリティをエンコードします。モジュロ 2 での減算は XOR と同等であるため、奇数和の条件は 2 つのプレフィックス パリティ状態を比較することになります。 

すべての有効なサブ配列は、異なるプレフィックス パリティを持つインデックスのペアに一意に対応します。 したがって、最も長い有効なサブ配列は、1 つのパリティの最も古い出現を、反対側のパリティの最も新しい出現に接続する必要があります。 最も早い発生を追跡することで、常に長さを最大化できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # prefix parity
    parity = 0

    # earliest index where parity 0 or 1 occurred
    first = [-1, -1]

    # prefix at index 0 (empty prefix has sum 0 -> parity 0)
    first[0] = 0

    best = -1

    for i in range(1, n + 1):
        parity ^= (a[i - 1] & 1)

        if first[parity] == -1:
            first[parity] = i
        else:
            # we can form a subarray ending at i
            best = max(best, i - first[1 - parity])

    print(best if best > 0 else -1)

if __name__ == "__main__":
    solve()
```この実装では、プレフィックス合計のパリティを維持するために実行中の XOR が維持されます。 配列`first`各パリティが発生する最も古いプレフィックス インデックスを格納します。 初期化します`first[0] = 0`なぜなら、何かを読み取る前は合計がゼロだからです。 

上位ビットは奇数/偶数の動作に影響を与えないため、各ステップでは各値の最下位ビットのみを使用してパリティを更新します。 プレフィックス パリティに遭遇すると、その最初の出現を記録するか、反対のパリティの最初の出現を使用して候補セグメントを形成します。 

引き算`i - first[1 - parity]`で終わる有効な間隔の長さを与えます。`i`。 これは、明示的なサブ配列の列挙を回避する中心的な計算です。 

微妙な点は、最初に出現したもののみを初期化し、その後は更新しないことです。これは、可能な限り最大のセグメント長が必要であり、常に最も早い開始インデックスの恩恵を受けるためです。

 ## 特殊なケース

 すべて偶数のシーケンスは、パリティ フリップがまったく発生しない障害モードを示しています。 そのような場合には、`first[1]`が設定されることはなく、計算されたすべての候補は無効のままです。 アルゴリズムは正しく返します`-1`なぜなら`best`決して更新しません。 

単一要素の配列は、初期化で最小限の入力が処理されるかどうかをテストします。 入力あり`[5]`、プレフィックスパリティが 1 になり、`first[1]`はインデックス 1 に設定されており、反対のパリティは存在しないため、単一の奇数要素を有効なセグメントとして解釈した場合にのみ、答えは正しく 1 になります。 

のようなケース`[2, 2, 2, 1]`は、プレフィックス インデックス作成の重要性を示しています。 最後のパリティ フリップは最後の要素で発生し、最も古い反対パリティはインデックス 0 にあり、全長の有効なセグメントが生成されます。
