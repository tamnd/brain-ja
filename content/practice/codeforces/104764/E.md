 ## 解決策
 ## 問題の理解

 最大 100 個のノードを持つ重み付きツリーが与えられます。 各ノードは海食洞を表し、非負の値で表されるある程度の量のクラゲが含まれています。 接続された 2 つの洞窟の間を移動するには、エッジ ウェイトに等しいエネルギーがかかり、任意の 2 つの洞窟間の移動コストの合計は、ツリー内の固有のパスに沿ったウェイトの合計になります。 

アオランが洞窟を選んだ場合$y$彼の拠点として、そしてすべての洞窟に$x$、彼はから旅行します$y$に$x$、距離料金を支払います$dist(y,x)$、そしてクラゲと「係合」します。$x$、追加のエネルギー単位がかかります。 洞窟からのエンゲージメント貢献度$x$は次のように定義されます$$\frac{c_x}{dist(y,x) + 1}.$$タスクはベース ノードを選択することです$y$これは、すべてのノードにわたるこれらの寄与の合計を最大化し、選択したノードと結果の最大合計の両方を出力します。 

入力サイズが小さいので、$n \le 100$したがって、3次法や2次法も実行可能です。 これは、ノード間のすべてのペアごとの距離を事前計算できることをすぐに示唆しています。 

微妙な問題は数値の安定性です。 答えには浮動小数点除算が必要であり、精度が範囲内である必要があります。$10^{-4}$したがって、単純な整数演算は最終集計ステップでは不十分ですが、項の数が少ない (合計あたり最大 100) ため、標準の倍精度で簡単に十分です。 

入力が明示的にツリーであるため、切り離されたグラフや複数のコンポーネントなどの厄介な構造上のエッジ ケースはありません。 

素朴な推論による失敗例の 1 つは、近くの高値のみに基づいて貪欲にルートを選択しようとすることです。$c_i$価値観。 たとえば、小さなライン ツリーでは、近隣の値がわずかに小さいものの、全体的な距離がはるかに優れているノードが、局所的に最適な選択よりも優れたパフォーマンスを発揮する可能性があります。 これは、目的がグローバルで距離に依存しており、ローカルな貢献に分解できないことを示しています。 

## アプローチ

 直接的なアプローチは、考えられるすべてのベース ノードを試すことです。$y$。 選択肢ごとに、最短経路距離を次から計算します。$y$他のすべてのノードに送信し、合計します$\frac{c_x}{dist(y,x)+1}$。 

グラフはツリーであるため、最短パスは一意であり、重みが小さい場合は BFS または DFS で計算できますが、重みは最大であるため、$10^3$、各ノードから独立して計算する場合はダイクストラが必要です。 それは与える$n$ディクストラの実行、それぞれのコスト$O(n \log n)$、それで、それについて$10^4 \log 100$、それは些細なことです。 

もっと簡単な観察は、$n$はわずか 100 なので、すべてのペアの最短パスを事前に計算できます。 フロイド＝ウォーシャルのどちらかが$O(n^3)$、または の各ノードからダイクストラを実行します。$O(n^2 \log n)$。 完全な距離行列を取得したら、各候補ルートの評価は単なる線形スキャンになります。 

これを機能させる重要な構造は、ツリーにサイクルがないため、距離が明確に定義され、ルートの選択に依存しないことです。 すべての距離が判明すると、目的関数は固定行列に対する直接的な評価になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 事前計算なしのブルート フォース |$O(n^2 \log n)$ルートごと →$O(n^3 \log n)$|$O(n^2)$| 許容できるが不要 |
 | 全ペアの距離 + 評価 |$O(n^2 \log n + n^2)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 重みを使用してツリーの隣接リストを作成します。 

これにより、各ノードが既知のコストで近隣ノードに到達できる構造が得られます。これは最短パスの計算に必要です。 
2. すべてのノードから Dijkstra を実行する$i$計算する$dist[i][*]$。 

グラフはツリーですが、ルート表現に関する推論を避けるために、一般的な重み付きグラフとして扱います。 
3. 各ノードについて$y$、ゼロに初期化されたスコアを計算します。 
4. ノードごとに$x$、 追加$c_x / (dist[y][x] + 1)$のスコアまで$y$。 

分母には​​追加の 1 ユニット交戦コストが含まれるため、同じノードであっても貢献度は次のようになります。$c_y / 1$。 
5. すべての候補を計算しながら、最大スコアを持つノードを追跡します。 
6. 最適なノード インデックスとそのスコアを小数点以下 5 桁にフォーマットして出力します。 

正確さは、距離が固定されると、各候補ルートが隠れた相互作用なしに独立して評価されるという事実に依存します。 和の各項は、選択した根と事前に計算された距離のみに依存します。 

### なぜ効果があるのか

 このアルゴリズムは、考えられるすべての基底を明示的に列挙し、それぞれの目的関数の正確な値を計算します。 ツリー内の距離は固定されており、ルート化とは独立しているため、事前に計算された距離行列はすべての評価に有効です。 したがって、最終的な選択は、正しく計算された値の有限セットに対する正確な最大化であり、最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def dijkstra(start, adj, n):
    INF = 10**18
    dist = [INF] * (n + 1)
    dist[start] = 0
    pq = [(0, start)]
    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

def solve():
    n = int(input())
    c = [0] + list(map(int, input().split()))

    adj = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        x, y, w = map(int, input().split())
        adj[x].append((y, w))
        adj[y].append((x, w))

    dist = []
    for i in range(1, n + 1):
        dist.append(dijkstra(i, adj, n))

    best_node = 1
    best_val = -1.0

    for y in range(1, n + 1):
        s = 0.0
        for x in range(1, n + 1):
            s += c[x] / (dist[y-1][x] + 1)
        if s > best_val:
            best_val = s
            best_node = y

    print(best_node)
    print(f"{best_val:.5f}")

if __name__ == "__main__":
    solve()
```このソリューションでは、まず隣接リストを構築し、ダイクストラ実行を繰り返してすべての最短パスを計算します。 距離テーブルは、各候補ルートを再計算せずに個別に評価できるように保存されます。 

スコアを計算するときの式は、`dist[y-1][x]`これは、距離を 1 から始まるインデックスのノードの 0 から始まるインデックスのリストに保存したことを反映しています。 除算は浮動小数点で行われますが、合計には最大 100 個の項が含まれ、数値誤差が許容範囲を十分に下回っているため、これで十分です。 

フロイド＝ウォーシャルの代わりにダイクストラを選んだのは、ここでは文体的なものである。 どちらも十分に高速ですが、ダイクストラは解を標準的なグラフの直感に近づけます。 

## 実用的な例

 ### トレースの例

 すべてのエッジの重みが 1 で、値が 1-2-3 の 3 つのノードが並んだ小さなツリーを考えてみましょう。$c = [2, 1, 3]$。 

| 基数 y | dist(y,1) | dist(y,2) | dist(y,3) | スコア計算 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 2 | 2/1 + 1/2 + 3/3 = 2 + 0.5 + 1 |
 | 2 | 1 | 0 | 1 | 2/2 + 1/1 + 3/2 = 1 + 1 + 1.5 |
 | 3 | 2 | 1 | 0 | 2/3 + 1/2 + 3/1 |

 最も近いベースはノード 3 です。これは、最大値が最も近いという利点があるからです。 

このトレースは、距離の非対称性が各ノードの寄与にどのように直接影響し、中心性と値の分散が同時に重要になるかを示しています。 

### トレース例 2

 中心 1 が重み 2 の 2、3、4 に接続され、値を持つ星形のツリー$c = [10, 1, 1, 1]$。 

| 基数 y | 中心距離パターン | スコア構造 |
 | --- | --- | --- |
 | 1 | すべては 1 のままです | 10/1 + 1/3 + 1/3 + 1/3 |
 | 2 | 非対称距離 | 1/1 + 10/3 + 1/5 + 1/5 |
 | 3 | 2 | に対称 似たような |

 トレースは、葉が中心に近づく可能性があるにもかかわらず、ベースが中心に配置された場合に高い中心値が優勢であることを示しています。

 ## 特殊なケース

 2 つのノードを持つ最小ツリーでは、ノードがソースとターゲットの両方である場合でも、分母ルールが正しく適用されているかどうかがチェックされます。 ノード 1 が重み 5 でノード 2 に接続すると、$c = [4, 6]$、ノード 1 を選択すると、次の結果が得られます。$4/1 + 6/6$、ノード 2 を選択すると、$6/1 + 4/6$。 アルゴリズムは、事前に計算された距離行列を使用して両方を正しく評価し、大きい方を選択します。 

100 個のノードのチェーンなど、非常にアンバランスなツリーでは、距離の累積によって精度のドリフトが生じていないかどうかがチェックされます。 各候補ルートは最大 100 個の小数加算を使用するため、浮動小数点誤差は安定しており、計算された合計を直接比較することによって最適なノードが正しく特定されます。
