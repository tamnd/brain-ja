 ## 解決策
 ## 問題の理解

 直線上に配置された一連の柱の高さが与えられています。 各位置には高さがあり、しきい値もあります`x`。 タスクは、セグメント内のすべての柱の高さが最大になるように、これらの柱の連続したセグメントを見つけることです。`x`。 このような有効なセグメントすべての中で、可能な限り最大の長さが必要です。 

より簡単に言うと、配列に沿って歩き、高さが超えない位置にのみ留まることを許可されると想像してください。`x`。 高すぎる柱にぶつかった場合は、そのセグメントを停止し、その後に新しいセグメントを開始する必要があります。 答えは、「許可された」ポジションが途切れることなく続く最長の範囲です。 

入力サイズは非常に大きくなり、最大 700,000 要素になる可能性があります。 これにより、すべてのサブセグメントを明示的にチェックするソリューションは即座に除外されます。 二次アプローチでは、すべての開始位置を考慮して右に拡張する必要があり、最悪の場合、次のように実行されます。$n^2$チェック、この制約には遅すぎます。 したがって、ソリューションは配列を線形時間で処理する必要があります。 

すべての要素が より大きい場合、微妙なエッジ ケースが発生します。`x`。 この場合、有効なセグメントは存在せず、答えはゼロになります。 もう 1 つの特殊なケースは、すべての要素が有効な場合です。この場合、答えは単純です。`n`。 

単純な間違いは、連続性を尊重せずに、問題をグローバルに「要素数 ≤ x」として扱うことから発生することがよくあります。 たとえば、配列が次の場合、`[1, 100, 2, 3]`と`x = 50`、有効な要素は 1、2、3 ですが、これらは 1 つのセグメントを形成しません。 正解は 3 ではなく 2 です。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべての開始インデックスについて、すべての要素が ≤ x のままでウィンドウを右に拡張し、その長さを計算します。 これにより、すべての有効なセグメントが正しく検索されますが、すべての要素が ≤ x である最悪のケースでは、各開始インデックスが最後までスキャンされ、おおよその結果が得られます。$n + (n-1) + \dots + 1$つまり二次関数です。 

重要な観察は、妥当性は個々の要素が ≤ x であるかどうかのみに依存し、セグメントの条件は純粋に局所的であるということです。 複雑な構造を維持したり、セグメント間で何かを再計算したりする必要はありません。 代わりに、配列は「良好な」値の最大の連続ブロックに自然に分割されます。 より大きな要素に遭遇するたびに、`x`、構造を完全に破壊し、現在のセグメントの長さをゼロにリセットします。 

これにより、現在の有効な実行の長さを追跡し、すべての実行にわたって最大値を維持する単一の線形スキャンに問題が軽減されます。

 ## アルゴリズムのチュートリアル

 現在の有効なセグメントの長さと、これまでに確認された最良の答えという 2 つの値を維持しながら、配列を左から右に処理します。 

1.初期化`cur = 0`そして`best = 0`。 変数`cur`有効な要素の現在の連続を追跡します。`best`これまでに見つかった最大のストリークを保存します。 
2. 配列内の各高さを反復処理します。 各要素について、≤ x であるかどうかを確認します。 これにより、現在の有効なセグメントを拡張できるかどうかが決まります。 
3. 要素が ≤ x の場合、インクリメントします`cur`有効なセグメントは中断されることなく継続するため、1 ずつ増加します。 これは、現在の位置が現在の実行を延長することを反映しています。 
4. 要素が x より大きい場合、リセット`cur`これが必要なのは、妥当性条件ではセグメント内のすべての要素が制約を満たす必要があり、この要素は連続性を完全に壊してしまうためです。 
5.アップデート後`cur`、 アップデート`best = max(best, cur)`この時点までに確認された最長の有効なセグメントを記録します。 
6. 配列全体を処理した後、出力します。`best`。 

### なぜ効果があるのか

 どのポジションでも、`cur`すべての値が ≤ x である位置で終わる現在の連続したサフィックスの長さを正確に表します。 リセットするたびに、有効なセグメントに可能な唯一のブレークポイントである無効な要素で配列を正確に切り取っています。 すべての有効なセグメントは 2 つの無効な要素 (または境界) の間に完全に存在する必要があるため、すべての候補セグメントは、次の値として完全にキャプチャされます。`cur`有効なセグメントが欠落せず、無効なセグメントがカウントされないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    cur = 0
    best = 0

    for v in a:
        if v <= x:
            cur += 1
            if cur > best:
                best = cur
        else:
            cur = 0

    print(best)

if __name__ == "__main__":
    solve()
```この実装は 1 パスで入力を読み取り、一定の追加状態のみを維持します。 重要な点は、次の値を超えるとすぐにリセットが行われることです。`x`無効な要素がセグメントを汚染しないようにします。 最大更新は現在の実行を拡張した後に実行され、各実行の最終値が正しくキャプチャされることが保証されます。

 ## 特殊なケース

 次のような完全に無効な配列`5 3 / 10 11 12 13 14`は、繰り返しトリガーされるリセット メカニズムを示しています。 アルゴリズムが増加することはありません`cur`したがって、全体を通してゼロのままです。`best`はゼロのままで、有効なセグメントが存在しないことを正確に捕捉します。 

次のような完全に有効な配列`5 10 / 1 2 3 4 5`リセットをトリガーすることはありません。 変数`cur`に蓄積する`n`、 そして`best`すべてのステップで更新され、次で終了します`5`。 これは、連続性が累積によって自然に処理されるため、アルゴリズムがセグメント境界を明示的に検出する必要がないことを示しています。 

のような混合ケース`6 4 / 1 2 10 3 4 5`配列を 2 つの候補セグメントに分割する単一のブレークを示します。`[1,2]`そして`[3,4,5]`。 アルゴリズムは、次の独立した実行を通じて両方を正しく評価します。`cur`、 そして`best`そのうちの最大値を捕捉します。`3`。
