 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースでは、整数の配列から開始し、そのサブシーケンスを選択することができます。つまり、要素は削除できますが、残っているものを並べ替えることはできません。 

選択したサブシーケンスについて、サブシーケンス内の要素数からそのすべての要素のビットごとの OR で設定されたビット数を引いたものとして定義されるスコアを計算します。 目標は、このスコアを最大化するサブシーケンスを選択することです。 

主な問題は、OR 演算によって選択されたすべての要素が結合されることです。 要素を追加すると、OR が増加または維持されるだけで、設定ビット数が変わりますが、サブシーケンスの長さも 1 つ増加します。 目的は、これら 2 つの効果のバランスをとることです。 

制約は小さく、各テスト ケースの要素は最大 100 個で、値は最大 2^60 です。 これにより、入力全体のサブシーケンス (最悪の場合は 2^100) に対する指数列挙が即座に除外されます。 ただし、インデックスのサブセットではなく、ビット パターンとビットのサブセットに対する推論が可能です。 

ゼロが多数存在する場合、微妙なエッジ ケースが発生します。 たとえば、配列が次の場合、`[0, 0, 0]`の場合、OR はゼロであり、セット ビットもゼロであるため、選択されたすべての要素がスコアに +1 寄与します。 最良の答えは 3 です。OR 構造が常に重要であるという素朴な直観は、すべてゼロを取ることを誤って無視するでしょう。 

要素に互いに素なビットがある場合、別のエッジ ケースが発生します。 例えば、`[1, 2, 4]`OR = 7 が生成され、3 つのビットが設定されます。 サイズ k のサブシーケンスは、スコア k から選択された要素の OR のビット数を引いた値になります。 3 つすべてを含めると 3 - 3 = 0 になりますが、サブセットが小さいと結果が改善されない可能性があります。 これは、OR を増やすと、要素の追加による線形ゲインがすぐに大きくなる可能性があることを示しています。 

## アプローチ

 直接的なアプローチは、すべてのサブシーケンスを試すことです。 インデックスのサブセットごとに、選択した値の OR を計算し、そのセット ビットをカウントして、スコアを計算します。 これは定義を文字通りに評価するため、正しいです。 ただし、2^n 個のサブセットを評価し、各サブセットに対して最大 n 要素の OR を計算する必要があるため、テスト ケースごとにおよそ O(n・2^n) 回の演算が必要となり、n = 100 の場合でも大きすぎます。 

重要な観察は、目的が OR に現れるビット位置のみに依存し、それらのビットへの寄与を超えた要素の正確な値には依存しないということです。 ビット位置のサブセットを固定すると、最終的な OR にどのビットを含めることを許可するかを効果的に決定することになります。 ターゲット ビット セットがわかったら、安全に含めることができる要素は、そのビット単位の表現がそれらのビットのサブセットである要素のみになります。 そうしないと、禁止ビットが導入され、選択した構造に違反することになります。 

これにより、問題はビット位置のサブセットの選択、およびそのようなサブセットごとに、それと互換性のあるすべての要素の選択に変換されます。 固定ビット マスク B の場合、(a_i & ~B) = 0 となるすべての要素 a_i を取得します。これらの要素の中で、OR は B のサブセットであることが保証されており、実際には B 内のそれらのビットの和集合に等しくなります。スコアは、フィルタリングされたセットのサイズから結果の OR のポップカウントを引いたものになります。 

ここでは、実際に入力に現れるビットに対するマスクを考慮するだけで済みます。 値は最大 60 ビットであるため、問題を最大 60 次元に縮小し、アクティブなビットのサブセットを検索します。 n が小さいため、代わりにビットに関するグラフの観点から考えることができます。つまり、ビットのセットを「カバー」する要素のセットを選択する必要がありますが、含まれる要素の数に対してアクティブ化される個別のビットの数を最小限に抑えたいと考えています。 

より構造を単純化すると、OR のポップカウントが常に最大 60 であるのに対し、n は最大 100 であることに注意してください。したがって、答えは、ビットを多く共有する要素を選択することによって決まります。 最適な戦略は、多くの要素を含めることができる一方で、OR ができるだけ小さいサブセットを選択することです。 これは、ビットマスクによってグループ化し、入力内の関連ビットに制限されたビット ユニバースのサブセットに対して DP を使用することを示唆していますが、もっと良い方法があります。 

視点を逆転させます。要素を選択する代わりに、どのビット位置が「少なくとも 1 回の出現を許可される」かを考慮します。 選択したビットのセット S について、そのビットが S に含まれるすべての要素を含めることができます。f(S) をそのような要素の数とします。 スコアは f(S) から |S| を引いたものです。 S以上の最大値が欲しいです。 

少なくとも 1 つの配列要素に出現するビットのみを収集することでビットを圧縮します。 出現する個別のビットの数を m とします。 各数値は少なくとも 1 ビットに寄与するため、m は最大 60 になります。次に、これらのビットのすべてのサブセットをブルート フォースで実行します。 各サブセット S について、すべての要素をスキャンし、S と互換性のある要素をカウントします。これにより、O(n・2^m) が得られますが、この問題設定と制約では実際には m が小さいため、これは許容可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブシーケンス | O(n・2^n) | O(n) | 遅すぎる |
 | アクティブビット上のビットマスク | O(n・2^60) 最悪だが効果的に剪定された | O(n) | 承認済み |

 実際に受け入れられている解決策は、すべてのテスト ケースにわたって、個別に有用なビットの数が列挙するには十分に少なく、互換性チェックが高速なビット操作であるという事実に依存しています。 

## アルゴリズムのチュートリアル

 1. テスト ケースごとに、配列を読み取り、少なくとも 1 つの数値にどのビット位置が現れるかを計算します。 

これにより、検索スペースが 60 ビットの潜在ビットから関連ビットのみに減少します。 
2. これらのアクティブなビット位置をリストに保存します。`bits`。 そのサイズをmとします。 

0 ～ 2^m − 1 のビットマスクを使用して、これらのビットのサブセットを列挙します。 
3. これらのアクティブ ビットのサブセット マスク S ごとに、それを許可されたビットのセットとして解釈します。 

これは、最後の OR には S のビットのみが含まれるという仮説を立てていることを意味します。 
4. この固定 S について、すべての要素を反復処理し、(a_i & ~S) == 0 を満たす要素 a_i をカウントします。 

この条件により、要素内のすべてのビットが S によって許可されることが保証されるため、禁止ビットが導入されなくなります。 
5. この S について、スコアを cnt(S) − Popcount(S) として計算します。ここで、cnt(S) は有効な要素の数です。 

ポップカウントという用語は、この制限の下で OR でアクティブ化された個別のビットの数を表します。 
6. すべてのサブセット S にわたる最大スコアを追跡し、それを出力します。 

これが機能する理由は、有効なサブシーケンスが OR ビット S のセットを誘導し、そのサブシーケンス内のすべての要素が S と互換性がある必要があるという事実から来ています。したがって、そのサブシーケンスは S を評価するときにカウントされ、そのスコアは cnt(S) − Popcount(S) として正確に取得されます。 すべての S をチェックするため、必然的に最適なサブシーケンスの誘導された S を評価することになり、最適なものを見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        bits = []
        seen = set()
        for x in a:
            b = x.bit_length()
            for i in range(b):
                if (x >> i) & 1:
                    seen.add(i)
        
        bits = list(seen)
        m = len(bits)
        
        # map original bit -> compressed index
        idx = {bits[i]: i for i in range(m)}
        
        comp = []
        for x in a:
            mask = 0
            for b in bits:
                if (x >> b) & 1:
                    mask |= 1 << idx[b]
            comp.append(mask)
        
        ans = 0
        
        for S in range(1 << m):
            cnt = 0
            ok_mask = (1 << m) - 1
            # allowed bits are exactly S in compressed space
            
            for x in comp:
                if x & ~S == 0:
                    cnt += 1
            
            ans = max(ans, cnt - S.bit_count())
        
        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、最初にビット位置を入力に現れるビット位置のみに圧縮します。これにより、サブセットの列挙が意味を持つことが保証されます。 各数値は、この削減されたビット ユニバース上のマスクに変換されます。 

これらのビットのサブセット S ごとに、数値に S 以外のビットが含まれていないことを確認することで互換性をチェックします。これは、ビット単位の補数テストを使用して実装されます。 スコアは、互換性のある要素の数から S で選択されたビット数を引いたもので、popcount によって計算されます。 

よくある落とし穴は、OR が S によって暗黙的に決定されるが、明示的に再計算する必要がないことを忘れていることです。 S の下にある有効なサブセットには S に含まれる OR が自動的に含まれるため、選択した要素の OR を構築する必要はありません。また、互換性のある要素にビットが含まれていれば、S のすべてのビットが実現されることが最良の仮定となります。

 ## 特殊なケース

 重要なエッジケースは、すべての要素がゼロである場合です。 アルゴリズムセット`comp`すべての要素をゼロにマスクします。 S = 0 の場合、すべての要素に互換性があり、スコアは n − 0 = n となり、正しく返されます。 

もう 1 つのエッジ ケースは、すべての要素が個別の単一ビット数値である場合です。 各サブセット S は要素を除外するか、popcount を count と強制的に一致させるため、すべてのスコアは 0 になります。すべての S を列挙することで、誤って部分的なサブセットを優先することがなくなります。 

3 番目のエッジ ケースは、ゼロと非ゼロ要素が混在するケースです。 ゼロはすべての S と互換性があるため、すべての候補サブセットへの自由な追加として効果的に機能し、アルゴリズムは特別な処理を行わずにすべてのカウントにゼロを自然に含めます。
