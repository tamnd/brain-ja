 ## 問題の理解

 0 から 0 までの番号が付けられた 1 次元のセルのストリップが与えられます。$10^{18}$。 最初はすべてのセルが白色です。 特定のセルを黒く塗る必要があり、距離が最大で次の白いセルのペアを選択できます。$k$同時に黒く塗装します。 必須リストにない追加セルを最大 1 つまでペイントすることもできます。 タスクは最小のものを見つけることです$k$これにより、ペアリングの制約を尊重しながら、必要なすべてのセルをペイントできるようになります。 

入力には、ペイントする必要があるセルが昇順に並べてリストされます。 出力は単一の整数です$k$テストケースごとに。 この制約は、セルの数を意味します。$n$テスト ケースあたりの数は最大 2000 であり、すべてのテスト ケースの合計は 2000 を超えません。これにより、次のようなアルゴリズムを実行できます。$O(n \log n)$あるいは$O(n^2)$操作の絶対数は管理可能なままであるためです。 セル位置の大きな値（最大）$10^{18}$、ストリップの直接の配列表現またはシミュレーションを排除します。 セルのインデックスに比例するメモリを使用するのではなく、数値自体を操作する必要があります。 

エッジケースとしては、必要なセルが連続している場合、セルがまばらで大きなギャップがある場合、および$n=1$必要なセルが 1 つだけあり、セルが等間隔に配置されている場合、追加のオプションのセルを考慮しないと左から右への単純なペアリングが失敗する可能性があります。 たとえば、次の場合$a=[1,3]$、最小限の$k$2 つのセルは距離 2 離れているため、2 になります。 常に連続するセルをペアにする不注意なアプローチでは、誤って 1 が返される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、ペイントプロセスをシミュレートして、値を増加させようとします。$k$、考えられるすべてのペアリングをチェックし、追加のセルが最大 1 つだけ使用されていることを確認します。 これは原理的には正しいですが、$n$最大 2000、すべてのペアリングをシミュレートするには$O(n^2)$あたり$k$、そして最大$k$セルが遠く離れている場合は非常に大きくなり、計算が実行不可能になる可能性があります。 

重要な洞察は、問題を貪欲で建設的な戦略に帰着できるということです。 与えられた$k$、左から右へ順番にセルをペアリングしてみることができます。 次のペアになっていないセルが範囲内にある場合$k$次のセルの、それらをペアにします。 そうでない場合は、オプションの追加セルを使用してギャップを埋める必要がある場合があります。 これにより、候補を確認することができます$k$線形時間で$O(n)$。 この決定関数を定義すると、二分探索を使用できるようになります。$k$0 から必要なセル間の最大距離までを計算し、実現可能な最小値を見つけます。$k$。 左から右への貪欲なペアリングで十分であるという観察は、連続するギャップのみが重要であり、オプションの追加セルは最大 1 回しか使用できないという事実に依存しています。

 ## アルゴリズムのチュートリアル

 1. 必要なセルのリストを並べ替えます。 これは入力によって保証されますが、正確性が保証されます。 
2. ヘルパー関数を定義する`check(k)`必要なすべてのセルを指定された値でペイントできる場合は True を返します。$k$。 最初のセルのポインタと、オプションの追加セルが使用されているかどうかを示すフラグを初期化します。 
3. セルを順番に繰り返します。 ペアになっていないセルごとに、次のセルとペアリングしてみます。 距離が最大でも$k$、それらをペアにして、ポインタを 2 進めます。 
4. 次のセルが遠すぎる場合は、オプションの追加セルの使用を検討してください。 まだ使用されていない場合は、ギャップを埋めるためにそれを「消費」し、1 つ進めてオプションを使用済みとしてマークします。 
5. ペアリングが失敗し、オプションの追加セルがすでに使用されている場合は、False を返します。 
6. すべてのセルが正常にペアリングされた場合は、True を返します。 
7. 二分探索を実行します。$k$0 から必要なセル間の最大可能距離まで。 中間点ごとに、次の呼び出しを行います。`check(k)`下を検索するか上位を検索するかを決定します。 
8. 最小限のものを出力する$k$誰のために`check(k)`True を返します。 

不変条件とは、与えられた条件に対して$k$、貪欲なペアリングは最も左側のペアになっていないセルを消費し、ギャップが大きすぎる場合は、単一の余分なセルが 1 回だけ使用されます。 どのような構成でも削減することはできません$k$距離制約に違反することなく、さらに小さくすることができます。$k$オプションのセルでは埋めることができないギャップが少なくとも 1 つ残ることになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        def check(k):
            used_extra = False
            i = 0
            while i < n:
                if i + 1 < n and a[i + 1] - a[i] <= k:
                    i += 2
                elif not used_extra:
                    used_extra = True
                    i += 1
                else:
                    return False
            return True
        
        lo, hi = 0, a[-1] - a[0]
        while lo < hi:
            mid = (lo + hi) // 2
            if check(mid):
                hi = mid
            else:
                lo = mid + 1
        print(lo)

if __name__ == "__main__":
    solve()
```各部分はアルゴリズムのステップに直接対応します。 並べ替えは入力に暗黙的に含まれます。 の`check`関数はセルを貪欲にペアリングし、最初のブリッジ不可能なギャップでオプションの追加セルを消費します。 二分探索により最小性が保証されます。 使用する`a[-1] - a[0]`の上限として`k`それを超える隙間はないので安全です。 取り扱い`i+1 < n`インデックスエラーを防ぎます。 の`used_extra`フラグは、オプションのセルが最大 1 回使用されることを保証します。
