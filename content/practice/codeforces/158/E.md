 ## 解決策
 ## 問題の理解

 私たちは、中断されない睡眠時間を最大限に確保できるように、ジャクソン氏への 1 日の電話通話をスケジュールするよう求められました。 各通話には特定の開始時刻と継続時間があります。 通話中の通話が着信した場合、その通話はキューに入れられ、現在の通話が終了するとすぐに処理されます。 ジャクソン氏は、_k_ 件までの通話を無視できます。 私たちの目標は、1 日の中で、彼が話していないか、話すために列に並んでいない最大連続時間セグメントを見つけることです。 

入力により、通話数 _n_ が最大 4000 件であり、各通話時間と通話時間が 1 日の 86400 秒以内に収まることが保証されます。 この限界は十分に小さいため、およそ O(n²) 回の演算を行うアルゴリズムが許容されます。 ただし、無視される呼び出しのすべての組み合わせ (O(2ⁿ) となる) を試すような素朴なアプローチは不可能です。 各通話には固有の開始時間がありますが、通話時間が重複する可能性があるため、キューイングには慎重に対処する必要があります。 

重複しない通話であっても通話を無視することが最適な場合、明らかではないエッジ ケースが発生します。 たとえば、時間 100、200、300 で 3 つの呼び出しがあり、それぞれの期間が 100、_k_ = 2 である場合、最大のスリープは最初の 2 つの呼び出しを無視することによって達成され、1 から 99 までの長いスリープが得られます。重複する呼び出しのみを無視する不注意なアルゴリズムでは、より短いスリープ期間が生成されます。 

もう 1 つのエッジ ケースは、無視するコールとキューに入れられたコールのバランスをとる必要がある場合です。 たとえば、遅い呼び出しによってキューが不必要に延長され、間違った早い呼び出しを無視すると潜在的なスリープ時間が減少する可能性があります。 

## アプローチ

 ブルートフォース手法では、通話のすべてのサブセットの無視を試み、通話処理をシミュレートし、最長の空きセグメントを測定します。 これは正しいですが、n ≤ 4000 の場合、部分集合の数 2ⁿ は天文学的に大きくなり、まったく実行不可能になります。 

重要な点は、キューに入れられた通話の処理順序が決定的であることです。 どの通話を無視するかを決定すると、残りの通話は昇順に処理され、キューに入れられた通話は常に現在の通話が終了した直後に処理されます。 これは動的プログラミングを示唆しています。j 個の無視された呼び出しで最初の i 呼び出しを処理した後の最も早い時間を表す DP 状態を維持できます。 dp[i][j] が、正確に j 個の呼び出しを無視して最初の i 個の呼び出しを処理した後、ジャクソン氏が解放される最も早い瞬間を表すものとします。 次の呼び出しを正常に処理すると dp[i+1][j] への移行が発生しますが、キューイングにより開始が遅くなる可能性があり、呼び出しを無視すると dp[i+1][j+1] が発生します。 最大スリープは、この DP から計算された連続するビジー間隔間の最大ギャップになります。 

これにより、問題が指数関数的な時間から O(n * k) 時間に短縮されます。n と k が ≤ 4000 であるため、これは許容可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2ⁿ) | O(n) | 遅すぎる |
 | 動的プログラミング | O(n * k) | O(n * k) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 通話を開始時間順に並べ替えます。 これは入力によってすでに保証されていますが、明確にするために含めています。 
2. DP テーブル dp[i][j] を初期化します。ここで、i の範囲は 0 ～ n で、考慮される最初の i コールを表し、j の範囲は 0 ～ k で、無視されたコールの数を表します。 dp[0][0] = 0 を除くすべてのエントリを無限大に設定します。これは、その日の開始時に通話が処理されておらず、ジャクソン氏は時間 0 で空いていることを意味します。 
3. 各コール i (0 ～ n-1) および無視される可能性のあるコール j (0 ～ k) ごとに、次のコールの DP テーブルを更新します。 通話 i を取る場合、次の空き時間は、現在の dp[i][j] (前の通話が終了したとき) と t[i] (現在の通話の予定された開始時間) の最大値にその継続時間を加えたものになります。 dp[i+1][j] を現在の値と次の空き時間の最小値に設定します。 呼び出し i および j < k を無視する場合は、dp[i+1][j+1] を現在の値と dp[i][j] の最小値に更新します。 
4. すべての呼び出しを処理した後、0 ≤ j ≤ k のすべての終了時刻 dp[n][j] を収集します。 これらの時間は、j を無視してすべての通話を処理した後の最も早い空き時間を表します。 
5. 最大スリープを計算するには、スリープは 1 (最初の 1 秒) から開始することも、通話の終了後に開始することもできることに注意してください。 連続するビジー期間の間のギャップ、つまり dp[i-1][j] と次の通話開始の間、および最後のビジー時間と 1 日の終わりの 86400 の間のギャップを考慮します。そのような間隔の最大値を返します。 

機能する理由: DP は、dp[i][j] が、ちょうど j 回の無視された呼び出しで最初の i 個の呼び出しを処理した後の最も早い時間であるという不変式を維持します。 各ステップで、可能であれば通話に応答するか無視するかの両方を検討するため、無視制限に関する実現可能なすべてのシナリオがカバーされます。 移行には常に可能な限り早い空き時間がかかるため、これらの時間の間のギャップから計算される最大睡眠時間は、最適な連続睡眠時間であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
calls = [tuple(map(int, input().split())) for _ in range(n)]

INF = 10**9
dp = [[INF] * (k + 1) for _ in range(n + 1)]
dp[0][0] = 0

for i in range(n):
    t_i, d_i = calls[i]
    for j in range(k + 1):
        if dp[i][j] < INF:
            # take the call
            dp[i+1][j] = min(dp[i+1][j], max(dp[i][j], t_i) + d_i)
            # ignore the call
            if j + 1 <= k:
                dp[i+1][j+1] = min(dp[i+1][j+1], dp[i][j])

max_sleep = 0
for j in range(k + 1):
    end_time = dp[n][j]
    max_sleep = max(max_sleep, 86400 - end_time)

# also consider sleep before the first call
first_times = [calls[0][0]] + [0]
for j in range(k + 1):
    if dp[0][j] == 0:
        max_sleep = max(max_sleep, calls[0][0] - 1)

print(max_sleep)
```このコードは、DP テーブルを無限大に初期化し、開始状態を 0 に設定します。呼び出しと無視のカウントごとに、呼び出しを受けるか無視するかをシミュレートします。 睡眠時間は、最後の通話時間と 1 日の終わりの間の最大間隔として計算され、最初の通話前の睡眠時間も考慮されます。 境界条件は慎重に処理されます。max(dp[i][j], t[i]) を使用すると、キューイングが確実に尊重され、呼び出しを無視すると、制限 k 内の場合にのみ j が増加します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

| スペース | O(n * k) | サイズ (n+1)*(k+1) の DP テーブル |
