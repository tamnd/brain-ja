 ## 解決策
 ## 問題の理解

 プログラミングコンテストの最終順位が与えられました。 スコアはすでに非昇順に並べ替えられています。つまり、各参加者のスコアが次の参加者以上であることを意味します。 

2 つの条件が true の場合、参加者は次のラウンドに進みます。 彼らのスコアは、現在 k 番目の位置にいる参加者のスコアと少なくとも同じでなければならず、彼らのスコアは正でなければなりません。 

タスクは、両方の条件を満たす参加者の数をカウントすることです。 

制約は非常に小さいです。 参加者は最大でも 50 人なので、単純なリニア スキャンでも十分です。 時間計算量が O(n²) までのアルゴリズムは、問題なく制限内に収まります。 この問題は、最適化ではなく、主に慎重な実装に関するものです。 

難しい部分は、ゼロ スコアと k 番目の位置付近の同点を正しく処理することです。 

次の例を考えてみましょう。```
5 3
10 5 0 0 0
```3 番目の参加者のスコアは 0 です。不注意な解決策では、スコアが 0 以上の全員がカウントされ、5 が生成される可能性があります。参加者もプラスのスコアを持つ必要があるため、これは誤りです。 正解は 2 です。 

多くの参加者が k 番目の参加者と同じスコアを共有する場合、別の微妙なケースが発生します。```
8 5
10 9 8 7 7 7 5 5
```5 位の参加者のスコアは 7 です。6 位の参加者を含む、スコア 7 以上の全員が進みます。 正解は 6 です。実装が間違っていると単純に k を出力する可能性があり、同点の参加者を見逃してしまいます。 

もう 1 つのエッジ ケースは、可能な最小の入力です。```
1 1
0
```唯一の参加者が 0 点を獲得したため、誰も先に進みません。 The answer is 0, not 1.

 ## アプローチ

 最も直接的なアプローチは、すべての参加者を検査し、コンテストのルールを満たしているかどうかを確認することです。 まず、k 番目の参加者のスコアを見つけて、次に、両方ともプラスであり、少なくともそのしきい値以上のスコアがいくつあるかを数えます。 

This brute-force method is already completely acceptable because n is at most 50. In the worst case, we perform around 50 comparisons, which is effectively instantaneous.

 入力はすでにソートされているため、より複雑なアプローチは必要ありません。 必要な唯一の観察は、k 番目の参加者が最小資格スコアを定義するということです。 その値がわかれば、すべての参加者を個別にチェックできます。 

資格ルールは 1 つの固定しきい値のみに依存するため、ブルート フォースが機能します。 検索、並べ替え、または追加のデータ構造は必要ありません。 1 回のリニア スキャンで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. Read the integers`n`そして`k`。 
2. スコアの配列を読み取ります。 
3. k 番目の位置の参加者のスコアを見つけます。 Python は 0 から始まるインデックスを使用するため、この値は次のようになります。`scores[k - 1]`。 
4. カウンタを 0 に初期化します。 
5. 配列内のすべてのスコアを反復処理します。 
6. 各スコアについて、次の 2 つの条件を確認します。 

1. スコアが k 番目のスコア以上である。 
2. スコアは厳密に 0 より大きくなります。 
7. 両方の条件が真の場合、カウンタをインクリメントします。 
8. 最終カウンターを出力します。 

2 番目の条件が必要なのは、たとえ k 番目の参加者のスコアが 0 であっても、スコア 0 の参加者は決して先に進めないからです。 

### なぜ効果があるのか

 k 番目の参加者が資格を得るために必要な最低スコアを確立します。 スコアが小さい参加者は先に進むことができません。 スコアがプラスであれば、同じスコアまたはそれ以上のスコアを持つ参加者が資格を得ることができます。 

アルゴリズムは、すべての参加者に対してこれら 2 つのルールを正確にチェックします。 適格な参加者はすべて 1 回カウントされ、適格でない参加者はすべて無視されるため、最終的なカウントは正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
scores = list(map(int, input().split()))

threshold = scores[k - 1]

answer = 0

for score in scores:
    if score >= threshold and score > 0:
        answer += 1

print(answer)
```プログラムは、参加者数と予選順位を読み取ることから始まります。 スコアはリストに保存されます。 

変数`threshold`k 番目の参加者のスコアを保存します。 これは昇進に必要な最低スコアです。 

ループは各参加者を個別に処理します。 条件:```
score >= threshold and score > 0
```コンテストのルールに正確に一致します。 

最初の部分ではタイが正しく処理されます。 複数の参加者が k 番目の参加者と同じスコアを共有する場合、全員がカウントされます。 

2 番目の部分では、スコアがゼロの参加者は先に進むことができません。 これは間違いを引き起こす可能性が最も高い詳細です。 

実装では以下を使用します`k - 1`Python リストのインデックスは 0 から始まるのに対し、コンテストの順位は 1 から始まるためです。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n, k = map(int, input().split())
    scores = list(map(int, input().split()))

    threshold = scores[k - 1]

    ans = 0

    for score in scores:
        if score >= threshold and score > 0:
            ans += 1

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided samples
assert run("8 5\n10 9 8 7 7 7 5 5\n") == "6\n", "sample 1"

# custom cases
assert run("1 1\n0\n") == "0\n", "minimum size with zero"
assert run("1 1\n100\n") == "1\n", "minimum size with positive score"
assert run("5 3\n10 5 0 0 0\n") == "2\n", "zero threshold handling"
assert run("6 4\n5 5 5 5 5 5\n") == "6\n", "all equal values"
assert run("5 5\n9 7 5 3 1\n") == "5\n", "k equals n"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`1 1 / 0`|`0`| スコアがゼロの 1 人の参加者 |

 ## 特殊なケース

 k 番目の参加者のスコアが 0 である場合を考えてみましょう。 

入力:```
5 3
10 5 0 0 0
```3 位の参加者のスコアが 0 であるため、しきい値は 0 になります。 

アルゴリズムはすべての参加者をチェックします。```
10 >= 0 and 10 > 0  -> counted
5 >= 0 and 5 > 0    -> counted
0 >= 0 and 0 > 0    -> not counted
```最終的な答えは 2 です。`score > 0`この条件により、誤ったカウントが防止されます。 

次に、カットオフの周りの関係を考えてみましょう。 

入力：```
8 5
10 9 8 7 7 7 5 5
```しきい値は 7 です。アルゴリズムは、スコアが 7 以上であるすべての参加者をカウントします。 

これには、次の理由から 6 位の参加者が含まれます。```
7 >= 7 and 7 > 0
```それは本当です。 

最終的な答えは 6 となり、同点のスコアが正しく処理されます。 

最後に、可能な限り最小の入力を調べます。 

入力：```
1 1
0
```しきい値は 0 です。唯一の参加者がプラススコア条件に失敗するため、カウンターは増加しません。 出力は 0 で、ルールに正確に一致します。
