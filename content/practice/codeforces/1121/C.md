 ## 解決策
 ## 問題の理解

 コンテスト設定での並列システム テストをモデル化する状況があります。 がある`n`コンテストに提出されたソリューション。 それぞれのソリューション`i`必要`a[i]`テストを完全に検証する必要があります。 がある`k`独立したテスト プロセス。それぞれが一度に 1 つのソリューションを実行でき、1 秒ごとに 1 つのテストを順番に実行します。 ソリューションは送信された順序で選択されます。テスト プロセスがアイドル状態になると、キューから次のソリューションが取得され、順番にテストの実行が開始されます。 

Vasya は、完全にテストされたソリューションの数を示すパーセンテージ キャプションを通じてテスト ステータスを監視します。`m`解決策が完了すると、ディスプレイに次のように表示されます`round(100*m/n)`。 テスト中に表示されるパーセンテージが現在のテスト番号と正確に一致する場合、そのソリューションは「興味深い」と言えます。 

制約は中程度です。`n`最大1000であり、`k`各ソリューションには最大 150 個のテストを含めることができます。 これは、すべてのテスト瞬間を計算する完全な総当たりシミュレーションが実現可能であることを意味します。`1000*150 = 150,000`1 秒以内の制限内で許容されます。 

複数のプロセスが同時にアイドル状態になると、明らかではないエッジケースが発生します。 たとえば、次の場合`k`を超える`n`、一部のプロセスはアイドル状態で開始され、解決策が選択されません。 もう 1 つの微妙なケースは、ソリューションが最後のテストを終了した時点でパーセンテージが急上昇する場合に発生します。 分数モーメントを考慮する必要があります (`t + 0.5`) 整数の 2 番目の境界だけでなく、キャプションが変更されたとき。 たとえば、ソリューションに 49 個のテストがあり、別のプロセスが 49 秒目に完了した場合、次のソリューションではテスト中に表示が変更される可能性があります。 整数秒のみをチェックする単純なアプローチでは、これらの状況を見逃してしまいます。 

## アプローチ

 ブルートフォースアプローチでは、各テストプロセスを毎秒シミュレートし、完全にテストされたソリューションの数を維持し、キャプションが実行中のソリューションのテスト番号と等しいかどうかを確認します。 これは正しいですが、ネストされたループが必要です。つまり、各ソリューションの各テストの 1 秒ごとに 1 つずつループが必要になります。 最悪の場合、それぞれ 150 のテストを含む 1000 のソリューションでは 150,000 回の反復が行われます。これは Python では問題ありませんが、やや洗練されていません。 

効率的でクリーンなソリューションを実現するための重要な洞察は、各ソリューションの開始時間と終了時間を追跡し、ソリューションが終了した瞬間にのみ表示の変化の割合を計算することです。 テストを毎秒シミュレートする代わりに、キャプションが区分的に一定であり、ソリューションの完了時にのみ変更されると推論できます。 各ソリューションについて、テストの間隔を計算し、この間隔内の四捨五入されたパーセンテージが現在のテスト数と等しいかどうかを確認できます。 

これにより概念的に複雑さが軽減され、シミュレーションがより明確になります。 制約により許可されているため、テストごとに単純な時間ベースのシミュレーションを実装することはできますが、更新には細心の注意が必要です。`m`(完全にテストされたソリューションの数) を正しく計算してください`round(100*m/n)`適切な瞬間に。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(合計(a_i)) | O(n) | 承認済み |
 | 最適化された間隔チェック | O(n log n + sum(a_i)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力値の読み取り`n`そして`k`、および配列`a`各ソリューションのテストの数を表します。 
2.初期化`finish_times`すべての配列`k`各プロセスがいつアイドル状態になるかを追跡するために、プロセスをテストします (最初はゼロ)。 
3. 提出順の各ソリューションについて、最も早い利用可能なテスト プロセスに割り当てます。 開始時刻をそのプロセスの現在の終了時刻として計算し、終了時刻を次のように計算します。`start + a[i]`。 
4. このソリューションのすべてのテスト (1 から 2 まで)`a[i]`)、テストが開始されたときの端数部分の時間を計算します。 完全に完了したソリューションの数を計算する`m`この瞬間までに、この小数時間前に完了したソリューションの数を数えることによって計算します。 ラウンド`100*m/n`キャプションを取得します。 キャプションが現在のテスト番号と等しい場合は、その解決策を興味深いものとしてマークし、次の解決策に進みます。 
5. すべてのソリューションが割り当てられ、処理されるまで続行します。 
6. 興味深い解をすべて数えて、合計を出力します。 

なぜ機能するのか: 維持される不変条件は、どの瞬間でも`t`ソリューションのテスト期間内で、完了したソリューションの数`m`は、終了時間が より短いソリューションの正確な数です。`t`。 キャプションのみに依存するため、`m`、各テストの瞬間をチェックすることで、ソリューションが興味深い可能性があるすべてのポイントを確実に把握できます。 テストを順番に繰り返すことにより、最初にキャプションが現在のテスト番号と一致するだけで、解決策をマークするのに十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

# track when each process is free
proc_free = [0]*k
finish_times = []

for tests in a:
    idx = min(range(k), key=lambda x: proc_free[x])
    start = proc_free[idx]
    end = start + tests
    proc_free[idx] = end
    finish_times.append((start, end, tests))

interesting = 0

for start, end, tests in finish_times:
    for t in range(1, tests+1):
        moment = start + t - 0.5  # middle of the test
        completed = sum(1 for s, e, _ in finish_times if e <= moment)
        caption = int((100*completed/n)+0.5)
        if caption == t:
            interesting += 1
            break

print(interesting)
```このコードはまず、追跡することによって各ソリューションを次に使用可能なテスト プロセスに割り当てます。`proc_free`。 次に、各ソリューションについて、各テストの瞬間をチェックします (分数中間を使用)`t - 0.5`) すでに完了したソリューションの数をカウントします。 四捨五入されたパーセンテージが現在のテスト番号と等しい場合、興味深いものとしてマークされます。 早めにブレイクすることで、各ソリューションを 1 回だけカウントすることが保証されます。

## 複雑さの分析

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    proc_free = [0]*k
    finish_times = []
    for tests in a:
        idx = min(range(k), key=lambda x: proc_free[x])
        start = proc_free[idx]
        end = start + tests
        proc_free[idx] = end
        finish_times.append((start, end, tests))
    interesting = 0
    for start, end, tests in finish_times:
        for t in range(1, tests+1):
            moment = start + t - 0.5
            completed = sum(1 for s, e, _ in finish_times if e <= moment)
            caption = int((100*completed/n)+0.5)
            if caption == t:
                interesting += 1
                break
    return str(interesting)
