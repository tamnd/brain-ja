 ## 解決策
 ## 問題の理解

 数直線上のセグメントの集合が与えられ、各セグメントは 2 つの偶数の整数の間にまたがります。 タスクは、すべてのセグメントに選択した点が 1 つだけ含まれるように、一連の点を同じ線上に配置すると同時に、選択したすべての点が少なくとも 1 つのセグメント内に存在するようにすることです。 

これにより、セグメントとポイントの間に緊密な結合が作成されます。 各セグメントは 1 つのポイントを排他的に「要求」する必要がありますが、ポイントが複数のセグメントに提供されるのは、それらのセグメントが依然としてそれぞれ 1 つのポイントだけになる場合にのみ許可されます。 領域内にポイントを配置すると複数の重なり合うセグメントを満たす可能性があり、その結果「セグメントごとに 1 つだけ」ルールに違反する可能性があるため、カバレッジと排他性のバランスをとることが困難になります。 

座標空間の範囲は 0 ～ 4n − 2 と狭いですが、n 自体は 200000 に達する可能性があります。これにより、候補点の位置を個別に探索したり、セグメントのすべてのサブセットをチェックしたりするソリューションは除外されます。 2e5 の 2 乗はすでに実行可能な限界を数桁超えているため、n の二次関数は遅すぎます。 偶数のエンドポイントの構造は、連続する整数を個別のスロットとして扱うことができるというヒントであり、間隔に関する組み合わせ論に対する幾何学的直観を効果的に軽減します。 

セグメントが完全にネストされている場合、微妙な障害が発生することがあります。 たとえば、セグメント [0, 10]、[2, 8]、[4, 6] を考えてみましょう。 最小セグメント内の 1 つの点は 3 つのセグメントすべてに含まれており、各セグメントに 1 つの点が含まれているという要件が直ちに破られます。 これは、セグメント内の任意の点を選択するだけでは不十分であることを示しています。 重複が「正確に 1 つ」の制約と一致しない限り、複数のセグメントを同じ点に積み重ねることを慎重に避ける必要があります。 

もう 1 つのエッジ ケースは、セグメントがチェーン状に重なっているにもかかわらず、明確な代表点を一貫して割り当てることができない場合に発生します。 たとえば、2 つのセグメントが同一である場合、たとえば [0, 4] と [0, 4] の場合、両方に一意の点が必要になるため不可能ですが、[0, 4] 内の点は両方のセグメントに属し、セグメントごとの一意性に違反します。 

## アプローチ

 直接的な試みは、各セグメントに独立してポイントを割り当てることです。 各セグメントについて、その内部の可能な座標をすべて試して、そこに点を配置することで以前のすべての制約が有効であるかどうかを確認できます。 新しいポイントが誤って以前の複数のセグメントに存在し、追加のポイントを獲得する可能性があるため、これはすぐに以前に配置されたすべてのポイントとの互換性をチェックすることになります。 

最悪の場合、実行可能性を確保するために各配置ですべての既存のセグメントまたはポイントをスキャンする必要があり、O(n²) プロセスが必要になります。 セグメントが 200,000 個になると、これは完全に不可能になります。 

重要な観察は、実現可能性は基本的に順序付けの制約に関係するということです。 点が配置されると、線が分割され、どのセグメントがすでに満たされているかが暗黙的に決定されます。 任意の配置という観点から考える代わりに、セグメントを離散的な候補位置に一致させるという観点から考えることができます。 

すべてのエンドポイントが偶数であるため、ラインを整数スロットとして解釈し、貪欲なマッチング戦略を使用できます。つまり、セグメントを右のエンドポイントの昇順に処理し、以前に割り当てられたセグメントに違反しない、利用可能な左端の有効な位置を各セグメントに割り当てます。 これにより、問題は、割り当て制約を伴うインターバル スケジューリングの変形に変換されます。 

これが機能する理由は、可能な限り早い有効な位置を選択すると、後のセグメントの柔軟性が保たれるためです。 セグメント内への配置を遅らせると、利用可能な範囲が狭くなる将来のより狭いセグメントがブロックされる危険があります。

 ## アルゴリズムのチュートリアル

 1. すべてのセグメントを右のエンドポイントで昇順に並べ替えます。 これにより、セグメントを処理するときに、それより前にすべての以前のセグメントが確実に終了します。 先に終了する制約が最初に満たされる必要があるため、順序付けは不可欠です。 
2. ライン上のどの位置がすでに点として使用されているかを追跡するデータ構造を維持します。 座標は離散的で有界であるため、単純なブール配列または素セット スタイルの「次に利用可能な位置」構造にすることができます。 
3. ソートされた順序でセグメントを反復処理します。 各セグメント [L, R] について、[L, R] 内のまだ使用されていない最小の位置 x を検索します。 
4. そのような位置が存在しない場合は、直ちに失敗を返します。 これは、セグメント内のすべての候補位置が前のセグメントに割り当てられたポイントによってすでに占有されていることを意味するため、このセグメントはポイントを共有することを強制され、「セグメントごとに 1 つだけ」という要件に違反します。 
5. そのような位置 x が存在する場合は、x に点を割り当て、それを使用済みとしてマークします。 
6. すべてのセグメントが処理されるまで続行し、選択したすべてのポイントを出力します。 

重要な実装の詳細は、範囲内の次の未使用の位置を効率的に見つけることです。 単純なスキャンは O(n²) になるため、代わりに、各位置が次の空きスロットを指す Union-find 構造を使用します。 位置が使用されると、それを次の位置と結合し、以降のクエリではその位置を事実上スキップします。 

### なぜ効果があるのか

 貪欲な選択により、すべてのセグメントにできるだけ早く個別の代表位置が割り当てられるようになります。 セグメントは右のエンドポイントを増やすことによって処理されるため、セグメントに選択された位置は可能な限り左に配置され、後のセグメントのための最大の余地が残されます。 Union-Find 構造により、位置が再利用されないことが保証されるため、2 つのセグメントが同じポイントを共有することはありません。 セグメントがその範囲内で空き位置を見つけられない場合は、考えられるすべての代表がすでに以前のセグメントにコミットされていることを意味し、割り当てによって重複が強制されるため、構成が不可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def find(x, parent):
    if parent[x] != x:
        parent[x] = find(parent[x], parent)
    return parent[x]

def union(x, parent):
    parent[x] = find(x + 1, parent)

def solve():
    n = int(input())
    seg = [tuple(map(int, input().split())) for _ in range(n)]
    
    seg.sort(key=lambda x: x[1])
    
    maxv = 4 * n + 5
    parent = list(range(maxv))
    
    res = []
    
    for l, r in seg:
        x = find(l, parent)
        if x > r:
            print(-1)
            return
        res.append(x)
        union(x, parent)
    
    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```コードは、最も制限されたセグメントが常に最初に処理されるように、正しいエンドポイントでセグメントを並べ替えることから始まります。 Union-find 構造体は親配列を通じて実装され、指定された座標以降の次に利用可能な位置を追跡します。 

の`find`この関数はパス圧縮を実行し、繰り返されるクエリが次の空きスロットにすぐにジャンプできるようにします。 ポジションを割り当てたら`x`セグメントにリンクすると、すぐに利用可能から「削除」されます。`x + 1`。 これにより、2 つのセグメントが同じ座標を再利用することがなくなります。 

重要なチェック`if x > r`最初に使用可能な位置がすでにセグメントの外側にある場合、有効な配置は存在しないことが保証されます。

 ## 特殊なケース

 完全にネストされた構造は、貪欲な割り当てによって後のセグメントのトラップが回避されるかどうかをテストします。 [0,10]、[2,8]、[4,6] などの入力の場合、アルゴリズムは 0、次に 2、次に利用可能な場合は 4 を割り当てますが、より厳密な構成では、最も内側のセグメントに新しいスロットが存在しない場合に失敗します。 Union-Find メカニズムにより、座標が一度消費されると再利用できなくなり、偶発的な重複が防止されます。 

同一のセグメントは、アルゴリズムがそれらを 1 つの制約に誤ってマージしていないかどうかをテストします。 繰り返される [0,2] セグメントの場合、それぞれが個別のポイントを受け取る必要があります。 結合ステップにより次の自由位置への前進が強制され、分離が確実になります。 

[0,2]、[2,4]、[4,6] などの緊密にチェーンされたセグメントは、境界共有によって競合が発生しないことを確認します。 座標は個別のスロットとして扱われ、割り当てごとに可用性がすぐに向上するため、共有エンドポイントは再利用違反なく一貫して処理されます。
