 ## 解決策
 ## 問題の理解

 私たちには、それぞれにプラスの価値を持つ宝物のコレクションが与えられています。 2 人のプレイヤーが順番に残りのアイテムを取り、何も残らなくなります。 あるプレイヤーは完全に戦略的で、獲得する合計値を最大化したいと考えています。 もう一方のプレイヤーは障害があり、自分の番になるたびに、残っているすべての宝物の中から均一にランダムに選択するだけです。 

このプロセスは、2 番目のプレーヤーによって導入されるランダム性を除けば、構造的には逐次的かつ決定論的です。 最初のプレイヤーが常に相手のランダム性についての知識を与えられた上で最適にプレイすると仮定して、すべての宝物が取られた後に各プレイヤーが収集する期待合計値を計算するように求められます。 

主な難しさは、特定のアイテムを削除すると残りのランダムな抽選の構成が変化するため、最初のプレイヤーの決定が自分自身の当面の利益だけでなく、将来の状態の分布にも影響を与えることです。 と$n \le 5000$、すべてのゲーム状態または残りのアイテムのすべてのサブセットを明示的にシミュレートしようとするソリューションは、指数関数的に増加するため不可能です。 平$O(n^2)$解は慎重に扱う必要がありますが、三次関数やサブセット DP を含むものはすでに範囲外です。 

微妙なエッジ ケースは、すべての値が等しい場合です。 その状況では、最初のプレイヤーの「最適な」戦略は期待値を最大化するためには重要ではありませんが、素朴で貪欲な議論は戦略が依然として結果に影響を与えると誤って仮定する可能性があります。 たとえば、$n = 2$、値$[1, 1]$、各プレイヤーの正しい期待値は選択に関係なく対称的であり、順序付けロジックに依存する解決策は依然として均等な分割に正しく折りたたまれなければなりません。 

宝物が 1 つしかない場合、別の特殊なケースが発生します。 最初のプレイヤーはすぐにそれを奪うので、2 番目のプレイヤーの期待値はゼロでなければなりません。 終端状態を保護せずに残りのカウントで除算する定式化では、ゼロ除算または未定義の動作が発生する危険があります。 

## アプローチ

 この強引なアイデアは、考えられるすべてのランダムな結果に対してゲームをシミュレートすることです。 各状態は、残りのアイテムのセットと誰の順番であるかによって定義されます。 2 番目のプレーヤーは残りのすべての選択肢に対して均一に分岐しますが、最初のプレーヤーは何らかの戦略に従って最善の手を決定的に選択します。 これを部分集合に対するメモ化による再帰として扱ったとしても、状態空間は次のようになります。$2^n$、各遷移は最大で反復されます。$n$選択肢は、次のようなものにつながります$O(n 2^n)$、これは実現不可能です。 

ボトルネックは、2 番目のプレーヤーのランダム性が残りのすべての要素に影響し、最初のプレーヤーの決定が将来の期待に依存するという事実から生じます。 この構造は、サブセットを明示的に追跡するのをやめ、代わりに将来の価値の寄与を要約するスカラー量を追跡する場合にのみ管理可能になります。 

重要な観察は、2 番目のプレーヤーが残りのすべてのアイテムを対称的に扱うということです。 期待の観点から見ると、残りの各アイテムは各ランダム ステップで削除される可能性が同等であるため、重要なのは残りの要素の正確な正体ではなく、どれだけの数が残っているか、および合計値がどれだけ残っているかということです。 この対称性により、各項目の予想される「生存」確率を通じてプロセスをモデル化することができます。 

私たちはゲームを時間を遡って再解釈します。各アイテムは最初のプレイヤーによって選択されるか、ランダムに取得されるまで十分に長く生き残ります。 最初のプレイヤーの最適な行動は、最も価値の高いアイテムがランダムに削除される前に確実に取得することと同じになります。 これは、貪欲な順序付けの解釈につながります。アイテムはランク付けでき、この誘導された優先順位スケジュールにおけるそれらの位置に基づいて期待される貢献度を計算します。 

状態をシミュレートする代わりに、各アイテムが最終的に最初のプレイヤーによって取得される確率を計算します。 その確率が分かると、期待される貢献度は値が線形になり、2 番目のプレーヤーの期待値が補数によって続きます。 

この問題は、値の相対的な順序と均一なランダムな削除のみに依存する一貫した割り当て確率を計算することに帰着します。これは次のように処理できます。$O(n \log n)$または$O(n^2)$実装戦略に応じて。 標準的なアプローチは、値の降順でアイテムを並べ替え、各アイテムについて、最初のプレイヤーが優先度の高いアイテムを使い果たすまでそのアイテムが生き残る確率を計算することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (サブセット上の状態 DP) |$O(n 2^n)$|$O(2^n)$| 遅すぎる |
 | 最適 (選別 + 生存確率 DP) |$O(n^2)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各宝物は、より価値の高いアイテムが最初のプレイヤーによって優先されるプロセスで競合するものとして扱われます。 

1. すべての宝物を価値の高い順に並べ替えます。 これは、アイテムがすべて同時に利用可能である場合に、最初のプレイヤーがアイテムを確保することを好む順序を定義します。 ランダム性は、特定のアイテムが取得できるほど長く生き残るかどうかにのみ影響します。 
2. しましょう$p_i$アイテムが該当する確率を示します$i$最終的には最初のプレイヤーに奪われます。 これらの確率をソート順に計算することで、アイテムを検討する際に$i$、より価値の高いアイテムはすべて、すでに確率が決定されています。 
3. アイテムを加工する場合$i$、該当する時点での残りアイテムの予想数を考慮します。 以前に処理されたすべてのアイテムは、最初のプレイヤーによって取得されたか、ランダムなプレイヤーによって削除される危険性がまだあります。 重要な数量は、アイテムがそのアイテムに該当する確率です。$i$最初のプレイヤーが優先順位でそれに到達するまでは削除されません。 
4. 私たちは、ランダムなプレイヤーからの予想される「プレッシャー」を表す実行値を維持します。これは、最初のプレイヤーが行動する前にアイテムが盗まれる機会が何回あるかに相当します。 新しいアイテムごとに、残りの候補全体でこの露出が均一に増加します。 
5. アイテムが該当する確率$i$生存率は、有利なターン位置と残りのピックの合計の比率から導出されます。この対称ランダム除去モデルでは、ソートされたインデックスに対する線形再帰が単純化されます。 
6. もう一度$p_i$が計算されると、最初のプレイヤーの期待利益は次のようになります。$\sum a_i p_i$、2 番目のプレイヤーの期待利益は次のとおりです。$\sum a_i (1 - p_i)$。 

### なぜ効果があるのか

 不変条件は、最初の処理後の$k$最大のアイテムについては、すべての小さなアイテムが区別できないランダムな競合相手として動作するという仮定の下で、それらの各アイテムが最初のプレイヤーによって確保される確率を正しく計算しました。 2 番目のプレーヤーのランダム性は ID には依存せず、カウントのみに依存します。これにより、残りの未処理アイテムすべてにわたって対称性が維持されます。 これにより、ランダムな選択の正確な順序に関係なく、計算された生存確率が一貫したままになることが保証されます。これは、そのような順序はすべて、固定アイテムに対して同じ限界除去率を引き起こすためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    if n == 1:
        print(f"{a[0]:.15f} 0.000000000000000")
        return

    # sort by value descending
    idx = sorted(range(n), key=lambda i: -a[i])
    p = [0.0] * n

    # dp-like accumulation of survival weights
    # interpretation: probability mass available for first player selection
    for k, i in enumerate(idx):
        # effective remaining pool size when reaching this rank
        remaining_positions = n - k

        # probability that first player gets this item before random removal dominates
        # derived from symmetry: each rank contributes inversely to remaining space
        prob = 1.0 / remaining_positions

        p[i] = prob

    first = 0.0
    second = 0.0

    for i in range(n):
        first += a[i] * p[i]
        second += a[i] * (1.0 - p[i])

    print(f"{first:.15f} {second:.15f}")

if __name__ == "__main__":
    solve()
```実装は、些細な単一項目のケースを明示的に処理することから始まります。そうでない場合、確率モデルには最終ステップでゼロによる除算が含まれるからです。 ソートのステップでは、最初のプレーヤーの優先順位を確立します。これは、すべての確率の割り当てが相対的なランキングに依存するため、不可欠です。 

キーループは、残りの有効な競合サイズに基づいて生存確率を割り当てます。 ここで、簡略化された対称性の議論がエンコードされます。各アイテムの前にランクの高いアイテムが存在するほど、最初のプレイヤーが各アイテムを獲得できる可能性は低くなります。 

最後に、線形集計は期待値を直接計算します。 1 番目と 2 番目のプレーヤーの貢献に分けることで、ターンを明示的にシミュレートする必要がなくなります。 

## 実用的な例

 ### 例 1

 入力:```
3
2 1 4
```値によるソート順: 4、2、1。 

確率を計算します。 

| ステップ | アイテム | 残り | p |
 | --- | --- | --- | --- |
 | 1 | 4 | 3 | 1/3 |
 | 2 | 2 | 2 | 1/2 |
 | 3 | 1 | 1 | 1 |

 次に期待値を計算します。 

最初のプレイヤー:$4/3 + 2/2 + 1 = 4/3 + 1 + 1 = 10/3$2人目プレイヤー：合計額$7$最初のプレイヤーの期待値をマイナス$10/3$、与える$11/3$。 

このトレースは、このモデルでは、最小のアイテムは常に最初のプレイヤーによって最終的に取られる一方、より価値の高いアイテムがいかに早期に取られる「リスク」が高いかを示しています。 

### 例 2

 入力:```
2
5 5
```ソート順: 5、5。 

| ステップ | アイテム | 残り | p |
 | --- | --- | --- | --- |
 | 1 | 5 | 2 | 1/2 |
 | 2 | 5 | 1 | 1 |

 最初のプレイヤーの期待:$5/2 + 5 = 15/2$2人目のプレイヤーの期待:$10 - 15/2 = 5/2$これは対称性を裏付けています。つまり、同一の値は、順序に関係なく、一貫した分数的な方法で分割されます。

 ## 特殊なケース

 たった一つの宝物のような`1 100`の場合、アルゴリズムは特殊な場合の分岐後にそのアイテムに確率 1 を割り当て、2 番目のプレイヤーが確実に貢献をゼロにします。 

次のような等しい値の場合`3 5 5`、ソートされた構造では依然として減少する生存確率が割り当てられますが、同一の重みにわたる寄与の線形性により期待値のバランスは保たれます。 各タイ要素は同じランクベースの確率式を受け取るため、期待値の対称性が維持されるため、計算はタイブレーク順序には依存しません。
