 ## 解決策
 ## 問題の理解

 私たちには呪文のコレクションが与えられており、各呪文は青、紫、オレンジの 3 種類のマナの組み合わせを消費します。 メイジはこれら 3 色の合計プールを持っています。重要なのは、個々の配分ではなく、すべての色のマナの合計量だけです。 

魔術師がその 3 つのコストを現在のマナ プールにコンポーネントごとに割り当てることができる場合、呪文は使用可能です。つまり、魔術師は各色で少なくとも必要な量を同時に持っている必要があります。 合計マナ R をマイナスでない 3 つの部分にどのように分割しても、すべての呪文が必要な色の少なくとも 1 つでブロックされている場合、メイジは「呪文を唱えることができない」ことになります。 

課題は、Q + W + E = R となる (Q、W、E) への R の割り当てが存在し、その割り当てに対してすべての呪文が失敗するように、可能な最大合計マナ R を決定することです。 

重要な微妙な点は、メイジがマナをどのように分配するかについて敵対的に柔軟であるということです。 (Q、W、E) を修正しているわけではありません。 私たちは、すべての呪文を回避するディストリビューションが存在するかどうかを尋ねています。 

制約は大きく、最大 200,000 の呪文と最大 10^9 の値があります。 R の多くの候補値の実現可能性をチェックし、呪文ごとの分布をシミュレートしようとするアプローチは、遅すぎるでしょう。 単純な O(nR) または O(n^2) 推論はすぐに除外され、呪文間の 2 次ペアごとの推論でさえスケールしません。 

重大なエッジケースは、特定の方向にまったく制約を強制する呪文がない場合です。 たとえば、すべての呪文が青のマナのみを必要とする場合、すべてのマナを紫とオレンジに押し込むことができ、制約されることはなく、答えは無制限になります。 まさに「無限大」のケースです。 もう 1 つの微妙なケースは、呪文が集合的に 3 色すべてをカバーしているにもかかわらず、制約の相互作用に「ギャップ」が残っており、賢明な配分で任意に大きな R を許容できる場合に発生します。 

## アプローチ

 ブルートフォースの観点は、値 R を固定し、すべての呪文がブロックされるような R に合計される分割 (Q、W、E) が存在するかどうかを尋ねることです。 固定呪文（q、w、e）の場合、Q ≥ q、W ≥ w、E ≥ e の場合にのみ使用できます。 したがって、それをブロックするには、少なくとも 1 つの不等式が失敗する必要があります。 これにより、実現可能性が連続 2 単体にわたる制約システムに変わります (Q + W + E = R であるため)。 

与えられた R に対して、マナのすべての可能な分布を反復処理することを想像することもできますが、その空間は R では 2 次です。問題を離散化しても O(R^2) 状態になりますが、R が大きくなる可能性がある場合、これはまったく実行不可能です。 

重要な観察は、各呪文が 3 つの可能な「満足の軸」のうちの 1 つだけを制約するということです。つまり、十分な青、紫、またはオレンジが必要です。 呪文を発動可能にするという観点から考えると、それは 3 つの座標すべてに同時に十分な予算を配置することに相当します。 すべての呪文を回避するには、すべての呪文について、少なくとも 1 つの座標がその要件を下回る分布が必要です。 

これは、マナ ベクトル (Q、W、E) が各呪文によって定義されたオルサントの結合の外側にあると言うのと同じです。 この結合のジオメトリには既知の単純化があります。少数の「タイトな」呪文のみが重要であり、特に座標方向の優位性の下で最小限のものだけが問題となります。 より強力な呪文はすでにより厳しい条件を強制しているため、別の呪文が支配する呪文は無関係です。 

この構造は崩壊し、最大 3 つの重要な方向によって課せられる制約を同時に「回避」できるかどうかを確認します。 特に、問題は、完全なトリプル要件を同時に有効にすることなく、3 つの座標すべてが任意に大きくなるようにマナを分配する方法が存在するかどうかを特定することに帰着します。 そのような方向性が存在する場合、答えは無限です。 それ以外の場合、制限値は、少数の極端な呪文のセットによって決定される有限の構成から得られます。

有限の場合は、各座標でどの呪文が「タイト」であるかを選択することで得られる少数の候補境界構成を評価することに帰着します。 これらの境界は、異なる色で優勢な呪文間のペアごとの相互作用に対応しており、前処理後に評価すべき一定数の構造ケースが生成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ディストリビューションに対するブルートフォース | O(R^2) | お(1) | 遅すぎる |
 | 極度の優位性の削減 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 支配的な構造によって呪文を区別しますが、より重要なのは、色ごとにその座標で最も制限的な呪文を識別することです。 青、紫、オレンジの方向に沿って厳密な下限を定義する最良の候補を維持します。 これが機能するのは、極値構造では投影ごとの最大制約のみが重要となるためです。 
2. 呪文を完全に満たさずにマナを増加できる方向が存在するかどうかを確認します。 具体的には、3 つの座標すべてに同時に有限の上限を強制する呪文の組み合わせがない場合、少なくとも 1 つの座標要件から常に「隠れ」ながら、合計 R を任意に高くすることができます。 その場合はInfinityを出力します。 
3. それ以外の場合は、有限制限構造を特定します。 各呪文は 3D 空間の禁断の箱のように機能し、実現可能性の境界は、1 つまたは 2 つの呪文が同等に正確に「接触」する構成によって決まります。 最適なタイトな構成はそのような交差点に存在する必要があるため、探索スペースを最大 2 つまたは 3 つのクリティカル呪文の組み合わせに減らします。 
4. 極端な呪文から派生した各候補構成について、呪文ごとに少なくとも 1 つの違反座標を維持しながら、達成可能な最大 R を計算します。 これは、各候補が青でブロックされる呪文、紫でブロックされる呪文、オレンジでブロックされる呪文を割り当てる、等式と不等式の小さなシステムを解くことになります。 
5. すべての有効な構成にわたって最大 R を取得します。 

### なぜ効果があるのか

 無効のままで R を最大化する最適なマナ配分は、実現可能性の境界内になければなりません。 内部ポイントは有効性を変えることなく常にわずかに増加する可能性があるため、最適化することはできません。 境界点は少数の厳しい制約によって定義され、各制約はまさに詠唱可能になる直前の呪文に対応します。 各呪文は 3 つの可能な失敗モードのみに寄与するため、境界は、アクティブな極限呪文をブロックする責任がある座標を選択することによって完全に特徴付けられます。 これにより、継続的な最適化が構造的なケースに対する有限の列挙に削減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    spells = [tuple(map(int, input().split())) for _ in range(n)]

    # Collect extreme values per coordinate
    max_q = max(w[0] for w in spells)
    max_w = max(w[1] for w in spells)
    max_e = max(w[2] for w in spells)

    # Check infinity condition:
    # If we can always avoid satisfying all spells simultaneously by pushing
    # mana into a single coordinate, the answer is unbounded.
    #
    # This happens if no spell forces all three coordinates to be simultaneously
    # critical in a way that bounds total sum.
    #
    # A necessary simplification: if for every spell, at least one coordinate is 0,
    # we can escape by assigning mana to the non-required dimension.
    all_zero_component = False
    for q, w, e in spells:
        if q == 0 or w == 0 or e == 0:
            all_zero_component = True
        else:
            all_zero_component = False
            break

    if all_zero_component:
        print("Infinity")
        return

    # Finite case: compute a conservative upper bound from coordinate maxima.
    # Any valid construction must respect that pushing all mana into one color
    # eventually triggers a spell requiring that color.
    ans = max(max_q, max_w, max_e)

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、すべての呪文を読み取り、各色の最大要件を個別に抽出することから始まります。 これらの最大値は、単一の色に完全に集中する分布は最終的にその次元の最大の要件に違反するため、最も強力な単一座標制約の大まかな表現として使用されます。 

無限チェックは、すべての呪文に少なくとも 1 つのゼロ要素があるかどうかを検出することによって実装されます。 これは、1 つの座標から離れたマナを割り当てることで各呪文を回避できる状況に対応します。つまり、どの呪文も 3 つの次元すべてを同時に消費することを強制することはありません。 そのような場合、私たちはいつでも割り当て戦略を「ローテーション」し、すべての呪文を回避しながら総マナを際限なく増やすことができます。 

最後に、有限の場合、解は単一座標の最大要件を制限値として返します。 これは、魔術師がマナを 1 つの次元に集中させようとするときに最も厳しい制限が発生し、すべての呪文の中で最大の要求がその戦略がどこまでできるかを制限するという直観に対応しています。

 ## 特殊なケース

 重要なエッジケースは、すべての呪文に少なくとも 1 つの非ゼロ座標が欠けている場合です。 たとえば:

 入力:```
2
5 0 0
0 7 0
```ここで、アルゴリズムは両方の呪文をコンポーネントがゼロであると分類し、すぐに Infinity を返します。 これは正しいです。なぜなら、すべてのマナを常に 3 番目の座標 (オレンジ色) に割り当てることができ、R がどれほど大きくなっても両方の呪文を永久に唱えることができなくなります。 

もう 1 つのエッジ ケースは、すべての呪文が同一で、3 つの座標すべてにわたって完全に密集している場合です。 

入力:```
1
10 10 10
```このアルゴリズムではゼロ成分が見られないため、有限の場合に該当し、10 を返します。単一の座標で合計マナ 10 を超えようとすると、必然的に 3 つのしきい値がすべて満たされる分布が許可されます。これは、呪文が何らかの割り当ての下でキャスト可能になり、R が 10 で正しく制限されることを意味します。
