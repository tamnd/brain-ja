 ## 解決策
 ## 問題の理解

 1 から n までのラベルが付いた頂点を持つ無向ツリーが与えられます。 任意の頂点をルートとして選択し、すべてのエッジをそこから離れる方向に向けて、ツリーをルートのある構造に変えることができます。 ルート化後、このルート化されたツリーが二分探索ツリーのように動作するようにします。すべてのノードは最大 2 つの子を持つことができ、通常の順序付けルールがグローバルに適用される必要があります。つまり、ノードの左側のすべてには小さなラベルのみが含まれ、右側のすべてには大きなラベルのみが含まれる必要があります。 

タスクは、そのようなツリーを構築することではなく、どの頂点が有効なルートとして機能できるかを決定し、ルート化後に、左右の子割り当ての選択に基づいてツリーが二分探索ツリーとして解釈できるようにすることです。 

n が 500000 までの制約により、あらゆる解が本質的に線形または線形対数になるように強制されます。 すべての頂点のルート化を個別にシミュレートしたり、ルート候補ごとにサブツリー情報を最初から再構築したりするアプローチはどれも遅すぎます。1 回の走査でも O(n) であり、それを n 回繰り返すと O(n²) になり、これは実行不可能だからです。 

微妙な問題は、ツリー構造は固定されていますが、BST の解釈がルートの選択と、子間の「左」と「右」の役割の割り当ての両方に依存することです。 素朴な直観は、次数制約をチェックするだけで十分であると考えるかもしれませんが、数値の順序付けがグローバルな方法でトポロジと相互作用するため、それだけでは十分ではありません。 

いくつかの特殊なケースでは、落とし穴が明らかになります。 

ツリーが 1 を中心とするスターで、ノード 2、3、4、5 が接続されている場合、他のすべての値が厳密に片側にない限り、ノード 1 が BST ルートになることは不可能です。これらの値は 1 を基準にして混合されているため、これは不可能です。次数制約が満たされていても、順序付けはすぐに失敗します。 

ツリーが 1-2-3-4 のような単純なパスの場合、すべてのノードは局所的には問題ないように見えますが、ルート化されるとサブツリーは構造に沿って増加または減少する制約に合わせて一貫して整列する必要があるため、特定のルートのみが機能します。 

別の失敗例は、ノードに多くの隣接ノードがあり、それぞれが異なる値の範囲を形成している場合に発生します。 たとえ各隣接ノードが個別にノードとの比較を満たしたとしても、2 つ以上の異なる指向性グループが必要な場合、左右のサブツリー間でそれらを混合することは不可能になります。 

## アプローチ

 ブルートフォース手法では、各ノードをルートとして試行します。 選択ごとに、DFS を実行してツリーをルート化し、間隔伝播を使用して BST 制約を検証しながら左右の子の割り当てを試みます。 各検証は O(n) であり、n 個の候補すべてに対してこれを行うと O(n²) になりますが、n が 500000 まででは実行できません。 

重要な点は、ノードが有効なルートになれるかどうかは、そのノードが削除されたときにツリーの残りの部分がどのように分割されるかによってのみ決まるということです。 ノードを削除すると、ツリーが接続されたコンポーネントに分割されます。 このような各コンポーネントは、値空間内のノードの片側に完全に存在する必要があります。これは、コンポーネント内のすべての値がノードよりも厳密に小さいか、ノードよりも厳密に大きいかのいずれかであることを意味します。 コンポーネントに混合値が含まれている場合、それを一貫して左または右に割り当てることは不可能です。 

これにより、問題は、各ノードを削除することによって形成されたコンポーネントの構造チェックに変換されます。 すべてのノードとすべての隣接コンポーネントについて、そのコンポーネント内の最小ラベルと最大ラベルを知る必要があります。 その情報を使用して、各コンポーネントを左側または右側に割り当てることができるかどうかを決定できます。

すべてのノードのこれらのコンポーネント統計の計算は、リルート動的プログラミングを使用して線形時間で実行できます。 まず、ツリーを任意にルート化し、サブツリーの最小値と最大値を計算します。 次に、「上向き」情報を伝播して、すべてのノードが自身のサブツリーを除くグラフ全体の最小値と最大値を認識できるようにし、O(1) のすべてのエッジのコンポーネント情報を再構築できるようにします。 

これらの値が利用可能になると、候補ルートのチェックは、隣接するすべてのコンポーネントがルート ラベルよりも完全に小さいか完全に大きいかを検証することになります。 これは実現可能性にとって必要かつ十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースルートチェック | O(n²) | O(n) | 遅すぎる |
 | コンポーネントの最小/最大を使用して DP を再ルートします | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 任意の頂点 (たとえば 1) でツリーをルート化し、前処理のためにエッジを親子関係として扱います。 

1. ノード 1 から DFS を実行して、すべてのノードについて、そのサブツリー内の最小ラベルと最大ラベルを計算します。 これにより、各ノードが下方向に何を制御しているのかがわかります。 これが機能する理由は、ルート付きツリーでは、すべてのノードのサブツリーが他のノードから切り離されているため、最小値と最大値をきれいに累積できるためです。 
2. 各ノードについて、そのサブツリーの外側にあるツリーの残りの部分に関する情報も必要です。 これは、2 番目の DFS (再ルート) を使用して計算されます。 親から子に移動するときは、親の「up」値と、子自身のサブツリーを除くすべての兄弟サブツリーからの情報を組み合わせます。 これにより、各ノードに、ルート表現でその上にあるコンポーネントに関する知識が与えられます。 
3. サブツリーとアップの値を使用して、すべての有向エッジについて、そのエッジが削除されたときに形成されるコンポーネントの最小ラベルと最大ラベルを決定できます。 各エッジは、各エンドポイントの観点から見た場合、そのようなコンポーネントの 1 つに正確に対応します。 
4. 各ノード v について、その近隣ノードすべてを反復処理します。 各近傍 u について、v が削除されたときに u 側にあるツリーのコンポーネントを調べます。 そのコンポーネント内のすべての値が厳密に v より小さいか、厳密に v より大きいかどうかを確認します。コンポーネントに v の両側に値が含まれている場合、v は有効な BST ルートになることはできません。 
5. さらに、構造がバイナリ ツリーをサポートできることを強制します。 これは、v でルート化した後、子に関して非ルート ノードの近傍ノード (次数) の数が 2 を超えてはいけないことを意味します。これは、元のツリーの次数制約に変換されます。 ノードに 3 つ以上の子を必要とする分離可能なコンポーネントが多すぎる場合、そのノードはルートとして機能できません。 
6. 上記のチェックに合格したすべてのノードが収集され、昇順に出力されます。 

### なぜ効果があるのか

 ノードがルートとして選択されると、ノードを削除した後に形成される各接続コンポーネントは、ルート化された BST 内のサブツリーになります。 BST 条件は、そのような各サブツリーがルートに対して連続した値の間隔を占めるように強制します。 コンポーネントにルートより小さい値と大きい値の両方が含まれている場合、左/右エッジを割り当ててもコンポーネントを分離できません。 逆に、すべてのコンポーネントが完全に片側にある場合は、コンポーネントを任意に左または右に割り当て、各コンポーネント内に同じロジックを再帰的に適用できます。 再ルート計算により、ツリーを毎回再構築することなく、すべてのノードに対してこの条件を効率的にテストできるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

parent = [-1] * n
order = []
stack = [0]
parent[0] = -2

# build order
while stack:
    v = stack.pop()
    order.append(v)
    for to in g[v]:
        if to == parent[v]:
            continue
        if parent[to] == -1:
            parent[to] = v
            stack.append(to)

# subtree min/max
sub_min = [10**18] * n
sub_max = [-10**18] * n

for v in reversed(order):
    sub_min[v] = v + 1
    sub_max[v] = v + 1
    for to in g[v]:
        if to == parent[v]:
            continue
        sub_min[v] = min(sub_min[v], sub_min[to])
        sub_max[v] = max(sub_max[v], sub_max[to])

# up values via rerooting
up_min = [10**18] * n
up_max = [-10**18] * n

up_min[0] = 10**18
up_max[0] = -10**18

for v in order:
    prefix_min = []
    prefix_max = []
    for to in g[v]:
        if to == parent[v]:
            continue
        prefix_min.append(sub_min[to])
        prefix_max.append(sub_max[to])

    m = len(prefix_min)
    pref_min = [10**18] * (m + 1)
    pref_max = [-10**18] * (m + 1)
    suf_min = [10**18] * (m + 1)
    suf_max = [-10**18] * (m + 1)

    for i in range(m):
        pref_min[i + 1] = min(pref_min[i], prefix_min[i])
        pref_max[i + 1] = max(pref_max[i], prefix_max[i])

    for i in range(m - 1, -1, -1):
        suf_min[i] = min(suf_min[i + 1], prefix_min[i])
        suf_max[i] = max(suf_max[i + 1], prefix_max[i])

    idx = 0
    for to in g[v]:
        if to == parent[v]:
            continue
        left_min = min(up_min[v], pref_min[idx], suf_min[idx + 1])
        left_max = max(up_max[v], pref_max[idx], suf_max[idx + 1])
        up_min[to] = min(left_min, v + 1)
        up_max[to] = max(left_max, v + 1)
        idx += 1

ans = []

for v in range(n):
    ok = True
    deg = 0
    for to in g[v]:
        if parent[v] == to:
            continue
        deg += 1

        # component is subtree or up depending on direction
        if parent[to] == v:
            cmin, cmax = sub_min[to], sub_max[to]
        else:
            cmin, cmax = up_min[v], up_max[v]

        if not (cmax < v + 1 or cmin > v + 1):
            ok = False
            break

    if ok:
        ans.append(v + 1)

print(*ans)
```この解決策は、ノード 1 でツリーをルート化し、サブツリー情報をボトムアップで集約できるように走査順序を計算することから始まります。 サブツリーの最小配列と最大配列は、ラベル空間内の各ノードの子孫範囲を要約します。 

再ルート段階では、サブツリーの外側にあるすべてのものに関する情報が伝播されます。 プレフィックス配列とサフィックス配列は、他のすべての寄与を効率的にマージしながら 1 つの子を除外するために使用され、各ノードが正しい「上位コンポーネント」情報を確実に受信できるようにします。 

最後に、すべてのインシデント コンポーネントをそのラベルと照合することにより、各ノードが潜在的なルートとしてテストされます。 コンポーネントがノード値の両側にまたがる場合、BST 条件は直ちに失敗します。 

## 実用的な例

 小さなチェーン 1-2-3 を考えてみましょう。 

| ルート候補 | 取り外し後のコンポーネント | コンポーネントの範囲 | 有効？ |
 | --- | --- | --- | --- |
 | 2 | {1}、{3} | [1]、[3] | はい |
 | 1 | {2,3} | [2,3] | いいえ |
 | 3 | {1,2} | [1,2] | いいえ |

 この表は、小さい値と大きい値をさまざまなコンポーネントに明確に分離するため、中央のノードのみが機能することを示しています。 

ここで、中心が 2 で、エッジが 2-1、2-3、2-4 である星について考えてみましょう。 

| ルート候補 | コンポーネント | コンポーネントの範囲 | 有効？ |
 | --- | --- | --- | --- |
 | 2 | {1}、{3}、{4} | [1]、[3]、[4] | いいえ |
 | 1 | {2,3,4} | [2,3,4] | いいえ |
 | 3 | {2,1,4} | [1,2,4] | いいえ |

 各ノードが個別に隣接ノードと適切に比較されたとしても、中央ノードには左側と右側のみに分割する必要があるコンポーネントが 3 つ以上あるため、中央ノードは失敗します。

 ## 特殊なケース

 単一ノード入力は、エッジのない 1 つの頂点で構成されます。 順序付け制約に違反するコンポーネントがないため、アルゴリズムはサブツリー値を自明に初期化し、それを有効なルートとして受け入れます。 

星型ツリーは、ノードに独立したコンポーネントが多すぎる場合の障害モードを示しています。 中心を評価する場合、各リーフは値がすべて片側にない個別のコンポーネントを形成し、チェックではノードが即座に拒否されます。 ただし、葉は、その唯一の構成要素が木の残りの部分であり、ラベル付けに応じて一貫して大きくなったり小さくなったりするため、合格します。 

長いパスは、複数の内部ノードがどのように認定されるかを示しています。 各候補ルートはパスを 2 つの単調セグメントに分割し、それらのセグメントがルート値ときれいに一致する場合にのみコンポーネント チェックが成功します。
