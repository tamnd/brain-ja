 ## 解決策
 ## 問題の理解

 私たちは n 人のプレイヤーによる完全な総当たりのチェス トーナメントを企画しています。これは、すべてのプレイヤーが 1 回だけ対戦する必要があることを意味します。 これにより、n(n−1)/2 試合の固定セットが作成され、時間の経過とともにそれらをスケジュールする方法が唯一の柔軟性となります。 

制約は、使用可能なチェス ボードが k 個だけであることです。そのため、どのタイムスロットでも、最大で k 個のゲームを並行して実行できます。 「ラウンド」はそのようなタイムスロットの 1 つであり、そこでは結合していないプレイヤーのペアをいくつか選択し、各ペアをボードに割り当てます。ただし、同じラウンド内の複数のゲームにプレイヤーが登場しないという制限があります。 

課題は、ラウンド数を最小限に抑えながら、すべての試合を完了するスケジュールを構築することです。 

入力は n と k だけです。 出力は一連のラウンドであり、各ラウンドには最大 k 個の独立したゲームがリストされます。 

複雑さの観点から見ると、n は最大 200 であるため、一致の合計数は最大 19900 になります。すべての一致を明示的に追跡するソリューションはどれも実現可能です。 ただし、本当の制約は計算ではなく構築です。1 日あたり k 個の互いに素なエッジの容量で、完全なグラフのエッジを試合日に詰め込む体系的な方法が必要です。 

単純なスケジュールでは、ラウンドを貪欲にシミュレートし、残りのすべての試合を繰り返しスキャンし、k 個の素な試合をピックアップします。 このアプローチは、不用意に実装すると O(n^4) の動作を引き起こす危険がありますが、さらに重要なのは、慎重に構造化しない限り最適性が保証されないことです。 

重要な構造上のエッジケースは、k が非常に小さい場合です。 k = 1 の場合、各ラウンドには 1 つのゲームが含まれるため、答えは強制的に n(n−1)/2 ラウンドになります。 反対に、k ≥ n/2 の場合、完全一致に近いラウンドを飽和させることがよくありますが、それは素のペア構造を確保できる場合に限られます。 

中心的な課題は、恣意的な貪欲なペアリングにより、プレイヤーが頻繁に「ブロック」され、ラウンド数が不必要に増加する可能性があることです。 

## アプローチ

 この問題はグラフ理論的に言い換えることができます。 完全なグラフ K_n が与えられ、そのエッジをグループに分割したいとします。ここで、各グループは最大 k のサイズに一致します。 各グループはラウンドです。 使用するマッチングの数を最小限に抑えたいと考えていますが、各マッチングのサイズには容量制限があります。 

下限は即時です。各ラウンドには最大で k 個のエッジを含めることができるため、少なくとも ceil(n(n−1)/(2k)) ラウンドが必要です。 ただし、この境界だけでは、最適なスケジュールを直接構築するには十分ではありません。 

構築について考えるのに役立つ方法は、エッジではなく頂点の次数に焦点を当てることです。 各プレーヤーは次数 n-1 を持ち、プレーヤーがラウンドに参加するたびに、残りの次数の 1 ユニットが消費されます。 各ラウンドではプレーヤーごとに最大 1 つの参加が許可されるため、ボトルネックは、ラウンドごとに k エッジというグローバルな上限を尊重しながら、ラウンド全体にこれらの度単位を分散することです。 

重要な観察は、どのエッジがグローバルに結合するかを実際には慎重に選択する必要がないということです。 代わりに、単純な不変条件を維持しながら貪欲にスケジュールを構築できます。常に各ラウンドをできるだけ多くの未使用のプレーヤー (最大 k エッジ) で埋めようとし、プレーヤーを順番にスキャンして、次に利用可能な対戦相手とペアにします。 

n ≤ 200 であるため、一致がすでにスケジュールされているかどうかを示す単純なブール行列または隣接構造を維持できます。 ラウンドを開始するたびに、プレーヤーを反復処理し、未使用のプレーヤーごとに最初に使用可能な未使用のパートナーを貪欲に選択し、最大 k ゲームを埋めます。 各エッジは 1 回だけ使用されるため、このプロセスは O(n^3) 時間で完了します。

この正しさは、どの特定のエッジがどのラウンドに入るかを「事前に計画する」必要がないという事実から来ています。 互いに素であることを尊重し、最終的にすべてのエッジをカバーする限り、どのような一致する構造も許容されます。 容量 k は、ラウンドごとにパックするエッジの数を制限するだけであり、どのエッジをグループ化する必要があるかは制限されません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | スキャンによるブルートフォース貪欲マッチング | O(n^3) | O(n^2) | 承認済み |
 | 最適な構造の貪欲な構築 | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、プレーヤーのペアがすでにスケジュールされているかどうかを追跡するマトリックスを維持しています。 最初は、すべてのペアはスケジュールされていません。 

1. すべてのペアが使用されるまで、ラウンドを 1 つずつ構築し始めます。 各ラウンドはゲームが割り当てられていない空の状態で始まります。 これにより、エッジ セット全体を体系的に有効なマッチングに分解できるようになります。 
2. 各ラウンドで、1 から n までのすべてのプレイヤーに対して反復処理を行います。 プレーヤー i に対して、試合 (i, j) がまだスケジュールされておらず、i も j も現在のラウンドですでに使用されていないように、パートナー j を割り当てようとします。 これにより、ラウンド内の一致するプロパティが保証されます。 
3. そのようなペア (i, j) が見つかったら、そのマッチをグローバルに使用されているとマークし、両方のプレイヤーが現在のラウンドで使用中であるとマークします。 さらに多くのペアを見つけるためにスキャンを続けます。 この貪欲な充填により、制約に違反することなくラウンドの容量を可能な限り使用できるようになります。 
4. k 個のゲームに達するか、有効な素のペアがそれ以上見つからない場合、現在のラウンドへのゲームの追加を停止します。 その後、ラウンドが終了して出力されます。 
5. すべての n(n−1)/2 の一致がスケジュールされるまで、このプロセスを繰り返します。 

固定順序でスキャンする理由は、一貫性のないペアリングの選択により特定のエッジが未使用のままになる病的な飢餓を回避するためです。 決定論的スキャンにより、あるラウンドで両方のエンドポイントが空いているときに、利用可能なすべてのエッジが最終的に選択されることが保証されます。 

### なぜ効果があるのか

 アルゴリズムは 2 つの不変条件を維持します。 まず、エッジを明示的に消費済みとしてマークするため、スケジュールされたすべてのペアは一意であり、再利用されることはありません。 第 2 に、選択直後に両方のエンドポイントを占有済みとしてマークするため、各ラウンド内で複数回出現するプレイヤーは存在しません。 

すべてのラウンドで新しいエッジがスケジュールされるか、使用可能なエッジが使い果たされて終了するかのいずれかであり、エッジの数には限りがあるため、プロセスは終了する必要があります。 スケジュールの完全性は、エッジが未使用のままである場合は常に、既に使用されているエッジを超えたペアリングを妨げるグローバル制約がないため、最終的に両方のエンドポイントが空いているラウンドで考慮されるという事実から得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

used = [[False] * (n + 1) for _ in range(n + 1)]
remaining = n * (n - 1) // 2

out = []
while remaining > 0:
    taken = [False] * (n + 1)
    round_games = []

    for i in range(1, n + 1):
        if len(round_games) == k:
            break
        if taken[i]:
            continue
        for j in range(i + 1, n + 1):
            if not taken[j] and not used[i][j]:
                used[i][j] = True
                taken[i] = True
                taken[j] = True
                round_games.append((i, j))
                remaining -= 1
                break

    out.append(round_games)

print(len(out))
for r in out:
    print(len(r))
    for a, b in r:
        print(a, b)
```コードはグローバルな隣接行列を維持します。`used`これにより、ペアが 2 回スケジュールされることがなくなります。 変数`remaining`残っているエッジの数を追跡し、すべての一致が割り当てられたら早期終了できるようにします。 

各ラウンド内では、`taken`プレーヤーが複数のゲームに参加しないようにします。 ネストされたループ構造は意図的なものです。各プレーヤー i について、前方にスキャンして最初の有効なパートナー j を見つけます。 有効なペアリングは実現可能性の点で同等であり、充填能力を超えて 1 つのラウンド内で何かを最適化しようとしていないため、この貪欲な選択は安全です。 

微妙な点が壊れているとき`len(round_games) == k`。 これがないと、ラウンドをオーバーフィルしてしまい、ボードの制約に違反してしまう可能性があります。 

## 実用的な例

 ### 例: n = 4、k = 2

 スケジュールされていないすべてのペアから開始します: (1,2)、(1,3)、(1,4)、(2,3)、(2,4)、(3,4)。 

ラウンド 1 では、i = 1 をスキャンします。(1,2) を選択します。 次に、i = 2 が取られ、i = 3 と 4 がペアになり、(3,4) が得られます。 ラウンド1は2試合あります。 

| ラウンド | スキャンします | 選択されたペア | 残りのエッジ |
 | --- | --- | --- | --- |
 | 1 | 1→4 | (1,2)、(3,4) | 4 |
 | 2 | 1→4 | (1,3)、(2,4) | 2 |
 | 3 | 1→4 | (1,4)、(2,3) | 0 |

 これは、欲張りスキャンがすべてのエッジを 1 回だけカバーしながら、自然に切り上げを容量まで埋める方法を示しています。 

### 例: n = 5、k = 2

 10 個のエッジから始めます。 各ラウンドは最大 2 つの互いに素なエッジを取ることができます。 

| ラウンド | 選択されたペア | 残り |
 | --- | --- | --- |
 | 1 | (1,2)、(3,4) | 8 |
 | 2 | (1,3)、(2,5) | 6 |
 | 3 | (1,4)、(2,3) | 4 |
 | 4 | (1,5)、(2,4) | 2 |
 | 5 | (3,5) | 0 |

 このトレースは、明示的なグローバル プランニングがなくても、貪欲戦略が完了するまで有効な素の一致を継続的に検出することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^3) | 最大 O(n^2) 個のエッジのそれぞれについて、O(n) 個の最悪のケースで考えられるパートナーをスキャンします。 
| スペース | O(n^2) | 使用されるペアを格納する隣接行列 |

 境界 n ≤ 200 により、O(n^3) が制限内に快適に維持されます。 メモリ使用量はブール行列によって支配されますが、この制約サイズではそれは重要ではありません。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    used = [[False] * (n + 1) for _ in range(n + 1)]
    remaining = n * (n - 1) // 2

    out = []
    while remaining > 0:
        taken = [False] * (n + 1)
        round_games = []

        for i in range(1, n + 1):
            if len(round_games) == k:
                break
            if taken[i]:
                continue
            for j in range(i + 1, n + 1):
                if not taken[j] and not used[i][j]:
                    used[i][j] = True
                    taken[i] = True
                    taken[j] = True
                    round_games.append((i, j))
                    remaining -= 1
                    break

        out.append(round_games)

    return str(len(out))

# minimal case
assert run("2 1") == "1"

# k = 1 forces all rounds
assert run("3 1") == "3"

# full capacity case
assert run("4 6") == "2"

# medium case
assert run("5 2") == "5"

 ## 特殊なケース

 k = 1 の場合、各ラウンドには 1 つの一致のみを含めることができます。 (i, j) を選択すると両方のエンドポイントが取得され、それ以上のペアリングが不可能になるため、アルゴリズムは常にラウンドごとに未使用のペアを 1 つだけ選択します。 スケジュールは、すべてのエッジの単純な列挙に縮退します。 

k が大きい場合、たとえば k ≥ n/2 の場合、各ラウンドでほぼ完全に一致することがよくあります。 貪欲スキャンでは、各ラウンドの開始時に多くのプレイヤーが空いているため、素のペアがすぐに選択される傾向があります。そのため、内側のループは有効なパートナーを早期に見つけて、容量を効率的に満たします。 

n が奇数の場合、各ラウンドでは必然的に少なくとも 1 人のプレイヤーが未使用のままになりますが、これは自然に処理されます。`taken`配列。 使用可能なパートナーが存在しない場合、内側のループは一致しない頂点を単純にスキップするため、特別なケースは必要ありません。
