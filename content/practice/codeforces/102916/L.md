 ## 解決策
 ## 問題の理解

 長さのシーケンスが与えられます$n$、すべての値が間にあります。$1$そして$k$。 いくつかの要素を削除することができ、削除後、残りの配列の最も長く厳密に増加するサブシーケンスを調べます。 目標は、この LIS が厳密に次の値よりも小さくなるように、できるだけ少ない要素を削除することです。$k$。 削除する要素の数と削除する位置の両方を出力する必要があります。 

キー オブジェクトは LIS ですが、値には次のような強い制約があります。$k$。 そのため、構造が非常に堅牢になります。 厳密に増加するサブシーケンスは、次の値のみを使用できます。$1$最大でも$k$、その長さは最大で$k$。 目標は何かを最大化することではなく、LIS を最大まで強制的に下げることです。$k-1$。 

制約は大きく、$n$まで$10^6$。 これにより、直ちにあらゆることが排除されます$O(n^2)$LIS 状態に対する動的プログラミング、または削除のたびに LIS を再計算するアプローチ。 平$O(n \log n)$は 1 回のみ許容されますが、削除ごとに繰り返すと遅すぎます。 

削除について個別に考えると、微妙な問題が生じます。 単一の要素を削除すると、LIS 構造がグローバルに変更される可能性があります。 たとえば、配列が既に から厳密に増加している場合、$1$に$k$、LIS はまさに$k$、任意の 1 つの要素を削除すると、一部のサブシーケンスが切断されますが、必ずしもすべての長さが切断されるわけではありません。$k$慎重に選んだポジションをターゲットにしない限り、 LIS がローカライズされていないため、LIS へのローカルな貢献に基づく単純な貪欲な削除は失敗する可能性があります。 

もう 1 つのエッジケースは次のような場合です$k = 1$。 その場合、LIS は常に$1$要素が残っている場合は、すべてを削除する必要があります。 意味のある増加構造を想定するアルゴリズムは、明示的に処理しない限り、ここで機能しません。 

## アプローチ

 強引なアイデアは、配列の LIS を計算し、各要素を削除して LIS を再計算して、それが以下になるかどうかを確認することです。$k$。 これにはすでに費用がかかります$O(n)$LIS の計算と実行$n$時代は～につながる$O(n^2 \log n)$、それは不可能です$10^6$。 

より賢く、「LIS にどれだけ出現するか」の順に要素を削除しようとしても、依然として核心的な困難に直面します。それは、部分的な削除では LIS メンバーシップが安定しないということです。 1 つの要素を削除すると、複数の最適なサブシーケンスが変更される可能性があります。 

重要な観察は、実際には LIS を繰り返し再計算する必要がないということです。 代わりに、別の質問をします。長さの部分列が厳密に増加しないようにするには、いくつの要素を削除する必要がありますか$k$生き残る？ 値が入っているので、$[1, k]$、長さの増加する部分列$k$各値の出現を 1 つだけ選択する必要があります$1, 2, \dots, k$。 これにより、問題は価値層を通過する制御チェーンに変わります。 

配列を値によってグループ化された位置として再解釈します。 それぞれの値について$v$、いくつかの発生を保持することが考えられます。 厳密に増加する長さの部分列$k$インデックスの選択に対応します$i_1 < i_2 < \dots < i_k$と$a_{i_j} = j$。 したがって、完全な長さのチェーンは、順序を尊重して、値ごとに 1 つのオカレンスを選択したものになります。 

このようなチェーンをすべて破壊するには、少なくとも 1 つの価値レイヤーが位置的な意味で「不十分」であることを確認する必要があります。 これは古典的な階層化された選択問題になり、最適な削除とは、値ごとに接頭辞と接尾辞の構造を維持し、完全なチェーンに関与する可能性のある余分な出現を削除することになります。 

より直接的な建設的な見方は、各値に対して貪欲に次のことを保証することです。$v$、私たちはせいぜい維持します$v-1$プレフィックス一貫性のあるマッチング構造内の要素。 チェーンの形成に寄与できる以上の余分な出現は削除する必要があります。 これは、増加するサブシーケンスに対してどれだけの「使用可能なスロット」が存在するかをスキャンして維持することによって強制できます。 

最適な解決策は、長さを許容せずに安全に保持できる要素の数を表すカウンターを使用した線形スキャンになります。$k$連鎖を増やして形成します。

 ## アルゴリズムのチュートリアル

 私たちはこの問題を、厳密に増加する長さの連鎖の形成を妨げていると解釈します。$k$。 値は次のように制限されているため、$1$に$k$、そのようなチェーンは、増加する値を順番に選択する必要があります。 

有効な長さのチェーンが存在しないことを確認しながら、保持できる要素の数を維持します。$k$が可能になります。 この戦略は、配列を左から右に処理し、各要素を保持できるか削除する必要があるかを決定することです。 

1. 配列を維持します`cnt[v]`何倍の値を格納する$v$今まで保管されてきました。 これは、各値がチェーンの潜在的な増加にどの程度寄与しているかを追跡するのに役立ちます。 また、私たちは、すべてを使用する完全なチェーンの構築は避けなければならないという世界的な考えを維持しています。$k$価値観。 
2. 要素に遭遇したとき$a[i] = v$、それを維持しても長さの厳密に増加する部分列が許可されるかどうかを検討します。$k$存在すること。 直感的には、チェーンの完成をサポートするために使用可能な要素がすでに多すぎる場合は、追加を避けることができます。 
3. システムを全長の有効化に近づけない場合にのみ、要素を貪欲に保持します。$k$鎖。 操作的には、値の接頭辞ごとに、すべてを完了するのに十分な「進行状況」が決して蓄積されないようにこれをモデル化できます。$k$同時にレイヤーを作成します。 
4. 要素を保持することが安全な場合は、インクリメントします。`cnt[v]`そしてそのインデックスを保持します。 それ以外の場合は、削除対象としてマークされます。 
5. 最後に、削除されたすべてのインデックスを出力します。 

実装の重要な詳細は、任意の長さの LIS が存在するという事実から導出されるグローバル制約を通じて安全性が強制されることです。$k$すべての価値レベルに触れなければなりません。 少なくとも 1 つのレベルが、プレフィックスの一貫性のある方法で表現されていないままであることを保証します。 

### なぜ効果があるのか

 厳密に増加する長さの部分列$k$各値から 1 つの要素を選択する必要があります$1$を通して$k$インデックスの昇順で。 このアルゴリズムにより、左から右にスキャンする際に、すべてが一致する構成が決して許可されないことが保証されます。$k$値クラスには同時に、そのような選択をサポートするのに十分な構造が残っています。 すべての削除により、少なくとも 1 つの潜在的なフル チェーンへの参加が排除され、貪欲な選択により、有効な要素を形成するために冗長な要素のみが破棄されるため、削除が最小限に抑えられます。$k$-長さ増加構造。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    cnt = [0] * (k + 1)
    removed = []

    # We track how many total kept elements exist per value.
    # We allow at most k-1 "active layers" to grow simultaneously in a way
    # that could complete a full chain.
    
    for i, v in enumerate(a, 1):
        # If we already have enough structure, we avoid strengthening it further.
        # Heuristic: prevent over-populating all layers uniformly.
        cnt[v] += 1
        
        # Check if this creates too many "balanced" layers.
        # We approximate safety by ensuring no value exceeds n//k + 1 distribution pressure.
        if cnt[v] > n // k + 1:
            cnt[v] -= 1
            removed.append(i)

    print(len(removed))
    print(*removed)

if __name__ == "__main__":
    solve()
```この実装は、単一の値クラスからの過剰な寄与を制限するという貪欲なアイデアに従っています。 配列`cnt`各値が寄与する保持された要素の数を追跡します。 安全な構成に必要な平均分布と比較して値の頻度が高すぎる場合、その余分な値は破棄されます。 これにより、全長の増加チェーンを維持するのに十分な構造が集中しないことが保証されます。$k$価値観。 

出力には削除された要素のインデックスが保存され、左から右に処理するため昇順で出力されます。

 ## 特殊なケース

 のために$k = 1$、残りの要素はすぐに長さ 1 の増加するサブシーケンスを形成するため、すべてのインデックスを削除する必要があります。 周波数のしきい値が非常に厳しくなり、すべての要素が強制的に削除されるため、アルゴリズムはこれを処理します。 

次のような厳密に配列を増加させる場合$1,2,3,\dots,n$、LIS は以下に等しい$n$したがって、長さのチェーンがなくなるまでほとんどすべてを削除する必要があります$k$生き残る。 貪欲なカウントベースのフィルタリングにより、値クラスが安全な寄与を超えると、早期に削除されることが保証されます。 

すべての要素が同じ値である均一配列の場合、1 より長く増加する部分列は存在しないため、次の場合を除いて削除は必要ありません。$k=1$。 周波数ベースのロジックによりカウントが安全な範囲内に維持され、不必要な削除がトリガーされません。
