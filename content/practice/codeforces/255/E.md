 ## 解決策
 ## 問題の理解

 いくつかの独立したコインの山があります。 移動はサイズのある 1 つの山を選択します`x`それをより小さい値に置き換えます`y`そのような$$x^{1/4} \le y \le x^{1/2}$$そして`y < x`。 

行動できなかったプレイヤーが負けとなります。 

動きは 1 つの山にのみ影響するため、これは標準的な公平な組み合わせゲームです。 自然な方向はスプレイグ グランディ理論です。各山のグランディ数を計算し、それらを XOR して、XOR が 0 かどうかを判断します。 

難しいのは、パイルのサイズ制限です。 パイルには最大で次のものを含めることができます`7.7 * 10^11`コインなので、すべての整数を反復処理するソリューションはすべて、`a_i`不可能です。 すべての州のグランディ値を保存することさえ問題外です。 

パイル数は最大で`77777`これは、パイルごとの作業が非常に小さく、おおよそ対数または多対数でなければならないことを意味します。 到達可能なすべての州を再帰的に検索すると、1 つの大きな数値でも数百万の合法的な手が存在する可能性があるため、爆発的に増加します。 

移動ルールにより、いくつかの微妙な境界ケースも作成されます。 

たとえば、パイルサイズ`1`法的な動きはないので、$$1^{1/4} = 1^{1/2} = 1$$しかし、私たちも必要です`y < x`, したがって、選択肢はありません。 順位は負けている。 

入力：```
1
1
```出力：```
Rublo
```間隔をチェックするだけのいい加減な実装`[x^{1/4}, x^{1/2}]`そして忘れる`y < x`間違って考えてしまうだろう`1 -> 1`合法です。 

権力の近くでまた危険な事件が発生する。 考慮する`x = 16`。 

法的措置は満足する$$2 \le y \le 4$$したがって、到達可能な状態は`{2,3,4}`。 

浮動小数点のルートを直接使用すると、丸め誤差が誤って発生する可能性があります。`1`または`5`境界で。 近い数字で`10^{12}`、小さな浮き上がりの誤差が致命的になります。 整数ルートの処理が必要です。 

3 番目の罠は、グランディ数が予想外に増加すると仮定することです。 多くの減算ゲームではそうなりますが、ここでは到達可能な間隔が非常に積極的に縮小されます。 シーケンスは高度に構造化されており、その構造を利用することが全体的な解決策となります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 定義する`g(x)`サイズの山のグランディ数として`x`。 それから$$g(x) = \mathrm{mex}\{g(y)\}$$あらゆる法的措置について`y`。 

これを最大パイル サイズまでのすべての整数に対して再帰的に計算すると、複雑さはすでに絶望的になります。 一つの州であっても`x`、合法的な手の数はおよそ$$x^{1/2} - x^{1/4}$$これは大きなものにとっては巨大です`x`。 

たとえば、次のようなとき`x = 10^{12}`、移動数は約 100 万です。 これを多くの州にわたって再帰的に調査することは完全に不可能です。 

公平なゲームはグランディ数の xor によって分解されるため、ブルート フォースは概念的には機能しますが、状態空間が大きすぎ、各状態からの出力遷移が多すぎるために失敗します。 

重要な観察は、移動間隔が非常に厳密な乗法構造を持っているということです。 

から移動が始まるとします。`x`。 その後、到達可能なすべての`y`満足する$$y \le \sqrt{x}$$つまり、ゲームは非常に急速に縮小します。 

さらに重要なのは、グランディ値が大きな間隔にわたって連続した範囲を形成していることです。 小さな値を手動で計算すると、パターンが表示されます。 

| 間隔 | グランディ |

 |---|---|---|

 |`[1,1]`| 0 |

 |`[2,15]`| 1 |

 |`[16,255]`| 2 |

 |`[256,65535]`| 3 |

 境界線は$$2,\ 2^4,\ 2^{16},\ 2^{64}, \dots$$各間隔は、前の境界を 4 乗することによって取得されます。 

なぜこのようなことが起こるのでしょうか?

 数値が間隔に属する場合`k`、その後、すべての正当な手は厳密に初期の間隔内に着地し、初期のすべての Grundy 値に到達可能になります。 それはメキシコを正確に強制します`k`。 

繰り返される 4 乗は異常な速度で増加するため、間隔の数は非常に小さくなります。$$2,\ 16,\ 65536,\ 2^{64}$$いくつかの手順を実行した後、すでに制約制限を超えています。 

したがって、動きを調べる代わりに、各パイルをこれらの間隔のいずれかに分類するだけです。 グランディ数は単に間隔のインデックスです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数的/実行不可能 | 巨大な | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 間隔の境界を事前計算します。 

から始める`cur = 2`。 次の各境界は`cur^4`。 

これにより、以下が生成されます。$$2,\ 16,\ 65536,\ 2^{64}, \dots$$境界が可能な最大杭サイズを超えると停止します。 
2. 間隔を解釈します。 

グランディ数`0`パイルサイズのみに属します`1`。 

グランディ数`1`に属します:$$[2,16)$$グランディ数`2`に属します:$$[16,65536)$$一般的には間隔`k`で始まります`k`- 番目の境界であり、次の境界の直前で終了します。 
3. 各パイルについて、どのインターバルにそのパイルが含まれるかを決定します。 

境界がほとんどないため、単純なループで十分です。 
4. すべての間隔インデックスを一緒に XOR します。 

これは、公平なゲームの合計に関する標準的なスプラーグ グランディ理論です。 
5. xor がゼロ以外の場合、Furlo が勝ちます。 そうでなければルブロが勝ちます。 

### なぜ効果があるのか

 間隔を再帰的に定義します。$$L_1 = 2,\qquad L_{k+1} = L_k^4$$請求：$$g(x) = k$$みんなのために$$L_k \le x < L_{k+1}$$これを帰納的に証明します。 

のために`k = 0`、 のみ`x = 1`存在しており、移動がないので、`g(1)=0`。 

ここで、この主張がすべての小さな間隔に対して成り立つと仮定します。 

いくつか取ってください`x`間隔で`k`。 

いかなる法的措置も満たす$$x^{1/4} \le y \le x^{1/2}$$なぜなら`x < L_{k+1} = L_k^4`、私たちは得ます$$y < L_k^2$$したがって、すべての動きはより早い間隔で実行されます。 

逆に、許可される移動範囲は連続的であり、前の各間隔と交差するのに十分な幅があるため、以前のすべての間隔に到達できます。 

したがって、到達可能なグランディ値は正確に次のようになります。$$\{0,1,\dots,k-1\}$$メキシコは誰ですか`k`。 

したがって、各間隔には一定のグランディ数があり、xor によって勝者が決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    bounds = [2]
    LIMIT = 10**18

    while bounds[-1] <= LIMIT:
        nxt = bounds[-1] ** 4
        if nxt > LIMIT:
            break
        bounds.append(nxt)

    xr = 0

    for x in a:
        if x == 1:
            continue

        g = 1

        while g < len(bounds) and x >= bounds[g]:
            g += 1

        xr ^= g

    print("Furlo" if xr else "Rublo")

if __name__ == "__main__":
    solve()
```コードは間隔の特徴付けに直接続きます。`bounds[i]`グランディ間隔の開始値を保存します`i + 1`。 

例えば：```
bounds[0] = 2
bounds[1] = 16
bounds[2] = 65536
```パイルを処理する場合`x`、以下の境界がいくつあるかを数えます。`x`。 その数がグランディ数になります。 

境界を越えるループは事実上一定時間です。これを超える前に存在する値はほんの少数であるためです。`10^18`。 

どこでも整数演算を使用することが不可欠です。 間隔境界付近の浮動小数点ルートは、次のような数値を誤って分類する可能性があります。`65535`そして`65536`。 

コードでも処理されます`x = 1`それは唯一負けているシングルパイルポジションだからです。
