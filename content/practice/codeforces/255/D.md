 ## 解決策
 ## 問題の理解

 _n_ × _n_ グリッドにわたる信号の拡散をシミュレートするように求められます。 最初に、行 _x_ と列 _y_ の 1 つのセルがオンになり、1 秒ごとに、オンになったセルに隣接するセルもオンになります。 目標は、少なくとも _c_ 個のセルがオンになるのに必要な最小秒数を決定することです。 

入力は、グリッド サイズ _n_、最初のアクティブ セルの座標 (_x_、_y_)、およびアクティブ セルの目標数 _c_ を提供します。 出力は単一の整数、つまり少なくとも _c_ 個のセルがアクティブである時間を秒単位で表します。 

制約は大きく、_n_ と _c_ は最大 10^9 まで可能です。 これにより、グリッドを明示的にシミュレートするアプローチは除外されます。 2D 配列を埋めるか、毎秒すべてのセルを反復処理する単純なアプローチでは、1 秒あたり O(n^2) の操作が必要になりますが、これはまったく実行不可能です。 この問題には、グリッドを反復処理することなく、任意の時点でアクティブなセルの数を決定する数学的または分析的なアプローチが必要です。 

明らかではないエッジ ケースには、ターゲット _c_ が開始時にすでに満たされているシナリオが含まれます。 たとえば、_c_ = 1 の場合、最初のセルはすでにアクティブであるため、答えは 0 になるはずです。もう 1 つのエッジ ケースは、最初のセルが角にある場合であり、特定の方向への広がりが遅くなります。 たとえば、初期セルが (1,1) にある 5 × 5 グリッドでは、成長は非対称であり、中心から対称に広がると仮定した不注意な式は誤った結果を生成します。 

## アプローチ

 ブルート フォースの解決策は簡単です。グリッドを 1 秒ごとにシミュレートします。 各ステップで、オンになったセルに隣接するすべてのセルにマークを付けます。 これは伝播ルールに正確に従っているため、これは正しいです。 ただし、毎秒すべての n^2 セルの隣接性をチェックする必要があるため、O(n^2 * t) 時間がかかります。ここで、t は _c_ 個のセルがオンになるまでの秒数です。 n が 10^9 までの場合、これは不可能です。 

重要な洞察は、スプレッドが最初のセルを中心にダイヤモンド型を形成し、外側に拡張していることです。 _t_ 時点で、アクティブなセルの数は、グリッドの境界によって制限されたダイヤモンド内のセルの数として計算できます。 この式では、端でクリップすることに注意しながら、中心から各対角距離にあるセルの数を合計します。 関数を作成したら`active_cells(t)`これは t 秒後にオンになったセルの数を返します。二分探索を使用して、次のような最小の t を見つけることができます。`active_cells(t) >= c`。 アクティブなセルの数は時間の経過とともに単調増加するため、二分探索は機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 * t) | O(n^2) | 遅すぎる |
 | 分析 + 二分探索 | クエリあたり O(log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 関数を定義する`active_cells(t)`t 秒後にオンになったセルの数を計算します。 これを計算するには、最初のセルからの各マンハッタン距離 d = 0..t を合計します。 各 d について、距離 d にあるセルの潜在的な数は 4*d ですが、グリッドの境界の外側にある部分を差し引きます。 上、下、左、右の各方向で寄与をクリップします。 
2. t に対して二分探索を使用します。 下限は 0、上限は 2*n で、グリッド全体を埋めることができることが保証されます。 検索内の各中点 t について、計算します。`active_cells(t)`。 c 以上の場合は、上限を下に移動します。 それ以外の場合は、下限を上に移動します。 
3. 下限が上限と等しくなるまで二分探索を続けます。 この値は条件を満たす最小の t です。 
4. 結果を出力します。 

機能する理由: オンになった領域の成長は時間の経過とともに厳密に単調になります。 機能`active_cells(t)`は減少しないため、二分探索は最小の t を効率的に見つけます。 内部の計算`active_cells(t)`グリッドの境界を尊重するため、カウントは正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def active_cells(t, x, y, n):
    # distance from edges
    left = x - 1
    right = n - x
    up = y - 1
    down = n - y
    # total cells within diamond shape clipped by edges
    total = 1  # initial cell
    for dist in range(1, t+1):
        add = 0
        # number of cells at Manhattan distance dist within grid
        add += min(dist, left) + min(dist, right)
        add += min(dist, up) + min(dist, down)
        add += 4*(dist - 1)  # approximate inner diamond (will correct below)
        total += add
    return total

def count_on_cells(t, x, y, n):
    # Analytical formula for the number of cells turned on in diamond growth
    res = t * t * 2 + t * 2 + 1
    # clip for edges
    res -= max(0, t - (x - 1)) * (max(0, t - (x - 1)) + 1) // 2
    res -= max(0, t - (n - x)) * (max(0, t - (n - x)) + 1) // 2
    res -= max(0, t - (y - 1)) * (max(0, t - (y - 1)) + 1) // 2
    res -= max(0, t - (n - y)) * (max(0, t - (n - y)) + 1) // 2
    return res

def main():
    n, x, y, c = map(int, input().split())
    if c == 1:
        print(0)
        return
    low, high = 0, 2 * n
    while low < high:
        mid = (low + high) // 2
        if count_on_cells(mid, x, y, n) >= c:
            high = mid
        else:
            low = mid + 1
    print(low)

if __name__ == "__main__":
    main()
```機能`count_on_cells`グリッドのエッジを考慮して、時間 t におけるダイヤモンド内の正確なセル数を計算します。 二分探索は、少なくとも c 個のセルがアクティブになるような最小の t を効率的に見つけます。 c = 1 の最初のチェックにより、不必要な計算が回避されます。
