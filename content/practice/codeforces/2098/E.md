 ## 解決策
 ## 問題の理解

 バミューダトライアングルの簡略化バージョンを、頂点が 2D 座標平面上の直角三角形としてモデル化するように求められます。$(0,0)$、$(0,n)$、 そして$(n,0)$。 平面はこの三角形の内側から始まります。$(x,y)$速度ベクトルで移動します$(v_x,v_y)$。 平面は継続的に移動し、三角形の辺 (頂点ではない) に当たるたびに、標準的な反射の法則に従ってその辺で反射します。つまり、辺に垂直な速度の成分は符号を反転しますが、平行な成分は変化しません。 目標は、飛行機が頂点の 1 つに正確に到達するかどうか (これを脱出と定義します)、到達する場合は、到達するまでに何回の反射を経験するかを判断することです。 

入力は最大で構成されます$10^4$テスト ケース、および各三角形の大きさは次のとおりです。$n=10^9$。 速度成分は最大の正の整数です。$10^9$。 これらの制約により、平面をステップごとに移動したり、反射ごとに反復したりするシミュレーション アプローチは除外されます。これは、エスケープ前の反射の数も非常に多くなる可能性があるためです。 直接シミュレーションを行うと遅すぎます。 

微妙な点は、平面が厳密に三角形の内側から始まることです。 これは、最初は境界上にないことを意味します。 もう 1 つの微妙な点は、頂点に触れるとエスケープとみなされ、反射としてカウントされないことです。 シミュレーションを不用意に行うと、3 つの側面すべてで反射を正しく処理する必要性を見逃したり、頂点に正確に到達した瞬間に反射を数え間違えたりする可能性があります。 

## アプローチ

 ブルートフォース手法では、三角形の辺との交点を計算し、反射ごとに速度ベクトルを更新することで、飛行機の動きをシミュレートします。 各ステップで、平面が頂点に到達するかどうかを確認します。 これは論理的には正しいですが、最大で$O(n)$またはより多くの反射が発生するため、実行不可能になります$n$まで$10^9$そして$10^4$テストケース。 

重要な洞察は、軌跡を明らかにすることから得られます。 すべての反射は速度成分を独立して反転するため、飛行機の動きは三角形の反射の「ミラーリングされた」グリッド内の直線に変換できます。 三角形を水平方向と垂直方向に反射させて平面全体に拡張すると、平面はある点に向かって直線に沿って移動します。$(k n, l n)$整数の場合$k,l$、頂点に到達することは、座標の合計が次の倍数に等しいこのグリッド内の格子点に到達することに対応します。$n$。 これにより、問題は一連の合同式を解くことに帰着し、中国剰余定理 (CRT) を使用して効率的に取り組むことができます。 

具体的には、負でない整数を見つける必要があります。$p$そして$q$そのような```
x + v_x * t ≡ 0 or n (mod 2n)
y + v_y * t ≡ 0 or n (mod 2n)
```なぜなら、各側面反射はモジュロ形式で座標を効果的に反映するためです。$2n$センス。 これにより、幾何学的反射問題が、計算効率の高い同時合同式を解く数論的問題に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォースシミュレーション | O(反射回数) | お(1) | 遅すぎる |
 | CRT 経由の直線 | O(log(max(n, v_x, v_y))) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$、$x$、$y$、$v_x$、$v_y$。 
2. 両方の座標のモジュロのターゲット合同を計算します。$2n$。 各座標には、頂点に到達する 2 つの可能性があります。$0$または$n$モジュロ$2n$。 のために$x$、 定義する`candidates_x = [0, n]`; $yで`, `候補者_y = [0, n]`。 
3. 候補の組み合わせごとに$x$と候補 $y` を使用して、2 つの合同系を解いてみます。```
x + v_x * t ≡ target_x (mod 2n)
y + v_y * t ≡ target_y (mod 2n)
```1. 拡張ユークリッド アルゴリズムを使用して線形合同式を解きます。 解が存在する場合は、非負の最小値を計算します。`t`両方の合同が満たされる場合。 これ`t`平面が頂点に到達する時間を表します。 
2. どの組み合わせにも解が存在しない場合は、出力`-1`。 
3. それ以外の場合は、反射の数を計算します。 各反射は、平面が頂点に到達せずに側面に衝突するたびに発生します。 直線の定式化では、反射の数は、頂点に到達する前に軌道が垂直境界と水平境界を横切る回数の合計です。```
reflections = ((x + v_x * t) // n - 1) + ((y + v_y * t) // n - 1)
```1. 反射回数を出力します。 

**機能する理由:** 側面全体で平面を繰り返し反射すると、平面のパスが直線になる平面のタイリングが作成されます。 このタイリングでは、頂点に到達することは、ミラー化された座標の合計が以下に等しい格子点に到達することと同等です。$n$モジュロ$2n$。 拡張ユークリッド アルゴリズムは、そのような格子点が存在する場合、効率的にそれを見つけることができることを保証します。 このアプローチでは、すべての反射のシミュレーションを回避し、最初に頂点に到達した時間を直接計算します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def extended_gcd(a, b):
    if b == 0:
        return (1, 0, a)
    x1, y1, g = extended_gcd(b, a % b)
    x, y = y1, x1 - (a // b) * y1
    return (x, y, g)

def solve_linear_congruence(a, b, m):
    x, _, g = extended_gcd(a, m)
    if b % g != 0:
        return None
    x0 = (x * (b // g)) % (m // g)
    return x0, m // g

def crt(a1, m1, a2, m2):
    x1, y1, g = extended_gcd(m1, m2)
    if (a2 - a1) % g != 0:
        return None
    lcm = m1 // g * m2
    t = (a1 + x1 * (a2 - a1) // g * m1) % lcm
    return t, lcm

def process_case(n, x, y, vx, vy):
    candidates_x = [0, n]
    candidates_y = [0, n]
    res = -1
    for cx in candidates_x:
        for cy in candidates_y:
            crt_res = crt((cx - x) % (2 * n), 2 * n, (cy - y) % (2 * n), 2 * n)
            if crt_res is not None:
                t, _ = crt_res
                reflections = ( (x + vx * t) // n - 1 ) + ( (y + vy * t) // n - 1 )
                if reflections < 0:
                    reflections = 0
                if res == -1 or reflections < res:
                    res = reflections
    return res

t = int(input())
for _ in range(t):
    n, x, y, vx, vy = map(int, input().split())
    print(process_case(n, x, y, vx, vy))
```このソリューションでは、まずモジュラー線形方程式を解くための拡張ユークリッド アルゴリズム関数を実装し、次にそれらを組み合わせる CRT 関数を実装します。 の`process_case`関数は、考えられる頂点合同を反復し、CRT を使用して平面が頂点に到達できる最も早い時間を計算し、各軸に沿った反射をカウントします。 反射は境界交差の数から計算され、三角形内の初期位置に合わせて調整されます。
