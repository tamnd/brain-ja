 ## 解決策
 ## 問題の理解

 各生徒は特定の日を決めます。ヴァディムは基本的に、その選んだ日の次の 2 日間に何が起こるかを「予測」しようとしています。 隠された重要な詳細は、実際の将来のプロセスは無関係であるということです。 重要なことは、すべての生徒に対して、ヴァディムは選択した日から始まる長さ 2 のウィンドウに対して 1 つの予測を実行する必要があるということです。 

したがって、すべてのインデックス値に対して$a_i$, Vadim は、間隔として 2 日のパターンを暗黙的に選択しています。$[a_i+1, a_i+2]$。 各生徒は、ヴァディムが選んだパターンがそのウィンドウ上の現実と一致するかどうかを個別に確認します。 バディムは、自分が選んだ予測がその生徒の窓に対して正しい場合にのみ、生徒との賭けに勝ちます。 

問題は実際のプロセスを予測することではありません。 実際のプロセスがどのような結果になったとしても、少なくとも 1 人の生徒が確実に満足できるように、ヴァディムが予測を選択できるかどうかが重要です。 これにより、問題は、長さ 2 のウィンドウで考えられるすべてのローカル結果をカバーする議論に変わります。 

制約により、テスト ケースごとに線形または線形に近い解決策が求められます。 合計から$n$テスト全体で最大$10^5$、テストごとのソートまたはハッシュベースのグループ化は許容されますが、単一のテストにわたる二次関数はすべて失敗します。 各ウィンドウには複数の可能な結果があり、同じ日または近い日の相互作用が組み合わせ的に爆発するため、生徒ごとの予測のすべての組み合わせを単純にチェックすることは直ちに不可能です。 

すべての生徒が繰り返しのない明確な日を選択する場合、微妙な特殊なケースが発生します。 例えば：```
1
3
1 2 3
```ここでは、各ウィンドウが分離されています。 直感的に、ヴァディムは複数の生徒を満足させるために予測を「再利用」することはできません。 正解は「いいえ」です。利用できる繰り返し構造がないからです。 

もう 1 つのエッジケースは、すべての生徒が同じ日を選択する場合です。```
1
4
5 5 5 5
```ここでは、長さ 2 の可能なパターンは 4 つしかないため、Vadim はさまざまな生徒に異なる予測を割り当て、少なくとも 1 つが次の 2 日間の実際の結果と一致することを保証できます。 正解は「はい」です。 

重要な違いは、考えられるすべてのローカル パターンを列挙できるような方法で重複が存在するかどうかです。 

## アプローチ

 直接推論しようとすると、各生徒は長さ 2 のウィンドウに対応します。 固定ウィンドウの場合、将来はバイナリ ペア (またはより一般的には、解釈に応じて少数の一定数の状態) として表すことができます。 重要な観察は、少なくとも 1 つのウィンドウで考えられるすべての結果がカバーされるように、十分な生徒に個別の予測を割り当てることができれば、ヴァディムは成功するということです。 

ブルートフォース解釈では、生徒ごとに予測を割り当て、考えられるすべての認識の下で、一部の割り当てが少なくとも 1 人の生徒の正確な一致を保証するかどうかを確認しようとします。 これはすぐに、選択されたインデックス全体で考えられるすべての 2-length パターンをカバーするという問題になります。 ポジションごとに考えられるすべてのパターンを明示的にシミュレートし、すべての課題を試してみると、構造を共有する生徒の数が増えるにつれて複雑さが指数関数的に増大し、たとえ$n = 10^5$。 

重要な単純化は、選択された日の多重度のみが重要であるということです。 1 日が複数回出現する場合、Vadim はそれらの生徒に異なる予測を配布できます。 異なる長さ 2 のパターンの数は一定であるため、成功を保証する唯一の方法は、一致を強制するために必要なすべての可能性をカバーするのに十分な繰り返しを少なくとも 1 日確保することです。 これにより、問題は頻度分布の確認のみに減ります。 

具体的には、この条件は、いずれかの日が少なくとも 4 回出現するかどうかを検証することになります。 直感的には、2 日間のプロセスの展開には 4 つの可能な方法があり (意図したモデルでの二値解釈)、同じ開始日に 4 つの独立したベットを行うことで、すべての結果をカバーできるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 割り当てに対するブルートフォース | 指数 | O(n) | 遅すぎる |
 | 周波数カウント | O(n log n) / O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての生徒を日ごとにグループ化する$a_i$。 これにより、各開始点にいくつの独立した賭けが存在するかが識別されます。 
2. それぞれの日の頻度を数えます。 
3. いずれかの頻度が少なくとも 4 であれば、Vadim が成功を保証できると直ちに結論付けます。 
4. それ以外の場合は、不可能であると結論付けます。 

ステップ 3 で十分な理由は、十分な同一の開始点がある場合にのみ、そのウィンドウで考えられるすべての結果をカバーするのに十分な個別の予測を割り当てることができるためです。 多重度が小さい場合は、少なくとも 1 つの考えられる結果が明らかにされません。 

### なぜ効果があるのか

 どの生徒も同じ$a_i$同じ未知の 2 日間のセグメントに対応します。 Vadim は、異なる生徒に異なる推測を割り当てることができますが、正確かどうかは、同じセグメントの実際の認識と一致するかどうかによって決まります。 2 日間のプロセスで実現できる可能性の数は一定かつ少ないため、勝利を保証するということは、少なくとも 1 つの繰り返されるセグメントでこれらの可能性を完全にカバーすることを保証することになります。 セグメントが十分に繰り返されない場合、どの割り当ても単一ウィンドウのすべての結果をカバーできないため、保証された勝利は不可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        
        freq = {}
        for x in arr:
            freq[x] = freq.get(x, 0) + 1
        
        ok = False
        for v in freq.values():
            if v >= 4:
                ok = True
                break
        
        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、ハッシュ マップを使用して、選択されたすべての日の頻度を集計します。 問題の構造は完全に繰り返しに依存しているため、これが必要です。 小切手`v >= 4`2 日間のウィンドウで考えられるすべての結果を確実にカバーするために必要な最小繰り返し回数を直接エンコードします。 

よくある実装上の間違いは、並べ替えてから、連続するブロックを手動で推論しようとすることです。 これは不必要であり、off-by-one エラーが発生する危険があります。 ここでのハッシュカウントはより簡単かつ安全です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        freq = {}
        for x in arr:
            freq[x] = freq.get(x, 0) + 1
        
        ok = any(v >= 4 for v in freq.values())
        out.append("Yes" if ok else "No")
    
    return "\n".join(out)
