 ## 解決策
 ## 問題の理解

 各有権者には、あなたを支持してもらうための 2 つの独立した方法があります。 有権者をアクティベートするために固定コストを直接支払うことができます。 あるいは、各有権者には要件値があり、この有権者が自由になる前に他の何人の有権者がすでにあなたを支持している必要があるかについてのしきい値として解釈できます。 

このプロセスは動的です。 一部の有権者のセットがアクティブになると、しきい値を満たしている他の有権者のロックを解除するのに役立ちます。 しきい値が満たされるたびに、その有権者は無料で参加し、これによりさらなるアクティベーションが引き起こされる可能性があります。 

タスクは、支払い総額を最小限に抑えながら、カスケードが最終的に全員をアクティブにするように、最初に支払う投票者を選択することです。 

入力により、投票者ごとに、しきい値とコストで構成されるペアが与えられます。 出力は、ロック解除ルールを繰り返し適用した後、すべての投票者がアクティブになることを保証するために必要な最小総コストです。 

この制約は、解がテスト ケースごとに線形または対数線形に近い必要があることを意味します。 すべてのテスト ケースにわたる n の合計は 2 × 10^5 であるため、すべてのテストにわたって O(n log n) よりも悪いアプローチは合格しません。 現在のアクティブ セットに対してすべての投票者を繰り返しチェックする単純なシミュレーションでは、O(n^2) まで劣化します。 

素朴な貪欲なアイデアによる一般的な失敗例は、1 人の投票者が安価であるにもかかわらず他の多くのロックを解除し、別の投票者が高価であるがすぐに残りのロックを解除する場合に発生します。 たとえば、ある投票者のしきい値は非常に大きいがコストは低く、別の投票者はしきい値は小さいがコストが高い場合、間違った初期シードを選択すると、不必要な購入が強制される可能性があります。 

もう 1 つの微妙なケースは、閾値 0 を持つ有権者がいない場合です。 この場合、常に少なくとも 1 つの有権者を購入する必要がありますが、わずかに高価な有権者を購入すると、将来複数回購入する必要性が減る可能性があるため、必ずしも最安の有権者である必要はありません。 

## アプローチ

 ブルートフォース戦略では、有権者のすべてのサブセットを最初に購入したセットとして試します。 各サブセットからプロセスをシミュレートします。追加できなくなるまで、しきい値が満たされた投票者を繰り返し追加します。 初期サブセットの合計コストを追跡し、完全なアクティベーションにつながるすべてのサブセットの最小値を取得します。 これは、考えられるすべての開始構成を明示的にチェックするので正しいですが、n では指数関数的であり、すぐには実行できません。 

重要な観察は、このプロセスは、どの特定の有権者がアクティブであるかではなく、すでにアクティブな有権者の数にのみ依存するということです。 各有権者はしきい値 m_i によって特徴付けられます。アクティブな数が m_i に達すると、有権者は自由になります。 これは、有権者をしきい値で分類し、少数の初期シードを支払った後に「無料でロックを解除」できる人数を推論することを示唆しています。 

この問題は次のように再解釈できます。数値 k を固定する場合、つまり、最終的に k 人の投票者が「自然に」アクティブ化されるようにしたい場合は、しきい値が k より大きい投票者に対してのみ料金を支払う必要があります。これは、k に達すると、他のすべての投票者が無料カスケードに含まれるためです。 強制的な支払いの中で、できるだけ安いものを選択します。 これにより、0 から n までの k にわたる候補が評価され、高速な更新を可能にする構造が維持されます。 

最適なソリューションでは、しきい値によるソートと動的構造 (通常は優先キューまたはプレフィックス蓄積) による貪欲な選択が使用されます。 m_i の昇順で投票者を処理し、まだ自動的に満たされていない有権者の中で最良の有給投票者のセットを維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての有権者を閾値 m_i で降順でない順に並べ替えます。 これにより、特定のレベルのアクティベーションを考慮すると、より低いしきい値を持つすべての有権者が支払いなしでアクティベートされる資格がすでに得られます。 
2. 現在支払い候補者として検討している有権者の費用を含む最大ヒープ (または最も高価な候補者を繰り返し選択するのと同等の構造) を維持します。 
3. ソートされた投票者を繰り返し処理します。 位置 i では、これを、最小のしきい値を持つ正確に i 人の有権者が直接支払いの圧力なしで最終的にアクティブ化されるシナリオとして解釈します。 
4. 遭遇した投票者ごとに、そのコストをヒープにプッシュします。 これは、この有権者が現在、無料カスケードでカバーできない場合に料金を支払う必要がある候補者であることを表しています。 
5. ヒープ内の有権者の数が、現在のしきい値レベルの下で未払いのままにすることが許可される有権者の数を超える場合、最も高価なコストをヒープから削除します。 これは、高価な有権者を「カスケード経由で無料」のままにし、代わりに安価な有権者に料金を支払うことを好むという考えをモデル化しています。 
6. 各ステップの後に、現在ヒープ内にあるコストの合計を追跡します。 すべての反復にわたる最小の合計が答えです。 

削除ステップの背後にある直観は、どの段階でも、限られた数の有権者のみが未払いのままでありながら、現在処理されているすべての低しきい値有権者が最終的にアクティブ化されることを許可する構成をシミュレートしているということです。 

### なぜ効果があるのか

 このアルゴリズムは、カスケードがそのしきい値レベルまでのアクティベーションの増加を維持できるという制約の下で、特定の値までのしきい値ですべての投票者を処理した後、ヒープがそれらの投票者のうちどの投票者に支払われるべきかの最適な選択を表すという不変条件を維持します。 キャパシティを超えた場合は常に最も高価な候補者を破棄することで、より高価な有償有権者を使用するソリューションは、実現可能性を損なうことなく、より安価な有権者と交換することで改善できることが保証されます。 この交換引数は、全体的な最適性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = []
        for _ in range(n):
            m, p = map(int, input().split())
            arr.append((m, p))

        arr.sort()

        import heapq
        heap = []
        total = 0
        ans = 10**30

        for i, (m, p) in enumerate(arr):
            heapq.heappush(heap, -p)
            total += p

            # we can keep at most (i+1) voters "covered" at this level
            if len(heap) > i + 1:
                total += heapq.heappop(heap)

            ans = min(ans, total)

        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、有権者をしきい値に基づいて並べ替え、カスケード解釈で「適格」になる順序で有権者を処理することを保証します。 必要なときに最大のコストを効率的に削除できるように、ヒープには負の符号を付けてコストが保存されます。 

変数`total`選択した有権者の合計を追跡します。 ヒープが大きくなりすぎると、最も高価なヒープが削除され、この投票者が料金を支払われる代わりにカスケードに残されることが事実上決定されます。 

各プレフィックスは「カスケードで到達」と「支払わなければならない」の間の可能な境界に対応するため、答えはプレフィックスごとに更新されます。

これは、低コストのシードを早期に含めることが、後でより良い構造が現れたときにどのように修正されるかを示しています。

 ## 特殊なケース

 n = 1 および m_1 = 0 の場合、前提条件は必要ないため、投票者は無料でアクティブ化されます。 このアルゴリズムは、単一のコストをヒープにプッシュし、そのコストの許容容量とすぐに比較し、削除せずに保持します。 カスケードでは初期支払いが必要ないため、最小の答えはゼロになります。 

すべての投票者が同じしきい値を持っている場合、並べ替えによって順序は変更されず、ヒープは均一に増加します。 容量を超えるたびに最も高価なコストが削除されますが、すべてのコストは等しいため、構造は安定したままになります。 最終的な答えは単に必要な 1 つのシードのコストであり、しきい値が満たされれば 1 人の投票者がカスケードをトリガーできるという直感と一致します。 

1 人の投票者のコストが非常に低いがしきい値が非常に高い場合、その投票者は最初はヒープに含まれますが、後でより安価な、またはより構造的に有用な選択肢を優先して削除されます。 これは、後のプレフィックス状態によって以前の選択が無効になる可能性があるため、初期の決定をロックしないことの重要性を示しています。
