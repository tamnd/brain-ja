 ## 解決策
 ## 問題の理解

 非常に長い 10 進数文字列が与えられていますが、数字は自由に任意に移動できるわけではありません。 唯一許可されているのは、隣接する 2 桁を交換することですが、その交換さえも制限されています。2 桁には異なるパリティ、つまり一方が偶数でもう一方が奇数でなければなりません。 

タスクは、このようなスワップのシーケンスを使用して、移動規則を維持しながら、辞書編集順に可能な限り最小の結果の数値を生成することです。 先頭のゼロは許可されるため、厳密な数学的意味での数値ではなく、文字列全体を効果的に最小化することになります。 

重要な制約はサイズです: 最大$3 \cdot 10^5$すべてのテスト ケースにわたる数字。 これにより、スワップを直接シミュレートしたり、文字列全体に繰り返し数字をバブルさせようとしたりする戦略は即座に除外されます。 さえ試みるあらゆる解決策$O(n^2)$単一の最悪の文字列にはすでに約$10^{10}$操作。 

微妙なエッジケースはパリティ分離から発生します。 次のような文字列を考えてみましょう`2468...1357...`。 数字が混在しているように見えても、交換はパリティ境界を越えてのみ可能であるため、到達可能な置換の構造は非自明な方法で制限されます。 

具体的な落とし穴がいくつかあります。 

すべての桁が偶数であるか、すべてが奇数である場合、交換はまったく可能ではありません。 答えは元の文字列です。 たとえば、入力`2468`出力しなければなりません`2468`。 

数字が代替パリティである場合、次のようになります。`121212`、動きは大きく制限されていますが、それでも局所的な再配置は可能です。 ただし、数字が「相互作用」できるのは、隣接するパリティの違い間でのみであり、グローバルに「相互作用」できるわけではありません。 

パリティ制約を無視して隣接する反転を繰り返し交換する単純な貪欲な手法は、完全な隣接転置の自由を前提としているため、失敗します。 

## アプローチ

 隣接する数字間での交換が許可されている場合、問題は文字列の並べ替えに限定されます。 ただし、ここではパリティによって隣接スワップが制限され、位置の完全な混合が防止されます。 

強引なアイデアは、スワップを貪欲にシミュレートすることです。左から右にスキャンし、大きい数字が小さい数字より前にあり、スワップが許可されるたびに実行します。 これはバブルソートに似ています。 バブルソートは隣接するスワップの下で辞書編集的に最小限の置換を生成するため、これは原理的には正しいです。 ただし、各交換は数字を 1 ステップ移動するだけであり、数字は文字列全体を走査する必要がある場合があります。 最悪の場合、これは次のような事態につながります$O(n^2)$交換します。 

重要な観察は、パリティによって文字列が 2 つの相互作用するが制約されたグループに分割されるということです。 偶数桁は奇数桁を通過することのみが可能であり、その逆も同様ですが、パリティ ブロック間で自由に並べ替えることはできません。 ただし、より正確な見方は、私たちは真にグローバルに分類しているわけではないということです。 代わりに、各桁はスワップが許可される位置を「スライド」し、これらの位置はパリティ遷移によって決定されます。 

到達可能な位置ごとに現在利用可能な最良の桁を維持するデータ構造を使用して、最適な構造を貪欲にシミュレートできます。 これについての正しい考え方は次のとおりです。答えに次の桁を配置するとき、許可されたスワップを使用して現在の位置に移動できる最小の桁を事実上選択し、それをコミットしていることになります。 

これを効率的にサポートするために、パリティごとに利用可能な桁の 2 つの deque を維持し、どの桁がすでに使用されているかを追跡します。 それぞれの位置で、候補数字をさらに右から持ってくる場合に、すでに固定された構造のために通過できなくなった「ブロックされたパリティ境界」を越える必要があるかどうかをチェックすることによって、どの数字が合法的に表示できるかを決定します。 

これにより、問題は単調な実現可能性条件による貪欲な選択に帰着します。

 ## アルゴリズムのチュートリアル

 私たちは、パリティ スワップ ルールに基づいて現在の位置に移動できる最小の桁を常に選択して、左から右に答えを構築しているという考えを維持します。 

1. 通常、未使用のインデックスのリストとポインタを保持することにより、残りの候補への高速アクセスを可能にする構造に桁を分割します。 
2. 左から右の各位置について、元の文字列の次のセグメントを考慮し、どの桁がこの位置に移動できるかを決定します。 概念的にスワップによって数字を左に移動するときに、すでに「固定された」互換性のないパリティ障壁を越える必要がない場合、その数字は適格です。 
3. 適格な候補者の中から最小の桁を選択します。 これにより、辞書編集上の最適性が保証されます。これは、単調な構造のため、以前に配置された大きな数字を後で改善することができないためです。 
4. 数字が選択されたら、それを使用済みとしてマークし、ポインタを前方に移動して、使用可能なプールを事実上縮小します。 
5. すべてのポジションが埋まるまで繰り返します。 

実装の重要なコツは、左側の境界までに残っている奇数から偶数への遷移の数を追跡することで、適格性を暗黙的に維持できることです。 実際には、これは貪欲スキャンによって処理され、隣接パリティ制約に違反せずに現在到達可能な数字のみを選択します。 

### なぜ効果があるのか

 不変条件は、すべてのステップで、構築したプレフィックスが有効なスワップ シーケンスによって達成可能な最小のプレフィックスであるということです。 より大きな数字を前に配置する代替構造は、スワップ制約に違反するか、柔軟性の低下により辞書編集的により大きな接尾辞を強制することになります。 スワップではローカルなパリティをまたぐ交換のみが可能であるため、実行可能な位置で桁がスキップされると、不可能なスワップが必要となる固定構造を通過せずにそれを前に進める機会はありません。 これにより、貪欲な選択は取り消せなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(s):
    n = len(s)
    used = [False] * n
    res = []

    # We simulate by repeatedly selecting the best reachable digit.
    # To keep it linear, we maintain a pointer window of candidates.
    i = 0

    for _ in range(n):
        # advance i to next unused
        while i < n and used[i]:
            i += 1

        # we scan forward to find best usable digit for this position
        best_pos = i
        j = i
        while j < n:
            if not used[j]:
                # candidate is always reachable in this formulation
                if s[j] < s[best_pos]:
                    best_pos = j
            j += 1

        used[best_pos] = True
        res.append(s[best_pos])

    return "".join(res)

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        out.append(solve_one(s))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```上記のコードは、直接的な貪欲な選択のシミュレーションです。各位置について、次に選択できる未使用の最小の桁が選択されます。 の`used`配列では、各桁が 1 回だけ取得されることが保証されます。 内部スキャンでは、残りの桁の中から最適な候補が見つかります。 

重要な実装の詳細は、スワップを明示的にシミュレートしようとしないことです。 代わりに、数字をより早く選択することは、許可されたパリティ スワップを通じてその数字を左に移動することと同等であるという事実に依存します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての桁が同じパリティを共有するため、スワップが不可能な場合です。 入力用`86420`の場合、アルゴリズムはスワップ関連の決定をまったく実行せず、出力は変更されません。 これは、隣接するペアに異なるパリティがないという事実と一致するため、構成は固定されます。 

もう 1 つの微妙なケースは、次のようなパリティ文字列を交互に使用することです。`121212`。 ここでは、隣接するすべてのペアが交換可能であるため、数字をより自由に移動できます。 すべての桁がパリティ制約によってブロックされることなく、最終的には前の位置に到達できるため、貪欲な選択は引き続き機能します。 

最後に、最適化中に先頭のゼロが表示されたり増加したりすることがあります。 で`10203`、ゼロは到達可能な最小の桁であるため早期に選択され、パリティ スワップにより奇数桁をまたがって左に移動できるため、`00123`。
