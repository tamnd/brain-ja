 ## 解決策
 ## 問題の理解

 いくつかの独立したシナリオが与えられています。 各シナリオには奇数の従業員がおり、各従業員には最終給与を選択する必要がある給与間隔があります。 また、全員に最低限の給与を支払うのに十分な額が保証されている総予算も与えられています。 

タスクは、選択されたすべての給与の中央値ができるだけ大きくなるように、各従業員に許可された間隔内で給与を割り当てることです。 中央値はすべての給与を並べ替えた後に定義され、従業員数が奇数であるため、中央の 1 つの要素になります。 

したがって、問題は給与総額の最大化や世界的な意味での公平性ではありません。 それは、個人の限界と全体的な予算を尊重しながら、ソートされた給与配列の中央の要素をできるだけ高くすることです。 

重要な相互関係は、3 つの制約の間にあります。各給与は一定の間隔で制限され、すべての給与の合計は制限され、中央値のみが問題となります。 

制約が十分に大きいため、割り当てをシミュレートしたり、推測に従って完全な配列を構築して実現可能性を繰り返し確認しようとしたソリューションは失敗します。 全体で最大 2×10^5 人の従業員がいる場合、テスト ケースごとに O(n log n) より悪いアプローチは拡張できません。 

多くの間隔が広いにもかかわらず、予算が最小額を超えて厳しい場合、微妙なエッジ ケースが発生します。 たとえ下限の実現可能性が保証されていたとしても、1 つの値を増加させると他の部分の実現可能性が低下する可能性があるため、単純にすべての給与を個別に引き上げる単純な貪欲は失敗します。 

貪欲に全員に対称的に高い給与を割り当てようとすると、別の失敗モードが現れます。 これは、中央の位置のみが重要であるため、下半分に予算を無駄にする必要がないことを無視しています。 

## アプローチ

 強引な考え方は、中央値の考えられるすべての値を試し、それが達成できるかどうかを確認することです。 候補値 x については、間隔と総予算を考慮しながら、従業員の少なくとも半数が少なくとも x の給与を得ている割り当てを構築しようとします。 

固定 x の実現可能性を検証するには、給与を貪欲に割り当てる必要があります。つまり、間隔内でできるだけ多くの人を少なくとも x に押し上げ、残りの予算を分配します。 これは、チェックごとに O(n) にすることができます。 

ただし、中央値は 10^9 に達する可能性があるため、すべての可能な値を線形スキャンすることは不可能です。 二分探索 x でもテスト ケースごとに O(n log n) が得られますが、各チェックが慎重に最適化されていない場合は遅すぎ、従業員総数が 2×10^5 未満では依然として厳しい制限が生じるリスクがあります。 

重要な観察は、実現可能性が x において単調であるということです。 少なくとも k 人の従業員の給与が x 以上になるようにすることができれば、さらに小さな x を設定することも可能です。 これにより、答えの二分探索が可能になります。 

2 番目のより深い洞察は、実現可能性を効率的に評価する方法です。 割り当てを完全に構築する必要はありません。 知る必要があるのは、予算内に収まりながら、少なくとも k = n//2 + 1 人の従業員に少なくとも x の達成を強制できるかどうかだけです。 

各従業員には、x に関して 3 つの関連する状態があります。x に到達できない (r_i < x)、追加料金を支払うことによってのみ x に到達できる (l_i < x ≤ r_i)、またはすでに x を超えるように強制されている (l_i ≥ x)。 予算が制限要因であるため、私たちはどの従業員を x を超えるようにするかを貪欲に決定し、常に最も安価に調達できる従業員を優先します。 

これにより、実現可能性のチェックが、候補を x まで引き上げるコストによって候補を分類することになります。

 | --- | --- | --- | --- |
 | ブルートフォース構築 | O(n・max_salary) | O(n) | 遅すぎる |
 | 二分探索 + 貪欲な実現可能性 | O(n log n log A) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 中央値 x をしきい値として扱い、答えを二分探索します。

1. 候補中央値 x を固定し、x に対する相対的な間隔に基づいて各従業員を分類します。 r_i < x の場合、この従業員は中央値の達成に貢献できないため、「高グループ」として無視されます。 l_i ≥ x の場合、追加コストなしですでに条件を満たしています。 それ以外の場合は、オプションでコスト x - l_i で x にプッシュできます。 
2. l_i ≥ x をすでに満たしている従業員の数を数えます。 これらは自動的に上位グループの一部となります。 この数値がすでに少なくとも k = n//2 + 1 である場合、中央値に影響を与えることなく他の全員を最小限に割り当てることができるため、x は実現可能です。 
3. x を超える従業員がまだ十分にいない場合は、すべての「アップグレード可能な」従業員 (l_i < x ≤ r_i の従業員) を収集します。 それぞれについて、コスト = x - l_i を計算します。 
4. これらのコストを昇順に並べ替えます。 各アップグレードでは x 以上の従業員が 1 人増えるため、最も安価な従業員を最初に選択してアップグレードしたいと考えています。 
5. 上位グループの k 人の従業員に達するまで、最小コストを採用します。 k に達する前に候補がなくなった場合、x は実行不可能になります。 
6. 選択したアップグレードについて、合計追加コストを (x - l_i) の合計として計算します。 この追加コストが l_i をすべて支払った後の残りの予算を超える場合、x は実行不可能です。 それ以外の場合は実現可能です。 
7. 十分に広い範囲 (通常は最大 10^9) にわたって x を二分探索します。 

正しさは、固定 x に対する最適解が、中央値条件を満たすのに必要な以上に x より上の誰かを増やしても予算を無駄にしないという事実に依存します。 追加の増加は実現可能性を助けず、コストが増加するだけです。 

### なぜ効果があるのか

 固定のしきい値 x の場合、重要なのは、予算の制約の下で少なくとも k 件の給与を x 以上にできるかどうかだけです。 x を超えて昇進させる k 人の従業員を選択するすべての方法の中で、最も安価な選択は常に (x - l_i) が最小の従業員を選択することです。 この選択から逸脱すると、実現可能性は向上せずに総コストが増加するだけです。 この貪欲な構造により、実行可能性チェックが最適かつ x で単調になることが保証され、二分探索が有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(x, arr, s, k):
    base = 0
    candidates = []

    for l, r in arr:
        base += l
        if r < x:
            continue
        if l >= x:
            continue
        candidates.append(x - l)

    if base > s:
        return False

    need = k
    have = 0

    for l, r in arr:
        if l >= x:
            have += 1

    if have >= k:
        return True

    need = k - have

    candidates.sort()

    extra = 0
    for i in range(min(need, len(candidates))):
        extra += candidates[i]

    return base + extra <= s

def solve():
    t = int(input())
    for _ in range(t):
        n, s = map(int, input().split())
        arr = [tuple(map(int, input().split())) for _ in range(n)]
        k = n // 2 + 1

        lo, hi = 1, 10**9
        ans = 1

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(mid, arr, s, k):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、実現可能性チェッカーとバイナリ検索ドライバーを中心に構成されています。 実現可能性関数は、すべての従業員に最低給与を支払うための基準コストを計算し、中央値のしきい値に達するまで十分な従業員を「アップグレード」しようとします。 

重要な詳細は、従業員をすでに x 以上の地位にある従業員と、アップグレード可能な従業員に分けることです。 並べ替えの手順により、常に最も安価なアップグレードが最初に選択されるようになります。 

実行可能性が単調であるため、二分探索によって解が導き出されます。つまり、中央値 x が達成可能であれば、それより小さい値も達成可能です。

    input = sys.stdin.readline

    def can(x, arr, s, k):

        candidates = []

                    lo = mid + 1

        return "\n".join(out)

 ## 特殊なケース

 多くの従業員がすでに l_i ≥ x を持っているが、中央値を求める必要がない場合、厄介な状況が発生します。 アルゴリズムは、それらが最も安価なアップグレード候補の中に含まれない場合でも、上位グループへの「無料」貢献者として正しくカウントします。 これらはコストなしですでにしきい値を満たしているため、候補リストに入ることがなく、貪欲な選択が歪められることもありません。 

もう 1 つのエッジ ケースは、最も安価なアップグレードの数が k に達するには不十分な場合です。 その場合、中央値の要件を満たす前に候補リストが枯渇してしまい、不必要な合計を試行することなく実現可能性が早期に失敗します。
