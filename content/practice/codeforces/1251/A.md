[CF 1251A - キーボードの故障](https://codeforces.com/problemset/problem/1251/A)

 **評価:** 1000
 **タグ:** ブルート フォース、文字列、2 つのポインター
 **解決時間:** 5 分 7 秒
 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 誰かがキーボードのキーを 1 つずつ押した後に画面に表示される最終的な文字列が与えられます。 各キーはラテン文字の小文字に対応しており、各キーは入力プロセス全体で常に正常であるか、常に壊れています。 

正常なキーの動作は単純です。キーを押すと、その文字のコピーが 1 つだけ出力に追加されます。 壊れたキーはより攻撃的です。キーを押すたびに、その文字のコピーが 1 つではなく 2 つ追加されます。 最後の文字列は、未知のキー押下シーケンス全体でこれら 2 つの動作を混合した結果です。 

タスクは、キーを押すシーケンスを再構築することではありません。 代わりに、最終的な文字列のあらゆる説明において、どの文字が健全なキーに対応することが保証されているかを識別する必要があります。 文字を出力しても安全なのは、文字列を 1 文字と 2 文字に分割する有効な分解において文字が分割されることが不可能な場合に限られます。 

重要な問題は、同じ文字列が、出現箇所を 1 つの文字として扱うか、2 つの文字として扱うかによって、複数の方法で説明できることがよくあることです。 単一の文字が文字列全体で一貫して解釈される場合もあれば、一貫性なく解釈される場合もあるため、この決定は見た目はローカルですが、制約はグローバルです。 

文字列の長さは最大 500 で、テスト ケースは最大 100 個あるため、ケースごとのソリューションは O(n^2) または O(n) で十分です。 すべての分解を列挙する必要はないため、解釈の選択肢に指数関数的なものは不要です。 

単純な間違いは、文字が時々単独で表示される場合、その文字は健全であるに違いない、または隣接するすべての同一文字のペアは壊れたキーから来ているに違いないと考えることです。 ペアリングの決定が文字列全体で独立していないため、どちらの解釈も失敗します。 

たとえば、次の文字列を考えてみましょう。`aabb`。 こう思うかもしれない`a`次のように表示されるため壊れています`aa`、 そして`b`次のように表示されるため壊れています`bb`。 しかし`aabb`4 つの健全な印刷機からも発生する可能性があります。`a a b b`、両方の文字が健全になります。 したがって、ローカルのグループ化では不十分です。 

もう 1 つの微妙な失敗例は、次のような交互のパターンです。`abab`。 ここでは、どちらの文字もペアを形成できないため、両方が正常である必要がありますが、可能な限りペアにしようとする貪欲なスキャンでは、両方が壊れているか曖昧であると誤ってマークされる可能性があります。 

## アプローチ

 直接的な総当たりアプローチでは、あらゆる方法で文字列をサイズ 1 または 2 のセグメントに分割し、各セグメントが 1 つの文字の繰り返しであることを確認します。 各パーティションは、各印刷機が 1 つまたは 2 つの文字を生成したかどうかを推測することに対応します。 有効なパーティションを生成した後、どの文字が破損または正常であると一致する形で出現し、すべてのパーティションにわたって交差するかを推定できます。 

各位置が 2 つの選択肢に分岐する可能性があり、最悪の場合 O(2^n) 分解につながるため、これはすぐに実行不可能になります。 枝刈りを行っても、次のような文字列の有効なセグメント化の数は減少します。`aaaaaa...`指数関数的に成長します。 

重要な点は、すべての有効な分解を明示的に構築する必要はないということです。 代わりに、すべての有効な説明において文字を強制的に分割できるかどうかを判断するだけで済みます。 同様に、プレスごとに正確に 1 文字を一貫して生成するという説明がつかない文字も必要です。 

重要な単純化は、文字の出現を完全に同一の連続する文字の素のペアに分割できる場合にのみ安全ではないことを観察することです。つまり、すべての出現をサイズ 2 のブロックにグループ化できることを意味します。 文字の少なくとも 1 つの出現が同一の隣接文字とペアにできない場合、その文字は正常である必要があるという有効な解釈が存在します。 

したがって、文字ごとに、文字列内のすべての文字が、互いに素な隣接するペアで完全にカバーできるかどうかを確認するだけで済みます。 それが不可能な場合、そのレターは少なくとも 1 つの有効な解釈において健全であることが保証されているため、必要な出力には含まれません。 逆に、すべての出現を完全にペアにすることができる場合は、解釈によっては文字が完全に壊れる可能性があるため、健全であるとは保証されません。 

これにより、問題は線形スキャンに帰着します。つまり、文字列全体の隣接するペアで出現する文字が完全に一致するかどうかを検出します。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 文字列をスキャンし、文字ごとに、その文字が出現するすべてのインデックスを記録します。 これにより、他のものからの干渉を受けることなく、キャラクターごとのペア構造を推論することができます。 
2. 固定文字の場合は、元の文字列の左から右へ貪欲にペアリングをシミュレートしてみます。 位置 i に文字が表示されるたびに、i と i+1 の両方に同じ文字が含まれているかどうかを確認します。 「はい」の場合、これを 1 つの壊れたキー ブロックとして扱い、両方の位置をスキップします。 そうでない場合、この発生は壊れたペアの一部であるはずがないため、単一の押下として扱う必要があります。 
3. スキャン中に、単一の出現をペアに一致させることができないが、構造全体で一貫してシングルトンとして安全に扱うこともできない状況に遭遇した場合、文字がどこでも壊れていると完全に説明できないと結論付けます。 つまり、安全であり、回答に含める必要があります。 
4. 26 文字すべてに対してこのプロセスを個別に繰り返します。 
5. 「完全にペアリング可能」条件を満たさないすべての文字を収集し、アルファベット順に出力します。 

### なぜ効果があるのか

 重要な不変条件は、壊れた文字は、同じ文字の連続したペアの中に出現する必要があるということです。 文字が本当に壊れている場合、壊れたプレスでは 2 つの連続する同一の文字が生成されるため、すべての出現は有効な隣接ペアの一部である必要があります。 1 つの出現でも孤立しているか、隣接関係の一貫性が壊れている場合、その文字が常に壊れている分解は存在しません。つまり、健全な解釈が少なくとも 1 つあることを意味します。 したがって、隣接するペアで完全にカバーできる文字のセットは、健全であることが保証されていない文字に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_fully_pairable(s, ch):
    i = 0
    n = len(s)
    while i < n:
        if s[i] != ch:
            i += 1
            continue
        if i + 1 < n and s[i + 1] == ch:
            i += 2
        else:
            return False
    return True

t = int(input())
for _ in range(t):
    s = input().strip()
    res = []
    for c in "abcdefghijklmnopqrstuvwxyz":
        if is_fully_pairable(s, c):
            res.append(c)
    print("".join(res))
```機能`is_fully_pairable`出現するすべての文字を隣接するペアとして使用できるかどうかをチェックします。 ポインタ`i`文字列の中を移動し、貪欲に消費します`cc`可能な限りペアで。 スタンドアロンの出現が現れると、その文字が常に壊れているものとして解釈される可能性が失われます。 

メイン ループは、このテストを 26 文字すべてに単純に適用し、それを満たす文字を収集します。

## 特殊なケース

 主なエッジケースは、文字が奇数の長さで連続して表示される場合です。 例えば、`aaa`完全に分割することはできません`aa`ブロックし、残りのオカレンスを 1 つ残します。 アルゴリズムは、単一の不一致を検出したため、これを即座に検出します。`a`1 つのペアを消費した後、完全なペアの解釈でその文字に対して失敗を返します。 

別のエッジケースは次のようなインターリーブです`ababa`。 どちらの文字も頻繁に出現しますが、どちらも一貫した隣接するペアを形成することはできません。 スキャンは各文字が最初に単独で出現した時点で失敗し、両方が正常な候補として正しく分類されることが保証されます。 

最後の微妙なケースは、ローカルではペアリングが可能だが、グローバルでは一貫性がない場合です。 例えば`aabbaabb`完全なペアリングが可能ですので、`a`はペアリング可能としてマークされていますが、`abac`ペアリングを中断する`a`隔離された場所ですぐに`c`移行し、誤った分類を防ぎます。
