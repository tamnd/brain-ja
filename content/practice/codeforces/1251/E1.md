 ## 解決策
 ## 問題の理解

 一連の投票者が与えられ、各投票者は 2 つの方法のいずれかでアクティブ化できます。 彼らを説得するために固定コストを直接支払うか、依存関係を利用することができます。つまり、十分な数の他の有権者がすでに説得されていれば、彼らは無料で参加することになります。

 正式には、各投票者にはコストがかかります$p_i$私たちが彼らの票を直接購入すれば。 あるいは、しきい値があります$m_i$、少なくとも一度は自動的に確信することを意味します$m_i$他の有権者はすでに支持セットに入っています。 有権者が参加すると、他の有権者の基準を満たすことができるため、プロセスを段階的に進めることができます。 

目標は、総コストを最小限に抑えながら、このカスケードが最終的に全員をアクティブにするように、購入する最初の有権者のセットを選択することです。 

このプロセスは動的で順序に依存しますが、しきい値が尊重されている限り、有効なアクティブ化シーケンスは許可されます。 これは、事実上「シード セット」を選択し、単調なクロージャー プロセスによってそれを拡張していることを意味します。 

制約は非常に具体的な意味で重要です。 合計あり$n$最大 5000 回のテストにわたって、$O(n^2)$または$O(n^2 \log n)$解は受け入れられますが、3 次関数やグローバル状態の繰り返しの再計算を伴うものは失敗します。 

素朴な推論による微妙な失敗例は、貪欲なローカル決定を仮定することです。$m_i$または$p_i$独立して。 たとえば、いつも一番安いものを買う$p_i$現在実行不可能な有権者の間では機能しません。$m_i$後で無料になり、他の多くのロックが解除される可能性があります。 

もう 1 つの危険なケースは、次のような有権者のみを考慮すべきであると仮定することです。$m_i = 0$初め。 これらは無料のスターターではありますが、それらだけに依存すると、少し高価な有権者を早期に購入すると、多くの購入を回避する大きなカスケードが解除される可能性があることが無視されます。 

## アプローチ

 核心的な問題は、有権者を買収することで他の多くの有権者の実現可能性が変わってしまうということだ。 これは、投票者をアクティブ化する順序が重要であることを示唆していますが、最終的なコストは順序とは独立したものにしたいため、プロセスを再解釈する必要があります。 

この強引なアイデアは、最初に購入した有権者のすべてのサブセットを試し、伝播をシミュレートし、すべての有権者がアクティブになるかどうかを確認することです。 これは正しいですが、次のような理由から実行不可能です。$2^n$サブセットと各シミュレーションのコスト$O(n^2)$、指数関数的な爆発につながります。 

重要な洞察は、視点を逆転させることです。 どの有権者を最初に購入するかという観点から考えるのではなく、各有権者の「無料アクティベーション条件」を検討する際に、すでにアクティベートした有権者の数という観点から考えます。 現在のアクティブ化された有権者の数を維持すれば、有権者が現在無料であるか、それとも有権者に料金を支払わなければならないかを決定できます。 

これは、貪欲なスケジュール解釈につながります。 私たちは、活性化した有権者の集団を繰り返し増やしていきます。 各段階で、しきい値を満たした投票者の中から次にどの投票者をアクティブにするかを決定します。そうでない場合は、プロセスを開始するために誰かに料金を支払う必要があります。 

これを効率的に行うために、有権者をしきい値によって並べ替えます$m_i$。 すでにアクティベートされている有権者の数が増えると、より多くの有権者が無料で参加できるようになります。 まだ対象になっていない人の中から、購入する人を選ぶ必要があるかもしれないので、できるだけ安い価格のものを選びたいと考えています。$p_i$。 

この構造は、「利用可能な制約」というプレフィックスを増加させながら、現在ロック解除可能な選択肢または必要な選択肢の中から最も安価なコストを繰り返し選択することに似ています。 

これを実装する標準的な方法は、次の基準で並べ替えることです。$m_i$、新しく利用可能な投票者に対するポインタを維持し、その投票者に対するデータ構造 (ミニヒープ) を使用します。$p_i$。 私たちは常に最初に無料の有権者を獲得しようとし、行き詰まった場合には入手可能な最も安価な候補者を購入するというプロセスをシミュレートします。

 | ソート + ヒープで貪欲 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちはこのプロセスを、活性化された有権者の最終セットを段階的に構築するものとして扱います。 

1. すべての有権者をしきい値で並べ替えます$m_i$昇順で。 これにより、すでにアクティブ化されている有権者の数が増加しても、新しくロック解除された有権者を効率的に発見できるようになります。 
2. このソートされたリストをスキャンするポインタを維持し、投票者を追加します。$m_i$最大でも、候補者プールにアクティブ化された現在の有権者の数です。 
3. 実現可能性については最大の優先順位を保ち、コストについては最小の構成を維持します。現在利用可能だがまだアクティブ化されていないすべての有権者のうち、支払いが必要な場合には、可能な限り最も安価な有権者を選択したいと考えます。 
4. 各ステップで、しきい値が満たされている投票者が存在するかどうか (すなわち、$m_i \le \text{current activated count}$）、無料で追加できます。 私たちは、支払いを検討する前に、そのような有権者をすべて消費することを繰り返しています。 
5. 無料の有権者が新たにいない場合は、料金を支払う有権者を 1 人選ばなければなりません。 最小限のものを選択します$p_i$まだ活動化していない有権者全員の中で。 支払い後、有効化カウントを 1 つ増やして続行します。 
6. アクティブ化するたびにさらに多くの有権者のロックが解除される可能性があるため、すべての有権者がアクティブ化されるまで繰り返します。 

### なぜ効果があるのか

 重要な不変条件は、いつでも、その正確なセット サイズを達成するあらゆる方法の中でコストが最小となるアクティブな投票者のセットを維持するということです。 有権者なら誰でも$m_i \le$現在のサイズは、最適なソリューションにおいては無料にならざるを得ません。料金を支払っても将来の実現可能性を向上させることはできないからです。 そのような投票者が存在しない場合は、初期コストがかからないと進行できない状態になりますので、最小の投票者を選択することになります。$p_i$すべての選択肢がアクティブ化数の増加につながりますが、異なるのは即時のコストだけであるため、これが最適です。 この貪欲な構造は、しきい値が ID ではなくカウントのみに依存するため安全であり、状態はアクティブな有権者の数によって完全に要約されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = []
        for i in range(n):
            m, p = map(int, input().split())
            a.append((m, p))
        
        # sort by threshold
        a.sort()
        
        import heapq
        i = 0
        taken = 0
        ans = 0
        heap = []
        
        while taken < n:
            while i < n and a[i][0] <= taken:
                heapq.heappush(heap, a[i][1])
                i += 1
            
            if heap:
                ans += heapq.heappop(heap)
                taken += 1
            else:
                # no available free candidates, must pick next by threshold
                # push next batch
                heapq.heappush(heap, a[i][1])
                i += 1
                ans += heapq.heappop(heap)
                taken += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```ソートのステップにより、現在アクティブ化されている有権者の数が増加するたびに、しきい値を満たしているすべての有権者をすぐに取り込むことができます。 ヒープには、現在資格のあるすべての有権者のコストが保存され、常に最小コストを選択することは、この段階で複数の有権者を無料でアクティブ化できる場合、またはアクティブ化の候補になる場合、購入が必要なときに最も安価な有権者を優先する必要があることを反映しています。 

微妙な部分は、ヒープが空の場合のフォールバックです。 これは、現在無料でアクティベートできる有権者がいないフェーズに相当するため、しきい値がまだ高すぎる人を購入してアクティベーションを強制する必要があります。 この購入後、州が変わり、以前は到達できなかった有権者が有権者になる可能性があります。

```活動化した有権者がゼロの状態から始めます。 

| ステップ | 撮影 | 利用可能 (ヒープ) | アクション | コスト |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | {} | 最初の候補を購入する必要があります | 5 |
 | 2 | 1 | {8} | 一番安いものを取る | +8 |
 | 3 | 2 | {10} | 取る | +10 |

 ただし、最適なシーケンスでは、最初に投票者 3 (コスト 8) を購入し、次に 1 が無料になり、次に 2 になります。ヒープベースのプロセスにより、強制的な移動の中から常に最小のコストが選択され、合計 8 が得られます。 

これは、強制アクティベーションの順序が重要であることを示していますが、ヒープにより、次善の強制シードが決して選択されないことが保証されます。

 ## 特殊なケース

 重要なエッジケースは、現時点で閾値条件を満たす有権者がいない場合です。 たとえば、すべてが$m_i$サイズが大きい場合、アルゴリズムは初期化後に空のヒープを持ちます。 その状況では、フォールバック ステップにより、システムの「ロックを解除」するための任意の次の候補の選択が強制されます。 正しい処理は、少なくとも 1 つの候補をヒープにプッシュした後、使用可能な最小の強制オプションを直ちに選択することです。 

1 回のアクティベーションにより複数の有権者が同時に資格を得る場合には、別の微妙なケースが発生します。 このアルゴリズムは、決定を下す前に新たにロック解除されたすべての有権者を継続的にプッシュすることでこれを処理し、適格な低コスト有権者がスキップされないようにします。
