 ## 解決策
 ## 問題の理解

 それぞれが固定の整数の長さを持つ複数のホワイト ボード セットと、非常に小さなレッド ボードのセットが与えられます。 これらの板から「山の形」のフェンスを形成したいと考えています。 フェンスでは赤いボードを 1 枚だけ使用します。これはシーケンス内で一意の最大要素である必要があります。 使用されるすべての白いボードは、厳密に赤いボードよりも小さくなければなりません。 

有効なフェンスの構造は、赤いボードまでは厳密に増加し、それ以降は厳密に減少します。 したがって、赤いボードはビットニック シーケンスのピークとして機能します。 すべての有効なフェンスは、赤いボードを選択し、次に左側に昇順で配置するいくつかの白ボードと、降順で右側に配置するいくつかのボード (値の選択肢は重複している可能性がありますが、位置は重複していません) を選択することによって完全に決定されます。 

外周は、選択されたすべてのボードの長さの合計として定義されます。 各クエリは、特定の偶数値について、その合計値を持つ個別の有効なフェンスがいくつあるかを尋ねます。 

この制約により、問題は明らかに総当たり攻撃ではなくなります。 最大 30 万のホワイト ボードと 30 万のクエリを設定でき、ボードの長さと目標合計は最大約 120 万になります。 サブセットまたはシーケンスを列挙する解決策は直ちに不可能です。 最大値範囲の二次関数であっても、畳み込みまたはプレフィックスサム形式の前処理を使用して慎重に最適化しない限り、遅すぎます。 

多くのホワイト ボードが同じ長さである場合、微妙なエッジ ケースが発生します。 構造を個別の位置として扱う単純なアプローチでは、構造を誤ってカウントしすぎてしまう可能性があります。 もう 1 つの落とし穴は、同じマルチセットが対称的にどのように寄与するかを注意深く追跡せずに、左右の選択間の独立性を仮定することです。 

## アプローチ

 強引な解釈では、赤いボードを 1 つ選択し、有効な配置パターンを持つ白いボードのすべてのサブセットを列挙します。 各サブセットについて、それを左側の増加部分と右側の減少部分に分割します。これは基本的に、単調性制約を尊重する順序を選択することになります。 順序付けの問題を無視し、マルチセットの観点からのみ考えたとしても、依然として最大 300,000 要素にわたるサブセットの列挙に直面することになり、これは指数関数的になります。 

より構造的なビューは、最初に赤いボードを固定することで得られます。 長さ R の赤いボードを固定するとします。使用するすべてのホワイト ボードは厳密に R より小さくなければならないため、値ドメインの接頭辞に制限します。 ここで、フェンスの構造は、より強力なものを暗示しています。どのホワイト ボードを左に配置し、どのホワイト ボードを右に配置するかを選択すると、両側は独立して厳密に増加または減少しますが、順序は並べ替えによって決定されるため、重要なのは各側で選択されたマルチセットのみです。 

したがって、固定 R の場合、寄与は、値 < R を持つ利用可能なホワイト ボードのマルチセットを 2 つのマルチセットに分割する方法を数えることに帰着します。1 つは左側に、もう 1 つは右側に割り当てられ、両方とも総和制約に寄与します。 

f_R[x] を、選択されたすべての要素が < R である合計 x を持つホワイト ボードのサブセットを選択する方法の数を示す場合、左側と右側は両方とも同じプールの独立したサブセットになります。 唯一の追加条件は、両面が空であり、赤ボードが必ず 1 回含まれることです。 

したがって、固定 R の場合、合計白和 S を持つフェンスの数は畳み込みになります。S の合計 = S_left + S_right of f_R[S_left] * f_R[S_right]。 まさに f_R の自己畳み込みです。 

これにより、問題全体が、各赤いボードのしきい値制約の下でサブセット和生成関数を計算し、それ自体で畳み込み、最後に赤いボード全体の寄与を累積することに帰着します。

重要な問題は、赤の値ごとに f_R を最初から再計算すると時間がかかりすぎることです。 洞察としては、R 値の数が小さい (k ≤ 5) ため、すべてのホワイト ボードに対してグローバル サブセット DP を 1 回事前計算してから、値に対してプレフィックス制限を使用できるということです。 各値クラスは出現ごとに多項式係数 (1 + x^{a_i}) を提供するため、周波数配列を維持し、FFT に適した畳み込みを使用して値に対する累積多項式を構築します。 

接頭多項式 F_R が得られると、各クエリの答えは、F_R * F_R の (Q - R) における係数の赤いボード R 上の合計になります。 

k が小さいため、最終ステップではすべてのクエリに対して最大 5 つの畳み込みを合計します。これは、オフライン FFT 評価を使用して効率的に抽出できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | プレフィックス DP + コンボリューション (FFT) | O(V log V + k V log V) | O(V) | 承認済み |

 ## アルゴリズムのチュートリアル

 ホワイトボードの長さを周波数配列 freq[x] に圧縮します。 V を最大長とします。 

一連のプレフィックス生成関数を構築します。 各関数は、値が最大 x のホワイト ボードを使用して、すべてのサブセットの合計を表します。 

1. 多項式 P_0 から始めます。P_0[0] = 1 (空のサブセットを意味します) です。 
2. 1 から V までの値を処理します。各値 v に対して、freq[v] 個の同一の項目があります。 (1 + x^v)^{freq[v]} を乗算することで、それらを現在の多項式に組み込みます。 これにより、長さ v の任意の数のボードが含まれるか除外されるように、すべてのサブセットの合計が更新されます。 

freq[v] が大きくなる可能性があるため、累乗は多項式の 2 進累乗を使用して行われます。 各乗算は、FFT ベースの畳み込みを使用して実行されます。 

1. 各接頭辞多項式 P_v を保存します。これは、値 ≤ v のみを使用してすべてのサブセットの合計をエンコードします。 
2. 白いボードは厳密に小さくなければならないため、各赤いボード R について F = P_{R-1} をとります。 
3. G_R = F * F を計算します。この畳み込みは、左側と右側に 1 つずつ、サブセットの順序付きペアをカウントします。 
4. 各クエリ Q について、すべての R を合計した、各赤いボード R の G_R[Q - R] が必要です。 
5. k ≤ 5 であるため、各 G_R を個別に計算し、直接検索によってクエリに答えます。 

### なぜ効果があるのか

 すべての有効なフェンスは、赤いボード R と、R より小さい値を持つ 2 つの独立した白いボードのサブセット (1 つは左に割り当てられ、もう 1 つは右に割り当てられます) の選択によって一意に決定されます。 単調性制約により、追加の自由度を持たずに各辺内でのソートにより有効な構成が生成されることが保証されます。 合計周長は R に両方のサブセットの合計を加えたものとして分解され、畳み込みはサブセット合計の順序付きペアをすべて正確にカウントします。 プレフィックス制限により、無効なホワイト ボードが赤色のしきい値を超えないことが保証されるため、無効な構成はカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAXV = 300000

# NTT implementation (standard iterative form)
def ntt(a, invert):
    n = len(a)
    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            a[i], a[j] = a[j], a[i]

    length = 2
    root = 3
    root_inv = pow(root, MOD - 2, MOD)

    while length <= n:
        wlen = pow(root if not invert else root_inv, (MOD - 1) // length, MOD)
        i = 0
        while i < n:
            w = 1
            for j in range(length // 2):
                u = a[i + j]
                v = a[i + j + length // 2] * w % MOD
                a[i + j] = (u + v) % MOD
                a[i + j + length // 2] = (u - v) % MOD
                w = w * wlen % MOD
            i += length
        length <<= 1

    if invert:
        inv_n = pow(n, MOD - 2, MOD)
        for i in range(n):
            a[i] = a[i] * inv_n % MOD

def convolution(a, b):
    n = 1
    while n < len(a) + len(b) - 1:
        n <<= 1
    A = a + [0] * (n - len(a))
    B = b + [0] * (n - len(b))
    ntt(A, False)
    ntt(B, False)
    for i in range(n):
        A[i] = A[i] * B[i] % MOD
    ntt(A, True)
    return A

n, k = map(int, input().split())
w = list(map(int, input().split()))
reds = list(map(int, input().split()))
q = int(input())
queries = list(map(int, input().split()))

freq = [0] * (MAXV + 1)
for x in w:
    freq[x] += 1

# Build prefix polynomials
P = [None] * (MAXV + 1)
P[0] = [1]

for v in range(1, MAXV + 1):
    base = [1]
    poly = [1]
    # multiply (1 + x^v)^{freq[v]} by repeated squaring
    for _ in range(freq[v]):
        poly = convolution(poly, [1, 0] + [0] * (v - 1))
    P[v] = convolution(P[v - 1], poly)

# Precompute self convolutions for each red
G = []
for r in reds:
    base = P[r - 1]
    G.append(convolution(base, base))

# Answer queries
res = [0] * q
for i, Q in enumerate(queries):
    ans = 0
    for j, r in enumerate(reds):
        if Q - r >= 0 and Q - r < len(G[j]):
            ans += G[j][Q - r]
    res[i] = ans % MOD

print("\n".join(map(str, res)))
```コードはまず、ホワイト ボードの長さの頻度カウントを構築します。 次に、v までの値を使用してすべてのサブセットの合計をエンコードするプレフィックス多項式 P[v] を構築します。更新ごとに、現在の多項式に長さ v のすべてのボードの寄与を乗算します。 

赤いボードごとに、関連するプレフィックス多項式を抽出し、自己畳み込みを計算します。 この畳み込みは、サブセットを左側と右側に割り当てるすべての方法を直接表します。 

最後に、各クエリは、どの赤いボードが周囲の一致する分割に寄与できるかをチェックすることによって回答されます。 

最もデリケートな実装の詳細は、畳み込みサイズを揃えておくことです。 すべての多項式は、可能な最大合計までの完全な係数配列として扱われなければなりません。そうしないと、有効な組み合わせが切り捨てられます。 

## 実用的な例

 ### 例 1

 入力:

 n = 3、白 = [1、1、2]、赤 = [3]、Q = 6

 白 {1,1,2} からサブセットの合計を構築します。 

サブセットは合計を生成します。 

0、1、2、3、4

 したがって、F = P_2 となります。 

自己畳み込み F * F は順序付きペアの数を求めます。 

| S_左 | S_右 | 合計 + 赤(3) |
 | --- | --- | --- |
 | 0 | 3 | 6 |
 | 1 | 2 | 6 |
 | 2 | 1 | 6 |

 したがって、Q = 6 の答えは 3 です。 

これは、左側と右側への順序付けされた分割が畳み込みによってどのように自然に処理されるかを示しています。 

### 例 2

 入力:

 白 = [2,2,2]、赤 = [4]、Q = 10

 サブセットの合計:

 F = {0,2,4,6}

 自己畳み込み:

 合計 6 を生成するペア:

 (0,6)、(2,4)、(4,2)、(6,0)

 赤4を加えると合計10になります。 

したがって、答えは 4 です。 

これは対称性を裏付けています。つまり、左と右は同じサブセット空間の独立した同一のコピーです。

 ## 特殊なケース

 ホワイト ボードの長さが繰り返される場合、それらは別個の恒等オブジェクトとして扱われるのではなく、多項式のべき乗に吸収されるため、アルゴリズムはそれらを正しく処理します。 

適格な白ボードがない非常に小さな赤いボードの場合、接頭辞多項式は単一の定数項に崩壊し、自己畳み込みは自明な空-左-空-右の構成のみを正しく生成します。 

すべての白の値を超える大きな赤いボードの場合は、完全な多項式が使用され、フィルタリング エラーが発生しないことが保証されます。
