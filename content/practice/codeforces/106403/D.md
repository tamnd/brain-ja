 ## 問題の理解

 この問題では、検出力値の集合に関する多くの独立したチェックに答えるように求められます。 一連の異なる数字があります。 1 回の操作で 2 つの異なる値を選択する`a`そして`b`新しい値を作成します。$$a \cdot b + 2(a+b)$$各クエリ値について`x`、元のセットのペアが正確に生成できるかどうかを判断する必要があります。`x`。 これは、Codeforces の問題 106403D、「パワーアップ」の問題です。 [Codeforces 問題アーカイブ](https://codeforces.com/gym/106403/problems)

 この式はすべてのペアをチェックする必要があるように見えますが、隠れた代数構造があります。 次のように書き換えることができます。$$a \cdot b + 2a + 2b + 4 - 4$$これは次のようになります:$$(a+2)(b+2)-4$$それでクエリ`x`まさにいつでも可能です`x + 4`は、配列からシフトされた 2 つの異なる値の積として表すことができます。 

入力サイズが大きいです。 まであります`2 * 10^5`値と同じ数のクエリ。 すべてのペアを試行するソリューションのパフォーマンスは約`n^2`オペレーション、それは周りにあります`4 * 10^10`最大の場合は、通常の 2 秒の制限をはるかに超えています。 線形または線形に近いソリューションが必要です。`q * small_factor`時間。 

シフトされた値`p_i + 2`せいぜい`200002`、これは可能な最大クエリ値よりもはるかに小さいです。 これは、利用可能なすべてのシフト値を高速メンバーシップ構造に保存できることを意味します。 各クエリについて、考えられる要素を検索するだけで済みます。`x + 4`。 

よくある間違いは、選択した 2 つの要素が異なっていなければならないことを忘れることです。 たとえば、配列が次の場合:```
1

## アプローチ

 簡単なアプローチは、要素のすべてのペアをテストすることです。 2 つの値ごとに`a`そして`b`、計算します`a*b + 2(a+b)`そして結果を保存します。 その後、各クエリは定数時間ルックアップになります。 

考えられるすべての組み合わせが明示的に考慮されるため、このアプローチは正しいです。 問題は組み合わせの数です。 と`n = 200000`、ペアの数はおよそ次のとおりです。$$\frac{n(n-1)}{2}$$それは約です`2 * 10^10`操作。 制限内で走行することは不可能です。 

重要な観察は次のような変換です。$$a*b+2(a+b)= (a+2)(b+2)-4$$すべてのペア積を生成する代わりに、プロセスを逆にします。 お問い合わせの場合`x`かどうかを知る必要があります。`x+4`には 2 つの要素があり、どちらもシフトされた配列値です。 

シフトされた値は十分に小さいため、セットに格納できます。 クエリに答えるために、因数分解します`x+4`そしてその約数を調べます。 クエリ値は最大でも約であるため、`10^9`、平方根は約`31623`, そのためファクタリングは速いです。 約数の場合`d`存在し、両方とも`d`そして`(x+4)/d`利用可能なシフト値がある場合、答えは「YES」です。 また、2 つの要素が等しくないことも確認します。

 ## アルゴリズムのチュートリアル

 1. 電力値を読み取り、すべての値を変換します`p`の中へ`p + 2`。 これらの変換された値をセットに保存します。 この変換により、元の 2 次式の代わりに乗算を使用できるようになります。 
2. クエリごとに`x`に置き換えてください`target = x + 4`。 有効な答えには、次のような積が得られる 2 つの格納された変換値が必要となります。`target`。 
3. すべての約数の候補を試してみる`d`から`1`まで`sqrt(target)`。 もし`d`分割する`target`、マッチング係数は`target / d`。 
4.両方あるかどうかを確認します`d`そして`target / d`変換された値セットに存在します。 存在し、2 つの値が異なる場合は、元のペアが存在するため、YES を出力します。 
5. すべての約数をチェックしても有効なペアが見つからない場合は、NO を出力します。 

平方根までのチェックだけで十分である理由は、すべての因子ペアが平方根以下の値と平方根以下の値を 1 つずつ持つためです。 ペアの小さい方の辺を見つけることで、完全なペアが見つかります。 

機能する理由: 変換により、元の問題の正確な状態が維持されます。 すべての有効なペア`(a, b)`になる`(a+2, b+2)`、そして彼らの製品はまさに`x+4`。 逆に、次のすべての有効な因子ペアは、`x+4`2 を減算して、2 つの元の値にマップし直します。 セットにはシフトされた元の値が正確に含まれているため、除数検索ではペアが存在する場合にのみペアが見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    vals = list(map(int, input().split()))

    present = set()
    for v in vals:
        present.add(v + 2)

    ans = []
    for _ in range(q):
        x = int(input())
        target = x + 4
        ok = False

        d = 1
        while d * d <= target:
            if target % d == 0:
                other = target // d
                if d in present and other in present and d != other:
                    ok = True
                    break
            d += 1

        ans.append("YES" if ok else "NO")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```セット`present`元のパワーではなく、変換された値を保存します。 これにより、クエリのたびに代数を繰り返すことがなくなります。 

クエリごとに、`target`は、シフトされた 2 つの数値に分割する必要がある値です。 ループは、次の時点まで除数のみをチェックします。`d*d`を超える`target`、考えられるすべての因子ペアをカバーします。 

条件`d != other`元のペアでは 2 つの異なる要素を使用する必要があるため、これが必要です。 元の累乗はすべて異なるため、2 つの等しくシフトされた値が異なる要素から得られることはありません。 

Python の整数は、最大の中間値が保持されるため、乗算と除算を安全に処理します。`10^9`。

## 特殊なケース

 利用可能な値が 1 つである場合、アルゴリズムは、同じシフトされた値を 2 回使用する因数分解を決して受け入れません。 入力では:```
1 1
1
5
```目標は`9`、シフトされた唯一の値は`3`。 それでも`3 * 3 = 9`、因子が等しいため、アルゴリズムはそれを拒否します。 

ターゲットが素数である場合、意味のある因子が 2 つ存在することはあり得ません。 例えば：```
2 1
1 2
7
```シフトされた値は次のとおりです。`3`そして`4`。 ターゲットは`11`、このセットには約数のペアがないため、答えは NO です。 

成功したケースの場合:```
2 1
1 3
11
```シフトされた値は次のとおりです。`3`そして`5`。 ターゲットは`15`、除数検索で次のことがわかります。`3 * 5`, したがって、答えはYESです。 これにより、変換が元の式と正確に一致することが確認されます。
