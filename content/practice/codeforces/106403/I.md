 ## 解決策
 # 問題の理解

 タイルのバイナリ文字列があります。 タイルは直線上に配置され、一定の距離で動作が制御されます`k`。 いくつかのタイルに立っている`p`、タイルを反転できます`p`タイルと一緒に`p + k`2 番目のタイルが存在する限り。 フリップするたびに、ライン上のどこにでも移動でき、移動距離をエネルギーとして支払います。 フリップ自体にコストがかかります`m`エネルギー。 

目標は、特定の取り決めに達することではありません。 必要なのは、文字列にできるだけ多くの文字列を残す一連の移動とフリップを選択することだけです。`1`タイルをできるだけ消費しながら、`E`エネルギー。 

操作グラフが主要な構造です。 インデックスの剰余モジュロが同じであるタイル`k`連鎖を形成します:```
r -> r+k -> r+2k -> ...
```反転は常に、これらのチェーンのいずれかにある 2 つの隣接する頂点に影響します。 

制約はこの観察に基づいて設計されています。 文字列の長さは最大でも`500`、テスト ケースのすべての長さの合計は最大で`1000`したがって、3 次時間に関する解決策は許容されます。 追加の保証は、`floor(n/k) <= 50`すべてのチェーンが最大でも`51`タイル。 これにより、チェーン内の指数関数的な処理が防止され、フリップ回数にわたる動的プログラミングが可能になります。 

エネルギー制限は次のように大きくなります。`10^18`, したがって、エネルギーをDP次元として使用することはできません。 すべてのフリップの価格は同じであるため、重要なコストはフリップの数です。 代わりに、動きは構造的に処理される必要があります。 

一部の特殊なケースは見落とされやすいものです。 

手頃な価格のフリップがない場合、答えは単純に既存のフリップの数です。`1`タイル。 例えば：```
n = 3, k = 1, E = 0, m = 5
s = 101
```出力は`2`。 常に少なくとも 1 つの操作を試行するソリューションでは、誤って答えが減少してしまいます。 

もし`m = 0`、フリップは無料で、移動のみがエネルギーを消費します。 例えば：```
n = 4, k = 1, E = 2, m = 0
s = 0000
```位置に移動できます`2`最初の 2 つのエッジを自由に使用して、`1110`、したがって、答えは次のとおりです`3`。 治療中`E / m`ゼロを処理しないと失敗します。 

チェーンに奇数のタイルがある場合、1 のパリティを変更することはできません。 例えば：```
n = 3, k = 1, E = 100, m = 1
s = 000
```出力は`2`、 ない`3`。 すべての操作が正確に 2 つのタイルを反転するため、チェーン全体のパリティは不変です。 

# アプローチ

 直接的な総当りのアプローチでは、可能なすべてのフリップ セットが試行されます。 まであります`n-k`可能な反転位置があるため、最悪の場合、何百ものバイナリの選択肢が存在します。 それらを列挙するには、約`2^(n-k)`それは、小さな制約さえ許す範囲をはるかに超えています。 

ブルートフォースが魅力的である理由は、選択された反転にはそれぞれ 2 ビットを変更するという単純な効果があるためです。 難しいのは、選択肢間の相互作用です。 1 つのエッジを選択すると、同じチェーン内の隣接するエッジの有用な効果が変化するため、独立した貪欲な決定は機能しません。 

最初の重要な削減は動きから生じます。 いくつかの反転位置のセットを選択するとします。 選択された最大の位置を次のようにします`x`。 ポジションから始める`0`に向かってまっすぐ歩きます`x`途中ですべての小さな位置を訪問するため、余分な動きをせずに選択したすべてのフリップを実行できます。 移動コストはまさに`x`。 その後戻る理由はありません。 

これにより問題が変わります。 あらゆる可能な最も遠いフリップ位置を試すことができます`x`。 支払い後`x`移動エネルギーを最大化するには、ポジション間で限られた数のフリップを使用して 1 の数を最大化するだけで済みます。`x`。 

2 番目の観察は、フリップは次の値で区切られた位置のみを接続するということです。`k`、つまり、各モジュロ-`k`チェーンは独立しています。 固定のフリップ制限の場合、すべてのチェーンを個別に解決し、使用されるフリップの数にわたってその答えをナップザック DP と組み合わせます。 

すべての操作シーケンスは選択されたエッジによって記述できるため、ブルート フォースは機能しますが、選択の数が指数関数的であるため失敗します。 チェーンの分解と動きの観察により、問題はパス上の小さな動的プログラムに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n^3) | O(n^2) | 承認済み |

 # アルゴリズムのチュートリアル

 1. 最初の 1 の数を数えます。 何もしないことは許されるので、これは常に可能な答えです。 
2. 考えられる最大のフリップ位置をすべて考慮する`x`。 もし`x`エネルギーはすでに高すぎるのでやめてください。 値`x`これは私たちが訪れる必要がある最も遠い地点を表しています。 
3. 移動コストを支払った後に何回フリップできるかを計算します。 もし`m`ポジティブです、これは`(E - x) // m`。 もし`m`がゼロの場合、利用可能なすべてのフリップを使用できます。 
4. 同じ剰余モジュロを持つインデックスに基づいて文字列をチェーンに分割します。`k`。 各チェーンについて、そのチェーンから利用可能な特定の数のフリップを正確に使用した後に取得できる 1 の最適な数を計算します。 
5. すべてのチェーンをナップザック DP と結合します。 DP インデックスは費やされたフリップの数です。 すべてのチェーン結果について、その可能なフリップ数をグローバル状態に追加してみてください。 
6. 現在のところ`x`、エネルギー バジェットで許可されているすべてのフリップ カウントを確認し、答えを更新します。 

これが機能する理由は、反転が 2 つの異なるモジュロ間で交差しないためです。`k`鎖。 各チェーンに割り当てられたフリップの数が固定されると、チェーンは相互に影響を与えることができなくなります。 唯一の共有リソースはフリップの合計数であり、これがまさにナップザックの組み合わせです。 

なぜ効果があるのか:

 選択した一連の操作について、次のようにします。`x`フリップが始まる最大の位置になります。 選択されたすべての開始位置は最大でも`x`、から歩いて`0`に`x`すべてのフリップを正確に実行できるようにします`x`移動コスト。 残りの予算はフリップの数のみを制限します。 

1 つのチェーン内で、その利用可能なエッジのあらゆる選択がパス DP によって考慮されます。 すべてのチェーンの最適な結果を組み合わせることで、エッジの考えられるすべてのグローバル選択がカバーされます。 すべての有効な操作シーケンスはアルゴリズムによって考慮される状態の 1 つに対応するため、生成される最大値は最適になります。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def build_chain_dp(bits, available_edges, limit):
    n = len(bits)
    dp = [[-10**9] * 2 for _ in range(limit + 1)]
    dp[0][0] = 0

    for i in range(n):
        ndp = [[-10**9] * 2 for _ in range(limit + 1)]
        if i < available_edges:
            choices = (0, 1)
        else:
            choices = (0,)

        for used in range(limit + 1):
            for prev in range(2):
                cur = dp[used][prev]
                if cur < 0:
                    continue
                for take in choices:
                    if used + take <= limit:
                        value = bits[i] ^ prev ^ take
                        ndp[used + take][take] = max(
                            ndp[used + take][take],
                            cur + value
                        )
        dp = ndp

    ans = [0] * (limit + 1)
    for used in range(limit + 1):
        ans[used] = max(dp[used][0], dp[used][1])
    return ans

def solve_case(n, k, E, m, s):
    bits = [int(c) for c in s]
    answer = sum(bits)

    chains = []
    for r in range(k):
        chain = []
        pos = r
        while pos < n:
            chain.append(bits[pos])
            pos += k
        if chain:
            chains.append((r, chain))

    cache = {}

    max_start = n - k - 1
    for x in range(max_start + 1):
        if x > E:
            continue

        if m == 0:
            flips = n
        else:
            flips = min(n, (E - x) // m)

        if flips < 0:
            continue

        global_dp = [-10**9] * (flips + 1)
        global_dp[0] = 0

        for r, chain in chains:
            if r <= x:
                edges = min(len(chain) - 1, (x - r) // k + 1)
            else:
                edges = 0

            key = (r, edges, flips)
            if key not in cache:
                cache[key] = build_chain_dp(chain, edges, flips)

            values = cache[key]

            ndp = [-10**9] * (flips + 1)
            for a in range(flips + 1):
                if global_dp[a] < 0:
                    continue
                for b in range(flips - a + 1):
                    if values[b] >= 0:
                        ndp[a + b] = max(ndp[a + b], global_dp[a] + values[b])
            global_dp = ndp

        answer = max(answer, max(global_dp))

    return answer

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, k, E, m = map(int, input().split())
        s = input().strip()
        out.append(str(solve_case(n, k, E, m, s)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```この解決策は、まず文字列をモジュロに分割します。`k`鎖。 各チェーンは、状態が反転されたエッジの数と前のエッジが反転されたかどうかを記憶する小さな DP によって解決されます。 頂点は 2 つの隣接するエッジにのみ依存するため、前のエッジ フラグで十分です。 

外側のループは、可能な限り最も遠い反転位置をすべて試します。 変数`flips`移動コストを支払った後に利用できる操作の最大数です。 特別な場合`m == 0`ゼロによる除算を回避し、到達可能なすべての反転を正しく許可します。 

ナップザックのマージはチェーンの答えを結合します。 のインデックス`global_dp`これまでに使用されたフリップの合計数です。 すべての有効なフリップ カウントの最大値により、選択した最も遠い位置で最良の結果が得られます。
