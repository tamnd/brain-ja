 ## 解決策
 ## 問題の理解

 都市のツリーがあります。 隕石は、初期エネルギーによって一度だけ都市に衝突する可能性があります。 ヒット後、その都市の貢献度は 1 秒ごとに 1 ずつ減少します。 クエリでは、特定の時点での指定された 2 つの都市間の一意のパス上のすべての都市の合計寄与度が求められます。 入力によりツリーが得られ、その後に流星の挿入とパスのクエリが続きます。 すべてのパス クエリの出力は、そのパス上の現在の電力の合計です。 

流星の価値は時間とともに変化するため、流星を直接解釈するのは不便です。 重要なのは、その貢献を書き直すことです。 隕石が街に落ちたら`x`時に`t0`価値のあるもの`val`、その後、時間に`t`その貢献は次のとおりです。`val - (t - t0) = (val + t0) - t`被害を受けた都市ごとに、寄与度は固定数から現在時刻を引いたものになります。 パス クエリでは、パス上のすべての固定数値の合計と、パス上でヒットした都市の数という 2 つのことが求められます。 パスに次のものが含まれている場合、`cnt`ヒットした都市とその固定値の合計は`s`、答えは次のとおりです。`s - t * cnt`制約により、これを迅速に処理する必要があります。 まで`100000`都市と`200000`クエリを実行し、すべてのパス上のすべての都市をチェックすると、時間がかかりすぎます。 単一のパスには以下を含めることができます`O(n)`すべてのクエリに対してこれを行うと、次の範囲に到達します。`2 * 10^10`最悪の場合の運用。 操作ごとに対数仕事が必要です。 

ツリー構造は、より高速な方法が存在する理由です。 都市の動的なポイント更新とパス合計クエリが必要です。 これは、重光分解がツリー パスを少数の配列間隔に変換し、フェンウィック ツリーまたはセグメント ツリーが必要な合計を答えることができるようにするまさに状況です。 

微妙なケースは、単一の都市を含むパスです。 入力の場合:```
2
1 2
3
1 5 2 10
2 5 2 2
2 10 1 1
```最初のクエリは都市 2 に流星を作成します。時刻 5 での値は次のとおりです。`10`。 2 から 2 へのパスには都市 2 のみが含まれるため、答えは次のようになります。`10`。 異なるノード間のパスのみを処理する不注意な実装では、誤ってゼロが返される可能性があります。 

もう 1 つのエッジ ケースは、流星が存在する前のクエリです。```
3
1 2
2 3
2
2 100 1 3
2 100 2 2
```どちらの答えも`0`。 この構造体は、存在しない流星に時間式を適用するのではなく、手つかずの都市に対してゼロを返す必要があります。 

3 番目の重要なケースは、マイナスの寄与です。```
2
1 2
2
1 0 1 -5
2 10 1 2
```流星の貢献度は、`-5 - (10 - 0) = -15`、したがって、答えは次のとおりです`-15`。 ステートメントでは負の累乗が許可されているため、値をゼロにクランプする実装はここで失敗します。 

## アプローチ

 ブルートフォース手法により、すべての都市の流星情報が保存されます。 パス クエリの場合、一方のエンドポイントからもう一方のエンドポイントまで歩き、訪問したすべての都市の現在の寄与を合計します。 これは正しいです。ツリーには 2 つの都市の間に単純なパスが 1 つだけあるからです。 

問題は散歩代です。 ツリー内のパスにはすべてを含めることができます。`n`都市なので、1 つのクエリにかかる時間は`O(n)`時間。 と`q`まで`200000`、最悪の場合は`O(nq)`、大きすぎます。 

各流星の寄与が固定部分と時間依存部分に分離できるという観察により、問題は変わります。 変化する値を保存する代わりに、次の 2 種類の更新をサポートするだけで済みます。 

都市は固定値を受け取ります`val + t0`。 

都市は次の増分を受け取ります。`1`活動中の流星の数。 

パスの場合、最初の値の合計とカウントの合計が必要です。 ヘビー ライト分解は、すべてのツリー パスを配列内の複数の連続した範囲にマップします。 フェンウィック ツリーは、ポイント更新と範囲クエリを使用してこれらの範囲を維持できます。 1 つのフェンウィック ツリーを固定値用に保持し、もう 1 つをカウント用に保持します。 

パス上のすべての都市が検査されるため、強引な方法が機能します。 パスが大きすぎるため失敗します。 ツリー パス分解では、次のことだけを調べることができます。`O(log n)`セグメントに分割されており、各セグメントのクエリは次のように処理されます。`O(log n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n) | O(n) | 遅すぎる |
 | 最適 | クエリあたり O(log² n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 街に木を根付かせる`1`そして深さ優先検索を実行します。 すべての都市の親、深さ、サブツリーのサイズ、および重い子を計算します。 重い子は、そのサブツリーが最大の子です。これは、重いエッジをたどると、パス クエリが対数の部分のみに分割されるためです。 
2. ツリーを重いパスに分解します。 すべての都市に基本配列内の位置を割り当てます。 各都市の現在の重いパスの上部頂点を保存します。 ツリー パスは、この配列内の複数の連続した間隔として表現できるようになりました。 
3. 基本配列上に 2 つのフェンウィック ツリーを作成します。 最初は固定流星の値を保存します`val + t0`各都市で。 2 番目の関数は、都市が攻撃を受けたかどうかを保存します。`1`ヒットした都市と`0`さもないと。 
4. 流星のクエリを処理するときに、両方のフェンウィック ツリー内のターゲット都市の位置を更新します。 固定値ツリーが受け取るのは`val + t`、カウントツリーは受信します`1`。 
5. パス クエリを処理するときに、より深い重いパスを繰り返し上に移動します。 セグメントごとに、両方のフェンウィック ツリーをクエリし、その結果を追加します。 両方のエンドポイントが同じ重いパスに到達したら、それらの間の残りの間隔を処理します。 
6. 集めた定額額を`s`収集されたヒット数は`cnt`。 最終的な答えは、`s - t * cnt`。 

なぜ効果があるのか:

 不変条件は、フェンウィックの木には、すでに攻撃を受けたすべての都市に必要な情報が常に正確に含まれていることです。 ヒット都市が貢献`val + t0`最初の木へ、そして`1`2本目の木へ。 したがって、パス クエリはすべての合計を取得します。`(val + t0)`用語と用語の数。 すべての流星が寄与するため、`(val + t0) - t`現時点での減算`t`ヒットした都市ごとに 1 回、正確なパスの合計が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 2)

    def add(self, i, v):
        n = self.n
        while i <= n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        res = 0
        while i:
            res += self.bit[i]
            i -= i & -i
        return res

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

n = int(input())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

parent = [0] * (n + 1)
depth = [0] * (n + 1)
size = [1] * (n + 1)
heavy = [-1] * (n + 1)

stack = [1]
order = [1]
parent[1] = -1

while stack:
    u = stack.pop()
    for v in g[u]:
        if v != parent[u]:
            parent[v] = u
            depth[v] = depth[u] + 1
            stack.append(v)
            order.append(v)

for u in reversed(order):
    best = 0
    size[u] = 1
    for v in g[u]:
        if v != parent[u]:
            size[u] += size[v]
            if size[v] > best:
                best = size[v]
                heavy[u] = v

head = [0] * (n + 1)
pos = [0] * (n + 1)
cur = 0

stack = [(1, 1)]
while stack:
    u, h = stack.pop()
    while u != -1:
        head[u] = h
        cur += 1
        pos[u] = cur
        for v in g[u]:
            if v != parent[u] and v != heavy[u]:
                stack.append((v, v))
        u = heavy[u]

bit_value = Fenwick(n)
bit_count = Fenwick(n)

def query_path(a, b):
    total_value = 0
    total_count = 0

    while head[a] != head[b]:
        if depth[head[a]] < depth[head[b]]:
            a, b = b, a
        h = head[a]
        total_value += bit_value.range_sum(pos[h], pos[a])
        total_count += bit_count.range_sum(pos[h], pos[a])
        a = parent[h]

    if depth[a] > depth[b]:
        a, b = b, a

    total_value += bit_value.range_sum(pos[a], pos[b])
    total_count += bit_count.range_sum(pos[a], pos[b])

    return total_value, total_count

q = int(input())
ans = []

for _ in range(q):
    data = list(map(int, input().split()))
    if data[0] == 1:
        _, t, x, val = data
        bit_value.add(pos[x], val + t)
        bit_count.add(pos[x], 1)
    else:
        _, t, a, b = data
        s, cnt = query_path(a, b)
        ans.append(str(s - t * cnt))

print("\n".join(ans))
```フェンウィック ツリーの実装では、1 つの位置への値の追加とプレフィックスの合計の取得がサポートされています。 重光分解はすべてのパスをいくつかの配列間隔に変換するため、これらの操作で十分です。 

深さ優先検索は、チェーン形状のツリーでの再帰の深さの問題を回避するために繰り返し実行されます。 最初のトラバーサルはサブツリー情報を計算し、2 番目のトラバーサルは重いパスの位置を割り当てます。 

パス クエリ関数は常に、より深いチェーンを上に移動します。 浅いチェーンを移動しても最下位の共通祖先への進行が保証されないため、これは順序付けの重要な選択です。 両方のノードが最終的にヘッドを共有すると、パスの残りの部分は 1 つの連続した間隔になります。 

すべての値は整数として保存されます。 Python は大きな整数を自動的に処理します。流星の値と時間の値の両方が大きくなり、最終的な合計が 32 ビットの制限を超える可能性があるため、これが必要になります。

```フェンウィックの木は両方とも空です。 パスクエリは固定合計を返します`0`そして数えます`0`、与える`0 - 100 * 0 = 0`。
