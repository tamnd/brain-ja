 ## 解決策
 ## 問題の理解

 いくつかの独立した整数が与えられます。 各整数 x について、その平方根の整数部分を計算し、それを k = ⌊√x⌋ と呼びます。 タスクは、x が「贅沢」であるかどうか、つまりこの k で割り切れるかどうかを判断することです。 

したがって、入力は一連の数値であり、それぞれについて、x mod ⌊√x⌋ が 0 に等しいかどうかの二項決定を出力します。 

構造は意図的に最小限に抑えられています。 各クエリは独立しているため、状態の共有や累積的な影響はありません。 通常、出力は入力と同じ順序の一連の回答です。 

このタイプの問題の制約スタイルは通常大きく、多くの場合最大 10^5 または 10^6 の数値 (x は最大 10^18) になります。 この組み合わせにより、数値当たりの定数または対数以上の仕事を行うソリューションは即座に排除されます。 すべての約数に対する単純なループでは、非常に遅すぎます。 

微妙なエッジケースは、完全な正方形と非常に小さな数値から生じます。 

例外的なケースの 1 つは x = 1 です。ここでは ⌊√1⌋ = 1 であるため、条件は常に成り立ち、答えは自明に true になります。 

もう 1 つは、x が完全な正方形のすぐ下の場合です。 たとえば、x = 15 は ⌊√15⌋ = 3 となり、15 は 3 で割り切れるので有効です。 しかし、x = 14 では ⌊√14⌋ = 3 も得られ、14 は 3 で割り切れないため、失敗します。 これらの隣接する値は、決定境界が x 自体の大きさではなく平方根ステップ関数によって駆動されることを強調しています。 

3 番目のエッジ ケースは、x = 16 のような完全平方です。ここでは ⌊√16⌋ = 4 であり、場合によっては割り算が正確になります (16 が機能する)。ただし、多くの完全平方は値によっては失敗するため、「すべての平方が合格」のような近道はありません。 

## アプローチ

 ブルートフォース解釈は簡単です。数値 x ごとに k = ⌊√x⌋ を計算し、x % k == 0 かどうかを確認します。i² が x を超えるまで 1 から上向きにスキャンして平方根を計算すると、クエリごとに O(√x) のコストがかかります。 入力が大きい場合、これは法外なものになり、最悪の場合は 10^10 演算に達する可能性があります。 

重要な点は、k を検索する必要がないということです。 値 ⌊√x⌋ は、実装に応じて定数時間または対数時間で実行される標準の整数平方根ルーチンを使用して直接計算できます。 k が既知になると、割り算チェックは定数時間で行われます。 

したがって、問題の構造はアルゴリズム的には深くありませんが、正しい整数平方根の計算には影響を受けます。 浮動小数点 sqrt は、丸め誤差によって k または k+1 が誤って生成され、完全な平方に近い割り算の結果が変化する可能性があるため、慎重に扱う必要があります。

 ## アルゴリズムのチュートリアル

 各数値を個別に処理します。 

1. 整数 x を読み取ります。 各値は個別に処理されるため、前処理は必要ありません。 
2. k を x の整数平方根として計算します。 これは、k² ≤ x となる最大の整数です。 残りのロジックの正しさは、k が近似値ではなく正確であるかどうかに依存します。 
3. x が k で割り切れるかどうかを確認します。 x % k == 0 の場合、x は豪華なものとして分類され、それ以外の場合は x は豪華ではないものとして分類されます。 
4. 次の数値に移動する前に、x の結果を出力します。 

唯一重要な決定は、k を確実に計算することです。 浮動小数点 sqrt と切り捨ての使用は多くの環境で許容されますが、より安全なアプローチは、整数演算を使用して k を計算するか、候補値を調整して丸めを修正することです。

これが機能する理由: すべての数値は、⌊√x⌋ との関係によってのみ分類されます。 数値間に相互作用はなく、隠れた状態もありません。 整数の平方根は、入力空間を k が定数である区間に分割し、各区間内で単一のモジュラー条件のみをテストします。 これにより、k が正しく計算されると、決定が正確であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def solve():
    t = int(input())
    for _ in range(t):
        x = int(input())
        k = math.isqrt(x)
        if x % k == 0:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```ソリューションは以下を中心に構築されています`math.isqrt`これにより、浮動小数点精度の問題が完全に回避されます。 よくある間違いは、`int(math.sqrt(x))`これは、誤って切り捨てられたり、まれなケースでは時々切り上げられるため、大きな完全な正方形の場合は失敗する可能性があります。 整数平方根ルーチンは、k² ≤ x < (k+1)² を保証します。 

実装の残りの部分は意図的に最小限に抑えられています。各テスト ケースは独立しており、割り算チェックは定数時間です。

次に、小さな値を考えてみましょう。

 これは、k = 1 の場合、条件が常に true であることを示しています。これは、コード内の特別なケースではなく、定義の構造的な特性です。

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = []
    input = sys.stdin.readline

    t = int(input())
    for _ in range(t):
        x = int(input())
        k = math.isqrt(x)
        out.append("YES" if x % k == 0 else "NO")
    return "\n".join(out)

# small cases
assert run("3\n1\n2\n3\n") == "YES\nYES\nYES"

# perfect square boundary
assert run("2\n15\n16\n") == "YES\nYES"

# non-trivial mix
assert run("4\n10\n11\n12\n13\n") == "NO\nNO\nYES\nNO"

 ## 特殊なケース

 x = 1 の場合、k = 1 が得られるため、割り算条件は常に成り立ちます。 1 % 1 = 0 であるため、アルゴリズムは特別な処理を行わずに直接 YES を返します。 

x = 24 などの完全な正方形のすぐ下の数値の場合、k = 4 が得られます。アルゴリズムは 24 % 4 = 0 をチェックし、定義と一致する YES を返します。 x = 23 の場合、k は 4 のままですが、23 % 4 ≠ 0 となり、NO が返されます。 正確さは、四捨五入平方根ではなく、⌊√x⌋の使用に完全に依存します。 

x = 49、k = 7、および 49 % 7 = 0 のような完全な平方の場合、出力は YES になります。 これにより、アルゴリズムが調整ロジックなしで正確な正方形の境界を処理することが確認されます。 

x = 2、k = 1 の場合、問題は 1 で割り切れるかどうかを確認するだけになり、常に true になります。 実装では、分岐せずにこれを自然に処理します。
