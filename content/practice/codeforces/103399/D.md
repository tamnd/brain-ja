 ## 問題の理解

 2 つの整数が与えられ、その積を非常に大きな係数 (係数は完全な 64 ビット値) で計算するように求められます。 主な困難は、乗算そのものではなく、その大きな数を法とする正確性を維持しながら、オーバーフローを発生させずに乗算を安全に実行することです。 

概念的には、タスクは単純です。計算したいのは、$a \cdot b \bmod m$、しかし両方とも$a \cdot b$また、中間結果は、言語と実装の詳細に応じて、64 ビットの符号付きまたは符号なしの制限を超える場合があります。 以来$m$それ自体は 64 ビット整数であるため、固定幅型での単純な乗算は、法が適用される前に暗黙的にラップアラウンドし、誤った結果が生成される可能性があります。 

入力は、反復された独立したクエリを表し、それぞれが 2 つの大きな整数と 1 つの係数で構成されます。 各クエリの出力は、正しいモジュール製品です。 

制約の意味は微妙です。 単一の乗算は数学的には定数時間ですが、実装では、すべての環境で組み込みの 128 ビット演算に依存することはできません。 ソリューションでは、64 ビット演算のみを使用して乗算を安全にシミュレートする手法を使用して中間オーバーフローを回避する必要があります。 

両方のオペランドが次の値に近い場合、エッジ ケースが発生します。$2^{64}$。 たとえば、次の場合$a = 2^{63}$、$b = 2$の場合、真の積はすぐに 64 ビットを超えます。 ラップ算術を使用する言語での単純なアプローチでは、モジュラスを適用する前にゼロまたは不正確なラップ値が計算される可能性があります。 

もう 1 つの問題となるケースは、係数自体が に近い場合です。$2^{64}$。 たとえば、次の場合$m = 2^{64} - 1$オーバーフローがあるとモジュラー リダクション ロジックが無効になるため、中間の乗算であっても慎重に制御する必要があります。 

## アプローチ

 ブルートフォースアプローチは、ネイティブの整数乗算を使用して積を直接計算し、モジュロを適用することです。 これは、積がリダクションの前に正確に計算されるため、無制限の整数を使用する言語で機能します。 ただし、固定 64 ビット演算では、法が適用される前に乗算がオーバーフローするため、計算値はすでに破損しています。 

障害点は単純です。2 つの 64 ビット整数の乗算には、最大 128 ビットの精度が必要になる可能性があります。 環境が 64 ビット演算のみをサポートしている場合、中間結果は失われます。 

重要な観察は、剰余乗算は加算に分解できるということです。 コンピューティングの代わりに$a \cdot b$直接的には、乗算を 2 進累乗ロジックと同様に、繰り返しの 2 倍と条件付き加算として解釈します。 これにより、大きな中間生成物が形成されることがなくなります。 各ステップでは、剰余を減じた値が維持されます。$m$、すべての中間選手が範囲内に留まるようにします。 

ビット分解を使用してこれを加速することもできます。1 つのオペランドのビットをスキャンし、もう 1 つのオペランドの寄与を累積し、各ステップで法の下で安全に 2 倍にします。 

これにより、乗算がオーバーフローする可能性のある演算から一連の制御された加算と 2 倍算に変換され、そのすべてを安全に剰余演算することができます。$m$。

 ## アルゴリズムのチュートリアル

 私たちは計算します$a \cdot b \bmod m$乗数のバイナリ分解を使用します。 

1. 結果変数をゼロとして初期化し、両方の入力数値を剰余で減らします。$m$。 早期に削減すると、その後のすべての操作が制限されたままになり、不必要な増加が防止されます。 
2. 乗算器のビットを反復処理します。$b$。 各ステップで、現在のビットが設定されているかどうかを確認します。 そうである場合、被乗数の現在の値を結果に追加し、法を直ちに適用します。 これが機能するのは、設定された各ビットがバイナリ展開における 2 のべき乗の寄与を表すためです。 
3. 各ビットを処理した後、法の下で被乗数を 2 倍にします。 これは、重量を次から移動することに対応します。$2^k$に$2^{k+1}$バイナリ表現で。 係数により、この 2 倍化がオーバーフローから安全に保たれます。 
4. 乗算器のすべてのビットが処理されるまで続行します。 蓄積された結果が最終的なモジュール製品となります。 

### なぜ効果があるのか

 正確さは、乗算をシフトされた寄与の合計として解釈することから得られます。 任意の整数$b$は 2 の累乗の和として書くことができ、次の乗算を行います。$a$はこの表現上に分布します。 アルゴリズムはこの分解を正確に反映しています。ビットが設定されるたびに、対応する 2 のべき乗のスケール値を追加します。$a$そして、すべての中間値が剰余化されることを保証することで正確さを維持します。$m$。 中間計算が意味のある形でモジュラス境界を超えることはないため、オーバーフローが正確さに影響を与えることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def mod_mul(a, b, m):
    a %= m
    b %= m
    res = 0

    while b > 0:
        if b & 1:
            res = (res + a) % m
        a = (a + a) % m
        b >>= 1

    return res

def solve():
    t = int(input())
    for _ in range(t):
        a, b, m = map(int, input().split())
        print(mod_mul(a, b, m))

if __name__ == "__main__":
    solve()
```機能`mod_mul`モジュラスに基づいてバイナリ乗算を実装します。 重要なアイデアは次のとおりです`a`は繰り返し 2 倍になり、連続する 2 の累乗を表します。`b`少しずつ分解されていきます。 ちょっとしたときはいつでも`b`がアクティブです。現在の貢献度は`a`が結果に追加されます。 

微妙な点は、両方の値を早期に削減することです。`a`そして`b`モジュロ`m`。 減らしながら`a`値を小さく保ち、`b`正確性を保つためにはオプションですが、無害であり、場合によってはループの反復をわずかに減らすのに役立ちます。 ループ構造はバイナリ表現を直接処理するため、正確性が保証されます。 

すべての加算と 2 倍算はすぐに剰余化されます。`m`64 ビットの制約のある環境でもオーバーフローを完全に防止します。
