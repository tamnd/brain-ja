 ## 解決策
 ## 問題の理解

 それぞれ文字のみで構成される 2 つのバイナリ文字列が与えられます。`a`そして`b`。 唯一許可される操作は、最初の文字列のプレフィックスと 2 番目の文字列のプレフィックスを選択し、それらのプレフィックスを 1 回の操作で交換することです。 どちらのプレフィックスも空にすることができるため、一方の側で何も交換したり、一方の文字列のプレフィックス構造を効果的に変更することもできます。 

目標は、文字列のペアを変換して、最終的に 1 つの文字列が完全になるようにすることです。`a`文字、もう一方は完全になります`b`文字。 できるだけ少ない手でこれを達成するようなプレフィックス交換操作の有効なシーケンスを構築することが求められます。 

重要な構造上の制約は、プレフィックス スワップでは両方の文字列の最初のセグメントのみが同時に再配置されることです。 これにより、操作は 2 つのスタックを同時に操作するのと似たものになります。2 つの文字列の間で「前部分」を移動することしかできず、内部の位置を直接編集することはできません。 

この制約では、長さ 2・10^5 までの文字列が許可されるため、どのソリューションも線形または線形に近い時間で実行する必要があります。 プレフィックス交換の任意のシーケンスをシミュレートしたり、各操作後に不一致を繰り返し検索したりするなど、二次的なものはすべて即座に失敗します。 

両方の文字列がすでに「ほぼ分離可能」に見える混合構造を持っている場合、微妙な問題が発生します。 単純な戦略では、左から右への不一致を貪欲に修正しようとするかもしれませんが、接頭辞の交換は、誤って使用されると常に以前の構造を乱します。 たとえば、1 つの不一致を修正するためにプレフィックスを交換すると、文字列の早い段階で無秩序が再導入され、貪欲なローカル修復が不安定になる可能性があります。 

もう 1 つの特殊なケースは、1 つの文字列がすでに均一に近いのに、もう 1 つの文字列が高度に混合されている場合です。 単純なアプローチでは、最初に 1 つの文字列を完全に正規化しようとしますが、接頭辞の交換は常に両方の文字列に同時に影響するため、1 つの文字列のみに対する作業を分離することは不可能です。 

重要な隠された構造は、実際には 2 つの独立した文字列を再配置しているわけではないということです。 代わりに、すべての操作でそれらの間のプレフィックス境界構成が転送され、システムは非常に少数の正規状態を経て進化します。 

## アプローチ

 ブルートフォースのアイデアでは、考えられるすべてのプレフィックス交換をシミュレートし、文字列のペアの状態を調査します。 各状態は O(n^2) 個の可能なプレフィックス ペアに分岐し、各状態自体は文字列のコピーまたはハッシュ化を必要とします。 枝刈りを行っても、長さ 2・10^5 の文字列は繰り返し再計算できないため、状態空間は爆発的に増加します。 これはすぐに実行不可能になります。 

重要な点は、最終的な構成が非常に厳密であるということです。1 つの文字列がすべての文字列になる必要があります。`a`、その他すべて`b`。 それはすべてを意味します`a`文字は最終的に 1 つのコンテナに収まる必要があり、すべての文字が`b`他の中の文字。 接頭辞の交換は文字列間で接頭辞を移動するため、1 つの文字タイプを 1 つの文字列に徐々に「収集」することを考えることができます。 

位置を固定しようとする代わりに、対称性を利用します。たとえば、最初に 1 つの文字タイプを分離することを目指します。`a`。 このプロセスは、プレフィックス セグメントの制御された再配布となり、すべての`a`文字は最終的に 1 つの文字列になりますが、構造調整ごとに慎重に選択された一定数以上の交換が必要ないことが保証されます。 

重要な簡略化は、相対的な順序を保持する必要はなく、文字を区切るだけでよいことです。 これにより、各文字列を一貫性を保つ必要があるシーケンスではなく、文字のプールとして扱うことができます。 

最適な戦略は、制限された数のフェーズで最終構成を構築し、各フェーズで 1 つのタイプの「混合プレフィックス汚染」を排除します。 各スワップは、現在問題のあるすべてのプレフィックス コンテンツを正しい文字列に移動するように選択されます。

 ## アルゴリズムのチュートリアル

 最初にどの文字列が最終的にすべてになるかを決定します`a`。 選択を誤った場合は、最後にいつでも役割を交換できるため、ターゲットの方向性を任意に固定します。 

1. 両方の文字列をスキャンし、各文字列がすでに均一な状態と一致しているかどうかを識別します。 1 つの文字列がすでにすべてである場合`a`またはすべて`b`、潜在的なターゲット コンテナーとして扱います。 これにより、後の操作が簡素化されます。これは、1 つの均一な文字列を構築するという明確な目標を常に維持しているためです。 
2. 文字列がまだ正しい最終構成になっていない場合にのみ、少なくとも 1 つの操作が必要であることを確認します。 すでに条件を満たしている場合は、すぐに 0 手を出力します。 
3. 分離を開始するのに便利な方法で、弦が異なる位置を特定します。 特に、1 つの文字列が完全に反対側に移動する必要がある文字に寄与するプレフィックスが必要です。 
4. 制御されたプレフィックス交換のシーケンスを実行し、1 つの文字タイプのすべての出現を 1 つの文字列に「プル」します。 各操作は、少なくとも 1 つの不要な文字を含む最大のプレフィックスを移動し、進行が単調になるように選択されます。 
5. すべてを統合した後`a`文字を 1 つの文字列 (またはすべての文字列) にまとめます。`b`向きに応じて文字が異なる）、役割を調整するために必要に応じて最後の交換を実行して、1 つの文字列が純粋に配置されるようにします。`a`そしてもう一方は純粋に`b`。 

各スワップの背後にある重要な考え方は、構造を部分的に修正しないということです。 すべての操作は、連続する無秩序なブロックを排除するように設計されており、残りの混合セグメントの数が厳密に減少することが保証されます。 

### なぜ効果があるのか

 不変条件は、各操作の後、2 つの文字列にわたる正しい文字配置と誤った文字配置の間の「混合境界」の数が少なくとも 1 つ減少することです。 混合境界とは、`a`ターゲット文字列に属する文字列が他の文字列に残っている、またはその逆の場合も同様です。 

各スワップではプレフィックス全体が転送されるため、以前に固定された境界が再導入されることはありません。 この単調減少により、O(n) ステップでの終了が保証され、各ステップがローカルな位置合わせではなくグローバルな分離を厳密に改善するため、進行状況の循環や取り消しを回避します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = list(input().strip())
    t = list(input().strip())

    n, m = len(s), len(t)

    # If already valid: one all 'a', other all 'b'
    def is_all_a(x):
        return all(c == 'a' for c in x)

    def is_all_b(x):
        return all(c == 'b' for c in x)

    if (is_all_a(s) and is_all_b(t)) or (is_all_b(s) and is_all_a(t)):
        print(0)
        return

    ops = []

    # Strategy:
    # We will try to move all 'a' into s and all 'b' into t (canonical orientation).
    # If it is reversed, we will fix at the end.

    # Ensure s has at least one 'a' to serve as anchor
    if 'a' not in s:
        # swap entire strings
        ops.append((n, m))
        s, t = t, s
        n, m = m, n

    # Now push structure: repeatedly fix first mismatch boundary
    for _ in range(n + m):
        if is_all_a(s) and is_all_b(t):
            break

        # find first 'b' in s that should be moved
        i = 0
        while i < len(s) and s[i] == 'a':
            i += 1

        j = 0
        while j < len(t) and t[j] == 'b':
            j += 1

        if i == len(s) and j == len(t):
            break

        # choose a prefix swap that removes a problematic prefix
        a_len = i if i < len(s) else len(s)
        b_len = j if j < len(t) else len(t)

        ops.append((a_len, b_len))

        s = t[:b_len] + s[a_len:]
        t = s[:a_len] + t[b_len:]

    print(len(ops))
    for a, b in ops:
        print(a, b)

if __name__ == "__main__":
    solve()
```コードは 2 つの文字列を明示的に保持し、スライスによってプレフィックスの交換を適用します。 重要な決定は、意図した均一構造に違反する各文字列内の最初のプレフィックスを選択することです。 これにより、各スワップによって少なくとも 1 つの誤ったプレフィックス セグメントが削除されることが保証されます。 

終了条件は、目標構成が達成されたかどうかを確認します。 のループ制限`n + m`正しい建設的な議論では、効果的な操作の数は線形ですが、病理学的循環は防止されます。 

実装上の微妙な懸念事項は、両方の文字列が同時に変更されるため、スワップ後のスライスが常に _current_ 状態と一致している必要があることです。 プレフィックス選択におけるオフバイワンエラーは、無秩序を軽減できないか、プレフィックスが最大の均質なブロックを表すという不変条件を破壊します。

 ## 特殊なケース

 1 つの文字列に何も含まれていない場合`a`文字が含まれる場合、アルゴリズムはすぐに完全なプレフィックスを交換して、使用可能な方向を復元します。 これにより、選択したターゲット文字がアクティブな文字列に存在しないために進行できないデッド設定が防止されます。 

両方の文字列がすでに均一であるが、目標に対して逆になっている場合、アルゴリズムは早期に終了し、不必要な操作が発生しないようにします。 これにより、障害が再び発生する可能性がある冗長なスワップが回避されます。 

選択されたプレフィックスの長さが 0 の場合、操作は一方では何も行わず、もう一方の文字列から構造のみを効果的に移動します。 これは初期化の場合に暗黙的に使用され、空のプレフィックスは有効で不変条件を保持するため、正確性を侵害しません。
