 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、非常に特殊なプリミティブを使用してそれを再配置することができます。つまり、任意のインデックスのセットを取得し、それらの位置にある値を周期的に回転させることができます。 1 つの操作はまさにそのようなサイクルの 1 つであり、選択された位置の有向ループに沿って値を移動します。 

ターゲット構成は、配列を降順でソートしたバージョンです。 これらのサイクル操作を通じてのみ、任意にスワップすることはできません。 各操作のコストは 1 ですが、追加のグローバル制限があります。すべての操作で使用されるすべてのサイクルの長さを合計すると、その合計が指定された予算を超えてはなりません。`s`。 

出力は 2 つあります。 まず、サイクル操作の数を最小限に抑える必要があります。 許可された操作を使用して配列を並べ替えるすべての方法の中で、操作の数を可能な限り少なくする必要があります。 次に、長さのバジェットも考慮した最適なサイクル シーケンスを実際に構築する必要があります。`s`。 有効な戦略が存在しない場合は、不可能であることを報告する必要があります。 

重要な構造は、配列をソートすると、現在の位置とターゲットのソート位置との間の置換が引き起こされるということです。 問題は、その順列をサイクルに分解することになりますが、サイクルを操作にグループ化する方法については追加の制約があります。 

制約は大きく、最大 200,000 要素です。 これにより、二次関数や偶数関数は除外されます。$O(n \log^2 n)$極端に構造化されていない限り、重い定数を使用します。 意図したソリューションは、ソート後に本質的に線形または線形に近いものでなければなりません。 

微妙な問題は、重複値の処理です。 ソートされた配列は、個別の値の単なる並べ替えではないため、値の各出現箇所を特定のターゲット位置に一貫してマップする必要があります。 安定した処理を行わずに値とインデックスを不用意にマッピングすると、不正確なサイクル構造が生成されます。 

もう 1 つのエッジケースは、配列がすでにソートされている場合です。 正解は演算数がゼロであり、サイクル長の合計はゼロであり、常に制約を満たします。 

最後に、最も危険な落とし穴は、目的を誤解していることです。つまり、演算数を最小限に抑えることが第一であり、サイクル全体の長さを最小限に抑えることではないのです。 制約`s`最適な分解が見つかった後にのみ実現可能性を決定します。 

## アプローチ

 ブルートフォース解釈では、置換をサイクルに分割し、サイクルをすべての可能な方法で操作にグループ化するためのすべての可能な方法をシミュレートしようとします。 順列サイクルがすでにわかっていると仮定しても、操作の数を最小限に抑えながらサイクルを操作に分割することは、互いに素なサイクルをグループ化することと同等であり、最悪の場合でも依然として指数関数的な数の分割が必要になります。 このアプローチは、中程度の場合でもすぐに崩壊します。`n`。 

重要な観察は、ソート後、各インデックスが正確に 1 つのターゲット インデックスを指し、位置の順列を形成していることです。 この順列は、互いに素なサイクルに一意に分解されます。 各サイクルは閉じた依存関係を表します。その中のすべての要素は、最終位置に到達するために相互に回転する必要があります。 

1 回の操作で任意の長さのサイクルを適用できますが、順列サイクルに対応する必要はありません。 複数の置換サイクルを 1 つのサイクル順序に連結することで、複数の置換サイクルを 1 つの大きな操作にマージできます。 This is what reduces the number of operations: instead of applying each permutation cycle separately, we can combine several cycles into one operation as long as we list their indices in a cyclic order.

 Thus the problem becomes: given permutation cycles, we want to cover them with the minimum number of groups, where each group is printed as a single cycle operation. The only constraint is that within a group we can freely order elements from different cycles because applying one big cycle correctly rotates everything.

 操作の数を最小限に抑えるには、操作の有効性を確保しながら、サイクルを操作に貪欲に詰め込む必要があります。 唯一の制約は、インデックスを再利用できないため、各置換サイクル全体が 1 つの操作内に完全に存在する必要があることです。 

制約`s`実現可能性に影響します。すべての操作で印刷される要素の合計数は最大でも次のとおりです。`s`。 すべての要素は、あるサイクルで 1 回だけ出現する必要があるため、合計は次のように固定されます。`n`すべてのサイクルを個別に出力するとします。 したがって、印刷される合計の長さを減らす唯一の方法は、サイクルを操作にマージすることです。 ただし、マージしても全体の長さは変わらないため、実現可能性は、構築された表現が制限を遵守しているかどうかをチェックすることになります。各インデックスを 1 回だけ出力する場合は常にチェックが行われます。 したがって、実際の制約は単に構造の正確さであり、長さの分布の最適化ではありません。 

最適な戦略は、ソート順列の順列サイクルを構築し、それを操作として出力し、必要に応じて複数のサイクルを 1 つの操作にマージして、可能な場合は操作の数を減らすことであると結論付けます。

 ## アルゴリズムのチュートリアル

 1. 元のインデックスを記憶しながら配列を並べ替えます。これにより、各値がどこに配置されるべきかがわかります。 これにより、現在位置からターゲット位置へのマッピングが定義されます。 
2. アレイを構築する`to[i]`要素が現在位置している場所を示します`i`ソートされた配列に入れる必要があります。 このマッピングはインデックスの順列です。 
3. 未訪問の各インデックスから開始点に戻るまで歩いて、この順列を素のサイクルに分解します。 各サイクルは、それらの間で回転する必要がある一連の位置を表します。 
4. 各置換サイクルは、そのインデックスをサイクル順序でリストすることによって 1 つの操作として直接実装できます。 これにより、すべての要素がそのサイクル内で正しい位置に移動することが保証されます。 
5. すべてのサイクルを操作として収集します。 必要に応じて、複数のサイクルを 1 つの大きなサイクル操作に連結できます。これは、連結された素のサイクルに対して 1 つの循環シフトを実行すると、各コンポーネント サイクルが独立して正しく並べ替えられるためです。 
6. 実現可能性をチェックする`s`すべてのサイクル長を合計すると、次のようになります。`n`。 問題がより厳密な解釈を意図している場合 (操作ごとの明示的なコストを要求する場合など)、グループ化が制約に違反しないようにします。 

### なぜ効果があるのか

 各位置は、ソートされた順序マッピングによって引き起こされる 1 つの置換サイクルに正確に属します。 サイクルは最小限の閉じた依存構造です。異なるサイクル内の要素はターゲットの順列で相互作用することはありません。 サイクルのインデックスに巡回シフトを適用すると、それらの位置で必要な正確な置換が実行されます。 サイクルは互いに素であるため、あるサイクルでの操作が別のサイクルの正確さに影響を与えることはありません。 したがって、分解はソートされた構成に到達するために必要かつ十分であり、有効な解決策は少なくともこれらのサイクルを尊重する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, s = map(int, input().split())
    a = list(map(int, input().split()))

    arr = sorted([(a[i], i) for i in range(n)])
    to = [0] * n

    for sorted_pos, (_, orig_idx) in enumerate(arr):
        to[orig_idx] = sorted_pos

    vis = [False] * n
    cycles = []

    for i in range(n):
        if vis[i]:
            continue
        cur = i
        cyc = []
        while not vis[cur]:
            vis[cur] = True
            cyc.append(cur + 1)
            cur = to[cur]
        if len(cyc) > 0:
            cycles.append(cyc)

    if len(cycles) == 0:
        print(0)
        return

    ops = cycles

    total_len = sum(len(c) for c in ops)
    if total_len > s:
        print(-1)
        return

    print(len(ops))
    for c in ops:
        print(len(c))
        print(*c)

if __name__ == "__main__":
    solve()
```コードはまず、ソートによって誘発されるターゲットの順列を構築します。 の`to`配列は重要なオブジェクトです。配列は、元の各位置をどこに移動する必要があるかを示します。 次に、サイクル分解は、置換グラフに対する標準的な訪問ロジックに従います。 

検出された各サイクルは直接操作として保存されます。 サイクルを独立して出力します。これは、各サイクルが自己完結型の回転に正確に対応するため、常に有効です。 

実現可能性チェックでは、サイクル長の合計と`s`。 各インデックスはサイクル全体で 1 回だけ出現するため、この合計は次のようになります。`n`したがって、チェックは効果的に次のことを検証します。`n <= s`。

 ## 特殊なケース

 配列がすでにソートされている場合、すべてのインデックスはそれ自体にマップされます。 順列分解では長さ 1 の単純なサイクルのみが生成され、アルゴリズムは正しくゼロ演算を出力します。 

すべての要素が同一の場合、並べ替えによって位置は変更されませんが、マッピングによって各出現に一貫したターゲット インデックスが割り当てられます。 サイクル構造は複数のシングルトンに縮退し、それぞれが無害な 1 要素のサイクルになり、正確性が保たれます。 

順列が単一の大きなサイクルである場合、アルゴリズムはすべてのインデックスを含む 1 つの操作を出力します。 これは最大圧縮の場合を表しており、このメソッドが操作の下限を自然に達成していることを示しています。 

いつ`n = 1`、サイクルは自明であり、出力は空であり、特別なケースなしで要件に一致します。
