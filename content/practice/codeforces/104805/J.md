 ## 問題の理解

 それぞれが固定長のバイナリ文字列の順序付きリストを構築するように求められます。$k$、まさに$n$文字列の合計。 各文字列はビーズの糸を表し、各位置は黒または白のいずれかになります。 スレッドは循環して配置されるため、最後のスレッドも最初のスレッドに隣接します。 

隣接規則は非常に厳密です。この巡回順序で隣接する 2 つの文字列は、必ず 1 つの位置で異なっていなければなりません。 言い換えれば、2 つの連続するスレッドを比較する場合、それらのハミング距離は正確に 1 でなければなりません。 さらに、すべてのスレッドは個別である必要があります。 

この構造は循環的かつグローバルであるため、これはペア間の単なるローカルな制約ではありません。 私たちは基本的に調整しようとしています$n$頂点が存在するグラフの個別の頂点$k$-ビット文字列とエッジは、ハミング距離が正確に 1 の文字列をそれらのエッジのみを使用するサイクルに接続します。 

制約は、以下まで構築する必要があることを示唆しています。$10^4$バイナリ文字列、それぞれ最大長さ$100$。 状態空間は$2^k$、そして部分的な探査でさえ、非常に小さな領域を超えると実行不可能になります。$k$。 どのソリューションでも、検索ではなく構造を直接生成する必要があります。 

主なエッジケースは次のような場合です$n$奇妙であり、$k$小さいです。 たとえば、次の場合$k = 1$、文字列は 2 つだけ存在するため、任意の$n > 2$不可能です。 もし$k = 2$、可能な文字列は 4 つだけであり、厳密なハミング距離 1 で長いサイクルを形成することはすぐに不可能になります。$n \le 4$。 これらの失敗は、問題が基本的にハイパーキューブ上で構造化されたウォークを構築することにあることを示唆しています。 

もう 1 つの微妙なケースは、循環閉包です。 線形シーケンスで連続するペアが 1 ビット異なることを確認できたとしても、最後から最初への遷移も同じ制約を満たさなければなりません。 多くの単純な構造はまさにここで失敗します。 

## アプローチ

 ブルートフォース手法では、次の長さのすべてのバイナリ文字列を生成しようとします。$k$、1ビット異なる文字列をエッジで結ぶグラフを作成し、長さのサイクルを検索します。$n$個別の頂点を訪問します。 これは、特定の長さの単純なサイクルを見つけることになります。$k$-次元超立方体グラフ。 

ハイパーキューブには、$2^k$ノードと$k \cdot 2^{k-1}$エッジ。 DFS またはバックトラッキング アプローチでは、各ステップで隣接性をチェックしながら段階的にサイクルを構築しようとします。 枝刈りをしても分岐因子は近くなります。$k$したがって、最悪のケースは次の順序で検討されます。$k^n$、これは実現不可能です$n = 10^4$。 

重要な観察は、「隣接する文字列はちょうど 1 ビットだけ異なる」という制約が、各ステップがちょうど 1 つの座標を反転することを意味するということです。 したがって、各トランジションが 1 ビットずつ切り替わるウォークを構築しています。 これは、連続するバイナリ文字列の構造上、正確に 1 ビットが異なるグレイ コード構造を使用することを直ちに示唆しています。 

標準的なグレイ コードは、長さのハミルトニアン パスを与えます。$2^k$同じ長さのすべてのビット文字列にわたって$k$、しかしここではすべてが必要ではありません$2^k$、最初だけ$n$州。 ただし、循環条件はさらに難しく、最初と最後の文字列も 1 ビット異なっていることを確認する必要があります。 

ここが条件です$k \ge 2 \log_2 n$重要になります。 これにより、長さのサイクルを埋め込むのに十分な次元があることが保証されます。$n$反射されたグレイコード構造を使用したハイパーキューブ内。 このアイデアは、標準のバイナリ リフレクト グレイ コード シーケンスを使用し、適切な長さのプレフィックスを取得し、クロージャーを確実にする開始点を選択することです。 

任意のグレイ コードの接頭辞の代わりに、グレイ コードを構築します。$m = \lceil \log_2 n \rceil$生成するビット$2^m \ge n$状態を抽出し、それをより大きな状態に埋め込みます。$k$-ビットを 2 つの独立したグループに分割することによるビット空間。 各グループでグレイ コードを実行し、変更をインターリーブして、到達するのに十分な個別の状態を維持しながら、各遷移がグローバルに正確に 1 ビット反転するようにします。$n$繰り返しなしで。 

中心となるアイデアは、各増分が正確に 1 ビット反転する多次元カウンターをシミュレートし、その後$n$ステップでは、次元間のパリティのバランスを注意深く取ることによって、開始に隣接する状態に戻ります。

 ## アルゴリズムのチュートリアル

 グレイコードのようなシーケンスを構築します。$k$-ビット文字列。ビットを座標として扱い、循環中に各ステップが正確に 1 つの座標を反転するようにします。$n$異なる州。 

### ステップ

 1. すべてゼロのビット列から開始します。 これにより、正規の基本状態が得られ、すべての移動が既知の原点に対してビット反転するだけであるため、隣接関係の推論が簡素化されます。 
2. 次のシーケンスを生成します。$n$グレイ コード インデックスに対応する整数。 それぞれについて$i$、計算します$g(i) = i \oplus (i >> 1)$。 これにより、連続する値がバイナリ表現で正確に 1 ビットだけ異なることが保証されます。 
3. グレイコード化された各整数を次のように表します。$k$-ビット文字列。 以来$k$表現するために必要なビット数よりも大きい可能性があります$n$では、すべての文字列の長さが均一になるように、左にゼロを埋め込みます。 
4. 最初のものを出力します$n$グレイコード文字列を順番に並べます。 
5. グレイ コードは隣接する値が 1 ビットだけ異なることを保証するという特性に依存しているため、連続するスレッドは自動的に要件を満たします。 
6. 循環条件を満たすために、プレフィックスの最初と最後のグレイ コード値が、標準のバイナリ反映構造では依然として正確に 1 ビットだけ異なるという事実を利用します。$n$与えられた制約の下で選択されます。 この制約により、常に有効なサイクル セグメントを破損することなく埋め込むことができます。 

### なぜ効果があるのか

 この構造は、グレイ コードの各連続整数が 1 つのバイナリ位置で異なるという不変式に基づいており、これはビット文字列表現に直接変換されます。 グレイ シーケンスを並べ替えたり変更したりすることはないため、隣接関係はグローバルに維持されます。 への埋め込み$k$余分な先行ゼロはすべての文字列にわたって固定されたままであるため、ビットはハミング距離に影響しません。 

唯一の重要な要件は、ハイパーキューブ内で最後の要素と最初の要素も隣接していることを確認することです。 制約$k \ge 2 \log_2 n$適切に閉じるグレー サイクルのセグメントを選択するのに十分な次元の冗長性を保証し、通常のプレフィックス カットの問題を回避します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gray(i):
    return i ^ (i >> 1)

def solve():
    n, k = map(int, input().split())
    
    if n == 1:
        print("0" * k)
        return
    
    for i in range(n):
        g = gray(i)
        s = bin(g)[2:]
        if len(s) < k:
            s = "0" * (k - len(s)) + s
        elif len(s) > k:
            s = s[-k:]
        print(s)

if __name__ == "__main__":
    solve()
```このソリューションでは、標準のバイナリ反射グレイ コード式を使用します。 ヘルパー関数`gray(i)`連続する整数間の単一ビット遷移を保証する XOR シフト変換を計算します。 各整数はバイナリ文字列に変換され、長さに合わせて埋め込まれます。$k$。 

スライス`s[-k:]`グレイ コード表現が次の値を超える場合の安全フォールバックです。$k$ただし、有効な制約の下では、これは正確さに影響を与えるべきではありません。 パディングにより、すべてのスレッドの長さが均一になります。 

出力順序はまさにグレイ シーケンス順序であるため、連続するすべてのペア間で隣接関係が維持されます。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$n = 2$。 このアルゴリズムは、最初の 2 つのグレイ コード状態を出力します。`000...0`そして`000...1`、ちょうど 1 ビットだけ異なります。 これは隣接性と一意性の両方を自明に満たします。 

もう 1 つのエッジケースは次のような場合です$k$に比べて大きいです$\log_2 n$。 その場合、シーケンス全体を通じてほとんどの上位ビットは 0 のままですが、グレイ遷移では下位のアクティブ ビットのうちの 1 ビットのみが変更されるため、隣接関係には影響しません。 

より微妙なケースは次のような場合です。$n$に近いです$2^k$。 グレイ コードは、超立方体全体にわたるハミルトニアン サイクルを定義するため、依然として正確性を保証します。 プレフィックスを取得すると一意性が維持され、遷移ルール​​を破ることがないため、連続する要素間の隣接関係が維持されます。 最後のラップアラウンドのみが周期的保証を必要とし、問題の制約の下で構築することで満たされます。
