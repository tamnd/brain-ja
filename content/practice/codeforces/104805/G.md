 ## 解決策
 ## 問題の理解

 私たちはベロニカが一日どのように眠っているかを記録した日記を渡されました。 各日記エントリには、眠りにつく開始時刻と目覚める終了時刻が示されます。 これらすべての睡眠時間から、1 日にどれくらいの時間が自由に保たれているか、つまり彼女が起きていて隣人が修理を許可されている瞬間を判断する必要があります。 

すべての時間は 24 時間サイクル内ですが、睡眠間隔は真夜中を超える場合があります。 たとえば、22:00:00 から 02:00:00 まで寝ているということは、一日の終わりまで眠っており、次の日まで眠り続けることを意味します。 各間隔は 24 時間未満であることが保証されているため、1 日全体を一度にカバーすることはありません。 

睡眠間隔は重複する可能性があるため、重要な作業は継続時間を直接合計することではありません。 代わりに、24 時間のタイムライン内のすべての睡眠期間を合わせた合計の長さを計算し、それを 1 日の合計秒数 (86400) から減算する必要があります。 

制約は最大 100,000 間隔までであり、間隔ごとに 1 秒ごとに個別にマークを付けようとするソリューションは除外されます。 最悪の場合、最大約 10^10 の操作が必要となるため、間隔ごとに丸 1 日にわたる単純なシミュレーションは非常に遅すぎます。 目的のソリューションでは、各間隔をイベントに圧縮し、線形または線形に近い時間で処理する必要があります。 

間隔が重なり合ったり、午前 0 時を前後したりすると、微妙な問題が発生します。 たとえば、1 つの間隔が 23:00:00 ～ 01:00:00 で、もう 1 つの間隔が 00:30:00 ～ 02:00:00 である場合、単純合計では 2 時間プラス 1.5 時間となりますが、実際の結合時間はわずか 3 時間になります。 もう 1 つのエッジ ケースは完全なカバレッジです。間隔が集合的に 24 時間全体をカバーする場合、答えはゼロでなければなりません。 

## アプローチ

 簡単なアプローチは、各スリープ間隔を秒に変換し、サイズ 86400 のブール配列で毎秒マークを付けることです。間隔ごとに、すべての秒を「スリープ」としてマークし、最後にマークされていない秒数をカウントします。 これはその日を直接モデル化しているため正しいですが、各間隔には最大 86400 回の操作が必要となる可能性があり、最悪の場合には全体で約 10^10 の操作が必要となり、これは制限をはるかに超えています。 

重要な改善は、個々の秒数ではなく、間隔の境界のみを考慮することを認識することによってもたらされます。 各間隔は、長さ 86400 の円形タイムライン上の連続セグメントに寄与します。すべての間隔を線形セグメントに変換し、それらの結合の長さを計算すると、各秒に明示的に触れないようにすることができます。 これは古典的な区間和集合問題です。 

唯一の複雑な点は、ラップアラウンド間隔の処理です。 真夜中をまたぐ睡眠間隔は、通常の 2 つの間隔に分割できます。1 つは開始時刻から 1 日の終わりまで、もう 1 つは 1 日の始まりから起床時刻までです。 この変換後、すべての区間は標準の数直線上にあり、掃引線または並べ替えベースのマージ アプローチを使用して O(n log n) でそれらの和集合を計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 毎秒マーク | O(n · 86400) | O(86400) | 遅すぎる |
 | 並べ替え + マージ間隔 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての時間を 1 日の始まりからの秒数に変換し、間隔が正規化されて深夜に重ならないようにします。 その後、重複するセグメントをマージし、カバーされる合計の長さを計算します。

1. 各タイムスタンプ hh:mm:ss を 00:00:00 からの合計秒数に変換します。 これにより、比較が簡単な一貫した数値表現が得られます。 
2. 各間隔について、午前 0 時を超えているかどうかを確認します。 開始時間が終了時間以下の場合は、単一のセグメントとして保持されます。 開始時刻が終了時刻より大きい場合は、開始時刻から 86400 までのセグメントと、0 から終了時刻までのセグメントの 2 つのセグメントに分割します。 これにより、すべてのセグメントが単一の連続範囲内に収まるようになります。 
3. 結果として得られるすべてのセグメントをリストに収集します。 この時点で、セグメントは最大 2n 個あり、すべて [0, 86400] 内にあります。 
4. セグメントを開始時間順に並べ替えます。 並べ替えにより、左から右にスキャンするときに、現在アクティブなマージされたセグメントでのみ重複が発生することが保証されます。 
5. 現在のマージ間隔を維持しながら、ソートされたセグメントをスイープします。 次のセグメントが現在のセグメントの前または終わりから始まる場合は、現在の終わりを延長します。 それ以外の場合は、完了したマージ間隔の長さを追加し、新しい間隔を開始します。 
6. すべてのセグメントを処理した後、最後のアクティブな間隔の長さを合計スリープ時間に加算します。 
7. 86400 から合計睡眠時間を引いて答えを求めます。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは、これまでに処理されたすべての間隔が、元の睡眠カバレッジと正確に一致する結合部分を持たないセグメントに完全にマージされるという不変条件を維持します。 オーバーラップはすべて現在のセグメントに吸収されるため、時間が二重にカウントされることはありません。 ラップアラウンド ケースを分割した後、すべての睡眠間隔が 1 回だけ表されるため、最終的に結合された長さは、正確に 1 日内の合計睡眠時間になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

DAY = 24 * 60 * 60

def to_sec(t):
    h = int(t[0:2])
    m = int(t[3:5])
    s = int(t[6:8])
    return h * 3600 + m * 60 + s

n = int(input())
intervals = []

for _ in range(n):
    a, b = input().split()
    l = to_sec(a)
    r = to_sec(b)

    if l <= r:
        intervals.append((l, r))
    else:
        intervals.append((l, DAY))
        intervals.append((0, r))

intervals.sort()

total_sleep = 0
cur_l, cur_r = intervals[0]

for l, r in intervals[1:]:
    if l <= cur_r:
        if r > cur_r:
            cur_r = r
    else:
        total_sleep += cur_r - cur_l
        cur_l, cur_r = l, r

total_sleep += cur_r - cur_l

print(DAY - total_sleep)
```実装は、間隔の演算を直接行うために、タイムスタンプを整数の秒に変換することから始まります。 ラップアラウンド間隔は、すべてのセグメントが標準の 0 ～ 86400 の範囲内に収まるように分割されます。 並べ替えにより、後戻りすることなく単一パスで間隔をマージできるようになります。 マージ ロジックは、現在のアクティブな間隔を維持し、オーバーラップが発生するたびにそれを延長します。 ギャップが見つかると、前のセグメントが確定され、合計睡眠時間に追加されます。 

微妙な点は、初期間隔が存在する必要があるため、入力には少なくとも 1 つの睡眠セグメントが含まれていると想定されることです。 86400 からの最後の減算により、修理のための自由時間が得られます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 最大 2n 間隔のエンドポイントの並べ替えが実行時間を支配します。 
| スペース | O(n) | 変換された間隔のストレージ |

 このアルゴリズムは、最大 100000 までの n の制約内に快適に適合します。効率的な入力解析を使用して実装された場合、並べ替えと 1 回の線形スキャンは Python の一般的な 1 秒の制限内に十分収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    DAY = 24 * 60 * 60

    def to_sec(t):
        h = int(t[0:2])
        m = int(t[3:5])
        s = int(t[6:8])
        return h * 3600 + m * 60 + s

    n = int(input())
    intervals = []

    for _ in range(n):
        a, b = input().split()
        l = to_sec(a)
        r = to_sec(b)
        if l <= r:
            intervals.append((l, r))
        else:
            intervals.append((l, DAY))
            intervals.append((0, r))

    intervals.sort()

    total = 0
    cur_l, cur_r = intervals[0]

    for l, r in intervals[1:]:
        if l <= cur_r:
            cur_r = max(cur_r, r)
        else:
            total += cur_r - cur_l
            cur_l, cur_r = l, r

    total += cur_r - cur_l

    return str(DAY - total)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、睡眠間隔が午前 0 時頃になる場合です。 たとえば、23:00:00 ～ 01:00:00 は、[23:00, 86400) と [0, 01:00] の 2 つのセグメントになります。 分割を行わないと、単純なマージでは間隔が無効であるか長さがゼロであると誤って想定されてしまいます。 

もう 1 つのエッジケースは、その日のすべてをカバーします。 マージ後の間隔がまとめて 00:00:00 から 24:00:00 に及ぶ場合、合計空き時間はゼロでなければなりません。 結合された間隔は正確に [0, 86400] になり、剰余がゼロになるため、アルゴリズムはこれを自然に処理します。 

最後の微妙なケースは、多くの間隔にわたる重度の重複です。 たとえば、同じ時間内の多数の短い間隔を二重にカウントすべきではありません。 マージ ステップにより、繰り返しのオーバーラップによって全長が複数回増加するのではなく、現在のセグメントが拡張されるだけになり、敵対的な入力の下でも正確さが維持されます。
