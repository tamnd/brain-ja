 ## 解決策
 ## 問題の理解

 私たちには、ツリーを形成する接続された都市のネットワークが与えられています。 それぞれの道路は 2 つの都市を結び、重みがあります。 任意の 2 つの都市の場合、自転車がないため、それらの間には単純なパスが 1 つだけ存在します。 

クエリごとに、指定された 2 つの都市間の一意のパスに沿って値を計算するように求められます。 値は合計や最小値ではなく、そのパス上のすべてのエッジの重みを法でとった積です。$10^9 + 7$。 

したがって、各クエリは次のようになります。 重み付きツリー内の 2 つのノード間のパスに沿って重みの積を見つける。 

この制約により、クエリごとにパスをたどるアプローチは避けられます。 まで$2 \cdot 10^5$ノードと$2 \cdot 10^5$クエリの場合、クエリごとの線形走査でも約$10^{10}$実行可能な限界をはるかに超えた最悪の場合の操作。 

いくつかの特殊なケースは概念的に重要です。 ツリーがチェーンに縮退すると、各クエリがほぼすべてのノードを横断する可能性があるため、クエリごとの単純な走査は最大のコストがかかります。 もう 1 つの微妙な問題は、最大で大きな重みの乗算を繰り返すことです。$10^9$、オーバーフローを避けるためにすべてのステップでモジュラー演算が必要です。 

## アプローチ

 ブルート フォース ソリューションでは、毎回親ポインターまたは DFS を使用して 1 つのノードから別のノードに移動し、途中でエッジの重みを乗算することで各クエリに応答します。 これはパスの定義に直接従うため、これは正しいです。 ただし、ツリーがチェーンである最悪のケースでは、各クエリにコストがかかります。$O(N)$、与える$O(NQ)$が遅すぎる$2 \cdot 10^5$。 

重要な点は、ツリー構造によりノード間の関係を前処理できるため、パス クエリをより小さな再利用可能な部分に分解できるということです。 パスを再計算する代わりに、ツリーをルート化し、ルートからすべてのノードまでの情報を事前計算します。 次に、2 つのノード間の任意のパスは、ルートとその最下位の共通祖先との関係を使用して表現できます。 

ルートから各ノードまでのエッジ重みの積を保存すると、祖先構造を使用して 2 つのノード間のパスに沿った積を再構築できます。 ただし、乗算は加算のようにキャンセルされないため、値を直接減算することはできません。 代わりに、パス分解が 2 つのルートからノードへのパスと共有プレフィックスに分割されるという事実に依存します。 最下位の共通祖先を使用すると、その共有プレフィックスをきれいに分離できます。 

LCA のバイナリ リフティングとルートからノードへの積を組み合わせることで、各クエリに対数時間で答えることができます。

 ## アルゴリズムのチュートリアル

 ### 前処理

 1. 任意のノード、たとえばノード 1 でツリーをルートします。これにより、すべてのノードに親子方向が与えられ、パス推論の一貫性が保たれます。 
2. ルートから DFS を実行して、バイナリ リフティングの親テーブルと値の 2 つの配列を計算します。`up_prod[node]`ルートからそのノードのモジュロまでのエッジの重みの積を格納します。$10^9+7$。 エッジを横切るたびに$u \to v$重さで$w$、設定しました`up_prod[v] = up_prod[u] * w mod M`。 これにより、ルートからノードへのパスがコンパクトにエンコードされます。 
3. バイナリリフティングテーブルを構築する`up[k][v]`、 どこ`up[k][v]`です$2^k$ノードの - 番目の祖先$v$。 これにより、LCA 計算中に対数ステップで上向きにジャンプすることができます。 これが必要な理由は、クエリごとに繰り返される親のクライミングが線形になり、遅すぎるためです。 

### LCA計算

 1. ノードの最小共通祖先を計算するには$a$そして$b$, まず、両方が同じ深さになるように、より深いノードを持ち上げます。 これにより、ルートから等距離にあるノードを比較することが保証されます。 
2. 次に、両方のノードを同時に上に持ち上げ、最初に最大のジャンプを試みます。 いつでも彼らの$2^k$-祖先が異なるため、両方のノードを上に移動します。 このプロセスは、LCA のすぐ下の点に収束します。 
3. いずれかのノードの最後の親は LCA です。 

### クエリの回答

 1. クエリごとに$(a, b)$、LCAを計算します$c$。 
2. からのパス積$a$に$c$ルート プロダクトから次のように派生できます。$$\frac{up\_prod[a]}{up\_prod[c]}$$しかし、剰余算術における除算は、剰余逆算による乗算に置き換えられます。 
3. 同様に、からのパス$b$に$c$は：$$\frac{up\_prod[b]}{up\_prod[c]}$$4. 両方の部分を掛け合わせて剰余を求めます$10^9+7$最終的な答えを得るために。 

### なぜ効果があるのか

 ルートからノードまでの製品`up_prod[x]`ルートから$x$。 任意の 2 つのノードのルートへのパスは、LCA へのパスに沿って正確に重複します。 この共有プレフィックスは両方のルート製品に表示されるため、一度削除する必要があります。 LCA はこのオーバーラップを正確に特定し、モジュラー逆演算によりモジュロ演算でそれをきれいにキャンセルできます。 すべてのエッジは再構成されたパスに 1 回だけ含まれるため、計算された値は真のパス積と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
LOG = 20

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        g[u].append((v, w))
        g[v].append((u, w))

    up = [[0] * (n + 1) for _ in range(LOG)]
    depth = [0] * (n + 1)
    up_prod = [1] * (n + 1)
    parent = [0] * (n + 1)

    sys.setrecursionlimit(10**7)

    def dfs(v, p):
        for to, w in g[v]:
            if to == p:
                continue
            parent[to] = v
            depth[to] = depth[v] + 1
            up_prod[to] = (up_prod[v] * w) % MOD
            up[0][to] = v
            dfs(to, v)

    dfs(1, 0)

    for k in range(1, LOG):
        for v in range(1, n + 1):
            up[k][v] = up[k - 1][up[k - 1][v]]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a

        diff = depth[a] - depth[b]
        for k in range(LOG):
            if diff & (1 << k):
                a = up[k][a]

        if a == b:
            return a

        for k in reversed(range(LOG)):
            if up[k][a] != up[k][b]:
                a = up[k][a]
                b = up[k][b]

        return parent[a]

    def path_product(a, b):
        c = lca(a, b)
        res = up_prod[a]
        res = (res * modinv(up_prod[c])) % MOD
        res = (res * up_prod[b]) % MOD
        res = (res * modinv(up_prod[c])) % MOD
        return res

    q = int(input())
    out = []
    for _ in range(q):
        a, b = map(int, input().split())
        out.append(str(path_product(a, b)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、ツリーの隣接リスト表現を構築することから始まります。 ノード 1 をルートとする DFS は、ルートからの深さとエッジの重みの積の両方を計算します。 同時に、バイナリ リフティング テーブルの最初の祖先レベルを埋めます。 

DFS の後、バイナリ リフティング テーブルはボトムアップで埋められ、サイズのあらゆるジャンプが保証されます。$2^k$利用可能です。 LCA 関数は、最初に深さを調整し、次に両方のノードを 2 のべき乗で減少させて最初の分岐点を見つけます。 

パス積関数は、ルートとノードの積とモジュラー逆関数を使用してクエリの答えを再構築します。 直接除算はモジュロ演算では無効であるため、逆算が必須です。 

実装の微妙な点の 1 つは、値がクエリごとに変化し、任意の重みに依存するため、逆モジュラーが事前計算ではなく高速累乗で計算されるようにすることです。

 ## 特殊なケース

 重要なエッジケースは、両方のノードが親子関係にある場合です。 その状況では、LCA はノード自体の 1 つになります。 アルゴリズムはまだ機能します。`up_prod[c]`は正しくキャンセルされ、フルパス積がより深いノード側に残ります。 

もう 1 つのエッジ ケースは、多くのクエリが LCA としてルートを共有する星型ツリーで発生します。 ここでは、両方のノードがルートの直接の子であるため、答えは 2 つのシングルエッジ パスを乗算することになります。 ルート積は 1 であるため、キャンセルしても正確さに影響はありません。 

最後に、縮退チェーンでは、すべてのクエリ LCA 計算が最大深度リフトになります。 バイナリ リフティング テーブルにより、これが対数時間で実行されることが保証され、中間ノードの繰り返しの走査が回避されます。
