 ## 解決策
 ## 問題の理解

 未知の記数法で書かれた 1 つの足し算が与えられます。 3 つの文字列は 2 つの加数とその合計を表しますが、基数は提供されません。 各文字列は数字を使用して記述されます`0-9`と大文字`A-Z`つまり、数字として解釈すると、各文字は 0 から 35 までの値を表すことができます。 

タスクは、有効な塩基が 1 つだけ存在するかどうかを判断することです。$b$3 つの文字列すべてを基数の数値として解釈すると、$b$、追加は正しいです。 そのようなベースが存在し、一意である場合は、それを出力します。 複数の塩基が機能するか、どれも機能しない場合は、0 が出力されます。 

重要な点は、3 つの数値すべてに同じ基数を使用する必要があり、すべての桁値がその基数で有効である必要があることです。つまり、基数は 3 つの文字列のいずれかに現れる最大桁値より厳密に大きくなければなりません。 

数値あたり最大 256 文字という長さの制約は、すべての候補塩基に対して単純な大きな整数演算を繰り返し使用して、すべてを任意の基底の標準整数に変換して値を解釈しようとすることができないことを意味します。 36 までのすべての基数を直接シミュレーションすることは可能ですが、オーバーフローや重い変換の繰り返しを注意深く回避する必要があります。 

数字が最小基数を強制する場合に、微妙なエッジ ケースが 1 つ発生しますが、算術等価性は複数のより大きな基数で成立します。 たとえば、次のような小さな表現`1 + 2 = 3`すべての塩基で少なくとも 4 が保持されるため、答えは一意ではなく、0 になるはずです。 

もう 1 つの重要なケースは、候補塩基の先頭の数字が無効であり、その塩基が完全に無効になる場合です。 たとえば、キャラクターの場合、`Z`と表示される場合、基数は少なくとも 36 である必要があります。 

## アプローチ

 単純な考えは、最小の有効な基数からある大きな境界まで、考えられるすべての基数を試し、その基数で 3 つの文字列すべてを整数に変換し、加算が成立するかどうかを確認することです。 塩基ごとに、変換には文字列の長さに対して直線的な時間がかかるため、全体的な複雑さは次のようになります。$O(B \cdot n)$、 どこ$B$最大 36 まで可能で、$n$最大 256 まで、単独で許容されます。 

ただし、本当の問題は、正確性と一意性のチェックです。 特に数値関係が複数の塩基で構造的に有効である場合、多くの塩基が偶然方程式を満たす可能性があります。 したがって、すべての有効な塩基を収集し、正確に 1 つだけ存在することを確認する必要があります。 

重要な観察は、制約された範囲から塩基を評価するだけでよいということです。$\max(digits)+1$36 を超えると、入力内の数字を表すことができないため、与えられたアルファベットの制限の下では、これより大きな基数は無関係になります。 

次に、完全な整数変換を回避し、逆に桁ごとの評価 (手動加算と同様) を使用して各基の加算をシミュレートします。 これにより、有効性を効率的かつ堅牢にチェックできるようになります。

 ## アルゴリズムのチュートリアル

 すべての候補塩基を評価し、方程式が成り立つかどうかを確認します。 

1. 3 つの文字列のいずれかに現れる最大桁値を計算します。 これにより、最小の有効な基数が決まります。 文字が値に対応する場合$v$、その後任意の塩基$\le v$その数字はそのような基数に存在できないため、無効です。 
2. この最小値から 36 までのすべての基底を反復します。各基底は、方程式が成立する可能性のある候補系です。 
3. 手算と同じように、基数ごとに右から左へ 1 桁ずつ加算をシミュレートします。 各ステップで、各数値から対応する桁 (または、使い果たされた場合は 0) を取り出し、それを数値に変換し、合計と桁上げがその基数の結果の桁と一致するかどうかを計算します。 
4. いずれかの時点で、現在の基数で数字が無効であるか、算術制約が失敗した場合は、その基数を直ちに拒否します。 
5. 完全なトラバースが完了し、キャリーが残っていない場合は、このベースを有効としてマークします。 
6. すべての塩基を確認した後、有効な塩基の数を数えます。 1 つだけ存在する場合は、それを出力します。 それ以外の場合は 0 を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、位置数値体系の定義を直接適用します。すべての数値は基数に分解されます。$b$各桁が桁上げルールに従っている場合に限り、加算は一貫しています。 唯一の意味のある範囲内で、考えられるすべての塩基が 1 回だけチェックされるため、有効な解を見逃したり、無効な解を受け入れたりすることはありません。 最初の一致を返すのではなく、有効な塩基を明示的にカウントすることによって、一意性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def char_val(c):
    if '0' <= c <= '9':
        return ord(c) - ord('0')
    return ord(c) - ord('A') + 10

def check(a, b, c, base):
    i, j, k = len(a) - 1, len(b) - 1, len(c) - 1
    carry = 0

    while i >= 0 or j >= 0 or k >= 0:
        va = char_val(a[i]) if i >= 0 else 0
        vb = char_val(b[j]) if j >= 0 else 0
        vc = char_val(c[k]) if k >= 0 else 0

        if va >= base or vb >= base or vc >= base:
            return False

        total = va + vb + carry
        if total % base != vc:
            return False

        carry = total // base

        i -= 1
        j -= 1
        k -= 1

    return carry == 0

def main():
    a = input().strip()
    b = input().strip()
    c = input().strip()

    max_digit = 0
    for s in (a, b, c):
        for ch in s:
            max_digit = max(max_digit, char_val(ch))

    valid_bases = []

    for base in range(max_digit + 1, 37):
        if check(a, b, c, base):
            valid_bases.append(base)

    if len(valid_bases) == 1:
        print(valid_bases[0])
    else:
        print(0)

if __name__ == "__main__":
    main()
```この解決策は、文字をすべての基数に対して一貫して数値に変換することから始まります。 の`check`関数は、キャリー伝播を使用して標準的な列単位の加算を実行します。 重要な部分は、数字が表現できない基数を拒否することであり、これは、数字の値が基数以上の場合に直ちに適用されます。 

基底上のループは小さく、制限されているため、代数的再構成ではなく直接シミュレーションに依存します。 これにより、精度の問題が回避され、長い文字列が安全に処理されます。

 ## 特殊なケース

 重要なエッジケースは、すべての数値がゼロの場合です。 最大桁を超える任意の基数が許可されます`0 + 0 = 0`非常に多くの塩基が有効ですが、一意でないため、正しい出力は 0 になります。 すべての塩基がチェックに合格するため、アルゴリズムがこれを処理します。`valid_bases`最終的には 1 より大きくなります。 

もう 1 つのケースは、次のように数字が基数 36 を正確に強制する場合です。`Z`。 有効な方程式が存在する場合でも、ループには上限が含まれるため、アルゴリズムは基数 36 を明示的にチェックします。 複数の塩基も式を満たす場合、必要に応じて一意性は失われます。 

最後に、キャリーが最上位桁を超えて伝播する場合、余分な先頭桁が正確に形成されない限り、チェック関数は基数を正しく拒否し、厳密な位置の正確性を保証します。
