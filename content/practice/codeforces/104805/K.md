 ## 解決策
 ## 問題の理解

 それぞれ 2 ～ 15 の整数の小さなコレクションが与えられます。このコレクションから、元のコレクションから繰り返しを許可して要素を選択することで、新しいマルチセットを構築する操作を繰り返し実行できます。 このように選択されたマルチセットから、単一の数値を計算します。そのマルチセットのサブセットごとに、サブセット内の要素を乗算し、すべてのサブセットにわたるこれらの積を合計します。 

空のサブセットはこの合計に 1 を与えるため、この操作はマルチセットを取得することと同等です。$Y$そして生産$$\sum_{S \subseteq Y} \prod_{y \in S} y.$$このような値を生成した後は、常に元の数値のみを構成要素として使用して、プロセスを有限回繰り返し続けることができます。 タスクは、以下を超えない個別の値の数を数えることです。$L$いつでも生産することができます。 

重要な構造的観察は、積の部分集合和の式に隠されています。 商品を拡大すると$$\prod_{y \in Y} (1 + y),$$すべてのサブセットの合計を正確に取得します。$Y$、空のサブセットを含みます。 したがって、各操作は次の形式の値を生成します。$$\prod_{y \in Y} (1 + y) - 1.$$これにより、問題は部分集合に関する推論から定数に対する乗算構造に関する推論に変換されます。$1 + x_i$、それぞれ 3 ～ 16 の間にあります。 

制約の初期要素の数は少なく、最大 20 ですが、値の範囲は最大 20 です。$10^{12}$。 これにより、すべてのマルチセットまたはすべてのサブセットの組み合わせを明示的に列挙するアプローチは直ちに除外されます。 各数値はさまざまな方法で再結合できますが、その構造は乗算的であり、非常に冗長であるため、値に対する単純な BFS であっても爆発する可能性があります。 

微妙なエッジケースが現れるのは、$x_i$等しいです。 多くの異なるマルチセットが同一の値を生成するため、個別の結果ではなく構造をカウントすると、大幅に過大にカウントされてしまいます。 もう 1 つの問題は、この演算では常に純粋な積よりも少なくとも 1 大きい値が生成されるため、「マイナス 1 シフト」を忘れると、以下と比較するときに不正確な境界とオフバイ 1 エラーが発生することです。$L$。 

## アプローチ

 直接シミュレーションでは、考えられるすべてのマルチセットを列挙しようとします。$Y$、結果の値を計算し、新しく生成された値からプロセスを繰り返します。 繰り返しが許可されているため、マルチセットの数は際限なく増加し、制限されたサイズに制限するだけでもすでに指数関数的な爆発につながります。$N$。 各状態内の計算は管理可能ですが、状態空間自体には制限がなく、すぐに実行可能な制限を超えます。 

重要な簡素化は、操作を製品として書き直すことで実現します。 生成されたすべての値には形式があります$$\prod (1 + x_i)^{c_i} - 1,$$どこ$c_i$は回数要素です$x_i$マルチセットで選択されます。 これは、到達可能なすべての値が、少数の基本整数のセットを繰り返し乗算して形成される積に対応することを意味します。$b_i = 1 + x_i$、それぞれ3から16の間です。 

これにより、サブセット構造が完全に削除され、問題は、上限以下の小さな整数セットから形成されるすべての個別の積を生成することに変わります。$L + 1$。 乗算の順序は重要ではないため、検索空間は指数の選択肢を組み合わせて探索することになりますが、製品の急速な成長により大幅な枝刈りが行われます。 

最適なアプローチは、個別の塩基値を深さ優先に列挙し、各塩基が積に寄与する回数を選択することです。 値が急速に増加するため、各ブランチの深さは非常に限られています。$L + 1$、検索が可能になります。

 ## アルゴリズムのチュートリアル

 まず、それぞれを置き換えて入力を圧縮します。$x_i$と$b_i = x_i + 1$なぜなら、すべての演算は乗算によるこれらの値にのみ依存するからです。 

1. すべての値の中から個別の値を抽出します。$b_i$重複によって、より多くの指数の選択が可能になる以外に、到達可能な製品のセットが変更されることはないためです。 これにより、不要な分岐が削減されます。 
2. 1 から開始して積を構築する再帰的検索を定義します。各ステップで、現在の基本値を何回掛けるかを決定します。 
3. 拠点ごとに$b_i$、現在の積に次の値を乗算してみてください。$b_i^k$、 どこ$k \ge 0$を超えない限り、$L + 1$。 それぞれの選択$k$その要素の選択を表します$k$マルチセット内の回数。 
4. 現在の基数の指数を修正した後、次の基数インデックスを再帰的に処理します。 これにより、以前の塩基を再度訪問することがなくなり、異なる順序で同じ組み合わせをカウントすることがなくなります。 
5. すべての塩基の処理が完了すると、有効な製品が得られます。$P$。 もし$P > 1$、記録します$P - 1$到達可能な値として。 

再帰では、制限によって制限された基本セットのすべての乗算の組み合わせが系統的に列挙されます。 

### なぜ効果があるのか

 すべての有効な構造は指数のベクトルに一意に対応します$(c_1, c_2, \dots, c_m)$、製品にマッピングされます$\prod b_i^{c_i}$。 DFS は、基底の固定順序を強制することにより、各指数ベクトルを 1 回だけ列挙します。 乗算は可換であるため、2 つの異なるパスが同じ指数構成を生成することはありません。 剪定の様子$P \le L + 1$どのブランチも許容範囲外の値を寄与できないことが保証されるため、検索空間は完全かつ有限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, L = map(int, input().split())
    x = list(map(int, input().split()))

    bases = sorted(set(v + 1 for v in x))
    limit = L + 1

    seen = set()

    def dfs(i, cur):
        if i == len(bases):
            if cur > 1:
                seen.add(cur - 1)
            return

        dfs(i + 1, cur)

        b = bases[i]
        nxt = cur
        while True:
            nxt *= b
            if nxt > limit:
                break
            dfs(i + 1, nxt)

    dfs(0, 1)
    print(len(seen))

if __name__ == "__main__":
    solve()
```この実装は、プロセスの指数解釈を直接反映します。 再帰インデックス`i`ベースに対して固定の順序付けを強制し、一意性を確保します。 ループの増殖`nxt`による`b`単一のブランチでその基数のすべての指数選択を繰り返しエンコードします。 の`limit = L + 1`実際に格納される値は常に乗算より 1 小さいため、シフトは非常に重要です。 

よくある間違いは、基本値の重複排除を忘れることです。これにより、冗長な探索が発生しますが、正確な値は保たれますが、速度が低下するだけです。 もう 1 つの微妙な点は、構造が純粋に乗法であるため、ゼロのようなセンチネル値から開始するのではなく、積 1 から開始することです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(S)$| 有効な積の状態はそれぞれ 1 回生成され、乗算の急速な増加によって分岐が大幅に制限されます。 
| スペース |$O(S)$| 訪問結果の保存と、別個の基底の数によって制限される再帰の深さ |

 塩基が少なくとも 3 であるため、個別の状態の数は少ないままであり、積のサイズが指数関数的に増加します。 これにより、最悪の入力配置でも DFS が迅速に終了することが保証されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from math import isclose

    N, L = map(int, sys.stdin.readline().split())
    x = list(map(int, sys.stdin.readline().split()))

    bases = sorted(set(v + 1 for v in x))
    limit = L + 1
    seen = set()

    def dfs(i, cur):
        if i == len(bases):
            if cur > 1:
                seen.add(cur - 1)
            return
        dfs(i + 1, cur)
        b = bases[i]
        nxt = cur
        while True:
            nxt *= b
            if nxt > limit:
                break
            dfs(i + 1, nxt)

    dfs(0, 1)
    return str(len(seen))

assert run("3 7\n2 2 3\n") == "2"
assert run("2 100\n14 15\n") == "2"

# all equal values
assert run("3 50\n2 2 2\n") == "2"

# minimum case
assert run("2 10\n2 3\n") == "2"

 ## 特殊なケース

 すべての入力数値が同一の場合、すべての乗算構造は単一の底の累乗の繰り返しに崩壊します。 DFS は引き続き指数の選択を検討しますが、重複排除により、個別の製品のみがカウントされることが保証されます。 たとえば、入力の場合`2 10 / 2 2`、到達可能な積は 1、3、9 のみであり、1 を減算すると 2 つの有効な値が生成されます。 

いつ$L$は非常に小さいため、多くの分岐は最初の乗算の直後に終了します。 たとえば、`2 5 / 2 3`、両方の塩基は 3 と 4 になりますが、2 番目の乗算はすでに制限を超えているため、単一塩基の寄与のみが残ります。 再帰は引き続き両方の選択肢を参照しますが、ほぼ即座にプルーニングされます。 

いつ$L$が非常に大きい場合、検索の深さはわずかに増加しますが、塩基の指数関数的な増加により、長いチェーンでも浅いままになります。 たとえば、3 の乗算を繰り返すと次の値を超えます。$10^{12}$25 ステップ未満で実行できるため、ブランチが無制限に成長することはありません。
