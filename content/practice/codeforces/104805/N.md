 ## 解決策
 ## 問題の理解

 私たちには、ヴェロニカが知っている単語の小さな辞書が与えられ、次にイーゴリが彼女の独白として書き留めたものを表す単一の長い文字列が与えられます。 課題は、文字を挿入または削除せずに、既知の単語のシーケンスを連結することによって長い文字列を形成できるかどうかを判断することです。 

言い換えれば、文字列を分割できるかどうかを知りたいのです。`s`連続した部分文字列のシーケンスに変換されます。各部分文字列は、指定された単語の 1 つです。 同じ単語を複数回再利用できます。すべての単語を使用する必要はありません。文字列全体を正確にカバーするのに十分な単語のみを使用します。 

入力サイズでは、既知の単語を 100 個まで使用でき、合計の長さは合計で最大 100,000 個になります。`s`最大 100,000 文字にすることもできます。 これにより、指数関数的な時間で文字列の可能なすべてのセグメント化を試みるアプローチは即座に除外されます。 繰り返しスキャンするソリューション`s`効率的に、または位置に対して動的プログラミングを実行します。`s`, が必要です。 

単語が重複したり接頭辞を共有したりする場合、微妙なエッジケースが発生します。 たとえば、辞書に次のような内容が含まれている場合、`"a"`、`"aa"`、 そして`"aaa"`、文字列は`"aaaaa"`、単純に貪欲なアプローチは、短い一致を選択するのが早すぎて失敗する可能性があります。 インデックスを作成せずにすべての位置で単語を照合しようとすると、別の問題が発生します。これにより、文字位置ごとにすべての単語のフル スキャンが繰り返される可能性があります。 

## アプローチ

 強引なアイデアはインデックスから始めることです`0`で`s`そして、現在の接頭辞に一致するすべての辞書の単語を再帰的に試し、その一致の最後から続行します。 これは、文字列内の位置に対する単純な深さ優先検索です。 

このアプローチは正しいですが、同じ部分問題が何度も繰り返される可能性があります。 指定されたインデックスから`s`、すべての単語の一致を何度も試みることがあります。 最悪の場合、各位置は最大 100 の選択肢に分岐し、各一致のコストは最大 O (単語の長さ) になり、敵対的な入力に対して指数関数的な動作が発生します。 

重要な観察は、問題は現在のインデックスにのみ依存しているということです。`s`、どうやってそこに到着したかについてではありません。 これは、各ポジションについての動的計画法を示唆しています。`i`、サフィックスかどうかを知りたいのです。`s[i:]`完全にセグメント化できます。 計算したら、この結果を再利用する必要があります。 

単語を反復処理し、`s[i:i+len(word)]`その言葉に等しい。 合計の語長には制限があるため、この直接比較は十分に効率的です。 あるいは、トライを構築することもできますが、制約があるため、位置ごとにこの小さな辞書スキャンで十分です。 

最終的な解決策は、ポジションを越えた DP になります。`s`ここで、すべての辞書の単語を使用して有効な状態を前方に拡張しようとします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DFS | O(exp) | O(n) | 遅すぎる |
 | ポジションに対するDP | O(n * 総単語数) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ブール配列を定義します`dp`、 どこ`dp[i]`プレフィックスかどうかを示します`s[0:i]`既知の単語に分割できます。 

1.初期化`dp[0] = True`空のプレフィックスは常に有効であるためです。 他の位置はすべて False として始まります。 
2. 位置を反復処理する`i`から`0`に`len(s)`。 
3. もし`dp[i]`は False です。スキップしてください。 これは、位置に到達する有効なセグメンテーションが存在しないことを意味します`i`, したがって、そこから拡張することは無駄です。 
4. 既知の単語ごとに`w`で始まる部分文字列かどうかを確認します。`i`マッチ`w`、つまり、`s[i:i+len(w)] == w`。 
5. 一致する場合は設定します`dp[i + len(w)] = True`有効なセグメンテーションをそのエンドポイントまで拡張できるためです。 
6. すべての位置を処理した後、チェックを入れます`dp[len(s)]`。 Trueの場合は「YES」、そうでない場合は「NO」を出力します。 

### なぜ効果があるのか

 すべてのインデックスで`i`、`dp[i]`までのプレフィックスの有効なセグメント化が存在するかどうかを正確に表します。`i`。 単語を使用して拡張する場合、有効な辞書単語のみを追加するため、新しくマークされた状態は有効なセグメンテーションに対応します。 逆に、有効なセグメンテーションは辞書の単語で終わる必要があり、遷移は最終的に対応するエンドポイントをマークします。 これにより、有効な構造が見逃されたり、無効な構造が導入されたりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    words = [input().strip() for _ in range(n)]
    s = input().strip()

    L = len(s)
    dp = [False] * (L + 1)
    dp[0] = True

    for i in range(L):
        if not dp[i]:
            continue

        for w in words:
            lw = len(w)
            if i + lw <= L and s[i:i + lw] == w:
                dp[i + lw] = True

    print("YES" if dp[L] else "NO")

if __name__ == "__main__":
    solve()
```実装は DP の定式化に直接続きます。 外側のループは文字列内の位置を反復し、遷移は到達可能な位置からのみ試行されるため、不必要な作業が回避されます。 部分文字列の比較`s[i:i+lw] == w`スライスする前に境界を明示的にチェックするので安全です。 

ここでよくある間違いは、遷移を到達可能なものに制限することを忘れることです。`dp[i] == True`これにより、無効なプレフィックスからのセグメントの構築が誤って許可されてしまいます。 もう 1 つの微妙な問題は、スライスする前に境界をチェックしないことです。これにより、不正確な部分一致や無駄な作業が発生する可能性があります。

| 私 | dp[i] | 一致した単語 | 更新されたポジション |
 | --- | --- | --- | --- |
 | 0 | 本当 | ぶぶぶ | dp[6] = True |
 | 0 | 本当 | 他になし | - |

 | 11 | 本当 | ぶぶぶ | dp[17] = True |

このトレースは、複数の辞書単語を連鎖させることができ、DP が到達可能な境界を正しく累積していることを示しています。 

失敗したケースも考慮できます。 

入力:```
2
ab
aba
abab
```で`i = 0`、 両方`"ab"`そして`"aba"`可能性のある移行です。 DP は位置 2 と 3 をマークします。2 から、経由して 4 に到達します。`"ab"`、完全なカバーが可能です。 これは、単なる貪欲な選択ではなく、すべての移行を検討することが必要である理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * m * k) | n は s の長さ、m は単語数、k は部分文字列比較による平均単語長です。 
| スペース | O(n) | 文字列位置に対する dp 配列 |

 n ≤ 100,000 および m ≤ 100 の場合、各遷移は単純な境界付き部分文字列の比較であり、到達不能な状態を早期にスキップすることで実際の作業が大幅に削減されるため、この積は Python で引き続き許容されます。

 ## 特殊なケース

 重要なエッジケースは、貪欲な選択が失敗する辞書の単語の重複です。 考慮する`words = ["a", "aa"]`そして`s = "aaa"`。 アルゴリズムセット`dp[1]`、`dp[2]`、 そして`dp[3]`これは、到達可能な各インデックスで両方の拡張子を探索するため、正しく実行されます。 貪欲なアプローチには次のようなことが必要になる場合があります`"aa"`最初は行き詰まりますが、DP はまだ維持されます`"a"`代替パスとして。 

もう 1 つの特殊なケースは、複数の単語が同じ位置で一致する場合です。 トランジションは追加的なものであるため、複数のエンドポイントをマークすると、有効なセグメンテーションが失われないことが保証されます。 

最後に、空の到達可能性はきれいに処理されます。`dp[i]`に到達することはなく、そこから遷移が発生することはなく、後の状態への無効な伝播を防ぎます。
