 ## 解決策
 ## 問題の理解

 4 つの名前のコレクションが与えられています。 イゴールには好きな名前のリストと嫌いな名前のリストがあります。 アイラには、好きな名前のリストと嫌いな名前のリストもあります。 名前は、両方の人がそれを好きで、どちらも明示的に嫌わない場合にのみ使用可能とみなされます。 タスクは、そのような使用可能な名前をすべて、重複せずに辞書順に並べて出力することです。 

これについて考えると便利な方法は、各人が 2 つのセット、つまり「必ず含まなければならない」セットと「禁止」セットを定義するということです。 最終的な答えは、どちらかの禁止されたセットに含まれるすべての要素が削除された、2 つの「must contains」セットの共通部分です。 

入力サイズは十分に小さいため、個々の名前のハッシュまたは並べ替えを伴うすべての操作は十分に高速です。 最悪の場合でも、名前の数は合計でせいぜい数千件です。 これは、リスト間の文字列の二次比較を伴うものを即座に除外します。これは、リストのペアごとに 10^6 の順序で比較することを意味するためですが、ハッシュ セットまたは並べ替えを直接使用するだけで十分であることも示唆しています。 

微妙な問題は、入力リスト内の重複です。 名前は同じリスト内で複数回出現する可能性があります。つまり、リストを単純な配列として扱い、それらを位置的に交差させると、出力で重複が発生したり、フィルタリングが正しく行われたりする可能性があります。 もう 1 つの問題は、名前が同じ人によって好まれたり嫌われたりする可能性があることです。 その場合、選択した名前を誰も嫌わないことが条件で明示的に要求されているため、嫌いな名前をオーバーライドする必要があります。 

具体的なエッジケースとしては、ある名前が両方に好かれているにもかかわらず、一方の嫌いリストにも載っている場合があります。 

入力：```
1 1 1 0
alex
alex
alex
```ここでは両方とも「アレックス」が好きですが、イゴールはそれを嫌います。 正しい出力は空です。 類似リストのみをチェックする単純なアプローチでは、誤って「alex」が出力されてしまいます。 

もう 1 つのエッジ ケースは、出力が繰り返される重複です。 

入力：```
2 2 0 0
mike
mike
mike
mike
```正しい出力:```
mike
```重複排除が明示的に処理されない限り、生のリストに対する単純な交差は「mike」を複数回出力します。 

## アプローチ

 この強引なアイデアは、Igor の「いいね！」リストにある各名前を扱い、それが Ira の「いいね」リストに含まれるかどうかをチェックすると同時に、両方の「嫌い」リストをスキャンして禁止されていないことを確認するというものです。 候補名ごとに、最大 4 つのリストを線形にスキャンする必要があります。 最悪の場合、すべてのリストに n 個の要素が含まれる場合、O(n^2) 個の文字列比較になります。 文字列比較には最大 20 文字のコストがかかりますが、上限に達すると快適に遅すぎます。 

重要な観察は、実際に必要なのはスキャンではなくメンバーシップ チェックであるということです。 各条件が純粋にセットベースであることを認識すると、各リストをハッシュ セットに変換できます。 この場合、名前が有効かどうかを確認するのにかかる時間は、条件ごとに平均 O(1) になります。 全体の問題は、好きと嫌いのセットを構築し、2 つの似たセットを交差させ、嫌いなセットの結合を減算することに帰着します。 

これにより、繰り返しスキャンの問題が、候補セットに対する 1 回のパスとその後の定時間フィルタリングに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n1 + n2) · (n1 + n2 + m1 + m2)) | O(1) おまけ | 遅すぎる |
 | 最適 (ハッシュ セット) | O(n1 + n2 + m1 + m2) | O(n1 + n2 + m1 + m2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 4 つの整数値をすべて読み取り、入力からすべての名前を読み取り、Igor の好み、Ira の好み、Igor の嫌い、および Ira の嫌いに対応する 4 つの別個のコレクションに入れます。 最終的なフィルタリングでは各グループが異なる制約の役割を表すため、グループ化は重要です。 
2. 各リストのすべての名前を個別のセットに挿入します。 これにより、重複が自動的に削除され、メンバーシップ クエリが定数時間の操作に変換されます。 
3. Igor の好みのセットと Ira の好みのセットの共通部分を取得して、候補セットを構築します。 これにより、残りのすべての名前が「両方とも気に入る」要件を満たすことが保証されます。 
4. この候補セットから、Igor の嫌いなセットまたは Ira の嫌いなセットのいずれかに出現するすべての名前を削除します。 これにより、どちらも選択した名前を嫌いになれないという制約が強制されます。 
5. 最終セットをソートされたリストに変換し、辞書順に出力します。 セットでは順序が保持されないため、ソートが必要ですが、この問題では順序付けされた出力が明示的に要求されます。 

その正しさの背後にある理由は、あらゆる段階で、必要かつ十分な制約を適用することで名前の範囲を狭めているということです。 名前は、両方に好まれる場合に限り、最初のフィルターを通過しても残ります。 名前は、どちらの当事者によっても明示的に禁止されていない場合に限り、2 番目のフィルタでも存続します。 問題には他の条件が存在しないため、最終的なセットは有効な回答と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n1, n2, m1, m2 = map(int, input().split())

    igor_like = [input().strip() for _ in range(n1)]
    ira_like = [input().strip() for _ in range(n2)]
    igor_bad = [input().strip() for _ in range(m1)]
    ira_bad = [input().strip() for _ in range(m2)]

    s1 = set(igor_like)
    s2 = set(ira_like)
    bad1 = set(igor_bad)
    bad2 = set(ira_bad)

    candidates = s1 & s2
    forbidden = bad1 | bad2

    result = sorted(x for x in candidates if x not in forbidden)

    sys.stdout.write("\n".join(result))

if __name__ == "__main__":
    main()
```実装はアルゴリズムをほぼそのまま反映しています。 各入力ブロックは直ちにセットに変換され、重複排除と効率的な検索の両方が保証されます。 交差演算子は、共有優先条件を強制するために使用されます。 いずれかのリストに名前が出現すると名前が失格となるため、嫌いセットの結合により単一の除外フィルターが形成されます。 最終的な理解では候補セットに対して 1 回のパスが実行され、出力要件を満たすために最後にのみソートが適用されます。 

よくある実装上の間違いは、並べ替えの前に重複排除を忘れることです。これにより、出力内で名前が重複して表示されます。 もう 1 つは、交差点の前に嫌いフィルターを誤って適用することです。これにより、最終的な交差点ステップでその名前を必要としない人によってのみ嫌われる場合にのみ考慮されるべき名前が削除される可能性があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、同じ人の「いいね」リストと「嫌い」リストの両方に名前が表示される場合です。 例えば：```
1 0 1 0
alex
alex
```イゴールは「アレックス」を好きであると同時に嫌いです。 セット構築フェーズでは、「好き」セットと「嫌い」セットの両方に同じ要素が含まれます。 候補の形成中、「alex」は両方の類似セットに存在する場合にのみ含まれますが、Ira には類似が存在しないため、交差には入りません。 正しい出力は空です。 フィルター処理の前に共通部分が計算されるため、アルゴリズムはこれを自然に処理します。そのため、1 人の人のリスト内の矛盾によって名前が誤って保存されることはありません。 

もう 1 つのエッジ ケースは、すべてのリストに同じ名前が含まれているが、そのすべてが少なくとも 1 人に嫌われている場合です。 例えば：```
1 1 1 1
bob
bob
bob
bob
```交差後は「ボブ」が候補になりますが、両方の嫌いセットに出現するため削除されます。 最終的な出力は空であり、単一の嫌いなものは失格であるという要件に一致します。
