 ## 解決策
 ## 問題の理解

 連続して配置された一連の塔の高さが与えられます。 各タワーには数値による高さがあり、左から右の順序を維持しながらいくつかのタワーを選択できます。 このようなすべてのサブシーケンスの中で、選択されたすべての高さが、以前に選択された高さと比較して厳密に増加している最も長いサブシーケンスが必要です。 

言い換えれば、値が上昇し続ける左から右に移動するインデックスの最長チェーンの長さを探しています。 出力は単一の数値です。つまり、このような最適な増加チェーンで選択できるタワーの数です。 

この制約では、最大 300,000 個のタワーが許可され、各高さは 10^9 までの大きさにすることができます。 サブシーケンスの数は n とともに指数関数的に増加するため、これにより、すべてのサブシーケンスを検査しようとするソリューションは即座に除外されます。 3・10^5 での n^2 は約 9・10^10 回の演算であり、1 秒あたりの実用的な制限をはるかに超えているため、O(n^2) メソッドでも最悪の場合は遅すぎます。 

微妙な点は、これは連続したセグメントを要求していないため、スライディング ウィンドウ手法は適用されないことです。 サブシーケンスは要素を任意にスキップできるため、単純な動的プログラミングが必要になりますが、コストが高くなります。 

単純な推論を打ち破ることが多いエッジ ケースには、厳密に減少しているシーケンス、すでにソートされているシーケンス、または繰り返しパターンが含まれているシーケンスが含まれます。 

次のような厳密に減少する例`5 4 3 2 1`増加するペアが存在しないため、答えは 1 になります。 次のような厳密に増加する配列`1 2 3 4 5`答えは 5 です。連続した選択を前提としたり、厳密な不等式を忘れたりする不注意な実装は、等しい値や隣接する構造を誤って扱う可能性があります。 

## アプローチ

 最も直接的なアイデアは動的プログラミングです。 dp[i] を、位置 i で終了する最も長く増加するサブシーケンスの長さとして定義するとします。 dp[i] を計算するには、すべての j < i をチェックし、a[j] < a[i] の場合は dp[i] を更新します。 これは正しいです。i で終わるすべての有効なサブシーケンスは、それより前の位置から来ている必要があるからです。 

これにより、すべてのペア (j, i) にわたる二重ループが直ちに発生します。 合計作業量は約 n(n-1)/2 回の比較です。 n = 3・10^5 の場合、これは完全に不可能です。 

重要な観察は、実際には、正確な高さごとに考えられるすべての dp 値を知る必要はなく、異なる長さのサブシーケンスを増加させる場合に考えられる最適なテール値のみを知る必要があるということです。 長さ L ごとに、長さ L の増加するサブシーケンスの可能な最小終了値を維持すると、この構造を効率的に更新できます。 

新しい値 x を処理するときは、x によって拡張できる最長のサブシーケンスを知りたいと考えます。 これは、tail[L] < x となる最大の L を見つけることと同じです。 末尾をソートされた順序で保存すると、これは二分探索問題になります。 

次に、テールを適切に交換または延長します。 x が既存のすべての裾よりも大きい場合、LIS の長さを延長します。 それ以外の場合は、ある長さに対して可能な限り最良の終了値を改善します。 

これにより、問題は古典的な忍耐ソート スタイルの LIS 計算に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのペアにわたる DP | O(n^2) | O(n) | 遅すぎる |
 | 貪欲 + 二分探索 (テール) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. という空のリストを維持します。`tail`、 どこ`tail[k]`長さ k+1 の増加するサブシーケンスの可能な最小の終了値を表します。 
2. 各タワーの高さ x を左から右に繰り返します。 
3. 現在の x に対して、二分探索を実行します。`tail`次のような最初のインデックスを見つけるには`tail[i] >= x`。 
4. そのようなインデックス i が存在する場合は、次のように置き換えます。`tail[i]`×付き。 これにより、長さ i+1 のサブシーケンスの最小終了値が向上します。 
5. そのようなインデックスが存在しない場合は、x を追加します。`tail`これは、以前よりも長い増加部分列が見つかったことを意味します。 
6. すべての要素を処理した後、`tail`が答えです。 

二分探索が機能する理由は次のとおりです。`tail`常に厳密な昇順で維持されます。 各位置は、その長さのサブシーケンスの可能な限り最良の「最後の値」を表し、より良い (小さい) 終わりがより多くの拡張機会を可能にするため、常に優先されます。 

### なぜ効果があるのか

 あらゆる段階で、`tail`最適なフロンティアを保存します。長さ L ごとに、長さ L の増加するサブシーケンスの最小の終了値を保持します。終了値がより小さい長さ L のより適切な候補があった場合、将来の要素のためにより多くの余地を残すため、常にそれを優先します。 二分探索配置により、サブシーケンスの長さの増加特性を決して壊すことがなく、置換によって達成可能な最大長が減少することはなく、将来の柔軟性が向上するだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    tail = []
    
    for x in a:
        lo, hi = 0, len(tail)
        while lo < hi:
            mid = (lo + hi) // 2
            if tail[mid] < x:
                lo = mid + 1
            else:
                hi = mid
        if lo == len(tail):
            tail.append(x)
        else:
            tail[lo] = x
    
    print(len(tail))

if __name__ == "__main__":
    solve()
```実装の中核は、現在の値でサブシーケンスを置換または拡張できる最初の位置を見つける二分探索です。 条件`tail[mid] < x`等しい値は増加チェーンを拡張することができないため、厳密に増加するサブシーケンスが保証されます。 

よくある間違いは、`<=`の代わりに`<`、これにより、厳密でないシーケンスが誤って許可されます。 もう一つの微妙な問題は、それを忘れていることです`tail`実際のサブシーケンスではありません。 それは簿記の構造です。

 ## 特殊なケース

 次のような入力の減少`5 4 3 2 1`ドライブ`tail`最初の要素を繰り返しリセットします。 それぞれの値を処理した後、`tail`残る`[1]`。 すべての新しい値は前の末尾の状態より小さいか等しいため、アルゴリズムはシーケンスの拡張を正しく回避します。 

次のようなすべて等しい入力`7 7 7 7`常にインデックス 0 で置換をトリガーし、維持します`tail`として`[7]`。 これにより、厳密な比較が強制され、等しい要素がサブシーケンスを拡張できないことが確認されます。 

入力が厳密に増加している場合は、追加が繰り返されていることを示します。 のために`1 2 3 4`、`tail`は置換なしで単調に増加し、アルゴリズムが完全に拡張可能なシーケンスを正しく認識していることを示しています。
