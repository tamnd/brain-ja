 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースでは、整数の配列を受け取ります。 私たちの仕事は、ポジションのペアが何組あるかを数える事です$(i, j)$と$i < j$値間の非常に特殊な代数関係を満たす$a_i$そして$a_j$。 

正の整数が見つかった場合、ペアは有効であるとみなされます。$x$そして$y$2 つの配列値が対称変換によって生成されるように、1 つの値は次のように動作します。$x^2$で割る$y$、もう一方は次のように動作します$y^2$で割る$x$。 同じペア$(x, y)$両方の数字を同時に説明する必要があります。 

制約により、最大で次のことが許可されます。$5 \cdot 10^4$すべてのテスト ケースの合計数、および値は最大で$10^9$。 これにより、すべてのペアを直接試行するソリューションは即座に除外されます。$O(n^2)$約につながるだろう$10^9$最悪の場合の運用。 

さらに微妙な問題は、条件に隠れた整数変数が含まれていることです。$x$そして$y$間の直接的な関係だけでなく、$a_i$そして$a_j$。 つまり、条件を数値自体のみに依存するプロパティに変換する必要があります。 

いくつかの特殊なケースでは、よくある間違いが明らかになります。 

すべての数字が$1$の場合、次を選択するため、すべてのペアが有効になります。$x = y = 1$どのペアでも機能します。 自明な因子構造を無視するソリューションでも、これを正しく処理する必要があります。 

次のような数字がある場合$8$そして$2$、単純な試みでは、比率または平方を個別に一致させようとする可能性がありますが、隠れた結合は$x$そして$y$これは、そのようなローカル推論が完全な制約から導出されない限り失敗することを意味します。 

数値が完全な立方体である場合、または素数構造が繰り返されている場合、特に因数分解が含まれる場合、不注意に指数を処理すると正確性が損なわれる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアに対して反復処理が行われます。$(i, j)$、そして各ペアについて整数を解こうとします$x, y$方程式を満たすもの。 たとえ代数的に式を導いたとしても、$x$そして$y$、妥当性をチェックするには、ペアごとに因数分解または指数の検証が必要となり、大まかに次のようになります。$O(n^2 \sqrt{A})$が遅すぎます。 

重要な洞察は、この条件が基本的に乗法的であり、素因数に基づいているということです。 すべてを素指数で書き直すと、整数の存在が$x$そして$y$これらの指数に厳密なモジュール制約を課します。 

代数的操作の後、隠れた変数は消え、条件は驚くほど単純なステートメントになります。つまり、2 つの数値は、それらの素数の指数ベクトルがすべての素数のモジュロ 3 に一致する場合にのみ互換性があります。 

これにより、問題はペアごとの実行可能性チェックからグループ化の問題に変換されます。 各数値は、各指数が 3 を法として減算される因数分解から導出される正規の「署名」にマッピングできます。すべての有効なペアは 2 つの同一の署名から得られるため、各グループ内の組み合わせをカウントするだけで済みます。

 ## アルゴリズムのチュートリアル

 次に、各数値を、状態に関連する情報を正確に取得する正規化された表現に変換します。 

1. 試算を使用して各数値を素因数分解します。$\sqrt{a_i}$。 私たちがこれを行う理由は、$a_i \le 10^9$, したがって、約 31623 までの素数で十分です。 
2. 各素因数について$p^e$、指数を置き換えます$e$と$e \bmod 3$。 システムから導出される制約では剰余 mod 3 のみが重要であるため、このステップでは実現可能性に影響を及ぼさないすべての情報が削除されます。 
3. 残りの非ゼロ残基から数値の正規署名を再構築します。 この署名は、番号が最初にどのように形成されたかには関係ありません。 
4. ハッシュ マップを使用して、各署名が配列内に出現する回数を数えます。 
5. 表示される各署名について$k$回、追加$k(k-1)/2$同じ署名グループ内のすべてのペアが有効であるため、答えは異なります。 

このグループ化が機能する理由は、元の条件がすべての素数にわたって同一の剰余指数構造を強制するためです。 2 つの数値が 3 を法とする素数指数で異なる場合、選択の余地はありません。$x$そして$y$両方の方程式の不一致を同時に調整できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def factor_signature(x, primes):
    res = []
    for p in primes:
        if p * p > x:
            break
        if x % p == 0:
            e = 0
            while x % p == 0:
                x //= p
                e += 1
            r = e % 3
            if r:
                res.append((p, r))
    if x > 1:
        res.append((x, 1))
    return tuple(res)

def build_primes(limit=31650):
    sieve = [True] * (limit + 1)
    primes = []
    for i in range(2, limit + 1):
        if sieve[i]:
            primes.append(i)
            step = i
            start = i * i
            if start <= limit:
                for j in range(start, limit + 1, step):
                    sieve[j] = False
    return primes

def solve():
    primes = build_primes()
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        freq = {}
        ans = 0

        for x in arr:
            sig = factor_signature(x, primes)
            ans += freq.get(sig, 0)
            freq[sig] = freq.get(sig, 0) + 1

        print(ans)

if __name__ == "__main__":
    solve()
```解決策は、以下の素数を事前計算することから始まります。$\sqrt{10^9}$, このセットを使用すると、すべての数値を完全に因数分解できるためです。 

次に、各数値は素因数分解に基づいて署名に変換されますが、3 を法とする指数剰余のみが保持されます。署名は次のタプルとして保存されます。$(prime, exponent \bmod 3)$、一意性とハッシュ可能性を確保します。 

署名付きの新しい番号が追加されたとき、回答は段階的に蓄積されます。$s$が処理されると、同じ署名を持つ以前に確認されたすべての数値と有効なペアが形成されるため、現在の周波数をインクリメントする前に追加します。 

## 実用的な例

 配列を考慮してください$[1, 1, 1]$。 

すべての数値には空の因数分解署名が含まれています。 どのペアも一致します。 

| ステップ | 値 | 署名 | 周波数マップの更新 | 新しいペア |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | () | {():1} | 0 |
 | 2 | 1 | () | {():2} | 1 |
 | 3 | 1 | () | {():3} | 2 |

 合計3ペア、お揃いです$3 \cdot 2 / 2 = 3$。 

ここで考えてみましょう$[2, 8, 4]$。 

署名を計算します。 

-$2 = 2^1 \Rightarrow (2,1)$-$8 = 2^3 \Rightarrow (2,0)$-$4 = 2^2 \Rightarrow (2,2)$| ステップ | 値 | 署名 | 周波数マップの更新 | 新しいペア |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | {(2,1)} | {(2,1):1} | 0 |
 | 2 | 8 | {(2,0)} | {(2,1):1,(2,0):1} | 0 |
 | 3 | 4 | {(2,2)} | {(2,1):1,(2,0):1,(2,2):1} | 0 |

 一致する署名が 2 つもないため、答えは 0 になります。 

これらの例は、同一のモジュラー指数構造のみが有効なペアを生成することを示しています。

 ## 特殊なケース

 完全に 1 で構成される入力の場合、すべての数値が空の署名にマップされます。 このアルゴリズムは、単一バケット内のすべてのペアをカウントし、$n(n-1)/2$を選択したため、これは正しい動作と一致します。$x = y = 1$は、任意のペアの元の方程式を満たします。 

同じ素数の異なる累乗である数値の場合、次のようになります。$2, 4, 8$、それぞれは 3 を法とする異なる指数を持ち、異なる署名を生成します。 どのグループにも複数の要素が含まれていないため、アルゴリズムはゼロのペアを正しく生成します。これは、一貫した要素が存在しないという事実と一致します。$x, y$異なる剰余にわたってすべての指数制約を同時に満たすことができます。
