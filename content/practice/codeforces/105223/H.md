 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースは、いくつかの石の山からなるゲームの状態を記述します。 各ターンで、プレイヤーは空でない山から 1 つの石を削除するか、現在のサイズが同じで空ではない 3 つの山を正確に選択し、それら 3 つの山のそれぞれから 1 つの石を削除する組み合わせ移動を実行できます。 

プレーヤーは交互に手を動かし、動けなかったプレーヤーが負けます。これはすべての山が空の場合にのみ起こります。 問題は、最適なプレイの下で、最初に移動したプレイヤー (ベッシャー) が強制的に勝利するかどうかを判断することです。 

制約は大きく、すべてのテスト ケースで最大 200,000 個のパイルがあり、パイル サイズは最大 10^9 です。 これにより、ゲームプレイや状態探索のシミュレーションが即座に除外されます。 状態を動的にモデル化したり、動きを検索したりするソリューションは、分岐係数が大きく、深さが石の総数に達する可能性があるため、実行不可能です。 

これらの制約に現実的に耐えることができる唯一の構造は、構成全体を小さな不変条件に圧縮するものであり、これにはパリティまたは単純な集計が含まれる可能性が高くなります。 

素朴な推論による微妙な失敗例は、「任意の山から 1 つ取る」という動きのために杭が独立していると仮定することです。 たとえば、杭の場合`[1, 1, 1]`、独立性は 3 つの別々のシングル ストーン ゲームを示唆しますが、トリプル パリティの手を使用すると、1 つの手で 3 つのストーンをすべて取り除くことがすぐに可能になり、ゲームの長さと構造が大幅に変わります。 正しいソリューションは、その相互作用を考慮する必要があります。 

もう 1 つの誤解を招きやすいケースは、杭の数のみが重要であると考えることです。 例えば、`[2, 2, 2]`そして`[1, 1, 1]`カウントの点では同一の構造を持っていますが、大まかに推論しようとすると、将来のパリティの動作が異なります。 

## アプローチ

 ブルートフォースアプローチでは、状態をパイルサイズの完全なベクトルとして扱い、メモ化による再帰を使用して勝ち/負けの位置を計算しようとします。 各州は最大で分岐します。`n`パリティ グループに応じて、シングル削除の移動と、潜在的に多くのトリプル削除の移動が行われます。 状態を圧縮したとしても、各パイルは独立して次の値から減少する可能性があるため、到達可能な構成の数は天文学的に大きくなります。`10^9`に`0`。 これにより、状態ベースの動的プログラミングは不可能になります。 

重要な観察は、すべての手が石の合計数を 1 または 3 ずつ減らすことです。どちらも奇数であるため、すべての手が石の合計のパリティを反転します。 これにより、合計パリティに基づいてゲーム グラフが 2 つの交互のレイヤーに即座に制限されます。 

総和の平価性に注目すると、構造はさらに単純化されます。 調べたすべてのケースにおいて、特別なトリプルパリティの動きの存在は、合計パリティを超える 2 番目の独立した不変式を作成しません。これは、それでも奇数の石を消費し、パリティを維持したり循環的利点を生み出す操作を導入したりしないためです。 負けたポジションの到達可能性を変えることなく、3つの独立した単一除去を1つの動きにバンドルするだけです。 

これは核心的な単純化につながります。ゲームの結果は、石の合計数が奇数か偶数かによってのみ決まります。

 ## アルゴリズムのチュートリアル

 各テスト ケースを単一の整数、つまりすべてのパイル サイズの合計に縮小します。 

1. すべての山のすべての石の合計を計算します。 これは重要な唯一のグローバル数量です。移動するたびに合計が奇数だけ変化し、パリティが反転するためです。 
2. この合計が奇数か偶数かを確認します。 最適なプレイではパリティによって勝者が完全に決まります。 
3. 合計が奇数の場合は、最初のプレイヤーが勝ちます。 それ以外の場合は、2 番目のプレーヤーが勝ちます。 

これで十分である理由は、すべての合法的な手がゲームを合計石の等価性が反対の状態に移行するためです。 唯一の最終状態はサム ゼロ (偶数) であるため、奇数和状態には少なくとも 1 つの手が必要であり、最適なプレイとは、終了までの各ターンで対戦相手を反対のパリティに強制することになります。 

## なぜ機能するのか

 ゲームは、各エッジが正当な動きに対応し、すべてのエッジが合計のパリティを反転する、有限の有向非巡回グラフとして見ることができます。 終端位置は偶数パリティ (和ゼロ) を持つため、ゲームは厳密にパリティ層ごとに勝ち位置が切り替わる 2 部構造になります。 パリティ制限付きトリプルムーブによって導入される追加の不変条件はなく、この交互を破ったり、パリティ層内に別の負けクラスを作成したりすることはないため、パリティは勝利条件を完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        total = sum(arr)
        if total % 2 == 1:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```実装は削減の直後に行われます。 テスト ケースごとの唯一の計算は配列の合計であり、制約の下では安全です。 パイルごとのパリティを追跡したり、遷移をシミュレートしたりする必要はありません。 

ここでよくある間違いは、奇数と偶数の山のカウントを維持しようとしたり、トリプルムーブ条件をシミュレートしようとしたりすることです。 グローバル合計はすべての関連情報をすでにエンコードしているため、最終的な決定には影響しません。 

## 実用的な例

 杭がある場所の入力を考慮します`[1, 1]`。 

| ステップ | パイル | 合計 | 決定 |
 | --- | --- | --- | --- |
 | 開始 | [1, 1] | 2 | 偶数 |

 合計は偶数であるため、最初のプレイヤーが負けると予測されます。 実際、どんな手でも合計が 1 に減り、2 番目のプレイヤーに 1 つの石が残り、それを受け取って勝つことができます。 

ここで考えてみましょう`[1, 1, 1]`。 

| ステップ | パイル | 合計 | 決定 |
 | --- | --- | --- | --- |
 | 開始 | [1、1、1] | 3 | 奇数 |

 合計は奇数なので、最初のプレイヤーが勝ちです。 実際、トリプルパリティの手をすぐに使用して、3 つの石をすべて削除し、ゲームを終了することができます。 

ここで考えてみましょう`[1, 1, 2]`。 

| ステップ | パイル | 合計 | 移動の選択 | 次の合計 |
 | --- | --- | --- | --- | --- |
 | 開始 | [1、1、2] | 4 | 2から削除 | 3 |
 | 結果 | [1、1、1] | 3 | 強制移行 | 奇数 |

 考えられるすべての動きは奇数和の状態につながり、次のプレイヤーが勝ちとなり、開始位置が負けになります。 

これらの例は、最適推論の下では総和のパリティのみが安定であることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        total = sum(arr)
        out.append("YES" if total % 2 == 1 else "NO")
    return "\n".join(out) + "\n"

# provided sample (interpreted)
assert run("1\n2\n1 2\n") == "NO\n"

# all equal small
assert run("1\n3\n1 1 1\n") == "YES\n"

# even sum simple
assert run("1\n3\n1 1 2\n") == "NO\n"

# single pile
assert run("2\n1\n1\n1\n2\n") == "YES\nNO\n"

# large even
assert run("1\n4\n2 2 2 2\n") == "NO\n"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`[1,1,2]`| いいえ | 混合パリティ負け位置 |

 ## 特殊なケース

 単一の山の場合、ゲームは 1 つの石を繰り返し取り除くことになるため、結果は純粋にパリティによって変わります。 合計が正確にパイル サイズであり、パリティが単一のテイク 1 ゲームの既知の結果と一致するため、アルゴリズムはこれを正しく処理します。 

トリプルムーブが技術的に利用可能な構成の場合、次のようになります。`[2,2,2]`、アルゴリズムは引き続き正しく動作します。 合計は偶数であるため、最初のプレイヤーの損失が予測されます。 トリプルムーブが存在するとしても、それは 3 つの石を削除するだけであり、パリティに基づく結論は変わりません。 

のような混合物の場合`[1,1,1,1]`、異なるステージで複数のトリプルムーブが可能ですが、それでも各ムーブはパリティを反転します。 合計は偶数であるため、最初のプレーヤーが負けますが、段階的に追跡すると、どの動きでもこの分類の正確さが維持されます。
