 ## 解決策
 ## 問題の理解

 We are simulating a hash table that supports inserting and deleting items, but insertion is not direct. 各項目にはハッシュ値によって指定される優先開始位置があり、そのスロットが占有されている場合、テーブルは固定サイズのジャンプで前方にプローブされます。`m`モジュロ`h`空きセルが見つかるまで。 

必要な重要な数量は、最終的な配置ではなく、挿入時の非効率です。 新しいアイテムを配置しようとするときにアルゴリズムが占有セルをチェックするたびに、そのチェックは 1 回の「ダミー呼び出し」としてカウントされます。 削除は単にセルを解放するだけであり、コストには影響しません。 

したがって、タスクは、テーブルの現在の状態を維持しながら一連の挿入と削除を処理し、挿入中に行われたすべての失敗したプローブを合計することです。 

この構造は基本的にステップ サイズを備えた円形配列です。`m`つまり、各挿入は空のスロットが見つかるまでモジュラー演算の決定的なサイクルに沿って進みます。 

制約は次のとおりです`2 * 10^5`操作とテーブルのサイズ`2 * 10^5`。 挿入ごとに空きスロットが見つかるまで線形にスキャンする単純なシミュレーションは、複数の操作にわたって多数のプローブが実行されると、二次的な動作に低下する可能性があります。 各挿入はテーブルの大部分を横断する可能性があるため、これは時間制限を超えてしまいます。 

微妙な点は、将来のプローブ パスを変更する穴が開く可能性があるため、削除が重要であるということです。 もう 1 つの重要な詳細は、ID は挿入に対して一意であるため、削除時に各 ID を現在の位置に直接マッピングできることです。 

単純な間違いは、位置を追跡せずに挿入を最初から再計算することです。 たとえば、各 ID が配置された場所を保存しないと、削除が不可能になったり、検索が必要になったりして時間がかかりすぎます。 

別の失敗例は、複数の挿入が同じプローブ サイクル内でクラスター化された場合に発生します。 たとえば、次の場合`h = 5`、`m = 2`、ハッシュに挿入`0, 0, 0, 0`同じサイクルを繰り返しスキャンします`0 → 2 → 4 → 1 → 3 → 0`、多くの衝突が発生します。 単純なアプローチでは、同じ占有パスを繰り返し通過する可能性があり、二次コストが発生する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 ハッシュ テーブルを表す配列を維持します。 挿入ごとに、ハッシュ値から開始してステップごとに繰り返し移動します`m`モジュロ`h`空のスロットが見つかるまで、発生したすべての占有スロットをダミー コールとしてカウントします。 空きセルが見つかったら、そこにアイテムを配置し、その位置を ID をキーとする辞書に保存します。 

これは正確なプローブ規則に従っているため、正しいです。 ただし、最悪の場合の挿入あたりのコストは、成功するまでに遭遇した占有セルの数に比例します。 テーブルが密になったり、プローブサイクルが長い場合、単一の挿入が横断する可能性があります。`O(h)`ポジション。 以上`n`操作、これは次のことにつながります`O(nh)`が鈍くなるにもほどがあります。`2 * 10^5`。 

重要な点は、各プローブを段階的に物理的にシミュレートする必要がないということです。 重要なのは、開始ハッシュが与えられた場合、固定等差数列モジュロに沿って最初の空の位置を見つける必要があるということです。`h`。 これは、「循環シーケンスに沿った次に利用可能なスロット」の問題になります。 

各セルが占有されているかどうかを維持できます。 重要な最適化は、各位置が占有されたとき、および挿入中にスキャンするときにのみアクセスされることです。 空きスロットが見つかるまで前進することで、占有されている各セルが O(1) の償却時間でスキップされるようにしますが、長いチェーンを繰り返し再スキャンすることは避けなければなりません。 

これを効率的に実現する標準的な方法は、状態を更新しながらプローブを直接シミュレートしますが、各セルが 1 回設定され、1 回クリアされるようにします。 各挿入ではセルが 1 つだけ埋められ、削除では 1 つが解放されるため、すべてのセルの状態は O(1) 回変化します。 配置が成功するたびにチェーンをたどる必要がある場合がありますが、プロセス全体を通じて、占有されている各セルは合計で制限回数スキップされます。これは、セルが一度埋まると、削除されるまでブロックされたままになるためです。 

これにより、償却された線形解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nh) | O(h + n) | 遅すぎる |
 | 最適化されたシミュレーション | O(n + h) 償却 | O(h + n) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を維持します`table`サイズの`h`、各セルには次のいずれかが格納されます。`-1`(空) またはそれを占有する ID。 辞書も整備しています`pos[id]`挿入された各 ID の現在位置を保存します。 

順番に操作をシミュレーションしていきます。 

1. 操作が削除の場合`id`でその位置を調べます。`pos`、そのセルを空にマークします`table`を選択し、マップから ID を削除します。 プロービングは発生しないため、コストは追加されません。 
2. 操作が挿入の場合`(id, hash)`から始めます`cur = hash`。 
3. その間`table[cur]`が占有されている場合、答えを 1 増やして移動します`cur = (cur + m) % h`。 

占有スロットを検査したため、このような各ステップはダミー プローブに正確に対応します。 
4. 空のセルを見つけたら、そこに ID を配置し、保存します。`pos[id] = cur`、マーク`table[cur] = id`。 

重要な考え方は、調査を最初からやり直すことはなく、グローバルに検索しないことです。 私たちは問題によって定義された循環的な進行に厳密に従っています。 

### なぜ効果があるのか

 どの時点でも、各セルは空であるか、1 つの ID だけが占有しています。 プローブ規則は、占有を除いて過去の挿入とは無関係に、各挿入の候補位置の決定的なシーケンスを定義します。 

私たちのシミュレーションはそのシーケンスを正確に反映しています。 プローブ中に占有セルに遭遇するたびに、失敗した試行が 1 回カウントされます。 ルールと同じ順序で最初の空のセルで停止するだけなので、最終的な配置は定義と一致します。 

各セルは解放される前に 1 回だけ占有されるため、セルを通過するポインタのすべての遷移は実際の衝突イベントに対応し、過大カウントまたは過少カウントは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    h, m, n = map(int, input().split())
    
    table = [-1] * h
    pos = {}
    ans = 0

    for _ in range(n):
        parts = input().split()
        if parts[0] == '-':
            id_ = int(parts[1])
            idx = pos.pop(id_)
            table[idx] = -1
        else:
            id_ = int(parts[1])
            start = int(parts[2])

            cur = start
            while table[cur] != -1:
                ans += 1
                cur = (cur + m) % h

            table[cur] = id_
            pos[id_] = cur

    print(ans)

if __name__ == "__main__":
    solve()
```実装では占有用の直接配列が保持されるため、各プローブは O(1) になります。 辞書`pos`削除が一定時間行われることが保証され、テーブルを検索する必要がなくなります。 挿入のループはハッシュ ルールの要求どおりに進み、衝突ごとにカウンタが 1 回増加します。 

微妙な点は、常に更新されるということです`cur`モジュロ`h`、循環構造を維持します。 もう 1 つの詳細は、削除はプローブのコストに直接影響しませんが、将来のスロットが開かれるため、正確性のために不可欠であるということです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    h, m, n = map(int, input().split())
    table = [-1] * h
    pos = {}
    ans = 0

    for _ in range(n):
        parts = input().split()
        if parts[0] == '-':
            id_ = int(parts[1])
            idx = pos.pop(id_)
            table[idx] = -1
        else:

            cur = start
            while table[cur] != -1:
                ans += 1
                cur = (cur + m) % h
            table[cur] = id_
            pos[id_] = cur

    return str(ans)

 ## 特殊なケース

 ステップ サイズ 1 の最小テーブルは、最悪の場合の線形プローブ動作を強調します。 たとえば、サイズ 4 のテーブルで、同じハッシュに 3 つの項目を挿入すると、挿入ごとにフル スキャンが発生します。 アルゴリズムはこれを正しく処理します。これは、占有されている各セルが遭遇ごとに 1 回だけカウンタをインクリメントし、ポインタがテーブル サイズを法として決定的に進むためです。 

2 番目のエッジ ケースは、初期のスロットが再び開かれる頻繁な削除です。 スロットが解放されても、開始ハッシュに応じて、今後の挿入でそのスロットを通過する可能性があります。 このアルゴリズムは、各プローブ ステップで占有セルと空セルを正しく区別するため、セルが解放されると、後続のプローブはそのセルを衝突としてカウントしなくなります。 

3 番目のエッジケースは次のような場合です。`m`そして`h`は互いに素ではないため、テーブル全体をカバーしないサイクルが生成されます。 プロービングは厳密に定義されたサイクル内にあるため、アルゴリズムは引き続き機能します。`(t + i*m) % h`、挿入が常に可能であることを保証する問題ステートメントによって終了が保証されます。
