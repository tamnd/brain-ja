 ## 解決策
 ## 問題の理解

 都市がノード、道路がエッジである無向接続グラフが与えられます。 各商人には、倉庫都市と店舗都市のペアの都市も与えられます。 販売者は、グラフ内の任意のパスを使用して倉庫から店舗に商品を出荷する必要があります。 

道路を撤去することで商人の 2 つの都市の間に存在する可能性のあるすべての経路が破壊される場合、その道路は商人にとって「重要」です。 グラフ用語で言えば、これは、選択した 2 つの頂点間のすべてのパス上に道路が存在することを意味します。つまり、道路は特定の端点のペアに対する橋であり、必ずしもグラフ全体のグローバル ブリッジである必要はありません。 

各クエリ ペアについて、2 つのエンドポイント間の接続のために避けられないエッジの数をカウントする必要があります。 

グラフ サイズは最大 10^5 のノードとエッジで、最大 10^5 のクエリが可能です。 これにより、クエリごとに接続を再計算するアプローチは即座に除外されます。 クエリあたり O(m) であっても、最悪の場合は約 10^10 の操作が必要になりますが、これは実行不可能です。 ソリューションでは、各クエリが準線形またはほぼ一定の時間で応答されるようにグラフを前処理する必要があります。 

グラフにサイクルが含まれる場合、微妙なエッジ ケースが発生します。 たとえば、グラフが単純な三角形 1-2-3-1 で、クエリが (1,3) である場合、2 つの互いに素なルートがあるため、エッジは必須ではありません。 答えは 0 です。単純な最短パスまたは DFS ベースの単一パス推論では、一部のエッジが必要なものとして誤って処理されてしまいます。 

もう 1 つの特殊なケースは、グラフがすでにツリーになっている場合です。 この場合、ノードのすべてのペアには一意のパスがあるため、そのパス上のすべてのエッジが重要になり、答えは単純にツリー内の距離になります。 

## アプローチ

 直接的なアイデアは、各エッジをテストして各クエリを個別に処理することです。エッジを削除して、2 つのエンドポイントがまだ接続されているかどうかを確認します。 m 個のエッジと k 個のクエリの場合、削除ごとに BFS/DFS を使用して単純に実行すると、これは O(km(m + n)) になりますが、これは完全に実行不可能です。 

もう少し良いアイデアですが、それでも遅すぎるアイデアは、クエリごとにソースから DFS を計算し、見つかったパス上のすべてのブリッジにマークを付けることです。 ただし、それでもクエリごとに走査をやり直す必要があり、サイクルにより注意を単一のパスに限定することができなくなります。 

重要な観察は、2 つのノード間で「常に必要な」エッジは、まさに、エンドポイントのコンポーネント間の一意のパス上にある _2 エッジ接続コンポーネント ツリー_ (ブリッジ ツリー) 内のブリッジであるエッジであるということです。 2 つのエッジで接続されたすべてのコンポーネントを 1 つのノードに縮小すると、残りのすべてのエッジがツリーを形成します。 このツリーでは、すべてのエッジがグローバルなブリッジであり、任意の 2 つのノード間には 1 つの単純なパスが存在します。 したがって、2 つの元のノード間で避けられないエッジの数は、それらのコンポーネント代表間のブリッジ ツリー エッジの数に等しくなります。 

これにより、ブリッジ ツリーを構築し、ツリー上のパス長クエリに応答するという問題が軽減されます。これは、LCA または深さの差を使用して実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース | O(k・m・(n+m)) | O(n+m) | 遅すぎる |
 | ブリッジ分解 + LCA | O(n + m + k log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフに対して DFS ベースのブリッジ検索アルゴリズム (Tarjan ローリンク) を実行して、すべてのブリッジを識別します。 

その考え方は、DFS ツリー内で v のサブツリーから u の祖先へのバックエッジが存在しない場合、エッジ (u, v) がブリッジであるということです。 
2. ブリッジ以外のエッジをすべて無視する新しいグラフを作成します。 

この時点で、グラフはいくつかの連結成分に分割され、それぞれが 2 エッジで連結されます。 
3. 非ブリッジ エッジ上の DFS/BFS を使用して、各ノードにコンポーネント ID を割り当てます。 

同じコンポーネント内のすべてのノードは、ブリッジを使用せずに相互に接続できます。 
4. ブリッジ エッジのみを使用して、グラフをコンポーネントのツリーに縮小します。

各ブリッジは 2 つの異なるコンポーネントを正確に接続しており、ブリッジはサイクルを形成しないため、この構造はツリー (フォレストですが、元のグラフは接続されているためツリーになります) です。 
5. このツリーを任意にルート化し、各コンポーネントの深さを計算します。 
6. バイナリ リフティングを使用して、コンポーネント ツリー上の LCA (最下位共通祖先) 構造を事前計算します。 
7. 各クエリ (s、l) について、両方のエンドポイントをそのコンポーネントにマッピングし、以下を使用してツリー内のそれらの距離を計算します。 

深さ[u] + 深さ[v] - 2 * 深さ[lca(u, v)]。 

この距離の各単位は 1 つの橋、つまり 1 つの「重要な道路」に相当します。 

### なぜ効果があるのか

 正しさは、2 つのエッジで接続されたコンポーネントを縮小した後、残りのすべてのエッジがブリッジであり、構造が非環状であるという事実に基づいています。 2 つの元のノード間のパスは、コンポーネントを接続する一連のブリッジ エッジを正確に通過する必要があります。 コンポーネント内では、任意の 2 つのノード間に少なくとも 2 つの互いに素なパスが存在するため、エンドポイントを分離するために内部エッジが重要になることはありません。 したがって、コンポーネント間のエッジのみが重要であり、それらはパスの一意性により、コンポーネント パス上のエッジの数が避けられない道路の数に等しいことを保証するツリーを形成します。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

n, m = map(int, input().split())
g = [[] for _ in range(n)]

edges = []
for i in range(m):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    g[a].append((b, i))
    g[b].append((a, i))
    edges.append((a, b))

tin = [-1] * n
low = [-1] * n
timer = 0
is_bridge = [False] * m

def dfs(u, pe):
    global timer
    tin[u] = low[u] = timer
    timer += 1
    for v, idx in g[u]:
        if idx == pe:
            continue
        if tin[v] == -1:
            dfs(v, idx)
            low[u] = min(low[u], low[v])
            if low[v] > tin[u]:
                is_bridge[idx] = True
        else:
            low[u] = min(low[u], tin[v])

dfs(0, -1)

comp = [-1] * n
cid = 0

from collections import deque

for i in range(n):
    if comp[i] == -1:
        dq = deque([i])
        comp[i] = cid
        while dq:
            u = dq.popleft()
            for v, idx in g[u]:
                if comp[v] == -1 and not is_bridge[idx]:
                    comp[v] = cid
                    dq.append(v)
        cid += 1

cg = [[] for _ in range(cid)]

for i in range(m):
    if is_bridge[i]:
        a, b = edges[i]
        ca, cb = comp[a], comp[b]
        cg[ca].append(cb)
        cg[cb].append(ca)

LOG = 17
up = [[-1] * cid for _ in range(LOG)]
depth = [0] * cid

dq = deque([0])
vis = [False] * cid
vis[0] = True

while dq:
    u = dq.popleft()
    for v in cg[u]:
        if not vis[v]:
            vis[v] = True
            depth[v] = depth[u] + 1
            up[0][v] = u
            dq.append(v)

for i in range(1, LOG):
    for v in range(cid):
        if up[i-1][v] != -1:
            up[i][v] = up[i-1][up[i-1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for i in range(LOG):
        if diff & (1 << i):
            a = up[i][a]
    if a == b:
        return a
    for i in reversed(range(LOG)):
        if up[i][a] != up[i][b]:
            a = up[i][a]
            b = up[i][b]
    return up[0][a]

k = int(input())
out = []
for _ in range(k):
    s, t = map(int, input().split())
    s -= 1
    t -= 1
    cs, ct = comp[s], comp[t]
    w = lca(cs, ct)
    out.append(str(depth[cs] + depth[ct] - 2 * depth[w]))

print("\n".join(out))
```リンク値が低い DFS は、サイクルをツリー状の接続から分離するエッジを正確にマークします。 その後、非ブリッジ エッジ上の BFS によってコンポーネントが構築され、各コンポーネントが最大 2 エッジ接続されることが保証されます。 

縮小されたグラフはブリッジのエッジのみから構築され、ブリッジはサイクルを形成できないため、ツリーとして動作します。 LCA 構造は標準的なバイナリ リフティングであり、各クエリはツリー距離の計算になります。 

よくある実装の落とし穴は、DFS で親エッジを正しくスキップし忘れたり、バック エッジの処理時に複数のエッジを誤ってブリッジとしてマークしたりすることです。 もう 1 つの微妙な点は、LCA は元のグラフではなくコンポーネント ツリー上で構築する必要があることです。そうしないと、サイクルによる過剰カウントが返されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、エッジがブリッジになっていない完全な循環グラフです。 その状況では、すべてのノードが 1 つのコンポーネントに属するため、すべてのクエリは 0 を返す必要があります。アルゴリズムは、コンポーネントの形成中にグラフ全体を 1 つのノードに折りたたむため、すべてのペアの LCA 距離が 0 になります。 

もう一つのケースは木です。 ここではすべてのエッジがブリッジであるため、各ノードは独自のコンポーネントを形成します。 ブリッジ ツリーは元のグラフと同一であり、LCA 距離はノード間の一意のパス長と正確に一致します。 

最後のケースには、単一のブリッジで接続された複数のサイクルが含まれます。 たとえば、2 つの三角形が 1 つのエッジで接続されているとします。 その 1 つのエッジがブリッジ ツリー内の唯一のブリッジとなるため、2 つのサイクルにまたがるクエリは、エンドポイントが異なるサイクルにある場合は正確に 1 を返し、それ以外の場合は 0 を返します。 このアルゴリズムは、各三角形をノードに正しく圧縮し、接続するブリッジを唯一のツリー エッジとして保持します。
