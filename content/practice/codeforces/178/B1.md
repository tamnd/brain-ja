 ## 解決策
 ## 問題の理解

 都市と道路を表す無向接続グラフが与えられます。 各道路は削除される可能性があり、これによって 2 つの特定の都市間の接続が切断される場合と切断されない場合があります。 グラフと一緒に複数の販売者が表示されます。 各商人には、商品が出発する出発都市と到着する必要がある目的地都市があります。 

固定の販売者の場合、グラフ内のすべての道路を考慮します。 その 1 本の道路を削除することでソースから目的地に到達できなくなる場合、その道路はその販売者に対してカウントされます。 グラフ用語では、頂点のペアについて、それらの間の可能なすべてのパス上にエッジがいくつあるかを数えます。 同様に、その特定のペアに関してブリッジであるエッジもカウントしています。これは、これらの 2 つのノード間の接続が避けられないことを意味します。 

タスクは、最大 100,000 の販売者についてこの数を個別に計算することです。 

この制約により、エッジの数が線形である販売者ごとのグラフの走査が即座に除外されます。 クエリごとの単純な DFS または BFS のコストはそれぞれ O(n + m) となり、結果として O(k(n + m)) になりますが、すべてが最大 10^5 である場合、これは大きすぎます。 

微妙な点は、エッジはある都市のペアにとっては重要でも、別の都市のペアにとっては無関係である可能性があることです。 これは、グローバル ブリッジの分解だけでは不十分であることを意味します。 高速なペアクエリを可能にする構造が必要です。 

よくある落とし穴は、グラフ内のすべてのブリッジがエンドポイントのコンポーネント間のすべてのパスに寄与していると想定することです。 これは誤りです。 ブリッジは、クエリ対象の 2 つのノードがブリッジ ツリー構造内でブリッジによって分離されている場合にのみ重要です。 

## アプローチ

 単純なアプローチでは、各販売者が個別に処理されます。 指定されたペア (s, t) について、各エッジを 1 つずつ削除し、DFS または BFS を使用して s と t 間の接続をテストします。 各小切手のコストは O(n + m) であるため、販売者ごとにこれは O(m(n + m)) となり、あまりにも大きすぎます。 

グラフをブリッジ接続されたコンポーネントに圧縮できることを観察することで、これを改善します。 最大の 2 エッジ接続コンポーネントをすべて 1 つのノードに縮小すると、結果として得られる構造は、一般にブリッジ ツリーと呼ばれるツリーになります。 このツリーのすべてのエッジは元のグラフのブリッジに対応し、元のグラフの 2 つの頂点間の単純なパスは、コンポーネントの代表間のこのツリー内の固有のパスに対応します。 

これで、重要なアイデアが明らかになりました。 道路が商人にとって重要なのは、それが橋ツリー内の s と t のコンポーネント間の固有のパス上にある橋である場合に限ります。 したがって、各クエリの答えは単にそのツリー パス上のエッジの数になります。 

これらのパス長のクエリに効率的に答えるために、ブリッジ ツリー上の最も低い共通祖先を計算します。 各クエリは、ツリー内の 2 つのノード間の距離を計算することになります。これは、深さと LCA 前処理を使用して実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース | O(k · m(n + m)) | O(n + m) | 遅すぎる |
 | ブリッジ分解 + LCA | O((n + m) + k log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DFS ベースのブリッジ検索アルゴリズム (Tarjan スタイル) を実行して、グラフ内のすべてのブリッジを識別します。 

アイデアは、発見時間とローリンク値を計算して、どのサイクルにも存在しないエッジを検出できるようにすることです。 
2. 2 つのエッジで接続された各コンポーネントが 1 つのノードに縮小される新しいグラフを構築します。 

2 つの元のノードがブリッジを渡さずに接続されている場合、それらは同じコンポーネントに属します。 
3. すべてのブリッジは 2 つの異なるコンポーネントを接続するため、これらのブリッジ エッジを使用してコンポーネント上にツリーを形成します。

ブリッジを削除するとすべてのサイクルがなくなるため、この構造は非循環的になります。 
4. ブリッジ ツリーを任意にルート化し、バイナリ リフティング LCA の深さと親ポインタを計算します。 
5. 各販売者について、そのソース都市と目的地都市をコンポーネント識別子にマッピングします。 
6. クエリ (u, v) の場合、ブリッジ ツリー内の LCA を計算し、ツリー距離公式を使用してそれらの間のエッジの数を取得します。 
7. この距離を、その販売業者にとって重要な道路の数として出力します。 

### なぜ効果があるのか

 2 エッジ接続されたコンポーネントの内部では、1 つのエッジを削除しても 2 つのノードは切断されないため、内部エッジはクリティカルとしてカウントされません。 重要なすべてのエッジはまさにブリッジです。 ブリッジ ツリーはツリーであるため、2 つのコンポーネント間には単純なパスが 1 つだけあり、そのパス上のすべてのエッジは避けられません。 したがって、ブリッジ ツリー内のパス上のエッジをカウントすることは、削除によってマーチャントのエンドポイントが切断されるエッジをカウントすることと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
g = [[] for _ in range(n)]

edges = []
for i in range(m):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    g[a].append((b, i))
    g[b].append((a, i))
    edges.append((a, b))

tin = [-1] * n
low = [-1] * n
timer = 0
is_bridge = [False] * m

def dfs(v, pe):
    global timer
    tin[v] = low[v] = timer
    timer += 1
    for to, eid in g[v]:
        if eid == pe:
            continue
        if tin[to] == -1:
            dfs(to, eid)
            low[v] = min(low[v], low[to])
            if low[to] > tin[v]:
                is_bridge[eid] = True
        else:
            low[v] = min(low[v], tin[to])

dfs(0, -1)

comp = [-1] * n
cid = 0

from collections import deque

for i in range(n):
    if comp[i] == -1:
        cid += 1
        q = deque([i])
        comp[i] = cid - 1
        while q:
            v = q.popleft()
            for to, eid in g[v]:
                if comp[to] == -1 and not is_bridge[eid]:
                    comp[to] = cid - 1
                    q.append(to)

tree = [[] for _ in range(cid)]
for i in range(m):
    a, b = edges[i]
    ca, cb = comp[a], comp[b]
    if ca != cb:
        tree[ca].append(cb)
        tree[cb].append(ca)

LOG = (cid).bit_length()
up = [[-1] * cid for _ in range(LOG)]
depth = [-1] * cid

def dfs2(v, p):
    up[0][v] = p
    for to in tree[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        dfs2(to, v)

for i in range(cid):
    if depth[i] == -1:
        depth[i] = 0
        dfs2(i, -1)

for j in range(1, LOG):
    for i in range(cid):
        if up[j-1][i] != -1:
            up[j][i] = up[j-1][up[j-1][i]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    j = 0
    while diff:
        if diff & 1:
            a = up[j][a]
        diff >>= 1
        j += 1
    if a == b:
        return a
    for j in range(LOG - 1, -1, -1):
        if up[j][a] != up[j][b]:
            a = up[j][a]
            b = up[j][b]
    return up[0][a]

def dist(a, b):
    c = lca(a, b)
    return depth[a] + depth[b] - 2 * depth[c]

k = int(input())
for _ in range(k):
    s, t = map(int, input().split())
    s -= 1
    t -= 1
    print(dist(comp[s], comp[t]))
```実装は、標準のローリンク DFS を使用してすべてのブリッジを識別することから始まります。 重要な詳細は、DFS 時間の分離を厳密に増加させるエッジのみがブリッジになるということです。 その後、非ブリッジ エッジのみを使用してコンポーネントをフラッドフィルし、各コンポーネントが 2 エッジ接続に関して最大​​になるようにします。 

コンポーネントが構築されたら、ブリッジ ツリーを明示的に構築します。 すべてのブリッジは 2 つの異なるコンポーネントを接続するため、この構造はフォレストであることが保証され、元のグラフが接続されているため、単一のツリーになります。 

次に、このツリーに対するバイナリ リフティング テーブルを前処理します。 各クエリは、距離の式が後に続く最小共通祖先の計算になります。 正確かどうかは、すべての重要な道路がこの木道上の固有のエッジに対応するという事実にかかっています。 

実装の微妙な詳細は、前処理中に切断された DFS ツリーを処理することです。 元のグラフは接続されていますが、ブリッジ ツリーはコンポーネント フォレストの走査ごとにルート化されているため、未訪問のコンポーネントごとに深さを慎重に初期化します。 

## 実用的な例

 ### 例 1

 入力グラフ構造は、いくつかの分岐を持つチェーン状のバックボーンであり、クエリはこの構造のさまざまな部分にわたる距離を要求します。 

| ステップ | コンプ | tコンプ | LCA | 深さ | 深さ(t) | 答え |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 2 | 1 | 2 | 2 | 2 |
 | 2 | 1 | 2 | 1 | 1 | 2 | 1 |
 | 3 | 1 | 3 | 0 | 1 | 3 | 2 |

 このトレースは、回答が元のグラフではなく、圧縮されたツリー内の距離にどのように正確に対応するかを示します。 

### 例 2

 複数のサイクルが単一のコンポーネントに集約されるグラフを考えてみましょう。 

| ステップ | コンプ | tコンプ | LCA | 深さ | 深さ(t) | 答え |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 0 | 1 | 1 | 0 |
 | 2 | 0 | 2 | 0 | 1 | 3 | 2 |
 | 3 | 2 | 4 | 1 | 3 | 4 | 3 |

 これにより、内部サイクル エッジは決して答えに寄与せず、コンポーネント間ブリッジのみが答えに寄与することが確認されます。

 ## 特殊なケース

 重要なエッジ ケースは、単一サイクルなど、ブリッジがまったくないグラフです。 この場合、すべてのノードが 1 つのコンポーネントに属しているため、すべてのクエリがブリッジ ツリー内の同じノードにマップされます。 LCA は両方の終点に等しく、距離はゼロです。これは、個別に重要な道路がないという事実と一致します。 

もう 1 つのケースはツリー グラフです。 ここではすべてのエッジがブリッジであるため、ブリッジ ツリーは元のグラフと同一です。 このアルゴリズムは標準のツリー距離クエリに縮小され、2 つのノード間の一意のパス上の各エッジが正しくカウントされます。 

最後のケースは、ソースと宛先が同じ 2 エッジ接続コンポーネント内にある場合です。 コンポーネントの圧縮は両方を同じノードにマッピングし、すぐにゼロを生成します。これは、単一のエッジ除去によってそれらが切断されないことを正しく反映しています。
