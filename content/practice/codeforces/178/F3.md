 ## 解決策
 ## 問題の理解

 文字列のマルチセットが与えられ、各文字列はタンパク質を表します。 このコレクションから正確に選択しなければなりません$k$文字列を選択し、選択したサブセットにスコアを割り当てます。 スコアは、選択された文字列の順序付けされていないすべてのペアに対して定義されます。 文字列のペアについては、最初から最初に相違する前に、それらが共有する文字数を計算します。 これは、それらの最長の共通プレフィックスの長さです。 合計スコアは、選択したサブセット内のすべてのペアにわたるこの値の合計です。 

タスクはサイズのサブセットを選択することです$k$これにより、このペアごとのプレフィックス類似性の合計が最大化されます。 

重要な問題は、類似性が文字列ごとに加算されないことです。 単一の文字列がサブセット内の他のすべての文字列に対するスコアに影響を与えるため、個々の項目ではなく、サブセット全体にわたって組み合わせ構造を最適化しています。 

制約は私たちをさまざまな方向に押し進めます。 文字列の数は最大 2000 まで可能で、各文字列の長さは最大 500 です。$\binom{2000}{k}$選択は不可能です。 中程度の場合でも$k$、サブセットを列挙することは、実行可能な限界をはるかに超えています。 これは、文字列を不透明なオブジェクトとして扱うのではなく、最も長い共通プレフィックスの構造を利用する必要があることを直ちに示唆しています。 

重複した文字列では微妙な問題が発生します。 同一の文字列は、すべてのペアの完全な文字列長と等しい最大プレフィックス長に寄与するため、重複を選択するとスコアが大幅に増加する可能性があります。 多重性を考慮せずに文字列を一意のオブジェクトとして扱うアプローチは、繰り返しが最適な場合には失敗します。 

別の失敗例は、文字列が長いプレフィックスを共有しているが、後で分岐する場合に発生します。 現在のセットとのペアごとの類似性が最大の文字列を選択する貪欲な戦略は、初期の選択が将来の互換性に大きく影響するため、局所的にトラップされる可能性があります。 

たとえば、次のことを考えてみましょう。```
aba
abb
abc
zzz
```と$k = 3$、欲張った選択は選択するかもしれません`aba`、`abb`、`abc`、ただし、1 つを次のように置き換えます`zzz`貢献度が大幅に減ります。 この構造は、ペアごとの極大値ではなく、グローバル クラスタリングに依存します。 

## アプローチ

 中心的な観察は、最長の共通プレフィックスが自然にトライ構造を誘発するということです。 文字列を直接考慮するのではなく、接頭辞によってグループ化します。 

すべての文字列をトライに挿入すると、すべてのノードは文字列のサブセットによって共有されるプレフィックスに対応します。 ノードを修正すると、そのサブツリー内のすべての文字列が少なくともそのプレフィックスを共有します。 そのサブツリー内のペアの寄与は明確な構造を持っています。サブツリー内のすべてのペアは、少なくともそのノードの深さに寄与しています。 

これは分解を示唆しています。トライ内の各ノードは、通過する選択された文字列の数に基づいて答えに寄与します。 

させて$c_v$ノードのサブツリー内で選択された文字列の数になります$v$。 最も低い共通プレフィックスが正確にノードにある、選択された文字列のすべてのペア$v$深さ(v)に寄与します。 言い換えれば、答えは、サブツリー内のカウントのみに依存して、寄与のトライノードの合計として書き直すことができます。 

ブルート フォース アプローチでは、サイズのすべてのサブセットが列挙されます。$k$、ペアごとの LCP を計算します$O(k^2 \cdot L)$、最大値を取ります。 これは$O(\binom{n}{k} \cdot k^2 L)$、でもそれは不可能です$n = 30$。 

重要な単純化は、目的がトライ ノードにわたって分解され、異なるノードでの決定がサブツリー カウントによってのみ結合されることです。 これにより、トライをボトムアップで処理し、指定された数の選択された文字列をその子に分配するために達成可能な最良の値をノードごとに計算するツリー DP が得られます。 

各ノードで DP 配列を維持します。$dp_v[i]$を選択することで得られる最大の表現性です。$i$をルートとするサブツリーの文字列$v$、上記の貢献を除く$v$。 子をマージするときは、サブツリーのサイズに対してナップザックのような畳み込みを実行します。 各エッジは、キャリーされるカウントを通じて暗黙的にその深さに寄与します。 

各文字列がトライ内の最大 500 ノードに寄与するため、複雑さは管理可能です。つまり、合計ノードは次のようになります。$O(nL)$、各マージは分散します$k$子供たちにまたがるアイテム。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット |$O(\binom{n}{k} \cdot k^2 L)$|$O(k)$| 遅すぎる |
 | サブツリー ナップザック上で DP を試す |$O(n L k^2)$最悪の場合、実際には効果的に最適化されます。$O(n k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての文字列からトライを構築します。 各ノードは、その子と、それが何らかの文字列の末尾に対応するかどうかを格納します。 これにより、プレフィックス関係が、深さがプレフィックス長に等しいツリー構造に変換されます。 
2. 各ノードで DP テーブルを定義します$v$、 どこ$dp_v[i]$正確に選択することで得られる最大の貢献度です$i$をルートとするサブツリーの文字列$v$、先祖からの貢献はカウントしません。 プレフィックスの寄与は発散が発生するノードで自然に考慮されるため、この分離は非常に重要です。 
3. 1 つの要素でペアが形成されないため、そのノードで終わる単一の文字列を選択すると、サブツリー内の追加ペア値が 0 になるように各ノードを初期化します。 ノードが実際の文字列の終わりに対応する場合、そのノードは 1 つの使用可能な項目を DP に提供します。 
4. 子を事後順序で再帰的に処理します。 子を結合するとき$u$の中へ$v$、ナップザック畳み込みを使用して DP テーブルを結合します。$i$で$dp_v$そして$j$で$dp_u$、 アップデート$dp_v[i + j]$を使用して$dp_v[i] + dp_u[j]$。 これが機能する理由は、結合されていないサブツリー内の選択肢は、選択された項目の数を除いて独立しているためです。 
5. 子をマージした後、現在のノードのプレフィックスの寄与を追加します。 もし$v$深みにある$d$、そのサブツリー内で形成されたすべてのペアが貢献します$d$。 これは、カウントを介して暗黙的に形成されるペアの数を追跡することによって組み込まれます。 同様に、貢献が最も低い共通祖先でカウントされることを保証します。 
6. 最終的な答えは次のとおりです。$dp_{\text{root}}[k]$。 

### なぜ効果があるのか

 選択された文字列の各ペアには、トライ内の固有の最下位共通祖先があります。 このアルゴリズムは、サブツリー構造を通じて、そのノードでそのペアの寄与を 1 回だけ割り当てます。 DP はすべてのサブツリーで選択された文字列の正確なカウントを強制するため、すべての有効な選択は 1 つの DP 状態パスに正確に対応し、ペアが複数のノードに関連付けられることはないため、無効な過剰カウントは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class Node:
    __slots__ = ("ch", "end")
    def __init__(self):
        self.ch = {}
        self.end = 0

def add(root, s):
    v = root
    for c in s:
        if c not in v.ch:
            v.ch[c] = Node()
        v = v.ch[c]
    v.end += 1

def solve():
    n, k = map(int, input().split())
    root = Node()

    for _ in range(n):
        add(root, input().strip())

    # DP: node -> list of best values for selecting i strings
    def dfs(v, depth):
        dp = [-10**18] * (k + 1)
        dp[0] = 0

        # each string ending here contributes as a selectable item
        if v.end:
            ndp = [-10**18] * (k + 1)
            for i in range(k):
                if dp[i] > -10**17:
                    ndp[i + 1] = max(ndp[i + 1], dp[i])
            dp = ndp

        for child in v.ch.values():
            cd = dfs(child, depth + 1)
            ndp = [-10**18] * (k + 1)
            for i in range(k + 1):
                if dp[i] < -10**17:
                    continue
                for j in range(k - i + 1):
                    if cd[j] < -10**17:
                        continue
                    ndp[i + j] = max(ndp[i + j], dp[i] + cd[j] + j * (j - 1) // 2)
            dp = ndp

        return dp

    dp_root = dfs(root, 0)
    print(dp_root[k])

if __name__ == "__main__":
    solve()
```トライ構造はすべての文字列に直接挿入され、共有プレフィックスが共有パスに確実にマッピングされます。 

DFS は DP テーブルをボトムアップで計算します。 用語$j(j-1)/2$子サブツリーをマージするときに表示されます。これは、サブツリー内ではすべてのペアが 1 回だけ寄与し、上に移動するときは、完全にその子の内部で形成された新しいペアをプレフィックス構造に関連して考慮する必要があるためです。 

実装上の微妙な問題はメモリです。各 DP 配列のサイズは次のとおりです。$k$、各ノードが 1 つを割り当てるため、再帰の深さと枝刈りが重要になります。 もう 1 つのデリケートな点は、不可能な状態が十分に負のセンチネルで表現され、最大値で選択されないようにすることです。

 ## 特殊なケース

 重要なエッジケースは、すべての文字列が同一である場合です。 この場合、すべてのペアが全長に寄与するため、最適な解決策は、任意のペアを取得することです。$k$彼らのうち。 トライは 1 つのパスに折りたたまれ、すべてのマージで各レベルで最大のペアの寄与が蓄積され、正しく生成されます。$\binom{k}{2} \cdot L$。 

もう 1 つのケースは、文字列が短いプレフィックスのみを共有し、すぐに分岐する場合です。 DP はすべての利点を浅いトライ ノードに正しくプッシュし、人為的なグループ化によってより深い貢献が膨らむことがないようにします。 

最後に、いつ$k = 1$、すべての DP 遷移は、ペアの寄与がゼロの単一項目を選択するように崩壊し、アルゴリズムは自然に 0 を返し、ペアが存在しないという定義と一致します。
