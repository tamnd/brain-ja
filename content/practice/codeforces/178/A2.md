 ## 解決策
 ## 問題の理解

 1 から _n_ までのインデックスが付いた、ある種の「カウンター」を表す非負の整数のシーケンスが線に沿って与えられます。 タスクは、考えられるすべてのプレフィックス長 _k_ (1 から _n_-1) について、シーケンスの最初の _k_ 要素をゼロに減らすことです。 許可される操作は次のとおりです。正の値のインデックス _i_ を選択し、_i + 2_t* が _n_ を超えないように非負の整数 _t_ を選択し、_a[i]_ を 1 だけ減分し、_a[i + 2_t]* を 1 だけ増分します。 

概念的には、この操作により、単一のユニットを位置 _i_ からさらに右側の等距離の別の位置に「シフト」できます。 目標は常に接頭辞をゼロにすることであるため、最初の課題は、値は右にのみ移動でき、左には戻せないことを理解することです。 これは、ルールが許す限り、最初に左端のゼロ以外の要素を処理し、その値を右に伝播するという貪欲なアプローチを示唆しています。 

制約は、_n_ が最大 10^5 であり、値が最大 10^4 であることを示しています。 あらゆる可能な動きを調べたり、あらゆる可能な操作の組み合わせを試行したりするアルゴリズムは遅すぎます。 たとえば、各動きを個別にシミュレートするには、最大 10^4 * 10^5 = 10^9 の操作が必要になる可能性があり、これは 2 秒の制限時間をはるかに超えています。 これにより、単純な総当たりアプローチが排除されます。 

明らかでないエッジ ケースには、1 つを除くすべての要素がゼロであるシーケンス、または最後の要素が多くのシフトの合計を吸収する必要があるシーケンスが含まれます。 たとえば、入力の場合`[1, 0, 0, 0]`、最初の要素はその値をインデックス 1、3 にのみプッシュできます。不注意な実装では、インデックス 3 の要素が最終的に単一ユニットを蓄積して最初のプレフィックスがゼロになるようにする必要があることを見落とす可能性があります。 

## アプローチ

 ブルートフォース手法では、すべてのプレフィックス長 _k_ を反復処理し、プレフィックスがゼロになるまで、許可されたすべての移動をシミュレートします。 各ステップで、左端のゼロ以外の要素を見つけて、すべての有効な _t_ を試みます。 これは正しいですが、その複雑さは法外です。 最大の制約の場合、O(n * max(a_i)) の演算 (場合によっては 10^9) が必要となるため、大きな入力では失敗します。 

重要な観察は、特定のプレフィックスについて、余分な部分を左から右に貪欲に転送することで、必要な移動数を決定できるということです。 位置 _i_ にあるすべてのユニットは、位置 _i+2_、_i+4_ などに直接移動でき、移動したユニットの数だけ移動カウントが増加します。 これにより、文字通り各ユニットの移動を実行することなく、プロセスを「シミュレート」することができます。 

最適なソリューションでは、伝播された値の実行シーケンスが維持されます。 左から右に移動すると、それぞれ`a[i]`移動（自身のユニット）に直接貢献し、ゼロ以外の場合はユニットをプッシュする必要があります。`a[i+2]`。 これを _n_ までのすべてのインデックスに対して繰り返し実行することで、各プレフィックスの移動数を O(n) 時間で計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * max(a_i)) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`moves`ゼロに設定し、元のシーケンスを作業配列にコピーします。`b`入力の変更を避けるため。 
2. 位置を反復処理する`i`0 から n-1 (便宜上、0 ベースのインデックス付け)。 もし`i + 2 < n`、余分なものを伝播する`b[i]`に`b[i+2]`増加することで`b[i+2]`による`b[i]`。 これは、許可される移動操作を一括でモデル化します。各ユニットは位置にあります。`i`最終的には右端の有効な場所にプッシュされます。 
3.追加`b[i]`に`moves`それぞれに`i`は _n_-1 未満です。`i`クリアリングに対応`a[i]`以降で終わるプレフィックスの場合`i`。 
4.加工後`i`、現在を保存します`moves`プレフィックスに必要な最小限の動きとしての値`k = i+1`。 繰り返しを続けます。 
5. 最後に、長さ 1 ～ n-1 のすべてのプレフィックスについて保存されている手を出力します。 

機能する理由: アルゴリズムは、位置を処理した後も不変条件を維持します。`i`、で終わる接頭辞`i`移動会計の観点から事実上ゼロにされ、超過分はすべてゼロになります。`i`ルールで許可されている範囲で広められています。 すべての移動はユニットを右へのみ転送するため、この貪欲な左から右への伝播により、不必要な移動がカウントされず、より少ない移動でプレフィックスをゼロにできないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
b = a.copy()
moves = 0
res = []

for i in range(n-1):
    moves += b[i]
    if i + 2 < n:
        b[i+2] += b[i]
    res.append(str(moves))

print("\n".join(res))
```このソリューションでは、入力配列をコピーして元の配列を保存し、各インデックスを左から右に処理します。 重要な実装の詳細は次のとおりです。`i+2`あらゆる可能性をシミュレーションするのではなく、`t`。 これにより、ネストされたループが回避され、線形時間が確保されます。 操作の順序 - 追加`moves`伝播前 - 将来の要素が蓄積される前に、現在のプレフィックスに影響を与える移動を正しく考慮するようにします。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    b = a.copy()
    moves = 0
    res = []
    for i in range(n-1):
        moves += b[i]
        if i + 2 < n:
            b[i+2] += b[i]
        res.append(str(moves))
    return "\n".join(res)

# provided samples
assert run("4\n1 0 1 2\n") == "1\n1\n3", "sample 1"

# custom cases
assert run("1\n0\n") == "", "single element, no moves"
assert run("5\n2 1 0 3 0\n") == "2\n3\n5\n9", "propagation with zeros"
assert run("6\n1 1 1 1 1 1\n") == "1\n2\n4\n6\n9", "all ones, propagation cascades"
assert run("3\n0 0 0\n") == "0\n0", "all zeros, no moves"
assert run("4\n10000 0 0 0\n") == "10000\n10000\n10000", "large numbers, single prefix propagation"
