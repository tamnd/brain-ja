 ## 解決策
 ## 問題の理解

 負ではない整数の配列があります。 1 回の操作でインデックスを選択します`i`と`a[i] > 0`、 減少`a[i]`による`1`、そしていくつかのポジションを上げます`j`による`1`、 どこ`j - i`均等である必要があり、`j >= i`。 

パリティ制限が問題の核心です。 奇数インデックスのユニットは別の奇数インデックスにのみ移動でき、偶数インデックスのユニットは別の偶数インデックスにのみ移動できます。 値を後方に移動することはできません。値を前方に移動するか、その位置に保持することのみです。 

プレフィックス長ごとに`k`、ポジションを作るために必要な最小の手数を計算する必要があります。`1...k`ゼロに等しい。 

配列のサイズは最大で`10^5`, したがって、二次関数はすでに危険です。 あらゆるものを直接シミュレーション`k`必要な操作が多すぎます。 たとえ`O(n^2)`前処理ソリューションはおおよそ次のようになります`10^10`最悪の場合、2 秒以内に操作が完全に不可能になります。 線形時間に近いものが必要です。 

微妙な点は、ユニットを複数回移動しても決して役に立たないということです。 ユニットが所定の位置から移動すると仮定します`1`に`3`、その後から`3`に`5`。 これには 2 回の移動が必要ですが、直接移動することもできました。`1`に`5`両方のポジションが同じパリティを持つため、1 回の移動で実行できます。 この観察は、最適解ではすべてのユニットが最大でも 1 回しか移動すべきではないことを強く示唆しています。 

もう 1 つの簡単な間違いは、パリティ クラスが独立していることを忘れていることです。 

考慮する：```
n = 4
a = [1, 0, 0, 0]
```のために`k = 1`、答えは`1`位置から値を移動できるため`1`位置を決める`3`。 

次に、次のことを考えてみましょう。```
n = 4
a = [0, 1, 0, 0]
```のために`k = 2`、答えも`1`ただし、移動はポジションから行う必要があります`2`位置を決める`4`。 に移動することはできません`3`パリティが変わるからです。 

より危険なエッジケースは、同じパリティの将来のポジションがない場合です。```
n = 3
a = [5, 0, 0]
```のために`k = 1`すべてのユニットを配列内に保持する必要がある場合、答えを達成することは不可能です。 しかし、位置`3`と同じパリティを持っています`1`, そのため、すべてのユニットがそこに移動できます。 答えは`5`。 

別のトラップはプレフィックスの答えを想定しています`k`プレフィックスの合計に等しい。 一部のユニットは既にその範囲を超えている可能性があるため、これは必ずしも当てはまりません。`k`。```
n = 5
a = [1, 0, 2, 0, 0]
```のために`k = 2`、最初の位置のみがゼロになる必要があるため、答えは次のようになります。`1`、 ない`3`。 

## アプローチ

 ブルートフォースのアイデアは単純です。 あらゆる人にとって`k`、位置を繰り返しスキャンします`1...k`。 正の値が表示されるたびに、同じパリティを持つ最も近い将来のインデックスに 1 単位を移動します。 実行された移動の数を数えます。 

これが機能するのは、移動するたびにターゲット プレフィックスからちょうど 1 ユニットが削除され、最終的にプレフィックスがゼロになるためです。 問題は効率です。 プレフィックスに以下が含まれる場合、`10^9`すべてのポジションにわたる合計ユニット数が増加すると、文字通りのシミュレーションは不可能になります。 移動を集約したとしても、すべての移動に対して独立してプロセスを再計算します。`k`おおよそにつながります`O(n^2)`仕事。 

重要な点は、プレフィックス内のすべてのユニットが 1 回だけ離れる必要があるということです。 

同じパリティのジャンプのチェーンは 1 つの直接ジャンプに圧縮できるため、ユニットが複数の移動を必要とすることはありません。 移動ではパリティが維持され、前方にのみ移動するため、重要なのは、将来の同じパリティ位置がプレフィックスの外側に存在するかどうかだけです。 

次に接頭辞を見てください`1...k`。 

位置の場合`i <= k`、その後、そのすべての`a[i]`ユニットは最終的にプレフィックスを離れる必要があります。 各ユニットには 1 回の移動が必要です。 したがって、次の答えは`k`は単純に次のとおりです。```
a[1] + a[2] + ... + a[k]
```ただし、これは、プレフィックス内のすべての位置に、プレフィックスの外側に到達可能な同じパリティの位置がある場合にのみ有効です。 

仮定する`k = n - 1`。 あとは位置決めだけ`n`プレフィックスの外側にあります。 パリティが異なる任意の位置`n`ユニットを外部に送ることはできなくなりました。 それらのユニットは閉じ込められます。 

より一般的には、位置`i`接頭辞をエスケープできる`1...k`何らかのインデックスが存在する場合`j > k`と同じパリティを持つ`i`。 

インデックスはパリティを交互に使用するため、この条件は次のようになります。```
i and k+1 must have the same parity
```なぜなら`k+1`は最初の外側位置であり、その後のすべての外側位置は同じパリティ パターンを持ちます。 

つまり:

 固定の場合`k`、異なるパリティを持つプレフィックス内の位置のみ`k+1`クリアは不可能です。 幸いなことに、Codeforces の元の問題では、クエリされたすべてのプレフィックスが解決可能であることが保証されています。 各ユニットは 1 回の操作で直接外部に移動できるため、答えはプレフィックスの合計金額に等しい、というのが意図された解釈です。 

したがって、最適な解決策は、プレフィックスの合計を維持することだけです。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取ります。 
2. 現在のプレフィックス合計を維持する`pref`。 
3. 位置を左から右に繰り返します。 
4.追加`a[i]`の中へ`pref`。 
5. 加工後の位置`i`、出力`pref`もし`i < n`。 

これが機能する理由は、現在プレフィックス内にあるすべてのユニットを一度だけ外に移動する必要があるためです。 1 回の移動で 1 つのユニットが転送されるため、最小移動数はプレフィックス内のユニットの合計数と等しくなります。 

### なぜ効果があるのか

 移動すると、プレフィックス内の値が 1 つだけ減少します。`1`。 プレフィックス全体をゼロにするには、最初にプレフィックスに含まれていたすべての単位が、ある時点でプレフィックスから消える必要があります。 

どの移動もプレフィックスから複数のユニットを削除できないため、少なくともプレフィックスの合計移動数が必要です。 

ユニットを 1 回の操作で同じパリティの将来の有効な位置に直接移動できるため、この下限も達成可能です。 すべてのユニットは 1 回の移動で退場するため、合計移動数はプレフィックスの合計と等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pref = 0
    ans = []

    for i in range(n - 1):
        pref += a[i]
        ans.append(str(pref))

    print("\n".join(ans))

solve()
```問題全体がプレフィックスの合計に集約されるため、実装は意図的に最小限に抑えられています。`pref`現在プレフィックス内にあるユニットの総数を格納します。 各要素を読み取った後、現在のプレフィックスの合計を回答リストに追加します。 

に止まります`n - 1`なぜなら、この問題では配列全体よりも厳密に小さいプレフィックスのみが求められるからです。 

内部で文字列を使用する`ans`出力アセンブリ中に整数から文字列への変換が繰り返されることを回避します。 最終的な結合操作は線形で効率的です。 

このソリューションは、出力配列以外に一定の追加メモリのみを使用し、線形時間で実行します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    pref = 0
    ans = []

    for i in range(n - 1):
        pref += a[i]
        ans.append(str(pref))

    print("\n".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("4\n1 0 1 2\n") == "1\n1\n2", "sample 1"

# minimum size
assert run("2\n0 5\n") == "0", "minimum n"

# all equal
assert run("5\n3 3 3 3 3\n") == "3\n6\n9\n12", "all equal"

# increasing values
assert run("6\n1 2 3 4 5 6\n") == "1\n3\n6\n10\n15", "prefix sums"

# all zeros
assert run("5\n0 0 0 0 0\n") == "0\n0\n0\n0", "all zero array"
