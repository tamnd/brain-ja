 ## 解決策
 ## 問題の理解

 私たちに与えられたコレクションは、`n`タンパク質文字列を正確に選択するように求められます`k`選択されたサブセット内のすべてのペア間の最長共通プレフィックス (LCP) の合計が最大になるようにそれらのうちの 1 つを選択します。 各タンパク質は空でない小文字の文字列です。 出力は、サイズのサブセットに対するペアごとの LCP の最大可能合計を表す単一の整数です。`k`。 

重要な観察は、単純なアプローチではすべてが考慮されるということです。`n choose k`サブセットを作成し、それぞれの LCP の合計を計算しますが、これはすぐに実行不可能になります。`n`2000年であり、`k`が 1000 の場合、サブセットの数は合理的な計算制限を超えています。 LCP 自体は、文字列ペアごとに最大 500 回の演算を計算する必要があります。 したがって、効率的なアルゴリズムでは、総当たりの列挙ではなく文字列の構造を利用する必要があります。 

文字列が通常とは異なる方法で共通のプレフィックスを共有する場合、エッジケースが発生します。 たとえば、すべての文字列が同一の場合、すべてのペアが文字列全体の長さに寄与します。 すべての文字列が完全に異なり、共有プレフィックスがない場合、LCP の合計はゼロになります。 小さな例として、次のことを考えてみましょう`n=3, k=2`タンパク質と一緒に`["aba","bzd","abq"]`。 最良のサブセットは`["aba","abq"]`LCP 2ではなく`["aba","bzd"]`LCP 0 を使用。常に辞書順に最初のものを選択する不注意で貪欲なアプローチ`k`文字列は失敗する可能性があります。 

制約`n ≤ 2000`文字列の最大長が 500 の場合は、次のようなアルゴリズムが推奨されます。`O(n^2)`またはわずかに複雑度が高くても許容されますが、指数関数的なものはすべて許容されます。`n`機能しません。 

## アプローチ

 ブルートフォースアプローチでは、すべてが生成されます。`C(n,k)`サブセットを作成し、それぞれのペアごとの LCP 合計を計算します。 それぞれの合計に必要なものは、`O(k^2 * L)`どこでの操作`L`は文字列の長さです。`O(n^k * k^2 * L)`全体的な複雑さ。 これは直ちに実行不可能です`n > 20`。 

重要な洞察は、表現力は文字列のペア間の共通のプレフィックスの長さのみに依存するということです。 文字列を辞書順に並べ替えると、共通のプレフィックスを持つ文字列が連続していることが保証されます。 トライは共有プレフィックス構造をエンコードすることもできますが、ソートと動的プログラミングを使用することで、より単純なソリューションを実現できます。 

並べ替えた後、選択を検討する再帰的アプローチまたは DP アプローチを検討します。`k`共通のプレフィックスを共有する連続した文字列グループからの文字列。 のグループであれば、`m`文字列は同じ長さのプレフィックスを共有します`l`、いずれかを選択します`p`このグループの文字列が貢献しています`l * C(p,2)`合計額に。 サブグループから文字列を再帰的に選択して、表現性を最大化できます。 

このアプローチにより、複雑さが大幅に軽減されます。`O(n^2)`ソートされた順序で LCP を計算する場合、各ペアは最大 1 回だけ考慮されるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^k * k^2 * L) | O(n*k) | 遅すぎる |
 | ソート/トライのDP | O(n^2 + n*L) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列の配列を辞書順に並べ替えます。 これにより、共通のプレフィックスを持つ文字列が隣接することが保証されます。 ソートの理由は、隣接する文字列間の最長の共通プレフィックスが、連続するサブシーケンス内のすべてのペア間の LCP を制限するためです。 
2. すべての文字列ペア間の LCP 値を事前計算します。 のために`i < j`、`lcp[i][j]`間の共通プレフィックスの長さを格納します。`strings[i]`そして`strings[j]`。 これにはかかります`O(n^2 * L)`時間はかかりますが、最初から文字が異なるまでスキャンすることで、各 LCP を効率的に計算できます。 
3. DP テーブルを定義する`dp[i][j]`を選択することで得られる最大の代表性として`j`最初から文字列`i`文字列。 初期化する`dp[0][0] = 0`他のすべてのエントリは負の無限大になります。 
4. 各文字列インデックスを反復処理します。`i`1から`n`。 選択した文字列の数ごとに`j`1から`k`、 アップデート`dp[i][j]`の選択を検討することで、`i`-th 文字列の一部として`j`- 番目の選択。 更新するには、以前のすべての選択を考慮し、新しい文字列と以前に選択した文字列の間に LCP 寄与を追加します。 
5. 最終的な答えは次のとおりです。`dp[n][k]`。 

このアプローチでは、DP が文字列配列のすべての接頭辞とすべての可能な選択数の最大表現性を明示的に追跡するため、正確性が保証されます。 すべての共通プレフィックスは連続しており、DP に蓄積できるため、並べ替えにより LCP 寄与が正しく考慮されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def lcp(a, b):
    length = min(len(a), len(b))
    for i in range(length):
        if a[i] != b[i]:
            return i
    return length

def solve():
    n, k = map(int, input().split())
    strings = [input().strip() for _ in range(n)]
    strings.sort()
    
    lcp_table = [[0]*n for _ in range(n)]
    for i in range(n):
        for j in range(i+1, n):
            lcp_table[i][j] = lcp(strings[i], strings[j])
    
    dp = [[-10**18]*(k+1) for _ in range(n+1)]
    dp[0][0] = 0
    
    for i in range(1, n+1):
        dp[i][0] = 0
        for j in range(1, min(i, k)+1):
            dp[i][j] = dp[i-1][j]  # skip i-th string
            for p in range(i):
                if j-1 >= 0:
                    add = sum(lcp_table[min(p,i-1)][max(p,i-1)] for p in range(i-1))
                    dp[i][j] = max(dp[i][j], dp[i-1][j-1] + add)
    
    print(dp[n][k])

if __name__ == "__main__":
    solve()
```このコードは文字列を並べ替え、ペアごとの LCP を事前計算し、DP を使用して段階的にソリューションを構築します。 LCP 合計を計算するときは、二重カウントを避け、ペアを正しく選択するために特別な注意が必要です。 

## 実用的な例

 サンプル 1:

 | ステップ | 選択された文字列 | LCP合計 |
 | --- | --- | --- |
 | イニシャル | [] | 0 |
 | 「アバ」を考えてみましょう | [「アバ」] | 0 |
 | 「bzd」を追加 | ["aba","bzd"] | 0 |
 | 「abq」を追加 | ["aba","abq"] | 2 |

 最適なサブセットは`["aba","abq"]`合計2で。 

サンプル 2:`n=3, k=3, ["aaa","aab","abb"]`| ステップ | 選択された文字列 | LCP合計 |
 | --- | --- | --- |
 | ["aaa","aab","abb"] | 3 | 1+0+1 = 2 |

 アルゴリズムは 3 つの文字列をすべて正しく選択し、LCP をペアごとに合計します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2 * L) | すべてのペアワイズ LCP を事前計算します。各 LCP の長さは最大でも L |
 | スペース | O(n^2 + n*k) | LCP テーブルと DP テーブル |

 ## 特殊なケース

 すべての文字列が同一の場合、LCP の合計は最大になります。`["aaa","aaa","aaa","aaa"]`そして`k=2`、選択されたサブセットの結果は次のとおりです。`3`「aaa」と「aaa」の LCP は 3 であるためです。`n=1`そして`k=1`、ペアが存在しないため、合計はゼロになります。 このアルゴリズムは、共通のプレフィックスを持たない文字列を正しく処理してゼロを返し、文字列を並べ替えて LCP 蓄積の正しい隣接性を確保します。
