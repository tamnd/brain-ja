 ## 解決策
 ## 問題の理解

 道路で結ばれた都市の無向接続グラフが与えられます。 各商人は 2 つの都市を選択し、1 つは供給元 (倉庫) として、もう 1 つは目的地 (店舗) として選択します。 すべての商業者は、これら 2 つの都市の間の接続が道路の故障に関してどの程度脆弱であるかを判断したいと考えています。 

道路を撤去することで商店の倉庫から店までの移動が不可能になる場合、その道路は商店としてカウントされます。 グラフ用語では、各ノードのペアについて、各エッジがペアを隔てる橋であるという意味で、ノード間のすべての可能なパス上にエッジがいくつあるかを数えなければなりません。 

したがって、クエリペアごとに$(s, t)$、削除によって切断されるエッジを数える必要があります。$s$から$t$。 

グラフには最大で$10^5$ノード、エッジ、クエリ。 これにより、DFS や BFS などのクエリごとのグラフ トラバーサルが即座に除外されます。$O(mk)$に達する$10^{10}$最悪の場合の運用。 

微妙なエッジ ケースは、グラフが 2 つのエッジで接続されている場合です。 たとえば、次のような単純なサイクルです。```
1 - 2 - 3 - 1
```どの都市のペアでも、単一のエッジを削除しても接続性が残るため、すべての答えは 0 になります。素朴な最短パスに基づいた考え方では、すべてのエッジが何らかのパスに現れるため重要であると誤って考えることになりますが、どれも重要ではありません。 

もう 1 つのエッジケースは木です。 木のすべての端が橋です。 したがって、ペアの答えは、それらの間の一意のパス上のエッジの数となります。 どのようなソリューションも、ツリー上のパス長の計算にまで低下する必要があります。 

## アプローチ

 この問題を直接考える方法は、各販売者を個別に処理することです。 特定のペアについて$(s, t)$、各エッジを削除して、$s$まだ到達できる$t$。 それには必要になります$m$クエリごとの接続チェック、それぞれのコスト$O(n + m)$、につながる$O(km(n+m))$、完全に不可能です。 

もう少し優れたブルート フォースは、標準の DFS ローリンク アルゴリズムを使用してグラフ内のすべてのブリッジを事前計算することです。 どのエッジがブリッジであるかがわかれば、問題は次のようになります。クエリごとに、クエリ間のすべてのパス上にブリッジ エッジがいくつあるかを数えます。$s$そして$t$。 重要な観察は、ブリッジ以外のエッジをすべて削除した後、残りの各コンポーネントがツリー (ブリッジ ツリーまたはブロック ツリーと呼ばれることが多い) になることです。 

ブリッジ ツリーでは、すべての元の頂点は 2 エッジ接続されたコンポーネントに属し、コンポーネント間のエッジは正確にブリッジに対応します。 すべてのサイクルを縮小するとすべての冗長性が削除されるため、構造はツリーになります。 

ここで、各クエリはツリー内のパス クエリに帰着します。ブリッジ ツリーに 2 つのノードが与えられた場合、それらの間のパス上にツリー エッジがいくつあるかを数えます。 これは、各コンポーネントに深さを割り当てると、標準的な LCA 距離の問題になります。 

この変換が重要な単純化です。密なグラフ内の任意のパスについて推論する代わりに、グラフをツリーに圧縮し、残りのすべてのエッジが定義上クリティカルになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとの BFS/エッジ削除 | O(k m (n + m)) | O(n + m) | 遅すぎる |
 | ブリッジ + コンポーネント ツリー + LCA | O((n + m + k) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフに対して DFS ベースのブリッジ検出アルゴリズム (Tarjan ローリンク) を実行します。 これにより、削除によって接続コンポーネントの数が増加するすべてのエッジが識別されます。 

この考え方は、エッジがサイクルの一部ではない場合に限り、エッジがブリッジであるというものであり、これは検出時間と低リンク値を使用して検出されます。 
2. 各ノードが 2 エッジ接続されたコンポーネントを表す新しいグラフを構築します。 

これを行うには、ブリッジ エッジを無視する DFS を実行してコンポーネント ID を割り当てます。 橋を渡らずに到達できるすべての頂点は、同じコンポーネントに属します。 

この圧縮ステップにより、新しいグラフに残っているすべてのエッジが正確にブリッジになることが保証されます。 
3. ブリッジツリーを構築します。 

各ブリッジは 2 つの異なるコンポーネントを接続するため、コンポーネント ID の間にエッジを追加します。 すべてのサイクルは元のグラフの非ブリッジ エッジを意味するため、結果として得られる構造はツリーになります。 
4. ブリッジ ツリー上の LCA 構造を事前計算します。 

ツリーを任意にルート化し、深さとバイナリ リフティング祖先を計算します。 これにより、任意の 2 つのコンポーネント間の距離を効率的に計算できます。 
5. 各加盟店のクエリについて$(s, t)$、両方の都市をコンポーネント ID にマッピングします。 

それらが同じコンポーネント内にある場合、それらの間を移動するためのブリッジは必要ないため、答えは 0 になります。 
6. それ以外の場合は、LCA を使用してコンポーネント間のツリー距離を計算します。 

パス上のエッジの数は次のとおりです。$$\text{dist}(u, v) = \text{depth}[u] + \text{depth}[v] - 2 \cdot \text{depth}[\text{lca}(u, v)]$$この値は、撤去によって 2 つの都市が切り離される橋の数と正確に一致します。 

### なぜ効果があるのか

 すべての非ブリッジ エッジはサイクル内にあるため、頂点のペアの切断に寄与することはありません。 各サイクルを単一のノードに集約すると、脆弱なエッジに依存するすべての接続関係が維持されます。 結果として得られるブリッジ ツリーは、分離に必要なすべてのエッジをエンコードします。 このツリー内の 2 つのコンポーネント間のパスは、元のグラフでそれらを分離しているブリッジを正確に通過する必要があり、ブリッジ分解の定義により代替バイパスは存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
g = [[] for _ in range(n)]

edges = []
for i in range(m):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    g[a].append((b, i))
    g[b].append((a, i))
    edges.append((a, b))

tin = [-1] * n
low = [-1] * n
timer = 0
is_bridge = [False] * m

def dfs(v, pe):
    global timer
    tin[v] = low[v] = timer
    timer += 1
    for to, ei in g[v]:
        if ei == pe:
            continue
        if tin[to] == -1:
            dfs(to, ei)
            low[v] = min(low[v], low[to])
            if low[to] > tin[v]:
                is_bridge[ei] = True
        else:
            low[v] = min(low[v], tin[to])

for i in range(n):
    if tin[i] == -1:
        dfs(i, -1)

comp = [-1] * n
cid = 0

def dfs_comp(v, cid):
    stack = [v]
    comp[v] = cid
    while stack:
        x = stack.pop()
        for to, ei in g[x]:
            if comp[to] == -1 and not is_bridge[ei]:
                comp[to] = cid
                stack.append(to)

for i in range(n):
    if comp[i] == -1:
        dfs_comp(i, cid)
        cid += 1

tree = [[] for _ in range(cid)]
for i in range(m):
    if is_bridge[i]:
        a, b = edges[i]
        ca, cb = comp[a], comp[b]
        tree[ca].append(cb)
        tree[cb].append(ca)

LOG = 20
up = [[-1] * cid for _ in range(LOG)]
depth = [0] * cid

def dfs_lca(v, p):
    up[0][v] = p
    for to in tree[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        dfs_lca(to, v)

for i in range(cid):
    if up[0][i] == -1:
        dfs_lca(i, -1)

for j in range(1, LOG):
    for i in range(cid):
        if up[j-1][i] != -1:
            up[j][i] = up[j-1][up[j-1][i]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for i in range(LOG):
        if diff >> i & 1:
            a = up[i][a]
    if a == b:
        return a
    for i in reversed(range(LOG)):
        if up[i][a] != up[i][b]:
            a = up[i][a]
            b = up[i][b]
    return up[0][a]

k = int(input())
out = []
for _ in range(k):
    s, t = map(int, input().split())
    s -= 1
    t -= 1
    cs, ct = comp[s], comp[t]
    if cs == ct:
        out.append("0")
    else:
        w = lca(cs, ct)
        ans = depth[cs] + depth[ct] - 2 * depth[w]
        out.append(str(ans))

print("\n".join(out))
```このコードは、まず DFS タイムスタンプとローリンク値を使用してブリッジを識別します。 次に、各ノードにはこれらのブリッジを無視したコンポーネントが割り当てられ、事実上すべてのサイクルが崩壊します。 ブリッジ エッジは、コンポーネント間にツリーを構築するために使用されます。 最後に、LCA 前処理により高速な距離クエリが可能になり、各加盟店クエリは定数時間のツリー距離計算になります。 

微妙な実装の詳細は、コンポーネントの DFS がブリッジ エッジを越えないようにする必要があることです。 そうしないと、コンポーネントが誤ってマージされ、ツリー構造が破壊されてしまいます。

### トレース

 まず、橋のコンポーネントを計算し、ツリーを構築します。 次にクエリを評価します。 

| クエリ (s, t) | コンプ | 補償(t) | LCA | 深さ | 深さ(t) | 答え |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 5 | あ | C | B | 1 | 1 | 2 |
 | 2 4 | B | B | - | - | - | 1 |
 | 2 6 | B | D | B | 0 | 2 | 2 |
 | 4 7 | C | C | - | - | - | 0 |

 この表は、頂点が橋コンポーネントに圧縮されると、各クエリがツリー内の最短パスになることを示しています。 

これは、カウントされたすべてのエッジが 2 つのコンポーネントを分離するブリッジであるため、それぞれが正確に 1 単位を答えに寄与するという不変条件を裏付けます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m + k log n) | ブリッジとコンポーネントの DFS は線形、LCA 前処理は対数、各クエリは LCA |
 | スペース | O(n + m) | 隣接リスト、コンポーネント配列、およびバイナリ リフティング テーブル |

 すべての操作がグラフ サイズで線形であるか、クエリごとに対数であるため、ソリューションは制限内に問題なく収まります。
