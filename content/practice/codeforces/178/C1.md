 ## 解決策
 ## 問題の理解

 各オブジェクトにそのハッシュ値によって指定される優先位置が割り当てられるハッシュ テーブルをシミュレートしていますが、衝突は固定ステップ サイズを使用して解決されます。 オブジェクトが挿入されると、まずそのハッシュ位置が試行されます。 そのセルがすでに占有されている場合は、一定の歩幅で前方にジャンプし続けます`m`(テーブルサイズの剰余`h`）空きスロットが見つかるまで。 

私たちが気にするコストは、最終的な配置ではなく、途中で試行が失敗した回数です。 挿入中にすでに占有されているセルをプローブするたびに、それはダミー呼び出しとしてカウントされます。 削除はより簡単です。削除はセルを解放するだけであり、調査コストは発生しません。 

一連の操作では挿入と削除が混在するため、すべての挿入で失敗したプローブの合計数を累積する必要があります。 

主な問題点は、削除後に以前にブロックされていた位置が利用可能になる可能性があるため、プローブ チェーンが動的になることです。 挿入ごとに前方スキャンを繰り返す単純なシミュレーションでは、操作数が 200,000 に達し、各挿入でテーブルの大部分がスキャンされると、速度が非常に遅くなります。 

この制約は、O(nh) アプローチでは遅すぎることを意味します。 定数因子を多用した O(n√h) アプローチも不要です。 必要なのは、効率的なデータ構造を使用した O(n) またはほぼ O(n) の償却ソリューションです。 

テーブルが密で長いチェーンが形成されている場合、単純なシミュレーションの微妙な失敗例が発生します。 たとえば、次の場合`h = 10, m = 3`、スロットの長い等差数列を満たす要素を挿入すると、各挿入は空きセルを見つける前に多くの占有セルを横断する可能性があります。 多くの操作にわたって繰り返されると、これは二次的な動作に変質します。 

もう 1 つの重要なエッジ ケースは、プローブ チェーンの途中での欠失です。 削除されたセルは、今後の挿入の新しい有効な停止点になる可能性があるため、構造は単調ではありません。 

## アプローチ

 ブルートフォースのアイデアは単純です。サイズの配列を維持します。`h`ハッシュテーブルを表します。 挿入ごとに、ハッシュ位置から開始して繰り返しチェックします。`(t + i·m) mod h`空のスロットが見つかるまで。 占有されているスロットごとにダミー カウンタがインクリメントされます。 挿入によりテーブルが更新されます。 削除は、指定された ID の保存された位置をクリアするだけです。 

このアプローチは、プローブ プロセスを正確にシミュレートするため、正しいです。 ただし、挿入ごとに多くの占有セルがスキャンされる可能性があります。 最悪の場合、1 回の挿入でほぼすべての領域を横断する可能性があります。`h`スロット。 まで`n = 2 · 10^5`、これは O(nh) につながりますが、これは非常に遅すぎます。 

重要な観察は、プローブを段階的にシミュレートする必要がないということです。 挿入ごとに、そのプローブ パスに沿って占有セルの数が何個あるかを知る必要があるだけです。 プローブ パスは、ステップによって定義される循環順序の決定論的なインデックス シーケンスです。`m`。 以来`1 ≤ m < h`、このシーケンスはテーブルをサイクルに分割します。 各位置は正確に 1 サイクルの長さに属します`h / gcd(h, m)`。 

各サイクル内では、プローブはラップアラウンドのある線形配列に沿って歩くように動作します。 問題は、サイクルごとに、特定のポイントにいくつの占有位置が存在するかを維持し、最初の空のスロットの前にいくつの占有位置が存在するかを迅速に見つける必要があるということです。 

これをサポートする標準的な方法は、サイクルごとに、ソートされた順序付きの占有インデックスのセットを維持することです。 挿入の場合、二分探索を使用して、開始インデックス以降の最初の占有位置を見つけます。 ラップアラウンド前に何も存在しない場合、最初に占有されたセグメントがサイクルを完了するまでのみ支払いが行われます。 

ただし、より効率的で標準的な CF ソリューションでは、重い構造が回避されます。配列を維持します。`next_free`各位置に対して、最初はそれ自体を指します。 また、パス圧縮を使用して、サイクルごとに DSU スタイルの「次に使用可能なスロット」構造を維持します。 スロットが占有されている場合、そのスロットをマークし、次の候補にマージします。`(i + m) % h`。 検索が成功するたびに、ほぼ一定の償却時間ですでに占有されているポジションがスキップされます。 

これは本質的に、ステップ実行によって誘導される有向後続グラフに対する素集合結合です。`m`。 セルを占有するたびに、そのセルを可用性から「削除」し、以降のクエリは O(1) 近くでそのセルを飛び越えます。 

したがって、各位置は 1 回削除され、各ポインタは最大 1 回圧縮され、償却された線形動作が得られます。

 ## アルゴリズムのチュートリアル

 各セルを空きセルまたは占有セルとしてモデル化します。 また、スタートポジションを与えられた場合には、`x`、シーケンスに沿った次の空き位置を返します。`x, x+m, x+2m, ... (mod h)`。 

1. 配列を初期化します`parent[i] = i`各位置が最初に空きスロット候補としてそれ自体を指していることを表します。 この構造は、「次に利用可能なポジション」の素なセットのように機能します。 
2. 関数を定義します`find(x)`現在の代表者を返します`x`。 もし`x`すでに占有されている場合、再帰的にジャンプします`find((x + m) % h)`空きスロットに達するまで。 パス圧縮により、今後のクエリはパス上のすべての占有位置をスキップします。 
3. ブール配列を維持します`used[i]`セルが占有されているかどうかをマークします。 これにより、埋まっているスロットの再利用が防止され、DSU 結合ステップの正確さが保証されます。 
4.挿入用`(+ id, hash)`、計算します`pos = find(hash)`。 これにより、プローブ シーケンスに沿った最初の空きスロットが得られます。 毎回`find`占有されているセルをスキップする場合、ダミー カウンタを 1 ずつインクリメントします。このコストは、空きスロットに到達するまでに実行される再帰ジャンプの数に対応します。 
5. 見つけたら`pos`、それを使用済みとしてマークし、その親を次のように設定して前方にユニオンします。`find((pos + m) % h)`。 これにより、将来の考慮事項から削除され、次の不変条件が維持されます。`find(x)`常に次に利用可能なスロットを返します。 
6. 削除の場合`(- id)`、保存された位置を取得し、空きとしてマークします。 簡単にするために、DSU リンクは再構築しません。 代わりに、将来のことを許可します`find`使用済みとしてマークされないため、この位置を自然に再利用するように呼び出します。 

正確性は、占有されている各セルが検索で見つかったときに正確にスキップされるという事実に依存しており、パス圧縮により、同じブロックされたチェーンを 2 回横断することがないことが保証されます。 DSU は、ステップによって引き起こされる各等差数列に沿って動的な「次のフリー ポインタ」を効果的に維持します。`m`。 

### なぜ効果があるのか

 いつでも、各セルは占有されているか、空いているかのどちらかです。 の`find`関数は常に、次の繰り返し加算によって開始インデックスから到達可能な最初の空きセルを返します。`m`。 親ポインタは占有されているセルのみをスキップし、セルが占有されると、明示的に解放されるまで永久にバイパスされます。 パス圧縮により、スキップされたすべてのセルが次の有効な候補に直接リンクされることが保証され、将来の検索で古い状態に再びアクセスすることがないという不変条件が維持されます。 各セルは検索構造から一度事実上削除されるため、総作業量は逆アッカーマン因子まで直線的になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    h, m, n = map(int, input().split())

    parent = list(range(h))
    used = [False] * h
    pos_of = {}

    sys.setrecursionlimit(10**7)

    def find(x):
        if parent[x] == x:
            return x
        parent[x] = find(parent[x])
        return parent[x]

    def next_pos(x):
        x = x % h
        start = x
        visited = []
        while True:
            fx = find(x)
            if not used[fx]:
                # compress path along the way
                for v in visited:
                    parent[v] = fx
                return fx, len(visited)
            visited.append(x)
            x = (x + m) % h
            if x == start:
                return -1, len(visited)

    total_dummy = 0

    for _ in range(n):
        parts = input().split()
        if parts[0] == '+':
            id_, hh = int(parts[1]), int(parts[2])
            pos, cost = next_pos(hh)
            total_dummy += cost
            used[pos] = True
            pos_of[id_] = pos
            parent[pos] = find((pos + m) % h)
        else:
            id_ = int(parts[1])
            pos = pos_of[id_]
            used[pos] = False

    print(total_dummy)

if __name__ == "__main__":
    solve()
```実装の中核となるのは、`next_pos`この関数は、空きスロットが見つかるまでプローブ シーケンスに沿って進みます。 その際、訪問したすべてのインデックスが記録されるため、空き位置が見つかると、すべての中間ノードがその位置に直接圧縮されます。 これにより、今後の挿入では、一定の償却時間内で占有セグメント全体がスキップされることが保証されます。 

保守します`pos_of`オブジェクト ID をその位置にマップし、削除を一定時間に行うようにします。 の`used`配列は、将来の検索が自然にそこで停止するため、DSU 構造を再構築することなく、削除されたスロットが再び有効になることを保証します。 

微妙な点は、空きスロットを見つけた後にのみ圧縮することです。 圧縮が早すぎると、新しく解放された位置が誤ってバイパスされる危険があります。

 ## 特殊なケース

 濃密なサイクル`m = 1`stresses the worst-case probing behavior. たとえば、完全に占有されているプレフィックスに挿入すると、すべてのセルの走査が強制されますが、DSU 圧縮により、各セルは全体で 1 回だけ走査されるため、繰り返しの挿入は線形のままになります。 

2 番目の微妙なケースは、同じスロットの削除と再挿入を繰り返すことです。 削除時に DSU リンクを再構築しないため、正確さは次の事実に依存します。`find`常に検証します`used[]`。 解放されたスロットはすぐに再び有効になり、以降の検索は構造の更新を必要とせずに自然にそこで停止します。 

最後に、次の場合のラップアラウンド動作`h`そして`m`互いに素ではないため、サイクルが作成されます。 The algorithm handles this implicitly because stepping by`m`常に正しい等差数列内に留まり、DSU リンクがサイクルを越えることはありません。
