 ## 問題の理解

 私たちには番号が与えられています`n`および許容される値の範囲`[l, r]`。 最小の整数を見つける必要があります`x`この範囲内では、`n`そして`x`も同じ範囲内です。 そうでない場合`x`存在する場合は印刷します`-1`。 

重要な観察は、gcd の定義から得られます。 どのような値であっても`gcd(n, x)`つまり、分割する必要があります`n`。 また、これより大きくすることはできません`x`。 これは、すべての有効な回答が次の約数に関連付けられていることを意味します。`n`。 

入力には最大で次のものが含まれます`1000`テストケース。 の値`n`、`l`、 そして`r`と同じ大きさにすることができます`10^9`、つまり、内のすべての値を反復処理します。`[l, r]`不可能です。 範囲自体に 10 億個の数値が含まれる場合があります。 規模に応じたアプローチが必要です`n`代わりに の因数分解を使用します。 までチェック中`sqrt(n)`許容できる理由は`sqrt(10^9)`ほんの約です`31623`、配る`3.2 * 10^7`すべてのテストケースに対する操作。 

厄介なケースは、有効な gcd と有効な gcd を混同することから発生します。`x`。 数値は、それ自体が可能な最小の答えでなくても、有効な gcd を持つことができます。 たとえば、入力が次の場合:```
6 5 6
```範囲内の値は次のとおりです。`5`そして`6`。 最初の値は次の値を与えます`gcd(6,5)=1`、これは無効です。 2番目は与えます`gcd(6,6)=6`、したがって、答えは次のとおりです`6`。 範囲に自明ではない gcd のある値が含まれているかどうかだけをチェックするソリューションでは、誤って受け入れられる可能性があります。`5`。 

もう 1 つのエッジ ケースは、約数が存在するがその下にある場合です。`l`。 のために：```
12 7 11
```の約数`12`は`1, 2, 3, 4, 6, 12`。 範囲内または範囲を超える唯一の約数は、`12`ですが、範囲外なので`12 > 11`。 有効ではありません`x`存在するので、答えは`-1`。 の次の約数を求める不用意な実装`l`確認せずに`r`失敗するだろう。 

最後の境界ケースは、単一要素の範囲です。```
10 1 1
```考えられる唯一の答えは、`1`。 以来`gcd(10,1)=1`、出力は`1`。 これは、アルゴリズムが処理するかどうかをテストします。`l = r`正しく。 

## アプローチ

 単純な方法では、可能な限りすべてのことを試します`x`から`l`に`r`、計算する`gcd(n, x)`、機能する最初の値を返します。 これは正しいです。候補を昇順に検査するため、最初の有効な候補が自動的に最小になります。 

問題は範囲の大きさです。 もし`l = 1`そして`r = 10^9`、これには、1 つのテスト ケースに対して最大 10 億の gcd 計算が必要です。 まで`1000`テストでは、最悪の場合は制限時間をはるかに超えます。 

重要な点は、有効な gcd は次の約数でなければならないということです。`n`。 仮定する`x`は有効な答えであり、`d = gcd(n, x)`。 以来`d`分割する`n`そして`d`中にあります`[l, r]`、番号`d`それ自体も有効な選択です。`gcd(n, d) = d`。 また、`d <= x`ので、置き換えます`x`と`d`決して答えを悪化させることはありません。 

これにより問題は完全に変わります。 次の最小の約数を見つけるだけで済みます。`n`それはに属します`[l, r]`。 以来`n`せいぜい`10^9`、周りのペアをチェックすることで約数を列挙できます`sqrt(n)`。

 ## アルゴリズムのチュートリアル

 1. 考えられるすべての約数の候補を反復処理します。`i`から`1`に`sqrt(n)`。 もし`i`分割する`n`、その後両方`i`そして`n / i`は約数です。 
2. 見つかったすべての約数について、それが以下に属しているかどうかを確認します。`[l, r]`。 これまでに確認された最小の有効な約数を保持します。 
3. すべての約数が処理された後、保存されている最小値を出力します。 範囲内に除数がなかった場合は、出力`-1`。 

までチェックした理由`sqrt(n)`すべての約数が以下であれば十分です`sqrt(n)`より小さい一致する約数があります`sqrt(n)`。 ペア`(i, n / i)`因数分解の両面を見てみましょう。 

これが機能する理由: 考えられるすべての有効な答えは、約数に還元できます。`n`。 アルゴリズムは、次のすべての約数を調べます。`n`、そのため、有効な候補者を見逃すことはできません。 必要な間隔内で常に最小の除数が維持されるため、最終値は正確に可能な最小値になります。`x`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, l, r):
    ans = 10**18
    i = 1
    while i * i <= n:
        if n % i == 0:
            if l <= i <= r and i < ans:
                ans = i
            other = n // i
            if l <= other <= r and other < ans:
                ans = other
        i += 1

    return -1 if ans == 10**18 else ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, l, r = map(int, input().split())
        out.append(str(solve_case(n, l, r)))
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```機能`solve_case`除数検索を実行します。 ループ条件`i * i <= n`すべての因子のペアには平方根のメンバーが 1 つしか含まれていないため、これで十分です。 

約数のとき`i`が見つかった場合、コードもチェックします`n // i`、これはペアの約数です。 これにより、間隔内にある可能性のある大きな約数の欠落が回避されます。 答えは、代わりに非常に大きな値で始まります。`None`これにより、最小の比較が簡単になります。 

main 関数は、すべてのテスト ケースを読み取り、印刷する前に回答を収集します。 この実装では整数演算のみが使用されるため、Python ではオーバーフローの懸念はありません。

## 特殊なケース

 入力の場合:```
6 5 6
```アルゴリズムは次の約数をチェックします。`6`。 それは見つけます`1`、`2`、`3`、 そして`6`。 のみ`6`は必要な間隔内にあるため、答えは次のようになります。`6`。 これは、範囲内の値が自動的に有効ではない場合に対処します。 

のために：```
12 7 11
```除数検索で次のことがわかります。`1`、`2`、`3`、`4`、`6`、 そして`12`。 間には何もありません`7`そして`11`、そのため、保存された答えは変更されず、アルゴリズムが出力します。`-1`。 範囲チェックにより、許可された間隔外の除数を受け入れることができなくなります。 

のために：```
10 1 1
```最初に見つかった約数は次のとおりです。`1`、それはすぐに答えになります。 アルゴリズムは除数スキャンを終了しますが、他の値はそれより小さくできません。 これは、可能な値を 1 つだけ含む範囲をカバーします。
