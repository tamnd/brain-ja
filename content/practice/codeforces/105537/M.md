 ## 解決策
 ## 問題の理解

 この問題は、複数のオブジェクトの山でプレイされる 2 人用の公平なゲームを表しています。 プレイヤーは交互に移動し、各移動でプレイヤーは 1 つの山を選択し、そこから少なくとも 1 つのオブジェクトを削除します。 最後の手を打つプレイヤーはミゼール ルールに基づいて決定されます。つまり、通常の「最後の手が勝つ」という条件が、通常のニムと比較してゲームの最終段階で逆転または変更されます。 

入力は複数の独立したゲーム構成で構成されます。 各構成ではいくつかのパイルのサイズが示されており、両方のプレーヤーが最適にプレイしていると仮定して、各構成について最初のプレーヤーが強制的に勝利するかどうかを判断する必要があります。 

複雑さの観点から見ると、すべてのテスト ケースにわたる杭の総数が大きくなり、通常は最大約 10^5 になるのが自然なスケールです。 これにより、動きをシミュレートしたり、完全なゲーム ツリーを構築しようとするソリューションは即座に除外されます。 山の数が 2 次であっても生き残ることはできません。 私たちは、パイルごとに一定の作業を行い、各構成を線形時間で処理するソリューションを余儀なくされています。 

ミゼール バリアントの明白ではない難しさは、杭サイズの XOR を使用する標準的な Nim 解析がほぼ正しいものの、非常に特殊な境界条件で失敗するという事実から来ています。 常にパイル サイズの XOR を計算し、それがゼロでない場合に最初のプレーヤーの勝利を宣言する不注意なアプローチは、すべてのパイルのサイズが正確に 1 である構成で中断されます。 たとえば、入力がサイズ 1 の単一の山である場合、単純な XOR アプローチは 0 以外を返し、最初のプレーヤーが勝つと主張しますが、ミゼール プレイでは唯一の手が負け手でもあります。 同様に、すべてのパイルがサイズ 1 で複数のパイルがある場合、XOR ではなく、パリティが唯一の決定要因になります。 この急激な変化が、この問題の重要な微妙な点です。 

## アプローチ

 ゲームについて考える強引な方法は、すべての状態をゲーム グラフ内のノードとしてモデル化することです。 状態はパイル サイズのベクトルによって定義され、すべての移動は座標を 1 つ減らすことで別の状態に遷移します。 このグラフから、標準的な後方帰納法を使用して、最終状態にラベルを付け、値を上方に伝播して、勝ちポジションと負けポジションを計算できます。 

これが概念的に機能するのは、ゲームが有限かつ非循環的であるため、すべてのポジションが勝ちか負けかのどちらかであるためです。 ただし、状態の数はオブジェクトの総数に応じて指数関数的に増加します。 適度なサイズのパイルであっても、状態空間は天文学的に大きくなります。 ブルートフォース手法では同じ下部構造を繰り返し探索するため、計算量が爆発的に増加します。 

重要な観察は、これが恣意的なゲーム グラフではないということです。 これは、ばらばらのコンポーネントを備えた古典的な公平な組み合わせゲームであり、既知の構造である Nim に還元されることを意味します。 通常の Nim の場合、Sprague-Grundy の定理により、各山は XOR を介して独立して寄与することがわかります。 唯一の逸脱はミゼール条件によって引き起こされ、すべての山がサイズ 1 であるゲームの終端領域にのみ影響します。 

その例外を分離すると、残りの構造は標準の XOR 動作に戻ります。 問題全体は、すべての杭サイズの XOR を計算し、すべての杭がサイズ 1 の場合に特別なルールを適用することに帰着します。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。

1. 杭の数とそのサイズを読み取ります。 ゲームの構造はこれらの値によって完全に決定されるため、前処理は必要ありません。 
2. すべてのパイルのサイズが正確に 1 つであるかどうかを確認します。 この条件は、通常の XOR ロジックが適用されない、ゲームの特殊な端末のような領域を識別します。 1 つの山が 1 つより大きい場合でも、ゲームは標準の Nim と同様に動作します。 
3. すべての杭のサイズが 1 の場合、杭の合計数を計算します。 各移動がちょうど 1 つの山を完全に削除するため、ゲームは単純なパリティ コンテストに縮小されます。 
4. すべての杭がサイズ 1 ではない場合は、すべての杭サイズの XOR を計算します。 これは、通常の Nim ルールに基づく結合位置の Sprague-Grundy 値を取得します。 
5. 計算された条件に基づいて勝者を決定します。 オール 1 の場合、山の数が偶数である場合に限り、最初のプレーヤーが勝ちます。 それ以外の場合は、XOR がゼロ以外の場合に限り、最初のプレーヤーが勝ちます。 

ステップ 2 の背後にある理由は、ミゼール プレイの構造的破壊です。 いずれかのパイルがサイズ 1 を超えた瞬間、ゲームは標準の Nim 理論を変更せずに適用できる十分な柔軟性を保持します。 

### なぜ効果があるのか

 不変条件は、少なくとも 1 つの山のサイズが 1 より大きい限り、ゲームはグランディ値の点で通常の Nim と同等であるということです。 ミゼール条件は終端位置の評価を変更するだけであり、それらの終端位置はまさにすべての杭がサイズ 1 を持つ構成になります。 その制限された部分空間では、各移動がちょうど 1 つの山を削除し、ゲームを単純なパリティ ゲームに変えます。 その部分空間の外では、最適なプレイでは、すでに避けられない限り、ゲームを純粋なオール 1 構成に強制することが常に回避されるため、XOR は引き続き意思決定基準として有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        all_ones = True
        x = 0
        
        for v in a:
            x ^= v
            if v != 1:
                all_ones = False
        
        if all_ones:
            # misère: last move loses, so parity decides outcome
            out.append("Second" if n % 2 == 1 else "First")
        else:
            out.append("First" if x != 0 else "Second")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装はアルゴリズムに直接に従います。 XOR は、各テスト ケースの 1 回のパスで累積されます。 同時に、ブール値フラグは、構成が完全にオール 1 体制にあるかどうかを追跡します。 

唯一微妙な決定は最後の条件です。 すべて 1 の場合、XOR には意味のある情報が含まれないため、XOR を意図的に無視します。 代わりに、純粋にパイル数の同等性に依存します。 それ以外の場合はすべて、標準の Nim ロジックが適用され、XOR のみで結果が決まります。 

## 実用的な例

 杭の場合を考えてみましょう`[1, 1, 1]`。 

| ステップ | パイル | XOR | オールワンズ | 決定 |
 | --- | --- | --- | --- | --- |
 | 開始 | [1,1,1] | 0 | 本当 | パリティチェック |
 | スキャン後 | [1,1,1] | 1^1^1 = 1 | 本当 | オールワンブランチ |
 | 最終回 | - | - | - | n=3 奇数 → 2 番目 |

 これは、XOR がゼロ以外であっても、構造上の制約により無視されることを示しています。 結果は完全にパリティによって決まります。 

ここで考えてみましょう`[1, 1, 2]`。 

| ステップ | パイル | XOR | オールワンズ | 決定 |
 | --- | --- | --- | --- | --- |
 | 開始 | [1,1,2] | 0 | 偽 | XOR ブランチ |
 | スキャン後 | [1,1,2] | 1^1^2 = 2 | 偽 | 通常のニム |
 | 最終回 | - | - | - | XOR≠0 → 最初 |

 これは、単一の非ユニット パイルが存在するとすぐに、ミゼール固有のロジックから標準 Nim に戻ることを示しています。

 ## 特殊なケース

 1 より大きいサイズの単一の山の場合、たとえば`[5]`、アルゴリズムは XOR 分岐に正しく入ります。 XOR はゼロではないため、最初のプレーヤーが勝ちます。これは、1 回の動きで常に山をゼロにできるという事実と一致します。 

のような構成の場合`[1]`、オール 1 条件は true であり、パリティは奇数です。 アルゴリズムは 2 番目を返します。これは、唯一の手が最初のプレーヤーにとって不利なゲームを終了することを反映しています。 

次のような混合構成の場合`[1,1,1,2]`の場合、オール 1 フラグは、次の存在により false になります。`2`。 XOR は通常どおり計算され、決定はそれにのみ依存します。 これにより、単純な実装でよくある失敗モードである、非終端構造にパリティ ロジックが誤って適用されることが防止されます。
