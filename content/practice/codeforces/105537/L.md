 ## 解決策
 ## 問題の理解

 2 つの文字列が与えられ、両方の文字列に現れる最も長い連続セグメントの長さを決定したいとします。 ここでの連続セグメントとは部分文字列を意味するため、文字は順番に、隙間なく一致する必要があります。 

入力は 2 行で構成され、各行にはアルファベット上の文字列が含まれます。 出力は、両方の文字列内のどこかに存在する部分文字列の最大長を表す単一の整数です。 

制約が大きいため、すべての部分文字列を明示的に比較するアプローチは実行不可能になります。 両方の文字列の長さが最大約 10^5 である場合、すべての部分文字列を列挙すると、文字列ごとにおよそ O(n^2) 個の候補がすでに含まれることになり、それらを比較すると、単純な形式で少なくとも O(n^3) 個に爆発します。 ハッシュに依存しながらもすべてのペアを反復する最適化された部分文字列比較でも、最悪の場合には速度が非常に遅くなります。 

これは、ソリューションが部分文字列の明示的な列挙を避け、代わりに繰り返される部分文字列の比較を圧縮する構造に依存する必要があることを直ちに示唆しています。 

実際には、いくつかのエッジの状況が重要になります。 1 つの文字列が空の場合、答えはゼロになります。 文字列に共通の文字がない場合は、両方が長い場合でも、答えはゼロになります。 文字列が同一の場合、答えは文字列の全長になります。 より微妙なケースは、文字が繰り返される場合です。たとえば、`"aaaaa"`そして`"aaa"`ここで、答えは最小長であり、単純な部分文字列マッチングでは、慎重に扱わないと重複を簡単にカウントしすぎてしまう可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 最初の文字列のすべての部分文字列と 2 番目の文字列のすべての部分文字列を生成し、それらを比較して最長一致を見つけます。 ハッシュを使用して比較を最適化しようとしても、部分文字列の数は依然として 2 次であるため、実装に応じて、文字列ごとにおよそ O(n^2) 個の部分文字列と、ペアごとに O(1) または O(log n) 個の比較を行うことになります。 これはすぐに大きくなりすぎます。 

もう少し優れた強引なアプローチは、各文字列に 1 つずつ開始位置のペアを固定し、文字が一致する間に拡張することです。 ペアごとに、一致するウィンドウを拡大します。 これは正しいです。共通の部分文字列は、整列された開始位置に対応する必要があるからです。 ただし、これでも O(n^2) ペアが検査され、最悪の場合はペアあたり O(n) まで拡張され、繰り返される文字などの敵対的な入力に対して O(n^3) の動作が生成される可能性があります。 

重要な点は、すべての部分文字列を個別にチェックするのではなく、2 つの文字列のすべての接尾辞の間で最も長い共通の接頭辞を見つけることとして問題を処理できることです。 最初の文字列のすべての接尾辞と 2 番目の文字列のすべての接尾辞を考慮すると、共通の部分文字列はまさに接尾辞のペアの共通の接頭辞になります。 これにより、問題はすべてのサフィックス ペアにわたる最大 LCP 値を見つけることに変換されます。 

接尾辞配列または接尾辞オートマトンは、すべての接尾辞とその関係を自然に捕捉します。 ここでは、サフィックス オートマトンのアプローチが特に明確です。 接尾辞オートマトンは文字列のすべての部分文字列をコンパクトに表し、各状態は同じ終了位置を持つ部分文字列のセットに対応します。 最初の文字列から構築されたオートマトンを通じて 2 番目の文字列をスキャンすると、最初の文字列に出現する各位置で終わる最長の部分文字列を追跡できます。 

これにより、オートマトンの現在の一致状態を維持しながら、すべての部分文字列ペアを 2 番目の文字列に対する単一の線形スキャンと比較することによる問題が軽減されます。

 ## アルゴリズムのチュートリアル

 最初の文字列のサフィックス オートマトンを構築し、各位置で終わる最長の有効な一致を追跡しながら、このオートマトン上で 2 番目の文字列のウォークスルーをシミュレートします。 

1. 最初の文字列から接尾辞オートマトンを構築します。 各状態には、文字の遷移、サフィックス リンク、およびその状態によって表される部分文字列の最大長が格納されます。 この構造は、最初の文字列のすべての部分文字列を O(n) 状態に圧縮します。 
2. 2 つの変数を初期化します。`state`オートマトンの初期状態を指し、`length`現在一致する部分文字列の長さを表します。 
3. 2 番目の文字列の各文字を左から右に繰り返します。 
4. 現在のキャラクターを使用して現在の状態から遷移がある場合は、それに従って増加します`length`1つずつ。 これは、最初の文字列に存在する有効な部分文字列を拡張したことを意味します。 
5. そのような遷移がない場合は、現在のキャラクタとの遷移がある状態が見つかるまで、またはルートに到達するまで、サフィックス リンクを繰り返したどります。 そうするうちに、`length`これは、一致したサフィックスが再び有効になるまで短縮されるためです。 
6. フォールバック後に有効な遷移が見つかった場合は、それを取得して設定します`length`その遷移状態の長さに 1 を加えたものになります。 そうでない場合はリセットしてください`state`そして`length`ゼロに。 
7. の最大値を追跡します。`length`2 番目の文字列のすべての位置にわたって。 この値が答えです。 

現在の一致は最初の文字列の部分文字列に一致する場合にのみ有効であるため、フォールバック ステップが必要です。 不一致が発生した場合は、オートマトン内にまだ表示されている現在の部分文字列の最長の接尾辞を見つける必要があります。 

### なぜ効果があるのか

 接尾辞オートマトンは、最初の文字列のすべての部分文字列をルートからのパスとしてエンコードします。 2 番目の文字列のスキャン中のどの時点でも、アルゴリズムは次の不変条件を維持します。`length`最初の文字列の部分文字列でもある 2 番目の文字列の処理されたプレフィックスの最長のサフィックスに対応し、`state`は、その部分文字列を表すオートマトンの状態です。 不一致が発生するたびに、有効な遷移が再び存在するまで、サフィックス リンクに従うことで、現在の部分文字列の左側から長さの降順で文字が効果的に削除されます。 接尾辞リンクは、オートマトンの意味では接頭辞でもある最長の適切な接尾辞を表すため、これにより、有効な候補部分文字列をスキップしたり、一致長を過大評価したりすることがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class State:
    __slots__ = ("next", "link", "length")
    def __init__(self):
        self.next = {}
        self.link = -1
        self.length = 0

def build_sa(s):
    st = [State()]
    last = 0

    for ch in s:
        cur = len(st)
        st.append(State())
        st[cur].length = st[last].length + 1

        p = last
        while p != -1 and ch not in st[p].next:
            st[p].next[ch] = cur
            p = st[p].link

        if p == -1:
            st[cur].link = 0
        else:
            q = st[p].next[ch]
            if st[p].length + 1 == st[q].length:
                st[cur].link = q
            else:
                clone = len(st)
                st.append(State())
                st[clone].length = st[p].length + 1
                st[clone].next = st[q].next.copy()
                st[clone].link = st[q].link

                while p != -1 and st[p].next[ch] == q:
                    st[p].next[ch] = clone
                    p = st[p].link

                st[q].link = st[cur].link = clone

        last = cur

    return st

def longest_common_substring(s, t):
    sa = build_sa(s)

    v = 0
    l = 0
    best = 0

    for ch in t:
        if ch in sa[v].next:
            v = sa[v].next[ch]
            l += 1
        else:
            while v != -1 and ch not in sa[v].next:
                v = sa[v].link
            if v == -1:
                v = 0
                l = 0
                continue
            l = sa[v].length + 1
            v = sa[v].next[ch]

        if l > best:
            best = l

    return best

s = input().strip()
t = input().strip()
print(longest_common_substring(s, t))
```この解決策は、最初の文字列に対して接尾辞オートマトンを構築することから始まります。 各状態は、辞書内の遷移、サフィックス リンク、およびその状態によって表される部分文字列の最大長を格納します。 この構造により、最初の文字列のすべての部分文字列がオートマトン内の何らかのパスに対応することが保証されます。 

2 番目の文字列のスキャン中に、現在の状態と一致長が維持されます。 現在の文字を使用して拡張できる場合は、直接拡張します。 それ以外の場合は、有効な遷移が見つかるかルートに戻るまで、サフィックス リンクをたどります。 長さは、オートマトン内にまだ存在する最長の有効な接尾辞を反映するように調整されます。 答えは、このスキャン中に検出された最大一致長です。 

微妙な詳細は、ルートにフォールバックしてもまだ移行できない場合のリセット動作です。 状態と長さの両方を明示的にリセットしないと、古い一致の長さが誤って伝播し、一致が過剰にカウントされる可能性があります。 

## 実用的な例

 検討してください`s = "ababc"`そして`t = "babca"`。 

スキャンの進行状況を追跡します`t`。 

| キャラクター | 状態遷移 | 長さ | ベスト |
 | --- | --- | --- | --- |
 | b | ルート → b | 1 | 1 |
 | | ば→ば | 2 | 2 |
 | b | バ → バブ | 3 | 3 |
 | c | バブ → バブ | 4 | 4 |
 | | 不一致、 | にフォールバックします。 1 | 4 |

 これは、オートマトンがどのように貪欲に一致を拡張し、必要な場合にのみフォールバックして、最長の有効な部分文字列を保持するかを示しています。 

ここで考えてみましょう`s = "aaaaa"`そして`t = "aaa"`。 

| キャラクター | 状態遷移 | 長さ | ベスト |
 | --- | --- | --- | --- |

 | | 拡張する | 2 | 2 |
 | | 拡張する | 3 | 3 |

 このケースでは、文字が繰り返されており、オートマトンは再利用性の高い領域に留まり、継続的に一致を延長しています。

 ## 特殊なケース

 空の文字列または単一文字の文字列の場合、ルート状態には遷移がないか、遷移が 1 つしかないため、オートマトンは引き続き正しく動作します。 のために`"a"`そして`"a"`、スキャンは有効な遷移の直後に行われ、長さ 1 が生成されます。 

次のような繰り返し文字列の場合`"aaaaa"`そして`"aaa"`、すべてのステップはオートマトンの小さなサイクル内に留まります。 フォールバック ロジックは決してトリガーされません。これは、アルゴリズムが明示的な部分文字列の列挙を必要としないことを確認します。 

For completely disjoint alphabets, for example`"abc"`そして`"xyz"`、すべての文字により、ルート状態へのフォールバックが発生し、一致長が即時にリセットされます。 遷移は決して成功しないため、最良の値は常にゼロのままです。
