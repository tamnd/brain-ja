 ## 解決策
 ## 問題の理解

 一列に配置された一連のレンガが与えられます。 各レンガは 1 単位の幅と特定の高さを持っています。 また、列の幅も固定されており、1 つの列に並べて配置できるレンガの数は限られています。 

構築ルールは単純です。左から右に行を埋め始めます。 各列には最大でも固定数のレンガを保持できます。 行が埋まったら、そのすぐ下に新しい行を開始し、同じ順序でレンガを配置し続けます。 列の高さはレンガの高さの合計ではなく、その列に配置されたすべてのレンガの最大の高さになります。 壁の合計の高さは、このようにして形成されたすべての列の高さの合計になります。 

したがって、タスクは、レンガの高さの配列を最大でも指定された幅のサイズの連続したブロックに分割し、各ブロックの最大値を取得し、それらの最大値を合計することになります。 

入力サイズの制約により、通常は最大約 10 万個のブリックが許可されます。 O(n²) アプローチでは、最悪の場合、2 秒の制限をはるかに超える 100 億回の演算が必要となるため、これにより、二次関数以上のものが即座に除外されます。 各ブリックを 1 回処理するリニア スキャンで十分です。 

最後の行が完全に埋まっていない場合、微妙なエッジケースが発生します。 たとえば、幅が 4 で、最後のグループに次のようなレンガが 2 つだけ含まれている場合、`[5, 1]`、その行の高さは変わりません`5`、平均的または部分的な調整ではありません。 もう 1 つのエッジ ケースは、すべてのレンガが行に正確に収まり、すべてのグループのサイズが正確である場合です。`w`また、ループ境界の間違いにより最終グループの処理を誤ってスキップしないようにする必要があります。 

## アプローチ

 この問題を直接考える方法は、説明どおりに行の構築をシミュレートすることです。 レンガを反復処理し、現在の行に配置されたレンガの数を継続的にカウントし、その行でこれまでに確認された最大の高さを追跡します。 行がいっぱいになると、その最大値を答えに追加し、カウンターをリセットして続行します。 

すべてのブリックを少なくとも 1 回読み取る必要があるため、このシミュレーションはすでに最適な構造になっています。 より単純な変形では、各行をリストとして明示的に構築し、それを埋めた後にその最大値を計算しようとします。 これでも合計作業量は線形になりますが、リストの割り当てとスキャンが繰り返されるため、一定のオーバーヘッドが高くなります。 もう 1 つの間違った単純な考えは、配列を事前にチャンクに分割してから最大値を個別に計算することです。これは同等ですが、各チャンクが値を増分的に維持するのではなく再計算する場合、非効率的に実装される可能性があります。 

重要な点は、レンガを配置した後に再度そのレンガにアクセスする必要がないということです。 行ごとに必要な情報は、これまでに検出された最大の高さだけであるため、スキャン中にこの値を増分的に維持できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 明示的な行構築 + 最大値の再計算 | O(n) | O(n) | 受け入れられるが非効率的 |
 | ローリング最大値を使用したシングルパス シミュレーション | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 レンガを左から右に処理し、現在アクティブな行に配置されているレンガの数と、その行でこれまでに確認された最大高さという 2 つの状態を維持します。 

1. 合計の答えをゼロとして初期化し、現在の行数と現在の行の最大値の両方をゼロに設定します。 
2. 各レンガを順番に繰り返します。 レンガごとに、現在の行の最大値をレンガの高さと比較して更新します。 これにより、現在の行で最も高いレンガが常にわかるようになります。 
3. 現在の行にもう 1 つのレンガを配置したので、現在の行のレンガの数を増やします。 
4. 現在の行が許容される幅に達した場合、最大の高さを答えの合計に加算することでこの行を完成させます。 次に、直後に新しい行が開始されるため、行数をリセットし、現在の最大値をリセットします。 
5. すべてのレンガを処理した後、部分的に塗りつぶされた行が残っている場合は、その最大高さも答えに追加します。 最後の行では全角補完がトリガーされない可能性があるため、この手順は不可欠です。 

現在の最大値のみを維持する理由は、行の高さはそのセグメント内の最も高いレンガのみに依存し、将来の操作では完成した行を変更できないためです。 

### なぜ効果があるのか

 各ブリックは、シーケンス内のインデックスによって純粋に決定される 1 つの行に属します。 アルゴリズムは、配列を長さの連続するセグメントに分割します。`w`(おそらく最後を除く)。 各セグメント内で、増分更新を使用して最大高さを 1 回だけ計算します。 行の高さはその最大値によってのみ定義され、行は独立しているため、これらの最大値を合計すると、正しい壁の合計高さが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, w = map(int, input().split())
    h = list(map(int, input().split()))
    
    total = 0
    cur_max = 0
    cnt = 0
    
    for x in h:
        cur_max = max(cur_max, x)
        cnt += 1
        
        if cnt == w:
            total += cur_max
            cnt = 0
            cur_max = 0
    
    if cnt > 0:
        total += cur_max
    
    print(total)

if __name__ == "__main__":
    solve()
```コードはアルゴリズムを直接反映しています。 の`cnt`変数は、現在の行に配置されたレンガの数を追跡し、行がいつ完了したかを確認します。 の`cur_max`変数は、セグメント全体を保存する必要なく、現在のセグメント内の最も高いレンガを維持します。 最後の条件付き加算は、不完全な最後の行を処理します。 

よくある間違いはリセットを忘れることです`cur_max`新しい行を開始するとき。 このリセットを怠ると、前の行の最大値が次の行に誤って混入し、結果が増大します。

 ## 特殊なケース

 レンガが 1 つだけあり、幅が 1 の場合、アルゴリズムは 1 回の更新を処理し、すぐに行を完成させ、その高さを返します。 部分的な行ロジックが干渉する可能性はなく、結果は自明のことながら正しいものになります。 

幅がレンガの数より大きい場合、シーケンス全体が 1 つの不完全な列を形成します。 このアルゴリズムはループ内で全行条件をトリガーすることはありません。`if cnt > 0`ブロックは、定義に一致する配列全体の最大値が返されることを保証します。 

すべてのレンガの高さが同じである場合、各行の最大値はすべてのセグメントにわたって同じままになります。 ローリング最大値は決して変化せず、完了した各行は同じ値に寄与し、アルゴリズムが正しく機能するために入力の変動に依存しないことが確認されます。 

シーケンスの長さが幅の正確な倍数である場合、最後の行は常にループ内で完全に処理され、後続の条件はトリガーされません。 これにより、二重カウントやセグメントの欠落が確実になくなります。
