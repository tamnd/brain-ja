 ## 解決策
 ## 問題の理解

 スティックの長さの配列が与えられます。 各クエリは、単一のスティックの長さを変更するか、部分配列内を調べて三角形を形成できる 3 つの異なるスティックを選択するように要求します。 その範囲内のすべての有効なトリプルの中で、周囲を最大化する必要があります。 

三角形の条件は非常に特殊な意味で重要です。 選択した 3 つの長さを次のように並べ替えると、$x \le y \le z$、三角形はまさに次のときに存在します。$x + y > z$。 これにより、幾何学的条件が 2 つの小さい辺と最大の辺を含む 1 つの不等式に縮小されます。 

この制約により、私たちはデータ構造の解決策に向かうことになります。 まで$2 \cdot 10^5$要素と$2 \cdot 10^5$クエリの場合、すべてのクエリの範囲をスキャンするソリューションは遅くなりすぎます。 クエリごとのフルスキャンは次のとおりです。$O(n)$、につながる$O(nq)$、これは許容範囲をはるかに超えています。 

素朴なアプローチの微妙な失敗例は、3 つの最大の要素を選択することが常に機能すると仮定することです。 スティックで範囲を考える$[10, 9, 1]$。 最大の 3 つは同じ値ですが、$1 + 9 > 10$が成り立つので、ここでは機能します。 ただし、$[10, 6, 5, 1]$、最大の 3 つは次のとおりです。$10, 6, 5$、 そして$6 + 5 > 10$も機能します。 本当の危険は、すべての候補をチェックせずにローカルで貪欲な選択が行われた場合、特に更新が存在し、順序が動的に変更される場合に現れます。 

もう 1 つの失敗例は、更新を無視して遅延的に再計算することです。 値は変更される可能性があるため、オフラインまたは静的な並べ替えアプローチは、ポイントの更新が表示されるとすぐに機能しなくなります。 

## アプローチ

 直接的なブルート フォース ソリューションは、範囲内のすべての要素を収集し、並べ替えて、最大側から下に向かって連続するトリプルをすべてチェックすることによって各クエリを処理します。 ソートがコストの大半を占めるため、各クエリが作成されます。$O(k \log k)$どこ$k$範囲サイズです。 最悪の場合$k = n$、これは次のようになります$O(n \log n)$クエリごとに、これは遅すぎます$2 \cdot 10^5$クエリ。 

重要な観察は、答えは範囲内の最大数の要素のみに依存するということです。 範囲全体を並べ替える場合、最適な三角形は常に最大要素間の何らかの 3 倍によって形成されます。これは、辺を増やすと周囲が増えるだけであり、最大要素の不等式を満たすことが容易になるためです。 

これは、完全に分類された情報は必要ないことを示唆しています。 セグメントごとに、三角形に参加できる最大数の候補を維持するだけで済みます。 たとえば、各セグメントの上位 50 または 60 の値を保持する場合、2 つのセグメントをマージしても、最適な三角形を回復するのに十分な候補が保持されます。 定数境界が機能するのは、有効な三角形にはローカル構成の最上位要素が含まれている必要があり、マージによって順序と候補が保持されるためです。 

これにより、当然のことながら、各ノードがそのセグメント内の最大値の小さな並べ替えリストを格納するセグメント ツリーが作成されます。 範囲クエリはこれらのリストをマージし、上位 K 個の要素のみを保持します。 更新によりリーフが変更され、上向きに再計算されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n \log n)$クエリごと |$O(n)$| 遅すぎる |
 | セグメント ツリー (上位 K のマージ) |$O(q \cdot K \log n)$|$O(nK)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードがそのセグメント内の最大 K 値のソートされたリストを格納するセグメント ツリーを維持します。 

1. 単一要素リストを使用してセグメント ツリーの葉を作成します。 各葉にはちょうど 1 本のスティックの長さが含まれています。 これにより、上向きにマージするための基本ケースが得られます。 
2. 内部ノードごとに、左右の子リストを結合し、結合されたリストを並べ替えて、最大の K 値のみを保持します。 十分に大きな候補が存在すると、より小さい値は最適な三角形に寄与できないため、K のみを保持します。 
3. 更新クエリの場合、対応するリーフの位置 p の値を置き換え、同じマージ ルールを使用してすべての祖先を再計算します。 
4. 範囲クエリの場合、間隔をカバーするすべてのセグメント ツリー ノードを収集し、保存されているリストを 1 つの候補リストにマージし、再び最大の K 値のみを保持します。 
5. クエリの最終候補リストを取得したら、それを最大から最小までスキャンし、トリプルをチェックします。 トリプルごとに$a[i], a[i+1], a[i+2]$かどうかを確認します。$a[i+1] + a[i+2] > a[i]$。 最初に見つかった有効なトリプル (最大側から開始) が最大周囲長を示します。 

スキャンが機能する理由は、リストが降順でソートされるため、以前のトリプルには常により大きな周囲候補が含まれるためです。 

### なぜ効果があるのか

 範囲内の最適な三角形は、関連するすべてのマージ ステップでの上位 K フィルタリングを通過した 3 つの要素によって形成されなければなりません。 セグメント ツリーにより、十分に大きな候補がすべて保存されることが保証されます。 三角形の条件は、順序と、最大の辺に対する 2 つの小さな辺の合計にのみ依存するため、任意の辺をより大きな利用可能な候補に置き換えても、実現可能性が低下することはなく、厳密に周囲を改善または維持することはできません。 これにより、上位 K 個の要素に注目を制限しても、最適なソリューションが削除されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

K = 60  # safe upper bound for candidate maintenance

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.tree = [[] for _ in range(2 * self.size)]
        
        for i in range(self.n):
            self.tree[self.size + i] = [arr[i]]
        
        for i in range(self.size - 1, 0, -1):
            self.tree[i] = self.merge(self.tree[2 * i], self.tree[2 * i + 1])
    
    def merge(self, a, b):
        i = j = 0
        res = []
        while i < len(a) and j < len(b):
            if a[i] > b[j]:
                res.append(a[i])
                i += 1
            else:
                res.append(b[j])
                j += 1
        while i < len(a):
            res.append(a[i])
            i += 1
        while j < len(b):
            res.append(b[j])
            j += 1
        if len(res) > K:
            res = res[:K]
        return res
    
    def update(self, idx, val):
        i = self.size + idx
        self.tree[i] = [val]
        i //= 2
        while i:
            self.tree[i] = self.merge(self.tree[2 * i], self.tree[2 * i + 1])
            i //= 2
    
    def query(self, l, r):
        l += self.size
        r += self.size
        left_res = []
        right_res = []
        
        while l <= r:
            if l % 2 == 1:
                left_res = self.merge(left_res, self.tree[l])
                l += 1
            if r % 2 == 0:
                right_res = self.merge(self.tree[r], right_res)
                r -= 1
            l //= 2
            r //= 2
        
        return self.merge(left_res, right_res)

def solve():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))
    st = SegTree(arr)
    
    out = []
    
    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 0:
            _, p, v = tmp
            st.update(p, v)
        else:
            _, l, r = tmp
            vals = st.query(l, r)
            
            ans = 0
            for i in range(len(vals) - 2):
                a, b, c = vals[i], vals[i + 1], vals[i + 2]
                if b + c > a:
                    ans = a + b + c
                    break
            
            out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```セグメント ツリーには制限されたサイズのベクトルのみが格納されるため、更新とマージの両方が予測可能になります。 各マージ ステップでは順序が保持されるため、リストが降順でソートされたままであると想定できます。これはトライアングル チェックにとって重要です。 

クエリ ロジックは、左側と右側の部分セグメントを個別にマージし、最後にそれらを結合することに依存します。 これにより、可能な間隔ごとに完全なセグメント ツリー ノードが必要になることがなくなります。 

最適な三角形はソートされた順序で上位の候補の中に出現する必要があり、先にスキップしても潜在的な境界が減少するだけであるため、三角形のチェックは連続するトリプルに対してのみ行われます。 

## 実用的な例

 ### 例 1

 入力:```
arr = [3, 1, 4, 1, 5, 9, 2]
query = [2, 6]
```値を抽出します`[4, 1, 5, 9, 2]`そして上位候補者を維持します。 

| ステップ | 候補者リスト (説明) | アクション |
 | --- | --- | --- |
 | マージ | [9、5、4、2、1] | トップKを集める |
 | スキャン i=0 | (9,5,4) 無効 | 5+4 <= 9 |
 | スキャン i=1 | (5,4,2) 有効 | 4+2 > 5 |

 答えは$5 + 4 + 2 = 11$。 

これは、ソートされた範囲の小さなサブセットのみが必要な理由を示しています。 

### 例 2

 アップデート後:```
arr = [7, 1, 4]
query = [0, 2]
```候補者リストは`[7, 4, 1]`。 

| ステップ | トリプル | チェック |
 | --- | --- | --- |
 | i=0 | (7,4,1) | 4+1 <= 7 |

 有効な三角形が存在しないため、答えは 0 です。 

これは、最大の要素でも三角不等式を満たさない可能性があるため、チェックが必要であることを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、最良の三角形が、配列全体の上位 3 位には属さないが、セグメントのマージでは依然として上位 K 位に含まれる値を使用する場合です。 有効な三角形に参加できるすべての候補をカバーするのに十分な大きさの K が選択されるため、セグメント ツリーはそれらを保持します。 

もう 1 つのケースは、同じ位置で繰り返し更新される場合です。 更新のたびにルートへのパスが再構築され、先祖に古い値が残らないようにするため、リーフの置換は簡単です。 

最後のケースは、すべての値が小さいか同一である場合です。 すべてのトリプルがチェックされ、不等式が均一に不合格または合格するため、スキャン ロジックは依然として機能します。そのため、正しさは値の多様性に依存しません。
