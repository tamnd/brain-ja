 ## 問題の理解

 整数の範囲が与えられます$[L, R]$、そしてすべての整数に対して$x$この範囲では、その 10 進表現を見て、各桁が何回あるかを数えます。$0$に$9$が表示されます。 それを桁として数えましょう$i$なれ$F(x, i)$。 

これらの数字の頻度からスコアを定義します$G(x)$ゼロ以外のすべての周波数の二乗を合計することによって。 言い換えれば、すべての数字が貢献します$F(x,i)^2$少なくとも 1 回出現する場合$x$。 

タスクには 2 つの出力があります。 まず、次の数字がいくつあるか数えます。$[L, R]$持っている$G(x) \ge K$。 次に、次の合計を計算します。$G(x)$このようなすべての数値を法として計算したもの$998244353$。 

範囲は最大です$10^{15}$したがって、すべての数値を反復することは不可能です。 フルスキャンには最大で次の時間がかかります$10^{15}$これは実現可能な限界をはるかに超えています。 要素の数が膨大であるため、数値ごとの対数計算でも依然として遅すぎます。 

しきい値$K$と同じ大きさにすることができます$10^{18}$、これはすぐに次のことを示します。$G(x)$興味深い場合には、かなり大きくなるはずです。 以来$G(x)$は桁数の二乗和であり、その大きさは長さだけではなく、桁がどのようにクラスター化されているかによって決まります。 

単純な落とし穴は、問題をカウントのみの桁 DP として扱い、2 番目の集計、つまり条件を満たす数値に対するスコアの合計も計算する必要があることを忘れることです。 もう 1 つの微妙な問題は、頻度を 2 乗すると同じ数字の出現間に相互作用が生じ、カウントを注意深く追跡せずに数字を独立して扱うことができないことです。 

## アプローチ

 ブルートフォース手法では、範囲内のすべての数値を列挙し、桁の頻度を計算し、評価します。$G(x)$、カウンターを更新します。 各番号にかかる費用$O(\log x)$したがって、完全な複雑さは次のようになります。$O((R-L+1)\log R)$、範囲サイズが次の値に達すると、これは完全に実行不可能になります。$10^{15}$。 

重要な観察は、各数値は 1 桁ずつ記述できるということです。$G(x)$の複数の桁セットにのみ依存します$x$、彼らの命令ではありません。 これは数字 DP を示唆していますが、標準の数字 DP はカウントのみを追跡します。 ここでは、カウントの非線形関数、つまり二乗和も計算する必要があります。 

秘訣は、各桁がこれまでに何回使用されたかを追跡する状態で桁 DP を拡張することです。 桁数は桁数 (最大 16) で制限されるため、状態をコンパクトに表現できます。 遷移により、選択された桁の頻度が更新され、寄与率が増分的に更新されます。 重要な単純化は、数字を 1 回追加することです。$d$変化$F(d)^2$予測可能なデルタによる：$$(k+1)^2 - k^2 = 2k + 1.$$これにより、継続的な価値を維持することができます。$G(x)$正方形を最初から再計算する必要はありません。 

次に、厳しい制約と現在の桁周波数ベクトルの表現の両方を保持しながら、位置に対して桁 DP を実行します。 各 DP 状態は、有効な数値の数と合計の両方を集計します。$G(x)$。

 ## アルゴリズムのチュートリアル

 差分関数の数字DPを使用して問題を解決します$F(\le X)$、そして次の答えを計算します$[L, R]$接頭辞の減算を介して。 

### 1. DP 状態を定義する

 数値は、最上位から最下位まで 1 桁ずつ処理されます。 状態は次のように定義されます。 

現在の位置、接頭辞によって境界が定められているかどうか$X$、および各数字がこれまでに何回出現したかを表します。 の現在値も追跡します。$G(x)$。 

この構造が必要な理由は、$G(x)$ローカルな選択だけではなく、累積桁数に依存します。 

### 2. 次の桁を選択して遷移します

 各位置で、0 から 9 までの数字を試します。$d$からカウントを更新します。$k$に$k+1$。 スコアの変化は次のように計算されます。$$\Delta = (k+1)^2 - k^2 = 2k + 1.$$このデルタを現在の値に追加します。$G(x)$。 

この増分更新により、ステップごとに完全な二乗和を再計算する必要がなくなります。 

### 3. DP 集約を維持する

 各状態について、この構成で数値を形成する方法の数と累積された合計の 2 つの値を保存します。$G(x)$それらの道を越えて。 移行する場合は両方を更新します。 

遷移によって複数の数値が得られる場合は、寄与を線形に結合します。つまり、カウントが加算され、スコア合計が適切に累積されて加算されます。 

### 4. 先頭のゼロは慎重に処理してください

 先行ゼロは数値の実際の桁に対応しないため、最初の非ゼロ桁が配置された後にのみ桁数の更新が開始されるようにするか、先行ゼロを周波数に影響を与えない別個の DP モードとして扱う必要があります。 

この区別は非常に重要です。そうしないと、異なる長さの数値が誤ってマージされてしまうからです。 

### 5. 範囲の答えを計算する

 次のように計算します。$$F(R) - F(L-1)$$両方の必要な出力に対応します。 DP は次のように返します。 

有効な整数の数$G(x) \ge K$、およびそれらの合計$G(x)$価値観。 

### なぜ効果があるのか

 DP は、位置制約を考慮して、すべての有効な数字シーケンスを 1 回だけ列挙します。 周波数ベクトルにより、すべての状態が、への寄与を一意に表すことが保証されます。$G(x)$。 増分更新式により、スコアが二乗周波数の定義に従って一貫して蓄積されることが保証されます。 範囲内のすべての数値は DP ツリー内の 1 つのパスによって表され、すべてのパスが正しいスコアに寄与するため、最終的な集計は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    L, R, K = input().split()
    L = str(int(L) - 1)
    R = str(int(R))
    K = int(K)

    from functools import lru_cache

    def calc(s):
        n = len(s)

        @lru_cache(None)
        def dp(i, tight, started, cnt_tuple, cur_sum):
            # returns (ways, total_g)
            if i == n:
                if started and cur_sum >= K:
                    return (1, cur_sum)
                return (0, 0)

            res_cnt = 0
            res_sum = 0

            limit = int(s[i]) if tight else 9

            cnt = list(cnt_tuple)

            for d in range(limit + 1):
                ntight = tight and (d == limit)

                nstarted = started or (d != 0)
                ncnt = cnt[:]
                ncur = cur_sum

                if nstarted:
                    old = ncnt[d]
                    ncnt[d] += 1
                    ncur += 2 * old + 1

                ways, sm = dp(i + 1, ntight, nstarted, tuple(ncnt), ncur)
                res_cnt += ways
                res_sum += sm

            return (res_cnt, res_sum % MOD)

        return dp(0, True, False, tuple([0]*10), 0)

    c2, s2 = calc(R)
    c1, s1 = calc(L)

    print((c2 - c1) % MOD, (s2 - s1) % MOD)

if __name__ == "__main__":
    solve()
```この実装は、プレフィックスを介した数字 DP の直接変換です。 重要な詳細は、完全な周波数状態をエンコードする桁数のタプルベースのメモ化です。 遷移では増分平方更新を使用します。$2k+1$。 減算トリックは範囲を処理します$[L, R]$。 

微妙な点は、$L-1$これは、文字列を変換し、慎重に減算することによって行われます。 これにより、脆弱な方法で完全な大きな整数のデクリメントを手動で実装することが回避されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、「0007」のような状態に達するなど、DP 構造で先頭にゼロが付いている数値です。 アルゴリズムは、`started`フラグ。 最初の非ゼロの数字が配置されるまで、数字の頻度は更新されないため、先頭のゼロが異なる表現は同じ論理数値空間に収まります。 これにより、人為的なインフレが防止されます。$G(x)$。 

もう 1 つのケースは、増分更新を正しく蓄積する必要がある反復数字です。 たとえば、「111」では、最初の 2 つが貢献します。$1^2 + 1^2 = 2$、3 番目は寄与を増加させます。$3^2 - 2^2 = 5$を合計すると$7$。 DP 遷移は各ステップでこのデルタを正確に適用するため、累積された合計は定義と一致します。 

最後の微妙なケースは次のような場合です。$K$非常に大きいです。 民主党は依然として州を列挙しているが、`cur_sum >= K`すべての有効な数値が依然として 1 回だけ訪問されるため、この条件はほとんどの場合早期に失敗し、正確さに影響を与えることなく葉の部分で寄与を枝刈りします。
