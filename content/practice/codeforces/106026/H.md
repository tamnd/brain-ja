 ## 問題の理解

重要な制約は、$n \le 10^5$したがって、ステップごとに線形時間で繰り返し変換を適用するメソッドは、一度実行すると不可能になります。$x$大きいです。 再帰の単純なシミュレーションは、各ステップが前の完全な置換に依存するという意味で指数関数的に増加します。$O(n \cdot x)$はすでに実行不可能であり、単純に実装すると再帰構造はさらに悪化します。

## アプローチ

 強引なアイデアは、文字通り定義に従うことです。 から開始$a$、新しい配列を構築することで次の順列を繰り返し構築します$b$どこ$b_i = a_{a_i}$、交換してください$a$と$b$、このプロセスを繰り返します$x$回。 それぞれのステップにかかるのは$O(n)$したがって、総コストは次のようになります。$O(n \cdot x)$。 以来$x$まで可能です$10^{10}$、このアプローチは完全に実行不可能です。 

構造的な観察は、操作が任意の再計算ではなく、順列の合成であることに気づくことから生まれます。 順列を解釈すると$p$機能として$p(i)$、次に変換$F(a,b)$はまさに関数の構成です:$F(a,b)(i) = a(b(i))$。 したがって、再帰は次のようになります。$$G(a, x) = G(a, x-1) \circ G(a, x-1)$$自己作曲の繰り返しです。 それが重要です。各ステップは、合成中の順列を二乗します。 

それで$G(a,1) = a \circ a = a^2$、$G(a,2) = a^2 \circ a^2 = a^4$、そして一般的に:$$G(a,x) = a^{2^x}$$これにより、問題は反復二乗法から変換されます。$x$の順列を 2 のべき乗で累乗します。 指数自体は非常に速く増加しますが、指数を 2 の累乗として数値的に計算する必要はありません。 代わりに、効果を別の方法で観察します。つまり、各ステップで順列の「パワー」が 2 倍になります。 つまり、私たちは本質的にコンピューティングを行っているのです$a$に引き上げられた$2^x$ただし、指数がバイナリ形式でエンコードされている場合、順列で二乗を繰り返すことによって累乗をシミュレートする必要があるだけです。

 ## アルゴリズムのチュートリアル

 各順列をインデックスからインデックスへの関数として扱います。 繰り返し適用する操作は関数の合成であるため、この関数のべき乗を事前に計算します。 

1. 順列を表現する$a$機能として$f$、 どこ$f(i) = a_i$。 これにより、構成が明確に定義され、値と位置の間のあいまいさが回避されます。 
2. テーブルを事前計算する$up[k][i]$、 どこ$up[k]$順列の適用を表します$2^k$回。 初期化する$up[0] = a$。 これは関数の 1 つの応用に相当します。 
3. それぞれについて$k > 0$、 建てる$up[k]$作曲することで$up[k-1]$それ自体で:$up[k][i] = up[k-1][up[k-1][i]]$。 これが機能するのは、次の 2 つのアプリケーションがあるためです。$2^{k-1}$ステップが等しい$2^k$ステップ。 
4.恒等順列から始める$res(i) = i$、ゼロアプリケーションは何もしないからです。 
5.分解する$x$バイナリ形式に変換します。 ビットごとに$k$どこ$x$1 が付いているので適用します$up[k]$構成ごとの現在の結果:$res(i) = up[k][res(i)]$。 これは正確に蓄積されます$x$アプリケーション。 
6. 最終出力$res(i)$すべてのポジションに。 

なぜ各ステップが必要なのかは、半群を形成する順列構成の構造に由来します。 それぞれ$up[k]$ジャンプする事前計算されたマクロ操作です$2^k$再帰のステップを増やすことで、線形反復を置き換えることができます。$x$対数分解します。 

### なぜ効果があるのか

 重要な不変条件は次のとおりです$up[k]$は常に後に得られる順列を表します$2^k$元の変換の自己適用。 これは次の場合に当てはまります$k = 0$定義上。 それが当てはまると仮定すると$k-1$、それ自体と合成すると、次のサイズの 2 つの連続したブロックが得られます。$2^{k-1}$、これらは一緒になって正確に形成されます$2^k$アプリケーション。 順列の構成は結合的であるため、グループ化の順序は正確さに影響せず、二値分解には影響しません。$x$必要な力を正確に組み合わせることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    a = list(map(int, input().split()))
    x = int(input())

    LOG = x.bit_length() + 1

    up = [a[:]]
    for k in range(1, LOG):
        prev = up[k - 1]
        cur = [0] * n
        for i in range(n):
            cur[i] = prev[prev[i] - 1]
        up.append(cur)

    res = list(range(1, n + 1))

    k = 0
    while x > 0:
        if x & 1:
            new_res = [0] * n
            for i in range(n):
                new_res[i] = up[k][res[i] - 1]
            res = new_res
        x >>= 1
        k += 1

    print(*res)

if __name__ == "__main__":
    main()
```この実装では順列を 1 から始まる形式で保存するため、アクセスごとに 1 が減算されてから Python 配列にインデックスが付けられます。 これにより、合成を損なう可能性のある偶発的なオフバイワンエラーが回避されます。 

前処理ループは、前の層をそれ自体で繰り返し構成することにより、順列の累乗を構築します。 各合成ステップは、変換を 2 回適用することを直接変換したものです。 

最後のループではバイナリ リフトを適用します。$x$。 最初から繰り返し再計算するのではなく、対応するビットが設定されている場合にのみ事前計算されたジャンプを適用し、結果の順列を構成します。

 ## 特殊なケース

 いつ$x = 0$の場合、アルゴリズムはバイナリ リフティング ループに入ることはなく、すぐに恒等順列を返します。 たとえば、入力$a = [3,1,2]$、$x = 0$生成する$[1,2,3]$アプリケーションがゼロであることは変換が発生しないことを意味するため、これは定義と一致します。 

順列が同一である場合、すべての構成層は同一のままです。 前処理では、それ自体と同一性を合成すると再び同一性が得られるため、すべての$up[k]$アイデンティティを保ちます。 したがって、最終結果は、次の条件に関係なく常に同一性になります。$x$これは、アイデンティティを何度作成しても何も変わらないという事実と一致します。 

循環順列の場合、繰り返し合成はサイクルの繰り返し累乗として動作します。 例えば$a = [2,3,1]$、1 回適用すると回転し、2 回適用すると ID が返され、それに応じてより高いパワーが交互に表示されます。 リフティング構造はこれを正確に捉えます。$up[k]$はサイクルの正確なべき乗を表し、バイナリ分解により中間ステップを明示的にシミュレートすることなく正しい指数が再構築されます。
