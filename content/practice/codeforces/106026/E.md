 ## 解決策
 ## 問題の理解

 すべての要素が常に 4 ビット値である長い配列を維持しているため、各値は 0 から 15 の範囲内にあります。配列は範囲の更新を通じて時間の経過とともに変化します。また、場合によっては、範囲にわたる要約統計量を計算するように求められることがあります。 

最初の 2 つの演算は、任意の値を割り当てるのではなく、各値に固定関数を適用することで部分配列内のすべての要素を変換します。 値は常にサイズ 16 の小さな固定領域内にあるため、すべての更新は事実上、これら 16 の状態の順列になります。 3 番目の演算では、範囲を調べ、0 から 15 までの各値が何回出現するかを数え、これらすべてのカウントのビットごとの XOR を計算します。 

入力サイズは n と q の両方で 5x10^5 に達するため、クエリごとに各要素に触れるソリューションはすぐに失敗します。 クエリごとに 1 回の線形スキャンでも、最悪の場合は約 2.5×10^11 の演算が発生し、これは実行可能な制限をはるかに超えています。 これにより、対数時間での範囲更新と範囲クエリの両方をサポートするデータ構造が必要になります。 

素朴な考え方における微妙な問題は、各更新を整数の算術として扱い、値を直接変更することです。 たとえば、セグメントに「+1 mod 16」または「×2 mod 16」を繰り返し適用するには、すべての要素を訪問する必要があります。 もう 1 つの間違いは、カウントのみを維持しようとして、更新が加算的ではないことを忘れていることです。更新は値を再マッピングします。これは、カウントをインクリメントするのではなく並べ替える必要があることを意味します。 

単純なアプローチによる小さな失敗例を次に示します。 

入力:

 n = 3、配列 = [1、2、3]

 操作: [1, 3] に 1 mod 16 を追加します。 

正しい結果は [2, 3, 4] です。 値を再マッピングせずにカウントを増加させる単純な頻度のみの更新では、これを元の構造とは独立して cnt2、cnt3、cnt4 が増加するものとして誤って処理され、要素とその変換された値の間の対応が失われます。 

中心的な問題は、更新が位置ではなく値に作用することです。そのため、生の要素ではなく値の分布を維持する方向に進むことになります。 

## アプローチ

 直接シミュレーションでは、配列が維持され、各変換が要素ごとに適用されます。 これは正しいです。各操作はインデックスごとに明確に定義されていますが、すべての範囲更新には O(n) のコストがかかり、q が 5×10^5 までの場合、これは実行不可能になります。 

重要な観察は、どちらの操作でも値ドメインが非常に小さく、閉じていることです。 各要素は常に 16 個の値の 1 つであり、各操作は、{0..15} からそれ自体への決定論的マッピングを通じて値を変換します。 個々の値を保存する代わりに、各値がセグメント内に何回出現するかを保存します。 

ただし、範囲の更新を効率的にサポートする必要があります。 セグメント ツリーは、各ノードにサイズ 16 の周波数配列を格納することでこれを解決します。範囲の更新は、この周波数配列に適用される順列になります。 子をすぐに変更する代わりに、既存の変換関数と合成する遅延変換関数を保存します。 

これにより、各ノードが 16 要素のヒストグラムとこれらの 16 状態にわたる遅延置換を保持するセグメント ツリーを維持するという問題が軽減されます。 ノードのマージはヒストグラムの単純な追加ですが、遅延タグのプッシュは順列を構成し、それらを周波数ベクトルに適用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 値のヒストグラムと遅延順列を含むセグメント ツリー | O(q log n · 16) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各セグメント ツリー ノードを頻度配列で表します。`cnt[16]`、 どこ`cnt[x]`は何倍の値ですか`x`そのセグメントに表示されます。 また、現在保存されている値をどのように再マッピングするかを記述する 16 個の値の順列である遅延タグも維持します。 

1. 初期値の位置に 1 つの 1 を含む頻度配列を使用して各リーフ ノードを初期化して、セグメント ツリーを構築します。 これにより、あらゆる位置での正確な値の分布がエンコードされます。 
2. 各内部ノードについて、その子の配列を合計することによってその周波数配列を計算します。 これにより、互いに素なセグメントが値のマルチセット全体に独立して寄与するため、正確さが保たれます。 
3. 演算タイプ 1 の変換を順列 f(x) = (x + 1) mod 16 として定義します。演算タイプ 2 を g(x) = (2x) mod 16 として定義します。これらの関数はセグメント内のすべての要素に適用されるため、周波数ベクトルに対して順列が生じます。 
4. 範囲更新がセグメント ツリー ノードを完全にカバーする場合、その子には触れません。 代わりに、新しい変換を使用してノードの遅延置換を構成します。 これにより、変換を効率的に蓄積できるようになります。 
5. 順列 p をノードに適用するとき、カウントを移動して周波数配列を変換します: 0..15 のすべての x に対して new_cnt[p(x)] += cnt[x]。 これにより、変換を通じて値が明示的にプッシュされます。 
6. クエリ中に、子にアクセスする前に保留中の遅延置換をプッシュし、周波数配列が以前のすべての更新を確実に反映するようにします。 
7. タイプ 3 クエリの場合、セグメントの頻度配列を取得し、cnt[0] から cnt[15] までの XOR を計算して、必要な答えを生成します。 

これが機能する理由は、配列に対するすべての操作が各要素に独立して適用される関数であるためです。 関数合成はカウントを超えて分散するため、要素ごとまたは集約された周波数ベクトルごとに変換を適用できます。 セグメント ツリーにより、影響を受ける対数部分のみが再計算されることが保証されますが、遅延伝播により、各変換が関連する更新ごとにノードごとに 1 回だけ適用されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 4 * self.n
        self.cnt = [[0] * 16 for _ in range(self.size)]
        self.lazy = [list(range(16)) for _ in range(self.size)]
        self._build(1, 0, self.n - 1, arr)

    def _apply(self, v, perm):
        new = [0] * 16
        for i in range(16):
            new[perm[i]] += self.cnt[v][i]
        self.cnt[v] = new

    def _compose(self, a, b):
        return [b[a[i]] for i in range(16)]

    def _push(self, v):
        if self.lazy[v] != list(range(16)):
            for child in (v * 2, v * 2 + 1):
                self._apply(child, self.lazy[v])
                self.lazy[child] = self._compose(self.lazy[v], self.lazy[child])
            self.lazy[v] = list(range(16))

    def _build(self, v, l, r, arr):
        if l == r:
            self.cnt[v][arr[l]] = 1
            return
        m = (l + r) // 2
        self._build(v * 2, l, m, arr)
        self._build(v * 2 + 1, m + 1, r, arr)
        for i in range(16):
            self.cnt[v][i] = self.cnt[v * 2][i] + self.cnt[v * 2 + 1][i]

    def _update(self, v, l, r, ql, qr, perm):
        if ql <= l and r <= qr:
            self._apply(v, perm)
            self.lazy[v] = self._compose(perm, self.lazy[v])
            return
        self._push(v)
        m = (l + r) // 2
        if ql <= m:
            self._update(v * 2, l, m, ql, qr, perm)
        if qr > m:
            self._update(v * 2 + 1, m + 1, r, ql, qr, perm)
        for i in range(16):
            self.cnt[v][i] = self.cnt[v * 2][i] + self.cnt[v * 2 + 1][i]

    def _query(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.cnt[v]
        self._push(v)
        m = (l + r) // 2
        res = [0] * 16
        if ql <= m:
            left = self._query(v * 2, l, m, ql, qr)
            for i in range(16):
                res[i] += left[i]
        if qr > m:
            right = self._query(v * 2 + 1, m + 1, r, ql, qr)
            for i in range(16):
                res[i] += right[i]
        return res

n, q = map(int, input().split())
arr = list(map(int, input().split()))

st = SegTree(arr)

f1 = [(i + 1) % 16 for i in range(16)]
f2 = [(2 * i) % 16 for i in range(16)]

for _ in range(q):
    t, l, r = map(int, input().split())
    l -= 1
    r -= 1

    if t == 1:
        st._update(1, 0, n - 1, l, r, f1)
    elif t == 2:
        st._update(1, 0, n - 1, l, r, f2)
    else:
        res = st._query(1, 0, n - 1, l, r)
        ans = 0
        for x in res:
            ans ^= x
        print(ans)
```この実装は、すべてのノードが値の完全なヒストグラムを保存するという事実に依存しています。 の`_apply`関数は実際の値の再マッピングが行われる唯一の場所であり、純粋に周波数ベクトル上で動作します。 遅延タグは順列であり、`_compose`複数の更新が重なった場合に正しい順序が保証されます。 

微妙な点は、遅延タグをプッシュする場合は、子のカウントに変換を適用することと、順列を正しく構成することの両方が必要であることです。 複数の更新が重なった場合、正しい順序で構成できないと正確性が損なわれます。 

## 実用的な例

 小さな配列を考えてみましょう。 

イニシャル: [1、2、3、4]

 操作: [1, 3] に +1 mod 16 を適用します。 

| ステップ | セグメント | 周波数 (簡略化) |
 | --- | --- | --- |
 | イニシャル | すべて | cnt1=1、cnt2=1、cnt3=1、cnt4=1 |
 | アップデート後 | [1,3] | cnt2=1、cnt3=1、cnt4=1、cnt5=1 |

 [1,4] に対するクエリは、それぞれ 1 に等しい周波数 cnt2..cnt5 を返すため、XOR は 1 ⊕ 1 ⊕ 1 ⊕ 1 = 0 となります。 

これにより、更新が構造の変更ではなく値の置換として機能することが確認されます。 

2 番目の例では、2 つの変換の相互作用をテストします。 

イニシャル: [1、1、2]

 配列全体に +1 mod 16 を適用 → [2, 2, 3]

 ×2 mod 16 を適用 → [4, 4, 6]

 クエリ頻度は cnt4=2、cnt6=1、XOR = 2 ⊕ 1 = 3 です。 

これは、遅延伝播による変換の構成が逐次適用と一致することを示しています。

| スペース | O(n log n) | セグメント ツリー ノードには 16 要素の周波数配列が格納されます。

 ## 特殊なケース

 重要なエッジ ケースは、正しく構成されるはずの更新が重複して繰り返されることです。 たとえば、セグメントに +1 を 2 回適用することは、2 回の独立した部分書き換えではなく、+2 と同等である必要があります。 遅延順列構成では、マッピングを上書きするのではなく連鎖することでこれを保証します。 

もう 1 つのエッジ ケースは、部分更新後のフルカバー クエリです。 セグメント ツリーは、古い遅延値を誤ってプッシュしてはなりません。 そうしないと、カウントには部分的な変換のみが反映されます。 プッシュ操作により、下降するたびに、保留中のすべての置換が確実に実現されます。 

最後に、単一要素セグメントはリーフ処理の正確さをテストします。 リーフはワンホット周波数ベクトルで始まるため、初期化または更新アプリケーションでミスが発生すると、長さ 1 の間隔でのクエリの正確性が直ちに損なわれます。
