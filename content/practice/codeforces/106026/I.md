 ## 解決策
 ## 問題の理解

 平面内に 3 つの固定凸多角形が与えられます。 各ポリゴンは、3 つの点質量のいずれかを配置する必要がある領域を表します。 塊の位置は固定されていません。 各クエリについて、対応する各多角形の内部または境界上の任意の点を選択できます。 

各質量はその値に比例して寄与するため、最後に注目する点は、選択した 3 つの位置の重み付けされた重心です。 クエリ ポイントの場合、加重平均がクエリ座標と正確に等しくなるように、各多角形から 1 つのポイントを選択できるかどうかを判断する必要があります。 

したがって、幾何学的には、各ポリゴンは点塊として可能な位置のセットです。 重心は、固定された正の係数を持つ各セットの 1 つの点の線形結合です。 問題は、目標点がこの線形結合の画像内にあるかどうかになります。 

制約は大きく、各ポリゴンは最大 500,000 個の頂点を持つことができ、最大 500,000 個のクエリがあります。 これにより、完全なポリゴンに対するクエリごとのジオメトリック構築が即座に除外されます。 交差、三角形分割を再計算したり、クエリごとにエッジを列挙したりするものはすべてタイムアウトになります。 

主な問題は、これまでに回答が「はい」の数に応じて、XOR ベースのデコードを使用してクエリがオンラインになることです。 この依存関係は、前処理がクエリから完全に独立している必要があり、クエリ処理が厳密に対数または定数時間である必要があることを意味します。 

微妙なエッジ ケースは、凸状の縮退とマス スケーリングから生じます。 1 つのポリゴンが非常に小さい場合、または有効範囲内の単一の点であっても、重心は低次元の制約に崩壊します。 すべてのポリゴン内で完全な 2D 自由度を仮定する単純なソルバーは、非対称質量制約により実際には到達できない点に対して誤って「YES」と答えます。 

## アプローチ

 ブルートフォース解釈では、定義を直接シミュレートしようとします。 クエリごとに、各ポリゴン内の任意の点を選択し、重心の一次方程式が満たされるかどうかを解決しようとします。 ポリゴンを離散化したり、頂点を推論しようとしても、これは実行不可能になります。各ポリゴンには最大 5e5 の頂点があり、実行可能な領域は連続しているため、列挙することは不可能です。 

重要な観察は、凸性によって各ポリゴンが凸セットに変わり、重心操作が線形マップになるということです。 凸集合の加重和もまた凸集合となります。 より具体的に言うと、セットを定義すると$P_A, P_B, P_C$の場合、達成可能なすべての重心のセットは次のようになります。$$G = \frac{m_A P_A + m_B P_B + m_C P_C}{m_A + m_B + m_C}$$これは、スケーリングが後に続く凸集合のミンコフスキー和です。 スケーリングによってメンバーシップ クエリは変更されないため、問題は点が単一の凸多角形内にあるかどうかを確認することになります。$$S = m_A P_A + m_B P_B + m_C P_C$$したがって、スケーリング下で 3 つの凸多角形のミンコフスキー和を計算する必要があります。 重要な単純化は、凸多角形のスカラー乗算は座標をスケーリングするだけであり、凸多角形のミンコフスキー和は凸型のままであり、それらのエッジ方向をマージすることで計算できることです。 

各凸多角形は、角度によってソートされたエッジ ベクトルによって表すことができます。 凸多角形のミンコフスキー和は、2 つの凸包を結合するのと同様に、これらの循環エッジ シーケンスを結合することによって、頂点の合計に対して線形時間で構築できます。 

結果として得られる凸多角形を構築した後、各クエリは、三角形の向きに関する二分探索または境界角度に関する三分探索を使用して、対数時間での凸多角形内の点テストに帰着します。 

したがって、問題は、連続的な選択による幾何学的構築から、静的な凸包構築と点包含クエリに変換されます。

 | 最適 | O(n1 + n2 + n3 + q log n) | O(n1 + n2 + n3) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ポリゴンを対応する質量でスケールします。 ポリゴンのすべての頂点$P_i$を乗算します$m_i$。 これにより、重心条件が分数係数のない純粋なミンコフスキー和問題に変換されます。 
2. スケールされた 3 つの凸多角形のミンコフスキー和を計算します。 これは、最初に 2 つのポリゴンの合計を計算し、次に 3 番目のポリゴンを追加するか、3 つのエッジ方向シーケンスすべてを 1 つのパスでマージすることによって行われます。 ポリゴンは凸状であるため、エッジの方向は角度が単調になります。 
3. エッジの方向をマージしている間、現在のエッジ ベクトルを追跡するポインタを各ポリゴン内に維持します。 各ステップで、現在の 3 つの候補の中から最小角度のエッジ ベクトルを選択し、そのポリゴンのポインタを進めて、そのベクトルを累計ポリゴンに追加します。 
4. 合計された頂点の結果のシーケンスは、すべての可能なスケーリングされた重心を表す最終的な凸多角形の境界を形成します。 
5. 各クエリについて、以前の YES の答えに応じて XOR/加算ルールを使用して座標をデコードします。 このステップは純粋に実装の詳細ですが、幾何学的チェックの前に実行する必要があります。 
6. 方向に関する二分探索を使用して、構築されたポリゴンに対してデコードされたクエリ ポイントの凸ポリゴン内ポイント テストを実行し、ポイントが存在するセクタを見つけます。 

ステップ 3 の正しさは、凸多角形のエッジが周期的に順序付けられた場合、方向角の単調な進行に対応するという事実に依存します。 凸多角形のミンコフスキー和はこの単調な構造を維持するため、角度による貪欲な結合で境界エッジを見逃すことはありません。 

### なぜ効果があるのか

 到達可能な重心のセットは、正の定数でスケールされた凸セットのミンコフスキー和です。 凸集合のミンコフスキー和は凸であり、その境界は境界方向の和で構成されます。 各ポリゴンは凸状であるため、そのエッジ方向シーケンスは角度によって循環的にソートされます。 このようなシーケンスを結合する場合、結果として得られる境界は、これらの角度ソートされたシーケンスを結合することによって取得され、合計セットのサポート関数を正確に構築します。 これにより、内部点または境界点が失われないことが保証され、実行可能なすべての重心が構築された多角形内の点に対応します。 

凸多角形の点メンバーシップで十分です。凸性により、点が境界でサポートされた合計の凸状の組み合わせとして達成可能である場合、その点は構築されたハルの内部または境界に存在する必要があるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def read_poly(n):
    pts = [tuple(map(int, input().split())) for _ in range(n)]
    return pts

def scale(poly, m):
    return [(x * m, y * m) for x, y in poly]

def cross(a, b):
    return a[0] * b[1] - a[1] * b[0]

def sub(a, b):
    return (a[0] - b[0], a[1] - b[1])

def minkowski(A, B):
    n, m = len(A), len(B)

    def edges(P):
        return [(P[(i + 1) % len(P)][0] - P[i][0],
                 P[(i + 1) % len(P)][1] - P[i][1]) for i in range(len(P))]

    EA, EB = edges(A), edges(B)
    i = j = 0
    res = []

    cur = (A[0][0] + B[0][0], A[0][1] + B[0][1])
    res.append(cur)

    while i < n or j < m:
        eA = EA[i % n] if i < n else (0, 0)
        eB = EB[j % m] if j < m else (0, 0)

        if j >= m or (i < n and cross(eA, eB) >= 0):
            cur = (cur[0] + eA[0], cur[1] + eA[1])
            i += 1
        else:
            cur = (cur[0] + eB[0], cur[1] + eB[1])
            j += 1
        res.append(cur)

    return res

def point_in_convex(poly, p):
    def orient(a, b, c):
        return cross(sub(b, a), sub(c, a))

    n = len(poly)

    if orient(poly[0], poly[1], p) < 0:
        return False
    if orient(poly[0], poly[-1], p) > 0:
        return False

    l, r = 1, n - 1
    while r - l > 1:
        mid = (l + r) // 2
        if orient(poly[0], poly[mid], p) >= 0:
            l = mid
        else:
            r = mid

    return orient(poly[l], poly[l + 1 if l + 1 < n else 0], p) >= 0

mA, mB, mC = map(int, input().split())

A = read_poly(int(input()))
B = read_poly(int(input()))
C = read_poly(int(input()))

A = scale(A, mA)
B = scale(B, mB)
C = scale(C, mC)

AB = minkowski(A, B)
ABC = minkowski(AB, C)

q = int(input())
t = 0

for _ in range(q):
    x0, y0 = map(int, input().split())

    if x0 < 0:
        x = x0 + t
    else:
        x = x0 ^ t

    if y0 < 0:
        y = y0 + t
    else:
        y = y0 ^ t

    if point_in_convex(ABC, (x, y)):
        print("YES")
        t += 1
    else:
        print("NO")
```実装は、質量に基づいて各ポリゴンをスケーリングし、係数をジオメトリに埋め込むことで開始され、重心の計算が単純なメンバーシップ問題になるようにします。 Minkowski 関数は、外積を比較することによってエッジ ベクトルをマージします。これにより、角度を明示的に計算することなく、角度の順序が効果的に比較されます。 

凸点内チェックでは、標準のファンベースの二分探索が使用されます。 まず、クエリ点が最初の頂点によって定義された角度セクター内にあることを確認し、次に点が存在する必要がある三角形を絞り込みます。 

実装上の微妙な問題は、Minkowski マージでの循環インデックスの処理です。 このアルゴリズムでは、ポリゴンが反時計回りの順序で与えられることを前提としているため、エッジ ベクトルは循環シーケンスを形成します。 この仮定に違反すると、積間の順序付けが崩れ、マージされたハルが無効になります。 

## 実用的な例

 動作を説明するために、小さなポリゴンを含む単純化されたトレースを考えてみましょう。 

入力は、それぞれスケール済みの 3 つの単一三角形と 1 つのクエリで構成されます。 

| ステップ | アクション | 状態 |
 | --- | --- | --- |
 | デコード | 初期値 t = 0 | クエリは変更されていません |
 | スケール | 多角形に質量を乗算する | A、B、C スケール |
 | AB をマージ | A と B のミンコフスキー和 | 凸多角形AB |
 | ABC をマージ | Cを追加 | 最終的な凸多角形 |
 | クエリ | ポリゴン内のポイント | はい/いいえ |

 YES クエリの場合、点が凸包の十分内側にあると仮定します。 二分探索では、点がすべての対角線の同じ側に一貫してあるウェッジを特定するため、最後の三角形テストは成功します。 

NO クエリの場合、点が最初と最後の頂点光線によって形成される境界の外側にある場合、最初の方向テストは直ちに失敗します。 これは、凸包構造により、完全な横断を行わずに早期の拒否がどのように可能になるかを示しています。

 ## 特殊なケース

 すべてのポリゴンが単一の点に縮退する場合、1 つの重要なエッジ ケースが発生します。 この場合、ミンコフスキー和は 1 つの点に崩壊し、その点のみに到達できます。 エッジ リストが空になり、マージされたハルには頂点が 1 つだけ含まれるため、アルゴリズムはこれを自然に処理します。 

1 つのポリゴンに同一線上の頂点が繰り返されている場合、別の微妙なケースが発生します。 エッジ ベクトルにはゼロまたは重複した方向が含まれる可能性があるため、相互積比較では等価性を許容する必要があります。 実装では使用します`>= 0`平らなエッジに沿った決定的なマージを保証します。 

最後のエッジ ケースは、以前の YES の答えに依存する XOR デコードです。 カウンタの更新ミス`t`印刷後にのみ、後続のすべてのクエリが非同期化されます。 正しい動作は更新することです`t`YES の決定の直後に、次のクエリで正しい暗号化状態が使用されるようにします。
