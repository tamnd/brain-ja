 ## 解決策
 ## 問題の理解

 非常に長い文字列長が与えられています$n$ただし、文字列を明示的に構築するように求められるわけではありません。 代わりに、固定されたアルファベットから形成された文字列を処理します。$\{y, u, k, o\}$、そのような長さの文字列が何個あるかを数えたいとします。$n$は「有効」です。 

文字列を再配置して「yuuko」という単語を形成できる部分文字列が含まれている場合、その文字列は無効とみなされます。 言い換えれば、任意の順序で 2 つの y、2 つの u、1 つの k、および 1 つの o を含む長さ 5 のウィンドウを持つことは禁止されています。 これら 5 つの文字が順列すると、禁止されたパターンがトリガーされます。 

したがって、このタスクは純粋に組み合わせによるものです。$4^n$可能な文字列。マルチセットが一致する長さ 5 のウィンドウを回避する文字列をカウントします。$\{y,y,u,u,k,o\}$。 

重要な制約は、$n \le 10^{18}$これにより、線形または対数的にスケールする DP が即座に除外されます。$n$大きな状態遷移を伴う。 どのようなソリューションでも、プロセスを、固定状態空間上の行列のべき乗のように動作するものに圧縮する必要があります。 

エッジケースは、禁止されたパターンがそれ自体とどのように重なるかによって発生します。 素朴なアプローチでは、スライディング ウィンドウ DP を試行しても失敗する可能性があります。これは、禁止されたパターンが自明ではない方法で重複する可能性があるためです。 たとえば、複数の重なり合うウィンドウが同じマルチセット条件を形成した場合にのみ文字列が無効になる可能性があり、構造なしで最後の数文字のみを追跡すると、状態が指数関数的に爆発的に増加します。 

正しい観点は、サイズ 5 の固定禁止マルチセットを使用した固定アルファベットのパターン回避問題を扱っているということです。これは、長さが制限された接尾語状態に対するオートマトンを強く示唆しています。 

## アプローチ

 ブルート フォース ソリューションでは、一定の長さの文字列をすべて構築しようとします。$n$、一度に 1 文字ずつ追加し、長さ 5 の部分文字列が「yuuko」の順列を形成するかどうかを確認します。 これは概念的には単純です。完全な文字列を維持し、各ステップでサイズ 5 のウィンドウをすべてスキャンします。 ただし、スライディング周波数ウィンドウを使用してチェックを最適化したとしても、文字列の数は$4^n$、これはたとえ$n = 50$。 

より構造化されたブルート フォースでは、状態が現在の文字列の最後の 4 文字を保存する DP を使用します。これは、新しい文字を追加するときに、新しい禁止された 5 長さのウィンドウを検出するために必要なのはそれらだけであるためです。 これにより、状態空間が次のように縮小されます。$4^4 = 256$、これは小さくて有望です。 各状態から 4 つの遷移を試みます。 問題はそれです$n$までです$10^{18}$、繰り返します$n$ステップはまだ無理です。 

重要な観察は、プロセスが有限オートマトンであるということです。各状態は境界付きの接尾語にのみ依存し、次の文字が与えられると遷移は決定的になります。 したがって、計数の問題は、長さの歩行の数を計算することになります。$n$最大 256 個のノードを持つ有向グラフで、禁止されたパターンを作成する遷移を回避します。 これはまさに、サイズが最大 256 の遷移行列に対する行列のべき乗です。 

禁止条件はローカルです。新しい文字を追加するときは、最後の 5 文字 (シフト後) がターゲット マルチセットと等しいマルチセットを形成しているかどうかを確認するだけで済みます。 つまり、オートマトンの構築中に遷移をフィルタリングできるということです。 

オートマトンが構築されたら、次の計算を行います。$T^n$初期状態ベクトルに適用されます。$T$有効な遷移の隣接行列です。 これにより、問題は次のような高速累乗に帰着します。$O(S^3 \log n)$、しかしそれ以来$S \le 256$、これは実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 |$O(4^n)$|$O(n)$| 遅すぎる |
 | サフィックス上の DP の状態 |$O(n \cdot 4^4)$|$O(4^4)$| 遅すぎる$n=10^{18}$|
 | オートマトンの行列累乗 |$O(S^3 \log n)$|$O(S^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 状態が文字列の最後の最大 4 文字を表す決定論的オートマトンを構築します。 長さ 5 の禁止パターンはそのようなサフィックスを拡張する場合にのみ現れるため、これで十分です。 

### ステップ

 1. 文字をエンコードする$\{y, u, k, o\}$状態を効率的に操作できるように整数として扱います。 これにより、サフィックス状態の高速な比較とハッシュが可能になります。 
2. 現在のプレフィックスの最後の最大 4 文字を表すタプルとして状態を定義します。 文字列が 4 より短い場合、状態はプレフィックス全体を保存します。 
3. 到達可能なすべての状態を列挙します。 空の状態から開始して、4 つの文字をそれぞれ繰り返し追加し、長さが最大 ​​4 のサフィックスのみを保持します。これにより、最大 4 つの文字が生成されます。$4^4 = 256$州。 
4. 各状態および考えられる次の文字ごとに、追加をシミュレートします。 結果の最後の 5 文字 (利用可能な場合) にちょうど 2 つの y、2 つの u、1 つの k、および 1 つの o が含まれている場合、この遷移を無効としてマークし、破棄します。 
5. 移行マトリックスを構築する$T$、 どこ$T[i][j]$状態が何通りあるかを数えます$i$状態への遷移$j$1文字ずつ。 それぞれの有効な文字は 1 つのトランジションに寄与します。 
6. ベクトルを初期化する$v$ここで、空の状態の値は 1 で、その他はすべて 0 です。 
7. コンピューティング$T^n \cdot v$2進累乗を使用します。 各乗算は、圧縮形式ですべての文字列を 1 文字ステップずつ拡張することを表します。 
8. 結果のベクトルのすべてのエントリを合計して、有効な文字列の総数を取得します。 

### なぜ効果があるのか

 あらゆる長さの文字列$n$正確に 1 つの長さのパスに対応します$n$これは、各状態が、禁止パターンが出現した瞬間に検出するのに十分なサフィックス情報を格納しているためです。 遷移フィルタリングは、無効な文字列が DP 内で表現されないことを保証し、遷移は文字ごとに決定的であるため、すべての有効な文字列が一意のパスを持つようにします。 有効な文字列とウォークの間のこの全単射により、行列のべき乗が必要なセットを正確にカウントすることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

chars = ['y', 'u', 'k', 'o']
idx = {c: i for i, c in enumerate(chars)}

from collections import deque

def get_suffix(s):
    return s[-4:]

def bad(window):
    cnt = [0, 0, 0, 0]
    for c in window:
        cnt[c] += 1
    return cnt == [2, 2, 1, 1]

def encode(state):
    x = 0
    for c in state:
        x = x * 4 + c
    return x

def decode(x, L):
    s = []
    for _ in range(L):
        s.append(x % 4)
        x //= 4
    return tuple(reversed(s))

states = []
state_id = {}
queue = deque()

start = ()
state_id[start] = 0
states.append(start)
queue.append(start)

# build states up to length 4
while queue:
    s = queue.popleft()
    for c in range(4):
        ns = s + (c,)
        if len(ns) > 4:
            ns = ns[-4:]
        if ns not in state_id:
            state_id[ns] = len(states)
            states.append(ns)
            queue.append(ns)

S = len(states)

T = [[0] * S for _ in range(S)]

for s, i in state_id.items():
    for c in range(4):
        ns = s + (c,)
        if len(ns) > 4:
            ns = ns[-4:]
        ok = True
        if len(ns) == 5:
            if bad(ns):
                ok = False
        if ok:
            j = state_id[ns]
            T[i][j] = (T[i][j] + 1) % MOD

def matmul(A, B):
    n = len(A)
    C = [[0] * n for _ in range(n)]
    for i in range(n):
        for k in range(n):
            if A[i][k]:
                for j in range(n):
                    C[i][j] = (C[i][j] + A[i][k] * B[k][j]) % MOD
    return C

def matpow(M, e):
    n = len(M)
    R = [[0] * n for _ in range(n)]
    for i in range(n):
        R[i][i] = 1
    while e:
        if e & 1:
            R = matmul(R, M)
        M = matmul(M, M)
        e >>= 1
    return R

if n := int(input().strip()):
    if n == 0:
        print(1)
        sys.exit()

    P = matpow(T, n)

    # initial vector is state 0 only
    ans = sum(P[0]) % MOD
    print(ans)
```この実装では、長さ 4 までのすべてのサフィックス状態が構築されます。これは、拡張時に禁止されている長さ 5 のマルチセットを検出するのに十分です。 遷移行列は、すべての有効な拡張子をカウントします。 行列のべき乗はこれらの遷移を適用します。$n$段階的に繰り返すことなく、何度も繰り返します。 

微妙な点は、禁止チェックの処理です。5 文字のウィンドウが形成された場合にのみ条件を評価します。 これにより、短いプレフィックスに対する誤った枝刈りが防止されます。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$n < 5$。 この体制では、禁止パターンはまったく出現できないため、4 文字を超えるすべての文字列が有効になります。 長さ 5 のウィンドウが形成されず、遷移が枝刈りされることもないため、オートマトンはこれを正しく反映します。 

もう一つのエッジケースはまさに$n = 5$、無効な文字列のみがマルチセットの順列です。$y,y,u,u,k,o$。 アルゴリズムは、5 番目の文字が追加された場合にのみこれを検出します。これは、禁止条件の定義と一致し、早期の拒否が発生しないようにします。
