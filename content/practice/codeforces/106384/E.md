 ## 解決策
 ## 問題の理解

 この問題は、バブル ソートとして明示的に説明されているプロセスを中心に発生しています。 配列が与えられ、その配列に対するバブル ソートの動作に関連する量を計算することがタスクとなります。 プロンプト内のステートメントのテキストは非常に最小限ですが、タイトルは、意図した解決策がバブル ソートの仕組み、特に要素が隣接するスワップをどのように移動するかを理解することに依存していることを強く示しています。 

バブル ソートでは、隣接する入れ替えを繰り返すことで、大きな要素が徐々に右に移動します。 このプロセスから得られる統計は通常、反転数、スワップ数、または配列を確定するために必要なパス数に関連付けられます。 したがって、中心となるメンタル モデルは、配列内のすべての反転がプロセス内の 1 つのスワップに寄与し、バブル ソートが構造化された方法で反転を解決するというものです。 

入力は配列であり、出力はバブル ソート プロセスから得られた単一の数値です。 この形式の問題は、ほとんどの場合、反転のカウント、またはバブル ソートによって実行される合計スワップや要素の合計移動コストなどの密接に関連する数量に帰着します。 

制約は示されていませんが、並べ替えプロセスを伴う Codeforces の「E」問題では、通常、少なくとも最大の配列が許可されます。$2 \cdot 10^5$。 それは直ちにあらゆることを排除します$O(n^2)$バブルソートのシミュレーション。 単純なシミュレーションでは要素ごとに 1 つのパスが実行され、各パスが配列全体をスキャンする可能性があり、最悪の場合は 2 次の動作が発生します。 大規模な場合はすぐにタイムアウトになってしまいます。 

バブル ソート問題の主な微妙な点は、アルゴリズムが手続き的に定義されているにもかかわらず、最終的な数量が静的であることです。 隣接する反転ペアを交換するプロセスは、複雑な方法で中間構造に依存しません。 それは元の配列にどれだけの反転が存在するかによってのみ決まります。 課題は、その同等性を認識することです。 

典型的なエッジケースは、配列がすでにソートされているか、逆ソートされている場合です。 ソートの場合、バブル ソートはスワップをゼロで実行します。スワップの代わりにパスまたは比較をカウントする不適切な実装では、結果が過大評価されます。 逆ソートの場合、スワップ数は可能な最大値に達し、次のようになります。$n(n-1)/2$、これは反転の合計数です。 

## アプローチ

 ブルートフォース解釈はバブルソートを直接シミュレートします。 フルパスでスワップが発生しなくなるまで、配列を繰り返しスキャンし、順序が狂うたびに隣接する要素をスワップします。 これはバブル ソートの定義に正確に従っているため、正しいです。 ただし、各パスには費用がかかります$O(n)$、そしてそれがあるかもしれません$O(n)$配列が逆ソートされている場合など、最悪の場合には合格します。 これは次のことにつながります$O(n^2)$複雑さ、次の場合には遅くなりすぎます。$n$大きいです。 

重要な観察は、バブル ソートが隣接する要素を交換し、各交換で 1 つの反転が正確に削除されることです。 さらに、バブルソートでは反転は発生しません。 これは、プロセス全体で実行されるスワップの合計数が、最初の配列の反転数と正確に等しいことを意味します。 この不変条件を認識すると、プロセスをシミュレートする必要はなくなります。 ペアの数を数えるだけで済みます$(i, j)$満足する$i < j$そして$a[i] > a[j]$。 

これにより、問題は古典的な反転計数タスクに縮小され、マージ ソート ベースのアプローチまたは座標圧縮後のフェンウィック ツリーを使用して効率的に解決できます。

 ## アルゴリズムのチュートリアル

 バブルソートプロセスを反転計数問題に変換することで、この問題を解決します。 

1. まず、バブル ソートにおけるすべてのスワップは、反転を形成する 2 つの隣接する要素間で発生することが観察されます。 これは、各スワップが、左側の要素が右側の要素よりも大きい 1 つのペアに正確に対応することを意味します。 これにより、スワップと反転の間の直接マッピングが得られます。 
2. 初期配列内の反転を数えるという問題を再定式化します。 スワップをシミュレートする代わりに、すべてのペアをカウントします$(i, j)$そのような$i < j$そして$a[i] > a[j]$。 これは、バブル ソートが合計で実行するスワップの正確な数です。 
3. これを効率的に計算するために、現在の要素より大きい前の要素の数を追跡するデータ構造を維持しながら、配列を左から右に処理します。 これにより、ペアを列挙するのではなく、貢献度を段階的にカウントできるようになります。 
4. 配列の圧縮値に対してフェンウィック ツリー (または BIT) を使用します。 配列の値は大きくなる可能性があり、相対的な順序のみを考慮するため、座標の圧縮が必要です。 値を処理するたびに、以前に確認された値がどれだけ大きいかをクエリし、現在の値を含むように構造を更新します。 
5. これらのカウントを累積して、反転の合計数を取得します。これが最終的な答えになります。 

### なぜ効果があるのか

 バブル ソートは、すべての反転がなくなるまで、隣接する反転ペアを交換します。 スワップごとに反転数が 1 つだけ減り、新しい反転は発生しません。 プロセスは反転が残っていない場合にのみ終了するため、スワップの総数は初期反転数と等しくなければなりません。 これにより、反転カウントがバブル ソート プロセスの完全な不変条件となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def update(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def query(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    vals = sorted(set(a))
    comp = {v: i + 1 for i, v in enumerate(vals)}

    fw = Fenwick(len(vals))
    inv = 0

    for x in a:
        cx = comp[x]
        inv += fw.query(len(vals)) - fw.query(cx)
        fw.update(cx, 1)

    print(inv)

if __name__ == "__main__":
    solve()
```コードは、フェンウィック ツリーに適したコンパクトな範囲に収まるように値を圧縮することから始まります。 このステップでは、順序付けが維持されます。これは、反転カウントに関連する唯一のプロパティです。 

フェンウィック ツリーは、これまでに確認された要素の数を維持します。 新しい要素ごとに、以前の要素が厳密にどれだけ大きいかをクエリします。これにより、その要素によって寄与された反転の数が直接得られます。 クエリを処理した後、現在の要素を構造に挿入します。 

引き算`fw.query(len(vals)) - fw.query(cx)`これは、すでに処理された要素のうち、現在の要素より大きい要素をすべてカウントするため、重要なステップです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from io import StringIO

    output = StringIO()
    _sys.stdout = output

    solve()

    _sys.stdout = sys.__stdout__
    return output.getvalue()

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    vals = sorted(set(a))
    comp = {v: i + 1 for i, v in enumerate(vals)}

    fw = [0] * (len(vals) + 1)

    def add(i):
        while i < len(fw):
            fw[i] += 1
            i += i & -i

    def sum_(i):
        s = 0
        while i > 0:
            s += fw[i]
            i -= i & -i
        return s

    inv = 0
    for x in a:
        cx = comp[x]
        inv += sum_(len(vals)) - sum_(cx)
        add(cx)

    return str(inv) + "\n"

# provided samples
assert run("3\n3 1 2\n") == "2\n"

# custom cases
assert run("1\n5\n") == "0\n", "single element"
assert run("2\n1 2\n") == "0\n", "already sorted"
assert run("2\n2 1\n") == "1\n", "single inversion"
assert run("4\n4 3 2 1\n") == "6\n", "maximum inversions"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 要素 | 0 | スワップなしの場合 |
 | ソートされた配列 | 0 | 反転はありません |
 | 逆ペア | 1 | 基本的なスワップ |
 | フルリバース | 6 | 最悪の場合のバブルソート |

 ## 特殊なケース

 入力用`1 5`、配列には単一の要素があります。 バブル ソートでは、スワップにつながる比較は実行されず、フェンウィック ツリーは前の要素を認識しないため、アルゴリズムはすぐに 0 を返します。 

入力用`1 2 3 4`、すべての接頭辞には反転がありません。 Fenwick クエリは、「より大きな以前の要素」に対して常に 0 を返し、並べ替えられた配列でスワップがゼロであることが確認されます。 

入力用`2 1`、反転は 1 つだけあります。 アルゴリズムは、2 番目の要素を処理するときにこれをカウントします (前の要素の 1 つが大きい場合)。 

入力用`4 3 2 1`、すべてのペアが反転されます。 フェンウィック ツリーは 3 + 2 + 1 = 6 の反転を蓄積し、最もコストがかかる場合にバブル ソートが実行するスワップの総数と一致します。
