 ## 解決策
 ## 問題の理解

 このタスクでは、ノード間の一連の有向接続が与えられ、これらの有向エッジをたどることによって形成できる最長のパスを決定するように求められるグラフ問題について説明します。 ここでのパスとは、連続する各ペアが有向エッジで接続され、同じパスに沿ってノードが再訪問されることのない一連のノードを意味します。 

ステートメントは最小限ですが、「最長経路問題」という構造は、有向非巡回グラフに取り組んでいることを強く示唆しています。 サイクルが許可されている場合、無限にループする可能性があるため、一般に最長のパスは定義されません。 したがって、意味のある解釈は、グラフが明示的に DAG であるか、暗黙的に非循環であることが保証されているということです。 

入力はグラフ記述として理解でき、ノードは状態を表し、有向エッジは許可された遷移を表します。 出力は、有効な有向パス内のエッジの最大数 (またはノードから 1 を引いたものと同等) を表す単一の整数です。 

複雑さの観点から見ると、通常、ノードの数が十分に大きいため、すべてのパスを列挙するアプローチは不可能です。 パスの総当たり列挙は、各分岐点によって可能な継続数が増加するため、指数関数的に増加します。 ノード数が数十であっても、これは実現不可能となるため、ソリューションではパスを直接探索するのではなく、グラフ内の構造を利用する必要があります。 

グラフの構造に注意しないと、いくつかの特殊なケースが見落とされやすくなります。 グラフにエッジがまったくない場合、遷移が存在しないため、最長パスはゼロになるはずです。 グラフが 1 → 2 → 3 → 4 などの単一のチェーンである場合、答えは単純にそのチェーンの長さになります。 1 → 3、2 → 3、3 → 4 など、複数のパスがマージする場合、より微妙なケースが発生します。メモ化しない単純な DFS は部分問題を繰り返し再計算し、グラフが小さい場合でもタイムアウトになる可能性があります。 

もう 1 つの微妙な問題は、サイクル処理のない単純な DFS が安全であると仮定していることです。 入力に誤って 1 → 2 → 3 → 1 のようなサイクルが含まれている場合、単純な再帰は無限にループするか状態を繰り返し再訪し、トポロジー構造または訪問順序構造を明示的に保証しない限り、誤った結果が生成されます。 

## アプローチ

 この問題を考える最も直接的な方法は、すべてのノードから開始して、考えられるすべてのパスを列挙してみることです。 各ノードからすべての出力エッジを試し、それ以上の拡張が不可能になるまでパスを再帰的に拡張し、確認された最大長を追跡します。 

このアプローチは、グラフ内のすべての有効なパスを探索するため、正しいです。 ただし、そのコストはすぐに爆発します。 各ノードに 2 つの出力エッジがあるグラフでは、パスの数はステップごとに 2 倍になり、最悪の場合はおよそ O(2^n) の動作になります。 サブパスの繰り返しの再計算が非効率の主な原因です。ノードから始まる最長パスは、異なる先行ノードからそのノードに到達するたびに再計算されます。 

重要な構造上の観察は、ノードから始まる最長のパスがわかると、その値は決して変わらないということです。 グラフが非循環の場合、依存構造は半順序を形成します。つまり、トポロジーの逆順序で答えを計算できます。 各ノードは、順序付けにおいてそのノードの後に​​来るノードにのみ依存します。 これにより、問題が指数関数的分岐から DAG 上のシングルパス動的プログラミング問題に変換されます。 

dp[u] をノード u から始まる最長パスとして定義します。 各エッジ u → v について、u からのパスに 1 ステップと、v で始まる最適なパスを加えて拡張できます。したがって、dp[u] は、単に 1 + dp[v] のすべての近傍 v の最大値になります。 逆のトポロジー順序でノードを処理すると、必要なときにすべての dp[v] 値がすでに計算されています。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DFS 列挙 | O(2^n) | O(n) | 遅すぎる |
 | DAG 上の DP (トポソート) | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 次に、グラフを、依存関係が依存関係の前に処理される構造に変換します。 

1. まず、有向グラフの隣接リストを構築します。 この表現により、任意のノードのすべての発信エッジに効率的にアクセスできるようになります。 これがないと、すべての遷移でエッジ リスト全体を繰り返しスキャンする必要があり、不必要なオーバーヘッドが発生します。 
2. ノードのトポロジカルな順序を計算します。 この順序付けにより、すべての有向エッジ u → v に対して、順序内でノード v が u の前に現れることが保証されます。 このプロパティは、dp[u] を計算するときに、出力エッジのすべての dp[v] 値がすでにわかっていることが保証されるため、非常に重要です。 
3. すべての値をゼロに設定して dp 配列を初期化します。 各 dp[u] には、最終的に u から始まる最長のパスが格納されます。 
4. 逆のトポロジー順序でノードを反復します。 この方向は、ノードが直接到達できるすべてのノードの後に​​常にノードを処理するため、重要です。 
5. 各ノード u について、すべての出力エッジ u → v を検査します。dp[u] を dp[u] = max(dp[u], 1 + dp[v]) として更新します。 このステップは、u で始まるパスは最初にその出力エッジの 1 つを通過し、次に次のノードから最適に続行する必要があるという考えを捉えています。 
6. すべてのノードを処理した後、最終的な答えを dp の最大値として計算します。 これは、グラフ全体の最適な開始点を表します。 

### なぜ効果があるのか

 正確さは、DAG ではすべてのパスがトポロジー的な順序を尊重する、つまり後方依存性がないという事実に基づいています。 逆トポロジー順序でノードを処理する場合、すべての部分問題 dp[v] は、dp[u] で使用される前に完全に解決されます。 これにより、各 dp 値が 1 回だけ計算され、すでに最終化された結果のみに依存する安定した反復が作成されます。 すべての有効なパスはグラフ内のエッジに従う必要があり、すべての拡張は繰り返しを通じて 1 回だけ考慮されるため、計算された最大値は真の最長パスに対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    indeg = [0] * n

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        indeg[v] += 1

    q = deque([i for i in range(n) if indeg[i] == 0])
    topo = []

    while q:
        u = q.popleft()
        topo.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    dp = [0] * n

    for u in reversed(topo):
        for v in g[u]:
            dp[u] = max(dp[u], 1 + dp[v])

    print(max(dp) if n > 0 else 0)

if __name__ == "__main__":
    solve()
```実装は、隣接リストを構築し、標準のカーン アルゴリズム トポロジカル ソートを実行するための次数を計算することから始まります。 これにより、再帰が確実に回避され、大きなグラフであっても線形順序付けが保証されます。 

トポロジー順序が構築されたら、ノードの後続ノードがすべて処理されるように、逆の手順を繰り返します。 dp 遷移は、各ノードから始まる最長パスの定義を直接反映します。 

微妙な点は、dp が 0 に初期化されていることです。これは、出力エッジのないノードがパス長 0 に寄与していることを正しく表しています。 もう 1 つの重要な詳細は、パスはどこからでも開始できるため、固定ノードの dp ではなく、最大 dp 値として最終的な答えを計算することです。 

## 実用的な例

 ### 例 1

 入力:```
4 4
1 2
2 3
3 4
1 3
```トポロジー的順序は次のようになります。 

| ステップ | ノード | 前の dp | アップデート |
 | --- | --- | --- | --- |
 | 1 | 4 | [0,0,0,0] | なし |
 | 2 | 3 | [0,0,0,0] | dp[3]=1 |
 | 3 | 2 | [0,0,1,0] | dp[2]=1+1=2 |
 | 4 | 1 | [2,2,1,0] | dp[1]=max(1+dp[2],1+dp[3])=3 |

 最終的な答えは 3 です。 

これは、複数のパスがノード 3 でどのようにマージされ、動的プログラミングが計算されたサフィックスを再計算するのではなく正しく再利用するかを示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各ノードはトポロジカル ソートで 1 回処理され、各エッジは DP | で 1 回緩和されます。 
| スペース | O(n + m) | 隣接リスト、度数配列、dp 配列、トポ順序 |

 すべての演算はグラフ サイズが線形であるため、アルゴリズムは最大 2×10^5 のノードとエッジまでの一般的な制約内に快適に適合します。

    import sys
    from collections import deque

    n, m = map(int, sys.stdin.readline().split())
    g = [[] for _ in range(n)]
    indeg = [0] * n

    for _ in range(m):
        u, v = map(int, sys.stdin.readline().split())
        u -= 1
        v -= 1
        g[u].append(v)
        indeg[v] += 1

    q = deque([i for i in range(n) if indeg[i] == 0])
    topo = []
    while q:
        u = q.popleft()
        topo.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    dp = [0] * n
    for u in reversed(topo):
        for v in g[u]:

    return str(max(dp) if n > 0 else 0)

 ## 特殊なケース

 空のエッジ セットの場合、次のようになります。`n = 3, m = 0`の場合でも、アルゴリズムは有効なトポロジー順序を生成し、すべてのノードに 0 の dp 値を割り当てます。 遷移が存在しないため、最大値は正しくゼロになります。 

純粋なチェーンの場合、次のような`1 → 2 → 3 → 4`逆トポロジー処理により、各 dp がステップごとに正確に 1 つの追加エッジを蓄積し、正しい線形成長が生成されます。 

次のような分岐マージ構造の場合`1 → 3, 2 → 3, 3 → 4`、ノード 3 は dp[3] = 1 として 1 回計算され、両方の先行ノードが再計算せずにこの値を正しく再利用し、DAG 順序付けのメモ化効果を確認します。
