 ## 解決策
 ## 問題の理解

 私たちには一日の長さが与えられている`m`分と、それぞれが連続した時間間隔を占める、重複しない一連のタスク。 アレックスはシャワーを浴びたいと思っています`s`分であり、次の長さの時間の連続したブロックが少なくとも 1 つ存在するかどうかを判断する必要があります。`s`スケジュールされたタスクのいずれとも交差しません。 入力は複数のテスト ケースで構成され、それぞれに独自のタスクとパラメーターのリストが含まれます。`n`、`s`、 そして`m`。 出力は、そのようなブロックが存在する場合は単純な「YES」、存在しない場合は「NO」となります。 

制約により、最大で`2 * 10^5`すべてのテスト ケースにわたるタスクを実行し、毎日最大で次のタスクを実行できます。`10^9`長さは数分。 このため、1 日中毎分反復するソリューションは非常に遅すぎます。 各テスト ケースのタスク数が直線的に機能するアプローチが必要です。 

考慮すべきエッジケースは、最初のタスクの前の日の開始時、または最後のタスクの後の終わりに空きブロックが存在する場合です。 たとえば、次の場合`s = 3`、`m = 10`、そして唯一のタスクは`(5, 7)`、間隔`(0, 5)`シャワーを浴びるのに十分な長さです。`(7, 10)`。 連続するタスク間のギャップのみをチェックする不注意な実装では、これらの開始間隔と終了間隔を見逃す可能性があります。 もう一つの微妙なケースは次のような場合です。`s`ギャップの長さに正確に等しい。 ここでは、off-by-one エラーがよく発生するため、不等式は次のようになります。`>= s`。 

## アプローチ

 ブルートフォースアプローチでは、1 日のあらゆる分を考慮して、ブロックの長さが次のとおりであるかどうかを確認します。`s`無料です。 開始分ごとに`t`であるかどうかを確認します。`[t, t+s)`任意のタスク間隔と重複します。 これは論理的には正しいですが、最大で`10^9`実行可能な限界をはるかに超えた最悪の場合にチェックします。 

重要な点は、タスクが重複しておらず、開始時間順に並べ替えられているということです。 したがって、連続するタスク間の間隔、および最初のタスクの前日の開始と最後のタスクの後の一日の終了を確認するだけで十分です。 各ギャップは、1 つのタスクの終了と次のタスクの開始によって定義されます。 少なくとも隙間があれば`s`数分あれば、アレックスはシャワーを浴びることができます。 これにより、問題は線形スキャンに帰着します。`n`間隔が長くなり、複雑になります`O(n)`テストケースごとに。 このアプローチはシンプルかつ高速で、すべてのエッジケースを自然に処理します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m * n) | O(n) | 遅すぎる |
 | 最適 | O(n) | テスト ケースごとに O(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 テスト ケースごとに、次の内容を読んでください。`n`、`s`、 そして`m`。 
2. すべて読む`n`タスクをペアとして保存します`(l_i, r_i)`。 
3. 最初のタスクの前の間隔を確認します。 最初のタスクが開始される場合`l_1`、 そして`l_1 >= s`、「YES」を出力します。 
4. 連続したタスクを繰り返します。 タスク用`i`そして`i+1`、ギャップを計算します`l_{i+1} - r_i`。 このギャップがあれば`>= s`、「YES」を出力します。 
5. 最後のタスク後の間隔を確認します。 最後のタスクが に終了する場合、`r_n`、 そして`m - r_n >= s`、「YES」を出力します。 
6. これらのチェックがいずれも成功しなかった場合は、「NO」を出力します。 

機能する理由: タスクは重複しておらず、並べ替えられています。 シャワーの可能な場所はすべて、最初のタスクの前、2 つのタスクの間、または最後のタスクの後のいずれかです。 これらの各間隔の長さを確認することで、`>= s`、有効なウィンドウを見逃すことなく、あらゆる可能性をカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_shower(n, s, m, tasks):
    if tasks[0][0] >= s:
        return True
    for i in range(n - 1):
        if tasks[i+1][0] - tasks[i][1] >= s:
            return True
    if m - tasks[-1][1] >= s:
        return True
    return False

t = int(input())
for _ in range(t):
    n, s, m = map(int, input().split())
    tasks = [tuple(map(int, input().split())) for _ in range(n)]
    print("YES" if can_shower(n, s, m, tasks) else "NO")
```機能`can_shower`コアロジックを処理します。 最初に 1 日の始まりのギャップを確認し、次にタスク間のギャップを確認し、最後に 1 日の終わりのギャップを確認します。 この順序により、最初の可能な間隔で「YES」を返すことが保証され、不必要な計算が回避されます。 タプルと直接演算を使用すると、ソリューションがシンプルかつ効率的に保たれます。 を慎重に使用することで、off-by-one エラーを回避します。`>= s`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | タスクを 1 回スキャンし、連続するタスク間のギャップを計算します。 |
 | スペース | テスト ケースあたり O(n) | タスク間隔をタプルのリストとして保存します。 |

 合計すると`n`すべてのテスト ケース ≤ 2*10^5 で、これは 2 秒の制限時間内に十分収まります。 メモリ使用量は最小限です。

## 特殊なケース

 最初のタスクが正確に開始される場合`s`、間隔が短いため、アルゴリズムはすぐに「YES」を返します。`[0, l_1)`長さがある`l_1 >= s`。 最後のタスクの後に唯一のギャップが発生した場合は、最終チェックが行われます。`m - r_n >= s`それを捕らえます。 入力保証により、負のギャップまたは長さゼロのギャップは発生できません。`l_i > r_{i-1}`、しかし私たちはまだ使用しています`>= s`オフバイワンエラーを避けるため。 これにより、境界であっても正確さが保証されます。
