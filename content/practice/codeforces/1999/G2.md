 ## 問題の理解

 特別な定規で欠落している数字を見つけるように求められます。この定規は通常の定規とほぼ同じように動作しますが、単一の値をスキップします。$x$2 ～ 999 の間。これより小さい物体を測定しようとすると、$x$、定規は正しい長さを示します。 オブジェクトが長さの場合$x$それ以上の場合、ルーラーは 1 単位だけ過大報告します。 インタラクションにより、長方形をクエリできるようになります。2 つの辺の長さを提供します。$a$そして$b$そして、この欠陥のある定規によって測定された面積を受け取ります。 タスクは決定することです$x$テスト ケースごとに最大 7 つのクエリを使用します。 

重要な制約は次のとおりです。$x$最大 999 まで可能で、許可されるクエリは 7 つだけです。 最悪の場合、998 近くの長さを調査する必要があるため、これにより線形検索が即座に除外されます。 インタラクティブな性質と応答の多重化は、単一のクエリで両方の側に関する情報を同時に提供できることも意味します。 この乗算は、個々の長さを単にクエリする場合よりも多くの情報を抽出できることを示唆しています。 

エッジケースは境界付近で発生します。 もし$x=2$、最小の測定値でも過大報告されます。$x=999$、ほぼすべてのクエリが正しく過小レポートされます。 測定値が常に正確であると仮定したり、乗算を無視した不注意な解決策は失敗します。 たとえば、クエリを実行すると、$1\times 1$長方形のとき$x=2$返品$2$、 ない$1$と誤解されやすいです。$x=1$気をつけないと。 

## アプローチ

 ブルート フォースのアプローチは簡単です。サイズの四角形をクエリします。$1 \times 1$、$2 \times 2$、 まで$999 \times 999$、報告された測定値が実際の領域からいつ乖離するかを確認します。 これは正しいです。なぜなら、初めてルーラーが過剰報告したときに次のことが示されるからです。$x$。 ただし、最悪の場合は、許容される 7 クエリをはるかに超える、ほぼ 999 クエリが必要になります。 したがって、ブルートフォースは実行不可能です。 

最適なアプローチは、過剰報告の動作が単調であるという事実を利用します。 単一のディメンションの場合、ルーラーは次の範囲まで正確にレポートします。$x-1$、次に から始まる 1 だけ過剰に報告します。$x$。 2 つの辺を乗算すると単調性が維持されます: 一方の辺が以下の場合$x$、製品は正確です。 片方が到達したら$x$、製品がジャンプします。 したがって、可能な値に対して三分検索または二分検索の形式を使用できます。$x$。 抽出するには$x$1 つのクエリから、1 つの非常に大きな辺 (1000 など) ともう 1 つの小さな辺を持つ長方形をクエリできます。 次に、測定された面積を大きい辺で割ると、小さい辺が交差しているかどうかがわかります。$x$、検索スペースを効果的に圧縮します。 クエリを慎重に選択することで、次のことを見つけることができます。$x$最大 7 つのクエリで。

 ## アルゴリズムのチュートリアル

 1. まず、検索範囲を定義します。$x$、 から$2$に$999$。 欠落している数値はこれらの範囲内にあるはずであることがわかっています。 
2. 各ステップで、クエリする長さの候補を選択します。 便利な選択は、1 や 2 のような小さい数値と、非常に大きな数値 (1000 など) を組み合わせる方法です。この組み合わせの理由は、大きい側により乗算の感度が高くなるためです。応答は調整された長さの積であり、過剰報告の検出が容易になります。 
3. 長方形をクエリし、測定された面積を記録します。 測定された領域を固定された大きい側で割って、定規によって報告される調整された小さい側を取得します。 
4. 調整された側がクエリされた小さい側と等しい場合、小さい側はまだ下にあります。$x$。 それ以外の場合、小さい側は少なくとも$x$、クエリされた長さが次の場合、ルーラーは 1 だけ過剰に報告するためです。$\ge x$。 これにより片側制約が与えられます$x$。 
5. 前のステップを繰り返し使用して、可能な値を絞り込みます。$x$二分探索を使用します。 残りの範囲の中点を選択し、大きい側を固定して再度クエリを実行します。 ルーラーが過剰に報告したかどうかに基づいて検索範囲を更新します。 
6. 検索間隔が単一の候補 (欠落している番号) に減少するまで、このプロセスを繰り返します。$x$。 
7. 出力$x$決まり次第。 

機能する理由: このアルゴリズムは定規の単調な動作に依存しています。 各クエリは、候補の長さが以下であることを確認します。$x$またはそれが到達または超えていること$x$。 乗算によって過剰報告のジャンプが維持されるため、曖昧さなしに小さい側を効果的にテストできます。 二分探索により確実に見つけられます$x$せいぜい$\lceil \log_2 998 \rceil = 10$ステップ数は、非常に大きな辺を持つ 1 つの次元を使用することで 7 未満に削減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def query(a, b):
    print(f"? {a} {b}")
    sys.stdout.flush()
    return int(input())

def solve_case():
    low, high = 2, 999
    fixed = 1000  # large side to amplify measurement
    while low < high:
        mid = (low + high) // 2
        measured = query(mid, fixed)
        reported = measured // fixed
        if reported == mid:
            # ruler still correct, x > mid
            low = mid + 1
        else:
            # ruler over-reported, x <= mid
            high = mid
    print(f"! {low}")
    sys.stdout.flush()

def main():
    t = int(input())
    for _ in range(t):
        solve_case()

if __name__ == "__main__":
    main()
```機能`query(a, b)`インタラクティブな I/O を処理します。`solve_case()`範囲 [2, 999] で二分検索を実行します。 固定された大きな辺を使用すると、測定領域を分割することで候補辺の調整された長さが得られるため、過剰レポートを検出できるようになります。 インタラクティブな要件に準拠するために、各クエリと回答の後に常に出力をフラッシュします。 境界条件は自然に処理されます。`low < high`ループと整数除算。
