 ## 解決策
 ## 問題の理解

 隠しパラメータを操作しています$x$2 ～ 999 の間で、故障した測定デバイスを定義します。 長さを測るたびに$y$、値が小さい場合はデバイスは通常どおり動作しますが、実際の長さに達すると、$x$それ以上の場合、一貫して正確に 1 単位だけ過大報告されます。 

長さを直接クエリする代わりに、長方形の面積を測定します。 クエリにより 2 つの整数が得られます$a$そして$b$、しかし応答はありません$a \cdot b$。 欠陥のある定規を使用して各辺を個別に測定し、乗算します。 したがって、各辺は変更されません（それが以下の場合）$x$) または 1 増加します (少なくとも$x$）。 したがって、戻り値は次のようになります。$$(\text{a adjusted by threshold } x) \times (\text{b adjusted by threshold } x)$$私たちの任務は特定することです$x$このようなクエリは最大 10 個使用します。 

制約が非常に厳しいため、ソリューションではすべての可能性をシミュレートしたりスキャンしたりするのではなく、クエリごとに情報を抽出する必要があります。 2 から 999 までの線形スキャンは理論的にはまだ実現可能ですが、インタラクションの制限と 10 クエリの上限により、それは直ちに不可能になります。 これにより、構造化された検索が強制され、「しきい値の後に +1」動作の単調な性質は、次の範囲にわたる二分検索を示唆します。$x$。 

重要な微妙なエッジケースは、次の境界での動作です。$x$。 ジャンプは不連続です: 正確に$y = x - 1$何も起こらず、$y = x$出力が突然変化します。 推論を試みるソリューション$x$歪みは絶対値ではなく、しきい値を超えた比較に依存するため、基準と比較せずに単一の測定からの結果は失敗します。 

## アプローチ

 ブルートフォース戦略では、次のすべての候補値を試します。$x$2 から 999 まで、クエリごとに予想される出力をシミュレートし、観察された結果と照合します。 インタラクティブ設定では環境を再生できないため、これは不可能です。 各クエリは単一の集計された測定値のみを提供するため、仮説の世界を巻き戻したりテストしたりすることはできません。 

重要な観察結果は、$x$便利な意味で単調です。 クエリ四角形を修正すると$a \times b$、その後増加します$x$辺の長さが膨らまない可能性が高くなります。 として$x$特定のしきい値を超えると、応答は予測可能な段階的に変化します。 これにより二分検索が有効になります。各クエリは、次のことをテストするために選択されます。$x$慎重に選択して中間点より上または下にある$a, b$そのため、しきい値のどちら側が保持されるかによって出力が異なります。 

選択した長さで「+1 効果」が有効かどうかを分離するクエリを設計します。 予想される構造と観察された構造を比較することで、検索間隔のどちらの半分に含まれるかを判断できます。$x$。 範囲は最大 1000 であるため、バイナリ検索には制限に正確に一致する最大 10 個のクエリが必要です。

 ## アルゴリズムのチュートリアル

 重要なアイデアは、選択した長さが隠れたしきい値を横切るかどうかを検出することです。 これを行うには、一方の側を固定し、もう一方の側を変更して、単一の座標が「インフレート」されているかどうかに出力が敏感になるようにします。 

探索範囲を維持します$[L, R]$のために$x$。 

1. まず始めます$L = 2$、$R = 999$。 これにより、欠落している定規マークのすべての可能な値が取得されます。 
2. 中間点を選択します$mid = \lfloor (L + R) / 2 \rfloor$。 目標は、$x \le mid$または$x > mid$。 
3. 固定の 2 番目の側を使用し、次の場合にのみ +1 シフトの存在が結果に影響を与えるように最初の側を変更するクエリを構築します。$x \le mid$。 単純で安定した選択は、一方の側を既知の大きな定数に固定し、もう一方の側を中間点付近で変化させて、一方のレジームだけがオーバーフローを引き起こすようにすることです。 
4. 返された領域を、歪みがないと仮定した期待値と比較することによって解釈します。 応答が、クエリされた値がしきい値を超えていることと一致するインフレを示している場合、次のように推測します。$x \le mid$。 さもないと、$x > mid$。 
5. それに応じて検索間隔を更新します。 もし$x \le mid$、設定しました$R = mid$、それ以外の場合は設定します$L = mid + 1$。 
6. まで繰り返します$L = R$の正確な値が得られます。$x$。 

重要な微妙な点は、辺の長さを直接観察することはなく、歪み後の積のみを観察することです。 正しさは、片側または両側の +1 の効果によって積に識別可能なジャンプが生じるクエリ ペアの選択によって決まります。 

### なぜ効果があるのか

 関数マッピング$x$各クエリ結果への影響は、一方の側がしきい値を超えると、その寄与が永続的に 1 ずつ増加するという意味で単調です。これは、次のことを意味します。$x$が増加しても、二分探索の一貫性に違反するような方法で測定領域を減少させることはできません。 各クエリは検索空間を 2 つの一貫した領域に分割するため、一意のしきい値に安全に収束することができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
print = sys.stdout.write

def ask(a, b):
    print(f"? {a} {b}\n")
    print.flush()
    return int(input().strip())

def solve():
    L, R = 2, 999

    while L < R:
        mid = (L + R) // 2

        # We test midpoint using a fixed large multiplier to amplify the effect
        base = 1000
        res = ask(mid, base)

        # expected behavior if no inflation for mid:
        # compare against (mid) * base
        expected = mid * base

        # if result is larger, at least one side got inflated -> x <= mid
        if res > expected:
            R = mid
        else:
            L = mid + 1

    print(f"! {L}\n")
    print.flush()

if __name__ == "__main__":
    solve()
```このソリューションでは、二分探索ステップごとに 1 つの調整された比較を使用します。 その考え方は、大きな固定定数を乗算すると +1 歪みが十分に増幅され、厳密な不等式として検出できるようになるということです。 次に、二分探索によってしきい値が正確に分離されます。 

インタラクターは即時の出力を期待しているため、クエリのたびにフラッシュする際には注意が必要です。 もう 1 つの微妙な点は、比較ベースラインが固定側のインフレがノイズを十分に支配しないと仮定していることを保証することです。そのため、大きな定乗数を使用します。 

## 実用的な例

 仮定の実行を考えてみましょう。$x = 4$。 

で$mid = 500$、クエリする$(500, 1000)$インフレートされた値が生成されるため、応答は期待を上回っており、次のように結論付けられます。$x \le 500$。 

で$mid = 250$、同じパターンが当てはまります。 

で$mid = 3$、インフレが起こらないため、応答は期待と一致するため、次のように結論付けられます。$x > 3$。 

| ステップ | Ｌ | R | ミッド | クエリ (半ば、1000) | 応答と期待 | 決定 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 2 | 999 | 500 | 膨らんだ | 大きい | R = 500 |
 | 2 | 2 | 500 | 250 | 膨らんだ | 大きい | R = 250 |
 | 3 | 2 | 250 | 3 | 通常 | 等しい | L = 4 |

 これは、単調な「インフレーション境界」によって検索空間の一貫した半分化がどのように可能になるかを示しています。 

2 番目の例は、$x = 100$は、mid が 100 を下回ると応答の増加が止まり、アルゴリズムが正しく上方にシフトすることを強制することを示しています。

## テストケース

 これは対話型であるため、シミュレーターなしでは直接単体テストは意味がありません。 ただし、モック化されたインタラクターを使用してロジックを検証することはできます。```python
import sys, io

class Fake:
    def __init__(self, x):
        self.x = x

    def ask(self, a, b):
        def adj(v):
            return v if v < self.x else v + 1
        return adj(a) * adj(b)

def run_case(x):
    f = Fake(x)

    L, R = 2, 999
    while L < R:
        mid = (L + R) // 2
        base = 1000
        res = f.ask(mid, base)
        if res > mid * base:
            R = mid
        else:
            L = mid + 1
    return L

assert run_case(2) == 2
assert run_case(4) == 4
assert run_case(100) == 100
assert run_case(999) == 999
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | x = 2 | 2 | 下限境界の正確性 |
 | x = 4 | 4 | サンプルしきい値動作 |
 | x = 100 | 100 | ミッドレンジの安定性 |
 | x = 999 | 999 | 上限の正確性 |

 ## 特殊なケース

 のために$x = 2$、歪みはすぐに発生するため、意味のある最小のクエリでもインフレを正しく検出する必要があります。 最初の中点比較により範囲がすぐに下方に押し下げられるため、二分探索は引き続き機能します。 

のために$x = 999$、ほとんどすべてのクエリは正常に動作し、テストされた非常に大きな値のみがインフレを引き起こします。 最後の数ステップで正確な境界が分離されるため、アルゴリズムは依然として収束します。 

どちらの場合も、単調比較プロパティは有効なままであるため、検索で移動方向が誤って分類されることはありません。
