 ## 解決策
 ## 問題の理解

 私たちには根の生えた木が与えられています。 すべての頂点には、負ではない数値が含まれます。 

操作はリーフ以外の頂点に適用できます。 頂点を選択するとき$v$で値を増やします。$v$サブツリー内の頂点を 1 つずつ減らすと同時に、次の頂点を 1 つずつ減らします。$v$1つずつ。 操作後はすべての値が負でないままでなければなりません。 

目標は、有効な操作を任意の数実行した後、ルートの値を最大化することです。 

ツリーには以下が含まれます$2 \cdot 10^5$すべてのテスト ケースにわたる頂点。 値は次のように大きくできます。$10^9$。 操作の数も非常に膨大になる可能性があるため、操作を直接シミュレートするソリューションは不可能です。 単一の頂点であっても、何十億回も増加する可能性があります。 

合計に関する制約$n$に近いものが必要であることをすぐに示唆します$O(n)$または$O(n \log n)$テストファイルごとに。 サブツリーを繰り返し変更したり、操作を検索したりするアプローチは、非常に遅すぎます。 

この問題の最も危険な部分は、操作がツリーの異なるレベル間で相互作用することです。 

考慮する：```
1(0)
|
2(10)
|
3(0)
```素朴な考えは、頂点 2 が 10 ユニットすべてを上向きに寄付できるということです。 それは誤りです。 頂点 2 に対するすべての操作により、頂点 3 も同様に減少します。 頂点 3 は 0 から始まるため、頂点 2 は 1 つの操作も実行できません。 

正解は 10 ではなく 0 です。 

別の微妙なケースは次のとおりです。```
1(0)
|
2(5)
|
3(3)
```頂点 3 がボトルネックであるため、頂点 2 は最大 3 つの操作を実行できます。 その後、頂点 2 は 8 になり、頂点 3 は 0 になります。これで、頂点 2 は動作できなくなります。 

サブツリー内の合計だけを調べる不用意な解決策では、8 つのユニットすべてが最終的にルートに到達できるという誤った結論を下してしまいます。 

3 番目の重要なケースは葉です。```
1(0)
|
2(7)
```頂点 2 には子がないため、操作を実行できません。 ルートは頂点 2 から最大 7 ユニットを受け取ることができ、サブツリー内の変換は不可能です。 リーフは内部頂点とは異なる動作をするため、個別に処理する必要があります。 

## アプローチ

 ブルートフォース解釈は簡単です。 有効な操作を繰り返し検索して適用し、影響を受けるすべての頂点を更新し、ルートを改善できる操作がなくなるまで続けます。 

これは定義に正確に従っているため、正しいです。 残念ながら絶望的に遅いです。 1 回の操作でサブツリー全体に影響を与える可能性があり、コストがかかります$O(n)$。 さらに悪いことに、操作の数が次のように大きくなる可能性があります。$10^9$。 たとえ小さな木であっても、これは不可能になります。 

何かをより速く取得するには、個々の操作について考えるのをやめ、代わりに実現可能性について質問する必要があります。 

ルートが少なくとも value で終わるようにしたいとします。$X$。 

これが可能かどうか判断できますか?

 その質問に効率的に答えることができれば、最終的な答えは二分探索で見つけることができます。 

重要な観察は、オペレーションがリソースを上方に移動させるだけであるということです。 すべてのサブツリーは、その親に十分な値を提供できなければなりません。 これはボトムアップ DFS を示唆しています。 

ノードを検討してください$v$そして、その親がそれからいくらかの量を要求するとします。 

もし$v$葉であるため、提供できる最大量は次のとおりです。$a_v$。 

内部ノードの場合、状況はさらに興味深いものになります。 

仮定する$v$少なくとも次で終わる必要があります$need$その親で使用可能なユニット。 

もし$a_v \ge need$、 それから$v$すでに要件を満たしています。 余分な値は無害です。 

もし$a_v < need$、 それから$v$何らかの方法で作成する必要があります$need-a_v$追加ユニット。 唯一の方法は、次の場所で操作を実行することです。$v$。 

操作ごとに増えていきます$v$1 ずつ増加しますが、すべての子サブツリーから 1 ユニットを消費します。 したがって、$d$追加ユニット$v$すべての子サブツリーが少なくとも提供する必要があります$d$単位。 

これにより、非常にきれいな再発が得られます。 

させて$req(v)$は、すべての子が提供できる必要がある最小値を示します。 

もし$a_v \ge req(v)$、子供たちは満足するだけで十分です$req(v)$。 

もし$a_v < req(v)$、赤字は$req(v)-a_v$。 その不足を生成するには、子が最終的な要件と消費されたリソースの両方をカバーする必要があります。$$req(child)=req(v)+(req(v)-a_v)$$

$$=2 \cdot req(v)-a_v$$問題全体は、根から葉まで伝わる実現可能性のチェックになります。 

操作によってリソースが上方に転送されるため、ブルート フォースが機能します。 再帰が機能するのは、親でターゲット値をサポートするためにサブツリーが保証する必要があるリソースの量を正確に取得するためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 無制限、潜在的に数十億の操作 | O(n) | 遅すぎる |
 | 最適 | O(n log A) | O(n) | 承認済み |

 ここ$A$は回答範囲で、おおよそ次のとおりです。$10^9$。 

## アルゴリズムのチュートリアル

 ### 実現可能性のチェック

 ルートが値に到達できるかどうかを知りたいとします。$X$。 

ルートには最初に次の内容が含まれます$a_1$。 ツリーの残りの部分は提供する必要があります$$need = X-a_1$$追加ユニット。 

もし$need \le 0$、目標はすでに達成されています。 

それ以外の場合は、すべてのサブツリーが必要な量をサポートできるかどうかを再帰的に検証します。 

### 再帰的な意味

 ノードの場合$v$、DFSパラメータを定義します$need$。 

意味は次のとおりです。 

> サブツリー$v$少なくとも配信できなければなりません$need$ユニットをその親に追加します。 

### 内部ノード遷移

 1. もし$v$葉であるかどうかを返します$a_v \ge need$。 
2. もし$a_v \ge need$、 それから$v$すでに十分な値が含まれています。 

すべての子供は同じ要件を満たすだけで済みます$need$。 
3. もし$a_v < need$、 させて$$d = need-a_v$$赤字になる。 

ノード$v$生成する必要があります$d$での操作による追加ユニット$v$。 
4. このようなユニットごとに、子サブツリーごとに 1 ユニットのコストがかかります。 

したがって、各子供が提供する必要があります$$need+d =2\cdot need-a_v$$単位。 
5. すべての子がその新しい要件を満たしていることを再帰的に検証します。 

### 二分探索

 1. 検索範囲を次のようにします。$[a_1, 10^{18}]$。 
2. 中間点の場合$mid$、実現可能性 DFS を実行します。 
3. 可能であれば、下限を上方に移動します。 
4. それ以外の場合は、上限を下に移動します。 
5. 実現可能な最大値が答えです。 

### なぜ効果があるのか

 DFS の不変条件は次のとおりです。 

> ノードをパラメータでチェックする場合$need$、再帰によって、そのサブツリーが少なくとも$need$必要な内部操作が行われた後、ノード自体にユニットが配置されます。 

リーフの場合、使用可能な操作がないため、これは即時です。 

内部ノードの場合、それ自体の値がすでに要件を満たしている場合、子は補正する必要はありません。 それが不足した場合$d$、 その通り$d$そのノードでの操作が必要です。 このような操作はすべて、すべての子サブツリーから 1 つのユニットを消費するため、各子は追加のユニットをサポートする必要があります。$d$単位。 再発は必要かつ十分である。 

実現可能性述語は単調なので、値が$X$が達成可能であれば、さらに小さな値も達成可能です。 二分探索は有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 20)

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        children = [[] for _ in range(n)]

        parents = list(map(int, input().split()))
        for v in range(1, n):
            p = parents[v - 1] - 1
            children[p].append(v)

        def feasible(target):
            need_root = target - a[0]
            if need_root <= 0:
                return True

            INF = 10**18

            def dfs(v, need):
                if need > INF:
                    return False

                if not children[v]:
                    return a[v] >= need

                if a[v] >= need:
                    child_need = need
                else:
                    child_need = 2 * need - a[v]
                    if child_need > INF:
                        return False

                for to in children[v]:
                    if not dfs(to, child_need):
                        return False

                return True

            for to in children[0]:
                if not dfs(to, need_root):
                    return False

            return True

        lo = a[0]
        hi = 10**18

        while lo < hi:
            mid = (lo + hi + 1) // 2

            if feasible(mid):
                lo = mid
            else:
                hi = mid - 1

        print(lo)

solve()
```すべての DFS トラバーサルは親から子に進むため、ツリーは子の隣接リストとして保存されます。 

機能`feasible(target)`根を上げられるかどうかを確認します`target`。 数量`need_root`は、まさにルートの子から到着する必要がある量です。 

DFS は、上記で導出された繰り返しを実装します。 葉が基本ケースです。 内部ノードはすでに要件を満たしているか、すべての子サブツリーからのリソースを消費することで不足を補う必要があります。 

オーバーフローガードを使用`INF`重要です。 長い連鎖に沿って、繰り返しが必要な値を 2 倍にする可能性があります。 実際の答えは選択された二分探索範囲を超えることはありません。そのため、上記の要件はすべて満たされません。`10^18`安全に不可能なものとして扱うことができます。 

二分探索では、標準の上中点公式を使用します。`(lo + hi + 1) // 2`無限ループを避けるため。

# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    sys.setrecursionlimit(1 << 20)

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        children = [[] for _ in range(n)]

        p = list(map(int, input().split()))
        for v in range(1, n):
            children[p[v - 1] - 1].append(v)

        def feasible(target):
            need = target - a[0]
            if need <= 0:
                return True

            def dfs(v, req):
                if not children[v]:
                    return a[v] >= req

                child_req = req if a[v] >= req else 2 * req - a[v]

                for to in children[v]:
                    if not dfs(to, child_req):
                        return False
                return True

            return all(dfs(to, need) for to in children[0])

        lo, hi = a[0], 10**18

        while lo < hi:
            mid = (lo + hi + 1) // 2
            if feasible(mid):
                lo = mid
            else:
                hi = mid - 1

        out.append(str(lo))

    return "\n".join(out) + "\n"

 入力:```

1 2
```木：```

 入力:```

1 2
```木：```

### ルートの葉の子

 入力:```

```ルートは、頂点 2 に既に存在するリソースのみを受け取ることができます。頂点 2 はリーフであるため、操作を通じて追加の値を作成することはできません。 

DFS は、リーフに十分な値があるかどうかを単純にチェックします。 ルートの最大値は次のようになります。$0 + 7 = 7$、まさに正解です。
