 ## 解決策
 ## 問題の理解

 順列が与えられています`A`からの数字の`1`に`n`。 あらゆる価値観に対して`i`、私たちは数字を知っています`b[i]`。 この数値は、その前に出現する要素の数を表します。`i`順列内にあり、少なくとも`i + k`。 

条件は位置ではなく値自体に付加されます。 もし`i = 3`そして`k = 2`、それ以上の数値がいくつあるかを数えます。`5`前に現れる`3`。 

タスクは、これらすべてのカウントを満たす辞書編集上の最小の順列を再構築することです。 

制約`n ≤ 1000`は二次アルゴリズムにとって十分小さいです。 アン`O(n^2)`ソリューションは約 100 万の操作を実行しますが、これは制限時間内では取るに足らないものです。 キュービック ソリューションは、最悪の場合、10 億回の操作に近づき始め、Python では安全ではありません。 

やっかいな部分は、`b[i]`通常の意味での反転については説明しません。 各値は少なくとも数値のみを考慮します`k`それ自体よりも大きい。 つまり、近くの値間の関係は無関係です。 

よくある間違いは、すべての位置に可能な限り小さい未使用の数値を貪欲に配置することが常に機能すると考えることです。 考慮する：```
n = 4, k = 2
B = [0, 1, 0, 0]
```価値`2`少なくとも 1 つ前の番号が必要です`4`。 唯一の候補は、`4`、 それで`4`前に現れる必要があります`2`。 貪欲に小さな数字を最初に配置すると、次のように構築できます。```
1 2 3 4
```これは次の要件に違反します`2`。 

別の微妙なケースが現れるのは、`k`大きいです。```
n = 5, k = 5
B = [0, 0, 0, 0, 0]
```少なくとも、値にそれより前の数値を含めることはできません`i + 5`、そのような数字は存在しないからです。 すべての順列が条件を満たすため、辞書編集上の最小の答えは次のようになります。```
1 2 3 4 5
```不注意な実装では、実際には不可能な依存関係を強制しようとする可能性があります。 

もう 1 つの危険なエッジ ケースは、複数の値が同じ要件を持つ場合です。```
n = 5, k = 2
B = [0, 0, 0, 0, 0]
```ここで、すべての小さな数は、大きな先行要素がゼロであることを望んでいます。 辞書編集上、有効な順列の最小値は単純に昇順です。 値を間違った方向に処理すると、次のような有効ではあるが最小ではない答えが生成される可能性があります。```
3 1 4 2 5
```問題は、任意の順列を再構成することだけではなく、辞書編集順で最も小さい順列を再構成することです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての順列を生成し、対応する配列を計算します`B`、入力に一致する最初の順列を返します。 コンピューティング`B`1 つの順列にかかる`O(n^2)`なぜなら、すべての値について、その左側にあるものをすべてスキャンする可能性があるからです。 本当の問題は順列の数です。 たとえ`n = 10`、 がある`10! ≈ 3.6 million`可能性。 で`n = 1000`、網羅的な検索はまったく不可能です。 

これを改善するには、カウントが実際に何を意味するのかを理解する必要があります。 

値を見てみましょう`i`。 からの数字のみ`i + k`に`n`その数は重要です。 小さい値は無関係です。 させて：```
big(i) = count of numbers >= i + k
```正確には次のとおりです。```
n - (i + k) + 1 = n - i - k + 1
```そのような数字があるとき、`i + k ≤ n`。 

値`b[i]`それらの大きな数値のうち何個が前に出現するかを教えてくれます`i`。 残りの大きな数値は後に表示される必要があります。`i`。 

これは、要素間の順序制約のように見え始めます。 

はるかに有用な観点は、最大値から下方向に順列を構築することです。 

価値を処理するとき`i`、少なくともすべての値`i + k`はすでに知られています。 それらの相対位置は固定されています。 どこに挿入するかを決めるだけです`i`それらの中ではまさにそれが`b[i]`それらの大きな値はその前に残ります。 

あると仮定します`m`すでに大きな値が配置されています。 まさに`b[i]`そのうちの 1 つが前にある必要があります`i`、 それから`i`最初の直後に挿入する必要があります`b[i]`大きな値。 

間の値`i + 1`そして`i + k - 1`カウントにはまったく影響しないため、この条件ではそれらの位置は無関係です。 

これにより、クリーンな貪欲な構造が得られます。 

以下の値を処理します。`n`まで`1`。 それぞれの値について`i`、現在のシーケンスの慎重に選択した位置に挿入します。 小さい値を後で挿入するため、シーケンスの最初に小さい値を配置すると、可能な限り辞書編集上の順序が向上します。 

最終的な複雑さは次のようになります。`O(n^2)`、制約に簡単に適合します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n²) | O(n) | 遅すぎる |
 | 最適 | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のシーケンスから始めます。 
2. からの値を処理します。`n`まで`1`。 
3. 現在値について`i`、少なくとも次のすべてのすでに挿入された値を識別します。`i + k`。 

これらはまさに、`b[i]`。 
4. 現在のシーケンスを左から右にスキャンし、見つかった寄与値の数を数えます。 
5.挿入`i`最初の位置で正確に`b[i]`寄与する値はその前に残ります。 

もし`b[i] = 0`、置きます`i`できるだけ早く。 

もし`b[i] = 2`を挿入する前に、過去の 2 つの寄与値をスキップします。 
6. すべての値が挿入されるまで続行します。 
7. 最終シーケンスを出力します。 

### なぜ効果があるのか

 加工時`i`、少なくともすべての値`i + k`大きい数値から小さい数値へ処理するため、すでに配置されています。 小さい値は決して影響しません`b[i]`したがって、今後の挿入は無害です。 

挿入位置は正確にそれを保証します`b[i]`有効な貢献者は以前に滞在します`i`。 いつも入れるので`i`このカウントを維持しながらできるだけ早くすると、結果として生じる並べ替えは辞書編集的に最小限になります。 

重要な不変条件は次のとおりです。```
After processing values from n down to i,
all conditions for processed values are already permanently satisfied.
```今後の挿入には、より小さい数値のみが含まれるため、処理された値のカウントに寄与することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    b = list(map(int, input().split()))

    perm = []

    for i in range(n, 0, -1):
        need = b[i - 1]

        cnt = 0
        pos = len(perm)

        for j in range(len(perm) + 1):
            if cnt == need:
                pos = j
                break

            if j < len(perm) and perm[j] >= i + k:
                cnt += 1

        perm.insert(pos, i)

    print(*perm)

solve()
```配列`perm`部分的に構築された順列を格納します。 

すべての値が影響を与える可能性があるため、値を降順で処理します。`i`配置場所を決定する前にすでに存在している必要があります`i`。 

内側のループは、正確に生成する最も古い挿入ポイントを検索します。`b[i]`大きな先人たち。 このループ内の操作の順序が重要です。 まず、条件を満たす先行者の現在の数が必要な数と等しいかどうかを確認します。 その後初めて、別の要素を越えて進みます。 

これにより、1 つ違いのミスを回避できます。 仮定する`need = 0`。 最初の修飾要素の後ではなく、その前に挿入する必要があります。 

条件:```
perm[j] >= i + k
```定義を直接実装します。 十分に大きな値のみが寄与します。 

Pythonのリスト挿入は`O(n)`、しかし、`n ≤ 1000`、全体の複雑さは二次のままです。

 ## 特殊なケース

 次のことを考慮してください。```
4 2
0 1 0 0
```価値`2`少なくとも 1 つの以前の値が必要です`4`。 アルゴリズムは以下を処理します。```
4 -> [4]
3 -> [3, 4]
2 -> [3, 4, 2]
1 -> [1, 3, 4, 2]
```のみ`4`に貢献する`2`、そしてそれは前に表示されます`2`なので、条件は満たされています。 小さな数字を最初に置く単純な貪欲なアプローチは失敗します。 

次に、次のことを考えてみましょう。```
5 5
0 0 0 0 0
```あらゆる価値観に対して`i`、しきい値`i + 5`を超える`n`。 貢献者は存在しません。 挿入中、アルゴリズムはすぐに次のことを認識します。`cnt == need == 0`そして各値を先頭に挿入します。```
[5]
[4,5]
[3,4,5]
[2,3,4,5]
[1,2,3,4,5]
```最終的な順列は辞書編集的に最小限です。 

最後に、次のことを考慮してください。```
5 2
0 0 0 0 0
```すべての値は、大きな先行要素がゼロであることを必要とします。 アルゴリズムは常に、最初の条件を満たす大きな要素の前に各値を挿入します。 これにより、可能な限り小さい数値が前面に押し出され、次の結果が得られます。```
1 2 3 4 5
```別の有効ではあるが辞書編集的により大きな順列の代わりに。
