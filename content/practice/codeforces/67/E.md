 ## 解決策
 ## 問題の理解

 単純な多角形が時計回りにリストされています。 最初の 2 つの頂点は水平エッジを形成します`AB`、他のすべての頂点は厳密にそのエッジの同じ側にあります。 Along the segment`AB`、すべての整数座標点が監視塔の可能な場所です。 

監視塔の位置としては`P`の上`AB`、多角形内のすべての点がから見える必要があります。`P`。 可視性とは、からのセグメントを意味します。`P`ターゲット ポイントへの距離は、端点を除いてポリゴンの内側に留まります。 ポリゴンはシンプルなので、`P`が境界上にある場合は、すべてのポリゴンのエッジが境界上から見えるようにするだけで十分です。`P`。 

タスクは、上にある整数点の数をカウントすることです。`AB`ポリゴン全体を見ることができます。 

ポリゴンには最大 1000 個の頂点があります。 このサイズは 2 次幾何学アルゴリズムには十分小さいですが、高価な浮動小数点演算を伴う 3 次アルゴリズムには十分ではありません。 解決策`O(n^2)`完全に安全です。 平`10^6`方向性テストは、制限内では簡単です。 難しいのはパフォーマンスではなく、幾何学的正確さです。 

重要な幾何学的制約は、以下のすべての頂点が`A`そして`B`～の同じ側に横たわる`AB`。 つまり、ポリゴンはフェンスの下または上にぶら下がっている「山」のように動作します。 この構造により、多くの視認性が困難なケースが排除され、問題が直線上の区間交差に変わります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

フェンスの 1 つの端点からのみ 1 つのエッジがかろうじて見える多角形について考えてみましょう。```
4
0 0
10 0
9 5
1 5
```あらゆる点で`AB`多角形が凸面であるため、ここでは機能します。 厳密な不等式を使用した不用意な実装は、エンドポイントを誤って拒否する可能性があります。 

次に、非凸多角形を考えてみましょう。```
5
0 0
10 0
10 10
5 3
0 10
```近くの内側のへこみ`(5,3)`多くの位置からの視界を妨げます。 サンプリングされたポイントの単純な「ポリゴンの内側」チェックでは、ターゲットに到達する前にセグメントが境界を横切るために表示が失敗することを見逃してしまいます。 

もう 1 つの微妙なケースは、可視性が整数座標で正確に変化する場合に発生します。```
5
0 0
6 0
6 6
3 1
0 6
```ここで、有効な間隔の境界は有理的です。 浮動小数点計算による丸め誤差により、カウントが 1 ずれる可能性があります。 整数演算の方がはるかに安全です。 

最後の重要なコーナーケースは、ポイントがまったく機能しない場合です。 一部のポリゴンには反射頂点が含まれており、その隣接エッジがあらゆる可能な視点をブロックします。`AB`。 正しい答えは、`0`、アルゴリズムは空の区間の交差をきれいに検出する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての整数点を列挙します`AB`。 候補ポジションごとに`P`、すべてのポリゴン エッジまたはすべてのポリゴン頂点の可視性をテストします。 からのセグメント`P`点への接続は、終点を除いてポリゴンの境界を越えない場合に有効です。 

これが機能するのは、単純なポリゴンの可視性をセグメント交差テストを使用してチェックできるためです。 問題は仕事量です。 フェンスの長さが最大の場合`10^6`の場合、候補ポジションは 100 万を超える可能性があります。 位置ごとに、すべてのエッジのコストに対して可視性をチェックする`O(n^2)`最悪の場合。 それが周りに爆発する`10^12`操作。 

ボトルネックは、すべての整数点を個別にスキャンすることです。 ジオメトリ自体は、より良いものを示唆しています。つまり、可視性の制約がフェンスに沿って連続的に変化します。 

1 つのポリゴン エッジを取得します`E`。 どの位置から`AB`エッジ全体が見えていますか？ ポリゴンは片側にあるため、`AB`、ブロッキング条件は、エッジの端点を通過する光線からのみ発生します。 表示される位置は 1 つの間隔を形成します。`AB`。 

これは重要な観察です。 各ポイントを個別にチェックする代わりに、各ポリゴン エッジによって寄与される有効な間隔を計算し、すべての間隔と交差します。 最後の交差点には、ポリゴン全体が見えるタワーの位置が正確に含まれています。 

ジオメトリは、反射頂点の場合に特にきれいになります。 凸状の頂点は制限を作成しません。 反射頂点は、2 つの隣接するエッジによって境界付けられる可視円錐を作成します。 これらのコーンを水平フェンスと交差させると、許容される間隔が得られます。`x`コーディネート。 

グローバル間隔を計算した後`[L, R]`、答えは単純に、そのセグメントに属する整数の数です。`AB`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O( | AB | · n²) |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 幾何学的セットアップ

 フェンスを仮定します`AB`水平線上にあります`y = Y`。 他のすべての頂点は同じ側にあるため、すべての頂点がフェンスの下にくるようにポリゴンの向きを変えることができます。 それらが上にある場合は、すべてを乗算して座標を垂直に反映します。`y`による値`-1`。 

有効な監視塔の位置は整数です`x`の間の座標`x1`そして`x2`。 

### 反射頂点からの可視性制限

 凸状の頂点が視界を妨げることはありません。 反射頂点のみが重要です。 

反射頂点の場合`V`、隣接する頂点を次のようにします。`U`そして`W`。 隣接するエッジの間違った側にある視点は、ポリゴンに到達する前にポリゴンの外側を見ることになります。`V`。 

目に見える視点と目に見えない視点の間の境界は、まさに隣接するエッジの 1 つを延長した線です。 

隣接するエッジごとに、その支持線がフェンスと交差する場所を計算します。`y = Y`。 それは制限を与えます`x`フェンスの上でコーディネートします。 

エッジの向きに応じて、視点はその交差点の左側または右側に留まる必要があります。 

### 反射頂点の検出

 頂点が時計回りにリストされ、ポリゴンがフェンスの下にあるため、再帰頂点の外積は正になります。```
cross(V-U, W-V) > 0
```凸状の頂点は無視されます。 

### 間隔制約の計算

 各反射頂点について:

 1. 優位に立つ`(U,V)`。 
2. ラインが届くまで伸ばします。`y = Y`。 
3. 対応する値を計算します。`x`。 
4. 有効な視点が左側にあるのか右側にあるのかを決定します。 

エッジに対して繰り返します`(V,W)`。 

これら 2 つの半平面の交差により、頂点によって課される可視間隔が決まります。`V`。 

この間隔をグローバル範囲に交差させます`[L,R]`。 

### 最終的なカウント

 すべての反射頂点を処理した後:

 1. 間隔を実際のフェンス セグメントにクランプします。 
2. 間隔内の整数を数えます。 

間隔が空の場合は戻ります`0`。 

### なぜ効果があるのか

 視点は、視点からあるポリゴン点までのセグメントがポリゴンから出た時点で無効になります。 すべての頂点がフェンスの片側にある単純なポリゴンでは、最初の障害物は常に反射頂点に表示されます。 

各反射頂点は、くさび形の禁止領域を作成します。 このウェッジをフェンスと交差させると、単一の間隔制約が生成されます。 ポリゴンの境界が局所的に視点から離れる方向に曲がるため、凸状の頂点は障害物を作成しません。 

アルゴリズムはこれらすべての間隔制約を正確に計算し、それらを交差させます。 ポイントは、すべての反射頂点の可視ウェッジの内側に留まる場合に限り、交差点を通過できます。これは、ポリゴン全体を見るのと同じです。 

## Python ソリューション```python
import sys
from fractions import Fraction

input = sys.stdin.readline

def intersect_x(a, b, Y):
    x1, y1 = a
    x2, y2 = b

    if y1 == y2:
        return Fraction(x1, 1)

    return Fraction(x1 * (y2 - Y) + x2 * (Y - y1), y2 - y1)

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def solve():
    n = int(input())
    p = [tuple(map(int, input().split())) for _ in range(n)]

    Y = p[0][1]

    # Make polygon lie below the fence
    if p[2][1] > Y:
        p = [(x, -y) for x, y in p]
        Y = -Y

    x1 = p[0][0]
    x2 = p[1][0]

    if x1 > x2:
        x1, x2 = x2, x1

    L = Fraction(x1, 1)
    R = Fraction(x2, 1)

    for i in range(n):
        u = p[(i - 1) % n]
        v = p[i]
        w = p[(i + 1) % n]

        c = cross(v[0] - u[0], v[1] - u[1],
                  w[0] - v[0], w[1] - v[1])

        # reflex vertex
        if c <= 0:
            continue

        xv1 = intersect_x(u, v, Y)
        xv2 = intersect_x(v, w, Y)

        left = min(xv1, xv2)
        right = max(xv1, xv2)

        L = max(L, left)
        R = min(R, right)

    if L > R:
        print(0)
        return

    lo = (L.numerator + L.denominator - 1) // L.denominator
    hi = R.numerator // R.denominator

    ans = max(0, hi - lo + 1)
    print(ans)

solve()
```最初のステップでは、ポリゴンの方向を正規化します。 編集上の推論では、すべての頂点がフェンスの下にあると想定しています。 垂直方向に反射すると、ジオメトリが単純化されながら、すべての可視性関係が変更されません。 

の`cross`関数は反射頂点を識別します。 多角形は時計回りであるため、正の外積は内角が 180 度を超えることを意味します。 

の`intersect_x`関数は、ポリゴンのエッジがフェンス ラインと出会う場所を計算します。 使用する`Fraction`浮動小数点精度のバグを回避します。 最終的な答えは正確な整数の境界に依存するため、これは重要です。 

グローバル間隔`[L, R]`フェンス全体として始まります。 すべての反射頂点が縮小します。 間隔が空になると、有効な監視塔は存在しません。 

整数をカウントするステップでは、有理端点を慎重に処理する必要があります。 必要なものは次のとおりです。```
ceil(L) ≤ x ≤ floor(R)
```分数の分子と分母を使用すると、丸めミスを回避できます。
