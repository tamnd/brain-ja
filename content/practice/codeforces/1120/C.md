 ## 解決策
 ## 問題の理解

 文字列と 2 つのコストが与えられます。 

最初の操作では、次のコストで 1 文字だけをエンコードできます。`a`。 

2 番目の操作では、空でない部分文字列を固定コストでエンコードできます。`b`ただし、その部分文字列がすでにエンコードされた文字列の一部のどこかにすでに出現している場合に限ります。 

文字列は左から右に処理する必要があります。 すべての位置で、次の文字を直接書き込むかどうか、または前に処理されたプレフィックスにすでに存在するより長い部分文字列をコピーできるかどうかを決定します。 

目標は、文字列全体のエンコードに必要な総コストを最小限に抑えることです。 

文字列の長さは最大 5000 です。これにより、大きな定数を持つ指数関数や 3 次関数さえも即座に除外されます。 動的プログラミング ソリューションは大まかに言うと、$O(n^2)$仕事は通常は受け入れられます$n=5000$、 その間$O(n^3)$必要なため、遅すぎるでしょう$1.25 \times 10^{11}$最悪の場合の運用。 

難しい部分は、位置ごとに、すでに処理されたプレフィックスから部分文字列をコピーできる長さを決定することです。 部分文字列を繰り返し比較する単純な実装では、簡単に 3 次的になってしまいます。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
3 3 1
aba
```最後`'a'`以前にすでに登場しているため、コピーされる可能性があります。 最適な答えは`7`、 ない`9`。 

考慮する：```
4 1 100
aaaa
```コピーするのは非常に高価です。 繰り返される部分文字列がどこにでも存在するとしても、最適な答えは次のとおりです。`4`、各文字を個別に書くことで得られます。 

考慮する：```
4 10 1
aaaa
```今ではコピー品も安く手に入るようになりました。 最適な構築の 1 つは次のとおりです。```
"a"  -> 10
"a"  -> 1
"aa" -> 1
```総コスト`12`。 

よくある間違いは、コピーされた部分文字列が以前に選択されたブロックとして出現したに違いないと仮定することです。 この問題では、それが既にエンコードされたプレフィックスの部分文字列であることのみが必要です。 プレフィックス内に出現するものであれば十分です。 

もう 1 つのよくある間違いは、将来の文字と重複するコピーを許可することです。 位置をエンコードする場合`i`、ソースオカレンスは、すでに処理されたプレフィックス内に完全に存在する必要があります。`s[0..i-1]`。 

## アプローチ

 最も直接的な動的プログラミングのアイデアは、`dp[i]`最初のコードをエンコードするための最小コストを示します`i`文字。 

位置から`i`、いつでも 1 つの文字をエンコードして、次の場所に移動できます。`i+1`費用がかかる`a`。 

また、次から始まるすべての可能な部分文字列を試すこともできます。`i`、以前に出現したかどうかを確認し、出現した場合は、コストを含むその部分文字列の末尾に直接ジャンプします。`b`。 

すべての有効なエンコーディングはプレフィックス長間の遷移のシーケンスに対応するため、この DP は正しいです。 

問題は、部分文字列がすでに出現しているかどうかを確認することです。 すべての開始位置、すべての長さを試し、文字列を直接比較すると、おおよその結果が得られます。$O(n^3)$仕事。 

重要な観察点は、どのポジションでも`i`、必要な数字は 1 つだけです。`mx[i] = maximum length of a substring starting at i that already occurs somewhere before i`。 

この値がわかれば、DP は単純になります。 もし`mx[i] = L`、次に、からのすべての長さ`1`に`L`有料でコピーできる`b`。 コストは長さに依存しないため、常に利用可能な最長の部分文字列をコピーすることが最良の選択です。 

残りの課題はすべてを計算することです`mx[i]`。 

すべてのポジションのペアについて`(i, j)`と`j < i`で始まるサフィックスの最長の共通プレフィックスを計算します。`i`そして`j`。 

させて：```
lcp[i][j] = longest common prefix length of s[i:] and s[j:]
```次に、次から始まるすべての出来事`j`コピー可能な長さの部分文字列を提供します。```
min(lcp[i][j], i - j)
```２学期が重要だ。 ソースオカレンスは、すでに処理されたプレフィックス内に完全に存在する必要があります。 試合がポジションを超えた場合`i-1`、その部分は使用できません。 

以前のすべてのポジションの最大値を取る`j`与える`mx[i]`。 

LCP テーブルは次のように計算できます。$O(n^2)$古典的な逆 DP を使用する:```
if s[i] == s[j]:
    lcp[i][j] = lcp[i+1][j+1] + 1
else:
    lcp[i][j] = 0
```一度`mx`がわかっている場合、DP は次のようになります。$O(n^2)$、全体的な$O(n^2)$解決。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n²) | 遅すぎる |
 | 最適 | O(n²) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取り、`n × n`LCPテーブル。 
2. 表を右下から左上に向かって埋めていきます。 

もし`s[i] == s[j]`の場合、共通のプレフィックスの長さは次のようになります。`1 + lcp[i+1][j+1]`。 それ以外の場合はゼロです。 
3. ポジションごとに`i`、コピー可能な最長の長さを計算します。`mx[i]`。 

以前のポジションをすべて調べる`j < i`。 

接尾辞一致の長さは次のとおりです。`lcp[i][j]`、ただし最初だけ`i-j`文字は完全にすでにエンコードされたプレフィックスに属します。 したがって、使用可能な長さは次のようになります。```
min(lcp[i][j], i-j)
```全体の最大値を取る`j`。 
4. DP アレイの作成`dp`、 どこ`dp[i]`最初のコードをエンコードするための最小コストです`i`文字。 
5. 初期化します。```
dp[0] = 0
```6. ポジションごとに`i`:

 1 文字をエンコードします。```
dp[i+1] = min(dp[i+1], dp[i] + a)
```7. もし`mx[i] > 0`、利用可能な最長の部分文字列をコピーします。```
dp[i + mx[i]] = min(dp[i + mx[i]], dp[i] + b)
```すべてのコピーの長さのコストは同じであるため、最大長を使用すると、すべての短い長さが優先されます。 
8. 出力`dp[n]`。 

### なぜ効果があるのか

 LCP テーブルは、2 つの接尾辞間で一致する連続文字の数を正確に測定します。 

ポジションのために`i`、コピーされた有効なブロックはすべて、次の時点で始まる以前の発生から取得されている必要があります。`j < i`。 そのような最長のブロックには length があります`min(lcp[i][j], i-j)`すでにエンコードされたプレフィックス内に完全に含まれる文字のみがソースとして機能するためです。 以前のすべての位置の最大値を取得すると、正確に、次の時点で利用可能な最長のコピー操作が得られます。`i`。 

DP は、プレフィックスのすでに最適なエンコーディングを拡張するためにあらゆる可能な方法を検討します。 1 つの遷移は 1 文字の書き込みに対応し、もう 1 つは利用可能な最適なコピー操作の使用に対応します。 コピーのコストはコピーの長さに依存しないため、短いコピーは同じ位置から始まる長いコピーよりも改善することはできません。 すべての有効なエンコードは一連の DP 遷移によって表され、すべての DP 遷移は有効なエンコード アクションを表します。 したがって`dp[n]`可能な最小総コストに等しい。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    s = input().strip()

    lcp = [[0] * (n + 1) for _ in range(n + 1)]

    for i in range(n - 1, -1, -1):
        si = s[i]
        row = lcp[i]
        next_row = lcp[i + 1]

        for j in range(n - 1, -1, -1):
            if si == s[j]:
                row[j] = next_row[j + 1] + 1

    mx = [0] * n

    for i in range(n):
        best = 0
        for j in range(i):
            best = max(best, min(lcp[i][j], i - j))
        mx[i] = best

    INF = 10 ** 18
    dp = [INF] * (n + 1)
    dp[0] = 0

    for i in range(n):
        dp[i + 1] = min(dp[i + 1], dp[i] + a)

        if mx[i] > 0:
            dp[i + mx[i]] = min(dp[i + mx[i]], dp[i] + b)

    print(dp[n])

solve()
```最初の部分では LCP テーブルを構築します。 逆方向に計算することで、必要なときにそれが保証されます。`lcp[i+1][j+1]`、すでに計算されています。 

の`mx`配列には、各位置で使用可能な最大コピー長が格納されます。 表現`min(lcp[i][j], i-j)`微妙な部分です。 なしで`i-j`この制限により、ソース オカレンスがまだエンコードされていない文字に拡張されることを誤って許可してしまいます。 

DP には、プレフィックスの最小コストが格納されます。 位置から`i`、常に 1 文字を書くことが可能です。 の場合のみコピー可能となります。`mx[i] > 0`。 

微妙な観察ですが、次を使用してのみ移行します。`mx[i]`、からすべての長さではありません`1`に`mx[i]`。 すべてのコピーに正確なコストがかかるため、`b`、長いコピーは常に、同じ位置で始まる短いコピーよりも優先されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n, a, b = map(int, input().split())
    s = input().strip()

    lcp = [[0] * (n + 1) for _ in range(n + 1)]

    for i in range(n - 1, -1, -1):
        for j in range(n - 1, -1, -1):
            if s[i] == s[j]:
                lcp[i][j] = lcp[i + 1][j + 1] + 1

    mx = [0] * n
    for i in range(n):
        for j in range(i):
            mx[i] = max(mx[i], min(lcp[i][j], i - j))

    INF = 10 ** 18
    dp = [INF] * (n + 1)
    dp[0] = 0

    for i in range(n):
        dp[i + 1] = min(dp[i + 1], dp[i] + a)
        if mx[i]:
            dp[i + mx[i]] = min(dp[i + mx[i]], dp[i] + b)

    return str(dp[n]) + "\n"

# provided sample
assert run("3 3 1\naba\n") == "7\n", "sample 1"

# minimum size
assert run("1 5 2\na\n") == "5\n", "single character"

# copying never worth it
assert run("4 1 100\naaaa\n") == "4\n", "expensive copy"

# repeated string
assert run("4 10 1\naaaa\n") == "12\n", "cheap copy"

# no repeated substrings
assert run("5 3 1\nabcde\n") == "15\n", "all unique"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 5 2 / a`|`5`| 最小サイズ |
 |`4 1 100 / aaaa`|`4`| コピーは存在しますが、使用しないでください。 
|`4 10 1 / aaaa`|`12`| 長く繰り返される部分文字列の処理 |

 ## 特殊なケース

 次のことを考慮してください。```
4 10 1
aaaa
```位置で`2`、で始まる接尾辞`0`そして`2`長さを合わせる`2`。 アルゴリズムは以下を計算します。```
min(lcp[2][0], 2) = min(2, 2) = 2
```それで`mx[2] = 2`。 DP はプレフィックス長から直接ジャンプします`2`プレフィックスの長さへ`4`費用のために`1`、正解を導き出す`12`。 

考慮する：```
4 1 100
aaaa
```同じコピーの機会が存在しますが、DP はそれらを文字を個別に書くことと比較します。 コピーごとにコストがかかるため、`100`、すべてのコピー トランジションはキャラクター トランジションによって支配されます。 答えは次のようになります`4`。 

考慮する：```
5 3 1
abcde
```すべてのサフィックスのペアには LCP が付いています`0`、それですべて`mx[i]`価値観は残る`0`。 DP は文字のトランジションとリターンのみを使用します。`15`。 

考慮する：```
6 5 1
ababab
```位置で`2`、部分文字列`"ab"`はすでにプレフィックスに表示されています。 LCP テーブルは長さの一致を見つけます`4`、ただし最初だけ`2`文字はソースとして有効です。`i-j=2`。 アルゴリズムは以下を使用します。```
min(4, 2) = 2
```将来の文字との不正な重複を防止します。 この制限はまさにソリューションを正しく保つものです。
