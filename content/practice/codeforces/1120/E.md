 ## 解決策
 ## 問題の理解

 正の整数かどうかを判断するように求められます。$n$指定された整数に対して存在します$a \ge 2$乗算するような$n$による$a$桁の合計を係数で減らします$a$。 正式には、私たちが望んでいるのは、$S(an) = S(n)/a$、 どこ$S(x)$の桁の合計です$x$。 そのような場合$n$存在する場合は、作成する必要があります。 それ以外の場合は出力します$-1$。 生産された番号$n$を超えてはなりません$5 \cdot 10^5$これは十分な数字ですが、それでもアルゴリズム構築にとって実際的な制約となります。 

主な課題は、乗算と数字の合計の間の相互作用に起因します。 桁の合計は、いくつかの特殊な場合を除いて、乗算では線形に動作しません。そのため、すべての小さな整数を試すという単純なアプローチは必要ありません。$n$すぐに実行不可能になってしまうだろう$a$まで$1000$。 

重要な微妙な点は、$n$非常に大きくなる可能性があります。 たとえば、次の場合$a = 2$、簡単な解決策は$n = 6$なぜなら$S(12) = 3 = S(6)/2$。 しかし、より大きな場合には、$a$、の桁$n$合計条件を満たすためには慎重な構築が必要になる場合があります。 チェックだけをする軽率な強引さ$n$1 以降は、時間内に解決策が見つからないか、終了しないかのどちらかです。 

解決策が存在しない場合、別の特殊なケースが発生します。 たとえば、次の場合$a$桁の合計に比べて大きすぎるため、数値が存在しない可能性があります$n$プロパティを満たすため、アルゴリズムはこのシナリオを検出する必要があります。 

## アプローチ

 最も素朴なアプローチは反復することです$n = 1, 2, 3, \dots$かどうかを確認してください$S(an) = S(n)/a$。 これは概念的には正しいですが、操作数は爆発的に増加します。 最大数十万桁の数値を繰り返し合計するのはコストがかかり、制限のない検索が行われるため、時間がかかりすぎます。$a = 1000$。 

重要な洞察は、9 を法とする桁の和関数が線形であるということです。$S(x) \equiv x \mod 9$。 したがって、条件は$S(an) = S(n)/a$暗示する$an \equiv n \mod 9$、または同等の$(a-1)n \equiv 0 \mod 9$。 これにより、小桁の数字を見つける問題が軽減されます。$n$で割り切れる$\gcd(9, a-1)$その桁の合計が次で割り切れる$a$。 桁の合計の特殊な構造により、次のような構成が可能になります。$n$1 から 9 までの数字を貪欲に選択します。 

最適なアプローチの構築$n$次のような数字のシーケンスとして$an$桁の合計が正確に一致します$1/a$の$n$の合計。 これを行うには、最初に次の数で割り切れる桁の合計を推測します。$a$そして、乗算後にターゲットに一致するように貪欲に数字を埋めていきます。 1 と 2 (または必要に応じてそれ以上の数字) のみを使用すると、数値が次の値を超えないようになります。$5 \cdot 10^5$数字。

 | 最適 | O(a) | O(a) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 任意の数値についてそれを観察します$n$、その数字のモジュロ 9 の合計は次の条件を満たします。$S(n) \equiv n \mod 9$。 したがって、$(a-1)n$条件が成立するには、9 で割り切れる必要があります。 コンピューティング$g = \gcd(9, a-1)$。 これにより、解が存在する場合、その桁の合計が次の値で割り切れることが保証されます。$a$そして$g$。 
2. 次のステップは、最小の桁の合計を見つけることです。$S$で割り切れる$a$これにより、次のような 1 ～ 9 の数字を使用して数値を構築できます。$S(n) = S$。 の倍数にわたって繰り返します$a$から始まる$a$、妥当な制限で停止します (例:$9 * 5\cdot10^5$）。 
3. 各候補の合計について$S$、どうかを確認してください$S \mod g = 0$。 これを満たす和だけが、次の乗算が可能な数値を生成できる可能性があります。$a$桁合計比率の条件を保持します。 
4. 構築する$n$残りの合計が許す限り、貪欲に左から右に 9 で数字を埋めていきます。 これにより、$n$長さが最小限であり、その可能性が最大化されます。$an$正しい桁の合計があります。 残った合計が 9 より小さい場合は、それを最後の桁として置きます。 
5. 乗算$n$による$a$そしてそれを確認してください$S(an) = S(n)/a$。 これがすべての合計で失敗した場合$S$限界まで、戻る$-1$。 

なぜ機能するのか: 構築全体を通して不変なのは、$S(n)$で割り切れます$a$9 を法とする数字の合計が一致する$(a-1)n \mod 9 = 0$。 貪欲な構造では、各桁が合計に最大 9 を寄与し、合計桁数が制限されているため、数値が許容桁長内に存在することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def digit_sum(x):
    return sum(int(c) for c in str(x))

def find_number(a):
    g = 9 // gcd(9, a - 1)
    # limit to avoid 5*10^5 digits
    for s in range(a, 9 * 500_000 + 1, a):
        if s % g != 0:
            continue
        # build number greedily from 9s
        rem = s
        digits = []
        while rem > 0:
            d = min(9, rem)
            digits.append(str(d))
            rem -= d
        n = int(''.join(digits))
        if digit_sum(a * n) == s // a:
            return str(n)
    return "-1"

def gcd(x, y):
    while y:
        x, y = y, x % y
    return x

def main():
    a = int(input())
    print(find_number(a))

if __name__ == "__main__":
    main()
```機能`digit_sum`桁の合計を計算します。`gcd`最大公約数を計算します。 の倍数にわたって繰り返します`a`そして、許容される桁制限内に収まるように、最大​​桁から順に数値を構築します。 最終チェックでは、次の乗算が行われていることを確認します。`a`正確なターゲット桁の合計が得られます。 9 を使用した貪欲なアプローチを使用すると、最小限の桁数が保証されます。
