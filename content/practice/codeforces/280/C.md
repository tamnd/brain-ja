 ## 解決策
 ## 問題の理解

 頂点に根を持つ木が与えられています`1`。 ゲームは、すべてのノードが消えるまで、このルート化されたツリー上でプレイされます。 

移動するたびに、現在残っている頂点の 1 つが均一にランダムに選択されます。 頂点のとき`v`が選択され、ルートとなるサブツリー全体が`v`を含めてすぐに削除されます`v`自体。 ルートを削除すると残りのツリー全体が削除されるため、最終的にルートが削除されるとゲームは終了します。 

タスクは、ツリーが空になるまでに予想される移動数を計算することです。 

入力は、最大で無向ツリーを記述します。`10^5`頂点。 木は頂点に根を張っているので、`1`を使用すると、ルートからの DFS または BFS 後の親子関係の観点からすべてのエッジを解釈できます。 

制約`n ≤ 100000`ランダムなプロセスを明示的にシミュレートするアプローチは直ちに除外されます。 たとえ`O(n^2)`アルゴリズムには次のようなものが必要です`10^10`制限時間を大幅に超えた最悪の場合の作戦。 線形またはほぼ線形のソリューションが必要です。 

この問題の微妙な点は、削除するたびにゲームの状態が変化することです。 頂点が選択される確率は、どの頂点が以前の移動で生き残ったかによって決まります。 残りのすべての可能なツリー間の遷移を書き込もうとすると、すぐに不可能になります。 

チェーンを考えてみましょう。```
1
|
2
|
3
```よくある間違いは、各頂点が独立して寄与していると考えることです。 そうではありません。 頂点の場合`2`選択された頂点`3`選ばれずに消えてしまいます。 1 回だけ選択される各頂点に固定確率を割り当てるアプローチでは、誤った期待が生じます。 

もう 1 つの陥りやすい落とし穴は、ルートは最終的に常に選択されるということを忘れていることです。 単一ノードツリーの場合:```
1
```ゲームは常に 1 つの手で終わるので、答えは次のとおりです。`1`。 を与える式はどれも`0`ここにはルートの貢献が欠けています。 

星型のツリーも、誤った推論を明らかにします。```
1
/|\
2 3 4
```葉は自分自身を選択することによってのみ消えることができますが、根はすべてを一度に破壊します。 期待される答えは、木の高さ、葉の数、またはその他の明白な構造量と等しくありません。 

重要なのは、プロセス全体をモデル化せずに期待値を直接計算できる量を見つけることです。 

## アプローチ

 ブルートフォース ソリューションでは、残りの考えられるすべてのツリーが状態として扱われます。 入っている状態から`k`頂点、各頂点は確率で選択されます`1/k`、サブツリーを削除することで得られる別の状態につながります。 

この状態空間ビューはゲームのルールに正確に一致するため、正しいです。 残念ながら、小さなツリーでも、可能な残りの構成が指数関数的に多く生成されます。 ある木`10^5`頂点により、これは完全に不可能になります。 

画期的な進歩は、測定するものを変えることから生まれます。 

予想される手数を直接求めるのではなく、特定の頂点がゲームに 1 つの手で貢献するかどうかを検討します。 

すべての頂点にランダムな優先順位を割り当てることを想像してください。 各ステップで均一にランダムな残りの頂点を選択することは、すべての頂点のランダムな並べ替えを生成し、その順序で明らかにすることと同じです。 頂点が実際に移動を引き起こすのは、その頂点が順列内でその頂点のすべての祖先の前に出現する場合に限られます。 

なぜ？ 祖先が最初に出現する場合、その祖先のサブツリーを削除すると、頂点が選択される前に削除されます。 頂点がルートからそれ自体へのパス上のすべての頂点の中で最も早い場合、その頂点はそのターンまで存続し、1 つの移動に貢献します。 

深さの頂点の場合`d`(根の深さ`1`)、ルートからその頂点までのパスには正確に次のものが含まれます。`d`頂点。 このうち`d`頂点の場合、すべての頂点がランダムな順列で最も早い頂点である可能性が等しくなります。 したがって、$$P(\text{vertex } v \text{ contributes a move}) = \frac{1}{d}.$$させて`I(v)`その頂点の指標となる`v`動きに貢献します。 総移動数は、$$X = \sum_v I(v).$$期待値の直線性を利用して、$$E[X] = \sum_v E[I(v)] = \sum_v \frac{1}{\text{depth}(v)}.$$問題は非常に単純なものになりました。 必要なのは、ルート化されたツリーのすべての頂点の深さだけです。 

単一の DFS がすべての深さを計算し、答えはその逆数の合計になります。

 ## アルゴリズムのチュートリアル

 1. ツリーの隣接リストを作成します。 
2. ツリーの頂点にルートを作成します`1`。 
3. ルートから DFS を実行し、深さを使用してすべての頂点の深さを計算します。`1`根のために。 
4. 訪問した頂点ごとに、次を追加します。`1 / depth`答えに。 
5. すべての頂点を訪問するまで続行します。 
6. 累積合計を十分な精度で出力します。 

明白ではない部分はステップ 4 です。頂点は、ランダムな置換の解釈において、ルートから頂点へのパス上の最も早い頂点である場合に、正確に 1 つの移動に寄与します。 そのパス上のすべての頂点が最も早い可能性が等しいため、寄与確率は単純に次のようになります。`1 / depth`。 

### なぜ効果があるのか

 任意の頂点に対して`v`、指標確率変数を定義します。$$I(v)= \begin{cases} 1,&\text{if }v\text{ is ever selected},\\ 0,&\text{otherwise}. \end{cases}$$頂点`v`の祖先が存在しない場合にのみ選択されます。`v`がその前に選択されています。 すべての頂点のランダムな並べ替えでは、これはまさに次のときに発生します。`v`ルートからルートまでの最初の頂点です`v`パス。 
パスに含まれるのは`depth(v)`頂点、対称性がもたらす$$P(I(v)=1)=\frac{1}{depth(v)}.$$ゲームの合計手の数は次のとおりです$$X=\sum_v I(v).$$期待値の直線性を適用すると、$$E[X] = \sum_v E[I(v)] = \sum_v P(I(v)=1) = \sum_v \frac{1}{depth(v)}.$$DFS はすべての深さを 1 回だけ計算するため、アルゴリズムはこの式を正確に評価します。 この式は予想される手数と等しいため、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    ans = 0.0

    stack = [(1, 0, 1)]  # node, parent, depth

    while stack:
        u, parent, depth = stack.pop()

        ans += 1.0 / depth

        for v in g[u]:
            if v != parent:
                stack.append((v, u, depth + 1))

    print("{:.15f}".format(ans))

if __name__ == "__main__":
    solve()
```隣接リストにはツリーが格納されます。`O(n)`メモリ。 

DFS は再帰的ではなく反復的に実装されます。 一定の長さのパス上の再帰的 DFS`100000`Python の再帰制限を超える可能性があります。 明示的なスタックを使用すると、この問題が完全に回避されます。 

各スタック エントリには、現在の頂点、その親、およびその深さが格納されます。 頂点がポップされると、すぐに追加します`1/depth`答えに。 これは証明された公式を直接実装します。$$\sum_v \frac{1}{depth(v)}.$$根は深いところから始まる`1`、 ない`0`。 根に関連する確率は次のとおりであるため、これは非常に重要です。`1`、ゼロで割るのは明らかに無効です。 

答えは浮動小数点変数に蓄積されます。 倍精度は必要な条件を満たすには十分です`10^{-6}`正確さ。
