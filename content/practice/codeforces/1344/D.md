 ## 解決策
 ## 問題の理解

 プロジェクトにはいくつかのカテゴリが与えられており、カテゴリごとにプロジェクトがいくつ存在するかがわかります。 各カテゴリから、履歴書に掲載するいくつかのプロジェクトを選択します。ただし、選択したプロジェクトの合計数が正確に次のとおりであるという制約があります。$k$、実際に持っている以上のものをカテゴリから選択することはできません。 

選択のスコアは直線的ではありません。 私たちが取るなら$b_i$カテゴリからのプロジェクト$i$、貢献度は$$b_i(a_i - b_i^2)$$そのため、カテゴリからの追加プロジェクトはそれぞれ、未使用のままのプロジェクトの数と相互作用し、次のような 3 次のペナルティを導入します。$b_i^3$。 合計スコアはすべてのカテゴリの合計であり、固定合計合計制約の下で最大化したいと考えています。 

主な問題点は、グローバルな制約により、各カテゴリの決定が独立していないことです。$\sum b_i = k$。 これにより、問題は正確に配布されるようになります$k$全体の単位$n$「コンテナ」。各コンテナは非線形の利益関数を持ちます。 

制約により、私たちはほぼ直線的な時間に追い込まれます。 と$n \le 10^5$、のすべての値を試すソリューション$b_i$明示的に行うか、カテゴリごとにネストされた最適化を使用すると遅すぎます。 平$O(n \log n)$許容されますが、全体にわたるユニットごとのシミュレーションを伴うものはすべて$k$（それは大きくなる可能性があります）は不可能です。 

いくつかの失敗例から、何が問題になる可能性があるかが明らかになります。 

現在の限界ゲインが最大のカテゴリから常に選択する貪欲な戦略は正しく見えるかもしれませんが、適切に処理せずに限界ゲインが単調でない方法で交差する場合は失敗します。 もう 1 つの微妙な失敗は、各カテゴリを独立して扱い、最適なものを選択することから生じます。$b_i$グローバル合計制約を無視すると、違反する可能性があります。$\sum b_i = k$。 

たとえば、1 つのカテゴリに$a_i = 100$、その局所最適値は、大きな値をとることを示唆するかもしれません。$b_i$, ただし、他のカテゴリからの小さな貢献が多数あればより高い合計スコアが得られる場合でも、予算を大量に消費する可能性があります。 

この構造は、値を増やすと値がどのように変化するかを理解する必要があることを示唆しています。$b_i$選択するのではなく段階的に$b_i$直接。 

## アプローチ

 結合制約を無視すると、次のように処理することで各カテゴリを独立して最適化できます。$f_i(b) = b(a_i - b^2)$。 全部試してみるのもいいかもしれない$b$から$0$に$a_i$、しかしそれは不可能です$a_i$できる$10^9$。 

より直接的な強引なアプローチでは、問題を分散として扱います。$k$同一のアイテム$n$カテゴリを作成し、割り当てごとに完全な関数を再計算します。 有効な分布に限定しても、方法の数は組み合わせになります。$k$、小さな制約でもこれは不可能になります。 

重要な観察は、最終的な値を選択するという観点から考えるのをやめるということです$b_i$代わりに、限界利益の観点から考えてください。 増えたら$b_i$から$x$に$x+1$、ゲインは次のとおりです。$$\Delta_i(x) = (x+1)(a_i - (x+1)^2) - x(a_i - x^2)$$これは次のように単純化されます。$$\Delta_i(x) = a_i - 3x^2 - 3x - 1$$したがって、各カテゴリは次のように減少する一連の限界値を生成します。$x$が増加します。 問題は、正確に選択することです。$k$すべてのカテゴリにわたって、限界合計が最大になるように増分します。 

これは古典的な「多くの減少シーケンスから k 個の最良の項目を取り出す」問題です。 各カテゴリは凹状の一連のゲインに寄与し、現在利用可能な最良の増分を繰り返し取得します。 

各カテゴリの現在の限界値を計算し、それらを最大ヒープに維持できます。 1 つの増分を選択するたびに、そのカテゴリが更新され、次の限界値がプッシュされます。 これは、各シーケンスが厳密に減少するため、ローカルでの貪欲な選択がグローバルに最適になるため有効です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙$b_i$| 指数関数 | O(n) | 遅すぎる |
 | 限界ヒープを備えた貪欲な | O(k log n) 単純で最適化された O(n log k) | O(n) | 承認済み |

 残された問題は、$k$は大きくなる可能性があるため、すべての増分を 1 つずつシミュレートすることは避けなければなりません。 代わりに、限界しきい値で二分探索を使用し、各カテゴリがそのしきい値を超えて寄与できる増分数を計算します。 

## アルゴリズムのチュートリアル

 ### 1. 問題を増分利益として再定式化する

 ソリューションの構築は以下から始まると解釈します。$b_i = 0$そしてパフォーマンス$k$操作ごとに、いくらか増加します$b_i$各操作の値は、その増分の限界ゲインに等しいです。 

目的は選択になります$k$合計限界ゲインが最大になるように増加します。 

### 2. 限界ゲインの公式を導き出す

 固定カテゴリの場合$i$、すでに選択したとします$x$要素。 次の利点は次のとおりです。$$g_i(x) = a_i - 3x^2 - 3x - 1$$この関数は次のように厳密に減少します。$x$が増加するため、各カテゴリは減少する一連の利益を形成します。 

この単調性により、グローバルな貪欲な推論が可能になります。 

### 3. 閾値による最適な選択の特徴付け

 明示的に増分を選択する代わりに、しきい値を定義します。$T$。 限界利得が厳密に次の値よりも大きいすべての増分が含まれます。$T$、そしておそらくそれに等しいものもあります$T$正確に一致する$k$。 

カテゴリごとに、次のことを解決します。$$g_i(x) \ge T$$これは、そのシーケンス内に有効な増分がいくつ存在するかを見つけることになります。 

### 4. 閾値での二分探索

 最大のしきい値を二分探索します$T$ゲインによる増分の合計数が$\ge T$少なくとも$k$。 

各チェックでは、カテゴリごとに、その数が計算されます。$x$満足する：$$a_i - 3x^2 - 3x - 1 \ge T$$これは次の式で解ける二次不等式です。$O(1)$カテゴリごとに。 

### 5. 閾値から解を構築する

 しきい値が固定されたら、各カテゴリを割り当てます。 

- ゲインが厳密に大きい場合のすべての増分$T$- 次に、ゲインが等しいものから残りの容量を使用します。$T$これにより正確に保証されます$k$合計増分。 

### なぜ効果があるのか

 限界ゲイン シーケンスはカテゴリごとに厳密に減少しているため、全体的な降順で増分を選択することは、カットオフを超えるすべての増分を選択することと同じです。 二分探索では、必要なカウントを維持しながら、すべての限界ゲインのマルチセットを選択された部分と選択されていない部分に分割するカットオフが見つかります。 シーケンスが減少した後に再び増加することはできないため、より低い限界ゲインを優先してより高い限界ゲインをスキップすることには利点がないため、貪欲なしきい値の構築が最適です。

import sys
input = sys.stdin.readline

def count_and_sum(a, t):
    # returns total increments and how many strictly above t, and how many equal
    cnt = 0
    exact = 0
    for ai in a:
        # solve ai - 3x^2 - 3x - 1 >= t
        # 3x^2 + 3x + (1 + t - ai) <= 0
        lo, hi = 0, ai
        # find maximum x satisfying inequality
        l, r = 0, ai
        best = -1
        while l <= r:
            m = (l + r) // 2
            val = 3*m*m + 3*m + (1 + t - ai)
            if val <= 0:
                best = m
                l = m + 1
            else:
                r = m - 1
        if best >= 0:
            cnt += best + 1
            # check exact threshold hits is not needed explicitly for final construction
    return cnt

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    lo, hi = -10**18, 10**18
    while lo < hi:
        mid = (lo + hi + 1) // 2
        if count_and_sum(a, mid) >= k:
            lo = mid
        else:
            hi = mid - 1
    T = lo

    b = [0] * n
    total = 0

    for i in range(n):
        ai = a[i]
        l, r = 0, ai
        best = 0
        while l <= r:
            m = (l + r) // 2
            val = 3*m*m + 3*m + (1 + T - ai)
            if val <= 0:
                best = m
                l = m + 1
            else:
                r = m - 1
        b[i] = best
        total += best

    rem = k - total

    for i in range(n):
        if rem == 0:
            break
        if b[i] < a[i]:
            b[i] += 1
            rem -= 1

    print(*b)

if __name__ == "__main__":
    main()

次に、カテゴリごとの実行可能な最大の増分数を使用して、基本割り当てを再構築します。 最後に、正確に不足している場合は、$k$、残りのユニットを、さらに多くの要素を受け入れることができるカテゴリ間で任意に分配します。これは、正確にしきい値レベルでいくつかの要素を含めることに対応します。 

実装の微妙な詳細は、浮動小数点ルートの代わりに整数二分探索を使用して二次不等式を慎重に解くことです。 これにより、大規模な場合の精度の問題が回避されます。$a_i$。
