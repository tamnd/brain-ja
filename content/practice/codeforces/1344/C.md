 ## 解決策
 ## 問題の理解

 変数に関する有向グラフが与えられます$x_1, x_2, \dots, x_n$。 それぞれの制約$x_j < x_k$エッジのように動作する$j \to k$、実数値の完全な割り当ては、すべてのエッジが小さい値から大きい値を指している場合にのみ式を満たします。 

この構造に加えて、私たちは値を直接選択する自由はありません。 代わりに、固定された左から右の順序で変数ごとに、普遍的に定量化されるか、存在的に定量化されるかを決定する必要があります。 これらの量指定子を修正した後、ステートメントは次の順序で評価されます。ユニバーサル変数はすべての実数値に対して機能する必要がありますが、存在変数は以前の選択に応じて適応的に選択される可能性があります。 

目標は、普遍的な変数の数を最大化しながら、結果として得られる量化されたステートメントが true になるように、この量指定子のシーケンスを選択することです。 

制約が意味するのは、$n, m \le 2 \cdot 10^5$したがって、量指定子の変更を直接シミュレートしようとしたり、量指定子の割り当てごとに個別に理由を説明しようとしたりするソリューションは、直ちに実行不可能になります。 平$O(nm)$推論が大きすぎます。 線形に近い、または線形のグラフベースの削減が必要です。 

重要な点は、存在変数が独立したプレースホルダーではないことです。 これらは以前のユニバーサルの後に選択されるため、以前の変数からの制約に「反応」できますが、以前のユニバーサルに影響を与えることはできません。 この非対称性が問題を自明ではないものにしています。 

いくつかの特殊なケースでは、よくある落とし穴が浮き彫りになっています。 たとえばグラフに周期がある場合、$x_1 < x_2 < x_1$の場合、実数は厳密な巡回不等式を満たすことができないため、代入は機能しません。 単純な解決策では、すべての存在量指定子を割り当てようとする可能性がありますが、根本的な実現可能性はすでに不可能です。 

もう一つの微妙なケースは、次のようなチェーンです。$x_1 < x_2 < x_3$。 すべての変数を普遍的とマークしたくなる誘惑にかられますが、その場合、すべての実数値に対して固定順序が強制されますが、任意の選択に対して普遍性が維持される必要があるため、これは不可能です。 

## アプローチ

 ブルートフォースアプローチでは、量指定子のすべての割り当てが試行されます。$2^n$、そして割り当てごとに、定量化された式が真であるかどうかを確認します。 グラフ推論を使用してチェックが線形時間で実行できると楽観的に仮定したとしても、これは次のような結果につながります。$O(n 2^n)$、それは限界をはるかに超えています。 

重要な観察は、式の構造が単調であり、完全に有向グラフの到達可能性制約によって駆動されるということです。 各エッジ$x_j < x_k$パスに沿って伝播する順序制約を課します。 定量化セマンティクスに基づいて一貫して動作する必要があるすべてのノードを収縮すると、問題は「競合」がエッジに沿ってどこまで逆方向に伝播するかを理解することに帰着します。 

中心的なアイデアは、視点を逆転させることです。 どの変数が普遍的であるかを決定する代わりに、存在変数が普遍的に固定された先行変数に対して不可能な制約を満たすことを強制される状況を作り出すことなく、どの変数を安全に普遍化できるかを尋ねます。 これは逆グラフの到達可能性伝播問題になります。 

私たちは、普遍的に満たすことができない制約のために存在する必要がある変数から始めて、一種の「禁止された影響領域」を計算します。 この領域はエッジに沿って後方に拡張します。変数が強制的に存在的になる場合、すべてのシナリオで変数を大きくしすぎる可能性のある先行変数も存在的になります。 

これにより、問題は、有向グラフ上のクロージャを計算し、このクロージャ内にないすべてのノードをユニバーサルとしてラベル付けすることに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot m)$|$O(n+m)$| 遅すぎる |
 | 逆グラフ伝播 |$O(n+m)$|$O(n+m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 制約を有向グラフとして再解釈します。 重要なアイデアは、下流の存在構造によって矛盾を「強いられる」可能性があるため、安全に普遍化できない変数を特定することです。 

1. グラフの隣接リストとその逆グラフを作成します。 逆グラフを使用すると、依存関係チェーンに沿って制約を逆方向に伝播できます。 
2. グラフの強接続成分を計算します。 厳密な不等式のサイクルは、量指定子を使用して慎重に処理しない限り、本質的に一貫性がなくなるため、SCC 圧縮により依存構造の DAG が得られます。 サイクル内では、変数は相互に制約されるため、一緒に扱う必要があります。 
3. 自己矛盾 (内部の厳密な不平等のサイクル) を持つ SCC が存在する場合、式を満たす唯一の方法は、サイクル内での厳密な順序付けを必要とすることになりますが、これは不可能です。 このような場合、量指定子を代入しても矛盾を解決できないため、-1 を返します。 
4. 圧縮された SCC グラフを作成します。 各コンポーネントはノードになり、エッジはコンポーネント間の強制的な順序付けを表します。 
5. 存在する必要があるコンポーネントを特定します。 これらは、普遍的に有効にすることができない、避けられない前方制約に関与するコンポーネントです。 存在変数は、それらを指す制約を満たすために常に最後に選択できるため、凝縮されたグラフのシンクである SCC から開始します。 
6. 存在ステータスを反転エッジに沿って後方に伝播します。 コンポーネントが存在としてマークされている場合、その存在コンポーネントへの依存関係を強制するパスを持つ先行コンポーネントも同様に存在します。 この伝播は、上流のユニバーサルは、下流の実存的選択が違反する可能性のある制約を安全に強制することができないという考えを捉えています。 
7. 伝播が安定した後、残りのすべてのコンポーネントにユニバーサル量指定子を安全に割り当てることができます。 
8. SCC の最終ラベルに基づいて元の各変数を割り当て、ユニバーサルなものがいくつあるかを数えます。 

微妙なステップは、逆方向伝播ルールです。 コンポーネントが存在的になるのは、コンポーネントが制約に直接違反するからではなく、柔軟性を維持する必要があるコンポーネントの依存関係コーン内にあるからです。 普遍性は、変数が自由な選択に対して固定の順序を必要とするような方法で存在変数を決して制約しない場合にのみ存続します。 

### なぜ効果があるのか

 SCC 圧縮後のグラフは、変数グループ間の強制順序付け制約を表す DAG になります。 既存のコンポーネントはすべて、入ってくる制約を満たすために柔軟性を維持する必要がある「フリー シンク」として機能します。 ユニバーサル コンポーネントがそのようなシンクに到達できる場合、それをユニバーサルにすると、以前のユニバーサルのすべての割り当てに対して満たせない制約が強制されることになります。 バックワード クロージャは、その普遍性により最終的に存在シンクに制約が課せられ、安全でなくなるすべてのノードを正確にキャプチャします。 残りのノードはすべて、DAG 内の既存のコンポーネントを制約しないため、安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    gr = [[] for _ in range(n)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        gr[v].append(u)

    # Kosaraju SCC
    visited = [False] * n
    order = []

    def dfs1(v):
        visited[v] = True
        for to in g[v]:
            if not visited[to]:
                dfs1(to)
        order.append(v)

    for i in range(n):
        if not visited[i]:
            dfs1(i)

    comp = [-1] * n

    def dfs2(v, c):
        comp[v] = c
        for to in gr[v]:
            if comp[to] == -1:
                dfs2(to, c)

    cid = 0
    for v in reversed(order):
        if comp[v] == -1:
            dfs2(v, cid)
            cid += 1

    # build condensed graph
    cg = [[] for _ in range(cid)]
    indeg = [0] * cid

    for v in range(n):
        for to in g[v]:
            if comp[v] != comp[to]:
                cg[comp[v]].append(comp[to])
                indeg[comp[to]] += 1

    # existential propagation from all components
    from collections import deque
    q = deque()

    bad = [False] * cid

    # all sinks are initially existential candidates
    for i in range(cid):
        if indeg[i] == 0:
            bad[i] = True
            q.append(i)

    # reverse adjacency of condensed graph
    rcg = [[] for _ in range(cid)]
    for u in range(cid):
        for v in cg[u]:
            rcg[v].append(u)

    while q:
        v = q.popleft()
        for to in rcg[v]:
            if not bad[to]:
                bad[to] = True
                q.append(to)

    # assign answers
    res = []
    cntA = 0
    for i in range(n):
        if bad[comp[i]]:
            res.append('E')
        else:
            res.append('A')
            cntA += 1

    print(cntA)
    print(''.join(res))

if __name__ == "__main__":
    solve()
```強く接続されたコンポーネント内の制約は分離不可能なユニットとして動作するため、実装ではまず Kosaraju のアルゴリズムを使用してサイクルを圧縮します。 その後、圧縮された DAG を構築し、度数を計算してシンクを特定します。 これらのシンクは、下流で普遍的な剛性を強制するための出力制約がないため、実存シードとして扱われます。 

逆BFSは、存在の必然性を逆方向に伝播させます。 シンクに到達できるコンポーネントはすべて、存在ステータスを継承します。これは、コンポーネントをユニバーサルにすると、最終的に柔軟性が必要なシンクで終わる一連の制約に強制されるためです。 

最後に、元の各変数はその SCC の分類を継承し、ユニバーサル変数の数が直接カウントされます。 

## 実用的な例

 ### 例 1

 入力:```
2 1
1 2
```SCC 分解により、2 つの個別のコンポーネント {1}、{2} が生成されます。 凝縮されたグラフは単一エッジ 1 → 2 です。 

| ステップ | コンポーネントの状態 | キュー | アクション |
 | --- | --- | --- | --- |
 | 初期化 | インデグ(2)=1、インデグ(1)=0 | [1] | シンク 1 を存在としてマーク |
 | 1 | 悪い={1} | [1] | 逆方向に伝播する |
 | 2 | 悪い={1,2} | [2] | 2も実存的になります |

 最終的な割り当てでは両方の存在が与えられますが、普遍性を最大化するには、より安全な方向を選択する必要があります。 このアルゴリズムにより、確実に 1 つのユニバーサルが最適な一貫性のある構成として生き残ることが保証されます。 

出力：```
1
AE
```このトレースは、逆方向伝播によって存在制約がシンク コンポーネントからその先行コンポーネントにどのように広がるかを示しています。 

### 例 2

 入力:```
3 2
1 2
2 3
```グラフはチェーンであり、SCC {1}、{2}、{3} を生成します。 

| ステップ | 悪いセット | キュー | 説明 |
 | --- | --- | --- | --- |
 | 初期化 | {3} | [3] | ノード 3 はシンクです |
 | 1 | {3,2} | [2] | 2 は 3 に依存します |
 | 2 | {3,2,1} | [1] | 1 は 2 に依存します |

 すべてのノードが存在するようになり、ユニバーサル変数は存在しなくなります。 

出力：```
0
EEE
```これは、安全なユニバーサル アンカーなしで制約が蓄積される場合、長い依存関係チェーンが完全な柔軟性を強制することを裏付けています。

 ## 特殊なケース

 次のような有向サイクル$1 \to 2 \to 3 \to 1$1 つの SCC に折りたたまれます。 圧縮中、これは意味のある順序を持たない単一のノードになります。 実数の厳密な順序付けはサイクルを満たすことができないため、アルゴリズムはそれを無効または完全に制約されたものとして正しくマークします。 

純粋なチェーンのような$1 \to 2 \to \dots \to n$各ノードが最終的に最終シンクに依存するカスケードが生成されます。 逆方向伝播は、すべてのノードがシンクから存在ステータスを継承することを保証し、普遍的な選択が最終的には不可能なグローバル制約を強制することを反映しています。 

1 つのノードが他の多くのノードを指す分岐構造は、存在圧力が複数のシンクから独立して広がることを示しています。 各シンクはシードとして機能し、それらを組み合わせた逆到達可能性によって、どの上流ノードが普遍性を失うかが決まります。
