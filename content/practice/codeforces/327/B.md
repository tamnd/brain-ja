 ## 解決策
 ## 問題の理解

 増加するシーケンスを構築する必要があります。`n`後の要素が前の要素で割り切れないような正の整数。 

入力には単一の数値が含まれています`n`。 任意の長さのシーケンスを出力する必要があります`n`という2つの条件を満たしていること。 まず、シーケンスは厳密に増加していなければなりません。 第二に、ポジションのペアごとに`i < j`、位置の値`j`位置の値の倍数であってはなりません`i`。 

この制約は、数学的な観点からは非常に寛大ですが、実装の観点からは制限的です。 まで必要です`100000`数値。すべての数値は最大でも`10^7`。 と`n = 100000`、すべてのペアを明示的にチェックするアルゴリズムでは、大まかに次のことが必要になります。$$\frac{100000 \cdot 99999}{2} \approx 5 \cdot 10^9$$1秒以内に比較することは完全に不可能です。 直接施工が必要です。 

最も重要な観察は、この問題が辞書編集上の最小のシーケンスや最適なシーケンスを求めていないということです。 有効な構造はすべて受け入れられます。 

よくある間違いは、1 から始まる連続した整数を使用することです。 

たとえば:```
n = 3
```順序：```
1 2 3
```すべての数値は 1 で割り切れるため、無効です。 

もう 1 つの魅力的なアイデアは、2 から始まる連続した整数を使用することです。```
2 3 4
```これはまだ無効です。`4`で割り切れます`2`。 

正しい順序`n = 3`考えられるのは:```
2 3 5
```後の要素を分割する要素はありません。 

もう 1 つの微妙な問題は上限です`10^7`。 非常に大きな数を生成する構造は、割り算条件を満たしても、許容範囲に違反する可能性があります。 

たとえば、2 のべき乗:```
2, 4, 8, 16, ...
```すでに可分性条件を満たしておらず、たとえ修正されたとしても、急速に成長する構造物は可分性条件を超えるリスクがあります。`10^7`。 

増加する順序を保証し、割り切れることを回避し、制限内にとどまる構造が必要です。 

## アプローチ

 ブルートフォース手法では、一度に 1 つの数値ずつシーケンスを構築します。 各候補値について、以前に選択した数値で割り切れるかどうかを確認します。 すべてのチェックに合格した場合は、シーケンスに追加します。 

このメソッドは、必要なプロパティを明示的に検証するため、正しいです。 問題は効率です。 新しい候補者はすべて、以前の多くの要素に対してテストする必要がある場合があります。 と`n = 100000`、最適化されたバージョンであっても、非常に多くの可算性チェックが実行されます。 

重要な観察は、素数が自動的に条件を満たしているということです。 

異なる素数を昇順に選択するとします。```
p1 < p2 < p3 < ...
```任意のペアを選択してください`i < j`。 以来`pj`は素数であり、より大きい`pi`、唯一の正の約数`pj`は`1`そして`pj`自体。 以来`pi`どちらの値でもない、`pj`で割り切れない`pi`。 

したがって、個別の素数のリストが増加すると、自動的にハングリー シーケンスになります。 

問題は次の発見になります`n`を超えない素数`10^7`。 

周知の事実は、`100000`以下の素数`10^7`。 実際、100000 番目の素数は`1299709`、快適に制限を下回ります。 したがって、最初の`100000`素数で十分です。 

標準ツールはエラトステネスのふるいです。 ふるいにかけると約`1.3 × 10^6`少なくとも簡単に生成できる`100000`素数。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | O(n) | 遅すぎる |
 | 最適 (ふるい + 最初の n 個の素数) | O(MログログM) | お(お) | 承認済み |

 ここ`M`ふるいの限界、約`1.3 × 10^6`。 

## アルゴリズムのチュートリアル

 1.読む`n`。 
2. 少なくとも次のものを含むのに十分な大きさのふるい限界を選択します。`100000`素数。 の制限`1300000`で十分です。 
3. エラトステネスのふるいをその限界まで実行します。 
4. すべての素数を昇順に収集します。 
5.最初の出力`n`素数。 

これが機能する理由は、素数がふるいから収集されたときにすでに厳密に増加しており、別の素数よりも大きい素数はその素数で割り切れないためです。 

### なぜ効果があるのか

 ふるいは昇順に素数を生成するため、シーケンスは厳密に増加します。 

選択した 2 つの要素を考慮します`pi < pj`。 以来`pj`は素数であり、その唯一の正の約数は`1`そして`pj`。 番号`pi`は、より小さい素数であるため、これらの約数のどちらでもありません。 したがって、`pi`分けない`pj`。 

この引数はインデックスのすべてのペアに適用されるため、生成されたシーケンスはハングリー シーケンス条件を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    LIMIT = 1300000

    is_prime = [True] * (LIMIT + 1)
    is_prime[0] = is_prime[1] = False

    p = 2
    while p * p <= LIMIT:
        if is_prime[p]:
            for multiple in range(p * p, LIMIT + 1, p):
                is_prime[multiple] = False
        p += 1

    primes = []
    for i in range(2, LIMIT + 1):
        if is_prime[i]:
            primes.append(i)
            if len(primes) == n:
                break

    print(*primes)

if __name__ == "__main__":
    solve()
```最初の部分は、必要なシーケンス長を読み取ります。 

ふるいは合成数をマークします。 素数ごとに`p`、から始まるすべての倍数`p²`非プライムとしてマークされています。 から開始`p²`より小さい倍数はより小さい素数によってすでに処理されているため、冗長な作業が回避されます。 

ふるいが終了したら、数値を昇順にスキャンして素数を収集します。 集まったら`n`素数の場合、配列の残りの部分をスキャンするのではなく、すぐに停止します。 

出力は最初のもので構成されます。`n`素数。 それらの昇順はスキャン順序から直接得られます。 

実装の微妙な詳細は、ふるいの制限です。 最悪の場合に備えて十分な素数が必要です`n = 100000`。 の制限`1300000`以上のものを安全に含んでいます`100000`素数なので、コレクション ループは常に成功します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(input())

    LIMIT = 1300000
    is_prime = [True] * (LIMIT + 1)
    is_prime[0] = is_prime[1] = False

    p = 2
    while p * p <= LIMIT:
        if is_prime[p]:
            for multiple in range(p * p, LIMIT + 1, p):
                is_prime[multiple] = False
        p += 1

    ans = []
    for i in range(2, LIMIT + 1):
        if is_prime[i]:
            ans.append(str(i))
            if len(ans) == n:
                break

    return " ".join(ans)

# provided sample
assert run("3\n") == "2 3 5"

# minimum size

# small case

# larger sanity check
out = run("10\n").split()
assert len(out) == 10
assert out[0] == "2"
assert out[-1] == "29"

 ## 特殊なケース

 最低限の入力に関しては```
1
```アルゴリズムは次のように出力します。```
2
```長さ 1 のシーケンスにはチェックするペアがないため、自動的にハングリーになります。 

次のような小さな入力の場合```
2
```アルゴリズムは次のように出力します。```
2 3
```順番が増えてきて、`3 % 2 != 0`, したがって、条件が成り立ちます。 

最大入力の場合```
100000
```アルゴリズムは単純に最初のものを取得します`100000`ふるいからの素数。 最後に選択された素数はまだ下にあります`10^7`、値の制約を満たします。 選択されたすべての数値は別個の素数であるため、どのペアも割り算条件に違反しません。 

間違った解法による一般的な失敗例は、連続した整数を使用することです。```
2 3 4
```どこ`4`で割り切れます`2`。 

すべての要素が素数であり、別の素数より大きい素数はその素数で割り切れないため、私たちの構築ではこれを完全に回避します。
