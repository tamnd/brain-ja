 ## 解決策
 ## 問題の理解

 次の 2D グリッドが与えられます。`n`行と`m`列。 各セルは、塔を設置できる空か、塔を建てられない穴のいずれかです。 タワーには 2 種類あります。青いタワーは常に人口 100 を提供し、赤いタワーは 200 を提供しますが、少なくとも 1 つの青いタワーに隣接するセルにのみ配置できます。 また、任意のタワーを破壊して再構築することもできます。これは、赤いタワーの配置を可能にするために戦略的に役立つ可能性があります。 目標は、グリッド内のタワーの総数を最大化することです。 

問題の制約は中程度です。`n`そして`m`最大 500 まで指定できるため、セルの総数は 250,000 に達する可能性があります。 大まかに動作するアルゴリズムが必要です`O(n*m)`時間; 空のセルの数の二次関数はすでに遅すぎる可能性があります。 操作数`k`最大 10^6 まで可能ですが、最適な母集団をもたらす有効なシーケンスを自由に生成できるため、これに限定されません。 

明らかではないエッジ ケースには、1 つのセルを除いて穴によって完全にブロックされたグリッドや、最初に戦略的に青いタワーを配置した後にのみ赤いタワーを配置できる構成が含まれます。 たとえば、赤のタワーに隣接するセルがないため、単一の孤立した空のセルには青のタワーしか保持できません。 最初にどこにでも赤い塔を配置しようとする不用意なアプローチは、このシナリオでは失敗します。 

## アプローチ

 素朴なアプローチは、すべての空のセルを反復処理し、許可されている場所に赤いタワーを配置してから、残りのセルを青いタワーで埋めることです。 これは小さなグリッドでは機能しますが、大きなグリッドでは失敗します。 複雑さは本質的には`O(n*m)`配置チェックごとに実行されますが、赤いタワーの隣接性チェックは複数回繰り返すことができ、再構築を繰り返すと操作が実用的な限界を超える可能性があります。 さらに、このアプローチでは、より多くの赤いタワーを有効にするために青いタワーをより適切に配置する構成を見逃す可能性があるため、人口の最大化は保証されません。 

重要な洞察は、グリッドを二部構成のような問題として見ることです。 青いタワーは隣接するセルの赤いタワーを有効にします。 人口を最大化するには、すべての赤いタワーに隣接する青いタワーが 1 つだけ必要です (同じ赤いタワーに複数の青いタワーを隣接させる必要はありません。人口が増加しないためです)。 空のセルをノードとして扱い、エッジが隣接する空のセルを接続する場合、エッジのサブセットを選択して、一方の側に青のタワーを配置し、もう一方の側に赤のタワーを配置し、残りの空のセルを青のタワーで埋める必要があります。 この構造は貪欲に解決できます。チェッカー盤パターンでセルを反復し、ある色に青いタワーを配置し、次に反対色の隣接する空のセルに赤いタワーを配置します。 

この観察により、すべてのシーケンスを試行するのではなく、系統的に貪欲な配置を行うことで問題が軽減され、セル数の線形時間計算量が保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n*m)^2) | O(n*m) | 遅すぎる |
 | 貪欲なチェッカーボード + 隣接 | O(n*m) | O(n*m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを解析し、すべての空のセルにマークを付けます。 空のリストを初期化して操作を記録します。 
2. 以下を使用して、グリッドを市松模様に繰り返します。`(i + j) % 2`色を交互に変更します。 1 つのパリティの空のすべてのセルに対して、青いタワーを配置し、操作を記録します。 これにより、各青いタワーが隣接する赤いタワーを潜在的に有効にすることが保証されます。 
3. すべての青いタワーを配置したら、残りの空のセルを繰り返します。 空の各セルについて、その 4 つの隣接セルをチェックします。 少なくとも 1 つの隣人が青いタワーを持っている場合は、そこに赤いタワーを置き、操作を記録します。 
4. 残った空のセル (どの青にも隣接していない) は青のタワーで埋められ、未使用のセルがないようにして人口を最大化します。 
5. 各操作に続く操作の合計数を順番に出力します。 

これが機能する理由: すべての赤いタワーは青いタワーに隣接することが保証されており、すべての空のセルは少なくとも 100 人の人口に貢献します。 チェッカーボード パターンにより、冗長な Blue 配置なしで最大限の隣接性が保証され、最適に近い人口構成が得られます。 操作を最小限にする必要がないため、隣接ルールが満たされている限り、配置の順序は任意でかまいません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
grid = [list(input().strip()) for _ in range(n)]

ops = []
blue = [[False] * m for _ in range(n)]

# Step 1: Place Blue towers on checkerboard
for i in range(n):
    for j in range(m):
        if grid[i][j] == '.' and (i + j) % 2 == 0:
            ops.append(f'B {i+1} {j+1}')
            blue[i][j] = True
            grid[i][j] = 'B'

# Step 2: Place Red towers adjacent to Blue
for i in range(n):
    for j in range(m):
        if grid[i][j] == '.':
            for dx, dy in [(-1,0),(1,0),(0,-1),(0,1)]:
                ni, nj = i + dx, j + dy
                if 0 <= ni < n and 0 <= nj < m and blue[ni][nj]:
                    ops.append(f'R {i+1} {j+1}')
                    grid[i][j] = 'R'
                    break

# Step 3: Fill remaining empty cells with Blue
for i in range(n):
    for j in range(m):
        if grid[i][j] == '.':
            ops.append(f'B {i+1} {j+1}')
            grid[i][j] = 'B'

print(len(ops))
print('\n'.join(ops))
```このソリューションでは、まずパリティ ベースのパターンを使用して青いタワーのグリッドを確立します。 次に、適格な隣人をレッドタワーに変換します。 最後に、残った空のセルは青いタワーで埋められます。 すべての配置は`ops`出力用のリスト。 の選択`(i + j) % 2`隣接する 2 つの青いタワーが不必要に配置されないことが保証され、作成される赤いタワーの数が最適化されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n*m) | 各セルは一定の回数アクセスされます。青の配置で 1 回、赤の隣接チェックで 1 回、残りのセルを埋めるために 1 回です。 |
