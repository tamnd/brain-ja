 ## 解決策
 ## 問題の理解

 参加者のセットが与えられ、それぞれが 2 つの数字で表されます。 これら 2 つの数字は、2 人トレーニング コンテストで参加者が最初のタスクを解決したのか 2 番目のタスクを解決したのかに応じて、参加者がどれだけのペナルティを課すかを表します。 2 人の参加者がチームを形成する場合、チームの合計ペナルティを最小限に抑える方法で 2 つの問題を自分たちの間で割り当てます。 

ペア用$(i, j)$、可能な割り当ては 2 つあります。 もし$i$最初のタスクを解決し、$j$2 番目を解決すると、コストは$x_i + y_j$。 役割を交換した場合のコストは$x_j + y_i$。 チームは常に、これら 2 つのオプションのうち安価な方を選択します。 

ただし、すべてのペアが許可されるわけではありません。 禁止されたペアのリストも与えられますが、それらのペアがチームを形成することはありません。 すべての参加者について、すべての有効なパートナーにわたる最適なチームコストの合計を計算する必要があります。 

入力サイズは大きく、最大 300,000 人の参加者と 300,000 の禁止ペアが可能です。 これにより、すべてのペアを明示的に評価する二次アプローチが即座に除外されます。$O(n^2)$作戦は制限時間をはるかに超えてしまうだろう。 各ペアの最小値を個別に再計算するなど、隠れた二次動作を伴うアプローチでも失敗します。 

微妙な問題は、ペアの最適な割り当てが、ペア間の比較のみに依存することです。$x_i + y_j$そして$x_j + y_i$、比較すると書き換えることができます。$x_i - y_i$そして$x_j - y_j$。 この削減が問題の重要な構造です。 

注目に値するエッジケースには、すべてのペアが禁止されている状況、全員の答えが自明にゼロである場合、または禁止されたペアが存在しない場合、つまりすべての参加者が他の参加者とペアになる状況が含まれます。 もう 1 つの重要なケースは、2 人の参加者が非常に大きな正または負の値を持っている場合です。 単純な合計は、慎重に扱わないと 64 ビット整数をオーバーフローさせる可能性があります。 

## アプローチ

 ブルートフォース手法ではすべての有効なペアが考慮されます$(i, j)$、2 つの可能な割り当ての最小値を計算し、その結果を両方の参加者の合計に加算します。 これは簡単です。ペアごとに定数時間式を評価するため、正確さがすぐにわかります。 ただし、$n$最大 300,000 ペアの数は$n^2$、大まかに言うと$10^{10}$実行可能な限界をはるかに超えた操作。 

重要な観察は、コスト関数が書き換え後に単純化されるということです。 定義する$d_i = x_i - y_i$。 次に:

 もし$d_i \le d_j$、最適な割り当ては次のとおりです。$i \to \text{first}, j \to \text{second}$、コストを与える$x_i + y_j$。 それ以外の場合は、割り当てます$j \to \text{first}, i \to \text{second}$、コストを与える$x_j + y_i$。 

これは、決定は、による注文のみに依存することを意味します。$d_i$、生の値を個別に扱うのではありません。 参加者を分類すると、$d_i$、すべての相互作用は構造化されます。どのペアについても、この順序に対する接頭辞と接尾辞の合計を使用して寄与を表現できます。 

すべてのペアが存在すると単純に仮定することはできないため、禁止されたエッジは複雑な問題を引き起こします。 代わりに、すべてのペアが存在するかのように答えを計算し、禁止されたペアの寄与を差し引きます。 グラフ全体の構造は密ですが、除外はまばらです。これは、包含-除外と並べ替えおよびプレフィックス合計を組み合わせたものが効果的になる古典的な設定です。 

各参加者について、ソートされた順序を使用して他の参加者に対する寄与度を計算します。 次に、同じ式を使用してペアの寄与を明示的に減算することで、禁止されたペアを修正します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | ソート + プレフィックス合計 + 修正 |$O(n \log n + m)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 完全な相互作用の合計を計算し、次に禁止された相互作用を削除するという 2 つのフェーズで処理を進めます。 

1. コンピューティング$d_i = x_i - y_i$参加者ごとに。 この値により、順序付けとスワップの決定が決まります。 
2. 参加者を並べ替える$d_i$。 これにより、どのペアでも$i < j$、私たちは知っています$d_i \le d_j$、割り当てルールの方向を修正します。 
3. プレフィックスの合計を構築する$x$そして$y$ソートされた順序で。 これらにより、特定のインデックスの前後ですべての参加者の合計を高速に計算できます。 
4. 参加者ごとに$i$、すべてのペアが許可されると仮定して、他のすべてに対するその合計寄与度を計算します。 

以前の参加者の方へ$i$、$i$最適なペアリングでは常に 2 番目の問題が割り当てられます。 その後の人たちのために$i$、最初の問題が割り当てられます。 これは次の順序から直接得られます。$d$-価値観。 
5. プレフィックス合計を使用して貢献度を蓄積します。$O(1)$方向ごとに。 
6. 禁止されたペアの寄与を減算します。 禁止されたペアごとに$(u, v)$、次を使用して正確なペアのコストを計算します。$$\min(x_u + y_v, x_v + y_u)$$そしてそれを両方の参加者の合計から差し引きます。 
7. 最終累積値を元の順序で出力します。 

重要な考え方は、並べ替えによってペアごとの決定が一貫した方向性ルールに変換され、プレフィックス合計によってグローバル ペア集計が定数時間クエリに変換されるということです。 

### なぜ効果があるのか

 で並べ替えた後、$d_i = x_i - y_i$、すべてのペアには固定の最適な方向があります。$d$常に最適な割り当ての最初のタスクを引き受けます。 これにより、ペアごとの決定から曖昧さが取り除かれ、問題は位置に基づいて寄与をカウントすることに変わります。 

各参加者の合計は、すべての小さな要素とすべての大きな要素からの寄与という 2 つの線形集計の合計となります。 これらはプレフィックス合計によって完全にキャプチャされます。$x$そして$y$。 禁止されたペアはスパースであるため個別に処理され、各修正はすでにグローバルに決定されている同じローカル比較ルールにのみ依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    x = [0] * n
    y = [0] * n

    for i in range(n):
        x[i], y[i] = map(int, input().split())

    order = list(range(n))
    order.sort(key=lambda i: x[i] - y[i])

    pos = [0] * n
    for i, idx in enumerate(order):
        pos[idx] = i

    xs = [x[i] for i in order]
    ys = [y[i] for i in order]

    pref_x = [0] * (n + 1)
    pref_y = [0] * (n + 1)

    for i in range(n):
        pref_x[i + 1] = pref_x[i] + xs[i]
        pref_y[i + 1] = pref_y[i] + ys[i]

    ans = [0] * n

    for i in range(n):
        p = pos[i]

        left_count = p
        right_count = n - p - 1

        left_sum_y = pref_y[p]
        right_sum_x = pref_x[n] - pref_x[p + 1]

        ans[i] += left_sum_y + right_sum_x

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1

        cost = min(x[u] + y[v], x[v] + y[u])
        ans[u] -= cost
        ans[v] -= cost

    print(*ans)

if __name__ == "__main__":
    solve()
```実装では、まず決定ルールを単一の順序に圧縮します。$x_i - y_i$。 ソート後、プレフィックス合計により、参加者の両側のすべての要素からの寄与を一定時間で計算できます。 貢献度の計算式はきれいに分割されます。参加者全員が対象となります。$i$、彼らだけ$y$貢献する。 結局のところ$i$、彼らだけ$x$貢献します。 

禁止されたペアに対する修正ループは、これらのエッジがグローバル集計に含まれているため、不可欠です。 各削除は両方のエンドポイントに対して対称的に行われます。 

実装によくある落とし穴は、どちらの側が貢献するかを混同することです。$x$そしてどれが貢献するか$y$。 ソートされた順序により、どのような場合でも$i < j$、最適な割り当ては常に次のようになります。$i$最初のタスクと$j$2番目。

 ## 特殊なケース

 特殊なケースとしては、すべてのペアが禁止されている場合があります。 その場合、蓄積フェーズでは依然として完全な密な寄与が計算されますが、すべてのペアは 1 回だけ削除されます。 潜在的なインタラクションがすべて差し引かれるため、各参加者はゼロになります。 

もう 1 つのケースは、すべての参加者が非常に似ている場合です。$x - y$価値観。 この場合、並べ替えによってそれらはあまり分離されませんが、割り当てルールの正確さを変更することなく同順位を任意に配置できるため、等価性によって順序付けの仮定が崩れることはなく、プレフィックス ロジックは引き続き機能します。 

3 番目のケースには、次のような極端な値が含まれます。$x_i = 10^9$そして$y_i = -10^9$。 ペアの貢献度は以下に達します$2 \cdot 10^9$、多数の参加者の合計には 64 ビット整数が必要です。 Python を使用するとオーバーフローを回避できますが、C++ ではこれが必要です。`long long`全体を通して。
