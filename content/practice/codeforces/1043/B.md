 ## 解決策
 ## 問題の理解

 一連のプレフィックス値が与えられます`a[0], a[1], ..., a[n]`どこ`a[0] = 0`。 シーケンスはもともと非表示の配列から生成されました`x`長さの`k`、しかしその配列はもう利用できません。 

生成ルールは単純で、次の値がそれぞれ存在します。`a[i]`前のプレフィックスの合計を取得して形成されます`a[i-1]`そして次の要素を 1 つ追加します`x`、循環的に選択されます。 具体的にはステップでの付加価値`i`のみに依存する`x[(i-1) mod k]`。 これは、一連の増分を意味します。`a`周期性があり周期的である`k`。 

次のすべての可能な値を見つけるように求められます。`k`何らかの整数配列が存在するような`x`長さの`k`これにより、指定されたプレフィックス合計配列が生成される可能性があります。 

入力サイズ`n`は最大でも 1000 です。これは、`O(n^2)`解決策は受け入れられます。 再構築を試みるあらゆるソリューション`x`候補者ごとに独立して`k`一貫性が問題なく通過することを確認します。 構造は周期性制約によってすでに完全に決定されているため、サブセットまたは順列にわたる指数関数的なものは不要です。 

重要な点は次のとおりです`x`は正または有界であるように制約されません。 これにより、多くの典型的なプレフィックスサム制約が削除され、決定要素として等価構造のみが残ります。 

よくある失敗例の 1 つは、条件を特定の構築されたコンポーネントが必要であると誤解することから発生します。`x`。 たとえば、次のように仮定します。`x[i] = a[i] - a[i-1]`直接動作するのは次の場合のみです`k = n`。 小さめの場合`k`、 同じ`x`値は複数の位置で再利用する必要があるため、インデックス間の一貫性が実際の要件です。 

別の微妙なエッジケースが現れるのは、`k = 1`。 この場合、すべての違いが同一である必要があります。 これを明示的にチェックすることを忘れた実装では、差異が一定ではない配列を誤って受け入れることがよくあります。 

## アプローチ

 最初の自然なアイデアは、それぞれの候補の長さを試してみることです`k`隠し配列を明示的に再構築します`x`。 仮定すると`x[j] = a[j+1] - a[j]`初めて`k`位置を取得したら、完全な配列の構築をシミュレートし、指定された配列と比較できます。`a`。 これは正しいですが、シミュレーションを繰り返して実装すると非効率的です。`k`までシミュレーションすることができます`O(n)`につながるステップ`O(n^2)`全体的なアプローチ。 

ただし、視点を変えることで問題を単純化することができます。 再構築という観点から考えるのではなく、`x`、一連の違いを見ていきます。`d[i] = a[i] - a[i-1]`。 このシーケンスはまさに次のパターンの繰り返しです。`x`。 そこで問題は次のとおりです。`k`周期を伴う差分配列です`k`?

 これにより、タスクが直接的な周期性チェックに変換されます。 固定の場合`k`、あらゆるポジション`i`満たさなければなりません`d[i] = d[i-k]`。 これがすべての有効な場合に当てはまる場合`i`、 それから`k`有効です。 

ブルートフォースアプローチでは、この状態をそれぞれ個別にチェックします。`k`、毎回比較を再計算します。 それぞれのチェックは`O(n)`、完全な解決策は次のとおりです`O(n^2)`。

 ## アルゴリズムのチュートリアル

 考えられるすべての周期長をテストすることで問題を解決します`k`。 

1. 差分配列を計算する`d`、 どこ`d[i] = a[i] - a[i-1]`。 これにより、隠し配列に対応する繰り返しパターンが分離されます。`x`。 差分を抽出すると、プレフィックスの合計は必要なくなります。 
2. 可能なすべての値を反復処理します。`k`から`1`に`n`。 それぞれ`k`を期間長の候補として扱います。 
3.固定の場合`k`、それが有効であると仮定し、差分配列全体の一貫性を検証します。 あらゆるインデックスに対して`i`から始まる`k+1`に`n`、どうかを確認してください`d[i] == d[i-k]`。 
4. 不一致が見つかった場合は、これを拒否します`k`すぐに。 これにより、真の周期構造のみを受け入れることが保証されます。 
5. すべての比較が成功した場合は、次の値を追加します。`k`回答リストに追加します。 
6. すべての候補をチェックした後、収集された有効な値を昇順に出力します。 

### なぜ効果があるのか

 重要な不変条件は、差分配列が毎回正確に繰り返される必要があるということです。`k`長さに由来する場合の位置-`k`循環配列`x`。 それぞれだから`d[i]`に直接対応する`x[(i-1) mod k]`、すべての要素の間隔が等しい`k`離れていれば必要かつ十分です。 不一致が存在する場合、割り当ては行われません。`x`それぞれの立場が一致しているため、矛盾を調整することができます。`x`2 つの異なる値を取ることを強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [0] + list(map(int, input().split()))

    d = [0] * (n + 1)
    for i in range(1, n + 1):
        d[i] = a[i] - a[i - 1]

    res = []

    for k in range(1, n + 1):
        ok = True
        for i in range(k + 1, n + 1):
            if d[i] != d[i - k]:
                ok = False
                break
        if ok:
            res.append(k)

    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```実装は、巡回構造が明確になるように差分配列を再構成することから始まります。 これにより、検証中にプレフィックス合計を繰り返し処理することが回避されます。 

コアループはあらゆる可能なことを試みます`k`各要素を正確に比較することで周期性をチェックします`k`その後ろのポジション。 矛盾が見つかった場合に不要な作業を防ぐため、早めの休憩が重要です。 

インデックス付けには注意が必要です。ここでは、差分配列は 1 から始まり、次の接頭辞のインデックス付けと一致します。`a`、関係を単純化します`d[i] = a[i] - a[i-1]`。

 ## 特殊なケース

 最小限の入力`n = 1`は重要です。`k = 1`は自明に有効です。 失敗する比較がないため、アルゴリズムはこれを自然に処理します。`1`が常に含まれています。 

すべての違いが同一の場合、すべての`k`が有効になります。 すべての比較のため、アルゴリズムはすべての値を正しく受け入れます。`d[i] == d[i-k]`常に保持します。 

交互または構造化されたパターンの場合は、より小さい`k`値が大きいほど成功する一方で、失敗する可能性もあります。 不一致は位置合わせが崩れた場所に正確に現れ、完全な再構築を必要とせずに即座に拒否が行われるため、定期的なチェックはこれを正確に捕捉します。
