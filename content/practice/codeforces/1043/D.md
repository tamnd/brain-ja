 ## 解決策
 ## 問題の理解

 同じ人々のセットに関するいくつかの異なる観察が与えられます。各観察は同じものの完全な順序付けです。$n$要素。 各観察者は完全な順列を見ましたが、視点が一貫していないため、同じ要素の相対的な位置が順列ごとに異なります。 

タスクは、すべての順列内の連続したブロックを選択することです。 順列ごとに一部のプレフィックスと一部のサフィックスを個別に削除できますが、シーケンスとして読み取られる場合、残りの中間セグメントはすべての順列にわたって同一である必要があります。 セグメントは空であってはならず、さまざまな選択肢は、その切断方法ではなく、結果として得られるシーケンスのアイデンティティによってカウントされます。 

したがって、本当の問題は、与えられたすべての順列にわたって共通の連続部分配列として現れる別個の配列がいくつあるかということです。同じ配列がすべての順列で連続セグメントとして出現する必要があり、場合によっては順列ごとに異なる位置に出現する必要があります。 

制約は厳しいです:$n$まで上がります$10^5$、 その間$m \le 10$。 これは、すべての順列のすべての部分配列を列挙することに依存する解決策は不可能であることを直ちに示唆しています。なぜなら、単一の順列にはすでに$O(n^2)$サブアレイ。 1 つの候補セグメントをすべての順列に対して検証するだけでも、すべての出現を繰り返しスキャンすると、$O(n^2 m)$行動。 

構造上の重要な点は、各順列に各値が 1 回だけ含まれるため、すべての値の位置が順列ごとに一意に定義されることです。 これにより、問題は部分文字列の一致から、順列にわたる相対的な順序付けの制約へと移行します。 

いくつかの特殊なケースで、答えの性質が明らかになります。 

すべての順列が同一の場合、すべての部分配列は有効であるため、答えは次のようになります。$n(n+1)/2$。 「共通のプレフィックス」または「整列されたウィンドウ」のみを考慮する単純なアプローチでは、ほとんどのセグメントが見逃されてしまいます。 

もし$m = 1$、やはりすべての連続したセグメントが有効です。 相互置換の一貫性を強制する方法は、答えを誤って制限することになります。 

順列が相互に完全に逆の場合、セグメントが長くなるとどこかで順序の一貫性が崩れてしまうため、単一の要素のみが有効なセグメントになり得ます。 

## アプローチ

 ブルートフォースのアイデアは、最初の順列でセグメントを選択することから始まります。$[l, r]$次に、まったく同じシーケンスが他のすべての順列で連続ブロックとして現れるかどうかを確認します。 これは、そのシーケンスの各順列をスキャンすることで実行できます。 ハッシュ化しても、$O(n^2)$候補者と各検証コストは少なくとも$O(n)$高度な前処理を行わないと、$O(n^3)$最悪の場合。 ローリング ハッシュを使用する場合でも、複数のシーケンスにわたるすべての部分文字列をチェックすることは境界線に達し、複雑になります。$n = 10^5$。 

主な観察点は、実際にはシーケンスを直接比較する必要がないということです。 各数値は各順列で 1 回だけ出現するため、セグメントはその端点によって完全に決定され、その有効性は順列全体にわたる要素の相対的な順序にのみ依存します。 

2 つの要素を修正することを検討してください$x$そして$y$。 有効なセグメントの場合、$x$前です$y$1 つの順列では、前になければなりません$y$そうしないと、連続するセグメントに両方を一貫した順序で含めることができません。 これにより、問題は、相対順序がすべての順列にわたって一貫している範囲を見つけることに変換されます。 

より有用な再定式化は、すべての順列を最初の順列の座標系にマッピングすることです。 あらゆる価値観に対して$v$、各順列でその位置を保存します。 その後、任意の間隔で$[l, r]$順列 1 では、その中の値のセットが、位置を通して投影されたときに他のすべての順列で連続した間隔を形成するかどうかを確認します。 

これは、スライディング ウィンドウのアイデアにつながります。つまり、右のエンドポイントを拡張し、他の並べ替えごとに、現在のウィンドウ内の要素の最小位置と最大位置を維持します。 ウィンドウは、すべての順列において、これらの要素の画像が連続ブロックを形成する場合にのみ有効です。つまり、最大位置から最小位置を引いた値がウィンドウ サイズから 1 を引いた値に等しいことを意味します。 

順列 1 のウィンドウを維持し、展開ごとに更新します$m$(最小、最大) のペア。 有効性が崩れると、左側の境界を縮小します。 

各右端点で終わる有効なウィンドウの数から、個別のセグメントの数がわかります。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$|$O(n)$| 遅すぎる |
 | 位置追跡機能付きスライディング ウィンドウ |$O(nm)$|$O(nm)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. アレイを構築する`pos[p][v]`値の位置を保存する$v$順列で$p$。 これにより、任意の順列における要素の順序の定数時間比較が可能になります。 
2. 順列 0 を参照順序として固定し、その上で右ポインタを繰り返します。 値を含めるたびに$x$、その位置を他のすべての順列の現在のウィンドウ追跡に挿入します。 
3. 各順列について$p > 0$、現在ウィンドウ内にある要素の最小位置と最大位置の 2 つの値を維持します。 これは、選択した要素が順列のどこにあるかを要約します。$p$。 
4. 新しい要素を右ポインタに挿入した後、すべての順列が満たされるかどうかを確認します。`max_p - min_p == window_size - 1`。 この条件により、順列において次のことが保証されます。$p$、選択されたすべての要素は、ギャップのない単一の連続ブロックを占めます。 
5. いずれかの順列がこの条件に違反する場合は、左ポインタを前方に移動してウィンドウから要素を削除し、有効性が回復するまですべての min 構造と max 構造を適宜更新します。 
6. ウィンドウが有効になった後、次で終わるすべてのサブ配列が無効になります。`right`そしてどこからでも始めてください`left`に`right`有効な共通セグメントであり、貢献しています`(right - left + 1)`答えに。 

### なぜ効果があるのか

 いつでも、ウィンドウは一連の値を表します。 すべての順列でこれらの値が連続した間隔を占める場合、そのセット内の順序はすべての順列にわたって保持されるため、一貫した相対順序が形成されます。 順列 0 はこれらの値の実際のシーケンス順序を定義するため、ウィンドウのすべての連続したセグメントが回答候補に対応します。 逆に、順列の位置にギャップがある場合、その順列のプレフィックスとサフィックスだけを削除してもセットを作成できないため、有効になりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    perms = [list(map(int, input().split())) for _ in range(m)]

    pos = [[0] * (n + 1) for _ in range(m)]
    for p in range(m):
        for i, v in enumerate(perms[p]):
            pos[p][v] = i

    from collections import deque

    left = 0
    ans = 0

    min_pos = [0] * m
    max_pos = [0] * m

    for right in range(n):
        x = perms[0][right]

        for p in range(m):
            px = pos[p][x]
            if right == left:
                min_pos[p] = max_pos[p] = px
            else:
                min_pos[p] = min(min_pos[p], px)
                max_pos[p] = max(max_pos[p], px)

        def valid():
            for p in range(m):
                if max_pos[p] - min_pos[p] != right - left:
                    return False
            return True

        while not valid():
            y = perms[0][left]
            for p in range(m):
                # recompute by scanning window (m small, n large, acceptable)
                # reset bounds
                min_pos[p] = n
                max_pos[p] = -1
            left += 1
            for i in range(left, right + 1):
                v = perms[0][i]
                for p in range(m):
                    px = pos[p][v]
                    min_pos[p] = min(min_pos[p], px)
                    max_pos[p] = max(max_pos[p], px)

        ans += (right - left + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、各置換における各値の位置を事前に計算することに依存しており、これがスキャンを繰り返さずに比較を可能にする中心的な構造です。 

スライディング ウィンドウは最初の順列に基づいて構築され、候補セグメントの正規の順序として扱われます。 右エンドポイントの展開ごとに、順列ごとの最小位置と最大位置を更新します。 有効性が崩れると、左から縮小して現在のウィンドウの境界を再計算します。 この再計算は許容できる理由です。$m \le 10$、ポインタの移動の合計数は線形のままです。 

微妙な点は、有効性が次を使用してチェックされていることです。`right - left`、ウィンドウ サイズから別途導出された 1 を引いたものではありません。 これにより、ウィンドウが包括的になるため、off-by-one の混乱が回避されます。

 ## 特殊なケース

 同一の順列の場合、インデックスのすべてのサブセットがすべての順列で連続したブロックを形成するため、ウィンドウは決して縮小しません。 アルゴリズムが拡張される`right`予想されるものと一致する、可能なすべてのサブ配列を完全に累積します。$n(n+1)/2$。 

逆順列の場合、1 より大きいサイズのウィンドウは最終的に 2 番目の順列の位置範囲にギャップを生成し、単一の要素だけが残るまで即時縮小を強制します。 

のために$m = 1$の場合、連続するブロックは 1 つの順列で自明に連続するため、妥当性条件は常に満たされます。 このアルゴリズムは、他の制約からの干渉なしに 1 つの配列内のサブ配列をカウントすることに帰着します。
