 ## 解決策
 ## 問題の理解

 正の整数の順序付けされたトリプルを数える必要があります$(a,b,c)$2 つの独立した制約を満たします。 

最初の制限はペア積を制限します。$$ab + ac + bc \le n$$2 番目の制限は合計を制限します。$$a + b + c \le x$$「順序付けられた」という言葉が重要です。 もし$(1,1,2)$有効であれば、$(1,2,1)$そして$(2,1,1)$は別々にカウントされます。 

入力には複数のテスト ケースが含まれています。 受け取るテストケースごとに$n$そして$x$、有効なトリプルの数を出力する必要があります。 

制約が本当の手がかりです。 1 つのテストでできることは、$n,x$と同じくらい大きい$10^6$、ただしすべての合計$n$入力全体の値は最大でも$10^6$、およびすべての合計$x$値も最大です$10^6$。 

すべての可能な値に対する三次検索$a,b,c$全く不可能です。 までのすべての値に対する二次探索でも、$10^6$大きすぎるでしょう。 の構造を利用する必要があります。$$ab + ac + bc$$検索スペースを大幅に制限します。 

簡単な間違いの 1 つは、変数が厳密に正でなければならないことを忘れることです。 例えば：```
n = 1, x = 10
```可能な最小値は次のとおりであるため、有効なトリプルはありません。$$ab+ac+bc$$正の整数の場合は$1+1+1=3$。 

もう 1 つの微妙なケースは、合計限界が巨大で事実上無関係である場合に発生します。```
n = 7, x = 1000
```答えが決まるわけではありません$x$。 有効なトリプルはすべて、積の不等式のみから得られます。 値を最大で反復するソリューション$x$膨大な時間を無駄にするでしょう。 

3 番目のよくあるバグは、順列を同一のものとして扱うことです。 のために```
n = 7, x = 4
```有効なトリプルは次のとおりです$$(1,1,1), (1,1,2), (1,2,1), (2,1,1)$$それは答えを与えます$4$、 ない$2$。 

## アプローチ

 最も直接的なアイデアはブルートフォースです。 ポジティブなものをすべて列挙する$a$、すべてのポジティブ$b$、すべてのポジティブ$c$、両方の不等式をチェックし、有効なトリプルを数えます。 

すべての候補者が一度だけ検査されるため、これは明らかに正しいです。 

残念ながら、最大の値だけを考慮したとしても、$10^6$の場合、検索スペースは次のようになります。$$10^{18}$$トリプル。 それは到底実現不可能です。 

重要な観察は、一度、$a$そして$b$が固定されている場合、両方の制約は単純な上限になります。$c$。 

から$$ab + ac + bc \le n$$私たちは得る$$c(a+b) \le n-ab$$したがって$$c \le \frac{n-ab}{a+b}.$$以来$c$整数でなければなりません、$$c \le \left\lfloor \frac{n-ab}{a+b} \right\rfloor.$$合計制限により、$$c \le x-a-b.$$したがって、固定ペアの場合$(a,b)$、有効な値の数$c$単純に$$\min\!\left( \left\lfloor \frac{n-ab}{a+b} \right\rfloor, x-a-b \right)$$この量が正の場合。 

ここで問題はペアを数えることになります$(a,b)$。 

すべてを繰り返すことを避ける必要があります$10^{12}$可能なペア。 積の不等式自体が強い制限を与えます。 以来$c\ge1$、$$ab+a+b \le n.$$並べ替えると、$$b(a+1) \le n-a.$$したがって$$b \le \frac{n-a}{a+1}.$$大型用$a$、この上限はすぐに小さくなります。 検査されるペアの総数は約$$\sum_{a=1}^{n} \frac{n}{a} = O(n\log n).$$全部の合計だから$n$入力全体の値は$10^6$、この高調波系列の複雑さは簡単に十分に高速です。

 ## アルゴリズムのチュートリアル

 1. 答えをゼロに初期化します。 
2. すべての正の値を繰り返します。$a$。 
3. 現在のところ$a$、可能な最大値を計算します$b$それでも多少はプラスになる可能性はある$c$。 

から$ab+a+b\le n$、$$b \le \left\lfloor \frac{n-a}{a+1} \right\rfloor.$$から$a+b+c\le x$と$c\ge1$、$$b \le x-a-1.$$これら 2 つの境界の最小値を取得します。 
4. 反復する$b$から$1$その最大値まで。 
5. 製品ベースの制限を計算します。$c$:$$c_1= \left\lfloor \frac{n-ab}{a+b} \right\rfloor.$$6. 合計ベースの制限を計算します。$c$:$$c_2=x-a-b.$$7. すべての整数$c$範囲内で$$1 \le c \le \min(c_1,c_2)$$は有効なので追加します$$\min(c_1,c_2)$$答えに。 
8. 全てのペアが終わったら$(a,b)$処理が完了したら、蓄積された回答を出力します。 

### なぜ効果があるのか

 固定ペアの場合$(a,b)$、元の両方の不等式は独立して上限を生成します。$c$。 の値$c$両方の境界を同時に満たす場合にのみ有効です。 許容最大値$c$したがって、 は 2 つの制限値の最小値になります。 

すべての有効なトリプルは 1 つのペアに正確に対応します$(a,b)$と 1 つのカウント値$c$。 のすべてのカウント値$c$は、元の不等式を両方とも構築によって満たします。 これにより、カウントされるオブジェクトと有効なトリプルの間に 1 対 1 の対応関係が確立されるため、アルゴリズムは多すぎも少なすぎもカウントしません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, x = map(int, input().split())

        total = 0

        a = 1
        while True:
            b1 = (n - a) // (a + 1)
            b2 = x - a - 1
            bmax = min(b1, b2)

            if bmax < 1:
                if b1 < 1:
                    break
                a += 1
                continue

            for b in range(1, bmax + 1):
                c1 = (n - a * b) // (a + b)
                c2 = x - a - b
                total += min(c1, c2)

            a += 1

        ans.append(str(total))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```外側のループは、次の可能な値を反復します。$a$。 表現```
(n - a) // (a + 1)
```必要条件から直接得られる$ab+a+b\le n$、少なくとも 1 つの正の値が保証されます。$c$存在することができる。 

セカンドバウンド```
x - a - 1
```ポジティブのための余地を必要とすることから来ます$c$合計制約内で。 

有効なペアごとに$(a,b)$、コードは 2 つの独立した上限を計算します。$c$。 許容される値の数は、2 つの限界のうち小さい方となります。 

よくある間違いは、次のことを忘れることです。$c$ポジティブである必要があります。 の境界$b$を仮定して導出されます$c\ge1$、これが、数式に余分な値が含まれている理由です。$+a+b$条件だけではなく$ab$。 

Python の整数は、サイズを超える可能性がある大きな答えを自動的に処理します。$2^{31}$。
