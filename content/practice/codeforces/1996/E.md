 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、その連続するセグメントをすべて調べます。 各セグメント自体には多くのサブセグメントが含まれており、0 の数が 1 の数と等しいサブセグメントのみに注目します。 

文字列内のより大きな間隔を選択するたびに、それに含まれるバランスの取れたサブセグメントの数をカウントします。 次に、すべての可能な間隔にわたってこの値を合計します。 これを理解する別の方法は、すべてのバランスのとれたサブセグメントが多くの囲み区間に寄与しており、それらすべての寄与を効果的に合計していることです。 

直接的な解釈では、すでに大量の繰り返しカウントが示唆されています。 すべての部分文字列が潜在的な候補とみなされ、それを囲む間隔ごとに再度追加されます。 外側の間隔と内側の部分文字列の数は両方とも二次関数的にスケールされるため、文字列の長さが 200000 に達すると、それらを明示的に列挙するソリューションは遅すぎます。 

素朴な考えでは、セグメントを修正してその中のすべてのサブセグメントをスキャンしようとしますが、これは三次的な動作につながります。 セグメントの数自体は依然として 2 次であるため、プレフィックス合計を使用して内部チェックを最適化しても、私たちは救われません。 問題の構造により、カウント順序を再解釈する必要があります。 

単純な推論による微妙な失敗例は、文字列が一様な場合に現れます。たとえば、`"0000"`。 バランスのとれた部分文字列はまったくないので、答えはゼロです。 ただし、カウントの差を誤って処理しようとする不注意な実装 (たとえば、外側の間隔ごとの寄与を減算せずにプレフィックスの等価性を誤ってカウントするなど) は、空の条件を二重にカウントするために依然としてゼロ以外の値を蓄積する可能性があります。 

重要な問題は、各有効な部分配列が一度だけではなく、それを含む外側の間隔の数に比例して寄与すること、そして 2 つの間隔層間のこの結合を解きほぐす必要があることです。 

## アプローチ

 ブルートフォース手法では、すべての間隔を列挙します。$(l, r)$、次にすべての部分間隔を列挙します$(x, y)$その中にある 0 と 1 が等しいかどうかを確認します。 プレフィックス合計を使用すると、チェック自体は定数時間になりますが、間隔のペアの数は変わりません。$O(n^3)$。 と$n$まで$2 \cdot 10^5$、これはまったく不可能です。 

改善するには視点を逆転させます。 外側の間隔を固定して内側の間隔を数える代わりに、候補部分配列を固定し、それが含まれる外側の間隔の数を数えます。 サブアレイ$(x, y)$すべてに含まれています$(l, r)$そのような$l \le x$そして$r \ge y$。 このような外側の間隔の数は位置にのみ依存します。$x$そして$y$、と等しい$x \cdot (n - y + 1)$。 

したがって、問題はすべてのバランスのとれた部分配列の合計に帰着します。$$\sum_{x \le y, \; s[x..y]\text{ balanced}} x \cdot (n - y + 1).$$残りのタスクは、すべてのバランスの取れたサブ配列を効率的に列挙することです。 これは古典的なプレフィックス合計の再定式化です: マップ`0 → -1`そして`1 → +1`。 サブ配列は、プレフィックスの合計の差がゼロの場合に正確にバランスが取れています。 したがって、プレフィックスの合計が一致する位置のすべてのペアを考慮する必要があります。 

させて$p[i]$プレフィックスの合計になります。 それぞれの値について$v$、その出現がインデックスにあると仮定します$i_1 < i_2 < \dots < i_k$。 任意のペア$(i_a, i_b)$と$a < b$バランスのとれた部分配列を定義します$(i_a + 1, i_b)$。 このような各サブ配列は以下に寄与します。$$(i_a + 1) \cdot (n - i_b + 1).$$したがって、各プレフィックス合計値を個別に処理し、プレフィックス集約を使用して、グループごとに線形時間ですべてのペアのこの合計を計算します。 

重要な観察は、固定された右エンドポイントの場合、二次列挙を回避するために左エンドポイントの累積和を維持できるということです。

 ## アルゴリズムのチュートリアル

 1. バイナリ文字列をプレフィックス合計配列に変換します。`0`-1になり、`1`+1になります。 これにより、「0 と 1 の数が等しい」という条件が「2 つの位置でのプレフィックスの合計が等しい」に変換されます。 
2. すべてのプレフィックスの合計を計算する$p[0], p[1], \dots, p[n]$から始まる$p[0] = 0$。 
3. プレフィックス合計値が等しいグループ インデックス。 各グループは、ランニングバランスが同一であるすべてのポジションに対応します。 
4. インデックスの各グループについて$i_1, i_2, \dots, i_k$、すべてのペアのプロセス貢献度$(i_a, i_b)$、 どこ$a < b$、それらを明示的に列挙することなく。 
5. 左端の合計とこれまでに確認された出現数という 2 つの実行値を維持しながら、インデックスを昇順にスイープします。 右エンドポイントとして扱われる新しいインデックスごとに、前に確認したプレフィックス インデックスを使用してその寄与を追加します。 
6. 正しいエンドポイントの場合$i_b$、前の各インデックス$i_a$貢献する$(i_a + 1) \cdot (n - i_b + 1)$。 因数分解$(n - i_b + 1)$したがって、次の合計だけが必要です。$(i_a + 1)$グループプレフィックスの上に。 
7. 結果のモジュロを累積します。$10^9+7$。 

### なぜ効果があるのか

 この変換により、バランスのとれた部分文字列がプレフィックスの合計と等しくなります。 すべての有効な部分文字列は、等しいプレフィックス合計位置のペアに一意に対応します。 寄与関数は、左端点のみに依存する項と右端点のみに依存する項の積にきれいに分離されます。 この分離性により、増分累積が可能になります。右エンドポイントを処理するときに、有効な左エンドポイントがすべて既知であるため、それらの寄与を再検討することなく合計できます。 これにより、すべての有効なサブ配列が正確に 1 回だけカウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)

        # prefix sum positions grouped by value
        groups = {}

        cur = 0
        groups.setdefault(0, []).append(0)

        for i, ch in enumerate(s, start=1):
            cur += 1 if ch == '1' else -1
            groups.setdefault(cur, []).append(i)

        ans = 0

        for pos in groups.values():
            if len(pos) < 2:
                continue

            pref_sum_left = 0
            count = 0

            for i in pos:
                if count > 0:
                    right_factor = (n - i + 1)
                    ans = (ans + pref_sum_left * right_factor) % MOD

                pref_sum_left += (i + 1)
                count += 1

        print(ans % MOD)

if __name__ == "__main__":
    solve()
```実装では、各プレフィックス合計値が出現するすべてのインデックスを収集するプレフィックス合計を構築します。 各グループについて、左から右にスイープします。 右端点として扱われる各位置で、左端点の累積合計 (部分文字列の開始寄与に一致するように +1 シフト) に、右境界への可能な拡張の数を掛けます。 これは、アルゴリズムで導出された因数分解された寄与と直接一致します。 

インデックス作成には注意が必要です。 プレフィックス配列は便宜上 0 から始まる位置を使用しますが、部分文字列のエンドポイントはプレフィックス インデックスを実際のセグメント境界に変換することに依存します。`(i + 1)`左側のエンドポイントに表示され、`(n - i + 1)`右側の拡張数の場合。 

## 実用的な例

 ### 例 1:`010`プレフィックスの合計は次のとおりです。 

| インデックス i | プレフィックスの合計 |
 | --- | --- |
 | 0 | 0 |
 | 1 | -1 |
 | 2 | 0 |
 | 3 | -1 |

 ポジションをグループ化します:

 0 → [0, 2]

 -1 → [1, 3]

 グループ 0 の場合:

 | そうだよ | プレフ_合計_左 | 貢献 |
 | --- | --- | --- |
 | 2 | 1 | (1 * (3 - 2 + 1)) = 2 |

 グループ -1 の場合:

 | そうだよ | プレフ_合計_左 | 貢献 |
 | --- | --- | --- |
 | 3 | 2 | (2 * 1) = 2 |

 合計 = 4。 

これは、各グループがどのように独立しており、寄与がペアの列挙ではなくプレフィックス合計を介して集約されるかを示しています。 

### 例 2:`1100`プレフィックスの合計:

 | 私 | p[i] |
 | --- | --- |
 | 0 | 0 |
 | 1 | 1 |
 | 2 | 2 |
 | 3 | 1 |
 | 4 | 0 |

 グループ:

 0 → [0, 4]

 1 → [1, 3]

 2 → [2]

 グループ 0 は以下に貢献します。 

(0,4) → (1 * 1) = 1

 グループ 1 は以下に貢献します。 

(1,3) → (2 * 2) = 4

 合計 = 5。 

これは、複数のバランスの取れた部分文字列が重なり合っている場合でもどのようにキャプチャされるか、またプレフィックスの合計によってグループ化することでそれらの欠落や二重カウントがどのように回避されるかを示しています。

 ## 特殊なケース

 次のような完全に均一な文字列`"0000"`単純な一致を超えるプレフィックス合計の衝突は生成されないため、初期状態を除いてすべてのグループのサイズは 1 になります。 このアルゴリズムはシングルトン グループをスキップするため、寄与は追加されず、結果はゼロのままとなり、正しい動作と一致します。 

次のような完全に交互の文字列`"0101"`多くの繰り返しプレフィックス合計が作成されます。 グループ化メカニズムにより、すべての等しいプレフィックス ペアが確実にキャプチャされ、各ペアはその左右の位置に基づいて寄与されます。 各右エンドポイントは、以前に確認された左エンドポイントを 1 回だけ処理するため、スイープの累積により、重複する平衡サブストリングが二重にカウントされないことが保証されます。
