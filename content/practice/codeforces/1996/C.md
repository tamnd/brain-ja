 **解決時間:** 2 分 35 秒

 ## 解決策
 ## 問題の理解

 2 つの文字列が与えられています。`a`そして`b`、同じ長さの`n`。 各クエリについて、範囲によって定義されます`[l, r]`の個々の文字を変更することができます。`a`その範囲内で。 目標は部分文字列を変換することです`a[l..r]`辞書順に並べ替えると、並べ替えられた部分文字列と一致するようになります。`b[l..r]`。 クエリごとに必要な文字変更の最小数を決定する必要があります。 

制約が示すのは、`n`そして`q`それぞれが最大に達することができます`2·10^5`すべてのテストケースにわたって、最大で`1000`テストケース。 これにより、クエリごとに O(n) 時間で各部分文字列を検査またはシミュレートするアプローチは即座に除外されます。最悪の場合、次のことが実行されるからです。`O(q·n) = 4·10^10`操作。 

明らかではないエッジケースには、以下の範囲が含まれます。`a`すでに一致しています`b`並べ替えると、長さ 1 の範囲、または文字が繰り返される範囲。 たとえば、次の場合`a = "abc"`そして`b = "cba"`、範囲の場合`[1,3]`、`sorted(a) = sorted(b) = "abc"`なので操作は必要ありません。 間の差異を直接カウントする素朴なアプローチ`a`そして`b`並べ替えを行わないと、誤って 3 つの操作が提案されてしまいます。 

もう 1 つの微妙な点は、正確な文字位置ではなく、ソートされた部分文字列のみを考慮していることです。 これにより、文字の頻度を一致させることができます。`a[l..r]`に`b[l..r]`個々の立場を再配置するのではなく。 

## アプローチ

 ブルートフォースアプローチでは、各クエリを個別に検査し、両方をソートします。`a[l..r]`そして`b[l..r]`、不一致の文字の数を数えます。 これは原理的には機能しますが、クエリごとに各部分文字列をソートするには O(k log k) が必要です。`k = r - l + 1`。 最大限に`k ~ 2·10^5`そして`q ~ 2·10^5`、これは不可能になります。 

重要な洞察は、並べ替えによって問題が文字の頻度のカウントに軽減されるということです。 次の部分文字列内の各文字の頻度がわかっている場合、`a`そして`b`、変更の最小数は、次の文字数を計算することで決定できます。`a`～に対して「過剰」である`b`。 より具体的に言うと、文字ごとに、`a`以上のものを持っています`b`部分文字列内の余剰部分は変更する必要があります。 これにより、問題が文字列全体の文字数のプレフィックス合計に変換され、範囲ごとに O(1) 頻度のクエリとクエリごとに O(26) の操作が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q・k log k) | O(k) | 遅すぎる |
 | 最適 | O(n + q・26) | O(n・26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 両方の文字列の文字頻度のプレフィックス合計を事前計算します。`a`そして`b`。 のために`a`、`freq_a[c][i]`文字数を保存します`c`で`a[1..i]`。 に対しても同じことを行います`b`。 
2. クエリごとに`[l, r]`、接頭辞の合計を減算して、部分文字列内の各文字の頻度を計算します。`count_a[c] = freq_a[c][r] - freq_a[c][l-1]`そして同様に`b`。 
3. 「a」から「z」までの各文字について、次の場合`count_a[c] < count_b[c]`、つまり`count_b[c] - count_a[c]`の文字`a`に変更する必要があります`c`。 すべての文字についてこれらの値を合計して、最小の操作数を取得します。 
4. この合計をクエリごとに出力します。 

これが機能する理由は、ソートされた部分文字列が文字数のみに依存するためです。 それぞれの欠落文字`a`に対して`b`変更を介して導入する必要があります。 余分な文字`a`欠落しているものを置き換えるために自然に使用され、操作の総数が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = input().strip()
        b = input().strip()
        
        # Prefix frequency arrays
        freq_a = [[0] * (n + 1) for _ in range(26)]
        freq_b = [[0] * (n + 1) for _ in range(26)]
        
        for i in range(1, n + 1):
            for c in range(26):
                freq_a[c][i] = freq_a[c][i-1]
                freq_b[c][i] = freq_b[c][i-1]
            freq_a[ord(a[i-1]) - ord('a')][i] += 1
            freq_b[ord(b[i-1]) - ord('a')][i] += 1
        
        for _ in range(q):
            l, r = map(int, input().split())
            ops = 0
            for c in range(26):
                count_a = freq_a[c][r] - freq_a[c][l-1]
                count_b = freq_b[c][r] - freq_b[c][l-1]
                if count_a < count_b:
                    ops += count_b - count_a
            print(ops)

if __name__ == "__main__":
    solve()
```プレフィックス配列を使用すると、クエリごとに O(1) 個の文字数を取得できます。 各クエリに対して 26 文字すべてを繰り返しますが、制約を考慮すると許容範囲内です。 境界処理`l-1`1 から始まる範囲に対しても接頭辞の減算が確実に機能するようにします。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q・26) | O(n・26) でプレフィックスの合計を事前計算します。 各クエリは O(26) で演算を計算します。 |
 | スペース | O(n・26) | 26 文字の頻度プレフィックスの合計を n 位置に保存します。 |
