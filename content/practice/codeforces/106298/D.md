 ## 解決策
 ## 問題の理解

 整数間隔のコレクションが与えられます。 各間隔は許容値の範囲を表し、GCD のような制約の下ですべての間隔にわたって一貫して動作する単一の整数が存在するかどうかを判断しようとしています。 

この問題は、すべての間隔が「厳密」であるか、または少なくとも 1 つの間隔が単一の固定値に集約されるかどうかに応じて、2 つの異なる領域に分割されます。 すべての間隔が正の長さである場合、つまり左端が右端よりも厳密に小さい場合、単一の強制値は存在しません。 この場合、出力は単純にすべて偶数になります。これは、問題の構造が、入力の詳細とは無関係に均一な答えに退化することを意味します。 

興味深いケースは、少なくとも 1 つの区間が 1 つの点に縮退する場合に現れます。これは、ある i について li が ri に等しいことを意味します。 その状況では、その値はアンカー X になります。X を素因数に因数分解し、そのような素数 p ごとに一貫性条件を確保する必要があります。つまり、すべての間隔に p の少なくとも 1 つの倍数が含まれている必要があります。 これがどの素数についても不可能な場合、その素数についての構築は失敗します。 

計算の観点から見ると、区間の数は大きくなる可能性があるため、どのソリューションでも区間と因子チェックの間の二次相互作用を回避する必要があります。 ドミナント演算は、n に単一の数値の因数分解コストを加えた線形である必要があります。 これにより、すべての間隔内のすべての候補値を明示的にチェックすることが除外されます。 

複数の固定間隔が存在する場合、微妙なエッジ ケースが発生します。 li が ri に等しいような i が複数ある場合、それらはすべて同じ X を表す必要があります。そうでない場合は、一貫したアンカーがまったく存在しません。 たとえば、ある区間で X = 12 が強制され、別の区間で X = 18 が強制される場合、因数分解する共有の基本値がないため、問題は直ちに矛盾します。 

別のエッジ ケースは、間隔が固定されていないが、出力ルールで「すべて偶数」となっている場合に発生します。 単純な実装では、とにかく間隔から何かを計算しようとして一貫性のない結果が生成される可能性がありますが、正しい動作はこのブランチの入力構造から完全に独立しています。 

## アプローチ

 直接的な総当たりアプローチでは、間隔によって暗示されるすべての可能な候補整数をテストしようとします。 任意の区間エンドポイントに現れるすべての値、または固定区間内のすべての値を反復して、各候補が区間 [li, ri] ごとにその中に必要な各素数の倍数が存在するという条件を満たすかどうかをチェックすることもできます。 

サイズ 10^9 の 1 つの区間でも候補が多すぎるため、これはすぐに実行不可能になります。 エンドポイントに限定したとしても、すべての間隔に対して各候補を検証する必要があり、最悪の場合は O(n^2) チェックが必要になります。 

重要な観察は、単一の強制値 X が存在する場合、その周囲で構造全体が崩壊するということです。 すべての候補を探索する代わりに、X を割る素数だけを考慮する必要があります。問題は、そのような素数 p ごとに、すべての区間に p の少なくとも 1 つの倍数が含まれているかどうかを検証することになります。 これにより、問題は値の検索から割り切れる範囲のチェックに変わります。 

区間 [l, r] の場合、それに p の倍数が含まれているかどうかをチェックすることは、l 以上の p の最小倍数がまだ r 内にあるかどうかをチェックすることと同じです。 これは間隔ごとに O(1) で実行できます。 したがって、X が固定されると、検証全体が n において線形になります。

 | --- | --- | --- | --- |
 | 候補者に対するブルーフォース | O(n · R) 以上 | お(1) | 遅すぎる |
 | 固定 X + 素数を確認する | O(n + sqrt(X)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 強制値があるかどうかを検出します

すべての間隔をスキャンします。 すべての間隔が li < ri を満たす場合、特定の値を固定する間隔はないため、必要に応じてすぐにすべての偶数を出力します。 

少なくとも 1 つの間隔が li = ri を満たす場合、その値を記録します。 このような間隔が複数存在する場合、それらはすべて一致する必要があります。 そうしないと、単一の X が 2 つの異なる固定制約を満たすことができないため、答えは不可能になります。 

### 2. アンカー値 X を抽出します。 

有効な固定間隔が存在することがわかったら、X をその値に等しく設定します。 複数の固定間隔が存在する場合は、それらすべてを X と比較することで一貫性を検証します。 

このステップが必要なのは、後のすべての推論が X が明確に定義されているかどうかに依存するためです。 一貫したアンカーがなければ、因数分解は無意味です。 

### 3. X を素因数分解します

 X の素因数分解を計算し、X を分割するすべての異なる素数 p を収集します。これらの素数は、問題の残りの部分で重要な唯一の制約を表します。 

個別の素数のみを考慮する理由は、p が X を割る場合、指数に関係なく、すべての区間に p の倍数が存在することを保証すれば十分だからです。 

### 4. 間隔全体にわたる各素数のカバレッジを確認する

 各素数 p について、すべての区間 [l, r] をチェックします。 l 以上の p の最初の倍数、つまり ((l + p - 1) // p) * p を計算します。 この値が r を超える場合、間隔には p の倍数が含まれず、p は無効になります。 

いずれかの素数がこのチェックに失敗すると、その X の構築は失敗します。 

### 5. 集計結果

 すべての素数が間隔カバレッジ テストに合格した場合、設定が受け入れられます。 それ以外の場合は拒否されます。 

### なぜ効果があるのか

 このアルゴリズムは、X を分割する素数によって定義される等差数列の範囲を検証することに問題を集約します。重要な不変条件は、有効な解は X によって引き起こされる割り算制約を尊重する必要があり、これらの制約は素数全体で独立しているということです。 X のすべての整数倍は同時に各素因数の倍数であるため、素数ごとのカバレッジを確保することは、X 自体のカバレッジを確保することと同等です。 間隔チェックは、必要な素数のすべての倍数を除外する間隔がないことを保証します。そうでないと、実現可能性が損なわれてしまいます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def factorize(x):
    primes = []
    d = 2
    while d * d <= x:
        if x % d == 0:
            primes.append(d)
            while x % d == 0:
                x //= d
        d += 1
    if x > 1:
        primes.append(x)
    return primes

def ok(intervals, p):
    for l, r in intervals:
        first = ((l + p - 1) // p) * p
        if first > r:
            return False
    return True

def solve():
    n = int(input())
    intervals = []
    fixed = None

    for _ in range(n):
        l, r = map(int, input().split())
        intervals.append((l, r))
        if l == r:
            if fixed is None:
                fixed = l
            elif fixed != l:
                print("NO")
                return

    if fixed is None:
        print("EVEN")
        return

    X = fixed
    primes = factorize(X)

    for p in primes:
        if not ok(intervals, p):
            print("NO")
            return

    print("YES")

if __name__ == "__main__":
    solve()
```解決策は、すべての間隔を解析し、固定点が存在するかどうかを識別することから始まります。 複数の固定間隔の一貫性チェックは、矛盾が後のステージに伝播するのを避けるために直ちに処理されます。 

因数分解ルーチンは、sqrt(X) までの標準的な試行除算です。 X は入力エンドポイントから直接導出されるため、一般的な制約の下でも効率的です。 

キーの検証手順は次のようにカプセル化されています。`ok`この関数は、各間隔内の各素数の最初に到達可能な倍数を計算します。 これにより、すべての倍数を明示的に反復処理することが回避されます。 

最終的な決定は 3 つのケースに明確に分岐します。固定間隔がない場合は偶数出力になり、固定間隔が一貫していない場合は拒否され、有効な X は素数ごとの検証になります。

 ## 特殊なケース

 重要なエッジケースの 1 つは、複数の固定間隔が一致しない場合です。 入力に ​​[5,5] と [7,7] が含まれているとします。 アルゴリズムは最初に fix = 5 を検出し、7 に遭遇するとすぐに拒否し、無効な因数分解ステップを防ぎます。 これにより、不可能なアンカーの構築が回避されます。 

もう 1 つのケースは、X が素数の場合です。 たとえば、X = 13 は素数 = [13] になります。 このアルゴリズムは、すべての間隔に 13 の倍数が少なくとも 1 つ含まれているかどうかをチェックします。1 つの間隔でも完全に 1 と 12 の間、または 13 の倍数以外の範囲にある場合、チェックは直ちに失敗します。 これは、単一素因数分解によって問題が周期シーケンスの純粋な区間範囲に縮小されることを示しています。
