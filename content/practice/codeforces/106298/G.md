 ## 解決策
 ## 問題の理解

 私たちはバイナリ文字列を扱っていますが、重要な構造は個々の文字ではなく、等しい文字の連続したセグメントです。 連続する各最大セグメント`0`または連続した`1`s はブロックを形成します。 たとえば、次の文字列`0001110011`4 つのブロックで構成されます。`000`、`111`、`00`、 そして`11`。 

許可される変換ルールは、これらのブロックに関して説明されます。 ブロックを完全に消すことはできませんが、その長さは柔軟です。 ブロックは任意に伸縮できます。つまり、ブロックに含まれる文字数は変更できますが、ブロックを削除したり、隣接するブロックとマージしたりすることはできません。 重要なのは、ブロックの順序とその開始値です。 

文字列を変換する条件`a`文字列に`b`ブロック構造を比較するだけです。 両方の文字列のブロック数が同じで、最初のブロックの値が同じであれば、一方をもう一方に変換できます。 

したがって、入力はテスト ケースごとに 2 つのバイナリ文字列で構成され、出力はブロック保持ルールに基づいて変換が可能かどうかの決定になります。 

ステートメント スニペットでは制約が明示的に指定されていませんが、この形式の問題では通常、テスト ケースごとに最大約 10^5 以上の文字列が許可されます。 これにより、変換をシミュレートしたり、中間文字列を構築しようとしたりするソリューションは即座に除外されます。 どのアプローチでも、各文字列を線形スキャンとテスト ケースごとの定数または対数比較に削減する必要があります。 

単純な間違いは、文字列を直接比較したり、文字列の数だけを比較したりすることです。`0`と`1`s. 構造が重要であるため、どちらも失敗します。 例えば、`0011`そして`0101`0 と 1 の数は同じですが、ブロック構造が異なり、許可された一連の操作が交互の構造を一致させることはできません。 

もう 1 つの微妙なエッジ ケースは、単一文字の文字列です。 例えば、`0`に変換できます`0000`、 しかし`0`に変換できません`1`たとえ両方の長さが 1 であっても、開始ブロックが異なるためです。 

## アプローチ

 これを考える強引な方法は、文字列内のブロックのサイズを変更する可能なすべての方法をシミュレートすることです。`a`そして文字列を一致させようとしています`b`。 各ブロックは自由に拡大または縮小できますが、所定の位置に留まらなければならないため、意味のある唯一の状態は文字列をブロックに分割することです。 ブルートフォースシミュレーションでは、各ブロックに長さを割り当てようとします。`a`合わせる`b`。 最悪の場合、両方の文字列に n 文字が含まれる場合、O(n) 個のブロックが存在し、すべての代入または位置合わせを試みると、隣接するブロック間の依存関係により、指数関数または少なくとも 2 次のマッチング ロジックに退化します。 これは、n が 10^4 程度の場合でもすぐに実行不可能になります。 

重要な観察は、ブロック境界が決して変わらないということです。 ブロックは破棄したり結合したりできないため、有効な変換ではすべてブロック タイプの正確な順序が保持されます。 唯一の自由は各ブロックの長さ内です。 これは、変換の問題全体が、2 つのランレングス エンコーディング間の構造的等価性チェック、つまり交互の文字のシーケンスが同一かどうかの比較に集約されることを意味します。 

これにより、問題は、両方の文字列のランレングス エンコーディングを計算し、両方のシーケンスの長さと文字の両方が正確に一致するかどうかを確認するだけになります。

 ## アルゴリズムのチュートリアル

 各文字列を一連のブロックに圧縮して処理します。 

1. スキャン文字列`a`左から右に向かってランレングスエンコーディングを構築します。 現在のキャラクターが前のキャラクターと異なるたびに、ブロックを閉じて新しいブロックを開始します。 長さは変換とは無関係であるため、各ブロックの長さではなく、各ブロックの文字のみを保存します。 
2. 文字列に対して同じプロセスを繰り返します`b`、そのブロックシーケンスを生成します。 
3. 両方のシーケンスのブロック数を比較します。 それらが異なる場合、禁止されているマージまたは分割を行わずにブロック構造を調整する方法はありません。 
4. 両方の文字列の開始文字を比較します。 最初のブロックは値が一致する必要があるため、ここで不一致があるとすぐに変換が不可能になります。 
5. 各ブロックの位置を比較します。 の位置 i にあるすべてのブロック`a`の対応するブロックと同じ文字が必要です。`b`。 不一致が発生すると変換できなくなります。 
6. すべてのチェックに合格した場合、変換は可能であると判断します。 

これで十分な理由は、ブロック境界が固定されると、各ブロックが独立して動作するためです。 ブロックを任意に拡大または縮小できるため、シーケンス パターンが一致する限り、対応するブロックの長さを常に一致させることができます。 

### なぜ効果があるのか

 不変条件は、バイナリ文字列の最大均一セグメントへの分割は一意に決定され、許可された操作の下では変更できないということです。 操作ではブロックがマージされたり破壊されたりすることはないため、有効な変換ではブロック ID の正確なシーケンスが保存されなければなりません。 したがって、2 つの文字列は、ランレングスでエンコードされた文字シーケンスが同一である場合に限り、操作規則の下では等価です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def rle(s: str):
    blocks = []
    n = len(s)
    i = 0
    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1
        blocks.append(s[i])
        i = j
    return blocks

def solve():
    t = int(input())
    for _ in range(t):
        a = input().strip()
        b = input().strip()

        ra = rle(a)
        rb = rle(b)

        if ra == rb:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```このソリューションは、各文字列のランレングス署名を直接構築します。 ヘルパー関数は各文字列を 1 回スキャンして、一連のブロック識別子を生成します。 その後、比較は単純なリストの等価性チェックに縮小されます。 

実装の微妙な点は、ブロック長をまったく保存しないことです。 この問題ではブロックが任意に拡大または縮小することが明示的に許可されているため、これは安全です。 長さを保存するとノイズが増えるだけであり、誤った比較が行われる危険性があります。 

正確さは、各ブロック内の実際の数ではなく、隣接構造が不変であるという事実に完全に依存します。 

## 実用的な例

 ### 例 1

 検討してください`a = 0001110`そして`b = 001110`。 

のために`a`、ブロックは次のとおりです。 

| ステップ | インデックス範囲 | ブロック |
 | --- | --- | --- |
 | 1 | 0-2 | 0 |
 | 2 | 3-5 | 1 |
 | 3 | 6-6 | 0 |

 それで`ra = [0, 1, 0]`。 

のために`b`、ブロックは次のとおりです。 

| ステップ | インデックス範囲 | ブロック |
 | --- | --- | --- |
 | 1 | 0-1 | 0 |
 | 2 | 2-4 | 1 |
 | 3 | 5-5 | 0 |

 それで`rb = [0, 1, 0]`。 

シーケンスが一致するため、出力は次のようになります。`YES`。 

これにより、ブロック長の違いは問題ではないことがわかります。 

### 例 2

 しましょう`a = 010`そして`b = 001`。 

のために`a`、ブロックは`[0, 1, 0]`。 

のために`b`、ブロックは`[0, 1]`。 

| 文字列 | ブロックシーケンス |
 | --- | --- |
 | | [0, 1, 0] |
 | b | [0, 1] |

 ブロック数が異なるため変換できないため、出力は`NO`。 

これは、合計数が類似している場合でも、交互が一致しないと実現可能性が損なわれることを示しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    def rle(s: str):
        blocks = []
        i = 0
        while i < len(s):
            j = i
            while j < len(s) and s[j] == s[i]:
                j += 1
            blocks.append(s[i])
            i = j
        return blocks

    t = int(sys.stdin.readline())
    for _ in range(t):
        a = sys.stdin.readline().strip()
        b = sys.stdin.readline().strip()
        output.append("YES" if rle(a) == rle(b) else "NO")
    
    return "\n".join(output)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、両方の文字列が単一の繰り返し文字で構成されている場合です。 例えば、`a = 0000`そして`b = 0`。 アルゴリズムは両方を 1 つのブロックに圧縮します`[0]`したがって、出力は次のようになります`YES`。 これは、ブロック長が無関係であるという事実を反映しています。 

もう 1 つのエッジ ケースは、文字列のカウントが同じである場合です。`0`そして`1`しかし、次のような異なる交代パターン`0011`そして`0101`。 最初に生成されるのは`[0, 1]`一方、2番目は生成します`[0, 1, 0, 1]`、即座に変換を拒否します。 アルゴリズムは圧縮中に境界情報を決して失わないため、これを正確に捕捉します。 

最後のエッジケースは、次のような単一文字列を交互に配置することです。`010101`対`0101010`。 両方が似ているように見えても、ブロック数は 1 つ異なります。アルゴリズムは比較ステップでそれを拒否し、ブロック構造が同一でなければならないという不変条件に一致します。
