 ## 解決策
 ## 問題の理解

 私たちは一列に並んだ一連のドアを与えられています。 各ドアには、そのドアの「強度」または「コスト」として解釈できる番号が関連付けられています。 最初のドアの前からスタートして、できるだけ前に進むように努めます。 ルールは単純です。可能な限りドアを通過し続けますが、行き詰まった場合、つまり次のセグメントを通過できない場合は、通過したばかりのセグメントでこれまでに確認された最も重要なブロック値を「リセット」する操作を実行する必要があります。 

より具体的に言い換えると、このプロセスは配列を左から右に繰り返しスキャンすることになります。 進歩の概念を蓄積し、現在の値で前進できる限り、続行します。 現在の状態では進行を継続できなくなる位置に到達すると、停止し、最後のリセット以降にセグメント内で発生した最大値を特定し、その値をゼロにリセットします。 その後、再度スキャンを続行します。 

出力は、ブロッキング セグメントがなくなった後の最終状態、または解釈に応じて、実行された操作の数または変換された配列と同等です。 この問題では、意図した結果は、失敗した各トラバースで最も制約の多いドアを繰り返し「破る」後の最終構成です。 

この制約は、大きなセグメントにわたって単純に繰り返されるフル スキャンをシミュレートできないことを意味します。 配列サイズが次のサイズに達した場合$10^5$その場合、失敗するたびにスキャンを最初から再開するソリューションにはリスクが伴います。$O(n^2)$最悪の場合の動作は、一般的な 2 秒の制限の下では遅すぎます。 セグメント最大値の効率的な特定と効率的な更新を可能にする構造が必要です。 

いくつかのエッジケースは、素朴な思考がどこで崩れるかを明らかにします。 

1 つのケースは、配列が厳密に減少している場合です。 入力例:`[5, 4, 3, 2, 1]`。 単純なスキャンは、「通過できない」の解釈によっては最初のステップですぐに中断し、縮小プレフィックスの現在の最大値を繰り返し選択する可能性があります。 正しい動作では、最初の障害点だけでなく、各完全なパスがアクティブなセグメントの最大値を確実に特定する必要があります。 

もう 1 つのケースは、すべての値が等しい場合です。たとえば、`[3, 3, 3, 3]`。 アルゴリズムがセグメントの真の最大値ではなく、最初のブロック値のみを誤ってリセットすると、残留値が残り、不必要なエラーが発生し続ける可能性があります。 

3 番目のケースは、セグメントの終わりで最大値が発生する場合です。 単純な実装が障害点までの最大値のみを追跡する場合、同じスキャン ウィンドウで後で表示される真の最大値を見逃してしまう可能性があります。 

これらの問題により、ダイナミック レンジ全体で常に最大値を取得し、それを効率的に更新できる構造を維持する必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 説明どおりにプロセスを正確にシミュレートします。 現在のセグメントを維持しながら、左から右にスキャンを繰り返します。 スキャン中に、これまでに確認された最大値を追跡します。 続行が許可されなくなった点に到達した場合は、スキャンを停止し、セグメントの最大値を取得してゼロに設定し、最初からスキャンを再開します。 

これはプロセス定義を直接反映しているため、これは正しいです。 障害ポイントは常に、現在のトラバースで最も重要なブロック要素のリセットを強制するため、これを忠実に繰り返すことで、最終的にはすべての障害が除去されます。 

問題はパフォーマンスです。 最悪の場合、各パスで除去される要素は 1 つだけになる可能性があり、各パスでスキャンが行われます。$O(n)$要素。 これにより、$O(n^2)$が鈍くなるにもほどがあります。$n = 10^5$。 

重要な洞察は、各操作は連続領域内の最大要素のみに依存し、その最大値が削除されると、再び寄与することはないということです。 これは、最初から再スキャンするのではなく、現在の最大値をすばやく抽出して削除済みとしてマークできる構造内にアクティブな値のセットを維持する必要があることを示唆しています。 優先キューまたはマルチセットを使用すると、何がまだアクティブであるかを追跡しながら、残っている最大の「ブロッキング ドア」を繰り返し特定して排除することができます。 

これにより、繰り返されるスキャン プロセスが最大要素の削除のシーケンスに変換され、それぞれが対数時間で処理されます。

 ## アルゴリズムのチュートリアル

 このプロセスは、残っている最も強力な障害物を繰り返し特定し、それを除去することであると解釈します。 

1. すべての値をそのインデックスとともに、最大値を抽出できる構造に格納します。 通常、これは最大ヒープです。 インデックスが必要な理由は、抽象化された値だけでなく、実際の要素を確実に削除する必要があるためです。 
2. 訪問済みまたは削除されたマーカー配列のサイズを初期化します。$n$、最初はすべて false です。 これは、どのドアがすでに「壊れた」かを追跡します。 
3. すべてのペアを含む最大ヒープを構築する$(value, index)$。 負の値を保存して、Python の最小ヒープを使用して最大ヒープをシミュレートします。 
4. ヒープが空でない間に、現在の最大候補を抽出します。 
5. この要素がすでに削除されている場合は、スキップして続行します。 これにより、古いヒープ エントリが回避されます。 
6. それ以外の場合は、この要素を削除済みとしてマークし、最終構造で概念的にゼロに「リセット」します。 
7. すべての要素が処理されるまで続行します。 

重要な推論ステップは、各反復で最も重要な残りの障害物が除去され、その領域内の主要なブロック要素が除去されると、以降の操作はより小さい値に依存しないということです。 

### なぜ効果があるのか

 どの時点でも、セグメント内のさらなる進行を妨げる可能性がある唯一の要素は、そのセグメント内の最大の要素です。 その要素が削除されると、その要素が課す制約は完全に消え、より小さな要素でそのブロック状態を再現することはできなくなります。 これにより、このプロセスが、現在の構造内に残っているアクティブな要素の中でグローバル最大値を繰り返し削除することと同等であることが確立されます。 すべての削除によりアクティブ セットが厳密に削減され、順序付けの制約が保持されるため、プロセスは、ブロッキング最大値がそれ以上残らない安定した構成に収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))

    # max heap via negative values
    heap = [(-a[i], i) for i in range(n)]
    heapq.heapify(heap)

    removed = [False] * n

    while heap:
        neg_val, idx = heapq.heappop(heap)
        if removed[idx]:
            continue
        removed[idx] = True
        a[idx] = 0

    print(*a)

if __name__ == "__main__":
    solve()
```この実装は、最大要素を繰り返し抽出するという考えに直接従っています。 ヒープには値とインデックスの両方が保存されるため、古いエントリを安全に無視できます。 の`removed`配列により、ヒープ状態の重複により同じ位置が複数回処理されることがなくなります。 

微妙な点は、値を「破る」と決めた瞬間にのみ値をゼロに設定することです。 同じインデックスを参照している以前のヒープ エントリはすべて古くなり、`removed`チェックにより、誤った二重処理を防ぎます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、配列に要素が 1 つしかない場合です。 ヒープには単一のエントリが含まれており、それはすぐに削除され、結果は正しくゼロに更新されます。 これは、アルゴリズムが機能するために要素の「ペア」を必要としないことを確認します。 

別のケースでは、等しい最大値が繰り返されます。 ヒープ エントリにはインデックスが含まれるため、各出現箇所は独立して処理されます。 の`removed`配列により、1 つのインスタンスが処理されると、そのインデックスの重複ヒープ エントリがすべて無視され、二重削除が防止されます。 

最後のケースは、すでにゼロの配列です。 ヒープは引き続きエントリを処理しますが、すべての削除は単純にゼロを書き換えます。 すでにゼロの要素を削除しても正確さに副作用がないため、アルゴリズムは安定したままになります。
