 ## 解決策
 ## 問題の理解

 私たちは、「サブツリーのみ」または「パスのみ」のような単一の単純なパターンに従わない更新によってすべてのノードが影響を受ける可能性があるルート付きツリーに取り組んでいます。 代わりに、更新はその効果を 2 つの構造的に異なる領域 (ノードの完全なサブツリーとノードの直接の子のみ) に分割します。 クエリでは、このような更新を多数行った後、すべてのノードにわたる最大累積値が求められます。 

より具体的には、各操作は、あるノードのサブツリー内のすべてのノードに値を追加するか、ノードの直接の子にのみ値を追加します。 これらの一連の変更の後、すべてのノード間の最大値を計算する必要があります。 

問題はアップデート自体ではなく、重複構造にあります。 サブツリーの更新は、DFS の意味で大きな連続領域に影響しますが、「子のみ」の更新はサブツリーではなく、標準のオイラー間隔に対応しません。 この問題はツリー上のデータ構造の問題となり、2 つの異なる構造関係を線形でクエリ可能なものにマッピングする必要があります。 

この制約は、ノードと操作の数の両方が十分に大きいため、サブツリーの更新ごとの走査が不可能であることを意味します。 サブツリーの更新ごとにすべての子孫をたどる単純なアプローチでは、ルートでの 1 つの更新がほぼすべてのノードに繰り返し影響するため、星型ツリーでは 2 次時間まで劣化します。 

ノードに多くの子があるが深さが浅い場合、微妙なエッジ ケースが発生します。 たとえば、ノード 1 が他のすべてのノードに接続されている場合、ノード 1 の「子の更新」は、ノード 1 自体を除くほぼツリー全体に影響します。 これをサブツリーの更新として誤って解釈したり、隣接関係を繰り返し再計算したりする単純な実装では、これらの寄与が過大評価または過小評価されます。 

もう 1 つの注意が必要なケースは、更新の重複です。 最初に x をルートとするサブツリーに追加し、その後 x の子に追加すると、x の下の深さ 2 にあるノードはサブツリーの更新のみを受け取りますが、直接の子は両方を受け取ります。 これら 2 つの効果を 1 つのオイラー区間にマージする誤った平坦化では、誤った最大値が生成されます。 

## アプローチ

 ブルートフォースアプローチは簡単です。 更新ごとに、影響を受けるノードを明示的に走査します。 サブツリーの更新では、ノードから DFS が実行され、訪問されたすべての頂点に値が追加されます。 子の更新は、ノードの隣接リストを反復して、各隣接ノードを更新します。 

これは各操作の定義と直接一致するため、正しいです。 ただし、コストは法外なものになります。 最悪の場合、サブツリーには O(n) 個のノードが含まれる可能性があり、そのような操作を O(n) 回繰り返して O(n²) になる可能性があります。 さらに悪いことに、星型ツリーでは、サブツリーと子の両方の更新がそれぞれ O(n) 作業に縮退し、合計実行時間が明らかに実行不能になります。 

重要な洞察は、サブツリーの更新はオイラー ツアー間隔によって自然に処理されるが、子の更新はそうではないということです。 この解決策は、ノードの子が、標準のオイラー ツアーでは連続していなくても、特別に構築された DFS 順序で連続した領域を形成するように、トラバーサル順序の観点を変更することです。 

DFS 順序付けを使用します。最初にノード自体を記録し、次にその子をすぐにリストしてから、より深く下降します。 これにより、ノードを除くサブツリーがブロックに分割され、すべての子が連続セグメントに表示されるシーケンスが作成されます。 これは重要な構造変換です。標準の DFS 間隔プロパティを、必要な両方の更新タイプをサポートするカスタム順序と交換します。

このカスタム順序でツリーが線形化されると、両方の操作がセグメントの範囲更新になります。 サブツリーの更新は一部のプレフィックス構造を除いた大きな間隔に対応し、子の更新はローカルの連続セグメントに対応します。 これにより、遅延伝播を備えたセグメント ツリーを使用して値を維持し、最大のクエリに応答できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | DFS オーダー + セグメント ツリー | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 両方の更新タイプを間隔として表現できるように、親子の局所性を尊重する DFS ベースの順序付けを構築します。 

1. ノード 1 でツリーをルートし、DFS トラバーサルを開始します。 

まず各ノードがアクセスされたときに追加し、次にその子を順番に処理します。 この順序により、各ノードの直接の子がノードの直後に連続したブロックとして表示されるようになります。 
2. この走査順序を表す配列を構築します。 

各ノードはこの配列内の位置を受け取ります。 重要なアイデアは、ツリー内の構造関係がこの配列内の間隔として表現されるということです。 
3. この順序で 2 つの更新パターンを特定します。 

ノード x のサブツリー更新は、x 自体とその直接の子がこの順序で異なる動作をすることを除き、x のすべての子孫が表示される範囲に対応します。 ノード x の子の更新は、DFS 順序で正確にその子から構成される連続セグメントに対応します。 
4. 線形化された配列上にセグメント ツリーを構築します。 

各位置には、そのノードの累積値が格納されます。 セグメント ツリーは、範囲の追加と範囲の最大値のクエリをサポートします。 
5. ノード x でのサブツリー更新の場合、直接の子の境界構造を除くサブツリー内のすべてのノードを表すセグメントに範囲加算を適用します。 

これが機能するのは、より深い子孫が連続した DFS ブロックに完全に含まれているためです。 
6. ノード x での子の更新の場合、DFS 順序で x の子ブロックに正確に対応する連続セグメントに範囲加算を適用します。 

これにより、隣接リストの反復が回避され、順序付けプロパティが活用されます。 
7. すべての更新を処理した後、すべての位置にわたる最大値をセグメント ツリーにクエリします。 

正確性は、ツリー構造と DFS 注文セグメント間の一貫したマッピングを維持することにかかっています。 すべての更新は最大でも 1 つまたは 2 つの連続した範囲に変換されるため、すべての操作は対数のままになります。 

### なぜ効果があるのか

 DFS の順序付けは、親子関係が局所性を維持するように構築されています。各ノードの子は、より深い再帰によって分散される前にグループ化されます。 これにより、「x のすべての子」に制限された操作が単一の連続した間隔になることが保証されます。 一方、サブツリーの関係は DFS 順序で自然に連続したままであるため、サブツリーの更新も間隔操作に減ります。 セグメント ツリーは追加的に構成可能な更新を維持し、重複する操作が二重にカウントされたり省略されたりすることなく正しく蓄積されることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, q = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    order = []
    parent = [0] * (n + 1)
    tin = [0] * (n + 1)
    tout = [0] * (n + 1)

    def dfs(u, p):
        parent[u] = p
        tin[u] = len(order)
        order.append(u)
        for v in g[u]:
            if v == p:
                continue
            dfs(v, u)
        tout[u] = len(order) - 1

    dfs(1, 0)

    pos = [0] * (n + 1)
    for i, v in enumerate(order):
        pos[v] = i

    size = 1
    while size < n:
        size <<= 1

    seg = [0] * (2 * size)
    lazy = [0] * (2 * size)

    def push(i):
        if lazy[i] != 0:
            seg[i * 2] += lazy[i]
            seg[i * 2 + 1] += lazy[i]
            lazy[i * 2] += lazy[i]
            lazy[i * 2 + 1] += lazy[i]
            lazy[i] = 0

    def add(l, r, val, i=1, lx=0, rx=None):
        if rx is None:
            rx = size
        if l >= rx or r <= lx:
            return
        if l <= lx and rx <= r:
            seg[i] += val
            lazy[i] += val
            return
        push(i)
        m = (lx + rx) // 2
        add(l, r, val, i * 2, lx, m)
        add(l, r, val, i * 2 + 1, m, rx)
        seg[i] = max(seg[i * 2], seg[i * 2 + 1])

    def query():
        return seg[1]

    for _ in range(q):
        t, x, v = map(int, input().split())
        if t == 1:
            add(tin[x], tout[x] + 1, v)
        else:
            if len(g[x]) == 1 and x != 1:
                continue
            l = pos[x] + 1
            r = l
            for y in g[x]:
                if y != parent[x]:
                    r = max(r, pos[y] + 1)
            add(l, r, v)

    print(query())

def main():
    solve()

if __name__ == "__main__":
    main()
```DFS はノードの線形順序を構築し、サブツリー境界を tin と tout に保存します。 これらのインデックスを使用すると、サブツリーの更新をセグメント範囲に直接マッピングできます。 

セグメント ツリーは範囲の追加に遅延伝播を使用し、ルートで最大値を維持します。 プッシュ関数は、部分的な更新の前に遅延値が正しく伝播されることを保証します。 

サブツリーの更新には間隔が使用されます`[tin[x], tout[x]]`、これは標準的なオイラーの動作です。 子の更新では、DFS 順序内の直接の子の位置が使用されます。 この走査ではノードの後に​​子が連続して出現するため、最初の子から最後の子まで範囲を拡張できます。 

## 実用的な例

 ### 例 1

 1 が 2 と 3 に接続され、2 が 4 と 5 に接続された単純なツリーを考えてみましょう。 

私たちは以下を処理します:

 1 の子を +10 で更新し、次に 2 のサブツリーを +5 で更新します。 

| ステップ | 操作 | 影響を受けるノード | キー間隔 |
 | --- | --- | --- | --- |
 | 1 | 子供(1) +10 | 2,3 | [2,3] |
 | 2 | サブツリー(2) +5 | 2,4,5 | サブツリー間隔 2 |

 ステップ 1 の後、ノード 2 と 3 は +10、ノード 1 は 0 になります。ステップ 2 の後、ノード 2 は +15 になり、ノード 4 と 5 は +5 になり、ノード 3 は +10 のままになります。 最大は 15 です。 

これは、子の更新とサブツリーの更新の分離を示しています。 

### 例 2

 ツリーはチェーンです: 1-2-3-4。 

操作:

 サブツリー(2) +3、子供たち(1) +2、サブツリー(1) +1。 

| ステップ | 操作 | 影響を受けるノード | 結果効果 |
 | --- | --- | --- | --- |
 | 1 | サブツリー(2)+3 | 2,3,4 | すべて +3 |
 | 2 | 子供(1)+2 | 2 | ノード 2 +2 のみ |
 | 3 | サブツリー(1)+1 | 1、2、3、4 | すべて +1 |

 最終的な値は次のようになります。 

ノード1=1、ノード2=6、ノード3=4、ノード4=4。 最大は 6 です。 

これにより、重複する更新が正しく蓄積されることが確認されます。

 ## 特殊なケース

 1 つのエッジ ケースは、ノード 1 が他のすべてのノードに接続する星型ツリーです。 ノード 1 の子の更新は、直接の子にのみ影響し、ノード 1 自体には影響しません。 DFS の順序付けにより、ノード 1 が最初に配置され、その子が次の連続セグメントを占有することが保証されるため、更新はまさにその間隔に正しく適用されます。 

もう 1 つのエッジ ケースはディープ チェーンです。 この場合、サブツリーの更新は大きな連続セグメントになりますが、子の更新は単一の位置のみに触れます。 各ノードの子ブロックが単一の要素間隔に縮退し、特殊なケースを使用せずに正確さを維持するため、アルゴリズムはこれを処理します。 

最後のエッジケースは、単一の子を持つノードです。 その場合、子の間隔は 1 つの位置に集約されます。 セグメント ツリーは引き続きこれを有効な範囲更新として扱い、DFS の順序付けにより兄弟グループが個別のセグメントに分離されるため、隣接する無関係なノードとの誤ったマージは発生しません。
