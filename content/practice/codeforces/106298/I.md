 ## 問題の理解

 降下階乗から構築された有理式を定義する整数のコレクションが与えられます。 中心のオブジェクトは定数です$K$多項式恒等式における 2 つの等価係数比較を通じて間接的に定義されます。 これらの恒等式を単純化した後、タスクは、連続する整数の積を次の値で割った値から構成される値かどうかをチェックすることに移ります。$A$は整数です。 

具体的には、表示される分子は次の形式の切り捨てられた階乗部分です。$n \cdot (n-1) \cdot \ldots \cdot (n-k+1)$。 これは長さの順列の数です$k$から選ばれた$n$と書かれることが多いです。$nPk = \frac{n!}{(n-k)!}$。 値$K$この順列積は次の値で割られますか?$A$。 The question is whether this division is exact.

 追加の代数恒等式が関係します。$B, C, D$、 そして$(n-k)$これにより、多項式係数の一貫性が保証されます。 そのアイデンティティは計算コアを変えるものではなく、なぜ同じなのかを動機付けるだけです。$K$は 2 つの異なる係数比較に現れます。 重要な計算上のチェックは、すべての素因数が正しいかどうかだけです。$A$順列積の素因数分解で完全にカバーされます。 

入力構造は当然ながら、それぞれがパラメータを指定する複数のクエリとして解釈されます。$A, B, C, D, n, k$、そしてクエリごとに、次のことを決定する必要があります。$K$は整数です。 

このタイプの Codeforces 問題によって暗示される制約形状では、通常、最大で大規模な制約が許容されます。$n$したがって、プロダクトを明示的に拡張することは不可能です。 単純な乗算には次のことが必要です$O(k)$クエリごとに、クエリの数とクエリの両方が増加すると遅くなりすぎます。$k$大きいです。 

微妙な失敗例が現れるのは、$A$小さな素数の高い累乗が含まれています。 たとえば、次の場合$A = 2^{20}$、$n = 10^6$、 そして$k$is large, a naive method might overflow or miscount factors if it does not properly track multiplicity of primes across the whole range. もう 1 つのエッジケースは次のような場合です$k = 0$、積は空で 1 に等しく、答えは純粋に次のとおりであるかどうかによって決まります。$A = 1$。 

## アプローチ

 最も直接的なアプローチは、積を計算することです。$n \cdot (n-1) \cdot \ldots \cdot (n-k+1)$各クエリに対して明示的に実行し、次のように割り算をチェックします。$A$。 これは分子の定義と正確に一致するため、原理的には正しいです。 問題はコストです。各クエリには時間がかかります。$O(k)$乗算、および入力が大きい場合、時間制限内ではこれは不可能になります。 さらに、中間積は非常に大きくなり、任意精度の算術演算や繰り返しのリダクションが必要になるため、実装が複雑になり、時間計算量の問題も解決できません。 

重要な観察は、製品の価値をすべて必要とすることは決してないということです。 私たちが知る必要があるのは、すべての素数についてだけです$p$分割する$A$の指数かどうか$p$順列積には少なくとも次の指数が含まれます。$A$。 これにより、問題は数値計算から評価カウントに移ります。 

順列積$n \cdot (n-1) \cdot \ldots \cdot (n-k+1)$次のように表現できます$\frac{n!}{(n-k)!}$。 これにより、あらゆる素数の指数を計算できるようになります。$p$標準的な要因評価のトリックを使用します。$v_p(n!) - v_p((n-k)!)$。 これにより、範囲内のすべての要素を反復処理する必要がなくなり、素数ごとの対数カウントに置き換えられます。 

因数分解します$A$クエリごとに 1 回、次に素因数ごとに$p$、階乗評価式を使用して、順列範囲内の指数を計算します。 必要な指数がすべて満たされている場合、答えは「はい」です。

 ## アルゴリズムのチュートリアル

 ### アルゴリズムのチュートリアル

 1. 以下で構成されるクエリを読み取ります。$A, B, C, D, n, k$。 のみ$A, n, k$割り算チェックに影響するため、他の値は計算では無視されます。 
2.因数分解$A$その主要なコンポーネントに。 これにより、$A = \prod p_i^{e_i}$。 各指数を個別に検証する必要があります。 
3. 分子を階乗比として書き換えます$n! / (n-k)!$。 これにより、積の範囲が素数指数を効率的に数えられる形式に変換されます。 
4. 各素数について$p_i$、その指数を計算します$n!$による除算を繰り返し使用する$p_i$、次にその指数を減算します。$(n-k)!$。 これにより、順列積の指数が得られます。 
5. この指数を次と比較します。$e_i$。 指数が不十分な素数がある場合は、すぐに結論を出します。$K$は整数ではありません。 
6. すべての素数が条件を満たしている場合、結論を導き出します。$K$は整数です。 

核となる考え方は、割り算は素因数分解における指数ごとの優位性のチェックに帰着し、階乗構造により、数値を明示的に構築せずにこれらの指数を計算できるようにするというものです。 

### なぜ効果があるのか

 順列積と階乗比は整数として同一であるため、それらの素因数分解は正確に一致します。 整数の割り算は素数の指数を成分ごとに比較することと同等であるため、各素数を個別にチェックすることで、次のことを完全に特徴付けることができます。$A$製品を分割します。 階乗分解により、範囲を列挙することなくこれらの指数を正確に計算できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def factorize(x):
    f = {}
    p = 2
    while p * p <= x:
        while x % p == 0:
            f[p] = f.get(p, 0) + 1
            x //= p
        p += 1
    if x > 1:
        f[x] = f.get(x, 0) + 1
    return f

def vp_factorial(n, p):
    cnt = 0
    while n:
        n //= p
        cnt += n
    return cnt

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        A, B, C, D, n, k = map(int, input().split())

        if k == 0:
            out.append("YES" if A == 1 else "NO")
            continue

        factors = factorize(A)
        ok = True

        for p, need in factors.items():
            total = vp_factorial(n, p) - vp_factorial(n - k, p)
            if total < need:
                ok = False
                break

        out.append("YES" if ok else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()

クエリごとに、順列範囲指数が 2 つの階乗指数の差として計算されます。 これにより、製品範囲全体での明示的な反復処理が回避され、計算が対数的に維持されます。$n$。 

特別な場合$k = 0$は空の積に相当し、1 に等しいため、$A = 1$成功することができます。 

## 実用的な例

 簡単なクエリを考えてみましょう。$A = 12$、$n = 5$、$k = 3$。 分子は$5 \cdot 4 \cdot 3 = 60$。 因数分解します$12 = 2^2 \cdot 3$。 製品60には、$2^2 \cdot 3 \cdot 5$, したがって、必要な指数が両方とも存在します。

ここで考えてみましょう$A = 8$、$n = 6$、$k = 2$。 製品は$6 \cdot 5 = 30$、これには 2 の因数が 1 つだけ含まれます。

これらの例は、この方法が完全な積を計算せずに主要な欠陥をどのように分離するかを示しています。

 ## 特殊なケース

 重大なエッジケースは次のような場合です。$k = 0$。 積は空になり、1 と評価されます。$A > 1$、割り算はすぐに失敗します。 アルゴリズムは、因数分解の前にこれを明示的に処理します。 

もう一つのケースは次のような場合です。$k = n$。 分子は次のようになります。$n!$そしてアルゴリズムは自然に次のことをチェックすることに帰着します。$A$分割する$n!$同じ評価方法を使用します。 階乗差は次のようになりますので、$v_p(n!) - v_p(0!)$、 そして$v_p(0!) = 0$、計算は一貫したままになります。 

3 番目の微妙なケースは次のような場合です。$A = 1$。 因数分解ステップでは空の素数セットが生成されるため、チェックは実行されず、答えは常に「はい」になります。
