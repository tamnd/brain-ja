 ## 解決策
 ## 問題の理解

 サイクルのない接続されたグラフを意味するツリーが与えられ、それが「マンハッタン ツリー」とみなせるかどうかを判断したいと考えています。 定義するプロパティは、明示的に提供される距離や座標に関するものではなく、エッジがグリッド接続のように動作する、マンハッタン スタイルの隣接関係を使用した 2D 整数グリッド上に描画されるツリーの構造と互換性があるかどうかに関するものです。 

グリッド上では、各ポイントには隣接するポイントと接続するための自然な方向が最大で 4 つあります (上下左右)。 その幾何学的制約は、そこに埋め込むことができる任意のツリーに対する構造制約に直接変換されます。つまり、頂点は 4 つを超える入射エッジを持つことができません。 ただし、この条件だけでは十分ではありません。平面グリッドの埋め込みで分岐が相互作用する方法により、高次の頂点がいくつ共存できるか、分岐チェーンが競合せずに伝播できるかについて、より強力な制限が課せられるためです。 

タスクは、ツリーを読み取り、その構造が許可された構成の小さなファミリーに属しているかどうかを判断することです。 制約は入力ツリーに最大約 200,000 個のノードを含めることができるほど十分に大きいため、どのソリューションも線形時間で動作する必要があります。 これにより、すべての埋め込み、幾何学的シミュレーション、またはレイアウトの組み合わせ列挙の試行を伴うものは直ちに除外されます。 

単純な試みでは、エッジに沿ったマンハッタン距離を考慮しながらノードに座標を割り当てようとする可能性があります。 このようなシミュレーションはすぐに曖昧になってしまいます。 たとえば、5 枚の葉を持つ星のような形をした木の場合、中心を配置して 4 方向に枝を広げようとしますが、枝を追加するとグリッド容量の制約が破られます。 同様に、複数の分岐頂点を持つツリーでは、局所的には各ノードが実行可能に見えても、方向の割り当てに矛盾が生じやすくなります。 

次数が小さいにもかかわらず、分岐構造が依然としてグリッドの埋め込みと互換性がない場合、微妙なエッジ ケースが発生します。 たとえば、2 つの頂点がそれぞれ次数 3 を持ち、それらの分岐サブツリーが合計 4 つ以上の方向を必要とする方法でインターリーブしているツリーを考えてみましょう。 単純な程度チェックだけでは、グローバルな分類構造を考慮していない場合、そのようなケースを誤って承認または拒否する可能性があります。 

この問題の重要な洞察は、有効なマンハッタン ツリーが任意の境界次数ツリーではないということです。 それらは非常に少数の全体的な構造パターンに分類され、これらのパターンを認識すると、問題は単純なカウントと分類に減ります。 

## アプローチ

 ブルートフォースアプローチでは、グリッド上にツリーを実際に埋め込むことを構築しようとします。 任意のルートから開始して、エッジに方向を再帰的に割り当て、競合が発生しないようにしながら、各子をマンハッタンの 4 つの方向のいずれかに配置することを試みることができます。 配置の決定ごとに制約がサブツリーに伝播され、競合が発生するたびにバックトラッキングが必要になります。 

この方法は、有効な埋め込みの定義を直接シミュレートするため、原理的には正しいです。 ただし、各分岐頂点には複数の選択肢があり、最悪の場合、多数の分岐点を持つツリーでは指数関数的な数の方向割り当てが発生します。 剪定を行ったとしても、検索スペースは非常に急速に拡大するため、大きな木ではこれを実行できません。 

重要な点は、実際には座標が必要ないということです。 問題ステートメントはすでに、有効なツリーを構造署名の小さなセットに制限しています。 これらの特徴は、グリッドでは分岐が厳しく制限されているという事実から生じます。ほとんどのノードはチェーン上にのみ配置でき、少数の頂点だけが分岐ジャンクションとして機能できます。 次数 3 または 4 の頂点がいくつ存在するか、およびそれらがどのように接続できるかを分析すると、すべての有効なツリーが 4 つのカテゴリに分類されることがわかります。

有効なマンハッタン ツリーは、次のいずれかでなければなりません。すべてのノードの次数が最大 2 である純粋なチェーン、次数 3 または 4 の分岐ノードが 1 つだけあるツリー、または次数 3 の分岐ノードが 2 つだけチェーン状の構造で接続されているツリーです。 追加の分岐があると、直ちにグリッド内で不可能なレイアウトが強制されます。 

したがって、問題は、次数を数えて、次数 2 を超える頂点がいくつあるか、および次数 4 を超える頂点があるかどうかを確認することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース埋め込み検索 | O(4^n) | O(n) | 遅すぎる |
 | 学位に基づく分類 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを読み取り、すべてのエッジをスキャンしてすべての頂点の次数を計算します。 これにより、各ノードが持つ接続数のローカルな尺度が得られます。これは、ノードを埋め込もうとした場合に必要となるグリッド方向の数に直接対応します。 
2. 次数が 4 より大きい頂点があるかどうかを確認します。そのような頂点が存在する場合、どの点でも利用可能なマンハッタン方向は 4 つしかないため、ツリーをグリッドに埋め込むことはできません。 この場合は即時お断りさせていただきます。 
3. 少なくとも次数 3 を持つ頂点の数を数えます。次数 2 の頂点は直線のように動作し、次数 1 の頂点は終点であるため、これらは分岐点です。 
4. 次数 3 以上の頂点がない場合、ツリーは単純なパスになります。 これは、ノードをグリッド上に直線上に配置することで常に埋め込み可能です。 
5. 次数 3 以上の頂点が 1 つだけ存在する場合は、受け入れられます。 この頂点は中央の接合点として機能し、次数が 4 を超えない限り、すべてのチェーンは競合することなく異なるグリッド方向に外側に拡張できます。 
6. 次数 3 以上の頂点がちょうど 2 つある場合、構造が 2 つの分岐点のチェーンと依然として一致しているかどうかを確認します。 ツリーでは、任意の 2 つのノード間にはパスが 1 つだけ存在するため、これは自動的に成り立ち、構造は 2 つの分岐ノードを接続する線形バックボーンに強制されます。 
7. 3 つ以上の分岐頂点がある場合、グリッドの埋め込みはオーバーラップや方向の再利用を強制せずに 3 つを超える真の分岐ジャンクションに対応できないため、拒否します。 

### なぜ効果があるのか

 重要な不変条件は、マンハッタン グリッドへのツリーの有効な埋め込みでは、分岐頂点に属する各エッジに個別のグリッド方向を割り当てる必要があり、各ノードでグローバルに使用できるそのような方向は 4 つだけであるということです。 2 つ以上の頂点で同時に分岐が必要になると、構造により共有パスに沿った方向の割り当てに矛盾が生じます。 ツリーには 2 つのノード間に固有のパスがあるため、分岐点は線形配置でのみサポートされ、一貫した埋め込みではその数が最大 2 つに制限されます。 この構造上の制限は、上で使用した度数分類によって正確に把握されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    if n == 1:
        print("YES")
        return

    deg = [0] * (n + 1)

    for _ in range(n - 1):
        u, v = map(int, input().split())
        deg[u] += 1
        deg[v] += 1

    for d in deg:
        if d > 4:
            print("NO")
            return

    big = sum(1 for d in deg if d >= 3)

    if big > 2:
        print("NO")
    else:
        print("YES")

if __name__ == "__main__":
    solve()
```実装は、エッジ リストから次数を計算することから始まります。 これは必要な唯一の構造情報であり、ツリーが許可されたマンハッタン構成の 1 つに適合するかどうかを完全に決定します。 

次数が 4 より大きいかどうかのチェックは、すぐにグリッド制約に違反するため、早期に適用されます。 その後、次数が 3 以上の頂点を数えると、すべての分岐点が特定されます。 最終的な決定は、アルゴリズムで導出された分類と一致する、そのような頂点がいくつ存在するかに純粋に基づいて行われます。 

このロジックでは、ツリーをルート化したり、次数の累積を超えて走査を実行したりする必要がないため、ソリューションが線形で堅牢に保たれます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    deg = [0] * (n + 1)

    for _ in range(n - 1):
        u, v = map(int, input().split())
        deg[u] += 1
        deg[v] += 1

    if n == 1:
        return "YES"

    for d in deg:
        if d > 4:
            return "NO"

    big = sum(1 for d in deg if d >= 3)
    return "YES" if big <= 2 else "NO"

# minimum size
assert run("1\n") == "YES"

# simple chain
assert run("5\n1 2\n2 3\n3 4\n4 5\n") == "YES"

# star with 5 leaves (invalid)
assert run("6\n1 2\n1 3\n1 4\n1 5\n1 6\n") == "NO"

# two branching nodes
assert run("5\n1 2\n1 3\n2 4\n2 5\n") == "YES"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一ノード | はい | 最小限のエッジケース |
 | チェーン | はい | 純粋なパス構造 |
 | 5枚の葉を持つ星 | 写真 5枚の葉を持つ星 いいえ | 度 > 4 拒否 |
 | 2 つの分岐ノード | はい | 二重分岐構造を許可 |

 ## 特殊なケース

 単一ノード ツリーは、すべての次数制約を自明に満たすため有効であり、次数制限に違反する頂点がなく、カウントする分岐点がないため、アルゴリズムは正しく YES を返します。 

5 枚の葉を持つ星は、次数 4 の境界条件を示します。 中央ノードの次数は 5 で、さらなる推論の前に即座に拒否がトリガーされます。 アルゴリズムは、明示的な次数チェックを通じてこれを早期に検出します。 

分岐頂点がちょうど 2 つあるツリーは、意図した自明ではない受け入れケースを示しています。 2 つのノードの次数が 3 以上であっても、構造は 2 つのジャンクションを持つ有効な線形バックボーンのままであり、カウント条件により、さらなる構造シミュレーションを行わなくても許可されます。
