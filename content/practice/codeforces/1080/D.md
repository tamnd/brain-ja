 ## 問題の理解

 具体的には、辺の長さが 2 の累乗である正方形のグリッドから始めます。$2^n \times 2^n$。 唯一許可される操作は、既存の辺の正方形を取得することです$a$それを4つの等しい小さな正方形の辺に分割します$a/2$。 このプロセスは繰り返すことができますが、単位正方形に到達すると、それ以上分割することはできません。 

プロセスは任意ではありません。正確に実行する必要があります。$k$このような分割は合計で行われ、異なる時点で異なる正方形を選択して分割する可能性があります。 すべての操作の後、大きな正方形をさまざまなサイズの等軸に揃えられた小さな正方形に最終的に分割することを確認します。 

重要な制約は、最終構成における構造的な制約です。 ある辺の長さが固定された正方形に焦点を当てます$a$。 これらのマス目のうち、ボード全体の左下と右上のマス目は、隣接する辺のマス目のみを通過するパスで接続する必要があります。$a$ここで、隣接とは完全な面を共有することを意味します。 

課題は、正確に実行できるかどうかを判断することです$k$この接続条件がいくつかの選択に対して保持されるように分割します。$a$。 可能であれば、次のように表現して、どのスケールが使用されているかも出力する必要があります。$\log_2(a)$。 

制約は非常に大きいです。$n$まで可能です$10^9$そして$k$まで$10^{18}$、グリッドのシミュレーションや明示的な構築は除外されます。 どのような解決策であっても、問題を完全なバイナリ分解のレベル間で分割がどのように分散するかについての算術推論に帰着させる必要があります。 

単純なアプローチでは、分割をシミュレートし、正方形の優先順位構造を維持し、操作のすべての分散を試みます。 いくつかのレベルを過ぎるとグリッドの保存さえ不可能になるため、これはすぐに失敗します。$n$完全な分割の場合、単位正方形の数は$4^n$、たとえ小さなものであっても、限界をはるかに超えています。$n$。 操作ごとに推論することさえ不可能であるため、$k$大きすぎます。 

微妙なエッジケースは次のような場合です$k$完全な再帰的分解で使用できる分割の数と比較すると小さいです。 たとえば、$n = 1$、私たちは$2 \times 2$グリッド。 One split produces four unit squares and already fixes all structure. もし$k$ユニット サイズに達する前に、すべての正方形にわたる分割の最大可能数を超えると、それ以上操作を適用できないため、プロセスは不可能になります。 

もう 1 つの微妙なケースは、次の値が異なることです。$a$分解のさまざまな「レベル」に対応します。 選択する$a = 2^d$グリッドを見ていることを意味します$2^{n-d} \times 2^{n-d}$接続要件は、分割を他の場所に分散しながら、そのレベルの十分なブロックをそのまま維持できるかどうかに完全に依存します。 

## アプローチ

 ブルートフォースのアイデアは、可能な分割操作のすべてのシーケンスをシミュレートすることです。 各状態は正方形サイズのマルチセットであり、各操作は 1 つの正方形を選択し、それを 4 つの小さな正方形に置き換えます。 これにより、巨大な分岐プロセスが形成されます。 対称性によって枝刈りしたとしても、状態の数は次のように指数関数的に増加します。$k$それぞれの分割により、将来の分割がどこで発生するかについて複数の新しい選択肢が導入されるためです。 状態空間はすぐに扱いにくくなります。 

重要な観察は、実際にはグリッドのジオメトリは必要なく、各スケールに存在する正方形の数だけが必要であるということです。 1 つの正方形が 4 つになるため、分割するたびに正方形の合計数がちょうど 3 ずつ増加します。 それでその後$k$演算では、正方形の総数は固定されています。$1 + 3k$。 問題は、左下から右上まで、選択したスケールの接続された「回廊」を維持する方法で、これらの正方形をレベル全体に分散できるかどうかに帰着します。 

次に、目標規模を修正することを検討してください$a = 2^d$。 その規模では、ボードは概念的には$2^{n-d} \times 2^{n-d}$ブロックのグリッド。 パスが存在するには、対角の間にそのスケールのブロックの接続されたチェーンが必要です。 これにより、無傷のブロックの最小限の「バックボーン」が強制されますが、余分な分割はすべて、接続を切断せずに他の領域をリファインすることしかできません。 

重要な洞察は、接続要件により、非常に特定のレベルの構造が強制されるということです。$d$、グリッドには$2^{n-d}$各方向にステップがあるため、どのパスにも少なくとも$2(2^{n-d}-1)+1$マンハッタンの観点から考えると、ブロック数は 1 つになりますが、より重要なのは、このスケール以上で、パスに沿って分割されずに残っておかなければならないブロックの数が固定されていることです。 これにより、グローバルに実行できる分割の合計数が制限されます。 

視点を逆にすると簡単になります。 1 つの正方形から構築するのではなく、すべてを単位正方形に完全に分割すると想像してください。 それは最大値に相当します$4^n - 1$分割しますが、中間の到達可能な状態のみを考慮します。 このプロセスはカットオフ レベルを選択するのと同じです。$d$そして、そのレベル以下のすべてが完全に拡張されている一方で、より高いレベルのいくつかの四角形は拡張されずに残されてバックボーンを形成していると判断します。 それぞれの選択$d$完全なバイナリ 4 分木に特定の必要な数の分割を誘発し、その数は一意に決定されます。

 ## アルゴリズムのチュートリアル

 プロセスをクアッドツリーのレベルの観点から再解釈します。 

1. 値を選択することを考慮します。$d$パスに辺の正方形を使用することを意味します$2^d$。 これにより、初期グリッドが次のように分割されます。$2^{n-d} \times 2^{n-d}$大きな細胞。 
2. 固定の場合$d$では、これらの大きなセルの左下から右上への最小接続パスを形成するセルを除くすべてのセルを完全にリファインする場合に必要な分割の数を計算します。 
3. レベルの各セル$i$そのままの状態を維持するか、レベルで 4 つに分割できる正方形に相当します。$i-1$。 レベルからセルを完全に拡張することによって寄与された分割の合計数$i$レベルまで下げる$0$は$4^i - 1$。 
4. We build the minimal path at level$d$。 そのパスには正確に次の内容が含まれています$2^{n-d+1}-1$対角間のマンハッタン パス構造内のセル。 
5. このパス上にないすべてのセルはレベル 0 まで完全に拡張されますが、パス セルはレベルのままです。$d$。 これにより、決定的な分割数が得られます。 

分割の合計数は、完全な拡張の合計からパスに沿って保存された拡張を差し引いたものです。 
6. すべてのレベルの寄与を合計し、パスの寄与を減算することで、この値を効率的に計算します。これにより、完全な列挙が回避されます。 
7. 可能な限りすべてのことを繰り返します$d$、もしあれば正確に生成します$k$YES を出力すると、$d$。 

### なぜ効果があるのか

 重要な不変条件は、単一のレベルを選択することで、すべての有効な最終構成を一意に記述できることです。$d$ここでは、分割されていない正方形の接続されたバックボーンが存在し、その他すべてが完全に拡張されます。 この構造から逸脱すると、必要なパスが切断されるか、接続を変更せずに分割数を変更せずにツリーの下または上にプッシュできる冗長な部分拡張が導入されます。 この正規化により、すべての有効な設定が 1 つのパラメータにまとめられます。$d$、各選択に対する操作の数が決定的になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_ops(n, d):
    # number of cells per side at level d
    # grid is 2^(n-d)
    m = n - d
    # total cells at level d grid
    total_cells = 1 << (2 * m) if m < 60 else None

    # If m is large, we avoid direct computation by noting overflow cases
    # We instead compute using geometric series reasoning:
    # total full expansion cost from level n to 0 is (4^n - 1)/3 in split-units
    # but we only need relative comparison, so we compute difference form.

    # compute full expansion cost for a single root down to level d
    def full(x):
        return (1 << (2 * x)) - 1

    full_all = full(n)
    full_cell = full(d)

    # number of cells on path at level d
    path_len = (1 << (m + 1)) - 1

    # each path cell saves full(d) expansion
    saved = path_len * full_cell
    return full_all - saved

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())

        # small n safety: try all d
        ans = -1
        for d in range(n + 1):
            if count_ops(n, d) == k:
                ans = d
                break

        if ans == -1:
            print("NO")
        else:
            print("YES", ans)

if __name__ == "__main__":
    solve()

反復が終わった$d$パスの可能なすべてのスケールをチェックします。 一致する分割数が見つかると、そのスケールが有効になります。
