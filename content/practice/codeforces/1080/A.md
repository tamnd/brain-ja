 ## 解決策
 ## 問題の理解

 Petya はパーティーの招待状を準備しています。各招待状には一定量の色紙が消費されます。 すべての招待状には、赤シート 2 枚、緑シート 5 枚、青シート 8 枚が必要です。 あれば$n$友達、それでは$n$招待状を作成する必要があるため、総需要は次のように直線的に増加します。$n$: 赤の需要は$2n$、グリーン需要は$5n$、青の需要は$8n$。 

当店ではシート単体での販売はしておりません。 代わりに、購入するたびに単一色のノートが提供され、すべてのノートに正確な内容が含まれます。$k$シート。 購入時にノートを複数の色に分割したり部分的に使用したりすることはできないため、決定は純粋に、合計シートが十分になるように各色の完全なノートを何冊購入する必要があるかによって決まります。 

出力は、すべての招待状に十分なシートを保証する、3 色すべてのノートブックの最小合計数です。 

制約により両方が許可されます$n$そして$k$と同じくらい大きくなる$10^8$これにより、ノートブックまたはシートを反復するシミュレーションが即座に除外されます。 どのアプローチでも、一定時間内に答えを計算する必要があります。 この構造は純粋に算術的なものであるため、対数解や線形解は不要であり、過剰になります。 

色の合計シートが次の値で割り切れない場合、微妙なエッジケースが発生します。$k$。 たとえば、次の場合$n = 1$、$k = 5$、赤の需要が 2 の場合、赤には 1 冊のノートブックで十分ですが、需要が 6 の場合、6 は 5 に近いにもかかわらず 2 冊のノートブックが必要になります。この天井動作は、特に切り上げなしで整数の除算を使用する場合、間違いの主な原因です。 

## アプローチ

 単純な戦略では、必要な枚数に達するまでノートを色ごとに 1 枚ずつ購入することをシミュレートします。 色ごとに、繰り返し追加できます。$k$シートを作成し、到達するまでに必要な追加数を数えます$2n$、$5n$、 そして$8n$。 これは、ノートブックを購入する物理的なプロセスを模倣しているため、正しいですが、最悪の場合、$n = 10^8$、必要な合計は次のとおりです。$10^9$シート。 もし$k = 1$、これは色ごとに数十億回の反復を必要とし、時間制限をはるかに超えています。 

重要な点は、各色が独立しているということです。 赤に必要なノートの数は緑や青には影響しません。 ある色に必要な合計シートを計算すると、問題は標準的な天井分割、つまりサイズのグループがいくつになるかということになります。$k$総需要をカバーする必要があります。 

これにより、問題全体が 3 つの独立した整数上限除算とその後の合計に縮小されます。

 ## アルゴリズムのチュートリアル

 1. 各色に必要なシートの合計数を計算します。赤は$2n$、緑は$5n$、そして青は$8n$。 このステップでは、各色を独立して処理できるように要求を分離します。 
2. 色ごとに、必要なノートの数を決定します。 各ノートブックが正確に貢献するため、$k$シートの場合、必要な枚数は需要を で割った値以上の最小の整数です。$k$。 こちらは天井分割です。 
3. 次のように整数演算を使用して上限除算を計算します。$(x + k - 1) // k$。 これにより、浮動小数点演算が回避され、次のような場合が正しく処理されます。$x$は正確に割り切れます$k$。 
4. 3 つの結果を合計し、ノートブックの総数を出力します。 

### なぜ効果があるのか

 各色は個別の梱包問題として動作します。つまり、固定サイズのコンテナを使用して固定需要をカバーしています。 どのソリューションも少なくとも需要を満たさなければならないため、色ごとにノートブックの数が満たさなければなりません$ans \cdot k \ge x$。 この不等式を満たす最小の整数がまさに天井除算です。 色は相互作用しないため、これらの最小の独立した解を合計すると、全体的な最小値が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    red = 2 * n
    green = 5 * n
    blue = 8 * n

    def need(x):
        return (x + k - 1) // k

    print(need(red) + need(green) + need(blue))

if __name__ == "__main__":
    solve()
```このコードは、数学的構造を 3 つの独立した計算に直接変換します。 ヘルパー関数`need`整数演算を使用して上限除算を安全に実装します。これにより、浮動小数点の精度の問題が回避され、境界での正確さが保証されます。`x`の倍数です`k`。

 ## 特殊なケース

 いつ$k = 1$、すべてのシートは別のノートブックから取得する必要があります。 入力用$n = 1, k = 1$、要求は 2、5、8 であるため、結果は 15 個のノートブックになります。 アルゴリズムはこれを正しく処理します。$(x + 0) // 1 = x$、正確なカウントを維持します。 

いつ$k$など非常に大きいです$k \ge 8n$、すべての要求が色ごとに 1 つのノートブックに収まります。 のために$n = 10, k = 100$、赤、緑、青はそれぞれ正確に 1 つのノートブックを必要とし、出力 3 を生成します。各需要が次のように割られるため、上限の公式は正しく崩壊します。$k$1未満ですが1に切り上げます。 

いつ$k$すべての要求を正確に分割します。たとえば、$n = 2, k = 2$、赤は 4、緑は 10、青は 16 で、すべて 2 で割り切れます。この数式は、四捨五入せずに正確な整数の割り算を行い、数えすぎを防ぎます。
