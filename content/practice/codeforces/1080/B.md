 ## 解決策
 ## 問題の理解

 非常に大きな無限シーケンスが与えられ、各位置はそのインデックスのみに基づいて決定的な値を持ちます。 値は符号を交互に変え、大きさが直線的に増加します。位置 1 は -1 に寄与し、位置 2 は +2 に寄与し、位置 3 は -3 に寄与します。 一般に、位置の要素は$i$は$i$ステップごとに反転する符号を掛けます。 

各クエリは、連続したセグメント内の値の合計を要求します。$[l, r]$。 クエリは最大 1,000 個、インデックスは最大 10 億個になる可能性があるため、配列を構築したり、範囲を直接反復したりすることはできません。 クエリ範囲内のすべての要素に触れるソリューションは、次のように劣化します。$10^9$制限時間内に不可能な最悪の場合の操作。 

重要な課題は、シーケンスが大きいにもかかわらず、その構造が非常に規則的であることです。これは、閉じた形式のプレフィックス合計が存在することを示唆しています。 

範囲が奇数または偶数の位置のみにまたがる場合、微妙なエッジ ケースが発生します。 たとえば、次のように考えてみましょう$[1, 1]$、$[2, 2]$、 または$[1, 2]$。 慎重なインデックス作成を行わずにインクリメンタル シミュレーションに依存する場合、単純な実装では符号の変更が誤って処理される可能性があります。 もう 1 つの故障モードは、符号パターンにおけるオフバイワン エラーです。$i$正または負であっても、プレフィックスと範囲の計算の両方で一貫性を保つ必要があります。 

## アプローチ

 ブルート フォース アプローチでは、次から反復して各クエリを独立して計算します。$l$に$r$そして合計$a_i$。 これは定義に直接従うため、正しいです。 ただし、各クエリは最大で次の範囲に及ぶ可能性があります。$10^9$要素があるため、単一の最悪のクエリでもすでに大きすぎ、最大で$10^3$クエリでは、このアプローチは完全に実行不可能です。 

シーケンスの構造が重要な観察です。 値は、大きさが線形に増加しながら符号が交互になります。 これは、シーケンスを偶数と奇数の位置に分割し、各サブシーケンスが一貫した符号を持つ単純な等差数列になることを示唆しています。 

奇数の位置は負の値に寄与します: 位置$2k-1$、値は$-(2k-1)$。 偶数の位置が正の値に寄与します: 位置$2k$、値は$+2k$。 これらの部分列のそれぞれには、等差数列の接頭辞の合計に関する既知の公式があり、これにより、次の合計を計算できます。$n$一定時間内に。 プレフィックスの合計が利用可能になると、各クエリは減算に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | クエリごとに O(r − l + 1) | お(1) | 遅すぎる |
 | 最適なプレフィックス式 | クエリごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 奇数インデックスと偶数インデックスからの寄与を分離してシーケンスを書き換えます。 これは、各部分が交互のパターンではなく標準の等差数列になるため重要です。 
2. プレフィックスの合計をインデックスまで導出します。$n$。 までに偶数項と奇数項がいくつ存在するかを計算します。$n$パリティに応じてカウントがわずかに異なるためです。 
3. 偶数インデックスの合計を計算します。 偶数のポジションは、$2, 4, 6, \dots, 2k$。 それらの合計は次のとおりです。$$2(1 + 2 + \dots + k) = k(k+1)$$どこ$k = \lfloor n/2 \rfloor$。 
4. 奇数のインデックスの合計を計算します。 奇数の位置は、$1, 3, 5, \dots, (2k-1)$。 彼らの貢献は否定的です:$$-(1 + 3 + 5 + \dots + (2k-1)) = -k^2$$どこ$k = \lceil n/2 \rceil$。 
5. 両方の部分を結合してプレフィックスの合計を取得します。$S(n)$。 その後、各クエリ$[l, r]$は次のように答えられます:$$S(r) - S(l-1)$$これが機能する理由は、シーケンスが素のインデックスを持つ 2 つの独立した算術シーケンスに分解されるためです。 プレフィックスの合計は線形性を尊重するため、各サブシーケンスを個別に合計し、相互作用することなくそれらを再結合できます。 

### なぜ効果があるのか

 重要な不変条件は、すべてのインデックスが 2 つの素なセット (偶数または奇数) のいずれかに正確に属することです。 各セットでは、値関数は固定ステップと固定符号を持つ純粋な等差数列になります。 プレフィックスの合計は、素の和集合に対して線形であるため、プレフィックスの合計の合計は、2 つの独立したプレフィックスの合計の正確な合計になります。 これにより、プレフィックス値を減算することでセグメントが正しく分離されることが保証されます。$[l, r]$再計算や重複エラーなし。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def pref(n):
    if n <= 0:
        return 0

    k_even = n // 2
    even_sum = k_even * (k_even + 1)

    k_odd = (n + 1) // 2
    odd_sum = k_odd * k_odd

    return even_sum - odd_sum

q = int(input())
for _ in range(q):
    l, r = map(int, input().split())
    print(pref(r) - pref(l - 1))
```機能`pref(n)`偶数と奇数の寄与に分割して、インデックス 1 から n までのシーケンスの合計を計算します。 偶数のインデックスの場合、最初の合計の式を使用します。$k$丁数。 奇数のインデックスの場合、最初のインデックスの合計を計算します。$k$奇数を指定してそれを否定します。 

各クエリは標準の接頭辞減算トリックを使用します。これは、接頭辞関数が明確に定義されているため安全です。$n = 0$ベースケース経由。 

ここでよくある間違いは、奇数位置と偶数位置のカウントを混同することです。 もう 1 つは、奇数の位置が負の値に寄与することを忘れているため、符号は合計の前ではなく後に適用する必要があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def pref(n):
        if n <= 0:
            return 0
        k_even = n // 2
        even_sum = k_even * (k_even + 1)
        k_odd = (n + 1) // 2
        odd_sum = k_odd * k_odd
        return even_sum - odd_sum

    q = int(input())
    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        out.append(str(pref(r) - pref(l - 1)))
    return "\n".join(out)

# provided samples
assert run("""5
1 3
2 5
5 5
4 4
2 3
""") == """-2
-2
-5
4
-1"""

# minimum range
assert run("""1
1 1
""") == "-1"

# single even index
assert run("""1
2 2
""") == "2"

# large symmetric range
assert run("""1
1 10
""") == str(sum(i if i % 2 == 0 else -i for i in range(1, 11)))

# mixed ranges
assert run("""2
1 2
3 6
""") == """1
-2"""

 ## 特殊なケース

 重要なエッジ ケースは、プレフィックス ロジックが処理に依存するため、範囲が 1 から始まる場合です。$l - 1 = 0$。 たとえば、$[1, 1]$、計算は次のようになります$S(1) - S(0)$。 実装は明示的に 0 を返します。$S(0)$、特別な大文字と小文字のクエリを使用せずに正確性を保証します。 

もう 1 つのエッジケースは次のような場合です$l = r$。 このアルゴリズムは、隣接するプレフィックスの減算による単一値の検索に縮小されますが、偶数と奇数の両方の寄与が境界を越えて連続しているため、算術式は依然として正しく動作します。 

3 番目のケースは次の場合です。$l$そして$r$異なるパリティを持っています。$[2, 3]$。 ここで、セグメントは正の偶数項から負の奇数項に交差します。 両方の寄与がすでにグローバルにエンコードされているため、プレフィックス関数はこの境界を気にしません。$S(n)$。
