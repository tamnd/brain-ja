 ## 解決策
 ## 問題の理解

 セグメントのコレクションがいくつか与えられており、各コレクションは 1 から n までのセット インデックスに対応します。 1 つのセット内には多数のセグメントが存在する可能性があり、各セグメントは数直線上の閉区間になります。 

このタスクは、さまざまなセットに関するクエリに答えることを中心に展開します。 各クエリは、a から b までのセット インデックスの範囲とターゲット間隔 [x, y] を指定します。 クエリは、そのインデックス範囲内のすべてのセットに、[x, y] 内に完全に含まれるセグメントが少なくとも 1 つ含まれているかどうかを尋ねます。 セグメントが完全にクエリ間隔内にある場合、セグメントはセットに対して有効です。つまり、その左端が x 以上で、右端が y 以下であることを意味します。 

したがって、各クエリは基本的に、セットの範囲にわたる普遍的な条件をチェックします。つまり、[a, b] のすべてのセットについて、[x, y] 内に少なくとも 1 つの「良好な」セグメントが存在します。 

制約は大きく、最大 10^5 セット、3×10^5 セグメント、および 10^5 クエリがあります。 これにより、クエリごとにすべてのセグメントをスキャンしたり、クエリごとにすべてのセットをスキャンしたりすることが直ちに除外されます。 クエリごとに O(n) またはクエリごとに O(k) に達するアプローチは失敗します。 

単純な間違いは、[a, b] 内のすべてのセットを反復処理して各クエリを処理し、各セットについてそのセグメントをスキャンしてセグメントが [x, y] 内にあるかどうかを確認することです。 これは最悪の場合には O(nk + m・k) にまで縮退し、これは限界をはるかに超えています。 

もう 1 つの微妙な落とし穴は、セットごとにソートされたセグメントのリストを事前計算し、クエリごとに二分検索を実行しようとすることです。 これは依然として失敗します。各クエリは単一のセットではなくセットの範囲にわたって集計する必要があるため、コストを倍増させる範囲チェックが依然として必要になります。 

主要な問題は、各クエリがセットにわたる範囲最小タイプの条件であるが、各セット内の条件は、動的区間 [x, y] 内に完全にセグメントが存在するかどうかに依存することです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。クエリごとに、a から b までのすべてのセットを反復処理し、そのセットに [x, y] に完全に含まれるセグメントが含まれているかどうかを確認します。 「はい」の場合は続行します。 それ以外の場合は、クエリを拒否します。 各セット内で、そのすべてのセグメントをスキャンします。 

これは定義に直接従うため、正しいです。 ただし、その複雑さはクエリごとのセグメント チェックの総数によって決まります。 最悪の場合、各クエリが n 個のセットすべてにアクセスし、各セットに多くのセグメントが含まれるため、実行時間が法外に長くなります。 

重要な点は、各セットがクエリに関連する非常に単純なプロパティを持っているということです。[x, y] 内に少なくとも 1 つのセグメントが含まれているかどうかだけを気にします。 固定セットの場合、そのセグメントを前処理して、「l ≥ x および r ≤ y のセグメントは存在しますか?」などの高速なクエリを可能にする構造にすることができます。 

これにより、各セットがそのセグメント セットの圧縮表現に縮小されます。 自然な縮小は、各セグメントを 2D の点 (l, r) として見ることであり、l ≥ x および r ≤ y で定義される長方形の中に点が存在するかどうかを尋ねます。 

したがって、各セットは 2D の支配構造になります。 問題は、各集合 p に対して、l ≥ x および r ≤ y を満たすセグメントが含まれる場合、関数 f_p(x, y) = 1 を定義することです。 各クエリは、[a, b] 内のすべての p について f_p(x, y) = 1 かどうかを尋ねます。 これは、バイナリ関数に対する範囲最小クエリです。 

この存在クエリに対数時間で答えるデータ構造をセットごとに事前計算し、セット全体にセグメント ツリーを構築して、各ノードがそのセットの和集合を記述する構造を格納できるようにします。 すべてのセグメントを明示的に保存する代わりに、各ノードは同じ 2D 支配クエリに効率的に答えることができる結合された構造を保存します。 

k が大きいため、セグメントの端点に対して座標圧縮を使用し、l 値でグループ化された r 値に対して並べ替えられた構造を各セットに対して維持します。 次に、ソートされたリストを維持し、支配的なセグメントを取り除くことによって、各ノードがマージされます。

クエリ時に、セットされたインデックスにわたってセグメント ツリーを走査し、訪問したノードごとに、その構造に (x, y) の有効なセグメントが含まれているかどうかを確認します。 範囲内のすべてのノードが成功した場合、答えは「はい」です。 

これにより、問題は、支配クエリを備えた標準的なオフライン セグメント ツリーに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m · n · avg_k) | O(k) | 遅すぎる |
 | 最適 (セグメントツリー + 支配構造) | O((k + m) log n) | O(k log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのセグメントを、特定のセット インデックスに関連付けられたペア (l, r) として扱います。 まず、すべてのセグメントをセットごとにグループ化します。 これが必要なのは、すべてのクエリがセットの連続範囲にわたるため、セットごとの集計が必要だからです。 
2. 各セットについて、そのセグメントを l で昇順に並べ替えます。 この並べ替えられた順序内で、優勢チェックに役立つ可能な限り最良の r 値が維持されます。 このステップにより、後で l ≥ x を満たすセグメントがあるかどうかを迅速に判断できるようになります。 
3. 1 から n までのインデックスのセットに対してセグメント ツリーを構築します。 各リーフ ノードは 1 つのセットに対応し、そのセグメントを表す構造を格納します。 
4. セグメント ツリーの内部ノードごとに、その 2 つの子の構造をマージします。 マージされた構造は、その範囲のセット内のすべてのセグメントを表します。 マージ操作では、優勢クエリに必要な候補のみを保持しながら、ソートされたリストを結合します。 より大きい l とより小さい r の両方を持つ別のセグメントによって支配されているセグメントはすべて破棄されます。 
5. クエリ (a、b、x、y) に答えるには、[a, b] をカバーするセグメント ツリー ノードをたどります。 完全にカバーされた各ノードについて、その構造に l ≥ x および r ≤ y のセグメントが含まれているかどうかを確認します。 すべての訪問ノードがこのテストに合格した場合、答えは「はい」になります。 それ以外の場合は「いいえ」。 

重要なアイデアは、各ノードが圧縮された候補セグメントのセットに対する固定タイプの 2D 優勢存在クエリに応答するということです。 

なぜそれが機能するかは、単調性不変式に基づいています。 各ノードは、クエリに対する答えとなる可能性のあるセグメントがノードの構造内に存在することが保証されるように、セグメントの縮小表現を格納します。 l ≥ x と r ≤ y の両方の制約において、支配的なセグメントが厳密に優れていることはあり得ないため、支配的なセグメントを削除しても、クエリに対する潜在的な有効な証人は削除されないため、マージによって正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

class SegTree:
    def __init__(self, data):
        self.n = len(data)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.tree = [[] for _ in range(2 * self.size)]

        for i in range(self.n):
            self.tree[self.size + i] = data[i]

        for i in range(self.size - 1, 0, -1):
            self.tree[i] = self.merge(self.tree[2 * i], self.tree[2 * i + 1])

    def merge(self, A, B):
        merged = []
        i = j = 0
        while i < len(A) and j < len(B):
            if A[i][0] < B[j][0]:
                merged.append(A[i])
                i += 1
            else:
                merged.append(B[j])
                j += 1

        while i < len(A):
            merged.append(A[i])
            i += 1
        while j < len(B):
            merged.append(B[j])
            j += 1

        # prune dominated segments
        pruned = []
        best_r = INF
        for l, r in merged:
            if r < best_r:
                pruned.append((l, r))
                best_r = r
        return pruned

    def query_check(self, l, r, x, y):
        l += self.size
        r += self.size
        res_nodes = []
        while l <= r:
            if l % 2 == 1:
                res_nodes.append(l)
                l += 1
            if r % 2 == 0:
                res_nodes.append(r)
                r -= 1
            l //= 2
            r //= 2

        for idx in res_nodes:
            if not self.node_has(idx, x, y):
                return False
        return True

    def node_has(self, idx, x, y):
        for l, r in self.tree[idx]:
            if l >= x and r <= y:
                return True
        return False

def main():
    n, m, k = map(int, input().split())
    sets = [[] for _ in range(n)]

    for _ in range(k):
        l, r, p = map(int, input().split())
        sets[p - 1].append((l, r))

    for i in range(n):
        sets[i].sort()

    st = SegTree(sets)

    for _ in range(m):
        a, b, x, y = map(int, input().split())
        a -= 1
        b -= 1
        print("yes" if st.query_check(a, b, x, y) else "no")

if __name__ == "__main__":
    main()
```セグメント ツリーの構築では、すべてのセグメントをセットごとにグループ化し、それらを再帰的にマージして、各ノードに関連するセグメントのコンパクトなスカイラインが含まれるようにします。 枝刈りステップにより、支配されていないセグメントのみが確実に残り、クエリ チェックが実用的な程度に小さく保たれます。 

各クエリは O(log n) ノードに分解され、各ノードはプルーニングされたリストをスキャンすることによってチェックされます。 正確かどうかは、有効なセグメントがクエリ範囲内のいずれかのセットに存在する場合、それが枝刈りを経ても存続し、そのセットをカバーする少なくとも 1 つのセグメント ツリー ノードに表示されるかどうかによって決まります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((k + m) log n) | 各セグメントは 1 回挿入され、各クエリは log n ノードにアクセスします。 
| スペース | O(k log n) | 枝刈りを使用してセグメント ツリー ノードに格納された各セグメント |

 k と m はそれぞれ最大 10^5 スケールであり、対数係数は小さいままであるため、複雑さは制限内に収まります。 プルーニングにより、ノード サイズが管理可能な状態に保たれ、最悪の場合の爆発が防止されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、クエリ間隔と部分的に重複するセグメントのみがセットに含まれ、クエリ間隔内に完全には含まれないセグメントが含まれる場合に発生します。 たとえば、セグメント [1, 10] とクエリ [2, 5] を含むセットは no を返す必要があります。 チェックでは l ≥ x および r ≤ y が明示的に要求され、セグメントは r ≤ y 条件を満たさないため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、異なるセットが個別に条件を満たしているにもかかわらず、クエリ範囲に 1 つの不合格セットが含まれている場合です。 このアルゴリズムでは範囲内のすべてのノードが通過する必要があるため、単一の失敗でもクエリは正しく無効になります。 

最後のエッジケースは、セグメントがセット間で複製される場合です。 セットごとの存在のみをチェックし、成功するには範囲内のすべてのセットが必要であるため、重複は正確性や枝刈り動作に影響を与えません。
