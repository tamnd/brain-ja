 ## 解決策
 ## 問題の理解

 各テスト ケースには 2 つの正の整数が含まれます。 実行できる操作は 1 種類のみです。最初の数値を 1 増やすというものです。 目標は、できるだけ少ない増分を使用しながら、2 番目の数値で割り切れる現在の値以上の最も近い値に到達することです。 

入力はテスト ケースの数から始まり、その後、数値の各ペアが個別に処理されます。 すべてのペアについて、最初の数値が 2 番目の数値の倍数になるまでに必要な増分数を出力する必要があります。 

テストケースの数が到達しました$10^4$、どちらの数値も次のように大きくなる可能性がありますが、$10^9$。 これらの制限は、テスト ケースごとの定数時間の作業には十分小さいですが、割り切れるまで繰り返し 1 を追加するアプローチは除外されます。 最悪の場合、答え自体が膨大になる可能性があるため、シミュレーションには数億回、さらには数十億回の反復が必要になる可能性があります。 

いくつかの特殊なケースは注目に値します。 

最初の数値がすでに 2 番目の数値で割り切れる場合、答えはゼロになります。 

入力：```
1
92 46
```出力：```
0
```というような不注意な公式`b - (a % b)`生成する`46`、移動する必要がないため、これは不正解です。 

除数が現在の値より大きい場合、別の注意が必要な状況が発生します。 

入力：```
1
123 456
```出力：```
333
```456 の次の倍数は 456 そのものなので、$456-123=333$増加します。 

非常に小さな例でも、off-by-one エラーが発生する可能性があります。 

入力：```
1
10 4
```出力：```
2
```以来$10 \bmod 4 = 2$、12 に達するにはさらに 2 つの増分が必要です。次のような間違った式を使用します。`b - a % b - 1`2 の代わりに 1 が返されます。 

## アプローチ

 最も簡単な戦略は、数値を 1 ずつ増やして、約数で割り切れたらすぐに止めることを繰り返します。 この方法は正しいです。すべての操作が強制され、最初の割り切れる値で停止すると最小の移動数が得られるからです。 

このアプローチの問題は実行時間です。 仮定する$a=1$そして$b=10^9$。 私たちはパフォーマンスします$999\,999\,999$最初の倍数に達する前に増分します$10^9$。 このようなシミュレーションは遅すぎます。 

重要な観察は、割り算は次で割ったときの余りにのみ依存するということです。$b$。 残りが$r$、それではまさに$b-r$次の倍数に到達するには、さらに多くのユニットが必要です。 唯一の例外が発生するのは、$r=0$なぜなら、数値はすでに割り切れており、演算は必要ないからです。 

ブルートフォースは最終的には次の倍数に到達するため機能しますが、その差が大きい場合は失敗します。 剰余がその倍数からどれだけ離れているかをすでに示しているという観察により、問題はいくつかの算術演算に軽減されます。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取り、ケースは相互作用しないため、各ペアを個別に処理します。 
2. 剰余を計算する`a % b`。 これにより、現在の値が最も近い下限の倍数からどれだけ離れているかがわかります。`b`。 
3. 余りがゼロの場合、現在の値はすでに割り切れるため、ゼロを出力します。 
4. それ以外の場合は出力`b - remainder`。 この量は、現在の値から次の倍数までの正確な距離です。`b`。 

### なぜ効果があるのか

 任意の整数の場合$a$、書くかもしれません$$a = kb + r,$$どこ$0 \le r < b$。 もし$r=0$、 それから$a$それ自体はの倍数です$b$。 それ以外の場合、次の倍数は$$(k+1)b = kb + b.$$これら 2 つの値の差は次のとおりです。$$(k+1)b-a = b-r.$$すべての中間値にはまだゼロ以外の剰余があるため、これより多くの増分を行うことはできません。 したがって、アルゴリズムは常に最小限の移動数を生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    a, b = map(int, input().split())
    rem = a % b

    if rem == 0:
        print(0)
    else:
        print(b - rem)
```プログラムはまずテスト ケースの数を読み取り、各ペアを個別に処理します。 

すべてのペアについて、除算後の剰余を計算します。`a`による`b`。 この余りによって、数値が前の倍数からどれだけ離れているかが決まります。 余りがゼロであれば、答えはすぐにゼロになります。 

それ以外の場合、次の倍数までの距離は以下となります。`b - rem`。 

唯一の微妙な点は、分割可能な場合です。 書き込みのみ`b - (a % b)`間違った答えをするとき`a % b`ゼロです。出力されるためです。`b`の代わりに`0`。 このケースを個別に処理すると、off-by-one エラーが回避されます。

 ## 特殊なケース

 すでに割り切れる数の場合を考えてみましょう。 

入力：```
1
92 46
```アルゴリズムは計算します`92 % 46 = 0`。 剰余はゼロなので、すぐに 0 を出力します。インクリメントは必要なく、特殊なケースにより、誤って 46 を返すことが防止されます。 

ここで、現在の値より大きい約数を考えてみましょう。 

入力：```
1
123 456
```余りは ​​123 に等しくなります。アルゴリズムは次のように計算します。`456 - 123 = 333`これは、123 を正確に 333 回増やすと 456 に達することを意味します。これより小さい増分では 456 未満の値が生成され、456 で割り切れません。 

最後に、オフバイワンの間違いが明らかになる可能性があるケースを考えてみましょう。 

入力：```
1
10 4
```余りは ​​2 です。アルゴリズムは次の値を返します。`4 - 2 = 2`これは、数列が 11、次に 12 になることを意味します。2 つの演算の後、割り算が達成されます。 11 は 4 で割り切れないため、1 回の演算では不十分です。
