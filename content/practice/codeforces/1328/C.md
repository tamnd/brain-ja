 ## 解決策
 ## 問題の理解

 3 値文字列が与えられます`x`、各位置が次の数字であることを意味します。`0`、`1`、 または`2`。 タスクは、この 1 つの数値を 2 つの 3 進数に分割することです。`a`そして`b`、両方とも同じ長さです`x`、これらを 3 を法として 1 桁ずつ加算すると、次のようになります。`x`。 したがって、各位置はローカル制約を満たします。`a[i] + b[i] (mod 3) = x[i]`。 

結果として得られる両方の数値がゼロで始まってはいけないという追加のグローバル制約があり、すべての有効なペアのうち、通常の基数 3 の整数と比較したときに 2 つの数値のうち大きい方を最小化する必要があります。 

主な問題点は、桁制約が局所的であるにもかかわらず、目的関数がすべての位置を結合する完全な数値の辞書編集的な順序に依存していることです。 の最初の桁から`x`であることが保証されています`2`、私たちはすでにそれを知っています`(a[0], b[0])`のいずれかである必要があります`(1,1)`または`(2,0)`または`(0,2)`。 

制約が十分に厳しいので、`n`テスト全体で最大 50,000 になる可能性があるため、ソリューションはテスト ケースごとに線形である必要があります。 二次または偶数`O(n log n)`グローバル検索やプレフィックスを介した DP に依存するアプローチは不要であり、合格しません。 

微妙なエッジケースは、先行ゼロから発生します。 それを無視して貪欲に数字を割り当てると、`a[0]`そして`b[0]`ゼロ以外でなければなりません。次のような無効な解を簡単に生成できます。`a = 011...`または`b = 001...`。 もう 1 つの微妙な失敗モードは、桁ごとに両方の数値を独立して最小化しようとすることです。これにより、グローバルな順序付けの制約が破られ、次善の最大値が生成される可能性があります。 

## アプローチ

 ブルートフォース解釈では、桁ごとにすべての有効な分割を試し、位置ごとに最大 3 つの可能性に分岐し、結果のペアを辞書編集的に比較して、可能な最小の最大値を見つけます。 これはおおよそ次のことにつながります`3^n`最悪の場合の組み合わせは、たとえ小規模であっても完全に実行不可能です。`n`。 

重要な点は、目的は両方の数値を個別に最小化することではなく、辞書編集順にそれらを可能な限り等しくすることであるということです。 最小限に抑えているので、`max(a, b)`、それらが異なる最初の位置ができるだけ遅くなるようにし、その時点より前にそれらができるだけ近く一致するようにします。 

これは、貪欲な戦略を示唆しています。つまり、数字を左から右に処理し、可能な限り数字を割り当てて、`a[i]`そして`b[i]`モジュロ制約を尊重しながら、等しいか、少なくともバランスが取れています。 対称性を破らなければならない場合は、制御された方法で、一貫して小さい桁を一方の文字列に割り当て、大きい桁をもう一方の文字列に割り当てます。 

なぜなら`x[i]`は常に小さいため、有効なペアを事前に計算できます`(a[i], b[i])`各桁について、単純な状態を使用してそれらの中から選択します: すでに作成したかどうか`a`より小さい`b`か否か。 これにより、問題は線形の貪欲な割り当てに帰着します。 

最終的な解決策は、最適な戦略は次のことを維持することであるという事実を利用します。`a`そして`b`可能な限り同じ状態が続くとき`x[i] = 0 or 2`、次の場合にのみ、制御された方法で不均衡を導入します。`x[i] = 1`、対称分割は不可能です。

 ## アルゴリズムのチュートリアル

 私たちが建設します`a`そして`b`シンプルなアイデアを維持しながら、左から右に移動します。`a`小さくすることを決定するまでは、できるだけ大きくし、対称にします。`b`。 最小限にしてから`max(a, b)`それらのバランスを可能な限り大きくすることは、制御された方法で一方をわずかに小さく保つことを試みます。 

1. 2 つの空の配列を初期化します。`a`そして`b`、およびブール値のフラグ`tied = True`つまり、辞書編集上の意味では、両方の数値が今のところ同じであることを意味します。 このフラグは、順序を自由に選択できる柔軟性がまだあるかどうかを追跡します。 
2. 各桁の処理`x[i]`左から右へ。 私たちが選択するそれぞれのポジションで`(a[i], b[i])`そのような`(a[i] + b[i]) % 3 = x[i]`。 
3. もし`x[i] = 0`、有効なペアは次のとおりです。`(0,0)`、`(1,2)`、`(2,1)`。 まだ結ばれているとき、私たちは選択します`(0,0)`両方の数値を同一に保ち、可能な限り小さくするためです。 
4. もし`x[i] = 1`、有効なペアは次のとおりです。`(0,1)`、`(1,0)`、`(2,2)`。 まだ結ばれているとき、私たちは選択します`(0,1)`となることによって`a`よりも小さいままです`b`この時点から。 これにより、制御された分離が最も早く行われ、確実に分離されます。`max(a, b)`不必要に成長しません。 
5. もし`x[i] = 2`、有効なペアは次のとおりです。`(0,2)`、`(1,1)`、`(2,0)`。 まだ結ばれているとき、私たちは選択します`(1,1)`なぜなら、これは等価性を維持し、発散を遅らせ、最大値を最小化するのに最適だからです。 
6. 対称性を破る最初の位置の後 (異なる桁を選択するとき)、貪欲に続けます。常に、より大きな数を必要以上に増加させずに、すでに確立された順序を維持するペアを選択します。 

重要な実装のコツは、次の 1 つのポイントを明示的に決定することです。`a`より厳密に小さくなる`b`、そして、私たちはもはやそれらを平等に保とうとはしません。 

### なぜ効果があるのか

 このアルゴリズムは、最初の分岐点の前にある不変条件に依存します。`a`そして`b`は同一であり、辞書編集的に最適です。 初めて等しくないペアを選択するときは、辞書編集上の比較において、一方の文字列が他方の文字列より永続的に大きくならないように順序付けを行います。 

辞書編集的な比較は最初の異なる桁に依存するため、次のことを最小限に抑えます。`max(a, b)`つまり、この最初の違いを遅らせて制御することになります。 すべての桁の選択は、等価性を維持するか、モジュロ制約と一致する可能な限り最小の非対称性を導入するために行われます。 これにより、桁制約に違反することなく、より小さな最大値を生成する代替割り当てが存在しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        x = input().strip()

        a = []
        b = []
        equal = True

        for i, ch in enumerate(x):
            d = int(ch)

            if d == 0:
                if equal:
                    a.append('0')
                    b.append('0')
                else:
                    # once split, keep smaller side small
                    a.append('0')
                    b.append('0')

            elif d == 1:
                if equal:
                    # start separation
                    a.append('0')
                    b.append('1')
                    equal = False
                else:
                    a.append('0')
                    b.append('1')

            else:  # d == 2
                if equal:
                    # keep them equal as long as possible
                    a.append('1')
                    b.append('1')
                else:
                    a.append('1')
                    b.append('1')

        print("".join(a))
        print("".join(b))

if __name__ == "__main__":
    solve()
```コードは両方の数値を左から右に構築します。 の`equal`flag は、これまでのところ両方の数値が依然として同一であるかどうかを表すことを目的としています。 数字の場合`1`を代入することで、最初の機会に意図的に対称性を破ります。`(0,1)`、確保する`a`よりも小さくなる`b`。 数字の場合`0`そして`2`を使用して、両辺を等しく保ちます。`(0,0)`そして`(1,1)`これにより、不必要に大きな数を増やすことがなくなります。 

微妙な点は、辞書編集上の順序が一度決定されると、以前の決定を後戻りしたり再考したりする必要がないということです。`a`そして`b`が固定されている場合、将来のすべての最適な選択は、最終的な最大値を最小化することと局所的に一致します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、入力が 1 桁の場合です。`2`。 唯一の有効な分解は、`(1,1)`、 以来`(0,2)`そして`(2,0)`数値の 1 つに先行ゼロが作成されます。 アルゴリズムは次のように割り当てるため、これを自然に処理します。`(1,1)`遭遇したとき`2`初期状態では。 

Another case is a string of all`2`s. ここでは発散は起こらないため、両方の数値は全体を通して同一のままです。 このアルゴリズムは非対称性を引き起こすことはありません。これは正しいことであり、いかなる偏差も最大数を増加させるだけであるためです。 

最後の微妙なケースは、最初の数桁が`2`続いて`1`。 最初`1`最初の意味のある分離を強制します。 アルゴリズムにより、これが 1 回だけ発生し、その後は両方の数値が一貫したままとなり、最大値の不必要な増加が防止されます。
