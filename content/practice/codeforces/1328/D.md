 ## 解決策
 ## 問題の理解

 円形に配置された位置が与えられ、それぞれの位置に動物の種類が割り当てられます。 ポジションはサイクルで接続されているため、最後のポジションの後に再び最初のポジションが来ます。 各位置に色を割り当てる必要があります。 

この制約はローカルです。サイクル上の 2 つの隣接する位置に異なる動物の種類がある場合、同じ色を共有することはできません。 2 つの隣接する位置が同じタイプである場合、それらは何も違反することなく色を共有できます。 目標は、この隣接ルールを尊重しながら、全体で使用される個別の色の数を最小限に抑えることです。 

これは、異なる値を持つ位置間のエッジのみが「重要」であるサイクル グラフの色付けとみなすことができます。 隣接する値が等しいと、そのエッジの制約が事実上解除されます。 

入力サイズは大きく、テスト ケース全体の合計 n は最大 2·10^5 です。 これにより、テスト ケースごとに二次関数が除外されます。 ワーストケースのパッキングでは O(n log n) を何度も繰り返してもタイトになるため、どのような解もテスト ケースごとに本質的に線形である必要があります。 

重要な微妙な点は、位置 n と位置 1 の間の円形エッジです。多くの誤った貪欲なアプローチは、このラップアラウンド制約でのみ失敗します。 たとえば、最後の値が最初のタイプのパターンに一致する場合を除いて、すべての値が交互である場合、サイクル クロージャにより、パリティと対称性に応じて追加の色を強制したり、圧縮を許可したりできます。 

すべての要素が同一である場合、別の特殊なケースが発生します。 その場合は何の制約もないので単色で十分です。 交互のパターンに少なくとも 2 つの色を想定する単純な解決策では、この場合は色が塗り重ねられてしまいます。 

最後に、最もデリケートな状況は、配列がほぼ交互になっているが「ブレーク」が 1 つだけ含まれている場合、またはサイクル パリティがエンドポイントの等価性と競合する場合です。 ここで、有効なエッジの下でサイクルが 2 部であるかどうかに応じて、答えは 2 または 3 になります。 

## アプローチ

 ブルートフォースの試みでは、競合が発生するたびにバックトラックしながら、段階的に色を割り当てようとします。 各位置で、隣接する色との隣接性制約に違反しない任意の色を選択できます。 最悪の場合、各位置が複数の色の選択肢に分岐し、サイクル制約によって最初と最後の位置が結合されるため、これは指数関数的になります。 

より構造化された総当たり攻撃は、k を 1 から上に向かって試し、有効な色付けが存在するかどうかをテストすることです。 各 k について、選択的なエッジを持つサイクル グラフでグラフの色付けの実行可能性チェックを実行します。 多くの値をテストする場合、これでも O(n·k) または最悪の場合 O(n²) のコストがかかります。 

重要な観察は、制約グラフが非常に単純であるということです。つまり、これはサイクルであり、エッジは隣接するタイプが異なる場合にのみ問題になります。 このようなグラフの最大次数は 2 であるため、その構造はパスの集合と、場合によってはサイクルを加えたものになります。 すべての接続されたコンポーネントはパスまたはサイクルのいずれかです。 これにより、直ちに色数が制限されます。パスは 2 色可能で、サイクルは奇数サイクルでない限り 2 色可能です。 

したがって、答えは 1、2、または 3 のいずれかになります。 3 色が必要になるのは、少なくとも 1 つのエッジがあり、すべての「アクティブな制約」によって形成されるサイクルが奇数長で、ラップアラウンドによりパリティ矛盾が強制される場合だけです。 

建設的な解決策は、配列を t[i] ≠ t[i+1] のエッジ上の循環カラーリング問題として扱うことです。 次に、安定して 2 色化できるかどうかを確認します。 そうでない場合は、慎重に選択したブレークポイントに 3 番目の色を導入して、サイクルを線形化します。

 ## アルゴリズムのチュートリアル

 テストケースごとに作業します。

1. まず、配列内のすべての値が同一かどうかを確認します。 その場合は、すべての位置に色 1 を割り当てます。 隣接性制約はトリガーされないため、1 つの色が最適です。 
2. それ以外の場合は、色 1 と 2 を使用してサイクル上で 2 色塗りを構築しようとします。各位置をノードとして扱い、t[i] ≠ t[i+1] の場合は c[i] ≠ c[i+1] であることを強制します。 
3. 少なくとも 1 つの開始パリティが機能する場合にのみサイクルを一貫して色付けできるため、2 つの可能な開始割り当てを試します。 最初の試行では c[1] = 1 を設定します。 
4. 順方向に伝播します。2 から n までの各 i について、t[i] が t[i-1] に等しい場合、それらの間に制約がないため、c[i] = c[i-1] を設定します。 それらが異なる場合は、c[i] = 3 - c[i-1] を設定し、反転を強制します。 
5. すべての色を塗りつぶした後、n と 1 の間の終了エッジを検証する必要があります。t[n] ≠ t[1] の場合、c[n] ≠ c[1] が必要です。 これに該当する場合は、2色塗りも承ります。 
6. 検証が失敗した場合、2 色は不可能であると結論付けられます。 次に、伝播を意図的に変更する単一のブレークポイントを導入して、3 色のソリューションを構築します。 
7. 3 色のソリューションを構築するには、t[i] ≠ t[i-1] となるインデックス i を見つけます。 前と同様に 1 と 2 を交互に使用して c[1..i] を設定します。 次に、c[i+1] = 3 を割り当て、常に隣接制約を尊重しながら残りを 1 と 2 で貪欲に色付けし続けます。 3 番目の色は、サイクル内のパリティの競合を解消するセパレーターとして機能します。 

### なぜ効果があるのか

 隣接制約は、異なる連続タイプ間にのみエッジが存在するグラフを定義します。 各接続コンポーネントはパスまたはサイクルのいずれかです。 パスは常に 2 色可能です。 サイクルは、その長さが偶数である場合にのみ 2 色可能です。 唯一の障害は、ラップアラウンド制約によって引き起こされる奇数パリティを持つ単一サイクル コンポーネントから発生します。 1 つの頂点カラーを導入すると、パスに循環する 3 つのブレークが発生し、パリティ制約が完全に排除され、その後、残りの構造には 2 色で十分になります。 これにより、最大 3 色での実現可能性が保証され、制約が存在しない場合にのみ 1 色が可能であり、サイクル条件が成立する場合に 2 色が可能となるため、最小性が続きます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        t = list(map(int, input().split()))

        if len(set(t)) == 1:
            print(1)
            print(" ".join(["1"] * n))
            continue

        c = [0] * n

        # try 2-coloring
        c[0] = 1
        for i in range(1, n):
            if t[i] == t[i - 1]:
                c[i] = c[i - 1]
            else:
                c[i] = 3 - c[i - 1]

        ok = True
        if t[0] != t[-1] and c[0] == c[-1]:
            ok = False

        if ok:
            print(2)
            print(" ".join(map(str, c)))
            continue

        # need 3 colors
        c = [0] * n

        # find a differing edge to place the third color
        idx = -1
        for i in range(n):
            if t[i] != t[i - 1]:
                idx = i
                break

        # build from idx
        c[idx] = 3
        for i in range(idx - 1, -1, -1):
            if t[i] == t[i + 1]:
                c[i] = c[i + 1]
            else:
                c[i] = 1 if c[i + 1] == 2 else 2

        for i in range(idx + 1, n):
            if t[i] == t[i - 1]:
                c[i] = c[i - 1]
            else:
                c[i] = 1 if c[i - 1] == 2 else 2

        print(3)
        print(" ".join(map(str, c)))

if __name__ == "__main__":
    solve()
```最初のブランチは、制約がまったく存在しない自明なケースを処理し、単一色への即時圧縮を可能にします。 2 番目のブランチは、隣接するタイプが異なるエッジに沿って一貫性を強制することによって候補 2 カラーリングを構築し、等しい隣接するタイプをコンポーネントのマージとして効果的に扱います。 

すべての内部エッジが構築によって満たされるため、検証ステップは円形クロージャーにのみ必要です。 最後と最初が異なっていても同じ色を受け取る場合、交互の伝播により一貫性のないサイクルが生成され、フォールバックが強制されます。 

3 色構造は、異なるタイプ間の移行点でサイクルを意図的に「切断」します。 インデックスは、カットが制約に関して有効になるように選択されます。 その時点から、サイクルがパスに分割されているため、着色は 2 色のみを使用して両方向に外側に進みます。

 | 1 | - | 開始 | 1 |

これにより、単純な伝播で十分であり、サイクル矛盾が発生しないことが確認されます。 

### 例 2

 入力:```
5
1 2 1 2 3
```伝播:

 | 私 | t[i-1]、t[i] | c[i] |
 | --- | --- | --- |
 | 1 | - | 1 |
 | 2 | 1 ≠ 2 | 2 |
 | 3 | 2 ≠ 1 | 1 |
 | 4 | 1 ≠ 2 | 2 |
 | 5 | 2 ≠ 3 | 1 |

 ここでラップアラウンド: t[5] ≠ t[1] しかし c[5] = c[1] = 1 であるため、競合します。 このサイクルではパリティ矛盾が強制されるため、ブレーク時に 3 番目の色を導入して、有効な 3 色の割り当てを生成する必要があります。

 ## 特殊なケース

 すべて等しい場合は、エッジのない縮退グラフをトリガーします。 アルゴリズムはただちに単一の色を割り当てます。これは、制約がアクティブになることがないため最適です。 伝播ベースの方法はいずれも機能しますが、不必要な遷移のチェックに時間を浪費することになります。 

2 番目のエッジ ケースは、アレイが完全に交互になる場合に発生します。 伝播では一貫して色が交互に変化し、パリティが一致すればラップアラウンド チェックが成功します。 これにより、有効長が均等なサイクルが 2 色化可能であることが確認されます。 

3 番目の特殊なケースは、均一な配列に不一致が 1 つだけ存在する場合に発生します。 伝播は局所的に一貫性を持ちますが、サイクルの終了によって矛盾が生じ、アルゴリズムが 3 色構成に強制されます。 挿入された 3 番目の色はサイクルを壊し、それをパスに変え、さらに複雑にすることなく実行可能性を回復します。
