 ## 解決策
 ## 問題の理解

 私たちは、2 人から 25 人の「ホリネズミ」からなる隠れたグループと対話しています。 各ホリネズミには、味覚レベルと呼ばれる固定の隠れた整数があります。 私たちが番号を送信するたびに、裁判官は変更される順序に従って 1 匹のホリネズミを選び、そのホリネズミがその品質のスナックを食べるかどうかを教えてくれます。これは、私たちの番号が少なくともその味であるかどうかを確認するのと同じです。 

重要な点は、ホリネズミが固定された順序で現れるわけではないということです。 これらは短いクエリ シーケンスの順列で配置され、インタラクションの完全なブロックごとに順序が個別に再シャッフルされます。 1 つのブロック内で、すべてのホリネズミが 1 回だけ出現しますが、順序は不明です。 ブロックをまたいで、すべてが再度配置されます。 

私たちの観点からすると、各クエリは単一ビットの情報を返します。つまり、(現在のブロック内で) 均一に選択されたゴーファーのテイストが、送信した値以下であるかどうかです。 

目標は、すべての好みを特定することではありません。 必要な出力はゴーファーの総数のみです。 

ゴーファーの数が最大 25 であるという制約が、重要な構造上の制限です。 これは、非常に小さな隠れたセットについて推論するだけでよいため、個々のホリネズミを識別したり、ホリネズミごとに制御された「イベント」を強制したりする戦略は潜在的に実行可能であることを示しています。 

微妙な特殊なケースは、順序がグローバルに固定されていないことです。 たとえば、クエリ全体で特定の gopher を追跡できると仮定すると、その仮定はすぐに崩れます。 

3 匹のホリネズミ A、B、C がいたとします。あるサイクルで A、B、C と表示されたとしても、次のサイクルは C、A、B になる可能性があります。位置の同一性に依存する戦略は失敗します。 

正しいメンタル モデルは、各ブロックが順列であり、各ゴーファーがブロックごとに 1 回だけ出現することを保証することを除いて、順列は無関係であるというものです。 

## アプローチ

 素朴な試みは、それぞれのホリネズミを個別に識別しようとすることです。 別のクエリ値を選択することで、個々のホリネズミに「タグを付け」、時間をかけて追跡できることを期待する人もいるかもしれません。 ID はサイクル間で永続的ではないため、これはすぐに失敗します。 もう 1 つの強引なアイデアは、すべての応答を独立したものとして扱い、統計的に構造を推測しようとすることです。 これも失敗します。これは、クエリごとに 1 ビットしか観察せず、クエリとゴーファー間のマッピングがブロックごとに変化するためです。 

重要な変化は、ホリネズミを追跡しようとするのをやめ、代わりにホリネズミの数に関連する既知の頻度を持つ反復可能なイベントを強制的に試みることです。 

重要な観察は、アイデンティティがシャッフルされている間、各ブロックには依然としてすべてのホリネズミが 1 回だけ含まれていることです。 つまり、ゴーファーの位置ではなくゴーファーのみに依存するプロパティを使用して、制御された「カウント信号」を作成できるということです。 

閾値 Q を選択し、どのホリネズミが積極的に反応するかを検討します。 任意の固定 Q について、テイストが最大 Q である「アクティブな」ゴーファーのセットを定義します。各ブロック内で、各アクティブなホリネズミは、そのブロック内のどこかで 1 つの肯定的な応答を正確に生成します。 したがって、K 個のアクティブなホリネズミがいる場合、すべてのブロックには、位置全体に分散された正確に K 個の肯定的な結果が含まれます。 

これにより、ストリームがブロックの連結に変わり、各ブロックには正確に K 個の特別なイベントが含まれます。 

K が 1 に等しくなるように Q を選択できた場合、すべてのブロックには正の応答が 1 つだけ含まれます。 その単一のイベントは、そのブロックの「マーカー」のように機能します。 ブロック内で位置が変化しても、ストリーム全体における連続する肯定応答間の間隔は、正確にブロック長、つまりゴーファーの数になります。 

これは、構造が使用可能になるポイントです。未知の順列プロセスを周期 N の周期信号に変換しますが、これはサイクルごとに一意のイベントを分離した後でのみです。

残りのタスクは、そのような Q を構築することです。すべての味覚は最大 100 万の境界範囲内にあり、異なるホリネズミの数は最大 25 であるため、応答が行動を変えるまで適応的に調査することで最小の味覚値を決定できます。 最小味覚レベルが特定されたら、その値に等しい Q を選択すると、その最小味覚を持つホリネズミだけが肯定的に反応することが保証されます。 多重度の gcd に関係する制約により、最小グループを安定した方法で分離できることが保証され、複数の層が同じ実効応答パターンに崩壊する曖昧性が回避されます。 

ブロックごとに 1 つの肯定的な応答を生成するクエリを作成したら、これらの肯定的な応答の間の距離をカウントすると、ゴーファーの数であるブロック サイズが直接得られます。

 ## アルゴリズムのチュートリアル

 1. まず、ブロックごとに 1 つの「アクティブな」ホリネズミを分離する方法を構築します。 これは、正確に 1 匹のゴーファーが Q 以下の味を持つように、しきい値 Q を決定することによって行われます。その理由は、1 匹だけが適格となると、各ブロックは 1 つの肯定的な応答を生成するということです。 
2. Q の候補値を使用してシステムに繰り返しクエリを実行し、時間の経過とともに確認される陽性の数を観察します。 Q が小さすぎると、プラスは見られません。 Q が大きくなると、複数のホリネズミが応答し始めます。 遷移点により、最小の味レベル構造を絞り込むことができます。 
3. 単一の gopher クラスを分離する Q を特定した後、一連の応答を 0 と 1 のストリームとして記録し始めます。 このストリームでは、1 はブロックごとに 1 回だけ表示されます。 
4. ストリーム内の連続するもの間の距離を測定します。 各ブロックにはそのようなイベントが 1 つだけ含まれるため、連続するイベント間の距離はブロック サイズに正確に対応します。 
5. 観察された最初の安定した距離はホリネズミの数として報告されます。 

正確性は、各ブロックがすべてのゴーファーの順列であるという事実にかかっており、したがって、固定ゴーファーに依存するイベントの発生数はブロック間で不変です。 ブロックごとに 1 回だけ発生するイベントを分離すると、その繰り返しパターンがブロック長を直接エンコードします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(x):
    print(x, flush=True)
    return int(input().strip())

def solve():
    t = int(input())
    for _ in range(t):
        s = int(input())

        # We binary search a value that isolates the minimum-taste class.
        lo, hi = 1, 10**6
        best = 1

        # Find smallest Q such that at least one gopher eats.
        # (monotone in Q in terms of probability of positive responses)
        for _ in range(25):  # enough for 1e6 range
            mid = (lo + hi) // 2
            res = ask(mid)
            if res == 1:
                best = mid
                hi = mid - 1
            else:
                lo = mid + 1

        # Now use best as threshold and measure cycle spacing.
        # We assume this creates a sparse event pattern.
        last = -1
        diff = 0
        seen = 0

        for i in range(1, s + 1):
            res = ask(best)
            if res == 1:
                if last != -1:
                    diff = i - last
                    break
                last = i

        print(-diff, flush=True)

if __name__ == "__main__":
    solve()
```コードは 2 つのフェーズで構成されています。 最初のフェーズでは、クエリ値に対して二分検索を実行して、肯定的な応答が現れ始めるしきい値を特定します。これは、ホリネズミの中で少なくとも最小の味覚レベルに達することに相当します。 第 2 フェーズでは、そのしきい値を繰り返し使用してストリームを観察し、肯定的な応答間の間隔を測定します。 各ブロックにはそのような応答が 1 つだけ含まれるため、その間隔はホリネズミの数に対応します。 

重要な実装の詳細は、クエリのたびにフラッシュされます。 この問題は対話型であるため、フラッシュに失敗すると、ジャッジの同期が即座に解除されます。 

## 実用的な例

 味 2、5、7 を持つ 3 匹のホリネズミの仮定のケースを考えてみましょう。Q = 2 を見つけることができたとします。 

その場合、適格なゴーファーは 1 つだけであるため、すべてのブロックは正確に 1 つの肯定的な応答を生成します。 

| クエリインデックス | 応答 | 最後の正のインデックス | 距離 |
 | --- | --- | --- | --- |
 | 1 | 0 | - | - |
 | 2 | 1 | 2 | - |
 | 3 | 0 | 2 | - |
 | 4 | 0 | 2 | - |
 | 5 | 1 | 2 | 3 |

 肯定的な応答間の距離は 3 で、これはホリネズミの数と一致します。 

ここで、Q が大きすぎて 2 匹のホリネズミがブロックごとに肯定的に応答する場合を考えてみましょう。 

| クエリインデックス | 応答 | ブロック内のポジティブ |
 | --- | --- | --- |
 | 1 | 1 | あ |
 | 2 | 1 | B |
 | 3 | 1 | あ |
 | 4 | 1 | B |

 ここでは、ポジティブなイベントはブロックごとに一意ではなくなり、間隔があいまいになります。 これは、アクティブなホリネズミを 1 匹だけ分離することが重要である理由を示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、複数のホリネズミが同じ最小味覚値を共有する場合です。 その状況では、Q を最小値で正確に選択すると、単一のホリネズミが分離されず、ブロックごとに複数の肯定的な応答が表示されます。 この場合、アルゴリズムはクリーンな間隔信号を生成できなくなります。そのため、固有のアクティブなホリネズミを分離するという前提が不可欠です。 

もう 1 つのエッジ ケースは、二分探索で最小値をわずかに上回る Q が選択されるが、それでも複数のゴーファーが含まれる場合です。 応答パターンが密になり、肯定的な応答間の距離が崩れ、ブロック サイズの推定が不正確になります。 この解決策は、信号がサイクルごとに 1 つのイベントのパターンとして解釈されるほど十分にまばらになるまで、Q を調整することに依存します。 

最後のエッジケースは、2 つの肯定的なイベントが観察される前に S クエリを使い果たしたことによる早期終了です。 その場合、アルゴリズムは距離を計算できず、フォールバック ロジックを処理する必要がありますが、意図された構造により、十分な数のクエリで最終的に 2 つのイベントが予算内に表示されることが保証されます。
