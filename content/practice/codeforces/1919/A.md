 ## 解決策
 ## 問題の理解

 アリスとボブはそれぞれ、ある程度の数のコインが入った財布から始まります。 毎ターン、現在のプレイヤーはウォレットをそのまま保持することも、2 つのウォレットを交換することもできます。 その選択の後、彼らは現在保持している財布からちょうど 1 枚のコインを取り出さなければなりません。 

プレーヤーが最終的に保持することになる財布に、コインを取り出す前に少なくとも 1 枚のコインが含まれている場合にのみ、移動は合法です。 合法的な手を打てなかった最初のプレイヤーが負けます。 

テストケースごとに、初期コイン数が与えられます。`a`そして`b`。 両プレイヤーは完璧なプレイをしており、勝者が先に動いたアリスかボブのどちらであるかを判断する必要があります。 

制約は驚くほど大きいです。 各ウォレットには最大で次のものを含めることができます`10^9`コイン、最大まであります`1000`テストケース。 ゲームを一手一手シミュレートするアプローチは直ちに不可能です。 1 つのゲームはおおよそ続く可能性があります`a + b`ターン、おそらく約`2 · 10^9`動く。 勝ちポジションと負けポジションを直接数学的に特徴付ける必要があります。 

難しいのは、ウォレットを交換できるため、ゲームが単純な山を取り除くゲームよりも複雑に見えることです。 よくある間違いは、どのプレイヤーがどのウォレットを所有しているかに注目してしまうことです。 所有権は常に変わりますが、実際には無関係です。 もう一つの間違いは、財布が大きいほど常に重要であると考えることです。 小さな例では、コインの合計数だけが勝者を決定することを示しています。 

次の位置を考慮してください。```
a = 1, b = 1
```コインの合計数は 2 です。アリスが 1 枚のコインを取り除き、ボブが 1 枚のコインを取り除き、コインは残りません。 次のプレイヤーはアリスで、負けます。 正しい答えは、`Bob`。 

次に、次のことを考えてみましょう。```
a = 1, b = 4
```コインの合計数は 5 です。取り外し可能なコインは合計 5 枚あるため、ゲームはちょうど 5 手続きます。 アリスは 1、3、5 番目の移動を行うため、ボブはその後移動できなくなります。 正しい答えは、`Alice`。 

ウォレットの所有権を追跡しようとする不注意なアプローチでは、この非常に単純なパターンを見逃す可能性があります。 

## アプローチ

 最も直接的なアイデアは、ゲームの状態を次のようにモデル化することです。`(a, b, turn)`そして、各ポジションが勝っているか負けているかを再帰的に判断します。 すべての状態から、現在のプレーヤーには最大 2 つの選択肢があります: スワップするかスワップしない。 選択後、現在のウォレットから 1 つのコインが削除されます。 

小さな値の場合、これは機能します。 到達可能なすべての位置を列挙し、ゲーム ツリーを観察できます。 問題は、状態空間がウォレットのサイズに応じて増大することです。 以来`a`そして`b`と同じくらい大きいかもしれない`10^9`、そのような検索は完全に不可能です。 

パターンを見つけるには、移動中に実際に何が変化するかを調べます。 

すべての合法的な動きは、ゲームからちょうど 1 枚のコインを取り除きます。 どのような動きもコインを生み出すことはありません。 スワップでは、現在誰がどのウォレットを保持しているかが変更されるだけです。 コインの総数は毎ターンちょうど 1 つずつ減少します。 

させて```
S = a + b
```最初に存在するのは、`S`コイン合計。 それぞれの動きでちょうど 1 枚のコインが取り除かれるため、正確に`S`すべてのコインがなくなる前に移動します。 

重要な観察は、どこかに少なくとも 1 枚のコインが存在する限り、現在のプレイヤーはいつでも手を打つことができるということです。 現在のウォレットが空の場合は、単に空でないウォレットを交換して取得します。 移動が不可能となるのは、両方のウォレットにコインがゼロの場合のみです。 

つまり、ゲームの長さは完全に固定されています。 まさにその通りです`S`戦略に関係なく動きます。 

長さが決まってしまえば、ゲームは簡単になります。 アリスは番号付きの動きをします```
1, 3, 5, ...
```そしてボブは番号付きの動きをします```
2, 4, 6, ...
```もし`S`が奇数である場合、アリスは最後の動きを実行し、ボブは空の位置に面します。 アリスが勝ちます。 

もし`S`が偶数の場合、ボブは最後の手を実行し、アリスは空のポジションに直面します。 ボブが勝ちます。 

ゲーム全体は、次のパリティをチェックすることに要約されます。`a + b`。

 ## アルゴリズムのチュートリアル

 1.読む`a`そして`b`。 
2. コインの合計数を計算します。```
S = a + b
```すべての動きでちょうど 1 枚のコインが削除されるため、`S`はゲーム内の正確な手数でもあります。 
3. かどうかを確認します。`S`奇数か偶数です。 

もし`S`奇妙です、アリスが最後の動きをして勝ちます。 

もし`S`が互角の場合、ボブが最後の動きをして勝ちます。 
4. 対応する勝者を出力します。 

### なぜ効果があるのか

 重要な不変条件は、すべての合法的な動きによってコインの総数がちょうど 1 つ減るということです。 これを変えることはできません。 また、少なくとも 1 つのコインがどこかに残っている場合は常に、現在のプレーヤーは必要に応じて交換することで空ではないウォレットを取得できます。 したがって、ゲームが早く終了することはありません。 

ゲームは全員が終わるまで続けなければなりません`a + b`コインは取り外されました。 合計の手数は固定されているため、`a + b`、勝者はその数値の同等性によってのみ決定されます。 手数が奇数の場合はアリスが最終手を取ることを意味し、偶数の場合はボブが最終手を取ることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    a, b = map(int, input().split())
    if (a + b) % 2:
        print("Alice")
    else:
        print("Bob")
```実装は数学的特徴付けに直接従います。 

テストケースごとに計算します`a + b`そしてそのパリティを検査します。 戦略はゲームの長さに影響を与えないため、シミュレーションは必要ありません。 すべての動きは常に 1 枚のコインを消費し、ゲームは常にすべてのコインがなくなるまで続きます。 

Python ではオーバーフローの懸念はありません。 考えられる最大の金額であっても、```
10^9 + 10^9 = 2 · 10^9
```通常の整数演算の範囲内に問題なく収まります。 

唯一の微妙な点は、スワップによって将来の手の合計数が決して変更されないことを認識していることです。 その観察が行われると、実装は 1 行で決定されます。

import sys
import io

def solve():
    input = sys.stdin.readline
    t = int(input())
    ans = []
    for _ in range(t):
        a, b = map(int, input().split())
        ans.append("Alice" if (a + b) % 2 else "Bob")
    print("\n".join(ans))

    old_stdin = sys.stdin
    old_stdout = sys.stdout

    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = old_stdout
