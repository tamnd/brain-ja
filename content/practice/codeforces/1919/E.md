 ## 解決策
 ## 問題の理解

 サイズの隠し配列をリバース エンジニアリングするように求められます。$n$のみを含む$1$そして$-1$。 配列自体が与えられる代わりに、配列のプレフィックス合計のソートされたリストが与えられます。 位置のプレフィックスの合計$i$最初の合計です$i$配列の要素。 すべてのプレフィックスの合計を計算した後、それらは非降順で並べ替えられ、それが受信する入力になります。 私たちのタスクは、このソートされたプレフィックス合計配列を生成できる個別の配列の数をカウントすることです。 

制約は控えめです。すべてのテスト ケースにわたる要素の合計数は 5000 を超えません。これは、アルゴリズムが最大で複雑であることを意味します。$O(n^2)$1 秒の制限内で効率的に実行されます。 考えられるすべての配列を明示的に生成しようとする素朴なアプローチは、すぐには実行不可能です。$n=5000$候補配列の数は$2^{5000}$という天文学的な数字になります。 

ソートされたプレフィックスの合計にゼロまたは繰り返しの要素が含まれる場合、エッジ ケースが発生します。 たとえば、ソートされたプレフィックスの合計が次の場合、`[0]`のために`n=1`、サイズ 1 の配列はありません。`1`そして`-1`のプレフィックス合計を生成できます`0`。 同様に、累積和が可能な以上減少する必要がある配列でも、ゼロ解が得られます。 これらを正しく処理するには、各プレフィックスの合計を残りの要素と組み合わせる方法が何通りあるかを慎重に考慮する必要があります。 

## アプローチ

 ブルートフォース手法では、サイズのすべての配列を列挙します。$n$要素付き`1`そして`-1`、プレフィックスの合計を計算し、並べ替えて、指定された配列と比較します。 これは問題を直接モデル化するため、原理的には機能します。 ただし、最悪のシナリオの操作数は次のとおりです。$2^n \cdot n \log n$、でもそれは不可能です$n=20$、ましてや$5000$。 

複雑さを軽減するための重要な洞察は、これをプレフィックス合計の複数セットの計数問題とみなすことです。 プレフィックスの合計の配列を次のようにします。$p$。 各プレフィックス合計は、以前のプレフィックス合計から 1 ずつ増加するか、1 ずつ減少します。 We can iterate through the sorted prefix sums, tracking how many "open" prefix sums there are at each value, and match them with incoming prefix sums using a dynamic programming approach. 具体的には、プレフィックス合計値の場合$v$、次のプレフィックス合計になる方法の数は、以前のプレフィックス合計から 1 を引いた数によって決まります。$v$、すでに使用されている数を引いたもの。 

これにより問題は次のように縮小されます$O(n^2)$それぞれの操作について$n$ポジションについては、最大でカウントをチェックする必要があるかもしれません$n$以前のプレフィックスの合計。 DP は、各要素を有効な以前のプレフィックス合計に割り当てる方法の実行カウントを保持し、有効な割り当ての数を法的に累積します。$998244353$。

 ## アルゴリズムのチュートリアル

 1. 動的プログラミングテーブルを初期化する`dp[i]`接頭辞の合計で終わる配列を構築する方法の数を表します`p[i]`。 
2. カウンタを使用して、各プレフィックスの合計がこれまでに出現した回数を記録します。 
3. ソートされたプレフィックスの合計を反復処理します。 最初の要素がそうでない場合、`1`または`-1`、有効な配列がないため、答えは 0 です。それ以外の場合は、最初のプレフィックス合計のウェイ数を 1 に設定します。 
4. 後続の各プレフィックス合計について`p[i]`、以前のプレフィックスの合計が次の値に等しい数を数えます。`p[i]-1`。 これは、前の合計を 1 増やす有効な方法を表します。`p[i]`。 
5. 方法の数を増やします。`p[i]`使用可能な以前のプレフィックス合計の数によって計算され、使用可能なプレフィックス合計のカウンタが消費されるにつれて減分されます。 
6. すべてのプレフィックスの合計を処理した後、答えは最後の要素に対して累積されたウェイの数、モジュロになります。`998244353`。 

不変条件は、DP が各ステップで、元の配列内の位置へのプレフィックス合計の有効な割り当ての数を正確にカウントすることです。 各プレフィックスの合計は、前の合計に 1 を加えたもの、または 1 を引いたものからのみ形成できます。 マルチセット数を維持することで、プレフィックス合計が誤って再利用されないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def solve_case(n, p):
    if p[0] not in [-1, 1]:
        return 0
    from collections import Counter
    counter = Counter()
    ways = 1
    counter[p[0]] += 1
    for i in range(1, n):
        prev_count = counter[p[i]-1]
        if prev_count == 0:
            return 0
        ways = ways * prev_count % MOD
        counter[p[i]] += 1
        counter[p[i]-1] -= 1
    return ways

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        print(solve_case(n, p))

if __name__ == "__main__":
    main()
```最初のチェックでは、最初のプレフィックス合計が次のいずれかであることを確認します。`1`または`-1`他の値が最初のプレフィックス合計として出現できないためです。 私たちは、`Counter`以前のプレフィックス合計が存在する回数よりも多く割り当てられることを避けるために、使用されるプレフィックス合計の数を変更します。 各反復では、現在のウェイ数に以前の有効な合計の数を乗算し、カウンターを更新します。 モジュロ演算により、整数のオーバーフローが防止されます。
