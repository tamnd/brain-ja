 ## 解決策
 ## 問題の理解

 配列が与えられているので、それを 2 つのサブシーケンスに分割し、それらを呼び出す必要があります。$s$そして$t$、各サブシーケンス内の相対的な順序を維持しながら、すべての要素を 1 回だけカバーします。 

どのシーケンスでも、ペナルティは、左から右に移動するときにシーケンスが増加する回数です。 だから毎回$b_i < b_{i+1}$、1単位を支払います。 

目標は、要素を 2 つのサブシーケンスに分散して、両方のシーケンス内で増加する隣接ペアの総数が最小限になるようにすることです。 

制約により、最大で次のことが許可されます。$2 \cdot 10^5$したがって、すべてのソリューションはテスト ケースごとに本質的に線形または線形に近いものでなければなりません。 すべての分割にわたる二次 DP やすべてのサブシーケンスを明示的に追跡することは不可能です。 

重要なエッジ ケースは、配列がすでに増加していないか、一定になっている場合です。 このような場合、すべてを 1 つのサブシーケンスに入れることができ、増加を生じないため、最適な答えはゼロになります。 もう 1 つのエッジ ケースは、厳密に増加する配列です。この場合、慎重に分割しない限り、サブシーケンスは依然として増加する構造を継承するため、コストが無視できなくなり、貪欲な分散が強制されます。 

## アプローチ

 総当たりで試す場合は、各要素を次のいずれかに割り当てます。$s$または$t$、次にペナルティを計算します。 つまり$2^n$テスト ケースごとに割り当てを行うことは、直ちに不可能です。 

より構造化された観点は、要素を左から右に処理し、各要素をどのサブシーケンスに配置するかを決定することです。 ペナルティは、サブシーケンス内の最後の要素が現在の要素より小さいかどうかのみに依存するため、各サブシーケンスは増加が「悪い遷移」となるチェーンのように動作します。 

重要な観察は、各サブシーケンスが事実上、増加する隣接ペアの作成を避けたい構造であるということです。 したがって、各サブシーケンスは、「可能な限り減少する」シーケンスのように動作する必要があります。 

これは、古典的な貪欲なアイデアにつながります。つまり、2 つのサブシーケンスの最後の値を維持し、新しいペナルティの増加が最も少ないサブシーケンスに現在の要素を常に割り当てます。 

各ステップで問題となるのは 2 つの状態のみであるため、問題は継続的な遷移を伴う小さな DP のような貪欲な状態に崩壊します。

 ## アルゴリズムのチュートリアル

 サブシーケンスの最後の要素を表す 2 つの変数を維持します。$s$そしてその後$t$。 累積されたペナルティも追跡します。 

要素を左から右に処理し、各値を配置する場所を決定します。 

### ステップ

 1. 両方のサブシーケンスを空として初期化します。つまり、最後の要素は次のように設定されます。$+\infty$(したがって、最初の要素がペナルティを作成することはありません)。 

これにより、最初の割り当ては常に無料になります。 
2. 各要素について$x$に追加するコストを計算します。$s$そしてへ$t$。 

そのサブシーケンスの最後の要素が厳密に次の要素よりも小さい場合、コストは 1 です。$x$、それ以外の場合は 0。 
3. 追加コストがより小さいサブシーケンスを選択します。 両方が等しい場合は、任意に選択します。 
4. 選択したサブシーケンスの最後の要素を次のように更新します。$x$そして答えにコストを加えます。 

### なぜ効果があるのか

 ペナルティが作成される唯一の方法は、同じサブシーケンス内の小さい前の要素の後に要素を配置する場合に、ローカルに作成される方法です。 将来の決定によって、この増加がすでに発生したかどうかが遡及的に変更されることはありません。 これにより、2 つのサブシーケンスの最後の値を除いて、各ステップのコストが独立します。 したがって、増加を遅らせたり将来にシフトしたりしても増加する隣接関係の総数は減らないため、当面のペナルティを最小限に抑える貪欲な選択が全体的に最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    INF = 10**18

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        last_s = INF
        last_t = INF
        ans = 0

        for x in a:
            cost_s = 1 if last_s < x else 0
            cost_t = 1 if last_t < x else 0

            if cost_s <= cost_t:
                ans += cost_s
                last_s = x
            else:
                ans += cost_t
                last_t = x

        print(ans)

if __name__ == "__main__":
    solve()
```実装では、貪欲な割り当てを直接シミュレートします。 唯一の微妙な詳細は、最初の要素がペナルティを生成しないように、最後の値を非常に大きな数値に初期化することです。 決定ルールは一貫している必要があります。つまり、最初のサブシーケンスに向けてタイは安全に破られますが、対称状態を交換する以上に将来のコスト構造に影響を与えないため、タイブレークは機能します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        last_s = 10**18
        last_t = 10**18
        ans = 0

            cs = 1 if last_s < x else 0
            ct = 1 if last_t < x else 0
            if cs <= ct:
                ans += cs
                last_s = x
            else:
                ans += ct
                last_t = x

        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、値が上下に切り替わる場合です。 このような場合、貪欲な割り当てにより、各立ち上がりが最大 1 つのサブシーケンスに「吸収」され、ペナルティの重複が防止されます。 もう 1 つは、等しい値が多数出現する場合で、どちらの部分列もコストがかからず、等しいことがペナルティの形成に影響を与えないことが確認されます。
