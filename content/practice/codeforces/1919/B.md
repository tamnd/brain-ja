 ## 解決策
 ## 問題の理解

 文字列は次のもののみで構成されます`'+'`そして`'-'`。 各文字を数値として解釈できます。`'+'`になる`+1`、 そして`'-'`になる`-1`。 

このシーケンスを任意の数の連続した空でない部分に分割することができます。 各部分について、以下を計算します。$$\text{penalty} = |\text{sum of piece}| \times \text{length of piece}$$合計ペナルティは、すべての駒のペナルティの合計です。 私たちの目標は、この合計を最小にする分割を選択することです。 

文字列の長さは最大 5000 で、最大 1000 のテスト ケースを含めることができます。 この声明は、すべての合計に制限がないことを明確に述べています。$n$したがって、各テストケースを線形時間で処理するソリューションを探す必要があります。 テスト ケースごとに 2 次式のものはすべてリスクになります。 

厄介な点は、ペナルティがセグメントの合計と長さの両方に依存することです。 多くの分割問題では動的プログラミングが必要となるため、考えられる分割を多数試行する必要があるかどうか疑問に思うのは自然なことです。 重要な観察は、値の構造が非常に制限されているということです。すべての要素は次のいずれかです。$+1$または$-1$。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
+
```配列には値が 1 つだけ含まれます。$+1$。 分割は出来ません。 答えは$1$、 ない$0$。 

考慮する：```
+-
```セグメント全体に合計がある$0$、したがって、そのペナルティは$0$。 答えは$0$。 個々の文字のみをカウントするソリューションでは、誤った値が返されます。$2$。 

考慮する：```
+++
```あらゆる要素は$+1$。 ゼロサムセグメントは存在しません。 単一要素に分割するとペナルティが発生する$1+1+1=3$、これはすでに最適です。 答えは$3$。 

これらの例は、本当に重要なのは、どれだけのプラスとマイナスが互いに打ち消し合うことができるかであることを示唆しています。 

## アプローチ

 ブルートフォースソリューションでは、配列を分割するためにあらゆる方法が試行されます。 

長さに関しては-$n$配列、あります$2^{n-1}$可能なパーティションの位置。 たとえ$n=50$、これはまったく不可能です。 もっとシンプルなものが必要です。 

ショートカットを見つけるには、単一のセグメントを確認します。 

その合計は整数です。 すべての要素はいずれかであるため、$+1$または$-1$、合計は次のようになります。$$(\text{number of pluses})-(\text{number of minuses})$$セグメントに合計があるとします。$0$。 すると、そのペナルティは、$$|0| \times \text{length}=0$$そのようなセグメントは何も貢献しません。 

ここで、セグメントに合計があるとします。$k\neq 0$。 すべての要素がどちらかに寄与するため、$+1$または$-1$、セグメントには少なくとも次の内容が含まれます$|k|$比類のない兆候。 ペナルティは$$|k| \times \text{length}$$そして長さは少なくとも$1$、 それで$$|k| \times \text{length}\ge |k|$$これは、すべてのセグメントが少なくともその合計の絶対値に寄与することを意味します。 

セグメントの合計を次のようにします。$s_1,s_2,\dots,s_m$。 それらの合計は配列全体の合計と等しくなります。$$s_1+s_2+\cdots+s_m=S$$ペナルティの合計は少なくとも$$|s_1|+|s_2|+\cdots+|s_m|$$三角不等式により、$$|s_1|+|s_2|+\cdots+|s_m|\ge |S|$$したがって、考えられるすべてのパーティションには少なくともペナルティがあります$|S|$。 

ここで、この下限が実際に達成できるかどうかを尋ねます。 

はい。 配列を単一の要素に分割します。 すべてのセグメントには長さがあります$1$したがって、そのペナルティはまさに$1$。 それぞれ`'+'`貢献する$1$、 それぞれ`'-'`貢献する$1$。 

プラスとマイナスが 1 つずつあれば、それらをより大きなゼロサム セグメントにマージできます。 そのセグメントが寄与する$0$の代わりに$2$。 一致するすべてのプラスとマイナスのペアが正確に削除されます$2$合計から。 

文字列に次の内容が含まれている場合$P$プラスと$M$マイナス、それでは$\min(P,M)$ペアはキャンセル可能です。 一致しないシンボルの数は$$|P-M|$$そしてまさにその通りです$|S|$。 

したがって、最小限のペナルティは単純に次のようになります。$$|P-M|$$実際のパーティションを構築する必要はありません。

 ## アルゴリズムのチュートリアル

 1. 何個数えるか`'+'`文字列内に文字が出現します。 これをそのままにしておきます`plus`。 
2. 何個数えるか`'-'`文字列内に文字が出現します。 これをそのままにしておきます`minus`。 
3. 以下を計算します。$$|plus-minus|$$これは、配列全体の合計の絶対値に等しくなります。 

1. 結果を出力します。 

これが機能する理由は、一致するすべてのプラスとマイナスのペアがゼロサム セグメント内に配置され、何も寄与しないためです。 多数決記号の余分な記号だけが避けられず、その数は正確に計算されます。$|plus-minus|$。 

### なぜ効果があるのか

 選択したセグメントの合計を次のようにします。$s_1,s_2,\dots,s_k$。 

すべてのセグメントのペナルティが満たされる$$|s_i|\cdot \text{len}_i \ge |s_i|$$すべての長さは少なくとも$1$。 

したがって、合計ペナルティは満たされます$$\sum |s_i|\cdot \text{len}_i \ge \sum |s_i| \ge \left|\sum s_i\right|$$最終的な量は、配列全体の合計の絶対値です。$|P-M|$。 

これは、パーティションが以下のペナルティを達成できないことを証明しています。$|P-M|$。 

一方、すべての一致するプラスとマイナスのペアはゼロサム セグメントにグループ化でき、正確に残ります。$|P-M|$一致しないシンボル。 一致しないシンボルごとにペナルティが発生します$1$したがって、合計ペナルティを伴うパーティション$|P-M|$存在します。 

下限と一致する構造の両方があるため、$|P-M|$考えられる最小限のペナルティです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    s = input().strip()

    plus = s.count('+')
    minus = n - plus

    print(abs(plus - minus))
```実装は数学的結果に直接従います。 

まず、数を数えます`'+'`文字。 他のすべての文字は次のようにする必要があるため、`'-'`、マイナスの数は単純に`n - plus`。 

答えは、これらのカウント間の絶対的な差です。 この証明では、すべての最適なパーティションが同じ最小値、つまり配列全体の絶対和を持つことが示されているため、パーティション化ロジックは必要ありません。 

オーバーフローの心配がないため、$n \le 5000$したがって、すべての値は Python の整数制限に比べて小さいです。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        s = input().strip()

        plus = s.count('+')
        minus = n - plus

        ans.append(str(abs(plus - minus)))

    return "\n".join(ans)
