 ## 解決策
 ## 問題の理解

 すべてのバルブ容量が固定されているため、$10^{18}$、バルブがボトルネックになることはありません。 塔内に残った水$i$ウィザードの行為後は、いつでも完全にタワーに移動できます$i+1$。 

これにより、プロセスの性質が劇的に変わります。 考える代わりに$n$別々の塔がある場合、水は 1 本のパイプラインを左から右に移動すると考えることができます。 

させて$a_i$最初にその位置に加えられた水になります$i$、そしてさせてください$b_i$そこで生産できるワインの最大量になります。 

プロセスがタワーに到達すると$i$、次の 2 つのことが起こります。 

まず、一定量の水がワインに変換されます。$b_i$。 

第二に、残った水はすべて右側に流れ続けます。 

更新のたびに、生産されるワインの総量を再計算する必要があります。 

制約こそが本当の課題なのです。 両方$n$そして$q$と同じくらい大きい$5 \cdot 10^5$。 アップデートのたびにプロセス全体をシミュレーションするには、$O(nq)$仕事、つまり大まかに言うと$2.5 \cdot 10^{11}$最悪の場合の運用。 それはまったく不可能です。 

更新では 1 つの位置のみが変更されます。これは、ポイントの更新と答えの高速な再計算をサポートするデータ構造が必要であることを強く示唆しています。 

タワーが受け取る水の量が、ウィザードが処理できる量よりも少ない場合、微妙なエッジケースが発生します。 

考慮する：```
a = [2]
b = [10]
```ウィザードは最大 10 リットルを処理できますが、存在するのは 2 リットルのみです。 ワインの正しい量は 10 ではなく 2 です。 

もう 1 つの重要なケースは、後の塔に到達する前に水が使い果たされる場合です。```
a = [3, 0]
b = [5, 5]
```タワー 1 は 3 リットルすべてをワインに変換します。 タワー 2 には何も到達しないため、答えは 8 ではなく 3 になります。 

3 番目のケースは、初期の赤字が後の黒字によって補われる場合です。```
a = [0, 10]
b = [5, 0]
```水がまだ存在しないため、タワー 1 は何も生成しません。 次に、タワー 2 は 10 リットルをすべて受け取り、ウィザードパワーが 0 であるため、ワインは 0 生産されます。答えは 0 です。タワーを個別に扱うアプローチでは、タワー 1 で 5 リットルが誤ってカウントされてしまいます。 

## アプローチ

 ブルート フォース ソリューションは、プロセスを直接シミュレートします。 

現在利用できる水の量を維持してください。 タワーにて$i$、 追加$a_i$、 変換する$\min(\text{water}, b_i)$ワインにリットルを注ぎ、その量を水から差し引いて、次の塔に移動します。 

このシミュレーションはプロセスのルールに正確に従っているため、正確です。 その費用は$O(n)$クエリごとに。 と$5 \cdot 10^5$更新すると、最悪のケースが発生します$O(nq)$、これは大きすぎます。 

何かをより速く取得するには、プロセスを数学的に記述する必要があります。 

させて$D_i$塔の後に残っている水の量である$i$。 

最初に:$$D_0 = 0$$タワーにて$i$、最初に追加します$a_i$リットルまで除去し、$b_i$リットル。 

再発となるのは、$$D_i = \max(0, D_{i-1} + a_i - b_i).$$定義する$$d_i = a_i - b_i.$$それから$$D_i = \max(0, D_{i-1} + d_i).$$これは古典的な反射プレフィックスサムの反復です。 

させて$$S_i = \sum_{j=1}^{i} d_j.$$標準的なアイデンティティによって得られるものは、$$D_n = S_n - \min_{0 \le k \le n} S_k.$$最初に存在する水の総量は、$$A = \sum a_i.$$まさに最後の塔の後$D_n$リットルは未処理のままです。 1リットルごとにワインになるので、$$W = A - D_n.$$式を代入すると、$D_n$、$$W = A - \Bigl(S_n - \min_{0 \le k \le n} S_k\Bigr).$$ここで問題は次のようになります。 

配列を維持する$d_i=a_i-b_i$ポイント更新では、以下をサポートします。$$S_n=\sum d_i$$そして$$\min_{0\le k\le n} S_k.$$これはまさに、セグメントの合計と最小のプレフィックスの合計を格納するセグメント ツリーが実行できることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n)$アップデートごと |$O(1)$| 遅すぎる |
 | 最適 |$O(\log n)$アップデートごと |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 差分配列を構築する

 定義する$$d_i = a_i - b_i.$$メンテナンスも行います$$A = \sum a_i.$$最終的な答えは次の要素のみに依存します$A$、の合計$d$、および最小プレフィックス合計$d$。 

### 2. セグメントツリーを構築する

 すべてのセグメントに 2 つの値を保存します。 

最初の値はセグメントの合計です。 

2 番目の値は、そのセグメント内の最小プレフィックス合計です。 

値を含むリーフの場合$x$、$$\text{sum}=x,\qquad \text{minPref}=x.$$### 3. 2 つの子を結合します。 

左側の子ストアが$$(\text{sum}_L,\text{minPref}_L)$$そして適切な子ストア$$(\text{sum}_R,\text{minPref}_R).$$それから$$\text{sum} = \text{sum}_L+\text{sum}_R.$$結合されたセグメントのプレフィックスは、完全に左側の子の内部に留まるか、左側の子全体を消費して右側の子に続きます。 したがって、$$\text{minPref} = \min\bigl( \text{minPref}_L, \text{sum}_L+\text{minPref}_R \bigr).$$### 4. アップデートを処理する

 位置決め時$p$変更:

 アップデート$A$追加することで$x-a_p$。 

交換する$$a_p \leftarrow x, \qquad b_p \leftarrow y.$$再計算する$$d_p = a_p-b_p$$そして、対応するセグメントツリーのリーフを更新します。 

### 5. 答えを取り戻す

 ルートには次のものを含めます。$$\text{totalSum}=S_n$$そして$$\text{minPref}.$$空のプレフィックスを含む最小のプレフィックスは次のとおりです。$$m = \min(0,\text{minPref}).$$それから$$D_n = S_n - m.$$ついに、$$W = A - D_n.$$出力$W$。 

### なぜ効果があるのか

 再発$$D_i=\max(0,D_{i-1}+d_i)$$塔の後に残っている水の量を追跡します$i$。 

古典的な表現$$D_i=S_i-\min_{0\le k\le i}S_k$$は、プロセス全体が最終的なプレフィックスの合計と途中で発生した最小プレフィックスのみに依存することを示しています。 

セグメント ツリーは、ポイント更新時にこれらの数量を正確に維持します。 最初の水は 1 リットルごとにワインになるか、ワインの中に残ります。$D_n$、ワインの量は常に$$A-D_n.$$したがって、報告されたすべての回答は、元のシミュレーションの結果と同じになります。

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.sum = [0] * (4 * self.n)
        self.mn = [0] * (4 * self.n)
        self._build(1, 0, self.n - 1, arr)

    def _build(self, idx, l, r, arr):
        if l == r:
            self.sum[idx] = arr[l]
            self.mn[idx] = arr[l]
            return

        mid = (l + r) // 2
        self._build(idx * 2, l, mid, arr)
        self._build(idx * 2 + 1, mid + 1, r, arr)
        self._pull(idx)

    def _pull(self, idx):
        left = idx * 2
        right = left + 1

        self.sum[idx] = self.sum[left] + self.sum[right]
        self.mn[idx] = min(
            self.mn[left],
            self.sum[left] + self.mn[right]
        )

    def update(self, pos, val):
        self._update(1, 0, self.n - 1, pos, val)

    def _update(self, idx, l, r, pos, val):
        if l == r:
            self.sum[idx] = val
            self.mn[idx] = val
            return

        mid = (l + r) // 2

        if pos <= mid:
            self._update(idx * 2, l, mid, pos, val)
        else:
            self._update(idx * 2 + 1, mid + 1, r, pos, val)

        self._pull(idx)

    def total_sum(self):
        return self.sum[1]

    def min_prefix(self):
        return self.mn[1]

def main():
    n, q = map(int, input().split())

    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    _ = input()  # c is irrelevant in easy version

    d = [a[i] - b[i] for i in range(n)]
    total_a = sum(a)

    seg = SegTree(d)

    ans = []

    for _ in range(q):
        p, x, y, z = map(int, input().split())
        p -= 1

        total_a += x - a[p]

        a[p] = x
        b[p] = y

        new_d = x - y
        seg.update(p, new_d)

        total_sum = seg.total_sum()
        mn_pref = min(0, seg.min_prefix())

        remaining = total_sum - mn_pref
        wine = total_a - remaining

        ans.append(str(wine))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    main()
```この実装は数学的導出を直接反映しています。 

配列`d`店舗$a_i-b_i$。 すべての更新は 1 つの位置にのみ影響するため、セグメント ツリー上のポイント更新で十分です。 

根の`sum`フィールドは$S_n$。 根の`mn`フィールドは、空でないプレフィックスの合計の最小値です。 Since the formula also allows the empty prefix, we take`min(0, seg.min_prefix())`。 

値```
remaining = total_sum - mn_pref
```まさに$D_n$、最後の塔の後に残った水。 

そのときの答えは、```
wine = total_a - remaining
```それは水を節約することから生まれます。 

すべての算術演算では Python 整数が使用されるため、$10^{18}$値がオーバーフローのリスクを引き起こすことはありません。
