 ## 解決策
 ## 問題の理解

 問題は一連のレベルとして見ることができ、各レベルはいくつかの要素に寄与し、その影響がどこに適用されるかを説明する間隔も伴います。 各レベル i は AI 単位の「利益」を提供しますが、これをアクティブにすると、範囲 [Li, Ri] に応じたペナルティを支払う必要があります。 重複する間隔は相互作用し、重複するペナルティは二重にカウントされるべきではないため、レベルのセットを選択する合計値は、それらの ai 値の合計だけではありません。 

本当の目的は、合計ゲインから合計ペナルティを差し引いた値を最大化するようにレベルのサブセットを選択することであり、ペナルティは整数位置に対するカバレッジのように動作します。 選択した複数のレベルが同じ領域をカバーする場合、複数のレベルがその領域のカバーに貢献する可能性がある場合でも、その領域は 1 回だけペナルティを受けます。 

計算上の観点から見ると、制約は O(n²) よりも優れた解を意味します。 レベルのペアに対する単純な動的プログラミングは、n が約 200000 に達するとすぐに失敗します。これは、遷移では以前のすべての選択肢をスキャンする必要があるためです。 

微妙なエッジケースは、重複する間隔から生じます。 間隔が重なり合っているか入れ子になっている場合、レベル間の独立性を前提とした単純なアプローチでは、ペナルティが 2 倍にカウントされたり、有益な組み合わせが誤って破棄されたりする可能性があります。 たとえば、すべての Li と Ri が同一である場合、どのソリューションでも、選択されたレベルの数に関係なく、それらを単一のカバーされたセグメントを共有するものとして正しく扱う必要があります。 

隣接しないレベルを選択すると、別の特殊なケースが発生します。 レベルがインデックス付けされている場合でも、最適な選択では、オーバーラップの伝播方法により中間レベルの包含が強制される可能性があります。つまり、インデックスをスキップすると、決定間の単純な独立性の仮定が無効になる可能性があります。 

## アプローチ

 直接的な総当たりアプローチでは、レベルのすべてのサブセットが試行されます。 各サブセットについて、合計 ai を計算し、すべての区間の和集合を計算してペナルティを評価します。 これは「結合を 1 回カウントする」ルールを明示的に尊重しているため、これは正しいです。 ただし、サブセットは 2ⁿ あり、サブセットごとの区間和集合の計算でも O(n) がかかり、O(n · 2ⁿ) となり、実行不可能です。 

インターバルの構造を活用する必要があります。 重要な観察は、間隔が単調であることです。Li と Ri は両方とも i に対して減少しません。 これは、レベルを進めていくと、そのカバレッジが構造化された方法で動作することを意味します。 選択した 2 つの間隔が重なると、相互作用が簡素化されます。つまり、それらの間のすべてのものは、あたかもそれが含まれなければならないかのように動作するか、または連続的なマージ効果に等価的に寄与することになります。 

この構造により、重複する間隔のチェーンを継続するか、新しい独立したセグメントを開始するかにのみ依存する動的プログラミング状態を維持することができます。 完全なサブセットを記憶する代わりに、i までの最良の値と、以前の決定点の最良の値のみを追跡します。 

移行は 2 つのケースに分かれます。 現在のレベルは前の重複しないセグメントに接続するか、i-1 から重複するチェーンを延長します。 これら 2 つの動作は、カスタムの max-plus 遷移の下で線形に進化する小さな状態ベクトルにエンコードできます。 このように表現すると、プロセス全体は 2 次元状態に対する一連のマトリックス状の変換になります。 

各レベルは固定変換に寄与するため、それらをセグメント ツリーに保存し、効率的に組み合わせることができます。 これにより、問題は点更新時の行列の積の維持に変わり、更新ごとに対数係数が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n · 2ⁿ) | O(n) | 遅すぎる |
 | 状態 DP + セグメント ツリー | O((n + m) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

すべてのインデックス i で 2 つの量を維持するように DP を再解釈します。1 つは i 以降で終了する構成の最良の値、もう 1 つは i で終了するかどうかに関係なく、以前のすべての状態にわたる最良の値です。 

レベル i では、2 つの寄与を計算します。 1 つ目は、i で新しいセグメントを開始する値です。 これは、ai から全区間 [Li, Ri] のペナルティを引いたものに等しくなります。i を開始点として扱う場合、以前の選択に比べてカバーされていない部分の全額を支払うことになるからです。 2 番目は、前のセグメントを i-1 から i に拡張する値で、右側の境界が Ri-1 から Ri に増加するだけなので、増加するカバーされていない部分のみがペナルティに寄与します。 

これらを 2 つのコンポーネントの状態の遷移としてエンコードします。 

1. 最初の成分がちょうど i-1 で終わる最良の DP 値であり、2 番目の成分がすべての j < i にわたる最良の DP 値である状態ベクトルを定義します。 
2. レベル i について、そのスタンドアロン寄与を計算します。これは、ai から区間全体の長さの k 倍 (Ri − Li + 1) を引いたものです。 これは、i で新しいセグメントを開始することに対応します。 
3. 拡張寄与を計算します。これは、ai から新しく追加された右部分 (Ri − Ri−1) のみを k 倍したものです。 これは、重なっているチェーンを延長することに相当します。 
4. i で終わる DP を、前の j から新たに開始して i-1 から拡張するまでの最大値として更新します。 
5. 良好な状態が一度形成されると、それは利用可能なままになるため、可能なすべての遷移にわたって最大値を取ることによって、同様にグローバル ベストを更新します。 
6. この更新を 2×2 マックスプラス行列として表します。レベルの結合は行列の乗算に対応します。 
7. これらの行列に対してセグメント ツリーを構築すると、ai、Li、Ri への更新が O(log n) に反映され、配列の全積が最終的な DP 状態になります。 

### なぜ効果があるのか

 重要な不変条件は、最適な選択は、間隔が互いに素であるか、完全に接続されたオーバーラップのチェーンを形成するセグメントに分解できることです。 チェーン内では、増分右拡張のみが重要であるため、寄与は前の右境界のみに応じて線形形式に崩壊します。 DP リセットはチェーン全体で、新しい独立したセグメントを開始するコストを取得します。 max-plus マトリックス構造は、これら 2 つのモードを正確に保持するため、レベルのすべての構成は、最適な構成を失うことなく、継続または再開のいずれかを正しく集約します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

class Node:
    __slots__ = ("a",)
    def __init__(self):
        self.a = [[-INF, -INF],
                  [-INF, -INF]]

def merge(A, B):
    C = Node()
    for i in range(2):
        for j in range(2):
            best = -INF
            for k in range(2):
                best = max(best, A.a[i][k] + B.a[k][j])
            C.a[i][j] = best
    return C

def make(a_i, L_i, R_i, k, prev_R):
    length = R_i - L_i + 1
    open_val = a_i - k * length
    add_val = a_i - k * (R_i - prev_R)

    if prev_R is None:
        add_val = open_val

    M = Node()
    M.a[0][0] = open_val
    M.a[0][1] = open_val
    M.a[1][0] = add_val
    M.a[1][1] = add_val
    return M

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.seg = [Node() for _ in range(2 * self.size)]

        for i in range(self.n):
            self.seg[self.size + i] = arr[i]
        for i in range(self.size - 1, 0, -1):
            self.seg[i] = merge(self.seg[2*i], self.seg[2*i+1])

    def update(self, i, val):
        i += self.size
        self.seg[i] = val
        i //= 2
        while i:
            self.seg[i] = merge(self.seg[2*i], self.seg[2*i+1])
            i //= 2

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    L = list(map(int, input().split()))
    R = list(map(int, input().split()))

    arr = []
    for i in range(n):
        prev_R = R[i-1] if i > 0 else None
        arr.append(make(a[i], L[i], R[i], k, prev_R))

    st = SegTree(arr)

    for _ in range(m):
        idx, val = map(int, input().split())
        idx -= 1
        a[idx] = val
        prev_R = R[idx-1] if idx > 0 else None
        st.update(idx, make(a[idx], L[idx], R[idx], k, prev_R))

    root = st.seg[1]
    ans = max(root.a[0][0], root.a[0][1], root.a[1][0], root.a[1][1])
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、レベルごとに最大プラス遷移行列が構築されます。 各行列は、新しいセグメントを開始するのか、既存のセグメントを拡張するのかをエンコードします。 セグメント ツリーはその構成を維持するため、更新後に、結果として得られる状態マトリックスの最大エントリを取得することで、グローバル ベストをクエリできます。 

微妙な点は、拡張項が Ri−1 にどのように依存するかです。 これが、値が変化したときに各レベルの行列を再計算する必要がある理由であり、遷移が ai で純粋にローカルではなく、Ri 構造の隣接性に依存する理由です。 

行列の合成は結合的ですが可換的ではないため、セグメント ツリーの乗算順序は重要です。 このコードは、レベルの順序を維持しながら、一貫して左の子、次に右の子をマージします。

 ## 特殊なケース

 重要なエッジケースは、すべての間隔が同一である場合です。 この状況では、すべてのレベルが同じ [L, R] を共有するため、レベルを追加しても AI からのメリットが増加するだけであり、ペナルティはマージされたセグメントごとに 1 回カウントされます。 アルゴリズムはこれを処理します。これは、拡張トランジションが常に繰り返しカバレッジを 1 つのコントリビューションに折りたたんで、二重カウントを防ぐためです。 

間隔が厳密に互いに素である場合、別の特殊なケースが発生します。 ここでは、拡張遷移が優勢になることはないため、DP は繰り返し再起動されます。 各マトリックスが「新規開始」と「拡張」の両方をエンコードし、最大プラス合成により再開ブランチが自然に選択されるため、セグメント ツリーはこれを正確に捕捉します。 

3 番目のエッジ ケースは、単一要素入力です。 レベルが 1 つだけの場合、以前の状態は存在しないため、延長期間は完全なインターバル ペナルティに縮退する必要があります。 この構築では、i = 0 の場合に add_i を open_i に置き換えることでこれを明示的に処理し、初期化の正確さを保証します。
