 ## 解決策
 ## 問題の理解

 スクルージはポリラインに沿ってペンを動かして書類に署名します。 署名は最初の点から始まり、最後の点に到達するまで連続する点の間に直線セグメントを描画します。 彼のペンの速度は毎秒 50 ミリメートルに固定されており、まったく同じ署名を繰り返します。`k`回。 

このタスクは、すべての書類の署名に費やした合計時間を計算することです。 

入力により、ポリラインの点が順番に与えられます。 連続する点の各ペアは、署名の 1 つのセグメントを形成します。 ペンが移動する合計距離は、これらすべてのセグメントのユークリッド長の合計です。 1 つの署名の合計距離がわかったら、それに次の値を掛けます。`k`そして書き込み速度で割ります。 

制約はわずかです。 ポイントは最大 100 個なので、セグメントは最大 99 個になります。 高価な計算でも簡単に制限内に収まります。 セグメント上の単純な線形スキャンで十分です。 ジオメトリの問題では、慎重な最適化や精密なトリックが必要になる場合がありますが、ここでは数が少なく、式は直接的です。 

実装上の主なリスクは、正確な取り扱いです。 点間の距離は平方根のため、通常は非整数になります。 整数演算を使用すると、黙って値が切り捨てられ、間違った答えが生成されます。 

次の入力を考えてみましょう。```
2 1
0 0
1 1
```セグメントの長さは`sqrt(2) ≈ 1.41421356`。 正しい時刻は次のとおりです。```
1.41421356 / 50 ≈ 0.028284271
```ソリューションで誤って整数除算を使用したり、除算する前に距離を整数に変換したりすると、次のように出力されます。`0`、これは間違いです。 

もう 1 つの簡単な間違いは、乗算を忘れることです。`k`。 

例えば：```
2 5
0 0
10 0
```1 つの署名には長さがあります`10`、つまり 1 つの署名が必要です`10 / 50 = 0.2`秒。 論文が 5 つあるので、正解は次のとおりです。```
1.0
```署名を 1 つだけ計算する不注意な実装では、次のような出力が出力されます。`0.2`。 

3 番目の微妙なケースは、負の座標です。 距離は絶対位置ではなく、座標の差に依存します。 

例：```
2 1
-3 -4
0 0
```距離はまだある`5`、 なぜなら：```
sqrt((0 - (-3))^2 + (0 - (-4))^2) = sqrt(9 + 16) = 5
```差分ではなく絶対座標値を直接使用すると、このようなケースは解決されません。 

## アプローチ

 ここでは、強引なアイデアがすでに十分に高速です。 すべてのセグメントを個別に処理し、距離公式を使用してそのユークリッド長を計算し、すべての長さを合計することができます。 

2連続ポイントの場合`(x1, y1)`そして`(x2, y2)`、セグメントの長さは次のとおりです。$d=\sqrt{(x_2-x_1)^2+(y_2-y_1)^2}$点をドラッグして 2 点間の距離を更新します。-10-8-6-4-2246810-10-5510A(6.0, 6.0)B(-6.0, -6.0)d = 16.97Delta x = 12Delta y = 12

 すべてのセグメントの長さを合計した後、次の値を掛けます。`k`同じ署名が繰り返されるため`k`回。 最後に書き込み速度で割ります`50`。 

署名パスが連続セグメントとして明示的に指定されているため、ブルート フォース手法が機能します。 再構築するための隠れた構造はなく、繰り返される計算を最適化する必要もありません。 すべてのセグメントは独立して合計距離に寄与します。 

幾何学の問題は、人々を交差点やパスの重複について考えすぎてしまうことがあります。 ここではそんなことは関係ありません。 ポリラインがそれ自体を横切ったり、以前のセグメントを引き戻したりした場合でも、スクルージはパス全体に沿って物理的にペンを移動するため、すべてのセグメントは描画されたものとして正確にカウントされる必要があります。 

制約が非常に小さいため、単一の線形パスがすでに最適であるため、最適なアプローチは総当たりアプローチと同じです。 ポリラインを 1 回トラバースするだけです。

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`k`。 
2. すべて読む`n`ポリラインの点を順番に並べます。 
3. Initialize a variable`total_distance = 0.0`。 
4. 連続する点のペアを繰り返します。 

あらゆる人にとって`i`から`0`に`n - 2`、ポイントを取得します。```
(x[i], y[i]) and (x[i+1], y[i+1])
```5. 2 点間のユークリッド距離を計算します。 

距離の式は、それらを接続する直線セグメントの正確な長さを測定します。 
6. このセグメントの長さを`total_distance`。 

すべてのペアを処理した後、`total_distance`1 つの署名に対するペンの完全な移動に相当します。 
7. 乗算`total_distance`による`k`。 

署名は毎回同一であるため、総移動距離は用紙の数に比例して増加します。 
8. 結果を次で割ります。`50`。 

ペンの速度は 50 ミリメートル/秒なので、次のようになります。```
time = distance / speed
```9. 答えを浮動小数点数として出力します。 

### なぜ効果があるのか

 すべての署名は、連続する点間のセグメントから正確に構成されます。 アルゴリズムはこれらの各セグメントを 1 回処理し、ユークリッド距離の公式を使用してその正確な幾何学的な長さを計算します。 

ループ中の不変条件は、最初の処理後の不変条件です。`i`セグメント、`total_distance`は、それらのセグメントに沿ったペンの合計移動量に等しくなります。 各セグメントは独立して寄与し、セグメントがスキップされたり二重にカウントされたりすることはないため、最終的な合計は 1 つの完全な署名の長さとまったく同じになります。 

乗算`k`すべての署名の合計距離が得られ、一定速度で割ると距離が時間に変換されます。 計算は問題で説明されている物理プロセスと直接一致するため、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

# solution

def solve():
    n, k = map(int, input().split())

    points = [tuple(map(int, input().split())) for _ in range(n)]

    total_distance = 0.0

    for i in range(n - 1):
        x1, y1 = points[i]
        x2, y2 = points[i + 1]

        dx = x2 - x1
        dy = y2 - y1

        total_distance += math.hypot(dx, dy)

    total_time = (total_distance * k) / 50.0

    print(f"{total_time:.9f}")

solve()
```ソリューションはアルゴリズムに直接に従います。 まず、すべてのポイントをリストに読み込み、連続するポイントに簡単にアクセスできるようにします。 

ループ内では、`dx`そして`dy`隣接する点間の座標の差を保存します。 機能`math.hypot(dx, dy)`計算します:```
sqrt(dx^2 + dy^2)
```これは、平方根の式を手動で記述するよりも安全かつクリーンです。 

アキュムレータ`total_distance`セグメントの長さは通常整数ではないため、 は浮動小数点値です。 

の乗算`k`署名全体の長さが計算された後に発生します。 これにより、同じ計算を不必要に繰り返すことがなくなります。 

最終的な印刷では小数点以下 9 桁が使用され、必要な精度を十分に満たしています。

```乗算は完全なパス長が計算された後に行われるため、すべての署名が正しくカウントされます。
