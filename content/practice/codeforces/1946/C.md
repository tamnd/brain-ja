 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$頂点。サイクルのない接続されたグラフです。 タスクは正確に削除することです$k$このツリーからエッジを抽出し、最大の整数を決定します$x$結果として得られる各接続コンポーネントには、少なくとも$x$頂点。 簡単に言うと、ツリーを次のように分割しています。$k+1$最小のコンポーネントを最大化しながら、ほぼバランスの取れたサイズのコンポーネントを配置します。 

入力は複数のテスト ケースで構成されます。 各テストケースについて、次のように読みます。$n$そして$k$、 に続く$n-1$ツリーを説明するエッジ。 各テスト ケースの出力は、実行可能な最大の単一の整数です。$x$。 

制約により許可されるのは、$n$まで$10^5$テストケースごとの合計と$n$すべてのテスト ケースの境界は次のとおりです$10^5$。 これにより、おおよそ次のようなアルゴリズムに制限されます。$O(n \log n)$またはそれより速く、$O(n^2)$アプローチは結果として$10^{10}$最悪の場合、動作が遅すぎます。 各テスト ケースは独立しているため、1 つずつ処理できます。 

微妙なエッジケースが発生する場合$k$～に比べて非常に小さい、または非常に大きい$n$。 たとえば、次の場合$k = 1$そして$n = 3$木と一緒に$1-2-3$1 つのエッジを削除できますが、結果として得られる 2 つのコンポーネントのサイズは次のとおりです。$1$そして$2$。 最大$x$それなら$1$平均的なサイズであっても、$1.5$。 平均を計算するか、均等な分布を仮定する単純なアプローチでは、次の結果が返されます。$2$、これは間違いです。 

もう 1 つのエッジケースは、星型のツリーです。 中心がすべての葉につながっていれば、$k = n-1$、エッジを削除すると、単一のノードが分離される可能性があります。 アルゴリズムでは、コンポーネントの最小サイズが理想的な分割ではなく最小の分岐によって制限されるという事実を考慮する必要があります。 

## アプローチ

 ブルートフォース手法では、すべてのセットを列挙します。$k$削除するエッジを特定し、結果として得られるすべてのコンポーネントのサイズを計算し、各構成の最小サイズを追跡します。 これは正しいですが、各ツリーには$\binom{n-1}{k}$エッジを削除する方法は不可能ですが、$n$まで$10^5$。 

重要な洞察は、候補のサイズを考慮することです$x$そして、ツリーを少なくとも次のサイズのコンポーネントに分割できるかどうかを判断します。$x$取り除くことで$k$エッジ。 これを特定の条件で効率的にチェックできれば、$x$、二分検索を実行できます$x$範囲内で$1 \dots n$。 それぞれの決断$x$で実現可能です$O(n)$深さ優先検索 (DFS) アプローチを使用します。 各ノードについて、そのサブツリーのサイズを計算し、完全なコンポーネントを形成できるかどうかを判断します。 サブツリーが十分に大きい場合は、それをカウントします。$k$エッジの除去。 それ以外の場合は、そのサイズを上向きに伝播します。 この貪欲な DFS は、形成するコンポーネントが少なくとも次のサイズを持つことを保証します。$x$。 

エッジの組み合わせの数は組み合わせ的に増加するため、総当り的なアプローチは実行できません。 DFS による二分探索は、ツリー構造によりボトムアップ方式でサイズを集約し、どのエッジをカットするかをローカルに決定できるため、最適です。 候補者をチェックする$x$で$O(n)$合計の複雑さは次のようになります$O(n \log n)$、制限時間内に快適に収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O( (n は k を選択) * n ) | O(n) | 遅すぎる |
 | 二分探索 + DFS | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 次のコマンドを使用して二分探索を初期化します。$l = 1$そして$r = n$。 答えはこの範囲にあります。 の候補値をテストすることで絞り込みます。$x$。 
2. ヘルパー関数を定義する`can_cut(x)`正確に削除できるかどうかを決定します$k$結果として得られるすべてのコンポーネントが少なくとも$x$頂点。 
3. で`can_cut(x)`、任意のノード (通常はノード) から DFS を実行します。$1$。 各ノードについて、すべての子を含む現在のサブツリーのサイズを計算します。 
4. 少なくともサイズの子サブツリーごとに$x$、潜在的なカットを表すカウンターをインクリメントします。 小さいサブツリーの場合は、サイズを累積して親に伝播します。 
5. 各ノードで、未割り当てノードの累積サイズが次の値に達すると、$x$、潜在的なカットカウンターをインクリメントし、累積サイズをゼロにリセットします。 これにより、形成された各コンポーネントが最小サイズを満たすことが保証されます。 
6. DFS 後、潜在的なカットの数が少なくとも$k$。 「はい」の場合、`x`実現可能です。 そうしないと大きすぎます。 
7. 二分探索を使用します。`can_cut(mid)`true、設定されています`l = mid`より大きな値を試してみます。 それ以外の場合は、設定します`r = mid - 1`。 まで続ける`l`等しい`r`。 
8. 実現可能な最大値を返す$x$。 

重要な不変条件は、DFS が常にサブツリーのサイズを集約し、下から上へ貪欲にコンポーネントを形成することです。 カットにカウントされる各コンポーネントはサイズ要件を満たしており、違反が発生しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(200000)

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        tree = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            tree[u - 1].append(v - 1)
            tree[v - 1].append(u - 1)

        def can_cut(x):
            cuts = 0
            def dfs(u, parent):
                nonlocal cuts
                total = 1
                for v in tree[u]:
                    if v == parent:
                        continue
                    subtotal = dfs(v, u)
                    if subtotal >= x:
                        cuts += 1
                    else:
                        total += subtotal
                return total
            dfs(0, -1)
            return cuts >= k

        l, r = 1, n
        while l < r:
            mid = (l + r + 1) // 2
            if can_cut(mid):
                l = mid
            else:
                r = mid - 1
        print(l)

if __name__ == "__main__":
    solve()
```DFS はサブツリーのサイズを蓄積します。 候補に達するか、それを超えるサブツリー`x`切り込みを形成し、より小さいものは上方に伝播します。 二分探索では各中間点をテストし、対数ステップを保証します。 使用する`sys.setrecursionlimit`大きなツリーのスタック オーバーフローを回避します。 インデックス付けは、1 ベースの入力から 0 ベースの Python リストに調整されます。
