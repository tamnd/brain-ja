 ## 解決策
 ## 問題の理解

 1 から 1 までの整数の順列が与えられます。$n$そして一連の問い合わせ。 各クエリは、指定された範囲内のインデックスのシーケンスがいくつあるかを尋ねます。$[l, r]$シーケンスが厳密に増加し、順列で各要素が次の要素を分割するように形成できます。 より簡単に言うと、部分配列内で増加する分割可能性の連鎖を数えています。 

順列プロパティにより、1 から 2 までのすべての数値が一致することが保証されます。$n$は 1 回だけ表示されます。 これにより、割り算の関係を考慮するときに、各数値が配列内で一意の位置を持つことが保証されます。 クエリは重複する可能性のあるサブ配列を要求します。$10^6$すべてのテスト ケースにわたるクエリ。 これにより、長さの配列内のサブシーケンスの数が制限されるため、単純な方法ですべてのサブシーケンスを反復処理するアプローチは即座に除外されます。$n$は$2^n-1$、これは不可能です$n$まで$10^6$。 

エッジケースには、答えが自明に 1 である長さ 1 の部分配列と、部分配列内に約数のない数値を含む範囲が含まれます。これらも個別の 1 要素シーケンスとしてカウントされる必要があります。 不注意な実装では、位置を考慮せずに約数を事前計算しようとしたり、複数の約数が存在する場合にシーケンスを二重にカウントしたりする可能性があります。 たとえば、配列では`[2, 1, 4]`クエリ付き`[1, 3]`、シーケンス`(1, 4)`1 は 4 を割るので、これは有効です。`(2, 4)`2 が 4 を割るので、これも有効です。これらのいずれかが欠けていると、間違った答えが生成されます。 

## アプローチ

 ブルートフォース手法では、クエリ範囲内のすべてのサブシーケンスを反復処理して、昇順と割り切りの両方をチェックします。 長さの部分配列の場合$k$、 がある$2^k-1$後続。 これは明らかに失敗します$k$最大値を考慮した場合、20 または 25 より大きい$n$まで$10^6$。 

重要な洞察は、これをグラフの問題として見ることで得られます。 各インデックス$i$はノードである可能性があり、からの有向エッジがあります。$i$に$j$もし$i < j$そして$a[i]$分割する$a[j]$。 有効なシーケンスをカウントすることは、この DAG 内のすべてのパスをカウントすることと同じです。 順列内の各数値は一意であり、次の制限があるため、$n$、各数値の倍数を事前に計算し、配列内の位置にマップできます。 

インデックスに対する動的プログラミングは自然です: 定義する`dp[i]`インデックスから始まる有効なシーケンスの数として`i`。 各インデックスの合計`1 + sum(dp[j])`全体`j`そのような`a[i]`分割する`a[j]`そして`i < j`。 倍数のブルート フォース計算は、数値からそのインデックスへのマップを使用して最適化でき、有効な倍数が配置されている場所への O(1) アクセスが可能になります。 複数のクエリに効率的に答えるために、プレフィックス合計配列を構築できます。`dp`これにより、連続するサブ配列に対して O(1) クエリを取得できるようになります。 これにより、全体的な複雑さが指数関数的なものから線形的なものに軽減されます。`n`プラスリニアイン`q`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | DAG + DP + プレフィックスの合計 | テスト ケースごとに O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、順列配列を読み取ります。`a`そして地図を構築する`pos`値からそのインデックスまで。 これにより、各倍数がどこに出現するかをすばやく見つけることができます。 
2. を初期化します。`dp`長さの配列`n+1`、 どこ`dp[i]`インデックスから始まる有効なシーケンスの数を保存します`i`。 
3. から逆方向に反復します。`i = n`まで`1`。 それぞれについて`i`、 セット`dp[i] = 1`のみを含むシーケンスを考慮する`a[i]`。 次に、すべての倍数を繰り返します`m`の`a[i]`そのような`m <= n`。 の位置であれば、`m`より大きい`i`、 追加`dp[pos[m]]`に`dp[i]`。 
4. プレフィックス合計配列を構築する`pref`以上`dp`、 となることによって`pref[i] = dp[1] + ... + dp[i]`。 
5. 各クエリについて`[l, r]`、答えを次のように計算します。`pref[r] - pref[l-1]`。 これが機能する理由は、`dp[i]`から始まるすべてのシーケンスをカウントします`i`、そして減算`pref[l-1]`前から始まるシーケンスを除外します`l`。 
6. すべてのクエリに対する回答を、与えられた順序で出力します。 

正しさを保証する不変式は次のとおりです。`dp[i]`インデックスから始まるすべての有効なシーケンスをカウントします`i`、エッジは順方向のみであるため、以前のインデックスで始まるシーケンスはこれに干渉しません。 プレフィックス合計を使用すると、二重にカウントすることなく、連続した範囲に対してこれらのカウントを効率的に合計できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        pos = [0] * (n + 1)
        for idx, val in enumerate(a):
            pos[val] = idx + 1

        dp = [0] * (n + 2)
        for i in range(n, 0, -1):
            dp[i] = 1
            val = a[i-1]
            mul = 2
            while val * mul <= n:
                m = val * mul
                if pos[m] > i:
                    dp[i] += dp[pos[m]]
                mul += 1

        pref = [0] * (n + 2)
        for i in range(1, n + 1):
            pref[i] = pref[i-1] + dp[i]

        res = []
        for _ in range(q):
            l, r = map(int, input().split())
            res.append(str(pref[r] - pref[l-1]))
        print(' '.join(res))

if __name__ == "__main__":
    solve()
```最初のセクションでは、数値を位置にマップして、有効な倍数をすばやく見つけます。 逆方向の反復により、次のことが保証されます。`dp[i]`で割り切れる、後から始まるすべてのシーケンスを組み込みます。`a[i]`。 プレフィックス合計により、定数時間の範囲クエリが可能になります。 Off-by-one エラーは、両方に 1 から始まるインデックスを使用することで回避されます。`pos`そして`dp`。
