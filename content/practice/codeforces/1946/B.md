 ## 解決策
 ## 問題の理解

 整数配列から始めます。 各操作により、空の部分配列を含む任意の連続した部分配列を選択し、その合計を計算し、その合計を新しい要素として配列内の任意の場所に挿入できます。 

重要な観察は、値を挿入すると配列の合計が変化するということです。 選択した部分配列に合計がある場合`x`、挿入後`x`、配列の合計は正確に増加します`x`。 

任務は正確に実行することです`k`演算を実行し、最終的な配列の合計を最大化します。 答えは膨大になる可能性があるため、それを剰余として出力します。`10^9 + 7`。 

制約が十分に大きいため、ほぼ線形の解決策が必要です。 すべてのテスト ケースにわたる合計値は、`n + k`せいぜい`2·10^5`これにより、部分配列を繰り返しシミュレートしたり、操作シーケンスを調査したりするアプローチは除外されます。 周りに何かが必要です`O(n)`または`O(n log n)`テストケースごとに。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

すべての部分配列が非正の合計を持つ配列を考えてみましょう。```
n = 2, k = 2
a = [-4, -7]
```最良の選択は空のサブ配列であり、その合計は次のようになります。`0`。 空でない部分配列があると、最終的な答えが減少します。 正しい結果は`-11`となり、`999999996`モジュロ`10^9+7`。 

正の最大部分配列を持つ配列を考えてみましょう。```
n = 3, k = 2
a = [2, 2, 8]
```部分配列の合計の最大値は次のとおりです。`12`。 挿入後`12`、その新しい要素はさらに大きな部分配列の一部になる可能性があります。 追加するソリューション`12`2回取得します`36`しかし、最適なプロセスにより生成されるのは、`12 + 24`、最終的な合計は`48`。 

もう 1 つの微妙なケースは、配列の合計が負であるが、正の部分配列が存在する場合です。```
n = 3, k = 1
a = [100, -200, 150]
```合計金額は`50`ただし、最良の操作では、最大の部分配列の合計が挿入されます。`150`、降伏`200`。 合計だけを見ると、利益の本当の源泉が見えなくなります。 

## アプローチ

 ブルートフォースの観点では、各演算をすべてのサブ配列の中から選択するものとして扱います。 がある`O(n²)`すべてのステップでサブ配列が作成され、挿入するたびに配列の長さが増加します。 1 回の手術でも費用がかかり、最大で`2·10^5`操作が完全に不可能になります。 

すべての操作は、選択された部分配列の合計をグローバル合計に正確に反映するため、総当たりのアイデアは正しいです。 難しいのは、どの選択順序が累積ゲインを最大化するかを判断することです。 

画期的な進歩は、正の合計を挿入した後に何が起こるかを理解することから始まります。 

元の配列の最大部分配列合計が次のようになると仮定します。`M`。 

もし`M ≤ 0`、空でない部分配列は取得する価値がありません。 空の部分配列が許可されているため、すべての操作が影響を与える可能性があります`0`。 答えは単純に元の配列の合計です。 

ここで仮定します`M > 0`。 

最初の操作では、次の値を挿入します。`M`。 その値が配列内に存在するため、元の最大合計セグメントと新しく挿入されたセグメントの両方を含む部分配列を選択できます。`M`。 その合計は次のようになります`2M`。 

挿入後`2M`、同じアイデアを繰り返して取得できます`4M`、 それから`8M`、 等々。 

ゲインの順序は次のとおりです。```
M, 2M, 4M, ..., 2^(k-1)M
```誰の貢献総額は```
M(2^k - 1)
```これより優れた戦略はありません。挿入されるすべての値は、最終的にはこれまでに利用可能な最大サブ配列合計から生じており、この 2 倍化戦略は常に可能な限り最大の増加を実現するからです。 

したがって、問題は次の 2 つの量に帰着します。```
S = sum of all array elements
M = maximum subarray sum, but at least 0
```最終的な答えは、```
S + M(2^k - 1)
```計算されたモジュロ`10^9 + 7`。 

最大部分配列合計は、Kadane のアルゴリズムを使用して線形時間で取得されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数的 / O(k·n²) より悪い | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列の合計を計算します。`S`。 
2. Kadane のアルゴリズムを実行して、部分配列の合計の最大値を見つけます。 
3. その値を次のように置き換えます。`max(0, maximum_subarray_sum)`。 

すべての部分配列が負の場合、いつでも空の部分配列を選択してゲインを得ることができます。`0`。 
4. コンピューティング`pow2 = 2^k mod MOD`。 
5. 追加の寄与を計算します。```
M(2^k - 1)
```モジュロ`MOD`。 
6. 元の合計を変換します`S`モジュロ形式に変換します。 

以来`S`負の場合がある場合は、Python のモジュロ演算を使用します。 
7. 2 つの部分を剰余として加算します。`MOD`そして結果を出力します。 

### なぜ効果があるのか

 しましょう`M`現在達成可能な非負の部分配列の合計の最大値になります。 

次の値を挿入した後`M`、挿入された値は、セグメントを生成するセグメントに隣接して配置できます。`M`。 次に達成可能な部分配列の合計の最大値は次のようになります。`2M`。 この議論を繰り返すと、最適なゲインがシーケンスを形成することがわかります。```
M, 2M, 4M, ..., 2^(k-1)M.
```それらの合計は正確に`M(2^k-1)`。 

挿入された値はすべて、部分配列の合計から生じます。 どのサブ配列も現在達成可能なサブ配列の合計の最大値を超えることはできないため、どの演算もそのステップでの 2 倍化戦略のゲインを超えることはできません。 この戦略は常に最大の利得を達成するため、最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def solve():
    t = int(input())

    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        total = sum(a)

        best = 0
        cur = 0

        for x in a:
            cur = max(0, cur + x)
            best = max(best, cur)

        extra = best * ((pow(2, k, MOD) - 1) % MOD)
        ans = (total % MOD + extra) % MOD

        print(ans)

solve()
```変数`total`元の配列の合計を格納します。 

Kadane のアルゴリズムは次を使用して実装されています。`cur`そして`best`。 表現```
cur = max(0, cur + x)
```は、空のサブ配列を許可しながら、現在の位置で終了するサブ配列の最大合計を維持します。 結果として、`best`自動的になる`max(0, maximum_subarray_sum)`。 

値`2^k`膨大になる可能性があるため、べき乗剰余演算が必要になります。 Pythonの組み込み`pow(2, k, MOD)`それを計算します`O(log k)`時間。 

よくある間違いはそれを忘れることです`total`マイナスになる可能性があります。 使用する```
total % MOD
```追加の寄与を追加する前に、それを正しいモジュール表現に変換します。
