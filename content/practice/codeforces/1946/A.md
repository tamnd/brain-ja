 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、配列の中央値を増やすために必要な増分演算の最小数を決定するように求められます。 インクリメント操作は、任意の要素を選択し、そこに要素を追加することで構成されます。 中央値は、並べ替えられると配列の中央の要素として定義されます。 配列の長さが偶数の場合、中央値は位置の要素になります。$\lceil n/2 \rceil$、1 から始まるインデックスを使用します。 

たとえば、配列の場合、`[2, 2, 8]`、中央値は`2`。 最初の要素に 1 つの増分を適用すると、次のようになります。`[3, 2, 8]`。 並べ替えるとこうなります`[2, 3, 8]`、新しい中央値は`3`、増加しました。 タスクは、中央値が厳密に増加することを保証するために、そのような操作の最小数を見つけることです。 

この制約は、効率的なアプローチが必要であることを意味します。 各配列には最大で次のものを含めることができます$10^5$すべてのテスト ケースの合計は次のようになります。$2 \cdot 10^5$。 これにより、要素を 1 つずつインクリメントして再ソートすると、特に数が多い場合に時間がかかりすぎるため、考えられるすべての操作をシミュレートする強引なアプローチが排除されます。 

サイズ 1 の配列では、微妙なエッジ ケースが発生します。 たとえば、配列が次の場合、`[1000000000]`、中央値は`1000000000`。 その 1 つの要素を 1 つ増やすと、中央値がすぐに増加します。 もう 1 つの特殊なケースは、すべての要素が等しい場合です。 例えば、`[5, 5, 5, 5]`中央値を増やすには、配列の後半に対する操作が必要です。 常に前半をターゲットにする不注意なアプローチでは、必要な増分をカウントし間違える可能性があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。配列内の要素を繰り返し増加させ、増加するまでそのたびに中央値を再計算します。 これが機能するのは、要素を中央値以上に増加させると中央値の値に影響を与える可能性があるためです。 ただし、これには各操作の後に配列を繰り返しソートする必要があります。$O(n \log n)$操作ごとに。 大規模なアレイまたは大きな中央値ギャップの場合、これは最大で$O(n^2 \log n)$動作が遅すぎます。 

最適なソリューションを得る上で重要な洞察は、中央値は並べ替えられた配列の中央と上半分にのみ依存するということです。 中央値より前の要素を増分しても役に立ちません。 配列がソートされたら、中央値とその右側の要素をターゲットにすると、それらを直接インクリメントして、その半分の次に大きい数値に到達できます。 ソートされた上半分の次の要素まで中央値を引き上げるのに必要な増分の合計数をカウントすることで、最小限の操作を効率的に決定できます。 

各増分を個別にシミュレートする必要はありません。 配列を 1 回ソートし、中央値の位置を特定してから、ターゲット値と現在の要素の差を中央値以降、中央値が増加するまで合計することができます。 このアプローチでは、並べ替え後の上半分のサイズが線形になります。$O(n)$配列がソートされると、テストケースごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 log n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取り、$t$。 テスト ケースごとに、次の内容を読んでください。$n$そして配列$a$。 
2. 配列をソートする$a$降順ではない順に。 並べ替えにより、中央値を直接特定し、それに影響を与える要素を操作できるようになります。 
3. 中央値のインデックスを次のように計算します。$m = n // 2$0 から始まるインデックス付け。 これは、$\lceil n/2 \rceil$1 から始まるインデックスの - 番目の要素。 
4. 変数を初期化する`operations`ゼロに。 これにより、必要な増分の合計数が累積されます。 
5. インデックスから要素を反復処理します。$m$に$n-1$、中央値とその右側のすべての要素をカバーします。 要素ごとに、選択したターゲット値と現在の要素の差を計算します。 ターゲット値は、すべての増分後の現在の中央値を超える最小値です。 
6. これらの差を合計します。 値に影響を与えるには、中央値以上の要素を増分対象とする必要があるため、合計によって必要な増分の最小数が決まります。 
7. 現在のテスト ケースの結果として合計を出力します。 

機能する理由: 並べ替え後、中央値は位置の要素になります$m$。 中央値を増やすには、少なくとも中央値の要素を増やす必要があります。 中央値を任意の値に引き上げる操作の数$x$からのすべての要素の増分の合計です。$m$その下にあるもの以降$x$。 常に適切な要素をターゲットにし、正確な差を合計するため、これにより中央値を厳密に増加させるための最小限の操作が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()
    median_idx = n // 2
    target = a[median_idx]
    operations = 0
    # Increment the median and right half until median increases
    for i in range(median_idx, n):
        operations += max(0, a[i] - target + 1)
        target = a[i] + 1
    print(operations)
```コードは、高速 I/O を使用してテスト ケースと配列を効率的に読み取ります。 並べ替えにより中央値に直接アクセスできます。 中央値以上の要素に必要な増分を計算し、それらを累積します。 微妙な点は、中央値に影響を与える次の可能な値まで常に増加するように、ステップごとにターゲットを更新することです。
