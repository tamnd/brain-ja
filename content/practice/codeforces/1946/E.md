 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$n$、つまり、以下のすべての整数が含まれます。$1$に$n$正確に 1 回、未知の順序で。 順列を直接見る代わりに、そのプレフィックスの最大値とサフィックスの最大値の位置が示されます。 位置におけるプレフィックスの最大値$i$の要素が$i$は、その前のすべての要素よりも大きくなります。 同様に、位置での接尾辞の最大値$i$はその後のすべての要素よりも大きくなります。 

タスクは、これらの指定された位置と一致する個別の順列がいくつあるかを数えることです。 答えは巨大になる可能性があるため、それを剰余として出力します$10^9 + 7$。 

制約は次のことを教えてくれます$n$と同じ大きさにすることができます$2 \cdot 10^5$、最大で$10^4$テストケース。 順列を列挙する強引なアプローチは不可能です。$n!$成長が早すぎます。 これは、解が線形または線形に近いものでなければならないことを意味します。$n$、 理想的には$O(n)$テストケースごとに。 

プレフィックスとサフィックスの最大値が重なっている場合、またはそれらの位置に互換性がない場合、明らかではないエッジ ケースが発生します。 たとえば、位置がプレフィックス最大値であると主張されているが、その前にサフィックス最大値のより大きな要素がある場合、両方の制約を満たす置換は存在しません。 もう一つの厄介なケースは、$n=1$; 唯一の順列は簡単ですが、少なくとも 2 つの要素を想定したコードは失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、サイズのすべての順列を生成しようとします。$n$プレフィックスとサフィックスの最大位置との一貫性をチェックします。 これは原理的には正しいですが、実行不可能です。 のために$n = 20$、 がある$20! \approx 2.4 \cdot 10^{18}$これは計算の限界をはるかに超えています。 

重要な洞察は、この問題が最大の要素から最小の要素への順列を埋めることと同等であることを理解することです。 最大の要素は、プレフィックスの最大値とサフィックスの最大値の両方が存在する場合、その位置になければなりません。そうでない場合、最大の要素は最大値の位置によって制限される自由範囲を持ちます。 最大の要素を配置すると、問題は再帰的に残りの位置を次に大きな数値で埋めることになります。 

より具体的には、各位置は、プレフィックスの最大値として固定、サフィックスの最大値として固定、または制約なしの 3 つのカテゴリのいずれかに分類されます。 制約のない位置は自由に割り当てることができますが、プレフィックスまたはサフィックスのルールに違反することはできません。 この推論を使用すると、位置を反復して各要素の有効な選択肢の数を維持し、これらの数をモジュロで乗算することができます。$10^9+7$。 これは$O(n)$テストケースごとのアプローチ。

 ## アルゴリズムのチュートリアル

 1. プレフィックス最大値とサフィックス最大値の位置を前処理します。 便宜上、これらをゼロベースのインデックスに変換します。 配列を初期化する`perm`サイズの$n$でいっぱい`-1`不明な位置をマークします。 
2. 最大の要素を配置します。$n$、その位置が一意に決定される場合。 位置が最初のプレフィックスの最大値と最後のサフィックスの最大値の両方である場合、最大の要素がそこに配置される必要があります。 そのような位置が存在しない場合、配置は指定された最大値で定義された範囲を満たす必要があります。 
3. 各要素について$n-1$まで$1$、それが占めることができる有効な位置を決定します。 A position is valid if it does not conflict with a prefix maximum to its left or a suffix maximum to its right that is larger than the current element. 各要素の有効な位置の数を数えます。 
4. 各要素の選択肢の数を乗算して、順列の合計数を取得します。 すべての計算をモジュロに保つ$10^9 + 7$。 
5. If at any step there are zero valid positions for an element, the configuration is impossible, and we output zero for this test case.

 Why it works: We maintain the invariant that all placed elements respect the prefix and suffix maxima constraints. 最大の要素から最小の要素まで考慮することにより、割り当てられたすべての位置が、より大きな要素を後で配置することによって無効にならないことが保証されます。 Multiplying the number of available choices accounts for all combinatorial possibilities without double-counting.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        n, m1, m2 = map(int, input().split())
        prefix = list(map(int, input().split()))
        suffix = list(map(int, input().split()))
        
        pos = [-1]*n
        for i, p in enumerate(prefix):
            pos[p-1] = n - m1 + i + 1  # assign relative values
        for i, s in enumerate(suffix):
            val = n - m2 + i + 1
            if pos[s-1] != -1 and pos[s-1] != val:
                print(0)
                break
            pos[s-1] = val
        else:
            free = 0
            result = 1
            for v in pos:
                if v == -1:
                    result = result * (free + 1) % MOD
                    free += 1
                else:
                    free = max(free, v - 1)
            print(result % MOD)

solve()
```このソリューションはすべての入力を効率的に読み取り、相対ランクを使用してプレフィックスとサフィックスの最大値の既知の位置を割り当てます。 競合はすぐに検出されます。 自由な位置は組み合わせてカウントされ、反復するにつれて可能性が増大します。 このアルゴリズムは再帰を回避し、線形時間で動作し、モジュロ演算を慎重に処理します。

 ## 特殊なケース

 入力など、プレフィックスとサフィックスの最大値が競合する場合:```
3 1 1
2
2
```アルゴリズムは、位置 2 が両方を満たすことができないことを検出し、ゼロを出力し、早期に終了します。 単一要素の置換の場合、ソリューションは正しく 1 を出力します。 自由な位置は、反復中に可能性を正確に増やし、過剰カウントを防ぎます。 プレフィックスとサフィックスの最大値で重複する位置は、相対順位によって調整されます。
