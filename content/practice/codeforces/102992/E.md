 ## 解決策
 ## 問題の理解

 原点から始まる無限グリッド上にウォークを構築しています。 各移動は、右、左、上、下という 4 つの基本方向のいずれかで 1 単位となり、各方向で使用可能なカウントが与えられます。 最後のウォークでは、すべての手を正確に使用する必要があります。 

そこには『悪の座標』と呼ばれる禁断の格子点が存在する。 この要件は、単にどこか別の場所で終了するよりも強力です。つまり、中間プレフィックスを含め、歩行中のどの時点でも、その座標に正確に着陸することは許可されません。 

タスクは、その禁止されたセルに足を踏み入れないようにするすべての動きの順序を決定するか、そのような順序が存在しないと判断することです。 

したがって、入力構造は、各方向に実行できるステップ数を表す 4 つの整数と、禁止された座標を表す 2 つの整数です。 出力は、通常は文字列としての有効な一連の動き、またはそれが不可能であるという宣言です。 

制約は、出力が移動数において線形になるほど十分に小さいですが、すべての順列をシミュレートしたり、順序付けを強引に実行しようとする試みはすぐに失敗するほど十分に大きいです。 合計 10^5 までの移動では、どの解法でも O(n) 時間でシーケンスを構築する必要があります。 

重要な問題は、「すべての右を実行し、次にすべてを上に、次にすべてを左に、次にすべてを下に移動する」といった単純な構造が、誤って禁止された座標を通過してしまう可能性があることです。 これは、モノトーン セグメントの中間プレフィックスが、それらのセグメントによって掃引された長方形内にある場合、悪点と正確に一致する可能性があるために発生します。 

微妙な失敗例は、禁止点が 2 つの連続する方向性ブロックによって形成される領域内に正確に存在する場合に発生します。 たとえば、最初にすべての権利を移動し、次にすべての権利を上に移動すると、x ≤ R および y ≤ U の任意の点 (x, y) が何らかの接頭辞でヒットします。 これに不正な座標が含まれている場合、最終エンドポイントが正常であっても、構築は無効になります。 

## アプローチ

 強引なアイデアは、4 つの方向ブロックのすべての順列を試し、禁止点を回避する順序があるかどうかを確認することです。 各順列は単調なパスの形状を定義し、各配置の歩行をシミュレートします。 

これは論理的に機能します。有効な解決策は複数の動きセットの順序付けでなければならないからです。 ただし、4つしかありません！ = 24 順列なので、チェックするだけでも安価です。 本当の問題は、パスが禁止された座標と交差するかどうかに対して各順序を慎重に検証する必要があることです。そしてさらに重要なことに、問題の構造から、非常に特殊な種類の障害のみが発生する可能性があることが明らかになりました。それは、単一の単調象限遷移内で禁止点に到達した場合です。 したがって、力ずくで行うのは過剰であり、構造を隠してしまいます。 

重要な観察は、禁止された座標に向かって移動する 2 つの直交する方向を切り替えた場合にのみ、そのパスが「危険」になるということです。 原点を基準とした各象限では、右/上、右/下、左/上、または左/下という 1 組の方向のみが重要になります。 他のすべての動きは直交しているため、その領域を離れると禁止された座標を再作成することはできません。 

したがって、順列をグローバルに検索する代わりに、関連する象限内の 2 つのブロックの相対的な順序を決定するだけで済みます。 残りの動きはすべて後から安全に追加できます。 

これにより、プレフィックス パスが正確に (x, y) に到達しないように、方向ブロックのペアに対して 2 つの順序のどちらかを選択するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 移動回数を R、L、U、D として表し、禁止座標を (x、y) として表します。 

### 1. 禁止点がどの象限にあるかを特定する

ターゲットの方向を (x, y) に向かって分類します。 x が負でない場合、それに到達するには右に移動する必要があります。 x が負の場合、左に移動する必要があります。 y 方向と垂直方向の移動についても同様です。 これにより、どの 2 つの移動タイプが禁止された座標を「構築」できる可能性があるかがわかります。 

他の 2 つの移動タイプは反対方向であり、禁止されたプレフィックスの形成に関与できません。 

### 2. 関連する 2 つの方向のみに焦点を当てる

 x ≥ 0 かつ y ≥ 0 の場合、(x, y) にヒットする可能性があるのは R と U だけです。 x ≥ 0 および y < 0 の場合、危険なペアは R と D です。x < 0 および y ≥ 0 の場合、それは L と U です。x < 0 および y < 0 の場合、それは L と D です。 

残りのすべての動きは、少なくとも 1 つの軸で禁止座標から離れるため、禁止座標を作成せずに前後に自由に配置できます。 

### 3. 2 つの重要なブロックの順序を決定する

 ここで、一方のブロックを他方のブロックの前に配置するとプレフィックスが (x, y) にヒットするかどうかを検討します。 

x ≥ 0 および y ≥ 0 の場合を考えます。すべての R の動きを最初に配置し、次にすべての U の動きを配置すると、R ブロックのすべての接頭辞が x 軸上に配置され、U に切り替えた後のすべての接頭辞が固定 x = R の垂直線に配置されます。 

x ≤ R および y ≤ U の場合、U ブロックへの移行中に、最終的には正確に (x, y) に到達しますが、これは禁止されています。 

これを避けるために、順序を入れ替えて、U を R の前に置きます。この配置では、最初に x とは関係なく y を増加させます。そのため、(x, y) に一致するプレフィックスが同じ方法で形成されることはありません。 

同じロジックが他の象限にも対称的に適用されます。同じプレフィックス ステップで禁止点に達するように両方の座標を揃えることを避ける順序を選択します。 

### 4. 残りの 2 つの方向を追加します。 

クリティカルペアの安全な順序を修正した後、すべての手を反対方向に追加します (右/上の象限の場合は L または D)。 これらの移動は座標を減らすだけであり、建設的なプレフィックスフェーズですでに一致を回避しているため、禁止ポイントを再導入することはできません。 

### 5. 構築したシーケンスを出力します。 

最終的なシーケンスは、選択したブロックを単純に連結したものになります。 

### なぜ効果があるのか

 不変条件は、どのプレフィックスでも、単調な動きの同じフェーズで禁止点に到達するために必要な両方の座標にパスが同時に一致することは決してないということです。 この構造で (x, y) に正確に到達する唯一の方法は、両方の軸が同じブロック順序内で同期された方法で累積される場合です。 2 つの座標の累積を分離する順序を選択することで、接頭辞が禁止された座標と一致することがなくなります。 

他のすべての動きは関連する象限ターゲットから離れるため、シーケンスの後半でミスした位置合わせを再導入することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    R, L, U, D, x, y = map(int, input().split())
    
    res = []
    
    # Decide quadrant of dangerous point
    if x >= 0 and y >= 0:
        # dangerous pair: R and U
        if not (x <= R and y <= U):
            res.append("R" * R)
            res.append("U" * U)
        else:
            res.append("U" * U)
            res.append("R" * R)
        res.append("L" * L)
        res.append("D" * D)
    
    elif x >= 0 and y < 0:
        # dangerous pair: R and D
        y = -y
        if not (x <= R and y <= D):
            res.append("R" * R)
            res.append("D" * D)
        else:
            res.append("D" * D)
            res.append("R" * R)
        res.append("L" * L)
        res.append("U" * U)
    
    elif x < 0 and y >= 0:
        # dangerous pair: L and U
        x = -x
        if not (x <= L and y <= U):
            res.append("L" * L)
            res.append("U" * U)
        else:
            res.append("U" * U)
            res.append("L" * L)
        res.append("R" * R)
        res.append("D" * D)
    
    else:
        # dangerous pair: L and D
        x = -x
        y = -y
        if not (x <= L and y <= D):
            res.append("L" * L)
            res.append("D" * D)
        else:
            res.append("D" * D)
            res.append("L" * L)
        res.append("R" * R)
        res.append("U" * U)
    
    print("".join(res))

if __name__ == "__main__":
    solve()
```実装は象限分解に直接続きます。 各ブランチは、禁止された座標を共同で構築できる 2 つの方向を分離し、それらの順序付けによりプレフィックスの同時整列が回避されるようにします。 

微妙な点は、各象限ケース内での実現可能性をチェックするときに、負の座標を正の比較に変換することです。 これにより、「これら 2 つのブロックをこの順序で結合すると (x, y) にヒットするかどうか」という条件がすべてのケースで一貫して保たれます。 

残りの方向は、重要な位置合わせが回避されると禁止点への到達に寄与できないため、無条件で追加されます。 

## 実用的な例

 ### 例 1

 入力:

 R = 2、L = 0、U = 2、D = 0、禁止 = (1, 1)

 私たちは第 1 象限のケースにいますので、R と U が重要です。 

| ステップ | アクション | ポジションの洞察 |
 | --- | --- | --- |
 | 1 | R を試してから U を試してください。 R プレフィックスが (1,0) に達し、次に U が (1,1) に達します → 禁止 |
 | 2 | U に切り替えてから R に切り替えます | U は (0,1) をビルドし、R は (2,1) をビルドしますが、(1,1) にはヒットしません |

 出力は、x と y の累積間の同期を解除することにより、禁止点を回避します。 

### 例 2

 入力:

 R = 3、L = 1、U = 2、D = 2、禁止 = (2、-1)

 これは右下象限のケースです。 

| ステップ | アクション | ポジションの洞察 |
 | --- | --- | --- |
 | 1 | R を確認してから D | 整列されたプレフィックスで (2,-1) に到達します |
 | 2 | D に切り替えてから R | D は最初に垂直に移動するため、x と y の位置合わせは分離されます。 

順序を修正した後、L と U が安全に追加されます。 

これらの例は、唯一の危険なイベントは、2 つの重要な方向のプレフィックス位置合わせが同時に行われることであることを示しています。

 ## 特殊なケース

 微妙なエッジ ケースの 1 つは、禁止座標が単調ブロックが到達する範囲の境界上に正確に存在する場合に発生します。 たとえば、R = 5 および U = 5 で、禁止点が (3, 3) である場合、R の次に U を順序付けると、プレフィックスとして必然的に (3, 3) が通過します。 その状況では、アルゴリズムは位置合わせ条件を検出し、順序を U、次に R に切り替え、両方の座標に同時に一致するプレフィックスがないことを保証します。 実行中、U は最初に点 (0, k) を生成するため、その段階では x が 3 になることはなく、その後 R が適用されると y は 5 に固定されるため、(3, 3) に到達することはありません。 

もう 1 つのエッジ ケースは、1 方向のカウントがゼロの場合です。 U = 0 または R = 0 の場合、パスは強制的に直線上に配置され、禁止点はその線分上に正確に存在する場合にのみヒットします。 x ≤ R および y ≤ U の実現可能性チェックが自動的に失敗するか、無害なスワップがトリガーされ、それでも有効な線形パスが生成されるため、アルゴリズムがこれを処理します。 

最後のエッジ ケースは、禁止された座標がすべての動きとは「異なる象限」にある場合です。たとえば、第 1 象限の場合の x > R または y > U です。 この場合、条件によりスワップが防止され、パスは物理的に禁止ポイントにまったく到達できないため、単純な順序付けが安全に使用されます。
