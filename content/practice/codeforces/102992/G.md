 ## 解決策
 ## 問題の理解

 入力は正方形のボードで、各位置は黒、白、または空のいずれかになります。 白い石は上下左右に隣接してクラスターを形成することができます。 クラスターは、その石の少なくとも 1 つが空のセルに触れた場合にのみ存続します。 クラスター内のすべての石が空ではないセル (黒または白) で完全に囲まれている場合、そのクラスターは捕捉されたとみなされ、そのすべての白い石を数えなければなりません。 

出力は単一の整数、つまりキャプチャされた白いクラスターに属する白い石の総数です。 

ボードには最大 100 万個のセルを含めることができるため、アルゴリズムはグリッド サイズに対して線形時間で実行する必要があります。 これにより、石ごとまたはクエリごとの繰り返し検索が即座に排除されます。 メモリ制限は、グリッドと同じサイズの補助配列を格納することは問題ないことを示唆していますが、超線形は不可能です。 

素朴なロジックの主な失敗ケースは、訪問したコンポーネントをマークせずに各ホワイト ストーンを個別にチェックするときに発生します。 10,000 個のホワイト ストーンのチェーンでは、同じ構造を繰り返し再スキャンすることになり、作業が大幅に重複し、パフォーマンスの誤った仮定が発生します。 

別のエッジケースは、白い​​クラスターが黒い石と他の白いクラスターの両方に触れているが、同じ接続されたコンポーネントのどこか遠くに単一の空の自由を持っている場合に発生します。 不完全なトラバーサルによりその自由が失われると、クラスターが誤ってデッドとしてマークされる可能性があります。 

## アプローチ

 ブルートフォース手法では、すべての白い石を反復処理し、そこからフラッド フィルを実行して、その接続されたコンポーネントに空の隣接コンポーネントが含まれているかどうかを判断します。 洪水の埋め立てごとにコストがかかる可能性がある$O(n^2)$、すべてが白い石の密なボードでは、これは次のようになります。$O(n^4)$最悪の場合。 各コンポーネントの自由度が明示的にチェックされるため、正確性は簡単ですが、同じコンポーネントの再計算が繰り返されるため、実行不可能になります。 

重要な観察は、ボードが自然に白い石の接続されたコンポーネントに分解され、各コンポーネントが 2 値の特性を持っていることです。つまり、少なくとも 1 つの隣接する空のセルがあるかどうかのいずれかです。 これは、ノードごとではなくコンポーネントごとに単一の走査を実行することを示唆しています。 標準の BFS または DFS は、1 回のパスでコンポーネント全体を検出し、境界が「.」セルに接触しているかどうかを同時に追跡できます。 走査が終了したら、コンポーネントのサイズを応答に追加するか、完全に無視します。 

これにより、各セルが正確に 1 回訪問され、各エッジが一定の回数検査されるため、問題は線形時間に短縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 石ごとのブルート フォース BFS |$O(n^4)$|$O(n^2)$| 遅すぎる |
 | コンポーネント BFS/DFS |$O(n^2)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドのすべてのセルをスキャンし、未訪問の白い石が見つかるたびに、そこからトラバースを開始します。 これにより、各白色コンポーネントが正確に 1 回処理されることが保証されます。 
2. トラバース中に、現在のコンポーネント内のすべての石を含むキューまたはスタックを維持します。 訪問した各白いセルにマークを付けて、別のトラバースに再度追加されないようにします。 
3. コンポーネントを展開する間、2 つの情報を保持します。それは、遭遇した白い石の数と、訪問した石の隣接するセルが空かどうかを示すブール フラグです。 このフラグが生存を決定します。 
4. トラバース構造から飛び出た各石について、その 4 つの隣接石をチェックします。 近隣が白で未訪問の場合は、コンポーネントに追加します。 ネイバーが空の場合は、liberty フラグを true に設定します。 黒のセルは展開では無視されますが、自由フラグには影響しません。 
5. トラバーサルの終了後、自由フラグが false の場合は、コンポーネント サイズを最終応答に追加します。 
6. すべてのセルが処理されるまでグリッドのスキャンを続けます。 

正確さは、各接続コンポーネントを単一のエンティティとして扱うことにかかっています。 トラバーサルにより、白石が 2 回カウントされることはなくなり、リバティ フラグはコンポーネントの考えられるすべてのエスケープ ポイントを集約します。 

### なぜ効果があるのか

 それぞれの白いコンポーネントは、決定が下される前に十分に検討されます。 接続性は推移的であるため、同じコンポーネント内の別の白い石から到達可能な白い石は、同じトラバースで発見されることが保証されます。 自由条件は空のセルへの隣接性にのみ依存し、この特性はコンポーネント全体にわたって単調です。つまり、いずれかの石に自由がある場合、コンポーネント全体が生きています。 したがって、単一の走査に基づいてコンポーネントを分類すると、正確性が維持され、二重カウントが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input().strip())
    grid = [input().strip() for _ in range(n)]
    
    vis = [[False] * n for _ in range(n)]
    
    dirs = [(1,0), (-1,0), (0,1), (0,-1)]
    
    ans = 0
    
    for i in range(n):
        for j in range(n):
            if grid[i][j] != 'o' or vis[i][j]:
                continue
            
            q = deque()
            q.append((i, j))
            vis[i][j] = True
            
            size = 0
            alive = False
            
            while q:
                x, y = q.popleft()
                size += 1
                
                for dx, dy in dirs:
                    nx, ny = x + dx, y + dy
                    if nx < 0 or nx >= n or ny < 0 or ny >= n:
                        continue
                    if grid[nx][ny] == '.':
                        alive = True
                    elif grid[nx][ny] == 'o' and not vis[nx][ny]:
                        vis[nx][ny] = True
                        q.append((nx, ny))
            
            if not alive:
                ans += size
    
    print(ans)

if __name__ == "__main__":
    solve()
```繰り返しの解析オーバーヘッドを避けるために、グリッドは文字列として保存されます。 訪問配列により、各白石が正確に 1 回処理されることが保証されます。 大規模なグリッドでの再帰の深さの問題を回避するために、DFS ではなく BFS が選択されます。 の`alive`flag は空の近傍が見つかるたびに更新され、コンポーネント サイズはそのような近傍が存在しない場合にのみ累積されます。 

実装によくある落とし穴は、BFS を伝播するのは白い石だけであることを忘れていることです。 たとえ拡張を妨げたとしても、黒い石はキューに入れられるべきではありません。 もう 1 つの微妙な問題は境界処理です。境界外のセルは空のスペースとして扱われずに無視されます。 

## 実用的な例

 ### 例 1

 小さな基板を考えてみましょう。```
o x o
x o x
o x .
```| ステップ | 開始セル | コンポーネントのサイズ | アライブフラグ | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | (0,0) | 1 | 偽 | 白人の隣人はいない |
 | 2 | (1,1) | 1 | 本当 | 「。」にタッチします。 (2,2) | で
 | 3 | (0,2) | 1 | 偽 | 孤立した白 | 写真

 最終的な答えは、自由のないコンポーネント、つまり孤立したコンポーネントのみをカウントします。 これにより、BFS が囲まれたクラスターと空の空間に接触しているクラスターを正しく区別していることが確認されます。 

### 例 2```
o o x
x o x
x x x
```| ステップ | コンポーネント | サイズ | アライブフラグ | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | すべて接続された o | 3 | 偽 | 完全密閉 |

 3 つの白い石はすべて、隣接する空のセルのない 1 つの接続されたコンポーネントに属します。 BFS はすべての白を 1 つのトラバースにマージし、すべてを正しくカウントします。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n^2)$| 各グリッド セルは、BFS/DFS トラバーサル中に 1 回アクセスされます。 
| スペース |$O(n^2)$| アクセスされた配列とキューは、最悪の場合、すべてのセルを格納します。 

グリッド サイズの境界$10^6$各操作はセルごとに一定時間であるため、セルはこの複雑さ内に快適に収まります。

 ## 特殊なケース

 黒い石に完全に囲まれた 1 つの白い石は、最も単純なキャプチャされたコンポーネントを示しています。 BFS はそのセルから開始され、空の隣接セルを見つけず、答えに 1 つだけ追加します。 

白い石の大きなチェーンのどこかに空のセルが 1 つ隣接している場合、セルごとのチェックが失敗する理由がわかります。 トラバーサルでは、空の近傍を 1 回確認し、アライブ フラグを設定して、構造全体のカウントを正しく回避します。 

白い石がないボードではトラバーサル トリガーはゼロとなり、アルゴリズムは不要な処理を行わずに即座にゼロを返します。
