 ## 解決策
 ## 問題の理解

 私たちにはチェス盤上のクイーンの位置が与えられています。 クイーンは左右上下と斜め4方向の8方向に攻撃します。 女王はある方向にあるすべての女王を攻撃するのではなく、その光線に沿って最初に遭遇した女王のみを攻撃します。 

すべての女王について、それが直接攻撃する他の女王の数を数えなければなりません。 可能な方向は 8 つだけであるため、その値は 0 ～ 8 です。 すべてのクイーンについてこの数を計算した後、配列を構築します。`t[i]`攻撃しているクイーンの正確な数です`i`他の女王たち。 

ボードのサイズとクイーンの数は両方とも同じくらい大きくなります。`10^5`。 二次解は直ちに除外されます。 すべてのクイーンのペアをチェックするには、大まかに必要になります`10^10`最悪の場合の比較。これは 2 秒に収まる量をはるかに超えています。 ソリューションは次の点に近いものでなければなりません`O(m log m)`またはそれ以上です。 

難しいのは、「この方向の最初の女王のみ」という表現です。 単純な実装では、同じ行、列、または対角線を共有するすべてのクイーンをカウントする可能性があります。 それは間違いです。 

次の例を考えてみましょう。```
5 3
2 1
2 3
2 5
```女王はすべて同じ列にいます。 

正しい攻撃数は次のとおりです。 

-`(2,1)`攻撃`(2,3)`-`(2,3)`両方の隣人を攻撃する
 -`(2,5)`攻撃`(2,3)`したがって、カウントは次のとおりです`[1,2,1]`、出力は次のようになります。```
0 2 1 0 0 0 0 0 0
```同じ行にあるすべてのクイーンを数える不注意な解決法では、誤った数が与えられてしまいます。`[2,2,2]`。 

斜めの処理もバグのよくある原因です。 2 つのクイーンが同じ対角線上にあるのは、どちらかの場合のみです。`r - c`または`r + c`一致します。 

例えば：```
5 2
1 5
3 3
```これらの女王たちは同じ上に横たわっています`/`対角線の理由:```
1 + 5 = 6
3 + 3 = 6
```ソリューションチェックのみ`r - c`この攻撃を見逃すだろう。 

もう 1 つの微妙なケースは、複数のクイーンがラインを共有しているものの、ソート後に隣接していない場合に発生します。```
8 4
4 1
4 3
4 5
4 8
```列に沿って隣接する女王のみが互いに攻撃します。 列の女王たち`1`そして`5`対話しないでください。`(4,3)`道を塞いでしまう。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての女王について、他のすべての女王をスキャンし、それらが 8 つの方向のいずれかにあるかどうかを確認します。 存在する場合は、別の女王が道を妨げているかどうかを判断します。 チェスの動きは幾何学的であり、座標演算で簡単にテストできるため、これは論理的に機能します。 

問題はコストです。 がある`m`クイーンなので、すべてのペアをチェックするのにすでに時間がかかります`O(m^2)`。 と`m = 10^5`、それは`10^10`ブロックロジックを考慮する前にペアチェックを行います。 

クイーンの動きの構造は、はるかに優れたアプローチを提供します。 女王は、以下を共有する女王とのみ対話します。 

- 同じ行
 - 同じ列
 - 同じ`r - c`対角線
 - 同じ`r + c`対角線

 これらのラインのいずれか 1 つの内側では、並べ替え後の隣接するクイーンのみが互いに攻撃できます。 同じライン上で 2 つのクイーンの間に別のクイーンがある場合、近い方のクイーンが遠い方のクイーンをブロックします。 

この観察によって問題は完全に変わります。 すべてのペアを比較するのではなく、女王を行ごとにグループ化します。 

- 行のグループ化`r`- 列のグループ化`c`- 対角グループ化`r - c`- による反対角グループ`r + c`各グループ内で、ラインに沿って位置を並べ替えます。 次に、隣接するすべてのペアが各方向に 1 回の攻撃に寄与します。 

たとえば、行の列にクイーンが含まれている場合:```
1, 4, 7
```それから：

-`1`攻撃`4`-`4`両方を攻撃する`1`そして`7`-`7`攻撃`4`ペア`(1,7)`直接対話することはありません。 

すべてのクイーンは、ライン タイプごとに最大 2 つの隣接関係に参加するため、計算全体が効率的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(㎡) | お(1) | 遅すぎる |
 | 最適 | O(m log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのクイーンの位置を読み取り、すべてのクイーンにインデックスを割り当てます。 

最終的な攻撃カウントは特定の各クイーンに属するため、安定したストレージが必要です。 
2. 4 つのハッシュ マップを作成します。 

各マップは 1 つの攻撃ラインを共有するクイーンをグループ化します。 

- 行数`r`- 列別`c`- 主対角線`r - c`- 対角線による`r + c`3. すべてのクイーンを 4 つのグループすべてに挿入します。 

保存された各エントリには、その線に沿ってクイーンを並べ替え、後でクイーン インデックスを回復するのに十分な情報が含まれています。 
4. すべての行グループについて、列ごとに並べ替えます。 

ソート後の隣接するクイーンは、まさに横方向に見たクイーンになります。 
5. ソートされた行の隣接するペアごとに、両方のクイーンの攻撃カウンターをインクリメントします。 

女王様なら`A`そして`B`はソート順に連続しており、それらの間にクイーンが存在しないため、互いに直接攻撃します。 
6. 列グループに対して同じプロセスを繰り返します。 

ここでは移動が垂直であるため、行でソートします。 
7. 繰り返します`r - c`斜めのグループ。 

この対角線に沿って行と列が一緒に増加するため、行による並べ替えで十分です。 
8. 繰り返します`r + c`斜めのグループ。 

繰り返しますが、行で並べ替えると、行に沿った正しい順序が得られます。 
9. 4 つの構造すべてが処理されると、各クイーンには攻撃されたクイーンの総数が表示されます。 
10. アレイを構築する`ans[0...8]`。 

各クイーンの攻撃回数`k`、増分`ans[k]`。 
11. 周波数配列を出力します。 

### なぜ効果があるのか

 任意の行、列、または対角線内で、女王は各方向の最も近い隣の女王のみを攻撃します。 線に沿ってクイーンを並べ替えると、最も近い要素が隣接する要素として正確に表示されます。 

すべての直接攻撃関係は、ちょうど 1 つのライン グループ内に隣接するペアとして 1 回出現します。 すべての有効な攻撃は 4 つの回線タイプのいずれかに基づいているため、攻撃が見逃されることはありません。 隣接しないクイーンには常に別のクイーンが経路をブロックしているため、追加の攻撃は追加されません。 

隣接するすべてのペアの両方のエンドポイントをインクリメントするため、各クイーンは攻撃するクイーンの数を正確に蓄積します。 

## Python ソリューション```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def process(groups, cnt):
    for arr in groups.values():
        arr.sort()

        for i in range(len(arr) - 1):
            _, a = arr[i]
            _, b = arr[i + 1]

            cnt[a] += 1
            cnt[b] += 1

def solve():
    n, m = map(int, input().split())

    rows = defaultdict(list)
    cols = defaultdict(list)
    diag1 = defaultdict(list)   # r - c
    diag2 = defaultdict(list)   # r + c

    cnt = [0] * m

    for idx in range(m):
        r, c = map(int, input().split())

        rows[r].append((c, idx))
        cols[c].append((r, idx))
        diag1[r - c].append((r, idx))
        diag2[r + c].append((r, idx))

    process(rows, cnt)
    process(cols, cnt)
    process(diag1, cnt)
    process(diag2, cnt)

    ans = [0] * 9

    for x in cnt:
        ans[x] += 1

    print(*ans)

solve()
```解決策は以下を中心に展開します`process`関数。 各グループには 1 つの攻撃ラインを共有する女王が含まれています。 タプルは次のように保存されます。```
(position_along_line, queen_index)
```ソート後、連続するクイーンはそのラインに沿って直接の隣接者になります。 隣接するペアごとに、両方のクイーンが 1 回の攻撃を獲得します。 

すべてのクイーンの動きは線形であるため、同じロジックが行、列、および両方の対角線に対して機能します。 唯一の違いは、グループの形成方法です。 

使用する`r - c`この値は常に一定であるため、1 つの対角方向を識別します。`\`対角線。 使用する`r + c`値が一定のままであるため、他の対角方向を識別します。`/`対角線。 

実装の微妙な詳細は、すべての隣接するペアの両方のエンドポイントをインクリメントすることです。 ここではクイーンの攻撃が対称的になります。 もし`A`見えます`B`、 それから`B`も見ます`A`反対方向から。 

もう 1 つの簡単な間違いは、対角線を間違って並べ替えることです。 固定対角線に沿って行で並べ替えると、列でも自動的に並べ替えられるため、単一の座標で十分です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m log m) | すべての女王は 4 つのグループ内の分類に参加します。 
| スペース | O(m) | ハッシュ マップと攻撃カウンターは、すべてのクイーンを構造ごとに 1 回保存します。 

保存されるデータの総量はクイーンの数に比例します。 並べ替えが実行時間の大半を占めます。 すべてのグループのサイズの合計は`m`、総仕分けコストは残ります`O(m log m)`の制限に簡単に適合します。`10^5`女王たち。

 ## 特殊なケース

 ブロックを使用して同じ行に複数のクイーンがあるとします。```
5 3
2 1
2 3
2 5
```行グループは次のようになります。```
[(1,A), (3,B), (5,C)]
```アルゴリズムは隣接するペアを処理します。 

-`A-B`-`B-C`決して繋がらない`A-C`ソート後に隣接していないためです。 結果として得られる攻撃数は次のとおりです。```
A = 1
B = 2
C = 1
```それは正しいです。 

次に、対斜め攻撃を考えてみましょう。```
5 2
1 5
3 3
```両方の女王は次のことを満たします。```
r + c = 6
```したがって、彼らは同じように入力します`diag2`グループ。 ソート後、それらは隣接し、両方とも 1 回の攻撃を獲得します。 最終的な出力は次のとおりです。```
0 2 0 0 0 0 0 0 0
```これにより、両方の対角方向が独立して処理されることが確認されます。 

最後に、対角線を共有しているもののブロックされているクイーンについて考えてみましょう。```
6 3
1 1
3 3
5 5
```ソートされた対角グループは次のようになります。```
[(1,A), (3,B), (5,C)]
```隣接するペアのみが寄与します。 

-`A-B`-`B-C`女王たち`A`そして`C`決してお互いを攻撃しないので、`B`道を塞いでしまう。 カウントは次のようになります。```
1 2 1
```実際のチェスの動きと正確に一致します。
