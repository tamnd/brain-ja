 ## 解決策
 ## 問題の理解

 長さの文字列が与えられます$n$文字0、1、?と整数で構成されます。$k$それは均等です。 私たちの目標は、? を置き換えることです。 0 または 1 の文字を使用して、長さのすべての部分文字列が$k$正確に含まれています$k/2$ゼロと$k/2$もの。 つまり、文字列は次のようにする必要があります。$k$-バランスのとれた。 

入力は複数のテスト ケースで構成され、それぞれが指定します$n$、$k$、および文字列$s$。 を形成できる場合、各テスト ケースの出力は YES になります。$k$- ? を置き換えてバランスの取れた文字列を作成し、それが不可能な場合は NO にします。 

制約が示すのは、$n$テスト ケースごとに 300,000 に達する可能性があり、合計は$n$すべてのテスト ケースの数は最大 300,000 です。 これにより、すべての部分文字列を明示的に反復するソリューションは除外されます。$O(nk)$このような部分文字列は最大で$10^{11}$操作。 に関して線形または線形算術的アプローチが必要です。$n$。 

部分文字列の重複する性質から、微妙なエッジ ケースが発生します。 考慮する$s = "1?0"$と$k=2$。 インデックス 0 で始まる部分文字列には 1 と 0 が 1 つずつ含まれている必要があり、インデックス 1 で始まる部分文字列にも 1 と 0 が 1 つずつ含まれている必要があります。 重複する部分文字列の競合をチェックせずに、1 つの部分文字列を貪欲に実行します。 ? にどの値を選択しても、他の部分文字列がバランスに違反するため、正解は NO です。 これは、位置を法的に推論する必要があることを示しています。$k$、独立してではありません。 

もう 1 つの特殊なケースは、すべての文字が ? である場合です。たとえば、$s = "???"$と$k=2$。 この場合、パターンが法を一貫して繰り返すことができる場合にのみ、解決策が存在します。$k$。 

## アプローチ

 ブルートフォースソリューションでは、長さのすべての部分文字列を反復処理します。$k$、0 と 1 を数えて、? の可能な組み合わせをすべて試してください。 これは原理的には正しいですが、$n$300,000 まではパフォーマンスが向上します$O(nk)$動作が遅すぎます。 

重要な観察は、各位置のモジュロが$k$インデックスで始まるすべての部分文字列に影響します$i, i+k, i+2k,\dots$。 したがって、合同なモジュロであるすべての位置は、$k$競合を避けるために、一貫して割り当てる必要があります。 たとえば、位置 0 のモジュロの場合、$k$1 つの部分文字列では強制的に 1 になりますが、他の重複する部分文字列では 0 にすることはできません。 これにより、長さの配列を埋める問題が軽減されます。$k$ここで、各エントリは 0、1、または ? です。 既知の位置を埋めた後は、これらの位置の 0 と 1 の数を確認するだけで済みます。$k$ポジションは超えない$k/2$。 もしそうなら、それは不可能です。 それ以外の場合、残りの ? カウントのバランスをとるために任意に割り当てることができます。 

この観察により、潜在的に$O(nk)$問題に入る$O(n)$、文字列を 1 回反復処理して制約をモジュロ位置に伝播するためです。$k$、カウントを検証します。 各モジュロ クラスの制約によって、実現可能性が完全に決まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nk) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`pattern`長さの`k`各モジュロ位置の強制値を保存します。 最初は、各エントリは ? です。 
2. 各文字を反復処理します。`s[i]`文字列の中で。 もし`s[i]`0 または 1 の場合、この値を次の値に伝播します。`pattern[i % k]`。 もし`pattern[i % k]`すでに異なる値が含まれている場合、競合が存在するため NO を出力します。 
3. すべての文字を処理した後、文字内の 0 と 1 の数を数えます。`pattern`。 どちらかのカウントを超えた場合`k/2`残りの ? を割り当てることができないため、NO を出力します。 バランスをとるために。 
4. それ以外の場合は、YES を出力します。 

なぜ機能するのか: 配列`pattern`位置に対するすべての強制割り当てをモジュロでエンコードします`k`。 これらの割り当てに一貫性があり、0 と 1 の数が以下の場合`k/2`、残りの ? は自由に埋めることができます。 完全にバランスのとれた長さの部分文字列を実現する`k`あらゆる位置で。 長さの各部分文字列`k`はパターンによって決定されるため、グローバル文字列は次のように保証されます。$k$-バランスのとれた。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    s = input().strip()
    pattern = ['?'] * k
    possible = True

    for i in range(n):
        if s[i] != '?':
            if pattern[i % k] == '?':
                pattern[i % k] = s[i]
            elif pattern[i % k] != s[i]:
                possible = False
                break

    if not possible:
        print("NO")
        continue

    zeros = pattern.count('0')
    ones = pattern.count('1')
    if zeros > k // 2 or ones > k // 2:
        print("NO")
    else:
        print("YES")
```解決策は最初にモジュロを構築します。`k`既知の値を伝播することによってパターンを作成します。 競合はすぐに検出されます。 パターン内の 0 と 1 を数えることで、残りの ? を埋めることが可能かどうかを判断できます。 各部分文字列のバランスをとります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        pattern = ['?'] * k
        possible = True

        for i in range(n):
            if s[i] != '?':
                if pattern[i % k] == '?':
                    pattern[i % k] = s[i]
                elif pattern[i % k] != s[i]:
                    possible = False
                    break
        if not possible:
            output.append("NO")
            continue
        zeros = pattern.count('0')
        ones = pattern.count('1')
        if zeros > k // 2 or ones > k // 2:
            output.append("NO")
        else:
            output.append("YES")
    return "\n".join(output)
