 ## 解決策
 ## 問題の理解

 立方根に関連付けられた特定の割り算ルールを満たす、多くの大きな間隔内の整数を数えるように求められます。 任意の正の整数の場合$x$、計算します$k = \lfloor \sqrt[3]{x} \rfloor$、そして私たちは呼び出します$x$で割り切れる場合に有効です$k$。 各クエリは範囲を指定します$[l, r]$、その範囲内に有効な整数がいくつあるかを数えなければなりません。 

主な問題点は、クエリの数と範囲境界の両方が非常に大きいことです。 まで$10^5$最大のクエリと値$10^{18}$、各数値を個別にチェックする解決策は直ちに不可能になります。 単一のサイズ範囲を反復しても$10^{12}$それ以上は問題外であるため、ソリューションでは番号ごとの検査を完全に回避する必要があります。 

小さな値からは、立方根フロアが予期せぬ動作をする微妙なエッジ ケースが発生します。 たとえば、次のようなとき$x = 1$、 我々は持っています$k = 1$, したがって、すべての数値が有効です。 で$x = 7$、$k = 1$はまだ成り立つので、以下のすべての数字は$7$有効です。 という素朴な仮定$k \ge 2$「大きな」数値は、これらの小さな範囲での正確性を損なう可能性があります。 

もう 1 つの注意が必要な状況は、キューブの境界付近です。 もし$x$が完全な立方体の直下または上にある場合、の値は$k$これは、割り算条件が立方根区間にわたって区分的に一定であることを意味します。 正しいソリューションは、このセグメンテーションを尊重する必要があります。 

## アプローチ

 ブルートフォース手法では、次のすべての数値の立方根の下限を計算します。$[l, r]$、割り算をチェックし、有効な値を数えます。 これは正しいですが、まったく実行不可能です。 最悪の場合の範囲サイズは次のとおりです。$10^{18}$そのため、単一のクエリでも多くの操作が必要になる可能性があります。 

重要な観察は次のとおりです$\lfloor \sqrt[3]{x} \rfloor$は長い間隔にわたって一定です。 具体的には、固定整数の場合$k$、立方根の下限は次の値に等しい$k$まさに全員にとって$x$で：$$k^3 \le x < (k+1)^3$$この区間内では、条件は均一になります。つまり、次で割り切れる数を数えるだけで済みます。$k$連続したセグメント内。 これにより、問題は立方根バケットからの寄与の合計に変換されます。 

固定の場合$k$の倍数を数えます$k$交差点で：$$[\max(l, k^3), \min(r, (k+1)^3 - 1)]$$そのカウントは、等差数列境界を使用して O(1) で計算できます。 以来$k^3$急速に成長し、$k$程度までしか範囲がありません$10^6$したがって、関連するすべてのキューブルート バケットを安全に反復処理できます。 

これにより、各クエリが線形から減少します。$r-l$おおよそに$O(\sqrt[3]{r})$、制約を考慮すると十分に高速です。

 ## アルゴリズムのチュートリアル

 各クエリを個別に処理し、立方根間隔をスキャンしてその答えを計算します。 

1. 特定の範囲について$[l, r]$、すべての整数を反復処理します$k$そのような$k^3 \le r$。 考慮する必要があるのは、キューブ ルート バケットがクエリ範囲と交差する値だけです。 これにより、無関係な領域を決して検査しないことが保証されます。 
2. それぞれについて$k$では、バケット間隔を定義します。$$L = k^3, \quad R = (k+1)^3 - 1$$これをクエリ範囲と交差させます。$$lo = \max(l, L), \quad hi = \min(r, R)$$もし$lo > hi$、このバケットは何も貢献しません。 
3. このバケット内では、すべての数値の立方根の下限は正確に次のようになります。$k$なので、次の倍数を数えるだけで済みます。$k$寝そべる$[lo, hi]$。 これは次のように計算されます。$$\left\lfloor \frac{hi}{k} \right\rfloor - \left\lfloor \frac{lo - 1}{k} \right\rfloor$$4. この貢献をクエリに対する回答に蓄積します。 
5. 有効なすべてについて繰り返します$k$そして最終的な合計を出力します。 

### なぜ効果があるのか

 すべての整数$x$によって定義された 1 つのキューブ ルート バケットにのみ属します。$k = \lfloor \sqrt[3]{x} \rfloor$。 そのバケット内では、条件で使用される除数は固定されています。 クエリ範囲と交差するすべてのバケットを列挙し、有効な倍数をバケットごとに 1 回だけカウントするため、有効な数値はすべて 1 回だけカウントされ、無効な数値は含まれません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cube(k):
    return k * k * k

def solve(l, r):
    ans = 0
    k = 1
    while True:
        L = cube(k)
        if L > r:
            break
        R = cube(k + 1) - 1

        lo = max(l, L)
        hi = min(r, R)

        if lo <= hi:
            ans += hi // k - (lo - 1) // k

        k += 1

    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        l, r = map(int, input().split())
        out.append(str(solve(l, r)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```このコードは、キューブ ルート バケット化戦略に直接準拠しています。 機能`solve`有効な範囲を反復します$k$値を取得し、バケットごとの寄与を計算します。 キューブの境界は整数演算を使用して計算されるため、浮動小数点の精度の問題が回避されます。 終了条件`L > r`キューブ間隔がクエリ範囲を超えて開始されるとすぐに停止します。 

よくある落とし穴は、倍数を数える前にバケットの交差部分をクランプするのを忘れることです。 それなし`lo`そして`hi`を実行すると、除数のカウントにクエリ範囲外の数値が誤って含まれてしまいます。

 のために$k=1$、すべての数値は 1 で割り切れ、7 つの値が得られます。 のために$k=2$, 8 ～ 20 の間の 2 の倍数は 8、10、12、14、16、18 となり、6 つの値が得られます。 合計は13です。

 ## 特殊なケース

 入力用$[1, 1]$、アルゴリズムは次から始まります$k=1$、バケットを計算します$[1, 7]$と交差し、$[1, 1]$。 貢献度は、$1 // 1 - 0 // 1 = 1$、それは正しいです。 

のために$[7, 9]$、関連するバケットが 2 つあります。 のために$k=1$、バケツ$[1,7]$数字の 7 のみが寄与します。$k=2$、バケツ$[8,26]$どちらも 2 で割り切れるため、8 と 9 が寄与します。アルゴリズムは、寄与を立方体の境界を越えて正しく分割し、各数値が正確に 1 つの立方根区間に属するため、二重カウントを回避します。 

これにより、範囲がキューブの境界をまたいでいる場合でも、バケットのパーティション分割が一貫していることが確認されます。
