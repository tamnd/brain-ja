 ## 解決策
 ## 問題の理解

 すべての位置に最初に値 1 が含まれる無限配列から始めます。配列は毎秒、そのプレフィックス合計バージョンに置き換えられます。これは、位置 i の値が、前の配列の位置 1 から i までのすべての値の合計になることを意味します。 1 回の操作の後、配列は増加する累積合計のシーケンスになり、k 回の操作の後、この変換は k 回適用されます。 

仕事は複数の質問に答えることです。 各クエリは位置 n と変換数 k を与え、k 回の接頭辞合計演算の後のインデックス n の値を法で計算する必要があります。$10^9 + 7$。 

この制約により、総当たり攻撃は即座に不可能になります。 たとえnが最大であっても$10^5$、kも最大です$10^5$、まであります$10^5$テストケース。 クエリごとにプレフィックス合計を繰り返しシミュレートするには、$O(nk)$最悪の場合のテスト ケースごとの作業量は、実現可能な限界をはるかに超えています。 

それほど明らかではない問題は、配列は概念的には無限ですが、各クエリで重要なのは最初の n 要素だけであることです。 必要以上に具体化しようとするアプローチは、構造を活用しない限り、依然として不必要なオーバーヘッドのリスクを伴います。 

単純な実装では、プレフィックス合計の再計算が繰り返されるため、通知なく失敗する可能性もあります。 たとえば、単一の n=100000 の場合に k=1000 の変換を計算するだけでも、各変換自体は線形であるため、すでに大きすぎます。 

## アプローチ

 ブルート フォース手法では、プレフィックス合計演算が k 回適用されます。 各操作では配列がスキャンされ、新しい配列が構築されます。 これは定義に直接従うため正しいですが、クエリごとに O(nk) のコストがかかります。 n と k が両方とも大きく、t が最大の場合$10^5$、これは天文学的な規模になります。 

重要な観察は、プレフィックスの合計が繰り返されると、よく知られた組み合わせ構造が生成されるということです。 1 回の操作の後、インデックス n の値は n と等しくなります。 2回の演算の後、1からnまでの合計が三角数になります。$\binom{n+1}{2}$。 3 回の演算を行うと、三角数の和になります。$\binom{n+2}{3}$。 このパターンは一般化します: k 回の操作の後、インデックス n の値は二項係数と等しくなります$\binom{n+k-1}{k}$。 

これは、各プレフィックス合計層が 1 レベルの合計を追加し、定数シーケンスの繰り返し合計がパスカルの三角形構造を構築するために発生します。 各位置は、n+k-1 位置の中から k 個のインデックスを選択する組み合わせに正確に対応する寄与を蓄積します。 

これにより、各クエリが k 回繰り返される配列変換ではなく、単一の組み合わせ計算に変換されます。 

階乗とモジュラー逆関数を最大で事前計算します。$n+k$、O(1) の各クエリに答えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとに O(nk) | O(n) | 遅すぎる |
 | 最適 | O(n + max(n+k)) 前処理、クエリごとに O(1) | O(最大(n+k)) | 承認済み |

 ## アルゴリズムのチュートリアル

 k 個のプレフィックス合計演算の後、インデックス n の値は次のようになるというアイデンティティに依存します。$$a_k(n) = \binom{n + k - 1}{k}$$1. すべてのクエリにわたる n+k の最大値を決定します。 これが必要なのは、階乗事前計算がクエリで使用される最大の二項パラメータをカバーする必要があるためです。 
2. この最大値を法とする階乗を事前計算します。$10^9 + 7$。 これにより、組み合わせの高速な計算が可能になります。 
3. フェルマーの小定理を使用して階乗のモジュラー逆関数を事前計算します。 これが必要なのは、剰余算術における除算が逆階乗による乗算に置き換えられるためです。 
4. 各クエリ (n, k) に対して、二項係数を計算します。$\binom{n+k-1}{k}$使用:$$\frac{(n+k-1)!}{k!(n-1)!}$$5. 結果のモジュロを出力します$10^9 + 7$。 

これが有効である理由は、各プレフィックス和レイヤーが 1 次元の累積加算に対応しており、繰り返される累積和の構造がパスカルの三角形と正確に一致するためです。 各エントリは、位置 n で終わる長さ k の弱く増加するシーケンスの数をカウントします。これはまさに上記の二項係数です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def build_fact(n):
    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD
    invfact[n] = modinv(fact[n])
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD
    return fact, invfact

def ncr(n, r, fact, invfact):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

def main():
    t = int(input())
    queries = []
    maxv = 0

    for _ in range(t):
        n, k = map(int, input().split())
        queries.append((n, k))
        maxv = max(maxv, n + k)

    fact, invfact = build_fact(maxv)

    for n, k in queries:
        ans = ncr(n + k - 1, k, fact, invfact)
        print(ans)

if __name__ == "__main__":
    main()
```階乗配列には、組み合わせを迅速に計算するために必要な値が格納されます。 逆階乗配列では、除算を乗算に変えることにより、モジュロでの除算が可能になります。 

重要な実装の詳細は次のとおりです。$n+k-1$二項係数の最上位として。 よくある間違いは、シフトを忘れて使用することです。$\binom{n+k}{k}$、これは Pascal 構造体の 1 つの完全な層だけオーバーカウントします。 

また、クエリごとに累乗剰余演算が繰り返されることを避けるために、逆方向パスで逆関数を事前計算します。これは遅すぎます。$10^5$クエリ。 

## 実用的な例

 | --- | --- |
 | n+k-1 を計算する | 5 |

 これは、既知の 2 番目のプレフィックスサム変換シーケンス 1、3、6、10 と一致します。 

ここで、n = 3、k = 1 について考えてみましょう。$$\binom{3}{1} = 3$$| ステップ | 式 |

 これは、配列が 1、2、3、... になる最初の変換と一致します。 

これらの例は、プレフィックス合計の k 層が二項係数の増加に正確に対応することを確認します。

import sys, io

MOD = 10**9 + 7

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def modinv(x):
        return pow(x, MOD - 2, MOD)

    def build_fact(n):
        fact = [1] * (n + 1)
        invfact = [1] * (n + 1)
        for i in range(1, n + 1):
            fact[i] = fact[i - 1] * i % MOD
        invfact[n] = modinv(fact[n])
        for i in range(n, 0, -1):
            invfact[i - 1] = invfact[i] * i % MOD
        return fact, invfact

    def ncr(n, r, fact, invfact):
        if r < 0 or r > n:
            return 0
        return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

    t = int(input())
    qs = []
    mx = 0
    for _ in range(t):
        n, k = map(int, input().split())
        qs.append((n, k))
        mx = max(mx, n + k)

    fact, invfact = build_fact(mx)

    out = []
    for n, k in qs:
        out.append(str(ncr(n + k - 1, k, fact, invfact)))
    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは k = 0 であり、変換は行われません。 式は次のようになります$\binom{n-1}{0} = 1$これは、配列がすべて 1 のままであることを正しく反映しています。 

もう 1 つのエッジ ケースは、n = 1 です。k に関係なく、プレフィックス合計配列の最初の要素は決して変更されないため、答えは常に 1 でなければなりません。 式は次のようになります$\binom{k}{k} = 1$、この不変式と正確に一致します。 

3 番目のエッジ ケースは、n が大きく、k が小さい場合です。 たとえば、n = 100000、k = 1 の場合、次のようになります。$\binom{100000}{1} = 100000$、これは、線形増加を生み出す単一のプレフィックス合計の定義と一致します。
