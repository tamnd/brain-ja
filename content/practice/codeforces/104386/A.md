 ## 解決策
 ## 問題の理解

 いくつかの独立したダンジョンの実行が与えられます。 各ランは一連のレベルで構成されており、各レベルで選択する必要があるのは 1 つだけです。レベルをクリアしてそこに書かれた値を獲得するか、連続するレベルのブロックをスキップしてスキップしたレベルの数に等しいペナルティを支払うかのどちらかです。 

重要な点は、「スキップ」が通常のように単一レベルの決定に関連付けられていないことです。 これは、任意の位置から適用できるセグメント操作であり、一度に複数のレベルをカバーします。 スキップしている間も概念的にはそれらのレベルを超えて移動しますが、基礎となる値が何であったかに関係なく、スキップされたレベルごとに 1 ポイントを失います。 

したがって、タスクは、「個別に解決」と「全体としてスキップ」の交互のセグメントへの配列の分割を決定することです。スキップされたセグメントは、その長さに等しい線形の負のコストに寄与し、解決された位置は独自の値に寄与します。 

出力は、達成可能な最大合計スコアです。 

制約が非常に厳しいため、部分配列に対する 2 次または 3 次の推論は失敗します。 テスト ケース全体のレベルの合計数は最大 200,000 であるため、テスト ケースごとに線形またはほぼ線形のアプローチが必要です。 すべてのセグメント境界を試行したり、インデックスのペアに対して動的プログラミングを実行したりすると、時間がかかりすぎます。 

よくある失敗例は、スキップ操作がセグメントごとにグローバルではなく、インデックスごとにローカルなものであると誤解することに起因します。 たとえば、インデックス i でのスキップが i にのみ影響すると仮定すると、答えは単に正の値の合計であると誤って結論付ける可能性があります。これは、長い負の実行をグループとしてスキップして利益を得ることができる場合には誤りです。 

もう 1 つの微妙なケースは、すべての値が負の場合です。 単純な解決策では、すべてをスキップすることが最適であると考えるかもしれませんが、スキップすると長さに等しいコストが発生し、それでも合計が負になるため、場合によっては負の最も小さい要素を 1 つ選択する方が良い場合があります。 

## アプローチ

 ブルート フォース解釈では、セグメントごとに、セグメントを個別のソルブに分割するか、スキップ操作に置き換えるかを決定しようとします。 これにより、配列のすべてのパーティションがセグメントに分割され、各セグメントのモードが決定されます。 i と i+1 の間のすべての境界はカットされるかカットされないかのいずれかであり、各セグメントにも 2 番目の決定があるため、このようなパーティションの数は n に応じて指数関数的に増加します。 枝刈りを行ったとしても、非常に小さい n を超えると、これはすぐに実行不可能になります。 

重要な観察は、長さ L のセグメントをスキップすることは、そのセグメント内の要素ごとに -1 の一定コストを追加することと同じであるということです。 これにより、スキップ操作が個々の位置に分散可能になります。つまり、実際にはセグメントについて推論する必要がまったくありません。 すべての位置 i は、それを解決する場合は a_i に寄与し、スキップ セグメントの一部としてスキップすることを選択した場合は -1 に寄与します。 

これがわかると、構造は大幅に単純化されます。 各インデックスは独立して、2 つの固定値 (a_i を取るか -1 を取る) の間の選択に影響します。 スキップされた位置をグループ化しても、合計コストは個別に処理する場合と同じになるため、スキップのセグメントの性質は無関係になります。 

したがって、問題は要素ごとの最大値の選択に帰着します。つまり、各 i に対して max(a_i, -1) を選択します。 これらの選択を合計すると、全体的な最適値が得られます。

 | --- | --- | --- | --- |
 | セグメント パーティションに対するブルート フォース | 指数 | O(n) | 遅すぎる |
 | 要素ごとの貪欲な選択 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各テスト ケースについて、レベル報酬を表す値の配列を読み取ります。 目標は、ポジションごとの独立した決定の下で、達成可能な最高の合計スコアを計算することです。 
2. アキュムレータをゼロに初期化します。 この変数には、各レベルからの最適な寄与を合計することによって最終スコアが保存されます。 
3. 配列内の各値 a_i を反復処理します。 この時点で、有効な戦略でこのポジションを処理できる 2 つの方法を検討します。 
4. レベルの解決への寄与 (a_i) を計算します。 
5. 効果的にスキップした場合の寄与を計算します。これは、レベル コストごとに -1 です。 
6. これら 2 つの値のうち大きい方をアキュムレータに加算します。 このステップは、スキップ コストがグループ構造に依存しないため、グローバル最適戦略は各位置でより良いオプションをローカルに選択する必要があるという事実を捉えています。 
7. すべての位置を処理した後、テスト ケースの答えとしてアキュムレータを出力します。 

### なぜ効果があるのか

 重要な特性は、スキップ操作が位置にわたって加算的に分解されることです。 長さ L のスキップされたセグメントは、内部でどのように分割されているかに関係なく、正確に -L に寄与します。 これにより、異なるインデックスでの決定間の依存関係が削除されます。 依存関係が解消されると、最適なグローバル ソリューションは独立して最適なローカル決定で構成されなければなりません。これは、ある立場の選択を変更しても他の立場の貢献に影響を与えることができないためです。 これでは、意思決定をセグメントに結合する利点が失われます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ans = 0
        for x in a:
            if x > -1:
                ans += x
            else:
                ans += -1
        
        print(ans)

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを独立して処理します。これは、テスト ケース間に相互作用がないために必要です。 各テスト ケース内で、配列を 1 回反復し、各要素で単純な比較を適用します。 

重要な実装の詳細は、-1 とのしきい値の比較です。 -1 より大きい値は直接取得する価値がありますが、それ以下の値はスキップに相当するコストに置き換える方が適切です。 これにより、セグメント追跡や動的プログラミングの必要がなくなります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ans = 0
        for x in a:
            ans += x if x > -1 else -1
        out.append(str(ans))
    return "\n".join(out)

# provided samples (as interpreted)
assert run("4\n5\n-1 -1 -1 2 -1\n5\n3 5 6 2 -1000000000\n2\n-1000000000 1\n3\n1 1 1") == "-2\n15\n-1\n3"

# all negative
assert run("1\n3\n-5 -2 -3") == "-3"

# all positive
assert run("1\n4\n1 2 3 4") == "10"

# mix
assert run("1\n5\n-1 10 -5 2 -1") == "12"

# single element
assert run("1\n1\n-1000000000") == "-1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべて否定的 | -3 | スキップが優勢ですが、依然として要素ごとに -1 のコストがかかります。 
| すべて肯定的 | 10 | 常に値を取る |
 | 混合値 | 12 | ローカル選択動作 |

 ## 特殊なケース

 次のような完全な負の配列`[-5, -2, -3]`スキップしても要素ごとに -1 が蓄積されるため、アルゴリズムがすべてをスキップして「エスケープ」しようとしないことを示しています。 計算は -1 との 3 つの比較となり、各位置に -1 が生成され、最終的な合計は -3 になります。 

次のような完全に正の配列`[1, 2, 3, 4]`は、それぞれの値が -1 より大きいため、アルゴリズムが常に実際の値を選択することを示しています。 累計は配列の合計となり、直感的な最適戦略と一致します。 

次のような混合ケース`[ -1, 10, -5, 2, -1 ]`は、-1 以下の要素のみが -1 に置き換えられ、強いポジティブはそのまま維持され、最終結果は結合効果なしで位置ごとの独立した決定を反映することを示しています。
