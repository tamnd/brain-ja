 ## 解決策
 ## 問題の理解

 各子供はちょうど 1 冊の本から始めて、毎日すべての本が固定された順列に従って同時に渡されます。 子供 i が自分の本を p[i] に渡すと、1 日後に本はこの有向辺に沿って 1 歩進みます。 2 日後、順列に沿って 2 ステップ移動し、以下同様です。 

単一の開始本の観点から、同じ順列を繰り返し適用しています。 各開始位置 i に対する質問は、順列を何回適用した後、i から始まった本が初めて i に戻るかということです。 

これは、各ノードが出ていくエッジを 1 つだけ持つ有向グラフのノード i を含むサイクルの長さを求めるのと同じです。 p は順列であるため、グラフはサイクルの素結合になります。 

制約は小さく、n は最大 200、クエリは最大 200 です。 これにより、テスト ケースごとに O(n²) または O(n³) のアプローチでも安全であることがすぐにわかります。 単純なトラバースとマーキングを超える大規模な最適化やデータ構造は必要ありません。 

微妙なエッジ ケースは、ノードがそれ自体にマップされる場合、つまり p[i] = i を意味します。 この場合、サイクルの長さは 1 で、答えは 1 でなければなりません。もう 1 つのケースは、完全なサイクルが完了するまでノードが繰り返されない長いサイクルです。たとえば、すべてのノードが同じ答え 5 を共有する 2 3 4 5 1 のような順列です。ノードごとに毎日の動きを個別にシミュレートしようとする間違ったソリューションは、小さな制約のためここでも機能する可能性がありますが、非効率または冗長な再計算のリスクがあります。 

## アプローチ

 直接的なシミュレーション アプローチでは、各開始インデックス i を取得し、i に戻るまで順列を繰り返し適用し、途中のステップをカウントします。 各ステップはブック パッシングのルールに正確に従っているため、これは正しいことです。 ただし、最悪のケースでは、長さ n の単一サイクルにより開始ノードごとに O(n) ステップが強制され、テスト ケースごとに O(n²) になります。 n を 200 まで、q を 200 までにしても、これは依然として快適に通過します (最悪の場合、約 800 万回の操作) が、サイクル内のすべてのノードが同じ走査を再計算するため、作業が頻繁に繰り返されます。 

重要な構造的洞察は、順列が互いに素なサイクルに分解されるということです。 同じサイクル内のすべてのノードは、サイクル長に等しい同じ戻り時間を共有します。 個別にシミュレーションする代わりに、各サイクルを 1 回走査し、そのサイズを計算し、そのサイズをその中のすべてのノードに割り当てます。 これにより、冗長な作業が削減され、ソリューションがクリーンなグラフ走査問題に変わります。 

すべてのノードを反復処理し、未訪問のノードに遭遇するたびにウォークを開始することで、サイクルを見つけることができます。 p[i]、p[p[i]] などを開始点に戻るまでたどり、そのループ内のノードの数を数えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | クエリあたり O(n²) | O(1) おまけ | 承認済み |
 | サイクル分解 | クエリごとに O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各クエリを個別に処理し、回答配列を構築します。 

1. false に初期化されたサイズ n の訪問済み配列と、ゼロに初期化された回答配列を維持します。 訪問された配列により、同じサイクルが複数回処理されないことが保証されます。 
2. 各ノード i を 1 から n まで繰り返します。 i がすでに訪問されている場合は、すでに処理されたサイクルに属しているため、スキップします。 
3. 未訪問のノード i を見つけると、i から始まるサイクルのトラバースを開始します。 開始ノードを保存し、p[current] を使用して順列を繰り返し移動します。 
4. トラバース中に、現在のサイクル内のすべてのノードをリストに収集し、それらを訪問済みとしてマークします。 また、開始ノードに戻るまでの歩数もカウントします。 
5. サイクルを終了すると (再び開始点に到達します)、計算されたサイクル長を収集されたリスト内のすべてのノードに割り当てます。

オンザフライで割り当てるのではなく明示的にノードを収集する理由は、走査の完了後にのみサイクル長がわかるからです。 

### なぜ効果があるのか

 順列内のすべてのノードは、正確に 1 つの有向サイクルに属します。 グラフは有限であり、各ノードには出力エッジが 1 つだけあるため、未訪問のノードからのトラバースは決定論的なエッジに従い、最終的には開始ノードに戻らなければなりません。 これにより、各トラバースが分岐や曖昧さのない完全なサイクルを発見することが保証されます。 答えは最初の戻り時間 (正確にサイクル長) として定義されるため、そのコンポーネント内のすべてのノードにサイクル サイズを割り当てることは正しいことになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

q = int(input())
for _ in range(q):
    n = int(input())
    p = [0] + list(map(int, input().split()))
    
    visited = [False] * (n + 1)
    ans = [0] * (n + 1)
    
    for i in range(1, n + 1):
        if visited[i]:
            continue
        
        cycle = []
        cur = i
        
        while not visited[cur]:
            visited[cur] = True
            cycle.append(cur)
            cur = p[cur]
        
        length = len(cycle)
        for v in cycle:
            ans[v] = length
    
    print(*ans[1:])
```この解決策は、順列を明示的にサイクルに分解することで機能します。 1 インデックスにより、入力からグラフ ノードへの直接マッピングが簡素化されます。 各ノードは 1 回だけ訪問されるため、走査コストはクエリごとに線形です。 

一般的な実装の落とし穴は、サイクル内の次のノードに移動する前にノードを訪問済みとしてマークするのを忘れることです。これにより、誤った実装で無限ループが発生する可能性があります。 もう 1 つの微妙な問題は、自転車ウォークの終了条件を混同していることです。 現在のトラバーサル内で以前に訪問したノードを再訪問することに依存していますが、すべてのノードには出力エッジが 1 つだけあるため、これは安全です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    q = int(input())
    out_lines = []
    for _ in range(q):
        n = int(input())
        p = [0] + list(map(int, input().split()))
        
        visited = [False] * (n + 1)
        ans = [0] * (n + 1)
        
        for i in range(1, n + 1):
            if visited[i]:
                continue
            cycle = []
            cur = i
            while not visited[cur]:
                visited[cur] = True
                cycle.append(cur)
                cur = p[cur]
            for v in cycle:
                ans[v] = len(cycle)
        out_lines.append(" ".join(map(str, ans[1:])))
    
    return "\n".join(out_lines)

 ## 特殊なケース

 p[i] = i などの自己ループは、トラバーサルが 1 回訪問した後すぐに開始ノードに戻り、サイクル長 1 が生成されるため、自然に処理されます。訪問済みのマークにより、無限ループにならずに正しく停止することが保証されます。 

すべてのノードが 1 つのループに接続されている大きなサイクルも、開始ノードに再度アクセスするまでトラバーサルが継続され、割り当て前にサイクルの完全なカバレッジが保証されるため、正しく処理されます。
