 ## 問題の理解

 数直線上の整数間隔の集合が与えられます。 各間隔は、その範囲内のすべての整数点にわたるカバレッジを表します。 ポイントが複数の要素でカバーされている場合、問題が発生します。$k$同時に間隔をあけます。 タスクは、整数点がそれ以上の値でカバーされないように、できるだけ少ない間隔を削除することです。$k$残りのインターバル。 

言い換えれば、すべての整数座標での最大重複が決して超えないように、いくつかの間隔を削除する必要があります。$k$削除する間隔の数を最小限に抑えながら。 

座標範囲は最大 200 と小さく、間隔の数も最大 200 です。これは、ソリューションがすべての整数点にわたるカバレッジを明示的にシミュレートし、依然として効率を維持できることを強く示唆しています。 すべてのセグメントとすべての座標を反復するアプローチはいずれも受け入れられますが、セグメントのサブセットで指数関数的なものは不必要な過剰になります。 

多くの間隔が 1 つの点で完全に重なる場合、微妙なエッジ ケースが発生します。 たとえば、すべての間隔が$[1, 200]$そして$k = 1$の場合、最初の間隔を超えるすべての追加間隔を削除する必要があります。 各ポイントでの現在のオーバーラップを追跡せずにエンドポイントのみを調べる貪欲なソリューションは失敗します。これは、競合がセグメント エンドポイントごとではなく整数座標ごとに定義されるためです。 

もう 1 つの障害モードは、複数のポイントにわたるセグメントの寄与を考慮せずにセグメントを削除することで発生します。 セグメントは、ある座標では無害に見えるかもしれませんが、超過する理由になります。$k$別の座標で。 

## アプローチ

 直接的な総当たりのアイデアは、セグメントのすべてのサブセットを試し、残りのセットが制約を満たすかどうかを確認し、最大サイズのサブセットを選択することです。 各サブセットについて、1 ～ 200 のすべての整数ポイントのカバレッジを計算し、それを超えるポイントがないことを確認します。$k$。 これは、考えられるすべての削除の選択肢を検討するため、正しいです。 

問題はサブセットの数です。$2^n$であっても天文学的に大きくなります。$n = 200$。 たとえサブセットのチェックにコストがかかるだけであっても$O(n \cdot 200)$、合計の作業は完全に実行不可能です。 

重要な構造的観察は、違反が個々の整数点に局所的であるということです。 何かのポイントがあれば$x$以上のものでカバーされています$k$セグメントの場合、カバレッジに寄与するセグメントを削除するだけで済みます。$x$。 これは、各座標での競合を個別に解決する貪欲な戦略を示唆していますが、ある時点での削除によって将来の違反も修正されるように慎重に調整されています。 

ポイントを左から右に処理します。 各ポイントで、それをカバーするアクティブなセグメントのセットを維持します。 アクティブなセグメントの数が超過した場合$k$、それらのいくつかを削除する必要があります。 最適な選択は、最も右に延びるセグメントを削除することです。 この選択により、長いセグメントが今後の多くのポイントに寄与し続けるため、将来の重複が可能な限り積極的に削減されます。 

この貪欲な戦略は、一度ポイントを修正すると機能するため、機能します。$x$、以下を保証します。$k$カバーする間隔$x$残り、最も右の端点との間隔を削除することで、後続の座標に対する将来の「圧力」を最小限に抑えます。

 ## アルゴリズムのチュートリアル

 1. 1 ～ 200 の各整数座標について、現在どのセグメントがカバーしているかを維持します。 制約が小さいため、これを効率的に再計算できます。 
2. 各座標で$x$をカバーするすべてのセグメントを収集します。$x$そしてまだ削除されていません。 このセットは、この時点での現在のオーバーラップを表します。 
3. アクティブなセグメントの数が$x$せいぜい$k$、制約はすでに満たされているため、次の座標に移動します。 
4. 以上の場合$k$アクティブなセグメントがある場合は、それらの一部を削除する必要があります。 将来の競合を最小限に抑えるには、最大の正しいエンドポイントを持つセグメントを選択します。 正確に十分なセグメントを削除して、$k$でアクティブなままにする$x$。 
5. 削除されたセグメントをグローバルにマークし、今後のすべての座標で無視されるようにします。 
6. 200 までのすべての座標に対してこのプロセスを続けます。 

なぜ機能するのか: どの座標でも$x$、それ以上の場合$k$間隔がカバーされている場合は、少なくとも 1 つを削除する必要があります。 最大の右エンドポイントの間隔を削除すると、将来のカバレッジに最も寄与する間隔が削除されるため、安全です。 より長い間隔を維持しながらより短い間隔を破棄する代替の削除は、将来の実現可能性を向上させることはできず、後の競合を増加させるだけである可能性があります。 この局所的に最適な修正を各座標で繰り返すことで、すべてのポイントが無効になるとすぐに修復されます。また、間隔を削除するだけで追加はしないため、削除によって以前のポイントに違反が再導入されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    seg = [None] * n

    for i in range(n):
        l, r = map(int, input().split())
        seg[i] = (l, r)

    removed = [False] * n

    for x in range(1, 201):
        active = []
        for i, (l, r) in enumerate(seg):
            if not removed[i] and l <= x <= r:
                active.append(i)

        if len(active) <= k:
            continue

        active.sort(key=lambda i: seg[i][1], reverse=True)

        for j in range(len(active) - k):
            removed[active[j]] = True

    ans = [i + 1 for i in range(n) if removed[i]]
    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```このソリューションは、各整数座標でのカバレッジを明示的にシミュレートします。 ポイントごとに、現在アクティブなセグメントのリストを作成し、余分なセグメントを削除することで制約を適用します。 正しいエンドポイントでソートすると、将来の座標に影響を与え続けるセグメントを確実に削除できます。これが中心的な貪欲な選択です。 

実装の微妙な詳細は、各座標でアクティブなセグメントを最初から再計算することです。 非効率的に見えますが、境界が十分小さいため安全であり、動的な間隔セットを維持する複雑さを回避できます。

 ## 特殊なケース

 すべてのセグメントが一致する場合は、アルゴリズムがすべての点で余分な部分を繰り返しトリミングしていることを示しています。 で$x=1$、すべてのセグメントがアクティブであるため、$k$は保持され、残りは削除済みとしてマークされます。 削除されたセグメントは決して再表示されないため、その後のすべての座標は自動的に有効なままになります。 

重複しない疎な構成は、アルゴリズムが不必要に何も削除しないことを示しています。 各座標でアクティブな数が超過することはありません$k$したがって、削除ブランチはトリガーされず、出力は空のままになります。 

セグメントが互い違いに配置されているものの、隣接するポイント間で継続的に重なり合う最悪の場合のオーバーラップ チェーンでは、貪欲な枝刈りの繰り返しが強制されます。 このアルゴリズムは、最も右のエンドポイントを持つセグメントを一貫して削除し、将来の重複をできるだけ早く減少させ、連鎖的な違反を防止します。
