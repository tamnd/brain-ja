 ## 解決策
 ## 問題の理解

 いくつかの独立したシナリオが与えられています。 各シナリオには、生徒のスキル レベルを表す個別の整数のリストがあります。 目標は、スキルが 1 つだけ異なる 2 人の学生がどのグループにも含まれないように、これらの学生を可能な限り少数のグループに分割することです。 

この制限は非常にローカルです。同じグループ内では、差がちょうど 1 であるペアのみが禁止されます。 他のペアは、その差が大きいか小さい場合でも、1 に等しくない場合でも許可されます。 

このことから、このタスクは、非常に具体的な隣接ルールを使用した整数に関するグループ化の問題になります。 各値を数直線上のノードとして想像すると、すべての値は、そのすぐ隣の値 - 1 および値 + 1 とのみ「競合」します。 

各クエリは小さく、生徒数は最大 100 人で、スキル値も 100 で制限されます。これにより、高度な最適化や高度なデータ構造の必要性が即座に排除されます。 クエリあたり O(n^2) のソリューションでも、十分に高速です。 

素朴なアプローチを誤解させる主なエッジケースは、複数のチェーン間の重複がどのように複数のチームに影響を与えるかを考慮せずに、連続するチェーンのみが重要であると仮定することです。 

たとえば、値について考えてみましょう。`[2, 3, 4]`。 割り当てを交代できるため、必要なチームは 2 つだけであると考えるのが甘い考えかもしれません。 ただし、2 は 3 と競合し、3 は 4 と競合しますが、2 と 4 は問題ないため、正しいグループ化はブリッジとして機能する 3 をどのように割り当てるかによって決まります。 

もう 1 つの微妙なケースは、次のような接続されていないセットです。`[1, 3, 5]`、競合がまったく存在せず、単一のチームで十分です。 

主な困難は、隣接制約によって強制される「競合レイヤー」の数を正確に特定することです。 

## アプローチ

 これについて強引に考える方法は、生徒を 1 人ずつチームに割り当て、制約を尊重しながらあらゆる配置を試みることです。 各学生について、正確に 1 異なるメンバーがいない場合は既存のチームに配置しようとします。そうでない場合は、新しいチームを作成します。 これは貪欲な色付けの試みに似ていますが、バックトラッキングを使用して素朴に実行すると、各割り当てが将来の実現可能性に影響を与えるため、指数関数的な可能性が探求されます。 

構造のない単純な欲張りでも、順序が悪ければ失敗する可能性があります。 たとえば、並べ替えを考慮せずに入力順に挿入すると、不要な新しいチームが作成される可能性があります。 

重要な観察は、制約が隣接する整数値のみに依存するということです。 配列をソートすると、連続するセグメントを通じて数値がどのように相互作用するかを推論できます。 任意の値`x`とのみ競合します`x-1`そして`x+1`。 これは、この問題が、連続する整数の間にのみエッジが存在する線上の数字に色を付けることと同等であることを意味します。 

ここで、必要なチームの数を考えてみましょう。 数値を値ごとにグループ化する場合、複数のチームに分ける必要があるのは、連続する整数のチェーンが存在する場合だけです。 みたいな連続走行の中で`[k, k+1, k+2, ..., k+m]`、各数値は隣接する数値と競合し、パス グラフを形成します。 パス グラフには彩色番号 2 がありますが、グローバルに必要な色は 2 つだけで、複数の独立したパスが重なり合うことがあります。 

これにより、より単純な観点が得られます。つまり、セット内に連続する整数のペアが存在するかどうかだけを知る必要があるということです。 そのようなペアが存在しない場合、すべての値は独立しており、正確に 1 つのチームが必要になります。 このようなペアが少なくとも 1 つ存在する場合は、正確に 2 つのチームが必要になります。これは、値の同等性に沿って代入を交互に行うことで、競合の連鎖が常に 2 色になる可能性があるためです。 

したがって、問題全体は、存在するかどうかを確認することに帰着します。`x`両方とも`x`そして`x+1`が存在します。

 ## アルゴリズムのチュートリアル

 1. クエリのすべての生徒のスキル値を読み取り、メンバーシップを高速にチェックできるようにセットに保存します。 これは、連続する整数が存在するかどうかをチェックするために定数時間の検索が必要なため必要です。 
2. 各値を反復処理します。`x`セット内にあるかどうかを確認してください`x + 1`セットにも存在します。 これは、暗黙的なグラフに少なくとも 1 つの競合エッジがあるかどうかを直接検出します。 
3. そのようなペアが見つかったら`(x, x+1)`、少なくとも 2 つのチームが必要であるとすぐに結論付けられます。 これは、これら 2 つの値がチームを共有できず、接続されたチェーン全体に伝播する分割が強制されるためです。 
4. すべての値をチェックした後、そのようなペアが存在しない場合は、制約はアクティブになっていないため、すべての生徒を 1 つのチームに配置できます。 

### なぜ効果があるのか

 値は、連続する整数の間にのみエッジが存在するグラフを形成します。 このグラフは構造上 2 部構成になっているため、常に最大 2 色が必要です。 1 色で十分な唯一のケースは、エッジがまったくない場合、つまり入力に 2 つの連続する整数が存在しない場合です。 したがって、少なくとも 1 つのエッジの存在を検出することで、答えが 1 か 2 かが完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

q = int(input())
for _ in range(q):
    n = int(input())
    a = list(map(int, input().split()))
    
    s = set(a)
    
    ans = 1
    for x in s:
        if x + 1 in s:
            ans = 2
            break
    
    print(ans)
```このソリューションは、値が存在するかどうかの定時チェックを有効にするセットに依存しています。 セットに対するループにより、一意の値のみを検査することが保証され、たとえ問題ステートメントによる入力に重複が存在しない場合でも、不必要な繰り返し作業が回避されます。 

主要な実装の詳細は早期終了です。答えが 2 を超えることはできないため、隣接するペアが 1 つ見つかるとすぐに停止します。

これらのトレースは、アルゴリズムが誘導グラフにエッジがあるかどうかを効果的に検出していることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    q = int(input())
    out = []
    for _ in range(q):
        n = int(input())
        a = list(map(int, input().split()))
        s = set(a)
        ans = 1
        for x in s:
            if x + 1 in s:
                ans = 2
                break
        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 連続する整数がない入力の場合、次のようになります。`[1, 4, 7]`、アルゴリズムはセットを構築します`{1, 4, 7}`そして何も見つかりません`x`どこ`x+1`存在します。 ループは条件をトリガーせずに終了するため、答えは 1 のままで、制限が存在しないという事実と一致します。 

次のような完全に連続した入力の場合`[5, 6, 7, 8]`、セットには複数の隣接するペアが含まれます。 アルゴリズムが検出するのは、`5-6`すぐに (または反復順序に応じて他のペアで)、答えを 2 に設定して停止します。 これは、チェーンに沿って代入を交互に行う必要性と一致し、構造全体をキャプチャするには 1 回のチェックで十分であることが確認されます。
