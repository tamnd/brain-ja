[CF 1249E - エレベーターまたは階段を使用しますか?](https://codeforces.com/problemset/problem/1249/E)

 **評価:** 1700
 **タグ:** dp、最短パス
 **解決時間:** 5 分 34 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 1 階から n 階までの建物が与えられます。 隣接するフロア間の移動は、階段またはエレベーターの 2 つの方法で行うことができます。 階段には 1 階あたりのコスト a[i] があり、エレベーターには 1 階あたりのコスト b[i] に、エレベーターの乗車を開始するたびに固定諸経費 c がかかります。 

重要な点は、1 回の移動が隣接するフロアに制限されないことです。 任意のフロア x から、階段またはエレベーター モデルを介してすべての中間フロアを通過するコストを支払うことで、1 回の移動で任意のフロア y にジャンプできます。 フロアに到達すると、別の動きを開始でき、場合によってはモードが再び切り替わります。 

このタスクは、フロア i ごとに、フロア 1 から開始して i に到達するまでに必要な最小合計時間を計算することです。 

この構造は基本的に n 個のノード上のグラフであり、フロアのすべてのペアが 2 つの加重パスによって接続されています。1 つのパスは a のプレフィックス合計によって定義され、もう 1 つは b と固定コスト c のプレフィックス合計によって定義されます。 課題は、グラフの説明が緻密であるにもかかわらず、重みが構造化されていることです。 

n が 200000 まで、値が 1000 までという制約は、フロアのペアに対する二次アプローチが不可能であることを意味します。 解は線形またはほぼ線形である必要があり、おそらく O(n) または O(n log n) です。 これは、動的プログラミングまたは 2 状態の最短パスの解釈を強く示唆しています。 

複数の手を検討する場合、微妙な問題が発生します。 単純な想定では、常に階段かエレベーターを使用して 1 階から 1 階に直接移動する必要があると考えられます。 中間スイッチングによりコストが削減されるため、これは不正確です。 

たとえば、エレベーターは早い階は安いが、階段は後で安くなるとします。 単純な直接比較では、中間フロアでモードを切り替えられることは無視されます。 

もう 1 つの特殊なケースは、c が大きい場合です。 したがって、エレベーターは小さなセグメントには決して最適ではありませんが、以前の状態の蓄積と組み合わせると、ロングジャンプには依然として役立つ可能性があります。 

本当の複雑さは、各フロアが最後の移動に階段を使用したかエレベーターを使用したかに応じて 2 つの「モード」で到達できることです。これは、将来のコストが蓄積された利益を通じて暗黙的にその選択に依存するためです。 

## アプローチ

 強引なアプローチでは、これを n ノードの完全なグラフ上の最短経路問題として扱います。 すべてのペア (x, y) について、プレフィックスの合計を使用して O(1) で階段とエレベーターの両方のコストを計算します。 次に、ノード 1 からダイクストラを実行します。 

このグラフには O(n^2) のエッジがあるため、ダイクストラは O(n^2 log n) になります。これは、n が 200000 までの場合は非常に遅すぎます。エッジを保存することさえ不可能です。 

重要な観察は、コスト構造がラインに沿って加算されるため、移行はプレフィックスの違いのみに依存するということです。 さらに重要なことは、エレベーターでは使用ごとに固定ペナルティ c が導入されるため、多くの階で償却しない限り、切り替えを繰り返すとコストが高くなります。 

このプロセスは、フロアごとに 2 つの状態を維持していると解釈できます。つまり、最後の移動が階段を使用した場合と、最後の移動がエレベーターを使用した場合は、フロア i に到達するための最適コストです。 フロア i の状態から、セグメント コストを支払うことで任意の j > i または j < i に拡張できます。 ただし、すべてのペアを再計算する代わりに、フロア次数を増加させて移動するとプレフィックスが緩和されるため、最適な遷移を線形遷移に圧縮できることがわかります。 

これにより、床を掃除し、階段やエレベーターで拡張するときに達成可能な最高のコストを維持する動的プログラミング ソリューションが実現します。 エレベーター状態は余分な c を蓄積するため、ペナルティ付きのリセットのように動作します。 

この削減が機能するのは、最適な一連の動きをラインに沿って単調な改善シーケンスに再配置できるため、任意のペアを再検討する必要がなくなるためです。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (全ペア最短パス) | O(n^2 log n) | O(n^2) | 遅すぎる |
 | 2 つの状態 + 線形遷移を持つ DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 2 つの配列を維持します。 1 つは、最後に使用した階段の移行後にそこで終了する場合に、各フロアに到達するための最良のコストを表します。 もう 1 つは同じものを表しますが、エレベータ遷移で終わります。 

また、セグメントコストを迅速に計算するために、a と b のプレフィックスの合計も維持します。 

### ステップ

 1. 階段とエレベーターのコストのプレフィックス合計を計算します。 

これにより、O(1) でセグメント コストを評価できるようになります。これは、遷移が複数のフロアにまたがる可能性があるため必要です。 
2. dp_s[i] を「階段一貫した」方法で終了するフロア i に到達するための最小コストとして定義し、エレベーターの使用についても同様に dp_e[i] を定義します。 

エレベーターの移行には将来の決定に影響を与える固定オーバーヘッドが含まれるため、この分離が必要です。 
3. dp_s[1] = dp_e[1] = 0 に初期化します。 

フロア 1 から開始すると、コストも以前のモードの制約も発生しません。 
4. フロアを 2 から n までスイープし、以前の最良の状態を使用して dp 値を更新します。 

各 i について、前の j < i から階段またはエレベーターを介して拡張することを検討します。 
5. 階段遷移の場合、prefix_s[i] - prefix_s[j] を使用して j から i までのコストを計算します。 

すべての j をチェックする代わりに、階段の最適な入口点を表す dp_s[j] - prefix_s[j] の実行最小値を維持します。 
6. エレベーター移行の場合、コストを dp_*[j] + c + (prefix_b[i] - prefix_b[j]) として計算します。 

同様に、エレベーターはセグメントの長さに関係なく一定のオーバーヘッド c を追加するため、dp_e[j] - prefix_b[j] の実行最小値を維持します。 
7. dp_s[i] と dp_e[i] をすべての有効な遷移の最小値とします。 

これにより、常に最適な方法でフロア i に到着することが保証されます。 
8. フロア i の答えは min(dp_s[i], dp_e[i]) です。 

最終フロアのモードは関係ありません。 総コストのみが重要です。 

### なぜ効果があるのか

 重要な不変条件は、任意のフロア i について、dp_s[i] と dp_e[i] が、それぞれの最後の遷移タイプを持つ i で終わるすべての有効な移動シーケンスの最適コストを表すことです。 すべての遷移コストはプレフィックスの差分と定数項 (エレベーターの場合のみ) に分解されるため、任意の j から i への遷移は、j にのみ依存する候補値と i のみに依存する項として書き換えることができます。 この分離可能性により、すべての j を列挙する代わりにプレフィックスの最小値を維持することができます。 すべての最適なパスは、コストがエンドポイントのみに依存する単調なセグメントに分解できるため、この緩和によって最適な解決策が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, c = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    ps_a = [0] * (n + 1)
    ps_b = [0] * (n + 1)

    for i in range(1, n):
        ps_a[i + 1] = ps_a[i] + a[i - 1]
        ps_b[i + 1] = ps_b[i] + b[i - 1]

    INF = 10**18

    dp_s = [INF] * (n + 1)
    dp_e = [INF] * (n + 1)

    dp_s[1] = dp_e[1] = 0

    best_s = 0
    best_e = 0

    res = [0] * n
    res[0] = 0

    for i in range(2, n + 1):
        dp_s[i] = min(dp_s[i], ps_a[i] + best_s)
        dp_e[i] = min(dp_e[i], ps_b[i] + c + best_e)

        best_s = min(best_s, dp_s[i] - ps_a[i])
        best_e = min(best_e, dp_e[i] - ps_b[i])

        res[i - 1] = min(dp_s[i], dp_e[i])

    print(*res)

if __name__ == "__main__":
    solve()
```このコードは、セグメント コストを一定時間にするためにプレフィックスの合計に完全に依存しています。 変数 best_s および best_e は、最適に調整された遷移の開始点を格納し、考えられるすべての以前のフロアを単一の候補値に効果的に圧縮します。 

よくある実装上の間違いは、dp[i] を計算する前に best_s と best_e を更新することです。これにより、誤って自己遷移が許可されてしまいます。 正しい順序は、最初に以前の最良の値を使用して dp[i] を計算し、次にそれらを i で更新することです。 

もう 1 つの微妙な点は、dp[1] - prefix[1] がゼロに等しいため、best_s と best_e をゼロに初期化することです。 これにより、両方のトランジション タイプが開始フロアに正しく固定されます。

入力:

 ps_a = [0、1、3、6、10]

トレースは、モードが準最適になると、将来の最良の遷移に自然に寄与しなくなることを確認します。

 ## 特殊なケース

 重要なケースの 1 つは、エレベータのオーバーヘッド c が非常に大きい場合です。 この状況では、エレベーター遷移は最適解によって無視されるはずですが、アルゴリズムは引き続き dp_e を通じて処理します。 正確さは、両方の状態の最小値を取得することで得られ、エレベーターが階段の最適な結果を決して汚さないようにします。 

もう 1 つのエッジ ケースは、階段のコストがゼロか、エレベーターに比べて非常に小さい場合です。 best_s がすぐに負になり、階段遷移が今後のすべての計算を支配するため、アルゴリズムは当然 dp_s を優先します。 

最後の微妙なケースは、将来の情報を使用しない遷移を保証することです。 更新の順序により、dp[i] が前のフロアの状態のみに依存することが保証され、best_s と best_e は dp[i] が確定した後にのみ更新されます。 これにより、DP 解釈を無効にする人為的な自己改善サイクルが防止されます。
