 ## 解決策
 ## 問題の理解

 私たちは、各子供が最初に固有の本を持ち、毎日各本が順列に従って別の固定の子供に渡されるシステムを与えられています。 1 日経つと、すべての本が 1 回動きます。 2 日後、同じルールに基づいて再び移動する、というように続きます。 

それぞれの子供について、私たちは子供を追跡しているのではなく、子供がもともと所有していた本を追跡しています。 質問は、0 日目から開始して、その特定の本が最初に元の所有者に戻るまでの日数を尋ねます。 

重要な観点は、各ノードが出ていくエッジを 1 つだけ持つ有向グラフとして順列を扱うことです。 各ノードは正確に 1 つの他のノードを指しており、これは順列であるため、すべてのノードも正確に 1 つの入力エッジを持ちます。 この構造は完全にばらばらのサイクルに分解されます。 

すべてのクエリにわたるノードの合計数は最大 2 · 10^5 であるため、制約が重要になります。 日々の動きをシミュレートするソリューションでは、最悪の場合、制限をはるかに超える O(n^2) が必要になる可能性があります。 各ノードは少なくとも 1 回処理する必要があるため、クエリごとに線形なもの (理想的には O(n)) が必要です。 

単純な落とし穴は、子供たちそれぞれの動きを個別にシミュレートすることです。 たとえば、長さ 10^5 のサイクルでは、1 冊の本を段階的に追跡するのにすでに 10^5 のコストがかかり、これをすべてのノードに対して実行すると、不必要な作業が乗算されます。 

もう一つの微妙な問題は、方向性の誤解です。 本の移動は順列に従って進みますが、元の本がいつ元の位置に戻るかが尋ねられます。これは、順列グラフの完全なサイクルが完了することに相当します。 

## アプローチ

 強引なアイデアは、開始ノードごとに時間を段階的にシミュレートすることです。 固定ノード i については、そのブックが i に戻るまで順列を繰り返し適用して、そのブックがどこに行くのかを確認します。 最悪の場合、これにはノードごとに O(n) ステップがかかり、すべてのノードに対してこれを実行すると O(n^2) になります。 n が 2 · 10^5 までの場合、これは実行不可能になります。 

重要な観察は、順列が互いに素なサイクルに分解されることです。 サイクルに入ると、そのサイクル内のすべてのノードは同じ戻り時間、つまりサイクルの長さを共有します。 これは、順列を適用するとサイクル内の位置が繰り返し回転され、初めてノードが自身に戻るのは完全に 1 回転した後であるためです。 

したがって、問題は、各ノードの出次数が 1 である有向グラフ内のすべてのサイクルを見つけて、各ノードにそのサイクルの長さを割り当てることに帰着します。 

これは、ノードを未訪問としてマークし、訪問済みのノードに到達するかサイクルを閉じるまで順列に沿って走査を実行することで実行できます。 サイクル内で遭遇するすべてのノードには同じ値が割り当てられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (ノードごとのシミュレーション) | O(n^2) | O(n) | 遅すぎる |
 | サイクル分解 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのノードに対して false に初期化された訪問先配列を維持します。 これにより、検出されたサイクルに既に属しているノードを再処理することができなくなります。 
2. 各ノード i を 1 から n まで繰り返します。 すでに訪問している場合は、以前に処理されたサイクルに属しているため、スキップします。 
3. i から順列の追跡を開始し、パスを一時リストに保存します。 訪問先のノードに到達するか、現在のパス内のノードに戻るまで、現在のノード x から p[x] への移動を続けます。 
4. 現在のパス内で以前に訪問されていないサイクルを検出した場合は、そのノードの最初の出現からパスの終端までのセグメントを測定することによって、その長さを決定します。 このセグメントは 1 つのサイクルに正確に対応します。 
5. サイクル長をそのサイクル セグメント内のすべてのノードに割り当てます。 
6. サイクル内のすべてのノードを訪問済みとしてマークし、次の未訪問ノードに進みます。

これが効率的である理由は、各ノードがパスに 1 回だけ追加され、1 回だけ割り当てられるためです。 

### なぜ効果があるのか

 順列グラフの各連結成分は単純な有向サイクルです。 任意のノードから開始して順列を繰り返し適用すると、最終的には正確なサイクル長の後に開始ノードに戻ります。 サイクル内のすべてのノードは回転に対して対称であるため、戻り時間はそのサイクル内のすべてのノードで同一になります。 アルゴリズムはこれらのサイクルを明示的に再構築し、その長さを一貫して割り当てるため、ノードが誤った値を受け取ることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        p = [0] + list(map(int, input().split()))
        visited = [False] * (n + 1)
        ans = [0] * (n + 1)

        for i in range(1, n + 1):
            if visited[i]:
                continue

            path = []
            cur = i

            while not visited[cur]:
                visited[cur] = True
                path.append(cur)
                cur = p[cur]

            cycle_start_index = 0
            for idx, node in enumerate(path):
                if node == cur:
                    cycle_start_index = idx
                    break

            cycle_nodes = path[cycle_start_index:]
            cycle_len = len(cycle_nodes)

            for node in cycle_nodes:
                ans[node] = cycle_len

        print(*ans[1:])

if __name__ == "__main__":
    solve()
```この実装では、未訪問のノードに沿って歩くことによってサイクル検出が行われます。 各ノードは一度パスに追加され、処理済みのノードに戻ったことを検出すると、パス内のサイクル部分を特定します。 次に、サイクル長がそのサイクル内のすべてのノードに割り当てられます。 

微妙な点は、すべてのノードには 1 つの発信エッジがあるため、ノードに入ったときにすぐに訪問したノードをマークするのが安全であるということです。 後でサイクル境界に遭遇した場合でも、パスにはすべてのノードが正しい順序で含まれているため、サイクル セグメントを切り出すことができます。 

## 実用的な例

 3 番目のサンプル クエリをトレースします。`p = [4, 6, 2, 1, 5, 3]`。 

| ステップ | 現在のノード | パス | 訪問セット |
 | --- | --- | --- | --- |
 | 1 | 1 | [1] | {1} |
 | 2 | 1→4 | [1,4] | {1,4} |
 | 3 | 4→1 | 停止 | {1,4} |

 検出されたサイクルは [1,4]、長さ 2 であるため、ans[1]=2、ans[4]=2 となります。 

次の未訪問ノードは 2 です。 

| ステップ | 現在のノード | パス | 訪問セット |
 | --- | --- | --- | --- |
 | 1 | 2 | [2] | {1,2,4} |
 | 2 | 2→6 | [2,6] | {1,2,4,6} |
 | 3 | 6→3 | [2,6,3] | {1,2,3,4,6} |
 | 4 | 3→2 | 停止 | 上記すべて |

 サイクルは [2,6,3]、長さ 3 で、それぞれに割り当てられます。 

次の未訪問ノードは 5 です。 

| ステップ | 現在のノード | パス | 訪問セット |
 | --- | --- | --- | --- |
 | 1 | 5 | [5] | すべて + 5 |
 | 2 | 5→5 | 停止 | |

 サイクル [5] の長さは 1 です。 

これにより、各サイクルが独立して処理され、サイクル内のすべてのノードが同一の値を受け取ることが確認されます。

 ## 特殊なケース

 次のような単一要素サイクル`p[i] = i`ノードを 1 回訪問するとすぐに走査が停止し、サイクル長が 1 になるため、自然に処理されます。アルゴリズムはそのノードに 1 を割り当てます。これは、本が 1 日後にすでに所有者のところにあるという事実と一致します。 

すべてのノードが 1 つのループを形成する完全な置換サイクルは、開始ノードに再び到達するまでパス全体を収集することによって処理されます。 サイクル抽出ステップでは、完全なパスが単一のセグメントに正しくスライスされ、すべてのノードが n に等しい同じ長さを受け取ることが保証されます。 

訪問済みマーキングにより各サイクルが 1 回だけ検出されることが保証されるため、サイクル サイズが混在していても問題はありません。 スライス ステップにより、以前に完了したサイクルに属するノードが決して再検討されないことが保証され、重複や誤ったオーバーラップが防止されます。
