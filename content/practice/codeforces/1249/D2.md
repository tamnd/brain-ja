 ## 解決策
 ## 問題の理解

 数直線上の整数セグメントのコレクションが与えられます。 各セグメントは、その端点間のすべての整数点をカバーします。 ポイントが複数の要素でカバーされている場合、問題が発生します。$k$同時にセグメント化します。 私たちの仕事は、整数点が覆われないように、できるだけ少ないセグメントを削除することです。 

これを再解釈する便利な方法は、各セグメントがアクティビティの間隔であるタイムラインを想像することです。 任意の整数座標で、その座標に重なるアクティブな間隔の数をカウントします。 間隔を削除することができますが、最終的な最大オーバーラップはどこでも最大で次の値にしたいと考えています。$k$。 

制約は大きく、最大で$2 \cdot 10^5$同じ範囲までのセグメントと座標値。 これにより、セグメントごとまたはポイントごとに重複カウントを繰り返し再計算するアプローチが除外されます。 削除ごとに単純にカバレッジをシミュレートしようとするものはすべて、次のように劣化します。$O(n^2)$が遅すぎます。 解決策は必ずあるはずです$O(n \log n)$または$O(n)$。 

微妙な問題は、悪い点が分離されていないことです。 ある座標でオーバーラップが超えた場合$k$の場合、複数のセグメントが原因である可能性があり、間違ったセグメントを早期に削除すると、今後不要な削除が発生する可能性があります。 もう 1 つの障害モードは、実際に過負荷が発生する場所を考慮せずに、最短または最も早いセグメントを貪欲に削除することです。 

たとえば、多くの長いセグメントが 1 つの小さな領域に重なっており、短いセグメントもその領域を通過するとします。 最初に短いセグメントを削除しても過負荷は修正されず、削除が無駄になります。 

正しい戦略は、オーバーラップが超えている部分に焦点を当てる必要があります。$k$_ そして、それらの点で最も有害な影響を与えるセグメントを削除します。 

## アプローチ

 強引なアイデアは、すべてのポイントの最大オーバーラップを繰り返し計算し、オーバーロードされたポイントに関与する 1 つのセグメントを削除することです。 オーバーラップの各再計算は次のようになります。$O(n \cdot R)$あるいはせいぜい$O(n \log R)$スイープでこれを行うと、$n$時間はおよそにつながります$O(n^2)$行動。 と$2 \cdot 10^5$セグメント、これは不可能です。 

重要な観察は、削除のたびに完全なグローバル再計算を行う必要がないということです。 代わりに、各ポイントをカバーするアクティブなセグメントの現在のセットを維持しながら、右端の昇順でセグメントを処理できます。 以上の点に到達すると、$k$セグメントが重なっている場合は、現在アクティブなセグメントの中で最も右に伸びているセグメントの 1 つを削除する必要があります。 

この選択は非常に重要です。 セグメントが早く終了する場合、セグメントを削除すると、ローカルでのみカバレッジが減少します。 はるか将来に広がるセグメントは、その後の多くの時点で潜在的な過負荷を生み出し続けます。 最大の右エンドポイントを持つセグメントを削除することで、現在の違反を修正しながら将来の干渉を最小限に抑えます。 

右端点で順序付けされたアクティブ セグメントの最大構造を維持しながら、位置にわたるスイープ ラインをシミュレートします。 補償範囲を超える場合$k$、最も大きな右端点を持つセグメントを削除し、削除済みとしてマークします。 これにより、将来のコストを最小限に抑えてすべての違反を解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2 \log n)$|$O(n)$| 遅すぎる |
 | 最適なスイープ + ヒープ |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 位置上のスイープ ライン内のすべてのセグメントの端点を処理します。 

1. セグメントを左の端点で並べ替えます。 左から右に移動しながらセグメントをアクティブ化します。 
2. 右側のエンドポイントをキーとして、アクティブなセグメントの優先キュー (最大ヒープ) を維持します。これにより、最も右に延びるセグメントをすぐに見つけることができます。 
3. ソートされたセグメント上でポインタを維持し、左端点が現在の位置以下であるすべてのセグメントをアクティブにします。 
4. 座標線を左から右にスイープします。 各位置で:

 新しく開始されたすべてのセグメントをヒープに挿入します。 
5. ヒープに次の内容が含まれている場合$k$アクティブなセグメントがある場合は、この位置でオーバーロードを解決する必要があります。 セグメントを貪欲に削除します。 

最大の右エンドポイントを持つセグメントを繰り返し抽出し、アクティブなサイズが最大になるまで削除済みとしてマークします。$k$。 

最端のセグメントを削除する理由は、それが現在の過負荷に寄与し、将来のポジションにも寄与し続けるため、維持するのが最も「高価」であるためです。 
6. すべてのセグメントが処理されるまで続行します。 
7. 削除されたすべてのセグメント インデックスを出力します。 

### なぜ効果があるのか

 どの座標でも、それ以上の場合は、$k$セグメントで覆われている場合は、少なくとも 1 つを削除する必要があります。 すべてのアクティブなセグメントの中で、最も大きな右のエンドポイントを持つセグメントを削除することは、最も長い残りの間隔のカバレッジを排除するため、最適です。 代替の削除では、現在の過負荷を修正できないか、将来的に同等以上の過負荷が発生する可能性があります。 この貪欲な選択により、セグメントが削除されると再検討する必要がなく、今後のステップが必要以上に悪化することはありません。 

不変条件は、各座標を処理した後、その座標までの点がそれ以上のものによってカバーされないことです。$k$削除されていないセグメント、および過去の過負荷を解決するためのすべての有効な方法の中で、このアルゴリズムは将来のセグメントに対して可能な限り最大限の柔軟性を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, k = map(int, input().split())
    segs = []
    for i in range(n):
        l, r = map(int, input().split())
        segs.append((l, r, i + 1))

    segs.sort()
    
    active = []  # max heap by r (store (-r, id))
    removed = [False] * (n + 1)
    
    j = 0
    for i in range(1, 200001):
        while j < n and segs[j][0] == i:
            l, r, idx = segs[j]
            heapq.heappush(active, (-r, idx))
            j += 1
        
        # clean removed segments from heap lazily
        while active and removed[active[0][1]]:
            heapq.heappop(active)
        
        while len(active) > k:
            r_neg, idx = heapq.heappop(active)
            removed[idx] = True

    ans = [i for i in range(1, n + 1) if removed[i]]
    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```コードはセグメントを並べ替え、すべての整数座標をスイープします。 セグメントが開始されるたびに、そのセグメントは、その右のエンドポイントをキーとする最大ヒープに追加されます。 ヒープは常に、現在アクティブなセグメントを表します。 

アクティブセグメント数を超えた場合$k$、将来のカバレッジに最も寄与するため、最も大きな右エンドポイントを持つエンドポイントを削除します。 の`removed`array を使用すると、すべての構造から要素を物理的に消去することなく、削除を追跡できます。 

微妙な点の 1 つは、以下のすべての座標を反復処理することです。$2 \cdot 10^5$。 これは、座標範囲が制限されており、すべてのセグメント アクティベーション イベントを順番にキャッチすることが保証されるため安全です。

 入力:```

これは、チェーンが重なっていると、延長しすぎたセグメントが強制的に削除されることを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのセグメントが同一である場合です。 例えば：```
3 1
1 5
1 5
1 5
```位置 1 では 3 つのセグメントがすべてアクティブであるため、2 つを削除する必要があります。 ヒープは常に最も右側のエンドポイントを持つセグメントを削除しますが、すべて同一であるため、任意の 2 つが有効です。 アルゴリズムは 2 つの除去を正しく出力します。 

もう 1 つの特殊なケースは、次のようなネストされたセグメントです。```
4 2
1 10
2 9
3 8
4 7
```ピークオーバーラップでは、4 つのセグメントすべてがアクティブになります。 以来$k=2$、2つを削除する必要があります。 ヒープは最初に最も外側のセグメントを削除します。これは正しいことです。なぜなら、それらのセグメントが最も広範囲にわたるカバレッジを支配しているからです。 

最後のエッジケースは、オーバーラップが一時的に超過するだけのまばらなアクティベーションです。$k$。 スイープにより、短い違反であっても、違反が発生した座標で正確に捕捉されるため、隠れた不良ポイントが残る可能性のある除去不足が防止されます。
