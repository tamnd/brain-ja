 ## 解決策
 ## 問題の理解

 私たちは、非常に特殊な構築システム、つまり各べき乗を最大 1 回使用できる 3 のべき乗を使用して分解できる数値を扱っています。 各数字は 1、3、9、27、81 などのサイズの「ブロック」から構築されていると考えてください。各ブロックは取得することも取得しないこともでき、繰り返すことはできません。 

合計がその数値に正確に等しいこれらのブロックのサブセットを選択できる場合、その数値は有効です。 タスクは、クエリ値ごとに次のとおりです。`n`、以上の最小の有効な数値を検索します。`n`。 

入力サイズが十分に小さいため、`n`は最大 10,000 で、クエリは最大 500 です。 これにより、高度なデータ構造や大量の事前計算が必要ないことがすぐにわかります。 候補番号のチェックは低コストなので、クエリごとのリニア スキャンでも快適に通過します。 

主な微妙な点は、多くの整数がこの制約の下では表現できないことです。 単純なアプローチでは、3 の累乗を貪欲に減算したり、表現を直接構築しようとしたりする可能性がありますが、その表現は桁数が 3 進数に制限された基数 3 システムと同等であるため、失敗します。`0`または`1`。 重要な問題は、一部の数値では基数 3 の桁上げが必要であり、その「桁上げ」により桁が無効になり、次の有効な構造に強制的にジャンプする可能性があることです。 

素朴な推論でよくある失敗例は、数値が個別の 3 のべき乗の合計に近くなったら局所的に修正できると仮定することです。 例えば、`20`に近いです`18 + 1 + 1`、ただし重複`3^0`is not allowed, and fixing it requires jumping to a completely different scale rather than patching locally.

 ## アプローチ

 A brute-force strategy is straightforward: start from`n`そして、各整数を 1 つずつチェックして、それが個別の 3 のべき乗の合計として記述できるかどうかをテストします。 数値をテストするには`x`を超えない最大の 3 のべき乗を繰り返し減算します。`x`、使用済みとしてマークし、電源を決して再利用しないようにします。 これは、base 3 表現に数字のみが含まれているかどうかのチェックを効果的にシミュレートします。`0`または`1`。 

これは、表現が書き込みと同等であるため機能します。`x`基数 3 で、等しい数字がないことを確認する`2`。 ただし、さらに直接的には、繰り返し 3 で割って余りを調べることができます。 

ブルートフォース手法は正しいですが、有効な数値を見つける前に多くの数値を上方にスキャンする必要があるため、最悪の場合は時間がかかる可能性があります。 有効な数値の構造は、より良い観点を示唆しています。有効な数値とは、まさに、基数 3 表現に数字のみが含まれる数値です。`0`そして`1`。 これは、次の有効な数値を意味します。`n`は本質的に、その基数 3 表現が「バイナリのような」次の整数です。 

これにより、問題は、制限された記数法で次の数字を生成することに変わります。 すべての整数をチェックする代わりに、安全限界まですべての有効な数値を生成できます (`3^10`すでに 59000 を超えており、最大 10000 までしか必要ありません)、二分検索で各クエリに答えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(Q × K × log N) 最悪の場合 | お(1) | 許容できるが不要 |
 | 有効な数値を事前計算 + 二分探索 | O(P log P + Q log P) | O(P) | 承認済み |

 ここ`P`必要な最大範囲までの有効な数値の数です。 

## アルゴリズムのチュートリアル

 1. 3 のべき乗に対する DFS を使用して、すべての有効な数値を生成します。各べき乗は含まれるか除外されます。 

各再帰ステップによって、実行するかどうかが決定されます。`3^k`か否か。 これが機能するのは、すべての有効な数値が 3 の累乗の一意のサブセットに対応しているためです。 
2. 構築された数値が安全な上限 (この問題では 10^9 または少なくとも 59000 など) を超えたら再帰を停止します。 

すべてのクエリ値は 10^4 で制限されるため、この枝刈りは有効です。 
3. 生成されたすべての数値をリストに保存し、並べ替えます。 

DFS では数値順に生成されないため、並べ替えが必要です。 
4. 各クエリについて`n`、リスト内で以下の最小の数値を見つけます。`n`二分探索を使用します。 
5. その値を出力します。 

重要な設計上の選択は、最初にすべての候補を生成することです。 これにより、繰り返しのチェックが回避され、各クエリが単純な検索に変わります。 

### なぜ効果があるのか

 すべての有効な数値は、個別の 3 の累乗のサブセットに正確に対応します。 逆に、すべてのサブセットは有効な数値を生成します。 これにより、有効な数値と、基数 3 の数字の位置にわたるバイナリ文字列との間の全単射が確立されます。 したがって、制限までの 3 のべき乗のすべてのサブセットを生成すると、すべての有効な数値が 1 回だけ列挙され、それらを並べ替えることで、クエリに答えるために必要なすべての候補の完全な順序付きセットが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

vals = []

# generate all sums of distinct powers of 3
def dfs(i, current):
    if current > 10**9:
        return
    if i > 20:
        vals.append(current)
        return

    # do not take 3^i
    dfs(i + 1, current)

    # take 3^i
    dfs(i + 1, current + (3 ** i))

dfs(0, 0)
vals = sorted(set(vals))

q = int(input())
for _ in range(q):
    n = int(input())
    # linear scan is fine due to small size, but binary search is cleaner
    l, r = 0, len(vals)
    while l < r:
        m = (l + r) // 2
        if vals[m] >= n:
            r = m
        else:
            l = m + 1
    print(vals[l])
```DFS は、3 の各べき乗を選択またはスキップすることによって形成されるすべての数値を構築します。 深さの限界`i > 20`安全なので`3^20`すでに必要な最大値をはるかに超えています。 の`set`この構築では実際には重複は発生しませんが、削除により重複が確実に削除されます。 

二分検索ステップにより、リストのサイズが予想よりも大きい場合でも、各クエリが効率的に回答されることが保証されます。 

## 実用的な例

 事前計算されたリストに対する検索の動作に焦点を当てて、サンプル入力から 2 つのクエリをトレースします。

 | ステップ | 低い | 高 | ミッド | ヴァルス[中] | 決定 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | k | k/2 | 9 | 9 < 13、右に移動 |

 検索は、それ自体が有効な数値であるため、13 に直接収束します (3^2 + 3^1 + 3^0 は許可されませんが、13 = 9 + 3 + 1 はすべての累乗が異なるため有効です)。 

これにより、有効な数値が生成されたセットに直接表示され、正確に取得されることが確認されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 |---|---|---|---|

 | 時間 | O(P log P + Q log P) | DFS は P 個の候補を生成し、コスト P log P をソートし、各クエリは二分検索を使用します。 

| スペース | O(P) | すべての有効な数値の保存 |

 制限までの有効な数値の数は少ないため (この制約範囲では約 2^12 以下)、時間とメモリの両方が制限内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    vals = []

    def dfs(i, current):
        if current > 10**9:
            return
        if i > 20:
            vals.append(current)
            return
        dfs(i + 1, current)
        dfs(i + 1, current + (3 ** i))

    dfs(0, 0)
    vals = sorted(set(vals))

    q = int(input())
    out = []
    for _ in range(q):
        n = int(input())
        l, r = 0, len(vals)
        while l < r:
            m = (l + r) // 2
            if vals[m] >= n:
                r = m
            else:
                l = m + 1
        out.append(str(vals[l]))
    return "\n".join(out)

# provided samples
assert run("7\n1\n2\n6\n13\n14\n3620\n10000\n") == "1\n3\n9\n13\n27\n6561\n19683"

# edge cases
assert run("1\n1\n") == "1"
assert run("1\n2\n") == "3"
assert run("3\n10\n11\n12\n")  # sanity check increasing behavior
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 1 | 最小境界 |

 ## 特殊なケース

 のために`n = 1`、DFS には以下が含まれます`1 = 3^0`直接検索するため、二分検索はすぐに 1 を返します。 

のために`n = 2`、明確な 3 の累乗を使用した表現は存在しないため、事前計算されたリストはそれを完全にスキップします。 次の有効なエントリは 3 で、これに対応します。`3^1`。 二分探索では連続性が想定されていないため、アルゴリズムはこれを自然に処理します。 

のために`n = 10000`これは、アルゴリズムが、増分チェックではなく事前計算された構造に完全に依存し、有効な数値が存在しない大きなギャップを正しくジャンプしていることを示しています。
