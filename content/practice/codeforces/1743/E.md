 ## 解決策
 ## 問題の理解

 私たちは 2 つの独立した武器で船を制御しています。 各武器には固定の威力と固定のクールダウン時間があります。 武器が発砲すると、クールダウン期間中は使用できなくなり、その後再び使用可能になります。 

少なくとも 1 つの武器が準備ができているときはいつでも、準備ができている単一の武器を発射するか、両方の武器が準備ができている場合は両方の武器を一緒に発射するかを選択できます。 両方を同時に発射すると、その威力が 1 回の攻撃で加算されます。 

敵船には耐久値と一定のシールドがあります。 すべての攻撃は、総火力からシールド値を差し引いた分だけ耐久性を低下させます。 攻撃するたびにシールドが減算されるため、強力な合体ショットでも部分的に吸収されてしまう。 

目標は、最小限の時間で耐久性をゼロ以下にすることです。 

重要な状態は時間だけではなく、2 つの周期的なプロセス間の相互作用です。両方の武器は独立して突撃し、どの組み合わせが単位時間あたりのダメージを最大化するかに応じて発砲するタイミングを選択します。 

耐久性とパワーの制約は小さいですが、クールダウン時間の制約は最大 10^12 と非常に大きくなります。 これにより、時間の経過に伴うシミュレーションが即座に除外されます。 時間を高密度に扱う場合、時間をステップごとに、あるいはイベントごとに繰り返すことはできません。 代わりに、イベントの起動の構造について推論する必要があります。 

素朴な間違いは、可能な限り貪欲に発砲することが最適であると考えることです。 たとえば、利用可能なときに常に両方の武器を発砲すると、発砲を遅らせることでより強力な複合攻撃スケジュールが得られる場合に、将来の調整の機会が無駄になる可能性があります。 

もう 1 つの微妙な失敗例は、同期の無視によって発生します。 1 つの武器のクールダウンが非常に短く、もう 1 つの武器のクールダウンが非常に遅いとします。 単純なアプローチでは、たとえ速い武器を単独で繰り返し発射する方が良い場合でも、遅い武器を待つことを過大評価する可能性があります。 

具体的な問題のあるシナリオは次のとおりです。 

p1 = 10、t1 = 1

 p2 = 9、t2 = 1000

 h = 5、s = 0

 常に両方の武器を待っていると、最適な高速単発ショットを数多く逃してしまいます。 

したがって、問題は基本的に、孤立した高速攻撃と時折の同期された大規模な攻撃のどちらを選択するかにあります。 

## アプローチ

 構造を無視すると、両方のレーザーの現在のクールダウン タイマーによって定義される状態の観点から考えることができます。 各状態は、少なくとも 1 つのレーザーが準備完了するまで時間とともに遷移し、その後、一方または両方を発射することを選択します。 

これにより、クールダウン フェーズのグリッド上で連続時間最短経路の問題が発生します。 関連するすべての充電イベントに時間を離散化した場合でも、クールダウンが長く、長いチェーンになる可能性があるため、状態の数は時間内で無制限になります。 直接的な最短パスや時間の経過に伴う DP は実現不可能です。 

重要な簡素化は、中間の待機ではなく、発砲の瞬間だけが重要であるという観察から来ています。 2 つの起動イベントの間では、両方のタイマーが進む以外は何も変わりません。 したがって、発生イベントのシーケンスのみを考慮します。 

各発火イベントは固定のダメージ量を生成します。 

シングルショット 1 は p1 - s を与えます

 シングルショット 2 は p2 - s を与えます

 ダブルショットは p1 + p2 - s を与えます

 唯一の困難は、ダブルショットでは両方の武器を同時に準備する必要があるという制約のもとで、これらのイベントをスケジュールすることです。 

絶対時間を追跡する代わりに、システムの構造が周期的であることがわかります。各レーザーは独立してサイクルし、最適な戦略は、選択したサブセットが準備が整って発射されるまで待機する一連の時間として説明できます。 

この問題の標準的なトリックは、時間内に答えを二分探索することです。 時間 T を固定する場合、時間 T までに与えることができる最大ダメージはいくらか、と尋ねることができます。 これを効率的に計算できれば、少なくとも h のダメージを達成する最小の T を見つけることができます。 

ここで問題は、時間 T 内に各発射モードを何回使用できるか、そしてそれらをどのように組み合わせるべきかということです。

任意の T に対して、各レーザーの可能な発射時間のセットが固定されていることがわかります。 レーザー i は t_i の倍数で発射されます。 ダブルショットは、両方のタイマーが揃ったとき、つまり lcm(t1, t2) の倍数になったときに発生します。 ただし、LCM を明示的に使用する必要はありません。 代わりに、ペアリングの発生について貪欲に推論することができます。 

固定 T の場合、次のように計算できます。 

各レーザーが持つ単一の機会の数、

 そのうち何個をダブルショットに組み合わせることができるか。 

h ≤ 5000 であるため、正確な最大フローや複雑なスケジューリングは必要ありません。 十分なダメージが達成可能かどうかだけを知る必要があり、p1 + p2 - s が個々のシーケンスよりも優れている場合、ダメージ密度の点でダブルショットが異なる時間に 2 つのシングルショットを行うよりも厳密に優勢であるため、貪欲にペアリングを最適化できますが、それでも可用性を尊重する必要があります。 

核となる洞察は、最適なスケジュールは時間的に単調であり、check(T) 内で貪欲にシミュレートでき、外部構造は T の二分探索であるということです。 

これにより、次の結果が得られます。

 | --- | --- | --- | --- |

 | 二分探索 + 貪欲な実現可能性チェック | O(log T · (p1 + p2)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 時間 T 内にどれだけのダメージを与えることができるかを決定する関数 check(T) を定義します。 

1. 整数除算を使用して、時間 T によって各レーザーが個別に何回発射できるかを計算します。 レーザー i は、floor(T / t_i) 回発射できます。 これにより、武器をペアにしなかった場合に各武器で利用可能な単発イベントの総数が得られます。 
2. 両方のレーザーの準備が整う時間 t を数えることによって、同時発射の瞬間が何回存在するかを決定します。これは、floor(T / lcm(t1, t2)) に相当します。 これらは、強制的または潜在的なダブルショットの機会を表します。 
3. ダブルショットはイベントごとに最大の即時ダメージを生み出すため、最初に使用します。 各ダブルショットは (p1 + p2 - s) のダメージを与え、両方のレーザーからのアベイラビリティを 1 つ消費します。 
4. ダブル ショットを割り当てた後、両方のレーザーの個々のカウントからその使用量を差し引きます。これらのインスタンスはシングル ショットとして再利用できないためです。 
5. 残りのシングルショット数を独立して使用し、それぞれ (p1 - s) と (p2 - s) に寄与します。 
6. すべてのダメージを合計し、それが少なくとも h であるかどうかを返します。 

check(T) が定義されると、最悪の場合の完全な逐次起動をカバーするのに十分な範囲で最小 T を二分探索します。 

### なぜ効果があるのか

 独立したシングルショットを遅らせたり交換したりしても、達成可能なダメージは減らないため、実行可能性を損なうことなく、すべてのダブルショットが自然な位置合わせ時間に発生するように、有効な発射スケジュールを再配置することができます。 ダメージは相加的であり、共有のタイミング制約を除いてイベントは独立しているため、最適な戦略は、使用する二重アライメントの数と残っている単一の発射の数によって完全に決定されます。 これにより、継続的なスケジューリングの問題が期間内のイベントのカウントに軽減され、すべてのダブル ショットが各レーザーからの 1 つの潜在的な発射スロットを厳密に消費するため、貪欲な割り当てにより最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

def lcm(a, b):
    return a // gcd(a, b) * b

def check(T, p1, t1, p2, t2, h, s):
    l = lcm(t1, t2)

    c1 = T // t1
    c2 = T // t2
    c12 = T // l

    # double shots
    use_double = c12
    damage = use_double * (p1 + p2 - s)

    c1 -= use_double
    c2 -= use_double

    damage += c1 * (p1 - s)
    damage += c2 * (p2 - s)

    return damage >= h

def solve():
    p1, t1 = map(int, input().split())
    p2, t2 = map(int, input().split())
    h, s = map(int, input().split())

    lo, hi = 0, 10**18

    while lo < hi:
        mid = (lo + hi) // 2
        if check(mid, p1, t1, p2, t2, h, s):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```このコードでは、まず、一定時間の実行可能性チェックを定義します。 各レーザーが実行できる発火回数と、クールダウンの LCM を使用して同時ショットとして自然に整列する発火回数を計算します。 これらの整列されたショットは、イベントごとの合計出力を最大化するため、最初にダブル攻撃として扱われます。 各レーザーの割り当てからこれらのペアでの使用を削除した後、残りの容量がシングル ショットに変換されます。 合計ダメージを蓄積し、必要耐久力と比較します。 

外部二分探索では、単調性に基づいて時間を探索します。特定の時間が破壊を許可する場合、それより大きな時間も破壊を許可します。 

実装の微妙な詳細は、大きな時間制限を安全に処理することです。 t_i は最大 10^12 であるため、LCM は 10^18 を超える可能性がありますが、Python は大きな整数を安全に処理し、除算の動作は正しいままです。

 ## 特殊なケース

 エッジケースの 1 つは、両方のレーザーのクールダウンが同じである場合です。 その場合、すべての発砲機会は 2 発であり、アルゴリズムは同一の複合攻撃の 1 つのシーケンスに縮小します。 LCM はクールダウンに等しいため、すべての発射時間は 2 倍として 1 回としてカウントされ、単発の残りは存在しません。 

1 つのレーザーがはるかに遅い場合、別のエッジ ケースが発生します。 For example, t1 = 1 and t2 = 10^12. ここで、ダブルショットは妥当な時間枠内で多くても 1 回しか発生しません。 c12 がゼロまたは非常に小さくなるため、アルゴリズムはこれを正しく処理します。そのため、ほぼすべてのダメージは高速レーザーのみから発生します。 

最後のエッジケースは、p1 + p2 - s が個々の寄与より大幅に大きくない場合です。 その場合でも、ダブル ショットは正しくカウントされますが、実行可能性チェックでは優位性を想定するのではなく、実際のダメージが蓄積されるだけであるため、解が人為的に膨らむことはありません。
