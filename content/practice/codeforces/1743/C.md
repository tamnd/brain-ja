 ## 解決策
 ## 問題の理解

 箱が並んでいます。 箱`i`含まれています`a[i]`雑誌。 バイナリ文字列により、どのボックスに最初に蓋が付いているかがわかります。 

すべての蓋は箱に取り付けられており、最初に含まれているものは`'1'`。 この蓋には 2 つの選択肢しかありません。その場所に留まるか、1 つ左に移動するかです。 蓋は複数回動かすことはできません。 

すべての決定が行われた後、蓋で覆われたすべての箱がそのマガジン数を答えに反映します。 目標は、保存される雑誌の総数を最大化することです。 

興味深いのは、蓋は独立したオブジェクトですが、その選択が相互作用することです。 位置からの蓋`i`どちらのボックスも保護できる`i`またはボックス`i-1`。 1 つのオプションを選択すると、別の蓋がより貴重な箱を保護できなくなる可能性があります。 

すべてのテスト ケースの合計の長さは最大でも`2 · 10^5`、二次関数は即座に除外されます。 アン`O(n²)`アルゴリズムは大まかに実行します`4 · 10^10`最悪の場合、限界をはるかに超えて動作する可能性があります。 テスト ケースごとに線形または線形に近いソリューションが必要です。 

いくつかのエッジケースでは、貪欲な実装が失敗します。 

考慮する：```
n = 2
s = 01
a = [10, 1]
```唯一の蓋は位置 2 から始まります。そこに置いておくと節約できます`1`、移動しながら左に保存します`10`。 正しい答えは、`10`。 既存のカバー付きボックスを常に保護し続ける戦略が戻ってくるでしょう。`1`。 

考慮する：```
n = 3
s = 011
a = [5, 100, 1]
```最適な結果は、`105`。 

蓋を位置 2 から位置 1 に移動し、蓋を位置 3 に保ちます。保存されたボックスは`{1, 3}`価値のあるもの`5 + 1 = 6`、これは最適ではありません。 

代わりに、蓋を位置 2 に保ち、蓋を位置 3 から位置 2 に移動します。2 つの蓋が同じ最終ボックスを占有することはできないため、プロセスをより適切に解釈する必要があります。 貪欲な正しいソリューションでは、連続するブロック内で最適なマガジンを効果的に選択します。 ローカルでの単純な決定は価値を簡単に失う可能性があります`100`。 

別の微妙なケースは次のとおりです。```
n = 4
s = 0111
a = [5, 4, 5, 1]
```答えは`14`、 ない`10`。 

現在覆われているボックスを常に保護する単純な戦略があれば、節約できるでしょう。`4 + 5 + 1 = 10`。 蓋を位置 2 から位置 1 に移動すると、保存できます。`5 + 5 + 4 = 14`。 

重要な観察は、大きな覆われていない箱の蓋を解放するために、意図的に小さな覆われた箱を犠牲にする場合があるということです。 

## アプローチ

 強引な解決策では、すべての蓋を調べて、留まるか左に移動するかの両方の可能性を試します。 あれば`k`蓋、これにより作成されます`2^k`可能な構成。 最悪の場合、どの位置にも蓋が入ってしまいますので、`k = n`。 

のために`n = 2 · 10^5`、 平`2^50`すでに不可能だし、`2^200000`天文学的に大きいです。 ブルートフォースアプローチは、すべての法的取り決めを明示的にチェックするため正しいですが、ほぼすぐに使用できなくなります。 

より迅速な解決策を見つけるには、蓋が実際に何を表しているのかを理解する必要があります。 

に遭遇したとします。`'1'`。 その蓋は、小さな地域の一つの箱が最終的に保護されることを保証します。 もし`'1'`に続きます`'0'`現在のボックスを保護するか、以前のカバーされていないボックスに保護を移すかの選択があります。 

これにより、1 の連続するすべてのセグメント内にチェーン効果が作成されます。 私たちが見るたびに、`'1'`次々に`'1'`を使用すると、そのセグメント内のボックス間で保護を効果的に再配置できます。 失われる可能性がある唯一のマガジンは、再配置された領域内の最小値です。 

特にエレガントな貪欲なプロセスが現れます。 

左から右にスキャンします。 

を含む位置に到達すると、`'1'`を追加して雑誌を暫定的に保存します。`a[i]`答えに。 

前の位置が`'0'`、新しい 1 のブロックの始まりを発見しました。 保護を左に移動して、代わりに前のボックスを含めることもできます。 

貪欲なルールは次のとおりです。 

アクティブなブロック内で現在選択されている保護ボックスの中で最小マガジン数を維持します。 

新しいとき`'1'`ブロックを拡張します。前のカバーされていないボックスに、これまでの最小の保護されたボックスよりも多くのマガジンがある場合、その最小値を前のボックスの値に置き換えます。 

この置換は、まさに最適な再配置で行われることです。 最も弱い保護されたボックスを交換し、代わりにより価値のある覆われていないボックスを保護します。 

結果はリニアスキャンになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^k) | O(k) | 遅すぎる |
 | 最適な貪欲さ | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 答えをゼロに初期化します。 
2. アレイを左から右にスキャンします。 
3. いつ`s[i] = '1'`、 追加`a[i]`このボックスは最初は保護されており、今後も保護される可能性があるためです。 
4. もし`s[i] = '1'`そして`s[i-1] = '0'`、新しい 1 のブロックが始まります。 変数を設定する`cur`に`a[i]`。 

ここ`cur`このアクティブなブロック内で現在選択されている最小のマガジン数を保存します。 
5. もし`s[i] = '1'`そして`s[i-1] = '1'`、 アップデート`cur = min(cur, a[i])`。 

ブロック内の保護された最小値が変更された可能性があります。 
6. ブロックがゼロの後に始まるたびに、カバーされていないボックスの値を比較します。`a[i-1]`と`cur`。 

もし`a[i-1] > cur`、最も弱い保護されたボックスをこの覆われていないボックスに置き換えると、答えは次のように増加します。`a[i-1] - cur`。 

この差を答えに追加して設定します`cur = a[i-1]`。 
7. 配列の最後まで続けます。 

最も受け入れられているソリューションで使用されている、より実装しやすいバージョンは、若干異なりますが、同等です。 

私たちが遭遇したとき、`'1'`後`'0'`、ブロックを開始し、前のゼロ位置ボックスの値を追跡します。 ブロックが成長するにつれて、新しい保護された値がその格納された値よりも大きくなるたびに、概念的にそれらを交換し、追加のマガジンを取得します。 

### なぜ効果があるのか

 次のような最大のセグメントを考えてみましょう。```
0 1 1 1 1 ...
```このセグメント内の各蓋は左に 1 位置だけ移動できます。 最終的に保護されるボックスの総数は、セグメント内の蓋の数と同じになります。 

先頭のゼロ位置とセグメント内のボックスで構成されるすべてのボックスのうち、ちょうど 1 つのボックスを保護から除外する必要があります。 保存されたマガジンを最大化するには、マガジン数が最小のボックスを除外する必要があります。 

貪欲スキャンでは、まさにこの不変条件が維持されます。 セグメントが成長するにつれて、現在保護されている最小値を継続的に追跡します。 より良い候補が現れるたびに、その最小値が置き換えられます。 セグメントの終わりまでに、最小値を除くすべての値が答えに寄与し、これが最適な選択となります。 

セグメントは独立しているため、各セグメントを個別に最適化すると、全体的に最適な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        s = input().strip()
        a = list(map(int, input().split()))

        ans = 0
        prev = 0

        for i in range(n):
            if s[i] == '1':
                if i > 0 and s[i - 1] == '0':
                    prev = a[i - 1]

                if prev and prev > a[i]:
                    ans += prev
                    prev = a[i]
                else:
                    ans += a[i]

        print(ans)

solve()
```変数`ans`これまでに保存した雑誌の合計を保存します。 

変数`prev`は、現在の 1 のブロックの直前にある、カバーされていないボックスの候補を表します。 ブロックがその位置から始まるとき`i`のボックス`i-1`蓋のずれによって保護セットに入る可能性がある唯一の蓋のないボックスです。 

私たちが処理するとき、`'1'`、その値を次と比較します。`prev`。 

もし`prev > a[i]`、前のボックスを保護することは、現在のボックスを保護するよりも優れています。 追加します`prev`小さい値を新しい候補として保持し、後で破棄される可能性があります。 

もし`prev <= a[i]`、現在のボックスは少なくとも同等の価値があるため、保護したままにして追加します`a[i]`。 

アップデート`prev = a[i]`交換後は微妙な部分です。 これは、より小さい値が現在のセグメント内で最も弱い選択ボックスとなり、後でさらに大きな候補に再度置き換えられる可能性があることを意味します。 

最大の答えは次のとおりであるため、すべての算術は Python の整数内に簡単に収まります。`2 · 10^5 × 10^4 = 2 · 10^9`。

 ## 特殊なケース

 次のことを考慮してください。```
n = 2
s = 01
a = [10, 1]
```ブロックの先頭では、`prev = 10`。 以来`10 > 1`、アルゴリズムは追加します`10`そして店`1`最も弱い値として。 最終的な答えは、`10`、蓋が左に移動する必要があるため、これが最適です。 

考慮する：```
n = 4
s = 0111
a = [5, 4, 5, 1]
```アルゴリズムは次から始まります`prev = 5`。 価値のあるもの`4`、それは置き換えて得ます`5`。 価値のあるもの`5`、それは得します`5`。 価値のあるもの`1`、それは得します`4`。 保存されたマガジンの合計が等しい`14`。 これはまさに、セグメント内の最小値、つまり`1`、は除きます。 

考慮する：```
n = 4
s = 0000
a = [100, 100, 100, 100]
```どの位置にも蓋が含まれていないため、スキャンによって何も追加されることはありません。 答えは残っている`0`、それは正しいです。 

考慮する：```
n = 4
s = 1111
a = [3, 7, 2, 8]
```保護セットに入る前にゼロはありません。 各蓋はセグメント内の一部のボックスを保護するだけであり、4 つのボックスすべてを保護したままにすることができます。 アルゴリズムはすべての値を加算して返します。`20`。
