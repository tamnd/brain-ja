 ## 問題の理解

 長さの配列を構築しています$n$負ではない整数を使用し、各要素の上限は次のとおりです。$x$。 配列は任意ではありません。配列には次の固定 MEX が必要です。$k$そして、そのようなすべての有効な配列の中で、可能な限り最大の要素の合計を持つ配列が必要です。 

MEX 条件では、非常に特殊な構造が強制されます。 からのすべての数字$0$まで$k-1$値は少なくとも 1 回は出現する必要がありますが、$k$完全に存在しない必要があります。 それより大きいものはすべて$k$MEX の目的には無関係であり、以下を超えない限り自由に使用できます。$x$。 

制約は小さいです。$n, k, x \le 200$そして$t \le 1000$。 これは、各テスト ケースを一定時間または線形時間で解決する必要があることを強く示唆しています。 テスト ケースごとの 2 次関数はすでに許容されていますが、並べ替えや配列に対する状態検索を伴うものは不要です。 

最初の微妙な失敗例が現れるのは、$k > x + 1$。 許容最大値が$x$そうすると、すべての数字を含めることさえできなくなります$0$に$k-1$。 たとえば、次の場合$x = 1$そして$k = 3$を含める必要があります$0,1,2$、 しかし$2$置くことは不可能です。 答えは次のとおりです。$-1$。 

もう 1 つの失敗例は、MEX 要件の誤解から生じます。 たとえば、次の場合$k = 0$からの数字を含める必要はありません。$0$に$k-1$(空のセット)、ただし、次のことを確認する必要があります。$0$配列に存在しません。 以下の値しか使用できないため、最適な構築は完全に変わります。$1$に$x$。 

最後に、配列を常に次のように埋める単純な貪欲型です。$x$小さい数値の必須の存在が無視されるため失敗します$0$に$k-1$、そうでなければ合計を最大化するはずのポジションを「無駄にする」ことを余儀なくされる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、同じ長さの配列をすべて構築しようとします。$n$の各エントリ$[0, x]$、次に MEX を計算し、最適な合計を追跡します。 配列の数は$(x+1)^n$、それも$n = 10$すでに巨大です。 これはまったく実現不可能です。 

重要な点は、MEX 制約が制限するのは 2 つのことだけであるということです: 必要な数値セット$0$を通して$k-1$、そして禁止された数字$k$。 それ以外はすべて無料の最適化スペースです。 

合計を最大化するには、未使用のすべてのポジションを可能な限り最大の値で埋める必要があります。$x$。 唯一の問題は、必要な数値を含める必要があることです。$0$に$k-1$、これらは合計としては最適ではないかもしれませんが、必須です。 

実現可能性も確保する必要があります。 MEX を正確に取得するには$k$、すべての数字を含める必要があります$0$を通して$k-1$、したがって、少なくとも必要です$k$ポジション。 それはいつでも可能です$n \ge k$、しかしキャップ$x$それらの値を許可する必要があります。 

実現可能性が確保されれば、最適な戦略は簡単です。$0,1,\dots,k-1$一度、残りのポジションを$x$、合計を計算します。 

さらに微妙な点が 1 つあります。$k \le x$、誤って導入しないようにする必要があります。$k$, しかし、実際に使うことはないので、これは当然満足です。

 ## アルゴリズムのチュートリアル

 ここで、答えを直接構築します。 

1. まず、有効な MEX の構築が可能かどうかを確認します。 もし$k > x + 1$そうすると、必要な値をすべて配置できなくなります$0$に$k-1$なぜなら$k-1 > x$。 その場合は返却してください$-1$。 この条件は、値の上限によって引き起こされるすべての不可能なケースを捉えます。 
2. 必要な要素の寄与を計算する$0,1,\dots,k-1$。 それらは少なくとも 1 回は出現する必要があるため、それらの合計を加算します。$\frac{k(k-1)}{2}$。 これは、MEX を適用するために必要な最小限の構造です$k$。 
3. 残りを埋めます$n - k$最大許容値を持つ位置$x$なぜなら、これらのいずれかをより小さい数値に置き換えると、MEX の有効性に影響を与えることなく合計が厳密に減少するからです。 
4. 最終的な答えは次のとおりです。$$\text{sum} = \frac{k(k-1)}{2} + (n-k)\cdot x$$5. もし$n < k$、私たちもすぐに返します$-1$, 必要な数をすべて配置することができないためです。 

### なぜ効果があるのか

 MEX 制約により配列が 2 つの部分 (個別の必須値の強制プレフィックス) に完全に分離されるため、この構築は最適です。$0$に$k-1$、およびサイズの空き領域$n-k$。 強制部分にはメンバーシップに関する柔軟性はなく、配置のみであり、配置は合計に影響しません。 自由部分は、最大許容値を選択することによって個別に最大化されます。$x$。 存在/不在の制約を超える位置間には相互作用がないため、この構造からの逸脱は MEX に違反するか、合計が減少します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, x = map(int, input().split())

        # feasibility check
        if k > x + 1 or n < k:
            print(-1)
            continue

        # sum of required MEX prefix
        res = k * (k - 1) // 2

        # fill remaining with x
        res += (n - k) * x

        print(res)

if __name__ == "__main__":
    solve()
```実装はその推論を直接反映しています。 実現可能性チェックにより、実際に MEX を実現できることが確認されます。$k$。 三角和は、必須の包含を計算します。$0$を通して$k-1$。 残りのポジションは貪欲に埋められます$x$を導入しないので安心です。$k$そして常に貢献を最大化します。 

三角和の整数の除算には注意が必要ですが、Python はこれをきれいに処理します。 チェックの順序は重要です。早期に失敗すると、無効な構成での誤った演算が回避されます。

 ## 特殊なケース

 いつ$k = 0$、必要なプレフィックスが空です。 アルゴリズムは必要な合計を正しく設定します。$0$そしてすべてを満たす$n$との位置$x$、与える$n \cdot x$。 これは MEX 要件と一致します。$0$は不在です。 

いつ$k = x + 1$、実現可能性条件はまだ合格しており、構築ではすべての値が正確に使用されます。$0$を通して$x$。 必要な部分には最適化の余地はありませんが、残りの位置はまだ埋めることができます。$x$。 

いつ$n = k$、自由なポジションはありません。 答えは正確になります$\frac{k(k-1)}{2}$、これはパディングのない強制 MEX 構造に対応します。
