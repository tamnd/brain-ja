 ## 問題の理解

 配列が与えられています`a`長さの`n`間の整数`1`そして`k`。 から`a`、正方形のテーブルを定義します`b`サイズの`n × n`ここで各細胞は`(i, j)`の最小値です`a[i]`そして`a[j]`。 の各整数`b`「色」を表します。 タスクは、すべての色に対して、`1`に`k`、最小の長方形を見つけます。`b`これには、その色のすべてのセルが含まれており、四角形の幅と高さの合計が報告されます。 

問題の制約は、両方のことを示しています。`n`そして`k`と同じ大きさにすることができます`10^5`、ただしすべての合計`n`そして`k`テストケース全体での制限は次のとおりです`10^5`。 を構築するブルートフォースアプローチ`n × n`テーブル`b`明示的には最大で必要になります`10^10`最悪の場合の運用は明らかに不可能です。 の構造を利用しなければなりません。`b`完全なテーブルを構築せずに結果を計算します。 

重要な観察は、次の値です。`b[i][j]`上は常に次によって制限されます`a[i]`そして`a[j]`。 これは、より高い値の「長方形」が、要素の位置によって定義される領域に含まれることを意味します。`a`それは少なくともその値です。 Non-obvious edge cases include arrays where some colors are missing entirely, or arrays where a color appears only once. たとえば、次の場合`a = [3, 2, 4]`そして`k = 5`、色`1`そして`5`が欠けています`a`。 これらの色の辺の正しい合計は次のとおりです。`0`。 単純なアプローチでは、存在しないセルを使用して誤って長方形を見つけようとする可能性があります。 

## アプローチ

 ブルートフォース ソリューションでは、明示的に次のように構築されます。`n × n`テーブル`b`そして、色ごとにすべてのセルをスキャンして、その色が発生する最小および最大の行インデックスと列インデックスを見つけます。 長方形の幅は`(max_col - min_col + 1)`そして高さは`(max_row - min_row + 1)`。 このアプローチの時間計算量は次のとおりです。`O(k * n^2)`を考慮すると、これは法外に大きい`n`できる`10^5`。 メモリ使用量も問題となるため、`b`必要になるだろう`O(n^2)`空間。 

重要な洞察は次のとおりです`b[i][j] = min(a[i], a[j])`内の要素の位置のみに依存します。`a`少なくとも指定された色であること。 色の長方形が必要な場合`c`、数値の最初と最後の出現を知る必要があるだけです ≥`c`で`a`。 形式的には、要素の左端と右端のインデックスを維持すると、`a`それは≧`c`、すべての色の出現をカバーする長方形を計算できます。`c`建設せずに`b`。 長方形の幅と高さは、それぞれ要素のインデックス間の最大距離 ≥ によって決まります。`c`。 繰り返すことで`c`から`k`まで`1`インデックスを伝播することで、繰り返しのスキャンを回避します`a`色ごとに。

 | ブルートフォース | O(k * n^2) | O(n^2) | 遅すぎる |
 | 最適 | テスト ケースごとに O(n + k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`left[c]`そして`right[c]`の最小および最大のインデックスを追跡する`a`ここで、要素は少なくとも`c`。 セット`left[c] = n`そして`right[c] = -1`初期センチネル値として。 
2. 反復処理する`a`左から右へ。 ポジションごとに`i`価値のあるもの`a[i]`、 アップデート`left[v]`そして`right[v]`みんなのために`v ≤ a[i]`。 これにより、`left[v]`要素が ≥ である最も古いインデックスをキャプチャします。`v`が発生し、`right[v]`最新のものを捉えています。 不足している数値のギャップを埋めるために、後で色の降順で最小インデックスと最大インデックスを伝播します。 
3. すべての位置を処理した後、次から繰り返します。`k`まで`1`。 各色ごとに`c`、 アップデート`left[c] = min(left[c], left[c + 1])`そして`right[c] = max(right[c], right[c + 1])`明示的に表示されない可能性のある色を考慮するため`a`ただし、より高い値によって暗黙的にカバーされます。 
4.各色ごとに`c`、 もし`left[c] > right[c]`、色が欠けていることを意味します`a`、したがって、長方形の合計は次のようになります。`0`。 それ以外の場合は、長方形の辺を次のように計算します。`width = right[c] - left[c] + 1`そして`height = width`なぜなら`b`は対称であり、長方形はインデックス空間では正方形です。 幅と高さの合計は、`2 * width`。 
5. すべての色の結果を出力します。`1`に`k`。 

機能する理由: アルゴリズムはインデックスの範囲を正確に識別します。`a`それぞれの色に貢献しています。 の長方形`b`色のために`c`常に左端から右端のインデックスにまたがります。`a[i] ≥ c`、水平方向と垂直方向の両方。 上位の色からインデックスを伝播することで、色の欠落がなくなり、センチネル値を使用することで、欠落した色のエラーが回避されます。 の対称性`b`幅と高さが同じインデックス範囲によって決定されることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        left = [n] * (k + 2)
        right = [-1] * (k + 2)
        
        for i, val in enumerate(a):
            left[val] = min(left[val], i)
            right[val] = max(right[val], i)
        
        # propagate from higher to lower colors
        for c in range(k, 0, -1):
            left[c] = min(left[c], left[c + 1])
            right[c] = max(right[c], right[c + 1])
        
        res = []
        for c in range(1, k + 1):
            if left[c] > right[c]:
                res.append(0)
            else:
                width = right[c] - left[c] + 1
                res.append(2 * width)
        print(*res)

solve()
```コードの各セクションはアルゴリズムに直接マッピングされます。 初期化中`left`そして`right`欠落している色を個別に処理する必要がなくなります。 反復中のインデックスの更新`a`線形時間処理を保証します。 伝播元`k`ダウンハンドルの欠落した中間色とコンピューティング`2 * width`の対称性により正しい辺の合計が得られます。`b`。
