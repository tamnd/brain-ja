 ## 解決策
 ## 問題の理解

 1 から 1 までの数字を考えるように求められます。$n$塩基で表現する$k$。 塩基で表現したら$k$では、これらの表現を文字列と同様に辞書順に並べ替えます。 並べ替えた後、要素に 1 から 1 までの番号を付けます。$n$。 課題は数字をいくつ数えるかです$i$に行き着く$i$このソートされた配列内の - 番目の位置。 

たとえば、次のように考えてみましょう$n=6$そして$k=4$。 基数 4 の表現は 1、2、3、10、11、12 です。これらを辞書順に並べ替えると、1、10、11、12、2、3 が得られます。数値 1 だけが「自然な」位置にあるため、答えは 1 になります。 

主な課題は次のような制約です。$n$そして$k$まで可能です$10^{18}$。 すべての表現を構築したり、明示的に並べ替えたりすることは不可能です。 平$O(n)$時間が遅すぎるでしょう。 これにより、すべての数値を反復処理したり、直接文字列の並べ替えを実行したりする単純なアプローチが即座に除外されます。 

明らかではないエッジケースが現れるのは、$k$に比べて小さい$n$。 たとえば、$n=33$そして$k=2$、複数の数値が同様の長さのバイナリ表現を共有します。 辞書編集上の順序は数値ではなく文字列の長さに依存するため、単純なアプローチでは数え間違える可能性があります。 もう一つの微妙なケースは次のような場合です。$k > n$。 それからベースは――$k$すべての数値の表現$1$に$n$は単なる数値そのものなので、すべての数値はその位置と一致します。 

## アプローチ

 ブルートフォースアプローチでは、ベースを計算します。$k$各数値を表現し、文字列として保存し、並べ替えて、位置をカウントします。 これは小規模な場合に機能します$n$そして$k$、しかしそれは必要です$O(n \log n)$時間と$O(n \cdot \log_k n)$空間。 のために$n=10^{18}$、これはまったく不可能です。 

重要な洞察は、すべての数値とその表現を生成しないようにすることです。 基本の数字の辞書編集順であることに注意してください。$k$それらの塩基の番号順に対応します。$k$基数の数値として解釈される数字$k$。 これは、有効なシーケンスを意味します。$i$は、まさに次の個別の累乗の合計として表現できる数列です。$k$各電力が最大 1 回使用される場合。 基本的に、任意の数のフォーム$1 \cdot k^0 + 1 \cdot k^1 + \dots$基数がその桁の数値に対応します$k$は厳密に 0 または 1 です。これは、基数を使用してバイナリのようなシステムで数を数えるのとまったく同じです。$k$、数字は 0 または 1 です。 

したがって、並べ替える代わりに、次の形式のすべての数値を列挙できます。$1, k, k+1, k^2, k^2+1, k^2+k, k^2+k+1, \dots$合計が超えるまで$n$。 これにより、単純な再帰または反復ループが得られ、数値が昇順に直接生成されます。 この方法で生成された各番号は、辞書編集上の「正しい」位置を自動的に占めます。

 | ブルートフォース | O(n log n) | O(n log n) | n が大きいと遅すぎます |
 | 最適 | O(log_k n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カウンターを有効な数値に初期化します。 次の 1 乗から始めます$k$、$k^0 = 1$。 
2. 現在の合計の変数を保持します。これが候補数になります。 0から始めてください。 
3. 次のべき乗を反復します。$k$昇順で:$1, k, k^2, k^3, \dots$。 べき乗ごとに、それを含めるバイナリの選択 (0 または 1) を繰り返します。 現在の合計に加算し、超えているかどうかを確認します$n$。 そうなら、壊れてください。 それ以外の場合は、カウンターをインクリメントします。 
4. キューまたは反復ループを使用して、べき乗の合計を列挙します。$k$を超えずに$n$。 それぞれの合計は、その基数を表す数値を表します。$k$数字は 0 または 1 です。これらはまさに、辞書編集上の自然な位置に表示される数字です。 
5. 次の候補が超えるまで繰り返します。$n$。 

機能する理由: 悪用される特性は、基数が 0 または 1 のみの数字であることです。$k$辞書順に、番号順に正確に表示されます。 他の数値はどこかに 2 以降の数字があり、辞書編集順でさらに下に押し込まれます。 の個別のべき乗のすべての合計を生成することにより、$k$≤$n$、「正しい」位置にあるすべての数字をカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        count = 0
        power = 1
        numbers = [0]
        while numbers:
            next_numbers = []
            for num in numbers:
                for add in (0, power):
                    new_num = num + add
                    if 1 <= new_num <= n:
                        count += 1
                        next_numbers.append(new_num)
            power *= k
            numbers = next_numbers
        print(count)

if __name__ == "__main__":
    solve()
```この解決策は、次のべき乗の和をレベルごとに生成することを使用します。$k$。 各レベルは次の 1 乗に対応します。$k$、そして 2 つの選択肢 (0 または 1) により、そのべき乗が使用されるかどうかのすべての数値が生成されます。 これにより、重複がないことが保証され、すべての数値 ≤ がカバーされます。$n$誰の基地-$k$数字は0か1のみです。 

微妙な点: 候補番号はべき乗の大きい順に生成されます。 1 から始まる数字を含める必要があります (0 は除く)。 乗算する`power`による`k`毎回、オーバーフローすることなく累乗を正確に追跡し、新しい数値が ≤ にならない場合、アルゴリズムは自然に停止します。$n$生成することができます。

 ## 特殊なケース

 n=1、k=2 の場合、アルゴリズムは 1 を直接生成します。 パワーをさらに増やす必要はありません。 出力 = 1、これは正しいです。 

n < k (n=3、k=5 など) の場合、すべての数値は 1 桁の進数 5 で表されます。 それぞれの位置が 1 であるため、アルゴリズムは 1、2、3 を正しくカウントします。
