 ## 解決策
 ## 問題の理解

 この問題は、ロールプレイング ゲームにおける単一の転生プロセスをシミュレートします。 

すでにいくつかのスキルを持っているキャラクターから始めます。 各スキルには名前と経験値があります。 転生が発生すると、既存のすべてのスキルのレベルが係数によって低下します`k`。 新しいレベルは次の整数部分になります。`k × level`。 

この削減ステップの後、結果として得られるレベルが厳密に次のレベルよりも低いスキルはすべて削除されます。`100`忘れられて完全に消えてしまいます。 

次に、キャラクターは対象クラスに属するスキルを受け取ります。 キャラクターが軽減フェーズ後にすでにこれらのスキルのいずれかを持っている場合は、何も変わりません。 スキルが現在存在しない場合は、レベルとともに追加されます`0`。 

最後のタスクは、これらの変換後に残っているすべてのスキルをスキル名で辞書順に並べて出力することです。 

制約は非常に小さいです。 現在のスキルの数とターゲットクラスのスキルの数は両方とも最大です`20`。 コレクションを繰り返しスキャンする単純な実装でも、十分に高速になります。 課題はアルゴリズムの複雑さではなく、ステートメントで説明されている変換のシーケンスに正しく従うことです。 

いくつかの微妙なケースでは、ルールが間違った順序で適用されると、誤った答えが生成される可能性があります。 

考慮する：```
1 1 0.50
fire 300
fire
```スキルは、`150`減少後も生き残る。 クラススキルはすでに存在するため、そのままにしておく必要があります`150`。 

正しい出力:```
1
fire 150
```不用意に実装すると、次のように上書きされる可能性があります。`0`。 

もう 1 つの重要なケースは、クラス スキルがもともと存在していたが、削減後に忘れられた場合です。```
1 1 0.50
fire 180
fire
```減額された値は、`90`, そのため、スキルは忘れられます。 次に、クラスは次のことを許可します。`fire`またレベルで`0`。 

正しい出力:```
1
fire 0
```忘れられたスキルを削除する前にクラスのスキルをチェックする実装では、間違った結果が生成されます。 

境界値`100`も重要です:```
1 0 0.50
fire 200
```減額された値は正確に`100`、厳密に小さい値のみが存在するため、これは存続します。`100`が削除されます。 

正しい出力:```
1
fire 100
```使用する`<= 100`の代わりに`< 100`スキルを誤って削除してしまう可能性があります。 

## アプローチ

 直接的なシミュレーションはすぐにそれを示唆します。 既存のすべてのスキルを処理し、その減少レベルを計算し、新しいレベルが少なくともそれ以上であるスキルのみを保持できます。`100`。 その後、ターゲットクラスのスキルを処理し、不足しているスキルをレベルで追加します`0`。 

どちらのリストにもスキルは最大 20 個しかないため、ネストされたスキャンを使用したブルートフォース アプローチであっても完全に受け入れられます。 最悪の場合、必要な操作は数百回だけです。 

もう少しすっきりしたアプローチでは、スキル名をキーとした辞書を使用します。 辞書は当然のことながら、キャラクターが現在所有しているスキルのセットを表します。 削減と忘却のルールを適用した後は、クラス スキルの追加が簡単なメンバーシップ チェックになります。 

重要な観察は、問題は純粋に状態の変換であるということです。 最適化、グラフ検索、動的プログラミング、または複雑なデータ構造は必要ありません。 指定された順序どおりにルールに注意深く従うだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n + m)^2) | O(n + m) | 承認済み |
 | 最適 | O(n + m + z log z) | O(n + m) | 承認済み |

 ここ`z`は最終的な回答に含まれるスキルの数であり、並べ替えステップが実行時間の大半を占めます。 

## アルゴリズムのチュートリアル

 1.読む`n`、`m`、係数`k`。 
2. 転生後に生き残るスキルを保存する空の辞書を作成します。 
3. それぞれについて`n`現在のスキル、計算:```
new_level = floor(k × old_level)
```このステートメントでは、整数部分を取得することが明示的に必要です。 
4. もし`new_level`少なくとも`100`、その値を使用してスキルを辞書に挿入します。 

以下のスキル`100`忘れ去られており、辞書には載っていないはずです。 
5. すべて読む`m`ターゲットクラスのスキルを一つずつ。 
6. 各クラス スキルについて、それが辞書にすでに存在するかどうかを確認します。 

存在しない場合はレベルを指定して挿入します`0`。 

すでに存在する場合は、現在の値を変更しないでください。 
7. すべての辞書エントリを抽出し、スキル名ごとに辞書順に並べ替えます。 
8. スキルの数を出力し、それぞれを出力します。`(name, level)`ソート順にペアにします。 

### なぜ効果があるのか

 ステップ 4 の後、元のすべてのスキルと以下のすべてのスキルが係数に従って変換されるため、辞書には削減フェーズを生き残るスキルが正確に含まれます。`100`が削除されます。 

ステップ 6 の後は、すべてのターゲット クラスのスキルが辞書に存在することが保証されます。 既存の生き残っているスキルは低下したレベルを維持しますが、不足しているクラススキルはレベルに追加されます`0`、まさに輪廻のルールに一致します。 

最終出力は、この最終スキル セットの辞書順に並べられたバージョンにすぎないため、アルゴリズムは固有の正しい結果を生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k_str = input().split()

    n = int(n)
    m = int(m)

    num, den = map(int, k_str.split('.'))
    k_num = num * 100 + den

    skills = {}

    for _ in range(n):
        name, exp = input().split()
        exp = int(exp)

        new_exp = (exp * k_num) // 100

        if new_exp >= 100:
            skills[name] = new_exp

    for _ in range(m):
        name = input().strip()

        if name not in skills:
            skills[name] = 0

    items = sorted(skills.items())

    out = [str(len(items))]
    for name, level in items:
        out.append(f"{name} {level}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```実装はシミュレーションに直接従います。 

細かい点は、係数がどのように計算されるかです。`k`扱われます。 通常、浮動小数点演算を使用するとこれらの制約に対処できますが、整数演算の方がよりクリーンで、精度の問題が発生する可能性を回避できます。 以来`k`常に小数点以下 2 桁が含まれる場合は、整数のパーセンテージに変換します。 例えば、`0.75`になる`75`、削減されたレベルは次のように計算されます。```
floor(exp × 75 / 100)
```整数の除算を使用します。 

辞書には、忘却段階の後に現在のスキルのセットが保存されます。 クラススキルが処理されるとき、簡単なメンバーシップチェックにより、レベルにスキルを追加する必要があるかどうかが決定されます。`0`。 

最後に、辞書項目をソートすると、必要な辞書編集順序が生成されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m + z log z) | 処理スキルは直線的であり、最終的なリストのコストを分類します`O(z log z)`|
 | スペース | O(n + m) | 辞書にはすべての生き残ったスキルと追加されたスキルが保存されます。

 減少値がちょうどなるスキル`100`生き残らなければなりません。 考慮する：```
1 0 0.50
fire 200
```減額された値は、`100`。 厳密に以下の値のみであるため、`100`忘れてしまった場合、最終出力は次のようになります。```
1
fire 100
```実装では使用します`>= 100`、この境界を正しく処理します。

fire
```減額された値は、`150`, そのため、スキルは存続します。 クラススキルを処理するとき、辞書にはすでに以下が含まれています`"fire"`, したがって何も変わりません。 最終結果は次のようになります。```
