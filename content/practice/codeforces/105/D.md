 ## 解決策
 ## 問題の理解

 このステートメントは意図的にゲーム用語でまとめられていますが、基礎となるプロセスは一連のカラー マージです。 

各マップ セルにはパネルの色があります。 一部のセルにはシンボルも含まれており、各シンボルには独自の色があります。 まず、1 つの特定のシンボルを破壊します。 破棄されたシンボルはキューを通じて処理されます。 

色を象徴するとき`S`処理されたら、現在の色を確認します`C`そのシンボルが立っているパネルの。 

もし`C = 0`(透明) または`C = S`、何も起こりません。 

それ以外の場合、現在の色が`C`カラーにリペイントされています`S`。 再描画されたすべてのセルは 1 回の再描画操作としてカウントされます。 これらの再描画されたセルのいずれかにまだ削除されていないシンボルが含まれている場合、そのシンボルは削除されてキューに追加されます。 スパイラル順序は、新しく削除されたシンボルがキューに入る順序を決定するだけです。 

グリッドには最大でも次のものが含まれます`300 × 300 = 90,000`細胞。 再描画のたびにグリッド全体を繰り返しスキャンする直接シミュレーションでは、コストがかかりすぎます。 イベントごとに線形または対数に近い値が必要です。 

最初の明らかではない観察は、細胞ではなく色がプロセスを推進しているということです。 再描画が行われるたびに、現在のカラー クラス全体が別のカラーにマージされます。 どのセルも現在のカラー コンポーネントを離れ、後で前のカラー コンポーネントに戻ることはありません。 

もう 1 つの微妙な点は、シンボルが 1 回しか削除されないことです。 シンボルは、色が何度も変わるセル上に存在する可能性がありますが、そのセルに触れる最初の再描画の後、シンボルはフィールドを離れ、キューに永久に入力されます。 

単純な実装では、色の値を配列インデックスとして直接扱うことによって失敗する可能性もあります。 カラーは以下まで`10^9`, そのため、座標圧縮が必要です。 

## アプローチ

 ブルート フォース シミュレーションでは、完全なグリッドが維持されます。 シンボルが処理されるたびに、すべてのセルをスキャンし、必要な色を持つセルを見つけて再描画し、新しく削除されたシンボルを検出して続行します。 

このアプローチは、ステートメントに文字通り従うため、正しいです。 残念ながら、一度の再ペイントで影響を受ける可能性があります。`O(nm)`細胞が存在する可能性があります`O(nm)`そういったイベント。 最悪のケースはおおよそ次のようになります`O((nm)^2)`、これは完全に不可能です`90,000`細胞。 

重要な点は、再描画が個々のセルに対して行われないことです。 現在のカラークラス全体に対して動作します。 色を付けたら`A`色に塗り直される`B`、これら 2 つのクラスは事実上 1 つの大きなクラスになります。 これはまさに、Disjoint Set Union 構造が役立つ状況です。 

圧縮された色ごとに以下を保存します。 

- 現在の DSU 代表者。 
- カラークラスのサイズ。 
- 現在その色に属しているシンボルのリスト。 

シンボルが色からの再描画をトリガーするとき`A`色に`B`、色のすべてのセル`A`再塗装されています。 カラークラスのサイズに応じて再描画回数が増加します`A`。 次に、2 つのカラー クラスが DSU 内でマージされます。 色に属する記号`A`必要なスパイラル順序に従ってキューに入れられます。

 ## アルゴリズムのチュートリアル

 1. パネルまたはシンボルに表示されるすべての個別の色を小さな整数 ID に圧縮します。 
2. パネルの色ごとに、その色に現在属しているセルの数を数えます。 これが初期の DSU コンポーネント サイズになります。 
3. 最初に破壊されたシンボルを除くすべてのシンボルについて、その位置を、そのシンボルが立っているパネルの色に関連付けられたコンテナに配置します。 
4. 開始シンボルを使用してキューを初期化します。 
5. キューからシンボルを繰り返しポップします。 
6. しましょう`A`その位置の現在のパネルの色になります。 色は時間の経過とともに統合されるため、DSU 担当者を通じて入手してください。 
7. しましょう`B`シンボルカラーとなります。 
8. もし`A = 0`または`A = B`の場合、このシンボルは再描画を行わず、処理が続行されます。 
9. それ以外の場合、カラークラスのすべてのセル`A`再塗装されています。 コンポーネントのサイズによって答えを増やします`A`。 
10. 現在カラークラスに保存されているすべてのシンボル`A`フィールドから削除され、キューに追加されます。 このステートメントにはスパイラル順序が必要なので、シンボルをプッシュする前に、現在処理されているシンボルに対する相対的なスパイラル インデックスによってシンボルを並べ替えます。 
11. カラークラスのマージ`A`色に`B`DSU の内部。 マージされたコンポーネントは色を表すようになりました`B`。 
12. キューが空になるまで続行します。 

### なぜ効果があるのか

 常に、DSU コンポーネントは 1 つの現在のパネル カラー クラスを表します。 再描画操作ではカラー クラスが分割されることはなく、あるカラー クラスを別のカラー クラスにマージするだけです。 この単調な動作により、DSU は常にボードの実際の状態と一致します。 

シンボルがカラークラスの再描画をトリガーするたびに`A`、現在属しているすべてのセル`A`その操作中に 1 回だけ再描画されます。 DSU コンポーネントのサイズを追加すると、それらの再描画が正確にカウントされます。 そのクラスに属するシンボルは、再描画によって削除されたシンボルとまったく同じであるため、それらをキューに配置すると、ステートメントで説明されているプロセスが再現されます。 したがって、マージと再ペイントのカウントのシミュレートされたシーケンスは、実際のゲーム プロセスと同じになります。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def spiral_id(dx, dy):
    if dy <= 0:
        n = max(abs(dy), abs(dx) - 1)
    else:
        n = max(abs(dy), abs(dx)) - 1

    if dx == n + 1:
        return 4 * (n + 1) * (n + 1) + (n + 1) - dy
    elif dy == n + 1:
        return (4 * n + 2) * (n + 1) + (n + 1) + dx
    elif dx == -(n + 1):
        return (2 * n + 1) * (2 * n + 1) + n + dy
    else:
        return 4 * n * n + 2 * n + n - dx

def solve():
    n, m = map(int, input().split())

    color_map = {0: 0}
    color_cnt = 1

    def get_color(x):
        nonlocal color_cnt
        if x not in color_map:
            color_map[x] = color_cnt
            color_cnt += 1
        return color_map[x]

    panel = [[0] * m for _ in range(n)]

    size = [0] * (2 * n * m + 5)

    for i in range(n):
        row = list(map(int, input().split()))
        for j, c in enumerate(row):
            cc = get_color(c)
            panel[i][j] = cc
            size[cc] += 1

    symbol = [[-1] * m for _ in range(n)]

    for i in range(n):
        row = list(map(int, input().split()))
        for j, c in enumerate(row):
            if c != -1:
                symbol[i][j] = get_color(c)

    x, y = map(int, input().split())
    x -= 1
    y -= 1

    total_colors = color_cnt

    parent = list(range(total_colors))
    rank = [0] * total_colors
    cur_color = list(range(total_colors))

    nodes = [[] for _ in range(total_colors)]

    for i in range(n):
        for j in range(m):
            if i == x and j == y:
                continue
            if symbol[i][j] != -1:
                nodes[panel[i][j]].append((i, j))

    def find(v):
        while parent[v] != v:
            parent[v] = parent[parent[v]]
            v = parent[v]
        return v

    def union(a, b):
        a = find(a)
        b = find(b)

        if a == b:
            return a

        if rank[a] < rank[b]:
            parent[a] = b
            size[b] += size[a]
            size[a] = 0
            return b

        if rank[a] > rank[b]:
            parent[b] = a
            size[a] += size[b]
            size[b] = 0
            return a

        parent[a] = b
        rank[b] += 1
        size[b] += size[a]
        size[a] = 0
        return b

    q = deque()
    q.append((x, y))

    answer = 0

    while q:
        cx, cy = q.popleft()

        root = find(panel[cx][cy])

        current_panel_color = cur_color[root]
        symbol_color = symbol[cx][cy]

        if current_panel_color == 0 or current_panel_color == symbol_color:
            continue

        answer += size[root]

        removed = nodes[current_panel_color]
        nodes[current_panel_color] = []

        removed.sort(
            key=lambda p: spiral_id(
                p[0] - cx,
                p[1] - cy
            )
        )

        for pos in removed:
            q.append(pos)

        parent[symbol_color] = symbol_color
        merged = union(root, symbol_color)
        cur_color[merged] = symbol_color

    print(answer)

solve()
```この実装は DSU モデルを直接反映しています。 元の値に達する可能性があるため、色は圧縮されています`10^9`。 DSU は、現在のマージされたカラー クラスとそのサイズを保存します。 の`nodes`配列には、カラー クラスに現在関連付けられているすべてのシンボルが格納されます。 再描画が行われると、これらのシンボルはフィールドから削除され、キューに追加されたものとまったく同じになります。 

唯一珍しい部分は、`spiral_id`関数。 現在処理されているシンボルを中心とする無限スパイラル内のセルの位置を計算します。 この値で並べ替えると、ステートメントで必要なキューの挿入順序が再現されます。 DSU マージはコンポーネント サイズを更新し、再描画ごとに正しい数の再描画セルが提供されるようにします。

 ## 特殊なケース

 シンボルは透明パネル上に立つことができます。 その場合、ルールは直ちに再描画が行われないことを示します。 アルゴリズムチェック`current_panel_color == 0`マージを行う前にキューが継続されるだけです。 

シンボルの色がすでに現在のパネルの色と同じになっている場合があります。 これは、以前に何度かマージを行った後によく発生します。 元のパネルの色だけを調べる単純な実装は間違っています。 DSU 代表は常に現在のカラー クラスを提供し、色がすでに一致している場合、アルゴリズムは再描画をスキップします。 

複数の元の色が 1 つの大きなコンポーネントにマージされている可能性があります。 後の再描画操作では、元のカラー サイズではなく、マージされたコンポーネントのサイズをカウントする必要があります。 DSU はコンポーネント サイズを代表に保存するため、再描画のたびに、古い情報ではなく、マージされたカラー クラス全体の現在のサイズが使用されます。
