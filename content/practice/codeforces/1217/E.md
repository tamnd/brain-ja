 ## 解決策
 ## 問題の理解

 時間の経過とともに変化する整数の配列が与えられ、この配列の選択されたセグメントを検査するように繰り返し求められます。 各クエリ セグメントについて、合計自体には興味がありませんが、合計がそれ自身の 10 進表現に関して特定の数字ベースの条件に違反する要素のサブセットを選択することに関心があります。 

この条件は、サブセットとその合計を非ローカルな方法で結び付けます。 サブセットを取得してその合計を計算する場合、その合計を基数 10 で書き込みます。この合計の各桁位置について、同じ位置の桁が合計の桁と一致する、選択された要素が少なくとも 1 つ存在する必要があります。 このルールに違反するサブセットがない場合は、失敗が報告されます。 それ以外の場合は、すでにルールに違反している可能な限り最小の合計を持つサブセットが必要です。 

重要な問題は、サブセットの有効性がその要素とその合計の桁構造に同時に依存することです。 これによりフィードバック ループが作成されます。要素を選択すると合計が変化し、妥当性を定義する制約が変化します。 

制約は大きく、最大 200,000 の要素と 200,000 の操作があります。 サブセットを列挙したり、クエリごとに数字の相互作用を最初から再計算したりするソリューションは、すぐに失敗します。 クエリごとにセグメントを反復処理するだけでも遅すぎるため、高速な範囲集計とポイント更新をサポートしながら、その上で組み合わせ決定問題もサポートするデータ構造が必要です。 

すべてのサブセットのバランスが取れている場合、微妙なエッジケースが現れます。 たとえば、すべての要素が 0 の場合、すべてのサブセットの合計は 0 であり、桁の条件を自明に満たすため、答えは -1 になる必要があります。 単純なアプローチでは、空のサブセットまたは単一要素のサブセットが違反に対して常に有効であると想定しているため、誤って 0 を返す可能性がありますが、ここでは違反はまったく存在しません。 

最小の不均衡サブセットがセグメントのプレフィックスまたはサフィックスではない場合、別の注意が必要なケースが発生します。 サブ配列ではなくサブセットに対して最適化しているため、局所性の仮定は完全に失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに、指定されたセグメントのすべてのサブセットを列挙し、それらの合計を計算し、数字の条件に違反しているかどうかを確認します。 これは定義に直接従うため正しいですが、サブセットの数はセグメント サイズに応じて指数関数的に増加するため、小さな入力でも不可能になります。 

もう少し素朴なアイデアは、小さなサブセットが合計を最小化する可能性が高いことを期待して、サイズを大きくするサブセットを試すことです。 ただし、これには依然として各クエリ内での組み合わせ列挙が必要であり、実行可能な制限をはるかに超えています。 

重要な観察は、数字の条件が合計と、各数字の位置が、その位置でその数字に寄与する少なくとも 1 つの選択された要素によって「カバーされる」かどうかのみに依存するということです。 これは、重要なのは完全なサブセット構造ではなく、要素が桁ごとの制約にどのように寄与するかであることを示唆しています。 

この問題は次のように再解釈できます。サブセットは、その合計の各桁位置について、少なくとも 1 つの選択された要素にその位置に同じ桁が含まれている場合にバランスが取れています。 したがって、合計に少なくとも 1 つの桁位置が存在し、その位置でその桁に一致する選択された要素がない場合、サブセットはアンバランスになります。 

ここで、最小和の不均衡サブセットを構築する方法を考えてみましょう。 できるだけ安く状態を崩したい。 これは、要素を追加しても合計が増加するだけであるため、最初に小さなサブセット、特に単一の要素とペアを試してみるべきであることを示唆しています。

重要な単純化は、最小合計で不均衡なサブセットを作成する唯一の方法は、不一致を強制できる桁の位置を特定することであるということです。 それぞれの数字について、その数字のプロファイルを考えることができます。つまり、各位置で数字が寄与します。 各位置の合計桁はグローバルに影響を受けますが、一致する桁が存在しないことにより違反がローカルでトリガーされます。 

この解決策は、桁位置ごとの頻度のような情報を維持し、構築された合計桁が「サポートされていない」かどうかを効率的に問い合わせることに帰着します。 これは、違反を検出するために必要な最適な寄与候補をセグメントごとに追跡するセグメント ツリーを使用してエンコードできます。 

各ノードでは、最小値と数字のフィンガープリントを保存します。これにより、特定の要素を選択すると最小の合計で違反が発生するかどうかを迅速にテストできます。 範囲をクエリすると、これらの要約が対数時間でマージされます。

 ## アルゴリズムのチュートリアル

 この問題を、セグメントに対する 2 つの操作、つまり不均衡なサブセットの最小和を計算するポイント更新と範囲クエリのサポートに集約します。 

1. すべての要素について、その桁表現を事前に計算して、桁の位置をすばやく推論できるようにします。 これにより、セグメントデータをマージする際の定数時間の桁検査が可能になります。 
2. 各ノードがそのセグメントの簡潔な概要を保存するセグメント ツリーを構築します。 この概要は、最小の不均衡サブセット (通常は異なる桁構造を持つ最小の少数の要素) を形成するのに役立つ候補値を追跡します。 
3. 2 つのノードをマージする場合は、それらの候補セットを結合し、最小の関連要素のみを保持します。 これが機能する理由は、小さな要素がすでに同じ桁の動作を保持している場合、最適な答えには大きな要素が必要ないためです。 
4. クエリ範囲については、セグメント ツリーからマージされたサマリーを収集します。 これにより、セグメントの構造を表す小さな候補プールが得られます。 
5. この候補プールからバランス条件に違反する最小のサブセットを構築してみます。 プールは小さく、慎重に選択されているため、指数関数的に爆発的に増加することなく、関連するすべての組み合わせをチェックできます。 
6. 条件に違反するサブセットがない場合は、-1 を返します。 それ以外の場合は、候補プール内で見つかったすべての違反サブセットの最小合計を返します。 

重要な隠れたステップは、セグメント ツリーによって必要な桁多様性情報が決して失われないようにすることです。 ほとんどの要素を破棄しても、サブセット内で桁位置がサポートされない可能性があるかどうかを検出するのに十分な構造を保持します。 

### なぜ効果があるのか

 正確さは、最小和の不均衡サブセットは、和への局所的な寄与が最小限でありながら、ある桁の位置でカバレッジを破る可能性がある要素で構成されている必要があるという事実から得られます。 要素が大きいと違反合計が小さくなる可能性がないため、要素が小さい場合は無視しても問題ありません。 セグメント ツリーは、すべての範囲のこれらの代表を正確に維持し、マージ中に潜在的な最適な答えが失われないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [[] for _ in range(4*self.n)]
        self.arr = arr
        self.build(1, 0, self.n-1)

    def digits(self, x):
        s = str(x)
        return list(map(int, s))

    def build(self, v, l, r):
        if l == r:
            self.t[v] = [self.arr[l]]
        else:
            m = (l + r) // 2
            self.build(v*2, l, m)
            self.build(v*2+1, m+1, r)
            self.t[v] = sorted(self.t[v*2] + self.t[v*2+1])[:10]

    def query(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.t[v]
        if r < ql or l > qr:
            return []
        m = (l + r) // 2
        left = self.query(v*2, l, m, ql, qr)
        right = self.query(v*2+1, m+1, r, ql, qr)
        return sorted(left + right)[:10]

def is_unbalanced(subset):
    if not subset:
        return False
    total = sum(subset)
    s = str(total)
    for i, d in enumerate(reversed(s)):
        ok = False
        for x in subset:
            if i < len(str(x)) and int(str(x)[-(i+1)]) == d:
                ok = True
                break
        if not ok:
            return True
    return False

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    st = SegTree(a)

    for _ in range(m):
        tmp = input().split()
        if tmp[0] == '1':
            i, x = int(tmp[1]) - 1, int(tmp[2])
            a[i] = x
            st = SegTree(a)
        else:
            l, r = int(tmp[1]) - 1, int(tmp[2]) - 1
            cand = st.query(1, 0, n-1, l, r)
            ans = float('inf')
            from itertools import combinations
            for k in range(1, len(cand)+1):
                for comb in combinations(cand, k):
                    if is_unbalanced(comb):
                        ans = min(ans, sum(comb))
            print(-1 if ans == float('inf') else ans)

if __name__ == "__main__":
    solve()
```このコードは、ノードごとに代表値の小さなセットを保存しようとするセグメント ツリーを構築します。 各クエリは、縮小された候補プールを抽出し、そのプール内でのみブルート フォースを実行して、最小限の不均衡なサブセットを検出します。 更新操作では、変更時に正確性を維持するために構造が再構築されます。 

の`is_unbalanced`関数は、合計の各桁位置をサブセット要素の桁と比較することにより、桁条件を直接実装します。
