 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、その「適切な」部分文字列を数えるように求められます。 部分文字列は、その長さがバイナリ表現の 10 進数値と等しく、先行ゼロを許容する場合に適しています。 つまり、次のような部分文字列の場合、`011`、つまり`3`10 進数では、長さも次の場合にのみ有効です。`3`。 入力は複数のクエリで構成されており、各クエリには 1 つのバイナリ文字列が含まれており、各クエリの出力はその文字列内の適切な部分文字列の数です。 

この制約により最大 1000 個のクエリが可能になり、すべてのクエリの長​​さの合計は最大 200,000 になります。 これは、考えられるすべての部分文字列を単純に反復するアルゴリズムは遅すぎることを意味します。すべての部分文字列を生成するのは非常に難しいためです。$O(n^2)$に到達する可能性があります$4 \cdot 10^{10}$最悪の場合の運用。 より近い解決策が必要です$O(n \cdot \text{small factor})$、実際には理想的には直線的です。 

注目すべきエッジケースは、先頭にゼロが付いている部分文字列です。 例えば、`000`10進数値を持つ`0`したがって、長さ 0 の部分文字列のみが対象となりますが、これは不可能です。 もう 1 つの微妙なケースは、ゼロの長いシーケンスとその後に 1 つの 1 が続く場合です。`0001`。 のような部分文字列`001`小数がある`1`しかし長さ`3`、だからダメなんです。 部分文字列の長さごとに 2 進数から 10 進数への変換を慎重に計算しない不注意なアプローチでは、過大カウントまたは過少カウントが発生する可能性があります。 

## アプローチ

 素朴なアプローチは、すべての部分文字列を考慮し、それを 10 進数に変換し、部分文字列の長さが 10 進数値と一致するかどうかを確認することです。 これは論理的には正しいですが、次のことが必要です$O(n^2)$クエリごとの反復回数。 バイナリ文字列を10進数に変換するだけでも時間がかかります$O(n)$部分文字列ごとに計算されるため、最悪の場合の複雑さは次のようになります。$O(n^3)$、これは許容範囲をはるかに超えています。 

効率的な解決策の重要な観察点は、バイナリ値が整数として解釈される場合、約 20 文字を超える部分文字列は「適切」とは言えないということです。 これは、部分文字列の長さがバイナリで表現された値よりもすぐに小さくなるためです。 たとえば、すべて 1 の 20 ビットの部分文字列は次のようになります。$2^{20}-1 \approx 10^6$、入力制約内の文字列の長さをはるかに超えています。 したがって、各位置から約 20 ビットまでの部分文字列をチェックするだけで済みます。 

さらに、先頭のゼロを効率的にスキップする必要がありますが、先頭のゼロを含める場合は、先頭のゼロが原因で 10 進数値が長さより小さい部分文字列を誤ってカウントしないようにする必要があります。 この洞察により、すべての部分文字列にわたる二次スキャンから、固定された小さなウィンドウを使用した各開始位置にわたる線形スキャンに問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 最適 | O(n * 20) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. クエリ数を読み取る`t`各クエリを反復処理します。 
2. 文字列ごとに`s`長さの`n`、カウンターを初期化します`ans = 0`適切な部分文字列の数を蓄積します。 
3. 各開始インデックスをループします。`i`文字列の中で。 
4. 最初は先頭のゼロをスキップするか、個別に考慮します。 10 進数値の構築を開始する`val = 0`。 
5. 各エンドインデックスについて`j`から始まる`i`最大 20 文字まで (または文字列が終了するまで) 更新します。`val = val * 2 + int(s[j])`。 
6. 部分文字列の長さを次のように計算します。`length = j - i + 1`。 
7. もし`val == length`、増分`ans`1.の場合`val > length + 20`、これ以上延長しても条件を満たすことができないため、早めに中断します。 
8. すべての開始位置を終了したら、カウンターを印刷します。`ans`。 

機能する理由: 不変条件は、開始インデックスごとに、長さが 10 進数値に相当する部分文字列のみを考慮することです。これにより、潜在的な適切な部分文字列を見逃すことがなくなります。 これより長い 2 進数は文字列の最大長を超えるため、20 文字の境界で十分です。これにより、非現実的な部分文字列の長さを反復することなく正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_good_substrings(s):
    n = len(s)
    ans = 0
    for i in range(n):
        if s[i] == '0':
            continue
        val = 0
        for j in range(i, min(n, i + 20)):
            val = val * 2 + int(s[j])
            length = j - i + 1
            if val == length:
                ans += 1
            if val > n:
                break
    return ans

t = int(input())
for _ in range(t):
    s = input().strip()
    print(count_good_substrings(s))
```このソリューションは入力を効率的に読み取り、複数のクエリを処理します。 内部ループは最大 20 文字のみなので、タイムアウトが回避されます。 小切手`val > n`実現可能な部分文字列の長さを超える不必要な反復を防ぎます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    def count_good_substrings(s):
        n = len(s)
        ans = 0
        for i in range(n):
            if s[i] == '0':
                continue
            val = 0
            for j in range(i, min(n, i + 20)):
                val = val * 2 + int(s[j])
                length = j - i + 1
                if val == length:
                    ans += 1
                if val > n:
                    break
        return ans

    t = int(input())
    res = []
    for _ in range(t):
        s = input().strip()
        res.append(str(count_good_substrings(s)))
    return "\n".join(res)

 のような文字列の場合`00001000`、アルゴリズムはインデックス 4 まで開始位置の先頭のゼロをスキップします。インデックス 4 からはカウントされます。`1`長さ 1、`10`長さ 2 など、正しく識別されます。`4`良い部分文字列。 のような部分文字列`0000`10 進数値は次のとおりであるため、無視されます。
