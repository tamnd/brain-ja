 ## 解決策
 ## 問題の理解

 私たちは 2 つの相互作用するレイヤーにわたる重み付き選択問題に取り組んでいます。 

まず、惑星の小さな固定グラフがあり、距離はノード間のワームホールの最短数として測定されます。 そして、これらの惑星には大規模な宇宙船と基地が配置されています。 各宇宙船には強度の制約、グラフ内で移動できる距離を制限する燃料制限、および運用コストがあります。 各拠点には防御値と報酬値があります。 

宇宙船と基地を組み合わせることができるのは、基地が強すぎず、グラフの距離の点で宇宙船の燃料制限内に到達できる場合に限られます。 複数の基地に到達可能な場合、宇宙船は常に、ベースゴールドから運用コストを差し引いた利益を最大化する基地を選択します。 

この独立したペアリング構造に加えて、船間には依存関係システムがあります。 船を起動すると、直接的または間接的に、その船が依存するすべての船を起動する必要があります。 目標は、総利益を最大化しながら、これらの依存関係の下で閉鎖される一連の船舶を選択することです。 

重要な相互作用は、船舶が世界的に基地を選択しないことです。 各船は到達可能な最適な基地を個別に選択しますが、船をアクティブにする決定は依存関係を通じてグローバルに結合されます。 

この制約は、2 つの主要なアルゴリズム上の圧力を意味します。 グラフのサイズは小さく、最大 100 ノードなので、全ペアの最短パスが実現可能です。 ただし、船と基地は最大 100,000 になるため、船と基地の間のペアごとのマッチングは、船ごとに線形または線形に近い値に減らす必要があります。 依存関係グラフもまばらで、エッジは最大 1000 個ですが、それでも最大 100000 個のノードにまたがるため、ブルート フォースのサブセットではなく、フローまたはクロージャ構造として扱う必要があることがわかります。 

単純なアプローチでは、各船について、到達可能なすべての基地を再計算し、依存関係を考慮して船のすべてのサブセットを試行します。 これはすぐに 2 つの場所で壊れます。1 つは船と基地のペアが大きすぎること、もう 1 つは依存関係の制約によりサブセットの選択が指数関数的になることです。 

複数の船が同じ最適なベースを共有しているものの、依存関係チェーンが異なる場合、微妙な障害が発生します。 収益性の高い船舶を個別に貪欲に選択すると、単一の高利益船舶をアクティブ化すると大きな負の連鎖が強制的にアクティブ化される可能性があるため、実現可能性が損なわれる可能性があります。 

## アプローチ

 この構造は、2 つの独立した部分問題に自然に分割されます。 

1 つ目は、各艦艇の可能な限り最適な目標基地を評価することです。 2 つ目は、依存関係の制約の下で船舶のサブセットを選択することです。 

最初の部分では、ブルート フォース ソリューションにより、すべての基地に対してすべての船が試行され、元のグラフで BFS を使用して最短経路の実現可能性がチェックされます。 BFS の再利用が不十分で慎重に実行すると、これはおよそ O(s · b · n) のコストがかかりますが、10^10 の操作では遅すぎます。 

重要な観察点は、グラフが小さいことです。 O(n^3) で Floyd-Warshall を使用すると、惑星間のすべてのペアの最短経路を事前計算できます。 その後、すべての船舶基地実行可能性チェックは O(1) になります。 これにより、ペアリングの問題が、事前に計算された距離に対する純粋な最適化に軽減されます。 

これで、各船は強度と距離の制約を満たすすべての基地を評価し、最適な金の価値を選択できるようになりました。 これにより、船舶ごとに 1 つの利益値が得られます。 

2 番目の部分は、前提条件のある制約のある船舶に関する最大重量の選択問題になります。 各依存関係「s1 は s2 に依存する」は、s1 を選択すると s2 が強制的に選択されることを意味します。 これは、有向閉鎖制約を定義します。有効な船舶のセットは、出力依存関係エッジの下で閉鎖されなければなりません。

これはまさに有向グラフ上の最大重み閉包問題であり、古典的に最小カット公式を使用して解決されます。 ノードの選択が利益またはペナルティを表す最先端に対応し、依存関係のエッジが無限の容量を持つ包含制約を強制するフロー ネットワークを構築します。 

ノードの数が多いにもかかわらず、依存関係エッジの数は少ないため、慎重に実装した maxflow ソリューションにとってグラフは十分にまばらなままです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシップベース + サブセット検索 | O(s · b · 2^s) | お(1) | 遅すぎる |
 | フロイド + 船ごとの評価 + 最小カットによる最大クロージャ | O(n^3 + s・n + maxflow(s + k)) | O(n^2 + s + k) | 承認済み |

 ## アルゴリズムのチュートリアル

 前処理、利益計算、選択を分離します。 

1. Floyd-Warshall を使用して、惑星間のすべてのペアの最短経路を計算します。 これにより、ノードのペアごとに dist[u][v] が得られます。 これが必要なのは、船舶の燃料制約は最短経路に依存しており、BFS を繰り返すと 100,000 隻の船舶では遅すぎるためです。 
2. 惑星ごとに、そこにあるすべての基地を保存します。 ベースはノードに関連付けられているため、これによりベース セットが最大 100 個のバケットに分割されます。 
3. 各船について、可能な限り最適なベースを計算します。 ノード u にある燃料 f と攻撃力 a の船については、dist[u][v] ≤ f となるようにすべてのノード v を検査します。 このようなノードごとに、防御力が最大でも a である基地のみを考慮します。 到達可能なノード全体のすべての有効な基地の中から、運用コストを差し引いた最大のゴールドを持つ基地を選択します。 

このステップにより、すべての船舶と基地のインタラクションが船舶ごとに 1 つの値に圧縮されます。これは、二部構成の爆発を除去するため、非常に重要です。 
4. 船に有効な基地がない場合、その船は決して選択できないため、その貢献は選択段階では無関係なものとして扱われます。 
5. 依存関係エッジを使用して船舶上の有向グラフを構築します。 各エッジ s1 → s2 は、s1 を選択すると s2 が強制的に選択されることを意味します。 
6. これを最大重量閉包問題に変換します。 ソースとシンクを備えたフロー ネットワークを構築します。 各船はノードです。 船舶の利益がプラスの場合、利益に等しい容量でソースを船舶に接続します。 利益がマイナスの場合は、絶対値と等しい容量のシンクに接続します。 依存関係エッジは、依存関係にあるシップから前提条件となるシップへの無限容量エッジとして追加されるため、両方が一貫して含まれていない限り、切断は実現可能性に違反します。 
7. 最小の s-t カットを計算します。 結果として得られる削減により、船舶の最適な閉じたセットが定義され、その答えは、合計のプラスの利益から削減コストを差し引いたものになります。 

### なぜ効果があるのか

 フロー構造は一貫性の制約をエンコードしています。つまり、依存関係のエッジには無限の容量があるため、それを切断するとコストが高くなり、依存関係にある船は切断の同じ側に留まらざるを得なくなります。 ソースエッジとシンクエッジは利益のトレードオフをエンコードしており、利益がコスト構造を上回る場合にのみ船舶を選択することが有益であることが保証されます。 したがって、min-cut は、依存関係の下で最適なクロージャに正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

class Dinic:
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(n)]

    def add_edge(self, u, v, c):
        self.adj[u].append([v, c, len(self.adj[v])])
        self.adj[v].append([u, 0, len(self.adj[u]) - 1])

    def bfs(self, s, t):
        self.level = [-1] * self.n
        q = [s]
        self.level[s] = 0
        for u in q:
            for v, c, _ in self.adj[u]:
                if c > 0 and self.level[v] < 0:
                    self.level[v] = self.level[u] + 1
                    q.append(v)
        return self.level[t] >= 0

    def dfs(self, u, t, f):
        if u == t:
            return f
        for i in range(self.it[u], len(self.adj[u])):
            self.it[u] = i
            v, c, rev = self.adj[u][i]
            if c > 0 and self.level[v] == self.level[u] + 1:
                ret = self.dfs(v, t, min(f, c))
                if ret:
                    self.adj[u][i][1] -= ret
                    self.adj[v][rev][1] += ret
                    return ret
        return 0

    def max_flow(self, s, t):
        flow = 0
        while self.bfs(s, t):
            self.it = [0] * self.n
            while True:
                f = self.dfs(s, t, INF)
                if not f:
                    break
                flow += f
        return flow

n, m = map(int, input().split())
dist = [[INF] * n for _ in range(n)]
for i in range(n):
    dist[i][i] = 0

for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    dist[u][v] = dist[v][u] = 1

for k in range(n):
    for i in range(n):
        for j in range(n):
            if dist[i][j] > dist[i][k] + dist[k][j]:
                dist[i][j] = dist[i][k] + dist[k][j]

s, b, k = map(int, input().split())

ships = []
for _ in range(s):
    x, a, f, p = map(int, input().split())
    ships.append((x - 1, a, f, p))

bases_at = [[] for _ in range(n)]
for _ in range(b):
    x, d, g = map(int, input().split())
    bases_at[x - 1].append((d, g))

deps = [[] for _ in range(s)]
for _ in range(k):
    u, v = map(int, input().split())
    deps[u - 1].append(v - 1)

profits = []
for i in range(s):
    x, a, f, p = ships[i]
    best = 0
    for v in range(n):
        if dist[x][v] <= f:
            for d, g in bases_at[v]:
                if d <= a:
                    best = max(best, g - p)
    profits.append(best)

N = s + 2
SRC = s
SNK = s + 1
dinic = Dinic(N)

total_positive = 0

for i in range(s):
    w = profits[i]
    if w > 0:
        dinic.add_edge(SRC, i, w)
        total_positive += w
    else:
        dinic.add_edge(i, SNK, -w)

INF_CAP = 10**15
for u in range(s):
    for v in deps[u]:
        dinic.add_edge(u, v, INF_CAP)

cut = dinic.max_flow(SRC, SNK)
print(total_positive - cut)
```フロイド-ウォーシャル ステップにより、すべての船舶がノードごとに一定時間で到達可能性を評価できるようになります。 ノード数が 100 しかないため、シップとノードにわたるネストされたループは許容されます。 

依存関係のエッジは閉包を強制する方向に追加されます。u が v に依存する場合、容量が無限であるため、v なしで u を切断することは不可能になります。 最終結果は、標準の最大クロージャ恒等式 (正の重みの合計から最小カットを差し引いたもの) から導出されます。 

## 実用的な例

 ### サンプル 1

 まず、6 ノード グラフ上の最短パスを計算します。 その後、各艦艇は燃料制約と強度制約の下で到達可能な基地を評価し、利益値を生成します。 

| 船 | 選ばれた最良のベース | 利益 |
 | --- | --- | --- |
 | 1 | 基数 1 | 正の計算値 |
 | 2 | 基数 1 | 正の計算値 |
 | 3 | なし / 悪い | 否定的または無視される |
 | 4 | 基数 2 | ポジティブ |

 利益を計算した後、依存関係のクロージャーを適用します。 船 1、2、および 4 は依存関係ルールに基づいて実行可能なクロージャを形成しますが、他の組み合わせは前提条件に違反するか、総利益が減少します。 

maxflow ステップはまさにこのクロージャを選択し、最終的な利益 2 を生成します。 

このトレースは、依存関係の制約によって他の船が強制的に含められると、船 3 は無関係になるため、個々の収益性が十分ではないことを示しています。 

### サンプル 2

 一方が他方に依存する 2 隻の船による単純化されたシナリオを考えてみましょう。 

| 船 | 利益 | 依存関係 |
 | --- | --- | --- |
 | あ | 5 | B に依存します |
 | B | -3 | なし |

 A だけを選択すると、B を含めざるを得なくなり、合計利益は 2 になります。A をスキップすると、B を完全に回避して 0 が得られます。正解は 2 で、フロー構築はこの強制的なトレードオフを正しく捉えています。 

これは、貪欲な選択が失敗する理由を示しています。A を個別に評価すると、それを採用することが提案されますが、依存関係のコストをグローバルに考慮する必要があります。

 ## 特殊なケース

 重要なエッジ ケースとは、単独では利益をあげているように見えても、依存関係チェーンが含まれると利益が得られなくなる船舶のことです。 無限容量エッジによりチェーンの部分的な選択が妨げられるため、流れの定式化ではこの結合が強制されます。 

もう 1 つのエッジ ケースは、到達可能な基地を持たない船舶です。 これらは、選択グラフ内で常に寄与がゼロであるものとして扱われなければなりません。そうしないと、クロージャの最適化が誤って歪められます。 

最後のエッジケースは、同じ最適な基地を共有する複数の船です。 これは最終モデルでは問題になりません。基地の選択は船ごとにローカルであり、ゴールドは攻撃ごとに効果的に複製されるため、リソースの競合をモデル化する必要はありません。
