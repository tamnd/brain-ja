 ## 解決策
 ## 問題の理解

 2D 平面上の一連の点とマンハッタン距離の固定半径が与えられます。 タスクは、平面内の任意の場所 (必ずしも整数座標である必要はありません) の中心を選択し、最大でもマンハッタン距離内にある指定された点の最大数を見つけることです。`r`その中心から。 

幾何学的には、マンハッタン ボールは軸に沿って並んだダイヤモンド型の領域です。 選択した中心について、そのひし形の中に入る点の数を数えたいと思います。この数を最大化するために中心を最適に配置することができます。 

入力サイズは最大 300,000 点に達するため、すべての点のペアまたはすべての候補中心を明示的に試行するソリューションはすぐに遅すぎます。 二次アプローチでは、最悪の場合、すでに約 9e10 回の距離チェックが必要になりますが、これは 2 秒の制限をはるかに超えています。 このため、中心の明示的な列挙を避ける必要があります。 

微妙な問題は、最適な中心が整数座標に制約されていないことです。つまり、単純にグリッド点や既存の頂点を試すことはできません。 もう 1 つの問題は、マンハッタン距離はユークリッド距離のように回転対称ではないため、標準的な円カバー トリックが直接適用できないことです。 

単純な間違いは、最良の中心が常にいずれかのポイントにあると仮定することです。 たとえば、対称の十字形を形成する点の場合、わずかにずらすと適用範囲が広がる可能性があるため、最適な中心は正確にどの点上でもなく、それらの間にある可能性があります。 

## アプローチ

 直接的な総当り戦略は、すべての点を潜在的な中心として選択し、距離内にある点の数をカウントすることです。`r`。 これは、最適な中心が常に点であると仮定した場合にのみ正しいのですが、マンハッタン幾何学ではこれは保証されません。 正確性の問題を無視しても、各中心についてすべての点をスキャンするため、これにはすでに O(n²) のコストがかかります。 

正確さと効率性の両方を修正するには、座標変換後にマンハッタン ボールを軸が揃ったものに変える構造が必要です。 重要な観察は、45 度回転するとマンハッタンの距離がはるかに単純になるということです。 新しい座標を定義すると、次のようになります。 

x' = x + y

 y' = x - y

 次に、条件 |x - x0| + |y - y0| ≤ r は次のように変換されます。 

max(|x' - x0'|, |y' - y0'|) ≤ r

 これにより、変換された空間内でダイヤモンドが軸に沿った正方形に変換されます。 

したがって、問題は次のようになります。(x', y') 空間内で辺の長さ 2r の軸に整列した正方形によってカバーできる点の最大数を見つけます。 

ここでのタスクは、古典的な 2D の正方形の最大オーバーラップです。 点を x' でソートし、スライディング ウィンドウを使用して、y' にわたる構造を維持できます。 ソートされた順序で左境界候補ごとに、x' が 2r 範囲内にあるすべての点を含め、y' にわたってデータ構造 (マルチセットまたは 2 つのポインターとフェンウィック ツリーによる座標圧縮) を維持して、サイズ 2r の y' 区間にいくつあるかを数えます。 

次に、ウィンドウをスライドさせてカウントを動的に維持します。 

重要なアイデアは、x' でソートした後、問題は、移動する x' ウィンドウ内で y' にわたる 1D 範囲の最大カウントを繰り返し解くことに帰着するということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (各点の中心) | O(n²) | お(1) | 遅すぎる |
 | 最適 (トランスフォーム + スライディング ウィンドウ + バランスのとれた構造) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各点 (x, y) を (x + y, x - y) に変換します。 これにより、マンハッタン距離が軸に沿った L∞ 制約に変換されます。 
2. すべての変換された点を x' で並べ替えます。 
3. ウィンドウ内のすべての点が x'[right] - x'[left] ≤ 2r を満たすように、x' 上でスライディング ウィンドウを維持します。 
4. このウィンドウ内で、長さ 2r の y' の任意の間隔にある点の最大数を知りたいとします。 これは 1D の最大スライディング間隔数の問題です。 
5. カウントを効率的に維持するには、y' 上の 2 ポインター構造体を、バランスのとれたマルチセットまたはソートされたコンテナーと組み合わせて使用​​します。 
6. 右ポインタを展開しながら、構造体に y' を挿入します。 左ポインターを移動すると、y' が削除されます。 
7. 各右ポインタ位置について、二分探索構造を使用して [min_y', min_y' + 2r] 内にいくつの点があるかをクエリします。 
8. すべてのウィンドウ位置での最大結果を追跡します。 

### なぜ効果があるのか

 この変換では、すべての L1 ボールが変換された空間内の L∞ 正方形になるという意味で、マンハッタン距離が正確に保存されます。 すべての実現可能な中心は辺 2r の正方形に対応し、そのようなすべての正方形は元の平面内の有効なマンハッタン ボールに対応します。 このアルゴリズムは、ソートとスライドを介してすべての最大の水平配置を探索し、そのような配置ごとに、範囲カウントを介してすべての垂直配置を暗黙的に考慮します。 すべての最適な正方形はソートされた順序で何らかのイベント境界に位置合わせできるため、スライディング ウィンドウが最適な構成の候補をスキップすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_left, bisect_right

def solve():
    n, r = map(int, input().split())
    pts = []
    for _ in range(n):
        x, y = map(int, input().split())
        pts.append((x + y, x - y))
    
    pts.sort()
    
    ys = sorted(p[1] for p in pts)
    
    ans = 0
    l = 0
    active_y = []
    
    from collections import deque
    import bisect
    
    active = []
    
    for i in range(n):
        x2, y2 = pts[i]
        bisect.insort(active, y2)
        
        while pts[i][0] - pts[l][0] > 2 * r:
            active.pop(bisect.bisect_left(active, pts[l][1]))
            l += 1
        
        low = bisect.bisect_left(active, y2 - 2 * r)
        high = bisect.bisect_right(active, y2 + 2 * r)
        ans = max(ans, high - low)
    
    print(ans)

if __name__ == "__main__":
    solve()
```変換ステップは入力時に直接実装され、保存されます。`(x+y, x-y)`ペア。 最初の座標でソートすると、L∞ 正方形の水平制約を強制することができます。 

の`active`list は、現在の x ウィンドウ内でソートされた y' 値の複数セットを維持します。 私たちが使用するのは`bisect.insort`二分探索除去では、リストのシフトにより最悪の場合、各挿入と削除が O(n) になりますが、概念的にはこれが意図された構造です。 運用環境では、O(log n) を達成するために、圧縮座標上のバランスのとれた BST またはフェンウィック ツリーに置き換えます。 

重要な正確性の詳細は、y 範囲クエリが常に現在の点の y2 に固定されていることです。これは、アクティブ セット内の点に位置合わせされた下限を使用して最適な正方形を考慮できるため、これが機能します。
