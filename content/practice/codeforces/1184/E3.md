 ## 解決策
 ## 問題の理解

 重み付けされたエッジを持つ無向接続グラフが与えられます。各エッジは 2 つの場所間の通路を表し、関連するエネルギー値を持ちます。 すべてのコリドーについて、さまざまなエッジ ウェイトしきい値の下でそのコリドーがスパニング ツリー構造とどのように相互作用するかに応じて値を計算するように求められます。 

このタスクを解釈する便利な方法は次のとおりです。許容されるコリドー エネルギーの制約を徐々に「厳しくする」と想像してください。 しきい値を下げると、一部の廊下が使用できなくなります。 元のエッジごとに、そのエッジのエネルギーをそのしきい値までわずかに変更しても、そのエッジがグラフの残りの部分によって誘導される有効な最小スパニング構造に表示される可能性がある、可能な最高のしきい値を見つけたいと考えています。 

したがって、すべてのエッジについて、グラフ内のすべての代替パスと競合するときに、少なくとも 1 つの最小スパニング ツリー構成の一部となる資格を維持しながら、その重みをどこまで削減できるかを事実上尋ねることになります。 

制約は大きいです。 最大 10^5 のノードと最大 10^6 のエッジを使用すると、エッジごとにパスを検査したりスパニング ツリーを再計算したりするソリューションは、直ちに遅すぎます。 単一の MST 構築でも O(m log n) ですが、エッジごとにこれを行うと限界をはるかに超えます。 これにより、各エッジの答えがすべての MST の構造化表現の 1 回または数回の走査から導出される、グローバルな前処理の観点が強制されます。 

重要な微妙な点は、最小スパニング ツリーが一意ではない可能性があり、同じ重みを持つ複数のエッジによって結合が作成される可能性があることです。 単純な Kruskal 実行では 1 つの MST が得られますが、答えは、選択された 1 つのツリーだけではなく、_考えられるすべての MST 代替案_に依存します。 

よくある失敗例は、MST ツリーのエッジのみが重要であると想定している場合です。 たとえば、1 つの MST を選択し、ツリー構造のみを考慮すると、その特定の MST には存在しないが、タイブレークがわずかに異なる別の MST に出現する可能性があるエッジを見逃してしまいます。 もう 1 つの失敗は、サイクル構造によって置換の可能性が決まるため、サイクルにまだ参加している重いエッジを無視することです。 

## アプローチ

 強引なアイデアは、各エッジを個別に処理することです。 固定エッジの場合は、その重みを何らかの値に設定し、最小スパニング ツリーを再計算して、エッジが含まれているかどうかを確認することを想像できます。 有効な最大値を見つけるには、重みを二分探索し、毎回 MST を再計算します。 

各 MST 計算には O(m log n) のコストがかかり、30 個の値に対する二分探索を使用してすべてのエッジに対してこれを実行すると、およそ O(m log n log C) になります。 m が 10^6 までの場合、これはすでに境界線に達しており、実際には一定の要因と繰り返しのソートまたはヒープ操作により遅すぎます。 

構造的な洞察は、MST の動作がスパニング ツリー内のパス上のサイクルと最大エッジによって完全に制御されるということです。 スパニング ツリーを修正すると、非ツリー エッジについては、MST に入る能力は、ツリー内のエンドポイント間の一意のパスに沿った最大エッジ重みに依存します。 これにより、問題はグローバルな再計算からパス最大のクエリにまで軽減されます。 

ただし、一意な MST はないため、_すべての MST と同等の選択肢_ を取得する構造が必要です。 これは、Kruskal プロセスを構築しながら、「接続パス上の最大エッジ」情報を保持する方法でコンポーネントをマージするというアイデアにつながります。 正しいツールは、しばしば Kruskal 再構成ツリーと呼ばれる、マージのツリーに拡張された Union-Find 構造です。 これは、エッジの重みの増加に応じてコンポーネントがどのようにマージされるかをエンコードし、このツリー内のパス クエリは、MST に準拠した構造内の最大エッジに対応します。 

このツリーが構築されると、元の各エッジをマージ ツリー内の最も低い共通祖先問題にマッピングでき、その答えはパス上の単一の最大重みクエリに減ります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (エッジごとに MST を再計算) | O(m² log n) | O(n + m) | 遅すぎる |
 | Kruskal + 再構築ツリー + LCA クエリ | O(m log m + m log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 Kruskal スタイルのマージ プロセスを構築しますが、構造を破棄する代わりに、コンポーネント マージのバイナリ ツリーを明示的に構築します。 

1. すべてのエッジを重みで降順でない順に並べ替えます。 これは、Kruskal がそれらを考慮する順序と一致し、MST 制約をしきい値の昇順で処理することを保証します。 
2. 各ノードが独自のコンポーネントである DSU を初期化します。 また、結合操作を表す別の「マージ ツリー」に新しいノードを作成します。 
3. ソートされた順序でエッジを処理します。 コンポーネント a と b を重み w で接続するエッジについて、それらの DSU ルートを見つけます。 それらが異なる場合は、これら 2 つのコンポーネントの結合を表す新しいノードを作成し、それに重み w を割り当て、2 つのコンポーネントのルートをこのノードの子として接続します。 次に、DSU でそれらをこの新しいノードに結合します。 

各マージ ノードは、クラスカルのプロセスで 2 つのコンポーネントが接続される正確な瞬間を表しており、そのマージの重みがそれらを接続する最小のエッジであるため、このステップは非常に重要です。 
4. すべての結合の後、最大 2n 個のノードを持つツリーが得られます。 元のノードはリーフであり、内部ノードはルート パスに沿って重みが増加するマージを表します。 
5. LCA クエリ用にこのマージ ツリーを前処理し、各ノードの親と深さを保存します。 
6. 元のエッジ (u、v、w) ごとに、マージ ツリー内の u と v の LCA を計算します。 その LCA ノードに関連付けられた値は、クラスカルのプロセスで u と v が接続される最小のしきい値を表します。 エッジに必要な答えは、この LCA 重みです。 

直感的には、マージ ツリーは、すべての MST 一貫性のある構造にわたる任意の 2 つの頂点間の正確な接続しきい値をエンコードしていると考えられます。 

### なぜ効果があるのか

 マージのたびに、指定された重みまでのエッジを使用して 2 つのコンポーネントが接続できる最も早い時点をシミュレートします。 元の 2 つの頂点間のパスはすべて、このマージ ツリー内の最も低い共通の祖先を通過する必要があり、その祖先での重みが、頂点間の接続を許可する最小しきい値になります。 この値は、MST サイクルでの置換動作を制御する最も強力なボトルネック エッジを特徴付けます。これはまさに、ある MST でエッジを置換できるかどうかを決定するものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
edges = []
for i in range(m):
    a, b, w = map(int, input().split())
    edges.append((w, a - 1, b - 1, i))

edges.sort()

parent = list(range(2 * n))
value = [0] * (2 * n)
children = [[] for _ in range(2 * n)]

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

next_id = n

for w, a, b, _ in edges:
    ra, rb = find(a), find(b)
    if ra != rb:
        cur = next_id
        next_id += 1
        value[cur] = w
        parent[ra] = cur
        parent[rb] = cur
        children[cur].append(ra)
        children[cur].append(rb)

for i in range(2 * n):
    find(i)

LOG = 20
up = [[-1] * (2 * n) for _ in range(LOG)]
depth = [0] * (2 * n)

root = next_id - 1 if next_id > n else 0

stack = [root]
order = []
while stack:
    v = stack.pop()
    order.append(v)
    for c in children[v]:
        depth[c] = depth[v] + 1
        up[0][c] = v
        stack.append(c)

for k in range(1, LOG):
    for v in range(2 * n):
        if up[k - 1][v] != -1:
            up[k][v] = up[k - 1][up[k - 1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    k = 0
    while diff:
        if diff & 1:
            a = up[k][a]
        diff >>= 1
        k += 1
    if a == b:
        return a
    for k in reversed(range(LOG)):
        if up[k][a] != up[k][b]:
            a = up[k][a]
            b = up[k][b]
    return up[0][a]

ans = [0] * m
for w, a, b, i in edges:
    l = lca(a, b)
    ans[i] = value[l]

sys.stdout.write("\n".join(map(str, ans)))
```最初の部分では、Kruskal マージ ツリーを構築します。ここで、各結合は、マージを担当するエッジの重みでラベル付けされた新しい内部ノードを作成します。 の`value`配列にはこのしきい値情報が格納されます。 

DFS スタイルのトラバーサルでは、LCA クエリ用のバイナリ リフティング テーブルが準備されます。 各ノードは 2 の累乗距離で祖先を保存し、高速ジャンプを可能にします。 

各エッジについて、マージ ツリー内のエンドポイントの LCA をクエリします。 その LCA は、それらの頂点を接続する最も早いマージ ポイントに対応し、その格納された値は、そのエッジの適切な最大実現可能しきい値になります。 

微妙な点は、DSU マージが概念的には無向であるにもかかわらず、マージ構造をルート付きツリーとして扱うことです。 構築された親ポインタは、各新しいノードの重み順が厳密に高いため、有効な階層を強制します。

### サンプル 2

 入力:```
4 4
1 2 5
2 3 6
3 4 1
1 4 4
```並べ替え:

 | ステップ | エッジ | 重みをマージ |
 | --- | --- | --- |
 | 1 | 3-4 | 1 |
 | 2 | 1-4 | 4 |
 | 3 | 1-2 | 5 |
 | 4 | 2-3 | 6 |

 この構造は、重みの低いエッジが最初にマージされ、より高いエッジがその上に接続される階層を構築します。 

エッジ 1 ～ 4 の場合、その LCA は重み 4 で発生します。これは、再構築ツリー内でエッジが接続される最初の点であるためです。 

エッジ 2 ～ 3 の場合、接続は 6 の上部マージでのみ発生します。 

これは、非ツリー エッジでも、選択した MST に直接含めるのではなく、構造的な接続からどのように答えを得るかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m log m + m log n) | エッジの並べ替えが第 1 フェーズを支配し、LCA クエリはエッジごとに対数的になります。 
| スペース | O(n + m) | マージ ツリーには最大 2n ノードとバイナリ リフティング テーブルが含まれます。 

この制約では最大 10^6 のエッジが許可されるため、ソートと線形 DSU 操作および対数クエリは、最適化された Python の制限内に快適に収まります。

 ## 特殊なケース

 重要なエッジ ケースは、複数のエッジが同じ重みを共有する場合です。 その状況では、Kruskal はコンポーネントを異なる順序でマージする可能性がありますが、すべての等しい重みのエッジがソートされた順序で一緒に処理されるため、再構築ツリーは依然として同じレベルでコンポーネントをマージします。 このアルゴリズムでは、このようなマージはすべて同じ重みでラベル付けされたノードの下で行われ、正しいボトルネック値が維持されるため、あいまいさが LCA 構造に影響を与えないことが保証されます。 

グラフがすでにツリーになっている場合、別の特殊なケースが発生します。 この場合、すべてのエッジは MST の一部となり、各エッジは独自の重みを返す必要があります。 再構成ツリーでは、各エッジが直接マージ ノードになるため、そのエンドポイントの LCA はまさにそのエッジによって作成されたノードとなり、正しい値が即座に生成されます。 

最後のエッジ ケースは、グラフが密で、2 つのノード間に複数の代替パスが存在する場合です。 再構築ツリーは、これらすべての選択肢をマージの単一階層に圧縮し、多くのサイクルが存在する場合でも、答えは最初にエンドポイントを接続する最もボトルネックの高いマージにのみ依存することを保証します。
