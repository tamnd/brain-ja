 ## 解決策
 ## 問題の理解

 銀河は、ワームホールによって接続された惑星の小さなグラフであり、惑星間の距離は、このグラフのエッジの最小数として測定されます。 このインフラストラクチャの上には、帝国の船と反乱軍の基地という 2 種類のアクターがあります。 各船は惑星上にあり、攻撃力があり、燃料は限られています。 各基地も惑星上にあり、防御値があります。 

船が基地を破壊できるのは、船が十分に強く、その燃料がグラフ内の最短経路に沿って基地に到達するのに十分な場合のみです。 有効な各船舶から基地への割り当ては、船舶ごとに最大 1 回、基地ごとに最大 1 回使用できるため、基礎となる構造は 2 つのセット間のマッチング問題ですが、実現可能性の制約はグラフの距離と強度によって定義されます。 

実際の基地が攻撃されるたびに、固定のゴールド損失が発生します。 反乱軍は、どの船でも常に到達でき、船が割り当てられるほど魅力的な人工基地を作成することもできます。 これらのダミー基地はゴールドの損失を直接引き起こすわけではありませんが、作成にはそれぞれゴールドがかかり、各ダミー基地はマッチングで 1 隻の船を消費します。 

目標は、最終的に基地に艦艇を割り当てて攻撃回数を最大化し、純金の損失を最小限に抑えるために導入するダミー基地の数を決定することです。 

グラフは小さく、惑星は最大 100 個ですが、最大 1000 隻の船と 1000 の基地が存在する可能性があります。 これは、グラフ上の最短経路が Floyd-Warshall を使用して約 1 時間で効率的に事前計算できることを直ちに示唆しています。$100^3$計算上の主な課題は、数千のエッジを持つグラフ上の 2 部マッチング問題です。 

すべての割り当てをシミュレートしたり、ダミーの基底を追加した後にマッチングを繰り返し再計算しようとする単純なアプローチでは、最大の 2 部マッチング自体がこの規模ではすでに何度も再計算するとコストが高くなるため、遅すぎます。 

いくつかの微妙なケースが重要です。 

最初のエッジケースは、燃料や強度の制約により、どの船も基地に到達できない場合です。 その場合、ダミー基地がなければ答えはゼロになりますが、ダミー基地を導入すると船舶の使用が強制され、コストが増加する可能性があります。 

2 番目のエッジ ケースは、すべての船がすでにすべての基地と一致している場合です。 この場合、ダミー基地は有益な攻撃を役に立たない攻撃に置き換えるため、効率を低下させるだけです。 

3 番目のエッジケースは、ダミー塩基が塩基あたりの金の損失よりも大幅に安い場合です。 そうなると、たとえ本物の基地が存在していても、意図的に艦船をダミー基地に「浪費」することが最適となり、最適解の構造が大きく変わります。 

## アプローチ

 最も難しいのは、ダミー塩基がマッチング構造に対して実際にどのような影響を与えるかを理解することです。 ダミー基地を無視すると、問題は、船が基地を攻撃できる場合にエッジが存在する、船と基地の間に二部グラフを構築することに帰着します。 一致した各塩基は固定損失に寄与するため、タスクは最大の一致を見つけることになります。 

させて$M_0$は、実数ベースでのこの最大一致のサイズになります。 これは、ダミー基地が存在しない場合の、攻撃された実際の基地のベースライン数です。 

ブルートフォース戦略では、あらゆる数のダミーベースを試します。$D$、毎回 2 部グラフを再構築し、最大一致を再計算します。 各マッチング計算はすでに存在しているため、$O(E\sqrt{V})$あるいはさらに悪いことに、$D$最大 1000 まで増加する可能性がありますが、これはすぐに実行不可能になります。 

重要な構造的観察は、ダミー基地が本物の基地とは根本的に異なるということです。すべての船がすべてのダミー基地と一致する可能性があります。 これは、ダミー基地が、実現可能性を制限することなく、船舶の追加使用のみを強制するユニバーサルシンクとして機能することを意味します。 

これが認識されると、追加の効果は$D$ダミーベースが予測可能になります。 これらは、常に一致させることができる利用可能な右側の頂点の数を増やすだけで、実際の基地がすでに使用しているものを超えて追加の船を消費できるようになります。 

したがって、マッチングを繰り返し再計算する代わりに、最大マッチング値が次の関数としてどのように変化するかを分析します。$D$。 これにより、問題は動的マッチングから単一の整変数に対する閉じた形式の最適化に軽減されます。

 ## アルゴリズムのチュートリアル

 まず銀河を最短経路距離に変換します。 次に、船舶と実際の基地の間の 2 部グラフを構築し、その最大マッチングを計算します。 

1. 惑星グラフ上のすべてのペアの最短経路を計算します。 これにより、船が燃料制限内で基地に到達できるかどうかをテストするために必要な、任意の 2 つの惑星間の最小移動コストが得られます。 
2. 各艦船が左側、各基地が右側となる 2 部グラフを作成します。 船の攻撃が基地にとって十分であり、その燃料が少なくとも惑星間の最短航路距離にある場合、優位性を追加します。 このステップでは、物理的な制約を純粋な組み合わせの実現可能性に変換します。 
3. 最大一致を計算します$M_0$このグラフでは。 これは、ダミーの介入なしで攻撃できる実際の基地の最大数を表します。 
4. ダミー基地がどのように動作するかを観察します。各ダミー基地はすべての船に接続されているため、現在使用されていない船と常に一致させることができます。 
5. しましょう$s$船の数になります。 追加すると$D$ダミーベースの場合、一致するサイズは次のようになります。$$M(D) = M_0 + \min(D, s - M_0)$$なぜなら、各ダミーはすべての船が使用されるまで新しい一致に貢献することしかできないからです。 
6. 合計コストは、一致する実際の塩基の数によって異なります。 実質一致は等しい$M(D) - D$、つまり損失は$$k \cdot (M(D) - D) + hD$$7. 2つの体制に分割する。 のために$D \le s - M_0$、実際の一致は一定のままです$M_0$したがって、コストは次のように直線的に増加します。$hD$。 のために$D > s - M_0$、すべての船が使用され、増加しています$D$実際の一致を減らし、傾きを与える$h-k$。 
8. この構造から、最適解は常に境界値で発生します。次のいずれかです。$D = 0$または$D = s$。 これにより、閉じた形式が得られます。$$\min(k \cdot M_0,\; h \cdot s)$$### なぜ効果があるのか

 実際のベースとのマッチングは実現可能性の制約によって修正され、ダミー ベースは普遍的に互換性のある頂点のみを追加します。 このような頂点は実際の一致の構造を改善することはできず、船舶の未使用の容量を再割り当てするだけです。 したがって、唯一の意味のあるトレードオフは、支払いと支払いの間です。$k$実際の一致ベースごと、または支払い$h$船ごとに完全にダミー用途に転用されます。 この二分法が確立されると、$D$コスト関数は区分的に線形であり、内部最小値がないため、最適化することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    INF = 10**9

    dist = [[INF] * n for _ in range(n)]
    for i in range(n):
        dist[i][i] = 0

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        dist[u][v] = dist[v][u] = 1

    for k in range(n):
        for i in range(n):
            di = dist[i]
            dk = dist[k]
            for j in range(n):
                nd = di[k] + dk[j]
                if nd < di[j]:
                    di[j] = nd

    s, b, k_gold, h = map(int, input().split())

    ships = []
    for _ in range(s):
        x, a, f = map(int, input().split())
        ships.append((x - 1, a, f))

    bases = []
    for _ in range(b):
        x, d = map(int, input().split())
        bases.append((x - 1, d))

    adj = [[] for _ in range(s)]
    for i, (sx, sa, sf) in enumerate(ships):
        for j, (bx, bd) in enumerate(bases):
            if sa >= bd and dist[sx][bx] <= sf:
                adj[i].append(j)

    match = [-1] * b

    def dfs(u, vis):
        for v in adj[u]:
            if not vis[v]:
                vis[v] = True
                if match[v] == -1 or dfs(match[v], vis):
                    match[v] = u
                    return True
        return False

    m0 = 0
    for i in range(s):
        vis = [False] * b
        if dfs(i, vis):
            m0 += 1

    ans = min(k_gold * m0, h * s)
    print(ans)

if __name__ == "__main__":
    solve()
```この解決策では、まず銀河を全距離行列に圧縮して、船と基地の間のすべての実現可能性チェックが一定時間になるようにします。 これにより、BFS クエリの繰り返しが回避されます。 

次に、実行可能な攻撃の 2 部グラフを構築し、標準の DFS ベースの Kuh アルゴリズムを実行して、2 部マッチングを最大化します。 これで十分なので、$s, b \le 1000$グラフは十分にまばらです$O(sb)$最悪の場合はエッジ。 

最後に、ダミーの基底をシミュレートする代わりに、派生した閉じた形式の式を適用します。 実装上の重要な決定事項は、ダミー ノードを明示的に追加しないことです。 その効果全体が最終的な式に反映されます。

 ## 特殊なケース

 どの基地にも船が到達できない場合、一致するサイズはゼロになります。 この状況では、公式はゼロの実利得とおそらく正のダミーコストを比較することになるため、最適な解決策は、次の場合を除いてダミーベースを完全に避けることです。$h = 0$, ここで、任意の数のダミー塩基が等価になります。 

すべての船がすべての基地に到達できるようになると、マッチングは純粋に容量が制限されます。 決定は、船舶を実際の基地に割り当てるのが安いか、ダミー基地に割り当てるのが安いかということになります。 導出された式は、次の間の比較を通じてこれを直接捉えます。$k \cdot M_0$そして$h \cdot s$、マッチング計算により次のことが保証されます。$M_0 = \min(s, b)$この完全に接続されたケースでは。 

燃料の制約が厳しい場合、一部の船舶が 2 部グラフで孤立します。 これらの艦艇は、ソリューションの第 2 項ではダミー基地を通じてのみ貢献し、マッチング アルゴリズムは実際のフェーズではそれらを正確にマッチングしないままにし、正確性を維持します。$M_0$。
