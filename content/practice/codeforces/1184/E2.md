 ## 解決策
 ## 問題の理解

 各エッジが固有のエネルギー コストを持つコリドーを表す、接続された無向グラフが与えられます。 Daleks は常に最小スパニング ツリーを構築することを意図しているため、すべての可能なスパニング ツリーの中から総コストが最小のものを選択します。総コストはすべてのエッジの重みが異なるため一意に決定されます。 

現在、この最小スパニング ツリーの一部ではないコリドーごとに、非常に具体的な感度の質問が行われます。 そのコリドーの重みを増減することを想像し、このコリドーが何らかの最小スパニング ツリーの一部になる可能性を残しながら、設定できる最大値を求めます。 言い換えれば、このエッジが MST 構築によって選択されるのに十分な競争力を維持できる最大しきい値の重みを求めています。 

これは基本的に MST の安定性に関する構造的な問題です。つまり、非ツリー エッジがすべての MST から除外されることが保証される前に、どれだけ「コストがかかる」かということです。 

制約が十分に大きいため、エッジごとの最小スパニング ツリーを再計算しようとするソリューションは直ちに不可能になります。 最大 10^6 のエッジでは、O(m log n) の MST 計算を m 回繰り返すだけでも、実行可能な限界をはるかに超えてしまいます。 クエリごとのグラフ走査でも遅すぎます。 MST の単一のグローバル前処理と、エッジごとの高速クエリが必要です。 

微妙な特殊なケースがサイクルから発生します。 MST が 2 つの最小のエッジを選択し、最大のエッジを拒否する三角形を考えてみましょう。 拒否されたエッジの重みを増やすと、明らかに拒否されたままになります。 しかし、これを十分に減らすと、サイクル内の最大エッジが置き換えられる可能性があります。 重要な点は、重要なのは単なる隣接関係ではなく、MST 内のエンドポイント間のパスに沿った最大エッジであるということです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 非 MST エッジごとに、その重みを一時的に変更し、MST を再計算します。 次に、エッジがまだ含まれている最大の重みを二分探索します。 各 MST 計算のコストは O(m log n) で、これを最大 m エッジに対して実行すると O(m^2 log n) になりますが、10^6 エッジではまったく実行不可能です。 

重要な観察は、MST のサイクル特性から得られます。 非ツリー エッジを MST に追加すると、ちょうど 1 つのサイクルが作成されます。 MST 条件は、このエッジがそのエッジよりも重くない場合にのみ、そのサイクルで最も重いエッジを置き換えることができることを示しています。 したがって、エッジ (u, v) に関して重要なのは、現在の MST における u と v の間の一意のパス上の最大エッジ重みです。 

u と v の間の MST パス上の最大エッジ重みを maxEdge(u, v) として表す場合、(u, v) に割り当てることができる最大の重みは、一部の MST で選択できるようにしながら、正確に maxEdge(u, v) になります。 これより大きい場合は、そのサイクル上のすべてのエッジよりも厳密に悪くなり、MST に入ることができなくなります。 それが等しいかそれより小さい場合、その最大エッジを置き換えることができる同点の状況が存在します。 

これにより、問題はツリー内のパス上の最大エッジ クエリに答えることになり、これはバイナリ リフティング問題を伴う古典的な LCA です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | エッジごとに MST を再計算する | O(m^2 log n) | O(n) | 遅すぎる |
 | MST + LCA パス最大クエリ | O(m log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、クラスカルのアルゴリズムを使用してグラフの最小スパニング ツリーを構築します。 すべての重みが異なるため、この MST は一意であり、推論が簡素化されます。 

次に、MST をルート付きツリーとして扱い、バイナリ リフティングのために前処理します。 各ノードについて、距離の 2 乗で祖先を保存し、各祖先へのパス上の最大エッジ重みも保存します。 これにより、任意のパス上の最大エッジ重みを対数時間で計算できます。

次に、MST の一部ではない元のグラフ内のすべてのエッジについて、MST 内のエンドポイント間のパスに沿った最大エッジ重みを計算します。 その値がそのエッジの答えです。 

1. すべてのエッジを重みでソートし、Kruskal のアルゴリズムを実行して、どのエッジが含まれているかを記録しながら MST を構築します。 これが機能するのは、Kruskal が常に最小の安全エッジを取ることによって最小の総重量を保証しているためです。 
2. MST の隣接リスト表現を構築します。 
3. 任意のノードで MST をルートし、DFS を実行して親、深さ、および親に対するエッジの重みを計算します。 これにより、持ち上げのための基礎構造が確立されます。 
4. バイナリリフティングテーブルを構築します。`up[k][v]`は v の 2^k 番目の祖先であり、`mx[k][v]`v からその祖先までの最大エッジ重みです。 このステップでは、パスを対数ジャンプに圧縮します。 
5. 非 MST エッジ (u、v) ごとに、リフティング テーブルを使用して、u と v の間の MST パスに沿った最大エッジ重みを計算します。 結果は、最大エッジ重みを追跡しながらより深いノードを持ち上げてから、それらが一致するまで両方のノードを上方に同期させることによって得られます。 
6. ツリー以外のすべてのエッジに対してこの最大値を出力します。 

正確さは、すべてのリフティング ステップで、部分パス上でこれまでに確認された最大エッジ ウェイトを正しく維持するという不変条件に依存します。 どのパスも 2 つのセグメントのべき乗に分解されるため、分解ではすべてのエッジが 1 回だけ考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
edges = []
for i in range(m):
    a, b, w = map(int, input().split())
    edges.append((w, a - 1, b - 1, i))

parent_ds = list(range(n))
rank = [0] * n

def find(x):
    while parent_ds[x] != x:
        parent_ds[x] = parent_ds[parent_ds[x]]
        x = parent_ds[x]
    return x

def union(a, b):
    ra, rb = find(a), find(b)
    if ra == rb:
        return False
    if rank[ra] < rank[rb]:
        ra, rb = rb, ra
    parent_ds[rb] = ra
    if rank[ra] == rank[rb]:
        rank[ra] += 1
    return True

edges.sort()

mst = [[] for _ in range(n)]
in_mst = [False] * m

for w, a, b, i in edges:
    if union(a, b):
        in_mst[i] = True
        mst[a].append((b, w))
        mst[b].append((a, w))

LOG = 20
up = [[-1] * n for _ in range(LOG)]
mx = [[0] * n for _ in range(LOG)]
depth = [0] * n

def dfs(v, p):
    for to, w in mst[v]:
        if to == p:
            continue
        up[0][to] = v
        mx[0][to] = w
        depth[to] = depth[v] + 1
        dfs(to, v)

for i in range(n):
    if up[0][i] == -1:
        dfs(i, -1)

for k in range(1, LOG):
    for v in range(n):
        if up[k-1][v] != -1:
            up[k][v] = up[k-1][up[k-1][v]]
            mx[k][v] = max(mx[k-1][v], mx[k-1][up[k-1][v]])

def get_max(u, v):
    if depth[u] < depth[v]:
        u, v = v, u
    ans = 0

    diff = depth[u] - depth[v]
    for k in range(LOG):
        if diff & (1 << k):
            ans = max(ans, mx[k][u])
            u = up[k][u]

    if u == v:
        return ans

    for k in reversed(range(LOG)):
        if up[k][u] != up[k][v]:
            ans = max(ans, mx[k][u], mx[k][v])
            u = up[k][u]
            v = up[k][v]

    ans = max(ans, mx[0][u], mx[0][v])
    return ans

res = []
for w, a, b, i in edges:
    if not in_mst[i]:
        res.append((i, get_max(a, b)))

res.sort()
for _, val in res:
    print(val)
```Kruskal セクションは MST を構築し、同時にどのエッジが除外されるかをマークします。 除外されたエッジのみが回答を必要とするため、これは非常に重要です。 

DFS は、直接の親およびエッジから親の値を初期化します。 次に、バイナリ リフティング テーブルはこれを 2 のすべてのべき乗ジャンプに拡張し、すべてのパス クエリが O(log n) で回答できるようにします。 

の`get_max`関数は、最初に深いノードを注意深く持ち上げ、これまでに確認された最大エッジを常に更新します。 最後のマージ ステップでは、LCA の直前の最後の 2 つのエッジを処理します。 

よくある落とし穴は、エッジの重みをノードの祖先とは別に追跡することを忘れることです。 リフティング構造は、親だけでなくエッジ情報も保存する必要があります。 

## 実用的な例

 ### 例 1

 入力:```
3 3
1 2 8
2 3 3
3 1 4
```MST エッジは、重み 3 の (2,3) と重み 4 の (3,1) です。 

| エッジ | MST | MST のパス最大値 | 出力 |
 | --- | --- | --- | --- |
 | (1,2,8) | いいえ | 最大(4,3) = 4 | 4 |

 非 MST エッジは 1 と 2 を接続します。それらの間の MST パスは 1-3-2 で、そのパス上の最大のエッジは 4 です。これが制限しきい値になります。 

### 例 2

 入力:```
4 5
1 2 10
2 3 5
3 4 7
1 4 6
2 4 8
```MST が (2,3,5)、(3,4,7)、(1,4,6) を選択したとします。 

| エッジ | MST | MST のパス最大値 | 出力 |
 | --- | --- | --- | --- |
 | (1,2,10) | いいえ | 最大パス 1-4-3-2 = 7 | 7 |

 各答えは、エンドポイント間の一意の MST パス上の最も重いエッジに正確に対応します。

 ## 特殊なケース

 2 つのエンドポイント間の MST パスが長いにもかかわらず、最大エッジがツリーの上部近くにある場合は、注意が必要なケースが発生します。 バイナリ リフティングでは常に最も関連性の高いセグメントが最初に考慮され、最大値を計算するときにパス上のエッジが見逃されないことが保証されるため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、複数のエッジが MST 内の異なるルートを介して同じ高レベル リージョンに接続する場合です。 その場合でも、答えは MST 内の一意のパスにのみ依存し、リフティング構造は構造によって一意性を強制するため、計算された最大値に曖昧さは生じません。
