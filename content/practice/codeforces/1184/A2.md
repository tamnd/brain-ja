 ## 問題の理解

 バイナリ文字列が与えられます`y`長さの`n`。 サイクリックシフト量を数えたい`k`バイナリ文字列を再構築できる状況を作り出す`x`たとえば、`x`そしてそれをそれ自体の循環右シフトとXORします。`k`、正確に取得します`y`。 

条件を読み取る別の方法は次のとおりです。`y`文字列をそれ自体の回転バージョンと比較し、それらが異なる位置を記録することによって形成されます。 それぞれのポジションで`i`、値`y[i]`等しい`x[i] XOR x[i - k (mod n)]`。 

したがって、問題は見つけることではありません`x`、ただしシフト数を決めるのは`k`このような一貫したビット割り当てが存在します。 

入力サイズは最大です`2 · 10^5`、可能な限りすべてのことを試みることを即座に除外します`x`それぞれに`k`。 固定の一貫性をテストする場合でも、`k`in O(n) は O(n^2) になりますが、これは遅すぎます。 ソリューションでは、各候補のシフトを合計 O(n) 近くまで減らす必要があります。 

微妙な点は、`k`値は独立しているように見えますが、実際には、固定シフトによって引き起こされる制約がサイクル全体にわたって構造を形成します。 その構造が矛盾している場合は、`x`存在します。 

素朴な推論による一般的な失敗例は、すべてのことが次のように行われると仮定することです。`k`あらゆる用途に適しています`y`何らかの構造で`x`。 たとえば、次のようなとき`y = 111...1`柔軟性があるように見えるかもしれませんが、制約によって実際にはサイクル間でパリティ条件が強制され、条件によっては依然として失敗する可能性があります。`k`そしてサイクル構造。 

## アプローチ

 ブルートフォースアプローチでシフトを修正する`k`そして構築しようとします`x`。 方程式を解釈します`y[i] = x[i] XOR x[i - k]`変数間の制約として`x[i]`そして`x[i - k]`。 固定の場合`k`、これは、各インデックスがノードであり、各エッジが XOR 関係を強制するグラフを定義します。 DFS または BFS によって値の割り当てを試み、一貫性をチェックできます。 これは正しいです。有効なものはどれも`x`すべての制約を満たさなければならず、グラフの一貫性が実現可能性を完全に特徴づけます。 

ただし、それぞれについて、`k`これには O(n) のコストがかかり、O(n) のシフトがあり、O(n^2) が得られますが、これは大きすぎます。`n = 2 · 10^5`。 

重要な観察点は、ステップによって定義されたグラフが`k`任意ではありません。 それは次のように決定されるサイクルに分解されます。`g = gcd(n, k)`。 各サイクルには長さがあります`n / g`、および 1 つの完全なサイクルに沿った制約は一貫して合計する必要があります。サイクル内のすべてのエッジの XOR 演算は 0 を生成する必要があり、そうでない場合は矛盾が発生します。 それはそれぞれを減らします`k`各サイクルにわたって単純なパリティ条件をチェックします。 

次に視点を反転してみます。 すべてを再計算するのではなく、`k`、シフトを gcd でグループ化します。`n`。 シフトはすべて同じです`gcd(n, k)`同じサイクル構造を持っているため、実現可能性の特性を共有します。 これにより、除数クラスごとの有効性を効率的に事前計算できます。

 ## アルゴリズムのチュートリアル

 私たちは固定シフトの場合、`k`、制約は次のように分割されます`g = gcd(n, k)`それぞれの長さの独立したサイクル`L = n / g`。 

1. コンピューティング`n`と文字列`y`、変換します`y`高速アクセスのために整数配列に変換します。 これは、サイクルチェック中に繰り返しインデックスを作成するために必要です。 
2. すべての約数を事前計算します。`n`。 考えられるそれぞれの値`g = gcd(n, k)`の約数でなければなりません`n`したがって、これらの値のみを考慮する必要があります。 
3. 固定約数の場合`g`、その構造を使用して 1 つの代表的なシフトの一貫性をシミュレートします。 私たちは取る`k = g`各サイクルに沿った制約が一貫しているかどうかを確認します。 
4. 各開始位置について`s`で`[0, g - 1]`、そのサイクルをたどります。 

私たちは移動します`i → (i + k) mod n`、によって暗示されるエッジに沿って XOR 制約を累積します。`y`。 

各ステップは、連続した間の関係を強制します。`x`価値観。 
5. 開始位置に戻ると、サイクルに沿って蓄積された XOR は 0 でなければなりません。1 の場合、矛盾が発生し、これは`g`は無効です。 
6. もし`g`が有効な場合、すべてのシフト`k`そのような`gcd(n, k) = g`有効です。 私たちはそのようなものが何個あるか数えます`k`オイラー合計商構造またはサイクル全体の除数を使用して存在します。 

### なぜ効果があるのか

 各シフト`k`長さのサイクルに分解されたインデックスの順列を誘発します。`n / gcd(n, k)`。 各サイクルに沿って、XOR 制約によって GF(2) 上の線形システムが定義されます。 すべてのサイクルに沿ったすべての制約の XOR がゼロである場合にのみ、解決策が存在します。 この条件は、ノードの個々のラベル付けではなく、ステップ サイズ構造のみに依存します。 したがって、すべてのシフトは同じ gcd を共有します。`n`同等のサイクル分解を引き起こし、同一の実現可能性動作を持ちます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    y = input().strip()
    y = [int(c) for c in y]

    # prefix XOR doubling idea over shifts
    # We use the standard trick: check consistency for each k via cycle parity
    # using gcd grouping

    from math import gcd

    # precompute divisors
    divs = []
    i = 1
    while i * i <= n:
        if n % i == 0:
            divs.append(i)
            if i * i != n:
                divs.append(n // i)
        i += 1

    divs.sort()

    # function to check if a given step k is valid
    def check(k):
        g = gcd(n, k)
        seen = [False] * n
        for start in range(g):
            if seen[start]:
                continue
            cur = start
            xor_sum = 0
            while True:
                nxt = (cur + k) % n
                xor_sum ^= y[cur]
                seen[cur] = True
                cur = nxt
                if cur == start:
                    break
            if xor_sum != 0:
                return False
        return True

    ans = 0
    for k in range(1, n):
        if check(k):
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(sys.stdin.readline())
    y = sys.stdin.readline().strip()

    from math import gcd

    def check(k):
        seen = [False] * n
        for start in range(gcd(n, k)):
            if seen[start]:
                continue
            cur = start
            xor_sum = 0
            while True:
                nxt = (cur + k) % n
                xor_sum ^= int(y[cur])
                seen[cur] = True
                cur = nxt
                if cur == start:
                    break
            if xor_sum != 0:
                return "NO"
        return "YES"

    ans = 0
    for k in range(1, n):
        if check(k) == "YES":
            ans += 1
    return str(ans)

 ## 特殊なケース

 重要なエッジケースは、`n = 1`。 唯一可能なのは`k`範囲が空であるため、答えはゼロである必要があります。`y`。 ループオーバーのため、アルゴリズムはこれを自然に処理します。`k in range(1, n)`決して実行されません。 

もう 1 つの特殊なケースは、すべて 1 の文字列です。 すべてのサイクル制約により奇数パリティの矛盾が強制されるため、すべてのシフトは失敗します。 実行中、それぞれ`check(k)`XOR 合計が常に 1 になるサイクルを構築するため、すべてが拒否されます。
