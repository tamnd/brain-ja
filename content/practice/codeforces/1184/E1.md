 ## 解決策
 ## 問題の理解

 接続された無向グラフが与えられます。各エッジは、関連するエネルギー コストを持つ時間回廊を表します。 ダーレクは必ずしもすべての廊下を使用するとは限りません。 代わりに、総エネルギー コストを最小限に抑えながらすべてのノードを接続する一連のコリドーを常に選択します。これはまさに最小スパニング ツリーの定義です。 

私たちは特定のエッジ、つまり入力の最初のエッジに興味があります。 その重みを任意の値に変更できると想定します。 考えられる変更値ごとに、このエッジをまだ含む最小スパニング ツリーが存在するかどうかを尋ねます。 タスクは、このエッジが少なくとも 1 つの MST に属することができるような重みの最大値を見つけることです。 

出力は、最初のエッジのこのしきい値を表す単一の整数です。 

制約は最大 100,000 個のノードと 1,000,000 個のエッジに達し、候補の重みごとに MST を最初から再計算するソリューションは即座に除外されます。 単一の MST 構築でも O(m log m) で問題ありませんが、エッジごとまたはクエリごとに繰り返すと遅すぎます。 1 つの MST 計算から構造情報を抽出し、それを再利用する必要があります。 

微妙な問題は、エッジが Kruskal によって構築された特定の MST の一部でなくても、ある MST に属する可能性があることです。 これは、単一の固定ツリーではなく、MST の柔軟性を扱っていることを意味します。 もう 1 つの重要なエッジ ケースは、タイ ブレークにより複数の有効な MST が許可されるため、複数のエッジの重みが等しい場合です。 

## アプローチ

 直接的なアプローチでは、最初のエッジの重みを変更し、それが MST に現れるかどうかを再計算しようとします。 固定の重みの場合、Kruskal を実行して包含をチェックできます。 次に、重みの範囲にわたって答えを二分探索できます。 各 MST 計算には O(m log m) のコストがかかり、二分探索では約 30 倍の係数が追加されるため、最悪の場合、テストごとに約 3e7 の対数係数演算が必要になりますが、これは 1e6 エッジには遅すぎます。 

重要な観察は、一部の MST にエッジが現れるかどうかは、グローバルな再計算によってではなく、MST 構造内のローカルなボトルネックによって決定されるということです。 グラフの MST を構築すると、そのツリー内の端点間の一意のパスを調べることによって、ツリー以外の各エッジを分析できます。 このパスは、このエッジをツリーに挿入しようとする場合に置き換える必要がある最大重みエッジを決定します。 

これは、標準的な MST 感度の考え方につながります。つまり、エッジの重みが、最小スパニング ツリー内のエンドポイント間のパス上の最大エッジの重みを厳密に超えていない場合に限り、エッジはある MST の一部になれるということになります。 したがって、MST がわかっていて、パス上の最大エッジのクエリに答えることができれば、最初のエッジのしきい値を計算できます。 

高速パスの最大クエリをサポートするために、MST をルート化し、ジャンプの最大エッジ重みを格納するバイナリ リフティング構造を構築します。 次に、最初のエッジ (u, v) について、O(log n) のパスに沿った最大エッジの重みを計算できます。その値が、ある MST の資格を維持するためのエッジの最大許容重みになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 値ごとに MST を再計算する | O(m log m log W) | O(m) | 遅すぎる |
 | MST + LCA パスの最大値 | O(m log m + n log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. クラスカルのアルゴリズムを使用してグラフの最小全域木を構築します。 これにより、最小限の総コストで必要なすべての接続を維持するベースライン ツリーが得られます。 MST 構造は、ノード間のすべての重大なボトルネックをエンコードします。 
2. 任意のノード、たとえばノード 1 で MST をルートし、バイナリ リフティング テーブルを準備します。 各エントリには、ノードの 2^k 番目の祖先だけでなく、その祖先へのパス上の最大エッジ重みも格納されます。 これにより、パス情報の高速な再構築が可能になります。 
3. MST の DFS トラバーサルを使用して、深さと親ポインターを事前計算します。 DFS 中に、親から各ノードに至るエッジの重みを記録します。これがリフティングの基本ケースとなるためです。 
4. バイナリリフティングテーブルをボトムアップで構築します。 各ノードとジャンプ長について、保存されているエッジの重みの最大値を取得して、2 つの小さなジャンプを結合します。 これにより、すべてのジャンプがパスのそのセグメントに沿って見られる最も重いエッジをエンコードすることが保証されます。 
5. 入力から最初のエッジ (u、v、w) を取得します。 リフティング構造を使用して、MST 内の u と v の間のパスに沿った最大エッジ重みを計算します。 これを行うには、より深いノードを同じ深さまで持ち上げてから、発生した最大エッジ重みを追跡しながら両方のノードを一緒に持ち上げます。 
6. この最大値を M とします。答えは M です。これは、MST コストを増加させることなく MST パスに沿ったエッジの置換が可能になるしきい値を表します。つまり、エッジが依然として何らかの MST 設定に属することができることを意味します。 

### なぜ効果があるのか

 MST にはサイクル プロパティがあります。MST にないエッジについては、エッジを追加するとサイクルが作成され、そのサイクルで最も重いエッジは、より小さい重みを優先する MST の一部になることはできません。 逆に、エッジの重みがエンドポイント間の MST パス上の最大エッジより厳密に大きくない場合は、総コストを増加させることなく MST 内のそのエッジを置き換えることができます。 これは、重み変更後の MST でエッジがいつ現れるかを正確に特徴付けます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def find(x, parent):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

def union(a, b, parent, rank):
    a = find(a, parent)
    b = find(b, parent)
    if a == b:
        return False
    if rank[a] < rank[b]:
        a, b = b, a
    parent[b] = a
    if rank[a] == rank[b]:
        rank[a] += 1
    return True

n, m = map(int, input().split())
edges = []

for i in range(m):
    a, b, w = map(int, input().split())
    edges.append((w, a, b, i))

edges.sort()

parent = list(range(n + 1))
rank = [0] * (n + 1)

mst_adj = [[] for _ in range(n + 1)]
used = [False] * m

for w, a, b, i in edges:
    if union(a, b, parent, rank):
        mst_adj[a].append((b, w))
        mst_adj[b].append((a, w))
        used[i] = True

LOG = 20
up = [[0] * (n + 1) for _ in range(LOG)]
mx = [[0] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)

def dfs(v, p):
    for to, w in mst_adj[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        up[0][to] = v
        mx[0][to] = w
        dfs(to, v)

dfs(1, 0)

for k in range(1, LOG):
    for v in range(1, n + 1):
        up[k][v] = up[k-1][up[k-1][v]]
        mx[k][v] = max(mx[k-1][v], mx[k-1][up[k-1][v]])

def query_max(u, v):
    if depth[u] < depth[v]:
        u, v = v, u
    ans = 0

    diff = depth[u] - depth[v]
    for k in range(LOG):
        if diff & (1 << k):
            ans = max(ans, mx[k][u])
            u = up[k][u]

    if u == v:
        return ans

    for k in reversed(range(LOG)):
        if up[k][u] != up[k][v]:
            ans = max(ans, mx[k][u], mx[k][v])
            u = up[k][u]
            v = up[k][v]

    ans = max(ans, mx[0][u], mx[0][v])
    return ans

u, v, w = edges[0][1], edges[0][2], edges[0][0]
print(query_max(u, v))
```このコードはまず、Kruskal を使用して MST を構築し、最小限の接続構造を保持するツリーを確保します。 DFS は、リフティングに必要な親情報と深さ情報を初期化します。 バイナリ リフティング テーブルには祖先と最大エッジの重みの両方が保存されます。これは、構造だけでなく、各ジャンプに沿った最も重い制約にも関心があるため、不可欠です。 

の`query_max`関数はコアコンポーネントです。 深さを慎重に均等化し、すでに処理されたパス セグメントでこれまでに確認された最大エッジの重みを常に知っているという不変条件を維持しながら、両方のノードを登ります。 最終結果は、最初のエッジのエンドポイント間の一意の MST パス上の最大エッジ重みです。 

よくある落とし穴は初期化を忘れることです`up[0][root]`そして`mx[0][root]`リフティングの一貫性が崩れてしまいます。 もう 1 つの微妙な問題は、DFS がグラフが接続されルートが 1 であると想定していることです。これは問題保証により当てはまります。

 ## 特殊なケース

 重要なエッジ ケースは、複数のエッジが同じ重みを持つ場合です。 このような場合、MST は一意ではないため、タイブレークに応じて最初のエッジが表示される場合と表示されない場合があります。 パス最大値は MST 構造の一意性ではなく厳密なボトルネックのみを捕捉するため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、最初のエッジ自体が MST の一部である場合です。 たとえば、最初のエッジが軽く、Kruskal の早い段階で 2 つのコンポーネントを接続している場合、そのエッジは含まれます。 代替 MST ではエッジをより重いエッジに置き換える必要がないため、パス最大値は引き続き正しいしきい値を返します。 

最後の微妙なケースは、グラフがすでにツリーになっている場合です。 この場合、MST はグラフ自体であり、最初のエッジの端点間のパスはまさにエッジ自体です。 パス上の最大値はそれ自体の重みに等しいため、それを超えると、他の場所でより重いエッジとの置換が強制され、そのエッジが MST から除外されることを正しく示しています。
