 ## 解決策
 ## 問題の理解

 順番に配置された宇宙の行があり、それぞれに 1 から 1 までの番号が付けられています。$n$、ドクターの位置から開始します$k$。 多元宇宙は、一連の操作に従って時間の経過とともに変化する可能性があります。 操作により、2 つの既存のユニバースの間または両端に新しいユニバースが挿入されるか、2 つのユニバース間のリンクが切断され、ドクターが含まれていないセグメントが消滅します。 各操作の後、ユニバースの総数とドクターの更新された位置を報告する必要があります。 

入力は初期の長さを与えます$n$、医師の立場$k$、許可されるユニバースの最大数$m$、および操作の数$t$。 各操作では、1 から始まるインデックスで挿入またはリンク ブレークのいずれかを指定します。 各ステップを順番にシミュレートし、それぞれの後に現在の状態を出力する必要があります。 

制約は小さいです。$n, m \le 250$そして$t \le 1000$。 これは、マルチバースの最大サイズが小さく、操作ごとに線形時間で操作を直接シミュレートできることがすぐにわかります。$t$中程度です。 エッジケースでは、特にドクターが位置 1 または最後のユニバースにある場合、リンクを切断すると左右のセグメント全体が削除される可能性があるため、端での操作が必要になります。 

たとえば、マルチバースの長さが 3 で、ドクターが位置 1 にある場合、リンク 1 を切断すると、右側のセグメントが消え、単一ユニバースのマルチバースでドクターが位置 1 に残ります。 単純な 0 ベースの配列実装では、挿入または削除後にインデックスがシフトするため、新しいドクターの位置が誤って計算される可能性があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。ユニバースの配列を維持し、各操作が発生するたびに要素を明示的に挿入または削除します。 挿入は要素を挿入ポイントから右にシフトすることによって処理され、リンクの切断は配列をスライスしてドクターを含むセグメントを維持することによって処理されます。 すべての操作で必要となるのは、$O(n)$最悪の場合は時間がかかりますが、$n$が最大 250 の場合、1000 ステップで最大 250,000 の配列操作が生成され、これは 1 秒の制限時間内で許容されます。 

もう少し最適なアプローチに関する重要な洞察は、ユニバースのコンテンツをまったく保存する必要がないということです。 必要なのは多宇宙の長さとドクターのインデックスだけです。 挿入により長さが増加し、挿入が医師の位置よりも前またはその位置で行われた場合、医師が移動する可能性があります。 リンクが切れると長さが短くなり、どのセグメントが生き残るかに応じてドクターの位置も移動する可能性があります。 たった 2 つの整数を慎重に更新するだけで、すべての操作をシミュレートできます。$O(1)$ステップあたりの時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースアレイシミュレーション | O(t * n) | O(n) | 小さな制約があるため受け入れられます |
 | 最適化された長さと位置の追跡 | O(t) | お(1) | 受け入れられ、きれいになった |

 ## アルゴリズムのチュートリアル

 1. 初期の多元宇宙の長さから開始します$l = n$そして医師の立場$k$。 
2. シーケンス内の各操作について、タイプを読み取ります。$op$とインデックス$i$。 
3. もし$op$1 (挿入) の場合、長さが増加します$l$1.の場合$i \le k$、増分$k$なぜなら、すべての宇宙は位置にあるからです$\ge i$右にシフトすると、ドクターが挿入ポイントまたは挿入ポイントの後にある場合は、ドクターを 1 ステップ右に移動します。 もし$i > k$、ドクターの立場は変わりません。 
4. もし$op$が 0 (リンク切れ) の場合、どのセグメントにドクターが含まれているかを判断します。 もし$i < k$、ドクターは正しいセグメントにいます。 休憩の後、多元宇宙は縮小します$l - i$そしてドクターの新しい役職は$k - i$、左側のセグメントがなくなっているためです。 もし$i \ge k$、ドクターは左側のセグメントにいます。 休憩の後、多元宇宙は縮小します$i$そして医師の地位はそのまま$k$。 これは自然に終了します。 
5. 各操作後に現在の長さとドクターの位置を出力します。 

これが機能するのは、多元宇宙が常に直線的であり、ドクターの相対位置を簡単な算術で追跡できるためです。 実際のユニバースの配列は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k, m, t = map(int, input().split())
length = n

for _ in range(t):
    op, i = map(int, input().split())
    if op == 1:
        # insertion
        if i <= k:
            k += 1
        length += 1
    else:
        # link break
        if i < k:
            # Doctor in right segment
            k -= i
            length -= i
        else:
            # Doctor in left segment
            length = i
    print(length, k)
```この解では、多元宇宙の長さとドクターの位置という 2 つの整数だけが維持されます。 挿入中、ドクターの現在の位置または前で挿入が行われた場合、ドクターは右に移動します。 リンクの切断中に、どちらの側にドクターが含まれているかを判断し、それに応じて長さと位置を調整します。 最初または最後の位置への挿入、または最初または最後のリンクの切断などの境界ケースは、追加のチェックを行わずに自然に処理されます。 

## 実用的な例

 サンプル 1 の使用:

 初期状態: 長さ = 5、k = 2

 | ステップ | 操作 | 長さ | 医師の職位 | 説明 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 1 | 4 | 1 | リンク 1 を解除します。 医師は右セグメントにあり、新しい位置 = 2-1=1 |
 | 2 | 1 1 | 5 | 2 | 1 に挿入します。 医師は 1 以降にいるため、2 に右に移動します。 
| 3 | 0 4 | 4 | 2 | リンク 4 を解除します。 左セグメントのドクター (2 <= 4)、長さ = 4、k は変更なし |
 | 4 | 1 2 | 5 | 3 | 2に挿入します。 i <= k なので、Doctor は右に 3、長さ = 5 に移動します。 

トレースにより、位置と長さの算術更新が操作を正しくシミュレートしていることが確認されます。

 入力:```
3 3 10 3

 | ステップ | 操作 | 長さ | 医師の職位 | 説明 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = []
    n, k, m, t = map(int, input().split())
    length = n
    for _ in range(t):
        op, i = map(int, input().split())
        if op == 1:
            if i <= k:
                k += 1
            length += 1
        else:
            if i < k:
                k -= i
                length -= i
            else:
                length = i
        out.append(f"{length} {k}")
    return "\n".join(out)

# provided sample
assert run("5 2 10 4\n0 1\n1 1\n0 4\n1 2\n") == "4 1\n5 2\n4 2\n5 3"

# minimum-size input
assert run("2 1 2 2\n1 1\n0 1\n") == "3 2\n1 1"

# maximum-size insertion
assert run("250 125 250 1\n1 126\n") == "251 126"

# breaking first link with Doctor at end
assert run("5 5 10 1\n0 1\n") == "4 4"

# consecutive left-breaks
assert run("5 3 10 2\n0 1\n0 1\n") == "4 2\n3 1"
