 ## 問題の理解

 クリスマス ツリーの構造を表す有向非巡回グラフがあります。 すべての頂点には 1 つのキャンディが含まれており、すべてのキャンディには期限があります。 頂点に置かれたキャンディー`v`から到達可能なすべてのキャンディーを食べた後にのみ食べることができます`v`すでに食べられています。 言い換えれば、すべてのエッジ`u -> v`ということです`v`よりも早く現れる必要があります`u`食べる順番で。 

タスクは、すべての頂点がその出力近傍のすべての後に処理され、順序内の位置が有効期限値を超えないような、すべての頂点の順序付けが存在するかどうかを判断することです。 

グラフには最大で次のものを含めることができます`100000`すべてのテスト ケースの頂点とエッジ。 有効なトポロジー次数の数は指数関数的に増加する可能性があるため、多くの可能な次数を試すソリューションは不可能です。 アルゴリズムさえも`O(n^2)`高価すぎるとき`n`到達する`100000`したがって、ソリューションでは各頂点とエッジを一定の回数だけ処理する必要があります。 

いくつかの詳細は誤って扱われやすいものです。 出ていくエッジのない頂点は、最初に食べる必要がある子孫がないため、すぐに使用可能になります。 例えば：```
1
1 0
0
```答えは、`YES`。 キャンディーは 1 つあり、初日に食べます。 すべての期限が正の値でなければならないと想定するソリューションでは、期限が誤って拒否されてしまいます。 

もう 1 つのよくある間違いは、エッジがキャンディーからその前に食べなければならないキャンディーを指していることを忘れていることです。 例えば：```
1
2 1
1 1
1 2
```答えは、`NO`。 あめ`2`最初に食べなければなりませんが、キャンディー`1`期限があります`1`、もう日がありません。 エッジの解釈を逆にすると、スケジュールが誤って許可されてしまいます。 

最後のエッジケースは、現在入手可能ないくつかのキャンディーの期限が異なる場合です。 考慮する：```
1
3 2
1 3 3
1 2
1 3
```答えは、`YES`。 葉は頂点より前に食べなければなりません`1`、それで頂点を食べる`2`または`3`最初はいいけど、期限があるお菓子を遅らせるのは`1`すぐにスケジュールが不可能になってしまいます。 アルゴリズムは常に、最も緊急に入手可能なキャンディーを選択する必要があります。 

## アプローチ

 直接的なアプローチは、現在許可されているキャンディーを繰り返し選択して、有効な食事順序を生成することです。 選択した注文が期限に違反した場合は、後戻りして別の注文を試すことができます。 考えられるすべての有効な注文が調査されるため、これは正しいですが、考えられる注文の数は膨大になる可能性があります。 多くの独立した頂点を持つグラフには、階乗的に多くの可能な位相順序があるため、強引な方法は使用できません。 

有益な観察は、スケジュールの解釈から得られます。 私たちはトポロジカルな順序を探しているのではなく、期限を満たすものを探しています。 グラフの制約は、各瞬間にどの頂点が利用可能かを決定するだけです。 使用可能なすべての頂点の中で、期限が最も小さい頂点が常に最も安全な選択となります。 

これは、最早期限優先スケジューリングで使用されるのと同じ交換引数です。 最適なスケジュールで入手可能なキャンディーを食べると仮定します。`b`入手可能なキャンディーの前に`a`、 しかし`a`期限が短くなります。 スワッピング`a`そして`b`その時点では両方が使用可能であったため、依存関係は破壊されません。 以来`a`早めに移動すれば、悪化することはありません。 この交換を繰り返すと、最適なスケジュールが、利用可能な最小の期限を常に選択するスケジュールに変換されます。 

この総当り攻撃は、すべての法的順序を調査するため機能しますが、数が多すぎるため失敗します。 利用可能な最小の期限のみが重要であるという観察により、検索を貪欲な優先順位キューのシミュレーションに置き換えることができます。

 ## アルゴリズムのチュートリアル

 1. グラフを作成し、各キャンディーの残りの前提条件の数を保存します。 キャンディーは、すべての外向きの近傍がいなくなった後にのみ食べることができるため、この値はその現在の出次数になります。 
2. 出次数が 0 のすべての頂点を有効期限順に並べた最小ヒープに置きます。 当日食べられるお菓子です。 
3. 期限が最も小さいキャンディーをヒープから繰り返し削除します。 日の数は、すでに食べたキャンディーの数に 1 を加えたものです。 この日がお菓子の締め切りより大きい場合は、スケジュールは不可能です。 
4. お菓子を食べた後`v`、入ってくるすべての隣人からその影響を取り除きます。 あらゆるエッジに`u -> v`、残りの出次数を減少させます。`u`。 それがゼロになると、`u`利用可能になり、ヒープに挿入されます。 
5. すべての頂点が期限を守ることなく処理された場合、答えは次のようになります。`YES`。 

これが機能する理由: ヒープには、次に合法的に食べられるキャンディーが常に正確に含まれています。 後で入手可能なキャンディを期限の早いキャンディと交換しても実現可能性が損なわれることはないため、貪欲な選択は安全です。 したがって、有効なスケジュールが存在する場合、貪欲なスケジュールも存在します。 貪欲なスケジュールで期限を過ぎてしまった場合、他の注文ではその失敗を避けることはできません。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, m = map(int, input().split())
        deadline = list(map(int, input().split()))

        incoming = [[] for _ in range(n)]
        outdeg = [0] * n

        for _ in range(m):
            a, b = map(int, input().split())
            a -= 1
            b -= 1
            incoming[b].append(a)
            outdeg[a] += 1

        heap = []
        for i in range(n):
            if outdeg[i] == 0:
                heapq.heappush(heap, (deadline[i], i))

        eaten = 0
        ok = True

        while heap:
            d, v = heapq.heappop(heap)
            eaten += 1

            if eaten > d:
                ok = False
                break

            for u in incoming[v]:
                outdeg[u] -= 1
                if outdeg[u] == 0:
                    heapq.heappush(heap, (deadline[u], u))

        ans.append("YES" if ok and eaten == n else "NO")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```隣接リストは逆方向に保存されます。 キャンディーを削除した後にどの頂点が利用可能になるかを知る必要があるので、すべてのエッジについて`u -> v`私たちは保管します`u`内部`incoming[v]`。 

出次数配列は、各頂点をブロックしているキャンディーの数を表します。 この値がゼロに達すると、頂点は正確にヒープに入ります。 ヒープには次のペアが格納されます。`(deadline, vertex)`そのため、Python は常に、最も緊急性の高い利用可能なキャンディーを削除します。 

最初に食べたキャンディーは 1 日目に消費されるため、日カウンターは 1 から始まります。 締め切りまで`2^30`Python 整数内に簡単に収まるため、特別なオーバーフロー処理は必要ありません。

 ## 特殊なケース

 期限がゼロの単一頂点のケースが処理されるのは、アルゴリズムが初日が期限を超過するかどうかをチェックするためです。 初日はこちら`1`ですので、期限は`0`期限が今日から数日後と解釈された場合、実際には失敗します。 この問題では、例と制約は、日数のカウントが有効期限値の 0 から始まることを暗示しているため、実装の比較は意図した解釈と一致する必要があります。 上記で提供されたソリューションの場合、期限の値は、通常の変換後の最新の 1 ベースの食事日を表します。 

依存関係チェーンの場合、アルゴリズムはブロックされた親を早すぎるタイミングで挿入することはありません。 で：```
2 1
1 1
1 2
```頂点`1`出次数 1 から始まるため、ヒープに入ることができません。 頂点`2`最初に食べられ、次に頂点が食べられます`1`が利用可能になります。 日数カウントがすでに大きすぎるため、アルゴリズムはそれを拒否します。 

複数のリーフが使用可能な場合、ヒープの順序付けにより、不注意な任意の選択が防止されます。 で：```
3 2
1 3 3
1 2
1 3
```頂点`2`頂点の前で選択されています`3`両方とも利用可能ですが頂点なので`2`の方が期限が厳しいです。 これにより、可能な唯一の有効なスケジュールが保存されます。
