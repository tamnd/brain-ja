 ## 解決策
 ## 問題の理解

 バケツのコレクションがあります。 バケツ`i`から始まる`a[i]`ストローがあり、共有の山があります。`K`余分なストロー。 これらの余分なストローの一部またはすべてをバケツに分配する場合があります。 配布後、ジミーは 2 つのバケツを選択し、最終的なストロー数の最小公倍数を受け取ります。 タスクは、この可能な LCM を最大化することです。 

バケットは最大 100 万個まで存在できるため、入力サイズは大きくなりますが、初期バケット サイズはすべて最大 1000 です。この違いが重要な制限です。 バケットのすべてのペアを比較するソリューションには、以下のものが必要になります。`10^12`操作、それは不可能です。 多くのバケットは同じ小さな初期値を持っているため、すべてのバケットに関する情報を個別に管理する必要さえありません。 

バケットの最終的な最大値は次のとおりです。`1000 + 1,000,000 = 1,001,000`, したがって、この範囲にわたる線形スキャンが可能です。 主な課題は、考慮する必要があるバケットの数を減らすことです。 

よくある間違いは、残りのストローをどのように分配するかを確認せずに、最大の初期値を持つ 2 つのバケツが自動的に答えになると想定することです。 LCM は大きさだけでなく gcd にも依存するため、最後の 2 つの数値の選択は依然として重要です。 

例えば：```
2 1
5 5
```2 つのバケツには 5 つのストローが入っています。 これら 2 つのバケットの最終合計は最大 11 になります。`(5,6)`の最小公倍数が得られます`30`。 余ったストローをすべて1つのバケツに入れて保管するだけの戦略`(5,7)`利用可能な合計を超えているため無効です。 

もう 1 つのエッジ ケースは、最適なペアが最も近い 2 つの値ではない場合です。 のために：```
2 2
3 5
```山を追加した後のストローの総数は 10 です。最良の選択は`(4,6)`または`(3,7)`?`(3,7)`与える`21`、 その間`(5,5)`だけを与える`5`。 プロダクトベースのみの戦略では gcd 効果を逃してしまいます。 

## アプローチ

 直接的な強引なアプローチは、バケットのすべてのペアを試し、可能な限りあらゆる方法で余分なストローを分配し、見つかった最大の LCM を維持することです。 ペア数だけではこれは不可能です。 100 万個のバケットがある場合、およそ`5 * 10^11`ペア。 

重要な観察は、初期値が小さいということです。 可能な最大の開始値は 1000 のみであるため、バケットに関して重要な情報は最大の 2 つの初期値のみです。 選択した開始値の 1 つを増やしても、達成可能な最大 LCM を減らすことはできません。これは、より小さい開始構成でも、少なくとも同量の利用可能な総材料を含む構成に移行できるためです。 

2 つの最大の開始バケットを選択した後、それらの初期値が次のようになったとします。`a`そして`b`。 最終的な値は以下を満たす必要があります。`x >= a`、`y >= b`、 そして`x + y <= a + b + K`。 

このペアの場合、1 つのバケットの可能な範囲は約 100 万値のみです。 考えられるすべての最終値を試すことができます`x`、可能な最大値を計算します`y`、LCMを評価します。 範囲が 100 万に制限されているため、これは十分に高速です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²K) | お(1) | 遅すぎる |
 | 最適 | O(K + 1000) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの最大の初期バケット値を見つけます。 これら 2 つのバケットのみが最適解に参加できます。選択したバケットのいずれかを、開始ストローの少ないバケットに置き換えても、利用可能な合計が大きくなることはないからです。 
2. これらの値を次のようにします。`a`そして`b`。 選択した 2 つのバケットの最終合計の最大値は次のとおりです。`limit = a + b + K`。 
3. 考えられるすべての最終値を反復処理します。`x`最初のバケットから始まる`a`。 2 番目のバケットの最大値は次のとおりです。`y = limit - x`なぜなら、未使用のストローは単純に無視できるからです。 
4. かどうかを確認します。`y`少なくとも`b`。 そうであれば計算してください`lcm(x, y)`そして答えを更新します。 
5. 見つかった最大の LCM を出力します。 

アルゴリズムの背後にある不変条件は、選択された 2 つのバケットのすべての有効な最終構成には、何らかの最初のバケット値があるということです。`x`スキャン範囲内。 そのために`x`、アルゴリズムは、可能な最大の 2 番目の値をテストします。これは、利用可能な合計を増やすことによって LCM を改善できる唯一の値です。 考えられるすべての最初の値がチェックされるため、最適なペアをスキップすることはできません。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))

    first = 0
    second = 0

    for x in arr:
        if x >= first:
            second = first
            first = x
        elif x > second:
            second = x

    a = first
    b = second
    limit = a + b + k

    ans = 0

    for x in range(a, limit - b + 1):
        y = limit - x
        g = gcd(x, y)
        cur = x // g * y
        if cur > ans:
            ans = cur

    print(ans)

if __name__ == "__main__":
    solve()
```最初のループでは、2 つの最大の開始値のみが保持されます。 配列全体を読み取った後は保存しないため、入力バッファーを除いてメモリ使用量が一定に保たれます。 

変数`limit`は、選択した 2 つのバケツに入るストローの合計数を表します。 未使用のストローが許可されるため、最初のバケットを選択した後、2 番目のバケットは常に可能な最大値で考慮されます。 

LCM 計算は次のように記述されます。`x // gcd(x, y) * y`の代わりに`x * y // gcd(x, y)`。 この除算は、固定サイズの整数を使用する言語でのオーバーフローの可能性を減らすために最初に行われます。 Python の整数はオーバーフローしませんが、この形式は依然として標準的な安全な実装です。 

## 実用的な例

 サンプルの場合:```
2 2
3 5
```2 つの最大のバケツは 5 と 3 です。利用可能なストローの総数は 10 です。 

| × | y | gcd(x,y) | lcm | 最高 |
 | --- | --- | --- | --- | --- |
 | 3 | 7 | 1 | 21 | 21 |
 | 4 | 6 | 2 | 12 | 21 |

 答えは 21 です。トレースは、積を最大化するだけでは十分ではない理由を示しています。 互いに素のペア`(3,7)`より大きく見えるペアに勝つ`(5,5)`。 

2 番目の例:```

4 6
```利用可能な合計は 11 です。 

| × | y | gcd(x,y) | lcm | 最高 |
 | --- | --- | --- | --- | --- |
 | 4 | 7 | 1 | 28 | 28 |

 アルゴリズムは、余分なストローを分配して互いに素な数を作成すると、より大きな答えが得られることがわかります。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(K + 1000) | スキャンでは、最大約 100 万個の可能な値がチェックされます。 |

 最大スキャン長はおおよそ次のとおりです。`1,001,000`、これは 2 秒の制限としては十分小さいです。 100 万のバケット入力が 1 パスで処理されます。 

## テストケース```python
import sys
import io
from math import gcd

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n, k = map(int, input().split())
    arr = list(map(int, input().split()))

    first = second = 0
    for x in arr:
        if x >= first:
            second = first
            first = x
        elif x > second:
            second = x

    limit = first + second + k
    ans = 0
    for x in range(first, limit - second + 1):
        y = limit - x
        ans = max(ans, x // gcd(x, y) * y)

    sys.stdin = old_stdin
    return str(ans)

assert run("2 2\n3 5\n") == "21"
assert run("2 1\n1 1\n") == "2"
assert run("2 1\n1000 1000\n") == "1001000"
assert run("3 5\n7 7 7\n") == "143"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 1 / 1 1`| 2 | 最小値と小さい LCM の処理 |
 |`2 1 / 1000 1000`| 1001000 | 最大の初期値と大きな乗算 |
 |`3 5 / 7 7 7`| 143 | 等しい値と gcd 相互作用 |

 ## 特殊なケース

 両方の最大のバケットが同じ値を持つ場合でも、アルゴリズムはすべての分割をチェックします。 のために：```
2 1
5 5
```合計は 11 です。スキャンチェックでは`(5,6)`、生産`30`両方のバケットを誤って等しく保つのではなく、

 最良の結果が互いに素な数値から得られる場合、アルゴリズムは最大の積に依存しません。 のために：```
2 2
3 5
```それはテストします`(3,7)`そして得ます`21`、 その間`(5,5)`与えるだけ`5`。 

最適解の山に未使用のストローが多数含まれている場合でも、アルゴリズムは不等式のみを使用するため機能します。`x + y <= limit`。 2 番目のバケットは、最初に選択した各バケットに対して可能な最大値に設定され、すべての有効な分布はスキャンされたペアによって表されます。
