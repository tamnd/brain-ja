 ## 解決策
 ## 問題の理解

 整数の行があり、その行を非降順でソートする必要があります。 使用できる唯一のアクションは、行の連続した部分を選択し、その部分だけを並べ替えることです。 消費されるエネルギーは、選択したパーツの長さとその長さのセグメントのみに依存します。`k`費用`k³`。 タスクは、必要な最小総エネルギーを見つけることです。 

最初の有益な観察は、値が最終的にソートされた配列に含まれるはずの値になっていない位置のみを考慮するということです。 正しい値を含む位置をタッチする必要はありませんが、間違った位置はすべて少なくとも 1 回の操作に含める必要があります。 

入力サイズが大きいです。 1 つのテスト ケースには最大で次のものを含めることができます。`100000`すべてのテスト ケースの数と合計サイズが到達可能`2000000`。 これにより、多くの間隔の試行やポジションに対する動的プログラミングを含むものは除外されます。`O(n²)`遅すぎるでしょう。 ソート後に配列を一定回数スキャンするソリューションが必要です。 

いくつかのケースは見落とされやすいものです。 配列がすでにソートされている場合、操作は必要ないため、答えはゼロになります。 

例えば：```
1
5
1 2 3 4 5
```答えは次のとおりです。```
0
```常に配列全体に対する演算を作成する不注意な解決策は、正の値を返します。 

もう 1 つの重要なケースは、間違った位置が正しい位置で区切られている場合です。```
1
4
2 1 1 3
```ソートされた配列は`[1,1,2,3]`したがって、位置 1 と 3 は間違っています。 間違った位置の連続した 1 つのブロックとして扱うことはできません。 最適なソリューションでは、長さ 2 の 2 つの演算を使用します。1 つは位置 1 と 2 をカバーし、もう 1 つは位置 2 と 3 をカバーします。コストは次のとおりです。`8 + 8 = 16`。 

連続する間違ったブロックの長さをカウントするだけのソリューションでは、この可能性が誤って無視されてしまいます。 

## アプローチ

 直接的なアプローチは、すべての間隔を試して並べ替え、どの一連の操作が最小のエネルギーを与えるかを確認することです。 これは正しいです。許可されたすべての移動が明示的にシミュレートされるからです。 ただし、`O(n²)`間隔が長くなり、各シミュレーションには追加の作業が必要になります。 のために`n = 100000`、これはまったく不可能です。 

重要な観察は、逆のプロセスを観察することで得られます。 ソートされた配列から始めて、操作の逆を適用することを想像してください。 順方向操作は単に並べ替えるだけであるため、逆方向操作では選択した間隔を任意に再配置できます。 したがって、逆演算に含める必要がある位置は、最終的にソートされた配置と異なる位置だけです。 

次にコスト関数を考えてみましょう。 長さのセグメント`k`費用`k³`。 長さが 2 を超えるセグメントは、それをより小さいセグメントに置き換えることよりも優れた方法はありません。 たとえば、長さ 3 のセグメントのコストは`27`、長さ 2 のセグメントが 2 つあるとコストがかかります`16`。 一般的に、長さをカバーする`k`隣接するペアの間隔のコスト`8 * ceil(k / 2)`、常により小さいです`k³`のために`k >= 3`。 

これにより、問題ははるかに単純なものになります。 すべての間違った位置が少なくとも 1 つのペアでカバーされるように、隣接する位置のペアを選択するだけで済みます。 選択した各ペアの正確な価格`8`。 

不正確な長さの位置が連続して実行される場合`k`、必要な隣接ペアの最小数は次のとおりです。`ceil(k / 2)`。 2 つのラン間の正しい位置は、孤立した不正確な位置の隣接位置として引き続き使用できるため、ランは相互作用しませんが、別のラン内で必要なペアの数を減らすことはできません。 間違った位置をスキャンし、これらのペアを数えることで答えが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 並べ替えられた配列のコピーを作成します。 すべての元の位置と並べ替えられたコピー内の値を比較し、位置が間違っているかどうかをマークします。 これらの位置は、操作でカバーする必要がある唯一の位置です。 
2. 間違った位置のブール配列をスキャンします。 不正確な位置の連続ランが見つかったときはいつでも、その長さを次のようにします。`len`。 この実行に必要なのは`ceil(len / 2)`各操作で最大 2 つの位置をカバーできるため、隣接する操作が必要になります。 
3.追加`8 * ceil(len / 2)`実行ごとに答えが得られます。 長さ 2 の演算コスト`2³ = 8`したがって、必要なペアの数に 8 を掛けると、総エネルギーが得られます。 
4. 蓄積されたエネルギーを出力します。 

なぜ効果があるのか:

 間違った位置はすべて、少なくとも 1 つの選択された間隔に出現する必要があります。 2 より長い間隔は長さ 2 の間隔に分割するよりも常にコストがかかるため、最適な解決策は隣接するペアのみを使用します。 の実行`len`間違った位置には少なくとも`ceil(len / 2)`各ペアが最大 2 つの位置をカバーするため、ペアになります。 交互に隣接するペアを使用する構成はこの下限に達するため、ペアの数は最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        b = sorted(a)

        wrong = [a[i] != b[i] for i in range(n)]

        cost = 0
        i = 0
        while i < n:
            if not wrong[i]:
                i += 1
                continue

            j = i
            while j < n and wrong[j]:
                j += 1

            length = j - i
            cost += ((length + 1) // 2) * 8
            i = j

        ans.append(str(cost))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```ソートされたコピーは、どの位置がすでに正しいかを識別するためにのみ使用されます。 実際の一連の操作は必要なく、最小限のエネルギーのみが必要なため、アルゴリズムは配列を変更することはありません。 

スキャンにより、不正確な位置の最大ランが検出されます。 表現`(length + 1) // 2`浮動小数点演算を回避して、ラン長の半分の上限を計算します。 Python の整数は、考えられる最大の答えが範囲内に収まるため、オーバーフローも回避します。 

境界条件は 2 つの while ループによって処理されます。 最後の位置で終了する実行は、次の場合に内側のループが停止するため、正しく処理されます。`j == n`。 

## 実用的な例

 サンプルの場合:```
1
4
2 1 4 3
```ソートされた配列は`[1,2,3,4]`。 間違った位置は 4 つの位置すべてです。 

| インデックス | 間違っています | 現在のランレングス | 追加コスト |
 | --- | --- | --- | --- |
 | 1 | はい | 4 | 0 |
 | 2 | はい | 4 | 0 |
 | 3 | はい | 4 | 0 |
 | 4 | はい | 終わった | 16 |

 ランレングスは`4`、したがって、それが必要です`ceil(4/2)=2`隣接する操作。 費用は`2 * 8 = 16`。 

分離された例:```
1
4
2 1 1 3
```ソートされた配列は`[1,1,2,3]`。 

| インデックス | 値 | 並べ替えられた値 | 間違っています |
 | --- | --- | --- | --- |
 | 1 | 2 | 1 | はい |
 | 2 | 1 | 1 | いいえ |
 | 3 | 1 | 2 | はい |
 | 4 | 3 | 3 | いいえ |

 長さ 1 のランが 2 つあります。 

| 走る | 長さ | 必要なペア | コスト |
 | --- | --- | --- | --- |
 | 最初の間違った位置 | 1 | 1 | 8 |
 | 2 番目の間違った位置 | 1 | 1 | 8 |

 最終的な答えは、`16`。 この例は、連続する間違ったブロックを数えるだけでは十分ではない理由を示しています。 単一の間違った位置は、依然として隣接する位置と組み合わせる必要があります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | リニア スキャンではソートが優先されます。 
| スペース | O(n) | ソートされたコピーとブール配列が保存されます。 

すべてのテスト ケースの要素の合計数は次のとおりです。`2 * 10^6`したがって、並べ替えアプローチは制限内に問題なく適合します。 残りの作業は直線的であり、小さな定数係数を追加するだけです。 

## テストケース```python

import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    def solve():
        import sys
        input = sys.stdin.readline
        t = int(input())
        out = []

        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))
            b = sorted(a)

            ans = 0
            i = 0
            while i < n:
                if a[i] == b[i]:
                    i += 1
                    continue
                j = i
                while j < n and a[j] != b[j]:

                ans += ((j - i + 1) // 2) * 8
                i = j

        print("\n".join(out))

    result = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = result
    solve()
    sys.stdout = old_stdout
    sys.stdin = old_stdin
    return result.getvalue()

 ## 特殊なケース

 次のようなすでにソート済みの配列の場合:```
1
5
1 2 3 4 5
```ソートされたコピーとの比較はすべて成功します。 スキャンが間違った位置で実行されることは決してないため、答えはゼロのままです。 

分離された間違った位置の場合:```
1
4
2 1 1 3
```アルゴリズムは長さ 1 の 2 つの実行を認識します。 各実行は 1 つの隣接するペアに寄与し、次のようになります。`8 + 8 = 16`。 中央の正しい位置は両方の操作に含めることができるため、2 つの間違った位置を修正することができます。 

連続して間違ったセグメントの場合:```
1
6
6 5 4 3 2 1
```6 つの位置がすべて間違っています。 ランレングスは 6 であるため、式によれば、隣接する操作は 3 つで十分です。 答えは、`3 * 8 = 24`。 3 次コストがはるかに大きくなるため、アルゴリズムは 1 つの大きな間隔を使用しようとしません。
