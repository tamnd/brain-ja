 ## 解決策
 ## 問題の理解

 ツリーにはすべての頂点に小文字が含まれています。 順序付けられた頂点のペアごとに 1 つの文字列が定義されます。最初の頂点から開始し、一意のパスに沿って 2 番目の頂点まで進み、見つかった文字を連結します。 タスクは、そのような順序付けされたパスすべての中から辞書順に K 番目に小さい文字列を見つけることです。 

頂点は最大 100,000 個あり、これは、可能なパスの数が 100 億に達する可能性があることを意味します。 すべてのパスを列挙したり並べ替えたりすることは不可能です。 K が最大でも 100000 しかないという事実を利用する必要があります。集合全体ではなく、辞書順の先頭のみが必要です。 

よくある間違いは、パスを方向のないものとして扱うことです。 u から v へのパスと v から u へのパスは、文字が異なる方向に読まれるため、異なる文字列になります。 

例えば：```
2 1
a b
1 2
```可能な文字列は次のとおりです。`a`、`b`、`ab`、 そして`ba`。 答えは、`a`、 ない`ab`これは、同じプレフィックスを持つ短い文字列の方が小さいためです。 

## アプローチ

 直接的な解決策は、すべての N² パスを生成し、それぞれを文字列に変換し、並べ替えて、K 番目の要素を取得することです。 ツリー トラバーサルでは O(N) で 1 つのパスを見つけることができるため、このアプローチでは、制限をはるかに超える最悪のケースでは O(N³) 回の作業が必要になります。 

有益な観察は、K が小さいということです。 ソートされたリスト全体を作成する代わりに、優先キューを使用して辞書順にパスを生成できます。 各キュー要素は、すでに構築された 1 つのパスを表します。 最初は、すべての単一頂点は長さ 1 の有効なパスです。 最小のパスを削除すると、すぐに前の頂点に戻らないように、可能なすべての方向に隣接する頂点を 1 つ拡張します。 

これは、すべての有効なツリー パスの暗黙的なトライを探索することと同じです。 優先キューには常に最小の未完了プレフィックスが含まれるため、最小値を繰り返し取得すると、次の辞書編集パスが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N3) | O(N²) | 遅すぎる |
 | 優先キューの列挙 | O((N+K) log(N+K) + S) | O(N+K) | K ≤ 100000 の場合は受け入れられます |

 ## アルゴリズムのチュートリアル

 1. すべての単一頂点を優先キューの初期パスとして挿入します。 これらの各文字列は、同じ頂点で始まり同じ頂点で終わるパスを表します。 
2. キューから最小の文字列を削除します。 これは辞書順で次のパスなので、答えの 1 つとして数えてください。 
3. これが K 番目に削除された文字列である場合は、すぐに出力します。 残りのパスを生成する必要はありません。 
4. それ以外の場合は、現在のパスを、元の頂点を除く最後の頂点のすべての近隣を通るように延長します。 これらの新しいパスをキューに挿入します。 

これが機能する理由は、すべての有効なパスに、最後の頂点を削除することによって取得された先行パスが 1 つだけ存在するためです。 優先キューは、可能なすべての継続を順序付けて維持するため、小さいパスより前のパスをスキップすることはできません。 

なぜ効果があるのか:

 キューの不変条件は、次の回答となる可能性のある生成されたすべてのパスがキューに含まれていることです。 最小要素が削除されると、キューにないすべてのパスは、すでに出力されているか、さらに小さいプレフィックスがキュー内で待機しているかのいずれかになります。 したがって、削除された要素は常に次の辞書編集パスになります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    letters = input().split()

    graph = [[] for _ in range(n)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        graph[a].append(b)
        graph[b].append(a)

    heap = []

    for i in range(n):
        heapq.heappush(heap, (letters[i], i, -1))

    count = 0

    while heap:
        s, node, parent = heapq.heappop(heap)
        count += 1

        if count == k:
            print(s)
            return

        for nxt in graph[node]:
            if nxt != parent:
                heapq.heappush(heap, (s + letters[nxt], nxt, node))

if __name__ == "__main__":
    solve()
```キューには、現在の文字列とパスの最後の 2 つの頂点が保存されます。 前の頂点が必要なのは、ツリー パスがすぐに戻ることができないためです。そうしないと、同じエッジを 2 回通過することになります。 

初期化では、長さ 1 の N 個のパスが挿入されます。 パスが削除された後、可能なすべてのワンステップ拡張が追加されます。 アルゴリズムは K 個のパスが抽出されるとすぐに停止するため、パスのセット全体を構築しようとすることはありません。 

実装の主な詳細は、前の頂点を保持することです。 これがないと、拡張により次のような無効なウォークが生成されてしまいます。`a b a b a`、これはツリー内の単純なパスではありません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((N+K) log(N+K) + L) | 抽出されたパスごとに展開が作成され、K 個のパスのみが削除されます。 
| スペース | O(N+K) | ヒープにはアクティブな候補が保存されます。 

この解決策は、K が 100000 によって制限されることに依存します。順序付けのプレフィックスのみを生成すると、可能なパスの 2 次数が回避されます。 

## 特殊なケース

 単一の頂点ツリー:```
1 1
a
```唯一の道は`a`、したがって、答えは次のとおりです`a`。 最初のキューにはすでに完全な回答が含まれています。 

繰り返される文字:```
3 3
a a a
1 2
2 3
```多くの文字列は、最初の文字については同等に比較されます。 最初の文字だけでなく完全な文字列が比較されるため、ヒープはこれを処理します。 

方向パス:```
2 4
a b
1 2
```順序付けられたパスは次のとおりです。```
a
ab
b
ba
```最後の答えは、`ba`。 ツリーを無向として扱うと、誤ってマージされる`ab`そして`ba`。 保存された以前の頂点は、トラバースの方向を維持します。
