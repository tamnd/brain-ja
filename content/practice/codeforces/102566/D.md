 ## 解決策
 # 問題の理解

 あります`N`プロジェクトと`M`都市。 すべてのプロジェクトは、可能な 2 つの方法のうちの 1 つで実行する必要があります。 最初のオプションは無害であると考えられますが、2 番目のオプションは有害です。 各オプションは既知の金額をすべての都市に寄付します。 

目標は、各都市の貢献総額が必要な予算と正確に一致するように、プロジェクトごとに 1 つのオプションを選択することです。 すべての有効な選択肢の中で、有害な選択肢が選択されたプロジェクトの数を可能な限り少なくする必要があります。 どのプロジェクトを選択しても市の予算すべてを満たすことができない場合、答えは次のとおりです。`impossible`。 

の値`N`そして`M`両方とも最大 30 です。各プロジェクトには 2 つの状態があり、構成の合計数は`2^N`。 と`N = 30`、それは10億以上の可能性であり、制限時間内にチェックできる範囲をはるかに超えています。 次元`M`また、長さ 30 のベクトルの保存と比較が実用的であるほど十分に小さいため、解決策はベクトルの次元を減らすのではなく、組み合わせの数を減らすことに重点を置く必要があります。 

この問題を考えるのに役立つ方法は、すべてのプロジェクトに対して無害な選択から始めることです。 これにより、固定の初期支出ベクトルが得られます。 どのプロジェクトでも、無害なプロジェクトから有害なプロジェクトに切り替えると、差異ベクトルが追加されます。 タスクは、選択したベクトルの数を最小限に抑えながら、合計が欠損量と正確に一致するこれらの差分ベクトルのサブセットを見つけることになります。 

単純なソリューションを壊す可能性のあるいくつかの特殊なケースがあります。 ターゲット ベクトルが存在するかどうかをチェックするだけで、有害な選択肢の最小数を保存しないソリューションは、有効ではあるが最適ではない答えを返す可能性があります。 例えば：```
N = 2, M = 1
budget = [2]
project 1: (0, 1)
project 2: (0, 2)
```プロジェクト 2 の有害なオプションを選択すると、1 つの有害な選択肢で予算に到達しますが、両方の有害なオプションを選択すると、2 つの有害な選択肢でも予算に到達します。 不注意な存在チェックにより、どちらかが返される可能性があります。 

もう 1 つの問題は、有害なオプションのコストが無害なオプションよりも小さい可能性があることを忘れていることです。 差分ベクトルは常に正であるとは限りません。 例えば：```
N = 1, M = 1
budget = [0]
project 1: (5, 0)
```正しい答えは、`1`, 有害なオプションを選択すると、無害な選択と比較して支出が 5 減少するためです。 有害な選択をプラスの増加のみとして扱うことは、ここでは失敗します。 

3 番目のエッジ ケースは、基本的な無害なソリューションがすでにすべての市の予算を満たしている可能性があるということです。```
N = 1, M = 1
budget = [5]
project 1: (5, 7)
```答えは、`0`。 少なくとも 1 つの有害な選択を強制するアルゴリズムは、誤った結果を生成します。 

## アプローチ

 直接的なアプローチは、プロジェクトへのオプションの割り当てをすべて試してみることです。 それぞれについて、`2^N`割り当てに応じて、すべての都市での結果として生じる支出を計算し、それが予算と一致するかどうかを確認し、有害な選択の数を最小限に抑えます。 このアプローチは、考えられるすべての決定を検討するため正しいですが、最悪の場合には次のことが必要になります。`2^30`これは約 10 億 7,000 万の州に相当します。 たとえ各状態が非常に迅速に処理されたとしても、これでは遅すぎます。 

重要な構造は、プロジェクトの数がわずか 30 であることです。これは、中間で会うことが役立つ典型的な範囲です。 30 件の意思決定をすべてまとめて処理するのではなく、プロジェクトを約 15 件ずつの 2 つのグループに分割します。各半分には、`2^15 = 32768`可能な選択肢ですが、それは管理可能です。 

無害な選択肢が出発点として使用されます。 プロジェクトごとに、有害な選択と無害な選択の違いを計算します。 次に、プロジェクトのサブセットは、それらのプロジェクトに対して有害なオプションを選択することによって引き起こされる全体的な変化を表します。 

前半では、すべてのサブセットを列挙し、結果として得られる差分ベクトルを、使用された有害な選択の数とともに保存します。 後半では、すべてのサブセットを列挙し、前半から相補的なベクトルを探します。 必要な合計の変更が`target`、後半は貢献します`s`の場合、前半は貢献する必要があります`target - s`。 

最小限の有害カウントは、前半の最良の一致と後半のすべての可能性を組み合わせることによって求められます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^N * M) | お(お) | 遅すぎる |
 | 真ん中で会う | O(2^(N/2) * M) | O(2^(N/2) * M) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのプロジェクトが無害なオプションを使用した場合の合計貢献度を計算します。 すべてのプロジェクトについて、そのプロジェクトを有害なオプションに変更するときに追加されるベクトルも計算します。 最終的な答えは、どの差分ベクトルが選択されるかによってのみ決まります。 
2. 必要なバジェットから無害な合計を減算して、ターゲット差分ベクトルを計算します。 プロジェクトの差異からこのベクトルを作成できない場合、有効な選択は存在しません。 
3. プロジェクトを 2 つのグループに分割します。 最初のグループにはプロジェクトの約半分が含まれ、2 番目のグループには残りが含まれます。 これにより、指数関数的な検索が減少します。`2^30`約 2 回の検索が可能`2^15`可能性。 
4. 最初のグループのすべてのサブセットを列挙します。 各サブセットについて、その差分ベクトルの合計と、それに含まれる有害な選択肢の数を計算します。 結果として生じるすべてのベクトルの最小有害カウントを保存します。 以降の組み合わせでは、そのベクトルを作成するための最も安価な方法のみが考慮されるため、最小限のみを維持するだけで十分です。 
5. 2 番目のグループのすべてのサブセットを列挙します。 各サブセットについて、その差分ベクトルと有害なカウントを計算します。 最初のグループで必要な欠落ベクトルは、ターゲット ベクトルから現在の 2 番目のグループのベクトルを引いたものです。 
6. 保存されたマップ内で必要な第 1 グループのベクトルを検索します。 存在する場合は、2 つの有害なカウントを組み合わせて答えを更新します。 
7. サブセットのペアがターゲット ベクトルを生成しない場合は、次のように出力します。`impossible`。 それ以外の場合は、見つかった最小の有害なカウントを出力します。 

なぜ効果があるのか:

 有害なプロジェクトのあらゆる選択は、前半から選択されたプロジェクトと後半から選択されたプロジェクトに一意に分割できます。 両方の半分の列挙では、そのようなすべての分割が考慮されます。 固定された後半の選択の場合、ルックアップでは、残りの必要な変更が前半までに生成できるかどうかが正確に尋ねられます。 格納された前半の各ベクトルは最小限の有害なカウントのみを保持するため、そのベクトルに対して可能な最良の組み合わせが常に使用されます。 したがって、あらゆる有効な解決策が考慮され、有害な選択肢は最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, m, budget, projects):
    base = [0] * m
    diff = []

    for harmful, harmless in projects:
        for j in range(m):
            base[j] += harmless[j]
        diff.append([harmful[j] - harmless[j] for j in range(m)])

    target = tuple(budget[j] - base[j] for j in range(m))

    first = diff[:n // 2]
    second = diff[n // 2:]

    def enumerate_half(arr):
        result = {}
        length = len(arr)
        total = 1 << length

        sums = [(0,) * m]
        counts = [0]

        for mask in range(1, total):
            bit = mask & -mask
            idx = bit.bit_length() - 1
            previous = mask ^ bit
            old = sums[previous]

            cur = tuple(old[j] + arr[idx][j] for j in range(m))
            sums.append(cur)
            counts.append(counts[previous] + 1)

            if cur not in result or counts[-1] < result[cur]:
                result[cur] = counts[-1]

        return result

    left = enumerate_half(first)

    answer = n + 1
    right_len = len(second)
    total = 1 << right_len
    sums = [(0,) * m]
    counts = [0]

    for mask in range(total):
        if mask != 0:
            bit = mask & -mask
            idx = bit.bit_length() - 1
            previous = mask ^ bit
            old = sums[previous]
            cur = tuple(old[j] + second[idx][j] for j in range(m))
            sums.append(cur)
            counts.append(counts[previous] + 1)
        else:
            cur = sums[0]

        need = tuple(target[j] - cur[j] for j in range(m))
        if need in left:
            answer = min(answer, counts[mask] + left[need])

    return "impossible" if answer == n + 1 else str(answer)

def main():
    data = sys.stdin.buffer.read().split()
    if not data:
        return

    it = iter(data)
    t = int(next(it))
    ans = []

    for _ in range(t):
        n = int(next(it))
        m = int(next(it))

        budget = [int(next(it)) for _ in range(m)]

        projects = []
        for _ in range(n):
            harmless = []
            harmful = []
            for _ in range(m):
                x = int(next(it))
                y = int(next(it))
                harmless.append(x)
                harmful.append(y)
            projects.append((harmful, harmless))

        ans.append(solve_case(n, m, budget, projects))

    print("\n".join(ans))

if __name__ == "__main__":
    main()
```実装の最初の部分では、無害なベースラインと差分ベクトルを構築します。 ベースラインは、有害な選択を検討する前にすでに費やされた金額を表し、各差分ベクトルは、1 つのプロジェクトを有害にすることによる正確な影響を表します。 

の`enumerate_half`関数は、片側の中央の列挙でミートを実行します。 配列`sums`以前に計算されたサブセットの合計を保存するため、新しいサブセットを生成するには、サブセット全体を再計算するのではなく、プロジェクトを 1 つ追加するだけで済みます。 複数のサブセットが同じ支出の変化を引き起こす可能性があるため、ディクショナリにはすべてのベクトルの最小有害カウントが格納されます。 

後半は、前半の辞書で補語を検索しながら列挙します。 必要なベクトルは次のように計算されます。`target - current_second_half`。 一致するということは、2 つの部分が一緒になって、不足している支出調整が正確に作成されることを意味します。 

Python の整数はオーバーフローしないため、唯一の懸念事項はメモリ使用量です。 せいぜい`2^15`長さ 30 のベクトルが保存されますが、これは許容されます。 タプルは辞書キーになる可能性があるため、タプル表現が使用されます。
