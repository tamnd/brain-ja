 ## 解決策
 ## 問題の理解

 グラフには、入力文字列の空でない部分文字列ごとに 1 つの頂点があります。`s`。 部分文字列から`t`長さの`L`、エッジは、のすべての個別の部分文字列に行きます。`t`長さの`L-1`。 

可能な長さの部分文字列は 2 つだけです`L-1`内部`t`: 最初の文字を削除するか、最後の文字を削除します。 通常、これら 2 つの文字列は異なるため、頂点には 2 つの出力エッジがあります。 のすべての文字が一致する場合、それらは正確に等しくなります。`t`同じです。 その場合、2 つの可能なエッジは 1 つに折りたたまれます。 

から始まるパス`s`どちらかの端から 1 文字を繰り返し削除します。 その長さは厳密に減少するため、すべてのパスは自動的に単純になります。 タスクは、次のものだけで構成されるパスも含め、そのようなパスをすべてカウントすることです。`s`、モジュロ`998244353`。 

限界の長さは`300000`したがって、文字列の長さの二次関数は範囲外になります。 Θ(n²) 個の異なる部分文字列が存在する可能性があり、その時点ですでに約 450 億個になります。`n = 300000`。 解決策では、部分文字列やグラフの頂点の列挙を避ける必要があります。 2 秒の制限により、定数係数が小さい場合を除き、O(n log n) の解は望ましくないものになりますが、O(n) の解は自然な目標です。 

微妙な部分は、同じ部分文字列の 2 つの異なる出現が 1 つのグラフの頂点を表すことです。 たとえば、`aabaa`、部分文字列`aa`は 2 回発生しますが、先行する異なる文字列を介してそれに到達するパスは依然として異なるパスです。 グラフの頂点の出現を個別にカウントするのではなく、パスをカウントする必要があります。 

もう 1 つの特殊なケースは、1 つの繰り返し文字で構成される部分文字列です。 のために`aa`、エンドポイントを削除するどちらの方法でも同じ頂点が生成されます。`a`, したがって、出ていくエッジは 1 つだけです。 入力に対する正解`aa`は`2`、に対応`aa`そして`aa -> a`。 2 つのエンドポイントの削除を異なるものとして扱うと、次のようになります。`3`。 

同じ現象は、単項文字列が長くなるとより顕著になります。 入力用`aaa`、グラフは単純に`aaa -> aa -> a`、したがって、答えは次のとおりです`3`、 ない`7`。 すべての頂点に 2 つの外向きエッジがあると仮定する不注意な解決策では、`2^n-1`数えて失敗する。 

反対の極端な例として、次のように考えます。`ab`。 長さ 1 の 2 つの子は次のとおりです。`a`そして`b`したがって、パスは次のようになります。`ab`、`ab -> a`、 そして`ab -> b`。 正しい答えは、`3`。 これは、2 つのエンドポイント遷移が実際に異なる最小のケースです。 

## アプローチ

 直接動的プログラムは値を割り当てます。`dp(t)`すべての個別の部分文字列に`t`。 もし`t`は単項ではなく、その 2 つの子はその長さの接頭辞と接尾辞です。`|t|-1`、与える`dp(t) = 1 + dp(prefix) + dp(suffix)`。 

単項文字列の場合、2 つの子は一致するため、`dp(t) = 1 + dp(prefix)`。 

この繰り返しは完全に正しいです。なぜなら、すべてのパスがすぐに停止するか、出力エッジを 1 つだけ取り、その子からのパスを続行するためです。 

問題は州の数です。 長さの文字列`n`Θ(n²) 個の異なる部分文字列を持つことができ、部分文字列ごとに 1 つの状態を保存することさえ不可能です。`n = 300000`。 最悪の場合、これは時間とメモリの制限をはるかに超える数百億の状態と遷移を意味します。 

有益な観察は、グラフがほぼバイナリ グラフであるということです。 すべての文字が等しい場合を除き、部分文字列には 2 つの異なる出力遷移があります。 公式チュートリアルでは、まさにこの区別を利用しています。つまり、現在の部分文字列が単項になると、その継続が強制されます。 

1 つのパスをたどって、現在の部分文字列が単項になる最初の瞬間を観察することを想像してください。 その瞬間までは、削除の選択肢はすべて完全に二値的です。 単項になると、次の頂点はどの長さにおいても 1 つだけ存在するため、単項部分文字列が長さを持っている場合`k`、まさにあります`k`そこから続く可能性のある経路。可能性のある停止点ごとに 1 つずつあります。 

これにより、巨大な部分文字列グラフを回避できます。 最終頂点が単項でないパスは、元の文字列内の間隔によって直接カウントできます。 単項になるパスは、代わりに最初の単項区間によって分類できます。 最大の等価文字ランのプレフィックスとサフィックスのみが最初の単項間隔になる可能性があるため、そのようなケースは O(n) のみです。 

発生間隔について`[l, r]`、からそこに到達します`s`削除することを意味します`l`左からの文字と、`n-1-r`右から文字。 これらの削除の順序は任意に選択できます。`C(l + n - 1 - r, l)`その間隔に到達するさまざまなパス。 

もし`[l,r]`少なくとも 2 つの異なる文字が含まれている場合、これは単項になったことのないパスの有効なエンドポイントです。 ホッケースティック ID を使用すると、すべての間隔を列挙しなくても、これらの値を合計できます。 

再帰には子が 2 つしかないため、ブルート フォースは機能しますが、Θ(n²) 個の部分文字列がある場合は失敗します。 単項部分文字列のみが 2 つの遷移を折りたたむという観察により、O(n) 回の実行ベースの寄与によってグラフ全体をカウントできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) の状態と遷移 | O(n²) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 階乗および逆階乗を最大で事前計算します。`n`したがって、必要なすべての二項係数は O(1) モジュロで評価できます。`998244353`。 すべての上位引数は最大でも`n-1`、これで十分です。 
2. スプリット`s`等しい文字の最大ラン数まで。 ランニング用`[L,R]`、その文字のみで構成されるすべての部分文字列がこの実行内にあります。 
3. 最終部分文字列に少なくとも 2 つの異なる文字が含まれるパスをカウントします。 左側の端点を修正する`l`、そしてさせてください`x`以降の最初の位置である`l`性格が違うのは`s[l]`。 それからインターバル`[l,r]`が非単項であるのは、正確に言うと`r >= x`。 

この修正に対する貢献`l`は`sum C(l+n-1-r, l)`のために`r = x ... n-1`。 

置く`a = l+n-1-r`。 範囲は次のようになります`a = l ... l+n-1-x`、したがって、ホッケースティックのアイデンティティは次のようになります。`sum C(a,l) = C(l+n-x, l+1)`。 

したがって、1 つの寄与が O(1) で得られ、すべての寄与が得られます。`l`O(n)で処理できる。 
4. 最大実行ごとに`[L,R]`、最初の単項部分文字列がこの実行のプレフィックスであるパスをカウントします。 このようなプレフィックスは、`[L,r]`。 直前の文字を削除することで、最初に単項になることができます。`L`、 提供された`L > 0`。 その先行者は非単項であるため、`[L,R]`最大限の走りです。 

前任者は、`[L-1,r]`、したがって、そこに到達するパスの数は`C(L+n-r-2, L-1)`。 

length の単項部分文字列に到達した後`r-L+1`、まさにあります`r-L+1`考えられる停止方法。 2 つの量を乗算し、その結果を加算します。 
5. 対称的に単項接尾辞を数えます`[l,R]`。 このような接尾辞は、直後の文字を削除することで初めて単項になります。`R`、 提供された`R < n-1`。 

前任者は、`[l,R+1]`、与える`C(l+n-R-2, l)`先代への道。 単項接尾辞には長さがあります`R-l+1`、したがって、その貢献度は`C(l+n-R-2, l) * (R-l+1)`。 
6. 実行の両側が存在する場合、実行全体がプレフィックスとサフィックスの両方の計算で発生する可能性があります。 2 つのケースは異なる先行頂点に対応し、したがって異なるパスに対応するため、これは正しいです。 
7. 入力文字列全体が 1 回の実行である場合、`s`それ自体はすでに単項です。 非単項先行関数がないため、前のカウントではゼロが生成されます。 この特殊なケースでは、グラフは次の連鎖になります。`n`頂点、そして答えは単純です`n`。 
8. 非単項エンドポイントからの寄与とすべての最初の単項ケースのモジュロを加算します。`998244353`。 

### なぜ効果があるのか

 以下から始まるパスを検討します。`s`。 単項部分文字列に到達しない場合、その最終頂点は非単項区間になります。`[l,r]`。 左右の削除の順序が一意にその間隔を決定し、正確に`C(l+n-1-r,l)`このような削除命令。 したがって、最初の部分では、このタイプのすべてのパスが 1 回だけカウントされます。 

次に、次の場所で初めて単項部分文字列に到達するパスを考えます。`[l,r]`。 以来`[l,r]`最大の等文字ランの内側にある場合、前の頂点はそのランの境界を越えて間隔を拡張する必要があります。 その結果`[l,r]`最大ランのプレフィックスまたはサフィックスである必要があります。 数式は、非単項先行関数に到達し、その後に移行するパスを正確にカウントします。`[l,r]`。 そこに到達すると、次のすべての遷移が強制されるため、次の長さの単項部分文字列`k`まさに貢献する`k`可能なパスの終わり。 これら 2 つのクラスは互いに素であり、すべてのパスをカバーしているため、最終的な合計が正確に必要な答えであることがわかります。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

MOD = 998244353

def solve_string(s: str) -> int:
    n = len(s)

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (n + 1)
    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def comb(a: int, b: int) -> int:
        if b < 0 or b > a:
            return 0
        return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

    if n == 1:
        return 1

    # runs = (L, R), inclusive.
    runs = []
    i = 0
    while i < n:
        j = i
        while j + 1 < n and s[j + 1] == s[i]:
            j += 1
        runs.append((i, j))
        i = j + 1

    # The whole string is unary.
    if len(runs) == 1:
        return n

    ans = 0

    # 1. Paths ending at a non-unary substring.
    #
    # For each l, let x be the first position after l with
    # s[x] != s[l]. Then [l, r] is non-unary iff r >= x.
    for L, R in runs:
        x = R + 1
        if x == n:
            continue

        for l in range(L, R + 1):
            # Sum over r = x .. n-1:
            #
            # C(l + n - 1 - r, l)
            #
            # = C(l + n - x, l + 1)
            ans += comb(l + n - x, l + 1)
            if ans >= MOD:
                ans -= MOD

    # 2. Paths whose first unary substring is a prefix of a run.
    #
    # The predecessor must extend one position to the left,
    # so L > 0 is required.
    for L, R in runs:
        if L == 0:
            continue

        for r in range(L, R + 1):
            ways_to_predecessor = comb(L + n - r - 2, L - 1)
            length = r - L + 1
            ans = (ans + ways_to_predecessor * length) % MOD

    # 3. Paths whose first unary substring is a suffix of a run.
    #
    # The predecessor must extend one position to the right,
    # so R < n - 1 is required.
    for L, R in runs:
        if R == n - 1:
            continue

        for l in range(L, R + 1):
            ways_to_predecessor = comb(l + n - R - 2, l)
            length = R - l + 1
            ans = (ans + ways_to_predecessor * length) % MOD

    return ans

def main() -> None:
    s = input().strip()
    print(solve_string(s))

if __name__ == "__main__":
    main()
```階乗配列は、すべての計数式で使用される二項係数を実装します。 逆剰余はフェルマーの定理を使用して一度計算され、残りの組み合わせは定数時間の乗算になります。 

実行構造は、すべての最大の等文字ブロックの両方のエンドポイントを与えます。 最初の単項部分文字列はそのようなブロックの境界に触れなければならないため、これで十分です。 部分文字列自体を構築する必要はありません。 

最初の計数ループは、アルゴリズムの非単項エンドポイント部分に対応します。 考えられるすべての左端点について、すべての有効な右端点は、ホッケースティックのアイデンティティから取得された 1 つの二項係数によって表されます。 これは、見かけ上の区間の二次列挙を取り除く重要なステップです。 

2 番目のループは、最初の単項プレフィックスを処理します。 前任者は、`[L-1,r]`、したがって、残った削除の数は次のようになります。`L-1`、右側の削除の数は`n-1-r`。 それらの合計が上位の引数を与えます`L+n-r-2`。 

3 番目のループは対称です。 前任者向け`[l,R+1]`、 がある`l`削除を残し、`n-R-2`正しい削除、与える`C(l+n-R-2,l)`。 

ループには、両側が存在する場合、両方向からの実行全体が意図的に含まれます。 先行する頂点が異なるため、これらは 2 つの別個のパスです。 初期文字列自体が単項である場合のみ、これらのループの前に処理されます。 

Python の整数はオーバーフローしませんが、すべての乗算は剰余化されます。`MOD`。 最大階乗指数は正確に`n`、すべての組み合わせ引数は事前計算された範囲内に収まります。 

## 実用的な例

 ### サンプル 1:`abba`最大実行数は次のとおりです。`[0,0] = a`、`[1,2] = bb`、 そして`[3,3] = a`。

 非単項寄与は次のとおりです。`5`。 たとえば、間隔`ab`、`abb`、`abba`、`ba`、 そして`bba`単項部分文字列に到達する前に終了するパスを考慮します。 

ランニングに向けて`bb`、単項接頭辞のケースは次のとおりです。`b`そして`bb`、左から到達。 彼らは貢献します`1 * 1 + 1 * 2 = 3`。 右から、対応するサフィックスが寄与します`1 * 1 + 1 * 2 = 3`。 頂点の 2 つの出現`bb`これらの計算では、異なる先行パスを表すため、両方の寄与が有効なままになります。 

合計は`5 + 4 + 4 = 13`、サンプル出力と一致します。

## テストケース```python
import sys
import io

MOD = 998244353

def solve_string(s: str) -> int:
    n = len(s)

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (n + 1)
    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def comb(a, b):
        if b < 0 or b > a:
            return 0
        return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

    if n == 1:
        return 1

    runs = []
    i = 0
    while i < n:
        j = i
        while j + 1 < n and s[j + 1] == s[i]:
            j += 1
        runs.append((i, j))
        i = j + 1

    if len(runs) == 1:
        return n

    ans = 0

    for L, R in runs:
        x = R + 1
        if x == n:
            continue
        for l in range(L, R + 1):
            ans = (ans + comb(l + n - x, l + 1)) % MOD

    for L, R in runs:
        if L == 0:
            continue
        for r in range(L, R + 1):
            ans = (
                ans
                + comb(L + n - r - 2, L - 1) * (r - L + 1)
            ) % MOD

    for L, R in runs:
        if R == n - 1:
            continue
        for l in range(L, R + 1):
            ans = (
                ans
                + comb(l + n - R - 2, l) * (R - l + 1)
            ) % MOD

    return ans

def run(inp: str) -> str:
    return str(solve_string(inp.strip()))
