 ## 解決策
 ## 問題の理解

 それぞれ最大 60 ビットを使用する最大 (300,000) の整数の配列と、しきい値 (x) があります。 選択された配列要素のすべてのペアが少なくとも (x) の XOR を持つ場合、サブシーケンスは良好であるとみなされます。 タスクは、答えを法 (998244353) として取得して、空ではないすべての良好なサブシーケンスをカウントすることです。 元の問題では、2 秒の時間制限と 1 GiB のメモリ制限が使用されています。 

配列の元の順序によってのみ、どのインデックスがサブシーケンスを形成するかが決まります。 条件自体は、選択した値にのみ依存します。 これは、最初に値を並べ替えて、その並べ替えられた順序から有効な選択をカウントできることを意味します。 ソートではサブシーケンスは失われません。等しい値は別個の要素のままであり、ソート後も位置の各サブセットは元の位置の 1 つのサブセットに正確に対応します。 

(n^2) は約 (9\cdot10^{10}) であるため、境界 (n\le300000) は (n) 内の二次関数を即座に除外します。 60 ビット境界の方がはるかに便利です。一度に 1 ビットを検査する操作では、要素ごとにおよそ 60 の作業を行うことができ、(O(60n)) アルゴリズムが得られます。 また、メモリ制限が大きいため、C++ ではトライが自然になりますが、単純な 60 レベルのトライには数千万のノードが含まれる可能性があり、Python では不必要にコストがかかります。 以下の実装では、圧縮されたバイナリ トライを使用し、分岐ノードのみを保持するため、そのサイズは個別の値の数に比例します。 

不注意な実装を黙って破壊してしまう可能性のあるエッジケースがいくつかあります。 (x=0) の場合、すべての XOR は負ではないため、空ではないすべてのサブシーケンスが有効になります。 たとえば、入力`3 0`価値観を持って`0 1 2`答え（2^3-1=7）があります。 等価性を無効として扱うソリューションでは、XOR ゼロのペアが誤って除外されてしまいます。 

等しい値が発生し (x>0) 、XOR が 0 になるため、同じ値の 2 つのコピーを一緒に選択することはできません。 例えば、`3 1`価値観を持って`5 5 5`答えがあります`3`3 つのシングルトン サブシーケンスのみが機能するためです。 配列を重複排除する不注意な解決策は、次のような結果を招く可能性があります。`1`3 つの等しい位置は依然として 3 つの異なるサブシーケンスの選択肢であるためです。 

条件が (x) 以上であるため、境界 (a_i\oplus a_j=x) は有効です。 例えば、`2 2`価値観を持って`0 2`答えがあります`3`: (0\oplus2=2) であるため、シングルトンとペア​​の両方が有効です。 を使用した実装`>`の代わりに`>=`戻るだろう`2`。 

最後に、ソートはリダクションに不可欠ですが、ソートされた位置は元のサブシーケンス インデックスではありません。 例えば、`3 2`価値観を持って`2 0 1`まだ答えがある`5`。 元の配列がすでに順序付けされていることを前提としたソリューションでは、有効な遷移が失われる可能性があります。 

## アプローチ

 直接的な総当たりアプローチは、空ではないすべてのサブシーケンスを列挙し、その中のすべてのペアをチェックすることです。 サイズ (k) のサブセットの場合、(\binom{k}{2}) 個の XOR 比較が行われます。 すべてのサブセットを合計すると、最悪の場合のペア チェックの数は次のようになります。 

\binom n2 2^{n-2}。 
]

 (n=300000) の場合、これは実際的な制限を超えています。 すべてのペアをチェックせずにサブセットを列挙する場合でも、すでに (2^n) 演算が必要です。 

最初の有益な観察は、値を並べ替えることから得られます。 (a\le b\le c) と仮定します。 3 つの数値がすべて等しくない最上位ビットに注目してください。 可能性は 2 つだけです。 (a) がそのビットで (b) および (c) の両方と異なるか、または (c) が (a) および (b) の両方と異なります。 最初のケースでは、(a\oplus b) と (a\oplus c) には上位ビットが設定されていますが、(b\oplus c) には設定されていないため、(b\oplus c) は両方より小さくなります。 2 番目のケースでは、(a\oplus b) は他の両方の XOR よりも小さくなります。 その結果、

 [
 \min(a\oplus b,b\oplus c)\le a\oplus c。 
]

 この性質は強い影響を及ぼします。 選択した値をソート順に取得し、

 [
 b_1\le b_2\le\cdots\le b_k。 
]

 連続する選択された値のすべてのペアが少なくとも (x) の XOR を持つ場合、すべての非連続ペアも少なくとも (x) の XOR を持ちます。 3 つの連続した選択された値について、上記の不等式は、外側のペアの XOR が少なくとも 2 つの隣接するペアの小さい方の XOR であることを示しています。 同じ引数を繰り返し適用すると、これが任意の距離まで拡張されます。 

したがって、ソート後は、元の全ペア条件がローカル条件になります。つまり、選択された 2 つの連続する値すべてが少なくとも (x) の XOR を持つ場合に、サブシーケンスが有効になります。 

これにより、計数の問題が動的なプログラムに変わります。 (f_i) を、最後に選択された要素がソートされた配列の (i) 番目の値である有効なサブシーケンスの数とします。 最後の要素は独立して、1 つのサブシーケンスを与えることができます。 それ以外の場合は、ある (j<i) で終わる有効なサブシーケンスに (a_i) を追加します。 

[
 a_j\oplus a_i\ge x。 
]

 したがって、

 1+
 \sum_{\substack{j<i\a_j\oplus a_i\ge x}}f_j。 
]

 残りの問題は、この重み付き XOR しきい値クエリを効率的に計算することです。 

標準のバイナリ トライでは、(O(60)) でクエリが解決されます。 すべてのビットで、XOR ビットと (x) の対応するビットを比較します。 (x) の対応するビットが 0 の場合、XOR ビットを 1 にすると、下位ビットに関係なく XOR 全体が大きくなり、トライ サブツリー全体をすぐに追加できるようになります。 (x) のビットが 1 の場合、(x) のプレフィックスと等しく保つには XOR ビットも 1 でなければならないため、1 つの分岐のみが続行できます。 

通常のトライには最大 (60n) 個のノードがあります。 これは低レベル言語では許容されますが、Python では適切な表現ではありません。 DP が開始される前にすべての値がわかっているため、分岐点のみを含む圧縮バイナリ トライを構築できます。 圧縮されたトライには (O(n)) 個のノードがありますが、クエリは最大 60 の分岐レベルに従います。 

結果の比較は次のようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2 2^n)) | (O(n)) | 遅すぎる |
 | 標準バイナリ トライ DP | (O(n\log A)) | (O(n\log A)) | 低レベル言語で使用可能 |
 | 圧縮バイナリトライ DP | (O(n\log A)) | (O(n)) | 承認済み |

 ここ (\log A\le60)。 

## アルゴリズムのチュートリアル

 1. 配列を非降順で並べ替えます。 元の全ペア条件は、(a\le b\le c) の場合、連続する選択された値のみをチェックすることで置き換えることができます。 

[
 \min(a\oplus b,b\oplus c)\le a\oplus c。 
]

 したがって、連続して選択されたペアがすべて閾値を満たしている場合、他のすべてのペアも閾値を満たします。

1. 等しい値を圧縮バイナリ トライの 1 つのリーフにグループ化します。 DP は依然として等しい出現を個別に処理するため、これは値空間の構造的な圧縮にすぎず、配列要素の削除ではありません。 
2. 圧縮トライを再帰的に構築します。 少なくとも 2 つの異なる値のセットについて、最小値と最大値が異なる最上位ビットを見つけます。 このビットにより、セットが 0 グループと 1 グループに分割されます。値はソートされているため、両方とも連続しています。 2 つのグループを再帰的に構築します。 
3. すべてのトライノードにサブツリーの合計を与えます。 この合計は、そのサブツリーに値が属するすでに処理された配列要素の合計 (f_j) を表します。 最初はすべての合計はゼロです。 
4. ソートされた配列を左から右に処理します。 現在の値 (v) について、次の条件を満たす以前の値 (y) の合計 DP 重みをトライに問い合わせます。 

[
 v\oplus y\ge x.
 ]

 返された合計を呼び出します (q)。 それから

 [
 f=1+q。 
]

 の`1`現在の位置のみを含むシングルトン サブシーケンスを表します。 

1. (f) をグローバル回答に追加し、この DP 重みを (v) を表すリーフに挿入します。 重みはすべての祖先にも伝播されるため、将来のクエリでは正しいサブツリーの合計が表示されます。 
2. 圧縮トライ クエリを実行するには、これまでの (x) との比較を等しく保ちます。 内部ノードでは、その分岐ビットは、その 2 つの子の値の間で異なる可能性がある次のビットです。 そのビットを使用する前に、圧縮によってスキップされたビットがサブツリー全体で固定されます。 これらの固定ビットを (x) と比較します。 固定 XOR プレフィックスがすでに (x) より大きい場合は、サブツリー全体を追加できます。 これより小さい場合は、サブツリー全体を破棄できます。 
3. 固定プレフィックスが等しい場合は、分岐ビットを検査します。 (x) の対応するビットが 0 の場合、XOR ビット 1 を生成する子は完全に有効であり、追加できますが、XOR ビット 0 を生成する子は等価パスを継続します。 (x) の対応するビットが 1 の場合、XOR ビット 1 を生成する子のみが続行できます。 
4. リーフでは、すべてのビットが固定されているため、その値と現在の値の XOR が少なくとも (x) であるかどうかを直接テストします。 リーフの保存された合計は含まれるか無視されます。 
5. すべての DP 値のモジュロ (998244353) を取得します。 Python の整数はオーバーフローしませんが、加算後に削減すると、保存されたサブツリーの合計が小さく保たれ、必要な出力係数と一致します。 

これが機能する理由: ソート後、重要な不変条件は、(f_i) によってカウントされた部分サブシーケンスが、連続して選択された値が XOR しきい値を満たす場合に正確に有効であるということです。 遷移では、そのしきい値を満たすすべての可能な前のエンドポイントが考慮されるため、(i) で終わるすべての有効なサブシーケンスは 1 回だけカウントされます。 圧縮されたトライは、保存されている値のセットを変更しません。 サブツリー内のすべての値が同じビットを持つビット位置のみをスキップし、それらのスキップされたビットを固定プレフィックスとして (x) と比較できます。 したがって、クエリによって追加されたすべてのサブツリーは完全に有効な先行処理で構成されますが、破棄されたすべてのサブツリーは完全に無効な先行処理で構成されます。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

MOD = 998244353
TOP = 59

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    # Only distinct values need structural nodes.
    vals = []
    for v in a:
        if not vals or vals[-1] != v:
            vals.append(v)

    m = len(vals)

    # Compressed binary trie.
    #
    # bit[u]  : branching bit, -1 for a leaf
    # left[u] : child with bit 0
    # right[u]: child with bit 1
    # rep[u]  : any representative value in the subtree
    # total[u]: sum of dp values currently stored in the subtree
    # parent[u]: parent node
    bit = []
    left = []
    right = []
    rep = []
    total = []
    parent = []

    leaf_of = {}

    def new_node(b, lch, rch, representative, par):
        idx = len(bit)
        bit.append(b)
        left.append(lch)
        right.append(rch)
        rep.append(representative)
        total.append(0)
        parent.append(par)
        return idx

    def build(lo, hi, par):
        if hi - lo == 1:
            v = vals[lo]
            u = new_node(-1, -1, -1, v, par)
            leaf_of[v] = u
            return u

        diff = vals[lo] ^ vals[hi - 1]
        b = diff.bit_length() - 1
        threshold = ((vals[lo] >> (b + 1)) << (b + 1)) | (1 << b)

        mid = bisect_left(vals, threshold, lo, hi)

        u = new_node(b, -1, -1, vals[lo], par)
        lc = build(lo, mid, u)
        rc = build(mid, hi, u)
        left[u] = lc
        right[u] = rc
        return u

    root = build(0, m, -1)

    def query(v):
        """
        Return the sum of dp values stored at y such that
        y xor v >= x.
        """
        u = root
        ans = 0

        # All bits above `top` are already known to be equal
        # between (representative xor v) and x.
        top = TOP

        while True:
            b = bit[u]

            if b == -1:
                if (rep[u] ^ v) >= x:
                    ans += total[u]
                    if ans >= MOD:
                        ans -= MOD
                return ans

            z = rep[u] ^ v

            # Bits b+1 ... top are fixed for the whole subtree.
            # If they already differ from x, the whole subtree has
            # the same comparison result.
            d = (z ^ x) >> (b + 1)
            if d:
                highest = b + 1 + d.bit_length() - 1
                if (z >> highest) & 1:
                    ans += total[u]
                    if ans >= MOD:
                        ans -= MOD
                return ans

            vb = (v >> b) & 1
            xb = (x >> b) & 1

            if xb == 0:
                # XOR bit 1 is already larger than x at this bit.
                greater_child = right[u] if vb == 0 else left[u]
                if greater_child != -1:
                    ans += total[greater_child]
                    if ans >= MOD:
                        ans -= MOD

                # XOR bit 0 keeps the prefix equal.
                equal_child = left[u] if vb == 0 else right[u]
            else:
                # XOR bit 0 would make the result smaller.
                # Only XOR bit 1 can keep equality.
                equal_child = right[u] if vb == 0 else left[u]

            if equal_child == -1:
                return ans

            u = equal_child
            top = b - 1

    answer = 0

    for v in a:
        dp = query(v) + 1
        if dp >= MOD:
            dp -= MOD

        answer += dp
        if answer >= MOD:
            answer -= MOD

        u = leaf_of[v]
        while u != -1:
            total[u] += dp
            if total[u] >= MOD:
                total[u] -= MOD
            u = parent[u]

    print(answer)

if __name__ == "__main__":
    solve()
```最初の部分では配列をソートし、`vals`、個別の値のソートされたリスト。 重複は次の場所に保持されます`a`なぜなら、すべての出現は異なる配列位置を表し、その結果、異なる可能性のあるサブシーケンスを表すからです。 圧縮トライは、個別の値ごとに 1 つの構造リーフのみを保存します。 

の`build`関数は、サブツリーの最小値と最大値の間で異なる最上位ビットを見つけます。 これが最初の異なるビットであるため、それより下のすべての値には同じ上位ビットのプレフィックスが付きます。 このビットが 0 に等しい値は 1 つの連続した範囲を形成し、このビットが 1 に等しい値は別の連続範囲を形成します。 結果として得られるツリーには、(m) 個の個別の値に対して最大で (2m-1) 個のノードが含まれます。 

の`total`配列には、各サブツリーの DP 値の合計が格納されます。 したがって、リーフを更新するには、その祖先をたどる必要があります。 パスには最大 60 の分岐レベルがあるため、更新コスト (O(60)) がかかります。 

微妙な部分は、`query`。 通常のバイナリ トライには、すべてのビット位置にノードがあります。 圧縮されたトライは、すべての値が一致する位置をスキップします。 圧縮されたノードでは、`rep[u]`は、そのサブツリー内のすべての値のスキップされたビットを表します。 表現```
d = (z ^ x) >> (b + 1)
```スキップされたプレフィックスがすでに (x) と異なっているかどうかを確認します。 存在する場合、最も高い相違ビットによってサブツリー内のすべての値の比較が決定されるため、クエリはすぐに終了できます。 

プレフィックスが等しい場合、現在の分岐ビットは通常の XOR しきい値トライとまったく同じように処理されます。 (x) ビットが 0 の場合、XOR ビット 1 を生成する分岐は完全に有効です。 (x) ビットが 1 の場合、XOR ビット 0 を生成する分岐は完全に無効になります。 等価性ブランチのみをさらに検査する必要があります。 

クエリは、現在の DP 値を挿入する前に実行されます。 これは、(f_i) が (j<i) のみを使用することを保証するものです。 シングルトンの寄与は、次のように個別に追加されます。`+1`。 

値は (2^{60}-1) まで大きくなるため、関連する最上位ビットは 59 になります。Python には任意精度の整数があるため、オーバーフロー処理は必要ありません。 係数は、保存されているすべての合計と、各加算後の答えに適用されます。 

## 実用的な例

 ### サンプル 1

 入力は`n=3`、`x=0`、並べ替えられた値は次のとおりです。`0,1,2`。 すべての非負 XOR は少なくとも 0 であるため、すべてのサブシーケンスは有効です。 

| ステップ | 値 (v) | クエリ結果 | (dp) | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 1 | 1 |
 | 2 | 1 | 1 | 2 | 3 |
 | 3 | 2 | 3 | 4 | 7 |

 最初の要素には前の値がないため、シングルトンのみがカウントされます。 2 番目の要素のシングルトンとサブシーケンス`[0,1]`有効です。 3 番目の要素では、4 つのサブシーケンスすべてが次のようになります。`2`有効です。 最終的な答えは (7) で、(2^3-1) と一致します。 

### サンプル 2

 現在 (x=2)、ソートされた値`0,1,2`。 

| ステップ | 値 (v) | 有効な以前の DP 合計 | (dp) | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 1 | 1 |
 | 2 | 1 | 0 | 1 | 2 |
 | 3 | 2 | 2 | 3 | 5 |

 のために`v=1`、以前の唯一の値は`0`、および (0\oplus1=1<2) であるため、ペアを形成できません。 のために`v=2`の場合、(0\oplus2=2) と (1\oplus2=3) であるため、前の値は両方とも機能します。 したがって、で終わる 3 つの有効なサブシーケンスは、`2`は`[2]`、`[0,2]`、 そして`[1,2]`。 答えは、`5`。 

2 番目のトレースも等価境界を実行します。つまり、(x) に正確に等しい XOR が受け入れられます。

| スペース | (O(n)) | 圧縮トライには、(m\le n) 個の個別の値に対して最大で (2m-1) 個のノードがあります。 

最大の入力には (300000) 個の値が含まれるため、(O(n\log n)) の並べ替えステップと定数 60 ビット係数は両方とも実用的です。 圧縮表現は、非圧縮バイナリ トライのおよそ (60n) ノードの爆発を回避できるため、Python では特に便利です。 元の問題では 1024 MiB のメモリが提供され、圧縮された実装では線形空間が使用されます。

## 特殊なケース

 (x=0) については、次のように考えます。`4 0`価値観を持って`7 7 7 7`。 すべてのペアには、XOR が 0 である等しい値のペアを含め、少なくとも 0 の XOR があります。 DP クエリは以前のすべての値を受け入れるため、DP 値は (1,2,4,8) となり、(15) になります。 圧縮トライには、(x=0) に対する特別なコード パスは必要ありません。これは、各ビットで XOR ビット 1 が対応する 0 ビットよりもすでに大きく、一方、等価ブランチは最終的にリーフに到達し、XOR 0 を受け入れるためです。 

正の (x) を持つすべての等しい値について、次のことを考慮します。`4 1`価値観を持って`5 5 5 5`。 等しい値のすべてのペアには XOR ゼロがあるため、4 つのシングルトン サブシーケンスのみが有効です。 トライには値として 1 つのリーフが含まれます`5`ですが、保存されている重みは発生するたびに更新されます。 それ以降のすべてのクエリはそのリーフに到達し、次の理由により拒否します。`5 xor 5 = 0 < 1`。 したがって、各 DP 値は 1 のままです。 

等価境界については、次のように考慮します。`2 2`価値観を持って`0 2`。 加工後`0`、その DP 値は 1 です。 加工時`2`、トライ クエリは (0\oplus2=2) を認識します。これは正確に (x) であるため、以前の DP 値が含まれます。 したがって、2 番目の DP 値は 2 となり、`[2]`そして`[0,2]`、最終的な答えは 3 つです。 

60 ビット境界については、次を考慮してください。```
3 1152921504606846975
0 1152921504606846975 1152921504606846974
```しきい値は (2^{60}-1) です。 ペア`0`with (2^{60}-1) は、XOR がしきい値とまったく同じであり、有効です。 他の 2 つのペアの XOR はしきい値を下回っているため、有効なサブシーケンスは 3 つのシングルトンとその 1 つのペアです。`4`。 実装ではビット 59 から 0 までがチェックされるため、許容される最上位のビットはオフバイワン エラーなしで処理されます。 

(x=0) の最大サイズの場合は、(300000) 個のゼロを取ります。 300000 個の位置の空でないサブセットはすべて有効であるため、答えは (2^{300000}-1) モジュロ (998244353) になります。 DP は、これらのサブセットを列挙することなくカウントします。 新しいゼロはそれぞれ、以前にカウントされたすべてのサブシーケンスを拡張して、おなじみの 2 倍シーケンス (1,2,4,\ldots) を与えることができますが、すべての値が同一であるため、圧縮トライには 1 つのリーフのみが保存されます。
