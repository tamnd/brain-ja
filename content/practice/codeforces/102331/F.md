 ## 解決策
 ## 問題の理解

 重み付けされた頂点のセットとインデックス付きエッジのリストがあります。 最初はグラフのエッジがないため、すべての頂点は独自の連結コンポーネントになります。 エッジ (i=(a_i,b_i,s_i)) の場合、その端点が現在異なるコンポーネント内にあり、これら 2 つのコンポーネントの頂点の重みの合計が少なくとも (s_i) である場合、エッジを使用できます。 使用可能なすべてのエッジの中で、プロセスは常に最小のインデックスを選択し、2 つのコンポーネントを結合し、繰り返します。 

出力は、このプロセスによって選択されたエッジ インデックスのシーケンスそのものです。 成功した操作はすべて 2 つの異なるコンポーネントを結合するため、選択できるエッジは最大 (n-1) 個です。 元の問題には (n,m\le 300000)、頂点の重みとしきい値は最大 (10^6)、制限時間は 5 秒、メモリは 256 MiB です。 

直接シミュレーションでは、すべての結合後にすべて (m) のエッジを繰り返し検査することはできません。 最悪の場合、(n-1) 個の結合が成功する可能性があるため、すべての結合後にすべてのエッジをスキャンすると、おおよそのパフォーマンスが得られます。 

[
 (n-1)m < 9\cdot 10^{10}
 ]

 エッジチェック。 これは、5 秒の実装で許容できる速度をはるかに超えています。 

不注意な実装を簡単に破ってしまういくつかのエッジケースがあります。 まず、しきい値 0 のエッジはすぐに使用できますが、後のコピーがすでに接続されている頂点を接続する場合は 1 回だけ使用できます。 例えば、```
2 2
0 0
1 2 0
1 2 0
```出力があります```
1
1
```2 番目のエッジも重み条件を満たしますが、その端点はすでに接続されています。 

条件がしきい値以上であるため、完全に等しいことも重要です。 のために```
2 1
2 3
1 2 5
```出力は```
1
1
```厳密な比較を行うと、唯一のエッジが誤って拒否されてしまいます。 

最初は使用できないエッジでも、まったく異なるインデックスの小さいエッジが選択されると使用できるようになることがあります。 例えば、```
3 2
1 1 1
1 2 3
2 3 2
```最初はエッジ 2 のみが使用可能です。 エッジ 2 が頂点 2 と 3 を結合すると、そのコンポーネントの重みは 2 になるため、(1+2=3) によりエッジ 1 が使用可能になります。 正しい出力は次のとおりです```
2
2 1
```エッジ 2 を選択した後、エッジ アレイの 1 パス スキャンが誤って停止していました。 

最後に、すべてのタプルには 2 つの異なるエンドポイントが必要であるため、公称下限 (n\ge1) では (n=1,m\ge1) の有効なインスタンスが得られません。 最小の有効なインスタンスには頂点が 2 つあります。 

## アプローチ

 ブルート フォース シミュレーションは概念的には単純です。 DSU を維持し、インデックス 1 から (m) までのエッジを繰り返しスキャンし、エンドポイントに異なる代表があり、2 つの成分の合計がしきい値に達する最初のエッジを選択します。 ユニオンが成功した後、インデックス 1 から別のスキャンを開始します。これは定義に正確に従っているため、その正しさはすぐにわかります。 問題はスキャンの繰り返しです。(n-1) 個の共用体が存在する可能性があり、各スキ​​ャンのコストが (O(m)) となり、(O(nm))、または最大の制約でほぼ (9\cdot10^{10}) 個のチェックが発生します。 

有益な観察は、コンポーネントの重みが増加するだけであるということです。 2 つの現在のコンポーネントの重みが (x) と (y) であり、しきい値が (s) であるエッジを考えます。 まだ使用できない場合は、残量を次のように定義します。 

[
 r=s-x-y>0。 
]

 エッジを使用できるようにするには、2 つのコンポーネントの重みを合わせて少なくとも (r) だけ増加する必要があります。 2 つのコンポーネントのうち少なくとも 1 つは少なくとも貢献する必要があります

 [
 \左\lceil\frac r2\右\rceil。 
]

 したがって、どちらかのエンドポイント コンポーネントが変更されるたびにこのエッジをチェックするのではなく、両方のコンポーネントにアラームを設定します。 重量の成分 (x) に関するアラームが発生します。 

[
 x+\left\lceil\frac r2\right\rceil,
 ]

 そして他の人は

 [
 y+\left\lceil\frac r2\right\rceil。 
]

 どちらのアラームも発報されなかった場合、エッジが使用可能になるはずはありません。 アラームが 1 つ鳴ると、エッジを 1 回検査します。 (x+y\ge s) の場合、エッジはグローバルに適格になります。 それ以外の場合は、残りの金額を再計算し、その残りの金額を再度半分に分割します。 

最初の側の警報が鳴ったとします。 その側は少なくとも (\lceil r/2\rceil) 増加しているため、新しい残量は次の条件を満たします。 

[
 r' \le r-\left\lceil\frac r2\right\rceil
 = \左\l床\frac r2\右\r床。 
]

 したがって、同じエッジが使用可能にならずに再検討されるたびに、その残りのしきい値は少なくとも半分になります。 (s\le10^6) であるため、エッジは (O(\log s)) 回のアラームの再計算のみを必要とします。 

すべての頂点に個別にアタッチされたすべてのエッジに対してアラームが発生することを避ける必要があります。 同じ接続コンポーネント内のすべての頂点はまったく同じコンポーネント ウェイトを持つため、アラームを一緒に保存できます。 各 DSU コンポーネントは、アラームの最小ヒープを所有します。 2 つのコンポーネントがマージされると、小さいアラーム ヒープが大きいアラーム ヒープにマージされます。 これは小規模から大規模への手法であるため、アラーム エントリは (O(\log n)) 回のみ移動されます。 

最後に、実際に使用可能になったすべてのエッジは、元のインデックスをキーとするグローバル最小ヒープに配置されます。 最小のインデックスが常に最初に処理されます。 選択した別のエッジがすでにそのエンドポイントに参加している可能性があるため、エントリが古くなっている可能性があるため、グローバル候補を使用する前にその DSU 代表を再度確認します。 

これは、ブルート フォースと最適解の間の中心的な接続です。 状態が変化した可能性があるときにすべてのエッジが正確にチェックされるため、ブルート フォースは機能しますが、チェックするエッジが多すぎます。 半減観察により、エッジが関連する可能性がある瞬間のみをスケジュールできると同時に、DSU と小規模から大規模へのコンポーネントの変更が効率的に行われます。 同じ警告のアイデアが、コンテストの社説でこの問題に対して使用される標準的な手法です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(nm)) | (O(n+m)) | 遅すぎる |
 | 最適 | (O(m\log C\log n\log m)) 直接バイナリ ヒープ実装の場合 | (O(n+m\log C)) | 受け入れられたアプローチ |

 ここで (C) は最大しきい値であり、最大 (10^6) です。 融合可能なヒープを使用すると、ヒープ結合係数を減らすことができます。これは、通常、目的のソリューションとして引用される形式です。 直接の`heapq`以下の実装ではデータ構造をシンプルに保ち、小規模から大規模まで同じ戦略に従います。 

## アルゴリズムのチュートリアル

 1. コンポーネントごとに 1 つの頂点を含む DSU を構築します。 各コンポーネントの現在の総重量をその代表者に保存します。 すべてのしきい値は最大 (10^6) であるため、コンポーネントの重みは安全に (10^6) に制限できます。コンポーネントがその値に達すると、それだけですべての可能なしきい値を満たすのに十分です。 
2. すべてのエッジ (i=(u,v,s)) について、(u) と (v) の現在のコンポーネントを見つけます。 最初は、それらは単なる個々の頂点です。 それらの重みの合計がすでに少なくとも (s) に達している場合は、(i) をグローバル候補の最小ヒープに入れます。 それ以外の場合は、

 [
 d=s-w_u-w_v
 ]

 各エンドポイント コンポーネントにアラームを設定します。 

[
 w_u+\left\lceil\frac d2\right\rceil
 \quad\text{および}\quad
 w_v+\left\lceil\frac d2\right\rceil.
 ]

 2 つのアラームにより、エッジが有効になる前に再検討されることが保証されます。 

1. グローバル候補ヒープから最小のエッジ インデックスを繰り返し削除します。 エンドポイントの現在の DSU 代表を見つけます。 それらが等しい場合、以前のエッジがすでにそれらのコンポーネントに接続しているため、候補は古くなり、その候補は破棄されます。 それ以外の場合、エッジは正確に現在適格な最小のエッジであるため、そのインデックスを答えに追加します。 
2. 2 つのエンドポイント コンポーネントをマージします。 アラーム ヒープで小さいものから大きいものまで使用し、大きい方のヒープを宛先として保持し、すべてのアラームを小さい方のヒープからそこに移動します。 コンポーネントの重みを合計し、結果の上限を (10^6) に設定します。 
3. マージ後、新しいコンポーネント ヒープ内の最小のアラームを検査します。 しきい値が新しいコンポーネントの重量よりも大きい場合は、それを下回るアラームも起動できないため、停止します。 しきい値に達した場合は、それを削除し、そのエッジを再考します。 
4. アラームを再検討するときは、エッジのエンドポイントの現在のコンポーネントを見つけます。 それらがすでに等しくなっている場合、アラームは古くなり、単純に破棄できます。 それ以外の場合は、現在の総重量を計算します。 エッジのしきい値に達した場合は、エッジをグローバル候補ヒープに入れます。 そうでない場合は、新しい残量を計算し、2 つの新しい半分しきい値アラームを作成します。 
5. グローバル候補ヒープが空になるまで処理を続けます。 その時点で、しきい値を満たす異なるエンドポイント コンポーネントを持つエッジは存在しないため、元のプロセスも停止する必要があります。 

### なぜ効果があるのか

 エンドポイントがまだ異なるコンポーネント内にあるすべてのエッジについて、各エンドポイントのアラームしきい値が現在のコンポーネントの重みに現在の残りの不足分の半分を加えた値であるという不変条件を維持します。 どちらのアラームも発生していない場合、両方のコンポーネントの増加量は不足分の半分未満であるため、それらを合わせた増加量は不足分全体よりも少なく、エッジはまだその条件を満たすことができません。 アラームが発生した場合、実際の状態をチェックすることで、エッジが現在適格であるかどうかが判断されます。 そうでない場合、残りの不足分はせいぜい以前の半分であるため、アラームを置き換えると不変条件が維持され、対数的に多くの再計算のみが保証されます。 

グローバル候補ヒープには、適格になったすべてのエッジが含まれており、場合によってはその後エンドポイントが結合された古いエッジも含まれます。 コンポーネントの重みは決して減少しないため、適格なエッジは、そのエンドポイントが等しくなるまで適格なままになります。 したがって、古くなった候補を破棄した後、グローバル ヒープの最小要素は、元のプロセスで必要とされる最小の有効なエッジとなります。 すべての結合は 2 つの異なるコンポーネントで実行されるため、生成されるシーケンスはステートメントのシーケンスとまったく同じになります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

MAX_S = 1_000_000

def solve():
    n, m = map(int, input().split())
    weight = list(map(int, input().split()))

    parent = list(range(n))
    size = [1] * n

    # Component weights. They are capped at MAX_S because
    # every threshold is at most MAX_S.
    comp = weight[:]

    U = [0] * m
    V = [0] * m
    S = [0] * m

    # alarms[root] contains (absolute_threshold, edge_id)
    alarms = [[] for _ in range(n)]

    # Edges that are currently eligible, ordered by original index.
    ready = []

    answer = []

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def schedule(e):
        u = find(U[e])
        v = find(V[e])

        if u == v:
            return

        remaining = S[e] - comp[u] - comp[v]

        if remaining <= 0:
            heapq.heappush(ready, e)
            return

        half = (remaining + 1) // 2
        heapq.heappush(alarms[u], (comp[u] + half, e))
        heapq.heappush(alarms[v], (comp[v] + half, e))

    def merge_components(a, b):
        a = find(a)
        b = find(b)

        if a == b:
            return a

        # Keep the larger alarm heap.
        if len(alarms[a]) > len(alarms[b]):
            a, b = b, a

        parent[a] = b
        size[b] += size[a]
        comp[b] = min(MAX_S, comp[a] + comp[b])

        small = alarms[a]
        large = alarms[b]

        # Move the smaller heap into the larger heap.
        while small:
            threshold, e = heapq.heappop(small)

            # The old alarm may already be obsolete because its endpoints
            # became connected.
            x = find(U[e])
            y = find(V[e])

            if x == y:
                continue

            if threshold <= comp[b]:
                schedule(e)
            else:
                heapq.heappush(large, (threshold, e))

        # Process every alarm that has become active because the component
        # weight increased.
        while large and large[0][0] <= comp[b]:
            threshold, e = heapq.heappop(large)

            x = find(U[e])
            y = find(V[e])

            if x == y:
                continue

            schedule(e)

        return b

    # Build the initial alarm structure.
    for e in range(m):
        u, v, s = map(int, input().split())
        u -= 1
        v -= 1

        U[e] = u
        V[e] = v
        S[e] = s

        schedule(e)

    while ready:
        e = heapq.heappop(ready)

        u = find(U[e])
        v = find(V[e])

        if u == v:
            continue

        # The edge is eligible and has the smallest index among all
        # candidates currently known to be eligible.
        answer.append(e + 1)

        merge_components(u, v)

    print(len(answer))
    print(*answer)

if __name__ == "__main__":
    solve()
```DSU 配列には通常の意味があります。`parent`コンポーネントを識別し、`size`結合ヒューリスティックをサポートし、`comp`各代表の現在の総重量を保存します。 パス圧縮により、代表的な検索が繰り返されるため、実質的に一定の償却時間が得られます。`alarms[root]`コンポーネントのローカル優先キューです。 エントリー`(threshold, e)`そのエッジは言う`e`このコンポーネントが到着したらすぐに再検討する必要があります`threshold`。 しきい値は相対的な増分ではなく絶対的なものであるため、2 つのヒープのマージが簡単になります。 

の`schedule`関数は半分にするトリックの核心です。 まず、エッジがすでに有効かどうかを確認します。 そうであれば、エッジは入ります`ready`。 それ以外の場合、残りの不足分は 2 つのエンドポイント コンポーネント間で均等に分割されます。 表現`(remaining + 1) // 2`必要な上限の整数実装です。 

マージ操作では、ソースとして小さいアラーム ヒープを意図的に選択します。 エントリを移動するたびに、それを含むデータ構造のサイズが 2 倍になるため、アラームは対数的にのみ移動できます。 コンポーネントの重みが変更された後、しきい値がまだ大きすぎる最初のアラームが見つかるまで、最小のアラームが繰り返し検査されます。 

での操作の順序は、`merge_components`重要です。 すべてのアラームは新しいコンポーネントの状態に対して評価される必要があるため、アラームが再検討される前に、DSU の親が変更され、新しいコンポーネントの重みが計算されます。 いつ`schedule`後で呼び出され、使用されます`find`したがって、この操作中にエンドポイントが誤ってマージされたエッジは安全に破棄されます。 

すべての算術演算は Python 整数を使用して行われるため、オーバーフローの問題はありません。 C++ では、64 ビット整数も安全な選択ですが、しきい値の上限により、アルゴリズムで使用されるコンポーネントの合計には 32 ビット値で十分になります。 

元のコンテストの制約は、この小規模から大規模のヒープ手法を中心に設計されています。 公開されたソリューションでは、同じ半赤字アラームとグローバル候補優先キューを使用します。

### サンプル 2

 初期の重みは (3,2,2) です。 エッジ 1、2、および 4 は頂点 1 と 2 の間の合計ウェイト 6 を必要とするため、最初はどれも有効ではありません。 エッジ 3 にはしきい値 3 があり、すぐに有効になります。 エッジ 5 は頂点 2 と 3 の間に 6 を必要とし、最初は同様に短いです。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(m\log C\log n\log m)) | 各エッジは (O(\log C)) 回再検討され、小規模から大規模へのマージではアラーム エントリが (O(\log n)) 回移動し、バイナリ ヒープ操作のコストが (O(\log m)) かかります。 |
 | スペース | (O(n+m\log C)) | DSU とエッジ アレイは (O(n+m)) を使用しますが、生成されるアラーム エントリの総数は (O(m\log C)) です。 |

 しきい値の境界 (C\le10^6) により、半分の係数が小さくなり、エッジごとに最大約 20 の意味のある削減が行われます。 ブルートフォースに対する重要な改善点は、コンポーネントをマージするたびにエッジが検査されなくなったことです。 目的のソリューションは通常、エッジごとに (O(\log C)) 個のアラーム更新と組み合わせた小規模から大規模のマージとして要約されます。 

Python ヒープ エントリにはかなりのオブジェクト オーバーヘッドがあるため、元の 256 MiB 制限の場合、C++ 実装がより安全なコンテストの選択となります。 上記の Python 実装は、アルゴリズムの忠実な実装ですが、Python オブジェクト表現ではなく、漸近的な手法が、元のコンテストの制約に基づいて設計されたものです。

 ## 特殊なケース

 ゼロしきい値のケースは次の処理中に処理されます。`schedule`。 のために```
2 2
0 0
1 2 0
1 2 0
```エッジ 1 はすぐにグローバル候補ヒープに挿入されます。 選択され、2 つの頂点が結合されます。 最終的にエッジ 2 がグローバル ヒープから削除されると、`find(1)`そして`find(2)`は等しいため、古いものとして破棄されます。 出力は`1`続いてエッジインデックス`1`。 

完全な等価性は次のように処理されます。`remaining <= 0`テスト。 と```
2 1
2 3
1 2 5
```初期コンポーネントの重みの合計はちょうど 5 になります。エッジは次のように挿入されます。`ready`すぐに選択され、出力が得られます`1`その後`1`。 

動的順序のケース```
3 2
1 1 1
1 2 3
2 3 2
```エッジ 2 のみが適格な状態で開始されます。 選択後、頂点 2 と 3 は重み 2 のコンポーネントを形成します。エッジ 1 はエンドポイント コンポーネントの重み 1 と 2 を持つようになり、そのしきい値 3 に達します。 これはグローバル候補ヒープに挿入され、次に選択されます。 出力は`2 1`。 これは、アルゴリズムがエッジを 1 回だけスキャンするのではなく、将来のアラームを維持する必要がある理由を示しています。 

ありえない正の閾値の場合、```
2 1
0 0
1 2 1
```残りの不足は 1 であるため、両方のアラームは現在のコンポーネントの重みより 1 単位上に配置されます。 コンポーネントが増大することはないため、アラームも起動されず、グローバル候補ヒープは空のままになります。 プロセスは直ちに停止し、選択されたエッジはゼロになり、空白の 2 行目が生成されます。 

最大サイズのチェーン テストではゼロしきい値が使用されるため、最初はすべてのエッジが適格になります。 グローバル ヒープは、残っている最小のインデックスを繰り返し選択します。 最初 (299999) のエッジはチェーンを接続しますが、最後のエッジは同じコンポーネント内の既存の頂点に結合し、破棄されます。 したがって、このアルゴリズムは、結合のたびにすべて (300,000) のエッジを検査する必要がなく、正確に (299,999) の選択されたエッジを生成します。
