 ## 解決策
 ## 問題の理解

 ケーキを表す小さな長方形のグリッドが与えられます。 各セルは通常のケーキ セル (`.`) またはイチゴが含まれている (`S`）。 

ケーキミネーターは、行全体または列全体を繰り返し選択してその中のすべてのセルを食べることがありますが、これはその行または列にイチゴがまったく含まれていない場合に限られます。 すでに食べられた細胞は問題ありません。 少なくとも 1 つの未食べのセルが含まれている限り、行または列を後で選択することができます。 

目標は、食べられる細胞の最大数を見つけることです。 

グリッドの寸法は最大 10 × 10 です。つまり、合計で最大 100 個のセルが存在します。 このように制限が小さいため、比較的非効率なアプローチであっても十分に高速です。 課題はパフォーマンスではなく、選択した行と列の間の交差を二重にカウントせずに、食べられるセルを正確にカウントすることです。 

重要な観察は、食べる操作の順序は重要ではないということです。 列にイチゴが含まれていない場合、最終的にはその列のすべてのセルが食べられる可能性があります。 列にイチゴが含まれていない場合、その列内のすべてのセルが最終的に食べられる可能性があります。 セルが少なくとも 1 つのイチゴのない行または 1 つのイチゴのない列に属している場合、そのセルは食べられます。 

いくつかの特殊なケースでは間違いが発生する可能性があります。 

セルが安全な行と安全な列の両方に属するグリッドを考えてみましょう。```
2 2
..
..
```正しい答えは次のとおりです。```
4
```不注意な解決策では、安全な行のすべてのセルをカウントし、次に安全な列のすべてのセルをカウントし、すべてのセルが 2 回カウントされるため、4 ではなく 8 が得られる可能性があります。 

もう 1 つの重要なケースは、どの行もどの列も安全でない場合です。```
2 2
S.
.S
```正しい答えは次のとおりです。```
0
```すべての行にイチゴが含まれており、すべての列にイチゴが含まれているため、移動はできません。 

3 番目のケースは、行のみが安全な場合です。```
2 3
...
S.S
```正しい答えは次のとおりです。```
3
```1段目は全部食べられます。 各列のどこかにイチゴが含まれているため、どの列も安全ではありません。 答えはまさに安全な列のサイズです。 

## アプローチ

 どの行とどの列が食べられるかを考えるのが総当たり的な視点です。 イチゴのない行は常に取得する価値があり、イチゴのない列は常に取得する価値があります。 それらを特定した後、食べられたすべての細胞をシミュレートし、食べられた個別の細胞の数を数えることができます。 

グリッドには最大 100 個のセルが含まれるため、すべてのセルを繰り返しチェックしてもまったく問題ありません。 主な課題は、安全な行と安全な列の交差点にあるセルの二重カウントを回避することです。 

重要な観察は、次の少なくとも 1 つが当てはまる場合に限り、細胞は食用であるということです。 

1. その列にはイチゴが含まれていません。 
2. その柱にはイチゴが含まれていません。 

いずれかの条件が当てはまる場合、対応する行または列がある時点で選択され、そのセルが食べられることになります。 どちらの条件も当てはまらない場合、その行と列の両方にイチゴが含まれるため、そのセルに到達できる正当な操作は存在しません。 

これにより、問題は単純な採点タスクに変換されます。 まず、どの行が安全でどの列が安全かを判断します。 次に、すべての細胞を調べます。 その行が安全であるか、その列が安全であるかどうかをカウントします。 

### 複雑さの比較

 | アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 訪問したセルを使用したブルート フォース シミュレーション | O(r・c) | O(r・c) | 承認済み |
 | 最適な行/列マーキング | O(r・c) | O(r + c) | 承認済み |

 グリッドが非常に小さいため、どちらのアプローチも制限内に簡単に収まります。 2 番目のアプローチはよりシンプルで、重要な観察を直接表現します。 

## アルゴリズムのチュートリアル

 1. グリッドを読み取ります。 
2. すべての列について、イチゴが含まれているかどうかを確認します。 

行に何も含まれていない場合`S`、安全であるとマークします。 
3. すべての列について、イチゴが含まれているかどうかを確認します。 

列に何も含まれていない場合`S`、安全であるとマークします。 
4. グリッドのすべてのセルを反復処理します。 
5. セルの行が安全であるか、セルの列が安全である場合は、答えに 1 を追加します。 

このような細胞は、少なくとも 1 回の合法的な手術によって最終的に食べられる可能性があります。 
6. 最終的なカウントを出力します。 

### なぜ効果があるのか

 イチゴのない行はいつでも選択できるため、その行のすべてのセルが食べられます。 同様に、イチゴのない列はいつでも選択できるため、その列のすべてのセルが食べられます。 

セルが安全な行にも安全な列にも属さない場合、その行とその列の両方にイチゴが含まれます。 完全にイチゴのない行と列のみを選択できるため、合法的な操作でそのセルを使用することはできません。 

したがって、食用セルとは、まさにその行または列が安全なセルです。 これらの細胞を正確に数えることにより、食べられた細胞の最大数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

r, c = map(int, input().split())
grid = [input().strip() for _ in range(r)]

safe_row = [False] * r
safe_col = [False] * c

for i in range(r):
    if 'S' not in grid[i]:
        safe_row[i] = True

for j in range(c):
    ok = True
    for i in range(r):
        if grid[i][j] == 'S':
            ok = False
            break
    safe_col[j] = ok

answer = 0

for i in range(r):
    for j in range(c):
        if safe_row[i] or safe_col[j]:
            answer += 1

print(answer)
```最初のセクションでは、イチゴのないすべての行を特定します。 Python の文字列メンバーシップ チェックを使用すると、これが非常に簡潔になります。 

2 番目のセクションでは、各列を個別にスキャンします。 列が安全であるとマークされるのは、行に次のものが含まれていない場合のみです。`S`そのコラムで。 

最後のネストされたループではセルをカウントします。 行または列のいずれかが食べられる場合、セルは食べられるため、条件では論理 OR が使用されます。 

よくある間違いは、安全な行のすべてのセルを数えてから、安全な列のすべてのセルを別々に数えることです。 交差点は 2 回カウントされます。 各セルを正確に 1 回チェックすると、この問題は完全に回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(r・c) | 各セルは一定の回数だけ検査されます。 
| スペース | O(r + c) | 行と列の安全性情報を格納します。 

以来`r, c ≤ 10`、可能な最大のグリッドには 100 個のセルしか含まれません。 このアルゴリズムはグリッド上で数回のパスを実行するだけで、時間とメモリの制限を簡単に満たします。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    r, c = map(int, input().split())
    grid = [input().strip() for _ in range(r)]

    safe_row = [False] * r
    safe_col = [False] * c

    for i in range(r):
        if 'S' not in grid[i]:
            safe_row[i] = True

    for j in range(c):
        safe_col[j] = True
        for i in range(r):
            if grid[i][j] == 'S':
                safe_col[j] = False
                break

    ans = 0
    for i in range(r):
        for j in range(c):
            if safe_row[i] or safe_col[j]:
                ans += 1

    return str(ans)

# provided sample
assert run(
"""3 4
S...
....
..S.
"""
) == "8", "sample 1"

# minimum size, all cells edible
assert run(
"""2 2
..
..
"""
) == "4", "all safe"

# no legal move
assert run(
"""2 2
S.
.S
"""
) == "0", "no safe row or column"

# only one safe row
assert run(
"""2 3
...
S.S
"""
) == "3", "safe row only"

# only safe columns contribute
assert run(
"""3 3
S.S
S.S
S.S
"""
) == "3", "middle column safe"
```### テストケースの概要

 | 斜めのイチゴ | 写真 斜めのイチゴ 0 | 安全な行も安全な列もありません |
 | 安全な列が 1 つ | 3 | 列ベースの食事のみ |
 | 3列`S.S`| 3 | コラムベースの食事のみ |

 ## 特殊なケース

 完全に空のケーキを考えてみましょう。```
2 2
..
..
```すべての行とすべての列は安全です。 アルゴリズムはすべての行と列を安全であるとマークし、4 つのセルすべてを 1 回だけカウントします。 出力は次のとおりです。```
4
```これにより、8 が生成される一般的な二重カウントのバグが回避されます。 

すべての行とすべての列にイチゴが入っているケーキを考えてみましょう。```

S.
.S

```行ベースでのみ食べる場合を考えてみましょう。```
2 3
...

```最初の列は安全です。 すべての列にはグリッドのどこかに少なくとも 1 つのイチゴが含まれているため、安全な列はありません。 アルゴリズムは最初の行の 3 つのセルを正確にカウントし、次の値を返します。```
3
```これにより、行と列が独立して処理され、セルが編集可能になるには 2 つの条件のうち 1 つだけが必要であることが確認されます。
