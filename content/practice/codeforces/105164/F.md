 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの文字列が与えられ、それぞれに決定論的な循環変換を繰り返し適用します。 最初の文字列の場合、各状態は左回転に対応し、最初の文字を最後に移動します。 2 番目の文字列の場合、各状態は右回転に対応し、最後の文字を前に移動します。 したがって、各文字列は正確に N 個の異なる構成を生成します。 

最初の文字列が辞書編集的に 2 番目の文字列以下である 2 つの文字列を生成する回転インデックスのペアが何組あるかを数える必要があります。 

重要な点は、どちらのマシンも回転のみを生成するということです。 したがって、反復操作の観点から考える代わりに、ある文字列のすべての循環シフトをもう一方の文字列のすべての循環シフトと比較することとして問題を考えることができます。 

この制約により、長さ 200000 までの文字列が許可されます。すべての N 平方ペアを単純に比較するには、最悪の場合でも約 4e10 回の文字列比較が必要になりますが、これは実行可能な制限をはるかに超えています。 単一の辞書編集比較でも O(N) のコストがかかるため、完全な文字列比較に対する O(N^3) または O(N^2 log N) のアプローチは直ちに除外されます。 

多くの回転が同一である場合、微妙な問題が発生します。 たとえば、文字列が「ababab」のように周期的である場合、多くの状態が一致します。 単純な方法では N 個の異なる文字列を誤って想定する可能性がありますが、重複しても正確さは変わりません。 それらはペアを数える場合にのみ重要です。 

もう 1 つの落とし穴は、回転がソート順に独立して動作すると仮定していることです。 適切にエンコードしない限り、単純なプレフィックス順の構造は形成されません。各ローテーションは 2 倍になった文字列の部分文字列ですが、ラップアラウンド セマンティクスを備えているためです。 

## アプローチ

 ブルートフォースアプローチは簡単です。 s の N 回転すべてと t の N 回転すべてを生成し、すべてのペアを辞書編集的に比較します。 各比較には O(N) がかかり、時間の計算量は O(N^3) になります。 これは、200000 までの N では遅すぎます。 

重要な点は、文字列のすべての回転が 2 倍になった文字列の部分文字列として表現できるということです。 具体的には、s のすべての左回転は、長さ N の s + s の部分文字列に対応します。同様に、t のすべての右回転は、t + t の部分文字列に対応しますが、異なる位置から始まり、循環ラップとして解釈されます。 

すべての回転が部分文字列として表現されると、問題は、一方が辞書編集的に他方より小さいか等しい部分文字列のペア (2 倍になった各文字列から 1 つずつ) を数えることになります。 

部分文字列を効率的に比較するために、文字列の直接比較を避け、代わりに 2 倍になった文字列に対して接尾辞配列または接尾辞ベースの順序付けを使用します。 s + s および t + t のサフィックス配列を構築すると、すべての回転にランクを割り当てることができます。 次に、問題は、S_i のランクが T_j のランク以下になるようなペア (i, j) をカウントすることに帰着します。 

これにより、この問題は、サイズ N の 2 つの並べ替えられた配列にわたる計数問題に変換され、2 ポインター スイープまたはバイナリ インデックス付きツリーを使用して解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^3) | O(N) | 遅すぎる |
 | サフィックス配列 + ランキング | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 2 倍の文字列 S2 = s + s および T2 = t + t を構築します。 これにより、すべての回転が長さ N の連続した部分文字列として表示されるようになります。 
2. S2 と T2 の接尾辞配列 (または同等の辞書編集的ランキング構造) を個別に構築します。 固定長 N の部分文字列の比較のみが必要なため、各回転に開始インデックスに基づいてランクを割り当てることができます。 
3. 0 から N - 1 までのすべての i について、S_i を部分文字列 S2[i : i + N] として定義します。 そのランクを配列 RS に記録します。 
4. 同様に、0 から N - 1 までのすべての j について、T_j を T2[j : j + N] として定義し、そのランクを配列 RT に記録します。 
5.RTを並べ替えます。 RS の各値について、二分探索を使用して、それ以上の RT の値がいくつあるかを数えます。 
6. これらのカウントをすべての i にわたって合計して、最終的な答えを取得します。 

完全な文字列の代わりにランクを比較できる理由は、サフィックス配列の順序付けによって 2 倍化された文字列内のすべての部分文字列の辞書編集的な順序が保持され、すべてのローテーションがそこから抽出された正確な固定長の部分文字列になるためです。 

### なぜ効果があるのか

 各回転は、2 倍の文字列の長さ N の部分文字列に一意に対応します。 2 つのローテーション間の辞書式比較は、対応する部分文字列間の辞書式比較と同等です。 接尾辞配列はすべての接尾辞に合計順序を割り当て、その順序から各位置から始まる固定長部分文字列の一貫したランクを導き出すことができます。 ランクは順序を保持するため、RS[i] と RT[j] を比較することは、辞書編集的に S_i と T_j を比較することと同等です。 したがって、有効なペアをカウントすることは、ランク ペアをカウントすることになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_suffix_array(s):
    n = len(s)
    k = 1
    sa = list(range(n))
    rank = list(map(ord, s))
    tmp = [0] * n

    while True:
        sa.sort(key=lambda x: (rank[x], rank[x + k] if x + k < n else -1))

        tmp[sa[0]] = 0
        for i in range(1, n):
            prev = sa[i - 1]
            cur = sa[i]
            tmp[cur] = tmp[prev] + (
                (rank[cur], rank[cur + k] if cur + k < n else -1)
                != (rank[prev], rank[prev + k] if prev + k < n else -1)
            )

        rank = tmp[:]
        if rank[sa[-1]] == n - 1:
            break
        k <<= 1

    return sa, rank

def solve():
    n = int(input().strip())
    s = input().strip()
    t = input().strip()

    s2 = s + s
    t2 = t + t

    _, rs_full = build_suffix_array(s2)
    _, rt_full = build_suffix_array(t2)

    rs = [0] * n
    rt = [0] * n

    for i in range(n):
        rs[i] = rs_full[i]
        rt[i] = rt_full[i]

    rt.sort()

    ans = 0
    from bisect import bisect_left
    for x in rs:
        ans += n - bisect_left(rt, x)

    print(ans)

if __name__ == "__main__":
    solve()
```接尾辞配列は、倍増文字列のすべての接尾辞に辞書編集上のランクを割り当てるために使用されます。 前半で始まるローテーションのみが有効な個別の状態であるため、最初の N ランクのみを抽出します。 後半は、ラップアラウンド比較を可能にするためにのみ存在します。 

次に、T 回転のランクをソートします。 S の回転ごとに、二分探索を使用して、少なくとも同じ大きさのランクを持つ T 回転が何回あるかを数えます。 これは条件 S_i ≤ T_j を直接実装します。 

よくある実装上の間違いは、回転は 2 倍の文字列の最初の N 位置からのみ取得する必要があることを忘れていることです。 すべてのサフィックスを使用すると、長さが短いサフィックスや重複する終了動作が誤って含まれてしまいます。 

## 実用的な例

 ### 例 1

 n = 3、s = "abc"、t = "bca" の小さな文字列を考えてみましょう。 

回転を計算します。 

| 私 | S_i |
 | --- | --- |
 | 0 | ABC |
 | 1 | BCA |
 | 2 | タクシー |

 | j | T_j |
 | --- | --- |
 | 0 | BCA |
 | 1 | タクシー |
 | 2 | ABC |

 辞書順にランク付けした後:

 abc < bca < cab

 したがって、RS = [0,1,2]、RT = [1,2,0] は [0,1,2] にソートされます。 

現在カウント中:

 abc の場合: 3 件の一致

 BCAの場合: 2試合

 キャブ用：1試合

 合計 = 6。 

これにより、このメソッドがランク順を通じてすべての有効な比較を正しく集計していることが確認されます。 

### 例 2

 s = "aaa"、t = "aab" とします。 

s のすべての回転は同一です: "aaa"。 

t のすべての回転は次のようになります。 

「ああ」、「あば」、「ばあ」

 辞書順:

 aaa < aab < aba < baa

 したがって、各 s 回転はすべての t 回転よりも小さくなります。 

合計 = 3 * 3 = 9。 

同一のローテーションは同一のランクを共有するため、アルゴリズムは重複を正しく処理します。

 ## 特殊なケース

 重要なエッジ ケースは、s = "aaaaa" など、文字列が定数である場合です。 すべての回転は同一の文字列に折りたたまれます。 このアルゴリズムは、すべての S_i および T_j 回転に同一のランクを割り当て、比較はすべてのペアをカウントすることになります。 すべてのペアが同等性を満たすため、結果は N の 2 乗となり、ランクベースのカウントによって正しく生成されます。 

もう 1 つの特殊なケースは、文字列に「abababab」などの短いピリオドが含まれる場合です。 ここでは多くの回転が重複していますが、すべてが同一であるわけではありません。 サフィックス配列は引き続き一貫したランクを割り当て、重複は RS または RT に複数回出現するだけで、最終的なカウントの多重度が維持されます。 

3 番目のエッジ ケースは、s と t が互いに逆のパターンであり、ローテーション間で辞書編集上の順序が逆になる場合です。 ランキングは 2 倍の文字列に対してグローバルであるため、ローテーション順序についてのローカルな直感が失敗した場合でも、比較は一貫性を保ちます。
