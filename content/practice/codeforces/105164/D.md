 ## 解決策
 ## 問題の理解

 マッチ棒を使っていくつの異なる三角形を形成できるかを数えるよう求められます。各辺の長さは棒の整数です。 三角形は 3 つの正の整数によって決まります$a \le b \le c$、周長は$a + b + c$を超えてはなりません$N$。 正の面積を持つ三角形のみが許可されるため、三角形不等式は次のようになります。$a + b > c$保持しなければなりません。 2 つの三角形は、辺の順列だけが異なる場合には同一とみなされます。そのため、減少しないトリプルのみをカウントします。 

入力$N$は利用可能なマッチ棒の総数を表し、合計周囲長が最大でいくつの異なる整数辺三角形を形成できるかを数えます。$N$。 

制約$N \le 10^6$すべてのトリプルをチェックインできないことを意味します$O(N^3)$時間。 平$O(N^2)$慎重に最適化しない限り境界線に達する可能性がありますが、2 次の 2 ポインターまたはプレフィックスをカウントするアプローチは許容されます。 値ごとに線形または線形に近い寄与が期待されます。 

単純な間違いは、すべてのトリプルを次のように数えることです。$a + b + c \le N$三角不等式を強制せずに。 たとえば、$N = 5$、トリプル$(1,1,3)$境界は満たしていますが、無効です。$1+1 \not> 3$。 もう 1 つの間違いは、順列を個別に数えることです。$(3,4,5)$そして$(4,3,5)$別個のものとして。 

より微妙なエッジケースは次のような場合です$N$小さいです。 のために$N = 1$または$N = 2$、三角形は存在しません。 のために$N = 3$、 のみ$(1,1,1)$存在します。 

## アプローチ

 ブルートフォースメソッドはすべてのトリプルを列挙します$1 \le a \le b \le c$そして両方をチェックします$a + b > c$そして$a + b + c \le N$。 これは、三角形の有効性と周囲の制約の両方を直接強制するため、正しいです。 ただし、トリプルまでの数は、$N = 10^6$の順序です$N^3/6$、あまりにも大きすぎるので、$10^{18}$操作。 

重要な観察点は、固定された$a$そして$b$、の有効な値$c$連続した間隔を形成します。 制約は次のようになります。$$c \le a + b - 1, \quad c \le N - a - b$$したがって、実現可能な最大値は$c$は$\min(a + b - 1, N - a - b)$。 一度$a$そして$b$固定されており、カウントは有効です$c$値は定数時間です。 

したがって、問題をペアの反復に帰着させることができます。$(a,b)$そして寄付金を集計します。 直接$O(N^2)$ループはまだ機能しますが、条件を使用してさらにプルーニングできます。$a + b + c \le N$、境界$b$それぞれに$a$、内部ループが制約の下で管理可能な状態を維持するようにします。 

これにより、トリプル列挙が、ペアごとに定数時間の集計を行う二重列挙に変わります。

 ## アルゴリズムのチュートリアル

 1.最小辺を固定します$a$。 これにより、対称性が低下し、各三角形が非減少順で 1 回だけカウントされるようになります。 
2. それぞれについて$a$、2番目の面を選択します$b \ge a$。 一度$a$そして$b$固定されている、3 番目の側$c$三角不等式と周長制約の両方を満たさなければなりません。 
3. 許容される最大値を計算します$c$として$c_{\max} = \min(a + b - 1, N - a - b)$。 最初の項は三角形の有効性を強制し、2 番目の項は周囲制限を強制します。 
4. の整数値がいくつあるか数えます。$c$可能です、つまり$\max(0, c_{\max} - b + 1)$。 引き算します$b$なぜなら$c \ge b$注文のせいで。 
5. このカウントを有効なすべてのカウントに累積します。$b$それぞれに$a$。 
6. 結果のモジュロを出力します。$10^9 + 7$。 

### なぜ効果があるのか

 すべての有効な三角形には固有の表現があります$a \le b \le c$, したがって、反復中にちょうど 1 回出現します。 固定ペアごとに$(a,b)$、アルゴリズムは正確にすべてをカウントします$c$両方の制約を満たす値。 これらの制約は連続した間隔を定義するため、有効な間隔はありません。$c$欠落していて無効ではありません$c$が含まれています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    ans = 0

    for a in range(1, n + 1):
        for b in range(a, n + 1):
            if a + b >= n:
                break

            c_max = min(a + b - 1, n - a - b)
            if c_max < b:
                continue

            ans += (c_max - b + 1)

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```実装は派生構造に直接に従います。 外側のループは最小の辺を固定します$a$、内側のループがオーバーオーバーします$b$。 早めの休憩`if a + b >= n`有効なケースがない場合はプルーニングします$c$可能な限り小さい 3 番目の辺でも周囲の制約を超えるため、存在する可能性があります。 

表現`c_max = min(a + b - 1, n - a - b)`両方の制約を同時にエンコードします。 小切手`c_max < b`3 番目の側が少なくとも 2 番目の側と同じ大きさのままである構成のみをカウントするようにします。 最後の追加`c_max - b + 1`整数範囲を含めてカウントします。 

すべての算術演算は Python 整数内に安全に収まりますが、結果は剰余化されます。$10^9 + 7$必要に応じて。

 ## 特殊なケース

 のために$N = 1$、ループオーバー$a$1 から始まりますが、有効な値がないためすぐに中断されます。$b$満足できる$a + b < N$。 結果は0のままです。 

のために$N = 3$、唯一の有効なペアは$a = 1, b = 1$、与える$c_{\max} = 1$したがって、正確に 1 つの三角形がカウントされます。$(1,1,1)$。 両方の制約が満たされるため、アルゴリズムにはそれが正しく含まれます。 

次のような境界ケースの場合$a + b = N - 1$、周囲拘束力$c \le 1$、および三角不等式では、値が許可される場合と許可されない場合があります。 小切手`c_max < b`無効な貢献を正確に排除し、実現可能性ぎりぎりでの過大なカウントを防ぎます。
