 ## 解決策
 ## 問題の理解

 私たちには、騎士のセットが与えられ、それぞれの正方形に配置されます。$N \times N$チェス盤。 各ナイトには標準的なチェスの動きがあり、L 字型のパターンで最大 8 つの潜在的な正方形を攻撃できます。 2 人の騎士は、一方がもう一方に 1 回の動作で到達できれば対立します。 

タスクは、残っている騎士のペアが互いに攻撃できないように、できるだけ少ない数の騎士を取り除くことです。 言い換えれば、除去後、残りの構成には攻撃ペアがゼロでなければなりません。 

入力はボード全体の状態を記述するのではなく、占有されているセルの座標のみを記述します。 これは、私たちが関心を持っている実際のグラフは完全なグリッドではなく、グリッドのサブセットのみであることを意味します。$K$占領された位置。エッジはそれらの位置間の騎士の攻撃を表します。 

出力は単一の整数です。これは、誘導されたグラフにエッジがなくなるように削除するナイトの最小数です。 

制約は小さいです。$N \le 25$そして$K \le 625$。 これにより、重度のオーバーヘッドを伴って不注意に実装された場合、すべてのペアにわたって二次関数またはそれより悪いものは即座に除外されますが、それでも許容されます。$O(K^2)$スタイルグラフ構築を快適に。 重要な課題は、エッジを構築することではなく、問題の構造を認識することです。 

いくつかの微妙なケースが重要です。 

2 人の騎士が互いに攻撃しない場合、答えはゼロです。 ノードの一致または削除を試行する単純な実装では、グラフにエッジがないことが適切に検出されない場合、誤って削除を過剰にカウントしてしまう可能性があります。 

すべてのナイトが密集した領域に配置されている場合、多くの攻撃が存在する可能性がありますが、構造は依然としてナイトの動きによって制約されるため、各ノードには最大 8 つのエッジがあります。 ナイト移動ルールによるフィルタリングを行わずに不注意にすべてのペアをチェックすると、非攻撃ペアが競合として誤って扱われてしまいます。 

もう 1 つのエッジケースは、ナイトが攻撃のサイクルを形成する場合です。 たとえば、3 人以上のナイトが相互攻撃チェーンを作成する場合があります。 「最大次数のナイトを除去する」などの貪欲な除去戦略は、ローカルな選択がグローバルな最適セットを反映していないため、ここでは大失敗する可能性があります。 

## アプローチ

 ブルートフォースの観点では、ナイトのすべてのサブセットを試し、サブセットに競合がないかどうかを確認します。 各サブセットについて、サブセット内のすべてのペアをスキャンすることで、2 人の騎士が互いに攻撃していないことを確認します。 がある$2^K$サブセットと各サブセットのコストを確認する$K^2$、につながる$O(K^2 2^K)$、中程度の人でも不可能になります$K$。 

失敗点は、制約がグローバルであることです。1 つのナイトを削除すると複数の競合を同時に解決でき、ブルート フォースではサブセット間で構造を再利用できません。 

重要な観察は、騎士とその攻撃がグラフを形成しており、タスクはそれらの間にエッジのない頂点の最大のサブセットを選択することになるということです。 これは最大独立集合問題です。 

一般的なグラフではこれは困難ですが、チェス盤上のナイト グラフは 2 部構成です。 各正方形をパリティで色付けすると、$r + c$、すべての騎士の動きは常にある色から別の色に移ります。 これにより、競合グラフが 2 部グラフに変わります。 

二部グラフでは、古典的な恒等式が適用されます。つまり、最大の独立セットのサイズは、頂点の数から最大一致のサイズを引いたものに等しくなります。 したがって、除去の観点から考えるのではなく、最適に一致させることができる素の攻撃ペアの数を計算し、減算します。 

これにより、この問題は、まばらなエッジを持つ最大 625 個のノードにわたる最大 2 部マッチング問題に変換され、DFS ベースの拡張パスまたは Hopcroft-Karp を使用して効率的に解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(K^2 2^K)$|$O(K)$| 遅すぎる |
 | 二部マッチング |$O(K \cdot E)$(DFS) |$O(E)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ナイトを次のようにインデックス付けされたグラフ内のノードとして表現します。$0$に$K-1$。 各ノードはそのボード座標を保存します。 この抽象化により、チェス盤の問題をグラフの問題に変換できます。 
2. 次を使用して、各ノードにその座標のパリティに基づいて色を割り当てます。$(r + c) \bmod 2$。 これにより、ナイトの動きごとに反対の色が接続されることが保証され、これがグラフを 2 部構成にする構造的特性です。 
3. ナイトのペアごとに、ナイトの移動ルールを使用して互いに攻撃するかどうかを確認します。 存在する場合は、それらの間に無向エッジを追加しますが、黒側から白側へのみ保存します。 これにより、二部マッチング用のグラフが準備されます。 
4. 最大 2 部マッチング アルゴリズムを実行します。 黒側の各ノードについて、DFS を使用して、一致しない白いノードと一致させるか、既存の一致を再ルーティングする拡張パスの検索を試みます。 
5. マッチングの結果は、互いに素な攻撃ペアの数です。 一致した各エッジは、少なくとも 1 人のナイトを削除する必要がある 1 つの「競合解決ユニット」に正確に対応します。 
6. 最終的な答えを次のように計算します。$K - \text{matching size}$。 これは、攻撃しないナイトの可能な限り最大のサブセットを維持することに対応します。 

### なぜ効果があるのか

 重要な不変条件は、マッチング プロセスのどの時点でも、各白いノードが最大 1 つの黒いノードとマッチングされ、各拡張ステップでは一致するペアの数を厳密に増やすか、既存の一致を再ルーティングしながら実現可能性を維持することです。 グラフは 2 部構成であるため、すべての攻撃関係は反対側のパーティション間のエッジとして表現されるため、マッチングによって有効なナイト競合の構造が侵害されることはありません。 最大マッチングの補数は最小頂点カバーに正確に対応し、その補数は最大独立セット (私たちが保持するナイトのセット) に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_attack(a, b):
    r1, c1 = a
    r2, c2 = b
    dr = abs(r1 - r2)
    dc = abs(c1 - c2)
    return (dr == 2 and dc == 1) or (dr == 1 and dc == 2)

def solve():
    N, K = map(int, input().split())
    knights = [tuple(map(int, input().split())) for _ in range(K)]

    # build bipartite graph: edges from black -> white
    adj = [[] for _ in range(K)]

    color = [(r + c) & 1 for r, c in knights]

    for i in range(K):
        for j in range(K):
            if i != j and color[i] == 0 and color[j] == 1:
                if can_attack(knights[i], knights[j]):
                    adj[i].append(j)

    match_to = [-1] * K

    sys.setrecursionlimit(10000)

    def dfs(v, seen):
        for to in adj[v]:
            if seen[to]:
                continue
            seen[to] = True
            if match_to[to] == -1 or dfs(match_to[to], seen):
                match_to[to] = v
                return True
        return False

    match = 0
    for i in range(K):
        if color[i] == 0:
            seen = [False] * K
            if dfs(i, seen):
                match += 1

    print(K - match)

if __name__ == "__main__":
    solve()
```コードは、すべてのナイトの位置を読み取り、座標パリティを使用して 2 部カラーを割り当てることから始まります。 これは、マッチングへの還元を可能にする構造的なステップです。 

隣接リストは、黒いノードから白いノードへのみ構築されます。 これにより、エッジの重複が回避され、DFS マッチングが適切な 2 部表現で実行されるようになります。 

DFS 関数は、白いノードを黒いノードに割り当てようとします。その白いノードがすでに一致している場合は、前のパートナーの再割り当てを再帰的に試みます。 パスを増やすと複数の再割り当てが連鎖する可能性があるため、再帰制限が増加します。 

最後に、成功した一致をカウントし、から減算します。$K$、一致した各ペアは、少なくとも 1 つの削除を強制する競合に対応するためです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、エッジがまったく存在しない場合です。 この状況では、マッチング手順では拡張パスが見つからないため、マッチング サイズはゼロのままとなり、答えは次のようになります。$K$。 このアルゴリズムは、隣接リストのチェック以外に不必要な DFS 拡張を試みません。 

もう 1 つのケースは、多数の騎士が互いに攻撃する完全に密集したローカル領域です。 それでも、各ノードは最大 8 つのエッジにしか参加しないため、DFS が組み合わせ的に爆発することはありません。 2 部構成のカラーリングにより、無効な同じ側のエッジが考慮されなくなり、同一のパーティション間での誤ったマッチング試行が防止されます。 

最後の微妙なケースは、複数の拡張パスが相互作用する場合です。 DFS ベースのマッチングは、以前にマッチングされたノードを再度訪問することに依存しており、正確さはマッチングを再ルーティングできるかどうかに依存します。 割り当てが失敗するたびに、空きノードが見つかるかすべての可能性がなくなるまで、代替割り当ての探索がトリガーされるため、再帰的構造によってこれが自動的に処理されます。
