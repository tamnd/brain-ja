 ## 解決策
 ## 問題の理解

 私たちは石の塔のコレクションを与えられており、それぞれがある程度の正の高さを持っています。 2 人のプレイヤーが同じ種類の動きを交互に実行します。 ターンでは、プレイヤーはゼロより大きい整数 X を選択し、まだ石があるすべてのタワーから X を引きますが、X は現在最も短い空ではないタワーの高さを超えることはできません。 ゼロに達したタワーは、実質的にそれ以降のプレイから削除されます。 

したがって、移動は、残っているすべてのタワーの底から何層剥がすかという選択によって完全に決まります。 移動するたびに、少なくとも 1 つが消えるまで、すべてのアクティブなタワーが均等に減少します。 

有効な手を打つことができないプレイヤーは負けます。これは、自分のターンの前にすべてのタワーが既にゼロになっている場合、または正の X が不可能な場合に発生します。 

この制約により、最大 100 万個のタワー (それぞれの高さは最大 100 万個) が許可されます。 これにより、レイヤーごとに繰り返し減算を行うシミュレーションは即座に排除されます。これは、最悪の場合、最大 10^12 のプリミティブ演算が必要になるためです。 

すべてのタワーが等しい場合、重要なエッジ状況が現れます。 たとえば、すべての高さが同じ場合、各移動は 1 ステップで残りのタワーをすべて完全に削除します。 もう 1 つの微妙なケースは、タワーが 1 つだけ残っている場合です。その場合、ゲームは単一の山から正の整数を繰り返し減算することになるため、複数のタワーの相互作用とは動作が異なりますが、実際には同じ構造と一致します。 

単純な間違いは、答えが高さの合計または最大値に依存すると仮定することです。 たとえば、タワー [1、100、100] の場合、大きなタワーが優勢であるように感じるかもしれませんが、最小のタワーでは最初の動きが X = 1 に強制され、その後、異なる「レベル」がいくつ存在するかによってのみ依存する予測可能な方法で構造が崩壊します。 

## アプローチ

 直接シミュレーションでは、各移動はすべてのタワーから現在の最小高さを減算し、枯渇したタワーを削除するものとして扱われます。 これは正しいです。なぜなら、最適な動きは常に最大許容値の X を選択する必要があるからです。そうしないと、同じタワー構造でより大きな残りの最小値で、厳密に有利な位置を対戦相手に残すことになります。 ただし、常に最小値を減算したとしても、プロセスには最大 O(max(ai)) 回の反復がかかる可能性があり、高さが大きい場合には遅すぎます。 

重要な観察は、各移動が少なくとも 1 つのタワーを完全に削除することです。これは、選択された X が現在の最小高さに等しいため、少なくとも 1 つのタワーがゼロになるためです。 ソート後、これは、個別の高さレベルを減少させて配列を剥がすことと同じです。 それぞれの個別の高さの値は 1 つの「レイヤー除去イベント」に寄与し、ゲームはすべての個別の高さを処理した後に終了します。 

したがって、ゲームの長さは、その大きさや数ではなく、異なる高さがどれだけ存在するかによってのみ決まります。 それぞれの個別の値は、最小値に等しいすべてのタワーを削除した後に最小値が増加する強制移動に対応します。 

勝者は純粋にそのような削減数の同等性によって決定されます。 個別の高さレベルの数が奇数の場合、最初のプレーヤーが最後の動きをして勝ちます。 互角の場合は、2 番目のプレイヤーが勝ちます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 層除去のシミュレーション | O(N * 最大(ai)) | O(N) | 遅すぎる |
 | 異なる高さを数える | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. タワーの高さのリストを昇順に並べ替えて、同じ高さが隣接するようにします。 これにより、レイヤーを削除した後に最小値がいつ変化したかを検出できます。 
2. ソートされたリストを調べて、値が前の値から何回変化したかを数えます。 それぞれの変化は、出現する新しい個別の高さレベルに対応します。 
3. 個別の値の数をゲームの手数として扱います。 これは有効です。なぜなら、それぞれの個別の高さが最小値になると、1 回の強制操作で削除されるからです。 
4. 異なる高さの数が奇数の場合は、アリシウスが勝者であると宣言します。 そうでなければ、ボビウスが勝ちます。 

主な理由は、各移動の後、少なくとも 1 つの高さレベル全体が消失し、高さレベルが再表示されたり、将来の構造を変更するような形で部分的に分割されたりすることはできないということです。 したがって、ゲームの状態は、ソートされた個別の値を通じて単調に崩壊します。 

### なぜ効果があるのか

 不変条件は、k 個の移動後、正確に k 個の異なる高さレベルが完全に削除され、残りの塔がソートされた一意の高さリストの接尾辞に正確に対応するということです。 X は強制的に現在の最小値に等しくなるため、レベルをスキップしたりレベルを結合したりする決定点はありません。 これにより、一連の動きは等しい要素の順序に至るまで決定的になるため、ゲーム全体は時間の経過とともに存在する個別の最小値の数を数えることになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n_and_rest = input().split()
    if not n_and_rest:
        return
    n = int(n_and_rest[0])
    arr = list(map(int, n_and_rest[1:]))

    # if input didn't fully come in first line
    while len(arr) < n:
        arr.extend(map(int, input().split()))

    arr.sort()

    moves = 0
    prev = None

    for x in arr:
        if x != prev:
            moves += 1
            prev = x

    if moves % 2 == 1:
        print("Alicius")
    else:
        print("Bobius")

if __name__ == "__main__":
    solve()
```この実装では、値が複数行にまたがる可能性があるため、まず堅牢な入力解析が保証されます。 ソートにより同じ高さがまとめられるため、1 回のスキャンで遷移を検出できます。 変数`moves`個別の身長グループをカウントします。これは強制削除の数に直接対応します。 

微妙な点は、最初の行に両方が含まれる可能性がある入力を処理することです。`N`これが、パーサーが N に達するまで値を蓄積する理由です。

 | --- | --- | --- | --- |

 | 4 | 3 | はい | 2 |

| 値 | 前へ | 明確な？ | 移動 |

 手数 = 5、奇数なので、アリシアスが勝ちます。 

これは、すべての値が個別であり、すべてのステップが強制的な削減イベントになる極端なケースを示しています。

 ## 特殊なケース

 単一の塔の場合`[7]`、並べ替えでは 1 つの要素が得られるため、異なる値は 1 つだけ存在します。 アルゴリズムは 1 手をカウントしますが、これは奇数であるため、Alicius が勝ちます。 これは、最初のプレーヤーが X = 7 を選択し、すぐにゲームを終了できるという事実と一致します。 

次のようなすべての等しい塔に対して、`[5, 5, 5]`、ソートしても 1 つの異なる値が生成されます。 移動は 1 つだけ行われます。5 を 1 回減算すると、すべてのタワーが消えます。 アルゴリズムは、最初の手が最後の手でもあるため、最適なプレイに一致するアリシウスを出力します。 

次のような交互の重複の場合`[1, 1, 2, 2, 3, 3]`、個別のカウントは 3 です。 最初のプレイヤーは構造を通じて間接的に最初の 2 つの削減を実行します。3 は奇数であるため、アリシアスが勝ちます。 これは、多重度が再生の長さに影響を与えるのではなく、異なる高さレベルのみが影響することを示しています。
