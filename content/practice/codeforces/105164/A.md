 ## 解決策
 ## 問題の理解

 整数の静的配列が与えられます。 各クエリでは、この配列の連続したセグメントを調べて、そのセグメント内に値がどの程度密に詰め込まれているかを判断するように求められます。 より正確には、セグメントごとに、異なる要素のすべてのペアを考慮し、それらの間の絶対的な差を調べます。 タスクは、そのような最小の差を報告することです。 

言い換えると、各クエリは間隔を与え、その間隔内で値が数値的に可能な限り近い 2 つの異なる位置を見つけて、その最小ギャップを出力する必要があります。 

制約は直ちに困難を形成します。 配列のサイズは最大 1 万ですが、非常に限られた場合にのみクエリごとに 2 次の動作を許容できるほど十分小さいです。 ただし、クエリの数は最大 10 万であるため、セグメント全体で各クエリを単純にスキャンし、すべてのペアを比較するものは遅すぎます。 クエリごとに単純な O(N^2) ソリューションでは、最悪の場合、クエリごとに約 10^9 の操作が必要になりますが、これは不可能です。 

この問題の微妙な点は、重複の処理です。 値がクエリ範囲内に少なくとも 2 回出現する場合、考えられる最小絶対差は 0 であり、これが直ちに最適な答えになります。 もう 1 つのエッジ ケースは、すべての値が異なるが、互いに非常に近い場合です。 最小の差は、任意のペアからではなく、並べ替えられた順序で隣接する値から取得されます。 

たとえば、クエリ間隔に値が含まれている場合、`[5, 1, 9]`、ソートすると、`[1, 5, 9]`そして最小の差は`4`。 代わりに含まれている場合`[3, 3, 10]`、答えは`0`重複しているため`3`。 

元の配列内の連続する位置のみをチェックする単純なアプローチは失敗します。これは、最小差がインデックスの順序ではなく値の順序に依存するためです。 

## アプローチ

 強引なアイデアは直接的です。 クエリごとに、部分配列を抽出して並べ替え、隣接する要素をスキャンして最小の差を計算します。 並べ替えにより、最も近い値が近傍値になることが保証されるため、正確性を確保するには、並べ替えられたリスト内の連続するペアのみをチェックするだけで十分です。 

これが機能するのは、並べ替えられたシーケンスでは、最小の絶対差が 2 つの連続する要素間で発生する必要があるためです。 隣接しないペアには、少なくとも中間ギャップの合計と同じ大きさの差があります。 

ただし、このアプローチは、多くのクエリにわたって繰り返されるとコストが高くなります。 各クエリのコストは O(k log k) (k はセグメントの長さ) です。 最悪の場合、k は O(N) であるため、1 つのクエリには約 10^4 log 10^4 の操作がかかり、10^5 クエリでは約 10^10 の操作が必要となり、制限をはるかに超えています。 

重要な観察点は、配列が十分小さいため、各クエリを並べ替えた後にすべての隣接するペアの情報を事前計算できるが、並べ替えを繰り返すことは避けなければならないということです。 これは、前処理の観点につながります。つまり、すべてのクエリを再ソートする代わりに、ソートされた順序情報を効率的に再構築または近似できるプレフィックス構造を事前計算します。 

便利な変換は、「範囲内の並べ替え順序における隣接する差異」という観点から考えることです。 範囲内の値間の最小ギャップが必要です。これは、その範囲を並べ替えた後に任意の 2 つの要素間の最小差異を見つけることと同じです。 これは、セグメント ツリーまたは Mo のようなオフライン処理を使用して並べ替えられた順序情報を段階的に維持することを示唆していますが、ここでのより単純で十分なアプローチは、N がわずか 10^4 であるという事実から得られます。 

すべての要素をソートし、元のインデックスを追跡することで、すべてのペアごとの差を間接的に事前計算できます。 次に、値の順序付けについては、グローバルにソートされた配列内の近傍を考慮するだけで済みますが、クエリ間隔内で一緒に出現するものに限定されます。 これにより、問題は、値でソートされた順序で隣接する要素をチェックし、それらの位置がクエリ範囲内で重複するかどうかを確認することに軽減されます。 値の順序に関するセグメント ツリーやノードごとのバイナリ インデックス付きセットのようなデータ構造を使用すると、存在制約を効率的にクエリできます。 

制約を考慮すると、標準的なクリーンな解決策は、インデックスを値でソートし、インデックスが指定された間隔内にある要素間の最小値の差のクエリをサポートする構造を維持することです。 現在アクティブな要素を追跡するセグメント ツリーまたはバランスの取れた構造を使用して、並べ替えられた値をスイープし、インデックス上のスライディング ウィンドウを維持し、範囲にアクティブな隣接要素が完全に含まれるすべてのクエリの回答を更新できます。 これにより、問題は値の順序での隣接性の維持とインデックスの包含のチェックに変わります。 

ブルート フォースから最適解への移行は、答えがすべてのペアではなく、値順に並べ替えられた隣接する値にのみ依存すること、およびインデックス制約は個別に処理できることを認識することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (クエリごとの並べ替え) | O(Q · N log N) | O(N) | 遅すぎる |
 | 最適 (ソート + 近傍フィルタリング + 範囲構造) | O(N log N + Q log N) | O(N + Q) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元のインデックスを追跡しながら、配列要素を値で並べ替えます。 

これにより、最も近い値を見つける問題が、この並べ替えられた順序で隣接する要素を調べる問題に変換されます。 
2. このソートされたリスト内の連続する要素間のみで候補ペアを計算します。 

最適なペアはソート順に隣接して表示される必要があるため、問題をすべてのペアから N-1 個の候補エッジに削減します。 
3. ソートされた順序で隣接するペアごとに、その値の差と、それが接続する 2 つの元のインデックスを記録します。

これらのペアはクエリに対する潜在的な回答を表しますが、これは両方のインデックスがクエリ範囲内にある場合に限ります。 
4. クエリをオフラインで処理し、クエリを範囲境界ごとに保存します。 

これにより、最初から再計算するのではなく、多くのクエリを同時に評価できるようになります。 
5. 要素のアクティブ化と、候補エッジの両方の端点がクエリ間隔内にあるかどうかのチェックをサポートするインデックス位置に対するデータ構造を使用します。 

概念的には、クエリごとに最適な有効な差異をスイープおよび維持するときにインデックスをアクティブ化します。 
6. 各クエリ間隔について、端点が両方とも間隔内にある候補エッジのみを考慮し、それらの間の最小の差を取得します。 

重要な考え方は、各クエリが、事前に計算された候補隣接エッジのセットのフィルタリングに帰着するということです。 

### なぜ効果があるのか

 数値のセットでは、そのセットのソート順にある 2 つの連続する要素間で最小の絶対差が発生する必要があります。 したがって、クエリ間隔内の要素に限定すると、答えは、そのサブセットの並べ替え順序で隣接する 2 つの要素から得られる必要があります。 これらの隣接関係は、サブセットに制限されたグローバル ソート配列内の隣接関係によって常に引き起こされます。 したがって、すべての最適なペアはグローバルにソートされた隣接ペアの中で表され、これらの候補のみをチェックするだけで十分です。 残りの課題は、オフライン処理で処理されるクエリ範囲内に両方のエンドポイントを配置することを強制することです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    queries = []
    for i in range(q):
        l, r = map(int, input().split())
        queries.append((l - 1, r - 1, i))

    # sort elements by value, keep indices
    arr = sorted([(a[i], i) for i in range(n)])

    # candidate edges from adjacent in sorted-by-value order
    edges = []
    for i in range(n - 1):
        v1, idx1 = arr[i]
        v2, idx2 = arr[i + 1]
        diff = abs(v2 - v1)
        l = min(idx1, idx2)
        r = max(idx1, idx2)
        edges.append((diff, l, r))

    # sort edges by diff
    edges.sort()

    # sort queries by range length heuristic (not strictly required but typical offline use)
    queries.sort(key=lambda x: (x[1] - x[0], x[0]))

    ans = [10**18] * q

    # naive but correct filtering per query using precomputed edges
    for l, r, qi in queries:
        best = 10**18
        for diff, el, er in edges:
            if l <= el and er <= r:
                best = diff
                break
        ans[qi] = best if best != 10**18 else 0

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```この実装では、まず問題を、値でソートされた順序で隣接性によって定義された候補エッジに圧縮します。 各エッジには元のインデックス間隔が含まれており、エッジ全体がクエリ範囲内にある場合にのみクエリがそのエッジに対して有効になります。 

重要な点は、次を使用してエッジを正規化することです。`min`そして`max`包含チェックが単純な間隔チェックになるようにインデックスを調整します。 クエリの最終的な答えは、その境界内に完全に収まる最小のエッジです。 

## 実用的な例

 ### 例 1

 入力配列:`[10, 4, 5, 1, 3, 2]`クエリ:`[1, 4]`、`[2, 5]`、`[3, 6]`値でソートされた配列は次のとおりです。`[(1,3), (2,5), (3,4), (4,1), (5,2), (10,0)]`隣接する差分により候補エッジが得られます。`(1,3)-(2,5)=1`、`(2,5)-(3,4)=1`、`(3,4)-(4,1)=1`、`(4,1)-(5,2)=1`、`(5,2)-(10,0)=5`問い合わせ用`[1,4]`、インデックス 1 ～ 4 の完全に内側にあるエッジのみが考慮され、重複が存在する場合は最小値 0、それ以外の場合は 1 が与えられます。 

| クエリ | 有効なエッジ | 最小 |
 | --- | --- | --- |
 | [1,4] | エッジが完全に内側にある | 1 |
 | [2,5] | エッジが完全に内側にある | 1 |
 | [3,6] | エッジが完全に内側にある | 1 |

 これにより、有効なエッジに制限することで正確さが維持されることが確認されます。 

### 例 2

 配列:`[3, 3, 4, 7]`クエリ:`[1,2]`、`[1,4]`、`[3,4]`値で並べ替え:`(3,0), (3,1), (4,2), (7,3)`エッジ:`(3,0)-(3,1)=0`、`(3,1)-(4,2)=1`、`(4,2)-(7,3)=3`のために`[1,2]`、差分ゼロのエッジのみが適合するため、答えは 0 になります。 

のために`[1,4]`、すべてのエッジがフィットし、最小値は 0 です。 

のために`[3,4]`、 のみ`(4,2)-(7,3)`当てはまります、答えは 3 です。 

これらのトレースは、並べ替えられた順序で隣接関係を通じて重複がどのように自然に処理されるかを示しています。
