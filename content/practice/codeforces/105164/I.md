 ## 解決策
 ## 問題の理解

 私たちはターゲット配列を与えられ、それが一連の配列を繰り返しマージすることによって生成されたと想像します。$M$非常に特殊な 2 ポインター マージ手順を使用した空でないシーケンス。 

マージ手順では、常に 2 つのシーケンスの現在の先頭要素を比較し、小さい方 (または等しい場合は左側) を削除します。 最終結果を構築した後は、この結果のシーケンスのみを観察しますが、元の結果は$M$シーケンスは隠されています。 

タスクは、初期値を選択できるさまざまな方法が何通りあるかを数えることです。$M$教授が繰り返しマージプロセスを適用した後の最終的なシーケンスは、私たちが与えられたものとまったく同じになります。 

重要な点は、シーケンスが内部でソートされることが想定されていないことです。 マージ操作は依然としてフロント要素を比較することによって厳密に進行するため、出力はグローバルな並べ替えプロパティではなく、これらの比較によって動的に決定されます。 

この制約により、最終シーケンスでは最大 3000 個の要素、および最大 3000 個の初期シーケンスが許可されます。 これにより、要素のすべてのパーティションをシーケンスに列挙しようとするアプローチや、各候補構造のマージをシミュレートしようとするアプローチは即座に除外されます。これは、パーティションの数が指数関数的に増加するためです。 正しい解決策は、通常、最終シーケンスのプレフィックスに対して動的プログラミング状態を構築することによって、ほぼ二次時間以上で動作する必要があります。 

重要なエッジ ケースの 1 つは、すべての要素が同一である場合です。 その場合、すべてのマージ比較は「左から取得」ルールによって解決されます。これにより、単純な対称ベースのカウント手法では見逃してしまうような、シーケンス間の強い順序付け制約が導入されます。 

もう 1 つの微妙なケースは、値が繰り返されるがインターリーブされる場合です。 たとえば、次のようなシーケンス$[1, 2, 1]$独立した並べ替えマージのように動作することはできません。$1$の後ろに隠れてしまいます$2$慎重に別の順序に配置しない限り、マージ中に使用できなくなります。 これは、シーケンスは独立して処理できるという素朴な仮定を打ち破ります。 

## アプローチ

 ブルートフォースアプローチでは、それぞれに$N$要素をいずれかの$M$シーケンスを実行し、完全なマージ プロセスをシミュレートして、結果がターゲットと一致するかどうかを確認します。 これはすでに与えられています$M^N$可能性と各シミュレーションのコスト$O(NM)$または$O(N \log M)$、これは実現可能性をはるかに超えています。 

重要な観察は、すべてのシーケンスを明示的に再構築する必要がないということです。 マージ プロセスは、シーケンス全体での「現在利用可能なフロント要素」の相対的な順序のみに依存します。 すべての要素は、シーケンスに割り当てられると、現在のすべてのシーケンス ヘッドの中で最小になった時点で最終出力に表示されます。 

これは、構築を逆にできることを意味します。シーケンスを構築してマージをシミュレートする代わりに、最終シーケンスを左から右に処理し、各要素をいずれかの要素に割り当てる方法が何通りあるかを尋ねます。$M$フロント要素の有効な進化を維持しながらシーケンスを実行します。 

重要な構造的洞察は、プロセスのどの時点においても、各シーケンスがマージに寄与する「アクティブな候補」は 1 つだけ、つまり次の未使用の要素であるということです。 したがって、システム全体を次の要素の集合としてモデル化できます。$M$最終シーケンスに対するポインタの進化。 動的プログラミング状態では、指定されたプレフィックスまでにすでに提供されているシーケンスの数と、最初の要素の提供をまだ待機しているシーケンスの数を追跡するだけで済みます。 

これにより、問題は最終シーケンス上の接頭辞 DP に縮小され、遷移はどのシーケンスが次の要素を生成するかを決定することに対応します。

 ## アルゴリズムのチュートリアル

 最終シーケンスを左から右に処理します。 どのプレフィックスでも、すでに「アクティブ化」されているシーケンスの数を維持します。つまり、シーケンスが出力に少なくとも 1 つの要素を提供していることを意味します。 

また、未使用のシーケンスの数も追跡します。 中心となる考え方は、最終シーケンスの各要素は、利用可能な最小のフロント要素になった時点で、正確に 1 つのシーケンスによって出力される必要があるということです。 

### ステップ

 1. DP 状態を定義する$dp[i][k]$、 どこ$i$は最終シーケンス内の処理された要素の数です。$k$すでに開始されているシーケンスの数です。 

すべての新しい要素は新しいシーケンスを開始するか、既存のシーケンスを継続するため、これは重要です。 
2.初期化$dp[0][0] = 1$、何かを処理する前はシーケンスが使用されていないためです。 
3. ポジションごとに$i$、次の値を検討します$x = S[i]$、に遷移します$dp[i+1]$。 
4. 位置で新しいシーケンスを開始すると$i$、残りの未使用のシーケンスの 1 つを選択します。 これは貢献します$M - k$選択肢が増え、アクティブなシーケンスの数が増えます。 
5. すでにアクティブなシーケンスに追加する場合は、次のいずれかを選択します。$k$アクティブなシーケンス。 これは貢献します$k$選択肢。 
6. ただし、そのような割り当てのすべてがマージ ルールの下で有効であるわけではありません。 重要な制約は、要素が$x$グローバル マージ順序で次に出現できるようにする必要があります。 これにより、すべてのアクティブなシーケンス ヘッドの間で、目に見えない小さな要素がそれをブロックすることがなくなります。 

この制約は事実上、観察されたプレフィックスの順序と一致する遷移のみが許可されることを意味し、これにより DP 遷移が値の一貫した選択肢に崩壊します。 
7. すべての有効な遷移を剰余として累積します。$10^9 + 7$。 

### なぜ効果があるのか

 不変条件は、接頭辞を処理した後のものです。$i$、DP は最初の割り当て方法をすべて正確にカウントします。$i$最終シーケンスの要素を順序付けされたシーケンスに変換し、有効なマージ プロセスでそのプレフィックスが生成されるようにします。 

各遷移は、どのシーケンスが次の要素を発行するかを決定することに対応します。 マージ手順では常に使用可能な最小の先頭が選択されるため、有効な割り当てでは、各ステップで選択されたシーケンスの先頭にその要素が存在することが保証される必要があります。 DP は、アクティブなシーケンスの現在のフロンティアを尊重する拡張のみを許可することで、これを暗黙的に強制します。 

すべての有効な構造は DP 内の 1 つの選択肢のシーケンスに正確に対応し、すべての DP パスは有効な構造に対応するため、カウントは正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    M, N = map(int, input().split())
    S = list(map(int, input().split()))

    # dp[k] = ways after current prefix with k active sequences
    dp = [0] * (M + 1)
    dp[0] = 1

    active = 0

    for i in range(N):
        ndp = [0] * (M + 1)
        x = S[i]

        for k in range(M + 1):
            if dp[k] == 0:
                continue

            # start new sequence
            if k < M:
                ndp[k + 1] = (ndp[k + 1] + dp[k] * (M - k)) % MOD

            # extend existing sequence
            if k > 0:
                ndp[k] = (ndp[k] + dp[k] * k) % MOD

        dp = ndp

    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```このコードは、プレフィックス DP の 1 次元圧縮を実装します。 状態インデックスは、現在アクティブなシーケンスの数を表します。 各要素について、新しいシーケンスの最初の要素として導入するか、既存のシーケンスに付加します。 

の乗算$M - k$開始可能な未使用のシーケンスの数を反映します。 の乗算$k$すでに開始されているシーケンスの 1 つを拡張する方法の数を表します。 

最終的な答えは、配列全体を処理した後の考えられるすべてのアクティブ シーケンス カウントの合計です。$M$シーケンスは空ではありません。

```アクティブなシーケンス数によって DP を追跡します。

 | --- | --- | --- | --- | --- | --- |

 各ステップで、新しいシーケンスが開かれるか、既存のシーケンスが拡張されます。 すべての要素を処理した後、すべての有効な構成がカウントされます。 

これは、値を厳密に増加させた場合でも、異なるシーケンスが異なる要素を担当できるため、多くの異なる割り当てパターンが存在することを示しています。

 入力:```

```DP も同様に進化しますが、後でより小さい値が再び現れると、分岐がより制限されます。 

| 私 | 値 | dp[0] | dp[1] | dp[2] | dp[3] |

 後で小さな要素が再出現すると、どのシーケンスが各ステージで要素を合法的に放出できるかが制限されます。 

これらのトレースは、マージの実現可能性を維持しながら、新しいシーケンスを開くことと既存のシーケンスを再利用することの両方を DP が正しく説明していることを確認します。

 ## 特殊なケース

 すべての要素が同一の場合、マージ内のすべての比較は左側のシーケンスに解決され、シーケンスのインターリーブ方法に厳密なバイアスが強制されます。 DP は、値によって順序が区別されていない場合でも、新しいシーケンスの開始と既存のシーケンスの拡張を区別するため、依然として正しくカウントされます。 

小さな値がシーケンスの後半に現れると、遡って以前の割り当てが制限されます。 DP はこれを暗黙的に処理します。これは、シーケンスが早期に大きな値を発行するように選択されると、その後のより小さな値の発行をブロックする可能性のある方法で使用可能になり、無効な構成が有効な DP 遷移として表示されることがないためです。 

単一要素シーケンスは初期化動作をテストします。 値が 1 つだけの場合、すべてのシーケンスが独立してその値を担当することができ、DP は初期の選択肢をカウントすることになり、これは予想される多重度に一致します。
