 ## 解決策
 ## 問題の理解

 この問題は、裕福な個人の集合と企業の集合を与えます。 各人は買収したい企業のリストを持っており、各企業を最大 1 人に割り当てることができます。 人によっては、許可された会社がまったくない場合や、複数のリストに会社が表示される場合があります。 

評議会は、すべての割り当てがリストを尊重するように、企業を人々に割り当てる必要があります。つまり、個人は明示的にリストに記載されている企業のみを受け取ることができます。 すべての割り当てが完了した後、一部の企業は割り当てられないままになる場合があります。 目標は、割り当てられていない企業の数を最小限に抑える方法で割り当てを選択することです。 

グラフで言えば、これは個人と企業の間の 2 部構成のマッチング問題であり、一致したすべての企業が「未割り当て」数から 1 つを削除するため、一致した企業の数を最大化したいと考えています。 

制約は十分に大きく、人数と企業の数は両方とも最大 10,000 まで、すべての人の好みの合計数は最大 100,000 まで可能です。 これにより、すべての一致を列挙しようとしたり、単純な方法で貪欲な再割り当てを繰り返しシミュレートしようとしたりするアプローチが除外されます。 どのソリューションも、エッジの数が線形またはほぼ線形に近い動作をする必要があります。 

一部の人が空のリストを持っている場合、微妙な特殊なケースが発生します。 たとえば、ある人に許可された企業がない場合、その企業はマッチングには何も貢献しませんが、入力には依然として存在します。 もう 1 つのエッジ ケースは、複数のユーザーが同じ 1 つの会社を希望している場合に発生します。たとえば、2 人のユーザーが両方とも会社 1 のみをリストしている場合です。入力順にユーザーを処理する単純な貪欲な割り当てでは、会社を次善の個人に簡単に割り当て、より適切な全体的なマッチングがブロックされる可能性があります。 

たとえば、同じ 2 つの会社に興味を持っている 2 人の人物が、非対称的に構成されているとします。 

入力:```
2 2
2 1 2
1 1
```担当者 1 を会社 1 にすぐに割り当てると、担当者 2 は満足できなくなりますが、担当者 1 を会社 2 に、担当者 2 を会社 1 に割り当てて、未割り当ての会社をゼロにするのがより適切です。 これは、ローカルで貪欲な決定が失敗する可能性があることを示しています。 

## アプローチ

 強引な戦略では、好みを尊重しながら、企業が従業員に割り当てる可能性のあるすべての割り当てを調査しようとします。 各人が複数の企業から選択することができ、私たちは再帰的に企業を割り当てたりスキップしたりして、矛盾が生じた場合には後戻りしていました。 複数の人が共有する各企業によって意思決定の分岐が生じるため、これはすぐに指数関数的になります。また、全員が多数の企業を必要とする最悪の場合、マッチングに対する階乗型の検索として州の数が増加します。 

重要な観察は、私たちが実際に彼らの利益のために最適に人材を割り当てようとしているのではなく、マッチングする企業の数を最大化しようとしているということです。 これにより、問題は、人と企業の間で最大の二者関係のマッチングを見つけることに変わります。 一致が成功するたびに、割り当てられていない企業の数が 1 つずつ減ります。そのため、一致を最大化することは、残りを最小限に抑えることと同じです。 

この構造により、古典的なマッチング手法を使用できるようになります。 エッジは重み付けされておらず、グラフは 2 部構成であるため、標準的な DFS ベースの拡張パス アプローチ (Kuhn のアルゴリズム) を適用できます。 考え方としては、人材を反復して各人を会社に割り当て、全体的なマッチングがより適切になる場合は、以前の割り当てを再配置することを試みることです。 会社がすでに買収されている場合、私たちはその現在の所有者を別の受け入れ可能な会社に再帰的に「プッシュ」し、現在の所有者を解放しようとします。 このローカルな再割り当てメカニズムは、まさに貪欲な割り当ての失敗ケースを修正するものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 割り当てに対するブルート フォース検索 | 指数 | O(N + M) | 遅すぎる |
 | Kuhn の DFS 拡張パス マッチング | O(N·E) 最悪の場合、~O(E√V) が標準 | O(N + M + E) | 承認済み |

 ## アルゴリズムのチュートリアル

 二部グラフの左側に人々をモデル化し、右側に企業をモデル化します。 エッジは、個人を希望リスト内の各企業に結び付けます。 

1. 各人が買収する意思のあるすべての企業を保存する隣接リストを作成します。 この表現により、人物と一致する可能性のあるすべての項目を効率的に調べることができます。 
2. 配列を維持する`match_to_company`これは各会社を現在どの人物が所有しているかを記録します。 最初はすべての会社が割り当てられていないため、この配列は空です。 
3. 会社を特定の個人に割り当てようとする深さ優先検索関数を定義します。 この関数は、その人のリストにあるすべての企業を調査します。 
4. 各企業について、現在割り当てが解除されているかどうかを確認します。 無料の場合は、それを現在のユーザーにすぐに割り当てて成功を返します。これは、競合することなくマッチング サイズを増やしたためです。 
5. 会社がすでに別の人物に割り当てられている場合は、その人物の DFS を再帰的に呼び出して、その既存の人物を別の会社に再割り当てしようとします。 この再帰呼び出しが成功した場合は、代替の配置先が見つかったことを意味するため、安全に現在の人材に代わって会社を採用できます。 
6. すべての人に対してこのプロセスを繰り返します。 新しい割り当てが行われるたびに、一致の合計を増やしながら実現可能性を維持する一連の再割り当てがトリガーされる可能性があります。 
7. すべての人を処理した後、割り当てられていない企業の数を数えます。 答えは、企業の総数から一致した企業の数を引いたものです。 

正確さの背後にある重要な考え方は、会社を再割り当てするたびに、有効な一致を保持しながら、別の割り当てのためのスペースを解放する可能性があるということです。 DFS は、代替パスに沿ったローカル スワップを通じて到達可能なより適切な構成が存在する場合、それが見つかることを保証します。 

## なぜ機能するのか

 アルゴリズムのどの時点でも、割り当てられた企業のセットによって有効なマッチングが形成されます。 DFS の検索では、自由な企業と占有されている企業の間を交互に探索します。 再帰的再割り当てが成功するたびに、フリー カンパニーで終わる交互のパスをたどることに対応し、パス全体を反転することができます。 これにより、可能な限り割り当てられる企業の数が単調に増加しながら、どの企業も複数の人物に割り当てられないという不変条件が維持されます。 成功した各 DFS は、以前に割り当てられていなかった会社を割り当てるか、チェーンを再構成して会社を解放するため、これ以上の拡張パスが存在しない場合、一致の総数は最大になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    
    for i in range(n):
        data = list(map(int, input().split()))
        k = data[0]
        if k > 0:
            g[i] = data[1:]

    match = [-1] * (m + 1)
    vis = None

    def dfs(u):
        for v in g[u]:
            if vis[v]:
                continue
            vis[v] = True
            if match[v] == -1 or dfs(match[v]):
                match[v] = u
                return True
        return False

    for i in range(n):
        vis = [False] * (m + 1)
        dfs(i)

    matched = sum(1 for x in match if x != -1)
    print(m - matched)

if __name__ == "__main__":
    solve()
```隣接リストには各ユーザーの許可された会社が直接保存されるため、DFS は有効な遷移のみを列挙できます。 の`match`配列には会社ごとにインデックスが付けられ、現在割り当てられている個人が格納されます。 

訪問された配列は、単一の拡張検索内での循環を防ぐために DFS 試行ごとに再作成されます。グラフは探索という点では動的ですが、構造は静的であるため、これが必要です。 リセットする`vis`外側の反復ごとに、各試行で新しい検索ツリーを探索することが保証されます。 

最後の引き算`m - matched`最大一致サイズを未割り当ての企業の数に変換します。これが必須の出力です。

 ## 特殊なケース

 重要なエッジケースは、複数の人が同じ 1 つの企業をリストする場合です。 このような状況では、素朴な貪欲なアプローチでは最初の人を割り当て、他の人をブロックしますが、DFS ベースのマッチングにより、最終的な割り当ては 1 つだけ残り、残りは未割り当てとして正しくカウントされます。 

もう 1 つの特殊なケースは、優先リストが空の人々です。 これらのノードはマッチングの試行には参加しないため、DFS は正確さに影響を与えることなくそれらを自然にスキップします。 マッチングの規模は割り当ての成功のみに依存するため、アルゴリズムは依然として割り当てられていない企業を適切にカウントします。 

最後のエッジケースは、プリファレンス リストが大きく、重複が多く、長い拡張パスが作成される場合に発生します。 再帰的 DFS は、フリー カンパニーに到達するまで交互のパスに沿って繰り返し再割り当てを行うことで、これらのチェーンを正しく処理し、局所的には最適だが全体的には次善の構成が残らないようにします。
