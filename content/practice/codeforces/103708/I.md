 ## 解決策
 ## 問題の理解

 このタスクは、一連の数字として書かれた 1 つの整数を中心に展開します。 この数値から各桁を検査し、その桁が数値全体の約数として機能するかどうかを確認します。 ゼロによる除算は定義されていないため、ゼロの数字は無視されます。 ゼロ以外のすべての数字について、元の数値が剰余なしで割り切れるかどうかをテストします。 出力は単にこの条件を満たす桁数です。 

入力は 1 つの整数であり、最大 8 桁の文字列として指定されます。 これを数値と数字シーケンスの両方として扱うことが重要です。算術演算では完全な整数値が使用され、反復処理では個々の文字が処理されます。 

最大 8 桁という制約は、数値が標準の 32 ビット整数制限内に問題なく収まることを意味します。 これにより、大きな整数を処理する必要がなくなり、整数型への直接変換と桁ごとの簡単なモジュラス演算が可能になります。 

最も一般的な失敗のケースは、ゼロ桁と繰り返し桁から発生します。 たとえば、`1010`、数字のみ`1`考慮する必要がありますが、`0`スキップする必要があります。 もう 1 つの微妙なケースは、次の繰り返しです。`111`、それぞれの発生`1`一度だけではなく、独立してカウントする必要があります。 

小さな例でエッジの動作を明確にします。 

入力:`120`数字のみです`1`、`2`、 そして`0`。 無視します`0`。`1`120を割ると、`2`120も割りますので、答えは`2`。 

単純な間違いは、数字を位置ではなく一意の値として扱うことです。これにより、繰り返された数字が単一のチェックに誤って折りたたまれます。 

## アプローチ

 ブルートフォースアプローチはすでに最適に非常に近づいています。 数値を文字列に変換し、各桁ごとにそれを整数に戻し、完全な数値を割るかどうかをテストします。 これには、最大 8 桁をスキャンし、それぞれに対して定数時間のモジュラス チェックを実行する必要があります。 

演算数は小さな定数によって制限され、テスト ケースごとに最大 8 つのモジュラス演算が行われます。 大規模な入力ストリームであっても、これはわずかに高速です。 

重要な点は、前処理や高度な構造が必要ないということです。 問題の構造は本質的に局所的であり、各桁が独立して「はい」または「いいえ」の決定に寄与します。 数字間には相互作用がないため、直接の反復を超えた最適化は不必要な複雑さを増すだけです。 

唯一の微妙な点は、ゼロ桁を安全に処理し、文字列文字と整数間の変換が正しく行われるようにすることです。

 ## アルゴリズムのチュートリアル

 1. 入力数値を文字列として読み取るため、算術抽出を行わずに数字に個別にアクセスできます。 
2. 文字列全体を整数値に変換します。`N`すべての割り算チェックはこの固定数と比較されるためです。 
3. カウンタを初期化する`ans = 0`何桁の除算を保存する`N`。 
4. 各文字を反復処理します。`c`の文字列表現では`N`。 
5.変換`c`整数に変換する`d`。 
6. もし`d`はゼロです。ゼロによる除算は定義されていないため、スキップします。 
7. それ以外の場合は、`N % d == 0`。 true の場合、インクリメントします`ans`1つずつ。 
8. すべての桁を処理した後、出力します。`ans`。 

### なぜ効果があるのか

 各桁は同じ固定整数に対して独立してテストされます。 割り算は桁ごとのバイナリ プロパティであるため、最終的な答えは単に独立した妥当性チェックの合計になります。 ゼロをスキップすると、ゼロは有効な除算に寄与できないため、正確性を維持しながら無効な算術演算が防止されます。 桁の相互作用は存在しないため、有効な桁の数はモジュラス条件を満たす位置の数と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = int(s)
    ans = 0

    for ch in s:
        d = ord(ch) - 48
        if d == 0:
            continue
        if n % d == 0:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、数値を文字列として読み取り、桁の構造を保持すると同時に、割り算を高速にチェックするために一度整数に変換します。 使用する`ord(ch) - 48`のオーバーヘッドを回避します`int()`タイトなループでは、ただし、入力サイズが小さい場合はどちらでも許容されます。 

正しく処理するための主な詳細は、モジュラス前のゼロ チェックです。 これがないと、ゼロ除算が原因でプログラムがクラッシュします。

## 特殊なケース

 次のようなゼロを含む入力の場合`1002003`を使用すると、アルゴリズムは除算を試行する前にすべてのゼロを正しくスキップし、無効なモジュラス演算が発生しないようにします。 ループは単にそれらの位置を無視し、有効な数字を累積し続けます。 

次のような繰り返しの数字の場合`11111111`、各発生は独立して評価されます。 次の場合、カウンタは 8 回増加します。`n % 1 == 0`、セットベースのカウントではなく位置のカウントを反映しています。 

有効な数字を含まない数値の場合、次のようになります。`39`どこだけ`3`数値を除算すると、除算しないすべての桁が他の桁に影響を与えることなくモジュラス条件を満たさないため、カウンターは当然低いままになります。
