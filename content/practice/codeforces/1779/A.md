 ## 解決策
 ## 問題の理解

 タリアには一連のトロフィーがあり、それぞれのトロフィーには左右どちらかに光るランプが付いています。 位置にあるランプ`i`それ自体を除くすべてのトロフィーを、それが指す方向に厳密に照らします。 入力は、すべてのランプの初期方向を「L」と「R」の文字列として記述します。 私たちの目標は、すべてのトロフィーが少なくとも 1 つのランプで照らされるようにすることです。 隣接するランプのペアを最大 1 回交換することも、何もしないこともできます。 

入力は、テスト ケースごとに最大 100,000 のトロフィー、および合計で最大 10,000 のテスト ケースにすることができます。`n`100,000 を境界とするすべてのテストにわたって。 これは、O(n²) のアプローチでは遅すぎるため、各テスト ケースをおよそ O(n) 時間で解決する必要があることを意味します。 考えられるすべてのスワップを明示的に試すような単純なアプローチでは、制限時間を超えてしまいます。 

すべてのランプが同じ方向を向いている場合など、明らかではないエッジ ケースが発生します。`LL`または`RR`。 このような場合、左端または右端のトロフィーは決して点灯せず、単一の交換ではこれを修正できません。 もう 1 つの微妙なシナリオは、単一の隣接するペアが形成される場合です。`RL`または`LR`すでにすべてのトロフィーが点灯しているか、1 回の交換で修正できる方法で。 「L」と「R」のグローバル数のみをチェックする不注意なアプローチでは、隣接性を考慮せずに照明が可能であると誤って想定する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、隣接するランプの可能な交換をそれぞれチェックし、どのトロフィーが点灯するかをシミュレートします。 長さのテスト ケースごとに`n`、照明のシミュレーションには O(n) がかかり、O(n) 回のスワップが可能です。 これにより、テスト ケースごとに O(n²) が得られます。 と`n`最大 10⁵、これは遅すぎます。 

重要な観察点は、トロフィーが消灯できるのは、トロフィーから遠ざかる連続したランプの境界にある場合のみであるということです。 具体的には、先頭のトロフィーは最初のランプが「L」であれば消灯し、最後のトロフィーは最後のランプが「R」であれば消灯します。 さらに、イルミネーションを修正できる唯一の隣接スワップは、`LR`ペア: スワッピング`LR`に`RL`2 つのトロフィーのうち少なくとも 1 つが確実に点灯します。 したがって、チェックする必要があるのは、`LR`パターン。 存在する場合は、それを交換すると問題が解決します。 そのようなペアが存在しない場合は、すべてのトロフィーがすでに点灯しているか、一部の境界が消灯しており、1 回の交換で修正することは不可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テストケースについて、トロフィーの数を読み取ります。`n`そして文字列`s`ランプの方向を表します。 
2. 境界のトロフィーを確認します。 もし`s[0] == 'L'`そして`s[-1] == 'R'`simultaneously, the leftmost and rightmost trophies are unlit, and no swap can fix both. その場合は出力`-1`。 
3. すべてのトロフィーがすでに点灯しているかどうかを確認します。 これは、最初のランプが「R」または最後のランプが「L」である場合、または少なくとも 1 つのランプが存在する場合に当てはまります。`LR`文字列内のどこかにある隣接するペア。 全て点灯していれば出力`0`。 
4. それ以外の場合は、部分文字列の最初の出現を検索します。`LR`。 このペアを交換すると、周囲のトロフィーが確実に点灯します。 そのペアの最初のランプの 1 から始まるインデックスを出力します。 
5. いいえの場合`LR`が存在し、一部のトロフィーが境界で消灯したままになる場合の出力`-1`。 

不変条件は、点灯していないトロフィーは端にあるか、トロフィーに隣接している必要があるということです。`LR`ペア。 最初のものを交換する`LR`ペアはカバー範囲を保証し、何もしないことはすべてのトロフィーがすでにカバーされている場合にのみ機能します。 これにより、すべての有効な構成が正確であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    
    if 'L' not in s[1:] and 'R' not in s[:-1]:
        # No pair can cover internal trophies
        print(-1)
        continue

    found = False
    for i in range(n - 1):
        if s[i] == 'L' and s[i+1] == 'R':
            print(i + 1)
            found = True
            break
        if s[i] == 'R' and s[i+1] == 'L':
            print(0)
            found = True
            break
    if not found:
        print(-1)
```このソリューションでは、最初に、ランプが境界を照らすことができないような、些細で不可能なケースをチェックします。 次に、最初にスキャンします`RL`または`LR`パターン。 もし`RL`が存在する場合、右のランプがすでに左のトロフィーを照らしており、その逆も同様であるため、交換する必要はありません。 もし`LR`が存在する場合、それらを交換すると、以前は点灯していなかった少なくとも 1 つのトロフィーが点灯します。 問題ステートメントに従って、1 から始まるインデックスが返されます。 境界チェックにより、off-by-one エラーがないことが保証され、次のように文字列が読み取られます。`.strip()`改行文字を正しく処理します。

 ## 特殊なケース

 のために`LL`、アルゴリズムは、両方のトロフィーを点灯できる内部ペアがないことをチェックします。 ループでは何も見つかりません`RL`または`LR`ペアになるので出力します`-1`予想通り。 のために`RL`、最初のペアは`RL`、これはすでに点灯しているケースと一致するため、`0`が返されます。 境界に多数の同一方向がある大規模な配列の場合、不必要なスワップを行わずに同じロジックが効率的に適用されます。
