 ## 問題の理解

 整数の配列が与えられ、Baltic は特定の接頭辞の合計、つまり最初の接頭辞の合計を求めています。`m`elements-to be the smallest among all prefix sums of the array. 任意の要素の符号を何度でも反転することができます。 The goal is to compute the minimum number of such sign-flips required to achieve this condition.

 入力により複数のテスト ケースが提供されます。 各テスト ケースは配列サイズを提供します`n`、お気に入りのプレフィックス長`m`、および配列要素。 各テスト ケースの出力は単一の整数であり、必要な最小数のフリップです。 

とすれば`n`最大 2·10^5 とすべての合計を指定できます`n`テスト ケース全体で 2・10^5 を超えない場合、O(n log n) を超える解は遅すぎる可能性があります。 可能な符号反転パターンは 2^n 通りあるため、符号反転のすべての組み合わせを試す単純な総当り攻撃は完全に不可能です。 

明らかでないエッジ ケースには、最初の合計が次のような配列が含まれます。`m`要素がすでに最小である場合、すべてが負の数またはすべてが正の数である配列、およびプレフィックスの合計を支配する可能性がある大きな値が配列の後半に現れる場合。 不注意なアプローチでは、多くの要素を反転したり、局所的な調整のみに焦点を当てたりして、必要以上の反転が発生する可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、要素ごとに考えられるすべての符号反転の組み合わせを試み、どの組み合わせが最初の符号反転を最小化するかを確認します。`m`他と比較したプレフィックスの合計。 これは原理的には正しいですが、組み合わせの数は指数関数的 (2^n) であるため、完全に非現実的です。 

最適化するための重要な観察は、問題が 2 つのフェーズに分けられるということです。`m`要素と残りの要素。 まず最初に`m`要素の合計が正の場合はできるだけ負になるようにし、すでに負の場合はそのままにしておきます。 これらの範囲内の正のプレフィックスの合計`m`要素を反転して合計を減らすことができますが、反転を最小限にするには、最大の正の値を最初に反転する必要があります。 残りの要素については、累積合計が最初の要素の合計を下回らないようにする必要があります。`m`要素。 これは、後で大きな負の数値を反転することで制御できます。`m`-th 要素は、プレフィックスの合計が目標を下回らないようにします。 

ヒープの使用 (最初の場合は max-heap`m`要素を使用して最大の正を反転し、残りの要素の最小ヒープを使用して最大の負を反転することで、これらの調整を効率的に処理できます。 各フリップ操作により、問題のあるプレフィックスが可能な最大量だけ削減され、最小限のフリップが保証されます。

 ## アルゴリズムのチュートリアル

 1. 配列を反復処理するときに、現在のプレフィックスの合計を保存する変数を初期化します。 
2. まず最初に`m`要素では、正の数値の最大ヒープを維持します。 最初から次までを繰り返します`m`- 番目の要素。それぞれを現在のプレフィックスの合計に加算します。 現在のプレフィックス合計がターゲット合計より大きい場合 (比較には最初はゼロが機能します)、最大ヒープ内の最大の正の数値を反転し、プレフィックス合計からその値の 2 倍を減算し、フリップ カウンタをインクリメントします。 最初のプレフィックスの合計まで続行します。`m`要素は最小限に抑えられています。 
3. 要素について`m+1`に`n`、負の数の最小ヒープを維持します。 前方に反復して、実行中のプレフィックス合計に各要素を追加します。 どこかの時点でプレフィックスの合計が最初の合計よりも小さくなった場合、`m`プレフィックスの合計。最小ヒープ (利用可能な場合) から最小の負の要素を繰り返し反転して、プレフィックスの合計を最初の値より大きくします。`m`プレフィックスの合計。 フリップするたびにカウンターがインクリメントされます。 
4. 配列全体を処理した後、カウンターには必要な最小数の符号反転が含まれます。 

**それが機能する理由:** 最初の`m`要素は、最大の正を最初に反転することで貪欲に最小化され、プレフィックスの合計が可能な限り効率的に削減されます。 残りの要素については、プレフィックスの合計が最初の値を下回らないようにします。`m`最初に最大のマイナスを反転して合計します。 これにより、必要なフリップのみを実行することが保証され、各ステップの後、現在のプレフィックスの合計がターゲットを決して違反しないという不変条件が維持されます。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    ops = 0
    pref = 0
    max_heap = []
    
    # Process first m elements
    for i in range(m):
        pref += a[i]
        if a[i] > 0:
            heapq.heappush(max_heap, -a[i])
    while max_heap and pref > 0:
        largest = -heapq.heappop(max_heap)
        pref -= 2 * largest
        ops += 1
    
    # Process remaining elements
    min_heap = []
    for i in range(m, n):
        pref += a[i]
        if a[i] < 0:
            heapq.heappush(min_heap, a[i])
        while min_heap and pref < 0:
            smallest = heapq.heappop(min_heap)
            pref -= 2 * smallest
            ops += 1
    
    print(ops)
```コードは最初に最初のものを処理します`m`大きな正を反転して要素を分割し、合計を効率的に削減します。 次に、大きなマイナスを反転して残りを処理し、後のプレフィックスの合計がないことを確認します。`m`-番目の要素は最初の要素より小さい`m`プレフィックスの合計。 ヒープの順序に細心の注意を払うことで、各フリップが関連するプレフィックスの合計の増減に最大限に寄与するようになります。
