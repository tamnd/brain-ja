 ## 解決策
 ## 問題の理解

 各ノードが小さな整数値を格納するルート付きツリーが与えられます。 1 回の操作でノードを選択し、そのサブツリー内のすべての値をそのサブツリー内の現在のすべての値の XOR に置き換えます。 この割り当ての後、そのサブツリー内のすべてのノードは同一になります。 

申請できるのは最大でも$2n$このようなサブツリーの「XOR による圧縮」操作であり、目標はすべてのノード値をゼロにすることです。 タスクは操作の数を最適化することではなく、有効なシーケンスを構築するか、不可能性を報告することだけです。 

ツリーはノード 1 をルートとし、サブツリーは通常のルート付きサブツリー、つまりノードとそのすべての子孫を意味します。 

制約$a_i \le 31$重要な構造シグナルです。 すべての値は 5 ビット空間内に存在するため、XOR の動作は小さなベクトル空間にわたって完全に線形になります。 大きな$n$まで$2 \cdot 10^5$サブツリーの操作ごとの走査が排除されるため、どのソリューションでもサブツリー XOR を最初から繰り返し再計算することを避ける必要があります。 

最初の微妙なエッジ ケースは、ツリーがチェーンであり、値が葉の近くのみゼロ以外になる場合です。 伝播を慎重に制御せずにボトムアップで操作を繰り返し適用する単純な戦略では、値が上向きにコピーされてから下位のサブツリーに再導入されるという振動が簡単に発生する可能性があります。 

もう 1 つのエッジ ケースは、すべての値がすでに 0 である場合です。 正しいソリューションではゼロ操作を出力する必要があり、正しく実装されていない場合にゼロ以外の値が導入される可能性がある不必要なサブツリー操作を試行してはなりません。 

3 番目のケースは、ツリー全体の XOR がゼロ以外の場合です。 一部の誤った貪欲な戦略は、ルートを早期に「修正」しようとしますが、構造が制御された順序で処理されない限り、サブツリーの上書きにより不整合が再び発生する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。ノードを繰り返し選択し、DFS によってすべてのサブツリー XOR を再計算し、その操作を適用して値を削減します。 それぞれの操作にかかる費用$O(n)$、そして最大$O(n)$操作が必要になる可能性があり、$O(n^2)$、これは限界をはるかに超えています$2 \cdot 10^5$。 

重要な構造上の観察は、この操作によりサブツリーがその XOR に等しい定数で置き換えられるということです。 これは射影のように動作します。サブツリー内の内部変動を破壊し、単一のビットごとの要約に置き換えます。 XOR は線形であるため、繰り返されるサブツリー投影の効果は、情報がどのように上向きに流れ、その後下向きに「平坦化」されるかという観点から推論できます。 

中心となるアイデアは、ツリーをボトムアップの DFS 順序で処理し、子が安定した後にサブツリーを制御された値にいつでも「リセット」できるという事実を利用することです。 私たちは、子を均一にした後、親のサブツリー XOR の推論が容易になるという事実を利用し、各ノードを一定回数訪問することで操作の数を制限しながら、体系的に値を削除できます。 

この構築は、サブツリーが強制的に一時的な状態になってから修正される方法で各ノードが処理されることを保証することで機能し、最初から再計算する必要がなく、制御を上方に伝播します。

 ## アルゴリズムのチュートリアル

 ツリーを 1 にルートし、DFS を実行します。 DFS 中に、常に親の前に子を完全に処理するようにノードの順序を構築します。 この構築は、サブツリー XOR が必要なときに安定するように、慎重に選択された瞬間に操作を適用することに依存しています。 

1. ルートから DFS を実行し、子の順序を保存します。 

これにより、ルートに作用する前にすべてのサブツリーが完全に探索されるポストオーダー構造が得られます。 
2. 各ノードについて、最初にすべての子を再帰的に処理します。 

これにより、ノードを操作するときに、その子孫がすでに制御された状態にあることが保証されます。 
3. 子サブツリーを処理した後、構築の構造を通じて暗黙的にそのサブツリーの XOR を計算します。 

毎回明示的に再計算するのではなく、サブツリーが以前の操作によって均一な値に削減されているという事実に依存します。 
4. 子ノードに操作を適用して、そのサブツリーをそのサブツリーの XOR に等しい単一の値に折りたたむ。 

このステップは、内部構造を削除し、後の推論でサブツリーを単一のノードとして扱えるようにするものです。 
5. すべての子が処理された後、現在のノードに操作を適用して、その子とそれ自体の間の一貫性を確保します。 

これにより、処理されたすべてのサブツリーが均一であるという不変条件を維持しながら、制御された値が上方に伝播されます。 
6. 最後に、必要に応じてルートでクリーンアップ パスを実行し、グローバル XOR 構造がゼロになるようにします。 

この段階ではすべてのサブツリーが均一であるため、最後のルート操作によってツリー全体が調整されます。 

この順序付けにより、均一性を損なうような方法でサブツリーが再訪問されることがなくなります。 

### なぜ効果があるのか

 不変条件は、ノードを処理した後、そのサブツリーが常に均一であることです。これは、そのサブツリー内のすべてのノードが同じ値を持つことを意味します。 サブツリーが均一になると、同一値の XOR はすべてのノードで一貫しているため、サブツリー内でのさらなるサブツリー XOR 操作では均一性が維持されます。 すべてのサブツリーは、その親によって使用される前に、制御された均一な状態に一度だけ縮小されるため、後で異質性を再導入する操作はありません。 この構築では基本的に、各ノードが一定数のサブツリー リセットに関与するようにすることで操作数を線形に保ちながら、ツリーを単一の値にボトムアップ圧縮します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    p = [0] * n
    g = [[] for _ in range(n)]
    
    for i in range(1, n):
        parent = int(input().split()[0])
        p[i] = parent - 1
        g[p[i]].append(i)

    ans = []

    def dfs(v):
        for u in g[v]:
            dfs(u)
        ans.append(v + 1)
        x = 0
        for u in g[v]:
            x ^= a[u]
        x ^= a[v]
        for u in g[v]:
            a[u] = x
        a[v] = x

    dfs(0)

    # final cleanup
    if a[0] != 0:
        ans.append(1)

    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```このコードは、ルート化されたツリーを構築し、親の前に子を処理する DFS を実行します。 リスト`ans`サブツリー操作の順序を記録します。 各ノードはその子が処理された後に追加されます。これは、内部構造が既に単純化された後でサブツリーを折りたたむことに相当します。 

ローカル変数`x`現在のノードとその子の値の XOR を計算します。これは、前の変換後のサブツリー集合体を表すために使用されます。 すべての子にこの値が割り当てられ、サブツリーが均一になります。 これは、今後の親の計算で各サブツリーが単一の集約ユニットとして扱われるようにするための重要なステップです。 

最終的なルート調整により、ルートが完全に無効化されたときにグローバル状態が完全に中立化されることが保証されます。
