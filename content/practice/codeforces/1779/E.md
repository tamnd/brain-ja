 ## 解決策
 ## 問題の理解

 私たちは、直接対決の結果が決定的であるものの、非推移的である可能性があるチェスプレイヤーのグループの中からマスター候補を特定するように求められます。 つまり、プレイヤー A が B に勝つ、B が C に勝つ、C が A に勝つなど、いくつかのサイクルが存在する可能性があります。Anya は最大で次のことを組織できます。$2n$選ばれた 1 人のプレイヤーが他のプレイヤーのサブセットと対戦する同時エキシビション。 彼女には、そのプレーヤーが誰に対して勝ったかではなく、何試合勝ったかだけが知らされます。 一連のクエリの後、どのプレイヤーが完全なトーナメントで優勝する可能性があるかをマークするバイナリ文字列を出力する必要があります。$n-1$エリミネーションマッチ。 

重要な制約は次のとおりです。$n$250まで$2n$許可されたクエリ。 すべてのペアに直接質問するには、$O(n^2)$クエリが多すぎます。 各サイマルは集計情報を提供するため、課題は、候補者を特定するのに十分な情報を超過することなく抽出するクエリを設計することです。$2n$クエリ。 非推移性とは、単純なランキングに依存できないことを意味し、一部のプレイヤーは特定の除去順序でのみ勝つことができることを考慮する必要があります。 

単純なアプローチでは、すべてのペアごとの結果を見つけようとする可能性があります。 たとえば、各プレーヤーを他のプレーヤーに対して個別にクエリするには、$n(n-1)$クエリ。 のために$n=250$、これは 60,000 件を超えるクエリであり、許可されたクエリをはるかに超えています。$500$。 さらに、勝利のサイクルは、推移性を仮定した場合、単純な消去順序が候補マスターを誤って分類する可能性があることを意味します。 

エッジケースは、すべてのプレーヤーがじゃんけんサイクルを形成するときに発生します。 のために$n=3$, プレイヤー 1 が 2 に勝ち、2 が 3 に、3 が 1 に勝った場合、試合順序に応じて各プレイヤーがトーナメントに勝つことができます。 線形階層を前提とした不用意なアプローチでは候補が 1 つしか出力されない可能性があり、これは正しくありません。 もう 1 つのエッジケースは、他のプレイヤーを倒す圧倒的なプレイヤーです。 プレイヤー 1 がすべてに勝った場合、そのプレイヤーだけがマスター候補となり、残りは対戦順序に関係なく勝つことができません。 集計結果を誤って読み取ると、候補者を過大評価する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、各プレイヤーが他のプレイヤーに対して個別にクエリを実行します。 プレイヤーにとって$i$、走れるでしょう$n-1$それぞれ単一の対戦相手に対するクエリを実行し、結果を記録します。 これは、勝利の完全な隣接行列を回復するため、正しいです。 ただし、必要なのは$n(n-1)$クエリ。$n=250$は 62,250 で、許容値をはるかに上回っています$2n = 500$クエリ。 遅すぎてクエリ集中型です。 

最適なアプローチはトーナメント構造を活用します。 プレーヤーがマスター候補になれるのは、どの除外順序でも絶対に負けることが保証されていない場合のみです。 これは、他のすべての対戦相手に勝ったプレイヤーに負けたプレイヤーは候補者になれないことを意味します。 貪欲な戦略を利用することができます。プレーヤーを反復処理しながら現在の「チャンピオン」を維持し、チャンピオンと次のプレーヤーの間の試合をシミュレートすると、勝者がチャンピオンに取って代わることができます。 現在のチャンピオンと次のプレイヤーの間でのみ同時クエリを行うことで、クエリの数を減らすことができます。$n-1$この貪欲なシーケンスで無敗の潜在的な候補者を 1 人特定します。 潜在的なチャンピオンを獲得したら、他のプレイヤーごとに、候補者になることを妨げるような方法で誰かに負けているかどうかを確認します。$n-1$追加のクエリ。 これにより合計が以下に抑えられます$2n$。 

洞察としては、1 対 1 の同時クエリにより、支配的なプレーヤーを段階的に識別できるということです。 プレイヤー X がサイマルで現在の候補者に勝った場合、X が彼らと交代します。 最終的な候補者は、フルトーナメントで優勝できる可能性のある人です。 そして、直接対決で最終候補者に負けないプレイヤーも候補者になることができます。 これにより、クエリの数が減少します。$O(n^2)$に$O(n)$正確性を確保しながら。

 ## アルゴリズムのチュートリアル

 1. プレイヤー数を読み取る$n$。 候補ステータスを追跡するために配列を初期化します。 
2. 最初のプレーヤーを現在の潜在的なチャンピオンとして設定します。 
3. プレーヤー 2 から$n$。 プレイヤーごとに$i$、現在のチャンピオンとプレーヤーの間で同時クエリを実行します。$i$のみ。 もし$i$勝った場合、チャンピオンを次のように置き換えます$i$。 
4. 反復の後、最終的なチャンピオンは、トーナメント全体で優勝する可能性のある人になります。 それらを候補としてマークします。 
5. 他のプレイヤーを確認します。 プレイヤーごとに$j$チャンピオンと等しくありません。プレーヤーと同時クエリを実行します$j$チャンピオンとの対戦。 プレイヤーの場合$j$少なくとも 1 つのゲームに勝った場合は、候補としてマークします。 
6. バイナリ文字列を出力します。1 は候補マスターを示し、0 はそれ以外を示します。 

重要な不変条件は、ステップ 3 の後、最終チャンピオンが貪欲エリミネーション シーケンスで無敗であるということです。 ステップ 5 では、非推移性を考慮して、トーナメントで優勝する可能性のあるプレーヤーを一定の順序で確実に捕捉します。 クエリの合計数が超過することはありません$2n$、問題の制限を満たしています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
flush = sys.stdout.flush

def query(player, opponents):
    s = ''.join('1' if j in opponents else '0' for j in range(n))
    print(f"? {player+1} {s}")
    flush()
    return int(input())

n = int(input())
candidate = [0]*n

# Step 1-3: find a potential champion
champ = 0
for i in range(1, n):
    wins = query(i, [champ])
    if wins > 0:
        champ = i

candidate[champ] = 1

# Step 5: check other players
for i in range(n):
    if i == champ:
        continue
    wins = query(i, [champ])
    if wins > 0:
        candidate[i] = 1

# Output answer
print("! " + ''.join(map(str, candidate)))
flush()
```このソリューションでは、まず潜在的なチャンピオンを貪欲に特定します。 各サイマル クエリは、関連するプレーヤーのみを含むように構築されており、慎重に`s[player] = 0`。 検証中、最終チャンピオンとの試合で少なくとも 1 勝した場合にのみ、プレーヤーを候補としてマークします。 フラッシュにより、アイドル状態の制限を超えないことが保証されます。 Off-by-1 エラーは、配列内の 0 から始まるインデックスをクエリ出力内の 1 から始まるインデックスに変換することで回避されます。
