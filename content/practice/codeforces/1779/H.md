 ## 問題の理解

 私たちに与えられたのは、$n$選手、どこ$n$は 2 の累乗であり、各プレイヤーは固定の正の強さを持ちます。 一連のエリミネーションラウンドが行われます。 各ラウンドでは、現在のプレーヤーのセットが 2 つの等しいグループに分割されます。 グループの総強さはメンバーの強さの合計であり、弱いグループは排除されます。 合計が等しい場合、主催者はどのグループが生き残るかを選択できます。 

このプロセスは、プレイヤーが 1 人になるまで繰り返されます。 各プレーヤーにとって問題は、このプレーヤーが最後の生き残りとなるような一連のスプリットとタイブレークの選択肢が存在するかどうかです。 

出力は長さのバイナリ文字列です。$n$、どこの位置$i$プレイヤーの場合は 1$i$勝つように配置することができ、それ以外の場合は 0 になります。 

制約のサイズは小さいですが、$n \le 32$、しかし、その構造は非常に組み合わせ的です。 すべてのラウンドでは、現在のセットのパーティションを選択する必要があり、この選択は以前のすべての決定に依存します。 単純なシミュレーションはすでに非常に迅速に分岐し、可能なトーナメント構造の総数は超指数関数的に増加します。 

重要な難しさは、プレイヤーの生存はプレイヤーの強さだけではなく、二分消去法のすべてのレベルでそのグループが厳密に弱くなることを回避できるパーティションを一貫して構築できるかどうかに依存していることです。 

単純な失敗モードは、より強いプレーヤーが常に勝つと想定することです。 これは不正確です。グループ化すると、弱いプレイヤーをより強い味方とペアにし、より強い対戦相手を別のグループに強制することで、弱いプレイヤーを「保護」できるからです。 

もう 1 つのよくある落とし穴は、個人の強みだけを貪欲に比較することです。 個々の比較ではなくサブセットの合計が重要であるため、ローカルな優位性はグローバルな優位性を意味しません。 

## アプローチ

 問題は基本的に、プレイヤーのセットに対するバイナリ ツリーの構築に関するもので、各内部ノードは 2 つの等しいサブセットへの分割を表し、より強力なサブセットのみが生き残ります。 各プレーヤーの実現可能性は、そのような構造の勝ち葉にそれらを埋め込むことができるかどうかに依存します。 

ブルートフォースアプローチでは、現在のセットをすべてのレベルで 2 つの半分に分割し、すべての結果をシミュレートするすべての可能な方法を列挙しようとします。 最上位レベルには、$\binom{n}{n/2}$分割され、これが生き残った半分ごとに繰り返されます。 たとえ$n = 16$、これはすでに管理不可能な数のパーティションに爆発的に増加しています。$n = 32$それは完全に不可能になります。 

重要な点は、トーナメントの構造全体を追跡する必要がないということです。 代わりに、プレイヤーのサブセットを、特定のターゲット プレイヤーとなる可能性のある 1 人の勝者に絞り込むことができるかどうかのみを考慮します。 これは、サブセット動的プログラミングの観点を示唆しています。 

勝者候補を修正する$i$。 次のような一連の消去が存在するかどうかを尋ねます。$i$どのラウンドでも生き残る。 各ラウンドでの現在のセット$S$2 つの同じサイズのサブセットに分割する必要があります$A$そして$B$、ここで、以下を含むサブセットは$i$合計は少なくとも他のサブセットと同じ大きさでなければなりません (または厳密にそれより大きいか、タイブレークによって強制的に勝利を強制することもできます)。 つまり、「ホームグループ」を確保できる限り、$i$どのレベルにおいても対戦相手より厳密に弱いことはありません。$i$実行可能です。 

これにより、問題はサブセットにわたる到達可能性の問題に変換されます。サブセットのペアを、以下を含む存続サブセットに繰り返しマージできるでしょうか。$i$、各マージ ステップで、過大な影響を与えないペアリングが存在することを保証します。$i$の側？ 

以来$n \le 32$、サブセットをビットマスクとして表し、それらの合計を事前計算できます。 次に、ターゲットごとに$i$を含むサブセットに対して DP を実行します。$i$、フルセットを以下に削減できるかどうかを確認します。$\{i\}$サブセットを 2 つの等しい半分に繰り返し分割することによって、$i$支配されていない。 

これを機能させるための重要なトリックは、サブセットが内部的にどのように構成されているかではなく、サブセットが「i を含むブロックとして存続」できるかどうかだけを知る必要があるということです。 これにより、サブセット パーティション上の中間一致スタイルの DP で、小さい有効なサブセットを大きいサブセットにマージできます。

 ## アルゴリズムのチュートリアル

 候補選手を固定する$i$最終的な勝者になれるかどうかを確認します。 

1. ビットマスク DP を使用して、すべてのサブセットの強度の合計を事前計算します。 これにより、パーティションを繰り返し比較するため、後で任意のグループの強度を定数時間で比較することができます。 
2. 状態を定義する$dp[mask]$で表されるサブセットを意味します。`mask`まだプレイヤーである可能性がある1人の生存者に減らすことができます$i$と仮定すると$i \in mask$。 を含まないサブセット$i$このDPには無関係です。 
3.初期化$dp[\{i\}] = true$。 シングルプレイヤー セットは、それ以上の分割が必要ないため、当然ながら存続します。 
4. サイズの大きい順にサブセットを処理します。 セットの有効な縮小は、より小さな中間サブセットから得られる必要があるため、この順序付けは重要です。 
5. サブセットの場合`mask`サイズが 1 より大きい場合は、空ではない 2 つのサブセットに分割しようとします。$A$そして$B$次のような:

 - 両方とも同じサイズです。 
-$A \cup B = mask$、
 -$i \in A$、
- 両方$A$そして$B$有効に約定可能である (または最終ステップで、$B$単なる競合グループである可能性があります)、
 - 強度条件により、$A$生き残る、という意味`sum[A] >= sum[B]`。 

そのようなパーティションが存在する場合は、`dp[mask] = true`。 

このような分割の実現可能性のみを必要とする理由は、すべてのトーナメント ラウンドがまさにそのような分割であるため、すべての有効な敗退履歴がこれらの有効なマージのシーケンスに対応するためです。 
6. dp を入力した後、次のことを確認します。`dp[full_mask]`それは本当です。 「はい」の場合、プレイヤー$i$最後の生き残りになる可能性があります。 
7. すべてのプレーヤーに対してこのプロセスを繰り返し、結果のバイナリ文字列を出力します。 

### なぜ効果があるのか

 すべての有効なトーナメントは、葉がプレーヤーであり、内部ノードが同じサイズのセットへのパーティションであるバイナリ ツリーに対応します。 DP は、そのようなノードの「勝者側」として表示されるサブセットのセットを正確に構築します。$i$。 すべてのリダクション ステップは、優勢制約の下で 2 つの有効なサブツリーをマージするものとしてモデル化されるため、dp に到達可能な状態はすべて実現可能なトーナメント構造に対応し、実現可能なトーナメントは有効な dp 構築を誘導します。 これにより、dp 到達可能性と勝者になる可能性が 1 対 1 で対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = list(map(int, input().split()))

    full = (1 << n) - 1

    # precompute subset sums
    subset_sum = [0] * (1 << n)
    for mask in range(1 << n):
        if mask:
            lsb = mask & -mask
            i = (lsb.bit_length() - 1)
            subset_sum[mask] = subset_sum[mask ^ lsb] + s[i]

    ans = []

    for target in range(n):
        if s[target] == 0:
            ans.append('0')
            continue

        dp = [False] * (1 << n)
        dp[1 << target] = True

        # iterate by increasing size
        for mask in range(1 << n):
            if not (mask & (1 << target)):
                continue
            if not dp[mask]:
                continue

            # try to extend by combining with disjoint subsets
            sub = mask ^ full
            t = sub
            while t:
                b = t
                a = mask
                if subset_sum[a] >= subset_sum[b]:
                    new_mask = a | b
                    if bin(new_mask).count('1') == bin(mask).count('1') * 2:
                        if new_mask < (1 << n):
                            dp[new_mask] = True
                t = (t - 1) & sub

        ans.append('1' if dp[full] else '0')

    print(''.join(ans))

if __name__ == "__main__":
    solve()
```コードは、グループ間の比較が定数時間になるように、ビットマスク DP を使用してサブセットの合計を計算することから始まります。 次に、候補選手ごとに、その選手を含むサブセットに対して DP を実行します。 内側のループは、候補となる敵グループを列挙し、ビットをカウントすることで暗黙的に等しいサイズの構造を維持しながら、それらを現在の存続セットとマージしようとします。 

実装の微妙な詳細は、ターゲット プレーヤーを含むサブセットへの制限です。 この枝刈りを行わないと、状態空間が不必要に 2 倍になり、構造が失われます。 もう 1 つの重要な点は、サブセット列挙ではビット操作を使用して、候補パーティションの繰り返し構築を回避することです。

 ## 特殊なケース

 重要なエッジケースは、すべてのプレイヤーが同じ強さを持っている場合です。 その状況では、すべてのパーティションがすべてのレベルで同点になるため、全体の結果は純粋に同点の勝者をどのように選択するかによって決まります。 DP はすべてのマージを実行可能として扱い、すべてのプレーヤーが最終状態に到達し、すべて 1 の文字列が生成されます。 

もう 1 つのエッジケースは、圧倒的に強いプレイヤーが 1 人いる場合です。 1 つの値が他のすべての値の合計よりも大きい場合、そのプレイヤーは常にすべてのステージで勝利側に孤立する可能性があります。 すべての対戦相手のサブセットの合計が厳密に小さいため、DP はこれを反映しており、必要なマージはすべて有効です。 

最後の微妙なケースは、強さによってローカルの優位性は許可されるが、グローバル構造は許可されない場合です。この場合、プレーヤーは早期マージに勝つことができますが、有効な完全なバイナリ分解にペアリングすることができません。 一部の中間マスクはサイズと合計の両方の制約を満たす有効な相補パーティションを見つけることができないため、サブセット DP はこれらを正しく拒否します。
