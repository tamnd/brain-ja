 ## 解決策
 ## 問題の理解

 村は三角形の交差点のグリッドとして表されます。 三角形の各辺には長さがある$n$、内部はさらに細分化されています。$n^2$小さめの正三角形。 村の道はこの三角形の辺に沿って一方通行になっています。 3 つの主な方向のそれぞれについて、長さの文字列$n$道路セグメントがデフォルトの方向 (1) に沿って配置されているか、反対方向 (0) に配置されているかをエンコードします。 私たちのタスクは、すべての交差点が他のすべての交差点に到達できるように、最小数の単位道路セグメントの方向を調整することです。 

重要な抽象化は、問題を有向グラフとして見ることです。 各単位道路区間がエッジ、交差点がノードとなる。 初期の方向により、グラフが切断されたり、特定のパスが妨げられたりする場合があります。 個々のエッジを反転して、強力な接続を作成できます。 サイズの三角格子の場合$n$、 がある$3n$道路は長いですが、到達可能性にとって重要なのは主三角形の端の 3 つの頂点だけです。 反転の最小数は、コーナーを接続する 3 つの境界道路の最初と最後のセグメントの方向のみに依存します。 

制約により次のことが決まります$n$と同じ大きさにすることができます$10^5$、テスト ケース全体の合計も次のように制限されます。$10^5$。 これにより、すべてのソリューションを反復することができなくなります。$n^2$交差点または単位道路セグメントの完全なセット。それには最大で$10^{10}$操作。 必要なのは$O(n)$あるいは$O(1)$per test case strategy.

 明らかではないエッジケースには、小規模なものが含まれます。$n$1 や 2 のように、境界セグメントが一致します。 たとえば、すべての境界道路が正しい方向を向いている場合、答えは 0 ですが、1 つのコーナー セグメントだけがその方向と反対の場合は、1 回の反転で十分です。 もう 1 つのエッジ ケースは、3 つの境界道路すべての最初と最後のセグメントが必要な流れの反対側にある場合です。 このシナリオでは 3 回のフリップが強制されます。 

## アプローチ

 単純なアプローチでは、グラフ全体を構築し、すべてのノードから到達可能性チェックを実行し、強力な接続が達成されるまでセグメントを 1 つずつ反転しようとします。 これは原理的には正しいですが、次の理由により実行できません。$n^2$交差点の成長。 のために$n=10^5$、ブルートフォースアプローチには次のことが必要です$10^{10}$操作。 

重要な洞察は、三角格子では、強い接続性は、3 つの角を接続する最小スパニング パスの境界を形成する 3 つの角セグメントの方向によってのみ決定されるということです。 各コーナーに、これらのエッジに沿って三角形から出たり入ったりするパスがある場合、三角形グリッドの再帰構造により、内部に自動的に到達できます。 したがって、問題は、3 つの境界文字列のそれぞれの最初と最後の文字を調べ、各隅でトラフィックの送受信を可能にするために反転する必要がある文字列の数を数えるということになります。 

接続するには、特定の方向でなければならないセグメントが 3 つあります。1 番目の道路の最初のセグメント、2 番目の道路の最後のセグメント、3 番目の道路の最初のセグメントです。 間違った向きの各セグメントは 1 回の反転に寄与します。 答えはこれら 3 つのフリップの合計です。 これにより、$O(1)$テストケースごとのソリューション。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n^2) | 遅すぎる |
 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 テスト ケースごとに、次の内容を読んでください。$n$そして3本の弦$s_1, s_2, s_3$。 
2. 重要なセグメント、つまり三角形の角を結ぶエッジに対応する文字列の最初と最後の文字を特定します。 具体的には、これらは、$s_1[0]$、$s_2[-1]$、 そして$s_3[0]$。 
3. 各クリティカル セグメントについて、その方向が目的の方向と反対の場合、フリップを 1 回カウントします。 望ましい方向は、トラフィックがコーナー ノードから出たり入ったりできることを保証することであり、これは、これらのセグメントが三角形の内側に向かうことを意味します。 
4. 3 つのセグメントからの反転を合計して、反転する道路セグメントの最小数を取得します。 
5. この合計をテスト ケースごとに出力します。 

機能する理由: 三角形の 3 つの角に沿ったエッジの方向のみが、グリッド全体の到達可能性に影響します。 三角格子によりパスがグリッドに沿って伝播できるため、角が正しい向きであれば内部が接続されることが保証されます。 3 つの重要なセグメントでのみフリップをカウントすることで、強力な接続を実現しながら最小限の反転数を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s1 = input().strip()
        s2 = input().strip()
        s3 = input().strip()
        flips = 0
        flips += s1[0] == '0'  # first segment of first road
        flips += s2[-1] == '1' # last segment of second road
        flips += s3[0] == '0'  # first segment of third road
        print(flips)

solve()
```各行は、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 3 つの重要なセグメントのみをチェックします。$O(1)$テストケースごとに。 のような表現`s1[0] == '0'`ブール値に評価され、Python では暗黙的に次のように変換されます。`1`追加されると、必要なフリップをカウントします。 順序は、問題ステートメント内の三角形の方向と一致するように選択されます。

 ## 特殊なケース

 のために$n=1$、三角形の交点は 1 つだけです。 3 つの道路がすべて正しく指している場合、出力は 0 です。1 つ以上の点が反対する場合、それぞれがちょうど 1 つの反転に寄与し、アルゴリズムはそれを正確にカウントします。 最大限に$n=10^5$、各文字列の最初と最後の文字のみが関連するため、アルゴリズムは全体の長さに依存せず、パフォーマンスの問題を回避します。 混合方向の場合、アルゴリズムは 3 つのセグメントのうち、必要な方向と反対のものがいくつあるかを正確にカウントし、最小限の反転を保証します。
