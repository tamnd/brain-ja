 ## 解決策
 ## 問題の理解

 ゴリラの特徴的な強さを一列に並べて表現しています。 セグメント$[l, r]$そのセグメント内の最も強い 2 つのゴリラがセグメントの端に正確に位置する場合、つまりどちらの端点よりも大きい内部要素がない場合、この関数は有効であると見なされます。 同様に、すべての内部要素は厳密に次の値よりも小さくなければなりません。$\min(a_l, a_r)$。 単一要素セグメントは無関係であり、長さ 2 のセグメントは内部がないため常に有効です。 

時間の経過とともに、強みは動的に変化します。 各クエリ ステップで、1 頭のゴリラがトレーニングを受けて非常に強くなり、以前のすべての値を超え、その時点でユニークな新しい値を取得します。 この更新は、「エンドポイントがセグメント内で 2 つ大きい」条件を満たすセグメントに影響を与える可能性があります。 

更新のたびに、現在の配列に有効なセグメントがいくつ存在するかをカウントする必要があります。 

制約により両方が許可されます$n$そして$q$まで$10^6$これにより、クエリごとにすべてのサブ配列をスキャンするソリューションは直ちに除外されます。 クエリごとの線形再計算でも、$10^{12}$実行可能な限界をはるかに超えた最悪の場合の操作。 したがって、ローカルな変更を更新し、グローバルなカウントを効率的に、理想的にはクエリごとの償却対数時間またはほぼ一定の時間で維持する構造が必要です。 

微妙な点は、値が単に恣意的に更新されるのではなく、常にグローバルな最大値になり、後で置き換えられるまでその値が維持されることです。 この単調な成長が重要な構造の単純化です。 

よくある落とし穴の 1 つは、スタックまたは単調構造をクエリごとに個別に使用して「適切なセグメント」を再計算しようとすることです。 これは、更新のたびに構造の大部分が無効になり、完全な状態が再計算されるため、失敗します。 

もう 1 つの特殊なケースは、妥当性の定義から生じます。これは、絶対値ではなく、セグメント内の相対的な順序にのみ依存します。 これにより、値ではなく最大要素の位置にわたる幾何学的構造への縮小が可能になります。 

## アプローチ

 ブルートフォース ソリューションでは、すべてのセグメントが検査されます。$[l, r]$そして、内部の最大値がいずれかの端点にあるかどうか、または同様にすべての内部要素が両方の端点よりも小さいかどうかを確認します。 クエリごとに、これを最初から再計算するには、繰り返しを行う必要があります。$O(n^2)$セグメントを分割して内部をチェックしていますが、すでに大きすぎます。 事前に計算された最大値を使用してセグメント チェックを最適化しても、依然として次のような結果が得られます。$O(n^2)$クエリごと、または$O(n^2 q)$全体としては絶望的だ$10^6$。 

重要な観察は、セグメントの最大要素と 2 番目の最大要素がその端点にあるときに、セグメントが有効であるということです。 すべての値は個別であるため、セグメントは配列内の「主要な要素」の位置によって決定されると考えることができます。 

より有用な再定式化は、要素を値の降順に処理することです。 新しい最大要素を導入するたびに、デカルト ツリーを構築するのと同様の方法で、その要素を隣接するすでにアクティブ化された要素に接続します。 実際、有効なセグメントの構造は、値の減少する挿入順序の隣接する要素のペアに対応しており、これはまさに動的隣接セットによって維持される構造です。 

すべてのセグメントを明示的に追跡する代わりに、インデックスによってソートされた「アクティブなポジション」の順序付けされたセットを維持します。 新しい最大値が導入されると、既存のセグメントがより小さなセグメントに分割され、ローカルの隣接関係のみが変更されます。 各隣接関係は 1 つの有効なセグメントにのみ寄与し、合計の答えは増分的に維持できます。 

これにより、挿入を伴う動的な順序付きセットの維持と、隣接するギャップに基づいた実行カウントの更新の問題が軽減されます。 各挿入は、順序内の直前の先行者と後続者にのみ影響します。

 ## アルゴリズムのチュートリアル

 私たちはこのプロセスを、「アクティベーション時間」の増加順に要素を段階的に明らかにし、更新ごとに新しいグローバル最大値を導入すると解釈します。 

私たちは、これまでにアクティブ化されたインデックスのソートされたコンテナーを維持します。 任意の 2 つの連続するアクティブなインデックスの間で、そのギャップによって寄与される有効なセグメントの数を維持します。 

1. 2 つのセンチネル位置を含むソートされた構造を初期化します。$0$そして$n+1$。 これらは、エッジ処理を簡素化する人工境界として機能します。 
2. アクティブなポジションのカウンタとゼロに初期化された実行中の応答を維持します。 答えは、隣接するアクティブな位置によって形成される有効なセグメントの数を表します。 
3. 更新ごとに、インデックスを取得します。$x_j$それをソートされた構造に挿入します。 挿入する前に、その直前の先行ファイルを見つけます。$p$そして後継者$s$アクティブなポジションの中で。 これら 2 つの位置は現在、単一の結合された間隔を形成しており、正確に 1 つの有効なセグメント範囲に寄与します。$p$に$s$。 
4. 1回$x_j$が挿入されると、間隔が$(p, s)$2つの区間に分かれています$(p, x_j)$そして$(x_j, s)$。 1 つのセグメントの前の寄与が削除され、2 つの新しい寄与が追加されるため、答えの最終的な変化は、この分割によって作成または破棄されるセグメントの数のみに依存します。 
5. このローカルな変更を調整して実行中の応答を更新し、挿入のたびに出力します。 

重要な考え方は、挿入された要素の近傍のみが有効性構造を変更するということです。 他のすべてのセグメントは、内部最大値の順序が変更されていないため、影響を受けません。 

### なぜ効果があるのか

 正確性は、すべての有効なセグメントが、ソートされたインデックス セット内の連続するアクティブな「支配的な境界」のペアに一意に対応するという不変条件に基づいています。 新しい支配的な要素がその位置に現れたとき$x$、アクティブな構造内で以前にまたがっていたセグメントにのみ影響します。 他のすべてのセグメントは完全に左側または右側にあるか、端点が変更されていないため、有効性条件はそのまま残ります。 この局所性により、各更新では、先行および後続の調整を通じてのみ回答が変更されることが保証されます。

def solve():

    a = list(map(int, input().split()))
    x = list(map(int, input().split()))

    # We simulate using sorted active set
    import bisect

    active = [0, n + 1]
    ans = 0
    res = []

    # We also need positions ordered by activation time
    # Each position becomes "active maximum" at its query time
    # We process in reverse: last activation first
    activated = [False] * (n + 2)

    for pos in x:
        i = bisect.bisect_left(active, pos)
        l = active[i - 1]
        r = active[i]

        # before inserting pos, (l, r) was one interval
        # after insertion, it becomes two intervals

重要な操作は、構造をどのように分割するかを決定する先行要素と後続要素を見つけることです。 Python リストへの挿入は$O(n)$これは厳密には最適ではありませんが、意図された競技プログラミング ソリューションはバランスのとれた BST または C++ などの順序セット構造を前提としています。`set`。 Python では通常、これを次のように置き換えます。`sortedcontainers`構造またはカスタム トリープを使用して制約を完全に遵守します。 

カウントのロジックは、挿入ごとに既存の間隔が 1 つだけ分割されるため、アクティブなセグメントの数が 1 つずつ増加するという事実に基づいています。

 ## 特殊なケース

 最小のエッジ ケースは、配列のサイズが 2 の場合です。 更新によって内部構造が作成されることはなく、すべてのセグメントは自明に有効です。 アクティブ セットには常に境界のみが含まれており、挿入ごとに答えが決定的に増加するため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、配列の終端で挿入が発生する場合に発生します。 たとえば、位置を挿入する$1$または$n$1 つの隣接間隔のみに影響します。 先行-後続ロジックは引き続き単一の分割を生成し、各挿入が正確に 1 つの間隔で変更されるという不変条件は引き続き有効です。 

最後のエッジケースは、時間の経過とともに同じ位置で更新が繰り返されることです。 更新のたびにその位置の新しいグローバル最大値が作成されるため、構造は同じインデックスをアクティブ セット ロジックに効果的に再挿入します。 先行者と後続者の調整により、影響を受ける区間が引き続き正確に分離されるため、無関係なセグメントに影響を与えることなく、以前の寄与が一貫して置き換えられます。
