 ## 解決策
 ## 問題の理解

 次のサイズの長方形グリッドが与えられます。$h \times w$。 トークンは左上のセルから始まります$(1,1)$右下のセルに到達したいと考えています$(h,w)$。 移動は右または下のみに制限されるため、有効なパスはすべてグリッド内の単調なパスになります。 

一部のセルはブロックされる可能性があり、ブロックされたセルにはアクセスできません。 ただし、建設は厳しく制限されています。 ブロックされたセルは、辺や角、および開始セルを共有することによって、別のブロックされたセルに隣接することはできません。$(1,1)$そして標的細胞$(h,w)$ブロックされていない状態を維持する必要があります。 タスクは、開始から終了までの有効な単調パスが存在しないようにいくつかのブロックされたセルを配置できるかどうかを判断し、可能であればそのような構成を構築することです。 

制約$h, w \le 200$ということを意味します$O(hw)$構築やチェックは簡単です。 グリッドにはすでに最大 40,000 個のセルがあり、単純なサブセット推論でさえ爆発してしまうため、ブロックされたセットの指数関数的な列挙を伴うものはすべて不可能です。 

微妙な問題は、パス自体がブロックされることではなく、ブロックされたセルに対する隣接関係の制限です。 セルを自由にブロックできれば、これはグリッド上の古典的な最小限のカット、または単純なジグザグのバリア構造になります。 ここでは、「対角線を含めて 2 つの隣接するブロックされたセルは存在しない」というルールにより、バリアの密度が厳しく制限されます。 

単純な間違いは、左上と右下を隔てる強固な壁を構築しようとすることです。 たとえば、$2 \times 2$グリッド、ブロックしようとするかもしれません$(1,2)$そして$(2,1)$。 これら 2 つのセルは斜めに隣接しているため、両方を同時にブロックできないため、これは失敗します。 の正しい出力$2 \times 2$したがって不可能です。 

もう一つの誤解を招くケースは、$2 \times 3$。 ブロッキングのような垂直カットを試みるかもしれない$(1,2)$そして$(2,2)$、しかし、それらは垂直に隣接しているため、やはり無効です。 隣接制約により、小さなグリッドでの完全なカットの形成が防止されます。 

重要な認識は、実現可能性は、すべての単調パスをブロックするスパース セパレータを埋め込むことができるかどうかに依存するということです。 

## アプローチ

 隣接制約を無視すると、問題は分割する頂点カットの構築に帰着します。$(1,1)$から$(h,w)$。 ブルート フォース アプローチでは、セルのすべてのサブセットを試し、隣接関係の有効性をテストし、ブロック後に BFS 経由で到達可能性をチェックします。 これは$O(2^{hw} \cdot hw)$、これはたとえ$h=w=10$、ましてや200。 

もっと合理的な総当たり戦略でも、行ごと、または列ごとにバリアを構築し、毎回接続性をテストしようとする可能性があります。 その場合でも、候補となる構成ごとに BFS または DFS が必要になります。少なくとも$O(hw)$チェックごとに多くの試行を掛けても、それでも遅すぎます。 

重要な構造的観察は、私たちは何かを最大化したり最小化したりすることを求められていないということです。 私たちに必要なのは存在だけです。 これにより、明示的なカットではなくパリティ パターンの観点から考えることが可能になります。 

隣接制約 (特に斜め隣接を含む) は、チェッカーボード スタイルの制限を示唆しています。つまり、ブロックされたセルは 8 近傍の意味で分離する必要があります。 つまり、ブロックされたセルはまばらにしか配置できず、効果的な構築では交互のパターンを利用する必要があります。 

決定的な洞察は、グリッドが狭すぎて非干渉セパレーターを配置できない最小の縮退ケースを除いて、すべてのグリッドに完全なブロッキング構成が存在するということです。 のために$h=w=2$、それは不可能です。 すべての大きなグリッドについては、隣接ルールに違反せずにすべてのブロックされた制約をバイパスできないため、すべての単調パスが確実に矛盾するようにする繰り返しの疎パターンを構築できます。 

標準的な構造では、ブロックされたセルが両方のインデックスが一致するモジュロ 2 である位置に慎重にずらして現れる周期パターンが使用されます。 これにより、斜めの障害物が作成され、ブロックされた 2 つのセルが斜めであっても接触しないというルールを維持しながら、左上から右下への連続した単調な移動が防止されます。

 ## アルゴリズムのチュートリアル

 1. まず次のことを確認します。$h = 2$そして$w = 2$。 この構成では、ブロッカーを 2 つ配置しても隣接ルールに違反するため、パスをブロックしようとしても失敗しますが、1 つだけ配置してもパスは開いたままになります。 
2. グリッドが表示されていない場合$2 \times 2$、ブロックされたセルがまばらな交互パターンを形成するグリッドを構築します。 目標は、すべての可能な右下方向のパスが、法的にブロックされた配置では完全にカバーできない少なくとも 1 つの制約された領域を強制的に通過するようにすることです。 
3. すべてのセルに対して繰り返します。 セルにマークを付ける$(i,j)$ブロックされた場合として$i \equiv j \pmod{2}$ただし、明示的にスキップします$(1,1)$そして$(h,w)$。 これにより、ブロックされたセルの市松模様のパターンが作成されます。 
4. ブロックされた 2 つのセルが隣接ルールに違反していないことを確認します。 すべてのブロックされたセルは単一のパリティ クラスにあるため、水平、垂直、または斜めの隣接セルは反対のパリティを持つため、ブロックされません。 
5. 結果のグリッドを出力します。 

### なぜ効果があるのか

 この構造により、ブロックされたセルがキングムーブ隣接グラフの下で最大の独立したセットを形成することが保証されます。 これにより、制約の下での妥当性が保証されます。 同時に、からの単調なパスは、$(1,1)$に$(h,w)$両方のパリティ クラスを繰り返し通過する必要がありますが、増加する座標の構造により、単調な進行で少なくとも 1 つのブロックされたセルを通過する必要があります。 すべてのブロックされた位置をバイパスすることが不可能であるのは、すべての単調パスが制御された方法でパリティを交互に配置する一方、ターゲット パリティ パターンは、禁止されたセルにヒットすることなしには調整できない方法で開始と終了を確実に分離しているという事実から来ています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    h, w = map(int, input().split())

    if h == 2 and w == 2:
        print("No")
        return

    grid = [["." for _ in range(w)] for _ in range(h)]

    for i in range(h):
        for j in range(w):
            if (i == 0 and j == 0) or (i == h - 1 and j == w - 1):
                continue
            if (i + j) % 2 == 0:
                grid[i][j] = "X"

    print("Yes")
    for row in grid:
        print("".join(row))

if __name__ == "__main__":
    solve()
```このコードは、唯一既知の不可能な構成を直接処理することから始まります。$2 \times 2$グリッド。 それ以外はすべて建設に進みます。 

グリッドは完全に空で初期化されます。 次に、座標にパリティ ルールを適用します。 ゼロベースのインデックスを使用すると、セルに$(i + j) \bmod 2 = 0$開いたままにする必要がある 2 つのエンドポイントを除き、ブロックされた候補として選択されます。 

このパリティ ベースの配置では、8 つの隣接セルすべてがパリティを反転するため、ブロックされた 2 つのセルが辺や角を共有しないことが保証されます。 これにより、隣接性制約が直接適用されます。 

最終的なグリッドは必要な形式で印刷されます。

def run(inp: str) -> str:

def main_capture(inp: str) -> str:
    import sys
    input = sys.stdin.readline

 ## 特殊なケース

 のために$2 \times 2$、ブロックされた 2 つのセルを配置しようとしても、それらは斜めに隣接しているため失敗しますが、1 つ配置するだけではグリッドを切断するには不十分です。 アルゴリズムはこのケースを直接検出し、「いいえ」を出力し、構築の試みを回避します。 

のようなグリッドの場合$2 \times w$、チェッカーボード構造は依然としてきれいに適用されます。 パリティ パターンにより、ブロックされたセルが隣接ルールに違反しないことが保証されます。 たとえば、$2 \times 3$、ブロックされたセルが交互の位置に表示され、エンドポイントは変更されず、有効な構成が生成されます。 

次のような大きなグリッドの場合$200 \times 200$、パターンは均一のままです。 すべてのセルの決定はパリティのみに依存するため、境界が不安定になることはありません。 構造はエッジとコーナーで一貫性を保ち、エンドポイントの除外により必要な位置が誤ってブロックされることを防ぎます。
