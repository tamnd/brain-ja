 ## 解決策
 ## 問題の理解

 独立したローターの列が与えられます。 各ローターはラップアラウンドする値を格納するため、ローター`i`円上の数字のように動作します`0`に`m_i - 1`。 システムはすべてのローターがゼロの状態で開始され、目標構成に到達する必要があります。`b`。 

許可される唯一の操作は、連続したセグメントを選択することです`[l, r]`そして、そのセグメント内のすべてのローターを、独自の弾性率に応じてラップアラウンドしながら、前方に 1 ステップずつ回転させます。 各操作は選択されたすべての位置に等しく影響しますが、係数は位置ごとに異なるため、同じ操作でもローターごとに異なる「効果的な動作」が生じます。 

タスクは、オール ゼロの状態をターゲット配列に変換するために必要なセグメント回転の最小数を計算することです。 

主な問題点は、操作が重複することです。セグメントを適用すると、複数の位置が一度に増分され、異なるセグメントが複雑な方法で重複する可能性があります。 可能なセグメント操作のすべてのシーケンスをシミュレートしようとする素朴なアプローチは、操作の数と可能なセグメントの数の両方が二次関数的に増加するため、すぐに実行不可能になります。`n`。 

制約は十分小さいので、`O(n^2)`または`O(n^3)`スタイル動的プログラミングはテスト セットごとに妥当ですが、注意が必要です。`n`テスト全体での値はわずか 500 です。つまり、およそ 500 を目指す必要があります。`O(n^2)`または全体的に優れています。 セグメント操作のすべてのシーケンスを明示的に列挙することは、実現不可能です。 

微妙なエッジケースは、ターゲット値が異なる方向に「キャリー」を強制する場合です。 たとえば、あるローターが小さな値を法とする多数の増分を必要とし、次のローターがほぼゼロを必要とする場合、セグメントを大幅に構造化する必要があるように見えるかもしれませんが、実際には値をラップアラウンドさせることで、いつでも過剰な増分を「元に戻す」ことができます。これは、モジュロ制約のみが重要であるためです。 ターゲットに直接一致するように常に増加する単純な貪欲さは、操作を過剰にカウントします。 

## アプローチ

 直接モデリングとは、各位置が全体で何回増加するかという観点から考えることです。 させて`x_i`位置をカバーする操作の合計数になります`i`。 次に、位置の最終値`i`単純に`x_i mod m_i`、操作ごとに 1 ずつ増加するためです。 

したがって、整数シーケンスを選択する必要があります`x`そのような`x_i ≡ b_i (mod m_i)`みんなのために`i`、そして私たちは構築したいと思っています`x`可能な限り少ないセグメントを使用したセグメント増分の合計として。 

次に、セグメント操作が何を行うかを解釈します。 各操作により次の値が追加されます。`1`連続した範囲にあるため、`x_i`インデックスをカバーするセグメントの数です`i`。 違いを見てみると`x_i - x_{i-1}`、この差が正になるたびに、その位置で新しいセグメントが開始されることに対応します。`i`、一方、負の差はセグメントの終了に対応します。 

この観点から見ると、操作の数は正確にセグメントを開始する合計回数であり、正の増分の合計に等しくなります。$$\text{cost} = \sum_{i=1}^{n} \max(0, x_i - x_{i-1})$$と`x_0 = 0`。 

問題は有効な代表者を選ぶことになる`x_i = b_i + k_i m_i`このコストを最小限に抑えるために。 各位置は独立して有効な値の無限の等差数列を可能にし、コストは連続する位置を結合します。 

ブルートフォースソリューションでは、それぞれの有効な選択肢をすべて試します。`x_i`、レイヤーごとに最大 500 の選択肢を持つ階層化された最短パスにつながります。 それは約`500 * 500 * 500`最悪の場合、移行が遅すぎます。 

重要な観察は、`x_i`不必要に大きい。 増えたら`x_i`必要以上に余分なセグメント開始を作成する場合がありますが、これは同じ残基クラスのより小さい代表を選択することで常に回避できます。 これにより、貪欲な遷移が可能になります。各位置で、有効な値を選択します。`x_i`可能な限り大きいですが、それを超えないものとします。`x_{i-1}`。 それが不可能な場合にのみ、上記の有効な最小値に移動します。`x_{i-1}`。 

これにより、問題は 1 つの左から右へのパスに軽減されます。

 ## アルゴリズムのチュートリアル

 達成可能な最良の値を維持しながら、配列を左から右に処理します。`x_{i-1}`。 

1.初期化`x_0 = 0`。 これは、最初の位置より前に増分が適用されていないことを表します。 
2. ポジションごとに`i`、剰余クラスを考慮します`b_i (mod m_i)`。 すべての有効な`x_i`次の形式でなければなりません`b_i + k * m_i`。 
3. 有効な最大値を選択してみてください。`x_i`それはまだ以下です`x_{i-1}`。 これは、サイズのフルステップ数を計算することによって行われます。`m_i`間にフィット`b_i`そして`x_{i-1}`、その後、それに応じて後退します。 そのような値が存在する場合、それを選択すると増加が回避されます`x_i`、この位置でのコストの支払いを回避します。 
4. 有効な最小値でも`b_i`より大きい`x_{i-1}`、そうすると増額せざるを得なくなります。 その場合は設定してください`x_i = b_i`そして増加費用を支払います`x_i - x_{i-1}`。 
5. いつでも総コストを累積する`x_i > x_{i-1}`、更新します`x_{i-1} = x_i`次の反復のために。 

### なぜ効果があるのか

 プロセスはシーケンスを構築します`x`これは、すべてのモジュール制約を満たしながら、連続する位置間の上向き遷移の数を最小限に抑えます。 どのようなソリューションも、各ステップで次のように変換できます。`i`、選ばれた`x_i`剰余を減算したもの`m_i`実行可能性を損なうことなく同じ剰余クラス内で、`x_i mod m_i`正確さが重要です。 実現可能な最大のものに注意を限定すると、`x_i ≤ x_{i-1}`将来の要件は、後で必要な正確な位置で増加することで満たされるため、増加を遅らせることは決して役に立ちません。 これは、成長を延期すると、セグメント開始の総数が厳密に削減または維持されるため、各ステップでの貪欲な選択が全体的に最適になることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        m = list(map(int, input().split()))
        b = list(map(int, input().split()))

        x_prev = 0
        ans = 0

        for i in range(n):
            mi = m[i]
            bi = b[i]
            r = bi

            if x_prev >= r:
                k = (x_prev - r) // mi
                x_i = r + k * mi
            else:
                x_i = r

            if x_i > x_prev:
                ans += x_i - x_prev

            x_prev = x_i

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは現在の可能な限り最良の状態を維持します`x_prev`、前のローターが効果的に増分された回数を表します。 新しいローターごとに、この値を超えない残基クラスの最良の代表値が計算されます。 分割ステップ`(x_prev - r) // mi`は、等差数列で実現可能な最良の値に直接ジャンプする重要な圧縮ステップです。 

コストは増加を余儀なくされた場合にのみ考慮されます`x_i`これは、新しいセグメントの開始に正確に対応します。

 ## 特殊なケース

 重大なエッジケースは、シーケンスによって構築されたデータが繰り返し強制的に減少する場合です。`x_i`。 たとえば、位置が前の値よりもはるかに小さい剰余クラスを許可する場合、アルゴリズムは以下の実現可能な最大の代表を選択します。`x_{i-1}`、コストが削減されゼロになります。 これにより、セグメントの開始を過剰にカウントすることがなくなります。 

もう 1 つのエッジケースは次のような場合です`b_i`いつも近くにある`m_i - 1`。 このような場合、アルゴリズムは繰り返し上向きにジャンプしますが、それは厳密に必要な場合のみです。各ジャンプは下に有効な代表が存在しない場合にのみトリガーされるためです。`x_{i-1}`。 これにより、誤って余分なセグメントが作成されるのを防ぎます。 

最後に、複数の位置でセグメントを再利用する機会がない場合、単一要素のケースにより正確性が保証されます。 アルゴリズムは、そのような各増加を新しいセグメントの開始として正しく処理し、最適な構成と一致します。
