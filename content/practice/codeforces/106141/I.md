 ## 解決策
 ## 問題の理解

 同じ長さの 2 つのシーケンスが与えられます。 1 つのシーケンスは n 日間にわたるモーティの成績を表し、もう 1 つは同じ日数にわたるリックの成績を表します。 各グレードは 0 ～ 5 の整数で、0 は欠席を意味する特別な値です。 

リックは自分のシーケンスを任意に並べ替えることができます。 並べ替えた後、モーティの i 日目とリックの i 日目を組み合わせます。 目標は、毎日、リックの成績がモーティの成績以上になるように、またはモーティがその日欠席したか、リックがその日欠席するように、リックが成績を調整できるかどうかを決定することです。 このような並べ替えが存在する場合、リックの成績の有効な順序を 1 つ出力する必要があります。 それ以外の場合は -1 を出力します。 

中心となる構造は、制約付きマッチング問題です。 各モーティ グレード a[i] は、a[i] が 0 でない限り、一致するリック グレード b[j] にしきい値要件を課します。a[i] が 0 の場合、制約はなくなります。 逆に、b[j] がゼロの場合、その位置は制約を満たすワイルドカードとして扱われるため、常に安全です。 

制約の値の範囲は 0 ～ 5 と小さいですが、テスト ケース全体で n は最大 3·10^5 になります。 これにより、テスト ケースごとにすべてのソリューションが線形または線形に近いものになります。 すべての順列のチェックや、ネストされたスキャンによる貪欲なマッチングを伴うものは、最悪の場合、遅すぎます。 

ゼロからは微妙なエッジケースが発生します。 モーティにはゼロ以外の成績が多数あるが、リックにはゼロが多数ある状況を考えてみましょう。 単純に貪欲なアプローチでは、誤ってゼロを割り当てるのが早すぎて、後でより高い制約がブロックされる可能性があります。 もう 1 つの失敗モードは、これを単純な並べ替え比較のように扱うことです。ゼロは条件の片側でのみ柔軟であり、位置の対称性が崩れるため、両方の配列を並べ替えて要素ごとに比較することは機能しません。 

たとえば、モーティが [5, 5, 5] でリックが [0, 4, 4] の場合、リックをソートすると [0, 4, 4] が得られ、不十分に見えますが、実際にはどの位置に対してもゼロを配置できます。 ただし、制約が不均等に分散されている場合、貪欲に 0 を間違って配置すると、実現可能性が損なわれる可能性があります。 

## アプローチ

 強引な解釈では、リックの成績のすべての順列を試し、条件を満たす順序があるかどうかを確認します。 これはすぐに「n!」につながります。 可能性があり、各チェックのコストは O(n) であるため、n が 10 ほど小さい場合でも完全に実行不可能になります。 

重要な観察は、モーティのシーケンスで重要なのは、少なくとも特定のしきい値を必要とする位置の数だけであるということです。 学年は 0 から 5 までしかないため、モーティの要件を学年レベルごとの数に圧縮できます。 同様に、Rick の成績は値ごとにグループ化できます。 

ここで、Rick の配列内の 1 つの値がどのように使用されるかを考えてみましょう。 グレード x は、要件 ≤ x のモーティ ポジションを満たすことができ、モーティ ゼロ ポジションで無駄になることもあります。 これは、最初にリックのグレードを最高の制約から最低の制約まで割り当てて、より難しい要件が早期に満たされるようにする必要があることを示唆しています。 

この問題は、6 つのバケットにわたるリソース割り当ての問題になります。 モーティのグレードを厳格さの昇順に処理し、それらをカバーするのに十分なリックのグレードが存在することを確認します。 Rick のゼロは普遍的なフィラーとして機能し、Morty のゼロは需要を完全に削除します。 

これにより、問題は、周波数バケットでの貪欲なマッチングによって実現可能性をチェックし、次に必要な場所に最初に大きな値を配置することによって明示的な割り当てを構築することに軽減されます。

 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 両方の配列の値 0 ～ 5 の頻度カウントを維持します。

1. モーティの配列とリックの配列に各グレードが何回出現するかを数えます。 これにより、問題はサイズ 6 の小さな固定状態空間に圧縮されます。 
2. モーティの位置を 2 つのグループに分割します。 a[i] が 0 である位置と、a[i] が 0 以外の位置です。 ゼロの位置は Rick にまったく制約を与えないため、後で残りの値を吸収します。 
3. 非ゼロの Morty グレードの場合、概念的に高グレードから低グレードまで制約を処理します。 リックからゼロを割り当てない限り、モーティ グレード x には少なくとも x のリック グレードが必要です。 
4. Rick グレードのカウントを通じてマルチセットのような構造を維持します。 私たちは常に、最初に利用可能な最大の Rick 値を使用して、最高の Morty 要件を満たすよう努めます。 これにより、ハード制約がカバーされないまま、簡単な制約で大きな Rick 値が無駄になるという状況が防止されます。 
5. 5 から 1 までの各モーティ グレードについて、正確または最小限の十分な一致を優先して、まだ有効な可能な最小のリック値と貪欲に一致させようとします。 より大きな値をすべて使用しても要件を満たすことができない場合は、不可能であると結論付けます。 
6. 非ゼロのモーティ要件をすべて満たした後、ゼロと未使用のグレードを含む残りのリック値は、モーティ ゼロの位置と残りのスロットに任意に配置されます。これらの位置には制約が課されないためです。 
7. 割り当てられた Rick 値を、マッチング フェーズ中に選択された元の順序位置に書き込むことによって、最終的な配列を構築します。 

### なぜ効果があるのか

 このアルゴリズムでは、最も強いものから優先する割り当て原則が適用されます。 ゼロ以外のモーティ要件はすべて、十分ではあるが不必要に大きくないリック グレードを消費し、より高い制約に対してより高いグレードを保持します。 評定は小さな境界領域に存在するため、より大きな可能性はすべてカウントですでに考慮されているため、要件を満たさない障害はその評定レベルを処理する時点で現れるはずです。 これにより、単調な実現可能性条件が与えられます。つまり、学年レベルが満たされなくなると、下位レベルの課題を再配置してもそれを修正できないということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        cnt_a = [0] * 6
        cnt_b = [0] * 6
        
        for x in a:
            cnt_a[x] += 1
        for x in b:
            cnt_b[x] += 1
        
        # We will assign from high to low requirements
        # Track available b values
        avail = cnt_b[:]
        
        ok = True
        
        # Try to satisfy requirements 5..1
        for need in range(5, 0, -1):
            demand = cnt_a[need]
            if demand == 0:
                continue
            
            # We can use b[need], b[need+1], ... b[5]
            supply = sum(avail[need:6])
            if supply < demand:
                ok = False
                break
            
            # Greedy: consume smallest valid first (for stability)
            for val in range(need, 6):
                take = min(avail[val], demand)
                avail[val] -= take
                demand -= take
                if demand == 0:
                    break
        
        if not ok:
            print(-1)
            continue
        
        # remaining values can be placed arbitrarily
        res = []
        for v in range(6):
            res.extend([v] * avail[v])
        
        print(*res)

if __name__ == "__main__":
    solve()
```解決策は、両方の配列を固定領域 0 ～ 5 の度数表に圧縮することから始まります。これにより、最初にすべての位置推論が削除され、リソース アカウンティングの問題に置き換えられます。 

次に、モーティのより厳格な成績を満たすことを最初にシミュレーションします。 要件レベルごとに、現在のバケットとそれ以上のバケットに十分な Rick グレードが存在することを確認します。 そうでない場合は、すぐに失敗します。 それ以外の場合は、将来のニーズに備えてより強力なグレードを保存するために、最初に最小の有効なバケットから消費します。 

最終的な再構成では、残りの未使用のリック グレードがすべて放出されるだけです。 すべての制約は割り当て中に適用されるため、残りの順序はすべて有効です。 

よくある実装の落とし穴は、Morty のゼロによって制約が完全に削除されることを忘れていることです。 このアプローチでは、ゼロを満たすことは決して試みられないため、ゼロは当然無視されます。 もう 1 つの微妙な点は、消費する前に上位のすべてのバケットの可用性を常に確認することです。そうしないと、時期尚早に消費すると偽陰性が発生する可能性があります。 

## 実用的な例

 ### 例 1

 モーティを [5、2、1、3、4]、リックを [1、2、3、4、5] と考えます。 

頻度テーブルを作成し、要件を 5 から下に処理します。 

| 必要 | 需要 | 利用可能 ≥ 必要 | アクション |
 | --- | --- | --- | --- |
 | 5 | 1 | 5 | 5を割り当てる |
 | 4 | 1 | 4 | 4を割り当てる |
 | 3 | 1 | 3 | 3を割り当てる |
 | 2 | 1 | 2 | 2を割り当てる |
 | 1 | 1 | 1 | 1を割り当てる |

 すべての要求は正確に満たされ、取り残しはありません。 

これは、各グレードが完全に一致し、貪欲な消費が将来の要件を妨げない、理想的なバランスの取れたケースを示しています。 

### 例 2

 モーティ: [3、2、1、0]

 リック: [2、3、4、1]

 モーティのゼロは無視します。 

最初にneed=3を処理します。 利用可能な {3,4} があるため、3 を割り当てます。 

次の need=2、残りは {1,2,4} なので、2 を割り当てます。 

次の必要性 = 1、残り {1,4}、1 を割り当てます。 

すべての制約を正常に満たし、残った 4 は任意の場所に配置されます。 

この例は、アルゴリズムがゼロ制約を自然に無視し、それでも有効な割り当てを完了する方法を示しています。

 ## 特殊なケース

 重要なエッジケースは、モーティが高いグレードしか持っておらず、リックが多くの低いグレードといくつかの高いグレードを持っている場合です。 たとえば、モーティは [5, 5, 5]、リックは [5, 1, 1] です。 このアルゴリズムは、最初に need=5 を処理し、単一の 5 を消費します。その後、5 以上の残りの供給がなくなるため、すぐに失敗します。 再配置によって追加の高グレードの一致を作成できないため、これは正しいです。 

もう 1 つのエッジ ケースは、[0, 0, 0, 5] のように、モーティの配列でゼロが優勢な場合です。 このアルゴリズムはゼロを完全に無視し、単一の厳密な要件の実現可能性のみをチェックして、すべての柔軟性が正しく活用されていることを確認します。 

最後のエッジ ケースは、Rick が 1 つの高い値を除いて完全に 0 で構成されている場合です。 アルゴリズムは、最初にその高い値を最も強い要件に正しく割り当て、ゼロ以外の追加の要求が存在する場合は残りを失敗として残します。
