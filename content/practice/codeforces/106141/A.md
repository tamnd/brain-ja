 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$いくつかのセルに石が含まれ、ちょうど 2 つの特別なセルにバナナが含まれるグリッド。 グリッドは単なる静止画ではありません。石は移動できますが、最大数までしか移動できません。$k$石は移動される可能性があり、$k \le 5$、これが重大な制限です。 

どの石を移動するかを選択した後、移動された各石は空のセルに再配置され、移動後に存在するすべての石がそのセルを「燃焼」し、それらのセルをグリッドから効果的に削除します。 残るのは、共有エッジによって接続された無傷のセルの集合です。 燃焼したセルが穴として機能するため、グリッドは複数の接続されたコンポーネントに分割される可能性があります。 

目標は、2 つのバナナ セルが燃焼後に残りのグリッドの同じ接続コンポーネントに確実に配置されるようにすることです。 せいぜい移動が許される$k$そのような構成を構築するか、不可能であることを報告する必要があります。 

接続は 4 方向であるため、斜めの隣接関係は役に立ちません。 これは、一見密なグリッド内でも多くの微妙な切断を引き起こすため、重要です。 

入力サイズは$n \le 1000$したがって、グリッドには最大$10^6$細胞。 しかし、$k \le 5$非常に小さいです。 これは、グリッドの状態を検索しているのではなく、非常に少数の「重大な変更」を検索していることをすぐに示唆しています。 

素朴な誤解は、任意の石が移動した後の接続性をシミュレートする必要があると考えることです。 それには、接続コンポーネントを繰り返し再計算する必要がありますが、これはすでに限界に達していますが、本当の問題ではありません。 本当の難しさは、石が_道を塞ぐ_ことができ、ブロック構造をわずかに調整することしか許可されていないことです。 

主なエッジケースは、何も動かなくてもバナナがすでに切断されている場合です。 たとえば、直線の廊下ですべての中間セルがブロックされており、次のような理由でそれを開けることができない場合、$k=0$、答えは即座に「いいえ」です。 

もう 1 つの微妙なケースは、バナナが隣接する斜めのセルにある場合です。```
1 0
0 1
```「視覚的に触れている」のに、つながっていない。 これは、接続が厳密に直交であることを思い出させます。 

最後に、重要なエッジ状態は、移動する石によってバナナを孤立させる新しい穴が生じるときです。 グローバルな接続性の維持を保証せずにリージョンを「接続」しようとするだけの不用意な戦略は、他の場所での構造を簡単に破壊する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、次のレベルに到達するためのあらゆる方法をシミュレートしようとします。$k$石を抽出し、結果として得られるグリッド内でバナナが接続されているかどうかを再計算します。 それぞれの選択肢について、最大$k$までの石$10^6$位置に応じて、宛先セルも選択します。 目的地の複雑さを無視しても、石を選択するだけですでに$\binom{10^6}{k}$、これはたとえ$k=2$。 

構成ごとの BFS ベースの接続チェックであっても費用がかかります$O(n^2)$, したがって、このアプローチはすぐに崩壊します。 

重要な観察は、$k$は小さいので、実際に 2 つのバナナの位置間の接続に関連する石の数を考慮する必要があります。 グリッド内のバナナ間の経路は、セルの狭い通路のみに依存します。 その通路がブロックされている場合は、いくつかのカットに沿った少数の重要な石によってブロックされます。 最大で 5 つの石を移動できるため、2 点間の小さな分離構造を排除する方法が存在するかどうかを実質的に尋ねていることになります。 

これにより、問題はブロックされたグリッドの限定された「修復」に変わります。つまり、最大まで変換できるグリッド内の 1 つのバナナから別のバナナへのパスを見つけようとします。$k$石を遠ざけることでブロックされたセルを空のセルに戻します。 石を移動するたびに 1 つのセルが解放され、別のセルが占有されますが、配置を制御し、バナナや再利用されたセルを避けるため、無関係な場所に石を配置できる限り、操作を「ブロックされた 1 つのセルを反転して解放する」ものとして扱うことができます。 

したがって、本質的な削減は次のとおりです。最大で変換することによって 2 つのバナナ セルを接続できるかどうかを判断します。$k$ブロックされた細胞を自由な細胞に変えます。 

これは、重み付けされた障害物解釈を備えたグリッド内の古典的な最短経路であり、空のセルに移動するコストは 0、石のセルに入るコストは 1 (それをクリアするには移動を費やす必要があるため) です。 2 つのバナナの位置間の 0 ～ 1 BFS 距離を効率的に計算しています。

 ## アルゴリズムのチュートリアル

 各セルをグリッド グラフのノードとしてモデル化します。 空のセルを通過する場合のコストは 0 で、石のセルを通過する場合のコストは 1 です。これは、その石を再配置してセルを通過可能にするために許可された移動を 1 回費やす必要があるためです。 

0 ～ 1 BFS を使用して、最初のバナナから 2 番目のバナナまでの最小コスト パスを計算します。 

1. 0 に設定されている開始バナナ セルを除く、すべてのセルに対して距離行列を無限大で初期化します。これは、開始点に立つために石の除去がゼロであることを表します。 
2. デキューを使用して 0-1 BFS を実行します。 開始セルを両端キューにプッシュします。 
3. デックが空ではない間に、前面からポップし、その 4 つの隣接をリラックスします。 移行コストは、隣接セルに元々石が含まれているかどうかによって異なります。 
4. 近隣が空の場合、同じコストでリラックスし、それをデックの前にプッシュしようとします。 石が入っている場合はコスト+1でリラックスして奥へ押し込みます。 この順序により、石の除去が少ないパスがより早く処理されるようになります。 
5. 到達可能なすべてのセルが処理されるか、2 番目のバナナに到達するまで続行します。 
6. 2 番目のバナナの計算された距離が超過した場合$k$、「いいえ」を出力します。 
7. それ以外の場合は、親ポインタを使用して 2 番目のバナナから最初のバナナに戻るパスを再構築します。 
8. この再構築されたパスに沿って、コスト 1 の遷移に寄与したセルを特定します。 これらは移動する必要がある結石細胞です。 
9. このような石のセルごとに、現在空であり、経路や禁止された位置の一部ではない目的地のセルを割り当てます。 以来$k \le 5$、十分に離れた空のセルに移動した石を貪欲に配置できます。 
10. 手のリストを出力します。 

### なぜ効果があるのか

 BFS 状態は、バナナ間に有効な通路を作成するために削除する必要がある石の最小数を正確にエンコードします。 有効な最終構成は、通過したすべてのストーン セルが最大 1 回クリアされたパスに対応します。 各移動で障害物が 1 つだけ除去され、移動した石は再利用されないため、BFS のコストは操作の数と一致します。 0-1 BFS の最適性により、ソリューションが存在するかどうかが保証されます。$k$移動しても、計算された距離は超えません$k$、再構築されたパスは、どの障害物を解決する必要があるかを直接特定します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

INF = 10**9

def solve():
    n, k = map(int, input().split())
    x1, y1 = map(int, input().split())
    x2, y2 = map(int, input().split())
    x1 -= 1; y1 -= 1
    x2 -= 1; y2 -= 1

    grid = [input().strip() for _ in range(n)]

    dist = [[INF] * n for _ in range(n)]
    parent = [[None] * n for _ in range(n)]

    dq = deque()
    dist[x1][y1] = 0
    dq.append((x1, y1))

    dirs = [(1,0), (-1,0), (0,1), (0,-1)]

    while dq:
        x, y = dq.popleft()
        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < n:
                cost = dist[x][y] + (grid[nx][ny] == '1')
                if cost < dist[nx][ny]:
                    dist[nx][ny] = cost
                    parent[nx][ny] = (x, y)
                    if grid[nx][ny] == '1':
                        dq.append((nx, ny))
                    else:
                        dq.appendleft((nx, ny))

    if dist[x2][y2] > k:
        print("No")
        return

    path = []
    cx, cy = x2, y2
    while (cx, cy) != (x1, y1):
        path.append((cx, cy))
        cx, cy = parent[cx][cy]
    path.append((x1, y1))
    path.reverse()

    path_set = set(path)

    moves = []
    used = [[False]*n for _ in range(n)]

    # collect stones on path
    stones = []
    for i in range(n):
        for j in range(n):
            if grid[i][j] == '1' and (i, j) in path_set:
                stones.append((i, j))

    # find free cells for placement
    free = []
    for i in range(n):
        for j in range(n):
            if grid[i][j] == '0' and (i, j) not in path_set:
                free.append((i, j))

    fi = 0
    for sx, sy in stones:
        fx, fy = sx, sy
        px, py = free[fi]
        fi += 1
        moves.append((fx+1, fy+1, px+1, py+1))

    print("Yes")
    print(len(moves))
    for a, b, c, d in moves:
        print(a, b, c, d)

if __name__ == "__main__":
    solve()
```BFS セクションは、コアとなる正確性エンジンです。 石に足を踏み入れる場合と空のセルに足を踏み入れる場合のコストの差は、デキュー順序付けで正確にエンコードされ、優先キューなしで最短パスの正確性が保証されます。 

再構成ステップは親ポインターに依存しており、これにより、距離値だけでなく実際に実行可能なコリドーが取得されることが保証されます。 その通路上にあるどのセルが石であるかを知ると、それらを除去する必要がある正確な障害物として扱います。 

配置戦略では、パス上にない任意の空きセルを使用します。 以来$k \le 5$、個別の空のセルを選択する限り、競合を回避する十分な柔軟性が常にあります。

 ## 特殊なケース

 重要なケースの 1 つは、石を無視してバナナがすでに同じ接続コンポーネント内にある場合です。 この状況では、石のセルに足を踏み入れないため、BFS 距離はゼロになります。 変更は必要なく、接続性はすでに満たされているため、アルゴリズムはゼロ手で「はい」を正しく出力します。 

もう 1 つのケースは、2 つの地域間の唯一の通路を 1 つの石がブロックしている場合です。 BFS パスは必然的にそのセルを通過し、コスト 1 に寄与します。再構成ステップにより、ブロックしているセルを正確に特定できるようになります。$k \ge 1$、パスを壊さずに別の場所に再配置できます。 

複数の最短パスが存在する場合、微妙なケースが発生します。 BFS はそれらのいずれかを選択できますが、コストはすべて最小限です。 すべての有効な最短パスは有効な最小セットの障害物に対応するため、再構築されたパスは移動するための正しい石のセットを生成します。
