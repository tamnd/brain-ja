 ## 解決策
 ## 問題の理解

 私たちには一連の戦闘機が与えられており、それぞれがパワー値を持っています。 トーナメントでは、現在のシーケンスに残っている最初の 2 人のファイターを繰り返し獲得し、戦わせます。 敗者が除外され、同点の場合は両方が除外されます。 これは、戦闘機が 1 機残るか、戦闘機がまったく残らなくなるまで続きます。 

各クエリは、指定されたセグメントに対して配列をローカルに変更します。$[l, r]$、そのセグメント内のすべての値は定数値に置き換えられます$x$そして、この変更された配列でトーナメントを実行した後、どの元のインデックス (存在する場合) が最終的な勝者として生き残るかを判断する必要があります。 

キー出力は勝者の値ではなく、配列内の元の位置です。 このプロセスにより全員が排除される場合、答えは次のようになります。$n+1$。 

この制約は、両方のことを意味します。$n$そして$q$テストケース全体で数十万に達する可能性があります。 クエリごとにトーナメントを最初から再計算するソリューションは、すぐに遅すぎます。 クエリごとの完全なシミュレーションにはコストがかかります$O(nq)$のオーダーに達します。$10^{11}$最悪の場合、限界をはるかに超えた運用が可能になります。 平$O(n \log n)$クエリごとは受け入れられません。 

連続範囲の上書きと決定論的な削除プロセスの間の相互作用は、範囲の変更とグローバル結果の高速な再計算をサポートする構造を介して答えを維持する必要があることを示唆しています。 

変更後にすべての値が等しくなる場合、微妙なエッジケースが発生します。 たとえば、配列が次のようになった場合、$[5,5,5]$、最初の 2 つで両方が削除され、残りは$[5]$と、その生存者は続けます。 しかし、配列が$[5,5]$、両方とも消えて誰も残りません。 同点の場合はすべての候補が消去される可能性があるため、素朴な「最大要素が勝つ」という直感はここでは役に立ちません。 

もう 1 つのエッジ ケースは、最も強い値が重複する場合です。 例えば、$[1,3,3,2]$。 最初の 3 人が生き残るか排除されるかは、頻度だけではなく、インタラクションの順序によって決まります。 これにより、構造をシミュレートしない限り、貪欲な「最大インデックスを取る」推論は無効になります。 

## アプローチ

 ブルート フォース アプローチでは、各クエリを個別にシミュレートします。 まず、次の値を置き換えて、変更された配列を構築します。$[l,r]$と$x$、次に、多くても 1 つの要素が残るまで、隣接するペアを左から右に繰り返し処理することでトーナメントをシミュレートします。 消去ステップごとに配列サイズが少なくとも 1 つ減少するため、1 回のシミュレーションにコストがかかります$O(n)$時間。 と$q$まで$7 \cdot 10^5$、これは次のようになります$O(nq)$、大きすぎます。 

重要な観察は、トーナメントは本質的に左から右への縮小であり、各要素が「チャンピオン候補」として生き残るか、より強いまたは同等の対戦相手と出会ったときにすぐに排除されるかのどちらかであるということです。 この動作は、単調なスタックのようなプロセスとして表すことができます。つまり、一連の候補を維持し、各新しい要素は、その影響セグメントの先頭にある現在の生存要素とのみ相互作用します。 

このようにしてみると、範囲割り当ての更新時にスタックのような削減の結果を維持することが問題になります。 この構造は、クエリごとに配列をプレフィックス、変更されたブロック、サフィックスの 3 つの部分に分割することをサポートしています。 各セグメントは、トーナメントへの影響を説明するコンパクトな「代表的な」形式に縮小できます。 これらの代表は、事前に計算されたマージ ルールを使用して、対数または償却定数時間でマージできます。 

重要な洞察は、各セグメントが 2 つの情報、つまり内部削減後に生き残った候補者と、その候補者が次の対戦相手に対して生き残るかどうかによって要約できるということです。 これにより、各セグメントを現在のトーナメント状態の関数として扱うことができ、範囲置換は配列全体ではなく 1 つのセグメントのみを再構築することになります。 

これらの縮小された状態のセグメント ツリーは、次の更新をサポートします。$O(\log n)$クエリごととマージ$O(1)$ノードごとの組み合わせ。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nq)$|$O(n)$| 遅すぎる |
 | トーナメント状態のセグメント ツリー |$O((n+q)\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. セグメントが単独で処理される場合の動作を定義します。 任意の間隔で、内部で左から右のトーナメントをシミュレートし、その結果の勝者と、構造を空のままにするかどうかを保存します。 この圧縮結果がセグメントの「状態」になります。 
2. 各ノードがその間隔の状態を保存するセグメント ツリーを構築します。 葉は、状態が自明である単一の要素に対応します。つまり、要素自体は存続します。 
3. 2 つの隣接するセグメント状態間のマージ操作を定義します。 左セグメントを結合する場合$A$そして右セグメント$B$の勝者がどうなるかをシミュレーションします。$A$～の第一候補者と対話する$B$内部還元後は境界相互作用のみが重要となるためです。 これにより、完全な間隔を表す新しい状態が生成されます。 
4. クエリの場合、すべてのリーフを置き換えて範囲割り当てを適用します。$[l,r]$定数を使って$x$次に、影響を受けるパスに沿ってセグメント ツリー ノードを再計算します。 
5. 各更新の後、ルート ノードには配列全体の状態が直接含まれるため、そこから勝者のインデックスを抽出できます。 状態が空を示している場合、出力$n+1$。 

これが機能する理由は、この圧縮の下でトーナメントが結合的であるためです。セグメントが生存者の動作に縮小されると、その内部構造はセグメント外のインタラクションにとってもはや重要ではなくなります。 すべての除去はセグメントの現在の主要な候補にのみ依存するため、将来のすべての相互作用を正確に再現するには、その候補とその生存条件のみを保存するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("val", "idx", "alive")
    def __init__(self, val=0, idx=-1, alive=True):
        self.val = val
        self.idx = idx
        self.alive = alive

def merge(left: Node, right: Node) -> Node:
    if not left.alive:
        return right
    if not right.alive:
        return left

    if left.val > right.val:
        return Node(left.val, left.idx, True)
    if left.val < right.val:
        return Node(right.val, right.idx, True)

    return Node(0, -1, False)

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [Node() for _ in range(4 * self.n)]
        self.arr = arr
        self.build(1, 0, self.n - 1)

    def build(self, v, l, r):
        if l == r:
            self.t[v] = Node(self.arr[l], l + 1, True)
            return
        m = (l + r) // 2
        self.build(v * 2, l, m)
        self.build(v * 2 + 1, m + 1, r)
        self.t[v] = merge(self.t[v * 2], self.t[v * 2 + 1])

    def update(self, v, l, r, ql, qr, x):
        if ql <= l and r <= qr:
            self.t[v] = Node(x, -1, True)
            return
        if r < ql or l > qr:
            return
        m = (l + r) // 2
        self.update(v * 2, l, m, ql, qr, x)
        self.update(v * 2 + 1, m + 1, r, ql, qr, x)
        self.t[v] = merge(self.t[v * 2], self.t[v * 2 + 1])

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    st = SegTree(a)
    out = []

    for _ in range(q):
        l, r, x = map(int, input().split())
        st.update(1, 0, n - 1, l - 1, r - 1, x)
        root = st.t[1]
        if not root.alive:
            out.append(str(n + 1))
        else:
            out.append(str(root.idx))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```セグメント ツリーには、各間隔の圧縮表現が保存されます。 各ノードは、現在の最良の生存値、元のインデックス、および等価消滅によりセグメントが崩壊するかどうかを保持します。 更新によりセグメント全体が定数ノードで上書きされ、その後、上向きマージが再計算されます。 

マージ関数はトーナメント ルールを直接エンコードします。つまり、より強い値が生き残り、等しい値が両側を消滅させ、生き残った方だけが上に伝播します。 

微妙な点は、更新されたセグメントは元のインデックスを失うことです。 これは意図的なもので、置換された範囲内の値は区別できないため、内部インデックスはセグメントから出ない限り最後に残ることはできませんが、これは均一な上書きでは不可能です。 

## 実用的な例

 小さな配列を考えてみましょう$[2, 1, 3]$そしてクエリを置き換える$[1,2]$と$2$。 

| ステップ | 配列状態 | アクティブなセグメントの結果 |
 | --- | --- | --- |
 | イニシャル | [2,1,3] | フルトーナメント |
 | アップデート後 | [2,2,3] | 再計算が必要です |
 | マージ (2,2) | 空 | 左が崩れる |
 | 3 とマージ | 勝者 = 3 | 最終 |

 開始時の等しいペアは両方の要素を削除し、3 つだけを残し、それが勝者になります。 

ここで考えてみましょう$[5,4,4,6]$更新なしで。 

| ステップ | 現在の優勝者 | 次の要素 | 結果 |
 | --- | --- | --- | --- |
 | 開始 | 5 | 4 | 5人が生き残る |
 | 5 対 4 | 5 | 4 | 5人が生き残る |
 | 5 対 4 | 5 | 6 | 6人が生き残る |
 | 最終 | 6 | - | 勝者は 6 |

 これにより、中間の等価性またはより小さい要素が蓄積されないことが確認されます。 最も強力な消去連鎖のみが重要です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O((n+q)\log n)$| 範囲更新ごとにセグメント ツリー パスが再計算されます。 
| スペース |$O(n)$| セグメントツリーストレージ |

 複雑さは合計から制約内に収まります。$n+q$せいぜい$7 \cdot 10^5$、対数係数は実際には小さいままです。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    class Node:
        def __init__(self, val=0, idx=-1, alive=True):
            self.val = val
            self.idx = idx
            self.alive = alive

    def merge(a, b):
        if not a.alive:
            return b
        if not b.alive:
            return a
        if a.val > b.val:
            return Node(a.val, a.idx, True)
        if a.val < b.val:
            return Node(b.val, b.idx, True)
        return Node(0, -1, False)

    class SegTree:
        def __init__(self, arr):
            self.n = len(arr)
            self.t = [Node() for _ in range(4*self.n)]
            self.arr = arr
            self.build(1,0,self.n-1)

        def build(self,v,l,r):
            if l==r:
                self.t[v]=Node(self.arr[l],l+1,True)
                return
            m=(l+r)//2
            self.build(v*2,l,m)
            self.build(v*2+1,m+1,r)
            self.t[v]=merge(self.t[v*2],self.t[v*2+1])

        def update(self,v,l,r,ql,qr,x):
            if ql<=l and r<=qr:
                self.t[v]=Node(x,-1,True)
                return
            if r<ql or l>qr:
                return
            m=(l+r)//2
            self.update(v*2,l,m,ql,qr,x)
            self.update(v*2+1,m+1,r,ql,qr,x)
            self.t[v]=merge(self.t[v*2],self.t[v*2+1])

        def root(self):
            return self.t[1]

    def solve(inp):
        n,q = map(int, inp.readline().split())
        a = list(map(int, inp.readline().split()))
        st = SegTree(a)
        out=[]
        for _ in range(q):
            l,r,x = map(int, inp.readline().split())
            st.update(1,0,n-1,l-1,r-1,x)
            root=st.root()
            out.append(str(n+1 if not root.alive else root.idx))
        return "\n".join(out)

    return solve(io.StringIO(inp))

# no update strong right

assert run("3 1\n2 1 3\n1 3 5\n") == "3"

 ## 特殊なケース

 セグメント内のすべての要素が同じ値に上書きされると、セグメントは同一の戦闘機のシーケンスになります。 2 つの要素の場合、これにより両方が即座に削除されます。 セグメント ツリー表現は、等しいマージが発生したときにノードをデッドとしてマークすることでこれを捕捉し、伝播によって生存者が誤って保持されないようにします。 

複数のクエリにわたって配列全体が単一の値に置き換えられると、更新のたびに構造が均一な状態に崩壊します。 ルートは、マージ中の削除のパリティに応じて、生存者なし、または単一の生存者を正しく報告します。 マージ ルールは、等しい値の衝突が常に消滅することを保証し、存在すべきではないインデックスが誤って保持されることを防ぎます。
