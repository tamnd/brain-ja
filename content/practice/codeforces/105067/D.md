 ## 解決策
 ## 問題の理解

 数値の配列が与えられ、各数値はパンダのラベルを表します。 個別のインデックスの順序付きペアの場合$(i, j)$、次のように書くことで新しい数を形成します$x_i$直接続いて$x_j$。 その連結した数値が固定の整数で割り切れる場合$K$、ペアは成功したとみなされます。 で割り切れる連結を生成する順序ペアの数を数えなければなりません。$K$。 

問題は、連結が前処理なしでモジュラー演算に直接組み込める算術演算ではないことです。 値は、次の両方の数値に依存します。$x_i$と桁数$x_j$、これにより、構造とモジュラー演算の間に結合が導入されます。 

制約が私たちを$O(N \log N)$または$O(N \sqrt{N})$最悪の場合、テストごとに。 以来$N$到達できる$10^5$複数のテストにわたる二次方程式$O(N^2)$ペアの列挙は、最大で次の時間が必要となるため、直ちに実行不可能です。$10^{10}$連結。 

値の繰り返しや桁長の衝突によって、微妙なエッジ ケースが発生します。 たとえば、すべての数値が 1 桁の場合、連結は次のような単純な算術になります。$10a + b$ただし、桁の長さが異なる場合、桁の長さが正しく処理されないと、単純なモジュラー推論が静かに機能しなくなる可能性があります。 次の場合には別の問題が発生します。$K = 1$、すべてのペアが有効です。 どのような解決策であっても、このケースを複雑にしすぎてはなりません。 

## アプローチ

 ブルートフォースソリューションは、順序付けられたすべてのペアを反復処理します。$(i, j)$、整数を連結し、次の方法で割り切れるかどうかを確認します。$K$。 これは定義に直接従っているため、正しいです。 ただし、各連結では桁シフトとモジュラー チェックを計算する必要があり、これを次のように実行します。$N^2$ペアは約につながります$10^{10}$実行可能な限界をはるかに超えた最悪の場合の操作。 

重要な観察は、桁構造を分離すると、連結をモジュラー算術で表現できるということです。 もし$len(x)$の桁数です$x$、 それから$$concat(x_i, x_j) = x_i \cdot 10^{len(x_j)} + x_j$$この値のモジュロのみを考慮します$K$。 これは、10 モジュロの前処理能力を示唆しています。$K$、数値を桁の長さでグループ化します。 

最大の難点は、桁の長さが最大 ​​10 になる可能性があることです。$x_i \le 10^9$。 これは、可能な長さは最大 10 個しかないことを意味します。 この制限により、ソリューションが効率的になります。すべてのペアを個別に処理するのではなく、桁長のクラスによってのみ相互作用を分離します。 

各数値について、剰余を事前計算します。$K$、およびその桁長。 それから固定用に$i$、および選択した桁の長さ$L$、その数を知る必要があります。$j$次のように存在します。$$(x_i \cdot 10^L + x_j) \bmod K = 0$$並べ替えると次のようになります。$$x_j \bmod K = (-x_i \cdot 10^L) \bmod K$$したがって、それぞれの長さに対して$L$、その長さの数値間の剰余の頻度マップを維持します。 それからそれぞれ$i$一定時間内に 10 個の可能な長さのバケットをクエリできます。 

これにより、ペアの列挙の問題が要素ごとに数回のハッシュ テーブル検索に軽減されます。

 ## アルゴリズムのチュートリアル

 1. すべての桁数を計算します。$x_i$。 これが必要なのは、連結が完全に 10 のべき乗による桁の長さに依存するためです。 
2. コンピューティング$x_i \bmod K$あらゆる要素に対して。 作業モジュロ$K$値が境界を維持し、割り算チェックの下で比較できることを保証します。 
3. 事前計算$10^L \bmod K$可能なすべての桁長に対して$L$これにより、べき乗を再計算することなく、連結効果を高速に再構築できます。 
4. 桁長ごとにグループ化された度数表を作成します。 それぞれの長さごとに$L$、残りの数値がいくつあるかを数えるハッシュ マップまたは辞書を保存します。$r$。 この構造により、一致する剰余に対する定数時間クエリが可能になります。 
5. 各インデックスについて$i$、すべての可能な桁長を反復します。$L$。 必要な剰余を計算します。$$target = (-x_i \cdot 10^L) \bmod K$$次に、長さの要素の数を追加します。$L$残りが等しいバケット$target$。 これはすべて有効なものをカウントします$j$これが修正されたために$i$そして長さの制約。 
6. 無効なケースを減算します。$i = j$。 これは次の場合にのみ必要です$x_i$順序付きペアをカウントしていますが、同一のインデックスは除外しているため、それ自体は一致するバケット内にあり、同じ条件を満たします。 

### なぜ効果があるのか

 すべての連結は、10 のべき乗でスケールされたプレフィックス寄与とサフィックス寄与にきれいに分割されます。 モジュラー条件により、問題は、事前に計算された定数による乗算下での相補的な残基のマッチングに軽減されます。 桁の長さは少数の一定数の値のみを取るため、完全な検索空間は、制限された数の独立した残基マッチング問題に分解されます。 有効な各ペアは、対応する桁長のバケットと剰余の一致を通じて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        N, K = map(int, input().split())
        arr = list(map(int, input().split()))
        
        # special case: K = 1, every ordered pair works except i == j
        if K == 1:
            print(N * (N - 1))
            continue
        
        # precompute powers of 10 mod K for lengths up to 10
        pow10 = [1] * 11
        for i in range(1, 11):
            pow10[i] = (pow10[i - 1] * 10) % K
        
        def digits(x):
            return len(str(x))
        
        # bucket[length][remainder] = frequency
        buckets = [dict() for _ in range(11)]
        
        info = []
        for x in arr:
            d = digits(x)
            r = x % K
            info.append((x, d, r))
            buckets[d][r] = buckets[d].get(r, 0) + 1
        
        ans = 0
        
        for x, d_x, r_x in info:
            for L in range(1, 11):
                target = (-r_x * pow10[L]) % K
                ans += buckets[L].get(target, 0)
            
            # remove self-pair if it was counted
            # self-pair happens only when concatenating with itself is valid,
            # and we counted (i, i) once per length bucket
            Lx = d_x
            concat_self = (r_x * pow10[Lx] + r_x) % K
            if concat_self == 0:
                ans -= 1
        
        print(ans)

if __name__ == "__main__":
    solve()

の`pow10`配列は、連結時の左オペランドを桁長でスケールする方法をエンコードします。 長さは 10 で制限されているため、この前処理は継続的な作業となります。 

各数値は、桁長と剰余モジュロとともに保存されます。$K$。 バケット構造は数値を桁長ごとにグループ化するため、候補の左オペランドを修正するときに、長さの制約が一致する互換性のあるすべての右オペランドを直接クエリできます。 

内側のループの長さは定数で制限されているため、各要素は最大 10 回のルックアップに寄与し、全体的に線形の動作が得られます。 

自己除去ステップにより、過剰カウントが修正されます。$(i, i)$、それ以外の場合は、数値がそれ自身のバケット内でそれ自体とペアになるときに含まれます。 

## 実用的な例

 3 つの数値を含む入力を考えてみましょう。$K = 11$ここでは、割り切れる連結を形成する順序付きペアが必要です。 

配列を次のようにします$[1, 2, 4]$。 

桁の長さと余りを計算します。 

| × | レン | x mod 11 |
 | --- | --- | --- |
 | 1 | 1 | 1 |
 | 2 | 1 | 2 |
 | 4 | 1 | 4 |

 すべての数値は長さ 1 を共有するため、連結は次のように動作します。$10a + b$。 

それぞれについて$i$、どれをチェックしますか$j$満足する$10x_i + x_j \equiv 0 \pmod{11}$。 

のために$i = 1$、必要です$10 + x_j \equiv 0 \Rightarrow x_j \equiv 1$。 それで$j = 1$, ただしセルフペアは除外されるので寄与なし。 

のために$i = 2$、必要です$20 + x_j \equiv 0 \Rightarrow 9 + x_j \equiv 0 \Rightarrow x_j \equiv 2$。 それで$j = 2$、また除外されました。 

のために$i = 4$、必要です$40 + x_j \equiv 0 \Rightarrow 7 + x_j \equiv 0 \Rightarrow x_j \equiv 4$。 それで$j = 4$、除外されます。 

これは、自己ペアが度数表に自然に表示される場合でも、慎重に削除する必要がある理由を示しています。 

次に、混合長の例を考えてみましょう。$[12, 3]$、$K = 5$。 

ここでは桁の長さが異なるため、両方を考慮する必要があります$L=1$そして$L=2$。 このソリューションは両方の連結形式を正しく評価します。$12|3 = 123$そして$3|12 = 312$、それぞれは事前に計算された 10 のべき乗を介して独立してモジュロ 5 をチェックしました。 

バケットを分離することで、これらが誤って混合されることがなくなります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    # re-implement solve inline for testing
    def solve():
        T = int(input())
        out = []
        for _ in range(T):
            N, K = map(int, input().split())
            arr = list(map(int, input().split()))
            if K == 1:
                out.append(str(N * (N - 1)))

 ## 特殊なケース

 厄介な状況となるのは、$K = 1$。 すべての連結は割り切れるため、すべての順序付きペア$(i, j)$と$i \ne j$有効です。 アルゴリズムはこれを次の式で直接処理します。$N(N-1)$、誤った自己削除動作を引き起こす可能性のある不必要なモジュールロジックを回避します。 

もう 1 つの微妙なケースは、すべての数値が同一である場合です。 例えば、$[11, 11, 11]$と$K = 11$。 すべての連結で同じ構造が生成されるため、順序付けられたペアのすべてが有効であるか、いずれも有効ではありません。 バケット手法は、同一の剰余を正しく集計し、最後の減算では対角線のペアのみを削除するため、引き続き機能します。 

最後のエッジケースは、次のように桁の長さが大きく異なる場合に発生します。$[1, 10, 100, 1000]$。 解の正しさは、10 のべき乗が適切に揃うように桁の長さで厳密に区切ることに依存します。 この分離がなければ、次のような連結が行われます。$1|100$そして$1|10$スケーリング係数を誤って共有し、誤ったモジュラー比較を生成します。
