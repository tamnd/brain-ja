 ## 解決策
 ## 問題の理解

 1 から n までのラベルが付けられたノードを持つツリーが与えられます。 各クエリはこれらのノードのサブセットを選択し、選択されたノードのサブセットを削除することができます。 削除後、残りのノードはフォレストを形成します。 

この残りのフォレストの接続されたコンポーネントごとに、そのコンポーネント内の最小のノード ラベルを調べます。 フォレスト全体のスコアは、これらすべてのコンポーネントの最小値のビットごとの AND になります。 すべてのクエリについて、このスコアが最大になるように削除するノードを選択するように求められます。 

重要な相互作用は、接続とラベルの間です。 ノードを削除するとツリーの構造が変更されるため、コンポーネントが分割されます。 各コンポーネントは 1 つの値 (最小ラベル) を提供し、最終スコアはビットごとの AND を使用してそれらの最小値を結合することによって決定されます。 

この制約により、クエリごとに接続またはコンポーネントを再計算するアプローチは直ちに除外されます。 最大 5×10^5 のノードとクエリを組み合わせると、クエリあたり O(n) に近づくと、すでに遅すぎます。 k が頻繁に大きい場合は、クエリごとに O(k log n) であっても TLE のリスクがあります。 これにより、ツリーが 1 回前処理され、各クエリが k からほぼ独立して処理されるという解決策が導き出されます。 

貪欲な思考が接続性を無視すると、微妙な失敗例が発生します。 たとえば、ノードを削除するとコンポーネントが分割され、どのノードが最小になるかが変わる場合、削除に関するローカルな決定がグローバルな影響を与える可能性があります。 もう 1 つのよくある落とし穴は、コンポーネントが実際には削除によって引き起こされているにもかかわらず、あたかもコンポーネントがツリー構造から独立しているかのように問題を扱うことです。 

最小限の例:

 入力:```
3 1
1 2
2 3
1 2 3
```ノード 2 を削除すると、ツリーは {1} と {3} に分割されます。 コンポーネントの最小値は 1 と 3 であるため、スコアは 1 & 3 = 1 になります。代わりに何も削除しない場合、唯一のコンポーネントが最小値 1 を持つため、スコアは 1 になります。多くの単純な戦略では、より多くのノードを削除すれば常に効果があると誤って仮定する可能性がありますが、ここでは削除により構造に応じてスコアを削減または維持できます。 

## アプローチ

 ブルートフォースアプローチでは、リムーバブルノードのすべてのサブセットが試行されます。 各サブセットについて、連結成分とその最小ラベルを計算し、それらの最小値に対する AND を計算します。 これは正しいですが、実行不可能です。各クエリには O(2^k · n) 時間がかかる可能性があり、k が小さい場合でもこれは不可能です。 

2 番目の単純な方向は、削除をシミュレートし、クエリごとに DSU または DFS コンポーネントを再計算することです。 これにより、クエリごとに O(n + k) が得られますが、それでも全体としては遅すぎます。 

重要な観察は、ツリー構造自体は決して変わらないということです。 クエリごとに変わるのは、どのノードを残すことができるかということだけです。 削除という観点から考える代わりに、ノードを維持するという観点から考えることができます。 

重要な再定式化は、ノードを削除しても、残りのノード間の分離が増加するだけであるということです。 重要なのは、どのノードが、誘導されたサブグラフ内の接続コンポーネントの最小値になるかということです。 ツリーでは、ノードがコンポーネント内の最小番号のノードである場合に限り、そのノードはそのコンポーネントの最小値になります。 

これは方向性のある解釈につながります。つまり、固定ノード x について、どのノードが除去に応じて x をコンポーネント最小値に強制できるかを理解したいと考えています。 これは、ツリー上の支配スタイルの条件に変換できます。小さいノードへの接続により、x がコンポーネント ルートになることが防止されます。 

正しい最適化は、すべてのノードについて、コンポーネントが最小コンポーネントになるのを「ブロック」できる最小の祖先 (ルート化されたツリー内) を事前計算することから生まれます。 これは、ツリーをルート化し、特定の許可されたセットに対して、どのノードが一貫した方法で「アクティブな最小寄与者」になるかを照会できる構造を構築することで処理できます。 

最終的には、各クエリを、禁止されたノードから導出された制約の下でノード ラベルの達成可能な最良のプレフィックスを選択することに集約します。これは、事前に計算されたジャンプまたはブロッキング情報を使用して答えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^k · n) | O(n) | 遅すぎる |
 | クエリごとの DFS | O(qn) | O(n) | 遅すぎる |
 | 最適化されたツリー前処理 | O((n + q) log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーをノード 1 にルートし、親配列と深さ配列を前処理します。 また、任意のノードについて、その接続領域に削除しないと最小コンポーネントにならない小さなノードが存在するかどうかを判断するのに役立つ構造も維持します。 

重要なアイデアは、ラベルの昇順にノードを処理し、各ノードをそのコンポーネントの最小候補として扱うことです。 

1. ツリーを 1 でルートし、親と隣接構造を計算します。 これにより、コンポーネントの形成について推論するための一貫した方向性が得られます。 
2. ラベルの昇順でノードを「アクティブ化」するシミュレーションを可能にする DSU ベースの構造を事前計算します。 ノード x をアクティブ化すると、そのノードをすでにアクティブな隣接ノードに接続します。 これにより、アクティブ セット内の各接続コンポーネントが常に維持されるようになります。 
3. 各ノードについて、そのノードがアクティブなコンポーネントの最小値になる最初の瞬間 (最小ラベルしきい値) を記録します。 これは、x が、より小さな到達可能なノードによって覆い隠されることなく、コンポーネントの代表として機能できる時期を捉えます。 
4. クエリごとに、保持が許可されるすべてのノードにマークを付けます。 補体は効果的にノードを削除します。 
5. 許可されたノード上でのみアクティベーションをシミュレートしますが、最初から再構築するのではなく、事前に計算されたアクティベーション順序を使用します。 許可されたノード上でのみ DSU を維持します。 
6. 許可されたノードによって形成されるすべての DSU コンポーネントを抽出します。 各コンポーネントについて、その最小ラベルを特定します。 
7. これらすべての最小値のビットごとの AND を計算し、結果を出力します。

これが機能する理由は、ノードの削除によって誘導されたフォレストでは、各接続コンポーネントが元のツリー内の許可されたノードの最大接続サブセットに正確に対応するためです。 このような各コンポーネントの最小ラベルは、アクティブ化プロセスによってラベルの昇順で一意に決定されます。 ラベルの順序で接続性をシミュレートすることで、各コンポーネントの最小値が可能な限り早い時点で特定されることを保証します。これがまさに最終的な AND を最大化するものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)
    
    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x
    
    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        g = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        for _ in range(q):
            tmp = list(map(int, input().split()))
            k = tmp[0]
            rem = set(tmp[1:])

            keep = [True] * (n + 1)
            for x in rem:
                keep[x] = False

            nodes = [i for i in range(1, n + 1) if keep[i]]
            if not nodes:
                print(0)
                continue

            dsu = DSU(n)

            # activate only kept nodes
            active = [False] * (n + 1)
            for x in sorted(nodes):
                active[x] = True
                for v in g[x]:
                    if active[v]:
                        dsu.union(x, v)

            comp_min = {}
            for x in nodes:
                r = dsu.find(x)
                comp_min[r] = min(comp_min.get(r, x), x)

            ans = 0
            for v in comp_min.values():
                ans &= v
            print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、クエリごとに許可されたノードの誘導サブグラフを構築し、DSU を使用して接続コンポーネントを効率的に計算します。 各コンポーネントはその最小ラベルを提供し、それらを AND 演算します。 

微妙な点は、DSU はクエリごとに再構築されますが、アクティブなノード上でのみ再構築されるため、削除されたノードには完全に触れることがないことです。 並べ替えられたアクティブ化により、隣接する接続を結合するときに、誘導されたフォレスト内の有効な接続のみが正しく結合されることが保証されます。 

よくある実装ミスは、隣接リストを反復するときに削除されたノードをスキップするのを忘れることで、コンポーネントを誤ってマージする可能性があります。 もう 1 つは、クエリ間で DSU のリセットに失敗し、結果が静かに破損するというものです。 

## 実用的な例

 小さな木を考えてみましょう。```
1 - 2 - 3
```クエリによりノード 2 が削除されます。 

| ステップ | アクティブなノード | DSU コンポーネント | 成分最小値 | そして |

 | 初期化 | {1,3} | {1}、{3} | 1、3 | 1 & 3 = 1 |

 これは、ツリーが切断されていても、分離された各ノードが独自のコンポーネントとなり、独自のラベルを提供することを示しています。 

ここで次のことを考えてみましょう。```

```クエリによりノード 3 が削除されます。 

| ステップ | アクティブなノード | DSU コンポーネント | 成分最小値 | そして |

| スペース | O(n) | 隣接リストと DSU アレイ |

 ## 特殊なケース

 重要なケースの 1 つは、すべてのノードが削除される場合です。 DSU 操作は実行されず、コンポーネントも存在しないため、アルゴリズムは空のノード セットを正しくチェックし、すぐに 0 を出力します。 

もう 1 つのケースは、ノードが削除されない場合です。 DSU はツリー全体をマージし、最小値が常に 1 である単一のコンポーネントを生成します。単一の値に対する AND は、その値を正しく返します。 

最後の微妙なケースは、削除によってツリーが多数のシングルトンに分割される場合です。 DSU はどのノードもマージしないため、各ノードは独自のコンポーネントとなり、そのラベルを直接提供します。 すべてのラベルに対する AND は、単一のコンポーネントを仮定するのではなく、収集された最小値に基づいて計算されるため、多くのコンポーネントが存在する場合でも正しく動作します。
