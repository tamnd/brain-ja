 ## 解決策
 ## 問題の理解

 入力内の各項目はトッピングを表します。 トッピングには値があり、別のトッピング インデックスを指す単一の制限も含まれます。 最終選択にトッピング i を含めることに決めた場合、トッピング b_i を一緒に表示することはできなくなります。 

タスクは、そのような制限をすべて尊重しながら、値の合計を最大化するトッピングのサブセットを選択することです。 すべての制限は入力では一方向ですが、最終的に選択されたセットに対する相互排他ルールとして機能します。つまり、i を取得すると、b_i を強制的に除外することになります。 

この構造は、任意のペアごとの競合ではありません。 各インデックスは、禁止されたパートナーを 1 つだけ生成します。つまり、すべての要素には最大 1 つの出力制約があります。 この詳細により、このスケールではグラフ構造が扱いにくい一般的な最大重み独立集合とは問題の動作が異なります。 

n が 100000 までの場合、サブセットを列挙したり、組み合わせの選択肢をシミュレートしようとするソリューションは直ちに範囲外になります。 O(n²) 個の交互作用でさえ大きすぎるため、サブセットごとの実行可能性の再計算を伴うものはすべて除外されます。 唯一の実行可能な解決策は、項目を並べ替えて貪欲に処理するか、制約グラフの機能的性質を利用するかのいずれかです。 

いくつかの状況は、素朴に対処すると間違いやすいものです。 1 つは、制限が対称であると仮定することです。 i が j を禁止しても、他の場所で明示的に記載されていない限り、j が i を禁止することを意味するものではありません。 たとえば、1 が 2 を禁止するが、2 が何も禁止しない場合、2 のみを選択することは常に有効であり、1 を選択すると 2 が強制的に除外されますが、その逆は当てはまりません。 

もう 1 つの微妙なケースは連鎖です。 1 が 2 を禁止し、2 が 3 を禁止する場合、1 を選択すると 2 が削除されますが、2 も選択されない限り、3 の削除は自動的に強制されません。 貪欲な戦略では、これを誤って推移閉包問題として扱うことを避ける必要があります。 

最後の落とし穴は、これがサイクルを打破する問題だと考えることです。 1 は 2 を禁止、2 は 3 を禁止、3 は 1 を禁止といったサイクルが存在する場合でも、制約は選択したノードから外側に向かってのみアクティブ化されるため、その構造は標準的な無向競合グラフではありません。 

## アプローチ

 直接的な強引なアプローチでは、トッピングのすべてのサブセットを試し、選択されたすべての i に禁止されている b_i が含まれていないかどうかを確認し、合計を計算します。 これは正しいですが、2^n 個のサブセットを反復する必要があり、各サブセットをチェックするだけでも O(n) のコストがかかるため、O(n・2^n) となり、n が約 25 を超えるとすぐに不可能になります。 

重要な観察は、制約の非対称性と希薄さから得られます。 各項目は他の項目を 1 つだけ禁止します。つまり、項目を選択すると、将来の検討対象から最大 1 つの候補が除外されるという 1 つの即時的な結果が生じます。 これにより、決定は局所的には破壊的ですが、全体的には簡単になります。 

アイテムが値の降順に並べ替えられると、貪欲な戦略が自然になります。 項目を処理するときに、以前に選択した項目によってその項目がまだ削除されていない場合、その項目を選択しても常に安全であり、他の 1 つの項目のみが無効になります。 私たちは常により価値の高いアイテムを最初に優先するため、後で選択しても、選択したより価値の高いアイテムを置き換えることによって合計を遡及的に改善することはできません。 

この構造は、利用可能なアイテムのセットを維持し、利用可能な最良のものを繰り返し選択することと同等であり、各選択により最大 1 つの追加ノードが削除されます。 削除は項目を再導入することはなく、選択順序による場合を除いてカスケードすることもないため、貪欲な順序付けで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・2^n) | O(n) | 遅すぎる |
 | 貪欲な値による並べ替え | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 問題を、値によってソートされた項目に対するプロセスに変換します。

1. すべてのトッピングを価格の降順に並べ替えます。 これにより、残っている最も収益性の高い選択肢を常に最初に検討することが保証されます。これは、価値の低いアイテムを選択すると、価値の高いアイテムを失っても補うことができないため、非常に重要です。 
2. 2 つのブール配列を維持します。 項目がすでに選択されているかどうかを記録します。 もう 1 つは、以前に選択したアイテムによってアイテムが無効化されたかどうかを記録します。 
3. ソートされたリストを繰り返し処理します。 各項目 i について、すでに無効化されている場合は、それを含めると以前にコミットされた決定に違反するため、スキップします。 
4. i がまだ有効な場合は、それを選択し、その値を答えに追加します。 
5. i を選択すると b_i が現在のソリューションと互換性がなくなるため、b_i を直ちに無効にします。 b_i がすでに選択されている場合、b_i が処理される前にこのステップは回避されるため、一貫性が保たれます。 
6. すべての項目が処理されるまで続行します。 

この順序により、2 つの項目間に競合が存在する場合は常に、値の高い方が最初に考慮されるようになります。 方向に応じて、低い値の方がスキップまたは削除されます。 

### なぜ効果があるのか

 不変条件は、あるしきい値より大きい値を持つすべてのアイテムを処理した後、現在選択されているセットが、それらの高価値アイテムに限定されたすべてのサブセットの中で最適であるということです。 処理中に削除されたアイテムは、より高い価値のアイテムが明示的に禁止しているため、削除されます。 削除された項目は後でソート順に厳密に処理されるため、より価値の高い項目を削除された項目と置き換えても、合計が増加することはありません。 これにより、すべての決定がローカルで最適であり、グローバルに一貫していることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [0] * (n + 1)
    b = [0] * (n + 1)

    items = []
    for i in range(1, n + 1):
        ai, bi = map(int, input().split())
        a[i] = ai
        b[i] = bi
        items.append((ai, i))

    items.sort(reverse=True)

    taken = [False] * (n + 1)
    banned = [False] * (n + 1)

    ans = 0

    for _, i in items:
        if banned[i]:
            continue
        ans += a[i]
        taken[i] = True
        bi = b[i]
        banned[bi] = True

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初にすべての項目を読み取り、値によって並べ替えます。これにより、決定は常に利益の降順で行われます。 の`banned`配列は重要な構造です。以前に選択された項目によって既に除外されているために取得できない項目を記録します。 

の`taken`配列は、この特定のグリーディの正確性のために厳密には必要ありませんが、ロジックを明示的にし、後で禁止された項目を選択しようとした場合に競合が発生するかどうかを推論するのに役立ちます。 キー操作はマーキングです`b_i`選択時に禁止されているものとして`i`これにより、無効なペアリングが決して形成されなくなります。 

## 実用的な例

 より高い値の項目がより低い値をブロックする小規模な構成を考えてみましょう。

5 1
```値によるソート順は (10,1)、(8,2)、(5,3) です。

 | --- | --- | --- | --- | --- |

 これは、1 を選択すると 2 が削除されますが、3 には影響する直接の制限がないため、引き続き 3 が許可される様子を示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各項目は一度処理されますが、並べ替えが優先されます。 
| スペース | O(n) | 配列は各トッピングの状態を保存します。 

この制約では最大 100,000 項目が許可されるため、O(n log n) ソリューションは時間制限内に問題なく収まります。 メモリ使用量は線形で安定しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    items = []
    a = [0] * (n + 1)
    b = [0] * (n + 1)

    for i in range(1, n + 1):
        ai, bi = map(int, input().split())
        a[i] = ai
        b[i] = bi
        items.append((ai, i))

    items.sort(reverse=True)

    banned = [False] * (n + 1)
    ans = 0

    for _, i in items:
        if banned[i]:
            continue
        ans += a[i]
        banned[b[i]] = True

    return str(ans)

assert run("3\n10 2\n8 3\n5 1\n") == "15"

# minimum case
assert run("1\n100 1\n") == "100"

# all independent
assert run("3\n5 2\n4 3\n3 1\n") == "12"

# strong chain
assert run("4\n9 2\n7 3\n6 4\n5 1\n") == "15"

 ## 特殊なケース

 トッピング 1 つを含む最小限の入力により、アルゴリズムが些細な選択を正しく処理することが確認されます。 他にアイテムがないため、何も禁止されることはなく、値は常に含まれます。 

1 は 2 を禁止、2 は 3 を禁止、3 は 1 を禁止といった循環依存関係は、ノードが選択された場合にのみ禁止がトリガーされるため、アルゴリズムを壊しません。 最も高い値のノードが最初に選択された場合、単に 1 つの近傍ノードが削除され、グローバル サイクル推論は必要ありません。 

値の低いノードが値の高いノードを禁止する場合は、ソートによって自然に処理されます。 高価値のノードが最初に処理され、低価値のノードを含めようとするその後の試みは、そのノードが禁止されている場合にはスキップされ、誤った交換や以前の最適な選択のオーバーライドを防ぎます。
