 ## 解決策
 ## 問題の理解

 長さ n の配列とスワップの固定シーケンスが与えられます。 各スワップは配列内の 2 つの位置を交換し、このシーケンスは常に同じ順序で適用されます。 すべてのスワップを 1 回実行した後、Jinshi は結果の配列が降順ではない順序でソートされているかどうかを確認し、配列を元の状態に戻します。 

毎日、壬氏がこの固定スワップ シーケンスを実行する前に、猫猫は現在のアレイに対して 1 回のスワップを実行します。 この変更は数日にわたって持続するため、アレイは時間の経過とともに進化します。 各変更の後、固定スワップ シーケンスの実行がソートされた配列で終了するかどうかを決定する必要があります。 

重要な構造は、スワップ シーケンスがすべてのクエリで固定されているのに対し、最初の配列のみが 2 つの位置をスワップすることによって毎日わずかに変更されることです。 

この制約では、最大 100,000 個の要素、100,000 個の固定スワップ、および 100,000 個のクエリが許可されます。 これにより、クエリごとに完全なスワップ シーケンスを再シミュレートするアプローチは即座に除外されます。これは、コストが O(nm) または O(mq) でさえあり、どちらも大きすぎるためです。 クエリごとに最終的な配列を最初から再計算しても時間がかかりすぎます。 

正しいソリューションでは、線形前処理後に各クエリをほぼ一定の時間に短縮する必要があります。 

直接シミュレートしようとすると、微妙な問題が発生します。 たとえば、すべての m スワップを再度適用して猫猫のスワップ後の最終配列を再計算すると、小さい入力は渡されますが、m と q が大きい場合は失敗します。 

もう 1 つのよくある落とし穴は、猫猫のスワップが最終的な並べ替え結果のローカル位置にのみ影響を与えると想定していることです。 これは、固定スワップ シーケンスを通じてインデックスがどのように伝播するかを明示的に追跡しない限り、当てはまりません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに、Maomao のスワップを配列に適用し、m 回のスワップを順番にシミュレートし、最後に結果の配列がソートされているかどうかを確認します。 各シミュレーションのコストは O(m + n) であるため、合計の複雑さは O(q(m + n)) になります。 各次元で 100,000 回の操作を行うと、これは完全に不可能であり、最悪の場合、約 10^10 回の操作が必要になります。 

重要な観察は、m 回のスワップのシーケンスがインデックスの固定順列を定義するということです。 インデックス 1 から n で開始し、これらのインデックスにスワップを適用すると、すべてのスワップの後、位置 i の要素が元の配列の位置 p[i] から来るような置換 p が得られます。 これにより、スワップ プロセス全体が 1 つの再インデックス作成ステップに減ります。 

この順列がわかると、スワップ シーケンス後の結果は、単純に変換された配列 c (c[i] = a[p[i]]) になります。 問題は、c がソートされているかどうかになります。 

ここで、決定的な単純化が行われます。猫猫は a の 2 つの位置を変更するだけです。 p は固定されているため、c の 2 つの位置 p^{-1}(l) と p^{-1}(r) のみが影響を受けます。 c 内の 1 つおきの位置は変更されません。 これは、各クエリが変換された配列内の 2 つのエントリのみを変更することを意味し、並べ替え条件がそれらのインデックスの周囲で局所的にまだ保持されているかどうかを確認するだけで済みます。 

毎回配列全体を再構築してチェックする代わりに、c 内のどの隣接するペアが有効であるかを維持します。 配列は、すべての隣接するペアが c[i] <= c[i+1] を満たす場合にのみソートされます。 各スワップは、更新された 2 つの位置とその近傍を含む比較にのみ影響するため、クエリごとに一定時間で答えを更新できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとにすべてのスワップを再シミュレートします。 O(q(m + n)) | O(n) | 遅すぎる |
 | 順列 + ローカル隣接追跡 | O(n + m + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、スワップ シーケンス全体をインデックスの単一の順列に圧縮し、次に更新時に派生配列を維持します。

1. 位置 1 から n までの ID マッピングから開始します。これは、各最終位置が元の配列のどこから値を取得するかを表します。 
2. m 個の各スワップをこの ID マッピングに適用します。 各スワップは 2 つの位置の画像を交換し、最終位置 i が元の位置 p[i] の値を取るように順列 p を構築します。 
3. pos[x] が一意のインデックス i になるように、逆ルックアップ配列 pos を構築します (p[i] = x)。 これにより、元の配列のインデックス x が変更されたときに、変換された配列内のどの位置が影響を受けるかをすばやく特定できます。 
4. c[i] = a[p[i]] を使用して、変換された配列 c を構築します。 
5. c[i] > c[i+1] の場合、bad[i] が true となる配列 bad を事前計算します。 存在する違反の数を示すカウンター bad_count を維持します。 bad_count が 0 の場合、配列は正確にソートされます。 
6. 各クエリについて、a 内の位置 l と r を交換する場合、i = pos[l] および j = pos[r] を使用して、影響を受ける c 内の位置を特定します。 
7. i と j に関係するすべての隣接性チェックの寄与を bad_count から一時的に削除し、c[i] と c[j] を更新してから、それらの位置の隣接性チェックを復元します。 
8. 更新後、bad_count が 0 の場合は Y を出力し、それ以外の場合は N を出力します。 

これが機能する理由は、c 内の影響を受けない位置がすべて同一のままであるため、i と j から離れたすべての比較が有効なままであるためです。 i と j を含む比較のみが変更される可能性があるため、正確さを維持するにはローカル隣接関係のみを追跡するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    a = list(map(int, input().split()))

    # build permutation p on positions
    p = list(range(n))
    for _ in range(m):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        p[x], p[y] = p[y], p[x]

    # pos[value_index] = position in c
    pos = [0] * n
    for i in range(n):
        pos[p[i]] = i

    # build transformed array
    c = [a[p[i]] for i in range(n)]

    def add(i):
        nonlocal bad
        if 0 <= i < n - 1 and c[i] > c[i + 1]:
            bad += 1

    def remove(i):
        nonlocal bad
        if 0 <= i < n - 1 and c[i] > c[i + 1]:
            bad -= 1

    bad = 0
    for i in range(n - 1):
        if c[i] > c[i + 1]:
            bad += 1

    out = []

    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1

        i = pos[l]
        j = pos[r]

        # remove old affected edges
        for k in (i - 1, i, j - 1, j):
            if 0 <= k < n - 1:
                if c[k] > c[k + 1]:
                    bad -= 1

        # apply swap in original array
        a[l], a[r] = a[r], a[l]

        # update transformed values
        c[i] = a[p[i]]
        c[j] = a[p[j]]

        # add new affected edges
        for k in (i - 1, i, j - 1, j):
            if 0 <= k < n - 1:
                if c[k] > c[k + 1]:
                    bad += 1

        out.append('Y' if bad == 0 else 'N')

    print(''.join(out))

if __name__ == "__main__":
    solve()
```この実装では、スワップ順列圧縮を動的メンテナンス フェーズから分離します。 順列 p は 1 回計算され、pos により影響を受ける位置の定数時間位置特定が可能になります。 配列 c は、概念的に固定スワップ シーケンスを適用した後の現在の変換状態を常に表します。 

注意すべき点は、変更された 2 つのインデックスの周囲の 4 つの境界領域のみを更新することです。 すべての並べ替え違反は隣接するペアによって完全に決定されるため、これらの近傍の外側にあるものを検査する必要はまったくありません。 

## 実用的な例

 ### 例 1

 n = 5 で、スワップ シーケンスが固定順列を引き起こす小さなケースを考えてみましょう。 前処理の後、変換された配列 c = [2, 4, 1, 3, 5] があるとします。 

隣接する比較をチェックすることで不良ペアを維持します。 

| ステップ | 操作 | c アップデート後 | 悪いペア |
 | --- | --- | --- | --- |
 | 0 | イニシャル | [2、4、1、3、5] | (4 > 1) |
 | 1 | スワップは指数に影響を及ぼし、修正につながる | [1、4、2、3、5] | なし |

 関連する位置を修正すると、配列がソートされるため、答えは Y になります。 

これは、クエリごとに配列のごく一部のみが変更され、全体的な再計算が不要であることを示しています。 

### 例 2

 配列が変換後にすでにソートされている場合を考えてみましょう。 

| ステップ | 操作 | c アップデート後 | 悪いペア |
 | --- | --- | --- | --- |
 | 0 | イニシャル | [1、2、3、4、5] | なし |
 | 1 | スワップは無秩序を生み出す | [2、1、3、4、5] | (2 > 1) |

 ここでは、単一のスワップによって反転が 1 つだけ導入され、変更されたインデックスに近い隣接するチェックのみがそれを検出します。 このアルゴリズムは、配列全体をスキャンすることなく違反を即座に特定します。

 ## 特殊なケース

 重大なエッジ ケースは、猫猫が、変換された配列 c 内の隣接する位置にマッピングされる 2 つの位置を交換する場合です。 その場合、影響を受ける両方のインデックスの隣接関係の更新が重複します。 このアルゴリズムは、再計算する前に両方のインデックスの周囲に影響を受ける可能性のあるエッジをすべて削除して再追加し、古い比較が残らないようにするため、これを処理します。 

l と r が pos の下の同じ位置にマップされる場合、別のエッジ ケースが発生します。 これは、l == r の場合にのみ発生します。この場合、更新は何も行われません。 同じローカル近傍を削除して再度追加しても、 bad_count は変更されないため、アルゴリズムは引き続き安全に処理します。 

3 番目のケースは、更新が境界位置 i = 0 または i = n - 1 に影響を与える場合です。実装は境界による隣接性チェックを保護するため、無効な比較は行われず、エッジでの正確性が維持されます。
