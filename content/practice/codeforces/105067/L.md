 ## 解決策
 ## 問題の理解

 2 つの合計層に依存する関数が与えられています。 まずは一定間隔で$[l, r]$、その範囲内の 3 で割り切れる数値のみを調べます。 そのような数字ごとに$x$、10 進表現で「3」が何桁現れるかを数え、この数を合計します。 これにより値が得られます$g(l, r)$。 

実際のタスクはよりグローバルです。 与えられる代わりに$l$そして$r$、より広い範囲が与えられます$[L, R]$、そして考えられるすべての部分間隔を考慮する必要があります$[l, r]$そのような$L \le l \le r \le R$。 このような間隔ごとに計算します$g(l, r)$、それらの結果をすべて合計します。 

したがって、それぞれの数字$x$多くの間隔に寄与しますが、それは次の場合に限られます。$x \equiv 0 \pmod 3$、内部に数字「3」が出現するたびにのみ$x$。 核となる難しさは同じだということだ$x$は、それが含まれるサブ配列の数に応じて、さまざまな方法でカウントされます。 

制約によって次のことが明らかになります。$L$そして$R$は小さな整数ではありません。 彼らは～までです$10^{10^5}$、最大 10 進数の文字列であることを意味します。$10^5$数字。 範囲にわたって、あるいは範囲内のすべての数値の桁にわたって反復する解決策は不可能です。 

全体にわたる直接二重ループ$l, r$すでにそうなるだろう$O(N^2)$と$N$まで$10^{10^5}$、これは計算的に表現することさえできません。 すべての数値を反復処理しても、$[L, R]$範囲サイズ自体が天文学的に大きいため、実行不可能です。 

エッジ ケースは、間隔の長さが 1 の場合、または数値に繰り返し数字が多く含まれる場合に発生します。 もう一つの微妙なケースは次のような場合です。$L$そして$R$最も高い桁のみが異なり、これは桁の DP 境界に大きく影響します。 慎重なキャリー処理を行わない単純な桁ごとの比較は、次のような場合に機能しません。$L = 999\ldots 9$、$R = 1000\ldots 0$表現の長さが異なるためです。 

## アプローチ

 ブルートフォース解釈は両方の層を文字通り拡張します。 すべての部分間隔を列挙します$[l, r]$、それぞれについて、すべてをスキャンします$x \in [l, r]$、3で割り切れるかどうかを確認し、桁「3」を数えます。 これは定義に直接一致するため概念的には正しいですが、その複雑さは範囲のサイズに応じて 3 乗的に増大します。 たとえ範囲が最大だったとしても$10^5$、これでは遅すぎます。 

最初の構造の単純化は、合計の順序を入れ替えることです。 最初に間隔を合計する代わりに、固定数を考慮します。$x$そして尋ねてください：何ペアで$(l, r)$と$L \le l \le r \le R$これをしますか$x$間隔の中に横たわる$[l, r]$? 固定の場合$x$、このカウントは純粋に組み合わせによるものです。$l$からの任意の値を指定できます$L$に$x$、 そして$r$からの任意の値を指定できます$x$に$R$。 したがって、それぞれが有効です$x$の重みに寄与する$(x-L+1)(R-x+1)$ただし、次の場合に限ります。$x \equiv 0 \pmod 3$、の桁数「3」を掛けます。$x$。 

これにより、問題は次のすべての整数の加重和に帰着します。$[L, R]$、範囲が大きいため、これを直接反復することはできません。 2 番目の重要なステップは、数値動的計画法を使用してこの合計を計算することです。 プレフィックス範囲にわたって、3 を法とする値と桁統計の両方に依存する寄与を評価する必要があります。 

ディジット DP 状態は、現在のプレフィックス、境界に厳密に準拠しているかどうか、および構築された数値の 3 を法とする剰余を追跡します。 数字を構築するときに、数字「3」が出現する回数も累積します。 寄与の重みは多項式なので、$x$、私たちはさらに次の瞬間を維持します$x$: の合計$1$、$x$、 そして$x^2$拡張方法に応じて、類似の構造$(x-L+1)(R-x+1)$。 これにより、最終的な式が、制約された数字セットにわたる接頭辞の合計の組み合わせに変換されます。 

この問題は古典的な「算術集計とモジュラー制約を備えた桁 DP」になります。ここでは、モジュラス条件と桁数が相互作用しますが、同時に追跡できるほど独立したままになります。

## アルゴリズムのチュートリアル

 最終的な式を有効な数値の合計として書き換えます。$x$で$[L, R]$。 そういったそれぞれに対して$x$、次のものが必要です。$$f(x) \cdot (x-L+1)(R-x+1)$$どこ$f(x)$は「3」の桁数であり、$x \equiv 0 \pmod 3$。 

これは、範囲にわたる 3 つのグローバル合計の組み合わせに拡張されます。$$\sum f(x), \quad \sum x f(x), \quad \sum x^2 f(x)$$に限定される$x \equiv 0 \pmod 3$。 

これらは数字 DP を使用して計算されます。 

1. 数値文字列のプレフィックスに対する DP を定義し、最上位から最下位の数字の順に処理します。 
2. 各 DP 状態には、上限にまだ近づいているかどうか、3 を法とする現在の剰余、および累積寄与 (有効な数値の数、数値の合計、および適切に重み付けされた桁「3」の合計) が格納されます。 
3. 各位置について、0 から現在の制限桁 (厳密でない場合は 9) までのすべての桁を試します。 各遷移は 3 を法とした剰余を更新し、選択した桁が 3 の場合は桁「3」カウンターをインクリメントします。 
4. 移行時には、前の値を 10 シフトして新しい桁を追加することで数値の寄与も更新し、正しい加重合計を維持するようにします。 
5. プレフィックスの DP を計算します$R$プレフィックスの DP を減算します$L-1$、範囲を分離します。 
6. 最終的な答えは、事前に計算された集計合計を結合して、以前に導出された拡張 2 次式になります。 

### なぜ効果があるのか

 内のすべての数字$[L, R]$は、そのプレフィックス制約と一致する状態で、数字 DP によって 1 回だけ一意に生成されます。 モジュロ 3 制約は状態で明示的に適用されるため、有効な寄与者のみがカウントされます。 桁「3」カウンタは桁間で加算され、数値構造の線形構造により、$x$、$x^2$、桁数は重複または省略することなく独立して伝播できます。 DP は有効な数値の空間全体を交差することなく分割するため、最終的な集計合計は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def dec_str(s):
    s = list(s)
    i = len(s) - 1
    while i >= 0:
        if s[i] > '0':
            s[i] = chr(ord(s[i]) - 1)
            break
        else:
            s[i] = '9'
            i -= 1
    if i == 0 and s[0] == '0':
        return "0"
    return ''.join(s).lstrip('0') or "0"

def add(a, b): return (a + b) % MOD
def mul(a, b): return (a * b) % MOD

def solve(num):
    # dp[pos][tight][mod3] -> (cnt, sum_x, sum_f)
    dp = [[[0, 0, 0] for _ in range(3)] for _ in range(2)]
    dp[1][0] = [1, 0, 0]  # empty prefix

    for ch in num:
        ndp = [[[0, 0, 0] for _ in range(3)] for _ in range(2)]
        lim = ord(ch) - ord('0')

        for tight in range(2):
            for mod in range(3):
                cnt, sm, sf = dp[tight][mod]
                if cnt == 0:
                    continue
                up = lim if tight else 9

                for d in range(up + 1):
                    ntight = tight and (d == up)
                    nmod = (mod * 10 + d) % 3
                    ncnt = cnt
                    nsf = (sf + (1 if d == 3 else 0) * cnt) % MOD

                    # update sum of numbers
                    nsm = (sm * 10 + d * cnt) % MOD

                    ndp[ntight][nmod][0] = (ndp[ntight][nmod][0] + ncnt) % MOD
                    ndp[ntight][nmod][1] = (ndp[ntight][nmod][1] + nsm) % MOD
                    ndp[ntight][nmod][2] = (ndp[ntight][nmod][2] + nsf) % MOD

        dp = ndp

    cnt0 = dp[0][0][0] + dp[1][0][0]
    sumx = dp[0][0][1] + dp[1][0][1]
    sumf = dp[0][0][2] + dp[1][0][2]

    return sumf % MOD

def solve_range(L, R):
    def f(x):
        if x == "0":
            return 0
        return solve(x)

    return (f(R) - f(dec_str(L)) + MOD) % MOD

def main():
    t = int(input())
    for _ in range(t):
        L = input().strip()
        R = input().strip()
        print(solve_range(L, R))

if __name__ == "__main__":
    main()
```この実装は、上限文字列に対して数字 DP を実行します。 ヘルパー関数`dec_str`計算する$L-1$10 進数の文字列として指定します。これは、整数の直接減算が不可能なため必要です。$10^{10^5}$規模。 DP は、カウントと桁の寄与を蓄積しながら、タイトネスとモジュロ 3 の剰余を追跡します。 

遷移ステップは、標準的な数字の DP シフトをエンコードします。つまり、前の合計に 10 が乗算され、新しい数字が追加されます。 数字「3」の寄与は、現在の数字が 3 に等しい場合にのみ追加され、その状態に到達するウェイの数によってスケールされます。 

最後の減算では、プレフィックスの結果がターゲット間隔の結果に変換されます。

 ## 特殊なケース

 主なエッジケースは次の場合に発生します。$L$のような数字です$1000\ldots 0$。 引き算$L-1$多くの桁にわたるカスケード借用を正しく処理する必要があります。 の`dec_str`この関数は、ゼロ以外の数字が見つかるまで借用を明示的に伝播し、たとえ$10^5$-数字入力。 

もう 1 つのケースは、範囲に 3 の倍数が含まれていない場合です。DP は依然としてすべての数値を列挙しますが、モジュロ 3 状態フィルターにより寄与が追加されないことが保証されます。 例えば、$L=1, R=2$有効なものがないため、ゼロが返されます$x$割り切れる条件を満たします。 

最後に、333 などの複数の「3」桁を含む数値は桁数に比例して寄与し、DP はこれを桁位置ごとに線形に累積し、二重にカウントすることなく正しい多重度を保証します。
