 ## 解決策
 ## 問題の理解

 文字列と数値が与えられます$k$。 文字列から、正確な長さを持つすべてのサブシーケンスを調べます。$k$。 問題は、文字列内の位置を選択する 2 つの異なる方法で、結果として同じ長さが得られるかどうかです。$k$文字の並び。 

ここでのサブシーケンスはインデックスを選択することを意味します$i_1 < i_2 < \dots < i_k$、その順序で文字を読み取って文字列を取得します。 異なるインデックスを選択しても同じ結果の文字列を生成できますが、そのようなことが起こるかどうかが尋ねられます。 

したがって、タスクは全期間にわたる一意性チェックです。$k$サブシーケンス: サイズのインデックスセットからのマッピングかどうかを知りたい$k$結果の文字列への変換は単射的です。 

この制約により、サブシーケンスのブルート フォースが不可能であることが明確になります。 文字列の長さは次のとおりです$10^5$テストケースごとに最大で$10^3$テストケースの全長は$3 \cdot 10^5$。 長さのすべてのサブシーケンスを生成する場合でも$k$部分列の数が次のとおりであるため、組み合わせ爆発的です。$\binom{n}{k}$、これは中程度の人々にとってはすでに天文学的な規模です$n$。 

2 番目の制約は暗黙的です。重複が存在するかどうかのみを考慮します。 これは、サブシーケンスを完全に列挙するのではなく、サブシーケンス間の衝突を検索していることを意味します。 

文字列に遠く離れた文字が繰り返し含まれている場合、微妙なエッジケースが発生します。 たとえば、`"abca"`、その続き`"aa"`インデックス (1,4) から形成できますが、文字が異なるため (2,4) は無効ですが、文字の繰り返しにより同一のサブシーケンスに対して複数のインデックス パターンが作成される可能性があります。 ローカル パターンまたは隣接する重複のみをチェックする単純なソリューションでは、長距離の衝突を見逃してしまいます。 

もう 1 つのエッジケースは次のような場合です$k = 1$。 この場合、サブシーケンスは単一の文字になります。 これらは、文字列内のすべての文字が異なる場合にのみ一意になります。 繰り返しがあると、直ちにサブシーケンスの重複が生じます。 

いつ$k = n$、サブシーケンスは 1 つだけであるため、答えは常に「はい」になります。 

本当に難しいのは、2 つの異なるインデックスを選択すると同じ長さが得られる場合を理解することです。$k$サブシーケンス、および組み合わせを列挙せずにその構造を検出する方法。 

## アプローチ

 直接的なアプローチでは、あらゆる長さを生成しようとします。$k$シーケンスを作成し、ハッシュセットに保存します。 生成された各文字列を比較して重複を検出できるため、これは原理的には正しいです。 ただし、1 つのサブシーケンスを生成する場合でも、選択する必要があります。$k$インデックスがあり、$\binom{n}{k}$彼らのうち。 最悪の場合、これは指数関数的に増加します$n$、それはたとえ$n = 50$。 

重要な点は、重複が発生するのは、順序を保持しながら同じ結果の文字列を生成する方法で同一の文字の位置を選択する際に曖昧さがある場合のみであるということです。 サブシーケンスを組み合わせオブジェクトとして考える代わりに、辞書編集的に誘導されたサブシーケンスの構造を構築し、異なるインデックス パスが収束できるかどうかを追跡することについて考えることができます。 

有用な再定式化は、サブシーケンス文字列を修正し、元の文字列に複数の埋め込みがあるかどうかを尋ねることです。 これはパターンカウントの問題になります: 長さは存在しますか?$k$少なくとも 2 つの異なる方法でサブシーケンスとして現れる文字列?

 重要な構造の単純化は、文字列内のすべての文字が特定の意味でグローバルに十分に区別できる場合、すべてのサブシーケンスが貪欲な左から右への構築によって一意に決定されることです。 あいまいさは、サブシーケンスのマッチング中に、残りの文字の完了をブロックすることなく両方を使用できる 2 つの等しい文字の間で選択できる位置が存在する場合に正確に発生します。$k-1$一致します。 

これは、貪欲な実現可能性の特性評価につながります。つまり、サブシーケンスの構築をシミュレートし、いずれかのステップで、両方とも完了につながる有効な次の選択肢が複数認められるかどうかを検出します。 

プレフィックス位置ごとに、部分一致を拡張するための選択肢がいくつ存在するかを追跡することで、明示的なサブシーケンスの列挙を回避します。 2 つの同一の文字を両方使用して部分シーケンスを完成できる位置を見つけた瞬間、一意性は失われます。 

これはスキャンベースのチェックに帰着し、各プレフィックスに存在する有効な継続パスの数を維持しますが、検出する必要があるのはパスが 1 を超えたかどうかだけです。 

最終的な還元は、残りのサフィックスに、有効な長さで次に選択される要素として機能する何らかの文字が少なくとも 2 回含まれる位置が存在する場合にのみ、一意性が失敗するということです。$k$その後の続き。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 各文字のサフィックス数を事前計算します。 あらゆるポジションについて$i$、各文字が何回出現するかがわかります。$s[i:]$。 これにより、文字列の後半で利用可能なものについて定数時間の推論が可能になります。 
2. 左から右へ貪欲にサブシーケンスの構築をシミュレートしますが、1 つのサブシーケンスを構築する代わりに、ある長さの次の文字に対して複数の有効な選択肢が存在するステップがあるかどうかを追跡します。$k$続いて。 
3. ポジションごとに$i$、使用を検討してください$s[i]$次に選ばれるキャラクターとして。 まだ完了できるかどうかを確認します$k-1$接尾辞の文字。 この実現可能性は、標準的な貪欲な部分シーケンス マッチングです。つまり、実行後に十分な残りの文字が存在することを保証します。$i$。 
4. 必要な文字の有効な位置が見つかったら、サブシーケンスを完了するのに十分な余地を残しつつ、次の選択としても有効な同じ文字を持つ別の位置が文字列の後半に存在するかどうかを確認します。 そのような 2 番目の位置が存在する場合、一意性が失敗しているとすぐに結論付けられます。 
5. 同じサブシーケンス構築状態に対して 2 つの有効な選択肢があるステップに遭遇しなかった場合、すべてのサブシーケンスは一意の埋め込みを持ちます。 

これが機能する理由は、重複するサブシーケンスが 2 つの異なる埋め込みに対応し、埋め込みが異なる最初のインデックスで両方の選択がローカルに有効であり、かつ残りのサフィックスを完全にする必要があるためです。 この分岐点を検出できれば十分です。 

### なぜ効果があるのか

 任意の長さ-$k$subsequence は、各文字のどの出現を取得するかについての一連の決定に対応します。 2 つの異なるインデックス シーケンスが同じサブシーケンスを生成する場合、それらが分岐する最初の位置が存在し、同じ文字の 2 つの異なる出現を選択しながら、残りのシーケンスを完了することができます。$k-1$文字。 私たちのスキャンは、すべての段階で、同じ必要な次の文字に対して複数の有効な継続位置が存在するかどうかをチェックするため、まさにこの状況を検出します。 そのような分岐点が存在しない場合、すべてのサブシーケンスには一意の埋め込みがあるため、すべてのサブシーケンスは一意になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        s = input().strip()

        if k == 1:
            # duplicates exist iff any character repeats
            seen = set()
            ok = True
            for c in s:
                if c in seen:
                    ok = False
                    break
                seen.add(c)
            print("Yes" if ok else "No")
            continue

        if k == n:
            print("Yes")
            continue

        # suffix counts
        suf = [[0] * 26 for _ in range(n + 1)]
        for i in range(n - 1, -1, -1):
            suf[i] = suf[i + 1][:]
            suf[i][ord(s[i]) - 97] += 1

        # try to find any ambiguity
        # we scan possible start positions of subsequences
        # and check whether first pick can be ambiguous
        possible_start = [[] for _ in range(26)]
        for i, c in enumerate(s):
            possible_start[ord(c) - 97].append(i)

        bad = False

        for c in range(26):
            idxs = possible_start[c]
            if len(idxs) < 2:
                continue

            # check if at least two occurrences can both start a valid subsequence
            # we test greedily from each occurrence
            valid = []
            for i in idxs:
                need = k - 1
                j = i + 1
                cnt = 0
                # greedy count how many we can still pick
                while j < n and need > 0:
                    need -= 1
                    j += 1
                if need == 0:
                    valid.append(i)

            if len(valid) >= 2:
                bad = True
                break

        print("No" if bad else "Yes")

if __name__ == "__main__":
    solve()
```実装では、最初に些細なケースが分離されます。 いつ$k = 1$の場合、答えは文字列に重複があるかどうかによってのみ決まります。 いつ$k = n$、サブシーケンスは 1 つだけ存在します。 

主なアイデアは、同じ文字の 2 つの異なる位置が両方とも有効な長さの最初の要素として機能できるかどうかを検出することです。$k$続いて。 そうなると、すぐに衝突してしまいます。 各候補内の貪欲なチェックにより、選択した開始位置からでも完了できることが保証されます。$k$右側の残りの文字を使用して選択します。 

重要な点は、この最初の分岐点を超えてサブシーケンスを完全に列挙する必要がないことです。これは、重複は、最も早い異なるインデックスでの発散として現れるはずであるためです。
