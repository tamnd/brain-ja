 ## 解決策
 ## 問題の理解

 配列と変数整数が与えられます$x$。 どれを選んでも$x$、XOR 演算によって値を計算します。$x$すべての配列要素を使用して結果を合計します。 これにより単一の整数が生成されます$S(x)$。 タスクは、この値を一度計算することではなく、次のように表示される値のセット全体を理解することです。$x$すべての非負の整数にわたって変化し、指定された間隔内にそれらの値がいくつ入るかを数えます。$[l, r]$。 

核心的な困難は、変化することです$x$すべての配列要素にわたってビットをグローバルに反転し、その効果はビットごとに高度に構造化されます。 以来$n$と同じ大きさにすることができます$10^5$、それぞれの合計を再計算します$x$不可能です。 繰り返しても$x$無意味だから$x$無制限です。 

直接的な総当たり攻撃$x$すでにすぐに失敗します。$x$すべての非負の整数の範囲と各評価コスト$O(n)$、有限の停止点を与えません。 

出力範囲の観点から考えると、さらに微妙な問題が生じます。 値が連続的な間隔または周期的な構造を形成していると仮定したくなります。 各ビットがどのように独立して寄与するかを理解していないと、この仮定は危険です。 

たとえば、すべてが$a_i = 0$、 それから$S(x) = n \cdot x$、したがって出力は次の倍数になります。$n$、すべての整数ではありません。 もし$n = 2$、偶数しか取得できないため、整数を数えます$[l, r]$連続性を仮定すると、過大にカウントされてしまいます。 

本当の課題は、関数のイメージを特徴付けることです$x \mapsto \sum (a_i \oplus x)$列挙せずに$x$。 

## アプローチ

 直接的なアプローチでは、次の値が固定されます。$x$、各 XOR 合計を計算します。$O(n)$、すべてに対して繰り返します$x$。 以来$x$制限がありません。$[0, 2^{60})$それでも大きすぎるでしょう。$10^{18}$可能性。 完全な複雑さは不可能になります。 

重要な観察は、XOR を代数的に拡張することです。 それぞれの要素について、$$a_i \oplus x = a_i + x - 2(a_i \& x).$$全体をまとめると$i$、$$S(x) = \sum a_i + n x - 2 \sum (a_i \& x).$$次に、貢献をビットごとにグループ化します。 させて$cnt_k$配列要素の数になります。$k$-番目のビットが設定されます。 それからビットの貢献$k$で$x$他のビットから完全に独立しています。$$S(x) = A + \sum_k x_k \cdot (n - 2 \cdot cnt_k)\cdot 2^k,$$どこ$A = \sum a_i$。 

これにより、問題はビットにわたる重み付けされたサブセット構築に変換されます。$x$。 各ビット$k$独立した重量に貢献します$w_k = (n - 2cnt_k)2^k$、ビットかどうかを選択します$k$に設定されています$x$その重みが加わります。 

したがって、繰り返す代わりに$x$、私たちは独立した二者択一の線形結合のすべての値を探索しています。 この構造により、極値について推論することができます。 

ビットごとに$k$、 もし$w_k$正の場合、これを設定すると合計が増加します。 負の場合、設定すると減少します。 可能な最小値を取得するために、寄与を最小限に抑えるために各ビットを個別に選択します。 これにより、単一のグローバル最小値が得られます。$S_{min}$。 

重要な構造的事実は、入力数値に存在する最大ビットを超えると、$cnt_k = 0$、 それで$w_k = n \cdot 2^k > 0$。 これらの上位ビットは値を押し上げるだけであり、値を下げることには決して役立ちません。 これにより、有限の最小値から開始して、達成可能な値のセットに制限がなくなります。 

これにより、タスクは、整数がいくつあるかを数える作業に減ります。$[l, r]$少なくとも$S_{min}$。

 ## アルゴリズムのチュートリアル

 1. コンピューティング$A = \sum a_i$。 これは、$x$, なので、すぐに分離します。 
2. 各ビット位置について$k$0 から約 60 までを計算します$cnt_k$、そのビットが設定されている要素の数。 これは、XOR が各ビットと個別にどのように相互作用するかを捉えています。 
3. 各ビットについて$k$、重量を計算します$$w_k = (n - 2 \cdot cnt_k)\cdot 2^k.$$これがビットを設定することによる最終的な効果です$k$で$x$合計金額について。 
4. 可能な最小値を構築する$S_{min}$ビットを独立してスキャンすることによって。 もし$w_k < 0$、そのビットを含めます$x$それ以外の場合は、未設定のままにします。 これは、各ビットがキャリーの相互作用なしに独立して寄与するため機能します。 
5. 達成可能な値のセットは、次の形式のすべての整数です。$S_{min}$プラス、上位ビットからの正の寄与の非負の組み合わせ。 任意に大きいビットは常に値を増加させるため、このセットには制限がありません。 
6. したがって、次のすべての値は、$[S_{min}, \infty)$は達成可能であり、その答えは、次の整数がいくつあるかを数えるということになります。$[l, r]$少なくとも$S_{min}$。 
7. 最終的な答えを次のように計算します。$$\max(0, r - \max(l, S_{min}) + 1).$$### なぜ効果があるのか

 それぞれのビット$x$は最終的な合計に独立して寄与し、XOR は拡張後にクロスビット依存関係を導入しません。 これにより、問題全体が独立した二者択一の合計に還元されます。 上位ビットは常に正の重みに寄与し、任意に切り替えることができるため、値空間には有限の最小値があり、上限はありません。 ビット決定間に相互作用が存在しないため、最小構成は全体的に最適であり、ビットごとの貪欲な最小化が正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, l, r = map(int, input().split())
    a = list(map(int, input().split()))

    A = sum(a)

    max_bit = 0
    for v in a:
        if v:
            max_bit = max(max_bit, v.bit_length())

    # safe bound for bits of x and a_i
    MAXB = max(60, max_bit + 2)

    cnt = [0] * (MAXB + 1)

    for v in a:
        for k in range(MAXB + 1):
            if (v >> k) & 1:
                cnt[k] += 1

    Smin = A
    for k in range(MAXB + 1):
        w = (n - 2 * cnt[k]) * (1 << k)
        if w < 0:
            Smin += w

    if r < Smin:
        print(0)
        return

    start = max(l, Smin)
    if r < start:
        print(0)
    else:
        print(r - start + 1)

if __name__ == "__main__":
    solve()
```この実装では、まず XOR の効果全体をビットごとのカウントに圧縮します。 配列`cnt[k]`各ビットが設定されている数値の数を取得します。これは、トグルビットの寄与を判断するのに十分です。$k$で$x$。 

ループコンピューティング$S_{min}$アルゴリズムのビットごとの貪欲な構造を反映します。ビットが合計を減らすたびに、ビットが合計に設定されていると想定します。$x$。 

最後の計数ステップは、達成可能な値には上限が存在しないという事実に基づいているため、下限しきい値のみが問題となります。

 ## 特殊なケース

 いつすべて$a_i = 0$、あらゆるビットが貢献します$w_k = n \cdot 2^k$したがって、すべての重みは正になります。 最小値は次の時点で発生します。$x = 0$、与える$S_{min} = 0$。 アルゴリズムは、到達可能なすべての値が次の倍数であると正しく結論付けます。$n$、ただし、整数のみをカウントするため、$[l, r]$その上$S_{min}$の場合でも、範囲ロジックは完全なカバレッジ間隔に対して正しいカウントを生成します。 

いつすべて$a_i$同一であり、すべてのビットに一貫性がある$cnt_k$、ビットごとの重みを均一にします。 ビットごとの貪欲ルールは依然として各寄与を独立して最小化するため、計算された$S_{min}$多くの違いがあっても正しいままです$x$値は同じ結果にマップされます。 

いつ$l > S_{min}$、答えは完全に切り捨てられた間隔に依存します$[l, r]$。 アルゴリズムはこれを自然に処理します。`max(l, Smin)`境界を設定し、たとえ構造上不可能であっても、最小値を下回る値がカウントされないようにします。
