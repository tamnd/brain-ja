 ## 解決策
 ## 問題の理解

 各訪問者が 1 日の特定の時間に到着し、各サービスにかかる時間が 1 分未満であると仮定して、すべての訪問者にすぐに対応できるように、ヴァレラがファストフード カフェに必要なレジの数を決定するように求められました。 最初の入力行以降の各入力行は、顧客が到着した時と分を示します。 出力は単一の整数です。つまり、同時に到着する人の最大数です。これは、顧客が離れることを避けるために必要な現金の数であるためです。 

制約により、`n`最大 100,000 まで、時間は時系列で表示されます。 これは、すべての顧客を 1 回反復するソリューション、またはマップを何度も使用するソリューションが受け入れられることを意味します。 すべての顧客のペアの重複時間を比較する単純なソリューションでは、おおよその時間が必要になります。`n^2`の上限では実行不可能な操作`n`。 

注意すべき主なエッジ ケースは、複数の顧客がまったく同時に到着すること、顧客が重複せず連続した時間に到着すること、および 1 人の顧客の入力が最小限であることです。 たとえば、3 人の顧客が 8:00 に到着し、さらに 2 人が 9:00 に到着した場合、顧客は合計で 5 人しか存在しませんが、正しい出力は 3 になります。 不用意に実装すると、最大同時到着数を取得するのではなく、到着数を合計する可能性があります。 

## アプローチ

 ブルートフォース手法では、すべての顧客を他のすべての顧客と比較し、同じタイムスタンプを共有している顧客の数を数えます。 問題は同時到着数のカウントに帰着するため、これは正しいと考えられますが、パフォーマンスは大まかです。`n^2`最悪の場合の比較は遅すぎます。`n = 10^5`。 

最適なアプローチは、入力がすでに時系列順になっているという事実を利用します。 これを 1 回繰り返すことで、同じ時間と分を共有する連続顧客の数を追跡できます。 新しい時間に遭遇するたびに、私たちはカウンターをリセットします。 この反復中にカウンタが到達する最大値は、必要な現金の最小数です。 この方法はシンプルであり、時間的にも直線的です。`O(n)`なぜなら、各顧客を 1 回だけ処理し、それぞれに対して定数時間の操作のみを実行するからです。 

重要な洞察は、時間がソートされているため、同時に到着するすべての顧客が連続しているということです。 これは、ハッシュ マップや複雑なデータ構造が必要ないことを意味します。 単純なカウンターで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`current_count`最初の顧客を表す 1 に、`max_count`1 に設定すると、最大同時到着数が保存されます。 
2. 最初の顧客の到着時刻を`last_time`タプルとして`(hour, minute)`。 
3. 残りの部分を繰り返します`n-1`顧客:

 ａ． 各顧客の到着時間をタプルとして読み取ります`(hour, minute)`。 

b. この時間が合えば`last_time`、増分`current_count`なぜなら、同じ時間に別のお客さんが到着したからです。 

c. 一致しない場合は設定してください`current_count`新しい時間ができたので、1 にします。 

d. アップデート`last_time`現在の時間まで。 

e. アップデート`max_count`もし`current_count`それを超えています。 
4. すべての顧客を繰り返した後、`max_count`最低限必要な現金の数です。 印刷してください。 

ここでの不変条件は、`current_count`現時点で到着する顧客の数を常に反映し、`max_count`これまでに観測された最大の値を記録します。 時間がソートされるため、同じタイムスタンプを持つ顧客がカウントされずに後から入力されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
h, m = map(int, input().split())
last_time = (h, m)
current_count = 1
max_count = 1

for _ in range(n - 1):
    h, m = map(int, input().split())
    current_time = (h, m)
    if current_time == last_time:
        current_count += 1
    else:
        current_count = 1
        last_time = current_time
    if current_count > max_count:
        max_count = current_count

print(max_count)
```ソリューションは、ループの外の最初の顧客を読み取り、初期化します。`last_time`そして`current_count`。 後続の顧客ごとに時間を比較し、カウンターを更新します。 これにより、最初の出現をカウントする際のオフバイワンエラーがなくなり、不必要なチェックが回避されます。 タプルの使用`(hour, minute)`比較をシンプルかつ明確に保ちます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各顧客に対して正確に 1 回反復し、顧客ごとに一定時間の操作を実行します。 |
 | スペース | お(1) | いくつかのカウンターとタプルのみを保存します。 追加の配列やマップは必要ありません。 |

 与えられた`n ≤ 100,000`線形反復により、ソリューションは 2 秒の時間制限内で適切に実行され、メモリ使用量は 256 MB の制限と比較して無視できます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    h, m = map(int, input().split())
    last_time = (h, m)
    current_count = 1
    max_count = 1
    for _ in range(n - 1):
        h, m = map(int, input().split())
        current_time = (h, m)
        if current_time == last_time:
            current_count += 1
        else:
            current_count = 1
            last_time = current_time
        if current_count > max_count:
            max_count = current_count
    return str(max_count)

# provided samples
assert run("4\n8 0\n8 10\n8 10\n8 45\n") == "2", "sample 1"
assert run("3\n9 0\n9 15\n9 30\n") == "1", "sample 2"

# custom cases
assert run("1\n0 0\n") == "1", "single customer"
assert run("5\n10 0\n10 0\n10 0\n10 0\n10 0\n") == "5", "all same time"
assert run("6\n1 1\n1 2\n1 2\n1 2\n1 3\n1 4\n") == "3", "three at same minute"
assert run("4\n23 59\n23 59\n0 0\n0 0\n") == "2", "boundary wrap-around"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 人の顧客 | 1 | 最小入力サイズ |
 | すべて同時に | 5 | 最大同時到着者数 |
 | 混合重複 | 3 | 重複のある複数のグループ |
 | 境界ラップ | 2 | 一日の終わりと始まりの時刻。日をまたいでカウントされないようにします。 

## 特殊なケース

 単一の顧客の場合は、次のように入力します。`1\n12 30\n`、`current_count`そして`max_count`は 1 に初期化され、ループは実行されず、正しい 1 が生成されます。 同時に到着するすべての顧客に対して、カウンタはループを通じて正しく増加し、正しい最大値が得られます。 到着が一日の終わりと次の深夜の場合、比較`(hour, minute)`日をまたいで誤った集計が行われないようにします。 この具体的な処理により、1 つずつずれたエラーや境界を越えたエラーが防止されます。
