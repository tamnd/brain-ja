 ## 解決策
 ## 問題の理解

 以下から整数の間隔が与えられます。`a`に`b`。 長さを選びたい`l`**すべて**の連続する長さのセグメント`l`この間隔内には少なくとも次のものが含まれます`k`素数。 

この条件を満たすすべての長さの中で、最も小さい長さが必要です。 長さが合わない場合は印刷します`-1`。 

問題を捉える別の方法は、候補の長さについて次のように考えることです。`l`、すべてのウィンドウを調べます`[x, x+l-1]`中に完全に収まる`[a, b]`。 候補は、これらのウィンドウのそれぞれに少なくとも以下が含まれている場合にのみ有効です。`k`素数。 

間隔のエンドポイントは最大でも`10^6`。 これが重要な制約です。 素数情報は繰り返し必要となるため、次の値までのすべての素数を事前計算します。`10^6`ふるい付きはとても安いです。 間隔自体には、最大で次のものを含めることもできます。`10^6`したがって、すべてのウィンドウを可能な限り長さごとに個別にチェックするソリューションは、おおよそのパフォーマンスを発揮します。`10^12`操作は不可能であり、完全に実行不可能です。 

条件の構造は単調な特性を示唆しています。 ある程度の長さであれば`l`機能する場合は、それより長い長さでも機能します。 大きなウィンドウには、少なくとも小さなウィンドウと同じ数の素数しか含めることができません。 この単調性は二分探索を直接示しています。 

見落としやすいエッジケースがいくつかあります。 

考慮する：```
14 16 1
```区間には素数がありません。 可能な最大のウィンドウでも素数は含まれないため、答えは次のようになります。`-1`。 二分探索の実装を不用意に行うと、解決策が存在するかどうかが明示的に検証されない可能性があります。 

考慮する：```
2 5 2
```窓`[2,3]`素数が2つ含まれていますが、`[3,4]`1 つだけ含まれています。 いくつかのウィンドウを見るだけでは十分ではありません。 すべてのウィンドウが条件を満たさなければなりません。 

考慮する：```
2 2 1
```区間には単一の素数が含まれます。 唯一可能な長さは`1`、これは有効です。 境界例`a = b`多くの場合、ウィンドウ処理における off-by-one エラーが明らかになります。 

考慮する：```
8 12 1
```唯一の素数は、`11`。 長さ`4`すべての長さ 4 のウィンドウには次のものが含まれるため、機能します。`11`、長さ`3`失敗する理由`[8,10]`プライムは含まれていません。 有効な最小長は、必ずしも連続する素数間の距離のみに関係するわけではありません。 

## アプローチ

 最も直接的な解決策は、可能な限りすべての長さを試してみることです`l`。 長さごとに、そのサイズのすべてのウィンドウを検査し、そこに含まれる素数の数を数えます。 すべてのウィンドウに少なくとも`k`素数、答えを記録します。 

ウィンドウ内の素数カウントは、素数値のプレフィックス合計を使用して効率的に計算できます。 このようなプレフィックスサムを使用すると、1 つのウィンドウをチェックすることは次のようになります。`O(1)`。 残念ながら、最大で`10^6`可能な長さと最大`10^6`長さごとの窓。 ウィンドウ クエリを最適化した後でも、合計作業量は約`10^12`、それは限界をはるかに超えています。 

重要な観察は単調性です。 

長さを仮定します`l`有効です。 あらゆる長さのウィンドウ`l`少なくとも含まれています`k`素数。 次に、より長い長さを検討してください`L > l`。 あらゆる長さ-`L`ウィンドウにはある程度の長さが含まれます -`l`サブウィンドウ。 そのサブウィンドウにはすでに少なくとも次のものが含まれているため、`k`素数の場合、大きいウィンドウには少なくとも次の要素も含まれます。`k`素数。 

これは次のことを意味します:

 - 無効な長さが最初に来ます。 
- 有効な長さはその後に来ます。 

答えは最初の有効な長さであり、二分探索で見つけることができます。 

候補の長さをテストするには`l`、窓をスライドさせて通過します`[a,b]`。 素数の接頭辞合計を使用すると、すべてのウィンドウ内の素数の数を定数時間で計算できます。 いずれかのウィンドウに含まれる内容が以下の場合`k`素数の場合、候補は失敗します。 

残りの要素は高速素数前処理です。 すべての数値が最大なので、`10^6`、エラトステネスの標準ふるいは、おおよその関連するすべての数値の素数を計算します。`O(10^6 log log 10^6)`時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((b-a+1)²) | O(b) | 遅すぎる |
 | 最適 | O(b log log b + (b-a+1) log(b-a+1)) | O(b) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. エラトステネスのふるいを最大まで構築します。`b`そしてどの数字が素数であるかを判断します。 
2. プレフィックス合計配列を構築する`pref`どこ`pref[i]`からの素数の数に等しい`1`を通して`i`。 
3. 関数を定義する`check(l)`。 
4. すべての開始位置について`x`から`a`に`b-l+1`、ウィンドウ内の素数の数を計算します。`[x, x+l-1]`使用:`pref[x+l-1] - pref[x-1]`5. いずれかのウィンドウに含まれる内容が以下の場合`k`素数、戻り値`False`。 
6. すべてのウィンドウが要件を満たしている場合は、リターンします。`True`。 
7. バイナリ検索の前に、可能な最大長が機能することを確認します。 これは間隔全体に相当します`[a,b]`。 
8. 最大長でも失敗した場合は、印刷します。`-1`。 
9. それ以外の場合は、長さの二分検索`1`に`b-a+1`。 
10.いつ`check(mid)`成功した場合は、それを回答候補として記録し、左半分の検索を続けます。 
11.いつ`check(mid)`失敗した場合は、右半分を検索します。 
12. 見つかった最小の有効な長さを出力します。 

### なぜ効果があるのか

 プレフィックス合計配列により、すべてのウィンドウの素数カウントが正確に計算されることが保証されます。 の`check(l)`関数は、すべての長さの場合に正確に true を返します。`l`ウィンドウには少なくとも次の内容が含まれます`k`素数。 

重要な特性は単調性です。 長さの場合`l`は有効ですが、より大きなウィンドウには有効な長さが含まれるため、それより大きな長さも有効です。`l`サブウィンドウなので、すでに少なくとも次のものが含まれています`k`素数。 したがって、有効な長さのセットは、可能なすべての長さの接尾辞を形成します。 この単調述語の二分探索により、有効な最小の長さが見つかり、これがまさに必要な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b, k = map(int, input().split())

    is_prime = [True] * (b + 1)
    if b >= 0:
        is_prime[0] = False
    if b >= 1:
        is_prime[1] = False

    p = 2
    while p * p <= b:
        if is_prime[p]:
            start = p * p
            for x in range(start, b + 1, p):
                is_prime[x] = False
        p += 1

    pref = [0] * (b + 1)
    for i in range(1, b + 1):
        pref[i] = pref[i - 1] + (1 if is_prime[i] else 0)

    def count_primes(l, r):
        return pref[r] - pref[l - 1]

    def check(length):
        end_start = b - length + 1
        for start in range(a, end_start + 1):
            if count_primes(start, start + length - 1) < k:
                return False
        return True

    n = b - a + 1

    if not check(n):
        print(-1)
        return

    lo, hi = 1, n
    ans = n

    while lo <= hi:
        mid = (lo + hi) // 2

        if check(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```ふるいは、任意のウィンドウに表示されるすべての数値の素数を計算します。 すべてのクエリは一定の間隔で素数のカウントを要求するため、プレフィックスの合計は直後に構築されます。 

の`check()`function は、二分探索で使用されるコア述語です。 候補の長さのすべてのウィンドウをスキャンし、不良ウィンドウが 1 つ見つかるとすぐにその長さを拒否します。 多くの候補者はすぐに失敗してしまうため、この早期の撤退は重要です。 

二分探索前の存在チェックは必須です。 間隔全体に含まれる内容が以下の場合`k`素数の場合、これより小さいウィンドウは要件を満たすことはできません。 この手順を行わないと、解が存在しない場合でも、バイナリ検索は誤って長さを返します。 

ウィンドウ数には以下が使用されます。```
pref[r] - pref[l - 1]
```これが、プレフィックス配列のインデックスが付けられる理由です。`0`。 これにより、次のような特殊なケースが回避されます。`l = 1`。

import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    a, b, k = map(int, input().split())

    is_prime = [True] * (b + 1)
    if b >= 0:
        is_prime[0] = False
    if b >= 1:
        is_prime[1] = False

    p = 2
    while p * p <= b:
        if is_prime[p]:
            for x in range(p * p, b + 1, p):
                is_prime[x] = False
        p += 1

    pref = [0] * (b + 1)
    for i in range(1, b + 1):
        pref[i] = pref[i - 1] + is_prime[i]

    def check(length):
        for s in range(a, b - length + 2):
            cnt = pref[s + length - 1] - pref[s - 1]
            if cnt < k:
                return False
        return True

    n = b - a + 1

        return "-1"

    lo, hi = 1, n
    ans = n

    while lo <= hi:
        mid = (lo + hi) // 2
        if check(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    return str(ans)
