 ## 解決策
 ## 問題の理解

 このタスクは、1 から 2 までのタイルで構成される 1 次元のアリーナを記述します。$n$。 位置から開始します$s$、以上$m$ボスが特定のセグメント内に立つことを禁止する攻撃を放つ離散的な瞬間$[l_i, r_i]$。 攻撃の瞬間にそのセグメント内にいた場合、ランはただちに終了します。 

各攻撃の前に、位置を変更することができます。 無料でその場にとどまることも、正確に移動するテレポートを実行することもできます$k$左または右のタイル、支払い$k$エネルギー。 エネルギー バジェットは決してゼロを下回ってはなりません。そのため、目標は、すべてのタイム ステップでそのステップの禁止セグメントの外にいることを確認しながら、消費される総エネルギーを最小限に抑えることです。 

重要な構造は、最終目的地を選択しないということです。 すべての攻撃の前に有効な位置を選択する必要があり、各位置は移動の制約と現在の禁止間隔を回避する必要性の両方に依存します。 

制約は、$O(m)$または$O(m \log n)$テスト ケースごとのソリューション (合計)$m$以下の範囲のテスト全体で$2 \cdot 10^5$。 ステップごとにすべてのタイルの到達可能性を再計算しようとするソリューションは、すぐに遅くなりすぎます。 

微妙だが重要なモデリング ポイントは、動きが固定サイズのジャンプに制限されていることです。$k$、位置が独立した等差数列モジュロに分割されることを意味します$k$。 これにより、単一ステップでの任意の再配置が防止され、構造化された遷移グラフが強制されます。 

いくつかの危険な状況が重要になります。 

禁止された間隔が現在位置に影響を与えない場合は、何もしないことが常に有効です。 たとえば、次の場合$n = 10$、$s = 5$、 そして$[l_1, r_1] = [7, 9]$の場合、5 に留まることは自明のことながら安全です。 

現在位置が禁止区域内にある場合は、攻撃が行われる前にそこから離れなければなりません。 たとえば、あなたが 6 で、禁止されたセグメントが$[4, 8]$の場合、4 の左または 8 の右のいずれかに移動する必要がありますが、移動の制約により 1 つのステップで両側に到達できない場合があります。 

動作ステップが禁止されたセグメント構造に比べて大きすぎる場合、単純な「常にすぐに飛び去る」戦略は将来の制約を無視し、不必要にエネルギーを浪費する可能性があるため失敗する可能性があります。 

## アプローチ

 ブルートフォースの観点では、これを時間展開グラフ上の最短経路問題として扱います。 各状態は時間と位置のペアで構成され、遷移は滞在または固定長テレポートの適用に対応します。 毎回レイヤーが内部のすべてのノードを禁止します$[l_i, r_i]$。 このグラフ上で最短パスを実行するのは正しいですが、グラフのサイズは$O(nm)$、それは完全に実行不可能になります。 

重要な構造上の観察は、動きがライン全体で任意に行われるのではなく、固定されたステップで発生するということです。 これにより、アリーナが独立したチェーンに分割され、各チェーンは折れ線グラフのように動作します。 各チェーンでは、基本的に 1 秒あたり 1 ステップ左または右に移動します。問題は、移動回数を最小限に抑えながら、時間の経過とともに禁止された間隔を回避する有効な位置を維持することになります。 

最適化に関する洞察は、移動する唯一の理由は、現在の位置が無効になった場合であるということです。 それが発生した場合、最善のアクションは、禁止されたセグメントの外側の最も近い有効な位置に移動することです。これ以上移動すると、現在のステップでの実現可能性が改善されずに厳密にコストが増加するためです。 コストは総変位のみに依存し、「オーバーシュート」から恩恵を受ける将来の状態の相互作用には依存しないため、この貪欲な補正で十分です。 

これにより、問題は 1 つの位置を追跡し、それが禁止された間隔に入った場合にのみ修復されるようになります。

 ## アルゴリズムのチュートリアル

 このアルゴリズムは、現在の位置を表す単一の変数を維持し、移動が必要になるたびにエネルギーコストを蓄積します。 

1. ポジションを次のように初期化します。$x = s$そして総エネルギーは0になります。 
2. 1秒ごとに$i$、禁止されたセグメントを読み取ります$[l_i, r_i]$。 
3. 現在のポジションの場合$x$間隔外です$[l_i, r_i]$、何もせずに次の秒に進みます。 動きを必要としないため、エネルギーが消費されません。 
4. もし$x$中にある$[l_i, r_i]$、安全な位置に移動する必要があります。 候補者は次の 2 人だけです。$l_i - 1$そして$r_i + 1$、それらが範囲内にあると仮定します。 
5. これら 2 つの境界位置のうち近い方を選択します。$|x - (l_i - 1)|$そして$|x - (r_i + 1)|$。 そこに移動し、移動距離をエネルギーコストに加算します。 
6.アップデート$x$この新しい位置に移動して続行します。 

このローカル修復手順が正しい理由は、禁止された間隔内に入ると、有効な位置はすべてその外側にあり、コストは距離に関して純粋に線形であるためです。 最適な解はその区間を終了する必要があり、最も近い終了により、その時点での実現可能性に影響を与えることなくコストが最小限に抑えられます。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは、選択された位置が現在の攻撃に対して有効であることを確認します。 修復が必要な場合は、禁止された間隔の外側で最も近い実行可能なポイントが選択されます。 より遠くにある代替移動は、現在のタイム ステップでは何のメリットもなくコストが厳密に増加します。また、間隔内にいることは直ちに致命的なため、終了を遅らせることは不可能です。 これにより、貪欲な修正が局所的に最適になり、決定は現在の違反にのみ依存するため、シーケンス全体にわたって全体的に最適なままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, s = map(int, input().split())
        x = s
        energy = 0

        for _ in range(m):
            l, r = map(int, input().split())

            if l <= x <= r:
                left = l - 1
                right = r + 1

                best = None
                best_cost = 10**18

                if left >= 1:
                    best = left
                    best_cost = abs(x - left)

                if right <= n:
                    cost = abs(x - right)
                    if cost < best_cost:
                        best = right
                        best_cost = cost

                energy += best_cost
                x = best

        print(energy)

if __name__ == "__main__":
    solve()
```このソリューションは、現在の位置のみを保持し、それを貪欲に更新します。 唯一の微妙な点は、禁止された間隔がアリーナの端に触れたときに境界を正しく処理することです。 このような場合、有効なエスケープ方向は 1 つだけ存在するため、アルゴリズムは自然にそれを選択します。 

コストの更新は絶対距離を使用して行われます。これは、移動がラインに沿った単位ステップの遷移として解釈される場合に必要なテレポート操作の数と一致します。

        out = []
        for _ in range(t):
            n, m, s = map(int, input().split())
            x = s
            energy = 0
            for _ in range(m):

                            best_cost = cost
                    energy += best_cost
                    x = best
            out.append(str(energy))
        return "\n".join(out)

 ## 特殊なケース

 開始位置がすでにすべての禁止セグメントの外側にある場合、アルゴリズムはまったく移動を実行しません。 たとえば、すべての間隔を右にずらして 1 から開始すると、修復がトリガーされないため、エネルギーはゼロになります。 

禁止区間が片側を除くすべてをカバーする場合、たとえば$[2, n]$、唯一の有効なエスケープは位置 1 に移動することです。境界候補が 1 つだけ存在し、それが自動的に選択されるため、アルゴリズムがこれを処理します。 

現在の位置が禁止された間隔の境界に正確に位置する場合でも、その間隔は包括的であるため、安全でないとみなされます。 その場合、アルゴリズムは正しく移動をトリガーし、明示的にチェックすることでオフバイワンの間違いを回避します。$l \le x \le r$。
