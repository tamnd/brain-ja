 ## 解決策
 ## 問題の理解

 それぞれのサイズの 2 つのマルチセットが与えられています$n$。 それらを 2 行の数字として考えてください。$s$そして$t$、それぞれが正確に含む$n$要素。繰り返しが許可されます。 

1 回の操作で、次から 1 つの要素を選択します。$s$からの 1 つの要素$t$ただし、値が異なる場合に限ります。 両方の要素を削除します。 両方のマルチセットからすべてを削除できるか、行き詰まるまで、この操作を繰り返します。 

タスクは、そのような操作を使用して両方のマルチセットを完全に空にすることが可能かどうかを判断することです。 

すべての操作で各サイドから 1 つの要素が正確に削除されるため、成功したプロセスは正確に次の要素で構成されている必要があります。$n$操作、すべての要素をペアにする$s$要素が 1 つだけある$t$。 唯一の制限は、同じ値をペアにすることができないことです。 

制約が大きい: すべてのテスト ケースにわたる要素の合計数が次の値に達します。$2 \cdot 10^5$。 これにより、テスト ケースごとの 2 次関数は即座に除外され、テストごとの並べ替えも、慎重に制限された場合にのみ許容されます。 ソリューションでは、各テスト ケースを線形または線形計算に効果的に削減する必要があります。 

単純なアプローチでは、貪欲にマッチングをシミュレートしたり、明示的な 2 部マッチングを構築したりすることもあります。 これは失敗します。多くの値が繰り返される最悪の場合のマルチセットでは、互換性チェックが多すぎて、一般的なマッチングが遅すぎるためです。 

素朴な貪欲マッチングの微妙な失敗例は、ローカルな選択が将来のペアリングをブロックする場合に発生します。 たとえば、グローバルな頻度制約を考慮せずに、常に見た目が同じ値を最初にペアにすると、有効な完全一致が存在する場合でも行き詰まる可能性があります。 

中核的な問題はグローバルです。両方のマルチセットにわたってあまりにも頻繁に出現する値は、ペアリングの機会をあまりにも多く「消費」する可能性があり、後で同じ値のペアリングを避けることができなくなります。 

## アプローチ

 ブルートフォース的な観点は、これを 2 部グラフの問題として考えることです。 我々は持っています$n$左側のノード (の要素)$s$） そして$n$右側（要素$t$）。 すべてのペア$(x, y)$次の場合を除いて許可されます$x = y$。 完璧なマッチングを望んでいます。 

単純な解決策は、完全なグラフを構築し、最大 2 部マッチング アルゴリズムを実行することです。 グラフは高密度で、ほぼすべてのエッジが存在するため、複雑さはおおよそ次のようになります。$O(n^2)$最悪の場合のテストごとに。 合計あり$n$まで$2 \cdot 10^5$、これでは遅すぎます。 

重要な点は、ペアリングを妨げるのは値が等しいことだけであるということです。 したがって、構造全体は、位置ではなく、各値の頻度カウントのみに依存します。 値の場合$v$両方のマルチセットに何度も出現しますが、それらをペアにすることはできないため、これらの出現は相互に大きく制限します。 

個々の要素の観点から考えるのではなく、すべてを頻度数に圧縮します。 それぞれの値について$v$、 させて$a_v$数えてください$s$、 そして$b_v$その数は$t$。 

次に、何が問題になる可能性があるかを考えてみましょう。 特定の値が両方の配列に何度も出現する場合は、次のようにします。$a_v + b_v$が非常に大きい場合、それらの出現のほとんどは他の値の要素と組み合わせる必要があります。 しかし、あるのは$n$反対側に要素があるため、ハードな容量制約が生じます。 

正しい条件は、すべての値に対して単純であることがわかります。$v$、両方の配列にわたる合計出現数が次を超えてはなりません。$n$、 意味$a_v + b_v \le n$。 これがすべての値に当てはまる場合、有効なペアが常に存在します。 そうしないと、値によっては過剰なクロスペアリングが強制されるため、これは不可能です。

 | ブルートフォースマッチング |$O(n^2)$|$O(n)$| 遅すぎる |
 | 周波数チェック |$O(n)$テストごと |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 問題を頻度のカウントと単純な制約のチェックに縮小します。 

1. 両方のマルチセットを読み取り、すべての値の出現をカウントします。$s$そして$t$。 

ペアリングの実現可能性に関して重要なのは多重度のみであるため、このステップでは位置推論が周波数推論に置き換えられます。 
2. 個別の値ごとに$v$、合計を計算します$a_v + b_v$。 

これは、この値が両側に何回出現するかを測定します。 
3. この合計がこれを超えているかどうかを確認します$n$。 

存在する場合は、有効な一連の操作は存在しないと直ちに結論付けます。 その理由は、$n$反対側の要素が一致するため、単一の値のコピーが多すぎると、避けられない競合が発生します。 
4. 条件に違反する値がない場合は、可能であることを出力します。 

この場合、分布は十分にバランスが取れているため、同じ値の一致を強制されることなく常にペアを配置できます。 

### なぜ効果があるのか

 それぞれの価値観を考える$v$それ自体とペアリングできない「タイプ」として。 あらゆる出来事が起こる$v$で$s$一部の非一致のものと一致する必要があります$v$の要素$t$、その逆も同様です。 しかないので、$n$両側の要素の合計は、単一の値によって作成される合計需要が、利用可能なマッチング容量を超えることはできません。 条件$a_v + b_v \le n$任意の値があまりにも多くのペアリング スロットを独占することを正確に防ぎ、等しいペアを回避する完全なマッチングを常に配置できることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import Counter

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        s = list(map(int, input().split()))
        t = list(map(int, input().split()))
        
        cs = Counter(s)
        ct = Counter(t)
        
        ok = True
        for v in set(cs.keys()) | set(ct.keys()):
            if cs[v] + ct[v] > n:
                ok = False
                break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```このソリューションは完全に周波数マップを中心に構築されています。 主要な実装上の選択は、両方のカウンターのキー セットをマージし、どちらかのマルチセットに表示されるすべての値が 1 回だけチェックされるようにすることです。 違反が見つかった場合に不必要な繰り返しを避けるために、早期に終了することが重要です。 

このロジックでは、明示的にペアリングを構築しようとしません。 実現可能性を検証するだけですが、構造上の制約は純粋に値ごとであるため、これで十分です。

## テストケース```python
import sys, io
from collections import Counter

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    T = int(input())
    out = []
    for _ in range(T):
        n = int(input())
        s = list(map(int, input().split()))
        t = list(map(int, input().split()))
        
        cs = Counter(s)
        ct = Counter(t)
        
        ok = True
        for v in set(cs.keys()) | set(ct.keys()):
            if cs[v] + ct[v] > n:
                ok = False
                break
        
        out.append("YES" if ok else "NO")
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースは、両方のマルチセットが同一であり、単一の繰り返し値で構成されている場合です。 例えば、$s = t = [1,1,\dots,1]$。 ここでは、合計頻度が次のとおりであるため、条件はすぐに失敗します。$2n$を超える$n$。 アルゴリズムは、ペアリングを試行せずにこれを正しく拒否します。 

もう 1 つのエッジ ケースは、2 つのマルチセット間で値が完全に素である場合です。 例えば、$s = [1,2,3]$そして$t = [4,5,6]$。 等価制約がトリガーされないため、すべてのペアは有効です。 頻度チェックは、毎回行われるため、簡単に合格します。$a_v + b_v = 1$。 

より微妙なケースは、1 つの値が 1 つのマルチセットを支配しているが、もう 1 つの値には存在しない場合です。 例えば、$s = [1,1,1,1]$、$t = [2,2,2,2]$。 カウントが偏っていても、各値の合計は正確に一致します$n$したがって、アルゴリズムは受け入れ、有効なクロスペアリングが存在します。
