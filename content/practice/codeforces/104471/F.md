 ## 解決策
 ## 問題の理解

 私たちは、数値をその桁の二乗和で繰り返し置き換える桁変換プロセスに取り組んでいます。 任意の正の整数から開始して、この変換は最終的に 1 に達するか、1 を決して含まない繰り返しサイクルに陥ります。最終的に 1 に達する数値はハッピー ナンバーと呼ばれます。 

タスクは、単一の数値を分類することではなく、複数の範囲クエリに答えることです。 各クエリでは、10 進数 200 桁までの 2 つの非常に大きな整数が与えられ、この値を含む範囲内で満足のいく整数がいくつあるかが尋ねられます。 

主な問題は、範囲のエンドポイントが大きすぎて直接反復できないことです。 標準型ではそれらを整数として格納することさえ不可能であるため、ソリューションは文字列を操作し、数字ベースの推論に依存する必要があります。 

この制約は、各数値を個別に評価しようとするソリューションが不可能であることを意味します。 サイズ 10^18 以上の範囲を反復処理することさえ不可能であり、ここでは範囲が天文学的に大きくなる可能性があります。 唯一の実行可能なアプローチは、10 進表現で機能する桁動的プログラミング手法を使用して数値を数える方法です。 

大きな間隔を文字列として処理する場合、微妙なエッジケースが発生します。 たとえば、「1」から「1」までの区間は、1 が満足であれば 1 を返すはずですが、単純な減算や解析エラーにより、1 桁または等値境界のケースが簡単に壊れる可能性があります。 もう 1 つの重要なエッジ ケースは、数字 DP での先行ゼロの処理です。「00123」のような数字は明示的には存在しませんが、実装が不注意な場合は構築中に現れる可能性があるためです。 

## アプローチ

 直接的な総当たり手法では、各間隔のすべての数値をチェックし、桁の二乗和変換を繰り返し適用し、それが 1 に達するかどうかをテストします。正確性は簡単ですが、コストは法外に高くなります。 単一の数値をチェックするだけでも複数の変換が必要になる可能性がありますが、実際のボトルネックは候補の数です。間隔には最大 10^200 の整数が含まれる可能性があり、列挙は不可能です。 

重要な観察は、「幸せ」特性は数字の二乗和プロセスにのみ依存し、このプロセスは大きな数を非常に小さな状態空間に急速に崩壊させるということです。 変換を繰り返し適用すると、d 桁の数値の桁の二乗和の最大値は 81d であり、増加が遅いため、値は最終的に固定限界を下回ります。 d が大きい場合、この上限はまだ管理可能であり、数回の反復の後、すべての数値が有界サイクル空間に入ります。 

これにより、2 段階の削減が可能になります。 まず、考えられるすべての中間合計のプロセスをシミュレートすることにより、狭い範囲内のどの値が「最終的に満足」であるかを事前計算します。 第 2 に、元の問題を、範囲内の数字の数がそれぞれの可能な桁二乗和の軌道を生成するかを数えることに縮小します。これは古典的な桁 DP 計数問題です。 

それぞれの数値をチェックする代わりに、桁の二乗和を追跡し、それらを事前に計算された「幸せかどうか」テーブルにマッピングすることで、X までの数値が最終的に 1 に達する数を計算します。 次に、各クエリはプレフィックスの違いを使用して回答されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 数値サイズの指数 | お(1) | 遅すぎる |
 | 桁 DP + サイクル事前計算 | O(t・d・S) | O(S) | 承認済み |

 ここで、d は最大 200 桁で、S は有界平方和状態空間です。 

## アルゴリズムのチュートリアル

1. 最大 200 桁の可能な最大桁二乗和を事前計算します。 各桁は最大 81 に寄与するため、最大合計は 200 × 81 = 16200 になります。これは、すべての中間変換の状態空間を制限します。 
2. この範囲内の任意の値に対する桁二乗和プロセスをシミュレートする関数を構築します。 それぞれの値 s について、s が 1 に達するかサイクルに入るまで、s をその桁の二乗和に繰り返し置き換えます。 s が幸せかどうかをマークします。 
3. 結果をブール配列に保存します`good[s]`合計状態が最終的に 1 になるかどうかを示します。 
4. 桁DP関数を定義する`count(x)`これは、[0, x] 内の整数値がいくつあるかを返します。 DP 状態は、数字列内の位置、プレフィックスに厳密であるかどうか、およびこれまでに蓄積された現在の数字の二乗和を追跡します。 
5. DP 遷移では、次の各桁について、累計平方和を更新します。 数値が完全に構築されると、最終的な累積合計が照合されます。`good[]`この数値が答えに寄与するかどうかを判断します。 
6. 各クエリ [l, r] について、次の値を計算します。`count(r) - count(l - 1)`ここで、減算は文字列として表現された大きな整数に対して行われます。 
7. l が「0」の場合、または文字列のデクリメントに多くの桁にわたる借用が必要な場合は、エッジ減算を慎重に処理します。 

正しさは、桁の二乗和が数字の桁によって完全に決定されるという事実に依存しており、最終的な幸福度は、すでに事前計算されている最終的な還元状態にのみ依存します。 

### なぜ効果があるのか

 すべての数値は、決定論的関数によってその桁から有限状態 (桁の二乗和) にマッピングされます。 その状態は、数値が形成されると、元の大きさとは無関係に進化します。 DP はすべての有効な数字の組み合わせを 1 回だけ列挙し、各組み合わせはその合計状態の事前計算された終了動作を使用して正しく分類されます。 これにより、カウントされた DP パスと間隔内の整数の間の全単射が保証されるため、数値が見逃されたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAX_SUM = 200 * 81

# precompute next state for sum-of-squares process
def next_val(x):
    s = 0
    while x:
        d = x % 10
        s += d * d
        x //= 10
    return s

# detect happy states
good = [False] * (MAX_SUM + 1)
vis = [0] * (MAX_SUM + 1)

def dfs(x):
    stack = []
    path = []
    cur = x
    while True:
        if cur == 1:
            for v in path:
                good[v] = True
            return True
        if vis[cur] == 1:
            for v in path:
                good[v] = good[cur]
            return good[cur]
        if vis[cur] == 2:
            for v in path:
                good[v] = good[cur]
            return good[cur]
        vis[cur] = 1
        path.append(cur)
        cur = next_val(cur)

# precompute
for i in range(1, MAX_SUM + 1):
    if not vis[i]:
        dfs(i)
good[1] = True

# digit DP
from functools import lru_cache

def count(x):
    if x <= 0:
        return 0
    s = str(x)

    @lru_cache(None)
    def dp(pos, tight, sm):
        if pos == len(s):
            return 1 if good[sm] else 0
        limit = int(s[pos]) if tight else 9
        res = 0
        for d in range(limit + 1):
            res += dp(pos + 1, tight and d == limit, sm + d * d)
        return res

    return dp(0, True, 0)

def solve():
    t = int(input())
    MOD = 10**9 + 7
    for _ in range(t):
        l, r = input().split()
        def to_int_dec(s):
            return int(s)

        def dec_one(s):
            s = list(s)
            i = len(s) - 1
            while i >= 0 and s[i] == '0':
                s[i] = '9'
                i -= 1
            if i >= 0:
                s[i] = str(int(s[i]) - 1)
            return ''.join(s).lstrip('0') or '0'

        r_val = int(r)
        l_val = int(l)
        ans = (count(r_val) - count(l_val - 1)) % MOD
        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、どの桁の二乗和が最終的に 1 になるかを事前に計算することから始まります。状態空間は 16200 で区切られているため、これは 1 回だけ実行されます。DFS は、1 またはサイクルに達するまで遷移を探索し、それに応じて状態をマークします。 

メインのカウント ロジックは桁 DP を使用します。 州`(pos, tight, sm)`累積二乗和を維持しながら数値の接頭辞を構築する方法が何通りあるかを表します。 構築の最後に、DP は、結果として得られる合計状態が良好であるとマークされているかどうかをチェックします。 

クエリごとに、範囲をプレフィックス数に変換します。 引き算`count(r) - count(l - 1)`包含範囲の標準です。 

実装の微妙な詳細の 1 つは、非常に大きな整数の処理です。 Python は大きな整数をサポートしていますが、意図したソリューションは一般的なコンテキストでの文字列演算に依存しています。 現在のコードは int にキャストすることで簡略化されていますが、これは環境で大きな整数が許可されている場合にのみ安全です。

これらのトレースは、DP が数値を正確に 1 回列挙し、事前計算された最終状態によってそれらを分類していることを確認します。

 ## 特殊なケース

 重要なエッジ ケースは、[13, 13] など、間隔の境界が等しい場合です。 DP は、これを完全なプレフィックス数から前のプレフィックス数を引いたものとして正しく処理する必要があります。 アルゴリズムは計算します`count(13) - count(12)`、そして 13 は 1 につながる合計状態 10 を介してハッピーとして分類されるため、正確に 1 に寄与します。 

もう 1 つのエッジ ケースは、1 から始まる間隔です。`l - 1`、負の数を生成しないように注意する必要があります。 実装では、これは DP ラッパー内の非正の入力に対して 0 を返すことによって処理されます。 

最後の微妙なケースは、桁数が多い非常に大きな数値です。 数値自体は巨大ですが、DP は桁位置と累積平方和のみに依存するため、パフォーマンスは安定しています。
