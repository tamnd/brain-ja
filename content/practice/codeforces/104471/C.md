 ## 解決策
 ## 問題の理解

 各エッジに重みがある有向グラフが与えられ、有向エッジに従ってグラフ内を移動することができます。 ウォークでは頂点とエッジを再利用できます。 このようなウォークでは、エッジの重みのマルチセットを取得し、通常の方法でその中央値、つまりソート後の中央の要素を定義します。 

タスクは、固定歩行の中央値を計算することではなく、少なくとも長さの歩行を構築することです。`k`この中央値を最大化するか、そのようなウォークは存在しないと報告します。 

主な難点は、ウォークの長さは任意に設定できることですが、ここで考慮するのはその中央値だけです。中央値は、選択したしきい値を上または下のウォーク内のエッジの数に依存します。 

制約の構造は厳密です。`k ≤ 50`、 しかし`m`そして`n`それぞれ最大 2×10^5 と 10^5 まで大きくなります。 これは、歩行を明示的に列挙できないことを直ちに示唆しています。 長い道や考えられるすべての歩行をシミュレートしようとするアプローチは不可能です。 の小さな値`k`これは、答えがグローバル パスの列挙ではなく、グラフ内の短い構造パターンにのみ依存することを示唆しています。 

単純な間違いは、最適な長さのパスを正確に計算できると仮定することです。`k`そしてそれを任意に拡張します。 中央値はエンドポイントのパス値だけではなく分布に依存するため、これは失敗します。 

## アプローチ

 強引なアイデアは、少なくとも長さの可能なすべての散歩を列挙することです。`k`、中央値を計算し、最大値を取得します。 これは原理的には正しいですが、グラフ内のサイクルにより歩行数が指数関数的に増加するため、完全に実行不可能です。 

重要な観察は、中央値条件を意思決定の問題として再構成できるということです。 候補値を固定するとします`X`。 少なくとも一定の長さの歩道が存在するかどうか知りたい`k`中央値は少なくとも`X`。 これは、歩行においてエッジの少なくとも半分に少なくとも重みがあると言うのと同じです。`X`。 

したがって、各エッジは次の場合に良好であると分類できます。`w ≥ X`それ以外の場合は悪いです。 問題は、少なくともある程度の長さの散歩道を見つけられるかということだ。`k`良好なエッジの数が不良エッジに比べて十分に多い場合は?

 これは、エッジの重みが次のように削減されたグラフ問題に変換されます。`+1`良好なエッジと`-1`悪いエッジの場合。 次に、少なくとも一定の長さの歩道が存在するかどうかを尋ねます。`k`プレフィックス合計のシフトされたしきい値条件の下で、非負のバランスで。 なぜなら`k`が小さい場合、パスの長さと頂点にわたって DP を使用して達成可能な最良の状態を追跡し、あるサイクルによって無限の改善が可能かどうかを検出できます。 

この構造により、実現可能性は単調であるため、答えに対する二分探索が可能になります。`X`。

 ## アルゴリズムのチュートリアル

 答えを二分探索します`X`、有効なウォークが存在するかどうかを確認します。 

1. 候補中央値を修正する`X`。 各エッジを次のように分類します。`+1`もし`w ≥ X`、 さもないと`-1`。 これにより、問題は歩行に沿ってスコアを最大化することに変換されます。 
2. DP を定義します。`dp[t][v]`頂点で達成可能な最大スコアです`v`正確に使用して`t`エッジ。 以来`k ≤ 50`、最大の長さのパスのみを考慮する必要があります。`2k`なぜなら、実現可能性の中央値を維持しながら、長いウォークはいつでも切り詰めたり圧縮したりできるからです。 
3. すべて初期化する`dp`長さの状態`0`として`0`すべての頂点で。 
4. エッジを緩和することによる遷移: 各ステップで、更新`dp[t+1][v] = max(dp[t+1][v], dp[t][u] + value(u→v))`。 
5.長さまで充填後`2k`が存在するかどうかを確認します。`t ≥ k`そして頂点`v`スコア条件はエッジの少なくとも半分が良好であることを意味します。 これを翻訳すると、`dp[t][v] ≥ 0`。 
6. そのような状態が存在する場合、候補は`X`は実現可能なので、二分探索を上に移動します。 それ以外の場合は、下に移動します。 

### なぜ効果があるのか

 固定しきい値の場合`X`、変換により、中央値条件がパス合計のバランス条件に減らされます。 有効な中央値は、十分なエッジがしきい値を超えるウォークに正確に対応します。 最適な歩行は、制限された長さにサイクルを加えたプレフィックスに分解できるため、制限された長さへの注意が制限されます。`2k`実現可能性を判断するには十分です。 次に、二分探索により、しきい値が最大化されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(n, edges, k, x):
    # build transformed edges
    adj = [[] for _ in range(n)]
    for u, v, w in edges:
        val = 1 if w >= x else -1
        adj[u].append((v, val))

    # dp[t][v]
    NEG = -10**18
    dp = [[NEG] * n for _ in range(k * 2 + 1)]

    for v in range(n):
        dp[0][v] = 0

    for t in range(k * 2):
        for u in range(n):
            if dp[t][u] == NEG:
                continue
            for v, val in adj[u]:
                if dp[t][u] + val > dp[t + 1][v]:
                    dp[t + 1][v] = dp[t][u] + val

    for t in range(k, 2 * k + 1):
        for v in range(n):
            if dp[t][v] >= 0:
                return True
    return False

def solve():
    n, m, k = map(int, input().split())
    edges = [tuple(map(int, input().split())) for _ in range(m)]

    lo, hi = 1, 10**9
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if check(n, edges, k, mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```## 実用的な例

 小さなグラフを考えてみましょう。 

入力:```
3 3 2
1 2 5
2 3 1
3 1 4
```候補の中央値をテストします`X = 3`。 

エッジは次のようになります。 

| エッジ | 重量 | 変換された |
 | --- | --- | --- |
 | 1→2 | 5 | +1 |
 | 2→3 | 1 | -1 |
 | 3→1 | 4 | +1 |

 短い散歩の DP では、正のバランスを持つサイクル 1→2→3→1 が見つかります。これは、中央値 ≥ 3 が達成可能であることを意味します。 

増えたら`X`6 にすると、すべてのエッジが`-1`したがって、長さ ≥ k の正のスコアの歩行は存在せず、実現可能性は失われます。 

これは、二分探索境界の動作を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(log W · k · m) | 二分探索ステップごとの k 状態にわたる DP |
 | スペース | O(k · n) | 制限された長さの DP テーブル |

 小さな制約`k ≤ 50`これにより、大きなグラフに対しても DP が実行可能であることが保証され、重みに対する二分探索では対数係数のみが導入されます。

 ## 特殊なケース

 すべてのエッジが候補しきい値を下回る場合、変換されたグラフには次の値のみが含まれます。`-1`したがって、長い歩行はすぐにマイナスのスコアを蓄積し、実現可能性を正しく拒否します。 すべてのエッジがしきい値を超えている場合、すべてのウォークが有効であるため、どのサイクルでも正のバランスで任意の長いウォークを許可し、候補を正しく受け入れます。 いつ`k = 1`の場合、問題はエッジがしきい値を満たすかどうかをチェックすることに帰着しますが、DP は依然としてこれを長さ 1 の実現可能な状態としてキャプチャします。
