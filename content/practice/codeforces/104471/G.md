### なぜ効果があるのか

 重要な不変条件は、どの時点でもフェンウィック ツリーが現在の値を正しく表すことです。$a$、およびそのすべての要素$b$まさにいくつかの現象の 1 回の発生です$a_i$1つのインターバル内で。 間隔構造は決して変わらないため、からのマッピングは$b$へのインデックス$(interval, position)$ペアは静的です。 したがって、すべてのクエリは$b$のセグメントにわたる互いに素な寄与に分解できます。$a$、それらの寄与を合計すると正確さが保たれます。

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_add(self, l, r, v):
        self.add(l, v)
        if r + 1 <= self.n:
            self.add(r + 1, -v)

    def point(self, i):
        return self.sum(i)

n, m, q = map(int, input().split())
intervals = []
lengths = []
pref = [0]

for _ in range(m):
    l, r = map(int, input().split())
    intervals.append((l, r))
    lengths.append(r - l + 1)
    pref.append(pref[-1] + (r - l + 1))

bit = Fenwick(n)

for _ in range(q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 1:
        _, l, r, v = tmp
        bit.range_add(l, r, v)
    else:
        _, L, R = tmp

        def get(idx):
            lo, hi = 1, m
            while lo <= hi:
                mid = (lo + hi) // 2
                if pref[mid] < idx:
                    lo = mid + 1
                else:
                    hi = mid - 1
            return lo

        res = 0
        cur = L

        while cur <= R:
            j = get(cur)
            l, r = intervals[j - 1]

            start_pos = pref[j - 1] + 1
            end_pos = pref[j]

            seg_l = max(cur, start_pos)
            seg_r = min(R, end_pos)

            a_l = l + (seg_l - start_pos)
            a_r = l + (seg_r - start_pos)

            # sum over a[a_l..a_r]
            for i in range(a_l, a_r + 1):
                res += bit.point(i)

            cur = seg_r + 1

        print(res, end=" ")

内側のループは、次のセグメントをマップします。$b$のセグメントに戻る$a$。 重要なステップは、間隔内のオフセットを実際のインデックスに変換することです。$a$。 マッピングが完了すると、ソリューションはフェンウィック ツリーからの値を単純に蓄積します。 

微妙な点の 1 つは、クエリが複数の間隔にまたがる可能性があるため、ループが進行することです。`cur`現在の間隔スライスの終わりまで。 もう 1 つの重要な点は、フェンウィック ツリーがポイント クエリに使用されるため、マップされたセグメント内の各要素を反復処理することです。

 重要なエッジ ケースの 1 つは、クエリが$b$間隔の途中で始まり、別の間隔で終了します。 アルゴリズムは、クエリを間隔の境界に合わせてセグメントに分割することでこれを処理し、重複が二重にカウントされないようにします。
