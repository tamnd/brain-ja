 ## 解決策
 ## 問題の理解

 同じ長さの 2 つのバイナリ文字列が与えられています。 各キャラクターはどちらかです`'0'`または`'1'`。 位置ごとに、2 つの文字列の文字を比較します。 

2 つの文字が異なる場合、結果の文字列は次のようになります。`'1'`その位置で。 それらが同じ場合、結果の文字列は次のようになります。`'0'`。 

この演算は、まさにバイナリ XOR 演算を桁ごとに適用したものです。 

たとえば、1 つの文字列が`'1'`そしてもう一方は`'0'`、出力は次のようになります`'1'`。 両方ともそうだった場合`'1'`または両方です`'0'`、出力は次のようになります`'0'`。 

文字列の長さは最大でも 100 であり、非常に小さいです。 文字列上の単純な線形スキャンでも、十分に高速です。 文字列の長さに比例する時間計算量を持つアルゴリズムは、制限内で即座に終了します。 

この問題の主な危険はパフォーマンスではなく正確さです。 小さな実装ミスにより、誤ったバイナリ文字列が静かに生成される可能性があります。 

簡単な間違いの 1 つは、先頭のゼロを保持することを忘れることです。 考慮する：```
Input:
001
001
```正しい出力は次のとおりです。```
000
```誰かが文字列を整数に変換したり、逆に変換したりすると、誤って単に文字列を出力してしまう可能性があります。`0`この問題ではすべての位置を維持する必要があるため、これは間違っています。 

もう 1 つのよくある間違いは、演算を XOR ではなく 2 進加算であると誤解することです。 例えば：```
Input:
1
1
```正しい出力:```
0
```不注意な実装で加算法 2 を誤って使用したり、キャリー ビットを処理したりすると、誤った結果が生じる可能性があります。 

3 番目の微妙なケースは、すべての比較が変化する交互パターンです。```
Input:
1010
0101
```正しい出力:```
1111
```これにより、実装が文字列を完全な 2 進数として解釈するのではなく、各位置を独立して比較するかどうかがチェックされます。 

## アプローチ

 最も直接的なアプローチは、文字列を 1 文字ずつ処理することです。 すべてのインデックスについて、2 つの文字を比較します。 異なる場合は追記`'1'`答えに。 それ以外の場合は追加`'0'`。 

最大長が 100 にすぎないため、これで問題はすでに効率的に解決されています。文字列に対して複数のパスを実行したとしても、実行時間は依然としてわずかです。 

より単純なバージョンでは、文字列の連結を使用して答えを繰り返し構築します。```
ans += '1'
```ループの中。 Python では、文字列は不変であるため、非常に大きな入力の場合、文字列の連結を繰り返すと非効率になる可能性があります。 連結するたびに新しい文字列が作成されます。 長さが 100 の場合、これは依然として完全に問題なく機能しますが、より大きな問題では、このパターンは二次関数になる可能性があります。 

よりクリーンなアプローチは、文字をリストに集めて、最後に一度結合することです。 重要な点は、すべての出力桁が対応する入力桁のペアにのみ依存するということです。 どの位置も他の位置に影響を与えません。 つまり、キャリー、前処理、または高度なデータ構造は必要ありません。 

タスク全体は単純な線形比較に帰着します。

 | --- | --- | --- | --- |
 | ブルートフォース文字列連結 | 理論上は O(n²) | O(n) | 承認済み |
 | 最適な文字ごとのビルド | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのバイナリ文字列を読み取ります。 

どちらの文字列も同じ長さであることが保証されているため、インデックスごとに安全に処理できます。 
2. 回答文字を保存するための空のリストを作成します。 

リストを使用すると、構築中に文字列の再割り当てが繰り返されることがなくなります。 
3. すべての位置を反復処理します。`0`に`n - 1`。 

各位置は他の位置から独立しています。 
4. 現在のインデックスの文字を比較します。 

文字が異なる場合は追記`'1'`回答リストに追加します。 それ以外の場合は追加`'0'`。 

これは、問題の XOR 定義と直接一致します。 
5. 収集したすべての文字を 1 つの文字列に結合します。 

最後の文字列では、先頭のゼロを含むすべての位置が保持されます。 
6. 結果を印刷します。 

### なぜ効果があるのか

 あらゆるインデックスに対して`i`、問題は答えの数字を完全にペアから定義します。`(a[i], b[i])`。 

アルゴリズムは、このルールをすべての位置に独立して適用します。 

- 等しい数字が生成されます`'0'`- 異なる数字が生成されます`'1'`すべての位置が正しく独立して処理されるため、完全な結果の文字列は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a = input().strip()
b = input().strip()

ans = []

for x, y in zip(a, b):
    if x != y:
        ans.append('1')
    else:
        ans.append('0')

print(''.join(ans))
```最初の 2 行はバイナリ文字列を読み取り、末尾の改行文字を削除します。`strip()`。 

リストへの追加が効率的であるため、回答はリストに保存されます。 すべてのポジションを処理した後、`''.join(ans)`1 回の操作で最終的な文字列を作成します。 

ループは使用します`zip(a, b)`両方の文字列の一致する位置を同時に反復処理します。 この問題では等しい長さが保証されているため、すべての文字ペアが正しく配置されます。 

比較`x != y`ステートメントの XOR 条件と完全に一致します。 整数変換は必要ないため、先頭のゼロや 2 進数の算術演算に伴う間違いを避けることができます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    a = input().strip()
    b = input().strip()

    ans = []

    for x, y in zip(a, b):
        if x != y:
            ans.append('1')
        else:
            ans.append('0')

    print(''.join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("1010100\n0100101\n") == "1110001\n", "sample 1"

# minimum size
assert run("0\n0\n") == "0\n", "single equal digits"

# minimum size different
assert run("1\n0\n") == "1\n", "single different digits"

# all equal values
assert run("11111\n11111\n") == "00000\n", "all positions equal"

# alternating pattern
assert run("1010\n0101\n") == "1111\n", "every position differs"

# leading zeros preserved
assert run("0011\n0011\n") == "0000\n", "leading zeros must remain"

# maximum-style repeated pattern
a = "01" * 50
b = "10" * 50
expected = "11" * 50 + "\n"
assert run(f"{a}\n{b}\n") == expected, "length 100 case"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`0 / 0`|`0`| 可能な最小の入力 |
 |`1 / 0`|`1`| 異なる 1 桁 |
 |`11111 / 11111`|`00000`| 等しい文字列 |
 |`1010 / 0101`|`1111`| それぞれの立場は異なります |
 |`0011 / 0011`|`0000`| 先頭のゼロは保持されます。 
| 長さ 100 交互の文字列 | 全て`1`s | 最大制約動作 |
