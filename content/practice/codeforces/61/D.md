 ## 解決策
 ## 問題の理解

 シャープールがすべての都市を少なくとも 1 回訪問するために移動しなければならない最小距離を見つけるように求められます。 都市はツリー構造で接続されています。つまり、正確に$n-1$双方向の道路と、任意の 2 つの都市間の独自の経路。 シャープールは都市 1 から開始し、どの都市でも終了できます。 各道路には、その長さを表す重みがあります。 入力により都市の数が得られます$n$その後$n-1$道路をその重みで表すトリプル。 出力は単一の整数、つまり最小合計移動距離です。 

なぜなら$n$と同じ大きさにすることができます$10^5$、都市や道路の数が線形または線形に近いものより悪いソリューションは遅すぎます。 考えられるすべてのルートまたは順列を試す単純な解決策は、順列の数が階乗的に増加するため、明らかに実行不可能です。 計算数を減らすためにツリー構造を利用する必要があります。 

明らかではないエッジ ケースは、最も重いパスが都市 1 から葉までの長いチェーン内にあるツリーです。 たとえば、3 つの都市が並んでいるとします。都市 1 は重み 10 で 2 に接続され、都市 2 は重み 20 で 3 に接続されます。最適な戦略は、1 → 2 → 3 と歩き、3 で停止することです。シャープールが都市 1 に戻らなければならないと仮定する不注意なアプローチでは、一部のエッジの重みが誤って 2 倍になり、30 ではなく 60 が与えられます。 

もう 1 つの微妙なケースは、ツリーが星型で、すべての都市が都市 1 に直接接続されている場合です。ここで、最適なパスは各エッジを 1 回だけ横断し、戻ることなく通過できるため、すべてのエッジの重みを合計することで答えが得られます。 

## アプローチ

 ブルートフォース手法では、都市 1 から始まり、すべての都市を 1 回だけ訪問するすべてのパスが生成され、それらの距離が計算され、最小値が取られます。 これは正しいですが、ツリー内の可能なパスの数は、自明でない形状の都市の数の階乗に影響するため、次の場合は実行不可能になります。$n$と同じくらい大きい$10^5$。 

重要な観察は、都市がツリーを形成しているということです。 すべての都市を訪問するには、すべてのエッジを少なくとも 1 回横断する必要があります。エッジを省略すると、接続されている都市が訪問されないままになるためです。 開始都市を無視すると、単純な方法では各エッジを 2 回横断することになります。1 回目は奥へ進み、1 回目は後戻りします。 これにより、各エッジがその重みの 2 倍としてカウントされます。 距離を節約する唯一の方法は、都市 1 からの最長の単一パス (都市 1 から最も遠いリーフまでのパス) でのバックトラックを避けることです。 最長のパスを 2 回ではなく 1 回だけ通過すると、合計距離が最小になります。 

したがって、最適なアプローチは、すべてのエッジの重みを合計して 2 を乗算し、都市 1 から任意のリーフまでの最大距離を減算することです。 DFS は、この最大距離を効率的に計算するために使用されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析して読み取る$n$そして$n-1$エッジ。 隣接エッジとエッジの重みの両方を含む隣接リストにエッジを保存します。 この表現により、どの都市からでも高速移動が可能になります。 
2. すべてのエッジの重みの合計を計算します。 バックトラックを回避するパスを除き、各エッジは両方向に少なくとも 1 回横断する必要があるため、この合計に 2 を乗算すると、各分岐を訪問した後に開始位置に戻る場合の単純な総移動量が求められます。 
3. 都市 1 から開始する深さ優先検索を実行して、都市 1 から任意のリーフまでの最大距離を見つけます。 距離アキュムレータを 0 に初期化し、まだ訪問していない近隣ごとにパス長を再帰的に計算し、最大値を追跡します。 
4. 2 つの合計から得られた最大距離を減算して、最小移動距離を取得します。 これが機能するのは、ルートから最も遠いリーフまでのパスに沿って、エッジを越えてバックトラックする必要がないためです。 他のすべてのエッジは 2 回カウントされます。 

機能する理由: すべての都市を確実に訪問するには、すべてのエッジを少なくとも 1 回横断する必要があります。 最初に各エッジを 2 回カウントすることで、出発と復帰が考慮されます。 開始都市からの最長の単一パスを特定することで、それらのエッジを 1 回通過することを回避できます。 DFS は、この経路を線形時間で正確に見つけることを保証し、この最大経路長を差し引くことで、どの都市も見逃すことなく最小限の移動が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(200000)

n = int(input())
adj = [[] for _ in range(n + 1)]
total_weight = 0

for _ in range(n - 1):
    u, v, w = map(int, input().split())
    adj[u].append((v, w))
    adj[v].append((u, w))
    total_weight += w

visited = [False] * (n + 1)
max_path = 0

def dfs(node, dist):
    global max_path
    visited[node] = True
    if dist > max_path:
        max_path = dist
    for neighbor, weight in adj[node]:
        if not visited[neighbor]:
            dfs(neighbor, dist + weight)

dfs(1, 0)

result = 2 * total_weight - max_path
print(result)
```隣接リストは、効率的な DFS トラバーサルのために選択されます。 グローバル変数`max_path`最大距離を追跡します。 DFS は距離を再帰的に蓄積し、各ノードが 1 回訪問されることを保証します。 最初は各都市に行って戻ってくると想定しているため、合計の重みに 2 を掛けます。 引き算`max_path`ルートからリーフまでの最長パスを二重にカウントすることを回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | DFS は各ノードとエッジを 1 回だけ訪問します。 
| スペース | O(n) | 隣接リストと訪問先配列は線形空間を必要とします。 

という制約を考慮すると、$n \le 10^5$、線形アルゴリズムは効率的で、2 秒の時間制限と 256 MB のメモリ制限内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    adj = [[] for _ in range(n + 1)]
    total_weight = 0
    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        adj[u].append((v, w))
        adj[v].append((u, w))
        total_weight += w

    visited = [False] * (n + 1)
    max_path = 0

    def dfs(node, dist):
        nonlocal max_path
        visited[node] = True
        if dist > max_path:
            max_path = dist
        for neighbor, weight in adj[node]:
            if not visited[neighbor]:
                dfs(neighbor, dist + weight)

    dfs(1, 0)
    return str(2 * total_weight - max_path)

# provided sample
assert run("3\n1 2 3\n2 3 4\n") == "7", "sample 1"

# custom tests
assert run("1\n") == "0", "single node"
assert run("2\n1 2 10\n") == "10", "two nodes only"
