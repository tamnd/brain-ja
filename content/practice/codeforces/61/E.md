 ## 解決策
 ## 問題の理解

 列に並んでいる兵士の力を表す個別の整数の配列が与えられます。 インデックストリプルがいくつあるかを数える必要があります`(i, j, k)`2 つの条件を同時に満たします。 

- ポジションは次のように並べられます。`i < j < k`- 値は厳密に減少しています。`a[i] > a[j] > a[k]`これについての別の考え方は次のとおりです: すべてのミドルポジションについて`j`、その前にいくつの大きな要素が存在し、その後にいくつの小さな要素が存在するかを知りたいのです。 これらの選択肢のすべての組み合わせは、1 つの有効な減少三重項を形成します。 

制約によって、必要なアルゴリズムの種類が完全に決まります。 配列サイズは次の範囲に達します`10^6`、3次どころか2次も除外されます。 たとえ`O(n^2)`解決策には約が必要です`10^12`最悪の場合、5 秒以内に収まる動作をはるかに超えた操作が行われます。 ターゲットの複雑さは線形に近いか、`O(n log n)`。 

値自体は次のように大きくできます。`10^9`したがって、値によってインデックス付けされた配列を直接構築することはできません。 値の範囲に依存するデータ構造では、最初に座標圧縮が必要です。 

微妙な問題の 1 つは、整数のオーバーフローです。 減少する三つ子の数は非常に多くなる可能性があります。 たとえば、配列が厳密に減少している場合、`n = 10^6`、答えは次のとおりです。$$\binom{10^6}{3}$$それはその辺です`1.67 × 10^17`、32 ビット整数には収まりません。 Python はこれを自動的に処理しますが、C++ では答えを次の場所に保存する必要があります。`long long`。 

もう 1 つの簡単な間違いは、「厳密に大きい」条件の処理を誤ることです。 配列が次のとおりであるとします。```
4
5 5 4 3
```この問題では個別の値が保証されるため、この入力は無効ですが、多くの汎用実装では誤って使用してしまいます。`>=`または`<=`論理。 重複が存在する場合、不正確な不等号処理により、暗黙的に過大カウントが発生します。 正しい条件は、ステップごとに厳密に減少します。 

より現実的なエッジ ケースは、厳密に増加する配列です。```
5
1 2 3 4 5
```正しい答えは、`0`減少するトリプルが存在しないためです。 左右のカウントを混同する不注意な実装により、誤って代わりに増加パターンをカウントする可能性があります。 

もう 1 つの重要なシナリオは、すべての有効なトリプルが同じ中間要素を共有する場合です。 例えば：```
5
5 4 3 2 1
```ここではすべてのトリプルが有効であり、次のようになります。$$\binom{5}{3} = 10$$このケースでは、アルゴリズムが「左側の大きいもの」と「右側の小さいもの」を正しく組み合わせているかどうかが強調されます。 

## アプローチ

 ブルート フォース ソリューションは定義に直接従います。 私たちはすべてのトリプルを試します`(i, j, k)`と`i < j < k`そして、値が厳密に減少するシーケンスを形成しているかどうかを確認します。```
for i:
    for j > i:
        for k > j:
            check a[i] > a[j] > a[k]
```これは正しいです。なぜなら、考えられるすべてのトリプルが 1 回だけ検査されるからです。 問題は走行時間です。 トリプルの数は次のとおりです。$$\binom{n}{3}$$のために`n = 10^6`、それはおおよそです`1.67 × 10^17`繰り返しですが、これは完全に不可能です。 

重要な観察点は、中間のインデックスが`j`がすべてを決定します。 すでにわかっている場合:

 - 前の要素の数`j`より大きい`a[j]`- 後の要素の数`j`よりも小さい`a[j]`次に、有効なトリプルの数を使用します。`j`中間要素は単純に次のようになります。$$\text{leftGreater}[j] \times \text{rightSmaller}[j]$$これにより、問題はトリプルの検索から頻度クエリへの回答へと変わります。 

タスクは次のようになります。 

- 左から右にスキャンしながら、以前の値が現在の値よりも大きいものがいくつあるか数えます。 
- 右から左にスキャンしながら、現在の値より小さい後の値がいくつあるかを数えます。 

これらは古典的なプレフィックス頻度クエリであり、Fenwick Tree を使用して効率的に処理できます。 

配列の値は最大なので、`10^9`、まずそれらを次のランクに圧縮します。`1`に`n`。 すべての値は個別であるため、圧縮では順序が正確に保持されます。 

フェンウィック ツリーの各操作には時間がかかります`O(log n)`、要素ごとに一定の数の操作を実行します。 それは全体的に複雑になります`O(n log n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n^3)`|`O(1)`| 遅すぎる |
 | 最適 |`O(n log n)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、その値を座標圧縮します。 

個別の値を並べ替えてランクを割り当てます。`1`に`n`。 フェンウィック ツリーはコンパクトな整数インデックスで動作するため、圧縮により巨大な配列を回避しながら比較を保持できます。 
2. 配列を作成する`left_greater`。`left_greater[i]`より大きい以前の要素がいくつあるかを格納します。`a[i]`。 
3. Fenwick Tree を使用してアレイを左から右にスキャンします。 

各位置で:

 - 現在の値以下の処理済み要素の数をクエリします。 
- 処理された要素の数からそれを減算して、どれだけ大きいかを取得します。 
- そのカウントを保存します`left_greater[i]`。 
- 現在の値をフェンウィック ツリーに挿入します。 

減算が機能する理由は、前のすべての要素が大きいか大きくなく、すべての値が異なるためです。 
4. フェンウィック ツリーをリセットします。 

これをサフィックス情報として再利用します。 
5. 配列を作成する`right_smaller`。`right_smaller[i]`より小さい後の要素がいくつあるかを格納します`a[i]`。 
6. アレイを右から左にスキャンします。 

各位置で:

 - 現在の値よりも厳密に小さい、すでに確認されている値がいくつあるかをクエリします。 
- 結果を保存します`right_smaller[i]`。 
- 現在の値をフェンウィック ツリーに挿入します。 

右から左に移動するため、ツリーには常に現在のインデックスの後の要素が正確に含まれます。 
7. 最終的な答えを計算します。 

あらゆるポジションについて`i`、 追加：$$\text{left\_greater}[i] \times \text{right\_smaller}[i]$$すべての有効なトリプレットにはちょうど 1 つの中間インデックスがあるため、減少する各トリプルを 1 回カウントします。 

### なぜ効果があるのか

 固定中間インデックスの場合`j`、有効なトリプレットは、次の選択によって完全に決定されます。 

- インデックス 1 つ`i < j`と`a[i] > a[j]`- インデックス 1 つ`k > j`と`a[k] < a[j]`選択肢は独立しているため、中心となる三つ子の数は次のようになります。`j`はこれら 2 つのカウントの積です。 

左から右へのフェンウィック パスは、すべての要素を正しく追跡します。`j`、右から左へのパスは、その後のすべての要素を正しく追跡します。`j`。 すべての減少する 3 連符には一意の中間位置があるため、すべてを合計すると、`j`有効なトリプレットをすべて 1 回だけカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def update(self, idx, delta):
        while idx <= self.n:
            self.bit[idx] += delta
            idx += idx & -idx

    def query(self, idx):
        res = 0
        while idx > 0:
            res += self.bit[idx]
            idx -= idx & -idx
        return res

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    # coordinate compression
    vals = sorted(arr)
    rank = {v: i + 1 for i, v in enumerate(vals)}
    comp = [rank[x] for x in arr]

    left_greater = [0] * n
    right_smaller = [0] * n

    bit = Fenwick(n)

    # left greater counts
    for i in range(n):
        x = comp[i]

        less_or_equal = bit.query(x)
        left_greater[i] = i - less_or_equal

        bit.update(x, 1)

    bit = Fenwick(n)

    # right smaller counts
    for i in range(n - 1, -1, -1):
        x = comp[i]

        right_smaller[i] = bit.query(x - 1)

        bit.update(x, 1)

    ans = 0

    for i in range(n):
        ans += left_greater[i] * right_smaller[i]

    print(ans)

solve()
```フェンウィック ツリーには、処理済みの圧縮値の頻度カウントが保存されます。 の`update`操作により値が挿入され、`query(idx)`最大で圧縮ランクを持つ挿入値の数を返します。`idx`。 

値は次のように大きくなる可能性があるため、座標圧縮が必要です。`10^9`。 フェンウィック ツリーには高密度の整数インデックスが必要なため、値を範囲に再マッピングします。`1...n`順序を維持しながら。 

左から右へのパス中に、ツリーには現在のインデックスより前の要素が正確に含まれます。`bit.query(x)`現在の値以下の以前の値がいくつあるかを示します。 すべての値は個別であるため、これは厳密に小さい値をカウントすることと同じです。 から引く`i`、前の要素の数は、より大きな値の数を示します。 

右から左へのパスは少し異なります。 ここで直接クエリします`x - 1`、ツリーにすでに挿入されているサフィックスのうち、厳密に小さい要素をカウントします。 

オフバイワンの簡単な間違いの 1 つは、フェンウィック ツリーのインデックスが通常 1 であることを忘れることです。 圧縮は次から始まります`1`、 ない`0`、特に無限ループを避けるため`update`。 

もう 1 つの微妙な点は、両方向を同時に計算するのではなく、2 つの別々のパスを使用することです。 ツリーの意味は、トラバース方向に完全に依存します。 同じツリーをリセットせずに再利用すると、プレフィックス情報とサフィックス情報が誤って混合されてしまいます。

 | --- | --- | --- |

    input = sys.stdin.readline

    class Fenwick:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)

                self.bit[idx] += delta
                idx += idx & -idx

            while idx > 0:

                idx -= idx & -idx

    vals = sorted(arr)

 ## 特殊なケース

 厳密に増加する配列を考えてみましょう。```
5
1 2 3 4 5
```左から右へのパス中、以前の値はすべて小さくなります。`left_greater`は次のようになります:```
[0, 0, 0, 0, 0]
```右から左へのパスでもさらに小さいサフィックス値が見つかりますが、すべての最終寄与にはゼロ係数が含まれています。```
left_greater[i] * right_smaller[i] = 0
```最終的な答えは正解です`0`。 

次に、完全に減少する配列を考えてみましょう。```
5
5 4 3 2 1
```アルゴリズムは以下を計算します。```
left_greater  = [0, 1, 2, 3, 4]
right_smaller = [4, 3, 2, 1, 0]
```貢献度は次のようになります。```
0*4 + 1*3 + 2*2 + 3*1 + 4*0
= 0 + 3 + 4 + 3 + 0
= 10
```これは期待値と一致します。$$\binom{5}{3} = 10$$これにより、乗算ロジックが、大きい方の要素と小さい方の要素の考えられるすべての組み合わせを正しくカウントしていることが確認されます。 

最後に、中間インデックスが 1 つだけ寄与するケースを調べます。```
5
5 1 4 2 3
```インデックス時`2`価値のあるもの`4`:

 - その前に、より大きな要素が 1 つ存在します。`5`- その後に 2 つの小さな要素が存在します。`2`そして`3`アルゴリズムはこれらのカウントを乗算します。```
1 * 2 = 2
```他のインデックスは寄与しません。 これは、問題を中間の要素で区切ることで過少カウントと二重カウントの両方を回避できる理由を示しています。
