 ## 解決策
 ## 問題の理解

 数字 0、1、2 のみで構成される文字列が与えられます。隣接するペアがいずれかの方向に 0 と 1 である場合、またはいずれかの方向に 1 と 2 である場合は、隣接するペアを繰り返し交換することができます。 目標は、これらの動きの下で文字列を辞書編集上可能な限り最小の文字列に変換することです。 

重要な点は、スワップはローカルであり、隣接するペアのみが関与するということですが、スワップは任意に何度でも適用できます。つまり、文字は、許可された隣接ルールを遵守している限り、文字列内を効果的に「移動」できます。 

文字列の長さは最大 100,000 であるため、スワップを明示的にシミュレートしようとするアプローチは遅すぎます。 単純なシミュレーションでは、各スワップでキャラクターが 1 位置しか移動しないため、最悪の場合、二次時間がかかる可能性があります。 これにより、キャラクターを繰り返し所定の位置にバブルさせるようなアプローチは即座に排除されます。 

3 桁すべてが混合されると、微妙なエッジケースが現れます。 たとえば、100210 のような文字列では、異なる外観の最終的な配置を生成する複数の有効なスワップ シーケンスが許可されます。 すべてのスワップが許可されているわけではない (0 と 2 が直接スワップすることはない) ため、「文字列のソート」のような素朴な貪欲な方法は失敗する可能性があります。また、スワップのチェーンによって初期構成からは明らかではない間接的な再配置が許可されるため、過度に慎重なローカル戦略も失敗する可能性があります。 

重要な問題は、1 が仲介者として機能することです。1 は 0 と 2 の両方と交換できるため、単純な順序付けの仮定を複雑にする間接的な移動が可能になります。 

## アプローチ

 ブルート フォース アプローチでは、到達可能なすべての文字列に対して BFS または DFS を使用して、考えられるすべてのスワップをシミュレートします。 各状態には最大 O(n) 個の近傍があり、隣接するスワップのシーケンスを通じて多くの順列に到達できるため、状態の数は爆発的に増加します。 枝刈りを試みても、最悪の場合、状態空間が階乗になってしまい、まったく実行できなくなります。 

重要な点は、個々のスワップ シーケンスを追跡する必要がないということです。 代わりに、許可された操作の下でどのような順序制約が不変のままであるかを理解する必要があります。 このシステムでは、0 と 1 の間、および 1 と 2 の間のローカル反転が可能です。つまり、1 は中間ステップを通じて 0 と 2 の両方を自由に移動できます。 これにより、1 が事実上最も柔軟なキャラクターになります。 

この柔軟性から、最適な戦略は、辞書編集上の順序を貪欲に最小化するという観点から推論することです。 0 は最小の桁なので、できるだけ早く 0 が必要です。 2 が最大であるため、できるだけ遅くしたいと考えています。 数字 1 は、小さな文字の配置を妨げない方法でそれらの間に配置できるバッファとして使用できます。 

これにより、標準的な構築的な結果が得られます。最適な文字列は、最初にすべて 0、次にすべて 1、次にすべて 2 を配置することによって得られます。 0 を遅らせたり、2 を前に進めようとすると、辞書編集上の順序が悪化するだけです。これは、0 を 1 秒を超えて左にプッシュしたり、2 を 1 秒を超えて右にプッシュしたりする一連の有効なスワップが常に存在するためです。 

ブルート フォースは、すべてのスワップ シーケンスを明示的に探索するため機能します。 関連する唯一のグローバル目標が辞書編集上の最小化であり、スワップ システムが十分に豊富であるため、数字をグローバル ソート順序に自由に再配置できるため、貪欲な方法が機能します。

 ## アルゴリズムのチュートリアル

 スワップをシミュレートするのではなく、直接答えを構築します。 

### ステップ

 1. 文字列内に現れる 0、1、2 の数を数えます。 

スワップでは辞書編集上の最小化と一致する任意の再配置が可能であるため、これらのカウントによって最終的な文字列が完全に決まります。 
2. 最初にすべて 0 を書き込んで結果を構築します。

辞書編集上の順序を悪化させることなく 0 を必要以上に大きくする操作はできないため、0 を前に置くことが常に最適です。 
3. 0 の後にすべて 1 を追加します。 

1 は 0 より大きく 2 より小さいため、これを中央に配置すると、0 との不必要な干渉を避けながらプレフィックスが最小限に保たれます。 
4. 最後にすべて 2 を追加します。 

2 は可能な最大の辞書編集値に寄与するため、これを遅らせることで最適性が最大化されます。 

### なぜ効果があるのか

 スワップにより、どの数字も、より小さい値の他の数字と比べて悪い位置に永続的にトラップされることがなくなります。 数値によってソートされていない構成は、隣接する反転ペア (1 の前に 0、または 2 の前に 1) を繰り返し交換することで改善できます。 これらのスワップは可逆的かつ網羅的であるため、小さい桁と大きい桁の間の反転を排除できます。 これは、辞書編集的に到達可能な最小の配列が、桁値によって完全にソートされた配列であることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

c0 = c1 = c2 = 0

for ch in s:
    if ch == '0':
        c0 += 1
    elif ch == '1':
        c1 += 1
    else:
        c2 += 1

print('0' * c0 + '1' * c1 + '2' * c2)
```この解決策は、問題を周波数のカウントに限定することで機能します。 ループは唯一の処理ステップであり、線形時間で実行されます。 カウント後、文字列は直接構築され、元の順序には依存しません。 

よくある間違いは、桁の交換をシミュレートしたり、桁の位置を追跡しようとしたりすることです。 許可された操作ではカウントを超える意味のある位置制約が削除されるため、これは不要です。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    s = input().strip()

    c0 = c1 = c2 = 0
    for ch in s:
        if ch == '0':
            c0 += 1
        elif ch == '1':
            c1 += 1
        else:
            c2 += 1

    return '0' * c0 + '1' * c1 + '2' * c2

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# provided sample
assert run("100210\n") == "000112", "sample 1"

# single character
assert run("0\n") == "0"
assert run("2\n") == "2"

# all same
assert run("11111\n") == "11111"

# mixed small
assert run("102012\n") == "001122"

# already sorted reverse
assert run("222111000\n") == "000111222"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 0 / 2 シングル | 同じ | 最小限の境界動作 |
 | すべて等しいもの | 変更なし | 施工の安定性 |
 | 102012 | 001122 | 混合順序 |
 | 222111000 | 000111222 | 最悪の場合の並べ替え |

 ## 特殊なケース

 次のような最小限の入力`0`または`2`は、アルゴリズムが人為的な構造を導入せず、単に同じ単一文字を返すことを示しています。 カウントステップでは単一の非ゼロカウンターが生成され、再構成ではそれを直接出力します。 

次のような完全に反転した入力`222111000`アルゴリズムが初期順序にまったく依存しないことを示しています。 元の文字列が最大限に「大きい」場合でも、すべての 0 が最初に出力され、次に 1、次に 2 が出力されるため、出力は完全に最小化されます。 

次のような混合入力`102012`位置間の相互作用が必要ないことを確認します。 数字がインターリーブされている場合でも、スワップ システムによりグループ化された形式への完全な再配置が可能になり、カウント手法により到達可能な最小値が直接取得されます。
