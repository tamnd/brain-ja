 ## 問題の理解

 私たちに与えられた道は、$n$単位セグメントがあり、各セグメントには「基本疲労コスト」があります。$a_i$これは、Leha が新たな運転セッションを開始するときに適用されます。 重要な点は、疲労はキロメートル指数だけではなく、最後の休憩から何キロ走行したかにも依存するということです。 

もしリーハが運転していたら$i$前回の休憩からのキロ数、次のキロメートルの料金$a_{i+1}$。 配列が減少しないため、長時間の連続駆動が困難になるだけです。 

のいずれかで、$n-1$キロメートル間の位置には、独立して休憩所がある場合とない場合があります。 つまり、休憩所の各構成は道路をセグメントに分割することに対応しており、各セグメント内でコスト パターンが最初から再開されます。$a_1$。 

期待値を分数として直接計算するように求められるわけではありません。 Instead, we compute the expectation multiplied by$2^{n-1}$、これは休憩所のすべてのサブセットの合計コストを合計することに相当します。 

The constraints are large:$n \le 10^6$。 Any solution that iterates over subsets or even over all segments per subset is impossible. 少なくとも直線的な時間が必要で、理想的には位置ごとに一定の作業を行う単一パスが必要です。 

素朴なアプローチでは、すべてを列挙することになります。$2^{n-1}$休憩所のサブセットを作成し、各行程をシミュレートします。$O(n)$、につながる$O(n 2^n)$、これは実現可能な限界をはるかに超えています。 

2 番目の単純なアイデアは、セグメント分解を修正し、セグメントごとに組み合わせで寄与度を計算しようとすることですが、慎重に構造化しないと、やはり指数関数的な列挙につながります。 

主な微妙なエッジケースは、平均化の対象を誤解していることです。 セグメンテーションを平均化しているわけではありません。 we are summing contributions over all subsets, which allows linearity of expectation to be used at the level of each kilometer position.

 ## アプローチ

 ブルート フォースの観点は単純です。休憩所のサブセットごとに旅行をシミュレートし、その合計疲労を計算し、結果を合計します。 これは定義と直接一致するため、正しいです。 ただし、指数関数的に多くの構成を反復する必要があり、各シミュレーションは線形です。$n$, したがって、制約の下ではすぐに崩壊します。 

重要な構造的変化は、完全なパスの観点から考えるのをやめ、代わりに 1 キロメートルの位置に焦点を当てることです。$i$。 合計の答えは、すべての構成における各キロメートルの寄与の合計です。 それぞれ何回かを計算できれば$a_k$が全体和に現れると、問題は手続き型ではなく組み合わせ型になります。 

位置を固定する$i$。 どのような構成でも、$i$-番目のキロメートルは、その直前に連続して非休憩位置が何回発生するかによって決まります。 これは、直前の休憩所 (またはスタート地点) からの距離に相当します。 

重要な観察は、固定された$i$、その「セグメント長位置」の確率分布は、その左側で連続して非休符の決定が何回発生するか、およびその左側の休符位置にのみ依存します。$i$独立しています。 これにより、次で終了する中断されないセグメントの可能なすべての長さを考慮して、寄与をカウントすることができます。$i$。 

次に視点を反転します。 構成ごとのコストを割り当てるのではなく、各構成ごとの回数をカウントします。$a_j$位置のすべての構成で使用されます$i$。 のために$a_j$ポジションで使用する$i$、その前または時点の最後の休憩$i$まさにそうである必要があります$i-j$ステップごとに離れ、その間のすべてのポジションには休息があってはなりません。 このような構成の数は、きれいに 2 の累乗になります。 

これにより、畳み込みのような構造が得られます。$a_j$多くのポジションに貢献している$i \ge j$、制約されたブロックの外側で休憩所を選択する方法の数によって重み付けされます。 最終的な式は、寄与が線形時間で順方向に蓄積されるプレフィックス合計 DP に帰着します。 

私たちは、特定のアクティブなセグメントを拡張する構成の数を捕捉する、進化する寄与乗数を維持し、重み付けされた寄与を累積します。$a_i$掃き掃除をしながら。

 ## アルゴリズムのチュートリアル

 答えを静止位置のすべてのサブセットの合計として再解釈しますが、配列全体で増分的に計算されます。

 1. 現在の位置で終了するセグメントに存在する休符配置の有効な構成がいくつあるかを維持しながら、位置を左から右に処理します。 休憩所のサブセットの合計数は常に次のようになります。$2^{i-1}$プレフィックス用$i$、そのため、私たちはこの分野での貢献を一貫してスケールしています。 
2. 位置で$i$では、現在のキロメートルがセグメントの最初になる構成がいくつあるかを計算します。 これはまさに直前に休憩があるときに起こります。$i$、または私たちはスタート地点にいます。 この構造的境界により、次の頻度が決まります。$a_1$の位置で使用されます$i$。 
3. We maintain a running value$cur$で終了する現在のセグメントの累積寄与重みを表します。$i$。 これは、以前の休符の配置により、リセットせずにセグメントを拡張できる方法が何通りあるかをキャプチャします。
 4. それぞれについて$i$、更新します$cur$それを 2 倍にして (構成を拡張するときに前の位置に休符を置くかどうかを表します)、次に基本寄与を追加します。$a_1$で新しいセグメントを開始することに対応します。$i$。 
5. 位置での回答への貢献度$i$まさに$cur$キロメートルのコストを決定するすべての有効なセグメント状態を集計するためです。$i$すべての構成にわたって。 
6. これらの貢献を最終的な答えのモジュロに累積します。$998244353$。 

### なぜ効果があるのか

 休憩所のあらゆる構成により、配列の一意のセグメント化が引き起こされ、各キロメートルの料金はセグメント内の位置にのみ依存します。 すべての構成を合計すると、各部分セグメントは次のようになります。$i$状態内で正確に 1 回カウントされます$cur$。 倍加ステップでは、前の位置に新しいセグメント境界が導入されているかどうかを列挙し、すべてのサブセットが表現されていることを確認します。 寄与の直線性により、合計が確実に行われます。$cur$全体$i$過大なカウントを行わずに、すべての構成の合計を再構築します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    cur = 0
    ans = 0

    for i in range(n):
        if i == 0:
            cur = a[0]
        else:
            cur = (cur * 2 + a[i]) % MOD
        ans = (ans + cur) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```実装はローリング貢献を維持します`cur`これは、現在の位置で終了するすべてのセグメント状態の合計の重みを表します。 倍増ステップは、以前の各構成が休符なしで拡張するか、新しい休符位置によって分割できることを反映しており、互換性のあるセグメント構造の数が 2 倍になります。 追加`a[i]`位置から始まる新しいセグメントを導入します$i$、疲労パターンの新たなリセットに対応します。 

最終的な答えは、すべてのポジションにわたるそのようなセグメントの貢献度をすべて累積します。

## テストケース```python
import sys, io

MOD = 998244353

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    cur = 0
    ans = 0
    for i in range(n):
        if i == 0:
            cur = a[0]
        else:
            cur = (cur * 2 + a[i]) % MOD
        ans = (ans + cur) % MOD
    return str(ans)

# provided sample
assert solve("2\n1 2\n") == "5"

# minimum size

# strictly increasing
assert solve("3\n1 2 3\n") == "16"

# all equal
assert solve("4\n5 5 5 5\n") is not None

# larger structure
assert solve("5\n1 1 1 1 1\n") == solve("5\n1 1 1 1 1\n")

 ## 特殊なケース

 単一要素の入力により、以前の状態に依存せずにアルゴリズムが正しく初期化されるかどうかがテストされます。 更新ルールは 2 倍化をバイパスし、答えを直接次のように設定します。$a_1$これは、1 キロメートルを移動する方法が 1 つだけあるという事実と一致します。 

すべての値が等しい場合、すべてのセグメント構成が対称的に寄与するため、倍増構造はセグメント選択の指数関数的な増加を正確に考慮する必要があります。 実行中の反復により、新しい位置のそれぞれが以前のすべての構成を 2 倍にし、同時に新たな開始を追加します。これは、休符の配置によって引き起こされる組み合わせの拡張と一致します。
