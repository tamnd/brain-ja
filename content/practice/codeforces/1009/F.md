 ## 解決策
 ## 問題の理解

 私たちは、頂点 1 がルートであると考えられるルート付きツリーを操作しています。 頂点ごとに$x$、概念的に、そのサブツリー内のすべてのノードを調べ、ノードからの距離に基づいてグループ化します。$x$ツリーの下向きのエッジに関して。 

より具体的には、固定頂点の場合$x$、 定義する$d_{x,i}$頂点の数として$y$そのような$y$のサブツリーにあります$x$そしてからの道$x$に$y$まさに下がります$i$エッジ。 それで$d_{x,0}$カウントされるため、常に 1 です$x$自体。 大きい値$i$深さに存在するノードの数を数えます$i$下に$x$。 

各頂点について、この分布の「支配的なインデックス」を見つけるように求められます。 このインデックス$j$値が次のように選択されます$d_{x,j}$厳密に左側のすべてより大きく、右側のすべてを超えることはありません。 言い換えれば、シーケンス内で、その前のすべてが厳密に小さく、その後のすべてが大きくないピークを探しています。 

ツリーには最大 100 万個の頂点を含めることができるため、ノードごとにサブツリーの深さの分布を個別に再計算するソリューションは即座に除外されます。 すべてのサブツリーを個別に探索する単純なアプローチでは、ツリーの大部分を繰り返し走査することになり、最悪の場合は 2 次の動作が発生します。 

チェーン状のツリーに微妙なエッジケースが現れます。 ツリーが単一のパスの場合、すべてのサブツリーもパスになります。 このような場合、各深さのすべてのカウントは正確に 1 であるため、すべてのインデックスは条件を満たしますが、左側の厳密な不等式により、定義では最小の有効なインデックスが強制されます。 これにより、どこでも答えが 0 になります。 

星型の木では、別の特殊なケースが発生します。 ルートには多くの子があり、すべての深さの分布は深さ 1 に集中しています。ルートではインデックス 1 が優勢ですが、リーフではインデックス 0 のみが存在します。 単純な DFS ベースの再計算では、異なるルート間でサブツリーの寄与が誤って混合されるため、これが誤って処理されることがよくあります。 

## アプローチ

 ブルートフォース手法では、ノードごとに計算が行われます。$x$、DFS はそのサブツリーに制限され、各深さに表示されるノードの数をカウントします。 これには費用がかかります$O(n)$最悪の場合、ノードごとに$O(n^2)$全体的な複雑さは大きすぎて、$n = 10^6$。 

重要な観察点は、シーケンスが$d_{x,i}$まさにそのサイズです$i$のサブツリーの - 番目のレベル$x$。 各サブツリーで最も「人口の多い」深さレベルを、特定のタイブレーク ルールを使用して探します。つまり、前の深さは厳密に小さくなければならず、後の深さはそれを超えてはなりません。 

これは、ツリー上で「小さいものから大きいものまで」マージすることが役立つ古典的な設定です。 ツリーをボトムアップで処理すると、ノードごとに、サブツリー内の深さの周波数配列を維持できます。 子をマージするときは、常に小さな構造を大きな構造にマージして、全体的に線形に近い複雑さを保証します。 

マージ中、現在の最適な候補の深さインデックスも追跡します。 1 深さだけシフトされた子からのカウントを追加するたびに、頻度値が更新され、影響を受けるレベルを比較することで最適なインデックスが調整されます。 制約構造により、各ノードの寄与が最大でもマージを通じて上方に移動することが保証されます。$O(\log n)$回償却されます。 

これにより、各サブツリーの深度-周波数マップを維持し、上位に構築するときに支配的なインデックスを抽出するという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(n)$| 遅すぎる |
 | ツリー上の小規模から大規模までの DSU |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを 1 にルートし、DFS を実行して、親の前に子を処理します。 

1. ルートから DFS トラバーサルを実行し、現在のノードの前にすべての子を処理するようにします。 これにより、ノードを処理する前にサブツリー情報が利用できるポストオーダー構造が確立されます。 
2. 各ノードについて$x$、周波数構造を初期化します$freq_x$と$freq_x[0] = 1$。 これは、ノード自体が深さ 0 の 1 つの頂点に寄与していることを表します。 
3. すべての子どもたちに$c$の$x$、最初に計算します$freq_c$。 次に、すべての深さのカウントを +1 シフトします。$c$のサブツリーは、相対的に 1 エッジ深いです$x$。 
4. マージ$freq_c$の中へ$freq_x$。 複雑さを制御し続けるために、常に小さい周波数マップを大きい周波数マップにマージします。 もし$freq_x$小さい場合は、マージする前に交換してください。 これにより、各要素が対数回のみ移動することが保証されます。 
5. すべての子をマージした後、次の支配的なインデックスを計算します。$x$。 これまでに確認された最良の値を追跡しながら、深度値を昇順にスキャンします。 最小のインデックスを選択します$j$前の値はすべて厳密に小さくなり、後の値はそれを超えることはありません。 実際には、これは、プレフィックス制約を満たす最小の有効なインデックスに向けてタイブレークを行い、最大周波数が発生する深さを特定することになります。 
6. このインデックスをノードの回答として保存します$x$。 
7. 戻る$freq_x$親コールまで上向きに。 

### なぜ効果があるのか

 すべてのノードで、アルゴリズムはサブツリーの深さの正しいマルチセットを維持します。 小から大へのマージにより、サブツリーの寄与が対数的に多くの回数を超えて処理されることがなくなりますが、さらに重要なのは、各深さで正確な頻度カウントが保存されることです。 

支配的なインデックス条件は、単一のサブツリー内の深さにわたる頻度の相対比較のみに依存します。 マージによって各サブツリーの正確なカウントが生成され、カウントが失われたり二重にカウントされたりすることはないため、各ノードで計算されたインデックスは定義と直接一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n + 1)]
for _ in range(n - 1):
    a, b = map(int, input().split())
    g[a].append(b)
    g[b].append(a)

ans = [0] * (n + 1)

def dfs(u, p):
    mp = {0: 1}
    best_idx = 0

    for v in g[u]:
        if v == p:
            continue
        child_mp = dfs(v, u)

        # shift depths by +1
        shifted = {}
        for d, cnt in child_mp.items():
            shifted[d + 1] = shifted.get(d + 1, 0) + cnt

        # small-to-large merge
        if len(shifted) > len(mp):
            mp, shifted = shifted, mp

        for d, cnt in shifted.items():
            mp[d] = mp.get(d, 0) + cnt

    # compute dominant index
    max_val = -1
    best_idx = 0
    for d in sorted(mp.keys()):
        if mp[d] > max_val:
            max_val = mp[d]
            best_idx = d

    ans[u] = best_idx
    return mp

dfs(1, -1)
print("\n".join(str(ans[i]) for i in range(1, n + 1)))
```DFS はサブツリーの深さの分布をボトムアップで構築します。 各ノードは深さ 0 の単一カウントから始まり、1 レベルずつシフトした後、各子の分布を吸収します。 マージのステップは、小さい辞書が常に大きい辞書にマージされるように慎重に記述されており、これにより二次関数の爆発が防止されます。 

ドミナントインデックスは、保存されているすべての深さカウントを単純にスキャンし、最大頻度で深さを選択することによって計算され、最大値の最初の出現によって満たされる「厳密に大きいプレフィックス」条件によって、より小さいインデックスへの関係が自動的に解除されます。 

再帰制限が増加するのは、チェーン形状のツリーが Python のデフォルトの再帰の深さを超えるためです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \log n)$| 各ノードの周波数寄与は小さいものから大きいものまでマージされ、要素ごとの償却対数参加が保証されます。 
| スペース |$O(n)$| 各ノードは、すべての構造にわたって深さレベルごとに 1 つのエントリを提供します。 

までの制約は、$10^6$ノードは線形に近い動作を必要とします。 小規模から大規模へのマージにより、各サブツリー情報が限られた回数だけ移動されることが保証され、合計実行時間が制限内に保たれます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)

    ans = [0] * (n + 1)

    sys.setrecursionlimit(10**7)

    def dfs(u, p):
        mp = {0: 1}
        for v in g[u]:
            if v == p:
                continue
            child = dfs(v, u)
            shifted = {d + 1: c for d, c in child.items()}
            if len(shifted) > len(mp):
                mp, shifted = shifted, mp
            for k, v in shifted.items():
                mp[k] = mp.get(k, 0) + v
        best = 0
        bestv = -1
        for k, v in mp.items():
            if v > bestv:
                bestv = v
                best = k
        ans[u] = best
        return mp

    dfs(1, -1)
    return "\n".join(str(ans[i]) for i in range(1, n + 1))

 ## 特殊なケース

 単一ノード ツリーでは、DFS は周波数マップを次のように初期化します。`{0:1}`そしてすぐに支配的なインデックス 0 を割り当てます。マージは行われないため、構造は自明で正しいままです。 

根元が 1 の星型ツリーでは、各葉は唯一の貢献をします`{0:1}`、根が溜まる一方で、`{0:1,1:k}`どこ$k$子供の数です。 最大値は深さ 1 で発生するため、ルートは 1 を返しますが、葉は 0 のままです。各子は独立しており、正確に 1 回シフトされるため、マージ プロセスはこれを正しく処理します。 

深いチェーンでは、各ノードは厳密に増加する深さの構造を継承します。 すべての深さの周波数は等しいため、後の深さが前の深さを厳密に超えることはありません。そのため、支配的なインデックスは常に 0 になります。周波数値は深さ全体で均一のままであるため、アルゴリズムはこれを正確に反映します。
