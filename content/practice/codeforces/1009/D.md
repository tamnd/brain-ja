 ## 解決策
 ## 問題の理解

 1 から n までの番号が付けられた頂点上に単純な無向グラフを構築するように求められます。 グラフには正確に m 個のエッジがあり、接続されている必要があり、自己ループと繰り返しエッジの両方を回避する必要があります。 追加の制約は、含めるすべてのエッジが、最大公約数が 1 である 2 つの頂点を接続する必要があるということです。 

したがって、タスクは単にグラフを構築するだけではなく、接続性を制約することです。i と j が互いに素である場合にのみ接続できます。また、結果のグラフが接続されるように、そのような有効なペアを正確に m 個選択する必要があります。 

入力サイズは n と m の両方で 100000 に達し、すべてのペアをチェックしたり、多くの候補エッジの gcd を再計算したりするものは直ちに除外されます。 すべてのペアの単純な O(n²) スキャンは、上限で約 5 × 10⁹ ペアが必要になるため、不可能です。 O(n √n) 構造であっても、エッジ選択における隠れた 2 次の動作を避けるために慎重な設計が必要です。 

困難を支配する 2 つの構造的制約があります。 まず、n 個の頂点上に接続されたグラフにはそれだけ多くのエッジが必要となるため、接続性により少なくとも n − 1 個のエッジが強制されます。 第 2 に、有効な共素ペアの数を超えることはできません。これは、単なるグラフの組み合わせ論ではなく、数論の構造に依存します。 

n = 1 の場合、微妙な障害が発生することがあります。その場合、m は 0 でなければなりません。そうでない場合は接続が不可能です。 もう 1 つの失敗ケースは、m が大きすぎる場合です。Kₙ に n(n−1)/2 のエッジがあるとしても、それらのペアの多くは互いに素ではないため、常に密なグラフに到達できると仮定するのは安全ではありません。 

i を i+1 に接続してチェーンを形成し、任意の有効なエッジを貪欲に追加する単純なアプローチは、注意して順序付けしないと十分な共素ペアの利用可能性が保証されないため、失敗することがよくあります。 たとえば、すべてのノードを 1 に接続しようとすると、エッジ (1, i) のみが生成されますが、m が大きい場合はエッジが少なすぎます。 

## アプローチ

 ブルート フォース アプローチでは、最初にすべてのペア (i, j) を列挙し、gcd(i, j) を計算して、すべての有効なエッジを収集します。 これには、gcd 計算によりすでに O(n² log n) のコストがかかりますが、これは制限をはるかに超えています。 gcd 構造を賢明に事前計算したとしても、すべての有効なエッジをメモリに保存すると大きすぎます。 

重要な観察は、頂点 1 が他のすべての頂点と互いに素であることです。これにより、1 をルートとする保証されたスター スパニング ツリーが得られます。これにより、接続性が即座に解決されます。エッジ (1, 2)、(1, 3)、...、(1, n) をバックボーンとして常に使用できます。 

これにより、n − 1 個のエッジが無料で得られます。 m が n − 1 に等しい場合、作業は完了です。 m が大きい場合は、単純性や共素性を損なうことなく余分なエッジを追加する必要があります。 次の洞察は、gcd(i, j) = 1 で頂点 i と j を接続し、j の昇順に追加のエッジを構築し、j を常に互いに素である i < j に接続する必要があるということです。 

建設的な貪欲な戦略が機能します。1 を中心とする星から開始し、2 から n までの各頂点 i について、gcd(i, j) = 1 になるたびに、m 個のエッジに到達するまで、他の頂点 j > i に接続しようとします。 共素性を尊重するエッジのみを追加し、エッジを決して複製しないため、正確性は、m が実現可能な場合に十分な有効なペアを常に見つけられることを保証することになります。 

実現可能性は簡単です。エッジの最大数はすべての互いに素なペアを考慮することで得られますが、明示的に計算する必要はありません。 代わりに、段階的に構築し、m に達したら停止します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log n) | O(n²) | 遅すぎる |
 | 建設的な貪欲 | O(n²) 最悪の場合 (実際には除去されます) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. n == 1 の場合、m == 0 の場合にのみ有効なグラフを作成できます。それ以外の場合、グラフは接続できないか、エッジを含むことができません。 
2. まず、2 から n までのすべての i にエッジ (1, i) を追加して、頂点 1 をルートとするスパニング ツリーを作成します。 すべての i に対して gcd(1, i) = 1 であるため、これにより n − 1 個の有効なエッジとの接続が保証されます。 
3. m < n − 1 の場合、接続されたグラフには少なくとも n − 1 個のエッジが必要となるため、グラフを接続したままにすることは不可能です。 
4. エッジのリストと n − 1 に初期化されたカウンタを維持します。 
5. 1 ≤ i < j ≤ n のすべてのペア (i, j) を繰り返します。 各ペアについて、gcd(i, j) = 1 かどうかを確認します。そうである場合、エッジが最初のスターの一部ではない場合は、それを追加のエッジとして追加します。 
6. エッジの数が m に達するまで、このようなエッジの追加を続けます。 mに達したらすぐに停止してください。 

これが機能する主な理由は、保証された接続構造から開始し、それを有効なエッジでのみ拡張するため、接続が決して切断されないことです。 追加されたすべてのエッジは gcd 制約を尊重するため、有効性が維持されます。 

### なぜ効果があるのか

 この構築は、初期化後もグラフが接続されたままであること、および追加されたすべてのエッジが既に接続コンポーネントの一部である 2 つの頂点を接続するという不変条件に依存します。 エッジを削除しないため、接続は単調になります。 残りの唯一の要件は、正確に m 個のエッジを達成することです。すべての有効な共素ペアに対して反復処理を行うため、最終的には、実行可能な追加のエッジが存在する場合はそれらを列挙します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    if n == 1:
        if m == 0:
            print("Possible")
        else:
            print("Impossible")
        return

    edges = []

    # build spanning tree (star at 1)
    for i in range(2, n + 1):
        edges.append((1, i))

    if m < n - 1:
        print("Impossible")
        return

    # try adding extra coprime edges
    import math

    if len(edges) > m:
        print("Impossible")
        return

    for i in range(1, n + 1):
        for j in range(i + 1, n + 1):
            if len(edges) == m:
                break
            if i == 1 and j <= n:
                continue  # already used in star
            if math.gcd(i, j) == 1:
                edges.append((i, j))
        if len(edges) == m:
            break

    if len(edges) != m:
        print("Impossible")
    else:
        print("Possible")
        for u, v in edges:
            print(u, v)

if __name__ == "__main__":
    solve()
```実装は、縮退した単一ノードの場合を明示的に処理することから始まります。これは、そこでは接続制約の動作が異なるためです。 

次に、1 を中心とする星形を構築します。これにより、有効な接続ベースが保証されます。 これにより、すぐに n − 1 個のエッジが生成されます。 m < n − 1 チェックでは、不可能なケースが早期に拒否されます。 

ネストされたループは候補エッジをスキャンし、gcd を使用して妥当性を確認します。 ノード 1 からエッジをスキップする条件は、最初のスター エッジがすでに固定されているため、その重複を避けることを目的としています。 

ループは m 個のエッジが収集されるとすぐに終了し、オーバーシュートが発生しないようにします。 

## 実用的な例

 ### 例 1

 入力:```
5 6
```最初に星のエッジを構築します。 

| ステップ | 私 | j | gcd(i,j) | アクション | エッジ数 |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | - | - | - | 加算 (1,2)(1,3)(1,4)(1,5) | 4 |
 | スキャン | 2 | 3 | 1 | (2,3) を追加 | 5 |
 | スキャン | 2 | 4 | 2 | スキップ | 5 |
 | スキャン | 2 | 5 | 1 | (2,5) を追加 | 6 |

 6 つのエッジで停止します。 余分なエッジはすべてスパニング ツリーの上に追加されるため、グラフは接続されたままになります。 これは、追加の共素ペアが基本構造をどのように補完するかを示しています。 

### 例 2

 入力:```
4 3
```スターエッジから始めます。 

| ステップ | 操作 | エッジ |
 | --- | --- | --- |
 | 初期化 | (1,2)、(1,3)、(1,4) | 3 |

 すでに m = 3 に達しているため、追加の処理は必要ありません。 これは、答えがまさにツリーである最小接続ケースを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n²) 最悪の場合 | m 個のエッジが見つかるまで、gcd のすべてのペアをチェックすることができます。 
| スペース | O(m) | 最終エッジ リストのみを保存します |

 この制約では最大 10⁵ のノードが許可されていますが、m も 10⁵ に制限されているため、実際のほとんどの場合、構築は早期に終了します。 Python では、許可された評価数に対して gcd チェックは十分に高速です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from math import gcd

    n, m = map(int, inp.splitlines()[0].split())

    if n == 1:
        return "Possible\n" if m == 0 else "Impossible\n"

    edges = []
    for i in range(2, n + 1):
        edges.append((1, i))

    if m < n - 1:
        return "Impossible\n"

    import math

    for i in range(1, n + 1):
        for j in range(i + 1, n + 1):
            if len(edges) == m:
                break
            if i == 1:
                continue
            if math.gcd(i, j) == 1:
                edges.append((i, j))
        if len(edges) == m:
            break

    if len(edges) != m:
        return "Impossible\n"

    return "Possible\n" + "\n".join(f"{u} {v}" for u, v in edges) + "\n"

# sample
assert run("5 6") is not None

# minimal connected
assert run("4 3") == "Possible\n1 2\n1 3\n1 4\n"

# impossible single node mismatch
assert run("1 1") == "Impossible\n"

# exact tree
assert run("3 2") == "Possible\n1 2\n1 3\n"

# dense small case
assert run("6 8") is not None

 | 4 3 | 木のみ | 最小限の接続 |
 | 3 2 | スターツリー | 基礎工事 |

 ## 特殊なケース

 n = 1 の場合、スター構築は不可能であるため、アルゴリズムは正の m を直ちに拒否します。 これはエッジ生成が開始される前に処理され、無効な出力が防止されます。 

m = n − 1 の場合、アルゴリズムは 1 を中心とする星を正確に出力し、追加のエッジ ループに入らずに停止します。 これにより、誤って過剰に追加することがなくなります。 

2 や 3 などの小さい n の場合、1 を含むエッジに対して gcd 条件が自明に満たされるため、追加のペアリング ロジックを必要とせずに、構築は最小限のツリーにきれいに縮退します。
