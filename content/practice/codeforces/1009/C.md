 ## 問題の理解

 長さの配列から始めます$n$最初はゼロのみが含まれています。 ボブが演奏します$m$操作。 各操作はペアで定義されます$(x, d)$、ボブはセンターのポジションを選ぶことができます$i$配列内で。 一度彼がそうなると、あらゆるポジションで$j$からの距離のみに依存する相加的な寄与を受け取ります。$i$: 位置に加算される値$j$は$x + d \cdot |i - j|$。 

すべての演算を任意の順序で適用し、各演算の中心を選択すると、配列は最終的な整数シーケンスになります。 目的は、配列の平均値を最大化することです。これは、すべての要素の合計を最大化することと同じです。$n$固定されています。 

主な難点は、各操作で値が構造化された「V 字型」パターンで配列全体に分散され、その中心をどこにでも自由に配置できることです。 

制約$n, m \le 10^5$これは、すべての位置にわたって各操作をシミュレートしようとする解決策は不可能であることを意味します。 直接シミュレーションするには次のことが必要です$O(nm)$更新は次の順序で行われます$10^{10}$、限界をはるかに超えています。 オペレーションごとにポジションごとのエフェクトを完全に保存するだけでも大きすぎます。 

センターを選択する自由から生じる微妙な問題$i$。 素朴なアプローチでは、グローバル構造を考慮せずに、操作ごとに最適な位置を貪欲に選択できると想定するかもしれませんが、それは、同じ操作が配置に応じてどのように異なる寄与をするか、およびその線形構造が配列全体とどのように相互作用するかを無視することになります。 

素朴な推論による小さな失敗例としては、次のような場合があります。$d < 0$。 この操作により、中心から離れるほど高い値が得られ、配置に関する直感が覆されます。$i$。 もう一つのエッジケースは、$d = 0$、演算は位置に関係なく定数加算となり、配置は無関係になります。 

## アプローチ

 ブルートフォース解釈は簡単です。 それぞれの操作について$(x, d)$、可能な限りすべてのセンターを試します$i$、配列合計に対する結果の合計寄与度を計算し、最良のものを選択します。 それぞれの選択に対して、$i$の合計を評価します。$x + d|i-j|$全体$j$、すでに費用がかかります$O(n)$。 全員のためにこれを行う$i$単一の操作を行う$O(n^2)$、そして向こう側$m$これは次の操作になります$O(n^2 m)$、それはまったく実行不可能です。 

重要な点は、実際には完全な配列が必要ないということです。 すべての演算後の合計のみを考慮します。 固定操作の場合、寄与の合計は、選択した中心の左右にある要素の数のみに依存します。 定義すると$i$を中心として、寄与は距離の接頭辞の合計を使用して表すことができます。 の構造$|i - j|$は左右の部分にきれいに分割されており、どちらの部分も等差級数です。 

これにより、各操作を選択するだけで済みます。$i$これは、左右の端点までの距離を含む単純な式を最大化します。 最適な位置は常に境界の 1 つに存在するか、次の単調関数によって特徴付けることができます。$i$で最適な配置を計算できるようになります。$O(1)$操作ごとに。 

したがって、配列をシミュレートする代わりに、各操作に対して可能な限り最良の合計ゲインを個別に計算し、それを累積します。

 ## アルゴリズムのチュートリアル

 単一の操作の寄与を書き換えて、中心の選択に基づいて最適化します。 

1. 操作を修正する$(x, d)$中央を選択すると仮定します$i$。 地位への貢献$j$は$x + d|i-j|$。 まず、一定部分と距離依存部分を分離します。 定数部分が寄与する$n \cdot x$かかわらず$i$したがって、最適化は距離項のみに依存します。 
2. 合計距離の合計を次のように書き換えます。$$\sum_{j=1}^n |i - j|$$これは 2 つの算術和に分割されます。左側が寄与します。$\frac{i(i-1)}{2}$、右側が貢献します$\frac{(n-i)(n-i+1)}{2}$。 
3. 1 つの操作の合計貢献度は次のようになります。$$n x + d \left( \frac{i(i-1)}{2} + \frac{(n-i)(n-i+1)}{2} \right)$$4.以来$n x$は一定です$i$では、次のもののみを最大化します。$$f(i) = d \cdot \left( \frac{i(i-1)}{2} + \frac{(n-i)(n-i+1)}{2} \right)$$5. 内部関数は凸です。$i$、つまり、整数を超える最大値は境界の 1 つで発生する必要があります。$i=1$または$i=n$。 これは対称性から来ています。中心から離れるにつれて距離が大きくなり、距離の合計は中央で最小になり、端で最大になります。 
6. したがって、各操作について、両方のエンドポイントを評価します。$i=1$そして$i=n$、それらの寄与を計算し、最大値を取得します。 
7. すべての操作にわたって選択された最適な寄与をすべて合計し、次で割ります。$n$最終的な答えを得るために。 

### なぜ効果があるのか

 すべての更新は追加的かつ線形であるため、各操作は独立しています。 1 つの操作の貢献は、別の操作の配布方法には影響しません。 固定演算の場合、目的は対称二次関数を最大化することになります。$i$。 この関数には整数の内部最大値がないため、境界点を評価するだけで十分です。 これにより、より良い配置を見逃すことがなくなり、操作に対する期待の線形性によって全体的な最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def total_dist(i, n):
    left = i * (i - 1) // 2
    right = (n - i) * (n - i + 1) // 2
    return left + right

n, m = map(int, input().split())
ans = 0

for _ in range(m):
    x, d = map(int, input().split())

    # evaluate both endpoints
    left_val = n * x + d * total_dist(1, n)
    right_val = n * x + d * total_dist(n, n)

    ans += max(left_val, right_val)

print(ans / n)
```実装では、派生した式を直接エンコードします。 ヘルパー関数は、すべての位置を反復処理するのではなく、閉じた形式の等差級数を使用して、選択した中心からの距離の合計を計算します。 

明示的に評価するのは$i=1$そして$i=n$これにより、すべてのセンターにわたる検索が回避されます。 最終的な除算$n$合計を算術平均に変換します。 

浮動小数点ドリフトを避けるために、最終ステップまで整数での計算を維持するように注意する必要があります。 Python の任意精度の整数は、大規模な場合でも安全性を確保します$n$。

 ## 特殊なケース

 いつ$d = 0$、寄与は位置に依存しないため、両方のエンドポイントが同じ結果を生成します。 アルゴリズムは両方を評価し、どちらかを正しく選択し、次の結果をもたらします。$n x$予想通り。 

いつ$d < 0$、距離はペナルティではなく報酬を与えられます。 対称性によって境界での最大距離合計が確実に達成されるため、この式では引き続き端点が正しく評価されます。 たとえば、$n=4, x=1, d=-1$、 両方$i=1$そして$i=4$同一の最大距離合計が生成され、アルゴリズムはこれを直接取得します。 

のために$n=1$、距離項は完全に消えます。 式は次のようになります。$x$、両方のエンドポイントが一致するため、エンドポイント評価は自明のことながら正しい値を返します。 

これらのケースでは、隠れた内部極値が見逃されていないこと、および境界評価がすべての最適な構成を完全に捕捉していることが確認されます。
