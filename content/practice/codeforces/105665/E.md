 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、部分配列に対するクエリに繰り返し答えます。 クエリごとに、連続したセグメントを調べ、非常に特殊な操作を使用してそのセグメントを変換するために必要な特定の「労力」を測定しようとします。 

この操作では要素は直接削除されません。 代わりに、現在のシーケンス内の任意の 2 つの値を選択し、両方を削除して、その積を挿入します。 これにより、マルチセットのサイズが 1 つ変更され、要素間の素因数も混合されます。 このような操作をいくつか実行した後、残りのすべての要素が厳密な条件を満たすようにします。つまり、各数値には少なくとも 2 つの異なる素約数が必要です。 

特定のサブ配列について、そのような状態に到達するために必要な最小操作数が答えであり、そうでない場合は不可能であると報告されます。 

重要な隠された構造は、この操作では因数分解をマージするだけであるということです。 新しい素因数を導入することは決してありません。また、素因数を積に組み込む以外に素因数を削除することもできません。 これは、問題が値自体に関するものではなく、その素因数分解がどのように相互作用するかに関するものであることをすぐに示唆しています。 

制約が十分に大きいため、クエリごとに何も最初から再計算することはできません。 最大 200,000 の要素とクエリを使用すると、クエリごとの因数分解や貪欲なシミュレーションは時間制限をはるかに超えてしまいます。 クエリごとの線形スキャンでも、二次的な動作が発生します。 

セグメントがすでに小さい場合、または 1 や素数などの特別な値のみが含まれている場合、微妙なエッジ ケースが発生します。 たとえば、セグメントが`[1]`1 には素因数がなく、単一要素の状態では何かを乗算することは不可能であるため、これを有効にする方法はありません。 同様に、次のような単一の素数のセグメント`[7]`結合する別の要素がなければ 2 番目の異なる素因数を作成できないため、これも不可能です。 

もう 1 つの注意が必要な状況は、条件をすでに満たしている合成数が多数ある場合です。 単純な解決策では、依然として不必要に演算が実行されたり、実行可能性が「不良」数値の数のみに依存すると誤って想定されたりする可能性があります。しかし、不良要素間の相互作用は重要です。2 つの不良数値を組み合わせて両方を修正できるのは、それらの因子構造が連携している場合に限られます。 

## アプローチ

 ブルート フォース戦略では、各クエリのプロセスをシミュレートします。 特定の部分配列について、2 つの要素を繰り返しスキャンして結合し、残りの数値がすべて「良好」であるかどうかを確認します。 各マージには係数情報の再計算が必要で、クエリごとに最大 O(n) 個のマージが可能です。 これにより、最悪の場合、クエリ全体で O(n³) の動作が発生しますが、n と q が大きい場合には、これは完全に不可能です。 

重要な洞察は、シーケンスを進化する値として考えるのをやめ、代わりに、各要素をすでに有効であるか、まだ「欠陥」であるかによって分類することです。 異なる素因数が 2 つ未満の場合、その数値は欠陥のある数値です。 唯一意味のある作業は、これらの欠陥のある要素を修正することです。すでに良好な数値が掛け算によって悪化することは決してないからです。 

各操作は 2 つの要素をマージするため、構造レベルでは、各操作で最大 2 つの欠陥アイテムを 1 つの新しいアイテムに修正できます。 これは、マージによって有効な結果が得られない、極端に小さい値や構造的に制限された値を含む特殊な場合を除いて、答えはクエリ範囲内に欠陥のある要素がいくつ存在するかによってほぼ完全に制御されることを意味します。 

このように問題を再構成すると、タスクは多くの範囲クエリにわたって効率的に欠陥要素の数を維持するようになります。 これはまさにプレフィックス合計またはフェンウィック ツリーがサポートできるもので、前処理後の各クエリは O(1) または O(log n) に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n3) | O(n) | 遅すぎる |
 | 因子分類 + 接頭辞の合計 | O(n log n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての数値について、その数値が「良好」であるかどうかを事前計算します。つまり、少なくとも 2 つの異なる素因数があることを意味します。 これは、最小の素因数ふるいを使用して、値ごとに異なる素数をチェックして行われます。 このステップでは、各値を生の整数ではなくブール分類に変換します。 
2. 配列をバイナリ配列に変換します。1 は欠陥 (不良) を意味し、0 はすでに良好であることを意味します。 優れた要素には操作が必要ないため、クエリに必要な情報はこれだけです。 
3. 欠陥のあるマーカーに対してプレフィックスの合計を計算します。 これにより、一定時間内にサブ配列に存在する不良要素の数を数えることができます。 
4. クエリごとに、セグメント内の欠陥のある要素の数を計算します。 この値を b と呼びます。 
5. b が 0 の場合、すべてがすでに良好であるため、操作は必要ありません。 
6. b が 1 の場合、1 つの欠陥要素は他のものと組み合わせることができず、それ自体を正常にすることもできないため、答えは不可能です。 
7. b ≥ 2 の場合、答えは b − 1 です。各操作では、最大 1 つが残るまで 2 つを 1 つの改善された要素に効果的にマージすることで、欠陥品目の数が減少します。すべての欠陥を除去する必要があります。 

### なぜ効果があるのか

 重要な不変条件は、選択した両方の要素に欠陥がある場合、すべての操作で欠陥要素の数が 1 つだけ減り、欠陥要素の数が決して増加しないということです。 操作で適切な要素を選択しても、欠陥数は減らず、マージの機会が無駄になるだけであるため、決して有益ではありません。 

したがって、プロセスは、最大でも 1 つが残るまで、欠陥のある要素を繰り返しペアリングするように動作します。 少なくとも 2 つ存在する場合は、いつでもそれらをペアにすることができます。 1 つだけ存在する場合、それは永続的にスタックされます。 したがって、答えはカウントが 0、1、または少なくとも 2 であるかどうかによって完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_spf(mx):
    spf = list(range(mx + 1))
    for i in range(2, int(mx ** 0.5) + 1):
        if spf[i] == i:
            step = i
            start = i * i
            for j in range(start, mx + 1, step):
                if spf[j] == j:
                    spf[j] = i
    return spf

def is_good(x, spf):
    cnt = 0
    last = 0
    while x > 1:
        p = spf[x]
        if p != last:
            cnt += 1
            last = p
        while x % p == 0:
            x //= p
        if cnt >= 2:
            return True
    return False

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    mx = max(a)
    spf = build_spf(mx)

    bad = [0] * (n + 1)
    for i, v in enumerate(a, 1):
        bad[i] = 1 if not is_good(v, spf) else 0

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + bad[i]

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        b = pref[r] - pref[l - 1]
        if b <= 1:
            out.append("-1")
        else:
            out.append(str(b - 1))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```ふるいは最小の素因数を構築するので、各数値を迅速に分解できます。 数値が「良好」であるかどうかだけを気にするため、分類関数は 2 つの異なる素数が見つかると早期に停止します。 

プレフィックス合計は、各クエリを単純な減算に圧縮します。これが、ソリューションを入力制限全体に拡張できる唯一の方法です。 

## 実用的な例

 たとえば、欠陥のある要素と正常な要素が点在する配列を考えてみましょう。`[2, 8, 3, 5, 1, 9, 42, 3]`。 クエリで、少数の欠陥値のみを含むセグメントが選択されたとします。 

セグメントの場合`[2, 8, 3]`、それぞれの番号を分類します。 2 は不良、8 は不良、3 は不良なので、b = 3 となります。 

| ステップ | セグメント | 不良カウント (b) | アクション | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | [2、8、3] | 3 | クエリを計算する | 3 − 1 = 2 |

 このトレースは、操作を決してシミュレートしていないことを示しています。 私たちは構造上の欠陥のみを考慮します。 

ここで、次のようなすでに良好な数値がほとんど含まれているセグメントを考えてみましょう。`[42, 9, 8]`。 ここでは 42 と 9 が良好で、8 だけが不良であるため、b = 1 となります。 

| ステップ | セグメント | 不良カウント (b) | アクション | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | [42、9、8] | 1 | 不可能なケース | -1 |

 これは、単一の欠陥要素を単独で修復できない理由を示しています。

 ## 特殊なケース

 次のようなプライムを含む単一要素クエリ`[7]`結果は不正なカウント 1 となるため、アルゴリズムは -1 を直接出力します。 プレフィックスの合計により、特別な大文字と小文字を区別せずにこれが確実に検出されます。 

のようなセグメント`[6, 10]`両方の数値がすでに良好である場合、 b = 0 が生成されるため、答えは 0 になります。これにより、不要な演算が導入されていないことが確認されます。 

たとえば素数の長いセグメント`[2, 3, 5, 7, 11]`、 b = 5 が生成されるため、答えは 4 になります。アルゴリズムの各ステップでは、欠陥のある要素を任意にペアにできることを暗黙的に前提としています。これは、マージのたびに欠陥の数が 1 つ減り、すでに有効な構造が壊れることがないため当てはまります。
