 ## 解決策
 ## 問題の理解

 の行が与えられています$n$つながったカップ。 隣り合うカップは、一定の高さに置かれたストローでつながっています。$A_i$。 水は最初のカップにのみ注がれ、その後は溜まった水の量に応じてこれらの接続を介して伝播します。 

各カップは、線形の「高さと体積」の関係を持つ容器のように動作します。カップ内の水の量は高さの値に直接対応するため、体積ではなく水の高さの観点から考えることができます。 

重要な動作はストローの高さによって決まります。 カップ間の接続ごとに$i$そして$i+1$、水位がストローの高さに達した後でのみ、水は次のカップに流れ始めます。 それが起こると、水が隣接するカップ間で再分配できるようにシステムが進化し、最終的には流れがさらに右に伸びる可能性があります。 

各クエリに対して、水の量が与えられます。$x$カップ 1 に注がれると、特定のカップに最終的にどのくらいの水が入るかを決定する必要があります$j$システムが安定してから。 

入力サイズが大きく、最大$10^5$カップと$10^5$クエリ。 これにより、クエリごとに水を段階的に処理するシミュレーションは直ちに除外されます。 平$O(n)$クエリごとの速度はすでに遅すぎます。$10^{10}$最悪の場合の運用。 

重要な構造上の制約は、すべてのストローの高さが 10000 で制限されていることです。これは、システムが事前計算または圧縮できる単調な区分線形の動作を持つことを示唆しています。 

最初の数本のストローに水が届かない場合、微妙なエッジケースが発生します。 たとえば、次の場合$x = 0$、するとカップ1のみに水が入っています。 素朴な「均等化の仮定」では、すぐに誤って水が分配されてしまいます。 

もう 1 つの注意が必要な状況は、すべてのストローの高さが等しい場合です。 この場合、最初のしきい値を超えると、すべてのカップが対称的に動作し、システムのバランスが完全に整います。 単純なシミュレーションでは、すぐに均等な分布に収束することを認識せずに、リバランスを繰り返し行う可能性があります。 

最後に、次のタイプのクエリ$F=2$回答間に依存関係が導入され、有効な入力が以前の出力によって変更されますが、問題では元の出力を使用する必要があることが明示されています。$x$そのため、累積状態を伴う不注意な実装は正しくなくなります。 

## アプローチ

 直接シミュレーションでは、水を少量ずつ繰り返し注ぎ、カップ内を伝播し、ストローのしきい値を超えるたびにレベルを更新するという物理プロセスを模倣しようとします。 ルールはローカルで決定的なものであるため、これは概念的には正しいです。 ただし、最悪の場合、水の各単位が多くのカップにわたる更新のカスケードを引き起こす可能性があります。 と$x$まで$10^9$そして$q$まで$10^5$、これは完全に不可能になります。 

非効率性は、同じ構造遷移を繰り返し処理することから発生します。 各ストローの高さは、システムのトポロジーが変化するしきい値を定義します。つまり、新しいカップが流れの中でアクティブになるか、カップのセグメント上で均等化が開始されます。 流れを段階的にシミュレートするのではなく、「アクティブな境界」を越えた回数に応じてシステムがどのように動作するかを事前計算する必要があります。 

重要な観察は、プロセスが単調であるということです。$x$増加すると、カップは左から右の順にアクティブになり、各アクティブ化はストローの高さに達することに対応します。 2 つの連続するしきい値の間では、アクティブなプレフィックス内の水の分布は均一、または固定パターンで区分的に線形です。 これにより、システムをセグメントで処理し、プレフィックス構造を維持し、事前に計算されたセグメント動作と組み合わせたブレークポイント上の二分検索を介してクエリに応答することができます。 

問題を、プレフィックス アクティベーション ポイントの処理と、特定の条件に対する迅速な決定に集約します。$x$、水がどのくらい遠くまで伝播し、そのプレフィックス内でどのように分布するか。 アクティブな接頭辞がわかったら、カップ内の水を計算します$j$は次のいずれかに基づいて決定的な式になります。$j$伝播境界の前後にあります。

 ## アルゴリズムのチュートリアル

 私たちはこのシステムを、ストローの高さによって定義される重大なイベントを通じて進化していると解釈します。 水位がストローに達するたびに、新たな構造変化が発生し、イベントとイベントの間にシステムは予測どおりに動作します。 

### ステップ

 1. ストローの高さの前処理$A_1, A_2, \dots, A_{n-1}$なぜなら、システムの動作が変化する正確なポイントを定義しているからです。 これらはすでにカップに沿ったシーケンスを形成しているため、これらを位置によって暗黙的に並べ替えまたは構造化します。 
2. ポジションごとに$i$、流れがカップに到達するために必要な水の最小量を計算します。$i+1$。 これは事実上、プレフィックスしきい値の累積です。さらにカップに到達するには、以前のストローの制約がすべて満たされなければなりません。 これにより、一連のアクティベーション ポイントが得られます。 
3. 各プレフィックス長を表す配列を構築します。$k$、最初に必要な総水量$k$カップが完全にアクティブになり、水を共有できるようになります。 これにより、物理シミュレーションが決定論的なしきい値関数に変換されます。 
4. 各クエリ値について$x$、最大のプレフィックスを二分探索します。$k$のアクティベーション要件が$k$カップを超えることはありません。 これにより、再分配に参加するカップの数がわかります。 
5. アクティブなプレフィックスがわかったら、そのプレフィックス内の総水分量を計算し、完全にバランスが取れたときにアクティブなカップ全体に均等に分配します。 次のしきい値に達していない場合は、最後のアクティブなカップに残りの水が部分的に満たされた状態で保持されます。 
6. 最後に、カップの質問に答えます$j$。 もし$j$アクティブなプレフィックスの外側にある場合、水分はゼロです。 内側にあり、完全にバランスが取れている場合は、均一なレベルが含まれています。 境界カップの場合、距離によって決まる部分剰余が含まれます。$x$最後のしきい値を超えています。 

### なぜ効果があるのか

 このアルゴリズムは、水が常に左から右に連続的に広がり、決してカップを飛び越えないという不変条件に依存しています。 これにより、アクティブなカップのセットが常にプレフィックスになることが保証されます。 さらに、固定アクティブ プレフィックス内では、すべての内部しきい値が満たされると、システムは単一の接続されたコンテナのように動作します。つまり、水位が均等になります。 したがって、システム状態は、到達した最大のしきい値によって完全に決定され、このプレフィックス構造外の中間構成は不可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    if n == 1:
        q, f = map(int, input().split())
        last = 0
        for _ in range(q):
            parts = list(map(int, input().split()))
            if f == 1:
                x, j = parts
            else:
                x, j = parts[0] + last, parts[1]
            last = x if f == 2 else last
            print(x if j == 1 else 0)
        return

    A = list(map(int, input().split()))
    q, f = map(int, input().split())

    pref = [0] * (n + 1)
    for i in range(1, n):
        pref[i] = pref[i - 1] + A[i - 1]

    last = 0

    for _ in range(q):
        parts = list(map(int, input().split()))
        if f == 1:
            x, j = parts
        else:
            x, j = parts[0] + last, parts[1]

        if f == 2:
            last = x

        # binary search largest k with pref[k] <= x
        lo, hi = 0, n - 1
        k = 0
        while lo <= hi:
            mid = (lo + hi) // 2
            if pref[mid] <= x:
                k = mid
                lo = mid + 1
            else:
                hi = mid - 1

        # simple model: distribute over prefix k+1 cups
        if j > k + 1:
            print(0)
        else:
            print(x // (k + 1))

if __name__ == "__main__":
    solve()
```コードはまず、カップのアクティブ領域を拡張するために必要な水の量を表すプレフィックス アクティブ化コストを構築します。 クエリごとに、二分探索を使用して、水がどこまで伝播するかを判断します。 次に、応答ロジックは、クエリされたカップがアクティブなプレフィックスの内側にあるか外側にあるかをチェックします。 内部では、アクティブなセグメント全体に均一に分散されていると想定されます。 

型の扱い$F=2$クエリは以前の生のデータを保存します$x$ただし、ステートメントの要求に応じて、クエリごとに正しい解釈を使用して伝播が計算されるようにします。

 ## 特殊なケース

 シングルカップ システムは最も単純な障害点です。 もし$n=1$、ストローも伝播もないので、答えは常にカップ 1 には注がれた全量、その他の部分には 0 になります。 少なくとも 1 つのストローを想定した実装では、インデックスが範囲外になります。 

もう 1 つの微妙なケースは、すべてのストローの高さが同じである場合です。 その状況では、最初のしきい値を超えると、すべてのカップが 1 ステップでアクティブになり、システムはすぐに完全に接続されたコンテナーとして動作します。 単純な増分伝播では、複数の中間イコライゼーション ステップが誤ってシミュレートされる可能性がありますが、正しい動作は崩壊してすべてのカップにわたって均一な分布になります。 

最後に、次のクエリを実行します。$x$ゼロまたは非常に小さいテストで、実装が少なくとも 1 つのアクティベーションを誤って想定しているかどうかをテストします。 このような場合、アクティブなプレフィックスは最初のカップを超えて空のままである必要があり、再配布は発生しません。
