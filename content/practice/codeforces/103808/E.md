 ## 問題の理解

 文字列を書き換えるシステムが与えられています。 各ルールは、1 つの文字が 2 文字の文字列にどのように展開されるかを説明します。 ルールが言うなら`c → ab`を含む文字列内の位置を選択するたびに、`c`、その文字をペアで置き換えることができます`ab`。 これにより、アプリケーションごとに文字列の長さが 1 ずつ増加します。 

各テスト ケースでは、ソース文字列から開始します。`s`目的の文字列を取得できるか知りたい`t`これらの置換ルールを任意の順序および任意の位置で繰り返し適用することにより、

 主要な構造特性は、すべての文字が出力するルールを最大 1 つ持ち、ルール グラフにサイクルがないことです。 つまり、任意の文字から開始し、展開を繰り返すと最終的には終了し、書き換えによって元の文字にループバックすることはありません。 ただし、各文字は 2 つの文字に展開できるため、展開は分岐する可能性があります。`s`文字のサブツリー全体を生成できます`t`。 

この制約は、完全な拡張を単純にシミュレートできないことを意味します。 文字は文字列の長さを繰り返し 2 倍にすることができるため、最悪の場合、展開された合計サイズは指数関数的に増加します。 それでも`n ≤ 59`, この構造では依然として長い依存関係チェーンが許可されています。 テスト ケース全体のすべての文字列の長さの合計は最大 3 · 10^5 であるため、ソリューションはテスト ケースごとにほぼ線形またはほぼ線形である必要があります。 

微妙な問題は、ルールが対称的ではなく、拡張が不可逆であることです。 キャラクターが展開されると、元に「マージ」することはできません。 これにより、文字列に対する貪欲なローカル マッチングが難しくなります。

中心的な課題は、生成されたツリー構造をフラットなターゲット文字列と照合することです。

 ## アルゴリズムのチュートリアル

 各文字を、2 つの子を生成する 0 または 1 つの出力ルールを持つグラフ内のノードとしてモデル化します。 次に、ソース文字列を展開するとターゲット文字列が正確に生成されるかどうかを検証します。 

1. 各文字をマッピングする辞書を作成する`c`その拡大に向けて`(a, b)`ルールなら`c → ab`存在します。 これにより、O(1) の子に直接アクセスできるようになります。 
2. 再帰的プロシージャを定義します`dfs(c, pos)`キャラクターの拡張に合わせようとするもの`c`インデックスから正確に開始する`pos`ターゲット文字列内。 次の位置を返します`t`によって生成されたすべてのキャラクターを消費した後、`c`、不一致が発生した場合は失敗します。 位置を返す理由は、各サブツリーが連続したセグメントを消費するためです。`t`。 
3. もし`c`ルールはありません。内の 1 文字と正確に一致する必要があります。`t`であるかどうかを確認します。`t[pos] == c`。 そうでなければ失敗します。 それ以外の場合は戻ります`pos + 1`。 これは拡張ツリーの基本ケースです。 
4. もし`c → ab`、最初に再帰的に一致します`a`から始まる`pos`、新たな地位を獲得する`mid`。 それからマッチングします`b`から始まる`mid`。 これにより、展開順序が左の子の次に右の子となることが強制され、生成された文字列の構造が維持されます。 
5. 初期文字列の各文字について`s`、繰り返し適用します`dfs`現在のグローバル ポインタから開始`t`。 どこかの時点で不一致または範囲外が発生した場合、変換は不可能であると結論付けられます。 
6. すべての文字を処理した後、`s`、正確にすべての文字を消費したかどうかを確認します。`t`。 そうでない場合、変換は不完全であるため、無効になります。 

重要な考え方は、すべての文字が固定順序の拡張ツリーを定義し、ターゲット文字列はこれらのツリーを順序通りに正確に連結したものでなければならないということです。 

### なぜ効果があるのか

 システムは非巡回であり、各ノードには最大でも 1 つの出力エッジがあるため、展開ルールは文字ごとにルート付き順序付きツリーを定義します。 ルールを適用するたびに、ノードがその 2 つの子で左から右の順序で置き換えられるため、最終的な文字列は、まさにこの拡張フォレストの順序走査となります。 

DFS プロシージャは、各サブツリーがターゲット文字列の連続セグメントを消費するように強制します。 サイクルがないため、各キャラクターの展開は明確に定義されており、無限に再訪することはできません。 メモ化またはシングルパス消費により、一貫性のない展開が再計算されることがなくなります。 いずれかの時点で、文字が予期される記号またはセグメンテーションと一致しない場合は、`t`失敗します。有効な展開シーケンスが生成されません。`t`有効な導出は同じツリー分解を尊重する必要があるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    T = int(input())
    
    for _ in range(T):
        n = int(input())
        rule = {}
        
        for _ in range(n):
            line = input().strip()
            a = line[0]
            b = line[3]
            c = line[4]
            # format: a->bc (actually a -> bc)
            rule[line[0]] = (line[3], line[4])
        
        s = input().strip()
        t = input().strip()
        
        idx = 0
        n_t = len(t)
        ok = True
        
        from functools import lru_cache
        
        @lru_cache(None)
        def dfs(ch, pos):
            if pos > n_t:
                return -1
            
            if ch not in rule:
                if pos < n_t and t[pos] == ch:
                    return pos + 1
                return -1
            
            a, b = rule[ch]
            
            mid = dfs(a, pos)
            if mid == -1:
                return -1
            return dfs(b, mid)
        
        cur = 0
        
        for ch in s:
            cur = dfs(ch, cur)
            if cur == -1:
                ok = False
                break
        
        if ok and cur == n_t:
            print("SI")
        else:
            print("NO")

if __name__ == "__main__":
    solve()

メモ化により、同じ位置で同じ文字が繰り返し展開されることが再計算されなくなります。これは重要です。`s`同一のサブツリーに拡張できます。 

ポインタ`cur`グローバルな連結順序を強制します。 の各キャラクター`s`の連続セグメントを完全に消費する必要があります`t`そうでない場合、構造は無効です。 

最終チェック`cur == len(t)`ターゲット内の残りの文字が一致しないままにならないことを保証します。
