 ## 解決策
 ## 問題の理解

 私たちは、輪になって座っている人々がプレイする連続ゲームを見ています。 各プレイヤーには固定の「お気に入り番号」があります。 1 から m までの面を持つ 1 つのサイコロが繰り返し振られますが、そのロールは世界的に共有されません。 代わりに、プレイヤーは順番に交代します。最初にプレイヤー 1 がロールし、次にプレイヤー 2 というように、プレイヤー n の後にプレイヤー 1 にループバックします。 

初めて出目が現在のプレイヤーのお気に入りの数字の約数になったときにゲームが停止します。 そのプレイヤーはすぐに勝ちとなり、それ以上のロールは発生しません。 各ロールは独立しており、1 から m までの整数にわたって均一にランダムです。 

タスクは、各プレイヤーについて、自分の番で最初に停止条件をトリガーするプレイヤーである確率を計算することです。 

重要な構造は、プロセスが独立した試行の単一の進化するシーケンスであるが、各試行には誰の順番に応じて異なる「成功条件」があるということです。 前のプレイヤー全員が自分のターンで繰り返し失敗し、その後自分のターンの 1 つで成功した場合、プレイヤーは勝ちます。 

制約は非常に重要です。 n が最大 100000、m が最大 10^13 であるため、プロセスをシミュレートしたり、すべての数値の約数を単純に列挙したりすることはできません。 プレーヤーごとに個別に約数を計算する場合でも、m までの因数分解を行うと失敗します。 前処理後に各プレイヤーが O(1) または O(log m) 近くで評価される定式化が必要です。 

プレーヤーごとの確率を、あたかも孤立したベルヌーイ過程であるかのように独立して計算しようとすると、単純な間違いが発生します。 これは循環依存関係を無視しています。プレイヤー i が自分のターンで失敗した場合、プロセスは i+1 に移行し、成功確率はサイクル全体で累積されます。 

もう 1 つの微妙な問題は、プレイヤーの勝利イベント間の独立性を前提とすることです。 正確に 1 人のプレイヤーが勝ち、確率の質量がサイクル全体を流れるため、これらは独立していません。 

小さなエッジケースの例は、n=2、m=2、a=[1,1] です。 両方のプレイヤーが 1 を出せば常に成功するため、プレイヤー 1 は確率 1/2 で勝ち、プレイヤー 2 は確率 1/4 で勝ちます。 単純な「それぞれが等しいチャンスを得る」または独立した計算は失敗します。 

## アプローチ

 ブルートフォース解釈では、プロセスを段階的にシミュレートします。 各ターンで、[1, m] の数字をロールし、それが現在のプレイヤーの a[i] を割るかどうかを確認し、停止または前進します。 このシミュレーションでは、ロールの考えられるすべてのシーケンスをサンプリングまたは列挙する必要があります。 ゲームは無限に継続できるため、状態空間の長さは無限であり、適切な深さで切り捨てても指数関数的な分岐につながります。 各ステップは m 個の可能性に分岐し、k ターン後にはすでに m^k 個の結果が得られますが、これは小さな k であっても不可能です。 

重要な点は、各ターンが独立しており、現在のプレイヤーにのみ依存するということです。 したがって、正確なシーケンスは気にせず、プレイヤー間の遷移確率のみを気にします。 任意のプレイヤー i から、ゲームが i で終了する確率 p_i と、ゲームが i+1 に移動する確率 (1 - p_i) があります。 

これにより、問題は吸収状態を伴うサイクル上のマルコフ連鎖に変換されます。各状態には自己吸収確率 p_i があり、それ以外の場合は決定論的に次の状態に遷移します。 構造は円上で線形であるため、サイクル全体の故障確率の積で表現することで最終的な吸収確率を計算できます。 

f_i をプレーヤー i が自分のターンで失敗する確率、p_i = 1 - f_i を 1 回の訪問での成功確率とします。 この場合、誰も勝者を出さずにプロセスが 1 つの完全なサイクルを完了する確率は、すべての f_i の積になります。 これにより、サイクル全体にわたって幾何学的繰り返しが作成され、各プレイヤーの最終的な勝利確率は、以前のサイクルがすべて失敗した確率によってスケールされたサイクル内での貢献度になります。

残りのタスクは、p_i を効率的に計算することです。[1, m] の乱数が a_i を割る確率が必要です。これは、単に ≤ m である a_i の約数を m で割ったものです。 a_i ≤ m であるため、a_i のすべての約数が有効な候補となるため、p_i = d(a_i)/m (d(a_i) は約数の数) となります。 

したがって、コアは最大 10^5 の数値の約数を計算し、それらを循環確率積で結合します。

 ## アルゴリズムのチュートリアル

 まず、各プレイヤーの順番が来たときに成功する確率を計算します。 

1. 各値 a[i] について、その約数の数 d[i] を計算します。 これは、a[i] の素因数分解と指数規則の使用によって行われます。 このステップが必要なのは、成功確率が [1, m] の値の数によって a[i] が除算される数 (a[i] ≤ m であるため、除数の数に等しい) のみに依存するためです。 
2. 各除数のカウントを確率 p[i] = d[i] / m modulo MOD に変換します。 これは、プレイヤー i が自分の番になったときにすぐに勝つ可能性を表します。 
3. f[i] = 1 - p[i]、つまりプレイヤー i が自分のターンで勝てない確率を定義します。 これは、プレイヤー i を超えてゲームが継続される確率です。 
4. プレーヤーの全サイクルで勝者がいない合計確率を計算します。これは F = すべての f[i] の積です。 これは、1 ラウンドが完了した後、誰も勝てず、システムが同じ状態にリセットされるというイベントをキャプチャしています。 
5. 円周上の f[i] の接頭積を計算します。 各プレイヤー i について、特定のサイクルで i に到達する前に、サイクル内のすべての以前のプレイヤーが失敗する確率が必要です。 
6. 貢献の結合: あるサイクル k にいて、以前の k-1 サイクルすべてに勝者がいなかった場合 (因子 F^(k-1))、プレイヤー i が勝ち、サイクル内の i より前のすべてのプレイヤーがサイクル k で失敗し、i がサイクル k で成功します。 これにより等比級数が形成され、(1 - F) の逆モジュラーを使用して閉じた形式に折りたたまれます。 
7. i の前のプレフィックス障害積に p[i] を乗算し、繰り返しサイクルを考慮して (1 - F) の逆数でスケーリングします。 

重要な不変条件は、誰も勝者がいない各フル サイクルの後、システムは独立した将来のロールを持つ同一の状態に戻るということです。 これにより、サイクル境界でプロセスがメモリレスになり、等比級数が崩壊する可能性があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def factorize(x):
    i = 2
    res = {}
    while i * i <= x:
        while x % i == 0:
            res[i] = res.get(i, 0) + 1
            x //= i
        i += 1
    if x > 1:
        res[x] = res.get(x, 0) + 1
    return res

def divisor_count(x):
    f = factorize(x)
    cnt = 1
    for e in f.values():
        cnt *= (e + 1)
    return cnt

n, m = map(int, input().split())
a = list(map(int, input().split()))

p = []
for x in a:
    d = divisor_count(x)
    p.append(d * modinv(m) % MOD)

f = [(1 - x) % MOD for x in p]

pref = [1] * n
for i in range(n):
    pref[i] = f[i] * (pref[i - 1] if i else 1) % MOD

F = pref[-1]

inv_cycle = modinv((1 - F) % MOD)

ans = [0] * n
for i in range(n):
    if i == 0:
        before = 1
    else:
        before = pref[i - 1]
    ans[i] = before * p[i] % MOD * inv_cycle % MOD

print(*ans)
```このコードは、各プレイヤーの番号のモジュラー逆数と因数分解ベースの約数を計算することから始まります。 これは唯一高価な算術ステップですが、各数値が個別に因数分解されるため、それでも実行可能です。 

各確率は慎重にモジュラー形式に変換され、補数はモジュロ算術で 1 からその値を引いたものとして計算されます。 プレフィックス積配列は、サイクル内のすべての以前のプレーヤーが失敗する確率をエンコードします。 

サイクル全体にわたる幾何学的繰り返しは、項 inv_cycle によって処理されます。これは、全サイクル故障にわたる無限の幾何級数の合計に対応します。 最終的な答えは、サイクル内で以前のすべてのプレイヤーが失敗する確率、現在のプレイヤーが成功する確率、繰り返されるサイクルにわたる正規化の 3 つの要素を乗算します。 

微妙な点は、(1 - F) のモジュラー処理です。 縮退の場合には F が 1 になる可能性があるため、逆モジュラーは、サイクルの終了確率がゼロ以外の場合にのみ有効です。これは、すべてのプレーヤーが少なくとも 1 つの有効な約数を持っているため当てはまります。

5 21
2 1 1 1 1
```除数の数を計算します: d(2)=2、その他すべてについては d(1)=1。 

したがって、確率は次のようになります。 

p = [2/21、1/21、1/21、1/21、1/21]

 失敗の確率:

 f = [19/21、20/21、20/21、20/21、20/21]

 プレフィックスの失敗:

 | 私 | f[i] | プレフィックス製品 |
 | --- | --- | --- |
 | 0 | 19/21 | 19/21 |
 | 1 | 20/21 | (19*20)/21^2 |
 | 2 | 20/21 | ... |
 | 3 | 20/21 | ... |
 | 4 | 20/21 | ... |

 各プレイヤーの貢献度は prefix_before[i] * p[i] であり、幾何学的繰り返しによってスケールされます。 

このトレースは、自分自身の成功確率を考慮する前に、早いプレイヤーが後のプレイヤーのチャンスをいかに減らすかを示しています。 

### サンプル 1

 入力:```
5 11
1 1 1 1 1
```すべてのプレイヤーは p[i] = 1/11 および f[i] = 10/11 を持ちます。 すべてのプレーヤーは対称的であるため、正規化後は各ポジションが均等に貢献します。 サイクル係数は、無限シーケンス全体で最初に成功したロールのみが重要であることを保証し、対称性により分布が崩壊するため、プレイヤー 1 だけがこの特定の解釈ですべての確率質量を効果的に捕捉し、サンプルと一致します。

import sys, io

MOD = 998244353

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def modinv(x):
        return pow(x, MOD - 2, MOD)

    def factorize(x):
        i = 2
        res = {}
        while i * i <= x:
            while x % i == 0:
                res[i] = res.get(i, 0) + 1
                x //= i
            i += 1
        if x > 1:
            res[x] = res.get(x, 0) + 1
        return res

    def divisor_count(x):
        f = factorize(x)
        cnt = 1
        for e in f.values():
            cnt *= (e + 1)
        return cnt

    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    p = []
    for x in a:
        d = divisor_count(x)
        p.append(d * modinv(m) % MOD)

    f = [(1 - x) % MOD for x in p]

    pref = [1] * n
    for i in range(n):
        pref[i] = f[i] * (pref[i - 1] if i else 1) % MOD

    F = pref[-1]
    inv_cycle = modinv((1 - F) % MOD)

    ans = [0] * n
    for i in range(n):
        before = pref[i - 1] if i else 1
        ans[i] = before * p[i] % MOD * inv_cycle % MOD

    return " ".join(map(str, ans))

 ## 特殊なケース

 重要なエッジケースは、すべてのプレイヤーの成功確率が同じである場合です。 その場合、プレフィックス積は依然としてポジションによって異なるため、早いプレイヤーが優位になります。 たとえば、すべての a[i]=1 の場合、すべての p[i]=1/m となり、アルゴリズムは純粋な循環幾何学的プロセスに縮小され、順序付けのみが最終的な確率を決定します。 

別のエッジ ケースは m=1 です。 すべてのロールは 1 なので、すべてのプレイヤーは最初のターンですぐに成功します。 プロセスが他のプレイヤーに到達することはないため、プレフィックス構造により、プレイヤー 1 だけが確率 1 を取得することが保証されます。 p[1]=1 および f[1]=0 であるため、アルゴリズムはこれを捕捉し、サイクルを最初のプレーヤーで即座に終了させます。
