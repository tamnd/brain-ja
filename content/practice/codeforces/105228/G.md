 ## 解決策
 ## 問題の理解

 複数の独立したクエリが与えられます。 各クエリは、3 つの点を使用して平面内の三角形を記述します。 垂直の光源が上から輝き、三角形の各点が地面に下向きの垂直投影を投影します。 タスクは、三角形自体の真下の面積を含む、この投影された影の下にある地面上の領域の合計面積を計算することです。 

幾何学的オブジェクトを言い換える便利な方法は次のとおりです。三角形で覆われているすべての x 座標について、その x 値を持つ三角形のすべての点を考慮します。 その中で最大のy座標を取ります。 これは、x に対する区分線形の「屋根」関数を定義し、必要な答えは、この屋根の下の y = 0 までの面積です。 

制約はテスト ケースの数が中程度 (最大 1000) で、座標は絶対値が約 1000 以内の小さな整数です。 これにより、高次元の細かいグリッド上でポイントごとの大量のシミュレーションを実行するアプローチは即座に排除されます。 X 範囲全体が最大でも約 2000 であるため、すべての整数 X 座標にわたる単純なスキャンは依然として実行可能ですが、ピクセルごとまたはテスト ケースごとのペアごとのエッジ相互作用ごとにジオメトリを再計算するものは安全ですが、不要です。 

1 つの頂点が、x 順序の観点から反対側のエッジの垂直投影の「内側」にある場合、微妙なエッジ ケースが発生します。 この状況では、上部境界は 3 つのエッジすべてによって順番に形成されるのではなく、三角形の凸包の 2 つのセグメントのみによって形成されます。 3 つの頂点すべてが常に上部の境界に寄与すると誤って仮定すると、中央の頂点が他の 2 つを接続する線分の下にある場合に面積を過大にカウントすることになります。 

たとえば、点が A(0,0)、B(1,1)、C(2,0) の場合、上部境界は A ～ B ～ C になります。しかし、B が (1,0) の場合、正しい上部境界は単一のセグメント A ～ C となり、B を境界の一部として扱うと、誤って「くぼみ」が作成され、領域が減少します。 

## アプローチ

 強引なアイデアは、細かい X グリッド上で影を直接シミュレートすることです。 x 座標の最小値と最大値の間の各整数 x について、三角形がその x で垂直線と交差する場所を計算し、交点の間で最大の y 値を取得し、小さな台形を使用して面積を累積します。 座標範囲は約 2000 しかないため、テスト ケースごとにおよそ 2000 回の評価が行われ、各評価では三角形のエッジをチェックする必要があるため、安全な上限はおよそ数百万回の操作になります。 それは通過しますが、幾何学的構造が隠蔽され、より壊れやすくなります。 

重要な観察は、三角形が凸面であるため、固定 x の場合、三角形内の点のセットが垂直セグメントを形成し、その上端点がエッジに沿って線形に変化するということです。 したがって、影の上の境界は、x 軸に投影されたときの三角形の上殻にすぎません。 

必要なのは上部のハルだけであることがわかれば、問題はそのハルを形成する三角形のどの辺を選択するかということになります。 X 座標で頂点を並べ替えると、可能性は 2 つだけになります。 中央の頂点が左端と右端の頂点を接続するセグメントの上にある場合、上の境界は左から中央、右へと進みます。 または、そのセグメントの上または下に位置します。この場合、上部の境界は左端から右端までの直線セグメントになります。 

境界が判明すると、その下の面積は連続するハルの頂点間の台形の合計となり、線形セグメントの標準公式を使用して直接計算されます。

## アルゴリズムのチュートリアル

 ### 1. 三角形の頂点を x 座標で並べ替えます。 

x₁ ≤ x₂ ≤ x₃ になるように点にラベルを付けます。 この順序により、水平軸に沿った左端、中央、右端の点が決まります。x では影の境界が単調であるため、これは重要です。 

### 2. 中間点が上部境界に寄与するかどうかを決定します。 

中間点が左端と右端の点を結ぶ線分の上にあるかどうかを確認します。 これは、中点の y 値を線分の x 座標における y 値と比較することによって行われます。 

上にある場合、上部境界は中点を通過する必要があります。 上にない場合は、左端から右端までの直接のセグメントが最大 y に関してすでにすべてを支配しているため、中間点は上のエンベロープとは無関係です。 

### 3. 上部境界ポリラインを作成します

 中間点が使用される場合、境界は、左から中央、および中央から右の 2 つのセグメントからなるポリラインになります。 それ以外の場合は、左から右への単一のセグメントになります。 

### 4. 境界の下の面積を計算する

 境界上の連続する点のペアごとに、それらと X 軸の間の台形面積を計算します。 セグメントが (xₐ, yₐ) を (x_b, y_b) に接続する場合、その寄与は (x_b − xₐ) × (yₐ + y_b) / 2 となります。 

これらの寄与を合計して、合計の影の領域を取得します。 

### なぜ効果があるのか

 三角形は凸面であるため、垂直線は 1 つのセグメント内で三角形と交差します。 これにより、x に対する最大の y 値が、三角形の上凸包によって正確に定義される凹の区分的線形関数であることが保証されます。 三角形には頂点が 3 つしかないため、その上部ハルには最大 3 つの点を含めることができます。唯一のあいまいさは、中央の X 頂点がベース セグメントの上にあるか下にあるかです。 その選択が正しく解決されると、積分される関数は各区間で正確に線形になるため、台形積分は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def upper_area(p):
    p.sort()  # sort by x

    (x1, y1), (x2, y2), (x3, y3) = p

    def on_or_below(xa, ya, xb, yb, xc, yc):
        # check if B is above AC using cross product (A->C) x (A->B)
        return (xb - xa) * (yc - ya) - (yb - ya) * (xc - xa) <= 0

    # if middle point is not above segment x1-x3, use direct segment
    if on_or_below(x1, y1, x3, y3, x2, y2):
        hull = [(x1, y1), (x3, y3)]
    else:
        hull = [(x1, y1), (x2, y2), (x3, y3)]

    area = 0
    for i in range(len(hull) - 1):
        xA, yA = hull[i]
        xB, yB = hull[i + 1]
        area += (xB - xA) * (yA + yB) / 2

    return area

def main():
    t = int(input())
    out = []
    for _ in range(t):
        arr = list(map(int, input().split()))
        pts = [(arr[0], arr[1]), (arr[2], arr[3]), (arr[4], arr[5])]
        out.append(str(int(upper_area(pts))))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```解決策は、三角形の水平構造が明確になるように点を並べ替えることから始まります。 機能`on_or_below`外積テストを使用して、中間点が外側の点を結ぶ線の上にあるかどうかを判断します。 これにより、浮動小数点演算が回避され、すべてが整数空間に保持されます。 

面積の計算は、上部境界セグメントに沿った台形積分を直接適用します。 この問題では整数の出力が保証されているため、ここでは浮動小数点除算を使用するのが安全ですが、内部的には整数のエンドポイントにより値が正確なままです。 

## 実用的な例

 中点がベース セグメントの上にある三角形を考えてみましょう。 

入力点: (0,0)、(1,2)、(2,0)

 | ステップ | 考慮すべき点 | 決定 | 境界 |
 | --- | --- | --- | --- |
 | 1 | (0,0)、(1,2)、(2,0) | ベースの上の真ん中 | (0,0)->(1,2)->(2,0) |
 | 2 | セグメント0-1 | 台形 | エリア追加 |
 | 3 | セグメント 1-2 | 台形 | エリア追加 |

 境界は中間点で上に曲がっているため、影は単純な三角形分割よりも大きくなります。 

次に、平坦な中点の場合を考えてみましょう。 

入力点: (0,0)、(1,0)、(2,2)

 | ステップ | 考慮すべき点 | 決定 | 境界 |
 | --- | --- | --- | --- |
 | 1 | (0,0)、(1,0)、(2,2) | ベースより上ではない真ん中 | (0,0)->(2,2) |
 | 2 | 単一セグメント | 台形 | 全エリア |

 ここでは、中間点は上部エンベロープに影響を与えないため、影は完全に極点によって決まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def upper_area(p):
        p.sort()
        (x1,y1),(x2,y2),(x3,y3)=p

        def ok():
            return (x2-x1)*(y3-y1) - (y2-y1)*(x3-x1) <= 0

        if ok():
            hull=[(x1,y1),(x3,y3)]
        else:
            hull=[(x1,y1),(x2,y2),(x3,y3)]

            xA,yA=hull[i]
            xB,yB=hull[i+1]
            ans+=(xB-xA)*(yA+yB)/2
        return int(ans)

    t = int(input())
    out=[]
    for _ in range(t):
        a=list(map(int,input().split()))
        pts=[(a[0],a[1]),(a[2],a[3]),(a[4],a[5])]

 ## 特殊なケース

 ソート後に三角形の最高点が中央の X 頂点ではない場合、クリティカルなエッジ ケースが発生します。 たとえば、左端または右端の頂点が最高点でもある場合でも、船体の構造が自然に 2 点に減り、台形公式が単一の大きなセグメントに正しく折りたたまれるため、アルゴリズムは引き続き機能します。 

もう 1 つの微妙なケースは、中点が他の 2 つの間のセグメント上に正確に位置する場合です。 その状況では、外積テストはゼロを返し、アルゴリズムは中間点を正しく破棄し、冗長ではあるが無害な分割を導入する不必要なセグメント化を回避します。
