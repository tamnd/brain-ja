 ## 解決策
 ## 問題の理解

 それぞれが非常に短い辞書の単語の固定セットが与えられ、その後、多数のクエリが与えられます。 各クエリは単語とランクを提供します。 

クエリ単語の場合、接尾辞の一致を使用して、すべての辞書単語と比較します。 辞書の単語は、クエリ単語と少なくとも 1 つの接尾辞を共有する場合に関連があるとみなされます。 このようなすべての一致の中で、まずクエリ単語と辞書単語の間に現れる最大のサフィックス長を特定します。 この最大接尾辞長に達する辞書の単語のみが保持されます。 これらから単語を辞書順に並べ替え、k 番目の単語を選択します。 答えは単語そのものではなく、入力リスト内の元の位置です。 選択したグループに十分な単語がない場合、答えは -1 になります。 

重要な構造上の詳細は、単語が非常に短く、長さが最大 ​​5 であることです。各単語は一定数の接尾辞のみを提供するため、出現できる個別の接尾辞の数が即座に制限されます。 

素朴な解釈では、各クエリ単語をすべての辞書単語と比較し、接尾辞の一致を直接計算しようとします。 最大 10^5 の辞書単語と 10^5 のクエリでは、それぞれの比較が短い場合でも、非常に遅すぎます。 

2 番目の微妙な問題は、「最適一致」が単語ごとに独立して定義されるのではなく、クエリごとにグローバルに定義されることです。 短い接尾辞に一致する辞書の単語は、別の単語が長い接尾辞に一致する場合には意味がありません。 

複数のサフィックス長が存在する場合、単純な失敗ケースが発生します。 

たとえば、辞書の単語が次のような場合`["aba", "caba"]`そしてクエリは`"xxcaba"`、両方の単語が接尾辞に一致します`"aba"`しかし、ただ`"caba"`接尾辞の長さ 4 に一致します。正解は、長さ 3 の一致をすべて完全に無視する必要があります。 

もう 1 つの落とし穴は、接尾辞の長さでフィルタリングした後に辞書編集的な順序を忘れることです。 2 つの単語が両方とも最適なサフィックス長に一致する可能性がありますが、答えは入力順序ではなく並べ替え順序によって異なります。 

## アプローチ

 直接的なブルート フォース ソリューションでは、各クエリ単語とすべての辞書単語を比較し、末尾から最大 5 文字をスキャンして、それらの最長の共通接尾辞を計算します。 各比較のコストは O(5) であるため、単一のクエリのコストは O(5n)、すべてのクエリのコストは O(5nq) であり、これは 10^10 の演算に相当します。 これは制限時間をはるかに超えています。 

単語の長さが最大 ​​5 であるという制約により、構造が完全に変わります。 辞書の各単語は、最後の文字、最後の 2 文字など、単語全体に至るまで、少数の接尾辞のセットのみを提供します。 考え方を逆にすると、クエリをすべての単語と比較する代わりに、辞書の単語を接尾辞によって事前にグループ化できます。 

辞書の単語ごとに、そのすべての接尾辞を生成し、その接尾辞文字列をキーとするバケットに単語を保存します。 各バケットは、その接尾辞を共有するすべての辞書の単語を表します。 クエリが同じ接尾辞で終わる場合、その正確な接尾辞の長さで一致するすべての単語をすぐに取得できます。 

重要な観察は、答えがこの事前計算された構造内に存在する最長の接尾辞のみに依存するということです。 したがって、各クエリについて、空ではないバケットが見つかるまで、そのサフィックスを最長から最短までチェックします。 そのバケットはまさに、可能な最大の接尾辞一致長を達成する単語のセットです。 次に、前処理中にそのバケットを辞書順に一度並べ替えて、各クエリがそのバケットに直接インデックス付けできるようにします。 

これにより、各クエリは最大 5 つのサフィックスをチェックし、単純な k 番目の選択を実行するようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq · 5) | お(1) | 遅すぎる |
 | 事前計算されたサフィックス バケット | O((n + q) · 5 + Σ ソート) | O(n · 5) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 辞書の単語ごとに、単語全体の最後の文字、最後の 2 文字などを取得して、そのすべての接尾辞を生成します。 各接尾辞をキーとするマップ内に単語の元のインデックスを保存します。 これにより、任意の接尾辞文字列から、それを含むすべての単語への直接アクセスが構築されます。 
2. すべての辞書単語を処理した後、各サフィックス バケットに格納されている単語のリストを単語自体の辞書順に並べ替えます。 後で必要な位置を出力できるように、単語とその元のインデックスの両方を保持します。 
3. 各クエリ単語について、長さの降順に接尾辞を考慮します。 完全な単語から始めて、1 文字だけが残るまで最初の文字を徐々に削除します。 
4. 各サフィックスについて、事前計算されたマップに存在するかどうかを確認します。 最初に見つかった接尾辞は、辞書の単語と共有される可能な最大接尾辞長に対応します。 
5. マップ内に接尾辞が見つからない場合は、辞書の単語がクエリと接尾辞を共有しないため、-1 が出力されます。 
6. それ以外の場合は、対応するバケットを取り出します。 サイズが k 未満の場合は、-1 を出力します。 それが十分に大きい場合は、辞書順で k 番目の要素を選択し、格納されている元のインデックスを出力します。 

正確さは、サフィックスが厳密に長さの降順でチェックされるという事実から得られます。 最初の一致によって最大性が保証されるため、そのバケットの外にある辞書の単語に対して接尾辞の一致は存在できなくなります。 そのバケット内のすべての単語はその接尾辞の長さを正確に共有しており、より短い接尾辞に一致する単語は問題の定義からは無関係です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    words = []
    buckets = {}

    for i in range(n):
        w = input().strip()
        words.append(w)
        L = len(w)
        for j in range(L):
            suf = w[j:]
            if suf not in buckets:
                buckets[suf] = []
            buckets[suf].append((w, i + 1))

    for suf in buckets:
        buckets[suf].sort(key=lambda x: x[0])

    q = int(input())
    for _ in range(q):
        s, k = input().split()
        k = int(k)

        found = None

        for i in range(len(s)):
            suf = s[i:]
            if suf in buckets:
                found = buckets[suf]
                break

        if not found or len(found) < k:
            print(-1)
        else:
            print(found[k - 1][1])

if __name__ == "__main__":
    solve()
```前処理段階では、接尾辞文字列からその接尾辞を共有するすべての辞書単語までの辞書を構築します。 ソートは単語ごとに行われますが、出力には元のインデックスが必要であるため、格納された各エントリは単語とその元の位置の両方を保持します。 

各バケットは一度ソートされるため、すべてのクエリは再計算せずに k 番目の辞書編集要素に直接アクセスできます。 

クエリ中に、クエリ単語の接尾辞が最長から最短の順にテストされます。 最初に成功した検索では、最大のサフィックス一致長が保証されます。 次に、対応するバケットを使用してランキング要求に応答します。 

微妙な点は、接尾辞の一致を動的に再計算しないことです。 すべての比較は、事前計算されたキーの辞書検索に集約されるため、クエリ時間が一定に保たれます。 

## 実用的な例

 小さな辞書とクエリ セットについて考えてみましょう。 

辞書：`["aba", "caba", "baba"]`クエリ:`"xxcaba", k = 2`| ステップ | サフィックスがチェックされました | マップ内に存在します | 選択されたバケット |
 | --- | --- | --- | --- |
 | 1 | "xxcaba" | いいえ | なし |
 | 2 | "xcaba" | いいえ | なし |
 | 3 | 「キャバ」 | はい | [「キャバ」] |

 この時点で検索は停止します。`"caba"`最長の有効な接尾辞です。 バケットには 1 つのワードしか含まれていないため、k = 2 は無効で、出力は -1 になります。 これは、長い接尾辞が見つかった後は、短い接尾辞の一致が決して考慮されないことを示しています。 

次に、次のことを考えてみましょう。 

辞書:`["abc", "xbc", "c", "bc"]`クエリ:`"zzbc", k = 2`| ステップ | サフィックスがチェックされました | マップ内に存在します | 選択されたバケット |
 | --- | --- | --- | --- |
 | 1 | "zzbc" | いいえ | なし |
 | 2 | "zbc" | いいえ | なし |
 | 3 | "BC" | はい | ["abc", "xbc", "bc"] |

 辞書順に並べ替えると、バケットは次のようになります。`["abc", "bc", "xbc"]`。 2番目の要素は`"bc"`したがって、出力は元のインデックスになります。 

トレースは、サフィックスの選択によって問題が単一の事前計算済みグループにどのように絞り込まれ、そのグループ内での順序付けによって最終的な答えがどのように決定されるかを示します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · L + q · L + 合計ソート) | 各単語は最大 5 つの接尾辞を提供し、各クエリは最大 5 つの接尾辞をチェックし、各バケットは 1 回ソートされます。 
| スペース | O(n・L) | すべての接尾辞には辞書の単語への参照が格納されます。 

L の値は最大 5 であるため、L に関係するすべての要素は一定のオーバーヘッドとして動作します。 これにより、10^5 の単語やクエリであっても、時間とメモリの両方が制限内に快適に保たれます。

 ## 特殊なケース

 クエリが複数のサフィックス長に一致する場合は、サフィックスを最長から最短までスキャンすることで処理されます。 最初に成功した検索は常に、可能な最大一致長に対応します。これは、短いサフィックスはすべて、長いサフィックスが使い尽くされた後にのみ考慮されるためです。 

のようなクエリの場合`"abcd"`辞書の単語で`"bcd"`そして`"cd"`、アルゴリズムは最初にチェックします`"abcd"`、 それから`"bcd"`、すぐに停止します`"bcd"`。 短い接尾辞`"cd"`は決して考慮されず、「最大サフィックス長」要件の正確性が維持されます。 

もう 1 つのエッジ ケースは、複数の単語が同じ最良の接尾辞を共有しているにもかかわらず、任意の入力順序で出現する場合です。 各バケットは構築後に辞書編集的に明示的にソートされるため、k 番目の要素の選択は入力順序とは無関係であり、挿入順序によって引き起こされる不正解を防ぎます。
