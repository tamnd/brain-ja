 ## 解決策
 ## 問題の理解

 各要素が最大 10^18 の大きな整数である配列が与えられており、2 つの演算をサポートする必要があります。 1 回の操作で配列内の 1 つの位置が更新されます。 もう 1 つの演算は部分配列を取得し、各要素に数字ベースの変換を繰り返し適用する場合、部分配列内のすべての値が同一になるまでに何回の適用が必要か、およびその最小数が必要であるかを尋ねます。 

変換関数は数値を受け取り、その桁の合計を 10 進数で計算し、その数値の最小桁を減算します。 この関数を繰り返すと、最終的にすべての数値が小さな固定範囲の値に近づきます。これは、桁の合計が急速に縮小し、最小桁の減算によってその縮小がわずかに変更されるだけであるためです。 

主な困難は、更新を伴うダイナミック レンジ クエリを通じて、この繰り返しの変換の下で多くの値の「収束の深さ」を比較する必要があることです。 n と q が最大 10^5 の場合、クエリごとまたは要素ごとにこのプロセスを再計算することは不可能です。 

単純なアプローチでは、すべての値が一致するまで、各クエリのすべての要素に対して f を繰り返しシミュレートします。 アプリケーションごとに大きさは小さくなりますが、10^18 のような数値では依然として複数のステップが必要になる可能性があり、これをクエリごとに 10^5 要素にわたって実行すると爆発的に増加します。 

1 つまたは 2 つの変換後に数値がすでに小さいか等しい場合、微妙なエッジ ケースが発生します。 たとえば、範囲内のすべての数値が最初は同一である場合、答えはゼロになります。 それらが異なる速度で等しさに収束する場合、事実上、それらの間の会合点までの最大距離が求められます。 

もう 1 つの重要なエッジ ケースはゼロです。 桁がすべてゼロなので f(0) = 0 なので、すでに安定しています。 厳密に正の数字の動作を想定しているロジックはここでは失敗します。 

この制約は、各クエリが対数または対数に近い時間内で応答される必要があり、各更新も効率的である必要があり、クエリごとのシミュレーションを完全に排除する必要があることを意味します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 数値ごとに関数 f を安定した値に達するまで繰り返し適用し、安定するか固定点に到達するまでに必要なステップ数を記録します。 次に、クエリ [l, r] について、範囲内のすべての要素を調べ、それらの安定化シーケンスを計算し、繰り返し適用した場合にすべての要素が等しくなるまでにかかる時間を決定します。 これは本質的に、すべてのシーケンスが共通の値で交差する最初の時間を追跡することを意味します。 

f は最終的に任意の数値を小さなサイクルまたは固定点に換算するため、これは原理的に機能し、すべての要素が有限の軌道を持つようになります。 ただし、コストはこれらの軌道を繰り返し再計算することによって大きく左右されます。 各数値に約 O(log x) のアプリケーションが必要な場合でも、クエリごとに最大 10^5 要素にわたってこれを再計算すると、最悪の場合約 10^10 の演算が必要になります。 

重要な点は、この関数が任意ではなく、値を強力に圧縮していることです。 少数のアプリケーションを適用すると、すべての数値が小さな値のセットに分解されます。 これは、実際には完全な軌道は必要ないことを意味します。 必要なのは、各番号が正規の代表に到達するまでに必要なステップ数と、これらのステップが結合範囲でどのように動作するかを知ることだけです。 

各値が小さな「安定性の深さ」にマッピングできること、およびこの深さが f の下で単調属性のように動作することが認識されると、問題はポイント更新を伴う整数に対する範囲クエリになります。 これは、セグメントごとにこれらの深さの最大値を維持するセグメント ツリーを使用して処理できます。 すべての値がいつ等しくなるかは最も遅い収束要素によって決まるため、範囲の答えはこれらの深さがどのように揃うかによって導き出されます。 

本当の計算上の利点は、更新値ごとに 1 回だけ F チェーンを事前計算し、それ以外はすべてセグメントの集約として扱うことからもたらされます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n × q × k) | O(n) | 遅すぎる |
 | 最適 | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、これまでに保存した値について、安定するまで f を繰り返し適用したときにその値がどのように変化するかを事前計算します。 値は急速に縮小するため、このチェーンは短く、個別の値ごとに結果をキャッシュできます。 

次に、各数値に対して深度 (安定したエンドポイントに到達するために必要なアプリケーションの数) を定義します。 この深さは、セグメント ツリーで維持する重要な不変条件です。 

各ノードがこれらの深さから得られる情報を格納する配列上にセグメント ツリーを構築します。 

## アルゴリズムのチュートリアル

 1. 各値 x について、シーケンス x、f(x)、f(f(x)) を計算し、シーケンスが静止したときに停止します。 この固定点に到達するために必要な歩数を記録します。 これにより、x の「深さ」が得られます。 
2. 各リーフが対応する配列要素の深さを格納するセグメント ツリーを構築します。 内部ノードは、セグメント全体にわたる集約情報 (主に最大深度) を保管します。 
3. タイプ 1 クエリの場合、新しい値 v の深さを再計算し、その位置でセグメント ツリーを更新することにより、位置 x を更新します。 
4. [l, r] に対するタイプ 2 クエリの場合、セグメント ツリーからその範囲の最大の深さを取得します。 この最大値は、f を繰り返し適用した場合に安定するのに最も遅い要素を表します。 
5. f を繰り返し適用すると、範囲内のすべての要素が等しくなるために必要な適用の数として、この最大値を出力します。 

最大値のみが必要な理由は、すべての要素が同じ安定値に達すると、さらに f を適用するとすべての値が同一に保たれ、最後に「追いつく」要素が時間を決定するためです。 

### なぜ効果があるのか

 f を繰り返し適用すると、各要素は固定点に到達するまで決定的な減少軌道をたどります。 f を繰り返しグローバルに適用すると、すべての要素が等しくなるプロセスは、要素間の最も遅い収束によって支配されます。 f は値を増やすことはなく、最終的にはすべての数値を小さな固定セットにまとめるため、同期までの時間は、範囲内の個々の収束深さの最大値となります。 これにより、安定した不変条件が得られます。セグメント ツリーは常に正しい最大収束深度を保存し、各点が独立して再計算されるため、更新は正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def f(x: int) -> int:
    s = 0
    mn = 10
    if x == 0:
        return 0
    while x > 0:
        d = x % 10
        s += d
        if d < mn:
            mn = d
        x //= 10
    return s - mn

def build_chain(x: int):
    seen = {}
    cur = x
    steps = 0
    while cur not in seen:
        seen[cur] = steps
        nxt = f(cur)
        if nxt == cur:
            break
        cur = nxt
        steps += 1
    return steps

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [0] * (4 * self.n)
        self.arr = arr
        self.build(1, 0, self.n - 1)

    def build(self, v, l, r):
        if l == r:
            self.t[v] = arr_depth[self.arr[l]]
        else:
            m = (l + r) // 2
            self.build(v * 2, l, m)
            self.build(v * 2 + 1, m + 1, r)
            self.t[v] = max(self.t[v * 2], self.t[v * 2 + 1])

    def update(self, v, l, r, pos, val):
        if l == r:
            self.t[v] = val
        else:
            m = (l + r) // 2
            if pos <= m:
                self.update(v * 2, l, m, pos, val)
            else:
                self.update(v * 2 + 1, m + 1, r, pos, val)
            self.t[v] = max(self.t[v * 2], self.t[v * 2 + 1])

    def query(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.t[v]
        m = (l + r) // 2
        res = 0
        if ql <= m:
            res = max(res, self.query(v * 2, l, m, ql, qr))
        if qr > m:
            res = max(res, self.query(v * 2 + 1, m + 1, r, ql, qr))
        return res

n = int(input())
arr = list(map(int, input().split()))
q = int(input())

arr_depth = {}

def get_depth(x):
    if x in arr_depth:
        return arr_depth[x]
    arr_depth[x] = build_chain(x)
    return arr_depth[x]

for x in arr:
    get_depth(x)

st = SegTree(arr)

out = []
for _ in range(q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 1:
        _, pos, val = tmp
        pos -= 1
        d = get_depth(val)
        st.update(1, 0, n - 1, pos, d)
    else:
        _, l, r = tmp
        l -= 1
        r -= 1
        out.append(str(st.query(1, 0, n - 1, l, r)))

print("\n".join(out))
```この実装では、最初に数字ベースの関数 f を定義し、次に各値が安定するのに必要なステップ数をメモ化します。 これにより、同じ値が複数回出現する場合、または更新後に再利用される場合の再計算が回避されます。 

セグメント ツリーには、これらの事前計算された深さが格納されます。 各更新では、影響を受ける位置のみが再計算されます。 各クエリは範囲にわたる最大の深さを抽出し、それが答えとして直接解釈されます。 

微妙な点は、深さの計算がグローバルにキャッシュされることです。 メモ化を行わないと、同じ値で更新を繰り返すと、同じ数字チェーンが繰り返し再計算され、パフォーマンスが低下する可能性があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | セグメント ツリー操作が支配的であり、各更新/クエリは対数的です。 
| スペース | O(n) | ツリーストレージとメモ化された深さキャッシュ |

 このソリューションは、各クエリが log n の集計に削減され、ディジット チェーンの計算がキャッシュを通じて頻繁に再利用されるため、制限内に問題なく収まります。

 ## 特殊なケース

 重要なエッジケースは、すべての要素がすでに同一である場合です。 この状況では、すべての要素の深さが同じになるため、等価性を得るには変換が必要ないため、正規化後に範囲クエリは 0 を返します。

最後のエッジケースは、同じ値で更新が繰り返されることです。 深さの計算はメモ化されているため、更新を繰り返しても数字チェーンが再計算されず、敵対的なシーケンス下でもパフォーマンスが安定します。
