 ## 解決策
 ## 問題の理解

 いくつかの独立したシナリオが与えられています。 それぞれのシナリオには、$n$それぞれに高さの値が指定されたステップと、左端のステップから右端のステップに移動するカエル。 カエルは旅を始める前に、手順を任意の順序に並べ替えることができます。 

移動ルールは、連続するステップ間の高さの違いに基づいています。 カエルが上向きにジャンプする場合、高さの増加は以下を超えてはなりません$k$。 下に下がった場合、その減少幅は以下を超えてはなりません$k$同じように。 絶対高低差を超えるジャンプ$k$失敗の原因となります。 問題は、すべての隣接する差が最大で最初から最後までのすべてのステップの順序が存在するように、指定された高さのマルチセットを並べ替えることができるかどうかです。$k$。 

各テスト ケースの出力は、そのような順序付けが存在するかどうかを示す 1 文字です。 

制約は十分に小さいので、どのような解決策もおおよそ$O(n \log n)$テストケースごとに問題ありません。 合計から$n$テスト ケース全体の数は最大 2000 ですが、各テストを個別に並べ替えても十分に高速です。 テストごとに二次関数を実行することは実際にはまだ許容されますが、階乗的に増加するため、すべての順列を試行したりバックトラックしたりすることは避けるべきです。 

微妙な問題は、再配置により位置構造が完全に削除されることです。 これが重要な変更点です。私たちは配列の走査問題に取り組んでいるのではなく、境界のある隣接する差分を含む順列を構築しているのです。 

単純だが誘惑しやすい間違いは、連続する並べ替えられた要素間の最大ギャップが最大以下であるかどうかをチェックするだけでよいと仮定することです。$k$。 それは実際には正しいのですが、多くの人は考えすぎて、貪欲なシミュレーションやグラフの接続を試みます。 

## アプローチ

 強引な解釈では、高さのすべての順列を試し、各順列が隣接するすべての差が最大であるという制約を満たすかどうかを確認することになります。$k$。 これは正しいですが、すぐには実行不可能です。$n!$順列は、$n = 10$。 

We need to understand what property of a permutation makes all adjacent differences bounded by$k$。 配列がソートされると、連続して選択された要素間の可能な最大のジャンプが最小限に抑えられます。 並べ替えでは近くの値ができるだけ密に配置されるため、他の順序では、並べ替えられた順序と比較して、隣接するギャップがいくらか増加するだけです。 

これは重要な洞察につながります。配列を並べ替えると、その並べ替え順序における最悪の隣接差は、まさに連続する要素間の最大ギャップになります。 その最大ギャップが最大でも$k$、ソートされた順序を有効な構造として単純に使用できます。 超えた場合$k$場合は、再配置しても問題を修正できません。これら 2 つの値は、どこかで少なくとも 1 つの隣接関係によって分離されている必要があり、値間の隣接関係には、順序付けのある時点で少なくともそのギャップが発生する必要があるためです。 

したがって、問題はソート後の単一の条件のチェックに帰着します。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 高さと制限のリストを読む$k$。 問題の構造は順序に依存しないため、入力を直ちにマルチセットとして扱います。 
2. 配列を降順でない順に並べ替えます。 ソートが使用されるのは、連続する要素間の局所的な差異が最小限に抑えられるためであり、まさにカエルが気にしていることです。 
3. ソートされた配列をスキャンし、連続する要素間の最大差を計算します。 
4. いずれかの時点で差が超えた場合$k$、有効な再配置が存在しないとすぐに結論付けられ、出力は失敗します。 それ以外の場合は成功と判断します。 
5. すべてのテスト ケースに対して繰り返します。 

このスキャンで十分である理由は、ソートされた順序が値の最も「圧縮された」配置であるためです。 他の順列では、最悪のギャップを改善できない方法で、並べ替えられた隣接関係の 1 つ以上の少なくとも 1 つの隣接関係が導入されます。 

### なぜ効果があるのか

 有効な置換を考慮します。 最小要素と最大要素を見てください。 順列のある時点で、遷移は中間値の間を移動する必要があります。 値間の可能な限り緊密な連鎖は、値を大きさ順に並べることによって実現されます。 この最適な連鎖でも、最大の隣接ギャップが$k$の場合、その値のペアは、トラバーサルのどこかで隣接しているか、累積遷移によってローカル ジャンプの最大要件を削減できない中間値によってブリッジされている必要があります。 したがって、ソートされた配置は、隣接する差異の最小構成として機能するため、それをチェックするだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        a.sort()
        
        ok = True
        for i in range(n - 1):
            if a[i + 1] - a[i] > k:
                ok = False
                break
        
        out.append("S" if ok else "F")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、各テスト ケースを個別に分類することを中心に構成されています。 重要な操作は並べ替え後の単一パスであり、隣接するもののみを比較します。 決定変数`ok`違反が発生したかどうかを追跡します。 早期ブレークは正確性のためには必要ありませんが、最悪の場合の入力における不必要な比較を減らします。 

よくある間違いは、並べ替え後は隣接する相違点のみが重要であることを忘れることです。 隣接しないペア間の有効なパスは中間ステップによってすでに制約されているため、隣接しないペアを考慮する必要はありません。

 ## 特殊なケース

 主なエッジケースは次のような場合です$n = 2$。 この場合、答えは 2 つの値の絶対差が最大かどうかによってのみ決まります。$k$。 2 つの要素の並べ替えとその違いの確認はまったく同じロジックであるため、アルゴリズムはこれを自然に処理します。 

すべての値が同一である場合、別の特殊なケースが発生します。 並べ替えではどこでも差分がゼロになるため、スキャンは失敗を引き起こすことなく合格し、次のような場合でも正しく成功を返します。$k = 0$。 

より具体的なケースは、次のような 1 つの値が残りの値から大きく外れている場合です。`[1, 2, 3, 100]`小さいもので$k$。 収量の選別`[1, 2, 3, 100]`、3 と 100 の間のギャップは直ちに制約に違反します。 これは、どの置換でも、チェーン内のどこかの時点で 100 を隣接して配置し、大きすぎるジャンプを強制することを避けることができないことを正しく反映しています。
