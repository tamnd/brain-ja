 ## 問題の理解

 私たちにはハトの種類のコレクションが与えられていますが、それぞれの種類で購入できるハトの数は限られています。 目標は、できるだけ多くの同じ鳩舎を建てることです。 すべての家には正確に含まれている必要があります`k`同じ家の中にある 2 羽のハトが同じ種に属することはできません。 ただし、その種で利用可能なハトの数を超えない限り、同じ種が複数の異なる家に出現する可能性があります。 

割り当てを明示的に構築する必要はありません。 これらの制約の下で形成できる家の最大数を決定するだけで済みます。 

重要な問題は、より多くの家を選択すると、各種が再利用できる頻度が制限されることです。これは、1 つの種が家ごとに提供できるハトはせいぜい 1 羽だけであるためです。 構築しようとすると`H`家、そしてそれぞれの種`i`せいぜい貢献できる`min(p_i, H)`合計で鳩。 

これは、実現可能性の条件を即座に示唆します。候補となる住宅の数を固定した場合`H`、すべての種の使用可能なハトの合計は次のようになります。`sum(min(p_i, H))`。 各家庭に必要なものなので、`k`ハトが必要です`sum(min(p_i, H)) >= H * k`。 

制約は次のとおりです`n = 10^5`そして`p_i ≤ 10^9`したがって、考えられるすべての割り当てを試したり、住宅ごとの分布をシミュレートしたりするソリューションは、非常に遅すぎます。 固定の素朴なチェック`H`これは問題ありませんが、多くの値を効率的にテストできなければなりません。これは、単調な実現可能性構造と二分探索を示唆しています。 

種が非常に大きい場合、微妙な特殊なケースが発生します。`p_i`。 素朴な解釈では、そのような種が常にすべての家に完全に寄与できると誤って仮定する可能性がありますが、「家ごとに 1 つ」という制限があるため、それでも家の数によって制限されます。 たとえば、次の場合`k = 2`、`p = [1000]`そうすると、たとえたくさんのハトがいたとしても、1 つの家を埋めるのに十分な明確な種が存在しないため、0 件以上の家を建てることはできません。 

次の場合には、別のエッジケースが発生します。`k > n`。 たとえ鳩の総数が多くても、一軒の家には必要な数が必要です。`k`異なる種が存在する場合、これは不可能です。`k`種。 したがって、正しい答えは常にゼロになります。 

## アプローチ

 直接的な試みは、家を一軒ずつ建設することです。 各家について、まだハトが残っている種を繰り返し選択し、各家につき 1 種につき最大 1 羽のハトを選択するようにしました。 各家を満たした後、カウントを減らして続行します。 各選択ステップで多くの種をスキャンする可能性があり、このプロセスを次の段階まで繰り返す可能性があるため、これはすぐにコストがかかります。`10^9`推論スペースの最悪の場合に発生します。 貪欲ヒープがあっても、制約がローカルではなくハウス全体にグローバルであるため、構造は安定しません。 

重要な点は、建設をシミュレーションする必要がないということです。 代わりに、指定された数の住宅があるかどうかを確認するだけで済みます。`H`実現可能です。 種ごとに`i`、貢献できるのはせいぜい`H`ハト（各家に 1 羽）、ただしそれ以下`p_i`。 したがって、その真の貢献は以下によって制限されます。`min(p_i, H)`。 

これらの貢献を合計すると、すべての家で埋めることができる鳩のスロットの総数が得られます。 各家が正確に必要とするため、`k`ハトの場合、実現可能性は 1 つの不等式に帰着します。 

これにより、問題は単調な決定問題に変換されます。`H`住宅は可能ですが、その後は何でも可能です`H' < H`も可能です。 この単調性により、二分探索が可能になります。`H`。 各中間点について、実現可能性を次のように計算します。`O(n)`ソートされた配列またはプレフィックスの合計を使用します。 1 回のソートにより、高速な計算が可能になります。`sum(min(p_i, H))`種を以下に分割することで`H`そして上記のもの。

 ## アルゴリズムのチュートリアル

 ### 1. 入手可能なハトを分類する

 配列をソートします`p`降順ではない順に。 これにより、完全に利用可能な種を迅速に分離することができます (`p_i < H`) で上限が定められているものから`H`。 

### 2. 固定数の住宅に対する実現可能性関数を定義する`H`種ごとに、貢献できるハトの数を計算します。 

もし`p_i < H`、貢献します`p_i`。 

それ以外の場合は貢献します`H`。 

これをすべての種について合計して、使用可能なハトの総数を取得します。 

このステップは、割り当てを構築せずにハウスごとの制限を暗黙的にエンコードするため、重要です。 

### 3. 次のことを確認します。`H`家を埋めることができる

 使用可能な鳩の総数と必要な鳩の数を比較します`H * k`。 使用可能な鳩が少なくともこのくらいの大きさであれば、家に鳩を分配することができます。 

### 4. 可能な限りの二分探索`H`から探す`0`に`sum(p_i) // k`。 各中間点について、上記の関数を使用して実現可能性をテストします。 可能であれば、右に進みます。 それ以外の場合は左に移動します。 

答えは実現可能な最大のものです`H`。 

### なぜ効果があるのか

 重要な不変条件は、固定されたものに対して`H`、式`sum(min(p_i, H))`は、合法的に割り当てることができる鳩スロットの正確な最大数です。`H`家々。 「1 家につき 1 種につき 1 つ」という制限は、`min(p_i, H)`キャップがあり、家は交換可能で対称であるため、それ以上の構造上の制約は存在しません。 したがって、実現可能性は総容量が総需要をカバーするかどうかのみに依存し、単調性によって二分探索の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def feasible(p, k, H):
    total = 0
    for x in p:
        if x >= H:
            total += H
        else:
            total += x
        if total >= H * k:
            return True
    return total >= H * k

def solve():
    n, k = map(int, input().split())
    p = list(map(int, input().split()))
    
    if k > n:
        print(0)
        return

    p.sort()

    lo, hi = 0, sum(p) // k
    ans = 0

    while lo <= hi:
        mid = (lo + hi) // 2
        if feasible(p, k, mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```の`feasible`関数は、どの種も 1 つの家で複数回使用できないという仮定に基づいて、使用可能なハトの総数を計算します。 早期退場時`total >= H * k`不必要な合計を防止する`H`大きいです。 

各ハウスが正確に消費するため、二分探索範囲は安全です。`k`したがって、家の最大数は、ハトの総数を次の値で割った値を超えることはできません。`k`。

 ## 特殊なケース

 いつ`k > n`の場合、十分な数の異なる種でハウスを形成できないため、アルゴリズムはすぐにゼロを返します。 たとえ`p_i`規模が大きい場合、住宅ごとの多様性の制約により建設が妨げられます。 

非常に大きい場合`p_i`、 のような`p = [10^9, 10^9, ..., 10^9]`、二分探索はプッシュします`H`高いが、それぞれの種が寄与するのはわずかであるため、実現可能性は成長を正しく抑制することになる`H`家ごとにカウントされ、過剰カウントを防ぎます。
