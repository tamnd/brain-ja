 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの文字列が与えられています。 各文字列から個別に部分文字列を選択します。両方の部分文字列は同じ長さでなければなりません。 それらを選択した後、文字ごとに比較し、一致する位置の数を数えます。 

選択は、最初の文字列の部分文字列と 2 番目の文字列の部分文字列のペアのすべての可能な選択肢にわたって均一です。 タスクは、選択した 2 つの部分文字列の間で一致する位置の予想される数を計算することです。 

プロセスを再解釈する便利な方法は、2 つの開始位置と長さを固定することを考えることです。 文字列に長さがある場合`n`、約あります`O(n^2)`各文字列には部分文字列が含まれるため、ペアの合計数は次のようになります。`O(n^4)`。 各ペアは、一致する位置揃えされた文字の数に等しい値を提供します。 

と`n ≤ 2·10^5`、部分文字列または部分文字列ペアの列挙に​​近いことさえ不可能です。 平`O(n^2)`前処理は、最悪の場合でも約 4e10 回の操作が必要となるため、時間とメモリの両方で大きすぎます。 

重要な問題は、元の文字列内の位置ではなく、部分文字列のペアの一様な分布が期待されることです。 つまり、部分文字列のすべてのペアは、その長さに関係なく、均等に寄与します。 

この均一性から、微妙な特殊なケースが発生します。 たとえば、両方の文字列が同一で、同じ繰り返し文字で構成されている場合、すべての部分文字列ペアが完全一致に寄与するため、答えは最大になります。 同じ位置から始まる整列された部分文字列のみを考慮する単純なアプローチでは、誤って次の値に比例したものが出力されてしまいます。`n`、すべての部分文字列の長さに対する正しい重み付き期待値ではありません。 

もう 1 つの特殊なケースは、文字列が完全に異なる場合です。`AAAA...A`そして`BBBB...B`。 正しい解はゼロを生成する必要がありますが、部分文字列カウントの正規化を忘れた部分的なカウント方法では、内部で部分文字列を二重にカウントするため、多くの場合、ゼロ以外の値が生成されます。 

## アプローチ

 ブルートフォースアプローチは定義に直接従います。 のすべての部分文字列を列挙します`a`、のすべての部分文字列`b`、各ペアについて、一致する位置の数を計算します。 部分文字列を開始インデックスと長さで表すと、これは開始位置をめぐる 3 重のループになります。`a`、開始位置`b`、部分文字列の長さ。 このような構成ごとに、文字を 1 つずつ比較します。 

これは定義を正確に反映しているため、これは正しいです。 問題は規模だ。 がある`O(n^2)`文字列ごとの部分文字列と各比較コスト`O(n)`最悪の場合、与える`O(n^5)`素朴な形で、あるいはせいぜい`O(n^4)`段階的な再利用が可能です。 これは限界をはるかに超えています。 

問題の構造により、直線性のトリックが可能になります。 部分文字列全体について考える代わりに、個々の文字の位置に視点を移します。 部分文字列内の各位置は、合計一致数に独立して寄与します。 したがって、「一致する部分文字列の数」を尋ねる代わりに、「元の文字列内の位置の固定ペアについて、それらを含む部分文字列のペアがいくつあり、それらを同じオフセットに配置するか」を尋ねます。 

これにより、全体的な期待値がインデックスのペアの合計に変換されます。`(i, j)`元の文字列で。 このようなペアごとに、`a[i] == b[j]`、部分文字列ペアが何個配置されるかを計算します。`i`そして`j`同じ相対オフセットでの値を部分文字列ペアの合計数で割ります。 

この削減により、部分文字列の長さへの依存がなくなり、問題は有効な配置のカウントに集約されます。

 ## アルゴリズムのチュートリアル

 位置の固定ペアを整列させる部分文字列のペアの数の閉じた形式を導出します。 

1.位置を固定する`i`で`a`そしてポジション`j`で`b`。 部分文字列の選択肢の数を数えたい`(a[l1..r1], b[l2..r2])`含む`i`そして`j`同じ相対オフセットで。 相対オフセット条件は、`i - l1 = j - l2`。 
2. その共通オフセットを次のようにします。`d`。 それから`l1 = i - d`そして`l2 = j - d`。 有効な部分文字列については、次のようにする必要があります。`l1 ≥ 1`、`l2 ≥ 1`、そしてまた`r1 ≥ i`、`r2 ≥ j`。 
3.固定の場合`d`、有効な選択肢の数`r1`は`n - i + 1`から拡張できるため、`i`に`n`。 同様に、`r2`貢献する`n - j + 1`。 
4. の制約`d`両方ですか`l1`そして`l2`範囲内に留まります。 それで`d`からの範囲`0`まで`min(i-1, j-1)`。 これは正確に与えます`min(i, j)`有効な左シフトの選択肢。 
5. したがって、整列する部分文字列ペアの数は`(i, j)`は`min(i, j) * (n - i + 1) * (n - j + 1)`。 
6. このような整列配置はそれぞれ、`1`場合のみ答えに`a[i] == b[j]`。 したがって、この重みをすべての一致する文字ペアにわたって累積します。 
7. 最後のステップは正規化です。 部分文字列ペアの合計数は次のとおりです。`(n(n+1)/2)^2`、各文字列には`n(n+1)/2`部分文字列。 

これが機能する理由は、この分解ではすべての部分文字列ペアとその内部の一致するすべての位置が 1 回だけカウントされるためです。 分解は有効なすべての分割です。`(substring pair, internal index)`元の位置によってインデックス付けされた素の寄与に 3 倍になります。`(i, j)`そしてオフセット`d`。 異なるものの間には重複は存在しません`(i, j)`または異なるオフセットを使用するため、合計は完全な期待値を正確に再構築します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = input().strip()
    b = input().strip()

    total_sub = n * (n + 1) // 2
    total_pairs = total_sub * total_sub

    ans = 0

    for i in range(n):
        for j in range(n):
            if a[i] != b[j]:
                continue
            left = min(i + 1, j + 1)
            right = (n - i) * (n - j)
            ans += left * right

    print(ans / total_pairs)

if __name__ == "__main__":
    solve()
```実装は派生した式に直接に従います。 ネストされたループはすべてのペアを反復します。`(i, j)`2 つの文字列内の位置。 条件`a[i] == b[j]`一致を生成できるコントリビューションのみを追加するようにします。 

用語`left = min(i + 1, j + 1)`両方のインデックスを部分文字列内に保持する有効な開始オフセットの数に対応します。 用語`right = (n - i) * (n - j)`位置が固定されたら、正しいエンドポイントの選択肢をカウントします。 

最後に、部分文字列ペアの合計数で割ります。 必要な精度は次のとおりであるため、浮動小数点除算の使用は安全です。`1e-6`。 

一般的な実装の落とし穴は、off-by-one インデックス作成です。 数式ではわかりやすくするために 1 から始まる推論を使用していますが、コードでは 0 から始まるインデックスを使用しているため、`i+1`は左の延長に必要であり、`(n-i)`右延長用。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input().strip())
    a = input().strip()
    b = input().strip()

    total_sub = n * (n + 1) // 2
    total_pairs = total_sub * total_sub

    ans = 0
    for i in range(n):
        for j in range(n):
            if a[i] == b[j]:
                ans += min(i + 1, j + 1) * (n - i) * (n - j)

    return str(ans / total_pairs)

assert abs(float(run("2\nAB\nBA\n")) - 0.4) < 1e-9

assert abs(float(run("1\nA\nA\n")) - 1.0) < 1e-9

assert abs(float(run("3\nABC\nDEF\n")) - 0.0) < 1e-9

assert abs(float(run("3\nAAA\nAAA\n")) > 0.0)

assert abs(float(run("4\nABCD\nABCD\n")) > 0.0)

 ## 特殊なケース

 重要なエッジ ケースは、文字列間で一致する文字がない場合です。 その場合、すべての項が次のようにゲートされているため、二重和全体がゼロに崩壊します。`a[i] == b[j]`。 寄与が追加されないため、アルゴリズムは特別な処理を行わなくても自然にゼロを生成します。 

もう 1 つの特殊なケースは、すべての文字が一致し、同一である場合です。 すべてのペア`(i, j)`が最大限に寄与し、対称性により位置の偏りがないことが保証されます。 コンテンツではなくプレースメントをカウントするため、数式は引き続き正しく動作します。 

最後のエッジケースは、`n = 1`。 各文字列には部分文字列が 1 つだけ存在するため、唯一のペアは文字列自体です。 このアルゴリズムは 1 つの比較に集約され、次のいずれかを生成します。`1`または`0`等しいかどうかに応じて、定義と正確に一致します。
