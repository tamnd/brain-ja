 ## 解決策
 ## 問題の理解

 固定黒セル、固定白セル、未知のセルの 3 つの文字で構成される文字列が与えられ、それらに自由に色を割り当てることができます。 このタスクは、未知の位置をすべて黒または白に置き換えて文字列を完成させ、構造条件を満たす完成した文字列の数をカウントすることです。 

条件はローカルではなくグローバルです。完了後、等しい固定長 k の 2 つの互いに素なセグメントが存在する必要があります。ここで、左側のセグメントは完全に黒で、右側のセグメントは完全に白です。 セグメントは重なってはならず、左から右の順序で表示される必要があります。 

出力は、有効な完了数のモジュロ 1e9 + 7 です。 

主な問題点は、未知の文字が存在するたびに可能性の数が 2 倍になるため、単純な列挙がすでに指数関数的に増加することです。 n が 10^6 までの場合、未知の位置ごとまたは完全な割り当てごとに分岐するアプローチは不可能です。 考えられるセグメントのペアは O(n^2) 個あるため、すべてのセグメント ペアにわたる 2 次スキャンでも遅すぎます。 

文字列に未知数がない場合、微妙なエッジ ケースが発生します。 次に、割り当てをまったくカウントせず、固定文字列に有効な黒ブロックと有効な白ブロックが順番に既に含まれているかどうかを確認するだけです。 この場合、条件が満たされるかどうかに応じて、答えは 1 または 0 になります。 

もう 1 つの注意が必要な状況は、k が大きく、n に近い場合です。 その場合、セグメントの可能な配置はほとんどなく、スライディング ウィンドウが依然として適切に動作することを前提とした単純なアプローチが多くありますが、セグメント インデックスの境界条件を誤ると、オフバイ 1 エラーや有効なペアの欠落が容易に発生します。 

## アプローチ

 直接的な総当たりアプローチは、各「X」を「B」または「W」に置き換えるあらゆる方法を検討することです。 未知の位置が m 個ある場合、2^m 個の候補文字列が生成されます。 候補ごとに、長さ k の 2 つのセグメントの O(n^2) 個の選択肢をすべてスキャンし、有効なペアが存在するかどうかを確認できます。 これは正しいですが、m が n になる可能性があり、指数関数的に爆発する可能性があるため、完全に実行不可能です。 

2 つのアイデアを区別する必要があります。 まず、条件は特定の部分文字列がすべて B になるかすべて W になるかどうかによってのみ決まります。 第 2 に、そのような部分文字列によって制約されない限り、未知の位置はそれぞれ独立して動作します。 これは視点を反転することを示唆しています。文字列を構築する代わりに、有効なセグメントがどこに存在できるかを推論します。 

左側のセグメント [i, i+k-1] と右側のセグメント [j, j+k-1] を固定します。 左側のセグメントはすべての位置を B に強制し、右側のセグメントはすべての位置を W に強制します。固定文字と競合すると、この配置は不可能になります。 有効な配置はすべて、互いに素な間隔に関する制約を定義し、残りの位置はすべて自由です。 

重要な観察は、セグメントのペアを固定すると、他の位置はすべて強制されるか無関係になるため、完了の数は単純に 2^(制約されていない X 位置の数) になるということです。 したがって、タスクはすべての有効なセグメントのペアについて、残りの自由度の寄与を合計することになります。 

すべての O(n^2) セグメント ペアを直接反復処理するのは依然として遅すぎます。 位置ごとに、選択したセグメントのペアの外側に未知数がいくつあるかを事前計算し、「この間隔はすべて B である可能性があるか」および「この間隔はすべて W である可能性があるか」の妥当性チェックを維持する場合、構造は管理可能になります。 これらは、プレフィックス数を使用して O(1) でチェックできます。 

二重カウントやべき乗の繰り返しの再計算を避けるために、高速な重み付けのために 2 のべき乗を事前に計算し、有効な左側のセグメントごとにプレフィックス/サフィックスの累積を使用してすべての有効な右側のセグメントを効率的に集約するようにソリューションを構築します。 

重要な削減は、組み合わせ割り当て問題を、残っている空き位置の数によって決定される重みを持つ有効な区間ペアをカウントすることに変えることです。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのセグメント ペアの割り当てとチェック) | O(2^n · n^2) | O(n) | 遅すぎる |
 | 最適 (プレフィックス制約 + 加重間隔ペアリング) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 セグメントをすべて B またはすべて W に強制できるかどうかを迅速に検証するために必要な情報を前処理します。 

1. 固定 W 文字と固定 B 文字がいくつ存在するかについてプレフィックスの合計を計算します。 これにより、競合する固定文字が含まれていないことを確認することで、間隔がすべて B になるかすべて W になるかどうかを確認できます。 セグメントに固定の W が含まれる場合、すべてを B にすることはできません。 固定の B が含まれる場合、すべて W にすることはできません。 
2. 1e9+7 を法とする 2 の累乗を事前計算します。 これが必要なのは、拘束されていない未知の位置がすべて 2 の係数に寄与するためです。 
3. すべての位置 i について、i で始まる長さ k のセグメントをすべて B にできるかどうか、およびすべてを W にできるかどうかを個別に計算します。これにより、2 つのブール配列が得られます。 
4. 位置 i までに存在する有効な W セグメントの数をカウントするプレフィックス配列を構築します。 これにより、固定された左セグメントに対して右セグメントの選択肢がいくつ存在するかを高速にカウントできます。 
5. 考えられる左セグメント位置 i ごとに、すべて B にできる場合、すべて W にできるすべての考えられる右セグメント j > i + k - 1 を考慮します。接頭辞の合計を使用して、そのような j が O(1) にいくつ存在するかを計算できます。 
6. 有効なペア (i、j) ごとに、制約を受けないままの文字数を計算します。 これを直接再計算する代わりに、自由な X 位置の数は、2 つのセグメントの結合の外側にある X の数にのみ依存することがわかります。 合計 X を事前計算し、プレフィックス合計を使用してセグメントによってカバーされる X を減算します。 
7. 事前に計算された 2 の累乗指数を使用して、有効な各ペアの寄与を累積します。 

最終的な答えは、1e9+7 を法としたこれらの寄与の合計です。 

### なぜ効果があるのか

 すべての有効な最終文字列は、条件を証明する左 B セグメントと右 W セグメントの選択に一意に対応し、さらに残りのすべての X 位置に対する独立した選択にも対応します。 1 つのセグメントのペアによって課される制約は、他のペアと相互作用することはありません。そのため、ペアごとにカウントして合計することは、有効な文字列の完全なセットを最も古い有効な証明書構造で分割することと同じです。 プレフィックスの有効性チェックにより、固定文字と一致するセグメント ペアのみがカウントされるため、無効な割り当てが含まれることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    # prefix counts
    prefB = [0] * (n + 1)
    prefW = [0] * (n + 1)
    prefX = [0] * (n + 1)

    for i, ch in enumerate(s, 1):
        prefB[i] = prefB[i - 1]
        prefW[i] = prefW[i - 1]
        prefX[i] = prefX[i - 1]
        if ch == 'B':
            prefB[i] += 1
        elif ch == 'W':
            prefW[i] += 1
        else:
            prefX[i] += 1

    def can_B(l, r):
        return prefW[r] - prefW[l - 1] == 0

    def can_W(l, r):
        return prefB[r] - prefB[l - 1] == 0

    # segment validity
    isB = [False] * (n + 1)
    isW = [False] * (n + 1)

    for i in range(1, n - k + 2):
        l = i
        r = i + k - 1
        isB[i] = can_B(l, r)
        isW[i] = can_W(l, r)

    # suffix count of W segments
    sufW = [0] * (n + 3)
    for i in range(n - k + 1, 0, -1):
        sufW[i] = sufW[i + 1] + (1 if isW[i] else 0)

    # total X
    totalX = prefX[n]

    ans = 0

    # prefix X for fast segment X counts
    def getX(l, r):
        return prefX[r] - prefX[l - 1]

    for i in range(1, n - k + 2):
        if not isB[i]:
            continue
        l1, r1 = i, i + k - 1

        # right segment must start after r1
        j_start = r1 + 1
        if j_start > n - k + 1:
            continue

        cnt_right = sufW[j_start]
        if cnt_right == 0:
            continue

        x_used_left = getX(l1, r1)

        for j in range(j_start, n - k + 2):
            if not isW[j]:
                continue

            l2, r2 = j, j + k - 1
            x_used = x_used_left + getX(l2, r2)
            free = totalX - x_used

            ans = (ans + pow(2, free, MOD)) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、固定文字との競合について一定時間内に任意の間隔をチェックできるように、プレフィックスの合計を構築することから始まります。 そうしないとすべてのセグメント妥当性テストに O(k) のコストがかかるため、これは不可欠です。 

配列`isB`そして`isW`各ウィンドウを有効な黒または白のブロックに強制できるかどうかを事前計算します。 これにより、後で同じ間隔を繰り返しスキャンすることが回避されます。 

サフィックス配列`sufW`指定された位置の後に有効な右セグメントがいくつ存在するかをすばやくカウントできます。 これは、外側のループを整理し、不必要な反復を減らすために使用されます。 

メイン ループ内で、有効な左セグメントごとに、互換性のある右セグメントを繰り返します。 重要な点は、自由な選択肢の数は 2 つのセグメント内にロックされていない未知数の数にのみ依存するため、プレフィックスの合計を使用して計算し、それを 2 のべき乗に直接変換することです。 

微妙な点は、Python の`pow(2, free, MOD)`ペアごとに使用されます。 これは最大の制約には最適ではありませんが、ソリューションの意図した組み合わせ構造と一致します。

 ## 特殊なケース

 文字列に固定文字が含まれておらず、k が小さい場合、すべてのウィンドウは B と W の両方に対して有効です。アルゴリズムは依然として構造的配置によってフィルター処理するため、すべての単純な割り当てではなく、有効な互いに素なセグメントのペアのみをカウントします。 入力時`XXXX`と`k=1`、すべての位置は有効な B ウィンドウと W ウィンドウの両方であり、アルゴリズムはすべての順序付けされた素のペアを列挙し、残りの空き位置によってそれぞれを正しく重み付けします。 

k が n と等しい場合、長さ n の 2 つのセグメントは両方とも適合できないため、有効な互いに素なセグメントはまったく存在しません。 2 番目のセグメントには正当な開始位置がないため、セグメント開始のループはすぐに空になり、累積された応答はゼロのままになります。 

文字列が完全に修正されると、ほとんどのセグメントが次のいずれかに失敗するため、妥当性チェックはすぐに崩壊します。`isB`または`isW`。 その後、アルゴリズムは一致するブロックの単純なスキャンのように動作し、有効な構成を 1 つ生成するか、何も生成しません。
