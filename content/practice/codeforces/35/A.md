 ## 解決策
 ## 問題の理解

 3 つのカップが一列に配置されており、そのうちの 1 つの下からボールが始まります。 出演者はちょうど 3 回のスワップを実行します。 スワップごとに 2 つのカップの位置が入れ替わります。 すべてのスワップが終了したら、どのカップにボールが入っているかを判断する必要があります。 

入力では、最初に開始カップ インデックス (1 から 3) が与えられます。次に 3 行が続き、それぞれにシャッフル中に交換されたカップを表す 2 つの整数が含まれます。 

重要な詳細は、ボールが現在のカップがスワップに参加している場合にのみ移動するということです。 ボールがカップ 2 の下にあり、カップ 1 とカップ 3 を交換すると、カップは決して動かないので、ボールはカップ 2 の下に留まります。 

制約はわずかです。 常にちょうど 3 つのカップとちょうど 3 つのスワップがあります。 想像できる限り最も遅い実装であっても、即座に実行されます。 これは、論理的な間違いを犯さずにプロセスを正しくシミュレートすることだけが問題であることを意味します。 

バグの主な原因は、スワップの意味を誤解していることです。 

次の入力を考えてみましょう。```
1
2 3
2 3
2 3
```ボールはカップ 1 の下から始まります。どのスワップもカップ 1 に関係しないため、答えは変わりません。```
1
```ステップごとに盲目的に位置を変更する不注意な実装では、ボールが誤って移動する可能性があります。 

同じスワップが複数回出現する場合、別の微妙なケースが発生します。```
2
1 2
1 2
1 2
```最初のスワップの後、ボールはカップ 2 からカップ 1 に移動します。 

2回目以降はカップ2に戻ります。 

3 回目以降はカップ 1 に戻ります。 

正しい出力は次のとおりです。```
1
```カップが交換されたかどうかだけを記憶するバグのあるソリューションでは、交換は順番に処理する必要があるため、ここでは失敗します。 

もう 1 つの簡単な間違いは、スワップが対称であることを忘れていることです。 ボールがカップ 3 の下にあり、シャッフルが行われた場合`1 3`、ボールはカップ 1 に移動する必要があります。```
3
1 3
1 2
2 3
```正しいシミュレーションでは次の結果が得られます。```
2
```現在の位置がペアの最初の番号と等しいかどうかのみをチェックする実装の場合、現在のカップが 2 番目の番号と等しいスワップを見逃してしまいます。 

## アプローチ

 最も直接的なアイデアは、説明どおりにゲームをシミュレートすることです。 ボールが入っている現在のカップを保存します。 シャッフルごとに、交換された 2 つのカップを検査します。 

ボールが最初のカップの下にある場合は、2 番目のカップに移動します。 

ボールが 2 番目のカップの下にある場合は、1 番目のカップに移動します。 

そうでなければ何も変わりません。 

問題のサイズが一定であるため、この総当りシミュレーションはすでに完全に許容可能です。 正確に 3 つのスワップを処理するため、合計の操作数はごくわずかです。 

別の可能な総当たり解釈では、配列内の 3 つのカップすべてを明示的に追跡し、各ステップでその内容を物理的に交換します。 これも機能しますが、必要以上に多くの情報が保存されます。 私たちが気にするのはただ 1 つだけ、それはボールの現在の位置です。 

重要な観察は、ゲームの状態全体が 1 つの整数で表現できるということです。 ボールが含まれるカップは 1 つだけなので、空のカップを個別にモデル化する必要はありません。 シャッフルするたびに、この整数が変更されるか、変更されないままになります。 

これにより、問題は一定のメモリと一定の時間を使用するコンパクトな状態遷移プロセスに縮小されます。

 ## アルゴリズムのチュートリアル

 1. ボールが開始される最初のカップ インデックスを読み取ります。 
2. このインデックスを変数に格納します。`pos`。 この変数は常にボールの現在位置を表します。 
3. 3 つのスワップを 1 つずつ処理します。 
4. 各スワップについて`(a, b)`、ボールがこれらのカップのいずれかの下にあるかどうかを確認します。 

もし`pos == a`、 セット`pos = b`ボールはカップと一緒に動くので`a`。 
5. それ以外の場合、`pos == b`、 セット`pos = a`。 

スワップは両方向に機能するため、ボールは次の方向から移動します。`b`に`a`この場合。 
6. もし`pos`どちらとも一致しない`a`または`b`、何もしません。 

シャッフルされたカップにはボールは入っていませんでした。 
7. 3 回すべての交換が完了したら、印刷します。`pos`。 

### なぜ効果があるのか

 不変条件は単純です。シャッフルが処理されるたびに、`pos`現在ボールが入っている実際のカップに相当します。 

最初はこれが真実です。なぜなら、`pos`入力から設定されます。 シャッフル中に、ちょうど 2 つのカップが位置を交換します。 ボールがどちらかのカップの下にある場合は、もう一方のカップに移動します。 そうでない場合、その位置は変わりません。 更新ルールはこれらの物理的な動きを正確に反映するため、各ステップの後でも不変条件は true のままです。 3回目のシャッフル後、`pos`が最終的な答えです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

pos = int(input())

for _ in range(3):
    a, b = map(int, input().split())

    if pos == a:
        pos = b
    elif pos == b:
        pos = a

print(pos)
```プログラムはボールの現在位置のみを保存します。 これは、空のカップを追跡する必要がないという観察と一致します。 

この問題では 3 回のシャッフルが保証されているため、ループはちょうど 3 回実行されます。 スワップごとに、現在のボールの位置をスワップされた両方のカップと比較します。 

条件の順序は多少重要です。 ボールが合ったら`a`、すぐに次の場所に移動します`b`。 使用する`elif`同じ繰り返しで更新された値を誤って再確認することを防ぎます。 

配列のインデックス作成は必要ないため、off-by-one のリスクはありません。 カップ番号は入力で指定されたとおりに直接使用されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    pos = int(input())

    for _ in range(3):
        a, b = map(int, input().split())

        if pos == a:
            pos = b
        elif pos == b:
            pos = a

    print(pos)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("1\n1 2\n2 1\n2 1\n") == "2\n", "sample 1"

# minimum movement, ball never touched
assert run("1\n2 3\n2 3\n2 3\n") == "1\n", "ball never moves"

# repeated swaps
assert run("2\n1 2\n1 2\n1 2\n") == "1\n", "odd number of repeated swaps"

# ball starts at highest index
assert run("3\n1 3\n1 2\n2 3\n") == "1\n", "swap symmetry"

# every swap affects the ball
assert run("2\n2 3\n1 3\n1 2\n") == "2\n", "continuous movement"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 2 3 / 2 3 / 2 3`|`1`| ボールは交換されない場合は変化しません。 
|`2 / 1 2 / 1 2 / 1 2`|`1`| 繰り返されるスワップは順番に処理する必要があります。 
|`3 / 1 3 / 1 2 / 2 3`|`1`| スワップは対称的に機能します。 
|`2 / 2 3 / 1 3 / 1 2`|`2`| ボールは一歩ごとに動きます |

 ## 特殊なケース

 ボールがスワップにまったく関与しない場合を考えてみましょう。```
1
2 3
2 3
2 3
```アルゴリズムは次から始まります`pos = 1`。 

シャッフルごとに、どちらのエンドポイントも等しくない`1`なので、値は決して変わりません。 

状態トレース:```
1 -> 1 -> 1 -> 1
```最終的な答えは次のように正しく出力されます。`1`。 

次に、同じペアの繰り返しのスワップを考えてみましょう。```
2
1 2
1 2
1 2
```実行は次のように進行します。 

最初の交換:`2 -> 1`2回目の交換:`1 -> 2`3回目の交換:`2 -> 1`最終結果:```
1
```これは、アルゴリズムが順序を尊重し、各シャッフルを独立して処理することを確認します。 

最後に、現在位置がスワップの 2 番目の値と一致する場合を考えてみましょう。```
3
1 3
1 2
2 3
```最初のシャッフルは、`(1, 3)`。 以来`pos == 3`、アルゴリズムは 2 番目の条件に入り、更新します。`pos = 1`。 

完全なトレースは次のようになります。```
3 -> 1 -> 1 -> 1
```最終的な答えは、`1`。 これにより、スワップが両方向で正しく処理されることが検証されます。
