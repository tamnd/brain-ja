 ## 解決策
 ## 問題の理解

 私たちは、動物が 1 日あたり 1 匹到着する農場をシミュレートするように求められます。`n`日々。 各動物には、到着した日から始まる毎日の餌の必要量が固定されています。 農園の始まりは、`X`たくさんの食べ物。 私たちは毎日、到着する動物を受け入れるか拒否するかを選択できますが、動物が決して飢えないようにしなければなりません。 目的は、一日の終わりまでに農場の動物の総数を最大化することです`n`。 

具体的には、1日あたり`i`、 動物`i`欲しい`c[i]`一日あたり一日から大量の食べ物`i`今日`n`。 動物を受け入れる場合`i`、消費します`(n - i + 1) * c[i]`累計でトン。 課題は、累積消費量の合計が以下を超えないように動物のサブセットを選択することです。`X`サブセットをできるだけ大きく保ちながら。 

制約が私たちに与えるのは、`1 ≤ n ≤ 100`そして`1 ≤ X ≤ 10000`。 動物のすべてのサブセットをチェックする素朴な総当たりアプローチには、`2^n`操作、つまり大まかに言うと`1.27e30`最悪の場合。 これはまったく実現不可能です。 動物 1 匹あたりの餌の必要量は最大 300、餌の合計は最大 10,000 に達する可能性があるため、正確な累積合計に依存するアルゴリズムは最大 10,000 の値を処理する必要があります。`3e4`これは、動的プログラミングや貪欲なアプローチには十分小さいです。 

エッジケースは、動物が最初または最後に大量の餌を必要とする場合に発生します。 たとえば、最初の動物が次のことを望んでいる場合、`X`、直ちに拒否しなければなりません。 もう 1 つの微妙なケースは、初期の小型動物と非常に大型の後期動物を組み合わせると、合計の餌の制限を超える可能性がある場合です。優先順位を付けずに動物を常に順番に受け入れる単純な貪欲な場合は、失敗する可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、動物のすべてのサブセットを列挙し、各サブセットの合計累積消費量を計算し、最大の有効なサブセットを選択します。 それは正しいですが、実用的ではありません。`n`は 100 にもなり、サブセット空間が天文学的に大きくなります。 

より良いアプローチは、毎日の累積消費量が動物の到着時間に比例するという事実を利用するものです。 初期の動物は後期の動物よりも総餌量が多いため、消費量の多い動物よりも消費量の少ない動物を早期に受け入れる方が良いです。 これは古典的なリソース割り当ての問題です。 優先キューまたはソートされたリストで毎日の累積餌消費量を追跡していれば、動物を貪欲に受け入れることができ、餌の総量が超過した場合は、`X`、これまでで最大の消費動物を削除します。 これにより、あらゆる段階で、飼料制限内に収まりながら動物の最大数を維持することが保証されます。 

重要な洞察は、到着順序は各動物の累積餌要求量を計算する場合にのみ重要であるということです。`(n - i + 1) * c[i]`。 それが分かれば、累積要件に基づいて動物を分類または管理し、最大の寄与者を貪欲に除去してできるだけ多くの動物を受け入れることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | ヒープに貪欲 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各動物の総餌必要量を計算します。 当日到着する動物に関しては`i`毎日の必要量で`c[i]`、その日までに消費する食料の合計`n`は`(n - i + 1) * c[i]`。 参照用に、これらの値を日インデックスと一緒にリストに保存します。 
2. 受け入れられた動物の合計要件を保存するために最小ヒープを初期化します。 また、変数を初期化します`current_sum`受け入れられたすべての動物の累積餌の合計を追跡するため。 
3. 到着順に動物を繰り返し処理します。 動物ごとに、その合計要件をヒープに追加し、`current_sum`。 
4. もし`current_sum`を超える`X`、合計が以下になるまで、最大の要件を持つ動物をヒープから (最大ヒープを維持することにより) 繰り返し削除します。`X`。 このステップでは、最も高価な動物を最初に廃棄することで動物の数を最大化します。 
5. すべての動物を処理した後のヒープのサイズは、農場で飼育できる動物の最大数になります。 

それが機能する理由: あらゆる段階で、私たちは新しい動物を受け入れ、必要に応じて最大の消費者を追い出します。 これにより、受け入れられたすべての動物の合計が決して超えないという不変条件が維持されます。`X`。 最大の寄与者を常に除去することで、総必要量が少なくてもより多くの動物を受け入れる余地を残し、それが直接的に数を最大化します。 体系的に累積コストを最小化するため、これ以外の一連の受諾/拒否の決定では、より多くの動物を生み出すことはできません。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

n, X = map(int, input().split())
c = list(map(int, input().split()))

# Step 1: compute total food requirement for each animal
requirements = [(c[i] * (n - i), i) for i in range(n)]  # using (total_food, index)

current_sum = 0
max_heap = []

for total_food, _ in requirements:
    heapq.heappush(max_heap, -total_food)  # push negative for max-heap behavior
    current_sum += total_food
    if current_sum > X:
        current_sum += heapq.heappop(max_heap)  # remove largest consumer

print(len(max_heap))
```このソリューションはまず、到着から終了までの各動物の総餌使用量を計算します。 Python の heapq はデフォルトで min-heap であるため、負の数を使用して max-heap を維持します。 新しい動物ごとに、それをヒープに追加し、累積合計を確認します。 超えた場合`X`、食料を解放するために最大の消費者を削除します。 最終的に、ヒープ サイズは動物の最大数を反映します。 

微妙なポイントには計算が含まれます`(n - i) * c[i]`1 つずつ異なるエラーを避けるために慎重に行ってください。 負の値をヒープにプッシュすると、ヒープが最大ヒープに変換されます。 ヒープからの更新の削除`current_sum`ポップされた負の数を追加することで正しくなります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各ヒープ操作はログ n であり、動物ごとに 1 回実行されます。 |
 | スペース | O(n) | 最大ヒープは最大で n 個の動物を保存します。 |

 と`n`≤ 100 の場合、log n は自明なので、この解決策は高速になります。 64MB の制限に比べれば、メモリの使用量はごくわずかです。 

## テストケース```python
def run(inp: str) -> str:
    import sys, io
    sys.stdin = io.StringIO(inp)
    import heapq
    n, X = map(int, input().split())
    c = list(map(int, input().split()))
    requirements = [(c[i] * (n - i), i) for i in range(n)]
    current_sum = 0
    max_heap = []
    for total_food, _ in requirements:
        heapq.heappush(max_heap, -total_food)
        current_sum += total_food
        if current_sum > X:
            current_sum += heapq.heappop(max_heap)
    return str(len(max_heap))

# provided samples
assert run("3 4\n1 1 1\n") == "2", "sample 1"

# custom cases
assert run("1 5\n6\n") == "0", "single animal too big"
assert run("5 100\n10 10 10 10 10\n") == "5", "all fit"
assert run("3 5\n2 2 2\n") == "2", "boundary fit"
assert run("4 10\n5 4 3 2\n") == "2", "removal of largest"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 5\n6 | 0 | 1 匹の動物が X を超える |
