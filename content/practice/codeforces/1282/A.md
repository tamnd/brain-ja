 ## 解決策
 ## 問題の理解

 位置から直線セグメントに沿って移動する人が与えられます`a`位置を決める`b`一定速度で 1 分あたり 1 ユニット。 独立した位置にネットワーク基地局があります`c`距離内のすべてをカバーします`r`。 人が移動している間、常にカバー範囲内にいるか、カバー外にいるかのどちらかになります。 タスクは、旅行全体で対象地域外で合計どのくらいの時間を費やすかを計算することです。 

速度が 1 なので、時間は移動距離に等しくなります。 したがって、問題は、どのセグメントがどのくらいの量を占めるかを測定することに帰着します。`a`に`b`対象範囲外にあります。 

重要な幾何学的観察は、数直線上のカバー領域自体が、次の点を中心とするセグメントであるということです。`c`、延長`r`両方向のユニット。 したがって、カバーされる領域は間隔です`[c - r, c + r]`。 動きもインターバルですが、左右によって左右に動くこともあります。`a < b`または`a > b`。 

この制約により、最大 10^8 の大きさの座標を持つ最大 1000 個のテスト ケースが許可されます。 これは、距離を超えたスキャンやシミュレーションを伴うものは不可能であるため、テスト ソリューションごとに O(1) が必要であることを直ちに示唆しています。 

素朴な解釈では、動きを分ごと、またはユニットごとにシミュレートすることになりますが、座標の範囲により、これは実行不可能になります。 1 つのテスト ケースでも、最大 2⋅10^8 ステップに及ぶ可能性があります。 

通常、誤ったアプローチを破るエッジ ケースには、方向の反転が含まれます (`a > b`)、完全なカバレッジ (内側のセグメント全体)`[c-r, c+r]`）、重複はまったくありません（セグメントはカバレッジから完全に切り離されています）。 もう 1 つの微妙なケースは、セグメントがカバレッジ間隔と部分的にのみ重複する場合であり、交差エンドポイントの慎重な処理が必要になります。 

たとえば、次の場合`a = 1, b = 10, c = 7, r = 1`、適用範囲は`[6, 8]`。 走行セグメントは次の範囲内でのみ重複します。`[6, 8]`、したがって、覆われていない部分は`[1, 6]`そして`[8, 10]`ここでの間違いは、オーバーラップを適切にクランプすることを忘れているか、方向は重要ではないと仮定していることです。 

## アプローチ

 この強引なアイデアは、Polycarp の動きを単位解像度でシミュレートし、各整数点または各小さなステップが内部にあるかどうかをチェックすることです。`[c - r, c + r]`。 カバレッジはポジションごとにテストするのが簡単であるため、これは概念的に機能します。 ただし、パスの長さはテストごとに最大 2⋅10^8 になる可能性があり、テストが最大 1000 回になると、これは完全に不可能になります。 

問題の構造により、シミュレーションの必要がなくなります。 移動も取材も直線上の連続した間隔です。 時間の経過とともに位置を追跡する代わりに、移動セグメントのどの程度がカバレッジ セグメントと交差するかを計算するだけで済みます。 これを認識すると、問題は純粋な区間交差タスクになります。 

移動間隔間の重複を計算します。`[min(a,b), max(a,b)]`そしてカバレッジ間隔`[c-r, c+r]`。 この重複の長さが取材に費やされる時間となります。 総移動距離からそれを引くと、カバー範囲外で費やした時間が求められます。

 ## アルゴリズムのチュートリアル

 すべてを間隔という観点から再定式化します。 

1. 動きを正規化されたセグメントに変換する`[l1, r1]`どこ`l1 = min(a, b)`そして`r1 = max(a, b)`。 これにより方向が完全に削除されるため、長さのみを扱います。 
2. カバレッジを次のように変換します。`[l2, r2]`どこ`l2 = c - r`そして`r2 = c + r`。 これは、信号が利用可能なすべてのポイントを表します。 
3. 次のようにして、これら 2 つのセグメントの交差を計算します。`left = max(l1, l2)`そして`right = min(r1, r2)`。 
4. もし`right > left`、交差点の長さは正であるため、カバレッジ時間は次のようになります。`right - left`。 もし`right <= left`、重複はなく、カバレッジ時間はゼロです。 
5. 合計移動時間を次のように計算します。`r1 - l1`、次にカバレッジ時間を減算して、非カバー時間を取得します。 

これが機能する理由は、速度 1 での移動が時間を幾何学的長さに変換するためです。 問題は、ある区間が他の区間の外側にどれだけあるのかを測定することに帰着します。これは、正確に全長から交点の長さを差し引いたものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, c, r = map(int, input().split())

    l1, r1 = min(a, b), max(a, b)
    l2, r2 = c - r, c + r

    left = max(l1, l2)
    right = min(r1, r2)

    overlap = max(0, right - left)
    total = r1 - l1

    print(total - overlap)
```このコードは、問題の間隔ビューを直接実装します。 最初のステップでは方向を正規化することで、特殊なケースを回避します。`a > b`。 2 番目のステップでは、カバレッジ間隔を明示的に構築します。 

交差ロジックは、重複するセグメントの標準式に依存します。 の`max(0, right - left)`重複しない間隔がゼロに寄与することを保証し、負の長さを回避します。 

最後に、合計から重複を差し引くと、カバレッジ外で費やされた時間が正確に得られます。

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline
    t = int(input())
    for _ in range(t):
        a, b, c, r = map(int, input().split())
        l1, r1 = min(a, b), max(a, b)
        l2, r2 = c - r, c + r
        overlap = max(0, min(r1, r2) - max(l1, l2))
        print((r1 - l1) - overlap)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out.strip()

 ## 特殊なケース

 いつ`a == b`、移動間隔は単一点に崩壊します。 この場合`r1 - l1`はゼロなので、カバレッジに関係なく、答えは自動的にゼロになります。 入力用`a = 5, b = 5, c = 0, r = 0`、間隔ビューは次のようになります。`[5,5]`そして`[0,0]`、オーバーラップもゼロ、全長もゼロとなり、正しい結果と一致します。 

全く重なりがない場合など`a = 0, b = 10, c = 100, r = 1`、交差の計算により次の結果が得られます。`min(r1,r2) < max(l1,l2)`なので、重なりはゼロになります。 答えはセグメント全体の長さの 10 になります。 

カバレッジに移動セグメントが完全に含まれている場合（次のような場合）`a = 2, b = 5, c = 3, r = 10`の場合、交差部分はセグメント全体に等しいため、オーバーラップは全長に等しく、結果はゼロになります。
