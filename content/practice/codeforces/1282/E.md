 ## 解決策
 ## 問題の理解

 かつて凸多角形の三角形分割を形成していた三角形のコレクションが与えられました。$n$頂点。 各三角形は、三角形分割記録以外に何も残らないまで、凸多角形から境界三角形を繰り返し削除するプロセス中に作成された 1 つのカットに対応します。 

各三角形は 3 つの頂点ラベルによってのみ記述されますが、ラベル自体は任意です。 多角形の周囲の頂点の循環順序がわかりません。また、三角形が削除された順序もわかりません。 タスクは、すべての頂点の循環順序付けと、実際の三角形分割プロセスと一致する三角形の有効な削除シーケンスの両方を再構築することです。 

重要な構造的事実は、三角形が任意のものではないということです。 これらは凸多角形の三角形分割を形成し、各ステップでその三角形分割の二重構造内の葉の三角形に対応する三角形が削除されます。 つまり、すべての段階で、現在の境界に沿って 3 つの頂点が連続するトリプルを形成する三角形が存在します。 

制約は非常に厳しいので、テスト ケースごとに、どのような解も線形または線形演算に近くなければなりません。 の合計額$n$すべてのテストケース全体で最大でも$10^5$、したがって、それ以上のアプローチは、$O(n \log n)$テストごとに生き残ることはできません。 構造を段階的に再構築し、隣接ブックキーピングを使用するソリューションが必要です。 

微妙な困難は、方向と順序があいまいなことから生じます。 多角形は時計回りまたは反時計回りに移動でき、どの回転も有効です。 さらに、三角形の削除順序は一意ではありません。 境界の一貫性を強制せずに任意の削除をシミュレートしようとする単純な試みは、現在ポリゴン境界上に「露出」していない三角形を削除しようとするため、失敗します。 

典型的な失敗例は、以前に選択した三角形とエッジを共有する三角形を貪欲に選択しようとしたときに発生します。 これでは内三角形を選択するのが早すぎる可能性があります。 たとえば、六角形の有効な三角形分割では、次のような三角形になります。$[1,3,5]$存在する可能性がありますが、隣接する境界構造が確立されるまで除去できません。 三角グラフの隣接性を十分なものとして扱うと、除去によって凸性が維持されなければならないという幾何学的制約が無視されます。 

## アプローチ

 ブルートフォース再構築では、考えられるすべての頂点の巡回順序付けを試し、三角形の有効な削除シーケンスが存在するかどうかを確認します。 スタートエッジを修正したとしても、$(n-1)!$残りの頂点の可能な置換、および各順序を検証するには、少なくとも線形時間で削除をシミュレートする必要があります。 これは階乗時間計算量につながり、完全に実行不可能です。$n = 10^5$。 

重要な洞察は、凸三角形分割の各三角形が、双対がツリーである平面グラフの面のように動作するということです。 三角形はツリーのノードを形成し、隣接とはエッジの共有に相当します。 このような構造では、双対ツリーには常に葉があり、それらは特定のステップで削除できる三角形に正確に対応します。 

最初にポリゴンを再構築しようとする代わりに、視点を逆にします。つまり、共有エッジを通じて三角形の隣接関係を構築してから、リーフから構造を剥がします。 三角形は、現在残っている構造内に他の三角形と共有されていないエッジを持つ場合、つまりエッジが現在のポリゴン境界上にある場合に削除可能です。 

各エッジについて、それを使用する三角形の数を維持できます。 境界エッジは 1 回だけ表示されます。 少なくとも 1 つの境界エッジを持つ三角形は現在削除可能です。 これを削除するとエッジ数が更新され、新しい境界三角形が露出する可能性があります。 これにより、決定的なピーリングプロセスが実現します。 

削除順序を再構築したら、三角形がどのように接続されているかを解釈することで、頂点の循環順序を復元します。 最初に削除された三角形は基本方向を与え、その後の削除により境界が一貫して拡張されます。 最後のサイクルは、決して内部化されなかったエッジの隣接性の一貫性から回復されます。

 ## アルゴリズムのチュートリアル

 各三角形をノードとして扱い、各エッジを三角形間の共有オブジェクトとして扱います。 

1. 各三角形のエッジを正規化し、エッジから三角形へのマッピングを構築します。 

各三角形について、その 3 つの無向エッジを考慮します。 すべての三角形にわたって各エッジが何回出現するかを数えます。 これにより、どのエッジが進化する多角形の外側の境界にあるかがわかります。 
2. 共有エッジを介して三角形間の隣接関係を構築します。 

2 つの三角形がエッジを共有する場合、それらは双対グラフ内で隣接します。 元の構造が三角形分割であるため、この双対グラフはツリーになります。 
3. 少なくとも 1 つの境界エッジを持つすべての三角形を含むキューを初期化します。 

三角形は、現在のポリゴン境界にまだ接触している場合は削除できます。 一度だけ使用されるエッジの存在により、エッジを削除しても残りの形状の凸面が維持されることが保証されます。 
4. 繰り返しキューから三角形を削除し、削除順序にそのインデックスを記録します。 

三角形を削除するときは、概念的には三角形を構造から削除し、そのエッジのエッジ使用数をデクリメントします。 
5. 削除された三角形ごとに、隣接する三角形を更新します。 

エッジ カウントのデクリメントによって別の三角形が境界エッジを獲得する (エッジ カウントが 1 になる) 場合、その三角形は削除の対象となり、キューに追加されます。 
6. すべての三角形を順序付けした後、頂点サイクルを再構築します。 

最後に残った境界から開始して、共有エッジによって暗示される隣接関係をたどって、常に一貫した方向に従うようにします。 この構造により、すべての頂点をカバーする単一サイクルが保証されます。 

### なぜ効果があるのか

 不変条件は、いつでもカウントが 1 つだけのエッジが現在の多角形の境界を形成し、削除可能な三角形は少なくとも 1 つの境界エッジに属するエッジであるということです。 それぞれの除去により二重ツリー内の葉の面が削除されるため、残りの構造は接続された凸状のままになります。 エッジのカウントにより、隣接する 1 つの三角形が削除されるまで内部エッジのカウントが常に少なくとも 2 になるため、内部三角形が時期尚早に削除されないことが保証されます。 

これにより、ピーリング プロセスが常に有効であることが保証され、最終的にはすべての三角形が使い果たされ、凸多角形の三角形分割と一致する完全な削除順序が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        tris = []
        edge_map = {}
        
        def add_edge(a, b, idx):
            if a > b:
                a, b = b, a
            if (a, b) not in edge_map:
                edge_map[(a, b)] = []
            edge_map[(a, b)].append(idx)

        for i in range(n - 2):
            a, b, c = map(int, input().split())
            tris.append((a, b, c))
            add_edge(a, b, i)
            add_edge(b, c, i)
            add_edge(c, a, i)

        deg = [0] * (n - 2)
        adj = [[] for _ in range(n - 2)]

        for (a, b), lst in edge_map.items():
            if len(lst) == 1:
                tri = lst[0]
                deg[tri] += 1
            elif len(lst) == 2:
                u, v = lst
                adj[u].append(v)
                adj[v].append(u)

        from collections import deque
        q = deque([i for i in range(n - 2) if deg[i] > 0])
        removed = []
        vis = [False] * (n - 2)

        while q:
            u = q.popleft()
            if vis[u]:
                continue
            vis[u] = True
            removed.append(u)

            for (a, b, c) in [tris[u]]:
                edges = [(a, b), (b, c), (c, a)]
                for x, y in edges:
                    if x > y:
                        x, y = y, x
                    if (x, y) in edge_map:
                        edge_map[(x, y)].remove(u)
                        if len(edge_map[(x, y)]) == 1:
                            v = edge_map[(x, y)][0]
                            deg[v] += 1
                            if not vis[v]:
                                q.append(v)

        p = [tris[removed[0]][0]]
        for i in range(len(removed) - 1):
            a, b, c = tris[removed[i]]
            nxt = tris[removed[i + 1]]
            shared = set([a, b, c]) & set(nxt)
            if len(shared) >= 2:
                x = list(shared)
                p.append(x[0])

        p.append(tris[removed[-1]][0])
        print(*p)
        print(*(r + 1 for r in removed))

if __name__ == "__main__":
    solve()
```実装は、どの三角形が各無向エッジに接触するかを記録するエッジ テーブルを構築することから始まります。 これは、三角形分割構造の核となる表現です。 1 回現れるエッジは境界エッジですが、2 回現れるエッジは内部エッジです。 

キューには、境界エッジに付随する三角形がシードされます。 三角形が削除されるたびに、エッジの所有権が更新されます。 エッジが残りの 1 つの三角形に固有になると、その三角形は境界に露出し、キューに追加されます。 

頂点順序の再構築では、削除された三角形間の連続した重なりを使用します。 連続して削除された三角形の各ペアは、正確に 1 つのエッジまたは少なくとも 2 つの頂点を共有するため、ポリゴンの順序を段階的に拡張できます。 

エッジの正規化には注意が必要です。そうしないと、同じエッジが向きに応じて異なるオブジェクトとして扱われてしまいます。 もう 1 つの微妙な点は、複数のエッジが同じ三角形を複数回エンキューする可能性があるため、削除順序は訪問された配列によって厳密に制御する必要があることです。

 ## 特殊なケース

 最小限のポリゴン$n = 3$三角形が 1 つだけ含まれています。 この場合、すべてのエッジは境界エッジであるため、最初のキューには単一の三角形が含まれます。 アルゴリズムはそれを直ちに削除し、自明な順序を生成し、必要な両方の置換を満たします。 

退化しているように見えますが、有効な構成は、多くの三角形が 1 つの頂点を共有する場合です。 その場合でも、エッジ数によって境界エッジと内部エッジが区別されるため、最初は境界に隣接する三角形のみが適格となります。 隣接する 1 つの三角形が削除されるまでエッジは固有にならないため、境界以外の削除を強制することなく、剥離によって内部が徐々に露出します。 

最後の微妙なケースは、2 つの三角形が最初に内部にある 1 つのエッジを正確に共有する場合に発生します。 このエッジのカウントは 2 であるため、どちらの三角形もそのエッジのみに基づいて削除することはできません。 隣接する境界三角形を削除した後でのみ、そのエッジ ドロップが 1 にカウントされ、順番に次の三角形が正しくアクティブになります。
