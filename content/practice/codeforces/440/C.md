 ## 解決策
 ## 問題の理解

 与えられた正の整数を表すように求められます$n$数値の合計として表されます。各数値は、1 回以上繰り返された数字 1 のみで構成されます。 たとえば、121 は 111 + 10 または 111 + 11 - 1 として表すことができますが、タスクは合計自体を見つけることではありません。 代わりに、すべての加数で使用される数字 1 の最小合計数が必要です。 したがって、121 の場合、考えられる和の 1 つは 111 (1 が 3 つ) と 11 (1 が 2 つ) を使用し、合計 5 桁の 1 になりますが、最小の配置では実際には 6 桁が必要です。 出力はこの最小カウントです。 

入力は単一の整数です$n$まで$10^{15}$。 1 のみの数値のすべての合計を生成する強引な試みは実行不可能であるため、この上限は重要です。 すべてのシーケンスを生成する単純な再帰であっても、可能な組み合わせの数は指数関数的に増加するため、1 秒で実行できるよりも多くのステップが必要になります。 

素朴なエッジケースは次のような場合に発生します。$n$は 7 などの 1 桁です。以下の 1 のみの最大の数値を貪欲に選択しようとする不注意な解決策です。$n$1、次に 11、次に 111 を役に立たない順序で選択し、1 を数えすぎてしまう可能性があります。 もう 1 つの微妙な点は、21 など、1 より大きい桁の数値です。この場合、最適な分解には、11 ベースの単一の貪欲な合計を使用するのではなく、10 の累乗にわたって桁を分割することが含まれる場合があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。最大の 1 のみの数値をすべて生成します。$n$、すべての組み合わせを試して合計を求めます$n$。 各ステップで、使用された 1 桁の合計数を追跡します。 最終的にはすべての有効な合計が考慮されるため、これは原則として正しいです。 問題は、中程度の場合でも、$n$のように$10^6$、1 だけの数字は数万通りあり、組み合わせの数は指数関数的に増加します。 メモ化しても状態空間が大きすぎるため、$n$まで可能です$10^{15}$。 

より迅速な解決策のための重要な洞察は、問題を数値ごとの分解の形式として扱うことです。 任意の数値は、その各桁に 10 のべき乗を乗算して形成される数値の合計として表すことができ、さらに、それらのそれぞれを、対応する繰り返される 1 の数として表すことができることに注目してください。 たとえば、121 = 1×100 + 2×10 + 1×1。 各コンポーネントは、100 → 111 - 11、20 → 11 + 11 - 2 など、1 のみの数値として書くことができます。1 の最小数を計算する体系的な方法は、次の桁に対して動的プログラミングを実行することです。$n$、「キャリー」がカウントにどのように影響するかを追跡します。 

具体的には、次のように DP を定義します。`dp[pos][carry]`数字で始まるサフィックスを形成するために必要な 1 の最小数です`pos`、前の桁からのキャリーが与えられる。 各ポジションで、そこに配置できる 1 の数 (0 ～ 9 + キャリー) のすべてのオプションを試し、キャリーを適切に更新します。 これにより、問題が固定桁数 (最大 16 桁) に減ります。$10^{15}$) と小さなキャリー状態 (0 または 1) により、DP が扱いやすくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 桁DP | O(16_2_10) ≈ O(320) | O(16*2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む$n$文字列として入力すると、その数字の最下位から最上位まで簡単にアクセスできます。 文字列を反転すると、単位から最高位まで処理できます。 
2. サイズの DP テーブルを初期化します。`[number of digits + 1][2]`。 2 番目の次元はキャリーを表します。前の桁からのキャリーがない場合は 0、ある場合は 1 になります。 を除くすべてのエントリを最初に無限大に設定します。`dp[0][0] = 0`0 を必要とする数字はないからです。 
3. 各桁位置について`i`キャリーごとに 0 から length-1 まで`c`, 0 から 9 までの 1 の数 + キャリーを足してみます。 キャリーを含めたこの位置の合計を計算します。 合計モジュロ 10 がこの位置の桁と等しい場合、次の位置の DP を新しいキャリー (合計 // 10) で更新し、使用された数だけ 1 のカウントを増分します。 
4. すべての数字を処理すると、答えは次のようになります。`dp[length][0]`最後の桁の後にキャリーがゼロでなければならないからです。 

不変条件は、各ステップで、`dp[i][c]`最初の値を表すために必要な最小数の 1 を保持します。`i`の桁`n`キャリー付き`c`。 遷移では、現在の桁のモジュロ 10 に一致するすべての可能な 1 の数が正しく考慮され、設定がスキップされないことが保証されます。 DP は 1 の最小合計数を見つけることが保証されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = input().strip()
digits = list(map(int, reversed(n)))
L = len(digits)

INF = 10**18
dp = [[INF]*2 for _ in range(L+1)]
dp[0][0] = 0

for i in range(L):
    for carry in range(2):
        for ones_here in range(10):
            total = ones_here + carry
            if total % 10 == digits[i]:
                new_carry = total // 10
                dp[i+1][new_carry] = min(dp[i+1][new_carry], dp[i][carry] + ones_here)

print(dp[L][0])
```この解決策では、最初に桁を逆にして、最下位から順に処理します。 ネストされたループでは、各桁の 1 の可能なすべての数が考慮されます。 モジュロ チェックにより、この位置の数字が作成中の数字と一致することが保証されます。 キャリーは適切に更新され、DP テーブルには使用された最小の合計が格納されます。 よくある間違いは、キャリーを正しく伝播することを忘れたり、最上位から最初の順序で数字を使用したりすることです。これにより、モジュロ チェックが壊れてしまいます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = input().strip()
    digits = list(map(int, reversed(n)))
    L = len(digits)
    INF = 10**18
    dp = [[INF]*2 for _ in range(L+1)]
    dp[0][0] = 0
    for i in range(L):
        for carry in range(2):
            for ones_here in range(10):
                total = ones_here + carry
                if total % 10 == digits[i]:
                    new_carry = total // 10
                    dp[i+1][new_carry] = min(dp[i+1][new_carry], dp[i][carry] + ones_here)
    return str(dp[L][0])

# provided samples
assert run("121\n") == "6", "sample 1"

# custom cases
assert run("1\n") == "1", "single digit minimal"
assert run("9\n") == "9", "single digit max"
assert run("10\n") == "2", "two digits, exact multiple of 10"
assert run("1000000000000\n") == "1", "large power of ten"
assert run("1111111111111\n") == "13", "all ones number"
