 ## 解決策
 ## 問題の理解

 私たちは、ポリカルプスがテレビ番組のシーズン内でどのエピソードを視聴していないかを判断するよう求められています。 彼は、合計 _n_ のうち _n_ - 1 のエピソードを視聴しました。各エピソードには 1 から _n_ までの連続番号が付けられています。 入力により、_n_、エピソードの総数、および彼がすでに見たエピソードを表す _n_ - 1 個の整数のリストが得られます。 タスクは、不足しているエピソード番号を見つけることです。 

_n_ が 100,000 まで大きくなる可能性があることを考えると、O(n) よりもスケーリングが悪い解は遅くなりすぎる可能性があります。 たとえば、1 から _n_ までの各数値のリストを繰り返しスキャンすると、最悪の場合 O(n²) になり、n ≈ 10⁵ の場合は許容できないほど遅くなります。 線形パスを実行するか、数学的特性を使用して作業を軽減するソリューションが必要です。 

明らかではないエッジケースは、欠落しているエピソードが最初のエピソード (1) または最後のエピソード (n) である場合に発生します。 たとえば、n = 3 で、視聴されたエピソードが [2, 3] の場合、欠落しているエピソードは 1 です。欠落しているエピソードがリストの中央のどこかにあると仮定するソリューションは失敗します。 同様に、n = 3 で視聴されたエピソードが [1, 2] である場合、欠落しているエピソードは 3 ですが、配列の境界が誤って処理されると見落とされる可能性があります。 

## アプローチ

 ブルートフォース手法では、番号 1 から _n_ までを繰り返し、各番号が監視リストに存在するかどうかを確認します。 これが機能するのは、リストに 1 から _n_ の範囲の個別の整数が含まれているため、欠落している数値が答えになります。 ただし、サイズ _n_ - 1 のリストのメンバーシップのチェックは O(n) であるため、この単純なアプローチでは O(n²) 回の操作が実行されます。 n = 100,000 の場合、これはおよそ 10¹⁰ の操作に相当し、1 秒の制限時間には遅すぎます。 

最適なアプローチは、単純な数学的特性に依存します。 最初の n 個の自然数の合計は n*(n+1)/2 です。 この合計を計算し、視聴したすべてのエピソードの合計を差し引くと、その差は欠落しているエピソードになるはずです。 これは、視聴されたエピソードが 1 つおきの番号を 1 回だけカバーするため、機能します。 合計の計算と減算は両方とも O(n) であるため、合計実行時間は線形であり、制約内に快適に収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 差の合計 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 総エピソード数を読みます。n。 これにより、有効なエピソード番号の範囲がわかります。 
2. n - 1 個の視聴済みエピソードのリストを読みます。 各数値は、1 から n までの範囲内で異なることが保証されます。 
3. 式 n*(n+1)//2 を使用して、n 個のエピソード番号すべての合計を計算します。 これにより、エピソードが欠落していなかった場合の合計が得られます。 
4. 視聴したエピソードの合計を計算します。 これにより、これまでに確認されたすべての数値が得られます。 
5. 総計から視聴したエピソードの合計を減算します。 結果は、ポリカルプスが見忘れたエピソードの番号です。 
6. この欠落しているエピソード番号を印刷します。 

正確さを保証する重要な特性は、1 から n までのすべての個別の数値の合計から、それらの任意の n - 1 の合計を引いたときに、欠落している数値が 1 つだけ残るということです。 これは、最初のエピソードや最終エピソードを含め、どのエピソードが欠けているかに関係なく機能します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
watched = list(map(int, input().split()))

total_sum = n * (n + 1) // 2
watched_sum = sum(watched)

missing_episode = total_sum - watched_sum
print(missing_episode)
```コードは n と視聴したエピソードのリストを読み取ります。 浮動小数点の問題を回避するために、整数の除算を使用して最初の n 個の自然数の合計を計算します。 次に、視聴されたエピソードの合計を計算し、合計から差し引きます。 最後に、不足しているエピソードを出力します。 よくある間違いは、整数の除算を忘れたり、浮動小数点の除算を使用したりすることです。これにより、不正確な結果が得られる可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    watched = list(map(int, input().split()))
    total_sum = n * (n + 1) // 2
    watched_sum = sum(watched)
    return str(total_sum - watched_sum)

# provided sample
assert run("10\n3 8 10 1 7 9 6 5 2\n") == "4", "sample 1"

# custom cases
assert run("3\n2 3\n") == "1", "missing first episode"
assert run("3\n1 2\n") == "3", "missing last episode"
assert run("5\n1 2 3 4\n") == "5", "small sequence, last missing"
assert run("2\n1\n") == "2", "minimum size"
assert run("4\n1 3 4\n") == "2", "missing middle episode"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3\n2 3 | 1 | 最初のエピソードがありません |
 | 3\n1 2 | 3 | 最後のエピソードがありません |
 | 5\n1 2 3 4 | 5 | 小さなシーケンス、最後が欠落しています |
 | 2\n1 | 2 | 最小サイズ入力 |
 | 4\n1 3 4 | 2 | 中盤のエピソードが欠けている |

 ## 特殊なケース

 欠落しているエピソードが最初のエピソードである場合、たとえば、n = 3、watched = [2, 3]、total_sum = 6、watched_sum = 5 の場合、アルゴリズムは正しい 1 を返します。 欠落しているエピソードが最後のエピソードである場合、たとえば、n = 3、watched = [1, 2]、total_sum = 6、watched_sum = 3 の場合、アルゴリズムは 3 を返します。すべての場合において、合計の差分は、リスト内の位置に関係なく、正確な欠落数を取得します。
