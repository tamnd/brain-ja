 ## 解決策
 ## 問題の理解

 マッチ箱の列が与えられ、各マッチ箱にはいくつかのマッチが入っています。 一致の総数はボックスの数で割り切れるため、すべてのボックスが最終的にまったく同じ数を保持するターゲット構成が存在します。 

許可される唯一の操作は、単一の一致を 1 つのボックスからそのすぐ隣のボックスに移動することです。 移動はローカルで行われるため、マッチをボックス 1 からボックス 5 に移動するには、中間のボックスを通過する必要があるため、複数回の移動が必要になります。 

タスクは、初期分布を完全にバランスの取れた分布に変換するために必要な、このような隣接する手の最小数を計算することです。 

重要な制約は、ボックスの数は最大 50,000 まで可能ですが、値は 10^9 に達する可能性があることです。 これにより、個々の試合を 1 つずつ移動するシミュレーションは即座に除外されます。 単一の一致でも再配置に O(n) ステップが必要な場合があり、それをすべての一致に対して単純に実行すると、制限をはるかに超えた O(nk) 動作が発生します。 

隠れた難しさは、動きが独立していないことです。 1 つの一致を移動すると、ローカルの不均衡が変化し、将来の決定に影響を与えるため、二重カウントや間接フローの欠落を避けるために、貪欲なローカル バランシングを慎重に構成する必要があります。 

一般的な失敗例は、累積フローを追跡せずに過剰なボックスを右または左に送信して各ボックスを個別に「修正」しようとしたときに発生します。 たとえば、余剰を近隣に貪欲にプッシュしようとすると、ラインを伝播するときに同じ動きを複数回カウントする可能性があります。 

失敗の小さな例: 入力を考慮する`3`と`[1, 0, 5]`。 素朴なアプローチでは、最後のボックスから中央に 2 つの一致が送信され、次に中央から最初のボックスに 2 つ送信される可能性がありますが、伝播が適切に追跡されていない場合、同じユニットの移動が方向の処理に応じてカウントされ、一貫性がなくなる可能性があります。 

正しい解決策には、局所的な修正ではなく、不均衡な流れを全体的に把握する必要があります。 

## アプローチ

 強引なアイデアは、配列を繰り返しスキャンし、余剰のあるボックスを見つけて、1 つの一致を赤字に向かって段階的に移動することです。 このような各動きは明示的にシミュレートされます。 これは文字通り許可された操作に従っているので正しいのですが、遅すぎます。 最悪の場合、試合は O(n) 距離を移動し、そのような動きが O(nk) 回ある可能性があり、分布に応じて二次関数またはさらに悪い動作が発生する可能性があります。 

この改善は、個々の試合をシミュレートする必要がないことに気づいたことから来ています。 重要なのは、隣接するボックス間の各境界を通過する必要がある一致の数です。 

インデックス i までのボックスのプレフィックスを見ると、現在保持している一致の数と、最終的なバランスのとれた状態で保持する必要がある一致の数との間にいくらかの違いがあります。 この差は、i と i+1 の間の境界を越えて押し出されなければなりません。 これは、プレフィックス内のすべての不均衡が、そのエッジを横切る必要な移動に直接変換されることを意味します。 

したがって、個々の試合を追跡する代わりに、ランニングの不均衡を追跡します。 左から右に移動するにつれて、これまでに蓄積された余分な一致または欠落した一致の数が維持されます。 各位置におけるこの不均衡の絶対値は、まさにその境界を越える必要がある一致の数です。 

これにより、問題は 1 回のリニア スキャンに軽減されます。

 ## アルゴリズムのチュートリアル

 1. 合計を n で割ることにより、ボックスごとの目標一致数を計算します。 これにより、各位置に必要な最終的な値が得られます。 
2. 2 つの変数を初期化します: 実行中のインバランス`carry`そして回答アキュムレータ`moves`。 の`carry`前のボックスから渡されたがまだ吸収されていない過剰な一致の数を表します。 
3. 各ボックスを左から右に繰り返します。 
4. 各ボックス i で、ターゲットからの現在のボックスの偏差を追加して不均衡を更新します。`carry += a[i] - target`。 
5. の絶対値を加算します。`carry`答えに。 これは、蓄積された不均衡により、ボックス i と i+1 の間の境界を越える必要がある一致を表します。 
6. 最後まで続けます。 最終的な答えは、すべての絶対的な不均衡の合計です。 

重要な推論ステップは、プレフィックスを修正したら、残りの不均衡は物理的に境界を通過して次のセグメントに到達する必要があり、そのようなパスごとに単位一致ごとに正確に 1 つの移動コストがかかるということです。 

### なぜ効果があるのか

 すべての位置 i で、変数`carry`プレフィックス内の一致の純余剰に等しい`[0..i]`最終構成でそのプレフィックスに含まれる内容と比較します。 一致は隣接する境界を越えてのみ移動できるため、この剰余のすべてのユニットは、ある時点で i で境界を越える必要があります。 これらの余剰の絶対値を合計すると、各不均衡がフロー表現の 1 つの境界遷移に関連付けられているため、各交差が 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    target = total // n
    
    carry = 0
    moves = 0
    
    for x in a:
        carry += x - target
        moves += abs(carry)
    
    print(moves)

if __name__ == "__main__":
    solve()
```この実装は、プレフィックスの不均衡の考え方に直接準拠しています。 ターゲットは 1 回計算されます。 ループはランニングの黒字または赤字を維持します。 絶対値の累積は、各境界を通過する必要がある流れの量をカウントするため、重要なステップです。 

微妙な点は、リセットしないことです。`carry`に追加した後`moves`。 キャリーはアレイ全体に伝播する永続的な不均衡を表すため、リセットするとグローバル フロー構造が破壊されます。

 ## 特殊なケース

 エッジケースの 1 つは、すべての一致がすでに均等に分散されている場合です。 アルゴリズムはこれをきれいに処理します。`carry`は全体を通してゼロのままであり、絶対的な寄与は追加されません。 

もう 1 つのケースは、後で解決される前に、一方に不均衡が大きく蓄積する場合です。 例えば：```
4
0 0 8 0
```キャリーは、剰余に達するまで徐々にマイナスになっていきます。 各境界はその不足分を繰り越さなければならないため、各ステップは正しく答えに貢献します。 

最後のケースは、最小入力サイズです。```
1
k
