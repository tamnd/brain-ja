 ## 解決策
 ## 問題の理解

 2D グリッド上の点のコレクションが与えられます。各点は整数の座標を持つセルと考えることができます。 すべてのポイントについて、最も遠い他のポイントからどのくらい離れているかを決定する必要があります。距離はマンハッタン距離を使用して測定されます。 2 点間のマンハッタン距離は、それらの x 座標と y 座標の差の絶対値の合計です。 

タスクは、各点について、セット内の他の点までの最大マンハッタン距離を計算し、これらの最大値を出力することです。 

これを興味深いものにしているのが制約構造です。 最大 n 個の点がある場合、ペアごとの直接比較はすべてのペアをチェックすることを意味し、n 乗の動作が行われます。 n が約 200,000、またはバージョンに応じて 2000 の場合、n の 2 乗はすでに実行不可能です。これは、数十億または数兆の操作が必要となるためです。 これにより、各点を他のすべての点と明示的に比較するソリューションは即座に除外されます。 

単純な実装では、絶対値でつまずく可能性もあります。 たとえば、点を x または y で個別に並べ替えて直接最適化を試みても、両方の座標が相互作用するため、マンハッタン距離を直接解決することはできません。 

すべての点が同一であるか、直線上にある場合、微妙なエッジ ケースが発生します。 すべての点が同じである場合、すべての点の正解は 0 になります。 すべての点が (i, i) のように対角線上にある場合、マンハッタン距離はインデックスの差に純粋に比例するようになり、x と y を独立して扱う誤った単純化は、一般的なケースでは失敗しても、そのような構造化入力では依然として機能するように見える可能性があります。 

たとえば、点 (0, 0)、(1, 2)、(3, 1) を考えてみましょう。 x または y のみへの単純な投影では、最遠点が独立した最大値ではなく結合された式に依存することがわかりません。 

## アプローチ

 主な困難は、マンハッタン距離公式の絶対値です。 2 つの点 (x, y) と (a, b) の距離は |x − a| です。 + |y − b|。 ブルート フォース アプローチでは、すべてのペアのこの値を直接計算し、ポイントごとの最大値を追跡します。 これは定義に正確に従っているので正しいですが、一定時間ごとに O(n²) 回の距離計算が必要となり、n が大きい場合には遅すぎます。 

重要な観察は、絶対値式は、符号の選択に応じて線形形式の有限セットに拡張できるということです。 単一の絶対差の場合、 |x − a| は max(x − a, a − x) と書き換えることができます。 この考えを拡張すると、マンハッタン距離は、x と y の差の符号の選択にそれぞれ対応する 4 つの線形式にわたって最大になります。 これにより、非線形メトリックが一連の線形関数に変換されます。 

この形式で書き直すと、問題は根本的に変わります。 すべての点のペアを直接比較する代わりに、すべての点にわたって少数の固定数の線形式を評価するだけで済みます。 これらの各式について、すべての点にわたる最大値を事前に計算できます。 次に、各点について、各式の下でその寄与を評価し、それを事前に計算されたグローバル最大値と組み合わせます。 

これが機能するのは、マンハッタン距離の各インスタンスがこれらの標識構成の 1 つに正確に対応し、すべての点の最大値がこれらの線形形式の 1 つで現れる必要があるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ポイントをさまざまな符号パターンに基づく寄与に変換し、グローバル極値を使用してポイントごとに一定時間でクエリに回答します。

1. 各点 (x, y) について、符号の組み合わせに対応する 4 つの変換値 (x + y、x − y、−x + y、および −x − y) を計算します。 各式は、展開時に絶対値を解決できる 1 つの方法を表します。 
2. これら 4 つの式のそれぞれについて、すべての点をスキャンし、最大値を計算します。 これらは、各サイン構成の下で可能な限り最高のパートナー ポイント寄与を表します。 このステップではグローバル構造を分離するので、後でペアごとの比較を行う必要がありません。 
3. 各点 (x, y) について、その点における 4 つの式のそれぞれの値を計算します。 
4. 各式について、その式の事前に計算された最大値からポイント自体の値を減算して、候補の答えを計算します。 これは、可能な限り最良の反対符号のパートナーとポイントをペアリングすることをシミュレートします。 
5. 4 つの候補の最大値を取得します。 これにより、その地点のマンハッタンの最遠距離が得られます。 

減算が行われる理由は、各線形形式が距離を 2 つの変換された点値の差として効果的にエンコードするためで、ペアリングはその差を最大化することにつながります。 

### なぜ効果があるのか

 マンハッタン距離は、x と y の差に関する独立した符号の選択から導出される線形関数の固定セットにわたる最大値に分解されます。 すべての点のペアは、これらの形式のいずれかでその距離に寄与します。 各フォームの最大値をグローバルに事前計算することにより、あらゆる固定点について、各フォームの下で可能な最良のパートナーがすでにわかっていることが保証されます。 すべての有効なペアがいずれかのフォームで正確にカバーされるため、フォーム全体で最大値を取ると、真の最大距離が再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    INF = 10**18
    max1 = -INF  # x + y
    max2 = -INF  # x - y
    max3 = -INF  # -x + y
    max4 = -INF  # -x - y

    for x, y in pts:
        max1 = max(max1, x + y)
        max2 = max(max2, x - y)
        max3 = max(max3, -x + y)
        max4 = max(max4, -x - y)

    for x, y in pts:
        ans = 0
        ans = max(ans, max1 - (x + y))
        ans = max(ans, max2 - (x - y))
        ans = max(ans, max3 - (-x + y))
        ans = max(ans, max4 - (-x - y))
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、変換された 4 つの座標系のグローバル極値を集計します。 これらの各極値は、固定符号構成の下で可能な最良のエンドポイントに対応します。 

2 番目のパスでは、各ポイントは、自身の寄与を差し引くことによって、変換された各システム内でどこまで伸長できるかを計算します。 減算は、絶対的なペアの選択を差の最大化の問題に変換するため、重要です。 

よくある実装上の間違いは、回答を反復するときに最大値を再計算することです。これにより、誤って点がそれ自体とペアになり、まれなケースで推論が歪む可能性があります。 事前計算により、すべてのクエリ間の一貫性が保証されます。 

もう 1 つの微妙な問題は、4 つの変換で十分であることを忘れていることです。 式を追加または少数追加すると、絶対値分解の完全性が損なわれます。 

## 実用的な例

 点 (0, 0)、(2, 3)、(5, 1) を考えてみましょう。 

変換された値を計算します。 

| ポイント | x+y | x−y | −x+y | −x−y |
 | --- | --- | --- | --- | --- |
 | (0,0) | 0 | 0 | 0 | 0 |
 | (2,3) | 5 | -1 | 1 | -5 |
 | (5,1) | 6 | 4 | -4 | -6 |

 グローバル最大値は、max1 = 6、max2 = 4、max3 = 1、max4 = 0 です。 

次に答えを計算します。 

| ポイント | max1-(x+y) | max2-(x−y) | max3-(-x+y) | max4-(-x−y) | 答え |
 | --- | --- | --- | --- | --- | --- |
 | (0,0) | 6 | 4 | 1 | 0 | 6 |
 | (2,3) | 1 | 5 | 0 | 5 | 5 |
 | (5,1) | 0 | 0 | 5 | 6 | 6 |

 これにより、明示的なペアの列挙を行わずに、各ポイントが最も遠いパートナーを見つけることが確認されます。 

対称構造の 2 番目の例: (1,1)、(1,1)、(1,1)。 変換された値はすべて同一であるため、max から self を引いた値はすべて 0 になります。 出力は正しくすべて 0 になり、縮退入力が正しいことが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 点ごとに一定の仕事量で点を越える 2 つの直線パス |
 | スペース | お(1) | 少数の実行最大値のみが保存されます。 

このアルゴリズムは、ペアごとの距離の計算を完全に回避するため、大規模な座標セットの一般的な制約内に快適に適合します。 n が 200,000 までの場合でも、ソリューションはポイントごとに数回の単純な算術演算のみを実行します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    out_lines = []

    n = int(sys.stdin.readline())
    pts = [tuple(map(int, sys.stdin.readline().split())) for _ in range(n)]

    INF = 10**18
    max1 = max(x + y for x, y in pts)
    max2 = max(x - y for x, y in pts)
    max3 = max(-x + y for x, y in pts)
    max4 = max(-x - y for x, y in pts)

    res = []
    for x, y in pts:
        ans = max(
            max1 - (x + y),
            max2 - (x - y),
            max3 - (-x + y),
            max4 - (-x - y),
        )
        res.append(str(ans))
    return "\n".join(res)

# sample-like
assert run("3\n0 0\n2 3\n5 1\n") == "6\n5\n6"

# single point
assert run("1\n10 10\n") == "0"

# all equal
assert run("3\n1 1\n1 1\n1 1\n") == "0\n0\n0"

# line structure
assert run("3\n0 0\n1 1\n2 2\n") == "4\n2\n4"

 | シングルポイント | 0 | 自明な基本ケース |

 ## 特殊なケース

 (10, 10) のような単一点入力の場合、アルゴリズムはすべての変換された最大値をそれぞれ 20、0、0、-20 として計算します。 ポイント自体の寄与を減算すると、すべての式が 0 に評価され、正しい答えが得られます。 

すべての同一のポイントでは、すべての変換された値は同一であるため、各最大値は各ポイントの値に等しくなります。 減算は正確にキャンセルされ、ゼロ距離が保証され、自己ペアリングの問題が発生しないことが確認されます。 

(0,0)、(1,1)、(2,2) などの対角線上に配置された点の場合、変換は単純な線形オフセットに減ります。 各符号構成が一貫して崩壊し、大域的最大値がラインの端点を正確に表すため、アルゴリズムは依然として最大広がりを正確に捕捉します。
