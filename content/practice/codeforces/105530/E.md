 ## 解決策
 ## 問題の理解

 6 と 9 の 2 桁のみを使用して形成された数字を調べます。すべての位置がこれら 2 桁のいずれかであれば、有効な数字はすべて「適切」です。 タスクは、それらから何か複雑なものを構築することではなく、次の形式の複数のクエリに答えることです: 指定された数値範囲内にそのような適切な数値がいくつあるか$[l, r]$。 

したがって、問題は、非常に特殊な数字の世界、つまりアルファベット上のすべての文字列を理解することに帰着します。$\{6, 9\}$、数字の選択以外の先頭の制限なしで整数として解釈されます。 クエリごとに、これらの特別な数値が 2 つの境界の間にいくつ入るかを数えたいとします。 

重要な構造上の観察は、すべての適切な数値のセットが、次の整数の範囲に比べて非常に小さいということです。$10^{18}$。 すべての桁位置には独立して 2 つの選択肢があるため、固定長の場合$i$、まさにあります$2^i$そういった数字。 18 までのすべての長さを合計すると、合計は次のようになります。$2^1 + 2^2 + \dots + 2^{18}$、これはわずか数十万の要素です。 これにより、乱暴な列挙が可能になります。 

この制約は、すべての整数に対して反復処理を行う解は次のとおりであることを意味します。$10^{18}$クエリごとに行うのは不可能です。$10^{18}$操作。 クエリごとのリニア スキャンでさえ、すぐに失敗します。 一方、最大でも周囲を反復処理すると、$3 \cdot 10^5$多くのテスト ケースであっても、事前に計算された値は些細なものです。 

次の場合、境界処理から微妙なエッジ ケースが発生します。$l = 1$またはいつ$l$それ自体は素晴らしい数字です。 たとえば、数字を数える場合$\le r$そして数字を引きます$< l$の場合、次の値とまったく同じ値を誤って除外したり二重にカウントしたりすると、1 つずつずれたミスが発生します。$l$。 もう 1 つのエッジ ケースは、数値を整数ではなく文字列として扱うことです。 長さ 1 から始まる固定長の数字列のみを生成するため、先頭のゼロは無関係です。 

## アプローチ

 直接的な総当たりアプローチは、次のすべての整数を反復処理することです。$l$に$r$そして、各数値に数字 6 と 9 のみが含まれているかどうかをチェックします。このチェックは桁数に線形であるため、単一の数値の場合は次のようになります。$O(18)$。 ただし、範囲の長さは最大です。$10^{18}$、これは完全に不可能になります。 単一のクエリでも、$10^{18}$小切手。 

重要な点は、実際には任意の数値を検査する必要がないということです。 有効なセット全体は構造的に決定されます。各長さは、数字の組み合わせの完全なバイナリ セットに正確に寄与します。 これは、すべての有効な数値を一度事前計算し、それらをソートされた順序で保存し、二分検索を使用してクエリに答えることができることを意味します。 

バックトラッキングまたは 1 ～ 18 の長さのビットマスクを使用して、すべての適切な数値を生成します。各構築ステップで 6 または 9 が追加され、サイズの完全なバイナリ ツリーが形成されます。$2^i$深さで$i$。 すべての値を収集した後、それらを並べ替えます。 次に、各クエリは標準的なプレフィックスカウント問題になります。つまり、事前に計算された値がいくつあるかを数えます。$[l, r]$2 つのバイナリ検索を使用します。 

総当りから最適への移行は、視点を変えることによってもたらされます。つまり、整数行をスキャンする代わりに、組み合わせ構造を直接列挙します。

 ## アルゴリズムのチュートリアル

 1. 1 から 18 までの長さの数字列を構築して、すべての適切な数値を生成します。各位置は、6 または 9 の 2 つの可能性に分岐します。これにより、各数字シーケンスが 1 つの整数に正確に対応するため、すべての有効な数値が 1 回だけ生成されます。 
2. 生成中に、構築された各数字シーケンスを整数に変換し、配列に格納します。 このステップが必要なのは、後で辞書編集上の順序ではなく、数値による順序付けが必要になるためです。 
3. 生成が完了したら、すべての nice 数値の配列をソートします。 ソートにより構造が調整され、二分探索が適用できるようになります。 並べ替えがなければ、範囲クエリに効率的に答えることができなくなります。 
4. 各クエリについて$[l, r]$、有効な値の数を計算します。$\le r$二分探索を使用して、有効な値の数を減算します。$< l$。 これにより、範囲クエリが 2 つのプレフィックス クエリに変換されます。 
5. そのクエリに対する回答として差分を返します。 

### なぜ効果があるのか

 重要な不変条件は、事前計算された配列にはすべての有効な Nice 数値が 1 回だけ含まれ、数値の昇順にソートされることです。 このため、二分探索では、すべての要素のプレフィックス数が正しく識別されます。$\le x$ソートされたリストの連続したプレフィックスを形成します。 2 つのプレフィックス数を減算すると、それらの要素が正確に分離されます。$[l, r]$、二重カウントや省略はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def generate(n, cur, arr):
    if n == 0:
        arr.append(int(cur))
        return
    generate(n - 1, cur + '6', arr)
    generate(n - 1, cur + '9', arr)

def main():
    arr = []
    for length in range(1, 19):
        generate(length, "", arr)

    arr.sort()

    def count_le(x):
        lo, hi = 0, len(arr)
        while lo < hi:
            mid = (lo + hi) // 2
            if arr[mid] <= x:
                lo = mid + 1
            else:
                hi = mid
        return lo

    t = int(input())
    for _ in range(t):
        l, r = map(int, input().split())
        print(count_le(r) - count_le(l - 1))

if __name__ == "__main__":
    main()
```この解決策は、1 から 18 までのすべての長さを構築する再帰ジェネレーターを使用して、すべての有効な数値を構築することから始まります。各再帰レベルでは、数字 6 または 9 が追加され、二分決定空間を完全にカバーすることが保証されます。 すべての数値が収集されると、数値の順序が配列の順序と一致するように並べ替えられます。 

機能`count_le(x)`標準の上限二分探索を実行し、要素の数を返します。$\le x$。 クエリごとの最終的な答えは、次のプレフィックス数の差です。$r$そして$l-1$、これにより間隔が正しく分離されます。 

重要な詳細は次のとおりです`l - 1`のメンバーシップを確認しようとする代わりに、`l`直接。 これにより、次のような特殊なケースが回避されます。$l$それ自体は有効な数値です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math
    from bisect import bisect_right

    arr = []
    def gen(n, s):
        if n == 0:
            arr.append(int(s))
            return
        gen(n - 1, s + "6")
        gen(n - 1, s + "9")

    for i in range(1, 5):
        gen(i, "")
    arr.sort()

    def count_le(x):
        return bisect_right(arr, x)

    it = iter(inp.strip().split())
    t = int(next(it))
    out = []
    for _ in range(t):
        l = int(next(it)); r = int(next(it))
        out.append(str(count_le(r) - count_le(l - 1)))
    return "\n".join(out)

# custom cases
assert run("1\n1 5\n") == "0"
assert run("1\n6 9\n") == "2"
assert run("1\n6 6\n") == "1"
assert run("1\n10 100\n") == "2"

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、クエリ範囲が最小の nice 数値よりも下で始まる場合です。 例えば、$l = 1, r = 5$。 アルゴリズムは計算します`count_le(5) - count_le(0)`。 生成された値がないため、$\le 5$、両方のカウントがゼロであり、正しい出力 0 が生成されます。$l-1$特別な分岐を行わずに自然に下限を処理します。 

もう 1 つのケースは、範囲が生成された数値と正確に一致する場合です。 のために$l = r = 66$、`count_le(66)`66 までのすべての値が含まれますが、`count_le(65)`それを除きます。 それらの差は 1 であり、単一の有効な数値を正確に数えます。 

最後の微妙なケースは順序付けです。生成は本質的にソートされていないため、ソートに失敗するとバイナリ検索の正確性が損なわれます。 たとえば、66 より前に 96 が生成された場合、プレフィックス数は無意味になります。 並べ替えにより、数値の順序が配列の順序と一致するという不変条件が保証されます。これは、すべてのクエリ ロジックにとって不可欠です。
