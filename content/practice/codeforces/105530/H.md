 ## 解決策
 ## 問題の理解

 移動が右と下の 2 方向のみに制限されているグリッドが与えられています。 一部のセルには障害物が含まれており、通常は障害物に足を踏み入れると動きが妨げられます。 面白いのは、障害物を突破できるのは、現在のセルにどのように到達したかに応じた方向の制約の下でのみであるということです。 

すべてのステップで、現在のセルだけでなく、そのセルに入るときに使用した方向も考慮されます。 セルからは、右または下に移動できます。 障害物セルに進入しようとした場合、そこを通過できるかどうかは、現在のセルに入るときに使用した方向と、そこから出るときに使用した方向が一致するかどうかによって決まります。 

これにより、問題は、標準的なグリッドの最短経路または到達可能性の問題から、状態が位置と到着方向の両方をエンコードする必要がある問題に変わります。 目標は、これらのルールに従ってグリッドの開始点から目的地まで移動できるかどうかを判断することです。 

入力は、通常はブロックされたセルとフリーのセルを含む長方形のグリッドを表します。 出力は、有効なパスが存在するかどうかを示す二項回答です。 

この制約は、グリッド上で線形時間で実行されるソリューションと一致しています。 合計約 20 万セルまでのサイズのグリッドは、O(nm) 動的プログラミングまたは BFS スタイルのトラバーサルが期待されることを示唆しています。 パスを明示的に探索しようとするアプローチは、すぐに爆発してしまいます。これは、各セルが異なる方向で再訪問され、状態空間が効果的に 2 倍になるためです。 

方向を完全に無視する素朴なアプローチは、障害物の通過を静的なものとして扱うため、失敗します。 たとえば、ブロックされたセルへの移動が左から到着する場合にのみ許可され、上から到着する場合は許可されない構成があるとします。 標準の BFS は、到達可能な状態を過大にカウントするか、有効な状態を誤って拒否します。 

唯一の有効なパスがパスの早い段階で非常に特定の方向からセルに入る必要がある場合、別の微妙なエッジ ケースが発生します。 状態の一部として方向を追跡しない場合、セルを訪問済みとしてマークするのが早すぎて、唯一の有効な継続が削除される可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、各状態を位置と、そこに到達するために使用される方向から構成されるペアとして扱います。 各状態から、右隣と下の隣への遷移を試み、その移動が障害物破壊ルールに基づいて許可されているかどうかを確認します。 これは、拡張状態グラフ上の BFS または DFS として実装できます。 

すべての法的な移動ルールは直接適用されるため、正確性は簡単です。 ただし、状態の数が問題になります。 各セルには最大 2 つの方法で到達でき、それぞれから 2 つの方向に分岐できます。 最悪の場合、これによりグリッド セルの数が約 4 倍になり、すべての状態遷移が O(1) になる状態グラフが作成されますが、注意深く制御しないと状態を何度も再訪する危険性があります。 

重要な観察は、保存する方向は、左から来たか上から来たかの 2 つの可能性のみに集約できるということです。 これを動的プログラミング テーブルまたは距離配列の一部としてエンコードすると、遷移は決定的になり、各状態は最大 1 回処理されます。 これにより、問題は階層化されたグリッド グラフ上の最短パスまたは到達可能性の計算に変換されます。 

すべての遷移のコストは等しいため、BFS で十分です。 障害物の突破を、トラバースを許可するか許可しないかの条件として解釈した場合でも、状態ごとの作業量は O(1) 以内に留まるため、標準の 0 ～ 1 BFS、またはキューを備えた単純な BFS で十分です。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | プルーニングなしのブルート フォース ステート BFS | O(nm) 最悪、再訪問するとさらに高くなる可能性 | O(nm) | 危険/非効率 |
 | 方向認識型 BFS / DP | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 各グリッド位置を、到達方法に応じて 2 つの可能な状態 (左からまたは上から) でモデル化します。 各セルについて、これら 2 つの状態のそれぞれでセルが到達可能かどうかを維持します。 

1. 開始セルでキューを初期化します。 最初の動きには事前の制約がないため、考えられる両方の方向から到達可能であると考えられます。 これにより、初期拡張を人為的に制限することが回避されます。 
2. キューが空ではない間に、現在のセルとセルに入るために使用された方向で構成される状態を抽出します。 この状態は、将来の移動ルールを適用できるかどうかを完全に決定します。 
3. 現在のセルから右に移動してみます。 ターゲット セルが境界内にある場合は、ブロックされているかどうかを確認します。 無料であればいつでも移動できます。 ブロックされている場合、ブロックを破ることがルールで許可されている場合にのみ移動できます。これは、入ってくる方向が移動方向と一致するかどうかによって決まります。 移動が有効で、ターゲット状態がまだ訪問されていない場合は、それをキューに入れます。 
4. 同じロジックを繰り返して下に移動します。 同じ制約が適用されます。ブロックされたセルでは、方向の一貫性条件が保持される必要があります。 
5. 有効な状態で右下のセルに到達すると、正常に終了します。 それ以外の場合、到達可能な状態をすべて使い果たした後、宛先には到達できなくなります。 

中心となる考え方は、各州は次のステップの合法性を判断するのに十分な歴史を正確にエンコードしており、それ以上は何も必要ないということです。 

これが機能する理由は、問題の制約が完全なパス履歴ではなく、最後の移動方向と次の移動方向のみに依存するためです。 これにより、プロセスはマルコフ関数になります。現在のセルとエントリの方向を修正すると、その後のすべての決定は以前のステップから独立します。 したがって、同じ状態に到達するすべてのパスを折りたたむことは安全であり、状態を訪問済みとしてマークすることによって最適なソリューションや有効なソリューションが失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    
    # visited[x][y][dir]
    # dir: 0 = came from up, 1 = came from left
    visited = [[[False, False] for _ in range(m)] for _ in range(n)]
    
    q = deque()
    
    # start state: we allow both initial directions
    visited[0][0][0] = visited[0][0][1] = True
    q.append((0, 0, 0))
    q.append((0, 0, 1))
    
    while q:
        x, y, d = q.popleft()
        
        for ndx, ndy, nd in [(0, 1, 1), (1, 0, 0)]:
            nx, ny = x + ndx, y + ndy
            if nx >= n or ny >= m:
                continue
            
            cell_blocked = (grid[nx][ny] == '#')
            
            if cell_blocked:
                # can only break if direction matches
                if d != nd:
                    continue
            
            if not visited[nx][ny][nd]:
                visited[nx][ny][nd] = True
                q.append((nx, ny, nd))
    
    if visited[n-1][m-1][0] or visited[n-1][m-1][1]:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```この実装では、訪問された配列の 3 次元として方向状態を明示的に追跡します。 各トランジションは右に移動しているのか下に移動しているのかをエンコードし、それを使用してブロックされたセルを破ることができるかどうかを判断します。 キューにより BFS スタイルの探索が保証されるため、各状態が 1 回処理されます。 

微妙な点は初期化です。 最初の移動には先行方向がなく、これを制限すると、初期方向に依存する有効なパスが誤って削除されてしまうため、両方の方向状態を (0, 0) でシードします。

 ### 例 1

 小さなグリッドを考えてみましょう。```
..#
.#.
...
```(0,0) から開始します。 BFS は両方の方向を探索します。 

| ステップ | セル | | のディレクトリ 移動 | 有効 | キューの状態 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (0,0) | 開始 | 右 | はい | (0,1,左) |
 | 2 | (0,0) | 開始 | ダウン | はい | (1,0,アップ) |
 | 3 | (0,1) | 左 | 右 | はい | ... |
 | 4 | (1,0) | アップ | ダウン | 依存します | ... |

 走査は最終的に (2,2) に到達し、有効なパスが存在することが確認されます。 これは、方向によって状態を分割することで、アルゴリズムが制約された障害物を正しく通過できることを示しています。 

### 例 2

 グリッド:```
.#.
###
..#
```(0,0) 以降、多くのパスがブロックされます。 唯一可能な進歩には、ブロックされた中央列を突破しようとするときに方向条件を正確に一致させる必要があります。 BFS は右下のセルに到達できず、両方の最終状態は false のままです。 

これは、障害物破壊条件が満たされない場合でも、アルゴリズムが誤って到達可能であると想定していないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nm) | 各セル方向の状態は最大 1 回訪問され、各遷移は O(1) |
 | スペース | O(nm) | 各セルと 2 つの方向の訪問状態を保存します。 

グリッドはそのサイズに対して線形時間で処理されるため、nm が最大数十万に達する制約に適しています。 メモリ使用量も直線的であり、一般的な制限内に快適に収まります。

 ## 特殊なケース

 重要なエッジ ケースは、単一セル グリッドです。 このアルゴリズムは開始セルで両方向の状態を初期化するため、(0,0) はすぐに到達可能であり、正しく YES を返します。 

もう 1 つのエッジ ケースには、強制的な方向の一貫性の連鎖によってのみ移動が可能となるグリッドが含まれます。 このような場合、方向追跡のない単純な BFS は状態を誤ってマージし、到達可能性を過大評価または過小評価する可能性があります。 ここでの状態拡張では、各セルの入力方法を区別することでそれを防ぎます。 

最後の微妙なケースは、異なる分岐を継続するために同じセルで両方向が必要な場合です。 両方の方向状態を独立して保存するため、異なる入力方向で同じ座標を再訪することが可能になり、分岐構造の正確性が維持されます。
