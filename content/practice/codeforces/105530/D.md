 ## 解決策
 ## 問題の理解

 このタスクは、指定された整数以上の非常に小さな固定セットから最小の数値を選択することです。 「適切な数値」はすでにわかっており、6 つの特定の値 (6、9、66、69、96、および 99) に限定されています。各入力整数について、目標は、このセットをスキャンし、少なくとも入力と同じ大きさの最小要素を選択することです。 

入力は、クエリを表す値または値のシーケンスにすぎません。 各クエリは同じ質問をします。これらの事前定義された候補のうち、指定されたしきい値を下回らない最初の候補はどれですか。 出力は、クエリごとに選択された候補です。 

候補セットは決して変更されず、サイズが一定であるため、計算量の点で制約は非常に小さくなります。 クエリが多数ある場合でも、クエリごとに最大 6 回の比較が必要です。 これにより、ソリューションはクエリ数に対してわずかな線形時間内に収まります。 

主な微妙な点は境界動作に由来します。 入力が適切な数値の 1 つに正確に等しい場合、答えは次に大きい数値ではなく、その数値そのものでなければなりません。 たとえば、66 の入力は 66 を返す必要があり、67 の入力は 69 にジャンプする必要があります。厳密に大きい値のみをチェックする不用意な実装は、完全一致で失敗します。 もう 1 つのエッジ ケースは、99 を超える入力であり、正しい動作は問題の予測に依存します。 このバージョンでは、99 が最大の nice 数値であるため、問題によって入力が有効であることが保証されている場合、または未定義であることが保証されている場合、99 を超える入力は通常、99 にマップされます。 この簡単なバージョンの標準的な解釈は、入力は有効な答えが存在する範囲内にあるということです。 

## アプローチ

 強引なアイデアは、直接列挙することです。 各クエリについて、6 つの候補番号すべてを反復処理し、「候補が n 以上である」という条件を満たす最小値を追跡します。 これが機能するのは、正確性が値の比較以外の順序付けの仮定に依存しないためです。 

データセットが固定されており小さいため、このアプローチは精神的にすでに最適です。 最悪の場合のクエリあたりのコストは 6 回の比較であるため、クエリの数が多い場合でも、非常に小さな定数係数を使用すると、合計作業量はクエリの数に比例します。 

この問題を自明なものにする主な観察点は、検索スペースが動的ではないということです。 並べ替え、大規模なドメインにわたる二分検索、またはオプションでリストを保存する以外の前処理は必要ありません。 この構造は本質的に、一定サイズの配列に対する静的検索です。 

もう少し「設計された」バージョンでは、リストが事前に並べ替えられ、最小の要素から上に向かって 1 回スキャンされます。 これにより、有効な候補が見つかり次第、早期に停止することが保証されます。 ただし、値が 6 つしかないため、最も単純なスキャンでも事実上一定時間になります。

 ## アルゴリズムのチュートリアル

 素敵な数値の固定リストを使用して、各クエリを個別に解決します。 

1. 6 つの素敵な数字をリストに保存します: [6、9、66、69、96、99]。 この表現により、計算を行わずに単純な反復が可能になります。 
2. 各入力値 n について、変数の回答を可能な候補よりも大きい値で初期化するか、未設定のままにして比較によって計算します。 
3. 固定リスト内の各数値 x を反復処理します。 
4. x が n 以上の場合、x を潜在的な答えとみなします。 これまでに発生した最小の x を追跡します。 
5. すべての候補をチェックした後、保存されている有効な最小値を出力します。

ステップ 4 で早期に停止する代わりに最小限の操作を使用する理由は、すべての実装でリストがソートされることが保証されていないためです。 事前に並べ替えておけば、最初の一致ですぐに返すこともできますが、これは要件ではなく実装上の選択です。 

### なぜ効果があるのか

 正確さは、候補セットが完全かつ有限であるという事実に依存します。 すべての有効な回答はこのセットに属している必要があり、それらの間に結果を変える可能性のある隠れた数字は存在しません。 すべての可能性を検討し、制約を満たす最小のものを選択するため、より有効な答えを見逃すことはなく、無効な答えを選択することもできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return

    nice = [6, 9, 66, 69, 96, 99]
    out = []

    for s in data:
        n = int(s)
        best = None
        for x in nice:
            if x >= n:
                if best is None or x < best:
                    best = x
        out.append(str(best))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、すべての入力トークンを一度に読み取り、単一行形式と複数行形式の両方を安全に処理します。 各トークンは独立したクエリとして扱われます。 クエリごとに、6 つの数値の固定リストをスキャンし、有効な数値が見つかった場合は最適な候補を更新します。 

重要な実装の詳細は、次の初期状態を処理することです。`best`。 使用する`None`センチネル値との誤った比較を回避し、最初の有効な候補がリストの後半に表示された場合に正確さを保証します。 

## 実用的な例

 次の入力シーケンスを考えます。`7`そして`66`。 

のために`n = 7`、各候補者を評価します。 

| 候補者 | x ≥ n を確認します | 現在のベスト |
 | --- | --- | --- |
 | 6 | いいえ | なし |
 | 9 | はい | 9 |
 | 66 | はい | 9 |
 | 69 | はい | 9 |
 | 96 | はい | 9 |
 | 99 | はい | 9 |

 7 以上の最小候補であるため、最終的な答えは 9 になります。 

のために`n = 66`、進行は次のとおりです。 

| 候補者 | x ≥ n を確認します | 現在のベスト |
 | --- | --- | --- |
 | 6 | いいえ | なし |
 | 9 | いいえ | なし |

 | 69 | はい | 66 |
 | 96 | はい | 66 |
 | 99 | はい | 66 |

 出力は 66 で、境界での等価性が正しく処理されたことを示しています。 

これらのトレースは、等価性が正しく処理されていること、およびアルゴリズムが常に最初に一致した候補ではなく最小の適格な候補を選択していることを確認します。 

## 複雑さの分析

 ## 特殊なケース

 入力が最小の nice 数値より小さい場合、条件を満たす最初の候補であるため、アルゴリズムは常に 6 を返します。 これが機能するのは、すべての候補が明示的にチェックされ、6 つが含まれることが保証されるためです。 

入力が 6、9、99 などの境界値のいずれかに等しい場合、等価性チェックが行われます。`x >= n`前にスキップするのではなく、候補自体が選択されるようにします。 たとえば、入力 9 の場合、スキャンでは 9 が検出され、すぐにそれが有効なものとして扱われるため、誤って 66 が選択されることがなくなります。 

入力が 99 を超える場合、動作はそのような入力が問題の制約に存在するかどうかによって異なります。 該当する場合、明示的に処理しない限り、アルゴリズムは有効な候補を返しません。 この簡単なバージョンのほとんどの解釈では、有効な答えがセット内に常に存在するように入力が制限されています。つまり、このケースは実際には起こりません。
