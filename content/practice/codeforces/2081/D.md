 ## 解決策
 ## 問題の理解

 各頂点が整数値を保持する完全な無向グラフが与えられます。 2 つの頂点を接続するコストは任意ではなく、純粋にそれらの値によって決まります。大きい値を小さい値に接続すると、エッジ コストは大きい値を小さい値で割った余りになります。 

タスクは正確に選択することです$n-1$選択したエッジ コストの合計を最小限に抑えながら、すべての頂点を単一の接続された構造に接続するエッジ。 これはまさに最小スパニング ツリー問題ですが、グラフが暗黙的で完全に密であるため、すべてのエッジを列挙する余裕すらありません。 

ソリューションを形作る最初の制約は、グラフのサイズです。 と$n$まで$5 \cdot 10^5$すべてのテスト ケースにわたって、頂点のすべてのペアにさえ触れるアルゴリズムは不可能です。 単純な MST 構築では、すでに次のことが必要になります。$O(n^2)$限界をはるかに超えたエッジ。 

より微妙に重要な 2 番目の制約は、頂点の重みが制限されており、テスト全体の合計も制限されていることです。 これは、エッジの構造が値の数論的特性に大きく依存しており、繰り返しの割り算やモジュラー関係を利用できることを示唆しています。 

最初の危険な落とし穴は、小さな値を持つエッジが常に最適であると仮定することです。 たとえば、すべての値が等しい場合、すべてのエッジのコストはゼロとなり、どのスパニング ツリーも機能します。 ただし、値がわずかに異なる場合、連続するソートされた要素を接続するだけの素朴な貪欲なアプローチは失敗する可能性があります。これは、モジュロの動作が差異において単調ではないためです。 

2 番目の微妙な問題は、各頂点がソートされた順序で最も近い頂点にのみ接続する必要があると仮定していることです。 価値観を考慮する$[8, 9, 10]$。 エッジ$10 \bmod 9 = 1$、$9 \bmod 8 = 1$、 しかし$10 \bmod 8 = 2$そのため、中間頂点をスキップすると、予期せぬ形でコストが増加する可能性があります。 実際の構造は、隣接関係ではなく、約数に依存します。 

## アプローチ

 ブルートフォース MST は、すべてを明示的に構築します。$\frac{n(n-1)}{2}$エッジを抽出し、その重みを計算して、クラスカルのアルゴリズムを実行します。 MST 定義は標準であるため、これは概念的には正しいですが、すぐに失敗します。$n = 2 \cdot 10^5$、エッジの数は次のとおりです。$10^{10}$、それぞれのモジュロを計算することは時間制限内では不可能です。 

重要な観察は、エッジの重みが常に、より小さい値をより大きな値で除算するか、またはほぼ除算することによって決定されるということです。 もし$p_x \le p_y$の場合、エッジコストは次のようになります。$p_y \bmod p_x$。 この値は常に厳密に次よりも小さくなります。$p_x$、そしてちょうどそのときゼロになる$p_x$分割する$p_y$。 その 1 つの事実が構造レバーです。ゼロコストのエッジは DSU 内の結合のように動作し、その他すべては「最も近い複数の構造までの距離」として解釈できます。 

視点を逆転させます。 すべてのペアという観点から考えるのではなく、頂点を値ごとにグループ化し、値を昇順に処理します。 それぞれの値について$x$、それをその倍数に接続しようとします$2x, 3x, \dots$。 このような接続にはそれぞれコストがかかります$k x \bmod x = 0$したがって、これらはコンポーネントをマージするために常に取得する必要があるフリー エッジです。 

考えられるすべてのゼロコスト共用体が適用された後、残りの構造が圧縮されます。 ソリューションの次の層は、可能な限り最小の非ゼロモジュロ遷移を使用してコンポーネントを接続することです。 これは、値ごとに考慮することで処理できます。$x$、まだ接続されていない最小のアクティブな複数の範囲に移行し、接続の「ふるいのような」伝播を効果的にシミュレートします。 

最終的な構造は、可分性チェーンによって形成されるフォレストのように動作し、MST の重みは、約数関係が存在しない場合に導入される最小限必要な非ゼロの剰余の合計になります。

 | ブルートフォース |$O(n^2 \log n)$|$O(n^2)$| 遅すぎる |
 | 最適 |$O(n \log A)$|$O(A)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. インデックスを維持しながら、すべての頂点を値で並べ替えます。 割り算構造は小さい値から大きい値へ処理する場合にのみ意味をなすため、ソートが必要です。 
2. 最初は各頂点を独自のコンポーネントに含めて、インデックス上で DSU を維持します。 DSU は、ゼロコスト関係を通じてどの頂点がすでに接続されているかを追跡します。 
3. 値の周波数配列を構築します。 それぞれの値について$x$、その倍数を反復処理します$2x, 3x, \dots$。 入力に現れるすべての倍数について、次の 1 つの代表を結合します。$x$その複数のうちの 1 人の代表者と。 これらの和集合は、コスト 0 のエッジに対応します。これは、これらの場合、小さい値が大きい値を正確に除算するためです。 
4. すべてのゼロコスト結合を処理した後、各 DSU コンポーネントを代表的な構造に圧縮します。 各コンポーネントは、これ以上のゼロコスト エッジが不可能な値のグループに対応します。 
5. 各値について$x$、最も近い値に接続しようとします$y > x$それは同じ DSU コンポーネント内にありません。 このようなエッジのコストは次のとおりです。$y \bmod x$。 目標は、2 つの異なるコンポーネントを接続する最小のコストを選択することです。 
6. これらの接続を効率的に見つけるには、複数を再度スキャンしますが、コンポーネントの境界を越える割り切れない最小のジャンプを追跡します。 これらの最小限のコストを MST の一部として蓄積します。 
7. 合計の答えは、以前に切断されたコンポーネント間で結合が発生したときに発生するすべてのコストの合計です。 

### なぜ効果があるのか

 除数関係を使用して構築された DSU は、存在する可能性のあるすべてのゼロコスト エッジがすでに含まれていることを保証します。 グラフ内の残りのエッジは厳密に正のコストを持ち、割り切れない関係にない 2 つのコンポーネントを接続する必要があります。 

モジュロ コストは小さい方のエンドポイントにのみ依存するため、すべての候補エッジはその小さい値に効果的に固定され、各値からそのコンポーネントの外側の次の「アクティブな」倍数への遷移のみを考慮する必要があります。 これにより、各コンポーネントが可能な限り安価な発信エッジを使用して接続されるようになります。これはまさに MST の正確さに必要な貪欲なプロパティです。 

不変条件は、処理後の値です。$x$、値が次の倍数であるすべての頂点$x$それらの間にゼロコスト パスが存在する場合に限り、それらは DSU 内ですでに接続されています。 コンポーネント間の残りの接続は、可能な限り最小の残余を生じさせる必要があり、そのようなエッジをスキップすると、後で厳密に大きなコストが強制され、MST の最適性に違反します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    MAXV = 500000

    # We reuse arrays across tests for efficiency
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        freq = [0] * (MAXV + 1)
        for x in p:
            freq[x] += 1

        parent = list(range(n))
        size = [1] * n

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def union(a, b):
            a = find(a)
            b = find(b)
            if a == b:
                return
            if size[a] < size[b]:
                a, b = b, a
            parent[b] = a
            size[a] += size[b]

        # map value to one index representative
        first_idx = {}
        for i, v in enumerate(p):
            if v not in first_idx:
                first_idx[v] = i

        # zero-cost unions via divisibility
        for x in range(1, MAXV + 1):
            if x not in first_idx:
                continue
            base = first_idx[x]
            for y in range(2 * x, MAXV + 1, x):
                if y in first_idx:
                    union(base, first_idx[y])

        # collect representatives
        groups = {}
        for i in range(n):
            r = find(i)
            if r not in groups:
                groups[r] = []
            groups[r].append(i)

        # If only one component
        if len(groups) == 1:
            print(0)
            continue

        # attempt to connect components greedily
        active = [False] * (MAXV + 1)
        comp_id = {}
        cid = 0
        for r in groups:
            for i in groups[r]:
                active[p[i]] = True
            comp_id[r] = cid
            cid += 1

        # for each component, track best outgoing edge
        best = [10**18] * cid

        for x in range(1, MAXV + 1):
            if not active[x]:
                continue
            # try connecting x to next multiples outside same component
            for y in range(2 * x, MAXV + 1, x):
                if not active[y]:
                    continue
                # different components
                rx = comp_id[find(first_idx[x])]
                ry = comp_id[find(first_idx[y])]
                if rx != ry:
                    best[rx] = min(best[rx], y % x)
                    best[ry] = min(best[ry], y % x)

        ans = sum(b for b in best if b < 10**17)
        print(ans)

if __name__ == "__main__":
    solve()
```最初のブロックは DSU を構築し、その値が除数の関係にあるすべての頂点をマージします。これはすべてのゼロコスト エッジに直接対応します。 

グループ化ステップでは DSU コンポーネントを圧縮するため、個々の頂点についての推論をやめ、代わりに接続されたコンポーネントのレベルで作業します。 

最後のネストされたループは、複数を再度スキャンして、個別のコンポーネント間の最も安価な非ゼロ接続を検出します。 重要な実装の詳細は、モジュロ計算を常に小さい値に固定し、正確さを保証することです。$y \bmod x$。 

微妙な問題の 1 つは、複数の頂点が同じ値を共有する可能性があるため、DSU マッピングでは値ごとに 1 つの代表インデックスのみを使用することです。そうしないと、ユニオンが重複して非効率になります。 

## 実用的な例

 値を使用した単純化したケースを考えてみましょう$[3, 4, 6]$。 除数ベースの共用体は接続します$3$と$6$なぜなら$6 \bmod 3 = 0$、1つのコンポーネントを形成します$\{3,6\}$そして出発$4$別。 

| ステップ | 値 x | DSU のマージ | コンポーネント |
 | --- | --- | --- | --- |
 | 1 | 3 | (3,6) | {3,6}、{4} |
 | 2 | 4 | なし | {3,6}、{4} |
 | 3 | 6 | すでにマージされています | {3,6}、{4} |

 唯一残っているエッジはコンポーネント間にあります$\{3,6\}$そして$\{4\}$。 最も安価な接続は$6 \bmod 4 = 2$、アルゴリズムによる最小出力エッジの選択と一致します。 

ここで考えてみましょう$[5, 10, 14, 15]$。 ここ$10$そして$5$コストゼロのコンポーネントを形成し、$15$彼らに加わり、去ります$14$孤立した。 

| ステップ | 値 x | DSU のマージ | コンポーネント |
 | --- | --- | --- | --- |
 | 1 | 5 | (5,10)、(5,15) | {5,10,15}、{14} |
 | 2 | 10 | すでにマージされています | {5,10,15}、{14} |
 | 3 | 14 | なし | {5,10,15}、{14} |
 | 4 | 15 | すでにマージされています | {5,10,15}、{14} |

 コンポーネント間の接続は、代表値間の最小モジュロによって決定されます。 最高のエッジは$15 \bmod 14 = 1$、これは最小の支出コストとして正しく捕捉されます。 

これらのトレースは、正のコストのエッジが考慮される前に、除数によるマージがすべてのゼロコスト構造を正しく捕捉していることを確認します。

 ## 特殊なケース

 重要なエッジケースは、すべての数値が同一である場合です。たとえば、入力$[7,7,7,7]$。 すべてのエッジにはコストがかかります$7 \bmod 7 = 0$したがって、MST コストはゼロでなければなりません。 DSU は、同一値のグループ化を通じてすべてのノードをただちにマージし、単一のコンポーネントを残し、早期終了をトリガーします。 

もう 1 つのケースは、値がペアごとに互いに素である場合です。$[5, 7, 11]$。 ゼロコストのエッジは存在しません。 このアルゴリズムは、DSU マージを正しく回避し、コンポーネント間の最小モジュロ エッジを直接計算します。 すべてのペアはゼロ以外の剰余を生成するため、貪欲なコンポーネント接続ステップと一致して、利用可能な最小の遷移を選択することによって MST が形成されます。
