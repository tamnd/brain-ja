 ## 解決策
 ## 問題の理解

 アレイに対してグローバルな「レベル削減」を繰り返し実行しています。 各ステップで、現在存在するすべての正の値を調べ、その中で最小のものを特定し、その値を出力して、すべての正の要素を同じ量だけ削減します。 ゼロは変更されず、再び寄与することはありません。 

このプロセスは、配列が以前に完全にゼロになった場合でも、固定回数の操作の間継続されます。 すべてがゼロになると、残りのすべての操作は単純にゼロを出力します。 

重要な構造は、配列が下から層ごとに剥がされていることです。各操作により、残りのすべての正のエントリから現在の最小の正の「高さ」が削除されます。 

この制約では、最大 100,000 個の要素と 100,000 回の操作が許可されます。 すべてのステップで配列全体をスキャンして最小値を再計算するソリューションでは、最悪の場合、制限時間をはるかに超える約 10^10 の演算が必要になります。 ステップごとに完全なソートまたは完全な再計算を繰り返しても合格しません。 

いくつかの特殊なケースでは、素朴なアプローチが明らかに明らかになります。 

配列がすでにすべて 0 である場合、答えは単純に k 個の 0 です。 少なくとも 1 つの正の値が存在すると仮定する単純な実装では、最小値を計算しようとしてクラッシュしたり、無効な値を返したりする可能性があります。 

k が明確な正の値の数よりもはるかに大きい場合、プロセスは最終的にすべて 0 で安定し、0 を出力し続けます。 例えば、`[5]`k = 3 の場合、次の結果が得られます。`5, 0, 0`。 配列が空になった後、残りの操作を実行せずに早期に停止する解決策は正しくありません。 

## アプローチ

 直接的なシミュレーションは容易に想像できます。配列を繰り返しスキャンし、最小の非ゼロ要素を見つけて、すべての正の要素からそれを減算して、それを出力します。 これは操作定義に正確に従っているため、これは正しいです。 ただし、各ステップのコストは O(n) であり、最悪の場合、O(k) ステップを実行して O(nk) が得られる可能性があります。 両方とも 10^5 までの場合、これは 10^10 の演算になり、これは現実的ではありません。 

重要な観察は、私たちは実際には、あらゆる瞬間に進化する配列値を気にしていないということです。 配列が「平坦化」されるとき、最小の正の値のシーケンスのみを考慮します。 現在の最小の正の値を減算するたびに、少なくとも 1 つの要素がゼロになり、アクティブな値のセットが縮小します。 このプロセスは、明確な正の値を昇順に繰り返し抽出することに相当します。 

配列をソートすると、一連の操作がより明確になります。 1 つの異なる値から次の大きな値に移動するたびに、その差は新しい減算レイヤーに対応します。 等しい値が一緒に崩壊し、長さゼロのギャップが生成されます。 特定の値が寄与する回数は、その上に別個の「レベル」がいくつ残っているかによって決まります。 

したがって、配列をソートして等しい値のグループを処理すると、すべての減算をシミュレートすることなく、各最小値が何回出現するかを計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(nk) | お(1) | 遅すぎる |
 | 並べ替え + グループ化 | O(n log n) | O(1) または O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を非降順で並べ替えます。 これにより、等しい値がグループ化され、残りの最小値が構造の先頭から常にアクセスできるようになります。 
2. ソートされた配列を反復処理して、正の要素の間で見られる前の値を追跡します。 新しい明確な正の値に遭遇するたびに、この時点以降アクティブなままになる要素の数を計算します。 
3. 個別の値ごとに、それを出力する回数を決定します。 これは、厳密にこの値以上である残りの要素の数から、以前のレベルによってすでに「消費」されている要素を差し引いたものと等しくなります。 
4. 残っているアクティブな要素の数に応じて、連続する個別の値の差を繰り返し出力します。 概念的には、等しい値の各グループは 1 つの「層の高さ」減算ステップに寄与します。 
5. k 個の出力を生成したら停止します。 k に達する前に正の値をすべて使い尽くした場合は、残りの操作にゼロを追加します。 

正確さは、各減算ステップの後、正の値のマルチセットが、既に通過した個別のしきい値の数だけ減算された元の値とまったく同じであるという不変条件から得られます。 並べ替えるとこれらのしきい値が直接明らかになるため、それぞれの個別の値は、新しい最小値になる 1 つのステップに対応します。 

このプロセスがソートされた値レベルをピーリングすることと同等であるため、アルゴリズムが機能します。 各レベルの変更は、ソートされた配列内の厳密に増加する値に対応し、すべての要素が使い果たされるまで、そのような変更ごとに 1 つの出力が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort()
    
    res = []
    i = 0
    
    while i < n and len(res) < k:
        if a[i] == 0:
            i += 1
            continue
        
        # current minimum positive value
        current = a[i]
        
        # skip all equal values
        j = i
        while j < n and a[j] == current:
            j += 1
        
        # number of remaining active elements
        remaining = n - i
        
        res.append(current)
        
        # after subtracting, all elements in [i, j) become zero,
        # so we conceptually move forward
        i = j
    
    # if we still need outputs, fill with zeros
    while len(res) < k:
        res.append(0)
    
    print("\n".join(map(str, res)))

if __name__ == "__main__":
    solve()
```この実装は、繰り返される減算プロセスの構造を公開するためにソートに依存しています。 ポインタ`i`は常に残りの最小の正の値を指します。 次を使用して等しい値をグループ化します。`j`、減算下では同じように動作するためです。 各グループは、現在の最小値に対応する 1 つの出力を生成します。 

残りのゼロによる埋め込みは、k 個の操作の前にすべての要素が使い果たされる場合を処理します。 

微妙な点は、配列から明示的に値を減算することがないことです。 この操作はグループ化ロジックに暗黙的に含まれています。値を渡すと、その値は将来の最小限の考慮事項から完全に削除されたとみなされます。 

## 実用的な例

 ### サンプル 1

 入力:```
3 5
1 2 3
```ソートされた配列は`[1, 2, 3]`。 

| ステップ | 私 | 現在 | 出力 | アクティブのまま |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 1 | 3 |
 | 2 | 1 | 2 | 1 | 2 |
 | 3 | 2 | 3 | 1 | 1 |
 | 4 | - | - | 0 | 0 |
 | 5 | - | - | 0 | 0 |

 配列が使い果たされるまで、各個別レベルを 1 回出力します。 すべての値が消費された後、ゼロで埋められます。 

これは、並べ替えられたそれぞれの個別の値が 1 つの減算レイヤーに寄与していることを示しています。 

### サンプル 2

 入力:```
4 5
10 3 5 3
```ソートされた配列は`[3, 3, 5, 10]`。 

| ステップ | 私 | 現在 | 出力 | アクティブのまま |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 3 | 3 | 4 |
 | 2 | 2 | 5 | 3 | 2 |
 | 3 | 3 | 10 | 5 | 1 |
 | 4 | - | - | 0 | 0 |
 | 5 | - | - | 0 | 0 |

 より高い個別の値に移動するたびに、以前の削減後の次の最小値としてその値が出力されます。 

これにより、ソートにより、繰り返される減算プロセスが一連のしきい値ジャンプに変換されることが確認されます。

 ## 特殊なケース

 配列にゼロのみが含まれている場合、アルゴリズムはすぐにパディングフェーズに入ります。 正の値に遭遇することはないため、ソートされたスキャンは出力を生成せず、最後のループは k 個のゼロを出力します。 すべての操作ですべてゼロの配列が参照されるため、これは定義と一致します。 

のような入力の場合`[5]`k が 1 より大きい場合、アルゴリズムは次のように出力します。`5`最初のパスでは、残りの正の値が認識されず、ゼロで埋められます。 これは、唯一の要素が削減されるとプロセスが安定するという考えと一致します。 

すべての要素が等しい場合、次のようにします。`[3,3,3]`、並べ替えられたスキャンでは、単一の個別の値が生成されます。 その値は 1 回出力され、残りの操作はすべてゼロになります。 これは、1 つの減算ステップですべての要素が同時に削除されるという事実を捉えています。
