 ## 解決策
 ## 問題の理解

 小さな整数が与えられます$x$、そして 2 つの整数を構築する必要があります$a$そして$b$、両方とも 1 と 2 の間にあるように制約されます。$x$、いくつかの算術条件が同時に成立するように。 初め、$b$分けなければなりません$a$、 意味$a$の正確な倍数です$b$。 第二に、製品$a \cdot b$を超えなければなりません$x$。 第三に、商$a / b$依然として厳密に以下に留まらなければなりません$x$。 

これを解釈する便利な方法は、約数の選択を考えることです。$b$、次に複数を選択します$a$このペアが十分に大きな積と、十分に小さな商の両方を生成するかどうかを確認します。$x$。 なぜなら$x \le 100$、検索空間は絶対的に小さいですが、制約の構造により、ブルート フォース パターンが予測可能になり、推論が容易になります。 

制約はすぐに次のことを示します。$O(x^2)$最大作業量は約 1 時間であるため、すべてのペアのチェックは完全に安全です。$10^4$繰り返し。 ただし、本当の目標はパフォーマンスではなく、構築が常に存在するかどうか、または構築が失敗する例外的な小さな値が存在するかどうかを認識することです。 

微妙なエッジケースが現れるのは、$x = 1$。 その場合はどちらも$a$そして$b$1 に等しくなければならず、条件は崩れます。$a \cdot b = 1$より大きくない$x$、したがって解決策は存在しません。 を想定した素朴な構築$x \ge 2$誤ってペアを出力します。 

もう 1 つの失敗モードは、設定などのあまりにも貪欲な選択から発生します。$a = x$そして$b = 1$。 これは常に割り算と商の制約を満たしますが、製品の状態は次のようになります。$x \cdot 1 > x$、これは誤りであるため、この戦略は体系的に失敗します。 

重要なのは、次のペアを見つけることです。$a$よりわずかに大きい$x$に対して$b$を保ちながら、$a/b < x$。 これは、小さなものを使用することを提案します$b$そして適度に大きい倍数$a$、両方の制約のバランスを取ります。 

## アプローチ

 直接的な総当たり戦略によりすべてのペアが試行されます$(a, b)$と$1 \le a, b \le x$、割り切れる可能性をチェックし、2 つの不等式を検証します。 これは簡単で、検索空間全体を徹底的にテストするため、常に正しいです。 候補者の数は最大で$x^2$、それで、$x \le 100$、これは約 1 万チェックであり、無視できる程度です。 

ただし、このアプローチでは構造が明らかになりません。 制約が大きい場合、総当たり攻撃は二次関数となり、直ちに実行できなくなります。 重要な観察は、実際には任意のペアが必要ないということです。 ペアだけが必要です。$a$の倍数です$b$、書き換えることができます$a = k \cdot b$。 条件はこうなります$k \cdot b^2 > x$そして$k < x$。 この再定式化では、小さいものを選択することを提案しています。$b$そして小さい$k$、およびよりわずかに大きい値の因子ペアを検索します。$x$。 

以来$x$は小さいので、最もクリーンな構造はペアをテストすることです。$b$範囲は 1 から上、$a$の最大倍数として選択されます$b$を超えない$x$、または小さな乗数を使用してわずかに上方に調整します。 実際には、制約によりすべてのペアの存在が保証されるため、すべてのペアを昇順に試して最初の有効なペアを返すだけで十分です。$x > 1$。

 ## アルゴリズムのチュートリアル

 徹底的なチェックに依存していますが、有効なペアが見つかった場合は直ちに停止します。 

1. 可能なすべての値を反復処理します。$b$1から$x$。 私たちが選ぶ$b$まず、許可される値を定義しているためです。$a$分割性を通じて。 
2. それぞれについて$b$、すべての可能な値を反復処理します。$a$1から$x$。 
3. かどうかを確認します。$a$で割り切れます$b$。 This enforces the structural constraint that$a$の倍数でなければなりません$b$。 
4. 割り切れる場合は、次のことを計算します。$a \cdot b > x$。 これにより、ペアの製品スペースが十分に大きくなります。 
5.次のことも確認してください。$a / b < x$。 これにより、商が厳密に以下の範囲にとどまることが保証されます。$x$。 
6. 両方の条件が満たされる場合、ペアを直ちに出力し、プログラムを終了します。 
7. すべての可能性を調べてもペアが見つからない場合は、-1 を出力します。 

これが機能する理由: 問題空間内のすべての有効なペアが明示的にチェックされます。 どの組み合わせもスキップしないため、解が存在する場合にはそれを見逃すことはありません。 早期終了は正確性を変えることなく効率を向上させるだけです。 制約により、解決策が存在するかどうかが保証されます。$x > 1$、列挙中に発生します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

x = int(input().strip())

for b in range(1, x + 1):
    for a in range(1, x + 1):
        if a % b == 0:
            if a * b > x and a // b < x:
                print(a, b)
                sys.exit()

print(-1)
```このコードは、前述の徹底的な検索を直接実装します。 ネストされたループは、すべての候補ペアを昇順に列挙します。$b$そして$a$。 割り算チェックにより、有効な倍数のみが考慮されることが保証されます。 浮動小数点エラーを回避するために、商条件には整数除算が使用されます。 プログラムは有効なペアが見つかるとすぐに終了します。これは、成功後の不要な計算を防ぐために重要です。

 ## 特殊なケース

 構造的に重要な唯一のエッジケースは、$x = 1$。 ここで考えられる唯一のペアは$(1, 1)$ですが、積制約に失敗します。$1 \cdot 1 \nleq 1$。 アルゴリズムはこれを明示的にチェックします: 単一の反復$b = 1, a = 1$がテストされ、不等式が失敗し、ループは -1 で終了します。 

もう一つの微妙なケースは非常に小さいです$x$たとえ解決策があったとしても直感的には解決策が存在しないと思われるような値。 たとえば、$x = 2$、アルゴリズムは試みます$(a, b) = (2, 1)$製品が以下の値を超えていないため、即座に拒否します。$x$。 徹底的なチェックにより、ケース分析を必要とせずに正確性が保証されます。
