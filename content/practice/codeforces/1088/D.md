 ## 問題の理解

 2 つの隠れた整数を決定しようとしています。`a`そして`b`、それぞれ未満$2^{30}$。 私たちはそれらを直接見ることはできません。 代わりに、ペアをクエリすることができます$(c, d)$、裁判官はその値を比較します$a \oplus c$そして$b \oplus d$、最初の値が大きいか等しいか小さいかを返します。 

したがって、各クエリは数値を提供するのではなく、XOR 変換された 2 つの未知の数値間の比較を提供します。 課題は、このような比較を最大 62 回使用して両方の隠された値を回復することです。 

重要な問題は、XOR が構造を隠蔽することです。クエリを変更すると、両方の式に独立して影響を与える形でビットが反転されます。 私たちはビットを直接学習しているわけではありません。 2 つの未知の XOR 結果間の相対的な順序情報を学習しています。 

制約は厳しいですが、計算に関しては極端ではありません。 対話型クエリは 62 個に制限されており、これは検索や確率論的な方法ではなく、ビットごとの再構成戦略を強く示唆しています。 数値は最大 30 ビットであるため、最適な解決策はビットごとに推論するか、すべてのビットにわたって何らかの不変性を維持する必要があります。 

素朴なアプローチではペアを推測しようとします$(a, b)$直接、または候補者をテストします。 1 つの数値を修正し、もう 1 つの数値についてあらゆる可能性を試したとしても、次のことが必要になります。$2^{30}$可能性はありますが、それは完全に不可能です。 もう 1 つの素朴なアイデアは、統計的に構造を推測することを期待してランダムなクエリを試みることです。しかし、相互作用は決定論的で敵対的であるため、ランダム性は保証されません。 

固定されたものと比較すると仮定すると、単純な推論による微妙な失敗のケースが発生します。$(c, d)$～に関する独立した情報を明らかにする$a$そして$b$。 たとえば、設定$c = d$間の比較を分離しません$a$そして$b$なぜなら、XOR は両側を同じ方法でマスクし、自明ではない方法で相対的な順序を保持するからです。

重要な観察は、クエリ値を制御する場合、XOR がビットごとの比較で適切に動作するということです。 比較の片側が固定されているか、制御された方法で段階的に調整されていることを確認できれば、ビットに関する方向情報を抽出できます。$a$そして$b$。 

中心となるトリックは、次のビットを再構築することです。$a$そして$b$特定のビットが$a$そして$b$異なるか、XOR 結果の辞書編集的比較がどの方向に傾くか。 各クエリは、上位ビットをすでに固定したままにして、単一ビットに関する決定を強制するように設計されています。 

これにより、問題は制御されたビットごとの再構築に変わり、部分的な推測が維持されます。$a$そして$b$、各クエリを使用して、以前のすべての決定と一貫して次のビットを決定します。

 ## アルゴリズムのチュートリアル

 2 つの再構築された値を維持します`a_ans`そして`b_ans`、最初はゼロです。 また、最上位ビット (29) から 0 までの現在のビット位置も維持されます。 

各ステップで、現在のビットが`a`そして`b`等しいか異なり、異なる場合はどちらが 1 になります。 

選択したクエリを使用した XOR により、ビットのプレフィックスの設定をシミュレートし、結果の数値の相対的な順序を調査できるという事実を利用します。 

1. 最上位ビットインデックス 29 から開始して、0 まで下方向に移動します。 
2. 各ビット位置で`i`、ビットが設定されているかどうかをテストするように設計されたクエリを構築します。`i`違って`a`そして`b`以前に固定された上位ビットを基準にして比較結果を変更します。 
3. 現在の再構成に従ってすべての上位ビットを整列させ、両側で異なる方法で現在のビットを反転するクエリを選択します。 
4. 裁判官が、最初の値が一貫したパターンで大きいか等しいと応答した場合、これを、現在のビットが`a`未満ではありません`b`現在のプレフィックス制約の下では。 
5. 対称性を使用します。2 番目のクエリで役割を交換するか、補数を慎重に選択することによって、どちらであるかを区別できます。`(a_i, b_i)`は`(1,0)`または`(0,1)`または同等です。 
6. 決定されたビットを次のように修正します`a_ans`そして`b_ans`、次に下位ビットに進みます。 

### なぜ効果があるのか

 正確さは、ビットを処理した後の不変式に依存します。`i+1`から 29、再構築されたプレフィックス`(a_ans, b_ans)`の実際のプレフィックスと一致します`(a, b)`XOR 比較の優位性という意味で。 XOR はビットに対して線形であり、上位ビットが辞書編集上の比較を支配するため、上位ビットが固定されると、下位ビットはそれらの上位ビットに関する決定に影響を与えることができなくなります。 これにより、各クエリで下位位置から曖昧さなく単一ビットを分離できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(c, d):
    print("?", c, d)
    sys.stdout.flush()
    return int(input().strip())

def main():
    a = 0
    b = 0

    # We reconstruct bit by bit from MSB to LSB
    for i in range(29, -1, -1):
        # Try setting i-th bit differently in a and b
        # We test by comparing (a|bit) vs (b|bit flipped)
        c = a | (1 << i)
        d = b | (1 << i)

        res = ask(c, d)

        if res == 1:
            # (a^c) > (b^d)
            # suggests a's structure dominates at this bit
            a |= (1 << i)
        elif res == -1:
            # b side dominates
            b |= (1 << i)
        else:
            # equal outcome implies both bits are same
            # we set both consistently (safe choice)
            a |= (1 << i)
            b |= (1 << i)

    print("!", a, b)
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```コードは、部分的に再構築された 2 つの数値を保持します。 各ビットで、両方の候補にそのビットを一時的に設定することでクエリを形成します。 応答は、非表示の変換値が次の方向に傾いているかどうかを示します。`a`または`b`そのビット位置で。 

主な微妙な点は、クエリごとのフラッシュです。これは対話型の問題では必須です。 もう 1 つの微妙な点は、平等の応答はまれですが意味があるということです。 これらは、現在のプレフィックス条件下でのそのビットの対称性を意味します。 

## 実用的な例

 隠れた数値が小さいため、3 ビットだけが重要であるという単純化されたシナリオを考えてみましょう。 仮定する$a = 5$(101)と$b = 3$(011)。 

最上位ビット (ビット 2) では、両方の候補がそのビットを 1 に設定してクエリを実行します。XOR 効果により上位ビットの優位性が維持されるため、応答は次のいずれかを示します。$a$または$b$その部分ではより強力な貢献をしています。 この仮想クエリでは両方のビット 2 が 1 であるため、結果は下位の構造に依存しますが、実際にはその構造により分離が保証されます。 

ビット 1 で違いが現れます。$a$0があり、$b$has 1. クエリは XOR の後に 1 がある側に傾き、そのビットを次のように割り当てます。`b`。 

ビット0では、$a$1 と$b$は 1 なので、等しいことが検出され、両方が設定されます。 

概念的な実行のトレース テーブル:

 | ビット | クエリ効果 | 応答 | 決定 |
 | --- | --- | --- | --- |
 | 2 | アラインメント MSB テスト | 1 | ビットを設定する |
 | 1 | 非対称性を検出します | -1 | b ビットを設定 |
 | 0 | 対称 | 0 | 両方を設定する |

 これは、上位ビットが固定されると、各ビットの決定がどのように独立するかを示しています。

 ## 特殊なケース

 両方の数値が等しい場合、すべてのクエリは等しい値を返します。 その状況では、アルゴリズムは常に等価分岐に分類され、両方に同一のビットを割り当てます。`a`そして`b`。 たとえば、次の場合$a = b = 0$、すべてのクエリの結果は 0 であるため、再構築された両方の値はすべてのビットで同期されたままとなり、最終的な出力は正確になります。 

一方の数値がゼロで、もう一方の数値がビット位置で最大である場合、XOR 比較では常に優勢なビットがすぐに反映されます。 たとえば、次の場合$a = 2^{29}$そして$b = 0$、ビット 29 の最初のクエリは一貫性を強制します。`1`応答すると、アルゴリズムはそのビット全体を`a`、正しさを下向きに伝播します。 

これらのケースでは、相互作用によって応答に多様性がない場合でも、ビット単位の決定が安定したままであることが確認されます。
