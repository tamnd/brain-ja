 ## 解決策
 ## 問題の理解

 加重ツリーが与えられます。このツリーでは、すべてのノードが正、負、またはゼロの整数値を保持します。 タスクは、いくつかのノードを選択し、選択したノードをいくつかの接続されたコンポーネントに分割することです。 選択した各コンポーネント内では、すべてのノードが同じコンポーネントのノードのみを使用してエッジを介して接続されている必要があり、異なるコンポーネントは互いに素である必要があります。 

選択が固定されたら、選択したすべてのノードの重みの合計を取得し、それを形成された接続コンポーネントの数で割ることによって評価します。 目標は、この比率を最大化することです。 複数の選択が同じ最良の比率を達成する場合、より多くのコンポーネントを使用する構成を優先することによって、この問題は解決されます。 

分母は選択した頂点の数ではなく、選択した頂点を分割する方法に依存するため、問題の構造は欺瞞的です。 ツリー構造では、暗黙的にエッジを切断することによってコンポーネントを形成できますが、隣接性によってノードが同じコンポーネントに強制されるわけではないため、実際には任意のサブセットを選択し、それらが誘発する接続された部分の数を数えています。 

3・10^5 までの制約 n により、線形または線形に近い解が強制されます。 サブセットの数が指数関数的であり、ノードごとの二次遷移でさえ時間制限を超えるため、サブセットを列挙したり、すべての可能なコンポーネント分解を明示的に試行したりするアプローチは、直ちに実行不可能になります。 

すべての重みが正でない場合、微妙なエッジ ケースが発生します。 単純な貪欲なアプローチでは、ノードの選択を完全に回避するか、コンポーネントを削減しようとする可能性がありますが、問題には少なくとも 1 つのコンポーネントが必要であるため、単一のノードを選択することが唯一の意味のあるアクションになります。 最適値が負の場合、別の非自明な状況が発生します。 このような場合、分母の効果がタイブレーク動作を支配するため、合計が増加しなくても、コンポーネントの数を増やすと比率が向上する可能性があります。 

## アプローチ

 直接的なアプローチでは、ノードのサブセットを選択し、それらが誘発する連結成分の数を計算し、比率を評価しようとします。 接続がノード間で独立しておらず、サブセットの数が 2^n であるため、これはすでに困難になっています。 たとえ k を固定したとしても、合計が最大になる k 個のコンポーネントを形成できるかどうかを判断することは、ツリー上の制約付き分割問題に帰着しますが、一般に依然として指数関数的です。 

重要な洞察は、ノードとコンポーネントの役割を分離することから得られます。 各コンポーネントは、そのサイズに関係なく、分母に 1 単位だけ寄与します。 したがって、問題はエッジやカットを直接選択することではなく、どのノードがコンポーネントの「開始」を許可されるか、またコンポーネント数を増やさずにどのノードを既存のノードにアタッチするかを決定することです。 

これは変換を示唆しています。コンポーネントの観点から考える代わりに、各ノードをコンポーネント数への「ルート寄与」として割り当てるか、k を増加させずに既存のコンポーネントの一部として割り当てる観点から考えます。 平均の目標値 x を固定すると、総和から x 倍の成分数を引いた値が負でないような選択が存在するかどうかを尋ねることができます。 これにより、問題は重み付けされた最適化の実現可能性をチェックすることに変換され、ツリー上で線形になります。 

固定 x の場合、各ノードは変更された値 a_u - x を提供します。 目標は、変換された目的を最大化するノードのセットを選択することになります。接続性によって、コンポーネントごとに x の追加のペナルティを支払うかどうかが決まります。 ツリーの構造により、ゲインを上向きに蓄積する貪欲な DP が可能になり、ノードを親の構造内に保持するか、ノードを切断して新しいコンポーネントを開始するかをローカルで決定します。

これは、標準的な「ツリー上のパラメトリック DP」のアイデアにつながります。つまり、最適な平均 x を二分探索し、各 x について、最適なコンポーネント分割でマイナスにならない調整後利益を達成できるかどうかを計算します。 チェック自体は、余剰を上方に伝播するツリー DP であり、有益な場合にのみ新しいコンポーネントを作成するようにします。

 | --- | --- | --- | --- |
 | サブセットとパーティションに対するブルート フォース | O(2^n) | O(n) | 遅すぎる |
 | パラメトリック検索 + ツリー DP 実現可能性チェック | O(n log V) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 コンポーネントごとに可能な最大の平均値を見つけるという目的を再定式化します。 この値 x を二分探索します。 

各候補 x に対して、変換された重み b_u = a_u - x を定義します。 いくつかの連結コンポーネントを形成するノードのセットを選択すると、変換されたスコアは、選択したすべてのノードの sum(b_u) から暗黙的にカウントされたコンポーネントの数を x 倍引いたものになります。 実現可能性の問題は、最適なコンポーネント構成の下でマイナスでないスコアを達成できるかどうかになります。 

任意の場所にルートされた DFS を使用してツリーを処理します。 

1. u がその親コン​​ポーネントに上向きに接続されている場合に、u のサブツリーからその親に渡すことができる最良の余剰を表す DP 値 dp[u] を計算します。 
2. u の子 v ごとに、まず dp[v] を計算します。 dp[v] が正の場合、それを保持して u にマージします。これを付加すると、コンポーネント数を増やすことなく総余剰が改善されるためです。 dp[v] が正でない場合、それを破棄します。これは、その子サブツリーを別個のコンポーネントとして切り取るか、まったく選択しないことに相当します。 
3. 子を集約した後、現在のノードに b_u を追加します。 これは、現在接続されている構造にノード u が含まれていることを表します。 
4. 結果の dp[u] が負になった場合は、それをゼロにリセットし、これをここでカットするものと解釈します。これは、親のコンポーネントに強制的に挿入するのではなく、u で新しいコンポーネントを開始することを意味します。 この削減は、世界的な黒字の足を引っ張ることを避ける方法で部品の数を増やすことに相当する。 
5. ルートを処理した後、dp[root] が負でないことを確認します。 そうであれば、候補 x は実現可能です。 

二分探索は、すべての可能な平均を含むのに十分な範囲にわたって実行され、通常はノードの重みの最小値と最大値の間で実行されます。 

なぜそれが機能するのかは、DP のカット解釈からわかります。 各ノードは、進行中のコンポーネントに貢献するか、含まれると調整された目標が減少する場合に新しいコンポーネントのルートになります。 DP は、より大きな構造を損なうのではなく、すべてのマイナスの影響を個別のコンポーネントに分離することを保証し、分母の最適な制御と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
a = list(map(int, input().split()))
g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

def check(x):
    b = [ai - x for ai in a]

    def dfs(u, p):
        s = b[u]
        for v in g[u]:
            if v == p:
                continue
            child = dfs(v, u)
            if child > 0:
                s += child
        return max(0.0, s)

    return dfs(0, -1) >= 0

lo = min(a)
hi = max(a)

for _ in range(60):
    mid = (lo + hi) / 2
    if check(mid):
        lo = mid
    else:
        hi = mid

print(f"{lo:.10f} 1")
```DFS は、現在の推定値 x によって重みをシフトした後、各サブツリーからどれだけの正の余剰を蓄積できるかを計算します。 重要な実装の詳細は、ゼロを含む最大値であり、コンポーネントの継続が有害になるたびにコンポーネントを切断するという決定をエンコードします。 これは、ネガティブなサブツリーがその親を汚染するのを防ぐものです。 

二分探索では、十分な精度に達するまで候補の平均を絞り込みます。 最適値は成分ごとの比率として表される実数であり、この連続形式で最大平均が実現されることが構造によって保証されているため、最終的な答えは分母 1 の分数として表されます。 

## 実用的な例

 重み 1、2、3 を持つチェーン内の 3 つのノードからなる小さなツリーを考えてみましょう。 

候補 x = 2 をテストします。 

| ノード | b[u] = a[u] - x | 子どもたちの貢献 | クランプ前の dp[u] | | 後の dp[u]
 | --- | --- | --- | --- | --- |
 | 3 | 1 | 0 | 1 | 1 |
 | 2 | 0 + 1 = 1 | 1 | 2 | 2 |
 | 1 | -1 + 2 = 1 | 2 | 3 | 3 |

 ルートは正の値を返すため、x = 2 が可能です。 これは、ポジティブチェーンがどのように余剰を上向きに蓄積するかを示しています。 

ここで、ノード 2 をルートとするスターの重み 1、-5、1 について考えてみましょう。 

| ノード | b[u] (x = 0) | 子供の合計 | dp[u] |
 | --- | --- | --- | --- |
 | 葉 | 1、1 | 0 | 1、1 |
 | ルート | -5 + 1 + 1 | 2 | 2 |

 これは、周囲の構造が補償する場合には、強い負のノードであっても含めることができることを示していますが、一般に、含めることが有益でなくなるしきい値は二分探索によって決定されます。 

これらのトレースは、サブツリーの寄与が有益な場合は上向きに伝播し、負の場合は別のコンポーネントとして吸収される様子を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log V) | 各二分探索ステップでは、ツリーに対して線形 DFS が実行されます。 
| スペース | O(n) | 隣接リストと再帰スタック |

import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    n = int(input())
    a = list(map(int, input().split()))
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    sys.setrecursionlimit(10**7)

    def check(x):
        b = [ai - x for ai in a]

        def dfs(u, p):
            s = b[u]
            for v in g[u]:
                if v == p:
                    continue
                val = dfs(v, u)
                if val > 0:
                    s += val
            return max(0.0, s)

        return dfs(0, -1) >= 0

    lo, hi = min(a), max(a)
    for _ in range(60):
        mid = (lo + hi) / 2
        if check(mid):
            lo = mid
        else:
            hi = mid

    print(f"{lo:.10f} 1")

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    solve()
    return out.getvalue().strip()

 ## 特殊なケース

 単一ノード ツリーは実現可能性チェックの動作を分離します。DP はノードの重みを現在のしきい値と比較することになり、クランプ ステップが誤って処理されると、直ちに正確さが失われます。 

完全に負のツリーでは、アルゴリズムにサブツリーの繰り返し破棄が強制され、最終結果は完全に最大の個々のノードに依存し、負の値が適切に切り取られない場合、グローバル累積ロジックでエラーが発生する可能性があります。
