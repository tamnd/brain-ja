 ## 解決策
 ## 問題の理解

 区切を請求されても当然です。`n`学生をちょうど 3 人のチームに分けます。 一部の学生は、特定の他の学生と同じチームになりたいと明示的に要求します。 これらのリクエストは相互に行われるため、生徒 2 が生徒 5 とチームを組みたい場合、生徒 5 も生徒 2 を望んでいます。私たちの仕事は、そのようなリクエストをすべて尊重する方法で生徒を三つ子に割り当てることです。 それが不可能な場合は、出力する必要があります`-1`。 それ以外の場合は、実際のチームを出力する必要があります。 

入力は次のもので構成されます`n`(3で割り切れます)そして`m`一緒にいたい学生のペア。 出力は次のいずれかです`-1`有効な取り決めが存在しない場合、または`n/3`それぞれがチームを表す 3 つの整数の行。 

制約は小さいです。`n ≤ 48`そして`m ≤ n(n-1)/2`。 これは、およそ次の複雑さを持つアルゴリズムはすべて、`O(n^2)`2秒以内に快適に実行されます。 したがって、大規模なデータセットの最適化を気にせずに、すべての生徒をスキャンしたり、グループを構築したり、チームをシミュレートしたりするアプローチを検討できます。 

主要なエッジケースは、学生が 3 人以上のグループを強制するような矛盾するリクエストを持っている場合に発生します。 たとえば、生徒 1、2、3、4 がすべて同じチームになることを要求した場合 (一連の要求によって)、ちょうど 3 人のチームを形成することは不可能です。 もう 1 つのケースは、一部の生徒が孤立しており、完全なチームを形成するために他の生徒と結合する必要がある場合です。 

## アプローチ

 ブルートフォースアプローチでは、生徒を可能な限り 3 人組のチームに分けて試し、すべての要求が満たされているかどうかを確認します。 このアプローチは理論的には正しいですが、実際には実行できません。 分割方法の数`n`学生を 3 人のグループに分けるのは次のとおりです。`(n!) / ((3!)^(n/3) * (n/3)!)`。 のために`n = 48`、これは天文学的な規模であり、列挙することはできません。 

最適なアプローチでは、リクエストがグラフ内の接続されたコンポーネントを定義していることが観察されます。つまり、各生徒がノードであり、エッジが「一緒にいたい」リクエストを表します。 各接続コンポーネントは、1 つ以上のチームに完全に適合する必要があります。 いずれかのコンポーネントに 3 人以上の生徒がいる場合、リクエストは相互に行われ、尊重する必要があるため、生徒を 3 人のチームに分けることはできません。 サイズ 1 または 2 のコンポーネントを組み合わせてチームを形成できます。 

洞察は、コンポーネントをサイズ別に分類することです。 サイズ 3 のコンポーネントは、すぐに完全なチームを形成します。 サイズ 2 のコンポーネントには、サイズ 1 のコンポーネントからさらに 1 人の生徒が必要です。 サイズ 1 のコンポーネントは 3 つにグループ化してチームを形成できます。 いずれかの時点で数値が一致しない場合、有効な解決策は存在しません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 接続されたコンポーネント + 貪欲なチームの割り当て | O(n^2) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 隣接リストを使用して、学生とそのリクエストを無向グラフとして表します。 各生徒はノードであり、それぞれが双方向エッジを要求します。 これにより、接続されているグループを効率的に見つけることができます。 
2. 深さ優先検索または幅優先検索を使用してグラフを横断し、すべての接続コンポーネントを特定します。 各コンポーネントは、同じチームに所属する必要がある一連の生徒を表します。 各コンポーネントのサイズとその中に生徒のリストを保存します。 
3. いずれかのコンポーネントのサイズが 3 より大きい場合、出力`-1`そして終了します。 このようなコンポーネントは、リクエストを保持しながら正確に 3 つのチームに分割することはできません。 
4. コンポーネントをサイズ 3、サイズ 2、サイズ 1 の 3 つのグループに分類します。サイズ 3 のコンポーネントは完全なチームを形成します。 サイズ 2 のコンポーネントでは、チームを完成させるためにサイズ 1 のグループから 1 人の生徒が必要です。 サイズ 1 のコンポーネントを 3 つ組み合わせて完全なチームを形成できます。 
5. サイズ 1 の生徒の数がサイズ 2 のコンポーネントとペアリングするには十分でない場合、またはペアリング後に 3 で割り切れない場合は、出力`-1`。 
6. この順序でチームを編成します。最初にサイズ 3 のコンポーネントのチーム、次にサイズ 2 の各コンポーネントとサイズ 1 の生徒のペア、最後に残りのサイズ 1 の生徒を 3 人ずつグループに分けます。 
7. すべてのチームを出力します。 各チームには 3 つの学生番号が印刷されています。 

機能する理由: グラフベースの分解により、すべての相互リクエストが尊重されることが保証されます。 3 つを超えるコンポーネントは、単一のチームに収まらないため拒否されます。 サイズ 2 のコンポーネントとサイズ 1 の生徒を貪欲に組み合わせ、残りのサイズ 1 の生徒を 3 つにグループ化することで、すべての生徒が 1 回だけ含まれるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n)]
    
    for _ in range(m):
        a, b = map(int, input().split())
        adj[a-1].append(b-1)
        adj[b-1].append(a-1)

    visited = [False]*n
    components = []

    def dfs(u, comp):
        visited[u] = True
        comp.append(u)
        for v in adj[u]:
            if not visited[v]:
                dfs(v, comp)

    for i in range(n):
        if not visited[i]:
            comp = []
            dfs(i, comp)
            if len(comp) > 3:
                print(-1)
                return
            components.append(comp)

    ones, twos, threes = [], [], []
    for c in components:
        if len(c) == 1:
            ones.append(c[0])
        elif len(c) == 2:
            twos.append(c)
        else:
            threes.append(c)

    if len(ones) < len(twos):
        print(-1)
        return

    teams = []
    for t in threes:
        teams.append(t)
    for i, t in enumerate(twos):
        teams.append(t + [ones[i]])
    remaining_ones = ones[len(twos):]

    if len(remaining_ones) % 3 != 0:
        print(-1)
        return

    for i in range(0, len(remaining_ones), 3):
        teams.append(remaining_ones[i:i+3])

    for team in teams:
        print(' '.join(str(x+1) for x in team))

if __name__ == "__main__":
    main()
```コードはまずグラフを構築し、DFS を使用して連結成分を見つけます。 3 つを超えるコンポーネントはすぐにトリガーされます`-1`。 コンポーネントはサイズごとに分割され、貪欲な方法でチームが構築されます。 慎重にインデックスを作成することで、学生が 1 回だけ割り当てられ、サイズ 2 のすべてのコンポーネントがサイズ 1 の学生で完了することが保証されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | DFS は各エッジを 1 回横断します。 n ≤ 48 なので、O(n^2) 個の隣接性チェックでも問題ありません。 |
 | スペース | O(n + m) | 隣接リストにはエッジが格納されます。 訪問された配列とコンポーネントのリストには n 個の要素が格納されます。 |

 n ≤ 48 および m ≤ n(n-1)/2 の場合、時間とメモリの両方が制限を大幅に下回ります。
