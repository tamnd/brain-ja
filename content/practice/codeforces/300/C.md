 ## 解決策
 ## 問題の理解

 2 つの固定桁が与えられており、その 2 桁のみを使用して長さ n の数値を構築できます。 すべての位置が完全な 10 進数セットではなく 2 要素のアルファベットに制限されているため、そのような数値はすべて第一の意味で「有効」であるとみなされます。 

これらすべての有効な長さ n の数値から、2 番目の条件を使用して再度フィルタリングします。 数値を取得し、その桁を合計する場合、結果として得られる合計自体も、10 進表記でも同じ 2 桁のみを使用する数値でなければなりません。 これらの数字の合計値のみが許可されます。 

このタスクは、2 桁にわたる長さ n のシーケンスがこの桁合計制約を満たす数を数え、1e9 + 7 を法とする数を返すことです。 

n が 10^6 までの制約により、すべての 2^n 文字列の列挙が直ちに除外されます。 最大 9n までの合計によってインデックス付けされた中間 DP 状態を保存する場合でも、扱いが下手な場合は単純な 2D 形式では大きすぎます。 この構造は、唯一意味のある状態は、数字 a と数字 b を使用した回数であることを示唆しています。 

桁の合計が大きい場合、微妙なエッジ ケースが発生します。 たとえば、a = 1、b = 9、n = 10^6 の場合、合計は最大 900 万の範囲になります。 各合計を個別に明示的に反復またはチェックしようとするアプローチは、問題を組み合わせカウント式に落とし込まない限り失敗します。 

もう 1 つの問題は先行ゼロですが、a と b は 1 から 9 までの範囲にあるため、ここでは問題になりません。したがって、構築されたすべての数値は当然有効です。 

## アプローチ

 ブルートフォース手法では、長さ n のすべての数字シーケンス {a, b} を生成し、その数字の合計を計算し、その合計が数字 a と b のみで構成されているかどうかを確認します。 これにはすでに 2^n シーケンスが必要ですが、n = 30 程度を超えると不可能になります。 

明示的な生成を避け、代わりに数字 a を選択する回数を反復したとしても、まだ n + 1 個の可能性があります。 選択ごとに、合計 s = i・a + (n−i)・b を計算し、s が桁の意味で「適切な」数値であるかどうかを検証します。 検証自体のコストは O(log s) です。 これにより O(n log n) が得られ、n = 10^6 の場合はかろうじて合格する可能性がありますが、これはチェックが非常に最適化されている場合に限ります。 ただし、これにはさらに深刻な問題が隠されています。同じ合計構造を繰り返し再チェックしているということです。 

重要な観察は、数値が桁 a の数によって完全に決定されるということです。 a の i 回の出現を選択すると、残りは b になるため、桁の合計は i で線形になります。 問題は次のようになります。[0, n] 内の i の数を数えると、10 進数が {a, b} にある合計が生成されます。 

これにより、問題は n+1 個の値の反復、一次式の計算、および数字のプロパティのチェックに変換されます。 n は 10^6 にできるため、操作を単純にし、大量の割り当てを避ける場合、これは Python では許容されます。 

実際の最適化は、各構成が C(n, i) で数えられる数字 a の位置の 1 つの選択に正確に対応するため、二項係数を超える組み合わせ論が必要ないことです。 したがって、答えは有効な i 値の加重合計になります。

 | --- | --- | --- | --- |
 | ブルート フォース (文字列を生成) | O(2^n) | O(n) | 遅すぎる |
 | 組み合わせでカウントし、i をスキャンします。 O(n log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 数字の中に数字 a が何回現れるかを修正します。 i 回出現する場合、数字 b は n − i 回出現します。 a の位置のみを選択するため、そのような文字列の数は正確に C(n, i) になります。 
2. この構成の桁合計を s = i・a + (n − i)・b として計算します。 これにより、文字列全体が 1 つの線形式に縮小されます。 
3. s が「適切な数」であるかどうかを確認します。つまり、s のすべての桁が a または b である必要があります。 これは、基数 10 の数字を繰り返し抽出し、{a, b} のメンバーシップを検証することによって行われます。 いずれかの数字がこのセットに違反すると、設定は破棄されます。 
4. s が有効な場合、答えのモジュロ 1e9 + 7 に C(n, i) を追加します。 
5. n までの階乗および逆階乗を事前計算して、O(1) の二項係数を計算します。 n は最大 10^6 であるため、これが必要です。 

なぜ効果があるのか

 長さ n の有効な数値はすべて、数字 a が出現する位置のセットによって一意に決定されます。 これにより、文字列と i の値と位置の選択との組み合わせの間で全単射が作成されます。 このアルゴリズムは、解空間全体を i でインデックス付けされた互いに素なサブセットに分割します。 各サブセットは C(n, i) によって正確にカウントされ、各サブセットはその桁の合計のみに基づいて完全に受け入れられるか拒否されるため、構成が見逃されたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def is_good(x, a, b):
    while x > 0:
        d = x % 10
        if d != a and d != b:
            return False
        x //= 10
    return True

n_a, n_b, n = map(int, input().split())

a, b = n_a, n_b

max_n = n

fact = [1] * (max_n + 1)
for i in range(1, max_n + 1):
    fact[i] = fact[i - 1] * i % MOD

invfact = [1] * (max_n + 1)
invfact[max_n] = pow(fact[max_n], MOD - 2, MOD)
for i in range(max_n, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def C(n, k):
    if k < 0 or k > n:
        return 0
    return fact[n] * invfact[k] % MOD * invfact[n - k] % MOD

ans = 0

for i in range(n + 1):
    s = i * a + (n - i) * b
    if is_good(s, a, b):
        ans = (ans + C(n, i)) % MOD

print(ans)
```階乗および逆階乗事前計算により、各二項係数を一定時間で計算できます。 i に対するループは、文字列内の数字 a の可能な分布をすべて列挙します。 機能`is_good`合計の桁ごとの検証を実行します。 

微妙な点は、実際の数値文字列を決して構築しないことです。 桁 a の数のみが重要なので、メモリ使用量は一定に保たれます。

 ## 特殊なケース

 合計のすべての桁が、許可されている桁の 1 つと一致する場合は、特殊なケースが発生します。 たとえば、a = 1 および b = 1 が制約により無効である場合、概念的には、111 または 1111 のような合計は常に数字フィルターを即座に通過し、アルゴリズムには対応するすべての二項選択肢が正しく含まれます。 

もう 1 つのケースは、桁の合計が 0 の場合です。これは両方の桁が 0 の場合にのみ発生しますが、問題では 0 が許可されていないため、これがトリガーされることはありません。 実装では引き続き安全に処理されます。`is_good(0, a, b)`有効な入力では決して到達しませんが、空虚な正しさによって True を返します。 

より意味のあるエッジ ケースは、1 と 9 のように、a と b が大きく離れている場合です。多くの合計には 2、3、4、5、6、7、8 などの中間数字が含まれるため、ほぼすべての構成が拒否されます。 ループは引き続きすべての i 値を正しく処理し、まれな有効なケースのみを蓄積します。
