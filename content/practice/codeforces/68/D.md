 ## 解決策
 ## 問題の理解

 高さの完全な二分木があります`h`。 すべての頂点にはある程度の数の電子が格納される可能性があり、クエリによって頂点に徐々に電子が追加されます。 

あ`decay`この操作では、1 つのリーフを均一にランダムに選択し、ルートからそのリーフまでのパス上のすべてのエッジを削除します。 頂点自体は残り、エッジだけが消えます。 これらのエッジを削除すると、ツリーはいくつかの接続されたコンポーネントに分割されます。 

各連結成分について、その内部の電子の合計を計算します。 この減衰の可能性は、すべての接続コンポーネント間の最大コンポーネント合計です。 あらゆる人にとって`decay`クエリでは、すべてのリーフにわたるこの最大値の期待値を出力する必要があります。 

ツリーは構造的には静的ですが、頂点の重みは時間の経過とともに変化します。 

ここでの本当の課題は制約です。 高さはせいぜい`30`したがって、頂点の総数は次のようになります。`2^31 - 1`、明示的に保存することは不可能です。 同時に、最大`10^5`したがって、各クエリはほぼ対数時間で処理する必要があります。 すべてのリーフまたはすべての頂点を反復するソリューションは、リーフの数だけで約 10 億に達する可能性があるため、すぐに失敗します。 

更新がまばらであることが重要です。 概念ツリーは巨大ですが、更新で言及されている頂点のみが重要です。 せいぜい`10^5`頂点はゼロ以外の重みを受け取ります。 

見落としやすいエッジケースがいくつかあります。 

すべての電子が根に集中していると仮定します。```
h = 2
add 1 100
decay
```崩壊するたびに根から葉への経路が 1 つ削除されますが、根は分離され、依然としてすべての経路が含まれています。`100`電子。 答えはいつも`100`。 不注意な解決策を使用すると、1 つのパス上のすべての出力エッジが削除されるため、ルート コンポーネントが消失すると誤って認識する可能性があります。 

重いサブツリーがそのまま残っている場合には、別の微妙なケースが現れます。```
h = 2
add 4 50
add 5 60
decay
```削除されたパスが右側のサブツリーを通過する場合、左側のサブツリー全体が接続されたままになり、`110`。 削除されたパスが左側のサブツリーを通過する場合、生き残るコンポーネントは小さくなります。 最大コンポーネントはどちらの側が破壊されたかによって異なります。 

3 番目の罠は、コンポーネント間の結びつきです。 考慮する：```
h = 1
add 2 10
add 3 10
decay
```ポテンシャルは常にある`10`、 ない`20`。 削除されたエッジにより 1 つの子がルートから切り離されるため、2 つのリーフが同時に接続されたままになることはありません。 生き残ったサブツリーの重みを単純に合計する解決策では、過剰にカウントされてしまいます。 

## アプローチ

 ブルートフォース解釈は簡単です。 あらゆる人にとって`decay`クエリ、すべて列挙`2^h`葉。 各リーフについて、対応するルートからリーフへのパスを削除し、連結成分を計算し、成分の最大合計を見つけて、すべてのリーフの平均を計算します。 

減衰後のツリー構造は選択した葉によって完全に決定されるため、これは概念的に機能します。 問題は規模だ。 たとえ`h = 30`、葉の数は10億以上あります。 それぞれのコンポーネントを再計算するのは絶望的です。 

次の改善は、パスを削除した後に接続されたコンポーネントが実際にどのように見えるかを観察することです。 

葉っぱを摘み取ります。 選択したルートから葉へのパス上のすべての頂点は、パス上の子から切断されますが、それらの各頂点はサブツリーを兄弟側からぶら下げたままにしておきます。 

パスの場合:```
root -> left -> right -> ...
```結果として得られるコンポーネントは次のとおりです。 

1. パス上の単一の頂点。削除されたエッジまで上向きにのみ接続されます。 
2. パスから分岐している未処理の兄弟サブツリー全体。 

重要な点は、すべてのコンポーネントが次のいずれかに対応しているということです。 

1. パス頂点の兄弟をルートとするサブツリー。 
2. 選択したパス自体のプレフィックス。 

これにより、問題はサブツリーの合計を維持し、対数の候補の中から最大値を求めることに変換されます。 

ここで決定的な洞察が得られます。 

固定リーフの場合、次のように定義します。 

-`sub[v]`サブツリー内の総重量として`v`。 
-`path_prefix`選択した根から葉へのパスに沿ったある深さまでの重みの合計として。 

パス上のエッジが削除されると、パス頂点を含むコンポーネントは、パス頂点の連続するプレフィックスのみで構成されます。 パス外のサブツリーはすべて完全にそのまま残ります。 

したがって、1 枚の葉の答えは次のようになります。```
max(
    every sibling subtree attached to the path,
    every prefix sum of the path
)
```あるのは`O(h)`そんな候補者たち。 

しかし、まだすべての葉を反復処理することはできません。 

同じプレフィックスを共有するリーフの構造が重要になります。 ノードに立ったら`v`、その後:

 - 左側のサブツリー内のすべてのリーフは同様に動作します。 
- 右側のサブツリー内のすべてのリーフは同様に動作します。 

これは、ツリー上の DP を分割して征服することを示唆しています。 祖先からこれまでに蓄積された最大コンポーネント値を保持しながら、各サブツリーの下の葉の期待される答えを再帰的に計算します。 

更新された頂点のみが重要であるため、タッチされたノードとその祖先に関する情報のみが保存されます。 このようなノードの総数は次のとおりです。`O(qh)`。 

最終的なソリューションは、各クエリを次のように処理します。`O(h^2)`十分に速い時間です`10^5`クエリ。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 減衰ごとに O(2^h * h) | O(h) | 遅すぎる |
 | 最適 | クエリごとに O(h^2) | O(qh) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 更新を受信した頂点のみの電子数を保存します。 

ツリーは概念的には巨大ですが、答えに影響を与えることができるのは、更新された頂点とその祖先だけです。 
2. サブツリーの合計を維持する`sub[v]`。 

追加する場合`e`電子が頂点へ`v`、根元に向かって上向きに歩き、追加します`e`すべての祖先のサブツリーの合計に。 

これは、すべての祖先サブツリーに次のものが含まれるため機能します。`v`。 
3. 減衰クエリの場合、予想される可能性を再帰的に評価します。 

再帰は、ランダムなリーフの選択を表します。 
4. 各ノードで`v`、次の 2 つの値を維持します。 

-`up`、現在のルートからルートへの合計の重み`v`パスコンポーネント。 
-`best`、現在のサブツリーの外側ですでに保証されている最大のコンポーネント。 
5. もし`v`葉である場合、朽ちる経路はここで終わります。 

この葉の可能性は次のようになります。```
max(best, up)
```パス コンポーネント自体が、生き残る最大のコンポーネントである可能性があるためです。 
6. それ以外の場合は、左右の子に分岐します。 

左の子を再帰するとします。 

- 右のサブツリー全体がそのまま残ります。 
- その成分の合計は`sub[right]`。 

したがって、新しい累積最大値は次のようになります。```
max(best, sub[right])
```パス コンポーネントは現在のノードの重みを取得します。 
7. 両方の子の結果を平均します。 

すべての葉の可能性は等しく、ツリーは完全であるため、各サブツリーには親の葉のちょうど半分が含まれます。 
8. メモ化は不要です。 

各減衰クエリの訪問のみ`O(h)`再帰的分岐に沿った状態、および`h ≤ 30`。 

### なぜ効果があるのか

 削除されたすべてのエッジは、ルートからリーフへの 1 つのパス上にあります。 存続する接続コンポーネントは次のいずれかを行う必要があります。 

- そのパスから分岐した兄弟サブツリー内に完全に留まる、または
 - パス自体上の頂点の接続されたプレフィックスで構成されます。 

再帰はこれらの可能性を正確に追跡します。`best`これまでに見つかった最大の無傷の兄弟サブツリーを格納します。`up`現在接続されているパスコンポーネントを保存します。 リーフに到達すると、これらのカテゴリの外に他のコンポーネントは存在できないため、それらの最大値がそのリーフの真の可能性になります。 

各内部ノードが 2 つの子の間でリーフを均等に分割するため、再帰的なブランチの平均化はリーフの一様分布と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    h, q = map(int, input().split())

    val = defaultdict(int)
    sub = defaultdict(int)

    sys.setrecursionlimit(1 << 20)

    def dfs(v, depth, up, best):
        up += val[v]

        if depth == h:
            return float(max(up, best))

        left = v * 2
        right = v * 2 + 1

        left_best = max(best, sub[right])
        right_best = max(best, sub[left])

        a = dfs(left, depth + 1, up, left_best)
        b = dfs(right, depth + 1, up, right_best)

        return (a + b) * 0.5

    out = []

    for _ in range(q):
        parts = input().split()

        if parts[0] == "add":
            v = int(parts[1])
            e = int(parts[2])

            val[v] += e

            cur = v
            while cur:
                sub[cur] += e
                cur //= 2

        else:
            ans = dfs(1, 0, 0, 0)
            out.append(f"{ans:.10f}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は再帰的解釈に直接従います。`val[v]`電子を頂点に正確に配置して保管します`v`。`sub[v]`をルートとするサブツリーの合計を格納します`v`。 

最中`add`クエリでは、更新された頂点からルートまで上向きに歩きます。 樹高はせいぜいですので、`30`、これには無視できる時間がかかります。 

再帰関数`dfs`ランダムな減衰プロセスをモデル化します。`up`は、選択されたパスの生き残ったプレフィックスによって形成される接続コンポーネントを表します。 現在のノードはその上のプレフィックスに接続されたままであるため、各再帰ステップによって現在のノードの重みが追加されます。 

左側の子に降りる場合、選択したパス上のエッジを削除した後、右側のサブツリーが完全に分離されます。 その合計貢献度はまさに`sub[right]`, したがって、それは全体的な最大値の候補になります。 

同じロジックが右側の子にも対称的に適用されます。 

よくある実装上の間違いは、サブツリー コンポーネントが完全にそのまま残っていることを忘れることです。 各深さで削除されるエッジは 1 つだけであるため、サブツリーの合計から部分的に減算することはありません。 

もう 1 つの微妙な点は、葉の処理です。 深さで`h`、パスは終了しているため、残っている候補は次のとおりです。 

- 蓄積されたパスコンポーネント、
 - 前に見た最良の分離サブツリー。 

これ以上の分岐は存在しません。 

考えられる最悪の合計はおよそ以下であるため、すべての合計は Python 整数内に安全に収まります。`10^5 * 10^4 = 10^9`。

## 特殊なケース

 根だけが電子を持っている場合を考えてみましょう。```
2 2
add 1 100
decay
```減衰するたびに下向きのパスが 1 つ削除されますが、ルート自体は電荷を持った孤立したコンポーネントとして存在し続けます。`100`。 

再帰は次から始まります`up = 0`。 ルートで:

 -`up`になる`100`。 
- すべての兄弟サブツリーの合計は`0`。 

すべての再帰的なブランチは次の条件を備えたリーフに到達します。 

-`up = 100`-`best = 0`アルゴリズムの出力`100`。 

次に、切断された等しい葉を調べます。```
1 3
add 2 10
add 3 10
decay
```選択した葉が`2`、右のサブツリーは合計で存続します`10`、パス コンポーネントには頂点のみが含まれます。`2`合計付き`10`。 

最大値は`10`、 ない`20`。 

再帰は以下を正確に追跡します。 

-`best = 10`-`up = 10`そしてその最大値を返します。 

最後に、深く存続するサブツリーを考えてみましょう。```
2 3
add 4 50
add 5 60
decay
```選択した葉がツリーの右半分にある場合、左のサブツリー全体が合計でそのまま残ります。`110`。 

正しい子セットへの再帰的遷移は次のようになります。```
best = sub[left] = 110
```その値はリーフに伝播され、それらのブランチの最終的な答えになります。 まさにこれが、サブツリーの合計をローカルで再計算するのではなく、明示的に維持する必要がある理由です。
