 ## 解決策
 ## 問題の理解

 いくつかのアキュムレータがあり、それぞれがある程度のエネルギーを蓄えています。 それらの間でエネルギーを移動することはできますが、移動ごとに一定の割合が無駄になります。 私たちが送ったら`x`1 つのアキュムレータからユニットを取得した場合、送信者はすべてを失います`x`、一方、受信者は利益のみを得る`x * (100 - k) / 100`。 

目標は、すべてのアキュムレータに最終的に同じ量のエネルギーが含まれるようにすることであり、その共通の値をできるだけ大きくしたいと考えています。 

入力により、アキュムレータの数、転送中の損失パーセンテージ、および初期エネルギー値が得られます。 出力は、一連の転送後に達成可能な最大の等エネルギー レベルです。 

制約は十分に小さいため、配列全体を繰り返しスキャンできます。 多くても`10^4`アキュムレータ、および各値は最大で`1000`。 すべてのペアにわたる二次シミュレーションは、特に浮動小数点精度が関係する場合、何度も繰り返すと依然として危険になります。 解決策`O(n log precision)`2秒以内であれば完全に安全です。 

難しいのは、エネルギーは保存されないということです。 転送ごとにある程度の量が破壊されます。 不注意な解決策はすべての値を直接平均する可能性がありますが、それは次の場合にのみ機能します。`k = 0`。 

次の例を考えてみましょう。```
2 50
10 0
```平均は`5`ただし、両方のアキュムレータを次と等しくすることはできません。`5`。 空のアキュムレータを与えるには`5`、送らなければなりません`10`、半分が失われるからです。 すると、最初のアキュムレータは次のようになります。`0`。 達成可能な最良の答えは、`10 / (1 + 2) = 3.333...`、 ない`5`。 

もう 1 つの微妙なケースは、すべてのアキュムレータがすでに同じ値を持っている場合です。```
4 30
7 7 7 7
```答えはまさに`7`。 移動が不要なため、エネルギーが失われません。 転送が発生することを常に前提とするソリューションでは、答えが誤って減少する可能性があります。 

もう 1 つの危険なケースは、高い損失率です。```
3 99
100 0 0
```のみ`1%`転送されたエネルギーの一部は残ります。 エネルギーのほとんどは再分配中に消滅するため、答えは非常に小さくなります。 ここでは、整数演算や精度が不十分な場合、誤った結果が簡単に生成される可能性があります。 

## アプローチ

 問題を考える強引な方法は、目標値を推測することです`T`、次にアキュムレータ間の転送を明示的にシミュレートします。 上記のアキュムレータ`T`ドナーとして機能し、以下のアキュムレーターとして機能します`T`受信機として機能します。 

アキュムレータが`a[i] > T`。 それは与えることができます`a[i] - T`単位。 転送ではエネルギーが失われるため、他の転送に寄与する実際の有効量は次のとおりです。```
(a[i] - T) * (100 - k) / 100
```もし`a[i] < T`、その場合は正確に必要です`T - a[i]`単位。 

使用可能な寄付されたエネルギーの合計が少なくとも必要なエネルギーの合計である場合、`T`達成可能です。 

ブルートフォースの難しさは、可能な限り最大限のことを探すことから生まれます。`T`。 整数ではなく実数を扱っているため、すべての候補をチェックすることは不可能です。 多くの離散値を試しても、正しい答えが非合理的である可能性があるため、失敗します。 

重要な観察は単調性です。 

何らかの目標値があれば`T`が達成可能であれば、さらに小さな目標も達成可能です。 いつでも転送を早期に停止することができます。 一方、次の場合は、`T`は不可能であり、それより大きな値もすべて不可能です。 

これにより、問題は答えに対する古典的な二分探索に変わります。 

候補者にとって`mid`、次のように計算します。```
extra = total usable energy from donors
need = total missing energy from receivers
```もし`extra >= need`、 それから`mid`は実現可能なので、より大きな値を試してみます。 それ以外の場合は、より小さい値を試します。 

各実現可能性チェックは直線的です`n`優れた浮動小数点精度を得るには、二分探索には約 100 回の反復が必要です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 連続値以上は不可能 | お(1) | 実用的ではない |
 | 最適 | O(n 対数精度) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. アキュムレータの数を読み取ります。`n`、損失率`k`、および配列`a`。 
2. 二分探索範囲を設定します。 

最低限考えられる答えは、`0`。 考えられる最大の答えは、`max(a)`なぜなら、アキュムレータは最大の初期値を超えるエネルギーを最終的に得ることができないからです。 
3. 目標値に対して二分探索を繰り返す`mid`。 

約 100 回の反復を実行しますが、これで十分です。`1e-6`精度。 
4. 各アキュムレータについて:

 もし`a[i] > mid`、損失後に貢献できる有用なエネルギーの量を計算します。```
(a[i] - mid) * (100 - k) / 100
```これを追加`extra`。 
5. もし`a[i] < mid`、必要なエネルギーを計算します。```
mid - a[i]
```これを追加`need`。 
6. すべてのアキュムレータを処理した後、比較します。`extra`そして`need`。 

もし`extra >= need`、 それから`mid`は達成可能なので、左側の境界を上に移動します。 

それ以外の場合は、右側の境界を下に移動します。 
7. 二分探索が終了したら、左側の境界を出力します。 

### なぜ効果があるのか

 固定ターゲットの場合`T`、上記のすべてのアキュムレータ`T`自分自身を安全に次のように減らすことができます`T`。 伝達損失により、除去されたエネルギーの一部のみが他の場所で使用可能になります。 以下のすべてのアキュムレータ`T`正確に必要です`T - a[i]`使えるエネルギー。 

使用可能な寄付されたエネルギーの合計が不足分をすべてカバーする場合、エネルギーを再分配して達成することができます。`T`。 そうしないと、残存する移動可能なエネルギーの合計が不十分になるため、再分配戦略は成功しません。 

実現可能条件は単調である。 ターゲットが小さいほど必要なエネルギーは常に少なくなりますが、ターゲットが大きいほど必要なエネルギーは多くなります。 二分探索は、実行可能な最大のターゲットを正確に見つけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

loss_factor = (100 - k) / 100.0

left = 0.0
right = max(a)

for _ in range(100):
    mid = (left + right) / 2.0

    extra = 0.0
    need = 0.0

    for x in a:
        if x > mid:
            extra += (x - mid) * loss_factor
        else:
            need += mid - x

    if extra >= need:
        left = mid
    else:
        right = mid

print(f"{left:.9f}")
```二分探索は、答えが必ずしも整数であるとは限らないため、浮動小数点値に直接作用します。 

変数`loss_factor`は、伝達後に生き残るエネルギーの割合を表します。 事前に計算しておくと、ループ内で同じ除算を繰り返すことがなくなります。 

実現可能性チェックでは、アキュムレータをドナーとレシーバに分離します。 ドナーは損失により減少したエネルギーを提供しますが、レシーバーは不足分の全額を必要とします。 

比較には、`extra >= need`。 正確な実現可能性によっても答えは上方に移動するはずであるため、平等性が重要です。 

ループは、間隔のサイズに関係なく、100 回の反復を実行します。 これは、浮動小数点二分探索のための一般的な競技プログラミング手法です。 反復ごとに間隔が半分になるため、100 ラウンドでは必要な精度よりもはるかに高い精度が得られます。 

小数点以下 9 桁で印刷すると、次の条件が安全に満たされます。`1e-6`エラー要件。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    loss_factor = (100 - k) / 100.0

    left = 0.0
    right = max(a)

    for _ in range(100):
        mid = (left + right) / 2.0

        extra = 0.0
        need = 0.0

        for x in a:
            if x > mid:
                extra += (x - mid) * loss_factor
            else:
                need += mid - x

        if extra >= need:
            left = mid
        else:
            right = mid

    print(f"{left:.9f}")

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

# provided sample
assert run("3 50\n4 2 1\n") == "2.000000000", "sample 1"

# minimum size
assert run("1 30\n7\n") == "7.000000000", "single accumulator"

# all equal
assert run("4 80\n5 5 5 5\n") == "5.000000000", "already balanced"

# no transfer loss
res = float(run("2 0\n10 0\n"))
assert abs(res - 5.0) < 1e-6, "average when k = 0"

# extreme transfer loss
res = float(run("2 99\n100 0\n"))
assert abs(res - 0.9900990099) < 1e-6, "high loss percentage"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 30 / 7`|`7`| 単一のアキュムレータは転送を必要としません。 
|`4 80 / 5 5 5 5`|`5`| すでにバランスの取れた構成 |
 |`2 0 / 10 0`|`5`| ゼロ損失は通常の平均化に減少します。 
|`2 99 / 100 0`|`0.990099...`| 重大な転送損失の正しい対処方法 |

 ## 特殊なケース

 転送損失により平均化が不可能になる場合を考えてみましょう。```
2 50
10 0
```アルゴリズムがチェックするとします。`mid = 5`。 

最初のアキュムレーターは以下を寄付できます。```
(10 - 5) * 0.5 = 2.5
```2 番目のアキュムレータには次のものが必要です。```
5 - 0 = 5
```以来`2.5 < 5`、目標は不可能です。 二分探索は下方向に移動します。 最終的には約に収束します`3.333333333`。 

これは、転送によってエネルギーが破壊されると、生の平均化が失敗する理由を示しています。 

ここで、すでにバランスのとれたセットアップを考えてみましょう。```
4 30
7 7 7 7
```のために`mid = 7`:

 | アキュムレータ | 貢献 | 必要 |
 | --- | --- | --- |
 | 7 | 0 | 0 |
 | 7 | 0 | 0 |
 | 7 | 0 | 0 |
 | 7 | 0 | 0 |

 両方の合計はゼロのままであるため、目標は実現可能です。 

アルゴリズムは、転送が必要ないこと、つまりエネルギーが失われないことを正しく認識します。 

最後に、非常に大きな損失を考慮します。```
3 99
100 0 0
```テストしたら`mid = 1`:

 寄付者は以下のことに貢献します。```
(100 - 1) * 0.01 = 0.99
```受信者には以下が必要です。```
1 + 1 = 2
```ターゲットはすぐに失敗します。 

二分探索は、実行可能な値がおおよそになるまで縮小し続けます。`0.4975`。 

このケースでは、移動可能なエネルギーと需要を比較する前に、アルゴリズムが損失係数を正しく適用していることが確認されています。
