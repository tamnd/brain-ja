 ## 解決策
 ## 問題の理解

 頂点に有向非巡回グラフがあります`1...n`。 すべてのペアについて`i < j`、からの有向エッジが 1 つだけ存在します。`i`に`j`。 

各パイプには 3 つのパラメータがあります。 間を運ばなければなりません`l`そして`h`そのパイプを使用したくない場合でも、流量の単位を含みます。 パイプを通る実際の流量が正の場合、アクティベーションコストを支払います`a`流れの二乗を加えます。 フローがゼロの場合、支払いはありません。 

燃料がノードに入る`1`そしてノードを経由して出発します`n`。 すべての中間ノードはフローを保存する必要があり、受信と送信が同じになります。 すべてのフローは整数です。 

実行可能なすべてのフロー割り当ての中で、まずノードに到達する総量を最小限に抑えたいと考えます。`n`。 最小の合計フローを持つすべてのソリューションの中で、可能な限り最大の総コストが必要です。 

グラフが小さいですね。`n ≤ 6`なので、エッジの数は最大で`15`。 すべてのエッジ容量は最大でも`5`。 これにより、問題の性質が完全に変わります。 私たちは洗練された多項式最適化アルゴリズムを求めているわけではありません。 検索スペースは十分に小さいため、エッジ フローに対するブルート フォースが現実的になります。 

それでも、すべての割り当てに対する素朴な強引な力は大きすぎます。 すべてのエッジは値を取ることができます`0...5`, したがって、最悪の場合、`6^15 ≈ 4.7e11`課題。 積極的な剪定を行っても、それは絶望的です。 

小さな容量が本当の鍵です。 ネットワークを通過するフローの総量が大きくなることはありません。 ノードから出るのはエッジだけなので`1`フローを作成し、そのような各エッジには最大でも容量があります`5`、グラフ全体への合計フローは最大で`5 * (n-1) ≤ 25`。 

つまり、独立したエッジの選択ではなく、ノードのバランスという観点から考えることができるということです。 

いくつかの微妙なエッジケースがあります。 

1 つ目は、非アクティブなエッジにも下限が適用されることです。 考慮する：```
3
1 2 0 2 0
2 3 3 5 0
1 3 0 5 0
```角`2 -> 3`少なくとも携帯しなければならない`3`、ノード`2`少なくとも受け取らなければなりません`3`。 でもエッジ`1 -> 2`せいぜい持ち運べる`2`。 正しい答えは次のとおりです。```
-1 -1
```使用されているエッジの容量のみをチェックする不注意な実装では、ネットワークが誤って受け入れられてしまいます。 

もう 1 つのトラップは、ゼロフロー ソリューションです。 例：```
2
1 2 0 5 3
```唯一のエッジを介してゼロユニットを送信する場合があります。 エッジは非アクティブであるため、コストもゼロです。 正しい出力は次のとおりです。```
0 0
```エッジが存在するたびに常にアクティベーションコストを追加すると、間違った答えが得られます。 

コスト関数も非直観的に動作します。 二乗和を最大化するので、複数のエッジにフローを分割すると、アクティブ化された各エッジが独自のアクティブ化ボーナスに寄与するため、合計が増加する可能性があります。 例：```
4
1 2 0 2 5
1 3 0 2 5
1 4 0 2 0
2 3 0 2 5
2 4 0 2 5
3 4 0 2 5
```実現可能な最小総流量が次のようになると仮定します。`2`。 両方のユニットを 1 つのパスに沿って送信すると、ユニットを異なるパスに分割するよりもアクティブ化されるエッジが少なくなります。 最適な答えは、可能な限りより多くのエッジをアクティブにすることを好みます。 

最後の微妙な点は、下限により DAG 内で循環のような動作が強制される可能性があることです。 グラフは小さい頂点から大きい頂点へのみ移行するため、サイクルは不可能ですが、出力の下限があるため、中間の頂点で強制的に強制的なフローを中継することができます。 

## アプローチ

 最も直接的な強引な方法は、すべてのエッジに個別に値を割り当てることです。 各エッジについて、間のすべての整数フローを試します。`0`そして`h`、下限またはフロー保存に違反する割り当てを拒否し、合計フローとコストを計算します。 

これは正しいです。すべての実行可能なソリューションがエッジ値の 1 つの割り当てに正確に対応するからです。 

問題は探索空間のサイズです。 と`15`エッジと`6`エッジごとの選択肢は大まかに得られます`4.7e11`州。 たとえ各状態が 1 つの CPU 命令を必要としたとしても、それは依然として不可能です。 

グラフの構造は、問題についてより適切に考える方法を与えてくれます。 

を除くすべての頂点について`1`そして`n`, 流入流量がわかれば、流量保存は総流出流量を決定します。 容量が小さいため、ノードに入る総量も小さいです。 

これは、頂点とバランスに対する動的プログラミングを示唆しています。 

頂点を左から右に処理します。 頂点に到達すると`v`、すべての入力エッジ`v`小さな頂点からのものであるため、すでに固定されています。 それらの合計により、流出するフローの量が正確に決定されます。`v`。 

あとは、必要な量をエッジ間で分配するだけです。`v -> u`どこ`u > v`、下限と上限を尊重します。 

可能な分布の数は少ないです。 頂点には最大でも`5`発信エッジと各エッジは最大でも伝送します`5`。 合計の流出フローは最大でも`25`。 すべての分布を列挙することが可能になります。 

重要な観察は、頂点を順番に処理すると、その後の決定によって、すでに処理された頂点のバランスが変更される可能性がないということです。 これにより、グローバルな実現可能性の問題がローカルな移行の問題に変わります。 

将来の各頂点がこれまでに蓄積した流入フローの量を説明する DP 状態を保持します。 頂点処理時`v`、私たちは州からの現在の流入額を知っています。 すべての有効な送信割り当てを列挙し、将来の残高を更新します。 

状態空間の合計は管理可能なままです。`5`将来の頂点と各バランスは最大で`25`。

 ## アルゴリズムのチュートリアル

 1. すべてのエッジを読み取り、その下限を保存します`l`、上限`h`、およびアクティベーションコスト`a`。 
2. 頂点の処理後に DP 状態を定義します`1...v-1`。 

将来の頂点ごとに状態が保存されます`u ≥ v`、すでに割り当てられている受信フローの量`u`。 

エッジは前方にのみ進むため、将来の決定によって以前の頂点のバランスを変更することはできません。 
3. 頂点を処理する前に、すべてのバランスをゼロに等しい状態から開始します。 
4. 頂点処理時`v`、そこから出なければならない流れの量を決定します。 

のために`v = 1`、ノードが存在するため、この量は無制限です。`1`がソースです。 その出力合計は、私たちが割り当てたものになります。 

中間頂点の場合、出力フローは、その状態の頂点に対してすでに蓄積されている入力フローと等しくなければなりません。 
5. 発信エッジに対して可能なすべての割り当てを列挙します。`v -> u`。 

各エッジ フローは次の場所に存在する必要があります`[l, h]`。 

中間頂点の場合、割り当てられた出力フローの合計は、必要な出力量と等しくなければなりません。 

頂点の場合`1`、ソースであるため、任意の合計が許可されます。 
6. 割り当てごとに、次を計算します。 

- 追加コスト、
 - 追加の流入フローが将来の頂点に寄与しました。 
- 最終的にノードに到達する合計フロー`n`。 
7. 次の頂点の DP 状態を更新します。 

2 つの方法が同じ最終合計フローで同じ状態に到達する場合は、より大きなコストを維持します。 
8. すべての頂点を処理した後、ノードが存在する状態を調べます。`n`ある程度の流れが蓄積されています。 

ノードに入る金額`n`まさにシンクロフェーソトロンに届けられる合計です。 
9. 実現可能な最小の総流量を選択します。 その中から最大のコストを選択します。 

### なぜ効果があるのか

 不変条件は、頂点を処理した後です。`1...v-1`、DP 状態は、すでに頂点に強制されているすべてのフローを正確に記録します。`v...n`。 

グラフは非循環であり、エッジは常に前方に進むため、将来の決定によって処理された頂点のバランスが変更されることはありません。 実行可能なすべてのグローバル フローは、DP 中のローカル発信割り当ての 1 つのシーケンスに対応し、DP によって生成されたすべてのシーケンスはすべての保存と容量の制約を満たします。 

DP は、すべての頂点における発信フローのすべての実現可能な分布を調査します。 遷移では正確なバランスと容量が維持されるため、無効なソリューションは残りません。 すべての有効な解は頂点ごとに再構築できるため、実行可能な解が失われることはありません。 

## Python ソリューション```python
import sys
from collections import defaultdict
from itertools import product

input = sys.stdin.readline

def solve():
    n = int(input())

    l = [[0] * n for _ in range(n)]
    h = [[0] * n for _ in range(n)]
    a = [[0] * n for _ in range(n)]

    for _ in range(n * (n - 1) // 2):
        s, f, lo, hi, cost = map(int, input().split())
        s -= 1
        f -= 1

        l[s][f] = lo
        h[s][f] = hi
        a[s][f] = cost

    # state:
    # tuple of accumulated incoming flow for every vertex
    # dp[state] = maximum cost

    start = tuple([0] * n)
    dp = {start: 0}

    for v in range(n - 1):
        ndp = dict()

        targets = list(range(v + 1, n))

        ranges = [range(l[v][u], h[v][u] + 1) for u in targets]

        for state, cur_cost in dp.items():

            required = state[v]

            for flows in product(*ranges):

                total_out = sum(flows)

                # conservation for intermediate vertices
                if v != 0 and total_out != required:
                    continue

                new_state = list(state)

                add_cost = 0

                for idx, u in enumerate(targets):
                    f = flows[idx]
                    new_state[u] += f

                    if f > 0:
                        add_cost += a[v][u] + f * f

                new_state = tuple(new_state)

                value = cur_cost + add_cost

                if new_state not in ndp or ndp[new_state] < value:
                    ndp[new_state] = value

        dp = ndp

    best_flow = None
    best_cost = -1

    for state, cost in dp.items():
        flow = state[n - 1]

        if best_flow is None or flow < best_flow:
            best_flow = flow
            best_cost = cost
        elif flow == best_flow:
            best_cost = max(best_cost, cost)

    if best_flow is None:
        print("-1 -1")
    else:
        print(best_flow, best_cost)

```実装における中心的な考え方は次のとおりです。`state[i]`どれだけの流入フロー頂点を保存するか`i`は処理された頂点からすでに蓄積されています。 

頂点処理時`v`、すべての入力エッジ`v`このようなエッジはすべて、より小さな頂点に由来するため、すでに修正されています。 つまり、`state[v]`残さなければならない正確な量です`v`もし`v`中間頂点です。 

トランジションでは、次を使用して、考えられるすべての送信割り当てを列挙します。`itertools.product`。 これが機能するのは、各エッジの容量が最大でも`5`そして多くても`5`発信エッジ。 

条件```
if v != 0 and total_out != required:
```流量保全を実現します。 頂点`1`はソースであり、任意のフローを注入する可能性があるため、除外されます。 

もう 1 つの微妙な点は、アクティベーション コストです。```
if f > 0:
    add_cost += a[v][u] + f * f
```エッジが実際に正のフローを伝送する場合にのみ、固定のアクティブ化コストを支払います。 

DP には、各状態の最大達成可能なコストのみが保存されます。 2 つの異なる構造が同じ累積残高を生み出す場合、将来の可能性は同じになるため、より大きなコストを維持することが、より小さなコストを優先します。

(5+1) + (5+1) + (5+1) + (5+1) = 24
```DP は、バランスが等しい状態間でより大きなコストを維持するため、分割構成を正しく選択します。
