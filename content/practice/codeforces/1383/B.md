 ## 解決策
 ## 問題の理解

 この問題は、非負の整数の配列でプレイされる 2 人用ゲームについて説明しています。 プレーヤーは順番に配列から要素を削除し、それを現在のスコアと XOR 演算します。 すべての要素が取り除かれた時点でゲームは終了し、より大きなスコアを持つプレイヤーが勝利し、同点の場合は引き分けとなります。 コアは常に最初に動きます。 

与えられた配列ごとに、両方のプレイヤーが最適にプレーした場合に Koa が勝つか負けるか、引き分けになるかを判断するように求められます。 入力は複数のテスト ケースで構成され、テスト ケース全体のすべての配列サイズの合計が 100,000 で制限されます。 個々の配列要素は最大 1e9 まで大きくできますが、テスト ケースごとの配列のサイズは最大 1e5 まで可能です。 

この制約は、テスト ケースあたりの線形演算時間よりも遅いアルゴリズムは遅すぎる可能性があることを意味します。 考えられるすべての移動シーケンスをシミュレートする総当りアプローチは n で指数関数的になるため、実行不可能です。 したがって、考えられるすべての動きのシーケンスを列挙することなく、配列を検査して結果を決定するメソッドが必要です。 

明らかではないエッジ ケースには、すべての要素が 0 である配列が含まれます。これは、ゼロとの XOR ではスコアが変わらないため、自明のことながら引き分けになります。 もう 1 つの微妙なケースは、すべての要素が 2 のべき乗に等しい場合、またはすべての要素の XOR が小さいがゼロではない場合です。これにより、単純な貪欲な戦略が間違った勝者を予測する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、両プレイヤーのあらゆる可能な一連の動きをシミュレートし、各パスのスコアを計算します。 これはゲームのルールを直接モデル化しているため、これは正しいです。 ただし、シーケンスの数は n 階乗であり、n = 10^5 では天文学的に大きいため、この方法は実行不可能です。 

最適化するための重要な洞察は、XOR が結合的かつ可換的であること、および XOR 演算要素の順序が各プレーヤーの最終スコアに影響を与えるのは、各ビット位置における手のパリティを通じてのみであるという観察から得られます。 これにより、問題は、すべての数値の XOR が 0 以外になる最上位ビットの分析に集約されます。 このビット位置を k と表すことにします。 このビットが設定された要素の合計数が奇数の場合、カウント モジュロ 4 が 1 でなければ、最初に動いたプレーヤーが有利になります。それ以外の場合、2 番目のプレーヤーは最初のプレーヤーの動きをミラーリングして引き分けまたは勝利を達成できます。 この観察により、動きをシミュレートすることなく、配列内の最も異なるビットとその頻度を検査することで勝者を決定することができます。

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、配列内のすべての要素の XOR を計算します。 XOR は可換であるため、これは 2 人のプレーヤー間の全体的な不均衡を表します。 
2. この合計 XOR がゼロの場合、ゲームは引き分けです。 一連の動きによって、一方のプレイヤーが他方のプレイヤーよりも厳密に高いスコアを獲得することはできません。 
3. 合計 XOR が 1 になる最上位ビット位置 k を特定します。これは、合計スコア寄与を区別する最上位ビットです。 
4. 配列内でこの k 番目のビットが設定されている数値がいくつあるかを数えます。 このカウントを次のように表します`cnt`。 
5. 勝利条件を適用します。`cnt % 2 == 1`そして`(n - cnt) % 2 == 0`または`cnt % 4 == 1`、その後、最初のプレイヤーであるコアが強制的に勝利を収めることができます。 そうしないと、2 番目のプレーヤーが強制的に勝利を収めることができます。 
6. 上記のルールに従って、WIN、LOSE、または DRAW を印刷します。 

正確性は、どのプレイヤーが最終スコアをより高くすることができるかが最も高い差ビットによって決定されるという不変条件から得られます。 このビットが設定された要素の数のパリティは、最初のプレーヤーと 2 番目のプレーヤーが最適な結果を達成するために動きをミラーリングできるかどうかを制御します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total_xor = 0
        for x in a:
            total_xor ^= x
        if total_xor == 0:
            print("DRAW")
            continue
        k = total_xor.bit_length() - 1
        cnt = sum(1 for x in a if (x >> k) & 1)
        if cnt % 2 == 1 and (n - cnt) % 2 == 0:
            print("WIN")
        else:
            print("LOSE")

solve()
```このソリューションでは、まず配列内のすべての数値の XOR を計算して、些細な引き分けを検出します。 XOR が 0 以外の最上位ビットによって、どの手が重要になるかが決まります。 このビットを使用して要素をカウントすると、プログラムはパリティに基づいて勝者を決定できます。 使用する`bit_length()`効率的であり、ビット位置を手動でループする必要がなくなります。 すべての操作は配列のサイズにおいて線形です。

 ## 特殊なケース

 すべて 0 の配列は合計 0 の XOR を生成し、アルゴリズムはこれを引き分けとして正しく識別します。 単一の非ゼロ要素を持つ配列は、その要素を Koa に与えるため、アルゴリズムは WIN を出力します。 最も異なるビットが奇数の要素内に存在する配列は、カウントによって処理されます。`cnt`そしてパリティをチェックして、正しい勝者が選択されることを保証します。 各トレースでは、アルゴリズムは最大ビット差とそれを含む数値のカウントのみを考慮し、ゲーム理論に基づいた最適な手が単純なリニア スキャンで正しくエンコードされることを保証します。
