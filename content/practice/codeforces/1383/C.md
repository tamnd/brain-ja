 ## 解決策
 ## 問題の理解

 20 文字の小さなアルファベットから構築された、同じ長さの 2 つの文字列が与えられます。 文字列 A から始めて、特定の操作を使用してそれを文字列 B に変換したいとします。 

1 つの操作は次のように機能します。文字 x を選択します。 現在 x に等しい A 内のすべての位置を調べ、それらの位置のサブセットを選択します。 次に、選択したすべての位置を文字 y に再色付けします。 主な制限は、現在同じ文字 x を保持している位置でのみ操作できることですが、それらの位置内では任意のサブセットを自由に選択できることです。 

タスクは、A を B と正確に等しくするために必要なこのような演算の最小数を計算するか、それが不可能であると判断することです。 

重要な構造上の特徴は、同じ現在の文字を共有するポジションを 1 回の移動で一緒に変更できるという事実を除いて、各ポジションが独立して進化することです。 これにより、見落としがちな位置間の結合が生じます。文字の 1 つの出現を変更すると、一度に多くの位置に影響を与える可能性がありますが、それらを将来の異なる動作に分割すると、コストが発生します。 

制約は大きく、テスト ケース全体の長さの合計は最大 100,000 です。 位置ごとに変換をシミュレートしたり、文字ごとに一連の操作を検索したりするソリューションは、遅すぎます。 解決策は、問題を 20 文字のアルファベットを単純に数えるというものに減らす必要があります。 

複数の位置が同じソース文字を共有しているが、異なるターゲット文字が必要な場合、微妙なエッジケースが発生します。 素朴なアプローチでは、各ポジションのコストが独立していると想定し、不一致の数やポジションごとの最短パスが発生する可能性がありますが、これは同じ現在の文字を共有する複数のポジション間で 1 つの操作を再利用する機能を無視しています。 たとえば、A が「aab」で B が「bcc」の場合、ポジションごとの戦略では 3 つの手が提案されますが、最適な再利用では、最初に両方の「a」ポジションを一緒に処理することで 2 つの手が得られます。 

もう 1 つのよくある落とし穴は、これが単なる文字の最短経路の問題であると仮定することです。 操作が単一のトークンに独立して影響を与えるわけではないため、その解釈は失敗します。 これらは同一の文字のサブセット全体に同時に影響を及ぼし、ソース文字ごとに共有構造を作成します。 

## アプローチ

 強引なアイデアは、操作を直接シミュレートすることです。 各ステップで、現在の文字列に存在する文字 x を選択し、その位置のサブセットを選択し、可能なすべてのターゲット文字 y を試します。 これは巨大な分岐要素につながります。各状態には指数関数的に多くのサブセットの選択肢があり、y には 20 の選択肢があります。 状態を圧縮したとしても、可能な文字列構成の数は天文学的に多く、n が小さい場合でも探索は不可能です。 

重要な観察は、ポジションが現在のレターを通じてのみ相互作用するということです。 現在同じ文字を保持しているすべてのポジションは、有効な操作の観点からは区別できません。 重要なのは、個々の位置ではなく、各ソース文字が最終的に何個の個別のターゲット文字に到達する必要があるかです。 

A の文字 x を修正します。A[i] = x であるすべての位置を考慮します。 これらの位置の中で、B はターゲット文字のいくつかのセットを割り当てます。 たとえば、これらのターゲットが {b, c, d} であるとします。 最終的には、x のグループをこれらの異なる文字になるサブグループに分割する必要があります。 

文字 x を含む移動を実行するたびに、x 位置の選択された 1 つのサブセットを新しい文字に割り当てることができます。 ただし、x を別の文字に分割すると、結果として得られる文字は x のグループの一部ではなくなるため、x に対する今後の操作はそれらの文字には影響しません。 これは、それぞれの個別のターゲット文字には、x からの少なくとも 1 つの「分岐アクション」が実質的にかかることを意味します。

微妙な節約方法が 1 つあります。x 自体がそのターゲットの中にある場合、x を自然な「基本状態」として扱い、それを保存するために明示的に移動を費やすことを避けることができます。 他のすべてのターゲット文字は、x から 1 つの変換ステップを必要とします。 したがって、文字 x あたりのコストは、A が x を持つ位置のうち、B に出現する別個の文字の数によって純粋に決まります。 

チェーンや中間変換が行われなくなると、このコストが削減されます。これは、中間変換には依然として操作が必要であり、x の異なるブランチを再びマージするのに役立たないためです。 

したがって、問題は、最初の文字によって位置をグループ化し、各グループが必要とする個別のターゲット文字の数をカウントすることに帰着します。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. アルファベットの各文字 x について、A[i] = x となるすべての文字 B[i] を収集します。 

これにより、各ソース文字から必要なターゲット文字のセットへのマッピングが構築されます。 
2. 各文字 x について、そのセット S 内の個別のターゲット文字の数を計算します。 

これは、x から始まるグループがいくつの異なる最終状態に分割される必要があるかを表します。 
3. S が空の場合、x は A に出現せず、何も寄与しません。 
4. それ以外の場合、x 自体が S にある場合、ターゲットの 1 つはすでに元の文字です。 余分な移動を費やすことなく、そのサブセットを維持できます。 貢献度は |S| です。 − 1.
 5. x が S にない場合、すべてのターゲットは x からの個別の変換を必要とするため、寄与は |S| になります。 
6. すべての文字 x の寄与を合計して、答えを取得します。 

### なぜ効果があるのか

 各ソースレターは、そのレターが残っている間のみ一緒に行動できるポジションの独立したプールを定義します。 これらの位置にある個別のターゲット文字ごとに、そのプールから少なくとも 1 つの分離イベントが強制されます。 サブセットが x から離れると、再び入ることはないため、これらの分離を異なるターゲット文字間で再利用することはできません。 唯一の例外は、x 自体を保持することです。これには操作は必要ありません。x がそれ自身のターゲットに含まれる場合、必要な分離の数が実質的に 1 つ減ります。 各ターゲット文字がそのソース グループからの必要な分岐に正確に 1 つ対応するというこの不変条件によって、最小移動数が完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input().strip())
        A = input().strip()
        B = input().strip()

        targets = [set() for _ in range(20)]

        for i in range(n):
            x = ord(A[i]) - 97
            y = ord(B[i]) - 97
            targets[x].add(y)

        ans = 0
        for x in range(20):
            if not targets[x]:
                continue
            k = len(targets[x])
            if x in targets[x]:
                ans += k - 1
            else:
                ans += k

        print(ans)

if __name__ == "__main__":
    solve()
```コードは、文字ごとに、必要な宛先文字のセットを構築します。 アルファベットのサイズが 20 に固定されているため、セットは小さくなり、n が大きい場合でも効率的です。 

最後のループでは、上記で導出されたルールが適用されます。各ソース文字は、ターゲット セットのサイズに寄与するか、それ自体が含まれる場合は 1 つ減ります。 結果はすべての文字にわたって累積されます。 

## 実用的な例

 ### 例 1

 次のことを考慮してください。 

A = "aab"、B = "bcc"

 ターゲット セットを構築します。 

| × | A | の位置 ターゲットセット S | x が含まれています | 貢献 |
 | --- | --- | --- | --- | --- |
 | | 1,2 | {b} | いいえ | 1 |
 | b | 3 | {c} | いいえ | 1 |

 合計 = 2。 

これは最適な戦略と一致します。最初に両方の「a」位置を「b」に変換し、次に残りの構造を必要な場所の「c」に到達するように変換します。 

トレースは、ソース文字ごとにグループ化することで、位置ごとの操作の過大なカウントを防止することを示しています。 

### 例 2

 A = "abc"、B = "tsr"

 | × | S | x が含まれています | 貢献 |
 | --- | --- | --- | --- |
 | | {t} | いいえ | 1 |
 | b | {s} | いいえ | 1 |
 | c | {r} | いいえ | 1 |

 合計 = 3。 

異なるソース文字間でグループ化を再利用できないため、各文字には 1 回の独立した変換が必要です。 

これは、すべての文字が位置間で異なる場合、答えは位置ごとのコストに縮退することを確認します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output

    import sys as _sys
    input = _sys.stdin.readline

    t = int(input())
    res = []
    for _ in range(t):
        n = int(input().strip())
        A = input().strip()
        B = input().strip()

        targets = [set() for _ in range(20)]
        for i in range(n):
            targets[ord(A[i]) - 97].add(ord(B[i]) - 97)

        ans = 0
        for x in range(20):
            if not targets[x]:
                continue
            k = len(targets[x])
            ans += (k - 1) if x in targets[x] else k

        res.append(str(ans))

    return "\n".join(res)

 ## 特殊なケース

 A がすでに B に等しい場合、すべてのターゲット セット S[x] は空であるか、x のみを含みます。 このような文字の場合、k = 1 および x ∈ S[x] であるため寄与はゼロになり、k − 1 = 0 になります。アルゴリズムは正しく 0 を返します。 

A の文字が出現しない場合、そのセットは空のままで何も寄与しないため、答えが偶発的に膨らむことが回避されます。 

文字のすべての出現が 1 つの異なる文字にマッピングされる場合、コストはちょうど 1 であり、サイズに関係なく 1 回の操作でグループ全体の色を変更できることを反映しています。 

これらのケースでは、グループ化ロジックが縮退構成と完全に混合された構成にわたって一貫して動作することが確認されています。
