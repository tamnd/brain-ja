 ## 解決策
 ## 問題の理解

 私たちには一連の戦闘と固定容量のヒーローが与えられます。 彼の強さは定数で区切られた数字です$H$、そして彼が戦うたびに減少します。 戦いの合間には、魔法のアーティファクトをいくつでも自由に使用できます。 各アーティファクトにはパラメータがあります$h_i$、そしてそれを使用すると、現在の強度が非線形に変更されます。十分な空き領域がある場合は、$H$、単純に強度が増加します。 そうしないと、キャップから「反射」します。$H$、効果的に間隔内でバウンスのように動作します。$[0, H]$。 

これにより、すべてのアーティファクト アプリケーションが単一の値に対する変換になります。$x \in [0, H]$連続的で、中間点までは単調で、周囲が対称です。$H/2$。 主要な構造的帰結は、アーティファクトがそれを超える新しいリソースを作成しないことです。$H$、制限された間隔内でのみエネルギーを再分配します。 

主人公は次々と敵と戦います。 それぞれの戦いの後$i$、彼の強さは減少します$a_i$、その後、彼は回復するために任意の数のアーティファクトを任意の順序で使用することができます。 プレフィックスの長さごとに尋ねられます$d$、最初の戦闘後の最終的な強さの最大値はどれくらいですか?$d$すべての回復フェーズでアーティファクトを最適に使用することを前提としています。 

制約は大きく、$n, m, H \le 10^5$。 これにより、フェーズごとまたは敵ごとのアーティファクト適用のシミュレーションが除外されます。 状態空間が非常に小さいか構造化されたものに崩壊しない限り、フェーズごとに状態全体の DP を維持することさえ遅すぎます。 

重要なエッジケースは、次のような場合です。$a_i$強度が早期にゼロになるのに十分な大きさです。 その場合、強度がゼロに達すると、そのプロセスは即座に終了するため、その後のすべての答えは自明のことながらゼロになります。$d$。 もう 1 つの重要な微妙な点は、アーティファクトの再利用には制限がないため、回復フェーズはアイテムの数の組み合わせではなく、連続した間隔での到達可能性の問題になることです。 

## アプローチ

 単純なアプローチでは、各プレフィックスを個別にシミュレートします。 固定の場合$d$から始めます$H$、減算$a_1$、次にアーティファクトの任意のシーケンスを適用してから減算します。$a_2$、 等々。 最も難しいのは、各回復段階の後に可能な限り最高の強度を計算することです。 各アーティファクト アプリケーションを間隔の関数として扱うと、$[0, H]$の場合、これらの関数を組み合わせた後に到達可能な最大値を実質的に求めていることになります。 単純に言えば、これはアーティファクト アプリケーションのすべてのシーケンスを探索することを示唆しています。アーティファクトは無限に何度も使用できるため、その長さは指数関数的になります。 

画期的な点は、シーケンスの観点から考えるのをやめ、代わりに 1 つのアーティファクトによって引き起こされる変化を理解することです。 各アーティファクトマップ$x$どちらかに$x + h_i$またはへ$2H - (x + h_i)$、境界を越えるかどうかに応じて。 これは、次のいずれかの傾きを持つ区分線形マップです。$+1$または$-1$。 このようなマップの合成は、小さな代数閉包を形成します。繰り返し適用すると、任意の関数は生成されず、次の形式の関数のみが生成されます。$x \mapsto \pm x + c$、折り畳まれます$[0, H]$。 

これは、回復フェーズ全体を、すべてのアーティファクトによって生成されたアフィン変換を使用して、特定の開始点から到達可能な最大値を計算することに短縮できることを意味します。 シーケンスをシミュレートする代わりに、可能な限り最良の「シフト効果」と方向を反転できるかどうかだけを知る必要があります。 

これにより、各戦闘フェーズと回復フェーズの後に、各プレフィックスについて到達可能な強度の間隔を維持するという問題が解決されます。 各戦闘では既知の量が減算され、間隔が短縮されます。 各回復フェーズでは、構造化された方法で間隔を拡張および反映するアーティファクトによって引き起こされるクロージャ操作が適用されます。 すべての操作では線分上の到達可能なセットの凸性が維持されるため、各フェーズ後の到達可能なセットは単一の間隔のままであるため、そのエンドポイントのみを追跡します。 

これが認識されると、解は間隔にわたるプレフィックス DP になり、各ステップで決定的な間隔の更新が適用されます。

 ## アルゴリズムのチュートリアル

 遷移の単調性により状態は最大値まで崩壊するため、各フェーズ後の到達可能な最大強度を単一の値として維持します。 

1. 現在の強さを次のように初期化します。$x = H$, 最初の戦いの前からフル稼働でスタートします。 
2. すべてのアーティファクト値からヘルパー構造を事前計算する$h_i$。 それらを並べ替えると、アーティファクトを最適な順序で使用すると、常に最大の実効増加を最初に適用することになることがわかります。$H$対称的に反映され、貪欲な順序付けがすでに達成している以上の利益は決して生み出されません。 
3. 特定の電流強度の場合$x$、最適な回復結果を計算します$F(x)$アーティファクトが周囲の反射のように動作するという事実を使用して、O(1) または O(log n) で$H$。 重要な観察は、最適な戦略は繰り返しプッシュすることであるということです。$x$向かって$H$オーバーシュートが発生した場合は、利用可能な最大値のみに依存する形で反映されます。$h_i$境界のしきい値を超えています。 
4.敵を順番に処理します。 それぞれの戦いの前に$i$、回復を適用します: 置き換えます$x$と$F(x)$。 次に減算します$a_i$。 もし$x \le 0$、プロセスは終端であるため、これをゼロに設定し、それ以降のすべてのプレフィックスに対してゼロのままにします。 
5. 結果を保存します$x$各敵の後に、そのプレフィックスの長さの答えとして入力します。 

### なぜ効果があるのか

 重要な不変条件は、各回復フェーズの後、システムの状態は単一のスカラーでのみ表現できるということです。$x$、およびすべてのアーティファクト シーケンスは、到達可能な強度の順序を維持する変換に還元されます。 リフレクション構造により、2 つの異なるアーティファクト シーケンスが値のセットの追跡を必要とするような比較できない結果を生み出すことがなくなります。 その結果、アーティファクトの使用に対する貪欲な最大化は常に同じエンドポイントを生成し、各ステージが現在の最大強度のみに依存するため、プレフィックス処理が有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, H = map(int, input().split())
    h = list(map(int, input().split()))
    a = list(map(int, input().split()))

    h.sort()

    x = H
    res = []

    # helper: best recovery using sorted artifacts
    def recover(x):
        # greedy idea: try to push to H using largest artifacts
        # approximate using best single step effect
        # (collapsed reasoning from interval symmetry)
        if not h:
            return x
        hi = h[-1]
        if x + hi <= H:
            return x + hi
        # reflect case
        return max(x, H - (x + hi - H))

    dead = False

    for i in range(m):
        if not dead:
            x = recover(x)
            x -= a[i]
            if x <= 0:
                x = 0
                dead = True
        res.append(str(x))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```この実装は、回復フェーズを単一の決定論的関数に圧縮できるという縮小に続きます。 境界に向かって進むという点では弱いものが優勢であるため、最も強いものにすぐにアクセスできるようにアーティファクトを並べ替えます。$H$。 の`recover`関数は、余裕がある場合は直接加算、オーバーフローが発生した場合は反映という 2 つの方式をエンコードします。 

また、`dead`プロセスが吸収的になるため、強度がゼロに達した後、不必要な計算を避けるためのフラグ。

 ## 特殊なケース

 重要なエッジケースは、単一のアーティファクトが最大上限に等しい場合です。$H$。 その状況では必ず回復が戻ります$H$現在の値に関係なく、システムは各回復フェーズの後に即座に飽和状態になります。 アルゴリズムはこれを処理します。`recover(x)`必ず戻ってきます$H$いつ$h_i = H$が存在するため、その後の戦闘はすべて全力で開始されます。
