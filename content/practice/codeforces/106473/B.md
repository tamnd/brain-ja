 ## 問題の理解

 非表示のオブジェクトはバランスの取れた括弧文字列です。 その連続部分自体が有効な括弧シーケンスであるかどうかを尋ねることができ、文字列全体を発見するのに十分な質問があります。 元のタスクは対話型であるため、入力では長さとクエリ制限のみが与えられ、プログラムは判定者と通信して文字列を回復します。 

有効な括弧シーケンスには、有用な数値解釈があります。 治療すれば`(`として`+1`そして`)`として`-1`、シーケンスのすべてのプレフィックスは負でない合計を持たなければならず、シーケンス全体は合計ゼロで終わる必要があります。 部分文字列は、その相対バランスがゼロを下回らず、ゼロで終了する場合に有効です。 

制限は問題の重要な部分です。 すべての位置のペアをチェックしたり、クエリの大規模な二分探索ツリーを使用して答えを再構築したりする余裕はありません。 と`q >= n - 3`、意図したソリューションでは、文字ごとにほぼ正確に 1 つのクエリを消費する必要があります。 これにより、次のようなアプローチが除外されます。`O(n log n)`クエリや何度も繰り返されるチェック。 

厄介なケースは、クエリが文字を直接明らかにしないという事実から生じます。 たとえば、長さ 2 のプレフィックスについて尋ねると、次のように返されます。`YES`プレフィックスが`"()"`、 その間`NO`どちらかを意味する可能性があります`"("`に続く`"("`または一般的な文字列内のその他の無効な状況。 私たちは、隠し文字列全体が有効であることが保証されているという事実に依存しています。 

隠し文字列を考慮してください`((()))`と`n = 6`。 隣接するペアのみを検査する場合、そのペアは`((`与える`NO`, しかし、それが深いネストの始まりなのか、それとも別の構造なのかはわかりません。 プレフィックス クエリでは、現在の残高がゼロに戻ったかどうかがわかるため、より多くの情報が得られます。 

もう 1 つの境界ケースは文字列の終わりです。 最初を取り戻せたら`n - 2`最後の 2 文字を任意に指定することはできません。 全シーケンスの最終的な残高はゼロでなければならないため、残りの残高によって完全に決定されます。 

## アプローチ

 直接的なアプローチでは、各文字を独立して決定しようとします。 考えられるアイデアの 1 つは、多数の小さな間隔について質問し、その回答から文字を推測することです。 すべての文字が一定の間隔の有効性に影響を与えるため、これは正しいですが、情報が無駄になります。 可能な間隔が多すぎるため、クエリの制限は線形のみです。 

有益な観察は、プレフィックスの有効性が正確に現在の残高に関するステートメントであるということです。 すべてのプレフィックスの長さがわかっている場合、`2, 3, ..., n - 2`バランスが取れている場合、ほぼすべてのポジション後のバランスがわかります。 残高の値が判明すると、残高は文字ごとに 1 つだけ変化するため、2 つの連続する既知の残高間の文字が強制されます。 

長さ 1 のプレフィックスが欠落していても問題はありません。 2 番目の接頭辞により、最初の 2 文字がわかります。 2 文字後の残高がゼロの場合、最初の 2 文字は`"()"`。 2 つの場合は、両方とも左括弧でなければなりません。 同じ考え方が後のすべてのポジションにも当てはまります。

 ## アルゴリズムのチュートリアル

 1. すべての接頭語について裁判官に尋ねます`[1, i]`のために`i`から`2`に`n - 2`。 肯定的な答えはポジション後の残高を意味します`i`はゼロです。 否定的な答えは、残高がプラスであることを意味します。 これらの残高は、回答と一致する可能な最大値を維持することによって保存されます。 
2. 最初のものを再構築する`n - 2`既知の天秤からの文字。 すべてのポジションについて、その前後のバランスを比較してください。 残高が増えるとキャラクターは`(`。 それが減少すると、そのキャラクターは`)`。 バランスはちょうど 1 だけ変化するため、3 番目のオプションはありません。 
3. 最初の支払い後の残りの残高を計算します。`n - 2`文字。 最後の 2 文字は強制されます。 残高がゼロの場合は、`"()"`。 残高が 2 の場合は、`"))"`。 
4. 再構築された文字列を出力します。 

これが機能する理由は、すべてのプレフィックスのバランスが回答によって一意に決定されるためです。 非表示の文字列は有効なブラケット シーケンスであるため、2 つの隣接するバランス間のすべての遷移は 1 つのブラケットに正確に対応する必要があります。 最後の 2 文字も一意に決定されます。これは、2 文字の接尾辞が 1 つだけであるため、現在の残高をマイナスにならずにゼロに戻すことができるためです。 

## Python ソリューション

 元の問題は対話型であるため、提出されたプログラムは審査員と通信します。```python
import sys
input = sys.stdin.readline

def ask(l, r):
    print("?", l, r, flush=True)
    ans = input().strip()
    if ans == "YES":
        return True
    return False

n, q = map(int, input().split())

balance = [0] * (n + 1)

for i in range(2, n - 1):
    if ask(1, i):
        balance[i] = 0
    else:
        balance[i] = -1

# The actual interactive solution keeps prefix balances.
# Here the reconstruction part is shown in terms of those balances.
ans = ['?'] * n

# The first two characters are determined by the prefix of length 2.
if ask(1, 2):
    ans[0] = '('
    ans[1] = ')'
else:
    ans[0] = '('
    ans[1] = '('

cur = 0
cur += 1 if ans[0] == '(' else -1
cur += 1 if ans[1] == '(' else -1

for i in range(3, n - 1):
    if balance[i] > cur:
        ans[i - 1] = '('
    else:
        ans[i - 1] = ')'
    cur += 1 if ans[i - 1] == '(' else -1

if cur == 0:
    ans[n - 2] = '('
    ans[n - 1] = ')'
else:
    ans[n - 2] = ')'
    ans[n - 1] = ')'

print("!", ''.join(ans), flush=True)
```の`ask`関数は対話ロジックを分離します。 通常のインタラクティブな提出では、審査員が応答できるように、印刷されたすべての質問を直ちにフラッシュする必要があります。 

再構成は、ブラケットの回答を直接保存するのではなく、残高に依存します。 プレフィックス クエリは、現在の残高がゼロかどうかを示し、シーケンス全体の有効性によって、可能なプラスの残高が制限されます。 

最後の 2 つの位置には特別な処理が必要です。 ループからそれらを推論しようとすると、アルゴリズムが意図的に次の値で停止するため、1 つずつ異なる間違いが発生します。`n - 2`クエリ制限に合わせて。

 | ステップ | クエリ | 結果 | 既知の情報 |

 ## 特殊なケース

 最小有効文字列の場合`()`、クエリする中間プレフィックスはありません。 最初のクエリは両方の文字を即座に決定するため、サフィックスの再構築は必要ありません。 

次のような深くネストされた文字列の場合`((()))`、完全な文字列を除き、初期のプレフィックスはすべて無効です。 アルゴリズムは、これを未知の状況と混同しません。これは、負のプレフィックス応答は残高がプラスであることを意味し、残高は各ステップで 1 つだけ変化するためです。 

で終わる文字列の場合`"()"`、ポジション後の残高`n - 2`はゼロであるため、接尾辞ルールは可能な唯一の語尾を選択します。 残高が 2 の文字列の場合、次のようになります。`((()))`、有効な補完は次のとおりです。`"))"`、これもアルゴリズムによって導出されます。
