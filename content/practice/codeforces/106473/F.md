 ## 解決策
 ## 問題の理解

 小文字の文字列が与えられます。 すべての文字を再配置する可能性があり、長さ 1 の接頭辞を除いて、接頭辞が回文にならない新しい文字列を構築する必要があります。 言い換えれば、最初の文字を選択した後は、長い接頭辞の両端に異なる文字が含まれるか、内部のどこかで回文対称性に欠ける必要があります。 入力には多くの独立した文字列が含まれており、それぞれについてルールを満たす配置を出力するか、配置が存在しないことを報告します。 

すべてのテスト ケースの合計文字数は最大で次のとおりです。$10^6$。 中程度の長さの文字列であっても因数分解数が多いため、これにより、考えられるすべての順列のチェックが除外されます。 また、100 万文字のスキャンは簡単ですが、回文チェックやコストのかかる検索を繰り返すと快適に収まらないため、意図したソリューションは文字列長が線形に近い必要があることも意味します。 

厄介なケースは、文字の頻度に起因します。 のような文字列`abba`有効な答えに並べ替えることはできません。 最初の文字は再び出現し、異なる文字が 2 つだけある場合、最初の文字が 2 回目に出現すると回文接頭辞が作成されます。 1 文字だけを含む文字列も失敗します。これは、長さ 2 の接頭辞がすぐに回文になるためです。 

シングルトンキャラクターは状況を完全に変えます。 例えば：```
Input:
1
aabbc
```正しい出力は次のようになります。```
YES
cabba
```キャラクター`c`は 1 回出現するため、これを最初に置くと、長いプレフィックスはすべて次で始まることになります。`c`しかし、別のキャラクターで終わります。 

もう 1 つの重要なケースは、まさに 2 つの異なる文字です。```
Input:
1
aabb
```正しい出力は次のとおりです。```
NO
```不注意な解決策では、文字を置き換えて次のようなものを生成しようとする可能性があります。`abab`、ただし接頭辞`aba`回文です。 2 人のキャラクターを配置した場合でも、基本的な問題は同じです。 

## アプローチ

 直接的なアプローチでは、文字の順列を生成し、それぞれをテストしようとします。 最終的には考えられるすべての再配置を調べるため、これは正しいですが、階乗的な複雑さがあります。 ある長さの文字列の場合$n$、注文可能な数は$n!$の値が小さい場合でも不可能になります。$n$。 

有益な観察は、答えを構築した後に実際にはプレフィックスを検査する必要がないということです。 最初の文字がどこに再度表示されるかを制御する必要があるだけです。 最初の文字が 1 回だけ出現する場合は、その文字を先頭に置くことができ、接頭語を回文にすることはできません。 

より困難なケースは、すべての文字が少なくとも 2 回出現する場合です。 すべての文字が等しい場合、最初の 2 文字は常に同じであるため、答えは不可能です。 異なる文字が 2 つだけ存在する場合、最初の文字が 2 回目に出現すると、常に回文プレフィックスが作成されます。 不可能性の推論と残りのケースの構築は、この周波数分割に基づいています。 

異なるキャラクターが 3 人以上存在する場合は、任意のキャラクターを選択してください`x`。 のコピーを 1 枚入れます`x`最初に、残りのコピーをすべて置きます`x`最後に、それらの間に 1 文字おきにソート順に配置します。 中間セクションには何も含まれていません`x`したがって、最後のブロックより前で終わるプレフィックスは回文になりません。 最終ブロックに到達するプレフィックスは 1 つだけで始まります`x`別の文字に遭遇する前に、その逆の場合はいくつかの先行文字が必要になります`x`文字なので、これらの接頭辞も回文にすることはできません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(1) 出力ストレージ以外の | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列内のすべての文字の頻度を数えます。 有効な配置が存在するかどうかは、存在する異なる文字の数と、ある文字が一度だけ出現するかどうかによってのみ決まるため、これらのカウントが必要になります。 
2. 1 回だけ出現する文字を検索します。 存在する場合は、それを最初に配置し、その後に 1 文字おきに追加します。 後の文字は最初の文字と等しくないため、長いプレフィックスはそれぞれ最初と最後の文字が異なります。 
3. シングルトン文字がない場合は、個別の文字の数を数えます。 この数値が 1 または 2 の場合は、次のように出力します。`NO`。 These are exactly the cases where every possible arrangement creates a bad prefix.
 4. If there are at least three distinct letters, choose one character`x`。 次のオカレンスを 1 つ入れます`x`最初に、他のすべての非`x`その後にソート順に文字を配置し、残りのコピーを追加します。`x`最後に。 
5. 構築された文字列を出力します。 

なぜ効果があるのか:

 最初の文字は、接頭辞回文にとって重要な唯一の文字です。 回文接頭語は、先頭と同じ文字で終わる必要があります。 The construction either makes that impossible by choosing a unique first character, or it separates the first character from all its later copies with a middle section that begins with another character. 不可能なケースとは、まさに、そのような分離が対称プレフィックスの繰り返しを回避できないケースです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(s):
    cnt = [0] * 26
    for c in s:
        cnt[ord(c) - 97] += 1

    single = -1
    for i in range(26):
        if cnt[i] == 1:
            single = i
            break

    if single != -1:
        ans = [chr(single + 97)]
        for i in range(26):
            if i != single:
                ans.append(chr(i + 97) * cnt[i])
        return "YES\n" + "".join(ans)

    kinds = sum(1 for x in cnt if x > 0)

    if kinds <= 2:
        return "NO"

    first = next(i for i in range(26) if cnt[i] > 0)

    ans = [chr(first + 97)]

    for i in range(26):
        if i != first:
            ans.append(chr(i + 97) * cnt[i])

    ans.append(chr(first + 97) * (cnt[first] - 1))

    return "YES\n" + "".join(ans)

def main():
    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        out.append(solve_case(s))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```タスクでは任意の並べ替えが可能であるため、元の順序から必要な情報は周波数配列だけです。 シングルトン検索では、最も簡単で建設的なケースが最初に処理されます。 それが失敗した場合、明確な文字数によって、不可能な入力が構築ケースから分離されます。 

最終的な構築では、最初に次のことが発生します。`first`別途追加されます。 これにより、最初にすべてのコピーを誤って一緒に配置することが回避されます。 残りのコピーは、他のすべての文字が配置された後にのみ追加されます。 の乗算`cnt[first] - 1`すべてのカウントが少なくとも 2 である場合にのみ分岐がこのポイントに到達するため、これは安全です。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().split()
    sys.stdin = old

    t = int(data[0])
    ans = []
    for s in data[1:]:
        ans.append(solve_case(s))
    return "\n".join(ans)

def solve_case(s):
    cnt = [0] * 26
    for c in s:
        cnt[ord(c) - 97] += 1

    for i in range(26):
        if cnt[i] == 1:
            return "YES\n" + chr(i + 97) + "".join(
                chr(j + 97) * cnt[j] for j in range(26) if j != i
            )

    kinds = sum(x > 0 for x in cnt)
    if kinds <= 2:
        return "NO"

    first = next(i for i in range(26) if cnt[i])
    return "YES\n" + (
        chr(first + 97)
        + "".join(chr(i + 97) * cnt[i] for i in range(26) if i != first)
        + chr(first + 97) * (cnt[first] - 1)
    )

 ## 特殊なケース

 次のような単一の文字列。```
1
a
```is handled immediately. 唯一のプレフィックスの長さは 1 であり、制限は長さ 2 から始まるため、答えは有効です。 

1 つの文字が繰り返される文字列:```
1
aaaa
```有効な取り決めがありません。 可能な配置はすべて同一であり、最初の 2 文字はすでに形成されています`aa`, a palindrome.

 正確に 2 つの異なる文字を含む文字列:```
1
aabb
```施工前に断られます。 最初の文字が`a`、次に発生する`a`最初と最後の文字が一致し、内部が次のもののみで構成されるプレフィックスを作成します。`b`回文を生成する文字。 最初の文字が次の場合にも同じ引数が適用されます。`b`。 

複数の文字を含むがシングルトンを含まない文字列:```
1
aabbcc
```最終構造を使用します。 選択する`a`のような形式を与えます`abbcca a`の最後のコピーで`a`最初の文字列は、それを反映できない文字によって分離されています。 配置ルールによって構造上プレフィックスが防止されるため、アルゴリズムはプレフィックスを個別にテストする必要はありません。
