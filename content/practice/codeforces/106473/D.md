 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、各値は固定ビット数を使用して表されます。 特別な操作があります。配列の任意の連続セグメントを選択し、そのセグメント内のすべての数値のすべてのビットを反転できます。 反転とは、各値を x ビット空間内のビット単位の補数で置き換えることを意味します。つまり、すべての数値が`v`になる`(2^x - 1) - v`。 

ゲームは正確に続きます`k`動く。 2 人のプレーヤーが最初のプレーヤーから順番に交互に動き、両方とも完璧にプレーしますが、目標は逆になります。 最初のプレーヤーは配列の最終合計を最大化したいと考えていますが、2 番目のプレーヤーはそれを最小化したいと考えています。 まさにその後`k`セグメントが反転すると、最終的な合計が出力されます。 

重要な点は、各操作がセグメントを反転しますが、その効果は単純な加算的な意味では局所的ではないということです。 各位置は、奇数の選択されたセグメントでカバーされるたびに、元の値と補数の間で切り替わります。 

制約があるため、慎重な構造的解決が求められます。 テスト全体の配列サイズは最大 50,000 であるため、どのソリューションもテストごとにほぼ線形またはほぼ線形である必要があります。 移動数`k`最大 10^12 になる可能性があり、ゲームプレイのシミュレーションは即座に除外されます。 ビット幅`x`は最大でも 10 であるため、値は非常に狭い範囲内に収まりますが、フリップを別の方法で解釈しない限り、それだけでは組み合わせゲームは単純化されません。 

よくある落とし穴は、各手を個別に分析したり、局所的に合計を改善するために貪欲に適用できると考えることです。 セグメントの反転が重なって相互作用するため、これは失敗します。 もう 1 つの失敗モードは、各移動をシミュレートし、配列を明示的に維持することですが、これは両方の理由で不可能になります。`k`また、セグメントの更新を適用する際の二次コストが原因です。 

## アプローチ

 直接的なシミュレーションの観点から始めます。 各移動は、セグメントを選択し、そのセグメント内のすべての値を次のように切り替えることで構成されます。`v`そして`maxVal - v`、 どこ`maxVal = 2^x - 1`。 これを文字通りシミュレートしようとすると、各移動にコストがかかります`O(n)`時間、につながる`O(nk)`、これは不可能です`k`10^12に達します。 

さらに、ゲーム構造は指数関数的な分岐を示唆しています。各ステップで、プレイヤーは O(n^2) 個のセグメントのいずれかを選択できます。 単純なミニマックス検索は完全に不可能です。 

重要な観察は、値について考えるのをやめ、代わりに合計への寄与について考えることです。 各ポジションについて、それを反転すると、その寄与度が次のように変化します。`a[i]`に`maxVal - a[i]`。 したがって、値の変化は固定デルタになります。`(maxVal - a[i]) - a[i] = maxVal - 2*a[i]`。 

したがって、すべてのインデックスには、正または負の重みがあり、それを反転することがどれほど有益であるかを表します。 ただし、連続したセグメントのみを反転できるため、反転は独立していません。つまり、パリティを介して効果が組み合わされる範囲を選択していることになります。 

これにより、問題は、各移動がセグメントを選択し、そのセグメント内のすべての値の符号を反転する重みの配列に関するゲームに変換されます。 スコアは値の合計であり、プレイヤーは正確に最大化と最小化を繰り返します。`k`操作。 

ここで、重要な構造の単純化が見られます。各操作はセグメントに対する符号反転にすぎないため、同じセグメントを 2 回適用するとキャンセルされます。 したがって、重要なのは、各ポジションが全体で偶数回反転されるか奇数回反転されるかだけです。 ゲーム全体は、フリップの最終的なパリティ構成を決定することになります。`k`プレーヤーがセグメント XOR 演算を制御しながら移動します。 

これは、プレフィックスとパリティの状態を交互に繰り返す古典的なゲームになります。 より深い結果は、最適なプレイが非常に小さなグローバル戦略のセットに崩壊するということです。プレーヤーは、グローバルゲインを即座に最大化するために手を使用するか、最小限の修正を強制するかのどちらかです。`k`が巨大な場合、ゲームは最初の数手の後に周期的または定常的なパターンに安定します。 解決策は、どれだけの効果的な「有用な」操作が重要であるかを計算することに帰着しますが、それは、`k`単一セグメントの最良の利得と単一セグメントの最悪の損失。 

したがって、ゲーム全体を、配列の合計に対する最良の単一操作の効果を評価し、プレイヤーがその値またはその逆を交互に実行できるかどうかを推論することに要約します。

 ## アルゴリズムのチュートリアル

 1. 定数値を計算する`M = 2^x - 1`。 これは、任意の要素が取り得る最大値であり、補数変換を定義します。 
2. 配列を「ゲイン配列」に変換します。ここで、各要素は、その位置が 1 回反転された場合の合計の変化を表します。 それぞれについて`a[i]`、計算する`b[i] = M - 2 * a[i]`。 これにより、反転の影響が分離されます。セグメントに反転を適用すると、次の合計が加算されます。`b[i]`そのセグメントの合計を合計します。 
3. 移動前のベースラインとなる配列の初期合計を計算します。 
4. セグメント演算により次の合計が加算されることを観察します。`b[i]`そのセグメント上で実行されるため、各移動は効果的に部分配列を選択し、その合計を加算します (その後、将来の重複のために暗黙的に符号を反転します)。 これにより、それぞれの動作が、何らかの値に寄与するサブ配列を選択することになります。 
5. サブ配列の最大合計を計算します。`b`と最小の部分配列の合計`b`。 最大値は可能な限り最善の動きに対応し、最小値は（対戦相手が強制できる）可能な最悪の動きに対応します。 
6. ゲームオーバーについて考えてみましょう`k`動く。 各移動では最大化と最小化が交互に行われるため、一連の寄与は最良のサブアレイ ゲインと最悪のサブアレイ ゲインの間で繰り返される相互作用になります。 最終的な効果は、各プレイヤーが何回動きを適用できるかによってのみ決まります。 
7. もし`k`は奇数で、最初のプレイヤーには 1 つの余分な動きがあり、結果は次のようになります。 

初期合計 + (猫猫の手数) * best_gain + (壬氏の手数) * worst_gain。 
8. もし`k`が偶数の場合、両方のプレーヤーが同じ動きをし、最終結果は次のようになります。 

初期合計 + (k/2) * (best_gain + worst_gain)。最適な再生により極端なセグメントが交互に配置されるためです。 

### なぜ効果があるのか

 重要な不変条件は、すべての動きは配列上の線形関数による現在の構成にのみ依存し、その関数は正確に次の合計であるということです。`b[i]`選択したセグメント上で。 セグメントの選択は定義に影響を与えないため、`b`、ゲーム全体は、交互制御の下で部分配列の極値を繰り返し選択することになります。 新しい構造を導入する動きはありません。 同じゲインランドスケープのみを再利用します。 これにより、ゲームは 2 つの極端な操作を繰り返し適用することになり、最終状態が完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_subarray(arr):
    best = -10**30
    cur = 0
    for v in arr:
        cur = max(v, cur + v)
        best = max(best, cur)
    return best

def min_subarray(arr):
    best = 10**30
    cur = 0
    for v in arr:
        cur = min(v, cur + v)
        best = min(best, cur)
    return best

t = int(input())
for _ in range(t):
    n, x, k = map(int, input().split())
    a = list(map(int, input().split()))

    M = (1 << x) - 1

    base = sum(a)
    b = [M - 2 * v for v in a]

    best = max_subarray(b)
    worst = min_subarray(b)

    if k % 2 == 1:
        moves_a = (k + 1) // 2
        moves_b = k // 2
    else:
        moves_a = moves_b = k // 2

    ans = base + moves_a * best + moves_b * worst
    print(ans)
```このソリューションでは、演算の前にまず配列のベースライン合計を計算します。 次に、各要素をそのフリップ デルタに変換し、セグメント反転の効果を相加的な寄与に線形化します。 

Kadane スキャンは、考えられる最良および最悪のセグメント効果を計算します。 これらは、プレイヤーが 1 回の動きで強制できる内容を表します。 最後のステップでは、これらのゲインをターン順序に従って分配します。これは、各プレーヤーが 1 つの動きにつき 1 つのセグメントだけを寄与し、順序によって最良の選択と最悪の選択のどちらがより頻繁に優先されるかが決まるためです。 

微妙な点は、同じセグメント構造が移動間で再利用されるため、移動のたびに配列を再計算する必要がないことです。 すべてのエフェクトは一度キャプチャされます`b`。

 ## 特殊なケース

 微妙なケースの 1 つは、すべての要素が次と等しい場合です。`0`またはすべて等しい`2^x - 1`。 その状況では毎回`b[i]`は一様に最大または最小のいずれかになり、両方の Kadane 結果は予測可能な極端な値に崩壊します。 サブ配列の最大値と最小値が引き続き正しい定数値を返し、パリティ ベースの集計によって偽の構造が出現しないことが保証されるため、アルゴリズムはこれをきれいに処理します。 

もう 1 つのエッジケースは次のような場合です`k`とても大きいですが、`n`小さいです。 解決策は依然として無視します`k`パリティと除算を除いて完全に大きさが変化するため、オーバーフローや反復爆発のリスクはありません。 

最後の重要なケースは、最適なサブ配列が負の場合です。 これは、セグメントを反転することが有害な場合に発生します。 Kadane の実装では、依然として最も害の少ないセグメントが正しく選択されており、対戦相手の最悪の選択はさらにマイナスになり、正しいミニマックス バランスが生成されます。
