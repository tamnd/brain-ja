 ## 解決策
 ## 問題の理解

 この問題は、糸に沿って移動するカエルについて説明しています。 すべての位置には 1 つの文字が含まれており、文字は小文字、大文字、数字の 3 つのカテゴリのいずれかに属します。 カエルは最初の位置からスタートし、最後の位置に到達したいと考えています。 ジャンプでカエルを前進させることができるのは最大で`k`ただし、カエルは現在の位置と同じカテゴリのキャラクターを含む位置にのみ着地できます。 

課題は、最後まで到達するために必要な最小限のジャンプ数を見つけるか、それが不可能であると報告することです。 

入力により、文字列の長さ、最大ジャンプ長、および文字列自体が得られます。 出力は、最初の文字から最後の文字に移動するために必要な有効なジャンプの最小数です。 

文字列の長さは 200,000 に達する場合があります。 考えられるルートの数は指数関数的に増加する可能性があるため、考えられるすべてのパスを繰り返し試行するソリューションはすぐに除外されます。 すべてのポジションのペアをチェックするアプローチさえも有効になる可能性があります`n²`これは上限で約 400 億回の操作に相当し、通常の時間制限をはるかに超えています。 

重要なのは、カエルは右にしか動かないということです。 サイクルがないため、ポジションを順番に処理し、将来のジャンプに重要な情報のみを保持できます。 

いくつかのケースは見落とされやすいものです。 

最初の文字と最後の文字のカテゴリが異なる場合、答えは不可能です。 例えば：```
5 3
aB123
```最初の文字は小文字で、最後の文字は数字です。 カエルはカテゴリを変更できないため、正解は次のとおりです。```
-1
```不注意な実装では、正しいタイプの位置が末尾近くに存在するかどうかだけをチェックする可能性がありますが、カエルはパス全体を通じてそのカテゴリを保持する必要があるため、それだけでは十分ではありません。 

もう 1 つの注意が必要なケースは、正しいカテゴリが存在するにもかかわらず、カテゴリよりも大きなギャップがある場合です。`k`。 

例：```
6 2
aaabca
```最初と最後の文字は小文字ですが、小文字の位置は次のとおりです。`1, 2, 3, 6`位置 3 から位置 6 へのジャンプは長さ 3 ですが、大きすぎます。 答えは次のとおりです。```
-1
```存在する有効な位置の数のみをカウントする実装では、パスが存在すると誤って認識されてしまいます。 

最後のエッジケースは、すべての有用なジャンプが正確に最大許容長に達している場合です。 

例：```
7 3
aaaaaaa
```カエルはジャンプできます。`1 -> 4 -> 7`したがって、答えは次のとおりです。```
2
```厳密な使用法`< k`代わりに比較`<= k`ここで失敗するだろう。 

## アプローチ

 問題を解決する簡単な方法は、考えられるすべての動きをシミュレートすることです。 到達可能なすべての位置から、距離内のすべての次の位置を試します`k`、そのキャラクターが同じカテゴリを持つかどうかを確認して、続行します。 考えられるすべてのパスが検討されるため、これは正しいです。 

問題は仕事量です。 最悪の場合、どのポジションでもほぼトライできる`k`次のポジション。 両方なので`n`そして`k`200,000 に近くなる可能性があり、これはおよそになります`O(nk)`、これは大きすぎます。 

有益な観察は、すべてのジャンプが前方にのみ進むという事実から得られます。 考えられるすべてのパスを知る必要はありません。 各キャラクター カテゴリの最新の到達可能な位置に対する最良の答えだけが必要です。 

私たちが現在、あるカテゴリーの位置にいると仮定してください。 同じカテゴリの将来の位置には、その後ろの到達可能な最も遠い位置から到達できます。これは、残りのジャンプ距離が最大となるためです。 到達可能な最も遠い位置が少なくとも`i - k`、現在位置に到達可能です。 

これにより、問題が 1 回のスキャンに変換されます。 左から右に移動しながら、3 つのカテゴリごとに最後に到達可能な位置を維持します。 キャラクターに遭遇するたびに、そのカテゴリーの以前の到達可能な位置が十分に近いかどうかを確認します。 そうであれば、必要なジャンプの数を更新し、この位置を到達可能としてマークします。 

3 つのカテゴリは 3 つの状態に圧縮できます。 アルファベットのグループが固定されているため、マップや複雑なデータ構造は必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nk) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての文字を 3 つのカテゴリ識別子のいずれかに変換します。 小文字、大文字、数字はそれぞれ独自の状態になります。 これにより、アルゴリズムは実際の文字を気にせずにカテゴリを比較できるようになります。 
2. 最初の位置から開始します。 ジャンプゼロで常に到達可能であるため、そのカテゴリの最新の到達可能な位置として保存します。 
3. 文字列を左から右にスキャンします。 すべてのポジションについて、同じカテゴリで最近到達可能なポジションを調べます。 

その位置が以内であれば`k`現在の文字の後ろにある文字がある場合、カエルはそこにジャンプできます。 現在位置に到達可能になります。 
4. 位置が到達可能になったら、そこに到達するために必要なジャンプの数を更新します。 最小ジャンプ数は、前の位置の答えに 1 を加えることによって求められます。 

保存された到達可能な位置は、常にそのカテゴリで可能な最も遠い位置です。 より遠くに到達可能な位置は、カエルが次のジャンプに使用できる距離をより長くできるため、常に近くの位置と少なくとも同じくらい役立ちます。 
5. 文字列全体を処理した後、最後の位置に到達できたかどうかを確認します。 そうでない場合は、印刷してください`-1`。 

なぜ効果があるのか:

 不変条件は、文字列の接頭辞を処理した後、カテゴリごとに、カエルが到達できるその接頭辞内の最も遠い位置と、そこに到達するために必要な最小限のジャンプ数を保存することです。 新しい位置を処理するときは、以前の有効なジャンプが同じカテゴリに属している必要があります。 現在の位置に到達できない場合は、それ以前の位置にも到達できないため、到達可能な最も遠い位置のみが重要です。 現在の位置に到達できる場合は、それを使用するとジャンプの回数が最小限で済みます。 これにより、すべての位置に対して不変式が true に保たれ、最終的な答えが最適であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    def get_type(c):
        if 'a' <= c <= 'z':
            return 0
        if 'A' <= c <= 'Z':
            return 1
        return 2

    last = [-1, -1, -1]
    dist = [-1] * n

    dist[0] = 0
    last[get_type(s[0])] = 0

    for i in range(1, n):
        t = get_type(s[i])

        if last[t] != -1 and i - last[t] <= k:
            dist[i] = dist[last[t]] + 1
            last[t] = i

    print(dist[-1])

if __name__ == "__main__":
    solve()
```の`get_type`関数は、すべての文字を 3 つの状態のいずれかに減らします。 これにより、アルゴリズム全体で繰り返し範囲をチェックすることが回避され、メイン ループが単純に保たれます。 

の`last`配列には、カテゴリごとに到達可能な最も遠い位置が格納されます。 到達不可能な位置は将来のジャンプに役立たないため、位置が到達可能な場合にのみ更新する必要があります。 

距離配列には、すべての位置に到達するために必要なジャンプの最小数が格納されます。 有効なジャンプが見つかった場合、現在の答えは、以前の到達可能な位置の答えより正確に 1 だけ増えます。 

境界チェックでは以下を使用します。`<= k`正確な長さのジャンプだから`k`許可されています。 位置は左から右に処理されるため、後方への移動や状態の再訪は必要ありません。
