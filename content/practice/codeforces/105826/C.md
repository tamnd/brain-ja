 ## 解決策
 ## 問題の理解

 私たちはコーヒーカップの中で時間の経過とともに何が起こるかをシミュレーションしています。 カップは空の状態で開始され、その後、カップにある程度の量のコーヒーを注ぐか、カップからある程度の量を飲むという一連の操作を処理します。 

重要な点は、コーヒーが概念的に階層化されていることです。 新しいコーヒーが注がれるたびに、既存の液体の上に新しい層が形成されます。 コーヒーを除去するときは、常に最初に最上層から除去され、除去された量が十分に多い場合は複数の層を消費する可能性があります。 

「コーヒーリング」は、このプロセス中に作成されたコーヒーの層間の境界に対応します。 最終的にすべてのコーヒーが取り除かれても、空のカップは依然として底部レベルで最後のリングに貢献します。 

したがって、このタスクはコーヒーの最終量を追跡することではなく、プロセス全体を通じて明確な層の境界がいくつ存在するかを追跡することです。 

入力は、「add X」（X ミリリットルを注ぐ）または「remove X」（X ミリリットルを飲む）という形式の一連の操作です。 出力は、すべての操作を実行した後に形成されるコーヒー リングの合計数です。 

制約が十分に大きいため、すべてのミリリットルにわたる二次シミュレーションは不可能です。 各操作を一定時間または対数時間で処理する必要があります。つまり、コーヒーを個々の単位ではなく構造化されたセグメントとして扱う必要があります。 

1 つの操作が複数のレイヤーを部分的に消費する場合、微妙な失敗のケースが発生します。 たとえば、サイズのレイヤーがある場合、`[3, 5]`そして削除します`4`、最上層が消え、2 番目の層が部分的に減少します。 構造を維持せずに各操作を独立して処理する単純な実装では、レイヤーの境界が誤ってカウントされます。 

もう 1 つのエッジケースは、すべてのコーヒーが除去される場合です。 たとえば:

 入力:```
3
+5 -3 -2
```すべてを処理した後、カップは空になりますが、答えはゼロではありません。 カップの底に相当するリングが 1 つだけ残っています。 「既存のレイヤー」のみをカウントする単純なソリューションでは、誤って 0 が出力されます。 

## アプローチ

 強引な解釈では、ミリリットルの解像度でコーヒーをシミュレートします。 すべての注ぎを個別のユニットに拡張し、ユニットのスタックを維持してから、ユニットを 1 つずつポップして各ドリンクをシミュレートします。 これは正しいですが、最悪の解釈では 1 つの操作に最大 10^9 ユニットが関与する可能性があり、さらに厳しい制約下でも総量によりこのアプローチは使用できなくなるため、すぐに実行不可能になります。 

重要な観察は、個々のミリリットルを追跡する必要がないということです。 同じ「世代」を共有する連続したコーヒーのブロック、つまり、後の中断の前に 1 回の操作で注がれたコーヒーのブロックのみを追跡する必要があります。 

注ぐたびに新しいレイヤーが作成されます。 飲み物は最上層のみを除去し、部分的に減少させることも、完全に除去することもあります。 これは当然、各要素がレイヤーとその残りのボリュームを表すセグメントであるスタックを維持することを示唆しています。 

リングの数は、これまでに作成され完全には除去されなかったセグメントの数とカップの底の最終境界によって決まります。 

これにより、セグメント サイズのスタックを維持し、操作ごとに最上位の要素のみを更新するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 カップをレイヤーのスタックとしてモデル化し、各レイヤーにはそのレイヤーに残っているコーヒーの量が保存されます。 

1. 空のスタックを初期化します。 各要素は、流し込み操作によって作成されたレイヤーを表します。 
2. 「X を注ぐ」操作の場合は、値 X を持つ新しい要素をスタックにプッシュします。 これは新しい上層を作成することを表しており、カップの構造に新しい境界が即座に導入されます。 
3. 「ドリンク X」操作では、スタックの一番上から繰り返し減らします。 最上層の残りの量から X を引きます。 最上位のレイヤーがゼロになった場合は、スタックからそのレイヤーを完全に削除し、次のレイヤーからの減算を続けます。 これは、飲み物を飲むと常に一番上のコーヒーが最初に消費されるという物理的な考え方を反映しています。 
4. X が完全に消費されるまで続けます。 これにより、1 つのドリンクが以前に注がれた複数のレイヤーにまたがる場合でも、影響を受けるすべてのレイヤーが正しく更新されます。 
5. すべての操作を処理した後、リングの数は、スタックに残っている層の数に、カップの底に追加のリングを 1 つ加えたものに等しくなります。 スタックが空の場合、答えは 1 です。 

### なぜ効果があるのか

 いつでも、スタックは、連続した注ぎによって形成される最大の連続セグメントへのカップの正しい分割を表します。 プッシュするたびに、新しいセグメント境界が 1 つだけ作成されます。 セグメントを完全に削除するたびに、その境界は永久に削除されます。 部分的な削除ではセグメントの数は変更されず、セグメントのサイズのみが変更されます。 ドリンクはレイヤーの順序を変更することはなく、常に上から動作するため、プロセス全体を通じてスタックの不変性が維持されます。 セグメントの最終的な数は、任意の時点で同時に存在した個別のコーヒー層の数と正確に一致し、そのような各層は 1 つのリング境界に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    stack = []

    for _ in range(n):
        op = input().strip()
        if op[0] == '+':
            x = int(op[1:])
            stack.append(x)
        else:
            x = int(op[1:])
            while x > 0 and stack:
                if stack[-1] > x:
                    stack[-1] -= x
                    x = 0
                else:
                    x -= stack[-1]
                    stack.pop()

    # number of layers + bottom ring
    if not stack:
        print(1)
    else:
        print(len(stack) + 1)

if __name__ == "__main__":
    solve()
```コードはスタック モデルを直接実装します。 注ぐたびに新しいレイヤーが追加されます。 各ドリンクは慎重に最初に最上層を減らし、複数の層を順番に除去する可能性があります。 最終的な答えは、残りの層の数にベース リングを加えたものから導出されます。 

よくある実装上の間違いは、レイヤーが完全に削除された後に減算を続けるのを忘れることです。 もう 1 つは、部分レイヤーの永続性を維持せずに、各操作を独立して処理することです。

 ## 特殊なケース

 重要なエッジケースの 1 つは、注がれたコーヒーがすべて最終的に取り除かれる場合です。 考慮する：```
2
+10
-10
```処理後、スタックは空になります。 コーヒーが残っていない場合でも、下部の境界はリングとしてカウントされるため、アルゴリズムは正しく 1 を出力します。 単純な「レイヤー数」アプローチでは、誤って 0 が出力されます。 

ドリンクが複数の層にまたがる場合、別のエッジ ケースが発生します。```

+3
+4
-5
```スタックは段階的に進化していきます。`[3, 4]`に`[2]`。 最上層は完全に除去され、次の層は部分的に縮小されます。 スタック サイズは正しく減少し、各要素がまだアクティブなレイヤーの境界に対応するという不変条件が維持されます。
