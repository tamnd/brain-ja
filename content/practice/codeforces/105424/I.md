 ## 解決策
 ## 問題の理解

 次のサイズの 1 次元ボードが与えられます。$N$、トークンはセル 1 から始まり、セルに到達する必要があります。$N$。 これらのエンドポイントの間の一部のセルには、トークンがそこに着地するたびに一定量だけ左に押し出す「ヘビ」が含まれています。 

移行は、単なる 1 つの決定的な移行ではありません。 代わりに、各ターンは 1 から 6 までのサイコロを振ることから始まります。トークンはその量だけ右に移動しますが、セルを通過しないように固定されています。$N$。 着地後、セルにヘビが含まれている場合、ヘビのいないセルに到達するまで、トークンはセルの値に従って左に繰り返し引っ張られます。 この連鎖反応は、同じ着地位置内で複数回発生する可能性がありますが、同じターン内でのみ発生します。 

特別な工夫は、6 を転がしても必ずしもターンが終了するとは限らないことです。 6 が表示された場合、プレイヤーはすぐにもう一度ロールを続けて、同じメカニズムを適用し、すべて 1 ターン以内に行うことができます。 他のロールは、結果として生じる一連の動きを処理した直後にターンを終了します。 

目標は、セルに到達するために必要な最小ターン数を決定することです。$N$、最適なプレイを想定し、役に立たない場合は「不運な」サイコロの順序を無視することさえ許可します。 決して到達する方法がないなら$N$、答えは$-1$。 

ボードのサイズは最大です。$2 \cdot 10^5$したがって、サイコロの結果を明示的にシミュレートしたり、ターンごとおよびロールごとに状態を調査したりするソリューションは、遅すぎます。 ソリューションでは、サイコロのランダム性を状態全体にわたる決定論的な最適化に圧縮する必要があります。 

微妙な問題は、ヘビに着地すると複数回カスケードする可能性があることです。 もう 1 つは、ローリング 6 により 1 つのターン内で移動を連鎖させることができ、ターン カウンターを増分することなく複数のトランジションを効果的にマージできることです。 

単純な間違いは、各セルをエッジを持つ単純なノードとして扱うことです。$i+1 \dots i+6$。 これは両方のクランプを無視します$N$そして、強制的な左方向へのヘビの伝播により、到達可能な位置が大幅に変化する可能性があります。 

もう 1 つの失敗モードは、各ダイスのロールを個別の BFS エッジ コスト 1 として扱うことです。これは、ロール シーケンスではなくターンを誤ってカウントし、特別な「6 で継続」ルールも無視します。これにより、一部のシーケンスは現在のターンを自由に延長できます。 

## アプローチ

 直接的なシミュレーションの観点では、各状態を位置と回転構造からなるペアとして扱います。 ある位置から、考えられるすべてのサイコロの結果を試し、正しい動きをシミュレートし、安定するまでスネーク トランジションを繰り返し適用します。 次に、出目が 6 だったかどうかに応じて、ターンが終了するか継続するかを決定します。 

このモデルは、ノードがボードの位置であるが、エッジがターンのグループ化によって複雑になっているグラフを提案します。 すべてを明示的に展開すると、各状態遷移はサイコロの出目に対応し、まだ同じターン内にいるのか、それとも新しいターンを開始しているのかを区別する必要があります。 これにより状態空間が 2 倍になり、最大で$6N$レイヤーごとのトランジションにより、$O(6N)$ターン層ごとの BFS。ターン数に制限がなく、各状態遷移のコストが均一ではないため、それでも大きすぎます。 

重要な観察は、停止する前に少なくとも 1 つの非 6 が発生するかどうかを除いて、ターン内のロールの正確な順序は無関係であるということです。 ターンは最大数回の連続した動きのバーストのように動作し、最初の 6 以外のロールのみがバーストを終了します。 最小ターン数が必要なため、正確なダイス履歴ではなく、一定のバースト数内で状態に到達できるかどうかのみを考慮します。 

これにより、各位置遷移がフル ターンの結果に対応する位置上の最短経路として問題を再解釈することができます。 1 ターン内で、任意の数の 6 の後に 1 から 5 までの 1 つの最後のロール (または、解釈によっては確定後にターンを終了する 6) の効果をシミュレートできますが、重要な単純化は、1 ターン内でサイコロ 6 で連鎖する複数の右の動きを実行できるという点で、各中間の位置はすぐにヘビを解決します。 

したがって、各ターンは、一連の決定的な「解決して再度ロールする」ステップを通じてトークンを進める一連の動きを選択することに相当します。ここで、ターンコストに影響を与える唯一の分岐は、継続するか終了するかです。 この構造は当然、各ノードがセルであり、エッジが 1 ターン以内に到達可能なすべての最終位置を表す BFS によって処理されます。 

これらのエッジを効率的に計算するために、0-1 スタイルの拡張を使用してターン内をシミュレートします。6 を介して移動すると新しいターンはかかりませんが、6 以外の場合はターンが終了します。 これをターン レイヤーごとのマルチソース BFS としてモデル化することも、二次的な意味で 6 に対応するエッジのコスト 0 とコスト 1 の 1 ～ 5 に対応するエッジのコスト 1 を持つ最短パスとしてより明確にモデル化することもできますが、最終的にはターン境界内で到達可能な状態を拡張することで、すべてを「最小ターン」BFS にまとめます。 

主な技術的なボトルネックは、スネーク チェーンを効率的に解決することです。 各セルは左を指しているため、繰り返し適用すると、後方エッジのみを持つ関数グラフが形成されます。 パス圧縮スタイルのメモ化または反復折りたたみを使用してヘビを完全に解決した後、最終的な着地位置を事前計算し、各セルがほぼ O(1) で解決されるようにすることができます。 

すべての動きが決定論的な「スネーク解決後」の位置に削減されると、トランジションがきれいになります。ある位置から、サイコロの目 k が私たちを次の位置に送ります。$resolve(\min(i+k, N))$。 次に、ローリング 6 を同じターン内での探索の継続を許可するものとして扱います。これは、k=6 の遷移のシーケンスを介して到達可能なすべてのノードがゼロコスト エッジの下で連結コンポーネントを形成し、1..5 の任意の k が移動後にターンの増分をトリガーすることを意味します。 

これにより、問題は BFS に縮小され、最初にゼロコスト エッジ (6 移動チェーン) を拡張し、次に 1 ～ 5 移動の +1 コスト エッジを重ねます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 指数 | O(N) | 遅すぎる |
 | スネーク圧縮を使用した状態にわたる 0 ～ 1 BFS | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 関数を事前計算する`go[i]`これは、i に着地し、ヘビ ジャンプを繰り返し適用した後の最終的な位置を示します。 これにより、すべての動きを単一の決定的な遷移として扱うことができます。 その理由は、スネーク チェーンが分岐することがないため、繰り返し適用すると常に定点に収束するためです。 
2. 各セル i から最大 6 つの宛先への遷移を構築します。`go(min(i+k, N))`k は 1 から 6 までです。これらは、サイコロを振ってすべての強制的な動きを即座に解決する効果を表します。 
3. ロール 6 の遷移はターンを終了しないためゼロコストのエッジとして解釈されますが、ロール 1 ～ 5 はターンを終了するエッジに対応するため、ターン カウントが 1 増加します。この分離は、6 以外のロールのみがターンを終了するというルールを捉えています。 
4. 距離 0 のセル 1 から開始して 0-1 BFS を実行します。コスト 0 の遷移 (k=6) が前方にプッシュされ、コスト 1 の遷移 (k=1..5) が後方にプッシュされるデキューを使用します。 これにより、状態がターンの昇順で処理されるようになります。 
5. セル N に到達したら停止します。 到達できない場合は、-1 を返します。 

正確かどうかは、一連のサイコロの出目が最初の 6 以外の目で終わるセグメントに分解でき、各セグメント内のすべての中間遷移がゼロコスト展開であるという事実にかかっています。 BFS により、常に最小数のそのようなセグメントが最初に処理されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    N = int(input())
    p = [0] * (N + 1)
    arr = list(map(int, input().split()))
    for i in range(2, N):
        p[i] = arr[i - 2]

    # resolve snake chains
    resolved = [-1] * (N + 1)

    sys.setrecursionlimit(10**7)

    def get(x):
        if resolved[x] != -1:
            return resolved[x]
        if x == 1 or x == N:
            resolved[x] = x
            return x
        if p[x] == 0:
            resolved[x] = x
        else:
            resolved[x] = get(x - p[x])
        return resolved[x]

    for i in range(1, N + 1):
        get(i)

    dist = [-1] * (N + 1)
    dist[1] = 0
    dq = deque([1])

    while dq:
        v = dq.popleft()
        if v == N:
            print(dist[v])
            return

        for k in range(1, 7):
            nv = v + k
            if nv > N:
                nv = N
            nv = resolved[nv]

            nd = dist[v] + (0 if k == 6 else 1)

            if dist[nv] == -1 or nd < dist[nv]:
                dist[nv] = nd
                if k == 6:
                    dq.appendleft(nv)
                else:
                    dq.append(nv)

    print(-1)

if __name__ == "__main__":
    solve()
```前処理ステップでは、すべてのスネーク効果後の各セルの最終的な着地位置を計算します。 これにより、BFS 中に再計算が繰り返されることがなくなり、各遷移が O(1) になることが保証されます。 

BFS はデキューを使用して 0 ～ 1 BFS ロジックを実装します。 k=6 の動きはゼロコストのエッジとして扱われ、前面に押し出されますが、他のすべての動きはターン数を増加させて背面に押し出されます。 

微妙なポイントはクランプです`v + k`に`N`、これは、移動が最後のセルを超えてはいけないというルールに一致します。 もう 1 つの重要な詳細は、ヘビが最終的な着地位置に適用されるため、クランプ前ではなくクランプ後の解決です。

 ## 特殊なケース

 重大なエッジ ケースは、深い後方ポインタ構造を形成するヘビの長いチェーンです。 このような場合、単純な反復シミュレーションでは中間状態が繰り返し再計算され、二次的な動作に低下します。 メモ化されたもの`get(x)`各セルが一度解決されることを保証し、深さに関係なくチェーンを単一のエンドポイントに折りたたみます。 

もう 1 つのエッジ ケースは、トークンが繰り返し着地する場合です。$N$オーバーシュートによるクランプが原因です。 クランプはスネークの解決前に発生するため、終わり近くの大きなロールは依然として正しく解決される必要があります。$N$たとえ中間セルにヘビが含まれていたとしても。 BFS は呼び出し前に明示的にクランプします。`resolved`、正確性を保証します。 

最後の微妙なケースは、ヘビがトークンを自分自身に送り返すか、サイクルを形成する場合です。 なぜなら`p[i] < i`、すべてのエッジは厳密に左に向かうため、サイクルは存在できません。 これにより、解決機能の終了が保証され、訪問状態の追跡なしでメモ化が正当化されます。
