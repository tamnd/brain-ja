 ## 問題の理解

 私たちに与えられた構造は、$N$独立した部品。 各部品には必要な標準重量があります$s_i$、現在の構成には重みがあります$a_i$。 構成のコストは絶対差の合計ではなく、正規化された偏差です。各部分が寄与します。$\frac{|a_i - s_i|}{s_i}$、合計偏差はこれらの寄与の合計です。 

各操作で 1 つの値を増減する単位操作を実行できます。$a_i$by 1.すべての操作に 1 分のコストがかかります。 目標は、配列の変換中に費やす操作をできるだけ少なくすることです。$a$最終的な配列に$a'$の合計偏差が$a'$せいぜい$K$。 

重要な問題は、すべての部品をターゲットとまったく同じにする必要がないことです。 全体の重み付け偏差をしきい値以下に減らすだけでよく、それを最小限の合計ユニット調整で実現したいと考えています。 

制約$N \le 10^5$あらゆる解を線形に近づけるか、$N \log N$。 各操作は異なるコンポーネントに影響を与える可能性があるため、ユニットごとのシミュレーションは不可能です。 

微妙な点としては、$s_i \le 10$これにより、偏差式の重みが小さな整数になります。 この有界分母がソリューションの構造的なレバーになります。 

単純な間違いは、常にすべての量を削減する必要があると想定することです。$a_i$向かって$s_i$。 一部の部品が偏差の観点から改善するには「コストがかかる」場合、これは必ずしも最適ではありません。 もう 1 つの罠は、正規化を考慮せずに最大の絶対差を貪欲に減らそうとすることです。$s_i$、不均一な方法で優先順位を変更します。 

具体的な障害シナリオとしては、次のように考えます。$s = [1, 10]$、$a = [100, 11]$、 そして$K = 0$。 単純な戦略では、両方の値をターゲットに向かって均等に削減する可能性がありますが、正規化が大幅に異なるため、最初の部分を削減することは、最初に 2 番目の部分を修正するよりも、操作ごとの偏差削減の点ではるかに効率が低くなります。 正しいソリューションでは、生の差ではなく、操作ごとの限界利益を評価する必要があります。 

## アプローチ

 強引な解釈とは、プロセスを段階的にシミュレートすることです。 1 分ごとに 1 つのインデックスを選択し、合計偏差を最も小さくする方向に 1 ずつ調整します。 更新のたびに、完全な偏差を再計算します。 

すべての状態遷移が有効であり、常に真の目的を追跡するため、これは概念的に機能します。 ただし、偏差を再計算するたびにコストがかかります$O(N)$まで実行する場合があります。$\sum |a_i - s_i|$操作。 以来$a_i$まで可能です$10^9$、最悪の場合の合計操作は以下に達する可能性があります。$10^{14}$、このアプローチは完全に実行不可能になります。 

重要な観察点は、インデックスに対する各単位操作が$i$非常に構造化された方法でそのインデックスの偏差を変更します。 もし$a_i > s_i$、減少$a_i$偏差を正確に減らす$\frac{1}{s_i}$に達するまでの単位ステップごと$s_i$。 もし$a_i < s_i$、値を増やすと、ステップごとに偏差が同じ量だけ減少します。 これは、各インデックスが固定の傾きの大きさで線形の「偏差バジェット」に寄与することを意味します。$1/s_i$ただし、目標に到達するまでのみです。 

したがって、すべての操作は、選択したインデックスに応じて既知の定数だけ合計偏差を減らすために 1 単位の時間を費やすことと同等です。 したがって、最適な戦略は、単位コストあたりの削減が最大になる、つまりまさに最小となるインデックスに常に操作を費やすことです。$s_i$利用可能なインデックスの中には、$\frac{1}{s_i}$より大きいとき$s_i$より小さいです。 

ただし、単一のインデックスから無限に多くのリダクションを自由に選択できるわけではありません。各インデックスで許可されるのは、$|a_i - s_i|$使える操作。 これにより、問題が複数の「削減単位」に変換され、それぞれが値を持ちます。$1/s_i$、合計偏差が最大以下に低下するまで、最小の単位数を選択したいと考えています。$K$。 

以来$s_i \le 10$、考えられる効率の種類は 10 種類だけなので、グループ化が可能です。$s_i$そして貪欲に処理します。

 ## アルゴリズムのチュートリアル

 偏差をどの程度削減できるかを推論できるように、偏差を再構成します。 

1. 初期合計偏差を計算します。$D = \sum \frac{|a_i - s_i|}{s_i}$。 これが現時点での実現可能性までの「距離」です。 最大でも次の値まで削減したいと考えています$K$したがって、必要な削減量は次のようになります。$R = D - K$。 もし$R \le 0$、操作は必要ありません。 
2. インデックスごとに$i$、その絶対的な不一致を計算します$d_i = |a_i - s_i|$。 これは、このインデックスを改善できる単位操​​作の最大数です。 
3. インデックスですべてのユニットが調整されていることを確認します。$i$合計偏差を正確に減少させます$\frac{1}{s_i}$まだ到達していない限り、$s_i$。 これは、各インデックスが同一の「メリット項目」の線形シーケンスに寄与することを意味します。 
4. ユニットごとに繰り返す代わりに、すべてのインデックスをそのインデックスごとにグループ化します。$s_i$。 以来$s_i \le 10$、各グループが配置される周波数配列を維持します。$g[x]$利用可能な操作の合計と操作ごとの偏差の合計削減量を格納します。$1/x$。 
5. ここで、各グループから取得する操作の数を決定します。 より小さいグループ$s_i$操作ごとに大きなメリットが得られるため、グループを昇順に処理します。$s_i$。 
6. 固定グループの場合$s$、そこから必要な操作の数を検討します。 このグループで使用可能なすべての操作を実行すると、残りの必要な削減がゼロ以下になる場合は、部分量のみを取得して終了します。 
7. 必要な削減量が正でなくなるまで演算を累積します。 累積した数が答えになります。 

中心的なアイデアは、各操作がそのグループにのみ依存して固定ゲインに寄与するということです。そのため、クラスごとに均一なアイテム値を持つ貪欲なナップザックを解決しています。 

なぜ効果があるのか:

 いつでも、より小さいインデックスに対する操作が可能です。$s_i$常に、より大きなサイズでの操作と少なくとも同程度の偏差の削減が提供されます。$s_i$、ステップごとの削減により、この順序はプロセス中に変更されることはありません。$\frac{1}{s_i}$は一定です。 したがって、実行可能性に影響を与えることなく、利益のより高いすべての操作が最初に来るように、最適な操作シーケンスを再配置することができます。これにより、次のような貪欲な順序付けが保証されます。$s_i$が最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = list(map(int, input().split()))
    a = list(map(int, input().split()))

    groups = [[] for _ in range(11)]

    total_deviation = 0.0

    for i in range(n):
        diff = abs(a[i] - s[i])
        if diff == 0:
            continue
        total_deviation += diff / s[i]
        groups[s[i]].append(diff)

    need = total_deviation - k
    if need <= 0:
        print(0)
        return

    ops = 0

    for val in range(1, 11):
        if need <= 0:
            break
        if not groups[val]:
            continue

        total_ops = sum(groups[val])

        reduction_per_op = 1.0 / val
        max_reduction = total_ops * reduction_per_op

        if max_reduction >= need:
            ops_needed = int(need * val + 1e-12)
            ops += ops_needed
            need = 0
        else:
            ops += total_ops
            need -= max_reduction

    print(ops)

if __name__ == "__main__":
    solve()
```解決策は、定義から直接初期偏差を計算することから始まります。 各インデックスは独立して寄与するため、合計します。$|a_i - s_i| / s_i$。 

次に、しきい値に到達するためにどれだけの偏差を除去する必要があるかを計算します。$K$。 これがすでに満たされている場合、答えはゼロになります。 

グループ化$s_i$問題を 10 個の独立したバケットに分割するため、これは非常に重要です。 バケット内の各単位操作により、偏差が一定量減少します。$1/s_i$したがって、必要なのはバケットごとに使用可能なオペレーションの合計数だけです。 

貪欲ループはバケットを最小のものから処理します。$s_i$最大まで。 バケットごとに、残りの要件を満たしているかどうかに応じて、完全に消費するか、部分的に消費します。 掛け算$need * val$必要な偏差の削減をそのバケットの操作数に変換します。 

実装上の微妙な問題は、偏差と演算数を比較および変換する際の浮動小数点精度です。 コードは、整数に変換するときに小さなイプシロンを使用することでこれを安定させます。

 ## 特殊なケース

 エッジ ケースの 1 つは、初期偏差がすでに許容しきい値内にある場合です。 例えば、$N=3$、$s=[1,2,1]$、$a=[1,2,1]$、$K=0$。 計算された偏差はゼロであるため、アルゴリズムは貪欲ループに入らずにすぐにゼロを返します。 

もう 1 つのエッジ ケースは、最小サイズのみの場合です。$s_i$グループはしきい値を超えるのに十分です。 この場合、アルゴリズムはグループの途中で停止し、次の乗算を使用して残りの必要なリダクションを部分的な演算数に変換します。$s_i$。 正確さは、グループ内で各操作が同じ値を持つという事実に依存しているため、部分選択は常に最適であり、明確に定義されています。 

3 番目のエッジ ケースは、すべてのグループが必要な場合です。 たとえば、大きな偏差が存在する場合、$s_i$、アルゴリズムはすべてのバケットを使い果たします。 すべてのグループが完全に消費されるため、答えは単にすべてのグループの合計になります。$|a_i - s_i|$これは、可能なすべての単位調整を使用する必要があるという事実と一致します。
