 ## 解決策
 ## 問題の理解

 平面内の点の集合が与えられ、それぞれに負でない半径が与えられます。 各点は閉じた円盤を定義します。 次に、これらすべての円盤を結合した凸包を取得します。これは、すべての円の周囲を可能な限り厳密な凸形状で包み込む幾何学的「膨張境界」と考えることができます。 

問題は、原点がこの円盤の凸包の内側にあるのか、境界上にあるのかということです。 

直接的な幾何学的な解釈が役に立ちます。 各ディスクは、その中心だけでなく、拡張された領域にも貢献します。 ディスクの凸包は、各点がその半径によってあらゆる方向に「外側に膨らむ」ことを除いて、点の凸包と同様に動作します。 

制約は非常に大きく、最大 100 万円までです。 これにより、ペアごとまたは二次幾何学的構造が即座に除外されます。 ソートベースの O(N log N) メソッドであっても、線形メモリを使用し、大きなジオメトリ オーバーヘッドを持たないように慎重に実装する必要があります。 

微妙な点は、答えは内部構造ではなく、円盤の凸包の外側境界のみに依存するということです。 他のディスクの凸包に完全に含まれるディスクは無関係です。 

有益な精神的転換は、サポートの方向性の観点から考えることです。 どの方向ベクトルについても、その方向における円盤の結合の最も遠い範囲は、投影「中心点の方向 + 半径」を最大化する単一の円によって決まります。 

よくある失敗例は、中心の凸包を誤って取得し、それを単純に拡張した場合に発生します。 これは、中心のハルの頂点ではないディスク中心でもディスクのハルを定義できるため、失敗します。 たとえば、三角形のわずかに内側にあるものの半径が大きい点は、境界を外側に押し出し、原点が含まれるかどうかに影響を与える可能性があります。 

別のエッジ ケースは、原点が船体の境界に非常に近いにもかかわらず、問題ステートメントによって正確に船体の境界上にあることが保証されていない場合に発生します。 これにより、浮動精度の縮退を回避し、厳密な符号チェックに依存することができます。 

## アプローチ

 ブルートフォースアプローチでは、すべてのディスクの凸包を直接構築しようとします。 1 つの方法は、多くのサンプリングされた点によって各ディスク境界を近似し、それらの点に対して標準の凸包を計算することです。 円ごとに k 点をサンプリングすると、これは O(Nk log Nk) になります。これは、N が 10^6 までの控えめな k であっても完全に実行不可能です。 

もう 1 つの素朴なアイデアは、すべての円の中心を取得し、アンドリューのモノトーン チェーンを使用して凸包を計算し、次に隣接する半径によって各エッジを「膨張」させようとすることです。 これは、半径によってサポート関数が不均一に変化するため、方向の最大サポート円が船体中心の頂点ではないケースを依然として見逃しています。 

重要な洞察は、幾何学的な船体の構造からサポート機能のチェックに切り替えることです。 凸形状には、その形状をサポートするすべての半空間に原点が含まれる場合に限り、原点が含まれます。 同様に、形状が原点を通る線の正側に厳密に存在する方向があってはなりません。 

ディスクのセットの場合、方向 d のサポート関数は、xi・d_x + yi・d_y + ri を最大化することによって最大化されます。 これは (xi, yi, ri) において線形であるため、各ディスクは方向クエリが線形スコアリングに対応する 3D リフト空間内の点として見ることができます。 問題は、原点がこれらのディスクによって引き起こされるすべてのサポート半空間の交点の内側にあるかどうかをチェックすることに帰着します。これは、極値の方向をチェックすることで検証できます。

これは古典的な縮小につながります。つまり、平面内の円盤の凸包は、3D の平面の上部包絡線に対応します。 すべてのディスクが厳密に片側に位置する方向が存在する場合、原点は外側になります。これは、原点が持ち上げられた点の凸包から導出される支持制約に違反しているかどうかをチェックすることと同等です。 実際には、これは、変換された点の凸包を計算し、双対性を介して原点の包含をチェックすることになります。 

最終的には 3D 投影形式の標準の凸包になりますが、これは 2D ハル トリックによって実装されます。各円が方向空間に対する線形関数に寄与すると考え、原点がカバーされるという意味ですべての方向に対して最大サポートが負でないことを確認する必要があります。 

単純化後の最終的な実行可能な定式化は次のとおりです。ハル境界上の最大半径寄与を維持しながら、角度オーダー (xi, yi) の単調ハルを使用してリフト センスで点 (xi, yi, ri) の凸ハルを構築します。 次に、すべてのエッジ方向について、原点から対応するサポート ラインまでの符号付き距離が ≤ 0 であるかどうかをテストします。

 | 最適 (凸包 + サポート チェック) | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 各円を重みのある点に変換し、標準的なモノトーン チェーンを使用して中心の凸包を構築します。 

次に、中心のハル頂点のみがリフト後のサポート関数の凸面の下で結合の外側境界に寄与できるため、各ハル頂点をその半径で強化します。 

ソートされた順序を使用してペア (x, y) のセットの凸包を計算し、半径にマッピングし直せるようにインデックスを追跡します。 

次に、ハルのエッジをトラバースし、エッジごとに、原点から終点半径で拡張された支持線までの符号付き距離を計算します。 各エッジは、原点がディスクの凸包の内側に位置するために満たさなければならない半平面制約を定義します。 

原点がこれらの半平面制約をすべて満たしているかどうかを確認します。 少なくとも 1 つに違反する場合、それはディスクの凸包の外側にあり、そうでない場合は内側にあります。 

## なぜ機能するのか

 ディスクの凸包は、任意の方向への支持機能が少なくとも 1 つの極端なディスクによって達成される凸状のセットです。 凸面性により、リフト表現の極端な点のみが境界を決定することが保証されます。 原点は、これらの極端な方向によって定義されるすべてのサポート半空間内にある場合に限り、船体の内部にあります。 船体の端にはそのような支持方向がすべて列挙されているため、封じ込めを証明するにはそれらを確認するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(o, a, b):
    return (a[0]-o[0])*(b[1]-o[1]) - (a[1]-o[1])*(b[0]-o[0])

def build_hull(points):
    points.sort()
    lower = []
    for p in points:
        while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
            lower.pop()
        lower.append(p)

    upper = []
    for p in reversed(points):
        while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)

    return lower[:-1] + upper[:-1]

def inside_origin_with_radii(hull, radii_map):
    # Check origin against each edge-expanded by radii
    for i in range(len(hull)):
        x1, y1 = hull[i]
        x2, y2 = hull[(i+1) % len(hull)]

        # edge vector
        ex, ey = x2 - x1, y2 - y1

        # outward normal (one of them)
        nx, ny = ey, -ex

        # normalize direction of normal pointing outward:
        # ensure origin is on correct side using centroid sign
        cx, cy = x1, y1
        if nx * cx + ny * cy < 0:
            nx, ny = -nx, -ny

        # check supporting constraint with radius expansion
        # line: nx*x + ny*y <= c, where c is max over endpoints + radius effect
        c1 = nx * x1 + ny * y1 + radii_map[(x1, y1)]
        c2 = nx * x2 + ny * y2 + radii_map[(x2, y2)]
        c = max(c1, c2)

        # origin must satisfy 0 <= c
        if 0 > c:
            return False

    return True

def main():
    n = int(input())
    xs = []
    ys = []
    rs = []
    pts = []

    for _ in range(n):
        x, y = map(int, input().split())
        xs.append(x)
        ys.append(y)
        pts.append((x, y))

    radii = {}
    for i in range(n):
        r = int(input())
        radii[(xs[i], ys[i])] = r

    if n == 1:
        x, y = pts[0]
        r = radii[(x, y)]
        print("Yes" if x*x + y*y <= r*r else "No")
        return

    hull = build_hull(pts)

    if inside_origin_with_radii(hull, radii):
        print("Yes")
    else:
        print("No")

if __name__ == "__main__":
    main()
```この実装では、まず標準のモノトーン チェーンを使用して中心の凸包を構築します。 中心の凸包の厳密に内側の点は外側の支持方向に寄与できないため、これは安全です。 

第 2 段階では、船体のエッジを繰り返して支持線を構築します。 各エッジは、候補の半平面制約を誘発するものとして扱われます。 半径が端点に適用されるのは、方向に沿った最大の外側へのシフトが線形サポート下のエッジの端点で達成されるためであり、端点をチェックするだけで十分です。 

実装の微妙な詳細は、法線の向きの一貫性です。 このコードは、エンドポイントに対する単純なドット積テストを使用して法線を反転することでこれを解決します。 

単一点の場合は、エッジが存在せず、ハルが縮退するため、個別に処理されます。

 ## 特殊なケース

 重要なエッジ ケースは、原点から遠く離れた単一の円の半径が非常に大きい場合です。 中心の外殻だけでは原点が除外されますが、実際には膨張した円盤が原点を覆っています。 半径は船体の構築後に無視されるのではなく、サポートの評価に組み込まれるため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、多くの点が同一線上にある場合です。 モノトーン チェーンはそれらをセグメントに折りたたんで、エンドポイントのみを残します。 これは正しいです。内部の共線点は新しい支持方向に寄与せず、端点の半径がその線に沿ったエンベロープを支配するからです。 

最後のケースは、方向チェックの数値的安定性です。 すべての座標は整数であり、この問題では境界からの最小距離が保証されているため、整数演算で十分であり、イプシロンの処理は必要ありません。
