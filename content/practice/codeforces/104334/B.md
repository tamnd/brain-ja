 ## 解決策
 ## 問題の理解

 頂点によって反時計回りの順序で記述された単純な多角形が与えられます。 多角形は必ずしも凸である必要はありません。 タスクは、形状が凸になるまで、凹面領域を非常に特殊な方法で修正する幾何学的な「修復」操作を繰り返し適用した後に得られる最終的な多角形を決定することです。 

この操作には幾何学的解釈があります。つまり、現在の非凸構造の内側に厳密に存在し、凸包上に端点がある境界点の最大チェーンを選択し、その端点の中点を横切ってそのチェーンを反映します。 これによって、最終的な安定した構成の点のセットは変更されません。 凹んだ部分を徐々に「真っ直ぐにする」だけです。 

重要な観察は、一見動的に見えるプロセスにもかかわらず、最終的な形状は最初の多角形によって一意に決定され、各ステップでどの有効な操作が適用されるかには依存しないということです。 出力はまさにこの最終的な凸多角形であり、辞書編集上の最小の頂点から開始して反時計回りの順序で整数座標の頂点のシーケンスとして与えられます。 

制約では最大 100,000 個の頂点が許可されるため、線形演算よりも悪い解決策は困難になります。 各操作は長い境界セグメントに影響を与える可能性があり、そのような操作が線形数存在する可能性があるため、説明した操作の 3 次または 2 次の幾何学的シミュレーションは完全に実行不可能です。 

最も危険なエッジケースは、変換によって実際に何が保持されるかを理解することから生まれます。 単純な解釈では、反射操作を直接シミュレートしようとする可能性がありますが、これは中間ジオメトリに関する誤った仮定につながります。 

微妙な落とし穴は、ローカル凸化または単調チェーン修正 (ローカルに適用される標準の凸包トリックなど) で十分であると想定していることです。 たとえば、「ジグザグ」コリドーのような形状のポリゴンには、局所的な修正ではなく全体的な修正が必要な場合があり、単純な反復的なハル更新では、セグメントの反射の繰り返しによって暗示される対称性を捉えることができません。 

## アプローチ

 強引なアイデアは、説明どおりにプロセスを正確にシミュレートすることです。 ハルの 2 つの頂点で囲まれた凹面領域を繰り返し見つけ、内部チェーンを反映し、ポリゴンを更新します。 このような各操作では、船体を特定するのに線形時間がかかり、影響を受けるセグメントを更新するのにさらに線形時間がかかります。 各ステップで少量の凹面しか除去されない最悪のケースでは、このような操作が O(N) 回発生する可能性があるため、全体の複雑さは O(N^2) 以上になります。 N が最大 100,000 であるため、これは許容範囲をはるかに超えています。 

重要な洞察は、この操作が実際には「ローカル スムージング」ではなく、非常に特殊な線形変換の下でのグローバルな凸化であるということです。中間点を横切る境界セグメントを反映させると、中間点の構造が維持され、凹面チェーンがミラーリングされた凸面チェーンに効果的に置き換えられます。 これは、最終的な形状が凸包のジオメトリと、境界点がどのように包のエッジを横切ってペアになるかのみに依存することを意味します。 

このプロセスを別のレンズを通して見ると、すべての非ハル エッジは最終的には「反転」され、凸包境界と位置合わせされます。 繰り返される中点反射により、すべての凹面が除去される対称性が強制されます。つまり、最終的なポリゴンは元の点セットの凸包とまったく同じになりますが、重要なひねりが加えられています。つまり、包の頂点は、整数の座標を保持する累積反射の下で変換されます。 

これにより、標準的な凸包計算が行われ、その後、誘導された変換と一致する最終境界が再構築されます。 重要な構造上の結果は、境界上に内部点が残らず、最終的な多角形が元の頂点の凸包とまったく同じになることです。

したがって、問題は、一連の点の凸包を計算し、それを辞書編集上の最小の頂点から反時計回りの順序で出力することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N²) 以上 | O(N) | 遅すぎる |
 | 凸包 (単調チェーン) | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 単調チェーン構造を使用して、指定されたポリゴン頂点の凸包を計算します。 

1. 入力からすべての点を読み取り、座標ペアとして保存します。 これにより、初期ポリゴンの完全な頂点セットが得られます。 
2. 点を x 座標で並べ替え、y 座標で結合を解除します。 この順序により、船体の上部と下部を効率的に構築できるようになります。 
3. 左から右に繰り返して、船体下部を構築します。 新しい点ごとに、船体の最後の 2 点と現在の点が常に反時計回りの回転を形成することを維持します。 そうでない場合は、中間点を削除します。 これにより、続行しても境界が凸状のままになります。 
4. 同じルールで右から左に繰り返して上部船体を構築します。 これにより、船体下部に含まれない残りの境界がキャプチャされます。 
5. 下部ハルと上部ハルを連結し、重複するエンドポイントを削除します。 これにより、反時計回りの順序で完全な凸多角形が生成されます。 
6. 出力仕様の要求に従って、辞書編集上最小の頂点が最初に来るように、結果のリストを回転します。 

この正しさは、元の多角形の凹頂点は常に厳密に凸包の支持線の内側にあるため、中点反射操作を繰り返しても最終境界上に残ることができないという事実から来ています。 唯一生き残る頂点は凸包境界上にある頂点であり、単調チェーン アルゴリズムはそれらの点を正確に計算します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(o, a, b):
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

def convex_hull(points):
    points = sorted(set(points))
    if len(points) <= 1:
        return points

    lower = []
    for p in points:
        while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
            lower.pop()
        lower.append(p)

    upper = []
    for p in reversed(points):
        while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)

    return lower[:-1] + upper[:-1]

def rotate_to_lexmin(poly):
    idx = 0
    for i in range(1, len(poly)):
        if poly[i] < poly[idx]:
            idx = i
    return poly[idx:] + poly[:idx]

def main():
    data = list(map(int, sys.stdin.read().strip().split()))
    n = data[0]
    pts = []
    idx = 1
    for _ in range(n):
        x = data[idx]
        y = data[idx + n]
        idx += 1
        pts.append((x, y))

    hull = convex_hull(pts)
    hull = rotate_to_lexmin(hull)

    print(len(hull))
    for x, y in hull:
        print(x, y)

if __name__ == "__main__":
    main()
```この解決策は、点を読み取り、標準点セットを形成することから始まります。 凸包関数は、外積テストを使用して厳密な凸性を強制する古典的な単調チェーンの実装です。 非左折を作成するポイントは削除され、境界頂点のみが残されるようにします。 

最後のステップでは、出力要件に一致する最小の辞書編集上の頂点が最初になるようにハルを回転します。 

実装の微妙な詳細の 1 つは、外積条件の厳密さです。 使用する`<= 0`同一線上の境界点が確実に削除されます。出力では連続した同一線上のトリプルが禁止されているため、これが必要です。 

もう 1 つの重要な詳細は、`set(points)`同一の座標を使用すると船体の正確性が損なわれるため、これは安全です。

 ## 特殊なケース

 重要なエッジケースは、すべてのポイントが同一線上にある場合です。 その状況では、すべての点が単一の線分上にあり、凸包は 2 つの極端な端点に縮退します。 外積はどこでもゼロになり、単調連鎖は次の理由により中間点を削除するため、アルゴリズムはこれを正しく処理します。`<= 0`状態。 

もう 1 つのケースは、ポリゴンがすでに凸状である場合です。 ハルの構築では、同一線上にある頂点以外の頂点は削除されず、元の凸状境界構造が維持されます。 

最後の微妙なケースは、座標の重複です。 セットベースの重複排除により、重複によって並べ替えやクロス積の決定が損なわれず、不正なハル ループやゼロ領域セグメントが防止されます。
