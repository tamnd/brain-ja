 ## 問題の理解

 それぞれの長さのバイナリ文字列のコレクションが与えられます。$M$、各文字列は、結果の完全な割り当てを表します。$M$イベント。 ある解釈では、$j$-番目のビットが 1 の場合はイベントを意味します$E_j$は「救い」、０は「破局」を意味します。 したがって、入力は実際には次のセットです$N$個別の完全な割り当てが終了しました$M$ブール変数。 

隠された構造は次のとおりです。$N$割り当ては任意ではありません。 それらは、未知の制約セットの閉包として定義されます。 各制約は 2 つのインデックスの選択から生じます$i, j$および 4 つの「知識タイプ」の 1 つ。各タイプは、値の 1 つの組み合わせを厳密に禁止します。$(E_i, E_j)$。 たとえば、タイプ 1 は両方が同時に大惨事になることを禁止し、タイプ 4 は両方が同時に救済されることを禁止し、他の 2 つは対称的な方法で混合ケースを禁止します。 したがって、各制約は 2 つの変数の値の 4 つの可能なペアのうち 1 つを正確に削除し、許可される 3 つのペアを残します。 

満足のいく代入のセットがまさに指定されたセットであるペアごとの制約の複数セットが存在するかどうかを判断するように求められます$N$バイナリ文字列であり、そうであれば、1 つの有効な構造を出力します。 

の制約$N, M \le 2000$これは、割り当てや制約のサブセットに対して指数関数的なことを試みることはできないことを意味します。 この構造は、解空間自体の動作から変数のペアにわたる関係構造を再構築していることを示唆しています。 

重要な観察は、各制約が 4 つの可能なペアのうち 1 つを正確に削除する二項関係であるということです。 これは、すべての制約が、オブジェクトの 1 つの「コーナー」を禁止することと同じであることを意味します。$2 \times 2$真理値表。 このような制約は、ペアごとの一貫性条件のファミリーを定義し、解セットは、列のペアでの射影動作の下で閉じられる制約の交差部分です。 

単純な推論を即座に打ち破る素朴なエッジケースは、次のような場合です。$M=1$。 この場合、変数のペアは存在しないため、制約は存在しません。 可能なセットはすべて文字列のみです$\{0,1\}$または単一の文字列。 もし私たちが与えられたら$N=2$両方の文字列が「0」と「1」の場合、それは有効です。 他の組み合わせが与えられた場合、ペア制約を使用してそれを表すことはできません。 常に異なるビットごとに制約を構築しようとする不注意なアプローチでは、誤って無効な構造が導入されてしまいます。 

もう 1 つの微妙なケースは、2 つの列がすべての文字列で同一である場合です。 どのような構造でも、制約の下でそれらを交換可能なものとして扱う必要があります。 そうしないと、それらの間の区別を強制しようとすると、有効な解決策が失われる可能性があります。 

## アプローチ

 強引なアイデアは、すべての可能な複数の制約セットをすべて考慮することです。$\binom{M}{2}$ペアで全4種類。 サイズの制約セットが 1 つであっても$K$までの交差によって定義される解空間につながります。$K$ローカル除外。 可能な制約マルチセットの数は天文学的に多く、1 つの候補セットを検証するだけでも、すべての候補セットの一貫性をチェックする必要があります。$N$課題。 このアプローチは明らかに小規模を超えると実行不可能です$M$。 

代わりに、重要な洞察は視点を逆転させることです。 制約を構築して解空間を導出する代わりに、与えられた解空間から開始して、どの列のペアが一貫して動作する必要があるかを推測します。 

各制約は 2 つの列のみに影響し、4 つのペア パターンのうち 1 つだけを禁止します。 したがって、列のペアを見ると、$(i, j)$、観察されたペアのセット$(S_k[i], S_k[j])$すべての文字列にわたって、そのペアの禁止パターンの補数、または制約が設定されていない場合は 4 つのパターンすべての補数である必要があります。 各制約は 1 つのパターンを正確に削除するため、この構造は、列のペアごとに、観察されるペアの許容セットがサイズ 3 またはサイズ 4 のいずれかであり、それより小さくなったり任意であったりしてはいけないことを暗示しています。 

これにより、問題は各列ペアを調べて、データセットと一致する一意の禁止ペアが存在するかどうかを判断することに減ります。 列のペアが特定の組み合わせを決して示さない場合、その欠落している組み合わせは、そのペアに適切な知識タイプを選択した結果として解釈できます。 複数の組み合わせが欠落している場合、または欠落しているパターンが有効な制約タイプに対応しない場合、構築は存在しません。

 ## アルゴリズムのチュートリアル

 各列のペアを独立して処理し、制約を強制するかどうかを再構築します。 

1. インデックスのペアごとに$(i, j)$、すべての文字列をスキャンし、4 つのペアのどれを記録するか$(0,0), (0,1), (1,0), (1,1)$現れる。 これにより、観測されたデータセットの下でこのペアの実現可能性を記述する 4 ビット マスクが得られます。 
2. 4 つのパターンがすべて表示される場合、このペアには制約は必要ありません。 このペアについては何も出力しません。 その理由は、単一の禁止パターンが観察された自由を説明できないため、ペアは有効な構造に制約されないためです。 
3. ちょうど 3 つのパターンが表示される場合は、ちょうど 1 つのパターンが欠落しています。 その欠けているパターンは、4 つの知識タイプのいずれかに対応します。 欠落しているペアを適切な制約タイプに変換し、1 つの制約を出力します。$(i, j)$。 タイプは、4 つの組み合わせのうちどれが欠けているかによって決まります。 
4. 出現するパターンが 3 つ未満の場合は、直ちに不可能であると判断します。 その理由は、単一のペアごとの制約によって削除されるパターンは 1 つだけであるため、同じペアで 2 つ以上のパターンを禁止する構造は不可能であるためです。 
5. すべてのペアを処理した後、構築されたすべての制約を出力します。 

正確さは、制約がペアに対して独立して作用するという事実に左右され、各制約はそのペアに対する 1 つのバイナリ代入を禁止することに正確に対応します。 

### なぜ効果があるのか

 すべての制約は、変数の固定ペアに対する 4 つの可能な代入のうち 1 つを正確に削除します。 したがって、有効な構成では、ペア上で観察された投影のセットは、4 つのペアの完全なセットから、そのペアに割り当てられた禁止パターンの和集合を正確に引いたものに等しくなければなりません。 制約は、どのペアの値がローカルで禁止されるかを変更するような形で、異なるペア間で相互作用しないため、各ペアを独立して再構築できます。 最大 1 つのパターンが欠落しているという条件は、表現可能性にとって必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    N, M = map(int, input().split())
    S = [input().strip() for _ in range(N)]

    # mask[i][j] stores seen pairs as 4-bit mask
    # bit 0: 00, bit 1: 01, bit 2: 10, bit 3: 11
    mask = [[0] * M for _ in range(M)]

    for s in S:
        for i in range(M):
            bi = ord(s[i]) - 48
            row = mask[i]
            for j in range(i + 1, M):
                bj = ord(s[j]) - 48
                row[j] |= (1 << (bi * 2 + bj))

    res = []

    for i in range(M):
        for j in range(i + 1, M):
            m = mask[i][j]
            if m == 0b1111:
                continue
            # if fewer than 3 patterns, impossible
            if m & (m - 1) == 0:
                print(-1)
                return

            # find missing pattern
            full = 0b1111
            miss = full ^ m
            if miss & (miss - 1):
                print(-1)
                return

            # decode miss into type
            # 00 -> type 1, 01 -> type 2, 10 -> type 3, 11 -> type 4
            if miss == 1:
                t = 1
            elif miss == 2:
                t = 2
            elif miss == 4:
                t = 3
            else:
                t = 4

            res.append((i, j, t))

    print(len(res))
    for i, j, t in res:
        print(i, j, t)

if __name__ == "__main__":
    main()
```このソリューションは、列のペアごとにペアごとの互換性マスクを構築します。 各マスクは、指定された文字列内に 4 つの可能な割り当てのどれが現れるかを記録します。 マスクを埋めた後、各ペアを独立して解釈します。完全に制約がないか、割り当てが 1 つだけ欠落しており、それを制約タイプに変換します。 単一の許可された制約では同じペア上の複数のパターンを排除できないため、複数の割り当てが欠落しているペアは直ちに無効になります。 

実装における微妙な点は、ペアを 4 ビット マスクにエンコードすることです。 マッピング$(0,0)\to 1$、$(0,1)\to 2$、$(1,0)\to 4$、$(1,1)\to 8$観測された各組み合わせが正確に 1 ビット切り替わることを保証します。 これにより、和集合演算が定数時間になります。

 ## 特殊なケース

 重要なエッジケースは、すべての文字列が同一である場合です。 その状況では、列の各ペアには 1 つのみのパターンが観察されます。 マスクには正確に 1 ビットが含まれているため、アルゴリズムは複数の欠落パターンを検出し、ただちに拒否します。 これは正しいです。すべての変数が固定されていない限り、単一のバイナリ制約では、すべてのペアにわたってグローバルに 1 つの代入のみを許可することはできず、この構造ではエンコードされません。 

もう 1 つのエッジ ケースは、1 組の列が 4 つの組み合わせすべてを示す場合です。 アルゴリズムは、そのペアに対して制約を正しく出力しません。 これは、局所的な制限は必要なく、制限を強制しようとすると解空間が人為的に減少することを反映しています。 

最後に、ちょうど 2 つのパターンが欠落しているケースは直ちに拒否されます。 これはアルゴリズムの中で最も強力な一貫性チェックであり、単一の知識ルールが表現できる範囲を超えてペアを過度に制限するような不可能な制約セットの構築を防ぎます。
