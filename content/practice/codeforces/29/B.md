 ## 解決策
 ## 問題の理解

 車は地点 A から出発し、直線道路に沿って地点 B に向かって移動します。総距離は次のとおりです。`l`メートルで、車は常に一定の速度で移動します`v`。 まさに道路沿いのどこか`d`スタート地点から数メートル先に信号があります。 

信号機は青と赤を永遠に繰り返します。 時間に`0`、ライトは緑色です。 それは緑色のままです`g`数秒、その後赤`r`その後、このサイクルを何度も繰り返します。 

車は瞬時に停止し、瞬時に加速する可能性があるため、信号待ちでも罰則はありません。 唯一の制限は、赤の区間中は車が横断できないことです。 赤が始まると同時に到着した場合は、停止する必要があります。 ちょうど青が始まるときに到着した場合は、すぐに通過する可能性があります。 

このタスクは、A から B までの可能な最小移動時間を計算することです。 

制約はわずかです。 すべての値は最大でも`1000`、信号は1つしかありません。 シミュレーションを多用したソリューションでも、制限内に問題なく収まります。 本当の課題は、タイミング境界、特にライトの状態が変化する瞬間を正しく処理することです。 

最も簡単な間違いは、まさに緑から赤への移行時に到着を誤って処理することです。 

次の入力を考えてみましょう。```
10 5 1 5 5
```車は時間通りに信号に到着する`5`。 緑の間隔は`[0, 5)`、赤は正確に始まります`5`。 車は通行禁止です。 時が来るまで待たなければなりません`10`、続けてください。 

正しい答えは次のとおりです。```
15
```を使用した不注意な実装`<= g`の代わりに`< g`誤って車の即時通過を許可し、`10`。 

もう 1 つの微妙なケースは、新しい緑の間隔が始まるまさにそのときに到着することです。```
10 5 1 3 2
```サイクルの長さは`5`。 車はやがて信号に到達する`5`、これはまさに緑の区間の始まりです。 すぐに継続する可能性があります。 

正しい答えは次のとおりです。```
10
```すべての境界をブロックされたものとして扱う実装では、不必要な待ち時間が誤って追加されてしまいます。 

もう 1 つのエッジ ケースは、車がライトに触れる前に目的地に到着したときに発生します。 問題は保証します`d < l`したがって、このようなことは決して起こりませんが、構造を考えることは依然として役立ちます。 待ちが発生する可能性がある唯一の場所は信号機そのものです。 車がそこを通過すると、残りの動きは常に中断されません。 

## アプローチ

 この強引なアイデアは、時間を秒単位でシミュレートし、車が目的地に到着するまで信号の状態を追跡することです。 値が小さいため、浮動小数点演算を慎重に実装すれば、きめの細かいシミュレーションでも機能する可能性があります。 

システムが非常にシンプルであるため、ブルートフォースが機能します。 車は 1 つの位置でのみ挙動を変え、信号のタイミングは周期的で、移動速度は一定です。 問題は、連続時間シミュレーションが扱いにくく、不必要であることです。 精度を維持するには非常に小さな増分が必要となり、浮動小数点の累積エラーが煩わしくなります。 

重要な観察は、車が信号機と 1 回だけ対話していることです。 

信号機がなければ、総移動時間は単純に次のようになります。$$\frac{l}{v}$$唯一の問題は、距離に達したときに車が待たなければならないかどうかです`d`。 

信号到着時刻は以下の通りです。$$\frac{d}{v}$$信号機は毎回繰り返します`g + r`秒。 到着時間をサイクル長で割ることにより、その瞬間の信号が緑か赤かを判断できます。 

もし：$$t \bmod (g+r) < g$$車は青の間に到着し、すぐに横切ります。 

それ以外の場合は、赤の間に到着し、次のサイクルが開始するまで待つ必要があります。 

これにより、問題全体が数回の算術演算に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(T) | お(1) | 不要 |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 5 つの整数を読み取ります`l`、`d`、`v`、`g`、 そして`r`。 
2. 信号に到達するまでに必要な時間を計算します。$$t = \frac{d}{v}$$車は常に最高速度で移動するため、これが可能な限り最も早い到着時間です。 

1. 信号サイクルの長さを計算します。$$cycle = g + r$$信号はこの周期で永遠に繰り返されます。 

1. 車が到着したときの現在のサイクル内の位置を見つけます。$$x = t \bmod cycle$$これにより、その時点で信号が青か赤かを知ることができます。 

1. 青の間に車が到着するかどうかを確認します。 

もし：$$x < g$$車はすぐに通り過ぎます。 

それ以外の場合、車は赤の時間帯に到着し、待つ必要があります。$$wait = cycle - x$$この待機時間により、現在時刻が次の緑色の間隔の始まりに正確に移動します。 

1. 信号機から目的地までの残りの移動時間を追加します。$$\frac{l-d}{v}$$1. 最終的な回答を十分な精度で出力します。 

### なぜ効果があるのか

 車の判断ポイントは信号機の 1 つだけです。 車はいつでもペナルティなしで即座に停止できるため、信号に到達する前に速度を落としても役に立ちません。 より早く到達することは、常に、遅く到達することと少なくとも同じくらい良いことです。 

このアルゴリズムは、信号への最も早い到着時間を計算し、その瞬間が青の区間に属しているかどうかを確認します。 「はい」の場合は、すぐに横断するのが最適です。 そうでない場合、最善の戦略は、次の緑の間隔が始まるまで正確に待つことです。 他の待機戦略では答えを改善することはできません。 

考えられるすべての有効な移動がこの構造に従っているため、計算される時間は最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

l, d, v, g, r = map(int, input().split())

time_to_light = d / v
cycle = g + r

pos_in_cycle = time_to_light % cycle

answer = l / v

if pos_in_cycle >= g:
    answer += cycle - pos_in_cycle

print(f"{answer:.10f}")
```この解決策は、信号機への可能な限り最も早い到着時間を計算することから始まります。 速度は一定で加速は瞬間的なものであるため、信号の前で意図的に速度を落とす必要はありません。 

変数`pos_in_cycle`信号と信号が繰り返されるサイクル内で車が到着する正確な瞬間を表します。 これが問題の核心的な観察です。 

条件:```
if pos_in_cycle >= g:
```が重要な境界です。 緑の間隔は`[0, g)`。 正確に到着します`g`赤はすでに発進しているため、車は待たなければならないことを意味します。 使用する`>`の代わりに`>=`間違った答えが生まれるでしょう。 

最初の答えは次のように設定されます。```
l / v
```これは待ち時間なしの移動時間です。 赤の時間帯に車が到着した場合は待ち時間のみ加算されます。 

出力では、必要な浮動小数点許容誤差を満たすために高精度フォーマットが使用されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    l, d, v, g, r = map(int, input().split())

    time_to_light = d / v
    cycle = g + r

    pos_in_cycle = time_to_light % cycle

    answer = l / v

    if pos_in_cycle >= g:
        answer += cycle - pos_in_cycle

    print(f"{answer:.10f}")

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    backup = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup
    return out.getvalue().strip()

assert run("20 7 2 3 5\n") == "14.0000000000", "fractional wait"

 ## 特殊なケース

 車が到着したときに信号が赤に変わる境界を考えてみましょう。```
10 5 1 5 5
```車はやがて信号に到達する`5`。 

サイクルは`10`、 それで：$$5 \bmod 10 = 5$$以来`5 >= 5`、ライトは赤です。 アルゴリズムにより待ち時間が追加されます。$$10 - 5 = 5$$最終的な答えは次のようになります。$$10 + 5 = 15$$This matches the rules precisely because the car cannot cross at the instant red begins.

 ここで、ちょうど緑が始まるときに到着することを考えてみましょう。```
10 5 1 3 2
```サイクルの長さは`5`。 車はやがて信号に到達する`5`。$$5 \bmod 5 = 0$$以来`0 < 3`、信号は青です。 The car crosses immediately and finishes in`10`合計秒数。 

これにより、モジュロ計算がサイクル ラップアラウンドを正しく処理することが検証されます。 

最後に、赤の間の部分到着を考えてみましょう。```
20 7 2 3 5
```車は次の後に信号に到達します。$$\frac{7}{2} = 3.5$$サイクルの長さは`8`。$$3.5 \bmod 8 = 3.5$$なぜなら`3.5 >= 3`、ライトは赤です。 車は待っています：$$8 - 3.5 = 4.5$$基本移動時間は次のとおりです。$$\frac{20}{2} = 10$$合計：$$10 + 4.5 = 14.5$$すべての計算が浮動小数点演算で実行されるため、アルゴリズムは小数点のタイミングを自然に処理します。
