[CF 29A - 唾吐きの問題](https://codeforces.com/problemset/problem/29/A)

 **評価:** 1000
 **タグ:** ブルートフォース
 **解決時間:** 1 分 12 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 各ラクダは数直線上の固有の座標に立っています。 位置にあるラクダ`x`正確に位置に向かって唾を吐きます`x + d`。 別のラクダがそこに立っていると、ぶつかってしまいます。 お互いがぶつかるようなラクダのペアが存在するかどうかを判断する必要があります。 

ラクダ A が立っているとします。`x1`そして距離を吐きます`d1`。 ポジションを狙う`x1 + d1`。 ラクダBが立っているのは`x2`そして距離を吐きます`d2`。 2 頭のラクダは次の場合に互いに唾を吐きます。```
x1 + d1 = x2
x2 + d2 = x1
```入力により、すべてのラクダの位置と唾を吐く距離が得られます。 出力は`"YES"`少なくとも 1 つの相互ペアが存在する場合、それ以外の場合`"NO"`。 

制約は非常に小さいです。 ラクダの数は最大でも 100 頭なので、すべてのペアを直接チェックするアルゴリズムでもまったく問題ありません。 すべてのペアにわたる二重ループのパフォーマンスは最大でも`100 * 100 = 10,000`チェック数は 2 秒の制限としては小さいです。 これは、高度なデータ構造や最適化のトリックが必要ないことをすぐに示します。 

見落としやすいエッジケースがいくつかあります。 

ラクダは右ではなく左に唾を吐くことがあります。`d`マイナスになることもあります。 例えば：```
2
5 -2
3 2
```ラクダで`5`ターゲット`3`、ラクダで`3`ターゲット`5`、したがって、答えは次のとおりです`"YES"`。 すべての唾がうまくいくと仮定する不注意な解決策は、ここで失敗するでしょう。 

もう 1 つの微妙なケースは、あるラクダが別のラクダにぶつかる場合ですが、その逆は当てはまりません。```
2
0 2
2 5
```ラクダで`0`ラクダにぶつかる`2`、しかしラクダで`2`ターゲット`7`。 正しい答えは、`"NO"`。 バグのある実装では、相互ターゲティングをチェックするのではなく、あるラクダが別のラクダを攻撃できるかどうかのみをチェックする可能性があります。 

3 番目のケースには、1 つのペアだけが機能する複数のラクダが含まれます。```
4
0 3
3 -3
10 1
20 -5
```正しい答えは、`"YES"`最初の二頭のラクダが互いに唾を吐き合ったからです。 アルゴリズムは、有効なペアが見つかったらすぐに停止する必要があります。 

## アプローチ

 最も直接的なアプローチは、ラクダのすべてのつがいを比較することです。 各ペアごとに`(i, j)`、ラクダかどうかを確認します`i`ラクダに正確に唾を吐きます`j`、ラクダ`j`ラクダに正確に唾を吐きます`i`。 
かつてはラクダの`i`は`(xi, di)`そしてラクダ`j`は`(xj, dj)`、そして次のようなときにお互いに唾を吐きます。```
xi + di = xj
xj + dj = xi
```考えられるすべてのペアが検査されるため、この総当り的なアプローチは正しいです。 有効なペアが入力内のどこかに存在する場合、最終的にそれをテストします。 

時間計算量は`O(n²)`注文されたすべてのペアを検査するためです。 と`n ≤ 100`、これは最大でも 10,000 件の比較であり、これは些細なことです。 

制約はすでに小さいため、より高度な最適化は必要ありません。 ラクダの位置をハッシュ マップに保存して、ターゲットをより高速に検索することもできますが、複雑さが増すため、実用的な利点はありません。 ペアごとのソリューションはすでに高速かつシンプルで、検証も簡単です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースペアチェック | O(n²) | お(1) | 承認済み |
 | ハッシュマップ検索 | O(n) 平均 | O(n) | 受け入れられるが不要 |

 ## アルゴリズムのチュートリアル

 1. ラクダの数を読み取ります。 
2. すべてのラクダをペアとして保管します`(x, d)`どこ`x`は位置であり、`d`スピット距離です。 
3. 個別のラクダのすべてのペアを反復処理します。`(i, j)`。 
4. 各ペアについて、ターゲット位置を計算します。```
camel i targets xi + di
camel j targets xj + dj
```5. ラクダかどうかを確認します`i`ラクダをターゲットにする`j`そしてラクダ`j`ラクダをターゲットにする`i`。 

これは次のことを確認することを意味します。```
xi + di == xj
xj + dj == xi
```6. 両方の条件が真の場合、すぐに出力します。`"YES"`そして終了します。 

この問題はそのようなペアが少なくとも 1 つ存在するかどうかを問うだけであるため、早期に停止できます。 
7. すべてのペアがチェックされ、いずれも条件を満たさない場合は、出力します。`"NO"`。 

### なぜ効果があるのか

 このアルゴリズムは、考えられるすべてのラクダのペアを 1 回だけチェックします。 ペアは、各ラクダの唾が他のラクダの位置に正確に着地した場合にのみ受け入れられます。 「互いに唾を吐き合う」の定義はまさにこれら 2 つの方程式であるため、アルゴリズムは有効なペアを見逃すことはなく、無効なペアを誤って受け入れることもできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
camels = []

for _ in range(n):
    x, d = map(int, input().split())
    camels.append((x, d))

for i in range(n):
    xi, di = camels[i]

    for j in range(i + 1, n):
        xj, dj = camels[j]

        if xi + di == xj and xj + dj == xi:
            print("YES")
            sys.exit()

print("NO")
```プログラムは、すべてのラクダをリストに読み込むことから始まります。`(position, distance)`ペア。 

ネストされたループは、すべての一意のペアを反復します。 使用する`j`から`i + 1`同じペアを 2 回チェックすることを避け、ラクダとそれ自体を比較することを避けます。 

ループ内では、条件は相互唾吐きの数学的定義と直接一致します。 最初の等価性は、キャメルかどうかをチェックします。`i`ラクダに当たる`j`。 2 つ目は逆方向をチェックします。 

有効なペアが見つかるとすぐに、プログラムは次のように出力します。`"YES"`そしてすぐに出ます。 早期に終了すると、実装が簡素化され、不必要な作業が回避されます。 

Python の整数はこれらの範囲を簡単に処理できるため、オーバーフローの心配はありません。 加算は数直線上の両方向を処理するため、負のスピット距離も自然に機能します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())
    camels = []

    for _ in range(n):
        x, d = map(int, input().split())
        camels.append((x, d))

    for i in range(n):
        xi, di = camels[i]

        for j in range(i + 1, n):
            xj, dj = camels[j]

            if xi + di == xj and xj + dj == xi:
                return "YES"

    return "NO"

# provided sample
assert run("2\n0 1\n1 -1\n") == "YES", "sample 1"

# minimum size
assert run("1\n0 5\n") == "NO", "single camel"

# one-direction hit only
assert run("2\n0 2\n2 5\n") == "NO", "not mutual"

# negative distances
assert run("2\n5 -2\n3 2\n") == "YES", "left and right spit"

# larger case with one valid pair
assert run(
    "5\n0 3\n3 -3\n10 1\n20 -5\n7 2\n"
) == "YES", "find pair among many"

# no valid pairs
assert run(
    "4\n0 1\n2 1\n4 1\n6 1\n"
) == "NO", "all spit away"

 ## 特殊なケース

 唾が左に行く場合を考えてみましょう。```
2
5 -2
3 2
```アルゴリズムはペアをチェックします。```
5 + (-2) = 3
3 + 2 = 5
```両方の条件が true であるため、出力されます`"YES"`。 計算は単なる整数の加算であるため、負の距離は自然に機能します。 

ここで一方的なヒットを考えてみましょう。```
2
0 2
2 5
```アルゴリズムは以下を計算します。```
0 + 2 = 2
2 + 5 = 7
```最初の条件は成功しますが、2 番目の条件は失敗します。 両方が同時に必要なため、ペアは拒否され、最終的な答えは次のようになります。`"NO"`。 

最後に、一致するペアが 1 つだけある複数のラクダについて考えます。```
4
0 3
3 -3
10 1
20 -5
```アルゴリズムはペアを順番にテストします。 最初の 2 頭のラクダに到達すると、次のようになります。```
0 + 3 = 3
3 + (-3) = 0
```ペアは条件を満たすため、アルゴリズムはすぐに出力します。`"YES"`残りのペアをチェックする時間を無駄にする必要はありません。
