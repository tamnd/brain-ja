 ## 解決策
 ## 問題の理解

 ボブとアレックスという 2 人の人を、次のような無向グラフとして表される町内を移動するよう求められます。`n`交差点と`m`道路。 ボブはノード 1 から開始し、ノードに到達したいと考えています`n`、Alex はノードから開始します`n`両方とも、接続された一連の道路に沿って、同じ速度で同時に移動する必要があり、同時に同じ交差点を占有することはできません。 道路の真ん中で交差することはあっても、結節点で出会うことはありません。 タスクは、この条件が満たされるように、両方の同じ長さの可能な最短のパスを見つけることです。 

入力はグラフを表す単純な整数ですが、重要な課題は相互作用の制約です。重複する可能性のある 2 つの最短パスについては、2 人の旅行者が同時に同じノードで遭遇しないように慎重に検討する必要があります。 有効なペアが存在しない場合は、戻り値が返されます。`-1`。 それ以外の場合は、有効な最短ルートを作成する必要があります。 

問題の範囲は中程度です。`n`最大500と`m`10,000まで。 これにより、時間的にはおよそ O(n^3)、空間的には O(n^2) までのアルゴリズムが可能になります。 重み付けされていないグラフ上の単純な BFS は O(n + m) で実行され、許容可能ですが、すべてのパスの置換を列挙するアプローチは実行不可能です。 エッジ ケースには、道路が 1 つだけある小さなグラフ (簡単なパス)、切り離されたグラフ (パスがない)、または最短パスが必然的に重複して有効な解決策が得られない状況が含まれます。 

たとえば、次のように考えてみましょう`n = 3`、道路`1-2`そして`2-3`。 1→3 と 3→1 の両方の最短パスは 2 を通過します。ノード 2 で会うことなく同時移動をスケジュールする方法はないため、答えは次のようになります。`-1`。 距離を計算して最短パスを選択するだけの単純なソリューションでは、ノードで競合するパスが誤って返されてしまいます。 

## アプローチ

 ブルートフォースのアイデアは、長さのパスをすべて列挙することです。`k`ボブの場合は 1 から n、アレックスの場合は n から 1 に移動し、すべてのペアに沿った同時移動をシミュレートしてノードの競合を確認します。 これは、有効な最短パスのペアが存在する場合には最終的にそれを見つけるため、原理的には機能します。 ただし、絶望的に遅いです。控えめなグラフであっても、パスの数は指数関数的に増加します。 最悪の場合の複雑さは、パスを列挙するだけでおよそ O(2^n) となり、n = 500 の場合には実現可能をはるかに超えています。 

最適な解決策につながる洞察は、これを「競合回避」制約を追加した最短経路問題として扱うことで得られます。 各開始ノードからの 2 つの独立した BFS トラバーサルを使用して問題をモデル化し、すべてのノードまでの距離を保存できます。 させて`d1[v]`1 から v までの距離であり、`d2[v]`n から v までの距離。重要な観察は、次の長さの有効な同期パスが存在することです。`L`各ステップで存在する場合`t`パスに沿って、ボブはノードにいます`u`アレックスはノードにいる`v`どちらかの`u != v`または、同じエッジに沿って反対方向に移動します。 これを、ボブとアレックスの位置の積グラフ上の最短経路問題として定式化し、それらが衝突する状態を避けることができます。 元のグラフが小さいため、サイズ n×n の積グラフ上の BFS が実現可能です。 これにより、問題は指数関数的なパスの列挙から多項式時間の探索に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (パスを列挙) | O(2^n) | O(2^n) | 遅すぎる |
 | 製品グラフ上の BFS | O(n^2 + n*m) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力グラフを読み取り、隣接リストを作成します。 これは標準であり、BFS が効率的に実行されることが保証されます。 
2. ノード 1 から BFS を実行して計算します`dist1[v]`すべてのノードに対して`v`。`dist1[v]`到達するエッジの最小数です`v`1から。 
3. ノード n から BFS を実行して計算します`distn[v]`すべてのノードに対して`v`。 
4. 状態に関する BFS を初期化する`(b, a)`ノードでボブを表す`b`ノードのアレックスと`a`。 開始状態は、`(1, n)`そして最終状態は`(n, 1)`。 
5. 州ごとに`(b, a)`BFS 中に、すべての動きを考慮します。ボブは、次の隣に移動します。`b`そしてアレックスは近所に引っ越します`a`。 押すだけ`(b', a')`次の場合、BFS キューに追加されます。`b' != a'`。 同じエッジに沿って反対方向に移動することは、ノードの競合を構成しないため許可されます。 
6. 2D 配列内の各状態の距離を追跡する`dist[b][a]`パス再構築のために親の状態を保存します。 
7. BFS は次の場合に終了します。`(n, 1)`に達します。 到達できない場合は出力`-1`。 
8. からバックトラックして、ボブとアレックスのパスを再構築します。`(n, 1)`親ポインタを使用します。 どちらのパスも同じ長さになります。 

**機能する理由**: 製品グラフの BFS は、すべての有効な同期動作をステップの増加順に調査します。 強制することで`b' != a'`各ステップで、同じノードが同時に占有されることを防ぎます。 BFS は、初めて到達することを保証します。`(n, 1)`それは最短の一連の動きに沿ったものです。 親ポインタは、同期されたパスの有効な再構築を提供します。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

n, m = map(int, input().split())
adj = [[] for _ in range(n + 1)]
for _ in range(m):
    u, v = map(int, input().split())
    adj[u].append(v)
    adj[v].append(u)

dist = [[-1] * (n + 1) for _ in range(n + 1)]
parent = [[None] * (n + 1) for _ in range(n + 1)]

queue = deque()
queue.append((1, n))
dist[1][n] = 0

while queue:
    b, a = queue.popleft()
    if (b, a) == (n, 1):
        break
    for nb in adj[b]:
        for na in adj[a]:
            if nb != na and dist[nb][na] == -1:
                dist[nb][na] = dist[b][a] + 1
                parent[nb][na] = (b, a)
                queue.append((nb, na))

if dist[n][1] == -1:
    print(-1)
    sys.exit()

# reconstruct paths
bpath, apath = [], []
b, a = n, 1
while (b, a) != (1, n):
    bpath.append(b)
    apath.append(a)
    b, a = parent[b][a]
bpath.append(1)
apath.append(n)
bpath.reverse()
apath.reverse()

print(len(bpath) - 1)
print(' '.join(map(str, bpath)))
print(' '.join(map(str, apath)))
```隣接リストは、重み付けされていないグラフをキャプチャします。 プロダクト グラフの BFS により、ノードの競合回避を強制しながら、すべての同時移動を確実に調査できます。 親ポインターによりパスの再構築が可能になり、BFS により最短の同期パスが保証されます。 繊細さはチェックにあります`nb != na`衝突を防ぐために近隣探索中に。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2 + n*m) | BFS は最大 n×n 状態を探索します。 それぞれに最大合計 m 個のエッジの隣接性チェックがあります。 
| スペース | O(n^2) |`dist`そして`parent`配列は n×n |

 と`n ≤ 500`そして`m ≤ 10,000`、n^2 = 250,000、n*m ≤ 5,000,000。 どちらも 1 秒と 256 MB に快適に収まります。
