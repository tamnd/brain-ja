 ## 解決策
 ## 問題の理解

 私たちは、好みのプログラミング言語によって決定される 3 つの学生グループを与えられます。 課題は、すべての生徒を正確に 3 つの練習グループに分けることです。 

唯一の制限は、1 つのグループにアセンブラー ファンと C++ ファンの両方を同時に含めることはできないことです。 基本的なファンは競合を引き起こさないため、どこにでも配置できます。 

制約が満たされている限り、学生を 3 つのグループに任意に分配することができます。 目標は、分割後に最大のグループをできるだけ小さくすることです。 

したがって、問題は有効な分割を見つけることではなく、3 つのタイプの項目を 3 つのコンテナーに分割する制約付きパーティションのバランスをとることです。ここで、1 つのタイプのペアは同じコンテナー内に共存できません。 

制約は非常に小さく、各タイプの生徒数は最大 1000 人、テスト ケースは最大 5 つだけです。 これにより、大量のグラフや状態探索のアプローチは除外されますが、直接的な数学的特徴付けや小規模なケース分析が強く示唆されます。 

素朴なアプローチでは、各生徒をグループに割り当て、あらゆる可能性をシミュレートしようとしますが、グループ割り当てのみを考慮した場合でも、構造は依然として生徒の数に応じて組み合わせ的に増大します。 これは必要なものをはるかに超えています。 

競合するタイプの 1 つが他のタイプに比べて非常に大きい場合、微妙なエッジ ケースが発生します。 たとえば、アセンブラの学生が多数を占め、C++ の学生が少ない場合、最適な戦略ではそれらを慎重に分離する必要があり、グループ サイズの単純で貪欲なバランスをとると、互換性のない型を簡単に一緒に配置したり、達成可能なバランスを過大評価したりする可能性があります。 

Basic の生徒が優勢な場合には、別の特殊なケースが発生します。 これらは柔軟性があるため、誤った解決策では常に分散を完全に平滑化すると仮定する可能性がありますが、アセンブラーと C++ を分離したままにしなければならないという基本的な制限を修正することはできません。 

## アプローチ

 ブルート フォース ビューでは、制約を尊重しながら、各学生を 3 つのグループの 1 つに割り当てるものとしてこれを扱います。どのグループにもアセンブラと C++ の学生の両方を含めることはできません。 すべての割り当てを繰り返して妥当性をチェックし、最適な最大グループ サイズを追跡することを想像することもできます。 これは、ソリューション空間全体を探索するため、概念的には正しいですが、生徒の数に応じて課題の数が指数関数的に増加するため、最小の制約であっても完全に実行不可能になります。 

重要な観察は、実際の対立はアセンブラーと C++ の学生の間だけであるということです。 基本的な生徒は、バランスを改善するために配布できるフリーマスのように行動します。 グループにアセンブラーと C++ の学生を含めることができる方法を修正したら、残りのタスクは、最大負荷を最小限に抑えるために Basic 学生を分散することになります。 

ちょうど 3 つのグループがあるため、各グループに「型制約」を割り当てる必要があります。つまり、アセンブラの学生を許可するか、C++ の学生を許可するかのどちらかですが、両方を許可することはできません。 これにより、構造は、紛争の各側に割り当てられるグループの数を選択することになります。 意味のある構成は 2 つだけ存在します。1 つのグループがすべてのアセンブラー スチューデントを処理し、他の 2 つのグループが C++ スチューデントを処理するか、その逆です。 

この分割が修正されると、各側は許可されたグループ全体に自分の学生を内部的に分散できるようになり、Basic 学生をバランスを取るリソースとして使用できるようになります。 最大グループ サイズ T を達成する実現可能性は、単純な定員条件になります。各グループには強制言語による一定の負荷があり、残りの定員は Basic の生徒で満たされており、利用可能な合計定員は Basic の生徒全員を吸収するのに十分でなければなりません。 

これにより、問題は 2 つの構成をチェックし、それぞれの構成で実行可能な最小の最大グループ サイズを計算することになります。

 ## アルゴリズムのチュートリアル

 アセンブラーと C++ は 1 つのグループ内で共存できないという制限の下で、3 つのグループをどのように構成できるかを推論します。 

1. 「アセンブラ許可」グループと「C++ 許可」グループの数を決定します。 グループは空であってはならず、アセンブラと C++ の両方が存在する必要があるため、意味のある分割は、アセンブラ側に 1 つのグループと C++ 側に 2 つのグループ、またはアセンブラ側に 2 つと C++ 側に 1 つのグループのみになります。 
2. 選択した分割では、許可されたグループ全体に Assembler 学生をできるだけ均等に分散します。 不均衡によってグループの最大サイズが増加するだけであるため、これにより、グループ内の最大のアセンブラ負荷が最小限に抑えられます。 
3. 許可されたグループ内の C++ 学生に対しても同じことを行います。 繰り返しますが、最適な分散は可能な限りバランスがとれたものです。 
4. Basic の生徒を柔軟なフィラーとして扱います。 候補の最大グループ サイズ T については、強制アセンブラーまたは C++ スチューデントを配置した後に各グループにどれだけの未使用容量が存在するかを計算します。 
5. 3 つのグループのすべての空き容量の合計が、少なくとも Basic 学生の数であるかどうかを確認します。 「はい」の場合、Basic 学生は T を超えずにすべての制約を満たすように分散できます。 
6. 構造的下限 (各グループは強制言語割り当てに適合する必要がある) とグローバル容量制約の両方を満たす最小 T を計算します。 
7. 両方の分割を評価し、結果として小さい方の T を返します。 

### なぜ効果があるのか

 重要な不変条件は、アセンブラー グループと C++ グループが固定されると、Basic 学生は自由に再割り当てできる分割可能な塊のように動作するということです。 したがって、答えに対する実際の制約は、グループごとの最小負荷と総容量だけです。 問題を特定の最大 T の実現可能性のチェックに縮小し、実現可能性は個々の割り当てではなく総容量のみに依存するため、構造は 2 つの構成によって完全に特徴付けられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(a, b, c):
    total = a + b + c

    def ceil_div(x, y):
        return (x + y - 1) // y

    # Case 1: 1 group for A-side, 2 groups for C-side
    t1 = max(
        ceil_div(total, 3),
        a,
        ceil_div(c, 2)
    )

    # Case 2: 2 groups for A-side, 1 group for C-side
    t2 = max(
        ceil_div(total, 3),
        c,
        ceil_div(a, 2)
    )

    return min(t1, t2)

def main():
    t = int(input())
    out = []
    for _ in range(t):
        a, b, c = map(int, input().split())
        out.append(str(solve_case(a, b, c)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装は派生した式に直接に従います。 すべての学生を正確に 3 つのグループに分散する必要があるため、合計を 3 で割った値が避けられない下限になります。 2 番目と 3 番目の項は、いかなる構成内でも、単一の言語側に割り当てられたグループが、少なくともその最も負荷の高いパーティションに対応する必要があることを強制します。 

2 つの構成を比較するという決定は、アセンブラーと C++ のどちらが「主要な分離側」であるかを選択することに正確に対応します。

### 例 2

 入力:`13 10 13`| ステップ | 合計 | 合計/3 | あ | 天井(C/2) | T1 | C | 天井(A/2) | T2 | 答え |

これらの例は、解がグローバル平均とローカル強制クラスタリング制約の両方によって支配されることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        t = int(input())
        res = []
        for _ in range(t):
            a, b, c = map(int, input().split())
            total = a + b + c

            def ceil_div(x, y):
                return (x + y - 1) // y

            t1 = max(ceil_div(total, 3), a, ceil_div(c, 2))
            t2 = max(ceil_div(total, 3), c, ceil_div(a, 2))
            res.append(str(min(t1, t2)))
        return "\n".join(res)

    return solve()

# provided samples
assert run("5\n3 5 7\n4 8 4\n13 10 13\n1000 1000 1000\n13 22 7\n") == "5\n6\n13\n1000\n14"

# minimum case
assert run("1\n1 1 1\n") == "1"

# asymmetric dominance
assert run("1\n1000 1 1\n") == "500"

# symmetric large
assert run("1\n1000 1000 1000\n") == "1000"

# skewed split case
assert run("1\n2 1000 2\n") == "336"

 ## 特殊なケース

 主なエッジケースは、競合する言語の一方が非常に大きく、もう一方が非常に小さい場合です。 このような場合、最適な解は、大規模なグループをその許容数のサブグループに分割することによって支配され、Basic の学生は最大値を有意に減らすことができません。 

たとえば、入力の場合`1000 1 1`、アルゴリズムは、大きい側を最適に分離する構成を選択します。 計算された境界`ceil(1002/3) = 334`アセンブラを単一のグループに分割する必要があるという要件が大半を占めており、選択した構成では強制最大値が 500 と大きくなります。 このソリューションは、平均化のみに依存するのではなく、全体的および構造的な制約を最大限に活用することで、この不均衡を正確に捉えます。
