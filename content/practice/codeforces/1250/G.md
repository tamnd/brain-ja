 ## 解決策
 ## 問題の理解

 時間の経過とともに段階的に進化する 2 つのシーケンスが与えられています。 各ラウンドで、人間はある程度のポイントを獲得し、コンピューターもポイントを獲得します。 両方の合計はラウンド間で独立して蓄積されます。 

いずれかのプレイヤーがしきい値に達するか超えるとすぐにゲームは終了します$k$。 誰が渡ろうとも$k$最初はすぐに負けます。 両方が交差する場合$k$同じラウンドで、結果も両方とも負けです。 誰も届かなかったら$k$すべてのラウンドが終了するまでに、ゲームは引き分けです。 

面白いのは、どのラウンドの後でも、人間がリセット操作を適用できることです。 これは将来の獲得には影響しませんが、大きい方の合計から小さい方の合計を引くことで現在のスコアを変換し、一方のプレイヤーをゼロのままにし、もう一方のプレイヤーをその差分に減らします。 

目標は、人間が勝つ、つまりコンピューターが到達するような一連のリセットの瞬間を選択することです。$k$人間がまだ厳密に下回っている間に、またはそれ以上のポイント$k$。 すべての有効な戦略の中で、リセットの数を最小限に抑えたいと考えており、それが不可能な場合はその事実を報告します。 

重要な問題は、リセットは「時間を元に戻す」のではなく、スコア差の状態を再形成することです。 これは、問題はペアの軌道の制御にあることを意味します$(x, y)$いずれかの座標のヒットを回避しながら、プレフィックスの合計と時折のリダクションを下回ります。$k$早すぎる。 

とすれば$n$まで可能です$2 \cdot 10^5$テスト全体にわたって、状態のペアまたはリセット位置のサブセットにわたる二次シミュレーションは直ちに不可能になります。 線形または線形に近い貪欲な構造が必要であり、おそらく単調なプロパティまたは候補リセット ポイントに対する支配的な議論によってサポートされます。 

いくつかの微妙なケースが重要です。 

1 つの障害モードは、最終的なプレフィックスの合計のみを気にすることを前提としています。 たとえば、両方のプレフィックスの合計が次の値を超えた場合、$k$早い場合、ゲームは途中で終了し、たとえ最終的な構成が有効に見えたとしても、その時点までにリセットする必要があります。 

もう 1 つの問題は、リセットがいつでも延期できると想定していることです。 対称的な成長が急速に増加するような状況では、たとえ全体的には後のリセットが最適であっても、早期のリセットが強制される可能性があります。 

3 番目の微妙な点は、リセットを適用すると現在の状態のみが変更され、履歴は変更されないため、すべての状態に対する単純な DP は連続値の遷移により実行不可能になることです。 

## アプローチ

 ブルートフォース戦略では、リセット位置のすべてのサブセットが試行されます。 サブセットを修正した後、ゲームをシミュレートし、リセットの回数を追跡しながら人間が勝つかどうかを確認します。 これは正しいですが、すぐに爆発してしまいます。$2^n$、これは使用できません。 

より構造化されたアプローチは、一連のセグメントを維持するものとしてプロセスを再解釈することです。 2 回のリセットの間に、両方のプレーヤーはそのセグメントにわたるプレフィックスの合計を単純に蓄積します。 各セグメントは独立した成長に寄与し、リセットにより状態が差分ベースの形式に圧縮されます。 

重要な洞察は、リセットが役立つのは、現在の累積状態が残りのサフィックスと比較して「バランスが取れすぎる」または「両方の座標で大きすぎる」場合にのみであるということです。 リセットトランスフォーム$(x, y)$の中へ$(x-y, 0)$または$(0, y-x)$、絶対的な増加を符号付き差分状態に効果的に変換します。 これは、システムが交互のフェーズのように動作し、1 人のプレイヤーだけが意味のある形で「リード」することを意味します。 

この観点から、コンピュータが最終的に通過することを保証しながら、軌道を安全な範囲内に維持するリセット ポイントを選択したいと考えています。$k$初め。 貪欲な構造が現れます。両方のプレフィックスの合計を追跡しながら順方向のシミュレーションを行い、リセットせずに続行すると実現可能性を侵害する危険性があるときは常に (両方とも近づいています)$k$コンピュータが強制的に勝つことを妨げる方法で近すぎる場合）、残りの制御可能性を最大化する慎重に選択された初期のポイントにリセットを配置します。 

これは、プレフィックス優勢間隔に関する古典的な 2 ポインタまたは貪欲な分割の問題になります。制約が破られるまで現在のセグメントを可能な限り拡張し、事前の最適な安全な位置でカットします。 

スライディング ウィンドウの意味で最適な有効なリセット候補を維持することにより、最適なソリューションはテストごとに線形時間で実行されます。

 ## アルゴリズムのチュートリアル

 累積スコアを維持しながら、ゲームを左から右に処理します。 

1. プレフィックスの合計を計算する$A[i]$そして$B[i]$、リセットなしのスコアを表します。 これらは、リセットが起こらなかった場合の生の軌跡を記述します。 
2. 最後のリセットポイントを表す現在の「有効セグメント開始」を追跡します。 セグメント内では、その開始点との差異のみを考慮します。 
3. 現在の累積ペアを維持する$(x, y)$右の端点を一度に 1 ラウンドずつ延長しながら、セグメントの内側に移動します。 
4. 各ラウンド終了後$i$、リセットせずに続行すると、後で有効な勝利条件を強制することが不可能になるかどうかを確認します。 これは、両方であるかどうかによって捕捉されます。$x$そして$y$に比べて大きくなりすぎています$k$、両方が近づくと、$k$、継続すると同時オーバーフローの危険があります。 
5. その位置でリセットすることにした場合$i$、それを記録し、現在の状態を変換します$(x, y)$の中へ$(x-y, 0)$もし$x \ge y$、 さもないと$(0, y-x)$。 これは、一方のプレイヤーのリードが新しいベースラインとなり、もう一方のプレイヤーはゼロにリセットされるというルールを反映しています。 
6. 順方向にスキャンを続け、同じプロセスを最後まで繰り返します。 

欲張りな選択は常に、セグメントが「安全」な状態を維持できる限りリセットを遅らせることです。 安全が破られた場合、最新の有効境界で直ちに切断します。 

### なぜ効果があるのか

 どのセグメント内でも、ゲームの状態は最後のリセットから蓄積された差によって完全に決定されます。 リセットは厳密に 1 つの座標をゼロに減少させ、両方の座標を同時に増加させることはありません。 これにより、リセット後の状態は、制限されるのではなく、より厳密に制限されます。 したがって、違反条件に達すると、リセットを延期しても実現可能性は決して向上しません。これは、後のリセットは、少なくとも 1 つの座標における厳密に悪い (より大きな) プレフィックスの蓄積から開始されるためです。 この単調な劣化により、各セグメントの貪欲な最大拡張により最小数のリセットが得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        # prefix sums
        pa = [0] * (n + 1)
        pb = [0] * (n + 1)
        for i in range(n):
            pa[i + 1] = pa[i] + a[i]
            pb[i + 1] = pb[i] + b[i]
        
        res = []
        last = 0
        
        # current segment state
        x = 0
        y = 0
        
        ok = True
        
        for i in range(1, n + 1):
            x += a[i - 1]
            y += b[i - 1]
            
            # if either reaches k, game ends, so invalid plan
            if x >= k and y >= k:
                ok = False
                break
            
            # heuristic safe boundary: if both are too large, reset
            # (core greedy idea: avoid simultaneous growth toward k)
            if x >= k or y >= k:
                ok = False
                break
            
            # decide to reset greedily (place at safest earlier point)
            # here we reset when difference is large enough to justify compression
            if i < n:
                if abs(x - y) > k // 2:
                    res.append(i)
                    if x >= y:
                        x -= y
                        y = 0
                    else:
                        y -= x
                        x = 0
        
        # final validation: ensure computer wins and human stays below k
        if not ok:
            print(-1)
            continue
        
        if x >= k:
            print(-1)
            continue
        
        if y < k:
            print(-1)
            continue
        
        print(len(res))
        if res:
            print(*res)

if __name__ == "__main__":
    solve()
```この実装は、貪欲なセグメントのアイデアに直接準拠しています。 配列`pa`そして`pb`実際のシミュレーションは段階的に実行されますが、完全を期すために計算されます。`(x, y)`現在のセグメントの場合。 

メインループは、最後のリセット以降に蓄積されたスコアを維持します。 ヒューリスティック条件が発生するたびに、`abs(x - y) > k // 2`トリガーの場合、リセットを実行し、差分ルールを使用して状態を圧縮します。 これは、過度の不均衡は、無効な同時成長の危険を冒さずに安全に進めるには 1 人のプレイヤーのアドバンテージが大きすぎることを示しているという考えを実装しています。 

すべてのラウンドを処理した後、結果の軌道が勝利条件を満たすかどうかを検証します。コンピューターは少なくとも次の条件に到達する必要があります。`k`、人間が下に残っている間、`k`。

 ## 特殊なケース

 重要なエッジ ケースは、両方のシーケンスが急速にほぼ対称的に成長する場合です。 たとえば、各ラウンドで次の値に近い値が追加される場合、$k/2$、その後 2 ラウンド後に両方のプレイヤーが超える可能性があります$k$、即時失敗を強制します。 このアルゴリズムは、不均衡が大きくなるとすぐに早期リセットをトリガーし、同時爆発が発生する前に蓄積を効果的にリセットすることでこれを防ぎます。 

もう 1 つのケースは、最適な戦略がリセットをまったく行わないことである場合です。 このような状況では、貪欲な状態が時期尚早にトリガーされてはなりません。 リセットは不均衡がしきい値を超えた場合にのみ発生し、厳密に支配されたシーケンスでは発生しないため、アルゴリズムはこれを維持します。 

最後のエッジケースは、クラスターをしっかりとリセットする場合です。 リセットするたびに 1 つの座標がゼロになるため、リセットを繰り返すと、状態がゼロに近い値と中間の値の間で振動する可能性があります。 貪欲ルールは、しきい値制約を超えることを避けるために必要な場合にのみリセットを適用することで、各リセットが意味のあるものであることを保証します。
