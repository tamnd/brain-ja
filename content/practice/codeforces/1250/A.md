 ## 解決策
 ## 問題の理解

 受信した「いいね！」に基づいて投稿の位置が継続的に入れ替わるソーシャル メディア フィードをシミュレートしています。 最初は、ポストは上から下に固定の垂直順序で配置され、ポスト 1 が一番上、ポスト n が一番下になります。 投稿が「いいね！」を受け取るたびに、その投稿が既に最上位にない限り、そのすぐ上の投稿と交換して、1 つ上の位置に移動しようとします。 

フィードは、初期構成から始まり、「いいね！」のたびに時間の経過とともに進化します。 すべての投稿について、タイムライン全体で 2 つの値を決定するように求められます。それは、これまでに到達した最高の位置 (一番上に最も近く、インデックスが最小であることを意味します) と、これまでに到達した最悪の位置 (一番下に最も近く、インデックスが最大であることを意味します) です。 

重要な問題は、ポジションが動的であり、以前のすべてのスワップに依存することです。 文字通り完全な配列をシミュレートし、各ステップで位置を追跡する場合、各スワップは O(1) ですが、位置を更新するにはポストを検索する必要があるため、補助構造を維持しない限り非効率になります。 

この制約により、最大 100,000 件の投稿と 400,000 件の「いいね！」が許可されます。 配列をスキャンしてそれぞれの「いいね！」の投稿を見つけるソリューションは O(nm) にまで低下し、これは実現不可能です。 O(m log n) さえも不要です。 構造は非常に単純なので、直接インデックスを作成することですべてを線形時間内に維持できます。 

投稿が複数の「いいね！」を連続して受け取った場合、微妙なエッジケースが発生します。 このような場合、小さなステップで上向きに振動する可能性があり、素朴な直観により、実際よりも頻繁に位置 1 に到達すると誤って想定される可能性があります。 もう 1 つの特殊なケースは、投稿がまったく「いいね！」されない場合です。 その最小位置は最初は 1 のままで、その最大位置は全体を通して n のままです。 

## アプローチ

 ブルート フォース シミュレーションでは、フィードを表す配列全体が保持され、「いいね！」ごとに、「いいね！」された投稿の位置が検索され、その上の要素と交換されて続行されます。 これはシステムを正しくモデル化していますが、各検索は O(n) であり、m 回の操作があるため、複雑さは O(nm) になります。 最悪の場合の入力では、これは 4 × 10^10 演算を超えます。 

重要な点は、各ステップの後に完全な構造を知る必要がないということです。 各ポストが現在どこにあるかを知る必要があるだけで、ローカル スワップのみを更新します。 これは、各投稿を現在のインデックスにマップする位置配列を維持することを示唆しています。 その後、ポジションに直接アクセスして更新できるため、各スワップは O(1) になります。 

最小位置と最大位置を計算するために、ポストごとに 2 つの配列、つまり、これまでに占有された最小のインデックスと、これまでに占有された最大のインデックスを追跡します。 投稿が移動するたびに、その現在位置が更新され、場合によっては記録された境界も更新されます。 

ブルート フォースとの違いは、配列を検索する代わりに、ポストからインデックスへの逆マッピングを維持し、すべての操作を定数時間のブックキーピングに変換することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シミュレーション | O(nm) | O(n) | 遅すぎる |
 | トラッキングによる位置マッピング | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 pos[i] が投稿 i の現在位置である配列 pos と、order[p] が現在位置 p にある投稿である配列 order を維持します。 また、投稿ごとに最良の配列と最悪の配列も維持します。

1. order[1] = 1、order[2] = 2、...、order[n] = n になるように order を初期化し、すべての i に対して pos[i] = i を設定します。 すべての投稿に対して best[i] = i および worst[i] = i を設定します。 これにより、「いいね」を付ける前の初期設定がキャプチャされます。 
2. a_j のようなそれぞれについて、その現在位置 p = pos[a_j] を取得します。 直接インデックスを維持しているため、これは O(1) です。 
3. p がすでに 1 の場合は、移動が起こらないため、境界が正しいままであることを保証する以外は何も更新しません。 
4. それ以外の場合、その上のポストを b = order[p - 1] とします。 order 配列内の a_j と b を交換し、それに応じて pos 内のそれらの位置を更新します。 
5. 交換後、新しい位置を使用して、影響を受ける両方の投稿の最良と最悪を更新します。 これら 2 つのポストのみが位置を変更するため、境界に影響を与えることができるのはこれら 2 つのポストだけです。 
6. すべての「いいね！」の処理を順番に続けます。 

すべての更新を処理した後、best[i] と worst[i] には、ポスト i がこれまでに到達した最小インデックスと最大インデックスが含まれます。 

### なぜ効果があるのか

 システムは隣接するスワップによってのみ進化するため、各操作は正確に 2 つのポストに影響します。 位置は明示的に追跡されるため、pos 配列は常に現在の構成を曖昧さなく反映します。 投稿が移動するたびに、新しい位置が過去の最小値または最大値を改善するかどうかを直ちに評価します。 他の投稿はその交換の影響を受けないため、追加の更新は必要ありません。 これにより、グローバルな再計算を回避しながら正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = list(map(int, input().split()))

pos = [0] * (n + 1)
order = [0] * (n + 1)

best = [0] * (n + 1)
worst = [0] * (n + 1)

for i in range(1, n + 1):
    pos[i] = i
    order[i] = i
    best[i] = i
    worst[i] = i

for x in a:
    p = pos[x]
    if p == 1:
        continue

    y = order[p - 1]

    order[p], order[p - 1] = order[p - 1], order[p]
    pos[x] = p - 1
    pos[y] = p

    best[x] = min(best[x], p - 1)
    worst[x] = max(worst[x], p - 1)

    best[y] = min(best[y], p)
    worst[y] = max(worst[y], p)

for i in range(1, n + 1):
    print(best[i], worst[i])
```中心となる構造は、ポストとポジション間の双方向マッピングです。 pos 配列は検索を回避し、順序によって近傍を一定時間内に更新できるようにします。 唯一の微妙な点は、両方の投稿の位置が変更されているため、交換された両方の投稿の最高値と最低値を交換直後に更新する必要があることです。 

## 実用的な例

 ### 例 1

 入力:```
3 5
3 2 1 3 3
```各ステップの後に配列を追跡します。 

| ステップ | いいね | 注文 | pos(1,2,3) | 更新された投稿 |
 | --- | --- | --- | --- | --- |
 | 0 | - | [1,2,3] | (1,2,3) | 初期化 |
 | 1 | 3 | [1,3,2] | (1,3,2) | 3 |
 | 2 | 2 | [1,2,3] | (1,2,3) | 2,3 |
 | 3 | 1 | [1,2,3] | (1,2,3) | 1 |
 | 4 | 3 | [1,3,2] | (1,3,2) | 3 |
 | 5 | 3 | [3,1,2] | (3,1,2) | 3,1 |

 ポスト 1 は位置 1 および 2 に到達します。ポスト 2 は位置 2 および 3 に到達します。ポスト 3 は位置 1、2、および 3 に到達します。 

これにより、ローカル スワップのみを追跡するとグローバルな極値が正しく捕捉されることが確認されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 初期化は線形であり、それぞれの場合、一定の更新で最大 1 つのスワップが発生します。 
| スペース | O(n) | 配列は各ポストの位置、順序、境界を格納します。 

この制約では最大 400,000 回の操作が許可されるため、操作ごとの一定時間のシミュレーションは制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdin
    input = stdin.readline

    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    pos = [0] * (n + 1)
    order = [0] * (n + 1)
    best = [0] * (n + 1)
    worst = [0] * (n + 1)

    for i in range(1, n + 1):
        pos[i] = i
        order[i] = i
        best[i] = i
        worst[i] = i

    for x in a:
        p = pos[x]
        if p == 1:
            continue
        y = order[p - 1]

        order[p], order[p - 1] = order[p - 1], order[p]
        pos[x] = p - 1
        pos[y] = p

        best[x] = min(best[x], p - 1)
        worst[x] = max(worst[x], p - 1)
        best[y] = min(best[y], p)
        worst[y] = max(worst[y], p)

    return "\n".join(f"{best[i]} {worst[i]}" for i in range(1, n + 1)) + "\n"

assert run("3 5\n3 2 1 3 3\n") == "1 2\n2 3\n1 3\n"

assert run("1 5\n1 1 1 1 1\n") == "1 1\n"

assert run("2 1\n2\n") == "1 2\n1 2\n"

assert run("4 3\n4 4 4\n") == "1 4\n2 2\n3 3\n1 4\n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一の繰り返しのいいね | 安定した要素の動き | 変更なしのスワップ |
 | 最小の n=1 | 些細な安定性 | 境界の正確性 |
 | シングルスワップ | ダイレクトワンステップ効果 | 基本的な隣接関係の更新 |
 | 繰り返されるトップの動き | 単調な上昇 | 写真 繰り返される更新の一貫性 |

 ## 特殊なケース

 決して「いいね！」されなかった投稿は決して移動しないため、最高の順位は 1 のままで、最悪の順位は n のままです。 初期化によって両方の境界が正しく設定され、更新がその投稿に影響を与えないため、アルゴリズムがこれを処理します。 

繰り返し「いいね！」を受け取った投稿は、トップに向かって段階的に上昇する可能性があります。 スワップごとに両方の参加者が更新されるため、中間ポジションはすべてキャプチャされます。 すべての動きはローカルであるため、グローバルな再計算は必要ありません。 

現在の最上位要素に対する「いいね！」は交換をトリガーしません。 位置 1 の条件チェックにより、無効な配列アクセスが防止され、不必要な更新が発生しないことが保証され、正確性が維持され、インデックス エラーが回避されます。
