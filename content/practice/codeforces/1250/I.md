 ## 解決策
 ## 問題の理解

 ダンサーのリストが与えられ、それぞれのダンサーのぎこちなさの値が固定されています。 「コンサート」は、これらのダンサーの一部を選択することとして定義されます。 すべてのサブセットが許可されるわけではありません。選択したサブセットの合計のぎこちなさが制限を超えてはなりません$k$。 

すべての有効なサブセットの中で、概念的には厳密な優先順位に従ってそれらを並べ替えます。 主キーはサブセットのサイズであり、セットが大きいほど常に優れています。 2 つのサブセットのサイズが同じ場合、合計の不自然さが小さい方が優先されます。 サイズと合計の両方が等しい場合、それらは等しいとみなされます。 

最高のものを挙げるように求められています$m$この順序のサブセット、または有効なサブセットが少ない場合はさらに少なくなります。 これらのサブセットごとに、そのサイズと合計を出力します。 リストの最後のサブセットについては、実際に選択されたインデックスも出力する必要があります。 

問題は、サブセットの数が指数関数的に増加することです。$n$したがって、たとえ小さな入力であっても、それらを直接列挙することは不可能です。 タスクは基本的にトップを生成することです$m$タプルによって定義された辞書編集的な順序に基づくサブセット$(-|S|, \sum a_i)$合計に対する制約の下で。 

制約が十分に大きいため、サブセットの列挙を含むソリューションは、たとえ部分的であっても、すぐに失敗します。 と$n$まで$10^6$、テスト ケースごとにすべてのサブセットまたはすべての組み合わせを考慮するアルゴリズムは除外されます。 平$O(n^2)$テストケースごとには不可能です。 

明らかではないエッジケースは次のような場合です$k$すべてに比べて非常に小さい$a_i$。 この場合、単一要素のサブセットのみが有効です (またはまったくサブセットが存在しません)。 より大きなセットが常に存在すると仮定する単純なアプローチでは、無効な組み合わせが試行され、早期の枝刈りが失敗します。 

もう 1 つの特殊なケースは、$a_i$は同一です。 その場合、複数のサブセットがサイズと合計の両方を共有するため、タイブレークは無関係になりますが、不注意な実装では依然として順序付けの一意性を不必要に強制しようとする可能性があり、オーバーヘッドが発生します。 

## アプローチ

 ブルートフォース戦略では、すべてのサブセットを生成し、その合計とサイズを計算し、超過したものをフィルタリングします。$k$、並べ替えます。 これは正しいですが、実行不可能です。$2^n$サブセット、さらには$n=40$、これは境界線になりますが、ここでは$n$到達できる$10^6$。 

重要な観察は、順序付けではより大きなサブセットが強く優先されるということです。 これは、任意のサブセットという観点から考えるのではなく、与えられたサイズの合計を常に最小限に抑えながら、サブセットを段階的に構築するという観点から考える必要があることを示唆しています。 固定サイズの場合$s$、最良のサブセットは単に$s$配列の最小要素。 

これにより、問題の構造が大幅に軽減されます。ソートされた配列のプレフィックスを考慮するだけで済みます。 仕分け後$a$、最初のものを取ると、$s$サイズのすべてのサブセット間で可能な最小の合計を与える要素$s$。 他のサイズのサブセット$s$の合計はそれより大きいか等しいため、順序付けにおいてこれが優れていることはありません。 

したがって、各プレフィックス サイズに対して$s$、その合計を計算し、それが次であるかどうかを確認できます。$\le k$。 実現可能な最大の$s$は最良のサブセットを提供し、次に最良のサブセットはわずかに悪い構成から得られますが、ヒープを使用した貪欲なプロセスを使用して候補を生成できます。可能な限り最小のセットから開始し、実現可能性を維持しながら要素を徐々に大きなセットに置き換えようとします。 これは、最良の優先順位でサブセット空間を探索することと同等です。 

サブセット サイズ (降順) と合計 (昇順) をキーとした優先キューを維持します。 各状態はサブセットを表します。 重複を避けるために並べ替えられた構造を維持しながら、要素を交換してインデックスを増やすことによって隣接要素を生成します。 残りの最良の状態のみを展開するため、自然に、次の状態に到達するまで、必要な順序でサブセットを列挙します。$m$。

 ## アルゴリズムのチュートリアル

 1. 元のインデックスを維持しながら、ぎこちなさによってダンサーを並べ替えます。 ソートは、サブセットを貪欲に構築するときは必ず、常に利用可能な最小の要素を最初に含めることを保証し、固定サイズの合計を最小化するため、ソートが不可欠です。 
2. 可能な限り最小の有効なサブセットを使用して初期状態を構築します。 空のセットから始めて、次の要素の追加が制限を超えるまで、ソートされたリストから要素を貪欲に追加します。$k$。 これにより、サイズごとに実現可能な最大のサブセットが得られ、その中で最小の合計が得られます。 
3. この最初のサブセットを優先キューにプッシュします。 キューは、サイズの大きいサブセットが最初に処理され、同じサイズのサブセットの合計が小さいサブセットが最初に処理されるように順序付けされます。 これは、問題のランキング ルールを直接エンコードします。 
4. キューから最適なサブセットを繰り返し抽出します。 各抽出は、次に優れたコンサートに対応します。 抽出したら停止します$m$サブセットが存在しない場合、キューが空になります。 
5. 抽出された各サブセットについて、そのサイズと合計を記録します。 これらは、最後のコンサートではダンサーの実際のインデックスも保存することを除き、すべてのコンサートに必要な出力です。 
6. 現在のサブセットから、「アップグレード」を試みて新しい候補サブセットを生成します。 ソートされた配列内の要素を後の要素に置き換えることができる最大のインデックス位置を取得し、正規の増加インデックス表現を維持することで重複がないようにします。 有効な置換ごとに、サイズがわずかに小さいか合計が大きくなる可能性のある新しいサブセットが生成され、これまでに存在しなかった場合はキューにプッシュされます。 
7. 同じサブセットの繰り返し処理を防ぐために、インデックスのビットマスクのような表現またはタプル表現によってキー設定された訪問セットを使用します。 

### なぜ効果があるのか

 すべての遷移で有効性が保持され、一連の制御された置換を通じて最初の貪欲シードから最終的にすべてのサブセットに到達できるため、各ステップで優先キューには常にすべての未確認のサブセットの中で最良のサブセットが含まれます。 ヒープ内の順序は、サブセットのサイズと合計によって定義される辞書編集順序と正確に一致するため、抽出順序は必要な出力順序と一致します。 スキップされたサブセットは、サイズと合計の両方において以前に抽出されたサブセットによって支配される必要があるため、より適切なサブセットをスキップすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    t = int(input())
    for _ in range(t):
        n, k, m = map(int, input().split())
        a = list(map(int, input().split()))
        
        arr = sorted([(a[i], i + 1) for i in range(n)])
        vals = [x[0] for x in arr]
        idxs = [x[1] for x in arr]

        # initial greedy subset: take as many smallest as possible
        cur_sum = 0
        cur = []
        for i in range(n):
            if cur_sum + vals[i] <= k:
                cur_sum += vals[i]
                cur.append(i)
            else:
                break

        if not cur:
            print(0)
            continue

        # state: (-size, sum, tuple of indices in sorted-space)
        start = (-len(cur), cur_sum, tuple(cur))
        pq = [start]
        seen = set([start[2]])

        results = []

        while pq and len(results) < m:
            neg_sz, s, comb = heapq.heappop(pq)
            sz = -neg_sz

            results.append((sz, s, comb))

            # expand neighbors
            comb_list = list(comb)
            used = set(comb_list)

            for i in range(len(comb_list) - 1, -1, -1):
                for nxt in range(comb_list[i] + 1, n):
                    if nxt in used:
                        continue
                    new_comb = comb_list[:i] + [nxt]
                    new_sum = sum(vals[j] for j in new_comb)
                    if new_sum <= k:
                        new_comb_t = tuple(new_comb)
                        if new_comb_t not in seen:
                            seen.add(new_comb_t)
                            heapq.heappush(pq, (-len(new_comb), new_sum, new_comb_t))
                used.remove(comb_list[i])

        r = len(results)
        if r == 0:
            print(0)
            continue

        print(r)
        for i in range(r):
            sz, s, _ = results[i]
            print(sz, s)

        last = results[-1][2]
        print(len(last))
        print(" ".join(str(idxs[i]) for i in last))

if __name__ == "__main__":
    solve()
```この解決策では、まずダンサーをソートすることで問題を軽減し、サブセットの構築が合計で単調になるようにします。 その後、ヒープは必要な順序付けをグローバルに適用し、常に残りの最適なサブセットを拡張します。 

重要な実装の詳細は、サブセットが元のインデックスではなく、並べ替えられた配列内の並べ替えられた位置に関して格納されることです。 これにより正規表現が保証され、状態の重複が防止されます。 の`seen`set により、同一のサブセットを再度訪問することがなくなります。 

拡張ステップでは、要素を右から左に慎重に置き換えてインデックスの昇順を維持し、同じサブセットの順列の生成を回避します。

 ## 特殊なケース

 いつすべて$a_i > k$、最初の貪欲な構築では空のサブセットが生成されます。 有効な状態がヒープに入らないため、アルゴリズムはすぐに 0 を出力します。 

すべての値が等しいなど、多くのサブセットが同じサイズと合計を共有する場合、ヒープは複数の同等の状態を生成する可能性があります。 の`seen`set により、正規のインデックスの組み合わせのみが 1 回処理されるようになり、指数関数的な爆発が防止されます。 

いつ$k$すべての要素を含めるのに十分な大きさである場合、初期状態は完全なセットになり、展開ではより少ない要素を含むサブセットのみが生成されます。 サブセット サイズが優先され、ヒープは自然に最大から最小の順に出力されるため、順序付けは依然として維持されます。
