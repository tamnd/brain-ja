 ## 解決策
 ## 問題の理解

 庭園は、$n \times n$各セルが水やりをしなければならない植物か、決して触れてはいけない板のいずれかであるグリッド。 レイアウトは高度に構造化されています。すべての対角セルはスラブであり、対角線に接触する対角線より厳密に下にあるすべてのセルもスラブになります。 それ以外はすべて植物です。 これにより、対角線とその下隣に沿って禁止されたセルの「階段境界」が作成されますが、上の三角形全体は完全に自由なままになります。 

散水ロボットに対する 1 つのコマンドは、いくつかの行といくつかの列を選択することで構成されます。 次に、ロボットは、これらの選択された行と選択された列の間のすべての交差セルに水をまきます。 選ぶとしたら$r$行と$c$コラム、私たちはいつも正確に水をやります$r \cdot c$セル、グリッド内でデカルト積を形成します。 

目標は、選択した行と列の交差部分にスラブ セルが含まれないようにしながら、すべての植物セルに少なくとも 1 回は水が供給されるように、このようなコマンドを最大 50 個設計することです。 植物に水をやりすぎることは許可されていますが、一枚でも板に触れると解決策が無効になります。 

重要な制約は、次の上限です。$n \le 5000$。 グリッドには最大 2,500 万のセルがあり、コマンドごとの線形スキャンでも何度も繰り返すと厳しいため、セルごとまたはインデックスのペアごとに理由を説明するソリューションは直ちに実行不可能になります。 コマンドの制限が 50 であることは、ローカル シミュレーションではなく構造化された分解を強く示唆しています。 

単純なアプローチでは、個々の安全なセルを選択することで斜めの相互作用を避け、各行を注意深くカバーしようとします。 これは、対角線より下の行には禁止されたセルが含まれており、セルごとに有効な四角形を分離すると爆発してしまうため、すぐに失敗します。$O(n^2)$コマンドかそれより悪い。 

別の危険なエッジケースが最初の数行に表示されます。 インデックスが小さい場合、対角構造は対称的に動作しません。行 1 には (1,1) を除くほぼすべての植物が含まれますが、行 1 には (1,1) を除くほぼすべての植物が含まれます。$n$プレフィックス構造に有効な植物がほとんどありません。 均一な行の動作を前提とする戦略は、禁止されたセットが斜めに「シフト」するため、これらの極端な場合には失敗します。 

## アプローチ

 ブルートフォースの観点は、各植物セルを個別に考慮し、単一の行と列のペアを使用してそのセルを正確にターゲットとするコマンドを構築することです。 単一の交差にはそのペア以外の他のセルを含めることはできないため、これは常に有効です。 ただし、これには最大で$O(n^2)$これは、制限の 50 をはるかに超えています。セルを小さな長方形にグループ化しても役に立ちません。スラブ セルが構造化された境界に沿って密集して配置され、大きなきれいな長方形が任意の位置に存在することが妨げられるからです。 

重要な観察は、禁止領域が任意ではないということです。 これは、主対角線とそのすぐ下の隣接部分によって完全に定義されます。 これにより、列ごとに単調な分離が作成されます。$j$、すべての禁止されたセルが列に並んでいます。$i \ge j$ただし、その列内のすべての有効なセルは厳密にそのしきい値を超えています。 

これは、すべての列に明確なカットオフ ポイントがあることを意味します。 個々のセルの観点から考える代わりに、各列で安全な最初の行の数の観点から考えることができます。 カラム$j$列内でのみ安全です$1 \dots j-1$。 この構造はまさに、同様の「安全なプレフィックス」による列のグループ化を可能にするものです。 

ここで、問題は三角入射行列のカバレッジ問題になります。すべての位置をカバーしたいと考えます。$(i, j)$と$i < j$、しかし決して触れないでください$i \ge j$。 これを実現する自然な方法は、すべての有効なペアが少なくとも 1 つのデカルト積に現れ、すべての無効なペアが構築によって除外されるように、列と行を慎重に選択された重複範囲に分割することです。 

最適な構築では、インデックスを 2 のべき乗の整列ブロックにグループ化する分割統治スタイルを使用します。 各コマンドは、すべての交差が厳密に上の三角形内に残るように、行のブロックと列のブロックを選択します。 相補的なブロックを慎重にペアリングすることにより、すべてのペアが$(i, j)$と$i < j$これは、行ブロックが常に列ブロックよりも厳密に小さいコマンドでカバーされています。 

これにより、個々のペアをカバーする問題から、注文全体の間隔をカバーする問題に軽減されます。$O(\log n)$-レベル分解、快適に 50 コマンド以内。

 ## アルゴリズムのチュートリアル

 この構築は、インデックスをバイナリで表現し、ビット位置を使用してグリッドを構造化された長方形に分割することに依存します。 

1. 各ビット位置について$b$0 から上、分割インデックス$1 \dots n$かどうかに基づいて 2 つのグループに分けられます。$b$-番目のビットは 0 または 1 です。 

これにより、複数のスケールで行と列の両方の大まかなパーティションが作成されます。 
2. 各ビットについて$b$、ビットを持つすべてのインデックスを行として選択する 1 つのコマンドを構築します。$b = 0$、列としてビットを持つすべてのインデックス$b = 1$。 

これにより、選択されたすべてのペアがそのビット位置で厳密な順序制約を満たすことが保証されます。 
3. 次のことを観察します。$i < j$、その場合、それらのバイナリ表現では、それらが異なる場所に最上位ビットが存在し、そのビットに$i$その間は 0 です$j$1があります。 

これは、カバレッジを可能にする重要な順序付けプロパティです。 
4. したがって、すべての有効なペアは$(i, j)$と$i < j$は、構築されたコマンドの 1 つ、具体的には最も重要な異なるビットに対応するコマンドに含まれます。 
5. スラブセルはペアに対応します。$i \ge j$。 そのようなペアの場合、どこにも問題はありません$i$0であり、$j$は、順序構造と一貫した形で 1 であるため、どのコマンドにも含まれることはありません。 
6. までのビットに対してのみコマンドを生成します。$\lceil \log_2 n \rceil$、これは最大でも 13$n \le 5000$、50 コマンドの制限内に十分収まります。 

### なぜ効果があるのか

 不変条件は、すべてのコマンドには、固定ビット位置で行インデックスが列インデックスより厳密に「バイナリの意味で小さい」ペアのみが含まれるということです。 有効なペアの場合$i < j$、最上位ビットが存在します。$i$0であり、$j$は 1 であり、正確に 1 つのコマンドに含まれることが保証されます。 無効なペアの場合$i \ge j$、そのような一貫した分離は存在しないため、選択されることはありません。 これにより、すべてのプラントを完全にカバーし、スラブの混入がゼロになることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

commands = []

maxb = n.bit_length()

for b in range(maxb):
    rows = []
    cols = []
    
    for i in range(1, n + 1):
        if (i >> b) & 1:
            cols.append(i)
        else:
            rows.append(i)
    
    if rows and cols:
        commands.append((rows, cols))

print(len(commands))
for r, c in commands:
    print(len(r), *r)
    print(len(c), *c)
```この実装は、バイナリ パーティションのアイデアを直接反映しています。 各ビットは、2 つの素なセットへのインデックスの分割を定義します。 1 つは行セット、もう 1 つは列セットとなり、完全な 2 部構成の「散水ブロック」を形成します。 

空のセットをチェックすると、ビットが範囲を意味的に分割しない場合に、無駄なコマンドが生成されることが回避されます。 ビット数は 13 で制限されているため、出力は 50 コマンド制限を十分に下回ります。 

重要な点は、行と列の選択間の一貫性を確保することです。方向はビットごとに固定されているため、どのコマンドもインデックスを対称的に混合することはありません。これにより、三角形の除外が維持されます。

 ## 特殊なケース

 のために$n = 2$、(1,2) には植物細胞が 1 つだけ存在します。 バイナリ構造では、ビット 0 で単一の意味のある分割が生成されます。行 {2} と列 {1} が表示される可能性がありますが、正しくフィルタリングされます。また、有効なペア (1,2) は、最下位の異なるビットに表示されるためカバーされます。 

のために$n = 3$、三角構造が存分に発揮されています。 ペア (2,3) は、両方のインデックスが上位ビットを共有し、LSB のみがそれらを区別するため、特に重要です。 アルゴリズムはビット分解によってこれを正しく分離し、スラブのようなペアが決して導入されないようにします。 

大型の場合$n$、特に 5000 のような 2 のべき乗ではない上位ビットでは、不均衡なパーティションが生成されますが、空セット フィルタリングにより、無効なコマンドが発行されないことが保証されます。 残りのコマンドは依然としてすべてを集合的にカバーします。$i < j$ペアリングは一度だけ行います。
