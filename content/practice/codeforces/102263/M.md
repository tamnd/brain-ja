 ## 問題の理解

 小文字の文字列があります。 任意の 2 つの位置を自由に交換できるため、文字の順序が実際の制限になることはありません。 2 番目の操作では、隣接する 2 つの等しい文字を取得し、次の文字に置き換えます。 たとえば、2 つの`c`キャラクターはひとつになれる`d`、その間に2`z`の後に文字がないため、文字を結合できません`z`。 

目標は、一連の操作を実行し、辞書編集上可能な最大の文字列を取得することです。 任意の入れ替えが可能なので、各文字のコピーが何部残っているかがわかれば、いつでも降順に並べることができます。 したがって、本当の問題は、最終的に最適な文字のマルチセットを決定することです。 

長さは次のように大きくすることができます`10^5`。 これは、考えられる多くの操作シーケンスを繰り返し探索したり、操作のたびに文字列全体をスキャンしたりするアルゴリズムを除外するには十分な大きさです。 線形または線形に近い解決策が適切です。 アルファベットは 26 文字しかないため、ある文字から次の文字に情報を伝えるのに特に便利な一定サイズの次元が得られます。 

不注意な実装によって問題が発生する可能性のあるエッジケースがいくつかあります。 入力用`aa`、正しい出力は次のとおりです。`b`。 元の文字列を単純にソートすると、`aa`、最初の文字を厳密に改善する操作が欠落しています。 のために`zz`、正しい出力は次のとおりです。`zz`、 なぜなら`z`後継者がいない。 すべてのペアを盲目的にインクリメントする実装では、アルファベット以外の文字が誤って生成されてしまいます。 のために`yyy`、正しい出力は次のとおりです。`zy`: 1ペア`y`になる`z`、残りは`y`他の作戦には参加できません。 最後に、`aaaa`、答えは`c`、 ない`bb`。 最初の 2 つのマージの後、次の結果が得られます`bb`、そしてその2つ`b`キャラクターは再びマージすることができます`c`。 新たに作成されたペアを上方に転送せずに各文字を 1 回だけ処理するソリューションでは、このカスケードを見逃してしまいます。 

## アプローチ

 直接シミュレーションでは、2 つの等しい文字を繰り返し検索し、そのようなペアをまとめるために必要に応じて文字を交換し、そのペアを後続の文字に置き換え、有用なペアがなくなるまで続行できます。 これは、使用可能なすべてのペアが最終的に処理される場合には正しいです。これは、操作ごとに文字列の長さが 1 つ減り、交換によって 2 つの等しい文字が隣接することができるためです。 

問題は、そのシミュレーションを効率的に実行するためのコストです。 いくつでもありえます`n - 1`操作。 この最大値は、たとえば文字列が 2 の累乗数で構成されている場合に達成されます。`a`文字。 と`n = 100000`、すべての操作を実行した後に現在の文字列をスキャンしてマージを見つける単純な実装です。`100000 + 99999 + ... + 1 = 5,000,050,000`最悪の場合は文字検査。 考えられるさまざまな操作順序を探索すると、大規模な検索ツリーが作成される可能性があるため、さらに困難になります。 

重要な観察は、スワップによってポジションの重要性が完全になくなるということです。 各文字の数だけが必要です。 あると仮定します`cnt[c]`ある手紙のコピー`c`。 すべてのペアを 1 つと置き換えることができます`c + 1`。 あれば`cnt[c] // 2`ペアの場合、それらはすべて変換できます。`cnt[c] % 2`のコピー`c`そして追加`cnt[c] // 2`次の文字にコピーします。 

この操作は、辞書編集上の最大化にとって常に有益です。 の 2 部`c`厳密に大きい文字の 1 つのコピーに置き換えられます`c + 1`。 残りの文字はすべて降順でソートできるため、アルファベットで 1 文字を上に移動すると、それらの文字からの最大の主要な寄与が得られます。 また、下位文字のペアは常に変換可能であり、次の文字で新たに作成されたペア自体も再度変換できるため、下位文字のペアを保持する理由もありません。 

したがって、プロセス全体は小さなキャリー操作になります。 からアルファベットを処理します`a`を通して`y`。 各カウントのパリティは現在の文字に残りますが、カウントの半分は次の文字に引き継がれます。 の`z`カウントは決して変更されません。`zz`変換できません。 最後に、残りのすべての文字を次から出力します。`z`まで`a`。 

各マージが有効な操作を表すため、ブルート フォース プロセスは機能しますが、マージの数が線形になり、各マージで別のスキャンが必要になると失敗します。 文字カウントのみが重要であるという観察により、これらの操作すべてを 25 個の定数時間カウントの遷移に置き換えることができます。

 ## アルゴリズムのチュートリアル

 1. 入力文字列内に 26 個の小文字がそれぞれ何回出現するかを数えます。 任意のスワップにより、必要に応じていつでも文字列を再配置できるため、位置を保持する必要はありません。 
2.からの手紙を処理する`a`に`y`。 カウント付きの現在の文字の場合`cnt[i]`、 保つ`cnt[i] % 2`この手紙をコピーして追加します`cnt[i] // 2`にコピーします`cnt[i + 1]`。 これは、現在の文字の可能なすべてのマージの実行を正確に表します。 
3. 更新されたカウントを使用して次の文字の処理を続行します。 このステップは、次のようなカスケードを処理します。`aaaa -> bb -> c`。 あるレベルで作成されたコピーは、元の入力に存在していたコピーとまったく同じように扱われます。 
4. カウントを残す`z`変わらない。 後に文字がありません`z`、つまり、一対`z`文字は変換できません。 
5. 以下を反復して答えを構築します。`z`まで`a`そして、最終的な数に従って各文字を追加します。 固定マルチセットの場合、より大きな文字を前に配置すると常に最大の文字列が生成されるため、この順序は辞書編集的に最大になります。 

なぜ機能するのか: 手紙を処理した後`i`、その最終的なカウントは、到達したコピーの数と正確に等価ですが、考えられるすべてのペアは次の文字に変換されます。 破棄されたペアは、それぞれが正確に 1 つのコピーを提供するため、失われることはありません。`i + 1`。 したがって、不変条件は、処理されたアルファベットの接頭辞が可能な限り上方に削減され、残りのすべてのペアが次の位置で表されるということです。 ペアが上に繰り上げられると、下位の文字をさらに改善することはできず、結果として得られるマルチセットには降順が最適であるため、最終的な文字列は辞書編集的に最大になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(s: str) -> str:
    cnt = [0] * 26

    for ch in s:
        cnt[ord(ch) - ord('a')] += 1

    for i in range(25):
        cnt[i + 1] += cnt[i] // 2
        cnt[i] %= 2

    ans = []

    for i in range(25, -1, -1):
        if cnt[i]:
            ans.append(chr(ord('a') + i) * cnt[i])

    return ''.join(ans)

def main():
    s = input().strip()
    print(solve(s))

if __name__ == "__main__":
    main()
```の`cnt`配列には、各文字の現在の多重度が格納されます。 入力をカウントするには文字列を 1 回通過し、各文字は ASCII 値を使用してインデックスに直接マップされます。 

インデックスからのループ`0`を通して`24`各文字から後続文字へのキャリー操作を実行します。 順序は重要です。 加工時`b`、そのカウントには、から生成されたペアがすでに含まれている可能性があります。`a`したがって、アルファベットを低位から高位まで処理すると、任意の長さの操作チェーンが自動的に処理されます。 

表現`cnt[i] // 2`はマージできるペアの数ですが、`cnt[i] % 2`現在の文字に残すべき唯一の数字です。 ここでは Python 整数にはオーバーフローの問題はなく、すべてのカウントは最大でも元の文字列の長さになります。 

構築ループは逆方向に実行され、大きな文字が最初に表示されます。 最終カウントに従って各文字を繰り返すと、キャリー プロセスによって生成された正確な最終マルチセットが保存されます。 

スワップを明示的にシミュレートする必要はありません。 元の操作における唯一の目的は、等しい文字を隣接させることです。文字をカウントすることで、中間文字列を構築することなく、すでに同じ自由度が得られます。
