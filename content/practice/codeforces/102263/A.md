 ## 解決策
 ## 問題の理解

 各参加チームには、問題ステートメントの印刷コピーが 1 部だけ必要です。 1部印刷費がかかる場合`k`コインとあります`n`チームの場合、合計コストは 1 コピーのコストにチームの数を掛けたものになります。 

入力には 2 つの整数が含まれています。`n`そして`k`。 値`n`コピーが必要なチームの数がわかります。`k`1部の印刷料金です。 必要な出力は、各チームで 1 部印刷するのに必要なコインの合計数です。これは単純に次のとおりです。`n * k`。 

どちらの値も 1 ～ 1000 の間です。これらの境界は非常に小さいため、線形アルゴリズムであってもすぐに終了します。 配列、グラフ、動的プログラミング、または反復プロセスは必要ありません。 合計は 2 つの入力値から直接取得されるため、定数時間が自然な解になります。 

可能な最小の入力は次のとおりです。`1 1`を生成します。`1`。 複数のチームが存在することを前提とした不用意な実装は、このケースを誤って処理する可能性がありますが、単一チームについては数学的に特別なことは何もありません。 

たとえば、入力の場合`1 7`、必要なコピーは 1 つだけなので、出力は次のようになります。`7`。 ループ境界が正しくないために誤ってもう一度価格を追加する実装では、`14`。 

可能な最大値も簡単です。 入力あり`1000 1000`、答えは`1000000`。 結果はどちらの入力よりも大きいため、固定幅の整数型を使用する言語で不必要に狭い整数型を使用する実装は、この問題の別のバージョンでオーバーフローする可能性があります。 Python の整数にはこの問題はありません。 

## アプローチ

 直接的な総当たりアプローチでは、印刷プロセスがシミュレートされます。 合計ゼロから開始して繰り返します`n`回、追加`k`反復ごとに合計を計算します。 これは正しいです。各反復は 1 つのチームが 1 つの印刷コピーを受け取ることを表すため、すべての反復後の累積値は正確にすべてのコピーのコストになります。 

実際の制約がある場合、このブルートフォース手法では最大 1000 回の加算が実行されます。 全然遅すぎず、すんなり受け入れられそうです。 この特定のブルートフォース手法が実際的な問題となる正確な入力サイズはありません。 

より良い観察は、同じ値を繰り返し追加することです。`k`、 その通り`n`倍は乗算の定義です。 パフォーマンスする代わりに`k + k + ... + k`ループを通じて計算できます`n * k`直接。 これにより、仕事が比例から減少します。`n`固定数の算術演算に。 

各チームが正確に貢献するため、ブルートフォースが機能します`k`コインですが、同じ計算をチームごとに個別に実行します。 問題の構造から、すべての寄与が等しいことがわかり、合計は 1 つの乗算にまとめられます。

 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの整数を読み取ります`n`そして`k`。 1 つ目はチームの数を表し、2 つ目は 1 部の印刷コストを表します。 
2. コンピューティング`n * k`。 それぞれの`n`チームには 1 つのコピーが必要で、各コピーのコストは正確です`k`したがって、個々のチームを明示的にシミュレートしなくても、乗算によって完全なコストが得られます。 
3. 結果の値を出力します。 乗算は要求された合計をすでに表しているため、追加の処理は必要ありません。 

### なぜ効果があるのか

 すべてのチームに対して、ジャッジは正確に支出します`k`コイン。 と`n`チームの場合、合計は繰り返しの合計として書くことができます`k + k + ... + k`、を含む`n`条項。 乗算の定義により、この合計は次となります。`n * k`。 アルゴリズムはこの値を正確に計算するため、出力される結果が必要な総コストになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
print(n * k)
```最初の行はインポートします`sys`、ソリューションでの使用を許可します`sys.stdin.readline`競技プログラミング入力の要求に応じて。 

2 行目は唯一の入力行を読み取り、空白で区切られた 2 つの値を整数に変換します。 問題には値のペアが 1 つだけ含まれているため、複数のテスト ケースを処理する必要はありません。 

最後の行では、完全な計算が実行され、それが出力されます。 ループ境界やインデックス操作がないため、off-by-one の問題は発生しません。 Python の整数型は、許可された結果全体を安全に処理します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline
    n, k = map(int, input().split())
    print(n * k)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# provided samples
assert run("5 3\n") == "15\n", "sample 1"
assert run("4 1\n") == "4\n", "sample 2"

# minimum-size input
assert run("1 1\n") == "1\n", "minimum values"

# maximum-size input
assert run("1000 1000\n") == "1000000\n", "maximum values"

# one team with a larger printing cost
assert run("1 1000\n") == "1000\n", "single team"

# minimum printing cost with the maximum number of teams
assert run("1000 1\n") == "1000\n", "unit cost"

 ## 特殊なケース

 入力`1 1`は最小の有効なケースです。 アルゴリズムは次のように読み取ります`n = 1`そして`k = 1`、計算します`1 * 1`、およびプリント`1`。 何も特殊なケースにする必要はなく、境界エラーを引き起こす可能性のある条件を導入するよりも望ましい方法です。 

入力`1 7`これは、正確に 1 つのチームが 7 コインで正確に 1 つのコピーを支払うことを表します。 計算は`1 * 7 = 7`したがって、出力は次のようになります`7`。 次のような、範囲が正しくないループベースの実装。`range(1, n)`0 回実行され、誤って 0 が生成されます。 

入力`1000 1000`問題で許可されている最大値を実行します。 計算は`1000 * 1000 = 1000000`。 アルゴリズムは次の大きさに依存しません。`n`Python は演算の数を表すことができ、Python は結果の整数を直接表すことができます。 

入力`1000 1`すべてのコピーのコストが最小になるもう一方の境界をテストします。 合計は`1000 * 1 = 1000`。 これは、個々のコピーのコストではなく、チームの数が合計に対する貢献数を決定することを裏付けています。
