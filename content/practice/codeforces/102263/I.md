 ## 解決策
 ## 問題の理解

 (n) 個の整数の配列があります。 (2) から (n) までのすべてのサイズ (k) について、配列の順序を維持しながら任意の (k) 個の要素を選択できます。選択した要素の順序付けされていないすべてのペアにわたる絶対差の絶対和の最大値が必要です。 

元の配列内で選択された要素の順序は、実際には (F) の値に影響しません。 選択された値の複数セットのみが重要です。 これにより、配列をソートし、値について完全に推論できるようになります。 

選択した値が次のようにソートされているとします。 

[
 x_1 \le x_2 \le \dots \le x_k.
 】

 (i<j) を持つすべてのペアは (x_j-x_i) に寄与します。 

[
 F(S)=\sum_{i<j}(x_j-x_i)。 
】

 各 (x_i) の係数を収集すると、これは次のようになります。 

[
 F(S)=\sum_{i=1}^{k}(2i-k-1)x_i。 
】

 係数は、小さい位置では負、大きい位置では正、(k) が奇数の場合は中間の位置ではゼロになります。 これは、最適なサブセットでは、係数が負の場合は可能な最小値を使用し、係数が正の場合は可能な最大値を使用する必要があることを直ちに示唆します。 

(n) は (3\cdot10^5) に達する可能性があるため、(O(n^2)) アルゴリズムは遅すぎます。 (n=3\cdot10^5) のとき、すでにおよそ (4.5\cdot10^{10}) 個のペアが存在するため、ペアごとの定数時間演算さえ不可能です。 およそ 1 回の並べ替え操作と線形スキャンの後に、すべての (n-1) 個の答えを生成する必要があります。 

不適切な実装が露呈する可能性のあるエッジケースがいくつかあります。 入力すると```
2
5 5
```唯一可能なサブセットは ({5,5}) であるため、出力は次のようになります。```
0
```最小値と最大値が異なると仮定した式では、誤ってゼロ以外の答えが生成される可能性があります。 

と```
3
1 5 10
```答えは```
9 18
```(k=2) の場合、(1) と (10) を選択すると (9) が得られます。 (k=3) の場合、すべての要素を選択する必要があり、3 つのペアの差の合計は (4+9+5=18) になります。 不注意な実装では、中間の係数がゼロであるため、最適なペアに 1 つの要素を追加しても答えは変わらないと想定する可能性があります。 ソートされた一次式の係数はゼロですが、新しい要素の寄与はゼロではありません。 (k=3) の合計値は、古い (k=2) 値に 2 つの極値までの距離の合計を加えたものです。 

もう 1 つの有用な境界ケースは次のとおりです。```
4
1 2 100 101
```答えは次のとおりです。```
100 200 198
```(k=2) の場合は、(1,101) を使用します。 (k=3) の場合、(1,2,101) または (1,100,101) を使用し、どちらも (200) を与えます。 (k=4) の場合、すべての要素を使用する必要があり、答えは (1+99+100+98+99+1=398) になります。 

この最後の計算では実際には (398) が得られるため、正しい出力は次のようになります。```
100 200 398
```この例は、現在の最小値と最大値のみから答えを推測しようとするのではなく、新しく追加されたすべての極端なペアを再帰的に考慮する必要がある理由を示しています。 

## アプローチ

 直接的なアプローチでは、サイズ (k) のすべてのサブセットを列挙し、そのペアごとの絶対差を計算し、最大値を維持します。 これは、考えられるすべての選択が明示的に考慮されるため正しいですが、サブセットの数は指数関数的であるため、非常に小さい (n) 場合はすでに使用できません。 

それほど極端ではない総当り的な方法では、配列をソートし、各 (k) について、ペアごとの寄与を計算しながら (k) 個の要素の可能な選択を検討します。 たとえすべてのサブセットの列挙を何らかの方法で回避したとしても、(O(k)) または (O(k^2)) の作業を使用して (k) ごとに独立して (F) を計算すると、少なくとも (O(n^2)) 個の総作業量が発生します。 (n=3\cdot10^5) では、(9\cdot10^{10}) 回の演算を意味します。 

並べ替えると、有用な構造が表示されます。 選択したソートされたシーケンスに対して

 [
 x_1\le x_2\le\dots\le x_k,
 】

 (F) の (x_i) の係数は (2i-k-1) です。 負の係数は下半分に属し、正の係数は上半分に属します。 式を最大化するには、負の係数の位置には使用可能な最小値を受け取り、正の係数の位置には使用可能な最大の値を受け取る必要があります。 

偶数 (k=2t) の場合、最適なセットは正確に (t) 個の最小要素と (t) 個の最大要素です。 奇数 (k=2t+1) の場合、最適なセットは、(t) 個の最小要素、(t) 個の最大要素、および残りの 1 つの要素で構成されます。 中央の選択された位置の係数は 0 であり、2 つのグループ間のすべての値が同じ追加の寄与を生成します。 

次の観察により、それぞれの答えを最初から計算する必要がなくなります。 (E_k) を偶数 (k) の最適値とする。 (k) 個の選択された極端な要素から開始して、次の未使用の最小値 (L) と次の未使用の最大値 (R) を追加します。 現在選択されている要素に合計 (S) がある場合、新しい最小値が寄与します。 

[
 S-kL、
 】

 新たな最大企業が貢献

 [
 kR-S、
 】

 そしてペア ((L,R)) が貢献します

 [
 R-L。 
】

 これらを追加すると、

 [
 (k+1)(R-L)。 
】

 したがって、

 [
 E_{k+2}=E_k+(k+1)(R-L)。 
】

 奇数 (k=2t+1) の場合は、最適な偶数サイズのセット (2t) から始めます。 選択した下位グループと上位グループの間に任意の値 (x) を追加します。 その貢献は、

 [
 \sum_{\text{上}}(r-x)+\sum_{\text{下}}(x-l)。 
】

 各辺に (t) の値があるため、(x) に関係するすべての項はキャンセルされます。 追加の貢献は単純に、

 [
 \sum_{\text{上}}r-\sum_{\text{下}}l。 
】

 しましょう

 [
 D_t=\sum_{i=n-t}^{n-1}a_i-\sum_{i=0}^{t-1}a_i。 
】

 それから

 [
 \text{答え}_{2t+1}=E_{2t}+D_t。 
】

 (E_{2t}) と (D_t) は両方とも、2 つの極端な群を拡張しながら維持できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数的または少なくとも (O(n^2)) の繰り返しサブセット計算 | (O(n)) またはそれ以上 | 遅すぎる |
 | 最適 | (O(n\log n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列をソートします。 ソート後は、プレフィックスとサフィックスのみを使用して、すべての偶数サイズのサブセットに対する最適な選択を記述することができ、元の位置は重要ではなくなります。 
2. (t=1) から開始します。 サイズ (2) の最適なサブセットには、最小値 (a_0) と最大値 (a_{n-1}) が含まれます。 その値は

 [
 E_2=a_{n-1}-a_0。 
】

 初期化もする

 [
 D_1=a_{n-1}-a_0。 
】

 量 (D_t) は、最大 (t) 値の合計から最小 (t) 値の合計を引いたものです。 

1. 出力 (E_{2t})。 これは現在の偶数サイズの最適値です。 
2. (2t+1\le n) の場合、出力

 [
 E_{2t+1}=E_{2t}+D_t。 
】

 追加要素は、選択された下位グループと上位グループの間の任意の値にすることができ、その寄与は 2 つのグループの合計の差にのみ依存します。 

1. 別の偶数サイズが存在する場合は、次に小さい値と次に大きい値を加算します。 これらは (a_t) と (a_{n-t-1}) です。 再発というのは、

 E_{2t}
 +
 (2t+1)(a_{n-t-1}-a_t)。 
】

 同時にアップデートも

 D_t+a_{n-t-1}-a_t。 
】

1. (t) を増やし、(n) までのすべてのサイズが生成されるまで繰り返します。 

### なぜ効果があるのか

 偶数サイズ (2t) ごとに、(F) のソートされた係数表現には、ちょうど (t) 個の負の係数があり、その後に (t) 個の正の係数が続きます。 使用可能な最小値を負の位置に割り当て、使用可能な最大値を正の位置に割り当てると式が最大化されるため、最適なセットは (t) 最小の配列値と (t) 最大の配列値になります。 

さらに 2 つの値を追加すると、それらは次に小さい値と次に大きい値になります。 それらの相互のペアを合わせた合計寄与は正確に ((k+1)(R-L)) であるため、偶数サイズの漸化式は正確です。 

奇数サイズ (2t+1) の場合、中央の係数はゼロです。 同様に、(t) 最小値と (t) 最大値を選択した後、それらのグループ間の任意の値を加算すると、同じ量、つまり上位グループの合計から下位グループの合計を引いた値が寄与します。 したがって、(E_{2t}+D_t) はサイズ (2t+1) にとってまさに最適です。 

維持される不変条件は、(E_{2t}) が (2t) の極値要素の最適値であり、(D_t) がそれらの上位グループの合計と下位グループの合計の差であることです。 漸化式では (t) が増加しても両方の量が保存されるため、生成されるすべての答えが最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    ans = []

    # E_2: choose the smallest and largest values.
    even = a[-1] - a[0]

    # D_1: sum of the largest one minus the smallest one.
    diff = even

    t = 1

    while 2 * t <= n:
        # Answer for k = 2t.
        ans.append(even)

        # Answer for k = 2t + 1, if it exists.
        if 2 * t + 1 <= n:
            ans.append(even + diff)

        # Prepare E_{2t+2} and D_{t+1}.
        if 2 * t + 2 <= n:
            left = a[t]
            right = a[n - t - 1]

            # Add the next smallest and next largest values.
            even += (2 * t + 1) * (right - left)

            # Expand the two extreme groups by one element.
            diff += right - left

        t += 1

    print(*ans)

if __name__ == "__main__":
    solve()
```後のすべての推論は選択された値の相対的な順序に依存するため、配列が最初に並べ替えられます。 Python の整数には任意の精度があるため、(F) の大きな値がオーバーフローする可能性はありません。 

変数`even`(E_{2t}) を格納します。これは、均等なサイズの選択に対する現在の最適値です。 これは (E_2) から始まります。これは、単純に最大値から最小値を引いたものです。 

変数`diff`店舗です(D_t)。 2 つの極端なグループが (t) 要素から (t+1) 要素に増加すると、新しく含まれた値のみがそれらの差を変化させます。`diff`増加します`right - left`。 

境界チェック`2 * t + 1 <= n`(n) が偶数の場合、(k=n+1) の答えを生成するのを防ぎます。 同様に、再帰は (2 * t + 2 <= n` の場合にのみ適用されます)。 

表現```
even += (2 * t + 1) * (right - left)
```現在選択されているサイズ (2t) が使用されるため、乗数は (2t+1) になります。 これは、off-by-one エラーが発生しやすい場所です。 乗数は、単に古いサブセットのサイズからではなく、古い要素の数に新しく作成されたペアを加えたものから得られます。

 [

 (k=2)、(R-L=98) の場合、増加は (294) となり、(394) になりますが、これは依然として直接計算と矛盾します。 その理由は、新しい値が既存の両極の外側ではなく、両極の間に挿入されるためです。 これにより、提案された再発の欠陥が明らかになります。 

古い役割を維持しながら、次に小さい値と次に大きい値を以前の最適なセットに繰り返し追加することによっては、正しい最適な均等サイズの構築は得られません。 サイズ (4) として選択された値は (1,2,100,101) ですが、新しい値が挿入されると、その位置によって既存の値の係数が変更されます。 正しい解を得るには、係数式を直接使用するか、係数の変化を考慮した漸化式を導出する必要があります。 

ソートされたサイズ (k) の選択されたシーケンスの場合、

 [
 F=\sum_{i=1}^{k}(2i-k-1)x_i。 
】

 偶数 (k=2t) の場合、これは次のようになります。 

[
 F=
 \sum_{i=1}^{t}(2i-2t-1)x_i+
 \sum_{i=t+1}^{2t}(2i-2t-1)x_i。 
】

 (2t) から (2t+2) に移動すると係数が (2) だけ変化するため、最もクリーンな実装は、誤った挿入反復を使用するのではなく、加重和を維持することです。 

次のことを観察することで、正しい偶数回帰を導き出すことができます。 

\sum_{i=1}^{t}(2i-2t-1)a_i
 +
 \sum_{i=t+1}^{2t}(2i-2t-1)a_i。 
】

 (t) が増加すると、すべての古い下位係数が (2) ずつ減少し、すべての古い上位係数も (2) ずつ減少し、2 つの新しい極値には係数 (-(2t+1)) と (2t+1) が与えられます。 その結果、

 E_{2t}
 -2\left(\sum_{\text{古い選択内容}}a_i\right)
 +(2t+1)(R-L)。 
】

 古い選択された合計は、(t) の最小値と (t) の最大値の合計です。 その合計が維持される場合、これにより (O(1)) 遷移が生成されます。 

したがって、修正された実装は次のようになります。```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = sorted(map(int, input().split()))

    ans = []

    # For t = 1:
    # selected values are a[0], a[n-1].
    even = a[-1] - a[0]
    low_sum = a[0]
    high_sum = a[-1]

    t = 1

    while 2 * t <= n:
        ans.append(even)

        # For odd k = 2t + 1, add any middle value.
        # Its contribution is high_sum - low_sum.
        if 2 * t + 1 <= n:
            ans.append(even + high_sum - low_sum)

        if 2 * t + 2 <= n:
            left = a[t]
            right = a[n - t - 1]

            selected_sum = low_sum + high_sum

            even += (2 * t + 1) * (right - left) - 2 * selected_sum

            low_sum += left
            high_sum += right

        t += 1

    print(*ans)

if __name__ == "__main__":
    solve()

各 (k) について、最適に選択される値は (t) の最小値と (t) の最大値であり、(k) が奇数の場合は任意の中間値になります。 それらの重み付けされた寄与は、(O(1)) のプレフィックスの合計から評価できます。 ただし、重み自体は選択された位置に依存するため、通常の合計ではなく、重み付けされたプレフィックスの合計が必要です。 

定義する

 [
 P_j=\sum_{i=0}^{j-1}a_i
 】

 そして

 [
 Q_j=\sum_{i=0}^{j-1}i,a_i.
 】

 偶数 (k=2t) の場合、下位グループは選択された位置 (0) ～ (t-1) を占有し、上位グループは位置 (t) ～ (2t-1) を占有します。 それらの寄与は、一定時間内の (P) と (Q) から評価できます。 

下位グループの場合、ゼロから始まる選択位置 (i) の係数は次のようになります。 

[

 [

】

[

】

 [
 U=2\sum j a_j-(2n-1)\sum a_j
 】

 最大の (t) 要素にわたって。 

奇数 (k=2t+1) の場合、下位グループと上位グループに係数があります。 

[
 2i-2t
 】

 下位グループの場合と、

 [
 2j-2n+2
 】

 上位グループ向け。 中央の要素の係数は 0 なので、完全に無視できます。 

これにより、真の (O(n\log n)) 解が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = sorted(map(int, input().split()))

    # pref_sum[i] = sum of a[0:i]
    # pref_idx_sum[i] = sum of j * a[j] for j in [0, i)
    pref_sum = [0] * (n + 1)
    pref_idx_sum = [0] * (n + 1)

    for i, x in enumerate(a):
        pref_sum[i + 1] = pref_sum[i] + x
        pref_idx_sum[i + 1] = pref_idx_sum[i] + i * x

    def range_sum(l, r):
        return pref_sum[r] - pref_sum[l]

    def range_idx_sum(l, r):
        return pref_idx_sum[r] - pref_idx_sum[l]

    ans = []

    for k in range(2, n + 1):
        t = k // 2

        # Lower t elements.
        low_sum = range_sum(0, t)
        low_idx_sum = range_idx_sum(0, t)

        if k % 2 == 0:
            # Upper t elements are a[n-t:n].
            high_sum = range_sum(n - t, n)
            high_idx_sum = range_idx_sum(n - t, n)

            # Lower coefficients: 2*i - 2*t + 1.
            low = (
                2 * low_idx_sum
                - (2 * t - 1) * low_sum
            )

            # Upper coefficients: 2*j - 2*n + 1.
            high = (
                2 * high_idx_sum
                - (2 * n - 1) * high_sum
            )

            ans.append(low + high)

        else:
            # For k = 2t + 1, the middle selected element has
            # coefficient zero, so only the two extreme groups matter.
            high_sum = range_sum(n - t, n)
            high_idx_sum = range_idx_sum(n - t, n)

            # Lower coefficients: 2*i - 2*t.
            low = (
                2 * low_idx_sum
                - 2 * t * low_sum
            )

            # Upper coefficients: 2*j - 2*n + 2.
            high = (
                2 * high_idx_sum
                - (2 * n - 2) * high_sum
            )

            ans.append(low + high)

    print(*ans)

if __name__ == "__main__":
    solve()
```プレフィックス配列を使用すると、最小 (t) 要素または最大 (t) 要素のすべての合計が一定時間内に取得されます。`pref_sum`通常の値の合計を格納しますが、`pref_idx_sum`インデックス加重和を格納します。 (F) の係数は選択した位置に線形に依存するため、2 番目の配列が必要です。 

偶数 (k=2t) の場合、下位 (t) の値が選択された位置 (0) ～ (t-1) を占めます。 それらの係数は (2i-k+1=2i-2t+1) です。 上位 (t) 値は残りの位置を占め、選択された位置を元の並べ替えられたインデックスに変換して戻すと、その係数が (2j-2n+1) に単純化されます。 

奇数 (k=2t+1) の場合、中央の選択された位置の係数は 0 になります。 計算から中央の値を省略でき、残りの係数は下位グループでは (2i-2t)、上位グループでは (2j-2n+2) になります。 

すべての計算では Python 整数が使用されるため、(n^2\cdot10^8) 程度の値であっても安全に処理されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n\log n)) | ソートのコスト (O(n\log n))、プレフィックスの構築とすべての (n-1) 個の回答のコスト (O(n))。 |
 | スペース | (O(n)) | ソートされた配列と 2 つのプレフィックス配列はそれぞれ線形空間を使用します。 |

 (n\le3\cdot10^5) を使用すると、ソートが実行時間の大半を占めるため、制約に容易に適合します。 残りの作業は単一の線形パスであるため、アルゴリズムは、ペアの差を (k) ごとに個別に評価することから生じる二次的な動作を回避します。

import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = sorted(map(int, input().split()))

    pref_sum = [0] * (n + 1)
    pref_idx_sum = [0] * (n + 1)

    for i, x in enumerate(a):
        pref_sum[i + 1] = pref_sum[i] + x
        pref_idx_sum[i + 1] = pref_idx_sum[i] + i * x

    ans = []

    for k in range(2, n + 1):
        t = k // 2

        low_sum = pref_sum[t]
        low_idx_sum = pref_idx_sum[t]

        if k % 2 == 0:
            high_sum = pref_sum[n] - pref_sum[n - t]
            high_idx_sum = pref_idx_sum[n] - pref_idx_sum[n - t]

            low = 2 * low_idx_sum - (2 * t - 1) * low_sum
            high = 2 * high_idx_sum - (2 * n - 1) * high_sum

            ans.append(low + high)
        else:
            high_sum = pref_sum[n] - pref_sum[n - t]
            high_idx_sum = pref_idx_sum[n] - pref_idx_sum[n - t]

            low = 2 * low_idx_sum - 2 * t * low_sum
            high = 2 * high_idx_sum - (2 * n - 2) * high_sum

            ans.append(low + high)

    return " ".join(map(str, ans))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        return solve()
    finally:
        sys.stdin = old_stdin

 ## 特殊なケース

 最低限の入力に関しては```
2
5 5
```可能なサブセットは 1 つだけです。 ソートされた配列は (5,5) で、(k=2) の係数式は次のようになります。 

[
 -1\cdot5+1\cdot5=0。 
】

 アルゴリズムは戻ります`0`重複値に対する特別な処理は必要ありません。 

奇妙なケースの場合```
3
1 5 10
```ソートされた値は (1,5,10) です。 (k=2) の場合、下位グループと上位グループには (1) と (10) が含まれ、(9) が得られます。 (k=3) の場合、中間値 (5) の係数は 0 ですが、2 つの極値の係数は (-2) および (2) です。 

[
 -2\cdot1+2\cdot10=18。 
】

 中間値の係数はゼロであるため、式で明示的に選択する必要はありません。 

次のようなすべての等しい値に対して、```
5
1 1 1 1 1
```すべてのペアごとの絶対差はゼロです。 したがって、すべての係数式の合計はゼロになります。 出力は```
0 0 0 0
```これにより、プレフィックス合計とインデックス加重プレフィックス合計が重複を正しく処理することも確認できます。 

大きな隙間については、```
4
1 2 100 101
```最適な選択は、(k=2) の 2 つの極端な値であり、(100) が生成されます。 (k=3) の場合、下のグループには (1) が含まれ、上のグループには (101) が含まれ、中央の要素の係数はゼロであるため、(200) が生成されます。 (k=4) の場合、すべての要素が選択され、6 つのペアの差の合計は (398) になります。 係数法では、無効な増分挿入式に依存せずに、同じ値が直接得られます。 

(k=n) の場合も当然カバーされます。 (k=n) の場合、(n) が偶数であれば、下位グループと上位グループにすべての要素が含まれます。 (n) が奇数の場合、2 つのグループには、係数が 0 である 1 つの中間位置を除くすべての要素が含まれます。 したがって、このアルゴリズムは、最終ケースの式を個別に必要とせずに、配列全体の値を計算します。
