 ## 解決策
 ## 問題の理解

 戦略は、すべての非境界セルに右矢印または下矢印を割り当てます。 一番下の行全体が右を向くように固定され、右端の列全体が下を向くように固定されます。 のみ`(n-1) × (m-1)`内部セルは実際の選択です。 

これらの矢印は、グリッド上に有向非巡回グラフを形成します。 右下のセルを除くすべてのセルには出力エッジが 1 つだけありますが、右下のセルには出力エッジがありません。 セルからゲームを開始するということは、その固有の出力パスを右下のセルまでたどることを意味します。 

この質問は、すべてのセルを訪問するために必要な開始セルの最小数が正確に次のとおりである戦略の数を尋ねます。`x`。 公式の制約は次のとおりです`1 <= n,m <= 100`そして`1 <= x <= nm`、1 秒の時間制限と 256 MB のメモリ制限があります。 

最初の有用な観察は、何らかの有向パスがセルに入った場合にのみ、別の開始セルからセルを訪問できるということです。 入力エッジのないセルは他のどこからでも到達できないため、必然的に開始セルである必要があります。 

逆に、セルに入力エッジがある場合、入力エッジを繰り返したどると、最終的には入力エッジのないセルに到達します。これは、すべてのエッジが右または下に移動し、グラフにサイクルがないためです。 そのソースから始まり、元のセルに到達します。 したがって、開始の最小数は、まさに次数 0 のセルの数になります。 

これらのソースをカウントするさらにクリーンな方法があります。 させて`S`はソースの数であり、`M`次数 2 のセルの数。 他のすべてのセルは次数 1 を持ちます。 がある`nm-1`右下のセルを除くすべてのセルには 1 つの出力エッジがあるため、有向エッジです。 したがって、`nm - 1 = 2M + (nm - S - M)`、

 これを単純化すると`S = M + 1`。 

したがって、2 つの入力エッジを持つセルの数に従って戦略をカウントするだけで済みます。 

内部セル`(i,j)`上のセルが下を指し、その左のセルが右を指すとき、2 つの入力エッジがあります。 右上端から左下端に向かって順序付けられた、対角線上のセルを考えてみましょう。 2 つの入力エッジを持つセルは、隣接するセルに正確に対応します。`D,R`この順序でペアにします。 

これにより、問題の中心的な分解が得られます。 すべての矢印は正確に 1 つの対角線に属し、すべてのマージは 1 つの対角線上の 2 つの隣接する矢印によって決定されます。 したがって、異なる反対角線は完全に独立しています。 

誤って対処しやすい特殊なケースがいくつかあります。 のために`1 × m`または`n × 1`、すべての矢は強制されるため、可能な戦略は 1 つだけです。答えは次のとおりです。`1`のために`x=1`そして`0`さもないと。 のために`2 × 2`、戦略は 2 つありますが、どちらも必要な開始セルが 2 つあるため、次の答えが得られます。`2 2 2`は`2`。 永続的なマージを覚えておらず、内部マージのみをカウントする不用意なソリューション`+1`間違った値を返します。 サンプルについて`3 3 9`、可能なマージの最大数は 3 つだけなので、9 回の開始は不可能であり、答えは次のようになります。`0`。 公式サンプルでもこの​​結果が確認されています。 

## アプローチ

 ブルートフォースの解決策は簡単です。 がある`(n-1)(m-1)`矢印セルは自由に選択できるため、`2^((n-1)(m-1))`戦略。 あらゆる戦略について、すべてを検査できます`nm`セルを計算し、その入次数を計算し、ソースを数えます。 上記のソースの特性評価が正確な最小開始数を示しているため、これは正しいです。 

問題は戦略の数です。 で`n=m=100`、 がある`9801`フリーセル、与える`2^9801`戦略、大まかに言うと`10^2949`。 実際にパスをシミュレートするコストを無視したとしても、すべての戦略についてすべてのセルをチェックするには、おおよその時間がかかります。`10000 × 2^9801`セルの操作。 徹底的な列挙はほとんど不可能です。 

反対角線に関する観察により、問題は完全に変わります。 グリッド全体を列挙する代わりに、グリッドの数を数えます。`D,R`遷移は、すべての対角線の内部で独立して発生します。 

反対角関数に次のものが含まれているとします。`L`矢印のセル。 どちらのエンドポイントも強制されない場合は、長さのバイナリ文字列の数が必要です。`L`正確に含む`k`の発生`D,R`。 その数字は`C(L+1, 2k+1)`。 

エンドポイントが 1 つだけ固定されている場合は、次のいずれかを実行します。`D`最初の位置または`R`最後の位置の数字は次のようになります`C(L, 2k)`。 

両方のエンドポイントが固定されている場合、最初のエンドポイントは`D`そして最後は`R`、その数は`C(L-1, 2k-1)`。 

これらの公式は、文字列を交互の実行として見ることから得られます。 毎`D,R`移行は完了したものに貢献します`D`実行に続いて`R`走る。 これらの実行の境界を選択すると、対応する二項係数が得られます。 

したがって、すべての反対角は小さな生成多項式を与えます。 の係数`t^k`対角を正確に構成する方法の数です`k`合併します。 これらすべての多項式を乗算すると、次の係数を持つグローバル多項式が得られます。`t^(x-1)`は必須の答えです。 

すべての対角線には最大でも長さがあるため、`100`、その多項式は最大でも次数を持ちます`50`。 これらの小さな多項式に 1 次元 DP を乗算し、すべての多項式を次数で切り捨てることができます。`x-1`。 乗算を行う前に、可能なマージの最大数も計算します。 もし`x-1`その値を超えると、答えはすぐにゼロになります。

 | 反対角多項式 DP |`O(K * sum(deg_i))`、 どこ`K=x-1`|`O(K)`| 承認済み |

 ここ`deg_i`対角線上で可能なマージの最大数です。`i`。 与えられた境界の下では、すべての度は最大でも`50`、せいぜいあります`199`実際の畳み込み作業は、制約に対して十分小さいままです。 

## アルゴリズムのチュートリアル

 1. しましょう`K = x-1`。 私たちが使用するのは`K`それよりも`x`必要な開始セルの数は常にマージ セルの数より 1 つ多いためです。 
2. 矢印セルのすべての対角を列挙します。 対角線は定数値によって識別されます`s = row + column`、からの範囲`2`を通して`n+m-1`。 
3. 各対角線の長さを決定します`L`。 選択した順序の最初のセルが一番上のセルであり、常に右端のエンドポイントでもあります。`s > m`。 最後のセルは最下位のセルであり、常に最下行にあります。`s > n`。 
4. その対角線の生成多項式を構築します。 エンドポイントが固定されていない場合、その係数は`k`マージは`C(L+1, 2k+1)`。 端点が 1 つだけ固定されている場合、係数は次のようになります。`C(L, 2k)`。 両方のエンドポイントが固定されている場合、係数は次のようになります。`C(L-1, 2k-1)`。 
5. 各対角多項式の次数を加算して、可能なマージの最大数を取得します。 もし`K`この最大値より大きい場合は、戻ります`0`どの戦略にも十分なマージ セルを含めることができないため、すぐに実行されます。 
6. 次のようにグローバル多項式を開始します。`dp[0] = 1`。 これは、合計マージがゼロの以前のすべての対角線を選択することを表します。 
7. 全体多項式に各対角多項式を乗算します。 次数の新しい係数`i+j`受け取る`dp[i] * poly[j]`、最初の対角コレクションが寄与するため`i`マージし、新しい対角線が寄与します`j`。 
8. すべての乗算を次数で切り捨てる`K`。 次数が高くても、要求された係数に寄与することはなく、実行時間が増加するだけです。 
9. 対角多項式を乗算する前に次数で並べ替えます。 最初に最小の因数を乗算すると、中間多項式ができるだけ長く短くなります。 
10. 戻る`dp[K]`。 以来`K=x-1`、これは、最小開始数が である戦略を正確にカウントします。`x`。 

### なぜ効果があるのか

 有向グリッドには、`nm-1`エッジ。 すべてのセルには次数 0、1、または 2 があり、次数がある場合は`S`ソースと`M`indegree-2 セル、indegree の合計は次のようになります。`S=M+1`。 次数 2 のセルは、上隣のセルが下を指し、左隣のセルが右を向いているときに正確に発生します。`D,R`1 つの対角線上での移行。 

すべての矢印はちょうど 1 つの対角線に属するため、異なる対角線での選択は相互作用しません。 対角線の生成多項式は、可能な数のそれぞれを作成する代入の数を正確に記録します。`D,R`トランジション。 乗算は独立した選択肢を組み合わせるため、次の係数は`t^K`すべての戦略を正確にカウントします`K`合併します。 以来`K=x-1`、その係数はまさに要求された答えです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
MAXC = 205

def build_combinations():
    c = [[0] * MAXC for _ in range(MAXC)]
    c[0][0] = 1
    for i in range(1, MAXC):
        c[i][0] = 1
        c[i][i] = 1
        for j in range(1, i):
            c[i][j] = (c[i - 1][j - 1] + c[i - 1][j]) % MOD
    return c

C = build_combinations()

def solve_case(n, m, x):
    K = x - 1

    factors = []
    max_merges = 0

    # s = row + column for the arrow cells on one anti-diagonal.
    for s in range(2, n + m):
        first_row = max(1, s - m)
        last_row = min(n, s - 1)
        L = last_row - first_row + 1

        # The first cell is on the rightmost column iff s > m.
        first_fixed = s > m

        # The last cell is on the bottom row iff s > n.
        last_fixed = s > n

        if first_fixed and last_fixed:
            deg = L // 2
            poly = [0] * (deg + 1)
            for k in range(1, deg + 1):
                poly[k] = C[L - 1][2 * k - 1]

        elif first_fixed or last_fixed:
            deg = L // 2
            poly = [0] * (deg + 1)
            for k in range(deg + 1):
                poly[k] = C[L][2 * k]

        else:
            deg = L // 2
            poly = [0] * (deg + 1)
            for k in range(deg + 1):
                poly[k] = C[L + 1][2 * k + 1]

        factors.append(poly)
        max_merges += deg

    if K > max_merges:
        return 0

    # Small factors first reduce the amount of convolution work.
    factors.sort(key=len)

    dp = [1]

    for poly in factors:
        deg = len(poly) - 1
        new_len = min(K, len(dp) - 1 + deg) + 1
        ndp = [0] * new_len

        for i, a in enumerate(dp):
            limit = min(deg, K - i)
            for j in range(limit + 1):
                ndp[i + j] += a * poly[j]

        for i in range(new_len):
            ndp[i] %= MOD

        dp = ndp

    return dp[K]

def main():
    n, m, x = map(int, input().split())
    print(solve_case(n, m, x))

if __name__ == "__main__":
    main()
```組み合わせテーブルは約までしか事前計算されません。`200`、対角線は最大でも長さがあるため、`100`、式に必要なのは最大でも`L+1`。 

すべての対角線に対して、`first_fixed`対角線が右端の列に達したときにまさに true になります。 右端の列は下矢印に固定されているため、順序付けの最初の矢印は`D`。 同様に、`last_fixed`対角線が一番下の行に到達したときに真になります。その矢印は に固定されています。`R`。 

3 つの多項式は、ランカウント式から直接実装されます。 両方固定の場合、ゼロ遷移の係数は正確にゼロになります。`D`そしてで終わる`R`少なくとも 1 つを含める必要があります`D,R`遷移。 

グローバルDPは以下から始まります`[1]`、空の製品を表します。 畳み込み中に、`i+j`マージの合計数です。 の`K-i`境界により、要求された次数より大きな係数を構築できなくなります。 

Python の整数はオーバーフローしないため、内部たたみ込みでは係数を取得する前にいくつかの積を累積できます。 結果として得られる各係数は、内部ループ全体の後で削減されるため、乗算ごとにコストのかかるモジュロ演算が回避されます。 

右下のセルは、列挙が次で停止するため、どの対角セルにも含まれません。`n+m-1`。 このセルには出ていく矢印がなく、戦略の自由矢印セルまたは強制矢印セルの一部ではないため、これはまさに私たちが望んでいることです。

 ## 特殊なケース

 のために`1 × 1`、矢印はまったくありません。 唯一のセルは出発点と目的地の両方であるため、1 つの出発地で十分です。 アルゴリズムには正の次数の反対角要素はありません。`K=0`、空の積には係数があります`1`。 したがって`1 1 1`生成する`1`。 

次のような単一行の場合`1 4 1`、宛先以外のすべてのセルは一番下の行にあり、強制的に右を指すようになります。 グリッドは 1 つの有向パスであるため、開始は 1 つだけ必要です。 すべての反対角因子の次数は 0 であり、グローバル多項式は残ります。`[1]`、ゼロ次の係数を与えると次のようになります。`1`。 などのどんなご要望でも`1 4 2`もっている`K=1`可能な最大マージ数を超えているため、すぐに戻ります`0`。 

のために`2 2 2`、左上のセルに空き矢印が 1 つあるため、2 つの戦略があります。 その選択に関係なく、右下のセルに入る 2 つの強制矢印は次のとおりです。`D`そして`R`、マージが 1 つになります。 したがって、あらゆる戦略には、`1+1=2`required が始まり、答えは`2`。 対角因子は次のとおりです。`2`自由な 1 セルの対角線については、`t`強制されたもののために`D,R`斜めに製品を与える`2t`。 

のために`3 3 9`、要求された 8 つのマージは不可能です。 5 つの対角線の矢印には最大のマージ カウントがあります。`0,1,1,1,0`、合計最大値は`3`。 したがって、可能な最大の開始数は次のようになります。`4`、はるか下`9`。 アルゴリズムが検出するのは、`K=8 > 3`DP を実行して戻る前に`0`、公式サンプルと一致します。 

のために`2 3 3`、必要なマージの数は`2`。 最初の自由対角は多項式に寄与します`2`、2番目は貢献します`3+t`、最後の強制対角線が寄与します`t`。 彼らの製品は、`6t+2t^2`、したがって、の係数は`t^2`は`2`。 これらは、まさに公式サンプルでカウントされている 2 つの戦略です。
