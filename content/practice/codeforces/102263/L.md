 ## 解決策
 ## 問題の理解

 無限ボードは周期的です。 すべての (n \times m) ブロックには同じ値が含まれるため、1 つのブロック内の位置のみが問題になります。 ゼロベースのローカル行と列を (x) と (y) とします。 その位置でのバーガーの価値は

 [
 f(x,y)=xm+y+1。 
】

 食事をした後、プレイヤーは (r) 行と (c) 列ずつ移動します。 繰り返されるブロック内の位置のみを考慮するため、状態のシーケンスは次のようになります。 

[
 (x+kr)\bmod n,\qquad (y+kc)\bmod m。 
】

 プレーヤーは、すでに価値が現れているハンバーガーを食べる直前に停止します。 (1) から (nm) までのすべての値は正確に 1 つのローカル位置で発生するため、行と列の剰余が両方とも等しい場合、2 つの状態は正確に同じ美味しさを持ちます。 したがって、残基のペアが繰り返されるとプロセスは停止します。 

行座標の場合、訪問した個別の位置の数は次のとおりです。 

[
 p_n=\frac{n}{\gcd(n,r)}。 
】

 列座標の場合は、

 [
 p_m=\frac{m}{\gcd(m,c)}。 
】

 完全なペアはその後繰り返されます

 [
 L=\オペレーター名{lcm}(p_n,p_m)
 】

 動きます。 プレイヤーはちょうど (L) 個のハンバーガーを食べます。 

シミュレーションするには制約が大きすぎます。 どちらの次元も (2\cdot10^9) に達する可能性があるため、1 つの期間には最大 (4\cdot10^{18}) 個の位置が存在できます。 公式の問題制限はわずか 0.5 秒であるため、(O(nm)) メソッドですら不可能であり、ましてやすべての開始セルから完全な軌道を反復することは不可能です。 この解決策では、軌道を数回の gcd、lcm、および算術合計の計算に減らす必要があります。 

簡単な罠がいくつかあります。 のために`1 1 1 1`、唯一のハンバーガーが値 (1) を持ち、最初のバーガーが食べられ、次の状態も同じ値を持つため、答えは次のようになります。`1`。 プレイヤーが常に少なくとも 2 つのバーガーを食べると仮定した解決策では、1 つずれることになります。 

のために`1 4 1 2`、任意の開始列から訪問される列は同じパリティを持ちます。 最適な軌道は、値 (2) および (4) の列を訪問し、(2+4=6) になります。 (2) のステップが最終的に 4 つの列すべてにアクセスすると仮定する不用意な解決策では、合計 (1+2+3+4=10) が誤って使用されてしまいます。 正しいサンプル出力は次のとおりです。`6`。 

のために`4 3 2 1`の場合、行ステップには (\gcd(4,2)=2) があるため、どの行サイクルにも 2 行のみが属します。 行ステップを (n) と互いに素であるかのように扱うソリューションには、4 つの行すべての値が含まれます。 正しい答えは、`48`。 

最後に、(r=n) または (c=m) の場合、対応する座標はまったく変化しません。 たとえば、`3 2 3 2`、移動するたびに同じセルに到達するため、最適な開始セルは単に右下のセルであり、その値は (6) です。 答えは`6`。 

## アプローチ

 直接的なアプローチは、可能なすべての開始位置を選択し、以前に食べられた値が発生するまでジャンプをシミュレートし、最大の合計を維持することです。 1 つの開始位置に対して、これには (L) 回の反復がかかります。 

[
 L=\オペレーター名{lcm}\left(\frac n{\gcd(n,r)},\frac m{\gcd(m,c)}\right)。 
】

 (nm) 個の可能なローカル開始位置があるため、ブルート フォース操作の数は次のようになります。 

[
 O(nmL)。 
】

 最悪の場合、2 つの短縮された周期が互いに素となり、(L) が (nm) に近くなる可能性があります。 両方の次元が (2\cdot10^9) に近い場合、これは ((nm)^2)、およそ (1.6\cdot10^{37}) の軌道ステップに近づく可能性があります。 ブルートフォース手法は文字通りプロセスに従うため正しいですが、期間に依存するため使用できません。 

有益な観察は、行と列の座標が独立して変化するということです。 ステップ (d) のサイズ (q) の 1 つの次元について、次のようにします。 

[
 g=\gcd(q,d),\qquad p=\frac qg。 
】

 残基から開始して、訪問された残基は正確に

 [
 s,\ s+g,\ s+2g,\ldots,s+(p-1)g
 】

 それらをモジュロ (q) で削減した後。 言い換えれば、軌道は 1 つの完全な剰余クラスを法 (g) で訪問します。 同じ剰余モジュロ (g) を持つすべての開始点は、同じ位置のセットを生成します。 

その剰余クラスの合計は次のようになります。 

[
 p s+g\frac{p(p-1)}2.
 】

 (s) の係数は正であるため、最大の合計は (s=g-1) から得られます。 したがって、この次元の最大 1 期間合計は次のようになります。 

[
 S(q,d)=p(g-1)+g\frac{p(p-1)}2.
 】

 行サイクルと列サイクルは異なる周期を持つことができるため、完全な 2 次元軌跡中に行サイクルは (L/p_n) 回繰り返され、列サイクルは (L/p_m) 回繰り返されます。 

バーガーの値は (xm+y+1) であるため、合計貢献度は行部分、列部分、および食べたバーガーごとに 1 つの定数 (1) に分割されます。 この分離により、最適な行サイクルと最適な列サイクルを個別に最大化できます。 対応する開始行と開始列を単純に 1 つの開始セルに組み合わせることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(nmL)) | (O(1)) | 遅すぎる |
 | 最適 | (O(\log(\max(n,m)))) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (g_n=\gcd(n,r)) と (p_n=n/g_n) を計算します。 (p_n r) は (n) の最小の正の倍数であるため、行座標は正確に (p_n) ジャンプした後に開始値に戻ります。 
2. 列についても同様に (g_m=\gcd(m,c)) と (p_m=m/g_m) を計算します。 完全なローカル セルがその後に繰り返されます。 

[
 L=\オペレーター名{lcm}(p_n,p_m)。 
】

 これは、次のハンバーガーが以前に確認された値になるまでに食べられるハンバーガーの数です。 

1. 行の次元については、次のように計算します。 

[
 S_n=p_n(g_n-1)+g_n\frac{p_n(p_n-1)}2.
 】

 これは、1 行サイクル中の 0 から始まる行インデックスの最大合計です。 最良の開始行は剰余クラス (g_n-1\pmod {g_n}) に属します。 

1. 列の寸法については、次のように計算します。 

[
 S_m=p_m(g_m-1)+g_m\frac{p_m(p_m-1)}2.
 】

 これは、1 つの列サイクル中の 0 から始まる列インデックスの対応する最大合計です。 

1. 長さ (p_n) の行サイクルが、完全な軌跡中に (L/p_n) 回発生します。 したがって、行インデックスの合計は次のようになります。 

[
 S_n\frac{L}{p_n}。 
】

 同様に、列インデックスの合計は次のようになります。 

[
 S_m\frac{L}{p_m}。 
】

 1. それらの座標の合計をハンバーガーの美味しさに変換します。 すべての行インデックスは係数 (m) に寄与し、すべての列インデックスは直接寄与し、すべての食べられたハンバーガーは (1) に寄与します。 答えは

 [
 mS_n\frac{L}{p_n}
 +
 S_m\frac{L}{p_m}
 +
 L.
 】

 この式をモジュロ (10^9+7) とします。

機能する理由: すべての軌道は、有限トーラス (\mathbb Z_n\times\mathbb Z_m) 上の平行移動 ((x,y)\mapsto(x+r,y+c)) の軌道です。 その長さは (L) なので、ちょうど 1 つの完全な軌道が食べられます。 各座標では、軌道は対応する gcd を法とする 1 つの剰余クラスで構成され、そのようなクラスの最大合計は、その最大の剰余を選択することによって取得されます。 バーガー値は独立した行項、独立した列項、および定数の合計であるため、2 つの座標の合計を独立して最大化すると、完全な軌跡の合計も最大化されます。 したがって、数式は可能な限り最良の開始セルを評価します。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

MOD = 10**9 + 7

def cycle_info(q, d):
    g = gcd(q, d)
    p = q // g

    # Maximum sum of residues in one cycle.
    # The best residue class starts at g - 1:
    # (g - 1), (2g - 1), ..., (pg - 1)
    s = p * (g - 1) + g * p * (p - 1) // 2
    return g, p, s

def solve():
    n, m, r, c = map(int, input().split())

    _, pn, row_sum = cycle_info(n, r)
    _, pm, col_sum = cycle_info(m, c)

    # lcm(pn, pm)
    L = pn // gcd(pn, pm) * pm

    row_repetitions = L // pn
    col_repetitions = L // pm

    answer = 0
    answer += (m % MOD) * (row_sum % MOD) % MOD
    answer %= MOD
    answer = answer * (row_repetitions % MOD) % MOD

    answer += (col_sum % MOD) * (col_repetitions % MOD) % MOD
    answer += L % MOD

    print(answer % MOD)

if __name__ == "__main__":
    solve()
```の`cycle_info`関数は 1 次元の数学的リダクションを実装します。`g`どの剰余クラスがジャンプによって保存されるかを識別します。`p`は、そのような 1 つのクラス内のポジションの数です。 可能な最大の合計が得られるため、等差数列は (g-1) から始まります。 

完全な周期は、行と列の周期の lcm です。 表現`pn // gcd(pn, pm) * pm`軌道を構築せずに計算します。 

行の寄与には、行サイクルの合計と、結合期間内でそのサイクルが発生する回数の両方が必要です。 要因`m`ゼロから始まる行インデックスをバーガーの値への寄与に変換します。 列の寄与には追加の次元係数は必要ありません。 

Python の整数には任意の精度があるため、完全な周期が (4\cdot10^{18}) 程度であっても中間積は安全です。 コードは引き続き積をモジュロ (10^9+7) で削減するため、演算がコンパクトに保たれ、必要な出力が直接反映されます。 

ゼロベースの座標の使用は意図的です。 行 (x) と列 (y) を使用すると、バーガーの値は正確に (mx+y+1) になります。 1 ベースの座標を使用すると、すべての等差数列で追加の調整が必要となり、off-by-one エラーが発生しやすくなります。 

## 実用的な例

 サンプル 1 の入力は次のとおりです。`3 3 1 1`。 両方の次元に gcd (1) があるため、すべての座標が完全に訪問されます。 

| 寸法 | (g) | ピリオド (p) | 最良のサイクル合計 | 繰り返し |
 | --- | --- | --- | --- | --- |
 | 行 | 1 | 3 | 3 | 1 |
 | コラム | 1 | 3 | 3 | 1 |

 完全な周期は (L=3) です。 行の寄与は (3\cdot3=9)、列の寄与は (3)、定数の寄与は (3) です。 合計は (9+3+3=15) となり、サンプルと一致します。 

サンプル 2 の入力は次のとおりです。`1 4 1 2`。 行次元には位置が 1 つだけあります。 列の場合、(\gcd(4,2)=2) なので、各軌跡は 2 つのパリティ クラスのいずれかを訪問します。 

| 寸法 | (g) | ピリオド (p) | 最良のサイクル合計 | 繰り返し |
 | --- | --- | --- | --- | --- |
 | 行 | 1 | 1 | 0 | 2 |
 | コラム | 2 | 2 | 4 | 1 |

 完全な周期は (L=2) です。 最良の列クラスには、バーガー値 (2) および (4) に対応する、ゼロから始まる列 (1) および (3) が含まれます。 答えは (0+4+2=6) です。 これは、gcd が重要である理由を示しています。ジャンプはすべての列を訪問するわけではありません。 

サンプル 3 の入力は次のとおりです。`2000000000 1 1 1`。 列が 1 つしかないため、列の寄与はゼロです。 行期間は (2\cdot10^9) で、最良の行サイクルにはすべての行が含まれます。 答えは

 [
 \frac{2000000000\cdot1999999999}{2}+2000000000。 
】

 モジュロ (10^9+7)、これは`91`サンプルのように。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(\log(\max(n,m)))) | 2 つの gcd 計算と定数時間演算 |
 | スペース | (O(1)) | | 固定数の整変数のみが保存されます。 

次元は (2\cdot10^9) にすることができますが、アルゴリズムは行、列、セル、または軌跡の位置を反復することはありません。 Euclid のアルゴリズムは対数時間で終了するため、ソリューションは 0.5 秒の制限に簡単に適合し、定数メモリを使用します。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
from math import gcd

MOD = 10**9 + 7

def solve_io(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        n, m, r, c = map(int, sys.stdin.readline().split())

        def cycle_sum(q, d):
            g = gcd(q, d)
            p = q // g
            s = p * (g - 1) + g * p * (p - 1) // 2
            return p, s

        pn, row_sum = cycle_sum(n, r)
        pm, col_sum = cycle_sum(m, c)

        L = pn // gcd(pn, pm) * pm

        ans = (
            (m % MOD) * (row_sum % MOD) % MOD
            * (L // pn)
            + (col_sum % MOD) * (L // pm)
            + L
        ) % MOD

        return str(ans)
    finally:
        sys.stdin = old_stdin
        output = sys.stdout.getvalue()
        sys.stdout = old_stdout

# Provided samples
assert solve_io("3 3 1 1\n") == "15", "sample 1"
assert solve_io("1 4 1 2\n") == "6", "sample 2"
assert solve_io("2000000000 1 1 1\n") == "91", "sample 3"

# Minimum size, only one burger and one-step repetition
assert solve_io("1 1 1 1\n") == "1", "minimum-size case"

# All burgers in the trajectory have the same local value
assert solve_io("1 2 1 2\n") == "2", "all-equal trajectory"

# Boundary case r = n and c = m, so the same cell is reached immediately
assert solve_io("3 2 3 2\n") == "6", "zero movement modulo dimensions"

# Partial gcd cycles in both dimensions
assert solve_io("4 3 2 1\n") == "48", "non-coprime row step"

# Maximum-size dimensions
assert solve_io("2000000000 2000000000 1 1\n") == "999998628", "maximum-size case"

 ## 特殊なケース

 のために`1 1 1 1`、 (g_n=g_m=1)、(p_n=p_m=1)、(L=1) となります。 行と列の合計は、ゼロから始まる座標が常にゼロであるため、両方ともゼロになります。 式は (0+0+1=1) を与えるので、ちょうど 1 つのハンバーガーが食べられることになります。 

のために`1 4 1 2`の場合、列 gcd は (2) となり、(p_m=2) になります。 最良の剰余クラスは (1\pmod2) で、ゼロから始まる列 (1) と (3) が含まれます。 それらの合計は (4) で、軌道の長さは (2) になります。 結果は (4+2=6) になります。 このアルゴリズムは、非共素ステップが次元全体に到達することを決して想定しません。 

のために`3 2 3 2`、両方のジャンプはその次元に等しい。 (p_n=p_m=1) となるため、(L=1) になります。 最良の行残余は (2)、最良の列残余は (1)、そして唯一食べたハンバーガーには価値があります (2\cdot2+1+1=6)。 次のポジションも全く同じ美味しさなので、プレイヤーはすぐに目覚めます。 式は (6) を生成します。 

のために`4 3 2 1`、行サイクルには (g_n=2) と (p_n=2) があります。 最良のゼロベースの行は (1) と (3) で、その合計は (4) です。 完全な期間は (L=\operatorname{lcm}(2,3)=6) であるため、各行位置は 3 回発生し、各列位置は 2 回発生します。 行の寄与は (3\cdot4\cdot3=36)、列の寄与は (3\cdot2=6)、定数の寄与は (6) です。 最終的な答えは (36+6+6=48) です。 

のために`2000000000 2000000000 1 1`、両方の次元に周期 (2\cdot10^9) があるため、完全な軌跡には (2\cdot10^9) 個のバーガーが含まれます。 1 次元の最大合計は、各座標について (2000000000\cdot1999999999/2) となります。 計算は剰余乗算を使用して実行されるため、膨大な軌跡を反復する必要はなく、最終結果は次のようになります。`999998628`。
