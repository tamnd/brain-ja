 ## 解決策
 ## 問題の理解

 私たちは持っています`n`選手たちは円の周りに配置され、Essa はその位置からスタートします`p`。 がある`n - 1`エリミネーションラウンド。 ラウンド用`i`、歌は続く`a[i]`秒と椅子`order[i]`は、そのラウンドが終了すると利用できなくなる椅子です。 各曲の前に、Essa は時計回りまたは反時計回りの移動を選択でき、各プレーヤーは選択した方向に 1 秒ごとに 1 つの位置を移動します。 

重要な点は、円が固定されていないことです。 椅子が消えると、対応する位置が円から消えるため、それ以降のすべての位置が 1 つずつ移動します。 したがって、次のラウンドはポジションが 1 つ少ない円で操作されます。 入力により、曲の長さと椅子が消える正確な順序がわかります。 時計回りと反時計回りの選択の少なくとも 1 つのシーケンスが Essa をすべて生き残らせるかどうかを判断するだけで済みます。`n - 1`ラウンドします。 公式の問題には、`n <= 1000`、1 秒の時間制限、および 256 MB のメモリ制限。 

曲の長さは次のとおりです。`10^9`, そのため、一度に 1 秒ずつシミュレーションすることは不可能です。 円のサイズだけ移動するとプレーヤーは同じ位置に戻るため、現在の円のサイズを法とする長さのみが重要になります。 以来`n`わずか 1000 です、`O(n^2)`動的プログラムは実用的ですが、全方向シーケンスの指数列挙は実用的ではありません。 

直接実装すると、気付かれずに問題が発生する簡単なケースがいくつかあります。 1 つ目は、曲の長さが現在のサークルよりもはるかに長い場合です。 例えば、```
2 1
2
1
```答えがあります`No`。 2 つのポジションがあり、エッサはポジション 1 から開始し、どちらかの方向に 2 歩移動するとポジション 1 のままになります。椅子 1 は除外された椅子なので、エッサは負けます。 モジュロ演算を忘れたり、2 つの方向を異なるものであるかのように処理すると、誤った結果が得られます。 

もう 1 つの微妙なケースは、取り外される椅子が室内の位置にある場合です。 例えば、```
5 3
4 4 4 4
4 3 2 1
```答えがあります`Yes`。 椅子が消えると、その椅子以降の位置の番号が付け直されます。 Essa の古いインデックスを圧縮せずに保持すると、後のラウンドで間違った位置が使用されます。 

3 番目のエッジ ケースは、両方の方向の選択が同じ位置につながる場合に発生します。 これはいつでも起こります`2 * a[i]`現在の円のサイズで割り切れます。 例えば、```
3 1
3 1
1 2
```答えがあります`No`。 最初のラウンドでは、円のサイズは 3 で、どちらかの方向に 3 歩進むと、Essa は位置 1 に残り、まさに除去される椅子になります。 

## 入力

 最初の行には以下が含まれます`n`そして`p`、 どこ`n`は初期のプレイヤー数であり、`p`は、1 から始まるインデックスを使用した Essa の初期位置です。 

2行目には次の内容が含まれます`n - 1`曲の長さ。 の`i`-th 値はラウンドの秒数です。`i`。 

3行目には以下が含まれます`n - 1`明確な椅子のラベル。 の`i`-th 値はラウンドで消える椅子を識別します`i`。 

椅子のラベルは個別であるため、生き残った椅子を明示的に保守するのは簡単です。`n <= 1000`。 

## 出力

 印刷する`Yes`エッサが最後まで残ることを可能にする時計回りと反時計回りの一連の決定が存在する場合。 それ以外の場合は、印刷します`No`。 

## アプローチ

 直接的なブルートフォース ソリューションでは、考えられるすべての方向シーケンスを試すことができます。 それぞれに 2 つの選択肢があります`n - 1`ラウンドなので、`2^(n-1)`可能なシーケンス。 各シーケンスについて、全ラウンドを通じて Essa の位置をシミュレートし、エリミネーションごとに円を更新できます。 円を維持した後、各ラウンドを一定時間で処理したとしても、これにより、`O(n * 2^n)`最悪の場合は動作します。 で`n = 1000`、これは次の順序です。`1000 * 2^1000`状態遷移は完全に不可能です。 

完全な方向シーケンスが Essa の軌道を完全に決定するため、強引な判断は正しいです。 問題は、多くの異なる方向シーケンスが同じラウンドで同じ位置に到達することです。 2 つの歴史が同じ現在の位置に統合されると、以前の違いは無関係になります。 未来は現在のサークルとエッサの現在の位置にのみ依存します。 

これにより、自然な動的プログラミング状態が得られます。 各ラウンドの開始時に、一連の決定をすべて覚えるのではなく、エッサが現在いる可能性のあるすべての位置を覚えておいてください。 ブール配列`dp`十分です:`dp[q]`Essa をその位置に残す、以前の選択の有効なシーケンスがある場合に、正確に true になります。`q`。 

現在の円のサイズがあるとします。`m`、取り外した椅子がインデックスにあります`r`、そして歌は続きます`a`秒。 手の届く位置から`q`、時計回りに移動すると到達します`(q + a) mod m`そして反時計回りに移動すると`(q - a) mod m`。 

どちらかの宛先が等しい場合`r`、その選択はラウンドに負け、破棄されます。 他の目的地はすべて生き残るが、椅子の後には`r`が消え、位置が次より大きくなります`r`1 つ左に移動します。 次の DP 配列を構築するときに、この圧縮を直接適用できます。 

円自体は、生き残っている椅子のラベルを含む通常の Python リストとして保存できます。 撤去された椅子を探す`alive.index(...)`そしてそれを削除します`pop(...)`費用`O(n)`ラウンドごとに、すでに期限内にあります`O(n^2)`予算。 これらの制約のためにフェンウィック ツリーや別のデータ構造を導入する理由はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n * 2^n)`|`O(n)`| 遅すぎる |
 | 動的プログラミング |`O(n^2)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在残っている椅子ラベルを循環順序で保管します。 もともとこれは`[1, 2, ..., n]`。 Essa の開始位置を 1 ベースのインデックスから 0 ベースのインデックスに変換し、それを唯一の到達可能な位置としてマークします。 
2. 各曲について、`m`現在の生き残っているポジションの数になります。 削除される椅子を見つけます。`alive`リストを作成し、そのゼロベースのインデックスを呼び出す`r`。 円は元の椅子のラベルではなく連続した位置で表されるため、動きにとってインデックスが重要です。 
3. 曲の長さを剰余的に減らす`m`。 歌が続くなら`a`秒、移動中`a`位置は移動とまったく同じです`a % m`サイズの円の周りの位置`m`。 これにより、潜在的に膨大な曲の長さに比例する作業を行うことがなくなります。 
4. 到達可能なすべての位置について`q`、両方の可能な目的地を計算します。 時計回りの目的地は`(q + step) % m`、反時計回りの目的地は`(q - step) % m`。 
5. 以下に等しいすべての宛先を拒否します。`r`。 そのポジションには曲の終わりに椅子がなくなったため、Essa がそのラウンドで敗退したプレイヤーになります。 
6. 生き残ったすべての目的地について`x`、椅子の後のインデックスに変換します`r`が削除されます。 もし`x < r`、そのインデックスは変わりません。 もし`x > r`、になります。`x - 1`。 結果の位置を次の DP 配列に格納します。 
7. 対応する椅子をから取り外します。`alive`そして次の曲に進みます。 DP 配列が空になった場合、考えられる戦略はすべて失われているため、答えはすぐに得られます。`No`。 
8. 結局のところ`n - 1`ラウンドを終えると、ちょうど 1 つのポジションが残ります。 最終位置が到達可能であれば、Essa は方向選択の勝利シーケンスを持っているため、次のように出力します。`Yes`。 

不変条件は、各ラウンドの直前に、`dp[q]`これは、前のすべてのラウンドで生き残った一連の選択の後にエッサが配置できる現在のサークル内の位置に正確に当てはまります。 移行では、そのようなすべてのポジションからの両方の法的選択が考慮され、排除された椅子に対応するポジションが正確に削除され、円が縮小した後、生き残ったポジションが新しいインデックスに変換されます。 したがって、不変式はラウンドごとに保存されます。 最終的に、到達可能な位置は、Essa が決して排除されない完全な選択シーケンスが存在するときに存在します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(data: str) -> str:
    values = list(map(int, data.split()))
    it = iter(values)

    n = next(it)
    p = next(it)

    songs = [next(it) for _ in range(n - 1)]
    order = [next(it) for _ in range(n - 1)]

    alive = list(range(1, n + 1))

    dp = [False] * n
    dp[p - 1] = True

    for song, removed_chair in zip(songs, order):
        m = len(alive)

        # Index of the chair that disappears in the current circle.
        r = alive.index(removed_chair)

        # Only the remainder modulo the current circle size matters.
        step = song % m

        after_move = [False] * m

        for q in range(m):
            if not dp[q]:
                continue

            clockwise = (q + step) % m
            if clockwise != r:
                after_move[clockwise] = True

            counterclockwise = (q - step) % m
            if counterclockwise != r:
                after_move[counterclockwise] = True

        if not any(after_move):
            return "No"

        # Remove the chair and compress all surviving positions.
        next_dp = [False] * (m - 1)

        for x in range(m):
            if not after_move[x]:
                continue

            new_pos = x if x < r else x - 1
            next_dp[new_pos] = True

        dp = next_dp
        alive.pop(r)

    return "Yes" if dp[0] else "No"

def main():
    data = sys.stdin.buffer.read().decode()
    print(solve(data))

if __name__ == "__main__":
    main()
```の`alive`list は、現在のサークルを循環順に表します。 その値は元の椅子ラベルであり、これにより、どの物理的な椅子が削除されているかを見失うことなく、入力から椅子を見つけることができます。 

DP 配列は、元の椅子のラベルではなく、現在の円形の位置によってインデックスが付けられます。 椅子を削除すると、その後のすべての椅子の位置が変更されるため、この区別は不可欠です。 の`alive.index(removed_chair)`呼び出しは、元の椅子ラベルを現在の位置に変換します。 

表現`song % m`動きは周期的であるため、必要です。 Python の整数はオーバーフローしないため、曲の最大長でも安全ですが、早めに短くすることで移行が簡単になります。 

2 つの宛先は独立して計算されます。 たとえば、円のサイズが 2 の場合、または移動が半円の場合、それらは等しい場合があります。 両方の宛先を同じブール配列セルに割り当てると、このケースは自然に処理されます。 

圧縮ステップでは次を使用します。`x if x < r else x - 1`。 削除された椅子の前の位置はインデックスを維持しますが、椅子の後のすべての位置は 1 つずつ左にシフトします。 削除された位置自体はすでに破棄されているため、次の配列でアクセスされることはありません。 

最終的な DP 配列の長さは 1 です。 チェック中`dp[0]`最終的な敗退後にゲームには 1 つのポジションしか残っていないため、これで十分です。

```最初の動きは`3 mod 3 = 0`。 Essa はインデックス 0 から開始し、両方向でインデックス 0 に到達し、インデックス 0 が削除された椅子になります。 DP には最初のラウンドの後に生き残る状態がないため、以降の曲を考慮する必要はありません。 

最大サイズの場合、円は 1000 位置から始まり、一度に 1 位置ずつ縮小します。 すべての曲の長さは 1 であるため、各ラウンドでは 2 つの隣接する目的地のみが考慮されます。 多くの異なる方向のシーケンスが存在する可能性がありますが、DP は同じ位置に到達するすべてのシーケンスをマージします。 どのラウンドでも最大 1000 の州が検査され、指数関数的ではなく二次関数的な増加が得られます。
