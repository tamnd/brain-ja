 ## 解決策
 ## 問題の理解

 正の整数のペアのリストが与えられ、各ペアについて、両方の数値を同時にインクリメントすることによって形成される一連の連続するペアを探索したいと考えています。 このシーケンスの各ペアは、2 つの数値が互いに素である場合、つまり最大公約数が 1 である場合に「幸運」であると見なされます。タスクは、幸運ではないペアに遭遇する前にこのシーケンスがどれだけ長く継続できるかを判断するか、またはこのシーケンスが無期限に継続できることを報告することです。 

入力サイズは最大 100 万ペアまで可能で、ペアの各数値は 1,000 万に達します。 これは、チェーンのすべてのステップを単純にチェックするソリューションは遅すぎることを意味します。100 万のペアごとに潜在的に数百万の連続する数値を反復処理すると、最悪の場合でも約 10^12 の演算が必要になるからです。 したがって、私たちのアルゴリズムは各ステップのシミュレーションを避け、代わりにペアがいつ不運になるかを数学的に推論する必要があります。 

2 つの数値が (8, 9) のように連続する整数である場合、そのような数値は常に互いに素であり、チェーンが無限に伸びる可能性があるため、明らかではないエッジ ケースが発生します。 もう 1 つの微妙なシナリオは、(5, 15) など、数字に共通の因数がある場合に発生します。この場合、最初のペアは幸運ではないため、チェーンの長さがすぐに 0 になります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。ペアごとに両方の数値を繰り返しインクリメントし、各ステップで gcd が 1 より大きくなるまで計算します。問題定義を直接実装しているため、これは正しいです。 ただし、最悪の場合、ペアごとに O(max(y)) 回の gcd 計算を実行することになりますが、これは 10^7 までの y と 10^6 までの n に対しては実行不可能です。 これにより、およそ 10^13 という大まかな操作数が得られ、妥当な制限時間をはるかに超えています。 

重要な洞察は、インクリメントされたペア (x+k, y+k) の gcd が数値の差を使用して書き換えられるということです。 d = y - x とします。 gcd(a, b) = gcd(a, b-a) であるため、gcd(x+k, y+k) は gcd(x+k, d) と同等になります。 これにより、問題は gcd(x+k, d) > 1 となる最小の k ≥ 0 を見つけることになります。そのような k が存在しない場合、チェーンは無限になります。 それ以外の場合、チェーンの長さはまさにこの k です。 

最適化では、d と素因数を共有する最初の数値がチェーンの停止場所を決定するという事実を利用します。 d を素因数に因数分解すると、x+k がこれらの素因数の 1 つで割り切れる最小の k をすぐに見つけることができます。 d = 1 の場合、連続する整数は常に互いに素であるため、チェーンは常に無限になります。 d > 1 の場合、d の素因数だけを考慮する必要があるため、問題は 10^7 整数にわたるシミュレーションからペアごとに数回のモジュロ チェックに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * 最大(y)) | お(1) | 遅すぎる |
 | 素因数分解 + モジュロ | O(n * sqrt(d)) 償却 | O(sqrt(d)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての入力ペアを読み取り、各ペアの差 d = y - x を計算します。 
2. d = 1 の場合、すぐに -1 を出力します。 これは、x と y が連続した整数であり、常に互いに素であるため、チェーンは無限に拡張できるためです。 
3. d を素因数分解します。 これらの素数だけが最終的に x+k を割り、連鎖を壊すことができます。 
4. d の各素因数 p について、(x + k) % p == 0 となる最小値 k ≥ 0 を計算します。これにより、その素数のためにチェーンが幸運でなくなった最初の位置が得られます。 
5. すべての素因数にわたる最小 k を取得します。 k のペアはすでに不運であるため、これは (x, y) から 1 を引いた幸運の連鎖の長さです。 
6. 最初に gcd(x, y) > 1 の場合は、チェーンが開始されていないため、0 を出力します。 
7. それ以外の場合は、計算されたチェーンの長さを出力するか、無限の場合は -1 を出力します。

不変条件は、d の素因数の最初の倍数より前の任意の k について、gcd(x+k, y+k) が 1 のままであることです。この時点以降、チェーンは続行できません。 これにより正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def prime_factors(n):
    factors = set()
    i = 2
    while i * i <= n:
        if n % i == 0:
            factors.add(i)
            while n % i == 0:
                n //= i
        i += 1
    if n > 1:
        factors.add(n)
    return factors

def longest_lucky_chain(x, y):
    from math import gcd
    if gcd(x, y) > 1:
        return 0
    d = y - x
    if d == 1:
        return -1
    primes = prime_factors(d)
    min_k = float('inf')
    for p in primes:
        rem = x % p
        k = (p - rem) % p
        min_k = min(min_k, k)
    return min_k

n = int(input())
res = []
for _ in range(n):
    x, y = map(int, input().split())
    res.append(str(longest_lucky_chain(x, y)))
print('\n'.join(res))
```まず、長さが直接ゼロのチェーンを処理するために gcd をチェックします。 次に、連続する整数が関係する場合の無限チェーンを処理します。 d を因数分解すると、問題は素数の小さなセットに縮小され、素数ごとに 1 つのモジュロ演算で最初のアンラッキーなステップが決定されます。
