 ## 解決策
 ## 問題の理解

 配列セグメントの場合、その要素を左から右に処理し、サブシーケンスのリストを維持します。 

新しい値が到着すると、現在の最後の要素が新しい値と正のビット単位の AND を持つ最初のサブシーケンスを探します。 そのようなサブシーケンスが存在する場合は、そこに値を追加し、そのサブシーケンスの最後の要素を更新します。 それ以外の場合は、まったく新しいサブシーケンスを作成します。 

させて$f(segment)$このプロシージャによって作成されるサブシーケンスの最終的な数になります。 

タスクは合計することです$f$指定された配列のすべての部分配列にわたって。 

配列の長さが次の値に達しました$3 \cdot 10^5$、約あります$4.5 \cdot 10^{10}$サブアレイ。 部分配列を個別に評価するアルゴリズムは絶望的です。 たとえ$O(n^2)$解決策は完全に範囲外です。 線形時間に近いものが必要です。 

珍しい制約は、すべての配列値が以下に属することです。$\{0,1,2,3\}$。 解決策全体は、この値セットが非常に小さいことを利用することから生まれます。 

最初の微妙なケースは、値です。$0$。 既存のサブシーケンスにゼロを追加することはできません。$x \& 0 = 0$あらゆる人にとって$x$。 ゼロごとに常に新しいサブシーケンスが作成されます。 

例えば：```
[0, 0]
```分解により 2 つのサブシーケンスが作成されるため、$f=2$。 

もう 1 つの微妙なケースは、アルゴリズムが任意のサブシーケンスではなく、最初の互換性のあるサブシーケンスを常に選択することです。 

例えば：```
[1, 2, 3]
```加工後$1,2$、アクティブなサブシーケンスは次のとおりです。```
[1]
[2]
```いつ$3$到着すると、最初のサブシーケンスに追加されます。$1 \& 3 > 0$。 2 番目のものを選択すると、異なる状態が生成され、間違った答えが生成されます。 

3 番目の罠は、各サブシーケンスの現在の最後の要素のみが重要であるということです。 以前の要素が将来の決定に影響を与えることはありません。 

例えば：```
[1,3,2]
```最初のサブシーケンスは次のようになります$[1,3,2]$。 将来の決定は最終的な値のみに依存します$2$、以前のものではありません$1,3$。 

## アプローチ

 ブルーフォースのアイデアは単純明快です。 

開始位置を選択してください$l$。 右側のエンドポイントを拡張します$r$一度に一歩ずつ。 分解を維持する$a[l..r]$現在存在するサブシーケンスの数を追跡します。 

これは、定義を直接シミュレートするため、正しいです。 

問題は複雑さです。 がある$O(n^2)$サブアレイ。 それぞれの拡張子があったとしても$O(1)$、合計作業量は依然として 2 次式になりますが、これはあまりにも大きすぎます。$n=3\cdot10^5$。 

重要な観察は、値が以下に制限されていることです。$\{0,1,2,3\}$。 

ある瞬間の分解状態を考えてみましょう。 将来の決定は、現在「使用可能な」すべてのサブシーケンスの最後の要素にのみ依存します。 

で終わる後続シーケンス$0$特別です。 彼らは将来の価値を決して受け入れることができません。$0 \& x = 0$みんなのために$x$。 サブシーケンスが終了すると、$0$、将来の移行には無関係になります。 

したがって、ゼロ以外の部分列の最後の値を覚えておく必要があるだけです。 

それらの値は次のものに属します$\{1,2,3\}$。 first-compatibility-subsequence ルールを繰り返し適用すると、ごく少数の状態しか出現しません。 実際、到達可能な状態は 16 のみです。 これが重要な圧縮です。 元のプロセスは複雑に見えますが、将来の動作全体は、可能な 16 の状態のうちの 1 つによって決定されます。 このアイデアはまさに公式ソリューションの基礎です。 

状態空間が一定になると、位置と状態に対して動的プログラミングを実行できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$それより悪い |$O(n)$| 遅すぎる |
 | 最適 |$O(n \cdot S)$、$S=16$|$O(S)$| 承認済み |

 ## アルゴリズムのチュートリアル

 状態を、ゼロ以外のすべての部分列の最後の値の順序付きリストであるとします。 

例:```
()
(1)
(2,1)
(3,2,1)
```到達可能な州は 16 のみです。 

遷移関数を定義します。```
go(state, x)
```1 つの新しい値を処理します。 

もし$x=0$、新しいサブシーケンスは常に作成されますが、ゼロで終わるサブシーケンスは後で役に立たないため、状態は変わりません。 

もし$x>0$、状態を左から右にスキャンします。 

最初の値が正の AND を持つ場合、$x$が見つかった場合は、その値を次のように置き換えます$x$。 

それ以外の場合は追加$x$州の終わりまで。 

遷移では次のものも返されます。```
add = 1
```新しいサブシーケンスが作成された場合、それ以外の場合```
add = 0
```次に、次のように定義します。```
dp[i][state]
```ポジションから生み出される貢献度の合計として$i,i+1,\dots,n-1$、現在の分解状態が次と等しいと仮定します。`state`。 

位置を仮定します$i$作成します`add`新しいサブシーケンス。 

新しく作成されたサブシーケンスはすべて増加します$f$で終わるサブ配列ごとに 1 ずつ増えます$i,i+1,\dots,n-1$。 

正確には次のとおりです。```
n - i
```そんな結末。 

つまり、ポジションの貢献度は$i$等しい:```
add * (n - i)
```加工後$a_i$、次の状態に進みます。 

これにより、次の繰り返しが得られます。```
dp[i][state]
=
add * (n - i)
+
dp[i+1][next_state]
```答えは次のとおりです。```
sum(dp[i][empty_state])
for all starting positions i
```これは、公式ソリューションで使用されているものと同じ繰り返しです。 

### なぜ効果があるのか

 固定開始位置の場合$l$、分解により位置に新しいサブシーケンスが作成されるたびに$r$、値$f(a[l..t])$ごとに 1 ずつ増加します$t \ge r$。 

まさにあります$n-r$そんな結末。 

繰り返しでは、作成された瞬間にこの増加分がカウントされ、将来のすべてのエンディングに即座に請求されます。 増加するたびに、$f$は正確に 1 回カウントされ、すべての寄与は正確に正しい数の終了の間持続し、結果の合計はすべてのサブ配列の合計に等しくなります。 

状態には、将来の遷移に必要な情報、つまりすべての非ゼロ サブシーケンスの現在の最後の値が正確に含まれています。 以前の情報は将来の選択に影響を与えることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

states = [()]
state_id = {(): 0}

def transition(state, x):
    arr = list(state)

    if x == 0:
        return 1, state

    for i, v in enumerate(arr):
        if v & x:
            arr[i] = x
            return 0, tuple(arr)

    arr.append(x)
    return 1, tuple(arr)

# Enumerate all reachable states.
ptr = 0
while ptr < len(states):
    s = states[ptr]
    ptr += 1

    for x in range(4):
        _, ns = transition(s, x)
        if ns not in state_id:
            state_id[ns] = len(states)
            states.append(ns)

m = len(states)

nxt_state = [[0] * 4 for _ in range(m)]
add_cost = [[0] * 4 for _ in range(m)]

for sid, s in enumerate(states):
    for x in range(4):
        add, ns = transition(s, x)
        nxt_state[sid][x] = state_id[ns]
        add_cost[sid][x] = add

dp_next = [0] * m
answer = 0
empty_id = state_id[()]

for pos in range(n - 1, -1, -1):
    dp_cur = [0] * m
    x = a[pos]

    for sid in range(m):
        ns = nxt_state[sid][x]
        add = add_cost[sid][x]

        dp_cur[sid] = add * (n - pos) + dp_next[ns]

    answer += dp_cur[empty_id]
    dp_next = dp_cur

print(answer)
```最初の部分では、完全な到達可能な状態グラフを構築します。 空の状態から開始して、4 つの可能な値すべてを繰り返し適用します。 登場する州は 16 州だけです。 

遷移テーブルには 2 つの情報が格納されます。 最初は次の状態です。 2 つ目は、新しいサブシーケンスが作成されたかどうかです。 

動的プログラミングは右から左に実行されます。`dp_next`位置を表します`i+1`、 そして`dp_cur`位置を表します`i`。 

表現```
add * (n - pos)
```は中心的なカウントステップです。 で作成された新しいサブシーケンス`pos`以降で終わるすべてのサブ配列に寄与します`pos`。 

すべての算術演算は 64 ビット整数内に快適に収まります。 Python では、とにかく整数に制限はありません。

# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    states = [()]
    state_id = {(): 0}

    def transition(state, x):
        arr = list(state)

        if x == 0:
            return 1, state

        for i, v in enumerate(arr):
            if v & x:
                arr[i] = x
                return 0, tuple(arr)

        arr.append(x)
        return 1, tuple(arr)

    ptr = 0
    while ptr < len(states):
        s = states[ptr]
        ptr += 1

        for x in range(4):
            _, ns = transition(s, x)
            if ns not in state_id:
                state_id[ns] = len(states)
                states.append(ns)

    m = len(states)

    nxt = [[0] * 4 for _ in range(m)]
    add = [[0] * 4 for _ in range(m)]

    for sid, s in enumerate(states):
        for x in range(4):
            c, ns = transition(s, x)
            nxt[sid][x] = state_id[ns]
            add[sid][x] = c

    dp_next = [0] * m
    ans = 0
    empty = state_id[()]

    for pos in range(n - 1, -1, -1):
        dp_cur = [0] * m

        for sid in range(m):
            ns = nxt[sid][a[pos]]
            dp_cur[sid] = add[sid][a[pos]] * (n - pos) + dp_next[ns]

        ans += dp_cur[empty]
        dp_next = dp_cur

    return str(ans)

 ## 特殊なケース

 次のことを考慮してください。```
1
0
```分解により、すぐに 1 つのサブシーケンスが作成されます。 ゼロで終わるサブシーケンスは保存されないため、状態は空のままです。 DPはこう付け加えた$1 \cdot 1$、正解 1 が生成されます。 

次のことを考慮してください。```
2
0 0
```最初のゼロはサブシーケンスを作成します。 2 番目のゼロは別のゼロを作成します。 部分配列には次の値があります。```
[0] -> 1
[0,0] -> 2
[0] -> 1
```合計は 4 です。すべてのゼロ遷移が寄与するため、アルゴリズムがこれを処理します。`add = 1`、状態は決して変化しません。 

考慮する：```
3
1 2 3
```不用意に実装すると追加される可能性があります`3`互換性のある最初のサブシーケンスではなく、2 番目のサブシーケンスに変換されます。 実際のルールは、最初の互換性のあるサブシーケンスを選択し、状態を生成します。`(3,2)`それよりも`(1,3)`。 遷移関数は明示的に左から右にスキャンし、最初の一致で停止し、定義を正確に保持します。 

考慮する：```
4
1 1 1 1
```最初の要素のみが新しいサブシーケンスを作成します。 以降のすべての要素は同じサブシーケンスを再利用します。 DP は 1 つの作成イベントを正しく記録し、その貢献をすべての長いエンディングに伝播します。 これにより、繰り返しの再利用が余分な状態を作成せずに処理されることが検証されます。
