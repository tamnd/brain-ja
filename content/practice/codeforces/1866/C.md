 ## 解決策
 ## 問題の理解

 各頂点が出力エッジの順序付きリストを持つ有向非巡回グラフが与えられます。 各エッジには 0 または 1 のラベルが付けられ、別の頂点を指します。 頂点 1 から開始して、すべての頂点に対してその出力エッジを順番に反復する再帰的走査を実行します。 各エッジについて、最初にそのラベルをグローバル配列に追加し、次にエッジの宛先頂点からのトラバースを再帰的に続行します。 重要な点は、訪問される配列がないため、別のパスが頂点につながるたびに頂点が複数回再入力されることです。 

このプロセスにより、0 と 1 のみからなるシーケンスが生成されます。 タスクは、このシーケンス内の反転の数、つまり 0 の前に 1 が現れる位置のペアを数えることです。 

グラフは DAG ですが、反復が許可されているため、トラバーサル自体は通常の意味での DAG トラバーサルではありません。 これは、生成されるシーケンスが原理的には指数関数的に長くなる可能性があることを意味しますが、構造と制約により、明示的に構築しなくても反転カウントを計算できることが保証されます。 

制約は大きく、最大 100,000 個の頂点と 200,000 個のエッジがあります。 シーケンスの長さが線形サイズをはるかに超えて爆発的に増加する可能性があるため、DFS を明示的にシミュレートして配列を構築するアプローチは不可能です。 このため、ノードごとまたはエッジごとのコントリビューションを処理し、情報を組み合わせて集約する必要があります。 

ノードに複数の出力エッジがあり、サブグラフの重複につながる場合、微妙なエッジ ケースが発生します。 たとえば、頂点 1 に 2 つのエッジがあり、どちらも最終的に同じサブツリーに到達する場合、単純なシミュレーションではそのサブツリーが 2 回再計算され、その寄与が重複します。 この重複は DFS 定義によって意図されているため、エントリ パスの多重度を保持しない限り、トラバーサルのみのメモ化は正しくありません。 

もう 1 つの問題は、反転が構築された配列内のグローバルな順序に依存することです。 グラフは非巡回ですが、DFS 順序付けは非常に特殊な連結構造を作成するため、ローカル サブツリー推論ではエッジ間の順序付けを考慮する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、文字どおり DFS をシミュレートし、配列 Z を構築し、すべてのペアをスキャンして反転をカウントします。 エッジをトラバースするたびに、値を追加して再帰します。 訪問済みのマーキングがないため、すべての個別のパス拡張が完全に実行されます。 最悪の場合、分岐のある線形チェーンであっても、各分岐が共有サブグラフに繰り返し再入するため、指数関数的に多くの訪問が生成される可能性があります。 これにより、明示的なシミュレーションが不可能になります。 

重要な点は、DFS 構造が、ブロックを厳密な順序で連結して構成されるシーケンスを定義していることです。 各頂点は、出力エッジごとに、エッジの重みとそれに続く子頂点の完全なシーケンスを順番に連結することによって形成されるシーケンスを生成します。 

シーケンスを構築する代わりに、頂点ごとに、その DFS 展開が寄与するものの概要 (ゼロの総数、1 の総数、展開内の反転の数) を計算します。 難しいのは、反転の寄与も連結されたセグメント全体で発生するため、同じサブツリーがエッジ間で結合されたときに独立していないことです。 

2 つのシーケンス A とそれに続く B を連結すると、反転は次のようになります。 

反転数(A) + 反転数(B) + (A の 1 の数) × (B の 0 の数)。 

このアイデンティティがコアの還元です。 各頂点のトリプル (0、1、反転) を計算できれば、再帰的展開の間に挿入された単一要素シーケンスとしてエッジの重みを考慮しながら、DFS 順序で子をマージできます。 

したがって、各頂点は DAG 上でポストオーダーで処理でき、その出力エッジは順次処理され、これまでに構築されたシーケンスの実行中の集計が維持されます。

 ## アルゴリズムのチュートリアル

 各頂点の DP 値、つまりゼロの数、1 の数、および完全な DFS 展開の反転数を計算します。 

1. すべての子が親の前に計算されるように、逆のトポロジー順序で頂点を処理します。 グラフは DAG であるため、これは有効です。 
2. 各頂点について、その出力エッジから遠くまで構築されたシーケンスを表す実行構造を維持します。 最初は、この構造は空です。ゼロゼロ、ゼロ 1、ゼロ反転です。 
3. 出力エッジを順番に繰り返します。 各エッジについて、最初にエッジの重みを単一要素シーケンスとして扱います。 重みが 0 の場合、ゼロが 1 つ追加されます。 1 の場合、1 つずつ貢献します。 内部反転は追加されません。 
4. 次に、連結ルールを使用して、この単一要素シーケンスを頂点の現在の累積シーケンスにマージします。 現在のシーケンス A の後にシーケンス X を追加すると、反転の増加は次のようになります。 

現在の反転 + 反転 (X) + 1 (A) × ゼロ (X)。 

X は単一の要素であるため、その内部反転はゼロであり、交差項は X が 0 か 1 かによってのみ依存します。 

1. エッジの重みを処理した後、子頂点の計算済みの DP を取得し、次に同じ連結式を再度使用してマージします。 子は独自の 0、1、および反転を提供し、交差反転は現在の頂点の累積されたプレフィックスに依存します。 
2. 各エッジの後に頂点の累計を更新し、続行します。 
3. 頂点 1 の最終的な DP 値が答えになります。 

これが機能する理由は、DFS 順序がシーケンスの決定論的な連結を定義しているためです。 すべてのエッジは最終的な配列内の連続したブロックに拡張され、連結によって順序が完全に取り込まれます。 反転恒等式により、要素のすべてのペアがブロック内にあるか、2 つのブロックにまたがっていることが保証され、ブロック間の寄与は 1 と 0 のプレフィックス カウントを使用して正確にカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

N = int(input())
g = [[] for _ in range(N + 1)]

for i in range(1, N + 1):
    S = int(input())
    for _ in range(S):
        v, w = map(int, input().split())
        g[i].append((v, w))

dp0 = [0] * (N + 1)
dp1 = [0] * (N + 1)
dpinv = [0] * (N + 1)

visited = [False] * (N + 1)

def dfs(u):
    visited[u] = True

    zeros = 0
    ones = 0
    inv = 0

    for v, w in g[u]:
        if w == 0:
            zeros += 1
        else:
            inv += ones
            ones += 1

        if not visited[v]:
            dfs(v)

        inv += dpinv[v]
        inv += ones * dp0[v]
        zeros += dp0[v]
        ones += dp1[v]

    dp0[u] = zeros
    dp1[u] = ones
    dpinv[u] = inv

dfs(1)

print(dpinv[1] % 998244353)
```このコードは頂点 1 から DFS を実行し、DP 値をボトムアップで計算します。 各頂点について、構築されたシーケンス プレフィックスでこれまでに生成された 0 と 1 の実行カウントを維持します。 エッジが処理されると、その重みは単一要素シーケンスとして即座に適用され、前のシーケンスに対する直接反転 (1 の場合)、またはプレフィックス数の増加に寄与します。 その後、事前に計算された DP 値を使用して子サブツリーが組み込まれます。 

用語`inv += ones * dp0[v]`現在のプレフィックスと子サブツリー内のすべてのゼロの間の相互反転です。 の更新内容`zeros`そして`ones`将来のエッジが拡張プレフィックスを正しく認識できるようにします。 

微妙な点は、訪問したノードをマークしても、ノードごとに 1 回だけ再帰を行うことです。 これが機能するのは、DP がさまざまなエントリ パスに個別に依存せず、固定された発信拡張の構造にのみ依存するためです。 

## 実用的な例

 頂点 1 に 2 つのエッジがある単純なグラフを考えます。最初は重み 1 の頂点 2 に、次に重み 0 の頂点 3 にあり、頂点 2 と 3 は両方ともリーフです。 DFS はシーケンス [1, 0] を生成します。 1 が 0 の前に現れるため、反転は 1 つあります。 

| ステップ | ノード | 接頭辞のゼロ | 先頭に付けるもの | 反転 | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 0 | 0 | 開始 |
 | 2 | エッジ 1→2 (1) | 0 | 1 | 0 | 1 を追加 |
 | 3 | エッジ 2 サブツリー | 0 | 1 | 0 | 葉 |
 | 4 | エッジ 1→3 (0) | 1 | 1 | 1 | 0 を追加すると反転が作成されます。 

これにより、単一エッジの順序付けが相互反転に正しく寄与することが確認されます。 

次に、頂点 1 が頂点 2 と 3 を指し、どちらも 1 の後に複数の 0 を生成する共有構造になる、少し大きな構造を考えてみましょう。 累積は、サブツリー DP 値が一貫して再利用され、クロスタームがプレフィックス 1 に応じてスケールされることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N + M) | 各頂点とエッジは 1 回処理され、各マージ操作は定数時間です。 
| スペース | O(N + M) | 各頂点の隣接リストと DP 配列 |

 この制約では最大 200,000 のエッジが許可されるため、線形トラバースは問題なく制限内に収まります。 DP はサブツリー構造の再計算を回避し、明示的な DFS シーケンスを構築することはありません。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    N = int(input())
    g = [[] for _ in range(N + 1)]
    for i in range(1, N + 1):
        S = int(input())
        for _ in range(S):
            v, w = map(int, input().split())
            g[i].append((v, w))

    sys.setrecursionlimit(10**7)

    dp0 = [0] * (N + 1)
    dp1 = [0] * (N + 1)
    dpinv = [0] * (N + 1)
    vis = [False] * (N + 1)

    def dfs(u):
        vis[u] = True
        z = o = inv = 0
        for v, w in g[u]:
            if w == 0:
                z += 1
            else:
                inv += o
                o += 1

            if not vis[v]:
                dfs(v)

            inv += dpinv[v]
            inv += o * dp0[v]
            z += dp0[v]
            o += dp1[v]

        dp0[u] = z
        dp1[u] = o
        dpinv[u] = inv

    dfs(1)
    return str(dpinv[1] % 998244353)

 ## 特殊なケース

 最初のエッジ ケースは、すべてのエッジの重みが同一である場合です。 すべての重みが 0 である入力の場合、DFS 出力は構造に関係なくゼロのみのシーケンスとなるため、反転カウントはゼロでなければなりません。 この場合、交差項が必要なため、アルゴリズムは反転カウンターをインクリメントしません。 

2 番目のケースは、すべての重みが 1 の場合です。生成されたシーケンスには 1 のみが含まれるため、反転は存在しません。 このアルゴリズムは、1 が 0 の前に出現する場合にのみ反転をカウントするため、dp0 は常に 0 となり、相互寄与は消滅します。 

3 番目のケースには、共有サブツリーへの分岐が含まれます。 頂点 1 に同じ頂点 2 への 2 つのエッジがあるとします。DFS はサブツリー 2 を 2 回訪問しますが、DP は頂点 ID ごとではなくトラバーサル パスごとに 1 回適用されるため、アルゴリズムはそれを 2 回正確にカウントします。 各エッジは独立してサブツリーの寄与をトリガーし、問題定義で必要とされる多重度を正確に維持します。
