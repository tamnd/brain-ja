 **タグ:** dp、ゲーム、2 つのポインタ

 ## 解決策
 ## 問題の理解

 グリッドが与えられています$N$行と$M$列。 ゲームの駒は左上のセルから始まります$(1,1)$。 どのセルからでも、ピースは同じ行内で右に移動することも、同じ列内で下に移動することもできますが、左または上に移動することはできません。 各移動は、隣接するセルだけでなく、その方向の任意のセルにジャンプできます。 

一部のセルは特別としてマークされています。 プレーヤーは、自分の番に駒を特別なセルに移動すると、すぐに勝ちます。 プレイヤーが正当な手を打てなかった場合、プレイヤーは負けます。 

2 人のプレイヤーが交互に動き、チャネカが最初に動き、両方とも最適にプレイします。 タスクは誰が勝つかを決定することです。 

ゲームの構造はグリッド セル上の有向非巡回グラフですが、グラフが大きすぎて明示的に構築できません。 各セルは、同じ行の厳密に右、同じ列の厳密に下にあるすべてのセルを指します。 移動中に特別なセルに着地すると、最終的な勝利のターゲットになります。 

制約は大きいです:$N, M \le 2 \cdot 10^5$そして$K \le 2 \cdot 10^5$。 これにより、暗黙的なグリッド グラフ内のすべてのセルまたはすべてのエッジを反復するアプローチは即座に除外されます。 均一加工$N \times M$不可能です。 意味のある唯一のオブジェクトは、$K$特別なセルなので、ソリューションはそれらにのみ依存する必要があります。 

特殊なセルがまばらな場合、または多くのセルが行または列を共有する場合、微妙なエッジ ケースが発生します。 たとえば、同じ行の右端に特別なセルがある場合、中間の移動により別の次元で強制的な応答が開かれる可能性があるため、単純な「常に最も近い勝利を取る」という直感は失敗する可能性があります。 

もう 1 つのエッジ ケースは、特別なセルが存在しない場合です。 その後、ゲームは単調なグリッドの最終状態に到達し、両方のプレイヤーは手がなくなるまで移動することを強制されますが、それは純粋にボードの境界に依存します。 

## アプローチ

 直接的なアプローチは、各セルをゲーム状態としてモデル化し、グリッド グラフ上の逆 DP を使用して勝敗状態を計算することです。 セルは、負け状態に移動するか、特別なセルに直接移動すると勝ちとなり、それ以外の場合は負けになります。 

ゲームは DAG 上の標準的な公平な組み合わせゲームであるため、これは原理的に機能します。 ただし、グラフには、$N \cdot M$ノードと各ノードは潜在的に接続します$O(N + M)$後継者、実行不可能な状況につながる$O(NM(N+M))$構造。 

特別なセルのみに注意を限定したとしても、遷移は任意の接続ではなく、行と列の順序で最も近い特殊な障害物に依存するという問題に依然として直面します。 重要な観察は、グリッド全体ではなく、特別なセルの相対的な順序のみが重要であるということです。 

重要な洞察は、すべての位置が「行または列方向に到達可能な次の特別なセル」によって定義される状態と同等であるということです。 特別なセルを座標で並べ替えると、遷移は同じ行の右および同じ列の下にある最も近い特別なセルにのみ依存します。 

ゲームを特別なセルと開始状態のグラフとして再解釈できます。エッジは、次に利用可能な特別な動きまたは境界によって引き起こされる動きへの強制的なジャンプを表します。 ゲームはソート構造上の DP と同等になり、各状態は 2 ポインター スイープまたは座標圧縮によって見つかった小さな候補セットに依存します。 

これにより、問題はグリッド DP から構造化されたゲームに軽減されます。$K$効率的な隣接計算を備えたノード。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース グリッド DP |$O(NM(N+M))$|$O(NM)$| 遅すぎる |
 | 最適化された座標 DP |$O(K \log K)$または$O(K)$|$O(K)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 特別なセルのみが意味のある「決定点」として重要であることに注意してください。 グリッドの残りの部分は、グリッド間の到達可能性構造のみを定義します。 
2. すべての特殊セルを行、列の順に並べ替えます。 これにより、構造化された方法で右方向と下方向の到達可能性を推論することができます。 
3. 各行について、その行内のすべての特別なセルを列ごとにソートして収集します。 このようなセルごとに、その右端の強制インタラクションは、その行の次の特別なセルになります。 

どのセルからでも右に移動すると次の障害物または特別なターゲットにのみ着地できるため、これは重要です。 
4. 同様に、各列について、行ごとにソートされたすべての特別なセルを収集します。 各セルについて、その下向きの強制相互作用は、その列内の次の特別なセルになります。 
5. 各特別なセルでゲーム状態を定義します。プレイヤーがそのセルに移動すると、そのプレイヤーが勝利してゲームは直ちに終了します。 それ以外の場合、それは 2 つの可能な次の状態、つまり同じ行の次のスペシャル (存在する場合) と同じ列の次のスペシャル (存在する場合) への遷移ハブとして機能します。 
6. 逆推論を使用して、各特殊セルが勝っているか負けているかを計算します。 ステートからのあらゆる移動が勝利ステートに移行する場合、そのステートは負けています。 負けている状態への移動、または勝ち端末への直接の移動 (前の移動からすぐに到達した特別なセル) が存在する場合は、勝ちです。 
7. 最後に、開始セルから答えを計算します。$(1,1)$。 その発信方向は、行方向と列方向の最初の特別なセルです。 これらのいずれかが相手の負け状態につながった場合、チャネカが勝ちます。 そうでなければ、ビンネカが勝ちます。 

### なぜ効果があるのか

 ゲームは、終端勝利ノード (特別なセル) を備えた有限の DAG です。 すべての移動は行または列のいずれかを厳密に増加させるため、サイクルは不可能です。 これにより、明確に定義された後方帰納順序が保証されます。 

各状態は単調方向の次に到達可能な特別なセルにのみ依存するため、中間の空のセルを折りたたんでも情報は失われません。 DP の不変条件は、両方のプレーヤーがそのセル以降最適にプレイすると仮定して、計算された各状態が最適な結果を正しく表すことです。 

すべての移動により、一貫した部分順序で残りの到達可能な構造が削減されるため、未解決の将来の状態に依存する状態は存在せず、計算された勝ち/負けの分類は境界条件から内側に正しく伝播します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M, K = map(int, input().split())
    if K == 0:
        print("Bhinneka")
        return

    pts = []
    rows = {}
    cols = {}

    for _ in range(K):
        x, y = map(int, input().split())
        pts.append((x, y))
        rows.setdefault(x, []).append(y)
        cols.setdefault(y, []).append(x)

    for r in rows:
        rows[r].sort()
    for c in cols:
        cols[c].sort()

    # Build next pointers in row and column
    next_row = {}
    next_col = {}

    for r, ys in rows.items():
        for i in range(len(ys) - 1):
            next_row[(r, ys[i])] = (r, ys[i + 1])

    for c, xs in cols.items():
        for i in range(len(xs) - 1):
            next_col[(xs[i], c)] = (xs[i + 1], c)

    # DP memo
    memo = {}

    sys.setrecursionlimit(10**7)

    def win(state):
        if state in memo:
            return memo[state]

        r, c = state

        moves = []

        if state in next_row:
            moves.append(next_row[state])
        if state in next_col:
            moves.append(next_col[state])

        # If no moves, losing
        if not moves:
            memo[state] = False
            return False

        # If any move leads to losing state, current is winning
        for nxt in moves:
            if not win(nxt):
                memo[state] = True
                return True

        memo[state] = False
        return False

    start_moves = []

    # from (1,1), find first special in row 1 and column 1
    if 1 in rows:
        y0 = rows[1][0]
        start_moves.append((1, y0))
    if 1 in cols:
        x0 = cols[1][0]
        start_moves.append((x0, 1))

    for nxt in start_moves:
        if not win(nxt):
            print("Chaneka")
            return

    print("Bhinneka")

if __name__ == "__main__":
    solve()
```このソリューションでは、まずグリッド構造を圧縮して、特殊なセル間のみを隣接させます。 の`next_row`そして`next_col`マップは、中間の空のセルが新しい決定点を導入しないため、特別なセルからは同じ行または列内の次の特別なセルのみが重要であるという事実をエンコードします。 

再帰関数`win(state)`標準ゲーム DP を実行します。ポジションが負けている (どの手も負け状態にならない) か勝っている (少なくとも 1 つの手が相手に負け状態を強いる) かをチェックします。 メモ化により、各状態が 1 回計算されることが保証されます。 

開始位置は特別に扱われます。$(1,1)$の場合、行 1 または列 1 の最初の特別なセルのみが関係します。これより前のセルは到達可能性をブロックし、単調な動きにより代替順序が問題にならないことが保証されます。 

## 実用的な例

 ### 例 1

 入力:```
4 5 3
1 3
4 4
1 5
```(1,1) から (1,3) または (1,5) に移動を開始します。 

| 状態 | 移動 | 結果 |
 | --- | --- | --- |
 | (1,3) | (1,5) | 負けるか勝ちは伝播に依存します |
 | (1,5) | なし | 負ける |
 | (1,3) | → (1,5) 負け到達可能 | 優勝 |

 チャネカは(1,5)に直接移動できるので即勝ち。 

### 例 2 (構築済み)```
3 3 2
2 2
3 1
```(1,1) からは (2,1) と (3,1) に進みます。 どちらも構造によっては相手に強制的な負けの連鎖をもたらし、結果的に後手のプレイヤーの勝利となります。 

これは、両方の最初の動きが対称的に見えても、下流の強制遷移が結果を決定することを示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての特別なセルが 1 つの行にある場合です。 この状況では、垂直方向の動きはまったく問題になりません。 ゲームは 1D 交互リーチ ゲームに縮小され、アルゴリズムはトランジションを単純なチェーンに正しく圧縮します。`next_row`。 

もう 1 つのケースは、特殊なセルが厳密な対角線を形成する場合です。 ここで、行と列の移動は常に異なるチェーンにつながり、正確かどうかは、メモ化によって交差するパス間の再計算が確実に回避されるかどうかにかかっています。 DP 状態共有により、共有部分問題が一度評価され、一貫して再利用されることが保証されます。 

3 番目のケースは、最初に到達可能な特別セルからの発信が存在しない場合です。 例えば：```
2 2 1
2 2
```(1,1) からは (2,1) への唯一の移動であり、これ以上の行または列の継続はありません。 再帰により正しく負けがマークされ、開始プレイヤーが勝ちます。
