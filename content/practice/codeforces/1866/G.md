 ## 解決策
 ## 問題の理解

 各車両には、最初はある程度の数の乗客が乗車しています。 馬車に乗り始める乗客`i`左または右に移動することはできますが、それ以上横切ることはできません`D_i`ドア。 つまり、車両の乗客全員が`i`間隔内のどこかで終了する必要があります$$[i-D_i,\; i+D_i]$$エンドポイントを有効な範囲にクリップした後`1..N`。 

すべての乗客が出発車両によって許可された間隔内に留まっている限り、乗客を自由に再分配することができます。 

目標は、全体の動きを最小限に抑えることではありません。 その代わりに、列車のバランスを可能な限り確保したいと考えています。 すべての動きが終わったら、`Z`あらゆる車両の中で最大の乗客数であること。 の達成可能な最小値を見つけなければなりません`Z`。 

制約があるからこそ、問題は面白くなります。 まであります`2 · 10^5`車両、乗客数は最大でも可能です。`10^9`。 明示的に乗客を移動させたり、乗客ごとに 1 つのノードを持つフロー グラフを構築したり、考えられるすべての最終分布を試行したりするアルゴリズムは、直ちに不可能になります。 たとえ`O(N^2)`アルゴリズムには次のようなものが必要です`4 · 10^10`最悪の場合の運用。 

移動制限の構造が重要な観察点です。 車両からのすべての乗客グループ`i`1 つの連続した間隔内でのみ割り当てることができます。 この区間構造は、任意のグラフよりもはるかに単純です。 

いくつかの特殊なケースは見落とされがちです。 

考慮する：```
1
10
0
```馬車は一台しかなく、誰も動けない。 答えは`10`。 再配布が常に可能であると仮定したソリューションは、ここでは失敗します。 

考慮する：```
2
5 0
0 0
```誰も出発馬車から降りることはできません。 答えは`5`、 ない`3`。 移動の制約によりバランスが取れない場合、合計平均は問題になりません。 

考慮する：```
3
3 3 3
2 2 2
```すべての乗客がすべての車両に到達できます。 がある`9`乗客と`3`馬車ですので、答えは次のとおりです。`3`。 ローカル制約のみを調べるソリューションでは、より大きな制約が誤って返される可能性があります。 

主な困難は、提案された値が以下であるかどうかを判断することです。`Z`実現可能です。 

## アプローチ

 強引な観点では、各車両の最終的な乗客数を推測し、すべての乗客をそこに誘導できるかどうかを確認します。 たとえ何らかの方法で各車両を最大で 2 台までに制限したとしても、`Z`乗客にとって、考えられる分布は指数関数的に多く存在します。 これでは絶望的だ。 

より洗練された総当り攻撃のアイデアは、問題をフロー ネットワークとしてモデル化することです。 各出発車両が貢献します`A_i`流量の単位。 各目的地車両には定員があります`Z`。 ソース間を接続します`i`到達可能なすべての目的地までの車両に到着します。 

これは正しいですが、グラフには次の内容が含まれています。$$\sum (2D_i+1)$$エッジ、`Θ(N^2)`最悪の場合。 と`N = 2 · 10^5`、それは大きすぎます。 

転換点は、すべての乗客グループが路線上の 1 つの区間に対応していることに気づいたことから始まります。 区間割り当ての問題では、多くの場合、貪欲なスイープライン解法が可能になります。 

いくつかの候補値を修正するとします`Z`。 各車両には定員が設けられています`Z`、つまり最大でも受け入れられることを意味します`Z`最終手配中の乗客。 

運送用`i`、という要望があります。`A_i`乗客は間隔内のどこかに配置されなければなりません`[L_i, R_i]`。 

これは次のようになります。 

「すべてのインターバル要求をポジションに割り当てることができますか?」`1..N`、どのポジションにも能力がある`Z`？」

 実現可能性の問題は単調です。 容量の場合`Z`動作する場合は、さらに大きな容量も動作します。 これは、答えに対する二分探索を即座に示唆します。 

残りのタスクは、効率的な実現可能性テストです。 

目的地の車両を左から右にスイープします。 位置に着いたら`x`、左端が`x`アクティブになります。 このポジションの定員は`Z`。 

その容量を最適に使用するには、常に最小の正しいエンドポイントを最初に使用してアクティブな間隔を提供する必要があります。 期限が早く切れる間隔ほど緊急性が高くなります。 これは、最早期限優先スケジューリングで使用されるのと同じ交換引数です。 

適切なエンドポイントによって順序付けされた最小ヒープは、まさに必要なものを提供します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | フロー / 明示的な割り当て | 少なくとも O(N²) | O(N²) | 遅すぎる |
 | 二分探索 + 貪欲な間隔スイープ | O(N log N log S) | O(N) | 承認済み |

 ここ`S = sum(A_i)`。 

## アルゴリズムのチュートリアル

 ### 修正の実現可能性チェック`Z`車両ごとに`i`、 定義する：$$L_i = \max(1, i-D_i)$$

$$R_i = \min(N, i+D_i)$$キャリッジ`i`～の需要に貢献する`A_i`車内のどこかに割り当てられなければならない乗客`[L_i, R_i]`。 

目的地の位置を左から右にスイープします。 

1. 各位置から始まる間隔のリストを作成します。 
2. 適切なエンドポイント順に並べられたアクティブな間隔の最小ヒープを維持します。 
3. 位置に到達したとき`x`、すべての間隔を挿入します`L_i = x`山の中へ。 
4. 容量を使用する前に、アクティブな間隔がすでに存在するかどうかを確認します。`R_i < x`。 このような間隔がまだ存在する場合は、期限が過ぎており、割り当ては不可能です。 
5. ポジション`x`利用可能な容量がある`Z`。 
6. 最小の右エンドポイントでアクティブな間隔を繰り返し取得します。 
7. その間隔にできるだけ多くの容量を割り当てます。 
8. 間隔が完全に満たされた場合は、完全に削除します。 
9. ポジションの残りの容量をすべて消費した後も、その区間にまだ乗客が必要な場合`x`、それをヒープに戻して次に進みます。 
10. ポジション後`x`アクティブな間隔が存在する場合、処理されます。`R_i = x`、すでに十分に満足しているはずです。 そうしないと実現可能性が失われます。 
11. すべてのポジションを処理した後、未完了の間隔が残っていない場合にのみ実行可能となります。 

### 二分探索

 1.セット`low = 0`。 
2.セット`high = sum(A)`。 
3. 最小の二分探索`Z`実現可能性テストは成功します。 
4. その値を出力します。 

### なぜ効果があるのか

 任意の宛先位置で、別のアクティブな間隔がすぐに期限切れになる一方で、後から右のエンドポイントを持つ間隔に容量を割り当てるとします。 

後で以前の間隔を満たすことができなくなった場合は、割り当ての一部を交換し、代わりにその容量を以前の間隔に与えることができます。 後のインターバルには、期限が早くないため、将来のポジションに少なくとも同じくらいの余地がまだ残っています。 

この交換引数を繰り返し適用すると、正しいエンドポイントの昇順でアクティブな間隔を提供することが、常に少なくとも他の選択肢と同じくらい優れていることがわかります。 

スイープにより、各間隔が許容範囲内の容量のみを受け取ることが保証されます。 間隔が適切な終点に達すると、アルゴリズムはその完全な需要がすでに割り当てられているかどうかをチェックします。 したがって、受け入れられたすべての割り当てはすべての制約を満たします。 

実現可能性は単調であるため、`Z`、二分探索により実現可能な最小値が見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from heapq import heappush, heappop

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    d = list(map(int, input().split()))

    starts = [[] for _ in range(n + 2)]

    for i in range(n):
        l = max(1, i + 1 - d[i])
        r = min(n, i + 1 + d[i])
        starts[l].append((r, a[i]))

    total = sum(a)

    def feasible(z):
        heap = []

        for pos in range(1, n + 1):
            for r, amt in starts[pos]:
                heappush(heap, (r, amt))

            while heap and heap[0][0] < pos:
                return False

            cap = z

            while cap > 0 and heap:
                r, need = heappop(heap)

                take = min(cap, need)
                cap -= take
                need -= take

                if need:
                    heappush(heap, (r, need))
                    break

            while heap and heap[0][0] == pos:
                return False

        return not heap

    lo, hi = 0, total

    while lo < hi:
        mid = (lo + hi) // 2
        if feasible(mid):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

solve()
```前処理では、各開始キャリッジを間隔に変換します。`[L_i, R_i]`要望と一緒に`A_i`。 

の`starts`配列を使用すると、インターバルがアクティブになったときに正確にヒープにインターバルを挿入できます。 これにより、掃引中にすべての間隔を繰り返しスキャンすることが回避されます。 

ヒープにはペアが格納されます`(right_endpoint, remaining_demand)`。 最小の右エンドポイントが常に最初に処理されます。 

微妙な点としては、`break`部分的に満たされた間隔を再挿入した後。 現在の位置の容量がなくなると、それ以上の間隔はこの位置から何も受信できなくなります。 再挿入して続行しても時間の無駄になるだけです。 

もう 1 つの微妙な点は、期限のチェックです。 ポジションを使用する前に`pos`、任意の間隔`r < pos`すでに有効期限が切れているため、失敗する可能性があります。 ポジション使用後`pos`、残りの間隔`r == pos`これは容量を受け取る最後のチャンスだったので、失敗の原因にもなります。 

乗客数は以下に達する可能性があります`10^9`したがって、すべての算術演算は、大きな値を保持できる整数を使用して実行する必要があります。 Python はこれを自然に処理します。
