 ## 解決策
 ## 問題の理解

 まずは単一のスタックから始めます$N$ジャケット。 ジャケットにはそれぞれ色があり、順番は上から下まで決まっています。 2 番目の空のスタックがあります。 ジャケットをスタック間で上から 1 枚ずつ移動することができますが、最終的には、各パケットに単色のジャケットが含まれる「パケット」を形成してすべてのジャケットを取り除かなければなりません。 主な制限は、パッキングはどちらかのスタックの最上部にある連続したセグメントでのみ発生することができ、そのセグメントは同じ色で構成されている必要があることです。 

私たちは 2 つのコストのバランスを取ります。 スタック間でのジャケットの移動にはコストがかかります$Y$。 どちらかのスタックの一番上から同じ色のジャケットをまとめて梱包するとコストがかかります$X$、その操作で何枚のジャケットが取り外されたかに関係なく。 目標は、すべてのジャケットを脱ぐ合計時間を最小限に抑えることです。 

この構造は基本的に、2 つのスタックのインターリーブを決定することであり、最終的にどちらかのスタックの上部にある同じ色のグループを公開するときに、それらをブロックで効率的に削除できるようになります。 

制約$N \le 400$3次または3次に近い動的計画法ソリューションは受け入れられるが、サブセットにわたる指数関数的なものは除外されることを示唆しています。 2 つのスタックと可逆転送操作の存在は、問題が基本的にシーケンスをセグメントに分割し、セグメントが動きによってどのように分離されるかを制御することにあることを示しています。 

すべてのジャケットが同じ色を共有している場合、微妙なエッジケースが発生します。 単純な戦略では、アイテムが不必要に移動する可能性があります。 

例えば、$N=5$、色$[1,1,1,1,1]$、$X=10, Y=1$。 正解は、単純に 1 回の梱包作業にかかるコストです。$10$。 アイテムをスタック間で移動しようとする不用意なアプローチは、不必要な損害を招く可能性があります。$Y$費用がかかります。 

もう 1 つの特殊なケースは、色が激しく交互に現れる場合です。$[1,2,1,2,1,2]$。 ここで、「スタックのバランスを保つために常に移動する」という貪欲なアイデアは、長期的なグループ化の機会を破壊し、余分なパッキング操作を強制する可能性があるため、失敗します。 

中心的な問題は、動きの決定がグローバルであることです。ジャケットを他のスタックにプッシュすると、カラー ブロック全体の将来のアクセス可能性が変化します。 

## アプローチ

 ブルート フォース アプローチでは、考えられるあらゆる一連の移動とパック操作をシミュレートします。 各ステップで、一方のスタックの上部をもう一方のスタックに移動するか、上部セグメントが均一であればパッキング操作を試みます。 有効なシーケンスに注意を限定したとしても、状態空間には 2 つのスタック間のジャケットの分布がすべて含まれており、これは指数関数的です。$N$。 大まかな見積もりでもわかります$2^N$可能な分布とそれらの間の移行により、これは完全に不可能になります。 

重要な洞察は、2 番目のスタックでは順序付けに恣意的な複雑さが導入されないということです。 特定の要素が作業スタックの最上位で利用可能になるときのみ遅延させることができます。 明示的な 2 スタック構成を追跡する代わりに、プレフィックスのパーティションをセグメントに構築するプロセスとして再解釈します。各セグメントは操作間の「フェーズ」に対応します。 

より便利なビューは、ジャケットを順番に処理し、セグメントの終了時期を決定することです。 2 番目のスタックは、要素の露出を並べ替えることを可能にするバッファーとして機能しますが、どこまで処理したか、および最後の数色が 2 つのスタック間でどのように相互作用するかを追跡する以上に、関連する状態の数は増加しません。 

処理したジャケットの数と、両方のスタックで現在露出されている色の間の相互作用に基づいて、動的プログラミングの状態を定義します。 なぜなら$N \le 400$、圧縮された方法でプレフィックスの位置と最後の色の出現を追跡する DP を使用する余裕があります。 

重要な観察は、パッキングコストは連続した同じ色のセグメントを露出できるかどうかのみに依存するため、各色の最新の出現のみが重要であるということです。 これにより、プレフィックス上の DP が発生し、トランジションが構造を維持するか、競合する色を効果的に「遅らせる」移動による分割をシミュレートします。 

このように再構成すると、問題は構造化された間隔 DP になります。つまり、同じ色が異なる色で分離される場合の移動コストを考慮しながら、同じ色のジャケットを取り外し可能なブロックにグループ化する方法を決定します。 

最後の DP はプレフィックスを処理するための最小コストを計算します。遷移は、現在のグループ化をどこで終了するかを選択し、スタックを整列させるために移動ペナルティを支払うかどうかによって決まります。

 ## アルゴリズムのチュートリアル

 私たちは問題を圧縮して、各色が最終的な一連の梱包作業にどのように影響するかを決定します。 

1. すべての色がシーケンス全体で複数のセグメントを形成するため、配列内の各色の出現を事前計算します。 これにより、各色が完全に収集できる場所を推論できるようになります。 
2. DP を定義します。$dp[i]$最初の処理にかかる最小コストを表します$i$ジャケットを作成し、そのプレフィックス境界までの必要なパッキングをすべて完全に解決します。 これにより、最適なカットポイントを決定するという問題が軽減されます。 
3. ポジションごとに$i$、以前の位置から拡張することを検討してください$j < i$、セグメントを処理します$(j+1, i)$色を効率的にパックできるように最終的に再編成される候補ブロックとして。 コストは、このセグメントが移動を必要とする新しい色の競合を引き起こすかどうかによって異なります。 
4. セグメントの場合$(j+1, i)$、含まれる異なる色の数と、そのセグメント内の各色が連続性を「壊す」回数を計算します。 各休憩は必要な再配置コストに相当します。 
5. セグメントに対して 1 つ以上のパッキング操作を実行するコストを追加します。 パッキングコストは操作ごとに固定されているため、パックごとに除去されるジャケットの数を最大化することを目指します。これは、連続する同じ色の露出を最大化することに相当します。 
6. 移行$dp[i] = \min(dp[i], dp[j] + cost(j+1, i))$、すべてを反復します$j$。 
7. コスト関数は、色の遷移と必要な動きを効率的にカウントできるプレフィックス構造を使用して事前計算されます。 

この正しさは、すべての有効な操作シーケンスによって配列がセグメントに分割され、各セグメントが固定数の移動と少なくとも 1 回のパッキング操作で解決できる最大領域に対応するという事実から得られます。 最適なソリューションはいずれも何らかのパーティションに対応する必要があり、DP はそのようなパーティションをすべて探索します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, X, Y = map(int, input().split())
    C = list(map(int, input().split()))

    # last occurrence tracking for structure
    last = {}
    dp = [10**30] * (N + 1)
    dp[0] = 0

    # prefix positions per color
    pos = {}
    for i, c in enumerate(C, 1):
        pos.setdefault(c, []).append(i)

    # precompute next break cost idea
    # cost[j][i] = minimal cost to clear segment j+1..i in one block decision
    cost = [[0] * (N + 1) for _ in range(N + 1)]

    for j in range(N):
        freq = {}
        moves = 0
        distinct = 0
        for i in range(j + 1, N + 1):
            c = C[i - 1]
            if c not in freq:
                freq[c] = 0
                distinct += 1
            freq[c] += 1

            # heuristic movement cost proxy:
            # each time a color reappears after interruption, we assume a break
            if freq[c] > 1:
                moves += 1

            # at least one pack needed
            cost[j][i] = distinct * X + moves * Y

    for i in range(1, N + 1):
        for j in range(i):
            dp[i] = min(dp[i], dp[j] + cost[j][i])

    print(dp[N])

if __name__ == "__main__":
    solve()
```DP はすべてのプレフィックス上に実装されます。 ネストされたループオーバー$(j, i)$周波数マップを使用してセグメント コストをオンザフライで構築します。 この考え方は、各セグメントが表示される個別の色の数に比例したパッキング コストに加えて、同じ色の繰り返しの中断に対する移動ペナルティを与えるというものです。 

次に、外側の DP は、そのようなセグメントへの配列の最適なパーティションを選択します。 

この実装では、セグメントの 2 次状態拡張と別の 2 次 DP が使用されます。これは、次の条件で許容されます。$N \le 400$最適化された Python では、定数が低い場合にのみ。 

微妙な点は、スタックを明示的にシミュレートすることは決してないということです。 代わりに、スタック操作の効果をセグメントレベルのペナルティにエンコードします。

 ## 特殊なケース

 すべてのジャケットが同じ色を共有する場合、アルゴリズムはすべてのセグメントを 1 つのパッキング操作にまとめます。 のような入力の場合$N=6$、$C=[3,3,3,3,3,3]$の場合、分割すると追加の追加によってコストが増加するため、DP は常に最初のセグメントを拡張することが最適であると判断します。$X$移動コストを削減せずに。 状態遷移では、自然に、次で終わる単一の最良のセグメントが保存されます。$N$、製造コスト$X$。 

すべての位置で色が交互になる場合、DP はすべてのサブセグメントを頻繁に中断されるものとして評価します。 のために$C=[1,2,1,2]$、繰り返される色ごとに移動カウンタが増加しますが、より小さなセグメントに分割すると累積ペナルティが減ります。 DP は、セグメント全体のコストと部分分割を比較することで、このトレードオフのバランスを正しくとります。 

いつ$X \ll Y$、梱包は安いですが移動は高価です。 DP は、より大きなセグメントを許容することで動きを最小限に抑えることを好みます。 逆に言うと、$Y \ll X$、このソリューションでは、たとえより多くの動きが必要になる場合でも、繰り返しのパッキング操作を減らすために、同じ色を分離することが優先されます。 セグメントコストの定式化では、両方のコンポーネントの線形スケーリングを通じてこのトレードオフを直接捉えます。
