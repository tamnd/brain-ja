 ## 解決策
 ## 問題の理解

 いくつかの数値行が与えられ、各行は 1 から M までの時間位置にわたる一連の報酬を表します。正確に M − K + 1 個のアクションを実行します。各アクションは、左から右に移動する K 個の連続する位置のスライディング ウィンドウに関連付けられます。 

p 番目のアクションでは、N 行のうち 1 つを選択し、その行の p から p + K − 1 までのインデックスにわたるウィンドウ内の未使用の要素を選択する必要があります。 その価値を利益として取り、永久にゼロにするので、後で再び使用することはできません。 目標は、収集された合計値を最大化するために、すべての行およびすべてのウィンドウにわたってこれらの選択をスケジュールすることです。 

この構造は、自明ではない方法で相互作用する 2 つの制約を強制します。 まず、各ウィンドウでは、限られた範囲内でのみ選択が可能です。 次に、選択すると削除されるため、各位置はグローバルに 1 回しか使用できません。 課題は、大きな値を選択することだけでなく、後で使用できない位置で貴重な要素を「無駄に」しないようにすることです。 

制約は、意図された複雑さについての強力なヒントを与えます。 行の数は少なく、最大 10 ですが、長さ M は 100000 に達する可能性があります。ウィンドウ サイズ K も小さく、最大 10 です。これは、行に対する列ごとの重い DP が可能であることを示唆していますが、各要素を個別に処理したり、すべてのウィンドウで選択をシミュレートしたりするソリューションは遅すぎます。 

単純な考えは、すべての操作を独立して処理し、各ウィンドウで利用可能な最適な値を貪欲に選択することです。 これはすぐに失敗します。値を選択すると、将来のすべてのウィンドウでその値がブロックされ、初期の貪欲な決定により、後で必要になる要素が削除される可能性があるためです。 

たとえば、K = 2 で行が 1 つある場合:```
[5, 100, 4]
```p = 1 では、ウィンドウは [1,2] です。 貪欲な選択では、位置 2 で 100 が選択されます。p = 2 では、ウィンドウ [2,3] に位置 3 だけが残り、4 が得られます。合計は 104 になります。しかし、最適なのは、p = 1 で 5 を選択し、p = 2 で 100 を選択し、105 が得られます。貪欲な戦略は、将来のウィンドウ制約を考慮していないため失敗します。 

したがって、各セルが最大 1 回使用されることを考慮しながら、スライディング ウィンドウ全体でグローバルに推論するメソッドが必要です。 

## アプローチ

 主な問題点は、各位置 j が連続した演算範囲内でのみ適格であることです。位置 j は、ウィンドウ p 中に p ≤ j ≤ p + K − 1 となるように選択できます。これは p ∈ [j − K + 1, j] と同等です。 これは、各セルには、それを取得できるタイムスロットの制限された間隔があることを意味します。 

「ウィンドウごとに行ごとに 1 つ」の相互作用を無視すると、問題はタイム ウィンドウで項目を選択することに似てきます。この場合、各項目は複数のタイム スロットの 1 つに割り当てることができ、各タイム スロットの行全体にわたる容量は限られています。 

ブルートフォース解釈では、ウィンドウ条件を満たし、まだ使用されていないすべての有効な (行、列) ペアの中から、M − K + 1 の各演算に選択肢を割り当てようとします。 各操作は最大 10 × 10 = 100 の候補から選択でき、最大 100,000 の操作があるため、これは指数関数的な分岐係数につながります。 初期の選択はその後の可用性に複雑な方法で影響するため、枝刈りさえも役に立ちません。 

主な観察点は、操作を明示的にシミュレートする必要がないということです。 代わりに、視点を逆にすることができます。各列 j について、それがどの操作で使用されるか、または同等に、その列をカバーするウィンドウに寄与するかどうかを決定します。 

K ≤ 10 であるため、各列は少数のウィンドウのみと対話します。 この制限された対話により、列を順番に処理し、ウィンドウ カバレッジがまだ残っている前の列からどれだけのピックが「オープン」であるか、または利用可能であるかを示す小さな状態のみを維持することができます。 

列を左から右に処理します。 列 j では、演算 max(1, j − K + 1) から始まる任意の値 A[i][j] が適格になります。 j を渡すと、最大 K ステップまで資格が残ります。 この制限された有効期間により、各行構成のアクティブなウィンドウから取得できるピックの数を状態が追跡する DP を維持することができます。 

これをエンコードする標準的な方法は、各列をサイズ N のベクトルに寄与するものとして扱うことです (N ≤ 10 であるため)。 各ステップで、この列から取得する要素の数を決定しますが、重複するウィンドウ構造で使用できる操作の合計数を超えないようにする必要があります。 

より具体的で実装可能なビューは次のとおりです。列を左から右に処理し、現在のウィンドウ スパンから取得した項目の数を表す行のサブセットにわたる DP を維持します。 N が小さいため、列の各行から取得する要素の数を表しますが、重要なことに、各列は将来の K 回の操作にのみ影響するため、遷移は最後の K 列のみに依存します。 

したがって、DP 状態は決定の最後の K 列を圧縮します。 K 個のアクティブな「タイム レイヤー」のそれぞれについて、各行に割り当てられたピックの数を追跡します。 K ≤ 10 および N ≤ 10 であるため、状態サイズはビットマスクまたはタプル エンコードを使用して管理できます。 

このウィンドウを一度に 1 ステップずつシフトし、各列で行間で操作ごとに 1 つの項目を選択する実行可能なすべての分布を試し、各行はセルごとに複数回選択できないこと、および各操作で 1 つの項目を正確に選択することを考慮しながら、選択された値の合計を最大化します。 

最適化は、列と行ごとに値を事前計算してから、ビットマスク遷移を備えた DP を使用してウィンドウ位置ごとに最適な割り当てを選択することで実現します。 これは事実上、幅が狭いスライディング ウィンドウ割り当て問題です。

## アルゴリズムのチュートリアル

 1. 各列 j を、長さ K の連続した操作間隔で使用可能になるアイテムとして解釈します。これにより、視点を操作から列に移すことができます。 
2. 各位置 j について、行全体のすべての値 A[i][j] を計算します。 これらは、スライディング ウィンドウで列 j が「アクティブ」である場合に使用できる候補です。 
3. 最後の K 列について、行ごとに割り当てられたピックの数を示す動的プログラミング状態を維持します。 これは、今後の操作でどの値がまだ使用できるかをエンコードします。 
4. 列を左から右に移動します。 各ステップで、ウィンドウ状態を前方にシフトし、列 j − K の寄与を削除し、列 j を導入します。 
5. 現在の列について、その寄与を利用可能な操作に割り当てる有効な方法をすべて試してください。 N と K は小さいため、ビットマスク サブセットを使用して、実行可能な行選択を効率的に列挙します。 
6. A[i][j] から選択した値を追加して DP 遷移を更新し、どの列も複数回使用されず、単一選択制約を超える操作がないことを保証します。 
7. すべての列を処理した後、完全にシフトされたウィンドウに対応する DP 状態は、達成可能な最大の合計を生成します。 

中心的な考え方は、各列が K 個の操作とのみ対話するため、グローバルな複雑さはすべて、小さな移動ウィンドウでのローカルな決定に集約されるということです。 

### なぜ効果があるのか

 いつでも、DP 状態は、最後の K 列からどの値がまだ選択できるのか、およびそれらの値に対して残りの操作スロットがいくつ存在するのかを完全に記述します。 すべての遷移は、現在の列値をこれらのスロットに一貫して割り当てることに対応します。 K ステップを超えて適格な値が存在しないため、将来の決定は K 列前より前の値に依存することはできません。 この制限された依存関係により、DP が古い決定を再検討する必要がなくなり、すべての最適なグローバル ソリューションをスライディング ウィンドウ上で局所的に最適な遷移のシーケンスに分解できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M, K = map(int, input().split())
    A = [list(map(int, input().split())) for _ in range(N)]

    # dp[state] = best value
    # state encodes last K columns' usage as a tuple compressed into a dict
    from collections import defaultdict

    dp = {(): 0}

    for j in range(M):
        ndp = defaultdict(lambda: -10**30)

        col_vals = [A[i][j] for i in range(N)]

        for state, val in dp.items():
            # state represents last K columns; we shift it
            new_state_base = state[-(K-1):] if K > 1 else ()

            # we try selecting a subset of rows for this column
            # each row can be chosen at most once in this column
            for mask in range(1 << N):
                chosen_sum = 0
                cnt = 0
                ok = True

                for i in range(N):
                    if mask & (1 << i):
                        chosen_sum += col_vals[i]
                        cnt += 1
                        if cnt > 1:
                            ok = False
                            break

                if not ok:
                    continue

                # we only allow at most 1 pick per column
                if cnt != 1:
                    continue

                # transition
                new_state = new_state_base + (mask,)
                ndp[new_state] = max(ndp[new_state], val + chosen_sum)

        dp = ndp

    print(max(dp.values()) if dp else 0)

if __name__ == "__main__":
    solve()
```この実装では、最後の K 列の決定を表す DP 状態の辞書が圧縮形式で保持されます。 各列では、状態ウィンドウをシフトし、その列の選択された値として 1 行だけを割り当ててみます。これは、各操作が変換されたビューの列ステップごとに 1 つの値を効果的に消費するためです。 

ビットマスク列挙は、各列にどの行が寄与するかを選択するために使用されます。 N ≤ 10 であるため、これは実現可能です。 

状態の切り捨て`state[-(K-1):]`将来の実現可能性にとって最後の K 列のみが重要であるというスライディング ウィンドウ制約を強制します。 

## 実用的な例

 N = 2、M = 3、K = 2 の小さなインスタンスを考えてみましょう。```
A =
[ [5, 1, 10],
  [4, 8, 2] ]
```各列の後に DP の状態を追跡します。 

### 列 1

 | 状態 | 値 | 選択された行 | 遷移値 |
 | --- | --- | --- | --- |
 | () | 0 | 行 1 (5) | 5 |
 | () | 0 | 行 2 (4) | 4 |

 列 1 の処理後:

 dp = { (行 1): 5、(行 2): 4 }

 ### 列 2

 | 前の状態 | 選択された行 | 値 | 新しい状態 | 合計 |
 | --- | --- | --- | --- | --- |
 | (行1) | 行2 | 8 | (行1、行2) | 13 |
 | (行1) | 行1 | 1 | (行1,行1) | 6 |
 | (行2) | 行1 | 1 | (行2、行1) | 5 |
 | (行2) | 行2 | 8 | (行2,行2) | 12 |

 最良の状態は最後の K=2 列を追跡します。 

これは、さまざまな行の選択がどのように伝播されるか、および DP がウィンドウ関連の履歴のみをどのように保持するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(M · 2^N) | 列ごとに行のサブセットを列挙します。 N ≤ 10 |
 | スペース | O(2^N・K) | DP 状態は最後の K 個の選択肢を保存します。 

M が 100000 まで、N が 10 までの制約により、2^10 = 1024 となるため、これが実現可能になります。そのため、列ごとの DP 遷移は 2 秒の制限に対して十分に小さいままです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、K = 1 の場合です。この場合、各操作ではインデックス p を正確に選択することしかできないため、問題は列ごとに 1 つの要素を個別に選択することになります。 DP はウィンドウ履歴を保持しようとすべきではなく、最適な解決策は行全体にわたる列ごとの最大値を単純に合計することになります。 

すべての行に同じ値が含まれている場合、別の特殊なケースが発生します。 アルゴリズムは、1 回の操作で複数の行にわたって同じ値を何度も過剰にカウントすることを避ける必要があります。 DP は、列状態ごとに 1 つの行を正確に選択することでこれを強制し、重複がないことを保証します。 

3 番目のエッジ ケースは、M が小さいが K が大きい (M に等しい) 場合です。 これにより、プロセス全体を通じてすべての列が使用できるようになり、順序の制約がなくなりました。 DP では、列全体での選択の順列が正しく許可されており、最適な戦略は、操作の数によって制限された最大の N × M 値を選択することになります。
