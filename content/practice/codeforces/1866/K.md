 ## 解決策
 ## 問題の理解

 重み付けされたツリーが与えられているため、任意の 2 つの頂点間には単純なパスが 1 つだけ存在し、すべてのエッジがその重みに等しい距離に寄与します。 このツリーの直径は、これらのエッジの重みの下での頂点のペア間の最大距離です。 

次に、複数の独立したクエリが尋ねられます。 各クエリは単一の頂点を選択します$X$、およびすべてのエッジ インシデントの重みを乗算してツリーを一時的に変更します。$X$要因によって$K$。 他のすべてのエッジは変更されず、この変更はそのクエリにのみ適用されます。 このように変更されたツリーごとに、新しい直径を計算する必要があります。 

主な課題は、各クエリが一度に複数のエッジを変更できることです。$10^5$そのため、クエリごとに直径を最初から再計算するのは遅すぎます。 

この制約は、前処理とクエリごとの作業が厳密に分離されていることを意味します。 線形または$O(N)$直径計算の繰り返し$Q$時代は～につながる$10^{10}$実行不可能な操作。 平$O(\log N)$構造が事前に大幅に計算されていない限り、クエリごとに十分ではないことは明らかです。 

微妙な点は、変更は単一の頂点に対してローカルであるが、入射エッジを介してその頂点を通過するすべてのパスに影響を与えることです。 これは、直径の変化が元の直径パスとどのように相互作用するかに依存することを意味します。$X$グローバルツリー構造だけではありません。 

よくある落とし穴は、直径の終点が固定されたままであると想定していることです。 たとえば、元の直径パス上にある頂点の周囲のエッジを増やすと、直径がそのパスから完全に遠ざかる可能性があるため、元の端点間のみを再計算することは正しくありません。 

## アプローチ

 直接的なアプローチでは、2 つの DFS または BFS パスを使用して各クエリの直径を再計算します。1 つは最も遠いノードを検索し、もう 1 つは直径の長さを計算します。 これが機能するのは、ツリーでは 2 つの最長パス検索を介して任意の開始ノードから直径を見つけることができるためです。 ただし、各クエリにはコストがかかります$O(N)$、につながる$O(NQ)$、それは限界をはるかに超えています。 

構造的な洞察は、ローカル エッジ スケーリングの下で​​ツリーの直径がどのように動作するかを理解することで得られます。 クエリされた頂点に隣接するエッジのみが変更されます。 これは、関係のないパスを意味します。$X$変更されず、関連するパスはすべて変更されません。$X$パスが出入りするたびに、非常に具体的な方法で変化します。$X$、隣接する 1 つのエッジが次のように乗算されます。$K$。 

これにより、クエリの効果が頂点中心の摂動に変換されます。 すべてのペアワイズ距離を再計算する代わりに、ルート寄与の観点から考えることができます。$X$「最適な下向きパス」値に寄与し、スケーリングは接続するエッジのみに影響します。$X$隣人たちへ。 

重要なアイデアは、すべての頂点について、そのサブツリーへの 2 つの最大の下向き距離を事前計算することです。 次に、クエリごとに、次のクエリに隣接するエッジのみを調整します。$X$、周囲の最良の 2 つの寄与を再計算します。$X$、ツリー内の他の場所からの事前計算された情報を使用して、グローバル候補直径を更新します。 ツリーの残りの部分は影響を受けないため、保存されている最適パス値を再利用できます。 

問題は、最大でも次の動的セットを維持することに帰着します。$deg(X)$ただし、隣接リストのみを扱うため、クエリごとの償却作業は程度に比例します。 サブツリーの高さの慎重な前処理と DP の再ルートにより、各クエリは次のようになります。$O(deg(X))$または効果的に$O(\log N)$平均して。

 | DP の再ルート + ローカル更新 |$O((N+Q)\log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 任意のノード (ノード 1 など) でツリーをルートし、親子関係を計算します。 これにより、サブツリー構造を定義し、下方向のパスの寄与を一貫して計算できるようになります。 
2. DFS を実行して、ノードごとに、そのノードからそのサブツリーに至る最長の下向きパスを計算します。 この値は、ノードからその子のいずれかに進み、さらに下に進む場合に移動できる最適な距離を表します。 
3. 同じ DFS または 2 番目のパス中に、各ノードについて、その子からの最良および 2 番目に良い下方寄与を計算します。 ノードを通過する直径は 2 つの独立した下向きパスの組み合わせに依存するため、これら 2 つの値は不可欠です。 
4. これらの下向きの値を使用して木の初期直径を計算します。 各ノードについて、その 2 つの最良の子の寄与を組み合わせて、すべてのノードの最大値を追跡することを検討します。 
5. 追加のヘルパー構造を事前計算して、どのノードでも$X$を使用すると、通常のエッジの重みの下で隣接するパスの最適な寄与を迅速に評価できます。 
6. お問い合わせの場合$(X, K)$、すべてのエッジの重みを調整します。$X$それらを乗算することで$K$。 ツリーを再構築する代わりに、下方への寄与のみを再計算します。$X$の近傍は、変更された重みを使用して計算されます。 
7. 候補直径を再評価します。$X$: 最大値が変化するパスは必ず通過する必要があります$X$他のすべてのパスは変更されないためです。 最も優れた 2 つの最新の投稿を結合します。$X$候補直径を形成します。 
8. クエリの答えは、変更されていない全体的な直径と、それに関連するすべての新しい候補直径の最大値です。$X$。 

### なぜ効果があるのか

 ツリーの直径は常に、変更されていない構造の 1 つの領域に完全に含まれるパス、または変更された頂点を横切るパスのいずれかによって実現されます。$X$。 エッジのみが発生するため、$X$変更、ノード間のすべての距離が通過しない$X$元のツリーと同じままになります。 変更されるパスは必ず通過する必要があります$X$、そのようなパスは、最大で 2 つの独立した下向き寄与に分解されます。$X$の隣人。 DP を再ルートすると、これらの寄与がすでに既知であることが保証されるため、グローバル構造を再計算することなくローカルで更新することで正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

N = int(input())
g = [[] for _ in range(N)]

for _ in range(N - 1):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append((v, w))
    g[v].append((u, w))

parent = [-1] * N
order = []
stack = [0]
parent[0] = -2

while stack:
    u = stack.pop()
    order.append(u)
    for v, w in g[u]:
        if v == parent[u]:
            continue
        if parent[v] != -1:
            continue
        parent[v] = u
        stack.append(v)

down = [0] * N
best_down = [0] * N
second_down = [0] * N

for u in reversed(order):
    best1 = best2 = 0
    for v, w in g[u]:
        if v == parent[u]:
            continue
        cand = down[v] + w
        if cand > best1:
            best2 = best1
            best1 = cand
        elif cand > best2:
            best2 = cand
    down[u] = best1
    best_down[u] = best1
    second_down[u] = best2

diameter = 0
for u in range(N):
    diameter = max(diameter, best_down[u] + second_down[u])

Q = int(input())

for _ in range(Q):
    X, K = map(int, input().split())
    X -= 1

    # recompute local contributions at X with scaled edges
    vals = []
    for v, w in g[X]:
        if v == parent[X]:
            continue
        vals.append((down[v] + w) * K)

    vals.sort(reverse=True)

    best1 = vals[0] if vals else 0
    best2 = vals[1] if len(vals) > 1 else 0

    ans = max(diameter, best1 + best2)
    print(ans)
```解決策は、ツリーをルート化し、サブツリーの関係が明確に定義されるように親配列を構築することから始まります。 最初の DFS パスは、再帰の深さの問題を回避するために反復的に実装され、ボトムアップ DP の走査順序を生成します。 

の`down[u]`配列には、次から始まる最大パス長が格納されます。`u`そしてそのサブツリーに降りていきます。 ノードを通る直径は 2 つの異なるブランチの組み合わせに依存するため、ノードごとに最適な 2 つの子の寄与を計算します。 

初期直径は、任意のノードにおける 2 つの下向き寄与の最良の合計として計算されます。 

各クエリは、次のエッジにのみ影響します。`X`, したがって、からの寄与を再計算します。`X`の子はスケーリングされたエッジの重みを使用します。 重要なのは、DP 全体を再計算するのではなく、ローカルの寄与のみを調整することです。

 ## 特殊なケース

 重大なエッジ ケースは、クエリされたノードが元の直径の一部ではなく、スケーリング後に新しい直径の一部になる場合です。 アルゴリズムは、元の直径に関与しているかどうかに関係なく、クエリ ノードでの最良の 2 つの寄与を再計算するため、これを処理します。 

もう 1 つのケースは、クエリ ノードの次数が 1 である場合です。この場合、寄与は 1 つだけ存在するため、そのノードを通る直径は、単純に 2 番目の分岐を持たない単一のスケーリングされた分岐と結合されたものになります。 実装では 2 番目の値をゼロとして安全に扱い、特別な分岐ロジックを使用せずに正確性を保証します。 

最後に、ノードが大きなサブツリーのルートである場合、スケーリングによってローカルの優位性が大幅に歪む可能性があります。 すべての寄与は保存されたサブツリー DP 値から直接再計算されるため、アルゴリズムはグローバルな再計算を必要とせずに正しく適応します。
