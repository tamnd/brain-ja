 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$頂点。 その中で、$m$特別な頂点には花が含まれます。 

多くても花を取り除くことがあります$k$それらの特別な頂点の。 削除後、花の咲いた頂点がいくつか残ります。 ツリー内のすべての頂点について、最も近い残りの花までの距離を考慮します。 すべての頂点の中で、その距離が最大となるものをとります。 

私たちの目標は、この最大距離ができるだけ大きくなるように、削除する花を選択することです。 

ツリーには以下が含まれます$10^5$花の頂点の数も最大です$10^5$。 すべての花から BFS または DFS を繰り返し実行するソリューションは、直ちに除外されます。 たとえ$O(nm)$アルゴリズムには次のようなものが必要です$10^{10}$最悪の場合の運用。 

重要な問題は、距離を最小化していないことです。これは、通常のマルチソース BFS の問題です。 削除後に残るすべての花から可能な限り離れた場所をツリー内に配置しようとしています。 

最適な場所自体が花の咲く頂点である場合、微妙なエッジケースが現れます。 

例：```
1 - 2 - 3
flowers: {2}
k = 0
```答えは 1 で、頂点 1 と 3 で得られます。花以外の頂点のみをチェックする解決策では、有効な候補を見逃してしまいます。 

もう 1 つのエッジケースは、選択した場所の近くの花を正確に削除する場合です。 

例：```
1 - 2 - 3 - 4 - 5
flowers: {2,4}
k = 1
```2 で花を削除すると、頂点 1 は最も近い残りの花からの距離 3 になります。 選択した場所から最も遠い花を常に削除するという貪欲な戦略は間違っています。 

3 番目のエッジ ケースは、複数の花が同じ半径内にある場合に発生します。 

例：```
1 - 2 - 3 - 4 - 5
flowers: {2,3,4}
k = 2
```半径をチェックするには、花が存在するかどうかだけでなく、その半径内に花が何本あるかをカウントする必要があります。 

## アプローチ

 まず最初に役立つのは総当たりビューです。 

答えの候補を修正するとします$D$。 最も近い残りの花が厳密に よりも大きい頂点を取得できるかどうかを尋ねます。$D$。 

頂点を選択します$v$。 遠くにあるすべての花$D$から$v$取り除かなければ、その花はまだ花に近すぎて残ってしまいます。$v$。 

させて$$cnt(v)=\text{number of flowered vertices within distance }D\text{ from }v.$$もし$cnt(v)\le k$、これらの花をすべて削除できます。 余分な削除は他の場所に費やすことができます。 そうすれば、残ったすべての花は、$D$から$v$。 

したがって、実現可能性の問題は次のようになります。$$\exists v \text{ such that } cnt(v)\le k.$$ブルートフォースメソッドは次のように計算します。$cnt(v)$すべての頂点とすべての半径について、ツリーを探索して確認します。 実現可能性テストを 1 つ行うだけでも、費用がかかりすぎます。 

問題を解決する観察は、すべての実現可能性テストで、距離半径内にある花の咲いた頂点の数だけを求めているということです。 これはまさに、重心分解が効率的に処理する種類のクエリです。 

固定半径の場合$D$、各花は、その花までの距離が最大以下のすべての頂点に +1 を与えます。$D$。 すべての寄与が追加された後、頂点の値は次と等しくなります。$cnt(v)$。 

重心分解により、任意の頂点についてカウントできるようになります。$v$、距離内に花の咲いた頂点がいくつあるか$D$の$v$で$O(\log^2 n)$時間。 

実現可能性は単調なので、距離があれば$D$が達成可能であれば、さらに小さな距離も達成可能です。 これにより、答えが二分探索されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nm)$小切手ごと |$O(n)$| 遅すぎる |
 | 重心分解 + 二分探索 |$O(n\log^2 n\log n)$|$O(n\log n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 前処理

 ツリーの重心分解を構築します。 

頂点ごとに、重心の祖先のチェーンを保存します。 祖先重心ごとに、以下を保存します。 

1. 頂点からその重心までの距離。 
2. 頂点が属する重心の子サブツリー。 

すべての重心について、花の咲いた頂点からその重心までのすべての距離も保存します。 

すべての重心の子サブツリーについて、そのサブツリー内の花の咲いた頂点から重心までのすべての距離を保存します。 

これらすべての距離リストはソートされています。 

### 半径 D の実現可能性チェック

 1. 頂点ごとに$v$、花の数をゼロとして初期化します。 
2. の重心祖先チェーンをたどります。$v$。 
3. 現在の重心を次のようにします。$c$、そしてさせてください$d=\text{dist}(v,c)$。 
4. 距離のあるすべての花$c$せいぜい$D-d$答えに貢献します。 

花の重心の距離のソートされたリストに対する二分探索の使用$c$、そのカウントを追加します。 
5. 両方とも数えられた花もありましたが、$v$そして花は同じ重心の子サブツリー内にあります。 それらの花はカウントから除外する必要があります。 

対応する子サブツリー リストを使用して、その寄与を差し引きます。 
6. すべての重心の祖先を処理した後、結果は距離内にある花の咲いた頂点の数と等しくなります。$D$の$v$。 
7. 頂点のカウントが最大の場合$k$、半径$D$実現可能です。 

### 二分探索

 1. 検索範囲を次のように設定します。$[0,n]$。 
2.中間距離を確認します。 
3. 可能であれば、右に移動します。 
4. それ以外の場合は左に移動します。 
5. 実現可能な最大距離が答えです。 

### なぜ効果があるのか

 固定半径の場合$D$、花が遠くにある場合に限り、花を取り除く必要があります。$D$選択した頂点から。 必要な削除の数は正確に$cnt(v)$。 

頂点は正確に次の場合に達成可能です$cnt(v)\le k$。 実現可能性テストでは、重心分解を使用してこの値を正確に計算します。 すべての花は重心祖先チェーンを通じて 1 回カウントされ、サブツリーの減算によりすべての過剰カウントが除去されます。 

実現可能性述語は単調です。 頂点をこれより遠くにできる場合は、$D$残っているすべての花から、それをより小さな半径よりも確実に遠くに作ることができます。 二分探索$D$有効です。 

## Python ソリューション```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

n, m, k = map(int, input().split())

g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

flowers = list(map(int, input().split()))
flowers = [x - 1 for x in flowers]

removed = [False] * n
sz = [0] * n

paths = [[] for _ in range(n)]
all_dist = []
sub_dist = []

def dfs_size(u, p):
    sz[u] = 1
    for v in g[u]:
        if v != p and not removed[v]:
            dfs_size(v, u)
            sz[u] += sz[v]

def dfs_centroid(u, p, tot):
    for v in g[u]:
        if v != p and not removed[v]:
            if sz[v] > tot // 2:
                return dfs_centroid(v, u, tot)
    return u

def collect(u, p, d, vec):
    vec.append((u, d))
    for v in g[u]:
        if v != p and not removed[v]:
            collect(v, u, d + 1, vec)

def build(entry):
    dfs_size(entry, -1)
    c = dfs_centroid(entry, -1, sz[entry])

    cid = len(all_dist)
    all_dist.append([])
    sub_dist.append([])

    paths[c].append((cid, 0, -1))

    child_id = 0
    for v in g[c]:
        if removed[v]:
            continue

        vec = []
        collect(v, c, 1, vec)

        sub_dist[cid].append([])

        for node, dist in vec:
            paths[node].append((cid, dist, child_id))

        child_id += 1

    removed[c] = True

    for v in g[c]:
        if not removed[v]:
            build(v)

build(0)

for f in flowers:
    for cid, dist, child in paths[f]:
        all_dist[cid].append(dist)
        if child != -1:
            sub_dist[cid][child].append(dist)

for vec in all_dist:
    vec.sort()

for groups in sub_dist:
    for vec in groups:
        vec.sort()

def count_near(node, D):
    res = 0

    for cid, dist, child in paths[node]:
        rem = D - dist

        if rem < 0:
            continue

        res += bisect_right(all_dist[cid], rem)

        if child != -1:
            res -= bisect_right(sub_dist[cid][child], rem)

    return res

def check(D):
    for v in range(n):
        if count_near(v, D) <= k:
            return True
    return False

lo, hi = 0, n

while lo < hi:
    mid = (lo + hi + 1) // 2

    if check(mid):
        lo = mid
    else:
        hi = mid - 1

print(lo)
```重心分解は一度構築されます。 すべての頂点について、重心の祖先を通るパスを、各重心までの距離および包含/除外に使用される子サブツリー識別子とともに記録します。 

配列`all_dist`すべての花から重心までの距離を保存します。 配列`sub_dist`特定の重心の子サブツリー内の花からの距離を保存します。 どちらも前処理中に 1 回ソートされます。 

機能`count_near(v, D)`距離内にある花の数を計算します`D`頂点から`v`。 各重心祖先は、次の二分探索カウントに寄与します。`all_dist`、一致するサブツリーの寄与が減算されます。 

実現可能性テストでは、一部の頂点が最大でも`k`削除。 そのような頂点が見つかるとすぐに、チェックは成功します。 

二分探索では述語の単調性を利用します。

 ## 特殊なケース

 次のことを考慮してください。```
3 1 0
1 2
2 3
2
```唯一の花は頂点 2 にあります。最も近い花までの距離は次のとおりです。```
vertex 1 -> 1
vertex 2 -> 0
vertex 3 -> 1
```答えは 1 です。 

半径チェック中$D=1$、すべての頂点は距離 1 以内の花をカウントします。カウントが 0 の頂点はないため、チェックは失敗します。 のために$D=0$、頂点 1 と 3 のカウントは 0 であるため、チェックは成功します。 アルゴリズムは正しい最大距離を返します。 

ここで次のことを考えてみましょう。```
5 2 1
1 2
2 3
3 4
4 5
2 4
```頂点 1 と半径 2 では、ちょうど 1 つの花が半径内にあります。 以来$k=1$、その花を削除するだけで十分です。 カウントが削除バジェットと等しいため、実現可能性テストは成功を報告します。 

ついに：```
5 3 2
1 2
2 3
3 4
4 5
2 3 4
```頂点 1 と半径 2 では、3 つの花すべてが半径内にあります。 カウントは3を超えます$k=2$。 禁止ゾーン内のすべての花は削除する必要があるため、アルゴリズムはこの半径を正しく拒否します。
