 ## 問題の理解

 ノード値を持つルート付きツリーが与えられます。 すべてのノードには整数ラベルが付けられており、ノード 1 がルートです。 クエリは 2 つのノードを選択します$s$そして$t$、 どこ$t$～の祖先であることが保証されている$s$、したがって、それらの間のパスは一意に上向きのパスになります。$s$に$t$。 

その上向きのパス上で、次から始まるノードを横断することを想像します。$s$。 最初は、次の値を「保持」します。$s$。 パスに沿って追加のノードを選択することで、持っているものを拡張することができますが、それは厳密なルールに基づいた場合に限られます。つまり、値が次のノードを取ることができます。$x$すでに値を持つノードがある場合のみ$x-1$。 各値は、収集されたセット内に最大 1 回出現できます。 

それで、からの道に沿って、$s$に$t$、次のようなチェーンを形成する値を持つノードのシーケンスを効果的に抽出しようとしています。$$a[s], a[s] + 1, a[s] + 2, \dots$$また、ノードはツリー パスに沿って上向きの順序で表示される必要があります。 クエリごとの目標は、次から始まる連続したバリュー チェーンの可能な最大長です。$s$そして完全にその道に留まります$t$。 

入力は、ツリー、ノードの値、およびこの形式の複数のクエリを記述します。 各クエリは、移行中に構築できる最長の「連続したバリュー チェーン」の長さを求めます。$s$上向きだが上を通らない$t$。 

複雑さの観点から見ると、ツリーのサイズが十分に大きいため、パスのクエリごとの走査を行うソリューションは遅すぎます。 単一のパスは次のとおりです。$O(n)$、多くのクエリが存在する可能性があるため、単純なアプローチでは次のような結果が得られます。$O(nq)$、これは受け入れられません。 各クエリが対数時間またはほぼ一定の時間で応答できるように、値と祖先の間の関係を事前計算する必要があります。 

正確性を保つためには、いくつかの特殊なケースが重要です。 

まれなケースとしては、拡張がまったく不可能な場合があります。 たとえば、パスが次の場合、$s \rightarrow t$そして先祖もいない$s$価値がある$a[s]+1$の場合、答えは常に 1 になります。単純な貪欲スキャンでは、誤ってノードをスキップしたり、パス上に存在しない値を「ジャンプ」しようとしたりする可能性があります。 

もう 1 つの微妙なケースは、チェーンは存在するが上に伸びている場合です。$t$。 からの完全な上向きチェーンを仮定します。$s$それを超えて続くだろう$t$、しかし、私たちは通過することを許可されていません$t$。 正しいソリューションでは、チェーンを正確に切り詰める必要があります。$t$、その上のノードはカウントしません。 

最後に、特定のパス上の先祖のみが関連するため、異なるブランチで同じ値が複数発生しても問題ありません。 祖先を無視し、グローバル値の隣接性のみを追跡するソリューションでは、誤ってオーバーカウントが行われます。 

## アプローチ

 直接的なアプローチは、各クエリを個別に処理することです。$s$到達するまで$t$、値を配列に収集し、から始まる連続増加シーケンスを形成する最長のプレフィックスを計算します。$a[s]$。 これが機能するのは、パスが明示的にわかっており、次の各値が順番に存在するかどうかを確認できるためです。 

ただし、各クエリでは、一定の長さのパスを走査する必要がある場合があります。$O(n)$。 多くのクエリがあると、最悪の場合の複雑さが生じます。$O(nq)$、両方の場合は遅すぎます。$n$そして$q$大きいです。 

重要な観察は、この構造が実際には任意のサブシーケンスに関するものではなく、決定論的な「値のジャンプ」に関するものであるということです。 任意のノードから$u$、次の有用なステップは最大でも 1 つだけです。$u$その値は$a[u] + 1$。 その祖先を効率的に知ることができれば、パス全体を、値シーケンスの意味で各ノードが最大 1 つの後続ノードを持つ機能チェーンに「圧縮」できます。 

これにより、ツリーの問題が関数グラフに近いものに変わります。つまり、すべてのノードが、ルート パスに沿った連続値チェーン内の次の有効なノードを指します。 このポインター構造が構築されると、クエリに答えることは、これらのポインターを上方向にどこまでたどることができるかをシミュレーションすることになり、上を通過した時点で停止します。$t$。 

主な困難は、これらの次のポインタを効率的に構築することです。 これは、ルートからの DFS 中に、現在のルートからノードへのパスに沿った値によってノードのスタック (またはスタックのマップ) を維持することで解決されます。 ノードに到着したら$u$、値を持つ最も近い祖先をすぐに見つけることができます。$a[u]+1$なぜなら、その値のスタックによって、パス上で現在どのノードがアクティブであるかが正確にわかるからです。 

この「ネクスト ポインター ツリー」を構築した後、各クエリが対数ステップでジャンプできるように、バイナリ リフティングを事前計算できます。

 ## アルゴリズムのチュートリアル

 まず、各ノードについて、連続値チェーンの次のステップがどこにあるかを示す構造を構築します。 

1. ルートから現在のノードへのパス上にあるノードのスタックに各値をマップするディクショナリを維持しながら、ルートから DFS を実行します。 

ノードに入るとき$u$に対応するスタックにプッシュします。$a[u]$。 これにより、いつでも、値のスタックの最上位が、その値に最も近い祖先 (それ自体を含む) になることが保証されます。 
2. 現在のノードの場合$u$、チェーン内でその後継者、つまり値を持つ最も近い祖先を見つけたいと考えています。$a[u] + 1$。 私たちはその積み重ねを見ます$a[u] + 1$。 空でない場合、その最上位要素はまさにそのような祖先に最も近いものになります。 以下を定義します。$$nxt[u] = \text{top of stack}[a[u] + 1]$$そのようなスタックが存在しない場合は、$nxt[u] = 0$。 

このステップでは、「祖先に沿った値の隣接性」をノードごとに 1 つのポインターに圧縮します。 
3. の子を処理した後$u$、私たちはポップします$u$値スタックから他のブランチの正しい状態を復元します。 これにより、スタックと現在の DFS パスの一貫性が保たれます。 
4. もう一度$nxt[u]$ポインタが構築されると、それらを各ノードが最大 1 つの出力エッジを持つ関数グラフとして扱います。 ジャンプできるようにバイナリリフティングテーブルを構築します$2^k$この連鎖に沿って素早く進みます。 
5. 各クエリについて$(s, t)$に沿って繰り返しジャンプします。$nxt$から始まるポインタ$s$、しかし、それ以上に移動しないようにしなければなりません$t$木の中で。 以来$t$の先祖です$s$、この条件は、訪問したノードに少なくとも深さがあることを要求するのと同じです。$\text{depth}[t]$。 

有効な深さの制約内に収まるように可能な限り最大のバイナリ ジャンプを貪欲に実行し、実行されたステップ数を累積します。 

### なぜ効果があるのか

 どのノードでも$u$の定義$nxt[u]$有効なチェーンが存在する場合、次に出現する値を正確に使用する必要があることを保証します。$a[u] + 1$。 同じ値を持つ他の祖先はより高く、パス順序で最も近いという要件を破り、それらの間に有効な中間値が存在できなくなります。 

これにより、チェーンが決定的になります。$s$の場合、ノードの選択に関して、可能な最大連続値パスが上向きに 1 つだけ存在します。 バイナリ リフティングでは、トラバースを高速化しながら、この決定性が維持されます。 深さ制約により境界が強制されます。$t$これにより、クエリ セグメント内にあるチェーンのプレフィックスのみが考慮されるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, q = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    parent = [0] * (n + 1)
    depth = [0] * (n + 1)

    nxt = [0] * (n + 1)

    from collections import defaultdict
    st = defaultdict(list)

    def dfs(u, p):
        parent[u] = p
        for v in g[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            dfs(v, u)

    dfs(1, 0)

    order = []

    def build(u, p):
        order.append(u)
        st[a[u]].append(u)

        val = a[u] + 1
        if st[val]:
            nxt[u] = st[val][-1]

        for v in g[u]:
            if v == p:
                continue
            build(v, u)

        st[a[u]].pop()

    build(1, 0)

    LOG = 20
    up = [[0] * (n + 1) for _ in range(LOG)]
    for i in range(1, n + 1):
        up[0][i] = nxt[i]

    for k in range(1, LOG):
        for i in range(1, n + 1):
            up[k][i] = up[k - 1][up[k - 1][i]]

    def query(s, t):
        limit = depth[t]
        cur = s
        ans = 1

        for k in reversed(range(LOG)):
            nx = up[k][cur]
            if nx and depth[nx] >= limit:
                cur = nx
                ans += 1 << k

        return ans

    for _ in range(q):
        s, t = map(int, input().split())
        print(query(s, t))

if __name__ == "__main__":
    solve()
```溶液は 2 つの相に分かれます。 DFS フェーズでは深さと親構造を構築し、次に 2 番目の DFS で`nxt`アクティブな値スタックを使用するポインター。 バイナリリフティングテーブル`up[k][u]`バリューチェーンに沿って迅速にジャンプすることができます。 

微妙な点は、クエリ内の深さチェックです。 強制せずに`depth[nx] >= depth[t]`、アルゴリズムは許可されたエンドポイントを喜んで超えてオーバーカウントします。 もう一つの詳細は、`nxt[u]`は機能エッジとして扱われるため、各ノードには出力遷移が 1 つしかないため、バイナリ リフティングは安全です。

## 特殊なケース

 値がパス上で分離されているノードなど、有効な拡張子が存在しない場合でも、DFS は引き続き`nxt[u] = 0`。 クエリでは、上向き遷移がないため、バイナリ リフティングは直ちに停止し、答えは 1 のままになります。 

完全な連続チェーンがクエリ境界を超えて拡張される場合$t$、深さの条件により、上を横切るジャンプがブロックされます。$t$。 このアルゴリズムは、深さが少なくとも次のノードのみをカウントします。`depth[t]`したがって、結果はチェーンの有効なプレフィックスに自動的に切り詰められます。 

複数のノードが異なるブランチで同じ値を共有する場合、現在の DFS パス スタックのみが表示されるため、`nxt[u]`常に正しい祖先を参照し、別のサブツリーのノードを参照することはありません。
