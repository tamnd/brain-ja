 ## 解決策
 ## 問題の理解

 ゲームは一連のボスで構成されています。 プレイヤーはすべての試みを完全な健康状態で開始し、すべてのボスを順番に倒す必要があります。 すべての健康を失うか、ボスによって即死されると、現在の試みは終了し、プレイヤーは最初からやり直す必要があります。 一定数のボスを倒すごとに、プレイヤーを完全な健康状態に戻すチェックポイントが存在する場合があります。 

各ボスの即死の可能性は、すでに失われた健康の量によって異なります。 プレイヤーが負けた場合`j`健康ポイント、即死確率は基本確率に次の値を乗算したものです。`x^j`。 プレイヤーが生き残った場合、さらに 1 つのヘルス ポイントを失う可能性があります。 タスクは、シーケンス全体をクリアするために必要な完全な試行の予想回数を見つけることです。 

入力により、ボスの数、初期体力、チェックポイント間隔、成長係数が得られます。`x`、各ボスの確率。 出力は予期される試行回数のモジュロです。`10^9 + 7`。 

制約から得られる重要な観察は次のとおりです。`n`そして`h`どちらも次のように大きくすることができます`5 * 10^4`。 すべてのボスとすべての可能な健康値に対する直接の DP は約`2.5 * 10^9`あまりにも多すぎる状態です。 ダメージを受けると即死の確率が指数関数的に増加するという事実を利用する必要があります。 

十分な体力が失われると、最も安全なボスでも確率 1 でプレイヤーを殺します。最小の即死確率は少なくとも`1%`そして`x`少なくとも`1.01`、有用な損傷状態の数はわずか数百です。 これにより、動的プログラミングの状態空間が大幅に減少します。 

見落としがちな特殊なケースがいくつかあります。 チェックポイントがない場合、ダメージは戦闘全体にわたって蓄積されます。 たとえば、次の入力を使用します。```
1 2 0 150
0
50
```ボスは完全な体力で確率でキルします`0.5`、そしてプレイヤーが生き残った場合、ダメージを受ける可能性はありません。 成功確率は`0.5`、したがって、答えは次のとおりです`2`。 すべてのボスの後に誤ってリセットされたソリューションでも、多くのテストには合格しますが、複数のボスが存在する場合は失敗します。 

もう 1 つのケースは、チェックポイントがボスの直後に来る場合です。 例えば：```
2 2 1 150
60 60
50 50
```最初のボスを倒した後、チェックポイントは 2 番目のボスの前に体力を回復します。 成功確率は`0.5 * 0.5 = 0.25`、したがって、答えは次のとおりです`4`。 ダメージを受けた状態をリセットせずにそのままにしておくと、誤って 2 番目のボスを難しいものとして扱うことになります。 

最後の厄介なケースは、ダメージによって体力がゼロになる場合です。 例えば：```
1 1 0 150
25
50
```プレイヤーは即死チェックを確率で生き残ることができる`0.5`、しかしその後ヘルスポイントを1つ失い、すぐに失敗します。 成功確率は`0.5 * 0.75 = 0.375`、答えを与える`8/3`必要な素数のモジュロ。 ヘルスゼロの失敗を無視すると、誤った結果が得られます。 

## アプローチ

 簡単なアプローチは、健康の損失を可能な限りあらゆる量でシミュレートすることです。 させて`dp[i][j]`最初の敵を倒した後に生き残る確率を表す`i`まさに上司`j`健康を失った。 すべてのボスに対して、ダメージを受けて生き残るか、ダメージを受けずに生き残るかの両方の結果を試します。 次のボスに必要な情報は現在のダメージ量だけであるため、この移行は正しいです。 

問題は状態空間のサイズです。 あり得る`n = 50000`上司と`h = 50000`考えられるダメージ値、`2.5 * 10^9`トランジション。 制限時間内では無理です。 

重要な観察は、大きなダメージ値は決して役に立たないということです。 プレイヤーの体力が減りすぎると、次のボスが確率 1 でプレイヤーを殺します。死亡確率は指数関数的に増加するため、有効な最大ダメージ値はわずか数百程度です。 

DP を圧縮して、到達可能な有用なダメージ量のみを保存できます。 遷移は同じままですが、2 番目の次元は小さな定数によって制限されます。 各チェックポイントの後、プレイヤーは回復するため、すべての生存状態は完全な状態にマージされます。 

予想される試行回数は、1 回の試行で成功する確率の逆数です。 成功確率が`p`、期待される独立した試行回数は次のとおりです。`1 / p`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nh) | O(h) | 遅すぎる |
 | 圧縮された健康状態による最適な DP | O(nC) | O(C) | 承認済み |

 ここ`C`有効な最大ダメージ数であり、指定された制限の場合は 500 未満です。 

## アルゴリズムのチュートリアル

 1. まだ存続できる損傷状態の最大数を計算します。 最も安全なボスであっても即死が保証されていないダメージ値のみを保持します。 これより大きな値は、実行の成功に寄与することはできません。 
2. DP 配列を維持します。`dp[j]`現在のボスに生きて到達する確率を保存します`j`健康を失った。 プレイヤーは最初は完全な健康状態にあるため、`dp[0] = 1`。 
3. ボスを 1 つずつ処理します。 ある状態の場合`j`体力を失った場合、即死判定で生き残る確率を計算します。 生存確率は`1 - p_i * x^j`。 
4. プレイヤーが生き残り、ボスがダメージを与えなかった場合、状態は同じダメージ量のままになります。 
5.プレイヤーが生き残ってダメージを受けると、ダメージ量が1増加します。 この移行は、新しいヘルスがまだ正であり、新しいダメージ量が有効な保存状態である場合にのみ許可されます。 
6. チェックポイント境界であるボスを処理した後、すべての生存状態確率を加算して戻します。`dp[0]`なぜなら、成功したすべての進歩は再び完全な状態に達するからです。 
7. 最後のボスの後、残りの確率をすべて合計します。 これは 1 回の試行を完了する確率です。 答えは、この確率の逆モジュールです。 

これが機能する理由: DP の不変条件は、ボスの接頭辞を処理した後、`dp[j]`という接頭辞の後に生きている確率を正確に表します`j`最後のチェックポイント以降に健康状態を失いました。 遷移は次のボスの考えられるすべての結果を列挙し、チェックポイント操作は治癒後に同一になる状態を正確にマージします。 ダメージが多すぎる状態は将来の成功に寄与する可能性がゼロであるため、それらを削除しても最終的な確率は変わりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, h, k, x0 = map(int, input().split())
    q0 = list(map(int, input().split()))
    p0 = list(map(int, input().split()))

    inv100 = pow(100, MOD - 2, MOD)
    x = x0 * inv100 % MOD

    # Compute the maximum useful damage states.
    mn = min(p0)
    limit = 0
    cur = mn
    while cur * x0 < 100:
        cur = cur * x0
        limit += 1
    limit += 1
    limit = min(limit, h)

    dp = [0] * limit
    dp[0] = 1

    for i in range(n):
        ndp = [0] * limit
        for j in range(limit):
            if dp[j] == 0:
                continue

            death = p0[i] * pow(x, j, MOD) % MOD * inv100 % MOD
            survive = (1 - death) % MOD

            if survive == 0:
                continue

            no_damage = (100 - q0[i]) * inv100 % MOD
            damage = q0[i] * inv100 % MOD

            ndp[j] = (ndp[j] + dp[j] * survive % MOD * no_damage) % MOD

            if j + 1 < limit:
                ndp[j + 1] = (ndp[j + 1] + dp[j] * survive % MOD * damage) % MOD

        dp = ndp

        if k != 0 and (i + 1) % k == 0:
            total = sum(dp) % MOD
            dp = [0] * limit
            dp[0] = total

    success = sum(dp) % MOD
    print(pow(success, MOD - 2, MOD))

if __name__ == "__main__":
    solve()
```すべての確率は整数のパーセンテージとして与えられるため、入力は整数として直接読み取られます。 の逆数を乗算して、確率をモジュラー分数に変換します。`100`。 

の`limit`計算が主な最適化です。 考えられる健康損失をすべて保存するのではなく、即死の確率が少なくとも 1 であることが保証された時点で停止します。 成長因子が少なくとも次の値であるため、ループは小さくなります。`1.01`。 

遷移では、最初に生存確率が適用されます。 生存後に考えられる 2 つの結果は、体力ポイントを 1 つ失うか、同じ体力を維持することです。 条件`j + 1 < limit`有効範囲を超えた状態は最後まで到達できないため、これが必要です。 

チェックポイント処理はボスを終了した後に行われます。 すべての健康喪失状態は治癒すると同一になるため、現在の確率は合計されます。 

問題が保証されているため、最終的な確率は決してゼロではないため、逆モジュールが存在します。 期待される試行回数は、1 回の試行が成功する確率の逆数です。 

## 実用的な例

 単純なケースの場合:```
1 1 0 150
25
50
```唯一のボスはフルヘルスの死亡確率を持っています`0.5`。 トレースは次のとおりです。 

| 上司 | 損傷状態 | | 前の確率 生き残る | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 1/2 | 体力 1 にダメージ、失敗 |

 プレイヤーは半分の確率でキルチェックを生き延びますが、体力が 1 つ失われると体力が 0 になるため、成功確率は次のようになります。`0.5 * 0.75 = 0.375`。 最終的な DP 合計は 1 回の実行が成功する確率であり、その逆数により期待される試行回数が得られます。 

チェックポイントの場合:```
2 2 1 150
60 60
50 50
```トレースは次のとおりです。 

| 上司 | 状態 | アクション | 確率 |
 | --- | --- | --- | --- |
 | 1 | 0ダメージ | ボスを生き残る | 0.5 |
 | 1 | 1 ダメージ | チェックポイントのリセット | 0ダメージに統合 |
 | 2 | 0ダメージ | ボスを生き残る | 0.5 |

 最初のボスの後は、成功したすべてのパスが修復されます。 2 つのボスは独立したフルヘルスの戦いなので、成功確率は`0.25`、答えを与える`4`。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nC) | 各ボスは圧縮されたダメージ状態のみを更新します。 
| スペース | O(C) | 現在と次の DP 配列のみが保存されます。 

値`C`は死亡確率の指数関数的な増加によって制限され、最大制約では数百を下回ります。 したがって、このソリューションは数百万回の操作のみを実行し、制限内に問題なく収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().split()
    sys.stdin = old

    if not data:
        return ""

    it = iter(data)
    n = int(next(it))
    h = int(next(it))
    k = int(next(it))
    x0 = int(next(it))
    q = [int(next(it)) for _ in range(n)]
    p = [int(next(it)) for _ in range(n)]

    MOD = 10**9 + 7
    inv100 = pow(100, MOD - 2, MOD)
    x = x0 * inv100 % MOD

    mn = min(p)
    limit = 0
    cur = mn
    while cur * x0 < 100:
        cur *= x0
        limit += 1
    limit += 1
    limit = min(limit, h)

    dp = [0] * limit
    dp[0] = 1

    for i in range(n):
        ndp = [0] * limit
        for j in range(limit):
            death = p[i] * pow(x, j, MOD) % MOD * inv100 % MOD
            survive = (1 - death) % MOD
            no_damage = (100 - q[i]) * inv100 % MOD
            damage = q[i] * inv100 % MOD
            ndp[j] += dp[j] * survive * no_damage
            ndp[j] %= MOD
            if j + 1 < limit:
                ndp[j + 1] += dp[j] * survive * damage
                ndp[j + 1] %= MOD
        dp = ndp
        if k and (i + 1) % k == 0:
            dp = [sum(dp) % MOD] + [0] * (limit - 1)

    return str(pow(sum(dp) % MOD, MOD - 2, MOD))

 ## 特殊なケース

 最初のエッジケースはチェックポイントがないことです。 DP は州をマージして完全な状態に戻すことはありません。そのため、ダメージは戦闘全体に影響します。 プレイヤーはチェックポイントでのみ回復するため、これはゲームのルールと一致します。 

2 つ目のエッジケースは、ボス直後のチェックポイントです。 アルゴリズムは、ボスの処理前ではなく、処理後にリセットされます。 治癒が起こる前にボスを倒す必要があるため、これは重要です。 

最後のエッジケースは、ヘルスがゼロになることです。 DP は決して次の状態を作成しません。`h`このような状態は失敗を表すため、健全性が失われ、これらのパスは自動的に消えます。 これにより、プレイヤーが即死判定を技術的に生き延びたものの、結果として生じたダメージにより死亡した場合の試行をカウントすることができなくなります。
