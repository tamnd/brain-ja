 ## 解決策
 ## 問題の理解

 円形のテーブルがあります`n`選手たち。 プレーヤー`i`から始まる`a[i]`カード。 ゲームはプレイヤー 1 から始まり、最初の方向は時計回りです。 

まさに次のシーケンス`m`プレイされたカードが与えられます。 各キャラクターは、そのターンにプレイされたカードを説明します。`C`通常カードなので効果はありません。`S`現在の方向の次のプレーヤーをスキップします。`R`再生方向を逆にします。`D`次のプレイヤーに追加のカード 2 枚を与え、そのプレイヤーもスキップします。 

プレイヤーがカードをプレイするたびに、手札のサイズが 1 つ減ります。 プレイ直後に手札がゼロになった場合は、直ちにゲームから退出し、サークルから除外されます。 

この入力により、プレイ シーケンスが有効であること、および最後のプレイ後に少なくとも 2 人のプレーヤーがまだカードを持っていることが保証されます。 すべての元のプレイヤーが保持するカードの最終的な数を出力する必要があります。 

興味深いのは、シミュレーション中にプレイヤーが消えることです。 誰かが退場すると、その後のターン順序、スキップ、リバース、およびドローツーの効果は、アクティブなプレイヤーの残りの循環リストに作用する必要があります。 

制限は次のとおりです`2 × 10^5`選手たちと`2 × 10^5`トランプをした。 次のアクティブ プレーヤーを見つけるために円を繰り返しスキャンするシミュレーションは、二次時間に低下する可能性があります。 200,000 回の操作があるため、毎ターンを一定時間または対数時間で処理する必要があります。 

プレイヤーが特別なカードをプレイした直後に退場する場合、微妙なエッジケースが発生します。 

例えば：```
3 players
cards = [1, 5, 5]
play = "S"
```プレイヤー 1 がプレイします`S`、カードの数がゼロになり、彼らは去ります。 「次のプレイヤー」はプレイヤー 1 が消える前の位置から決定されるため、スキップされたプレイヤーは依然としてプレイヤー 2 です。 最初にプレイヤー 1 を削除してから次のプレイヤーを検索するという不注意な実装では、間違った人をターゲットにする可能性があります。 

もう 1 つの注意が必要なケースは、退場したプレイヤーがリバース カードを出した場合です。```
3 players
cards = [1, 5, 5]
play = "R"
```プレイヤー 1 はプレイ後すぐに退出します。 方向が変わり、次のターンは新しい方向でプレイヤー 1 の反対側にいたプレイヤーに属します。 隣接プレーヤーを保存せずに、削除されたプレーヤーから続行しようとすると、シミュレーションが中断します。 

バグの最後の原因は、削除とスキップを組み合わせることです。```
3 players
cards = [1, 5, 5]
play = "D"
```プレイヤー 1 がプレイヤー 2 に 2 枚のカードを渡し、プレイヤー 2 はターンを失い、プレイヤー 1 が退場し、次のターンがプレイヤー 3 になります。これらの更新の順序は重要です。 

## アプローチ

 最も直接的なシミュレーションでは、すべてのアクティブなプレイヤーをサークル内に保存し、カードごとにプレイヤーを調べて、次に誰が行動するかを見つけます。 ゲーム ルールはローカルであり、各ターンは現在の方向の近くのプレイヤーにのみ影響するため、これは正しいです。 

問題は効率です。 プレイヤーがゲームから離れる可能性があります。つまり、プレイヤーをサークルから削除する必要があります。 アクティブなプレイヤーを通常の配列またはリストで表す場合、誰かを削除するとコストがかかる可能性があります`O(n)`。 それをここまでやると`m = 2 × 10^5`時間はおよそにつながります`O(nm)`限界をはるかに超えた仕事。 

重要な観察は、ゲームではアクティブ プレイヤーに対して 3 つの操作のみが必要であるということです。 

1. 次にアクティブなプレーヤーを見つけます。 
2. 以前のアクティブ プレーヤーを見つけます。 
3. プレーヤーをサークルから削除します。 

これらは、まさに、次の循環二重リンク リストによってサポートされる操作です。`O(1)`時間。 

すべてのプレーヤーの現在の時計回りの隣と反時計回りの隣を保存します。 プレーヤーを削除すると、標準のリンク リスト スプライスになります。 その後、すべての効果は近隣ポインターのみを使用して処理できます。 

プレイされた各カードは、一定数のポインターの更新とハンド カウントの更新のみを必要とするため、全体の複雑さが線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n) | 遅すぎる |
 | 最適 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのプレイヤーのカード カウントを配列に保存します。 
2. 2 つの配列を使用して循環二重リンク リストを作成します。`nxt[i]`プレーヤーの時計回りの隣人です`i`、`prv[i]`プレーヤーの反時計回りの隣人です`i`。 
3. しましょう`cur = 1`, プレイヤー 1 が最初に移動するためです。 
4. しましょう`dir = 1`時計回りを表し、`dir = -1`反時計回りを表します。 
5. プレイストリング内の各文字について:

 1. 削除する前に、現在のプレーヤーの 2 つの隣接プレーヤーを記録します。`left = prv[cur]`、`right = nxt[cur]`。 
2. カードが`S`または`D`、影響を受けるプレイヤーを特定します。`target = right`いつ`dir = 1`、`target = left`いつ`dir = -1`。 
3. カードが`D`、カードを 2 枚追加します`target`。 
4. 減少`cards[cur]`カードがプレイされたため、1 ずつ増えます。 
5. もし`cards[cur]`ゼロになる、削除する`cur`リンク先リストから。 
6. カードの効果を処理します。 

のために`C`、次のプレイヤーは単純に`target`。 

のために`S`そして`D`、次のプレイヤーは次のプレイヤーです。`target`現在の方向に。 

のために`R`、方向を逆にします。 次のプレーヤーは、新しい方向で現在の位置の隣になります。 
6.すべて終わるまで続けます`m`カードが処理されました。 
7. 各プレイヤーの最終カード数を出力します。 

### なぜ効果があるのか

 リンクされたリストは常に、まだカードを持っているプレイヤーを正確に表します。 プレイヤーのカウントがゼロになると、ルールに従って直ちに削除されます。 

すべてのターンについて、アルゴリズムは、今後のターンが選択される前に、現在の円と現在の方向を使用して影響を受けるプレイヤーを特定します。 これは、ゲームの「次のプレイヤー」の定義と一致します。 

不変条件は、各カードを処理する前に、`cur`はまさにそのターンのプレイヤーであり、リンクされたリストにはアクティブなプレイヤーが正しい循環順序で正確に含まれています。 すべての更新ではこの不変条件が維持されるため、最後のカードの後、保存されたカードの数が真の最終的なハンド サイズとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = list(map(int, input().split()))
s = input().strip()

nxt = [0] * n
prv = [0] * n

for i in range(n):
    nxt[i] = (i + 1) % n
    prv[i] = (i - 1 + n) % n

cur = 0
dirv = 1

for ch in s:
    left = prv[cur]
    right = nxt[cur]

    target = right if dirv == 1 else left

    if ch == 'D':
        a[target] += 2

    a[cur] -= 1

    dead = (a[cur] == 0)

    if dead:
        l = prv[cur]
        r = nxt[cur]
        nxt[l] = r
        prv[r] = l

    if ch == 'C':
        cur = target

    elif ch == 'S' or ch == 'D':
        if dirv == 1:
            cur = nxt[target]
        else:
            cur = prv[target]

    else:  # 'R'
        dirv *= -1

        if dirv == 1:
            cur = right
        else:
            cur = left

for x in a:
    print(x)
```配列`nxt`そして`prv`アクティブなプレーヤーに対して循環二重リンクリストを形成します。 プレーヤーを削除するには、その 2 つの隣接プレーヤーを再接続するだけで済みますが、これは一定時間です。 

変数`target`は削除前に計算されます。 スキップとドローツーは、後の更新後のサークルを基準とするのではなく、直前に行動したプレイヤーを基準として次のプレイヤーを参照するため、これは不可欠です。 

裏面カードの場合は、`left`そして`right`取り外す前に。 現在のプレーヤーが退出した場合でも、方向転換後にどのプレーヤーが次に行動すべきかがわかります。 

カードの枚数がおよそを超えることはありません`2 × 10^5 + 2m`、これは Python 整数内に簡単に収まります。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    s = input().strip()

    nxt = [0] * n
    prv = [0] * n

    for i in range(n):
        nxt[i] = (i + 1) % n
        prv[i] = (i - 1 + n) % n

    cur = 0
    dirv = 1

    for ch in s:
        left = prv[cur]
        right = nxt[cur]

        target = right if dirv == 1 else left

        if ch == 'D':
            a[target] += 2

        a[cur] -= 1

        if a[cur] == 0:
            l = prv[cur]
            r = nxt[cur]
            nxt[l] = r
            prv[r] = l

        if ch == 'C':
            cur = target
        elif ch in "SD":
            cur = nxt[target] if dirv == 1 else prv[target]
        else:
            dirv *= -1
            cur = right if dirv == 1 else left

    return "\n".join(map(str, a)) + "\n"

# sample
assert run("3 6\n3 2 3\nSRDCCD\n") == "3\n0\n3\n"

# minimum style case
assert run("2 2\n1 2\nCC\n") == "0\n1\n"

# reverse with elimination
assert run("3 1\n1 5 5\nR\n") == "0\n5\n5\n"

# draw-two with elimination
assert run("3 1\n1 5 5\nD\n") == "0\n7\n5\n"

# all normal cards
assert run("4 4\n3 3 3 3\nCCCC\n") == "2\n2\n2\n2\n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 2 / 1 2 / CC`|`0 1`| 最小のアクティブなサークル |
 |`3 1 / 1 5 5 / R`|`0 5 5`| 現在のプレイヤーが離れる間に逆転 |
 |`3 1 / 1 5 5 / D`|`0 7 5`| 2 ドローしてエリミネーションでスキップ |
 |`4 4 / 3 3 3 3 / CCCC`|`2 2 2 2`| ピュアターン回転 |

 ## 特殊なケース

 次のことを考慮してください。```
3 1
1 5 5
S
```プレイヤー 1 はスキップ カードをプレイし、すぐにカードが 0 枚になります。 カードがプレイされた時点ではプレーヤー 2 が次にアクティブなプレーヤーであったため、スキップされたプレーヤーは依然としてプレーヤー 2 です。 アルゴリズムは計算します`target`削除前に削除されるため、正しいプレーヤーがスキップされます。 最終的なカウントは次のようになります。```
0
5
5
```ここで次のことを考えてみましょう。```
3 1
1 5 5
R
```プレイヤー 1 はリバースプレイ後に退場します。 方向は時計回りから反時計回りに変わります。 次のプレーヤーは、プレーヤー 1 の元左隣のプレーヤーでなければなりません。アルゴリズムは、`left`そして`right`したがって、プレイヤー 1 が消えた後でも次のターンを正しく選択できます。 

ついに：```
3 1
1 5 5
D
```プレイヤー 1 はプレイヤー 2 に 2 枚のカードを渡し、プレイヤー 2 をスキップして退場します。 プレイヤー 3 が次のプレイヤーになります。 このアルゴリズムは除去前にドロー 2 効果を適用し、スキップされたプレイヤーを現在の位置から直接計算するため、結果は正確に次のようになります。```
0
7
5
```これらのケースは、ほとんどの不正確なシミュレーションが失敗するケースであり、リンクされたリスト表現によって自然に処理されます。
