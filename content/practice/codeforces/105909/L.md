 ## 解決策
 ## 問題の理解

 設定は次の行を記述します。$n$通信局が整然と並んでいます。 各ステーションは送信者として機能します: ステーション$i$メッセージをその直後から始まる連続範囲内のすべてのステーションにブロードキャストします。$i + r_i$、しかしそれを超えない$n$。 したがって、すべてのステーションは 1 つの通信間隔を生成します。$[i, \min(n, i + r_i)]$。 

ここで、どこかの駅に傍受装置を設置することを検討してください。$x$。 このデバイスは、次の場所から発信されたメッセージを傍受するだけではありません。$x$ただし、送信間隔が範囲内であるメッセージはすべて$x$。 つまり、メッセージが送信された場合、$p$に$q$そして満足する$p \le x \le q$、次にデバイス$x$captures it.

 インターセプトされた各メッセージは、インターセプト ポイントがメッセージ間隔のエンドポイントからどれだけ離れているかに応じて値を提供します。 具体的には、寄与は、からの距離の小さい方です。$x$差出人へ$p$、そしてから$x$遠くの端まで$q$。 したがって、メッセージは、範囲の中央付近で傍受された場合にはより多くの影響を及ぼしますが、エンドポイント付近で傍受された場合にはより少なくなります。 

タスクはすべてのステーションについて計算することです$x$、インターセプトの合計値は、その間隔がカバーするすべてのメッセージの寄与を合計することによって得られます。$x$。 

構造は基本的に以下の集合です。$n$それぞれの区間には区間内の位置に依存する重み関数があり、すべての点でこれらの区分的線形寄与の合計が必要です。 

この制約は、各位置のすべての間隔を反復する単純な解法では、$O(n^2)$操作は、次の場合に実行できなくなります。$n$大きい (典型的な Codeforce のスケールは最大を示唆しています)$2 \cdot 10^5$）。 実行可能なソリューションでは、すべての間隔をほぼ線形で処理する必要があります。$O(n \log n)$時間。 

間隔が重なり合うと、単純な推論による微妙な失敗のケースが発生します。 たとえば、すべての場合、$r_i$が大きい場合、すべての駅はほぼすべての区間内に収まります。 単純な位置ごとの累積では、同じ寄与が繰り返し再計算され、二次関数の爆発が発生します。 もう 1 つの特殊なケースは、間隔が短く、高度に局所化されている場合であり、エンドポイントの正しい処理が重要となる場合です。貢献度は、$x$に近いです$p$または$q$したがって、関数を区間全体で均一なものとして扱うと、合計が不正確になります。 

## アプローチ

 直接的なアプローチは、各メッセージ間隔を処理することです。$[p, q]$そして、どのポジションでも$x$その間に追加します$\min(x-p, q-x)$。 これは簡単です。すべての間隔とすべてのカバーされた位置をシミュレートするだけです。 定義に正確に従っているため、正しさはすぐにわかります。 

ただし、これには、すべての間隔にわたって反復し、さらにそれがカバーするすべてのポイントにわたって反復する必要があります。 最悪の場合、各間隔がまたがる可能性があります。$O(n)$ポジション、与える$O(n^2)$総仕事量。 と$n$大きいので、これでは遅すぎます。 

重要な観察は、各区間が中間点に単一の転換点を持つ区分線形関数に寄与しているということです。 区間の左半分では、寄与は次のように直線的に増加します。$x - p$、右半分では、次のように直線的に減少します。$q - x$。 したがって、各間隔はその範囲にわたって「V 字型」関数に寄与します。 

間隔をポイントごとに処理する代わりに、問題を範囲にわたる多くの線形関数の累積に変えることができます。 間隔からの寄与は 2 つの線形セグメントに分解できます。1 つは増加し、もう 1 つは減少します。 これらは、差分配列スタイルのトリックまたは係数に対するプレフィックス合計を使用して処理し、傾きの変化と切片の変化を個別に追跡できます。 すべての間隔が範囲にわたる傾きと切片の寄与に変換されると、最後のプレフィックス スイープによってすべての位置の値が再構築されます。 

これにより、間隔点ペアの列挙から、間隔ごとに一定時間での範囲線形パラメータの更新までの問題が軽減されます。

 ## アルゴリズムのチュートリアル

 1. インターバルごと$[p, q]$、その中点を特定します$m = \lfloor (p + q) / 2 \rfloor$。 この中間点によって、関数が動作を変更する場所が決まります。 貢献度は最大まで増加します$m$、その後減少します。 
2. 間隔を 2 つの独立した部分に分割します。$[p, m]$一次関数に寄与する$x - p$、 そして$[m, q]$貢献する$q - x$。 これにより、累算中に最小値を明示的に処理することが回避されます。 
3. 両方の部分をプレフィックス蓄積と互換性のある形式に書き換えます。 左側の部分を展開すると、$x - p = x + (-p)$の傾きに寄与する$+1$そしてインターセプトシフト$-p$。 右側の部分を展開すると、$q - x = -x + q$、傾きに寄​​与します$-1$そしてインターセプト$+q$。 
4. 2 つの差分配列を使用します。1 つは傾きの変化用、もう 1 つは切片の変化用です。 間隔ごとに範囲の更新を適用して、傾きと切片の寄与がそれぞれの部分範囲にのみ適用されるようにします。 
5. すべての間隔を処理した後、傾き配列に対してプレフィックス合計を実行して各位置の傾きを取得し、同時に別のプレフィックス合計を使用して実行中の切片を維持します。 
6. 最後に、各位置の値を計算します。$x$として$\text{slope}[x] \cdot x + \text{intercept}[x]$。 

正確さは、すべての間隔がブレークポイントを 1 つだけ持つ区分的線形関数に寄与するという事実に依存します。 そのブレークポイントで分割すると、すべてのセグメントが純粋に線形になり、係数を個別に合計することで線形関数を集計できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    r = list(map(int, input().split()))

    slope_diff = [0] * (n + 3)
    intercept_diff = [0] * (n + 3)

    for i in range(1, n + 1):
        p = i
        q = min(n, i + r[i - 1])

        if p > q:
            continue

        m = (p + q) // 2

        # left part: [p, m], value = x - p
        # slope +1, intercept -p
        slope_diff[p] += 1
        slope_diff[m + 1] -= 1
        intercept_diff[p] -= p
        intercept_diff[m + 1] += p

        # right part: [m+1, q], value = q - x
        # slope -1, intercept +q
        slope_diff[m + 1] -= 1
        slope_diff[q + 1] += 1
        intercept_diff[m + 1] += q
        intercept_diff[q + 1] -= q

    slope = 0
    intercept = 0
    res = [0] * (n + 1)

    for i in range(1, n + 1):
        slope += slope_diff[i]
        intercept += intercept_diff[i]
        res[i] = slope * i + intercept

    print(*res[1:])

if __name__ == "__main__":
    solve()
```この実装では、2 つの並列差分配列が維持されます。 勾配が何回あるかを追跡します。$+1$または$-1$は各位置に適用され、他のものは間隔のエンドポイントによって導入された一定のシフトを追跡します。 プレフィックス スイープは、各インデックスで累積された線形関数を再構築します。 

主な微妙な点は、中間点の分割が正しく処理されることです。 区間は、すべての位置が 2 つの線形式のいずれかに正確に寄与するように分割され、重複が回避されます。 間の境界$m$そして$m+1$一貫して処理する必要があります。 包含範囲と排他範囲を誤って混合することは、off-by-one エラーの最も一般的な原因です。 

## 実用的な例

 次の小さなケースを考えてみましょう$n = 5$、 そして$r = [2, 1, 0, 1, 0]$。 間隔は$[1,3], [2,3], [3,3], [4,5], [5,5]$。 

間隔が処理されるにつれて、傾きと切片の違いを追跡します。

| × | 勾配 | 切片 | 結果 |

重複しない間隔を使用した 2 番目の例では、分離されたセグメントが独立して動作することを確認します。 領域をカバーする間隔が 1 つだけの場合、計算された関数は予想される V 字型と正確に一致し、中間点での分割によって正確さが保たれることが確認されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    n = int(sys.stdin.readline())
    r = list(map(int, sys.stdin.readline().split()))

    slope_diff = [0] * (n + 3)
    intercept_diff = [0] * (n + 3)

        p = i
        q = min(n, i + r[i - 1])
        if p > q:

        m = (p + q) // 2

        slope_diff[m + 1] -= 1
        intercept_diff[p] -= p
        intercept_diff[m + 1] += p

 ## 特殊なケース

 重大なエッジケースは、間隔の長さが 1 の場合に発生します。$p = q$。 その状況では、中間点は両方の終点に等しく、両方の半分が崩壊します。 左右のセグメントの更新が空になるか、正しくキャンセルされるため、アルゴリズムは引き続き機能します。 たとえば、$p = q = 3$の場合、中点は 3 であるため、縮退寄与のみが存在し、傾斜伝播は発生しません。 

間隔が極端に歪んでいる場合、次のような別のエッジケースが発生します。$p = 1, q = n$。 ここでは中点が中心近くにあり、両方の半分が広い範囲に広がっています。 プレフィックスの累積により、各位置が 2 つの線形寄与のうちの 1 つを正確に受け取ることが保証されるため、分割境界を越えて二重にカウントされることはありません。 

3 番目のケースは、多くの間隔が 1 つの点で重なり合う場合です。 このような位置では、傾きと切片の値が大きくなる可能性がありますが、アルゴリズムは 64 ビット安全な整数の加算のみを使用するため、値が一般的な Codeforce の範囲内にある限り、累積は安定して正しいままになります。
