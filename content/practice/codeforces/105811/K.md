 ## 解決策
 ## 問題の理解

 部屋 1 をルートとする博物館の部屋のツリーが与えられます。部屋 1 が入り口です。 クロニとTfgの2人は入り口からスタートし、常に1つの道を一緒に進みます。 

リーフ以外のルームでは、次の目的地として 1 つの子ルームを必ず選択する必要があります。 クロニが最初の手を選択し、次に Tfg が次の手を選択し、その後再びクロニがというように続きます。 グラフはツリーであり、部屋への再訪問は禁止されているため、彼らの旅は単なる根から葉への道です。 

各部屋は、Kuroni が好むか、Tfg が好むか、両方が好むか、どちらにも好まれない可能性があります。 プレイヤーのスコアは、最終パスに表示される「いいね！」の部屋の数です。 

プレイヤーは決断を下すとき、最適に行動します。 彼らはまず自分自身の最終スコアを最大化します。 いくつかの選択肢が自分自身に同じスコアを与える場合、他のプレイヤーに最大のスコアを与える選択肢を選択します。 

タスクは、両方のプレーヤーの最終スコアを決定することです。 

ツリーには以下が含まれます$10^5$ノード。 このサイズのツリーには直線的な数のリーフと、深さの点で指数関数的に多くの決定シーケンスが含まれる可能性があるため、ルートからリーフへの考えられるすべてのパスを独立して探索するソリューションは直ちに除外されます。 線形または線形に近い解決策が必要です。 

微妙な点は、プレイヤーが他のプレイヤーのスコアを最小限に抑えようとしていないことです。 彼らのタイブレークルールは、自分たちのスコアが決まった後は実際には協力的です。 

次の小さな例を考えてみましょう。```
1
|
2
```両方のプレイヤーがルーム 1 とルーム 2 を好む場合、答えは単純です。`(2, 2)`。 選択肢がまったくないため、ゲーム理論の推論には、訪問したすべての部屋が正しく含まれている必要があります。 

もう 1 つの簡単な間違いは、タイブレークのルールを忘れることです。```
    1
   / \
  2   3
```部屋 2 を選択するか部屋 3 を選択するかに関係なく、クロニの最終スコアが同じであると仮定します。その後、クロニは Tfg に大きな最終スコアを与える子供を選択する必要があります。 現在のプレーヤーのスコアのみを最大化し、同点を無視するソリューションでは、間違ったパスが生成される可能性があります。 

3 番目の落とし穴は、スコアは現在の移動で選択した部屋だけでなく、選択したパス上のすべての部屋から得られることを忘れていることです。 局所的に魅力的な子は、後でさらに悪いサブツリーにつながる可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、問題を完全なゲームツリーとして扱います。 各部屋からすべての子供を試し、結果のゲーム状態を再帰的に評価し、プレイヤーの優先順位に従って選択します。 これは最適なプレイのルールに正確に従っているため、これは正しいです。 

問題は、多くのサブゲームが繰り返されることです。 ある部屋に到着したとします。$u$そしてクロニの番です。 その時点以降の結果は、ルートとなるサブツリーのみに依存します。$u$そして誰の番なのか。 到達するために使用されるパスには依存しません$u$。 

この観察により、ゲームはツリー動的プログラミングの問題に変わります。 

2 つの情報によって状態を定義します。```
(current node, whose turn chooses next)
```ノードごとに 2 つの答えを計算します。`dp0[u]`をルートとするサブツリーから取得できる最終スコアのペアです。`u`クロニが次の部屋を選ぶ番になったとき。`dp1[u]`Tfg の番のときの類似ペアです。 

もし`u`葉っぱなので決定権はありません。 パスはすぐに終了するため、結果は単純に部屋の寄与分になります。`u`。 

内部ノードの場合、現在のプレーヤーは 1 つの子を選択します。 ゲームの残りの部分は、ターンが切り替わったその子の対応する DP 状態とまったく同じです。 

残る詳細は比較ルールだけです。 

クロニが選択する場合、最初に大きいクロニ スコアを好み、次に大きい Tfg スコアを好みます。 

Tfg が選択する場合、彼女は最初に大きな Tfg スコアを好み、次に大きな Kurani スコアを好みます。 

最良の子を選択した後、現在のルームの貢献度を追加します。 

各ノードが 1 回処理され、すべてのエッジが 1 回検査されて、線形時間のソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | ツリー深さの指数関数 | O(深さ) | 遅すぎる |
 | ツリー上の最適な DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノード 1 でツリーをルートします。 
2. DFS トラバーサルを実行してポストオーダーを取得し、すべての子がその親の前に処理されるようにします。 
3. リーフノードの場合`u`、 セット：```
dp0[u] = dp1[u] = (a[u], b[u])
```移動が残っていないため、パスは次のものだけで構成されます。`u`。 
4. コンピューティング`dp0[u]`。 

すべての子供を検査する`v`。 

ゲームは次から続きます`v`Tfg のターンなので、候補結果は次のようになります。`dp1[v]`。 

以下の結果が辞書編集的に最大となる子を選択します。```
(Kuroni score, Tfg score)
```最適な子を選択した後、ノードの貢献を追加します`u`。 
5. コンピューティング`dp1[u]`。 

すべての子供を検査する`v`。 

ゲームは次から続きます`v`クロニのターンなので候補結果は`dp0[v]`。 

以下の結果が辞書編集的に最大となる子を選択します。```
(Tfg score, Kuroni score)
```最適な子を選択した後、ノードの貢献を追加します`u`。 
6. 答えは次のとおりです。`dp0[1]`, なぜなら、ゲームはルーム1から始まり、クロニが最初の決定を下すからです。 

### なぜ効果があるのか

 どのノードについても、誰の番であるかが分かれば、その後のゲームはそのサブツリーのみに依存します。 これにより、最適な下部構造が得られます。 

すべての子にはすでに正しい DP 値が含まれていると想定します。 

クロニの番の場合、すべての合法的な動きは子供を 1 人選択することに相当します。 結果として得られるスコアは、その子の状態に保存されているスコアとまったく同じです。 クロニのルールでは、彼女は自身のスコアを最大化する結果を選択し、Tfgのスコアはタイブレークとしてのみ使用されると規定されている。 その順序で最良の子を選択することは、ゲームの定義と正確に一致します。 

同じ議論が Tfg のターンにも当てはまります。 

葉は正しく、すべての親はすでに正しい子から計算されるため、サブツリー サイズの帰納法により、すべての DP 状態が正しいことが証明されます。 ルートの値がゲームの最終結果です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

a = list(map(int, input().split()))
b = list(map(int, input().split()))

g = [[] for _ in range(n)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

parent = [-1] * n
order = [0]
parent[0] = 0

for u in order:
    for v in g[u]:
        if parent[v] == -1:
            parent[v] = u
            order.append(v)

dp0 = [(0, 0)] * n
dp1 = [(0, 0)] * n

for u in reversed(order):
    children = [v for v in g[u] if v != parent[u]]

    if not children:
        dp0[u] = (a[u], b[u])
        dp1[u] = (a[u], b[u])
        continue

    best_k = None
    for v in children:
        cand = dp1[v]
        if best_k is None or (cand[0], cand[1]) > (best_k[0], best_k[1]):
            best_k = cand

    dp0[u] = (best_k[0] + a[u], best_k[1] + b[u])

    best_t = None
    for v in children:
        cand = dp0[v]
        if best_t is None or (cand[1], cand[0]) > (best_t[1], best_t[0]):
            best_t = cand

    dp1[u] = (best_t[0] + a[u], best_t[1] + b[u])

ans = dp0[0]
print(ans[0], ans[1])
```最初の DFS は、親関係と走査順序を構築します。 この順序を逆にすると、ポストオーダーのような処理シーケンスが得られ、すべての子が親の前に処理されます。 

2 つの DP 配列はペアを格納します`(kuroni_score, tfg_score)`。 

のために`dp0`、子の結果を次のように直接比較します。`(kuroni, tfg)`なぜなら、Kuroni の優先順位は辞書編集上の順序に正確に従っているからです。 

のために`dp1`、次のように比較します`(tfg, kuroni)`Tfgのスコアが第一の目的だからだ。 

この実装では、再帰的 DFS ではなく反復トラバーサルが使用されます。 と$10^5$ノードでは、再帰の深さが Python のデフォルトの再帰制限を超える可能性があります。

 ## 特殊なケース

 ルートのみで構成されるツリーを考えてみましょう。```
1
1
0
```根も葉です。 アルゴリズムは即座に以下を割り当てます。```
dp0[1] = dp1[1] = (1, 0)
```決定は下されておらず、答えは次のとおりです。`(1, 0)`。 

ここで純粋なネクタイを考えてみましょう。```
3
0 1 1
0 0 1
1 2
1 3
```子の結果は次のとおりです`(1,0)`そして`(1,1)`。 

クロニの主スコアはどちらの場合も 1 です。 アルゴリズムは辞書編集的に次のように比較します。`(Kuroni, Tfg)`そして選択します`(1,1)`。 これは、問題のタイブレーク ルールと正確に一致します。 

最後に、パスの形をしたツリーについて考えてみましょう。```
4
1 0 1 0
0 1 0 1
1 2
2 3
3 4
```各ノードには最大 1 つの子があります。 どこにも選択肢は存在しません。 DP は単にリーフから上に向かって部屋の寄与を蓄積し、`(2,2)`。 これにより、ゲームの要素が消えてパスが強制された場合でも、アルゴリズムが正しく動作することが確認されます。
