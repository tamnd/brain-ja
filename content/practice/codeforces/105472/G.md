 ## 解決策
 ## 問題の理解

 ノームと呼ばれる同一のユニットのセットが与えられており、プロセスを開始する前にそれらを最大でも固定数のグループに分割する必要があります。 その後、双方の間で相互作用が繰り返されます。ラウンドごとに、すべての生きているノームが 1 単位のダメージを与えます。その後、対戦相手は、選ばれた 1 つのグループから最大一定数のノームを削除することで、正確に 1 つのグループを減らします。 

重要な相互作用は、攻撃者がラウンドごとに常に 1 つのグループをターゲットにし、そのグループから最大 k 個のノームを削除することです。 グループが k より小さい場合、グループは完全に消滅します。 このプロセスはすべてのグループが空になるまで続き、対戦相手は、すべてのラウンドで与えることができる合計ダメージを最小限に抑える方法で毎回ターゲット グループを選択します。 

私たちのタスクは、固定パーティションでこの相互作用をシミュレートすることではなく、最適な敵のプレイの下でプロセス全体にわたる合計累積ダメージが最大化されるように、パーティションを最大 m 個のグループに選択することです。 

制約は即座に重要になります。 n が最大 10^9 であるため、個々のノームの反復やラウンドのシミュレーションに依存するアプローチは不可能です。 O(n) または O(nm) の推論でも大きすぎます。 少量の論理前処理の後、閉じた形式またはほぼ定数時間の計算を強いられます。 この構造は、シミュレーションではなく、グループ サイズに対する貪欲な最適化またはパラメトリックな最適化を強く示唆しています。 

k が n に比べて非常に大きい場合、微妙なエッジケースが発生します。 そのような状況では、たった 1 回の攻撃でグループ全体が消滅する可能性があるため、分裂行動は非常に敏感になります。 もう 1 つの特殊なケースは、m が n に比べて大きい場合であり、多くのシングルトン グループが許可され、時間の経過とともにダメージがどのように減衰するかが変化します。 最後に、k が小さい場合、グループはゆっくりと排水される貯水池のように動作し、敵の最適な戦略は、より大きな残りのグループを効果的に優先します。 

多くの場合失敗する素朴な直感は、m 個の等しいグループに分割することが最適であると仮定することです。 たとえば、n = 10、m = 4、k = 3 の場合、均等分割では (3,3,2,2) が得られますが、最適な戦略では、実際には質量を 1 つの大きなグループといくつかのシングルトンに集中させて、少なくとも 1 つのグループの完全な枯渇を遅らせます。 このアンバランスは不可欠です。 

## アプローチ

 強引に試す場合は、n を最大 m 個の正の整数に分割するすべての方法を列挙し、各構成でゲームをシミュレートし、最適な敵のプレイの下で結果として生じる合計ダメージを計算することになります。 シミュレーションの難易度を無視しても、n の分割数は膨大であり、√n で指数関数的に増加します。 これは、中程度の n であっても完全に実行不可能です。 

たとえパーティションを修正したとしても、プロセスをシミュレートするには、すべてのグループを追跡し、最大の効果的なグループを繰り返し選択するか、どのグループが敵に攻撃されるかを計算する必要があります。 各シミュレーションにはラウンドごとに O(n) かそれより悪い時間がかかり、最大 O(n/k + m) ラウンドが存在する可能性がありますが、それでも 10^9 までの n には大きすぎます。 

重要な構造的洞察は、視点を逆転させることです。 ラウンドについて考える代わりに、各ノームが削除される前に一定数の「アクティブなラウンド」に貢献していることを考えます。 各ノームは殺されるまでラウンドごとに 1 ダメージを与えるため、合計ダメージはすべてのノームの生存時間の合計に等しくなります。 敵はラウンドごとに 1 つのグループから常に k 人のノームを削除します。これは、グループがサイズ k の塊で排出されるキューのように機能することを意味します。 

サイズ s のグループ内では、そのメンバーの生涯寄与は決定的です。つまり、そのグループ内で十分な k サイズの欠失が発生するまでメンバーは存続します。 サイズ s のグループは ceil(s / k) 攻撃で効果的に処理され、その寄与は地球規模の時間にわたって減少する算術のような構造を形成します。

これにより、グループの貢献度の合計を最大化するために n を最大 m 個の部分に分割する方法を決定するという問題に変換されます。グループが大きいほど、より長く持続する高ダメージのプレフィックスが作成されるため有益です。 重要な単調な動作は、2 つのグループをマージしても、k 回の攻撃単位あたりの合計ダメージが決して減少しないことです。 生存力が集中する傾向があります。 

最適な構造は貪欲であることが判明しました。許可される限り多くのシングルトン グループを作成する必要があります。各シングルトンは 1 回のヒット後にすぐに削除され、無駄なオーバーラップが最小限に抑えられる一方で、残った 1 つの大きなグループが残りを吸収してロングテールのダメージを最大化するためです。 

決定は、許容できるシングルトンの数に帰着します。 x 個のシングルトン グループを作成すると、残りのグループのサイズは n - x になり、グループの総数は x + 1 となるため、x ≤ m - 1 となります。トレードオフは、多くのグループによる初期の大きなダメージと、1 つの大きなグループによる長期にわたる継続的なダメージのバランスをとることになります。 

この構造を評価すると、攻撃ごとに 1 つずつ削除されるシングルトンを考慮しながら、k 削除が繰り返された場合に大規模なグループがどのくらい存続するかをテストする閉じた形式が得られます。

 ## アルゴリズムのチュートリアル

 システムは、1 つの潜在的に大きなグループと、いくつかのオプションのシングルトン グループを持つものとしてモデル化されます。 

1. x 個のシングルトン グループを選択することを検討します (0 ≤ x ≤ min(m - 1, n))。 各シングルトンは、削除される前に、ちょうど 1 ラウンドの完全なマージナル プレゼンスに貢献します。 

理由は、シングルトンはターゲットにされるとすぐに殺され、敵が最適であるため、シングルトンは関連するとすぐに消費されるためです。 
2. 残りのグループのサイズは s = n - x です。 このグループは、複数の k サイズの攻撃を排除する必要があるため、プロセスの長期フェーズを決定します。 
3. 大規模なグループは、それに対する ceil(s / k) 攻撃に対して生き残ります。 このような攻撃のたびに、現在生きているすべてのノームが軽減が起こる前に最大のダメージを与えます。 
4. 有効ラウンドの総数は、シングルトン除去の数と大規模グループがヒットした回数を足したものに等しくなります。 敵は常にダメージ軽減効率を最大化するグループを選択するため、最初にシングルトンが除去され、その後、大きなグループに注意が移ります。 
5. これらのフェーズにわたる寄与の合計として合計ダメージを計算します。 シングルトン相は、順序に応じて m - 1、m - 2、... の減少シーケンスに寄与しますが、大きなグループはその空乏化にわたって三角形構造に寄与します。 
6. x を増加させると初期ダメージが線形に増加するが、大規模グループのテール寄与が超線形に減少することを観察して、最適な分割点を評価します。 最適なバランスは境界で発生するため、k によって引き起こされる臨界分割を確認します。 
7. k に対する大きなグループのサイズによって、グループが完全な攻撃サイクルを何回持続できるかが決まる遷移点のみをシミュレートすることによって最適な値を計算し、それをシングルトンの寄与と組み合わせます。 

### なぜ効果があるのか

 このプロセスは、各グループが削減のために選択された回数によって完全に決定され、各削減では固定キャップ k によって 1 つのグループのみが削減されます。 これにより、敵の貪欲な選択によって課せられたスケジュール順序を除いて、各グループが独立したものになります。 すべてのノームは、そのグループが除去されるほど十分に減少するまでラウンドごとに 1 ユニットのダメージを与えるため、グループ化はこれらの除去のタイミングにのみ影響します。 

敵にとっての最適な戦略は、残りのアクティブなノームの総数が最も早く減少するグループを常に攻撃することです。これは、常に最大のグループをターゲットにすることと一致します。 これにより、すべての小さなグループが最初に排除され、その後初めて大きなグループが優勢になるという単調な構造が作成されます。 この分離により、最適なパーティションは単一パラメーターのファミリーに分割され、ソリューションを 1 つの主要なブレークポイントの評価に還元できるようになります。

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    # If we can isolate all gnomes into singletons or small groups,
    # the process degenerates into repeated removal of k per group selection.
    # The key observation is that optimal structure reduces to a single large group
    # plus up to (m-1) singletons.

    # Let x be number of singletons.
    # remaining group size s = n - x

    # Each full "cycle" reduces large group by k, contributing triangular damage.

    # We evaluate best split by iterating only over possible critical points:
    # x = 0 or x = min(m-1, n) are sufficient due to monotonicity.

    x = min(m - 1, n)
    s = n - x

    # Damage from large group: sum of s + (s-k) + (s-2k) + ...
    def tri(sum_start):
        res = 0
        cur = sum_start
        while cur > 0:
            res += cur
            cur -= k
        return res

    ans = 0

    # case 1: all possible singletons
    ans = max(ans, x + tri(s))

    # case 2: no singletons
    s = n
    ans = max(ans, tri(s))

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、大きなグループの寄与を k ステップで減少する等差数列としてモデル化します。これは、そのグループに対する最適な攻撃が繰り返されることに対応します。 ヘルパー関数は、そのグループがその存続期間中に寄与した累積ダメージを正確に計算します。 

次に、2 つの境界構成を比較します。1 つはシングルトンの使用を最大化する構成、もう 1 つはシングルトンを使用しない構成です。 これらは、早期排除とロングテール生存の間のトレードオフが最も顕著な 2 つの構造的極端に対応します。 中間の分割では結果は改善されません。これは、ダメージ関数がこれらの極端な値の間で単調であるためです。 

ここでの一般的な落とし穴は、すべてのグループを時間の経過とともに明示的にシミュレートしようとすることです。 これは最悪の場合には 2 次の動作につながりますが、損傷は決定論的な枯渇下での残りのグループ サイズの順序にのみ依存するため、不必要です。

 ## 特殊なケース

 m = 1 の場合、システム全体が 1 つのグループに崩壊します。 シングルトン戦略は不可能であるため、このアルゴリズムは、k による減算を繰り返し計算し、減少するプレフィックス シーケンスを合計することに正確に帰着します。 

k ≥ n の場合、各攻撃はグループ全体を即座に削除します。 この場合、グループ化が支配的となり、最適な解決策はグループの数を最大 m まで最大化し、主にシングルトンの動作を生成することです。 三角関数はすぐにグループごとに 1 つの項に折りたたまれるため、実装ではこれを処理します。 

m ≥ n の場合、すべてのノームを分離できます。 最適な動作は自明です。各 gnome は削除される前に完全な貢献を 1 ラウンドだけ生き残り、答えは n になります。 分割ロジックは、x = n を介して自然にこの構成に到達します。
