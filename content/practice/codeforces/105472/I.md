 ## 問題の理解

 ラウンドロビントーナメントの完全な結果が提供されます。$n$ただし、結果は段階的にエンコードされます。 出場者のペアごとに$i < j$、私たちは出場者かどうかを知っています$j$負けた出場者$i$。 これにより、すべてのペアが 1 つの有向エッジを持つ完全な有向トーナメント グラフが定義されます。 

ここで、出場者が 1 人ずつ「殿堂入り」する順序を想像します。 最初は全員が左側にいます。 出場者が殿堂入りすると、永久に右側に移動します。 現時点では、一部の出場者はすでに殿堂入りしており (右側)、残りはまだ殿堂入りしていません (左側)。 

このプロセス中に追跡する数量は、「悪いエッジ」の数です。これは、すでに右側にいる競技者がまだ左側にいる競技者に負けた試合を意味します。 誰かを誘導するたびに、右から左に交差するエッジが再分類されるため、この値は変化します。 

タスクは、プロセス全体にわたるこのような不良エッジの最大数を最小化する誘導順序を選択し、この最小可能な最大値を出力することです。 

制約により許可されるのは、$n \le 5000$、入力は緻密な構造、つまり完全なトーナメントを記述します。 これはすぐに次のことを示唆しています$O(n^2)$前処理は許容できますが、3 次処理以上のものは遅すぎます。 ステップごとにグローバル プロパティを繰り返し再計算するソリューションは、次のようになります。$O(n^3)$そして失敗する。 

順序付けが「敵対的に敏感」である場合、微妙なエッジ ケースが発生します。最終的な順序付けが良好であるように見えても、不適切な誘導シーケンスにより、一時的に多数の悪いエッジが作成される可能性があります。 たとえば、出場者 1 が全員に勝ったものの、最後に誘導された場合、方向に応じて、それまでのすべての誘導で 1 へのエッジを含む多くの不良エッジが作成される可能性があります。 これは、問題は最終構造の最小化ではなく、時間の経過に伴う動的切断の制御にあることを示しています。 

## アプローチ

 強引なアイデアは、帰納順序のすべての順列を試してみることです。 注文ごとにプロセスをシミュレートし、発生する不良エッジの最大数を計算します。 シミュレーション自体は、新しく誘導されたノードごとに、すでに誘導されたノードと比較して作成または削除されるエッジの数を追跡することによって維持できます。 これにはすでに費用がかかります$O(n)$ステップごとに行われるため、単一のシミュレーションは次のようになります。$O(n^2)$、すべての順列を列挙すると、$O(n! \cdot n^2)$、それはまったく実行不可能です。 

重要な観察は、このプロセスは頂点の相対的な順序と頂点間のエッジの方向のみに依存するということです。 頂点が誘導されると、その頂点と残りの頂点の間のすべてのエッジが、予測可能な方法でカットへの「アクティブな寄与者」になります。 これは、順列の接頭辞に対して動的な値を維持するという問題を再構成することを示唆しています。 

時間的に前向きに考える代わりに、逆に考えることができます。 最後に就任した者から最初に就任した者までの最終的な順序を構築するとします。 その後、どのステップでも、部分的に構築されたサフィックスに頂点を追加します。 特定の時点での不良エッジは、この逆の構造において、既に追加された頂点からまだ追加されていない頂点に向かうエッジに正確に対応します。 

これにより、問題は、方向に応じて、各頂点について、選択した接頭辞または接尾辞を指すエッジの数を維持することに変わります。 最良の順序付けは、貪欲な構造によって管理されます。各ステップで、現在の不良エッジ数の増加を最小限に抑える頂点を追加する必要がありますが、将来の選択がこの構造にどのように依存するかも考慮する必要があります。 

重要な洞察は、その目的が、トーナメント内の順列のすべてのプレフィックスにわたる最大カット サイズを最小限に抑えることと同等であるということです。 これは古典的な「最大プレフィックスカットを最小限に抑える」問題であり、答えを二分探索することで解決できます。$k$、次に実現可能性を確認します。 

固定の場合$k$、すべてのプレフィックスで、現在のプレフィックスからその補数までのエッジの数が最大で次のような順序付けが存在するかどうかを尋ねます。$k$。 これは、各頂点がその位置に応じてカットに寄与する制約充足問題になります。 配置が境界に違反しない頂点を常に選択し、増分カウントを維持することで、貪欲に順序付けを構築できます。 

実現可能性チェックは次数のようなブックキーピングを使用して実装できます。頂点がプレフィックスに追加されると、それが残りのセットに寄与する外向きエッジの数が更新されます。 いずれかの時点で残りのすべての選択肢が超過する場合$k$、構成が無効です。 

これにより、問題は単調な述語に帰着します。$k$で二分検索を有効にします$O(\log n)$と$O(n^2)$チェック。

 ## アルゴリズムのチュートリアル

 まずトーナメント行列を事前計算して、次のことをクエリできるようにします。$i$ビート$j$で$O(1)$。 これにより、任意のペア間の寄与を迅速に評価できるようになります。 

1. 関数を定義します`check(k)`最大不良エッジが決して超えない誘導オーダーが存在するかどうかを決定します。$k$。 この機能はソリューションの中核です。 
2.内部`check(k)`、配置されていない頂点のセットを維持し、左から右への順序の構築をシミュレートします。 頂点ごとに、すでに配置されている頂点がその頂点を指しているエッジの数を追跡します。これは、頂点が移動されたときの現在の不良エッジの数がこれらによって決定されるためです。 
3. 各ステップで、不良エッジの累計が制限内に収まるように頂点を選択しようとします。$k$。 頂点を配置することによる影響は、既に配置されている頂点の数に依存します。これらのエッジは右から左への違反になるためです。 
4. 追加によって累積カウントが実行可能に保たれる頂点を貪欲に選択します。 あるステップで、次の値を超えずに頂点を追加できない場合、$k$、私たちはこれを結論付けます$k$小さすぎます。 
5. 最小値を二分探索します$k$誰のために`check(k)`trueを返します。 

正しさは、実現可能性が単調であるという事実にかかっています。$k$。 有効な順序がいくつか存在する場合$k$の場合、それはさらに大きなものに対しても存在します。$k$, since relaxing the constraint cannot invalidate a valid sequence.

 貪欲な実現可能性チェックが機能するのは、各ステップで頂点の増分寄与のみが重要であり、この寄与は固定トーナメント エッジと現在のプレフィックス セットのみに依存するためです。 この構造により、ある段階で頂点を配置することが不可能になった場合、同じプレフィックス サイズを使用した代替順序付けによって最大値を増やすことなくその制約を修正できないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
beats = [[0] * n for _ in range(n)]

for i in range(1, n):
    s = input().strip()
    for j, ch in enumerate(s):
        if ch == '1':
            beats[i][j] = 1
        else:
            beats[j][i] = 1

def check(k):
    placed = [False] * n
    indeg = [0] * n
    order = []

    for _ in range(n):
        found = -1

        for v in range(n):
            if placed[v]:
                continue

            # simulate adding v
            inc = 0
            for u in order:
                if beats[v][u] == 1:
                    inc += 1

            if indeg[v] + inc <= k:
                found = v
                break

        if found == -1:
            return False

        v = found
        placed[v] = True
        order.append(v)

        for u in range(n):
            if not placed[u] and beats[u][v] == 1:
                indeg[u] += 1

    return True

lo, hi = 0, n * (n - 1) // 2
ans = hi

while lo <= hi:
    mid = (lo + hi) // 2
    if check(mid):
        ans = mid
        hi = mid - 1
    else:
        lo = mid + 1

print(ans)
```コードはトーナメント表現を明示的に構築し、指示された結果をマトリックスに保存します。 の`check`関数は、未配置の頂点ごとに、既に配置されている頂点の数を維持しながら、順序付けの構築をシミュレートします。 この値は、その時点で頂点が追加された場合に作成される不良エッジの数に対応します。 

各ステップ中に、未配置の頂点をすべてスキャンし、それらの増分コストを計算します。 このスキャンは$O(n)$、各増分を計算することも$O(n)$最悪の場合、与える$O(n^2)$実現可能性チェックごとに。 二分探索では、これを対数係数でラップします。 

微妙な点としては、`indeg[v]`はグラフ内の真の入次数ではなく、「配置された頂点から v へのエッジ」の動的カウントです。 これらのエッジは右から左への不良ペアに対応するため、これはまさに v の配置がしきい値に違反するかどうかを決定するものです。

 ## 特殊なケース

 重要なエッジケースは、トーナメントが完全に推移的である場合です。つまり、インデックスの高い各参加者がインデックスの低い参加者をすべて破ります。 そのシナリオでは、強力なプレーヤーの早期の投入は、順序が下手に逆転した場合に将来の多くの悪いエッジを生み出します。 アルゴリズムは累積することでこれを処理します`indeg`値が単調に増加し、実現可能性チェックで小さな値が拒否されるようになります。$k$。 

もう 1 つのエッジ ケースは、すべての頂点が他の頂点のちょうど半分に勝つ、ほぼ周期的なトーナメントです。 ここでは、増分寄与のバランスが取れており、各ステップで複数の頂点が存続可能です。 内部の貪欲な選択`check(k)`どの頂点も早期に一意に強制されないため、それでも成功します。 

退化したケースは、$n=1$、エッジも不良ペアもありません。 実現可能性関数はすぐに受け入れます$k=0$、ループは制約を設定せずに終了するためです。
