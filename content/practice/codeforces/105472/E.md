 ## 解決策
 ## 問題の理解

 子供の円形配置で選択プロセスをシミュレートしています。 子供たちは時計回りに固定された順序で立っており、与えられた韻 (単なる単語の連続) によって定義されたカウント ルールに基づいて、一度に 1 人ずつ子供を繰り返し削除します。 各単語はカウント プロセスのステップに対応し、韻の最後の単語に到達すると、着地した子供が選択されて削除されます。 

削除するたびに、次に残っている子から時計回りにプロセスが続行されます。 選ばれた子は交互に 2 つのチームに割り当てられます。最初に選ばれた子はチーム A、2 番目にチーム B、3 番目が再び A というように全員が割り当てられるまで続きます。 

入力サイズは小さく、子数は最大 100 です。 これは、O(n²) シミュレーションが完全に安全であることをすぐに示します。リストを繰り返しスキャンまたはウォークスルーする単純な循環消去でも、実行されるのは 10⁴ 程度の演算だけだからです。 

微妙な点は、カウントが円を一周し、削除された子を完全にスキップすることです。 このため、削除を適切に処理せずにインデックスを使用してシミュレーションしようとすると、間違いが発生しやすくなります。 

一般的な失敗例は、ステップ サイズが残りの子の数よりも大きい場合に発生します。 たとえば、韻に多くの単語があり、少数の子だけが残っている場合、カウントは縮小する円の周りを複数回正しくラップする必要があります。 モジュロ動作を忘れたり、削除された要素をスキップしない実装では、誤った選択が生成されます。 

もう 1 つの注意が必要な点は、各ラウンドの開始点です。 子を削除した後、次のラウンドは、同じ位置またはインデックス 0 にリセットされるのではなく、時計回りに次に残っている子から開始されます。 

## アプローチ

 直接的なアプローチは、残りの子のリストを維持し、各ラウンドをシミュレートすることです。 選択ごとに、現在の位置から開始して韻を単語ごとに進めます。 各単語はサークル内の次のまだ生きている子に進み、必要に応じてラップアラウンドします。 韻を踏み終わったら、選択した子を削除します。 

この強引なシミュレーションは簡単に推論できます。 削除するたびに、次に生きている子を見つけるために前方へのスキャンを複数回行う必要がある場合があります。 n 個の子とステップあたり最大 O(n) 個の動き、合計 n ステップの場合、複雑さは O(n²) になります。 n ≤ 100 の場合、これは十分に高速です。 

制約が小さいため、バランス ツリーやセグメント ツリーなどの高度なデータ構造は必要ありません。 ブール値の削除または直接ポップを行う単純なリストが機能します。 

重要な構造的洞察は、プロセスが固定されたステップ パターンによる純粋に逐次消去であるということです。 クエリやバックトラッキングは存在しません。 これにより、完全なシミュレーションが正確かつ最適になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n² · k) ここで、k = 韻の長さ | O(n) | 承認済み |
 | 最適化済み (同じシミュレーション、慎重な実装) | O(n² · k) | O(n) | 承認済み |

 「最適化」とは円運動を慎重に処理するだけなので、実際にはどちらも同じです。 

## アルゴリズムのチュートリアル

 1. 韻を解析して単語のリストにし、その長さを計算します。 長さによって、各除去の前に発生するカウントステップの数が決まります。 
2. 子を最初の時計回りの順序でリストに格納します。 並列ブール構造またはリスト構造を維持して、どの子がまだ存在するかを追跡するか、単にリストから要素を削除します。 
3. 現在の開始位置を示すポインターを保持します。 これは、次のラウンドで検討される最初の子を表します。 
4. ラウンドごとに、カウントプロセスを実行します。

韻を踏んだ単語を段階的に進めていきます。 単語ごとに、ポインタを時計回りの順序で次に生きている子に進めます。 リストの最後に達したら、最初に戻ります。 これは円形構造をシミュレートします。 
5. すべての単語を処理した後、ポインターは選択した子に移動します。 この子を現在のチームの次のメンバーとして記録します。 
6. 選択した子をサークルから削除します。 
7. 次のラウンドの開始ポインタを、削除された位置から時計回りに次に生きている子に設定します。 
8. 選択ごとに 2 つのチームを交互に行います。 

正確さは、削除するたびに円の一貫した表現を維持することで得られます。 どのラウンドでも、ポインターは常に最初の有効な開始点を表し、カウント手順は残りの円での韻の段階的な進行を忠実にシミュレートします。 すべての移動は決定的であり、削除は状態を縮小するだけであるため、将来の決定は現在の円の構成と開始インデックス以外には依存しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    rhyme = input().strip().split()
    n = int(input())
    kids = [input().strip() for _ in range(n)]

    alive = [True] * n
    remaining = n
    idx = 0
    team_turn = 0

    team1 = []
    team2 = []

    while remaining > 0:
        # move through all words in rhyme
        for _ in rhyme:
            steps = 0
            while True:
                idx = (idx + 1) % n
                if alive[idx]:
                    break

        # idx is selected
        if team_turn == 0:
            team1.append(kids[idx])
        else:
            team2.append(kids[idx])
        team_turn ^= 1

        alive[idx] = False
        remaining -= 1

        if remaining == 0:
            break

        # move to next alive for next round start
        while True:
            idx = (idx + 1) % n
            if alive[idx]:
                break

    # output: first line is first team, then second team
    if len(team1) == 0:
        print(len(team2))
        print(*team2, sep="\n")
    else:
        print(len(team1))
        print(*team1, sep="\n")
        print()
        print(len(team2))
        print(*team2, sep="\n")

if __name__ == "__main__":
    solve()
```実装では、`alive`リストから要素を物理的に削除するのではなく、配列を削除します。 これにより、高価なシフト操作が回避され、インデックス演算が単純に保たれます。 循環動作はインデックスのモジュラー演算によって処理されます。 

内側のループは、韻内の単語ごとに、次に生きている子に進みます。 これは最もデリケートな部分です。有効な残りの子のみに到達することを保証する必要があるため、生きているとマークされた子が見つかるまでインデックスを繰り返しインクリメントします。 

子供を選択した後、すぐにチーム割り当てフラグを反転し、再び前進して次のラウンドの開始位置を確立します。 次のラウンドは削除された子の後に開始されるため、この順序は重要です。 

よくある間違いは、次のラウンドに進むときに死んだ子をスキップするのを忘れることで、シミュレーション状態が破損します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n² · k) | n 個の除去のそれぞれが k 個の韻を踏んだ単語をスキャンし、各ステップは最悪の場合でも最大 n 個の子をスキャンする可能性があります。 
| スペース | O(n) | 生存状態を保存し、チームを出力します。 

n ≤ 100 という制約により、円上でネストされたスキャンであっても実行時に簡単なままであることが保証されます。 シミュレーションは制限内で快適に実行されます。

 ## 特殊なケース

 1 つの特殊なケースは、子が 1 人だけ残っている場合に発生します。 この状況でも、韻ループは引き続き実行されますが、生きている唯一の子であるため、すべての動作ステップはすぐに同じ子に解決されます。 削除後はプロセスがすぐに終了するため、アルゴリズムは無限ループに入ることなく、その子の選択を正しく続けます。 

もう 1 つのエッジ ケースは、削除後に開始ポインターが削除された子に到達する場合です。 明示的な「生存するまで進む」ループにより、無効な位置からカウントを開始することがないことが保証されるため、多くの削除によって円が断片化された後でも、シミュレーションは一貫性を保ちます。 

最後の微妙なケースは、子の数に比べて韻の長さが長い場合です。 モジュロ動作を繰り返すことで、必要に応じて円を複数回横断することが保証され、標準のアライブスキップ ループを超える特別な処理は必要ありません。
