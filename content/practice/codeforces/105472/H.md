 ## 解決策
 ## 問題の理解

 長期間の休暇をカバーする一連の毎日の気温が与えられます$n$。 連続する 3 日間の連続ブロックを選択する必要があります。1 日目は湖までのハイキング、2 日目は休憩 (暑さの考慮のため無視)、3 日目はハイキングで戻ります。 重要なのは 2 日間のハイキング日だけであり、旅行中の不快感は、その 2 日間のハイキング日の間の最高気温として定義されます。 

したがって、有効な開始日ごとに$d$、温度のペアを見てみましょう$(t_d, t_{d+2})$を最小限に抑えたいと考えています。$\max(t_d, t_{d+2})$。 出力は、最良の開始日と、この最大値の対応する最小値です。 複数の開始日が同じ最小値に達する場合、最小の開始日インデックスが選択されます。 

制約$3 \le n \le 50$二次または三次解であっても制限内で簡単に実行できることがすぐにわかります。 考えられるすべての開始日を直接スキャンするだけですでに十分です。 高度なデータ構造や最適化は必要ありません。 

微妙なエッジケースはタイブレークから生じます。 2 つの開始位置で最高ハイキング温度が同じになる場合は、最も早い方を選択する必要があります。 たとえば、気温が次の場合、$[10, 1, 10, 1]$、1日目から開始すると最大値が得られます$10$、2日目から最大値が得られます$10$同様に、1 日目を出力する必要があります。 

もう 1 つのエッジ ケースは、最適なソリューションが配列の最後にある場合です。 アクセスしてから$d+2$、最後の有効な開始日は次のとおりです。$n-2$。 よくある間違いは、次のようなことを繰り返すことです。$n-1$、範囲外のインデックスが作成されるか、有効な候補が無視されます。 

## アプローチ

 ブルートフォースアプローチは、可能なすべての開始日を試みます$d$1から$n-2$。 それぞれについて$d$、2 つのハイキング日の気温の最高値を計算します。$t_d$そして$t_{d+2}$、これまでに確認された最小値を追跡します。 すべての有効な旅行は 1 回だけ考慮されるため、これは正しいです。 

このアプローチのコストは次のとおりです$O(n)$、各候補者は一定時間で評価され、$n-2$候補者たち。 問題をより複雑なパターンをチェックするように拡張したとしても、このスライディング ウィンドウの列挙は依然として低コストです。 

各開始日は独立しているため、これを超える意味のある最適化はありません。 問題の構造はすでに最小限になっており、2 つのエンドポイントにわたる単純な集計を備えた固定サイズのウィンドウです。 重要な観察は、中日は無​​関係であるため、計算時に中日を考慮する必要がないということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n)$|$O(1)$| 承認済み |
 | 最適 |$O(n)$|$O(1)$| 承認済み |

 実際、「最適な」解決策は、クリーンな帳簿を備えたブルートフォース スキャンです。 

## アルゴリズムのチュートリアル

 すべての有効な開始位置を処理し、各候補旅行のコストを計算します。 

1. 変数を初期化して、最良の答え (最低気温の大きな値と最良の開始日のプレースホルダー) を保存します。 実際の温度によって改善されるように、非常に大きな初期値を使用します。 
2. すべての開始日にわたって反復します。$d$0から$n-3$ゼロベースのインデックス付けで。 これにより、両方が保証されます$d$そして$d+2$は有効なインデックスです。 
3. それぞれについて$d$、値を計算します$v = \max(t[d], t[d+2])$。 これは、その旅行における最悪のハイキング日の気温を表します。 
4. もし$v$これまでに確認された最良の値よりも厳密に小さい場合は、最良の値と最良の開始日の両方を次のように更新します。$d$。 また、厳密な改善にのみ更新することで暗黙的にタイブレークを処理し、最も古いインデックスを保持します。 
5. スキャンが終了したら、1 ベースのインデックスに変換し直した最適な開始日と最適な値を出力します。 

### なぜ効果があるのか

 有効な各旅行は 1 つのインデックスに正確に対応します$d$そして、その旅行の費用は 2 つの固定要素によってのみ決まります。$t[d]$そして$t[d+2]$。 このようなペアをすべて 1 回だけ評価し、常にすべての候補の最小値を保持するため、保存された答えは全体的に最適になります。 タイブレークの正確性は、最初の出現が記録された後は、等しい値を決して上書きしないことから決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
t = list(map(int, input().split()))

best_val = float('inf')
best_d = 0

for d in range(n - 2):
    val = max(t[d], t[d + 2])
    if val < best_val:
        best_val = val
        best_d = d

print(best_d + 1, best_val)
```コア ループは、すべての有効な開始日の列挙を直接実装します。 ゼロベースのインデックスを使用すると、自然に次の位置で停止するため、境界処理が簡素化されます。$n-3$。 条件`val < best_val`以前のインデックスが等しいものに置き換えられることがないため、最小化と正しいタイブレークの両方が強制されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from io import StringIO as _StringIO

    backup = _sys.stdin
    _sys.stdin = _StringIO(inp)

    n = int(input())
    t = list(map(int, input().split()))

    best_val = float('inf')
    best_d = 0

    for d in range(n - 2):
        val = max(t[d], t[d + 2])
        if val < best_val:
            best_val = val
            best_d = d

    _sys.stdin = backup
    return f"{best_d + 1} {best_val}"

assert run("5\n23 27 31 28 30\n") == "2 28"
assert run("4\n30 20 20 30\n") == "1 30"

# minimum size
assert run("3\n10 1 10\n") == "1 10"

# all equal
assert run("5\n5 5 5 5 5\n") == "1 5"

# decreasing
assert run("5\n40 30 20 10 0\n") == "3 20"

# increasing
assert run("5\n0 10 20 30 40\n") == "1 20"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3日交互 | 1 10 | 有効な最小長 |
 | すべて等しい | 1 5 | タイブレークの安定性 |
 | 降順 | 3 20 | 最良の近端境界 |
 | 増加シーケンス | 1 20 | 開始境界で最適 |

 ## 特殊なケース

 最小の場合$n = 3$、可能な旅行はまさに 1 つです。 アルゴリズムはのみを評価します$d = 0$、コンピューティング$\max(t[0], t[2])$。 あいまいさはなく、ループは正確に 1 回実行されます。 

次のような定数配列の場合$[5,5,5,5,5]$、すべての候補は同じ値を生成します。 厳密な改善のみを更新するため、最初のインデックスが選択されたままとなり、インデックスを明示的に比較しなくても正しいタイブレークが保証されます。 

厳密に増加するシーケンスなど、境界が多い場合の最適解は常に次のとおりです。$d = 0$、後の位置は でさらに大きな値とペアになるため、$d+2$。 スキャンでは、特別な処理を行わなくても、これが自然に保存されます。 

厳密に減少するシーケンスの場合、最良の選択は、両方のエンドポイントが最小となる端に向かってシフトします。 ループには次のものが含まれているため、$d = n-3$、最終候補が常に考慮され、1 つずれたエラーが防止されます。
