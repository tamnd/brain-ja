 ## 解決策
 ## 問題の理解

 いくつかの独立したスロットに分割された冷蔵庫が与えられます。 各スロットにはすでにある程度の数の冷たいソーダ ボトルが含まれており、各スロットの最大容量も固定されています。 また、新しい温かいボトルも何本も渡され、冷蔵庫のスロットの前に置いて挿入する必要があります。 学生がソーダを飲むときは、常に均一にランダムな空ではないスロットの前のボトルを取り外すため、この挿入は重要です。 

重要な相互作用は、各スロット内でボトルが厳密に前から消費されることです。 したがって、新しい温かいボトルを前面に挿入すると、そのスロット内の既存の冷たいボトルよりも先に取り出されます。 このシステムは、学生が空ではないスロットをランダムに選択し、その前面から 1 本のボトルを取り出すことを繰り返すにつれて進化していきます。 

目標は、最初の m 人の生徒が常に冷たいボトルを受け取る確率ができるだけ高くなるように、新しい温かいボトルをスロットに分配することです。 正の確率を達成する方法がない場合は、不可能であることを報告する必要があります。 

制約は小さいです。 すべてのパラメーターは最大 100 です。これは、完全な確率過程を明示的にモデル化しようとするあらゆるソリューションが多項式時間で実行可能であることを直ちに示唆していますが、不必要な状態爆発を避けるためには依然として構造的な洞察が必要です。 

早い段階で頻繁に選択されるスロットに温かいボトルを積極的に置きすぎると、微妙な失敗のケースが発生します。 このような場合、特定の構成では、最初の数回のランダムな抽選で確率 1 の温かいボトルが必然的に当たる可能性があり、成功は不可能になります。 簡単な例は、スロットが 1 つだけあり、そこに少なくとも 1 つの温かいボトルが置かれている場合です。 初めてそのスロットが選択されると、温かいボトルが選択されるため、最初の m 選択以内にこれが発生すると、イベントは直ちに影響を受けます。 したがって、適切なソリューションでは、ボトルの温度がスロット全体にどのように分配されるかを注意深く制御する必要があります。 

## アプローチ

 強引な戦略は、n 個のウォーム ボトルを s スロットに分配するすべての方法を列挙することです。 分布の数は組み合わせによるもので、$\binom{n+s-1}{s-1}$これは、n の場合でもすでに大きく、s は約 100 です。分布ごとに、最初の m 回の描画が温かいボトルを避ける確率をシミュレートまたは計算する必要があります。 そのシミュレーション自体には、ステップごとに最大 s 個の選択肢がある m ステップにわたる確率的プロセスが含まれるため、単一の評価でさえ自明ではありません。 これはすぐに実行不可能になります。 

重要な観察は、確率構造がスロット内の冷たいボトルの詳細な順序には依存せず、各スロットの前に置かれた温かいボトルの数にのみ依存するということです。 スロットの前にウォーム ボトルがあると、最初に選択されたときにウォーム ボトルが生成され、その後のみ純粋なコールド ソースのように動作します。 

これにより、問題は n 個の同一の「リスク ユニット」 (ウォーム ボトル) をスロット全体に分散する方法を決定することになります。ここで、各スロット i には、スロットがアクティブであり続ける時間を決定する基本サイズ ci があります。 唯一意味のある決定は、スロット間での影響のバランスを取るためにウォーム ボトルをどのように割り当てるかです。 

正しい戦略は貪欲です。初期のプロセスへの影響が最も少ないスロットに温かいボトルを集中させます。 スロットは空ではないスロットの中から均一に選択されるため、空ではない状態が長く続くスロットほど、実質的に選択される機会が多くなります。 このようなスロットに温かいボトルを置くと、リスクが高まります。 したがって、最適な戦略は、すぐに無関係になるスロット、つまり初期サイズが小さいスロットに温かいボトルを配置することです。 

これにより、現在のサイズによってスロットが並べ替えられ、小さいものから順に温かいボトルが充填されます。

 ## アルゴリズムのチュートリアル

 各スロットは残りのスペースまで追加の保温ボトルを収容できる容量があるものとして扱い、n 個の保温ボトルを一度に 1 スロットずつ分配します。 

1. 現在のコールドボトルの数に基づいてスロットを降順で並べ替えます。 直感的には、小さいスロットは消費中に早く消えるため、そこに温かいボトルを置くと、ランダム選択プロセスに対する長期的な影響が軽減されます。 
2. 最小スロットから n 個の保温ボトルの配布を開始します。 ソートされた順序で各スロットに、残りの容量まで、温かいボトルがなくなるまで、できるだけ多くの温かいボトルを入れます。 
3. n 個の温かいボトルがすべて配置されるまで割り当てを続けます。 すべてのボトルを配置する前にすべてのスロットを使い果たす場合、これは入力制約の不一致を示しますが、この問題は実現可能性を保証します。 
4. 結果の割り当てを元のスロット順序で出力します。 

貪欲なステップの背後にある理由は、残りの空ではないスロット間で選択が均一であるため、プロセス中に長く存続するスロットがより頻繁に選択されるということです。 そこに温かいボトルが置かれていると、生徒の選択のシーケンスの早い段階で遭遇する可能性が高く、失敗する可能性が高くなります。 逆に、存続期間の短いスロットは初期のドローに関与する頻度が低いため、そこに置かれた温かいボトルが最初の m イベントを妨げる可能性は低くなります。 

### なぜ効果があるのか

 どの時点でも、プロセスはどのスロットがまだ空ではないかによってのみ決まります。 初期サイズが大きいスロットはアクティブな状態を長く保つため、時間の経過とともに選択分布にさらに寄与します。 スロットの消費の初期段階で発生した場合、すべてのウォーム ボトルは潜在的な障害を表すため、露出を最小限にするには、ウォーム ボトルを含むスロットの予想される選択頻度を最小限に抑える必要があります。 初期サイズを大きくして分類すると、初期のサンプリング分布への影響が最も少ないスロットに保温ボトルが確実に配置され、最初の m ステップで保温ボトルの消費を回避できる可能性が最大限に保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, s, d = map(int, input().split())
    c = list(map(int, input().split()))
    
    slots = [(c[i], i) for i in range(s)]
    slots.sort()
    
    remaining = n
    w = [0] * s
    
    for cap, idx in slots:
        if remaining == 0:
            break
        add = min(remaining, d - c[idx])
        w[idx] = add
        remaining -= add
    
    print(*w)

if __name__ == "__main__":
    solve()
```実装はまず入力を解析し、各スロットの現在のフィル レベルとそのインデックスを組み合わせます。 現在のフィルで並べ替えると、より小さいスロットが優先されます。 

次に、残りの容量まで温かいボトルを各スロットに貪欲に割り当てます。 の使用`d - c[idx]`スロット容量の制約を超えないようにします。 

最後に、出力形式で必要とされる元の順序で答えを再構築します。 

## 実用的な例

 ### 例 1

 入力:```
5 3 3 4
2 3 0
```スロットを現在のサイズ順に並べ替えます: スロット 3 (0)、スロット 1 (2)、スロット 2 (3)。 

温かいボトルを5本配布します。 

| ステップ | 選択されたスロット | 残り n | 割り当て |
 | --- | --- | --- | --- |
 | 1 | スロット 3 | 5 → 5-4=1 | w = [0,0,4] |
 | 2 | スロット 1 | 1 → 0 | w = [1,0,4] |

 最終出力は、温かいボトルを最初に最小のスロットに集中させる有効な割り当てです。 

このトレースは、温かいボトルが最も「持続性」の低いスロットに最初に押し込まれ、高周波スロットとの初期の相互作用を最小限に抑えていることを示しています。 

### 例 2

 入力:```
2 7 6 4
0 1 2 2 0 1
```サイズごとに並べ替えられたスロット:```
0, 0, 1, 1, 2, 2
```2 つの温かいボトルを最小のスロットに割り当てます。 

| ステップ | スロット | 残り |
 | --- | --- | --- |
 | 1 | 0 のスロット | 2→1 |
 | 2 | 次の 0 スロット | 1 → 0 |

 これにより、温かいボトルが最も一時的なスロットに確実に隔離されます。 

トレースは、アルゴリズムが常に初期のサンプリング分布への影響を最小限に抑えたスロットを優先することを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、スロットが 1 つしかなく、少なくとも 1 つの温かいボトルが挿入されている場合に発生します。 この場合、アルゴリズムは依然としてすべての温かいボトルをそのスロットに割り当てますが、成功の確率は、プロセスが早期に温かいボトルを選択することを回避できるほど m が十分小さいかどうかに完全に依存します。 貪欲なロジックは依然として唯一の実現可能な構成を生成します。 

多くのスロットが同じサイズである場合、別の特殊なケースが発生します。 ソートのステップではそれらを区別する必要はなく、同じサイズのスロット間で並べ替えても同じ動作が得られます。 アルゴリズムは安定した順序付けに依存しないため、これを正しく処理します。 

3 番目のエッジ ケースは、n が複数のスロットを完全に埋めるのに十分な大きさである場合です。 このアルゴリズムは、サイズの大きい順にスロット全体に割り当てを自然に分散し、容量オーバーフローが発生しないようにします。`d - c[i]`縛られた。
