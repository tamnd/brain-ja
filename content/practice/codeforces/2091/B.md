 ## 解決策
 ## 問題の理解

 それぞれに固定のスキル値を持つ学生のグループが与えられ、すべての学生が 1 つのチームに所属するようにグループに分割する必要があります。 どのチームでも、そのチームの強さは、チーム内の生徒の数とそのチーム内の最小のスキルを掛けたものとして定義されます。 この計算された強さが少なくとも所定のしきい値に達した場合にのみ、チームは有効であるとみなされます。 

タスクは、合計の強さを最大化したりチームのバランスを最大化することではなく、単に全員を一度だけ分割した後で強さの条件を満たすチームの数を最大化することです。 

重要な点は、より多くの生徒をグループ化すると乗数は増加しますが、チーム内の最低限のスキルが低下する可能性があることです。 グループ分けの構造によって、チームが資格を得るかどうかが完全に決まります。 

制約により、すべてのテスト ケースにわたる生徒の総数は最大 200,000 人になります。 これにより、すべてのパーティションまたはすべてのサブセットを考慮しようとするソリューションは即座に除外されます。これは、それらが指数関数的に増大するためです。 最悪の場合の集計では、テスト ケースごとに O(n^2) であっても安全ではありません。 ソートベースの線形または線形に近い貪欲なアプローチを期待する必要があります。 

学生が非常に高いスキルを持っているにもかかわらず、放置されている場合、微妙なエッジケースが発生します。 たとえば、x が大きく、1 つの大きな値を除いてすべてのスキルが小さい場合、単純な貪欲な人は、強い生徒を誤って分離したり、積極的にマージしすぎたりする可能性があります。 もう 1 つの失敗例は、弱い生徒を追加すると最小値が減り、有効なチームが崩壊する可能性があることを考慮せずにグループ化が行われた場合です。 

## アプローチ

 強引なアイデアとしては、あらゆる方法で生徒をチームに分割し、条件を満たすチームが何チームあるかを確認するというものがあります。 さまざまな順序で貪欲にチームを構築することに自分自身を制限したとしても、グループ化の選択肢は依然として組み合わせ爆発的に増加します。 学生が n 人いる場合、パーティションの数は指数関数的に増加し、早期の決定が後の実現可能性に影響を与えるため、局所的に最適なマージを決定するだけでも不十分です。 

重要な観察は、チームの条件を書き換えることから得られます。 チームの最小スキルが m でサイズが k の場合、k · m ≥ x、または同等の k ≥ ceil(x / m) のときにチームは強力です。 これは、チームの最も弱いメンバーを修正すれば、そのメンバーをサポートするために必要な最小限の人数がわかることを意味します。 

これは、生徒をスキルごとに分類し、より弱い生徒にはより強い生徒を使って「サポートを割り当てる」ことを提案しています。 これを考えるのに役立つ方法は、生徒を最も強いものから最も弱いものへと処理し、候補チームを蓄積することです。 蓄積されたサイズが現在の最小値をサポートするのに十分であれば、すぐにチームを完成させることができます。 降順で処理しているため、現在の生徒は常に現在のグループの最小値になります。 

この貪欲さが機能するのは、チームを編成することを決定するたびに、利用可能な最も強力な生徒を最初に使用することで、以前の弱いグループで潜在的な強さを無駄にしないことが保証されるためです。

 ## アルゴリズムのチュートリアル

 1. スキル配列を降順に並べ替えます。 これにより、チームを段階的に構築するときに、最後に追加された要素が常に現在のセグメントで最も弱いことが保証されます。 これにより、チームを閉鎖する場合に強さを評価しやすくなります。 
2. カウンターを維持する`cnt`現在チームを構成している生徒の数を表します。 また、すでに形成されている有効なチームの数も維持します。 
3. ソートされたスキルを繰り返し実行します。 生徒ごとに増加します`cnt`暫定的に現在のチームに追加しているためです。 
4. 追加するたびに、`cnt * current_skill ≥ x`。 以来`current_skill`が現在のグループ内で最小である場合 (並べ替えのため)、この条件は現在のグループがすでに有効なチームを形成できるかどうかをチェックします。 
5. 条件が満たされる場合、このチームを終了します。回答をインクリメントしてリセットします。`cnt`ゼロになり、次の生徒から新しいチームが始まります。 

### なぜ効果があるのか

 このアルゴリズムは、現在のグループが常に最も強い残りの生徒で降順に構成されているという不変条件を維持するため、最後に追加された要素が常にそのグループ内の最小スキルとなります。 チームを結成すると決めた場合は、そのグループが有効になるできるだけ早い時点で結成します。 遅延すると、将来のチームに弱い要素が含まれるか、有効なグループの数が減少するだけになります。 常に条件が満たされ次第確定するため、チーム編成の可能性を逃したり、不必要に大きなグループでペアを組んで強い生徒を無駄にしたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        
        a.sort(reverse=True)
        
        cnt = 0
        ans = 0
        
        for v in a:
            cnt += 1
            if cnt * v >= x:
                ans += 1
                cnt = 0
        
        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、スキルを降順に並べ替えることから始まります。これにより、グループを順番に構築するときに、現在の要素が常にその部分グループ内で最も弱いものになります。 カウンター`cnt`進行中のグループのサイズを追跡します。 グループを拡張するたびに、そのサイズに最も弱い要素を乗算してしきい値を満たしているかどうかを確認します。 そうなった場合は、すぐにグループを閉じてリセットします。 

よくある間違いは、部分的に形成された複数のグループを維持しようとしたり、ソートせずに貪欲に生徒をビンに割り当てようとしたりすることです。 降順により、各チェックが現在のグループの真の最小値を正しく表すことが保証されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

| スペース | O(1) おまけ | インプレースソートと定数カウンター |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        
        a.sort(reverse=True)
        cnt = 0
        ans = 0
        
        for v in a:
            cnt += 1
            if cnt * v >= x:
                ans += 1
                cnt = 0
        
        out.append(str(ans))
    return "\n".join(out)

# provided samples

3 6

6 10
6 1 3 6 3 2
""") == """4
0
4
2
1"""

""") == "1"

# single strong element

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての値が等しいが、フル サイズで乗算したときにしきい値をわずかに下回る場合です。 例えば：```
n = 5, x = 10, a = [2,2,2,2,2]
```ソート後、カウントが蓄積されます。1 は 2、2 は 4、3 は 6、4 は 8、5 は 10 となり、1 つの完全なチームが形成されます。 このアルゴリズムは、グループが十分に大きくなるまで形成を正しく遅らせます。 

もう 1 つのエッジ ケースは、単一の大きな値が優勢である場合です。```
n = 3, x = 5, a = [10,1,1]
```1・10 ≥ 5 がサイズ 1 ですでに満たされているため、すぐに 10 でチームを形成します。残りの弱い要素は 2 番目のチームを形成できない可能性がありますが、これも正しいです。 

3 番目のケースは、貪欲な誘惑に弱い要素を最初に組み合わせるという場合です。 ソートすると、弱い要素が常に後で表示され、強い要素を時期尚早に消費するのではなく、必要な場合にのみ寄与するため、この間違いを防ぐことができます。
