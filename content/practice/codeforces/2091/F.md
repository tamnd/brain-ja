 ## 解決策
 ## 問題の理解

 山の垂直方向のスライスを表す長方形のグリッドが与えられます。 各セルは空であるか、Igor が使用できる保留が含まれています。 列は山の水平な層であり、列があります`1`一番上と行に`n`一番下にあります。 列は垂直セグメントです。 Igor は、いくつかの制約を満たすホールドのシーケンスを選択して、下の行から上の行に登ろうとしています。 各ルートは下部から開始し、上部で終了し、行ごとに少なくとも 1 つのホールドを使用し、行ごとに最大 2 つのホールドを使用し、連続するホールドのすべてのペアがユークリッド距離以内にある必要があります。`d`。 

入力は複数のテスト ケースを与え、それぞれがグリッドの寸法を指定します。`n`そして`m`、距離`d`、およびグリッド自体を使用して`X`ホールド用と`#`for empty cells. すべての有効なルートを 998244353 を法としてカウントする必要があります。 

Constraints imply that`n`そして`m`両方とも最大 2000 であり、すべてのテスト ケースにわたるセルの総数は最大 400 万です。 有効なルートの数は行数に応じて指数関数的に増加するため、すべてのパスを明示的に列挙しようとするソリューションは除外されます。 すべての組み合わせを列挙することを避け、行ごとの小さな制限 (行ごとに最大 2 つのホールド) を活用して、組み合わせの爆発を抑えるアプローチが必要です。 

単純な実装が誤って処理する可能性のあるエッジ ケースとしては、ホールドのない行 (出力はゼロである必要がある)、単一列 (距離チェックは行の差に応じて崩れる)、長い水平ジャンプを可能にする大きなアーム スパンなどがあります。 

## アプローチ

 最も単純なアプローチは総当たりです。行ごとの制限を満たすホールドのシーケンスをすべて列挙し、連続するホールド間の距離をチェックします。 単一行の場合`k`保持します、あります`C(k,1) + C(k,2)`選択肢。 グリッドがある場合`n`行があり、各行には大まかに`m`が成立すると、シーケンスの数はおよそ`(m^2)^n`最悪の場合。 と`m`そして`n`2000 年までは、これは天文学的な規模になります。 

重要な洞察は、行ごとのホールドの数が少ないということです (選択できるのは最大 2 つですが、どの行にも多くのホールドを含めることができます)。 この問題は、行ごとの動的計画問題として定式化できます。 各行について、各保留または保留ペアで終了する有効な部分ルートの数を追跡します。 距離チェックに基づいて次の行への接続を計算します。 これにより、組み合わせ爆発が次のように減少します。`O(n * m^2 * m^2)`最悪の場合ですが、事前に計算された隣接リストを使用して慎重にプルーニングすると、ホールドごとの距離チェックの数が大幅に削減されます。 距離制約に隣接リストまたはスライディング ウィンドウを使用すると、これがさらに最適化されます。 

ブルート フォースはシンプルで正しいですが、制約内で実行することはできません。 DP アプローチは、行ごとの使用量が少ない (行ごとに最大 2 つのホールド) ことと、距離制約によって到達可能なホールドが局所化されるという事実を活用し、実現可能にします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((m^2)^n) | O((m^2)^n) | 遅すぎる |
 | 動的プログラミング + 隣接関係枝刈り | O(n * m^4) 最悪の場合 | O(n * m^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを解析し、すべてのホールドの位置を各行に保存します。 各行について、1 つまたは 2 つのホールドのすべてのサブセットを生成します。 各サブセットは、その行の「状態」の候補です。 
2. 各行の隣接リストを事前計算します。 行内の各サブセットについて`i`、行内のすべてのサブセットを検索します`i-1`距離制約に従って到達可能なもの`d`。 ここでユークリッド距離の公式が使用されます。 連続する行のホールドのペアは、上の行のすべてのホールドが範囲内にある場合に有効です。`d`一部は下の行に保持されます (または、必要に応じてすべてのペアを確認します)。 
3. DP を初期化します。 基本ケースは一番下の行です。 一番下の行のすべてのサブセットについて、そのサブセットで終了するルートの数を 1 に設定します。 
4. 下の行から上の行まで繰り返します。 現在の行の各サブセットについて、下の行の到達可能なすべてのサブセットの DP 値を合計し、これを現在の DP エントリのモジュロ 998244353 に格納します。 
5. 最終的な答えは、一番上の行のすべてのサブセットの DP 値の合計 (998244353 を法とする) です。 

機能する理由: 各 DP エントリは、そのサブセットで終了する有効なルートの正確な数を表します。 行ごとに反復し、到達可能なサブセットのみを接続するため、カウントされたすべてのルートはアーム スパン、行ごとの制限、および行ごとに少なくとも 1 つの制約を満たします。 モジュロ演算により、数値が制限内に収まることが保証されます。 

## Python ソリューション```python
import sys
import itertools
from math import sqrt
input = sys.stdin.readline
MOD = 998244353

def distance(p1, p2):
    return sqrt((p1[0]-p2[0])**2 + (p1[1]-p2[1])**2)

def solve_case(n, m, d, grid):
    rows = []
    for i in range(n):
        holds = [(i, j) for j, c in enumerate(grid[i]) if c == 'X']
        if not holds:
            return 0
        rows.append(holds)
    
    dp_prev = {}
    bottom = rows[-1]
    # generate 1 or 2 hold subsets for bottom
    for sz in [1, 2]:
        for combo in itertools.combinations(bottom, sz):
            dp_prev[combo] = 1
    
    for r in range(n-2, -1, -1):
        dp_curr = {}
        upper = rows[r]
        for sz in [1, 2]:
            for combo in itertools.combinations(upper, sz):
                total = 0
                # check connectivity to all combos in dp_prev
                for prev_combo in dp_prev:
                    if all(any(distance(u, v) <= d for v in prev_combo) for u in combo):
                        total = (total + dp_prev[prev_combo]) % MOD
                if total > 0:
                    dp_curr[combo] = total
        dp_prev = dp_curr
    
    return sum(dp_prev.values()) % MOD

t = int(input())
for _ in range(t):
    n, m, d = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    print(solve_case(n, m, d, grid))
```コードはまず各行をホールド座標のリストに変換します。 各行について、すべての 1 ホールドまたは 2 ホールドの組み合わせが列挙されます。 これは、保持サブセットをそれらに到達する方法の数にマッピングする DP 辞書を保持します。 一番下より上の各行について、距離制約が満たされている前の行からの寄与を合計します。 これにより、すべてのルートの明示的な列挙が回避されます。 

## 実用的な例

 **例 1:**

 入力グリッド:```
XX#X
#XX#
#X#X
```一番下の行については`#X#X`、サブセットは`[(2,1)], [(2,3)], [(2,1),(2,3)]`。 DP はこれらのカウント = 1 で初期化されます。次の行`#XX#`サブセットを生成します`[(1,1)], [(1,2)], [(1,1),(1,2)]`。 サブセットごとに、それらが距離内にあるかどうかを確認します`d=1`以前のサブセットのいずれか。 すべての制約を満たすルートは 2 つだけです。 一番上の行`XX#X`それに応じて最終的なカウントが生成されます。 合計 = 2。 

**例 2:**

 と`d=2`、より離れたホールドが接続され、同じプロセスの後に 60 個の有効なルートが生成されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * m^4) 最悪の場合 | 各行には最大 m 個のホールドがあります。 行内の各サブセットの組み合わせは最大 O(m^2) であり、前の行サブセットへの接続性のチェックは O(m^2) です。 |
 | スペース | O(n * m^2) | 各サブセットの DP 値を行に保存します。 行あたりの最大サブセットは O(m^2) です。 |

 の合計`n*m`すべてのテスト ケースで ≤ 4 * 10^6 により、最悪の場合でも確実に`m^4`行ごとの数はプルーニングで許容されます (ほとんどの行のホールド数は少なくなります)。
