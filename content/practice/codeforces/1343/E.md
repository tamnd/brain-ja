 ## 解決策
 ## 問題の理解

 各エッジが道路を表す、接続された無向グラフが与えられていますが、道路にはまだ固定コストがありません。 代わりに、価格のリストも与えられ、各エッジに正確に 1 つの価格を割り当てる必要があります。 

割り当ての後、マイクは a から b に移動し、次に b から c に移動します。 彼はエッジに沿って何度も歩くことが許可されており、エッジを使用するたびにエッジのコストを支払います。 彼の目標は、重みを割り当てた後に最適な計画を立てることができると仮定して、可能な限り安価な歩行を選択することです。 

私たちの仕事は、この最適な移動コストを可能な限り小さくする方法でエッジの重みを割り当てることです。 

この問題を考えるのに役立つ方法は、重みが固定されると、マイクは常に関連ポイント間の最短パスを選択しますが、それによって総コストが削減される場合は、パスの一部を再利用することが許可されるということです。 したがって、a から b への最短経路と b から c への最短経路の重なりの構造がキーオブジェクトになります。 

この制約は、テスト ケースごとに超線形的なことは何も実行できないことを意味します。 すべてのテストにわたる頂点とエッジの合計数は最大でも 2 · 10^5 です。そのため、テスト ケースごとに線形または線形に近いグラフ処理 (通常は BFS または DFS と並べ替えを組み合わせた処理) が必要になります。 すべてのペアの最短パスやテスト ケースごとのフローベースの推論を伴うものは遅すぎます。 

微妙な点は、パスが固定されていないことです。 マイクが a から b へ、および b から c への最短パスのみを独立して通過すると単純に仮定すると、マイクが共有中間頂点を介してルートの一部をマージして総コストをさらに削減できる可能性を見逃してしまいます。 正しい解決策では、重み付けされていないグラフ内の最短パス間の重なり構造を考慮する必要があります。 

## アプローチ

 直接的な試みは、重みを任意に割り当ててから、Mike の最適なルート コストを計算しようとすることです。 固定割り当ての場合、最短経路の計算を実行し、a から b 、そして c への歩行の考えられるすべての分解をシミュレートします。 各割り当てには少なくとも BFS またはダイクストラが必要であり、割り当ての数は m 単位で階乗するため、これはすでにコストが高くなります。 

割り当てを修正して最適なルートのみを計算したとしても、重複する可能性のある a から b および b から c に向かうパスについて推論する必要があります。 主な問題点は、エッジが両方のセグメントにわたって再利用できることです。これは、エッジの重みを 2 回支払う可能性があることを意味します。 

重要な観察は、パス構造を修正すると、結合されたジャーニーで各エッジが 0 回、1 回、または 2 回使用されるということです。 エッジが a から b への最短パス上にあり、また b から c への最短パス上にもある場合、そのエッジは 2 回使用できます。 1 つのリージョンにのみ存在する場合は、1 回使用されます。 それ以外は未使用です。 

これにより、ルートの選択から、エッジごとに最適な構造に何回属するかを決定する問題が軽減されます。 その構造は、重み付けされていないグラフの最短経路距離のみに依存します。 

したがって、BFS を使用して、a から、b から、c からの最短パス距離を計算します。 これらの距離により、端点間の距離の一貫性をチェックすることで、エッジが 2 つの端点間の最短パス上に存在できるかどうかを判断できます。 

最適な構成で各エッジを何回使用できるか (0、1、または 2) がわかったら、問題をエッジに重みを割り当てて重み付き合計を最小化することに集約します。 最良の戦略は、使用量が最も多いエッジに最小の価格を割り当てることです。これは、エッジの方が総コストに大きく寄与するためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (割り当てを試してパスを再計算する) | O(m! · (n + m)) | O(n + m) | 遅すぎる |
 | 最適 (BFS + ソート + 貪欲な割り当て) | O(n + m + m log m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

これから、ソリューションを段階的に構築していきます。 

1. 重み付けされていないグラフで BFS を使用して、a、b、および c からの最短パス距離を計算します。 

これらの距離は、選択した 1 つのパスだけではなく、すべての最短パスの構造を捉えます。 
2. すべてのエッジ (u, v) について、それが 2 つの特別なノード間の最短パス上に存在できるかどうかを判断します。 

いずれかの方向が dist[x][u] + 1 + dist[v][y] が dist[x][y] に等しい場合、エッジは x から y への最短パス上にあります。 
3. 上記の条件を使用して、各エッジについて、a から b への最短パスに属するかどうか、および b から c への最短パスに属するかどうかを計算します。 
4. 各エッジの使用値を定義します。 

aからbとbからcの両方の最短構造に参加できる場合は2、

 1 それらのうちの 1 つに属する場合、

 それ以外の場合は 0。 
5. すべてのエッジの重みを昇順に並べ替えます。 
6. エッジを使用法に従って降順に並べ替えます。 
7. 使用率が最も高いエッジに最小の重みを割り当て、乗算と合計を行って答えを求めます。 

この順序が正しい理由は、各エッジが使用量と重みの積として線形に寄与し、重みを再配置しても実現可能性に影響せず、最終的な合計にのみ影響するためです。 

### なぜ効果があるのか

 BFS 距離は、各ソースからのすべての最短パスの DAG のような構造を定義します。 有効な最短パスは、ターゲットに向かう距離を厳密に減少させるエッジをたどる必要があります。 エッジ分類テストは、エッジが少なくとも 1 つの最短パスに現れるかどうかを正確に捕捉します。 

a から b、そして c への有効なウォークの総コストは、エッジの寄与に分解できます。各エッジは、最短パス構造のオーバーラップ内にあるかどうかのみに応じて固定回数使用されます。 重みは構造から独立しているため、最適化は再配置不等式問題に帰着します。つまり、より大きな係数 (使用法) とより小さな重みを組み合わせることで合計が最小化されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def bfs(start, n, adj):
    dist = [10**18] * (n + 1)
    q = deque([start])
    dist[start] = 0
    while q:
        v = q.popleft()
        for to in adj[v]:
            if dist[to] == 10**18:
                dist[to] = dist[v] + 1
                q.append(to)
    return dist

t = int(input())
for _ in range(t):
    n, m, a, b, c = map(int, input().split())
    p = list(map(int, input().split()))

    adj = [[] for _ in range(n + 1)]
    edges = []

    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)
        edges.append((u, v))

    da = bfs(a, n, adj)
    db = bfs(b, n, adj)
    dc = bfs(c, n, adj)

    dab = da[b]
    dbc = db[c]

    contrib = []

    for u, v in edges:
        use = 0

        if da[u] + 1 + db[v] == dab or da[v] + 1 + db[u] == dab:
            use += 1

        if db[u] + 1 + dc[v] == dbc or db[v] + 1 + dc[u] == dbc:
            use += 1

        contrib.append(use)

    p.sort()
    contrib.sort(reverse=True)

    ans = 0
    for i in range(m):
        ans += p[i] * contrib[i]

    print(ans)
```BFS 関数は、3 つの特別な頂点のそれぞれからの最短距離を計算します。 これらの距離は、パスを明示的に列挙することなく、最短パス構造のエッジ メンバーシップをテストするために使用されます。 

各エッジには、これらの距離チェックのみに基づいて寄与値が割り当てられ、ルートの組み合わせ列挙が回避されます。 

最後に、ソートにより、目的の線形構造により貪欲なペアリングが最適であることが保証されます。 

## 実用的な例

 ### 例 1

 a、b、c がチェーン状の構造を形成し、複数の代替ルートが存在する小さなグラフを考えてみましょう。 BFS 距離を計算した後、エッジが a から b へ、および b から c への最短パス上にあるかどうかによってエッジを分類します。 

| エッジ | a-b最短 | b-c 最短 | 使い方 |
 | --- | --- | --- | --- |
 | e1 | はい | いいえ | 1 |
 | e2 | はい | はい | 2 |
 | e3 | いいえ | はい | 1 |

 重みと使用法を並べ替えた後、使用法 2 のエッジが最小の重みを受け取り、繰り返しのコスト寄与が最小限に抑えられます。 

このトレースは、最適化においてオーバーラップ エッジの価値がどのように高まるかを示しています。 

### 例 2

 b を中心とする星形のグラフの場合、ほとんどのエッジは a-b または b-c パスのいずれかのみに属し、両方には属しません。 

| エッジ | a-b最短 | b-c 最短 | 使い方 |
 | --- | --- | --- | --- |
 | e1 | はい | いいえ | 1 |
 | e2 | いいえ | はい | 1 |
 | e3 | はい | はい | 2 |

 ここでは、中心を介して直接接続しているエッジのみが 2 回寄与します。 これは、アルゴリズムが中央の重複エッジを自然に優先することを裏付けています。 

## 複雑さの分析

import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    from collections import deque

    def bfs(start, n, adj):
        dist = [10**18] * (n + 1)
        q = deque([start])
        dist[start] = 0
        while q:
            v = q.popleft()
            for to in adj[v]:
                if dist[to] == 10**18:
                    dist[to] = dist[v] + 1
                    q.append(to)
        return dist

    for _ in range(t):
        n, m, a, b, c = map(int, input().split())
        p = list(map(int, input().split()))

        adj = [[] for _ in range(n + 1)]
        edges = []

        for _ in range(m):
            u, v = map(int, input().split())
            adj[u].append(v)
            adj[v].append(u)
            edges.append((u, v))

        da = bfs(a, n, adj)
        db = bfs(b, n, adj)
        dc = bfs(c, n, adj)

        dab = da[b]
        dbc = db[c]

        contrib = []
        for u, v in edges:
            use = 0
            if da[u] + 1 + db[v] == dab or da[v] + 1 + db[u] == dab:
                use += 1
            if db[u] + 1 + dc[v] == dbc or db[v] + 1 + dc[u] == dbc:
                use += 1
            contrib.append(use)

        p.sort()
        contrib.sort(reverse=True)

        out.append(str(sum(p[i] * contrib[i] for i in range(m))))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースは、2 つのノード間に複数の最短パスが存在する場合に発生します。 その状況では、エッジは、一意に決定されたパスだけでなく、最短パス上にある場合にも寄与していると見なされます。 距離等価性チェックはパスの再構築に依存しないため、これを正しく処理します。 

たとえば、a から b までの等しい長さのルートが 2 つある場合、どちらかのルートのエッジが距離条件を満たし、1 回カウントされます。 このアルゴリズムは、多重度ではなく存在のみを記録するため、過剰にカウントしません。 

別のエッジ ケースは、a から b および b から c へのすべての最短パスが互いに素である場合に発生します。 この場合、すべてのエッジの使用量は 1 または 0 になり、解決策は使い捨てエッジへの重みの単純な貪欲な割り当てに帰着します。これは当然同じソート メカニズムによって処理されます。
