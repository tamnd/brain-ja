 ## 解決策

 ## 問題の理解

 偶数の長さの配列が与えられ、それをミラー化されたペアのセットとして見ます。最初の要素は最後の要素とペアになり、2 番目の要素は最後から 2 番目の要素とペアになります。 このようなペアごとに、ミラーリングされた各ペアの合計がすべてのペアで同一になるように要素を変更できます。 

1 回の操作で、任意の要素を 1 から k までの任意の値に置き換えることができます。目標は、置換をできるだけ少なくしながら、すべてのペアの合計を等しくすることです。 

最大の難点は、最終的な配列を直接構築していないことです。 代わりに、単一の目標合計 x を選択し、すべてのペアがその同じ合計に寄与することを確認し、各ペアの一方または両方の要素を変更する可能性があります。 

制約が十分に大きいため、ペアとすべての可能な合計に対する二次推論は遅すぎます。 各テスト ケースには合計で最大 2e5 個の要素を含めることができるため、ペアまたは合計に対する O(n^2) アプローチは現実的ではありません。 最悪の場合、テストあたりのスキャンが O(nk) であっても遅すぎます。 

単純な間違いは、x によるグローバル結合を考慮せずに各ペアを独立して扱うことから発生することがよくあります。 たとえば、あるペアが合計 5 を安価に形成でき、別のペアが合計 6 を好む場合、個別に選択すると、一貫性のない答えが得られます。 

もう 1 つの微妙な失敗ケースは、複数のペアが同じ合計をサポートする値をすでに共有しているにもかかわらず、貪欲なローカル決定によりその共有構造が破壊される場合に発生します。 

落とし穴の例:

 入力:

 n = 4、k = 5

 a = [1、4、2、3]

 ペアは (1,3) と (4,2) です。 両方の合計はそれぞれ 4 と 6 になります。 素朴なアプローチでは、各ペアを個別に修正すると 2 つの変更が生じると考えるかもしれませんが、x = 5 を選択すると、両方のペアがそれぞれ 1 つの変更のみで修正可能となり、調整された最適な選択よりも悪くなります。 

重要な問題は、コストが 0 または 1 の変更で所定の合計を達成できるペアの数に依存し、これらの寄与をグローバルに集計する必要があることです。 

## アプローチ

 ブルートフォースアプローチでは、2 から 2k までの可能なすべてのターゲット合計 x を試行します。 各 x について、すべての n/2 ペアをスキャンし、合計 x に達するためにそのペアに必要な変更の数を計算します。 各ペアは、すでに x と一致しているか、1 つの要素を変更することで一致できるか、または両方の変更が必要かどうかに応じて、0、1、または 2 つの変更を提供します。 

これは正しいですが、各 x を評価するにはすべてのペアをスキャンする必要があるため、単純な実装ではテスト ケースごとに O(nk) のコストがかかります。 k が 2e5 まで、合計 n が 2e5 までの場合、これは遅すぎます。 

重要な観察は、各ペア (a[i]、a[n-i+1]) が複雑な方法で各 x に独立して寄与しているわけではないということです。 代わりに、構造化された間隔形式で貢献します。 

ペア (u, v) の場合、mn = min(u, v) および mx = max(u, v) とします。 次に:

 - x = u + v の場合、コストは 0 です。 
- x が [mn+1, mx+k-1] の場合、1 回の変更で十分です。 
- それ以外の場合は 2 つの変更が必要です。 

重要な洞察は、問題を逆転させることです。 ペアごとに各 x を評価する代わりに、ペアあたり 2 つの変更のベースラインと比較して節約できるペアの数を累積します。 各ペアは、コストを 2 から 1 に削減できる「利益範囲」と、コストが 2 から 0 に削減できる単一ポイントに貢献します。 

これにより、問題は可能な合計に対する差分配列のスイープに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての x に対するブルート フォース | O(nk) | お(1) | 遅すぎる |
 | 寄与合計に対する差分配列 | O(n + k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべてのペアを修正し、考えられる目標合計 x ごとに保存される操作の数を数えます。

1. すべてのペア (u, v) について、mn = min(u, v) および mx = max(u, v) を計算します。 これにより、このペアの有効な合計の構造が決まります。 
2. およそ 2k + 2 のサイズの配列 Gain[] を初期化します。これにより、考えられる合計 x ごとに何組のペアが安くなるかを追跡します。 
3. 各ペアについて、まずベースライン コストが 2 操作であると仮定します。 次に、このペアをコスト 2 ではなく 1 に改善できる箇所を特定します。これは、区間 [mn + 1, mx + k] 内のすべての合計で発生します。 差分配列内のこの間隔を増分します。 
4. 次に、コストが 2 ではなく 0 になる特別な合計 x = u + v を特定します。これを、単一点での追加の改善としてマークします。 
5. すべてのペアを処理した後、gain[] に対するプレフィックスの合計を計算します。 各 x について、gain[x] はコスト 2 からコスト 1 または 0 に改善できるペアの数を示します。 
6. 各 x について、総コストを次のように計算します。 

n/2 * 2 - ゲイン[x]ですが、正確な合計に達するペアはさらに 1 単位の追加節約を与えるため、調整します。 
7. すべての x の最小値を追跡します。 

これが機能する理由は、各ペアが独立して x のみに依存して相加的節約に寄与するためです。 寄与が間隔更新に変換されると、全体的な最適値は単なる最良の集計合計になります。 

## なぜ機能するのか

 各ペアは、2 つの操作の固定ベースライン コストに影響します。 いかなる改善も、選択された目標合計 x がそのペアによって完全に決定される 2 つの領域のいずれかに該当するかどうかによってのみ決まります。 これらの領域は、加算による場合を除いて、ペア間で相互作用しません。 これにより、目的関数は x に対する独立した区分的定数寄与の合計になります。 この分離可能性のため、蓄積された寄与を使用して x をスイープすると、ペアのコストを繰り返し再計算することなく、大域的な最適値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        max_x = 2 * k + 2
        diff = [0] * (max_x + 2)
        freq = {}

        pairs = n // 2

        for i in range(pairs):
            u = a[i]
            v = a[n - i - 1]
            if u > v:
                u, v = v, u

            freq[u + v] = freq.get(u + v, 0) + 1

            l = u + 1
            r = v + k

            diff[l] += 1
            if r + 1 <= max_x:
                diff[r + 1] -= 1

        best = float('inf')
        cur = 0

        for x in range(2, 2 * k + 1):
            cur += diff[x]

            zero_cost = freq.get(x, 0)

            total_cost = pairs * 2 - cur - zero_cost
            best = min(best, total_cost)

        print(best)

if __name__ == "__main__":
    solve()
```実装では、各ペアを 1 回処理し、可能な合計に対して差分配列を構築します。 ディクショナリは、指定された合計にすでに正確に一致するペアの数を追跡します。これらのペアは、間隔ベースの削減を超える追加の改善に寄与するためです。 

次に、スイープは各候補の合計について、改善できるペアの数を計算し、これをベースライン コストから差し引きます。 すべての合計の最小値が答えになります。 

微妙な点は、境界の処理です。可能な合計の範囲は最大 2k であり、差分配列は、オーバーフローすることなく r + 1 の更新を安全に適用するのに十分な大きさでなければなりません。 もう 1 つの重要な詳細は、完全一致ペアを分離することです。これは、一般的な「1 回の置換」間隔を超えてさらなる改善が得られるためです。

 ## 特殊なケース

 重要なエッジケースは、すべてのペアの合計がすでに同じ値になる場合です。 この状況では、最適な答えはゼロです。 周波数マップがその合計に最大の節約を割り当て、差分配列の寄与によってペナルティが課されないため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、k = 1 の場合です。すべての要素は 1 である必要があるため、すべてのペアはすでに合計 2 に一致します。スイープは引き続き実行されますが、完全な節約を生み出すのは x = 2 だけです。 

最後の微妙なケースは、ペアが対称的であるにもかかわらず、異なる自然和を生成する場合です。 間隔構造により、オーバーラップが引き続き正しくカウントされ、完全一致追跡を超える特別なケーシングを必要とするペアを必要とせずに、最適なグローバル x が表示されます。
