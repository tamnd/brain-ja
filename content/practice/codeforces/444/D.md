[CF 444D - DZY は文字列が大好き](https://codeforces.com/problemset/problem/444/D)

 **評価:** 2500
 **タグ:** 二分検索、ハッシュ、文字列、2 つのポインター
 **解決時間:** 1 分 6 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 長い文字列が与えられました`s`小さな文字列のペアのリスト`(a_i, b_i)`。 各ペアについて、次の最短の部分文字列を見つける必要があります。`s`両方を含むもの`a_i`そして`b_i`部分文字列として。 両方を含む部分文字列がない場合は、レポートします。`-1`。 文字列`a_i`そして`b_i`は非常に短い (長さ 4 まで) のに対し、メインの文字列は`s`最大 50,000 文字、クエリ数`q`最大 100,000 まで可能です。 

入力制約は、次のすべての部分文字列をチェックする素朴なアプローチを意味します。`s`各クエリの処理は非常に遅すぎます。 ブルート フォース チェックでは、クエリごとに約 50,000 平方の部分文字列を反復処理する必要があり、これはクエリあたり約 25 億の操作に相当します。 100,000 クエリの場合、それは完全に不可能です。 

素朴な解決策がつまずく可能性があるエッジ ケースには、複数回出現する文字列、重複する出現、または一方または両方の文字列がまったく出現しないペアが含まれます。 たとえば、次の場合`s = "aaabaaa"`、`a = "aa"`そして`b = "aaa"`、最も短い部分文字列は`"aaa"`ではなく、インデックス 1 から始まります`"aaab"`。 同様に、クエリに含まれていない文字列が含まれている場合、`s`、アルゴリズムは正しく返さなければなりません`-1`。 パターンが重なると、単純な貪欲なアプローチがオフバイワンエラーを起こしやすくなります。 

## アプローチ

 ブルートフォースアプローチは、すべての開始位置に対して反復されます。`s`、出現するものをすべて検索します。`a_i`そして`b_i`、そしてそれらの出現の任意の組み合わせを含む最小の部分文字列を計算します。 これは理論的には正しく機能しますが、クエリごとに O(|s|²) 個の部分文字列をスキャンする必要があります。 |s| 付き 最大 50,000、q 最大 100,000 の場合、何兆もの演算が必要となり、これは明らかに容認できません。 

最適化するための重要な洞察は 2 つの観察から得られます。 まず、文字列`a_i`そして`b_i`は非常に短いため、クエリに表示される個別の文字列の総数は制限されます。 次に、長さ 1 ～ 4 のすべての文字列の開始位置を事前に計算すると、`s`の場合、各クエリは、開始位置を表す 2 つの並べ替えられた整数リスト間の最小距離を見つける問題に帰着します。 2 つのソート済みリストのマージは、2 ポインター アプローチを使用して線形時間で実行できるため、これははるかに高速です。 

最適化されたアルゴリズムは、次のすべての部分文字列をマッピングする辞書を事前計算します。`s`長さ 1 ～ 4 の、それが表示される位置のソートされたリスト。 次に、クエリごとに`(a_i, b_i)`、両方の文字列の開始位置のリストを取得します。 2 つのポインターを使用してこれらのリストをスキャンし、カバーする部分文字列の長さを最小にする出現のペアを見つけます。 どちらの文字列も出現しない場合は、`s`、すぐに戻ります`-1`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * n²) | お(1) | 遅すぎる |
 | 事前計算 + 2 つのポインター | O(n + q * k) | O(n) | 承認済み |

 ここ`k`内のクエリ文字列の合計出現数です。`s`、実際には小さいです。`a_i`そして`b_i`短いです。 

## アルゴリズムのチュートリアル

 1. 辞書を作成する`occ`の各部分文字列をマッピングする`s`長さ 1 ～ 4 のすべての開始インデックスのリスト。 反復処理`s`各ポジションごとに 1 回`i`、 追加`s[i:i+l]`のために`l`1から4まで`occ[i:i+l]`。 これにより、後ですべての出現を一定時間検索できるようになります。 
2. クエリごとに`(a_i, b_i)`、両方であるかどうかを確認してください`a_i`そして`b_i`辞書に存在します。 どちらでもない場合は、すぐに出力します`-1`。 
3. ソートされたリストを取得する`pos_a`そして`pos_b`の開始位置について`a_i`そして`b_i`。 2つのポインタを初期化する`i`そして`j`から 0 まで、現在のインデックスを表します。`pos_a`そして`pos_b`。 
4. 2 ポインタ トラバースを使用します。 各ステップで現在のポジションを考慮する`pos_a[i]`そして`pos_b[j]`。 両方をカバーする部分文字列は次から始まります`min(pos_a[i], pos_b[j])`そしてで終わります`max(pos_a[i] + len(a_i), pos_b[j] + len(b_i))`。 長さを計算し、これまでに見つかった最小値を追跡します。 
5. 小さい方の開始位置に対応するポインタを進めます。 これにより、最小限のカバレッジを見逃すことなく、すべてのペアを昇順に探索することが保証されます。 いずれかのリストがなくなるまで繰り返します。 
6. 見つかった最小の長さを出力します。 

機能する理由: 事前計算により、関連するすべての文字列のすべての開始点がわかっていることが保証されます。 2 ポインターのトラバーサルは、ソートされた出現順序を利用して、最小のカバー長に向かって貪欲に移動します。 各ステップで、いずれかのポインターの増分により、潜在的な最小部分文字列がすべて探索されます。 両方のリストがソートされており、すべてのペアを順番にチェックするため、候補の最小部分文字列が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)
q = int(input())

# Precompute all substrings of length 1-4
occ = {}
for i in range(n):
    for l in range(1, 5):
        if i + l <= n:
            sub = s[i:i+l]
            if sub not in occ:
                occ[sub] = []
            occ[sub].append(i)

for _ in range(q):
    a, b = input().split()
    if a not in occ or b not in occ:
        print(-1)
        continue
    pos_a = occ[a]
    pos_b = occ[b]
    i = j = 0
    min_len = float('inf')
    while i < len(pos_a) and j < len(pos_b):
        start = min(pos_a[i], pos_b[j])
        end = max(pos_a[i] + len(a), pos_b[j] + len(b))
        min_len = min(min_len, end - start)
        if pos_a[i] < pos_b[j]:
            i += 1
        else:
            j += 1
    print(min_len)
```ソリューションは最初に構築されます`occ`、長さ 1 ～ 4 の部分文字列を開始位置にマップします。 クエリでは文字列が繰り返される可能性があり、クエリごとに位置を再計算するのは非効率的であるため、これは非常に重要です。 2 ポインタ アプローチにより、すべての有効な組み合わせを効率的に探索できます。 小さい方の開始インデックスのポインタを進めるのは微妙です。これにより、可能性をスキップすることなく、次の潜在的な最小部分文字列が考慮されることが保証されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q * k) | 部分文字列を事前計算するには O(n)、2 つのソートされた出現リストをマージするにはクエリごとに O(k) |
 | スペース | O(n) | 長さ ≤4 のすべての部分文字列を辞書に保存します。合計エントリ数は最大で O(n) です。 

|s| が与えられると ≤ 50,000 および q ≤ 100,000、事前計算は線形であり、文字列の長さが ≤ 4 であるため、クエリには非常に短いリストのマージが含まれます。 このソリューションは 3 秒と 256 MB に快適に収まります。
