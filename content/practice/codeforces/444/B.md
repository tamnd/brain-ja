 ## 問題の理解

 このタスクではシーケンスを計算するように求められます。`c`2つのシーケンスに基づいて`a`そして`b`長さの`n`。 順序`a`1 から 1 までの整数の順列です。`n`、 そして`b`は正確に次のバイナリ シーケンスです`d`どちらも擬似ランダムだが再現可能な方法でシャッフルされています。 シーケンス`c`各要素が次のように定義されます`c[k]`の最大値です`a[i] * b[j]`すべてのインデックスペアにわたって`(i, j)`満足のいく`i + j = k`。 

事実上、ポジションごとに`k`、スライドします`b`以上`a`インデックスの合計が次になる最大の積を記録します。`k`。 なぜなら`b`0 と 1 のみが含まれる積`a[i] * b[j]`0 または`a[i]`もし`b[j] = 1`。 これにより、問題はすぐに、それぞれの項目を見つけることに減ります。`k`、最大の`a[i]`どこ`i`と一致します`1`で`b`位置にある`j = k - i`。 

制約は次のとおりです。`1 ≤ n ≤ 100000`したがって、O(n²) 個の演算を実行するアルゴリズムは実行不可能です。 たとえば、すべてのペアを反復する`(i, j)`計算する`c[k]`最大 10^10 の操作が必要となり、制限時間をはるかに超えます。 微妙なエッジケースが発生するのは次の場合です。`b`ほとんどがゼロであるか、`d = n`、この最大値は、素朴に予想されるものとは異なる位置から得られます。 たとえば、次の場合`b = [0, 1, 0]`そして`a = [2, 1, 3]`、 結果`c[0]`でなければなりません`0`なぜなら`i = 0, j = 0`与える`0`、 ない`2`。 

## アプローチ

 ブルートフォースアプローチでは、可能な限りすべての攻撃が繰り返されます。`i`それぞれに`k`から`0`に`2n-2`、計算する`j = k - i`、どうかを確認してください`j`範囲内にあり、更新します`c[k]`と`a[i] * b[j]`。 これは問題の定義に直接従うため、正確性が保証されますが、最悪の場合、およそ n²/2 回の乗算 (n = 10^5 の場合、約 5 * 10^9) が必要となり、非常に遅くなります。 

重要な観察は次のとおりです`b`0 と 1 のみが含まれます。 したがって、それぞれについて`1`で`b`インデックスで`j`に貢献します。`c[k]`位置で`k = j + i`みんなのために`i`。 毎回チェックするのではなく、`(i, j)`ペアの場合、内の 1 の位置を事前に計算できます。`b`、それぞれについて`i`で`a`、 アップデート`c[i + j]`と`a[i]`それぞれに`j`どこ`b[j] = 1`。 This reduces the operation count to O(n * d), which is efficient if`d`小さいです。 しかし、`d`まで可能です`n`, したがって、次のように処理することでさらに最適化できます。`b`1 つのスライディング ウィンドウとして。 に入っているもの以来、`b`シャッフルする前に連続している場合、1 のすべての位置を追跡し、対応するものを更新できます。`c`最大値を持つインデックス。その結果、線形パスオーバーが発生します。`a`のリニアスキャンと組み合わせて`b`。

 ## アルゴリズムのチュートリアル

 1. 配列の初期化`c`長さの`n`すべてゼロで。 これにより、各位置に最大の積が格納されます。 
2. 生成する`a`の順列として`[1, 2, ..., n]`擬似ランダムジェネレータを使用して`x`。 それぞれ`a[i]`に従ってシャッフルされます`x`問題の入力と一致します。 
3. 生成する`b`正確な値を持つバイナリ配列として`d`ものと`n-d`同じジェネレーターによってシャッフルされたゼロ。 
4. インデックスを事前計算する`ones_indices`どこ`b[j] = 1`。 これらは唯一のポジションです`b`ゼロ以外の製品を提供できるもの`c`。 
5. 反復処理`i`から`0`に`n-1`。 それぞれについて`i`、繰り返します`j`で`ones_indices`。 コンピューティング`k = i + j`。 もし`k < n`、 アップデート`c[k] = max(c[k], a[i])`。 
6. すべての投稿を処理した後、`b`、の各要素を出力します`c`新しい行に。 

機能する理由: このアルゴリズムは、次の位置のみを考慮します。`b`値はどこにあるのか`1`。 それぞれについて`a[i]`の位置のみを更新します。`c`ゼロ以外の積を受け取ります。 常にそれぞれの最大値を取ることで、`k`、私たちはそれを保証します`c[k]`可能な限り最大のものが含まれています`a[i]`それは`1`で`b`で`k - i`。 これは、問題の畳み込み定義と、変更された乗算ルールとが一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, d, x = map(int, input().split())
    a = list(range(1, n + 1))
    b = [1] * d + [0] * (n - d)

    def getNextX():
        nonlocal x
        x = (x * 37 + 10007) % 1000000007
        return x

    for i in range(n):
        j = getNextX() % (i + 1)
        a[i], a[j] = a[j], a[i]

    for i in range(n):
        j = getNextX() % (i + 1)
        b[i], b[j] = b[j], b[i]

    ones_indices = [i for i, val in enumerate(b) if val == 1]

    c = [0] * n
    for i in range(n):
        ai = a[i]
        for j in ones_indices:
            k = i + j
            if k >= n:
                continue
            c[k] = max(c[k], ai)

    print('\n'.join(map(str, c)))

if __name__ == "__main__":
    main()
```最初のセクションで生成されるのは、`a`そして`b`まさに説明どおりです。 の`ones_indices`list はゼロを除外し、不必要な更新を減らします。 ネストされたループは、次の位置のみを更新します。`c`影響を受ける可能性があります。 境界条件はチェックによって慎重に処理されます`k >= n`。 使用する`nonlocal x`擬似ランダムジェネレーターの状態が正しく保存されるようにします。
