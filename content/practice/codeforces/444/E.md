 ## 解決策
 ## 問題の理解

 _n_ 個のノードを含むツリーが与えられ、各エッジには正の重みが与えられます。 任意の 2 つのノード _x_ および _y_ について、関数 _g(x, y)_ は、それらを接続する一意のパスに沿った最大重みとして定義されます。 次に、長さ _n_ のシーケンス _p_ が、連続する要素の _g(p_i, p_{i+1})_ を合計することによって評価されます。 各ノード _j_ は _p_ 内に最大 _x_j_ 回出現できます。タスクは、繰り返し制約の下でこの合計を最大化するシーケンス _p_ を構築することです。 

入力ツリーには最大 3000 個のノードがあります。 O(n²) 個の異なるノード ペアがあるため、すべてのペアを直接検査するソリューションは実行可能ですが、_n_ で指数関数的なものは現実的ではありません。 エッジ ケースは、すべての _x_j_ が 1 で各ノードが 1 回出現するように強制される場合、または 1 つのノードの _x_j_ が非常に高い場合に発生し、合計を支配する可能性のある遷移の繰り返しが可能になります。 もう 1 つの微妙なシナリオは、最大のエッジが中央に発生するパスのようなツリーです。 単純な貪欲シーケンスはそれを捕捉できない可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、繰り返し制限に従って長さ _n_ のすべてのシーケンスが生成され、連続する要素に沿った最大エッジの合計が計算され、最大の合計が返されます。 これは原理的には正しいですが、シーケンスの数は組み合わせ的に増加し、_n_ = 3000 で処理できる数をはるかに超えています。繰り返し制約だけですべてのシーケンスをカウントすることは、最悪の場合でもおよそ O(n^n) であり、まったく現実的ではありません。 

重要な洞察は、関数 _g(x, y)_ が _x_ と _y_ の間の最大エッジのみに依存しており、パスに沿って対称かつ単調であることを観察することで得られます。 この構造により、問題を複数のノードセットでの重み付けマッチングの変形として再構成することができます。 個別のエッジのみを降順で考慮することで、繰り返し制限に違反することなくノードを貪欲に「接続」することを試みることができます。 最適化は、マルチセットにわたる動的プログラミング、または慎重なブックキーピングを伴う最大コスト フロー/DP の使用に帰着します。各 DP 状態は、各ノードがまだ使用できる回数を追跡します。 

最適なアプローチは、ノード数に対する動的プログラミングです。 させて`dp[S][v]`マルチセットを使用して取得できる最大合計になります。`S`ノードで終わる`v`。 合計は前のノードのみに依存するため、各遷移が更新されます`dp`最大エッジを次のノードに追加することによって。 繰り返し制限によりサイズが制限されます`S`、組み合わせ爆発を防ぎます。 ビットセットまたはカウントの配列を使用して慎重に実装すると、複雑さはペアワイズ エッジの場合は O(n²)、DP 遷移の場合は O(n³) になり、これは n ≤ 3000 で許容可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^n) | O(n) | 遅すぎる |
 | ノード数に対する DP | O(n3) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. _n_ 個のノードを含むツリーを読み取り、エッジの重みを含む隣接リストを保存します。 各エッジは双方向であり、パスに沿った最大エッジを計算するときに高速アクセスできるように重みが明示的に保存されます。 
2. 事前計算`g(u, v)`ノードのすべてのペアに対して。 ツリーが小さいため、パスに沿った最大エッジを維持しながら、各ノードから BFS または DFS を実行します。 結果を 2D 配列に保存する`g[u][v]`。 各 BFS がすべてのノードに 1 回接触し、パスに沿った最大値が O(1) で更新されるため、このステップには O(n²) 操作が必要です。 
3. DP テーブルの初期化`dp[v][k]`どこ`v`は現在の終了ノードであり、`k`使用された回数です。 当初は、`dp[v][1] = 0`すべてのノードに対して`x_v ≥ 1`。 他の状態は負の無限大に設定されます。 
4. シーケンス全体の長さを反復します。`L`1からnまで。 DP 状態ごとに`(v, used_v)`、任意のノードへの移動を検討してください`u`そのような`used_u < x_u`。 アップデート`dp[u][used_u + 1]`として`max(dp[u][used_u + 1], dp[v][used_v] + g[v][u])`。 この遷移は繰り返し制限を尊重し、最大エッジの合計を累積します。 
5. DP テーブルに記入すると、答えは最大値になります。`dp[v][used_v]`全体的に`v`そして`used_v`。 

機能する理由: 各ステップで、DP は、指定された使用回数のノードで終了するすべてのシーケンスの連続 _g_ 値の最大可能合計を維持します。 遷移では、繰り返し制限に違反することなく有効なエッジの重みのみが追加され、すべてのシーケンスが暗黙的に考慮されます。 あらゆる可能な拡張が考慮されるため、DP は決して過小評価されません。 

## Python ソリューション```python
import sys
from collections import deque
input = sys.stdin.readline

n = int(input())
adj = [[] for _ in range(n)]
for _ in range(n - 1):
    a, b, c = map(int, input().split())
    a -= 1
    b -= 1
    adj[a].append((b, c))
    adj[b].append((a, c))

x = [int(input()) for _ in range(n)]

# Precompute g(u, v) for all pairs using BFS
g = [[0]*n for _ in range(n)]
for start in range(n):
    visited = [False]*n
    q = deque()
    q.append((start, 0))
    visited[start] = True
    while q:
        node, max_edge = q.popleft()
        g[start][node] = max_edge
        for nei, w in adj[node]:
            if not visited[nei]:
                visited[nei] = True
                q.append((nei, max(max_edge, w)))

# DP: dp[v][used_v] = max sum ending at node v with used_v times
dp = [[-1]* (x[v]+1) for v in range(n)]
for v in range(n):
    if x[v] >= 1:
        dp[v][1] = 0

for _ in range(n - 1):
    new_dp = [[-1]* (x[v]+1) for v in range(n)]
    for v in range(n):
        for used_v in range(1, x[v]+1):
            if dp[v][used_v] == -1:
                continue
            for u in range(n):
                if u == v:
                    if used_v + 1 <= x[u]:
                        new_dp[u][used_v+1] = max(new_dp[u][used_v+1], dp[v][used_v] + g[v][u])
                else:
                    for used_u in range(1, x[u]+1):
                        if dp[u][used_u] != -1:
                            continue
                        if used_u <= x[u]:
                            new_dp[u][used_u] = max(new_dp[u][used_u], dp[v][used_v] + g[v][u])
    dp = new_dp

answer = 0
for v in range(n):
    answer = max(answer, max(dp[v]))
print(answer)
```このソリューションは、効率的な走査のための隣接リストを構築することから始まります。 各ノードの BFS は次のように計算します。`g(u, v)`パスに沿った最大エッジを追跡することによって。 DP アレイは使用回数を注意深く追跡し、制限を超えるノードがないことを確認します。 ネストされたループは遷移と更新を処理しますが、これは最も微妙な部分です。使用量が増えると、off-by-one エラーが簡単に発生する可能性があります。 一時的なものを使用する`new_dp`現在の反復で必要な状態を上書きすることを防ぎます。
