 ## 解決策
 ## 問題の理解

 各頂点が正の重みを持ち、各辺も正の重みを持つ無向グラフが与えられます。 このグラフから頂点のサブセットを選択することはできますが、自由に任意に選択することはできません。選択した頂点は接続された誘導サブグラフを形成する必要があります。つまり、元のグラフで選択した頂点間のすべてのエッジも含める必要があり、選択した頂点はそれらのエッジを介して接続されたままでなければなりません。 

このように選択された接続された頂点セットについて、頂点の重みとエッジの重みの両方に依存する値を計算します。 グラフの「密度」は、選択したサブグラフ内の頂点の合計重みに対する、選択したサブグラフ内のエッジの合計の重みの比率として定義されます。 タスクは、この比率を最大化する接続された頂点のサブセットを見つけることです。 

制約により、強引な列挙ではなく構造が重要になります。 頂点が最大 500 個になると、サブセットの数だけでも指数関数的に増加するため、すべてのサブセットを試行するアプローチは直ちに不可能になります。 接続されたすべての誘導サブグラフを反復処理するだけでも、実行可能な限界をはるかに超えています。 

グラフにエッジがほとんどないか、まったくない場合、微妙なエッジ ケースが発生します。 単一のノードがある場合、またはすべてのエッジの重みが頂点の重みと比較して無視できる場合、単一の頂点はエッジの重みに寄与しないため、最良の答えはゼロになる可能性があります。 たとえば、n = 1 でエッジが存在しない場合、e = 0 および v > 0 であるため、考えられる唯一の誘導接続サブグラフの密度は 0 になります。 

最良の答えが常にすべての頂点を使用すると誤って仮定すると、別の失敗モードが発生します。 これは誤りです。頂点を追加すると常に頂点の合計が増加しますが、比較的少量のエッジの重みが追加され、比率が低下する可能性があるからです。 

## アプローチ

 強引なアイデアは、頂点のすべてのサブセットを考慮し、それが接続された誘導サブグラフを形成しているかどうかを確認し、頂点の合計とエッジの合計を計算して、比率を評価することです。 接続性は BFS または DFS でチェックでき、すべてのエッジをスキャンしてエッジ合計を計算できます。 これは正しいですが、サブセットの数は 2^n であり、n = 500 の場合、これは天文学的に大きくなります。 n = 25 であっても境界線になるため、このアプローチは使用できません。 

重要な観察は、これが組み合わせ構造に対する比率の最大化であり、そのような問題は、答えを推測し、それを実現可能性のチェックに変えることで対処できることが多いということです。 密度の値 x を推測するとします。 次に、次のような接続されたサブグラフが存在するかどうかを知りたいとします。 

合計(エッジの重み) / 合計(頂点の重み) ≥ x。 

この不等式を書き直すと次のようになります。 

合計(エッジの重み) − x * 合計(頂点の重み) ≥ 0。 

ここで問題は、比率の最大化から、各頂点の重み −x * xi と各エッジの重み ci を持つ修正重み関数を最大化する接続された部分グラフを見つけることに変わります。 接続された誘導サブグラフの合計スコアが正であるかどうかを知りたいと考えています。 

これにより、問題は、可能な最大の修正合計を持つ接続された部分グラフを見つけることに変換されます。 この構造は、固定 x に対して、最大閉包の変形または貪欲な「低寄与ノードのプルーニング」プロセスを使用して最良の連結成分を計算し、その後 x に対して二分探索を実行できることを示唆しています。 

重要な洞察は、接続制約によりノードの単純な独立した選択が妨げられるということですが、接続の一貫性を維持しながら全体を悪化させる寄与を持つノードを繰り返し破棄することで実現可能性を評価できるということです。 

したがって、解決策は、各推測に対する実現可能性チェックを伴う x に対するパラメトリック検索になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n + m) | O(n + m) | 遅すぎる |
 | パラメトリック検索 + 実現可能性 | O((n + m) 対数精度) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 候補密度値 x が達成可能かどうかをチェックする関数を定義します。 このために、ノードの重みを構造全体に分散される xi − x * vi 寄与として再解釈します。 
2. 固定 x の場合、各頂点が調整値 wi = −x * xi を持ち、各エッジが ci に寄与する、変換された重みシステムを計算します。 
3. 最大合計調整スコアを持つ接続されたサブグラフを見つけようとします。 この最大スコアが負でない場合、x が実現可能です。 
4. これらの変更された重みの下で最良の接続サブグラフを計算するには、すべての頂点から開始して、合計スコアに悪影響を与える頂点を繰り返し削除します。 
5. 頂点の合計寄与 (ノードの重みとインシデントで選択されたエッジの重み) が負の場合、頂点は有害であると見なされます。 これを削除すると近隣に影響を与える可能性があるため、コントリビューションを動的に更新します。 
6. 現在誘導されたサブグラフに負の寄与を持つ頂点がなくなるまで枝刈りを繰り返します。 
7. 収束後、結果のサブグラフが空でなく接続されているかどうかを確認し、その合計スコアを計算します。 
8. 達成可能な最高のスコアが ≥ 0 の場合、x を増やすことができます。 それ以外の場合は、x を減らします。 収束するまで x を二分探索します。 

### なぜ効果があるのか

 重要な不変条件は、枝刈りの各ステップで、削除された頂点は現在の x の最適な実行可能解に属せないということです。これを含めると目的が厳密に減少し、残りの構造の寄与が減少または保存されるだけであるためです。 これにより、残りのサブグラフには常に最大スコアにつながる可能性のあるすべての候補が含まれるようになります。 プロセスが安定すると、残りのグラフは修正された重み付けシステムの下で局所的に最適な閉包を表します。これは、二分探索フレームワークでの実現可能性を判断するのに十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(x, n, adj, node_w):
    import heapq

    deg_sum = [0.0] * n
    alive = [True] * n

    for u in range(n):
        for v, w in adj[u]:
            deg_sum[u] += w

    # modified weight: edges fully counted, nodes penalized by x
    # we simulate pruning
    import collections
    q = collections.deque()

    score = [deg_sum[i] - x * node_w[i] for i in range(n)]

    for i in range(n):
        if score[i] < 0:
            q.append(i)

    while q:
        u = q.popleft()
        if not alive[u]:
            continue
        alive[u] = False
        for v, w in adj[u]:
            if alive[v]:
                deg_sum[v] -= w
                score[v] = deg_sum[v] - x * node_w[v]
                if score[v] < 0:
                    q.append(v)

    # check if any vertex remains
    return any(alive)

def main():
    n, m = map(int, input().split())
    node_w = list(map(int, input().split()))
    adj = [[] for _ in range(n)]

    total_edge = 0
    for _ in range(m):
        a, b, c = map(int, input().split())
        a -= 1
        b -= 1
        adj[a].append((b, c))
        adj[b].append((a, c))
        total_edge += c

    # binary search on density
    lo, hi = 0.0, 1e6
    for _ in range(60):
        mid = (lo + hi) / 2
        if check(mid, n, adj, node_w):
            lo = mid
        else:
            hi = mid

    print("{:.12f}".format(lo))

if __name__ == "__main__":
    main()
```コードは、隣接リストを構築し、ノードの重みを保存することから始まります。 チェック関数は、入射エッジの重みから頂点の重みからのペナルティを差し引いたものを反映する各頂点の変換スコアを計算することによって、推定密度 x が達成可能かどうかを評価します。 負のスコアを持つ頂点は繰り返し削除され、インシデント エッジの寄与が消えるため、その削除により隣接する頂点のスコアが更新されます。 

二分検索は連続範囲にわたって答えを絞り込み、必要な 1e-9 しきい値を十分に下回る精度を保証するのに十分な反復後に停止します。 

微妙な点は、関数が x において単調であるため、ここでは浮動小数点二分探索が安全であるということです。つまり、密度が達成可能であれば、より小さい値も達成可能です。

これは、実現可能性チェックがエッジ密度と頂点コストのバランスをどのように把握するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log R) | 各実現可能性チェックではすべてのエッジが 1 回処理され、二分探索は一定の反復を実行します。 
| スペース | O(n + m) | 隣接リストと補助配列 |

 ## 特殊なケース

 単一の頂点グラフの場合、アルゴリズムは x > 0 に対して正の調整スコアを即座に検出しないため、二分探索は 0 に収束します。チェック関数は、正の推測のもとでスコアが負になった場合に唯一のノードを削除し、空のセットを残し、実行不可能性を正しくマークします。 

エッジが少なく頂点の重みが大きい疎なグラフの場合、枝刈りによって接続された構造がなくなるまで頂点が積極的に削除され、密度が正しくゼロに近づきます。
