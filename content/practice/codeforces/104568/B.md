 ## 解決策
 ## 問題の理解

 私たちは、N 人の候補者の中からちょうど K 人で構成される委員会を組織するように求められています。 各候補者は独立して行動し、それぞれが「賛成」に投票する既知の確率 Pi を持っています。 投票は常に「はい」か「いいえ」のどちらかであるため、各候補者は偏ったコイントスになります。 

委員会が選ばれると、K 人のメンバー全員が投票し、最終結果が同点になる確率、つまり正確に K/2 票が賛成、K/2 人が反対となる確率に注目します。タスクは、固定委員会を分析することではなく、この同点確率ができるだけ大きくなるように、どの K 人を含めるかを選択することです。 

入力は複数のテスト ケースで構成されます。 それぞれについて、サイズ K の任意のサブセットを自由に選択し、そのサブセットの独立ベルヌーイ変数によって引き起こされる確率分布を計算します。 出力は、K/2 回の成功で正確に着陸する可能性のある最大確率です。 

この制約は、N が大きくなると、すべてのサブセットにブルート フォースを実行するのは不可能であることを意味します。 中程度の N の場合でも、K 人を選択する方法の数は C(N, K) のオーダーで組み合わせ式であり、N = 200 の場合は天文学的に大きくなります。単一の委員会を評価する場合でも、K+1 の可能な投票総数にわたる分布を計算する必要があり、これはすでに K に対する二次依存性を示唆しています。これにより、委員会を直接列挙しようとするアプローチは即座に除外されます。 

素朴な推論による微妙な失敗例は、0.5 に最も近い確率を持つ人を選ぶことが常に最適であると仮定することです。 この直感は単独では正しいことが多いですが、組み合わせた選択が非線形に相互作用する場合には当てはまりません。 たとえば、K = 2 の確率 0.49、0.51、0.9、0.1 を考えます。0.5 に最も近い 2 つを貪欲に選択すると 0.49 と 0.51 が得られますが、0.1 と 0.9 を選択すると、確率 1.0 と決定的な関係が得られます。 正しい解決策は、個々のバランスだけでなく、選択した確率間の相互作用を考慮する必要があります。 

## アプローチ

 直接的なアプローチでは、K 人のサブセットを固定し、ちょうど K/2 人が「はい」と投票する確率を計算します。 固定サブセットの場合、これは K 個の独立したベルヌーイ分布の古典的な畳み込みです。 各候補は 2 項多項式に寄与します。ここで、x^0 の係数は (1 − Pi)、x^1 の係数は Pi です。 すべての K 多項式を乗算すると K 次多項式が得られ、x^(K/2) の係数が同点確率になります。 

1 つのサブセットのこの計算には O(K^2) のコストがかかります。これは、新しい人が確率をシフトおよび混合することによって DP 分布を更新するためです。 ただし、難しいのは、どの K 人を選択すればよいかわからないことです。 

サイズ K のすべてのサブセットをブルート フォースで処理する場合、C(N, K) の可能性を評価する必要があり、各評価のコストは O(K^2) となり、200 までの N ではまったく実行不可能な指数関数的爆発が発生します。 

重要な観察は、組み合わせ的な方法でサブセットを明示的に決定する必要がないということです。 代わりに、アイテムに対する動的プログラミングを使用して段階的に構築し、選択した人の数と、達成できる投票数の分布の両方を追跡できます。 

候補のいくつかのプレフィックスを考慮し、それらのうち正確に j 個を選択した後、達成可能な最良の分布を表す DP 状態を定義します。 各 j について、可能な数の賛成票の配列を維持します。 確率 p で新しい候補を処理するときに、それらを含めるかどうかを決定します。 それらを含めると、分布は (1 − p, p) の畳み込みによってシフトします。 それらを除外すると、前の状態が引き継がれます。 これは本質的には、「値」がスカラーではなく確率分布であるナップザックです。 

これにより、問題は、組み合わせによるサブセットの列挙から、選択に対する構造化された DP に変換されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット + サブセットごとの DP | O(C(N, K) · K^2) | O(K) | 遅すぎる |
 | DP オーバーアイテムと選択サイズ | O(N · K^2) | O(K^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ## アルゴリズムのチュートリアル

 1. dp[j][t] が (これまで j 人を選択するすべての方法で) ちょうど t 人が Yes に投票する最大確率を表す DP テーブルを作成します。 すべての候補を処理した後の目標は dp[K][K/2] です。 
2. dp[0][0] = 1 でテーブルを初期化します。つまり、何も選択しないと、確率 1 で賛成票がゼロになります。他のすべての状態は不可能であるため、0 から始まります。 
3. 各候補を 1 つずつ処理します。 確率が p の候補者については、委員会に含めるかどうかを検討します。 
4. j = K から 1 まで逆順に選択カウントを更新します。これにより、まだ必要な状態がより小さい j から上書きされるのを防ぎ、各候補が最大 1 回使用されるようにします。 
5. サイズ j のグループに候補を含める場合、ソース分布として dp[j−1] を使用して dp[j] を更新します。 dp[j−1] 内のすべての可能な投票数 t について、候補者が確率 p で賛成に投票してカウントを t+1 に増やすか、または確率 (1 − p) でノーに投票してカウントを t に保つか、という 2 つの結果に分割します。 これは、新しいディストリビューションを構築する畳み込みステップです。 
6. すべての候補を処理した後、dp[K][K/2] を答えとして読み取ります。 

### なぜ効果があるのか

 DP は、処理された接頭語からのサイズ j のサブセットを使用して、選択された人々 j のすべての可能な数について、投票合計に対する達成可能な最良の確率分布を維持します。 サイズ j のすべてのサブセットは、サイズ j−1 のサブセットを現在の要素で拡張するか、スキップすることによって形成されるため、遷移は投票の独立性を正しく考慮し、最適性を維持します。 この反復ではすべてのサブセット構造が 1 回だけ表現されるため、最終的な dp[K][t] はサイズ K のすべての有効な委員会を集約し、t = K/2 をとることで同点イベントを分離します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N, K = map(int, input().split())
        P = list(map(float, input().split()))

        dp = [[0.0] * (K + 1) for _ in range(K + 1)]
        dp[0][0] = 1.0

        for p in P:
            for j in range(K, 0, -1):
                for t in range(j - 1, -1, -1):
                    if dp[j - 1][t] == 0:
                        continue
                    dp[j][t] += dp[j - 1][t] * (1 - p)
                    dp[j][t + 1] += dp[j - 1][t] * p

        ans = dp[K][K // 2]
        print(f"Case #{tc}: {ans:.10f}")

if __name__ == "__main__":
    solve()
```DP 配列は、dp[j][t] が常に正確に j 人を選択し、t 個の賛成票を蓄積したことに対応するように構造化されています。 順方向反復では 1 回の反復で同じ候補を複数回使用でき、正確性が損なわれるため、j に対する逆方向反復は不可欠です。 

内部遷移は、確率質量を「はい」と「いいえ」の結果に明示的に分割し、合計の確率質量を保持し、各候補の後で分布が有効なままであることを保証します。 

## 実用的な例

 K = 2、確率 [0.5, 0.5] の場合を考えてみましょう。 

最初の候補を処理した後、dp[1] は 0 の賛成票の 0.5 の確率と 1 つの賛成票の 0.5 の確率を反映します。 2 番目の候補を追加した後、dp[2][1] は両方の (0 Yes、1 Yes) 遷移からの寄与を蓄積します。 

| ステップ | 選択された j | t | 更新後の dp[j][t] |
 | --- | --- | --- | --- |
 | 一人称 | 1 | 0 | 0.5 |
 | 一人称 | 1 | 1 | 0.5 |
 | 2人目 | 2 | 0 | 0.25 |
 | 2人目 | 2 | 1 | 0.50 |
 | 2人目 | 2 | 2 | 0.25 |

 最終的な同点確率 dp[2][1] は 0.5 で、予想される対称性と一致します。 

次に、確率 [0.0, 1.0] で K = 2 を考えます。 有効な委員会には両方の人物が含まれている必要があります。 1 つ目は常に「いいえ」に投票し、2 つ目は常に「はい」に投票するため、結果は決定的に 1 つが「はい」、もう 1 つが「いいえ」になります。 

| ステップ | 選択された j | t | dp[j][t] |
 | --- | --- | --- | --- |
 | 両方の後 | 2 | 1 | 1.0 |

 これにより、決定論的な極値が正しく処理され、確率が 0 または 1 の場合、DP は自然に不確実性を解消することが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N · K^2) | N 個の候補者のそれぞれが最大 K 個の選択状態を更新し、それぞれが最大 K 個の投票数を更新します。 
| スペース | O(K^2) | DP テーブルには、各選択サイズの分布が格納されます。 

この制約により、K は最大 200、N は最大 200 まで許可されるため、最適化された Python ではテスト ケースごとに約 800 万の DP 遷移が実現可能になります。 最大 100 のテスト ケースであっても、一般的な入力は十分にまばらであるため、効率的なループの下では制限内に収まります。

 ## 特殊なケース

 重要なエッジ ケースは、すべての確率が 0 または 1 である場合です。このような場合、DP は不確実性を蓄積せず、1 つの投票パターンのみが残ります。 たとえば、確率 0 および 1 で 2 2 を入力すると、すべての選択が固定結果につながるため、強制的に dp[2][1] = 1 になります。 DP 遷移は依然として両方の分岐を処理しますが、すべての確率質量は決定論的に単一の状態に流れ込みます。 

もう 1 つの微妙なケースは、K が N に比べて小さく、最適な選択によって「平均」確率が完全に回避される場合です。 DP は単調性や局所的な最適性を想定していないため、これを正しく処理します。 状態の伝播を通じて、すべてのサブセット構成を暗黙的に評価します。
