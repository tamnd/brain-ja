 ## 解決策
 ## 問題の理解

 片側にワーカー、もう一方にマシンを配置した 2 部構成のシステムが与えられており、どちらもサイズが異なります。$N$。 各ワーカーは最初、マシンの一部の操作方法を知っています。 毎日、すべての従業員が任意の順序で到着します。 従業員が到着すると、まだ割り当てられていないマシンを確認し、その中から任意に 1 台を選択します。 マシンが取得されると、その日はそのマシンが割り当てられたままになります。 

新しい「トレーニング エッジ」を追加することが許可されています。これは、ペアごとに 1 のコストで任意のワーカーに任意のマシンを教えることができ、二部グラフに効果的にエッジを追加できることを意味します。 目標は、ワーカーがどのように順序付けられているか、マシンを選択するときにどのように関係が切れているかに関係なく、プロセスの最後にはすべてのマシンが 1 人のワーカーに割り当てられることを保証することです。 

主な問題点は、攻撃者が到着順序と利用可能なマシンの選択の両方を制御していることです。 つまり、グラフ内の脆弱な構造が悪用されて強制的に障害が発生する可能性があります。 

制約$N \le 25$サブセットを列挙したり、サイズの状態をシミュレートしようとするソリューションを提案します。$2^N$潜在的に許容される可能性がありますが、存在する場合には、より単純な構造観察の余地も残されています。 

作業者がマシンを知らないときは必ず、微妙な障害が発生します。 静的グラフに完全な一致が存在する場合でも、貪欲なプロセスは、後で必要な割り当てをブロックする「初期の悪い選択」を行うことによって、それを破壊する可能性があります。 

たとえば、労働者の場合、$A$マシン 2 を操作することはできませんが、作業者は操作できます$B$両方のマシンを操作できる場合、$B$最初に到着し、マシン 1、ワーカーを選択します$A$その後、マシン 1 も強制的に取得されるか、アイドル状態になり、マシン 2 が割り当てられないままになります。 完全に一致するものが存在するだけでは十分ではありません。 システムは、あらゆる貪欲な実行に対して堅牢である必要があります。 

この堅牢性の要件がソリューションの原動力となります。 

## アプローチ

 自然な出発点は、2 部グラフでの貪欲なマッチングの観点から考えることです。 このプロセスは、標準的なオフライン マッチングの問題ではありません。 代わりに、これは敵対的な注文と敵対的なタイブレークを備えたオンラインプロセスです。 

貪欲なマッチングが常に成功するタイミングを特徴づけることができます。 これはすぐに、すべてのプレフィックスとすべてのサブ選択肢に対してホール条件のような構造的制約を強制しようとすることにつながります。 ただし、作業者は利用可能な複数のマシンの中から任意に選択する可能性があるため、システムは、ある順序だけでなく、考えられるすべての破壊的な選択順序の下でも正しい状態を維持する必要があります。 

グラフの修正を考える強引な方法は、エッジを追加して、考えられるすべての到着順序と選択肢をシミュレートすることを検討することです。 構成ごとに、考えられるすべての貪欲な実行で完全な一致が得られるかどうかを検証します。 これは組み合わせ的に爆発的に増加します。固定グラフの場合でも、可能な実行数は順列と分岐の選択肢の両方で指数関数的になります。 

重要な観察は、エッジが欠落していると、悪用される可能性のある潜在的な障害点が発生するということです。 労働者だと仮定します$i$機械を知りません$j$。 システムがまだ安全だと主張するには、そのマシンを見せなければなりません$j$以前の任意の割り当てによって「失われる」ことはありません。 しかし、初期のワーカーは実現可能性を維持するために必要な代替マシンをすべて消費する可能性があるため、攻撃者はいつでも次のような構成を強制できます。$j$を除く残りのすべての労働者から隔離されます。$i$、 そして$i$それは取れません。 それは避けられない失敗を生み出します。 

この推論により、非常に強力な結論が導き出されます。つまり、任意の貪欲な動作の下で正確性を保証するには、すべてのワーカーがすべてのマシンを操作できなければなりません。 それが事実であれば、残っているワーカーは常に、残っているマシンを受け入れる完全な柔軟性を備えているため、いかなる選択肢も実現可能性を排除することはできません。 

したがって、最適な戦略は、不足しているワーカー マシン エッジをすべて追加して、単純に 2 部グラフを完成させることです。 

答えは、行列内のゼロエントリの数になります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. を読んでください。$N \times N$どのワーカーがどのマシンを操作できるかを説明するマトリックス。 各「1」は既存のエッジ、各「0」は欠落したエッジです。 
2. 何ペアか数えます$(i, j)$マトリックスにゼロが含まれています。 このような各ペアは、欠落している機能を表します。 
3. 堅牢性を保証するには、欠落しているエッジをすべて追加する必要があるため、このカウントをコストとして出力します。 

### なぜ効果があるのか

 ワーカーとマシンのペアが欠落している場合、慎重に選択された到着順序に基づいて、そのペアが強制的なボトルネックになる可能性があります。 攻撃者は、マシンに唯一残っている安全な割り当てに欠落エッジが必要となるような方法で、他のすべてのワーカーが代替マシンを確実に消費するようにすることができます。 その割り当ては不可能であるため、システムが完了することは保証できません。 

すべてのエッジが存在すると、現在の部分的な割り当てに関係なく、すべてのワーカーは常にすべてのマシン間で完全な自由を得ることができます。 貪欲な選択を連続して行っても、マッチングを完了できなくなることはありません。これは、マシンが 1 台だけ残る最後のステップまで、ワーカーが有効なオプションを使い果たすことがないためです。 

これにより、考えられるすべての障害モードが排除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        n = int(input())
        ans = 0
        for _ in range(n):
            row = input().strip()
            ans += row.count('0')
        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    solve()
```コードは、追加する必要があるトレーニング エッジの数を直接カウントします。 各行は 1 回スキャンされ、欠落している機能ごとに 1 ドルが答えに貢献します。 書式設定は、必要な出力スタイルに従います。 

このソリューションは欠落している接続の総数のみに依存するため、追加のデータ構造は必要ありません。

 ## 特殊なケース

 ワーカーが最初にマシンを知らない場合、そのワーカーに関係する欠落しているエッジをすべて追加する必要があります。 これらのエッジがないと、ワーカーは命令に関係なく永久にアイドル状態になる可能性があります。 

マシンを知っているワーカーがいない場合は、そのマシンに関係する欠落しているエッジもすべて追加する必要があります。追加しないと、そのマシンを割り当てることはできません。 

どちらの状況でも、アルゴリズムは自然にすべて 0 をカウントし、これらの病理学的構成が完全に修復されることを保証します。
