 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの整数シーケンスが与えられます。 インデックスの任意の連続セグメントから、最初の配列で選択したセグメントの合計と 2 番目の配列で選択したセグメントの合計という 2 つの値を計算できます。 したがって、各セグメントは、各配列から 1 つずつ、数値のペアを生成します。 

タスクは、両方の合計を二乗して加算することによって形成される数量ができるだけ小さくなるように、単一の連続セグメントを選択することです。 幾何学的には、各セグメントは 2 次元平面内の点に対応し、ユークリッドの二乗距離の観点から原点に最も近い点を探します。 

この制約により、最大 50 万の要素が許可されます。 すべての部分配列に対する二次関数のアプローチでは、N 平方セグメントのオーダーを試行することになりますが、これは実現可能な限界をはるかに超えています。 軽い定数係数を使用した O(N^2) のアルゴリズムでも、最悪の場合は約 10^11 の演算を試行することになり、2 秒以内に実行することはできません。 これにより、すべてのセグメントを明示的に列挙することを回避する方法で問題を解釈することが直ちに強制されます。 

素朴な貪欲なアイデアについて推論するときに、微妙な問題が発生します。 一方の配列の合計が小さくても、もう一方の配列の大きさが大きいセグメントでも、1 つの座標のみを最小化するセグメントよりも優れている可能性があります。 たとえば、A-sum のみを最小化するセグメントを選択すると、B の寄与が完全に無視され、真の最適値を逃す可能性があります。 もう 1 つの失敗例は、目的がセグメント長において単調ではないため、ウィンドウを貪欲に縮小または拡張しようとすることです。 

重要な問題は、すべてのセグメントが 2 つの独立した累積和に依存しているため、配列によって引き起こされる 2 次元構造を実際に最適化していることです。 

## アプローチ

 ブルートフォース手法は簡単です。 エンドポイント L と R のすべてのペアを反復し、その間隔で A と B の合計を計算し、目的を評価します。 プレフィックス合計を使用すると、各クエリが O(1) に減りますが、L と R の選択肢は依然として O(N^2) あり、最悪の場合は約 10^11 の評価が必要になります。 これでは遅すぎます。 

重要な観察は、サブ配列の合計がプレフィックスの合計を使用して書き換えられるということです。 SA[i] と SB[i] をプレフィックスの合計とする。 次に、セグメント [L, R] の合計は SA[R] から SA[L−1] を引いたものになり、B についても同様です。したがって、各セグメントは 2D 平面内の 2 つの接頭点間の差に対応します。 

P[0] = (0, 0) を含む点 P[i] = (SA[i], SB[i]) を定義すると、すべてのセグメントは P[R] − P[L−1] に対応します。 目的は、このプレフィックス合計点セット内の 2 点間の二乗距離になります。 したがって、問題は、2 次元の N+1 点の中から最も近い点のペアを見つけることになります。 

これにより、問題は、平面内の最も近い点のペアという古典的な計算幾何学タスクに変換されます。 分割統治アプローチでは、x 座標でソートされた半分を再帰的に解き、両方の半分の候補がより近いペアを形成する可能性がある狭い垂直ストリップのみをチェックすることで、O(N log N) を達成します。 そのストリップ内では、y 座標でソートすることで効率的な比較が可能になります。 

プレフィックス ポイントには任意の座標であること以外に特別な制約がないため、これより単純な 1 次元のトリックは適用されないため、これはまさに必要な構造です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) | O(1) 追加 (またはプレフィックス合計付き O(N)) | 遅すぎる |
 | 最適 (最も近いペア) | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレフィックス合計配列 SA および SB を構築し、0 から N までの i に対してポイント P[i] = (SA[i], SB[i]) を構築します。 

これにより、すべての部分配列が 2 点間の差に変換され、直接的な間隔の処理が不要になります。 
2. すべての点を X 座標で並べ替えます。

この順序付けは、バランスのとれたジオメトリで問題を左半分と右半分に分割するために必要です。 
3. x でソートされた点のセグメントを取得し、そのセグメント内の最小二乗距離と、y 座標でソートされた同じ点のリストの両方を返す再帰関数を定義します。 

y でソートされたリストは、境界を越えた候補セットを効率的に構築するために重要です。 
4. セグメント サイズが小さい場合は、すべてのペアごとの距離を直接計算して戻ります。 

基本ケースが小さいと、再帰のオーバーヘッドが回避され、さらに分割するよりも高速になります。 
5. X 座標の中央値によって点を左半分と右半分に分割し、両方の半分を再帰的に解決します。 

各半分は独立して最適な内部ペアを見つけます。 
6. マージ ステップ: 分割線からの x 距離が、これまでに見つかった最適な距離よりも短い点を収集します。 

x 内でさらに離れたペアは現在の最適二乗距離をすでに超えている必要があるため、これらの点のみが境界を越えるより適切なペアを形成できます。 
7. このストリップを y 座標でソートし、各ポイントを y 順序で次のいくつかのポイントと比較します。 

幾何学的パッキング引数により、ポイントごとに一定数の比較のみが必要になることが保証されます。 
8. 左半分、右半分、および境界を越えたチェックの間で見つかった最良の距離を、より高い再帰レベルの y でソートされたリストとともに返します。 

最終的な答えは、すべての再帰レベルにわたって見つかった最小二乗距離です。 

### なぜ効果があるのか

 すべてのサブ配列はプレフィックス ポイントのペアに一意に対応するため、サブ配列の二乗和を最小化することは、すべてのプレフィックス ポイントの中から最も近いペアを見つけることと同じです。 分割統治ステップでは、候補ペアが完全に半分の内側にあるか、分割を越えていることが保証されます。 垂直方向のストリップに対する境界を越える制限は有効です。なぜなら、水平方向の分離が大きいペアは、現在の最適値よりも大きな二乗距離をすでに持っている必要があるからです。 ストリップ内では、y 順序での比較の制限は幾何学的パッキングに依存します。近すぎる点が多すぎると、そのうちの 2 つが現在の最適点よりも近くなることが強制され、最適性に矛盾します。 これにより、二次比較を回避しながら正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))

    px = 0
    py = 0
    pts = [(0, 0)]

    for i in range(n):
        px += A[i]
        py += B[i]
        pts.append((px, py))

    pts.sort(key=lambda x: x[0])

    def dist2(p1, p2):
        dx = p1[0] - p2[0]
        dy = p1[1] - p2[1]
        return dx * dx + dy * dy

    def closest(arr):
        m = len(arr)
        if m <= 3:
            best = float('inf')
            for i in range(m):
                for j in range(i + 1, m):
                    best = min(best, dist2(arr[i], arr[j]))
            return best, sorted(arr, key=lambda x: x[1])

        mid = m // 2
        midx = arr[mid][0]

        left = arr[:mid]
        right = arr[mid:]

        d1, ly = closest(left)
        d2, ry = closest(right)
        d = min(d1, d2)

        merged_y = []
        i = j = 0
        while i < len(ly) and j < len(ry):
            if ly[i][1] < ry[j][1]:
                merged_y.append(ly[i])
                i += 1
            else:
                merged_y.append(ry[j])
                j += 1
        merged_y.extend(ly[i:])
        merged_y.extend(ry[j:])

        strip = []
        for p in merged_y:
            if (p[0] - midx) * (p[0] - midx) <= d:
                strip.append(p)

        for i in range(len(strip)):
            for j in range(i + 1, len(strip)):
                if (strip[j][1] - strip[i][1]) * (strip[j][1] - strip[i][1]) > d:
                    break
                d = min(d, dist2(strip[i], strip[j]))

        return d, merged_y

    ans, _ = closest(pts)
    print(ans)

if __name__ == "__main__":
    solve()
```コードは、配列を接頭辞合計ポイントに変換することから始まります。これは、問題を幾何学的にする構造的な変化です。 再帰関数は、y 座標でソートされたポイントを常に返すという不変条件を維持します。これは効率的なストリップ処理に不可欠です。 

ストリップ構造では、現在の最良値に対する二乗距離の比較が使用され、浮動小数点演算が完全に回避されます。 内側のループの初期のブレークは、y でソートされた順序に依存しており、近くの候補のみを比較することが保証されます。 

微妙な点は、再帰によって最適な距離と y でソートされたリストの両方が返されることです。 再帰レベル全体で y 順序を維持しないと、マージ ステップのコストが高くなり、O(N log N) の保証が破られます。

 ## 特殊なケース

 単一要素の配列は、自明ではない最も単純なケースです。 このアルゴリズムは、プレフィックス ポイント (0,0) および (A1,B1) を処理し、それらの二乗距離を唯一の候補として正しく評価します。 

すべての値がゼロの場合、すべてのプレフィックス ポイントは原点に折りたたまれます。 最も近いペアの距離は再帰を通じてゼロのままであり、すべての距離がゼロであるため、ストリップによって無効な比較が生成されることはありません。 

交互符号配列では、複数のプレフィックス ポイントが一致するか、非常に近くなります。 比較は純粋に幾何学的なものであり、座標の一意性を想定していないため、ストリップ ロジックは依然として正しく機能します。
