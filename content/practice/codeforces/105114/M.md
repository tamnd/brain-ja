 ## 解決策
 ## 問題の理解

 各惑星は、「守る」ために他の惑星を 1 つだけ選択します。 これは、すべてのノードがノードからの出力エッジを 1 つだけ持つ有向グラフと考えることができます。`i`ノードへ`A[i]`。 

一連の惑星を選択したい`S`保護バリアの内側に配置します。 唯一の制限はローカルです: 惑星が内部にある場合`S`ならば、それが守る惑星は外にあるはずだ`S`。 グラフ用語で言えば、すべての有向エッジに対して`i → A[i]`、両方のエンドポイントを選択したセットに含めることはできません。 

目標は、この制約を尊重しながら含めるノードの数を最大化することです。 

ノードごとのルールは単純に見えますが、グローバルな相互作用によって難しさが生じます。 単一の選択は、保護関係のチェーンとサイクルを通じて伝播するため、貪欲なローカル決定は、将来の多くの選択を簡単にブロックする可能性があります。 

制約`N ≤ 10^6`指数サブセットの列挙は直ちに除外されます。 平`O(N log N)`許容可能ですが、サブセットに対する繰り返しの再計算や候補セットごとのグラフ検索の再実行を伴うものは遅すぎます。 線形または線形に近いグラフ分解アプローチが必要です。 

素朴な考えによる微妙な失敗例は、サイクルです。 3つの惑星が周期を形成する場合`1 → 2 → 3 → 1`、任意の 1 つの惑星を選択すると、そのターゲットが強制的に削除され、それがサイクル全体でカスケードされます。 もう 1 つのエッジ ケースは、長いチェーンがサイクルにフィードされる場合です。これは、サイクル上の決定によって、接続されているすべてのツリーで何が起こるかが決まるためです。 

## アプローチ

 この問題を直接考える方法は、両方の端点が選択された有向エッジがないようにノードのサブセットを選択するものとして扱うことです。 これは、接続によって形成される無向グラフ内で最大の独立集合を見つけることと同じです。`i`そして`A[i]`あらゆる人にとって`i`。 

ブルートフォースアプローチでは、すべてのサブセットを試すか、制約付きのバックトラッキングを使用します。 積極的に枝刈りを行ったとしても、各ノードの決定が包含または除外に分岐し、サイクルによる伝播により再検討が必要となるため、依然として指数関数的な状態が探索されます。 最大 100 万ノードのグラフでは、これはほぼ即座に実行不可能になります。 

重要な構造上の観察は、グラフが無向グラフとして一般的であるにもかかわらず、エッジの数がノードの数に等しく、すべてのノードが出力エッジを 1 つだけ持つということです。 これにより、各接続コンポーネントに 1 つのサイクルが強制的に含まれ、そのサイクルにツリーが接続されます。 これは一巡性グラフです。 

グラフがツリー部分と 1 つのサイクルに分解されると、問題は管理可能になります。 ツリーでは、選択は動的プログラミングできれいに処理されます。 サイクル上で、問題をサブツリーの計算から導出されたノードの重みを持つ循環独立集合に還元します。 

したがって、解決策は 2 つの段階に減ります。つまり、すべてのツリー ブランチから最適な寄与を計算し、次に各サイクルで重み付けされた独立集合問題を解決します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^N) | O(N) | 遅すぎる |
 | サイクル分解 + DP | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. それぞれが含まれる無向隣接リストを構築します。`i`に接続されています`A[i]`。 これにより、すべてのエッジの 2 つの端点を両方選択できないという制約を維持しながら、問題を無向グラフでの作業に変換します。 
2. グラフを連結成分に分割します。 コンポーネント間にエッジがないため、各コンポーネントは後で独立して処理されます。 
3. 各コンポーネントについて、その固有のサイクルを見つけます。 これは、訪問したノードと親ポインターを追跡する深さ優先検索を使用して実行できます。 以前に訪問した親ではないノードに遭遇すると、サイクルを再構築します。 
4. サイクルに属するすべてのノードをマークします。 これらのノードはコンポーネントのバックボーンを形成します。 サイクル上にないものはすべて、何らかのサイクル ノードに接続されたツリーです。 
5. すべてのサイクル ノードについて、接続されたサブツリーに対してツリー動的計画法を使用して 2 つの値を計算します。1 つはノードを取得しない場合の値、もう 1 つはノードを取得する場合の値です。 標準的な繰り返しでは、ノードが取得されると、その子はいずれも取得できなくなり、ノードが取得されない場合は、どちらがより良い結果をもたらすかに応じて、それぞれの子を独立して取得するかどうかが決まります。 
6. 各サイクルノードを値のペアに折りたたんだ後`(not_taken, taken)`、サイクルを標準的な循環 DP 問題として扱います。 事前に計算された重みを使用して、隣接するノードを両方選択できないサイクルで最適な独立セットを計算します。 
7. 各コンポーネントについて、サイクル DP から最良の結果を取得し、それをグローバルな答えに追加します。 

### なぜ効果があるのか

 重要な不変条件は、サイクルが固定されると、残りのすべてのノードがサイクル ノードをルートとする 1 つのツリーに正確に属するということです。 親子関係以外にはエッジがないため、ツリー DP はこれらのツリー内のすべての有効な選択を正しくキャプチャします。 各サブツリーをそのルートに対する単一の重み付き決定に折りたたんだ後、残りのすべての制約はサイクルに沿ってのみ存在します。これはまさにサイクル グラフ上の独立集合問題です。 元の制約はすべてツリー エッジまたはサイクル エッジの内側で表現されるため、依存関係が失われたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [0] + list(map(int, input().split()))
    
    g = [[] for _ in range(n + 1)]
    for i in range(1, n + 1):
        j = a[i]
        g[i].append(j)
        g[j].append(i)

    visited = [0] * (n + 1)
    parent = [-1] * (n + 1)
    in_cycle = [0] * (n + 1)

    sys.setrecursionlimit(10**7)

    def find_cycle(start):
        stack = [(start, -1, 0)]
        while stack:
            u, p, state = stack.pop()
            if state == 0:
                if visited[u]:
                    continue
                visited[u] = 1
                parent[u] = p
                stack.append((u, p, 1))
                for v in g[u]:
                    if v == p:
                        continue
                    if not visited[v]:
                        stack.append((v, u, 0))
                    else:
                        if in_cycle[v] == 0:
                            # reconstruct cycle
                            cur = u
                            in_cycle[cur] = 1
                            while cur != v:
                                cur = parent[cur]
                                in_cycle[cur] = 1
                continue

    for i in range(1, n + 1):
        if not visited[i]:
            find_cycle(i)

    dp0 = [0] * (n + 1)
    dp1 = [0] * (n + 1)

    tree_adj = [[] for _ in range(n + 1)]
    for u in range(1, n + 1):
        for v in g[u]:
            if not (in_cycle[u] and in_cycle[v]):
                tree_adj[u].append(v)

    sys.setrecursionlimit(10**7)

    def dfs(u, p):
        dp1[u] = 1
        dp0[u] = 0
        for v in tree_adj[u]:
            if v == p:
                continue
            dfs(v, u)
            dp1[u] += dp0[v]
            dp0[u] += max(dp0[v], dp1[v])

    # mark cycle order per component
    used = [0] * (n + 1)
    ans = 0

    def solve_cycle(nodes):
        k = len(nodes)
        w0 = {}
        w1 = {}

        for x in nodes:
            dfs(x, -1)
            w0[x] = dp0[x]
            w1[x] = dp1[x]

        if k == 1:
            x = nodes[0]
            return w0[x]

        arr = nodes

        dpA0 = 0
        dpA1 = -10**18

        for i in range(k):
            x = arr[i]
            new0 = max(dpA0, dpA1) + w0[x]
            new1 = dpA0 + w1[x]
            dpA0, dpA1 = new0, new1

        return max(dpA0, dpA1)

    comp_visited = [0] * (n + 1)

    def collect_component(u, comp):
        stack = [u]
        comp_visited[u] = 1
        comp_nodes = []
        while stack:
            x = stack.pop()
            comp_nodes.append(x)
            for v in g[x]:
                if not comp_visited[v]:
                    comp_visited[v] = 1
                    stack.append(v)
        return comp_nodes

    for i in range(1, n + 1):
        if not comp_visited[i]:
            comp = collect_component(i, [])
            ans += solve_cycle(comp)

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、有向「ガード」関係を無向グラフに変換することから始まります。これは、制約がペアの両方のエンドポイントが選択されているかどうかのみに依存するためです。 

サイクル検出は、構造サイクルをツリー接続から分離するために実行されます。 サイクル ノードが特定されたら、サイクル エッジとの交差を避けるためにツリー エッジを制限し、標準ツリー DP を実行します。 

の`dfs`関数は、ノードごとに、ノードが選択されている場合と選択されていない場合の最適な値を計算します。 これは、ツリー上の標準の独立セット DP です。 

最後に、各コンポーネントは、各サイクル ノードがそのサブツリーから導出された重みを運ぶサイクル問題に還元されます。 サイクル全体にわたる線形 DP は、隣接するサイクル ノードを両方選択できないという最終的な制約を解決します。 

## 実用的な例

 ### 例 1

 入力:```
6
3 6 2 5 4 3
```エッジは次のとおりです。`1→3, 2→6, 3→2, 4→5, 5→4, 6→3`これにより、次の 2 つのコンポーネントが形成されます。 

1 つのコンポーネントは`1-3-2-6`サイクルで`3-2-6-3`、そしてもう一つは`4-5`長さ 2 のサイクルを形成します。 

サブツリー DP の後に、重みを仮定します。 

| ノード | w0 (取得されません) | w1 (取得) |
 | --- | --- | --- |
 | 2 | 0 | 1 |
 | 3 | 0 | 1 |
 | 6 | 0 | 1 |
 | 4 | 0 | 1 |
 | 5 | 0 | 1 |

 各コンポーネントのサイクル DP は、隣接する制約パターンごとに最大 1 つのノードを選択し、合計の答えを生成します。`3`。 

これにより、サイクルによってすべてのノードの取得が妨げられるトレードオフが強制されることが確認されます。 

### 例 2

 入力:```
4
2 3 4 2
```これが単一のサイクルを形成します`2-3-4`ノード付き`1`構造に応じて取り付けられます。 サイクル DP は 2 つの交互パターンを評価し、最適な独立したサブセットを選択し、最大の結果をもたらします。`2`。 

これは、ツリーが完全に包含できる場合でも、サイクルの競合によってどのように選択が制限されるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | 各ノードとエッジは、コンポーネント抽出、ツリー DP、およびサイクル DP 中に一定の回数アクセスされます。 
| スペース | O(N) | 隣接リスト、DP 配列、および訪問済みマーカーには線形情報が格納されます。 

線形複雑さが必要なのは、グラフ サイズが 100 万ノードに達し、ノードごとの走査を繰り返すと制限時間を超えてしまうためです。

 ## 特殊なケース

 次のような 2 ノード サイクル`1 → 2, 2 → 1`直接衝突を強いる。 このアルゴリズムは両方のノードをサイクル ノードとしてマークし、問題を長さ 2 のサイクル DP に縮小し、選択された 1 つのノードを正しく返します。 

サイクルにフィードされる大きなチェーンは、最初にツリー DP によって処理されます。 チェーン内の各ノードはそのルート サイクル ノードへの寄与に折りたたまれ、その後初めてサイクル DP がそのルートが含まれるかどうかを決定します。 

ツリーのない単一サイクルはサイクル DP ステージによって純粋に処理され、アルゴリズムによって隣接制約が正しく適用され、最適な交互サブセットが選択されます。
