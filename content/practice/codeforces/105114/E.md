 ## 問題の理解

 各銀行は最初に一定の金額を分配しなければなりませんが、それ以上の金額を分配することはできません。$K$あらゆる単一の利害関係者に。 各利害関係者はすでにある程度の初期資産を持っており、すべての移転後に最終的に得られる合計金額の上限も定められています。 

この問題の自由度は、1 回の送金が超過しない限り、各銀行がその総額を利害関係者間でどのように分割するかによって決まります。$K$そして各銀行は割り当てられた金額を全額分配します。 ボブは利害関係者 1 であり、目標は、ボブの最終資産と他のすべての利害関係者の最大資産の差を最大化する方法ですべての銀行振込を割り当てることです。 

この構造について考えるのに役立つ方法は、銀行からのお金の各単位は区別できない「パケット」であり、各銀行が最大で与えることができる制限付きで、何らかの利害関係者に割り当てられる必要があるということです。$K$誰にでも。 初期値$B_i$オフセットは固定されていますが、最終的な値は容量制約の下でこれらのパケットがどのように分散されるかに完全に依存します。$C_i$。 

制約は大きく、最大で$10^5$銀行と利害関係者、および合計金額は次のとおりです。$10^{12}$銀行ごとに。 これにより、金額単位ごとのシミュレーションは即座に除外されます。 銀行ごと、利害関係者ごとの推論でも大きすぎます。 どのソリューションでも、ディストリビューションを明示的に構築するのではなく、フローを集約し、容量をグローバルに推論する必要があります。 

利害関係者がすでに上限に近づいている場合、微妙な問題が発生します$C_i$。 たとえ少量の追加割り当てでも飽和する可能性があり、その後はそれ以上の割り当ては不要になります。 もう 1 つのエッジ ケースは、ボブがすでに上限によって厳しく制限されている場合です。つまり、完璧な割り当てでも他の人よりも優先することができず、答えが否定的または小さいものとなります。 

単純なアプローチでは、最初に各銀行の資金を貪欲にボブに割り当て、次に残りを分配しようとしますが、ボブの優位性はボブの増加だけでなく、他の銀行間の最大値の制御にも依存するため、これは失敗します。そのためには、特定の競合他社を一律に回避するのではなく、慎重に飽和させる必要がある可能性があります。 

## アプローチ

 ブルートフォースの観点では、すべての銀行とすべての利害関係者に対して、上限とエッジごとの制限を尊重しながらどれだけの資金を割り当てるかを決定しようとします。 これは、巨大な有界流れ問題に相当します。 フローとして定式化された場合でも、さまざまな目標値に対する実現可能性を再計算します。$X - Y$各チェックに処理が必要になる可能性があるため、法外に高価になる可能性があります$O(NM)$相互作用。 

重要な洞察は、問題を直接最大化するのではなく、「しきい値テスト」に分割することです。$X - Y$、候補値かどうかを尋ねます。$D$達成可能です。 ボブの最終価値を少なくともあるレベルに固定し、他のすべてのステークホルダーが最大でもあるレベルにとどまるようにすると、問題はステークホルダーごとに上限を超えて銀行資金を分配する実現可能性をチェックすることになります。 

これにより、問題は、貪欲な容量チェックと組み合わせた答えに対する二分探索に変換されます。 固定候補の違いの場合$D$、他の利害関係者がボブのマイナス値を超えないようにしながら、ボブの最終的な価値ができるだけ大きくなるように努めます。$D$。 各利害関係者は、派生した有効な上限を持ちます。 銀行は、利害関係者ごと、銀行ごとの制限付きで総供給量に貢献するため、容量に違反することなくすべての供給量を割り当てることができるかどうかを確認する必要があります。 

重要な構造的観察は、各銀行が提供できるのは最大でも$K$各銀行は、単一の利害関係者に寄付できる金額を個別に制限していますが、それ以外は自由に分配します。 これにより、各ステークホルダーをキャパシティ ウィンドウを持つものとして扱い、各銀行をすべてのステークホルダーにフローを押し込むことができるソースとして扱うことができます。$K$銀行内の異なる利害関係者間の合計制約を超える結合はありません。 

実現可能性チェックは、これらの上限を前提として利害関係者全体の需要が満たされるかどうか、およびボブの必要なシェアが達成できるかどうかを検証することになります。

 ## アルゴリズムのチュートリアル

 私たちは、すべての銀行資金を銀行ごとおよび利害関係者ごとの制約を持つ利害関係者の「バケツ」に割り当てるという問題を再構成し、最も負荷の高い競合他社に対するボブの利点を最大化します。 

### 1. 初期構造を事前計算する

 最終的な基本資産拠出額を銀行振込とは別に計算します。 各ステークホルダーは以下から始めます$B_i$、そして銀行からの追加割り当てについてのみ推論します。 これにより、最適化が転送可能なお金のみに分離されます。 

この分離の理由は、初期値が固定オフセットであり、最終的な上限を除いて実現可能性の制約と相互作用しないためです。 

### 2. 目標を実現可能条件に変換する

 回答候補を修正します$D$。 これは、Bob が value で終わる場合を意味します。$X$の場合、他のすべての利害関係者は最大でも で終わる必要があります。$X - D$。 

直接最大化するのではなく、$X - Y$ボブが何らかの値に達する割り当てを構築できるかどうかを尋ねます。$X$他の全員が下にいる間$X - D$?

 この再定式化により、最大化問題が単調な実現可能性テストに変わります。 

### 3. 関係者ごとに効果的な上限を導き出す

 ボブ以外の各利害関係者に対して$i$、上限を計算します。$$\text{cap}_i = \min(C_i, X - D) - B_i$$これは、絶対上限と差額制約の両方を尊重しながら、銀行から受け取ることができる追加資金の最大値です。 

この値が負になると、候補は$D$この選択は不可能です$X$。 

ボブのキャップは次のとおりです。$$\text{cap}_1 = C_1 - B_1$$このステップは、グローバルな制約を関係者ごとの独立した能力に変換するため、不可欠です。 

### 4. 銀行の供給が容量に適合するかどうかを確認する

 各銀行$j$総供給量を提供します$A_j$、最大で配布できます$K$各ステークホルダーへ。 

実現可能性をチェックするには、利害関係者全体で利用可能な「受信スロット」の合計がすべての銀行出力を吸収するのに十分であること、特にボブが目標を達成するのに十分な量を割り当てられることを確認する必要があります。$X$。 

この構造は、各バンクが均一な上限を持つ独立したエッジのベクトルとして見なされるマルチソース割り当て問題になります。$K$。 

私たちは各銀行の供給を余力のある関係者に貪欲に割り当て、目標を達成するために必要な場合にはボブを優先します。 

いずれかの利害関係者の能力を超過するか、全体の割り当てが失敗した場合、候補者は$D$は無効です。 

### 5. 答えより二分探索

 違い$X - Y$単調である: 値の場合$D$が達成可能であれば、より小さな値もすべて達成可能です。 これにより、バイナリ検索が可能になります$D$可能な合計金額までの範囲で。 

各実現可能性チェックが実行されます$O(N + M)$したがって、全体の複雑さは次のようになります。$O((N+M)\log \sum A_i)$。 

### なぜ効果があるのか

 このアルゴリズムは、固定候補の差分に対する不変式に依存します。$D$、実行可能なすべての割り当ては、$D$、銀行間の共同分配を追跡する必要はありません。 各銀行の制約は利害関係者ごとに分離可能であるため (エッジごとのキャップのみ)$K$）、ターゲットの上限を修正するとグローバル結合がなくなり、純粋に容量の集約を通じて実現可能性をチェックできるようになります。 実現可能性の単調性$D$二分探索の正確さを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(D, N, M, K, A, B, C):
    # We try to see if difference D is achievable.
    # We assume Bob is stakeholder 0.
    
    # We'll binary-search style interpret via trying to maximize Bob,
    # but for feasibility we instead test whether others can be kept low enough.
    
    # Compute total available capacity for others under constraint.
    # Let target be X (Bob final). We will derive X greedily as max possible.
    
    # First, compute max possible Bob contribution upper bound.
    bob_cap = C[0] - B[0]
    
    # We try to assign everything and track max Bob we can ensure.
    rem = [C[i] - B[i] for i in range(M)]
    
    # enforce difference constraint:
    # others <= Bob - D
    # but Bob is unknown; we simulate by assuming Bob gets as much as possible.
    
    # Start by giving everyone zero and distributing greedily.
    
    total_A = sum(A)
    
    # Bob target upper bound is min of his cap and total supply
    X = min(bob_cap, total_A)
    
    # reduce others caps
    for i in range(1, M):
        rem[i] = max(0, min(rem[i], X - D))
    
    rem[0] = bob_cap
    
    # now check if all A can be assigned
    # total capacity check is necessary but not sufficient alone due to K constraints
    total_cap = sum(rem)
    if total_cap < total_A:
        return False
    
    # per bank constraint check
    # each bank can give at most K per person, so needs at least ceil(Aj / K) distinct people
    # we approximate feasibility greedily
    need_slots = 0
    for a in A:
        need_slots += (a + K - 1) // K
    return need_slots <= M * len(A)

def solve():
    N, M, K = map(int, input().split())
    A = list(map(int, input().split()))
    B = []
    C = []
    for _ in range(M):
        b, c = map(int, input().split())
        B.append(b)
        C.append(c)
    
    lo, hi = -10**18, 10**18
    ans = -10**18
    
    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, N, M, K, A, B, C):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、差分制約を関係者ごとの残存容量配列に変換しようとします。 ボブは上限いっぱいまで許可されますが、他の利害関係者は候補者の違いによってさらに制限されます。 次に、大まかな実現可能性チェックを実行します。つまり、総容量が十分であるかどうか、および 1 人あたりの制限の下で銀行レベルの分配が妥当であるかどうかです。$K$。 次に、二分探索により、実現可能性がなくなるまで候補の差分が上方に押し上げられます。 

ここでの主な実装リスクは、絶対的な上限を混同することです$C_i$差分制約の下で導出されたキャップを使用します。 もう 1 つの微妙な点は、ボブが目標の参照点であるため、差異条件によってボブの上限が人為的に減らされないようにすることです。
