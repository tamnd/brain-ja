 ## 解決策
 ## 問題の理解

 整数のリストが与えられたので、最大公約数が 1 より大きい異なる要素のペアが少なくとも 1 つ存在するかどうかを判断する必要があります。 より具体的に言えば、このタスクは、リスト内の少なくとも 2 つの異なる数値を分割する素数があるかどうかを尋ねます。 

入力サイズは大きく、最大 100 万個の整数があり、それぞれの整数は 100 億に達します。 これにより、ペアを直接比較するアプローチは即座に除外されます。 単純なペアごとの gcd チェックでは、およそ n²/2 回の比較が必要となり、これは最悪の場合約 10¹² の操作となり、時間制限内で実行できる量をはるかに超えます。 

値の大きさも重要です。 各数値は最大 10¹⁰ であるため、因数分解戦略はその境界の平方根 (10⁵) までのみ行う必要があります。 つまり、すべての入力値を完全に因数分解するには、最大 100000 までの素数を事前計算するだけで十分です。 

多くの数値が 1 に等しいか、ペアごとに互いに素である場合、微妙な失敗のケースが発生します。 たとえば、次のように入力します`1 1 1 1`生産すべき`NO`1 には素因数がないため、1 を超える gcd に寄与することはできません。繰り返される値を誤って自動的に有効なものとして扱う単純なアプローチでは、誤った値が返されます。`YES`共有素因​​数ではなく等価性のみをチェックする場合。 

もう 1 つの特殊なケースは、合成数が繰り返されることです。 例えば、`6 10 15`すべてのペアに共通の素因数を同時に共有するペアはありませんが、`6`そして`10`シェア2なので、正解はすでにあります`YES`。 正しい解法では、完全因数分解のグローバル共通部分だけでなく、任意のペアにわたる共有素数を検出する必要があります。 

## アプローチ

 ブルート フォース手法では、数値のすべてのペアをチェックし、その gcd を計算します。 これが機能するのは、gcd 計算が効率的であり、値のサイズがほぼ対数であるためです。 ただし、最大 100 万個の番号では、ペアの数は 5 × 10¹¹ 程度になるため、これは完全に不可能になります。 たとえ各 gcd 操作が非常に高速だったとしても、ペア列挙のスケールがすべてを支配します。 

重要な観察は、ペアが少なくとも 1 つの素因数を共有する場合、そのペアの gcd が 1 より大きくなるということです。 これにより、問題は数値間のペアごとの相互作用から、素因数の発生をグローバルに追跡することに変わります。 数値を直接比較する代わりに、各数値を因数分解し、すでに見た素数を記録します。 素数が別の数値で再び出現すると、有効なペアが存在することがすぐにわかります。 

これにより、問題は増分因数分解とハッシュ セット内のメンバーシップ チェックに変わります。 各数値は、平方根までの試算を使用して素数に分解されます。 因数分解中に、それぞれの異なる素因数がグローバル セットに対してチェックされます。 最初の繰り返しで答えが導き出されます。

 ## アルゴリズムのチュートリアル

 1. ふるいを使用して、100000 までのすべての素数を事前計算します。 10¹⁰ までの合成数は平方根以下の素因数を持つ必要があるため、これで十分です。 
2. 処理済みの数値にすでに出現している素因数を格納する空のセットを維持します。 このセットは、以前の要素によって「要求」されたすべての素数を表します。 
3. 入力内の各数値について、事前に計算された素数を使用して因数分解します。 因数分解中に、それぞれの異なる素因数を最大 1 回抽出します。 
4. 現在の数値の個別の素因数ごとに、それがグローバル セットにすでに存在するかどうかを確認します。 存在する場合は、すぐに出力します`YES`なぜなら、この素数は少なくとも 2 つの数値の間で共有されるからです。 
5. 素因数がまだセットにない場合は、素因数を挿入し、残りの数値の処理を続けます。 
6. 素因数の繰り返しが検出されずにすべての数値が処理された場合、出力`NO`。 

重要な考え方は、素数が少なくとも 2 つの異なる数値に現れるかどうかだけを気にするということです。 単一の数値内の多重度は重要ではないため、各素数が数値ごとに 1 回考慮されるようにします。 

### なぜ効果があるのか

 1 より大きいすべての整数は、一意に素因数に分解できます。 2 つの数値の gcd が 1 より大きい場合、少なくとも 1 つの素因数を共有する必要があります。 逆に、素因数が 2 つの異なる数値に現れる場合、それらの数値は自動的に少なくともその素数以上の gcd を持ちます。 したがって、数値全体にわたって素数の最初の出現を追跡することは、有効なペアを検出するために必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    if n <= 1:
        print("NO")
        return

    max_p = 100000

    is_prime = [True] * (max_p + 1)
    is_prime[0] = is_prime[1] = False
    primes = []

    for i in range(2, max_p + 1):
        if is_prime[i]:
            primes.append(i)
            step = i * i
            for j in range(step, max_p + 1, i):
                is_prime[j] = False

    seen = set()

    for x in arr:
        original = x
        for p in primes:
            if p * p > x:
                break
            if x % p == 0:
                if p in seen:
                    print("YES")
                    return
                seen.add(p)
                while x % p == 0:
                    x //= p
        if x > 1:
            if x in seen:
                print("YES")
                return
            seen.add(x)

    print("NO")

if __name__ == "__main__":
    solve()
```ふるいは最大 100000 までの素数のリストを作成します。これはすべての入力値を安全に因数分解するのに十分です。 処理中に、各数値はその素因数を除算することで削減され、各素数が数値ごとに 1 回だけ考慮されるようになります。 の`seen`set は、以前の数値にすでに関連付けられている素数を格納するため、繰り返しは共有因数を示します。 

ここでよくある間違いは、同じ数値内の重複する素因数を削除するのを忘れることです。 インナーなしで`while x % p == 0`ループの場合、12 のような数値は誤って素数 2 を 2 回登録し、誤って一致がトリガーされる可能性があります。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての数値が 1 である場合です。アルゴリズムは各数値を処理しますが、素数セットには何も挿入しないため、誤検知は発生せず、出力はそのまま残ります。`NO`。 

もう 1 つの特殊なケースは、次のような合成数が繰り返されることです。`8 8`。 最初の 8 は素数 2 をセットに挿入します。 2 番目の 8 は再び素数 2 を生成します。これはセット内にあり、すぐにトリガーされます。`YES`。 これは、単一の数値内ではなく、複数の位置にわたる重複を正しく処理することを示しています。 

最後のエッジケースは、数値がペアごとに互いに素であるが大きい場合です。`2, 3, 5, 7, 11`。 各素数は一度挿入され、再検討されることはないため、アルゴリズムは一致をトリガーすることなく正しく完了します。
