 ## 問題の理解

 文字列が与えられています$S$長さの$N$そして、そこから特別な「ジェネレーター」文字列を抽出したいと考えています。 キーと呼ばれるこのジェネレーターは、元の文字列のコピーを繰り返し配置する場合に元の文字列全体を再現できる最短の部分文字列として定義され、連続するコピー間の重複を許可します。 

このプロセスを考えるのに役立つ方法は、短いパターンから始めてそれをライン上にスタンプし続けるということですが、文字が重なる部分で一致する限り、新しいスタンプをそれぞれ左または右にシフトすることができます。 目標は、この重複する繰り返しプロセスを通じて完全な文字列を再構築するのに十分な内部構造をまだ保持している最小のパターンを見つけることです。 

制約$N \le 10^7$二次関数や偶数関数は即座に除外されます。$O(N \log N)$候補部分文字列を繰り返し試行し、シミュレーションによって検証するアプローチ。 どのソリューションも、時間とメモリの両方で文字列の長さが線形またはほぼ線形である必要があり、ネストされた比較や繰り返しの部分文字列抽出などの文字ごとの大きなオーバーヘッドも回避する必要があります。 

文字列に強い周期構造があるがシフトがある場合、微妙なエッジ ケースが発生します。 たとえば、次のような文字列`aaaaa`どの単一文字でも機能するので簡単ですが、次のようなものです`ababab`重複によって複数の解釈が示唆される場合でも、単純な繰り返し構造のように動作します。 もう 1 つの重要なケースは、文字列に完全なピリオドではない小さな境界構造がある場合です。たとえば、`ababa`ここで、接頭辞と接尾辞の等価性のみを使用する単純な周期的推論では、最小生成器の判断を誤ることになります。 

重要な問題は、オーバーラップによって純粋な周期タイリングよりも柔軟性が高まるため、慎重に正当化することがなければ、標準的な「文字列の最小周期」では十分ではないことです。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての部分文字列の長さを試します。$L$、 抽出する$S[0:L]$、この部分文字列のコピーを貪欲に配置し、重複によってすべての文字が一致するかどうかを確認することで、文字列全体の再構築を試みます。 候補者ごとに$L$、このシミュレーションは次のように劣化する可能性があります。$O(N)$、があるので、$O(N)$候補者の場合、全体の複雑さは次のようになります。$O(N^2)$、これは不可能です$10^7$。 

重要な洞察は、オーバーラップベースの再構成が実際には周期構造を超えた新しい表現力を導入するわけではないということです。 部分文字列がオーバーラップの下で完全な文字列を生成できる場合、その文字列はその部分文字列の繰り返しの位置合わせと一致している必要があり、これは完全な文字列に対する周期的な制約を意味します。 これにより、問題は、文字列の有効な期間のように動作する最小のプレフィックスを見つけることになります。 

これは、Knuth-Morris-Pratt アルゴリズムからの接頭辞関数スタイルの推論に直接接続されます。 サフィックスでもある最長の適切なプレフィックスは最大の内部反復構造をエンコードし、そこから最小のピリオド候補を導き出します。 プレフィックス関数を計算したら、最小期間を決定し、文字列がその期間の繰り返しで完全に構成されているかどうかを確認できます。 その期間の長さが答えです。 

有効なオーバーラップ構造は、キー長を法とするすべての位置で一貫した文字の配置を意味するため、オーバーラップの解釈には、この周期的な分解を超える追加の機構は必要ありません。

 ## アルゴリズムのチュートリアル

 プレフィックス関数を使用します$\pi[i]$、最長の適切なプレフィックスの長さを格納します。$S[0..i]$これはこの部分文字列の接尾辞でもあります。 

1. 文字列全体に対して左から右にプレフィックス関数を計算します。 各位置で、以前に計算された値を使用して最長の境界線を維持し、比較を再計算する代わりに構造を再利用します。 
2. 計算後$\pi[N-1]$、サフィックスでもある文字列全体の最も長い適切なプレフィックスがわかります。 この値を$k$。 
3. 最小の繰り返し単位の候補は$p = N - k$。 これは、文字列に長さの境界がある場合、という標準的な事実から来ています。$k$、その後、その周期はそのオーバーラップ量だけ減少します。 
4. 文字列がこのピリオドの長さと完全に一致しているかどうかを確認します。$p$。 実際には、これはプレフィックス関数の構造によってすでに保証されているため、$p$オーバーラップ構築時の分解に有効です。 
5. 戻る$p$答えとして。 

ステップ 4 で明示的な検証が必要ない理由は、prefix 関数が一貫性に必要なすべての接頭辞と接尾辞の制約をエンコードしているためです。 周期構造に矛盾があると、すでに境界計算が早期に中断されてしまいます。 

### なぜ効果があるのか

 プレフィックス関数は、文字列を最大の自己重複構造に分割します。 より短いキーが存在する場合$N - \pi[N-1]$の場合、境界線がより長くなります。$\pi[N-1]$、最大性に矛盾します。 逆に、長さの境界の存在$\pi[N-1]$ある長さのブロックを確実に繰り返す$N - \pi[N-1]$オーバーラップによって許容されるシフトの下で文字列をそれ自体と位置合わせします。 これにより、導出された期間が最小限かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    pi = [0] * n
    j = 0

    for i in range(1, n):
        while j > 0 and s[i] != s[j]:
            j = pi[j - 1]
        if s[i] == s[j]:
            j += 1
            pi[i] = j

    period = n - pi[-1]
    sys.stdout.write(str(period))

if __name__ == "__main__":
    solve()
```このソリューションは完全にプレフィックス関数配列によって駆動されます。`pi`。 ループはポインタを維持します`j`これは、前方にスキャンしながら、現在最も長く一致するプレフィックスを追跡します。 不一致が発生した場合、以前に計算されたプレフィックス長を使用してフォールバックするため、文字を最初から再チェックする必要がなくなります。 

最終的な値`pi[-1]`完全な文字列の最長の境界線をキャプチャし、それをから減算します。`n`最小繰り返し単位サイズが得られます。 実装では、スライスや部分文字列の操作は慎重に避けられます。これらの操作は遅すぎます。$N = 10^7$。

 ## 特殊なケース

 次のような単一文字列の場合`a`、接頭辞関数はすべてゼロなので、`pi[-1] = 0`そしてピリオドは`1`。 アルゴリズムは正しく 1 を返し、唯一の可能なキーは文字列自体であるという事実と一致します。 

次のような完全に均一な文字列の場合`aaaaaa`、すべての位置が境界線を拡張し、`pi[-1] = 5`長さ 6 で、期間 1 につながります。このアルゴリズムは、オーバーラップベースの再構成でも単一の文字で十分であることを捉えています。 

のような内部構造を持たない文字列の場合`abcde`、接頭辞関数は決して拡張されないため、`pi[-1] = 0`そして答えは次のようになります`N`。 これは、より短い重複ジェネレーターでは矛盾なく個別の文字を再構築できないという直観と一致します。
