 ## 解決策
 ## 問題の理解

 奥行きのある三角形のグリッドが与えられます$n$。 一番下の行には 1 つのセルが含まれており、その上の各行は両側に 1 つのセルずつ拡張されるため、一番上の行は次のようになります。$2n-1$細胞。 ボールは上の行のいずれかのセルにドロップされ、その後、下の行の 1 つのセルの下から出るまで、行ごとに決定的に移動します。 

ボールが列のセルから移動したとき$r$列まで$r+1$、通常は同じ列に続きます。 ただし、この移動ルールには 2 つの変更があります。 まず、ボールが行の左側の境界にある場合、ボールは降下する前に 1 セル右にシフトされます。 右境界にある場合は、1 セル左に移動します。 第二に、一部のセルにはコンベアが含まれており、ボールがそのようなセルに到着すると、すぐに同じ列内で左または右に 1 歩移動してから、下向きの動きを続けます。 

タスクは、テスト ケースごとに、一番上の列のどの開始位置が最終的にボールを一番下のセルから出るように導くかを決定することです。 

構造は大規模です:$n$まで可能です$10^5$、まであります$2 \cdot 10^5$テスト ケースごとの全体的なコンベア数、最大$10^4$テストケース。 これにより、開始位置ごとに個別にボールを追跡するシミュレーションは即座に除外されます。これにはコストがかかるためです。$O(n^2)$最悪の場合のテスト ケースごとに、実行可能な限界をはるかに超えています。 

微妙な難しさは、移動が単純な垂直方向の真っすぐな降下ではないことです。 各行には、コンベアによって引き起こされる局所的な水平方向の摂動と、パスを効果的に「折り畳む」境界反射が含まれています。 それぞれの開始位置を個別にシミュレートする単純な試みは失敗します。単一のパスには最大で$n$行遷移、および$O(n)$出発点。 

重要なエッジ状況の 1 つは、コンベアが境界を越えてボールを繰り返し押し出すときに現れます。 

たとえば、列に次のようなコンベアシーケンスがある場合、$c \rightarrow c+1$次のセルにはコンベヤーがあります$L$、慎重にモデル化されていない場合、単純な単一ステップの解釈では、連鎖した動きを誤って処理する可能性があります。 もう 1 つの問題は、境界の相互作用です。コンベアがなくても、左端または右端にあると次の列が変更されます。 

## アプローチ

 直接的な総当たりアプローチでは、最上列のすべての開始セルからのボールがシミュレートされます。 各シミュレーションは、すべてを詳しく説明します。$n$列を作成し、各ステップでコンベアの移動と境界調整を適用します。 あるので$2n-1$開始位置、これにはコストがかかります$O(n^2)$最悪の場合のテストケースごとに。 と$n = 10^5$、これは完全に不可能になります。 

重要な観察は、プロセスが機能していること、つまり行の各セルが機能していることです。$r$行内の正確に 1 つのセルに決定的にマッピングされます。$r+1$。 コンベヤーと境界ルールを解決した後、各行が機能を定義します$f_r$その行の列から次の行の列まで。 したがって、システム全体は次のような構成になります。$$f_1 \circ f_2 \circ \cdots \circ f_{n-1}$$開始ごとに順方向にシミュレーションするのではなく、視点を逆にします。 一番下の行には出口セルが 1 つあるため、逆方向に伝播できます。行内のどのセルを決定します。$n-1$出口に着くことができたら、どの列に並ぶか$n-2$、など上まで続きます。 各行は、同じサイズのセグメントの 2 つのレイヤー間のマッピング問題となり、コンベアはこれらのマッピングにローカルな変更のみを作成します。 

これにより、問題は一連の行単位の機能変換全体にわたる到達可能性の維持に変換され、各行では少数の局所的な中断 (コンベヤーごとに最大 1 つ) しか発生しません。 この構造により、行を独立して処理し、一連の「良好な」位置を行ごとに線形時間で上方に伝播することができます。

 ## アルゴリズムのチュートリアル

 各テスト ケースを下から上に処理し、最終的に出口に到達できる位置を行ごとに維持します。 

1. 一番下の行から始めます。 唯一の有効なエンドポイントはその単一セルであるため、それを到達可能としてマークします。 
2. 一度に 1 行ずつ上に移動します。 列で$r$、どの位置が行内の既知の到達可能な位置につながるかを判断したいと考えています。$r+1$。 これは、移動ルールを逆にすることによって行われます。つまり、状態を下に押し下げる代わりに、到達可能性を上に引き上げます。 
3. 特定の行に対して、最初にコンベア効果を組み込みます。 各コンベアは、同じ行内の 1 つの列からその隣の列へのローカル シフトを定義します。 これは、下降する前に、状態を一度左右に転送できることを意味します。 
4. コンベア調整を適用した後、逆に境界ルールを適用します。 行の境界の位置$r$行内のシフトされたエントリに対応します$r+1$したがって、後方に引くと、境界柱によって到達可能性が隣接する内部位置に分散されます。 
5. これらの遷移を結合して、行の新しいブール配列を計算します。$r$。 行内に有効な先行者が存在する場合、各位置は到達可能としてマークされます。$r+1$出口に到達できる。 
6. 一番上の行に到達するまで繰り返します。 結果として得られるブール配列は、どの開始位置が成功するかを直接返します。 

重要な考え方は、各行は構造をローカルでのみ変更するということです。 コンベアはそれぞれ 1 つのセルにのみ影響を与えるため、隣接関係にローカルな変更のみを導入し、境界ルールは均一です。 これにより、行ごとのグローバルな再計算が防止されます。 

### なぜ効果があるのか

 各セルには、コンベヤーと境界の影響を解決した後、次の行への前方遷移が 1 つだけあります。 これにより、システムは、すべてのノードが出次数 1 を持つ階層化された有向グラフになります。 到達可能性を下から上に計算すると、これらの決定論的な遷移を繰り返し適用して、最終的に終端ノードにマッピングされるノードのセットを効果的に計算していることになります。 行間のすべての変換はローカル ルールによって完全にキャプチャされるため、逆方向伝播では、曖昧さや分岐の爆発がなく、各層での正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())

        # store conveyors per row
        left = {}
        right = {}

        for _ in range(m):
            r, c, d = input().split()
            r = int(r)
            c = int(c)
            if d == 'L':
                left[(r, c)] = 1
            else:
                right[(r, c)] = 1

        # dp over rows, bottom starts with single position
        # row i has length 2*(n-i)+1, but we only track reachable set
        cur = set([1])  # bottom row

        for r in range(n - 1, 0, -1):
            length = 2 * (n - r + 1) - 1
            new = set()

            # expand each reachable position upward
            for c in cur:
                # reverse boundary effect
                if c == 1:
                    nc = 2
                    new.add(nc)
                elif c == length:
                    nc = length - 1
                    new.add(nc)
                else:
                    new.add(c)

            # apply conveyors inversely
            final = set()
            for c in new:
                if (r, c) in left:
                    final.add(c - 1)
                elif (r, c) in right:
                    final.add(c + 1)
                else:
                    final.add(c)

            cur = final

        # top row size is 2n-1
        ans = ['0'] * (2 * n - 1)
        for c in cur:
            if 1 <= c <= 2 * n - 1:
                ans[c - 1] = '1'

        print(''.join(ans))

if __name__ == "__main__":
    solve()
```このソリューションは、行ごとに到達可能な位置のセットを維持します。 一番下の行は、単一の出口セルで初期化されます。 次に、到達可能性を行ごとに上向きに伝播し、最初に境界効果を取り消してから、コンベアの反転を適用します。 最後のセットは、一番上の行の有効な開始位置に対応します。 

各行には異なるセル数があるため、行の長さには注意が必要です。 の計算`length`境界動作がすべてのレベルで正しく適用されるようにします。 

## 実用的な例

 次の小さなケースを考えてみましょう$n = 3$、下の行には 1 つのセルがあり、上の行には 5 つのセルがあります。 

行 2 に、中央のセルから右に押し出すコンベアがあるとします。 

到達可能な位置を追跡します。 

| 行 | 現在の到達可能なセット | 境界反転後 | コンベア後 |
 | --- | --- | --- | --- |
 | 3 | {1} | {1} | {1} |
 | 2 | {1} | {2} | {3} |
 | 1 | {3} | {3} | {3、4 構造に応じて} |

 これは、単一のコンベアが到達可能な領域を上方にシフトし、複数の上部位置に伝播する様子を示しています。 

ここでコンベアのないケースを考えてみましょう。$n = 4$。 境界反射のみが適用されるため、到達可能な状態は中心に位置し、対称のままになります。 到達可能なセットは一番上の行の 1 列に安定し、摂動がない場合の決定論的な崩壊を示しています。

 ## 特殊なケース

 主なエッジ ケースは、到達可能な状態が正確に境界に位置し、複数の行を介して繰り返し上方に反映される場合です。 このようなシナリオでは、単純な実装では、隣接する位置を交互に配置するのではなく、誤って固定したままにしてしまう可能性があります。 

たとえば、$n = 3$コンベアはなく、一番下のセルから開始して、位置間を交互に上向きに伝播します。$1$そして$2$境界反射によるものです。 アルゴリズムは、すべての層で境界反転を適用することでこれを処理し、振動が平坦化されるのではなく確実に捕捉されるようにします。 

別のエッジケースは、コンベヤが境界に隣接している場合に発生します。 コンベアがボールを境界セルに押し込むと、次の行の遷移で即座に反射が適用され、2 段階の変位が生成されます。 伝播モデルは、コンベアの移動と境界調整を行ごとに個別の段階に分割することで、これを正確に考慮します。
