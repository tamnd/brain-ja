 ## 解決策
 ## 問題の理解

 以下のみからなるバイナリ文字列を構築するように求められます。`0`そして`1`部分列の数が次と等しくなるように、`01`まさに`m`。 サブシーケンス`01`を選択することを意味します`0`文字列のどこかと`1`文字列の後半で。 このようなペアはすべて、合計カウントに 1 を加えます。 

より具体的に再構成すると、`0`すべてを「見る」`1`はその後に表示され、その数の有効なサブシーケンスに寄与します。 したがって、文字列の合計値は、すべてのゼロとその右側にある 1 の数の合計です。 

このタスクは建設的です: 与えられた`m`まで$10^9$、最大でも次の長さの有効なバイナリ文字列を出力する必要があります。$10^5$まさにこの値が生成されます。 

制約は十分小さいので、$O(n)$建設でも$O(\sqrt{m})$推論は十分です。 二次関数以上のもの$10^5$遅すぎますが、すべての文字列を検索または最適化する必要はなく、決定的に文字列を構築するだけです。 

微妙なエッジケースが現れるのは、`m = 0`。 その場合、`0`の前に`1`たとえば、作品`"0"`、`"1"`、 または`"000"`。 ただし、常に少なくとも 1 つを想定した不注意な構築は、`1`または固定構造を強制すると、誤って危険が生じる可能性があります。`01`ペアになり、次の場合に正の値が生成されます。`m`はゼロです。 

## アプローチ

 ブルートフォースアプローチでは、文字列を段階的に構築し、現在の文字列数を維持しようとします。`01`各挿入後のサブシーケンス。 各ステップで、次のいずれかを追加してみることができます。`0`または`1`そして寄与度を再計算します。 長さの文字列の値を再計算する必要があるため、これはすぐに実行不可能になります。$n$費用$O(n)$、あらゆる可能性を探索すると、指数関数的な分岐が発生します。 各ステップでカウントを再計算する貪欲なバリアントでも、次のように劣化します。$O(n^2)$が遅すぎる$10^5$。 

重要な観察は、値の構造が非常に特殊な方法で線形であるということです。 何個直したら`1`はブロックの後に表示されます`0`s、それからそれぞれ`0`そのブロックでは、まったく同じ量が貢献します。 これは、文字列をブロックにグループ化し、残りの数が`1`s は段階的に減少します。 

ゼロと単一の 1 のブロックが交互に並ぶ形式で文字列を構築できます。```
0...0 1 0...0 1 0...0 1 ...
```あると仮定します`K`ones in total. 次に、 の前に置かれるすべてのゼロ`i`- 番目のものは正確に貢献します`(K - i + 1)`答えの後にはその数だけ表示されるからです。 これにより、問題は次のような表現に変換されます。`m`重み付けされたゼロのカウントの合計として、重みは次のようになります。`K, K-1, ..., 1`。 

私たちが選ぶなら`K`その周り$O(\sqrt{m})$、その後、貪欲に分解できます`m`これらのウェイトを使用して、長さの制限を超えないようにします。 これが機能するのは、重みが完全な減少基準を形成しており、最初にできるだけ多くの大きな寄与をいつでも減算できるためです。

 ## アルゴリズムのチュートリアル

 ここで、文字列を明示的に構築します。 

### アルゴリズムのチュートリアル

 1. 値を選択します`K`そのような$K \approx \sqrt{2m}$、通常は約 450$m \le 10^9$。 これは、`1`s 最後の文字列に置きます。 目標は、重量を減少させることです。`K`まで`1`表すのに十分な`m`。 
2. 最後の文字列は交互のセグメントであると考えてください。ゼロのブロックと単一のブロックです。`1`、繰り返しました`K`回。 それぞれ`1`ブロックを分割し、その右側にいくつのブロックが残るかを定義します。 
3. ポジションごとに`i`から`1`に`K`、ゼロの数を決めます`z[i]`の前に置く`i`-th`1`。 これらのゼロはそれぞれ正確に寄与します`(K - i + 1)`最終的な答えへ。 
4. 重みを大きいものから小さいものへと処理します。 体重の場合`w = K - i + 1`、できるだけ多くのゼロを取ります。$$z[i] = \min\left(\frac{m}{w}, \text{remaining capacity}\right)$$次に引きます`z[i] * w`から`m`。 この貪欲な選択により、確実に`m`最初に大きな貢献を迅速に使用します。 
5. すべての重みを処理した後、`m`ゼロになります。 次のようにして最終的な文字列を構築します。`z[1]`ゼロ、その後`1`、 それから`z[2]`ゼロ、その後`1`、 等々。 
6. オリジナルの場合`m`ゼロだった場合は、次のような単一の文字列を出力します。`"0"`。 

### なぜ効果があるのか

 この構造では、ターゲット値を重みの線形結合としてエンコードします。`K, K-1, ..., 1`ここで、各重みは、特定のブロックにゼロが配置された場合に残る 1 の数に対応します。 約までのすべての整数なので、$K(K+1)/2$これらの減少する重みを貪欲に使用して表現できます。$K$この合計が超えるのに十分な大きさが選択されます$m$、表現は常に成功します。 各ゼロはブロック位置に応じて独立して寄与するため、合計は構築された分解と正確に一致します。`m`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    m = int(input().strip())

    if m == 0:
        print(1)
        print("0")
        return

    # choose K ~ sqrt(2m)
    K = 1
    while K * (K + 1) // 2 < m:
        K += 1

    z = [0] * K

    # greedy decomposition from large weights to small
    rem = m
    for i in range(K):
        w = K - i
        if w == 0:
            break
        take = rem // w
        z[i] = take
        rem -= take * w

    # build string
    res = []
    for i in range(K):
        res.append("0" * z[i])
        if i < K - 1:
            res.append("1")

    print(sum(z) + K - 1)
    print("".join(res))

if __name__ == "__main__":
    solve()
```コードは最初にゼロの場合を直接処理します。これは、有効な文字列が存在しないためです。`0`前に`1`ペアでも可。 ポジティブな場合`m`、適切な数の 1 を計算します。`K`、次に、各ゼロの前にいくつのゼロを出現させるかを貪欲に割り当てます。 

重要な実装の詳細は、各ブロックの重みが純粋に右からの位置によって決定されることです。 ループは残りの値を維持します`rem`、各割り当てが有効で独立していることを確認します。

 ## 特殊なケース

 のために`m = 0`、アルゴリズムは構築を完全にバイパスし、単一の`0`。 これにより、誤って導入されることを回避できます。`01`これは、少なくとも 1 つが含まれる交互構造では避けられません。`1`。 

非常に大きい場合`m`、選ばれた`K`は小さいまま (約 450) であるため、多くのゼロが生成されたとしても、各重み単位が貪欲に消費されるため、全長は制限されたままとなり、ブロック サイズの爆発を防ぎます。 

小型用`m`のような`1`または`2`、貪欲な分解では、最も重みの高い位置にのみゼロが割り当てられ、慎重に配置された少数のゼロのみが合計カウントに寄与するコンパクトな文字列が生成されます。
