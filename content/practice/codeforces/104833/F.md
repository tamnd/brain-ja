 ## 解決策
 ## 問題の理解

 自然数に基づいて定義された関数が与えられています。 数字の場合$x$、整数の指数が存在するかどうかを調べます。$k > 1$そのような$x^k$は有理数です。 機能$f(x)$そのような指数が存在する場合は 1 を出力し、存在しない場合は 0 を出力します。テスト ケースごとに、次の合計を計算するように求められます。$f(i)$すべての整数にわたって$i$1から$n$。 

入力には複数のクエリが含まれており、各クエリは単一の値を提供します$n$まで$10^{12}$。 これは、すべての値を反復処理するソリューションはすべて、$n$単一のテスト ケースでも最大で$10^{12}$操作。 

このステートメントの重要な点は、整数入力を評価しており、条件にはそれらの整数のべき乗が含まれていることです。 よくある落とし穴は、条件を深い整数理論や非整数入力が関係するものとして考えすぎることです。 ただし、毎回以来、$i$は自然数、あらゆる累乗です$i^k$も整数なので、自動的に有理数になります。 

単純な誤解は、複雑な代数的推論によって結果を合理化する何らかの指数が存在するかどうかをチェックしようとすることです。 これはここでは不要であり、核となる単純化がまだ欠けている複雑すぎる実装につながる可能性があります。 

直感をテストするための典型的なエッジケースは次のとおりです。$i = 1$。 以来$1^k = 1$常に合理的であるため、$f(1) = 1$。 他の整数については、次のようにします。$i = 2$、まだあります$2^k$すべて整数であること$k$、したがって合理的、したがって$f(2) = 1$。 このパターンはあらゆる自然数に当てはまります。 

したがって、合計の各項は 1 になります。 

## アプローチ

 ブルートフォースアプローチでは、それぞれの定義を直接評価します。$i$1から$n$、そしてそのようなそれぞれについて$i$、さまざまな値を試してください$k > 1$かどうかを確認してください$i^k$合理的です。 以来$i^k$は整数に対して正確に計算できるため、このアプローチでは常に条件が確認されます。 しかし、たとえ狭い範囲に限定したとしても、$k$、まだ公演中です$O(n)$クエリごとに動作するため、次の場合には実現不可能です。$n$到達できる$10^{12}$。 

重要な点は、この条件では実際には自然数が除外されないということです。 任意の整数の場合$i \ge 1$、および任意の整数の指数$k > 1$、値$i^k$は整数のままであるため、有理数のセットに属します。 これは、の定義における存在条件を意味します。$f(x)$いつも満足しています。 

すべての要素が 1 に寄与することがわかれば、問題は単純なプレフィックスの合計を計算することになります。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$T$。 各テスト ケースは独立しており、範囲の合計を求めます。$n$。 
2. 各テスト ケースについて、整数を読み取ります。$n$。 
3. すべての整数が次のとおりであることを認識します。$i$で$[1, n]$満足する$f(i) = 1$したがって、必要な合計は単に範囲内の整数の数です。 
4. 答えを次のように計算します。$n$。 
5. 結果を出力します。 

### なぜ効果があるのか

 機能$f(i)$指数が存在するかどうかに依存します$k > 1$そのような$i^k$合理的です。 以来$i$は自然数、任意のべき乗$i^k$整数のままです。 すべての整数は有理数であるため、条件は常に true です。 これにより、$f(i)$ドメイン全体で同様に 1 に等しい$[1, n]$、合計が正確であることを確認します$n$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        print(n)

if __name__ == "__main__":
    solve()
```このソリューションは、各クエリを読み取って出力するだけです。$n$, すべての項がちょうど 1 単位で合計に寄与するためです。 

唯一の微妙な実装の詳細は、高速 I/O を確保することです。$T$と同じ大きさにすることができます$2 \times 10^3$, ただし、テスト ケースごとに定数処理を行うため、ここでは標準の入出力でも十分です。
