 ## 解決策
 ## 問題の理解

 セルの三角形の配置が与えられています。$n$行。 一番下の行には 1 つのセルがあり、その上の各行は対称的に展開されるため、一番上の行にはセルが含まれます。$2n - 1$細胞。 上の行を左から右にインデックスすると、それらの位置がボールの開始点として機能します。 

開始セルに落ちたボールは決定的に動きます。 セルからは常に 1 行下に移動しますが、位置制約に応じて水平方向にもシフトします。行の左境界にある場合は次の行で 1 ステップ右に強制され、右境界にある場合は 1 ステップ左に強制されます。 それ以外の場合は、水平方向に変化することなくまっすぐ下に進みます。 ボールが穴のあるセルに到達すると、ボールはすぐに消えて続行されません。 すべての列を生き残った場合、最終的には一番下の 1 つのセルに到達し、その下の出口から出ます。 

各テストでは、三角形の穴の位置のリストも提供されます。 タスクは、最上列のすべての開始位置について、そこから始まったボールがどの穴にも当たらずに出口に到達するかどうかを判断することです。 

制約は大きく、最大で$10^4$テストケース、合計$n$まで$10^5$合計の穴数は次のとおりです$2 \cdot 10^5$。 これにより、各開始位置を個別にシミュレートすることが直ちに排除されます。 単純なシミュレーションではコストがかかる$O(n^2)$テストごとに、これは限界をはるかに超えています。 

微妙なエッジケースは、最上列近くに配置された穴から生まれます。 各開始位置のパスは決定論的なバウンス動作を通じてグローバルに結合されているため、貪欲な推論または行ごとに独立した推論は失敗します。 

たとえば、底部近くの中央の通路を穴が塞いでいる小さな三角形について考えてみましょう。 2 つの隣接する開始位置は、パスの長いプレフィックスを共有し、終点近くでのみ分岐する場合があるため、それらを個別に処理したり、パスを個別に再計算したりすると、繰り返し作業が発生し、TLE が発生する可能性があります。 もう 1 つのエッジ ケースは、ホールによって「チャネル」全体が早期に削除され、多くの開始位置が等価になる場合ですが、単純なアプローチでは依然として個別に再計算されます。 

## アプローチ

 直接的なアプローチは、各開始位置を個別にシミュレートすることです。 一番上のセルから、そのパスを下に向かってシミュレートし、各行に左右の境界反射を適用し、穴に当たるかどうかを確認します。 各シミュレーションの費用$O(n)$、そして、あります$2n - 1$開始位置が異なるため、単一のテストは$O(n^2)$。 と$n$まで$10^5$総合的に見て、これは完全に不可能です。 

重要な観察点は、行内の各セルが$r$行内の正確に 1 つのセルに決定的にマッピングします。$r+1$。 これは、構造が分岐グラフではなく、層ごとの機能グラフであることを意味します。 すべての位置には一意の後続者が存在するため、異なる開始点からのパスが結合し、下向きにバラバラな「動線」を形成します。 

上からシミュレーションするのではなく、視点を逆転させます。 一番下のセルは、それが「安全」（出口につながっている）か「ブロックされている」（穴であるか、下の穴につながっている）かを決定します。 この情報を上方向に伝播すると、各セルの安全性は下の行の 1 つの子にのみ依存します。 これにより、問題は、各セルが出次数 1 を持つグリッド上のボトムアップ動的計画法に変換されます。 

境界反射が唯一の複雑な問題です。 これは、水平方向のマッピングが線形ではないことを意味しますが、依然として固定されており、決定論的です。つまり、各セルには、下の行内で一意に決定される次の位置があります。 したがって、すべてのセルについて次のセルのインデックスを事前計算し、下から上へ逆 DP を実行できます。 

どの下のセルが出口につながっているかがわかったら、「良さ」を上向きに伝播します。穴でなければセルは良好であり、その次のセルは良好です。 最後に、上の行を読み上げます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$テストごと |$O(1)$番外編 | 遅すぎる |
 | 最適なDP |$O(n + m)$テストごと |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 すべてのセルが次の行の 1 つのセルを正確に指す、有向層状グラフとして三角形をモデル化します。 

1. まず、ハッシュ セットまたはキーをキーとしたブール配列内のすべてのホールを表します。$(r, c)$。 これにより、セルがブロックしているかどうかを定期的にチェックすることができます。 
2. 各行について、列からのマッピングを決定します。$c$並んで$r$行内の列に$r+1$。 このマッピングはジオメトリに直接従っており、内部セルは真っ直ぐ下にマップされ、境界セルは下に向かう前に内側に移動します。 これにより、すべてのノードが出力エッジを 1 つだけ持つことが保証されます。 
3. DP 配列を定義します`good[r][c]`セルから開始するかどうかを意味します$(r,c)$最終的には穴にぶつからずに出口に到達します。 
4. 一番下の行を初期化します。 穴がない場合は、最下位の 1 つのセルが適しています。これは、そこに到達するとすぐに終了することを意味するためです。 
5. 行を下から上に処理します。 各セルについて、穴があれば直ちに不良となります。 それ以外の場合は、下の行の一意の子セルが良好である場合に正確に良好です。 これが機能するのは、プロセスが決定的であり、代替の遷移がないためです。 
6. DP を入力した後、テスト ケースの回答を読み取ることで取得されます。`good[1][c]`すべての有効な最上行位置。 

重要な不変条件は次のとおりです`good[r][c]`行が正しいと仮定して、そのセルからの出口への到達可能性を正しく表します$r+1$。 すべてのセルはちょうど 1 つの下のセルに遷移するため、欠落するケースはありません。将来のすべての動作は子状態によって完全にキャプチャされます。 境界ルールは、どの子が選択されるかにのみ影響し、1 つだけの子が存在するかどうかには影響しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())

        # total width is 2n - 1, but row r has 2r - 1 cells from bottom symmetry
        # we index rows 1..n, and each row r has 2*r - 1 cells

        holes = set()
        for _ in range(m):
            r, c = map(int, input().split())
            holes.add((r, c))

        # dp for current row
        # we build from bottom up
        dp = []

        # bottom row has 1 cell
        # dp[r][c] conceptually, but we compress per row
        dp_prev = [False] * (2 * n + 5)

        # bottom row (r = n, 1 cell at c=1)
        dp_prev[1] = (n, 1) not in holes

        # precompute row widths
        for r in range(n - 1, 0, -1):
            width = 2 * r - 1
            dp_curr = [False] * (2 * r + 5)

            for c in range(1, width + 1):
                if (r, c) in holes:
                    dp_curr[c] = False
                else:
                    # determine child position in row r+1
                    # geometry: center alignment implies shift by +1 except boundaries
                    if c == 1:
                        nc = 1
                    elif c == width:
                        nc = 2 * (r + 1) - 1
                    else:
                        nc = c + 1

                    dp_curr[c] = dp_prev[nc]

            dp_prev = dp_curr

        ans = []
        for c in range(1, 2 * n):
            ans.append('1' if dp_prev[c] else '0')

        print(''.join(ans))

if __name__ == "__main__":
    solve()
```コードの中核となる考え方は、ボトムアップの伝播です。`dp_prev`は常に元の三角形の次の行を表し、次のように計算します。`dp_curr`すでに計算された結果を使用して現在の行を検索します。 唯一微妙な部分はマッピングです`nc`、列からのボールの決定論的な動きをエンコードします。$r$に$r+1$。 マッピングが正しいと、残りは単純な依存関係チェーンになります。 

境界処理は潜在的なバグの主な原因です。 左端と右端のセルは正しくクランプされている必要があります。 そうしないと、パス構造が壊れ、無効な遷移が生成されます。 もう 1 つの微妙な点は、行幅が次のように一貫して計算されるようにすることです。$2r - 1$そうでない場合、インデックスがドリフトし、DP の位置がずれてしまいます。 

## 実用的な例

 次の小さな三角形を考えてみましょう。$n = 3$そして単一の穴$(2,2)$。 一番上の行には 5 つの開始位置があります。 

ボトムアップで計算します。 

| 行 | セル | 穴 | 次へ | DP値 |
 | --- | --- | --- | --- | --- |
 | 3 | (3,1) | いいえ | 終了 | 1 |
 | 2 | (2,1) | いいえ | (3,1) | 1 |
 | 2 | (2,2) | はい | - | 0 |
 | 2 | (2,3) | いいえ | (3,1) | 1 |
 | 1 | (1,1) | いいえ | (2,1) | 1 |
 | 1 | (1,2) | いいえ | (2,2) | 0 |
 | 1 | (1,3) | いいえ | (2,3) | 1 |

 最終的な答えは、`10101`。 これは、単一のブロックされた中間セルが、それに依存するパスにのみ障害を伝播する様子を示しています。 

ここで考えてみましょう$n = 2$穴はありません。 どの道も底に到達します。 

| 行 | セル | 次へ | DP値 |
 | --- | --- | --- | --- |
 | 2 | (2,1) | 終了 | 1 |
 | 1 | (1,1) | (2,1) | 1 |
 | 1 | (1,2) | (2,1) | 1 |
 | 1 | (1,3) | (2,1) | 1 |

 出力は`111`。 

これらのトレースは、DP が底部に向かうすべてのパスを正しくマージし、ホールのみが伝播を妨げていることを確認します。

 ## 特殊なケース

 重大なエッジケースは、多くの上位ポジションが集中するセルにホールが配置された場合です。 このような構成では、単一の DP セルが false になり、その値がすべての依存状態を通じて上方に伝播します。 各状態は 1 つの子にのみ依存するため、アルゴリズムはこれを自然に処理します。そのため、追加の処理を行わなくても、1 つの障害が確定的に上方に広がります。 

もう 1 つの特殊なケースは、穴が境界セルを占有する場合です。 境界遷移は方向を内側に固定するため、エッジの穴は直観が示唆するよりも大きいまたは小さい領域に影響を与える可能性があります。 境界マッピングは遷移ルール​​内で直接エンコードされているため、DP は引き続きこれを正しく処理します。そのため、正しいインデックス付け以外に特別な場合の推論は必要ありません。 

最後に、ブロックされている一番下のセルは、グローバルな障害状態です。 すべてのパスはそこで終了する必要があるため、それを到達不能として正しくマークすると、同じ繰り返しによってその上のすべての DP 状態が強制的に false になります。
