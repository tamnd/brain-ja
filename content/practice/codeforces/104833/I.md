 ## 問題の理解

 非常に小さな「プログラム」、つまり整数に対して多くの独立したチェックが与えられます。`x`32 ビットの符号付き形式で保存されます`int`、その後、未知の整数型に変換され、結果の値が指定された整数と比較されます。`y`。 不明な型は符号なしまたは符号付きのいずれかであり、どちらの場合もラップアラウンド オーバーフローを伴う固定幅のモジュラー型のように動作します。 

符号なし型の場合、値は次の範囲内にあります。`[0, M]`演算はモジュロで実行されます`M + 1`。 それで保管する`x`と置き換えることを意味します`x mod (M + 1)`、常に負ではない数値として解釈されます。 

符号付き型の場合、値は次のようになります。`[-M - 1, M]`、算術演算はモジュロで実行されます。`2M + 2`。 保存された剰余は剰余として取得されます`2M + 2`、その後、通常の 2 の補数スタイルで解釈されます: 上記の値`M`減算によって下にシフトされます`2M + 2`。 

各テストでは、有効な型 (符号付きまたは符号なし) が存在するかどうか、および有効な最大値が存在するかどうかが尋ねられます。`M`(10^18 を超えない)`x`その型に入力すると正確に生成されます`y`。 このような構成が存在する場合は、有効な説明を 1 つ出力する必要があります。 それ以外の場合は出力します`-1`。 

主な制約は、テスト ケースが最大 100,000 件あるため、各テストは前処理後にほぼ対数時間または定数時間で処理する必要があることです。 検索を試みることはできません`M`。 

微妙なエッジケースが現れるのは、`x == y`。 その状況では、次のような非常に小さな係数を含む、さまざまな係数が機能します。`M = 0`だけでなく、署名された構成も含まれます。 割り算パターンのみをチェックする単純なアプローチでは、その些細な等式のケースを見落としたり、存在しないモジュラス構造を強制することによって誤って処理したりする可能性があります。 

もう 1 つの注意が必要な状況は次のような場合です。`y`はマイナスです。 符号なし型は負の結果を生成することは決してないので、正しい解決策はその場合、符号なしの可能性をすべて即座に拒否する必要があります。 ただし、方法によっては、署名付き型も引き続き機能する可能性があります。`y`によって引き起こされる符号付き範囲内に収まります`M`。 

## アプローチ

 強引なアイデアは、可能な値をすべて試してみることです。`M`最大 10^18 まで変換し、符号付きと符号なしの両方の解釈の変換をシミュレートします。 候補ごとに、次のモジュラー イメージを計算します。`x`そしてそれが一致するかどうかを確認してください`y`。 これは型システムの定義に直接従うため、これは正しいです。 問題は、検索スペースが膨大であり、意味のあるサブセットを反復処理することさえあることです。`M`不可能です。 範囲が大きすぎるため、マッピングはスキャンできるように単調に動作しません。 

重要な観察は、変換がモジュラー演算のみに依存しているということです。 符号付きの場合と符号なしの場合の両方で、格納される値は完全に次の条件によって決定されます。`n = M + 1`(署名なし) または`n = 2M + 2`(署名済み)。 変換された値が等しいという条件`y`合同を強制する：`x ≡ y (mod n)`。 

これにより、検索による問題が軽減されます`M`可能なモジュールの検索へ`n`それを分ける`x - y`。 候補モジュラスを修正したら、それが有効な符号付き範囲または符号なし範囲に対応できるかどうかを検証するだけで済みます。 

したがって、膨大な範囲をスキャンする代わりに、約数のみを列挙します。`|x - y|`、これは最大でも約 2^32 の大きさであり、最悪の場合でも約 60,000 個の約数しか意味しません。

 ## アルゴリズムのチュートリアル

 値を含む 1 つのテスト ケースに焦点を当てます`x`そして`y`。 

1. コンピューティング`d = x - y`。 もし`d == 0`、原理的には任意の法が機能するため、符号なし型などの自明な有効な型を直接構築できます。`M = 0`または署名付き型`M = 0`制約に応じて。 これは特殊なケースとして扱われます。 
2. それ以外の場合は、`|d|`すべての正の約数を列挙します`n`。 条件が次のとおりであるため、各約数は候補モジュラスです。`x ≡ y (mod n)`を保持する必要があり、これは次と同等です`n | (x - y)`。 
3. 各候補者について`n`, まず、符号なし型を表現できるかどうかをテストします。 これには次の 2 つの条件が必要です。`y`負ではなく、次の範囲にある必要があります`[0, n - 1]`。 そうであれば、設定できます`M = n - 1`、そしてこの候補は有効です。 
4. 今でも同じ`n`、符号付き型を表現できるかどうかをテストします。 符号付き型には係数があります`n = 2M + 2`、 それで`n`均等でなければなりません。 私たちは計算します`M = n / 2 - 1`、どうかを確認してください。`y`中にある`[-M - 1, M]`。 「はい」の場合、この係数は符号付き型に対して有効です。 
5. いずれかの除数が有効な構成を生成する場合、それをすぐに出力します。 それ以外の場合は、すべての約数を使い果たした後、次のように出力します。`-1`。 

各約数をチェックするのに十分な理由は、モジュラー等式が次の場合に完全に特徴付けられるためです。`x`そして`y`ラッピング後も同一になる可能性があります。 残りの唯一の制約は、結果として得られる剰余が、許可される符号付きまたは符号なしの範囲内で解釈できるかどうかです。 

### なぜ効果があるのか

 変換プロセスでは、次のすべての情報が破棄されます。`x`ただし、型サイズを法とする剰余は除きます。 したがって、有効な解決策はすべて次の条件を満たす必要があります。`x - y`そのサイズの倍数になります。 これにより、問題は除算する係数を見つけることに変わります。`x - y`そして同時に認めます`y`対応する数値範囲内の有効な表現として。 すべての有効な型はそのようなモジュラス 1 つに正確に対応するため、次のすべての約数をチェックします。`x - y`必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get_divisors(n):
    res = []
    i = 1
    while i * i <= n:
        if n % i == 0:
            res.append(i)
            if i * i != n:
                res.append(n // i)
        i += 1
    return res

def solve():
    t = int(input())
    for _ in range(t):
        x, y = map(int, input().split())
        d = x - y

        if d == 0:
            # trivial valid construction
            # unsigned with M = 0 always works
            print("unsigned 0")
            continue

        ad = abs(d)
        divisors = get_divisors(ad)

        found = False

        for n in divisors:
            if d % n != 0:
                continue

            # unsigned case
            if y >= 0 and y <= n - 1:
                print("unsigned", n - 1)
                found = True
                break

            # signed case
            if n % 2 == 0:
                M = n // 2 - 1
                if -M - 1 <= y <= M:
                    print("signed", M)
                    found = True
                    break

        if not found:
            print(-1)

if __name__ == "__main__":
    solve()
```コードは、約数を列挙することから始まります。`|x - y|`なぜなら、それらのモジュライだけが必要な合同性を満たすことができるからです。 各約数について、まず、次のことを確認して、符号なし型として解釈しようとします。`y`に適合する`[0, n - 1]`。 それが成功した場合は、直接出力します`M = n - 1`。 

unsigned が失敗した場合は、signed 解釈を試みます。 これには必要です`n`符号付き範囲は対称であり、常に次の形式の係数から得られるため、偶数である必要があります。`2M + 2`。 次に再構築します`M`かどうかを確認してください`y`は符号付き区間内にあります。 この問題では任意の正解が許容されるため、最初の有効な一致があれば十分です。 

特別な場合`x == y`すべてのモジュールが機能するため、個別に処理され、最小の有効な構成を安全に出力できます。

 ## 特殊なケース

 いつ`x == y`、すべてのモジュラスがゼロを除算するため、モジュラー制約はなくなります。 このアルゴリズムは除数検索を明示的にバイパスし、自明な符号なし型を返します。 たとえば、入力`0 0`生成する`unsigned 0`、すべての値が等しい 1 要素型に対応します。 

いつ`y`が負の場合、範囲が厳密に負ではないため、署名されていない候補は自動的に拒否されます。 例えば、`x = 1, y = -1`アルゴリズムに署名付きチェックのみを強制し、偶数のモジュライのみを考慮します。 

いつ`|x - y|`約数が非常に少ない場合 (たとえば、素数の場合)、ループはすべての候補をすぐに失敗させ、正しく生成します。`-1`不必要な構成を探索する必要はありません。
