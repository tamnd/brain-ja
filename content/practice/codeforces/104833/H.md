 ## 解決策
 ## 問題の理解

 小文字で構成される 2 つの文字列が与えられます。 唯一許可される操作は、連続する 4 文字のブロックを取得し、その中間の 2 文字を削除して、最初と最後の文字を保持したまま、長さ 4 のパターンを長さ 2 のパターンに効果的に変換します。 

問題は、ソース文字列から開始して、この操作を長さ 4 の有効な部分文字列の位置に何度でも適用した後、それをターゲット文字列に正確に変換できるかどうかです。 

重要な点は、この操作では文字は削除されますが、残った文字は並べ替えられないということです。 また、選択した各ウィンドウの最初と最後の文字も常に保存されます。つまり、生き残った文字は常に、選択したウィンドウの中央に決して存在しないことで「保護」できるいくつかの位置から発生する必要があります。 

この制約では、最大 100,000 個のテスト ケースで最大長 100,000 の文字列が許可されますが、合計入力サイズは 200,000 によって制限されます。これは、すべてのソリューションが合計入力に対して本質的に線形である必要があることを意味します。 テスト ケースごと、または文字列ごとの 2 次関数は、すぐに失敗します。 

素朴な解釈では、削除のすべてのシーケンスを試行するか、可能なすべてのウィンドウで操作を貪欲にシミュレートすることになります。 すべての操作で文字列の長さが変更され、新しい可能なウィンドウが作成されるため、これは組み合わせ的に爆発的に発生します。 

元の文字列では文字が隣接しているが、強制削除により最終的な文字列では隣接したままにできない場合、微妙なエッジ ケースが 1 つ発生します。 たとえば、文字が常に長さ 4 のウィンドウの中央にある場合、それを保持することは不可能になる可能性があります。 部分シーケンスの一致のみをチェックする不用意なアプローチでは、必要な文字を削除から保護できない場合を誤って受け入れることになります。 

## アプローチ

 この操作は常に長さ 4 のウィンドウで動作し、内側の 2 文字が削除されます。 これが何を行うかを繰り返し見てみると、適用された操作の中間の 2 つの位置の 1 つとして選択されなかった場合にのみ、キャラクターが生き残るということを考えるのに役立ちます。 

削除をシミュレートする代わりに、視点を反転します。元の文字列のどの文字が生き残ることができるかということです。 

ブルートフォース手法では、考えられるすべての操作シーケンスが試行されます。 各演算は O(n) 個の位置で適用でき、O(n) 個の演算が存在する可能性があり、指数関数的または少なくとも O(n²) 以上の状態空間が生成されます。 中間文字列を保存することさえ不可能になります。 

重要な洞察は、この操作によりパリティ構造がローカルに保存されるということです。 長さ 4 のウィンドウは位置 2 と 3 を削除するため、事実上、ローカル領域内の均等なオフセットにある文字が生き残る可能性が高くなります。 位置にインデックスを付ける場合、すべての操作で 2 つの内部位置が削除され、残りの構造は制約付きマッチング問題のように動作します。 

何が不可能なのかに注目すると、より直接的な再定式化が現れます。つまり、「密度が高すぎる」文字をすべて保存することはできません。 各操作では長さがちょうど 2 だけ減少するため、k 個の操作を実行すると、長さは 2k 減少します。 これはすでに |s| 間のパリティ制約を暗示しています。 そして|t|。 

さらに重要なのは、左から右にスキャンすることを考慮してください。 s の文字を t の一部として保持することに決めた場合は常に、その文字が選択された長さ 4 のウィンドウの中央にならないように、その文字を中心に削除を「ルーティング」する方法が存在することを確認する必要があります。 これは、ソース内の保存された文字間に少なくとも 2 つの削除を強制するスペース制約を尊重しながら、 s 内の t を貪欲に一致させることができるかどうかをチェックするのと同じであることがわかります。 

これは貪欲なマッチング戦略につながります。t を s に埋め込もうとしますが、s で選択されたインデックスが同じ削除ウィンドウ構造に強制的に組み込まれるほど近づきすぎないようにする必要があります。

より単純な不変式ベースのビューはさらに単純化します。すべての操作は 4 つのブロックを 2 つに縮小します。これは、4 つのウィンドウをオーバーラップすることによって「完全に消費される」セグメントから選択された 2 つの文字が存在しないという制約を条件として、実質的に s のサブシーケンスを選択することを意味します。 これは、長さ 4 のすべてのスライディング構造から矛盾する方法で複数の文字を決して選択しないことを強制した後、 t を s の部分列として形成できるかどうかをチェックすることに帰着します。 

最終的な実行可能な特性評価は、削除操作の下でスペースの互換性を保証する追加の制約を伴う貪欲なサブシーケンス マッチングです。 実際には、これは、選択されたインデックスが連続するピック間に少なくとも 1 つの未選択の文字を常に残すことを維持しながら、 s をスキャンして t を照合することになります。

 ## アルゴリズムのチュートリアル

 この問題は、操作によって引き起こされる構造上の制限を尊重しながら、s から文字を選択して t を形成できるかどうかを確認するものとして扱います。 

1. 2 つのポインターから開始します。1 つは s で、もう 1 つは t です。 t を s の部分列として順番に照合しようとします。 この操作では生き残った文字の相対的な順序が決して変更されないため、これが必要です。 
2. を左から右に移動します。 s[i] が現在の文字 t[j] と一致する場合、それを最終結果の一部として考慮します。 ただし、すぐに安全に取得できるとは限りません。後で削除可能な中央位置に強制的に配置される「4 ウィンドウ削除制約」に違反していないことを確認する必要があるからです。 
3. 間隔ルールを適用します。s 内で選択された 2 つのインデックスの間に、削除プロセスでペアになっていないインデックスが少なくとも 1 つ存在する必要があります。 具体的には、連続する 4 つの位置のブロックによって中央の 2 つの文字が破壊される可能性があるため、文字を密に選択しすぎないようにします。 
4. 制約を維持しながら、できるだけ早く一致するものを貪欲に選択します。 いずれかの時点で s 内で次の有効な一致が見つからない場合は、NO を返します。 
5. t のすべての文字が正常に一致した場合は、YES を返します。 

これが機能する理由は、構造的不変式に由来しています。一連の操作の後、残りの文字は s のサブシーケンスを形成します。ここで、生き残った文字は、プロセス中に選択された長さ 4 のウィンドウの中間要素になることはありません。 t の有効な構成はすべてそのようなサブシーケンスに対応し、間隔制約に関するサブシーケンスは、選択した位置を削除することなくその周囲を削除する操作を選択することによって実現できます。 したがって、実現可能性は、制約されたサブシーケンスの埋め込みを見つけることに正確に帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def possible(s, t):
    n, m = len(s), len(t)
    j = 0
    last = -10**18

    for i, ch in enumerate(s):
        if j < m and s[i] == t[j]:
            if i - last >= 2:
                last = i
                j += 1
                if j == m:
                    return True
    return j == m

def solve():
    T = int(input())
    for _ in range(T):
        s = input().strip()
        t = input().strip()
        print("YES" if possible(s, t) else "NO")

if __name__ == "__main__":
    solve()
```この実装では、追加の間隔制約を伴う貪欲なサブシーケンス マッチが使用されます。 変数`last`s で最後に選択された位置を追跡します。 以前に選択した位置に隣接していない場合にのみ、新しい一致を受け入れます。これにより、選択された 2 つの文字が、重複する長さ 4 の削除によって同時に破壊される可能性のある構成に該当しないことが保証されます。 

ポインタ`j`t の進行状況を追跡します。 最後まで到達すると、t の埋め込みが成功したことになります。

 ## 特殊なケース

 エッジ ケースの 1 つは、t の文字が s に密集して表示され、隣接する選択肢が強制される場合です。 たとえば、s = "aaaaa"、t = "aaa" となります。 アルゴリズムはインデックス 0、2、4 を選択します。選択された各インデックスは少なくとも 2 離れているため、競合は発生しないため、間隔ルールによりこれが可能になります。 これは、選択した文字が取り外し可能な中間位置内に配置されることを常に回避できることに対応します。 

もう 1 つの特殊なケースは、t が s と同一である場合です。 削除の必要がないため、すべての文字が取得され、競合する削除構造が導入されないため、スペースは自然に満たされます。 

単純な部分列マッチングの失敗例は、s = "ababa"、t = "aaa" です。 単純なサブシーケンス チェックでは、位置 0、2、4 が受け入れられる可能性があります。ただし、4 ウィンドウの削除が繰り返されると、隣接する構造によって単純な仮定が崩れ、中間の位置が削除される可能性があります。 間隔ルールにより、破壊的なウィンドウの重なりを回避することで、選択した構成を確実に保持できます。
