 ## 問題の理解

 1 から制限値までのすべての整数に適用される関数が与えられています$n$そして、各整数について、それが 1 の値に寄与するか 0 の値に寄与するかを決定します。各テスト ケースの最終的な答えは、特定の構造特性を満たす範囲内の整数の合計数です。 

定義に隠された条件は、その数値が 1 より大きい整数乗にされたときに「適切に構造化」されるかどうかに関するものです。これをより具体的な言葉で書き直すと、次のようになります。$x$、整数の指数が存在するかどうかを確認します$k > 1$そのような$x$パーセントで表すことができます$k$有理数の - 乗。 整数の場合、これはさらによく知られた条件に分解されます。$x$完全累乗でなければなりません。つまり、次のように書くことができます。$a^k$整数の場合$a \ge 2$そして$k \ge 2$。 

したがって、タスクは、次の数字がいくつあるかを数えるということになります。$[1, n]$は少なくとも 2 の指数の完全累乗です。 

入力制約$n \le 10^{18}$がソリューションの主な推進力です。 までのすべての数値を直接反復します。$n$テスト ケースごとのリニア スキャンでさえ、許容される操作をはるかに超えてしまうため、不可能です。 実行可能なアプローチでは、代わりに完全な累乗のまばらな構造のみを列挙する必要があります。 

微妙な特殊なケースは、多くの数値が完全累乗として複数の表現を持っていることです。 たとえば、64 は次のように書くことができます。$2^6$、$4^3$、 そして$8^2$。 重複排除を行わずに指数ごとに個別にカウントする単純な方法では、これらの数値が過剰にカウントされてしまいます。 

もう一つのエッジケースは、$x = 1$。 以来$1 = 1^k$誰にとっても$k$、これは常に完全な検出力であり、正確に 1 回含める必要があります。 

## アプローチ

 ブルートフォース解釈ではすべての数値をチェックすることになる$x \le n$すべての指数を試してください$k \ge 2$かどうかを確認します。$x$完璧です$k$-乗。 これには、数値ごとに整数ルートのチェックを繰り返す必要があり、おおよその結果が得られます。$O(n \log n)$テストケースごとに作業しますが、これは完全に不可能です$n \le 10^{18}$。 

重要な観察は、完全な能力は非常に希薄であるということです。 繰り返す代わりに$x$、生成ペアを反復処理できます。$(a, k)$。 すべての有効な数値は何らかの基数によって生成されます$a \ge 2$ある指数に上げられる$k \ge 2$、指数は有界であるため、$a^k \le n$暗示する$k \le \log_2 n$、最大でも 60 です。 

これにより、問題は、膨大な間隔をスキャンすることから、少数の指数層の列挙に移ります。 指数ごとに$k$、すべての有効な基数を計算できます$a$そのような$a^k \le n$を実行し、結果として得られる値をすべて収集します。 複数の指数形式で現れる 64 などの数値によって生じる重複を排除するには、セットが必要です。

 ## アルゴリズムのチュートリアル

 ### 最適な戦略

 1. 有効な数値はすべて次の形式であることを認識します。$a^k$どこ$k \ge 2$そして$a \ge 2$。 This reframes the problem from filtering numbers to generating them.
 2. 指数が$k$大きくすることはできないので、$2^k \le n$。 したがって、考慮する必要があるのは、$k$2から60まで。 
3. 指数ごとに$k$、最大の整数の基数を計算します$a$そのような$a^k \le n$。 これは、整根抽出を使用して行うことができます。 
4. 有効な塩基ごとに$a \ge 2$、計算する$a^k$それをセットに挿入します。 このセットにより、次のような重複が保証されます。$64 = 8^2 = 4^3 = 2^6$は 1 回のみカウントされます。 
5. すべての指数を処理した後、テスト ケースの答えはセットのサイズになります。 

### なぜ効果があるのか

 カウントされたすべての整数はべき乗として少なくとも 1 つの表現を持っているため、挿入されます。$a^k$と$k \ge 2$。 逆に、すべての挿入は範囲内の有効な完全パワーに対応します。 このセットでは一意性が保証されているため、指数ベース分解の数に関係なく、各数値は 1 回だけ寄与します。 60 を超えるすべての指数は不可能なので、$n \le 10^{18}$、有効な番号が欠けていることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def kth_root(n, k):
    lo, hi = 1, int(n ** (1 / k)) + 2
    while lo <= hi:
        mid = (lo + hi) // 2
        v = mid ** k
        if v <= n:
            lo = mid + 1
        else:
            hi = mid - 1
    return hi

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        seen = set()

        for k in range(2, 61):
            a = kth_root(n, k)
            for base in range(2, a + 1):
                seen.add(base ** k)

        print(len(seen))

if __name__ == "__main__":
    solve()
```この実装は、指数を反復処理し、対応するすべての基数を生成することに依存しています。 ヘルパー関数は、二分探索を使用して各指数の有効な基数の最大値を計算し、根を抽出する際の浮動小数点精度の問題を回避します。 

ネストされたループ構造は重く見えるかもしれませんが、実際には値は次のように非常に急速に縮小します。$k$成長します。 のために$k \ge 6$、有効な塩基の範囲が非常に小さくなり、総生成量が管理可能になります。

 ## 特殊なケース

 最も重要なエッジ ケースは、複数の指数表現を持つ数値です。 たとえば、入力$n = 64$として 64 が含まれます$2^6$、$4^3$、 そして$8^2$。 アルゴリズムは 3 つのフォームすべてを生成しますが、セットでは 1 つのカウントのみが保証されます。 実行中、k=2、k=3、k=6 に 64 が挿入されますが、それ以降の挿入は無視されます。 

もう一つのエッジケースは、$n = 1$。 1は等しいので$1^k$みんなのために$k$、常に含まれています。 ループは引き続き生成を試行しますが、挿入されるのは 1 回だけです。 

最後に、非常に大きな$n$のような値$10^{18}$高い指数に対して非常に小さな有効範囲が生成されます。 たとえば、$k = 10$、4 までの基数のみが考慮されます。 これにより、計算の爆発が防止され、列挙が厳密に制限されます。
