 ## 解決策
 ## 問題の理解

 従業員 1 が CEO である従業員のルート ツリーが与えられます。 他の従業員には必ず 1 人の直属の上司がおり、階層が形成されます。 各従業員に 1 から D までの整数の給与を割り当てる必要がありますが、従業員は直属の上司よりも多く稼ぐことができないという制約があります。 

同様に、親から子へのすべてのエッジに沿って、割り当てられた値は下に行くにつれて増加しない必要があります。 タスクは、1 から D までの範囲の値の代入がこれらすべての不等式を満たす回数を数え、結果のモジュロを返すことです。$10^9+7$。 

この構造はルート付きツリーであるため、制約はルートからノードへのすべてのパスに沿って下方向に伝播します。 素朴な解釈では各ノードを独立して扱いますが、各ノードの有効範囲はすべての先祖に依存するため、依存関係はグローバルになります。 

制約は厳しいです:$n \le 3000$そして$D \le 10^9$。 ドメイン サイズが大きいため、ノードごとにすべての給与値を明示的に反復する DP は直ちに除外されます。 ノードごとまたは状態ごとに D を反復することに依存する解決策は不可能です。 

微妙な失敗例は、ツリーがチェーンである場合に発生します。 その場合、制約は長さ n のグローバルな非増加シーケンスになります。 サブツリーの独立性を前提とした単純な DP は、ルートでの選択がすべての子孫を大幅に制限するため、過度にカウントされます。 逆に、サブツリーの相互作用をマージせずにローカルの親子制約のみを追跡する単純なノードごとの DP は、ノードの単一の値がその下のサブツリー全体を制約するという事実を見落とします。 

## アプローチ

 ブルート フォース ソリューションでは、次の値が割り当てられます。$[1, D]$すべてのノードにアクセスし、すべてのエッジをチェックします。 これはすでにあります$D^n$可能性はありますが、それはたとえ$n=10$。 制約構造は、独立した割り当てという観点ではなく、制約がサブツリーを通じてどのように伝播するかという観点から考える必要があることを示唆しています。 

重要な点は、サブツリーにとって重要なのは、サブツリー内で割り当てられる正確な値ではなく、親によって課された上限を考慮してどれだけの方法でサブツリーを割り当てることができるかであるということです。 ノードに最大許容給与 x を強制する場合、そのサブツリー内のすべてのノードに値を割り当てる必要があります。$[1, x]$同じ単調制約を使用します。 

これは、各ノードが関数を計算するツリー DP を示唆しています。$f_u(x)$、サブツリー内のすべてのノードが最大でも x になるような、u をルートとするサブツリーの有効な割り当ての数。 ただし、D までのすべての x に対してこの関数を明示的に格納することは不可能です。 

重要な構造的洞察は、$f_u(x)$は、サブツリー u の最大サイズの次数の x における多項式のような関数です。 すべての x の値を追跡する代わりに、x にわたるプレフィックスの合計を使用して寄与を増分的に計算できます。 子をマージする場合、子の値が親を超えることはできないという制約があり、これは許容最大値を超える累積カウントとなります。 

dp[u][k] を、そのサブツリーで使用される最大値が正確に k になるように u のサブツリーに値を割り当てる方法の数として定義し、すべての値が$[1, k]$。 これにより、k は実際の D ではなく、ツリー構造によって引き起こされるサブツリー サイズ境界までの範囲で十分であるため、D への依存関係が管理可能な O(n^2) DP に圧縮されます。 

子を結合するときは、親の値が固定されるとサブツリーが独立するという事実を利用します。 各ノードについて、可能な最大値ごとにいくつの割り当てが存在するかを計算し、たたみ込みのような分布のマージによって子を結合します。 

根の答えは、1 から D までのすべての k について dp[1][k] を合計することによって得られますが、dp は n を超えると安定するため (サブツリー サイズよりも大きい値は組み合わせ構造内で同様に動作します)、k を n でキャップすることができます。 

n を超える値は集計できる乗算因子のみに寄与するため、これにより D への依存が線形から対数に効果的に減少します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(D^n) | O(n) | 遅すぎる |
 | 値の状態に対するツリー DP | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを 1 にルートし、子が親より先に解決されるようにノードを事後処理します。 

1. DP テーブル dp[u] を定義します。ここで、dp[u][k] は、すべての値が含まれる u のサブツリー内の有効な割り当ての数を表します。$[1, k]$そして、そのサブツリーで使用される最大値は正確に k です。 この定式化により、許容上限の増加に応じてサブツリーがどのようにスケールするかのみを追跡することが保証されます。 
2. リーフ ノード u の場合、すべての割り当てはその値 k を選択するだけなので、dp[u][k] は 1 から D までのすべての k について (概念的には) 1 になります。 n を超える値は同様に動作するため、サイズ n までのみを格納します。 
3. 内部ノード u を処理するときは、単一​​ノードの寄与として初期化された dp[u] から開始します。 ノード自体は k までの任意の値を取ることができるため、最初は dp[u][k] はすべての k に対して 1 になります。 
4. 次に、各子 v を u にマージします。 重要な制約は、v のサブツリーも同じ上限 k を尊重しなければならず、u のすでに処理された残りの子と独立して結合する必要があるということです。 これにより、プレフィックス構造を整列させた後、dp 配列の点ごとの乗算が行われます。 
5. マージ ステップでは、プレフィックスの合計を使用して、子サブツリー内の k までの値を割り当てる累積的な方法を k ごとに効率的に計算します。 これにより、可能なすべての子の最大値を明示的に反復処理することが回避されます。 
6. すべての子を処理した後、dp[u][k] は、k で区切られたサブツリー u 内の有効な構成の数を表します。 
7. 最終的な答えは dp[1][D] ですが、dp は k ≥ n で安定するため、min(D, n) まで計算します。 

### なぜ効果があるのか

 DP 状態は、単調な制約ファミリーをエンコードします。k を増加すると、制約が緩和されるだけです。 この単調性により、各サブツリーは兄弟間の相互作用ではなく、親から渡された上限のみに依存するため、サブツリーの寄与がきれいに構成されることが保証されます。 ツリー構造では、親制約が与えられた場合に子の条件付き独立性が保証されるため、累積 DP 状態の乗算により、二重カウントや省略が発生することなく正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, D = map(int, input().split())
    g = [[] for _ in range(n)]
    for i in range(1, n):
        p = int(input()) - 1
        g[p].append(i)

    K = min(n, D)

    dp = [None] * n

    def dfs(u):
        nonlocal dp
        # dp[u][k] for k=1..K
        cur = [1] * (K + 1)

        for v in g[u]:
            dfs(v)
            nxt = [0] * (K + 1)

            # prefix sums of child
            pref = [0] * (K + 1)
            for i in range(1, K + 1):
                pref[i] = (pref[i - 1] + dp[v][i]) % MOD

            for k in range(1, K + 1):
                # child must be <= k
                nxt[k] = cur[k] * pref[k] % MOD

            cur = nxt

        dp[u] = cur

    dfs(0)
    print(dp[0][K] % MOD)

if __name__ == "__main__":
    solve()
```DFS は dp テーブルを完全に構築した後でのみ各ノードが子を集約するように dp をボトムアップで計算します。 子に対するプレフィックス合計により、k を超えない値に効率的に制限でき、単調な給与制約をエンコードできます。 

実装の微妙な詳細は、n を超えると単調代入の組み合わせ構造が新しい個別の状態を導入できないため、dp 配列の上限が K = min(n, D) であることです。 これにより、D への依存が回避されます。$10^9$。 

乗算ステップでは、同じ上限 k を条件として独立したサブツリーの選択を結合します。 これは、親の最大許容給与が固定されると、各子サブツリーが独立して貢献するという事実を反映しています。

 ## 特殊なケース

 単一ノード ツリーの場合、DP は、すべての可能な値をカウントすることになります。$[1, D]$。 アルゴリズムは K までのすべての k に対して dp[1][k] = 1 を初期化し、最終的な答えは K になります。これは、D ≤ n の場合は D に等しく、それ以外の場合は n となり、正しい範囲の動作と一致します。 

チェーンの場合、すべてのノードはその親に完全に依存するため、dp 伝播によって累積的な制約が形成されます。 プレフィックスの乗算により、追加の各ノードが有効なプレフィックスの数を正しく乗算し、パスに沿った非増加構造を維持します。
