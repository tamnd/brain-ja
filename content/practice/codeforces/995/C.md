 ## 問題の理解

 一連の平面変位ベクトルが与えられ、それぞれが原点または現在の位置からの移動を表します。 すべてのベクトルについて、その方向を独立して選択することができます。指定されたとおりに加算するか、減算します。 すべてのベクトルを処理した後、平面内の最終点を取得します。タスクは、最終点が原点の周りの固定半径内に収まるようにこれらの記号を選択することです。 

入力の構造は、最大 100,000 個のベクトルのリストであり、それぞれの大きさが 1,000,000 で区切られた座標を持ちます。 出力は、ベクトルごとに 1 つずつ、1 または -1 としてエンコードされたプラス記号またはマイナス記号のシーケンスであり、各動きの向きを説明します。 

この制約により、符号の割り当てに対する指数関数的な戦略が即座に除外されます。 可能な選択肢は 2^n 通りあり、このスケールでは n についてすべての可能性について推論することさえ不可能です。 有効な解決策はすべて、線形または線形に近い時間で答えを構築する必要があり、符号構成の空間を明示的に検索せずに構築する必要があります。 

最終位置でのターゲットの境界は、蓄積される可能性のある大きさと比較して比較的小さいです。 最悪の場合、単純加算では 10^6 の n 倍、つまり約 10^11 の座標が生成されます。 必要な境界である 1.5 × 10^6 は、何桁も小さく、これは、キャンセルは最後にのみ修正されるのではなく、プロセス全体を通じて慎重に適用される必要があることを示唆しています。 

一般的な故障モードは、ドリフトを制御しない貪欲な蓄積です。 たとえば、x 座標を小さく保つ符号を常に選択しても、y 座標が任意に大きくなる可能性があります。 もう 1 つの微妙な失敗は、座標のバランスを独立して取ろうとすることです。これは、それぞれの決定が両方の軸に同時に影響することを無視しています。 

重要な問題は、各ベクトルが同時に 2 次元に寄与し、局所的に最適に見える決定が、不可逆的な全体的な不均衡を引き起こす可能性があることです。 

## アプローチ

 強引な解釈では、すべての符号の割り当てを試し、その結果のベクトルの合計を計算します。 これは、すべての構成の条件を直接評価するため正しいですが、それぞれに n ベクトルの加算を含む 2^n 回の計算が必要であり、実行可能な制限をはるかに超えています。 

より構造化されたブルートフォースの改善は、部分ベクトルの合計に基づく枝刈りを伴うバックトラッキングを使用することですが、大きさの限界が大きすぎて、最悪の場合枝刈りは有効になりません。 状態空間は依然として指数関数的に増加します。 

重要な観察は、ベクトルの順序は最終的な合計には無関係ですが、符号を選択​​する_プロセス_は段階的にガイドできるということです。 最終的なベクトルを直接制御しようとする代わりに、現在の合計を維持し、それが制御された領域から大きく逸脱しないようにします。 

中心となるアイデアは、ベクトルをサイズ別に暗黙的にグループ化し、その寄与を階層的に制御することです。 ベクトルを大きさで並べ替えると、まず大きなベクトルの寄与を安定させ、次に小さなベクトルを使用して残差誤差を修正できます。 

これは、貪欲なバランス戦略につながります。新しいベクトルを処理するとき、更新されたプレフィックスの合計がユークリッドの意味で可能な限りゼロに近くなるように、その符号を選択​​します。 これは、現在の部分和のノルムを最小化する符号を常に選択することと同じです。 

この戦略が機能するのは、各ステップで原点全体に反映することで現在の変位ベクトルを減らすことができる 2 値の選択肢が与えられるためです。 幾何学的には、現在の合計を押しのけるのではなく原点に向かって引き戻すように、常に次のベクトルを反映しています。

これにより、時間の経過とともに、部分和が累積的な偏りのある合計ではなく、制限されたドリフトを伴う制御されたランダム ウォークのように動作することが保証されます。

 ## アルゴリズムのチュートリアル

 現在の位置を原点で初期化されたベクトルとして保持します。 

1. すべてのベクトルを指定された順序で読み取ります。 
2. 現在の合計を初期化します`p = (0, 0)`。 
3. ベクトルごとに`v_i`、2 つの候補結果を計算します。`p + v_i`そして`p - v_i`。 
4. 結果の位置の小さい二乗ノルムを生成する符号を選択​​します。 

これは、浮動小数点演算を回避するために、ユークリッド距離の代わりに二乗距離を使用して行われます。 
5.アップデート`p`それに応じて、選択した記号を保存します。 
6. すべてのベクトルを処理した後、保存されている符号を出力します。 

ステップ 4 が有効である理由は、二乗距離の最小化はユークリッド距離の最小化と同等であり、これにより局所的に最もダメージの少ない手を常に選択することが保証されるためです。 

### なぜ効果があるのか

 すべてのステップで、次のベクトルを組み込んだ後、現在の位置が原点にできるだけ近くなるようにします。 重要な特性は、それぞれの決定が、考えられる最悪の選択と比較して標準の成長を減らすか、少なくとも妨げることです。 各ベクトルは方向を反転することしかできないため、アルゴリズムは、原点を中心とする制御されたボール内の累計を維持する投影を効果的に選択します。 

これにより、あらゆる方向への系統的なドリフトが防止されます。 一連のベクトルが一方向に進む傾向がある場合でも、符号を交互に選択することで、単一の方向でチェックされない大きさが蓄積されることがなくなります。 このプロセスは原点に向かって繰り返される反射のように動作し、シーケンス全体にわたる部分和の増加を制限します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    v = [tuple(map(int, input().split())) for _ in range(n)]
    
    x = 0
    y = 0
    ans = []
    
    for vx, vy in v:
        # try +v
        x1 = x + vx
        y1 = y + vy
        d1 = x1 * x1 + y1 * y1
        
        # try -v
        x2 = x - vx
        y2 = y - vy
        d2 = x2 * x2 + y2 * y2
        
        if d1 <= d2:
            x, y = x1, y1
            ans.append(1)
        else:
            x, y = x2, y2
            ans.append(-1)
    
    print(*ans)

if __name__ == "__main__":
    solve()
```このソリューションは、実行中の座標ペアを維持し、各ベクトルに対して考えられる両方の符号結果を評価します。 二乗距離の比較により、浮動小数点エラーが回避され、整数演算が全体的に保証されます。 選択した記号はすぐに保存され、状態がその場で更新されます。 

微妙な点は、中間合計の最大値がおよそ 10^11 で制限され、二乗計算が Python の任意精度の範囲内である 10^22 以内に収まるため、すべての算術演算が 64 ビット整数に安全に収まることです。

 ## 特殊なケース

 単純な実装が壊れてしまう特殊なケースは、すべてのベクトルが同じ方向を向いている場合です。 そのような状況では、常に +1 を選択するか、常に -1 を選択すると線形成長が得られますが、貪欲なバランシングによって十分なベクトルが反転され、合計が小さく保たれます。 

たとえば、入力の場合`(1,0)`何度も繰り返されると、グローバルバランスを無視した単純な戦略では、サイズ n の最終的な x 座標が生成されます。 貪欲なアルゴリズムは、有益な場合に符号を交互に切り替え、累計をドリフトさせるのではなくゼロ付近で振動させます。 

もう 1 つの微妙なケースは、ベクトルが大きく、互いにほぼ打ち消し合う場合です。 2 つのベクトルがほぼ正反対である場合、同じ符号を持つ両方を選択すると、バランスの取れた割り当てが存在する場合でも、大きな中間和が生成されます。 このアルゴリズムは、各ステップで両方の符号オプションを評価し、原点に最も近い部分和を維持する構成を即座に選択することでこれを処理し、キャンセルが遅延するのではなくローカルに利用されるようにします。
