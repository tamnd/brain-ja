 ## 問題の理解

 長さのすべてのバイナリ文字列に対して定義された関数が与えられています。$n$。 これを次の表として考えてください。$2^n$エントリ、ビットマスクごとに 1 つの値。 最初は、このテーブルのすべてのエントリに何らかの数値が入力されます。 

このテーブルのどのエントリが最終的に公開されるかを決定するためにゲームが行われます。 空の代入から始める$n$変数を使用して、プレイヤーは完全なバイナリ文字列が形成されるまでビットを徐々に割り当てます。 各ステップでは、どのプレイヤーが行動するかをランダムに選択し、そのプレイヤーは割り当てられていないポジションを選択し、それに値 0 または 1 を割り当てます。すべての変数が割り当てられた後、ゲームの値は、結果として得られるバイナリ文字列に対応するテーブル エントリにすぎません。 

アレンはこの最終値を大きくすることを望み、ベッシーはそれを小さくすることを望み、両方ともテーブルの完全な知識を持って最適にプレイします。 

このゲームの期待される結果を計算した後、テーブルがわずかに変更されます。単一のエントリが更新され、期待値を再計算する必要があります。 これは複数回発生するため、更新のたびに新しい期待を報告する必要があります。 

この制約は、ゲームを直接シミュレートできないことをすぐに示唆しています。 テーブルのサイズは以下の通りです$2^{18}$、更新数も最大です。$2^{18}$, それでさえ$O(n 2^n)$クエリごとの速度はすでに遅すぎます。 

単純なアプローチでは、部分的な割り当てをツリーとしてゲームをモデル化しようとします。 各状態は、どの変数がすでに固定されているかだけでなく、割り当てられた値にも依存します。 これは爆発につながります。サブセットと代入の両方を追跡すると、結果が得られます。$3^n$州はすでに大きすぎて、$n = 18$、そして移行にはミニマックスの決定が含まれるため、事態はさらに悪化します。 

よくある微妙な失敗例は、誰が最初に動くかというランダム性を無視しようとすることから生じます。 たとえば、Allen が常に最初に移動すると誤って仮定した場合、値は変数の順序に対する決定的な最小値となり、まったく異なる結果が生成されます。 などの小さなケースでも、$n=2$、これは、異なるプレイヤーが最初に行動するときに誤った答えにつながります。 

もう 1 つの失敗は、「変数を割り当てる順序は重要ではない」と仮定することから生じますが、これは一般的なミニマックス ゲームでは誤りです。 ここでの正しさは、最小値と最大値の構造を慎重に書き出した後にのみ表示されるキャンセルにかかっています。 

## アプローチ

 ブルートフォース定式化では、空の状態からゲームを明示的にシミュレートします。 それぞれの部分的な割り当てから、次の変数のすべての選択肢を考慮し、0 または 1 の割り当てで分岐し、最適なプレイの下で結果の状態を再帰的に評価します。 これですでにおおよそのサイズのゲーム ツリーが形成されます$n! \cdot 2^n$、各変数の順序が現れる可能性があり、各代入により分岐が 2 倍になるためです。 状態は割り当てられた変数とその値の両方をエンコードする必要があるため、積極的なメモ化でも役に立ちません。$O(3^n)$州。 

重要な簡素化は、プレーヤーが実際に影響を与えるものを分離することから生まれます。 プレーヤーは最終的なビット文字列を直接制御しません。 次にどの座標が公開されるかを選択するだけです。 座標が選択されると、その座標に対する最適な応答は、それを 0 または 1 に設定することによって得られる 2 つのサブツリーにのみ依存します。 

固定座標の場合$i$を設定した場合の残りのゲーム値を仮定します。$x_i=0$または$x_i=1$は$A$そして$B$。 アレンが動いた場合、彼は 2 つのうちの良い方を選択するため、結果は次のようになります。$\max(A,B)$。 ベッシーが動けば、悪い方を選び、$\min(A,B)$。 引越し業者は確率で選ばれるので$1/2$、座標を選択することで期待される貢献度$i$は次のようになります:$$\frac{1}{2}(\max(A,B) + \min(A,B))$$決定的なアイデンティティは、$\max(A,B) + \min(A,B) = A + B$したがって、これは次のように単純化されます。$$\frac{A + B}{2}$$どのプレイヤーが移動したかへの依存性は完全になくなります。 

これにより、ゲーム全体がハイパーキューブ上の線形平均プロセスに組み込まれます。座標を選択すると、その座標が 2 つの半分の平均値に置き換えられるだけです。 平均化は座標間で可換であるため、変数を削除する順序は重要ではありません。 

したがって、プロセスは全次元の平均化を繰り返し適用することになり、その結果、テーブル内のすべての値が一様に平均化されます。

 ## アルゴリズムのチュートリアル

 1. すべての最初の合計を計算します。$2^n$表内の値。 これは、更新前のディストリビューションの総質量を表します。 
2. この合計を次の値で割ります。$2^n$ゲームの初期期待値を取得します。 ゲームの構造により、最終結果はすべてのリーフの均一な平均​​化に帰着します。 
3. 更新が到着すると、合計を動的に維持します。 更新ごとに 1 つのエントリが置き換えられるため、古い値を減算し、新しい値を追加します。 
4. 各更新後に、現在の合計を で割った値として期待値を再計算します。$2^n$。 

### なぜ効果があるのか

 変数が選択される各ステップで、2 人のプレーヤーの最適な応答が崩れて 2 つの部分問題の平均がとられます。 これにより、戦略的順序や敵対構造への依存が排除されます。 各次元は線形平均演算子として機能するため、すべての次元を構成します。$n$演算子はすべてを均一に平均します。$2^n$葉。 線形性により、ローカルな更新はグローバルな合計にのみ影響し、部分的な割り当てに関する隠された構造情報はプロセス中に残らないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, r = map(int, input().split())
    size = 1 << n
    arr = list(map(int, input().split()))
    
    total = sum(arr)
    inv = 1.0 / size
    
    print(total * inv)
    
    for _ in range(r):
        z, g = map(int, input().split())
        total -= arr[z]
        arr[z] = g
        total += g
        print(total * inv)

if __name__ == "__main__":
    main()
```この実装は、配列のグローバル合計の維持のみに依存しています。 設計上の重要な選択は、ゲーム構造をシミュレートする試みを避けることです。 平均化の性質が認識されると、ゲーム理論の複雑さはすべてなくなります。 浮動小数点除算は印刷時にのみ実行されるため、中間ステップでの精度誤差の蓄積が回避されます。 

微妙な点は、再計算にはコストがかかるため、更新では毎回合計を再計算するのではなく、段階的に合計を調整する必要があることです。$O(2^n)$クエリごとに実行され、最大入力サイズでは遅すぎます。

 ## 特殊なケース

 特殊なケースは、テーブル内のすべての値が同一である場合に発生します。 この状況では、1 つのエントリを除いて、どの更新も均一な構造を保持しており、期待値はグローバル合計調整を通じてのみ変更されます。 このアルゴリズムは、分散や構造には決して依存せず、合計のみに依存するため、これをきれいに処理します。 

もう 1 つのエッジ ケースは、更新が繰り返し同じインデックスを対象とする場合です。 毎回最初から合計を再計算する素朴な実装はまだ正しいですが、遅すぎます。一方、増分更新戦略は、新しい値を追加する前に前の値を減算することで繰り返しの上書きを自然に処理します。 

最後に、いつ$r = 0$の場合でも、期待値は初期合計にのみ依存するため、解は更新ループに入らなくても正しい初期平均を出力します。
