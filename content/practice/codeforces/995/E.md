 ## アルゴリズムのチュートリアル

 私たちは、制御された拡張の深さと訪問された状態のハッシュを使用した双方向の構築に依存しています。 

1. まず、各状態を 3 つの遷移を持つグラフ内のノードとして扱います。 グラフ全体を探索する代わりに、2 つの部分的な検索ツリーを構築します。$u$、もう一方のルートは$v$ただし、逆トランジションを使用します。 
2. 両側の最大深度 100 を定義します。 これは、2 つのパスを連結することで最大 200 の操作が行われ、制限を満たすように選択されます。 
3. スタート状態から$u$、有界幅優先拡張を実行します。 各ノードは、現在の値と、その値に到達するために使用される一連の操作の両方を保存します。 また、値を対応する操作シーケンスにマッピングする辞書も維持します。 値が繰り返される場合、最も短いシーケンスが維持されます。 
4. 目標状態から$v$、同様の展開を実行しますが、演算を逆に解釈します。 インクリメントとデクリメントは相互に対称の反転ですが、反転は自己反転です。 これにより、許可された操作セットを変更せずに後方到達可能性をシミュレートできます。 
5. 展開中に、前方辞書と後方辞書の両方に値が表示されるたびに、合流点が見つかりました。$x$。 次に順方向シーケンスを結合します$u \to x$そして逆の逆方向シーケンス$v \to x$(順方向に反転) 有効なフルパスを形成します。 
6. 合計の長さが 200 を超えないように、連結されたシーケンスを出力します。 

### なぜ効果があるのか

 状態空間は操作の下で有限のグループのような構造を形成し、すべての操作は可逆的または対称的に可逆的です。 これにより、からの前方到達可能性が保証されます。$u$からの後方到達可能性$v$同じ接続コンポーネントをカバーします。 分岐係数は固定されており、深さの上限は 100 であるため、検索ではこの空間内の十分に大きな対称ボールが探索されます。 鳩の巣原理は、問題ステートメントが 200 手以内のパスの存在を保証しているため、この制限された探索内で共通の状態に到達する必要があることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque, defaultdict

def apply(x, op, p):
    if op == 1:
        return (x + 1) % p
    if op == 2:
        return (x - 1) % p
    return pow(x, p - 2, p)

def bfs(start, p, limit):
    q = deque([start])
    dist = {start: []}
    while q:
        x = q.popleft()
        if len(dist[x]) == limit:
            continue
        for op in (1, 2, 3):
            y = apply(x, op, p)
            if y not in dist:
                dist[y] = dist[x] + [op]
                q.append(y)
    return dist

def invert_op(op):
    if op == 1:
        return 2
    if op == 2:
        return 1
    return 3

def main():
    u, v, p = map(int, input().split())

    if u == v:
        print(0)
        print()
        return

    A = bfs(u, p, 100)
    B = bfs(v, p, 100)

    meet = None
    for x in A:
        if x in B:
            meet = x
            break

    path1 = A[meet]
    path2 = B[meet]

    path2 = [invert_op(x) for x in reversed(path2)]

    res = path1 + path2
    print(len(res))
    print(*res)

if __name__ == "__main__":
    main()
```この実装では、深さ 100 に制限された 2 つの BFS レイヤーが構築されます。各状態はルートからの完全なパスを保存します。これは、分岐が早期に切り詰められるため、制約の下では許容されます。 

重要な実装の詳細は、バックワード パスの反転と操作の反転です。 インクリメントとデクリメントは役割を交換しますが、反転は変更されません。 これにより、再構築されたパスが連結時に有効であることが保証されます。 

このミーティング ポイントは、2 つの BFS フロンティア間の最初の衝突として選択されます。 両側が保証された解の半径内に制限されているため、衝突はあれば十分です。

    import sys
    from collections import deque, defaultdict

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$u = v$。 このアルゴリズムは明示的に空のシーケンスを直ちに返し、不必要な BFS 作業を回避します。 たとえば、入力$5\ 5\ 101$は操作を生成しません。開始状態がすでに目標を満たしているため、これは正しいことです。 

もう一つのケースは次のような場合です。$u = 0$。 反転は常にあるので、$0$べき乗剰余では、状態には操作 3 の自己ループがあります。BFS はこれを正しく処理します。これは、BFS がすでに見た状態の再訪を無視するためであり、そのため、ループが検索ツリーを誤って展開することはありません。
