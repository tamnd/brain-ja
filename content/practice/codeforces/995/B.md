 ## 解決策
 ## 問題の理解

 ラインナップをご用意させていただいております$2n$各整数のラベルがどこから来た人$1$に$n$正確に 2 回表示されます。 各ラベルはカップルを表すため、目標は、すべての数字の両方の出現が互いに隣り合うように行を再配置することです。 

許可される唯一の操作は、隣接する 2 人の人物を交換することです。 初期配置をすべてのペアが連続ブロックを形成する配置に変換するために必要な、このようなスワップの最小数が必要です。 

これは古典的な「ペアになったアイテムをグループ化するための最小隣接スワップ」問題です。 重要な制約は、$n \le 100$, したがって、ポジションは最大 200 です。 これにより、順列を超える指数関数的なものはすぐに除外されますが、それでも許容されます。$O(n^2)$あるいは$O(n^3)$心地よく近づいていきます。 

微妙な点は、ペアリングが最初は予測可能な構造に揃っていないことです。 数値は、その 2 つの出現を任意に遠く離れて配置することができ、複数のペアをインターリーブすることができます。 

単純な間違いは、将来の干渉を考慮せずに、最初に出現したものと右に次の同じ値をペアにするなど、ローカルの貪欲ペアリングが常に最適であると想定することです。 たとえば、次のような配置です。```
1 2 1 2
```最初のペアリング`1`最も近いものと貪欲に`1`要素を移動する必要がある`2`ただし、ペアごとに個別にこれを行うと、慎重に扱わないと、スワップが二重にカウントされたり、スワップの順序が間違ったりする可能性があります。 正しい解決策は、1 つのペアを修正すると他のペアに影響を与える可能性があるという事実を考慮する必要があります。 

もう 1 つの潜在的な問題は、配列構造を更新せずにスワップをペアごとに独立したものとして扱うことです。 スワップは要素を物理的に移動するため、後の決定は以前の操作に依存します。 

## アプローチ

 ブルートフォースの観点は、有効な配置をもたらす隣接スワップの可能なすべてのシーケンスをシミュレートし、最小の長さを選択することです。 「常に間違ったペアを最初に修正する」と制限しても、各ステップでどの間違ったペアを修正するかについて多くの分岐選択肢が残ります。 状態空間は本質的に次のすべての順列です。$2n$要素、つまり$(2n)!$、たとえ$n = 10$。 

より構造化されたブルート フォースでは、隣接するスワップによって定義されたエッジを持つ順列に対して BFS を試みます。 これは正しいです。各スワップには単位コストがあるため、BFS は最短パスを見つけます。 ただし、各州には、$O(n)$隣接する状態と状態の数は$(2n)!$、これは完全に不可能になります。 

重要な観察は、実際にはグローバルなすべての要素の同一性については気にしておらず、一致するペアをまとめるためにどれだけの反転が必要かということだけを気にしているということです。 左から右にスキャンして、各最初の出現をそのパートナーと「一致させる」方法を決定するとき、このプロセスを、ペアを繰り返し抽出し、交差する必要がある要素の数をカウントするものとして扱うことができます。 

これは、配列を左から右に処理するという建設的な貪欲戦略につながります。 ペアの最初の要素に遭遇すると、そのパートナーを特定し、それらの間にある要素の数を数えます。 この数は、左方向に「引く」と仮定して、パートナーを最初の出現の次の位置に移動するために必要な隣接スワップの数に正確に対応します。 これを行った後、概念的にはペアを削除し、縮小された配列で続行します。 

これが機能するのは、すべてのスワップがローカルな順序にのみ影響するためであり、一度ペアが修正されると、それを考慮から外せば再びそれを乱す必要がなくなるからです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 順列に対するブルート フォース BFS |$O((2n)! \cdot n)$|$O((2n)!)$| 遅すぎる |
 | 除去シミュレーションによる貪欲なペアリング |$O(n^2)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 現在の行を表す可変リストを維持します。 左から右にペアを繰り返し修正します。 

1. 配列の最初の位置からスキャンを開始します。 
2. 位置を見つけるとき$i$、値を特定します$x = a[i]$。 次に、次の出現を検索します。$x$右側の位置$j$。 ペアは最初は隣接していないため、この検索が必要です。 
3. このカップルのペアリングにかかる​​費用は$j - i - 1$。 これは 2 つの出現間の要素の数を表し、2 つの要素を作成するには、これらの各要素が端点の 1 つを少なくとも 1 回交差する必要があります。$x$が隣接しています。 
4. このコストを答えに追加します。 
5. 両方の出現箇所を削除します。$x$配列から。 これは、後のステップに干渉しないように、ペアを永続的に固定することをシミュレートします。 
6. 縮小されたアレイ内の次に利用可能な位置からスキャンを続けます。 

より実装しやすいバージョンでは、インデックスを使用して位置をシミュレートし、一致した要素をマークすることで、リストの繰り返しの削除を回避しますが、概念的には同じロジックが適用されます。 

### なぜ効果があるのか

 各ペアは 1 回だけ解決され、ペアを修正するときに、最適な隣接スワップ シーケンスでそれらを隣接させるために交差する必要がある要素の正確な数を計算します。 ペアを削除すると、そのペアに関係するすべての相互作用が排除されるため、後の計算は厳密に小さな独立した部分問題に対して実行されます。 これにより、スワップが二重にカウントされず、今後の操作によって以前のコスト計算が無効になることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    used = [False] * (2 * n)
    pos = {}
    
    for i, v in enumerate(a):
        if v not in pos:
            pos[v] = i
    
    ans = 0
    
    i = 0
    while i < 2 * n:
        if used[i]:
            i += 1
            continue
        
        x = a[i]
        j = i + 1
        while used[j] or a[j] != x:
            j += 1
        
        ans += j - i - 1
        
        used[i] = True
        used[j] = True
        
        i += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、最初に一致しなかった各出現箇所と、次に一致するパートナーとのペアリングをシミュレートします。 の`used`array は、要素が一度一致すると、その後のスキャンでは無視されることを保証します。 内側のループは、既に削除された要素をスキップして、次に出現する同じ値を検索します。 貢献`j - i - 1`答えは直接蓄積されます。 

実装の微妙な点は、配列を物理的に圧縮しないことです。 代わりに、`used`配列。 これにより、繰り返しを避けることができます$O(n)$正確性を維持しながら削除します。
