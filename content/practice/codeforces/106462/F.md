 ## 解決策
 ## 問題の理解

 グリッドはセルで構成される長方形の迷路を表しており、一部のセルは壁でブロックされており、残りは歩行可能です。 歩行可能なセルの中には、A としてマークされた開始位置が 1 つだけあり、G としてマークされたターゲット セルが 1 つだけあります。開始セルからは、4 つの基本方向に一度に 1 歩ずつ移動できますが、壁ではないセルにのみ移動できます。 タスクは、A から始まり最終的に G に到達する一連の有効な手が存在するかどうかを判断することです。 

迷路は複雑に見えるかもしれませんが、問題は純粋にグリッド グラフの接続性に関するものです。 各フリー セルはノードとして機能し、直交する隣接するフリー セルの間にエッジが存在します。 

制約は小さく、グリッドは最大 100 x 100 であるため、ノードの数は最大 10,000 です。 このサイズは、グリッド全体を複数回探索するソリューションでも十分に高速であることをすでに示唆しています。 各セルに一定回数接触するトラバースは十分に制限内ですが、すべてのパスを明示的にチェックするなど、セルのペアごとに超線形なものは不要です。 

いくつかの危険な状況は、一見したときよりも重要です。 1 つは、A と G が壁によって別の領域に囲まれている場合です。 たとえば、狭い廊下が 1 つのブロック セルによって分割されているとします。```
A . #
# # #
. . G
```A と G は両方とも存在しますが、それらは接続されていないコンポーネント内にあるため、答えは NO でなければなりません。 「オープンスペースは到達可能性を意味する」と仮定する素朴なアプローチは、ここでは失敗します。 

もう 1 つのケースは、最短経路が存在するものの、障害物を迂回する必要があるため明らかではない場合です。```
A . # . G
# . # . #
# . . . #
```ここで、G に向かう貪欲な動きは失敗する可能性があります。局所的な選択によって迷路の進行が保証されるわけではないからです。 正しいソリューションを実現するには、単一の方向に固執するのではなく、代替案を模索する必要があります。 

最後に、A と G が隣接していても、斜めにブロックされたり、周囲の壁によって移動が妨げられたりする可能性があります。 共有エッジのみが重要です。 斜めに近づくと移動できなくなります。 

## アプローチ

 直接的なアプローチは、これを経路探索問題として扱い、A から G までのルートを明示的に構築しようとすることです。循環を避けるために訪問したセルにマークを付けて、考えられるすべての移動シーケンスを再帰的に試行することを想像することもできます。 これが機能するのは、グリッドが有限で移動が制限されているためであり、最終的には到達可能なすべての状態が探索されます。 ただし、最悪の場合、可能なパスの数はオープンセルの数に応じて指数関数的に増加します。 多くの空のセルがある 100 x 100 のグリッドでは、このアプローチは、異なる順序のステップを通じて同じ領域を再訪問する、膨大な数の冗長な部分パスを試行します。 

重要な観察は、セルにアクセスする順序は到達可能性にとって重要ではないということです。 重要なのは、グリッド セルの暗黙的なグラフにおいて G が A と同じ連結成分にあるかどうかだけです。 これが分かると、問題は標準的なグラフ走査に帰着します。つまり、A から開始して、幅優先検索または深さ優先検索のいずれかを使用して、到達可能なすべてのセルを探索します。 各セルは最大 1 回処理され、すべてのエッジはノードを展開するときにのみチェックされます。 

これにより、パスの列挙が完全に不要になります。 一連の動きについて推論する代わりに、グラフのプロパティとしての到達可能性について推論します。

 ## アルゴリズムのチュートリアル

 各フリー セルがノードであり、エッジが隣接するフリー セルを接続するグラフとしてグリッドをモデル化します。 

1. グリッドを読み取りながら、A と G の座標を見つけます。 これにより、グラフ内の開始ノードとターゲット ノードが得られます。 
2. BFS のキュー (または DFS のスタック) を初期化し、開始位置 A を挿入します。また、セルの再訪問を避けるために、グリッドと同じサイズの訪問済み配列を維持します。 
3. 構造体が空ではない場合、次のセルを削除し、それを現在の位置として扱います。 
4. 現在位置が G の場合、A から G に到達できることが証明されたので、すぐに停止できます。 
5. それ以外の場合は、上下左右の 4 方向に移動してみます。 それぞれの近隣について、それが壁ではなくグリッドの内側にあるか、まだ訪問していないかを確認します。 すべての条件が当てはまる場合は、訪問済みとしてマークし、キューに追加します。 
6. G に到達することなくトラバースが終了した場合、A から G に到達できなくなります。 

正確さは、キューには、何らかのパスを介して A から到達可能であるがまだ処理されていないグリッド セルのセットが常に正確に含まれるという不変条件から得られます。 セルをポップするたびに、A からそのセルを通る有効なパスを延長するためのすべての方法を徹底的に調査します。 到達可能なセルはすべて最終的に発見されるため、G が到達可能な場合は、最終的にキューに入れて処理する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    H, W = map(int, input().split())
    grid = []
    start = goal = None

    for i in range(H):
        row = list(input().strip())
        grid.append(row)
        for j, c in enumerate(row):
            if c == 'A':
                start = (i, j)
            elif c == 'G':
                goal = (i, j)

    sx, sy = start
    gx, gy = goal

    q = deque()
    q.append((sx, sy))
    visited = [[False] * W for _ in range(H)]
    visited[sx][sy] = True

    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    while q:
        x, y = q.popleft()

        if (x, y) == (gx, gy):
            print("YES")
            return

        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < H and 0 <= ny < W:
                if not visited[nx][ny] and grid[nx][ny] != '#':
                    visited[nx][ny] = True
                    q.append((nx, ny))

    print("NO")

if __name__ == "__main__":
    solve()
```このソリューションでは、グリッドを変更せずに、到達可能性のみを追跡します。 訪問された配列は不可欠です。これがないと、BFS は開いた領域で繰り返しサイクルに再入力し、指数関数的な繰り返しに劣化してしまうからです。 

G に到達したときに早期に終了することで、答えがすでに決定されている場合の不必要なトラバースを回避できます。

 ## 特殊なケース

 A と G が隣接しているが壁で隔てられている場合は、隣接しているだけでは十分ではないことを確認します。 次のような入力で:```
#####
#AG##
#####
#...#
#####
```BFS は A から開始し、訪問したことをマークし、近隣を検査します。 G を含むセルは隣接していますが、それが壁またはブロックされた位置である場合 (規則に従って、「#」またはアクセス不能になります)、キューに入れられることはありません。 このアルゴリズムは、歩行可能条件を満たすセルのみを追加するため、実際に到達可能でない限り G は無視されます。 

迷路が一本の長く曲がりくねった通路である場合には、再訪防止が確実に必要となる。 訪問した配列がないと、アルゴリズムは 2 つのセル間を無限に行ったり来たりすることになります。 これにより、各コリドー セルが 1 回処理され、ゴールに到達するかコリドーを使い果たすまで横断が直線的に進みます。
