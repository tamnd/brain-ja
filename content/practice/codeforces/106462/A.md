 ## 解決策
 ## 問題の理解

 概念的な九九が与えられています。`n`行と`m`列。 並んでいます`i`そしてコラム`j`、保存される値は単純に`i × j`。 全部平らにしたら`n × m`値を 1 つのリストにまとめ、降順でない順に並べ替えると、`k`-th position.

 したがって、テーブルを明示的に構築する代わりに、タスクは製品の分布を理解することです。`i × j`そしてそのマルチセットに対するランククエリに答えます。 

制約は大きく、どちらの寸法も最大で`5 · 10^5`、これによりテーブルのサイズが大きくなる可能性があります`2.5 · 10^11`。 エントリを直接列挙しようとするアプローチは直ちに不可能であり、構造を保存することさえ問題外です。 これにより、グリッドを実体化せず、その代わりにグリッドのプロパティをカウントするという解決策が必要になります。 

素朴な解釈では、すべての製品を生成して並べ替えようとするかもしれませんが、単一の行を生成するだけでもコストがかかります。`O(m)`すべての行に対してこれを行うと、`O(nm)`実行可能性をはるかに超えた操作です。 

多くの製品が等しい場合、特に数値が小さい場合、微妙なエッジ ケースが発生します。 For example, in a`3 × 3`テーブル、値`2`出現するのは 2 回だけですが、`4`異なるペアから 3 回表示されます。 製品の独自性を前提としたアプローチは失敗します。 

もう 1 つの問題は、オーバーフロー思考です。積は 32 ビット整数に収まりますが、値の数は 32 ビット整数に収まります。`≤ x`到達できる`n × m`、これには 64 ビット演算が必要です。 

## アプローチ

 ブルート フォース手法は簡単です。すべての値を計算します。`i × j`、それらを配列に格納し、並べ替えて、`k`- 番目の要素。 これは、問題で説明されているマルチセットを直接構築するため、正解です。 ただし、生成する必要があります`n × m`値、最悪の場合は約`2.5 · 10^11`同じ数の要素の乗算とメモリ。 たとえ記憶が無視されたとしても、時間だけがそれを不可能にします。 

重要な構造的観察は、すべての値を知る必要はなく、候補数以下の値がいくつあるかだけを知る必要があるということです。`x`。 この数を効率的に計算できれば、二分探索で答えを得ることができます。 これが機能する理由は単調性です。値が`x`少なくとも`k`- 番目に小さい要素の場合、それより大きい値も有効ですが、それより小さい値は無効になります。 これにより、二分探索に適した単調述語が作成されます。 

したがって、問題は数えることに帰着します。`x`、何ペア`(i, j)`満足する`i × j ≤ x`。 行ごとに`i`、 有効`j`値の由来は`1`まで`min(m, x // i)`。 すべての行を合計すると、合計数が得られます。

 ## アルゴリズムのチュートリアル

 1. 最小値を探します`x`少なくともそうなるように`k`表内の数字は`≤ x`。 これにより、ランキングの問題が決定の問題に再構成されます。 
2. 二分探索境界を以下から設定します。`1`に`n × m`、最小値は`1 × 1`そして最大のものは`n × m`。 
3. 候補値について`mid`、製品の数を計算します`i × j`は`≤ mid`。 行ごとに`i`、有効な列を次のように数えます。`min(m, mid // i)`。 これは行にあるため機能します`i`、値は次のように直線的に増加します。`i, 2i, 3i, ...`。 
4. これらのカウントをすべて合計します。`i`から`1`に`n`。 合計が少なくとも`k`、 それから`mid`は十分大きいので、検索を左に移動します。 それ以外の場合は、右に進みます。 
5. 二分探索が収束した後、答えは最小になります`mid`条件を満たすものです。 

### なぜ効果があるのか

 核となる不変条件は、関数が`F(x)`「テーブルエントリの数 ≤ x」として定義される値は、`x`。 一度の値`x`カウントを生成します ≥`k`、値が大きいほどカウント ≥ も生成されます。`k`。 この単調な構造により、二分探索が有効な最小値に収束することが保証されます。これはまさに`k`-ソートされたマルチセット内の 2 番目に小さい要素。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, k = map(int, input().split())

def count_le(x):
    total = 0
    for i in range(1, n + 1):
        total += min(m, x // i)
    return total

lo, hi = 1, n * m

while lo < hi:
    mid = (lo + hi) // 2
    if count_le(mid) >= k:
        hi = mid
    else:
        lo = mid + 1

print(lo)
```機能`count_le`重要なコンポーネントです。 行インデックスごとに`i`、`x // i`超過する前にその行でどこまで進むことができるかを示します`x`。 それをクランプします`m`各行には`m`列。 

二分探索はインデックスではなく値ドメインで実行されます。 配列は明示的に構築されないため、この区別は重要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m, k = map(int, input().split())

    def count_le(x):
        total = 0
        for i in range(1, n + 1):
            total += min(m, x // i)
        return total

    lo, hi = 1, n * m
    while lo < hi:
        mid = (lo + hi) // 2
        if count_le(mid) >= k:
            hi = mid
        else:
            lo = mid + 1

    return str(lo)

assert run("1 10 5") == "5"

 ## 特殊なケース

 小さなグリッドのような`1 × m`単純なシーケンスのように動作します`1, 2, ..., m`。 各行が最大 1 つの要素に寄与するため、アルゴリズムは正しく削減されます。`min(m, x // i)`になる`min(m, x)`いつ`i = 1`。 

いつ`k = n × m`、答えは最大積でなければなりません`n × m`。 二分検索中は、この最大値を下回る値のみが述語に失敗するため、検索は上限で正しく収束します。 

複数の成形方法など、リピート品が多い場合`6`で`3 × 3`グリッドでは、それぞれが有効であるため、カウント関数にはすべての出現が正しく含まれます。`(i, j)`ペアは独立してカウントされます`min(m, x // i)`。
