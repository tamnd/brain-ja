 ## 解決策
 ## 問題の理解

 一次元の紙ストリップがあります。 最初は、ストリップのすべての位置にちょうど 1 つの紙の層が含まれています。 折り目の位置`p`ストリップの一方の部分を他方の上に配置することにより、短い側の向きが考慮されます。 何度か折りたたんだ後、クエリによって、現在表示されているストリップ上の 2 つのカット位置の間にある紙の総量が求められます。 カットによってすべてのピースがそこに積み重ねられたままになるため、重複するレイヤーは複数回カウントされます。 

入力は、初期幅と一連の操作を記述します。 折り操作を行うと、現在の配置が変更され、幅が減少します。 クエリ操作では、現在のストリップ上の 2 つの位置が与えられ、その間隔内のすべてのレイヤー数の合計が求められます。 

この制約により、セルごとのストリップのシミュレーションを回避する必要があります。 幅と操作数が到達すると、`10^5`、支出するアプローチ`O(width)`折り目ごとに約に達することができます`10^10`これは通常のコンテストの制限をはるかに超えています。 すべての演算が対数に近づく必要があります。 

難しいのは、フォールドによって値だけでなく位置の順序も変更されることです。 現在のレイヤーの総数を保存するだけのソリューションでは、任意の間隔については何も答えることができません。 また、折りたたむたびにレイヤーの順序を保存する必要があります。 

順序が重要である理由を小さな例で示します。 入力の場合:```
3 2
1 1
2 0 2
```所定の位置で折り畳んだ後`1`、2 つの部分が重なっているため、新しいストリップには値が含まれる 2 つの位置があります。`[2, 1]`。 クエリはストリップ全体を要求し、答えは次のようになります。```
3
```幅のみを追跡する不注意な実装では、次のような結果が返されます。`2`というのは、紙の量ではなく位置をカウントすることになるからです。 

もう 1 つのエッジケースは、不均一な折り目です。 のために：```
5 2
1 4
2 0 1
```折り目は左側を長い部分として残します。 新しいストリップには値があります`[1, 1, 1, 2]`したがって、最初の位置にはレイヤーが 1 つだけ含まれており、答えは次のようになります。```
1
```常に左側を右側に反転する間違った実装では、残りの部分がシフトされ、不正な値が返されます。 

## アプローチ

 直接的なアプローチは、現在のストリップを配列に保存することです。 折り目は新しい配列を作成することでシミュレートできます。折り目の位置に応じて、大きい方の辺をコピーし、その上に反転した小さい方の辺を追加します。 折り目は正確に一方のセグメントを他方のセグメントに重ね合わせたものであるため、これは正しいです。 ただし、単一の折り目で電流ストリップのほぼ全体に接触する可能性があります。 幅が近い場合は`100000`多くの折り目があるため、処理される要素の総数は約`10^10`。 

有益な観察は、折り畳みは恣意的な変更ではないということです。 シーケンスを 2 つの部分に分割し、そのうちの 1 つを反転して、部分を連結するだけです。 これは、暗黙的 treap によって効率的にサポートされる操作の正確なセットです。 各 treap ノードは現在のストリップの連続セグメントを表し、そのサブツリーにレイヤー数の合計を格納し、位置による分割と結合をサポートします。 遅延反転フラグを使用すると、すべての要素に触れることなくセグメント全体を反転できます。 

新しいストリップは古いシーケンスの単なる変換であるため、ブルート フォースは機能しますが、多くの変換が大規模な場合は失敗します。 折り目は分割、反転、結合の操作のみであるという観察により、ストリップ構造全体を対数時間で維持することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 暗黙的トレプ | O(q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 以下を含む暗黙的トレプを構築します。`n`ノード。 すべてのノードには最初に値があります`1`、紙の元の部分はすべて単一のレイヤーであるためです。 ノードのサブツリー合計は、現在のストリップのそのセグメント内の紙の量を表します。 
2. クエリの場合、要求された間隔に応じてトレプを分割します。 中央の部分は 2 つのカット間の目に見える位置であるため、保存されている合計が答えになります。 その後、パーツを結合してストリップを復元します。 
3.折り目位置の場合`p`、トレプを長さの左側の部分に分割します`p`そして残りを含む右側の部分。 小さい側は、大きい側を裏返す部分です。 
4. 左側が短いか等しい場合は、逆にして右側の後に置きます。 右側が短い場合は、右側を逆にして左側の後に置きます。 結果として得られるトリープは、新しく折りたたまれたストリップです。 

これが機能する理由は、処理順序が常に現在のペーパーの左から右の順序と一致するためです。 折り目では、隣接する 1 つの辺を反転し、残りの辺の端に移動することによってのみ、この順序が変更されます。 遅延反転操作では、合計レイヤー数を変更せずに順序が変更されるため、保存されているすべての合計は有効なままになります。 

## Python ソリューション```python
import sys
import random

input = sys.stdin.readline

class Node:
    __slots__ = ("val", "sum", "size", "left", "right", "prio", "rev")

    def __init__(self, val):
        self.val = val
        self.sum = val
        self.size = 1
        self.left = None
        self.right = None
        self.prio = random.randint(1, 1 << 30)
        self.rev = False

def size(t):
    return t.size if t else 0

def total(t):
    return t.sum if t else 0

def apply_rev(t):
    if t:
        t.rev ^= True
        t.left, t.right = t.right, t.left

def push(t):
    if t and t.rev:
        if t.left:
            t.left.rev ^= True
        if t.right:
            t.right.rev ^= True
        t.rev = False

def update(t):
    if t:
        t.size = 1 + size(t.left) + size(t.right)
        t.sum = t.val + total(t.left) + total(t.right)

def merge(a, b):
    if not a:
        return b
    if not b:
        return a
    if a.prio > b.prio:
        push(a)
        a.right = merge(a.right, b)
        update(a)
        return a
    else:
        push(b)
        b.left = merge(a, b.left)
        update(b)
        return b

def split(t, k):
    if not t:
        return None, None
    push(t)
    if size(t.left) >= k:
        a, b = split(t.left, k)
        t.left = b
        update(t)
        return a, t
    else:
        a, b = split(t.right, k - size(t.left) - 1)
        t.right = a
        update(t)
        return t, b

def solve(data):
    it = iter(data.split())
    n = int(next(it))
    q = int(next(it))

    root = None
    for _ in range(n):
        root = merge(root, Node(1))

    ans = []
    for _ in range(q):
        typ = int(next(it))
        if typ == 1:
            p = int(next(it))
            left, right = split(root, p)
            if size(left) <= size(right):
                apply_rev(left)
                root = merge(right, left)
            else:
                apply_rev(right)
                root = merge(left, right)
        else:
            l = int(next(it))
            r = int(next(it))
            a, b = split(root, l)
            b, c = split(b, r - l)
            ans.append(str(total(b)))
            root = merge(a, merge(b, c))

    return "\n".join(ans)

if __name__ == "__main__":
    data = sys.stdin.read()
    print(solve(data))
```treap ノードには 3 つの情報が格納されます。 サイズは位置ベースの分割に必要であり、合計はクエリに応答するために必要です。 reverse フラグは子への変更を遅らせるため、大きなセグメントを反転しても 1 つのブール値を反転し、2 つのポインタを交換するだけです。 

の`split`関数は、指定された位置数の後で現在のシーケンスを切り取ります。 クエリとフォールドの両方を連続した部分を取り出すことに還元できるため、これは重要な操作です。 の`merge`関数は、順序を維持しながら 2 つのシーケンスを結合します。 

折り畳むとき、まずコードが両側を分離します。 それらのサイズを比較することで、どちらの側がもう一方の上に物理的に折りたたまれるかが決まります。 折り畳むと向きが変わるため、短辺が逆になります。 これにより、要素の直線的な動きが回避されます。 

クエリ コードは、要求された範囲を分割し、保存されている合計を読み取り、すべてを結合し直します。 境界位置は次の位置で分割することで処理されます。`l`そして残りのシーケンスを次のように分割します。`r - l`、オフバイワンの間違いを回避します。

 ## 特殊なケース

 折り目がちょうど真ん中にあるとき、両側は同じ長さになります。 アルゴリズムは左側を折りたたまれた側として選択しますが、反対側を選択すると、座標の反転後に同じ物理的結果が作成されます。 操作はまだ単に反転してマージするだけであるため、保存されたシーケンスは有効なままです。 

折り目が 1 つの端の近くで発生する場合、短い部分には 1 つの位置のみが含まれる可能性があります。 このアルゴリズムは依然として 1 つの分割と 1 つの遅延反転を実行し、両側のサイズが同様であると仮定する間違いを回避します。 

のために：```
3 2
1 1
2 0 2
```分裂が生み出す`[1]`そして`[1,1]`。 単一要素側が反転され、もう一方の側の後でマージされ、`[2,1]`。 合計額は`3`、折り畳まれたストリップ内の紙の量と一致します。 

のために：```
5 2
1 4
2 0 1
```分裂が生み出す`[1,1,1,1]`そして`[1]`。 小さい方の面を反転して端に取り付けると、正しい残りの順序が得られます。 最初の位置にはレイヤーが 1 つだけ含まれているため、クエリの答えは次のようになります。`1`。
