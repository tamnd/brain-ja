 ## 解決策
 ## 問題の理解

 2 つの配列が与えられています。`a`そして`b`、それぞれの長さ`n`。 の要素`a`はすべて異なりますが、`b`繰り返しの数字が含まれる場合があります。 タスクは、要素を並べ替えることができる方法の数を数えることです。`a`並べ替え後、すべてのインデックスに対して`i`、条件`a[i] > b[i]`が成立する。 結果はモジュロで報告される必要があります$10^9 + 7$。 

概念的に考えると、`a`固有の値を持つカードのセットとして、`b`しきい値として。 カードが厳密にしきい値を超えるように、各カードをしきい値に割り当てる必要があります。 有効な割り当ての数が最終的な答えになります。 

制約により許可されるのは、`n`と同じくらい大きくなる$2 \cdot 10^5$すべてのテストケースにわたって、最大で$10^4$テストケース。 これにより、すべての順列を明示的に試行するソリューションが禁止されます。`n!`たとえ小さくても成長が早すぎる`n`。 強引な階乗法はまったく実行不可能であるため、並べ替えとカウントを活用する方法が必要です。 

エッジケースは、次のすべての要素が含まれる場合に発生します。`b`の最大の要素よりも大きい`a`。 たとえば、次の場合`a = [1, 2, 3]`そして`b = [4, 5, 6]`、条件を満たす方法がないため、出力は次のようにする必要があります。`0`。 いくつかの要素が含まれている場合、別の微妙な状況が発生します。`b`が繰り返されます。 もし`a`大きな要素は十分にあるものの、量が十分ではない場合、単純な比較では無効な順列が誤ってカウントされる可能性があります。 

## アプローチ

 素朴なアプローチは、次のすべての順列を生成することです。`a`各順列が満たされるかどうかを確認します`a[i] > b[i]`みんなのために`i`。 これは正しいですが、まったく現実的ではありません。 のために`n = 10`、これには必要です`10! = 3,628,800`テストケースごとのチェック。 のために`n`何百、何千というと、これは天文学的な数字に膨れ上がります。 

最適化するための重要な洞察は、順列を直接考慮する必要がないということです。 代わりに、両方を並べ替えることができます`a`そして`b`そして要素を貪欲に割り当てます。 もし`a`が昇順にソートされている場合は、最大のものを割り当てることを試みることができます。`a`最大のものまで`b`それは勝つことができるということ。 正式にはそれぞれ`b[i]`、要素の数を数えます`a`厳密には大きいです。 次に、各位置について、以前に使用した要素を考慮した上で、利用可能な選択肢の数を掛けます。 

これにより、問題は並べ替えと線形計数に限定されます。 両方の配列のソートにはコストがかかります`O(n log n)`、有効な選択肢のコストを計算するために繰り返します`O(n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 並べ替え + 数える | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 テスト ケースごとに、次の内容を読んでください。`n`そして配列`a`そして`b`。 
2. 配列のソート`a`昇順で。 並べ替えると、最小のものを簡単に割り当てることができます。`a`それは`b`有効なオプションをスキップせずに。 
3. 配列のソート`b`昇順で。 これにより、しきい値を最小から最大まで処理できるようになります。 最小のものを割り当てる`b`まず、より大きなものに対して選択肢を最大化します`b`後で。 
4. 変数を初期化する`answer = 1`有効な選択肢の実行積を法的に保持する$10^9 + 7$。 
5. インデックスの初期化`j = 0`現在の候補者を追跡するには`a`。 反復処理`b`。 それぞれについて`b[i]`、何個数えますか`a[j]`満足する`a[j] > b[i]`。 このポジションの有効な選択肢の数は次のとおりです`count_available - i`どこ`i`の数です`b`値はすでに処理されています。 乗算する`answer`この数値のモジュロ (10^9 + 7)`. If the count is zero or negative, immediately set `答え = 0` とブレークします。 
6. すべての要素を処理した後、印刷します。`answer`。 

**機能する理由:** 並べ替え`a`そして`b`これにより、最初に最小のしきい値を処理し、必要最小限のカードを割り当てることができます。 不変条件は、それぞれの`b[i]`、利用可能なすべてを正確に数えました`a[j]`まだ使用されていないもの。 カウントを乗算すると、各位置の独立した選択肢の数が反映され、有効な順列の正しい合計数が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

def count_orders():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort()
        b.sort()
        
        answer = 1
        j = 0
        for i in range(n):
            while j < n and a[j] <= b[i]:
                j += 1
            choices = j - i
            if choices <= 0:
                answer = 0
                break
            answer = (answer * choices) % MOD
        print(answer)

count_orders()
```解決策は、入力を効率的に読み取ることから始まります。 仕分け`a`そして`b`貪欲な割り当ての準備をします。 の`while`ループにより、すべてをスキップします`a[j]`それは勝てない`b[i]`。 計算`choices = j - i`残りの数を説明します`a`現在のに割り当てることができる要素`b[i]`使用後`i`以前の位置の要素。 乗算する`answer`による`choices`有効な代入の総数を法で計算します$10^9 + 7$。
