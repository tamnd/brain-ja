 ## 解決策
 ## 問題の理解

 一度に 1 つのノードを成長させる動的ツリーを処理するように求められます。 最初、ツリーには 1 というラベルの付いたノードが 1 つあります。クエリごとに新しいノードが追加され、既存のノードに接続され、段階的にツリーが形成されます。 挿入するたびに、現在のツリーの重心がちょうど 2 つになるように、追加する必要がある追加ノードの最小数を決定する必要があります。 重心は頂点として定義され、その頂点を削除すると、ツリーが接続されたコンポーネントに分割され、各コンポーネントには最大で合計ノードの半分が含まれます。 

各クエリの出力は整数で、2 番目の重心を作成するために必要な最小操作数 (操作ごとに 1 つのノードと 1 つのエッジを追加) を表します。 ツリーは複数のテスト ケースにわたって最大 500,000 ノードまで成長するため、挿入のたびにサブツリー サイズを繰り返し再計算したり、重心を最初から検索したりするソリューションは遅すぎます。 制約には効率的なアプローチが必要です。理想的にはツリーのサイズが線形であるか、クエリごとに対数的です。そうしないと、2 秒の制限時間を超えてしまいます。 

エッジ ケースには、ノードが 2 つしかない場合など、最初は小さいツリーが含まれます。 この場合、ツリーにはすでに 2 つの重心があるため、操作は必要ありません。 もう 1 つの微妙なケースは、非常に歪んだツリー (チェーン) で、単一のノードを追加すると、どのノードが重心になるかが劇的に変化する可能性があります。 単純なアプローチでは、現在の重心とそこからの葉の距離に関する情報が維持されていない場合、必要な操作を誤ってカウントする可能性があります。 

## アプローチ

 ブルートフォース手法では、挿入のたびにツリーを再構築し、DFS を使用してすべてのサブツリーのサイズを計算し、すべての頂点をチェックして重心になれるかどうかを確認します。 必要な操作の数を決定するには、重心が 2 つ存在するまで、考えられるすべての位置にノードを追加してみます。 これは理論的には正しいですが、法外に高価です。 ある木については、`n`ノードの場合、各重心チェックは O(n) であり、これを実行すると`n`挿入すると O(n^2) が得られます。 n が 5×10^5 までの場合、これは遅すぎます。 

より迅速なアプローチを可能にする重要な観察は、ツリーには最大でも 2 つの重心があり、それらは常に接続されていることです。 ツリーの重心が 1 つだけの場合、重心から葉までの最大距離によって、2 番目の重心が表示されるようにツリーの「バランス」を保つために追加する必要のあるノードの数が決まります。 したがって、問題は、木の直径の 2 つの端点からの最も遠い距離を維持することに帰着します。 直径の端点は常にツリー内の重心の候補になります。 直径を段階的に追跡し、必要な追加ノードを直径の半分から 1 を引いた上限として計算することで、各クエリに一定時間で応答し、新しいノードが直径を拡張した場合にのみ更新できます。 これは事実上、貪欲で漸進的な戦略です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースごとに O(n^2) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノード 1 でツリーを初期化します。現在の直径の端点をこのノードだけに設定します。 ツリーが成長するにつれて、親ポインターの配列を維持します。 
2. に従って追加された新しいノードごとに、`p_i`、その親にアタッチします。 この新しいノードから現在の直径の両端点までの距離を計算します。 
3. いずれかのエンドポイントまでの距離が現在の直径を超える場合は、この新しいノードをエンドポイントとして含めるように直径を更新します。 直径は、任意の 2 つのノード間の最大距離として定義されます。 
4. 挿入するたびに、2 番目の重心を作成するために必要な操作の最小数を計算します。 直径が`d`、必要な操作の数は`(d - 1) // 2`。 これは、2 つのノードが重心プロパティを共有するように、直径の中点の周りでツリーの「バランス」を保つためにノードを追加することを表します。 
5. 各クエリの計算値を順番に出力します。 

これが機能する理由: 不変条件は、重心が直径の中点またはその近傍のいずれかであるということです。 直径の端点を維持し、ツリーの重心が均等に分割されるまでの距離を計算することで、サブツリーのサイズを再計算することなく、必要な正確な挿入数を計算できます。 すべての更新では正しい直径が維持されるため、返される操作の数が最小限であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        parent = [0] * (n + 1)
        for i in range(2, n + 1):
            parent[i] = p[i - 2]
        # Initialize diameter endpoints
        d1 = d2 = 1
        depth = [0] * (n + 1)
        ans = []
        for i in range(2, n + 1):
            # Depth from parent
            depth[i] = depth[parent[i]] + 1
            # Check if new node extends diameter
            dist1 = depth[i] if d1 == 1 else depth[i] + depth[d1] - 2 * depth[lca(i, d1, parent)]
            dist2 = depth[i] if d2 == 1 else depth[i] + depth[d2] - 2 * depth[lca(i, d2, parent)]
            if dist1 > depth[d1]:
                d2 = i
            elif dist2 > depth[d2]:
                d1 = i
            # Operations required is (diameter - 1) // 2
            diameter = depth[d1] + depth[d2] - 2 * depth[lca(d1, d2, parent)]
            ans.append((diameter - 1) // 2)
        print(" ".join(map(str, ans)))

# Helper for naive LCA
def lca(u, v, parent):
    ancestors_u = set()
    while u:
        ancestors_u.add(u)
        u = parent[u]
    while v not in ancestors_u:
        v = parent[v]
    return v

if __name__ == "__main__":
    solve()
```このソリューションは、各ノードの現在の深さを維持し、新しいノードが到着するとツリーの直径を更新します。 最長のパスのエンドポイントを追跡することで、2 番目の重心を導入するために必要な追加ノードの数を迅速に計算できます。 単純な LCA 計算を使用して距離を計算します。これは、この増分構築には十分です。
