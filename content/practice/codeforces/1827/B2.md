 ## 解決策
 ## 問題の理解

 個別の整数の配列が与えられ、範囲ソート操作を使用してそれをソートするのに必要な最小合計時間を、連続するサブ配列ごとに計算するように求められます。 各範囲ソート操作により、少なくとも 2 つの長さの連続した部分配列を選択し、その長さから 1 を引いた時間でソートできます。 すでにソートされている部分配列は、操作が必要ないため、美しさはゼロになります。 タスクは、各テスト ケースのすべての部分配列の美しさを合計することです。 

制約はかなり大きいです。 配列には最大 300,000 個の要素を含めることができ、最大 10,000 個のテスト ケースを含めることができます。 すべてのテスト ケースの配列長の合計の上限は 300,000 です。 単一の配列内のサブ配列の数は長さが 2 次であるため、すべてのサブ配列を明示的に反復するアプローチは除外されます。 ナイーブ$O(n^3)$すべてのサブ配列を検査し、操作をシミュレートすることによって最小ソート時間を計算するという解決策は、明らかに実行不可能です。 たとえ$O(n^2)$最悪の場合、解決策は遅すぎます。 

明らかではないエッジ ケースには、常に美しさ 0 を持つ長さ 1 のサブ配列や、1 回の操作に可能な限り最大の時間を必要とする厳密に減少するサブ配列が含まれます。 たとえば、配列では`[5, 4, 3]`、サブ配列`[5, 4, 3]`並べ替えには 1 回の操作が必要です`[5, 4, 3]`コスト 2、ただしサブ配列`[5, 4]`そして`[4, 3]`美品が各1あります。 すべてのサブ配列がゼロまたは 1 つの演算を実行すると仮定する不注意なアプローチでは、ここで誤った結果が生成されます。 

## アプローチ

 ブルートフォースアプローチは簡単です。 サブ配列ごとに、ソートされているかどうかを確認できます。 そうでない場合は、可能な限りすべての操作を試して最小時間を見つけることができます。 正確さは、すべての部分配列を列挙し、操作を正確にシミュレートすることから生まれます。 問題は、次のサイズの配列の場合です。$n$、 がある$O(n^2)$サブアレイ。 各サブ配列には少なくとも次のものが必要です$O(k)$長さの部分配列を処理します$k$、につながる$O(n^3)$トータルオペレーション。 と$n$300,000 までは明らかに遅すぎます。 

解決策を加速するための重要な観察は、ソート時の配列の位置を考慮することです。 各要素をソートされた配列内のランクで置き換えると、問題は部分配列内の「連続する整数のセグメント」を数えるということになります。 各部分配列の美しさは、ランクの順列において連続する要素の順序が狂っている位置の数によって決まります。 具体的には、部分配列の要素が整数の連続セグメントに順番に対応する場合、部分配列がソートされます。 そうでない場合は、最大の連続増加シーケンスを貪欲にソートすることで、最小の操作数を計算できます。 各サブ配列の美しさは、ランクが後方にジャンプする「ブレークポイント」の数に等しいという洞察が得られます。 ランクを事前に計算し、これらのブレークポイントを追跡することで、すべてのサブ配列の結果を線形時間で集計できます。

 ## アルゴリズムのチュートリアル

 1. 配列要素をソートされた配列内のランクにマップします。 これにより、問題は 1 から 1 までの整数の順列に変換されます。$n$。 ランクを使用すると、大きな値を気にせずに相対的な順序付けに集中できます。 
2. 配列を構築する`pos`どこ`pos[r]`要素のインデックスをランク付きで与えます`r`元の配列で。 これは、連続するランクがどこにあるかを追跡するのに役立ちます。 
3. 連続するランク間のブレークポイントの数を数えます。 ブレークポイントは常に発生します`pos[r+1] < pos[r]`、次のランクが配列内の現在のランクの前に表示されることを意味します。 すべてのブレークポイントは不連続性を示しており、サブ配列にこれらの要素が含まれている場合には個別の並べ替え操作が強制されます。 
4. カウンタの初期化`segments = 1`最初のランクがセグメントを開始するため。 1 から n-1 までのすべてのランクを反復します。 ブレークポイントが検出されるたびにインクリメントします`segments`。 セグメントの数は、配列全体をソートするために必要な範囲ソート操作の最小数に対応します。 
5. すべてのサブ配列を処理するには、ブレークポイントがそのブレークポイントの両方の要素を含むサブ配列に影響を与えることに注意してください。 前のランクが後のランクの前にあるサブ配列の数を計算することにより、各ブレークポイントによって影響を受けるサブ配列の数を数えます。 これらの要素の総和によって、総合的な美しさが生まれます。 
6. 次の式を使用して、すべてのブレークポイントの寄与を集計します。`(i - l + 1) * (r - i)`どこ`l`は左側の境界であり、`r`ブレークポイントを含むサブ配列の右境界です。 すべてのブレークポイントを合計すると、美しさの合計が効率的に計算されます。 

機能する理由: すべてのサブ配列の美しさは、その要素の相対的な順序によってのみ決まります。 配列をランクに変換し、位置を追跡し、ブレークポイントをカウントすることにより、範囲ソート操作を必要とする不連続点を正確に捕捉します。 各サブ配列の最小ソート時間は、サブ配列に含まれるブレークポイントの合計となり、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        rank = {v: i for i, v in enumerate(sorted(a))}
        pos = [0] * n
        for i, val in enumerate(a):
            pos[rank[val]] = i
        total = 0
        l = 0
        for r in range(1, n):
            if pos[r] < pos[r-1]:
                length = r - l
                total += length * (length + 1) // 2
                l = r
        length = n - l
        total += length * (length + 1) // 2
        print(total - n)

solve()
```最初のステップでは、順序付けを簡素化するために、各要素をそのランクにマップします。`pos`元の配列内のランクの位置を格納します。 ランクを反復して不連続性を検出し、各セグメントの影響を受けるサブ配列の数を計算します。 式`(length * (length + 1)) // 2`セグメント内のすべてのサブ配列をカウントします。 引き算します`n`なぜなら、単一要素のサブアレイの美しさはゼロだからです。 境界条件は、ループ後の最終セグメントを処理することによって処理されます。 

## 実用的な例

 **例 1:**

 配列:`[6, 4]`| ランク | 位置 |
 | --- | --- |
 | 1 | 1 |
 | 2 | 0 |

 ブレークポイント: pos[2] < pos[1] したがって、ブレークポイントは 1 つあります。 セグメントの長さ: 2。サブ配列の合計 = 3。2 つのシングルトンを減算すると、ビューティー サム 1 が得られます。 

**例 2:**

 配列:`[3, 10, 6]`| ランク | 位置 |
 | --- | --- |
 | 1 | 0 |
 | 2 | 2 |
 | 3 | 1 |

 ブレークポイント: pos[3] < pos[2] (1 < 2) → ブレークポイントが検出されました。 セグメントの長さ: 最初のセグメントの長さ 2、2 番目のセグメントの長さ 1。式によってカウントされたサブ配列の合計からシングルトンを差し引くと、ビューティー サム 2 が得られます。

 ## 特殊なケース

 単一要素配列の場合`[100]`、長さが 1 を超える部分配列はないため、美しさは 0 です。ソートされた配列の場合`[1, 2, 3]`、ランクは順番に連続しており、ブレークポイントは発生せず、美しさが残ります。
