 ## 問題の理解

 長さの順列が与えられています$n$。 位置から始まるサフィックスを取得することができます$k+1$プレフィックスを維持したまま自由に並べ替えることができます$a_1 \ldots a_k$所定の位置に固定されます。 それぞれについて$k$、接尾辞を最適に並べ替えた後、「完全な間隔」にすることができる最適な部分配列の数を知りたいと考えています。 

サブ配列は、その最大値から最小値を引いた値がその長さから 1 を引いた値に等しい場合に適しています。 順列を使用しているため、この条件は、サブ配列を整数の連続ブロックに再配置できることを意味します。つまり、最小値と最大値の間のすべての整数がギャップや重複なく正確に含まれることを意味します。 

したがって、このタスクは一定の間隔でチェックすることではありません。 代わりに、最終的な配列内の「密なセグメント」のように動作する間隔の数を最大化するためにサフィックスを再配置する方法を選択しています。 

主な問題は、サフィックスを再配置するたびに多くのサブ配列が一度に変更されるため、すべてのプレフィックス長に対して最適な配置を評価する必要があることです。$k$これは事実上、間隔密度を最大化するために尾部を「成形」できるあらゆる方法を考慮することを意味します。 

制約は厳しいです: 合計$n$テストケース全体で最大$2 \cdot 10^5$。 任意の二次関数または偶数$O(n \sqrt{n})$テストケースごとの処理が遅すぎます。 この構造は、各要素が全体にわたってグローバルに一貫した方法で貢献する必要があることを示唆しています。$k$したがって、テストごとに線形またはほぼ線形のソリューションが期待できるはずです。 

素朴なアプローチでは、それぞれの場合、$k$、サフィックスのすべての順列を試してみるか、すべての間隔パーティションについて推論してみてください。 1つの手配を確認するだけでも費用がかかります$O(n^2)$有効な部分配列を数えるのに、接尾辞の順列が指数関数的に多いため、これは直ちに不可能です。 

さらに微妙な落とし穴は、サフィックスを並べ替えた後、答えが固定されていると仮定することです。 プレフィックスはサフィックスと相互作用するため、これは誤りです。プレフィックスにすでに配置されている要素によって、境界を越えて形成できる間隔の数が制限されます。 

## アプローチ

 ブルートフォース視点は修正から始まります$k$次に、あらゆる方法でサフィックスを配置して、有効な部分配列をすべて数えます。 配置を修正したとしても、有効な部分配列を数えるにはすべてのペアをチェックする必要があります$(l,r)$そして最小値と最大値を検証します。$O(n^2)$。 あるので$(n-k)!$接尾辞の順列、これはすぐに爆発します。 ソートのような単一の「合理的な」順序付けに限定したとしても、すべての最適な間隔構造を効率的にカウントすることはできません。$k$。 

重要な洞察は、順列について考えるのをやめ、代わりに部分配列がどのようにして有効な間隔になるかを考えることです。 部分配列は、その値が整数の連続セグメントを形成する場合にのみ有効です。 この条件は、その内部の要素を隙間なく「詰め込む」ことができるかどうかによってのみ決まります。 

次に、接尾辞を自由に決めると何が起こるかを観察してください。 サフィックスは複数の値のセットであり、任意の順序で配置できます。 プレフィックスは固定されており、部分的に構築された構造のように機能します。 最良の戦略は常に、新しい連続セグメントの形成に対する「有用性」の昇順に接尾辞要素を配置することです。 これにより、問題は、隣接する位置間でどれだけの「適切なマージ」を作成できるかを追跡することになります。 

間の境界を定義すると、$i$そして$i+1$、境界をブリッジするために必要なすべての値がサフィックスに配置できる場合、または互換性のある方法でプレフィックスにすでに存在している場合、その境界は「安全」になります。 このような安全な境界ごとに、有効なセグメントが追加されることでコピウム部分配列の数が増加します。 

主要な削減点は、サブ配列について直接推論する代わりに、どれだけの隣接するギャップを削除できるかを追跡することです。 それぞれ$k$これは、より多くの要素をプレフィックスに徐々にフリーズすることに相当し、柔軟性が低下します。 答えは、最後の制約から柔軟性を取り除いた後でも満たせる隣接制約の数の累積数になります。$n-k$要素。 

各ポジションについて、それが潜在的な連続間隔の形成または破壊にどのように寄与するかを事前計算し、そのような寄与がアクティブのままである数を維持します。$k$が増加します。 これにより、インターバル形成における役割によって順序付けられた位置を貪欲にスイープすることで、線形時間内に答えを維持することができます。

 ## アルゴリズムのチュートリアル

 1. 各値を 1 から 1 までの線上の点として解釈します。$n$有効な部分配列は、連続範囲内のすべての整数を含む間隔に対応することに注意してください。 これにより、このタスクは、suffix 要素を配置することによって形成できる連続する値の範囲の数を制御するものとして再構成されます。 
2. 順列内の各値の位置を事前計算します。 これにより、再配置後に有効になる部分配列を介して 2 つの値がいつ「接続」されるかを推論できます。 
3. 隣接する値のペアごとに$x$そして$x+1$、最も古いプレフィックス長を決定します$k$その後、サフィックスを再配置することによって同じ連続ブロックに強制的に入れることはできなくなります。 このしきい値は、プレフィックス制約により隣接関係が不可能になった時点を捕捉します。 
4. このような各制約をイベントに変換します。$k$、しきい値を超えると、有効なセグメントを形成する能力が低下します。 これにより、問題が広範囲にわたる問題に変わります$k$。 
5. 現在実行可能な隣接接続の数を維持します。 生き残った接続ごとに、予測可能な相加的な方法でコピウム部分配列の数が増加します。 
6. で答えを初期化します。$k=0$ここで、完全な再配置の自由とは、あらゆる可能な隣接構造を最適に実現できることを意味します。 
7.スイープ$k$から$0$に$n$、しきい値を超えたときに、各制約の寄与を 1 回だけ減分します。 現在の合計をその答えとして保存します$k$。 

### なぜ効果があるのか

 この正しさは、すべての有効なコピウム部分配列が、すべて満たされる必要がある一連の連続値制約に対応するという事実から得られます。 各制約は、プレフィックスを修正した後も両方のエンドポイントを連続した間隔に配置できるかどうかのみに依存します。 プレフィックスの位置によって 1 つのエンドポイントを柔軟に配置する機能が失われると、その制約はより大きなすべてのエンドポイントで永久に失われます。$k$。 制約は独立して単調であるため、$k$1 回のスイープで、各段階で達成可能な残りの数が正確にカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, v in enumerate(a):
            pos[v] = i

        # We track when each adjacency (x, x+1) becomes impossible
        events = [[] for _ in range(n + 2)]

        for x in range(1, n):
            l = min(pos[x], pos[x + 1])
            r = max(pos[x], pos[x + 1])
            # if prefix fixes anything inside (l, r), adjacency is restricted
            # threshold is r: once k > r, we lose flexibility
            events[r + 1].append(1)

        cur = 0
        ans = [0] * (n + 1)

        # initial value: all adjacencies potentially usable
        base = n * (n + 1) // 2

        for k in range(0, n + 1):
            if k > 0:
                for delta in events[k]:
                    cur += delta
            ans[k] = base - cur

        print(*ans)

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        pos = [0] * (n + 1)

        for i, v in enumerate(a):
            pos[v] = i

        # each adjacency contributes an interval until it becomes broken
        break_at = [0] * (n + 2)

        for x in range(1, n):
            l = min(pos[x], pos[x + 1])
            r = max(pos[x], pos[x + 1])
            break_at[r + 1] += 1

        cur = 0
        ans = [0] * (n + 1)

        base = n * (n + 1) // 2

        for k in range(n + 1):
            cur += break_at[k]
            ans[k] = base - cur

        print(*ans)

if __name__ == "__main__":
    main()

配列`break_at`プレフィックス サイズが特定のしきい値を超えたときに正確に失われる隣接関係の数を格納します。 これにより、クエリごとに何かを再計算することがなくなります$k$。 最後のループはこれらの損失を蓄積し、完全に柔軟な配置における潜在的なサブアレイの総数に等しい固定ベースラインからそれらを差し引きます。 

微妙な部分は、各隣接関係が損失に 1 回だけ寄与するため、正しいプレフィックス境界でのみ損失をカウントするようにする必要があることです。 これが、各ペアをマッピングする理由です$(x, x+1)$に$r+1$、 ない$r$。

 ## 特殊なケース

 重要なエッジケースは、順列がすでにソートされている場合です。 その場合、すべての隣接するペアは完全に位置合わせされており、サフィックスから柔軟性を削除しても、すぐに多くの隣接制約が破られるわけではありません。 スイープは減少を適切に遅らせ、突然の低下ではなく徐々に減少します。 

もう 1 つの特殊なケースは、完全に逆の順列です。 ここでは、すべての隣接ペアのスパンが大きいため、多くの制約が早期にアクティブになります。 アルゴリズムはこれを処理します。$r+1$イベントは終わり近くに集中し、スイープの早期かつ大幅な減少をもたらします。 

最後に、とても小さいですが、$n$のような場合$n=1$または$n=2$ループオーバーのため、隣接構築で無効なインデックス作成が発生していないことを確認します。$x \in [1, n-1]$当然、空またはシングルステップになっても、正しい塩基カウントが生成されます。
