 ## 解決策
 ## 問題の理解

 間隔で表される駐車セグメントがあります`[0, L]`。 車は一度に 1 台ずつ到着し、常に左から右に走行し、各ドライバーはできるだけ早い位置に駐車したいと考えています。 

長さのある車の場合`x`背中を向けて公園`p`、その後車が占有します`[p, p + x]`。 この車とその後ろの車の間には少なくとも`b`メートルの空きスペース。 この車とその前の車の間には少なくとも`f`メートルの空きスペース。 道路の境界線は特別であり、余分なスペースは必要ありません。 

リクエストには 2 種類あります。 A型`1 x`リクエストとは、長さのある新車を意味します`x`到着して駐車しようとします。 その背面が終了する座標を出力する必要があります。`-1`駐車が不可能な場合。 A型`2 k`リクエストとは、によって作成された車を意味します。`k`- 番目のリクエストは駐車場から出発します。 

操作数は最大で`100`、驚くほど小さいです。 たとえ`O(n^2)`シミュレーションは簡単に適合します。 課題はパフォーマンスではなく、間隔ルールを正しくモデル化することです。 間違った答えのほとんどは、必須のギャップがどこに適用されるかについての誤解から生じています。 

重要な点は、間隔が非対称であることです。 車に必要なのは`b`数メートル後ろと`f`数メートル前にあります。 駐車中の 2 台の車が共存する場合、それらの間の実際の空き距離は、両方の車が同時に満たす必要があります。 車 A が車 B の後ろにあるとします。その場合、それらの間の間隔は少なくとも`max(f, b)`? いいえ、後部車両には必要です`f`前方の車は必要ですが、`b`後ろなので、ギャップは少なくとも必要です`f + b`。 

もう一つの簡単な間違いが国境で現れます。 車が最初に駐車した車の場合、座標から開始する可能性があります`0`リアギャップを必要とせずに。 同様に、最後に駐車した車はちょうど次の時間に終了する可能性があります。`L`フロントギャップを必要とせずに。 

次の例を考えてみましょう。```
L = 10, b = 2, f = 3
Current parked car: occupies [4, 6]
New car length = 1
```不注意な実装は空き期間を考える可能性があります`[0, 4]`からの車に適合します`0`、 なぜなら`0 + 1 <= 4`。 それは間違いです。 新しい車にも必要です`f = 3`駐車した車の数メートル前にあるため、次のものが必要です。```
0 + 1 + 3 <= 4
```これはここでは当てはまりますが、かろうじてです。 

2台の車の間に挿入する場合、別の危険なエッジケースが発生します。```
L = 20, b = 2, f = 2
Cars:
[0, 4]
[10, 14]
New car length = 2
```空き区間は、`[4, 10]`、 長さ`6`。 単純なアプローチでは、その車が適合すると考えるかもしれません。`2 <= 6`。 実際に必要なスペースは次のとおりです。```
b + car_length + f = 2 + 2 + 2 = 6
```車は座標から正確にフィットします`6`。 

座標を保存するだけで、どのリクエストがどの車を作成したかを忘れると、削除操作も誤って処理されやすくなります。 削除はリクエストのインデックスを参照するため、リクエスト ID からパーク間隔までのマッピングを維持する必要があります。 

## アプローチ

 最も直接的なシミュレーションは、駐車されているすべての車を位置別にソートして維持することです。 到着するすべての車について、駐車場を左から右にスキャンし、すべての空き間隔をテストします。 

現在駐車されている車が次のとおりであるとします。```
[p1, p1 + len1]
[p2, p2 + len2]
...
```3種類の隙間をチェックします。 

先頭車両の前のプレフィックスギャップ。 新車は`0`、しかし出発しなければなりません`f`最初に駐車した車の数メートル前。 

連続する車両間の中間の隙間。 前の車両が で終了した場合`r1`次の車は に出発します`l2`、それから長さの新しい車`x`から始まる可能性があります`r1 + b`もし：```
r1 + b + x + f <= l2
```最終車両の後の接尾部のギャップ。 新車は`last_end + b`に限って：```
last_end + b + x <= L
```ドライバーは常に可能な限り早い位置を選択するため、最初の有効な位置が常に最適です。 

この総当たりシミュレーションはすでに十分に高速です。 せいぜい`100`オペレーションが存在し、各到着スキャンは最大でも`100`駐車中の車、大まかに与える`10^4`小切手。 

主な観察は、制約が小さいため、複雑な区間ツリーやバランスの取れた構造は決して必要ないということです。 実際の作業は、正確な配置公式を正しく導き出すことです。 ジオメトリを理解したら、実装は慎重な間隔スキャンになります。 

私たちは今でも、駐車した車を順番に保管し、必要に応じて取り除くことで、データをきれいに整理しています。 これにより、シンプルで信頼性の高いソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 承認済み |
 | 最適 | O(n²) | O(n) | 承認済み |

 ここでの「最適な」ソリューションとは、実際には適切にモデル化されたシミュレーションです。 より大きな制約には間隔構造が必要になりますが、`n ≤ 100`、漸近的なトリックよりも慎重な実装が重要です。 

## アルゴリズムのチュートリアル

 1. 駐車中の車のリストを整理して管理します。 

各車両は次のように保管されます`(start, length, request_id)`。 リストをソートしたままにする`start`空いているギャップを左から右にスキャンしてみましょう。 
2. リクエスト ID から駐車車両データまでの辞書を維持します。 

撤去クエリでは、駐車命令ではなく、元のリクエスト番号が参照されます。 このマッピングにより、駐車中の車を一定時間内に正確に見つけることができます。 
3.車長による到着リクエストの場合`x`、まず車を座標に置いてみてください`0`。 

駐車している車がない場合、車は次のときに収まります。`x <= L`。 

それ以外の場合は、最初に駐車した車から出発させます。`s`。 新しい車は次の位置に適合します`0`もし：```
x + f <= s
```左側の境界には後部のギャップは必要ありません。 
4. プレフィックス ギャップが失敗した場合は、隣接する駐車車両のペアをすべてスキャンします。 

前の車が乗っていたとします。`[l1, r1]`次の車は に出発します`l2`。 

最も早い開始は次のとおりです。```
r1 + b
```次の車両の前に必要な前方間隔を確保するには:```
r1 + b + x + f <= l2
```この条件を満たす最初のペアにより、正しい駐車位置が得られます。 
5. 中間の車間距離がうまくいかない場合は、最後の車の後に駐車してみてください。 

最終車両が で終点の場合`r`、可能な最も早い位置は次のとおりです。```
r + b
```車は次の場合に適合します。```
r + b + x <= L
```右側の境界線には前部のギャップは必要ありません。 
6. 3 つのケースのいずれも成功しない場合は、次の出力が行われます。`-1`。 
7. 車が正常に駐車したら、それを並べ替えたリストに挿入し、リクエスト ID マッピングに記録します。 
8. 削除リクエストの場合は、リクエスト ID を使用して保管されている車を特定し、駐車リストから削除します。 

### なぜ効果があるのか

 このアルゴリズムは常に空きスペースを左から右に調べ、各ギャップ内の最も古い有効な座標を常に選択します。 可能な駐車位置はすべて、最初の車の前、2 台の車の間、または最後の車の後という 3 つのカテゴリのいずれかに正確に属している必要があります。 

中間のギャップ内では、有効な配置は 以降で開始する必要があります。`previous_end + b`, 前の車は後ろのスペースが必要なので。 後で開始してもスペースを無駄にするだけであり、より早い回答を生成することはできません。 したがって、そのギャップ内の最も早い候補は一意に決定されます。 その候補者が前方に十分なスペースを残せなかった場合、同じギャップ内で後続のポジションは機能しません。 

すべてのギャップが左から右の順序でチェックされ、各ギャップの最も早い実行可能な位置がテストされるため、最初に受け入れられた位置は、問題で必要とされる左端の有効な駐車座標と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    L, b, f = map(int, input().split())
    n = int(input())

    parked = []
    by_request = {}

    for req_id in range(1, n + 1):
        t, x = map(int, input().split())

        if t == 1:
            length = x
            pos = -1

            if not parked:
                if length <= L:
                    pos = 0
            else:
                first_start = parked[0][0]

                if length + f <= first_start:
                    pos = 0
                else:
                    for i in range(len(parked) - 1):
                        s1, len1, _ = parked[i]
                        s2, len2, _ = parked[i + 1]

                        end1 = s1 + len1

                        candidate = end1 + b

                        if candidate + length + f <= s2:
                            pos = candidate
                            break

                    if pos == -1:
                        last_start, last_len, _ = parked[-1]
                        last_end = last_start + last_len

                        candidate = last_end + b

                        if candidate + length <= L:
                            pos = candidate

            print(pos)

            if pos != -1:
                car = (pos, length, req_id)

                idx = 0
                while idx < len(parked) and parked[idx][0] < pos:
                    idx += 1

                parked.insert(idx, car)
                by_request[req_id] = car

        else:
            car = by_request[x]
            parked.remove(car)
            del by_request[x]

solve()
```このソリューションでは、駐車場が占有区間の並べ替えられたリストとして明示的に表示されます。 演算数が少ないため、単純なリスト演算で十分です。 

挿入ロジックは、ウォークスルーからの幾何学的推論を反映しています。 最初にプレフィックス ギャップ、次にすべての内部ギャップ、次にサフィックス ギャップを試します。 境界線には余分なスペースが必要ないため、数式は若干異なります。 

実装の微妙な詳細の 1 つは、次の意味です。`candidate`。 駐車した 2 台の車の間で、新しい車を常に可能な限り左端に配置します。```
candidate = end1 + b
```開始位置を遅らせても、次の車までの残りスペースが減るだけなので、この 1 つの座標を確認するだけで十分です。 

1 つ違いのもう 1 つの簡単な間違いは、間隔は整数スロットではなく連続した長さであることを忘れていることです。 条件:```
candidate + length + f <= s2
```正確です。 車は必要な量の空きスペースを正確に残すことができるため、平等が許可されます。 

削除ロジックは、保存されたタプル自体を使用します。 タプルは不変であり、駐車中の車を一意に識別するため、`list.remove()`正しい間隔を完全に削除します。

 ## 特殊なケース

 Consider this input:```

2
1 4
1 8
```最初の駐車場は、`0`、占領している`[0,4]`。 

2 番目の車両の場合、最も古い末尾の位置は次のとおりです。```
4 + 2 = 6
```新しい車が占有します`[6,14]`、駐車場内にぴったり収まります。 サフィックスの配置は以下のチェックのみを行うため、アルゴリズムはそれを受け入れます。```
candidate + length <= L
```右の境界線の前にスペースは必要ありません。 

ここで次のことを考えてみましょう。```
20 2 2
3
1 4
1 4
1 2
```車を 2 台追加すると、次のようになります。```
[0,4]
[6,10]
```残りのサフィックスは次で始まります。```
10 + 2 = 12
```3番目の車の長さは、`2`、 そして：```
12 + 2 = 14 <= 20
```アルゴリズムはそれを次の場所に駐車します`12`。 

最後に、扱いにくい内部ギャップについて考えてみましょう。```

3
1 4
1 4
1 1
```最初の 2 台の車両の後:```
[0,4]
[7,11]
```それらの間の自由間隔は長さです`3`。 不注意な解決策は長さを考える可能性があります`1`そこに車が収まります。 

アルゴリズムは以下をチェックします。```
candidate = 4 + 2 = 6
6 + 1 + 3 <= 7
```それは失敗します。 フロントに必要なスペースがないため、車を駐車できません。 アルゴリズムは、代わりに後のギャップを正しく検索します。
