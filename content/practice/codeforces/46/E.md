 ## 解決策
 ## 問題の理解

 テーブルの各行には整数が含まれており、すべての行から正の長さの接頭辞を取得する必要があります。 私たちが選ぶなら`c[i]`行のセル`i`の場合、その行で選択されているセルは正確に最初のセルになります。`c[i]`エントリ。 

合計報酬は、選択されたすべての数字の合計です。 この制限は、プレフィックスの長さのシーケンスから生じます。$$c_1 > c_2 < c_3 > c_4 < \dots$$不等式は隣接する行間で交互に現れます。 奇数のインデックスが付けられた行は山のように動作し、偶数のインデックスが付けられた行は谷のように動作します。 

タスクは、この交互の条件を尊重しながら合計を最大化することです。 

テーブルの寸法は最大です`1500 x 1500`。 これは十分に大きいため、行構成のすべてのペアを個別に使用するアルゴリズムは困難になります。 行では、次のいずれかのプレフィックス長を選択できます。`1`に`m`したがって、単純な状態空間はすでに`m^n`可能性はありますが、それは完全に不可能です。 

隣接する行に対する動的プログラミングでも注意が必要です。 以前のすべてのプレフィックス長から現在のすべてのプレフィックス長への直接移行にはコストがかかります`O(m^2)`行ごとに。 と`n,m ≤ 1500`、それは次のようになります:$$1500 \times 1500^2 \approx 3.4 \times 10^9$$限界をはるかに超えた操作。 

この制約は、行ごとの線形時間に最適化された遷移を備えた DP が必要であることを強く示唆しています。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

すべての値が負の場合を考えてみましょう。```
2 3
-5 -2 -1
-7 -3 -4
```すべての行から少なくとも 1 つのセルを選択する必要があります。 空のプレフィックスを許可する不注意な実装では、誤って返される可能性があります。`0`。 

もう 1 つの危険なケースは、最適な遷移が一意ではない場合です。```
3 3
5 -100 5
1 1 1
5 -100 5
```最適な選択は、必ずしも最も長く収益性の高いプレフィックスであるとは限りません。 各行を独立して最大化する貪欲な戦略は失敗します。これは、交互の不等式が隣接する行を結合するためです。 

境界の不平等も重要です。```
2 2
10 10
1 1
```1行目は長さを選べません`1`2行目も選択した場合`1`、パターンには必要があるため、`c1 > c2`。 同じ長さは無効です。 

最後に、パリティが重要です。 関係は行ごとに方向が変わります。 行間で有効な遷移`1`そして`2`行間では無効になります`2`そして`3`。 これを忘れると、静かに間違った答えが生まれます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての行について、考えられるすべてのプレフィックス長を試します。`1`に`m`。 結果のシーケンスが交互の不等式を満たすかどうかを確認し、プレフィックスの合計を計算します。 

これが機能するのは、各行の選択が単一の整数、つまりプレフィックス長によって完全に決定されるためです。 問題は可能性の数です。$$m^n$$と`m = 1500`そして`n = 1500`、これは絶望的です。 

次の自然な改善は動的プログラミングです。 

まず、すべての行のプレフィックスの合計を計算します。$$pref[i][j] = \text{sum of first } j \text{ numbers in row } i$$次に、次のように定義します。$$dp[i][j]$$行の処理後に取得可能な最大合計として`1..i`, ここで行`i`プレフィックス長を選択します`j`。 

遷移は不等式の方向によって異なります。 

行の場合`i-1`行より大きくなければなりません`i`、 それから：$$dp[i][j] = pref[i][j] + \max(dp[i-1][k]), \quad k > j$$行の場合`i-1`行より小さくなければなりません`i`、 それから：$$dp[i][j] = pref[i][j] + \max(dp[i-1][k]), \quad k < j$$この DP は正しいですが、単純な実装ではすべてがチェックされます。`k`あらゆる人にとって`j`、につながる`O(nm^2)`。 

重要な観察は、各遷移が前の行の最大範囲のみを要求することです。 固定行の場合は、次のものが繰り返し必要になります。```
maximum over k < j
```または```
maximum over k > j
```これらは、接頭辞最大値または接尾辞最大値を使用して線形時間で維持できます。 

現在の長さよりも小さい以前の長さが必要な行を処理しているとします。 建てる：$$best[j] = \max(dp[i-1][1..j])$$それから：$$\max_{k<j} dp[i-1][k] = best[j-1]$$同様に、現在の長さよりも大きい以前の長さが必要な場合は、接尾辞 maxima を作成します。 

これにより、各行が次のように削減されます。`O(m^2)`に`O(m)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m^n) | O(n) | 遅すぎる |
 | ナイーブDP | O(nm²) | O(m) | 遅すぎる |
 | 最適 | O(nm) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての行のプレフィックスの合計を計算します。 

させて`pref[i][j]`最初の合計になる`j`並んだセル`i`。 これにより、プレフィックス長を選択することによって提供される値に定時アクセスできるようになります。 
2. 最初の DP 行を初期化します。 

行用`1`、前の行がないため、すべてのプレフィックス長が有効になります。$$dp[j] = pref[1][j]$$3. 行を 1 つずつ処理します。 

新しい行ごとに、現在の行が前の行より大きいか小さいかによって遷移が異なります。 
4. 必要な関係が`previous > current`、接尾辞 maxima を構築します。 

定義する：$$suf[j] = \max(dp[j], dp[j+1], \dots, dp[m])$$次に現在の長さについて`j`、最も有効な以前の状態は次のとおりです。$$suf[j+1]$$なぜなら、厳密にもっと大きな以前の長さが必要だからです。 
5. 必要な関係が`previous < current`、プレフィックス maxima を構築します。 

定義する：$$pre[j] = \max(dp[1], dp[2], \dots, dp[j])$$次に現在の長さについて`j`、最も有効な以前の状態は次のとおりです。$$pre[j-1]$$6. 現在の行の寄与を追加します。 

最適な有効な以前の状態がわかったら、次のように計算します。$$ndp[j] = best + pref[i][j]$$7. 古い D​​P アレイを新しいものと交換します。 

現在の行のすべての長さを処理した後、次の行に進みます。 
8. 答えは、最終的な DP 配列の最大値です。 

### なぜ効果があるのか

 DP 状態は、現在の行インデックスとその行で選択されたプレフィックス長など、将来の決定に必要なすべてを完全にキャプチャします。 

有効な継続は、次の行のプレフィックスの長さが大きいか小さいかによってのみ決まります。 現在の長さが固定されると、以前の行は重要ではなくなります。 

プレフィックスとサフィックスの最大値が、以前の長さの許容範囲内で達成可能な最良の DP 値を正確に表すため、最適化されたトランジションは正しいままです。 を使用して厳密な不等式が強制されるため、有効な遷移はスキップされず、無効な遷移も含まれません。`j-1`または`j+1`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    n, m = map(int, input().split())

    pref = [[0] * (m + 1) for _ in range(n)]

    for i in range(n):
        row = list(map(int, input().split()))
        for j in range(1, m + 1):
            pref[i][j] = pref[i][j - 1] + row[j - 1]

    dp = [-(INF)] * (m + 1)

    for j in range(1, m + 1):
        dp[j] = pref[0][j]

    for i in range(1, n):
        ndp = [-(INF)] * (m + 1)

        # previous > current
        if i % 2 == 1:
            suf = [-(INF)] * (m + 2)

            for j in range(m, 0, -1):
                suf[j] = max(suf[j + 1], dp[j])

            for j in range(1, m + 1):
                best = suf[j + 1]
                if best > -INF:
                    ndp[j] = best + pref[i][j]

        # previous < current
        else:
            pre = [-(INF)] * (m + 1)

            for j in range(1, m + 1):
                pre[j] = max(pre[j - 1], dp[j])

            for j in range(1, m + 1):
                best = pre[j - 1]
                if best > -INF:
                    ndp[j] = best + pref[i][j]

        dp = ndp

    print(max(dp[1:]))

solve()
```最初の部分では行プレフィックスの合計を計算します。 すべての選択肢は常に接頭辞であるため、これにより各行の決定が定数時間の検索に変換されます。 

DP 配列には、前の行の結果のみが保存されます。 満杯`n x m`遷移は直前の行にのみ依存するため、ストレージは不要です。 

パリティチェックは微妙です。 行を処理するとき`i`ゼロベースのインデックス付けの場合:```
row 1 > row 2
row 2 < row 3
row 3 > row 4
```したがって、奇数の行`i`必要とする`previous > current`、偶数ながら`i`必要とする`previous < current`。 

接尾辞の最大配列は、厳密に「より大きい」遷移を処理します。 現在の長さの場合`j`、以前の有効な長さは次のとおりです。`j+1 ... m`, そこでクエリを実行します`suf[j+1]`。 

プレフィックス最大配列は、厳密に小さい遷移を処理します。 現在の長さの場合`j`、以前の有効な長さは次のとおりです。`1 ... j-1`, そこでクエリを実行します`pre[j-1]`。 

非常にネガティブなセンチネルを使用すると、到達不能な状態を誤って有効なものとして扱うことを回避できます。

 ## 特殊なケース

 すべてが負の場合を考えてみましょう。```
2 3
-5 -2 -1
-7 -3 -4
```プレフィックスの合計は次のようになります。```
Row 1: -5 -7 -8
Row 2: -7 -10 -14
```状態は長さに対してのみ存在するため、DP では行をスキップすることはできません。`1..m`。 最も有効な選択肢は次のとおりです。```
c1 = 2
c2 = 1
```与える：```
-7 + (-7) = -14
```または：```
c1 = 3
c2 = 1
```与える：```
-8 + (-7) = -15
```最適な答えは`-12`、次から取得します。```
c1 = 2
c2 = 1
```実際のプレフィックス合計を正しく計算した後。 空のプレフィックスを許可するバグのある実装では、誤った出力が発生します。`0`。 

ここで平等性を考えてみましょう。```
2 2
10 10
1 1
```有効なペアは次のとおりです。```
(2,1)
```のみ。 

ペア`(1,1)`最初の関係は厳密である必要があるため、これは無効です。$$c_1 > c_2$$サフィックスの最大遷移は、クエリによってこれを自動的に強制します。`suf[j+1]`の代わりに`suf[j]`。 

最後に、パリティを考慮します。```
3 2
5 5
1 1
10 10
```有効なパターンは次のとおりです。$$c_1 > c_2 < c_3$$選択:```
(2,1,2)
```有効です。 

選択:```
(2,1,1)
```3 番目のリレーションでは 3 番目の行が 2 番目の行よりも大きい必要があるため、この処理は失敗します。 

このアルゴリズムは、行パリティに基づいてサフィックスとプレフィックスの遷移を切り替えるため、各不等号の方向が正しく適用されます。
