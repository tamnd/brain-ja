 ## 解決策
 ## 問題の理解

 2 行のグリッドが与えられ、$n$列。 最初の行全体は、A と B で構成される文字列としてすでに固定されています。 2 行目は完全に自由に選択できますが、A と B も入力する必要があります。 

両方の行が埋められたら、グリッド内の隣接性を調べます。 2 つのセルがエッジを共有している場合、つまり 1 行内で水平方向、または 2 つの行間で垂直方向を意味する場合、2 つのセルは隣接しているとみなされます。 隣接するセルのペアごとに、2 つのセルに異なる文字が含まれているかどうかをカウントします。 目標は、このような異なる隣接ペアの合計数が正確に一致するように 2 行目を構築することです。$k$。 これが達成できない場合は、不可能であることを報告しなければなりません。 

各列は、垂直エッジと水平エッジを通じてこのグローバル カウントに局所的に寄与します。 各列が 1 つの垂直隣接関係に寄与するのに対し、水平方向の寄与は各行内の遷移に依存するため、垂直構造は特に重要です。 

制約は非常に厳しいので、どのソリューションも全体としてテスト ケースごとに直線的な時間で実行する必要があります。 合計から$n$すべてのテストにわたって$2 \cdot 10^5$、2 行目の文字列をすべて試行するアプローチや、列に対して指数関数的推論を使用するアプローチは、直ちに除外されます。 プレフィックスごとのすべての状態にわたる二次 DP であっても、高度に最適化されていない限り、遅すぎます。 

貪欲な戦略がグローバルな結合を考慮せずにローカルな寄与を一致させようとした場合、微妙な失敗のケースが発生します。 たとえば、2 行目の各セルを選択して、1 行目との不一致を局所的に最大化または最小化すると、2 行目の水平エッジが以前の選択にどのように依存するかが無視されます。 もう 1 つのよくある落とし穴は、垂直方向と水平方向の寄与を独立して扱うことですが、同じ選択が両方に同時に影響するため失敗します。 

## アプローチ

 この問題を単純に考えると、考えられるすべての 2 行目を試してみることになります。 それぞれについて、$2^n$選択肢に応じて、不一致エッジの数を計算します。$O(n)$、全体的な結果を与える$O(n \cdot 2^n)$方法。 これは非常に小さい場合にのみ機能します$n$が、すぐに不可能になってしまうと$n$25や30にも達します。 

重要な構造は、各列が非常に制御された方法で隣接する列と相互作用することです。 グリッドをグローバルに考える代わりに、列ごとに処理し、これまでに蓄積した「余分な」不一致の数を維持します。 コラムからの移行$i-1$に$i$2 行目で前に選択した文字と現在の文字にのみ依存します。 これにより、問題は小さな状態空間にわたるパス構築に帰着します。 

中心的な観察は、2 行目の文字が 1 行目の文字と一致するかどうかに応じて、各列が固定の垂直コストに寄与するということです。 さらに、隣接する列の各ペアは、文字を切り替えるかどうかに応じて 2 行目の水平コストに寄与します。 したがって、総コストは、段階的に追跡できるローカル貢献の合計に分解されます。 

これにより、状態が現在の列と 2 番目の行で最後に選択された文字であるという動的プログラミングの解釈が可能になり、残りのパラメーターはまだ達成する必要があるコストを表します。 トランジションは、反転するか同じキャラクターを維持するかによってのみ決まるため、正確にヒットするように選択肢を調整する方法を理解すると、構造は貪欲に決定的になります。$k$。

 ## アルゴリズムのチュートリアル

 まず、どの程度の不一致が避けられないか、または簡単に制御できるかを計算し、次に残りの予算を尊重しながら貪欲に 2 番目の行を構築します。 

1. 各列について、2 行目の文字が 1 行目の文字と異なる場合は垂直方向の寄与を 1、それ以外の場合は 0 として定義します。これは選択によって直接制御されます。 
2. 2 行目の水平エッジについては、隣接する列間で文字を切り替えるたびにコストに 1 が加算されることに注目してください。 同じままだと0が加算されます。 
3. 列を左から右に処理し、各位置の 2 行目の文字を決定します。 
4. アットコラム$i$では、2 行目の文字 (A または B) の両方の可能な選択肢を検討します。 選択ごとに、直前のコスト、つまり垂直方向の不一致と、前に選択した文字との水平方向の不一致を計算します。 
5. 残りの必要コストを達成できるキャラクターを選択します$k$。 これは、ターゲットをオーバーシュートせず、将来の列に十分な柔軟性を残す遷移のみを選択することを意味します。 
6. 実現可能性を高めるために、残りの必要な不一致数を維持し、残りの列数を考慮して達成可能な範囲内に収まるようにします。 
7. いずれかのステップで A も B も残りの目標を達成できない場合、解決策は存在しないと結論付けます。 

### なぜ効果があるのか

 重要な不変条件は、列の処理後です。$i$、残りの必要な不一致数は、詳細な履歴ではなく、2 行目の現在の文字と残っている列の数のみに依存します。 それぞれの決定は既知のローカル コストに寄与し、将来のすべての構成では、制限された数の追加不一致のみが追加されます (垂直エッジごとに最大 1 つ、水平エッジごとに 1 つ)。 この有界で分解可能な構造のため、グローバルに有効なソリューションは、実現可能性を変えることなく、選択されたプレフィックスと一致するものに変換できるため、貪欲な実現可能性枝刈りによって、有効な完全な構築が存在する場合にはそれが削除されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()

        # dp[pos][last_char][cost] is impossible to store fully,
        # so we greedily track feasibility using bounds.

        # Precompute max possible cost from each position:
        # Each column can contribute at most 2:
        # vertical (1) + horizontal (1 except first column)
        
        # We build greedily, tracking remaining k.
        res = []
        
        # try both starting options
        possible = False
        for start in "AB":
            ans = [start]
            cur_cost = 1 if start != s[0] else 0
            prev = start

            rem_k = k - cur_cost
            if rem_k < 0:
                continue

            ok = True
            for i in range(1, n):
                found = False
                for c in "AB":
                    add = (c != s[i]) + (c != prev)
                    # remaining positions after i
                    rem_positions = n - i - 1
                    max_future = 2 * rem_positions

                    if rem_k - add < 0:
                        continue
                    if rem_k - add > max_future:
                        continue

                    ans.append(c)
                    rem_k -= add
                    prev = c
                    found = True
                    break

                if not found:
                    ok = False
                    break

            if ok and rem_k == 0:
                print("YES")
                print("".join(ans))
                possible = True
                break

        if not possible:
            print("NO")

if __name__ == "__main__":
    solve()
```このソリューションでは、2 行目を段階的に構築します。 各ステップで、選択肢 A と B の両方を評価し、その文字を選択することで残りの必要な不一致数が達成可能な範囲内に収まるかどうかをチェックします。 用語`(c != s[i])`垂直方向の不一致が考慮されますが、`(c != prev)`水平方向の不一致が考慮されます。 バウンド`2 * rem_positions`残りの各列が将来最大 2 つの不一致に寄与する可能性があることを反映しています。 

最初の列には水平方向の寄与がないため、開始文字に対する外側のループが必要です。そのため、これを誤って修正すると、有効な構造がブロックされる可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()

        # brute check for small n only
        if n > 10:
            # just call solver
            continue

        best = None
        for mask in range(1 << n):
            b = []
            for i in range(n):
                b.append('A' if (mask >> i) & 1 == 0 else 'B')
            b = "".join(b)

            cnt = 0
            for i in range(n):
                if b[i] != s[i]:
                    cnt += 1
                if i:
                    cnt += (b[i] != b[i-1])
            if cnt == k:
                best = b
                break

        if best is None:
            out.append("NO")
        else:
            out.append("YES")
            out.append(best)

    return "\n".join(out)

 ## 特殊なケース

 主なエッジケースは次の場合に発生します。$n=1$、水平エッジはなく、垂直エッジが 1 つだけ存在します。 アルゴリズムは垂直方向の不一致のみを評価し、実行可能性を即座にチェックするため、これを自然に処理します。$k$。 

もう 1 つのエッジケースは次のような場合です$k$可能な最大値に近い$3n$。 このような場合、ほぼすべての選択で垂直方向と水平方向の両方の不一致が生じ、交互のパターンに向かって構築する必要があります。 実現可能性チェックにより、十分な残りのコストを維持できない構成への時期尚早のコミットメントが防止されます。 

最後に、最初の行が頻繁に交互する場合、最適な 2 行目でも水平コストを制御するために長い均一なセグメントが必要になる可能性があります。 制限付き残存コスト チェックでは、すべてのステップで将来達成可能な貢献が考慮されるため、これらの強制セグメントが誤って拒否されないことが保証されます。
