 ## 解決策
 ## 問題の理解

 最初は無限のような集合が与えられています$S$整数で構成される$1, 2, 3, \dots$。 毎日、Ntarsis はこのセットから特定の要素を削除します。 削除する要素は配列で与えられます$a = [a_1, a_2, \dots, a_n]$、ここでそれぞれ$a_i$現在のセット内の要素の位置 (1 から始まる) です。 この操作を繰り返します$k$日々。 タスクは、に残っている最小の要素を決定することです。$S$後$k$日々。 

考慮すべき主な制約は次のとおりです。$n$そして$k$それぞれが最大に達することができます$2 \cdot 10^5$、および配列$a$まで厳密に増加する要素があります$10^9$。 セット$S$概念的には～まで拡張されます$10^{1000}$ですが、明示的に構築する必要はありません。 の合計$n$そして$k$すべてのテスト ケースにわたって次の制限も受けられます。$2 \cdot 10^5$、つまり、合計がほぼ線形になる解が必要です。$n$そして$k$。 

リストまたはセット内の削除を明示的にシミュレートする単純なアプローチは失敗します。$S$そして操作の数は膨大になる可能性があります。 要素ごとに反復しても遅すぎます。 もう 1 つの微妙なエッジ ケースは、削除する最初の要素が 1 の場合です。つまり、最小の要素が初日に削除されます。 配列に連続した整数が含まれている場合、削除された要素間のギャップによって、生き残った最小の要素が増加する速度が決まります。 不注意な実装では、これらのギャップの計算を誤ることが多く、off-by-one エラーが発生します。 

## アプローチ

 ブルート フォース ソリューションでは、現在のセットが維持されます。$S$そして毎日、$a_i$- 番目の要素を順番に並べます。 これは問題を直接モデル化しますが、一連のサイズをシミュレートしようとすると、1 日でも数百万の要素を削除する必要があるため、実行不可能です。$10^{1000}$。 操作の数は爆発的に増加し、簡単に$O(n \cdot k)$各テストケースでは大きすぎて、$n, k \sim 2 \cdot 10^5$。 

最適なアプローチは、最小の要素を追跡するだけでよいという観察を活用します。 毎日、移動によって引き起こされる位置の移動は、予測可能なパターンを形成します。 具体的には、前日の最小要素がわかっている場合$x$、削除後$a_1, \dots, a_n$、新しい最小要素は次のように増加します。$n$毎日、連続した間のギャップによって調整されます$a_i$。 セット全体をシミュレートするのではなく、次の最小要素の増加を計算できます。$k$のポジションのみを使用した日$a$そして日数カウント$k$。 問題は、「最初に残っている要素の前に削除される」要素の数を計算し、それを伝播することに帰着します。$k$日々。 

この観察は、次の線形時間アルゴリズムにつながります。$n + k$テスト ケースごとに、合計された制約を考慮するとこれで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * k) | O(n) | 遅すぎる |
 | 最適 | O(n + k) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、次の内容を読んでください。$n$そして$k$、配列を読み取ります$a$。 この配列はすでに厳密に昇順にソートされています。 
3. 変数を初期化する`current_min`の最小要素を表す 1 に$S$削除の前に。 
4. 1 日分の削除による増分効果を計算します。 概念的には、1 日後、最小の要素は、その前に削除された要素の数だけ増加します。 これは、最初に削除された要素とその位置インデックスの間の違いとして見ることができます。$a_1 - 1$。 後続の要素の場合、削除された位置間のギャップ$a_i - a_{i-1} - 1$それらの間でどれだけの要素が生き残るかを示します。 
5. この毎日の増分を繰り返します$k$回。 パターンが繰り返されるため、合計の増加量は$k \cdot n$さらに、削除された位置が連続していない場合は、ギャップからの調整が行われます。 
6. 出力`current_min + k * n`後の最小要素として$k$日々。 0 ベースのインデックス付けと 1 ベースのインデックス付けを慎重に調整してください。 

**機能する理由:** このアルゴリズムは、最初に生き残った要素が毎日どれだけ前進したかのみを追跡します。 のポジション$a$は相対的なものであるため、セット全体をシミュレートせずに毎日のシフトを計算できます。 不変条件は、指定された位置を削除した後に残る最小の要素は常に、次の要素でカバーされない最小のギャップであるということです。`a`。 これを応用すると`k`回は直線的に累積します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        last = 0
        cnt = 0
        for ai in a:
            if ai > last:
                cnt += 1
                last = ai + cnt - 1
        # The first element after k days is 1 + n * k - number of skips already counted
        print(cnt + k - 1 + 1)

if __name__ == "__main__":
    solve()
```このソリューションは、セットを明示的に維持することなく、入力を効率的に読み取り、削除の効果を計算します。 変数`cnt`現在の最小値の前に効果的に削除される要素の数を累積します。 最終出力を次のように調整します。`+1`1 から始まるインデックスに変換し直します。

 ## 特殊なケース

 いつ`a`1 から始まる場合、最小の要素はすぐに削除されます。 たとえば、入力`1 1\n1\n`結果として`2`。 アルゴリズムが重要`cnt`正しく実行され、生き残った要素に 1 つ追加されます。 大型用`k`、最小の要素は直線的に増加し、アルゴリズムは効果的に計算することによってそれを捕捉します。
