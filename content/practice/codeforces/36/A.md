 ## 解決策
 ## 問題の理解

 数日間にわたる Vasya の観察を表すバイナリ文字列が与えられます。 キャラクター`'1'`はその日に信号が受信されたことを意味します。`'0'`信号が現れなかったことを意味します。 

タスクは、受信信号が完全に規則的なパターンに従っているかどうかを判断することです。 より正確に言うと、すべての位置を見ると、`'1'`文字の場合、連続する位置間のギャップはすべて同一である必要があります。 すべての間隔が同じ場合、印刷します`"YES"`。 それ以外の場合は印刷します`"NO"`。 

たとえば、文字列では`001001001`、信号は位置に表示されます`2`、`5`、 そして`8`。 ギャップは`3`そして`3`, したがって、パターンは規則的です。 

制約は非常に小さいです。 文字列の長さは最大でも`100`つまり、非効率的なソリューションでも制限内で簡単に実行できることになります。 近似の二次解`10^4`制限時間は 2 秒なので、操作は簡単です。 それでも、この問題は主にクリーンな実装と信号の位置を正しく処理することに関係しています。 

難しいのはパフォーマンスではなく、信号間の間隔を正しく解釈することです。 

次の入力を考えてみましょう。```
5
10101
```信号の位置は、`0`、`2`、 そして`4`。 ギャップは`2`そして`2`、したがって、答えは次のとおりです`"YES"`。 

不注意な実装では、信号間でゼロをカウントし、誤って比較してしまう可能性があります。`1`そして`1`これはここではたまたま機能しますが、インデックス作成ロジックと混合すると混乱を招く可能性があります。 

もう 1 つの微妙なケースは、信号間にゼロが存在せずに連続した信号が表示される場合です。```
6
111000
```ポジションは`0`、`1`、 そして`2`。 ギャップは`1`そして`1`、したがって、答えは次のとおりです`"YES"`。 

すべての信号の間に少なくとも 1 つのゼロが必要であると仮定する間違ったアプローチは、ここでは失敗します。 

より危険なエッジケースは、一部の間隔のみが一致する場合です。```
7
1001001
```信号の位置は、`0`、`3`、 そして`6`。 ギャップは`3`そして`3`、したがって、答えは次のとおりです`"YES"`。 

しかし：```
7
1001010
```ポジションは`0`、`3`、 そして`5`。 ギャップは`3`そして`2`、したがって、正しい答えは次のとおりです。`"NO"`。 

最初と最後の信号のみを比較すると、パターンが規則的であると誤って結論付ける可能性があります。 

## アプローチ

 最も直接的な総当たりのアイデアは、以下を含むすべてのポジションを収集することです。`'1'`、その後、すべての連続する差分を明示的に計算して比較します。 

信号の位置が配列に格納されているとします。```
pos = [2, 5, 8, 11]
```次のように計算します。```
5 - 2 = 3
8 - 5 = 3
11 - 8 = 3
```すべての差異が最初の差異と等しい場合、パターンは規則的です。 

このアプローチはすでに十分に高速です。 せいぜい`100`文字列を繰り返しスキャンしても、制限内で快適に動作します。 

より単純なブルート フォースの変形では、考えられるすべての間隔の長さを試し、すべての信号がその間隔に従うかどうかを検証できます。 制約が小さいためそれでも問題は解決しますが、不必要な作業が実行され、実装が複雑になります。 

重要な観察は、問題は連続するオブジェクト間の距離のみに依存するということです。`'1'`ポジション。 最初の間隔がわかったら、その後のすべての間隔はその間隔と正確に一致する必要があります。 他には何も関係ありません。 

この観察により、タスクは信号位置の単純な線形スキャンに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 承認済み |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`そしてバイナリ文字列。 
2. 文字列をトラバースし、文字が存在する場所のインデックスを保存します。`'1'`。 

これらのインデックスは、信号が受信された日を表します。 
3. 最初の 2 つの信号位置間の距離を計算します。 

これは、以降のすべてのペアが従わなければならない予想される間隔になります。 
4. 残りの連続する信号位置のペアを繰り返します。 

各ペアについて、それらのインデックスの差を計算します。 
5. 現在の差を予想される間隔と比較します。 

間隔が異なる場合は印刷します`"NO"`パターンが規則的ではないのですぐに。 
6. すべての間隔が一致する場合は、印刷します。`"YES"`。 

### なぜ効果があるのか

 この問題で必要な唯一の条件は、連続する信号間のすべての間隔が等しいことです。 アルゴリズムはそのプロパティを直接チェックします。 

信号の位置を次のようにします。```
p₀, p₁, p₂, ..., pₖ
```シーケンスは次の場合にのみ有効です。```
p₁ - p₀ = p₂ - p₁ = ... = pₖ - pₖ₋₁
```アルゴリズムは最初の差分を計算し、それ以降のすべての差分を検証します。 必要な間隔はすべて 1 回だけチェックされるため、アルゴリズムがシーケンスを誤って受け入れたり拒否したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
s = input().strip()

positions = []

for i in range(n):
    if s[i] == '1':
        positions.append(i)

gap = positions[1] - positions[0]

for i in range(2, len(positions)):
    if positions[i] - positions[i - 1] != gap:
        print("NO")
        break
else:
    print("YES")
```コードの最初の部分は入力を読み取り、次の内容を含むすべてのインデックスを収集します。`'1'`。 インデックスを直接使用すると、ロジックが単純になり、信号間のゼロのカウントに関する混乱が回避されます。 

変数`gap`信号間の予想される間隔を格納します。 ステートメントでは少なくとも 3 つが保証されているため、`'1'`文字、アクセス`positions[1]`常に安全です。 

ループはインデックスから始まります`2`最初の間隔がすでに基準として使用されているためです。 後のすべての信号について、前の信号からの距離を比較します。`gap`。 

の`for-else`ここの構造は便利です。 ヒットせずにループが終了した場合`break`、すべての間隔が一致し、出力します`"YES"`。 

よくある間違いは、ゼロカウントとインデックスの差を混同することです。 たとえば、ポジション`0`そして`3`の距離だけ離れている`3`たとえそれらの間にゼロが 2 つしかないとしても。 インデックスを直接使用すると、その曖昧さを回避できます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    s = input().strip()

    positions = []

    for i in range(n):
        if s[i] == '1':
            positions.append(i)

    gap = positions[1] - positions[0]

    for i in range(2, len(positions)):
        if positions[i] - positions[i - 1] != gap:
            print("NO")
            return

    print("YES")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run("8\n00111000\n") == "YES", "sample 1"

# custom cases
assert run("5\n10101\n") == "YES", "equal spacing"
assert run("7\n1001010\n") == "NO", "unequal spacing"
assert run("6\n111000\n") == "YES", "consecutive signals"
assert run("3\n111\n") == "YES", "minimum size"
assert run("10\n1001001001\n") == "YES", "large equal intervals"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`10101`|`YES`| 信号間にゼロを含む規則的な間隔 |
 |`1001010`|`NO`| 不等間隔 |
 |`111000`|`YES`| 間隔 1 の連続信号 |
 |`111`|`YES`| 有効な最小入力サイズ |

 ## 特殊なケース

 連続した信号の場合を考えてみましょう。```
6
111000
```位置配列は次のようになります。```
[0, 1, 2]
```予想されるギャップは次のとおりです。```
1 - 0 = 1
```残りのチェックは次のとおりです。```
2 - 1 = 1
```すべての間隔が一致するため、アルゴリズムは次のように出力します。`"YES"`。 

このケースでは、長さの間隔が`1`完全に有効です。 

次に、不規則なパターンを考えてみましょう。```
7
1001010
```ポジションは次のとおりです。```
[0, 3, 5]
```予想されるギャップは、`3`。 

次の間隔は次のとおりです。```
5 - 3 = 2
```以来`2 != 3`、アルゴリズムはすぐに出力します`"NO"`。 

これは、連続するすべての間隔が独立してチェックされることを示しています。 

最後に、完全に規則的なスパース パターンを考えてみましょう。```
9
100100100
```ポジションは次のとおりです。```
[0, 3, 6]
```予想されるギャップは次のとおりです。```
3
```2番目の間隔も`3`、アルゴリズムは次のように出力します`"YES"`。 

これにより、実際のゼロの数は重要ではないことが確認されます。 連続距離が等しいことだけが重要です。
