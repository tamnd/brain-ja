 ## 解決策
 ## 問題の理解

 まずは、`n × n`黒いセルで構成されるパターン (`*`) と白血球 (`.`）。 このパターンはテンプレートのように機能します。 

フラクタルは再帰的に構築されます。 最初のレベルでは、キャンバス全体が次のように分割されます。`n × n`ブロックになり、テンプレート内の黒いセルに対応するすべてのブロックが完全に黒になります。 白いテンプレートセルは今のところ未定です。 

次のレベルでは、まだ白いブロックがすべて再び次のように分割されます。`n × n`より小さいブロックであり、その中に同じテンプレートが適用されます。 黒セルは永久に拡大を停止しますが、白セルは再帰的に継続します。 

このプロセスを正確に実行した後、`k`場合によっては、最終的な画像を印刷する必要があります。 そのサイズは`n^k × n^k`。 

制限は数値的には非常に小さいですが、最終的な出力自体は大きくなる可能性があります。 以来`n ≤ 3`そして`k ≤ 5`、可能な最大のグリッドのサイズは`3^5 = 243`したがって、出力には最大で約 60,000 個のセルが含まれます。 つまり、アルゴリズムがすべての最後のセルに複数回アクセスしても完全に安全です。 

本当の課題は、再帰によって特定のセルが黒になるか白になるかをどのように決定するかを理解することです。 

よくある間違いは、レベルごとに前の色が上書きされると考えることです。 それはプロセスの仕組みではありません。 領域が黒になると、再帰はそこで永久に停止します。 

次の入力を考えてみましょう。```
2 2
*.
..
```最初のレベルでは、左上の象限が完全に黒になります。 その中にあるものは再び細分化されません。 不用意に実装すると、その象限への再帰が続き、完全に黒のままであるべき領域内に白セルが誤って作成される可能性があります。 

テンプレートに白いセルが 1 つしか含まれていない場合は、別の微妙なケースが発生します。```
2 3
**
*.
```右下の枝のみが細分化され続けます。 他のすべての領域はすぐに黒になります。 実装がステップごとにすべてのセルを盲目的に展開すると、作業が無駄になり、固定された黒い領域を誤って上書きする可能性があります。 

可能な限り最小のケースもチェックする価値があります。```
2 1
..
.*
```ここでの答えは、まさに元のテンプレートです。 1 つのレベルのみを実行するため、再帰的な拡張は行われません。 

## アプローチ

 最も直接的なシミュレーションは、このステートメントを文字通り反映しています。 

単一の白い正方形から始めます。 各ステップで、現在白い四角形はすべて`n × n`テンプレートのコピー。 黒い四角は永遠に黒一色のままです。 

これを実装する 1 つの方法は再帰的細分割です。 すべての領域はすぐに完全に黒になるか、再度細分化されます。 最終的な画像には最大でも次のものが含まれるため、`243 × 243`セルの場合、このアプローチはすでに十分に高速です。 

問題は、再帰領域を明示的に管理するのが面倒になることです。 座標、サイズ、停止条件、およびすでに黒い領域の慎重な処理が必要です。 

重要な観察は、すべての最終セルを独立して分析できることです。 

細胞を取る`(x, y)`最終グリッドで。 すべての再帰レベルで、テンプレートはその位置が黒のサブセルに該当するか白のサブセルに該当するかを決定します。 各レベルの座標は単に次の数字です。`x`そして`y`基地内で`n`。 

あるレベルで次のことを調べるとします。```
template[x % n][y % n]
```この位置が黒の場合、祖先領域全体がその再帰深さで黒になるため、最後のセルも黒になる必要があります。 すぐに止められます。 

白の場合、再帰は上向きに継続します。```
x //= n
y //= n
```これを全員に繰り返します`k`レベル。 黒いテンプレート セルにレベルが到達しない場合、最後のセルは白のままになります。 

これにより、問題は再帰的な領域構築から単純なセルごとの桁検査問題に変換されます。 

総当り再帰的構築は出力サイズが小さいため機能しますが、座標ベースの解釈の方がクリーンで推論がはるかに簡単です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース再帰構築 | O(n^(2k) * k) | O(n^(2k)) | 承認済み |
 | 最適な座標検査 | O(n^(2k) * k) | O(1) おまけ | 承認済み |

 出力自体がすでに存在するため、漸近的な複雑さは同じように見えます。`n^(2k)`細胞。 この改善は、シンプルさと低い定数要因によってもたらされます。 

## アルゴリズムのチュートリアル

 1. テンプレート グリッドを読み取り、最終的なサイズを計算します。`size = n^k`。 
2. すべての最終セルを反復処理します。`(i, j)`で`size × size`出力グリッド。 
3. 現在のセルの座標を一時変数にコピーします。```
x = i
y = j
```4. 正確に繰り返します`k`回。 

各ステップで以下を検査します。```
template[x % n][y % n]
```これらの剰余は、どのテンプレート セルが現在の再帰レベルを制御しているかを示します。 
5. そのテンプレートセルが黒の場合 (`*`)、最後のセルをすぐに黒にマークし、より深いレベルのチェックを停止します。 

これが機能するのは、黒い領域がそれ以上細分化されないためです。 
6. それ以外の場合は、座標を分割します。```
x //= n
y //= n
```これにより、親の再帰レベルに移動します。 
7. もしすべてが`k`レベルは白のままで、最後のセルは白になります。 
8. 構築された行を印刷します。 

### なぜ効果があるのか

 最終的なイメージ内のすべての座標は、再帰的サブディビジョン ツリー内のパスに対応します。 

最も重要でない塩基 -`n`数字は最も深いサブディビジョン レベルを決定し、次の数字は親レベルを決定します。 

このパスのいずれかのレベルが黒いテンプレート位置に到達すると、セルは黒になります。 それが起こると再帰は停止し、子孫領域全体が永久に黒いままになります。 

すべてのレベルが白いテンプレート セルに到達した場合、再帰はすべて存続します。`k`ステップを実行してもセルは白のままです。 

アルゴリズムはこれらの条件を正確にチェックするため、すべての出力セルは正しい色を受け取ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
pattern = [input().strip() for _ in range(n)]

size = n ** k
answer = []

for i in range(size):
    row = []

    for j in range(size):
        x = i
        y = j
        black = False

        for _ in range(k):
            if pattern[x % n][y % n] == '*':
                black = True
                break

            x //= n
            y //= n

        row.append('*' if black else '.')

    answer.append(''.join(row))

sys.stdout.write('\n'.join(answer))
```外側の 2 つのループは、最終画像のすべての位置を生成します。 

各セルの変数`x`そして`y`整数除算を使用して繰り返し削減されます。 これにより、再帰レベルを効果的に上に向かって進みます。 

表現:```
pattern[x % n][y % n]
```現在のベースを抽出します-`n`数字のペア。 これらの数字は、どのテンプレート ブロックが現在のレベルを制御しているかを識別します。 

初期の`break`重要です。 黒いテンプレート セルが表示されると、再帰はそこで永続的に停止するため、より深いレベルは問題になりません。 

実装の微妙な詳細は、操作の順序です。 で割る前に現在の剰余を確認する必要があります`n`。 順序を逆にすると、最も深い再帰レベルがスキップされ、シフトされたパターンが生成されます。 

別の詳細が正確に反復されています`k`回。 たとえ`x`そして`y`早期にゼロになり、より高い再帰レベルは依然としてテンプレートの位置に対応します`(0, 0)`。

 ## 特殊なケース

 再帰が 1 つのパスのみで存続する場合を考えてみましょう。```
2 3
**
*.
```どのレベルでも、3 つの象限が即座に永続的に黒になります。 右下の象限のみが細分化を続けます。 

セルを取る`(7,7)`。 

各レベルで:```
(7 % 2, 7 % 2) = (1,1) -> white
(3 % 2, 3 % 2) = (1,1) -> white
(1 % 2, 1 % 2) = (1,1) -> white
```黒レベルが表示されないため、セルは白のままです。 

さあ、取ってください`(6,7)`:```
(0,1) -> black
```アルゴリズムは即座に停止し、セルを黒にマークします。 

これは、単一の黒人の祖先がすべ​​てのより深いレベルを支配するという規則を裏付けています。 

ここで、再帰の最小の深さを考えてみましょう。```
2 1
..
.*
```アルゴリズムは各セルに対して 1 つのレベルを正確にチェックします。 

のために`(1,1)`:```
(1 % 2, 1 % 2) = (1,1) -> black
```のために`(0,1)`:```
(0,1) -> white
```出力はテンプレートと正確に一致し、実装が処理していることを確認します。`k = 1`余分な分割なしで正しく。 

最後に、すべて白のテンプレートを考えてみましょう。```
2 2
..
..
```すべてのレベル チェックは常に白いテンプレート セルに到達します。 どの再帰レベルも黒を生成しないため、最終イメージ全体は白のままになります。 

これにより、誤ってセルを黒として初期化する実装や、反復間の状態のリセットに失敗する実装が捕捉されます。
