 ## 解決策
 ## 問題の理解

 この問題は、単純な基数変換タスクを表記法の背後に隠しています。 指定された値は何らかのベースを使用して書き込まれます`i`、そして目標は、別の基数を使用して書かれた同じ数字を出力することです`j`。 

紛らわしいのは表記です`a_i`。 のように見えます`i`シーケンスの - 番目の要素ですが、実際には「数値の表現」を意味します。`a`基地内で`i`”。より大きな基数での表現は一般に桁数が少なくなります。これは、インデックスを増やすと書き込まれた値が小さく見えるという観察と一致します。基数`1`は有効な位置番号体系ではありません。これが、最初のケースが特別である理由を説明しています。 

入力により、元の基数、ターゲットの基数、および元の基数の数値の桁が与えられます。 出力は、ターゲットの基数で表現されたのと同じ整数です。 

制約は、変換された値が通常の 64 ビット整数に収まるように設計されています。 ターゲットベースは最大でも`10`したがって、すべての出力桁は 10 進数文字を使用して出力できます。 これは、入力桁数の線形作業のみが必要であることを意味します。 可能な数値を試したり、大きなテーブルを構築したりするようなアプローチは必要ありません。 

主なエッジ ケースはベース ハンドリングから発生します。 のような数字`0`残らなければなりません`0`変換後。 基底からそれ自体への変換では、元の表現が返される必要があります。 入力表現内の先頭のゼロは値を変更してはなりません。 

たとえば、入力が次の場合:```
2 10
1010
```正しい出力は次のとおりです。```
10
```入力を 10 進数として扱う不用意な解決策では、次のように解釈されてしまいます。`1010`バイナリ表現ではなく、1000 として。 

別のエッジケースは次のとおりです。```
10 2
0
```正しい出力は次のとおりです。```
0
```すべてのゼロを削除したり、ゼロ以外の数字が常に存在すると仮定したりする解決策は、ここでは失敗します。 

## アプローチ

 直接的なアプローチは、数字の意味をシミュレートすることです。 ベースに書かれた数字`b`左から右に数字を処理することで評価できます。 現在の積算値が`x`そして次の桁は`d`、新しい値は次のとおりです。`x * b + d`これを繰り返すと、表現全体が実際の整数値に変換されます。 その後、対象の基数を法とした余りを基数で割ることを繰り返すことで、別の基数に同じ値を書き込むことができます。 

これが機能するのは、位置表記が乗算と加算を正確に繰り返すためです。 ブルートフォースの代替手段は、指定された桁と表現が一致する数値を検索することですが、使用可能な値は桁数とともに指数関数的に増加するため、このアプローチは使用できなくなります。 

真の値には限界があるという観察により、任意精度のトリックを回避し、通常の整数演算を使用できるようになります。

 ## アルゴリズムのチュートリアル

 1. オリジナルのベースを読む`i`、ターゲットベース`j`、および数値の表現。 
2. 表現をベースから変換する`i`整数値に変換します。 価値から始める`0`、そしてすべての桁について、現在の値に次の値を掛けます。`i`数字を追加する前に。 
3. 結果の値が次の場合`0`、印刷`0`すぐに。 これは、通常の繰り返し除算で桁が生成されない唯一の数値を処理します。 
4. 値を繰り返し除算します。`j`。 各剰余は、ターゲット表現の最下位桁から始まる次の桁です。 
5. 割り算では右から左に数字が検出されるため、収集した数字を反転して印刷します。 

機能する理由: 最初のフェーズでは、入力数字で表される一意の整数を再構築します。 2 番目のフェーズでは、位置表記の逆のプロセスを使用します。 基数で繰り返し除算すると、その基数表現の数字が最下位から最上位に与えられるため、それらを反転すると、必要な出力が正確に生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = input().split()
    if not data:
        return

    src = int(data[0])
    dst = int(data[1])
    s = data[2]

    value = 0
    for ch in s:
        value = value * src + int(ch)

    if value == 0:
        print(0)
        return

    ans = []
    while value > 0:
        ans.append(str(value % dst))
        value //= dst

    print("".join(reversed(ans)))

if __name__ == "__main__":
    solve()
```変換ループは位置表記の式に直接に従います。 変数`value`これまでに処理されたプレフィックスの数値を常に格納します。 

ゼロ除算を繰り返すと桁が生成されないのに対し、ゼロの表現には 1 桁が含まれなければならないため、ゼロ チェックが必要です。 

出力変換中に、剰余が逆方向に生成されます。 たとえば、10進数を変換すると、`13`基地へ`2`剰余を生成します`1`、`0`、`1`、`1`、右から左に読まれる表現に対応します。 逆にすると順序が固定されます。 

インデックスは使用されないため、off-by-one の問題は発生しません。 Python の整数では、オーバーフローの問題も回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    data = sys.stdin.readline().split()
    if not data:
        sys.stdin = old_stdin
        return ""

    src = int(data[0])
    dst = int(data[1])
    s = data[2]

    value = 0
    for ch in s:
        value = value * src + int(ch)

    if value == 0:
        result = "0"
    else:
        res = []
        while value:
            res.append(str(value % dst))
            value //= dst
        result = "".join(reversed(res))

    sys.stdin = old_stdin
    return result + "\n"

assert run("2 10\n1010\n") == "10\n", "binary to decimal"
assert run("10 2\n15\n") == "1111\n", "decimal to binary"

assert run("10 10\n00042\n") == "42\n", "leading zeroes"
assert run("8 2\n17\n") == "1111\n", "octal conversion"
assert run("10 10\n0\n") == "0\n", "zero handling"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 10 / 1010`|`10`| 小規模なベースからの基本的な変換 |
 |`10 2 / 15`|`1111`| 繰り返し除算出力の構築 |
 |`10 10 / 00042`|`42`| 先頭のゼロを無視する |
 |`8 2 / 17`|`1111`| 10 進数以外のソース ベース |
 |`10 10 / 0`|`0`| ゼロの特別な処理 |

```アルゴリズムは最初に値を次のように再構築します。`10`。 出力の基数は 10 進数であるため、除算フェーズによりすぐに 1 桁が生成されます。`10`。
