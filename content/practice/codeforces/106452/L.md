 ## 解決策
 # 問題の理解

 接続された重み付き無向グラフがあります。 MST は、可能な限り最小の合計エッジ重みを持つスパニング ツリーですが、いくつかの異なるツリーが同じ最小コストを持つ可能性があります。 

この問題によって許可される操作は特殊です。エッジの重みを増やすだけでよく、増加ごとに 1 回の操作が必要になります。 目標は、MST を見つけることではなく、既存の MST 構造からすべてのあいまいさを取り除くことです。 最小スパニング ツリー コストがまったく同じになり、可能な MST が 1 つだけになるように、最小数のエッジの重みを増やす必要があります。 

入力は頂点とエッジを記述します。 各エッジは 2 つの頂点を接続し、正の重みを持ちます。 出力は最小の個体数です。`+1`体重増加が必要です。 

制約が大きい: 頂点とエッジの両方の数が制限されます。`2 * 10^5`。 スパニング ツリーの数は指数関数的に増加する可能性があるため、考えられるすべてのスパニング ツリーをチェックするアルゴリズムは不可能です。 すべてのエッジにわたってグラフ検索を繰り返すアプローチでも、遅すぎます。 線形に近い、または`O(m log m)`これは、クラスカルのアルゴリズムの構造を使用することを指します。 

難しいのは、同じ重みのエッジのグループを処理することです。 複数の MST が存在する唯一の理由は、重みが等しいことです。 たとえば、次のことを考えてみましょう。```
3 3
1 2 1
2 3 1
1 3 1
```答えは`1`。 不注意な解決策では、3 つのエッジはすべて最小の重みを持っているため、すべてが必要であると考えるかもしれませんが、3 つの頂点を接続するのに必要なのは 2 つのエッジだけです。 片方のエッジを持ち上げて加重する`2`MST は 1 つだけ残ります。 

もう 1 つのエッジ ケースは、同じ重みでは選択肢が作成されない場合です。```
3 3
1 2 1
2 3 2
1 3 3
```答えは`0`。 最小のエッジの選択によってツリーが強制されるため、MST はすでに一意です。 すべての非 MST エッジをカウントするソリューションは、誤って返します。`1`またはそれ以上。 

最後の境界ケースは、頂点が 1 つあるグラフです。```
1 0
```答えは`0`。 変更するエッジはなく、単一の頂点がすでにスパニング ツリーを形成しています。 少なくとも 1 つのエッジを想定するコード、または MST を構築しようとするコード`n-1`ここでエッジが失敗する可能性があります。 

# アプローチ

 直接的なアプローチは、MST を構築してから、すべての代替ツリーを検査することです。 複数の MST が存在する場合は、エッジを 1 つずつ増やして、MST が一意になるかどうかを確認してみてください。 MST プロパティによって一意性をテストできるため、この考えは正しいですが、可能な変更の数が多すぎます。 最悪の場合、多くの等しい重みのエッジを持つ密なグラフでは、多くの MST 候補を繰り返し検査する必要があり、これは限界をはるかに超えています。 

重要な観察は、クラスカルのアルゴリズムから得られます。 Kruskal は、重みの増加順にエッジを処理します。 すべてのエッジの重みが以下の場合`w`処理が完了すると、現在の DSU コンポーネントは、重みのエッジを考慮する前にすでに強制されているすべてのものを表します。`w`。 

同じ重みを持つエッジだけを見てみましょう`w`。 重みが小さい各 DSU コンポーネントの内部では、これらのエッジは MST に影響を与えることはできません。 残りの等しい重みのエッジは、現在のコンポーネントを相互に接続します。 これらのエッジにサイクルが含まれている場合、重みの MST エッジを選択する方法は複数あります。`w`。 

これらの等しい重みのエッジによって形成されるすべての接続コンポーネントについては、それらの間にスパニング ツリーのみが必要です。 そのツリーを超える余分なエッジは代替 MST を作成するため、増やす必要があります。 一時コンポーネントに次のものが含まれている場合、`E`エッジと`V`DSU コンポーネント、正確には`E - (V - 1)`エッジを上げる必要があります。 

これは、各重量グループの処理中に計算できます。 現在のさまざまな DSU コンポーネントを接続する等しい重みのエッジを数えてから、実際にコンポーネントを結合するエッジの数を数えます。 違いは不要なエッジの数です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数的`n`| O(n + m) | 遅すぎる |
 | 最適 | O(m log m) | O(n + m) | 承認済み |

 # アルゴリズムのチュートリアル

 1. すべてのエッジを重みで並べ替えます。 Kruskal のアルゴリズムは、より小さい重みを最初に処理することに依存しています。これは、より重いグループが考慮される前に、より低い重みを持つエッジがすでに固定されているためです。 
2. 現在のグループより厳密に小さい重みを持つすべてのエッジを含む DSU を維持します。 同じ重みを持つエッジのグループの場合、同じ DSU コンポーネント内の 2 つの頂点を既に接続しているエッジを一時的に無視します。 これらのエッジは、より安価なパスがすでにエンドポイントに接続されているため、MST を変更することはできません。 
3. この重みグループの残りのエッジについて、異なる DSU コンポーネントを接続できる数を数えます。 これらは、一部の MST に参加できるエッジです。 
4. これらの残りのエッジを DSU にマージします。 マージが成功するたびに、必要な独立した接続の数が減ります。 マージが失敗した場合、エッジは同じ重みの選択肢の間でサイクルを作成します。これは、エッジが非一意性を引き起こすエッジであることを意味します。 
5. この加重グループからの失敗したマージの数を答えに加算します。 これらはまさに重みを増やす必要があるエッジです。 
6. すべてのエッジが処理されるまで、次の重みグループを続行します。 

なぜ効果があるのか:

 Kruskal のアルゴリズムは、各重みグループ内のエッジを選択して、現在別々のコンポーネントをできるだけ多く接続することによって、すべての MST を構築できることを示しています。 より小さい重みがすべて固定された後、サイクルを持つ等しい重みのエッジの接続グループにより、複数の有効な選択肢が得られます。 ツリーを残すのに十分なエッジを削除すると、同じ合計コストで MST を構築する能力を維持しながら、すべての選択肢が削除されます。 失敗した DSU マージはまさに余剰サイクル エッジであるため、それらをカウントすることで必要な増加の最小数が得られます。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def unite(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

def solve():
    n, m = map(int, input().split())
    edges = []

    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((w, u - 1, v - 1))

    edges.sort()

    dsu = DSU(n)
    ans = 0
    i = 0

    while i < m:
        j = i
        while j < m and edges[j][0] == edges[i][0]:
            j += 1

        before = 0
        for k in range(i, j):
            _, u, v = edges[k]
            if dsu.find(u) != dsu.find(v):
                before += 1

        merged = 0
        for k in range(i, j):
            _, u, v = edges[k]
            if dsu.unite(u, v):
                merged += 1

        ans += before - merged
        i = j

    print(ans)

if __name__ == "__main__":
    solve()
```DSU は、すでに処理されたすべての軽量エッジによって形成されたコンポーネントを保存します。 並べ替えステップでは、Kruskal で使用されているのと同じ順序が与えられます。 

各体重グループごとに、`before`MST 内に出現する可能性のある等しい重みのエッジの数をカウントします。 すでに 1 つのコンポーネント内にあるエッジは、より軽いパスで置き換えることができるため、無視されます。 

の`merged`count は、コンポーネントを接続するために実際に必要なエッジの数を記録します。 成功したすべてのマージは、可能性のあるスパニング フォレストに 1 つのエッジを提供します。 違い`before - merged`は、その重みグループ内のサイクル エッジの数です。 

このコードでは、反復パス圧縮を使用しています。`find`サイズによる結合`unite`、DSU の動作をほぼ一定の時間に保ちます。 すべての重みは整数として処理され、答えはオーバーフローを心配することなく通常の Python 整数に収まります。

# エッジケース

 等しい重みの三角形の場合:```
3 3
1 2 1
2 3 1
1 3 1
```最初はすべてのエッジが MST に表示されます。 DSU は 3 つの個別のコンポーネントから始まります。 最初の 2 つのマージによってスパニング ツリーが作成されます。 3 番目のエッジは、ウェイト 1 エッジによってすでに接続されている頂点を接続するため、サイクルを形成します。 アルゴリズムは失敗したマージを 1 回カウントして返します。`1`。 

すでに一意の MST の場合:```
3 3
1 2 1
2 3 2
1 3 3
```最初のエッジは 2 つのコンポーネントを接続します。 2 番目のエッジは残りの頂点を接続します。 最後のエッジはより重く、最小エッジの中から選択を行うことはありません。 失敗したマージは発生しないため、答えは残ります`0`。 

単一頂点グラフの場合:```
1 0
```エッジ ループには決して入りません。 DSU はすでに 1 つの頂点の完全なスパニング ツリーを表しているため、答えは変わりません。`0`。 

複数の同じ重みグループの場合:```
5 6
1 2 2
2 3 1
4 5 3
2 4 2
1 4 2
1 5 3
```重み 1 のエッジが強制されます。 重み 2 のエッジのうち、安価なコンポーネントを考慮すると 1 つのエッジが冗長になり、重み 3 のエッジの間には別の冗長性が現れます。 アルゴリズムは余剰の選択肢と収益の両方をカウントします`2`。
