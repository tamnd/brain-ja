 ## 解決策
 ## 問題の理解

 非表示の値は、1 ～ 1,000,000 の間で選択される単一の整数です。 プログラムは、「少なくとも隠された数字はありますか？」という形式の質問をすることで裁判官とコミュニケーションをとることができます。`k`?”. 裁判官はこう答えます。`1`条件が true の場合、および`0`さもないと。 目標は、以下を使用して隠された数字を特定することです。`4!`、つまり 24 です、このような質問です。 

これは対話型の問題であるため、入力セクションは空です。 実行中にプログラムが受け取る唯一のデータは、各クエリの後の審査員からの応答です。 出力はクエリと、十分な情報が収集された後の最終的な推定数値で構成されます。 

この範囲には 100 万個の可能な値が含まれます。 リニア スキャンには最大 1,000,000 個の質問が必要ですが、これは許容される 24 個をはるかに超えています。インタラクションの数に制約があるため、検索スペースを非常に迅速に削減する必要があります。 すべての質問には可能な答えが 2 つしかないため、戦略を成功させるには、毎回残りの候補をほぼ半分に分ける必要があります。 20 の質問で十分です。`2^20`は 100 万より大きいため、許容制限の 24 には若干の余裕が残されています。 

主なエッジケースは範囲の境界です。 隠し番号があれば、`1`、より大きな値について尋ねるすべてのクエリは否定的に答える必要があります。 二分探索の実装を不用意に行うと、下限が大きくなりすぎて返される可能性があります。`0`、有効範囲外です。 たとえば、隠し番号が`1`、クエリ シーケンスは最終的に間隔を狭める必要があります。`[1, 1]`そして出力`1`。 

もう 1 つの境界ケースは最大値です。 隠し番号があれば、`1000000`、その値までのすべてのクエリは正です。 上限を排他的として扱う間違った実装は、次で終了する可能性があります。`999999`正解の代わりに。 たとえば、非表示の値`1000000`最終ステップまで、正しいエンドポイントを含む区間を離れる必要があります。 

## アプローチ

 簡単なアプローチは、考えられるすべての値を昇順に尋ねることです。 問い合わせることができます`1`、 それから`2`、 それから`3`など、裁判官が隠された数字が現在の値より小さいと告げるまで、または答えにたどり着くまで続きます。 考えられるすべての数がチェックされるため、これは正しいですが、最悪の場合、100 万のクエリが必要となり、インタラクション制限を大幅に違反します。 

有益な観察は、すべての質問が順序付けの比較を行うということです。 個別の番号をテストする必要はありません。 閾値のある質問`k`すべての候補を 2 つのグループに分類します: 以下の値`k`そして少なくとも価値観`k`。 私たちがいつも選択するなら`k`現在の範囲の中央付近では、各回答は残りの可能性の約半分を削除します。 

これにより、問題は区間にわたる二分探索に変換されます。`[1, 1000000]`。 約 20 回のクエリの後、残る値は 1 つだけになります。 24 クエリの許容量は十分すぎるため、従来のバイナリ検索戦略が安全です。

 | 二分探索 | O(log 1,000,000) クエリ | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在考えられる回答の間隔を表す 2 つの変数を保持します。`low = 1`そして`high = 1,000,000`。 

非表示の番号はこの間隔内に留まることが保証されます。 この不変条件を維持することがアルゴリズムの中心的な考え方です。 

1. 中間の値を選択します`mid = (low + high) // 2`そして、隠された数字が少なくとも次のものであるかどうかを尋ねます`mid`。 

答えは、間隔を 2 つの小さな有効な間隔に分割します。 答えが正の場合、隠された数字はこれを下回ることはできません`mid`。 答えが否定的な場合は、以下でなければなりません`mid`。 

1. 答えが次の場合`1`、 セット`low = mid`。 それ以外の場合は設定`high = mid - 1`。 

更新間隔では、これまでに受け取ったすべての回答と一致する候補が正確に保持されます。 

1. までプロセスを繰り返します。`low`等しい`high`。 

この時点では、使用可能な数値は 1 つだけであるため、それが非表示の値である必要があります。 

1. 必要な応答形式を使用して最終値を出力します。 

アルゴリズム全体で不変なのは、隠された数値が常に次のものに属するということです。`[low, high]`。 最初は、許可された範囲全体が使用されるため、これは当てはまります。 各クエリでは、裁判官の応答と矛盾する値のみが削除されるため、不変条件は true のままになります。 区間の長さが 1 になると、残る候補は正解のみとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    low = 1
    high = 10**6

    while low < high:
        mid = (low + high) // 2

        print(f"? {mid}", flush=True)
        ans = int(input())

        if ans == 1:
            low = mid
        else:
            high = mid - 1

    print(f"! {low}", flush=True)

if __name__ == "__main__":
    solve()
```2 つの変数`low`そして`high`現在の可能な範囲を保存します。 これらは対話のたびに更新され、最終的な値は範囲が 1 つの数値に集約された後にのみ出力されます。 

クエリしきい値は整数である必要があるため、中間点の計算では整数の除算が使用されます。 アップデート`high = mid - 1`は否定的な答えの後に必要です。`mid`それ自体が不可能であることが証明されています。 アップデート`low = mid`肯定的な答えは次のことを意味するため、異なります。`mid`は依然として有効な候補です。 

の`flush=True`インタラクティブな問題では引数が必要です。 フラッシュしない場合、クエリはバッファされたままになり、ジャッジに到達しない可能性があり、正しいロジックがあるにもかかわらずプログラムが失敗する原因となります。

## テストケース

 インタラクティブなソリューションは、審査員が応答を制御するため、固定入力と出力でテストすることはできません。 ローカル テストでは、代わりに、隠れた数値をシミュレートすることによって、二分探索遷移ロジックを検証できます。```
def find_number(hidden):
    low = 1
    high = 10**6

    while low < high:
        mid = (low + high) // 2
        if hidden >= mid:
            low = mid
        else:
            high = mid - 1

    return low

assert find_number(1) == 1, "minimum value"
assert find_number(1000000) == 1000000, "maximum value"
assert find_number(500000) == 500000, "middle value"
assert find_number(999999) == 999999, "upper boundary"
assert find_number(123456) == 123456, "random value"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 最小値の場合、隠れた数値は次のとおりです。`1`。 しきい値を超えるすべてのクエリ`1`返品`0`、そのためアルゴリズムは減少し続けます`high`届くまで`1`。 区間不変条件により、結果が次のような状態になるのを防ぎます。`0`。 

最大値の場合、隠れた数値は次のとおりです。`1000000`。 すべての中間点クエリが返されます`1`、 それで`low`上向きに進み続けます。 最終的な間隔は次のようになります。`[1000000, 1000000]`、上位エンドポイントが正しく処理されていることを証明します。 

隠された数値が問い合わせの中点と正確に等しい場合、裁判官は答えます。`1`条件が「少なくとも」だからです。 アルゴリズムは維持します`mid`を代入して考えられる答えとして`low = mid`、正しい値を破棄するというよくある間違いを回避します。
