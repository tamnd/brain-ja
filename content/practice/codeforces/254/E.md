 ## 解決策
 ## 問題の理解

 ヴァシャさんは毎朝食べ物を受け取ります。 その日の食事`i`その日しか食べられない`i`または日`i + 1`。 毎日、ヴァシャ自身が正確に摂取する必要があります`v`キログラム。 それに加えて、一部の友人は一定の間隔で彼と一緒に滞在し、ヴァシャがその友人がいる日に友人に食事を与えることにした場合、彼はその友人の毎日の必要量を全額提供しなければなりません。 

給餌が成功するたびに、人気スコアが 1 ずつ増加します。 目標は、食品の有効期限ルールを尊重しながら、学期全体の総給餌回数を最大化することです。 

難しいのは、食べ物はちょうど2日間生き残ることです。 これにより、ローリング リソース制約が作成されます。 今日届いた食料はすぐに使われるか、明日のために保存されるかもしれませんが、明日以降は永久に消えてしまいます。 そのため、ある日の決断は翌日に直結します。 

制約は動的プログラミングには十分小さいですが、指数関数的なものには十分ではありません。 両方`n`そして`m`せいぜい`400`、それぞれの食事の量と友人の食欲も最大です`400`。 周囲の状態空間`400 * 400 * something`これは合理的ですが、毎日すべての友人のサブセットを試すのは不可能です。 1 日に何百ものアクティブな友人が含まれる可能性があるため、サブセットに対するブルート フォースは 1 日ですでに爆発的に増加します。 

単純な実装は、いくつかの点で暗黙的に失敗する可能性があります。 

危険な間違いの 1 つは、古い食品は 1 日余分に期限切れになることを忘れることです。 仮定する：```
2 1
1 100
0
```1日目に1キログラムが到着し、すぐに消費する必要があります。 3 日目は存在しないため、誰も 3 日目まで生き残ることはできません。期限切れを追跡する代わりに累積的な食料を保持する不用意な実装は、膨大な食べ残しが永遠に存在すると誤って考える可能性があります。 

もう 1 つの微妙な問題は、古い食品を優先する必要がある今日、新鮮な食品を使いすぎていることです。 考慮する：```
2 2
4 1
1
2 2 1
```1日目、Vasyaには2キログラムが必要で、2キロが余分に残ります。 この 2 つは保管して 2 日目に使用できます。2 日目の友人には 1 キログラムが必要なので、正解は次のとおりです。`1`。 生鮮食品を先に貪欲に消費すると、貯蔵可能な資源を無駄にしてしまい、友人に食事を与えることができないと結論付ける可能性があります。 

3 番目の簡単なバグは、どの友人に餌を与えたかを再構築するときに発生します。 複数の友人が同じ食欲を持ち、重複する間隔を持つことができます。 再構築で ID ではなくカウントのみが保存される場合、無効なフレンド インデックスの割り当てが出力される可能性があります。 

例えば：```
3 1
3 3 3
2
1 3 1
1 3 1
```最適な答えは`6`、毎日両方の友人に餌を与えています。 再構築では実際の友人インデックスを保存する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 毎日、どの友人が出席しているかを判断し、その一部をすべて試してみます。 その日に必要な食料の合計は次のようになります。```
v + sum(friend appetites in chosen subset)
```次に、食品の賞味期限規則でその選択が許可されているかどうかをシミュレーションします。 

すべての給餌決定は 1 日単位で行われ、有効期限は 1 日余分にかかるだけであるため、これは論理的に機能します。 問題はサブセットの数です。 たとえ 1 日に 20 人の友達がアクティブだったとしても、すでに 100 万を超える可能性があります。 友達が最大 400 人になると、検索スペースは完全に不可能になります。 

重要な観察は、1日に消費した余分な食物の合計のみが重要であり、どの友人がそれを生産したかは正確には重要ではないということです。 2 つの異なる友人のセットが同じ合計キログラムを必要とし、同じ人数が含まれている場合、食料システムの観点からはそれらは交換可能です。 

これにより、問題は 2 つの層に分かれます。 

最初の層は、日ごとのナップサック スタイルの前処理です。 その日に参加できるすべての友人の中で、可能な限りの追加の食べ物の量`x`、正確に使用してフィードできる友達の最大数を計算します。`x`キログラム。 

2 番目の層は、数日間および残り物の食料を対象とした動的プログラミングです。 食料は正確に 1 日存続するため、覚えておく必要がある唯一の状態は、昨日の食料が今日どれだけ残っているかということです。 

仮定する`carry`昨日からキログラムが生き残っています。 当日`i`、受け取ります`a[i]`新鮮なキログラム。 余分な消費を選択します`x`友人の場合、1 日の合計消費量は次のようになります。```
need = v + x
```昨日の残り物を使ってこれを満たさなければなりません。なぜなら、昨日の未使用のものは今日を過ぎると消えてしまうからです。 支払い後`need`、未使用の生鮮食品は明日まで生き残ることができます。 

これにより、クリーンなトランジション DP が作成されます。 

ブルート フォースは、個々の友人のサブセットについて直接推論するため、失敗します。 食品システムは消費された合計キログラムのみを考慮するのに対し、スコアはその合計を生産した友人の数のみを考慮するため、最適化されたソリューションは成功します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n · 2^m) | O(2^m) | 遅すぎる |
 | 最適 | O(n · 400² + n · 400²) | O(n · 400) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 毎日、その日が含まれる間隔にあるすべての友達を収集します。 
2. その日のナップザック DP を作成します。 

させて`best[d][x]`その日にフィードできる友達の最大数になります`d`正確に使用して`x`キログラムの追加の食料。 

最初に:```
best[d][0] = 0
```食欲旺盛でアクティブな友人たちへ`f`、0/1 ナップザック アップデートを実行します。 
3. メイン DP を作成します。 

させて：```
dp[day][carry]
```終了後に達成可能な最大の人気であること`day - 1`、 と`carry`キログラムの生鮮食品が生き残る`day`。 
4. 以下から始めます:```
dp[1][0] = 0
```1日目までは食べ残しはありません。 
5. 毎日処理します。 

私たちが州にいると仮定してください`(day, carry)`。 

今日入手可能な食料の合計は次のとおりです。```
carry + a[day]
```6. 可能な限り追加の食事量を試す`x`そのような`best[day][x]`有効です。 

今日の総消費量は次のようになります。```
need = v + x
```もし`need > carry + a[day]`、この選択は不可能です。 
7. 古い食べ物を最初に食べる。 

私たちは以下を使用します:```
used_old = min(carry, need)
```そして残りの需要は生鮮食品から取り出されます。 
8. 明日まで生き残る生鮮食品の残りを計算します。 

今日使用される生鮮食品:```
used_new = need - used_old
```新鮮な残り物:```
next_carry = a[day] - used_new
```9. トランジションをリラックスします。```
dp[day + 1][next_carry]
```次の方法で改善される可能性があります。```
dp[day][carry] + best[day][x]
```10. 再構築のために親ポインタを保存します。 

前回のキャリー状態と追加金額の両方を覚えておく必要があります`x`が選ばれました。 
11. 丸一日処理した後、最適な最終キャリー状態を選択します。 
12. 選択したものを再構築する`x`毎日の価値を。 
13. 毎日のナップザックの再構築を再実行して、どの友達がその総食欲を生み出しているかを正確に判断します`x`。 

### なぜ効果があるのか

 重要な不変条件は、DP 州が 1 日の処理後、明日使用できる量の生鮮食料品を正確に保管していることです。 古い食品は 1 回の移行より長く生き残ることはありません。 

昨日の食品は今日の直後に期限切れになりますが、未使用の新鮮な食品は明日も役立つ可能性があるため、古い食品を最初に使用するのが常に最適です。 新鮮な食品を消費しながら古い食品を無駄にする解決策は、それらの消費を交換することによって、同等以上の優れた解決策に変えることができます。 

食事システムは友達が消費した合計キログラムにのみ依存するため、毎日のナップザックは正しいです。 達成可能な追加の食欲の合計ごとに、その合計を与える友人の最大数がナップザックに保存されます。これはまさに人気の目的が求めるものです。 

これら 2 つの事実により、最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = -10**9

def solve():
    n, v = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    m = int(input())

    friends = [None]
    active = [[] for _ in range(n + 1)]

    for idx in range(1, m + 1):
        l, r, f = map(int, input().split())
        friends.append((l, r, f))

        for day in range(l, r + 1):
            active[day].append((idx, f))

    MAXF = 400 * 400

    # best[day][x] = max friends count using exactly x food
    best = [[INF] * (MAXF + 1) for _ in range(n + 1)]

    # reconstruction for daily knapsack
    take = []

    for day in range(1, n + 1):
        dp = [INF] * (MAXF + 1)
        dp[0] = 0

        parent = [[False] * (MAXF + 1) for _ in range(len(active[day]) + 1)]

        for i, (_, f) in enumerate(active[day], start=1):
            ndp = dp[:]

            for s in range(MAXF - f + 1):
                if dp[s] == INF:
                    continue

                if dp[s] + 1 > ndp[s + f]:
                    ndp[s + f] = dp[s] + 1
                    parent[i][s + f] = True

            dp = ndp

        best[day] = dp
        take.append(parent)

    max_carry = 400

    dp = [[INF] * (max_carry + 1) for _ in range(n + 2)]
    prev_carry = [[-1] * (max_carry + 1) for _ in range(n + 2)]
    chosen_sum = [[-1] * (max_carry + 1) for _ in range(n + 2)]

    dp[1][0] = 0

    for day in range(1, n + 1):
        for carry in range(max_carry + 1):
            if dp[day][carry] == INF:
                continue

            total = carry + a[day]

            for extra in range(MAXF + 1):
                cnt = best[day][extra]

                if cnt < 0:
                    continue

                need = v + extra

                if need > total:
                    continue

                used_old = min(carry, need)
                used_new = need - used_old

                nxt = a[day] - used_new

                if nxt < 0 or nxt > max_carry:
                    continue

                val = dp[day][carry] + cnt

                if val > dp[day + 1][nxt]:
                    dp[day + 1][nxt] = val
                    prev_carry[day + 1][nxt] = carry
                    chosen_sum[day + 1][nxt] = extra

    ans = max(dp[n + 1])
    end_carry = dp[n + 1].index(ans)

    extras = [0] * (n + 1)

    cur = end_carry

    for day in range(n + 1, 1, -1):
        extras[day - 1] = chosen_sum[day][cur]
        cur = prev_carry[day][cur]

    result = [[] for _ in range(n + 1)]

    for day in range(1, n + 1):
        target = extras[day]

        parent = take[day - 1]
        people = active[day]

        s = target

        for i in range(len(people), 0, -1):
            idx, f = people[i - 1]

            if s >= f and parent[i][s]:
                result[day].append(idx)
                s -= f

        result[day].reverse()

    print(ans)

    for day in range(1, n + 1):
        arr = result[day]
        print(len(arr), *arr)

solve()
```このソリューションには 2 つの異なる DP レイヤーがあります。 

最初の層は毎日独立して処理します。 現在存在するすべての友人の中で、正確な食欲の合計ごとに達成可能な最高の人気を計算します。 重さが食欲をそそり、お値打ち感が人気のポイントの定番0/1ナップサックです。 

2 番目の層は食品の有効期限を処理します。 州では、古いものはすでに期限切れになっているため、昨日の残りの生鮮食品のみを保管しています。 これにより、状態空間が小さく保たれます。 

実装の微妙な詳細の 1 つは、残り物の移行ルールです。 私たちはいつも新鮮な食べ物の前に古い食べ物を食べます。 この順序が逆の場合、DP は期限切れの食品を誤って保存し、不可能な状態を引き起こす可能性があります。 

もう 1 つの重要な詳細は、キャリー バウンドです。 それぞれなので`a[i] ≤ 400`、明日の残り物は決して超えることはできません`400`。 これにより、DP テーブルが大幅に縮小されます。 

毎日の友人選択の再構成では、日ごとに別の親行列が使用されます。 複数のサブセットが同じ食欲合計を生成する可能性があるため、カウントのみを保存するだけでは不十分です。

import sys, io

def solve():
    input = sys.stdin.readline

    INF = -10**9

    n, v = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    m = int(input())

    friends = [None]
    active = [[] for _ in range(n + 1)]

    for idx in range(1, m + 1):
        l, r, f = map(int, input().split())
        friends.append((l, r, f))

        for day in range(l, r + 1):
            active[day].append((idx, f))

    MAXF = 400 * 400

    best = [[INF] * (MAXF + 1) for _ in range(n + 1)]

    for day in range(1, n + 1):
        dp = [INF] * (MAXF + 1)
        dp[0] = 0

        for _, f in active[day]:
            ndp = dp[:]

            for s in range(MAXF - f + 1):
                if dp[s] == INF:
                    continue

                ndp[s + f] = max(ndp[s + f], dp[s] + 1)

            dp = ndp

        best[day] = dp

    max_carry = 400

    dp = [[INF] * (max_carry + 1) for _ in range(n + 2)]

    dp[1][0] = 0

    for day in range(1, n + 1):
        for carry in range(max_carry + 1):
            if dp[day][carry] == INF:
                continue

            total = carry + a[day]

            for extra in range(MAXF + 1):
                if best[day][extra] < 0:
                    continue

                need = v + extra

                if need > total:
                    continue

                used_old = min(carry, need)
                used_new = need - used_old

                nxt = a[day] - used_new

                dp[day + 1][nxt] = max(
                    dp[day + 1][nxt],
                    dp[day][carry] + best[day][extra]

2日目には、利用可能な食料は次のとおりです`2 + 1 = 3`。 友人は 1 キロ必要なので、合計必要量は次のようになります。`3`。 このアルゴリズムは、最初に古い 2 キログラムを消費し、次に新しい 1 キログラムを消費します。 その後食べ物は残りません。 

移行時に最初に生鮮食品が使用された場合、古い食品は使用されずに期限切れになり、DP は誤って実行可能な給餌を失うことになります。

入力：```

2

1 3 1
```毎日3キログラムが利用可能です。 Vasya 自身には 1 キロの体重が必要で、毎日両方の友人のためにスペースを残しています。

```再構成行列には、どの正確なフレンド インデックスがその合計を作成したかが格納されます。 バックトラッキング中に、両方のインデックスが適切に回復されます。 この再構成データがないと、アルゴリズムが重複したインデックスを出力したり、1 つの友人を完全に省略したりする可能性があります。 

最後に、食品の賞味期限について考えてみましょう。 

入力：```
3 1
10 1 1
0
```1日目以降、生き残れるのは最大でも9kgです。 これら 9 つは 2 日目にのみ使用できます。3 日目までに、1 日目のすべてが永久に失われます。 

DP 状態は 1 日分のキャリーのみを保存するため、不可能な長期保存は発生しません。
