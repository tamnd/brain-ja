 ## 解決策
 ## 問題の理解

 同じ長さの大文字の文字列が 2 つあります。 最初の文字列の文字を置換することができ、すべての置換後の最後の文字列は 2 番目の文字列のアナグラムになるだけで済みます。 複数の文字セットの順序は重要ではありませんが、最小数の置換を使用したすべての有効な回答の中で、辞書編集的に最小の結果文字列を出力する必要があります。 

重要な点は、私たちは変革しようとしているわけではないということです`s`の中へ`t`ポジションごとに。 最終的な文字の頻度が次の文字の頻度と一致することだけを考慮します。`t`。 

仮定する`t`3つ含まれています`A`と２つ`B`s. したがって、最後の文字列にもちょうど 3 つが含まれている必要があります。`A`と２つ`B`どこに表示されるかに関係なく。 

届く長さは`10^5`、二次関数は即座に除外されます。 効率的な簿記がなければ、文字列を繰り返し再構築したり、大きなプレフィックスを何度も並べ替えたり、すべての置換の選択肢を貪欲に試したりすることはできません。 アルファベットには大文字が 26 文字しか含まれていないため、頻度のカウントは非常に魅力的になります。 アン`O(n * 26)`ソリューションはまったく問題ありませんが、`O(n^2)`すでにそこら中にあるだろう`10^10`最悪の場合の運用。 

辞書編集上の最小要件によって、いくつかの微妙なケースが発生します。 

考慮する：```
s = BAA
t = AAC
```最小置換数は次のとおりです。`1`。 交換しなければなりません`B`と`C`、与える`CAA`。 あらゆる位置に可能な限り小さな文字を貪欲に配置する不用意な戦略は、最初の文字を変更しようとする可能性があります。`B`の中へ`A`、しかしそれでは多すぎるでしょう`A`後でも別の交換が必要です。 

もう 1 つの注意が必要なケースは、文字がすでに過剰に出現しているが、一部の出現を置き換えるのを遅らせる必要がある場合です。 

例：```
s = CBA
t = ABB
```周波数が必要です`{A:1, B:2}`。 正しい答えは次のとおりです。```
ABB
```今後の位置を確認せずに最初の特大文字を貪欲にすぐに置き換えると、先頭を維持する可能性があります。`C`代わりに後の文字を変更して、辞書編集的により大きなものを作成します。 

もう 1 つの微妙な状況は、文字が現在過剰である場合に発生しますが、初期の文字を保持することは、後の位置への置換を保存するよりも辞書編集上の順序を維持するのに役立ちます。 

例：```
s = BBAA
t = AACC
```二人の交代要員が必要だ。 最良の答えは次のとおりです。```
AACC
```単純な「強制された場合のみ置換」実装では、誤って最初の部分が保持される可能性があります。`B`、その後、追加のものを導入する必要があることが後でわかります`A`とにかく、辞書編集的により大きな答えが得られます。 

最も難しいのは、次の 2 つの目標を同時に両立させることです。 

まず、可能な限り最小限の置換数を使用します。 

第 2 に、そのようなすべての解決策の中で、最も早いポジションをできるだけ小さくします。 

## アプローチ

 この問題を考える強引な方法は、次のすべてのアナグラムを生成することです。`t`、次に、どれだけの位置が異なるかを確認します。`s`。 異なるポジションの数は、必要な置換の数と同じです。 最小距離を持つすべてのアナグラムの中で、辞書編集的に最小のものを選択します。 

これは正しいです。有効な最終文字列はすべて、次のアナグラムでなければならないからです。`t`。 問題はそれです`t`まで持つことができます`10^5`文字。 長さに関しても`20`、異なる順列の数はすでに膨大です。 完全な列挙は絶望的です。 

より実用的な総当り攻撃の変形では、周波数の有効性を維持しながら、あらゆる位置であらゆる可能な置換を貪欲に試みます。 各インデックスについて、26 文字すべてをテストし、残りの接尾辞がターゲット頻度を満たしているかどうかを確認できます。 これは、単純に実装すると、特に周波数の再計算を繰り返す場合にはコストが高くなります。 

重要な観察は、置換の最小数は完全に周波数の重複によって決定されるということです。 

もし`s`すでに5つ入っています`A`と`t`3つ必要です`A`s、その後少なくとも 2 つ`A`は消えなければなりません。 もし`s`1つ含まれています`C`そして`t`4つ必要です`C`s、その後、3 つの新しいものを作成する必要があります`C`どこかにある。 

したがって、問題は次のようになります。 

どの文字が過剰でどの文字が欠落しているかが正確にわかります。 辞書編集上最小の文字列を取得するには、どのように再配布すればよいでしょうか?

 これは貪欲な左から右への戦略につながります。 

各位置で:

 現在のキャラクターがまだ必要な場合は、それを保持しておくこともできます。 

しかし、それをより小さい欠落文字に置き換えることで辞書編集上の順序が改善される場合は、すぐにそうすべきです。 

現在の文字が過剰で、さらに小さな欠落文字が存在する場合は、前の位置が辞書編集順序を支配するため、今すぐ変更することが常に有益です。 

大きな欠落文字のみが残っている場合は、現在の文字を小さくしておくとプレフィックスを最小限に抑えることができるため、可能な限り置換を遅らせることをお勧めします。 

小さなアルファベットサイズなので簿記が簡単です。 各文字のコピーがまだ必要な数と、文字列の後半に残るコピーの数を維持します。

 ## アルゴリズムのチュートリアル

 1. のすべての文字の頻度を数えます。`t`。 

これらの数は、最終的な文字列に何を含める必要があるかを正確に表します。 
2. のすべての文字の頻度を数えます。`s`。 

2 つの頻度配列を比較すると、どの文字が過剰でどの文字が欠落しているかがわかります。 
3. 文字列を左から右にトラバースします。 

辞書編集上の順序は最初に前の位置に依存するため、各位置の最終値を貪欲に決定します。 
4. 現在のキャラクターの場合`c`、まずサフィックス内の残りのカウントを減らします。 

これにより、次のコピーの数がわかります。`c`この発生を変更しないことを選択した場合でも、後でまだ存在します。 
5. かどうかを確認します。`c`過剰です。 

現在の合計数が`c`すでに必要な大きさを超えていないため、この文字を保持する必要があります。 置き換えても、不必要な余分な操作が発生するだけです。 
6. もし`c`多すぎるため、欠落している最小の文字を検索します`x`。 

からの手紙を試してみます`'A'`辞書編集的に最小の結果が必要なため、上向きになります。 
7. もし`x < c`、すぐに交換してください。 

前の位置にある小さな文字は常に答えを改善します。 
8. もし`x > c`安全に保管できない場合にのみ交換してください`c`。 

具体的には、将来のコピーが残っている場合、`c`必要な量より少ない場合、この現象は継続する必要があります。 それ以外の場合は、交換を後で延期することができます。 
9. 交換が行われるたびに、両方の周波数配列を更新します。 

過剰な文字は 1 出現を失い、欠落した文字は 1 出現を増やします。 
10. すべての位置が処理されるまで続行します。 

### なぜ効果があるのか

 アルゴリズムは単純な不変条件を維持します。 

各位置を処理する前に、現在の頻度配列は部分的に変更された文字列にまだ存在する文字を表します。 

文字を置換するときは常に、過剰な文字から不足している文字に 1 単位を移動するため、最小置換数は維持されます。 

辞書編集上の最適性は、左から右への貪欲な選択から生まれます。 より小さい欠落文字を現在の位置に配置できる場合、辞書編集上の比較は最も古い異なる位置に依存するため、その改善を遅らせても役に立ちません。 逆に、大きな置換文字のみが存在する場合は、可能な限り現在の小さな文字を維持し、避けられない増加を後の位置に延期します。 

すべての決定は局所的に最適であり、将来の実現可能性を決して損なうことがないため、最終的な文字列はすべての最小置換ソリューションの中で辞書順に最小になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = list(input().strip())
    t = input().strip()

    need = [0] * 26
    cur = [0] * 26

    for ch in t:
        need[ord(ch) - 65] += 1

    for ch in s:
        cur[ord(ch) - 65] += 1

    changes = 0

    for i in range(len(s)):
        c = ord(s[i]) - 65

        # this character is not excessive
        if cur[c] <= need[c]:
            continue

        for x in range(26):
            if cur[x] < need[x]:
                # smaller character, always beneficial
                if x < c:
                    cur[c] -= 1
                    cur[x] += 1
                    s[i] = chr(x + 65)
                    changes += 1
                    break

                # larger character
                # replace only if enough copies remain later
                elif x > c:
                    if cur[c] - 1 >= need[c]:
                        cur[c] -= 1
                        cur[x] += 1
                        s[i] = chr(x + 65)
                        changes += 1
                    break

    print(changes)
    print("".join(s))

solve()
```2 つの周波数アレイがソリューションのバックボーン全体です。`need`最終的な文字列に各文字が何部出現する必要があるかを格納します。`cur`進化する答えに現在存在するコピーの数を保存します。 

トラバースは貪欲かつ永続的です。 一度あるポジションを通過すると、そのポジションを再び訪れることはありません。 辞書編集上の順序では、後の位置よりも前の位置が完全に優先されるため、これは安全です。 

条件:```
if cur[c] <= need[c]:
```は非常に重要です。 それは、このキャラクターが過剰ではなくなったことを意味します。 これを置き換えると、同じキャラクターを別の場所で再作成する必要があり、操作数が不必要に増加します。 

2 番目の微妙な部分は次のとおりです。```
if cur[c] - 1 >= need[c]:
```これにより、現在の出現を安全に破棄し、後でこの文字の十分なコピーを保持できるかどうかがチェックされます。 この条件が欠けていると、あまりにも多くのレターのコピーが早すぎて削除される可能性があるため、多くの誤った答えが発生します。 

アルファベットのサイズが一定であるため、26 文字すべてのループは低コストです。 たとえ`10^5`キャラクター、総作業量はそのまま`2.6 * 10^6`操作。
