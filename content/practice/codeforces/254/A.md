 ## 解決策
 ## 問題の理解

 私たちは持っています`2n`順番に並べられたカード。 すべてのカードには整数が書かれており、各カードには次のインデックスもあります。`1`に`2n`。 タスクは、すべてのカードを正確に分割することです。`n`すべてのペア内の両方のカードに同じ数字が含まれるようにペアを作成します。 

出力では値自体は要求されません。 有効なペアを形成するカードのインデックスを要求します。 1 つの値でも奇数回出現すると、完全なペアを形成することが不可能になり、出力する必要があります。`-1`。 

制約は、解が線形時間に近いものでなければならないことをすぐに示します。 まであります`6 * 10^5`合計でカードが 2 つあるため、二次関数は爆発します。 残りのカードを繰り返しスキャンする単純なペア検索アプローチでは、次のようなパフォーマンスが得られます。`(2n)^2`最悪の場合の比較は、1 秒の制限には大きすぎます。 一方、頻度による値のハッシュ化またはグループ化は、各カードを一定の回数だけ処理するだけで済むため、簡単に適合します。 

不注意な実装を黙って破壊してしまう可能性のあるエッジケースがいくつかあります。 

次の入力を考えてみましょう。```
2
1 2 1 2
```正しい答えは次のとおりです。```
1 3
2 4
```バグのある実装では、特に値のみを追跡し、どの特定の出現が消費されたかを追跡しない場合、インデックスを一度ペアにした後に誤って再利用してしまう可能性があります。 

もう 1 つの重要なケースは、値が奇数回出現する場合です。```
2
5 5 5 7
```値`5`は 3 回表示されるため、1 つのコピーは常に一致しないままになります。 正しい出力は次のとおりです。```
-1
```不用意に貪欲な解決策を講じると、2 つの問題がペアになる可能性があります`5`すべての出現が消費されたことを確認するのを忘れます。 

すべてのカードに同じ数字が含まれる場合もあります。```
3
9 9 9 9 9 9
```すべてのインデックスは、出力内に 1 回だけ出現する必要があります。 有効なペアリングは任意ですが、実装では位置のスキップや重複を避ける必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 ペアになっていないカードごとに、同じ値を持つ別のカードが見つかるまで残りのカードをスキャンします。 見つかったら、両方を使用済みとしてマークし、続行します。 

これが機能するのは、有効なソリューションでは同じ値をグループ化するだけでよいためです。 問題は効率です。 最悪の場合、すべての検索で残りの配列のほぼ全体がスキャンされる可能性があります。 まで`6 * 10^5`カードの場合、比較の数はおよそに達する可能性があります`3.6 * 10^11`、それは完全に不可能です。 

重要な観察は、カードを値別にグループ化した後でのみ実際の位置が重要になるということです。 特定の数値が出現するすべてのインデックスがわかっていれば、ペアを形成するのは簡単になります。 これらのインデックスを一度に 2 つずつ取得するだけです。 

これにより、問題は繰り返しの検索からグループ化の問題に変わります。 配列を 1 回走査し、すべてのインデックスをその値に対応するバケット内に格納し、すべてのバケットのサイズが均一であることを確認します。 バケットサイズが奇数の場合はペアリングできません。 それ以外の場合、バケット内の連続するインデックスは有効なペアを自動的に形成します。 

値は最大でも`5000`したがって、ベクトルの配列でも機能しますが、ハッシュ マップも同様にクリーンで一般的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして配列`2n`カードの価値。 
2. 各キーがカード値であり、関連するリストにその値が表示されるすべてのインデックスを格納するディクショナリを作成します。 
3. 配列を左から右に走査します。 
4. ポジションごとに`i`、インデックスを追加`i + 1`値に対応するリストに`a[i]`。 

保管します`i + 1`この問題では 1 から始まるインデックスが使用されているためです。 
5. すべてのインデックスをグループ化した後、すべての値グループを繰り返し処理します。 
6. いずれかのグループのサイズが奇数の場合は、次のように出力します。`-1`そしてすぐに終了します。 

奇数のカードは、あるカードが別の同じカードと一致することがないことを意味します。 
7. それ以外の場合は、グループのインデックスを一度に 2 つずつ処理します。 
8. 印刷`(indices[0], indices[1])`、 それから`(indices[2], indices[3])`、 等々。 

グループ内のすべてのインデックスは同じ値に属しているため、生成されたすべてのペアは有効です。 

### なぜ効果があるのか

 このアルゴリズムは単純な不変条件を維持します。つまり、保存されているすべてのリストには、同じ値を持つカードのインデックスが正確に含まれています。 

値が奇数回出現する場合、少なくとも 1 枚のカードがすべての可能な配置で一致しないままになるため、有効な解決策は存在しません。 

値が偶数回発生する場合、すべてのペアに同一の値が含まれており、インデックスは再利用されないため、そのグループ内の連続するインデックスのペアは常に機能します。 グループは配列のすべてのインデックスを分割するため、すべてのカードは正確に 1 つの印刷ペアとして表示されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pos = defaultdict(list)

    for i, x in enumerate(a, start=1):
        pos[x].append(i)

    ans = []

    for indices in pos.values():
        if len(indices) % 2 == 1:
            print(-1)
            return

        for i in range(0, len(indices), 2):
            ans.append((indices[i], indices[i + 1]))

    print("\n".join(f"{x} {y}" for x, y in ans))

solve()
```辞書`pos`ソリューションの中核となる構造です。 各値は、それが表示されるすべてのインデックスにマップされます。 左から右にスキャンしながらインデックスを追加するため、すべての出現が 1 回だけ記録されます。 

の`enumerate(..., start=1)`この問題では次から始まるインデックスが必要となるため、この呼び出しは重要です。`1`。 これを忘れることは、最もよくある間違いの 1 つです。 

パリティ チェックはペアを作成する前に行われます。 グループのサイズが奇数になると、インスタンス全体を処理することは不可能になるため、処理を続行する理由がありません。 

ペアリング ループは次のように進みます。`2`各反復。 これにより、すべてのインデックスが 1 回だけ使用されることが保証され、ペア間の偶発的な重複が防止されます。 

この解決策は並べ替えに依存しません。 インデックスの元の順序は、すでに十分な構造を提供しています。

import sys
import io
from collections import defaultdict

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    pos = defaultdict(list)

    for i, x in enumerate(a, start=1):
        pos[x].append(i)

    ans = []

    for indices in pos.values():
        if len(indices) % 2 == 1:
            print(-1)
            return

        for i in range(0, len(indices), 2):
            ans.append((indices[i], indices[i + 1]))

    print("\n".join(f"{x} {y}" for x, y in ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

pairs = set(tuple(map(int, line.split())) for line in out.splitlines())

assert len(pairs) == 3

# minimum size valid

# impossible because of odd frequency
assert run("2\n5 5 5 7\n") == "-1"

# all equal values
out = run("3\n9 9 9 9 9 9\n")
pairs = [tuple(map(int, line.split())) for line in out.splitlines()]
used = set()

for x, y in pairs:
    used.add(x)
    used.add(y)

assert len(pairs) == 3
assert used == {1, 2, 3, 4, 5, 6}

# alternating values

pairs = [tuple(map(int, line.split())) for line in out.splitlines()]

    used.add(y)

 ## 特殊なケース

 次の入力を考えてみましょう。```
2
1 2 1 2
```グループは次のようになります。```
1 -> [1, 3]
2 -> [2, 4]
```このアルゴリズムは、各グループ内の連続するインデックスをペアにして、以下を生成します。```
1 3
2 4
```元の配列では同じ値が分離されていますが、値でグループ化すると、位置の複雑さが完全に排除されます。 

ここで次のことを考えてみましょう。```
2

```保存されているグループは次のとおりです。```

```検証中に、アルゴリズムは両方のグループのサイズが奇数であることを検出します。 その瞬間、すぐに印刷されます`-1`。 部分的なペアリングは試行されないため、アルゴリズムが無効な不完全な応答を生成することはありません。 

最後に、すべてが等しい場合を考えてみましょう。```

```単一のグループは次のようになります。```

```ペアリング ループはインデックスを 2 つのステップで処理します。```

(3, 4)
(5, 6)
```すべてのインデックスが 1 回だけ使用されるため、アルゴリズムが大規模な重複グループを正しく処理することが確認されます。
