 ## 解決策
 ## 問題の理解

 各オリンピックは 2013 年の固定暦日に開催されます。その日までに、審査員のグループは数日間継続的に仕事をしなければなりません。 オリンピックに必要な場合`p`人々と`t`準備日、そしてまさに`p`人々はそれぞれのことに忙しい`t`オリンピック直前の数日。 

同じ人が同じ日に 2 つの異なるオリンピックを準備することはできません。 あらゆる準備スケジュールを同時に実行できるように、審査員の総数は最小限にする必要があります。 

問題全体は 1 つの質問に集約されます。 

暦日ごとに、同時に何人の人が必要ですか?

 答えは、これらの 1 日の必要量の最大値です。 

制約は非常に小さいです。 オリンピックは最大でも 100 回あり、各準備期間は最大でも 100 日です。 たとえすべての準備日を明示的にシミュレーションしたとしても、総作業量は約`100 * 100 = 10,000`小さな操作です。 

主な問題はパフォーマンスではなく、日付を正しく処理することです。 

いくつかの特殊なケースでは、オフバイワンの間違いが簡単に発生します。 

オリンピックが 3 月 10 日に開催され、準備に 3 日かかるとします。 この作業は 3 月 7 日、3 月 8 日、3 月 9 日に行われます。3 月 10 日自体は含まれません。 不用意に実装すると、誤ってオリンピックの日もカウントされる可能性があります。 

例：```
1
3 10 5 3
```正解:```
5
```占有日は3月7日～3月9日のみです。 

もう 1 つの注意が必要なケースは、2012 年に向けて準備が完了することです。 

例:```
1
1 3 4 5
```準備日は 12 月 29 日から 1 月 2 日です。2013 年内の日だけを保存すると、間隔の一部が失われます。 

正解:```
4
```複数のオリンピックが同じ日に開催されることもあり、その準備期間が完全に重なる場合もあります。 

例：```
2
5 20 3 2
5 20 4 2
```どちらも5月18日と5月19日に作業が必要となる。 

正解:```
7
```毎日の負荷を蓄積せずにイベントを独立して処理するバグのあるソリューションは、ここで失敗します。 

## アプローチ

 最も直接的なアイデアは、すべてのオリンピックの準備日をシミュレーションすることです。 

オリンピックごとに、審査員が勤務する正確な曜日を決定します。 次に追加します`p[i]`日々の仕事量に合わせて。 すべてのオリンピックを処理した後、丸一日スキャンして最大限のワークロードを取得します。 

これが機能するのは、陪審の対立が 1 日のうちの完全にローカルなものであるためです。 ある日同時に 12 人が必要な場合、少なくとも 12 人の陪審員が存在する必要があります。 逆に、最大同時要件が 12 人の場合、同じ 12 人を別の日に再利用できます。 

単純な実装では、日付を次のように表すことができます。`(month, day)`をペアにして、カレンダー ロジックを使用して 1 日ずつ繰り返し逆方向に移動します。 シミュレートされる合計日数が少ないため、ここではすでに十分に高速です。 

さらにクリーンなアプローチがあります。 すべての日付を単一の整数の日インデックスに変換します。 たとえば、1 月 1 日は 1 日目、2 月 1 日は 32 日目、というようになります。 日付が整数になると、すべての準備間隔は単なる数直線上の連続したセグメントになります。 

次に、毎日何人の陪審員が忙しいかを格納する配列が必要になるだけです。 

オリンピック開催日に向けて`D`準備長さあり`t`、占有間隔は次のとおりです。```
[D - t, D - 1]
```追加します`p`その合間の毎日に。 

カレンダーには 365 日しかなく、準備が前年まで約 100 日及ぶ可能性があるため、反復による直接範囲更新さえも簡単です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 手動日付ステップによるブルートフォース | O(n・t) | お(365) | 承認済み |
 | 日インデックス変換で最適 | O(n・t) | O(500) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2013 年の各月の日数を含む配列を作成します。 
2. カレンダーの日付を変換するヘルパー関数を構築する`(month, day)`年間の日数に変換します。 

例えば：```
Jan 1  -> 1
Feb 1  -> 32
Mar 1  -> 60
```3. 配列を作成する`cnt`1 月 1 日より前の数日間のワークロードを保存するのに十分な大きさです。 

負の日インデックスが表示されないようにオフセットを使用します。 
4. 各オリンピックについて:

 日付を整数に変換します`D`。 
5. 準備間隔は次のとおりです。`D - t`に`D - 1`。 

まさにオリンピックの前日です。 
6. その間隔内の毎日について、次を追加します。`p`に`cnt[day]`。 

これはつまり`p`陪審員はどの日も忙しい。 
7. すべてのオリンピックを処理した後、配列をスキャンして最大値を見つけます。 
8. その最大値を出力します。 

### なぜ効果があるのか

 毎日のために、`cnt[d]`その日に同時に必要とされる陪審員の総数に等しい。 

有効なスケジュールには少なくとも次の内容が含まれている必要があります。`cnt[d]`毎日の人`d`、それらの準備は時間的に重複しており、人々を共有することができないためです。 

1日の最大必要量が`M`、 それから`M`人も十分です。 毎日のすべてのアクティブなタスクに個別の担当者を割り当てるだけで、別の日にそれらを自由に再利用できます。 

したがって、陪審員の可能な最小人数は、まさに 1 日の最大作業負荷となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MONTHS = [31, 28, 31, 30, 31, 30,
          31, 31, 30, 31, 30, 31]

def day_number(month, day):
    total = 0
    for i in range(month - 1):
        total += MONTHS[i]
    return total + day

def solve():
    n = int(input())

    OFFSET = 200
    cnt = [0] * 1000

    for _ in range(n):
        m, d, p, t = map(int, input().split())

        D = day_number(m, d)

        start = D - t
        end = D - 1

        for day in range(start, end + 1):
            cnt[day + OFFSET] += p

    print(max(cnt))

solve()
```ヘルパー関数は、日付を連続した日の数値に変換します。 これにより、メイン ロジックからすべてのカレンダーの複雑さが削除されます。 

準備が 1 月 1 日より前に開始される可能性があるため、配列ではオフセットが使用されます。たとえば、1 月 3 日は次のようになります。`t = 5`日数が必要です`-2, -1, 0, 1, 2`年の番号付けと相対的に。 Python リストでは、ここで希望するような負の論理インデックスは許可されないため、すべてを定数オフセットでシフトします。 

間隔の境界は、実装の中で最もデリケートな部分です。 

オリンピックが当日に開催される場合`D`、準備は以下を占めます：```
[D - t, D - 1]
```当日`D`それ自体を含めてはいけません。 

ループ:```
for day in range(start, end + 1):
```準備期間の両端が正しく含まれています。 

配列のサイズは意図的に必要以上に大きくなっています。 最大日数は 365 で、準備の長さは最大 100 であるため、サイズ 1000 の配列は十分に安全です。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

MONTHS = [31, 28, 31, 30, 31, 30,
          31, 31, 30, 31, 30, 31]

def solve_io(inp: str) -> str:
    input = io.StringIO(inp).readline

    def day_number(month, day):
        total = 0
        for i in range(month - 1):
            total += MONTHS[i]
        return total + day

    n = int(input())

    OFFSET = 200
    cnt = [0] * 1000

    for _ in range(n):
        m, d, p, t = map(int, input().split())

        D = day_number(m, d)

        for day in range(D - t, D):
            cnt[day + OFFSET] += p

    return str(max(cnt))

def run(inp: str) -> str:
    return solve_io(inp).strip()

# provided sample

5 23 1 2
3 13 2 3
"""

"""

# crossing into previous year

"""
