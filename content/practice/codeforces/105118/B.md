 ## 解決策
 ## 問題の理解

 私たちには二種類の言葉が与えられています。 1 つのグループには短い単語が含まれており、すべて同じ長さです`a`、そして、あります`n`このタイプの独特の単語。 もう 1 つのグループには、すべて同じ長さの長い単語が含まれています。`b`、そして、あります`m`このタイプの異なる単語、`a < b`。 

オリヤは、これらの単語のいくつかを選択して詩を作成したいと考えています。 選択された各単語は、その全長が詩の全長に影響します。 彼女は各単語を最大 1 回使用することができます。 シーケンスは単語の種類ごとに交互にする必要があります。つまり、2 つの短い単語または 2 つの長い単語が最終的なシーケンスで隣接することはできません。 選択した単語の合計の長さは少なくとも`k`。 

短い単語を含めるたびに、彼女は次の時間を費やす必要があります`c`意味を学ぶのに必要な時間単位と、長い単語ごとにコストがかかります`d`時間単位。 目標は、単語の学習に費やす合計時間を最小限に抑えながら、合計の長さが少なくとも`k`、利用可能な単語の供給量を超えることなく。 

重要な難しさは、詩が単なる複数の集合の選択問題ではないということです。 交互制約は、各タイプの単語を一緒に使用できる数を制限します。 単語はコストと数の制限を除いて各タイプ内で同一であるため、問題は短い単語と長い単語の数を選択し、それらを交互のシーケンスに配置することに帰着します。 

制約は非常に大きく、最大で`10^18`言葉。 これにより、カウントを超える直接的な動的プログラミングや総当たり列挙が排除されます。 正しい解決策は、最適な交互パターンに関する構造観察に依存する必要があります。 

単純な間違いは、任意のカウントを自由に選択できると想定することです`x`そして`y`そのような`a*x + b*y >= k`。 たとえば、次のような場合には、長い単語だけを選択するのが最適であると思われるかもしれません。`d`小さいですが、もし`m`には制限があるため、短い単語を含めることを余儀なくされる場合があり、交互に詰めることができる数が制限される場合があります。 

もう 1 つの微妙な失敗例は、交互シーケンスには 2 つの可能な開始パターンがあることを忘れていることです。 短い単語が豊富にある場合、最適なシーケンスは短い単語から始まる可能性があります。 それ以外の場合は、long から始まる可能性があります。 これらのパターンのいずれかを無視すると、最適な答えを逃す可能性があります。 

最後に、1 つの型がはるかに高価な場合、欲張りな選択により安価な型のみが選択される可能性がありますが、長さの効率が原因で失敗する可能性があります。長い単語では、選択ごとにより多くの文字が提供され、到達するために必要な総数が減少する可能性があります。`k`。 

## アプローチ

 構造を無視する場合、強引なアイデアは、短い単語の可能な数をすべて試してみることです。`x`から`0..n`そして長い言葉`y`から`0..m`、それらを交互に配置できるかどうかを確認します。`a*x + b*y >= k`、コストを計算します`c*x + d*y`。 実現可能性とコストを明示的にテストしているため、これは正しいです。 ただし、それは両方とも不可能であるため、`n`そして`m`まで可能です`10^18`したがって、すべての可能性を反復しても、実行可能な限界をはるかに超えています。 

重要な簡素化は、「交互」が実際に何を制限するのかを理解することから生まれます。 有効なシーケンスは、各タイプのカウントによって完全に決定され、唯一の制約は、カウントの差が 1 を超えてはいけないということです。シーケンスが短い単語で始まるか長い単語で始まるかを固定する場合、カウントは厳密な構造的関係を満たさなければなりません。つまり、開始文字とどちらのタイプがより頻繁であるかに応じて、一方のタイプが他方よりも正確に同じ回数、または正確に 1 回多く出現します。 

これにより、問題は、実行可能な構造に対して 2 つの可能な形状のみをチェックすることに変わります。 すべてを探索するのではなく、`(x, y)`、次のいずれかのシーケンスのみを考慮します。`x == y`、`x == y + 1`、 または`y == x + 1`、可用性と、少なくとも到達するという要件によって制限されます。`k`文字。 

1 つのタイプの可能な数ごとに、代替と可用性によって制限されながら、必要なだけ他のタイプの単語を貪欲に使用します。 長さとコストは線形であるため、総コストは有効な構造の範囲にわたって単調に動作し、制約が変化する境界点のみを評価することができます。 

残りのアイデアは、どのタイプから開始するかを固定し、次に使用可能な最大の交互構造を計算し、その構造内で到達するまでに必要な単語の数を決定することです。`k`。 カウントを増やすと常に長さとコストの両方が線形に増加するため、完全な代替ペアをいくつ取得できるか、および開始タイプの余分なワードを 1 つ追加するかどうかを推論して、実行可能な最小構成を検索できます。

 ## アルゴリズムのチュートリアル

 1. まず、有効な詩は短い単語の数によって完全に決まることに注目してください。`x`そして長い言葉`y`私たちは取る。 開始タイプが選択されると、この配置は常に強制されるため、実現可能性はカウントの違いが最大 1 つであり、可用性を超えないかどうかによってのみ決まります。 
2. 可能な開始タイプごとに、可能な最大の交互構造を計算します。 短い単語から始める場合、短い単語は長い単語より多くても 1 回多く出現することができます。 長い単語から始めると、対称条件が成り立ちます。 
3. 固定パターンの場合、完全な交互ペアをいくつ取ることができるかを検討します。 ペアはどちらかに貢献します`a + b`手紙とか`b + a`文字は順序に応じて異なりますが、長さの寄与は常に`a + b`。 これにより、個々の単語ではなくブロック単位で推論できるようになります。 
4. 少なくとも到達するために必要な完全なペアの数を計算します。`k`文字。 これにより、コストに関係なく、含める必要がある単語の数の下限が決まります。 
5. 次に、次の制約の下でその単語数を実現できるかどうかを確認します。`n`そして`m`選択した開始タイプに応じて。 そうでない場合は、下方修正して実現可能性をテストします。 
6. 実行可能な構成ごとに、合計時間を次のように計算します。`x*c + y*d`。 両方の開始選択肢の最小値を追跡します。 
7. どちらの開始パターンも長さに達する有効なシーケンスを生成できない場合`k`、出力`-1`。 

### なぜ効果があるのか

 重要な不変条件は、任意の交互シーケンスにおいて、開始タイプが固定されると、シーケンス構造が厳密になり、カウントのみによって決定されることです。 カウント間の差が最大 1 であるという制約を超えると、配置に柔軟性がありません。 コストと長さはどちらも選択されたワード数に対して線形であるため、最適な解は常に、交互に 1 つのタイプを最大化するか、長さの制約を満たすために必要な最小ワード数に達する境界構成で発生します。 これにより、インテリアの組み合わせを検討する必要がなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a, b = map(int, input().split())
    c, d = map(int, input().split())
    k = int(input())

    INF = 10**30
    ans = INF

    def check(first_short):
        nonlocal ans

        if first_short:
            # pattern: S L S L ...
            # x = number of short, y = number of long
            # x == y or x == y + 1
            max_pairs = min(n, m)
            # try pairs from max down is unnecessary; monotonic cost allows boundary check

            # case x = y
            x = y = min(n, m)
            # reduce until feasible length
            # we can only reduce pairs
            lo, hi = 0, min(n, m)
            best = -1

            while lo <= hi:
                mid = (lo + hi) // 2
                x = y = mid
                if a * x + b * y >= k:
                    best = mid
                    lo = mid + 1
                else:
                    hi = mid - 1

            if best != -1:
                x = y = best
                ans = min(ans, x * c + y * d)

            # case x = y + 1
            lo, hi = 0, min(n, m)
            best = -1
            while lo <= hi:
                mid = (lo + hi) // 2
                x = mid + 1
                y = mid
                if x <= n and y <= m and a * x + b * y >= k:
                    best = mid
                    lo = mid + 1
                else:
                    hi = mid - 1

            if best != -1:
                x = best + 1
                y = best
                ans = min(ans, x * c + y * d)

        else:
            # pattern: L S L S ...
            # symmetric
            max_pairs = min(n, m)

            # case y = x
            lo, hi = 0, min(n, m)
            best = -1

            while lo <= hi:
                mid = (lo + hi) // 2
                x = y = mid
                if a * x + b * y >= k:
                    best = mid
                    lo = mid + 1
                else:
                    hi = mid - 1

            if best != -1:
                x = y = best
                ans = min(ans, x * c + y * d)

            # case y = x + 1
            lo, hi = 0, min(n, m)
            best = -1
            while lo <= hi:
                mid = (lo + hi) // 2
                x = mid
                y = mid + 1
                if x <= n and y <= m and a * x + b * y >= k:
                    best = mid
                    lo = mid + 1
                else:
                    hi = mid - 1

            if best != -1:
                x = best
                y = best + 1
                ans = min(ans, x * c + y * d)

    check(True)
    check(False)

    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```この解決策では、考えられる 2 つの開始パターンを分離し、各パターンについて、交互にいくつのペアを選択できるかを選択するという問題を軽減します。 それぞれのケースについて、二分探索により、長さの要件を満たす実現可能な最大数のペアが見つかります。`k`ペア数の増加に関しては単調です。 

ペアを短い単語と長い単語の実際の数にマッピングするときは注意が必要です。 1単語の違いは、`x = y + 1`または`y = x + 1`開始タイプに応じてケースが異なり、それぞれが可用性の制約を尊重する必要があります`n`そして`m`。 最終的な答えは、両方のパターンにわたるすべての有効な構造を比較します。

 ## 特殊なケース

 主なエッジケースは、利用可能なすべての単語を交互に使用しても到達できない場合です。`k`。 このような場合、両方のバイナリ検索で有効なペア数を見つけることができず、答えは無限大のままになり、正しく生成されます。`-1`。 

もう 1 つのケースは、1 つの単語タイプが非常に安価だが限定されている場合です。 アルゴリズムは使用量を正しく制限します。`n`または`m`これにより、数学的に長さの制約を満たす場合でも、二分探索が実行不可能な構成を受け入れることがなくなります。 

最後の微妙なケースは次のような場合です。`k`とても小さいです。 二分検索は引き続き正しく動作します。`mid = 0`、ペアを取らないことに対応し、パターンに応じて 1 つの追加ワードで十分かどうかを確認し、最小限の構成がスキップされないことを確認します。
