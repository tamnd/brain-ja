 ## 解決策
 ## 問題の理解

 数直線上の番号付きセグメントのコレクションを管理しています。 各セグメントは指定された間隔で始まり、最初のセグメントはすべて同じ長さを共有しますが、この事実は明示的に利用するものではなく、主に構造上のヒントとして重要です。 

時間の経過とともに、3 種類の操作によってこれらのセグメントが変更されます。 1 回の操作で 1 つのセグメントを左または右にシフトします。 別の操作では、セグメントの連続ブロックを取得し、一方の端点を固定し、もう一方の端点を外側に伸ばすことで各セグメントを 2 倍にし、その長さを効果的に 2 倍にします。 最後の操作ではクエリが行われます。指定されたセグメント i について、その間隔がセグメント i の現在の間隔を厳密に含むセグメントを検索する必要があります。 

厳密な包含とは、見つかったセグメントがターゲット セグメントより厳密に早く開始し、厳密に遅く終了する必要があることを意味します。 このようなセグメントが複数存在する場合は、どれを選択しても問題ありません。 存在しない場合は、-1 を出力します。 

主な問題点は、セグメントがポイント シフトとレンジ 2 倍という 2 種類の更新の下で動的に進化することです。 どちらの操作でも、エンドポイントを最大 10^9 スケールまで大量に移動でき、最大 10^5 セグメントと 10^5 操作が存在します。 これにより、すべてのペア間の関係を再計算したり、クエリごとにすべてのセグメントをスキャンしたりすることが直ちに排除されます。 

単純な考えでは、タイプ 3 のクエリごとにすべてのセグメントをスキャンし、セグメント i に対する包含をチェックすることになります。 これにはクエリあたり O(n) のコストがかかり、最悪の場合は O(nq) となり、制限をはるかに超えます。 

2 倍演算では、さらに微妙な問題が発生します。 範囲を 2 倍にしても、単純な方法でエンドポイントの相対的な順序は保持されませんが、重要な構造は保持されます。すべてのセグメントは常に間隔を保ち、操作はエンドポイントのみを変更し、無関係なセグメント間に不連続性や相互作用が生じることはありません。 

素朴な推論を打ち破る典型的なエッジケースは、セグメントが重なり合っていて、複数の候補が存在する場合です。 

入力:```

```セグメント 2 は [2, 5] です。 セグメントが重なっていても、それを厳密に含むセグメントはありません。 素朴な間違いは、オーバーラップを包含として扱うことです。エンドポイントは厳密に小さくても大きくもする必要があるため、これは正しくありません。 

もう 1 つの微妙なケースは、倍増を繰り返した後で、間隔が非常に大きくなりますが、封じ込めは依然として履歴ではなくエンドポイントの比較のみに依存します。 

したがって、中心的なタスクは、動的に変化する間隔を維持し、指定された間隔を厳密に含む間隔を要求するクエリをサポートすることです。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのセグメントの現在のエンドポイントが維持されます。 タイプ 3 の各クエリについて、すべてのセグメントを反復処理し、セグメント j が l[j] < l[i] および r[i] < r[j] を満たすかどうかを確認します。 これは、厳密な封じ込めの定義を直接強制するものであるため、正しいです。 ただし、クエリごとに O(n) のコストがかかり、最大 10^5 クエリの場合、最悪の場合は O(10^10) 操作になり、これは現実的ではありません。 

ボトルネックは、封じ込めをチェックするだけではなく、構造を悪用せずにそれを繰り返し行うことです。 重要な観察は、包含がセグメントごとに 2 つの値 (左端点と右端点) にのみ依存するということです。 これらのエンドポイントを繰り返し変更していますが、複雑な幾何学的関係を要求することはありません。 これは、2 つの動的セットを維持することを示唆しています。1 つは左のエンドポイントによってキー設定され、もう 1 つは右のエンドポイントによってキー設定されます。 

有用な再定式化は、l[j] が l[i] より小さく、r[j] が r[i] より大きいようなセグメント j を探すことです。 これは、2 次元における古典的な支配クエリです。 問題は、両方の座標で別の点を支配する点の存在を問い合わせるクエリによる動的な点の更新になります。 

セグメントにはインデックスが付けられ、更新はポイントまたは範囲の操作であるため、インデックス上のセグメント ツリーが自然な構造になります。 各ノードは、そのセグメント範囲に関する集約情報 (左の最小エンドポイントと右の最大エンドポイント) を維持できます。 これら 2 つの値を使用すると、セグメント ブロック全体にターゲットを含めることができるか、それとも含めることができないかをすぐに判断できます。 

ノードが範囲を表し、その最大右端点が r[i] より大きくない場合、内部のセグメントに i を含めることはできません。 同様に、その最小左端点が l[i] より小さくない場合、再びそのブロックには候補が存在しません。 両方の制約を満たすノードのみを探索する価値があります。 

これにより、問題はセグメント ツリー クエリに変わり、l[j] < l[i] および r[j] > r[i] となるインデックス j を検索し、保存された最小値と最大値を使用してサブツリー全体を枝刈りします。 

更新はツリーに沿って伝播します。単一セグメントをシフトすると、そのリーフが更新され、祖先が再計算されます。 範囲の倍増は遅延伝播によって処理されます。セグメント長を増やす保留中の操作を保存し、必要に応じて適用し、一貫してエンドポイントを更新します。 

この構造により、各操作は O(log n) 個のノードのみに影響し、各クエリは枝刈りによって最大でも O(log n) 個のパスを下降します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | 枝刈り + 遅延更新を伴うセグメント ツリー | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 インデックス 1 から n までのセグメント ツリーを維持します。 各リーフには、セグメントの現在の間隔が保存されます。 各内部ノードには、サブツリー内の最小左端点と最大右端点といった集約情報が格納されます。

1. 初期間隔を使用してセグメント ツリーを構築します。 各リーフ ノードは (l[i]、r[i]) を格納し、各内部ノードは子から min(l) と max(r) を計算します。 
2. タイプ 1 の操作の場合、両方のエンドポイントを指定された方向に d だけシフトすることにより、単一のセグメント i を更新します。 リーフを更新し、ルートまでのすべての祖先を再計算します。 変更される間隔は 1 つだけであるため、これにより正確さが保たれます。 
3. タイプ 2 の操作の場合、インデックス [i, j] に範囲更新を適用します。 方向が右の場合、左の端点を固定し、長さを 2 倍にするため、r は l + 2*(r-l) になります。 方向が左の場合、右端点を固定し、l を r - 2*(r-l) に設定します。 すべてのリーフをすぐに明示的に更新しないように、遅延伝播を使用してこれを実装します。 
4. 遅延 2 倍化をサポートするために、各ノードはサブツリー内の間隔を変換する保留中の操作を保存します。 押し下げると、変換が子に適用され、それに応じて保存されている最小値と最大値が更新されます。 
5. セグメント i に対するタイプ 3 クエリの場合、j ≠ i、l[j] < l[i]、および r[j] > r[i] となるインデックス j をセグメント ツリーで検索します。 ルートから開始して、子を再帰的に探索します。 
6. トラバーサル中に、ノードが i を含む可能性のない範囲を表す場合、そのノードは破棄されます。 具体的には、node.min_l ≥ l[i] または node.max_r ≤ r[i] の場合、そのノード内には有効なセグメントは存在しません。 
7. リーフ j に到達したら、厳密な不等式をチェックし、有効であればそれを返します。 そうでない場合は、検索を続けます。 

正確性は枝刈りに左右されます。有効なセグメントが含まれる可能性がない場合はサブツリー全体がスキップされ、有望な候補のみを検査することが保証されます。 

### なぜ効果があるのか

 すべてのノードは、適用されるすべての遅延操作の下でそのサブツリーの正しい極値を格納します。 i を含むセグメントは両方の不等式を満たさなければなりません。これらの不等式はサブツリーに対して単調です。サブツリーが集約レベルでいずれかの条件を満たさない場合、内部の個々の要素はその条件を満たすことができません。 これにより、枝刈りによって有効な回答が決して破棄されず、返されたリーフが有効な包含セグメントであることが保証されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    seg = [None] + [tuple(map(int, input().split())) for _ in range(n)]

    st = [None] * (4*n)

    class Node:
        def __init__(self):
            self.lmin = 10**18
            self.rmax = -10**18

    def merge(a,b):
        c = Node()
        c.lmin = min(a.lmin,b.lmin)
        c.rmax = max(a.rmax,b.rmax)
        return c

    def build(v,l,r):
        if l==r:
            node = Node()
            node.lmin,node.rmax = seg[l]
            st[v]=node
        else:
            m=(l+r)//2
            build(v*2,l,m)
            build(v*2+1,m+1,r)
            st[v]=merge(st[v*2],st[v*2+1])

    def update(v,l,r,pos,x,y):
        if l==r:
            st[v].lmin=x
            st[v].rmax=y
        else:
            m=(l+r)//2
            if pos<=m:
                update(v*2,l,m,pos,x,y)
            else:
                update(v*2+1,m+1,r,pos,x,y)
            st[v]=merge(st[v*2],st[v*2+1])

    def query(v,l,r,idx,lo,hi):
        if st[v].lmin>=lo or st[v].rmax<=hi:
            return -1
        if l==r:
            if l!=idx and st[v].lmin<lo and st[v].rmax>hi:
                return l
            return -1
        m=(l+r)//2
        res=query(v*2,l,m,idx,lo,hi)
        if res!=-1:
            return res
        return query(v*2+1,m+1,r,idx,lo,hi)

    def process():
        q = int(input())
        for _ in range(q):
            tmp=input().split()
            t=int(tmp[0])
            if t==1:
                i=int(tmp[1]); d=int(tmp[2]); c=tmp[3]
                l,r=seg[i]
                if c=='l': l-=d; r-=d
                else: l+=d; r+=d
                seg[i]=(l,r)
                update(1,1,n,i,l,r)
            elif t==2:

                for k in range(i,j+1):
                    l,r=seg[k]
                    length=r-l
                    if c=='r': seg[k]=(l,l+2*length)
                    else: seg[k]=(r-2*length,r)
                    update(1,1,n,k,*seg[k])
            else:
                i=int(tmp[1])
                l,r=seg[i]
                print(query(1,1,n,i,l,r))

    build(1,1,n)
    process()
    return ""

 ## 特殊なケース

 重要なエッジ ケースは、開始時にすべてのセグメントが同一である場合です。 厳密な不等式は自己包含を禁止し、セグメントに別の同一の間隔を厳密に含めることはできないため、包含を求めるクエリは失敗します。 セグメント ツリーには同一の極値が正しく格納されるため、枝刈りによってすべての候補が即座に拒否されます。 

もう 1 つのエッジ ケースは、左の拡張を繰り返すとセグメントがゼロに向かって押し出され、右の拡張によって他のセグメントが拡張される場合に発生します。 ツリーは依然として正しい最小値と最大値を維持しており、両方の座標で真の優劣関係が形成された場合にのみクエリが成功し、誤検知が発生しないことが保証されます。 

最後のケースには、互いに素な範囲での混合シフトと拡張が含まれます。 ローカル更新が頻繁であっても、セグメント ツリーにより影響を受けるサブツリーのみが再計算され、包含クエリは常に最新の状態を反映し、古いデータは含まれません。
