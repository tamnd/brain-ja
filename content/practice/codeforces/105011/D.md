 ## 解決策
 ## 問題の理解

 1 から n までの固定された旅行順序で一連の都市が与えられます。 各都市には値 a[i] と、スコアリング モードの 1 つに影響を与えるパラメータ c があります。 旅行者が都市を移動するとき、都市ごとに、単に通過するだけなのか、それともそこに丸 1 日滞在するのかを決定する必要があります。 

都市を通過するだけの場合、その都市と定数 c のみに応じて固定報酬が与えられます。 都市が停止点として選択された場合、その都市の報酬は、シーケンス内の前の都市ではなく、その値がその前の停止都市とどのように比較されるかによって決まります。 最初の都市は強制経由地となり、最後の都市も強制経由地となります。 最初の停止では、以前の参照がないため、報酬は得られません。 

このプロセスは逐次的に行われます。都市 1 から都市 n に移動する間、実際に停止した最新の都市を維持します。 私たちが立ち寄ることを決めるたびに、その都市は将来の立ち寄り先間の比較のための新しい基準になります。 

目標は、これらのルールに基づいて、すべての都市での累計報酬の合計を最大化することです。 

制約は最大 100 万都市にまで及ぶため、二次動的計画法または二次二次動的計画法さえ即座に除外されます。 どのような解も本質的に線形または線形演算的でなければなりません。 遷移は最後の停止位置に依存するため、考えられるすべての以前の停止都市を考慮する単純な動的プログラムでは、最悪の場合、O(n^2) 個の遷移が必要になりますが、これでは遅すぎます。 

微妙な問題は、報酬がどのように相互作用するかに現れます。通過は前の停止点から独立した項に寄与しますが、停止は現在の値と最後に選択した停止点の両方に対する二次依存性を導入します。 この結合が重要な難点です。 

単純な思考を打ち破るエッジケースには、常に停止または常に追い越すことが、局所的には最適であるように見えても、全体的には最適ではない状況が含まれます。 たとえば、すべての a[i] が等しく、c が異なる場合、通過すると一貫したゲインが得られますが、慎重に間隔をあけないと停止するとゼロになります。 もう 1 つのエッジ ケースは、大きい値と小さい値が交互に繰り返される場合で、停止点をまばらに選択すると、より大きな 2 次の差が生成されます。 

## アプローチ

 ブルートフォース戦略では、都市ごとに停止または追い越しの可能なすべての選択肢を明示的に試みます。 これは、ストップとして 1 と n を含む都市のすべてのサブセットを反復処理することに相当します。 各構成について、最後の停止を維持し、貢献を蓄積します。 n−2 個の中間都市にはそれぞれ 2 つの選択肢があり、2^(n−2) 個の可能性が生じるため、これは指数関数的な動作につながります。 報酬はローカルの貪欲な決定ではなくグローバル構造に依存するため、枝刈りさえも役に立ちません。 

自然な動的プログラミングの定式化により、これが改善されます。 都市 i が経由地として選択され、それがこれまでに処理された最後の経由地である場合に、dp[i] を可能な限り最高のスコアとして定義するとします。 2 つの停止点 j と i の間では、すべての中間都市は「パススルー」報酬のみを提供します。これはプレフィックス合計を使用して事前計算できます。 残りの困難は、a[j] と a[i] の両方を含む遷移式を最大化する最良の前のストップ j を計算することです。 

代数を拡張すると、j から i への遷移は a[i] の 2 次式になります。ここで、j は線形係数と定数項によってのみ寄与します。 これにより、問題は動的行セットの維持と x = a[i] での最大値のクエリに変換されます。 これはまさに凸包トリックまたはリーチャオ ツリーの設定です。以前の各停留所がラインを定義し、新しい都市のそれぞれがその a 値で最適なラインをクエリするためです。 

以前のストップに対する強引な操作は、候補ラインを効率的に維持するオンライン構造に置き換えられます。

 ## アルゴリズムのチュートリアル

 まず、通過都市の寄与を停止の決定プロセスから分離します。 パススルー特典は個々の都市のみに依存し、終点には依存しないため、これは重要です。 

各位置がその時点までに都市を通過した合計報酬を累積するプレフィックス配列を事前計算します。 

次に、都市を左から右に処理し、候補となる停止点の動的な構造を維持します。 

1. 最初の停止点として都市 1 を強制します。 その寄与は定義上ゼロであるため、この状態を唯一の有効な以前の停止として動的構造を初期化します。 これにより、以降のすべての計算の初期参照点が確立されます。 
2. 2 から n までの各都市 i について、i が停止点であると判断した場合に、可能な限り最高の合計報酬を計算します。 終点と i-1 の間の都市からのパススルー寄与はプレフィックス合計からすでにわかっているため、直接追加できます。 
3. 最後に立ち寄る最適な都市 j を決定するために、a[j] と a[i] の両方に依存する遷移式を評価します。 展開後、これは各固定 j に対する a[i] の一次関数になるため、各 j は 1 行に対応します。 
4. x = a[i] で以前に挿入されたすべての行の最大値をクエリします。 これにより、i で終了するための前回の最適な停止位置が得られます。 
5. クエリされた最良の値に、事前に計算されたパススルー寄与と展開からの自己項を加えて dp[i] を計算します。 
6. i が最後の都市ではない場合は、i を今後の停止点として選択することに対応する新しい行を挿入します。 この行は、将来の移行への貢献をエンコードしています。 
7. すべての都市を処理した後、n は強制的に停止点となるため、答えは dp[n] になります。 

重要な構造ステップは、停止点間のペアごとの相互作用を線形関数に変換することです。これにより、オンライン最大クエリ構造の使用が可能になります。 

### なぜ効果があるのか

 最適なソリューションは、停止点間のセグメントに分解できます。 各セグメントは、選択された停止エンドポイントとは無関係に、固定のプレフィックス合計コストに寄与します。 セグメント間の唯一の結合は、二次式で使用される最後の停止値から得られます。 二次方程式を展開すると、前のストップへの依存関係が a[i] の線形関数に分離されます。つまり、前のストップの各選択が 1 次元のクエリ空間内の線を定義します。 常に解を左から右に拡張するため、すべての候補ストップが 1 回だけ挿入され、将来の位置についてのみクエリされ、正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Line:
    __slots__ = ("m", "b")
    def __init__(self, m, b):
        self.m = m
        self.b = b

    def value(self, x):
        return self.m * x + self.b

class LiChao:
    def __init__(self, xs):
        self.xs = xs
        self.n = len(xs)
        self.INF = -(10**30)
        self.seg = [None] * (4 * self.n)

    def insert(self, line, v=1, l=0, r=None):
        if r is None:
            r = self.n - 1

        mid = (l + r) // 2
        x_l = self.xs[l]
        x_m = self.xs[mid]
        x_r = self.xs[r]

        cur = self.seg[v]

        if cur is None:
            self.seg[v] = line
            return

        left_better = line.value(x_l) > cur.value(x_l)
        mid_better = line.value(x_m) > cur.value(x_m)

        if mid_better:
            self.seg[v], line = line, self.seg[v]
            cur = self.seg[v]

        if r == l:
            return

        if left_better != mid_better:
            self.insert(line, v * 2, l, mid)
        else:
            self.insert(line, v * 2 + 1, mid + 1, r)

    def query(self, x, v=1, l=0, r=None):
        if r is None:
            r = self.n - 1

        mid = (l + r) // 2
        res = self.seg[v].value(x) if self.seg[v] is not None else self.INF

        if l == r:
            return res

        if x <= self.xs[mid]:
            return max(res, self.query(x, v * 2, l, mid))
        else:
            return max(res, self.query(x, v * 2 + 1, mid + 1, r))

def solve():
    n, c = map(int, input().split())
    a = list(map(int, input().split()))

    # prefix sum of pass-through rewards
    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + (a[i - 1] - c) ** 2

    xs = sorted(set(a))
    lichao = LiChao(xs)

    def add_line(j, dpj):
        # slope = -2*a[j], intercept = dp[j] - pref[j] + a[j]^2
        m = -2 * a[j]
        b = dpj - pref[j] + a[j] * a[j]
        lichao.insert(Line(m, b))

    dp = [0] * n

    # first city is forced stop
    dp[0] = 0
    add_line(0, 0)

    for i in range(1, n):
        best = lichao.query(a[i])
        dp[i] = pref[i] + a[i] * a[i] + best
        if i != n - 1:
            add_line(i, dp[i])

    print(dp[n - 1])

if __name__ == "__main__":
    solve()
```実装は、プレフィックス合計配列を使用してパススルー寄与を分離することから始まります。 これにより、中間都市の以前の停車地への依存がすべて取り除かれます。 

クエリはこれらの座標でのみ実行されるため、Li Chao 構造は、考えられるすべての a[i] 値の圧縮セット上に構築されます。 挿入された各行は、停止点として都市を選択することに対応し、将来のすべての選択に対するその影響をコード化します。 

ループ内の遷移では、x = a[i] における前回の最適な停止構成をクエリすることによって dp[i] を計算し、決定論的なプレフィックス寄与と二次自己項 a[i]^2 を追加します。 

微妙な点の 1 つは、最初の都市がループの前に挿入され、最初の行として機能することです。 また、最後の都市は最終停止点のままでなければならないため、挿入されません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    n, c = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + (a[i - 1] - c) ** 2

    xs = sorted(set(a))

    class Line:
        def __init__(self, m, b):
            self.m = m
            self.b = b
        def value(self, x):
            return self.m * x + self.b

    class LiChao:
        def __init__(self):
            self.lines = []
        def add(self, m, b):
            self.lines.append((m, b))
        def query(self, x):
            return max(m * x + b for m, b in self.lines)

    lichao = LiChao()

    dp = [0] * n
    lichao.add(0, 0)

    for i in range(1, n):
        best = lichao.query(a[i])
        dp[i] = pref[i] + a[i] * a[i] + best
        lichao.add(-2 * a[i], dp[i] - pref[i] + a[i] * a[i])

    return str(dp[-1])

 ## 特殊なケース

 n = 1 または n = 2 の場合、すべての都市が強制的に停止することになり、すべての利益は強制されたルールから得られるため、構造は崩壊します。 プレフィックスの合計と DP の初期化によって最初の停止の移行コストがすでにゼロにエンコードされているため、アルゴリズムはこれを自然に処理します。 

すべての a[i] が等しい場合、ストップ間の二次差はすべてゼロになります。 残りの唯一の貢献はパススルー条件によるものです。 すべての行が同一になり、クエリが一貫した結果を返すため、DP は正しく縮退してプレフィックス パススルー値のみを蓄積します。 

c が極端に大きいか小さい場合、ストップからストップへの移行と比較して、パススルー コストが支配的になるか、無視できる程度になります。 これらの項は DP 遷移から独立しており、常に均一に追加されるため、プレフィックス和分離により、このスケーリングが凸包ロジックに干渉しないことが保証されます。
