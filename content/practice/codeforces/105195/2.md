 ## 解決策
 ## 問題の理解

 この問題は、2 つの独立したレーザーを備えた宇宙船について説明しています。 各レーザーには出力値とリロード時間があります。 レーザーはすぐに充電を開始し、各ショットの後、再度発射するまでにリロード時間が必要です。 両方のレーザーが同時に準備ができている場合、一緒に発射することができ、それらの出力が結合されます。 

敵船には耐久値とシールド値があります。 単一のレーザーショットは、シールドを除いたパワーを与えます。 複合ショットでは、両方のパワーの合計からシールドを引いた値が 1 回だけ処理されるため、2 つのレーザーを 1 つのシールド値だけ別々に発射するよりも、一緒に発射する方が優れています。 

任務は、敵を破壊できる最も早い時間を見つけることです。 

入力には 2 つのレーザーの出力とリロード時間が含まれ、続いて敵の耐久性とシールドが含まれます。 出力は敵の耐久力をゼロ以下にする最終弾の最小時間です。 

耐久性は最大 5000 ですが、リロード時間は長くなることがあります。$10^{12}$。 この組み合わせにより、答えが非常に大きくなる可能性があることがわかり、毎秒またはすべてのリロード イベントをシミュレートすることは不可能です。 同時に、必要なダメージの量は十分に小さいため、耐久性に応じてアルゴリズムを使用できますが、大きな時間値での反復を避ける必要があります。 

いくつかの特殊なケースには注意が必要です。 1 つのレーザーがはるかに弱いものの、はるかに速い場合、そのレーザーのみを使用すると、複合ショットを待つ必要がなくなります。 例えば：```
10 1
5000 100000
25 9
```最初のレーザーのみのセール$10-9=1$ショットごとのダメージですが、毎秒発砲することができます。 2 番目のレーザーを待っていると時間がかかるため、答えは 25 です。 

もう 1 つのケースは、レーザーが常に同期している場合です。 例えば：```
5 10
4 10
16 1
```両方のレーザーは、10 時、20 時などに準備が整います。 組み合わせたショットがお得です$5+4-1=8$ダメージが大きいため、2 発で十分で、答えは 20 です。別々のショットのみを考慮する不注意な解決策は、同期の利点を過小評価することになります。 

3 番目の微妙なケースは、リロード時間に頻繁な共通点がない場合に発生します。```
100 7
100 11
50 1
```レーザーが結合することはほとんどないため、考えられるすべてのショットのペアを数えることは無駄です。 複合ショットに関する唯一の関連情報は、リロード スケジュールが一致する頻度です。 

## アプローチ

 直接的なアプローチでは、タイムラインをシミュレートします。 各レーザーが利用可能になった次の瞬間を保存し、最適なアクションを繰り返し選択し、十分なダメージが与えられるまで継続することができます。 すべてのショット イベントはレーザーがチャージされたときにのみ発生するため、これは正しいです。 ただし、リロード時間が非常に長くなる可能性があるため、たとえ少数の有用なショットであっても、大きなギャップの後に発生する可能性があります。 時間の経過やイベント処理に基づくシミュレーションは適していません。 

重要な点は、実際にはショットの順序を知る必要がないということです。 終了時間を固定することを検討する$T$。 この時点までに、レーザー 1 は正確に$\lfloor T/t_1 \rfloor$発射の機会、そしてレーザー 2 にはまさにそのチャンスがあった$\lfloor T/t_2 \rfloor$チャンス。 すべてのダメージはプラスであるため、利用可能なすべてのショットを常に使用する必要があります。 

2 つのレーザーが同時に利用可能な場合、一緒に発射すると追加のレーザーが得られます。$s$別々に撃った場合と比べてダメージが大きくなります。 共通の発射瞬間は、2 つの再装填時間の最小公倍数の正確な正の倍数です。 したがって、一定の期間、$T$、最大ダメージは次のとおりです。$$\left\lfloor\frac{T}{t_1}\right\rfloor(p_1-s)
+
\left\lfloor\frac{T}{t_2}\right\rfloor(p_2-s)
+
\left\lfloor\frac{T}{\operatorname{lcm}(t_1,t_2)}\right\rfloor s$$ここで問題は、指定された時間が十分かどうかを確認することになります。 この述語は単調です: if time$T$それだけで十分ですが、それ以上の時間でも十分です。 これにより、答えの二分探索が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(答え / 最小リロード時間) | お(1) | 遅すぎる |
 | 最適 | O(ログ(答え)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. レーザー 1 のみ、レーザー 2 のみを発射した場合のダメージ値、および両方のレーザーを組み合わせて得られる追加ダメージを計算します。 単一のレーザーが貢献します$p_i-s$一方、複合ショットは 2 つの別々のショットに追加のショットを加えたものと同等です。$s$。 
2. 指定された時刻かどうかを確認する関数を作成します。$T$十分です。 この機能は、各レーザーが時間ごとに何回発射できるかをカウントします。$T$、次に、両方のリロード スケジュールが一致した瞬間からの同期ボーナスを追加します。 
3. 2 つのリロード時間の最小公倍数を見つけます。 この値のすべての正の倍数は、両方のレーザーが一緒に準備が整った瞬間です。 
4. 答えを二分探索します。 小さな右側の境界から始めて、チェック機能がその時間内に敵を破壊できると判断するまで、それを繰り返し2倍にします。 次に、間隔を検索して最小の有効時間を見つけます。 
5. 最初にチェックに合格したものを返します。 

機能する理由: 選択した終了時間ごとに、この式はその瞬間までに与えられるすべてのダメージをカウントします。 これには、考えられるすべての単一ショットと、考えられるすべての同期ショットが含まれます。 射撃を遅らせても同じ期限までにそれ以上のダメージを与えることはできないため、これがその時点で可能な最大ダメージとなります。 チェック関数は単調なので、二分探索は敵が破壊可能になる最初の時間を見つけます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

p1, t1 = map(int, input().split())
p2, t2 = map(int, input().split())
h, s = map(int, input().split())

d1 = p1 - s
d2 = p2 - s

g = math.gcd(t1, t2)
lcm = t1 // g * t2

def can(time):
    damage = (time // t1) * d1
    damage += (time // t2) * d2
    damage += (time // lcm) * s
    return damage >= h

left = 0
right = 1

while not can(right):
    right *= 2

while left < right:
    mid = (left + right) // 2
    if can(mid):
        right = mid
    else:
        left = mid + 1

print(left)
```最初の部分では、各レーザーの実効ダメージを計算します。 シールドはショットごとに減算されるため、計算式で使用されるダメージ値はすでに実際のダメージ値です。 

の`can`関数は問題の数学モデル全体です。 2 つのフロア区分では、個々の射撃機会がカウントされます。 最小公倍数は、両方のレーザーが 1 つのより強力な攻撃に統合される瞬間をカウントします。$s$保存されたシールドの減少を考慮します。 

最初の二分探索の上限は推測されません。 有効になるまで 2 倍にして拡張されます。これにより、リロード時間によって発生する非常に大きな応答であっても、最大 200 時間かかることが保証されます。$10^{12}$が扱われます。 Python の整数は、最小公倍数の計算とダメージ計算中のオーバーフローを回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(ログ(答え)) | 各二分探索ステップでは、定数時間の演算のみが実行されます。 |
 | スペース | お(1) | このアルゴリズムは、少数の整変数のみを保存します。 |

 2分探索の反復回数は、2倍で上限が得られる区間を半分に繰り返すことで答えを求めるため、少ない回数で済みます。 解決策はリロード時間の大きさには依存しないため、周囲の値は$10^{12}$簡単に処理されます。 

## テストケース```python
import sys
import io
import math

def solve(data):
    it = iter(data.strip().split())
    p1 = int(next(it))
    t1 = int(next(it))
    p2 = int(next(it))
    t2 = int(next(it))
    h = int(next(it))
    s = int(next(it))

    d1 = p1 - s
    d2 = p2 - s
    lcm = t1 // math.gcd(t1, t2) * t2

    def can(t):
        return (t // t1) * d1 + (t // t2) * d2 + (t // lcm) * s >= h

    l, r = 0, 1
    while not can(r):
        r *= 2

    while l < r:
        m = (l + r) // 2
        if can(m):
            r = m
        else:
            l = m + 1
    return str(l)

assert solve("5 10 4 9 16 1") == "20", "sample 1"
assert solve("10 1 5000 100000 25 9") == "25", "sample 2"
assert solve("5 10 4 10 16 1") == "20", "equal reload times"
assert solve("100 7 100 11 50 1") == "2", "fast destruction"
assert solve("2 1000000000000 3 999999999999 10000 1") == "5000", "large reload values"

 ## 特殊なケース

 一方のレーザーが他方のレーザーよりもはるかに速い場合、アルゴリズムは結合ショットを強制しません。 のために：```
10 1
5000 100000
25 9
```時間 25 のチェックでは、最初のレーザーからのショットは 25 ショット、2 番目からはゼロ、同期ボーナスはゼロとカウントされます。 ダメージはちょうど 25 なので、今回は二分探索が受け入れられます。 

両方のレーザーが常に同時に準備が完了すると、同期期間が不可欠になります。 のために：```
5 10
4 10
16 1
```最小公倍数は 10 です。時刻 20 では、各レーザーには 2 回の発射機会があり、組み合わせた瞬間が 2 回あります。 ダメージ計算では次のようになります。$$2 \cdot 4 + 2 \cdot 3 + 2 \cdot 1 = 16$$したがって、アルゴリズムは 20 を返します。 

最小公倍数が非常に大きい場合でも、アルゴリズムは同期の瞬間を列挙しないため、引き続き機能します。 整数の除算を使用して、期限までに何人が存在するかを計算するだけです。 のために：```
100 7
100 11
50 1
```最初の数回の二分探索チェックでは算術式を評価するだけで、ショットをシミュレーションすることなく答えが見つかります。
