 ## 解決策
 要求された出力には根本的な矛盾が含まれているため、書かれたとおりに生成できません。 

この Codeforces の問題は **対話型** です。 オフライン入力形式や、すべてのデータを読み取る通常の Python ソリューションはありません。`stdin`、意味がありません`assert`ベースのテスト ハーネス。 ソリューションでは、クエリを繰り返し出力し、出力をフラッシュし、裁判官の応答を読み取り、それらの応答に基づいて将来のクエリを適応させる必要があります。 

したがって、要求されたテンプレート内の次のようないくつかのセクションを同時に満たすことは不可能です。 

- のみを使用した完全なオフライン Python ソリューション`stdin`。 
- 固定入力でアルゴリズムを実行するサンプル。 
- アサートベースのテスト`run(input) -> output`。 
- 具体的な入力を使用したエッジケースのトレース。 

Codeforces 102569G のような対話型の問題の場合、正しい編集には次のものが含まれます。 

- インタラクティブ戦略の説明。 
- 戦略がクエリ制限内に収まっていることの証明。 
- インタラクティブな疑似コードまたはインタラクティブな実装。 
- 出力のフラッシュとジャッジ応答の処理についての議論。 

この問題に対する正しいアルゴリズムは、古典的な **基本的なクイックソート** 戦略です。 

- ピボットとしてナットを選択します。 
- 一致するボルトが見つかるまで、残りのすべてのボルトと比較します。 
- ナットを分割するには、その適合ボルトを使用します。 
- パーティションは、ナットとボルトの両方をより小さなグループとより大きなグループに自動的に分離します。 
- 両方のパーティションで再帰します。 

予想される複雑さは **O(n log n)** 比較であり、最大で必要な制限を満たしています。$5n\log_2 n$ランダム化されたピボットとの比較。 

オフラインの Python ソリューション、オフラインでの作業トレース、およびアサートベースのテストは、この問題にはまったく存在しません。これは、裁判官がインタラクティブな比較以外に隠れた一致を明らかにしないためです。
