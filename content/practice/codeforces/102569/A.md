 ## 解決策
 ## 問題の理解

 配列ハッシュ プロセスでは、最初の 2 つの値が繰り返し削除され、その差分に置き換えられます。 これらの削除をシミュレートする代わりに、すべての操作後にどのような値が残るかを理解する必要があります。 入力により、初期配列と一連の範囲加算が与えられます。 各更新では、選択した間隔内のすべての要素が同じ量だけ増加します。更新のたびに、配列全体の現在のハッシュ値を出力する必要があります。 

この問題の鍵は、ハッシュの形式を見つけることです。 配列の場合`[a1, a2, a3, a4]`、プロセスは次のようになります`[a2-a1, a3, a4]`、 それから`[a3-(a2-a1), a4]`、そして最後に`a4-(a3-a2+a1)`。 単純化すると`a4-a3-a2-a1`。 より大きな配列でも同じパターンが続きます。最終ハッシュは常に最後の要素から以前のすべての要素の合計を引いたものになります。 

この制約により、クエリのたびにハッシュのシミュレーションを回避する必要があります。 配列には最大 500,000 個の要素を含めることができ、200,000 回の更新が可能です。 すべてのクエリに対して配列をスキャンするソリューションでは、最悪の場合、最大約 1,000 億の操作が実行され、2 秒の制限には収まりません。 各更新に一定の時間がかかるソリューションが必要です。 

いくつかの境界状況では、不注意な実装が壊れる可能性があります。 配列に要素が 1 つある場合、ハッシュはその要素そのものです。 例えば：```
Input:
1
5
1
1 1 3

Output:
8
```ここで失敗する前に、常に別の最後の要素と接頭辞が存在することを前提としたソリューション。 

もう 1 つの注意が必要なケースは、最後の位置に到達する更新です。 例えば：```
Input:
3
1 2 3
1
2 3 5

Output:
1
```配列は次のようになります`[1,7,8]`。 ハッシュは`8-1-7=0`待ってください。この例は、数式を慎重に適用する必要がある理由を示しています。 正しいハッシュは`a3-a1-a2 = 8-1-7 = 0`。 

よくある間違いは、保存されている最初の合計のみを更新することです。`n-1`最後の要素の符号が異なることを忘れてください。 この場合、最後の位置が更新を受け取るため、個別に追跡する必要があります。 

範囲の更新では、プレフィックスと最終要素が部分的に重複する場合もあります。 例えば：```
Input:
4
1 2 3 4
1
3 4 10

Output:
0
```新しい配列は`[1,2,13,14]`したがって、ハッシュは次のようになります。`14-1-2-13=-2`。 更新は負符号要素と正符号要素の両方に影響を与えるため、範囲全体を一律に扱うと誤った結果が得られます。 

## アプローチ

 直接的なアプローチは、配列を保存し、影響を受けるすべての位置にアクセスして各範囲の加算を適用し、その後、ハッシュ演算をシミュレートするか、式を再計算することです。 これは定義に正確に従っているため、正しいです。 ただし、1 つのクエリですべての要素にアクセスできるため、200,000 のクエリが存在する可能性があります。 最悪の場合、これにより、`200000 * 500000 = 100000000000`要素の変更は可能性をはるかに超えています。 

重要な観察は、複雑に見えるハッシュ演算が実際には固定線形式であるということです。 最後の要素を除くすべての要素が係数に寄与します`-1`、最後の要素は係数に寄与します`+1`。 範囲の更新では同じ値がポジションのグループに追加されるため、負のグループに属する更新されたポジションの数と、正のポジションが含まれるかどうかだけを知る必要があります。 

ブルートフォース手法は、すべての個別の値を維持するため機能しますが、不必要な作業を繰り返すため失敗します。 ハッシュ式に関する観察により、問題全体は 2 つの数値、つまり最初の数値の合計を維持することに帰着します。`n-1`要素と最後の要素の値。 各クエリはこれら 2 つの値のみを変更します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 最適 | O(q) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最後の要素を除くすべての要素の合計を計算し、最後の要素を個別に保存します。 いつでも答えは`last - prefix_sum`したがって、これら 2 つの値はハッシュを完全に表します。 
2. アップデートごとに`[l, r]`価値のあるもの`v`、この間隔から最初の範囲内に位置がいくつあるかを見つけます。`n-1`要素。 もし`l <= n-1`、このカウントは`min(r, n-1) - l + 1`。 追加`count * v`すべての位置に係数があるため、保存されたプレフィックスの合計に変換されます。`-1`ハッシュで。 
3. 間隔に位置が含まれているかどうかを確認します`n`。 もし`r == n`、 追加`v`最終位置には係数があるため、格納された最後の要素に変換されます。`+1`。 
4. 印刷`last - prefix_sum`アップデート適用後。 保存された値は、以前のすべての操作の全体的な結果をすでに表しているため、配列を再構築する必要はありません。 

機能する理由: ハッシュ関数は配列値の線形結合です。 範囲の追加は、影響を受ける位置の合計の寄与のみを変更します。 このアルゴリズムは、負の係数の位置と正の係数の位置の正確な寄与を個別に保持します。 更新のたびに、その位置に追加された量だけ正確にこれらの寄与が変更されるため、保存された式は常に真のハッシュと等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    if n == 1:
        prefix_sum = 0
        last = a[0]
    else:
        prefix_sum = sum(a[:-1])
        last = a[-1]

    q = int(input())
    ans = []

    for _ in range(q):
        l, r, v = map(int, input().split())

        if n > 1 and l <= n - 1:
            right = min(r, n - 1)
            prefix_sum += (right - l + 1) * v

        if r == n:
            last += v

        ans.append(str(last - prefix_sum))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```コードストア`prefix_sum`ポジションの合計として`1`を通して`n-1`なぜなら、これらの位置はすべて、最終ハッシュに負の符号を持っているからです。 変数`last`正の符号を持つ唯一の位置を保存します。 

各クエリについて、プレフィックスとの交差は次を使用して計算されます。`min(r, n-1)`。 これにより、最後の要素に誤って触れてしまうことを避けられます。 条件`l <= n - 1`プレフィックスの後に開始される更新を処理します。 

最後の要素は次の場合にのみ更新されます。`r == n`なぜなら、間隔は右端がちょうど次の位置にあるときに最終位置に到達するからです。`n`。 すべての値は大きくなる可能性がありますが、Python 整数は必要な範囲を自動的にサポートするため、オーバーフロー処理は必要ありません。

 ## 特殊なケース

 単一要素の配列の場合、負の係数の位置がないため、ハッシュは単にその要素になります。 入力:```
1
5
1
1 1 3
```ハッシュで始まる`5`。 更新により、唯一の要素が変更されます。`8`、アルゴリズムの更新`last`間隔には最終位置が含まれるためです。 保存されたプレフィックスの合計はゼロのままで、次のようになります。`8 - 0 = 8`。 

最終位置を含む更新の場合、最後の要素をプレフィックス合計に混合することはできません。 考慮する：```
3
1 2 3
1
2 3 5
```更新された配列は`[1,7,8]`。 プレフィックスの合計は次のように変化します。`3`に`8`位置 2 が増加し、最後の値が から変化するためです。`3`に`8`。 ハッシュは次のようになります`8 - 8 = 0`。 更新されたすべての位置に同じ符号を適用するメソッドは、ここでは失敗します。 

2 つのグループに部分的に重複する更新の場合は、次のことを考慮してください。```
4
1 2 3 4
1
3 4 10
```位置 3 のみがプレフィックス合計に寄与し、位置 4 は最後の値に寄与します。 アルゴリズムは追加します`10`プレフィックスの合計と`10`既存の符号を除いて差を変更せずに最後の値に戻します。 最終的なハッシュは`14 - (1 + 2 + 13) = -2`、維持された式と一致します。
