 ## 解決策
 # 問題の理解

 グラフは、双方向のエッジによって接続された頂点のネットワークを表します。 すべての端には小文字が付いています。 パスに沿って頂点 1 から頂点 n に移動すると、エッジで見つかった文字から文字列が作成されます。 可能な限り最小のエッジ数を持つすべてのパスの中で、生成される文字列が辞書編集的に最小のものを選択し、頂点と文字列の両方を出力する必要があります。 

グラフには、最大 200,000 個の頂点と 200,000 個のエッジを含めることができます。 数秒という制限があるため、エッジまたは頂点ごとに少量の一定量の作業を探索するアルゴリズムが必要です。 パスを列挙したり、選択肢のすべての組み合わせを試したり、多くの候補の検索を繰り返し実行したりするアプローチでは、指数関数的に増大するか、少なくとも使用可能な時間を超える可能性があります。 入力サイズと一致するため、O(n + m) 付近の解がターゲットとなります。 

問題は、最短パス条件と辞書編集条件が相互作用することです。 最初の文字が小さいパスは、最短距離より長い場合は役に立ちません。 正しい長さのパスであっても、後の文字の方が大きいため、パスが失われる可能性があります。 アルゴリズムは、最適化できるパスのみを保持する必要があります。 

単純な間違いは、頂点 1 から最小のエッジをすぐに選択してしまうことです。 考慮する：```
4 4
1 2 b
2 4 a
1 3 a
3 4 z
```最短のパスの長さは 2 です。最小の最初のエッジを選択すると、パスが 1、3、4 になり、文字列が得られます。`az`、それは正しいです。 ただし、最短パス層に制限しない貪欲な方法は、小さな文字をたどって行き止まりやより長いルートに到達するため、他のグラフでは失敗する可能性があります。 

もう 1 つのよくある間違いは、BFS を実行して、最初に見つかった最短パスを選択することです。 考慮する：```
3 3
1 2 b
2 3 a
1 3 z
```最短パスの長さは 1 なので、答えは次のようになります。```
1
1 3
z
```距離を確認する前に小さい文字を優先する検索では、パスが選択される可能性があります`ba`, しかし、その道は決して最短の道ではありません。 

3 番目の問題は、複数の頂点が同じ最適なプレフィックスを共有する場合に発生します。 考慮する：```
5 5
1 2 a
1 3 a
2 5 b
3 4 a
4 5 b
```最高の弦は`ab`。 最初の文字を選択したら`a`、頂点 2 と頂点 3 はどちらもまだ候補です。 頂点 3 を破棄するのが早すぎると、最適な答えを与える唯一の継続が削除される可能性があります。 

## アプローチ

 直接的なブルート フォース ソリューションでは、頂点 1 から頂点 n までのすべてのパスが生成され、最小の長さのものだけが保持され、それらの文字列が比較されます。 これは、必要な候補セットを正確にチェックするため、正しいです。 問題は、グラフ内のパスの数が膨大になる可能性があることです。 多くの分岐エッジを持つグラフには、指数関数的に多くの異なるパスが含まれる可能性があるため、このアプローチは中程度の入力でさえ終了できません。 

BFS は重み付けされていないグラフで最短距離を与えるため、頂点 1 から BFS を実行することをお勧めします。 その後、グラフを調べながら最小の文字を選択してみることができます。 欠けている部分は、どの頂点が最短パスに参加できるかを知ることです。 その情報がなければ、小さな文字がターゲットから遠ざかってしまう可能性があります。 

重要な観察は、距離によってすべての有効な最短パスがレイヤーに分割されるということです。 頂点 1 から頂点 n までの最短距離を L とします。頂点 1 からの距離が i で、頂点 n までの距離が L - i の場合にのみ、頂点は最短経路の位置 i に出現できます。 これらの有効な層が判明すると、すべての有効な移動は常に層 i から層 i + 1 へ進みます。 

これで、辞書編集上の選択がローカルになります。 各レイヤーには、これまでに見つかった最良のプレフィックスを共有する一連の頂点があります。 次の有効なレイヤーに続くすべての発信エッジを検査し、その中で最小の文字を選択し、その文字を使用してすべての宛先に到達できるようにします。 いくつかの接頭辞は、後の文字によって分離されるまで結合されたままになる可能性があるため、このような頂点をすべて保持することが必要です。 

2 回の BFS 実行により、最短パス構造が見つかります。 次に、貪欲なレイヤー処理により、その構造内に最小の文字列が構築されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(パスの数) | O(n) | 遅すぎる |
 | 貪欲な再構成による BFS レイヤー | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 頂点 1 から BFS を実行して保存します`dist_start`、ソースからすべての頂点までの最短距離。 頂点 n から別の BFS を実行して保存します`dist_end`、すべての頂点から目的地までの最短距離。 
2. しましょう`length = dist_start[n]`。 頂点が最短パスに属するのは、次の場合のみです。`dist_start[v] + dist_end[v] == length`。 これにより、最適なルートの一部になり得ないすべての頂点が削除されます。 
3. 頂点 1 のみを含む現在のセットから開始します。0 から 0 までのすべてのレイヤーに対して`length - 1`、現在のセットを残すすべてのエッジを検査します。 エッジのみを考慮する`(u, v)`いつ`v`次に最短パス層にあります。 
4. 考慮されたすべてのエッジの中から最小の文字を見つけます。 他のすべての候補は、それらが異なる最初の位置で文字列を大きくするため、この文字は答えの次の文字である必要があります。 
5. その最小の文字を持つエッジを通って到達可能なすべての目的地を取得して、次のセットを構築します。 新しく追加された頂点ごとに 1 つの親を保存し、後で有効なパスを再構築できるようにします。 
6. すべてのレイヤーを処理した後、最終セット内の任意の頂点を選択し、頂点 1 に到達するまで保存された親を逆にたどります。パスを取得するには、この順序を逆にします。 

機能する理由: すべてのレイヤーで、現在のセットには、これまでに構築された最小のプレフィックスの後に表示される可能性のある頂点が正確に含まれています。 可能な限り小さい次の文字を選択すると、より大きな文字を使用するすべてのパスは直ちに辞書編集的に悪化します。 すべての宛先をその文字で保持すると、最適なプレフィックスを共有する可能性のあるすべての継続が保持されます。 すべての遷移は最短パス層内に留まるため、最終的なパスの長さは最小になります。 不変式は各層の後でも true のままであるため、完成した文字列はすべての最短パスの中で最小になります。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def bfs(start, graph):
    n = len(graph) - 1
    dist = [-1] * (n + 1)
    dist[start] = 0
    q = deque([start])

    while q:
        u = q.popleft()
        for v, _ in graph[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)

    return dist

def solve():
    n, m = map(int, input().split())
    graph = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v, c = input().split()
        u = int(u)
        v = int(v)
        graph[u].append((v, c))
        graph[v].append((u, c))

    dist_start = bfs(1, graph)
    dist_end = bfs(n, graph)

    length = dist_start[n]

    parent = [0] * (n + 1)
    current = {1}
    answer_chars = []

    for layer in range(length):
        best = '{'
        for u in current:
            for v, c in graph[u]:
                if dist_start[v] == layer + 1 and dist_start[v] + dist_end[v] == length:
                    if c < best:
                        best = c

        answer_chars.append(best)

        nxt = set()
        for u in current:
            for v, c in graph[u]:
                if c == best and dist_start[v] == layer + 1 and dist_start[v] + dist_end[v] == length:
                    if v not in nxt:
                        parent[v] = u
                        nxt.add(v)

        current = nxt

    end = next(iter(current))
    path = []

    while end != 0:
        path.append(end)
        end = parent[end]

    path.reverse()

    out = []
    out.append(str(length))
    out.append(" ".join(map(str, path)))
    out.append("".join(answer_chars))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```2 つの BFS 呼び出しは、独立した最短距離の計算です。 グラフは重み付けされていないため、キューで十分であり、すべてのエッジは一定の回数だけ検査されます。 

メインループは貪欲な構造を表します。 変数`current`は、すでに選択されている最適なプレフィックスを共有する頂点のセットです。 条件`dist_start[v] + dist_end[v] == length`どの最短パスにも属さないエッジを除外します。 

親配列には、頂点が最初に次の層に入るときに選択された先行要素が格納されます。 頂点は 1 つの距離レイヤーにのみ表示されるため、再構築にはこの 1 つの親の値で十分です。 最後の逆方向走査では、複数のパスに同じ最小文字列が含まれている場合でも、最適なパスの 1 つが生成されます。 

キャラクター`'{`は、辞書編集上、すべての小文字の英語文字よりも大きいため、初期値として使用されます。 Python 文字列は文字を ASCII 値で比較するため、これは入力アルファベットに対して安全に機能します。 

## 実用的な例

 最初のサンプルの場合:```
3 2
1 2 a
2 3 b
```最短距離は 2 です。有効な最短パス層は 1、2、3 です。 

| レイヤー | 現在の頂点 | 選択したキャラクター | 次の頂点 |
 | --- | --- | --- | --- |
 | 0 | {1} | | {2} |
 | 1 | {2} | b | {3} |

 唯一可能なルートがたどられます。 各ステップの後、セットには最適なプレフィックスを生成できるすべての頂点が含まれるため、不変式が成り立ちます。 

2 番目のサンプルの場合:```
3 3
1 3 z
1 2 a
2 3 b
```直接エッジは頂点 2 を通るルートよりも短くなります。 

| レイヤー | 現在の頂点 | 選択したキャラクター | 次の頂点 |
 | --- | --- | --- | --- |
 | 0 | {1} | z | {3} |

 レイヤ制限によりパスが削除されます`1 -> 2 -> 3`これは、距離情報を辞書編集上の選択肢と組み合わせる必要がある理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | BFS トラバーサルと貪欲層処理の両方で、グラフが線形に検査されます。 |
 | スペース | O(n + m) | 隣接リストにはすべてのエッジが格納され、配列には距離、親、および一時的なセットが格納されます。 |

 入力制限には​​線形解が必要です。 頂点とエッジが 200,000 個ある場合、O(n + m) は制限時間内に収まりますが、パスの列挙や多数の候補の繰り返し検索に依存するアプローチでは制限時間内に収まりません。

 ## 特殊なケース

 最初のエッジ ケースは、直接エッジが辞書編集的に小さい長いパスに勝つ状況です。 

入力：```
3 3
1 3 z
1 2 a
2 3 b
```1 から 3 までの BFS 距離は 1 です。貪欲な構築中、距離 1 の頂点のみが次のレイヤーとして考慮されます。 頂点 2 に到達するには別のエッジが必要であるため、頂点 2 は除外されます。 アルゴリズムは唯一の最短パスを出力します。```
1
1 3
z
```2 番目のエッジ ケースは、複数の頂点が同じプレフィックスを共有する場合です。 

入力：```
5 5
1 2 a
1 3 a
2 5 b
3 4 a
4 5 b
```最短の長さは 2 です。選択後`a`、現在のセットは次のようになります`{2, 3}`。 次のレイヤーにはエッジが含まれています`2 -> 5`そして`4 -> 5`、しかし、ただ`2 -> 5`現在のセットから取得されるため、最後の文字列は次のようになります。`ab`。 このアルゴリズムは、1 つの頂点にあまり早くコミットしません。 

3 番目のエッジ ケースは、グラフに同じ文字が多数含まれている場合です。

2 6 a
1 3 a
3 4 a
4 6 a
1 5 b
```最短距離は 2 です。両方とも`1 -> 2 -> 6`そして`1 -> 3 -> 4 -> 6`から始める`a`ですが、2 番目のルートの方が長く、レイヤー条件によって削除されます。 このアルゴリズムは、最短パス層を 1 つ前方に移動するエッジのみを考慮するため、次のように出力されます。```
