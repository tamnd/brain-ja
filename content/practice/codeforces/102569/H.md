 ## 解決策
 ## 問題の理解

 ツリーは接続された頂点のネットワークを表します。 操作では 2 つの頂点を選択し、それらの間の一意のルート上のすべての頂点とエッジに色を付けます。 目標は、ツリーのすべての部分をカバーする最小数の選択されたルートを見つけることです。 

入力はツリーの接続を記述します。 ある木以来`n`頂点には常に`n - 1`エッジ、全体の構造はこれらの接続によって定義されます。 出力は、ツリー全体をペイントするために必要なパス選択の最小数です。 

制約`n <= 200000`問題へのアプローチ方法が変わります。 多くの可能なパスを探索したり、選択肢ごとにツリーの走査を繰り返し実行したりするソリューションは、2 秒の制限には収まりません。 入力自体には最大約 20 万のエッジが含まれるため、線形時間に近いアルゴリズムが必要です。 周りのものすべて`O(n^2)`さらに悪いことに遅すぎます。 

よくある間違いは、葉だけに注目してしまうことです。 葉はペイント パスの自然な終点であるため重要ですが、奇数次数の内部頂点も答えに影響します。 たとえば、中心に 3 つの枝がある木の場合、中心自体が何らかのパス配置の終点として機能する必要があるため、葉を数えるだけでは誤った直感が得られます。 

次のツリーを考えてみましょう。```
4
1 2
3 2
4 2
```正しい答えは、`2`。 3 つの葉だけを数える不注意なアプローチでは、パスは 2 つの葉を接続し中心を通過できるため、1 つのパスで十分であると考えるかもしれませんが、1 つの操作で 3 つの枝すべてをカバーすることはできません。 センターには学位がある`3`, したがって、必要なエンドポイントの 1 つもそこに作成されます。 

もう 1 つの境界ケースは単純なチェーンです。```
5
1 2
2 3
3 4
4 5
```答えは`1`。 ここでは、葉の数を 2 で割った値を常に返すソリューションは機能しますが、すべての分岐点に個別の操作が必要であると想定するソリューションは、誤ってより大きな値を返す可能性があります。 チェーンの 2 つの端点は唯一の奇数次の頂点です。 

## アプローチ

 直接的なアプローチは、ツリー内で可能なすべてのパスを生成し、結合にすべてのエッジが含まれるこれらのパスの最小コレクションを検索することです。 がある`O(n^2)`可能なエンドポイントのペアがあり、それらのすべてのサブセットをチェックすることは指数関数的です。 最適化を行っても、これはすぐに不可能になります。`n = 200000`。 

すべての有効な答えは実際にはパスのコレクションであるため、ブルート フォースは機能しますが、可能なコレクションの数が入力サイズよりはるかに大きいため失敗します。 

重要な観察は、頂点次数を調べることから得られます。 パス操作を使用するたびに、使用されたパスが奇数の入射パス エッジに寄与する場所は、そのパスの 2 つの端点だけになります。 パスのすべての内部頂点は 2 つのパス エッジを受け取るため、パリティには影響しません。 

ツリー全体をカバーする複数のパスを選択した場合、これらのパスの終点となる必要がある頂点は、まさに奇数次数の頂点になります。 単一のパスには 2 つの端点があるため、2 つの奇数次の頂点を修正できます。 これにより下限が与えられます: ツリーが`x`少なくとも奇数次の頂点`x / 2`パスが必要です。 

この下限も達成可能です。 奇数次の頂点をペアにして、各ペアを 1 つのパスの終点にすることができます。 パスは頂点で重なることがありますが、何かを複数回ペイントしても悪影響はないため、これは許可されています。 ツリーのすべてのエッジをこのペアリング プロセスに含めることができるため、追加のパスは必要ありません。 

答えは単純に、奇数次数の頂点の数の半分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 可能なパスの数は指数関数的 | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーのエッジを読み取り、すべての頂点の次数を保存します。 すべてのエッジは、その両方の端点の次数を増加させます。これは、次数によって頂点から離れる枝の数がわかるためです。 
2. 奇数次数を持つ頂点の数を数えます。 これらはパスの内部点では完全に処理できない頂点であるため、端点として表示する必要があります。 
3. このカウントを 2 で除算し、結果を出力します。 各操作は正確に 2 つのエンドポイントを提供し、ペアリング引数は、この操作数が常に十分であることを示しています。 

なぜ効果があるのか:

 重要な不変条件は、頂点次数のパリティです。 パス操作により、ツリーの視点が使用されたパス エッジのコレクションに変更されます。 ペイントされたパス内では、端点以外のすべての頂点が 2 つの使用済みエッジを受け取り、パリティを均等に保ちます。 パスのエンドポイントのみが奇数パリティに寄与します。 元のツリーには端点として表現する必要がある奇数次の頂点が正確に含まれているため、どの解法でも少なくとも奇数次の頂点の半分の数のパスが必要です。 これらの奇数の頂点をパスにペアにするとその境界に達するため、最小値は正確に奇数次の頂点の数を 2 で割った値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    degree = [0] * (n + 1)

    for _ in range(n - 1):
        u, v = map(int, input().split())
        degree[u] += 1
        degree[v] += 1

    odd = 0
    for i in range(1, n + 1):
        if degree[i] % 2 == 1:
            odd += 1

    print(odd // 2)

if __name__ == "__main__":
    solve()
```配列`degree`ツリーから必要な情報のみを保存します。 最終的な答えは各頂点の次数パリティのみに依存するため、隣接リストは必要ありません。 

各エッジの読み取り中に、両方のエンドポイントが 1 つの入射エッジを取得するため、両方の次数の値が増加します。 すべてのエッジが処理された後、ループは次数が奇数の頂点をカウントします。 

ツリーには常に偶数の奇数次の頂点があるため、整数を 2 で割ると、必要な演算の正確な数が得られます。 Python の整数は、オーバーフローを考慮せずに最大次数値を処理します。
