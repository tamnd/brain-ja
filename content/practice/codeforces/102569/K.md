 ## 問題の理解

 テーブルの4本の脚となる棒が4本あります。 各脚は床から表面まで届くため、その長さによってテーブルトップの四隅の高さが決まります。 問題は、1 つの平らなテーブルトップ平面が 4 つの端点すべてを通過するように、これら 4 つの高さを長方形の角に配置できるかどうかです。 

長方形上の平面は特別な構造を持っています。 四隅に注目すると、長方形の 2 つの方向に沿って高さが独立して変化します。 これは、4 隅の高さを任意に設定できないことを意味します。 課題は、与えられた 4 つの数字をその幾何学的条件を満たすように配置できるかどうかを判断することです。 出力は`YES`そのような取り決めが存在する場合、そして`NO`さもないと。 

各バーの長さは次のとおりです。$10^9$、しかしバーは4つしかありません。 値のサイズにより、可能な長さを試したり、座標ベースのシミュレーションを使用したりするアプローチは除外されます。 要素の数は固定されているため、解は大きな状態空間を検索するのではなく、4 つの値の数学的特性に依存する必要があります。 一定数の配置を並べ替えたり確認したりすることは、簡単に制限内に収まります。 

主なエッジケースは、バーがすべて同じ長さでなければならない、または等しいペアのみが機能するという仮定から生じます。 不用意に実装すると、有効な傾斜テーブルを見逃したり、無効なセットを受け入れたりする可能性があります。 

たとえば、入力`1 3 2 2`生産すべき`YES`。 4 つの高さは、対角の合計が等しいように配置できます。$1+3=2+2$。 4 つの等しい値または 2 組の等しい値のみを受け入れるソリューションでは、このケースは誤って拒否されます。 

もう一つのケースは、`1 2 3 10`、生成されるはずです`NO`。 最小値と最大値の合計は次のようになります。$11$、中間の値の合計は次のようになります。$5$。 どのような配置でも反対側のコーナーの合計を一致させることはできないため、どの平面も 4 つの端点すべてを通過することはできません。 

ケース`5 5 5 5`生産すべき`YES`。 平らなテーブルトップは単に傾斜したテーブルトップの特殊なケースであるため、ゼロ以外の傾きを要求すると、この入力が誤って拒否されます。 

## アプローチ

 直接的なアプローチは、4 つのバーを長方形の 4 つの角に可能な限り割り当ててみるというものです。 あるのは$4! = 24$順列。 各配置について、向かい合う角の合計の高さが同じかどうかを確認できます。 これが機能するのは、すべての有効な四角形の配置がこれらの割り当ての 1 つに対応しているため、すべてを試しても解決策を見逃すことがないためです。 

24 回のチェックは一定の作業量であるため、総当たりアプローチはすでに十分に高速です。 ただし、根底にある構造は隠蔽されます。 実際の観察は、長方形上の任意の平面の 4 つの隅の高さは常に単純な等式を満たすということです。 

長方形の角に高さがあると仮定します$x_1, x_2, x_3, x_4$、反対側の角がペアになっています。 長方形の一方の方向に移動すると高さに同じ量が追加され、もう一方の方向に移動すると同じ量が追加されます。 4 つの値は次のように表すことができます。$$c,\quad c+a,\quad c+b,\quad c+a+b$$最初と最後の値の合計は次のとおりです。$$c + (c+a+b) = 2c+a+b$$残りの 2 つの値の合計は次のようになります。$$(c+a)+(c+b)=2c+a+b$$したがって、2 つの反対側のコーナーの合計は等しくなければなりません。 4 つの値を次のように並べ替えた後、$a \leq b \leq c \leq d$、反対側のコーナーで可能な唯一の組み合わせは、最小値と最大値、および 2 つの中間値の組み合わせです。 条件は次のようになります。$$a+d=b+c$$これにより、ソート後に直接定数時間の解が得られます。 

検索スペースには 24 個の可能なレイアウトしか含まれていないため、総当たり法が機能しますが、上記の方程式により、これらすべてのチェックが 1 つの比較に圧縮されます。 幾何拘束は、並べ替えられた値の算術プロパティになります。

 | ブルートフォース | お(4!) | お(1) | 受け入れられますが、検索は不要です |
 | 最適 | O(4 log 4) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 4 つのバーの長さを読み取り、並べ替えます。 ソートされた値を次のようにします$a, b, c, d$。 並べ替えを行うと、有効な配置では最小値と最大値が 1 つの反対のペアを形成する必要があるため、考えられるすべての配置について考える必要がなくなります。 
2. かどうかを確認します。$a+d=b+c$。 これは、値を順序付けした後、考えられる 2 つの反対側のコーナーの合計を比較します。 それらが等しい場合、4 つの高さは、それらすべてに接する平面を持つ長方形の角として配置できます。 
3. 印刷`YES`等式が成り立つとき、そして`NO`さもないと。 等しいことは必要かつ十分であるため、検証する追加のジオメトリはありません。 

なぜ効果があるのか:

 長方形上に配置された平面の場合、角の高さは次の形式になります。$c, c+a, c+b, c+a+b$。 対角の合計は常に等しいため、有効なテーブルはすべてソートされた等式を満たす必要があります。$a+d=b+c$。 逆に、等式が成り立つ場合は、並べ替えられた値を次のように選択します。$a,b,c,d$長方形の周囲にこの順序で配置されます。 隣接するコーナー間の差異により、2 つの長方形の方向に沿った一貫した変化が定義されるため、4 つの点すべてを通る平面が存在します。 条件は有効なテーブルを正確に特徴付けます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = list(map(int, input().split()))
    a.sort()

    if a[0] + a[3] == a[1] + a[2]:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```このソリューションは 4 つの高さを読み取り、それらを並べ替えるので、個々の配置を考慮せずに幾何学的関係を確認できます。 比較では、一方の側では最小値と最大値が使用され、もう一方の側では中央の 2 つの値が使用されます。 

Python の整数は最大の値を処理します$2 \times 10^9$入力値自体が到達できるにもかかわらず、オーバーフローの問題は発生しません。$10^9$。 配列には常に正確に 4 つの数値が含まれるため、インデックス境界の問題はありません。 

数式は並べ替えられた位置に依存するため、演算の順序が重要になります。 元の注文を確認すると、1 つの任意の配置のみがテストされ、有効な配置が拒否される可能性があります。

 2 つの短い脚は反対側の角を占めることができ、2 つの高い脚は他の反対側の角を占めることができます。 合計が等しいため、表面を傾斜面にすることができます。

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    data = list(map(int, inp.split()))
    data.sort()
    return "YES\n" if data[0] + data[3] == data[1] + data[2] else "NO\n"

def run(inp: str) -> str:
    return solution(inp)

assert run("1 1 1 1") == "YES\n", "sample 1"
assert run("1 5 1 5") == "YES\n", "sample 2"
assert run("1 3 2 2") == "YES\n", "sample 3"

assert run("1 2 3 10") == "NO\n", "invalid opposite sums"
assert run("1000000000 1000000000 1000000000 1000000000") == "YES\n", "maximum equal values"
assert run("1 1 1 2") == "NO\n", "single different leg"
assert run("1 2 2 3") == "YES\n", "minimum non-flat slope"

## 特殊なケース

 入力`1 3 2 2`は、等しいペアが必要ない理由を示しています。 並べ替え後の値は次のようになります。`1,2,2,3`。 アルゴリズムチェック$1+3=2+2$これは true なので、返されます。`YES`。 高さがすべて同じではないため、対応するテーブルトップは傾斜しています。 

入力`1 2 3 10`無効な取り決めを示しています。 並べ替えると得られるもの`1,2,3,10`、アルゴリズムチェック$1+10=2+3$。 以来`11`に等しくありません`5`、必要な平面は存在できないため、答えは次のようになります。`NO`。 

入力`5 5 5 5`はフラットテーブルのケースを示しています。 並べ替えても値は変更されず、方程式の両辺は等しくなります。`10`。 水平面は単に傾きがゼロの平面であるため、アルゴリズムはこれを受け入れます。
