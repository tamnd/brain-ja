 ## 解決策
 # 問題の理解

 この旅は、決まった順序で魔法の源を訪れることで構成されています。 各ソースは魔術師の現在のマナを指定された量だけ変更します。唯一の失敗条件は、マナ レベルがいつでもゼロ未満になることです。 課題は、メイジがシーケンス全体を生き残ることができる最小の開始マナ値を決定することです。 

入力配列は、ソースによって引き起こされるマナの変化を記述します。 正の値は現在のマナを増加させ、負の値はマナを消費し、ゼロの値は変更されません。 出力は旅の後の最終マナではなく、旅のすべてのプレフィックスがマナをマイナスにしないようにするために必要な最小の初期量です。 

最大 500,000 個のソースという制約は、ソリューションが線形時間で配列を処理する必要があることを意味します。 多くの可能な開始値を試したり、行程を繰り返しシミュレートしたりするアプローチでは、実行される操作が多すぎます。 2 秒の制限では、O(n) または O(n log n) 付近のアルゴリズムが期待されますが、O(n²) のアプローチは実現可能な範囲をはるかに超えています。 

いくつかのケースでは、間違ったソリューションが壊れる場合があります。 メイジは決してマナを失わないため、プラスの変化のみを含むシーケンスの答えは 0 になります。 例えば：```
3
5 2 8
```正しい出力は次のとおりです。```
0
```何らかのプラスの開始マナが常に必要であると仮定する解決策は、ここでは失敗するでしょう。 

最初の大きな負の値は、後の正の値が考慮される前に処理する必要があります。 例えば：```
3
-10 20 -5
```正しい出力は次のとおりです。```
10
```最初のソースはすぐに少なくとも 10 マナを必要とします。 最終的な合計だけを見る不注意なアプローチでは、旅が全体で 5 マナを獲得することがわかり、誤ってゼロと答える可能性があります。 

もう 1 つの微妙なケースは、最悪の赤字が最後ではなく中央で発生する場合です。 例えば：```
5
4 -7 1 1 10
```正しい出力は次のとおりです。```
3
```最初の 2 つのソースの後、合計の変化は -3 であるため、開始マナは 3 つ必要です。 合計9という数字だけを見ていると、一時的な下落を見逃してしまいます。 

# アプローチ

 直接的なアプローチは、初期マナを推測し、旅をシミュレーションすることです。 開始値が固定されている場合、すべてのソースを 1 回訪問する必要があるため、メイジが生き残るかどうかを確認するには O(n) 時間がかかります。 1 つが機能するまで、考えられるすべての開始値を 0 から試してみることができます。 答えは多くの負の変化の合計と同じくらい大きくなる可能性があるため、最悪の場合、最大約 500000 × 10^9 の演算が必要になる可能性がありますが、これは不可能です。 

答えを二分探索することで、この考えが改善されます。 条件は単調です。開始マナ値が機能する場合は、それより大きな値も機能します。 これにより、O(n log A) アプローチが得られます。ここで、A は可能な回答範囲のサイズです。 ただし、問題の構造により、さらに簡単に観察することができます。 

選択した開始値が十分であるかどうかを繰り返し尋ねる代わりに、マナの変化自体を追跡します。 マナゼロから始めて旅全体を辿ることを想像してみてください。 あらゆる時点での累計は、メイジがゼロよりどれだけ下に落ちたかを示します。 ゼロを下回る最大の低下は、まさに最初に不足していたマナの量です。 不足している量を追加すると、最小プレフィックスがゼロになるのに十分なだけすべてのプレフィックスが上方にシフトされます。 

たとえば、累計が次の場合、```
3, -1, 1, -2, -4, 3
```最小値は -4 です。 4 マナから開始すると、これらの合計は次のように移動します。```
7, 3, 5, 2, 0, 7
```すべての値が有効になり、開始金額が小さくても最低点はマイナスのままになります。 

ブルート フォースは、開始値がジャーニーのすべてのプレフィックスを保護するかどうかをテストするため機能しますが、同じシミュレーションを何度も繰り返します。 最小のプレフィックス合計のみが重要であるという観察により、1 回のパスで答えを見つけることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n × 答え) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在のマナ残高が 0 で、これまでに到達した最小残高を格納する変数から開始します。 現在の残高は、メイジがマナ 0 で開始した場合に何が起こるかを表します。 
2. 各マナの変更を順番に処理し、現在の残高に追加します。 追加するたびに、現在の値が小さい場合は最小残高を更新します。 
3. シーケンス全体が処理された後、最小残高が負の場合は、その絶対値を返します。 最小残高がゼロまたはプラスの場合は、ゼロを返します。 

最小のプレフィックスで十分な理由は、配列の一部のプレフィックスが処理された後に危険が常に発生するためです。 必要な初期マナの最大値は、最も低いプレフィックスをゼロに戻すのに必要な量となります。 

機能する理由: 累計値は、マナ 0 で開始した場合にメイジが死亡する可能性があるすべてのポイントを示しています。 最小累計が`-x`。 開始マナが以下より小さい場合`x`その点はゼロ未満のままになるので、少なくとも`x`マナは必要だ。 正確に始める`x`すべての累計を増加させます`x`、最小値をゼロにし、他のすべての値を非負にします。 したがって`x`必要かつ十分です。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n_line = input().strip()
    if not n_line:
        return

    n = int(n_line)
    a = list(map(int, input().split()))

    current = 0
    minimum = 0

    for value in a:
        current += value
        if current < minimum:
            minimum = current

    print(-minimum)

if __name__ == "__main__":
    solve()
```コードは配列のスキャン中に 2 つの情報のみを保持します。`current`は、魔術師がマナ 0 から開始する架空のシミュレーションにおけるマナ レベルです。`minimum`そのシミュレーションで到達した最低値を保存します。 

ランニングバランスが小さくなるたびに、メイジがその時点で生き残るために追加の開始マナが必要になることを意味します。 最終的な答えは、最低残高のマイナスです。 以来`minimum`ゼロから始まり、決して負にならないシーケンスは自動的に答え 0 を生成します。 

Python の整数はオーバーフローしません。これは、大きさが 10^9 までの 500000 個の値の合計が約 5 × 10^14 に達する可能性があるため、重要です。 また、このアルゴリズムは不必要なプレフィックス合計の保存を回避し、メモリ使用量を一定に保ちます。

# 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | すべてのソースは 1 回だけ処理されます。 |
 | スペース | お(1) | 現在の合計と最小プレフィックス値のみが保存されます。 |

 このソリューションは、最大 500,000 個の値に対して単一の線形スキャンを実行し、入力サイズに比例してメモリを割り当てないため、制約に簡単に適合します。 

# テストケース```python
import sys
import io

def solve_io(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    import builtins
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    current = 0
    minimum = 0

    for x in a:
        current += x
        minimum = min(minimum, current)

    result = str(-minimum)

    sys.stdin = old_stdin
    return result

assert solve_io("6\n3 -4 2 -3 -2 7\n") == "4", "sample 1"

assert solve_io("1\n0\n") == "0", "single zero"

assert solve_io("3\n5 2 8\n") == "0", "all positive values"

assert solve_io("3\n-10 20 -5\n") == "10", "large first deficit"

assert solve_io("5\n4 -7 1 1 10\n") == "3", "middle deficit"

assert solve_io("500000\n" + " ".join(["-1000000000"] * 500000) + "\n") == str(500000000000000), "maximum size input"

 # エッジケース

 すべてが陽性の場合:```
3
5 2 8
```現在の残高は 5、7、15 です。シミュレートされたメイジは決してマナを失うことがないため、プレフィックスの最小値はゼロのままです。 アルゴリズムは戻ります`-0`、これは単純に`0`、初期マナが必要ないという事実を正しく処理します。 

最初の負の値の場合:```
3
-10 20 -5
```現在の残高は -10、10、および 5 です。最小のプレフィックスは -10 であるため、答えは 10 になります。魔術師は回復が可能になる前に最初のソースから生き残る必要があるため、これは要件に一致します。 

中程度の赤字の場合:```
5
4 -7 1 1 10
```現在の残高は 4、-3、-2、-1、および 9 です。最小値は -3 なので、答えは 3 です。アルゴリズムは最終的なマナ量に依存せず、旅の途中で最も危険なポイントを正確に識別します。 

最大サイズの入力の場合:```
500000

```残高はステップごとに 10^9 ずつ減少します。 すべてのソース後の最小残高は -500000000000000 なので、答えは 500000000000000 です。Python の整数は 64 ビットの制限よりもはるかに大きな値を表現できるため、実装はこれを処理します。
