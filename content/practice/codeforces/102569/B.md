 ## 解決策
 ## 問題の理解

 数直線上に配置された一連のボーナス位置があります。 開始位置は座標 0 であり、1 単位の距離を移動するには常に 1 秒かかります。 タスクは、ボーナスのグループを選択し、利用可能な時間内に選択したすべての場所を訪問することです。`t`。 答えは、移動距離や最終順位ではなく、収集できるボーナスの最大数です。 

入力により、ボーナスの数、制限時間、およびすべてのボーナスのソート済みの座標が得られます。 座標がソートされているため、近くのボーナスが隣り合って保存されます。これは、効率的な解決策を可能にする構造的特性です。 出力は、到達可能なボーナスの最大数を表す単一の整数です。 

ボーナスの数は 200,000 に達する可能性があるため、考えられるすべてのボーナス グループをチェックすることは現実的ではありません。 二次アルゴリズムは、最悪の場合でも約 40000000000 回の演算を実行しますが、これは 2 秒の制限をはるかに超えています。 線形時間に近いアプローチが必要です。 座標と制限時間は次のように大きくできます。`10^9`したがって、計算では、大きな中間値を安全に格納できる整数演算を使用する必要があります。 Python の整数はすでにこれを処理しています。 

よくある間違いは、選択した範囲内で最も遠いボーナスまでの距離だけを確認することです。 これは、すべてのボーナスが原点の片側にある場合は機能しますが、ボーナスが両側にある場合は失敗します。原点を越えて戻ると余分な移動がかかるためです。 たとえば、次のようになります。```
3 4
-2 1 3
```正しい答えは`2`。 訪問`-2`そして`1`費用`2 + 3 = 5`最初に左に行く場合は数秒、または`1 + 3 = 4`最初に右に行けば数秒なので、2 つのボーナスが可能です。 最も遠い座標のみを調べる方法では、3 つのボーナスがすべて適合すると誤って考えることになります。`3`。 

もう 1 つの特殊なケースは、時間がないことです。 例えば：```
1 0
5
```正しい出力は次のとおりです`0`。 1 つの到達可能なボーナスから開始したり、移動前に位置を確認したりする不注意な実装では、ボーナスを誤ってカウントする可能性があります。 

3 番目のケースは、最適範囲がゼロと交差するが、開始および終了が反対側である場合です。 例えば：```
4 5
-4 -1 2 10
```最良の選択は`-1, 2`、かかります`3`最初に右に行けば数秒。 含む`-4`より多くの時間が必要になります。 復路を考慮せずに、可能な最大の座標範囲を常に拡張するアルゴリズムでは、答えが過大評価されてしまいます。 

## アプローチ

 直接的な総当たりの解決策では、ボーナスの可能なすべての連続セグメントが試行されます。 各セグメントについて、ゼロから始まりセグメントの両端を訪れる最短ルートを計算できます。 セグメント内のすべてのボーナスはこれら 2 つのエンドポイントの間にあるため、エンドポイントにアクセスするだけで十分です。 これは正しいです。両方の極端な値に到達すると、途中ですべての中間ボーナスを収集できるからです。 

問題はセグメント数です。 くらいあります`n * (n + 1) / 2`可能なセグメントは約 20000000000 です。`n = 200000`。 定期的なコストチェックを行ったとしても、これでは遅すぎます。 

重要な観察は、最適なボーナスのセットは常にソートされた配列内の連続したセグメントであるということです。 ソリューションが 2 つのボーナスを取得し、それらの間のボーナスをスキップする場合、ルートはすでにその位置を通過しているため、スキップされたボーナスを追加しても追加の移動コストはかかりません。 これにより、問題は最長の有効なウィンドウを見つけることに変わります。 

右の端点が固定されている場合、左の端点を右に移動すると、必要な移動距離が小さくなるか、変更されないままになるだけです。 この単調な動作により、2 ポインターによるアプローチが可能になります。 現在のウィンドウでそれ以上のボーナスが必要になるたびに、右側を一度に 1 つずつ拡張します。`t`秒間、ウィンドウが再び可能になるまで、左側からボーナスを削除します。 

ウィンドウの移動コストは、その両端のみに依存します。 ウィンドウ全体が正の側にある場合、コストは右端の座標になります。 マイナス側の場合、コストは左端の座標の絶対値となります。 ゼロを横切る場合、考えられる順序は 2 つあります。最初に左側を訪問するか、最初に右側を訪問します。 2 つのうちの小さい方を採用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ボーナスの現在のセグメントを説明する 2 つのポインターを保持します。 右ポインタが左から右に拡大し、毎回新しいボーナスが 1 つ追加されます。 左のポインタは、現在含まれている最初のボーナスを示します。 
2. 新しい右エンドポイントを追加した後、現在のセグメントにアクセスするのに必要な最小時間を計算します。 他のすべてのボーナスはそれらの間にあるため、必要な座標は左端と右端のボーナスだけです。 
3. 現在のセグメントにそれ以上のものが必要な場合`t`数秒経ったら、左ポインタを 1 つ右の位置に移動して、もう一度確認してください。 左側からボーナスを削除しても必要な時間を増やすことはできないため、このプロセスは最終的に、現在の右側のポインターで終わる最長の有効なセグメントを見つけます。 
4. 現在のセグメントが有効な場合は常に、そのサイズを使用して回答を更新します。 スキャン中に確認された最大サイズが、収集できるボーナスの最大数です。 

不変条件は、縮小後、現在のウィンドウが常に現在の右のエンドポイントで終わる最も長い有効なウィンドウになるということです。 右端点が同じで左端点が小さいウィンドウはすでにチェックされており、削除された場合は無効になります。 考えられるすべての正しいエンドポイントが考慮されるため、スキャンによって見つかった最大の有効なウィンドウが全体的な最適値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, t = map(int, input().split())
    x = list(map(int, input().split()))

    def cost(l, r):
        left = x[l]
        right = x[r]

        if right <= 0:
            return -left
        if left >= 0:
            return right

        return min(right - 2 * left, 2 * right - left)

    ans = 0
    l = 0

    for r in range(n):
        while l <= r and cost(l, r) > t:
            l += 1
        if l <= r:
            ans = max(ans, r - l + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```の`cost`機能はソリューションの中核です。 両端が負の場合、最も遠い点は左側にあり、必要な移動はゼロから左の端点までの距離だけです。 両端が正の場合、右端がコストを決定します。 セグメントがゼロと交差するとき、2 つの公式は、サイドを訪問する 2 つの可能な順序を表します。 

メインループは 2 ポインターのプロセスに従います。 右ポインタは 1 回だけ前に移動し、左ポインタも 1 回だけ前に移動するため、ポインタの移動の総数は線形です。 繰り返しの呼びかけは、`cost`少数の算術演算のみを使用します。 

縮小ループの境界条件は重要です。 現在の右エンドポイントのみを含むウィンドウは、そのコストがチェックされていれば引き続き有効であるため、条件により次のことが許可されます。`l == r`。 すべてのボーナスが遠すぎる場合、ウィンドウは空になり、答えはゼロのままになります。 

Python の整数はオーバーフローしないため、大きな座標を特別に処理する必要はありません。 固定サイズの整数型を使用する言語では、2 倍の座標を含む式には 64 ビット整数が必要です。

 ## 特殊なケース

 ゼロ時間の場合:```
1 0
5
```右ポインタは唯一のボーナスから始まります。 費用は`5`より大きい`t`, そのため、左ポインタが右ポインタを超えて移動します。 ウィンドウは空になり、答えはゼロのままになります。 このアルゴリズムでは、到達できないボーナスはカウントされません。 

ゼロの両側の範囲の場合:```
3 4
-2 1 3
```3 つのボーナスすべてを含むウィンドウにはコストがかかります`2 * 3 - (-2) = 8`または`3 - 2 * (-2) = 7`, したがって拒否されます。 左ポインタはウィンドウが表示されるまで移動します。`[-2, 1]`残り、その費用は`1 - 2 * (-2) = 5`そして`2 * 1 - (-2) = 4`、有効なコストは次のようになります。`4`。 答えは２つになります。 

片側だけの窓の場合:```
3 5
-6 -3 -1
```このアルゴリズムではゼロクロッシング式は使用されません。 コストは単に最も遠いマイナス点までの距離です。 最初のウィンドウにはコストがかかります`6`, そのため、左ポインタが移動します。 残りのボーナス`-3, -1`料金`3`秒がカウントされ、出力が生成されます`2`。 

大きな座標の場合:```
2 2000000000
-1000000000 1000000000
```交差式は周囲の値を評価します`3000000000`、32 ビット整数の制限を超えています。 Python はこれを正しく処理し、アルゴリズムは両方のボーナスが適合するかどうかを判断する前に完全な整数値を比較します。 出力は`2`。
