 ## 解決策
 ## 問題の理解

 整数のリストが与えられ、単一の整数を選択することができます。$X$。 一度$X$が固定されている場合、すべての配列値は次の XOR によって変換されます。$X$であり、変換された最大値に注目します。 目標は選ぶことです$X$この最大値ができるだけ小さくなるようにします。 

このタスクを言い換えると便利な方法は、XOR を使用してすべての数値を「整列」しようとしており、整列後に数値が大きくなりすぎることはないということです。 XOR はビットに対して独立して動作するため、$X$これは、すべての数値を一貫した方法で反転する方法を少しずつ決定していることを意味します。 

入力サイズは最大です$10^5$、各数値は 30 ビットに収まります。 これにより、あらゆる可能性を試みる解決策は即座に除外されます。$X$、 以来$X$までもあります$2^{30}$可能性。 一つの候補をチェックするだけでも$X$費用$O(n)$、とても強引です$X$約必要になる$10^5 \cdot 2^{30}$、それはまったく実行不可能です。 

この構造は、XOR では順序が保持されないため、並べ替えだけでは不十分であることも示しています。 任意のマスクを使用して XOR を適用すると、値の近くにある 2 つの数値が遠く離れてしまう可能性があります。 

素朴な推論による微妙な失敗例は、選択できると仮定することです。$X$貪欲に各要素を個別に最小化します。 たとえば、次を選択して最大値を最小化しようとすると、$X$これにより最大の要素が小さくなりますが、より小さな要素を大きな要素に分割することができます。 

例：```
n = 2
a = [0, 7]
```選ぶなら$X = 7$、結果は次のようになります$[7, 0]$、最大は 7 です。$X = 0$、最大も7です。 しかし、1 つの要素だけに焦点を当てる貪欲なアイデアは、XOR が両方の要素に同時に影響することを無視するため、局所最小化は信頼できません。 

重要な難点は、$X$すべての数値にわたってすべてのビットを同時に制御する必要があります。 

## アプローチ

 ブルートフォースアプローチはあらゆる可能性を試みます$X$から$0$に$2^{30}-1$。 それぞれについて$X$、すべてを計算します$a_i \oplus X$そして最大値を追跡します。 これは、すべての候補の目的関数を直接評価するため、正しいです。 ただし、必要なのは$2^{30}$候補者と各候補者の費用$O(n)$、おおよそにつながります$10^{14}$限界をはるかに超えた操作。 

これを改善するには、次のことを考えるのをやめる必要があります。$X$フラットな数値として計算し、代わりに少しずつ構築します。 重要な観察点は、最大値は、任意の値が存在する最上位ビットに依存するということです。$a_i \oplus X$バイナリで特定のプレフィックスを超える数値がないことを保証できれば、最大値を制限することができます。 

これにより、必然的にビット単位のトライ構造が得られます。 各数字はルートから深さ 30 までのパスです。$X$、枝を反転する方法でトライを効果的に歩いています。 目標は次のとおりです: 選択できるか$X$すべての数値がサブツリー内に留まり、大きな XOR 結果が生成されるのを避けるためですか?

 最上位から最下位までビットごとに数値を再帰的に分割します。 各ビットで、XOR 制約を適用した後、すべての数値を 1 つの分岐内に保持できるかどうかを判断します。 両方の分岐を使用する必要がある場合、そのビットが答えに貢献します。 

この問題は、ビット位置の分割統治に帰着します。各レベルで、結果として得られる XOR の最大値が最小になるように数値を整列させようとします。

 ## アルゴリズムのチュートリアル

 最上位 (ビット 29) からビット 0 までのビットを処理します。各レベルで、一連の数値と考慮中の現在のビットを維持します。 

1. すべての数値と最上位ビットのインデックスから始めます。 

考え方は、現在のビットで定義されたしきい値よりも答えを小さくできるかどうかを判断することです。 
2. 現在のセットを現在のビットに基づいて 2 つのグループ (ビット 0 を持つグループとビット 1 を持つグループ) に分割します。 

XOR はビットを反転できますが、すべての要素に一貫して影響を与えることなくグループ間の構造的な違いをマージすることはできないため、この分離は重要です。 
3. グループの 1 つが空の場合は、次のビットの空ではないグループのみを続行します。 

これは、このビットではすべての数値が一致するため、この位置からの最終最大値に「コスト」がかからないことを意味します。 
4. 両方のグループが空ではない場合、応答でこのビットを考慮する必要があります。 

選ぶことはできません$X$これにより、このレベルでは両方のグループが同じように動作するため、このビットは最終結果の 1 に寄与します。 次に、両方のグループで下位ビットを再帰的に調べます。 
5. 再帰の結果を結合します。両方の分岐が必要な場合、最終的な答えは最悪の場合の変換値によって決まるため、最大の寄与をとります。 
6. ビット -1 に到達するか、グループに分割できない 1 種類の構造のみが含まれる場合、再帰は停止します。 

これが機能する理由は、XOR がバイナリ プレフィックスにどのように影響するかに関係しています。 どのビット レベルでも、数値の間に 0 と 1 の両方が存在する場合、XOR マスクは変換後にそのビットで一部のペアが分岐するという事実を排除できません。 この発散は、最大 XOR 値の下限に直接変換されます。 

このアルゴリズムは、XOR ですべての数値を一貫したバイナリ パーティション内に保持できるように、可能な限り最小のしきい値を効果的に見つけます。 再帰により、構造的に避けられないビットに対してのみ「支払う」ことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    def dfs(arr, bit):
        if bit < 0 or len(arr) <= 1:
            return 0

        zero = []
        one = []

        for x in arr:
            if (x >> bit) & 1:
                one.append(x)
            else:
                zero.append(x)

        if not zero:
            return dfs(one, bit - 1)
        if not one:
            return dfs(zero, bit - 1)

        return (1 << bit) + min(dfs(zero, bit - 1), dfs(one, bit - 1))

    print(dfs(a, 29))

if __name__ == "__main__":
    solve()
```コアの実装では、ビット位置に対する再帰関数が使用されます。 各呼び出しでは、現在のセットが現在のビットに 0 または 1 を持つセットに分割されます。 片側が空の場合は、このビットを完全に無視して下に進むことができます。 両方が存在する場合、最終的な答えでこのビットを考慮する必要があるため、次のように追加します。$2^{bit}$そして両方の可能性を探求し続け、より良い結果を導き出します。 

再帰は、ビットに対する制約ツリーを構築しているという考えをエンコードします。 各レベルでの決定は、個々の数値ではなく、選択後に現在のビットをすべての数値にわたって統合できるかどうかによって決まります。$X$。

```ビット 29 から始めますが、重要なのはビット 0 と 1 だけです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての数値が同一である場合です。 例えば：```
n = 3
a = [5, 5, 5]
```各ビットで 1 つのグループのみが存在するため、再帰は常に 1 つの分岐に従います。 このアルゴリズムは寄与をまったく追加せず、0 を生成します。これは、$X = 0$最大差がゼロになります。 

もう 1 つのケースは、数値が次のような完全なバイナリ セットを形成する場合です。```
0, 1, 2, 3
```最も高い異なるビットでは、両方のグループが存在し、寄与を強制します。 再帰により、必要な分割のみがカウントされることが保証され、各サブツリーは上位ビットで条件付けされると均一になるため、下位ビットでは余分なコストが発生しません。
