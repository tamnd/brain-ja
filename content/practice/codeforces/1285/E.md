 ## 解決策
 ## 問題の理解

 数直線上にいくつかの区間が与えられます。 各間隔は、カバーされたポイントの連続セグメントを表します。 複数の間隔が重なったり接触したりする場合、結合すると、それらの結合されたカバー領域は 1 つの連続した部分にマージされます。 

タスクは、完全なセットの和集合を直接計算することではなく、正確に 1 つの区間を削除し、残りの区間の和集合にいくつの素な連続セグメントが残っているかを計算することです。 この連結成分の数ができるだけ大きくなるように、削除される間隔を選択したいと考えています。 

したがって、問題は、それぞれの間隔が、以前に個別にカバーされていた領域のマージにどのように寄与するかを理解することです。 間隔を削除すると、1 つのマージされた領域が複数の部分に分割される可能性がありますが、その間隔が冗長である場合は何も行われない可能性もあります。 

制約は厳しく、すべてのテスト ケースで合計最大 200,000 間隔です。 これにより、削除ごとに完全結合を再計算するソリューションは即座に除外されます。 各間隔を削除した後にマージを再計算する素朴なアプローチでは、n 回の削除ごとに並べ替えとスキャンが必要となり、テスト ケースあたりおよそ O(n^2 log n) となり、非常に遅すぎます。 

微妙な点は、間隔が完全に冗長である場合もあれば、完全に重要である場合もあることです。 たとえば、ある区間が他の区間によって完全に覆われている場合、それを削除しても何も変わりません。 逆に、2 つのパート間の唯一の橋渡しとなるインターバルが重要です。 

素朴な思考を打ち破るエッジケースには、すべての間隔が同一である場合や、どの間隔を削除しても何も起こらない場合、または各間隔がわずかに重なり合って 1 つの間隔を削除すると長い連結成分が 2 つに分割される連鎖のような状況が含まれます。 小さな例:

 入力:```
3
1 3
3 5
5 7
```ここでは、すべての間隔が 1 つのチェーンを形成し、1 つの連結コンポーネントが生成されます。 中間の間隔を削除すると、チェーンが 2 つのコンポーネントに分割され、答えが 1 から 2 に増加します。インデックスごとに単純な「削除後にマージされたコンポーネントの数」を実行してもまだ遅すぎますが、構造が長さではなく重複接続に依存するため、最小または最大の間隔を削除するような単純な貪欲なアイデアも失敗します。 

## アプローチ

 ブルートフォース戦略は簡単です。各間隔について、それを削除し、残りの間隔の結合を再構築し、結合されていないマージされたセグメントがいくつ存在するかを数えます。 ユニオンを構築するには、左端点ごとに間隔を並べ替え、一度スキャンして重複部分をマージする必要があります。 これには、テスト ケースごとに O(n log n) のコストがかかります。 これを n 回実行すると O(n^2 log n) になりますが、合計 2e5 の間隔ではまったく実行不可能です。 

重要な観察は、和集合構造は、端点でソートしたときに区間がどのように重なるかのみに依存するということです。 間隔が左端点でソートされている場合、間隔が現在のアクティブな右境界に重なるか接触するたびに、現在のセグメントを貪欲に拡張することによって結合が形成されます。 拡張に失敗するたびに、新しいコンポーネントが開始されます。 

ここで、間隔を 1 つ削除すると何が起こるかを尋ねます。 間隔の削除は、その間隔がマージされたコンポーネントの拡張または 2 つの部分の接続に関与している場合にのみ問題になります。 左側のエンドポイントによってソートされたスイープでは、現在のアクティブなカバレッジがアクティブな間隔の最大の右側のエンドポイントによって決定される瞬間があります。 重要な間隔は、スイープのある時点で「最大の適切なエンドポイント寄与者」となる間隔だけです。 

これは古典的な変換につながります。削除ごとに結合を再計算する代わりに、間隔ごとに、必要な「結合セグメント」の数を計算します。 これを削除するとマージまたは分割が発生する場合、その効果は、アクティブな最大カバレッジを一意に決定する回数を使用して表現できます。 

これを正確に行うために、左端点でソートされた間隔を処理しますが、アクティブな右端点を 1 つだけ維持するのではなく、現在最大の右端点に寄与している間隔の数を追跡します。 最大値が一意である場合、その間隔を削除するとカバレッジの拡張が減少し、和集合に分割が生じる可能性があります。 最大値が一意でない場合、コピーを 1 つ削除しても結合境界は変更されません。 

これにより、問題は、区間ごとに、あるセグメント遷移で結合を拡張する一意の責任があるかどうかを追跡することになります。 座標圧縮と、マルチセットまたはヒープのような構造でのスイープを使用すると、現在の最適および 2 番目に最適な正しいエンドポイントを維持し、最適なエンドポイントが一意であることを検出できます。 

結合が新しい右境界に拡張されるたびに、その拡張は少なくとも 1 つの間隔に起因すると考えられます。 正確に 1 つの間隔が原因である場合、それを削除するとその拡張機能が壊れ、コンポーネントの数が 1 つ増えます。 

最後に、答えは、結合セグメントのベースライン数から 1 を引いた値に、一意の重要な間隔を削除することで得られる最大の改善を加えたものになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、すべての区間の和集合における連結成分の数を計算します。 これは、左のエンドポイントで間隔を並べ替え、次の間隔が現在の間隔と重なるたびに貪欲にマージすることによって行われます。 新しい非重複領域を開始するたびに、コンポーネント数が増加します。 

次に、この同じスイープをシミュレートしますが、どの間隔が現在の最右端のエンドポイントの拡張に関与しているかに関する情報で強化します。

1. 間隔を左のエンドポイントで並べ替え、等しい場合は右のエンドポイントで降順に並べ替えます。 これにより、同じ点で始まる間隔のうち、さらに延長する間隔が最初に処理されることが保証されます。 
2. 現在のマージされた領域内の「アクティブな候補」の右端点のマルチセット (または 2 つのヒープ) を維持します。 目標は、最大値とそれが一意であるかどうかを常に把握することです。 
3. 間隔をスイープします。 間隔ごとに、その右端点をアクティブな構造に挿入します。 
4. 現在のマージされたセグメントの終了後に現在の間隔が開始されると、前のコンポーネントが終了します。 ここで、新しい結合セグメントが始まることが記録されます。 
5. セグメントを拡張する際に、最大右端点が増加するたびに、この拡張はその最大値に達する間隔によるものと考えます。 
6. いずれかの時点で、ちょうど 1 つの間隔によって最大右端点が達成された場合、その間隔を「この境界でクリティカル」としてマークします。これは、その間隔を削除すると、この拡張が妨げられ、コンポーネントが分割されることを意味します。 
7. すべての間隔を処理した後、1 つの間隔を削除することで得られる成分の数を計算します。 各間隔は、それがそうでなければ起こらないマージを独自に担当する場合、最大で +1 の改善に貢献できます。 
8. 最終的な答えは、元のコンポーネント数に削除後のすべての間隔での最良の改善を加えたものです。 

### なぜ効果があるのか

 結合構造は、アクティブな最大右端点がコンポーネント間のギャップを越えて変化する点でのみ変化します。 コンポーネントの境界は、カバレッジを拡張するためにギャップを埋める間隔がない場合に正確に存在します。 境界での最大リーチを一意に定義する間隔のみが、削除後にその境界が消えるかどうかに影響を与えることができます。 オーバーラップはスイープの最大トラッキングによって完全にキャプチャされるため、すべてのマージまたは分割イベントは、その時点で最大の正しいエンドポイントに達する間隔のアイデンティティによってのみ決定され、間隔ごとの影響が独立して集約可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    segs = []
    for i in range(n):
        l, r = map(int, input().split())
        segs.append((l, r, i))

    segs.sort()

    import heapq

    # active max-heap by (-r, id)
    heap = []
    contrib = [0] * n

    i = 0
    ans = 0
    cur_l = None
    cur_r = None

    while i < n:
        l = segs[i][0]

        if cur_l is None:
            cur_l, cur_r = segs[i][0], segs[i][1]

        if l > cur_r:
            ans += 1
            heap.clear()
            cur_l, cur_r = segs[i][0], segs[i][1]
            heapq.heappush(heap, (-segs[i][1], segs[i][2]))
            i += 1
            continue

        while i < n and segs[i][0] <= cur_r:
            l, r, idx = segs[i]
            heapq.heappush(heap, (-r, idx))
            cur_r = max(cur_r, r)
            i += 1

        # collect candidates with max r
        best_r = -heap[0][0]
        best_ids = []

        while heap and -heap[0][0] == best_r:
            best_r2, idx = heapq.heappop(heap)
            best_ids.append(idx)

        if len(best_ids) == 1:
            contrib[best_ids[0]] += 1

        for idx in best_ids:
            heapq.heappush(heap, (-best_r, idx))

    ans += 1
    print(ans + max(contrib) - 1)

t = int(input())
for _ in range(t):
    solve()
```コードはまず、ソートされた間隔をスイープし、ギャップの後に新しいセグメントが始まる時点を検出することにより、存在する和集合コンポーネントの数を計算します。 現在のカバレッジ境界が単一の間隔によって一意に決定される時期を識別するために、アクティブな右エンドポイントのヒープを維持します。 

の`contrib`配列は、各間隔がユニオン セグメントの拡張を一意に担当する回数を追跡します。 インターバルが少なくとも 1 つのそのような拡張を一意に担当している場合、インターバルを削除すると、ユニオン コンポーネントの数が 1 つだけ増える可能性があります。 

最後の式は、単一の間隔を削除することで可能な限り最大のゲインを加算します。

 ## 特殊なケース

 重大なエッジケースは、複数の同一の間隔が存在する場合です。 この場合、別の同一の間隔が同じカバレッジを保持しているため、1 つのコピーを削除しても結合はまったく変更されません。 最大右端点が単一の間隔に一意に関連付けられることはないため、アルゴリズムはこれを処理します。 複数のインデックスは同じ最良値を共有するため、寄与は記録されません。 

もう 1 つのエッジ ケースは、2 つの離れた領域を接続するために各オーバーラップが必要なオーバーラップ区間のチェーンです。 このような場合、単一のブリッジ間隔を削除すると、結合コンポーネントの数がちょうど 1 つ増加します。 スイープは、マージ境界で現在の最大右端点を拡張する原因となる固有の間隔を検出し、その間隔がクレジットされます。 

最後の微妙なケースは、間隔がより大きな間隔の中に完全に含まれる場合です。 これを削除しても、ユニオン構造に影響を与えることはありません。 これは、スイープ ステップ中に一意の最大右エンドポイントになることはなく、ゲイン カウントに寄与することもないため、最終的な答えでは正しく無視されます。
