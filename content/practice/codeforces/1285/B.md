 ## 解決策
 ## 問題の理解

 カップケーキの美味しさを表す配列と 2 人のプレーヤーがあります。 Yasser は常にすべてのカップケーキを受け取り、配列全体を合計します。 Adel は、配列全体を**カバーしない**、任意の連続したサブ配列を選択できます。 ヤセルは、彼の美味しさの合計がアデルが達成できる**可能な合計**よりも厳密に大きいかどうかを知りたいと考えています。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、カップケーキの数と美味しさの値の配列が得られます。 各テスト ケースの出力は、Yasser の合計が常に厳密に高い場合は「YES」、そうでない場合は「NO」になります。 

制約を見ると、各配列には最大で次のものを含めることができます。$10^5$すべてのテスト ケースの合計も$10^5$。 これにより、直ちにあらゆることが排除されます$O(n^2)$すべての部分配列を反復処理すると、おおよそ次のようになります。$10^{10}$最悪の場合の運用。 線形または線形に近い解決策が必要です。 おいしさの値は、大きなマイナスまたはプラスになる可能性があります ($-10^9$に$10^9$) そのため、固定サイズの整数を持つ言語では整数オーバーフローにも注意する必要がありますが、Python はこれを自動的に処理します。 

配列に要素が 2 つしかない場合、微妙なエッジ ケースが発生します。 Adel は一度に 1 つの要素のみを取ることができ、Yasser の合計は常に両方の要素の合計と等しくなります。 一方の要素が他方の要素よりも優れている場合、ヤセルは幸せになります。 Adel が取り得る最大の部分配列の合計が Yasser の合計と等しい場合、答えは「NO」です。 別のエッジ ケースは、配列に正の数値と負の数値が交互に含まれる場合に発生します。たとえば、`[5, -5, 5]`。 ヤセルの合計額は`5`、しかしアデルは最後のものを選ぶことができます`5`単独でもヤセル氏の合計に匹敵する。 不用意に実装すると、配列全体を取得しないという制限が無視されたり、プレフィックスとサフィックスのサブ配列が適切に考慮されなかったりする可能性があります。 

## アプローチ

 ブルート フォース アプローチは簡単です。テスト ケースごとに、Yasser の合計を計算します。 次に、Adel が取得できるすべての有効な部分配列について、その合計を計算し、Yasser のものと比較します。 文字通りあらゆる可能性をチェックするため、これにより正確さが保証されます。 ただし、これは$O(n^2)$テストケースごとに。 と$n$まで$10^5$、これでは遅すぎます。 

重要な洞察は、Yasser を脅かす可能性のある唯一のサブ配列がプレフィックスまたはサフィックスであるという認識から得られます。 配列内に完全に存在し、境界に触れていないサブ配列は、より多くの要素を含めることができ、合計が増加する可能性があるため、合計はエッジに及ぶプレフィックスまたはサフィックスよりも厳密に小さくなります。 したがって、プレフィックスの最大合計 (配列全体を除く) とサフィックスの最大合計をチェックするだけで十分です。 これらの両方が Yasser の合計よりも厳密に小さい場合、内部部分配列は彼の合計を超えることはできず、答えは「YES」になります。 それ以外の場合、答えは「NO」です。 これにより、複雑さがテスト ケースごとに線形に軽減されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列全体を合計して、Yasser の合計を計算します。 これは簡単で、比較のベースラインとなります。 
2. 最後の要素を除くプレフィックスを考慮して、最大プレフィックス合計を計算します。 累計をゼロに初期化し、最初の要素から最後から 2 番目の要素まで繰り返し、各要素を累計に加算し、検出された最大値を追跡します。 Adel は配列全体を取得できないため、最後から 2 番目の配列で停止します。 
3. 最初の要素を除く接尾辞を考慮して、接尾辞の最大合計を計算します。 累計をゼロに初期化し、最後の要素から 2 番目の要素までを逆に繰り返し、各要素を累計に加算して、検出された最大値を追跡します。 配列全体を取得することを避けたい場合は、最初の要素をサフィックスに含めることはできないため、最後の要素から開始します。 
4. Yasser の合計をプレフィックスとサフィックスの最大合計と比較します。 いずれかの最大値が Yasser の合計値以上の場合は、「NO」と出力します。 それ以外の場合は、「YES」を出力します。 

機能する理由: 不変条件は、完全な配列を除くサブ配列の最大合計が常にプレフィックスまたはサフィックスのいずれかであるということです。 内部サブ配列は、プレフィックスとサフィックスの合計によって制限されます。 プレフィックスまたはサフィックスの合計が Yasser の合計以上にならないようにすることで、Adel によるサブアレイの選択が Yasser の合計を超えることがないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        total = sum(a)
        
        # check max prefix sum excluding last element
        max_prefix = curr = 0
        for i in range(n - 1):
            curr += a[i]
            if curr > max_prefix:
                max_prefix = curr
        
        # check max suffix sum excluding first element
        max_suffix = curr = 0
        for i in range(n - 1, 0, -1):
            curr += a[i]
            if curr > max_suffix:
                max_suffix = curr
        
        if max_prefix >= total or max_suffix >= total:
            print("NO")
        else:
            print("YES")

if __name__ == "__main__":
    main()
```高速 I/O を使用します`sys.stdin.readline`潜在的なテストケースの数が多いためです。 プレフィックスとサフィックスの合計はゼロに初期化され、段階的に更新されるため、負の値が正しく処理されます。 Off-by-one エラーは、プレフィックスを次で停止することで回避されます。`n - 1`そして接尾辞は`1`。 比較には、`>=`幸福の条件が厳密に大きいからです。
