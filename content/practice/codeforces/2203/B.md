 ## 解決策
 ## 問題の理解

 与えられた整数を最小限の桁変更で「美しい数値」に変換することが求められます。 美しい数値は、桁の合計関数を 2 回適用すると 1 回適用した場合と同じ結果が得られるように定義されます。 具体的に言うと、$F(x)$の桁の合計です$x$、 それから$x$あれば美しい$F(F(x)) = F(x)$。 たとえば、次の場合$x = 37$、$F(37) = 10$そして$F(10) = 1$。 これは美しくありませんが、37 を 33 に変更すると次のようになります。$F(33) = 6$そして$F(6) = 6$、それは美しいです。 

入力は複数のテスト ケースを提供します。各テスト ケースは最大 1 つの整数で構成されます。$10^{18}$。 それぞれの場合において、数値を美しくするために必要な 1 桁の変更の最小数を出力する必要があります。 各数字は任意に置き換えることができますが、先頭のゼロは禁止されています。 

とすれば$x$最大 18 桁を含めることができます。$10^4$テスト ケースでは、どのアルゴリズムもこの長さの数値を効率的に処理する必要があります。 これにより、考えられるすべての数字の変更を列挙する強引なアプローチが排除されます。 18 桁のすべてのサブセットを考慮しても、$2^{18} \approx 260{,}000$組み合わせて、これを行うと、$10^4$テストケースが遅すぎる可能性があります。 

明らかではないエッジ ケースには、桁の合計がすでに大きい非常に大きな数値、桁が繰り返される数値、および 1 桁の数値が含まれます。 たとえば、999999999999999999 (18 9) のような数値は、$F(x) = 162$そして$F(F(x)) = 9$, そのため慎重な調整が必要です。 先頭のゼロの処理にはもう 1 つの微妙な点があります。最初の桁をゼロに変更することは違法です。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる方法で桁を変更し、結果が美しいかどうかを確認します。 すべての数字の組み合わせを繰り返して数字を合計し、double-sum プロパティをチェックすることができます。 これは小さな数値には機能しますが、18 桁の整数ではすべてをチェックしても機能します。$9^{18}$オプションは実行不可能です。 複雑さは指数関数的であり、非現実的です。 

重要な観察は、数字の合計が次の場合に美しいということです。$S = F(x)$は 1 桁の数値です。1 桁の数値はいずれも次の条件を満たします。$F(S) = S$。 もし$S \ge 10$, 数字の合計が 1 桁になる場合でも、数字は美しいままです。 したがって、数値自体を操作する代わりに、桁の合計が 1 から 9 までの 1 桁の数値のいずれかになるように桁を変換することだけに集中する必要があります。変更の正確な順序は、最小限の桁の変更 (小さい桁を 9 に変更) で合計を増やすか、大きい桁を 0 または 1 に変更して合計を減らすことで、貪欲に最小化できます。 

最適な戦略は、現在の桁の合計を計算することです。 1 から 9 までの目標合計ごとに、桁を減らす (現在の合計が高すぎる場合) か桁を増やす (現在の合計が低すぎる場合) ことによって、その合計に到達するために必要な最小桁変更数を決定します。 すべてのターゲットにわたる最小限の変更数を追跡します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(9^18) | お(1) | 遅すぎる |
 | 最適 | テスト ケースごとに O(18 * 9) | お(18) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 指定された数値をその桁のリストに変換します。 これにより、操作と合計計算が簡単になります。 
2. 数値の桁の合計を計算します。これを呼び出します。`current_sum`。 
3. 最小移動を追跡するために変数を初期化します。`min_moves`、大きな値にします。 
4. 目標金額ごとに`t`1から9まで:

 1. もし`current_sum`等しい`t`、変更は必要ありません。 セットはゼロに移動します。 
2. もし`current_sum`未満です`t`、数字を昇順に並べ替え、合計が次の値に達するまで、可能な最大の数字を貪欲に増やします。`t`。 各桁の変更をカウントします。 
3. もし`current_sum`より大きい`t`、数字を降順に並べ替え、合計が次の値に達するまで最大の数字をゼロに向かって貪欲に減らします。`t`。 各桁の変更をカウントします。 
4. この目標合計に必要な手数を記録します。 
5. すべての目標合計をチェックした後、遭遇した最小の手がこのテスト ケースの答えとなります。 
6. すべてのテスト ケースに対して繰り返します。 

機能する理由: 各ステップで、可能な限り 1 桁の合計に近づくように桁を貪欲に調整します。 不変条件は、桁の合計が目標合計に向かって単調に移動し、各桁の変化がその調整に最大限に寄与するということです。 目標合計のセットが小さく、桁数が制限されているため、これにより最小限の変更が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_moves_to_beautiful(x):
    digits = list(map(int, str(x)))
    current_sum = sum(digits)
    min_moves = float('inf')
    
    for target in range(1, 10):
        if current_sum == target:
            return 0
        
        if current_sum < target:
            # Need to increase sum
            inc_digits = sorted(digits)
            need = target - current_sum
            moves = 0
            for d in reversed(inc_digits):
                max_inc = 9 - d
                take = min(max_inc, need)
                need -= take
                if take > 0:
                    moves += 1
                if need == 0:
                    break
            if need == 0:
                min_moves = min(min_moves, moves)
        else:
            # Need to decrease sum
            dec_digits = sorted(digits, reverse=True)
            need = current_sum - target
            moves = 0
            for d in dec_digits:
                max_dec = d
                take = min(max_dec, need)
                need -= take
                if take > 0:
                    moves += 1
                if need == 0:
                    break
            if need == 0:
                min_moves = min(min_moves, moves)
    return min_moves

t = int(input())
for _ in range(t):
    x = int(input())
    print(min_moves_to_beautiful(x))
```この解決策は、数値を数字のリストに変換して個別に変更できるようにすることから始まります。 桁の合計を計算し、1 から 9 までの可能なターゲット合計を反復処理します。ターゲットごとに、アルゴリズムはターゲット合計に到達するために貪欲に桁を増減します。 並べ替えにより、最も影響のある数字が最初に変更され、移動が最小限に抑えられます。 合計を減らすときに最初の桁をゼロ未満に減らすことがないため、先頭のゼロは暗黙的に回避されます。 

## 実用的な例

 トレース`x = 37`:

 | ステップ | 数字 | 現在の合計 | ターゲット | 動く | 必要 | アクション |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | [3,7] | 10 | 6 | 0 | 4 | 7 から 3 に減らし、移動 = 1 |

 トレースは、7 を 3 に変更すると、1 回の移動で合計が 6 に減り、最小限の調整が確認されたことを示しています。 

トレース`x = 645`:

 | ステップ | 数字 | 現在の合計 | ターゲット | 動く | 必要 | アクション |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | [6,4,5] | 15 | 6 | 0 | 9 | 6→0 (6) 減少、移動 = 1 |
 | 2 | [0,4,5] | 9 | 6 | 1 | 3 | 5→2 (3) 減少、移動数 = 2 |

 これは、アルゴリズムが最初に最大桁を減らし、2 回の移動で目標合計に到達することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t * n * 9) | 各テスト ケースについて、9 つのターゲット合計を考慮し、毎回 n 桁にわたって繰り返します。 n ≤ 18 |
 | スペース | O(n) | 数値の桁をリストとして保存します。 

t ≤ 10^4 および n ≤ 18 とすると、合計操作は 10^6 をはるかに下回り、512MB のメモリで 2 秒の制限に十分収まります。
