 ## 問題の理解

 この問題では、合計が指定された合計値になる非負の整数の配列を生成するように求められます。`s`、各要素には、別の数値にも設定されているビットのみを設定する必要があるという追加の制約があります。`m`。 言い換えれば、ビットがゼロの場合、`m`、すべての配列要素でゼロでなければなりません。 このような配列内の要素の最小数を見つけるか、レポートするように求められます。`-1`配列が存在しない場合。 

制約から、`s`そして`m`と同じ大きさにすることができます$10^{18}$、最大で$10^4$テストケース。 これにより、可能なすべての配列を試行したり、ビットのすべてのサブセットを列挙したりする総当り的な試みが排除されます。`s`実現不可能です。 重要なのは、ビットレベルで作業し、合計がどのように計算されるかを推論することです。`s`によって許可される 2 のべき乗を使用して構築できます。`m`。 

微妙なエッジケースが発生する場合`m`に比べて非常に小さいです`s`。 たとえば、次の場合`s = 13`そして`m = 6`（バイナリ`110`)、配列要素には、`2`-ビットまたは`4`-ビットセット。 これらを組み合わせても生成できません`13`したがって、出力は次のようになります`-1`。 もう 1 つの例外的なケースは次のような場合です。`m`ビットが 1 つだけ設定されています。 のために`s = 10`そして`m = 1`、唯一の有効な配列は`[1,1,1,...,1]`、長さは正確です`10`。 

これらの例は、実現可能性が次の条件に依存することを示しています。`s`は、次の許容される 2 の累乗の合計として表すことができます。`m`。 

## アプローチ

 素朴なアプローチは、数値を繰り返し加算してすべての配列を構築しようとすることです。`a_i`そのような`a_i & m = a_i`、可能な最大の数値から開始します ≤`s`。 考えられるすべての要素のシーケンスを試すことができます。 これは、有効な配列が存在する場合には最終的にそれを見つけますが、指数関数的に遅くなります。各ビットは要素内に出現するかどうかのどちらかであるため、最大 2^{\text{#bits}} の可能性が生じます。`s`大きいです。 

重要な洞察は、すべての有効な数値が、設定されたビットのサブセットであるということです。`m`。 仮定する`m`位置にビットが設定されています`[b0, b1, ..., bk]`。 その後、配列内の任意の数値を次の合計として書き込むことができます。`2^bi`インデックスの一部のサブセットの場合。 考えてみると`s`バイナリでは、これらの許可された累乗の無制限のコピーを使用して構築する必要がある目標合計として扱うことができます。 これは、設定されたビットを分配することと同等です。`s`によって許可されたポジションを超えて`m`。 

最適なアプローチでは、貪欲なビットレベルの分散が使用されます。 最下位ビットから開始して、合計を合計するには、許容される 2 のべき乗のそれぞれのコピーが何個必要か決定します。`s`。 それぞれのビット`s`上位ビットを分割することで「カバー」できます。`m`。 たとえば、次の場合`m`許可します`4`そして`2`、 そして`s`持っています`6`バイナリでは、次のように配布できます。`4 + 2`。 許可されたビットの寄与をすべて合計することにより、必要な要素の最小数を決定できます。これは、最初に合計を許可された最大のべき乗に分配し、次に小さいべき乗で残りを処理することに対応します。

 ## アルゴリズムのチュートリアル

 1. リストを初期化する`count`サイズ60（以来`s`そして`m`≤$10^{18}$) に基づいて各ビットが何回使用できるかを保存します。`m`。 のビットを反復処理します。`m`。 ビット位置ごとに`i`どこ`m`持っています`1`、 セット`count[i] = 1`。 これらは、許容される 2 の累乗を表します。 
2. 以下のビットを反復処理します。`s`。 ビット位置ごとに`i`どこ`s`持っています`1`、からの許可されたビットを使用してそれをカバーしてみてください。`count`。 もし`count[i]`もう十分なので、消費してください。 そうでない場合は、上位ビットを「分解」します。`count[j]`のために`j > i`それらを分割することで`2^(j-i)`少しずつコピーする`i`。 これにより、より高い電力が効果的に引き下げられ、より低い電力がカバーされます。 
3. ビットが入っている場合`s`を使用してカバーすることはできません`m`のビット、配列が存在しないため、戻ります`-1`。 
4. それ以外の場合、要素の最小数`n`すべての合計に等しい`1`分散ビット数の s。これは、到達するために必要な 2 のべき乗の個数を表します。`s`。 
5. 戻る`n`現在のテストケースの場合。 

なぜ機能するのか: 不変条件は、許可される各ビット`m`は、任意の数の 2 のべき乗に分割できます。 これにより、外部のビットを必要としないあらゆる合計を表現できることが保証されます。`m`。 上位ビットから下位ビットまで貪欲に分散することで、配列要素の最小数が確保されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s, m = map(int, input().split())
        counts = [0]*60
        for i in range(60):
            if (m >> i) & 1:
                counts[i] = 1
        need = [0]*60
        for i in range(60):
            if (s >> i) & 1:
                need[i] = 1
        # distribute higher bits down
        for i in range(59, -1, -1):
            if need[i] > counts[i]:
                if i == 0:
                    counts[i] = -1
                    break
                need[i-1] += (need[i]-counts[i])*2
        if counts[0] < 0:
            print(-1)
        else:
            total = 0
            for i in range(60):
                total += need[i]
            print(total)

solve()
```この実装では、`counts`どの権限が許可されているかを追跡します`m`。 配列`need`作成に必要なビット数を追跡​​します`s`。 下位ビットの要件が可用性を超える場合は常に、より高い電力を下方に分配します。 配布に失敗した場合は、`-1`と印刷されています。 それ以外の場合は、すべてを合計します`need`bit は配列要素の最小数を示します。
