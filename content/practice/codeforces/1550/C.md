 ## 解決策
 ## 問題の理解

 各要素がインデックスの垂直線上の点を表す配列が与えられます。 より正確には、i 番目の要素が点を形成します。$(a_i, i)$2D 平面内で。 2 点間の距離は、マンハッタン距離を使用して測定されます。 

重要な制約は、部分配列から取得される点の約 3 倍です。 マンハッタン幾何学において、点の 1 つが他の 2 つの点の間の最短経路上に正確に位置する場合、トリプルは不良とみなされます。 代数的には、これはマンハッタン距離が加算されることを意味します。つまり、最初の点から 3 番目の点までの距離は、中間点を通る距離の合計に等しくなります。 

タスクは、そのような「マンハッタン計量における共線性」トリプルを含まない部分配列の数を数えることです。 

すべてのテスト ケースの全長は最大 2×10^5 であるため、制約により、テスト ケースごとに線形に近い解または線形解が求められます。 テスト ケースごとの 3 次または 2 次の解法は、最悪の場合、非常に遅くなります。 

すべてのサブ配列とその内部のすべてのトリプルをチェックする単純なアプローチでは O(n^3) の動作が発生しますが、これらの制限では直ちに不可能です。 部分配列ごとにすべてのトリプルをチェックするだけでも、合計で O(n^3) になります。 

単調なパターンまたは並べ替えられた値のパターンのみが重要であると仮定すると、より微妙な問題が発生します。 たとえば、次のような部分配列`2 4 1 3`局所的には無害に見えますが、インデックスの違いが値の違いと相互作用するため、中間の要素をスキップして形成された一部のトリプルはマンハッタン距離では依然として問題になります。 

主なエッジケースは、違反が隣接する要素のみに依存しないことです。 近隣配列をチェックするとサブ配列は安全に見えても、インデックスのような不正なトリプルが含まれている場合があります。$i < j < k$どこ$j$値は局所的に極端ではありませんが、依然としてマンハッタンの測地線上にあります。$i$そして$k$。 

## アプローチ

 ブルートフォース手法は単純です。すべての部分配列を列挙し、各部分配列についてすべてのトリプルを列挙します。$i < j < k$、マンハッタン距離条件が成立するかどうかを確認します。 これは定義に直接従っているため、正しいです。 問題は、長さ n の配列の場合、テスト ケースごとにおよそ O(n^3) 回の三重チェックが必要となり、最悪のケースでは 10^15 回の演算に相当することです。 

重要な洞察は、2 番目の座標が単なるインデックスであるため、マンハッタンの距離条件が大幅に単純化されるということです。 3点条件の拡大$(a_i, i)$、$(a_j, j)$、 そして$(a_k, k)$と$i < j < k$、次のようになります。$$|a_i - a_k| + (k - i) = (|a_i - a_j| + (j - i)) + (|a_j - a_k| + (k - j))$$インデックス項はきれいにキャンセルされ、次のようになります。$$|a_i - a_k| = |a_i - a_j| + |a_j - a_k|$$これは典型的な状態です。$a_j$間にあります$a_i$そして$a_k$実際のライン上で。 したがって、不正なトリプルが存在するのは、まさに次のような場合です。$a_j$の間にあります$a_i$そして$a_k$価値において。 

これにより、問題全体が純粋な 1D プロパティに集約されます。サブ配列に 3 つのインデックスが含まれる場合、そのサブ配列は不良になります。$i < j < k$そのような$a_j$の間にあります$a_i$そして$a_k$。 同様に、サブ配列は、「値の単調なサンドイッチ パターン」を回避する場合に適しています。 

ここで、これが構造的に何を意味するかを観察してください。 部分配列の長さが少なくとも 5 で、非常に制約された方法で厳密に単調でない場合、ほとんどの場合、そのようなパターンが含まれます。 意図したソリューションで使用されている重要な簡略化は、厳密には単調ではない長さ 3 のパターンが含まれている場合に限り、サブ配列は不良であるということです。これは最終的には、配列のローカル遷移をチェックし、スライディング ウィンドウ内で 2 回連続する「方向の変更」を決して許可しないようにすることになります。 

これは、サブ配列内で一連の差分の符号が複数回変化するかどうかを追跡するために再定式化できます。 サブ配列は、単調な方向の変化が 1 つだけ含まれている場合、つまり「ほぼ単調」である場合に適しています。 

これにより、標準の 2 ポインター / スライディング ウィンドウ ソリューションが、各位置で終わる最長の有効なセグメントを維持することになります。

 ## アルゴリズムのチュートリアル

 現在のインデックスで終わる最小の有効なウィンドウを定義する左ポインタを維持しながら、配列を処理します。 

1. 隣接するペアごとに、シーケンスが増加しているか減少しているかを計算します。 これを、各位置が連続する要素間の方向を示す符号配列として表します。 
2. 符号の変化の数が最大 1 回であるウィンドウを維持します。 符号の変化は局所的な山または谷の構造を示し、これがまさにトリプル間の値を作成するものです。 
3. 右側の境界を段階的に拡張します。 拡張するたびに、新しい記号を追加することで 2 番目の遷移が作成されるかどうかを確認します。 そうなった場合は、遷移が 1 つだけ残るまで、左側の境界を前方に移動する必要があります。 
4. 左側の境界を縮小しながら、ウィンドウの一貫性が保たれるように、古い符号の寄与を効果的に削除して構造を更新します。 
5. 各右端点について、ウィンドウが有効になると、そのインデックスで終わり、左から右の任意の場所で始まるすべてのサブ配列が有効になります。 答えに (r - l + 1) を加えます。 

微妙な点は、すべての悪い構成がウィンドウ内の 2 つの符号の変化に正確に対応しており、これは「V」または逆「V」字形の存在を暗示しているということです。 要素を左側から削除すると、競合する遷移の 1 つが削除され、有効性が復元されます。 

### なぜ効果があるのか

 正しさは、マンハッタンの「悪いトリプル」とトリプル間の値の等価性に基づいており、これらは非単調なローカル構造に対応します。 サブ配列に 2 つの方向変化が含まれる場合は常に、中間値が 2 つの極値の間に位置するように強制する構成内にローカル ピークとローカル バレーが含まれている必要があります。 逆に、せいぜい 1 方向の変化がある場合、シーケンスは完全なサンドイッチ構造を持たない単調またはバイトニックであるため、必要な方法で他の 2 つの要素の間に要素が存在することはできません。 この不変条件により、カウントされたすべてのウィンドウが正確に適切な部分配列であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        if n <= 2:
            print(n * (n + 1) // 2)
            continue

        # direction between consecutive elements
        def sign(x, y):
            return 1 if y > x else -1 if y < x else 0

        l = 0
        ans = 0

        # we track last two directions
        prev_dir = 0
        prev_prev_dir = 0

        for r in range(n):
            if r == 0:
                ans += 1
                continue

            cur_dir = sign(a[r - 1], a[r])

            # shift window if we now have 2 direction changes
            if prev_dir != 0 and cur_dir != 0 and prev_dir != cur_dir:
                # shrink from left
                l = r - 1
                prev_prev_dir = 0

            ans += r - l + 1

            prev_prev_dir = prev_dir
            prev_dir = cur_dir

        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、連続する要素間の方向の変化を追跡します。 スライディング ウィンドウは、2 番目の交互ターンが表示されるたびにリセットされ、トリプル間の値が作成されるパターンが決して許可されないようにします。 答えは、各位置で終わるすべての有効な部分配列を累積します。 

実装の微妙な点は、平等が中立的な方向として扱われることです。 等しい要素は単調な構造を作成せず、多くの場合、符号の衝突と同じように効果的にリセットを強制します。

 ## 特殊なケース

 トリプルが存在しないため、単一要素の配列は、自明のことながら 1 つの適切な部分配列を形成します。 n ≤ 2 の場合、アルゴリズムは早期リターンを通じてこれを処理します。 

要素が等しい場合、すべての方向の値がゼロになります。これは、符号の変更が発生せず、配列全体が有効なままであることを意味します。 スライディング ウィンドウは不必要に縮小しないため、すべてのサブ配列が正しくカウントされます。 

厳密に単調な配列の場合、方向は一定であるため、ウィンドウがリセットされることはなく、すべての部分配列が有効です。 アルゴリズムは n(n+1)/2 を累積し、予想される結果と一致します。 

1 3 2 4 3 のような交互パターンの場合、2 回目の方向変更が導入されるたびに、左側の境界が前方に移動し、無効なサンドイッチ構造がウィンドウ内に残らないようにします。 これにより、ピーク-バレー-ピーク構成を含むサブ配列を過剰にカウントすることが防止されます。
