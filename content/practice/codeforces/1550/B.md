 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、1 つの文字タイプのみで構成される部分文字列を繰り返し削除します。 長さの部分文字列のすべての削除`l`与える`a * l + b`ポイント。 残りの部分が連結されるため、各操作の後に文字列は縮小します。 

目的は、一連の削除を見つけることではなく、文字列全体が消去された後に可能な最大合計スコアを計算することです。 

まず注目すべきことは、すべての文字が 1 回だけ削除されるということです。 操作をどのように選択しても、削除されたすべての長さの合計は常に次のようになります。`n`。 そのため、皆様からのご寄付は、`a`修正されています:`a * n`選択によって影響を受けるのは、実行する削除操作の数だけです。 私たちが演奏したら`k`削除の場合、合計スコアは次のようになります。`a * n + b * k`この観察により、問題は完全に変わります。 削除された部分文字列の正確な長さを気にする必要はなくなりました。 の符号に応じて、操作の数を最大化または最小化することのみを考慮します。`b`。 

制約は非常に小さいです。 文字列の長さは最大 100 で、テスト ケースの数は最大 2000 です。 かなり非効率なソリューションでも快適にフィットします。 それでも、意図したソリューションは、テスト ケースごとに線形時間で実行される単純な貪欲な観察です。 

スコア計算式ではなく削除のみに焦点を当てると、いくつかの特殊なケースが誤って処理されやすくなります。 

考慮する：```
n = 5
a = 3
b = 4
s = 11111
```不用意な解決策を実行すると、1 回の操作で文字列全体が削除され、スコアが発生する可能性があります。`15 + 4 = 19`。 正しい答えは、`5 * (3 + 4) = 35`、なぜなら、いつ`b > 0`、追加の操作を行うたびに追加のポイントが与えられるため、一度に 1 文字ずつ削除するのが最適です。 

考慮する：```
n = 6
a = 1
b = -5
s = 000000
```一度に 1 文字を削除すると 6 回の操作が行われ、マイナスのボーナスが 6 回発生します。 最適な戦略は、文字列全体を一度に削除することであり、次のようになります。```
1 * 6 + (-5) = 1
```もう 1 つの微妙なケースは、交互の文字列です。```
n = 5
a = 0
b = -1
s = 01010
```一見すると、実行が 5 つあるため、5 つの削除を実行する必要があるように見えます。 実際には、1 つの文字タイプの出現をすべて削除した後、残りの文字は 1 つのブロックにマージされます。 最適な答えは、後で説明する実行回数の式から得られ、次の式と等しくなります。`-3`、 ない`-5`。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての有効な削除を試み、結果の文字列を再帰的に探索します。 すべての法的な操作シーケンスが検査されるため、これは正しいです。 残念ながら、考えられる欠失配列の数は指数関数的に増加します。 長さ 100 の文字列であっても、検索スペースは天文学的に大きく、まったく実行不可能です。 

重要な観察は、長さによる寄与の合計が固定されていることです。 すべてのキャラクターが正確に貢献します`a`削除順序に関係なく、一度だけ。 最適化の問題全体は、操作の数の選択に帰着します。 

スコアは次のように書き換えることができます。```
a * n + b * k
```どこ`k`は削除数です。 

もし`b >= 0`、さらに削除するたびにスコアが増加します。 最善の戦略は最大化することです`k`。 すべての文字はそれ自体有効な単色の部分文字列であるため、文字を 1 つずつ削除して次のことを実現できます。```
k = n
```興味深いケースは、`b < 0`。 現在、すべての操作にポイントがかかるため、削除はできるだけ少なくしたいと考えています。 

文字列を次のように構成します。`runs`等しい文字の最大ブロック。 

バイナリ文字列の場合、いつでも最初に 1 つの文字タイプのすべてのランを削除できます。 その後、残りのすべての実行が 1 つの実行にマージされ、最後の 1 回の操作で削除できます。 

あれば`runs`ブロック内に最大 1 文字が表示されます。`runs / 2`ブロック。 ブロックの少ないキャラクターを選択します。 

可能な最小操作数は次のようになります。```
floor(runs / 2) + 1
```よく知られている同等の式は次のとおりです。```
max(count_0_runs, count_1_runs)
```以来：```
max(count_0_runs, count_1_runs)
= floor(runs / 2) + 1
```任意のバイナリ文字列の場合。 

最適な演算数がわかれば、すぐに答えを計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、`a`、`b`、およびバイナリ文字列。 
2. もし`b >= 0`、 戻る：```
n * (a + b)
```これは各文字を個別に削除することに相当し、正確に`n`操作。 
3. もし`b < 0`、文字列内の実行数を数えます。 

ランはその位置から始まります`0`そしていつでも`s[i] != s[i-1]`。 
4. 以下を計算します。```
operations = runs // 2 + 1
```これは、バイナリ文字列の達成可能な最小削除数です。 
5. 返却:```
a * n + b * operations
```ランを数えた後、答えはスコア計算式から直接導き出されます。 

### なぜ効果があるのか

 プロセス全体で削除される合計の長さは常に次のようになります。`n`、したがって、どの戦略も正確に収益を上げます`a * n`長さの期間からのポイント。 唯一の可変部分は、`b`操作の数を掛けます。 

いつ`b >= 0`、操作の数を増やすと、常にスコアが向上します。 一度に 1 文字ずつ削除すると、可能な最大値が得られます`k = n`。 

いつ`b < 0`、操作が少ないほど良いです。 バイナリ文字列では、まず頻度の低い文字のランをすべて削除すると、残りのランが 1 つのブロックにマージされます。 あれば`runs`総ブロック数、頻度の低い文字が占める`floor(runs / 2)`走る。 これらの実行は個別に削除され、マージされた残りの部分がもう一度削除され、次のようになります。`floor(runs / 2) + 1`操作。 これ以上に優れた戦略はないため、これは可能な最小限の削除数です。 

アルゴリズムは常に次の最適値を使用するため、`k`、常に最大のスコアを生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, a, b = map(int, input().split())
    s = input().strip()

    if b >= 0:
        print(n * (a + b))
    else:
        runs = 1
        for i in range(1, n):
            if s[i] != s[i - 1]:
                runs += 1

        operations = runs // 2 + 1
        print(a * n + b * operations)
```最初のブランチは、追加の削除がすべて有益であるという簡単なケースを処理します。 個々の文字の削除は常に許可されているため、最適な操作数は正確に次のとおりです。`n`。 

2 番目の分岐カウントが実行されます。 隣接する文字が異なる場合は必ずラン境界が発生します。 1 つのランから開始してトランジションをカウントすることで、オフ バイ ワンのミスを回避できます。 

実行回数を取得したら、次の式を適用します。`runs // 2 + 1`最小限の削除のため。 最終スコアは次から直接計算されます。`a * n + b * operations`。 

長さ 1 の文字列には特別な処理は必要ありません。 実行カウンタは正しく 1 のままであり、1 つの操作が生成されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        n, a, b = map(int, input().split())
        s = input().strip()

        if b >= 0:
            ans.append(str(n * (a + b)))
        else:
            runs = 1
            for i in range(1, n):
                if s[i] != s[i - 1]:
                    runs += 1
            ans.append(str(a * n + b * (runs // 2 + 1)))

    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    solve()
    return sys.stdout.getvalue()

 ## 特殊なケース

 ### 単一文字の文字列

 入力:```
1
1 3 -2
0
```文字列は 1 回実行されます。```
runs = 1
operations = 1 // 2 + 1 = 1
answer = 3 * 1 + (-2) * 1 = 1
```このアルゴリズムは、特別なケースを必要とせずに、可能な限り最小の入力を正しく処理します。 

### すべての文字が等しい

 入力:```
1
6 1 -5
000000
```実行はちょうど 1 回です。```
runs = 1
operations = 1
answer = 6 - 5 = 1
```キャラクターを個別に削除する単純な戦略では、6 つの操作が実行され、追加のポイントを失うことになります。 この式は、1 つの削除が最適であることを正確に示しています。 

### 代替文字列

 入力:```
1
5 0 -1
01010
```実行回数をカウントすると、次のことがわかります。```
runs = 5
operations = 5 // 2 + 1 = 3
answer = -3
```最初は 5 つのランがありますが、最初に 1 つの文字タイプのランをすべて削除すると、残りのランをマージできるようになります。 これはまさに、多くの誤ったソリューションが最小操作数を過大評価するシナリオです。 

### 1 回の実行でプラスのボーナス

 入力:```
1
5 2 3
11111
```以来`b > 0`の場合、アルゴリズムは実行構造を無視して次のように計算します。```
answer = 5 * (2 + 3) = 25
```一度に 1 文字を削除すると 5 回の操作が必要になるため、文字列全体を一度に削除するよりも優れています。 ポジティブボーナスブランチは、この動作を自動的にキャプチャします。
