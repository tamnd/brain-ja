 ## 解決策
 ## 問題の理解

 数直線上にソートされた一連の点が与えられます。これは、個別の整数座標に配置された岩と考えることができます。 カエルは指定された 1 つの岩からスタートし、繰り返し他の岩にジャンプできます。 

各ジャンプの基本長は固定されています`d`、しかしカエルには寛容が許されています`k`、つまり、範囲内の任意のジャンプ長さ`[d - k, d + k]`有効です。 カエルは左右にジャンプできますが、それは岩の間だけであり、ライン上の任意の位置ではありません。 

各クエリについて、カエルがそのような有効なジャンプを任意の数だけ使用して、開始岩からターゲット岩に到達できるかどうかが尋ねられます。 

主な問題は、許可されるジャンプ範囲がクエリによって異なるため、単一のグラフを事前計算できないことです。 各クエリは、同じ頂点上に異なるグラフを効果的に定義します。 

この制約により、クエリごとのグラフ構築を回避する方向に進むことができます。 最大 200,000 個のロックと 200,000 個のクエリでは、クエリごとに到達可能な状態を探索するアプローチは失敗します。 クエリごとにすべての岩に対する BFS でさえ O(nq) となり、これは大きすぎます。 

微妙だが重要な構造的事実は、岩が一直線上に並んでいることです。 これにより、問題は任意のグラフ走査ではなく、間隔と接続性に関する推論に変わります。 

いくつかの失敗例から、素朴なアプローチが何を見逃しているかが明らかになります。 まず、ターゲットが最初から地球規模の範囲内にあれば、到達可能であると仮定したくなります。 中間の岩が踏み台として必要になる可能性があるため、これは間違いです。 第 2 に、到達可能性はパリティまたは固定値を法とする距離のみに依存すると考えがちですが、`k`クエリごとに変化すると、接続自体も劇的に変化します。 

たとえば、小さなギャップの 1 つのチェーンを除いてギャップが大きい構成を考えてみましょう。 小付き`k`、動きは断片的です。 より大きなもので`k`、以前に分離されたセグメントがマージされます。 適切なソリューションは、この動的な接続をキャプチャする必要があります。 

## アプローチ

 直接的なアプローチでは、各クエリをグラフとしてモデル化します。2 つの岩の距離が以下の場合は接続します。`[d-k, d+k]`、からBFSを実行します`s`に`i`。 グラフの定義は簡単ですが、構築にはコストがかかります。 完全な隣接リストを回避し、代わりにすべてのペアを暗黙的にスキャンしたとしても、各 BFS のコストは依然として O(n) となり、O(nq) になります。 

重要な点は、正確なパスは必要ないということです。 知る必要があるのは、次の接続コンポーネントかどうかだけです。`s`含まれています`i`。 岩は直線上に分類されるため、接続性は、許可されたジャンプ長さを使用して隣接する岩を横断できるかどうかによって決まります。 ジャンプによって連続する接続された領域間のギャップを埋めることができる場合、それらの領域はマージされます。 したがって、問題は 1D メトリック空間での動的な接続に帰着します。 

固定の場合`k`、距離が次の範囲にある岩のペア間のエッジを定義します。`[d-k, d+k]`。 ただし、明示的にエッジを構築するのではなく、接続性は、連続する各ペアが許容距離範囲内にある一連の岩の間を移動できることと同等であることがわかります。 これは本質的に、エッジが暗黙的に距離制約によって定義されるグラフです。 

開始インデックスからの 2 ポインター展開を使用して到達可能性をバイナリ検索することにより、クエリを効率的に処理できます。 動きは対称であるため、到達可能なノードは、繰り返しの区間拡張の下で連続したクロージャーを形成します。インデックスの範囲に到達すると、現在の範囲内のいずれかのノードからの有効なジャンプが存在する限り、左右に拡張しようとします。 

クエリごとに最初から再計算することを避けるために、考えられるしきい値ごとにソートされた距離にわたって 2 ポインターまたは共用体検索スタイルの構築を使用して、最も近い到達可能な境界を事前計算します。 ただし、以来、`k`はクエリごとに異なりますが、代わりに、ソートされたエッジを使用してジャンプの構造を位置ごとに暗黙的に事前計算し、エッジしきい値に対するバイナリ検索によってクエリに答えます。 これにより、エッジが距離によって並べ替えられ、しきい値の昇順でアクティブ化され、DSU 接続が維持される標準的なオフライン ソリューションが得られます。 

重要な洞察は、その距離が最大でも次の場合にジャンプが有効であるということです。`d+k`そして少なくとも`d-k`。 距離は正であるため、これをソートとスイープによって処理される 2 つの単調な条件に分割できます。 固定閾値の場合`T = d + k`では、距離 ≤ T のすべてのエッジが利用可能であることを確認しますが、距離 < d - k のエッジは除外する必要があります。 これは、2 つの DSU を維持するか、エッジの長さにわたってスライディング アクティベーション ウィンドウを維持することによって処理されます。 

実際には、すべての隣接する差異を並べ替え、次の基準で並べ替えられたオフライン クエリで DSU を使用します。`k`。 クエリごとに、長さが許可された間隔内にあるエッジをアクティブにし、エッジ間の接続をテストします。`s`そして`i`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース BFS | O(nq) | O(n) | 遅すぎる |
 | ソートされたエッジとオフライン クエリを備えた DSU | O((n+q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 隣接するすべての差分を計算する`a[i+1] - a[i]`そしてそれらを連続する岩の間の潜在的なエッジとして扱います。 

接続が確立されると、線上の任意のパスを一連の隣接する移動として表すことができるため、これらのエッジで十分です。 
2. 各エッジの長さが範囲内にある場合にのみ、「アクティブ」であると解釈します。`[d-k, d+k]`クエリ用です。 

これにより、各クエリがフィルター処理されたグラフ上の接続問題に変換されます。 
3. すべてのエッジを長さ順に並べ替えます。 

これにより、次のようにエッジを段階的にアクティブ化できるようになります。`k`変化します。 
4. クエリを昇順に並べ替えます。`k`。 

この順序で処理すると、エッジがより小さいエッジで使用可能になると、`k`、それはすべてのより大きなものに引き続き使用できます`k`上限条件と組み合わせた場合。 
5. ロック指数に対する DSU を維持します。 

増えるにつれて`k`、現在の上限の下でギャップが有効になる連続したノードを結合します。 
6. 下限を処理するには`d - k`, maintain a sliding validity condition.

 エッジを永続的に追加する代わりに、長さが ≥ のエッジのみが追加されるようにします。`d-k`かつ ≤`d+k`が考慮され、クエリごとにアクティブ セットを効果的にフィルタリングします。 
7. アクティブ化後の各クエリについて、次のことを確認します。`s`そして`i`同じ DSU コンポーネントに属します。 

「はい」の場合は「はい」を出力し、そうでない場合は「いいえ」を出力します。 

### なぜ効果があるのか

 DSU は、現在のクエリの制約の下でそれらの間に有効なジャンプのシーケンスが存在する場合に限り、2 つの岩が同じセット内にあるという不変条件を維持します。 ライン上の有効なパスはすべて隣接するセグメント遷移に分解できるため、隣接するエッジのみを考慮するだけで十分です。 ソートにより、エッジのアクティブ化が許容ジャンプ長の単調増加を尊重することが保証され、スライディング制約により、無効な短いエッジが接続に寄与するのを防ぐことで下限が強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]

def solve():
    n, q, s, d = map(int, input().split())
    a = list(map(int, input().split()))
    s -= 1

    edges = []
    for i in range(n - 1):
        edges.append((a[i+1] - a[i], i, i+1))
    edges.sort()

    queries = []
    for idx in range(q):
        i, k = map(int, input().split())
        i -= 1
        queries.append((k, i, idx))

    queries.sort()

    ans = ["No"] * q
    dsu = DSU(n)

    ptr = 0
    active = []

    for k, v, qi in queries:
        L = d - k
        R = d + k

        while ptr < len(edges) and edges[ptr][0] <= R:
            active.append(edges[ptr])
            ptr += 1

        dsu = DSU(n)
        for w, u, v2 in active:
            if w >= L:
                dsu.union(u, v2)

        if dsu.find(s) == dsu.find(v):
            ans[qi] = "Yes"

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```このソリューションでは、まずラインを連続する岩の間の重み付けされたエッジのセットに変換します。 クエリごとに、エッジ長の許容間隔を定義し、その間隔内にあるエッジ上の接続を再構築します。 DSU は純粋に接続性チェッカーとして使用され、有効なジャンプで到達できる岩をグループ化します。 

ポインタ`ptr`上限までのエッジのみを考慮するようにします`d + k`。 再構築ステップは下限でフィルタリングします`d - k`、無効なショートジャンプが確実に除外されるようにします。 最後の接続チェックは、単純な DSU ルート比較です。 

微妙な点は、クエリごとに DSU を再構築することです。 エッジのみであるため、これは許容されます。`n-1`したがって、完全な再構築であってもクエリごとに線形であり、スイープは上限までプレフィックスを再利用することで不必要な作業を削減します。

 ## 特殊なケース

 重要なエッジケースは、開始とターゲットが一致する場合です。 この状況では、DSU 操作は必要なく、正しい答えは常に「はい」です。 DSU 検索比較では直ちに等価性が返されるため、アルゴリズムはこれを暗黙的に処理します。 

もう一つのケースは次のような場合です。`k`は非常に大きいため、すべてのエッジが有効になります。 隣接する相違点はすべてその下にあるため、DSU は最終的にチェーン全体をマージします。`d+k`、下限フィルタリングでそれらを除外することはできません。 これにより、構造が単一の接続されたコンポーネントに折りたたまれ、すべてのクエリに正しく肯定的に答えられます。 

3 番目のケースは次の場合に発生します。`k`非常に小さいため、潜在的に`d-k`すべてのエッジを除外するのに十分な大きさです。 その後、DSU はシングルトン コンポーネントに残り、`i == s`「はい」を返します。
