 ## 問題の理解

 サイズの小さなアルファベットの小文字で構成される文字列が与えられます。$k$、自由に置き換えることができるワイルドカード文字に加えて。 すべてのワイルドカードをこのアルファベットの文字に置き換えた後、各文字は値、つまりその文字のみで構成される最長の連続ブロックを誘導します。 この最長ランを文字ごとに個別に計算し、最終的な文字列の品質はこれらの最小値になります。$k$価値観。 目標は、この最小の最長実行値ができるだけ大きくなるように、すべてのワイルドカードの置換を選択することです。 

この構造はバランスのとれた方法で敵対的です。 1 つの文字を最大化しようとしているのではなく、すべての文字が最終的な文字列のどこかに適度に長く連続したセグメントに表示されるようにすることを目的としています。 ワイルドカードは、これらの最長セグメントのバランスをとるのに役立つ文字に割り当てることができる柔軟な接着剤として機能します。 

制約の長さは長くなり、$2 \cdot 10^5$、 その間$k$これにより、文字を明示的に割り当て、割り当てごとに実行統計を再計算するアプローチは即座に除外されます。 文字ごとの位置ごとに完全な状態を保存する場合でも、それが線形または線形に近い場合にのみ許容されます。$n$そして指数関数的にのみ$k$、 以来$k$小さいです。 指数関数的なものは何でも$n$または二次関数$n$失敗します。 

元の文字列に 1 文字が不足している場合、微妙な失敗が発生します。 たとえば、次の場合$k = 3$文字列に 2 つの文字のみと多くのワイルドカードが含まれている場合、単純な貪欲な塗りつぶしにより、誤ってワイルドカードが文字のサブセットに集中しすぎて、別の文字が小さな断片としてのみ表示されるか、まったく表示されなくなる可能性があります。 文字が欠けているとその文字のスコアが 0 になるため、1 つでも不均衡があれば、答えが崩れる可能性があります。

 ## アルゴリズムのチュートリアル

 問題を、固定された候補が答えるかどうかをテストするものに変換します。$x$達成可能です。

これが機能する理由は単調性です。すべての文字が一定の長さであることを保証できれば$x$の場合は、より小さい値でもそれを確保することができます。 
2. 固定の場合$x$、文字列を前処理して、長さのセグメントかどうかをチェックできる構造にします。$x$特定の文字に割り当てることができます。 位置は、その文字がすでにある場合、またはワイルドカードである場合に、その文字に使用できます。 
3. 文字ごとに、有効な長さの連続ブロックが存在するすべての位置を計算します。$x$始めることができます。 これは、ウィンドウがその文字に対して有効かどうかを追跡するスライディング ウィンドウを使用して実行できます。 
4. 実現可能性のチェックを選択まで簡素化します$k$競合しない配置。文字ごとに 1 つ。各配置がその文字の有効なウィンドウをカバーします。 
5. すでに割り当てられている文字に対してビットマスク DP を維持します。 マスクごとに、選択した文字のサブセットを重複競合なしに配置できるかどうかを追跡します。 トランジションは、以前に選択した間隔と重複しない有効な間隔に新しい文字を割り当てようとします。 
6. マスク全体に到達できたら$2^k - 1$、 それから$x$実現可能です。 そうでなければそうではありません。 

最終的な答えが最大です$x$それは実現可能性を通過します。 

### なぜ効果があるのか

 各文字は、最大連続実行を通じて目的に独立して貢献します。 文字間の唯一の相互作用は、位置の共有によるものです。 各文字を強制的に単一の連続した長さのブロックに確保することによって$x$、グローバル制約を次のパッキング問題に変換します。$k$間隔。 DP は、選択された 2 つの間隔が競合しないことを保証しますが、スライディング ウィンドウは、選択されたすべての間隔が元の文字列制約の下で有効であることを保証します。 有効な最終的な色付けにはスコアが含まれるため、この等価性により正確さが保たれます。$x$にはそのような配置が含まれている必要があり、成功した配置はフルカラーに拡張できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

def can(x, s, n, k):
    if x == 0:
        return True

    # precompute valid windows for each letter
    valid = [[False] * (n + 1) for _ in range(k)]

    for c in range(k):
        ok = 0
        left = 0
        for r in range(n):
            if s[r] != '?' and ord(s[r]) - 97 != c:
                ok += 1

            while r - left + 1 > x:
                if s[left] != '?' and ord(s[left]) - 97 != c:
                    ok -= 1
                left += 1

            if r - left + 1 == x and ok == 0:
                valid[c][left] = True

    # dp over subsets of letters
    size = 1 << k
    dp = [False] * size
    dp[0] = True

    intervals = [[] for _ in range(k)]
    for c in range(k):
        for i in range(n - x + 1):
            if valid[c][i]:
                intervals[c].append((i, i + x - 1))

    for mask in range(size):
        if not dp[mask]:
            continue
        # find next letter
        for c in range(k):
            if mask & (1 << c):
                continue
            for l, r in intervals[c]:
                ok = True
                # check overlap with already used letters
                for c2 in range(k):
                    if mask & (1 << c2):
                        for l2, r2 in intervals[c2]:
                            if not (r < l2 or r2 < l):
                                ok = False
                                break
                        if not ok:
                            break
                if ok:
                    dp[mask | (1 << c)] = True

    return dp[size - 1]

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    lo, hi = 0, n
    ans = 0
    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, s, n, k):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()

次に、ビットマスク DP は、重複することなく文字ごとに 1 つの間隔を割り当てようとします。 各 DP 状態は、すでに配置されている文字のサブセットを表します。 トランジションでは、以前に選択した間隔と交差しない有効な間隔で新しい文字を追加しようとします。 すべての文字を配置できれば、構成は可能です。 

二分探索により、実現可能な最大値が確実に見つかります。

 ## 特殊なケース

 重要なエッジケースは、一部の文字が最初の文字列にまったく現れない場合に発生します。 このような状況では、プラスのランレングスを与える唯一の方法は、ワイルドカードに完全に依存することです。すべての文字に対して同時に十分なワイルドカード スペースを確保できなければ、間違った楽観的な答えにつながります。 実現可能性チェックではグローバルな一貫性が強制され、文字が誤って不足することがないようになります。 

もう 1 つのエッジ ケースは、文字列が固定文字を密に交互に配置し、互換性のない制約の間にワイルドカードが散在する場合です。 貪欲なフィルでは領域が誤ってマージされる傾向がありますが、間隔ベースの DP はオーバーラップを強制する配置を正しく拒否し、高度に断片化された入力でも正確さを維持します。
