 ## 解決策
 ## 問題の理解

 小文字で構成される文字列と、各文字に数値の重みを割り当てる方法が与えられています。 完全な文字列の値は、位置インデックス (1 から始まる) とその位置の文字の重みの積をすべての位置で合計することによって計算されます。 したがって、後から配置されたキャラクターは乗数が大きいため、貢献度が高くなります。 

正確に挿入することもできます`k`文字列内の任意の場所に小文字を追加します。 挿入された各文字は、最終的な文字列内の位置に独自の重みを乗じた値に寄与し、文字を挿入すると、その後のすべてが 1 つ右にシフトされ、乗数が増加します。 目標は、最終的な加重合計が最大になるように、挿入される文字とその位置の両方を選択することです。 

制約は小さく、文字列の長さは最大 1000 です。`k`これは、位置に関する 2 次または 3 次推論が許容されることを直ちに示唆しますが、各挿入には 26 の選択肢と 2000 の位置があり、指数関数的な爆発につながるため、考えられるすべての挿入構成を総当りで実行することは不可能です。 

挿入について貪欲に推論すると、微妙な問題が発生します。 単純な考えは、後の位置の乗数が大きくなるため、最高値の文字を常に最後に配置することです。 これは、最後に文字を挿入すると長さが長くなり、それ以前のすべての文字の寄与も増えるため、失敗します。 もう 1 つの罠は、実際には各挿入によって後続のすべてのインデックスが変更されるにもかかわらず、挿入が独立していると考えることです。 

## アプローチ

 ブルートフォースビューは、あらゆる挿入方法を試すことです。`k`文字を文字列に入力し、結果のスコアを直接計算します。 挿入位置を固定したとしても、各位置にどの文字を挿入するかを選択する必要があります。 これはおおよそ次のことにつながります$\binom{n+k}{k} \cdot 26^k$たとえ小さな入力であっても、実現可能性をはるかに超えています。 各構成を評価するコストは最終的な長さに比例するため、このアプローチはすぐに破綻します。 

重要な観察は、値関数が位置ごとの文字の寄与において線形であるということです。 重要なのは、挿入のために選択する絶対的な位置ではなく、全体的にどの文字を使用するかを決定し、それらの文字を何個挿入するかです。 

挿入された文字のマルチセットを修正したら、後の位置ほど重みが大きくなるため、値の高い文字をできるだけ右に配置することが常に最良の戦略になります。 これにより、問題は、各文字を何文字挿入するかを決定し、挿入されたすべての文字を重みの増加しない順に文字列の末尾に貪欲に配置することに変わります。 元の文字列の順序は保持されます。これは、以前に出現した文字列の位置乗数が小さいため、元の文字の順序を変更しても問題が生じるだけであるためです。 

したがって、解決策は次のようになります。元の文字列を固定として扱い、追加します`k`最適に選択された文字。 順序は重みによってのみ重要となるため、挿入された文字は重みによってソートされ、最後に配置される必要があります。 

これにより、問題は、最良のものを選択するという単純な貪欲な構造に縮小されます。`k`文字 (繰り返しを許可) を重みの降順に追加します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n + k log 26) | O(26 + n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各文字の位置を指定する式を使用して、元の文字列の現在の寄与を計算します。`i`貢献する`i * w[c]`。 これは固定されており、並べ替えによって変更することはできないため、単純に蓄積されます。 
2. すべての文字の重みを抽出し、どの文字が最大の重みを持つかを特定します。 任意の文字を挿入できるため、すべての挿入でこの最大ウェイト文字を使用する必要があります。 

その理由は、各挿入が合計に直線的に寄与するため、挿入された文字をより重みの低い文字に置き換えると結果が厳密に減少するためです。 
3. を追加して最終的な文字列を構築します。`k`この最良の文字を元の文字列にコピーします。 挿入を元の文字列内にインターリーブする必要はありません。挿入を前に配置すると位置乗数が減少し、最後に挿入するとインデックスが最大化されるためです。 
4. 挿入された文字の寄与を計算します。 最後を占めているので、`k`位置、そのインデックスは次のように固定されています`n+1`に`n+k`したがって、それらの合計貢献度は、それらのポジションに対する単純な算術評価となります。 
5. 元の投稿と挿入された投稿を加算して、答えを取得します。 

### なぜ効果があるのか

 値関数は位置に対して線形であり、挿入は位置のシフトによる順序付けにのみ影響します。 以前に配置された挿入されたキャラクターはそれ自体の重み乗数を減らし、元のキャラクターをより高い位置に押し上げますが、それらの元の寄与は相対的な順序ですでに固定されています。 挿入された文字は、他の挿入された文字の寄与を損なうことなく常に右に移動できるため、最適な配置により、すべての挿入が常に最後まで押し出されます。 これが確立されると、各挿入は独立し、利用可能な最大の文字の重みを使用する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    k = int(input())
    w = list(map(int, input().split()))
    
    n = len(s)
    
    # original contribution
    base = 0
    for i, ch in enumerate(s, start=1):
        base += i * w[ord(ch) - ord('a')]
    
    mx = max(w)
    
    # inserted letters occupy positions n+1 ... n+k
    # all are best letter
    for i in range(1, k + 1):
        base += (n + i) * mx
    
    print(base)

if __name__ == "__main__":
    solve()
```コードは、挿入された文字から元の文字列の寄与を分離します。 元のループはスコアリング関数の定義を直接適用します。 次に、最大の重み文字を選択し、それを最後の文字に配置することで、可能な限り最良の挿入寄与を計算します。`k`インデックスが正確にわかっている位置。 

よくある間違いは、文字列への挿入を段階的にシミュレートしようとすることです。これにより、不必要な複雑さが発生し、インデックスのシフト時に off-by-one エラーが発生します。 このソリューションは、最終位置について直接推論することにより、すべてのシフトを回避します。

 ## 特殊なケース

 主なエッジケースは次のような場合です`k = 0`。 アルゴリズムはすべての挿入ロジックをスキップし、元のスコアのみを計算する必要があります。 挿入ループは 0 回実行され、基本寄与のみが残るため、実装はこれを自然に処理します。 

別のケースは、すべての重みが等しい場合です。 挿入の選択肢はどれも同等になるため、アルゴリズムは最大重みの文字を選択することによって有効な最適な戦略を選択します。 文字の選択に関係なく、挿入されたすべてのコントリビューションが同一であるため、計算は正しいままです。 

文字列の長さが 1 の場合、`k`が大きい場合、挿入された寄与が優勢になります。 アルゴリズムは、すべての挿入を位置 2 ～ に正しく配置します。`k+1`、追加の各キャラクターが乗数の増加に寄与することを保証します。これは、線形スコアリングの下で​​はまさに最適な配置です。
