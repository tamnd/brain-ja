 ## 解決策
 ## 問題の理解

 私たちは、固定数のバケットを使用してハッシュ テーブルへの挿入をシミュレートする任務を負っています。 各バケットには最大 1 つの要素を保持できます。 ハッシュ関数は単純です: 数値の場合$x$、ターゲットバケットは$x \mod p$。 一連の数字を受け取るので、それらを順番に挿入する必要があります。 番号の宛先がすでに占有されているバケットである場合、競合が発生します。 目的は、最初の競合を引き起こす挿入のインデックス、または競合が発生しない場合は -1 を報告することです。 

入力により得られるのは、$p$、バケットの数、および$n$、挿入する数値の数、その後に続きます。$n$数字。 両方$p$そして$n$最大 300 であり、それぞれの数値は次のように大きくなります。$10^9$。 これにより、単純な O(n) または O(n²) シミュレーションでも実行可能になりますが、不必要なネストされたループは避ける必要があります。 

明らかではないエッジ ケースには、同じ数値を複数回挿入する場合や、モジュロ演算で衝突するが別個の数値が挿入される場合などが含まれます。 たとえば、次の場合$p=3$入力シーケンスが 1、4、7 である場合、モジュロ結果はすべて 1 です。最初の 2 つの挿入はバケットを正常に占有しますが、3 番目の挿入で競合が発生します。 モジュロで以前の挿入をチェックしない不注意な実装では、同じバケットへの複数の挿入が誤って許可されてしまいます。 

## アプローチ

 ブルートフォースアプローチは、配列のサイズを維持することです。$p$バケットを表します。 挿入のたびに、ターゲット バケットが占有されているかどうかがチェックされます。 存在する場合は、インデックスを返します。 このアプローチは、ハッシュ テーブルの動作を忠実にシミュレートするため、正しいです。 操作数は最大 300 挿入 × 挿入ごとに 1 チェックであり、指定された制限を考慮するとわずかです。 ネストされたループや複雑なデータ構造は必要ありません。 

もう少し洗練されたソリューションの重要な洞察は、モジュロ演算によりバケット インデックスが 0 から 0 までの範囲にあることが保証されることを認識することです。$p-1$。 これにより、固定サイズの配列を使用して占有フラグを格納できるようになり、動的なデータ構造が不要になります。 配列インデックスはバケット番号に直接対応するため、すべての検索と更新は O(1) です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | O(p) | 承認済み |
 | 最適 | O(n) | O(p) | 承認済み |

 この問題については、入力サイズが小さく、漸近的な改善は不可能であるため、基本的にブルート フォースが最適です。 

## アルゴリズムのチュートリアル

 1.読む$p$そして$n$入力から。 配列を初期化する`occupied`サイズの$p$すべての要素を False に設定します。 この配列は、どのバケットがすでに満たされているかを追跡します。 
2. 1 から始まるインデックスを使用して一連の数値を反復処理します。$i$。 それぞれの番号について$x$、ターゲット バケットを次のように計算します。`bucket = x % p`。 
3. 次のことを確認します。`occupied[bucket]`は本当です。 そうであれば、競合が発生しているため、すぐに印刷します。$i$そして出ます。 
4. バケットが空いている場合は、次のように設定します。`occupied[bucket]`True に設定し、次の番号に進みます。 
5. すべての数値が競合せずに処理された場合は、-1 を出力します。 

このアルゴリズムが機能する理由は、`occupied`配列は、どのバケットが使用されているかを常に正確に反映します。 挿入するたびに、バケットが占有されているとマークされるか、競合が検出されます。 各番号は 1 回だけチェックされるため、競合を見逃す可能性はありません。 The invariants are that`occupied[bucket]`以前の数値がそのバケットに挿入され、インデックスが挿入された場合にのみ True になります。$i$返されたものは最初の競合であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

p, n = map(int, input().split())
occupied = [False] * p

for i in range(1, n + 1):
    x = int(input())
    bucket = x % p
    if occupied[bucket]:
        print(i)
        break
    occupied[bucket] = True
else:
    print(-1)
```最初の行にはバケットの数と数値が表示されます。 の`occupied`配列はバケットの使用状況を追跡するために初期化されます。 このループは、挿入インデックスに対する問題の要件に直接一致するように、1 から始まるインデックス付けを繰り返します。 モジュロ演算により正しいバケットが計算されます。 の`else`for ループ上の は、ループが中断せずに完了した場合にのみ実行され、「競合なし」の場合を適切に処理します。 

微妙な実装ポイントは、結果に 1 から始まるインデックスを使用することです。 ここでは、誤って戻った場合に、1 つ違いのエラーがよく発生します。`i-1`またはループをゼロから開始します。

 ## 特殊なケース

 このアルゴリズムは、次より大きい数値を処理します。$p$なぜなら、モジュロはそれらを有効なバケットインデックスに還元するからです。 繰り返される番号は、最初の繰り返しで競合として正しく識別されます。 最小サイズの入力の場合、ループは中断せずに完了し、`else`句を実行し、-1 を返します。 すべての痕跡がそれを裏付けています`occupied`バケットの使用状況を忠実に記録し、返されたインデックスは常に最初の競合に対応します。
