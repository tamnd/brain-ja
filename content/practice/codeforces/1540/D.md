 ## 解決策
 ## 問題の理解

 配列$b$任意ではありません。 あらゆるポジションについて$i$、$b_i$より大きい順列の以前の要素がいくつあるかを示します。$p_i$。 

最初だけ見てみると$i$順列の要素、つまり正確に$b_i$そのうちの大きいものは$p_i$、まさにそのとおりです$i-1-b_i$そのうちの小さいものです。 つまりランクは$p_i$最初のうちに$i$要素は$$r_i=i-b_i.$$全体の順列はこれらのランクによって一意に決定されます。 クエリは、次の個々の値を変更します。$b$、1ランク変わります$r_i$、その後のクエリでは最終値が要求されます。$p_i$。 

制約こそが本当の課題なのです。 両方$n$そして$q$と同じくらい大きい$10^5$。 更新のたびに順列全体を再構築するには、少なくとも次のものが必要になります。$O(n)$更新ごとに作業するため、おおよそ$10^{10}$最悪の場合の運用。 すべてのクエリで配列全体に影響を与えるソリューションは、直ちに除外されます。 

微妙な点は、更新が後の多くの位置に間接的に影響を与えることです。 考慮する```
n = 3
b = [0, 0, 0]
```に相当する```
p = [1, 2, 3].
```変更のみ$b_2$に$1$生成する```
b = [0, 1, 0]
```そして今の順列は次のようになります```
p = [2, 1, 3].
```位置のみを更新しようとする単純なアプローチ$2$位置の値が$1$も変わります。 

もう 1 つの簡単な間違いは、複数の順列が存在する可能性があると仮定することです。 反転ベクトル表現は実際に一意の順列を決定します。 例えば、```
b = [0, 1, 2, 3]
```力```
p = [4, 3, 2, 1].
```まったく自由がありません。 

## アプローチ

 最も直接的な解決策は、次のような観察から始まります。$$r_i=i-b_i$$地位のランクです$i$最初のうちに$i$要素。 

ある役職の順位がすでにわかっていると仮定します。$k$最初のうちに$t-1$要素。 位置決め時$t$が挿入されている場合、そのランクは$r_t$。 以上の既存のすべてのランク$r_t$1つずつシフトアップします。 

現在の役職のランクを表すと$k$による$x$、移行は$$x \leftarrow \begin{cases} x+1 & x \ge r_t\\ x   & x < r_t \end{cases}$$このトランジションをすべてに適用すると、$t>k$最終的に最終値を与える$p_k$。 

ブルート フォース クエリでは、その後のすべての挿入を単純にシミュレートできます。 これは反転ベクトルの定義に正確に従っているため、これは正しいです。 残念ながら、各クエリにはコストがかかります$O(n)$、そして$10^5$最終的に近いクエリ$10^{10}$操作。 

重要な観察は、後のすべての位置が小さな操作に寄与しているということです。$$T_a(x)=x+[x\ge a].$$ポジションのブロック全体は、そのような操作の単なる組み合わせです。 

ブロックを生の値として保存する代わりに、ブロック変換全体を保存します。 これらの操作を組み合わせたものは次のように表すことができます。$$F(x)=x+\#\{c_j\le x\},$$ソートされたブレークポイントのコレクションの場合$c_j$。 

ブロックがブレークポイント セットに圧縮されると、ブロック全体の適用が単一の二分探索になります。$$F(x)=x+\text{count}(c_j\le x).$$これにより、長い更新シーケンスがブロックごとに 1 つの操作に変わります。 平方根分解により、効率的な更新とクエリが行われます。

 ## アプローチ

 しましょう$$r_i=i-b_i.$$固定位置の場合$k$、 定義する$x_t$ポジション処理後のランクとして$1\ldots t$。 

当初は、$$x_k=r_k.$$位置決め時$t>k$少なくともすべてのランクが挿入されます$r_t$上にシフトします:$$x_t=x_{t-1}+[x_{t-1}\ge r_t].$$すべてのポジションを処理した後、$$p_k=x_n.$$各ポジション$t$オペレーターに貢献します$$T_{r_t}(x)=x+[x\ge r_t].$$後の接尾辞全体$k$は、このような演算子の組み合わせです。 

位置のブロックの場合、その構成は次のように書くことができます。$$F(x)=x+\#\{c_j\le x\},$$どこで$c_j$ソートされた順序で保存されます。 

ブロックの適用は単一の二分探索になります。```
x += number of breakpoints <= x
```どの費用がかかりますか$O(\log B)$。 

更新では 1 つの位置のみが変更されます。 その位置を含むブロックを再構築し、他のすべてのブロックは変更しないままにします。 

## アルゴリズムのチュートリアル

 1. 次を使用して反転数をランクに変換します。$r_i=i-b_i$。 
2. インデックスをおよそのサイズのブロックに分割します。$\sqrt n$。 
3. ブロックごとに、その圧縮変換を構築します。 

ブロック内のランクを左から右に処理します。 結果として得られるブロック変換は、ブレークポイントのソートされたリストによって表されます。$c_j$。 
4. 更新クエリの場合、対応するランクを変更します。$r_i$。 
5. を含むブロックのみを再構築します。$i$。 
6. 位置での値のクエリの場合$i$、から始めます$$x=r_i.$$7. 同じブロックの残りの要素を明示的に処理します。 

のみ$O(\sqrt n)$位置はそのブロックに属します。 
8. その後の完全なブロックごとに、保存されている変換を適用します。 

これは、ブロックのブレークポイント リストの二分探索によって行われます。$$x \leftarrow x+\#\{c_j\le x\}.$$9. すべての接尾辞ブロックが適用された後、出力$x$。 

### なぜ効果があるのか

 ランク$r_i=i-b_i$まさに～が占める位置です$p_i$最初のうちに$i$要素。 

ランクのある新しい要素が追加されるたびに$r_t$が挿入されると、既存のランクはすべて次の値以上になります$r_t$1つずつずれます。 移行$$x \leftarrow x+[x\ge r_t]$$したがって、その反転ベクトルから順列を構築する挿入プロセスと同じです。 

クエリ アルゴリズムは、これらの遷移を元の構造と同じ順序で適用します。 各ブロック変換は近似的ではなく正確に表現されるため、ブロック圧縮によって結果は変わりません。 したがって、アルゴリズムによって計算された最終的なランクは正確に次のようになります。$p_i$。 

## Python ソリューション```python
import sys
from bisect import bisect_right, insort

input = sys.stdin.readline

class SqrtDecomposition:
    def __init__(self, n, r):
        self.n = n
        self.r = r
        self.B = 320

        self.blocks = []
        self.bid = [0] * (n + 1)

        l = 1
        while l <= n:
            rr = min(n, l + self.B - 1)
            idx = len(self.blocks)
            for i in range(l, rr + 1):
                self.bid[i] = idx
            self.blocks.append([l, rr, []])
            l = rr + 1

        for b in range(len(self.blocks)):
            self.rebuild(b)

    def rebuild(self, b):
        l, r, _ = self.blocks[b]

        c = []

        for pos in range(l, r + 1):
            a = self.r[pos]

            lo, hi = 0, self.n
            while lo < hi:
                mid = (lo + hi) // 2
                if mid + bisect_right(c, mid) >= a:
                    hi = mid
                else:
                    lo = mid + 1

            insort(c, lo)

        self.blocks[b][2] = c

    def apply_block(self, b, x):
        c = self.blocks[b][2]
        return x + bisect_right(c, x)

    def update(self, pos, value):
        self.r[pos] = value
        self.rebuild(self.bid[pos])

    def query(self, pos):
        x = self.r[pos]

        b = self.bid[pos]
        l, r, _ = self.blocks[b]

        for i in range(pos + 1, r + 1):
            if x >= self.r[i]:
                x += 1

        for nb in range(b + 1, len(self.blocks)):
            x = self.apply_block(nb, x)

        return x

def solve():
    n = int(input())
    b = list(map(int, input().split()))

    r = [0] * (n + 1)
    for i in range(1, n + 1):
        r[i] = i - b[i - 1]

    ds = SqrtDecomposition(n, r)

    q = int(input())
    ans = []

    for _ in range(q):
        s = list(map(int, input().split()))

        if s[0] == 1:
            _, i, x = s
            ds.update(i, i - x)
        else:
            _, i = s
            ans.append(str(ds.query(i)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```配列`r`ランク表現を格納します$r_i=i-b_i$。 この形式では挿入動作がはるかに単純になるため、後のすべてのロジックはランクに基づいて動作します。 

各ブロックには、圧縮されたサフィックス変換が保存されます。 クエリ中に、現在のブロックの未完了部分が明示的に処理され、その後、単一の二分検索を使用して以降のすべてのブロックが適用されます。 

実装の最もデリケートな部分は、ブロックの再構築です。 ブレークポイント表現は、ブロック内のすべての演算子の正確な構成を記述する必要があります。 内部の二分探索`rebuild`変換されたランクが現在の要素の挿入ランクに達する最小値を見つけます。 これらのブレークポイントは、ブロック変換を完全に特徴づけます。

 ## 特殊なケース

 検討してください```
3
0 1 0
```それは与える$$r=[1,1,3].$$位置$1$ランクから始まります$1$。 位置$2$ランクもあります$1$, したがって、最初の位置が上にシフトされ、ランクになります。$2$。 現在のランクより大きい後のランクのみを検査するソリューションでは、誤ってランクを変更しないままにしてしまいます。 

もう一つの重要な事例は、```
4
0 1 2 3
```すべてのランクが等しい場合$1$。 新しく挿入された各要素は前に配置されます。 アルゴリズムはトランジションを繰り返し適用します$x \leftarrow x+1$、逆順列が生成されます。 これにより、等しい挿入ランクが正しく処理されることが確認されます。 

最後に、最後の位置に関するクエリを考えてみましょう。 そのサフィックスは空であるため、答えは正確に現在のランクでなければなりません。 ローカル スキャンも後続のブロックも処理されないため、実装はこれを自然に処理します。
