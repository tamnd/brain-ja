 ## 解決策
 ## 問題の理解

 この操作は隣接するペアに作用します。 させて$$d_i=a_{i+1}-a_i.$$もし$d_i\ge b_i$、操作は何も変わりません。 もし$d_i<b_i$、両方の値は、合計が同じで差が正確にある数値に置き換えられます。$b_i$。 

プロセスを表示する便利な方法は、累積値を差し引くことです。$b$-価値観。 

定義する$$p_1=0,\qquad p_i=\sum_{j=1}^{i-1} b_j,$$そして$$y_i=a_i-p_i.$$それから$$a_{i+1}-a_i\ge b_i$$になる$$y_{i+1}\ge y_i.$$違反ペアの場合$y_i>y_{i+1}$が選択されると、両方の値がその平均値に置き換えられます。 これはまさに、非減少になるはずのシーケンスに対する等張回帰で使用されるローカル操作です。 限界値$F(a,b)$は等張投影の最初の座標です。 アイソトニック回帰の標準的な特性は、最初の投影値が元のシーケンスの最小プレフィックス平均に等しいということです。 それを適用すると、$y$与える$$F(a,b)=\min_{k\ge1} \frac{\sum_{i=1}^{k}(a_i-p_i)}{k}.$$制約は小さいです。 我々は持っています$n\le100$そしてすべての$c_i\le100$したがって、すべての配列要素の可能な合計は最大でも$10000$。 これは、プレフィックス合計に対する動的プログラミング ソリューションを即座に示唆します。 

よくある間違いは、収束プロセスをシミュレートすることです。 制限には小数値が含まれており、プロセスは無限であり、いつ停止するかの判断さえ不明確です。 実際のソリューションでは、操作をシミュレートすることはありません。 

別の微妙なケースが現れるのは、$x$とても大きいです。 一部のプレフィックス平均に必要な下限が、可能な最大プレフィックス合計を超える場合、答えは自動的にゼロになります。 すべての状態が無効になるため、DP はこれを自然に処理します。 

考慮する```
n = 2
c = [0, 0]
b = [100]
x = 1
```唯一可能な配列は次のとおりです$[0,0]$、 そして$F(a,b)\le0$、したがって、答えは次のとおりです$0$。 プレフィックス平均の特徴付けを無視するソリューションでは、これを簡単に見逃す可能性があります。 

もう一方の極端では、```
n = 2
c = [0, 0]
b = [100]
x = -100000
```適切な配列はすべて条件を満たすため、答えは次のようになります。$1$。 大規模な否定クエリは DP 状態空間を壊してはなりません。 

## アプローチ

 最も直接的なアイデアは、適切な配列をすべて列挙することです。$a$、収束プロセスを実行し、計算します$F(a,b)$、有効なものを数えます。 

配列の数は$$\prod_{i=1}^{n}(c_i+1).$$と$n=100$そして$c_i=100$、これは天文学的な大きさです。 収束シミュレーションを考える前に、列挙することは不可能です。 

重要な観察は、収束プロセスが閉じた形式で記述されているということです。 変身後$$y_i=a_i-p_i,$$このプロセスは、非減少でなければならないシーケンスに対する等張回帰になります。 制限の最初の値は、最小プレフィックス平均と等しくなります。$$F(a,b)=\min_k \frac{\sum_{i=1}^{k}(a_i-p_i)}{k}.$$今の状態は$F(a,b)\ge x$になる$$\frac{\sum_{i=1}^{k}(a_i-p_i)}{k}\ge x$$すべてのプレフィックスに対して$k$。 

乗算$k$、$$\sum_{i=1}^{k} a_i \ge \sum_{i=1}^{k}(p_i+x).$$問題はもはや収束に関するものではありません。 それは次のようになります:

 配列をカウントする$0\le a_i\le c_i$そのプレフィックスの合計が下限のコレクションを満たす。 

すべての可能な合計値なので、$a_i$せいぜい$10000$、プレフィックス合計に対する DP は完全に実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙とシミュレーション | 指数 | 指数 | 遅すぎる |
 | プレフィックス合計 DP |$O(n \cdot S)$|$O(S)$| 承認済み |

 ここ$S=\sum c_i\le10000$。 

## アルゴリズムのチュートリアル

 1. 累積配列を計算する$$p_1=0,\qquad p_i=\sum_{j=1}^{i-1} b_j.$$2. プレフィックス長ごとに$k$、必要な下限を計算します$$R_k=\sum_{i=1}^{k}(p_i+x).$$条件$F(a,b)\ge x$これは、次のすべてのプレフィックスの合計を要求することと同じです。$a$少なくとも$R_k$。 
3. しましょう$S=\sum c_i$。 DP を使用する場合$dp[s]$現在のプレフィックスの合計が等しくなるように処理された要素を選択する方法の数です。$s$。 
4. 最初は、$dp[0]=1$。 
5. 位置を左から右に処理します。 
6. 位置を処理しているとします。$i$。 以下から任意の値を追加できます。$0$に$c_i$。 

移行は、$$ndp[s] = \sum_{t=s-c_i}^{s} dp[t].$$これは有界ナップザック遷移です。 
7. DP 配列のプレフィックス合計を使用して、これらすべての範囲合計を評価します。$O(1)$それぞれ。 
8. フィニッシュポジション後$i$、プレフィックスの合計が以下のすべての州を削除します。$R_i$。 

このような状態は、必要な接頭辞の不等式の 1 つにすでに違反しており、後で有効になることはありません。 
9. すべての位置を処理した後、残りのすべての DP 状態を合計します。 
10. 結果のモジュロを出力します。$10^9+7$。 

### なぜ効果があるのか

 アイソトニック回帰の特徴付けにより、次のことがわかります。$$F(a,b)\ge x$$すべてのプレフィックスの平均が$a_i-p_i$少なくとも$x$。 

これらの不等式を書き直すと、$$\sum_{i=1}^{k} a_i \ge R_k$$すべてのプレフィックスに対して$k$。 

DP は、値の境界を満たすすべての配列を正確に列挙します。$0\le a_i\le c_i$。 各位置の後、現在のプレフィックスの合計が対応する下限に違反しているすべての状態を削除します。 ステップで削除された状態$k$この状態はすでに修正されたプレフィックスに関するものであるため、後で修復することはできません。 

すべての有効な配列は DP を通過する 1 つのパスにのみ寄与し、残りのすべての DP パスは有効な配列に対応します。 したがって、最終的なカウントは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n = int(input())
c = list(map(int, input().split()))
b = list(map(int, input().split()))
q = int(input())
x = int(input().split()[0])

p = [0] * n
for i in range(1, n):
    p[i] = p[i - 1] + b[i - 1]

need = [0] * n
cur = 0
for i in range(n):
    cur += p[i] + x
    need[i] = cur

tot = sum(c)

dp = [0] * (tot + 1)
dp[0] = 1

for i in range(n):
    pref = [0] * (tot + 2)
    for s in range(tot + 1):
        pref[s + 1] = (pref[s] + dp[s]) % MOD

    ndp = [0] * (tot + 1)

    lim = c[i]
    for s in range(tot + 1):
        l = max(0, s - lim)
        ndp[s] = (pref[s + 1] - pref[l]) % MOD

    bound = need[i]
    if bound > 0:
        upto = min(tot, bound - 1)
        for s in range(upto + 1):
            ndp[s] = 0

    dp = ndp

print(sum(dp) % MOD)
```最初のブロックは、変換されたオフセットを計算します。$p_i$。 これらは次の累積合計です。$b$-array で、等張回帰ビューの各位置から減算される量を表します。 

配列`need`下限を保存します$R_k$すべてのプレフィックスに対して。 DP 中に、以下のプレフィックスの合計`need[i]`は無効です。 

この遷移は、標準的な境界付きナップザックの繰り返しです。 目標金額ごとに`s`、間隔内の以前の合計から取得することができます$$[s-c_i,\, s].$$プレフィックスサム配列を使用する`dp`、各遷移は単一の範囲合計クエリになります。 

剪定のステップは非常に重要です。 加工後の位置`i`、プレフィックスの合計が以下のすべての州`need[i]`すぐに削除されます。 このチェックを遅らせると、必須の不等式の 1 つにすでに違反している配列がカウントされます。

import sys, io

def run(inp: str) -> str:
    MOD = 10**9 + 7

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    c = list(map(int, input().split()))
    b = list(map(int, input().split()))
    q = int(input())
    x = int(input().split()[0])

    p = [0] * n
    for i in range(1, n):
        p[i] = p[i - 1] + b[i - 1]

    need = [0] * n
    cur = 0
    for i in range(n):
        cur += p[i] + x
        need[i] = cur

    tot = sum(c)

    dp = [0] * (tot + 1)
    dp[0] = 1

    for i in range(n):
        pref = [0] * (tot + 2)
        for s in range(tot + 1):
            pref[s + 1] = (pref[s] + dp[s]) % MOD

        ndp = [0] * (tot + 1)

        for s in range(tot + 1):
            l = max(0, s - c[i])
            ndp[s] = (pref[s + 1] - pref[l]) % MOD

        if need[i] > 0:
            upto = min(tot, need[i] - 1)
            for s in range(upto + 1):
                ndp[s] = 0

        dp = ndp

    return str(sum(dp) % MOD)
