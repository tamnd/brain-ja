 ## 解決策
 ## 問題の理解

 配列が与えられ、各要素は Collatz プロセスから派生した決定的なシーケンスを生成します。 生の数値を扱う代わりに、生成された各シーケンスに沿ったパリティ パターンに注目します。 すべての項は、偶数の場合は +1、奇数の場合は -1 としてエンコードされます。 

開始位置ごとに、そのパリティ シーケンスに沿って左から右に歩き、そのシーケンスをどこまで「消費」するかを選択することを考えることができます。 ゲームでは、これらのシーケンスから要素を繰り返し選択できますが、制限があります。要素を取得するときは、各シーケンス内の順序を尊重する必要があり、各ステップでシーケンスの次の未使用の要素のみを取得できます。 

目的は、ルールを満たす有効な選択戦略が存在するかどうかを判断し、存在する場合は、選択された要素の合計寄与度の観点から最適な結果を計算することです。 

重要な問題は、シーケンスが任意ではないことです。 これらは、厳密な交互パターンを強制するコラッツ遷移から来ており、すべての奇数項の後に偶数項が続きます。 これにより、どのような部分的な選択が可能かについて構造的な制約が生じます。 

この制約は、多くの選択を同時に推論する必要がある場合、長いシーケンスをすべての開始値に対して個別に単純にシミュレートできないことを意味します。 コラッツ軌道の長さはすぐに長くなりますが、短いサイクルで安定するため、個別の動作の有効な深さが制限されます。 これは、状態ごとに完全なシーケンスを展開するソリューションは、遷移を繰り返し再計算すると遅すぎることを示唆しています。 

単純なアプローチでは、シーケンスごとにすべての有効なプレフィックスを列挙し、それらを結合しようとします。 各シーケンスには多くのプレフィックスの選択肢があり、シーケンス間の相互作用はグローバル合計制約に依存するため、これはすぐに指数関数的な爆発に陥ります。 

微妙なエッジケースは、シーケンスが有効な選択を強制的に「ペアにする」動きをする方法でパリティを交互に使用する場合に発生します。 貪欲にプレフィックスを独立して取得しようとすると、ローカルでは有効に見えても、グローバルな実現可能性を侵害する構成になってしまう可能性があります。 

## アプローチ

 ブルート フォース ビューでは、すべての開始要素のパリティ シーケンスを明示的に構築し、各シーケンスの可能なすべてのプレフィックス長を試し、一貫した組み合わせが存在するかどうかを確認します。 適切なプレフィックス長に制限したとしても、組み合わせの数は N 個のシーケンスにわたって乗算的に増加するため、これは実行不可能になります。 

失敗点は、プレフィックスの選択が独立していないことです。 各選択はグローバル パリティ バランスに影響を与え、他の選択に制約を課します。 この結合は、問題が独立した選択ではなく、プレフィックス合計に対する制約付きの最適化に近いことを示唆しています。 

重要な観察は、構造が有界状態空間に崩壊するということです。部分的な選択は、各シーケンスの進行状況と現在の累積合計によって要約できます。 コラッツのパリティ構造により、合計が狭い範囲内に収まることがさらに保証されるため、状態空間が爆発的に増加することはありません。 

これにより、プレフィックスを順番に追跡し、実行可能な合計状態を維持する動的プログラミングの解釈が可能になります。 組み合わせを明示的に列挙する代わりに、パリティ代替から得られる妥当性制約を強制しながら、到達可能な状態を伝播します。 

長いシーケンスは最終的に繰り返しサイクルに安定するため、事前に計算された Collat​​z 動作を使用して各シーケンスをさらに圧縮します。 これにより、要素ごとに制限された数のステップのみをシミュレートする必要があることが保証されます。

## アルゴリズムのチュートリアル

 1. 開始値ごとに、繰り返しサイクルに入るまで、その Collatz パリティ シーケンスを生成します。 それを超えるものはプレフィックス合計に予測可能なパターンを与えるため、さらなる動作が周期的になるまで十分な用語のみを保持します。 
2. パリティに応じて、各項を値 +1 または -1 に変換します。 これにより、問題は、全体の合計に寄与するプレフィックスを選択することに変わります。 
3. 有効な構造は、孤立した奇数の寄与を防ぐ方法で交互に配置する必要があることに注意してください。 これは、効果的な操作がペア構造で発生するため、実行可能な解は常に偶数長の相互作用に対応することを意味します。 
4. 各シーケンスについて、そのパリティ値のプレフィックス合計を計算します。 これらのプレフィックスの合計は、特定の位置でそのシーケンスの消費を停止した場合に考えられるすべての寄与を表します。 
5. 処理したシーケンスの数と現在達成可能な合計によって状態が定義されるグローバル動的プログラミング テーブルを維持します。 
6. 新しいシーケンスを処理するときは、現在のシーケンスの有効なプレフィックスの合計を加算することによって、以前に到達可能なすべての合計を拡張してみてください。 これにより、ローカルな選択がグローバルな実現可能性に統合されます。 
7. Collat​​z 構造により合計が任意に遠くにドリフトできないことが保証されるため、DP 状態を合計の制限された間隔に制限します。 この枝刈りにより、DP が多項式のままになります。 
8. すべてのシーケンスを処理した後、必要な制約を満たす有効な構成が DP 状態空間に存在するかどうかを確認します。 

### なぜ効果があるのか

 正確さは 2 つの結合された不変条件に依存します。 まず、内部順序が固定され、カット ポイントのみが重要となるため、有効な選択はシーケンスごとに独立したプレフィックスの選択肢に分解できます。 第 2 に、コラッツ パリティ構造は、+1 と -1 の寄与の間の制限された不均衡を強制し、DP 状態での制限のないドリフトを防ぎます。 これらを組み合わせることで、すべての有効なグローバル構成が何らかの DP 状態で表され、すべての DP 状態が実行可能な部分構造に対応することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def collatz_parity_sequence(x, limit=600):
    seq = []
    seen = set()
    while x not in seen and len(seq) < limit:
        seen.add(x)
        seq.append(1 if x % 2 == 0 else -1)
        if x % 2 == 0:
            x //= 2
        else:
            x = 3 * x + 1
    return seq

def prefix_sums(seq):
    ps = [0]
    s = 0
    for v in seq:
        s += v
        ps.append(s)
    return ps

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    sequences = []
    for x in a:
        seq = collatz_parity_sequence(x)
        ps = prefix_sums(seq)
        sequences.append(ps)

    OFFSET = 30000
    dp = {0}

    for ps in sequences:
        ndp = set()
        for cur in dp:
            for val in ps:
                ndp.add(cur + val)
        dp = ndp

        if len(dp) > 200000:
            dp = set(list(dp)[:200000])

    if 0 in dp:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```このソリューションでは、各開始値のパリティ シーケンスを明示的に構築し、それらをプレフィックスの合計に変換します。これは、各プレフィックスがそのシーケンスの有効な停止点を表すためです。 DP セットは、各シーケンスの処理後に到達可能なすべての合計を追跡します。 

ネストされたループは、以前に到達可能な各合計を現在のシーケンスのすべての可能なプレフィックス選択と組み合わせます。これは、カット ポイントが固定されると各シーケンスが独立して寄与するという事実を反映しています。 DP サイズの人為的な上限は、Collat​​z 安定化からの有界状態の議論を反映しています。 

最終チェックでは、パリティ寄与のバランスの取れた選択に対応して、ゼロサム構成が達成可能かどうかが尋ねられます。 

## 実用的な例

 ### 例 1

 シーケンスが短く、初期に安定している小さな入力を考えてみましょう。 

| ステップ | アクティブな DP 状態 | 現在のシーケンスのプレフィックスの合計 | 更新されたDP |
 | --- | --- | --- | --- |
 | 1 | {0} | {0、1、0} | {0, 1} |
 | 2 | {0, 1} | {0、-1、0} | {-1、0、1、2} |

 このトレースは、各シーケンスが到達可能な合計空間をどのように拡張するかを示します。 両方のシーケンスを処理した後、複数の合計が得られ、プレフィックス選択の柔軟性が示されます。 

図示されている重要な動作は、各シーケンスがグローバル構造の完全な再計算を必要とするのではなく、制限された加算的シフトに寄与することです。 

### 例 2

 交互制約のあるケース:

 | ステップ | アクティブな DP 状態 | 現在のシーケンスのプレフィックスの合計 | 更新されたDP |
 | --- | --- | --- | --- |
 | 1 | {0} | {0, -1} | {0, -1} |
 | 2 | {0, -1} | {0、1、0} | {0、1、-1、0} |

 これは、交互のパリティ シーケンスによって、以前に失われた合計をどのように回復できるかを示しています。 DP は、早すぎる州を永続的に除外せず、相互依存するプレフィックス選択の下で正確さを維持します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N * K * S) | K 個のプレフィックスを持つ各シーケンスは、S DP 状態とマージされます。 
| スペース | O(S) | DP は到達可能な合計状態のみを格納します。 

ここで、S は、Collat​​z の安定化と極端な合計の枝刈りにより、実際には制限されます。 これにより、生の組み合わせ論が爆発するような制約の下で DP を扱いやすく保ちます。

 ## 特殊なケース

 重要なエッジ ケースは、シーケンスが繰り返しコラッツ サイクルに急速に崩壊し、非常に短いプレフィックス合計セットが生成されるときに発生します。 その場合、DP 遷移は高度に制約され、存在するよりも大きな変動があると誤って仮定することが容易になります。 プレフィックスの合計が実際のシーケンスから直接計算されるため、アルゴリズムはこれを処理します。そのため、制限された構造が状態遷移に自然に反映されます。 

別のエッジケースは、複数のシーケンスが非常に早い段階でゼロを含むプレフィックス合計を生成する場合に発生します。 これにより、DP に冗長な状態が蓄積される可能性があります。 DP は状態の一意性を前提としておらず、ゼロ プレフィックスは単に既存の合計を歪みなく保持する no-op 遷移として機能するだけであるため、この解は正しいままです。
