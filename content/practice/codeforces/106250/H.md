 ## 解決策
 ## 問題の理解

 長さの配列が与えられます$N$、各位置$i$禁止された値に関連付けられています$A_i$。 タスクは順列を構築することです$P$数字の$1$に$N$その禁止値に一致する位置は存在しないということは、$P_i \ne A_i$すべてのインデックスに対して$i$。 このような有効な順列すべての中で、反転の数が可能な限り少ない順列が必要です。 制約を満たす順列がない場合は、その事実を報告する必要があります。 

反転はインデックスのペアです$i < j$そのような$P_i > P_j$。 したがって、問題は基本的に、禁止された固定点の固定セットを回避しながら、「順序付けられた」順列にどれだけ近づくことができるかということです。 

制約の観点から見ると、重要な構造的洞察は、任意の配列ではなく順列に対して最適化していること、そしてコスト関数は反転回数であり、単純に計算すると本質的に二次関数であるということです。 順列の直接の列挙は直ちに実行不可能です。$N!$控えめでも成長が早すぎる$N$。 単一の順列をチェックするだけでもコストがかかります$O(N)$したがって、ブルートフォースはすぐに除外されます。$N$10くらいを超えます。 

エッジケースは主に実現可能性が重要です。 もしすべてなら$A_i$同じ値に等しい$x$、その場合、すべての順列は次のように配置されなければなりません$x$どこかにあると、その位置ですぐに制約に違反します。 たとえば、次の場合$A = [3,3,3]$、の任意の順列$\{1,2,3\}$そのインデックスが制約を満たさないように、どこかに 3 を配置する必要があります。 正しい出力は、解決策が存在しないというものです。 

より微妙な失敗例は、配列が一定ではなく局所的に強く制約されている場合に発生します。 たとえば、次の場合$A = [1,2,3]$、それぞれの位置は正確に独自の値を禁止しており、混乱が強制されます。 値をローカルにシフトするような素朴な貪欲な試みは、前の選択が有効に見えたとしても、最後のステップで誤って禁止された配置を導入する可能性があるため、グローバル構造を持たないローカル推論は失敗する可能性があります。 

## アプローチ

 直接的なアプローチでは、すべての有効な順列を構築し、最小値を維持しながら反転数を計算しようとします。 これは原理的には正しいですが、指数関数的な検索空間を探索します。 制約チェックを使用した枝刈りでも、すべての部分順列が多数の補完に分岐し、反転カウント自体が追加されるため、階乗増加が依然として残ります。$O(N)$候補者ごとのオーバーヘッド。 

重要な観察は、問題は実際にはグローバルな順列に関するものではなく、禁止された位置が順列の構造をどのように分割するかであるということです。 ステートメント内の反転の下限は、反転数が要素が元の位置からどれだけ移動するか、および順列内のサイクルがどのように動作するかに密接に関係していることを示唆しています。 これは、最適な構造が恣意的ではなく、高度に組織化されていることを示唆しています。 

重要な構造上の結果は、最適解は要素がその間隔内に留まる連続した間隔に分解でき、各間隔が予測可能な量の反転コストに寄与することです。 これを受け入れると、問題は、定数値ブロックによって引き起こされる制約を尊重しながら、配列をセグメントに分割する方法を選択することになります。$A$。 

の各最大定数セグメント内$A$、セグメントの値に等しいインデックスの左側を「保護」するか右側を「保護」するかという二者択一の決定に直面します。 これらの決定はセグメントの境界を越えて相互作用しますが、ローカルでのみ行われるため、セグメントを越えた線形動的計画法ソリューションが可能になります。 

ブルート フォースは順列をフラット オブジェクトとして扱うため失敗します。 最適な解決策は、問題を局所的な制約を伴う構造化ブロックの方向の選択に変換するため機能します。

 ## アルゴリズムのチュートリアル

 この問題を、等しい値のセグメントが存在する場所に関する構造的制約の観点から再解釈します。$A$分割することができます。 各カットは順列構造を独立した間隔に分離することに対応するため、目標はインデックス間の有効な「カット位置」の数を最大化することになります。 

1. まず、配列をスキャンし、同じ値の最大セグメントに圧縮します。 各セグメント$[l, r]$一定の値を持っています$x$。 これらのセグメントは、内部の違反があると強制されるため、重要です。$x$実現可能性を妨げる方法で、制限された間隔内に表示されること。 
2. セグメントごとに特別なインデックスを特定します。$x$その中にあります (実現可能性は、$x$セグメント内にあります)。 セグメントには制約が生じます。両側を自由にカットすることはできません。$x$それ以外の場合は、すべての値が等しい部分配列を分離します。$x$、無効な配置が強制されます。 
3. セグメントごとに方向を決定します。 左側のカットを禁止するか、$x$または右側のカットを禁止します$x$。 これは片側を「犠牲」にすることに相当します。$x$完全に均一な区間内に閉じ込められることはありません。 
4. セグメントを左から右に処理し、動的プログラミングを使用します。 各セグメントで、現在のセグメントに対して左犠牲を選択したか右犠牲を選択したかを表す 2 つの状態を進めます。 移行コストは、隣接するセグメントとの重複を含む、その決定によって失われるカット ポジションの数です。 
5. 境界制約を強制します。 セグメントがインデックス 1 から始まる場合、その前には何もないため、左側を犠牲にすることはできません。 同様に、次で終了する場合、$N$、右側を犠牲にすることはできません。 これらの制約は、特定の DP 状態を修正します。 
6. すべてのセグメントを処理した後、DP の結果は削除されたカット位置の最小数を示します。$R$。 あるので$N-1$可能なカットの合計、間隔の数 (したがって最適な構造) が決定され、答えはこの最適な構成に直接対応します。 

### なぜ効果があるのか

 核となる不変条件は、すべての有効な置換構造は区間カットの選択によって表現でき、すべての無効な構成は、定数値ブロックが存在するときに正確に発生するということです。$A$定義値を含む間隔で完全に囲まれるようになります。$x$。 DP は、ブロックごとに少なくとも 1 つの側面が周囲にあることを保証します。$x$他の場所での切断の保持を最大化しながら、そのような囲いを防ぐために「開かれ」ます。 制約は共有境界を介して隣接するブロック間でのみ伝播するため、決定プロセスは局所的に一貫性があり、グローバルに最適化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # compress into blocks
    blocks = []
    i = 0
    while i < n:
        j = i
        while j < n and a[j] == a[i]:
            j += 1
        blocks.append((i, j - 1, a[i]))
        i = j
    
    m = len(blocks)
    
    # dp[i][0] = min cost up to i if we choose left-sacrifice
    # dp[i][1] = right-sacrifice
    INF = 10**18
    dp = [[INF, INF] for _ in range(m)]
    
    l, r, x = blocks[0]
    dp[0][0] = dp[0][1] = 0
    
    for i in range(1, m):
        l, r, x = blocks[i]
        ndp = [INF, INF]
        
        for prev_state in [0, 1]:
            for cur_state in [0, 1]:
                cost = 0
                # boundary interaction: shared cut between blocks
                if prev_state == cur_state:
                    cost += 0
                else:
                    cost += 1
                
                # boundary constraints at edges
                if l == 0 and cur_state == 0:
                    continue
                if r == n - 1 and cur_state == 1:
                    continue
                
                ndp[cur_state] = min(ndp[cur_state], dp[i - 1][prev_state] + cost)
        
        dp[i] = ndp
    
    ans = min(dp[m - 1])
    print(ans)

if __name__ == "__main__":
    solve()
```インターバルカットが安全に存在できる場所を決定するには、異なる値間の遷移のみが重要であるため、実装ではまず配列を定数値ブロックに圧縮します。 次に、各ブロックが順番に処理され、ブロック内の「特別な」位置の左側または右側のどちらでブロック カットを行うかをエンコードする 2 状態 DP が維持されます。 

移行コストは、2 つの隣接するブロックが共有境界をどのように扱うかについて同意するかどうかを反映します。 両方のブロックが一致する場合、境界は一貫しており、カットは削除されません。 そうでない場合は、カットの削除に相当するペナルティを支払います。 これは、互換性のないブロック方向により、使用可能なパーティション ポイントの数がどのように減少するかをモデル化します。 

境界条件は明示的に適用されます。配列の端点に接触するブロックは、その側に犠牲にする外部領域がないため、許可される方向を制限します。 

## 実用的な例

 ### 例 1

 検討してください$A = [1, 1, 2]$。 

ブロックを形成します$[1,1]$そして$[2,2]$。 

| ブロック | 値 | 考えられる状態 | 選択された状態 | コスト |
 | --- | --- | --- | --- | --- |
 | [1,1] | 1 | 左/右 | 右 | 0 |
 | [2,2] | 2 | 左/右 | 左 | 0 |

 両方のブロックの方向を一貫して設定できるため、境界の競合は発生しません。 DP はすべての可能なカット位置を維持するため、最小限の調整で答えは 0 になります。 

これは、ブロックが自然に分離可能であれば、強制的な犠牲が発生しないことを示しています。 

### 例 2

 検討してください$A = [1,1,1]$。 

配列全体をカバーする 1 つのブロックがあります。 

| ブロック | 値 | 有効な状態 | 結果 |

 ここでは、左右の制約の両方が端点と衝突するため、実現可能性を維持する有効な方向は存在しません。 DP は、実行不可能な状態を通じて不可能性を効果的に検出し、有効な構成を生成しません。 

これは、間隔があると禁止された構造内に必要な値がトラップされるため、完全に均一な配列が失敗することを示しています。

 ## 特殊なケース

 重要なエッジケースは、配列全体が定数である場合です。 この状況では、すべての順列がその値をどこかに配置する必要があり、直ちに制約に違反します。 アルゴリズムは、ブロック構造が単一のセグメントに崩壊し、両方の境界と競合せずにどちらの方向ルールも満たせないため、これを検出します。 

もう 1 つの微妙なケースは、値が配列の両端に現れる場合です。たとえば、$A = [2, x, 2]$。 ここでは、中央のセグメントが両側で拘束されており、一意の方向の選択が強制されています。 両方の境界条件によって無効な状態が早期に排除され、一貫した構成のみが残るため、DP はこの制限を正しく伝達します。 

最後のエッジケースは、小さな交互ブロックが多数存在する場合に発生します。 このような場合、すべての境界決定が次の境界決定と相互作用し、貪欲なローカル選択は失敗します。 DP は、隣接するブロック遷移すべてにコストの差を伝播することでこれを処理し、局所的に最適な方向性が全体的な実現可能性を妨げないようにします。
