 ## 解決策
 ## 問題の理解

 1 から N までのインデックスが付けられた正の整数の未知の配列を使用しています。重要な構造上の約束は、この配列の 2 つの異なる要素は互いに素であるため、それらの最大公約数は常に 1 であるということです。 

配列に関する情報を取得する唯一の方法は、2 つの位置の積を明らかにするクエリを使用することです。 このような積から、配列内のすべての隠された値を回復することが目標です。 

問題は、要素に直接アクセスできないことです。 N に比例する厳密な上限、具体的には 3 つの要素あたり最大 2 つのクエリを使用して、非常に少数の積クエリを使用する戦略を設計する必要があります。 

N ≤ 100 という制約は、二次アプローチでも技術的には合格しますが、実際の制限は計算時間ではなくクエリ バジェットであることを意味します。 あまりにも多くのペアを検査したり、クエリを繰り返して要素を 1 つずつ再構築したりするソリューションは、許容されるインタラクション数を超えてしまいます。 

素朴なアプローチは、すべてのペア (i, j) をクエリし、gcd 関係を回復し、値を間接的に因数分解しようとすることです。 これは O(N²) クエリを必要とするため、すぐに失敗します。これは、N = 100 の場合でも許容制限をはるかに超えています。 

より微妙な失敗例は、隣接する製品のみを使用して各要素を個別に回復しようとした場合に発生します。 たとえば、a1·a2、a2·a3、a3·a4 のみを計算し、構造化されたグループ化を行わずに値を分離しようとすると、境界値が欠落したり、要素ごとに追加のクエリが必要になったりして、クエリ バジェットが壊れてしまいます。 

中心的な課題は、代数的再構成そのものではなく、要素間で情報を償却する方法でそれを行うことです。 

## アプローチ

 ブルートフォース戦略では、すべての未知の値を独立した値として扱い、複数の積クエリを使用して分離しようとします。 たとえば、多くの j 値について (i, j) をクエリし、gcd 関係を間接的に使用して、a[i] を計算しようとする場合があります。 正しさについて議論するのは難しくありませんが、各値は他の多くの値に対して繰り返し確認する必要があるため、このアプローチは O(N²) クエリに堕落します。 

重要な構造的観察は、単一の積クエリがすでに 2 つの未知の値を乗算的にエンコードしており、互いに素な条件によって因子の重複における曖昧さが防止されていることです。 これは、中間要素を共有する 2 つの積を取得した場合、その中間要素は gcd 操作を使用してきれいに抽出できることを意味します。 

具体的には、積 x = a[i]・a[j] と y = a[j]・a[k] をクエリするとします。 a[i] と a[k] はそれ自体以外のものと素因数を共有しないため、gcd は a[j] になります。そのため、すべての共有構造は a[j] に由来する必要があります。 a[j] がわかったら、a[i] と a[k] の両方を直接除算で復元できます。 

これにより、自然な 3 要素の再構成ブロックが作成されます。2 つのクエリで 3 つの値すべてが正確に決定されます。 これが認識されると、配列全体を素のトリプルに分割し、それぞれを独立して解決できます。

 | ブルートフォース | O(N² クエリ) | お(1) | 遅すぎる |
 | トリプルブロッキング | O(N クエリ) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. インデックス範囲を 3 つの要素の連続するグループに分割します。 グループ (i、i+1、i+2) の場合、正確に 2 つの積クエリを使用して 3 つの値すべてを回復します。 このグループ化により、すべてのクエリが最大限の情報を提供できるようになります。 
2. グループ内の最初の 2 つの要素の積をクエリし、x = a[i]・a[i+1] を取得します。 次に、最後の 2 つの要素の積をクエリし、y = a[i+1]·a[i+2] を取得します。 
3. 中央の要素 a[i+1] を gcd(x, y) として計算します。 これが機能するのは、両方の積に a[i+1] が含まれている一方で、a[i] と a[i+2] はそれ自体以外のすべてと互いに素であるため、これらは gcd に寄与しないからです。 
4. a[i+1] がわかったら、直接除算によって残りの 2 つの要素を復元します: a[i] = x / a[i+1] および a[i+2] = y / a[i+1]。 このステップは、積が正確であり、共素特性によるあいまいさが存在しないため、有効です。 
5. 完全なトリプルごとにこのプロセスを繰り返します。 N が 3 で割り切れない場合は、同じ積クエリと除算のロジックを使用して、残りの 1 つまたは 2 つの要素を以前のトリプルからの既知の回復値とペアにして処理します。 

### なぜ効果があるのか

 不変条件は、すべての数値がその素因数が一意に現れる積にのみ関与するということです。 すべての個別の要素はペアごとに互いに素であるため、2 つの積の gcd はトリプル内の共有された中間要素を正確に分離します。 その要素が回復されると、各クエリの乗法構造は完全に反転可能になります。 因数の回復を妨げる 2 つの異なる値が素因数を共有できないため、どのステップでも曖昧さが生じます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# NOTE: This is written as if an interactive judge provides a query function.
# In a real interactive problem, replace `query(i, j)` with stdout flush and read.

def query(i, j):
    print("?", i, j, flush=True)
    return int(input())

def answer(arr):
    print("!", *arr, flush=True)

def solve():
    n = int(input())
    a = [0] * (n + 1)

    i = 1
    while i + 2 <= n:
        x = query(i, i + 1)
        y = query(i + 1, i + 2)

        # middle element
        mid = gcd(x, y)
        a[i + 1] = mid

        a[i] = x // mid
        a[i + 2] = y // mid

        i += 3

    # handle leftover
    if n % 3 == 1:
        # single element, must be deduced from any known pair
        # assume n > 1 and a[n-1] known
        a[n] = query(n-1, n) // a[n-1]

    elif n % 3 == 2:
        # last two elements, use known neighbor from previous block
        a[n-1] = query(n-2, n-1) // a[n-2]
        a[n] = query(n-1, n) // a[n-1]

    answer(a[1:])

if __name__ == "__main__":
    from math import gcd
    solve()
```実装はトリプル分解に直接続きます。 各ブロックは正確に 2 つのクエリを発行し、gcd ステップは共有された中間要素を分離します。 それが分かると、整数除算によって曖昧さなく外側の要素が再構築されます。 

実装の微妙な点は、除算の前に gcd を適用する必要があることです。 この順序を逆にすると、システム内の唯一の堅牢なアンカーが失われます。 もう 1 つの重要な点は、すべてのインデックス付けが概念的に 1 ベースであることです。これは対話型の定式化と一致し、トリプルのグループ化における off-by-one の混乱を回避します。 

残りの処理では、少なくとも 1 つの近傍が前のブロックからすでに再構築されていることを前提としています。これは、グループ化によって N を法とする 3 に応じて重複または隣接性が確保されるため、これは有効です。

 ## 特殊なケース

 N = 3 の場合、アルゴリズムは 2 つのクエリを正確に実行し、単一のブロック内のすべての値を再構築します。 gcd ステップは中間要素を直接識別し、追加の構造を必要とせずに除算によって両方のエンドポイントを生成します。 

N = 4 の場合、最初のトリプルはインデックス 1 から 3 を再構築します。インデックス 4 の残りの要素は、インデックス 3 を持つ単一の積クエリを使用して復元されます。これは前のブロックからすでにわかっており、除算で a4 を安全に復元できます。 

N = 5 の場合、最初のブロックは 1 から 3 を再構築し、残りのペア (4,5) は、順序に応じてインデックス 3 または 4 を介して 2 つの依存クエリを使用して処理されます。 最終的な回復の前に少なくとも 1 つの近傍が常に知られているため、分割は明確に定義され、明確なままになります。
