 ## 解決策
 ## 問題の理解

 固定原点を持つ平面内の一連の点が与えられます。$O$。 タスクは、距離と角度に依存する幾何学的制約の下で、これらの点のサブセットがいくつ「有効」であるかを数えることです。$O$。 サブセットは、選択された点のすべてのペアが原点の周りのユークリッド幾何学から導出された特定の分離規則を満たす場合にのみ有効です。 

この状態は、単純な線形的な意味では局所的ではありません。 ペアが許可されるかどうかは両方の距離によって決まります$OP_i, OP_j$そして角度$\angle P_i O P_j$。 これにより、構造はインデックスの組み合わせではなく、基本的に幾何学的なものになります。 出力は、すべてのペアごとの制約を満たすサブセットの数です。 

この問題の制約サイズは十分に大きいため、単純なサブセット列挙は直ちに実行不可能になります。 あれば$N$点の場合、すべてのサブセットを列挙すると、$O(2^N)$そして、各サブセットを注意深くチェックしたとしても、そのコストは少なくとも 2 倍になります。$O(N^2)$最悪の場合。 これは実際的な限界をはるかに超えています。 

隠れた構造は、有効なサブセット内に共存できるポイントの数がジオメトリによって厳しく制限されるということです。 この制限を理解すると、問題は指数関数的なサブセットの列挙から、小規模な構成にわたる限定された組み合わせの計数に移行します。 

多くの点が同様の角度または半径上にある場合、微妙なエッジ ケースが発生します。 このような構成では、慎重に順序付けしない限り、ペアごとの制約が単純なグラフのエッジ条件のように動作しないため、独立性に関する素朴な推論は失敗します。 もう 1 つのエッジ ケースは、原点との共線性またはほぼ共線性です。この場合、角度条件が劣化し、浮動小数点または順序付けロジックが不注意な場合に誤評価される可能性があります。 

## アプローチ

 最も直接的なアプローチは、点のすべてのサブセットを反復処理し、すべてのペアが幾何学的制約を満たしているかどうかを確認することです。 各サブセットについて、すべてをチェックします$\binom{k}{2}$ペアを作成し、距離と角度を計算して、条件を確認します。 これは、有効性の定義を直接強制するため、正しいです。 ただし、そのコストは次のように増加します$O(N^2 2^N)$、中程度の人でも不可能になります$N$。 

最初の重要な構造的観察は、角度制約が非常に制限的であるということです。 2 つの点が両方とも選択されている場合、原点での角度は次の値を超える必要があります。$60^\circ$。 これは、完全な円の周りに、角度分離を侵害することなく、最大 5 つのそのような点が共存できることをすでに示唆しています。 これにより、有効なサブセット サイズが縮小されます。$N$多くても5つまで。 

サブセットのサイズが定数で制限されると、最大 5 つのサイズのサブセットに対するブルート フォースが実行可能になります。 残りの課題は、特に依存関係がインデックス順で純粋にペアごとに独立していない場合に、選択した組み合わせがすべての制約を満たすかどうかを効率的に検証することです。 

2 番目の構造的改善は、原点の周りの極角によってポイントを順序付けることによって実現されます。 この順序では、隣接しない競合は常に中間点によって「仲介」されます。これは、循環的に隣接する関係のみをチェックするだけで十分であることを意味します。 これにより、検証の複雑さが軽減され、動的プログラミングや順序付きサブセットの組み合わせ列挙が可能になります。 

最後に、ソリューションは DP スタイルの構築または慎重な列挙に進化し、有効なサブセットを角度順に構築し、隣接性チェックのみを使用して互換性を確保します。 これにより、問題が多項式時間に還元されます。具体的には、$O(N^3)$開始点を反復し、境界のある遷移を使用して構成を拡張するためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | フルサブセットブルートフォース |$O(N^2 2^N)$|$O(1)$| 遅すぎる |
 | ジオメトリ + 順序付き DP |$O(N^3)$|$O(N^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 原点に対するすべての点の極角を計算し、これらの角度によって点を並べ替えます。 これにより、幾何学的問題が、隣接性が角度的近接性を反映する循環順序に変換されます。 
2. 各点について、距離と角度の制約の下で他のどの点がその点と共存できるかを事前に計算します。 これにより、ジオメトリを繰り返し再計算する代わりに、後で一定時間の互換性チェックが可能になります。 
3. ソートされた角度順序でサブセットの開始点を修正します。 これにより、異なるローテーションで同じ巡回サブセットを複数回カウントすることが回避されます。 
4. 以前に選択したすべての点と互換性のある角度順序で次の点を選択することにより、サブセットを段階的に拡張します。 重要な考え方は、ポイントが角度によって順序付けされると、違反はグローバルではなくローカルに現れるはずであるということです。 
5. 拡張中、最後に選択したポイントをエンコードした状態を維持します。 すべての制約は角度順に境界点との互換性をチェックすることに帰着するため、これで十分です。 
6. サブセットが有効な構成 (ジオメトリによって暗示される最大許容サイズまで) に達したら、それを答えとしてカウントします。 

隣接ベースのチェックが機能する主な理由は、角度順に、非隣接ペアは中間点によって分離されており、その角度位置によって拘束構造が強制的に「伝播」するためです。 これにより、すべての隣接するペアが有効な場合、隠れた長距離違反が角度と距離を制限する幾何学的補題と矛盾することが保証されます。 

### なぜ効果があるのか

 正しさは 2 つの幾何学的事実に基づいています。 まず、選択した 2 つの点は、次の角度より大きい角度を成す必要があります。$60^\circ$、サブセット サイズを 5 で制限します。 第 2 に、角度順序付けでは、隣接しない点間の違反は中間点の存在を意味し、その角度位置により三角形不等式と距離制約によって矛盾が強制されます。 これにより、グローバルな妥当性が循環順序に沿ったローカルなチェックに集約されます。 その結果、完全な有効性を保証するには、隣接関係の一貫性のみを維持しながらサブセットを構築するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def solve():
    n = int(input())
    pts = []
    for _ in range(n):
        x, y = map(int, input().split())
        ang = math.atan2(y, x)
        pts.append((ang, x, y))
    
    pts.sort()
    
    # precompute compatibility
    ok = [[True] * n for _ in range(n)]
    for i in range(n):
        xi, yi = pts[i][1], pts[i][2]
        for j in range(n):
            if i == j:
                continue
            xj, yj = pts[j][1], pts[j][2]
            # condition derived from geometry: Pi Pj must be large enough vs OPi, OPj
            # we encode directly using squared distances
            oi = xi*xi + yi*yi
            oj = xj*xj + yj*yj
            pij = (xi-xj)**2 + (yi-yj)**2
            if pij <= max(oi, oj):
                ok[i][j] = False
    
    ans = 0

    # enumerate subsets starting from each i
    for i in range(n):
        stack = [(i, [i])]
        while stack:
            last, seq = stack.pop()
            ans += 1  # every valid sequence is a valid subset
            for nxt in range(last + 1, n):
                if all(ok[p][nxt] for p in seq):
                    stack.append((nxt, seq + [nxt]))
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、サブセットの構築で循環順序が尊重されるように、まず極角によって点が並べ替えられます。 互換性マトリックス`ok`問題の余弦の法則条件から導出された幾何学的制約にペアが違反しているかどうかをエンコードします。 

インデックス上の DFS は、角度の昇順でサブセットを構築します。 これにより、各サブセットが正確に 1 回カウントされるようになり、同じセットの順列が回避されます。 小切手`all(ok[p][nxt] for p in seq)`ペアごとの有効性が段階的に適用されるため、無効なサブセットが展開されることはありません。 

微妙な点は、循環ローテーションを明示的に処理するのではなく、重複を避けるために順序付けに依存していることです。 並べ替えを行わないと、階乗多順で同じサブセットが生成されます。 

## 実用的な例

 ほぼ異なる角度で、すべて原点から適度な距離に配置された 4 つの点の小さな構成を考えてみましょう。 最初の点から始めてサブセットの構築を追跡します。 

| ステップ | 最後 | 現在のサブセット | アクション |
 | --- | --- | --- | --- |
 | 1 | 0 | [0] | 開始サブセット |
 | 2 | 1 | [0,1] | 有効な拡張子 |
 | 3 | 2 | [0,1,2] | 有効な拡張子 |
 | 4 | 3 | [0,1,2,3] | 無効、スキップされました |

 このトレースは、増分検証によって不正なサブセットの形成がどのように防止されるかを示しています。 

ここで、小さなサブセットのみが有効となるように点が円の周りに均等に配置される 2 番目のケースを考えてみましょう。 

| ステップ | 最後 | 現在のサブセット | アクション |
 | --- | --- | --- | --- |
 | 1 | 0 | [0] | 開始 |
 | 2 | 2 | [0,2] | 有効 (角度大) |
 | 3 | 4 | [0,2,4] | 有効 (最大サイズに達しました) |
 | 4 | 6 | スキップ | 角度制約に違反します |

 これは、サブセット サイズを制限し、組み合わせの爆発を防ぐ幾何学的制限を示しています。

 ## 特殊なケース

 重要なエッジ ケースは、複数のポイントが原点からのほぼ同じ光線上にある場合です。 その場合、角度ソートによりそれらが隣接しますが、距離の制約によりペアリングが禁止される場合があります。 互換性は明示的に強制されるため、アルゴリズムはこれを正しく処理します。`ok[i][j]`したがって、隣接性が有効性を誤って暗示することはありません。 

もう 1 つのエッジ ケースは、点が原点の周りにほぼ正五角形を形成する場合です。 これは、最大サブセット サイズ 5 が飽和する構成です。 DFS は当然、サイズ 5 までのすべての組み合わせを探索しますが、すべての拡張がペアワイズ チェックでエンコードされた角度制約に違反し、理論上の限界に一致するため、それ以上拡張することはできません。
