 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースでは、ボード上に複数の正の整数のセットが配置されています。 1 回の移動は、これらの数値の 1 つを選択し、決定論的変換を適用することで構成されます。数値が偶数の場合はその数値の半分になり、奇数の場合は数値の 3 倍に 1 を加えた数値になります。 選択した数値が結果に置き換えられ、プロセスが続行されます。 

すべての数値がそれ以上移動できない状態にまで減少すると、テスト ケースのプロセスが停止します。これは事実上、すべての数値がこの変換の下で最終値である 1 に到達したことを意味します。 

タスクは、リアルタイムで貪欲にシミュレーションすることではなく、操作が不可能になるまで常に有効な操作を実行し続けると仮定して、すべてが安定するまでに実行できる最大移動数を計算することです。 

入力サイズの制約は、すべてのテスト ケースにわたる合計数が最大数百、各数値が最大 100 万であることを示しています。 また、このステートメントは、この制限までの値から始まるシーケンスが最終的に 1 に到達し、制限されたステップ数内で到達することを保証します。 これは、数値ごとのシミュレーションは効率的に実行できれば実現可能ですが、単純な軌道の再計算を繰り返すと遅すぎることを示唆しています。 

アレイ全体を繰り返しスキャンして一度に 1 ステップずつ適用する単純なシミュレーションは、非常にコストがかかる可能性があります。 1 つの数値に数百のステップが必要で、数値が数百ある場合、演算の合計数は数万に達する可能性があり、毎回最初から再計算すると、同じ中間状態が繰り返し再計算されることになります。 

単純な実装が、繰り返される部分問題について推論せずに独立性を前提としている場合、より微妙な障害モードが発生します。 たとえば、2 つの異なる数値が両方とも 16、8、4、2、1 のような同じ中間値を通過する可能性があります。毎回チェーンを最初から再計算すると作業が無駄になり、厳しい制限の下ではパフォーマンスの問題が簡単に発生する可能性があります。 

## アプローチ

 ブルートフォースの観点は、文字通りプロセスをシミュレートすることです。 各ステップで、リストをスキャンし、まだ操作可能な要素を選択し、変換を 1 回適用し、すべての値が 1 になるまで繰り返します。これはプロセスの定義に正確に従っているため正しいですが、移動ごとに 1 回のスキャンが実行されます。 各数値には最大で数百の移動が必要であり、スキャンには要素の数で直線的な時間がかかるため、最悪の場合はテスト ケースあたりおよそ O(N * total_steps) となり、すべてのテスト ケースを合計すると不必要に遅くなります。 

重要な観察は、演算を適用する順序によって、個々の数値が 1 に達するまでに変換される合計回数は変わらないということです。各数値は決定論的なルールに基づいて独立して進化し、開始値が固定されるとその軌道も固定されます。 グローバル プロセスは、これらの独立した軌道を交互に配置しているだけです。 

これにより、問題は、各開始値について、指定された変換の下で 1 に到達するまでに必要なステップ数を計算することになります。 それが分かれば、テスト ケースの答えは、そのテスト ケース内のすべての数値の単純な合計になります。 

残る唯一の課題は、最大 10^6 の値についてこれらのステップ数を効率的に計算することです。 直接再帰計算では、多くのシーケンスが重なり合うため、同じ値が繰り返し再計算されます。 正しいアプローチはメモ化です。値のステップ数を計算したら、それを保存し、将来のすべてのクエリで再利用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(合計ステップ数 × N) | O(1) おまけ | 遅すぎる |
 | メモ化されたコラッツ DP | O(N + 状態の合計) | O(最大A) | 承認済み |

## アルゴリズムのチュートリアル

 関数を定義します`steps(x)`必要な操作の数を返します。`x`1に到達するために。 

1. もし`x == 1`、0 を返します。1 からはそれ以上の移動はできないため、これが再帰を停止する基本ケースです。 
2. すでに計算済みの場合`steps(x)`、保存された値をすぐに返します。 これにより、複数のシーケンスに出現する値の再計算が回避されます。 
3. もし`x`偶数である場合、計算します`steps(x) = 1 + steps(x / 2)`。 その理由は、1 つの操作は半分にすることですぐに消費され、残りのプロセスは次から継続されるということです。`x / 2`。 
4. もし`x`奇数です、計算してください`steps(x) = 1 + steps(3x + 1)`。 ここでも、最初の操作はすぐに適用され、残りは次の状態に依存します。 
5. 各テスト ケースについて、すべての数値を読み取り、合計します。`steps(a_i)`すべての要素に対して実行し、結果を出力します。 

重要な構造上の考え方は、各数値が独立して合計移動数に寄与するため、異なる数値間の相互作用をシミュレートする必要がないということです。 

## なぜ機能するのか

 このプロセスでは、開始値ごとに決定的なチェーンを定義します。 数字が選択されると、その将来の進化はボード上の他の数字に依存しません。 これにより、グローバル プロセスがばらばらの軌道に分解されます。 メモ化により、到達可能な状態空間内の各整数のステップ数が最大 1 回計算されることが保証されるため、計算は暗黙的な状態遷移に対する有向非循環トラバーサルになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

dp = {1: 0}

def steps(x):
    if x in dp:
        return dp[x]

    if x % 2 == 0:
        dp[x] = 1 + steps(x // 2)
    else:
        dp[x] = 1 + steps(3 * x + 1)

    return dp[x]

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    ans = 0
    for v in arr:
        ans += steps(v)
    print(ans)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```コードはグローバルメモ化辞書に依存しています`dp`すでに計算された歩数を保存します。 再帰は正確な変換規則に従います。 チェーンが 1 に到達する前に深くなる可能性があるため、再帰制限が増加します。 

微妙な点は、次のような値があっても、`3x+1`一時的に初期制約を超えて拡大する可能性がありますが、この問題により、シーケンスが最終的に元に戻り、実際には制限されたままになることが保証されます。 メモ化により、大きな中間値が出現した場合でも、それらは 1 回だけ計算されるようになります。 

最後のループは、独立した寄与を単純に集計し、演算が適用される順序のシミュレーションを回避します。

繰り返される部分問題が単純な再帰を支配し、メモ化によってその冗長性が除去されるため、この解決策は時間とメモリの両方の制約内に簡単に収まります。

 ## 特殊なケース

 エッジ ケースの 1 つは、入力に 2 のべき乗が多数含まれる場合です。 この状況では、変換は純粋に半分の繰り返しで行われるため、シーケンスは短く、予測可能性が高くなります。 各値が個別に減算され、メモ化により 8 → 4 → 2 → 1 などの共有中間値の結果がすぐに再利用されるため、アルゴリズムはこれをきれいに処理します。 

もう 1 つのエッジ ケースは、値が小さいものの奇数である場合で、これにより 3x+1 分岐が早期に強制されます。 たとえば、シーケンスは 3 から始まり 10 にジャンプし、その後他の数値と同じ軌跡にマージします。 再帰はすでに計算された状態に自然に収束するため、保存された結果は再計算せずに再利用されます。 

最後のエッジ ケースは、入力配列内で同じ値が繰り返されることです。 それぞれの出現が同じメモ化された結果を独立してクエリするため、アルゴリズムは単に保存されたステップ数を再利用して再度追加します。これは、値が一致してもボード上の各トークンが独立して進化するという事実と一致します。
