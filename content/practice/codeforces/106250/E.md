 ## 解決策
 ## 問題の理解

 離散化後にグリッド上に配置された麻雀タイルのセットが与えられているため、すべてのタイルは範囲内の整数座標上にあります。$N \times N$ボード。 各タイルにはタイプがあり、タスクは、各ペアが同じタイプの 2 つのタイルで構成され、ペアの 2 つのタイルが、問題の一致ルールによって定義された行または列の構造を通じて有効な直線関係を共有するという意味で「接続可能」になるように、すべてのタイルをペアにすることが可能かどうかを判断することです。 

重要な構造上の制約は、型内でペアリングが任意ではないということです。 2 つのタイルは、適切な構造圧縮後に同じ行または同じ列にある場合にのみペアにすることができます。 これは、問題がジオメトリに直接関係しているのではなく、行、列、およびタイルの出現の間の出現関係に関係していることをすぐに示唆しています。 

入力は、グリッド構造上の一連の色付きエッジとして解釈できます。目的は、これらのエッジを、誘導されたグラフ構造の下で各ペアが共通のエンドポイントを共有するペアに分割できるかどうかを判断することです。 

この制約は、すべてのペアの直接検索が不可能であることを意味します。 中程度でも$N$各タイルはさまざまな方法でペアリングされる可能性があり、検索スペースが階乗的に増加するため、ブルート フォース ペアリングが指数関数的に行われます。 有効な解決策は、問題を、ほぼ線形または対数線形時間でチェックおよび構築できるグラフ プロパティに帰着させる必要があります。 

同じタイプのタイルが行や列に他のタイプのタイルと点在している場合、微妙な問題が発生します。 行全体または列全体を原子単位として扱う単純なアプローチは、隣接関係が生の座標ではなく最大の同種セグメントに依存するため、失敗します。 

たとえば、次の行について考えてみましょう。```
A A B B A A
```行全体をタイプ A の単一単位として誤って処理すると、A が 2 つの切断されたセグメントに出現するという事実が失われます。 ペアリングの実現可能性はこれらのセグメントに独立して依存するため、構造をあまりにも積極的に崩壊させると、誤った結論が生成されます。 

別のエッジ ケースは、接続された構造内で型が奇数回出現する場合に発生しますが、それ以外の場合はローカルでペアリング可能であるように見えます。 貪欲なローカル ペアリングは、小規模なコンポーネントでは成功する可能性がありますが、接続されているコンポーネント間のパリティ制約により全体的には失敗します。 

## アプローチ

 ブルート フォース解釈では、接続ルールに基づいてすべての有効なペアをチェックすることにより、同じタイプのタイルをペアにしようとします。 タイルごとに、互換性のある別のタイルとのマッチングを試み、再帰的に実行します。 これは基本的に、頂点がタイルでエッジが有効なペアを表す一般的なグラフでのマッチングを構築します。 

このグラフを明示的に構築したとしても、エッジの数は$O(N^2)$密な構成では、完全に一致するものを検索したり、すべてのペアを列挙したりすることは計算上不可能になります。 最悪の場合の状態の数は、タイルの数に比例して増加します。 

重要な単純化は、問題をマッチング問題ではなくグラフ分解問題として再解釈することです。 頂点をペアにするのではなく、グラフ内のエッジをペアにするという観点から考えます。 

単一のタイル タイプの場合、各タイルを行の頂点と列の頂点の間のエッジにマッピングできます。 2 つのタイルは、それらのエッジが頂点を共有している場合、ペアにすることができます。 問題は、エッジの各ペアが少なくとも 1 つのエンドポイントを共有するように、エッジをペアに分割できるかということです。 

これはグラフの構造特性に相当します。つまり、各接続コンポーネントには偶数のエッジが含まれている必要があります。 この状態が認識されると、問題はパリティの検証と、ツリー分解と DFS 伝播によるペアリングの構築に集約されます。 

複数のタイル タイプが存在する場合、異なるタイプによって隣接関係がブロックされるため、直接適用は失敗します。 この問題は、グリッドをサブ行およびサブ列と呼ばれる最大均一セグメントに圧縮することで解決され、各セグメント内ですべてのタイルが均一に動作し、境界が型の変更を正しくエンコードするようになります。 

これにより、各タイプが独立した 2 部構成の発生グラフに変換され、単一タイプの構造が復元されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースペアリング検索 | 指数 | O(N^2) | 遅すぎる |
 | グラフ + コンポーネントのパリティ | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 異なるタイプのタイルをペアにすることはできないため、問題をタイル タイプごとに独立したサブ問題に分割します。 

1. 各行を同一のタイル タイプの最大の連続セグメントに圧縮し、各列に対して同じことを行います。 このような各セグメントは、2 部グラフの頂点になります。 これが必要なのは、ペアリングは個々のセルではなく、同じタイプの連続したストレッチのみに依存するためです。 
2. 各タイルについて、そのタイルに含まれるサブ行セグメントとサブ列セグメントを識別します。 これにより、2 部グラフの 2 つの頂点間のエッジが一意に決定されます。 
3. タイル タイプごとに個別のグラフを作成します。頂点はそのタイプによって引き起こされるサブ行およびサブ列であり、エッジはそのタイプのタイルに対応します。 
4. このグラフの各連結成分について、エッジの数を計算します。 コンポーネントのエッジの数が奇数の場合は、直ちにペアリングが不可能であると結論付けます。 これは、すべての有効なペアリングがコンポーネント内の 2 つのエッジを消費するという事実からわかります。 
5. すべてのコンポーネントが偶数エッジ条件を満たしている場合、各コンポーネントを個別に処理してペアリングを構築します。 DFS ベースのボトムアップ トラバーサルを実行し、各ノードでペアになっていないインシデント エッジのリストを維持します。 
6. DFS 中の各ノードで、すべての受信一致しないエッジを、親が存在する場合はツリー エッジと結合します。 可能な限りノードでエッジを貪欲にペアリングします。 1 つのエッジがペアになっていないままの場合は、それを上に伝播させます。 
7. 各コンポーネントのルートに、一致しないエッジが残っていないことを確認します。 不変式が成立する場合、構築されたペアを出力します。 

これが機能する理由は、すべてのサブツリーが上向きに進む不対のエッジを最大でも 1 つ維持するという不変条件から来ています。 これにより、すべてのペアリング制約がローカル パリティ決定に限定されます。 各ペアリングでは正確に 2 つのエッジが削除され、エッジは共有頂点でのみ交わるので、このプロセスが実現可能性を侵害することはありません。 パリティ条件により、ルートに残留エッジが存在しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    grid = [input().strip() for _ in range(n)]

    # compress rows
    row_id = [[-1]*n for _ in range(n)]
    col_id = [[-1]*n for _ in range(n)]

    row_cnt = 0
    for i in range(n):
        j = 0
        while j < n:
            k = j
            while k < n and grid[i][k] == grid[i][j]:
                k += 1
            for x in range(j, k):
                row_id[i][x] = row_cnt
            row_cnt += 1
            j = k

    col_cnt = 0
    for j in range(n):
        i = 0
        while i < n:
            k = i
            while k < n and grid[k][j] == grid[i][j]:
                k += 1
            for x in range(i, k):
                col_id[x][j] = col_cnt
            col_cnt += 1
            i = k

    # build edges per type
    from collections import defaultdict

    type_edges = defaultdict(list)

    for i in range(n):
        for j in range(n):
            t = grid[i][j]
            u = row_id[i][j]
            v = col_id[i][j]
            type_edges[t].append((u, v))

    def check(edges):
        adj = defaultdict(list)
        edge_count = defaultdict(int)

        for u, v in edges:
            adj[u].append(v)
            adj[v].append(u)
            edge_count[u] += 1
            edge_count[v] += 1

        visited = set()
        ok = True

        def dfs(u):
            nonlocal ok
            stack = [(u, 0)]
            parent = {u: -1}
            order = []

            while stack:
                node, state = stack.pop()
                if state == 0:
                    if node in visited:
                        continue
                    visited.add(node)
                    order.append(node)
                    stack.append((node, 1))
                    for v in adj[node]:
                        if v not in parent:
                            parent[v] = node
                            stack.append((v, 0))
                else:
                    pass

            return order

        # parity check via component size
        for u in list(adj.keys()):
            if u not in visited:
                comp = []
                stack = [u]
                visited.add(u)
                ec = 0
                nodes = []

                while stack:
                    x = stack.pop()
                    nodes.append(x)
                    ec += edge_count[x]
                    for y in adj[x]:
                        if y not in visited:
                            visited.add(y)
                            stack.append(y)

                ec //= 2
                if ec % 2 == 1:
                    return False

        return True

    for t, edges in type_edges.items():
        if not check(edges):
            print("NO")
            return

    print("YES")

if __name__ == "__main__":
    solve()
```このソリューションは、最初に圧縮された行セグメントと列セグメントを構築する構造に従い、各タイルがきれいな 2 部構成にマッピングされるようにします。 隣接関係はタイプごとに暗黙的に表され、タイプ間の干渉が回避されます。 

判定出力には完全な明示的なペアリング構築が必要ないため、チェック関数は各コンポーネントをエッジ数のパリティ テストに削減します。 DFS 構造により、各コンポーネントの探索は 1 回のみとなります。 

微妙な実装の詳細は、各タイルが正確に 1 つのエッジに寄与するため、度数で累積するときにエッジのカウントを 2 で割る必要があることです。

これにより、条件が純粋にコンポーネントのエッジ パリティに依存することが確認されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、エッジ数がローカルでは偶数であるが、グローバルでは奇数である複数の切断された領域にタイル タイプが表示される場合に発生します。 各接続コンポーネントは独立して評価されるため、アルゴリズムはこれを正しく処理します。 2 つの領域が対称に見える場合でも、共有のサブ行またはサブ列の頂点を介して接続されていない限り、それらはマージされません。 

もう 1 つのエッジ ケースは、行の型が頻繁に切り替わり、各セルが独自のサブ行になる場合です。 このようなシナリオでは、各最大セグメントが正確に 1 つのセルであるため、圧縮によって正しい頂点が生成され、隣接マッピングの正確さが維持されます。 

最後のエッジ ケースは、ツリー状の構造を形成する交互のタイプの単一の長いチェーンです。 視覚的には単純なパスに似ていますが、コンポーネント パリティ テストはエンドポイントが一致しないままであるかどうかを正確に識別し、無効なペアリングが受け入れられるのを防ぎます。
