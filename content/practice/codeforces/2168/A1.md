 ## 解決策
 ## 問題の理解

 私たちは、単一の文字列を介して整数の配列を通信する 2 フェーズのプログラムを設計するように求められています。 最初の実行時に、プログラムは長さの配列を受け取ります。`n`、各要素は最大 26 です。この配列を英小文字のみで構成される文字列にエンコードする必要があります。 2 回目の実行では、プログラムはエンコードされた文字列のみを受け取り、元の配列とその長さを回復する必要があります。 

主な課題は、実行間に永続的なメモリが存在しないことです。 デコードに使用される情報はすべて、文字列自体にエンコードする必要があります。 制約は中程度です。`n`は最大 10,000 まで指定でき、各要素は最大 26 であり、これはアルファベットの 26 文字に一致します。 出力文字列は 100,000 文字を超えることはできないため、数値を文字に単純に 1 対 1 でエンコードすることが可能です。 

明らかではないエッジケースは、複数の要素が同一である場合、または次の場合に発生します。`n`は最大値に達しています。 たとえば、次の場合`n = 3`そして`a = [1, 1, 1]`、区切り文字を使用せずに文字を連結するだけの単純なエンコーディングでは、「aaa」が生成されます。 事前に定義されたスキームを使用せずにこれをデコードすると、注意しないと長さや順序が誤解される可能性があります。 同様に、最小の入力を処理する必要があります。`n = 1`と`a = [1]`これにより、スキームが単一要素の配列に対して機能することが保証されます。 

## アプローチ

 ブルートフォース手法により各整数がエンコードされます`a_i`対応する小文字として、1 → 'a'、2 → 'b'、…、26 → 'z' をマッピングします。 エンコードは単にこれらの文字を連結したものです。 このアプローチが機能するのは、すべての整数がアルファベット内に収まり、文字列の長さが最大 ​​10,000 文字であり、100,000 文字の制限を大幅に下回っているためです。 デコードには、マッピングを逆にすること、つまり各文字を数値に変換することが含まれます。 

この方法は、数値を文字に直接マッピングするため、正確かつ高速です。`O(n)`時間と空間。 慎重なマッピングを行わない単純な亜種では、たとえば、複数文字コードが使用されたり、数値が 26 を超えたりした場合に、文字の位置がずれる可能性があります。重要な洞察は、この問題では値が明示的に 26 に制限されており、追加の区切り文字なしで数値と文字の間の単純な全単射が可能であるということです。

 ## アルゴリズムのチュートリアル

 1. **エンコードフェーズ (最初の実行)**

 整数を読み取る`n`そして配列`a`。 要素ごとに`a_i`を計算して小文字に変換します。`chr(ord('a') + a_i - 1)`。 これらの文字を文字列に連結します`s`。 印刷する`s`そして終了します。 
2. **デコードフェーズ (2 回目の実行)**

 エンコードされた文字列を読み取る`s`。 長さ`s`は`n`。 各文字を数値に変換して戻します。`ord(c) - ord('a') + 1`配列を再構築するには`a`。 印刷する`n`の要素が続きます`a`。 

正確さは、1 ～ 26 の整数と文字「a」～「z」の間の 1 対 1 のマッピングに依存します。 各文字は正確に 1 つの数値を表し、文字列の長さは配列の長さと等しいため、デコード中に曖昧さはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

mode = input().strip()

if mode == "first":
    n = int(input())
    a = list(map(int, input().split()))
    # Encode: map 1->'a', 2->'b', ..., 26->'z'
    s = ''.join(chr(ord('a') + x - 1) for x in a)
    print(s)

else:  # second run
    s = input().strip()
    n = len(s)
    a = [ord(c) - ord('a') + 1 for c in s]
    print(n, *a)
```最初の分岐は、各整数を文字に変換します。 使用する`ord`そして`chr`マッピングが正確であることを保証します。 2 番目の分岐では、プロセスが逆になります。 使用する`*a`print ステートメントでは、配列をスペースで区切られた値に効率的に展開します。 問題が保証するため、境界チェックは暗黙的です。`1 ≤ a_i ≤ 26`。

 ## 特殊なケース

 のために`n = 1`そして`a = [1]`、エンコードにより生成される`"a"`。 デコードでは単一の文字を読み取り、計算します`ord('a') - ord('a') + 1 = 1`、および出力`1 1`。 のために`a = [26, 26, 26, 26]`、エンコードの結果`"zzzz"`; デコードして再構築する`[26, 26, 26, 26]`。 マッピングでは、すべての要素が同一または極端な場合でも配列が保持され、曖昧さが回避されます。 

この社説では、この問題の簡単なバージョンでは、単純な 1 対 1 の文字マッピングで十分であることを示しています。 より難しいバージョンでは、26 を超える値を処理するために、より高度なエンコーディングが必要になります。
