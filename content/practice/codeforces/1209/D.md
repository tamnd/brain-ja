 ## 解決策
 ## 問題の理解

 スナックの種類のコレクションとゲストのグループが与えられます。 各スナックの種類は 1 回だけ表示されるため、$n$ラベルを付けた個別のアイテム$1$に$n$。 各ゲストには好みのスナックが 2 種類あります。 ゲストは選択された順序で到着し、ゲストが到着すると、好きな 2 種類のスナックを残りすべて消費します。 好みの軽食が両方とも前のゲストによってすでに食べられていた場合、そのゲストは不満を持って帰ってしまいます。 

仕事は、不幸なゲストの数ができるだけ少なくなるように、ゲストの訪問順序を調整することです。 

このプロセスを再解釈する便利な方法は、各スナックの種類をノードとして考えることです。 各ゲストは、関心のある 2 つのスナック タイプを接続する無方向のエッジです。 ゲストが到着すると、両方のエンドポイントを「削除」し、それらのノードをシステムから削除します。 削除されたノードにアクセスする後続のゲストは、もう一方のエンドポイントがまだ存在する場合はそれを消費する可能性がありますが、両方のエンドポイントがすでに削除されている場合、そのゲストは応答に貢献します。 

入力サイズが到達しました$10^5$ノードと$10^5$エッジ。 これにより、ゲストの注文に対する順列ベースまたは階乗推論が即座に排除されます。 すべてのペアに対する二次グラフ アルゴリズムでさえ遅すぎます。 通常、本質的に線形または線形に近いものが必要です。$O(n + k)$または$O(k \log n)$。 

複数のゲストが同じタイプのスナックを共有する場合、微妙なエッジケースが発生します。 たとえば、2 人のゲストが両方とも気に入っている場合、$(1,2)$、最初の頂点がその前に処理されると 2 番目の頂点は常に不幸になりますが、順序はこれらの頂点が他のエッジに比べて早く消えるか遅く消えるかに影響を与える可能性があります。 もう 1 つのエッジ ケースは、グラフがすでにツリーまたはフォレストであり、構造が単純である場合と、グラフにサイクルが含まれており、意思決定が相互作用する場合です。 

重要な問題は、1 人のゲストを削除すると、他のゲストの今後の利用が切断される可能性があるため、貪欲なローカル注文は明らかに安全ではないことです。 

## アプローチ

 ブルートフォースアプローチでは、ゲストのすべての順列を試し、食事のプロセスをシミュレートし、不満を抱いたゲストをカウントします。 これは正しいですが、完全に実行不可能です。$k!$シミュレーション、および各シミュレーション自体のコスト$O(n + k)$、指数関数的なランタイムにつながります。 

重要な観察は、ゲストはスナックの種類によって形成されるグラフの接続構造を通じてのみ重要であるということです。 ゲストが両方のエンドポイントを食べると、一部の頂点をより長く存続させる原因となっている可能性のあるエッジが効果的に「削除」されます。 中心的な疑問は、両方のエンドポイントを早期に分離せずに処理できるゲストはどれかということです。 

視点を反転させます。 ゲストの順序を考える代わりに、ゲストが 2 つのまだアクティブなコンポーネントをリンクする最初の接続になるときを考えます。 コンポーネントの「破棄を遅らせる」機能を、それが避けられなくなるまで失わないようにゲストを処理する場合、基本的に、接続されたコンポーネントを動的に維持することになります。 

これは、ゲストを逆に処理する場合、まさに素集合結合 (DSU) の観点です。存在するすべてのスナック タイプから開始し、徐々にゲスト (エッジ) を追加します。 エッジを追加するときに、すでに接続されている 2 つのコンポーネントを接続すると、サイクル エッジが形成されます。 これらのエッジは、接続を維持する必要がないゲストに対応しており、「最後に犠牲にする」ことができます。 このような冗長エッジの数は、まさに最適な順序で不幸にできるゲストの数です。 

同様に、ゲストの処理をシミュレートし、DSU で既に接続されている 2 つの頂点の接続を試行する回数をカウントすることができます。 このような各試行はサイクル形成エッジに対応し、各サイクル エッジは、ゲストが到着したときに両方のスナックがすでに実質的に利用できない位置に配置できるゲストを示します。 

したがって、問題は、グラフ上にスパニング フォレストを構築する際に冗長なエッジがいくつあるかを数えるということになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 |$O(k! \cdot (n+k))$|$O(n+k)$| 遅すぎる |
 | DSUサイクル検出 |$O((n+k)\alpha(n))$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ゲストを処理する際に、スナック タイプ間の接続を維持するために、素セットのユニオン構造を使用します。 

1. 次のコマンドを使用して DSU を初期化します。$n$ノード、各スナック タイプは独自のコンポーネントで始まります。 これは、最初はスナック関係がマージされていないことを表します。 
2. 各ゲストを任意の順序で繰り返します。 ゲスト接続の場合$x_i$そして$y_i$、それらのコンポーネントを DSU にマージしようとします。 
3. もし$x_i$そして$y_i$すでに同じ DSU コンポーネント内にある場合、結合は実行されません。 代わりに、「冗長ゲスト」のカウンターをインクリメントします。 これは、接続を拡張するのではなく、グラフ内のサイクルを閉じるエッジに対応します。 
4. 異なるコンポーネント内にある場合は、それらを結合してコンポーネントをマージします。 これにより森林構造が維持されます。 
5. すべてのゲストを処理した後、カウントされた冗長ゲストの数を出力します。 この値は、悲しいゲストの最小数です。 

この順序付けが機能する理由は、DSU がグラフのスパン フォレストを効果的に構築しているためです。 接続されたコンポーネントの数を増やすことができないエッジは、接続を維持する必要がなく、サイクル エッジに対応します。 

### なぜ効果があるのか

 どの時点でも、DSU は、以前に受け入れられたゲストによって形成された、スナック タイプの連結コンポーネントへの分割を表します。 ゲストが同じコンポーネント内にすでにある 2 つの頂点を接続する場合、そのゲストは到達可能性の拡大には寄与しません。 すでに接続されている構造内に代替ルートを作成するだけです。 このようなエッジは、先に選択したエッジによって両方のエンドポイントが効果的に使い果たされるまで、正確に「延期」できるエッジです。 したがって、サイクルを形成するすべてのエッジは、好みのスナックが両方ともすでになくなっている状況に追い込まれ、最適な順序でもゲストを悲しませる可能性があるゲストに対応します。 逆に、すべての非サイクル エッジはコンポーネントを接続するために必要であり、悲しみを防ぐ方法で常に早めにスケジュールできます。 これにより、DSU の障害を数えることで最適な答えが得られることがわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra = self.find(a)
        rb = self.find(b)
        if ra == rb:
            return False
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        return True

def solve():
    n, k = map(int, input().split())
    dsu = DSU(n)
    bad = 0

    for _ in range(k):
        x, y = map(int, input().split())
        if not dsu.union(x, y):
            bad += 1

    print(bad)

if __name__ == "__main__":
    solve()
```DSU 構造は各スナック タイプの代表を維持し、ゲストが以前は別個だった 2 つのコンポーネントを接続するときにそれらをマージします。 Union 関数は、エッジが冗長である場合、つまり答えをインクリメントする場合に正確に False を返します。 パス圧縮により、操作あたりの時間がほぼ一定になり、ソリューションの効率が維持されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O((n+k)\alpha(n))$| 各結合/検索操作は、パス圧縮とサイズによる結合によりほぼ一定です。 
| スペース |$O(n)$| DSU 配列には、スナックの種類ごとに親とサイズが格納されます。 

制約により、最大で次のことが許可されます。$10^5$ノードとエッジを統合するため、ニアリニア DSU ソリューションは時間とメモリの制限内に快適に収まります。

 ## 特殊なケース

 単純なチェーンなどの完全に非循環的なグラフ$1-2-3-4$、冗長な DSU ユニオンは生成されないため、答えはゼロです。 アルゴリズムは各エッジを成功した結合として処理し、カウンターは増加しません。 

三角形のような完全な循環構造$1-2, 2-3, 1-3$冗長検出を 1 つだけトリガーします。 最初の 2 つのエッジはコンポーネントをマージし、最後のエッジはすでに接続されている両方のエンドポイントを検出し、答えを 1 つ増やします。 

接続されていないコンポーネントは独立して動作します。 たとえば、各コンポーネント内のサイクルを閉じるエッジがないため、2 つの別個のチェーンは答えに何も寄与しません。
