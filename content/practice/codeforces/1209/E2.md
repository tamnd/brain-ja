 ## 解決策
 ## 問題の理解

 少数の行と潜在的に多数の列を含むグリッドが与えられています。 許可される唯一の操作は、任意の 1 つの列を取得し、それを周期的に何度でも回転させることです。 これらの回転を列ごとに個別に実行した後、各行を調べ、その行内の最大値を選択します。 構成の最終スコアはこれらの行の最大値の合計であり、タスクはこのスコアを最大化することです。 

重要な自由度は、各列を回転によって並べ替えることができますが、循環的にのみ可能であることです。つまり、各列は値のマルチセットを保持しますが、どの要素をどの行に配置するかを選択できます。 回転は列間で独立しているため、最終的な配置は列ごとに垂直方向のシフトを選択することによって決定されます。 

n ≤ 12 という制約が中心的な構造上のヒントです。 これは、各列が最大 12 位置にわたる順列を選択すると考えることができることを意味します。そのため、検索空間は n では指数関数的ですが、集計が可能な方法で m には依存しません。 m が 2000 まで大きいということは、列の寄与をタイプごとに分類した後、圧縮するか貪欲に蓄積する必要があることを示唆しています。 

各行が各列から独立して最良の値を取得できると仮定した場合、素朴な考えによる微妙な失敗例が現れます。 これは、単一の列が行の割り当てごとに 1 つの値を提供し、シフトにより列間で行の選択が結合されるため、誤って過大数を数えることになります。 

たとえば、n = 2、単一列 [10, 1] について考えてみましょう。 異なるローテーションによって両方の行が「10 を取得」できると考える人もいるかもしれませんが、列ローテーションでは一度に 10 は 1 行にのみ配置されます。 1 つの列からの正解は、回転全体の max(10 + 1) で、これは 20 ではなく 11 です。 

もう 1 つの落とし穴は、各列を独立して扱い、その最大値を世界的に最適な行に割り当てることです。 これは、複数の列が最大値を異なる行に同時に配置する必要がある可能性があり、衝突によって達成可能な合計が減少することを無視しています。 

## アプローチ

 ブルートフォース手法では、すべての列に対してすべての循環シフトが試行されます。 各列には n 個の可能な回転があるため、n^m 個の構成が存在します。 列ごとに個別に枝刈りを行ったとしても、最終的な行の最大値は結合位置合わせに依存するため、列間の相互作用は組み合わせのままです。 これは、m = 2000 の場合でも実現可能をはるかに超えています。 

重要な観察は、m は大きいが n は小さいということです。 列が独立してシフトを選択するという観点から考えるのではなく、視点を逆転させます。 すべての列が選択された後、どの値のセットが最終的に各行の最大値になるかを尋ねます。 

固定列の場合、回転によって値が行に割り当てられるため、行全体での要素の並べ替えが行われます。 重要な考え方は、行のサブセットが最大数の要素を受け取ることによって各列を分類することです。 n ≤ 12 であるため、行のサブセットはビットマスクとして表すことができ、列内の値の相対的な順序は、どの上部の位置をどの行に割り当てるかを選択することによってのみ重要になります。 

各列について、その列によって「アクティブ化」される可能性のある行のすべてのサブセットに対する可能な限り最良の寄与を事前計算します。 次に、全体的な問題は、マスク パターンごとに列のサブセットを選択し、各行の最終的な最大値が、正しい位置に大きな値を割り当てる少なくとも 1 つの列と一致していることを確認することになります。 ビットマスク上の DP は、どの行が選択された列によってすでに「満たされている」かを追跡し、列の寄与を貪欲にまたは DP 結合します。

より具体的で標準的な再定式化は、各列を独立して処理することです。行の固定サブセット S に対して、それらの行がこの列の最大の影響を受ける候補とみなされるように、割り当てることができる最適な値を定義します。 各列を降順に並べ替え、その k 番目に大きい値を k 個の個別の行の選択に関連付けます。 これにより、マスク上のサブセット畳み込みスタイルの DP が得られます。 

次に、列を繰り返し追加する DP を実行し、その寄与をグローバル マスク DP にマージします。このグローバル マスク DP では、行にすでに最大候補が保証されています。 m が大きいため、完全な DP で各列を個別に処理することはできません。 代わりに、同一のカラムプロファイルの頻度を累積し、一意のカラムごとに DP を適用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 回転に対するブルートフォース | O(n^m) | O(nm) | 遅すぎる |
 | 列上のマスク DP | O(m · n^2 · 2^n) を O(m · 2^n) に最適化して償却 | O(2^n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各列の値を降順に並べ替えます。 これにより、回転調整の下でどの値が行の最大値となる最良の候補であるかを確実に知ることができます。 
2. 各列を最大 n 個の「ランク付けされた貢献」を提供するものとして解釈します。ここで、その k 番目に大きい値を割り当てることは、強力な候補をある行の位置に配置することに相当します。 
3. 固定列の場合、ビットマスクの DP 配列を計算します。ここで、dp[mask] は、マスク内の行のセットがこの列の上位の要素によって「提供される」行である場合に達成可能な最良の合計寄与になります。 これは、どの行に上位の値を割り当てるかをエンコードします。 
4. マスク上のグローバル dp2 配列を使用して、列全体の寄与を結合します。 各列は、dp2[mask] → dp2[mask | 遷移を行うことによってマージされます。 サブマスク] + 貢献度[サブマスク]。 これは、各列が 2^n 状態の項目であるサブセットに対する標準的なナップザックです。 
5. すべての列を処理した後、dp2[full_mask] を、ローテーション設定と一致する最良の列寄与がすべての行に割り当てられた、達成可能な最良の合計として解釈します。 
6. 答えは、すべての完全なカバレッジ状態にわたる最大値、dp2[(1 << n) - 1] です。 

### なぜ効果があるのか

 不変条件は、列のプレフィックスを処理した後、dp2[mask] が、有効な列ローテーションと一致して、マスク内の行がこれまでに最終決定最大候補を正確に受け取っているように、達成可能な寄与の最良の合計を格納することです。 すべての列の割り当てが有効な巡回シフトに対応し、すべてのサブセットの割り当てがどの行がどのランク付けされた要素を受け取るかの選択に対応するため、各遷移は実現可能性を維持します。 各行の最終的な最大値は、列全体で受け取った最適な割り当て値のみに依存するため、DP により、二重にカウントしたり列の制約に違反したりすることなく、すべての一貫した割り当てを確実に探索できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    # transpose to columns
    cols = []
    for j in range(m):
        col = [a[i][j] for i in range(n)]
        col.sort(reverse=True)
        cols.append(col)

    # dp over masks: best total contribution
    dp = [-10**18] * (1 << n)
    dp[0] = 0

    for col in cols:
        # precompute contribution for this column:
        # assigning k top elements to some subset of size k
        contrib = [0] * (1 << n)

        for mask in range(1 << n):
            vals = []
            for i in range(n):
                if mask & (1 << i):
                    vals.append(i)
            # assign top len(mask) values
            total = 0
            for idx, row in enumerate(vals):
                total += col[idx]
            contrib[mask] = total

        ndp = dp[:]
        for mask in range(1 << n):
            if dp[mask] < -10**17:
                continue
            for sub in range(1 << n):
                if mask & sub:
                    continue
                val = dp[mask] + contrib[sub]
                nm = mask | sub
                if val > ndp[nm]:
                    ndp[nm] = val

        dp = ndp

    print(dp[(1 << n) - 1])

if __name__ == "__main__":
    solve()
```このコードは、最初にグリッドを列に変換し、各列を並べ替えて、最大値を簡単に割り当てられるようにします。 列ごとに、行のすべてのサブセットにわたる寄与テーブルを構築し、各サブセットを、回転後にその列の最上位要素を受け取る行を選択するものとして解釈します。 

次に、DP は各列をマスク上のグローバル状態にマージします。 各マスクは、どの行が選択されたコントリビューションによってすでに「カバー」されているかを表します。 遷移では、すべての素なサブセットの追加が試行され、同じ列の組み合わせ内で複数の互換性のない役割が行に割り当てられていないことが保証されます。 

微妙な点は、各列の dp 配列を ndp に複製し、同じ列処理内で部分的な更新を再利用しないようにしていることです。 これにより、列に対する 0-1 ナップザック構造の正確さが維持されます。

 ## 特殊なケース

 最小の単一セル行列は、DP が dp[0] = 0 を正しく初期化し、サブセット遷移を試行せずに唯一の値を直接受け入れる必要があることを示しています。 すべての列がすべての行に寄与する必要があると想定する単純な実装では、誤ってオーバーカウントされてしまいます。 

複数の行を含む単一列の行列で回転モデルをテストします。 回転によってマルチセットの値は変更されないため、最良の結果は単に各行の割り当てで最大の要素を取得することであり、DP は 1 つの列から人為的に複数の寄与を強制してはなりません。 

すべての値が等しいなどの一様な行列は、サブセット割り当てロジックが誤って特定のマスクを優先するかどうかを明らかにします。 正確さには、すべての割り当てが同じ合計をもたらすように対称性が必要であり、DP は反復順序によってバイアスを導入してはなりません。 

1 つの列に 1 つの非常に大きな値が存在する偏った行列では、アルゴリズムがその値を分散しようとせずに 1 つの行に正しく割り当てているかどうかがチェックされ、各列の寄与が有効なサブセットの選択を通じて割り当てられるという不変条件が維持されます。
