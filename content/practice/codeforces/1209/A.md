 ## 解決策
 ## 問題の理解

 整数のリストが与えられているので、それらをできるだけ少ないグループに分割したいと考えています。 各グループには構造上の制約があります。そのグループ内の最小の数値に注目すると、同じグループに割り当てられる他のすべての数値はその最小の数値で割り切れなければなりません。 

各グループは、その最小要素によって「固定」されていると考えることができます。 その最小値を選択すると、グループ内の他のすべての値はその倍数になる必要があります。 タスクは、作成されるグループの数を最小限に抑えながら、すべての番号を何らかのグループに割り当てることです。 

値が最大 100 であるという制約により、問題の性質が大きく変わります。 大きな状態にわたる複雑なグラフや DP を必要とする代わりに、小さな整数間の周波数と割り算構造について直接推論することができます。 グローバル ビューを使用せずにパーティションを明示的に列挙したり要素を貪欲に割り当てたりしようとするソリューションでは、特に同じ値が複数回出現する可能性があり、一貫して処理する必要があるため、最適なグループ化が失われる危険があります。 

素朴な推論が微妙に失敗するケースは、数値が約数を共有しているものの、連鎖的には直接ではない場合に発生します。 たとえば、`[6, 10, 15]`、貪欲なアプローチでは、部分的な互換性に基づいて 6 と 10、または 10 と 15 を組み合わせようとする可能性がありますが、すべての要素が選択された最小値の倍数でない限り、いずれもグループを共有できません。 両方を分割する有効な共通最小値を共有するペアはないため、正解は 3 つのグループになります。 

もう 1 つの微妙なケースは、重複と除数の再利用です。 で`[2, 4, 8, 3, 9]`、グループを複数の無関係なチェーンに「再利用」できるのではないかと考えたくなりますが、各グループの最小値により厳密な可分性が強制されるため、どの数値がアンカーとして機能するかを慎重に決定する必要があります。 

## アプローチ

 ブルートフォース手法では、各要素をいくつかのグループの 1 つに割り当て、有効性をチェックしようとします。 割り当てごとに、すべてのグループのすべての数値がそのグループの最小要素で割り切れることを確認します。 各要素には複数のグループの選択肢があり、事前に最適なグループ数がわからないため、これにより検索空間が指数関数的に増加します。 枝刈りを行っても、n 個の要素のパーティション数は、n が 100 までになると急激に増加します。 

重要な構造的観察は、グループのメンバーシップが選択された最小値によって完全に決定されるということです。 数値 x がグループの最小値である場合、そのグループ内のすべての要素は x の倍数でなければなりません。 これは、考えられる値 x ごとに、それがグループの代表として機能するかどうかを検討し、その倍数がまだ他の場所に割り当てられていない場合はそのグループにすべて割り当てることができることを意味します。 

問題をこのように解釈すると、すべての数値が正確に 1 つのアンカーのグループに属し、各アンカーがそれ自体で割り切れる数値のみをカバーできるように、一連の「アンカー」を選択することが目標になります。 最適な戦略は、数値を最小から最大まで処理することです。以前のグループにまだ割り当てられていない数値が見つかった場合は、新しいグループを開始する必要があります。 次に、そのすべての倍数をそのグループの対象としてマークします。 

これが機能するのは、数値が小さい方が常に適切なアンカーとなるためです。より多くの数値を分割するため、より柔軟なグループが作成されます。 大きな数は小さな数に対する有用なアンカーとして機能できないため、決定を遅らせると最適なグループ化が失われるリスクだけが生じます。

 ## アルゴリズムのチュートリアル

 配列または周波数構造を使用して、まだ割り当てられていない値を追跡します。 

1. ブール配列を初期化する`used`値の範囲を超えています。 これは、番号がすでに何らかのグループに割り当てられているかどうかを追跡します。 
2. 入力内の 1 から最大値までの可能な値を反復処理します。 この順序により、潜在的なグループ アンカーを最小から最大まで常に考慮することが保証されます。 
3. 価値観に出会ったとき`x`入力に表示され、まだ使用済みとしてマークされていない場合、次のように判断します。`x`新しいグループを開始します。 有効にアンカーできる以前のより小さい約数が存在しないため、この選択が強制されます。`x`。 
4. 1回`x`がグループの最小値として選択されている場合、すべての倍数をマークします。`x`使用済みとして。 これは、割り切れるすべての数値を割り当てることを表します。`x`このグループに入る。 これが安全である理由は、次の倍数ごとに`x`に関して割り切れる制約を満たします。`x`。 
5. 上方向へのスキャンを続け、配列内に未使用の数値が見つかるたびにこのプロセスを繰り返します。 

最終的な答えは、新しいグループを開始する回数です。 

正確さは、値 x でグループを開始するたびに、x 未満のすべての数値がすでに完全に処理されて割り当てられており、x が未割り当ての最小値であるという不変条件に依存します。 これにより、以前のグループには x を割らない小さな最小値が存在するため、x を以前のグループに入れることができないことが保証されます。 したがって、x で新しいグループを開始することは避けられず、すべての倍数を貪欲にカバーすることで、無効な割り当てなしでカバレッジを最大化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    maxv = max(a)
    freq = [0] * (maxv + 1)
    
    for x in a:
        freq[x] += 1

    used = [False] * (maxv + 1)
    groups = 0

    for x in range(1, maxv + 1):
        if freq[x] > 0 and not used[x]:
            groups += 1
            for multiple in range(x, maxv + 1, x):
                used[multiple] = True

    print(groups)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず入力を周波数配列に圧縮して、値が存在するかどうかをすばやくテストできるようにします。 の`used`配列は、値が以前のグループにすでに吸収されているかどうかを追跡します。 

ループオーバー`x`潜在的なグループ リーダーを常に昇順に処理するようにします。 新しいリーダーを選択すると、その倍数すべてにすぐにマークが付けられ、後で重複したグループが形成されるのを防ぎます。 

よくある間違いは、値の範囲ではなく入力配列を直接反復処理することです。 グループ化は入力順序ではなく数値関係に依存するため、これにより除数構造が壊れます。

 ## 特殊なケース

 重要なエッジケースは、すべての数値がペアごとに互いに素である場合です。`[7, 11, 13]`。 このアルゴリズムでは、各値で新しいグループが開始されます。これは、他に分割するものがなく、3 つのグループが生成されるためです。これは、グループ化が不可能であるため最適です。 

もう 1 つのケースは、次のような完全にネストされた除数チェーンです。`[2, 4, 8, 16]`。 アルゴリズムは 2 から始まり、すべての倍数をマークし、1 つのグループで終了します。 これは、初期のアンカリングが長い鎖を単一のグループに正しく折りたたむことを示しています。 

3 番目のケースでは、次のような値が繰り返されます。`[3, 3, 6, 6, 12]`。 最初の 3 つがアンカーとなり、他のすべてはすぐに吸収され、重複によってグループ数が増加しないことが確認されます。
