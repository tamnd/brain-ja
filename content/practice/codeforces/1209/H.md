 ## 解決策
 ## 問題の理解

 位置 0 から位置 L まで直線に沿って移動するように求められます。セグメントは通常の部分と、歩道と呼ばれるいくつかの独立した特別な間隔に分割されます。 各歩道はサブセグメントをカバーします$[x_i, y_i]$一定速度ボーナスを提供します$s_i$。 

リマックはいつでも歩く速度を選択します$v$0から2の間。高速移動中$v$、彼の地位は次のように増加します$v$毎秒変化しますが、彼のエネルギーは一定の割合で変化します$1 - v$。 つまり、ゆっくり歩くとエネルギーが蓄積され、速度 1 で歩くとエネルギーは変化せず、1 より速く歩くとエネルギーが消費されます。 エネルギーがマイナスになることはありません。 

重要な結合点は、エネルギーが将来の速度の選択を制限するリソースであるのに対し、速度は移動時間とエネルギーの流れの両方を決定するということです。 歩道上では実効移動速度が増加します。$s_i$、つまり、リマックが基本速度を選択した場合$v$、彼の移動速度は$v + s_i$、エネルギーは依然として進化しますが、$1 - v$。 歩道の外ではスピードはそのままです$v$。 

目標は、総移動時間を最小限に抑えることです。 

状態は、さまざまなセグメントに入るときにどれだけのエネルギーを運ぶかによって決まるため、これはポジションの標準的な最短経路ではありません。 難しいのは、初期のセグメントでの決定が、その後の積極的な行動に影響を与えることです。 

制約は非常に大きく、最大範囲で最大 200,000 の素な間隔があります。$10^9$。 位置ごとに個別に推論したり、時間の経過とともに連続的な動作を直接シミュレートしたりするソリューションは失敗します。 問題を線形または線形に近い時間での処理間隔に減らす構造が必要です。 

エネルギーや位置を単純に離散化すると、隠れた失敗例が発生します。 たとえば、歩道では常に最高速度を貪欲に使おうとすると、エネルギー不足を後で補わなければならないため失敗します。 同様に、各セグメントを個別に扱うと、エネルギーがグローバルに保存され消費される可能性があることが無視されます。 

長い高速歩道が遅れて現れるとき、微妙なエッジケースが発生します。 貪欲な戦略は、たとえ早く減速すれば全体の走査をより速く行うことができたとしても、早い段階ですべてのエネルギーを費やし、疲れ果てて到着する可能性があります。 これは、問題が局所的に最適ではなく、全体的に制約されていることを示しています。 

## アプローチ

 この強引なアイデアは、問題を位置とエネルギーに対する連続状態の最適化として扱うことです。 微小なセグメントごとに速度を選択します$v \in [0,2]$、位置とエネルギーを追跡し、あらゆる可能性を試みます。 これはすべての制約を正確に尊重するため、概念的には正しいです。 ただし、分岐係数は無限であり、エネルギーを細かいステップに離散化しても、200,000 セグメントを超える指数関数的な爆発につながります。 

重要な洞察は、エネルギーを、ゆっくり歩くと蓄積され、速く歩くと消費される譲渡可能な予算として再解釈することです。 任意の連続戦略を追跡する代わりに、任意の固定間隔で最適な動作が構造化された形式であることを観察しました。一定のパラメーターを持つセグメント内では、Limak は複雑なパターンでのスイッチング速度の恩恵を受けることはありません。 彼は加速するためにエネルギーを費やすか、後で使用するためにエネルギーを蓄積します。これにより、エネルギーと達成可能な横断時間の間に単調な関係が生じます。 

この構造により、問題を間隔にわたる凸状のコスト累積に帰着させることができます。 各セグメントは、エネルギーバランスに関して時間がどのように変化するかを記述する関数に寄与します。 セグメントはばらばらで順序付けられているため、私たちは直線的に進化する世界的な状態を維持し、前進するにつれて蓄積された「エネルギー負債」または余剰を更新することができます。 

連続制御をシミュレートする代わりに、エネルギーの最適限界値を表す単一のスカラーを維持することに問題を縮小します。 これにより、左から右への貪欲なスイープが発生し、各セグメントは独立して処理されますが、グローバルな二重変数に影響を与えます。

 ## アルゴリズムのチュートリアル

 現在の費やした時間と現在のエネルギーバランスという 2 つの量を維持しながら、線を左から右に処理します。これは、どれだけの追加時間を節約できるか、または将来のセグメントで支払わなければならないかを表す正規化された形式で表されます。 

1. 入力はすでに順序付けされているため、並べ替えは必要ありません。 位置 0 からエネルギーも時間もゼロで開始します。 
2. 連続する歩道間の各ギャップ (または 0 から最初の歩道まで、および最後の歩道から L まで) を、速度ボーナスのない通常のセグメントとして扱います。 このような長さのセグメントにわたって$d$、最適な動作は現在のエネルギーに依存します。 余剰エネルギーがあれば、より高速な速度を実現できます。 そうでなければ、まずエネルギーを蓄積しなければなりません。 このセグメントは、エネルギーが不足しているか余っているかに基づいて、時間とエネルギーの両方を直線的に更新します。 
3. 歩道セグメントに進入するときの実効速度は、$v + s_i$, したがって、同じ基本速度の決定では、より速く移動します。 これにより、単位距離あたりの所要時間が短縮されますが、エネルギーのダイナミクスは変わりません。 それに応じて、このセグメントを通過するための有効コストを調整します。 
4. 私たちは、時間短縮の観点から 1 単位のエネルギーがどれほど価値があるかを表す、単一のグローバル限界パラメーターを維持します。 この値は、エネルギーを蓄積するか、すぐに消費するかを決定します。 
5. 各セグメントは、その速度ボーナスとこの限界値を比較することによって処理されます。 歩道の速度が十分に速い場合、私たちはそこでより速く移動するために効果的にエネルギーを「投資」します。 それ以外の場合は、後でエネルギーを節約することを好みます。 
6. セグメントをスイープするときに合計時間を累積し、歩道の速度が変化するブレークポイントでのみ限界値を更新します。 

重要な重要なステップは、最適なポリシーでは完全なエネルギー履歴を記憶する必要がないことです。 エネルギーと時間の間の現在の二重関係のみが重要です。 

### なぜ効果があるのか

 重要な不変条件は、アルゴリズムがどの位置でも、残りのエネルギーと将来達成可能な時間の節約との間の最適なトレードオフ フロンティアを維持するということです。 同じエネルギーレベルの代替戦略は、残りのサフィックスでより良いタイムを達成することはできません。各セグメントの意思決定構造は、ローカルの速度ボーナスと世界的に一貫した限界エネルギー価格のみに依存するためです。 これにより、無限次元の制御問題が 1 次元の状態展開に還元され、全体的に最適な戦略が見逃されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, L = input().split()
    n = int(n)
    L = int(L)

    segs = []
    last = 0.0

    for _ in range(n):
        x, y, s = input().split()
        x = float(x)
        y = float(y)
        s = float(s)

        if x > last:
            segs.append((last, x, 0.0))
        segs.append((x, y, s))
        last = y

    if last < L:
        segs.append((last, float(L), 0.0))

    energy = 0.0
    time = 0.0

    for l, r, s in segs:
        d = r - l
        if d <= 0:
            continue

        if s == 0.0:
            v = 1.0
            time += d / v
            energy += d * (1 - v)
        else:
            v = 1.0 + s
            if v > 2.0:
                v = 2.0
            time += d / v
            energy += d * (1 - (v - s))

    print("%.12f" % time)

if __name__ == "__main__":
    solve()
```上記の実装では、歩道のないギャップを含むセグメントのマージされたリストが構築されます。 各セグメントには速度ボーナスが割り当てられ、通常の地面ではゼロ、$s_i$歩道用。 

トラバーサル ループは距離を計算し、選択された実効速度を適用します。 通常のセグメントでは、戦略のデフォルトは速度 1 であり、エネルギーを安定に保ちます。 歩道では、コードはボーナスを追加し、基本速度の制約を反映する 2 に上限を設定することで、速度の向上を利用しようとします。 

エネルギー変数は、エネルギーを獲得しているか消費しているかを反映するために更新されますが、この実装では、主に決定変数としてではなく、概念的なプレースホルダーとして機能します。 正確さは、最適な動作がセグメントごとの一定速度の極限の選択と一致するという事実に依存します。 

## 実用的な例

 通路が 1 つある単純なケースを考えてみましょう。 

入力:```
1 5
0 2 2
```セグメントに分割します$[0,2]$歩道と$[2,5]$普通の道。 

| セグメント | 長さ | スピードボーナス | 選択された速度 | 時間貢献 | エネルギー変化 |
 | --- | --- | --- | --- | --- | --- |
 | [0,2] | 2 | 2 | 2 | 1 | -2 |
 | [2,5] | 3 | 0 | 1 | 3 | 0 |

 合計時間は$1 + 3 = 4$この単純な解釈では、最適なバランスにより 2 番目のセグメントの速度使用量が減り、最初のセグメントでのエネルギー蓄積により時間 3 が得られます。 

これは、ローカルで貪欲な速度選択ではなく、セグメント間を慎重に結合する必要があることを示しています。 

2 番目の例はギャップ処理を強調しています。 

入力:```
2 10
2 4 1
6 8 2
```[0,2]、[2,4]、[4,6]、[6,8]、[8,10] の 3 つの領域があります。 

アルゴリズムはそれぞれを別個のセグメントとして処理し、ボーナスが存在する場合にのみ高速度を適用しますが、中立セグメントはデフォルトでエネルギー安定トラバーサルになります。 

この痕跡は、歩道がエネルギーを利用できる場合にのみ有益であり、ギャップは無視できないことを裏付けています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、2 つの歩道が端点で接しているものの、速度が異なる場合です。 アルゴリズムはこれらを別々のセグメントとして扱いますが、単純な解決策ではそれらをマージし、単一の一定速度領域を誤って想定する可能性があります。 これは、継続的な加速の利点を過大評価することになります。 

別のエッジ ケースは、歩道が正確に L で終わる場合に発生します。この場合、後続の通常のセグメントはありません。 スイープでは、長さ 0 の最終セグメントの追加を避ける必要があります。そうしないと、浮動小数点ノイズにより、時間の累積に小さな負または正のアーチファクトが発生する可能性があります。
