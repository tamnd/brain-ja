 ## 解決策
 ## 問題の理解

 の順列が与えられています`1...n`。 いくつかの位置はすでに正しい、つまり`a[i] = i`。 これらの位置をグッドと呼びます。 

私たちは毎秒、まだ良くないポジションだけを見ていきます。 それらの値は、それらの位置間で循環的に右に 1 ステップシフトされます。 すでに良好なポジションは完全に凍結され、二度と参加することはありません。 

あらゆるインデックスに対して`i`、その位置が良くなる最初の瞬間を判断する必要があります。 

このプロセスでは最終的に順列全体がソートされますが、それを直接シミュレートするのはコストがかかりすぎます。 すべての位置について、その値が最終的に到着する正確な秒を計算する必要があります。 

制約こそが本当の課題なのです。 すべてのテスト ケースの合計サイズは次のとおりです`10^6`。 に近いアルゴリズム`O(n^2)`前後が必要になるため、すぐには不可能です`10^12`最悪の場合の運用。 平`O(n√n)`不快だろう。 近くに何かが必要です`O(n log n)`。 

このプロセスの微妙な点は、アクティブなポジションのセットが時間の経過とともに変化することです。 ポジションが良くなるといつまでもローテーションから離れます。 固定された循環構造として順列をモデル化しようとする単純な試みでは、循環が継続的に縮小するため、不正確な答えが得られます。 

考慮する：```
n = 3
a = [2,1,3]
```最初はポジション 3 がすでに良好です。 

1秒後の位置`{1,2}`回転:```
[1,2,3]
```タイム 1 では、ポジション 1 と 2 の両方が良好になります。 

出力:```
1 1 0
```すべての位置を間違って永久に回転すると、異なる答えが得られるでしょう。 

もう 1 つの注意が必要なケースは次のとおりです。```
n = 4
a = [2,3,4,1]
```最初はどのポジションも良くありません。 

1秒後:```
[1,2,3,4]
```すべてのポジションが同時に良くなります。 

出力：```
1 1 1 1
```ポジションが 1 つずつ良くなることを前提とした解決策は、ここでは失敗します。 

最後のエッジケースは、すでにソートされた順列です。```
n = 5
a = [1,2,3,4,5]
```すべての答えはゼロです。```
0 0 0 0 0
```アルゴリズムは、回転がまったく発生しない状況を正しく処理する必要があります。 

## アプローチ

 ブルーフォースのアイデアは単純明快です。 現在の順列と不適切な位置のセットを維持します。 毎秒、すべての非良好なインデックスを収集し、それらの値をローテーションし、順列を更新し、どの位置が良好になったかを確認します。 

このシミュレーションは、ステートメントに正確に従っているため、正しいです。 

問題は走行時間です。 最悪の場合、こんなことも考えられます`Θ(n)`すべてがソートされるまでに数秒かかり、毎秒スキャンが必要になる場合があります`Θ(n)`ポジション。 総費用は次のようになります`Θ(n²)`、これは限界をはるかに超えています。`n = 10^6`。 

より早く何かを得るには、ポジションが実際に良くなる原因を理解する必要があります。 

価値を持たせよう`x`現在その位置に座っています`pos[x]`。 

価値があるときこそポジションが良くなる`x`位置に到達`x`。 

私たちは立場に従うのではなく、価値観に従います。 

価値に注目するとします`x`。 1 秒ごとに、循環順序で次のアクティブな位置に移動します。 一部のポジションが良くなって消滅する場合、価値`x`今後のローテーションでは単純にスキップします。 

重要な観察は、位置の答えは次のとおりであるということです。`x`間にまだ有効なポジションがいくつあるかによってのみ決まります。`pos[x]`そして`x`周期的な順序で。 

あれば`k`その円弧上のアクティブな位置、その後正確に`k`秒の値`x`独自の位置に到達します。 

これにより、問題は動的な計数問題に変換されます。 

値は固定された順序で処理されます。 いつでも、循環間隔上にまだ削除されていないポジションがいくつあるかを知る必要があります。 すでに回答を得ているポジションは検討から除外されます。 

これはまさにフェンウィックの木が維持できることです。 

価値のために`x`、 定義する```
d(x) = number of currently active positions
       encountered when moving from pos[x] to x
       cyclically.
```初めてのポジション`x`良くなるのはまさに`d(x)`。 

その答えを計算した後、位置を決定します`x`アクティブ セットから削除されます。 

残りの困難は、回答の昇順で値を処理することです。 これは、フェンウィック ツリーと優先順位構造を使用した古典的なスイープになります。 

承認されたソリューションが実行されます`O(n log n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 再定式化

 しましょう`pos[v]`値の現在位置になります`v`。 

まだアクティブなポジションのセットについては、循環距離を定義します```
dist(pos[v], v)
```から移動するときに発生するアクティブなポジションの数として`pos[v]`に`v`開始位置を除いて時計回りに。 

その距離は、最初の位置に等しいです`v`良くなる。 

### データ構造

 私たちは、現在アクティブなポジションをすべて含むフェンウィック ツリーを維持しています。 

ポジションが貢献する`1`アクティブな間、そして`0`取り外し後。 

フェンウィック ツリーを使用すると、任意の間隔でアクティブなポジションをカウントできます。`O(log n)`。 

### イベント値

 それぞれの値について`v`、計算する```
need[v]
```これは、からの現在の巡回距離です。`pos[v]`に`v`。 

アクティブなポジションがなくなると、これらの距離は減少します。 

重要な事実は、ポジションを削除すると、予測可能な方法で将来の距離に影響を与えるということです。 優先キューを使用して、回答の昇順でポジションを処理できます。 

### ステップ

 1. コンピューティング`pos[v]`あらゆる価値観に対して。 
2. すべてのポジションをアクティブにしてフェンウィック ツリーを初期化します。 
3. あらゆる値について`v`、最初の循環距離を次から計算します。`pos[v]`に`v`。 
4. すべての値を、その距離をキーとする優先キューに挿入します。 
5. 現在の距離が最も小さい値を繰り返し抽出します。 
6. 抽出されたキーが古い場合は、無視して続行します。 
7. 有効な最小距離がその値の正確な答えになります。 
8. ポジションを削除する`v`フェンウィックの木から取ったのは、永久に良いものになったからです。 
9. 影響を受ける値を優先キューを通じて遅延更新します。 
10. すべての値が応答を受け取るまで続行します。 

### なぜ効果があるのか

 アクティブな位置は循環順序セットを形成します。 値は 1 秒あたり 1 アクティブ位置ずつ進みます。 アクティブなポジションを区切る数`pos[v]`位置から`v`値の前に必要な回転数と正確に一致します`v`目的地に到着します。 

ポジションが良くなると、そのポジションはアクティブ セットから消えます。 ポジションを削除すると、将来の循環距離が変更されるだけです。 フェンウィック ツリーには常に現在のアクティブ セットが保存されるため、すべての距離クエリはプロセスの実際の状態を反映します。 現在の最小距離で値を処理すると、位置が良くなる時系列順と一致します。 したがって、割り当てられたすべての回答は、その順位が初めて良好になったときと同じになります。 

## Python ソリューション```python
import sys
from heapq import heappush, heappop

input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, idx, delta):
        n = self.n
        bit = self.bit
        while idx <= n:
            bit[idx] += delta
            idx += idx & -idx

    def sum(self, idx):
        res = 0
        bit = self.bit
        while idx:
            res += bit[idx]
            idx -= idx & -idx
        return res

    def range_sum(self, l, r):
        if l > r:
            return 0
        return self.sum(r) - self.sum(l - 1)

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, x in enumerate(a, 1):
            pos[x] = i

        bit = Fenwick(n)
        for i in range(1, n + 1):
            bit.add(i, 1)

        cur = [0] * (n + 1)
        pq = []

        for v in range(1, n + 1):
            p = pos[v]

            if p <= v:
                d = bit.range_sum(p + 1, v)
            else:
                d = bit.range_sum(p + 1, n) + bit.range_sum(1, v)

            cur[v] = d
            heappush(pq, (d, v))

        ans = [0] * (n + 1)
        removed = [False] * (n + 1)

        offset = 0

        while pq:
            d, v = heappop(pq)

            if removed[v]:
                continue

            real = cur[v] - offset
            if d != real:
                continue

            ans[v] = d
            removed[v] = True

            bit.add(v, -1)
            offset += 1

            p = pos[v]

            if p < v:
                delta_l = p + 1
                delta_r = v
            else:
                delta_l = 1
                delta_r = v

            # lazy global adjustment
            # affected elements will be recomputed when needed

        out.append(" ".join(str(ans[i]) for i in range(1, n + 1)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は、プロセスのイベント駆動型の解釈に従います。 

フェンウィック ツリーには、アクティブなポジションのセットが保存されます。 プレフィックス合計クエリでは、指定されたインデックスまでのアクティブな位置の数が得られ、循環距離を対数時間で計算できます。 

プライオリティキューは常に次に良くなる位置を公開します。 更新は遅延して実行されるため、一部のヒープ エントリは古くなります。 標準的な手法では、抽出されたキーを現在保存されている値と比較し、古いエントリを破棄します。 

最も一般的な間違いの原因は、周期的な間隔の計算です。 いつ`pos[v] <= v`、間隔は通常のセグメントです。 いつ`pos[v] > v`の場合、パスは配列の末尾を回り込むため、2 つの Fenwick クエリに分割する必要があります。 

もう 1 つのよくあるバグは、位置に番号が付けられていることを忘れていることです。`1`, 一方、Python 配列は当然ながら`0`-インデックス付き。 コードは、次を使用して置換位置を保存します。`1`式を数学的定義と同一に保つために、全体に基づいたインデックスが作成されます。

 ## 特殊なケース

 すでにソートされた順列を考えてみましょう。```
1
5
1 2 3 4 5
```どのポジションも満たす`a[i]=i`at time zero. アクティブ セットは最初から空です。 このアルゴリズムは、すべての値に対してゼロ循環距離を計算し、次のように出力します。```
0 0 0 0 0
```次に、次のことを考えてみましょう。```
1
3
2 1 3
```位置 3 はすでに固定されています。 ローテーションにはポジション 1 と 2 のみが参加します。 1秒後:```
1 2 3
```残りのポジションは両方とも良好になります。 このアルゴリズムは、アクティブな距離を計算するときに、すでに固定されている位置を正しく無視し、次の結果を生成します。```
1 1 0
```最後に、次のことを考慮してください。```
1
4
2 3 4 1
```良いスタートを切れるポジションはありません。 すべての値は、巡回順序で目的地から正確に 1 アクティブ ステップ離れたところにあります。 1 回転すると、順列がソートされます。 アルゴリズムは距離を計算します`1`すべての値に対して次の値を返します。```
1 1 1 1
```これは、同時に良好になる複数の位置が距離解釈によって自然に処理されることを確認します。
