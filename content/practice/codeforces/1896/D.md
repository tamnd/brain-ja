 ## 解決策
 ## 問題の理解

 1 と 2 だけからなる配列が与えられ、その配列は時間の経過とともに変化します。 変更の間に、合計が正確にターゲット値となる連続した部分配列が存在するかどうかという、はい/いいえの質問が繰り返し出されます。 

主な問題は、配列が静的ではないことです。 更新のたびに、1 つの位置が 1 と 2 の間で切り替わり、多くの部分配列の合計が一度に変更される可能性があります。 配列サイズとクエリ数の両方が到達する可能性があるため、$10^5$、更新のたびにすべての部分配列の合計を再計算することは不可能です。 

制約構造では、クエリごとに部分配列を列挙するアプローチは直ちに除外されます。 更新はすべてのサフィックスに影響するため、すべてのプレフィックスの合計を明示的に維持するだけでは十分ではありません。 

すべての要素が 1 の場合、微妙なエッジ ケースが発生します。その場合、すべての部分配列の合計はその長さになるため、連続範囲内の合計のみを形成できます。 たとえば、`n = 5`と配列`[1,1,1,1,1]`、1 から 5 までのすべての合計は可能ですが、それ以上は不可能です。 「最大プレフィックス合計までのすべての合計が到達可能である」と仮定する単純な解決策はここでも機能しますが、2 が導入されると長さと合計の関係が歪むため、この解決策は失敗します。 

別の故障モードは、部分配列の合計が可能であれば、より小さな合計もすべて可能であると仮定することから生まれます。 これは誤りです。単一の 2 の力は、サブ配列に含まれる 2 の数に応じて、達成可能な合計でジャンプします。 

## アプローチ

 直接的な総当たりアプローチでは、クエリごとにすべてのサブ配列を列挙し、それらの合計を計算します。 これは正しいですがコストがかかります$O(n^2)$クエリごとのデータ量は、制約の下では天文学的に大きくなります。 

もう少し良いアイデアは、プレフィックスの合計を事前に計算し、すべてのペアをチェックすることで各クエリに答えることです。$(l,r)$。 変更のたびにプレフィックスの合計を再構築する必要があるため、更新ではこの問題が完全に解消されます。 

重要な構造観察は、すべての要素が基本値 1 に寄与し、2 がその基準値の上に追加の +1 に寄与することです。 部分配列に長さがある場合$L$そして含まれています$k$2 の場合、その合計は$$L + k.$$そこで問題は、2 の数と長さが満たされる部分配列を見つけることができるかということです。$L + k = s$。 

任意の部分配列の観点から考える代わりに、視点を切り替え、2 の位置によって配列をグループ化します。 部分配列にどの 2 が含まれるかを決定すると、2 からの寄与が固定され、唯一の柔軟性は周囲の 1 をいくつ含めるかによって決まります。 

これにより、連続する 2 ブロックとその周囲の 1 ギャップのみを考慮する必要がある構造が得られます。 各ブロックは達成可能な合計の連続範囲を示し、最終的な答えはそのようなブロックすべてにわたる範囲メンバーシップ チェックになります。

 ## アルゴリズムのチュートリアル

 すべての 2 の位置を記録することで配列を圧縮します。 これらの位置をソートされたリストに保存します。 また、位置 0 と位置に仮想センチネルを想像します。$n+1$、境界を均一に処理するのに役立ちます。 

1. すべての 2 のインデックスをソートされた順序で維持します。 値を反転すると 2 が挿入または削除される可能性があるため、この構造は更新のたびに変更されます。 
2. 連続する 2 の間のギャップも維持します。 2 の位置が$p_1 < p_2 < \dots < p_m$、ギャップを定義します$$g_i = p_i - p_{i-1} - 1$$どこ$p_0 = 0$そして$p_{m+1} = n+1$。 これらのギャップは 1 の範囲を表します。 
3. クエリの場合、すべてのサブ配列を考慮するのではなく、インデックスからの 2 の連続ブロックによって定義されたサブ配列を考慮します。$i$に$j$。 これらの 2 を正確に含む有効なサブ配列は、前の 2 つの間になければなりません。$p_i$そして次の 2 つの後$p_j$。 
4. このブロックを含む最小のサブ配列はタイト スパンです。$$\text{span} = p_j - p_i + 1.$$これにより、サブ配列に強制的に 1 が挿入される数が決まります。 
5. この部分配列内の 2 の数は次のように固定されています。$k = j - i + 1$。 したがって、このブロックで達成可能な最小合計は次のようになります。$$S_{\min} = \text{span} + k.$$6. 新しい 2 を含めることなく、サブ配列を隣接する 1 ギャップに外側に拡張できます。 これにより長さは増加しますが、長さは維持されます$k$変化しないため、合計が増加します。 最大拡張により以下が追加されます。 

- すべて 1$g_i$左側にある
 - すべて 1$g_{j+1}$右側にある

 したがって、最大合計は$$S_{\max} = \text{span} + k + g_i + g_{j+1}.$$7. したがって、連続する 2 の各ブロックは、達成可能な合計の間隔を生成します。$[S_{\min}, S_{\max}]$。 
8. クエリ「合計を含む部分配列は存在しますか?」$s$” は次のようになります: ブロック間隔には次のものが含まれますか?$s$。 
9. 更新時に 2 位置構造を動的に維持し、影響を受けるギャップをローカルで再計算します。 各クエリについて、位置全体にわたってバランスのとれた構造を使用してブロックを効率的にスキャンします。 

### なぜ効果があるのか

 重要な不変条件は、サブ配列がどの 2 を含むかによって一意に決定され、含まれる 2 の固定セットの場合、合計は含まれる 1 の数のみに依存し、サブ配列を隣接する 1 ギャップに拡張することによってのみ調整できることです。 これは、すべての実現可能な構成が 2 ブロックごとの合計の連続区間に収まり、要素を 1 つ拡張すると常に合計がちょうど 1 だけ増加するため、ブロックの達成可能な範囲内に「穴」が存在しないことを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    ones = [0] * (n + 2)

    pos2 = []

    def rebuild():
        nonlocal pos2
        pos2 = [i + 1 for i, v in enumerate(a) if v == 2]

    rebuild()

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '2':
            i = int(tmp[1]) - 1
            v = int(tmp[2])
            a[i] = v
            rebuild()
        else:
            s = int(tmp[1])

            m = len(pos2)
            if m == 0:
                print("YES" if 1 <= s <= n else "NO")
                continue

            ok = False

            # sentinels
            p = [0] + pos2 + [n + 1]

            # try all blocks of 2s
            for i in range(1, m + 1):
                for j in range(i, m + 1):
                    k = j - i + 1

                    span = p[j] - p[i] + 1
                    S_min = span + k
                    S_max = span + k + (p[i] - p[i - 1] - 1) + (p[j + 1] - p[j] - 1)

                    if S_min <= s <= S_max:
                        ok = True
                        break
                if ok:
                    break

            print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```実装はブロックの解釈に直接に従います。 更新のたびに 2 の位置のリストを再構築します。これにより、ロジックが単純に保たれ、構造が明確になります。 クエリごとに、連続する 2 のグループをすべて列挙し、スパンと拡張可能な境界ギャップを使用して、達成可能な合計間隔を計算します。 

重要な詳細は、センチネルの位置を使用して 2 つの境界ギャップを正しく計算することです。 これにより、ブロックが配列の先頭または末尾に触れる場合の特殊なケースが回避されます。 

## 実用的な例

 配列を考えてみましょう`[2,1,2,1,2]`そして、合計 7 が可能かどうかを尋ねるクエリ。 

まず 2 の位置を次のように記録します。`[1,3,5]`。 センチネルを使用すると、`[0,1,3,5,6]`。 

3 つすべての 2 を含むブロックの場合、次のようになります。 

| ステップ | 私 | j | k | スパン | S_分 | S_max |
 | --- | --- | --- | --- | --- | --- | --- |
 | フルブロック | 1 | 3 | 3 | 5 | 8 | 8 |

 これは、このブロックでは合計 7 に到達できないことを示しています。 ただし、次のようなサブブロックを考慮すると、`[3,5]`、間隔は次のようになります。 

| ステップ | 私 | j | k | スパン | S_分 | S_max |
 | --- | --- | --- | --- | --- | --- | --- |
 | ブロック [3,5] | 2 | 3 | 2 | 3 | 5 | 7 |

 ここでは 7 が区間内にあることがわかり、答えは YES です。 

このトレースは、含まれる 2 の異なる選択によって異なる合計範囲がどのように生成されるか、および全配列情報のみをスキャンすると有効な答えが見つからない理由を示しています。

 ## 特殊なケース

 完全に 1 で構成される配列の場合、すべての部分配列の合計はその長さに等しいため、各クエリはターゲットが範囲内にあるかどうかを確認することになります。$[1,n]$。 2 がゼロであるため、ブロック定式化はきれいに縮退します。これは、唯一の間隔が自明な連続範囲であることを意味します。 

すべて 2 の配列の場合、各部分配列の合計はちょうどその 2 倍の長さになります。 この場合、各ブロック間隔は長さごとに 1 つのポイントに折りたたまれ、アルゴリズムは可能な限り偶数の合計のみを正しく報告します。 

次のような交互パターンの場合`[2,1,2,1]`、1ギャップに拡張する柔軟性が不可欠になります。 このアルゴリズムは、内部の 2 カウントを固定したまま境界拡張を許可することでこれを捉え、サブ配列がどの程度拡張されるかに応じて、5 と 6 などの合計が両方とも到達可能であることを保証します。
