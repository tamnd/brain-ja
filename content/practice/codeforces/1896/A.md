 ## 解決策
 ## 問題の理解

 順列と非常に具体的なスワップ操作が与えられています。 

スワップはポジションでのみ許可されます`i`ここで、要素は極大値です。 言い換えると、`a[i]`隣接するものよりも大きくなければなりません。 そのようなポジションが存在する場合、交換する可能性があります`a[i]`要素をそのすぐ右側に置きます。 

タスクは実際に順列を並べ替えることではありません。 必要なのは、一連の有効な操作によって最終的に順列を昇順に変換できるかどうかを判断することだけです。 

制約は驚くほど小さいです。 順列の長さは最大 10 で、テスト ケースの数は最大 5000 です。 状態空間は次のように制限されているため、到達可能なすべての状態に対する総当たり検索は実際に可能です`10!`, しかし、それでも必要以上に大きいです。 この問題は、操作によって何が変更でき、何が変更できないかについての単純な観察を中心に設計されています。 

主な罠は、要素が繰り返しのスワップを通じて自由に移動できることを前提としています。 操作は非常に制限的です。 

考慮する：```
3
3 1 2
```最初の要素は`3`。 この操作では 2 から 2 までのインデックスのみが許可されるため、位置 1 を含む有効な操作はありません。`n-1`。 順列は決して並べ替えられないので、答えは次のようになります。`NO`。 

見落としやすいもう 1 つのケースは次のとおりです。```
5
1 3 2 5 4
```これは部分的にしかソートされていないように見えますが、両方とも`3`そして`5`は極大値です。 許可されたスワップを実行すると、次のようになります。```
1 3 2 5 4
→ 1 2 3 5 4
→ 1 2 3 4 5
```答えは`YES`。 

最も重要なエッジケースは、最小の要素がまだ前面にない場合です。 

例：```
5
2 1 3 4 5
```順列はほぼソートされていますが、要素は`1`位置 1 には決して移動できません。答えは次のとおりです。`NO`。 

なぜこのようなことが起こるのかを理解することは、解決策に直接つながります。 

## アプローチ

 ブルートフォースアプローチでは、すべての順列を状態として扱い、すべての有効な操作を繰り返し適用します。 グラフ検索を実行して、ソートされた順列に到達できるかどうかを確認できます。 

これが機能する理由は、`n ≤ 10`, しかし、それでも不要です。 最悪の場合は、`10! = 3,628,800`州。 多くが到達不能であるとはいえ、何千ものテスト ケースの状態を探索するのは過剰です。 

重要な観察は、最初の要素に何が起こるかを調べることから得られます。 

許可されているすべての操作では、次の間のインデックスが使用されます。`2`そして`n-1`そして位置を交換します`i`そして`i+1`。 

位置`1`決して触れられません。 

つまり、順列の最初の要素は決して変更されません。 

ソートされた順列の最初の要素は何でなければなりませんか? 配列は次の順列であるため、`1..n`、ソートされた順列は常に次で始まります。`1`。 

したがって、最初の要素がそうでない場合、`1`、並べ替えは不可能です。 

驚くべきことは、最初の要素がすでに等しい場合、`1`、並べ替えはいつでも可能です。 

なぜ？ より大きいすべての要素`1`最終的には、一連の有効な極大スワップによって右方向に移動できます。 公式の解決策の観察によると、`1`フロントに固定するだけで必要十分です。 

問題全体は、単一の値をチェックすることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(到達可能な状態の数) | O(到達可能な状態の数) | 不要 |
 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列を読み取ります。 
2. 最初の要素を確認します。 
3. 最初の要素が等しい場合`1`、印刷`"YES"`。 

ソートされた順列は次で始まる必要があります`1`、そしていつ`1`が先頭ですでに固定されている場合、許可された操作は残りの要素を並べ替えるのに十分です。 
4. それ以外の場合は印刷します`"NO"`。 

最初のポジションはいかなる操作にも参加できないため、`1`決して置き換えることはできません`1`。 

### なぜ効果があるのか

 不変条件は、位置 1 が決して変更されないことです。 

操作ごとに位置が入れ替わります`i`そして`i+1`どこ`2 ≤ i ≤ n-1`。 位置 1 は関与しないため、最初の要素はプロセス全体を通じて一定のままです。 

ソートされた順列`1..n`から始めなければなりません`1`。 最初の要素がそうでない場合は、`1`、ソートされた順列に到達することは不可能です。 

逆に、最初の要素が`1`、残りの要素は、許可された極大スワップを使用して、いつでも並べ替えられた順序に並べ替えることができます。 この事実は問題の背後にある中心的な観察であり、この条件が必要かつ十分であると言えます。

各テスト ケースについて、順列を読み取り、その最初の要素のみを検査します。 シミュレーションは必要ありません。 

よくある間違いは、スワップを明示的にモデル化しようとすることです。 この操作は並べ替えプロセスのように見えますが、最初の位置の不変式によって答えが完全に決まります。 

もう 1 つの考えられる間違いは、順列が既にソートされているかどうかを確認することです。 次のような順列:```
1 3 2
```最初は並べ替えられていませんが、答えはまだありません`"YES"`許可された操作で並べ替えを完了できるためです。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ans.append("YES" if a[0] == 1 else "NO")

    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample

"""
) == "YES"
