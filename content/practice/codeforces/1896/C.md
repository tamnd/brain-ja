 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列があります。 配列`a`は固定ですが、配列`b`任意に並び替えることができます。 の順列を選択した後、`b`、配列を位置ごとに比較します。 

結果として得られる配列のペアの美しさは、インデックスの数です。`a[i] > b[i]`。 

テストケースごとに目標値が与えられます`x`。 タスクは、次の順列が存在するかどうかを判断することです。`b`まさにその美しさは`x`。 このような順列が存在する場合は、1 つの有効な配列を出力する必要があります。 

すべてのテスト ケースの合計サイズは最大でも`2 · 10^5`。 これにより、多くの順列を検査するものは即座に除外されます。 たとえ`O(n²)`アルゴリズムは次のように実行します`4 · 10^10`限界をはるかに超えた最悪の場合の動作。 仕分けしてから`2 · 10^5`数字は簡単に手に入る、解決策`O(n log n)`テスト ファイルごとが自然なターゲットです。 

難しいのは、美しさを最大化することも最小化することもしないということです。 指定された数の勝ちポジションを正確に生み出す仕組みが必要です。 

簡単な間違いの 1 つは、貪欲に小さな値を代入することです。`b`可能な限り一度停止してください`x`勝利が生まれました。 

考慮する：```
n = 3, x = 1
a = [2, 4, 3]
b = [4, 1, 2]
```不注意で貪欲な人は、`1`に対して`4`, creating one win, and then assign the remaining values arbitrarily. 偶然に2度目の勝利を生み出す可能性もある。 正しい答えは存在します。```
b = [2, 4, 1]
```これにより、勝ちポジションが 1 つだけ生成されます。 

要求された美しさが不可能な場合には、別の微妙なケースが発生します。```
n = 1, x = 1
a = [1]
b = [2]
```再配置は存在しません。 以来`1 > 2`は偽であり、美しさは常にゼロです。 

バグの 3 番目の原因は、等しい値から発生します。```
n = 3, x = 0
a = [2, 2, 2]
b = [2, 2, 2]
```美は厳格な不平等のみを考慮します。 等しい値は寄与しません。 処理するロジック`>=`勝利すると間違った答えが生まれるからです。 

## アプローチ

 ブルートフォースアプローチは簡単です。 のすべての順列を生成します`b`、各配置の美しさを計算し、いずれかの美しさが等しいかどうかを確認します。`x`。 

美しさの計算には次の時間がかかります`O(n)`時間。 がある`n!`順列。 たとえ`n = 10`、これはもう`3.6 million`順列。 のために`n = 20`、完全に不可能になります。 実際の限界は`2 · 10^5`, ブルートフォースは問題の構造を理解する場合にのみ役に立ちます。 

重要な観察は、値の相対的な順序のみが重要であるということです。 の位置を並べ替えるとします`a`価値観によって。 正確に望むなら`x`位置`a[i] > b[i]`、次に最小のもの`x`の値`b`小さい値の方が勝ちやすいため、これらの勝利を生み出すために使用する必要があります。 

のインデックスを並べ替えてみましょう`a`増やすことで`a[i]`。 それらのインデックスを次のようにします。```
p[0], p[1], ..., p[n-1]
```また、次の値を並べ替えます。`b`。 

正確に作成するには`x`勝ち、最小のものを割り当てます`x`ソートされた要素`b`最大のものまで`x`の要素`a`。 

なぜ？ それらの最大の要素は、`a`保証するのが最も簡単な場所です`a[i] > b[i]`。 

その割り当ての後、残りの`n - x`の値`b`残りのポジションに割り当てられます`a`。 

非常にエレガントな構造が現れます。 並べ替えると`b`は：```
b0 ≤ b1 ≤ ... ≤ b(n-1)
```次に、位置を並べ替えた後、`a`、次のように配置します。```
b0 ... b(x-1)
```最大のものに`x`の位置`a`、 そして```
bx ... b(n-1)
```最小のものに`n-x`ポジション。 

これは、ソートされたデータを回転することと同じです。`b`配列による`x`ソート済みに対する相対的な位置`a`。 

結果として得られる配置は、次のいずれかを正確に与えます。`x`勝つか、解決策が存在しないことを証明します。 後は実際の美しさを数えるだけです。 カウントが等しい場合`x`、アレンジメントを出力します。 そうしないと、有効な取り決めが存在しません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・n!) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. のインデックスを並べ替えます。`a`価値を高めることで。 
2. すべての値を並べ替えます。`b`。 
3. 長さの回答配列を作成します。`n`。 
4. 最小の場合`n - x`ソートされた順序での位置`a`、最大のものを割り当てます`n - x`ソートされた値`b`。 

より正確に言えば、`i = 0 ... n-x-1`:```
ans[pos[i]] = sorted_b[x + i]
```これらのポジションでは、可能な限り勝利を生み出すことを避けるべきです。 
5. 最大の場合`x`ソートされた順序での位置`a`、最小のものを割り当てます`x`ソートされた値`b`。 

のために`i = 0 ... x-1`:```
ans[pos[n-x+i]] = sorted_b[i]
```これらは勝利を目指すポジションです。 
6. 構築された配置の美しさを計算します。 
7.美しさが等しいなら`x`、印刷`"YES"`そしてアレンジメント。 
8. それ以外の場合は印刷します`"NO"`。 

### なぜ効果があるのか

 両方の配列をソートした後、構築では最小のものをペアにします。`x`の要素`b`～の最大の要素を備えた`a`。 何らかのアレンジメントが作成できる場合`x`勝利のポジション、それらは勝利に最も有利なポジションです。 

残りのより大きな要素は、`b`のより小さい要素と照合されます。`a`、追加の勝利を生み出す可能性を最小限に抑えます。 

この配置は、公式ソリューションで使用される標準的なサイクリック シフト構造です。 求める美しさが実現できるなら、建築はそれを実現します。 建築が生み出す美しさが正確でないなら`x`の場合、必要な勝利数はどのような順列でも取得できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        pos = sorted(range(n), key=lambda i: a[i])
        b.sort()

        ans = [0] * n

        for i in range(n - x):
            ans[pos[i]] = b[x + i]

        for i in range(x):
            ans[pos[n - x + i]] = b[i]

        beauty = sum(a[i] > ans[i] for i in range(n))

        if beauty == x:
            print("YES")
            print(*ans)
        else:
            print("NO")

solve()
```最初のステップでは、インデックスを並べ替えます。`a`並べ替える代わりに`a`自体。 最終的には順列を元の順序で出力する必要があるため、位置を追跡することが重要です。 

2 つの割り当てループは循環シフトを実装します。 最初のループは、次のより小さい要素を埋めます。`a`ソートされた大部分`b`。 2 番目のループでは、次の最小値が配置されます。`b`の最大値に基づいて`a`。 

候補の配置を構築した後、コードは直接検証を実行します。 等しい値が存在すると、意図した勝ち位置が実際に満足できない可能性があるため、この最終チェックは重要です。`a[i] > b[i]`。 

確認手順はあくまで`O(n)`, したがって、全体的な複雑さには影響しません。

# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    out = []

    t = int(input())

    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        pos = sorted(range(n), key=lambda i: a[i])
        b.sort()

        ans = [0] * n

        for i in range(n - x):
            ans[pos[i]] = b[x + i]

        for i in range(x):
            ans[pos[n - x + i]] = b[i]

        beauty = sum(a[i] > ans[i] for i in range(n))

        if beauty == x:
            out.append("YES")
            out.append(" ".join(map(str, ans)))
        else:
            out.append("NO")

    return "\n".join(out)

# minimum size, beauty 0
assert run(
"""1
1 0
1
2
"""
) == "YES\n2"

# minimum size, impossible beauty 1

"""
) == "NO"

"""
) == "YES\n2 2 2"

3 3
2 4 3
4 1 2
"""
) == "NO"

3 2
2 4 3

"""

 ## 特殊なケース

 次のことを考慮してください。```
1
1 1
1
2
```ソートされた配列は変更されません。 この構築により以下が生成されます。```
ans = [2]
```美しさは次のとおりです。```
1 > 2 = false
```美しさは`0`、 ない`1`、アルゴリズムは次のように出力します`"NO"`。 

ここで、等しい値を考えてみましょう。```
1
3 0
2 2 2
2 2 2
```並べ替え後も、すべての割り当ては引き続き配置されます`2`に対して`2`。 

美しさは次のようになります。```
0
```なぜなら、平等は勝利とはみなされないからです。 検証ステップでは、取り決めが正しく受け入れられます。 

最後に次のことを考慮してください。```
1
3 3
2 4 3
4 1 2
```この構築では、次の最小値が配置されます。`b`の最大値に対して`a`、3つの勝利を生み出そうとしています。 結果の配置には、次の位置が 1 つ含まれます。```

```それは勝利ではありません。 美しさは`2`。 最終検証では不一致が検出され、出力されます。`"NO"`。
