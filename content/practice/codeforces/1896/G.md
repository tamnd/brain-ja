 ## 解決策
 ## 問題の理解

 あります$n^2$独特のスピードを持つレーサー。 レースには正確に次のものが含まれる場合があります$n$返される情報は、そのレースの勝者だけです。 

元の対話型タスクでは、最速のタスクの完全な順序を決定するように求められます。$n^2-n+1$レーサーは最大で使用中$2n^2-2n+1$レース。 公式ソリューションは、勝者を注意深く維持することを中心に構築されています。$n$サイズのグループ$n$。 重要な観察は、グループの勝者が削除されると、そのグループの勝者のみを再計算する必要があるということです。 これにより、クエリ バジェット内で最も速いレーサーから最も遅いレーサーまでを抽出できます。 

Codeforces ハック形式の場合、インタラクションはなくなります。 代わりに、ランキング全体が直接提供されます。 

入力に順列が含まれています$a$長さの$n^2$。 値が大きいほど高速になります。 もし$a_i>a_j$、次にレーサー$i$レーサーより速い$j$。 

したがって、ハッキングされたバージョンでは、タスクは非常に単純になります。速度でソートされたレーサーを回復し、最速のレーサーを出力します。$n^2-n+1$彼らのうち。 

制約$\sum n^3 \le 3\cdot 10^5$これは対話型バージョンに関連しますが、ハック形式では長さの配列のみを処理します。$n^2$。 仕分け$n^2$要素は簡単に十分に高速です。 

よくある間違いは、値を並べ替えることです$a_i$自分自身で印刷してください。 出力には、インデックスであるレーサー ラベルが含まれている必要があります。 

たとえば、次の場合```
n = 2
a = [3, 1, 4, 2]
```レーサー 3 が最速、レーサー 1 が 2 位、レーサー 4 が 3 位、レーサー 2 が最後となります。 正しい出力は次のとおりです。```
3 1 4
```ない```
4 3 2
```なぜなら、この問題ではレーサーの識別子が求められるからです。 

## アプローチ

 インタラクティブ バージョンでは、現在の最速レーサーを繰り返し抽出するものとして見ることができます。 単純な実装では、抽出のたびにすべてを最初から再計算します。 レーサーを次のように分類します$n$サイズのグループ$n$、各グループの勝者を見つけてから、グループの勝者をレースしてグローバル勝者を見つけます。 その過程を繰り返すことで$n^2-n+1$時間はおよそにつながります$n(n^2)$許容範囲をはるかに超えたレース。 

重要な観察は、現在最速のレーサーを削除すると、1 つのグループにのみ影響するということです。 他のすべてのグループの勝者は引き続き有効です。 勝者を削除した後、その特定のグループの勝者のみを再計算し、現在のグループの勝者を再度比較します。 これにより、抽出されたレーサーごとの追加レースの数が一定量に減り、制限に達します$2n^2-2n+1$。 

ハック形式の場合、完全なランキングがすでに与えられているため、このような機構は必要ありません。 レーサーインデックスをスピード値で並べ替えるだけです$a_i$降順で最初のものを出力します$n^2-n+1$インデックス。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | インタラクティブなゼロからの再計算 |$O(n^3)$レース |$O(n^2)$| 人種が多すぎます |
 | 公式対話型メンテナンス |$O(n^2)$レース |$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む$n$そして順列$a$。 
2. ペアを作成する$(a_i, i)$、 どこ$i$is the racer label.
 3. これらのペアを降順に並べ替えます。$a_i$。 
4. ソートされたインデックスは、レーサーを最速から最も遅い順に並べたものです。 
5.最初の出力$n^2-n+1$インデックス。 

### なぜ効果があるのか

 順列は、速度の全体的な順序を直接エンコードします。 より大きな$a_i$レーサーを意味します$i$のほうが速いです。 レーサーラベルの並べ替え$a_i$したがって、独自の速度ランキングが生成されます。 問題は最速のみを求めます$n^2-n+1$レーサーなので、その順序の接頭辞を取得するのが正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        parts = input().split()
        n = int(parts[0])
        
        a = list(map(int, input().split()))
        
        order = sorted(range(1, n * n + 1),
                       key=lambda i: a[i - 1],
                       reverse=True)
        
        k = n * n - n + 1
        print(*order[:k])

solve()
```この実装では、出力で必要とされるものであるため、レーサー ラベルを 1 から始まるインデックスとして格納します。 

ソートのキーは、各レーサーに関連付けられた速度値です。 入力は順列であるため、すべての値は個別であり、タイ処理は必要ありません。 

表現`n * n - n + 1`は、正確に印刷する必要があるレーサーの数です。

## 特殊なケース

 次のことを考慮してください。```
1
2 manual
4 3 2 1
```ランキングはすでにレーベル順になっています。 速度で並べ替えると、次の順序が維持されます。`1 2 3 4`。 必要なレーサーは 3 人だけなので、答えは次のようになります。```
1 2 3
```速度値を誤って出力するソリューションは次のように出力します。`4 3 2`、これは間違いです。 

次に、次のことを考えてみましょう。```
1
2 manual
3 1 4 2
```最も速いレーサーは、速度値が 4 であるため、ラベル 3 です。2 番目に速いレーサーは、速度値が 3 であるため、ラベル 1 です。完全なランキングは次のとおりです。```
3 1 4 2
```必要な出力は次のとおりです。```
3 1 4
```これは、ハック バージョンにおける誤答の最も一般的な原因です。 配列には、最終的な順序そのものではなく、速度が保存されます。 

公式のインタラクティブなソリューションは、グループ勝者を維持し、各抽出後に影響を受けるグループのみを更新することに基づいており、許可されたレース予算内に正確に収まります。
