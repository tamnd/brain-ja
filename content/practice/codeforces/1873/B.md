 ## 解決策
 ## 問題の理解

 小さな数字の集合が与えられており、そのうちの 1 つを 1 単位ずつ増やすことができます。 この 1 つの変更の後、すべての桁の積を計算し、それを最大化したいと考えます。 

構造は意図的に単純になっています。配列は小さいため、大規模なシーケンスや複雑な状態に対して最適化は行っていません。 代わりに、結果の積ができるだけ大きくなるように、どの 1 桁を増分するかについてのみ決定します。 

制約により最大 10⁴ のテスト ケースが許可されますが、各テスト ケースの桁数は最大 9 桁です。 これにより、テスト ケースごとの定数係数を超えるものは直ちに排除されます。 総作業量はケースごとに最大でも約 9 操作であり、簡単なので、すべての可能性を試しても完全に安全です。 

主な微妙な点は、桁を増やすと製品に非局所的な影響が及ぶ可能性があることです。 たとえば、0 を 1 に増やすと、積が 0 からゼロ以外の可能性のある値に変化し、これが他のほとんどの変化を支配します。 同様に、この問題では数字が 1 つの整数のままであるため、9 を 10 に増やすことはできません。そのため、増加後の最大値は、数字の構造ではなく、値のみで 10 になります。 

ゼロが存在する場合、エッジ ケースが表示されます。 「最大の桁を増やす」ことを前提とした単純なアプローチは、大失敗する可能性があります。 

たとえば、次のように考えてみましょう`[0, 1, 9]`。 9 を増やすと製品 0 が得られ、1 を増やすと製品 0 が得られますが、0 を増やすと製品 0 が得られます。`[1, 1, 9]`そして製品 9 が最適です。 

したがって、本当の問題は規模だけではなく、製品へのわずかな貢献です。 

## アプローチ

 ブルートフォースアプローチは簡単です。 各インデックスを 1 回増分して積を計算し、最大値を取得します。 n ≤ 9 であるため、これはテスト ケースごとに最大 9 つの候補があり、各積の計算に最大 9 回の乗算がかかることを意味するため、実際には合計は一定時間になります。 

これが機能するのは、決定空間が非常に小さく、複数の選択肢を結び付ける制約がないためです。 ブルートフォースが失敗するのは、ローカルな数字のプロパティが最適なグローバル製品を決定すると仮定して、誤って貪欲に最適化を試みた場合のみです。 

解決策を明らかにする観察は、単一の変更された位置を超えて選択肢間に相互作用がないということです。 すべての候補解は独立しているため、すべての可能性を列挙することが最適かつ十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テストあたり O(n²) | お(1) | 承認済み |
 | 最適 | テストあたり O(n²) (同じ考え方) | お(1) | 承認済み |

 ここで、いわゆる「最適な」ソリューションは、制約によってすでに最適化されているため、単純に総当りそのものです。 

## アルゴリズムのチュートリアル

 1. テスト ケースの数字の配列を読み取ります。 
2. ベースラインのアイデアを計算します。各インデックスを 1 回だけ変更してみます。 これにより、すべての有効な構成を確実に調査できます。 
3. インデックス i ごとに、a[i] を一時的に 1 ずつ増やします。 
4. この変更後のすべての桁の積を計算します。 これは、i を選択した結果を直接評価します。 
5. a[i] を復元し、次のインデックスに進みます。 
6. すべての選択肢にわたって確認された最大の製品を追跡します。 
7. 最大値を出力します。 

### なぜ効果があるのか

 有効な各解は、増分された数字の位置によって一意に決定されます。 それ以外の自由度はありません。 考えられるすべての選択肢を評価するため、最適な選択肢が含まれることが保証されます。 正確さは、一定サイズの決定空間にわたる徹底的な列挙から得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    best = 0

    for i in range(n):
        a[i] += 1

        prod = 1
        for v in a:
            prod *= v

        best = max(best, prod)

        a[i] -= 1

    print(best)
```このソリューションは、考えられる各増分位置をテストするというアイデアを直接実装しています。 インデックスごとに、インデックスを変更し、完全な積を再計算して復元します。 変更を元に戻さないとその後の評価が損なわれる可能性があるため、復元手順は重要です。 

n ≤ 9 なので、積を繰り返し再計算するのは低コストです。 ネストされたループによってパフォーマンスの問題が発生することはありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        best = 0

        for i in range(n):
            a[i] += 1
            prod = 1
            for v in a:
                prod *= v
            best = max(best, prod)
            a[i] -= 1

        out.append(str(best))

    return "\n".join(out)

 ## 特殊なケース

 配列にゼロが含まれる場合、積を 0 から正の値に変換するため、ほとんどの場合、ゼロをインクリメントするのが最適な方法です。 このアルゴリズムは、ゼロを含むすべてのインデックスをバイアスなしで明示的に評価するため、これを正しく処理します。 

すべての数字が同一の場合、どの選択をしても同じ積構造が得られ、列挙によってこの対称性が自然に捉えられます。 

n = 1 の場合、唯一の有効な操作はその 1 桁をインクリメントすることであり、アルゴリズムはその唯一の可能性を正しく評価し、その値を返します。
