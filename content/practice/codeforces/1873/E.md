 ## 解決策
 ## 問題の理解

 それぞれに初期の高さが設定されたサンゴの列の行が与えられます。 均一な目標高さを選択して、この構造物の上に水槽を構築したいと考えています$h$。 サンゴが下にある柱$h$まで水で満たされます$h$、すでに上にある列はいずれも$h$水は必要ありません。 

したがって、各列の水の寄与は次のようになります。$\max(0, h - a_i)$、使用される水の合計はこれらの寄与の合計です。 目標は、可能な限り最大の整数を選択することです$h \ge 1$必要な総水量が以下を超えないようにする$x$。 

重要な問題は、$h$各カラムが影響を及ぼし始めるのは、$h$その高さを超えています。 

制約が十分に大きいため、テスト ケースごとの 2 次スキャンまたは線形スキャンは遅すぎます。 まで$2 \cdot 10^5$すべてのテスト ケースにわたる要素の合計と$t \le 10^4$、大まかに必要です$O(n \log A)$または$O(n)$テストケースごとに。 多くの候補高さに対して水の使用量を最初から再計算するアプローチはタイムアウトになります。 

いくつかのエッジの状況を切り分ける価値があります。 

もしすべてなら$a_i$に比べて大きい$x$、答えは近くなります。$\max(a_i)$またはそれよりわずかに上です。$h$ほんの少しでもすでに水の予算を超えている可能性があります。 たとえば、次の場合$a = [100]$そして$x = 5$、 それから$h = 105$定義を注意深く解釈した場合にのみ機能します。$h - a_i$貢献するので、$h = 105$ちょうど5の水を使用します。 

もしすべてなら$a_i$等しいし、$x$が大きい場合、答えは次のように直線的に増加します。$x$, すべての単位が増加するため、$h$正確に追加します$n$水。 

単純な間違いは、水が連続してソートされた要素間のギャップにのみ依存すると考えることです。しかし、実際には、水はすべての要素に同時に依存し、次のように継続的に蓄積されます。$h$が増えます。 

## アプローチ

 直接的なアプローチは、可能な値をすべて試してみることです。$h$1から次のようなものまで$\max(a_i) + x$。 候補となる身長ごとに、合計して必要な総水量を計算します。$\max(0, h - a_i)$全体$i$。 This is correct, but each evaluation costs$O(n)$、および範囲$h$と同じ大きさにすることができます$10^9 + x$。 合理的な範囲に制限したとしても、たとえば$10^9$、これは完全に不可能になります。 

重要な観察点は、関数が$$f(h) = \sum_{i=1}^n \max(0, h - a_i)$$は単調です$h$。 増加中$h$水の使用量を増やすか維持することしかできず、減らすことはできません。 この単調性により、二分探索が可能になります。$h$。 

評価するには$f(h)$効率的に配列をソートします。 分類が完了すると、構造化された方法で寄与度を計算できます。 閾値を固定すると$h$、すべての要素以上$h$寄与ゼロおよびそれ以下のすべての要素$h$直線的に貢献します。 プレフィックスの合計を使用すると、次の合計を計算できます。$h - a_i$全体$a_i < h$前処理後の一定時間内。 

これにより、各チェックが次のように削減されます。$O(\log n)$二分探索ステップの場合、または$O(1)$プレフィックスの合計を事前に計算し、二分探索を使用してカットオフ インデックスを見つけた場合。 

したがって、問題は古典的な「単調制約下の実現可能な最大値」になります。

 ## アルゴリズムのチュートリアル

 1. 配列をソートする$a$降順ではない順に。 選別により、選択した水に寄与する要素とそうでない要素を分離することができます。$h$。 
2. ソートされた値に対してプレフィックス合計配列を構築します。 これにより、毎回反復することなく、セグメントの合計をすばやく計算できます。 
3. 関数を定義する$f(h)$特定の高さに必要な総水量を計算します。 最初のインデックスを見つけます$i$そのような$a_i \ge h$。 そのインデックスより前のすべてのものは水に寄与します。 
4. もし$k$は要素の数です$a_i < h$、すると水の使用量は$k \cdot h - \text{sum of those } a_i$。 この式は展開から得られます$\sum (h - a_i)$。 
5.二分探索$h$。 検索範囲は安全に最大まで拡張できます。$\max(a_i) + x$、それを超えると、水の必要量は少なくとも直線的に増加するため、$n$。 
6. 各中間点について$h$、計算する$f(h)$。 予算内であれば$\le x$、増やしてみることができます$h$。 それ以外の場合は、それを減らします。 
7. 最終的な答えが最大です$h$それは制約を満たします。 

二分探索が機能する理由は、ある高さが実行不可能になると、それ以上の高さは実行不可能のままであるためです。$h$少なくともカラムの数だけ水の使用量が増加します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import bisect

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]

        def water(h):
            idx = bisect.bisect_left(a, h)
            return h * idx - pref[idx]

        lo, hi = 1, max(a) + x + 1

        while lo < hi:
            mid = (lo + hi) // 2
            if water(mid) <= x:
                lo = mid + 1
            else:
                hi = mid

        print(lo - 1)

if __name__ == "__main__":
    solve()
```この実装は、プレフィックスの合計と二分検索を有効にするためにソートに依存しています。 プレフィックス配列は、最初の値の合計を計算するために不可欠です。$k$一定時間内の要素。 

機能`water(h)`重要な式を分離します。 の`bisect_left`呼び出しは、厳密に以下の要素の数を見つけます。$h$これは、どのカラムが水を必要とするかを直接決定します。 

二分探索は、配列のインデックスではなく、応答空間に対して実行されます。 上限は次のように選択されます$\max(a_i) + x + 1$なぜなら、最も有利な場合であっても、ユニットの高さが増加するたびに、寄与する柱ごとに少なくとも 1 ユニットの水が必要になるからです。

 ## 特殊なケース

 単一要素の配列は最も単純な動作を示します。 のために$a = [5], x = 0$、水の関数は次のようになります。$\max(0, h-5)$。 どれでも$h > 5$は無効なので、答えは正確に 5 です。その境界で実現可能性が反転するため、二分探索は依然として正しく動作します。 

すべての要素が等しい場合、次のようにします。$a = [2,2,2,2]$、増加するたびに$h$水を正確に 4 だけ増加させます。関数は次の値を超えると完全に線形になります。$h=2$、したがって最大$h$は$2 + \lfloor x/4 \rfloor$。 このアルゴリズムは、特別なケースを必要とせずに、プレフィックス計算を通じてこれを自然に取得します。 

いつ$x = 0$、答えは次のようになります。$\min(a_i)$水の使用を許可しない場合に限ります。最小値を超えて増加すると、直ちに水のコストがプラスになるためです。 実行可能性チェックではすべてが正しく拒否されます$h > \min(a_i)$。
