 ## 解決策
 ## 問題の理解

 文字だけで構成される文字列が与えられます`A`そして`B`、隣接する文字のペアに対して 2 種類の操作を実行できます。 最初の操作では、`AB`ペアに変えることができます`BC`コインを獲得するために。 2 番目では、`BA`ペアに変えることができます`CB`コインを獲得するために。 目標は、収集したコインの数を最大化することです。 

各テスト ケースでは 1 つの文字列が与えられ、その文字列で取得できる最大コインを表す 1 つの整数を出力する必要があります。 この制約は、すべてのテスト ケースにわたる文字列長の合計が最大 200,000 であることを示しています。 これは、テスト ケースごとに各文字を一定回数検査するアルゴリズムや、部分文字列を線形にスキャンするアルゴリズムは十分に高速であることを意味します。 すべての部分文字列を明示的にチェックする 2 次アプローチでは、大まかに次のことが必要になります。$n^2$最悪の場合、手術が行われる可能性があります。$4 \cdot 10^{10}$制限時間を大幅に超えた作戦。 したがって、リニアスキャンが必要です。 

明らかではないエッジ ケースには、完全に 1 文字で構成される文字列が含まれます。たとえば、`AAAAA`または`BBBB`。 このような場合、操作は実行できず、正しい出力はゼロになります。 もう 1 つの微妙なケースは、次のような交互パターンです。`ABABAB`。 操作が左から右に貪欲に適用される場合、アルゴリズムは、コインを生成する可能性がある重複するペアをスキップすることを回避する必要があります。 たとえば、`ABA`、申請中`AB → BC`最初はまだ残りを許可します`BA`2 番目のステップで変換され、合計 2 枚のコインが得られます。 キャラクターを「使用済み」としてマークするのが早すぎる不注意な実装は、コインを過小評価する可能性があります。 

## アプローチ

 ブルートフォース手法は簡単です。文字列をスキャンして、`AB`または`BA`ペアを作成し、変換を適用してコインを獲得し、ペアがなくなるまで繰り返します。 これは正しいです。各変換はペアを消費して 1 つのコインを生成するため、操作の合計数は取得可能な最大コインに正確に対応します。 問題は複雑さとともに発生します。各変換では、新しいペアを見つけるために文字列を再スキャンする必要があり、潜在的に時間がかかることがあります。$O(n^2)$素朴にやれば時間。 

重要な観察は、コインが発生するたびに獲得されるということです。`AB`または`BA`、そして変換によって生成されるのは、`C`2 番目の文字の代わりに使用します。これを新しい有効なペアの一部にすることはできません。 これは、それぞれが`AB`または`BA`元の文字列の は、左から右に注意深くスキャンし、ペアを置き換えながら正確に 1 回カウントできます。 左から貪欲に処理する場合、あるペアを別のペアよりも選択する利点はありません。キャラクターが一度変換されると、重複するペアは自動的に処理されます。`C`、今後の操作には参加しません。 これにより、問題は 1 回のリニア スキャンに軽減され、隣接する文字をチェックしてペアをカウントします。

 ## アルゴリズムのチュートリアル

 1. コインカウンターをゼロに初期化します。 これにより、文字列から取得したコインの合計数が累積されます。 
2. インデックスを使用して、文字列の左から右へのスキャンを開始します。`i`ゼロに初期化されます。 
3. 各位置で、現在の文字と次の文字が同じ形をしているかどうかを確認します。`AB`または`BA`ペア。 どちらでもない場合は増分します`i`1つずつ続けてください。 
4. ペアの場合`AB`または`BA`が見つかった場合、コインカウンタを 1 つインクリメントします。 動く`i`数えたばかりのペアをスキップするには、2 つの位置を進めます。 これが必要なのは、ペアの 2 番目の文字が効果的に次のように変換されるためです。`C`新しいペアの一部になることはできません。 
5. インデックスが作成されるまで手順 3 ～ 4 を繰り返します。`i`文字列の最後から 2 番目の文字に到達します。 
6. テスト ケースの結果としてコイン カウンタを返します。 

なぜ機能するのか: 不変条件は、有効なコードに遭遇するたびに、`AB`または`BA`ペアの場合、1 コインと交換できますが、その後別のペアに寄付することはできません。 左から右にスキャンすることで、機会を逃すことなく、可能性のある各コインを正確に 1 回カウントすることが保証されます。 重複するペアは移動するため自然に処理されます。`i`2 倍にすることで、二重にカウントされなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_coins(s: str) -> int:
    n = len(s)
    coins = 0
    i = 0
    while i < n - 1:
        if (s[i] == 'A' and s[i + 1] == 'B') or (s[i] == 'B' and s[i + 1] == 'A'):
            coins += 1
            i += 2
        else:
            i += 1
    return coins

t = int(input())
for _ in range(t):
    s = input().strip()
    print(max_coins(s))
```機能`max_coins`文字列の単一の線形スキャンを使用します。 隣接する各文字のペアを 1 回だけチェックします。 変換が成功した後にインデックスを 2 つインクリメントすることで、変換された文字が再利用されることがなくなります。`C`。 テスト ケース管理の場合、メイン ループはテスト ケースの数を読み取り、各文字列を処理し、結果を出力します。

 ## 特殊なケース

 文字列`AAAAA`には有効なペアがありません。 左から右にスキャンすると、`i`遭遇せずに0から4まで移動する`AB`または`BA`。 予想通り、コインカウンターはゼロのままです。 のために`ABA`、左から右へのスキャンでは最初のスキャンが正しくカウントされます。`AB`ペアになりますが、後続は無視されます`A`それはペアを形成することができません。 のために`ABABAB`、隣接するすべての`AB`または`BA`重複する文字を二重にカウントせずにペアがカウントされ、貪欲なスキップの正確性が確認されます。 これらの具体的なトレースは、アルゴリズムが最小長、最大長、および交互のパターンを正しく処理していることを示しています。
