 ## 解決策
 ## 問題の理解

 セルのストリップを表すバイナリ文字列が与えられます。各位置は黒または白です。 許可される唯一の操作は、固定長の連続セグメントを選択することです$k$そしてそのセグメント内のすべてのセルを白に再描画します。 目標は、このようなセグメント再描画操作をできるだけ少なくして、すべての黒セルを除去することです。 

重要な観察は、各操作が同じサイズの連続したウィンドウに影響を与えるということです。$k$、そのウィンドウ内の複数の黒いセルを同時にクリアできます。 ただし、操作はオーバーラップを通じて相互作用するため、問題は黒のセルを数えることではなく、これらの固定長の「消しゴム」をどのように最適に配置してすべての黒の位置をカバーできるかということです。 

制約により、最大で次のことが許可されます。$2 \cdot 10^5$すべてのテスト ケースの合計文字数。 これにより、各黒セルに対してすべての可能なウィンドウを試したり、二次時間で文字列に対して各操作を素朴にシミュレートしたりするソリューションは即座に除外されます。 アン$O(n^2)$このアプローチでは、重複するセグメントを繰り返しスキャンまたは更新する必要があり、制限時間内に終了しません。 

この問題には、微妙な特殊なケースがいくつか現れています。 

もし$k = 1$、各操作でクリアされるセルは 1 つだけなので、答えは正確に黒いセルの数になります。 単純なスライディング ウィンドウのアイデアは、このケースを過度に複雑にする可能性があります。 

文字列に黒いセルがない場合、答えはゼロになります。 少なくとも 1 つの操作が必要であると想定するアルゴリズムでは、誤って正の値が出力されます。 

黒いセルが長いブロック内で連続して出現する場合、貪欲な方法では、重複する消去を不必要に適用して操作を過剰にカウントしないようにする必要があります。 

たとえば、文字列では`BBBW`と$k = 3$、位置 0 で 1 回の操作を行うと、3 つの黒いセルがすべてクリアされます。 各黒セルを個別に処理する不用意なアプローチでは、複数の重複した操作が適用され、過剰にカウントされる可能性があります。 

## アプローチ

 ブルートフォース手法では、考えられるすべての操作シーケンスをシミュレートします。 各ステップで、任意のサイズのウィンドウを選択してみることができます。$k$少なくとも 1 つの残りの黒いセルをカバーし、それを適用して再帰します。 これは原理的には正しいですが、分岐係数が大きく、状態空間が指数関数的に増大します。 最適なウィンドウを繰り返しスキャンして文字列を更新する貪欲な亜種であっても、次のように劣化します。$O(n^2)$最悪の場合、各操作で少数の新しい黒セルしか除去されない場合もあります。 

作戦の構造は、より直接的な戦略を示唆しています。 黒のセルに遭遇した場合、唯一意味のある決定は、それをカバーする操作を適用することです。 どの操作もセグメント全体の長さに影響するため、$k$、最適な選択は、一番左の覆われていない黒いセルをアンカーとして使用し、そこから始まるセグメントを消去することです。 開始の前後に開始される操作は、このセルをカバーできないか、すでにクリーンな領域のカバレッジを無駄にします。 

これは、単純な貪欲なスイープにつながります。左から右に移動し、前の操作でまだカバーされていない黒いセルを見つけるたびに、その位置から開始する操作を適用します。 これにより、そのセルと次のセル内のすべての黒いセルが即座にクリアされます。$k-1$位置が決まっているので、安全に先にスキップできます。

 ## アルゴリズムのチュートリアル

 最後に適用された操作がどこまで続くかを維持しながら、文字列を左から右に処理します。 

1. ポインタを初期化する$i = 0$そして変数$covered = -1$、前の操作によってクリーンアップされた右端のインデックスを追跡します。 
2. 文字列を左から右にスキャンします。 
3. もし$i \leq covered$、現在のセルは前の操作によりすでに白になっているため、次のインデックスに移動します。 
4. もし$s[i] = 'B'$、これは覆われていない黒セルなので、次から始まる新しい操作を適用する必要があります。$i$。 
5. 応答カウンタをインクリメントして設定します。$covered = i + k - 1$、この操作によってクリーンアップされた全範囲を表します。 
6. スキャンを続行します。 

各操作は、最初のカバーされていない黒セルで強制的に実行されます。これは、それを遅らせたり、右にシフトしたりすると、この位置が処理されないままになるためです。 

### なぜ効果があるのか

 このアルゴリズムは、すべての操作が固定長の間隔をカバーするという事実に基づいています。 位置で左端の覆われていない黒セルをカバーすることに決めたら$i$、最適なソリューションには、以下をカバーする操作が少なくとも 1 つ含まれている必要があります。$i$。 このようなすべての操作の中で、$i$修正しながら右側の範囲を最大化できるため、後で開始することよりも悪いことはありません。$i$。 これにより、貪欲な選択特性が作成されます。最初に覆われていない黒セルを修正すると、問題は以前の決定とは独立した厳密に小さな接尾辞に縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    s = input().strip()

    ans = 0
    covered = -1

    for i in range(n):
        if i <= covered:
            continue
        if s[i] == 'B':
            ans += 1
            covered = i + k - 1

    print(ans)
```重要な実装の詳細は次のとおりです。`covered`ポインタを使用すると、文字列を明示的に変更する必要がなくなります。 再描画をシミュレートする代わりに、最後の操作がどこまで広がったかを記録します。 これにより不要なことが防止されます$O(k)$操作ごとに更新され、ソリューションが線形に保たれます。 

条件`i <= covered`これにより、以前の消しゴムによってすでに処理された位置が再検討されることがなくなります。 小切手`'B'`必要な場合にのみ操作をトリガーすることを保証します。

 ## 特殊なケース

 いつ$k = 1$の場合、アルゴリズムは当然のことながら、各黒セルを独自の操作が必要なものとして扱います。 それぞれが明らかになった`'B'`答えをインクリメントして設定します`covered = i`, そのため、スキップエラーは発生しません。 

黒のセルがない場合、条件が次のとおりであるため、ループは操作をトリガーしません。`s[i] == 'B'`決して満たされない。 結果はゼロのままです。 

より短い距離内で黒マスが重なり合う場合$k$、最初に遭遇した黒いセルは、それらすべてを自動的にカバーする操作をトリガーします。 例えば、`BBBW`と$k = 3$セット`covered = 2`、追加の操作を行わずに残りをスキップします。これは最適な戦略と一致します。
