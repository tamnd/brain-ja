 ## 解決策
 ## 問題の理解

 私たちは、あるプレイヤー、ヴァレリューが、正確に接続されたグラフとしてモデル化された都市で、別のプレイヤー、マルセルに捕まることを無期限に回避できるかどうかを判断するように求められています。$n$建物と$n$道路。 各建物はノードであり、各道路は 2 つのノードを接続する無向エッジです。 マルセルとヴァレリューは特定の建物からスタートし、隣接する道路に沿って移動することも、ターン中その場にとどまることもできます。 重要なのは、ヴァレリューがマルセルの次の動きを事前に知っており、捕らえられないように最適に行動することです。 両方が同時に同じ建物内または同じ道路上にある場合、キャプチャが発生します。 

各テスト ケースは、グラフ構造と開始位置を提供します。 Valeriu が永遠に逃げられる場合は「YES」、そうでない場合は「NO」を出力する必要があります。 

この制約により、すべてのテスト ケースを組み合わせると最大 200,000 の建物が生成され、考えられるすべての動きの単純なシミュレーションが除外されます。 各操作は基本的に次のようにする必要があります。$O(n)$テストケースごと、または$O(n \log n)$せいぜい。 両方のプレイヤーのすべての動きをシミュレートするなどの単純なアプローチは、指数関数的に爆発的に増加します。 

不注意な解決策に陥ることが多いエッジケースには、次のようなものがあります。 

- ヴァレリューがいつでもマルセルを反映できる小さなサイクル。 たとえば、マルセルが 2、バレリウが 1 の三角形です。グラフがループバックするため、マルセルはバレリウを追い詰めることができません。 
- マルセルがヴァレリューの非常に近くで開始し、グラフが「ハブ」構造を持つ場合。 たとえば、マルセルが中心から始まる星形グラフです。 バレリューが葉の上からスタートした場合、彼はすぐにバレリューを捕まえることができます。 単純な距離のみのチェックでは、これを見逃す可能性があります。 
- ブリッジまたは長いチェーンを含むグラフ。エスケープは最短経路だけではなくグラフの直径に依存します。 

これらを理解することで、距離計算における 1 つずつの間違いを回避し、すべてのグラフがサイクルまたはツリーであると想定することを回避できます。 

## アプローチ

 ブルートフォースアプローチは、マルセルとバレリューのあらゆる一連の動きをシミュレートすることです。 マルセルは現在のノードから可能なすべての動きを試し、ヴァレリューはそれらを観察して最適に対応します。 最適なプレイでは両方のプレイヤーの動きが決定的であるため、これは概念的に機能しますが、各ノードには次数があります。$O(n)$、動きは無限に繰り返される可能性があり、状態空間のサイズが指数関数的に大きくなります。 のために$n = 2 \cdot 10^5$、これはまったく不可能です。 

重要な洞察は、問題をグラフの距離に近づけることから得られます。 都市をツリーまたは接続されたグラフとして扱うと、$n$ノードと$n$エッジ（木と追加のエッジが 1 つ）であるため、バレリューがすぐに捕まることを防ぐ唯一の要因は、マルセルのスピードを考慮して彼が常に手の届かないところにいられるかどうかです。 マルセルは、彼らが接近してスタートし、グラフが十分に短い場合、すぐにバレリューを捕まえることができます。 それ以外の場合、グラフに十分な長さのパス (直径) があり、ヴァレリューが最初から十分に離れている場合、彼はサイクルまたは分岐を使用して無限に先を進むことができます。 

具体的には、マルセルとバレリューの間の最短パス距離が 1 より大きく、バレリューが常にマルセルを追い越せる十分な長さのパス (グラフの直径の約半分) がグラフに含まれている場合、バレリューはキャプチャを回避できます。 これにより、任意のノードの BFS を使用して距離とグラフの直径を効率的に計算できるようになります。 グラフは接続されていて疎であるため、BFS は線形です。$n$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n!) または指数 | O(n) | 遅すぎる |
 | 距離と直径の分析 | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 道路接続を使用してグラフの隣接リストを作成します。 これにより、隣接するものを効率的に通過できるようになります。 
2. BFS を使用して、マルセルの開始建物から他のすべての建物までの最短経路距離を計算します。 させて$d(a,b)$ヴァレリューまでの距離になります。 もし$d(a,b) \le 1$, マルセルは移動または滞在することですぐにヴァレリューを捕まえることができるので「NO」を出力します。 
3. 2 つの BFS トラバーサルを使用してグラフの直径を計算します。 任意のノードを選択し、BFS を実行して最も遠いノードを見つけます$x$、次に BFS から$x$最も遠いノードを見つけるには$y$。 間の距離$x$そして$y$直径です。 これは、ヴァレリューが脱出するために利用できる最大の長さを示します。 
4. グラフの直径がマルセルとヴァレリューの間の距離に比べて小さい場合、最終的にはマルセルが彼を追い詰めることになります。 それ以外の場合、ヴァレリューは最長のパスまたはサイクルを使用して無限に回避することができます。 
5. Valeriu が永遠に逃げられる場合は「YES」、そうでない場合は「NO」を出力します。 

機能する理由: マルセルがヴァレリューを捕まえられるかどうかは、最初の距離とグラフの構造という 2 つの要素に依存します。 BFS 距離チェックにより、キャプチャが即時に行われるかどうかがわかります。 直径チェックにより、都市が十分に長い場合、ヴァレリウには追い詰められることなく予測どおりに移動できる余地があることが保証されます。 これにより、無限ゲームが有限の計算可能なグラフのプロパティに縮小されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def bfs_farthest(n, adj, start):
    dist = [-1] * (n + 1)
    dist[start] = 0
    q = deque([start])
    farthest_node = start
    while q:
        u = q.popleft()
        for v in adj[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)
                if dist[v] > dist[farthest_node]:
                    farthest_node = v
    return farthest_node, dist

def solve():
    t = int(input())
    for _ in range(t):
        n, a, b = map(int, input().split())
        adj = [[] for _ in range(n + 1)]
        for _ in range(n):
            u, v = map(int, input().split())
            adj[u].append(v)
            adj[v].append(u)

        # Distance between Marcel and Valeriu
        _, dist_a = bfs_farthest(n, adj, a)
        if dist_a[b] <= 1:
            print("NO")
            continue

        # Graph diameter
        x, _ = bfs_farthest(n, adj, 1)
        y, dist_x = bfs_farthest(n, adj, x)
        diameter = max(dist_x)

        if dist_a[b] * 2 <= diameter:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```Marcel の BFS は正確な距離を計算して、即時の捕獲を決定します。 2 ステップの BFS は、すべてのペアの距離を必要とせずに、グラフの直径を効率的に見つけます。 BFS はすべてのパスを尊重するため、サイクルやスター グラフなどのエッジ ケースは自然に処理されます。 

## 実用的な例

 **サンプル 1:** トライアングル、マルセルが 2、バレリューが 1。 

| ステップ | マルセルからのノード距離 | 即時捕獲？ | 直径 |
 | --- | --- | --- | --- |
 | 2からのBFS | [2:0、1:1、3:1] | dist(a,b)=1 → NO | 2 |
 | 決定 | マルセルはすぐには捕まえることができません。 直径 = 2 | はい | |

 ヴァレリューは、三角形の周りでマルセルの動きを無限に反映できます。 

**サンプル 2:** 4 ノード、Marcel が 1、Valeriu が 4 (スター グラフ)。 

| ステップ | マルセルからのノード距離 | 即時捕獲？ | 直径 |
 | --- | --- | --- | --- |
 | 1からのBFS | [1:0,2:1,3:1,4:1] | dist(a,b)=1 → NO | 2 |
 | 決定 | マルセルが隣接し、すぐにキャプチャします。 いいえ | |

 これにより、直径が小さい開始位置が近いと脱出が防止されることが確認されます。
