 ## 解決策
 ## 問題の理解

 私たちには木の列が与えられ、それぞれの木には高さと果物の数という 2 つの属性があります。 これらのツリーの連続したセグメントを選択したいと考えています。 セグメントは、セグメント内を左から右に移動して、すべての木の高さが次の木の高さで割り切れる場合にのみ有効です。 これにより、セグメントの開始場所と終了場所を制限する方向性のある分割チェーンが作成されます。 

すべての有効なセグメントの中で、木の数が最大のセグメントが必要ですが、追加の制限があります。そのセグメントから収集される果物の総数は、指定された制限を超えてはなりません。$k$。 両方の条件を満たすセグメントがない場合、答えはゼロになります。 

主な難点は、妥当性が 2 つの独立した制約に依存することです。 1 つは構造的なもので、隣接する高さの間の可分性の関係から生じます。 もう 1 つは定量的なもので、成果の合計から生じます。 

入力サイズが到達しました$2 \cdot 10^5$すべてのテスト ケースにわたって行われるため、すべてのサブ配列を直接チェックするソリューションは制限時間内に収まりません。 二次列挙は約$n^2$テスト ケースごとのセグメント チェック。最悪の場合は約$10^{10}$作戦全体としては、実現可能性をはるかに超えています。 

隣接するすべてのペアですぐに割り切れない場合、微妙なエッジ ケースが発生します。 たとえば、高さが次の場合、`[2, 3, 5]`の場合、1 より長いセグメントは無効になります。 フルーツ制約をチェックするだけの単純な解決策では、誤って長いセグメントが考慮されてしまいます。 

可分性がどこでも成立するが、フルーツの値が大きい場合には、別の特殊なケースが発生します。 たとえば、高さ`[8, 4, 2]`完全に有効な連鎖を形成しますが、果物が`[10, 10, 10]`そして$k = 15$、長さ 2 のセグメントであっても、構造的妥当性にもかかわらず無効です。 

これら 2 つの制約は、最初に問題を管理可能なブロックに分割する必要があることを示唆する方法で相互作用します。 

## アプローチ

 構造を少し無視すると、問題は最大でも合計を含む最長の部分配列を見つけることになります。$k$、これは標準的なスライディング ウィンドウの問題です。 その部分だけは直線的です。 

フルーツ制約を無視する場合、代わりに、すべての隣接するペアが満たされる最大セグメントを見つける必要があります。$h_i \bmod h_{i+1} = 0$。 これは、配列を分割可能性が連続的に維持される最大の「有効なチェーン」に分割することによって事前に計算できます。 各チェーン内では、どのサブセグメントも構造的に有効です。 

ブルートフォース ソリューションでは、すべての開始インデックスを試し、割り算をチェックして累計を維持しながら右に拡張します。 各展開は O(n) であり、n 回繰り返されるため、テスト ケースごとに O(n²) になります。 合計 n まで$2 \cdot 10^5$、これは遅すぎます。 

重要な観察は、割り算の制約によって独立したブロックが定義されるということです。 一度$h_i$分けない$h_{i+1}$、セグメントはその境界を越えることはできません。 したがって、各最大有効ブロックを個別に扱うことができます。 各ブロック内では、問題は純粋に、合計 ≤ k の最長部分配列となり、2 つのポインターを使用して解決できます。 

各ブロックにわたってスライディング ウィンドウを維持し、合計が k 以内にある間は右に拡大し、それ以外の場合は左から縮小します。 各要素がウィンドウに出入りするのはブロックごとに 1 回だけであるため、全体の複雑さは線形のままです。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | ブロック + 2 つのポインター | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を左から右にスキャンし、隣接する各ペアが満たすセグメントを特定します。$h_i \bmod h_{i+1} = 0$。 これらは最大の構造ブロックです。 有効なセグメントがその境界を越えることができないため、条件が失敗するたびにブロックをリセットします。 
2. 各ブロックを個別に扱います。 ブロック内では、すべての部分配列が自動的に割り算条件を満たすため、合計制約のみが関連します。 
3. ブロックの先頭の 2 つのポインターとフルーツの累計を初期化します。 
4. 右ポインタを段階的に伸ばし、現在のフルーツ値を合計に加えます。 延長するたびに、合計が次を超えているかどうかを確認します$k$。 
5. 合計額を超える場合$k$、合計が再び有効になるまで、値を減算しながら左ポインタを前方に移動します。 これにより、現在の正しいエンドポイントで終了する最大ウィンドウ サイズが維持され、可能な限り最小の方法で実現可能性が復元されます。 
6. 右の各エンドポイントで、現在のウィンドウの長さで答えを更新します。 

貪欲に縮むことの正しさは、すべての値が正であるという事実から来ます。 必要以上の要素を削除しても、新しい有効な構成が有効になることなく、ウィンドウがさらに縮小するだけです。 

### なぜ効果があるのか

 このアルゴリズムは 2 つの不変式に依存します。 まず、現在のウィンドウは常に最大可分性ブロック内に完全に存在するため、考慮されるすべての候補セグメントは構造的に有効です。 第 2 に、スライディング ウィンドウは、調整後にその合計が常に ≤ k であるという不変条件を維持します。 すべてのフルーツ値は正であるため、拡張すると合計が増加するだけで、縮小すると合計が単調に減少するだけなので、各ポインターが一方向に移動し、有効な候補がスキップされないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        h = list(map(int, input().split()))

        ans = 0
        l = 0
        s = 0

        i = 0
        while i < n:
            j = i
            while j + 1 < n and h[j] % h[j + 1] == 0:
                j += 1

            # process block [i, j]
            l = i
            s = 0

            for r in range(i, j + 1):
                s += a[r]
                while s > k and l <= r:
                    s -= a[l]
                    l += 1
                ans = max(ans, r - l + 1)

            i = j + 1

        print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、単純なポインター展開を使用して、配列を最大の有効な割り算チェーンに分割します。 条件が失敗するたびに、ブロックを閉じます。 これにより、無効な隣接を越えてセグメントを形成しようとすることがなくなります。 

各ブロック内で、スライディング ウィンドウをリセットし、現在の合計を維持します。 左ポインタは前方にのみ移動し、後方には移動しないため、直線的な複雑さが保証されます。 

ここでよくある間違いは、ブロック境界で合計と左ポインタをリセットしないことです。 このリセットがないと、以前の無効な構造セグメントの要素がウィンドウに誤って含まれる可能性があります。 

## 実用的な例

 ### 例 1

 入力:```
n = 5, k = 12
a = [3, 2, 4, 1, 8]
h = [4, 4, 2, 4, 1]
```可分性構造はブロックを作成します。`[4, 4, 2, 4, 1]`最後のステップを除いてブレークしないため、配列全体が 1 つのブロックになります。 

| r | h 条件が有効 | ウィンドウ (l..r) | 合計 | アクション | 最高 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 開始 | [0] | 3 | わかりました | 1 |
 | 1 | 4%4 | [0,1] | 5 | わかりました | 2 |
 | 2 | 4%2 | [0,1,2] | 9 | わかりました | 3 |
 | 3 | 2 % 4 は失敗しますか? 実際には 2 % 4 ≠ 0、ブロックは早く終了します | 再起動 | | | |

 実はブロックは`[0..2]`そして`[3..4]`。 2ブロック目で`[1,8]`、最適な長さは 2 です。最終的な答えは 3 です。 

これは、構造分割によって無効な遷移によるウィンドウの破損がどのように防止されるかを示しています。 

### 例 2

 入力:```
n = 4, k = 8
a = [5, 4, 1, 2]
h = [6, 2, 3, 1]
```可分性ブロック:

 -`[6,2]`-`[3,1]`最初のブロック:

 - 窓`[5]`、`[5,4]`合計は9 > 8になるので縮小→`[4]`、ベスト1

 2 番目のブロック:

 -`[1,2]`合計 = 3 が有効、最良の 2

 これは、スライディング ウィンドウが各構造セグメント内の合計制約にのみどのように反応するかを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての隣接するペアがすぐに割り切れない場合です。 その状況では、各ブロックのサイズは 1 であり、アルゴリズムは、それぞれの単一のフルーツ値が ≤ k であるかどうかをチェックすることになります。 スライディング ウィンドウは要素間で拡張されることはないため、正確性はすべてのインデックスでのリセットに完全に依存します。 

もう 1 つのケースは、配列全体が 1 つの長い有効なチェーンである場合です。 ここで、アルゴリズムは、合計制約の下で標準の 2 ポインターの最大長部分配列とまったく同じように動作する必要があります。 ブロック ロジックはウィンドウの連続性を妨げてはなりません。 

3 番目の微妙なケースは、大きなフルーツ値が頻繁に縮小を強制する場合に発生します。 すべての値が正であるため、縮小を繰り返すと常に収束し、無限ループは発生しません。
