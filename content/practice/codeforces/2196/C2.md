 ## 解決策
 ## 問題の理解

 すべてのパスを辞書編集順に列挙するシステムと対話することによって、隠れた有向非巡回グラフ (DAG) を再構築するように求められます。 各クエリにより、次のことを尋ねることができます。$k$- 番目のパス。 パスは、連続する頂点がエッジによって接続されるような頂点インデックスのシーケンスです。 課題は、クエリの数が厳密に制限されていることです。$n + m$、 どこ$n$は頂点の数であり、$m$未知のエッジの数です。 

入力で提供されるのは、$n$、頂点の数、すべてのエッジを検出する必要があります。 各クエリはパスを返すか、そのようなパスが存在しないことを示します。 DAG には最大 30 個の頂点を含めることができますが、これはすべての可能なパスに対して組み合わせ推論を可能にするのに十分な小ささです。 パスの辞書編集的な順序付けは非常に重要です。これにより、すべてのパスを明示的にクエリすることなく、DAG 内の頂点の相対位置を推測できるようになります。 

DAG にエッジがない場合、重要なエッジ ケースが発生します。 このシナリオでは、各頂点は単一ノード パスであり、最初の頂点以降のクエリはすべて$n$ゼロを返します。 これが誤って処理されると、すべての頂点に出力エッジがあると想定する単純なアルゴリズムが誤ってさらにパスを抽出しようとし、クエリ制限を超える可能性があります。 もう 1 つの微妙な状況は、複数の頂点が独立したチェーンを開始する場合です。辞書編集パス リスト内の頂点の順序によって、どのチェーンがより早く開始されるかがわかります。これは、エッジの方向を推定するために重要です。 

## アプローチ

 ブルートフォースソリューションは、すべてのパスを順番にクエリし、連続するパスを比較することによってエッジを再構築することです。 これには最大で$2^{30}$最悪の場合はクエリが実行されますが、これは明らかに非現実的です。 指数関数的に増加するため、すべてのパスを保存することさえ不可能です。 

最適なソリューションを明らかにする洞察は、DAG の辞書順の構造から得られます。 DAG では、各頂点から始まる辞書順の最初のパスを考慮すると、そのパス内の一連の頂点によって、どのエッジが存在するかについての直接的な情報が得られます。 具体的には、頂点からの最初のパス$u$のすべての発信近隣を直ちに含めます$u$辞書編集上最小限のものです。 最初のパスに出現する順序で頂点を反復処理することにより、次の値に比例したクエリ数を使用して隣接関係を再構築できます。$n + m$、問題の制約に適合します。 

したがって、すべてのパスをクエリする必要はありません。 まず、まだ処理されていない最小の頂点から始まるパスをクエリし、次にシーケンスを比較して直接の後続頂点を抽出します。 すべての頂点に対してこれを繰り返すことで、範囲内に留まりながらすべてのエッジを確実に検出できます。$n + m$クエリ制限。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(2^n) | 遅すぎる |
 | 最適 | O(n + m) クエリ | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初のクエリから始めます$n$パス。 各クエリ`? k`辞書編集的には$k$- 番目のパス。 返されたシーケンスを保存します。 これにより、すべての開始頂点とその最小パスが初めてわかります。 
2. 空の隣接リストを初期化します。 取得したパスごとに、連続する頂点を反復処理します。 頂点の場合$u$すぐに頂点が続きます$v$パス内でエッジを記録する$u \to v$まだ追加されていない場合。 これは、最初のパスに次のものが含まれるため機能します。$u$最小限の出向きエッジがすべて含まれます。 
3. 重複を避けるために、検出されたエッジのセットを維持します。 同じ頂点で始まるパスの場合、後続のパスにはすでに考慮されているより長い延長部分のみが含まれる可能性があるため、外向きエッジを抽出するために最初のパスのみを考慮します。 
4. クエリが返された場合`0`、この開始インデックスからさらにパスが存在しないことを示す信号として扱います。 まだ処理されていない次の頂点にスキップします。 
5. すべての頂点が処理された後、またはクエリ制限が終了した後$n + m$に達したら、必要な形式で答えを出力します。`! m`、すべてのエッジを任意の順序でリストします。 

機能する理由: 不変条件は、各頂点について、その辞書編集上の最初のパスをクエリすると、DAG の辞書編集上の順序を満たすために存在する必要があるすべてのすぐ隣の頂点が明らかになることです。 DAG は非周期的であるため、エッジが検出されると、将来のパスと矛盾することはありません。 各頂点を順番に処理すると、許可されたクエリ数を超えずにすべてのエッジが確実にキャプチャされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    edges = set()
    queries_used = 0

    # map from vertex to first path starting with that vertex
    first_paths = {}

    for i in range(1, n+1):
        print(f"? {i}")
        sys.stdout.flush()
        queries_used += 1

        q = int(input())
        if q == -1:
            sys.exit(0)
        if q == 0:
            continue

        path = list(map(int, input().split()))
        first_paths[path[0]] = path

    # extract edges from paths
    for path in first_paths.values():
        for u, v in zip(path, path[1:]):
            edges.add((u, v))

    # output result
    print(f"! {len(edges)}")
    for u, v in edges:
        print(f"{u} {v}")
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```最初のセクションでは以下のクエリを実行します。`n`パス。各頂点で始まる最初のパスのみを保存します。 使用する`zip(path, path[1:])`連続する頂点ペアをエッジとして効率的に抽出します。 セットを使用すると、重複したエッジが記録されなくなります。 最終出力では、エッジの総数が出力され、それらが任意の順序でリストされます。

## 特殊なケース

 グラフにエッジがない場合、すべてのクエリは単一の頂点パスを返します。 アルゴリズムはこれらのパスを保存しますが、エッジは抽出しません。 たとえば、入力の場合`n=2`、クエリが返されます`1`そして`2`。 連続するペアが存在しないため、エッジ セットは空のままになり、`! 0`。 

複数の独立したチェーンが存在する場合、各開始頂点からの最初のパスは、辞書編集上最小限の出向きエッジのみをキャプチャします。 のために`n=3`パス付き`1 3`そして`2 3`、クエリすると 1 が返されます`1 3`、エッジを捉える`(1,3)`; クエリすると 2 が返されます`2 3`、捕獲`(2,3)`。 余分なエッジは追加されず、このアプローチが辞書編集上の制約とクエリ制限を尊重していることがわかります。
