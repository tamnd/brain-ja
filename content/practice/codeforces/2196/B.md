 ## 解決策
 ## 問題の理解

 配列が与えられており、配列内のそれらの位置の値とそれらの距離の間に非常に特殊な関係が成立する位置のペアを数えたいと考えています。 2つのインデックスの場合$i < j$、2 つの値の積がインデックス間の距離と正確に一致する場合、そのペアは有効であると見なされます。つまり、$a_i \cdot a_j = j - i$。 

したがって、各テスト ケースでは、すべてのインデックス ペアをスキャンし、この等式を満たすものがいくつあるかを数えるように求められます。 

入力サイズから、すべてのペアを直接検査する方法は最悪の場合には実行できないことがすぐにわかります。 まで$2 \cdot 10^5$テスト ケース全体の要素の合計、$O(n^2)$スキャンは次の順序を意味します$10^{10}$最悪の場合の比較は、2 秒の制限をはるかに超えています。 したがって、すべてのペアを明示的に反復処理することを回避する方法が必要です。 

この条件の微妙な点は、右側はインデックスのみに依存し、左側は値のみに依存することです。 この不一致が構造を可能にします。 

いくつかの特殊なケースは、精神的に隔離する価値があります。 

すべての値が次の場合$1$、状態になります。$1 \cdot 1 = j - i$したがって、距離がちょうど 1 であるペアを数えているだけです。つまり、隣接するペアのみが寄与し、答えは次のようになります。$n-1$。 単純な実装では、すべてのペアを不必要に試行する可能性がありますが、より重要なのは、値が些細な場合でも、多数の有効なペアが存在できることが確認されることです。 

値が大きい場合は、次のようになります。$10^9$の場合、積は巨大であり、考えられる指数の差を簡単に超える可能性があるため、寄与するペアはありません。 不注意な実装では、ほとんどのペアが自動的に無効になることに気づかずに、値を直接照合しようとする可能性があります。 

主な難点は、この条件がインデックスと値を乗算的に結びつけているため、一方を修正してもう一方を効率的に検索できるものに変換する必要があることです。 

## アプローチ

 ブルートフォース手法は簡単です。すべてのペアを反復処理します。$(i, j)$、計算する$a_i \cdot a_j$と等しいかどうかを確認します$j - i$。 これは定義を直接エンコードしているため、これは正しいです。 ただし、すべてを調べる必要があります$\frac{n(n-1)}{2}$テストケースごとのペア。 いつ$n = 2 \cdot 10^5$、これは不可能になります。 

主な観察は、値とインデックスをより効果的に分離する方法で条件を書き直すことです。 から$$a_i \cdot a_j = j - i$$それを次のように並べ替えます。$$j = i + a_i \cdot a_j$$今すぐ修正してください$i$。 それぞれについて$i$、インデックスを見つけたい$j > i$次のような:$$a_j = \frac{j - i}{a_i}$$これはまだ直接役に立ちません。$j$両側に現れます。 重要なコツは、両方のエンドポイントを修正したり、問題を直接解決しようとしたりするのではなく、視点を切り替えることです。$j$、違いによってペアを分類します$d = j - i$。 

一定距離の場合$d$、条件は次のようになります。$$a_i \cdot a_{i+d} = d$$これは純粋に位置関係です。 オフセットごとに$d$、有効なものをすべてスキャンします$i$、どうかを確認してください。$a_i \cdot a_{i+d} = d$。 

これにより、問題は考えられるすべてのギャップを反復処理することになります。$d$。 これは理論的にはまだ二次関数ですが、有効なペアが非常にまばらであるという事実を利用できます。 固定の場合$d$、因数分解のみ$d$貢献できる。 次のように書き換えることができます。$$a_i \cdot a_{i+d} = d$$だから両方とも$a_i$そして$a_{i+d}$の約数でなければなりません$d$。 つまりポジションごとに$i$、私たちは価値観だけを気にします$a_{i+d}$その一致$d / a_i$、これが整数の場合のみ。 

したがって、すべてを列挙するのではなく、$d$、修正します$i$、意味のある候補のみを列挙します。$a_i$位置によって暗示される小さな値の約数として。 重要な観察は、$d$せいぜい$n$、したがって、それはただ$O(\sqrt{n})$有効な各ペアは、割り算可能性によって大きく制約されます。 

これにより、位置を反復して、実行可能な製品と一致する距離のみをチェックする効率的な計数戦略が実現します。

 ## アルゴリズムのチュートリアル

 1. 各インデックスを反復処理します。$i$配列内で。 このインデックスは、潜在的なペアの左端として機能します。 
2. それぞれについて$i$、右に距離を延長することを検討してください$d$から始まる$1$残りの長さまで。 すべてを盲目的にテストするわけではありません$d$ですが、代わりに制約を使用します$a_i \cdot a_{i+d} = d$無効なケースを早期に排除するため。 
3.固定の場合$i$の候補値を試します。$a_i$。 以来$a_i \cdot a_{i+d} = d$、値$d$で割り切れる必要があります$a_i$。 したがって、距離だけを考慮します$d$そのような$d \bmod a_i = 0$。 
4. それぞれについて$d$、必要なパートナー値を計算します$a_{i+d} = d / a_i$。 
5. もし$i + d$範囲内にあり、配列は実際に次の条件を満たします$a_{i+d} = d / a_i$の場合、このペアは有効なものとしてカウントされます。 

このように視点を逆転させる理由は、指数の違いによるものです。$d$は小さな構造化された数値として機能しますが、値は任意です。 乗算を割り算に変えることで、ほぼすべての候補ペアを取り除くことができます。 

### なぜ効果があるのか

 すべての有効なペア$(i, j)$独特の距離感を生み出す$d = j - i$。 そのペアについて、方程式は次のようになります。$d$正確に考慮する$a_i \cdot a_j$。 逆に、すべてのペアを列挙すると、$(i, d)$そのような$d$で割り切れます$a_i$一致する位置が相補的な要素を保持している場合、すべての有効なペアを 1 回だけ正確にキャプチャします。 乗算制約と位置制約の両方が同時に適用されるため、無効なペアはカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ans = 0

        # We fix left endpoint i
        for i in range(n):
            ai = a[i]

            # step size d must satisfy d = ai * aj
            # so d is multiple of ai
            d = ai
            while i + d < n:
                j = i + d
                aj = a[j]

                if ai * aj == d:
                    ans += 1

                d += ai

        print(ans)

if __name__ == "__main__":
    solve()
```コードの中心的な考え方は、考えられるすべての距離での反復を避けることです。 代わりに、開始インデックスごとに$i$の倍数の距離のみをテストします。$a_i$なぜなら、それらだけが積の制約を満たすことができるからです。 これは、検索スペースを縮小する主要な枝刈りステップです。 

ループ変数`d`ギャップを表します$j - i$。 増加させると`ai`分割可能な候補者のみを訪問するようにします。 最終チェック`ai * aj == d`割り算だけでは十分ではないため、これが必要です。 候補のペアリングが代数的に可能であることを保証するだけであり、配列が実際に一致することを保証するものではありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ans = 0
        for i in range(n):
            ai = a[i]
            d = ai
            while i + d < n:
                j = i + d
                if ai * a[j] == d:
                    ans += 1
                d += ai
        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 同一のものの最小限の配列は、可能な限り高密度の有効な構造を示します。 入力用`[1, 1]`、アルゴリズムは次から始まります`i = 0`、セット`d = 1`、位置を確認します`1`、そして見つけます`1 * 1 = 1`, したがって、正確に 1 ペアとカウントされます。 他にインデックスは存在しないため、出力は正しいです。 

など、すべての値が大きい場合`[1000000000, 1000000000]`、アルゴリズムセット`d = 1000000000`最初のインデックスについては、すぐに配列の境界を超え、何もカウントせずに終了します。 これは、このような大きな製品では指数の差が達成できないという事実と一致します。 

次のような有効な乗算構造を持たない配列の場合`[3, 3, 3, 3, 3]`、すべての候補距離はすぐに境界または等価性のいずれかに違反するため、内側のループは答えをインクリメントせず、正しくゼロを生成します。
