 ## 解決策
 ## 問題の理解

 非負の整数の配列が与えられ、最大 3 つの追加の数値を追加できます。 目標は、最終的な数値のマルチセットが非常に特殊な代数条件を満たすようにすることです。つまり、すべての要素の合計がビットごとの XOR の 2 倍に等しくなければなりません。 

この条件は、同じデータの 2 つの異なる集計を結合します。 合計は要素間で線形に動作しますが、XOR はビットごとに動作し、同一ビットのペアをキャンセルします。 課題は、数値を加算すると両方の量がさまざまな方法で変化すること、そして加算は数回のみに制限されることです。 

までの制約$10^5$すべてのテスト ケースにわたる要素は、各テストが線形時間で解決される必要があることを意味します。 追加された数値の組み合わせを検索したり、総当たりの候補を最大数まで使用したりする戦略。$10^9$または$10^{18}$すぐには実行不可能です。 

配列がすでに条件を満たしている場合、微妙なエッジ ケースが発生します。 その場合、追加要素をゼロで出力する必要があります。 もう 1 つの注意が必要な状況は、配列の XOR 構造が単一の数値では修正できないほど「不均衡」である場合です。 XOR 補数を単に追加する単純な試みは、合計と XOR の相互作用の違いを無視するため、失敗することがよくあります。 

たとえば、次のような単一の数字で始めるとします。$[8]$、何も追加しないと合計が得られます$8$と XOR$8$を満たさない$8 = 2 \cdot 8$。 同じ数値を 2 回追加するなどの単純な修正は誤って機能する可能性がありますが、強制される不変条件を理解していないと体系的に信頼できません。 

## アプローチ

 定義されるアイデンティティは次のとおりです。$$\sum a_i = 2 \cdot (a_1 \oplus a_2 \oplus \dots \oplus a_n)$$させて$S$合計となり、$X$XORになります。 私たちが望んでいるのは:$$S = 2X$$ブルート フォース アプローチでは、範囲内の最大 3 つの数値の考えられるすべてのシーケンスが試行されます。$[0, 10^{18}]$。 追加を 2 つまたは 3 つに制限しても、天文学的に大きな検索スペースが得られます。 各候補では、すべての要素の合計と XOR を再計算する必要があり、少なくとも$O(n)$これは制限をはるかに超えています。 

重要な観察は、最終的な方程式が成り立つように、最大​​ 3 つの数値からなる補正セットを構築するものとして問題を扱うことができるということです。 方程式を直接解く代わりに、合計と XOR がどのように変化するかを制御します。 

させて：$$S = \text{initial sum}, \quad X = \text{initial XOR}$$次のように数字を追加する必要があります。$$S + S' = 2(X \oplus X')$$どこ$S'$そして$X'$追加された要素の合計と XOR です。 

秘訣は、最終的な XOR を単純な構造に強制することです。 XORの合計がゼロになる状態で終了することを目指します。 XOR が達成できれば$= 0$、条件は次のようになります。$$\text{sum} = 0$$これはすべての数値がゼロでない限り不可能であるため、代わりに制御された中間変換をターゲットにします。 

建設的な既知の戦略は次のとおりです。 

2つの数字を追加すると$x$そして$y$、合計と XOR の両方を制御できます。 

- 新しい合計は次のように増加します$x + y$- 新しい XOR は次のようになります$X \oplus x \oplus y$次のことを強制したいのです。$$S + x + y + z = 2(X \oplus x \oplus y \oplus z)$$クリーンな構造では、バイナリ分離を使用して合計と XOR の間の不一致を直接修正することで、最大 3 つの数値を使用します。 標準的なアプローチは次のとおりです。 

目標数値を計算します。$$T = S - 2X$$次に、ビット単位の相互作用によって内部キャリー効果がキャンセルされる数値を慎重に選択することで、最終的な等価性が維持されるように XOR を調整します。 古典的な解決策は、問題を、低ビットと高ビットの分離から得られる数値を使用して補正を表現することに還元し、ビット間の干渉がないことを保証します。 

実際には、構築は以下に基づいてケースに分割されます。$S \ge 2X$かどうかを判断し、両方の方程式を同時にバランスさせるために最大 3 つの数値を使用します。

 ## アルゴリズムのチュートリアル

 初期値を定義します$S$(合計)と$X$配列の (XOR)。 

1. コンピューティング$S$そして$X$アレイ上で。 

これにより、配列全体が 2 つの数値でコンパクトに表現されます。 
2. もし$S = 2X$、何も出力しません。 

配列は必要な ID をすでに満たしているため、修正する必要はありません。 
3. それ以外の場合は計算します$d = S - 2X$。 

この値は、現在の状態が条件を満たすまでどれだけ離れているかを測定します。 
4. 合計と XOR の両方を同時に修正する最大 3 つの数値を作成します。 

このアイデアは、意図しないキャリー相互作用を生じさせることなく、ビット寄与を独立して制御する数値を導入することです。 

標準的な建設的なパターンを使用します。 

- 最初の数字は、上位ビット区切り値をエンコードします。 
- 2 番目の数字は XOR 補正を調整します。 
- 3 番目の数値は、両方の制約が一貫するように合計バランスを最終的に決定します。 

正確な構造により、これらの数値を追加した後、最終的な XOR が値になることが保証されます。$X'$そのような$S' = 2X'$。 
5. 作成したリストを出力します。 

### なぜ効果があるのか

 不変条件は、追加された数値の合計と XOR 寄与の間の制御された関係を常に維持することです。 追加される各値は、そのバイナリ表現が以前に固定されたビットに干渉しないように選択され、XOR を独立して追跡しながら合計を線形に調整できます。 この構築により、線形制約 (和) とビットごとの制約 (XOR) の両方を同時に満たすのに十分な自由度が得られるため、最大 3 回の加算後に和と XOR の方程式系が有効な解を得ることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        S = sum(a)
        X = 0
        for v in a:
            X ^= v

        if S == 2 * X:
            print(0)
            print()
            continue

        # Standard constructive fix:
        # We use a known CF construction that always works in <= 3 moves.
        # Idea: add two numbers x and y such that XOR and sum become aligned.
        #
        # We choose:
        # x = S + X
        # y = X
        #
        # Then recompute:
        # New XOR = X ^ (S+X) ^ X = S
        # New sum = S + (S+X) + X = 2S
        #
        # Now condition becomes: 2S = 2 * S (since XOR = S)

        x = S + X
        y = X

        print(2)
        print(x, y)

if __name__ == "__main__":
    solve()
```この解決策は、配列全体を 2 つの不変式 (合計と XOR) に圧縮することに依存しています。 これらが分かると、追加された要素は、XOR が元の合計に等しい予測可能な式に折りたたまれ、同時に合計がその値を 2 倍にするように設計されます。 

微妙な点は、構築では最大の値が使用されることです。$10^{18}$、両方とも安全です。$S$そして$X$は入力値の合計によって制限され、範囲内に留まります。 

演算の順序は重要です。XOR は変更する前に計算する必要があり、計算時に合計に追加された値を含めてはなりません。$x$そして$y$。

def run(inp: str) -> str:

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての要素がゼロである場合です。 この場合、sum と XOR は両方とも 0 なので、条件はすでに成り立ちます。 アルゴリズムはゼロ加算を正しく出力します。$S = 2X$と評価される$0 = 0$。 

もう 1 つのケースは、XOR でキャンセルされてもゼロ以外の合計が残る重複が配列に含まれている場合です。 例えば$[5, 5]$XOR は 0 ですが、合計は 10 です。 アルゴリズムは不一致を検出して構築を適用し、それに応じて合計をスケーリングしながら XOR をゼロからシフトすることで正しい関係を復元する値を生成します。 

3 番目のケースは次の場合に発生します。$S < 2X$、これは素朴に解釈するとマイナスの修正を示唆する可能性があります。 この構築では、差分を直接的に解決することはなく、代わりに、追加されるすべての値を非負かつ有界に保つ代数変換に依存することで、これを完全に回避します。
