 ## 解決策
 ## 問題の理解

 いくつかのテスト ケースが与えられ、各テスト ケースは整数の配列を提供します。 タスクは、長さに比べて広がりが十分に大きい、この配列の連続セグメントが存在するかどうかを判断することです。 より正確には、最大要素と最小要素の差が少なくともそのサブ配列内の要素の数と同じであるサブ配列が必要です。 

各テスト ケースでは、そのようなサブ配列が存在しないことを出力するか、この条件を満たす有効なサブ配列を出力する必要があります。 

すべてのテスト ケースにわたる合計配列サイズの制約は最大 200,000 であり、テスト ケースごとに 2 次またはそれより悪いアプローチは除外されます。 すべての部分配列の最小値と最大値を再計算するソリューションでは、テスト ケースごとにおよそ O(n^2) の作業が必要となり、すぐにタイムアウトになります。 これにより、直線または直線に近い構造が求められます。 

素朴だが重要なエッジケースは、すべての要素が同一である場合です。 この場合、すべての部分配列の最大値から最小値を引いた値はゼロになりますが、少なくとも 1 の長さの部分配列には少なくともその長さの差が必要です。 したがって、答えは常に不可能です。 もう 1 つのエッジ ケースは、有効なサブ配列が配列の端にのみ存在する場合です。これは、サブ配列の構築方法に注意しないと、貪欲な「中間重視」アプローチでは見逃される可能性があります。 

## アプローチ

 直接的なアプローチは、すべてのサブ配列を試して、その最小値と最大値を計算することです。 エンドポイントのペアごとにセグメントをスキャンし、条件が当てはまるかどうかを評価します。 これは問題の定義を正確にチェックするため、正しく機能します。 ただし、サイズ n の配列の場合、O(n^2) 個のサブ配列があり、それぞれの評価に O(n) 時間が必要となり、合計の複雑さは O(n^3) になります。 最小値と最大値を段階的に維持する最適化を行ったとしても、依然として O(n^2) であり、これは n が 200,000 までの場合には遅すぎます。 

重要な観察は、実際にはすべての部分配列を考慮する必要はないということです。 最大値と最小値の間のギャップが長さに比べて十分に大きいものを見つけるだけで済みます。 任意の間隔で考える代わりに、配列が大きなジャンプを示す 2 つの位置の周囲に部分配列を貪欲に構築できます。 

絶対差 |a[i] - a[j]| が次のようなインデックス i と j のペアを考慮します。 大きいです。 i から j までにわたる部分配列を取得する場合、その最大値は少なくとも max(a[i], a[j]) であり、その最小値は最大でも min(a[i], a[j]) です。 長さは j - i + 1 です。値の差がインデックス距離に比べて十分に大きい場合、有効な答えがすぐに得られます。 

これにより、問題はサブ配列の検索から、十分に「急な」ペアが存在するかどうかのチェックに移ります。 必要な有効な部分配列は 1 つだけであるため、建設的な条件を探すことができます。極値を並べ替えたり概念的に追跡したりする場合、配列に短い距離にわたって大きな値のギャップを強制するローカル構成が含まれている場合、常に有効なセグメントを導出できます。 

標準的な解決策はこれをさらに単純化します。インデックスを値でソートした後で隣接する要素をチェックするか、そのような部分配列が存在しない場合は、すべての要素が等しいことを意味する正確な意味で配列が「平坦すぎる」に違いないと推論するだけで十分です。 これは直接的な構築につながります。値の差が少なくともインデックス距離である 2 つの位置が見つかったら、そのセグメントを出力します。

 ## アルゴリズムのチュートリアル

1. 各テスト ケースについて、配列をスキャンし、大きな値の差がそれらの距離を補う可能性がある位置のペアによって定義される候補サブ配列を検討します。 最も単純な候補は、配列を走査しながら要素を比較することで得られます。 
2. これまでに確認された最小値と最大値をその位置とともに繰り返しながら維持します。 目的は、現在位置が以前に確認された極値と有効なセグメントを形成できるかどうかを検出することです。 
3. インデックス i で、a[i] をこれまでに確認された現在の最小値および最大値と比較します。 a[i] が最小値よりも大幅に大きいか、最大値よりも大幅に小さい場合、それらの位置間のセグメントが最大値 - 最小値 ≥ 長さの条件を満たすかどうかをテストします。 
4. いずれかの条件が当てはまる場合は、有効なサブ配列で十分であるため、対応するセグメントが直ちに出力されます。 
5. 有効なペアが見つからずにスキャンを終了した場合は、興味深いサブ配列が存在しないと結論付けます。 

### なぜ効果があるのか

 有効なサブ配列は、セグメントの 2 つの端点に最大値と最小値を持たなければなりません。 左から右にスキャンすると、これらのエンドポイントは以前の位置と現在のインデックスに対応します。 有効なセグメントが存在する場合、スイープで到達した時点で、そのエンドポイントの 1 つが最終的に正しい境界になります。 その瞬間、反対側に保存されている極値が状態を検出することを保証します。 これにより、すべての有効なサブ配列が走査中にその最後の要素によって監視されるため、候補セグメントを見逃すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        min_val = a[0]
        max_val = a[0]
        min_pos = 0
        max_pos = 0

        found = False
        ans_l = ans_r = -1

        for i in range(n):
            if i == 0:
                continue

            # try extending with current element as right endpoint
            if a[i] < min_val:
                min_val = a[i]
                min_pos = i

            if a[i] > max_val:
                max_val = a[i]
                max_pos = i

            # check using current extremes
            if max_val - a[i] >= (i - max_pos + 1):
                ans_l, ans_r = max_pos, i
                found = True
                break

            if a[i] - min_val >= (i - min_pos + 1):
                ans_l, ans_r = min_pos, i
                found = True
                break

        if found:
            print("YES")
            print(ans_l + 1, ans_r + 1)
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```この実装では、左から右にスキャンしながら、実行中の極値とその位置が維持されます。 重要な点は、現在の要素を常に既知の最小値と最大値と比較することです。i で終わる有効な部分配列は、これらのいずれかを反対側の端点として使用する必要があるためです。 

インデックス付けは、内部的に 0 から始まる位置を保存し、出力時にのみ 1 から始まるインデックス付けに変換することによって慎重に処理されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        min_val = a[0]
        max_val = a[0]
        min_pos = 0
        max_pos = 0

        found = False
        ans = None

        for i in range(n):
            if i == 0:
                continue

            if a[i] < min_val:
                min_val = a[i]
                min_pos = i
            if a[i] > max_val:
                max_val = a[i]
                max_pos = i

            if max_val - a[i] >= (i - max_pos + 1):
                found = True
                ans = (max_pos + 1, i + 1)
                break
            if a[i] - min_val >= (i - min_pos + 1):
                found = True
                ans = (min_pos + 1, i + 1)
                break

        if found:
            out.append("YES")
            out.append(f"{ans[0]} {ans[1]}")
        else:
            out.append("NO")

    return "\n".join(out)

 ## 特殊なケース

 すべての値が同一の配列の場合、アルゴリズムは min と max を同じ値に初期化し、max から min を引いた値が増加する可能性のあるセグメントを見つけることはありません。 必要な長さが増加しても値の差がゼロのままであるため、すべての比較は失敗します。 スキャンは完了し、正しく NO を返します。 

サイズ 2 の小さな配列の場合、値が異なる場合、その差は少なくとも 1 であり、差が十分に大きい場合にのみ必要なしきい値も 2 であるため、セグメントは直ちに有効になります。 アルゴリズムは、可能なセグメントのみをチェックし、条件に正確に一致するセグメントを直接返します。 

厳密に増加するシーケンスの場合、最大値から最小値を引いた値が時間の経過とともに増加しても、部分配列の長さは同じ割合で増加するため、不等式が有効性を優先して反転することはありません。 アルゴリズムは継続的に極値を更新しますが、値のギャップがインデックス距離を支配するセグメントに遭遇することはなく、正しい NO 結果が得られます。
