 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$各セルが黒または白のグリッド。 単一の操作は 1 回だけ許可されます。ここでは、$k \times k$正方形にして、その正方形内のすべてのセルを白に再描画します。 この操作の後、一部の行と列が完全に白くなる場合があります。 

再描画後に黒いセルがまったく含まれていない行または列は「白」とみなされます。 目標は、の配置を選択することです。$k \times k$完全に白の行と完全に白の列の合計数が最大になるように正方形を再ペイントします。 

重要な点は、この操作では黒いセルが追加されるのではなく、1 つの固定された正方形内の黒いセルが削除されるだけであるということです。 その正方形の外側では、グリッドは変化しません。 したがって、選択の影響は局所的ですが、行全体または列全体を完了できるため、その影響はグローバルになります。 

制約により許可されるのは、$n \le 2000$、だから、$O(n^3)$さもなければ、より悪い解決策は生き残れません。 すべての単純なスキャン$O(n^2)$配置、行と列の有効性を再計算する$O(n^2)$、に達するでしょう$8 \cdot 10^9$最悪の場合、動作が遅すぎます。 前処理後にほぼ一定時間で各配置を評価する方法が必要です。 

いくつかの特殊なケースは過小評価されがちです。 

演算前に行がすでに完全に白である場合、正方形をどこに配置したかに関係なく、常に 1 が与えられます。 列についても同様です。 たとえば、グリッドが完全に白の場合、答えは次のようになります。$2n$また、静的寄与を分離せずにすべてを再計算する単純なアプローチでは、誤って二重にカウントされたり、誤って再計算されたりする可能性があります。 

もう 1 つの微妙なケースは、行の外側に黒いセルが広がっている場合です。$k \times k$ウィンドウ。 その行は操作によって決して白にすることはできず、この事実は候補位置ごとではなく全体的に検出する必要があります。 

最後に、すべての黒いセルが 1 つの内側にある行または列です。$k \times k$領域は配置に応じて「修正可能」になります。 ジオメトリと間隔の間のこの依存関係が、問題を自明ではないものにしています。 

## アプローチ

 直接的なアプローチでは、消しゴムの左上のあらゆる位置を試します。 位置ごとに、再描画をシミュレートします。$k \times k$ブロックし、全体をスキャンしてどの行と列が完全に白であるかを再計算します。 これはプロセスを正確に反映しているため、これは正しいです。 ただし、配置ごとに行と列の有効性を最初から再計算するにはコストがかかります$O(n^2)$、そして$O(n^2)$これは配置になります$O(n^4)$、それは限界をはるかに超えています。 

行および列ごとの黒数を追跡して最適化したとしても、依然として中核的な非効率に直面しています。つまり、重複する長方形から同じ局所的な寄与を繰り返し再計算することになります。 

重要な点は、配置の選択の影響は、選択した配置と交差する行と列に対してのみ影響するということです。$k \times k$四角。 それ以外は何も変わりません。 したがって、答えを 2 つの部分に分ける必要があります。すでに白になっている行と列と、選択した正方形内に残っている黒のセルを削除することによって白になる行と列です。 

正方形を選択した後に行が完全に白になるには、その行のすべての黒いセルが選択したセルの内側になければなりません。$k \times k$ウィンドウ。 これは、正方形がその行の最小および最大の黒列位置をカバーする必要があり、その垂直方向の配置が行自体と交差する必要があることを意味します。 同じ考え方が列にも対称的に当てはまります。 

したがって、各行と列は、正方形がそれを「固定」できる有効な位置のセットに寄与します。 問題は、すべての正方形の配置にわたって、そのような間隔が重なる数を数えることに帰着します。 

各行と列を左上隅の一連の制約に変換します。$(i, j)$、次に 2D 差分配列を使用して、すべての有効な位置にわたる寄与を累積します。 これにより、各行または列が次のように変換されます。$O(1)$四角形を更新し、最終的な答えはプレフィックスの合計から得られます。

 ## アルゴリズムのチュートリアル

 ソリューションを静的貢献と動的貢献に分けます。 

1. まず、グリッドをスキャンし、行ごとおよび列ごとにすべての黒いセルを記録します。 これにより、すでに完全に白になっている行または列をすぐに識別できます。 このような各行または列は、演算に関係なく、最終的な答えに 1 を与えます。 
2. 少なくとも 1 つの黒セルを含むすべての行について、その左端と右端の黒列の位置を計算します。 黒マスの範囲がこれより広い場合$k$、その後シングルはありません$k \times k$正方形は水平方向にすべてをカバーできるため、操作後にこの行が完全に白になることはありません。 
3. 行が修正可能な可能性がある場合は、正方形の左上隅のすべての位置を決定します。$(i, j)$これにより、行の黒いセグメントの両端がカバーされます。 垂直座標$i$満たさなければなりません$i \le r \le i+k-1$、 それで$i$にある$[r-k+1, r]$。 水平座標は次のことを保証する必要があります$[minCol, maxCol]$広場の中にあるので、$j \in [maxCol-k+1, minCol]$。 これにより、配置可能な空間内に長方形が定義されます。 
4. 2D 差分配列を使用して、この四角形に +1 を加算します。 これにより、この行を完全に白にする消しゴムの配置がすべて 1 回だけカウントされるようになります。 
5. 列に対して同じプロセスを繰り返し、各列を対称的に扱います。 各列は、同じ座標空間内の有効な配置の四角形にも寄与します。 
6. すべての行と列を処理した後、差分配列の 2D プレフィックス合計を計算します。 各セルの値$(i, j)$正方形を配置した場合に完全に白になる行と列の数を表します。 
7. 最終的な答えは、有効なすべての値の最大値です。$(i, j)$に、すでに完全に白になっている行と列の数を加えます。 

### なぜ効果があるのか

 各行または列は、その黒いセルが選択した正方形で完全に覆われているかどうかに基づいて、独立して寄与します。 2D 差分配列により、すべての有効な配置で、完全にカバーされたラインごとに 1 つの寄与が正確に蓄積されることが保証されます。 各行と列は有効な正方形の位置の幾何学的領域に変換され、これらの領域は線形に追加されるため、プレフィックスの合計は単一行の寄与内で二重にカウントされることなく正しく集計されます。 

不変条件は、すべての行を処理した後、すべてのグリッド セルが$(i, j)$消しゴムを置いた場合に白になる行と列の数を正確に保存します。$(i, j)$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
grid = [input().strip() for _ in range(n)]

base = 0
row_min = [n] * n
row_max = [-1] * n
col_min = [n] * n
col_max = [-1] * n

for i in range(n):
    for j in range(n):
        if grid[i][j] == 'B':
            row_min[i] = min(row_min[i], j)
            row_max[i] = max(row_max[i], j)
            col_min[j] = min(col_min[j], i)
            col_max[j] = max(col_max[j], i)

# count already clean rows and columns
for i in range(n):
    if row_max[i] == -1:
        base += 1
    if col_max[i] == -1:
        base += 1

m = n - k + 1
diff = [[0] * (m + 2) for _ in range(m + 2)]

def add(x1, y1, x2, y2):
    diff[x1][y1] += 1
    diff[x2 + 1][y1] -= 1
    diff[x1][y2 + 1] -= 1
    diff[x2 + 1][y2 + 1] += 1

for i in range(n):
    if row_max[i] == -1:
        continue
    if row_max[i] - row_min[i] + 1 > k:
        continue

    x1 = max(0, i - k + 1)
    x2 = min(i, m - 1)
    y1 = max(0, row_max[i] - k + 1)
    y2 = min(m - 1, row_min[i])

    if x1 <= x2 and y1 <= y2:
        add(x1, y1, x2, y2)

for j in range(n):
    if col_max[j] == -1:
        continue
    if col_max[j] - col_min[j] + 1 > k:
        continue

    x1 = max(0, col_max[j] - k + 1)
    x2 = min(m - 1, col_min[j])
    y1 = max(0, j - k + 1)
    y2 = min(m - 1, j)

    if x1 <= x2 and y1 <= y2:
        add(x1, y1, x2, y2)

ans = 0
for i in range(m):
    cur = 0
    for j in range(m):
        cur += diff[i][j]
        diff[i][j] = cur
        if i > 0:
            diff[i][j] += diff[i - 1][j]
        ans = max(ans, diff[i][j])

print(ans + base)
```実装は、各行と列を最も黒い位置に圧縮することから始まります。 差分配列は、各行のすべての有効な配置を、可能な左上隅のスペース内の長方形としてエンコードします。 プレフィックスの蓄積中に、各セルは行ベースと列ベースの両方の制約からの寄与を蓄積します。 最後に、消しゴムの位置に関係なく、すでにきれいな線を追加します。 

境界クリッピングには注意が必要です。 有効な左上の座標は、縮小された座標を形成します。$(n-k+1) \times (n-k+1)$したがって、計算されたすべての間隔はこの範囲に固定される必要があります。 ここでの 1 つずつの間違いが、間違った答えを生み出す最も一般的な原因です。

 ## 特殊なケース

 黒のセルが幅より広く広がっている行$k$は、どの配置でも解決できないケースを示しています。 アルゴリズムは、長方形を生成する前に幅の条件をチェックすることでこれを処理し、無効な寄与が追加されないようにします。 

完全に白い行または列は、`base`これは、消しゴムの位置に依存しないことを意味します。 これにより、二重カウントが防止され、差分配列がその行に寄与していない場合でも正確さが保証されます。 

黒いセグメントが枠内に正確に収まる行$k \times k$ウィンドウは、配置スペースに単一の連続した長方形を作成します。 プレフィックスの合計は、その領域をカバーするすべての配置を正確にカウントし、グリッド上の最大値が他の行および列との最適なオーバーラップをキャプチャします。
