 ## 解決策
 ## 問題の理解

 Block Adventure には、高さの異なる列が並んでいます。 プレーヤーは最初の列から開始し、最後の列に到達する必要があります。 キャラクターはブロックをバッグに入れて運ぶことができ、現在の列からブロックを削除するか、バッグからその上にブロックを置くことで列の高さを変更できます。 次の列への移動は、高低差が所定の制限を超えない場合にのみ可能です。`k`。 目的は、プレーヤーがこれらのルールに従って最初の列から最後の列まで移動できるかどうかを判断することです。 

入力により、列の数、バッグ内のブロックの初期数、許容値が与えられます。`k`、および列の高さの配列。 プレーヤーが最後の列に到達できる場合、出力は「YES」、そうでない場合は「NO」です。 

制約が示すのは、`n`は最大 100 であり、単純なループで各列を処理するのに十分な大きさです。 バッグとカラムの高さは最大で$10^6$つまり、考えられるすべてのブロック転送をシミュレートすることはできません。 代わりに、先に進むにつれてバッグ内のブロックの数を動的に更新する貪欲なアプローチが必要です。 たとえば、不注意なアプローチでは、ブロックの可能な再配置をすべてシミュレートしようとするか、次のような場合に失敗する可能性があります。`k=0`または、プレーヤーがジャンプするのにちょうど十分なブロックを持っています。 

エッジケースは、列がすでに次の列よりも低い場合に発生しますが、バッグにはギャップを埋めるのに十分なブロックがありません。 たとえば、`h = [3, 7]`、`m = 3`、 そして`k = 0`、ギャップが許容値を超えているため、次の列に到達できません。バッグのすべてのブロックを使用すると、依然として赤字が残ります。 単純なチェック`|h_i - h_{i+1}| <= k`追加できるブロックを考慮せずに移動が不可能であると誤って示唆することになります。 

## アプローチ

 ブルートフォース手法では、各列でのブロックの追加または削除のあらゆる組み合わせをシミュレートし、バッグの中身を追跡します。 これは正しいですが、各列で複数のブロックを追加または削除できるため、組み合わせ的に爆発的になり、膨大な数の状態が作成されます。 と`n=100`そして`m`潜在的に最大$10^6$、操作の数は完全に非現実的になります。 

重要な点は、すべてのアクションをシミュレートする必要はないということです。 各ステップで重要なのは、次の列の高さを許容範囲内で満足できるかどうかだけです。`k`。 現在の列が必要以上に高い場合は、余分なブロックをバッグに取り除きます。 それより短い場合は、バッグのブロックを使用して最小許容高さに達します。 この貪欲なアプローチが機能するのは、バッグの容量が無制限であり、追加/削除操作の正確なシーケンスではなく、次の列に到達することのみを考慮しているためです。 

バッグ内のブロック数を動的に維持し、遷移ごとに次の列に到達できるかどうかを確認します。 これにより、問題は列全体の線形スキャンに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数的`n`| O(n + m) | 遅すぎる |
 | 貪欲 / 最適 | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。`n`、`m`、`k`、および列の高さの配列`h`。 
2. バッグ内のブロックの数を次のように初期化します。`m`。 
3. 最初の列から最後から 2 番目まで列をループします。 各列ごとに`i`、列に安全に残すことができる最大の高さを計算します。`i`列に移動します`i+1`可能です。 これは`max(0, h[i+1] - k)`。 
4. もし`h[i]`この最小必要高さ以上の場合は、余分なブロックをバッグに追加します。 過剰分は、`h[i] - min_required`。 
5. もし`h[i]`必要な最小高さに満たない場合は、バッグから必要なブロックの数を計算します。 バッグに必要なブロックよりも少ないブロックが含まれている場合、移動は不可能です。 ブレークして「NO」を返します。 それ以外の場合は、バッグから必要なブロックを減算します。 
6. すべての遷移を処理した後、ブロックが不足しなかった場合は、「YES」を出力します。 

機能する理由: 各ステップで、列の高さが次の移動の許容範囲内にあることを確認します。 ブロックを貪欲に使用または収集することにより、バッグには常に前の列から入手可能な余剰ブロックが正確に含まれるという不変条件が維持されます。 これにより、現在のバッグで列を満たすことができない場合は、さらに先に進むことができないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m, k = map(int, input().split())
    h = list(map(int, input().split()))
    bag = m
    possible = True
    for i in range(n - 1):
        min_required = max(0, h[i+1] - k)
        if h[i] >= min_required:
            bag += h[i] - min_required
        else:
            need = min_required - h[i]
            if bag < need:
                possible = False
                break
            bag -= need
    print("YES" if possible else "NO")
```このコードは貪欲な戦略に従っています。 前進するために必要な最低高さを計算し、それに応じてバッグを調整します。 の`max(0, h[i+1] - k)`負の高さを残さないようにします。 バッグが不足分をカバーできない場合、ループは直ちに停止し、不必要な計算を節約します。 

## 実用的な例

 **例 1**:

 入力:`3 0 1`そして高さ`4 3 5`。 

| 私 | h[i] | h[i+1] | min_required | バッグ | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 4 | 3 | 2 | 0 | 4 >= 2 → バッグ += 2 → バッグ = 2 |
 | 1 | 3 | 5 | 4 | 2 | 3 < 4 → 必要 = 1 → バッグ -= 1 → バッグ = 1 |

 ループが終了し、`bag >= 0`したがって、出力は「YES」になります。 

**例 2**:

 入力:`3 1 2`そして高さ`1 4 7`。 

| 私 | h[i] | h[i+1] | min_required | バッグ | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 4 | 2 | 1 | 1 < 2 → 必要 = 1 → バッグ = 0 |
 | 1 | 4 | 7 | 5 | 0 | 4 < 5 → 必要 = 1 → バッグ < 必要 → 不可能 |

 出力は「NO」です。 

これらのトレースは、アルゴリズムがバッグの不変性を維持し、到達可能性を正しく決定していることを示しています。

| スペース | O(n) | 各テスト ケースの列の高さの配列を保存します。 

与えられた`n ≤ 100`そして`t ≤ 1000`、合計操作は最大 100,000 であり、1 秒の制限内に十分収まります。 バッグと高さの計算は整数演算であるため、パフォーマンスのボトルネックは発生しません。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        h = list(map(int, input().split()))
        bag = m
        possible = True
        for i in range(n - 1):
            min_required = max(0, h[i+1] - k)
            if h[i] >= min_required:
                bag += h[i] - min_required
            else:
                need = min_required - h[i]
                if bag < need:
                    possible = False
                    break
                bag -= need
        output.append("YES" if possible else "NO")
    return "\n".join(output)
