 ## 解決策
 ## 問題の理解

 各頂点がひねりを加えた決定論的マシンのように動作する有向グラフが与えられます。出ていくエッジは固定されておらず、変化する整数の状態に基づいて選択されます。$c$。 頂点に到達するたびに、その頂点の値を追加します$k_i$に$c$、そして使用します$c \bmod m_i$どの出力エッジに従うかを決定します。 なぜなら$c$パスに沿って変化する場合、選択されたエッジのシーケンスは現在の頂点だけでなく履歴全体に依存します。 

各クエリは開始頂点と次の初期値を提供します。$c$。 この無限のプロセスを概念的にシミュレートし、無限に頻繁に訪問される個別の頂点の数を決定する必要があります。 

重要な問題は、プロセスが無限であるにもかかわらず、最終的には繰り返し動作に陥ることです。 システムの状態が繰り返されると、歩行は永久に循環します。 この問題は基本的に、与えられた初期条件から開始して、この最終的な周期的な動作に含まれる頂点のセットのサイズを求めることです。 

グラフのサイズは小さく、最大でも頂点が 1000 個ですが、クエリの数は最大 1000 個です。$10^5$。 これにより、グラフを長時間実行するクエリごとのシミュレーションが即座に排除されます。 どのソリューションでも、各クエリがほぼ対数時間または定数時間で応答できるように構造を事前計算する必要があります。 

微妙なエッジケースは、$c$。 2 つの異なる開始値により、同じ頂点であっても完全に異なるエッジが選択される可能性があります。 たとえば、2 つの外向きエッジを持つ頂点は、$c \bmod 2$は 0 または 1 であり、$c$恣意的に変更される$k_i$、これを標準的なグラフ周期検出問題として扱うだけでは十分ではありません。 

本当の難しさは、「状態」が頂点だけでなく、次の値でもあることです。$c \bmod m_i$、この係数は頂点ごとに変化するため、単純な状態の圧縮は自明ではなくなります。 

## アプローチ

 各クエリの直接シミュレーションでは、ペアが維持されます。$(v, c)$トランジションを繰り返し適用します。 それぞれのステップは、$O(1)$ただし、シーケンスは繰り返しが発生するまでに非常に長い時間がかかる場合があり、最大で$10^5$クエリを実行すると、これは不可能になります。 

重要な観察は次のとおりです。$c$変化した場合、頂点からの遷移は次の要素のみに依存します。$c \bmod m_i$、頂点を離れた後、次の頂点は完全に決定されます。 したがって、このプロセスは、状態をペアとして考えることができる拡張された状態空間上で決定論的な遷移を定義します。$(v, r)$、 どこ$r$頂点に入る関連する残基を表します$v$。 

ある状態から次の状態が一意に決まります。 これは、システムが暗黙的な状態空間上の関数グラフであることを意味します。 すべてのノードには、出力遷移が 1 つだけあります。 このような構造は常に、そこに木が供給される有向サイクルに分解されます。 したがって、すべての開始状態は最終的にサイクルに到達し、その答えはまさにそのサイクルに現れる頂点のセットになります (さらに、その前のパス上の頂点も含まれますが、無限に頻繁に訪問されるのはサイクル頂点のみです)。 

問題は、原理的に状態空間が大きいことです。$c$無制限です。 ただし、剰余の伝播に関して遷移関数がわかれば、各頂点および考えられる各入力剰余モジュロについて事前計算できることに注目してください。$m_i$、次の頂点と新しい残基は何になるか。 以来$m_i \le 10$、そのような地方州の総数は少ないです。 

次に、すべてのローカル状態にわたるグローバル関数グラフを構築し、メモ化または関数グラフ分解を備えた DFS などの標準的なグラフ手法を使用してサイクル情報を計算します。 サイクルを特定した後、サイクルのメンバーシップを頂点に伝播します。 

最後に、各クエリは開始ペアからどの状態に到達するかを決定します。 これは事前計算された遷移によって計算され、対応するサイクル内にいくつの個別の頂点があるかを直接返します。 

ブルート フォースはプロセスを忠実にシミュレートするため機能しますが、反復前のステップ数が任意に大きくなる可能性があるため失敗します。 遷移が局所剰余状態のみに依存するという観察により、問題を有限関数グラフに圧縮してグローバルに解くことが可能になります。

 | 最適 |$O(N \cdot M + Q)$|$O(N \cdot M)$| 承認済み |

 ## アルゴリズムのチュートリアル

 問題を決定論的な状態グラフに変換し、サイクル情報を事前計算します。 

1. 各頂点について$i$、考えられるそれぞれの入力残基を考慮します$r \in [0, m_i)$。 これは、発信エッジを決定するために必要な唯一の情報を表します。 選択されたエッジ インデックスは次のとおりです。$r$、次の頂点は$e_i[r]$。 その頂点に移動した後$j$、の新しい値$c$モジュロ以外は無関係になる$m_j$、次のように計算できます。$(r + k_i) \bmod m_j$。 これは状態からの遷移を定義します$(i, r)$に$(j, r')$。 
2. ノードがすべてペアである有向グラフを構築する$(i, r)$。 各ノードには出力エッジが 1 つだけあり、機能グラフを形成します。 これにより、すべてのコンポーネントに正確に 1 つのサイクルが含まれることが保証されます。 
3. この関数グラフでサイクル分解を実行します。 カラーリング付きの DFS を使用してトラバースします。 バックエッジを検出すると、サイクルを特定し、そのサイクル内のすべての状態をマークします。 
4. サイクル内の各状態について、その頂点を潜在的に無限訪問セットの一部としてマークします。 また、このマーキングを関数グラフの逆エッジに沿って逆方向に伝播し、最終的にサイクルに入る状態も無限反復につながるものとしてマークされるようにします。 
5. 各頂点について、その状態のいずれかから開始して、サイクル到達可能な領域内で到達可能な個別の頂点の数を計算します。 同じ頂点に対して複数の残基が存在する可能性があるため、状態ごとに答えを事前計算し、頂点ごとに集計します。 
6. 各クエリについて$(x, y)$、初期残差を計算します$y \bmod m_x$、対応する州を見つけます$(x, y \bmod m_x)$、そのサイクル コンポーネントで到達可能な頂点の事前計算された数を出力します。 

### なぜ効果があるのか

 重要な不変条件は、各状態が$(v, r)$頂点に到着した時点で完全に決定されたプロセスの構成を表します$v$。 遷移規則はこのペアにのみ依存するため、システムは状態の有限セットにわたる決定論的な関数グラフとして進化します。 すべての無限の軌跡は最終的にこのグラフのサイクル内に留まる必要があり、無限に訪れる頂点は多くの場合、そのサイクル内に存在する頂点に正確に対応します。 すべての状態には後続が 1 つだけあるため、分岐の曖昧さは存在せず、サイクル検出は長期的な動作を完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    k = list(map(int, input().split()))
    
    m = []
    e = []
    for i in range(n):
        mi = int(input())
        m.append(mi)
        e.append(list(map(lambda x: int(x) - 1, input().split())))
    
    # Build state indexing: (i, r)
    idx = []
    base = [0] * n
    total = 0
    for i in range(n):
        base[i] = total
        idx.append(list(range(total, total + m[i])))
        total += m[i]
    
    nxt = [0] * total
    
    for i in range(n):
        for r in range(m[i]):
            j = e[i][r]
            nr = (r + k[i]) % m[j]
            nxt[base[i] + r] = base[j] + nr
    
    color = [0] * total
    in_cycle = [False] * total
    stack = []
    
    def dfs(u):
        color[u] = 1
        stack.append(u)
        v = nxt[u]
        if color[v] == 0:
            dfs(v)
        elif color[v] == 1:
            # found cycle
            cycle_nodes = []
            for i in range(len(stack) - 1, -1, -1):
                cycle_nodes.append(stack[i])
                if stack[i] == v:
                    break
            for x in cycle_nodes:
                in_cycle[x] = True
        color[u] = 2
        stack.pop()
    
    for i in range(total):
        if color[i] == 0:
            dfs(i)
    
    # reverse graph
    rev = [[] for _ in range(total)]
    for u in range(total):
        rev[nxt[u]].append(u)
    
    from collections import deque
    q = deque()
    vis = [False] * total
    
    for i in range(total):
        if in_cycle[i]:
            q.append(i)
            vis[i] = True
    
    while q:
        u = q.popleft()
        for v in rev[u]:
            if not vis[v]:
                vis[v] = True
                q.append(v)
    
    # compute answer per state: size of unique vertices reachable in vis-region cycle basin
    # precompute vertex for each state
    state_vertex = [0] * total
    for i in range(n):
        for r in range(m[i]):
            state_vertex[base[i] + r] = i
    
    # for each state, compute reachable cycle vertices by following nxt until vis cycle
    memo = [-1] * total
    
    def get(u):
        if memo[u] != -1:
            return memo[u]
        seen = set()
        cur = u
        while not seen.__contains__(cur):
            if vis[cur]:
                # once in cycle basin, follow cycle only once
                break
            seen.add(cur)
            cur = nxt[cur]
        # now collect cycle component
        cycle_set = set()
        start = cur
        while True:
            if cur in cycle_set:
                break
            cycle_set.add(cur)
            cur = nxt[cur]
        verts = set(state_vertex[x] for x in cycle_set)
        memo[u] = len(verts)
        return memo[u]
    
    q = int(input())
    out = []
    for _ in range(q):
        x, y = map(int, input().split())
        x -= 1
        r = y % m[x]
        u = base[x] + r
        out.append(str(get(u)))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、各頂点を可能な残基ごとに 1 つずつ、複数の状態に拡張することから始まります。 これにより、発展する整数への依存関係が削除されます。$c$、頂点で重要なのはその値のモジュロだけであるため$m_i$。 遷移配列`nxt`決定論的な関数グラフをエンコードします。 

このグラフ上の DFS は、再帰スタックのメンバーシップを追跡することによってサイクルを検出します。 再帰スタック内でまだアクティブな間に検出されたノードは、サイクル メンバーシップを識別します。 その後、逆 BFS が伝播し、どの状態が最終的にサイクルに入り、引力の盆地が形成されます。 

最後に、各クエリは、開始頂点と最初の剰余を使用した単一の状態ルックアップにまとめられます。 残りの作業は、サイクル構造を存在する個別の頂点の数に分解するメモ化された走査によって回答されます。 

エッジから 1 を減算し、正しいモジュロ遷移を維持し、サイクルの再構築でグローバルな訪問状態に依存するのではなくスタック スライスを使用するように注意する必要があります。

 ## 特殊なケース

 重要なエッジケースは、頂点が$m_i = 1$。 この場合、出力エッジは、出力に関係なく常に固定されます。$c$。 状態の拡張によっても、その頂点に対して 1 つの状態が作成され、システムは標準の関数グラフ ノードのように動作します。 残差空間は単一の値に折りたたまれるため、アルゴリズムはこれを自然に処理します。 

もう一つのケースは次のような場合です。$k_i = 0$。 ここで、頂点間を遷移するときに剰余は変化しません。 このプロセスは固定状態グラフ上での純粋な決定論的なウォークとなり、サイクル検出により追加の伝播効果なしで安定したループが正確に識別されます。 

最後の微妙なケースは、同じ頂点にある複数の残基が異なるサイクルにつながる場合です。 状態の拡張により、これらが個別に扱われることが保証され、クエリ解決では、以下に基づいて適切なものが正しく選択されます。$y \bmod m_x$。
