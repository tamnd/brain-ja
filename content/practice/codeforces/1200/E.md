 ## 解決策
 ## 問題の理解

 文を構成する一連の単語が与えられており、そのタスクはそれらを左から右に結合して単一の文字列に圧縮することです。 結合ルールは、現在の文字列に単語を追加するときに、現在の文字列の接尾辞と一致する新しい単語の接頭辞がすべて削除されるというものです。 目標は、すべての単語を処理した後に最終的な圧縮文字列を生成することです。 

入力は整数で構成されます`n`単語の数の後に単語自体が続きます。 すべての単語を組み合わせた合計の長さは、最大 100 万文字になります。 これは、O(total_length) など、文字の合計の長さに比例して機能するアルゴリズムは実行可能ですが、2 次の長さ (O(total_length²)) は遅すぎることを意味します。 これにより、長い文字列にわたってサフィックスとプレフィックスを 1 文字ずつ繰り返し比較する単純なアプローチが除外されます。 

エッジ ケースには、1 つの単語が完全に次の単語の接頭辞である場合や、2 つの単語が重複するセクションを共有する状況が含まれます。 たとえば、結合する`"abc"`そして`"bcd"`生産すべき`"abcd"`。 最も長く重複する接尾辞と接頭辞を計算せずに常に追加する単純な実装では、次のような結果が得られます。`"abcbcd"`、これは間違いです。 もう 1 つの微妙なケースは、単語が前の文字列と同一である場合です。この場合、重複部分は 2 番目の単語全体に等しく、何も追加する必要はありません。 

## アプローチ

 ブルート フォース ソリューションでは、各単語を反復処理し、新しい単語ごとに、現在の文字列のすべての可能な接尾辞をチェックして、新しい単語の接頭辞と一致するかどうかを確認します。 これには、最大 O(L²) 回の比較が必要です。ここで、L は、これまでに蓄積された文字列の長さです。 最大 10^6 文字の場合、最悪の場合、およそ 10^12 の演算が必要となり、明らかに遅すぎます。 

これを高速化するための重要な洞察は、これを Knuth-Morris-Pratt (KMP) アルゴリズムを使用して解決できる古典的な文字列の重複問題として認識することです。 サフィックスとプレフィックスを手動で比較する代わりに、新しい単語、区切り記号、および蓄積された文字列の最後の部分を連結して一時的な文字列を構築し、プレフィックス関数 (KMP 失敗配列) を計算できます。 プレフィックス関数の最後の値は、最大オーバーラップの長さを示します。 新しい単語の重複しない接尾辞のみを追加することで、単語を効率的に結合できます。 これにより、プレフィックス関数の計算で各文字が一定の回数処理されるため、合計作業量が O(total_length) に減ります。 

すべてのサフィックスとプレフィックスの組み合わせを常にチェックできるため、ブルート フォースは機能しますが、二次時間のために失敗するという話です。 KMP を使用してオーバーラップを効率的に計算できることを確認すると、問題は線形時間文字列操作タスクに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(合計長さ²) | O(全長) | 遅すぎる |
 | KMP ベースの最適 | O(全長) | O(全長) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`compressed`最初の単語として、これが開始文字列になります。 
2. 文内の後続の各単語を繰り返します。 
3. 現在の単語について、現在の単語との最大重複を計算します。`compressed`弦。 現在の単語と一意の区切り文字を連結します (例:`#`）、そして最後に`len(word)`の登場人物`compressed`。 
4. この連結文字列のプレフィックス関数を構築します。 接頭辞関数配列の最後の値は、接尾辞に一致する現在の単語の最長接頭辞の長さを示します。`compressed`。 
5. に追加`compressed`現在の単語の重複しない部分のみ。 
6. すべての単語が処理されるまで続行します。 
7. 最終出力`compressed`弦。 

このアルゴリズムが機能するのは、各ステップで現在の文字列と次の単語の間の最大の重複が明示的に計算されるためです。 KMP 接頭辞関数は、長い重複を決して見逃さないことを保証するため、「圧縮された単語には常に、最大の重複で正しくマージされたすべての単語が含まれる」という不変条件が全体にわたって保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def compute_prefix_function(s):
    n = len(s)
    pi = [0] * n
    for i in range(1, n):
        j = pi[i - 1]
        while j > 0 and s[i] != s[j]:
            j = pi[j - 1]
        if s[i] == s[j]:
            j += 1
        pi[i] = j
    return pi

def main():
    n = int(input())
    words = input().strip().split()
    
    compressed = words[0]
    
    for word in words[1:]:
        # only need last len(word) chars for overlap check
        overlap_check = word + "#" + compressed[-len(word):] if len(compressed) >= len(word) else word + "#" + compressed
        pi = compute_prefix_function(overlap_check)
        overlap_len = pi[-1]
        compressed += word[overlap_len:]
    
    print(compressed)

if __name__ == "__main__":
    main()
```この解決策は、入力を読み取り、圧縮文字列を最初の単語で初期化することから始まります。 後続の各単語に対して、接頭辞関数の計算に使用される文字列が構築されます。 接頭辞配列の最後の値によって、既存の圧縮文字列の接尾辞と一致する新しい単語の接頭辞の長さが決まります。 重複しない部分のみを追加すると、正しいマージが保証されます。 最後のものだけを使用する`len(word)`の登場人物`compressed`不必要な作業を回避し、アルゴリズムを線形に保ちます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(全長) | 各文字は最大 2 回処理されます。1 回は接頭辞の計算で、もう 1 回は追加で処理されます。 
| スペース | O(全長) | 各単語連結の接頭辞関数配列は、単語の長さに比例したスペースを使用します。 

単語の合計の長さが 10^6 以下であるとすると、これは 1 秒および 256 MB 以内に収まります。

 ## 特殊なケース

 入力用`"abc bc c"`、アルゴリズムは最初にマージします`"abc"`と`"bc"`。 最後の 2 文字`"bc"`と重なる`"bc"`, したがって、何も追加されません。 次、`"c"`の最後の文字と完全に重複します`"abc"`, したがって、やはり何も追加されません。 最後の文字列が残る`"abc"`、それは正しいです。 プレフィックス関数は、新しい単語全体にまたがる場合でも、最大の重複を正確に識別します。 入力用`"aaaa aaa"`、重複部分は 3 文字であり、圧縮文字列は次のようになります。`"aaaa"`。 これらのエッジ ケースは、アルゴリズムが冗長な文字を追加することなく、完全なオーバーラップと部分的なオーバーラップを正しく処理することを示しています。
