 ## 解決策
 ## 問題の理解

 私たちは 8 × 8 のボードで簡略化されたチェスのエンドゲームをプレイしています。 私たちはキングとルークをコントロールしますが、相手はキングのみをコントロールします。 問題は、相手の次のターンに相手のキングがこちらのルークを合法的に占領できるように、合法的な手を 1 つだけ実行できるかどうかです。 言い換えれば、こちらの移動後、ルークは敵のキングが合法的に占領しているマス目に置かれなければなりません。 

入力にはいくつかの独立した位置が含まれています。 各位置は、私たちのキング、私たちのルーク、そして相手のキングの正方形を与えます。 すべてのポジションについて、そのような 1 手犠牲が可能かどうかを出力します。 ボード サイズは固定されているため、入力サイズはテスト ケースの数にのみ影響します。 最大 10,000 のテスト ケースという制限は、ソリューションが数十万の単純な操作を簡単に処理できることを意味しますが、考えられるすべてのゲームや多くの動きシーケンスを調査する検索は不要です。 

基板が小さいことが主な制約です。 正方形は 64 個しかないので、複雑な数学的特徴付けは必要ありません。 チェスのルールを直接モデル化し、考えられるすべての初手をチェックできます。 テスト ケースごとに一定の作業量があれば十分です。 

厄介なケースは、動きだけではなく、チェスの合法性によって引き起こされます。 敵の王はルークに到達できるように見えますが、こちらの王がそのマスを守っているため、攻略が失敗する可能性があります。 例えば：```
1
d2 e6 f1
```答えは`NO`。 ルークは敵のキングに隣接する e2 または e1 に移動できますが、こちらのキングが目的のマスを攻撃するため、敵のキングはそこをキャプチャできません。 キングとルークの間の距離だけをチェックする不用意な解決策は、誤った答えを返します。`YES`。 

もう 1 つのケースは、自分のキングがルークをブロックした場合です。 例えば：```
1
d4 b4 f4
```答えは`NO`。 ルークはこちらのキングを通り抜けることができないため、たとえ敵のキングがルークの列の近くにいたとしても、合法的なルークの動きは犠牲を生み出すことはできません。 

最後のエッジケースは、ルークの代わりにキングを動かすことによって犠牲を払うことです。 例えば：```
1
f2 g2 h1
```答えは`YES`。 ルークは動かない。 代わりに、キングは f3 に移動し、ルークをキャプチャ可能にします。 ルークの動きをチェックするだけではこの可能性を見逃してしまいます。 

## アプローチ

 簡単なアプローチは、できる限りあらゆる法的手段を講じることです。 考えられるキングの動きとルークの動きごとに、結果の局面をシミュレートします。 相手のキングがその位置でルークを捕捉できる場合は、それを受け入れます。 

チェス盤は決して成長しないので、この総当たりはすでに速いです。 キングの宛先マスは最大 64 個、ルークの宛先マスは最大 64 個あります。 各候補について、攻撃と占有されたマスについての一定時間のチェックを数回行うだけで済みます。 最悪のケースは、128 の候補手数のおよそ 10000 倍であり、これはごくわずかです。 

より複雑なアプローチでは、ピースの相対位置に関する式を導き出そうとします。 それはうまくいきますが、キングがルークをブロックしたり、マスが守られているために敵のキングがキャプチャを拒否したりするなどの特別なルールを見逃しがちです。 ボード サイズが固定されているため、シミュレーションがよりクリーンなソリューションになります。 

すべての合法的な最初の動きが表現され、チェックされるため、ブルートフォースが機能します。 すべての正方形を列挙することが一定ではなくなるため、より大きなボードでは失敗します。 ここで、状態空間が固定されているという観察により、難しいチェスの推論を完全な検証に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(T * 64 * 64) | お(1) | 承認済み |
 | 最適 | 固定基板サイズによって隠蔽された大きな定数を持つ O(T) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての正方形を文字と数字からゼロベースの座標に変換します。 すべてを整数のペアとして保持すると、動きのチェックが容易になります。 
2. 私たちの王のためにあらゆる手を講じます。 キングの移動は、目的地がボード内にあり、こちらのルークが含まれておらず、キングが敵のキングまたはルークによって攻撃されたマスに移動しない場合にのみ有効です。 
3. ルークに対して可能なすべての手を生成します。 ルークは、ボードの端または別の駒に到達するまで、水平または垂直に移動できます。 私たちの王も敵の王も飛び越えることはできません。 
4. 各候補が移動した後、相手のキングがルークを合法的にキャプチャできるかどうかを確認します。 敵のキングはルークに隣接していなければならず、移動先のマスはこちらのキングによって保護されてはならず、移動後にこちらのルークによって保護されてはなりません。 
5. いずれかの候補手がキャプチャ チェックに合格した場合、出力`YES`。 すべての動きが失敗した場合、出力`NO`。 

これが機能する理由は、考えられるすべての最初の動きが検査されるためです。 犠牲は、少なくとも 1 つの合法的な動きが存在し、その後相手のキングが合法的なキャプチャを獲得した場合にのみ可能です。 列挙はすべての正当な手をカバーしているため、チェックされたすべての手を失敗することは、犠牲が存在しないことを証明します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def inside(x, y):
    return 0 <= x < 8 and 0 <= y < 8

def king_attack(a, b):
    return max(abs(a[0] - b[0]), abs(a[1] - b[1])) == 1

def rook_attack(r, target, king):
    if r[0] == target[0]:
        step = 1 if target[1] > r[1] else -1
        y = r[1] + step
        while y != target[1]:
            if (r[0], y) == king:
                return False
            y += step
        return True
    if r[1] == target[1]:
        step = 1 if target[0] > r[0] else -1
        x = r[0] + step
        while x != target[0]:
            if (x, r[1]) == king:
                return False
            x += step
        return True
    return False

def can_capture(k, r, enemy):
    if not king_attack(enemy, r):
        return False
    if king_attack(k, r):
        return False
    if rook_attack(r, enemy, k):
        return False
    return True

def legal_king_moves(k, r, enemy):
    res = []
    for dx in (-1, 0, 1):
        for dy in (-1, 0, 1):
            if dx == 0 and dy == 0:
                continue
            nx, ny = k[0] + dx, k[1] + dy
            if not inside(nx, ny):
                continue
            if (nx, ny) == r:
                continue
            nk = (nx, ny)
            if king_attack(enemy, nk):
                continue
            if rook_attack(r, nk, nk):
                continue
            res.append(nk)
    return res

def legal_rook_moves(k, r, enemy):
    res = []
    for dx, dy in ((1, 0), (-1, 0), (0, 1), (0, -1)):
        x, y = r
        while True:
            x += dx
            y += dy
            if not inside(x, y):
                break
            if (x, y) == k:
                break
            if (x, y) == enemy:
                break
            res.append((x, y))
    return res

def solve_case(k, r, e):
    for nk in legal_king_moves(k, r, e):
        if can_capture(nk, r, e):
            return True
    for nr in legal_rook_moves(k, r, e):
        if can_capture(k, nr, e):
            return True
    return False

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        a, b, c = input().split()

        def conv(s):
            return (ord(s[0]) - ord('a'), int(s[1]) - 1)

        k = conv(a)
        r = conv(b)
        e = conv(c)

        ans.append("YES" if solve_case(k, r, e) else "NO")

    print("\n".join(ans))

if __name__ == "__main__":
    main()
```ヘルパー関数はチェスのルールを分離します。`king_attack`隣接関係を処理します。これが王が正方形を制御する唯一の方法です。`rook_attack`2 つの四角形が行または列を共有しているかどうかをチェックし、ルークのラインがブロックされていないことを確認します。 

捕獲チェックは手の生成から分離されています。 これにより、敵のキングがルークに近いという理由だけで手が成功したとみなされる一般的なバグが防止されます。 敵のキングもルークの角に立つことを許可されなければなりません。 

2 つの移動ジェネレーターは、キングを移動するかルークを移動するという唯一の選択肢をカバーします。 ルークのスキャンは、ブロッキング ルールを処理する別の駒に到達すると停止します。 座標は 0 ～ 7 であるため、オーバーフローや大量の入力の心配はありません。 

## 実用的な例

 最初のサンプル位置の場合:```
c5 e2 f4
```変換された座標は重要です`(2,4)`、ルーク`(4,1)`、 敵`(5,3)`。 

| ステップ | キング | ルーク | アクション | 敵は捕らえられるのか？ |
 | --- | --- | --- | --- | --- |
 | 開始 | (2,4) | (4,1) | チェックムーブ | いいえ |
 | rook を e4 に試してみる | (2,4) | (4,4) | ルークが動きました | はい |

 ルークを動かすと、ルークが敵のキングの隣に配置されます。 敵の王は私たちの王の攻撃に進入していないので、犠牲は機能します。 

3 番目のサンプル位置の場合:```
f2 g2 h1
```国家は王様だ`(5,1)`、ルーク`(6,1)`、 敵`(7,0)`。 

| ステップ | キング | ルーク | アクション | 敵は捕らえられるのか？ |
 | --- | --- | --- | --- | --- |
 | 開始 | (5,1) | (6,1) | ルークは犠牲にできません | いいえ |
 | キングを f3 に移動 | (5,2) | (6,1) | キングは引っ越した | はい |

 このトレースは、ルークの手だけをチェックすることが不完全である理由を示しています。 ルークはすでに適切な位置にあり、キングの動きによって保護の状況が変わります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

| スペース | お(1) | 少数の座標と一時的な移動リストのみが保存されます。 

基板サイズは固定されているため、定数係数は小さくなります。 テスト ケースが 10,000 件であっても、操作数は一般的なコンテストの制限をはるかに下回ります。

import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    
    def inside(x, y):
        return 0 <= x < 8 and 0 <= y < 8

    def king_attack(a, b):
        return max(abs(a[0] - b[0]), abs(a[1] - b[1])) == 1

    def rook_attack(r, target, king):
        if r[0] == target[0]:
            step = 1 if target[1] > r[1] else -1
            y = r[1] + step
            while y != target[1]:
                if (r[0], y) == king:
                    return False
                y += step
            return True
        if r[1] == target[1]:
            step = 1 if target[0] > r[0] else -1
            x = r[0] + step
            while x != target[0]:
                if (x, r[1]) == king:
                    return False
                x += step
            return True
        return False

    def can_capture(k, r, e):
        return king_attack(e, r) and not king_attack(k, r) and not rook_attack(r, e, k)

    def solve(k, r, e):
        for dx in (-1, 0, 1):
            for dy in (-1, 0, 1):
                if (dx, dy) != (0, 0):
                    nk = (k[0] + dx, k[1] + dy)
                    if inside(*nk) and nk != r and not king_attack(e, nk) and not rook_attack(r, nk, nk):
                        if can_capture(nk, r, e):
                            return "YES"
        for dx, dy in ((1,0),(-1,0),(0,1),(0,-1)):
            x, y = r
            while True:
                x += dx
                y += dy
                if not inside(x, y) or (x, y) == k or (x, y) == e:
                    break
                if can_capture(k, (x, y), e):
                    return "YES"
        return "NO"

    t = int(input())
    out = []
    for _ in range(t):
        a, b, c = input().split()
        f = lambda s: (ord(s[0])-97, int(s[1])-1)
        out.append(solve(f(a), f(b), f(c)))
    sys.stdin = old
    return "\n".join(out)

 ## 特殊なケース

 保護されたルークの場合:```
1
d2 e6 f1
```アルゴリズムは、ルークを敵のキングの近くに配置する動きを試みます。 キャプチャを確認すると、目的地の広場が私たちの王によって管理されていることがわかります。 敵の王はチェックに移ることができないため、すべての犠牲は失敗し、答えは次のとおりです。`NO`。 

ブロックされたルークの場合:```
1
d4 b4 f4
```ルーク移動ジェネレーターはルークから外側に向かってスキャンします。 d4 でキングに到達するとスキャンが停止するため、キングを通過する不正な移動は発生しません。 アルゴリズムでは、ルークが実際に実行できない手を考慮することはありません。 

キングの移動の場合:```
1
f2 g2 h1
```ルークはすでに敵のキングに隣接していますが、現在のキングの位置ではキャプチャできません。 キングを動かすと攻撃されるマスが変化し、ルークが捕獲可能になるため、アルゴリズムは有効な手を見つけてリターンします。`YES`。
