 ## 解決策
 ## 問題の理解

 この問題は、次のサイクルとして配置された動物園について説明します。`n`場所。 訪問者が開始場所を選択します`a`、終了場所`b`、およびサイクル上のそれらの間の 2 つの可能なパスのうちの 1 つ。 選択したパスは長くても十分に短くなければなりません`k`エッジ。 次に訪問者は、 に始まり、 に終わる散歩を実行します。`a`、選択したパスから離れることはなく、選択したパス上のすべての場所を訪問し、全長は最大でも`m`。 タスクは、可能なすべての歩行をモジュロでカウントすることです`10^9+7`。 

重要なのは、選択したパスがどのようなものかを理解することです。 方向が決まると、サイクル セグメントは直線になります。 セグメントに長さがある場合`d`、ポジションが含まれています`0, 1, ..., d`、どこの位置`0`が開始位置です。 散歩は次から始まります`0`、で終了する必要があります`0`、位置に到達する必要があります`d`少なくとも一度は。 

この制限により、ソリューションは動的プログラミングに向けて推進されます。 パスの長さ`k`と同じ大きさにすることができます`100000`、しかし歩く距離`m`だけです`2000`。 遠くまで届く散歩`d`そして、少なくとも必要な最初の状態に戻ります`2d`動くので、`d <= 1000`重要になる可能性があります。 これは、サイクル サイズではなく歩行長に基づいて状態空間を確保できることを意味します。 

いくつかの特殊なケースは見落とされがちです。 歩行距離が短すぎて遠方の終点に到達できない場合は、カウントしないでください。 たとえば、次の入力を使用します。```
10 5 1
```答えは次のとおりです。```
0
```選択された有効なセグメントには少なくとも長さがあるため、`1`ただし、反対側の端に到達して戻ってくるには、少なくとも 2 つの移動が必要です。 

別のケースは、長さがちょうど 1 のパスです。 のために：```
4 3 2
```選択したエッジ上の有効なウォークは`0 -> 1 -> 0`。 すべての出発点から 2 つの方向が考えられます。そのため、答えは次のとおりです。`4 * 2 = 8`。 パスのみをカウントし、選択された方向を無視するソリューションでは、正解の半分が返されます。 

3 番目によくある間違いは、ファーサイドに到達したが戻らない四球をカウントすることです。 のために：```
5 5 1
```シーケンス`0 -> 1`は、開始した場所で終了しないため無効です。 終了条件はウォーク定義の一部です。 

## アプローチ

 直接的な総当たりアプローチでは、考えられるすべての開始位置、考えられるすべての方向、考えられるすべてのパスの長さを試し、そのパス上のすべての歩行を列挙します。 これは定義に正確に従っているため、正しいです。 ただし、可能な歩行数は指数関数的に増加します。 長さ`m`walk には各ステップで最大 2 つの選択肢があるため、検索スペースはおよそ`O(2^m)`、次の場合は不可能です`m = 2000`。 

問題の構造により、数え方がはるかに適切になります。 サイクル自体は乗算係数に寄与するだけです。1 つの固定線分上の歩行数を数えた後、その線分がどこから始まるか、時計回りか反時計回りかを選択できます。 

残りのタスクはライン上の四球を数える事です。 開始エンドポイントからの現在の距離を知る必要があるだけです。 後`i`位置にあれば移動します`j`、次の動きのいずれかが増加します`j`または減少します`j`。 ゼロを下回ったり、最大許容距離を超えたりすることはできません。 遠方のエンドポイントに到達したかどうかのみを考慮しているため、代わりに、考えられるすべての最大距離について歩行を計算し、ゼロに戻る歩行を追加できます。 

有益な観察は、歩く距離が長いということです。`i`位置で終わる`j`以前の長さから計算できます。 遷移は隣接する位置にのみ依存するため、単純な動的計画表で十分です。 までのあらゆる長さの状態を構築します。`m`、現在の距離を維持します。 上記のポジション`k`選択したセグメントは次の値を超えることはできないため、これらは不要です。`k`。 

これらの値を計算した後、有効な歩行の数は、歩行が位置に戻るすべての長さの合計になります。`0`正の最大距離を持ちます。 DP 状態は、すべての位置が必要なエンドポイントにすでに到達しているウォークとして解釈できます。`j`は、選択したセグメントのエンドポイントを表します。 最終的なカウントは次のように乗算されます。`2n`2つの方向と`n`可能な開始場所。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m) | O(m) | 遅すぎる |
 | 最適 | O(m * min(k, m)) | O(m * min(k, m)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 動的プログラミング テーブルを作成します。`dp[i][j]`長い距離を歩く方法の数を表します`i`そして遠距離でフィニッシュ`j`スタート地点から。 距離の上限は`k`それより長いパスは選択できないためです。 
2. Initialize`dp[0][0] = 1`。 行動を起こす前に、ウォーカーがスタート地点にいます。 
3. 歩行距離ごとに、`1`に`m`、可能な各距離を更新します。 遠くに到着するには`j`、前の位置は次のとおりである必要があります`j - 1`または`j + 1`。 これらは、前の動きの 2 つの可能な方向に対応します。 
4. 姿勢を保つ`0`有効な遷移に限定されます。 最初から左に移動することは不可能なので、状態がマイナスになることはありません。 
5. すべての状態を合計する`dp[i][0]`のために`i >= 1`。 これらは、正の回数移動した後に開始位置に戻るウォークです。 
6. 結果を乗算します。`2n`。 がある`n`開始位置の選択肢と、選択したパスの方向の 2 つの選択肢。 

DP の背後にある不変条件は次のとおりです。`dp[i][j]`長さのウォークのすべての有効なプレフィックスを正確にカウントします`i`位置で終わる`j`。 次に考えられるすべての手が一度考慮され、パスの外にある無効な手が追加されることはありません。 状態が位置に達したとき`0`、復帰条件を満たす完全な歩行を記述します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k, m = map(int, input().split())

    limit = min(k, m)
    dp = [[0] * (limit + 2) for _ in range(m + 1)]
    dp[0][0] = 1

    for length in range(1, m + 1):
        for pos in range(limit + 1):
            if pos > 0:
                dp[length][pos] += dp[length - 1][pos - 1]
            if pos < limit:
                dp[length][pos] += dp[length - 1][pos + 1]
            dp[length][pos] %= MOD

    ans = 0
    for length in range(1, m + 1):
        ans += dp[length][0]
        ans %= MOD

    ans = ans * (2 * n) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```テーブルのサイズは以下に基づいています`min(k, m)`それよりも`k`直接。 たとえ`k`巨大なため、これ以上の距離を歩くことはできません`m`、したがって、これらの州は決して貢献しません。 

トランジションでは、両方の隣接する位置をチェックします。 最初の条件は開始点から左に移動することを防ぎ、2 番目の条件は選択したセグメントの長さを超えて移動することを防ぎます。 配列内で追加の列を使用すると、`pos + 1`特別な処理をしなくても安全にアクセスできます。 

サイクルのジオメトリは動きのカウントとは独立しているため、最後の乗算は DP の後に行われます。 DP は 1 つのエンドポイントから始まる 1 つの指向性セグメントをカウントし、サイクルはそのセグメントが配置される場所のみを選択します。 

## 実用的な例

 各方向に対して 1 つの線分ウォークのみが可能です。 乗算`2 * 4`与える:

 | 値 | 結果 |
 | --- | --- |
 |`1 * 8`|`8`|

```DP は以下を生成します。 

| 長さ | ポジション 0 四球 |
 | --- | --- |
 | 1 | 0 |
 | 2 | 1 |
 | 3 | 0 |
 | 4 | 3 |
 | 5 | 0 |
 | 6 | 10 |

```重要な部分は、DP では遠方のエンドポイントに到達した後に開始位置に戻る歩行のみがカウントされるため、より短い振動は除外されるということです。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m * min(k, m)) | 各長さは、到達可能なすべての位置を考慮しています。 |
 | スペース | O(m * min(k, m)) | DP にはすべての長さと位置が保存されます。 |

 ## 特殊なケース

 最大ウォーク長が小さすぎる場合、DP は当然、返されるすべての状態をゼロのままにしておきます。 で`2 1 1`、可能な移動は一方の側からもう一方の側へのみですが、ウォーカーは戻ることができないため、答えはゼロのままです。 

選択したパスの長さが 1 の場合、唯一の有効なウォークはエッジを横切ってすぐに戻ることになります。 DP はポジションのシーケンスをカウントします。`0 -> 1 -> 0`帰りの散歩として。 最後の乗算は、サイクル全体でのこのエッジの可能な配置を処理します。 

いつ`k`よりもはるかに大きいです`m`までの距離のみ`m`案件。 より長い長さのパス`m / 2`に到達したり返されたりすることは決してないので、無視された状態は答えに影響を与えることはできません。 これが、DP 次元を制限することが安全である理由です。
