 ## 解決策
 ## 問題の理解

 私たちには無限のグリッド上の家のセットが与えられています。 ある位置に設置された塔`(r, c)`西側にない、その価値のあるすべての家にサービスを提供できます`row + column`塔よりも大きくない`row + column`。 タワーの建設コストはその列数です。 

重要なのは、家に対する見方を変えることです。 家の場合`(r, c)`、間隔を定義します。```
[c, r + c]
```この家を覆う塔は、以下の左側の境界を選択する必要があります。`c`およびそれ以上の右境界`r + c`。 そのタワーのコストは、選択したカバー間隔の長さと正確に一致します。 したがって、家の集合をカバーすることは、それらの間隔を 1 つの大きな間隔でカバーすることと同じです。 そのコストは、最大の右エンドポイントから最小の左エンドポイントを引いたものです。 

タスクは、最大で次の値を使用して最小の総コストを要求します。`i`あらゆる人のための塔`i`から`1`に`n`。 

到達できる家の数`200000`したがって、家のすべてのサブセットを試したり、すべての家とすべての可能なタワー数に対して動的プログラミング テーブルを構築したりするアプローチは遅すぎます。 数秒程度の制限があるため、`O(n log n)`または解決策を閉じます。 座標は次のように大きくできます。`10^9`したがって、アルゴリズムはグリッド サイズに依存できません。 

明らかではないケースは、重複する間隔から発生します。 単純な解決策では、タワーを追加するたびに常に役立つと考えるかもしれませんが、重複する間隔を分割してもコストは削減されません。 例えば：```
1
5 10
```間隔は`[10, 15]`、したがって、タワー1つのコストがかかります`5`答えは次のとおりです。```
5
```一戸建て住宅を、コストが等しいタワーが必要であるとみなす不用意な実装`r + c`出力するだろう`15`、タワーの斜めの位置とコストを混同します。 

もう 1 つの重要なケースは、2 つの住宅の補償範囲間隔が交差している場合です。```
2
3 5
2 6
```間隔は`[5, 8]`そして`[6, 8]`。 1 つのタワーで両方のコストをカバーできる`3`、2 つのタワーには依然として最小コストがかかります`5 + 4 = 9`別々の塔を強制的に設置する場合に限ります。 せいぜい許されてるので`i`塔の場合、答えは次のとおりです。```
3 3
```すべての家に新しいタワーを貪欲に作成する間違ったアプローチは、重なり合う間隔が一緒に維持されるべきであるという事実を見落とすことになります。 

最後のエッジケースは、間隔が完全に分離されている場合です。```
2
1 1
8 8
```間隔は`[1,2]`そして`[8,16]`。 1 つのタワーにかかる費用`15`、タワーが 2 つあると費用がかかりますが、`1 + 8 = 9`。 アルゴリズムは、ギャップでの分割が有益であることを認識する必要があります。 

## アプローチ

 直接的なアプローチは、可能な限り家をタワーにグループ化してみることです。 各グループについて、変換された最小値と最大値を見つけて、タワーのコストを計算します。 これは正しいです。1 つのタワーは、そのタワーがカバーする家屋の中で最小の柱と最大の対角値によって完全に決定されるからです。 ただし、可能なパーティションの数は指数関数的であるため、使用できません。 

より現実的な強引なアイデアは、間隔をソートし、動的プログラミングを使用することです。`dp[k]`を使用して最良のコストを保存します`k`最初のいくつかの間隔内のグループ。 これには依然として、以前の多くの分割点を考慮する必要があります。 と`n = 200000`、最適化されたものであっても`O(n^2)`バージョンでは約 400 億の操作が必要になります。 

重要な観察は、家を間隔に変換した後、問題は間隔をセグメントで覆うことになるということです。 間隔ごとに 1 つのセグメントから始める場合、総コストは個々の間隔の長さの合計になります。 2 つの隣接するグループをマージするときは常に、それらの間のギャップから追加コストが発生するだけです。 間隔が重なっている場合、マージにはコストはかかりません。 サイズに隙間がある場合`g`、マージするとコストがちょうど増加します`g`。 

すべてのマージ コストは独立しているため、タワーの数を減らす最善の方法は、最初に最大のギャップを削除することです。 から始まる`n`グループの場合、ギャップを越えてマージするたびにタワーの数が 1 つ減り、そのギャップの分だけコストが増加します。 したがって、有用なギャップをすべて分類することで答えを構築できます。 

プロセスは次のとおりです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | ソートされたギャップとの間隔のマージ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての家を改造する`(r, c)`間に入って`[c, r + c]`。 これが機能するのは、塔の間隔に家の間隔の終点が含まれているときに、塔が家を正確に覆うからです。 
2. すべての間隔を左のエンドポイントで並べ替えます。 並べ替え後は、重複する可能性のあるすべての間隔が隣り合って表示されるため、隣接する間隔を検査するだけで済みます。 
3. 左から右にスキャンしながら間隔をマージします。 現在の結合間隔を維持します。 現在の間隔が終了する前に次の間隔が開始する場合、2 つの間隔は同じ接続コンポーネントに属し、追加のタワーは必要ありません。 そうしないと、それらの間にギャップが生じ、そこで分割することで正確にそのギャップを節約できます。 
4. すべての接続コンポーネントが個別にカバーされる場合の総コストを計算します。 これは、タワーの最大数で考えられる最良のコストです。 
5. 連続するコンポーネント間のすべてのギャップを保存します。 各ギャップは、2 つのコンポーネントを 1 つのタワーに押し込むときに支払われる追加コストを表します。 
6. ギャップを降順に並べ替えます。 タワーの数を減らすには`n`まで`1`、残っている最大のギャップを繰り返しマージします。 各結合後のランニングコストから、対応するタワー数の答えが得られます。 

機能する理由: 接続されたコンポーネント内の間隔はチェーンを通じて重なり合うため、1 つのセグメントがコンポーネントを覆うことは避けられません。 唯一の選択肢は、異なるコンポーネントを結合するかどうかです。 2 つのコンポーネントを結合すると、それらの間の距離が正確に追加され、異なるギャップは相互に影響しません。 最初に削除する最大のギャップを選択すると、可能なマージの数が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    intervals = []

    for _ in range(n):
        r, c = map(int, input().split())
        intervals.append((c, r + c))

    intervals.sort()

    base = 0
    gaps = []

    left, right = intervals[0]

    for l, r in intervals[1:]:
        if l <= right:
            if r > right:
                right = r
        else:
            base += right - left
            gaps.append(l - right)
            left, right = l, r

    base += right - left

    gaps.sort(reverse=True)

    ans = [0] * n
    cur = base

    components = len(gaps) + 1
    ans[components - 1] = cur

    for gap in gaps:
        cur += gap
        components -= 1
        ans[components - 1] = cur

    for i in range(1, n):
        if ans[i] == 0:
            ans[i] = ans[i - 1]

    print(*ans)

if __name__ == "__main__":
    solve()
```コードはまず、変換された間隔を作成します。 適切なエンドポイントは以下を使用します`r + c`、一方、左側のエンドポイントは単純に`c`。 

ソート後、スキャンによって接続されたコンポーネントが検出されます。 変数`base`各コンポーネントをカバーするコストを個別に保存します。 ギャップ リストには、2 つの隣接するコンポーネントを組み合わせたときに失われる正確な量が含まれています。 

最後のループでは、ギャップを最大から最小の順に処理します。 処理される各ギャップは、使用するタワーが 1 つ少なくなることに対応します。 出力では「最大でも」が要求されるため、`i`タワーの場合、未使用の大きなタワー数が利用可能な最良の値を維持するように、答えが埋められます。 

境界処理は重要です。 最後のコンポーネントはループの後に追加する必要があります。追加しないと、最後の間隔が消えてしまいます。 すべての算術演算では Python 整数が使用されるため、大きな座標によってオーバーフローが発生することはありません。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline

    n = int(data())
    intervals = []
    for _ in range(n):
        r, c = map(int, data().split())
        intervals.append((c, r + c))

    intervals.sort()
    base = 0
    gaps = []

    l, r = intervals[0]
    for nl, nr in intervals[1:]:
        if nl <= r:
            r = max(r, nr)
        else:
            base += r - l
            gaps.append(nl - r)
            l, r = nl, nr

    base += r - l
    gaps.sort(reverse=True)

    ans = [0] * n
    cur = base
    cnt = len(gaps) + 1
    ans[cnt - 1] = cur

    for g in gaps:
        cur += g
        cnt -= 1
        ans[cnt - 1] = cur

    for i in range(1, n):
        if ans[i] == 0:
            ans[i] = ans[i - 1]

    sys.stdin = old
    return " ".join(map(str, ans))

## 特殊なケース

 戸建住宅の場合は、次のようなものがあります。```
1
5 10
```間隔は`[10,15]`。 このアルゴリズムではギャップが生じないため、コンポーネントは 1 つだけであり、コストは`15 - 10 = 5`。 これにより、タワーの対角座標とその列コストの混同を避けることができます。 

重複する間隔の場合:```
2
3 5
2 6
```間隔は`[5,8]`そして`[6,8]`。 最初の間隔が終了する前に 2 番目の間隔が開始されるため、スキャンではそれらがすぐにマージされます。 構成要素の数は 1 つであるため、すべての答えは同じになります。 これは、追加のタワーによって価格を下げることができない場合に対処します。 

区切られた間隔の場合:```
2
1 1
8 8
```スキャンにより 2 つのコンポーネントが作成され、ギャップが記録されます`8 - 2 = 6`。 2 つのタワーの場合、コストはコンポーネントの長さの合計になります。`1 + 8 = 9`。 許可されるタワーが 1 つだけの場合、アルゴリズムはギャップを追加して戻します。`15`。 この結果は、空きスペースを埋めるために料金を支払う必要性と一致します。
