 ## 解決策
 ## 問題の理解

 当社では、速度が低下しないさまざまなロボットを用意しています。 この配列の連続するセグメントごとに、ロボットがトラックの長さを超えて移動する前にグループを 1 つずつ停止できるように、ロボットを分割できるグループの最大数を知りたいと考えています。`L`。 最終的な答えは、考えられるすべてのサブ配列にわたるこれらの最大グループ数の合計です。 元の問題ステートメントと制約は Codeforces Gym 105819L からのものです。 

グループがあるとします。`x`- 番目のグループが撃たれます。 そのグループは生き残る`x`停止するまでに数秒かかるため、その中にある最速のロボットは次の条件を満たす必要があります。`speed * x <= L`。 グループの数を最大化するには、後でより厳しい制限が設けられるため、より高速なロボットを早い段階で配置する必要があります。 

位置で終わる部分配列の場合`r`、配列がソートされており、右側に最も速いロボットが含まれているため、ロボットを右から左に移動することを想像してください。 のスコアが必要な場合`k`、次に遠く離れたロボット`t`右端から順に次の条件を満たす必要があります。```
t * a[r - t + 1] <= L
```入力サイズが到達しました`N = 200000`したがって、すべてのサブ配列をチェックしてそのグループをシミュレートすることは不可能です。 くらいあります`N^2`サブ配列、これは周囲にあります`4 * 10^10`最悪の場合。 サブ配列ごとに少量の一定量の作業を行うだけでも、遅すぎます。 すべての部分配列をまとめて処理する必要があります。 

重要なエッジ ケースは、必ずしもセグメント全体の最大速度が原因ではなく、右端近くのロボットが原因でサブアレイに障害が発生する可能性があるという事実から来ています。 最速のロボットのみをチェックするソリューションは間違っています。 

例えば：```
Input:
3 10
1 6 10

Output:
6
```サブ配列は次のとおりです。`[1]`、`[6]`、`[10]`、`[1,6]`、`[6,10]`、`[1,6,10]`スコア付き`1,1,1,2,1,2`。 セグメント`[6,10]`スコアは持てない`2`なぜなら、`10`スピードロボットを最初に撃つ必要があり、`6`スピードロボットが第二弾まで生き残るためには、`12 <= 10`。 

もう 1 つの注意が必要なケースは、ロボットが正確に最後まで到達する場合です。 ロボットは厳密に通過した場合にのみクラッシュするため、許可されています`L`。```
Input:
2 10
5 10

Output:
4
```セグメント`[5,10]`スコアがある`2`。 の`10`スピードロボットは1秒後に発射され、正確な位置に到達します`10`、一方、`5`スピードロボットは2秒後に撃たれ、所定の位置に到着します`10`。 

## アプローチ

 直接的なアプローチは、すべてのサブ配列を調べることです。 それぞれについて、最速のロボットから順にグループを作成してみることができます。 すでに作成している場合`x`グループ、次のロボットは生き残る必要があります`x + 1`秒。 これは正しいです。なぜなら、より速いロボットに後から攻撃を与えると、状況がさらに困難になるだけだからです。 

問題はサブアレイの数です。 がある`N * (N + 1) / 2`たとえ各チェックがサブ配列を 1 回だけスキャンしたとしても、合計の作業量は 2 次になります。 と`N = 200000`、これは収まりません。 

有益な観察は、視点を逆転させることです。 部分配列全体が機能するかどうかを尋ねる代わりに、固定位置が現在のインデックスで終わるサフィックスが無効になる理由となるのはいつかを尋ねます。 

インデックスの場合`i`、 定義する：```
limit[i] = i + floor(L / a[i])
```1 から始まるインデックスを使用します。 部分配列が次で終了する場合`r`、位置にあるロボット`i`次の場合にのみ有効なサフィックスに属することができます。```
r - i + 1 <= floor(L / a[i])
```これは次と同じです:```
r + 1 <= limit[i]
```だから位置`i`終点としては悪い位置です`r`まさに次のとき:```
r >= limit[i]
```どのポジションにも、調子が悪くなる時期が決まっています。 右のエンドポイントを左から右に処理します。 位置に着いたら`r`、以前の位置をすべて追加します。`limit`に等しい`r`。 これまでに確認されたすべての不正な位置の中で、最新の位置は、その後に有効なサフィックスが開始できる最初の位置です。 その最新の悪いポジションが`last`、その後で終わるすべてのサブ配列`r`スコアがあります:```
r - last
```これにより、問題は最大アクティブ化インデックスの維持に変換され、これは単純なスイープで実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) 以上 | お(1) | 遅すぎる |
 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. コンピューティング`limit[i] = i + floor(L / a[i])`あらゆるロボットに。 この値は、サフィックス計算内でこのロボットが使用できなくなる最初の終了位置を示します。 
2. 次の値でインデックス付けされたバケットを作成します。`limit[i]`。 各バケットには、右のエンドポイントがそのインデックスに到達したときに無効になる位置が格納されます。 制限が大きいポジションは、配列境界内のバケットに入ることはありません。 
3. 右のエンドポイントをスイープします`r`から`1`に`N`。 この答えを計算する前に`r`、バケットに保存されているすべてのポジションを有効にします。`r`。 これらの位置は、次で終わるすべてのサブ配列に対して無効になりました。`r`そしてその後。 
4. Maintain the largest activated position. これは、現在の右エンドポイントに最も近い無効なロボットです。 
5.追加`r - last_bad`答えに。 これは、で終わる有効な接尾辞の可能な開始点の数です。`r`、これはまさにこの正しいエンドポイントのスコア貢献度です。 

なぜ機能するのか: 不変条件は、エンドポイントの処理後に`r`、アクティブ化されたすべての位置は正確に位置です`i`ここで、接尾辞は次で終わります`r`失敗するだろう。 最後にアクティブ化された位置は最も近い障害点であるため、その後のすべての位置と、障害が発生する前のすべての位置が有効なサフィックスを形成します。 したがって、有効な接尾辞の長さの数は次のようになります。`r - last_bad`、これはグループの最大数に等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, L = map(int, input().split())
    a = list(map(int, input().split()))

    events = [[] for _ in range(n + 2)]

    for i, speed in enumerate(a, 1):
        limit = i + L // speed
        if limit <= n:
            events[limit].append(i)

    ans = 0
    last_bad = 0

    for r in range(1, n + 1):
        for pos in events[r]:
            if pos > last_bad:
                last_bad = pos
        ans += r - last_bad

    print(ans)

if __name__ == "__main__":
    solve()
```コードは最初にアクティベーション スケジュールを構築します。 配列にはロジック内で 1 つのインデックスが付いているため、ループは次を使用します。`enumerate(a, 1)`数学的導出と一致します。 

ロボットは次の時点で無効になります。`r = i + floor(L / a[i])`。 この値がより大きい位置`N`入力内で終わるサブ配列は無効になることがないため、無視されます。 

掃討中、`last_bad`すでに無効になっているすべてのロボットの中で最大のインデックスを格納します。 更新の順序は重要です。コントリビューションを追加する前に、現在の正しいエンドポイントのイベントをアクティブにします。`limit[i] = r`で終わるサブ配列ではすでに失敗しています`r`。 

最終的な合計額は約`N²`Python の整数型は任意の精度を自動的に処理するため、ここでは役に立ちます。

 ## 特殊なケース

 最速のロボットだけが決定要因ではない場合は、アクティベーション プロセスによって処理されます。 で`3 10 / 1 6 10`、スピードのあるロボット`6`限界がある`3`、そのため、右のエンドポイントでは無効になります`3`。 アルゴリズムは位置をマークします`2`悪いものとして扱い、その後に始まるサフィックスのみをカウントします。 

条件が次を使用するため、ロボットが正確に端に到達する境界ケースが機能します。`floor(L / speed)`。 のために`2 10 / 5 10`、速度`10`ロボットが持っている`floor(10 / 10) = 1`, したがって、最初のグループとして許可されます。 スピード`5`ロボットが持っている`floor(10 / 5) = 2`, したがって、2 番目のグループとして許可されます。 

単一のロボットの場合、どの位置も初期の故障点になることはありません。 スイープは維持します`last_bad = 0`、つまり貢献度は`1`、これが唯一可能なスコアです。 これは、インデックス変換によって長さ 1 の部分配列が削除されないことも確認します。
