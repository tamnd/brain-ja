 ## 解決策
 ## 問題の理解

 チェストと鍵のコレクションがあります。 各チェストには何らかの価値があり、各鍵には価格があります。 アリスはチェストにロックを設置できます。ロックには特定のキーが必要です。 ボブは、購入する鍵のサブセットを選択し、その代金を支払い、必要なすべての鍵を所有しているチェストを正確に開けます。 アリスは、ボブがプラスの利益を決して得られないようにロックを選択し、ロックの設置にかかる費用をできるだけ少なくしたいと考えています。 

入力には、チェストと鍵の数、チェストの価値、鍵の価格、およびすべてのチェストに可能なすべてのタイプの錠前を取り付けるコストが記述されます。 出力は、アリスの勝利を保証する最小総ロック コスト、または`-1`ロックの配置が機能しない場合。 

制約はチェストと鍵の数が少ないことです。 両方とも最大 6、チェスト値は最大 4 です。ロックのコストは最大 10^7 と大きくなる可能性があるため、アルゴリズムは考えられる総コストをすべて試行することに依存できません。 チェストとキーが少数しかないため、意図したソリューションでは小さな寸法を使用して状態空間を圧縮します。 考えられるすべてのロックの割り当てを直接考慮するアプローチでは、チェストごとに最大 64 の選択肢があり、64^6 の可能性が得られますが、これはすでに快適な解決策としては大きすぎます。 

よくある間違いは、貴重なチェストに多くのロックを追加すれば常に十分であると考えることです。 ロックは、ボブが購入できるすべてのキーのセットに対して連携して機能する必要があります。 例えば：```
1 2
4
1 1
5 5
5 5
```唯一のチェストに両方のキーが必要な場合、ボブは両方のキーを購入し、値 4 を取得し、2 を支払うので、ボブが勝ちます。 出力は次のようにする必要があります`-1`。 すべてのチェストの合計値がキーコストの合計より小さいかどうかだけをチェックする不用意な解決策は、ボブがより小さいサブセットを選択できるため、ここでは失敗します。 

もう 1 つのエッジ ケースは、チェストの合計値がすべてのキーでカバーできない場合です。 例えば：```
1 1
4
1
10
```ボブはいつでも唯一の鍵を購入して宝箱を開けることができるため、鍵の配置がなくても役に立ちます。 正しい出力は次のとおりです`-1`。 

## アプローチ

 直接的なアプローチは、すべてのチェストに必要なキーの最終セットを割り当てることです。 各チェストについて、キーのすべてのサブセットを試して、ボブが行うすべての可能な選択が非プラスの利益をもたらすかどうかを確認できます。 これは正しいです。最終的なロックの配置によって、ボブの可能なアクションが完全に決定されるからです。 問題は、各チェストには最大 2^6 個の可能なロック セットがあるため、検索スペースが 64^n まで増大することです。 チェストが 6 つある場合、これは何億もの組み合わせとなり、すべての組み合わせでキーの多くのサブセットをチェックする必要があります。 

重要な観察は、チェストの値が非常に小さいということです。 ボブが宝箱を開けるのを妨げているものは何なのか考えてみましょう。 価値のあるチェスト`x`必要なだけ`x`最適なソリューションでさまざまなロックが割り当てられます。 チェストに以上のものがある場合`x`ロックのうちの 1 つは、ソリューションの背後にある min-cut 引数には不要です。 つまり、各チェストは正確な履歴ではなく、受け取ったロックの数だけを追跡する必要があります。 

鍵を一つ一つ加工していきます。 現在のキーについては、このロックを受け取るチェストの数を決定します。 状態は、各チェストがこれまでに収集したロックの数を保存します。 すべてのキーが処理された後、すべてのチェストはロック内の値を正確に収集する必要があります。 その理由は、ボブが開けるチェストのセットは、それらのチェストに必要な個別のキーに対して課金される可能性があるためです。 必要なロック数に達すると、あらゆる収益性の高いセットが不可能になります。 

キーが 6 つしかなく、各チェストに必要なロックは最大 4 つであるため、DP 移行は小さくなります。 状態空間は最大でもいくつかのカウンターの 5^6 倍であり、これは小さいです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((2^m)^n * 2^m) | お(1) | 遅すぎる |
 | 最適 | O(m * 5^n * 5^n) | O(5^n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. キーのプレフィックスを処理した後、各チェストが持つロックの数を表す DP 状態を作成します。 初期状態では、どのチェストにもロックはなく、キーも処理されていません。 今後の決定は各チェストにさらに必要なロックの数のみに依存するため、この状態で十分です。 
2. キーを順番に処理します。 現在のキーについては、このキーのロックをチェスト間で分散するためにあらゆる方法を試してください。 鍵はチェストに置くことも置かないこともでき、同じ鍵を複数のチェストの錠前として使用することもできます。 
3. チェストがこの鍵を受け取ると、そのロック数が 1 つ増加します。 キーが少なくとも 1 つのチェストで使用される場合は、このキーを最初のチェストに配置するコストを追加し、コストがチェストとキーのペアごとに 1 回だけ支払われるように、移行を慎重に処理します。 
4. すべてのキーが処理されたら、すべてのチェストが正確に配置されている状態を確認します。`a[i]`ロック。 これは、アリスがボブが利益を得ることができないことを保証するのに十分な制限がある唯一の州です。 
5. 最終状態に到達できない場合は、次のように出力します。`-1`。 それ以外の場合は、保存されている最小コストが答えとなります。 

なぜ効果があるのか:

 不変条件は、いくつかのキーを処理した後、DP 値は、それらの処理されたキーのみを使用して、保存されている数のロックを正確に作成する最も安価な方法であるということです。 遷移では、次のキーのあらゆる使用法が列挙されるため、有効な構築がスキップされることはありません。 最後の要件は、開いたチェストのコレクションの合計値が必要なキーのコストを超えないようにするために、すべてのチェストに十分な独立した制限が必要であるという条件と一致します。 考えられるすべてのロック割り当てが表現されるため、到達可能な最小の最終状態がまさに最適な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    c = [list(map(int, input().split())) for _ in range(n)]

    start = tuple([0] * n)
    dp = {start: 0}

    for key in range(m):
        ndp = {}
        for state, cost in dp.items():
            def dfs(i, cur, add_cost):
                if i == n:
                    ndp[tuple(cur)] = min(ndp.get(tuple(cur), 10**30), cost + add_cost)
                    return
                for take in range(a[i] - cur[i] + 1):
                    cur[i] += take
                    dfs(i + 1, cur, add_cost + (c[i][key] if take else 0))
                    cur[i] -= take

            dfs(0, list(state), 0)

        dp = ndp

    target = tuple(a)
    ans = dp.get(target, None)
    print(-1 if ans is None else ans)

solve()
```考えられるすべてのチェストとキーのペアが最終的な答えに現れる可能性があるため、入力処理では完全なコスト マトリックスが読み取られます。 DP ディクショナリは到達可能な状態のみを保持するため、未使用の組み合わせの保存が回避されます。 

トランジションは、現在のキーが各チェストに追加される回数を再帰的に試行します。 1 つのキーはチェストごとに 1 つのロックしか提供できませんが、状態表現では、そのチェストに割り当てられた処理済みキーの数がカウントされます。 各チェストに必要なロックは最大 4 つであるため、再帰には制限があります。 

最終的な検索では、すべてのチェスト値を含むタプルが使用されます。 価値のある宝箱なのでこれがターゲットです`a[i]`圧縮された定式化にはまさにその数のロックが必要です。 その状態に到達しなかった場合、アリスは強制的に勝利を得ることができません。

import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    c = [list(map(int, input().split())) for _ in range(n)]

    for key in range(m):
        ndp = {}
        for state, val in dp.items():

 ## 特殊なケース

 すべてのチェストの合計値がすべての鍵の合計値よりも大きい場合、ボブはすべての鍵を単純に購入できるため、アリスは勝つことができません。 十分なロックを必要とする最終状態に到達できないため、アルゴリズムがこれを処理します。 例では:```
1 1
4
1
10
```キーを処理した後の唯一の状態では値 4 のチェストをブロックするのに十分ではないため、答えは次のようになります。`-1`。 

複数のチェストが同じ安価なキーを求めて競合する場合、貪欲なソリューションは失敗する可能性があります。 DP はすべてのキーのすべての配布を考慮するため、それが最終的な安全な状態に到達する唯一の方法である場合は、1 つのチェストで安価なキーを未使用のままにし、別のチェストでより多くのキーを費やすことを決定できます。 

のために：```
2 3
3 3
1 1 4
10 20 100
20 15 80
```アルゴリズムが到達する`(3,3)`3 つのキー タイプをすべて正しい組み合わせで使用した後にのみ使用してください。 中間状態はグローバルに比較されるため、局所的に安価な選択にとどまりません。
