 ## 解決策
 ## 問題の理解

 フィボナッチに似た長さのシーケンスが与えられます。`n`。 

最初の 2 つの用語は次のとおりです`a`そして`b`、後の各項は前の 2 つの項の合計です。 各クエリについて、そのシーケンスから開始して操作を実行する場合があります。 操作によりインデックスが選択されます`k`、増加します`f[k]`1 ずつ増やしてから、フィボナッチ漸化式を使用して後の項ごとに再計算します。 最初`k - 1`値は変更されません。 

タスクは、シーケンスの合計を目標値と等しくするために必要な演算の最小数を決定することです。`x`、またはレポート`-1`それができない場合。 世界的な価値`n`はすべてのクエリで固定されていますが、クエリによって異なる値が提供されます。`a`、`b`、 そして`x`。 制約は次のとおりです。`n ≤ 30`、`q ≤ 5 · 10^5`、 そして`x ≤ 5 · 10^6`。 

クエリの数が異常に多いため、クエリごとの操作のシミュレーションは即座に除外されます。 たとえ`O(n^2)`クエリごとのソリューションは、50 万のクエリに対して遅すぎるでしょう。 のみに依存する前処理ステップが必要です。`n`、非常に高速なクエリ処理が続きます。 

元の合計がすでに より大きい場合、微妙なエッジ ケースが発生します。`x`。```
n = 4
a = 1
b = 1
x = 6
```順序は`[1, 1, 2, 3]`、その合計は`7`。 すべての操作で合計が増加するため、`6`不可能です。 正しい答えは、`-1`。 

もう 1 つの簡単な間違いは、項を増やすと合計が 1 だけ変わると仮定することです。```
[2, 1, 3, 4, 7]
```3 番目の項を増やすと、```
[2, 1, 4, 5, 9]
```合計額が増加しました`4`ではなく、`1`。 繰り返しにより、変更が前方に伝播されます。 

3 番目の罠は、ポジションが違えば貢献度も異なるということを忘れてしまうことです。 初期のインデックスに対する操作は将来の多くの条件に影響を与えますが、終了近くの操作は少数の条件にのみ影響します。 

## アプローチ

 ブルート フォース ビューでは、各操作を独立して処理します。 すべてのポジションについて、1 つの操作を適用すると合計がどれだけ増加するかを計算できます。 その場合、問題はコインの両替の問題になります。つまり、最小限の操作で必要な増額に達するということです。 

この観察は、問題の論理的な部分を解決するにはすでに十分です。 

増やしたとします`f[k]`1つずつ。 誘発された変化シーケンスは次のとおりです。```
1, 1, 2, 3, 5, ...
```位置から開始`k`。 

合計額の増加分は、```
1 + 1 + 2 + 3 + ... + Fm
```どこ`m = n - k + 1`。 

フィボナッチ接頭辞合計恒等式を使用すると、```
F1 + F2 + ... + Fm = Fm+2 - 1
```その位置での 1 回の操作によるゲインは```
cm = Fm+2 - 1
```したがって、利用可能な操作値は次のとおりです。```
1, 2, 4, 7, 12, 20, ...
```まさにそれは`F3 - 1, F4 - 1, F5 - 1, ...`。 

クエリは次のようになります。```
Let D = x - current_sum.
Find the minimum number of coins needed to form D
using coin values F3-1, F4-1, ..., Fn+2-1.
```重要な観察は、このコイン システムが正規であるということです。 使用可能な最大のコインを貪欲に選択することが常に最適です。 その理由はフィボナッチ構造にあります。```
(Fi+2 - 1) = (Fi+1 - 1) + (Fi - 1) + 1
```これにより、Zeckendorf 表現を機能させるのと同じ交換プロパティが得られます。 どのような最適解も、最初に可能な限り最大のコインを取得し、次に残りの金額を貪欲に解決する解に変換できます。 

以来`n ≤ 30`、コインの値は最大 30 個です。 貪欲なクエリは、`O(n)`時間。

 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DP コインの変更 | O(n・D) | O(D) | 遅すぎる |
 | 貪欲なフィボナッチコインシステム | クエリあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. インデックスまでのフィボナッチ数を事前計算する`32`。 
2. コインの価値を構築する```
coin[i] = Fi+2 - 1
```使用可能なすべての操作位置に対応します。 
3. シーケンス全体を生成せずに、元のシーケンスの合計を計算します。 

の係数`a`合計額は`Fn`、および係数`b`は`Fn+1 - 1`、与える```
S = a · Fn + b · (Fn+1 - 1)
```4. しましょう```
D = x - S
```もし`D < 0`、印刷`-1`。 
5. それ以外の場合は、残りの価値を超えない最大のコインを繰り返し取得します。 
6. 取られたコインの数を数えます。 
7. 余りがゼロになった場合、カウントを出力します。 それ以外の場合は出力`-1`。 

### なぜ効果があるのか

 すべての操作は値の 1 つを提供します```
F3 - 1, F4 - 1, ..., Fn+2 - 1.
```数回の操作後の合計増加量は、選択したコインの価値の合計となります。 

フィボナッチ由来のコイン システムは、ゼッケンドルフ表現と同じ交換特性を満たします。 解決策が可能な限り最大のコインを使用しない場合は常に、コインの数を増やすことなく、その貢献を同等以上の額面で置き換えることができます。 この変換を繰り返すと、貪欲なソリューションが生成されます。 各グリーディ ステップは何らかの最適なソリューションで強制されるため、最終的なグリーディ カウントは最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())

fib = [0] * 35
fib[1] = fib[2] = 1
for i in range(3, 35):
    fib[i] = fib[i - 1] + fib[i - 2]

coins = [fib[i + 2] - 1 for i in range(1, n + 1)]

coef_a = fib[n]
coef_b = fib[n + 1] - 1

out = []

for _ in range(q):
    a, b, x = map(int, input().split())

    s = a * coef_a + b * coef_b
    d = x - s

    if d < 0:
        out.append("-1")
        continue

    ans = 0
    rem = d

    for c in reversed(coins):
        if rem == 0:
            break
        take = rem // c
        ans += take
        rem -= take * c

    if rem == 0:
        out.append(str(ans))
    else:
        out.append("-1")

sys.stdout.write("\n".join(out))
```最初のブロックはフィボナッチ数を 1 回計算します。 以来`n`30 を超えることはありません。この前処理は非常に小さいです。 

次のステップでは、演算ゲインを構築します。 ポジションに関連付けられた値は、その右側にどれだけの用語が残っているかによってのみ決まるため、すべてのクエリに対して同じコイン リストが再利用されます。 

式```
S = a · Fn + b · (Fn+1 − 1)
```シーケンス全体の生成を回避します。 最大 500,000 個のクエリがあるため、これは重要です。 

貪欲ループは最大 30 の金種を処理するため、すべてのクエリが非常に小さく保たれます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n, q = map(int, input().split())

    fib = [0] * 35
    fib[1] = fib[2] = 1
    for i in range(3, 35):
        fib[i] = fib[i - 1] + fib[i - 2]

    coins = [fib[i + 2] - 1 for i in range(1, n + 1)]

    coef_a = fib[n]
    coef_b = fib[n + 1] - 1

    out = []

    for _ in range(q):
        a, b, x = map(int, input().split())

        s = a * coef_a + b * coef_b
        d = x - s

        if d < 0:
            out.append("-1")
            continue

        ans = 0
        rem = d

        for c in reversed(coins):
            take = rem // c
            ans += take
            rem %= c

        out.append(str(ans) if rem == 0 else "-1")

    return "\n".join(out)
