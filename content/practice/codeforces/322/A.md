 ## 解決策
 ## 問題の理解

 このタスクでは、すべてのパフォーマンスに男の子と女の子が 1 人ずつ参加するダンス ルームについて説明します。 参加者は未経験からスタートし、各ダンス中に少なくとも 2 人のうち 1 人は初めて踊る必要があります。 言い換えれば、各ペアには、これまでのダンスに一度も出演したことがない参加者が少なくとも 1 人含まれていなければなりません。 

男の子と女の子の数が与えられているので、この制約を尊重しながら、できるだけ長く有効な一連のダンスを構築する必要があります。 それぞれのダンスは独立したものではありません。一度参加すると、今後のペアリングでは「初めて」の条件を満たさなくなる可能性があるため、以前の選択は、後で何が可能になるかに直接影響します。 

境界は小さく、どちらのカウントも最大 100 です。これにより、大幅な最適化やサブセットの検索の必要性が即座に排除されます。 O(n²) や O(nm) の構築でさえ、時間的には些細なことなので、本当の困難は効率ではなく、将来の有効な手を誤ってブロックすることを避ける構造を見つけることです。 

素朴なアプローチは、有効なペアを繰り返し選択し、貪欲に続行することです。 微妙な障害モードは、選択したペアの両方の参加者が以前に使用されている場合に表示されます。 たとえば、すでに使用されている 2 人の人物をペアにすると、すぐにルールに違反し、構造が壊れてしまいます。 もう 1 つの失敗モードは、「新しい」参加者の一方のグループが時期尚早に疲弊し、もう一方の参加者が十分に活用されないままになり、達成可能なダンスの総数が減少することです。 

主な困難は、後の有効なペアリングを妨げるような形で、新しい参加者を早期に紹介する機会を決して「無駄」にしないようにすることです。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての有効なシーケンスをシミュレートします。 各ステップで、まだルールを満たしている未使用または以前に使用されたすべてのペアを試して再帰することができます。 原理的には正しいですが、各状態が多くの可能な組み合わせに分岐するため、これはすぐに指数関数的になります。 n と m が約 100 であっても、決定ごとにどの参加者が「新規」のままであるか、および将来の遷移の有効性が変化するため、シーケンスの数は爆発的に増加します。 

構造的な洞察は、すべてのダンスが、これまでに使用されていなかった少なくとも 1 人の参加者に貢献しているということです。 これは、ダンスの数が、どれだけ新しい人を紹介できるかによって厳密に制御されることを意味します。 両方のグループが部分的に消費されたら、最善の戦略は、できるだけ長く、ダンスごとに 1 人の新しい参加者を導入し続けることです。 早期に 2 人の新しい参加者を導入するような逸脱は役に立ちません。将来利用可能な「新しい」貢献のプールが減少するからです。 

これは、最初に 1 人の男の子と 1 人の女の子を一緒に「固定」するという構造につながります。 その後、残りの男の子を固定の女の子と系統的に組み合わせて、新しい男の子を紹介し続けます。さらに、残りの女の子を固定の男の子と組み合わせて、新しい女の子を紹介し続けます。 これにより、最初のペアリングの後にすべてのステップで 1 人の新しい参加者が導入されることが保証され、これが最適です。

 ## アルゴリズムのチュートリアル

1. 男の子と女の子を 1 人ずつ最初のアンカー ペアとして選択し、最初に一緒に踊るようにスケジュールします。 これにより、双方に少なくとも 1 人の「使用済み」参加者がいることが保証され、残りの構築に柔軟性が与えられます。 
2. 選択した女の子を再利用可能なパートナーとして固定し、他のすべての男の子とペアにします。 これらのダンスはそれぞれ、新しい男の子を導入しますが、女の子はすでに使用されているため、制約は満たされたままになります。 
3. 選択した男の子を再利用可能なパートナーとして固定し、最初のステップですでに使用された女の子を除く残りのすべての女の子とペアにします。 これらのダンスはそれぞれ、男の子がすでに慣れている間に新しい女の子を登場させ、ルールを有効に保ちます。 
4. 記録されたすべてのペアを順番に出力します。 

重要なアイデアは、最初のペアリングの後、どちらの側が新しい参加者を提供するかを交互に切り替え、もう一方の側には 1 人の固定の「古い」参加者を維持するということです。 

### なぜ効果があるのか

 最初のステップ以降の各ステップでは、ペアの参加者の 1 人だけがこれまでに踊ったことがありません。 これにより、すべてのダンスでルールが満たされることが保証されます。 また、この構造により、未使用の男の子はすべて最終的に 1 回ペアリングされ、未使用の女の子もすべて 1 回ペアリングされるため、有効なペアが早期に不足することがないことが保証されます。 新しい参加者はそれぞれ、ペアリングの「新しい」側として 1 回だけ消費されるため、制約に違反することなくこれ以上のダンスを生成する構成はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    res = []
    
    # Step 1: anchor pair
    res.append((1, 1))
    
    # Step 2: use girl 1 with remaining boys
    for i in range(2, n + 1):
        res.append((i, 1))
    
    # Step 3: use boy 1 with remaining girls
    for j in range(2, m + 1):
        res.append((1, j))
    
    print(len(res))
    for a, b in res:
        print(a, b)

if __name__ == "__main__":
    solve()
```このソリューションでは、スケジュールを検索するのではなく、明示的にスケジュールを作成します。 最初のペアは両方の参加者を「使用済み」として初期化し、どちらの側でも安全に再利用できるようにします。 男の子のループにより、女の子 1 が固定され、すべての新しい男の子が必要な目新しさを提供できるようになります。 2 番目のループはこのアイデアを反映しており、男の子 1 が固定され、残りの女の子がすべて紹介されます。 

ループを逆にすることは正確性にとって重要ではないため、順序は重要ですが、後のステップで少なくとも 1 つの再利用された参加者が存在することを保証するために、最初のアンカーが最初に発生する必要があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各男の子と女の子は、初期化後に最大 1 つの構築ステップで使用されます。 
| スペース | お(1) | 出力リストのみが保存され、入力サイズに応じた補助構造は保存されません。 

この制約により、1 グループあたり最大 100 人の参加者が許可されるため、線形構築は時間とメモリの両方において簡単になります。 出力サイズも n + m で制限され、直接印刷できるほど小さいです。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    n, m = map(int, input().split())
    res = [(1, 1)]
    for i in range(2, n + 1):
        res.append((i, 1))
    for j in range(2, m + 1):
        res.append((1, j))
    print(len(res))
    for a, b in res:
        print(a, b)

# provided sample
assert run("2 1\n") == "2\n1 1\n2 1"

# custom cases
assert run("1 1\n") == "1\n1 1", "minimum case"
assert run("1 5\n") == "5\n1 1\n1 2\n1 3\n1 4\n1 5", "single boy"
assert run("5 1\n") == "5\n1 1\n2 1\n3 1\n4 1\n5 1", "single girl"
assert run("3 3\n") == "5\n1 1\n2 1\n3 1\n1 2\n1 3", "balanced case"

 ## 特殊なケース

 男の子が 1 人だけ、または女の子が 1 人だけの場合でも、最初のペアリングで唯一の参加者がすぐに再利用可能になり、残りのすべてのダンスでは反対側を導入しながらその固定された人を再利用する必要があるため、アルゴリズムは依然として機能します。 たとえば、入力の場合`1 4`、シーケンスペア`(1,1), (1,2), (1,3), (1,4)`は自然に生成され、すべてのステップで新しい女の子が導入され、ルールが満たされます。 

n と m が両方とも 1 の場合、単一のダンスのみが可能です。 アルゴリズムは正確に生成します`(1,1)`シーケンスを延長する参加者が残っていないため、停止します。
