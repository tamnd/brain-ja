 ## 解決策
 ## 問題の理解

 それぞれが固定色の花を表す 3 つの独立したアイテムが与えられています。 これらの材料から、根本的に異なる 2 つの方法で花束を作ることができます。 1 つのタイプの花束は単一の色の花を 3 つ消費しますが、もう 1 つのタイプの花束は各色から 1 つだけの花を消費します。 

タスクは、花が再利用されず、花束の総数ができるだけ多くなるように、花束の形成順序を選択することです。 この決定は、花束の順序によって制約されるのではなく、限られたリソースを 2 つの競合する消費パターン間でどのように分割するかによってのみ制約されます。 

この制約により、各色のカウントは最大 10^9 まで許可され、花束タイプ間の花の分布を調査しようとするシミュレーションは除外されます。 単純な方法で混合ブーケの可能な割り当てを反復するソリューションは、入力値のサイズが線形かそれ以上に低下するため、実行不可能です。 

微妙な難しさは、2 種類の花束間の相互作用から生じます。 混合ブーケでは 3 つのカウントすべてが同時に減少しますが、単色のブーケでは 1 つの次元のみが減少します。 「常に最初にできるだけ多くの混合ブーケを取得する」などの単純な貪欲な選択は、後で多くの単色のトリプルを形成する機会を破壊する可能性があるため、失敗する可能性があります。 たとえば、(1、1、100) のようにカウントが不均衡な場合、1 つのミキシング ブーケを選択すると、利用可能な唯一の赤と緑の花がすぐに削除されますが、すべての色にわたってより構造的なバランスが存在していれば、これら 2 つの花はより適切に予約されていた可能性があります。 

本当の問題は、最適な戦略は小さなシフトを法とするカウントのみに依存することです。これは、すべての単色のブーケが色を 3 減らすのに対し、すべての混合ブーケはすべての色を 1 減らすためです。これにより、3 つのカウントの絶対的な大きさではなく、相対的な位置合わせのみが重要となる構造が作成されます。 

## アプローチ

 強引なアプローチでは、混合ブーケの数 (たとえば x) を決定し、残りの数から単色のブーケの最適な数を計算します。 x を選択するたびに、3 つの色すべてから x を減算し、3 による除算のフロアを計算します。x の範囲は min(r, g, b) までであるため、O(min(r, g, b)) の可能性が生じますが、値が 10^9 に達する場合、これは完全に不可能になります。 

重要な洞察は、花束を混合するための決定空間を範囲全体にわたって調査する必要がないということです。 各混合ブーケは 3 つのカウントすべてを均等に減らすため、重要なのはカウントが相互にシフトされたときの剰余構造です。 混合ブーケの共通数を減算すると、少なくとも 1 つのカウントが小さくなり、その小さな値がシステムの構成を効果的に決定します。 

これは、最適解は 3 つの状態のいずれかに非常に近い値で発生する必要があるという観察につながります。パリティの配置を変更するために少数の花を「犠牲」にする 0、1、または 2 つの初期調整を行い、その後、できるだけ多くの混合ブーケを貪欲に取得します。 その後、残った花はすべて単色トリプルで独立して使用されます。 混合ブーケの数を 3 つ増やすと、各色が 3 つ減るだけであり、残りの 3 分割の構造は変更されないため、3 つのオフセットをすべて試すだけで十分です。

 ## アルゴリズムのチュートリアル

1. 事前に 0、1、または 2 つの混合ブーケを削除することで初期状態を調整できることを考慮します。 これが行われるのは、最適な構成は、繰り返しの削減後に 3 つの値がモジュロ 3 でどのように整列するかに依存するためです。 
2. {0, 1, 2} の各オフセット値 x について、r、g、b から x を減算します。ただし、すべてが負でない場合に限ります。 これは、一括操作をコミットする前に別の位置合わせを強制するというアイデアをモデル化しています。 
3. 調整された値について、形成できる混合ブーケの数 (min(r, g, b)) を計算します。 その数を取り、3 色すべてから引きます。 このステップでは、そのような各ブーケがすべての制約を同時に軽減するため、クロスカラー リソースの使用が最大化されます。 
4. 考えられるすべての混合ブーケを除去した後、床を 3 で割って、残りの各プールから何個の単色のブーケを形成できるかを計算します。 
5. この構成のすべてのブーケ数を合計します。 
6. 3 つのオフセットすべてにわたって最大の結果を取得します。 

### なぜ効果があるのか

 このプロセスでは、最初にすべての色を一緒にシフトした回数に基づいて、解空間を剰余クラスに分割します。 この配置が修正されると、残りの不均衡はすべての色から 1 つのユニットを同時に消費することによってのみ解決できるため、可能なすべての混合ブーケを使用することが最適になります。 その時点以降、各色は 3 で除算して独立して進化し、色間のそれ以上の相互作用は結果を改善できません。 これにより、実行可能なすべての最適な構造が、テストされた 3 つのアライメントのいずれかで表されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    r, g, b = map(int, input().split())
    
    ans = 0
    
    for shift in range(3):
        rr, gg, bb = r - shift, g - shift, b - shift
        if rr < 0 or gg < 0 or bb < 0:
            continue
        
        # take as many mixing bouquets as possible
        mix = min(rr, gg, bb)
        rr -= mix
        gg -= mix
        bb -= mix
        
        # then take single-color bouquets
        total = mix + rr // 3 + gg // 3 + bb // 3
        ans = max(ans, total)
    
    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、システムのさまざまなアライメント状態に対応する 3 つの可能な初期オフセットをすべて試行します。 各状態について、可能な限り多くのミキシング ブーケを貪欲に抽出します。これは、ミキシング ブーケが 3 つのリソースすべてを均等に消費するため、最も効率的な方法で不均衡が軽減されるためです。 この安定化ステップの後、残りの各色は 3 つのグループを通じてのみ寄与できるため、整数を 3 で割ると、追加のブーケの正確な最大数が得られます。 

3 つのオフセットの最大値により、わずかに異なる開始アライメントによって長期的により適切な構成が生成されるケースを見逃すことがなくなります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return main()

def main():
    r, g, b = map(int, input().split())
    ans = 0
    for shift in range(3):
        rr, gg, bb = r - shift, g - shift, b - shift
        if rr < 0 or gg < 0 or bb < 0:
            continue
        mix = min(rr, gg, bb)
        rr -= mix
        gg -= mix
        bb -= mix
        ans = max(ans, mix + rr // 3 + gg // 3 + bb // 3)
    return str(ans)

# provided sample
assert run("3 6 9") == "6"

# all equal small
assert run("1 1 1") == "1"

# no mixing possible
assert run("3 0 0") == "1"

# boundary minimal
assert run("0 0 0") == "0"

# skewed large imbalance
assert run("100 100 1") >= "33"

 ## 特殊なケース

 のようなケース`3 0 0`花束を混合するのは不可能であり、アルゴリズムは自然に単色のトリプルのみに戻ることを示しています。 シフト 0 では、ミキシングがゼロで、有効な赤い花束が 1 つ得られますが、他のシフトは負の値のため無効です。 これにより、アルゴリズムが不可能な場合に誤って混合を強制していないことが確認されます。 

のために`1 1 1`、シフト 0 状態では、ただちに 1 つのミキシング ブーケが生成され、すべての花が削除されますが、他のシフトは無効になります。 アルゴリズムは、単一色のグループ化が他の色の組み合わせよりも優れていることを正しく認識し、正しい配置で最大値が達成されます。
