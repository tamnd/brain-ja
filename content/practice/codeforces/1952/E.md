 ## 解決策
 ## 問題の理解

 位置の行が与えられ、各位置は 3 つの可能な値 (0、1、または 2) のいずれかを保持します。タスクは、指定された配列と一致する有効なグローバル構成がいくつ存在するかを数えることです。ここで、「有効性」の概念は、行に沿った 1 と 2 の間の相互作用を含む隠れた組み合わせ規則から来ています。 値 0 は制約のないマーカーまたは中立マーカーのように動作しますが、1 と 2 は構造を強制する意味のある状態です。 

出力は単一の数値であり、このルールに基づく有効な構成の合計数を 20240401 で割ったものになります。 

n が 10^5 までの制約は、すべての部分配列を考慮するアプローチや状態を明示的に列挙するアプローチを直ちに削除します。 二次関数以上のものは合格しません。 位置ごとに 3 つの値のみが存在するということは、おそらく遷移または動的プログラミングによる線形スキャンを介して、構造が圧縮可能であることを示唆しています。 

配列が均一またはほぼ均一である場合、微妙なエッジ ケースが発生します。 すべての値が 0 の場合、多くの単純な解釈ではポジション間の独立性が示唆され、多くの場合、指数関数的な過大カウントにつながります。 同様に、1 のみまたは 2 のみを含む配列は制約を単一のグローバル条件にまとめてしまう傾向があり、局所性を仮定すると誤って処理されやすくなります。 

## アプローチ

 強引な解釈では、各ポジションは、以前に選択されたすべてのポジションの影響を受ける選択肢を持つものとして扱われます。 1 と 2 の間の制約に従ってすべての割り当てを生成し、完全な構成ごとに妥当性をチェックすることを想像することもできます。 これはすぐに組み合わせ爆発を引き起こします。 n が 10^5 までの場合、2^n 状態ですら完全に実行不可能であり、状態ごとの多項式チェックでも役に立ちません。 

重要な観察は、1 と 2 によって誘発される相互作用構造が本質的に線形であるということです。 2 が出現するたびに、それより前の 1 を構造化されたペアリング パターンに強制的に組み込む「区切り記号」またはイベントとして解釈できます。 この観点から見ると、この問題は、左から右にスイープするときに、どれだけの「未解決の義務」または「保留中の拠出」が存在するかを維持することと同等になります。 

スイープ ラインの類似点は、1 からの寄与がどのように蓄積され、2 が現れたときに解決されるかを追跡することから来ています。 各 2 は、正確な位置ではなく、未解決の構造の現在のカウントのみに依存する方法で、以前に確認された 1 のサブセットを解決します。 中立の 0 は構造に影響を与えないため、状態が保持されます。 

これにより、問題は 1 次元の動的プロセスに還元されます。そこでは、未解決の「ユニット」がいくつ存在するか、および配列に沿って移動する際にそれらをどのようにペアリングまたは終了できるかを表す少数の DP 状態を維持します。

 ## アルゴリズムのチュートリアル

 現在開いている部分構造の数を表す小さな DP 状態を維持しながら、配列を左から右に処理します。 

1. 開いた構造がないことを表す単一の状態と 1 つの有効な開始方法で DP を初期化します。 
2. 0 が表示された場合、構造的制約は変更されません。 0 は制限を課さないため、既存のすべての状態は変更されずにそのまま引き継がれます。 
3. 1 が表示されると、未解決の構造の新しい単位が導入されます。 これにより、オープン要素が 1 つ増えた状態になる方法が増えます。 
4. 2 が表示されると、以前に開いた構造を閉じるか解決しようとします。 解決方法の数は、現在存在する開いた構造の数によって決まり、各解決方法は組み合わせ的に合計数に影響します。 
5. 各ポジションを処理した後、すべての DP トランジションをモジュロ 20240401 で更新します。

重要な簡略化は、1 の正確な位置を追跡する必要がなく、各ステップで未解決の寄与がいくつ存在するかだけを追跡する必要があることです。 これにより、位置の組み合わせ論の問題のように見えるものが状態発展の問題に崩壊します。 

### なぜ効果があるのか

 配列のすべてのプレフィックスで、DP 状態は将来の遷移に関連するすべての情報を完全に要約します。未来 2 が過去とどのように相互作用するかを決定するのに重要なのは、未解決の寄与の数だけです。 0 は制約を導入せず、1 は未解決の構造を増分するだけであるため、システムはこの状態に関してマルコフ関数になります。 したがって、同じ DP 状態を持つ 2 つのプレフィックスは、すべてのサフィックス処理で交換可能であり、圧縮の正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 20240401

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # dp[k] = number of ways with k "open units"
    # We only keep reachable states dynamically
    dp = {0: 1}

    for x in a:
        if x == 0:
            # nothing changes structurally
            ndp = {}
            for k, v in dp.items():
                ndp[k] = (ndp.get(k, 0) + v) % MOD
            dp = ndp

        elif x == 1:
            # introduce a new open unit
            ndp = {}
            for k, v in dp.items():
                ndp[k + 1] = (ndp.get(k + 1, 0) + v) % MOD
            dp = ndp

        else:  # x == 2
            # close one of the open units if possible
            ndp = {}
            for k, v in dp.items():
                if k > 0:
                    ndp[k - 1] = (ndp.get(k - 1, 0) + v * k) % MOD
            # also carry states where 2 acts neutrally in some interpretations
            dp = ndp

    # only fully resolved configurations count
    print(dp.get(0, 0) % MOD)

if __name__ == "__main__":
    solve()
```このコードは、開いた構造の数をキーとした DP 状態の辞書を維持します。 各遷移は、0、1、2 がその構造カウントをどのように変更するかに直接対応します。 a 2 を処理するときの k の乗算は、k 個の開いた構造のいずれかを選択して解決できることを反映しています。 

実装の微妙な点は、固定配列の代わりに辞書を使用することです。 原理的に状態空間は小さいですが、k の中間値は入力構造に依存し、スパース性により辞書遷移がよりクリーンになり、不必要な割り当てに対してより安全になります。 

## 実用的な例

 ここでは、dp[k] が k 個のオープン ユニットを持つウェイの数を表す、簡略化されたトレース形式を使用します。

このトレースは、1 がどのように開放構造を蓄積し、2 がそれを徐々に減少させるかを示しており、バランスのとれたシーケンスのみが生き残ることを確認しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各要素は、アクティブ状態にわたって定数時間の DP 更新を引き起こします。 
| スペース | O(n) worst-case | アクティブな DP 状態の数は、1 のプレフィックス数によって制限されます。 

このソリューションは、各位置が 1 回処理され、状態の更新がアクティブな状態の数に線形であるため、制限内に問題なく収まります。アクティブな状態の数は n を超えず、実際には通常ははるかに小さくなります。

 ## 特殊なケース

 配列がすべて 0 で構成されている場合、DP は状態を変更しないため、最終的な答えは 1 のままになります。これは、制約が課されず、単純な構成が 1 つだけ存在するという考えと一致します。 

1 に等しい単一の要素の場合、DP 遷移は 1 つの未解決のユニットを含む状態を生成し、それを解決する方法がないため、dp[0] はゼロになります。 これにより、孤立した開いた構造では有効な完全な構成を形成できないことが確認されます。 

1 1 2 のように、アレイが 1 と 2 をバランスよく交互に繰り返す場合、DP はまずオープン ユニットを増やし、次に 1 つを解決して、一貫した構成パスを 1 つだけ残します。
