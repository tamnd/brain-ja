 ## 解決策
 ## 問題の理解

 それぞれが英小文字で構成される文字列のリストが与えられ、各文字列に対して、隠されたパターンに基づいて「YES」または「NO」のいずれかで答えるように求められます。 サンプルの入力と出力を観察すると、文字列「it」、「submit」、および「timelimitexceeded」は「YES」を生成しますが、「is」、「stated」、または「ac」などの他の文字列は「NO」を生成します。 これらを調べると、パターンが明らかになります。文字列内のどこかに部分文字列「it」が含まれている場合、その文字列は「YES」とマークされます。 この部分文字列を欠く他のすべての文字列には「NO」のマークが付けられます。 

入力制約は控えめで、文字列の長さはそれぞれ 100 文字までで、最大 100 文字です。これは、最悪の場合、合計 10,000 文字をチェックする必要があることを意味するため、各文字列を 1 回スキャンするソリューションであれば十分に高速です。 文字列ごとに単純な線形スキャンを行うことができます。 

明らかではないエッジ ケースには、非常に短い文字列や、「it」が端に表示される文字列が含まれます。 たとえば、「it」自体は「YES」を返す必要がありますが、「ti」は「NO」を返す必要があります。 また、文字列には「it」が複数含まれる場合がありますが、少なくとも 1 つ存在していれば十分です。 

## アプローチ

 素朴なアプローチは、すべての文字列で長さ 2 の考えられる各部分文字列をチェックし、それが「it」と等しいかどうかを確認することです。 これは、すべての 2 文字の部分文字列が一致の候補となるため機能しますが、チェックごとに文字列のほぼ全体をスキャンする必要があります。 最悪の場合、長さ n の文字列の場合、これは O(n^2) になります。 制約上、これはまだ許容されますが、不必要です。 

最適なアプローチでは、Python の組み込みの部分文字列検索を使用します。 簡単に確認できます`"it" in s`各文字列ごとに`s`。 部分文字列検索は Python で効率的に実装されており、不要な部分文字列を構築せずに問題のロジックを直接取得するため、これは文字列の長さにおいて線形です。 ブルート フォース チェックは正しいですが、文字列が大きい場合は時間がかかります。 Python のネイティブ部分文字列テストを使用すると、オーバーヘッドが削減され、クリーンで読みやすくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての部分文字列) | 文字列ごとに O(n^2) | お(1) | 受け入れられるが不要 |
 | 最適 (`"it" in s`) | 文字列ごとに O(n) | お(1) | 受け入れられ、クリーンです |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 文字列ごとに`s`テストケースでは:

 1.次のことを確認します`"it"`の部分文字列です`s`。 
2. 「はい」の場合は、「YES」と出力します。 
3. いいえの場合は、「NO」と出力します。 

重要な洞察は、問題が単純な部分文字列チェックに帰着するということです。 パイソンの`in`演算子は文字列を効率的に反復処理し、部分文字列が見つかるとすぐに停止するため、文字列あたりの直線時間が保証されます。 

機能する理由: このアルゴリズムは、各文字列について、「it」がどこかに出現した場合、部分文字列チェックによって 1 回だけ検出されるという不変条件に依存しています。 他の文字の有無は結果に影響しません。 タスクはこの固定部分文字列のみに依存するため、あいまいさはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    if "it" in s:
        print("YES")
    else:
        print("NO")
```コードは最初にテスト ケースの数を読み取ります。 部分文字列をチェックする際の偽陰性を避けるために、各文字列の末尾の改行が削除されます。 部分文字列チェック`"it" in s`はコアロジックを効率的にキャプチャし、print ステートメントは結果を即座に出力します。

これらのトレースは、アルゴリズムが長さ 2 の文字列、先頭、中間、または末尾に「it」を含む文字列、および部分文字列のない文字列を正しく処理していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(T * n) | 各 T 文字列は 1 回スキャンされます。 n は文字列の長さ |
 | スペース | お(1) | 使用される変数はわずかです。 入力サイズに比例する追加のデータ構造は不要 |

 制約 (T ≤ 100、n ≤ 100) を考慮すると、最大操作数はおよそ 10,000 であり、2 秒の制限時間内に十分収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        s = input().strip()
        if "it" in s:
            print("YES")
        else:
            print("NO")
    return output.getvalue().strip()

 ## 特殊なケース

 のために`"i"`、アルゴリズムがチェックします`"it" in "i"`文字列が短すぎるため、False が返され、「NO」が返されます。 のために`"itstart"`、部分文字列が先頭に表示され、`"it" in s`すぐに検出し、「YES」を返します。 のために`"endit"`、部分文字列は最後にあります。 Python は一致するものが見つかるまでスキャンします。 のために`"middleitmiddle"`の場合、中央の部分文字列が正しく検出されます。 のために`"ititisit"`の場合、必要な一致は 1 つだけであり、複数の一致がある場合でもアルゴリズムは「YES」を返します。 のために`"xyz"`、一致は発生しないため、アルゴリズムは正しく「NO」を出力します。 すべてのエッジ ケースは、追加のロジックを使用せずに部分文字列チェックによって直接処理されます。
