 ## 解決策
 ## 問題の理解

 21 × 21 のグリッドが与えられ、各セルには次のいずれかが含まれます。`0`または`1`。 タスクは、最大の「クロス」を決定することです。`1`このグリッド内に形成できる 。 十字は、いくつかの点を中心とするセルのセットとして定義されます。`1`ここで、上下左右の 4 本の腕はすべて連続したもので構成されています。`1`中心から伸びています。 出力は、`1`最大の十字を形成する 。 たとえば、腕の長さ 2 の十字には中心が 1 つと各方向に 2 つのセルがあり、合計 1 + 2*4 = 9 つのセルがあります。 

グリッドは小さく、21x21 に固定されており、セル数はわずか 441 個です。 これは、合計操作が 100 万回未満にとどまり、1 秒の制限内に十分収まるため、すべてのセルを調べて 4 方向すべてを個別に検査するアプローチでも実現可能であることを意味します。 

明らかではないエッジケースは、潜在的なクロスがグリッドの境界に触れたり、グリッドの境界線によってブロックされたりしたときに発生します。`0`中心部のすぐ隣にあります。 たとえば、中心が次の場合、`(0,0)`そして細胞`(0,1)`は`0`、その方向の最大アームは 0 です。対称性を前提としたり、常にアームの長さを固定してカウントしたりする単純なアプローチでは、十字のサイズを誤って過大にカウントしてしまいます。 

## アプローチ

 ブルートフォース手法では、グリッド内の各セルを検査します。 セルが`1`、連続した回数を数えながら、4 方向すべてに展開します。`1`までは各方向にあります。`0`またはグリッド境界に到達しました。 十字のサイズは、腕の長さの合計に中心の 1 を加えたものになります。 このアプローチは正しいですが、グリッドが大きい場合、セルごとに行全体または列全体を走査する可能性があるため、その複雑さは O(n^2 * min(n, m)) に増加します。 ここで、n = 21 の場合、最大演算数は 21 * 21 * 21 = 9261 であり、これは許容範囲内です。 

最適なアプローチでは、グリッドを前処理して各セルの各方向のアームの最大長を計算できることが認識されています。 左方向と右方向については、行ごとにトラバースし、2 つの補助行列を連続した行列で満たします。`1`行の先頭または末尾から見られます。 上下については、列ごとに同じことを行います。 これらの行列が構築されると、任意のセルの最大クロスは、事前に計算された 4 つの値の最小値になります。 これにより、繰り返しのカウントが減り、アルゴリズムが単純かつ実装しやすくなります。また、この例では、グリッド サイズが固定されているため、前処理のオーバーヘッドは無視できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | n=21 で許容 |
 | 前処理 | O(n^2) | O(n^2) | 受け入れられ、きれいになった |

 ## アルゴリズムのチュートリアル

 1. グリッドを 21x21 の整数行列に読み取ります。 変換中`0`そして`1`文字を整数に変換すると、算術演算と比較が簡素化されます。 
2. サイズ 21x21 の 4 つの行列を初期化します。`up`、`down`、`left`、`right`。 各マトリックスには、連続する最大値が格納されます。`1`s は現在のセルからその方向に伸びています。 
3. を入力します。`left`各行を左から右に走査して行列を作成します。 各セルについて、`1`の場合、値は 1 に同じ行の前のセルの値を加えたものになります。 それ以外の場合、値は 0 です。これは連続した回数をカウントします。`1`s は現在のセルを含めて左にあります。 
4. 同様に、`right`各行を右から左に走査して行列を作成します。 
5. を入力します。`up`各列を上から下に走査し、連続した数をカウントすることで行列を作成します。`1`s.
 6. を入力します。`down`各列を下から上に走査してマトリックスを作成します。 
7. 各セルには中心が含まれるため、各セルのアームの長さの最大値は、4 つの方向の値の最小値から 1 を引いたものになります。 クロスの合計サイズを 1 + 4 * 腕の長さとして計算します。 
8. すべてのセルをスキャンしているときに見つかった最大クロス サイズを追跡します。 
9. 最大クロスサイズを出力します。 

機能する理由: 各補助行列は連続したものを正しくカウントします。`1`その方向にあります。 最小値を取ることで、アームが利用可能な連続時間を超えることがなくなります。`1`s. 「中心を含めた本数」を「アームの長さ」に換算し、1を引くと4倍して1を足すことでクロスの合計サイズとなります。 これにより、計算されたサイズが有効なクロスに正確に対応することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

grid = [list(map(int, input().strip())) for _ in range(21)]

n = 21

up = [[0]*n for _ in range(n)]
down = [[0]*n for _ in range(n)]
left = [[0]*n for _ in range(n)]
right = [[0]*n for _ in range(n)]

# Left and Right
for i in range(n):
    for j in range(n):
        if grid[i][j]:
            left[i][j] = left[i][j-1] + 1 if j > 0 else 1
    for j in range(n-1, -1, -1):
        if grid[i][j]:
            right[i][j] = right[i][j+1] + 1 if j < n-1 else 1

# Up and Down
for j in range(n):
    for i in range(n):
        if grid[i][j]:
            up[i][j] = up[i-1][j] + 1 if i > 0 else 1
    for i in range(n-1, -1, -1):
        if grid[i][j]:
            down[i][j] = down[i+1][j] + 1 if i < n-1 else 1

max_cross = 0
for i in range(n):
    for j in range(n):
        if grid[i][j]:
            arm = min(up[i][j], down[i][j], left[i][j], right[i][j])
            size = 1 + 4 * (arm - 1)
            max_cross = max(max_cross, size)

print(max_cross)
```このソリューションでは、まずグリッドを整数に変換します。 各方向は独立して処理され、連続した方向を計算します。`1`境界を慎重に扱います。 腕の長さを計算するときは、中心を除くために 1 を引いて、4 を掛けるとすべての腕が計算されます。 包括的なカウントを使用する場合、off-by-one エラーが発生しやすいため、この手順には細心の注意が必要です。
