 ## 解決策
 ## 問題の理解

 この問題では、指定された文字列が前後から同じように読めるかどうかを判断するよう求められます。これが回文の定義です。 複数のテスト ケースが与えられ、それぞれが 1 つの小文字の文字列で構成されます。 各文字列について、回文の場合は「YES」、そうでない場合は「NO」を出力する必要があります。 

制約により、テスト ケースの数は最大 100 で、文字列の最大長は 100 であることがわかります。これは、処理する必要がある合計文字数が最大 10,000 であり、少ないことを意味します。 長さ 100 の文字列内の各文字ペアをチェックするのに必要な比較は 50 回だけであるため、各文字列の長さに関して線形時間で実行されるソリューションは十分に高速です。 

注意が必要なエッジ ケースには、自明の回文である長さ 1 の文字列や、「ab」など、最初と最後の文字だけが異なる文字列が含まれます。 文字列の境界を正しく処理しない単純なアプローチでは、そのような文字列を誤って識別する可能性があります。 

## アプローチ

 最も簡単な方法は総当たり法です。文字列ごとに、最初の文字と最後の文字、2 番目の文字と最後から 2 番目の文字などを、文字列の中央に到達するまで比較します。 これらのペアがすべて一致する場合、文字列は回文です。 いずれかのペアが異なる場合、それは異なります。 このアプローチは、回文の定義を直接実装しているため、正しいです。 時間計算量は文字列あたり O(n) です (n は文字列の長さ)。 n ≤ 100 なので、これは効率的です。 

最悪の場合にはすべての文字を少なくとも 1 回検査する必要があるため、この問題に対してより高速な漸近解決策はありません。 重要な洞察は、文字列の途中までしかチェックする必要がないことを認識することです。 文字列全体を両方向でチェックしたり、比較のために反転したりすることは機能しますが、端から 2 つのポインターを使用する方がメモリ効率がわずかに高く、直接的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (2 点比較) | 文字列ごとに O(n) | お(1) | 承認済み |
 | 逆にして比較 | 文字列ごとに O(n) | O(n) | 承認済み |

 ここではどちらのアプローチも受け入れられます。 2 つのポインタの比較は余分なメモリを使用せず、若干クリーンです。 

## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 各テスト ケースを個別にループします。 
2. テスト ケースごとに、文字列を読み取ります。`s`そして 2 つのポインターを初期化します。`i`0 (開始) および`j`で`len(s)-1`（終わり）。 
3. その間`i < j`、 比較する`s[i]`そして`s[j]`。 等しい場合は増分します`i`そして減少します`j`。 これにより、ポインタが文字列の中心に向かって移動し、対称性がチェックされます。 
4. いつでも`s[i]`そして`s[j]`異なる場合、文字列を回文にすることはできません。 すぐに「NO」を出力し、それ以降の文字のチェックを停止します。 
5. 不一致の文字が見つからずにループが完了した場合、ミラー化されたペアはすべて等しいことになります。 「YES」を出力します。 

機能する理由: このアルゴリズムは、各反復でポインターの外側のすべての文字がチェックされ、対称であるという不変条件を維持します。 不一致が発生すると、回文の対称性が違反されます。 不一致が見つからない場合、文字列は回文の特性を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    i, j = 0, len(s) - 1
    is_palindrome = True
    while i < j:
        if s[i] != s[j]:
            is_palindrome = False
            break
        i += 1
        j -= 1
    print("YES" if is_palindrome else "NO")
```私たちが使用するのは`input().strip()`末尾の改行文字を削除します。 2 ポインターのアプローチにより、ミラーリングされた位置を効率的に比較できます。 の`is_palindrome`flag を使用すると、不一致の場合に早期に終了し、不必要な比較を回避できます。 これにより、ループ後の結果の出力も簡単になります。 

## 実用的な例

 文字列「radar」のトレース:

 | 私 | j | s[i] | s[j] | 回文 |
 | --- | --- | --- | --- | --- |
 | 0 | 4 | r | r | 本当 |
 | 1 | 3 | | | 本当 |
 | 2 | 2 | d | d | 本当 |

 すべての比較が一致するため、出力は「YES」になります。 

文字列「tle」のトレース:

 | 私 | j | s[i] | s[j] | 回文 |
 | --- | --- | --- | --- | --- |
 | 0 | 2 | t | e | 偽 |

 最初の比較で不一致。 出力は「NO」です。 

これらのトレースは、アルゴリズムが回文と非回文の両方を正しく識別していることを示しています。 2 ポインター手法は、対称性が侵害されるとすぐに停止するため、不必要な作業が節約されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | 文字列ごとに O(n) | 各文字は、2 ポインター スイープで最大 1 回比較されます。 |
 | スペース | お(1) | 文字列の長さに関係なく、少数の整変数とブール値フラグのみが使用されます。 |

 n ≤ 100 および t ≤ 100 の場合、操作の合計数は最大 10,000 であり、3 秒の制限内に十分収まります。 メモリ使用量が最小限に抑えられるため、このソリューションはすべての入力に対して効率的で安全です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        s = input().strip()
        i, j = 0, len(s) - 1
        is_palindrome = True
        while i < j:
            if s[i] != s[j]:
                is_palindrome = False
                break
            i += 1
            j -= 1
        output.append("YES" if is_palindrome else "NO")
    return "\n".join(output)

# provided samples
assert run("8\nac\ntle\nradar\nracecar\nphp\natcoder\ncodeforces\nsteam\n") == "NO\nNO\nYES\nYES\nNO\nNO\nYES\nYES", "sample 1"

# custom cases
assert run("3\na\nab\naba\n") == "YES\nNO\nYES", "single-character and small palindromes"
assert run("2\nzzzzzzzzzz\nabcdefghijk\n") == "YES\nNO", "all-equal and completely non-palindromic"
assert run("1\nx"*100 + "\n") == "YES", "maximum-length palindrome"
assert run("1\n" + "ab"*50 + "\n") == "NO", "maximum-length non-palindrome"
```| テスト入力 | 期待される出力 | 検証内容 |

 | ア、アブ、アバ | はい、いいえ、はい | 1 文字、2 文字の不一致、小さな回文 |
 | zzzzzzzzz、abcdefghijk | はい、いいえ | 均一な文字列、完全に非回文 |
 | x 繰り返し 100 | はい | 最大長の回文 |
 | ab を繰り返し 50 | いいえ | 最大長の非回文 |

 ## 特殊なケース

 「x」などの長さ 1 の文字列の場合、ポインタ`i`そして`j`0 から開始します。`i`未満ではありません`j`の場合、ループは実行されず、文字列は回文として正しく分類されます。 文字が異なる 2 文字の文字列の場合、ポインタは直ちに不一致を検出し、「NO」を出力します。 「aaaa」など、すべての文字が同一である文字列は、ミラー化された各ペアが一致するため、回文として正しく認識されます。 2 ポインターのアプローチでは、特別な分岐ロジックを使用せずに、偶数長と奇数長の両方の文字列を自然に処理します。
