 ## 解決策
 ## 問題の理解

 シリンダーには、`n`スロットは円形に配置されており、正確に`k`そのうちのいくつかには弾丸が含まれています。 ゲームの開始前に、シリンダーは均一にランダムに回転するため、すべての循環シフトは同じ確率で発生します。 

ローテーション後、サーシャが最初にシュートを放ちます。 現在のスロットが空の場合、シリンダーが 1 位置進み、Roma が射撃します。 最初に銃弾に遭遇したプレイヤーは即死します。 

タスクはゲームをシミュレートすることではありません。 代わりに、サーシャが死亡する可能性を最小限に抑える弾丸の配置を構築する必要があります。 すべての最適な配置の中で、辞書編集的に最小のものを出力する必要があります。`.`よりも小さいです`X`。 

入力では、文字列全体を直接出力するように要求されません。 以来`n`と同じ大きさにすることができます`10^18`、すべての位置を印刷することは不可能です。 代わりに、私たちは受け取ります`p`特定の位置について尋ねるクエリを実行し、クエリされたインデックスごとに、そのスロットに黒丸が含まれているかどうかを出力します。 

巨大な限界`n`問題の性質が完全に変わります。 に比例する任意のアルゴリズム`n`不可能です。 文字列全体を構築したり、ゲームをシミュレートしたり、すべてのポジションを一度に反復したりすることさえできません。 解決策は、算術公式とローカルな決定のみを使用して機能する必要があります。 

微妙な部分は、何がサーシャの負け確率を決定するのかを理解することです。 

ランダムなローテーションの後、あるスロットでゲームが開始されるとします。 

偶数の空スロットの後に最初の弾丸が出現した場合、サーシャは最終的にそれに直面して死亡します。 

奇数の空スロットの後に最初の弾丸が出現した場合、代わりにローマが死亡します。 

つまり、連続する空スロットの最大ブロックはすべて、そのパリティに応じて開始位置の勝ちまたは負けに寄与します。 

素朴な直観では、弾丸を均一に散布することが常に最適であると考えられます。 それだけでは十分ではありません。 辞書編集的に最小の最適な配置も必要です。 

たとえば:

 入力:```
5 2
```バランスの取れた配置は次のようになります。```
X..X.
```しかし：```
..X.X
```弾丸をできるだけ右に遅らせるため、辞書編集的に小さくなりながらも同じ確率が得られます。 

もう 1 つの簡単な間違いは、シリンダーが周期的であることを忘れることです。 

例えば：```
n = 6
k = 2
```アレンジメント:```
X...X.
```長さのギャップが 1 つ含まれます`3`そして長さの1つのギャップ`1`、2 つの別々の線形ギャップではありません。 最初と最後の位置は円内で隣接しています。 

ケース`k = 0`も重要です。 誰も死なないので、サーシャの損失確率は`0`。 有効な配置はすべてドットのみです。 

ケース`k = n`は対極です。 すべてのスロットに弾丸が含まれており、サーシャは確率で即死します`1`、そしてアレンジメントはすべてです`X`。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての配置を列挙します。`k`間の弾丸`n`スロット。 各配置について、すべてをチェックすることでサーシャが負ける確率を計算できます。`n`周期的な開始位置。 

がある`C(n, k)`手配、そしてそれぞれがかかります`O(n)`評価すること。 次のような中程度の値であっても、`n = 50`、これは天文学的な規模になります。 

重要な観察は、ゲームの結果は弾丸の間の空のセグメントの長さにのみ依存するということです。 

2 つの弾丸間の隙間に長さがあると仮定します。`g`。 

このギャップ内でゲームが開始される場合、プレイヤーは交互にギャップを通過します。 弾丸に到達するプレイヤーは、距離の同等性のみに依存します。 

長さの隙間の中に`g`:

 -`ceil(g / 2)`スタートポジションではサーシャは負けます。 
-`floor(g / 2)`先発ポジションのせいでローマは負ける。 

したがって、奇数の長さのギャップはすべて、サーシャの不利なポジションを 1 つ増やすことになります。 

これにより、問題は直ちに組み合わせ最適化問題に変わります。 

分割したいのですが、`n - k`空のスロットに`k`奇数ギャップの数が最小限になるように循環ギャップを調整します。 

もし`n - k`が均一であれば、すべての隙間を均等にすることができ、完璧なバランスが得られます。 

もし`n - k`が奇数である場合、少なくとも 1 つのギャップは奇数でなければなりません。 

したがって、奇数ギャップの可能な最小数は次のようになります。 

-`0`もし`n - k`均等です
 -`1`それ以外の場合

 奇数のギャップの数を最小限に抑えた後も、辞書編集的に最小の配置が必要です。 

辞書順に小さいということは、箇条書きをできるだけ右に遅らせることを意味します。 ギャップが弾丸の位置を決定するため、初期のギャップをできるだけ大きくする必要があります。 

すべての最適なソリューションの中から:

 - 1 つの奇数ギャップを除き、すべてのギャップは偶数である必要があります。 
- それ以前のギャップは貪欲に最大化する必要があります。 

これにより、完全な文字列を構築せずに、クエリされた各位置に独立して答えることができる建設的な算術ソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(k + p) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. しましょう`m = n - k`、空のスロットの数。 
2. 私たちはこれらを配布しなければなりません`m`空のスロットに`k`弾丸間の周期的なギャップ。 
3. サーシャが負ける可能性を最小限に抑えるには、奇数のギャップの数を最小限に抑えます。 

もし`m`が均等であれば、すべてのギャップを均等にすることができます。 

もし`m`が奇数の場合、ギャップは 1 つだけ奇数でなければなりません。 
4. 辞書編集的に最小の配置を取得するには、以前のギャップを最大化します。 

前のドットは前の箇条書きを延期するため、文字列が辞書編集的に小さくなります。 
5. 左から右へ貪欲にギャップを構築します。 

各ギャップはグローバル パリティ条件を維持する必要があります。 

- ほとんどのギャップは均等である必要があります。 
- 次の場合、奇数のギャップは最大 1 つまで許可されます。`m`奇数です。 
6. 残りのギャップに十分なスロットを確保しながら、現在のギャップにできるだけ多くの空のスロットを配置します。 
7. すべてのギャップを決定した後、概念的に弾丸の位置を再構築します。 

ポジションから始める`1`、 場所：

-`gap[0]`ドット、
 - 弾丸1発、
 -`gap[1]`ドット、
 - 弾丸1発、
 - などを周期的に繰り返します。 
8.以来`n`巨大になる可能性があるため、完全な文字列を構築しないでください。 

代わりに、箇条書きの位置をセットに保存し、クエリされたインデックスのみを応答します。 

### なぜ効果があるのか

 確率は、各空のギャップのパリティのみに依存します。 差が均等であれば、勝ち負けのスタート数も同じになります。 奇妙なギャップにより、サーシャはさらに 1 つの負けスタートに貢献します。 

空のスロットの総数には固定パリティがあるため、奇数ギャップの可能な最小数はパリティのみによって強制されます。 

最適なパリティ構造を修正した後、辞書編集上の順序は最も古い異なる位置によって決定されます。 初期のギャップを最大化すると、箇条書きが可能な限り右に遅延され、文字列が辞書編集的に最小限になります。 

残りのパリティ制約が維持される限り、初期のより大きなギャップを選択しても将来の実現可能性が損なわれることはないため、貪欲な構築は機能します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, p = map(int, input().split())

    queries = [int(input()) for _ in range(p)]

    if k == 0:
        ans = ['.'] * p
        print(''.join(ans))
        return

    if k == n:
        ans = ['X'] * p
        print(''.join(ans))
        return

    m = n - k

    gaps = []

    odd_needed = m % 2
    remain = m

    for i in range(k):
        left = k - i - 1

        # largest feasible gap
        g = remain - left

        # adjust parity
        if odd_needed == 0:
            if g % 2 == 1:
                g -= 1
        else:
            if g % 2 == 0:
                g -= 1

        gaps.append(g)

        remain -= g

        if g % 2 == 1:
            odd_needed = 0

    bullets = set()

    pos = 1

    for g in gaps:
        pos += g
        bullets.add(pos)
        pos += 1

    out = []

    for x in queries:
        if x in bullets:
            out.append('X')
        else:
            out.append('.')

    print(''.join(out))

solve()
```最初の特殊なケースのハンドル`k = 0`そして`k = n`。 これらにより、構成的ロジックの例外的なケースが回避され、無効な循環解釈も回避されます。 

変数`m`空のスロットの総数を保存します。 これらを次のように配布します。`k`ギャップ。 

貪欲なステップでは、実現可能な最大の電流ギャップが選択されます。 条件:```
g = remain - left
```残りのギャップごとに少なくとも 1 つのスロットを残すことを意味します。 

次にパリティを調整します。 それでも奇数ギャップが必要な場合は、現在のギャップは奇数である必要があります。 それ以外の場合は均等になるはずです。 

微妙な点は、パリティがちょうど 1 だけ変化し、後のギャップ用に十分なスペースがすでに確保されているため、1 ずつ減らすと常に実現可能性が保たれることです。 

再構築フェーズでは完全な文字列が作成されることはありません。 代わりに、箇条書きを含む位置のみを計算します。 しかないので、`k`弾丸、これは効率的です。 

クエリは 1 からインデックス付けされるため、位置は 1 からインデックス付けされます。

 ## 特殊なケース

 次のことを考慮してください。```
1 0 1
1
```弾はありません。 ゲームは決して終わらないので、サーシャの負け確率は`0`。 アルゴリズムは、構築フェーズに入らずに、すぐにすべてのドットを返します。 

ここで次のことを考えてみましょう。```
4 4 4
1
2
3
4
```すべてのスロットには弾丸が含まれています。 サーシャはいつも即死する。 アルゴリズムは再びこれを直接処理し、すべてを出力します。`X`。 

より微妙な周期的なケース:```
6 2
```不用意に線形解釈すると、次のように考えられるかもしれません。```

```隙間がある`3`そして`1`。

このアルゴリズムは周期的な順序で明示的にギャップを構築するため、このような間違いを犯すことはありません。 

ついに：```
7 2
```我々は持っています`m = 5`、これは奇妙です。 少なくとも 1 つのギャップは奇数でなければなりません。 

構築では以下を選択します。```

```与える：```

```奇数のギャップが 1 つだけあり、これが最適であり、最初の箇条書きが可能な限り右端に寄せられ、辞書編集上の最小性が保証されます。
