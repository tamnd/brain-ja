 ## 解決策
 ## 問題の理解

 テストには、順番に回答する必要があるいくつかの質問が含まれています。 各質問には複数の回答選択肢があり、そのうちの 1 つだけが正解です。 Vaganych は事前に正しい答えを知りませんが、間違いを犯した後、どの選択肢が間違っていたかを思い出します。 

間違った答えをクリックすると、テスト全体が最初にリセットされます。 続行するには、失敗した質問に到達するまで、既知の正解をすべて再度クリックする必要があります。 

すべての質問について、答えのバリエーションの数だけがわかります。 正しい答えが見つかる前に、すべての問題ができるだけうまく解決されないと仮定して、考えられる最悪のケースで必要なクリック数を計算する必要があります。 

入力は単なる配列です。`a[i]`質問に対する可能な回答の数です`i`。 出力は 1 つの整数、つまり最悪の場合のクリックの合計数です。 

制約は非常に小さいです。 質問は最大 100 個なので、線形アルゴリズムまたは二次アルゴリズムは完全に安全です。 それぞれの理由により、答え自体が大きくなる可能性があります。`a[i]`届くかもしれない`10^9`したがって、64 ビット整数を使用する必要があります。 Python はこれを自動的に処理します。 

難しいのは、何がクリックとしてカウントされるのかを理解することです。 テストがリセットされるたびに、以前に解決した問題に再度回答する必要があります。 不注意な実装では、現在の質問に対する試行のみがカウントされ、リセットによって繰り返される作業が忘れられることがよくあります。 

次の例を考えてみましょう。```
2
2 2
```正しい答えは、`5`。 

最初の質問では、最悪のケースは、間違った選択肢を 1 つ試してから、正しい選択肢を試すことです。 それには費用がかかります`2`クリックします。 

2 番目の質問については、最悪のケースは次のとおりです。 

1. 質問 2 に到達し、
 2. 間違った答えを 1 つクリックし、
 3. 質問 1 からやり直します。 
4. 質問 1 にもう一度正解します。 
5. 最後に質問 2 に正解します。 

それは追加します`3`さらにクリックすると、合計で`5`。 

もう 1 つの間違いが起こりやすいのは、選択肢が 1 つだけの質問です。```
3
1 1 1
```答えは`3`、 ない`0`。 選択肢が 1 つしかない場合でも、Vaganych はそれをクリックする必要があります。 

3 番目の微妙なケースは、質問に多数の回答がある場合に発生します。```
1
5
```答えは`5`。 

再訪する以前の質問がないため、リセットペナルティはありません。 Vaganych は単純に 4 つの間違った選択肢を試し、次に正しい選択肢を試します。 

## アプローチ

 プロセスについて考える最も直接的な方法は、ストーリーで説明されているとおりにすべてのクリックを正確にシミュレートすることです。 各質問について、正しいものが見つかるまで繰り返し答えを試します。 間違った試行を行うたびに問題 1 に戻されるため、すでに解かれた問題をすべてもう一度やり直すことになります。 

この総当りシミュレーションは実際にここで実行可能です。`n ≤ 100`。 すべての質問に多くの回答がある場合でも、シミュレートされたアクションの総数は、指定された制限内で管理可能なままになります。 ロジックはステートメントを直接反映しているため、検証も簡単です。 

1 つの質問に対して何が起こるかに注目すると、問題ははるかに単純になります。 

現在問題を解決しているとします。`i`、0 から始まるインデックスを使用します。 以前の質問`0...i-1`はすでに知られています。 最悪の場合、ヴァガニッチは試みる`a[i] - 1`最終的に正しいものを選択する前に、間違った答えを選択します。 

間違った試みにはそれぞれ次のコストがかかります。 

1. 間違った答えを 1 回クリックします。 
2. その後、すべてを再生します`i`以前に解決した質問を返すことができます。 

したがって、あらゆる間違った試みが影響を及ぼします`i + 1`クリックします。 

すべての間違った試行の後、最終的な正解を得るにはさらに 1 回クリックする必要があります。 

それは次のようになります:$$(a_i - 1)(i + 1) + 1$$これを展開すると次のようになります。$$(a_i - 1)i + a_i$$すべての質問についてこれを合計すると、合計の答えが得られます。 

最悪の場合の推測を仮定すると、プロセスが決定的になるため、ブルートフォース シミュレーションが機能します。 質問に対するすべての間違った答えは、`i`強制的に正確に再生する`i`前の質問では、シミュレーションを直接式に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(合計(aᵢ)) | お(1) | 巨大にしては遅すぎる`aᵢ`|
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 問題数を読む`n`そして配列`a`。 
2.初期化`answer = 0`。 
3. すべての質問インデックスを反復処理します。`i`。 
4. ご質問について`i`、最悪の場合に必要なクリック数を計算します。 

質問には、`a[i] - 1`正しい答えが見つかる前に、間違った答えが見つかります。 
5. 間違った試みには必ずコストがかかる`i + 1`クリックします。 

間違った答え自体に 1 回のクリックが費やされ、`i`リセット後に以前の正しい質問を再生するには、後でさらにクリックする必要があります。 
6.追加`(a[i] - 1) * (i + 1)`答えに。 
7. この質問の最終的な正解を得るには、もう 1 回クリックします。 
8. すべての質問を処理した後、合計を印刷します。 

### なぜ効果があるのか

 疑問を解くとき`i`、 最初`i`質問はすでに既知であるため、試行が失敗するたびに再実行する必要があります。 最悪の場合は常に、正しい選択肢の前に間違った選択肢をすべて試すことを意味します。 

それぞれの間違ったオプションは、正確に 1 回のクリック失敗と正確に影響します。`i`後でクリックをリプレイします。 これらのコストは試行間で独立しているため、直接合計できます。 

最終的な正解はリセットをトリガーしないため、クリックは 1 回だけです。 

以前の質問が修正されると、すべての質問は独立して動作するため、各質問の寄与を合計すると、正確な合計クリック数が算出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

answer = 0

for i in range(n):
    answer += (a[i] - 1) * (i + 1)
    answer += 1

print(answer)
```実装は、ウォークスルーで導出された式に従います。 

ループインデックス`i`は、失敗後に再実行する必要がある以前の質問の数を表します。 Python は 0 から始まるインデックスを使用するため、正確に`i`質問の前の以前の質問`i`。 

表現:```
(a[i] - 1) * (i + 1)
```現在の質問に対する失敗した試行をすべてカウントします。 の`+1`内部の乗算は間違いやすいです。 これには、間違った答え自体をクリックすることも含まれます。 

すべて失敗した後、最終的な正解を得るにはさらに 1 回クリックする必要があります。```
answer += 1
```Python の整数は任意の大きな値を自動的にサポートするため、答えが大きくなってもオーバーフローの危険はありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    ans = 0

    for i in range(n):
        ans += (a[i] - 1) * (i + 1)
        ans += 1

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("2\n1 1\n") == "2\n", "sample 1"

# custom cases
assert run("1\n5\n") == "5\n", "single question"
assert run("2\n2 2\n") == "5\n", "reset behavior"
assert run("3\n1 1 1\n") == "3\n", "all single-choice"
assert run("3\n3 2 4\n") == "12\n", "mixed values"

# maximum-style boundary case
assert run("100\n" + "1000000000 " * 100 + "\n") != "", "large values"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`3 / 1 1 1`|`3`| 誤答のない問題 |

 ## 特殊なケース

 可能な最小の入力を考えてみましょう。```
1
1
```アルゴリズムは以下を計算します。$$(1 - 1)(0 + 1) + 1 = 1$$間違った試行はありませんが、唯一の答えを選択するには 1 回のクリックが必要です。 出力は正しく行われています`1`。 

ここで、リセットが非常に重要となるケースを考えてみましょう。```
2
2 2
```最初の質問について:

 - 1 回の間違ったクリック、
 - 1 回の正しいクリック。 

これまでの合計:`2`。 

2 番目の質問については、次のようになります。 

- 質問 2 で 1 回間違ってクリックした場合、
 - リセット、
 - 質問 1 をもう一度やり直す、
 - 質問 2 を 1 回正解します。 

それは貢献します`3`。 

アルゴリズムは以下を計算します。$$(2-1)(1)+1 = 2$$質問1については、$$(2-1)(2)+1 = 3$$質問 2 については、`5`。 

最後に、より大きな再生チェーンを考えてみましょう。```
3
1 2 2
```質問 1 が貢献します`1`。 

質問 2 は次のことに貢献します。$$(2-1)(2)+1 = 3$$質問 3 は次のことに貢献します。$$(2-1)(3)+1 = 4$$合計：$$1 + 3 + 4 = 8$$重要な点は、質問 3 で間違った回答をすると、前の質問を両方とも再実行する必要があるということです。 数式は、係数を通じてこれを自動的に処理します。`(i + 1)`。
