 ## 解決策
 ## 問題の理解

 各テスト ケースは、泉への 3 人の定期的な訪問者を記述します。 アリスは毎日到着します$a$毎日、ボブ$b$毎日、そしてキャロルは毎日$c$日々。 日からの範囲内の任意の日$1$今日$m$、日番号の割り切りに応じて、それらの一部が到着する可能性があります。 

この泉は、訪れる人の数に応じて、1 日あたり一定量の水を分配します。 ちょうど 1 人が訪問した場合、その人は 6 リットルを受け取ります。 2名様でご来店の場合はお一人様3リットルとなります。 3人全員が訪問した場合、それぞれ2リットルを受け取ります。 したがって、毎日、合計 6 リットルが常にその場にいる訪問者に完全に分配されます。 

私たちは、各人ごとに、1 日を通して蓄積される合計リットル数を計算する必要があります。$m$。 

直接解釈すると、$m$そして割り切れる可能性をチェックする$a$、$b$、 そして$c$。 しかし、$m$と同じ大きさにすることができます$10^{17}$したがって、毎日処理するソリューションは不可能です。 平$10^4$テストケースでは、これは完全に不可能になります。 

2 番目の単純なアイデアは、各期間の倍数のみを独立して考慮し、重複を調整しようとすることです。 個々の日について包含-除外を試みると、依然として問題が発生します。これは、単に訪問数をカウントしているのではなく、3 つの等差数列すべての交差構造に依存する重み付けされた寄与をカウントしているためです。 

単純な考え方を打ち破るエッジ ケースには、3 つの期間がすべて等しい、ペアごとの重複が優勢である、および 1 つの期間が 1 であるシナリオが含まれます。$a = b = c = 1$とすると、毎日 3 人全員が訪問し、それぞれが常に 2 リットルを受け取ります。したがって、答えは単純です。$2m$人それぞれに。 単純な 1 日あたりのシミュレーションは依然として必要です。$m$、規模的には不可能です。 別の例は$a = 1, b = 2, c = 3$ここで、ボブとキャロルの貢献はアリスが常に存在することに大きく依存しており、重複が正確に処理されない限り独立したカウントが不正確になります。 

## アプローチ

 重要な観察は、各人の合計貢献度は、各人が出演した日を合計することによって個別に計算できますが、同じ日に出演した人の数によって重み付けされることです。 

アリスを直してください。 特定の日に$d$、アリスは次のように寄稿しています。 

- 6 アリスだけが訪問する場合、
 - 3 アリスともう 1 人が訪問した場合、
 - 3 人全員が訪問した場合は 2。 

ケースごとに考えるよりも、次の日に割り切れる日に他に誰が出演するかに基づいてアリスの貢献を分割するという観点から考える方がより安定します。$a$。 

以下を定義しましょう:

 -$A$: で割り切れる日数$a$-$B$: で割り切れる日数$b$-$C$: で割り切れる日数$c$アリスにとって、私たちが気にしているのは日数だけです$A$。 その日は、その日が次の数で割り切れるかどうかに応じて、ボブも出席する場合といない場合があります。$b$、キャロルについても同様です。 

アリスの訪問日を 3 つの独立したグループに分類します。 

1. 日数$A$しかし、中にはありません$B$または$C$: アリスは一人で、6 を獲得します。 
2. 日数$A$正確に次のうちの 1 つがどこにあるのか$B, C$成立: アリスは 3 を取得します。 
3. 日数$A \cap B \cap C$: アリスは 2 を獲得します。 

これにより、問題は等差数列の交差を数えるという問題に縮小されます。これは、整数の除算による標準的なものです。 

-$|A| = \lfloor m/a \rfloor$-$|A \cap B| = \lfloor m/\mathrm{lcm}(a,b) \rfloor$、他のペアについても同様に
 -$|A \cap B \cap C| = \lfloor m/\mathrm{lcm}(a,b,c) \rfloor$アリスの場合、次のように計算します。 

- A のみ:$|A| - |A \cap B| - |A \cap C| + |A \cap B \cap C|$- A と B のみ:$|A \cap B| - |A \cap B \cap C|$- A と C のみ:$|A \cap C| - |A \cap B \cap C|$- 3 つすべて:$|A \cap B \cap C|$次に、それぞれ 6、3、または 2 を掛けて合計します。 

ボブとキャロルに対して対称的に繰り返します。 

ブルートフォースアプローチは、次の時間まで一日中繰り返すことです。$m$3 つの数値のそれぞれで割り切れるかどうかを確認し、コストを計算します。$O(m)$テストケースごとに、最大で$10^{17}$最悪の場合の運用。 最適化されたアプローチでは、gcd/lcm 計算を使用したテスト ケースごとの定数時間演算にすべてが削減されます。

 ## アルゴリズムのチュートリアル

 1. 計算するヘルパー関数を事前計算する$\gcd$そしてそこから導き出される$\mathrm{lcm}(x,y) = x / \gcd(x,y) \cdot y$。 これは、定期的な訪問の重複を正確にカウントするために必要です。 
2. テスト ケースごとに、次を計算します。$|A|, |B|, |C|$として$m // a, m // b, m // c$。 

これらは、各人が独立して訪問した回数を表します。 
3. ペアごとの交差数を計算します。$|AB| = m // \mathrm{lcm}(a,b)$、$|AC|$、 そして$|BC|$。 

これらは、正確に 2 人が出会った日をカウントしますが、それでも 3 つの交差点が含まれます。 
4. 三重交差を計算します。$|ABC| = m // \mathrm{lcm}(a,b,c)$。 

これにより、3 つすべてが同時に出現する日が分離されます。 
5. これらの生のカウントを互いに素な領域に変換します。 アリスの場合:

 オンリーアリスの日々は$|A| - |AB| - |AC| + |ABC|$。 

この修正により、トリプルのオーバーラップが一度復元されながら、ペアごとの交差からオーバーカウントが削除されます。 
6. アリスの合計を次のように計算します。$6 \cdot \text{onlyA} + 3 \cdot (\text{AB only} + \text{AC only}) + 2 \cdot \text{ABC}$。 
7. ボブとキャロルに対して、役割を交換して対称的に同じ構造を繰り返します。 

### なぜ効果があるのか

 毎日、アリスの参加には 4 つの構造タイプのうちの 1 つが含まれます。単独で参加するか、他の 1 人とペアになるか、または 3 つすべてが一緒に参加します。 包含/排他分解により、毎日の$A$は、これらの互いに素なカテゴリのいずれかに分類されます。 すべてのカテゴリは問題の支払いルールに従って正確に重み付けされるため、貢献度の合計は真の合計と等しくなります。 建設では交差カウントを使用して重複を体系的に削除するため、二重にカウントされる日はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd

def lcm(x, y):
    return x // gcd(x, y) * y

def solve_case(a, b, c, m):
    ab = lcm(a, b)
    ac = lcm(a, c)
    bc = lcm(b, c)
    abc = lcm(ab, c)

    def calc(x, y, z, xy, xz, yz, xyz):
        X = m // x
        XY = m // xy
        XZ = m // xz
        XYZ = m // xyz

        only = X - XY - XZ + XYZ
        xy_only = XY - XYZ
        xz_only = XZ - XYZ
        all3 = XYZ

        return 6 * only + 3 * (xy_only + xz_only) + 2 * all3

    A = calc(a, b, c, ab, ac, bc, abc)
    B = calc(b, a, c, ab, bc, ac, abc)
    C = calc(c, a, b, ac, bc, ab, abc)

    return A, B, C

def main():
    t = int(input())
    out = []
    for _ in range(t):
        a, b, c, m = map(int, input().split())
        ares, bres, cres = solve_case(a, b, c, m)
        out.append(f"{ares} {bres} {cres}")
    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装の中核となるのは、`calc`1 人の人物を基本セットとして解釈する関数$X$また、事前に計算された交差サイズを使用して、訪問日を互いに素なカテゴリに分割します。 アリス、ボブ、キャロルの間の対称性は、引数を並べ替えて同じ関数を呼び出すことで処理されます。 

微妙な点は、lcm 計算の順序です。 コンピューティング$lcm(a,b,c)$として$lcm(lcm(a,b),c)$オーバーフローを回避し、正確性を保証します。 すべての除算は整数のフロア除算を使用します。これは、すべてのカウントが正確な倍数であるため安全です。

 ## 特殊なケース

 3 つの期間がすべて等しい場合、毎日が三重交差点になります。 アルゴリズムは計算します$|ABC| = m/a$、および他のすべてのカテゴリは包含と除外の後に消え、各人に正確な情報が残ります。$2m/a$。 のために$a=b=c=1$、これは次のようになります$2m$、1 日あたりの予想される定数の割り当てと一致します。 

1つの期間が1の場合、その人物は毎日現れ、すべての交差点を支配します。 他の期間の倍数ごとが交差セット内で自動的にカウントされ、包含/除外により、正しい区分がのみ、ペアごとのみ、およびトリプルのみのカテゴリに分離されるため、分解によって毎日が正しく割り当てられます。 

期間がペアごとに互いに素である場合、三重の 1 を除くすべての交差項は 0 になります。 このアルゴリズムは単純な独立した計数に還元され、各人の合計は重複補正なしの等差数列上の単純な合計になります。
