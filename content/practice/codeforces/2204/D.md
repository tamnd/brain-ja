 ## 解決策
 ## 問題の理解

 無向グラフが与えられ、いくつかの頂点が「美しく」なるように各エッジに方向を割り当てるように求められます。 頂点を起点として、元のグラフ内のすべてのパスがエッジに沿って交互に方向を変えている場合、頂点は美しいと言えます。つまり、最初のエッジは外に出なければならず、次のエッジは入って、次のエッジは出ていく必要があります。 美しい頂点の数を最大化したいと考えています。 

言い換えれば、この問題は、できるだけ多くの頂点から開始して、すべての走査でエッジに沿って正確な out-in-out-in パターンが見られるように、エッジの方向を設定する方法を見つけることを求めています。 パスは頂点とエッジを繰り返すことができます。 

入力グラフには、すべてのテスト ケースにわたって合計で最大 200,000 個の頂点と 200,000 個のエッジを含めることができます。 つまり、テスト ケースあたり O(n + m) よりも悪いものは許容されません。 グラフのサイズに応じてパスの数が指数関数的に増加する可能性があるため、すべてのパスまたはサイクルにわたるネストされたループは実行できません。 

重要な点は、奇数の長さのサイクルが接続されている頂点は美しくないことです。 たとえば、三角形 (3 サイクル) を考えてみましょう。 任意の頂点から開始してパスをたどってエッジをどのように配向しても、ある時点で 2 つの連続するエッジがパスに沿って同じ方向を向くことになります。 エッジを恣意的に方向付ける単純なアプローチでは、そのようなサイクル上の頂点を誤って美しいものとして数えてしまう可能性があります。 

もう 1 つのエッジ ケースは、エッジのないグラフです。 交互条件に違反するパスがないため、すべての孤立した頂点は非常に美しいです。 グラフが 2 部構成の場合、1 つのパーティション内のすべての頂点が出力エッジで始まり、もう 1 つのパーティションのすべての頂点が入力エッジで始まるようにエッジの方向を設定する一貫した方法が存在します。 

## アプローチ

 ブルートフォースアプローチでは、エッジを方向付けるために可能な 2^m の方法をすべて試みます。 方向ごとに、すべての頂点からのすべてのパスをシミュレートし、それらが交互になるかどうかを確認できます。 これは理論的には正しいですが、明らかに不可能です。m = 20 の場合でも 100 万を超える構成があり、m = 200,000 の場合は不合理です。 

重要な洞察は、頂点が美しくない原因を理解することから得られます。 頂点から到達可能な奇数長のサイクルがある場合、頂点は失敗します。これは、奇数長のサイクルに沿って交互の方向を一貫させることができないためです。 これは、2 部グラフへの関連性を直ちに示唆します。グラフは、奇数のサイクルがない場合に限り、2 部グラフになります。 2 部グラフでは、頂点を 2 つのセットに分割し、一方のセットからもう一方のセットへエッジの向きを一貫して設定できます。 「out-in-out-in」の要件を満たす方向を選択すると、1 つのセット内のすべての頂点を美しくすることができます。 

したがって、問題はグラフの 2 つの部分を識別することに帰着します。 グラフの各連結成分は 2 部であるか、そうでないかのいずれかです。 二部構成であれば、すべての頂点を美しくすることができます。 奇数のサイクルが含まれている場合、より大きなパーティション内の頂点のみを安全に美しくすることができます。 実際、任意のグラフの場合、BFS または DFS を使用して 2 色で色付けするだけで十分です。 各頂点の色によって、最初のエッジが外側に出るか内側に出るかが決まります。同じ色の頂点間のエッジは、非 2 部コンポーネントを示します。 最悪の場合、そのようなエッジから 1 つの頂点だけが美しいものになる可能性があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m * f(n,m)) | O(n + m) | 遅すぎる |
 | 二部構成のカラーリング | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、頂点の数を読み取ります。`n`そしてエッジ`m`。 グラフの隣接リストを初期化します。 
2. を読んで隣接リストを設定します。`m`エッジ。 各エッジは双方向に保存されます。 
3. サイズのカラー配列を初期化します。`n`-1まで。 これにより、2 部カラーリングの場合は 0 または 1 が保存されます。 
4. 色付けされていない頂点ごとに、BFS を開始します。 カラー 0 を割り当てます。 
5. BFS 中に、各頂点に対して`v`そしてそれぞれの隣人`u`、 もし`u`色付けされていない、割り当てます`u`の反対の色`v`。 追加`u`行列に。 もし`u`すでに同じ色をしています`v`、コンポーネントを非 2 部構成としてマークします。 
6. 各コンポーネントについて、それが 2 部構成であれば、そのコンポーネント内のすべての頂点を美しくすることができます。 奇数のサイクルが含まれている場合、そのコンポーネントの最大の美しい頂点は、2 つのカラー クラスの大きいサイズになります。 
7. すべてのコンポーネントから最大の美しい頂点を合計します。 合計を出力します。 

機能する理由: グラフに色を付けると、隣接する 2 つの頂点が同じ色になることがなくなります。 2 部コンポーネントでは、パスは色間で交互に切り替わります。これは、交互のエッジ方向に対応します。 BFS は、カラーリングの一貫性を保証します。 奇数サイクルは完全な交替を防ぎ、より大きなカラー クラスを選択することで、到達可能なパス上の交替に違反することなく美しい頂点の数を最大化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        adj = [[] for _ in range(n)]
        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            adj[v].append(u)

        color = [-1] * n
        visited = [False] * n
        max_beautiful = 0

        for i in range(n):
            if not visited[i]:
                queue = deque()
                queue.append(i)
                color[i] = 0
                count = [1, 0]
                bipartite = True
                visited[i] = True

                while queue:
                    v = queue.popleft()
                    for u in adj[v]:
                        if color[u] == -1:
                            color[u] = 1 - color[v]
                            count[color[u]] += 1
                            queue.append(u)
                            visited[u] = True
                        elif color[u] == color[v]:
                            bipartite = False

                if bipartite:
                    max_beautiful += count[0] + count[1]
                else:
                    max_beautiful += max(count)

        print(max_beautiful)

if __name__ == "__main__":
    solve()
```このソリューションは、BFS を使用して入力を読み取り、隣接リストを構築し、グラフに色を付けます。 の`color`配列は 2 色のパーティションを追跡しますが、`visited`ノードを再度訪問する必要がなくなります。 各連結コンポーネントは個別に評価されます。 2 部コンポーネントと非 2 部コンポーネントを処理するロジックは明確に分離されています。 エッジ インデックスは、Python のゼロベースのインデックスに調整されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各頂点は 1 回訪問され、各エッジは 2 回考慮されます。 
| スペース | O(n + m) | 隣接リストと色および訪問済み配列 |

 BFS は頂点とエッジに対して線形にスケールするため、n + m ≤ 2×10^5 の場合、この解は 2 秒以内に簡単に適合します。 隣接リストのストレージが O(m) で補助配列が O(n) であるため、メモリ使用量も 512 MB 以内です。
