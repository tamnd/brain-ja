 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、非常に具体的な削除プロセスをシミュレートするように求められます。 各操作では、現在の配列を調べて最大要素を見つけ、複数の要素がその最大値を共有する場合は、右端の要素を選択します。 次に、その要素とその後にあるすべてのものを削除します。 質問は、配列を完全に空にするためにそのような操作が何回必要になるかを尋ねます。 

入力は複数のテスト ケースを提供します。 各テスト ケースでは、配列の長さが指定され、その後に配列そのものが続きます。 この制約により、配列サイズは最大 200,000、テスト ケースは最大 10,000 個まで可能ですが、テスト ケース全体のすべての配列サイズの合計は 200,000 を超えないことがわかります。 これは、テスト ケースごとに O(n) より悪いアルゴリズムは遅すぎるため、配列サイズがほぼ線形の解が必要であることを示しています。 

素朴な解決策を壊す可能性のあるエッジ ケースには、厳密に増加している配列、厳密に減少している配列、または複数の最大要素が出現する配列が含まれます。 たとえば、配列`[3, 3, 3]`右端の最大値が最後の要素であるため、1 回の操作で配列全体が削除されます。 常に最初の最大値を選択する単純な実装では、複数の操作が誤ってシミュレートされます。 

## アプローチ

 ブルートフォース手法では文字通りプロセスをシミュレートします。各ステップで配列をスキャンして右端の最大値を見つけ、その位置から最後まですべての要素を削除し、これを繰り返します。 これは正しいですが、最大値を見つけるには毎回 O(n) かかり、最悪の場合は O(n) 回の操作を実行する可能性があります。 その結果、テスト ケースあたりの時間は O(n^2) となり、n = 200,000 では遅すぎます。 

最適な解決策の重要な観察は、演算の数が、右から左に最大の要素を削除するときに配列が左にどれだけ伸びるかに対応するということです。 具体的には、配列を右から左にトラバースして、これまでに確認された最大値を追跡すると、現在の要素がこの現在の最大値と等しくなるたびに、何らかの操作でその要素が選択されることがわかります。 除去をシミュレートする代わりに、最大値が左側の境界を「拡張」するセグメントをカウントするだけで済みます。 この洞察により、問題は、少数の整変数を使用した 1 回の逆走査 (O(n) 時間) に短縮されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列の末尾から開始して、操作用のカウンター、サフィックスの現在の最大値を追跡する変数、および次の削除によって影響を受ける左端のインデックスを示す境界マーカーを初期化します。 
2. 配列を逆方向に反復処理します。 これまでに確認された現在の最大値を更新します。 
3. インデックスが現在の削除セグメントの左端の境界と一致するたびに、操作カウンタをインクリメントし、セグメントを拡張する次の最大値の位置に境界を移動します。 これは、左の最大値が最終的に次の操作の新しい右端の最大値になるため機能します。 
4. 配列の先頭に到達するまで続行します。 
5. オペレーションカウンタを返します。 

機能する理由: 右から左に移動すると、各最大値の最後に発生したものが最初に考慮されるようになります。 削除されるセグメントの左側の境界に到達するたびに、1 つの操作が発生したことがわかります。 セグメントは以前の最大値より大きい要素によってのみ拡張されるため、各要素は最大 1 回考慮され、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ops = 0
        right = n
        current_max = 0
        
        # traverse from right to left
        i = n - 1
        while i >= 0:
            current_max = max(current_max, a[i])
            if i == right - current_max:  # left boundary of next removal segment
                ops += 1
                right = i
                current_max = 0
            i -= 1
        print(ops)

if __name__ == "__main__":
    solve()
```このソリューションは高速 I/O を使用し、各テスト ケースを個別に反復します。 右端の要素から左へトラバースして更新します。`current_max`現在のサフィックスの最大要素を反映します。 現在のインデックスが最大値で定義されたセグメントの左境界と一致する場合、操作をカウントし、次の操作のために境界をリセットします。 境界を慎重に処理することで、一般的なオフバイワンエラーである、重複するセグメントが二重にカウントされないようにすることができます。

 この表は、インデックス 3 で 3 を選択した後、右端のセグメントが削除され、残りの操作を正しくカウントし続けていることを示しています。

 ## 特殊なケース

 アレイの場合`[3, 3, 3]`、アルゴリズムは最後の要素から開始し、インデックス 2 で右端の最大値を特定し、それとその後のすべての要素 (この場合はなし) を削除し、1 つの操作をカウントします。 左側の境界が更新され、トラバースが続行されますが、それ以上の操作は必要ありません。 出力は正しく行われています`1`。 

のために`[5, 4, 3, 2, 1]`、考慮される最後の要素は 1 ですが、右端の最大値はインデックス 0 の 5 です。インデックス 0 以降のすべての要素は 1 回の操作で削除されます。 最大値は左の境界を拡張して配列全体をカバーするため、アルゴリズムは 1 つの操作を正しくカウントします。
