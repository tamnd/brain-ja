 ## 解決策
 ## 問題の理解

 私たちには、左から右に配置された生徒の列と、一定のルールに従って決定的に動くボールが与えられます。 各生徒には左または右の方向があり、ボールがその生徒に到達すると、すぐにその方向にある隣の生徒にボールが渡されます。 エンドポイントは強制されます。最初の生徒は常に右に通過し、最後の生徒は常に左に通過します。 

このプロセスは、生徒 1 がボールを持っているところから始まります。 そうすればボールは正確にパスされる$n$回。 これらのパス中に、ボールが同じ生徒に何度も訪れる可能性がありますが、私たちが考慮するのは、どの生徒が少なくとも 1 回ボールを保持したことがあるかだけです。 

したがって、問題は、各ノードが近隣ノードへの発信エッジを 1 つだけ持つ折れ線グラフ上の決定論的ウォークをシミュレートすることに帰着し、ノード 1 から始まる固定数のステップ中に訪問される個別のノードの数をカウントします。 

制約は十分小さいため、直接シミュレーションは完全に安全です。 と$t \le 10^4$そして$n \le 50$、 平$O(n^2)$テスト ケースあたりの結果は最大で$2.5 \cdot 10^7$これは Python の制限内に十分収まります。 

動きは常に定義されているため、無効な動きに関してトリッキーな隠れエッジのケースはありません。 唯一の微妙な点は、ステップ数が正確であることです。$n$、安定するまで、または境界から出るまでは行われません。 パスが振動してノードを何度も再訪問する可能性があるため、これは重要です。 

単純な間違いは、歩行が単調なセグメントを形成している、または常に最初に右に移動し、その後 1 回左に移動すると仮定することです。 たとえば、`RLRL`、ボールは 1 と 2 の間を無限にバウンドします。 間違った貪欲な解釈は、ウォークが連続的に拡大すると誤って想定する可能性がありますが、実際はそうではありません。 

もう 1 つの潜在的な間違いは、パスが発生する前に最初にボールを受け取ることが問題で明示的に示されているため、開始ノード (生徒 1) を数え忘れることです。 

## アプローチ

 説明したプロセスはすでに完全に決定的であるため、最も簡単なアプローチはそれを段階的にシミュレートすることです。 ボールの現在の位置を維持し、各パスの後に現在のスチューデントに保存されている方向に従って位置を更新します。 また、どの学生がすでにボールを受け取ったかを示すブール配列またはセットも保持します。 

正確に実行した後$n$遷移時に、訪問済みとしてマークされた学生の数をカウントします。 

これが機能するのは、各状態遷移が次のとおりであるためです。$O(1)$、そして私たちはただそうするだけです$n$テストケースごとに遷移するため、全体の複雑さは線形になります。$n$。 

ここでは総当たりシミュレーションがすでに最適です。 サイクル検出やグラフ圧縮は必要ありません。$n$は最大でも 50 であるため、多くのテスト ケースにわたって再計算を繰り返しても簡単です。

 ## アルゴリズムのチュートリアル

 1. ボールを位置 1 に置き、生徒 1 を訪問者としてマークします。 これは、移動が行われる前の初期状態を反映しています。 
2. 正確に繰り返します$n$回：現在の生徒の方向を見て、ボールを左または右に動かします。 各移動は、現在のノードからの一意の出力エッジをたどることに対応します。 
3. 移動するたびに、新しい位置を訪問済みとしてマークします。 これにより、セグメントのエンドポイントだけでなく、ボールを受け取ったすべてのノードが確実にキャプチャされます。 
4. すべての移動が完了したら、訪問済みとしてマークされた生徒の数を数え、その数を出力します。 

### なぜ効果があるのか

 いつでも、ボールの位置は、前の位置とそのノードでの固定方向によって完全に決定されます。これは、このプロセスが、各ノードの出次数が正確に 1 である有向グラフ上の決定論的な歩行であることを意味します。すべての遷移を明示的にシミュレートしているため、この歩行の正確な軌道を正確に複製します。$n$ステップ。 カウントされるすべての学生は、軌跡が少なくとも 1 回入った学生です。すべての訪問は発生するとすぐに処理されるため、見逃される学生はいません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input().strip())
        s = input().strip()

        # 0-indexed positions
        pos = 0
        visited = [False] * n
        visited[pos] = True

        for _ in range(n):
            if s[pos] == 'R':
                pos += 1
            else:
                pos -= 1
            visited[pos] = True

        out.append(str(sum(visited)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、アルゴリズムで説明されているシミュレーションを直接反映しています。 配列`visited`各生徒がボールを受け取ったかどうかを追跡します。 生徒 1 がボールから始めるため、位置 0 を初期化します。 各反復では、文字列内の現在の文字に従って位置が更新されます。 

微妙な点は、移動が常に安全であるということです。この問題では、最初の文字が確実に移動します。`R`そして最後は`L`, したがって、範囲を超えることはありません。

 ## 特殊なケース

 重要なエッジケースは、純粋な振動動作です。 のような入力の場合`RLRL`、ウォークは最初の 2 つのノードを超えて広がることはありません。 シミュレーションはノード 1 から開始し、ノード 2 に移動し、すぐにノード 1 に戻り、繰り返します。 各ステップで訪問を明示的にマークするため、ノード 1 と 2 の両方がカウントされ、誤った展開は発生しません。 

もう1つのケースは、次のような完全な単調な動きです。`RRRRRL`。 ここでは、ボールは端に到達するまで右に移動し、すべてのノードを訪れてから、一度戻ります。 シミュレーションでは、エンドポイントだけではなくすべての移動後にマークを付けるため、戻る前にノード 6 もカウントされることが保証されます。 

最後の微妙なケースは、次のような最小限の入力です。`n = 2`。 プロセスはノード 1 から開始して正確に 2 つの移動を実行します。シミュレーションはこれを自然に処理します。最初の移動はノード 2 に到達し、2 番目の移動はノード 1 に戻り、結果として両方のノードが訪問されます。
