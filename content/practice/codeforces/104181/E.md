 ## 問題の理解

 私たちに与えられているのは、$n \times n$各セルがその行によって決定されるグリッド$i$そしてコラム$j$。 そのセルの値は整数除算の結果です$\left\lfloor \frac{j}{i} \right\rfloor$。 つまり、各行$i$すべての列インデックスを次の値で割ることによって形成されます。$i$、切り捨て。 

タスクはグリッドを構築することではなく、指定された値が含まれるセルの数を数えるということです。$k$。 

したがって、テーブルを埋める代わりに、事実上次のことが求められます: すべてのペアについて$(i, j)$と$1 \le i, j \le n$、何人が満足しますか$$\left\lfloor \frac{j}{i} \right\rfloor = k.$$制約$n \le 100000$すべてを直接列挙することは直ちに除外されます。$n^2$細胞。 完全なグリッド評価には、最大で次のものが必要になります。$10^{10}$これは実行可能な制限時間をはるかに超えています。 

行ごとに考えると、さらに微妙な問題が現れます。 列を直しても$i$、すべての列をスキャンします$j$は依然として行ごとに線形であり、再び次のようになります。$O(n^2)$。 

エッジ ケースは、境界付近の床分割の動作から生じます。 

いつ$k = 0$、ペアを数えています。$j < i$。 たとえば、$n = 4$、 行$i = 3$貢献する$j = 1,2$、どちらもゼロを与えるためです。 を前提とした素朴な実装$j / i \ge 1$いつもこの地域全体が恋しくなるでしょう。 

いつ$k = n$、非常に制約されたペアのみが満たすことができます。$j = i \cdot k$、多くの行は何も寄与しません。 それぞれを盲目的に想定する手法$k$頻繁に表示されるとオーバーカウントされる可能性があります。 

The key difficulty is that each row produces long contiguous ranges of equal values, not independent per-cell behavior.

 ## アプローチ

 A brute-force solution directly evaluates every pair$(i, j)$、計算します$j // i$と等しいかどうかを確認します$k$。 これは簡単で正しいですが、次のことが必要です。$n^2$操作。 と$n = 10^5$、これは$10^{10}$分割することはほとんど不可能です。 

関数の構造$\left\lfloor \frac{j}{i} \right\rfloor$イメージが完全に変わります。 固定の場合$i$、値は間隔にわたって一定のままです。$j$。 具体的には、すべて$j$で$$[k \cdot i, (k+1)\cdot i - 1]$$価値を生み出す$k$、範囲内に留まることを条件として$[1, n]$。 

これにより、一連の個別のチェックの各行が範囲交差問題に変換されます。 すべてを繰り返すのではなく$j$、間の重複部分に整数がいくつあるかを計算します。$[k i, (k+1)i - 1]$そして$[1, n]$。 

これにより、各行の作業が一定時間に短縮され、ソリューション全体が線形になります。$n$。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 行インデックスを修正する$i$。 列の数を数えたい$j$満足する$\left\lfloor \frac{j}{i} \right\rfloor = k$。 一つ一つ確認するのではなく、$j$、条件を範囲制約として解釈します。$j$。 
2. 条件を不等式に書き換えます。$$k \le \frac{j}{i} < k+1.$$乗算$i$与える:$$k i \le j < (k+1)i.$$以来$j$が整数の場合、これが包含範囲になります。$$j \in [k i, (k+1)i - 1].$$3. この範囲を有効な列境界と交差させます。$[1, n]$。 実際の有効なセグメントは次のようになります。$$L = \max(1, k i), \quad R = \min(n, (k+1)i - 1).$$もし$L > R$、行はゼロ値を提供します。 
4. 有効枚数$j$この行については$\max(0, R - L + 1)$。 この投稿を回答に追加します。 
5. すべてに対して繰り返します$i$から$1$に$n$、合計を積み上げます。 

### なぜ効果があるのか

 各行は、フロア分割が一定である、互いに素な間隔に分割されます。 値の間隔$k$フロア分割の定義から直接導出され、値を生成する整数が正確に含まれます。$k$。 これらの間隔は正確であり、異なる間隔で重複しないため、$k$との交点を合計します。$[1, n]$すべての有効なセルを重複または省略せずに 1 回だけカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

ans = 0

for i in range(1, n + 1):
    L = k * i
    R = (k + 1) * i - 1

    if R < 1 or L > n:
        continue

    L = max(L, 1)
    R = min(R, n)

    if L <= R:
        ans += R - L + 1

print(ans)
```実装は、派生間隔ロジックに直接続きます。 各反復では、固定行の列の有効なセグメントが計算されます。$i$、それをグリッドの境界にクランプします。 小切手`R < 1 or L > n`まったく寄与しない行をスキップします。これは、次の場合に特に重要です。$k = 0$、生の数式は負またはゼロの下限を生成するためです。 

整数の境界には注意が必要です。 表現`(k + 1) * i - 1`上限は整数範囲に変換し直す前に排他的であるため、これは重要です。 が足りない`-1`1 つずつの過大カウントにつながります。

 ## 特殊なケース

 いつ$k = 0$、間隔は$[0, i-1]$、ただし有効です$j$1 から開始します。アルゴリズムはこれをクランプすることで処理します。$L = \max(1, 0)$したがって、各行は正確に寄与します$i-1$ときの値$i \le n$。 たとえば、$n = 4$、 行$i = 3$間隔を生成します$[1,2]$、フロア分割の定義と一致する 2 つの有効なセルが与えられます。
