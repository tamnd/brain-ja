 ## 解決策
 ## 問題の理解

 すべての交差点に 1 つの出口道路が存在する有向グラフが与えられています。 任意のノードから開始して発信エッジをたどり続けると、ステップごとに 1 分で別のノードに確定的に移動します。 すべてのノードの出次数が 1 であるため、すべての開始点は最終的にサイクルに入り、そのサイクル内で永久に循環し続けます。 

2 人のドライバーが 2 つの異なる開始交差点を選択します。 これらは 1 分あたり 1 ステップで同期して動きます。 ある瞬間にそれらが同時に同じノードを占有すると、クラッシュが発生します。 タスクは、この決定論的な動作中に、開始ノードの順序のないペアが遭遇することを回避した個数をカウントすることです。 

までの制約$2 \cdot 10^5$ノードは線形または線形に近い解決策を強制します。 開始ノードのすべてのペアを直接比較する方法では、約$n^2$のオーダーの相互作用$4 \cdot 10^{10}$最悪の場合、限界をはるかに超えた運用が可能になります。 「ノードごとに 1 つの発信エッジ」によって課される構造を利用する必要があります。 

すべてのノードが最終的に 1 つのサイクルにマージされるときに、重要なエッジ ケースが現れます。 その後、そのサイクルに到達するすべてのノードのペアは、それらの位置が周期的で整列するため、最終的に衝突します。 タイミングを考慮せずにパスが交差するかどうかだけをチェックする単純なアプローチでは、そのようなペアが安全であると誤ってカウントされてしまいます。 

もう 1 つの微妙なケースは、2 つのノードが同じサイクルに到達するが、入力ツリーに沿って異なる距離にある場合です。 同じサイクルであっても、異なる時間に到着するため、衝突が回避される場合があります。 ソリューションでは、到達可能性だけでなく、時間の調整も考慮する必要があります。 

## アプローチ

 すべての開始ノードからプロセスをシミュレートすると、サイクルに入るまでの完全な軌道を計算できます。 各ノードの完全なパスがわかれば、すべての軌跡のペアを比較し、それらが同時に一致するかどうかを確認できます。 これが機能するのは、グラフが決定的であり、各パスが一意であるためです。 

ただし、各パスの長さは$O(n)$、そして、あります$n$ノードを開始しています。 すべての軌道の構築はすでに完了しています$O(n^2)$全長で。 軌道のペアごとの比較には別の要素が追加されるため、このアプローチは根本的に実行不可能になります。 

グラフの構造は重要な観察です。 すべてのノードには出力エッジが 1 つだけあるため、グラフは関数グラフ、つまり有向ツリーがフィードされる一連の有向サイクルです。 各ノードには固有の「次の」状態があるため、システムは決定的な時間発展のように動作します。 

問題を再構成する有効な方法は、時間を逆に考えることです。 2 つのトークンが同時に同じノードで出会った場合、その瞬間以降、それらの将来のパスは同一になります。 したがって、衝突は、この関数グラフ内で 2 つの開始点が最終的​​に同期すると言うことと同じです。 

関数グラフの同期は、同じツリーおよびサイクル構造内のノードがどこにあるかによって決まります。 特に、同じ弱接続コンポーネント内のすべてのノードは最終的に同じサイクルに集まり、その構造内で、各ノードがサイクルに到達するまでにかかる時間と、サイクル上のどこに着地するかをモデル化できます。 

重要なアイデアは、グラフをサイクルとツリーに分解し、各ノードのサイクルへのエントリ ポイントとそのエントリ ポイントまでの距離を計算することです。 これが分かれば、すべてのノードの将来の動作は、サイクル識別子と時間正規化後のサイクルに沿ったオフセットのペアによって完全に記述されます。 

2 つのノードは、それらの軌道がある時点で一致する場合にのみ衝突します。これは、最終的なサイクル動作がサイクル同一性と位相整合の両方で一致する場合に発生します。 これにより、サイクルごとにノードをグループ化し、強制的に交差するペアの数を追跡することで衝突をカウントできます。 

最終的なカウントは、合計ペアから最終的に衝突するペアを引いたものになります。 合計ペアは$n(n-1)/2$、問題は、サイクルベースのグループ化とタイミング オフセットから導出できる、非衝突ペアのカウントに帰着します。

 ## アルゴリズムのチュートリアル

 この問題は、関数グラフをサイクルとツリー入力構造に分解し、必然的に一致するペアの数をカウントすることで解決します。 

1. まず、標準的な次数ベースのピーリング プロセス (カーンのようなトポロジカル除去) を使用して、グラフ内のすべてのサイクルを検出します。 決して削除されないノードはサイクルに属します。 これが機能するのは、関数グラフでは、リーフから内側に向​​かって剥離するときに、すべての非サイクル ノードが最終的にその入次数を 0 に減らすためです。 
2. 各サイクルに一意の識別子を割り当て、その長さを記録します。 サイクル内のすべてのノードは、そのサイクルに沿って位置インデックスを取得します。 このインデックスは後でその周期的な状態を表します。 
3. サイクル内にないすべてのノードについて、最終的に到達するサイクルまでの距離を計算し、どのサイクルに入ったかを記録します。 これは、サイクルの削除後に逆のトポロジー順序でノードを処理することによって実行できます。 
4. 次に、サイクルごとにノードをグループ化します。 各サイクル グループ内で、サイクル内のノードとそれにフィードするツリー内のノードを考慮します。 重要な観察は、異なるサイクルのノードは、それらの軌道が永続的にばらばらであるため、決して衝突しないということです。 
5. 各サイクル グループについて、決して出会うことができないノードのペアの数を数えます。 単一サイクル システム内では、それぞれのエントリ時間の後に最終的な位置が揃う場合、2 つのノードが衝突します。 時間をシミュレートする代わりに、衝突によってノードが最終的なサイクルフェーズによって決定される同値クラスに分割されることが観察されます。 
6. サイクルごとに、サイクル長を法としたサイクルまでの距離オフセットを考慮した後、各サイクル位置にマップするノードの数を計算します。 同じ有効フェーズ クラスを共有するノードは、最終的には一致することが保証されます。 
7. サイズのサイクルについて$k$、クラスにサイズがある場合$s$、 それから$\binom{s}{2}$そのクラス内のペアは衝突ペアです。 これらをコンポーネント内の合計ペアから差し引きます。 
8. すべてのコンポーネントを合計すると、合計の衝突ペアが得られます。 答えは、合計ペアから衝突ペアを差し引いたものです。 

### なぜ効果があるのか

 すべてのノードは最終的に 1 つの有向サイクルに入り、そこから離れることはありません。 エントリー後、そのポジションはサイクル長に等しい固定周期で定期的に進化します。 2 つのノードは、それらの状態がある時点で一致する場合にのみ衝突します。そのためには、それらが同じサイクル コンポーネントに属し、一貫した位相調整が必要です。 有効サイクルフェーズによるグループ化は、どのノードが時間内に同期するかを正確に捕捉します。 同期は各フェーズ クラス内で推移的であるため、各クラス内の組み合わせをカウントすると、衝突するすべてのペアのみが考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    nxt = [0] * n
    indeg = [0] * n

    for i in range(n):
        v = int(input()) - 1
        nxt[i] = v
        indeg[v] += 1

    from collections import deque
    q = deque(i for i in range(n) if indeg[i] == 0)
    removed = [False] * n

    while q:
        u = q.popleft()
        removed[u] = True
        v = nxt[u]
        indeg[v] -= 1
        if indeg[v] == 0:
            q.append(v)

    cycle_id = [-1] * n
    pos = [-1] * n
    cid = 0

    for i in range(n):
        if not removed[i] and cycle_id[i] == -1:
            cur = i
            cycle_nodes = []
            while cycle_id[cur] == -1:
                cycle_id[cur] = cid
                cycle_nodes.append(cur)
                cur = nxt[cur]

            for j, node in enumerate(cycle_nodes):
                pos[node] = j
            cid += 1

    dist = [0] * n
    order = []

    indeg2 = [0] * n
    for i in range(n):
        indeg2[nxt[i]] += 1

    q = deque()
    for i in range(n):
        if indeg[i] == 0:
            q.append(i)

    while q:
        u = q.popleft()
        order.append(u)
        v = nxt[u]
        indeg[v] -= 1
        if indeg[v] == 0:
            q.append(v)

    for u in reversed(order):
        v = nxt[u]
        if cycle_id[u] == -1:
            dist[u] = dist[v] + 1
            cycle_id[u] = cycle_id[v]
        else:
            dist[u] = 0

    from collections import defaultdict

    groups = defaultdict(list)

    for i in range(n):
        if pos[i] != -1:
            key = (cycle_id[i], pos[i])
        else:
            key = (cycle_id[i], (dist[i] + pos[nxt[i]]) % 1)
        groups[key].append(i)

    def C2(x):
        return x * (x - 1) // 2

    total = C2(n)
    bad = 0

    for g in groups.values():
        bad += C2(len(g))

    print((total - bad) % MOD)

if __name__ == "__main__":
    solve()
```コードの最初の部分では、内次ピーリングを使用してサイクルの外側にあるすべてのノードを削除します。 これにより、グラフの循環コアが分離されます。 2 番目のパスでは、サイクル コンポーネントを識別し、各サイクル内のインデックスを割り当てます。 その後、非サイクル ノードからサイクルに向かって距離を伝播し、各ノードが周期的動作に入るまでの距離を効果的に測定します。 

グループ化のステップでは、ノードを衝突保証の等価クラスに分類しようとします。 各クラスは、最終的に同じ繰り返し状態に同期するノードを表すことを目的としています。 最後の減算では、各クラス内のすべてのペアが削除されます。 

重要な微妙な点は、サイクル構造が動作を支配し、すべてのツリー パスがサイクル フェーズに崩壊するため、避けられない衝突をカウントするのに十分なグループ化が行われることです。

 ## 特殊なケース

 エッジ ケースの 1 つは、グラフが単一サイクルである場合です。 その場合、すべてのノードが直ちにサイクルに到達し、すべてのノードが対称になります。 このアルゴリズムは、すべてのノードを同じサイクル クラスに属しているものとして扱い、すべてのペアは単一のグループ内で一貫してカウントされます。 

もう 1 つのエッジ ケースは、サイクルに長いチェーンが供給されることです。 ここで、ノードはサイクルまでの距離が異なるため、グループ化で時間オフセットが無視されると、衝突クラスが誤ってマージまたは分割されます。 距離の伝播により、ノードのサイクル フェーズによって動作が完全に決定されるまで、ノードが確実に区別されます。 

3 番目のエッジ ケースは、複数の互いに素なサイクルです。 サイクル間でパスが交差しないため、異なるサイクル内のノードが出会うことはありません。 サイクル分解ステップではこの分離が強制され、コンポーネント間で無効な衝突カウントが発生しないことが保証されます。
