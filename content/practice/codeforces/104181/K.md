 ## 問題の理解

 私たちは、それぞれが化学物質を表す整数の動的なコレクションを維持します。 時間の経過とともに、このセットに新しい値を挿入します。 現在利用可能な化学物質の任意のサブセットを取得し、0 を生成する空のサブセットを含め、選択されたすべての要素を XOR 演算することで、いつでも新しい値を形成できます。 

タイプ 2 の各クエリは酸性値を与えます。`a`そしてターゲットマスク`b`。 何らかの価値が存在するかどうか知りたい`c`これは、次のような現在のセットのサブセット XOR から形成できます。`c`と`a`正確に等しい`b`。 

したがって、コア オブジェクトは挿入されたすべての数値の XOR スパンであり、各クエリは、この XOR 空間でビットマスクへの射影を持つベクトルを実現できるかどうかを尋ねます。`a`等しい`b`。 

制約は最大 100,000 操作に及ぶため、クエリごとに XOR サブセット空間全体を再計算するソリューションは直ちに実行不可能になります。 完全なサブセット空間は、挿入された要素の数に応じて指数関数的に増大し、それを明示的に表現することさえ不可能になります。 

素朴なアプローチでは、到達可能なすべての XOR 値を維持し、それらに対して各クエリをテストしようとしますが、30 回の挿入でもセット サイズはすでに天文学的に大きくなります。 もう 1 つの単純な間違いは、セットを基礎として扱いながら、クエリが完全な等価性ではなくビット単位の制約のみに依存していることを忘れていることです。 

微妙なエッジケースが現れるのは、`a`利用可能な化学薬品の範囲外のビットが含まれています。 たとえば、挿入されたすべての数値が下位ビットのみを使用する場合、`a`上位ビットが含まれており、`b`1 である必要がありますが、サブセット XOR に関係なく、答えは直ちに不可能になります。 多くの誤った解決策は、この射影制約を見逃しています。 

## アプローチ

 重要な観察は、サブセット XOR は大きな空間を形成しますが、GF(2) 上では線形部分空間を形成するということです。 挿入されたすべての数値は基底に寄与し、達成可能な XOR は基底ベクトルの線形結合になります。 

これは、すべてのサブセットについては考慮せず、セットの XOR 基底のみを考慮することを意味します。 30 ビットにわたって線形基底を維持すると、考えられるすべての XOR 結果のセットを正確に表すことができます。 

クエリ条件`c & a = b`のビットを制限します`c`ポジションで`a`1が付いています。 あらゆるビットごとに`a`1 の場合、次のいずれかを要求します`c`合わせる`b`または、次の場合に自由を許可します`a`これにより、問題が投影された部分空間上の制約に分割されます。 

構築することを考えることができます`c`以下の位置でのみビットごとに`a`重要です。 外側のビットについて`a`、私たちは何を気にしません`c`したがって、これらのビットは、利用可能な基底ベクトルを使用して常に調整できる自由変数です。 

重要な削減点は、基底が制約と一致する値を生成できるかどうかを確認するだけでよいことです。 これは、固定ビット制約を持つ 30 次元 XOR 空間での到達可能性の問題となり、ガウス消去法をベースに必要なビットを満たすことを貪欲に試みることで解決できます。 

ビットを上位から下位まで処理し、有効なビットを構築しようとします。`c`からの強制ビットを尊重しながら基礎を使用する`b`。

 ## アルゴリズムのチュートリアル

 30 ビットにわたってバイナリの線形基底を維持します。 

1. 配列を初期化する`basis[30]`どこ`basis[i]`最上位の設定ビットが`i`。 これにより、すべての数値が正規表現に変換されます。 
2. 挿入ごとに`c`、ビット 29 から 0 まで繰り返します。`i`に設定されています`c`、 そして`basis[i]`空です、私たちは保管します`c`そこで止まります。 もし`basis[i]`すでに存在するため、XOR します`c`と`basis[i]`そのビットを削除して続行します。 このステップにより、すべての基底ベクトルが独立したままになることが保証されます。 
3. 質問に答えるため`(a, b)`、XORの組み合わせが存在するかどうかを判断しようとします`c`それは満足する`(c & a) = b`。 
4. まず、必要なビットの一貫性を検証します。`b`。 ビットが 1 インチの場合`b`、これも 1 である必要があります。`a`、そうでない場合は不可能です`c & a`にないビットを導入することはできません`a`。 
5. ビット上の必要な寄与を一致させるための基底を使用して、制約されたビット上でターゲット パターンを構築します。`a`は1です。 
6. まず基底ベクトルを使用して上位ビットを貪欲に削除し、射影が一致するベクトルを構築できるかどうかを効果的にチェックします。`b`。 

### なぜ効果があるのか

 挿入された数値のすべての XOR 組み合わせのセットは、GF(2) 上のベクトル空間を形成します。 維持される基準はこのスペースのフルランク表現であるため、達成可能なすべての`c`は基底ベクトルの一部のサブセットに対応します。 条件`(c & a) = b`は、選択した座標に制限された線形制約のシステムです。 実現可能性のチェックは、基底が及ぶ部分空間内にシステムが解を持っているかどうかを判断することに帰着します。これは、ビット上のガウス消去法によって正しく決定されます。 すべての変換で到達可能な空間の等価性が維持されるため、有効な構造が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class XorBasis:
    def __init__(self):
        self.b = [0] * 30

    def insert(self, x):
        for i in range(29, -1, -1):
            if not (x >> i) & 1:
                continue
            if self.b[i] == 0:
                self.b[i] = x
                return
            x ^= self.b[i]

    def can_build_projection(self, a, b):
        # check impossible bits
        if b & ~a:
            return False

        # try to build a value consistent with constraints
        x = 0
        for i in range(29, -1, -1):
            if (a >> i) & 1:
                # we want bit i of (x & a) to match b
                # so we try to control x[i]
                if ((x >> i) & 1) != ((b >> i) & 1):
                    if self.b[i] == 0:
                        return False
                    x ^= self.b[i]
        return True

def main():
    q = int(input())
    xb = XorBasis()
    out = []

    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            xb.insert(tmp[1])
        else:
            _, a, b = tmp
            out.append("YES" if xb.can_build_projection(a, b) else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```挿入ロジックは標準の XOR ベースのメンテナンスです。 各数値は、ゼロになるか新しいピボット ビットが導入されるまで、既存の基底ベクトルによって減らされます。 

クエリ ロジックは最初に構造上の不可能性をチェックします。`b`少し外側にあります`a`、構築されていません`c`AND条件を満たすことができます。 次に、基底ベクトルを使用して、構築された候補のビットが一致しない場合は常にビットを反転させて、ビットを高位から低位に貪欲に修正します。`b`。 

上位ビットが基底の正規表現を支配するため、貪欲な性質は有効です。そのため、上位のインデックスでの決定は後で取り消されません。

 ## 特殊なケース

 主なエッジケースは次のような場合です`b`に存在しないビットが含まれています`a`。 例えば、`a = 2 (10)`、`b = 3 (11)`すぐには無理なので`(c & 2)`最下位ビットを生成することはできません。 小切手`b & ~a`はこれを直接処理し、アルゴリズムは根拠のある推論の前にそれを拒否します。 

もう一つのケースは、化学物質が挿入されていない場合です。 構成可能な値は 0 のみであるため、クエリはすべて次のことをチェックすることになります。`(0 & a) == b`、これは次の場合にのみ当てはまります。`b = 0`。 基底は空から始まり、貪欲な構築は必要なビットが生成できないときは必ず失敗し、些細な場合を除いて正しく NO を返します。
