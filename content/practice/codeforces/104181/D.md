 ## 解決策
 ## 問題の理解

 私たちには、アルベルトが厳密に順番に消費する一連のエネルギー源が与えられています。 各ソースは固定量のエネルギーを提供し、一度消費すると再利用したり分割したりすることはできません。 ワークアウトセットが完了するたびに、アルベルトのエネルギーは完全にゼロにリセットされます。 

ワークアウト セットは、増加する要件によって定義されます。最初の腕立て伏せには 1 エネルギーがかかり、2 番目には 2 エネルギーがかかり、M 番目の腕立て伏せには M エネルギーがかかるまで続きます。 セットを完了するということは、アルベルトが連続して消費するシェイクで、合計コスト 1 + 2 + … + M をカバーするのに十分なエネルギーを蓄積する必要があることを意味します。セットが終了してもアルベルトはシェイク シーケンスを再開せず、エネルギー カウンターのみがリセットされます。 

このプロセスは継続的です。彼はシェイクを 1 つずつ消費し、エネルギーを蓄積し、シェイクがなくなる前にできるだけ多くのフルセットを完了しようとします。 課題は、彼がフルセットを何セット完了したかを計算することです。 

制約は、O(N) または O(N log N) の解を意味します。 N は 100,000 に達する可能性があるため、すべてのセットにわたる二次シミュレーションや以前の状態の繰り返しスキャンは遅すぎます。 M は最大 1000 であり、セットごとの要件が制限されており、事前に計算するか、一定のしきい値として扱うことができることを示唆しています。 

多くの小さな揺れでエネルギーがゆっくりと蓄積する場合や、1 つの大きな揺れが複数の腕立て伏せの要件をオーバーシュートする場合、単純なシミュレーションは失敗する可能性があります。 

たとえば、M が小さいが N が大きい場合:
 入力:```
5 3
1 1 1 1 100
```不用意なアプローチでは、腕立て伏せを個別にシミュレートし、要件を繰り返し再計算しようとする可能性があり、エネルギー オーバーフローが誤って処理された場合、非効率になったり、誤ったリセット処理が発生したりする可能性があります。 

もう 1 つの微妙なケースは、単一の揺れが設定された複数のしきい値を超える場合です。 ロジックでは、過剰なエネルギーがセット間で誤って伝達されないようにする必要があります。 

## アプローチ

 直接的な総当たり解釈では、説明どおりにプロセスを正確にシミュレートします。 ランニングエネルギー値を維持します。 また、現在のセットもシミュレートします。1 から M までの腕立て伏せ i ごとに、現在のエネルギーが十分かどうかを確認します。 そうでない場合は、そうなるまでさらにシェイクを消費します。 腕立て伏せを 3 回完了したら、答えを増やしてエネルギーをリセットします。 

このアプローチはプロセスを正確に反映しているため、正しいです。 ただし、腕立て伏せを繰り返しスキャンしたり、セット全体でシェイクを複数回スキャンしたりする可能性があるため、非効率になります。 最悪の場合、すべてのシェイクは M ステップにわたる頻繁な内部チェックで処理され、O(NM) の複雑さになり、10^8 の演算に達する可能性があります。 定数によっては、Python ではこれが限界か遅すぎます。 

重要な観察は、単一セット内では必要なエネルギーの合計が固定されており、事前にわかっているということです。\[
S = 1 + 2 + \dots + M = \frac{M(M+1)}{2}
\]したがって、腕立て伏せを 1 つずつシミュレートする代わりに、蓄積されたエネルギーが S に達するかどうかを追跡するだけで済みます。各揺れはこの蓄積に直接寄与します。 S に達するかそれを超えると、セットを完了し、カウンターをインクリメントし、S を減算します (エネルギーはセット間で持ち越されないため、事実上リセットです)。 

これにより、問題は、累積和を維持し、しきい値を何回超えたかをカウントする単純な線形スキャンに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォースシミュレーション | O(NM) | お(1) | 遅すぎる |
 | セットごとのプレフィックスの累積 | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 重要なアイデア
 各セットには固定のエネルギー量 S が必要です。シェイクを消費している間に累計が S に達した回数のみを追跡します。 

### ステップ

 1. 1 つのフルセットに必要な総エネルギーを S = M(M+1)/2 として計算します。 これにより、可変プッシュアップ プロセスが 1 つのしきい値チェックに変換されます。 
2. 可変電流 = 0 を初期化して、進行中のセットの累積エネルギーを保存します。 
3. 完了したセットをカウントするには、answer = 0 を初期化します。 
4. 各エネルギーシェイクEiを順番に繰り返します。 
5. 現在にeiを追加します。 
6. 電流が S 以上である間は、電流から ​​S を減算し、答えを増分します。 
7. すべてのシェイクを処理した後、答えを出力します。 

減算ステップは、現在のシェイクからの残りのエネルギーを保存することを除いて、セットを終了してエネルギーをリセットすることと同等です。これは、単一の大きなEIが複数のセットにまたがる場合に重要です。 

### なぜ効果があるのか

 セット内の腕立て伏せのプロセスは、シェイク全体のエネルギー配分ではなく、総エネルギーのみに依存します。 エネルギーは増加する要件を満たすためにのみ消費されるため、セットごとの総コストは固定されます。 したがって、固定しきい値に対して累積エネルギーのみを追跡することで、セットの完了を完全に把握できます。 セットを完了した後の余剰エネルギーは次のセットに属する必要があり、S を減算するとその残留状態が正確に保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    E = list(map(int, input().split()))

    S = M * (M + 1) // 2

    current = 0
    ans = 0

    for x in E:
        current += x
        if current >= S:
            ans += current // S
            current %= S

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、しきい値の削減に直接続きます。 最も微妙な選択は、整数の除算を使用して、1 ステップで完了する完全なセットの数をカウントすることです。 これは有効です。エネルギーが S を超えると、複数のフルセットが瞬時に完了し、残りが繰り越されるためです。 

モジュロ演算により、残りのエネルギーが次のセットのために正しく保存されることが保証されます。 これにより、減算演算の繰り返しループが回避され、解が線形に保たれます。

 ## 特殊なケース

 重要なエッジケースは、単一のエネルギーシェイクが一度に複数のセットを完了する場合です。 たとえば:

 入力:```
1 3
100
```ここでは S = 6 です。アルゴリズムは current = 100 を計算し、ans += 100 // 6 = 16 を実行し、剰余は 4 になります。 

段階的に、これは現実と一致しています。アルベルトは 16 のフルセットを完了し、次の不完全なセットに 4 つのエネルギーを運びます。 反復ごとに 1 セットの完了だけをチェックする単純なシミュレーションでは、最初の完了後に誤って停止し、残りのエネルギーが失われ、答えが過小評価されてしまいます。 

もう 1 つのエッジ ケースは、セットが完了しない場合です。 

入力:```
5 4
1 1 1 1 1
```S = 10。累計は 10 に到達しないため、ans は 0 のままです。アルゴリズムは、誤ったリセットを強制することなく現在のエネルギーを自然に保存し、意図した動作に一致します。
