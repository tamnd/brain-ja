 ## 解決策
 ## 問題の理解

 1 から H までの各整数の高さは、一度放出される雨滴を表し、各水滴は高さ 1 に達するまで独立して落下します。運動規則は決定論的です。どの高さ x においても、水滴は多重度でカウントされた x の素約数の数だけ高さが減少します。 したがって、x に因数分解がある場合$x = p_1^{a_1} p_2^{a_2} \dots$、その後、ドロップは x から に移動します。$x - (a_1 + a_2 + \dots)$毎秒。 

このタスクは、1 から H までのすべての高さについてこのプロセスを次々にシミュレートし、各落下を完全に終了してから次の落下を開始する場合に必要な合計秒数を計算することです。 

出力は、この繰り返しの減算プロセスで i が 1 に達するまでに必要なステップ数の、すべての開始高さ i の合計です。 

制約$H \le 4 \cdot 10^6$因数分解を繰り返して各ドロップを個別にシミュレートすることは不可能になります。 単純な数値ごとのシミュレーションでは、各中間値を繰り返し因数分解して、大まかに次のようになります。$O(H \sqrt{H})$またはより悪い行動。 たとえ$O(H \log H)$ステップごとの因数分解アプローチでは、各数値が中間状態のチェーンを生成するため、非常に時間がかかりすぎます。 

さらに微妙な問題は、中間値が異なる開始番号間で繰り返されることです。 たとえば、10 と 12 は両方ともすぐに同じ小さな範囲に入ります。つまり、係数カウントを繰り返し再計算すると作業が無駄になります。 

H が小さい場合、エッジ ケースが発生します。 H = 1 の場合、動きは起こらず、答えは 0 です。H = 2 の場合、2 → 1 に 1 秒かかりますが、1 の寄与はゼロです。 0 に到達するステップ数を誤って含む単純な実装では、無効な遷移が生成されますが、プロセスは 1 で停止することが保証されています。 

## アプローチ

 直接的なアプローチでは、各開始値 i の最小の素因数の合計 (多重度を持つ素因数の数) を繰り返し計算し、1 に達するまでそれを減算することによってシミュレートします。これは、プロセスに正確に従っているため、正しいです。 ただし、すべてのステップで素因数の合計を最初から計算するのはコストがかかります。 各因数分解には少なくともコストがかかります$O(\sqrt{x})$そして、すべての中間州にわたって、これは法外なものになります。$H = 4 \cdot 10^6$。 

重要な観察は、「ステップあたりのコスト」は履歴ではなく現在の値にのみ依存するということです。 すべての x の値を事前計算すると、$\Omega(x)$、多重度を持つ素因数の合計数の場合、各遷移は単純な検索になります。 これにより、すべての数値に対して関数を計算し、減少する値に対して単一の DP を実行するという問題が軽減されます。 

dp[x] を、x から開始したドロップが 1 に達するまでに必要な秒数として定義します。次に、次のようになります。$$dp[x] = 1 + dp[x - \Omega(x)]$$基本ケース dp[1] = 0 です。x は常に減少するため、dp を昇順に計算できます。 

唯一欠けているのは効率的なコンピューティングです$\Omega(x)$これは、修正されたふるいを使用して実行できます。素数のみを保存する代わりに、素因数を伝播し、最小素因数ふるいと同様に多重度をカウントします。 

一度$\Omega(x)$が既知の場合、各 dp 遷移は O(1) であり、完全な解は線形になります。

 ## アルゴリズムのチュートリアル

 ### 素因数の数を事前計算する

 1. 1 から H までのすべての x に対して配列 omega[x] = 0 を初期化します。これにより、各 x の多重度を持つ素因数の数が格納されます。 
2. 0 に初期化された配列 spf[x] を維持します。この配列には、検出されたときに x の最小の素因数が格納されます。 
3. x を 2 から H まで繰り返します。spf[x] が 0 の場合、x は素数であり、spf[x] = x と設定します。 
4. 複数の y = x、2x、3x、... ごとに、spf[y] が設定されていない場合は更新します。 
5. spf を使用して、2 番目のパスでオメガを計算します。x ごとに、x = spf[x] * (x // spf[x]) を表し、omega[x] = omega[x // spf[x]] + 1 を設定します。 

これが機能する理由は、すべての数値の因数分解が、一度に 1 つの最小の素因数を剥がすことによって段階的に構築できるためです。 

### 高所での DP を計算する

 1. 高さ 1 の落下はすでに地面にあるため、dp[1] = 0 を設定します。 
2. 2 から H までの x について、dp[x] = dp[x - omega[x]] + 1 を計算します。 
3. 1 から H までのすべての x について、答えを sum(dp[x]) として累積します。 

各遷移は厳密に x を削減するため、必要なすべての状態は必要なときにすでに計算されています。 

### なぜ効果があるのか

 重要な不変条件は、dp[x] が常に x から始まるドロップに必要な正確なステップ数を表すことです。 各移動は固定され事前計算された omega[x] のみに依存し、x は常に減少するため、すべての dp[x] は値がすでに正しい小さいインデックスのみに依存します。 これにより、循環依存関係が発生せず、すべての値が正しい順序で 1 回だけ計算されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    H = int(input().strip())
    if H == 1:
        print(0)
        return

    spf = [0] * (H + 1)
    omega = [0] * (H + 1)

    primes = []

    for i in range(2, H + 1):
        if spf[i] == 0:
            spf[i] = i
            primes.append(i)
        for p in primes:
            if p > spf[i] or i * p > H:
                break
            spf[i * p] = p

    omega[1] = 0
    for i in range(2, H + 1):
        omega[i] = omega[i // spf[i]] + 1

    dp = [0] * (H + 1)
    total = 0

    for i in range(1, H + 1):
        if i == 1:
            dp[i] = 0
        else:
            dp[i] = dp[i - omega[i]] + 1
        total += dp[i]

    print(total)

if __name__ == "__main__":
    solve()
```この解決策は、最小の素因数を計算する線形ふるいから始まり、すべての合成数に最小の約数が 1 回だけ割り当てられるようにします。 これにより、spf による再帰を使用して、omega[x] を数値ごとに O(1) で計算できるようになります。 

その後、dp 配列が 1 から上に構築されます。 x > 1 の場合、omega[x] は常に少なくとも 1 であるため、各値は厳密に小さいインデックスにのみ依存し、基本ケースへの進行が保証されます。 

最終的な合計は、すべての個別の落下時間を累積します。 

よくある実装の落とし穴は、omega[x] が個別の素数ではなく多重度をカウントする必要があることを忘れていることです。 素の約数の単純なセットを使用すると、ステップ サイズが誤って縮小され、dp 値が増大します。 

## 実用的な例

 ### 例 1: H = 6

 オメガを計算します。 

1→0

 2→1

 3→1

 4→2

 5→1

 6→2

 ここで dp:

 | × | オメガ[x] | x - オメガ[x] | dp[x] |
 | --- | --- | --- | --- |
 | 1 | 0 | - | 0 |
 | 2 | 1 | 1 | 1 |
 | 3 | 1 | 2 | 2 |
 | 4 | 2 | 2 | 3 |
 | 5 | 1 | 4 | 4 |
 | 6 | 2 | 4 | 5 |

 合計 = 0 + 1 + 2 + 3 + 4 + 5 = 15 ですが、dp[3] = dp[2] + 1 = 2、dp[4] = dp[2] + 1 = 2 であることに注意してください。修正により、サンプルと同様に最終的な合計は 11 になります。 

このトレースは、各 dp が以前に計算された値のみに依存していることを示しており、順序付けが正しいことが確認されます。 

### 例 2: H = 3

 オメガ:

 1→0、2→1、3→1

 DP:

 dp[1] = 0

 dp[2] = 1

 dp[3] = 2

 合計 = 3

 これは、すべてのチェーンがすぐに 1 で終了する最小限の伝播を示しています。

 ## 特殊なケース

 H = 1 の場合、アルゴリズムは dp[1] = 0 を初期化し、ループは他に何もせず、ただちに出力 0 を生成します。 これにより、基本ケースが dp[0] または負のインデックスに誤ってアクセスしないことが確認されます。 

x = 2 や x = 3 のような素数の場合、omega[x] = 1 となるため、各値は x - 1 に直接遷移します。DP は、状態をスキップすることなく、以前に計算された値に正しく連鎖します。 

x = 12 のような高度に合成された数値の場合、omega[12] = 3 であるため、dp[12] は dp[9] に依存します。 9 < 12 であり、昇順に処理するときに dp[9] がすでに計算されているため、前方依存性は発生せず、大きなジャンプでも正確さが維持されます。
