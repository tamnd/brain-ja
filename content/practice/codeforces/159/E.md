 ## 解決策
 ## 問題の理解

 私たちは持っています`n`立方体。 すべての立方体には色とサイズがあります。 正確に 2 つの異なる色の立方体を使用してタワーを構築したいのですが、タワー内の隣接する立方体は常に異なる色でなければなりません。 

キューブのサイズや順序に制限はありません。 小さな立方体は大きな立方体の下に置くことができますが、同じ色の立方体を並べて表示することはできません。 目標は、選択した立方体のサイズの合計を最大化することです。 

出力には、可能な最大合計高さ、使用されるキューブの数、およびキューブ インデックスの 1 つの有効な順序が含まれている必要があります。 

最も重要な観察は、2 つの色を選択したら、最初に最大の立方体を取りながら、それらの色の立方体を交互に配置することで最高のタワーが得られるということです。 交互以外に制限はないため、可能な限り、それらの色の有用なキューブがすべて最終タワーに表示される必要があります。 

制約は、二次または三次の探索を除外するのに十分な大きさです。 と`n ≤ 10^5`、周りのものすべて`O(n^2)`が遅くなりすぎます。 すべてのキューブのペアごとの比較には、すでに約`10^10`最悪の場合の運用。 意図したソリューションには大まかに必要なものがあります`O(n log n)`複雑さは主に並べ替えが避けられないためです。 

不注意な実装を簡単に破ってしまう微妙なエッジケースがいくつかあります。 

次の入力を考えてみましょう。```
5
1 100
1 1
2 50
2 49
2 48
```常に現在最大のキューブを取得する貪欲な戦略では、次のものが選択されます。```
1(100), 2(50), 2(49)
```ただし、隣接する 2 つの立方体が同じ色であるため、これは無効です。 

正しい答えは次のとおりです。```
1(100), 2(50), 1(1), 2(49)
```全高あり`200`。 

別の危険なケースは、ある色が他の色よりも多くの立方体を持っている場合に発生します。```
6
1 10
1 9
1 8
1 7
2 1
3 100
```単純な考えでは、支配的な色のキューブをすべて使用しようとするかもしれませんが、交互に使用すると、1 つの色のキューブが参加できる数が制限されます。 色を選ぶなら`1`そして`3`、最も有効なタワーは次のとおりです。```
3(100), 1(10)
```全高`110`。 

追加のカラーキューブの使用`1`それらを分離するための 2 番目のカラー キューブが残っていないため、これは不可能です。 

もう一つの微妙な点は再構築です。 2 つの色が同じ数の立方体に寄与すると仮定します。```
4
1 5
1 4
2 3
2 2
```どちらの注文も有効です。```
1 2 1 2
```そして```
2 1 2 1
```常に最初の色から始まる再構成方法では、カウントを慎重に扱わないと、誤って無効なシーケンスが作成される可能性があります。 

## アプローチ

 強引なアプローチは、すべての色のペアを試してみることです。 固定ペアの場合、それらの色に属するすべての立方体を収集し、各色の内側の降順のサイズで並べ替え、最適な交互シーケンスをシミュレートします。 

これが機能するのは、2 つの色が決まれば、最適な戦略が簡単になるからです。 どの立方体も答えにプラスの影響を与えるため、常に利用可能な最大の立方体が必要です。 

問題は色のペアの数です。 最悪の場合、すべての立方体は異なる色を持っているため、`O(n^2)`ペア。 ペアごとに、多くの立方体を再度処理する場合があります。 全体の複雑さは簡単に超えてしまいます`10^10`操作。 

重要な観察は、最適なタワーが 2 つのソートされたシーケンスをマージするように動作することです。 

色を仮定します`A`立方体があります:```
a1 ≥ a2 ≥ a3 ...
```そして色`B`もっている：```
b1 ≥ b2 ≥ b3 ...
```1 つの色が他の色よりも多くの立方体に寄与する場合、数の差が 1 を超えることはありません。そうでない場合は、変更が不可能になります。 

したがって、すべての色のペアについて、使用可能な立方体は、長さが最大で 1 つ異なるだけの最大のプレフィックスになります。 

これにより、問題は、ソートされたキューブ リストにわたるプレフィックスの合計を維持することに変わります。 

各色について:

 1. キューブをサイズの降順に並べ替えます。 
2. プレフィックスの合計を作成します。 
3. 色のペアを反復しながら、達成可能な最良の合計を計算します。`O(1)`プレフィックス合計を使用した時間。 

残りの課題はすべてを回避することです`O(n^2)`直接ペアリングします。 

重要な削減点は、大きなプレフィックスのみが問題となり、すべてのキューブが 1 つの並べ替えられたリストのみに参加することです。 色を効率的に処理し、不可能な状態を取り除くことで、全体の複雑さはほぼゼロに抑えられます。`O(n log n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての立方体を色ごとにグループ化します。 

色ごとにペアを保存します`(size, index)`。 
2. すべての色グループをサイズの降順に並べ替えます。 

すべてのキューブがプラスに寄与するため、色の最適なキューブが常に最初に使用されます。 
3. 各色のプレフィックスの合計を作成します。 

カラーにソートされたサイズがある場合:```
10, 7, 5
```その場合、そのプレフィックスの合計は次のようになります。```
10, 17, 22
```これにより、最大の合計サイズを即座に計算できます。`k`立方体。 
4. 色のペアごとに`(A, B)`、使用可能な最大数を決定します。 

色の場合`A`もっている`x`立方体と色`B`もっている`y`cubes` の場合、有効な交互シーケンスとして以下を使用できます。```
min(x, y) * 2
```カウントが等しい場合は立方体、または```
min(x, y) * 2 + 1
```片側が追加の立方体を 1 つ提供する場合は立方体。 
5. プレフィックスの合計を使用して、このペアの最適な合計高さを計算します。 

もし`x > y`の場合、次のようになります。```
y + 1
```からの立方体`A`そして`y`からの立方体`B`。 

全高は次のようになります。```
prefA[y + 1] + prefB[y]
```同様のロジックが対称的に適用されます。 
6. 世界的に最適なペアと各色から使用されるカウントを保持します。 
7. 塔を再建します。 

より多くの立方体に寄与する色から始めます。 選択したすべてのキューブが配置されるまで、選択した 2 つのプレフィックスからキューブを交互に配置します。 

### なぜ効果があるのか

 固定色の場合、すべてのサイズが正であるため、選択された立方体ごとに答えが増加します。 したがって、同じ色内で、より大きな立方体をスキップしながらより小さな立方体を取得することは、決して最適ではありません。 

唯一の制限は交代です。 この制限は、実際のサイズではなく、各色が寄与する立方体の数にのみ依存します。 

したがって、2 つの色に最適なタワーは、ソートされた両方のリストから可能な限り最大の有効なプレフィックスを取得することによって常に形成されます。 プレフィックスの合計により、すぐに最適な値が得られます。 

アルゴリズムはすべての実行可能なペアをチェックし、そのペアの正確な最適な寄与を計算するため、グローバル最適が見つかることが保証されます。 

## Python ソリューション```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def solve():
    n = int(input())

    groups = defaultdict(list)

    for i in range(1, n + 1):
        c, s = map(int, input().split())
        groups[c].append((s, i))

    colors = list(groups.keys())

    pref = {}

    for c in colors:
        groups[c].sort(reverse=True)

        p = [0]
        for s, _ in groups[c]:
            p.append(p[-1] + s)

        pref[c] = p

    best_sum = -1
    best = None

    m = len(colors)

    for i in range(m):
        c1 = colors[i]
        len1 = len(groups[c1])

        for j in range(i + 1, m):
            c2 = colors[j]
            len2 = len(groups[c2])

            k = min(len1, len2)

            # equal counts
            cur = pref[c1][k] + pref[c2][k]

            if cur > best_sum:
                best_sum = cur
                best = (c1, k, c2, k)

            # c1 gets one extra
            if len1 >= k + 1:
                cur = pref[c1][k + 1] + pref[c2][k]

                if cur > best_sum:
                    best_sum = cur
                    best = (c1, k + 1, c2, k)

            # c2 gets one extra
            if len2 >= k + 1:
                cur = pref[c1][k] + pref[c2][k + 1]

                if cur > best_sum:
                    best_sum = cur
                    best = (c1, k, c2, k + 1)

    c1, take1, c2, take2 = best

    arr1 = groups[c1][:take1]
    arr2 = groups[c2][:take2]

    ans = []

    p1 = 0
    p2 = 0

    turn = 1 if take1 >= take2 else 2

    while p1 < take1 or p2 < take2:
        if turn == 1:
            if p1 < take1:
                ans.append(arr1[p1][1])
                p1 += 1
            turn = 2
        else:
            if p2 < take2:
                ans.append(arr2[p2][1])
                p2 += 1
            turn = 1

    print(best_sum)
    print(len(ans))
    print(*ans)

solve()
```この解決策は、色に従って立方体をグループ化することから始まります。 再構築にはインデックスをタワー順に出力する必要があるため、各グループはサイズと元のインデックスの両方を保存します。 

すべてのカラー リストはサイズの降順で並べ替えられます。 これが貪欲な観察の核心です。 取ることに決めたら`k`色から立方体を作成する場合、最適な選択は常に`k`最大の立方体。 

プレフィックスの合計により、スコアの計算が定数時間になります。 これらがないと、すべてのペアの評価が大きなセグメントを繰り返し合計することになり、非常に遅くなります。 

再構築のステップは微妙です。 私たちは常に、他の色と少なくとも同じ数の立方体に寄与する色から開始します。 これにより、交代が終わり近くで決して失敗しないことが保証されます。 

もう 1 つの簡単な間違いは、カウントが等しい場合を忘れることです。 有効なタワーでは、両方の色の同じ数のキューブが使用される可能性があるため、次の 3 つの可能性をすべてチェックする必要があります。 

1. 等しい数。 
2. 最初の色には 1 つ余分にあります。 
3. 2 色目は 1 つ余分にあります。 

すべての合計には Python 整数が使用され、合計が次の値に達する可能性があるため、考えられる最大の答えを安全に処理します。`10^14`。
