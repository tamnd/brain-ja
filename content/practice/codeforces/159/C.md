 ## 解決策
 ## 問題の理解

 文字列が与えられています`s`そして整数`k`。 ユーザーは最初にユーザー名を登録します`t`これは単なる文字列です`s`繰り返された`k`連続して何回も。 その後、一連の編集が行われ、それぞれの編集で`p`- 現在の文字列から指定された文字が 3 番目に出現します。 私たちのタスクは、これらすべての削除を順番に適用した後、最終的な文字列を計算することです。 

文字列`s`最大でも 100 文字ですが、`k`最大 2000、つまり最初の文字列を意味します`t`最大 200,000 文字まで含めることができます。 削除数`n`最大20,000にすることもできます。 これらの境界から、削除ごとに文字列をスキャンする単純なアプローチでは、各削除に O(|t|) 時間がかかり、最悪の場合 200,000 × 20,000 回の操作が発生する可能性があり、これは許容できないほど大きいため、遅すぎる可能性が高いことがすぐにわかります。 

主なエッジ ケースは、削除する文字が何度も出現し、削除の対象が最初または最後の出現のいずれかである場合、または複数の操作が同じ文字に影響を与える場合に発生します。 たとえば、`s = "aa"`そして`k = 3`、`t = "aaaaaa"`3 番目の「a」を削除すると、後続の出現位置が変わるため、慎重な計算が必要です。 もう 1 つの注意が必要なシナリオは、すべての削除が密集したブロック内の同じキャラクターをターゲットにしている場合です。これは、位置を正しく追跡しないと、簡単にオフバイワンの間違いにつながる可能性があります。 

## アプローチ

 最も単純なアプローチは総当たりです。文字列を構築します。`t`明示的に、操作ごとに文字列を反復処理して、`p`ターゲット文字が - 番目に出現してから削除します。 これは正確な操作を模倣しているので正しいですが、コストは O(n × |t|) であり、最悪の場合は約 4×10^9 回の操作になります。 これは、3 秒の時間枠で実行可能な計算限界を明らかに超えています。 

より高速な解決策の重要な点は、文字列全体を繰り返しスキャンして出現箇所を見つける必要がないことです。 代わりに、前処理することができます`t`文字ごとに、その文字が出現する位置を保存します。 次に、各削除操作は、位置のリストにインデックスを付け、その位置を削除済みとしてマークし、後で最終的な文字列を再構築することになります。 ソートされたリストや出現位置の配列などのデータ構造を使用すると、前処理後に各削除を一定時間で処理できるようになります。 

どの位置にあるかを示すブール配列を維持できます。`t`が削除されます。 すべての操作を処理した後、次の手順を繰り返します。`t`削除されていない位置のみを含めると、最終的な文字列が得られます。 これにより、複雑さは O(|t| + n) に軽減され、指定された制約では許容可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n × k × | s | ) |
 | 最適 | O(k × | s | + n) |

 ## アルゴリズムのチュートリアル

 1. 初期文字列を構築します`t`繰り返すことで`s` `k`回。 これは簡単で、全長は`len(s) * k`。 
2. 辞書を準備する`positions`各文字を、その文字が出現するインデックスのリストにマッピングします。`t`。 反復処理`t`1 回、各インデックスを適切なリストに追加します。`positions`。 これにより、`p`任意の文字の - 番目の出現。 
3. ブール配列を初期化する`deleted`に等しい長さの`t`どのポジションが削除されたかを追跡するため。 
4. 各削除操作の処理`(p, c)`。 文字のインデックスのリストを調べる`c`で`positions`そして見つけてください`p-1`そのリスト内の - 番目のインデックス (ゼロベース)。 マーク`deleted[index] = True`それを取り除くために。 
5. すべての削除が完了したら、次の手順を繰り返します。`t`そして、次の文字のみを含めて最終的な文字列を構築します。`deleted`フラグは False です。 

なぜ効果があるのか​​: あらゆる段階で、`positions[c]`のすべての出現の絶対位置を維持します。`c`以前の削除とは関係なく、元の文字列内にあります。 を使用して、`deleted`配列により、構造が変更されないことが保証されます。`positions`、文字列の現在の状態を正しく表現しながら、コストのかかるリストの更新を回避します。 この不変式により、最終的な再構築で正しい答えが得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

k = int(input())
s = input().strip()
n = int(input())
operations = [input().split() for _ in range(n)]

t = s * k
positions = {chr(c): [] for c in range(ord('a'), ord('z')+1)}

for i, char in enumerate(t):
    positions[char].append(i)

deleted = [False] * len(t)

for p_str, c in operations:
    p = int(p_str)
    index = positions[c][p-1]
    deleted[index] = True

result = ''.join(t[i] for i in range(len(t)) if not deleted[i])
print(result)
```このソリューションでは、初期文字列を構築し、すべての文字の位置を事前計算し、単純なブール配列を使用して削除を追跡します。 使用する`positions[c][p-1]`スキャンの繰り返しを回避します。これがブルート フォースよりも主な高速化になります。 最終的な再構築では、削除された位置が無視され、正しい順序が維持されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    k = int(input())
    s = input().strip()
    n = int(input())
    operations = [input().split() for _ in range(n)]

    t = s * k
    positions = {chr(c): [] for c in range(ord('a'), ord('z')+1)}
    for i, char in enumerate(t):
        positions[char].append(i)
    deleted = [False] * len(t)
    for p_str, c in operations:
        p = int(p_str)
        index = positions[c][p-1]
        deleted[index] = True
    return ''.join(t[i] for i in range(len(t)) if not deleted[i])

# Provided sample
assert run("2\nbac\n3\n2 a\n1 b\n2 c\n") == "acb", "sample 1"

# Custom cases
assert run("3\naa\n2\n1 a\n3 a\n") == "aaaa", "multiple same character deletions"
assert run("1\nabc\n0\n") == "abc", "no deletions"
assert run("2\nab\n4\n1 a\n1 a\n1 b\n1 b\n") == "", "all characters deleted"
assert run("5\na\n3\n1 a\n1 a\n1 a\n") == "aa", "single character repeated"
```| テスト入力 | 期待される出力 | 検証内容 |

 | 1\nabc\n0 | ABC | 削除はなく、文字列は変更されません。 
| 2\nab\n4\n1 a\n1 a\n1 b\n1 b | | すべての文字が削除されました |
