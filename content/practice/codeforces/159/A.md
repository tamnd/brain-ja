 ## 解決策
 ## 問題の理解

 私たちは、ソーシャル ネットワーク内のユーザー間のプライベート メッセージの時系列のログを受け取ります。 各レコードには、メッセージの送信者、受信者、およびタイムスタンプが含まれます。 

2 人のユーザーのうちの 1 人がもう一方のメッセージにすぐに返信した場合、2 人のユーザーは友達になります。 より正確に言うと、ユーザーを想定します`A`ユーザーにメッセージを送信します`B`時に`t1`、以降のユーザー`B`ユーザーにメッセージを送信します`A`時に`t2`。 もし`0 < t2 - t1 <= d`の場合、2 番目のメッセージは最初のメッセージに対する返信としてカウントされます。 2 人のユーザーの間にそのような返信が少なくとも 1 つ存在すると、そのユーザーは友達とみなされます。 

タスクは、メッセージ履歴から形成できるすべての友情ペアを見つけることです。 

入力サイズが小さいです。 メッセージ数は最大です`1000`、したがって、`O(n^2)`このソリューションは最大 100 万個のペア チェックを実行しますが、これは 3 秒の制限時間内で完全に安全です。 高度なデータ構造や最適化のテクニックは必要ありません。 

主な課題は、応答条件を正しく処理することです。 メッセージはすでに時間順に並べ替えられていますが、タイムスタンプが同じである可能性があり、厳密に後のメッセージのみが返信としてカウントされます。 ゼロの差は無効です。 

簡単な間違いの 1 つは、返信の方向を忘れることです。 

次の入力を考えてみましょう。```
2 5
alice bob 1
alice bob 3
```正しい出力:```
0
```どちらのメッセージも送信元は`alice`に`bob`。 応答するには方向を逆にする必要があります。 

もう 1 つの微妙なケースは、時間に対する厳密な不平等です。```
2 5
alice bob 10
bob alice 10
```正しい出力:```
0
```タイムスタンプは等しいので、`t2 - t1 = 0`を満たさない`0 < t2 - t1`。 

3 番目のトラップは、重複した友情ペアを印刷することです。```
4 10
alice bob 1
bob alice 2
alice bob 3
bob alice 4
```正しい出力:```
1
alice bob
```有効な応答が複数存在する場合でも、そのペアは 1 回だけ出現する必要があります。 

## アプローチ

 ブルートフォース手法では、順序付けられたすべてのメッセージのペアがチェックされます。 

メッセージを仮定します`i`は：```
A -> B at time t1
```そしてメッセージ`j`は：```
B -> A at time t2
```もし`i < j`そして`0 < t2 - t1 <= d`の場合、2 番目のメッセージは有効な応答であるため、`A`そして`B`友達になる。 

友情の定義はメッセージのペアのみに依存するため、この方法は正しいです。 考えられるすべてのペアをチェックすることで、有効な相互作用を見逃すことはありません。 

最悪の場合のパフォーマンスは約`1000 × 1000 = 1,000,000`比較は簡単に十分に高速です。 

重要な観察は、制約が十分に小さいため、総当たりのアイデアが実際にはすでに最適化されているということです。 スライディング ウィンドウやハッシュ ベースのタイムスタンプ追跡によってソリューションを複雑にする必要はありません。 

唯一の追加の詳細は、友情ペアを重複せずに保存する方法です。 友情は対称的であるため、`(alice, bob)`そして`(bob, alice)`同じ関係を表します。 セットに挿入する前に 2 つの名前をアルファベット順に並べ替えることで、各ペアを正規化できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(k) | 承認済み |
 | 最適 | O(n²) | O(k) | 承認済み |

 ここ、`k`は友情ペアの数です。 

## アルゴリズムのチュートリアル

 1. すべてのメッセージを配列に読み取ります。 
2. という空のセットを作成します。`friends`。 

このセットは、重複する友情ペアを自動的に削除します。 
3. メッセージのすべてのペアを反復処理します。`(i, j)`そのような`j > i`。 

ログは時系列なので、メッセージ`j`メッセージより早くなることはありません`i`。 
4.メッセージを送りましょう`i`なれ`(a1, b1, t1)`そしてメッセージ`j`なれ`(a2, b2, t2)`。 
5. 方向が逆になっていないか確認してください。 

必要なものは次のとおりです。```
a1 == b2
b1 == a2
```これは、2 番目のメッセージが元の送信者に返されることを意味します。 
6. 時差が次の条件を満たしているかどうかを確認します。```
0 < t2 - t1 <= d
```応答は同時に発生することができないため、差は厳密に正である必要があります。 
7. 両方の条件が当てはまる場合は、正規化されたペアをセットに挿入します。 

私たちは以下を保管します:```
tuple(sorted([a1, b1]))
```両方の方向が同じ友情にマッピングされるようにします。 
8. すべてのペアを処理した後、セットとすべての友情ペアのサイズを出力します。 

### なぜ効果があるのか

 このアルゴリズムは、考えられるすべての早い時間と遅い時間のメッセージのペアを検査します。 友情は、返信条件を満たすペアが少なくとも 1 つある場合にのみ成立します。 どのペアもスキップされないため、すべての有効な友情が発見されます。 

正規化ステップにより、メッセージの方向に関係なく、同じ友情が一意に表現されることが保証されます。 結果はセットに格納されるため、同じユーザー間で有効な応答を繰り返しても、重複した出力行が作成されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())

    messages = []

    for _ in range(n):
        a, b, t = input().split()
        messages.append((a, b, int(t)))

    friends = set()

    for i in range(n):
        a1, b1, t1 = messages[i]

        for j in range(i + 1, n):
            a2, b2, t2 = messages[j]

            if a1 == b2 and b1 == a2:
                diff = t2 - t1

                if 0 < diff <= d:
                    friends.add(tuple(sorted((a1, b1))))

    print(len(friends))

    for a, b in friends:
        print(a, b)

solve()
```すべてのメッセージをその後のすべてのメッセージと比較する必要があるため、解決策はすべてのメッセージをリストに保存することから始まります。 

ネストされたループにより、時系列順が自動的に強制されます。 以来`j > i`、2 番目のメッセージが最初のメッセージより早くなることはありません。 

方向のチェックは実装の最も重要な部分です。 送信者と受信者が入れ替わるメッセージのみを受け入れます。 同じ方向の 2 つのメッセージは応答ペアを形成できません。 

時間条件では厳密な正の値が使用されます。```
0 < diff <= d
```使用する`diff >= 0`同時メッセージを誤って受け入れてしまう可能性があります。 

友情ペアは、セットに挿入される前に正規化されます。 ソートせずに両方とも`(alice, bob)`そして`(bob, alice)`どちらの応答が最初に見つかったかに応じて、個別に表示される場合があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n²) | メッセージの各ペアが 1 回チェックされます。 
| スペース | O(k) | 友情セットは最大でストアされます`k`unique pairs |

 と`n ≤ 1000`、二次スキャンは最悪の場合でも約 100 万回の比較を実行しますが、これは指定された制限内の Python にとっては些細なことです。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    def solve():
        n, d = map(int, input().split())

        messages = []

        for _ in range(n):
            a, b, t = input().split()
            messages.append((a, b, int(t)))

        friends = set()

        for i in range(n):
            a1, b1, t1 = messages[i]

            for j in range(i + 1, n):
                a2, b2, t2 = messages[j]

                if a1 == b2 and b1 == a2:
                    diff = t2 - t1

                    if 0 < diff <= d:
                        friends.add(tuple(sorted((a1, b1))))

        out = [str(len(friends))]

        for a, b in sorted(friends):
            out.append(f"{a} {b}")

        return "\n".join(out)

    return solve()

# provided sample
assert run(
    "4 1\n"
    "vasya petya 1\n"
    "petya vasya 2\n"
    "anya ivan 2\n"
    "ivan anya 4\n"
) == (
    "1\n"
    "petya vasya"
), "sample 1"

# minimum-size input
assert run(
    "1 5\n"
    "alice bob 1\n"
) == (
    "0"
), "single message cannot form friendship"

# equal timestamps should not count
assert run(
    "2 5\n"
    "alice bob 10\n"
    "bob alice 10\n"
) == (
    "0"
), "difference must be strictly positive"

# multiple replies but only one friendship
assert run(
    "4 10\n"
    "alice bob 1\n"
    "bob alice 2\n"
    "alice bob 3\n"
    "bob alice 4\n"
) == (
    "1\n"
    "alice bob"
), "duplicate friendships must be removed"

# boundary condition diff == d
assert run(
    "2 3\n"
    "a b 5\n"
    "b a 8\n"
) == (
    "1\n"
    "a b"
), "difference equal to d is valid"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一メッセージ | 友人関係0 | 最小サイズの動作 |
 | 等しいタイムスタンプ | 友人関係0 | 厳密な不平等`t2 > t1`|
 | 複数の有効な返信 | たった一つの友情 | 重複の削除 |

 ## 特殊なケース

 同時メッセージを考慮してください。```
2 5
alice bob 10
bob alice 10
```アルゴリズムは 2 つのメッセージを比較し、次のように計算します。```
diff = 10 - 10 = 0
```という条件なので、`0 < diff <= d`、ペアは正しく拒否されます。 を使用した不注意な実装`diff >= 0`誤って友達としてマークされてしまいます。 

次に、繰り返される会話を考えてみましょう。```
4 10
alice bob 1
bob alice 2
alice bob 3
bob alice 4
```アルゴリズムは友情を何度か検出しますが、挿入のたびに次のものが使用されます。```
tuple(sorted((a1, b1)))
```これは常に以下を生成します:```
(alice, bob)
```結果はセットに保存されるため、重複は自動的に消えます。 

最後に、一方向のみのメッセージを考慮します。```
3 10
alice bob 1
alice bob 2
alice bob 3
```すべての比較は逆方向チェックに失敗します。```
a1 == b2 and b1 == a2
```したがって友情は追加されません。 出力は正しく次のようになります。```
0
```
