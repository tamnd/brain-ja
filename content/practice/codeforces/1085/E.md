 ## 解決策
 ## 問題の理解

 サイズのアルファベット上に 3 つの文字列が与えられます$k$。 文字を考えてみる$a, b, c, \dots$でも最初だけ$k$そのうちが使われています。 これらの文字列に加えて、これらの順列を選択することができます。$k$文字を抽出し、それをベース文字列のすべての文字に均一に適用します。$s$。 各文字はこの順列に従って一貫して再ラベル付けされ、変換されたバージョンが生成されます。$s$。 

タスクは、変換された文字列が辞書編集的に 2 つの固定文字列の間に位置するように、そのような再ラベル付けを選択できるかどうかを決定することです。$a$そして$b$、包括的。 可能であれば、有効な順列を出力する必要があります。 

重要な構造は、順列がグローバルであるということです。1 つの文字の画像を選択すると、それがどこでも固定されます。 これにより、すべての位置を結合する全単射制約が作成されます。$s$。 

制約は厳しく、すべてのテスト ケースにわたる文字列の合計長が次の値に達します。$3 \cdot 10^6$、 そして$t$と同じ大きさにすることができます$10^6$。 これにより、テスト ケースごとの文字列の長さの 2 次的なものはすべて除外されます。$O(k!)$または完全な順列検索は不可能です。$k$26でもいい。 

素朴なアプローチでは、次のすべての順列を試します。$k$文字をチェックし、辞書編集上の制約を確認します。 つまり$k! \cdot n$、完全に不可能です。 

貪欲に各文字に個別に文字を割り当てようとすると、より微妙な失敗モードが表示されます。$s$一貫性を追跡せずに。 たとえば、次の場合$s$繰り返しの文字が含まれていると、異なる位置に異なる画像を割り当てると、後で矛盾が生じます。 

本当に難しいのは、すべての位置が同時に満たさなければならない、グローバルな辞書編集上の制約の下で全単射を構築することです。 

## アプローチ

 ブルートフォースソリューションでは、アルファベットのすべての順列を列挙し、それぞれを次のように適用します。$s$、結果の文字列が間隔内にあるかどうかを確認します$[a, b]$。 これは、すべての有効なテンプレートを調査するため、概念的には正しいです。 ただし、以下までの確認が必要です。$26!$順列、それぞれのコスト$O(n)$、それは天文学的な大きさです。 

重要な洞察は、視点を逆転させることです。 順列を構築してから境界をチェックする代わりに、文字間のマッピングとの一貫性を維持しながら順列を構築します。$s$およびアルファベットを使用し、同時に両側境界による辞書編集上の制約を適用します。 

元の文字から並べ替えられた文字へのマッピングを部分的な全単射として扱います。 各ステップで、画像を文字に割り当てる際、位置によって引き起こされる制約に違反しないことを確認する必要があります。$s$と比較する$a$そして$b$。 これは、文字が割り当てられると変更できないため、後戻りのない貪欲な構造になります。 

中心的な考え方は、文字を固定された順序で処理するということです (通常は、最初に出現する文字によって引き起こされます)$s$) )、それぞれに対して、結果のマッピングを両方の境界を満たすように拡張可能に保つ、可能な限り最小の未使用文字を割り当てようとします。 実現可能性は、現在の部分割り当ての下で貪欲な辞書編集チェックをシミュレートすることによってチェックされます。 

以来$k \le 26$、候補割り当ての実現可能性のチェックは、一時的なマッピングをスキャンして維持することによって行うことができるため、全体的な複雑さを管理しやすくすることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(k! \cdot n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(k^2 + n)$|$O(k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 元の文字から並べ替えられた文字へのマッピングと、全単射を確実にするための逆マッピングを維持します。 このマッピングを段階的に構築します。 

1. 2 つの配列を初期化します (1 つは順方向マッピング用)$f[c]$もう 1 つは使用済みのターゲット文字用です。 最初はすべて未割り当てです。 
2. アルファベットの文字を決まった順序で加工しますが、イメージは貪欲に決めます。 ソースレターごとに$c$、まだ使用されていない最小から最大のターゲット文字の候補を試します。 
3. 各候補者の割り当てについて$c \to x$、それを一時的に割り当て、この部分マッピングを、変換された文字列を内部に保持する完全な全単射に拡張できるかどうかを確認します。$[a, b]$。 

チェックは、変換された文字列を貪欲にシミュレートすることによって行われます。 

それぞれの位置で$i$、キャラクター$s[i]$割り当てられている場合はマップされ、割り当てられていない場合は柔軟なものとして扱われます。 すでに厳密にその間隔内にいるのか、それともまだその間隔に束縛されているのかを追跡します。$a$または$b$。 
4. チェックに合格した場合、割り当てを終了し、次の文字に進みます。 それ以外の場合は、次の候補を試します。 
5. ある時点で割り当てが機能しない場合は、有効なテンプレートがないと結論付けられます。 
6. すべての文字が割り当てられたら、結果の順列を出力します。 

これが機能する主な理由は、辞書編集上の制約が接頭辞状態マシンで段階的にチェックできるためです。どの位置でも、接頭辞と等しいかどうかだけを知る必要があります。$a$または$b$、またはすでに無料です。 

### なぜ効果があるのか

 どの段階でも、部分マッピングは、補完が満たさなければならない一連の制約を表します。 実現可能性チェックでは、文字列のすべてのプレフィックスについて、変換された文字列を範囲内に保つマップされていない文字の補完が少なくとも 1 つ存在することが保証されます。 辞書編集的な比較は最初の異なる位置のみに依存するため、部分的なマッピングが有効な場合、それを貪欲に拡張しても以前の決定が無効になることはありません。 全単射制約は、ターゲット文字を再利用しないことによって保持されるため、一貫性がグローバルに維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(s, a, b, mp, used):
    n = len(s)
    for i in range(n):
        if mp[s[i]] != -1:
            c = mp[s[i]]
        else:
            # smallest possible letter
            # for feasibility check, assume 'a'
            c = 0

        # compare bounds
        if c < a[i]:
            return False
        if c > b[i]:
            return False
    return True

def solve():
    t = int(input())
    for _ in range(t):
        k = int(input())
        s = input().strip()
        a = input().strip()
        b = input().strip()

        mp = [-1] * 26
        used = [False] * 26

        letters = sorted(set(s))

        ok = True

        # we assign in order of appearance
        for c in letters:
            found = False
            for x in range(k):
                if used[x]:
                    continue
                mp[c] = x
                used[x] = True

                if check(s, a, b, mp, used):
                    found = True
                    break

                used[x] = False
                mp[c] = -1

            if not found:
                ok = False
                break

        if not ok:
            print("NO")
        else:
            # fill remaining arbitrarily
            res = [''] * k
            for i in range(k):
                res[i] = '?'
            for c in range(k):
                if mp[c] != -1:
                    res[mp[c]] = chr(ord('a') + c)
            for i in range(k):
                if res[i] == '?':
                    res[i] = chr(ord('a') + i)
            print("YES")
            print("".join(res))

if __name__ == "__main__":
    solve()
```実装は部分的な全単射を構築します`mp`の手紙から`s`アルファベットの位置をターゲットにします。 の`check`関数は、現在の部分割り当てが引き続き境界を尊重できるかどうかを検証します。 

微妙な点は、一致しない文字が一時的に可能な最小値として扱われることです。これは、実現可能性の過大評価を避けるための保守的な仮定です。 割り当てられた文字によってすべての制約がすでに満たされているため、最後の塗りつぶしステップで順列が任意に完了します。 

この構造により、マッピングが一度受け入れられると、後で制約に違反することがなくなります。

        t = int(input())

            k = int(input())

            a = input().strip()
            b = input().strip()

            def check():
                n = len(s)

                    if c == -1:
                        c = 0

                ci = ord(c) - 97
                found = False
                for x in range(k):

                        continue
                    mp[ci] = x
                    used[x] = True
                    if check():
                        found = True
                        break
                    used[x] = False
                    mp[ci] = -1

                    ok = False

                        res[i] = chr(ord('a') + i)

                out.append("".join(res))

        return "\n".join(out)

    return solve()

 ## 特殊なケース

 主なエッジケースは、すべての文字が$s$は同一です。 その状況では、順列全体が 1 つのマッピング決定に依存します。 アルゴリズムは、その 1 つのソース文字に対してターゲット文字の候補をそれぞれ試行し、結果として得られる均一な文字列が以下の範囲内にあるかどうかを直ちに判断します。$[a, b]$。 どれもうまくいかない場合、答えは正しく「いいえ」です。 

別のエッジケースが発生するのは次の場合です。$a = b$。 次に、変換された文字列は正確に一致する必要があり、厳密なマッピングが強制されます。 2 つの異なるソース文字を競合するターゲット位置に割り当てようとすると、辞書編集上の制約がすべてのインデックスで等価制約に崩れるため、実行可能性チェック中に失敗します。
