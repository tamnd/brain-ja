 ## 問題の理解

 2 つの整数、乗算式から構築されたターゲット値、および正の整数を商と剰余に分割する方法を制御する固定基本パラメータが与えられます。 

任意の正の整数の場合$x$、に関して分割します。$k$2 つの部分に分割: 除算の整数部分。サイズの完全なブロックの数を数えます。$k$に適合する$x$、およびそれらのブロックを削除した後に残った部分。 次に、これら 2 つの値を乗算し、その結果が等しいことを要求します。$n$。 タスクは最小の正の整数を見つけることです$x$この条件を満たすものです。 

式の構造からわかることは、$x$は任意ではなく、商と余りがどのように相互作用するかによって決まります。 以来$k \le 1000$、 それぞれ$x$は小さな商と有限の剰余に分解できます。これは、これらのコンポーネントのいずれかを反復することを強く推奨します。$x$自体。 

の範囲$n$まで上がります$10^6$、したがって、可能なすべてを反復する解決策$x$大きな値までは遅すぎます。 直接検索$x$まで$10^6 \cdot k$すでに境界線に達しており、二次関数またはネストされたものはすべて$x$明らかに不可能です。 

商と余りがどのように相互作用するかを考えると、微妙な問題が生じます。 多くの間違ったアプローチは修正しようとします$x \bmod k$そして計算する$x \div k$独立していますが、一方を変更すると、定義を通じてもう一方に影響を与えることを忘れてください。$x = (x \div k)\cdot k + (x \bmod k)$。 それらを独立変数として扱うと、無効な変数が構築されることになります。$x$。 

## アプローチ

 ブルートフォース手法では、すべての正の整数が試行されます。$x$、両方を計算します$x \div k$そして$x \bmod k$、それらを乗算し、結果が次と等しいかどうかを確認します。$n$。 これは問題の定義に直接従うため、正しいです。 ただし、最悪の場合、すべての値をチェックする必要があるかもしれません。$x$最初の有効な解が見つかるまで、有効な解は遠く離れている可能性があるため、これはすぐに実行不可能になります。 までチェックしても$10^6 \cdot k$オペレーションはすでに大規模すぎて、厳しい制限時間には対応できません。 

重要な観察は、次の観点から考えるのをやめるということです。$x$代わりに、その商の観点から考えてください。 させて$q = x \div k$そして$r = x \bmod k$。 それから$x = qk + r$と$0 \le r < k$、条件は単純な積制約になります。$q \cdot r = n$。 これにより、問題は整数の検索から因数のペアの検索に移行します。$n$。 

約数を固定したら$q$の$n$、対応する剰余は次のようにする必要があります。$r = n / q$。 このペアが有効であるためには、残りが次の条件を満たす必要があります。$r < k$、モジュロから来ているので$k$。 有効な各ペアは候補を直接再構築します。$x = qk + r$。 このような候補すべての中で、最小のものを選択します。 

この削減は強力です。$n$十分に小さいため、すべての約数を反復処理するのは高速であり、制約は$k \le 1000$各候補の検証が簡単になります。

 ## アルゴリズムのチュートリアル

 1. すべての整数を反復処理します。$q$1から$\sqrt{n}$。 これが機能するのは、すべての約数が次の値よりも大きいためです。$\sqrt{n}$対応する小さい対応物があります。 
2. それぞれについて$q$、分割されるかどうかを確認します$n$。 そうでない場合は、有効な製品ペアを形成できないため、スキップしてください。 
3. ペアの約数を計算します$r = n / q$。 この時点で、$(q, r)$の分解候補です$n$。 
4. 有効なペアごとに、両方の解釈を考慮します。$q$商として、そして$r$残りの候補として、またはその逆。 これが必要なのは、因子ペアのどちらかの側が商の役割を果たすことができるためです。 
5. 各解釈について、剰余候補が厳密に以下であるかどうかを検証します。$k$。 これにより、法的にモジュロ値にできることが保証されます。 
6. 有効な場合は再構築する$x = qk + r$（または$x = rk + q$）すべての有効な構造にわたって最小値を追跡します。 

中心的な考え方は、すべての有効な解は、次の因子ペアに一意に対応するということです。$n$、すべての因子ペアは最大 2 つの候補値を生成します。$x$。 

### なぜ効果があるのか

 すべての整数$x$ペアを一意に定義します$(q, r)$どこ$x = qk + r$そして$0 \le r < k$。 問題の条件は次のようになります$q \cdot r = n$したがって、すべての有効な解は次の因数分解に対応します。$n$。 逆に、剰余制約を尊重するすべての因子ペアは、有効な$x$。 すべての因子のペアを列挙するため、解を見逃すことはなく、再構成するため、$x$除算と剰余の定義から直接、無効な値が生成されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    ans = None

    q = 1
    while q * q <= n:
        if n % q == 0:
            r = n // q

            # case 1: q is quotient, r is remainder
            if r < k:
                x = q * k + r
                if ans is None or x < ans:
                    ans = x

            # case 2: r is quotient, q is remainder
            if q < k:
                x = r * k + q
                if ans is None or x < ans:
                    ans = x

        q += 1

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、除数ペア ロジックを直接実装しています。 ループオーバー$q$は因数の候補を列挙し、有効な約数のペアが見つかるたびに、商と剰余の役割の両方の可能な割り当てを直ちにテストします。 再建$x = qk + r$整数除算の定義から直接従うため、追加のシミュレーションは必要ありません。$x$が必要です。 

役割の交換に失敗すると、小さい方の除数が残りとして機能する有効な構成が失われるため、両方向のチェックには注意が必要です。

 ## 特殊なケース

 重要なエッジケースは次の場合に発生します。$n = 1$。 唯一の因数ペアは (1,1) であり、正しさは商と剰余の両方の方向を正しく解釈することに依存します。 のために$n=1, k=2$、私たちは得ます$x = 2 \cdot 1 + 1 = 3$、を満たす$3 \div 2 = 1$そして$3 \bmod 2 = 1$、製品1を与えます。 

別の微妙なケースが発生する場合$k$に比べて大きい$n$。 例えば、$n=2, k=1000$。 唯一の有効な構造は、2 を商として、1 を余りとして扱うことによって得られます。$x = 2k + 1$。 このアルゴリズムは、すべての要素ペアの両方向を明示的にチェックし、1 つのコンポーネントがそれよりはるかに小さい場合でも有効な構成がスキップされないようにするため、これを処理します。$k$。
