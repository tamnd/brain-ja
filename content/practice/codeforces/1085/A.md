 ## 解決策
 ## 問題の理解

 右側に文字を追加し、左側に文字を挿入することを交互に行って、別の隠し文字列を繰り返し構築した最終結果である文字列が得られます。 このプロセスは最初の文字から始まり、2 番目の文字を現在の文字列の右に配置し、3 番目の文字を現在の文字列の左に配置し、4 番目の文字を再び右に配置するというように外側に向かって構築されます。 

タスクは、このプロセスを逆にすることです。 構築をシミュレートする代わりに、最終的にスクランブルされた結果が与えられ、左右の挿入が発生する前に元の文字シーケンスを復元する必要があります。 

重要な点は、暗号化中に文字が両端に挿入されるにもかかわらず、操作の順序が決定的であり、右、左、右、左、交互であるということです。 これは、最終的な文字列が任意ではないことを意味します。 これは、移動する中心に対して既知の位置に配置された文字で構成されます。 

長さが最大 ​​50 であるという制約により、すべてが変わります。 動的構造への挿入をシミュレートするソリューションはどれも簡単に十分に高速ですが、O(n) の構築順序を逆にすることで直接再構築することもできます。 

長さが奇数と偶数の場合、微妙なエッジケースが発生します。 たとえば、単一の文字では何も変わりません。 2 文字の場合、2 番目の文字は常に右側に追加されます。 3 文字の場合、3 番目の文字が左側に追加されるため、中央の構造が移動します。 ステップのパリティを追跡せずに、常に 1 つの固定方向から交互に切り替えるという単純な試みでは、正しく再構築できません。 

もう 1 つのよくある落とし穴は、「中心」が暗黙的に移動し続けることに気づかずに、文字列を左から右に再構築しようとすることです。 正しい再構築は、各ステップが順方向プロセスの左側に挿入されるか右側に挿入されるかを知ることに依存します。これは純粋にインデックス パリティによって決定されます。 

## アプローチ

 ブルートフォース解釈では、考えられるすべての元の文字列をシミュレートし、その暗号化が指定された文字列と一致するかどうかをテストします。 候補文字列の数が 26^50 であり、各シミュレーションのコストが O(n) であるため、長さが 50 の場合でもこれは直ちに実行不可能であり、天文学的に大きな検索空間が必要になります。 

重要な洞察は、文字がどのように追加されたかを考えると、暗号化は段階的に元に戻せるということです。 各ステップでは、現在の文字列の左端または右端に新しい文字を 1 つだけ挿入します。 つまり、逆に、決定的なパターンでどちらかの端から文字を剥がすことができるということです。 

構築プロセスを順にシミュレートすると、文字列の末尾に挿入を繰り返して変更することになり、これは両端キュー構造を示唆します。 しかし、逆に、最終的な文字列はすでにわかっているので、逆の順序で操作を元に戻すことで元の文字列を再構築できます。最後の操作はステップ インデックスのパリティによって決まります。 

最後に挿入された文字が n が奇数か偶数かによって異なることを認識してプロセスをリバース エンジニアリングし、元の文字列を再構築しながら対応する端から文字を繰り返し削除します。

 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 最終的な文字列がどのように構築されるかを逆の順序でシミュレートすることにより、元の文字列を再構築します。

1. 指定された文字列の長さ n を決定します。 これは、暗号化中に発生する挿入ステップの数を定義します。 
2. 進化する再構成結果を表す構造を維持します。 両端から効率的に削除する必要があるため、両端キューを使用します。 
3. すべての操作後の現在の状態として、最後の文字列 t から開始します。 
4. ステップ n から 2 までの取り消し操作をシミュレートします。各ステップ i で、i 番目の文字 (前方構文) が左側または右側のどちらに配置されたかを決定します。 これはパリティによって異なります。奇数インデックスのステップは右側に挿入され、偶数インデックスのステップは左側に挿入されます。 
5. 逆に、ステップ i が右挿入の場合は、最後の文字を削除します。 左挿入の場合は、最初の文字が削除されます。 削除された文字は、再構築された元の文字列の位置 i に属します。 
6. 削除された文字を再構築の逆の順序で収集し、最終的に元の文字列を組み立てます。 

### なぜ効果があるのか

 各暗号化ステップでは、現在の文字列の既知の末尾に 1 文字だけが追加されます。 これは、最終的な文字列には元の文字列のすべての文字が含まれていますが、それらの位置は一連の決定的な末尾挿入の結果であることを意味します。 各操作は一方の端にのみ影響するため、プロセスを元に戻すには、推測したり後戻りしたりする必要はありません。 パリティ ルールは各ステップでどちらの端が使用されたかを一意に決定するため、逆方向のすべての削除は元の 1 つの文字位置に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = input().strip()
    n = len(t)

    # simulate reverse construction
    # we track current string as deque via pointers
    l, r = 0, n - 1

    res = []

    # we undo steps from n down to 1
    for i in range(n, 0, -1):
        if i == 1:
            # last remaining character is the first original char
            res.append(t[l])
        else:
            if i % 2 == 0:
                # even step: was left insertion -> undo from left
                res.append(t[l])
                l += 1
            else:
                # odd step: was right insertion -> undo from right
                res.append(t[r])
                r -= 1

    print("".join(res[::-1]))

if __name__ == "__main__":
    solve()
```このソリューションでは、最終文字列上に 2 つのポインターを保持し、対応する前方ステップが左挿入か右挿入かに応じて文字を削除します。 重要な実装の詳細は、元の文字列を逆の順序で再構築するため、最後に収集された文字を逆順に配置することです。 

すべての削除の後、ちょうど 1 文字が残り、それが元の文字列の最初の文字でなければならないため、i == 1 の境界条件は重要です。

 ## 特殊なケース

 入力用`a`、アルゴリズムセット`l = r = 0`、そして直接追加します`t[l]`、生産`a`。 単一の文字列が暗号化によって変更されないという事実と一致して、削除は発生しません。

次のような小さな入力を交互に行う場合`bac`、ポインタの移動により、左右の削除が挿入の反転を正しくシミュレートし、パリティベースの終了選択が曖昧さなく元の順序を完全に決定することが確認されます。
