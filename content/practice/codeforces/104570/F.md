 ## 解決策
 ## 問題の理解

 私たちは、ポイント更新、範囲演算、確率的ビット反転を通じて時間の経過とともに変化する 20 ビット整数の配列を操作しています。 主な問題は、一部の操作でランダム性が導入されるため、これらの進化する分布の下で部分配列に対するペアごとの XOR 統計の期待値を維持する必要があることです。 

各クエリは、単一の位置を上書きするか、範囲内のすべての要素にランダムなビット単位の摂動を適用するか、範囲内の 2 つのランダムに選択された個別のインデックスの XOR の期待値を要求します。 ランダム性は、影響を受けるセグメント内の位置ごとに 0 から 19 までのビット位置を個別に選択し、そのビットを切り替えることで得られます。 

タイプ 3 の各クエリの出力は期待値ですが、浮動値として返されません。 代わりに、これは大きな素数を法として生成される必要がある有理数です。 このため、ランダム性をシミュレートするのではなく、正確な確率的寄与を維持する必要があります。 

この制約は、操作ごとに O((n + q) log n) または O((n + q) * 20) に近い解を提案します。 最大 40,000 の演算と 20 ビットでは、ビットごとのセグメント ツリーまたは線形代数スタイルの分解が必要になる可能性があります。 

単純なソリューションでは、クエリされた範囲内のすべてのペアを列挙し、各値の分布を追跡することによって期待値を再計算します。 1 つのクエリに O(n^2) ペアのチェックが含まれる可能性があるため、これはすぐに失敗します。 

2 番目の単純なアイデアは、ランダム性をシミュレートすることです。 更新ごとに、実際にはビットをランダムに反転し、配列を維持します。 しかし、サンプリング中は期待値が安定していません。 差異があると正しさが損なわれてしまいます。 

さらに微妙な落とし穴は、ランダムな XOR 演算を繰り返した後に要素間の独立性を仮定することです。 ビットは操作ごとに独立して影響を受けますが、位置間の相関関係は蓄積され、生の値のみを追跡する場合は無視できません。 

具体的な失敗例は、同じ範囲が複数回ランダム化された場合に発生します。 2 回の操作の後、各ビットの確率分布は均一ではなくなります。 独立したベルヌーイ状態の混合になるため、単純な「ビット確率を 1/2 に設定する」は誤りです。 

## アプローチ

 中心となるアイデアは、完全な整数についての推論をやめ、代わりに予想される XOR を各ビット位置からの独立した寄与に分解することです。 

整数 x と y の任意のペアについて、XOR 値は、2^k で重み付けされた、そのビットで異なるかどうかのビットの合計です。 したがって、期待される XOR は、ビット k が 2 つの位置間で異なる確率の線形結合です。 これにより、問題は、ビットごとに独立して、位置にそのビットが設定されている確率を追跡することに変換されます。 

ブルートフォース手法では、2^20 の状態にわたって各配列要素の完全な確率分布を維持することになりますが、これは不可能です。 値ごとの確率を保存するだけでも、指数関数的な状態爆発が発生します。 

重要な観察は、各操作がビットに独立かつ対称的に影響を与えるということです。 タイプ 2 の操作は、20 ビットの中から均一に選択されたビットを反転します。これは、各ビットについて、ある位置でトグルされる確率が 1/20 であることを意味します。 これにより、ビットが 1 である確率に線形変換が行われます。 

したがって、各ビット k について、a[i] のビット k が 1 に等しい確率である p[i][k] を維持するだけで済みます。範囲演算では変換が適用されます。p は p * (19/20) + (1 - p) * (1/20) となり、1/2 からの偏差の縮小が単純化されます。 つまり、各ビットの確率は乗算的に 1/2 に近づきます。 

これにより、構造が線形で構成可能になるため、ビットごとのセグメント ツリーを使用して範囲の更新とクエリを維持し、確率の合計を保存し、遅延アフィン変換を適用できます。

最後に、範囲内で均一に選択された 2 つのインデックス間で期待される XOR は、各ビット k について、ペアで結合された分散様項の合計 p_i (1 - p_i) にのみ依存します。 ビットごとの p_i のプレフィックス合計と平方和を使用すると、クエリごとにビットごとに O(1) のペアごとの差を計算できます。 

したがって、アフィン遅延更新の下で、p の合計と p^2 の合計を格納するセグメント ツリーをビットごとに維持します。

 ## アルゴリズムのチュートリアル

 各ビットを独立して処理し、位置にわたるセグメント ツリーを維持します。 

各ビット k について、すべてのセグメントに格納します。 

sum1 はビット k が 1 である確率 p_i の合計です。 

sum2 は p_i の 2 乗の合計であり、ペアごとの計算に必要です。 

そして、p -> a * p + b という形式の遅延アフィン変換を維持します。 

### ステップ

 1. 各位置 i とビット k を、a[i] のビット k が設定されている場合は p_i = 1、そうでない場合は 0 で初期化します。これにより、開始時に決定論的分布がエンコードされます。 
2. ビットごとに 1 つずつ 20 のセグメント ツリーを構築し、範囲にわたって sum1 と sum2 を格納します。 これにより、あらゆるクエリ間隔にわたって期待値を高速に集計できます。 
3. タイプ 1 クエリの場合、単一の位置 i を更新します。 20 ビットの確率を再計算し、これらの更新をすべてのセグメント ツリーにプッシュします。 
4. 範囲にわたるタイプ 2 クエリの場合、変換を各ビットに個別に適用します。 各位置確率 p に対して、均一に選択されたビットとのランダム XOR によって誘導されるアフィン マップを適用します。 このマップは線形であるため、セグメント ツリーに遅延的に適用できます。 
5. 各ノードについて、変換 p -> a p + b を適用するときに、次のように更新します。 

sum1 は a * sum1 + b * len になります。 

sum2 は a^2 * sum2 + 2ab * sum1 + b^2 * len になります。 

これにより、後でペアの寄与を計算するために必要な情報がすべて保存されます。 

1. [l, r] に関するタイプ 3 クエリの場合、各ビット ツリーで sum1 と sum2 をクエリします。 これらから、次を使用して、ランダムに選択された 2 つのインデックスがそのビットで異なる確率を計算します。 

すべての i < j にわたる p_i (1 - p_j) の合計。これは集計合計から導出されます。 
2. 各ビットの寄与に 2^k を乗算し、すべての k を合計します。 最後に、範囲内のペアの数によって正規化します。 

### なぜ効果があるのか

 各ビットはすべての演算の下で独立して進化し、ランダム XOR 演算により各ビットの確率空間に線形変換が引き起こされます。 期待値は線形であるため、期待される XOR はビットの合計にきれいに分解されます。 セグメント ツリーは、ペアを列挙することなくペアごとの不一致確率を再構築するために十分な統計 (合計と二乗和) を維持します。 アフィン構造により、すべての更新が正しく構成されることが保証されるため、隠れた相関関係が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
INV20 = pow(20, MOD - 2, MOD)

class SegTree:
    def __init__(self, n):
        self.n = n
        self.size = 1
        while self.size < n:
            self.size <<= 1
        self.sum1 = [0] * (2 * self.size)
        self.sum2 = [0] * (2 * self.size)
        self.lazy_a = [1] * (2 * self.size)
        self.lazy_b = [0] * (2 * self.size)

    def apply(self, idx, a, b, length):
        s1 = self.sum1[idx]
        s2 = self.sum2[idx]

        self.sum2[idx] = (a * a % MOD * s2 + 2 * a * b % MOD * s1 + b * b % MOD * length) % MOD
        self.sum1[idx] = (a * s1 + b * length) % MOD

        self.lazy_a[idx] = self.lazy_a[idx] * a % MOD
        self.lazy_b[idx] = (self.lazy_b[idx] * a + b) % MOD

    def push(self, idx, length):
        if self.lazy_a[idx] == 1 and self.lazy_b[idx] == 0:
            return
        a = self.lazy_a[idx]
        b = self.lazy_b[idx]

        self.apply(idx * 2, a, b, length // 2)
        self.apply(idx * 2 + 1, a, b, length // 2)

        self.lazy_a[idx] = 1
        self.lazy_b[idx] = 0

    def pull(self, idx):
        self.sum1[idx] = (self.sum1[idx * 2] + self.sum1[idx * 2 + 1]) % MOD
        self.sum2[idx] = (self.sum2[idx * 2] + self.sum2[idx * 2 + 1]) % MOD

    def build(self, arr):
        for i in range(self.n):
            self.sum1[self.size + i] = arr[i]
            self.sum2[self.size + i] = arr[i] * arr[i] % MOD
        for i in range(self.size - 1, 0, -1):
            self.pull(i)

    def range_apply(self, l, r, a, b, idx, nl, nr):
        if r < nl or nr < l:
            return
        if l <= nl and nr <= r:
            self.apply(idx, a, b, nr - nl + 1)
            return
        self.push(idx, nr - nl + 1)
        mid = (nl + nr) // 2
        self.range_apply(l, r, a, b, idx * 2, nl, mid)
        self.range_apply(l, r, a, b, idx * 2 + 1, mid + 1, nr)
        self.pull(idx)

    def range_query(self, l, r, idx, nl, nr):
        if r < nl or nr < l:
            return (0, 0)
        if l <= nl and nr <= r:
            return (self.sum1[idx], self.sum2[idx])
        self.push(idx, nr - nl + 1)
        mid = (nl + nr) // 2
        s1l, s2l = self.range_query(l, r, idx * 2, nl, mid)
        s1r, s2r = self.range_query(l, r, idx * 2 + 1, mid + 1, nr)
        return (s1l + s1r, s2l + s2r)

n, q = map(int, input().split())
a = list(map(int, input().split()))

bits = []
for k in range(20):
    arr = [(a[i] >> k) & 1 for i in range(n)]
    st = SegTree(n)
    st.build(arr)
    bits.append(st)

for _ in range(q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 1:
        i, x = tmp[1] - 1, tmp[2]
        for k in range(20):
            bits[k].range_apply(i, i, 1 if (x >> k) & 1 else 0, 0, 1, 0, bits[k].size - 1)
    elif tmp[0] == 2:
        l, r = tmp[1] - 1, tmp[2] - 1
        a_aff = INV20 * 19 % MOD
        b_aff = INV20
        for k in range(20):
            bits[k].range_apply(l, r, a_aff, b_aff, 1, 0, bits[k].size - 1)
    else:
        l, r = tmp[1] - 1, tmp[2] - 1
        m = r - l + 1
        if m < 2:
            print(0)
            continue
        inv_pairs = pow(m * (m - 1) // 2, MOD - 2, MOD)
        ans = 0
        for k in range(20):
            s1, s2 = bits[k].range_query(l, r, 1, 0, bits[k].size - 1)
            total = m * m % MOD
            diff = (s1 * (m - s1) * 2) % MOD
            ans = (ans + diff * pow(2, k, MOD)) % MOD
        ans = ans * inv_pairs % MOD
        print(ans)
```この実装では、各ビットを独立した遅延セグメント ツリーに分離し、ランダムな XOR 更新にアフィン変換を適用します。 クエリは、合計を使用してビットごとの予想される不一致を計算します。 

## 実用的な例

 ### 例 1

 入力セグメント:```
a = [1, 0, 1]
query: expected XOR over full range
```ビットごとの寄与を計算します。 ビット 0 のみが重要です。 

| ステップ | 合計1 | 合計2 | メートル | 貢献 |
 | --- | --- | --- | --- | --- |
 | イニシャル | 2 | 2 | 3 | ペア (1,0),(0,1) |

 異なるペアの数は 2 で、合計ペアは 3 なので、期待値は 2/3 です。 

これは、ペア (1,0)、(1,1)、(0,1) の直接の列挙に一致します。 

### 例 2

 入力:```
a = [1, 1, 0, 0]
after random update over full range
query full range
```ランダムな XOR 演算を繰り返すと、各ビットは確率 1/2 に向かってドリフトします。 セグメント ツリーは、アフィン更新を繰り返すことでこの収束を維持します。 

異なるペアの期待数は、アフィン固定点と一致して、各ビットが期待値でペアごとに 1/2 を寄与する一様分布動作付近で安定します。 

| 状態 | p_i分布 | 合計1 | 解釈 |
 | --- | --- | --- | --- |
 | 開始 | 決定論的 | 2 | 構造化された |
 | 更新後 | 混合 | 2 | 1/2 に向かってドリフト |

 これは、ランダム XOR を繰り返すとアフィン構造は破壊されず、固定された確率的平衡に向けて情報が圧縮されるだけであることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、クエリされたセグメントのサイズが 1 である場合です。 その場合、順序付けされていないペアの数はゼロとなり、除算に基づく式はすべて短絡されなければなりません。 実装では、m < 2 の場合にゼロを直接返し、ゼロのモジュラー反転を回避することでこれを処理します。 

もう 1 つの微妙なケースは、全範囲のランダム XOR 演算が繰り返されることです。 適用されるアフィン変換は固定点に向かう縮小であるため、セグメント ツリーは遅延更新を正しく構成する必要があります。 遅延合成が単純な上書きに置き換えられた場合、更新が繰り返されると、変換が蓄積されるのではなく、ディストリビューションが誤ってリセットされ、タイプ 2 のクエリの長​​いシーケンスが中断されてしまいます。 

3 番目のケースは、ポイントの更新によって高度にランダム化された値が上書きされる場合に発生します。 ツリーはそのリーフで以前の確率構造を破棄し、決定論的な状態に再初期化する必要があります。そうしないと、古いアフィン タグが新しい値に漏れてしまいます。
