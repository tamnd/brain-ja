 ## 解決策
 ## 問題の理解

 1 価値のコイン、10 価値のコイン、および 100 価値のコインの 3 つのコイン タイプで構成される小さな「通貨システム」が与えられています。各テスト ケースについて、各タイプのコインが何枚利用可能であるかがわかっており、合計値がターゲット数と正確に等しくなるように、これらのコインの一部を選択できるかどうかを判断したいと考えています。 

各テスト ケースは独立しています。 何かを最小化または最大化する必要はなく、正確な合計を形成する可能性を判断することだけが必要です。 

制約は大きく、テスト ケースは最大 100,000 個で、各パラメーターは 1e9 まで大きくなる可能性があります。 これにより、コインの組み合わせを列挙したり、あらゆる可能性をシミュレートしようとするソリューションは即座に除外されます。 最悪の場合は 1e27 演算程度になるため、三重にネストされたループでカウントをオーバーすることさえ不可能です。 

値の構造が重要です。1、10、100 は 10 の累乗です。 これは、より高い額面は小数点以下の上位にのみ影響し、制限された範囲を超えてより低い額面で補うことができないため、貪欲な桁ごとの構築を強く示唆しています。 

階層を尊重せずにコインを独立して扱うと、単純な間違いが発生します。 たとえば、10 コインと 1 コインで残りの実現可能性を確認せずに、貪欲に最初に 100 コインで合計を満たそうとすると失敗する可能性があります。 

これを示す簡単なエッジケースは次のとおりです。 

入力:```
a = 9, b = 0, c = 1, n = 10
```ここでは、10 コイン 1 枚 (利用不可) を使用するか、1 コイン 10 枚と 100 コインマイナス調整ロジック 1 つを使用して 10 を形成できますが、実際にはコインを減算することはできません。 最初に 100 コインを取るという不注意で貪欲な選択をすると、実現可能性を誤って仮定することになります。 

正しい答えは次のとおりです。```
NO
```なぜなら、100 コインをその一定の寄与を超えてより小さな値に「分割」することはできないからです。 

最も難しいのは、コイン制限を尊重しながらレベル間の相互作用を正しく処理することです。 

## アプローチ

 ブルートフォースアプローチでは、100 コイン、10 コイン、1 コインの可能なすべてのカウントが試行されます。 x 100 コイン、y 10 コイン、z 1 コインのそれぞれの選択について、次のことを確認します。 

x * 100 + y * 10 + z = n

 x ≤ c、y ≤ b、z ≤ a という制約があります。 

x、y、z をその限界まで反復したとしても、これは O(abc) であり、それぞれが最大 1e9 になる可能性があるため、これはまったく実行不可能です。 

重要な観察は、コイン システムが 10 進数で位置決めされているということです。1 コインと 10 コインは合計の下 2 桁を完全に制御しますが、100 コインはそれ以上のすべてを決定します。 これは、すべての組み合わせを検索する必要はなく、1 つのレベルを貪欲に調整するだけで残りを修正できることを意味します。 

まずは100コインを処理します。 できるだけ多くの値を使用するよう努めますが、n // 100 を超えず、c を超えないようにしてください。 この選択を修正すると、残る問題は 10 コインと 1 コインを使用して余りを形成することになります。 この削減された問題は、再び貪欲に解決できます。できるだけ多くの 10 コインを使用し、残りの価値が利用可能な 1 コインに収まるかどうかを確認します。 

この構造により、低額通貨では高額単位の不足を補うことができないため、高額面での決定が低額から独立していることが保証されます。

 ## アルゴリズムのチュートリアル

 1. 目標または在庫を超えない範囲で、できるだけ多くの 100 価値コインを使用するようにしてください。 x = min(c, n // 100) を計算します。 このステップにより、高額コインを使用しても目標を超過しないことが保証されます。 
2. ターゲットからその寄与を差し引くと、n は n − 100·x になります。 これにより、より小さなコインを使用して形成する必要がある残りの価値が分離されます。 
3. 次に、10 価値のコインを同様に使用してみます: y = min(b, n // 10)。 これにより、残額を超過することなく中コインの使用量が最大化されます。 
4. それらの寄与を差し引くと、n は n − 10・y になります。 この時点では、1 価値のコインのみが関連します。 
5. 残額が利用可能な 1 コインの数以下であるかどうかを確認します。 そうであれば、合計は達成可能です。 そうでなければ不可能です。 

### なぜ効果があるのか

 正しさは、各コイン タイプが次に小さいタイプの 10 倍であるという事実から来ています。これにより、レベル間のトレードオフが排除されます。100 コインの使用量を減らしても、10/1 の範囲で実現可能性が高まる場合を除き、役に立ちません。しかし、100 コインを減らしても、必要な剰余が 100 の倍数だけ増加するだけであり、すでに処理されているモジュラー制約を超えて 10 コインや 1 コインで修復することはできません。 同じ理由が 10 から 1 にも当てはまります。各ステップでは、次のステップに進む前に現在の桁の位置が完全に飽和するため、最適な解が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c, n = map(int, input().split())

        use_100 = min(c, n // 100)
        n -= use_100 * 100

        use_10 = min(b, n // 10)
        n -= use_10 * 10

        if n <= a:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```実装は、説明どおりに貪欲なリダクションに従います。 唯一の微妙な点は、各額面ステップの後に残りの値を更新することです。 これは、次のコイン タイプに移動する前に行う必要があります。そうしないと、後の決定が古い状態に基づいて行われることになります。 

すべての算術演算は安全な整数範囲内に収まり、各テスト ケースは入力サイズを考慮して必要な一定時間で処理されます。

```| ステップ | 100コイン使用 | 残り n | 10コイン使用 | 残り n | 必要なコインは1コインです |

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        a, b, c, n = map(int, input().split())
        use_100 = min(c, n // 100)
        n -= use_100 * 100

        use_10 = min(b, n // 10)
        n -= use_10 * 10

        out.append("YES" if n <= a else "NO")
    return "\n".join(out)

 ## 特殊なケース

 微妙なケースの 1 つは、ターゲットがゼロの場合です。 このアルゴリズムは、すべての額面で直ちに減額し、n ≤ a をチェックします。これは、n が 0 であるため当てはまります。これは、コインが存在しない場合でも、正しく YES を返します。 

もう 1 つのケースは、高額な額面が潜在的な組み合わせをオーバーシュートする場合です。 常に min(available, n // value) で使用量をクランプするため、必要以上に減算することはなく、負の剰余を防ぎます。 

3 番目のケースは、最適なソリューションが貪欲な選択よりも使用する高額コインの数が少ない場合です。 より多くの価値の高いコインを取得しても、より低い額面での実現可能性が低下することは決してないため、このようなことは起こり得ません。 残りの合計を 100 または 10 の倍数で減らすだけであり、残余の問題空間での可解性が維持されます。
