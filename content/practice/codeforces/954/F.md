 ## 解決策
 ## 問題の理解

 3 × m のグリッドが与えられており、移動は常に右に 1 列であり、垂直方向に最大 1 行移動することもできます。 旅は最初の列の中央行で始まり、最後の列の同じ中央行で終了する必要があります。 各ステップでは常に列インデックスが 1 だけ増加するため、パスは各列でどの行を占有するかによって完全に決まります。 

細胞の特定のセグメントがブロックされています。 各制限は、固定行について、連続する列間隔内のすべてのセルが使用できなくなることを示しています。 いずれかの列でブロックされたセルに入ろうとした場合、パスは無効になります。 

タスクは、移動制約を尊重し、ブロックされたセルを回避しながら、行 2 で始まり行 2 で終わる列 1 から列 m までに存在する有効な行シーケンスの数をカウントすることです。m は 10^18 に達する可能性があるため、列ごとにシミュレートすることはできません。 

重要な制約の意味は、どのソリューションでも列の反復を回避する必要があるということです。 唯一の合理的な演算は、障害物の数の線形演算または m の対数演算です。 n は最大 10^4 であるため、O(n log n) または O(n) の前処理が可能ですが、m に比例するものはありません。 

すべての列に対する単純な動的プログラミングは不可能です。 10^18 列の DP を格納しても意味がありません。 圧縮したとしても、遷移は個々の列ではなく障害物の境界に依存します。 

障害物が重なり合うと、微妙なエッジケースが発生します。 複数の障害物を同じ列および間隔に積み重ねることができます。 適切にマージされていない場合、単純な実装では、部分的にブロックされた領域が誤って別個のものとして扱われ、ブロックされているはずのセルを通過してしまう可能性があります。 たとえば、行 2 に障害物 [2,3] と [3,4] がある場合、正しいブロック領域は [2,4] であり、2 つの互いに素な領域ではありません。 マージに失敗すると、列 3 で不正な DP 遷移が発生します。 

もう 1 つの失敗モードは、移動が厳密に 1 列前であることを忘れていることです。 これにより、問題は列によってインデックス付けされた層状グラフをカウントするパスになりますが、エッジが列をスキップすることはありません。 注意深く状態を処理せずにブロックされた間隔を飛び越えようとするソリューションは、パスのカウントを誤ります。 

## アプローチ

 ブルートフォース手法では、各列を状態として扱い、セル (i, j) に到達する方法の数として dp[i][j] を計算します。 各セルから、有効な場合は右上、右、右下に遷移します。 これはプロセスを正しくモデル化していますが、m は最大 10^18 になる可能性があるため、列を反復処理することさえ不可能です。 操作数は m に比例しますが、これは実現可能な制限をはるかに超えています。 

ブロッキング イベントが行に影響を与えない限り、遷移がすべての列で同一であることが観察されると、問題の構造が変わります。 ブロックされたセルのセットが変化する 2 つの連続する列の間では、遷移ルール​​は一定です。 これは、プロセスが列軸に沿って区分的に一定であることを意味します。 

障害物の開始点または終了点のすべての点で、列に沿ってグリッドを圧縮できます。 これにより、無限の列範囲が最大 2n 個の臨界点に縮小されます。 これらの点の間では遷移は均一であるため、セグメントの長さに行列の累乗を適用できます。 

各列の状態はサイズ 3 のベクトルで、その列の各行に存在するウェイの数を表します。 列 j から j+1 への遷移は、列 j+1 でどのセルがブロックされるかによって決定される 3 行 3 列の行列です。 同一の閉塞構成の各セグメントについて、この行列をセグメントの長さでべき乗します。 

これにより、問題はイベントのソート、列セグメントのスイープ、セグメントごとの遷移行列の構築、および大きなギャップに対する高速行列累乗の適用に軽減されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 列に対するブルート フォース DP | O(m) | お(1) | 遅すぎる |
 | セグメント圧縮 + 行列累乗 | O(n log m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 障害物をコラムイベントに変換する

 各障害物について、列 l でセルがブロックされ、列 r+1 でブロックが解除されることをマークします。 これらを行ごとにグループ化されたイベントとして保存します。 

この変換により、間隔制約が列上のスイープ ライン構造に変わります。 

### 2. すべてのイベント位置を並べ替える

 すべてのイベント列を収集して並べ替え、連続するイベント ポイント間のセグメントを処理します。 各セグメントはブロックされたセルが変化しない範囲を表します。 

2 つのイベント ポイント間では遷移行列が固定されているため、間隔全体を安全に均一に扱うことができます。 

### 3. アクティブなブロックされた行を維持する

 列をスイープするときに、3 つの行のうちどの行が現在ブロックされているかを維持します。 どのセグメントでも、これにより、許可された状態のブール マスクが得られます。 

このマスクは、どの遷移が正当​​であるかを完全に決定します。 

### 4. 現在のセグメントの遷移マトリックスを構築する

 行 j がブロックされていない場合、列 x の行 i から列 x+1 の行 j に移動できる場合、T[i][j] が 1 である 3 × 3 行列 T を定義します。 

各行は、境界とブロックされたセルを考慮して、それ自体または隣接する行に遷移できます。 

このマトリックスは、固定セグメントのすべての移動ルールをエンコードします。 

### 5. 行列のべき乗を使用してセグメント間をジャンプする

 セグメントの長さが L の場合、高速累乗を使用して T^L を計算します。 次に、それを現在の状態ベクトルと乗算します。 

これにより、列ごとに反復することなく、任意の大きな m をシミュレートできます。 

### 6. 初期化とファイナライズ

 行 2 から開始するため、dp = [0, 1, 0] から開始します。すべてのセグメントを順番に処理し、dp を繰り返し更新します。 最終的な答えは、列 m の dp[1] です。 

### なぜ効果があるのか

 このアルゴリズムは、各セグメント内で遷移構造が一定であり、列インデックスに依存しないという不変条件に依存します。 移動は隣接する列間で厳密に局所的であるため、セグメントにわたる状態の発展は、同じ線形変換を正確に繰り返し適用することになります。 行列累乗では、考えられるすべてのパスの正確な数が保存されるため、同一の遷移を圧縮しても、個別のパスが失われたりマージされたりすることはありません。 すべての有効なパスは行遷移の一意のシーケンスに対応し、そのような各シーケンスは行列累乗で 1 回カウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def mat_mul(a, b):
    res = [[0]*3 for _ in range(3)]
    for i in range(3):
        for k in range(3):
            if a[i][k] == 0:
                continue
            for j in range(3):
                res[i][j] = (res[i][j] + a[i][k] * b[k][j]) % MOD
    return res

def mat_pow(mat, exp):
    res = [[1 if i == j else 0 for j in range(3)] for i in range(3)]
    base = mat
    while exp:
        if exp & 1:
            res = mat_mul(res, base)
        base = mat_mul(base, base)
        exp >>= 1
    return res

def apply(mat, vec):
    return [
        (mat[0][0]*vec[0] + mat[0][1]*vec[1] + mat[0][2]*vec[2]) % MOD,
        (mat[1][0]*vec[0] + mat[1][1]*vec[1] + mat[1][2]*vec[2]) % MOD,
        (mat[2][0]*vec[0] + mat[2][1]*vec[1] + mat[2][2]*vec[2]) % MOD,
    ]

def build_matrix(blocked):
    mat = [[0]*3 for _ in range(3)]
    for i in range(3):
        if blocked[i]:
            continue
        for d in [-1, 0, 1]:
            j = i + d
            if 0 <= j < 3 and not blocked[j]:
                mat[i][j] = 1
    return mat

def solve():
    n, m = map(int, input().split())
    events = {}

    for _ in range(n):
        a, l, r = map(int, input().split())
        a -= 1
        events.setdefault(l, []).append((a, 1))
        events.setdefault(r + 1, []).append((a, -1))

    xs = sorted(events.keys())
    blocked = [0, 0, 0]

    dp = [0, 1, 0]

    cur = 1

    def process_segment(length):
        nonlocal dp, blocked
        if length <= 0:
            return
        mat = build_matrix(blocked)
        matL = mat_pow(mat, length)
        dp = apply(matL, dp)

    for x in xs:
        process_segment(x - cur)
        for a, t in events[x]:
            blocked[a] += t
        cur = x

    process_segment(m - cur + 1)

    print(dp[1] % MOD)

if __name__ == "__main__":
    solve()
```このソリューションは、各行をインデックス 0 ～ 2 としてエンコードし、現在の列の各行に到達する方法のベクトルを維持します。 重要な実装の詳細は、遷移には常に同じ行に留まり、有効な場合は隣接する行に移動することが含まれることです。 

イベントは列境界に適用されるため、各セグメントは固定ブロック構成になります。 セグメント長の計算では、連続するイベント位置間の差分が使用され、最後のフラッシュでは最大 m までのサフィックスが処理されます。 

セグメントの長さは 10^18 に達する可能性があるため、行列のべき乗が必要です。 各セグメントは独立して処理され、状態は乗算的に前方に伝播されます。

```障害物をイベントに変換します。

Segments are:

 列 1-1、2-2、3-4、5-5。 

We track dp = [0,1,0].

 | セグメント | Blocked rows | 長さ | Transition | dp after segment |
 | --- | --- | --- | --- | --- |

 ## 特殊なケース

 重大なエッジケースは、複数の障害物が同じ列および間隔で重なっている場合です。 イベントベースのシステムは、増分と減分がカウンターに蓄積されるため、これを正しく処理します。そのため、カウンターがゼロ以外の場合、セルはブロックされていると見なされます。 これにより、重複する間隔を別個の独立したブロックとして扱うという間違いを回避できます。 

もう 1 つのエッジ ケースは、m が最後のイベントの位置よりもはるかに大きい場合です。 最後のセグメントは m まで延長する必要があります。そうでない場合、最後の障害物を超えるパスは考慮されません。 このアルゴリズムは、サフィックス セグメント m - cur + 1 を明示的に処理し、それ以上のイベントが存在しない場合でも正確さを保証します。 

最後の微妙なケースは、行がセグメントに対して完全にブロックされる場合です。 その場合、遷移行列には単純にゼロ行があり、dp 質量がその行に入ることができないことを意味します。 このような行列を乗算すると、特別なケースを使用せずに無効なパスが自然に削除されるため、べき乗は引き続き機能します。
