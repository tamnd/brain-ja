 ## 解決策

 ## 問題の理解

 隠された長方形のグリッド上を歩くことで得られる一連の整数が与えられます。 グリッドは行優先の順序で埋められます。最初の行には連続する数字が含まれ、その直後に次の行が続く、というように続きます。 グリッドに`x`行と`y`列、次に位置のセル`(i, j)`値が含まれています`(i-1)·y + j`。 からのすべての数字`1`に`x·y`は 1 回だけ表示されます。 

パスが一連の値として表示されます`a1, a2, ..., an`。 各値は、この未知のグリッド内の固有のセルに対応し、シーケンス内の連続する値は、グリッド内のエッジに隣接するセルから取得されることが保証されます。 タスクは、ペアが存在するかどうかを判断することです`(x, y)`このパスがその解釈の下で有効であるかどうか、および有効である場合には、1 つの有効なグリッド サイズを構築します。 

重要な問題は、数値から座標へのマッピングが次のものに依存することです。`y`、不明です。 変化`y`値が行に分割される方法が変更されるため、シーケンス内の隣接性は、固定されたグラフ走査問題ではなく、非表示パラメータに対する制約になります。 

この制約により、私たちは線形または線形に近い解決策に向かうことになります。 最大 200,000 個の要素を使用すると、考えられるすべてのグリッド幅を試したり、ネストされたループ内で座標を繰り返し再計算したりするアプローチは遅すぎます。 各遷移から制約を抽出し、段階的に結合する必要があります。 

2 つの数値間で 1 種類の移動のみが可能であるとソリューションが想定している場合、微妙な失敗例が発生します。 たとえば、次のようになります。`8 → 9`、素朴な解釈では、水平方向の隣接性が常に意図されていると想定するかもしれませんが、`y = 1`、同じ遷移は垂直方向です。 次のようなペアの場合、別の失敗ケースが発生します。`1 → 2`は常に水平であると想定されますが、`y ≥ 2`、レイアウトによってはまだ垂直になる場合があります。 曖昧さがあるため、すべてのステップで両方の解釈を一貫して考慮する必要があります。 

## アプローチ

 強引なアイデアは、可能な値をすべて試してみることです。`y`から`1`に`max(a[i])`、各選択肢の座標を再構築し、シーケンス内のすべてのステップが有効な動きに対応するかどうかを検証します。 これは概念的に機能します。`y`グリッド構造を独自に定義しますが、遅すぎます。 各チェックは直線的です`n`、および範囲`y`最大 10^9 になる可能性があるため、これは完全に不可能になります。 

重要な点は、すべてのグリッドを明示的にシミュレートする必要がないということです。 固定の場合`y`、それぞれの数字`a`座標にマップします`( (a-1)//y, (a-1)%y )`。 2 つの連続する値は、マンハッタン距離がちょうど 1 で隣接している必要があります。 この条件は、次の算術制約に変換されます。`y`。 

ペア用`(u, v)`、隣接関係は 2 つの方法でのみ可能です。 それらは垂直に隣接している、つまり同じ列にあり、正確に異なっていることを意味します`y`、または水平方向に隣接しています。つまり、同じ行にあり、正確に異なります。`1`、行境界を越えることなく。 したがって、各ペアは、次の許容値のセットを課します。`y`、そして正しい答えは、これらすべての許可されたセットの交差部分にある必要があります。 

複雑な幾何学的条件を直接追跡する代わりに、各遷移を候補の制約チェックに削減します。`y`シーケンスの違いから得られる値。 最も重要な候補者は垂直方向の移行から生まれます。`|u - v|`直接等しい`y`。 これにより、小さくて管理しやすい潜在的な幅のセットが得られます。 その後、各候補を線形時間で検証できます。

 ## アルゴリズムのチュートリアル

 ### アルゴリズムのチュートリアル

 1. 連続した差分からすべてのグリッド幅の候補を抽出します。 隣接するペアごとに`(a[i], a[i+1])`、計算する`|a[i] - a[i+1]|`可能な限り収集してください`y`。 これが機能するのは、グリッド内の垂直方向の移動がサイズのジャンプに正確に対応する必要があるためです。`y`。 
2. 各候補者について`y`、行優先デコードを使用してすべての値の座標を再構築します。`(a-1)//y`そして`(a-1)%y`。 このステップでは、シーケンスを候補グリッド内の明示的なウォークに変換します。 
3. シーケンス内のすべての連続するペアが有効な動きに対応するかどうかを確認します。 座標間のマンハッタン距離がちょうど 1 の場合、移動は有効です。 
4. 候補者がいる場合`y`シーケンス全体の検証に合格し、計算します`x`計算では行のインデックスが 0 から付けられるため、発生した最大行インデックスに 1 を加えたものとなります。 
5. 出力`YES`最初の有効なものと一緒に`(x, y)`ペアが見つかりました。 候補が機能しない場合は出力`NO`。 

### なぜ効果があるのか

 すべての有効なソリューションは固定幅を割り当てる必要があります`y`それはすべての遷移にわたって一貫しています。 垂直方向の移動力`y`2 つのセル間の値の差が等しくなるため、垂直方向の動きが発生した場合、そのような差の少なくとも 1 つは実際の幅と一致する必要があります。 パスが水平方向の移動のみを使用する場合でも、水平方向の隣接性は一度完全に決定されるため、テスト候補の幅は構造的に一貫した解釈をすべてカバーします。`y`固定されています。 再構成ステップでは、無効な隣接関係が 1 つでもマンハッタン距離条件を破るので、一貫性のない幅が検証に残らないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(a, y):
    coords = []
    for v in a:
        v -= 1
        coords.append((v // y, v % y))
    for i in range(len(a) - 1):
        r1, c1 = coords[i]
        r2, c2 = coords[i + 1]
        if abs(r1 - r2) + abs(c1 - c2) != 1:
            return False
    return True

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    if n == 1:
        print("YES")
        print(1, 1)
        return

    candidates = set()

    for i in range(n - 1):
        d = abs(a[i] - a[i + 1])
        if d > 0:
            candidates.add(d)

    candidates.add(1)

    for y in candidates:
        if y <= 0:
            continue
        if check(a, y):
            mx = 0
            for v in a:
                mx = max(mx, (v - 1) // y)
            print("YES")
            print(mx + 1, y)
            return

    print("NO")

if __name__ == "__main__":
    solve()
```この実装では、まず、絶対的な差から考えられるすべてのグリッド幅を収集します。 次に、各候補の幅が、すべての値をそのグリッド座標にデコードし、隣接性を検証することによってテストされます。 チェック関数は中核です。この関数は、すべてのステップが、その幅によって引き起こされるグリッド グラフ内の 1 つのエッジの移動に対応していることを確認します。 

行の計算`(v-1)//y`と列の計算`(v-1)%y`行優先の充填ルールを直接変換したものです。 表示される最大行インデックスによって、必要な最小高さが決まります。 

よくある間違いは、すべての違いが有効な幅に対応すると仮定することです。 これは厳密には当てはまりませんが、最後の検証ステップで無効な候補が除外されるため、誤った幅が出力に残されることはありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    if n == 1:
        return "YES\n1 1\n"

    def check(a, y):
        coords = []
        for v in a:
            v -= 1
            coords.append((v // y, v % y))
        for i in range(len(a) - 1):
            r1, c1 = coords[i]
            r2, c2 = coords[i + 1]
            if abs(r1 - r2) + abs(c1 - c2) != 1:
                return False
        return True

    candidates = set(abs(a[i] - a[i + 1]) for i in range(n - 1))
    candidates.add(1)

    for y in candidates:
        if y > 0 and check(a, y):
            mx = max((v - 1) // y for v in a)
            return f"YES\n{mx+1} {y}\n"

    return "NO\n"

 ## 特殊なケース

 単一要素のパスはどのグリッドでも有効であり、アルゴリズムは最小値を正しく返します。`1 × 1`隣接関係の制約が存在しないため、設定が無効になります。 

のようなパス`1 → 2`は複数のグリッド幅で機能し、候補生成には次のような有効な幅が正しく含まれます。`y = 2`、水平方向に移動する単一行のグリッドが生成されます。 

次のようなジグザグシーケンス`1 → 3 → 2 → 4`水平方向と垂直方向のトランジションの両方を同時に揃える幅を選択するようアルゴリズムに強制します。 テスト`y = 2`すべての制約を満たしますが、無効な候補は隣接性チェック中に失敗します。 

小さなグリッド内で完全に密なトラバーサルを行うと、行の境界を越える遷移が検証中に誤った幅を即座に無効にするため、行の折り返しが正しく処理されることが保証されます。
