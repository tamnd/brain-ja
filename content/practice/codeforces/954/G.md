 ## 解決策

 ## 問題の理解

 壁上の各位置は、保護強度が必要なセグメントと考えることができます。 射手の初期配置が与えられ、各射手は自分の陣地を守るだけでなく、固定半径内の近くの陣地を支援します。 したがって、すべての射手は純粋に局所的な貢献ではなく、その位置を中心とした対称的な範囲に影響力を広げます。 

壁の各セクションの防御力は、その影響力をカバーする射手の総数です。 ディフェンスプランの質は、最も弱いディフェンスセクションによって決まります。つまり、すべてのポジションにわたって最小限のカバー範囲を最大化することに重点を置いています。 

追加の射手をどこにでも配置することができ、新しい射手はそれぞれ既存の射手とまったく同じように動作し、距離 r 内のすべての位置に貢献します。 任務は、すべての貢献の後、すべての壁セクションの最小範囲がで​​きるだけ大きくなるように、これらの追加の射手を分配することです。 

重要な問題は、地域的な配置と広範囲にわたる影響力との間の相互作用に起因します。 追加された 1 人の射手はインターバル全体に影響を与えるため、すべての決定は重複した結果をもたらします。 

制約が十分に大きいため、二次シミュレーションや素朴な貪欲シミュレーションさえも直ちに実行不可能になります。 最大 500,000 の位置と非常に大きな k が存在する可能性があるため、配置を 1 つずつシミュレートしたり、カバレッジを最初から再計算しようとするアプローチは、時間制限を数桁超えてしまいます。 このため、単調性と線形時間の実現可能性チェックを使用する戦略に向かうことになります。 

r が大きい場合、微妙な問題が発生します。 その場合、各射手は壁のほぼ全体に影響を与えるため、問題は局所的な調整ではなく全体的な合計のバランスをとることに退化します。 もう 1 つのエッジ ケースは r = 0 です。この場合、各位置は独立しており、解は純粋に局所的な不足に基づく単純な再分配問題になります。 

## アプローチ

 直接的なアプローチは、すべてのポジションの初期カバー範囲を計算し、追加の射手の配置をシミュレートしてみることです。 各配置は、およそ 2r + 1 のサイズの完全な間隔を変更します。これを単純に更新すると、射手ごとに O(n) のコストがかかります。 k が最大 10^18 であるため、これは計算的に概念化することさえ不可能です。 

たとえ私たちがより賢く、常に現在の最小値が最小になる場所に射手を配置しようとしても、同じ構造的な問題に直面します。単一の配置が多くの位置に影響を及ぼし、将来の決定は将来の重複する効果に依存します。 

重要な観察は、答えが単調であるということです。 最小防御レベル X を達成できれば、X より小さい値も達成可能です。 これにより、最終的な答えを二分探索することができます。 

残りの課題は、固定された目標 X が達成可能かどうかを確認することです。 これはリソース割り当ての問題になります。左から右にスキャンして、すべての位置が少なくとも X に到達することを確認します。位置が不足している場合は、すぐに修正するために十分な数の射手を配置する必要があります。以前の決定に影響を与えずに今後配置することはできないためです。 

各配置は、「カバレッジ配列」内の連続したセグメントにカバレッジを追加するものとしてモデル化できます。これにより、差分配列を使用して効果を維持し、すべてを線形時間で処理できます。 

これにより、問題は「k 個の配置をグローバルに選択する」という問題から、「範囲を更新して左から右へ制約を貪欲に満たす」という問題に変換され、効率的かつ決定的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(k · n) | O(n) | 遅すぎる |
 | 二分探索 + 貪欲な実現可能性 | O(n log V) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

各射手は一定の間隔に寄与するため、最初にプレフィックスの合計を使用して各位置の基本カバレッジを計算します。 これにより、追加の射手を追加する前に、各セクションの開始強度が得られます。 

次に、X で示される答えを二分探索します。 

1. 初期カバー範囲配列 b[i] を計算します。ここで、b[i] は、位置 i をカバーする既存の射手の数です。 これは、区間 [i - r, i + r] にわたる差分配列を使用して行われます。 
2. 最大 k 個の追加射手を使用して、すべてのポジションが少なくとも X の範囲を確保できるかどうかを確認する関数 can(X) を定義します。 
3. can(X) 内で、以前に配置された射手によって提供された追加の範囲を表す実行配列 add[i] を維持します。 位置を左から右に移動します。 
4. 位置 i で、現在のカバレッジを b[i] に累積加算を加えたものとして計算します。 この値がすでに X 以上である場合は、続行します。 
5. X を下回っている場合、赤字を直ちに修正する必要があります。 need = X - current[i] とします。 必要な射手を i + r の位置に配置します。 この選択は、カバレッジを可能な限り適切なものにし、将来の柔軟性を無駄にしないようにするため、重要です。 
6. このような各配置により、間隔 [i, i + 2r] のカバレッジが増加します。 差分配列を使用してこれを適用すると、更新は O(1) のままになります。 
7. 配置された射手の総数を累計します。 kを超えると目標Xを達成できなくなります。 
8. k を超えずにスキャンを終了すれば、X は実現可能です。 

二分探索は、最初の可能な最小値からその値に k を加えた値までの範囲で実行されます。 

### なぜ効果があるのか

 貪欲な実現可能性ステップは、強制的な議論に依存しています。 私たちが位置 i にいるとき、そこにある欠点は、その影響力が i をカバーする射手によって修正されなければなりません。 すべての可能な配置の中で、最も右側の有効な配置を選択すると、将来の適用範囲が最大化され、その後の配置の実現可能性が低下することはありません。 位置 i を一度修正すると、それを再検討する必要はありません。これは、以降のすべての操作でカバレッジが右側に拡張されるだけであり、既に処理されたインデックスに有害な影響が及ばないためです。 これにより、安定した左から右への不変式が作成されます。つまり、処理されたすべての位置が永久にターゲットを満たすことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_base(n, r, a):
    diff = [0] * (n + 2)
    for i, val in enumerate(a):
        if val == 0:
            continue
        l = max(0, i - r)
        rr = min(n - 1, i + r)
        diff[l] += val
        diff[rr + 1] -= val

    b = [0] * n
    cur = 0
    for i in range(n):
        cur += diff[i]
        b[i] = cur
    return b

def can(X, n, r, k, b):
    diff = [0] * (n + 3)
    active = 0
    used = 0

    for i in range(n):
        active += diff[i]
        cur = b[i] + active

        if cur < X:
            need = X - cur
            used += need
            if used > k:
                return False

            active += need
            end = i + 2 * r + 1
            if end < n:
                diff[end] -= need

    return True

def solve():
    n, r, k = map(int, input().split())
    a = list(map(int, input().split()))

    b = build_base(n, r, a)

    lo = min(b)
    hi = lo + k

    while lo < hi:
        mid = (lo + hi + 1) // 2
        if can(mid, n, r, k, b):
            lo = mid
        else:
            hi = mid - 1

    print(lo)

if __name__ == "__main__":
    solve()

重要な点は、位置 i + r への配置です。 これにより、追加された射手は右方向へのリーチを最大化しながら位置 i を確実にカバーできるようになります。これは、将来の決定を実行可能に保つために不可欠です。 

二分探索は、問題の単調構造を利用して、この実現可能性チェックをラップします。

 ## 特殊なケース

 r = 0 の場合、近隣に影響を与える射手が存在しないため、各位置は独立して動作します。 各不足はローカルで解決され、貪欲なプロセスによって同じインデックスを超えて影響が広がることはないため、アルゴリズムは引き続き機能します。 たとえば、b[i] = 0、ターゲット X = 3 の位置 i では、他の位置に影響を与えることなく、その位置で 3 ユニットを直接費やします。 

r が大きく、n に近い場合、追加された各射手はほぼ配列全体に影響を与えます。 この場合、すべての加算を任意の 1 つの最適な位置に配置すると、グローバル最小値が均一に効果的に増加します。 すべての配置が残りのすべての位置に均等に影響を与えるため、貪欲スキャンは引き続き正しく動作します。そのため、初期の決定は後のインデックスにも有効です。 

k = 0 の場合、二分探索はすぐに最初のカバレッジ配列の最小値まで崩壊し、実現可能性チェックは更新を実行せず、改善が不可能であることを正確に反映します。
