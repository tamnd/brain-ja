 ## 解決策
 ## 問題の理解

 空の文字列から始めて構築したい文字列が与えられています。 各アクションには 1 回の操作が必要です。 基本的なアクションは、既存の文字の末尾に 1 文字を追加することです。 さらに、プロセス全体で 1 回、現在構築されている文字列を取得し、その正確なコピーを 1 回の操作でそれ自体に追加することができます。 

タスクは、最小限の操作を使用して、指定された最終文字列を生成することです。 

重要な構造は、ターゲット文字列のプレフィックスを段階的に構築しているということです。 ある時点で、現在のプレフィックスを「2 倍」にすることを選択することもありますが、それはそのプレフィックスがターゲット文字列の次のセグメントと一致する場合に限られます。そうでない場合は、コピー操作によって最終的な文字列との一致が即座に不可能になります。 

制約 n ≤ 100 は、O(n^3) または O(n^2) の解を快適に得ることができることを意味します。 すべての分割点を試して部分文字列の同等性をチェックするアプローチはどれも実現可能です。 プレフィックスに対する貪欲または動的プログラミングのアプローチで十分です。 高度な文字列ハッシュやサフィックス構造は必要ありませんが、それらも機能します。 

微妙なエッジ ケースは、コピー操作をまったく使用しないことが最善の戦略である場合です。 たとえば、abcdef のような繰り返し構造を持たない文字列では、すべての単一文字の操作が必要です。 もう 1 つのエッジ ケースは、繰り返し構造が存在するが、コピー操作の使用が早すぎる場合、コピー操作を遅らせることよりも悪い場合です。 

たとえば、abcabca について考えてみましょう。 次の部分が abc で始まるため、abc の後にコピーすると有益です。 しかし、ab の後にコピーしようとすると、ababab が得られ、すぐに目標から外れてしまいます。 

もう 1 つのエッジ ケースは、aaaaaa のような文字列です。 最適な戦略は、プレフィックスを作成し、一度コピーしてから、いくつかの追加文字を入力することです。 正確な分割ポイントは、単なる繰り返しではなく、繰り返されるプレフィックスのアライメントを最大化することに依存します。 

## アプローチ

 ブルートフォースのアイデアは単純です。文字列の構築を 1 文字ずつシミュレートし、必要に応じてあらゆる瞬間にコピー操作を適用します。 各接頭辞の長さ i で、次の文字を追加するか、コピー操作をまだ使用していない場合は接頭辞全体をコピーしてそこから続行するかを決定します。 これにより、各状態が現在の位置とコピーが使用されているかどうかによって定義される状態空間が形成されます。 

これは、すべての有効な構築シーケンスを探索するため機能しますが、各位置で 2 つの選択肢に分岐し、コピーのシミュレーションも必要になるため、コストが高くなります。 すべての位置でコピー操作を使用する場合と使用しない場合があり、単純なシミュレーションでは文字列連結が繰り返し再計算されるため、最悪のケースは n とともに指数関数的に増加します。 

重要な点は、コピー操作が役立つのは、現在構築されているプレフィックスがターゲット文字列の次のセグメントと正確に一致する場合のみであるということです。 位置 i にいて、現在構築されている文字列の長さが i である場合、コピーを使用するということは、部分文字列 s[0:i] が s[i:2i] に等しくなければならないことを意味します。 したがって、唯一意味のある決定は、2 倍にすることを選択した分割点 i であり、2 倍にした後でも、残りのいくつかの文字を個別に追加できます。 

これにより、問題は、文字列がその接頭辞から開始して可能な限り同じ 2 つの半分に分割されるように接頭辞の長さ i を選択し、合計操作 (接頭辞を構築するための i 操作、1 回のコピー操作、および残りの文字) が最小限に抑えられるようになります。 

1 から n までのすべての可能なプレフィックス長 i を試し、2 倍化がどこまで有効であるかを計算し、それに応じてコストを計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(2^n) | O(n) | 遅すぎる |
 | すべての分割ポイントを試してみる | O(n^2) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. コピー操作をまったく使用しないと仮定して、答えを計算します。 すべての文字を 1 つずつ入力するため、これは単に n です。 これはベースラインとして機能します。 
2. 1 から n までの考えられるプレフィックス長 i ごとに、i 演算を使用して最初の i 文字を構築するというアイデアを考えてみましょう。 
3. 選択した i について、位置 i で始まる部分文字列が接頭辞 s[0:i] と一致するかどうかを確認します。 この一致を可能な限り、たとえば、s[i:j] が s[0:j-i] に等しい位置 j まで拡張します。 これにより、位置 i でのコピー操作がどの程度役立つかが決まります。 
4. i でコピー操作を使用することにした場合、コピーのために 1 回の追加操作を支払いますが、その後も、一致しない残りのサフィックス文字を個別に追加する必要があります。 完全な倍加が 2i まで可能であれば、合計コストは i + 1 + (n - 2i) になります。それ以外の場合は、試合がどこまで続くかに基づいて調整します。 
5. すべての有効な i にわたる最小コストを追跡します。 

機能する理由: 最適なソリューションでは、コピー操作が 1 回しか使用されないため、入力によって構築されたプレフィックス、その後にそのプレフィックスの 1 つの複製、その後に最後に入力された文字が続く必要があります。 このようなすべての解決策は、コピーが発生するプレフィックスの長さによって一意に決定されます。 考えられるすべてのプレフィックス長を列挙し、重複がターゲット文字列とどの程度一致しているかを測定することで、すべての有効な最適な構造を探索します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    ans = n  # type everything

    for i in range(1, n + 1):
        # build prefix of length i
        j = i
        while j < n and s[j] == s[j - i]:
            j += 1

        # cost: i to type prefix + 1 copy + remaining characters
        remaining = n - j
        ans = min(ans, i + 1 + remaining)

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、コピー操作を適用する可能性のあるすべてのポイントを反復します。 このような点ごとに、コピーされたプレフィックスがターゲット文字列に対して有効なままである範囲を貪欲に拡張します。 内側の while ループにより、構造が一致する限りコピーのみが行われることが保証されます。 不一致が現れたら、それ以上コピーすると正確性が損なわれるため、中止します。 

ベースラインの答え n は、コピーが決して有益ではないケースを扱います。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | 各プレフィックス i について、不一致になるまで前方比較文字をスキャンします。 
| スペース | お(1) | 少数のカウンターと入力文字列のみが保存されます。 

n ≤ 100 の場合、最大 10^4 文字の比較が発生するため、これは制限内に問題なく収まります。

 ## 特殊なケース

 のような文字列の場合`abcdef`の場合、アルゴリズムはすべての接頭辞 i を試行しますが、一致する拡張子 j が i を超えることはありません。 これにより、すべての候補コストが i + 1 + (n - i) になり、常に n + 1 となるため、ベースライン n は最適なままになります。 アルゴリズムは正しくすべてを入力するようにフォールバックします。 

のために`aaaaaaa`, starting at i = 1 immediately allows full extension to the end, so the cost becomes 2, which matches the intuition that one character plus copying covers everything.

 次のような混合繰り返しの場合`ababa`、 i = 2 を選択すると、部分的な拡張は得られますが、完全にはカバーされず、残りのサフィックスを入力する必要があります。 アルゴリズムは、最初の不一致で拡張を停止することでこれを捕捉し、無効なオーバーコピーがカウントされないようにします。
