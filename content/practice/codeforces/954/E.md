 ## 解決策
 ## 問題の理解

 各蛇口は制御可能な水の流れに貢献しますが、すべての蛇口の温度は固定されています。 各タップの実数値の流量をゼロから最大容量までの間で選択できます。 最終混合物の温度は、アクティブなすべてのタップの加重平均に等しい温度になります。ここで、重みは選択された流量です。 

正式に、フロー値を割り当てると、$x_i$、総量は$V = \sum x_i$、結果の温度は次のようになります。$\frac{\sum x_i t_i}{V}$、すべてを除いて$x_i = 0$この場合、温度はゼロとして定義されます。 

目標は、結果として得られる温度が目標値と正確に等しくなる流量を選択することです。$T$、全体のボリュームを最大化しながら。 

主な難しさは、ボリュームを最適化するだけでなく、すべてのタップを比率で結合する非線形制約の下で最適化していることです。 この制約により、高温源と低温源のバランスが強制されます。 

入力サイズが到達しました$2 \cdot 10^5$これにより、サブセットを列挙したり、代入を明示的に検索しようとするアプローチは除外されます。 どのような解決策でも、問題をソートと線形または対数処理に削減する必要があります。 

いくつかの特殊なケースが素朴な直感を打ち破ります。 すべての蛇口の温度が厳密に次の値を超えている場合$T$、いかなる混合物も温度を以下に下げることはできません。$T$, したがって、答えはゼロです。 同様に、すべての蛇口の温度が厳密に以下の場合、$T$、温度をそこまで上げることはできません。$T$。 もう 1 つの微妙なケースは、一部の蛇口の温度が正確である場合です。$T$、実現可能性に影響を与えることなく自由に使用できますが、他のタップと組み合わせた場合でも最適なスケーリングと相互作用するためです。 

グローバルな順序付けをせずに貪欲にフローの「バランス」をとろうとする単純なアプローチは失敗する可能性があります。これは、ミキシングが相対的な寄与に依存するためです。$T$、絶対温度ではありません。 

## アプローチ

 直接的なアプローチでは、各タップを独立して考慮し、目標比率を維持しながら流量値を割り当てようとします。 決めようとする人もいるかもしれない$x_i$を順番に調整し、残りの容量を調整して結果の温度を固定します。 これは、すべての決定が非線形にグローバル加重平均を変更し、ローカルな決定が将来の実現可能性を破壊する可能性があるため、失敗します。 可能な割り当てを離散化したとしても、状態空間は連続的であり、以前のすべての選択に依存するため、指数関数的に複雑になります。 

重要な観察は、制約が線形形式で書き換えられることです。 から始まる$$\frac{\sum x_i t_i}{\sum x_i} = T,$$に並べ替えます$$\sum x_i (t_i - T) = 0.$$これにより、問題は非ネガティブな選択に変わります。$x_i \le a_i$正と負の寄与が正確に相殺され、同時に最大化される$\sum x_i$。 

各タップは、単位フローあたりの符号付きの「利益」に寄与します。$t_i - T$。 でタップします$t_i > T$混合物を目標より上に押し出し、$t_i < T$目標より下に引っ張ります。 でタップします$t_i = T$制約に影響を与えることなくボリュームに貢献します。 

これにより、問題は、制限された容量を持つ線形方程式の 2 つの辺のバランスをとることに変わります。 総フローを最大化するために、タップを最大限に活用したいと考えています。$t_i = T$、ボリュームは無料なので。 残りのタップについては、正と負の寄与が正確に相殺されるように金額を選択する必要があります。 

最適な戦略は、温度別にタップを分類することから生まれます。 並べ替えると、接頭辞と接尾辞を考慮できます。高温タップは正の余剰を提供し、低温タップは負の余剰を提供します。 タスクは、分割点を見つけて、両側の累積加重超過を一致させることになります。 この構造により、プレフィックス合計を使用して実現可能性と達成可能な最大フローを計算し、パーティション ポイントにわたる二分探索によるスイープが可能になります。 

ブルート フォースはフローを直接割り当てようとするため失敗します。 最適化されたソリューションは、並べ替えられた順序での線形累積数量の比較の実現可能性を低下させるため、成功します。

 ## アルゴリズムのチュートリアル

 1. タップを 3 つのグループに分けます。$t_i < T$、$t_i = T$、 そして$t_i > T$。 この分離により、制約のないボリュームが制約のバランスから分離されます。 
2. 中間グループのすべての容量を合計します。$t_i = T$。 これらは比率の条件に影響を与えないため、常に完全に摂取できます。 
3. タップの場合$t_i \ne T$、温度順に並べ替えます。 最適なバランシングでは、任意の値をインターリーブするのではなく、常に極端な値をペアにするため、この順序付けが必要です。 
4. 各タップを署名付き投稿に変換します$d_i = a_i \cdot (t_i - T)$、最大限の効果を維持しながら、プラスの寄与とマイナスの寄与を分離します。 
5. ソートされた配列に対する容量と符号付き寄与のプレフィックス合計を構築します。 これらにより、どの程度の不均衡を生成または分割ポイントまで修正できるかを迅速に評価できます。 
6. 右側からの正の寄与が左側からの負の寄与と正確に釣り合うパーティションを検索します。 これは、分割インデックスに対する二分検索を使用して行われ、プレフィックスの合計によって実現可能性をチェックします。 
7. 実行可能な各分割について、すべての中立タップと両側からの制限バランス量を加算することにより、最大合計流量を計算します。 
8. すべての有効なパーティションにわたって達成可能な最適な合計ボリュームを追跡します。 

### なぜ効果があるのか

 重要な不変条件は、実行可能なソリューションは総フローを減らすことなく、ソート順序を尊重するソリューションに変換できるということです。 2 つのタップが温度によって順序が狂っているが、両方が部分的に使用されている場合、それらの寄与を交換しても実現可能性は損なわれませんが、極端なバランスをとる能力が高まるだけです。 この交換引数により、最適なソリューションが常に「T より低い」使用量と「T より高い」使用量の間の 1 つの分割に対応することが保証され、これにより、ソートされたシーケンスに対するプレフィックスのバランスに対する連続割り当ての問題が軽減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, T = map(int, input().split())
    a = list(map(int, input().split()))
    t = list(map(int, input().split()))

    exact = 0
    pos = []
    neg = []

    for ai, ti in zip(a, t):
        if ti == T:
            exact += ai
        elif ti > T:
            pos.append((ti - T, ai))
        else:
            neg.append((T - ti, ai))

    # sort by distance from T (not strictly required, but helps structure reasoning)
    pos.sort()
    neg.sort()

    # we will match total weighted deviation
    # prefix sums for positives and negatives
    import itertools

    pos_pref = [0]
    pos_w = [0]
    for d, cap in pos:
        pos_pref.append(pos_pref[-1] + cap)
        pos_w.append(pos_w[-1] + cap * d)

    neg_pref = [0]
    neg_w = [0]
    for d, cap in neg:
        neg_pref.append(neg_pref[-1] + cap)
        neg_w.append(neg_w[-1] + cap * d)

    # two pointers: choose how much we take from positives, match with negatives
    j = len(neg)

    ans = 0

    for i in range(len(pos) + 1):
        # take i positive taps fully
        # need to match weighted sum using negatives
        pos_need = pos_w[i]

        # binary search max j such that neg_w[j] >= pos_need
        l, r = 0, len(neg)
        best_j = 0
        while l <= r:
            m = (l + r) // 2
            if neg_w[m] >= pos_need:
                best_j = m
                r = m - 1
            else:
                l = m + 1

        # volume is exact + all used from pos and neg
        vol = exact + pos_pref[i] + neg_pref[best_j]
        ans = max(ans, vol)

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、タップを目標温度より高い温度、低い温度、および目標温度に等しい温度に分割することから始まります。 等しいグループはすぐに蓄積されます`exact`なぜなら、実現可能性に影響を与えることなくボリュームに貢献できるからです。 

残りのタップは、ターゲットに対して正と負の 2 つの配列に変換されます。 各エントリには、からの両方の距離が格納されます。$T$そして容量。 これにより、完全に使用された各タップがどの程度「温度の不均衡」に寄与するかを計算できます。 

プレフィックス合計は、合計フローと合計不均衡寄与の両方を追跡します。 実現可能性はこれらの累積的な不均衡を正確に一致させるかどうかに依存するため、これは非常に重要です。 

ループオーバー`i`完全に使用するプラス側タップの数を修正します。 そのような選択ごとに、どの程度の負の不均衡が必要であるかを計算し、累積不均衡の二分探索を使用してそれを補償できる負のタップの最小プレフィックスを見つけます。 

最後に、完全に取得されたすべてのニュートラル タップと両側から選択されたプレフィックスを加えた合計ボリュームを計算します。 

プレフィックスの合計を一致させるには、微妙な注意が必要です。`pos_pref[i]`そして`pos_w[i]`同じプレフィックス長に対応する必要があります。そうでない場合、実現可能性チェックに一貫性がなくなります。

 ## 特殊なケース

 すべてのタップが片側にある場合、重大なエッジケースが発生します。$T$。 すべての場合$t_i > T$の場合、すべての寄与はプラスであり、ゼロにバランスをとることができず、答えは強制的にゼロになります。 アルゴリズムはこれを処理します。これは、負の配列が空であるため、正の不均衡のプレフィックスが一致せず、実行可能なボリュームはゼロだけであるためです。 

もう 1 つのエッジ ケースは、すべてのタップが$t_i = T$。 この場合、pos 配列と neg 配列は両方とも空であり、すべてのユニットが中立で制約に違反しないため、アルゴリズムはすべての容量の合計をすぐに返します。 

バランスをとるためにタップのサブセットのみが必要な場合には、微妙なケースが発生します。 プレフィックスベースの構造により、部分的な補償も確実に考慮されます。これは、累積的な不均衡に対するバイナリ検索により、等価性が達成または超過された時点で正確に停止できるため、総量を削減する可能性がある低容量タップの過剰使用を防ぐことができます。
