 ## 解決策
 ## 問題の理解

 数直線上の整数位置の 2 つの集合が与えられます。 1 つのマルチセットは石の開始位置を記述し、もう 1 つは石の終了位置を記述します。 石は現在の位置以外は区別できず、選択した 2 つの石を線に沿って互いに向かって同時に移動させる操作を実行できます。 

1 回の操作でポジションにある 2 つの石をピックします$s_i \le s_j$そして同じ量だけ内側にシフトします$d$、交差しないという制約付きで、左側を右に、右側を左に移動します。 幾何学的には、各操作は選択したペアの中点を保持し、それらの距離を次のように短縮します。$2d$。 タスクは、このようなペアごとの短縮を使用して初期マルチセットをターゲット マルチセットに変換できるかどうかを判断し、変換できる場合は一連の操作を明示的に構築することです。 

制約により、最大で$3 \cdot 10^5$石なので、どのような解決策も線形または$n \log n$。 ペアごとのマッチングを繰り返しシミュレートしたり、すべてのペアを試行したりする二次戦略は、直ちに実行不可能になります。 

最初の微妙な点は、この操作では任意の再配置が許可されていないことです。 対称的な縮小のみが許可されるため、グローバル構造は制限された方法で保存されます。 単純な試みでは、各初期位置を個別に目標位置に貪欲に一致させようとする可能性がありますが、操作では一度に 2 つの石が結合され、初期の決定が妨げられる可能性があるため、これは失敗します。 

並べ替えられたリストのみを考慮すると、別の失敗ケースが発生します。初期位置とターゲット位置を並べ替えたとしても、それらをインデックス方向にペアにすることは無効です。 たとえば、イニシャルが$[1, 100, 101]$そしてターゲットは$[50, 51, 101]$、単純なペアリングは大きな独立したシフトを示唆しますが、許可される操作ではペア間の対称的な縮小のみが許可され、独立した再配置は許可されません。 

重要な隠れた制約は、ポジションの合計がすべての操作で不変であるということです。 各操作では、石を右に 1 つ、左に 1 つずつ同じ量だけ移動し、合計は正確に維持されます。 したがって、必要な条件は、初期位置の合計が目標位置の合計と等しいことです。 どのようなアプローチでも、この地球規模の保全の法則を尊重する必要があります。 

## アプローチ

 ブルートフォースの観点では、石のペアを繰り返し選択し、可能なすべての内側への動きをシミュレートし、初期構成をターゲット構成に変換しようとします。 各操作は 2 つの位置を変更し、以下から選択できます。$O(n^2)$最も近い不一致を貪欲に一致させようとしても、依然として多くの調整が必要になります。 各操作は局所的に距離を短縮するだけであるため、収束には必要な場合があります。$O(n^2)$敵対的な場合に動きます。 

重要な洞察は、石を独立した実体として考えるのをやめ、その代わりに、ラインに沿って「過剰質量」と「不足質量」のバランスを維持しながら、それらを分類された順序で処理することです。 操作では合計を維持しながらペア間の変位のみを転送するため、石を左から右に貪欲に一致させ、常に最も近い不一致の黒字と最も近い赤字をペアにすることができます。 これにより、問題はソートされた配列間の構造化された 2 ポインターのマッチングに変わり、差異が徐々にキャンセルされます。 

両方の配列を並べ替えると、それらは線に沿った質量の流れとして解釈されます。 初期位置のプレフィックスがターゲット位置の対応するプレフィックスより小さいか大きい場合、その不均衡は境界を越えて質量を移動することによって修正する必要があります。 各補正は、左側の余剰石と右側の不足石をペアにし、1 つの不一致を減らすのに必要な距離を正確に計算して操作を適用することに対応します。 

これにより、問題は任意のペア操作から 2 つの単調シーケンス間の貪欲なキャンセルの制御されたシーケンスに軽減されます。

 ## アルゴリズムのチュートリアル

 1. 初期位置と目標位置を並べ替えます。 これにより、両方のマルチセットを一貫した左から右の順序で操作できるようになります。これは、すべての操作で対称性によって引き起こされる相対的な順序制約が保持されるため、これが必要です。 
2. 2 ポインター スキャンを使用して、2 つの配列間のプレフィックスの違いを暗黙的に計算します。 ポインタを維持する$i$そして$j$初期配列とターゲット配列に対して。 
3. 現在の比類のない「質量」を各位置で維持する$s_i$そして$t_j$。 各ステップで、どれくらいの量を使用するかを決定します。$s_i$と一致させることができます$t_j$秩序に違反せずに質量をどこまで移動できるかを検討することによって。 
4. もし$s_i = t_j$、それらを直接照合し、両方のポインタを進めます。 これはコストゼロの調整であり、両方のマルチセットを一貫して削減します。 
5. もし$s_i < t_j$、私たちは治療します$s_i$右に移動する必要があるため。 最初の配列内で次に適切なペアを見つけてペアリングし、シフトを吸収できる右側の石を確実に選択します。 移動する操作を適用します$s_i$一方がターゲットの境界に揃うまで、一方は上向きに、もう一方は下向きに動作します。 
6. もし$s_i > t_j$、対称的に扱います$t_j$左に移動する必要があるため、ターゲットのアンバランスにある適切な右側の石と組み合わせます。 
7. 各操作はトリプルとして記録されます$(i, j, d)$、 どこ$d$は、現在の不一致で縮めたい距離の半分として選択されます。 
8. すべてのポジションが一致するか、矛盾が現れるまで続行します (有効なパートナーが存在せず、一致しない余剰があるなど)。 

### なぜ効果があるのか

 中心となる不変条件は、各ステップで、初期位置のプレフィックスをターゲット位置のプレフィックスに変換するために必要な総変位が、独立したペアごとの不均衡の合計として保存されることです。 各操作は、グローバル合計制約を維持しながら、そのような不均衡を 1 つだけ削減します。 このプロセスは常に左端の未解決の不一致を解決し、すでに一致した位置を再検討することはないため、以前に固定された位置合わせが崩れることはありません。 これにより、マルチセットが変換可能な場合に限り、有効なシーケンスでの終了が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = list(map(int, input().split()))
    t = list(map(int, input().split()))

    if sum(s) != sum(t):
        print("NO")
        return

    s = sorted([(v, i + 1) for i, v in enumerate(s)])
    t = sorted([(v, i + 1) for i, v in enumerate(t)])

    ops = []
    i = j = 0

    # We maintain lists of active positions; we will always operate on endpoints
    while i < n and j < n:
        sv, si = s[i]
        tv, tj = t[j]

        if sv == tv:
            i += 1
            j += 1
            continue

        if sv < tv:
            k = i + 1
            while k < n and s[k][0] <= tv:
                k += 1
            if k == i + 1:
                k = i + 1

            if k >= n:
                print("NO")
                return

            x = min(tv - sv, s[k][0] - sv)
            d = x // 2
            if d <= 0:
                print("NO")
                return

            ops.append((s[i][1], s[k][1], d))

            s[i] = (sv + d, si)
            s[k] = (s[k][0] - d, s[k][1])

        else:
            k = j + 1
            while k < n and t[k][0] <= sv:
                k += 1
            if k == j + 1:
                k = j + 1

            if k >= n:
                print("NO")
                return

            x = min(sv - tv, t[k][0] - tv)
            d = x // 2
            if d <= 0:
                print("NO")
                return

            ops.append((t[j][1], t[k][1], d))

            t[j] = (tv + d, tj)
            t[k] = (t[k][0] - d, t[k][1])

    print("YES")
    print(len(ops))
    for a, b, d in ops:
        print(a, b, d)

if __name__ == "__main__":
    solve()
```解決策は、直ちに保持する必要がある唯一のグローバル不変式、つまり位置の合計をチェックすることから始まります。 異なる場合、一連の対称的な動きで構成を一致させることはできません。 

この操作では空間構造が考慮されるため、両方の配列のソートが不可欠です。 ソート後、問題を 2 つの順序付けされたシーケンスの同期として扱います。 

2 ポインター ループは、現在の最小の不一致要素を位置合わせしようとします。 異なる場合は、値が小さい方を上に、値が大きい方を近くの要素と組み合わせて下に調整します。 選択されたパートナーは、手術には 2 つの異なる石と非負の距離が必要であるため、有効な収縮を実行する余地があることを確認するために選択されます。 

各操作は、値と一緒に保存された元のインデックスを使用して、問題ステートメントの要求どおりに正確に記録されます。 操作を適用した後、影響を受ける位置を更新して、後続のステップで更新された構成を確認できるようにします。 

実装上の微妙なリスクは、並べ替えられた順序を維持せずに値を更新すると、正確性が損なわれる可能性があることです。 このソリューションは完全な再ソートを回避し、代わりにローカル調整に依存します。そのため、パートナーの選択は常に前方にスキャンされます。

 ## 特殊なケース

 重要なエッジケースは、複数の石が同じ座標を共有する場合です。 操作は位置の一意性ではなくインデックスのみに依存するため、重複は依然として個別のオブジェクトとして扱われる必要があります。 値とともにインデックスを保持し、同一性が確実に保持されるため、ソートされたペアリングは引き続き機能します。 

別のケースは、すべての初期位置が緊密にクラスター化されているが、ターゲットが分散している場合に発生します。 このアルゴリズムは、拡散には対称的な縮小ステップが必要であるという事実に基づいています。 適切な側にパートナーが存在しない場合、スキャンは失敗し、正しく NO が返されます。 

最後の微妙なケースは、ローカル調整が一時的に値の並べ替え順序に違反する場合です。 この実装ではグローバルな再ソートが回避されますが、正確かどうかは、縮小の実現可能性を維持するのに十分なだけパートナーを常に選択することに依存します。
