 ## 解決策
 ## 問題の理解

 動的に増加する配列を維持することが求められます。 操作ごとに、新しい要素を配列に追加し、指定された範囲内の連続したサブ配列 (セグメント) の数をすぐにカウントします。`[l, r]`**mex** が指定された数値に等しい`k`。 セットの mex は、そのセットに存在しない最小の非負の整数です。 

ただし、クエリは難読化されており、値が与えられています。`a'`、`l'`、`r'`、`k'`、前のクエリに対する答えを使用してそれらをデコードする必要があります。 これにより、依存関係のチェーンが導入され、各操作を独立して計算できなくなります。`lans`は最初はゼロですが、後続の各クエリは最後に計算された答えに依存します。 

制約は重要です。 と`n`最大 2 · 10^5 と 3 秒の時間制限、可能なすべての部分配列をチェックするアルゴリズム`[l, r]`クエリごとに実行することは不可能です。 最悪のケースとしては、`O(n^3)`操作 (各クエリでチェックできる)`O(n^2)`サブ配列)、遅すぎます。 mex とインクリメンタル構築の特性を活用するアプローチが必要です。 

単純な実装でつまずくことが多いエッジ ケースには、次のようなクエリが含まれます。`k`配列内の現在の最大値、長さ 1 の範囲、および繰り返し要素を超えています。 たとえば、配列が次の場合、`[0,0,0]`そして`k=1`の場合、セグメントは次のようになるため、答えはゼロではありません。`[0]`mex 1 がありますが、実装が mex が max+1 に等しいと単純に仮定すると、誤ってゼロを返す可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、`a`配列にコピーし、すべてのセグメントを列挙します`[x, y]`と`l ≤ x ≤ y ≤ r`各セグメントの mex を計算します。 これは定義を直接適用するので正しいですが、`n=2·10^5`遅すぎます。 完全な長さの範囲を持つ 1 つのクエリでも、`O(n^2)`サブ配列、これを作成する`O(n^3)`全体。 

重要な洞察は、与えられた条件に対して、`k`、**数値を含まない連続した範囲を数えるという問題に減らすことができます。`0,1,…,k-1`正確に**、オプションで次の内容が含まれます`k`。 もし`k`がゼロの場合、セグメントにはゼロが含まれていてはなりません。 もし`k`が 1 の場合、ゼロを含めることはできますが、1 を含めることはできません。 これは、メキシコが等しいためです`k`からのすべての数字がそうである場合に限り、`0`に`k-1`少なくとも 1 回存在し、かつ`k`は不在です。 

これは、**次回発生追跡** アプローチを示唆しています。 それぞれについて、`k`数字`0`を通して`k-1`、次に出現するインデックスを維持します。 から始まるセグメントのこれらの中で最も古いインデックス`x`最大値を決定します`y`メキシコが残るように`k`。 このインデックスの後に始まるセグメントは mex 制約を満たすことができません。 これらのインデックスを効率的に（たとえば、一定のサイズの配列で）保持することにより、`n+1`)、クエリごとに線形時間で有効なセグメントの数を計算できます。 

最適化は、小規模な mex クエリの場合、`k`（まで`n`)、セグメントの境界は、最初の欠落番号の位置によって効果的に決定されます。 このプロパティを使用して、実際にセグメントの mex を直接計算することはありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適 (次回発生追跡) | クエリあたり O(n) | O(n + k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空の配列を初期化する`arr`そして配列`last_occurrence`長さの`n+1`最後のインデックスを追跡するには、各番号が表示されます。 初期化する`lans = 0`。 
2. 各操作ごとに`i`:

 ａ． 実際の値をデコードする`a, l, r, k`前の回答を使用して`lans`。 

b. 追加`a`配列に。 
3. セグメントをカウントするには`mex = k`:

 ａ． もし`k > n`mex は超えることができないため、すぐに 0 を返します。`n`長さの配列で`n`。 

b. 最新の数値を追跡する`0`に`k-1`。 現在の範囲のこれらの出現の最小インデックスによって、指定された位置から始まるセグメントがどれだけ右にあるかが決まります。`l`延長することができます。 
4. 反復処理`l`に`r`。 開始インデックスごとに、事前に計算されたインデックスを使用して有効な終了インデックスの数を計算します。`last_occurrence`。 これらのカウントを累積して生成します`lans`。 
5. 出力`lans`このクエリの場合。 アップデート`lans`次のクエリのデコードに使用されます。 

**機能する理由**: 不変条件は次のとおりです。`last_occurrence[x]`常に最新の位置を反映します。`x`現れた。 メキシコ人`k`数字が必要です`0..k-1`少なくとも一度は現れること。 このプロパティが失敗した最初の位置を追跡することにより、範囲内のすべての有効な部分配列が正しく計算されます。 これにより、依存関係がある場合でも、すべてのクエリの正確性が保証されます。`lans`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
queries = [tuple(map(int, input().split())) for _ in range(n)]

arr = []
last_pos = [-1] * (n + 1)
lans = 0

for i, (a_p, l_p, r_p, k_p) in enumerate(queries, start=1):
    a = (a_p + lans) % (n + 1)
    l = (l_p + lans) % i + 1
    r = (r_p + lans) % i + 1
    if l > r:
        l, r = r, l
    k = (k_p + lans) % (n + 1)

    arr.append(a)
    if k > n:
        lans = 0
        print(0)
        continue

    # Track the latest occurrence of 0..k-1
    latest = [-1] * k
    for num in range(k):
        latest[num] = -1
    count = 0
    pos_map = dict()
    for idx in range(l-1, r):
        val = arr[idx]
        pos_map[val] = idx
        if val < k:
            latest[val] = idx
        min_latest = max(latest) if latest else -1
        count += max(0, idx - min_latest)
    lans = count
    print(lans)
```**実装の説明**: 配列`arr`追加されたすべての要素を累積します。`latest`各数値の最新のインデックスを追跡します`0..k-1`。 開始インデックスの場合`l-1`に`r-1`、有効なサブ配列数は、必要な数の最も最近の出現までの距離によって決まります。 使用する`max(latest)`すべてが一致するセグメントのみをカウントするようにします。`0..k-1`数字が存在し、`k`は不在です。 境界チェックは範囲を処理します。`l > r`デコード後。
