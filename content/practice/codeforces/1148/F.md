 ## 解決策
 ## 問題の理解

 オブジェクトのコレクションが与えられ、それぞれが符号付きの値とバイナリ マスクを提供します。 正の整数を選択する必要があります`s`。 一度`s`が固定されている場合、各オブジェクトはそのまま維持されるか、から計算されるパリティ条件に応じて符号が反転されます。`s`そしてそのマスク。 

具体的には、オブジェクトごとに計算します。`t_i = s & mask_i`。 次に、セットされたビットが何個あるかを数えます。`t_i`。 このカウントが奇数の場合、値は`val_i`否定される場合、それ以外の場合は変更されません。 すべてのオブジェクトを処理した後、変更されたすべての値を合計します。 目標は選択することです`s`この最終的な合計は、元の合計とは逆の符号を持ち、ゼロではありません。 

入力サイズは大きく、最大 3 · 10^5 オブジェクトで、各マスクは最大 62 ビットに収まります。 これにより、可能なすべてを反復しようとするアプローチは即座に除外されます。`s`、 以来`s`それ自体は 2^62 のサイズの空間に存在します。 単一の候補者を評価しようとしても`s`すべてのオブジェクトをスキャンする必要があるため、実行可能なソリューションは適切なソリューションを構築する必要があります。`s`線形または線形に近い時間で集合構造から直接。 

素朴な見方は、ビットのサブセットを選択していると考えることです。`s`、各ビットは独立して寄与するため、`s & mask_i`。 ただし、AND 結果の設定ビット数のパリティはビットごとに線形ではありません。 それは各マスク内のビットの組み合わせによって異なります。 ここで、直接的な貪欲なアイデアのほとんどが失敗します。 

すべての値が正であるか、1 つの大きな外れ値を除いてすべて負である場合、微妙なエッジ ケースが発生します。 「最も貢献度の高いマスク」を個別に反転しようとする単純な貪欲な場合は、単一のビットを反転するだけなので失敗する可能性があります。`s`同時に、予測できないパリティ パターンで多くのマスクに影響を与えます。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての値を列挙します。`s`1 から 2^62 − 1 まで、各候補の結果の変換された合計を計算し、符号を確認します。 これはプロセスを直接シミュレートするため正しいですが、実行不可能です。10^6 の候補をテストするだけでもすでに遅すぎ、全空間は天文学的に大きいです。 

重要な構造的観察は、実際には正確な変換された合計は気にせず、それが正になるか負になるかだけを気にするということです。 各オブジェクトは次のいずれかに貢献します`+val_i`または`-val_i`したがって、変換は配列に対する符号反転パターンを定義します。 

パリティ条件は再解釈できます。各オブジェクトの符号反転は、オブジェクトのビットセット間の交差のパリティによって決まります。`s`とビットセット`mask_i`。 これは、まさに、次のバイナリ ベクトル間の GF(2) の内積のパリティです。`s`そして`mask_i`。 

したがって、各オブジェクトは次の係数に寄与します。`(-1)^{<s, mask_i>}`どこ`< , >`XOR ドット積パリティです。 最終的な合計は、指数反転内の GF(2) 線形形式上の関数になります。 重要な単純化は、変換全体が、ビットによって引き起こされるパリティ構造のみに依存することです。`s`。 

選択することを考えることができます`s`少しずつ。 各ビットはマスクのサブセットの反転に独立して参加します。`k`そのビットが設定されているすべてのマスクに影響します。 固定の場合`k`を切り替えると、そのビットを含むすべてのマスクのパリティが反転します。 これにより、最終的な合計に対する各ビットの影響を段階的に推論することができます。 

正確に最適なビットのサブセットを求める代わりに、建設的な事実を利用します。つまり、単一のビット位置が常に存在し、その活性化だけで変換された合計がすでにゼロを横切るか、または少なくとも、以前に選択されたビットと貪欲に結合されたときに正しい方向に符号が変わります。 これにより、限界効果に基づいてビット寄与のサブセットを貪欲に選択する作業が軽減されます。 

現在の合計を維持し、各ビットの切り替えの効果を評価します。 ビットごとに`k`を含めた場合に符号が反転する値の数を計算します。 これは、各ビットについて、マスクに現在のパリティ状態のビットが含まれているオブジェクト間の寄与の差を事前計算することによって実行できます。 

貪欲な構築が構築する`s`最上位ビットから最下位ビットまで、各包含により合計が符号反転に近づくようにします。 各ビットは制御された方法で素パリティの寄与に影響を与えるため、このプロセスは O(62 · n) で安定します。

 ## アルゴリズムのチュートリアル

 問題を部分を選択するように再定式化します。`s`各ビットが符号反転パターンにどのように影響するかを追跡しながら、1 つずつ実行します。 

1. 初期合計を計算する`S = sum(val_i)`。 もし`S > 0`、最終的な合計が負になるようにします。 それ以外の場合は、それをポジティブにしたいと考えます。 
2. 各ビット位置の事前計算`k`(0 ～ 61) オブジェクトのセット。`mask_i`ビットがある`k`セット。 これにより、ビットをアクティブにする効果をすぐに評価できます。`k`。 
3. 各オブジェクトの現在の「符号状態」を維持します。最初はすべて正です (ビットが選択されていません)。`s`まだ反転しないことを意味します）。 
4. 高から低までの各ビットについて、このビットを切り替えた場合に何が起こるかをシミュレートします。`s`。 これにはパリティ効果を再計算する必要があります。マスクにこのビットが含まれているすべてのオブジェクトの符号は、現在の状態に対して反転します。 
5. このビットが含まれている場合は、結果として生じる新しい合計を計算します。 反転すると符号が入れ替わるため、変更は、現在プラスにカウントされている影響を受けるすべてのオブジェクトの寄与を 2 倍マイナスして減算することで計算されます。 
6. 合計をターゲットの符号に近づける場合、またはゼロと交差する必要がある場合は、ビットを選択します。 それに応じて現在のサインの状態を更新します。 
7. すべてのビットが処理されるまで続行します。 構築したものを出力する`s`。 

### なぜ効果があるのか

 それぞれのビット`s`オブジェクトのセットに対する独立した XOR パリティの切り替えを定義します。 これらのトグルは最終的な合計で相互作用しますが、すべてのステップでローカルな決定の正確なグローバルな影響が評価されるため、貪欲な構築は機能します。 各ビット フリップは完全な現在の状態に対して評価されるため、後のビットによって以前の最適性の決定が無効になることはありません。 このプロセスは現在の合計の一貫した変換を維持し、終了時に累積された変換は 2 つの符号領域のいずれかに到達し、問題ステートメントによって存在が保​​証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    vals = []
    masks = []
    
    total = 0
    for _ in range(n):
        v, m = map(int, input().split())
        vals.append(v)
        masks.append(m)
        total += v

    # We will maintain current contribution after applying chosen bits
    cur = vals[:]

    s = 0

    for b in reversed(range(62)):
        # try flipping bit b in s
        flipped = cur[:]
        
        for i in range(n):
            if (masks[i] >> b) & 1:
                flipped[i] = -flipped[i]

        new_sum = sum(flipped)

        # target is to move toward opposite sign of original total
        if total > 0:
            # want negative
            if new_sum < total and new_sum != 0:
                s |= (1 << b)
                cur = flipped
        else:
            # want positive
            if new_sum > total and new_sum != 0:
                s |= (1 << b)
                cur = flipped

    print(s)

if __name__ == "__main__":
    solve()
```この実装は、配列全体の状態に対する各ビットの影響を明示的にシミュレートします。 ビットごとの合計を再計算しますが、固定の 62 ビット制限により、一般的な制約の下で Python の許容範囲内に解が維持されます。 

各ビットは、現在の変換状態に対して個別にテストされます。 適用することで符号反転の方向が改善される場合、コミットされます。 重要な点は、元の値ではなく、常に変換された現在の値に対して評価し、累積効果の一貫性を確保していることです。

 ## 特殊なケース

 重要なエッジケースは、すべてのマスクが同一である場合です。 そのような状況では、あらゆる点で、`s`すべての要素を同時に反転します。つまり、変換全体が合計を維持するか、合計を否定するかのどちらかになります。 各ビット評価ではすべてのオブジェクトにわたって同一の効果が見られるため、アルゴリズムはこれを自然に処理し、グローバル符号を反転する場合にのみビットを選択します。 

もう 1 つのエッジ ケースは、1 つのオブジェクトだけがゼロ以外の値を持つ場合です。 次に、マスク内に存在する任意のビットが選択されていれば、その符号がすぐに反転され、貪欲な選択は反転を生成する任意の有効なビットを受け入れます。 段階的な評価により、必要なときにそのようなビットが選択されることが保証されます。

 3 番目のケースは、初期合計が絶対値ですでにゼロに近い場合です。 それでも、アルゴリズムはマグニチュードヒューリスティックに依存しません。 常に正確な結果の合計を評価するため、ゼロを生成する遷移を拒否することで偶発的なゼロ出力を正しく回避します。
