 ## 問題の理解

 同じ長さの 2 つの文字列が与えられています。 許可される唯一の操作は、現在の文字列から文字を選択し、それを一番前または一番後ろに移動することです。 移動するたびに、そのキャラクターはその位置から削除され、2 つの極端な位置のいずれかに再挿入されます。 

目標は、最初の文字列を変換することです`s`ターゲット文字列に`t`最小限の数の移動を使用するか、実行できないと報告します。 

重要な観察は、この操作によって複数の文字セットが変更されることはないということです。 それはそれらを並べ替えるだけです。 これは、両方の文字列にまったく同じ文字数が含まれている必要があるという必要な条件を直ちに暗示します。 1 文字でも周波数が異なる場合は、一連の動きで修正することはできません。 

制約は小さく、`n ≤ 100`テストごとに最大 100 テスト。 これにより、3 次または 2 次の動作を伴うソリューションが快適に実行できるようになります。 ただし、操作の構造には高度な制約があるため、状態検索を使用して任意の再配置をシミュレートする単純なアプローチは依然として必要ありません。 

素朴な推論による微妙な失敗例は、次に必要な文字を常に直接その位置に移動することで、文字を左から右に貪欲に一致させることができると仮定することです。 これは、キャラクターの移動が相対的な順序に影響を及ぼし、後で追加の移動を強制する可能性があるという事実を無視しています。 

たとえば、次のことを考えてみましょう。`s = "abac"`

`t = "baca"`単純な戦略では正しい文字を繰り返し前面に表示する可能性がありますが、選択によっては、数えすぎたり、後方挿入をより効果的に使用するより良いシーケンスに気付かなかったりする可能性があります。 

正しい解決策は、許可された動きを反映する構造化された方法で、ターゲットのどの程度をサブシーケンスとして照合できるかを推論する必要があります。 

## アプローチ

 ブルートフォース解釈では、すべての文字列を状態として、すべての動きをエッジとして扱い、次に到達可能な順列に対して最短パス検索を実行します。`s`。 各州にはあるので、`O(n)`可能な動きはあります`n!`州では、たとえ小規模であってもこれは完全に実行不可能です`n`。 

構造上の重要な洞察は、この操作では 1 つの文字のみが抽出され、それが端の 1 つに配置されるということです。 これは、すでに正しい相対順序で出現している文字を意味します。`s`そして`t`必ずしも移動する必要はありません。 問題は、間違って配置された文字だけを「抽出」しながら、可能な限り多くの順序を維持することになります。 

このプロセスを逆に再解釈することができます。 構築する代わりに`t`から`s`、私たちは調整しようとします`s`と`t`すでに一致している大きな中央セグメントを特定することによって`t`安定した方法でサブシーケンスとして。 この位置合わせされた領域の外側にある文字は、実行する必要がある移動に対応しており、各移動は、位置を間違えた 1 つの文字を最後まで押し込むことによって効果的に修正されます。 

これは核となるアイデアにつながります。「一致させようとする」`t`に対して`s`両端からの削除が可能ですが、再配置する必要がある文字の数は最小限に抑えられます。 

それを確認するための 1 つの明確な方法は、次の最長のサブシーケンスを見つけることです。`t`回転をシミュレーションするときにその位置に留まることができます`s`の中へ`t`。 この保存された構造にないすべての文字は少なくとも 1 回移動する必要があり、操作の構造により、そのような不一致はそれぞれ 1 回の移動で個別に解決できることが保証されます。 

したがって、答えは次のようになります。`n - L`、 どこ`L`実現可能性の制約を考慮しながら、正しい相対順序を維持できる文字の最大数です。 これは、末尾の挿入のみが許可されるという特別な制限の下で最長の共通部分列を見つけるのと同じであり、これは、文字数をカウントする貪欲な 2 ポインタ マッチングに集約されます。`t`内部で順番に並べることができます`s`最適な再配置後。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. まず、文字頻度を比較して実現可能性を検証します。`s`そして`t`。 それらが異なる場合、答えは次のとおりです。`-1`。 移動によって文字数が変更されることはないため、これが必要です。 
2. 2 ポインター戦略を使用して、次の文字数を計算します。`t`内部で順番に一致させることができます`s`構造の可能な限り最高の保持をシミュレートしながら。 スキャンしていきます`s`の各文字に貪欲に一致させようとします`t`順番に。 
3. 一致する文字が見つかるたびに、両方のポインタを進めます。 一致しない場合は、ポインタのみを進めます。`s`。 これはどれくらいの量を測定しますか`t`すでに「埋め込まれている」`s`再配置の必要のない順序付けられた構造として。 
4. この一致した長さを次のようにします。`L`。 残り`n - L`文字は、許可された操作を使用して再配置する必要がある要素に対応します。 このような不一致は、構築の適切な段階でキャラクターを正しい端まで引っ張ることにより、1 回の移動で解決できます。 
5. 出力`n - L`最小移動数として。 

### なぜ効果があるのか

 不変条件は、貪欲なマッチングがプレフィックスの一貫性のある最長の埋め込みを計算することです。`t`内部`s`エンドのみの抽出操作でも存続できます。 この埋め込みの一部ではない文字は、保存された構造の境界を少なくとも 1 回横切る必要があり、移動ごとに、単一の文字を極端に再配置することで、そのような修正が 1 回だけ可能になります。 移動は、保存されたサブシーケンス内ですでに固定されている相対的な順序を妨げないため、2 つの不一致を個別に解決するよりも安価に解決することはできません。 これによりカウントが厳しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        s = input().strip()
        t = input().strip()

        if sorted(s) != sorted(t):
            print(-1)
            continue

        i = 0
        j = 0

        while i < n and j < n:
            if s[i] == t[j]:
                j += 1
            i += 1

        L = j
        print(n - L)

if __name__ == "__main__":
    solve()
```この解決策は、両方の文字列に同一の文字の複数セットが含まれているかどうかを確認することから始まります。 制約が少ない場合は、並べ替えで十分です。 異なる場合は、直ちにケースを却下します。 

2 ポインター ループは、次の文字数を計算します。`t`内部で順番に一致させることができます`s`。 ポインタ`i`スキャン`s`、 その間`j`の進行状況を追跡します`t`。 試合が成功するたびに両方に進み、それ以外の場合はのみ`i`前進します。 これにより、次の最長のサブシーケンスの長さが生成されます。`t`で見つかりました`s`。 

最終的に、答えは次のように計算されます。`n - L`、完全な位置合わせを行うために端の 1 つにアクティブに移動する必要がある文字に対応します。

 ## 特殊なケース

 次のような同一の文字列の場合`s = "aaaa"`、周波数の一致が保持され、完全なサブシーケンスのアライメントが即座に成功するため、アルゴリズムはゼロの手を正しく計算し、次のようになります。`L = n`。 

次のような完全に反転した文字列の場合`s = "abcd"`、`t = "dcba"`の場合、周波数チェックは合格しますが、貪欲なマッチングではほとんど一致が検出されず、高い不一致数が発生します。 それぞれの不一致は 1 つの必要な境界移動に対応し、アルゴリズムはすべての文字を少なくとも 1 回は再配置する必要があることを正確に捕捉します。 

単一文字の文字列の場合、一致チェックと頻度チェックの両方が簡単な結果に陥り、特別な処理を行わなくても正確さが保証されます。
