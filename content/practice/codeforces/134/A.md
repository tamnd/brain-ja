 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 すべての位置について、その要素を削除し、残りの数値の算術平均を計算します。 削除された値自体がその平均と正確に等しいすべての位置を見つけなければなりません。 

配列が次のようになっているとします。`[1, 2, 3, 4, 5]`。 取り除いたら`3`、残りの数字は`1, 2, 4, 5`。 それらの合計は`12`、その平均は`12 / 4 = 3`、インデックス`3`有効です。 

配列サイズは次の範囲に達します`2 · 10^5`これにより、すべての位置の合計を最初から再計算するソリューションは即座に除外されます。 二次アルゴリズムは次のように実行されます。`4 · 10^10`最悪の場合、1 秒の制限時間をはるかに超えた操作が行われます。 線形時間に近いものが必要です。 

値自体はせいぜい小さいです`1000`、しかし、それは高価なネストされたループを正当化するには十分ではありません。 ボトルネックは要素の数であり、数値の大きさではありません。 

簡単な間違いの 1 つは、平均に浮動小数点演算を使用することです。 条件は完全に等しいため、浮動小数点比較では精度の問題が発生する可能性があります。 すべて整数で扱うことができます。 

次の入力を考えてみましょう。```
3
1 2 3
```取り除いたら`2`、残りの平均は`(1 + 3) / 2 = 2`、インデックス`2`有効です。 

不注意な実装では平均を浮動小数点数として計算し、それらを直接比較する可能性がありますが、これは不必要かつ危険です。 

もう 1 つの微妙なケースは、残りの合計が次の数で割り切れない場合です。`n - 1`。```
4
1 1 1 2
```最後の要素の残りの平均は次のようになります。`(1 + 1 + 1) / 3 = 1`、 それで`2`は無効です。 

最初の要素の残りの平均は次のようになります。`(1 + 1 + 2) / 3 = 4/3`、これは整数ではありません。 配列要素は整数であるため、このインデックスは機能しません。 割り算チェックを忘れると、間違った答えが生成される可能性があります。 

すべての値が等しい配列もチェックする価値があります。```
5
7 7 7 7 7
```すべてのインデックスは削除されるため、有効になります。`7`平均を残す`7`。 

## アプローチ

 最も直接的な解決策はブルートフォースです。 あらゆるインデックスに対して`i`、 取り除く`a[i]`、残りのすべての要素の合計を計算し、で割ります。`n - 1`、結果が次と等しいかどうかを確認します`a[i]`。 

文字通り定義に従っているので、強引な方法は正しいです。 問題は繰り返しの合計です。 残りの合計の計算には次の時間がかかります`O(n)`1 つのポジションに対して時間を置き、これをすべてのポジションに対して繰り返します`n`ポジション、与える`O(n^2)`全体的な複雑さ。 

と`n = 2 · 10^5`、これはおおよそ次のようになります。```
2 · 10^5 × 2 · 10^5 = 4 · 10^10
```動作が遅すぎます。 

重要な観察は、配列の合計がすでにわかっている場合、残りの要素の合計を即座に取得できるということです。 

させて：```
total = sum of all elements
```取り除いたら`a[i]`、 それから：```
remaining_sum = total - a[i]
```条件は次のようになります。```
a[i] = (total - a[i]) / (n - 1)
```実際に平均を浮動小数点値として計算する代わりに、方程式を並べ替えます。```
a[i] × (n - 1) = total - a[i]
```または同等の意味で:```
a[i] × n = total
```これは、問題全体を 1 つの単純な等式にまとめたものです。 

すべての位置を一定時間内に独立してチェックできるようになり、`O(n)`解決。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、その合計を計算します。 

合計により、一定時間内に任意の位置を削除した後に残った要素の合計を導き出すことができます。 
2. 空のリストを作成する`answer`有効なインデックスを保存します。 

インデックスを昇順で出力する必要があるため、左から右にスキャンすると、必要な順序が自然に保持されます。 
3. インデックスごとに`i`、次のことを確認します。```
a[i] × n == total
```これは、平均条件を並べ替えることから直接得られます。 
4. 条件が成立する場合は追加します。`i + 1`回答リストに追加します。 

この問題では 1 から始まるインデックスが使用されますが、Python 配列は 0 から始まるインデックスが使用されます。 
5. 有効なインデックスの数を出力します。 
6. インデックス自体を出力します。 

### なぜ効果があるのか

 インデックスの場合`i`有効であるためには、値`a[i]`他のすべての要素の平均と等しくなければなりません。```
a[i] = (total - a[i]) / (n - 1)
```両辺を乗算すると、`n - 1`与える:```
a[i](n - 1) = total - a[i]
```項をまとめて移動する:```
a[i]n = total
```アルゴリズムは、すべてのインデックスについてこの条件を正確にチェックします。 この方程式は元の定義と数学的に同等であるため、報告されるすべてのインデックスは正しく、すべての正しいインデックスが報告されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    total = sum(a)

    ans = []

    for i in range(n):
        if a[i] * n == total:
            ans.append(i + 1)

    print(len(ans))

    if ans:
        print(*ans)

solve()
```最初のステップでは、合計を 1 回計算します。 これは、繰り返し合計する必要をなくす重要な最適化です。 

条件:```
a[i] * n == total
```は、元の平均方程式を再構成したものです。 整数演算を使用すると、浮動小数点の問題がすべて回避されます。 

ステートメントではそれが必要であるため、回答リストには 1 から始まるインデックスが格納されます。 を忘れて`+1`1 つ違いのよくある間違いです。 

2 番目の出力行は、有効なインデックスが少なくとも 1 つある場合にのみ出力されます。 この問題では、回答数が 0 の場合、行を省略したり、空の行を出力したりすることができます。
