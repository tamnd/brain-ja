 ## 解決策
 ## 問題の理解

 私たちに与えられた村は、`n`家が並んでいる。 各居住者は、通りのどちら側に住みたいかの好みを持っています: 左 (`0`) または右 (`1`）。 村の計画立案者は、両側の住民の少なくとも半数が満足できるように、家と家の間のどこかに道路を配置したいと考えています。 希望する側を獲得する住民の数が少なくともその側の家数の半分の上限であれば、側は満足します。 

事実上、この問題ではパーティション インデックスを見つけることが求められます。`i`(道路は家の後です`i`) の左セグメントの長さが`i`少なくとも`ceil(i/2)`ゼロと長さの右側のセグメント`n-i`少なくとも`ceil((n-i)/2)`もの。 有効なものの中で`i`、村の中央に最も近いものを選択する必要があります。つまり、最小化する必要があります。`abs(n/2 - i)`、小さな者によって絆が切れた`i`。 

この制約により、すべてのテスト ケースで最大 300,000 戸の住宅と、最大 20,000 のテスト ケースが許可されます。 左右のセグメントのフル スキャンですべての分割をチェックする単純なソリューションでは、最悪の場合、テスト ケースあたり O(n^2) となり、非常に遅すぎます。 テスト ケースごとに O(n) 以上のソリューションが必要です。 エッジ ケースには、同じ側を好むすべての家、境界の道路 (最初の家の前または最後の家の後)、またはセグメントの半分の天井に影響を与える奇数と偶数のサイズのセグメントが含まれます。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての分割が考慮されます。`i`0から`n`そして、左側のセグメントのゼロと右側のセグメントの 1 の数を数えます。 カウントが上限条件を満たしていれば、有効とみなされます。 このアプローチは論理的には機能しますが、分割ごとに配列の一部をスキャンする必要があるため、大きな文字列に対して O(n^2) の操作が必要となり、実用的ではありません。`n`3・10^5まで。 

重要な洞察は、プレフィックスの合計を事前計算できることです。 させて`prefix_zeros[j]`最初のゼロの数になります`j`家々。 次に、長さの左側のセグメントにあるゼロの数`i`は`prefix_zeros[i]`。 長さの右側のセグメントにある 1 の数`n-i`次のように導出できます`(total_ones - prefix_ones[i])`または同等の`((n - prefix_zeros[n]) - (i - prefix_zeros[i]))`、しかしより簡単なのは、1 のプレフィックスの合計も計算することです。 これらのプレフィックスの合計を使用すると、各分割のチェックは O(1) になり、最適な分割を見つけるために配列を 1 回通過するだけで済みます。 

満足条件が 0 と 1 の数にのみ依存するという観察により、上限の不等式を接頭語の合計を使用した単純な数値比較に変換できます。 これにより、潜在的に二次的なブルート フォースが線形時間に短縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | プレフィックス合計 / リニア スキャン | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`そして文字列`a`。 変換する`a`算術を簡単にするために整数のリストに変換します。 
2. ゼロのプレフィックスの合計を計算します。`prefix_zeros`、 どこ`prefix_zeros[i]`最初のゼロの数です`i`家々。 
3. 1 の合計数を計算します。`total_ones`、配列全体で 1 を数えるか、配列から 0 を減算します。`n`。 
4. 変数を初期化して最適なインデックスを追跡する`best_i`そして中心までの最小距離`min_dist = n`。 最小限に抑えるよう努めます`abs(n/2 - i)`。 
5. 考えられるすべての分割インデックスを反復処理します。`i`0から`n`。 各分割では、左側のセグメントの長さは次のようになります。`i`、右セグメントの長さ`n-i`。 
6. 左側のゼロの数を計算します。`left_zeros = prefix_zeros[i]`。 右側の 1 の数を計算します。`right_ones = total_ones - (i - left_zeros)`。 
7.次のことを確認します`left_zeros >= ceil(i/2)`そして`right_ones >= ceil((n-i)/2)`。 上限には整数演算を使用します。`ceil(x/2) = (x+1)//2`。 
8. 両方の条件が成立する場合、計算します。`dist = abs(n/2 - i)`。 もし`dist < min_dist`または`dist == min_dist`そして`i < best_i`、 アップデート`best_i`そして`min_dist`。 
9. ループ後、出力`best_i`。 

機能する理由: プレフィックスの合計により、左側のセグメントにゼロがいくつあるか、右側のセグメントに 1 がいくつあるかが即座にわかります。 天井条件は整数演算で適切に処理されます。 全部スキャンすると`i`0から`n`中央に最も近いものを追跡することで、ソリューションが公平性条件と最小距離要件の両方を満たしていることを確認します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = input().strip()
        arr = [int(ch) for ch in a]

        prefix_zeros = [0]*(n+1)
        for i in range(n):
            prefix_zeros[i+1] = prefix_zeros[i] + (1 if arr[i] == 0 else 0)
        total_ones = n - prefix_zeros[n]

        best_i = 0
        min_dist = n
        for i in range(n+1):
            left_len = i
            right_len = n - i
            left_zeros = prefix_zeros[i]
            right_ones = total_ones - (right_len - (total_ones - (prefix_zeros[n] - prefix_zeros[i])))
            right_ones = total_ones - (i - left_zeros)

            if left_zeros >= (left_len + 1)//2 and right_ones >= (right_len + 1)//2:
                dist = abs(n/2 - i)
                if dist < min_dist or (dist == min_dist and i < best_i):
                    best_i = i
                    min_dist = dist
        print(best_i)

if __name__ == "__main__":
    solve()
```この実装では、ゼロのプレフィックスの合計を計算します。 右側のセグメントの 1 の数は、左側でカウントされた 1 を合計から減算して計算されます。 の`(length + 1)//2`トリックは天井分割を正しく処理します。 0 から 0 までの繰り返し`n`最初の家の前と最後の家の後を含め、道路のすべての可能な配置を確実に考慮します。 タイブレーク ロジックにより、2 つの位置が中心に等しく近い場合、より小さいインデックスが選択されます。
