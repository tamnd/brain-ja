 ## 解決策
 ## 問題の理解

 参加者のグループが与えられ、各テントに最大 3 人まで収容できるテントに割り当てられます。 参加者には 3 つのタイプがあり、テントを共有する方法についての制約が異なります。 

内向的な人はテントを共有することをまったく拒否するため、内向的な人はそれぞれ単独でテントを占有する必要があります。 外向的な人はその反対の極端です。各人はちょうど 3 人の完全なテントにいることを主張します。つまり、すべての外向的な人は他の 2 人の参加者とグループ化されなければなりません。 ユニバーサルは柔軟性があり、テントのサイズが 3 人を超えない限り、単独で、または他の 1 人で、または 2 人でテントを占有することができます。 

課題は、すべての制約を尊重しながら全員をテントに割り当てることが可能かどうかを判断し、可能であれば使用するテントの数を最小限に抑えることです。 

入力サイズは最大 10^4 テスト ケースで、各タイプのカウントは 10^9 までになります。 これにより、個人に対するシミュレーションは即座に除外されます。 正しいソリューションは、各テスト ケースを定数時間の演算に削減する必要があります。 

単純なアプローチでは、テントを段階的に貪欲に埋め、人がなくなるまで有効なグループを繰り返し形成しようとする可能性があります。 割り当ての順序が実現可能性に影響するため、この種のシミュレーションは危険です。 たとえば、普遍的なものを早く消費しすぎると、後で完全な外向的なグループを完成させることができなくなる可能性があります。 

重要なエッジ状況は、すべてのユニバーサルを使用した後でも、外向的な人を 3 人の完全なグループに入れることができない場合に現れます。 

入力:```
0 1 1
```1 人の外向的で 1 人の普遍的な人が 3 人の有効なグループを形成することはできません。また、外向的な人が一人でいることも、部分的なテントの中にいることもできません。 正しい出力は次のとおりです`-1`。 普遍的なものを最初に他の場所に配置する貪欲なアルゴリズムは、外向的な人を立ち往生させて、実現可能性を誤って結論付ける可能性があります。 

もう一つの微妙な失敗は、内向的なグループが外向的なグループを完成させるために後でユニバーサルが必要になる可能性があるという事実を考慮せずに、推論の早い段階で内向的な人があまりにも多くのテントを消費したときに発生します。 

これらの観察は、残りのテントを数える前に、外向的な人に必要なユニバーサルの数を全体的に推論する必要があることを示唆しています。 

## アプローチ

 強引な解釈は、文字通りテントを建てることです。 私たちは、外向的な人を 3 人のグループに割り当て、次に内向的な人を 1 つのテントに配置し、最後に残りの空きスロットにユニバーサルを分配することを繰り返し試みます。 テストケースごとに、外向的なグループと残りのテントの間でユニバーサルの可能な分布をすべて試してみます。 

ただし、状態空間は参加者の数に応じて拡大します。 各人を 1 回処理する単純化されたシミュレーションでも、テスト ケースごとに O(a + b + c) のリスクがあり、最悪の場合、すべての入力で 10^14 の演算が必要になります。 これでは遅すぎます。 

問題の構造は、より直接的な分解を示唆しています。 内向的な人は固定されています。彼らは常にそれぞれ 1 つのテントを消費します。 外向的な人も厳格です。正確に 3 人のグループを形成しなければならないため、b テントに貢献しますが、b が完全なトリプルに分割できない場合は普遍者の助けが必要になる場合があります。 ユニバーサルは唯一の柔軟なリソースであり、その役割は外向的なグループの欠けている部分を埋め、その後残った部分的なグループを形成することです。 

重要な洞察は、まず外向的なグループを扱うことです。 完全に外向的なグループはそれぞれ、サイズ 3 のテントを 1 つ消費します。 b % 3 がゼロ以外の場合、残りの 1 人または 2 人の外向型はグループを完成させるために普遍型を必要とします。 それ以外の場合、十分なユニバーサルが存在しない場合、構成は不可能です。 外向的な人を満足させた後、残った万能テントは 3 つのグループにまとめることによってのみテントの数を減らすことができます。 

これにより、問題は代入検索ではなく単純な算術に縮小されます。

 | 最適 | テストごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. まず、内向型の人 1 人につき 1 つのテントを割り当てます。 内向的な人は共有できないので、これは強制されます。 答えは次から始めます`a`。 
2. 次に、外向的な人を 3 人のグループに分けて扱います。 3 人の外向的なグループ全体がちょうど 1 つのテントを消費するので、次のように追加します。`b // 3`答えに。 
3. 剰余を計算する`r = b % 3`。 これは、完全なグループを形成できない取り残された外向的な人々を表します。 
4. もし`r > 0`、最後の不完全な外向的なグループを完成させるには、ユニバーサルを使用する必要があります。 以下の場合は、`3 - r`普遍的なものは利用可能ですが、外向的な制約を満たしてリターンすることはできません。`-1`。 
5. 最後のグループを完了することができた場合、必要なユニバーサルを差し引きます。 不完全なグループはまだ 1 つのテントを提供しているため、次のように追加します。`1`答えに。 
6. これで、ユニバーサルが残りました。 これらは 3 つのグループに自由に詰めることができ、各グループが 1 つのテントを形成します。 追加`(c_remaining) // 3`答えに。 
7. 梱包後にユニバーサルが残っている場合は、引き続きテントを占有しますが、各テントは最大 3 人まで収容できるため、残ったユニバーサルは常に最大 1 つの追加の部分テントを形成します。 ただし、残りの 1 ～ 2 個のユニバーサルにはまだ 1 つのテントが必要であるため、これはすでに整数の除算によって説明されています。 

よりコンパクトな定式化が現れます。外向型を処理した後、残りのスポットを埋めて、残りのユニバーサルを貪欲にテントに追加し、トリプルをグループ化するだけです。 

### なぜ効果があるのか

 このアルゴリズムは、参加者を剛性によって分離します。 内向型と外向型は固定的な構造的制約を課しますが、ユニバーサルは不完全な外向型グループを修復したり、余った能力を埋めるためにのみ使用されるリソースです。 不変条件は、外向型を処理した後、すべてのテントが完全に決定されるか、空きスロットが 1 つまたは 2 つだけあり、新しいテントを形成する前にユニバーサルが常にこれらのスロットに配置されることです。 新しいテントが避けられる場合に、部分的に充填された構造でユニバーサルを未使用のままにしておくのは決して有益ではないため、貪欲に梱包することが最適であり、テントの数を増やすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c = map(int, input().split())

        # introverts always need their own tents
        ans = a

        # handle extroverts in full groups of 3
        ans += b // 3
        r = b % 3

        if r:
            need = 3 - r
            if c < need:
                print(-1)
                continue
            c -= need
            ans += 1

        # pack remaining universals
        ans += (c + 2) // 3

        print(ans)

if __name__ == "__main__":
    solve()
```他の構成は有効ではないため、コードは最初に各内向型を個別のテントに割り当てます。 次に、外向的な人々を 3 つの完全なグループにまとめます。 残った外向的なメンバーは追加のテントの作成を強制しますが、そのグループを完成させるのに十分なユニバーサルが存在する場合に限ります。 

表現`(c + 2) // 3`これは、残りのユニバーサルを最大 3 つのグループに最適に梱包するために必要なテントの数を数える標準的な方法です。 特別な場合を除き、部分的な最終グループを暗黙的に処理します。 

よくある間違いは、外向的な剰余を解決する前にユニバーサルを配置しようとすることです。 これでは、ユニバーサルが必要のないところで消費され、必要な外向的なグループを完成させる方法がなくなるため、実現可能性のチェックができなくなります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        a, b, c = map(int, input().split())
        ans = a
        ans += b // 3
        r = b % 3
        if r:
            need = 3 - r
            if c < need:
                out.append("-1")
                continue
            c -= need
            ans += 1
        ans += (c + 2) // 3
        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 重大なエッジケースは、外向的な人が 3 つずつグループ化した後、残り 1 つまたは 2 つを残す場合です。 たとえば、次のように考えてみましょう`0 1 2`。 1 人の外向的な人は、あと 2 人がいないと有効なテントを形成できないため、ユニバーサルは 2 つあれば十分です。 アルゴリズムが検出するのは、`r = 1`、小切手`c >= 2`、テントが1つ完成します。 

もう 1 つの特殊なケースは、普遍的なものが豊富にあるにもかかわらず、厳格な内向的な要求により無関係である場合です。 のために`3 0 10`、内向的な人はすぐに 3 つのテントを消費し、残りの普遍的な人は単純に形成されます。`10`人が入り込む`4`テント (3,3,3,1)、合計`3 + 4 = 7`。 

最後に、外向的な人がまったくいない場合、問題は内向的な人と普遍的な人を個別にパッキングすることに帰着します。 外向的ブランチは何も貢献せず、ユニバーサルは天井分割を使用して最適にグループ化されるため、アルゴリズムは依然として機能します。
