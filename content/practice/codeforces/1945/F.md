 ## 解決策
 ## 問題の理解

 キリルは、エリクサーを醸造するためにワイズオークの下でキノコを集めたいと考えています。 キノコにはそれぞれ魔力があり、キノコ群から作られるエリクサーの強さはキノコの数とその中の最小魔力の積となります。 キリルは任意の順序でキノコを選ぶことができますが、微妙な罠を課す順列が与えられています。`k`マッシュルーム、インデックスの前にリストされているすべてのマッシュルーム`k`-番目の順列は価値がなくなり、魔力はゼロになります。 ゼロではない魔力を持つキノコのみがエリクサーに貢献します。 

入力は複数のテスト ケースを提供します。それぞれのテスト ケースは次のとおりです。`n`キノコ、その魔法の力の配列、そしてその順列。 出力では、テスト ケースごとに、エリクサーの最大強度と、それを達成するために必要なキノコの最小数を報告する必要があります。 

制約は、すべての合計が`n`テスト ケース全体で 200,000 を超えないこと。 これは、複雑なソリューションを意味します`O(n log n)`テスト ケースごとのテストは効率的に実行されますが、キノコのすべてのサブセットを考慮する単純な総当たりアプローチは問題外です。 最も権力のある最大のキノコが順列の後半に現れる場合、特殊なケースが発生します。 キノコを採りすぎると、最高のキノコが無効になる可能性があります。 たとえば、次の場合`v = [10, 1, 5]`そして`p = [2, 1, 3]`、3つのキノコをすべて摘むと10パワーのキノコが死に、エリクサーの強度が大幅に減少します。 

複数のマッシュルームが同じ値を共有する場合、別の特殊なケースが発生します。 順列によりより強力なキノコがゼロになる場合は、すべてを選択するよりも 1 つを選択する方が良い可能性があります。 

## アプローチ

 ブルートフォース手法では、選択するキノコの可能な数をすべて考慮し、ゼロ以外のキノコがどれかを計算し、その結果得られるエリクサーの強度を計算します。 のために`n`キノコ、これはおおよその結果です`O(n^2)`順列の各プレフィックスをチェックする必要があるため、テスト ケースごとに機能します。 これは明らかに遅すぎます`n`200,000まで。 

重要な洞察は、エリクサーの強さは常に、順列順序で連続するキノコの接頭辞によって決定されるということです。 その理由は、順列の最初にキノコを選択すると、その順序でその後に来るキノコにのみ影響するためです。 したがって、特定の数のキノコを選択する場合、順列の接頭辞の最後のキノコが、エリクサーに含まれる元の配列の最小インデックスを定義します。 これにより、キノコを魔法の力によって分類し、各キノコを含めるのに必要な順列の最大インデックスを段階的に追跡することができます。 これにより、問題は 1 つのパスに短縮されます。最大値から最小値までの値でソートされたマッシュルームを反復処理し、これまでに確認された最大の順列インデックスを維持し、強度を次のように計算します。`(number of mushrooms) * (current mushroom value)`、最適なソリューションを更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 並べ替え + プレフィックス追跡 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`、魔法の力の配列`v`、および順列`p`。 変換する`p`計算を簡素化するためにゼロベースのインデックスを作成します。 
2. タプルのリストを作成する`(value, original_index)`から`v`そのため、元の位置を失うことなく、魔法の力によってキノコを分類することができます。 
3. このリストを降順に並べ替えます。`value`。 より大きな魔法のパワーがエリクサーの強度を支配するため、最初により強力なキノコを検討したいと思います。 
4. 変数を初期化する`max_perm_index`選択したキノコの順列の最大のインデックスを追跡します。 このインデックスは、現在のキノコを含めるために選択する必要があるキノコの最小数を示します。 
5. ソートされたキノコのリストを繰り返し処理します。 各キノコについて:

 ａ． アップデート`max_perm_index`現在の値と現在のマッシュルームの順列インデックスの最大値として。 

b. 採取するキノコの数を計算します。`max_perm_index + 1`。 

c. エリクサーの強さを次のように計算します。`(number of mushrooms to pick) * (current mushroom value)`。 

d. この強度が以前の最大値を超えた場合は、対応するキノコの数とともに保存します。 同じ場合は、キノコの数が小さい方を選択します。 
6. すべてのキノコを処理した後、そのテスト ケースの最大強度と最小キノコ数を出力します。 

機能する理由: マッシュルームのパワーの降順で繰り返し、最大の順列インデックスを追跡することで、考慮されたすべてのマッシュルームが有効なプレフィックスに含まれることを保証します。 これにより、選択したサブセットの最小パワーが現在のマッシュルーム値となり、選択されたマッシュルームの数が順列ゼロ化制約に従うことが保証されます。 このロジックでは、同点になった場合に、最も少ないキノコで最も強力なエリクサーが自然に見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        v = list(map(int, input().split()))
        p = list(map(int, input().split()))
        p = [x - 1 for x in p]  # convert to zero-based

        mushrooms = [(v[i], i) for i in range(n)]
        mushrooms.sort(reverse=True)

        max_perm_index = -1
        best_strength = 0
        best_count = 0

        pos_in_perm = [0] * n
        for idx, pi in enumerate(p):
            pos_in_perm[pi] = idx

        for val, original_idx in mushrooms:
            max_perm_index = max(max_perm_index, pos_in_perm[original_idx])
            count = max_perm_index + 1
            strength = count * val
            if strength > best_strength or (strength == best_strength and count < best_count):
                best_strength = strength
                best_count = count

        print(best_strength, best_count)

if __name__ == "__main__":
    solve()
```最初のセクションは入力を読み取り、置換インデックスをゼロベースに変換します。 私たちは、`pos_in_perm`各マッシュルームの元のインデックスを順列内の位置にマッピングする配列。 キノコを価値別に分類すると、強いキノコが最初に考慮されるようになります。 トラッキング`max_perm_index`必要なプレフィックス サイズを維持し、強度の計算により、この選択によってエリクサーが向上するかどうかがチェックされます。 同点の最小数の選択は条件文で実装されます。 これは微妙な部分です。 タイの処理を忘れると、キノコの最小数が不正確になります。
