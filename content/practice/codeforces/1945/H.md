 ## 問題の理解

 整数の配列が与えられ、2 人のプレイヤーがその配列を 2 つのグループに分割します。 Kirill は小さすぎず大きすぎないサブセット、具体的には少なくとも 2 つの要素、最大で 2 つの要素を選択できます。$n-2$要素。 選択された要素は赤色のグループを形成します。 それ以外はすべて青のグループになります。 

分割が修正されると、スコアは 2 つの独立した方法で計算されます。 赤い側では、選択されたすべての数値の GCD を取得します。 青側では、残りのすべての数値のビットごとの AND をとり、固定値を加算します。$x$。 キリルは、選択したセットの GCD がこの青い式よりも厳密に大きくなるようにしたいと考えています。 

タスクは、単純な意味ですべてのサブセットを最適化することではなく、有効な分割が存在するかどうかを判断し、存在する場合はそれを構築することです。 

制約は、すべてのサブセットを列挙することが不可能であることをすでに示唆しています。 サブセットに対する制限された検索であっても、$n$、 その間$n$まで上がります$4 \cdot 10^5$。 すべてのテスト ケースにわたる合計制約により、ケースごとに線形またはほぼ線形になるように強制されます。 

主な問題は、両側が相補的なサブセットに依存しているため、1 つの要素を変更すると GCD と AND の両方に非局所的な影響が及ぶことです。 素朴なアプローチでは、赤のセットを修正して両方の値を直接計算しようとするかもしれませんが、これは次のような問題につながります。$O(2^n)$可能性、あるいは少なくとも$O(n^2)$サブセットごとにスキャンします。 

よくある失敗例は、ローカルな選択を貪欲に試みた場合に発生します。 たとえば、GCD の動作を最大化するために最小の要素を赤色で選択することは誤解を招きます。 

入力:```
n = 4, x = 0
a = [1, 2, 3, 6]
```などの小さな要素を選択する$[1,2]$は GCD 1 を返しますが、青側の AND は選択に応じて 2 または 0 になる可能性があるため、比較が不安定になります。 重要な問題は、GCD が大きさだけではなく、慎重に調整されたサブセット構造のみに依存することです。 

もう 1 つの微妙な失敗は、最適な赤のセットが非常に小さい (多くの場合サイズ 2) 場合に発生します。一方、単純なアプローチではサブセットが大きくなると GCD が向上すると想定されますが、これは誤りです。 

## アプローチ

 ブルート フォースの解釈は簡単です。2 から 2 までのサイズの有効なサブセットをすべて選択します。$n-2$、その GCD を計算し、相補的な AND プラスを計算します。$x$と比較してみます。 これはゲームのルールを直接シミュレートしているため、これは正しいです。 ただし、サブセットの数は$\sum_{k=2}^{n-2} \binom{n}{k}$、これは指数関数的です。 それぞれの評価があったとしても$O(n)$、解決策は実行不可能です。 

重要な構造上の観察は、セットの GCD が割り算制約によって決定されるのに対し、補数の AND はビットごとの包含によって決定されるということです。 これら 2 つの演算は、除数とビット パターンによるフィルタリングに関して適切に動作します。 

任意のサブセットを選択する代わりに、視点を反転して、候補値を固定します。$g$赤セットのGCD用。 赤のセットの GCD が次の値に等しい場合$g$の場合、すべての赤い要素は次の数で割り切れる必要があります。$g$、セットにはそのような要素が少なくとも 2 つ含まれている必要があります。 問題は、少なくとも 2 つの倍数を選択できるかどうかになります。$g$残りのすべての要素が十分に小さい AND を生成するようにします。 

青のセット内の 1 つの要素でも位置に 0 ビットがある場合、AND はそのビットを失うことに気づくと、AND 側が簡単になります。 これは、AND がビット パターンの交差によって支配されているため、慎重に選択したサブセットを削除すると、AND を大幅に削減できることを意味します。 

重要な単純化は、優れたソリューションを常に赤のセットに正確に 2 つの要素を選択することに帰着できることです。 GCD に有効な大きい赤セットが存在する場合$g$, 次に、それらの要素の中から GCD がまだ変化しない 2 つを選択できます。$g$なぜなら、GCD は結合的であり、それを達成するサブセットには証人ペアが含まれるからです。 

これにより、ペアを試行するという問題が軽減されますが、それでもすべてのペアが実行可能であるわけではありません。$O(n^2)$。 最後の最適化は、値でグループ化し、周波数と除数構造を使用して、配列ドメインからのみ候補をチェックすることです。 

それぞれの値について$v$、潜在的な GCD ターゲットとして扱います。 で割り切れる要素の数を確認します。$v$。 少なくとも 2 つ存在する場合、赤色のペアを形成できます。 次に、これら 2 つを除くすべての要素の AND を計算します。これは、プレフィックス/サフィックス ビット トリックまたはグローバル ビット カウントを使用して効率的に維持できます。 

これにより、値を最大で反復するソリューションが得られます。$4 \cdot 10^5$、除数の列挙を使用して、ほぼ線形の合計時間で除数カウントを累積し、条件を検証します。

 ## アルゴリズムのチュートリアル

 1. 配列内の各値の頻度を事前計算します。 これにより、考えられる各 GCD にいくつの候補が存在するかを迅速に推論できます。 
2. 考えられる各値について$g$1 から最大要素まで、配列要素の数が何で割り切れるかを計算します。$g$。 これにより、GCD が次で割り切れる赤色のグループを形成できる少なくとも 2 つの要素を選択できるかどうかがわかります。$g$。 これが重要な理由は、有効な赤セットはすべてその GCD の倍数内に完全に存在する必要があるためです。 
3. 割り切れる要素が 2 つ未満の場合$g$、有効な赤セットを形成することさえできないため、スキップします。 
4. の倍数である 2 つの要素を使用して赤色のセットを構築してみます。$g$。 GCD 条件を維持する 2 つの要素を選択します。これは、実際の G​​CD が等しいことを確認することで確認できます。$g$。 
5. これら 2 つの要素を一時的に削除し、残りの要素のビット単位の AND を計算します。 これは、事前に計算されたグローバル AND または周波数ベースのビット再構成を使用して行われます。 
6.追加$x$この AND 結果と比較します$g$。 もし$g$厳密には大きいですが、最適な構成が見つかりました。

### なぜ効果があるのか

 有効な赤セットには明確に定義された GCD があります。$g$。 そのセットは、値が次の値で割り切れるインデックス内に含まれている必要があります。$g$。 それらの中で、GCD の最小証人は常に、GCD が既に設定されている要素のペアです。$g$, なぜなら、より大きな集合は次のように縮小されるからです。$g$それを生成するペアが含まれている必要があります。 これにより、有効な解を失うことなく、探索空間がサブセットからペアに縮小されます。 赤のセットが決定されると、青のセットが決定され、比較は決定的になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 400000

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    freq = [0] * (MAXV + 1)
    for v in a:
        freq[v] += 1

    # global bit counts for AND reconstruction
    bit_cnt = [0] * 20
    for v in a:
        for b in range(20):
            if v >> b & 1:
                bit_cnt[b] += 1

    def full_and(excluded):
        cnt = bit_cnt[:]
        for v in excluded:
            for b in range(20):
                if v >> b & 1:
                    cnt[b] -= 1
        res = 0
        m = n - len(excluded)
        for b in range(20):
            if cnt[b] == m:
                res |= (1 << b)
        return res

    for g in range(1, MAXV + 1):
        tot = 0
        for m in range(g, MAXV + 1, g):
            tot += freq[m]
        if tot < 2:
            continue

        found = []
        for v in range(g, MAXV + 1, g):
            if freq[v]:
                found.extend([v] * min(freq[v], 2))
                if len(found) >= 2:
                    break
        if len(found) < 2:
            continue

        a1, a2 = found[0], found[1]

        red_gcd = a1 if a1 == a2 else __import__("math").gcd(a1, a2)
        if red_gcd != g:
            continue

        blue = []
        removed = 0
        for v in a:
            if removed < 2 and v in (a1, a2):
                removed += 1
                continue
            blue.append(v)

        blue_and = full_and([a1, a2])
        if g > blue_and + x:
            print("YES")
            print(2, a1, a2)
            print(len(blue), *blue)
            return

    print("NO")

t = int(input())
for _ in range(t):
    solve()
```この実装では、まず周波数とビットの統計を構築し、配列を繰り返しスキャンすることなく候補 GCD 値をテストできるようにします。 ヘルパー関数は、ビット カウントを使用して赤色のペアを削除した後、青色のセットの AND を再構築します。これにより、AND を最初から再計算する必要がなくなります。 

実装の重要な点は、正確に 2 つの要素を正しく除外することです。 重複が存在するため、削除はインデックスベースの削除ではなく、出現回数をカウントすることによって処理されます。

 ## 特殊なケース

 重要なエッジケースは、すべての要素が同一である場合です。 この場合、有効な赤色のサブセットはその値と等しい GCD を持ちますが、青色の AND は同じ値のままであるため、比較は次のことを確認することになります。$g > g + x$、そうでない限り不可能です$x < 0$したがって、構築によってサブセットのサイズが変更されない限り、答えは常に NO です。 

もう 1 つのエッジ ケースは、候補 GCD で割り切れる要素が 2 つだけである場合に発生します。 赤のセットは正確にこれら 2 つの要素で構成されている必要があり、正確さはその GCD が候補と一致するかどうかを検証することに依存するため、アルゴリズムは引き続き機能します。 

最後の微妙なケースは、ペアを削除した後に青のセットの AND がゼロになる場合です。 これにより、不等式は次のいずれかにのみ依存します。$g > x$、これは多くの場合、支配的な勝利条件となり、実際には多くの YES 出力を説明します。
