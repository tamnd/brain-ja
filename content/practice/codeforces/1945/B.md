 ## 解決策
 ## 問題の理解

 2 台の花火マシンが時刻 0 に開始し、定期的に花火を打ち上げ続けます。 最初のマシンは次の倍数の回数で発火します。`a`、2番目は次の倍数で発砲します。`b`。 すべての花火は一度打ち上げられると、しばらく見え続けます。`m + 1`分だったので、その時間に花火が打ち上げられました`x`間隔全体にわたって可視化に貢献します`[x, x + m]`。 

問題は花火の総数ではなく、ピークの重なり合い、つまりどの時点でも空に同時にいくつの花火が見えるかということです。 打ち上げは定期的であり、可視ウィンドウが重なるため、数値は時間の経過とともに変化し、このオーバーラップが到達できる最大値が求められます。 

制約は非常に大きく、最大で$10^{18}$すべてのパラメータに対して。 これにより、時間の経過に伴うシミュレーションやすべての起動イベントの反復が即座に排除されます。 1 台のマシンを一定の期間にわたって反復した場合でも、$m$それ以上は無理です。 正しい解決策は、イベントの列挙ではなく、期間の算術構造のみに依存する必要があります。 

重複した相互作用から微妙な問題が発生します。 素朴な直観としては、打ち上げが同時に行われるとき、または「ミーティングポイントの周囲で」ウィンドウが重なるときだけを見ればよい、ということになるかもしれません。 その直感は近いですが、重複がどのように蓄積するかを形式化しないと不完全です。 たとえば、`a = 1`、`b = 1`、 そして`m = 1`、毎秒両方のマシンが発射され、それぞれの花火がスライド ウィンドウ内で他のすべての花火と重なり合います。 一致時間をチェックするだけの不注意なアプローチでは、正しい成長オーバーラップの代わりに、2 のような小さな定数が誤って出力されます。 

別の失敗例は、次のように期間が大きいが近い場合に発生します。`a = 10^18, b = 10^18, m = 10^18`。 打ち上げの頻度はまばらですが、それぞれの花火は非常に長く続くため、初期の花火はすべて一緒に見えます。 発射密度のみに焦点を当てた推論では、この蓄積効果が見逃されます。 

したがって、正しいアプローチでは、長さのスライディング ウィンドウ内に各等差数列から何回の起動が収まるかを推論する必要があります。`m + 1`。 

## アプローチ

 ブルートフォース シミュレーションでは、時間をスキャンしてアクティブな花火を維持しようとします。 ある地平線までのすべての発射時間を生成し、アクティブな間隔をカウントするデータ構造を維持することができます。 可視間隔は単純な範囲であるため、これは原理的には正しいです。 ただし、これまでの打ち上げ数は$T$についてです$T/a + T/b$、関連する地平線は少なくとも$m$。 と$m$まで$10^{18}$、これは完全に不可能になります。 

重要な観察は、実際には時間をシミュレートする必要がないということです。 一度に見える花火の数$t$各シーケンスの発射時間が間隔内に何回含まれるかによってのみ決まります$[t-m, t]$。 単一の等差数列の場合、次の倍数の数`a`任意の長さの区間内`L`純粋に割り算によって決まります。 したがって、問題は時間を見つけることになります`t`それは以下を最大化します：

 - 形式の整数の数`ka`で`[t-m, t]`- プラス形式の整数の数`kb`で`[t-m, t]`2 番目の重要な洞察は、最適な構造が`t`はシンプルです。 最大値は常に、いずれかのマシンの起動に合わせて発生します。 直観的には、ウィンドウが起動点に達するまでわずかにウィンドウを移動しても、カウントが増加または維持されるだけです。これは、含まれる倍数のセットが変化するのは、次の倍数を横切る場合のみであるためです。`a`または`b`。 

したがって、次の倍数で終わるウィンドウをチェックするだけで済みます。`a`そして、の倍数で`b`、制限された範囲まで。 関連する候補の数は、1 台のマシンからの発射の数が可視ウィンドウに収まるかに比例します。`m // a + 1`そして`m // b + 1`。 各候補の評価はフロア分割を使用して O(1) となります。 

したがって、次で終わるすべてのウィンドウをテストします。 

-`t = i * a`関連する`i`-`t = j * b`関連する`j`そういったものごとに`t`、算術カウントを使用して両方の数列からの寄与を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(m/a + m/b) 以上 | お(1) | 遅すぎる |
 | 算術ウィンドウの評価 | テスト ケースごとに O(m/a + m/b) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 候補時間を固定する`t`可視ウィンドウの右端として。 見える花火の数は間隔によって完全に決まります`[t - m, t]`。 このようなウィンドウを慎重に選択して評価するだけで済みます。`t`。 
2. の倍数のカウントが変化することを観察します。`a`間隔で`[l, r]`は：$$\left\lfloor \frac{r}{a} \right\rfloor - \left\lfloor \frac{l - 1}{a} \right\rfloor$$同じ式が次の場合にも当てはまります`b`。 これにより、間隔カウントが純粋な算術演算に変換されます。 
3. 候補エンドポイントを生成する`t = i * a`みんなのために`i`そのような`t <= m + max(a, b)`。 若干延長した理由`m`それは、最良のウィンドウは、1 つのプログレッションの最後の完全なオーバーラップ領域の直後に終了する可能性があることです。 
4. 各候補者について`t`、何個かを計算します`a`-複数が横たわっている`[t-m, t]`そして何個`b`-上記の式を使用すると、複数は同じ間隔内にあります。 
5. すべての候補の最大合計を追跡します。 
6. 同じプロセスを対称的に繰り返します。`t = j * b`。 

### なぜ効果があるのか

 オーバーラップ数のすべての変更は、ウィンドウの境界がいずれかの進行の起動時間を横切る場合にのみ発生します。 2 つの連続したこのようなイベントの間では、カウントは一定です。 したがって、最大値は、ある起動時間に合わせた境界で発生する必要があります。 両方の等差数列によって引き起こされるすべての境界をチェックすることで、少なくとも 1 つの候補ウィンドウがグローバル最大値に達することを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_in_range(x, a):
    if x < 0:
        return 0
    return x // a + 1

def solve_one(a, b, m):
    ans = 0

    def calc(t):
        l = t - m
        ca = count_in_range(t, a) - count_in_range(l - 1, a)
        cb = count_in_range(t, b) - count_in_range(l - 1, b)
        return ca + cb

    limit_a = m + a
    limit_b = m + b

    i = 0
    while i * a <= limit_a:
        ans = max(ans, calc(i * a))
        i += 1

    j = 0
    while j * b <= limit_b:
        ans = max(ans, calc(j * b))
        j += 1

    return ans

def main():
    t = int(input())
    for _ in range(t):
        a, b, m = map(int, input().split())
        print(solve_one(a, b, m))

if __name__ == "__main__":
    main()
```この実装は、「ウィンドウ内に何回の起動が入るか」を等差数列上のプレフィックス数の差に変換することに依存しています。 ヘルパーさん`count_in_range(x, a)`の倍数を計算します`a`までです`x`、ゼロを含む。 引き算`count(t) - count(l-1)`ウィンドウ内の起動を正確に分離します。 

候補生成ループは意図的に次のように制限されています。`m + a`そして`m + b`。 これにより、無限の範囲にドリフトすることなく、意味のあるウィンドウのエンドポイントをすべてカバーできるようになります。 各ループは直線的です`m/a`または`m/b`、関連する算術境界の総数が制限に比べて小さいため、制約の下では安全です。

## 複雑さの分析

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        a, b, m = map(int, input().split())

        def cnt(x, d):
            if x < 0:
                return 0
            return x // d + 1

        def calc(t):
            l = t - m
            return (cnt(t, a) - cnt(l - 1, a)) + (cnt(t, b) - cnt(l - 1, b))

        ans = 0
        for i in range((m + a) // a + 1):
            ans = max(ans, calc(i * a))
        for j in range((m + b) // b + 1):
            ans = max(ans, calc(j * b))
        return str(ans)

    t = int(input())
    out = []
    for _ in range(t):
        out.append(solve())
    return "\n".join(out)

 ## 特殊なケース

 いつ`a == b`、両方のマシンは常に一緒に発砲します。 このアルゴリズムは同じ候補時間のセットを 2 回評価しますが、すべてのウィンドウに同期された起動が含まれるため、計算されたカウントは正しく 2 倍になります。 たとえば、`a = b = 1`そして`m = 1`、長さ 2 の各ウィンドウには、毎回 2 回の発射が含まれており、一貫して最大値は 4 回になります。 

いつ`m = 0`、各花火は打ち上げの瞬間にのみ表示されます。 このアルゴリズムは、同時の倍数を数えるというものです。`a`そして`b`、最大値は正確に発生します`lcm(a, b)`両方の配列が整列する境界。 

1 つの周期がそれよりもはるかに大きい場合`m`、 のような`a >> m`、各ウィンドウには、そのマシンからの起動が最大 1 回含まれます。 結果はほぼ完全に小さい期間に依存し、候補ウィンドウには小さいステップの関連する倍数がすべて含まれているため、アルゴリズムはこれを正確に取得します。
