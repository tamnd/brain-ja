 ## 解決策
 ## 問題の理解

 著者には固定の順序が与えられており、各著者には最大 10 個の可能な文字列があり、各文字列はフルネームの一部です。 著者ごとに 1 つの文字列を正確に選択する必要があります。 これらの選択を行った後、元の順序で著者ごとに 1 つずつ文字列のシーケンスを取得します。 

要件は、この結果として得られるシーケンスが辞書編集順に非降順でソートされている必要があることです。 著者の順序を変更することはできません。最終的なリストで各著者を表す名前の部分を決定することのみが許可されています。 

したがって、タスクはシーケンスに対する制約付き選択問題です。位置 i で小さなセット S_i から 1 つの値を選択し、辞書編集的に S_1 ≤ S_2 ≤ … ≤ S_n が必要です。 

制約は、n の点​​では大きく、最大 100,000 人の作成者ですが、各セットは小さく、最大でも 10 個の文字列です。 このサイズの n では、位置ごとに 2 つの選択肢を使用する指数構成でさえもすでに実行不可能であるため、作成者全体のすべての組み合わせを考慮する解決策は即座に除外されます。 実行可能なソリューションは、作成者ごとに最大でも対数または一定のオーバーヘッドで、n においてほぼ線形に動作する必要があります。 

単純な試みでは、左から右に貪欲に選択し、これまでのシーケンスを有効に保つ最小の文字列を常に選択しようとする可能性があります。 ローカルで有効な小さな選択により、将来のすべての作成者がブロックされる可能性があるため、これは失敗します。 たとえば、初期に非常に小さい文字列を選択すると、後の作成者はさらに小さい文字列を選択することを余儀なくされる可能性があります。初期にわずかに大きい文字列を選択しておけば有効な継続が可能だったとしても、その文字列はセットに存在しない可能性があります。 

重要な微妙なエッジケースは、実現可能性は将来に依存するということです。 サフィックスで何が可能なのかを理解しなければ、プレフィックスを決定することはできません。 

## アプローチ

 ブルートフォース戦略では、作成者ごとに 1 つの文字列の可能な選択肢をすべて探索し、結果のシーケンスがソートされているかどうかを確認しようとします。 各作成者には最大 10 個のオプションがあるため、最悪の場合、およそ 10^n 通りの組み合わせになります。 無効なシーケンスを早期に削除しても、分岐の深さは指数関数的なままであるため、保存されません。 これは実行可能な計算をはるかに超えています。 

問題の構造は古典的な順次実行可能性制約です。各位置は候補値の小さなセットに寄与し、最終シーケンスは単調制約を満たさなければなりません。 これは貪欲な構築を示唆していますが、それはローカルな決定がグローバルな実現可能性を破壊しないことを保証できる場合に限ります。 

重要な観察は、右から左へのシーケンスを安全に構築できるということです。 位置 i+1 以降でどの値を選択する必要があるかがすでにわかっている場合、位置 i では、その将来の値を超えない値を選択するだけで済みます。 これにより、問題は、左に行くにつれて徐々に厳しくなる一連のローカル制約に変換されます。 

前方を推測する代わりに、サフィックスによって許可される可能な最小の上限を維持し、常にその範囲内の現在の位置で実行可能な最良の値を選択します。 各セットは小さいため、並べ替えられたオプションに対する単純なスキャンまたは二分探索を使用して、最適な候補を効率的に見つけることができます。

 ## アルゴリズムのチュートリアル

 著者を最後の著者から最初の著者まで処理し、最終シーケンスの次の位置に選択された値を維持します。 

1. 各著者の名前部分のリストを辞書順に並べ替えます。 これにより、各セット内の最小および最大の有効な選択肢を迅速に推論することができます。 
2. 変数を初期化する`next_value`右側の作成者のために選択された文字列を表します。 最後の作成者にとって、これは辞書編集的な意味で実質的に正の無限大であり、あらゆる選択が許可されることを意味します。 
3. 現在の著者 i について、S_i 内のすべての候補文字列をスキャンし、辞書編集上以下の最大の文字列を選択します。`next_value`。 複数の文字列が条件を満たす場合は、最大のものを選択することが重要です。`next_value`以前の作成者の柔軟性を維持しながら、できるだけ大きくします。 
4. S_i 以下の候補がない場合`next_value`の場合、この作成者は接尾辞の有効な継続に適合できないため、有効なシーケンスを構築することは不可能になります。 
5.セット`next_value`選択した文字列に移動し、前の作成者に移動します。 
6. すべての作成者を処理した後、収集した選択肢を逆にして元の順序に戻します。 

### なぜ効果があるのか

 重要な不変条件は、位置 i を処理した後、`next_value`はサフィックス i..n の有効な選択を表し、位置 i に対して行われたすべての選択は、右側に少なくとも 1 つの有効な補完を許可する最大の文字列です。 接尾辞制約に関して常に実現可能性を維持し、利用可能なスペースを必要以上に縮小しないため、位置 i での失敗は以前の決定によるアーチファクトではなく、真の不可能性です。 

実現可能な最大の文字列を取得するという貪欲な選択が重要です。 より小さい文字列を選択すると、以前のすべてのポジションの制約が強化されるだけで、制約が拡張されることはなく、実現可能性が向上することなく成功の可能性が低下するだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    sets = []
    for _ in range(n):
        parts = input().split()
        p = int(parts[0])
        arr = parts[1:]
        arr.sort()
        sets.append(arr)

    next_value = None
    ans = [None] * n

    INF = chr(127) * 20  # lexicographically larger than any valid string

    next_value = INF

    for i in range(n - 1, -1, -1):
        best = None
        for s in sets[i]:
            if s <= next_value:
                best = s
            else:
                break

        if best is None:
            print("impossible")
            return

        ans[i] = best
        next_value = best

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```この実装は、文字列が現在の上限を超えるとすぐにスキャンを停止できるように、各著者の候補リストをソートすることに依存しています。 番兵`INF`は、辞書編集上、有効な名前の部分よりも大きくなるように選択され、最終作成者に制限がないことが保証されます。 

逆方向ループは接尾辞制約を直接強制します。 各反復は以前に選択した値にのみ依存するため、追加の DP テーブルは必要ありません。

 ## 特殊なケース

 微妙なケースの 1 つは、以前の作成者が、後の作成者に不可能な制約を強いる非常に小さな文字列を持っている場合です。 たとえば、初期の作成者が「A」を選択し、後の作成者が「B」しか持っていない場合、貪欲な逆方向プロセスは、後の作成者が最初に「B」にコミットすることを保証することで自然にこれを防ぎ、その後、以前の作成者は何か ≤ 「B」を選択することを強制されます。 

もう 1 つのエッジ ケースは、著者に対して複数の有効な選択肢が存在する場合です。 アルゴリズムは常に実行可能な最大のものを選択し、以前の位置を不必要に制限しないようにします。 これにより、有効なソリューションが存在するにもかかわらず、過度に保守的な選択によって誤って除外されてしまうという状況を回避できます。
