 ## 解決策
 ## 問題の理解

 長さのバイナリ配列が与えられます$n \le 1000$、最初はすべてゼロです。 ビットを直接設定しません。 代わりに、連続したセグメントを繰り返し選択します。$[l, r]$、そしてシステムはそのセグメントをランダム性に「さらし」、その中のすべてのビットを独立した公正なコイン投げに置き換えます。 

各操作の後、配列全体と、現在の割合が表示されます。 配列の少なくとも 70% が 1 になると、プロセスは直ちに停止します。 最大 125 の操作が許可されます。 

したがって、実際に制御できるのはビット値ではなく、配列のどの部分をどのような順序で再ランダム化するかです。 すべての操作により、選択したセグメント内の以前の情報が破壊され、新しい不偏ランダム性に置き換えられます。 

制約$n \le 1000$また、操作が 125 回しかないということは、各位置を決定論的に修正することを複数回試みるような余裕はないことを意味します。 代わりに、ソリューションでは、重複するセグメント上で繰り返されるランダムなリサンプリングがどのように動作するかという構造を利用する必要があります。 

微妙なエッジケースは、ランダム性が累積されないことです。 セグメントを複数回ランダム化する場合、各インデックスに影響を与える最後の操作のみが問題になります。 たとえば、ランダム化すると$[1, n]$2 回実行すると、最初の結果が完全に上書きされます。 したがって、ランダム性の蓄積を前提とした戦略はすべて正しくありません。 

もう 1 つの特殊なケースは、期待に過度に焦点を当てていることです。 リサンプリングされたすべてのビットが 1 になる確率は常に 50% であるため、配列全体を単純に繰り返しサンプリングすると、グローバル分布の中心が 50% に保たれます。 構造がなければ、70% に到達することは天文学的に不可能です。 

## アプローチ

 ブルートフォースメンタルモデルは、配列全体を繰り返しランダム化し、単一のサンプルが 70% のしきい値を超えることを期待することです。 各完全な操作では一様にランダムなバイナリ配列が生成されるため、1 回の試行で成功する確率は、二項式が実行される確率です。$(n, 1/2)$変数が超過$0.7n$。 のために$n = 1000$、これは指数関数的に小さいため、125 回の試行以内では基本的に成功しません。 

重要な観察は、グローバルなリサンプリングに限定されていないということです。 配列の一部のみを選択的にリサンプリングできます。 これにより、すべてを再起動するのではなく、ローカルで構成を「改善」することができます。 このアイデアは、配列を小さなセグメントのコレクションとして扱い、すでに多くのセグメントが含まれている部分を保持しながら、現在パフォーマンスが低下しているセグメントのみを繰り返し再ランダム化することです。 

これにより、プロセスが確率論的な山登りシステムに変わります。 各操作により、セグメントの新しいランダムな候補が得られ、複数のランダムなサンプルの中から、そのセグメントの現在の構成よりも優れた構成が見つかる可能性が高いという事実を利用します。 この原則を多くのセグメントに繰り返し適用すると、セグメントの全体的な密度が上昇します。

 | セグメントごとの確率的改善 |$O(125 \cdot n)$|$O(n)$| 高い確率で採用される |

 ## アルゴリズムのチュートリアル

 配列を、通常は約 8 ～ 15 個の適度なサイズの複数の連続したブロックに分割します。 目標は、リサンプリングを繰り返し、グローバルな 1 の数を改善する効果を維持することで、各ブロックを個別に改善することです。 

1. 配列を次のように分割します。$k$同じサイズのブロック (最後のブロックは小さい場合があります)。 ブロック サイズは、125 回の操作内でブロックを複数回再訪できるように選択されます。 
2. まだ「十分」ではないブロック、つまり安定性のために必要なブロックよりも少ないブロックを繰り返し選択します。 
3. 次のクエリを発行して、そのブロックに 1 つの操作を適用します。$[l, r]$ブロック範囲に対応します。 これにより、ブロック全体が新しいランダム ビットに置き換えられます。 
4. 各操作の後に、更新された配列を検査し、全体的な 1 の割合を計算します。 以前と比較してパーセンテージが増加した場合、その変化を概念的に進歩として保持します。 そうでない場合でも続行しますが、後続のステップで弱いブロックを再検討することを優先します。 
5. このプロセスを継続し、現在 1 の数が遅れているブロックに常にバイアスをかけます。 時間が経つにつれて、繰り返しリサンプリングされたブロックは、不良セグメントに対して「再試行」を続けるため、より良いランダム結果が蓄積される傾向があります。 
6. グローバルパーセンテージが少なくとも 70 に達した場合は早期に停止し、それ以外の場合は 125 の操作をすべて使用します。 

重要なメカニズムは、小さなブロックにランダム性が集中することです。 サイズのブロック$B$は 1 回のリサンプルで高密度のものが生成される可能性が高く、これをブロック全体で繰り返すと、多くのブロックが同時に強力になる可能性が高まります。 

### なぜ効果があるのか

 各ブロックのリサンプリングにより、独立したサンプルが生成されます。$B$-ビットランダムベクトル。 期待が残る中、$B/2$、分散が高く、サンプリングを繰り返すと、異常に良好な実現を得る複数の機会が与えられます。 まだ弱いブロックのみに焦点を当てるため、低品質の領域を新鮮な独立したサンプルに継続的に置き換えます。 これにより、弱い領域が好ましい構成になるまで、より頻繁に「再ロール」されるドリフト効果が生じます。 十分な操作を行うと、十分なブロックがローカルで 70 パーセントを超え、グローバル配列が 70 パーセントのしきい値を超えます。 

不変条件は、特定のビットが単調に改善するということではなく、アルゴリズムが常に計算量を低密度領域に集中させ、すでに成功した領域をさらなる混乱から保護するということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input().strip())
    a = [0] * n

    ops = 0

    def apply(l, r):
        nonlocal ops, a
        print(l + 1, r + 1, flush=True)
        ops += 1

        a = list(map(int, input().split()))
        _ = input().strip()  # percentage line ignored

    B = max(5, min(12, n))
    blocks = []
    for i in range(0, n, B):
        blocks.append((i, min(n, i + B)))

    while ops < 125:
        total_ones = sum(a)
        if total_ones * 10 >= 7 * n:
            return

        # pick a block with fewer ones than half its size if possible
        chosen = None
        best_deficit = 0

        for l, r in blocks:
            ones = sum(a[l:r])
            size = r - l
            deficit = size - ones
            if deficit > best_deficit:
                best_deficit = deficit
                chosen = (l, r)

        if chosen is None:
            chosen = blocks[ops % len(blocks)]

        l, r = chosen
        apply(l, r)

if __name__ == "__main__":
    main()
```実装では、各対話後に現在の配列状態が維持されます。 配列は小さなブロックに分割されているため、各操作には局所的な密度が大幅に変化する可能性があります。 

各ステップでは、現在 1 の点で最も弱いと思われるブロックを選択し、それをリサンプリングします。 これにより、アレイ全体にランダムに労力を分散するのではなく、限られた数の操作が最悪の領域の改善に集中します。 

これは対話型の問題であるため、クエリのたびに出力をフラッシュするように注意する必要があります。 もう 1 つの微妙な点は、各操作の後、配列全体が入力で置き換えられるため、常にローカル コピーを上書きする必要があることです。

 ## 特殊なケース

 非常に小さい場合$n$、 のような$n = 1$の場合、配列は 0 または 1 になり、しきい値は 70 パーセントであるため、最初の操作の後、単一のリサンプリングは確率 1 ですぐに成功します。 

大型用$n$、主なリスクは、ランダムな更新がすでに良好な領域に集中しすぎて、一部のブロックが永久に弱いままになることです。 ブロック選択戦略は、常に最も密度の低いセグメントを優先し、領域が無期限に無視されることを保証することでこれを防ぎます。 

ほとんどのビットがすでに 1 であるほぼ均一な配列の場合、グローバル パーセンテージ チェックは 70 パーセントに達するとすぐにそれ以降の操作を停止するため、アルゴリズムは当然早期に終了します。
