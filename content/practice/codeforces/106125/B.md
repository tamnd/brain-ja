 ## 解決策
 ## 問題の理解

 最初にアルコールとその他すべての 2 種類の液体が入ったボトルが渡されます。 時間の経過とともに、両方の部分が蒸発しますが、その速度は 1 日あたり異なります。 ボトルを開けて一定の日数経過した後、残っている液体のどの部分がアルコールであるかをパーセンテージで計算して求めます。 

具体的には、ボトルの状態は初期アルコール量から始まります。`a`および最初のノンアルコール量`o`。 一日ごとにアルコールが減っていきます`∆a`そしてもう一方の液体は によって減少します`∆o`。 後`d`日の場合、残りの量は時間の一次関数であり、残りのアルコールの比率を計算するように求められます。 

出力は浮動小数点パーセンテージです。$$\text{answer} = \frac{a - d \cdot \Delta a}{(a - d \cdot \Delta a) + (o - d \cdot \Delta o)} \cdot 100$$制約により、次の値まで許容されます。$10^{12}$そして数日まで$10^6$、中間値は約に達する可能性があります$10^{18}$。 これは 64 ビット整数の範囲内に安全に収まりますが、演算の順序に注意しないと浮動小数点整数の精度内に収まりません。 

微妙な点は、この問題により、ボトルが空になっていないことが保証されるということです。`d`日々。 これにより、分母が常に厳密に正になるため、ゼロ除算のケースを処理する必要がなくなります。 

素朴なソリューションを壊す可能性のあるエッジケースは、通常、精度とオーバーフローから生じます。 

1 つの障害モードは、32 ビット整数の中間値を計算することです。 たとえば、次の場合`a = 10^12`、`d = 10^6`、`∆a = 10^6`、 それから`d * ∆a = 10^12`、すでに 32 ビットではオーバーフローしていますが、64 ビットには適合します。 早期に切り捨てる言語やアプローチは、静かに壊れます。 

もう 1 つの失敗モードは、浮動小数点への変換が早すぎることです。 計算してみると`(a - d*∆a)`そして`(o - d*∆o)`減算の前に浮動小数点数が発生するため、整数の精度が失われ、最終的な比率が必要な値を超えてドリフトする可能性があります。$10^{-6}$許容範囲。 

最後の微妙なケースは、1 つの成分が完全に蒸発する場合です。 たとえば、他の液体が残っている間にアルコールがゼロになる可能性があります。 この式は引き続き機能しますが、ステップバイステップで分割したり、早期に正規化したりする単純なコードでは、不正確な中間無限大または NaN が生成される可能性があります。 

## アプローチ

 直接的な解釈は、単純なシミュレーションです。 残りのアルコールと残りの他の液体を計算します。`d`日を計算し、その比率を計算します。 蒸発は直線的であり、両方の成分に対して独立しているため、これは正しいです。 

ブルートフォースアプローチでは、`∆a`そして`∆o`一日ずつ。 それには必要になります`d`繰り返し、そしてそれ以降`d`まで可能です$10^6$、これはすでに境界線にありますが、まだ可能です。 ただし、制約が大きい場合 (同様の問題ではよくあることですが)、これはすぐに失敗します。 どちらのプロセスも等差数列であるため、問題の構造上、いずれにせよそれは不要です。 

重要な観察は、その後です。`d`日の場合、各数量は O(1) で計算できます。$$a' = a - d \cdot \Delta a,\quad o' = o - d \cdot \Delta o$$これらの最終値を直接計算すると、答えは単一の比率の計算だけになります。 アルコールと他の液体の間には相互作用がないため、動的プロセスや各ステップでの丸め処理、シミュレーションの必要はありません。 

唯一必要な実際の注意は数値の安全性です。すべての中間算術演算は 64 ビット整数または Python 整数で実行する必要があり、浮動小数点変換は最後の除算でのみ発生する必要があります。

 ## アルゴリズムのチュートリアル

 1. 日数を読み取る`d`、初期アルコール`a`、その他の液体`o`。 これらは、2 つの独立した線形減衰プロセスの初期状態を定義します。 
2. 蒸発速度を読み取る`∆a`そして`∆o`。 これらは 1 日あたりの一定の減少を表すため、システムはコンポーネント間の相互作用なしに直線的に進化します。 
3. 使用後のアルコール残量を計算します。`d`としての日々`a' = a - d * ∆a`。 毎日正確に削除するため、これは機能します`∆a`、だからその後`d`日ごとに合計損失を 1 ステップで差し引きます。 
4. 残りの他の液体も同様に計算します。`o' = o - d * ∆o`。 
5. 残りの液体の合計を次のように計算します。`t = a' + o'`。 これは、比率の分母として重要な唯一の数量です。 
6. アルコールの割合を次のように計算します。`100 * a' / t`。 これは、構成比率の定義と直接一致します。 
7. 浮動小数点形式を使用して結果を出力し、内でエラーが発生しないことを保証します。$10^{-6}$。 

### なぜ効果があるのか

 このプロセスは、時間の 2 つの独立した線形関数によって支配されます。 すべてのタイム ステップで、システムの状態は以下によって完全に決定されます。`(a - t∆a, o - t∆o)`。 2 つのコンポーネント間には結合がないため、中間のステップをスキップしても情報が失われることはありません。 最終的な比率はエンドポイント値のみに依存するため、直接評価は完全なシミュレーションと同等になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    d = int(input())
    a, o = map(int, input().split())
    da, do = map(int, input().split())

    a_rem = a - d * da
    o_rem = o - d * do

    total = a_rem + o_rem
    ans = 100.0 * a_rem / total

    print(ans)

if __name__ == "__main__":
    main()
```この解決策は、最終的な残りの数量を直接計算することに依存しています。 掛け算`d * da`そして`d * do`減算の前に実行する必要がありますが、Python では整数に制限がないため安全です。 除算は最後に 1 回だけ実行されるため、累積的な浮動小数点エラーが回避されます。 

実装の微妙な詳細は、最終ステップまで分子と分母を整数として維持することです。 これにより、最大の精度が維持されます。 float への変換は、最終的な比率の計算まで遅延されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、蒸発率がゼロの場合です。 のような入力の場合`d = 100`、`da = 0`、`do = 0`、式は元の比率に減少します。 アルゴリズムはこれを自然に処理します。`d * 0 = 0`したがって、減算は行われず、状態は変化しません。 

もう 1 つのケースは、1 つの成分が完全に蒸発する場合です。 仮定する`a = 10`、`da = 2`、`d = 5`。 それから`a' = 0`。 問題保証により分母が正のまま分子がゼロになるため、アルゴリズムは引き続き機能します。 

より微妙なケースは、減算によって 64 ビット整数の制限に近い非常に大きな中間値が生成される場合です。 両方なので`d`料金は最大で$10^{12}$、彼らの製品は到達することができます$10^{18}$。 このアルゴリズムは Python の整数に依存することでオーバーフローを回避しますが、C++ のような言語では、128 ビットの中間ストレージまたは乗算の前に慎重なキャストが必要です。
