 ## 解決策
 ## 問題の理解

 次の文字で構成される 3 つの文字列が与えられます。`1`、`2`、 そして`3`。 

隠されたオブジェクトは、ゲームの勝者の実際のシーケンスです。 プレイヤーの場合`1`ゲームに勝つ、そしてプレイヤー`2`そして`3`書き留める`1`、しかしプレーヤー`1`その試合を録画するのを忘れた。 同じルールが他のプレイヤーにも対称的に適用されます。 

その結果、各入力文字列は、特定の 1 文字が削除された完全な勝者シーケンスになります。 

-`s1`すべての勝者シーケンスです`1`削除されました。 
-`s2`すべての勝者シーケンスです`2`削除されました。 
-`s3`すべての勝者シーケンスです`3`削除されました。 

タスクは、元の勝者シーケンスを再構築することです。 このステートメントは、答えが存在し、一意であることを保証します。 

文字列の長さは次のとおりです。`10^5`, したがって、非表示シーケンス自体もそのスケールの長さを持つことができます。 文字列を繰り返しスキャンしたり、高価な部分文字列操作を実行したり、大量のバックトラックを実行したりするアルゴリズムは、遅すぎます。 線形時間に近いものが必要です。 

微妙な点は、勝者が出現するたびに 3 つの文字列のうち 2 つだけに出現することです。 たとえば、次の勝者が次の場合`2`、それからそれ`2`に登場する`s1`そして`s3`、ではありません`s2`。 シーケンスを回復するとは、3 つの文字列の現在の未読位置に基づいて、次にどの文字が来る必要があるかを特定することを意味します。 

小さな例を考えてみましょう。```
s1 = 2
s2 = 1
s3 = 21
```答えは次のとおりです。```
21
```最初の勝者は、`2`。 それ`2`の前面に表示されます`s1`そして`s3`。 これら 2 つの文字列からそれを消費した後、残りの未読文字は次のようになります。`""`、`"1"`、 そして`"1"`、次の勝者はきっと`1`。 

よくある間違いは、順序を無視して、文字列の任意のペア間で貪欲に文字を一致させようとすることです。 例えば：```
s1 = 23
s2 = 13
s3 = 12
```答えは次のとおりです。```
123
```最初は、3 つの文字列はすべて異なる文字で始まります。 周波数だけを見ても何の手がかりも得られません。 重要な観察は、正確に 2 つの文字列が次の勝者に一致する必要があるということです。 

同じ勝者が何度も連続して発生する場合、別の簡単な罠が現れます。```
s1 = 2222
s2 = ""
s3 = 2222
```これは隠れたシーケンスに対応します`2222`。 どの再構築方法でも、異なる勝者間で交互に実行するのではなく、一致するプレフィックスを連続して複数回正しく消費する必要があります。 

## アプローチ

 ブルートフォース再構築では、あらゆる可能性をテストして次の勝者を決定しようとします。 

3 つの文字列に現在位置があるとします。 追加してみることもできます`1`、`2`、 または`3`答えを選択し、その選択肢が文字列と一致しているかどうかを確認します。 勝者を選択した後、その勝者を含む 2 つの文字列が 1 つずつ進みます。 

隠しシーケンスのすべてのステップが 3 つの勝者候補の 1 つに対応するため、このアプローチは正しいです。 残念ながら、可能性を再帰的に探索すると、指数関数的な検索ツリーが生成されます。 剪定しても、最大の長さの文字列は`10^5`そのような戦略を不可能にする。 

重要な観察は、次の勝者が実際には強制されているということです。 

各文字列の最初の未使用の文字を取得します。 もし次の勝者が`1`、次の未読の文字`s2`そして`s3`両方でなければなりません`1`。 同じく優勝者`2`次に登場するのは`s1`そして`s3`、そして勝者`3`次に登場するのは`s1`そして`s2`。 

答えは一意であることが保証されているため、各ステップで、正確に 1 つの文字が正確に 2 つの文字列の現在の文字として表示されます。 そのキャラクターが次の勝者になるに違いありません。 出力後、これら 2 つの文字列のポインタを進めて繰り返します。 

端から見る別の方法もあります。 最初のゲームの勝者は、正確に 2 つのリストの最初に表示されます。 勝者を特定したら、それら 2 つのリストからその勝者を削除します。 同じ議論が残りのサフィックスにも適用されます。 これにより、単純なポインターベースの線形アルゴリズムが生成されます。 公式のソリューションでは、まさにこの観察結果が使用されています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース検索 | 指数 | 指数 | 遅すぎる |
 | スリーポイント再構成 | O(n) | 出力以外の O(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 3 つの文字列を読み取ります`s1`、`s2`、 そして`s3`。 
2. 3つの指標を維持する`i1`、`i2`、 そして`i3`、最初はゼロです。 各インデックスは、その文字列の最初の未読の文字を指します。 
3. 少なくとも 1 つの文字列に未読の文字が残っている間に、ポインタが末尾に到達していない各文字列の現在の文字を調べます。 
4. 中のどの文字を数えます`1`、`2`、 そして`3`ちょうど 2 つの文字列の先頭に表示されます。 
5. そのキャラクターが、隠されたシーケンスの次の勝者です。 それを答えに追加します。 
6. 現在の文字が選択された勝者と等しい 2 つの文字列のポインタを正確に進めます。 
7. すべての文字列のすべての文字が消費されるまで繰り返します。 

### なぜ効果があるのか

 勝者が出現するたびに 2 つのリストに表示され、勝者自身のリストには含まれません。 

次の隠れた勝者が次であると仮定します。`x`。 次に、他のプレイヤーに属する 2 つのリスト内の次の未読の文字は、両方とも`x`、これらのリストは勝者の元の順序を保持しているためです。 3 番目のリストには、この現象はまったく含まれていません。 

したがって、いつでも、次の勝者は、正確に 2 つの文字列の現在位置に表示される文字です。 これら 2 つの文字列からその文字を消費すると、すべての表現から次のゲームの 1 つの出現が削除されます。 残りのサフィックスは残りのゲームに対応するため、同じ議論が帰納的に適用されます。 アルゴリズムはすべての勝者を正しい順序で再構築するため、間違ったキャラクターを選択することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = [input().strip() for _ in range(3)]

    p = [0, 0, 0]
    ans = []

    while True:
        cur = []

        for k in range(3):
            if p[k] < len(s[k]):
                cur.append((k, s[k][p[k]]))

        if not cur:
            break

        cnt = {'1': 0, '2': 0, '3': 0}

        for _, ch in cur:
            cnt[ch] += 1

        winner = None
        for ch in "123":
            if cnt[ch] == 2:
                winner = ch
                break

        ans.append(winner)

        for k, ch in cur:
            if ch == winner:
                p[k] += 1

    print("".join(ans))

solve()
```実装は証明を直接反映しています。 

配列`p`各文字列内の現在の未読位置を保存します。 繰り返しのたびに、現在指定されている文字のみを検査し、逆方向にスキャンしたり、前方向に検索したりすることはありません。 

辞書`cnt`現在、各勝者候補で始まる文字列の数を記録します。 シンボルは 3 つしか存在しないため、この作業は定数時間です。 

勝者を特定した後、現在の文字がその勝者に等しいポインターを正確に進めます。 これは重要なステップです。 他のポインタを進めると、リストに保存されている順序情報が破壊されます。 

各ポインターは、最大でもその文字列の長さだけ前方に移動します。 ポインタが後方に移動することはないため、総作業量は直線的です。

    return "".join(ans)

 ## 特殊なケース

 次のことを考慮してください。```
2
1
21
```当初フロントは、`(2,1,2)`。 キャラクター`2`が 2 回出現するため、アルゴリズムは次のように出力します。`2`そして 1 番目と 3 番目のポインタを進めます。 残りの前線は、`(end,1,1)`、強制勝者`1`。 出力は`21`、それは正しいです。 

次に、繰り返し勝者を考えてみましょう。```
22
1
221
```フロントは`(2,1,2)`、それで勝者`2`が選ばれます。 ポインタを 2 つ進めた後、フロントは再び`(2,1,2)`。 アルゴリズムは別のものを正しく選択します`2`。 そうして初めてそうなります`1`2回登場するキャラクターになります。 結果は`221`。 

さらに興味深いケースは次のとおりです。```
23
13
12
```3 つの文字列はすべて異なる記号で始まります。 文字列全体の周波数ベースの再構成は失敗します。 現在の未読位置だけを見るとカウントが得られます`{1:2, 2:1, 3:0}`、強制勝者`1`。 同じロジックを繰り返すと再構築される`123`その通り。 

これらの例は、ローカルな「正確に 2 つの現在位置に出現する」不変式がシーケンス全体を一意に復元するのに十分である理由を示しています。
