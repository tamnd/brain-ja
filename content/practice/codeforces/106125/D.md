 ## 解決策
 ## 問題の理解

 単一の小文字文字列が与えられ、その文字を並べ替えて回文を形成できるかどうかを判断するように求められます。 タスクは回文を構築することではなく、そのような再配置が存在するかどうかを判断することだけです。 

回文には、文字がその中心を中心に映るという性質があります。 これにより、各キャラクターが出現できる回数が即座に制限されます。 文字は、長さが奇数の場合に中央の 1 文字を除き、対称的にペアにする必要があります。 

入力の長さは最大 100000 まで可能で、二次関数またはそれより悪いアプローチは除外されます。 順列をシミュレートしたり、候補文字列を構築しようとするものはすべて、組み合わせ的に爆発的に発生します。 ソートベースの構造でも問題ありませんが、すべての順列の並べ替えを伴うものは不可能です。 

文字列自体が回文に置換できるかどうかではなく、回文であるかどうかだけに注目すると、単純な間違いが発生します。 たとえば、次のような文字列`cacao`書かれたとおりの回文ではありませんが、次のように並べ替えることができます。`acoca`、これは有効です。 

もう 1 つの微妙なエッジ ケースは、複数の文字の頻度が奇数である文字列です。 例えば、`aabbcc`複数の文字が中心位置を占める必要があるため、回文を形成することはできません。 全長パリティのみをチェックする不注意な実装では、そのようなケースが誤って受け入れられてしまいます。 

## アプローチ

 ブルートフォース戦略では、文字列のすべての順列を試し、それらのいずれかが回文であるかどうかをテストします。 これは、dralinpome の定義に直接一致するため、概念的には正しいですが、実行不可能です。 順列の数は n 階乗であり、各回文チェックは線形であるため、20 のような中程度の n の場合でも実行時間は天文学的になります。 

重要な観察は、配置は気にせず、頻度数だけを気にするということです。 回文では、文字は中心の周りに鏡像ペアで表示されなければなりません。 これは、文字列の長さが奇数の場合に奇数カウントになる可能性がある 1 文字を除いて、すべての文字カウントが偶数である必要があることを意味します。 

したがって、問題全体は、奇数回出現する文字の数を数えるということになります。 この数が最大 1 の場合、回文の再配置が存在します。 これにより、構造的な構築が回避され、問題が弦上の単一周波数パスに圧縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n) | O(n) | 遅すぎる |
 | 周波数カウント | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各文字の出現をカウントすることで文字列を処理し、それらのカウントのうち奇数がいくつあるかを評価します。 

1. 文字列内のすべての文字の頻度を数えます。 これにより、順序に関係なく、各文字が何回出現するかについての完全な概要が得られます。 
2. 頻度テーブルを調べて、奇数の頻度を持つ文字の数を数えます。 それぞれの奇数の頻度は、回文内の鏡像位置を占める必要があるペアになっていない文字を示します。 
3. 奇数頻度の文字の数が 1 より大きい場合は、回文の再配置は不可能であると直ちに結論付けます。 
4. それ以外の場合は、有効な再配置が存在すると結論付けます。 

### なぜ効果があるのか

 回文は、その中心を中心に対称的に文字を組み合わせます。 左からのすべての位置 i は、右からの対応する位置と一致する必要があります。 これにより、長さが奇数の場合に中央に位置する可能性がある 1 つの残りの文字を除いて、各文字の出現がペアに分割可能でなければならないことが強制されます。 複数の文字が対になっていない場合は、対称性を崩さずにそれらを配置する方法がないため、順列が回文を形成することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    s = input().strip()
    
    freq = [0] * 26
    for ch in s:
        freq[ord(ch) - ord('a')] += 1
    
    odd_count = 0
    for f in freq:
        if f % 2 == 1:
            odd_count += 1
    
    if odd_count <= 1:
        print("yes")
    else:
        print("no")

if __name__ == "__main__":
    main()
```この解決策は、文字列を読み取り、小文字の固定サイズの頻度配列を構築することから始まります。 これにより、辞書のオーバーヘッドが回避され、文字ごとの操作が一定に保たれます。 

次に、26 個のカウントをスキャンし、奇数の個数を累積します。 決定ロジックは、回文の再配置条件を直接変換したものです。 

一般的な実装の落とし穴は、周波数パリティの代わりに文字列長パリティを使用することです。 偶数長の文字列は依然として不可能な可能性があるため、これは不正確です (たとえば、`abcabcx`)、奇数長の文字列も引き続き有効です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各文字は 1 回処理され、固定サイズの 26 配列をスキャンします。 
| スペース | お(1) | 周波数配列のサイズは一定です |

 すべての文字を少なくとも 1 回読み取る必要があることを考慮すると、リニア スキャンが最適です。 この制約により最大 100,000 文字が許可され、単一パスで快適に処理されます。 

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    
    s = input().strip()
    freq = [0]*26
    for c in s:
        freq[ord(c)-97] += 1
    
    odd = 0
    for f in freq:
        if f % 2:
            odd += 1
    
    print("yes" if odd <= 1 else "no")

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

# provided samples (conceptual, since formatting may vary)
assert run("zoo\n") == "yes"
assert run("racecars\n") == "no"

# custom cases
assert run("a\n") == "yes"
assert run("ab\n") == "no"
assert run("aabbcc\n") == "yes"
assert run("abcabcx\n") == "yes"

 ## 特殊なケース

 次のような最小限の文字列`a`奇数の頻度で 1 つの文字が含まれており、アルゴリズムは奇数のエントリを 1 つ正確にカウントして受け入れます。 これは自明な回文に相当します。 

のような文字列`ab`各文字に 1 つずつ、合計 2 つの奇数周波数が生成されます。 周波数配列のスキャンにより奇数カウンタが 2 回インクリメントされ、最終条件ではそれが拒否され、対称構造で両方の文字をペアにすることは不可能と一致します。 

次のようなより大きな構造化されたケース`abcabcx`順序が無関係であることを示しています。 周波数は`{a:2, b:2, c:2, x:1}`, したがって、奇数のカウントは 1 つだけ存在します。 アルゴリズムはそれを受け入れ、それを正しく反映します`abcxcba`は有効な再配置です。
