 ## 解決策
 ## 問題の理解

 「A、B の息子」という形式で書かれた親子関係のコレクションが与えられます。 各ステートメントは、人 A には既知の父親 B が 1 人いると述べています。同じ名前が子供または親として複数回出現する可能性があり、別のステートメントがたまたま同じ名前の別の人物を指す場合もあります。 

これらの関係から、最終的にルート祖先が 1 つだけ存在する有効な祖先構造、つまり記録された父親が存在せず、他のすべての人物は父親リンクを通じて上位に追跡できる単一の人物を意味する、有効な祖先構造に由来すると解釈できるかどうかを判断したいと考えています。 

有効な解釈は 2 つの制約を尊重する必要があります。 まず、どの人も父親を持つことができるのは最大でも 1 人です。 第二に、あらゆる人から父親のつながりを上にたどる場合、人には 2 人の異なる父親が必要になる、または祖先が一貫して単一の最終祖先に根ざしていることができないという矛盾には決して陥ってはなりません。 

入力サイズは最大 100,000 リレーションに達するため、クエリごとに大規模なチェーンを明示的に構築または繰り返し実行しようとするソリューションは遅すぎます。 グラフ構築と単一の走査または共用体検索構造など、関係の数に関して線形または線形に近い動作を期待する必要があります。 

微妙さは、名前とサイクルの繰り返しから生まれます。 入力は、名前がループを形成する状況、または個人が直接的または間接的に自分自身の祖先として宣言される状況を記述する場合があります。 もう 1 つの問題は、名前を不用意にノードとして扱うと、ID のマージに一貫性がなくなることです。 

素朴な間違いは、各子供に父親が 1 人だけいる限り、その構造は常に有効であると想定することです。 たとえば、次のような場合です。 

「バジル、アレクシオスの息子」

 「プロコピウス、アレクシオスの息子」

 これは大丈夫です。 しかし、次のようなことがあったとしたら:

 「バジル、アレクシオスの息子」

 「バジル、コンスタンティヌスの息子」

 その場合、バジルには二人の父親がいることになりますが、それは直ちに不可能です。 ただし、サイクルが存在する場合には、次のようなより複雑な矛盾が発生します。 

「アルビン、バートの息子」

 「バート、チャールズの息子」

 「チャールズ、アルビンの息子」

 ここでは、各ノードには父親が 1 つだけありますが、ルート祖先は 1 つもありません。 その代わりに、すべては周期的です。 

もう 1 つのエッジケースは、セルフペアレンティングです。 

「アロン、アロンの子」

 これは、縮退ループとして解釈される可能性があるため、ルートの一意性をすぐに壊すわけではありませんが、それでも循環を形成するため、一貫して処理する必要があります。 

主な困難は、最終的に単一のルートのような構造に還元される有効な関数グラフと、単一の祖先ルートに解決できない複数の切断されたコンポーネントまたはサイクルを含む関数グラフを区別することです。 

## アプローチ

 この関係は、各人が自分の父親を指す有向グラフを自然に定義します。 各ノードには (その父親への) 発信エッジが 1 つしかないため、構造は関数グラフになります。 

ブルートフォースアプローチでは、すべてのノードの父親ポインタを繰り返したどり、すべてのノードが最終的に単一のルートに収束するかどうかをチェックすることによって、祖先の一貫性をシミュレートしようとします。 最悪の場合、n 個のノードのそれぞれについて、長さ n のチェーンを走査し、O(n²) の動作が発生する可能性があります。 これは、n が 100000 までの場合には遅すぎます。 

重要な観察は、有効な構成では、繰り返される名前を無視すると、グラフ構造は、反転すると単一のルートに折りたたまれる森のように動作する必要があるということです。 同様に、すべての接続されたコンポーネントは、最終的には正確に 1 つの末端祖先候補につながる必要があり、単一のグローバル祖先に解決されない複数の切断されたルートまたはサイクルによって生じる曖昧さがあってはなりません。

これは、エッジを無向として扱うときに、有向グラフに弱接続成分が 1 つだけあるかどうか、およびすべてのノードが最大 1 つの親を持つかどうかが、入力の構築によってすでに保証されているかどうかをチェックすることに帰着します。 ただし、サイクルは単一の祖先の解釈と互換性がなければならないため、接続性だけでは十分ではありません。 重要な改良点は、サイクルが新しいルートを作成せず、最上位祖先のない自己完結型ループのように動作することです。そのため、単一の一貫したルートを介して構造の残りの部分に接続されていないサイクルは、一意のグローバル祖先を持つという要件を破っています。 

これを形式化するきれいな方法は、各人をノードとして扱い、マッピングを構築し、次に入次数を計算して接続を追跡することです。 有効な構造には、決して子ではないノード (逆の意味で次数 0) が 1 つだけ存在する必要があり、すべてのノードは最終的に、祖先が競合することなく一貫した上向き構造で到達可能でなければなりません。 

最も堅牢な方法は、グラフを構築してから Union-find または BFS/DFS を使用して、方向を無視するときにすべてのノードが単一の接続コンポーネント内にあることを確認すると同時に、機能上の制約 (入力形式によってすでに保証されている) に違反しないことを確認することです。 各ノードには最大でも 1 つの父親があるため、サイクルは許可されますが、複数の独立した祖先盆地を作成してはなりません。 

より単純な同等の条件が現れます。各人をノードとして扱い、子を父親に接続する場合、有効な祖先モデルでは、すべての名前を考慮した後、弱く接続されたコンポーネントが 1 つだけ存在する必要があり、どのノードも矛盾する親の割り当てを持つことはできません (すでに強制されています)。 この条件が当てはまる場合、コンポーネントを単一の祖先ルートを持つものとして方向付けることができます。 

したがって、問題は、すべての一意の名前に対するグラフを構築し、接続をチェックすることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (ノードごとの反復トラバーサル) | O(n²) | O(n) | 遅すぎる |
 | 最適 (グラフ構築 + 接続チェック) | O(n α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 それぞれの一意の名前をグラフ内のノードとしてモデル化します。 

1. 入力内で見つかったすべての個別の名前に整数 ID を割り当てます。 これにより、グラフの走査中の文字列比較が回避され、効率的な処理が保証されます。 
2. 「A は B の息子」という関係ごとに、A と B の間に無向の接続を追加します。すべての人々が 1 つの接続された構造内に存在することを確認するだけでよいため、接続の方向は重要ではありません。 
3. 訪問した構造を横断のために維持します。 
4. 任意のノードを選択し、BFS または DFS を実行して、そこから到達可能なすべてのノードをマークします。 
5. トラバース後、すべてのノードが訪問されたかどうかを確認します。 ある場合は「可能」を出力し、そうでない場合は「不可能」を出力します。 

これが機能する理由は、すべてのノードが親子リンクの下の単一の接続コンポーネントに属している場合、構造全体に対して単一のルート祖先を選択する一貫した方法が存在するためです。 切り離されたコンポーネントはいずれも独立した祖先系統に相当し、単一の共通祖先という要件に矛盾します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict, deque

n = int(input())

id_map = {}
adj = defaultdict(list)
idx = 0

def get_id(name):
    global idx
    if name not in id_map:
        id_map[name] = idx
        idx += 1
    return id_map[name]

for _ in range(n):
    line = input().strip()
    # format: "A, son of B"
    left, right = line.split(", son of ")
    a = get_id(left)
    b = get_id(right)
    adj[a].append(b)
    adj[b].append(a)

if idx == 0:
    print("possible")
    sys.exit()

visited = [False] * idx
q = deque([0])
visited[0] = True

while q:
    u = q.popleft()
    for v in adj[u]:
        if not visited[v]:
            visited[v] = True
            q.append(v)

if all(visited):
    print("possible")
else:
    print("impossible")
```このコードは、隣接リストを効率的に保存できるように、最初にすべての名前を整数の識別子に変換します。 接続性が確認する必要がある唯一のプロパティであるため、各関係には双方向エッジが追加されます。 

BFS は、任意のノード (ここではノード 0) から開始し、接続されているコンポーネント全体を探索します。 BFS 後に一部のノードが訪問されないままになっている場合、グラフは切断され、すべての人々をカバーする単一のグローバル祖先構造は存在できません。 

まれなケースとしては、関係がまったく存在しない場合があり、その場合、答えは自明に「可能」になります。 

## 実用的な例

 ### 例 1

 入力:

 「イサクの子ヤコブ」

 「アブラハムの子イサク」

 「アブラハムの子イシュマエル」

 名前を ID にマッピングし、隣接関係を構築します。 

| ステップ | ノード | キュー | 訪問 |
 | --- | --- | --- | --- |
 | 開始 | 0 (ジェイコブ) | [0] | {ジェイコブ} |
 | ジェイコブを訪問 | アイザック | [アイザック] | {ジェイコブ、アイザック} |
 | アイザックを訪問 | アブラハム | [エイブラハム] | {ヤコブ、イサク、アブラハム} |
 | アブラハムを訪問 | イシュマエル | [イシュマエル] | {すべて} |

 すべてのノードに到達しているので出力可能です。 

これにより、親を共有する複数の子は、すべてが接続されている限り有効性が損なわれないことが確認されます。 

### 例 2

 入力:

 「バジル、アレクシオスの息子」

 「プロコピウス、コンスタンティヌスの息子」

 切断されたペアが 2 つ存在します。 

| ステップ | ノード | キュー | 訪問 |
 | --- | --- | --- | --- |
 | 開始 | バジル | [バジル] | {バジル、アレクシオス} |
 | BFS の終了 | - | [] | 最初のコンポーネントのみ |

 プロコピウスとコンスタンティヌスが関係するノードは未訪問のままです。 

これは、関係を発明しない限り、切り離された祖先クラスターを単一のルートに統合することはできないため、答えは不可能であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各関係は隣接関係を構築するために 1 回処理され、BFS は各ノードとエッジを 1 回訪問します。 
| スペース | O(n) | ネーム マッピング、隣接関係リスト、訪問先配列のストレージ |

 線形動作は 100,000 リレーションの制約内に快適に適合し、メモリ使用量は一意の名前の数に比例します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict, deque

    n = int(input())
    id_map = {}
    adj = defaultdict(list)
    idx = 0

    def get_id(name):
        nonlocal idx
        if name not in id_map:
            id_map[name] = idx
            idx += 1
        return id_map[name]

    for _ in range(n):
        line = input().strip()
        a, b = line.split(", son of ")
        a = get_id(a)
        b = get_id(b)
        adj[a].append(b)
        adj[b].append(a)

    if idx == 0:
        return "possible"

    visited = [False] * idx
    q = deque([0])
    visited[0] = True

    while q:
        u = q.popleft()
        for v in adj[u]:
            if not visited[v]:
                visited[v] = True
                q.append(v)

    return "possible" if all(visited) else "impossible"

# provided samples
assert run("3\nJacob, son of Isaac\nIsaac, son of Abraham\nIshmael, son of Abraham\n") == "possible"
assert run("2\nBasil, son of Alexios\nProcopius, son of Constantine\n") == "impossible"

# custom cases
assert run("1\nA, son of A\n") == "possible"
assert run("3\nA, son of B\nB, son of C\nC, son of A\n") == "possible"
assert run("4\nA, son of B\nC, son of D\nD, son of E\n") == "impossible"
assert run("0\n") == "possible"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | セルフループ | 可能 | 自己子育てサイクルは構造的に許可されています |
 | 3サイクル | 可能 | 純粋なサイクルは依然として 1 つのコンポーネントを形成します。 
| スプリットチェーン | 不可能 | 切断されたコンポーネント |
 | 空の入力 | 可能 | 自明な基本ケース |

 ## 特殊なケース

 「アーロンの息子アーロン」のような自己子育て関係は自己ループを形成します。 このアルゴリズムは、アーロンをエッジを持つ単一のノードにアーロンをマッピングします。 BFS 中に、アーロンから開始して、トラバーサルはすぐに同じノードを再訪問しますが、それ以上は拡張されません。 訪問セットには Aaron のみが含まれており、他のノードが存在しない場合、出力は「可能」になります。 

A→B→C→Aといった複数人が関わるサイクルも同様に扱われます。 任意のノードから開始する BFS はサイクル全体を横断し、すべてのノードを訪問済みとしてマークします。 すべてのノードが単一の接続コンポーネント内にあるため、アルゴリズムは「可能」を出力し、循環祖先が依然として 1 つの統一された構造を形成していることを正しく反映しています。 

A → B や C → D などの切断されたフォレストでは、BFS で到達可能な 2 つの別々のコンポーネントが作成されます。 A から開始しても B にのみ到達し、C と D は未訪問のままになります。 単一の祖先が欠落した歴史的関係を追加せずに両方のコンポーネントを接続できないため、アルゴリズムは「不可能」を正しく出力します。
