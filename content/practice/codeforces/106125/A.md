 ## 解決策
 ## 問題の理解

 それぞれが整数のピッチとして表される音符のシーケンスが与えられます。 また、ℓ から h までの包括的な間隔で定義される固定の音声範囲も与えられます。 重要な点は、12 の倍数を加算または減算することで、連続する音符のブロックを「移調」できることです。効果的にそれらをオクターブ単位でシフトすることで、そのブロック内のすべての音が声域内に収まるようになります。 

曲は連続したセグメントに分割する必要があり、各セグメント内で、すべての音符 a[i] + 12k が [ℓ, h] に収まるように単一の整数シフト k を選択します。 セグメント間で k を変更できます。 パーティションのコストは、最小セグメントのサイズとして定義されます。 この最小セグメント長ができるだけ大きくなるように、セグメントの境界とシフトを選択したいと考えています。 

したがって、タスクは有効な移調を見つけることではなく、短いセグメントを避けるためにオクターブ シフトを「再調整」する場所を選択することです。 適切なパーティションではすべてのセグメントが長く保たれ、最悪の場合のセグメント長が最適化されます。 

n ≤ 1000 という制約は、O(n^2) 解が快適に高速であることを意味します。 原則的には立方体も通過しますが、不要です。 これは、各位置について、二次構造内のすべての可能なセグメントの終点またはシフトをチェックする余裕があることを強く示唆しています。 

同じ音に対して複数のオクターブ シフトが有効な場合、微妙なエッジ ケースが発生します。 たとえば、ノートはシフト k と k + 1 の両方に適合する可能性があります。ノートごとに最初の有効なシフトを固定する単純な貪欲な選択は失敗する可能性があります。これは、ローカルで有効なシフトが後でセグメントを拡張するために実行不可能になる可能性があるためです。 

もう 1 つの特殊なケースは、移調なしですべてのノートがすでに範囲内に収まっている場合です。 この場合、k = 0 はどこでも機能し、セグメントの区切りが必要ないため、答えは単純に n になります。 

最後に、ノートが境界近くにあるケースが重要です。ノートは 1 つのシフトにかろうじて収まるかもしれませんが、次のノートには別のシフトが強制されるため、連続する実現可能性を慎重に最大化しない限り、頻繁な切り替えが発生します。 

## アプローチ

 強引なアイデアは、配列をセグメントに分割し、シフトされたすべての値が [ℓ, h] に収まるように各セグメントに整数 k を割り当てるあらゆる可能な方法を検討することです。 固定セグメント [i, j] の場合、各 a[i] から導出されたすべての有効な k 範囲を交差することによって、そのセグメント内のすべての値に機能する k が存在するかどうかをテストできます。 これは正しいですが、分割方法は 2^(n-1) 通りあるため、すべてのパーティションを列挙すると n で指数関数的になります。 

視点を緩めることができます。 最初にセグメントを選択する代わりに、セグメント内のすべての a[t] が ℓ ≤ a[t] + 12k ≤ h を満たす場合に限り、セグメント [i, j] が固定 k に対して有効であることが観察されます。 並べ替えると、各要素は k に制約を課します。 

(ℓ - a[t]) / 12 ≤ k ≤ (h - a[t]) / 12、整数の範囲を使用します。 

したがって、各位置は実行可能な k 値の間隔に寄与し、これらの間隔の交点が空でない場合、セグメントは有効です。 これにより、問題は、間隔の交差部分が空でない、長く連続したセグメントを見つけることに変わります。 

配列上でスライディング ウィンドウを維持し、ウィンドウ内のすべての k 間隔の交差を追跡できます。 交差点が空でない限り、セグメントを拡張できます。 空になったら、新しいセグメントを開始する必要があります。 最小セグメント長を最大化するために、2 ポインター手法を使用して暗黙的に可能なすべての開始を試み、セグメント長を記録します。 

重要な観察は、実現可能性は間隔の縮小に関して単調であるということです。要素を削除すると交差が大きくなるだけです。 これにより、2 つのポインタが適用可能になります。

 ## アルゴリズムのチュートリアル

各音符 a[i] を k の間隔制約として書き換えます。 固定 i の場合、k は両方の限界を満たさなければなりません。 

k ≥ ceil((ℓ - a[i]) / 12) および k ≤ Floor((h - a[i]) / 12)。 

これにより、整数の間隔 [L[i], R[i]] が得られます。 

次に、これらの間隔の交差点が空でない最長のセグメントを探します。 

1. すべての位置 i について L[i] と R[i] を事前計算します。 これらは、その音符に対して許容されるすべてのオクターブ シフトを表します。 これにより、音楽的制約が純粋な音程交差の問題に変換されます。 
2. スライディング ウィンドウ [l, r] を維持し、その中のすべての間隔の交差を追跡します。 ウィンドウ全体の currentMaxL = 最大 L[i] とウィンドウ全体の currentMinR = 最小 R[i] の 2 つの値を保持します。 currentMaxL ≤ currentMinR の場合、ウィンドウは有効です。 
3. r を左から右に展開し、交点を新しい間隔で更新します。 これは、新しいノートを追加し、現在のセグメント内のすべてのノートに対して機能する 1 オクターブ シフトが存在するかどうかを確認することに相当します。 
4. ウィンドウが無効になった場合、つまり currentMaxL > currentMinR は、再び有効になるまで左から縮小します。 最後に追加されたノートにより互換性のないオクターブ制約が強制されるため、この手順が必要です。 
5. 各 r について、ウィンドウが有効になると、ウィンドウの長さ r - l + 1 で最良の答えを更新します。これにより、r で終わる実現可能な最長のセグメントが追跡されます。 
6. 最終的な答えは、記録されたウィンドウの最大長です。 

なぜ効果があるのか

 各音符は、k を閉じた整数間隔に制限します。 セグメントは、これらすべての制約が重なったときに正確に実行可能になります。これは、交差が空ではないことと同じです。 スライディング ウィンドウは、この交差を段階的に維持します。 制約を削除すると実行可能なセットが拡張されるだけであるため、可能な場合はウィンドウを縮小すると常に実行可能性が復元され、有効なセグメントがスキップされなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, l, h = map(int, input().split())
    a = list(map(int, input().split()))

    L = []
    R = []

    for x in a:
        # compute k range
        # smallest k such that x + 12k >= l  -> k >= ceil((l-x)/12)
        # largest  k such that x + 12k <= h  -> k <= floor((h-x)/12)

        low = (l - x + 11) // 12
        high = (h - x) // 12

        L.append(low)
        R.append(high)

    ans = 0
    cur_maxL = float("-inf")
    cur_minR = float("inf")

    left = 0

    for right in range(n):
        cur_maxL = max(cur_maxL, L[right])
        cur_minR = min(cur_minR, R[right])

        while cur_maxL > cur_minR:
            # remove left element
            left += 1
            # recompute intersection naively for correctness (n is small)
            cur_maxL = max(L[left:right+1])
            cur_minR = min(R[left:right+1])

        ans = max(ans, right - left + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```核となる変換は、各音符を k の実行可能な音程に変換することです。 下限の上限除算には (l - x + 11) // 12 が使用されます。これは、正の除数の上限除算を計算するための標準的な整数安全な方法です。 上限はフロア分割を直接使用します。 

スライディング ウィンドウは、セグメント全体にわたる単一の k の実現可能性を維持します。 この実装では、縮小後にウィンドウ境界を再計算します。これは、漸近的に最適ではありませんが、n ≤ 1000 の場合でも十分高速です。 完全に最適化されたバージョンでは、両端キューを使用して最大値と最小値が維持されます。 

正確さは、ウィンドウが各正しいエンドポイントで終わる最大の有効なセグメントを常に正確に表すかどうかにかかっています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての音がすでに声域内にある場合です。 その場合、すべての L[i] は 0、すべての R[i] は 0 であるため、交差は常に有効であり、ウィンドウは配列全体に拡張されます。 アルゴリズムは最大 L と最小 R をゼロに保つため、縮小は起こらず、出力は n になります。 

もう 1 つのケースは、ノートで交互のオクターブ シフトが必要な場合です。 たとえば、一部の要素に対して L[i] = 0、R[i] = 0 を強制し、他の要素に対して L[i] = 1、R[i] = 1 を強制するシーケンスでは、すべての混合セグメントが無効になります。 スライディング ウィンドウは、ミキシング直後に最大 L > 最小 R を検出し、一貫したブロックのみが残るまで縮小し、1 を出力します。これは、2 つの隣接するノートが実行可能な k を共有しないという事実と一致します。 

境界が重いケースとは、音が声域の端に正確に位置する場合です。 このメモは単一の有効な k 値を生成するため、厳格な制約として機能します。 より柔軟なメモと組み合わせると、k 範囲が重複するかどうかに応じて、交差は有効なままになるか、すぐに折りたたまれます。 このアルゴリズムは、特別なケースを使用せずに、区間交差を通じてこれを自然に処理します。
