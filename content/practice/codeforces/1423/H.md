 ## 解決策
 ## 問題の理解

 私たちは、日々エッジが生み出される成長を続けるソーシャル コンタクト ネットワークを維持しています。 各エッジは 2 人の人々の間の会議を表し、これらの会議は長さの固定された時間枠にのみ関連します。$k$日々。 その期間より古い会議は「感染との関連性」に寄与しなくなります。 

いかなる瞬間においても、ある人の「不審者集団」は、過去の一連の会議を通じてその人物に関係したすべての個人として定義されます。$k$日々。 これは直接的な接触だけではなく、アクティブな時間枠によって引き起こされるグラフ内の接続性です。 人について尋ねられるたびに$z$、最後のエッジからすべてのエッジによって形成されるグラフ内の、それらの接続コンポーネント (それ自身を含む) のサイズを報告する必要があります。$k$日々。 

このシステムは 3 つの方法で進化します。2 人が出会ったときに無向エッジを追加し、日数カウンターを進め、ノードの接続サイズをクエリします。 

この制約により、私たちは非常に厳しい体制に追い込まれます。 まで$5 \times 10^5$操作を行う場合、クエリごとに接続を最初から再計算するソリューションは直ちに実行不可能になります。 隣接関係リストを維持し、クエリごとに BFS または DFS を実行しても、次のような問題が発生します。$O(n + q)$これは制限をはるかに超えています。 また、構造はエッジの挿入と削除の両方で動的であるため (古いエッジは期限切れになるため)、静的な DSU が直接除外されます。 

最も危険な落とし穴は、エッジがカウントではなく経過時間によって期限切れになることを忘れていることです。 エッジを結合するだけの単純な DSU は、古い接続を決して削除しないため、オーバーカウントされます。 もう 1 つの微妙な問題は、接続が「日ごとのスナップショット」ではなく、スライディング ウィンドウを介して行われるため、時間を意識した構造が必要であることです。 

## アプローチ

 ブルート フォース戦略では、各クエリ時間でアクティブなエッジの完全なリストが維持されます。 タイプ 2 クエリごとに、最後のクエリからすべてのエッジのグラフを構築します。$k$日を経過し、クエリされたノードから BFS/DFS を実行して、そのコンポーネントのサイズをカウントします。 各 BFS のコスト$O(n + m)$、最悪の場合、ノードとエッジの両方が$10^5$以上、最大で繰り返す$5 \times 10^5$回、つまりおおよそ次のようになります$10^{10}$操作。 

重要な構造的観察は、接続性が 2 種類のイベントでのみ変化することです。つまり、新しいエッジが追加されたときと、古いエッジが追加されたときに古いエッジが期限切れになったときです。$k$日々。 挿入と削除の両方で接続を維持できれば、作業は完了です。 標準の DSU は効率的な挿入のみをサポートし、削除はサポートしません。 

古典的な回避策は、ロールバックをサポートする DSU と組み合わせた、時間の経過に伴う分割統治を使用して時間をオフラインで処理することです。 すべてのエッジは連続した時間間隔内に存在します$[t, t+k)$、したがって、各エッジは既知の時間に挿入および削除できます。 セグメント ツリーを時間の経過とともに処理すると、各ノードはその間隔中にアクティブなエッジを保存します。 セグメントに入るときに再帰的にユニオンを適用し、セグメントから出るときにユニオンをロールバックして、そのセグメント内のすべてのクエリの正確性を保証します。 

これにより、動的接続の問題が、可逆結合操作を伴う静的な間隔割り当ての問題に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース BFS |$O(q(n+m))$|$O(n+m)$| 遅すぎる |
 | セグメント ツリー + DSU ロールバック |$O((n+q)\alpha(n)\log q)$|$O(n+q)$| 承認済み |

 ## アルゴリズムのチュートリアル

 時間を線形の一連のイベントに変換します。 毎回の会議の時間$t$から常にアクティブなエッジを作成します。$t$に$t+k-1$。 私たちは毎日を一連の業務として扱います。 

1. すべての操作にタイムスタンプを割り当て、「前日」操作が表示された場合にのみ時間を増分します。 各エッジは開始時刻と有効期限を正確に取得します。$k$数日後。 エッジは永続的なものではなく、間隔にマッピングする必要があるため、この手順が必要です。 
2. 各ミーティングエッジについて$(x, y)$時間に発生する$t$、間隔でアクティブとして保存します$[t, t+k)$。 後で期限切れになるため、すぐに DSU に永続的に挿入することはしません。 
3. すべてのクエリの時間軸に沿ってセグメント ツリーを構築します。 各エッジ間隔は、そのアクティブ範囲を完全にカバーするすべてのセグメント ツリー ノードに挿入されます。 これにより、各エッジが関連する場所で正確に処理されるようになります。 
4. ロールバックをサポートする DSU 構造を準備します。 親配列とサイズ配列とともに、ユニオン操作中に行われたすべての変更を記録するスタックを維持します。 これにより、セグメントを離れた後にマージを元に戻すことができます。 
5. セグメント ツリーを再帰的に走査します。 ノードに入るとき、そのノードに格納されているエッジのすべての結合を適用します。 これにより、その時間セグメントの正しい接続状態が構築されます。 
6. ノードが単一の時点に対応する場合、クエリされたノードの DSU コンポーネント サイズを使用して、すべてのタイプ 2 クエリに応答します。 
7. ノードの終了後、親に戻る前に、そのノードで行われたすべての DSU 変更をロールバックします。 これにより、兄弟セグメントが干渉しないことが保証されます。 

### なぜ効果があるのか

 どのセグメント ツリー ノードでも、アクティブな存続期間全体がそのセグメントをカバーするエッジを一時的に正確に適用します。 したがって、その再帰中の DSU 状態は、その間隔内のすべての時間に有効なエッジによって引き起こされるグラフを正確に表します。 すべてのエッジはアクティブな間隔に完全に含まれるセグメント内にのみ挿入されるため、エッジがその有効期間の外に適用されることはありません。 ロールバックはセグメント間の独立性を保証するため、すべてのクエリでアクティブ エッジの正しいセットが正確に認識されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class DSURollback:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)
        self.history = []

    def find(self, x):
        while self.parent[x] != x:
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            self.history.append((-1, -1, -1))
            return
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.history.append((b, self.parent[b], a))
        self.parent[b] = a
        self.size[a] += self.size[b]

    def snapshot(self):
        return len(self.history)

    def rollback(self, snap):
        while len(self.history) > snap:
            b, old_parent, a = self.history.pop()
            if b == -1:
                continue
            self.parent[b] = old_parent
            self.size[a] -= self.size[b]

def solve():
    n, q, k = map(int, input().split())

    events = []
    queries_at = {}
    edges = []

    time = 0

    for _ in range(q):
        tmp = input().split()
        t = int(tmp[0])
        if t == 1:
            x, y = map(int, tmp[1:])
            edges.append((time, x, y))
        elif t == 2:
            z = int(tmp[1])
            queries_at.setdefault(time, []).append((len(events), z))
            events.append((0, 0, 0))
        else:
            time += 1

    max_time = time + k + 2

    seg = [[] for _ in range(4 * max_time)]

    def add(l, r, edge, idx=1, nl=0, nr=max_time):
        if r <= nl or nr <= l:
            return
        if l <= nl and nr <= r:
            seg[idx].append(edge)
            return
        mid = (nl + nr) // 2
        add(l, r, edge, idx * 2, nl, mid)
        add(l, r, edge, idx * 2 + 1, mid, nr)

    for t, x, y in edges:
        add(t, t + k, (x, y))

    dsu = DSURollback(n)
    ans = [0] * len(events)

    def dfs(idx, l, r):
        snap = dsu.snapshot()
        for x, y in seg[idx]:
            dsu.union(x, y)

        if r - l == 1:
            if l in queries_at:
                for qi, z in queries_at[l]:
                    ans[qi] = dsu.size[dsu.find(z)]
        else:
            mid = (l + r) // 2
            dfs(idx * 2, l, mid)
            dfs(idx * 2 + 1, mid, r)

        dsu.rollback(snap)

    dfs(1, 0, max_time)

    return "\n".join(map(str, ans))

if __name__ == "__main__":
    print(solve())
```実装の核心は、各会議を時間間隔にマッピングし、その間隔をセグメント ツリーに挿入することです。 DSU はエッジを永久に削除することはなく、再帰フレーム内で一時的にエッジを適用し、後でロールバックするだけです。 

微妙な点は、パスの圧縮を避けていることです。`find`。 パス圧縮は元に戻すことができず、ロールバックの正確性が損なわれる可能性があるため、これが必要です。 代わりに、効率性を高めるためにサイズによる結合に依存する単純な親チェーンの走査を使用します。 

もう 1 つのデリケートな側面は、クエリ結果の保存方法です。 複数のクエリが同時に発生する可能性があるため、各クエリは出現順にインデックス付けされます。 出力順序を維持するために、クエリ インデックスに合わせて配列に回答を格納します。

 ## 特殊なケース

 重大なエッジ ケースは、すべてのエッジが 1 日以内に発生するが、複数のクエリにまたがる場合です。 単純な DSU はノードを永続的にマージしますが、ここではウィンドウの期限が切れた後にコンポーネントを縮小する必要があります。 セグメント ツリーのアプローチでは、有効な時間間隔にのみエッジを接続することでこれに対処します。 

もう 1 つの微妙なケースは、同じタイムスタンプでの複数のクエリです。 クエリはすぐに処理されるのではなくインデックスが作成されるため、クエリに応答する前にそのタイム スライスのすべての DSU 状態が同一であることを確認し、順序依存を防ぎます。 

最後のコーナーケースは次のような場合です。$k = 0$これにより、すべてのエッジがすぐに期限切れになります。 各エッジが に挿入されるため、間隔の構築は引き続き機能します。$[t, t)$、事実上何も寄与せず、すべてのクエリは分離されたノードを正しく返します。
