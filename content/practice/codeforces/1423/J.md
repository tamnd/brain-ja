 ## 問題の理解

 係数が 0 ～ 7 の小桁に制限されている多項式の底 2 評価を使用して、数値の表現を数えています。具体的には、各多項式は係数の選択に対応します。$a_0, a_1, a_2, \dots$、それぞれ 0 から 7 の間であり、それを次のように評価します。$x = 2$。 これは、すべての多項式が次の形式の値に寄与することを意味します。$$P(2) = a_0 + a_1 \cdot 2 + a_2 \cdot 2^2 + \cdots$$したがって、この問題は、「数値は何通りの方法で表現できるか」と尋ねることと同じです。$m$2 のべき乗の和として、各べき乗は$2^k$多重度は0から7まで使用できますか?

 入力は最大になります$5 \cdot 10^5$の値$m$、それぞれ最大$10^{18}$。 これにより、クエリごとの動的プログラミングやビットマスク列挙が直ちに除外されます。$m$。 クエリごとのビットに対する線形スキャンでも許容されますが、ビット数の二次関数やクエリごとの畳み込みを伴うものは合格しません。 

微妙な点は、これが標準のバイナリ表現ではないことです。 2 進数では、2 の各べき乗は最大 1 回現れますが、ここでは各べき乗は最大 7 回現れます。 これによりビット間のキャリーが発生し、オーバーフローの伝播を適切に処理しないと単純なビットごとの貪欲な推論は失敗します。 

典型的な間違ったアプローチは、各ビットを独立して扱うことです。$m$、係数を選択します$a_i$そのビットを mod 2 または mod 8 に一致させます。位置で係数を選択しているため、これはすぐに中断されます。$i$キャリーを通じて上位ビットに影響を与えます。 たとえば、次のように表現しようとすると、$m = 8$、単純な方法では、係数 8 を使用しようとする可能性があります。$2^0$、ただし、係数は 7 で制限されているため、これは不可能です。そのため、正しい表現には、より高い位置へのキャリーが含まれる必要があります。 

## アプローチ

 重要な観察は、多項式を 2 で評価することは、係数を基数 2 の数字として解釈することと同じですが、桁の範囲は 0 ～ 1 ではなく 0 ～ 7 であるということです。つまり、表現方法が何通りあるかを数えているのです。$m$各桁が 0 ～ 7 であり、位置の重みが 2 の累乗である混合基数システムです。 

拡大すると$m$バイナリでは、各ビット位置に値があり、その位置とそれより低い位置の係数からどれだけの寄与がキャリー伝播後にそのビットを生成できるかを決定する必要があります。 

ブルートフォース解釈では、すべての係数の割り当てをシミュレートしようとします。 各ビットは 8 つの値を取ることができ、関連するビット位置は最大 60 個あるため、これはすでに次のようになります。$8^{60}$、それは完全に不可能です。 

重要な洞察は、その構造が有界キャリーを持つバイナリ表現上の数字 DP であるということです。 各ビット位置で、正確な係数の割り当てを追跡するのではなく、次のビットへの特定のキャリーを生成する方法の数を追跡します。 各係数は最大 7 であり、2 の累乗を合計するため、どのステップでも最大キャリーは定数 (具体的には 8 未満) によって制限され、DP 状態が小さく保たれます。 

各ビットのキャリー状態が何通り発生するかを維持しながら、最下位から最上位までビットを処理します。 各ビットは遷移に寄与します。0 から 7 までの係数を選択し、それを現在のキャリーとターゲット ビットに加算し、次のキャリーを決定します。 

これにより、問題は、一定サイズの状態空間を持つ最大 60 ビットにわたる線形 DP に変換されます。

 ## アルゴリズムのチュートリアル

 のバイナリ表現を扱います。$m$ビットのシーケンスとして$b_0, b_1, \dots$、最も重要でないものから最も重要なものまで処理します。 

1. DP テーブルを初期化します。`dp[c]`これまでに処理されたビットをキャリー値で処理する方法の数を表します`c`現在のビットに入力します。 当初は、`dp[0] = 1`。 
2. 各ビット位置について$i$、 抽出する$b_i$、新しい DP テーブルを作成します`ndp`。 
3. 可能なキャリーごとに`c`0 ～ 7 の各係数の選択`a`0 から 7 までの合計を計算します。$$s = c + a$$この値は現在のビットに寄与し、次のビットへのキャリーを生成する可能性があります。 

現在のビット制約により、次のことが強制されます。$$s \bmod 2 = b_i$$有効な組み合わせのみが保持されます。 
4. 有効な場合は、以下を更新します。$$ndp[(c + a - b_i) / 2] += dp[c]$$この式は、ビット寄与を減算し、残りの値を上方に伝播することを反映しています。 
5. すべての係数とキャリーを処理した後、次のように置き換えます。`dp = ndp`。 
6. すべてのビットを処理すると、答えは次のようになります。`dp[0]`、最上位ビットを超えてキャリーが残らないようにする必要があるためです。 

### なぜ効果があるのか

 DP は、ビット位置ごとに、指定されたキャリーでその位置に到達するためのすべての方法の完全な要約を維持します。 この遷移では、現在の 2 進数の制約を考慮して、0 ～ 7 の数字を割り当てる有効な方法がすべて考慮されます。 キャリーは状態で完全にキャプチャされるため、履歴情報が失われることはありません。 これにより、有効な係数の割り当てはすべて 1 回だけカウントされ、無効な割り当てはビット制約に違反する最も早い時点で除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    ms = list(map(int, input().split()))

    # precompute bits up to 60
    MAXB = 61

    for m in ms:
        bits = [(m >> i) & 1 for i in range(MAXB)]

        dp = [0] * 16
        dp[0] = 1

        for b in bits:
            ndp = [0] * 16

            for carry in range(16):
                if dp[carry] == 0:
                    continue
                for a in range(8):
                    s = carry + a
                    if (s & 1) != b:
                        continue
                    nc = s >> 1
                    if nc < 16:
                        ndp[nc] = (ndp[nc] + dp[carry]) % MOD

            dp = ndp

        print(dp[0] % MOD)

if __name__ == "__main__":
    solve()
```この実装は、上記で説明した数字 DP を直接反映しています。 DP アレイのサイズは、エッジの問題を発生させずにキャリー伝播に安全に対応できるように、余裕をもって選択されています。 各反復で 1 つの 2 進数が処理されます。$m$、各状態について、0 から 7 までのすべての係数値を試します。パリティ チェックでは、現在のビットの正確性が強制され、1 つ右にシフトして次のキャリーが計算されます。 

よくある落とし穴は、キャリーの飛距離を過小評価することです。 直感的なキャリーは小さく感じられますが、中間合計は減らされる前に一時的に 7 を超える可能性があるため、16 のような安全な上限を使用すると、サイレント状態の切り捨てが回避されます。

def run(inp: str) -> str:

 ## 特殊なケース

 のために$m = 0$の場合、唯一有効な多項式は、すべての係数がゼロであるゼロ多項式です。 DP はキャリー 0 から始まり、ゼロ以外の寄与が決して導入されないため、最終状態は有効なままであり、正確に 1 つのウェイが生成されます。 

次のような 2 のべき乗の場合$m = 8$単純な推論では、係数 1 を位置 3 に配置しようとしますが、システムでは、係数が低いほど上向きのキャリーが生成される構成も許可されます。 DP は、キャリー状態をビット間で伝播することにより、これらすべての分解を正しく説明し、正規のバイナリ表現だけでなく、すべての有効な構造が確実にカウントされるようにします。
