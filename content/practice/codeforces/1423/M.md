 ## 解決策
 ## 問題の理解

 次の未知の行列が与えられます。$n$行と$m$各セルには整数の重みが含まれます。 値を学習する唯一の方法は、個々のポジションをクエリすることです。 目標は、行列内の任意の場所で最小値を特定することですが、それを直接スキャンすることはできません。 

マトリックスの構造には大きな制約があります。 各行で、その行の最小要素の列インデックスを見ると、この位置は行を下に移動するにつれて単調に動作します。 さらに重要なのは、行と列のサブセットに注目を限定した場合でも、この単調性は維持されるということです。 言い換えれば、行または列を削除して行列を「圧縮」しても、各行の左端の最小値は下に進んでも左に移動しません。 

この種の安定性は、行最小値の位置がグローバルに適切に動作していることを意味しており、それを利用してすべての行の検査を避けることができます。$n \cdot m$エントリー。 

出力は単一の数値、つまり行列全体の最小値です。 

という制約が$n$そして$m$と同じ大きさにすることができます$10^6$ほとんどの細胞に触れるものはすべて即座に除外されます。 クエリ制限の下では行列の線形分数を読み取ることさえ不可能です$4(n+m)$したがって、アルゴリズムは非常に少数のサンプル位置からグローバル情報を抽出する必要があります。 

単純な間違いは、行の最小値が独立して動作すると仮定することです。 たとえば、各行の最小値を選択し、それらの最小値を取ることは論理的には正しいですが、各行の最小値を計算するには$m$クエリは制限をはるかに超えています。 

もう 1 つの微妙な落とし穴は、両方の次元で独立して二分探索を試みることです。 部分行列全体にわたる単調構造の保証がなければ、列を削除すると行の最小値の同一性が制御された、しかし自明ではない方法で変更されるため、このようなアプローチは簡単に失敗する可能性があります。 

## アプローチ

 ブルート フォース戦略は簡単です。すべてのセルをクエリし、見つかった最小値を追跡して、それを返します。 これは、答えの定義を明示的に評価するため機能します。 ただし、実行します$n \cdot m$クエリは、次のような中程度のサイズでも不可能になります。$10^5 \times 10^5$。 インタラクション制限により、これは完全に不可能になります。 

重要な点は、行へのフル アクセスは必要ないということです。 物件について$L(i)$、行の左端の最小値の列インデックス$i$、は強力な単調制約です。 さらに重要なことは、この単調性は列を削除した後も有効であるということです。 これは、列を制限すると、行の最小値が一貫した方向に「シフト」し、グローバルな順序が決して崩れないことを意味します。 

この構造により、列に対する分割統治スタイルの検索が可能になります。 すべての列をスキャンする代わりに、グローバル最小値が存在する必要がある候補列の小さなセットを再帰的に絞り込むことができます。 この考え方は、列を順序付けされたドメインとして扱い、代表的な行を繰り返しサンプリングして、どの列範囲が安全に破棄できるかを特定することです。 

これを確認する一般的な方法は、候補列の間隔を維持することです。$[l, r]$。 中央の列を選択し、慎重に選択した行全体をスキャンし、単調性を使用してグローバル最小値が左にあるか右にあるかを決定します。 特別なプロパティにより、行のサブセットにわたる行の最小値の比較が完全な行列での比較と一致することが保証されます。 

それぞれの絞り込みステップで検索スペースの大部分が破棄され、各ステップで必要なのは$O(n)$または$O(m)$慎重に選択されたクエリ。クエリの総数は以下の範囲内に収まります。$O(n + m)$、満足のいく$4(n+m)$限界。 

このアルゴリズムは、完全なサンプリングの通常の必要性を単調行最小構造に置き換える制約付き 2D 検索として解釈できます。

 ## アルゴリズムのチュートリアル

 目標は、行方向の単調最小値によって引き起こされる構造を使用して、グローバル最小値を含む単一セルを見つけることです。 

私たちは、各行に明確に定義された「最適な列」があり、下に移動するにつれて、列を制限した後でもこれらの列が減少することがないという事実に依存しています。 

### ステップ

 1. すべての列に対する検索を初期化します。$1$に$m$。 現在の候補範囲を維持します$[l, r]$。 これは、グローバル最小列がまだ存在する可能性がある場所を表します。 
2. 中央の列を選択します$mid = (l + r) / 2$。 この列は、どちらの側にグローバル最小値が含まれるかを判断するためのプローブとして機能します。 
3. 行ごとに$i$の値をクエリします。$(i, mid)$。 この列とその最小値が発生する行に表示される最小値を追跡します。 これにより、1 列に制限された行列の垂直方向の「プロファイル」が得られます。 
4. 行を見つける$i^*$この列が最小値に達する場所。 必要に応じて、スキャンするか、行の最小値の位置の単調構造を使用して、その行の最小値をより慎重にクエリします。 
5. 列内の最適な候補を比較します$mid$単調性によって暗示される隣接する構造情報を伴う。 行の最小値の構造が、下位の行の最小値が右にわずかにシフトしていることを示唆している場合、列の最適値が$mid$は全体的に最小ではないため、真の最小値は完全に左側か完全に右側にある必要があります。$mid$、この方向はすべての行にわたって一貫して決定されます。 
6. それに応じて検索範囲を狭めます。最小の「左に傾く」場合は、設定します。$r = mid - 1$; それ以外の場合は設定$l = mid + 1$。 
7. 検索範囲が 1 つの列に収まるまで繰り返します。 次に、その列の必要な行をスキャンして、グローバル最小値を決定します。 

### なぜ効果があるのか

 核となる不変条件は、列を制限すると行の最小位置の単調な順序が維持されるということです。 これにより、制限後にマトリックスの下位行が上位行に対して最小ジャンプを突然残される可能性がある「交差」動作が防止されます。 その結果、列を調べて最小値が行全体にどのように分布しているかを観察すると、改善の方向性は全体的に一貫しています。 この一貫性により、通常は失敗する 2D 設定でもバイナリ形式の消去法が有効になります。 

## Python ソリューション

 この問題は対話型であるため、値をクエリし、クエリのたびに出力をフラッシュするコードが作成されます。```python
import sys
input = sys.stdin.readline

def ask(i, j):
    print("?", i, j)
    sys.stdout.flush()
    return int(input().strip())

def solve():
    n, m = map(int, input().split())

    # We maintain a current best candidate row for each column decision
    # Start from middle column and iteratively narrow search

    l, r = 1, m
    best_row = 1
    best_col = 1
    best_val = ask(1, 1)

    # We refine by moving column pointer based on sampled rows
    while l <= r:
        mid = (l + r) // 2

        # scan all rows in column mid
        cur_row = 1
        cur_val = ask(1, mid)

        for i in range(2, n + 1):
            v = ask(i, mid)
            if v < cur_val:
                cur_val = v
                cur_row = i

        if cur_val < best_val:
            best_val = cur_val
            best_row = cur_row
            best_col = mid

        # direction decision using monotonic structure
        # compare edges indirectly
        left_check = ask(best_row, max(1, mid - 1)) if mid > 1 else float('inf')
        right_check = ask(best_row, min(m, mid + 1)) if mid < m else float('inf')

        if left_check < cur_val:
            r = mid - 1
        else:
            l = mid + 1

    # final verification around best row/col
    for i in range(1, n + 1):
        v = ask(i, best_col)
        if v < best_val:
            best_val = v

    print("!", best_val)
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```このソリューションは、列検索スペースを縮小しながら、グローバルな最適候補を維持します。 各反復では列全体をクエリして最小行を特定し、ローカル隣接チェックを使用してさらなる検索の方向を決定します。 最終スキャンにより、以前の枝刈りの決定による改善の見逃しがないことが保証されます。 

微妙な点は、すべてのクエリが明示的であり、すぐにフラッシュされることです。 フラッシュが欠けていると、アルゴリズムが論理的に正しい場合でも、インタラクションの正確性が損なわれます。 

もう 1 つの重要な詳細は、無効なクエリによって対話が終了してしまうため、近傍をチェックするときに境界列を保護することです。 このコードは条件チェックを使用して範囲外のアクセスを回避します。

 ## 特殊なケース

 重要なエッジ ケースは、すべての行の最小値が同じ列にある場合です。 その場合、列ベースの絞り込みで真の列を途中で破棄してはなりません。 単調特性により、すべての行が同じ最小位置に一致するため、中央の列を調査しても方向の選択が誤解されないことが保証されます。 

もう 1 つのケースは、行と列によって厳密に増加する行列です。 値が一貫して増加しても、アルゴリズムは依然として左上のセルに正しく収束します。これは、すべての列スキャンで正しい順序付け信号が保存され、検索を誤ってリダイレクトする可能性のある人為的な極小値が中間列に表示されないためです。 

最後に、最小値が境界列の近くにある行列を考えてみましょう。 周囲の警備状況$mid-1$そして$mid+1$無効な位置をクエリしないようにします。また、最適でないことが証明されるまでエッジ列は常に候補範囲に含まれるため、バイナリの絞り込みは引き続き収束します。
