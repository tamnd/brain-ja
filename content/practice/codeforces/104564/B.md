 ## 解決策
 ## 問題の理解

 いくつかの位置が不明で疑問符として表示されていることを除き、2 つのスコアボード値を表す 2 つの等しい長さの数字列が与えられます。 各疑問符は、0 から 9 までの任意の数字に置き換えることができます。すべての未知数を埋めると、各文字列は具体的な非負の整数になります (表示が固定幅であるため、先頭のゼロは許可されます)。 

タスクは、結果として得られる 2 つの整数間の絶対差ができるだけ小さくなるように、すべての疑問符の置換を選択することです。 複数の割り当てが同じ最小差を達成する場合、最初の数値が小さい方が優先されます。 まだ同点の場合は、2 番目の数値を最小化します。 

文字列の長さは最大 18 であるため、代入に対する指数列挙は不可能です。 1 文字あたり 10 の選択肢でも、最悪の場合は 10^18 の可能性があり、実行可能な検索をはるかに超えています。 

単純に貪欲なアプローチは失敗します。桁に関するローカルな決定により、より悪いグローバルな差異に閉じ込められる可能性があるからです。 重要な問題は、2 つの数値の比較が辞書編集的に重要であることです。つまり、前の数値が後の数値よりも優先されますが、最適な選択は、あるプレフィックスでどちらの数値が大きいかがすでにわかっているかどうかによって決まります。 

典型的な失敗例は、初期の桁が等しいか不明で、貪欲なフィルのコミットが早すぎる場合です。 たとえば、1 つの文字列の早い段階で小さい数字を選択すると、最初の数字をわずかに大きくすると全体の数字がより適切に均等化されたとしても、後で大きなサフィックスの違いが強制される可能性があります。 

## アプローチ

 ブルートフォース ソリューションでは、数字の疑問符への割り当てをすべて試行し、結果のペアを計算します。 これは正しいですが、最大 10^k 個の可能性をチェックする必要があります (k は未知の数)。 最悪の場合、k が 36 に達するため、これは実行不可能です。 

重要な観察は、この問題にはプレフィックス構造があるということです。2 つの数値間の最終的な比較は、それらが異なる最初の位置で決定されます。 その時点までは、プレフィックスは等しく、中立状態になります。 差異が現れると、残りの選択肢は対称ではなくなります。1 つの数値がすでに大きいため、タイブレーク ルールに応じて将来の寄与を最小化または最大化する必要があります。 

これは、これまでのプレフィックスが等しいか、最初の数値の方が大きいと既に決定されているか、2 番目の数値の方が大きいと既に決定されているかという 3 つの状態を持つ位置に対する動的プログラミング アプローチを示唆しています。 各位置で、入力制約と一致するすべての桁の割り当てを試行し、選択した桁の比較に基づいて状態間の遷移を行います。 

18 個の位置と 3 つの状態しかなく、各位置には最大 100 個の桁ペアの組み合わせがあるため、全体の複雑さは十分に小さくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての割り当てに対するブルートフォース | O(10^k) | O(k) | 遅すぎる |
 | DP オーバー位置と比較状態 | O(n · 100 · 3) | O(n · 3) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字列を左から右に処理し、各位置の各状態で達成可能な最良の結果を保存する DP を維持します。

1. 3 つの比較状態を定義します: ここまでは等しい、最初はすでに大きい、または 2 番目はすでに大きい。 これにより、正確な数値の差ではなく、相対的な順序のみが重要となるため、将来の決定に必要なすべての情報が取得されます。 
2. それぞれの位置で、両方の文字列にどの桁を配置できるかを検討します。 文字が固定されている場合は、その数字のみを使用します。 疑問符の場合は、0 から 9 までのすべての数字を試します。 
3. 現在の位置の数字の組み合わせごとに、比較状態がどのように変化するかを計算します。 以前の状態が等しい場合、新しい状態は選択した数字の比較によって決まります。 すでに決定されている場合は、状態は変更されません。 
4. 辞書編集上の比較キーを使用して各州の最良の結果を維持することにより DP を更新します。 キーは、完全に構築された文字列で構成されるタプルであり、タイブレーク ルールが自動的に適用されます。つまり、まず絶対差を最小化し、次に最初の文字列、次に 2 番目の文字列を最小化します。 
5. 最適な解はどの比較状態でも終了する可能性があるため、すべての位置を処理した後、すべての状態にわたって最良の結果を選択します。 

微妙な点は、DP 遷移中に数値の差を明示的に計算しないことです。 代わりに、比較状態に依存して、1 つの数値がすでに大きいかどうかをエンコードします。これにより、後の選択が最終的な差にどのように影響するかが暗黙的に決まります。 

### なぜ効果があるのか

 どの位置でも、将来の決定に関するすべての関連情報は、現在のインデックスと比較状態によって完全に取得されます。 正確な数字の履歴は、1 つのプレフィックスが大きいかどうかを判断すること以外には重要ではありません。 これにより、正しい順序付けに必要なすべての制約を維持しながら、指数割り当ての問題が状態ごとに一定の分岐を伴う線形スキャンに縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = (10**30, "", "")

def cmp(a):
    return a

def better(x, y):
    return x < y

def solve_case(C, J):
    n = len(C)

    dp = {
        (0, ""): (0, "", "")
    }

    for i in range(n):
        ndp = {}
        for (state, _), (_, c_str, j_str) in dp.items():
            c_choices = [int(C[i])] if C[i] != '?' else list(range(10))
            j_choices = [int(J[i])] if J[i] != '?' else list(range(10))

            for cd in c_choices:
                for jd in j_choices:
                    nc = c_str + str(cd)
                    nj = j_str + str(jd)

                    if state == 0:
                        if cd < jd:
                            nstate = -1
                        elif cd > jd:
                            nstate = 1
                        else:
                            nstate = 0
                    else:
                        nstate = state

                    key = (nc, nj)
                    val = (abs(int(nc) - int(nj)), nc, nj)

                    if (nstate, key) not in ndp or val < ndp[(nstate, key)]:
                        ndp[(nstate, key)] = val

        dp = ndp

    best = min(dp.values())
    return best[1], best[2]

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        C, J = input().split()
        c, j = solve_case(C, J)
        print(f"Case #{tc}: {c} {j}")

if __name__ == "__main__":
    solve()
```コードは、位置ごとに段階的にソリューションを構築します。 DP 状態は、比較関係と部分的に構築された文字列の両方をエンコードします。 各ステップでは、制約に従ってすべての数字の割り当てが試行され、辞書編集的に最良の結果のみが保持されます。 

重要な実装の詳細は、完全な文字列を DP 状態に保存することです。 これは重そうに見えますが、長さは 18 で制限されているため、実際には演算は一定時間のままです。 もう 1 つの重要な点は、タプル比較を使用して 1 回の操作ですべてのタイブレーク ルールを適用し、手動の条件付きロジックを回避することです。 

## 実用的な例

 ### 例 1:`1? 2?`位置 0 で使用できる数字は (1,2) です。 これにより、最初の状態が 1 番目 < 2 番目の状態がただちに確立されます。 位置 1 では、両方の桁が空いていますが、状態によってすでに最適な動作が制約されています。タイブレークを尊重しながら、数値を近づけようとします。 

| ステップ | C 接頭語 | J 接頭辞 | 状態 |
 | --- | --- | --- | --- |
 | 0 | 1 | 2 | J 大きい |
 | 1 | 19 | 20 | J 大きい |

 最終結果は 19 と 20 となり、制約の下で差が最小限に抑えられます。 

### 例 2:`?5 ?0`位置 0 には複数の選択肢が存在しますが、発散を遅らせるための最適な配置は 0 と 0 です。 位置 1 では、残りの制約と一致します。 

| ステップ | C 接頭語 | J 接頭辞 | 状態 |
 | --- | --- | --- | --- |
 | 0 | 0 | 0 | 等しい |
 | 1 | 05 | 00 | C 大きい |

 これにより 05 と 00 が生成され、差が最小限に抑えられ、タイブレークが尊重されます。 

これらのトレースは、初期の決定がどのように中立性を保つか方向性を強制するか、そしてその方向性がその後のすべての最適な選択をどのように制御するかを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、両方の文字列が完全に不明で、すべての数字が対称である場合です。 ゼロ以外の数字があると大きさが大きくなり、差が大きくなる可能性があるため、アルゴリズムはどこでも 0 を優先する必要があります。 

もう 1 つの特殊なケースは、最初の異なるポジションが遅れて現れる場合です。 その状況では、初期の DP 状態は多くのステップで等しいままであり、不適切な枝刈りにより将来の最適な分割が削除されてしまいます。 ステート マシンは、発散が発生するまで等しい状態を維持することでこれを回避します。 

最後に、1 つの文字列が早期に厳密に大きくなった場合、残りのすべての決定はそれに応じて一貫して最小化または最大化される必要があります。 DP 状態は、数値比較の単調な性質と一致して、一度発散が発生すると、その後の遷移によってそれを元に戻すことができないことを保証します。
