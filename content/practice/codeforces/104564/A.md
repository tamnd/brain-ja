 ## 解決策
 ## 問題の理解

 シャッフルされた文字のコレクションを表す文字列が与えられます。 これらの文字は、0 から 9 までの数字を表す英単語を書き出し、それらの単語をすべて連結して未知の数字のシーケンスにし、最後に結果の文字を任意に並べ替えることによって得られます。 元の数字シーケンスは降順ではない順序でソートされることが保証されていますが、その順序は文字のシャッフルで失われます。 

タスクは、元の複数の数字セットを再構築することです。 言い換えれば、スクランブルされた文字だけを使用して、最初に 0、1、2 などがいくつ使用されていたかを判断する必要があります。 カウントを回復したら、数字を昇順に出力します。 

制約は主に規模に関係します。 文字列の合計の長さはテスト ケースごとに 2000 に達する可能性があり、テスト ケースは最大 100 個まで存在できます。 文字を並べ替えたり、総当たりで数字のシーケンスを並べ替えたりしようとするソリューションは、直ちに実行不可能になります。 テスト ケースごとに 2 次的なものであってもギリギリ許容されますが、指数関数的なものは完全に問題外です。 

注意して順序付けせずに数字の単語を貪欲に一致させようとすると、微妙な失敗モードが発生します。 多くの数字は文字を共有します。たとえば、「ONE」と「TWO」は両方とも O などの一般的な文字を含むため、単純な一致ではカウントしすぎたり、順序に依存したりする可能性があります。 変更可能な文字プールから部分文字列を繰り返し検索して削除しようとすると、別の問題が発生します。これは、削除の順序が間違っていると、残りの数字を再構築する機能が破壊される可能性があるためです。 

具体的な失敗例として、入力「OZONETOWER」を考えてみましょう。 素朴で貪欲なアプローチでは、頻繁に出現する「ONE」を最初に一致させようとするかもしれませんが、これらの文字を削除するのが早すぎると、実際には文字 Z を一意に説明する唯一の数字であるにもかかわらず、「ZERO」の認識が妨げられる可能性があります。 

中心的な課題は、曖昧さを回避する方法で、重複する複数の文字セットから桁数を抽出することです。 

## アプローチ

 ブルートフォース解釈では、位置に数字を割り当て、そのスペルアウト形式で指定された文字マルチセットを生成できるかどうかをテストしようとします。 たとえ桁の頻度を数えることに限定したとしても、各桁が固定語に寄与する制約付きの組み合わせシステムを解く必要があります。 長さ 2000 までの桁数のすべての組み合わせを試すと、天文学的に大きな検索空間が得られます。 

重要な構造的洞察は、各数字の単語に文字が含まれており、一部の文字は 1 つの数字の単語内に独自に現れるということです。 たとえば、Z は ZERO にのみ、W は TWO にのみ、U は FOUR にのみ、X は SIX にのみ、G は EIGHT にのみ表示されます。 これらの一意の識別子を使用すると、数字を 1 つずつ剥がし、文字のマルチセットからその寄与を削除し、制御された順序で他の一意のマーカーを明らかにすることができます。 

これらの強制された数字が削除されると、以前は一意ではなかった数字が一意に識別できるようになります。これは、その曖昧さがすでに説明されている文字に依存するためです。 

これにより、問題は組み合わせ検索ではなく度数表上の決定論的な演繹プロセスに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 桁数のブルートフォース列挙 | 指数 | O(1) または O(n) | 遅すぎる |
 | 固有の文字を使用した頻度 + 貪欲な消去 | O(T * N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 入力文字列を文字の頻度表に変換します。 次に、慎重に選択した識別文字を使用して、各桁の数を段階的に決定します。 

1. 周波数マップを構築する`cnt`文字列内のすべての文字の。 これは、数字の単語で説明できる文字が何文字残っているかを表します。 
2. 一意の識別文字を持つ数字を識別します。 

Z を介して 0、W を介して 2、U を介して 4、X を介して SIX、G を介して EIGHT。このような各桁の桁のカウントは正確に次のようになります。`cnt[unique_letter]`。 これは、他の数字がその文字に寄与しないため機能します。 
3. ステップ 2 で特定された各桁について、その全単語の寄与を頻度表から減算します。 他の数字を識別するときにこれらの文字を再利用してはいけないため、これが必要です。 
4. これらの数字を削除すると、新しい一意性が現れます。 

H 経由の THREE、F 経由の FIVE、S 経由の SEVEN。これらの文字は、既に削除された数字またはまだ存在する数字に表示されるため、以前は曖昧でしたが、現在では一意に帰属できるようになりました。 
5. 同じ推論を適用します。これらの各桁について、更新された度数表を使用してカウントを計算し、その寄与を差し引きます。 
6. 最後に、残りの数字 1、9、および 0 が残差構造を使用して最後に決定されます。 実際には、以前の消去の後、一貫性を確保するために注意深く減算することで、O から ONE を決定することができ、重複を考慮した後で N から NINE を演繹することができます。 
7. すべての桁数がわかったら、頻度に従って昇順に繰り返される各桁を印刷して出力を作成します。 

消去の順序は任意ではありません。 少なくとも 1 つの文字が未解決の数字と共有されなくなったときに、すべての数字が解決されるように選択されます。 

### なぜ効果があるのか

 あらゆる段階で、次の不変条件を維持します。`cnt`まだ処理されていない数字によって提供される文字のマルチセットに等しい。 固有のマーカー文字を使用して数字を識別する場合、各数字が文字空間内の固定ベクトルであるシステムで基底ベクトルを効果的に選択していることになります。 そのベクトルを削除すると、新しい独立した方向が明らかになり、システムの次元が削減されます。 各減算は既知の単語と正確に一致するため、誤ったキャンセルは発生せず、再構成は強制的かつ一意になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import Counter

digit_words = {
    0: "ZERO",
    1: "ONE",
    2: "TWO",
    3: "THREE",
    4: "FOUR",
    5: "FIVE",
    6: "SIX",
    7: "SEVEN",
    8: "EIGHT",
    9: "NINE"
}

# order chosen by unique identifying letters
order = [
    (0, 'Z'),
    (2, 'W'),
    (4, 'U'),
    (6, 'X'),
    (8, 'G'),
    (3, 'H'),
    (5, 'F'),
    (7, 'S'),
]

def solve_case(s):
    cnt = Counter(s)
    res = [0] * 10

    for d, ch in order:
        c = cnt[ch]
        if c > 0:
            res[d] = c
            for _ in range(c):
                for c2 in digit_words[d]:
                    cnt[c2] -= 1

    # remaining digits 1 and 9 and 0 already handled but safe cleanup:
    res[1] = cnt['O']
    res[9] = cnt['N'] // 2  # after previous removals, NINE structure isolates cleanly

    return ''.join(str(i) * res[i] for i in range(10))

def main():
    T = int(input())
    for tc in range(1, T + 1):
        s = input().strip()
        ans = solve_case(s)
        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    main()
```この実装は、文字上の周波数カウンターを中心にしています。 の`order`配列は、グローバルに一意の文字を持つ数字から始まる消去戦略をエンコードします。 このような各桁について、対応する一意の文字からそのカウントを直接読み取り、頻度表からその桁の単語全体の寄与を繰り返し減算します。 

最後の再構成ステップでは、残差構造を使用して残りの桁を処理します。 クリーンな実装では、ONE と NINE はすべての一意の文字が削除された後にのみ決定され、O と N の数に曖昧さが残らないようにします。 

よくある落とし穴は、減算は数字の種類ごとに 1 回ではなく、数字の出現ごとに繰り返す必要があることを忘れていることです。 各数字インスタンスは完全なワードに寄与するため、頻度の更新は多重度を反映する必要があります。 

## 実用的な例

 「OZONETOWER」という入力を考えてみましょう。 初期の頻度カウントには、O、Z、E、N、T、W、R、および複数の O と E が含まれます。 

削除命令を進めていきます。 

| ステップ | 数字 | ユニークな文字 | カウント | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | Z | 1 | ゼロを削除 |
 | 2 | 2 | W | 1 | 2 つ削除 |
 | 3 | 4 | う | 0 | スキップ |
 | 4 | 6 | X | 0 | スキップ |
 | 5 | 8 | G | 0 | スキップ |
 | 6 | 3 | H | 0 | スキップ |
 | 7 | 5 | ふ | 0 | スキップ |
 | 8 | 7 | S | 0 | スキップ |

 ZERO と TWO を削除した後、残りの文字は ONE とすでに解決されている他の数字に対応します。 数字 0、1、2 を復元すると、「012」が得られます。 

このトレースは、一意の文字の削除によってバックトラッキングを必要とせずにマルチセットがきれいに削減され、強制された数字が削除されると残りのあいまいさが自動的に消えることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(T * N) | 各文字は、カウントおよび減算中に一定の回数処理されます。 
| スペース | お(1) | 周波数配列のサイズは固定 (26 文字) |

 このアルゴリズムは、テスト ケースごとに文字列に対して制限された回数のパスを実行し、各パスには固定アルファベットに対する定数時間の更新のみが含まれます。 N が最大 2000、T が最大 100 であれば、このソリューションは制限内に問題なく収まります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、一意に識別可能な数字が複数出現する場合です。 たとえば、「ZEROZERO」には Z の文字が 2 つあります。 一意の文字数が多重度を直接エンコードするため、アルゴリズムはこれを 2 つの 0 桁として正しく解釈します。 出現するたびに単語の完全な減算がトリガーされるため、残った文字が不明のまま残ることはありません。 

もう 1 つのケースは、N と E が大半を占める文字列など、数字間で文字が重なり合う場合です。「NINENINE」では、単純なアプローチにより、一貫性を持たずに ONE または NINE を割り当てようとする可能性があります。 削除順序により、真に一意のマーカーを持つ数字が最初に削除され、残りのカウントが未解決の数字タイプのみと一致することが保証されるため、これが防止されます。 

最後の微妙なケースは、最初の一意のマーカーのない数字だけが残る場合です。 残りのカウントのステップにより、すべての強制除去の後、残りの構造が決定的であることが保証されます。 たとえば、ZERO、TWO、FOUR、SIX、EIGHT、THREE、FIVE、SEVEN が削除されると、残った文字は ONE と NINE に明確に対応し、残りの周波数ベクトルから曖昧さなくその数を導き出すことができます。
