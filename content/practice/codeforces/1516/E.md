 ## 解決策
 ## 問題の理解

 1 から n までの数字を一列に並べた恒等置換から始めます。 1 回の操作で、任意の 2 つの位置を選択し、それらの値を交換できます。 このようなスワップを正確に j 回実行すると、配列は 1 から n の順列になります。 スワップのシーケンスが異なっていても、最終的には同じ順列が得られる可能性がありますが、ここでは最終的な順列がどのように生成されるかではなく、どの最終的な順列に到達できるかのみを考慮します。 

1 から k までのすべての j について、正確に j 回交換した後に、異なる順列がいくつ現れるかを数えたいとします。 

重要な問題は、n が最大 10^9 と非常に大きいため、順列を明示的にシミュレートしたり推論したりすることさえできないことです。 一方、k は小さく、最大でも 200 です。これは、答えが完全な順列列挙ではなく、小さな構造変化のみに依存することを示唆しています。 

素朴な解釈では、順列距離の観点から考えようとします。 n からサイクル数を引いたものに等しい最小スワップ数を使用して、恒等式から順列に到達できます。 ただし、特定のスワップ距離を持つ順列の数を数えることは、すぐに組み合わせが複雑になります。 

j が n に対して大きい場合、微妙なエッジ ケースが発生します。 たとえば、n = 2 および k = 3 の場合、すべてのスワップは同じ 2 つの順列間を切り替えるだけなので、答えはすぐに安定します。 j による成長を想定した単純な試みでは、ここで過大評価されてしまいます。 

もう 1 つのエッジ ケースは、j が順列構造内の独立したスワップの最大可能数を超える場合です。 任意の順列は最大でも n−1 個のスワップで生成できるため、j が n に対して十分に大きくなると、カウント動作はもはや「スワップが多いほど順列が増える」という単純な直感では変わりません。 

中心的な問題は、サイズ n の順列にわたる直接の組み合わせ論は不可能であり、その代わりに、スワップがサイクル構造にどのように影響するかによって、到達可能な順列を分類する必要があるということです。 

## アプローチ

 強引な方法では、j スワップのすべてのシーケンスを列挙し、その結果の順列を計算しようとします。 各スワップ選択にはおよそ O(n^2) の可能性があり、j ステップ後には (n^2)^j になります。これは、j = 3 の場合でも天文学的に大きくなります。状態空間が n! であるため、訪問した順列を保存することさえ不可能です。 

正しい観察は、スワップは恒等から始まり、要素間にエッジを追加することによって順列グラフを構築するのと同等の構造を徐々に構築するということです。 各スワップは、サイクルのマージまたは再配置として解釈できます。 

重要な構造的洞察は、あらゆる順列はそのサイクル分解によって決定され、順列を取得するために必要な最小スワップ数は n からサイクル数を引いたものであるということです。 したがって、j 回のスワップの後、n 個のシングルトン サイクルから始まる最大 j 回のマージでサイクル構造を形成できる置換を正確に数えることになります。 

順列を直接追跡する代わりに、スワップによってフォレスト解釈の接続コンポーネントの数がどのように減少するかを追跡します。 2 つの要素間の各スワップは、2 つのサイクルをマージするか、サイクル内で再配置します。 組み合わせの複雑さは、有効なマージ操作によってコンポーネントの数を n から n−j に減らすことができる方法が何通りあるかを数えることに集約されます。 

n は巨大ですが j は小さいため、実際のラベルは気にせず、マージされたコンポーネントの数だけを気にします。 これにより、「有効なマージ」の数を超える DP が得られますが、これは n ではなく j のみに依存します。 

最終的な式は、次数が最大 2j の n の多項式になり、係数はサイクルマージ遷移上の DP を介して計算されます。 これは標準的なパターンです。ラベル空間が大きく、演算数が少ない場合は、n の下降階乗のみに依存することを意味します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | O((n^2)^k) | お(1) | 遅すぎる |
 | サイクル構造DP | O(k^2) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 dp[j][c] を、結果として得られる順列が正確に c サイクルになるように j 個のスワップを実行した後のウェイの数として定義します。 有効な構造では、スワップごとにサイクル カウントが最大 1 だけ変更されるため、遷移は j 内でローカルのままになります。 

ただし、完全な n を明示的に追跡することはありません。 代わりに、スワップに参加する要素の選択は、関与する個別の要素の数のみに依存するため、すべてを n の下降階乗という観点から表現します。 

距離 j での順列の数は、正確に t 個の要素が非自明なサイクルに関与し、残りの n-t 個の要素が固定された構成の合計として表すことができます。 

これは古典的なアイデンティティにつながります。 

答えは n の多項式で、係数は j のみに依存し、n とは独立して事前計算できます。 

dp[j][t] を事前計算します。t は、j 回の交換後に影響を受ける要素の数を表します。 各スワップでは、最大 2 つの新しい要素をアクティブ セットに導入したり、既存の要素をマージしたりできるため、遷移は成長するグラフにエッジを追加することに似ています。 

また、nCr モジュロ MOD を使用して、n から t 個の要素を選択するための組み合わせ係数を事前計算します。 

各 j の最終的な答えは次のとおりです。 

dp[j][t] * C(n, t) * f(t) の t にわたる合計

 ここで、f(t) は、j 回のスワップで達成可能な t 要素の内部順列を説明します。 

重要なのは、t が 2j によって制限されるため、DP は小さいままであるということです。 

### なぜ効果があるのか

 不変条件は、j 個の交換後、固定小数点を超えて「非自明に再配置」できるのは最大 2j 個の要素だけであるということです。 他のすべての要素は変更されません。 したがって、グローバルな置換カウントは、n から最大 2j 個の要素のサブセットを選択し、j 個のスワップを使用してそのサブセット上の有効な置換をカウントすることに分解されます。 サブセットのサイズは n ではなく j のみに依存するため、n への依存は二項係数と階乗項に減少します。 これにより、DP 定式化の正確性と完全性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k = map(int, input().split())

    maxm = 2 * k

    # precompute factorials up to maxm for binomial coefficients on small t
    fact = [1] * (maxm + 1)
    invfact = [1] * (maxm + 1)

    for i in range(1, maxm + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[maxm] = pow(fact[maxm], MOD - 2, MOD)
    for i in range(maxm, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(n, r):
        if r < 0 or r > n:
            return 0
        # n is large, but r is small
        res = 1
        for i in range(r):
            res = res * ((n - i) % MOD) % MOD
        res = res * invfact[r] % MOD
        return res

    # dp[j][t] where t <= 2j
    dp = [[0] * (maxm + 1) for _ in range(k + 1)]
    dp[0][0] = 1

    for j in range(1, k + 1):
        for t in range(0, 2 * j + 1):
            val = 0
            # new swap introduces either 1 or 2 new active elements
            if t > 0:
                val += dp[j - 1][t - 1] * t
            if t > 1:
                val += dp[j - 1][t - 2] * (t - 1)
            dp[j][t] = val % MOD

    ans = []
    for j in range(1, k + 1):
        res = 0
        for t in range(0, 2 * j + 1):
            res += dp[j][t] * C(n, t)
        ans.append(res % MOD)

    print(*ans)

if __name__ == "__main__":
    solve()
```DP テーブルには、j 回の交換後にちょうど t 個の要素が影響を受ける方法が何通りあるかが格納されます。 遷移は、新しいスワップが 1 つまたは 2 つの新しい要素を導入してアクティブ セットを増やすか、またはすでにアクティブな要素内で再編成するかを反映します。 次に、二項項 C(n, t) は、1 から n までのどの実際のラベルがこれらの非固定位置に関与するかを選択します。 

t が 2j を超えることはなく、j は最大 200 であるため、組み合わせ乗算は安全です。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、n が 2j より小さい場合です。 この状況でも、DP は 2j までの項を生成しますが、t > n の場合は二項係数 C(n, t) がゼロになり、無効な寄与が自動的にトリミングされます。 たとえば、n = 3 および j = 3 の場合、DP では t が 6 に達する可能性がありますが、t ≤ 3 のみが最終的な合計に寄与します。 これにより、特別なケースを使用しなくても正確さが保証されます。 

もう 1 つのエッジ ケースは n = 2 で、すべてのスワップが単に順列を切り替えるだけです。 非常に小さな t 値のみが非ゼロの二項係数に寄与し、すべての高次構造が崩壊するため、DP はこれを正しく反映しています。
