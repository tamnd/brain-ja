 ## 解決策
 ## 問題の理解

 配列が与えられると、隣接する 2 つの要素を取得し、それらを削除し、XOR で置き換えることによって繰り返し圧縮できます。 各演算により長さは 1 ずつ減りますが、強力な構造特性は保持されます。つまり、2 つの値をその XOR で置き換えても、すべての要素の合計 XOR には影響しないため、配列全体の XOR は変更されません。 

プロセスは停止を決定するまで継続しますが、配列を 2 要素未満に減らすことはできません。 目標は、残りの要素がすべて等しい状態に到達できるかどうかを判断することです。 

の制約$n \le 2000$二次または偶数であることを示唆しています$O(n^2 \log n)$ソリューションは問題なく通過するかもしれませんが、3 次的なものは複数のテスト ケースにわたって危険になります。 ただし、ここで重要なのは、問題は操作のシミュレーションに関するものではなく、ターゲット構成に到達できる時期を特徴付ける構造的不変条件を特定することであるということです。 

素朴な思考によるよくある失敗例は、平等に向けて貪欲に融合できると思い込むことです。 たとえば、次のような配列では、$[1, 2, 3]$、マージ順序が異なると中間配列も異なり、貪欲な試みは、たとえ別のシーケンスが機能しても、早期にスタックしてしまうため、不可能であると誤って結論付ける可能性があります。 もう 1 つの微妙な罠は、配列にすでに等しい要素がある場合、答えは常に「YES」であると仮定することです。 イコライゼーションで要素を 2 つ未満に減らす必要がある場合、これは失敗しますが、これは禁止されています。 

3 番目のエッジ ケースは、小さな配列です。 のために$n = 2$、操作はまったく許可されないため、答えは単純に 2 つの要素がすでに等しいかどうかです。 

## アプローチ

 ブルート フォース アプローチでは、隣接する XOR マージの可能なすべてのシーケンスをシミュレートしようとします。 各ステップはペアを選択し、新しい配列に分岐し、すべての要素が等しくなるか、2 つだけが残るまで続行します。 可能なマージ シーケンスの数は膨大であり、本質的には、あるサイズの配列にわたるすべてのバイナリ マージ ツリーを数えることと同じです。$n$、カタルーニャ語のように成長し、指数関数的に増加します。 たとえ$n = 30$、これはすでに実行不可能になります。 

重要な観察は、隣接する XOR マージによって配列のグローバル XOR が変更されないこと、そしてさらに重要なことに、マージによって形成されるセグメントは、XOR が最終要素となる連続グループに配列を分割することに対応するということです。 したがって、最終的な状態は、配列のパーティションを選択することと同じです。$k \ge 2$連続したセグメント。各セグメントは同じ XOR 値を持ちます。 

各セグメントの最終値が$x$、すべてのセグメントを XOR すると、合計 XOR は次のようになります。$x$もし$k$奇数です、そして$0$もし$k$は均等です。 これは中心条件につながります。配列を、XOR がすべて等しい少なくとも 2 つの連続した部分に分割できるかどうかを確認する必要があります。 

意味のある唯一の候補は、$x$プレフィックス構造から来ています。 合計 XOR がゼロの場合、XOR ゼロの複数のセグメントを目指すことができます。 それ以外の場合は、合計 XOR に等しい少なくとも 3 つのセグメントに分割する方法が必要です。これは、必要な構造を生成する 2 つのカット ポイントを見つけることができれば可能になります。

 ## アルゴリズムのチュートリアル

 問題をプレフィックス XOR に関する推論に落とし込みます。 

1. 配列の合計 XOR を計算します。 この値により、有効なパーティション内の各最終セグメントが何と等しくなければならないかが決まります。 
2. 合計 XOR が 0 の場合、配列がそれぞれ XOR 0 を持つ少なくとも 2 つの連続するセグメントに分割できるかどうかをチェックします。 実行中の XOR を維持しながら左から右にスキャンし、終了する前にゼロになる回数を数えます。 このような分割を少なくとも 2 つ見つけることができれば、少なくとも 2 つの等しいセグメントを形成でき、答えは「YES」です。 
3. 合計 XOR がゼロ以外の場合、有効な最終構成は少なくとも 3 つのセグメントで構成され、それぞれの XOR が合計 XOR に等しい必要があります。 これは、2 つのセグメントの XOR がゼロに戻り、合計がゼロでないことに矛盾するためです。 したがって、プレフィックス XOR が合計 XOR に等しい 2 つの異なるカット ポイントを探します。2 番目のカットの後、残りのサフィックスも同じ XOR 構造に一致する必要があります。 これは、少なくとも 2 つの有効なプレフィックス位置を見つけて、3 番目のセグメント用の余地があることを確認することと同じです。 
4. 配列をスキャンし、プレフィックス XOR を追跡し、ターゲット値と等しい位置を記録します。 配列の終わりの前に少なくとも 2 つのそのような位置が見つかった場合は、2 番目のカットが最後の要素にないことを確認することで、暗黙的に 3 番目のセグメントを形成する可能性をチェックします。 

### なぜ効果があるのか

 XOR 演算は結合的かつ可換であるため、隣接するマージのシーケンスは、配列のパーティションを連続したブロックに選択することと同等であり、各ブロックは XOR に折りたたまれます。 したがって、最終的な配列はそのようなパーティションによって完全に決定されます。 すべての最終要素が等しいという条件は、セグメントの XOR の等価性に対する制約になります。 有効なセグメント境界を定義できるのはプレフィックス XOR 値のみであるため、問題は実行可能なプレフィックス一致をカウントすることになります。 これにより、マージ順序への依存が排除され、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        total = 0
        for x in a:
            total ^= x

        if n == 2:
            print("YES" if a[0] == a[1] else "NO")
            continue

        # If total XOR is zero, we just need at least two zero-prefix splits
        if total == 0:
            cur = 0
            cuts = 0
            for i in range(n - 1):
                cur ^= a[i]
                if cur == 0:
                    cuts += 1
            print("YES" if cuts >= 2 else "NO")
        else:
            cur = 0
            cuts = 0
            for i in range(n - 1):
                cur ^= a[i]
                if cur == total:
                    cuts += 1
            print("YES" if cuts >= 2 else "NO")

if __name__ == "__main__":
    solve()
```解決策は、配列全体の XOR を計算することから始まり、有効な分解における各セグメントの唯一の候補値が決定されます。 特別な場合$n = 2$操作ができないため、直接処理されます。 

大きな配列の場合、合計 XOR がゼロかどうかに応じて、ロジックは 2 つの構造的なケースに分かれます。 どちらの場合も、実装はプレフィックス XOR をスキャンし、最終インデックスの前に必要な値が出現する頻度をカウントすることに依存しており、常に少なくとも 2 つのセグメントのためのスペースを確保します。 

よくある落とし穴は、カットを最後の要素より前の位置に制限することを忘れることです。 最後にカットを許可すると、最後のセグメントが空である無効なパーティションが誤ってカウントされます。

    input = sys.stdin.readline

            out.append("YES" if cuts >= 2 else "NO")

            cur = 0
            cuts = 0
            for i in range(n - 1):
                cur ^= a[i]
                if cur == total:
                    cuts += 1
            out.append("YES" if cuts >= 2 else "NO")

    return "\n".join(out)

 ## 特殊なケース

 のために$n = 2$の場合、結合は許可されないため、アルゴリズムは 2 つの値を直接比較します。 これにより、さらなる変換によってそれらが等化される可能性があるという誤った想定を防ぐことができます。 

合計 XOR が 0 であるが、有効なプレフィックス カットが 1 つだけ存在する配列の場合、アルゴリズムはそれらを正しく拒否します。 具体的なケースとしては、$[1, 2, 3]$ここで、XOR の合計は 0 ですが、最後の要素の前で 0 に達するプレフィックスは 1 つだけであり、2 番目のセグメントは阻止されます。 

合計 XOR がゼロでない場合、少なくとも 2 つの有効なプレフィックス一致が必要なので、少なくとも 3 つのセグメントを形成できます。これは、一貫性のない XOR 制約に戻ることを避けるために必要な最小値です。
