 ## 解決策
 ## 問題の理解

 寸法が記載された長方形のボードが与えられます$n \times m$。 各セルはチェスの駒を配置できる位置として解釈でき、問題はナイトのような攻撃ルールによる移動制限の下で配置できる駒の最大数を求めます。 1 つのセルに配置されたピースは他の特定のセルを「制御」し、有効な構成では、配置された 2 つのピースが互いに攻撃しないようにする必要があります。 

動きの構造は重要な隠された情報です。攻撃関係は常にグリッドの 2 つのカラー クラス間のパリティを反転します。 これはすぐに 2 部構造を意味します。つまり、チェス盤のようにグリッドに色を付けると、すべての動きは 1 つの色から別の色に移ります。 その結果、同じクラス内の 2 つのセルが互いに攻撃できないため、完全に 1 つのカラー クラスに配置されたピースのセットは自動的に安全になります。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは 2 つの整数を提供します$n$そして$m$、グリッドのサイズを説明します。 出力は、各グリッドに個別に配置できるピースの最大数です。 

制約は明示的に示されていませんが、リファレンス コード内に閉じた形式の解決策が存在することは、次のことを示しています。$n, m$大きくなる可能性があり、少なくとも最大の可能性があります$10^9$または同様のもの。 これにより、シミュレーションやグラフの構築が即座に排除されます。 どのソリューションでも、グリッドをテスト ケースごとの定数時間式に削減する必要があります。 

主なエッジケースは、1 つの次元が非常に小さい場合に発生します。 次のような完全なチェス盤の色付け結果を想定する単純なチェッカー$\lceil nm/2 \rceil$薄い基板では失敗します。 たとえば、$2 \times 3$ボードの場合、単純な式では 3 が得られますが、慎重な配置ルールでは 4 つしか許可されず、場合によっては攻撃ジオメトリに応じて異なる構造化された動作が許可されます。 もう一つの壊れやすいケースは、$1 \times m$、ボードは線に縮退し、すべてのインタラクションが消えます。 

## アプローチ

 直接的なアプローチは、各セルがノードでエッジが有効な攻撃を表すグラフとしてグリッドを扱うことです。 次に、最大の独立セットを計算しようとします。 内部にエッジのない最大のノードのセットが必要なので、これは原理的には正しいです。 

ただし、このグラフの構築にはすでにコストがかかります$O(nm)$また、二部マッチング定式化であっても、テスト ケースごとに少なくとも線形または超線形の時間を必要とするため、最大独立セットを求める標準アルゴリズムを実行することは不可能です。 大規模なグリッドの場合、このアプローチはすぐに失敗します。 

重要な観察は、攻撃構造が非常に規則的であり、相対座標のみに依存しているということです。 グリッドは自然に 2 つのパリティ クラスに分割され、ほとんどの相互作用はこれらのクラスのみを横断します。 これは、ほとんどの場合、1 つのパリティのすべてのセルを取得すると最適な答えが得られ、グリッドのおよそ半分、つまりグリッドのおよそ半分が得られることを示唆しています。$\lfloor (nm+1)/2 \rfloor$。 

これは、両方の次元が少なくとも 3 である場合に完全に機能します。その理由は、グリッドが「十分に密である」ため、ローカル パターン制約が 2 部境界を破らないためです。 

困難は小さな次元から来ています。 いつ$n = 1$、垂直方向の相互作用がまったくないため、すべてのセルが独立しています。 いつ$n = 2$、ボードは 2 列のストリップになり、ナイトの動きが繰り返しパターンで局所的な衝突を引き起こします。 これにより、周期 4 列の周期的最適構造が得られ、幅 4 のブロックあたり 4 セルの繰り返し最大パターンが生成され、残りは特別に処理されます。 

したがって、解決策は、自明なラインの場合、制約されたストリップの場合、およびパリティが支配的な一般的な場合の 3 つの領域に集約されます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1.読む$n$そして$m$、必要に応じてそれらを交換します。$n \le m$。 すべての式は「高さ」という小さい方の次元のみに依存するため、これにより大文字と小文字の処理が軽減されます。 
2. もし$n = 1$、 戻る$m$。 In a single row, no piece can attack any other because all moves require vertical displacement. したがって、すべてのセルを安全に占有することができます。 
3. If$n = 2$、列に沿ったブロック構造を使用して答えを計算します。 ボードを 4 列のセグメントに分割します。 各完全なブロックは 4 つのピースに貢献します。 残りについては$m \bmod 4$追加の列が 1 つあると追加の配置が 2 つ、2 つの列が 4 つ、3 つの列が 4 つ、4 つの列が 4 つ追加の配置を与えます。これは、攻撃パターンが 4 列ごとに繰り返される 2 行のグリッドでの最適なローカル パッキングから生じます。 
4. もし$n \ge 3$、 戻る$\lceil nm / 2 \rceil$。 これは、チェス盤の色の 1 つの色クラスを塗りつぶすことに対応します。 すべての攻撃はパリティと交差するため、選択された 2 つのセルが競合することはなく、これは対称性により最大になります。 

### なぜ効果があるのか

 正しさは、二部性を維持するナイトのような動きの構造と、純粋なパリティの最適性を破る局所的な制約を生み出すのは狭いグリッドだけであるという事実に依存します。 のために$n \ge 3$、すべてのセルには十分な近隣の柔軟性があり、ローカル構成によってパリティ境界を下回ることはできません。 のために$n = 1$そして$n = 2$、グラフが薄すぎるため、局所的な重複制約がグローバルになり、単純な 2 部最大値ではなく周期的な最適パターンが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    if n > m:
        n, m = m, n

    if n == 1:
        print(m)
    elif n == 2:
        k = m // 4
        r = m % 4
        ans = k * 4 + min(4, r * 2)
        print(ans)
    else:
        print((n * m + 1) // 2)

t = int(input())
for _ in range(t):
    solve()
```最初のステップでは、より小さい次元を常に次のように扱うようにします。$n$の推論を簡素化します。$n = 2$場合。 の$n = 1$ブランチは縮退した折れ線グラフを直接処理します。 

の$n = 2$計算により、4 列のブロックにわたって繰り返し最適なパターンがエンコードされます。 フルブロックの 4 倍は、各 2x4 セグメントが最適な構成で 4 つの非攻撃部分を収容できることを反映しています。 を使用した余り調整`min(4, r * 2)`部分ブロックに対して事前に計算された最良の値をエンコードします。 

最後のケースでは、整数演算を使用して計算します。$\lceil nm/2 \rceil$安全に`(n * m + 1) // 2`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    data = inp.strip().split()
    t = int(data[0])
    idx = 1
    out = []

    for _ in range(t):
        n = int(data[idx]); m = int(data[idx+1])
        idx += 2

        if n > m:
            n, m = m, n

        if n == 1:
            out.append(str(m))
        elif n == 2:
            k = m // 4
            r = m % 4
            ans = k * 4 + min(4, r * 2)
            out.append(str(ans))
        else:
            out.append(str((n * m + 1) // 2))

    return "\n".join(out)

# provided sample-like checks
assert run("1\n1 10\n") == "10"
assert run("1\n2 3\n") == "4"
assert run("1\n3 3\n") == "5"

# custom cases
assert run("1\n2 1\n") == "2", "thin 2-row minimal width"
assert run("1\n2 8\n") == "8", "full 2-row blocks"
assert run("1\n3 4\n") == "6", "general parity small grid"
assert run("1\n10 10\n") == "50", "square large grid parity"

 ## 特殊なケース

 の$n = 1$ケースが一番壊れやすいです。 単純なパリティベースのソリューションでは、誤って出力されます。$\lceil m/2 \rceil$, しかし実際にはすべての細胞は独立しています。 入力用`1 7`、正しい出力は次のとおりです。`7`、アルゴリズムは直接返します$m$これは、単一の行にアタック エッジが存在しないという事実と一致します。 

の$n = 2$case は唯一の重要な構造をエンコードします。 入力用`2 5`、アルゴリズムは 1 つの完全なブロックと 1 つの剰余を計算します。$4 + 2 = 6$。 単純な半グリッド仮定では、次のようになります。$\lceil 10/2 \rceil = 5$これは厳密には間違っています。なぜなら、相互作用パターンでは、単純な 2 部構成の色付けよりも高密度のパッキングが可能になるからです。 

のために$n \ge 3$、 のような`3 3`、アルゴリズムは戻ります$\lceil 9/2 \rceil = 5$。 実行をトレースすると、特別な分岐がトリガーされておらず、二部構造が答えを支配していることが確認され、シングリッド制約がもう存在しないという事実と一致します。
