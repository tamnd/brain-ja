 ## 解決策
 ## 問題の理解

 それぞれ整数の重みを持つ項目のコレクションが与えられます。 また、システムの開始残高のように動作する初期オフセット値もあります。 プロセスはこのオフセットから始まり、各項目は最大 1 回選択できます。 選択された各項目は、その重量によって現在の値を変更します。目標は、すべての項目を考慮した後に到達可能な合計値を理解することです。 

単一の到達可能な目標を求めるのではなく、最初のオフセットから始めて、すべての項目を処理した後に達成可能なすべての合計を特徴付け、最終結果がシステムの総質量に関して可能な限りバランスのとれた構成を見つけることがタスクとなります。 具体的には、蓄積された量を 2 つの部分に分割することを想像すると、これら 2 つの部分ができるだけ近くなることが望まれ、不均衡をそれらの間の絶対差として測定します。 

入力サイズは十分に小さいため、合計に対する擬似多項式動的計画法が実行可能です。 重要な隠れた制約は、すべての値とオフセットの合計によって DP 範囲が決まるということです。 これにより、指数サブセットの列挙が即座に除外されます。これは 2^n として増大し、n が 40 付近であっても実行不可能になります。 

すべての値がゼロである場合、またはオフセットが他のすべての値よりも大きい場合には、微妙な特殊なケースが発生します。 たとえば、配列が [0, 0, 0] でオフセットが 5 の場合、すべてのサブセットが同じ合計を生成するため、答えは 5 になる必要があります。オフセット状態を考慮せずに DP を誤って初期化する単純な実装では、合計 0 のみが到達可能であると誤って結論付ける可能性があります。 

大きな値が 1 つある場合には、別の特殊なケースが発生します。 x = 10 および a = [7] の場合、到達可能な合計は 10 と 17 のみです。最適な分割はこれら 2 つの極端な値の間にあり、有効な開始合計としてオフセットを使用して DP を初期化するのを忘れると、基本構成が完全に失われることになります。 

## アプローチ

 この問題を直接考える方法は、項目のすべてのサブセットを列挙することです。 サブセットごとに、オフセットから開始して結果の合計値を計算し、この合計が全体の合計の半分にどの程度近いかを計算します。 これは、考えられるすべての組み合わせを探索するため正しいですが、本質的には指数関数的です。 n 項目の場合、これには 2^n 個のサブセットを評価する必要があり、各サブセットの合計を計算するだけでも O(n) がかかり、O(n・2^n) となり、小さな制限を超えると不可能になります。 

重要な観察は、これが構造的にサブセット合計の到達可能性の問題であるということです。 サブセットを明示的に列挙する代わりに、考えられるすべての合計に対してブール状態を維持します。 状態 dp[s] は、項目のいくつかのプレフィックスを処理した後に合計 s を達成できるかどうかを表します。 各項目は 0 から 1 のナップザック遷移として機能し、項目を含めるか除外し、それに応じて到達可能な合計を更新します。 

重要な点は、初期状態がゼロではなく、指定されたオフセット x であることです。 これにより、DP ドメイン全体がシフトされます。つまり、到達可能なすべての合計がこの開始点の周りに集中することになります。 すべての到達可能な合計が計算されると、最後のタスクは、合計累積値の 2 つの部分間の差を最小化する到達可能な合計を見つけることになります。 

これにより、問題は指数列挙から和の範囲にわたる擬似多項式 DP に軽減されます。これは、すべての要素の和が状態空間を制限するため許容可能です。

 ## アルゴリズムのチュートリアル

 ## 1. 可能な合計の合計範囲を計算します。

まずすべての要素の合計を計算し、オフセットを追加して到達可能な最大値を定義します。 これにより DP 境界が定義されます。 この範囲を制限しないと、DP テーブルがどのくらいの大きさでなければならないか分からず、遷移が未定義になります。 

## 2. DP テーブルの初期化

 dp[s] が合計 s に到達可能かどうかを示すブール DP 配列を作成します。 到達可能な初期状態はオフセット値だけです。これは、項目を取得する前の現在の合計が正確に開始オフセットであるためです。 

この初期化は、サブセット合計の問題をゼロからシフトするため、ソリューション全体の中で最も重要なモデリング ステップです。 

## 3. 0-1 ナップザック トランジションを使用して各アイテムを処理する

 項目ごとに、前の状態に基づいて新しい DP 配列を計算します。 和 j が到達可能であれば、次の状態では j + a[i] が到達可能になります。 前の DP をコピーして「アイテムを取得しない」という選択肢を保存し、前方遷移を適用します。 

これにより、各レイヤーは前のレイヤーから構築されるため、各アイテムが最大 1 回使用されることが保証されます。 

## 4. 最適なバランスのパーティションを抽出する

 すべての項目を処理した後、到達可能なすべての合計をスキャンします。 到達可能な合計のそれぞれについて、それをパーティションの片側として解釈し、合計に対する不均衡を計算します。 答えは最小絶対差です。 

## なぜ機能するのか

 すべてのステップで、 dp[s] は、オフセットから始まる処理済みアイテムのサブセットを使用して達成可能な合計のセットを正確に表します。 すべての新しい状態は現在の項目を除外または含めることによって形成され、他の操作は不可能であるため、遷移は正確さを維持します。 すべてのサブセットは DP で暗黙的に表現されるため、到達可能な状態の最終スキャンは、明示的に列挙することなく、すべてのサブセットを評価することと同等になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    total = sum(a) + x

    dp = [False] * (total + 1)
    dp[x] = True

    for w in a:
        ndp = dp[:]
        for s in range(w, total + 1):
            if dp[s - w]:
                ndp[s] = True
        dp = ndp

    ans = float('inf')
    for s in range(total + 1):
        if dp[s]:
            ans = min(ans, abs(total - 2 * s))

    print(ans)

if __name__ == "__main__":
    solve()
```DP 配列のサイズは、最初に 1 回計算される、達成可能な合計範囲全体によって決まります。 初期化 dp[x] = True は、システムをオフセット状態に固定します。 

遷移ループはコピーされた配列を使用して、各項目が 1 回だけ適用されるようにします。 よくある間違いは、dp をインプレースで更新することです。これにより、1 回の反復内で同じアイテムを複数回使用できるようになります。 

最後に、スキャンは、到達可能な各合計を潜在的な分割点として扱うことにより、最小の不均衡を計算します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n・S) | 各アイテムは DP 範囲にわたってフル スキャンを 1 回実行します。 
| スペース | O(S) | 到達可能なすべての合計を合計した DP 配列 |

 値 S は、すべての入力重みにオフセットを加えた合計です。 これは通常、n・S が数億回以下の操作内に収まるように制限され、最適化された Python または C++ でこのソリューションが受け入れられるようになります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    total = sum(a) + x
    dp = [False] * (total + 1)
    dp[x] = True

    for w in a:
        ndp = dp[:]
        for s in range(w, total + 1):
            if dp[s - w]:
                ndp[s] = True
        dp = ndp

    ans = float('inf')
    for s in range(total + 1):
        if dp[s]:
            ans = min(ans, abs(total - 2 * s))

    return str(ans)

# minimal case
assert run("1 0\n0\n") == "0"

# offset dominates
assert run("1 10\n0\n") == "10"

# simple partition
assert run("3 5\n1 2 3\n") == "0"

# two-element split
assert run("2 4\n5 1\n") == "0"

# all equal values
assert run("4 3\n2 2 2 2\n") == "1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 0 / 0 | 0 | ゼロのみのベースライン |
 | 1 10 / 0 | 10 | オフセット優位性 |
 | 3 5 / 1 2 3 | 0 | 完璧なパーティションケース |
 | 2 4 / 5 1 | 0 | 混合到達可能スプリット |
 | 4 3 / 2 2 2 2 | 1 | 対称性とパリティの制約 |

 ## 特殊なケース

 重要なエッジケースは、すべての要素がゼロの場合です。 この場合、DP は初期状態を超えて拡張することはありません。 入力用`n=3, x=7, a=[0,0,0]`、dpは残ります`{7}`全体を通して、そして最終的な答えは`|7 - 7| = 0`、不均衡の変化がないことを正しく示しています。 

もう 1 つのエッジ ケースは、オフセットが 0 で項目が 1 つだけの場合です。 入力用`n=1, x=0, a=[5]`、dpはから進化します`{0}`に`{0,5}`、最良の分割は明らかに 0 と 5 の間にあり、不均衡 5 が生成されます。DP は正しい初期条件から開始するため、両方の状態を正しく捕捉します。 

最後の微妙なケースは、大きな値が合計範囲の上限近くに集まっている場合です。 DP は反復ごとに完全なコピーを使用するため、遷移は項目ごとに分離されたままとなり、同じステップ内での再利用が防止されます。 これにより、複数の組み合わせが異なるパスを通じて同じ合計に達する可能性がある場合でも、正確さが保証されます。
