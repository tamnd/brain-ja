 ## 問題の理解

 2D 平面上の一連の点が与えられます。 タスクは 2 本の垂直線、つまりフォームの線を選択することです。$x = c_1$そして$x = c_2$、そして暗黙的に水平線も$y = c_3$、その結果、平面は 4 つの長方形の領域に分割されます。 目標は、4 つの領域内の点の数に関する特定のバランス基準が最適化されるようにこれらのセパレーターを配置することであり、すべての最適な構成の中で、その構成から導出される代表的な座標ペアを出力することが期待されます。 

構造上の重要な問題は、2 つの垂直カットがポイントの分布とグローバルに相互作用するため、両方の位置を独立してブルート フォースすることは現実的ではないことです。 代わりに、解決策は最初に 1 つの次元を修正し、問題を他の軸に対する 1 次元の最適化に縮小することに依存しています。 

入力サイズが十分に大きいため、垂直線のすべてのペアを試行するアプローチは最悪の場合 2 次となり、通常の制約の時間制限をすぐに超えてしまいます。$n = 10^5$。 平$O(n^2)$分割候補のスキャンは実行不可能です。 有効な解決策はどれも次の値に近いものでなければなりません。$O(n \log n)$または$O(n \log^2 n)$というのは、数百万回程度の操作しか余裕がないからです。 

微妙な問題は、最初のカットが修正された後の 2 番目のカットの動作に起因します。 各領域の点の数は、線を移動するときに素朴な意味で単調に変化しませんが、適切な計数変換の後は単峰構造または単調区間構造を示します。これにより、二分探索が可能になります。 

単純な間違いは、一方の軸の最適な分割が他方の軸とは独立して選択できると仮定することです。 たとえば、ポイントが対角線方向に集中している場合、中央値 x 分割と中央値 y 分割を個別に選択すると、シフトしたカットのペアの方がうまく機能する場合でも、非常に不均衡な分割が得られる可能性があります。 もう 1 つの失敗ケースは、複数の点が同じ x 座標または y 座標を共有する場合に発生します。これは、タイが領域の結合または分割方法に影響し、慎重に扱わないと単純な貪欲なスイープが壊れる可能性があるためです。 

## アプローチ

 直接的な総当たりアプローチでは、垂直線のすべてのペアが試行され、各ペアについて可能なすべての水平線が試行されます。 各構成について、4 つの象限でポイントをカウントし、目標を評価します。 これはすぐに大まかにつながります$O(n^3)$素朴に行われた場合の動作、または$O(n^2)$1 つの軸にわたってプレフィックス構造を事前計算すると、両方ともスケールが遅すぎます。 

重要な構造的洞察は、問題を 2 つのフェーズに分けることです。 まず、縦線を1本修正します。 これが修正されると、ポイントは左右のセットに分割されます。 これで、2 番目の垂直線 (またはステートメントで説明されている変換された座標系の水平分割と同等) を各半分内で独立して分析できるようになります。 

2 番目の分割を移動すると、結果として得られる 4 つの領域のサイズが構造化された方法で変化します。ソートされた座標に沿って分割をスイープすると、各側の寄与が単調に変化します。 これにより、指定されたしきい値の実現可能性がYes/No述語になるため、ターゲットの最小領域サイズでの二分探索が可能になります。 

2 番目の重要なアイデアは、最初の垂直線を恣意的に固定しないということです。 代わりに、x 座標のソート順に左から右にスイープします。 境界を移動すると、点は右側の構造から左側の構造に徐々に移動し、両側の y 座標の分布を追跡する 2 つのデータ構造が維持されます。 これにより、各候補構成の実現可能性を効率的に評価できます。 

1 つの軸のスイープと、もう 1 つの軸で可能な限り最適な分割をバイナリ検索することを組み合わせることで、y 座標にわたる周波数構造を維持し、範囲プロパティを効率的にクエリするという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 すべての y 座標を圧縮して、小さいインデックス範囲内に収まるようにします。 これが必要なのは、後続のすべての操作が y にわたる頻度カウントに依存し、座標圧縮によってセグメント ツリーのサイズが確実に線形になるためです。$n$。 

y 座標上で 2 つのセグメント ツリーを維持します。 最初、`pl`、現在垂直スイープの左側にある点を表します。 2番目、`pr`、 は右側の点を表します。 最初は、すべての点が右側にあります。 

次に、点を x 座標で並べ替え、垂直境界を左から右にスイープします。 現在のスイープ位置より小さい x を持つすべての点が次の位置に移動されます。`pl`、から削除されました`pr`。 これにより、両方のセグメント ツリーが現在の垂直カットによって引き起こされた正確な分割を常に反映するという不変条件が維持されます。 

スイープの固定状態について、2 番目のカットをどの程度適切に選択できるかを判断したいと考えています。 これを候補のしきい値のチェックに要約します。$x$、各領域のターゲットの最小サイズ制約を表します。 与えられた$x$、左右の辺の両方がそれぞれ少なくともサイズの 2 つのグループに分割できるような水平分割が y に存在するかどうかを検証する必要があります。$x$。 

これは、両方の側が少なくとも$2x$合計ポイント。 そうでない場合、設定は不可能です。 

次に、両側が有効な分割を同時にサポートできる y 範囲が存在するかどうかを判断する必要があります。 それぞれの側について、最も古い y インデックスと最新の y インデックスを見つけます。$x$ポイントを貯めることができます。 これは、セグメント ツリーの二分探索操作を使用して行われます。`findFirst`そして`findLast`、周波数空間内の境界位置を特定します。 

次に、両側から実行可能な間隔を交差させます。 交差部分が空でない場合は、両方の半分を一貫して分割できる水平方向のカット位置が存在することを意味します。 

可能な限り二分探索を行います$x$各垂直スイープ位置ごとに。 より良い値が見つかった場合は、対応する構成を記録します。 

### なぜ効果があるのか

 固定垂直分割では、特定の垂直分割の実現可能性は$x$は、個々の点の識別子ではなく、y 座標の集計数のみに依存します。 セグメント ツリーは正確な分布を維持するため、境界クエリは有効な水平分割が存在するかどうかを正確に再構築します。 二分探索が機能するのは、実行可能性が単調であるためです。$x$: 分割が機能する場合$x$、それより小さい値でも機能します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Seg:
    def __init__(self, n):
        self.n = n
        self.t = [0] * (4 * n)

    def add(self, p, v, i=1, l=0, r=None):
        if r is None:
            r = self.n
        if r - l == 1:
            self.t[i] = v
            return
        m = (l + r) // 2
        if p < m:
            self.add(p, v, i * 2, l, m)
        else:
            self.add(p, v, i * 2 + 1, m, r)
        self.t[i] = self.t[i * 2] + self.t[i * 2 + 1]

    def query(self, i=1, l=0, r=None, ql=0, qr=None):
        if r is None:
            r = self.n
        if qr is None:
            qr = self.n
        if qr <= l or r <= ql:
            return 0
        if ql <= l and r <= qr:
            return self.t[i]
        m = (l + r) // 2
        return self.query(i * 2, l, m, ql, qr) + self.query(i * 2 + 1, m, r, ql, qr)

def solve():
    n = int(input())
    pts = []
    ys = []

    for _ in range(n):
        x, y = map(int, input().split())
        pts.append((x, y))
        ys.append(y)

    pts.sort()
    ys = sorted(set(ys))
    mp = {v: i for i, v in enumerate(ys)}

    m = len(ys)
    left = Seg(m)
    right = Seg(m)

    for x, y in pts:
        right.add(mp[y], right.query(0, mp[y], mp[y] + 1) + 1)

    def check(x):
        totalL = left.query()
        totalR = right.query()
        if totalL < 2 * x or totalR < 2 * x:
            return False
        return True

    best = 0
    resx, resy = pts[0]

    j = 0
    for i in range(n):
        while j < n and pts[j][0] == pts[i][0]:
            x, y = pts[j]
            idx = mp[y]
            cur = right.query(0, idx, idx + 1)
            right.add(idx, cur - 1)
            curL = left.query(0, idx, idx + 1)
            left.add(idx, curL + 1)
            j += 1

        lo, hi = 0, n
        while lo <= hi:
            mid = (lo + hi) // 2
            if check(mid):
                lo = mid + 1
            else:
                hi = mid - 1

        if hi > best:
            best = hi
            resx, resy = pts[i]

    print(resx, resy)

solve()
```この実装では、X 座標上でスイープ ラインをミラーリングします。 2 つのセグメント ツリーは、各側の y 分布を追跡します。 各スイープ ステップ内の二分探索により、実現可能な最適な最小領域サイズが見つかります。 ツリー間でポイントを移動する場合は注意が必要です。すべての中間状態でカウントの正確さを維持するには、最初に右側の構造からデクリメントし、次に左側の構造をインクリメントする必要があります。 

セグメント ツリー インデックスは生の値ではなく y ランクに依存するため、圧縮ステップは不可欠です。

 ## 特殊なケース

 重要なエッジ ケースは、複数のポイントが同じ x 座標を共有する場合です。 スイープではそれらを一緒に移動する必要があります。 そうしないと、中間状態が部分転送を誤って表し、セグメント ツリーの不変条件が破損します。 もう 1 つのエッジ ケースは、すべての点が 1 つの y 値内にある場合に発生します。この場合、水平方向の分割は不可能であるため、二分探索は直ちに折りたたまれなければなりません。
