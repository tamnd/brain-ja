 ## 解決策
 ## 問題の理解

 一連の数値が与えられ、その中のすべての増加部分列に依存するグローバル値を計算するように求められます。 それぞれの有効なサブシーケンスは、それに含まれる各要素の寄与に分解できる何かに寄与しており、タスクは最終的に、すべての要素について、「特定の構造的役割で使用する」増加するサブシーケンスの数とその値を乗算して合計することに帰着します。 

重要な隠された構造は、増加するすべてのサブシーケンスが中間の特定の要素に「固定されている」と考えることができるということです。 要素を修正したら、サブシーケンスを 2 つの独立した部分に分割できます。1 つはその要素で終わる有効な増加サブシーケンス、もう 1 つはその要素から始まる有効な増加サブシーケンスです。 その要素の最終的な寄与は、その左側の部分を構築する方法の数と、その右側の部分を構築する方法の数の積に、要素自体の値を乗じたものになります。 

入力は単なる整数のリストです。 出力はモジュラスに基づく単一の整数であり、上で説明した合計加重カウントを表します。 

この制約は、シーケンスの長さが十分に大きいため、サブシーケンスの二次列挙が不可能であることを意味します。 増加するサブシーケンスを明示的に列挙しようとしたり、ネストされたループを使用して要素ごとにサブシーケンスをカウントしようとしたりするアプローチは、制限時間を超えてしまいます。 唯一の実行可能な方向は、対数更新を伴う線形または線形に近い方法であり、通常は値を圧縮した後にフェンウィック ツリーまたはセグメント ツリーを使用します。 

微妙な落とし穴は、長さ 1 の部分列も有効であることを忘れていることです。 すべての要素について、その左と右の両方の寄与に空の選択肢が含まれているため、両方向に基本値 1 が追加されます。 

## アプローチ

 直接的なアプローチでは、増加するすべてのサブシーケンスを列挙し、サブシーケンスごとにその寄与をその内部のすべての要素に分配しようとします。 これは概念的には正しいですが、計算的には実行不可能です。 最悪の場合のサブシーケンスの数は指数関数的であり、要素ごとの寄与を追跡する場合でも、依然として指数関数的に多くの構造を反復する必要があります。 

中心的な観察は、各要素の役割をピボットとして固定すると、サブシーケンスの寄与がその要素全体にわたって乗算的に分解できるということです。 固定要素の場合、それが出現する有効なサブシーケンスは 2 つの独立した選択肢に分割できます。つまり、厳密に小さい要素とその前の要素を選択する方法と、厳密に大きい要素とその後ろの要素を選択する方法です。 この独立性は、位置に対する動的プログラミングと、値の順序に対する効率的なプレフィックスとサフィックスの集約を組み合わせたものであることを示唆しています。 

要素ごとに 2 つの量を計算します。 1 つ目は、その要素で終わる増加するサブシーケンスの数です。 これは、より小さい値を持つその前の要素にのみ依存します。 2 番目は、その要素から始まる増加するサブシーケンスの数であり、より大きな値を持つその後の要素のみに依存します。 必要なのは DP 値のプレフィックスとサフィックスの合計だけであるため、圧縮された値に対してフェンウィック ツリーを使用して両方を計算できます。 

両方の配列が計算されると、各要素はその左と右のカウントとその値の積に寄与します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | フェンウィック DP 分解 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題は、値の圧縮、左の寄与の計算、右の寄与の計算、結合という 3 つの概念フェーズで処理されます。

1. まず、すべての値を密な範囲に圧縮します。 これが必要なのは、フェンウィック ツリーがインデックスに対して動作し、実際の大きさではなく相対的な順序のみを考慮するためです。 圧縮後、「未満」などの比較は接頭辞クエリになります。 
2. 左側の寄与配列を計算します。 左から右に繰り返します。 各位置 i について、現在の値より厳密に小さい値で終わる有効なサブシーケンスがいくつあるかをクエリします。 このクエリは、より早く終了する増加するサブシーケンスを拡張するためのすべての可能な方法を提供します。 要素自体から構成されるサブシーケンスを考慮して 1 を追加します。 次に、この値をフェンウィック ツリーの圧縮されたインデックスに挿入し、将来の要素で使用できるようにします。 
3. 対称的に正しい寄与配列を計算します。 右から左に繰り返していきます。 各位置 i について、現在の値より厳密に大きい値で始まるサブシーケンスがいくつあるかをクエリします。 ここでも、単一要素のサブシーケンスに 1 つ追加します。 途中でフェンウィックツリーに挿入します。 
4. 結果を結合します。 各要素 i について、その合計寄与率は left[i] と right[i] を乗算し、さらに圧縮前の要素の元の値を乗算します。 

この要素がピボットとして選択される有効なサブシーケンスは、左側の部分と右側の部分を個別に選択することによって形成されるため、乗算が表示されます。 

### なぜ効果があるのか

 フェンウィック ツリーは、すべての位置で、これまでに処理された各値インデックスで終了する (または開始する) 有効な増加サブシーケンスの総数を格納します。 DP 遷移は、増加するサブシーケンスが左側で最後に選択された値と右側で最初に選択された値によって完全に決定されるという事実に依存しています。 ピボットが固定されると、これらの選択肢は独立するため、積の分解は有効になります。 各サブシーケンスには、最終的な合計で「中間の寄与ソース」としてカウントされる一意のピボット要素があるため、サブシーケンスは二重にカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        i += 1
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        res = 0
        while i > 0:
            res += self.bit[i]
            i -= i & -i
        return res

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l)

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    vals = sorted(set(a))
    mp = {v: i for i, v in enumerate(vals)}
    a = [mp[x] for x in a]

    m = len(vals)

    left = [0] * n
    right = [0] * n

    fw = Fenwick(m)

    for i in range(n):
        left[i] = fw.sum(a[i]) + 1
        fw.add(a[i], left[i])

    fw = Fenwick(m)

    for i in range(n - 1, -1, -1):
        right[i] = fw.sum(m) - fw.sum(a[i] + 1) + 1
        fw.add(a[i], right[i])

    ans = 0
    for i in range(n):
        ans += left[i] * right[i] * vals[a[i]]

    print(ans)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、同じ構造で異なるトラバース方向で 2 回使用されています。 左側のパスでは、プレフィックスの合計により、以前の小さな要素からの寄与が蓄積されます。 右側のパスでは、接頭辞の減算を逆にして、接尾辞の動作がシミュレートされます。 

の`+1`各要素だけで有効なサブシーケンスを形成し、それがないと DP はスタンドアロン シーケンスではなく拡張子のみをカウントするため、両方のパスの term は必須です。 

## 実用的な例

 小さな配列を考えてみましょう`[1, 2, 1]`。 圧縮後もそのまま残ります`[0, 1, 0]`。 

左側のパスでは、段階的に処理します。 

| 私 | 値 | フェンウィック州 (概念的) | 左[i] |
 | --- | --- | --- | --- |
 | 0 | 0 | 空 | 1 |
 | 1 | 1 | 0 | からのシーケンスが含まれます。 2 |
 | 2 | 0 | 以前の投稿が含まれています | 1 |

 インデックス 1 では、0 で終わるサブシーケンスを拡張でき、2 つの可能性があります。 インデックス 2 では、前の 1 はそれより小さい値まで拡張できないため、自明なサブシーケンスのみが存在します。 

右のパスでは:

 | 私 | 値 | 利用可能な将来情報 | 右[i] |
 | --- | --- | --- | --- |
 | 2 | 0 | 空 | 1 |
 | 1 | 1 | 右に 0 だけ | 2 |
 | 0 | 0 | すべての将来が含まれます | 1 |

 寄与を結合すると、正しいピボット分解により、増加するすべてのサブシーケンスにわたって正しい重み付きカウントが得られます。 

ここで考えてみましょう`[3, 1, 2]`、に圧縮`[2, 0, 1]`。 左側の DP は、小さい値の後に大きい値に遭遇した場合にのみ増加します。これは、順序が寄与フローをどのように制御するかを示しています。 右側の DP は、この動作を反対側から反映しています。 

これらのトレースは、各要素の寄与が絶対的な位置ではなく、その前後の相対的な順序にのみ依存することを確認します。

 ## 特殊なケース

 重要なエッジケースは、すべての要素が同一である場合です。 その状況では、増加するすべてのサブシーケンスは長さ 1 のみを持つことができるため、各要素は独立して寄与します。 両方の DP 配列はすべての位置で 1 と評価される必要があり、最終的な答えはすべての要素の合計になります。 フェンウィック ツリーはこれを正しく処理します。これは、厳密に小さいか大きい要素がないため、すべてのプレフィックスおよびサフィックス クエリは 0 を返し、ベース +1 が優先されます。 

もう 1 つの微妙なケースは、厳密に降順です。 ここでは、前の要素より小さいものはないため、左のすべての DP 値は 1 のままです。 右側では、対称性によって同じ結果が得られます。 これにより、順序付け制約が遷移をブロックするときに、アルゴリズムが誤って無効なサブシーケンスを拡張しようとしないことが確認されます。
