 ## 問題の理解

 このタスクは基本的に 2 つの整数間の直接比較です。 各テスト ケースは 2 つの数値を提供し、出力はそれらの相対的な順序にのみ依存します。 両方の値が同じ場合、結果は引き分けになります。 最初の値が大きい場合、1 人の参加者が勝ちます。 それ以外の場合は、他の参加者が勝ちます。 

アルゴリズムの観点から見ると、2 つの数値を読み取って比較する以外に処理する構造がないため、入力サイズは無関係です。 問題に多くのテスト ケースがあったとしても、それぞれのテスト ケースは依然として独立しており、一定時間の作業のみが必要です。 

各操作は単純な比較と出力の決定であるため、非常に大きな入力でもパフォーマンスが脅かされることはありません。 不要な解析オーバーヘッドや余分なデータ構造を回避するソリューションは、制限内で快適に実行できます。 

唯一の微妙なエッジケースは平等です。 明示的に等価性を処理せずに、大なり小なりのみをチェックする単純な実装では、誤って論理分岐を通過し、誤った出力またはデフォルトの動作が生成される可能性があります。 たとえば、両方の数値が等しく、プログラムがチェックのみを行う場合、`a > b`そうしないと、固定敗者が出力され、引き分けを宣言する代わりに誤って勝者が割り当てられてしまいます。 

Example of correct behavior:

 入力:`5 5`出力：`Pingju`不注意な条件連鎖により、これが「else」ケースとして扱われる可能性があります。`a > b`、平等であると認識せず、勝者を誤って出力します。

 ## アルゴリズムのチュートリアル

 1. 2 つの整数を読み取る`a`そして`b`入力から。 これらは 2 人の競合他社のスコアまたは値を表します。 
2. かどうかを確認します。`a`に等しい`b`。 完全に一致する場合は出力します`"Pingju"`、どちらの側にも利点がないためです。 
3. 等しくない場合は、直接比較します。 もし`a > b`、出力`"Liang"`。 
4. それ以外の場合は、`a < b`ので、出力します`"Chuang"`。 

決定の構造により、比較を順序付ける前に等価性が確実に処理され、曖昧さが防止されます。 

### なぜ効果があるのか

 この問題は、等価性の特殊なケースを使用した 2 つの値の全順序比較を定義します。 整数のすべてのペアは次のいずれかを正確に満たさなければならないため、`a == b`、`a > b`、 または`a < b`、分岐ロジックは入力空間を重複することなく完全に分割します。 各分岐は 1 つの有効な結果に正確に対応し、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())
    if a == b:
        print("Pingju")
    elif a > b:
        print("Liang")
    else:
        print("Chuang")

if __name__ == "__main__":
    solve()
```このソリューションは、入力の 1 行を読み取り、すぐに 2 つの整数を解析します。 比較の順序は重要です。厳密な不等式の分類に当てはまらない唯一のケースであるため、最初に等価性をチェックする必要があります。 

出力文字列は固定されており、比較結果のみに依存します。 追加のフォーマットや計算は必要ありません。

 ## 特殊なケース

 等しいかどうか、アルゴリズムは明示的にチェックします。`a == b`不等号ロジックの前に。 入力用`5 5`、実行は等価分岐ですぐに停止し、出力されます。`"Pingju"`。 

負の数の場合は入力を考慮してください`-3 -10`。 比較は引き続き正常に動作します。`-3 > -10`したがって、アルゴリズムは大なり分岐に到達し、出力します。`"Liang"`。 整数の順序付けもマイナスよりも合計であるため、特別な処理は必要ありません。 

次のような大きな値の場合`10^9 10^9`、等価性でも最初の分岐がトリガーされ、境界の大きさであっても正しい描画動作が保証されます。
