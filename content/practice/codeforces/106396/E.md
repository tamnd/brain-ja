 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの整数配列が与えられています。 各位置には数値のペアが含まれており、ユークリッド減算を繰り返すのと同様に、本質的には小さい値を減算することで大きい値を置き換え続ける特定のリダクション演算を実行できます。 

このプロセスは、安定するまで構造全体に適用できます。目標は、すべての位置でこのような削減をすべて完全に実行した後に達成できる最終値を決定することです。 

動的プロセス全体を追跡する代わりに、タスクは、許可されたすべての操作が最適に適用された後のシステムの最終的に到達可能な状態を要約する単一の整数を計算することです。 

このステートメントは繰り返しの変換という観点から表現されていますが、重要な出力は、2 つの配列の対応する要素間の関係から導出される 1 つの数値にすぎません。 

制約の観点から見ると、入力サイズが十分に大きいため、説明した繰り返し減算プロセスのシミュレーションが非常に遅くなる可能性があります。 各リダクション ステップを文字通りシミュレートする単純なアプローチでは、操作ごとに線形リダクションに低下する可能性があり、多くの要素にわたって集約されると二次関数またはさらに悪い動作が発生する可能性があります。 

唯一の実行可能な解決策は、繰り返された変換をインデックスごとの直接算術計算に圧縮し、それらの結果を線形時間で結合する必要があります。 

対応する要素間の差異がすべてゼロの場合、微妙なエッジ ケースが発生します。 その状況では、すべてのペアはすでにバランスが取れており、答えは明らかにゼロになるはずです。 アキュムレータを誤って初期化するか、絶対値をスキップする単純な実装では、誤った負の結果または初期化されていない結果が生成される可能性があります。 たとえば、すべてのペアが同一である場合、次のようになります。`a = [5, 5]`そして`b = [5, 5]`、正しい出力は次のとおりです。`0`、未定義または残りのアキュムレータ値ではありません。 

もう 1 つの特殊なケースは、違いが大きく異なる場合です。たとえば、`a = [1, 100]`そして`b = [50, 0]`。 共有不変式を介してペアを結合せずにペアを独立して扱う不用意なアプローチでは、すべてのペアを結び付けるグローバル構造を見逃すことになります。 

## アプローチ

 ブルートフォース解釈は、問題で説明されている文字通りのプロセスに従います。 各ペアについて、ペアが安定するまで、大きい値と小さい値の間で減算を繰り返し適用します。 これは本質的に、各ペアに独立して適用されるユークリッド アルゴリズムです。 ただし、減算の繰り返しとして直接実装した場合、各ステップは最悪の場合でも値を 1 単位しか減らすことができないため、単一のペアでは値の大きさに線形時間がかかる可能性があり、多くのペアではこれは計算上実行不可能になります。 

重要な観察は、減算を繰り返しても 2 つの数値間の差の最大公約数が変化しないことです。 各ペア`(a[i], b[i])`効果的に価値に貢献する`|a[i] - b[i]|`、許可されたすべての操作は、システム全体で gcd 構造を保持します。 操作をシミュレートする代わりに、絶対的な差を計算し、その gcd を取得できます。 これが機能するのは、変換ルールが差にすでに存在する素因数の外に新しい素因数を導入することがなく、減算を繰り返すと、gcd に収束する Euclid のアルゴリズムとまったく同じように動作するためです。 

したがって、プロセス全体は、すべてのペアごとの差に対して単一の gcd を計算することに集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n * 最大値) | お(1) | 遅すぎる |
 | 差異の GCD | O(n log V) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 システム全体を、すべてのインデックス ペアにわたる単一の不変式を計算することに還元します。 

1. 2 つの配列のすべての要素を読み取ります。 各位置は、絶対値ではなく関係が重要となるペアを定義します。 これにより、個人の価値観から差異へと焦点が移ります。 
2. 各インデックスについて、ペアの値間の絶対差を計算します。 減算演算では方向が消去され、ユークリッド縮小プロセスでは大きさのみが重要となるため、符号は無関係です。 
3. 実行中の gcd アキュムレータをゼロに初期化して維持します。 ゼロから開始すると、最初に計算された差によってバイアスなしで gcd が完全に初期化されます。 
4. 現在の値と次の絶対差の間の gcd を取得することにより、アキュムレータを繰り返し更新します。 これにより、各ペアによって課される制約が単一の一貫した値に徐々にマージされます。 
5. すべてのインデックスを処理した後、最終的な gcd 値を答えとして出力します。 

正しさは、各ペアが「最終的に達成可能な値はこの差を除算する必要がある」という形式の制約に寄与するという事実から得られます。 gcd はまさに、そのような制約をすべて同時に満たす最も強い数です。 

## Python ソリューション```python
import sys
import math

def solve():
    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))
    b = list(map(int, sys.stdin.readline().split()))
    
    ans = 0
    for i in range(n):
        ans = math.gcd(ans, abs(a[i] - b[i]))
    
    print(ans)

def run(inp: str) -> str:
    import io
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import sys as _sys
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    sys.stdin = old_stdin
    return out.getvalue().strip()
```このソリューションでは、まず配列と両方のシーケンスのサイズを読み取ります。 次に、絶対差に対して実行中の gcd を計算します。 の使用`math.gcd`大きな入力でも効率的なリダクションが保証され、アキュムレータをゼロで初期化すると、特別なケースを使用せずに最初の要素が正しく処理されます。 

関連する唯一の状態は進化する gcd であるため、この構造では中間の変換された配列の保存が回避されます。

 ## 特殊なケース

 すべてのペアが同一の場合、すべての差はゼロになります。 入力用`a = [7, 7, 7]`そして`b = [7, 7, 7]`、アルゴリズムは差を計算します`[0, 0, 0]`。 gcd アキュムレータはゼロから始まり、各ステップの後もゼロのままで出力を生成します。`0`。 これは、リダクションが必要なく、正の不変式が出現できないという事実と一致します。 

多数のゼロの中に 1 つの非ゼロの差がある場合、次のようになります。`a = [10, 10, 17]`そして`b = [10, 10, 11]`、違いは次のようになります`[0, 0, 6]`。 アキュムレータは最後のステップまでゼロのままで、最終ステップでは次のようになります。`6`これは、自明ではない制約が 1 つだけ存在することを正しく反映しています。 

すべての差異が公約数を共有する場合、たとえば`a = [2, 8, 14]`そして`b = [0, 2, 8]`、違いは次のとおりです`[2, 6, 6]`。 gcd は次のように進化します。`2 → 2 → 2`、不変式が累積下で安定していること、および gcd 集計を超えてインデックス間に隠れた相互作用が存在しないことが確認されます。
