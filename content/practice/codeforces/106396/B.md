 ## 解決策
 ## 問題の理解

 重み付けされた無向グラフが与えられます。 各エッジは 2 つの頂点を接続し、コストを伴います。 タスクは、選択したエッジの重みの合計を最大化しながら、すべての頂点を接続して単一の接続された構造を形成するエッジのセットを選択することです。 すべての頂点を接続することが不可能な場合、答えは不可能であると報告する必要があります。 

この問題を別の見方で見ると、最大の総エッジ重みを持つスパニング ツリーが必要になるということです。 スパニング ツリーは、すべての頂点を接続し、サイクルを含まないエッジのサブセットです。 このようなすべての有効な構造の中で、重みの合計が最大の構造が必要です。 

入力サイズが十分に大きいため、エッジのサブセットを列挙したり、接続性を繰り返し再計算しようとしたソリューションでは速度が遅すぎます。 グラフに対する一般的な Codeforce の制限に達すると、二次または指数関数的なアプローチは直ちに除外されます。 たとえ$O(n^2)$頂点の数が多く、グラフが密集している場合、エッジの数が増加する可能性があるため、この方法は遅すぎる可能性があります。$O(n^2)$最悪の場合。 

制約主導型の重要な意味は、接続性チェックには操作ごとに線形に近い方法または対数的な方法が必要であるということです。 これは、高速な結合および検索操作をサポートしているため、素のセット結合構造を直接示唆しています。 

グラフが切断されている場合、微妙なエッジケースが発生します。 たとえば、ノードが 4 つあり、エッジ (1,2) と (3,4) のみがある場合、単一のスパニング ツリーを形成する方法はありません。 素朴な貪欲選択でも両方のエッジを選択して合計を出力する可能性がありますが、構造が完全に接続されていないため、正しい出力は -1 になります。 

もう 1 つの特殊なケースは、同じ頂点のペアの間に複数のエッジが存在する場合です。 不注意な実装ではこれらを同一に扱う可能性がありますが、最適なスパニング ツリーに寄与するのは最良の組み合わせのみであるため、正しいアルゴリズムではこれらを独立して考慮する必要があります。 

## アプローチ

 この強引なアイデアは、エッジのすべてのサブセットを試し、それがスパニング ツリーを形成しているかどうかを確認し、その合計の重みを計算することです。 接続のチェックは BFS または DFS で実行でき、正確に存在することを確認します。$n-1$エッジは非循環性を保証します。 このアプローチは、すべての有効な候補構造を直接テストするため、正しいです。 ただし、エッジサブセットの数は$2^m$、それぞれの有効性チェックにコストがかかります$O(n + m)$、全体的に複雑になります$O(2^m \cdot (n + m))$これは、適度に小さなグラフでも実行不可能です。 

重要な構造的観察は、最大スパニング ツリー問題を解決しているということです。 問題は正確に選択することになります$n-1$総重量を最大化しながらすべての頂点を接続するエッジ。 これは、順序を逆にして最小化ではなく最大化することを除いて、古典的な最小スパニング ツリー問題と同じです。 

クラスカルのアルゴリズムは必要な構造を提供します。 エッジを重みの昇順に並べ替えるのではなく、降順に並べ替えます。 次に、エッジを反復処理し、素セット共用体を使用して、以前に切断されたコンポーネントを接続するエッジのみを受け入れます。 受け入れられた各エッジは 2 つのコンポーネントをマージし、合計の重みに寄与します。 この貪欲な選択が機能するのは、既に接続されている 2 つのコンポーネントを接続するエッジはサイクルを作成し、スパニング ツリー構造を改善できない一方で、合計を最大化するには利用可能な最も重いエッジを優先する必要があるためです。 

最後に、正確に使用していない場合は、$n-1$エッジでは、グラフは切断されており、スパニング ツリーは存在しません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^m \cdot (n + m))$|$O(n + m)$| 遅すぎる |
 | クラスカル (DSU) |$O(m \log m)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 頂点とエッジの数を読み取り、すべてのエッジをエンドポイントと重みを含むトリプルとして保存します。 これにより、貪欲戦略の中核である重量による並べ替えのためのデータが準備されます。 
2. すべてのエッジを重みの降順に並べ替えます。 その理由は、スパニング ツリーに含まれる可能性が最も高くなるように、重いエッジを最初に検討するためです。 
3. 各頂点が独自のコンポーネントで始まる、素の集合共用体構造を初期化します。 この構造により、エッジを追加することで 2 つの別々のコンポーネントが接続されるのか、それともサイクルが作成されるのかを迅速に判断できます。 
4. ソートされた順序でエッジを繰り返します。 各エッジについて、DSU 検索操作を使用して、そのエンドポイントが異なるコンポーネントに属しているかどうかを確認します。 それらが異なる場合は、それらをマージし、エッジの重みを答えに追加します。 それらがすでに同じコンポーネント内にある場合は、サイクルを形成するため、スキップします。 
5. 残っているコンポーネントの数のカウンターを維持します。 マージが成功するたびに、コンポーネントの数が 1 つずつ減ります。 
6. すべてのエッジを処理した後、連結成分が 1 つだけ残っているかどうかを確認します。 そうでない場合は、グラフが完全に接続可能ではなかったため、スパニング ツリーを形成できないことを意味します。 
7. グラフが接続されている場合は、累積重量の合計を出力します。 

### なぜ効果があるのか

 アルゴリズムは常に、接続されたコンポーネントのフォレストを維持します。 選択された各エッジは、その時点で 2 つの異なるコンポーネントを接続できる最大のエッジです。 これにより、接続を切断することなく、選択したエッジをより重い有効な代替物に置き換えることができなくなります。 サイクルが導入されないため、構造は常にフォレストのままであり、すべての頂点が接続されると、選択されたエッジが最大の総重みを持つスパニング ツリーを形成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

def solve():
    n, m = map(int, input().split())
    edges = []

    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((u - 1, v - 1, w))

    edges.sort(key=lambda x: x[2], reverse=True)

    dsu = DSU(n)
    total = 0
    used = 0

    for u, v, w in edges:
        if dsu.union(u, v):
            total += w
            used += 1

    if used != n - 1:
        print(-1)
    else:
        print(total)

if __name__ == "__main__":
    solve()
```DSU 構造は、接続されたコンポーネントを効率的に維持するために使用されます。 パス圧縮により、操作ごとの償却時間がほぼ一定になり、大きなグラフでもアルゴリズムの高速性が維持されます。 降順に並べ替えると、より重いエッジが最初に考慮されることが保証されます。これは総重量を最大化するために不可欠です。 

変数`used`正常に含まれたエッジの数を追跡します。 有効なスパニングツリー$n$ノードには正確に含まれている必要があります$n-1$エッジなので、これが最終的な正確性チェックです。 

## 実用的な例

 4 つのノードとエッジ (1-2, 10)、(2-3, 5)、(3-4, 7)、(1-4, 1) を持つ小さなグラフを考えてみましょう。 

降順にソートすると、エッジは (1-2, 10)、(3-4, 7)、(2-3, 5)、(1-4, 1) になります。 

| ステップ | エッジ | | の前のコンポーネント アクション | 合計 |
 | --- | --- | --- | --- | --- |
 | 1 | 1-2 (10) | {1}{2}{3}{4} | マージ | 10 |
 | 2 | 3-4 (7) | {1,2}{3}{4} | マージ | 17 |
 | 3 | 2-3 (5) | {1,2}{3,4} | マージ | 22 |
 | 4 | 1-4 (1) | {1,2,3,4} | スキップ | 22 |

 このトレースは、アルゴリズムが利用可能な最も高い接続エッジを常に選択しながらスパニング ツリーを構築する方法を示しています。 

ここで、エッジ (1-2、5) のみを持つ 3 つのノードからなる、切断されたグラフを考えてみましょう。 

| ステップ | エッジ | | の前のコンポーネント アクション | 合計 |
 | --- | --- | --- | --- | --- |
 | 1 | 1-2 (5) | {1}{2}{3} | マージ | 5 |

 処理後、ノード 3 は分離されたままになるため、結果は無効になり、出力は -1 になります。 

これは、最終的な接続チェックが不可欠であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(m \log m)$| ソートエッジが支配的で、DSU 操作はほぼ一定に償却されます。 
| スペース |$O(n + m)$| DSU アレイとエッジ リストのストレージ |

 ソートは最大数十万のエッジに対して効率的であり、DSU 操作はほぼ直線的にスケールされるため、複雑さは大規模なグラフの一般的な制約内に問題なく収まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from math import inf

    class DSU:
        def __init__(self, n):
            self.p = list(range(n))
            self.s = [1] * n

        def f(self, x):
            while self.p[x] != x:
                self.p[x] = self.p[self.p[x]]
                x = self.p[x]
            return x

        def u(self, a, b):
            a = self.f(a)
            b = self.f(b)
            if a == b:
                return False
            if self.s[a] < self.s[b]:
                a, b = b, a
            self.p[b] = a
            self.s[a] += self.s[b]
            return True

    n, m = map(int, input().split())
    e = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        e.append((u - 1, v - 1, w))
    e.sort(key=lambda x: -x[2])

    d = DSU(n)
    ans = 0
    used = 0

    for u, v, w in e:
        if d.u(u, v):
            ans += w
            used += 1

    return str(ans if used == n - 1 else -1)

 ## 特殊なケース

 単一の頂点の場合、DSU は 1 つのコンポーネントから開始され、エッジは必要ありません。 アルゴリズムがエッジ ループに意味のある形で入ることはありません。`used`ゼロのままです。 以来$n-1 = 0$、条件は満たされ、答えは 0 であり、空のスパニング ツリーの正しい定義と一致します。 

ノード 1 ～ 2 が接続され、ノード 3 が分離されているなど、切断されたグラフの場合、アルゴリズムは到達可能なコンポーネントのみをマージします。 DSU は 2 つのコンポーネントで終了するため、`used`1 になる$n-1 = 2$。 最終チェックでは結果が正しく拒否され、-1 が出力され、すべての頂点にまたがることは不可能であることが一致します。
