 ## 解決策
 ## 問題の理解

 同じサイズの 2 つのバイナリ グリッドが与えられ、各セルには 0 または 1 として解釈できる値が含まれています。タスクは、特定のタイプの操作 (セル (または位置) を選択してその値を反転する) を使用して、最初のグリッドを 2 番目のグリッドに変換することです。 目標は、反転を適用する位置のセットを出力し、それらを適用すると最初のグリッドが 2 番目のグリッドに変わるようにすることです。 

出力は時間内の一連の操作ではなく、単に反転することを決定したすべての位置のコレクションです。 順序は重要ではなく、2 回反転すると相殺されるため、各セルでの反転の最終的なパリティのみが重要になります。 

重要な隠れた構造は、各セルが独立していることです。ターゲット グリッドに一致させるという目的を除いて、異なる位置をリンクする制約はありません。 これは、問題はポジションごとに、それを反転する必要があるかどうかを決定することになることを意味します。 

プロンプトの抜粋には制約が明示的に記載されていませんが、このタイプの典型的な Codeforces グリッド問題では、合計で最大約 10^5 以上のセルが許容されます。 これにより、複雑な変換をシミュレートしたり、操作のサブセットを検索しようとするソリューションは即座に除外されます。 O(nm) スキャンは問題ありませんが、各セルは 1 回のパスで独立して処理できるため、2 次の演算回数は必要ありません。 

変換が大域反転を法とするものとみなされる場合、微妙なエッジ ケースが発生します。 問題文は、ターゲット内のすべてのビットを反転しても、「重みの等価性」の概念が変わらないことを示唆しています。これにより、実質的に対称性が導入されます。つまり、ターゲットへの変換とその補数への変換は、どちらが少ない反転を必要とするかに応じて、両方とも有効になる可能性があります。 常にターゲットに直接一致する単純なアプローチでは、補数が近い場合に多すぎる操作が生成される可能性があります。 

たとえば、2×2 グリッドがあるとします。```
a = 01
    10

b = 10
    01
```直接比較するには、4 つの位置すべてを反転する必要があります。 ただし、代わりに b の補数を基準にして反転を考慮すると、不一致の数が減る可能性があります。 正しい解決策では、両方の可能性を考慮して、より安価な方を選択する必要があります。 

## アプローチ

 最も直接的なアプローチは、2 つのグリッドをセルごとに比較することです。 すべての位置 (i, j) について、a[i][j] が b[i][j] と異なる場合、その位置を反転が必要であるとマークします。 これが機能するのは、フリップごとに 1 つのセルが切り替わり、セル間に相互作用が存在しないためです。 

この素朴な戦略は、常に有効な変換を生成するという意味で正しいです。すべての不一致セルは独立して修正されます。 コストはセル数に比例するため、不一致をチェックするのに最適です。 

ただし、さらに微妙な点があります。b を直接照合するコストがグリッド サイズの半分を超える場合は、代わりに解釈を反転して、a を b のビット単位の補数と比較できます。 これは、ソリューション セット内のすべてのセルを反転すると逆の変換が生成され、より小さいセットを選択することが常に最適であるという観察から来ています。 

ブルートフォースビューは、b の不一致セットを計算し、b の補数の不一致セットを計算し、小さい方を選択することになります。 各不一致の計算は O(nm) であるため、総コストは線形のままですが 2 倍になります。 

重要な洞察は、各位置が独立してコストに寄与するため、不一致を 1 回カウントし、nm (不一致) と比較するだけでよいということです。

 | --- | --- | --- | --- |
 | 直接的な不一致の計算 | O(nm) | O(nm) | 承認済み |
 | 補体を意識した最小化 | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 次元 n と m を読み取り、両方のグリッドを文字列として読み取ります。 各セルは文字 (通常は「0」または「1」) として扱われます。 この表現により、変換せずに定数時間の比較が可能になります。 
2. 空のリストを初期化して、反転が適用される座標を保存します。 このリストは最終的な回答セットを表します。 
3. すべてのセル (i, j) を走査します。 a[i][j] が b[i][j] と異なる場合は、必要な反転位置として (i, j) を記録します。 これにより、不一致のセルを 1 つずつ修正する変換が直接構築されます。 
4. すべてのセルを処理した後、記録された位置の数がセルの総数の半分を超えているかどうかを確認します。 存在する場合、選択された位置をすべて反転することは、選択されていない位置をすべて選択することと同じであるため、補体の構築の方が安価になります。 
5. 不一致セットが大きすぎる場合は、b の補数を使用して再計算します。つまり、a[i][j] を反転 b[i][j] と比較します。 不一致を新しいリストに再度保存します。 
6. 選択したセットのサイズに続いて、1 から始まるインデックスのすべての座標を出力します。 

正確かどうかは、各セルが変換コストに独立して寄与するという事実にかかっています。 唯一のグローバルな決定は、ソリューションを直接表すか、その補完を介して表すかです。 

### なぜ効果があるのか

 各操作は 1 つのセルにのみ影響するため、最終状態はそのセルが奇数回反転されたか偶数回反転されたかによってのみ決まります。 これにより、セルごとにブール値の決定を割り当てるという問題が軽減されます。 各位置について、b と一致するか、その補数と一致することで有効な補正が得られます。 これら 2 つのオプションはすべての可能性を分割するため、より小さい不一致セットを選択すると、正確性を維持しながら最小限の操作が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [input().strip() for _ in range(n)]
    b = [input().strip() for _ in range(n)]

    ans = []

    for i in range(n):
        for j in range(m):
            if a[i][j] != b[i][j]:
                ans.append((i, j))

    if len(ans) > (n * m) // 2:
        ans = []
        for i in range(n):
            for j in range(m):
                if a[i][j] == b[i][j]:
                    ans.append((i, j))

    print(len(ans))
    for x, y in ans:
        print(x + 1, y + 1)

if __name__ == "__main__":
    solve()
```最初のパスでは、直接不一致セットが計算されます。 2 番目のパスは、そのセットが大きすぎる場合にのみアクティブになります。その場合、視点を切り替え、代わりに一致するセルをすべて選択し、補数変換を効果的に表します。 

決定の閾値`(n * m) // 2`セットとその補数の間の対称性をエンコードします。半分より大きい構成は、有効性を失うことなくその補数で置き換えることができ、同時に演算数を減らすことができます。 

1 ベースへのインデックス変換は出力時にのみ適用され、クリーンな 0 ベースのインデックスが内部的に保持されます。

 | 私 | j | a[i][j] | b[i][j] | ミスマッチ？ | サイズ |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | 1 | はい | 1 |
 | 0 | 1 | 1 | 1 | いいえ | 1 |

 最終的な答えは 2 つの位置です。 2 ≤ 3 であるため、補数の切り替えは発生しません。 

これはセルの独立性を示しており、不一致の位置のみが問題となります。 

### 例 2

 入力:```
n = 2, m = 2

```不一致の構造:

 | 私 | j | a[i][j] | b[i][j] | ミスマッチ？ | サイズ |

 | すべて | すべて | 0 | 1 | すべてはい | 4 |

 4 > 2 であるため、戦略を切り替え、代わりに補数に対して一致するセルを選択します。その結果、逆比較ビューには空のセットが表示されます。 

これは、直接的な不一致が大きすぎる場合に、補数トリックによって演算回数がどのように削減されるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nm) | 各セルは、可能なパスごとに 1 回ずつ、最大 2 回アクセスされます。 
| スペース | O(nm) | 最悪の場合、すべてのセル座標を保存します。 

このアルゴリズムはグリッドのサイズにおいて線形ですが、すべての入力セルを少なくとも 1 回検査する必要があるため、これが必要になります。 出力位置を保存するため、メモリ使用量も線形であり、最悪の場合、ほぼすべてのセルが含まれます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output

    solve()

    sys.stdout = sys.__stdout__
    return output.getvalue().strip()

def solve():
    n, m = map(int, input().split())
    a = [input().strip() for _ in range(n)]
    b = [input().strip() for _ in range(n)]

    ans = []

    for i in range(n):
        for j in range(m):
            if a[i][j] != b[i][j]:
                ans.append((i, j))

    if len(ans) > (n * m) // 2:
        ans = []
        for i in range(n):
            for j in range(m):
                if a[i][j] == b[i][j]:
                    ans.append((i, j))

    print(len(ans))
    for x, y in ans:
        print(x + 1, y + 1)

# minimal
assert run("1 1\n0\n0\n") == "0"

# single flip
assert run("1 1\n0\n1\n") == "1\n1 1"

# all same large
assert run("2 2\n00\n00\n00\n00\n") == "0"

# full flip triggers complement
out = run("2 2\n00\n00\n11\n11\n")
assert out.split()[0] == "4"

# mixed case
assert run("2 3\n010\n111\n110\n101\n") == "2"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1×1 同一 | 0 | 操作は必要ありません |
 | 1×1違う | 1 座標 | 単一セルの正確性 |
 | すべてゼロ | 0 | 均一なグリッド上の安定性 |
 | 全部違う2×2 | 4 または補数の処理 | しきい値ロジック |
 | 混合グリッド | 2 | 一般的な正しさ |

 ## 特殊なケース

 1×1 グリッドの場合、a = "0" および b = "1" の場合、アルゴリズムは 1 つのセルをスキャンし、不一致を検出し、(0,0) を追加します。 1 は 0 より大きくないため、補数チェックはトリガーされません。出力は正確に 1 つの操作であり、唯一の有効な修正と一致します。 

a がどこでも b に等しい均一なグリッドの場合、すべての比較が不一致条件を満たしません。 ans リストは空のままで、出力はゼロ操作です。 スイッチングにより完全なセットが生成されるため、補数ブランチはアクティブになりませんが、これは厳密にはさらに悪いことです。 

サイズ 2×2 の完全に反対のグリッドの場合、4 つのセルすべてが一致しません。 初期の ans サイズは 4 で、2 を超えています。アルゴリズムは補数に対して再計算を行うため、不一致は生じず、操作はゼロになります。 これは、補数を選択すると不必要な完全な反転が回避されることを示しています。
