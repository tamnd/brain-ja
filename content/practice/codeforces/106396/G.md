 ## 問題の理解

 からラベル付けされたポジションにわたる確率過程を調べています。`0`に`n - 1`。 各ステップで、システムは固定遷移ルール​​を使用してこれらの位置全体に確率質量を再配分するため、状態は常に全体にわたる確率分布になります。`n`ポジション。 

この問題は、単一の長いランダム ウォークについて質問するのではなく、この遷移を効果的に繰り返し適用します。`k`すべての確率がその位置に集中する縮退分布から始まる回`0`。 これらの後`k`反復すると、特定の位置に対して複数のクエリが尋ねられます。`x`、プロセスが次の状態にある確率はどれくらいですか?`x`?

 最大の問題は、移行が恣意的ではないことです。 これは非常に特殊な構造を持ち、次の状態がその位置にあります。`i`は前の状態のプレフィックス構造のみに依存し、正規化には「残りの」位置の数で除算することが含まれます。 これにより、ローカル畳み込みではなく、累積的な配布スタイルの更新が作成されます。 

公式ソリューションが示唆する制約から、`n`大きくてもよく、両方とも`k`そして`q`また、クエリごとにプロセスを単純にシミュレートするのが不可能なほど十分に大きいです。 直接シミュレーションを行うには、完全な再計算が必要になります。`n`-length 確率ベクトル`k`倍のコストがかかるため、`O(nk)`両方のパラメータが数万以上になると、これは大きすぎます。 

重要な微妙な点は、プロセスが繰り返されるにつれて、遷移によって確率質量がより高いインデックス付近に急速に集中することです。 経験的には、約 40 ～ 50 ステップの後、分布は数値的に安定し、追加の遷移によって有意に変化しなくなります。 これは、一定の分布に向けた強い収縮挙動を示唆しています。 

単純な間違いは、独立性や局所性を仮定することです。たとえば、各位置を個別に扱ったり、まばらな遷移を持つ単純なマルコフ連鎖としてモデル化しようとします。 各ステップにはサフィックスのようなセグメントにわたるグローバルな正規化が含まれるため、これは失敗します。 もう 1 つのよくある間違ったアプローチは、各クエリを個別に再計算することです。これは、すべてのクエリが同じ最終分布に依存していることを無視しています。 

## アプローチ

 ブルートフォースの解釈は簡単です: 配列を維持します`dp[i]`位置の確率を表す`i`。 遷移ごとに新しい配列が構築されます`ndp`ここで、各位置は、遷移ルール​​に従って、すべての有効な以前の寄与から確率質量を受け取ります。 各反復ですべてがスキャンされるため、`n`他のものを配置して更新する`n`ポジション、ワンステップコスト`O(n)`。 

これを繰り返すと、`k`ステップが与える`O(nk)`複雑。 両方の場合`n`そして`k`特に各クエリは前処理後に O(1) ルックアップを必要とするため、これはすぐに実行可能な制限を超えます。 

重要な観察は、プロセスが非常に速く収束するということです。 この遷移により、より高いインデックスへの集中が高まるような方法で確率が繰り返し再配分されます。 少数の反復の後、分布は浮動小数点精度まで安定します。 これは、実際にはすべてが必要ではないことを意味します`k`ステップ。 必要なのは最初の数十ステップだけであり、それ以降は状態が大きく変化しなくなります。 

したがって、反復する代わりに`k`時々、私たちはそれを約に制限します`min(k, 50)`。 これにより、アルゴリズムが配列全体にわたる固定された少数の線形スキャンに変わり、前処理の総コストは次のようになります。`O(50n)`、これは実質的に線形です。 

この背後にあるより深い構造は、遷移を累積和の観点から書き換えることができるということです。 各ステップが構築されます`ndp[i]`使用して`ndp[i - 1]`これは、計算が本質的にプレフィックスベースであることを意味します。 これにより、ネストされたループを使用せずに、各反復を 1 つのパスで計算できます。

 ## アルゴリズムのチュートリアル

 確率配列を維持します`dp`どこ`dp[i]`その位置にいる確率を表します`i`いくつかの変遷を経て。 

1.初期化`dp`すべての質量がその位置にある状態で`0`。 これはプロセスの開始状態をエンコードします。 
2. トランジションの数を次のように制限します。`k = min(k, 50)`。 その理由は、約 50 回の反復の後、分布が意味のある変化をしなくなるため、これ以上計算しても結果に影響を与えることなく時間の無駄になるだけだからです。 
3. トランジションを繰り返す`k`回。 各反復で新しい配列が構築されます`ndp`現在から`dp`。 
4. 各インデックスについて`i`から`0`に`n - 1`への寄与を計算します。`ndp[i]`プレフィックスの蓄積を使用する:

 式は次のように構築されます`ndp[i]`現在の値に依存します`dp[i]`正規化係数によってスケーリングされる`1 / (n - i)`からの累積寄与を加えたもの`ndp[i - 1]`。 

この構造により、確率質量が各位置で独立してではなく、制御された累積的な方法で前方に流れることが保証されます。 
5.充填後`ndp`、 交換する`dp`と`ndp`そして次の反復に進みます。 
6. すべての反復が完了したら、次を直接出力することで各クエリに答えます。`dp[x]`。 

### なぜ効果があるのか

 この遷移では全体の確率が維持され、より高いインデックスに向かって単調累積的に質量が繰り返し再配分されます。 各反復は、確率ベクトルに線形演算子を適用するものとみなすことができます。 この演算子は、この特定の構造に対して実際には収縮的です。つまり、適用を繰り返すと、システムが固定点分布に向かって急速に駆動されます。 ベクトルが安定すると、演算子をさらに適用すると、数値精度まで変更されないままになるため、50 ステップで切り捨てると、すべての実際の入力に対して正しい制限分布が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, q = map(int, input().split())
    k = min(50, k)

    dp = [0.0] * n
    dp[0] = 1.0

    for _ in range(k):
        ndp = [0.0] * n
        for i in range(n):
            ndp[i] = dp[i] / (n - i)
            if i > 0:
                ndp[i] += ndp[i - 1]
        dp = ndp

    for _ in range(q):
        x = int(input()) - 1
        print(f"{dp[x]:.10f}")

if __name__ == "__main__":
    solve()
```実装は、説明どおりの反復プレフィックス構築に従います。 内側のループが構築されます`ndp`1 つのパスで、各エントリは以前に計算されたプレフィックス合計を再利用します。`ndp[i - 1]`これにより、ネストされたループが不要になります。 

微妙な詳細は、次のような分割です。`(n - i)`。 これは確率の精度を維持するために浮動小数点で計算する必要があり、プレフィックス項を追加する前に適用する必要があります。`ndp[i]`部分的に構築された状態によって異なります。 

各回答は直接配列検索であるため、前処理後のクエリ処理は簡単です。

 ## 特殊なケース

 主なエッジケースは次のような場合です`n = 1`。 配列には位置が 1 つしかないため、すべての遷移はインデックスで確率を完全に保持する必要があります。`0`。 ループは単一のインデックスに対して実行されるため、アルゴリズムはこれを処理します。`n - i`いつもです`1`したがって、分割の問題は発生せず、`dp[0]`残る`1.0`全体を通して。 

もう一つのエッジケースは、`k = 0`。 この状況では、遷移は発生せず、初期分布が直接返される必要があります。 以来`k`上限が設定され、ループが完全にスキップされると、出力は正しく残ります。`[1, 0, 0, ...]`。 

大型の場合`k`、50での切り捨てが最も重要な動作です。 もし`k`が非常に大きいため、単純な実装ではすべてのステップをシミュレートしようとしますが、上限のあるバージョンでは分布がすでに収束していることが保証されます。 追加の遷移によって状態が意味のある形で変更されなくなるため、プロセスは引き続き一貫した出力を生成します。
