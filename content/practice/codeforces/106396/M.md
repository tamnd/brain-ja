 ## 解決策
 ## 問題の理解

 私たちは、グラフ内のノードのように動作する要素の動的システムを扱っており、時間の経過とともにノードをより大きなコンポーネントにマージできます。 各ノードには値が含まれており、検証ステップ中にどのコンポーネントが対話できるかを定義する無向グラフもあります。 クエリの過程で、ノードのリストを繰り返し取得し、現在のマージで有効な構造を形成しているかどうかを確認し、操作タイプに応じてその値を更新しながら、そのリストを単一のマージされたコンポーネントに圧縮します。 

各クエリにより、ノードのシーケンスと操作タイプが得られます。 マージを実行する前に、シーケンスが構造的に有効かどうかを確認する必要があります。 検証は、元のノードだけでなく、以前のマージによって形成された現在の接続コンポーネントに依存します。 検証後、シーケンス内のすべてのノードが 1 つのコンポーネントにマージされ、結果のノードは、操作の種類に応じて、マージされた要素の最大値または最小値として計算された値を継承します。 時間が経つと、ノードはコンポーネントに消え、代表的なノードのみがアクティブのままになります。 

出力は、最後に残ったアクティブ ノードに格納された最終値、またはいずれかの時点で有効性チェックが失敗した場合は失敗になります。 

主な問題点は、クエリの観点から見るとグラフ構造が静的ではないことです。 ノードは繰り返しマージされるため、隣接関係はこれらのマージを効果的に尊重する必要があります。 単純な隣接表現は、慎重に更新しないとすぐに無効になってしまいます。 

構造によって暗示される制約と、繰り返されるセット操作とマージの存在は、各ノードが限られた数の高価な操作のみに参加すべきであることを示唆しています。 これは、大規模な隣接リストの繰り返しの移動を回避するヒューリスティックと組み合わせた共用体検索構造を強く示しています。 

単純なアプローチでは、クエリごとに、展開するグラフ上で BFS または DFS を使用してシーケンスに沿った接続をチェックし、隣接リストを物理的に結合することでノードをマージします。 最悪の場合、長いチェーンを繰り返しマージすると、隣接リストが何度も再処理され、二次的な動作が発生します。 

マージ後のクエリ シーケンスに同じノードが複数回出現する場合、微妙なエッジ ケースが発生します。 たとえば、ノードがすでに別のコンポーネントにマージされている可能性があるため、ノードを独立したものとして扱うと、カウントが重複したり、妥当性チェックが不正確になったりする可能性があります。 もう 1 つのエッジ ケースは、タイプ 1 クエリにサイクルが含まれる場合に発生します。この場合、シーケンスはパスではなくサイクルを形成する必要があり、終了エッジが欠けていると誤った拒否が発生します。 

## アプローチ

 ブルート フォース解釈では、各ノードがその隣接セットを明示的に維持しているものとして扱われ、各クエリが現在のグラフ上の新しい検証問題として扱われます。 すべてのシーケンスについて、DFS または BFS を使用して隣接するノードに沿ったトラバーサルをシミュレートし、現在のマージされた代表の下で遷移が有効かどうかを確認します。 検証後、すべての隣接セットを物理的に 1 つにマージし、ノード値を更新します。 

これは問題定義に直接従うため、概念的に機能します。 ただし、隣接セットを繰り返しマージするとコストがかかります。 最悪の場合、ノードの隣接リストが何度もマージされ、より大きな構造になる可能性があります。 サイズ 1 のコンポーネントをサイズ n に繰り返しマージし、各マージに隣接セットのコピーが含まれる場合、合計コストは次のようになります。$O(n^2)$これは、一般的な制約に対して遅すぎます。 

重要な洞察は、ヒューリスティック マージ戦略を使用して隣接関係の維持を効率的にできるということです。 隣接セットをやみくもにマージするのではなく、常に小さい隣接セットを大きい隣接セットにマージします。 これにより、各エッジが合計で対数的にのみ移動されることが保証されます。 コンポーネントの代表を追跡する Union-find 構造と組み合わせると、常にエンドポイントを現在の代表に解決することで隣接関係チェックに答えることができます。 

これにより、問題は、構造検証を代表者にローカルに保ちながら、効率的なメンバーシップ チェックとセット ユニオンによる進化するコンポーネントの管理に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(n + m)$| 遅すぎる |
 | 最適 (DSU + ヒューリスティック セット マージ) |$O((n + m) \log n)$償却済み |$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ノード全体にわたって素のセット和集合構造を維持し、各コンポーネント代表に対して隣接する代表のセットを維持します。 各ノードには値と、まだスタンドアロンの代表であるかマージされているかを示す「アクティブ」フラグもあります。 

各クエリについて、最初に各ノードを現在の代表に変換することにより、ノードのリストを処理します。 現在の状態でノードがすでに非アクティブまたは無効である場合、クエリは直ちに失敗します。 

1. 指定されたシーケンスについて、すべてのノードをその現在の DSU 代表にマッピングします。 これにより、古いノード ID ではなく、最新のコンポーネントで動作することが保証されます。 ノードがアクティブでなくなった場合、クエリは無効になります。 
2. クエリがタイプ 1 の場合、シーケンスが有効なサイクル構造を形成しているかどうかを確認します。 これには、すべての連続する代表が隣接構造内で接続されていることが必要であり、さらに最後の代表が最初の代表に接続し直される必要があります。 隣接関係チェックは、コストを最小限に抑えるためにエンドポイント間で小さい隣接関係リストを反復処理し、代表間に接続が存在するかどうかを確認することによって行われます。 
3. クエリがタイプ 2 の場合、シーケンスが有効なパス構造を形成しているかどうかをチェックします。 これには、終了エッジ要件なしで、連続した隣接性チェックのみが必要です。 
4. いずれかの時点で検証が失敗した場合、直ちに終了します。 
5. 検証が完了したら、マージされたノードの新しい値を計算します。 タイプ 1 では、関係するすべての値の最大値を取得します。 タイプ 2 では、最小値を採用します。 これは、クエリの種類によって異なる集計セマンティクスがどのように定義されるかを反映しています。 
6. 次に、シーケンス内のすべてのノードを単一の DSU コンポーネントに物理的にマージします。 常に小さい隣接関係セットを大きい隣接関係セットに接続し、それに応じて DSU 親ポインターを更新します。 
7. マージされたコンポーネントに新しい代表インデックスを割り当て、すべての元のノードを非アクティブとしてマークします。 
8. すべてのクエリが処理されるまで処理を続けます。 最終的には、有効成分が 1 つだけ残るはずです。 その値が答えです。 

### なぜ効果があるのか

 正確性は、各 DSU コンポーネントが他の現在のコンポーネントに対して完全かつ正確な隣接関係セットを維持し、構造チェックの前にすべてのノードが常にその代表を通じて解決されるという不変条件に基づいています。 常に小さい隣接セットを大きい隣接セットにマージするため、各隣接エントリは対数的にのみ移動され、再計算の爆発を防ぎます。 すべてのチェックは代表に対して実行されるため、古いエッジは決して観察されず、構造検証は常に現在の契約されたグラフを反映します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return a
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]
        return a

def solve():
    n, m = map(int, input().split())
    a = [0] * (2 * n)

    for i in range(n):
        a[i] = int(input())

    adj = [set() for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].add(v)
        adj[v].add(u)

    dsu = DSU(n)
    active = [True] * (2 * n)
    rep_of = list(range(2 * n))
    cur = n

    def get(u):
        return dsu.find(rep_of[u])

    def merge_sets(u, v):
        if len(adj[u]) < len(adj[v]):
            u, v = v, u
        for x in list(adj[v]):
            if x != u:
                adj[u].add(x)
        adj[v].clear()
        dsu.union(u, v)
        return dsu.find(u)

    def check(u, v):
        if len(adj[u]) < len(adj[v]):
            for x in adj[u]:
                if dsu.find(x) == v:
                    return True
        else:
            for x in adj[v]:
                if dsu.find(x) == u:
                    return True
        return False

    def chk_chain(p):
        reps = [get(x) for x in p]
        if len(set(reps)) != len(reps):
            return False
        for i in range(1, len(reps)):
            if not check(reps[i - 1], reps[i]):
                return False
        return True

    def chk_cycle(p):
        if len(p) < 3 or not chk_chain(p):
            return False
        reps = [get(x) for x in p]
        return check(reps[0], reps[-1])

    for _ in range(int(input())):
        tmp = list(map(int, input().split()))
        opt, l = tmp[0], tmp[1]
        p = [x - 1 for x in tmp[2:]]

        if opt == 1:
            if not chk_cycle(p):
                print(-1)
                return
        else:
            if not chk_chain(p):
                print(-1)
                return

        vals = [a[get(x)] for x in p]
        if opt == 1:
            new_val = max(vals)
        else:
            new_val = min(vals)

        root = get(p[0])
        for x in p:
            x = get(x)
            if x != root:
                root = dsu.union(root, x)

        a.append(new_val)

    print(a[dsu.find(0)])

    solve()
```この実装は、DSU と隣接セットのアイデアを直接反映しています。 の`get`この関数は、すべてのクエリが古いインデックスではなく現在の代表に対して確実に動作するようにするため、重要です。 サイクルとチェーンのチェックでは、代表値を比較し、シーケンス内に重複が存在しないことを確認することで、二重カウントを注意深く回避します。 

結合ステップでは、関係するすべてのコンポーネントが 1 つの DSU セットに集約されますが、隣接関係のマージは、常に小さいセットを大きいセットにマージすることによって最適化されます。 

## 実用的な例

 ノード 0、1、2 が線 0-1-2 で接続され、値が [3, 5, 2] である小さなグラフを考えてみましょう。 

[0, 1, 2] に対するタイプ 2 クエリでは、最初に変更されていない代表を解決します。 

| ステップ | 現在の担当者 | チェック |
 | --- | --- | --- |
 | 1 | [0、1、2] | 0 が 1 に接続されました |
 | 2 | [0、1、2] | 1 が 2 に接続されています |

 すべてのチェックに合格したため、min(3, 5, 2) = 2 を取得し、すべてを 1 つのコンポーネントにマージします。 

ここで、すべてのペア間にエッジが存在する三角形 [0, 1, 2] を形成するタイプ 1 クエリについて考えてみましょう。 

| ステップ | 担当者 | チェック |
 | --- | --- | --- |
 | 1 | [0、1、2] | 有効なチェーン |
 | 2 | [0、1、2] | 有効なチェーン |
 | 3 | サイクルチェック | 2 が 0 に接続されている |

 終了エッジが存在するため、結合されたノードには max(3, 5, 2) = 5 が割り当てられます。 

これらのトレースは、サイクルの終了が必要かどうかに応じて、同じ構造がどのように異なる方法で検証されるかを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、クエリ内のノードがすでに別のコンポーネントにマージされている場合です。 たとえば、ノード 1 がノード 0 に吸収された場合、0 と 1 の両方を含むクエリはそれらを同じ代表として扱う必要があります。 すべてのノードは以下を介して変換されるため、アルゴリズムがこれを処理します。`get(x)`構造チェックの前に、重複が正しく検出されていることを確認します。 

もう 1 つのケースは、最後のエッジが必要なサイクル検証です。 シーケンスが有効なパスを形成しているが、閉じている接続がない場合、タイプ 1 は失敗しますが、タイプ 2 は合格します。 アルゴリズムは分離します`chk_chain`そして`chk_cycle`、タイプ 1 の終了エッジ条件のみを適用し、両方の解釈にわたって正確さを維持します。
