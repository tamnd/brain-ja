 ## 解決策
 ## 問題の理解

 からの路線上にバス停を設置しています。`0`に`n`。 ジェラルドは停止からスタート`0`そして停留所に到達したいと思っています`n`。 

各バスは間隔によって記述されます`[s, t]`。 ジェラルドはどこの停留所からでもそのバスに乗車できます。`s`を通して`t - 1`ただし、一度乗ったら、止まるまで乗り続けなければなりません`t`。 彼は後退することも、停留所間を歩くこともできません。 

ジェラルドが別のバスに乗る隣接する停留所間に少なくとも 1 つのセグメントが存在する場合、2 つのルートは異なるものとみなされます。 実際には、これはバスの正確な順序が重要であることを意味します。 

課題は、停留所に到達するための有効な方法が何通り存在するかを数えることです`n`。 

制約によってソリューションが完全に形作られます。 停車駅数`n`と同じ大きさにすることができます`10^9`したがって、すべてのストップを反復するアルゴリズムは不可能です。 同時に、バスの数はわずかです。`10^5`これは、入力に現れる停止のみが関連していることを強く示唆しています。 

グラフの直接的な解釈が役に立ちます。 すべてのバスは、市内のすべての停留所からトランジションを作成します。`[s, t-1]`停止する`t`。 定義すると`dp[x]`停留所に到達する方法の数として`x`の場合、すべてのバスが次のように寄与します。$$dp[t] += dp[s] + dp[s+1] + \dots + dp[t-1]$$難しいのは、これらの範囲の合計を効率的に計算することです。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
3 1
0 2
```正しい答えは、`0`。 ジェラルドは停止に到達できます`2`、しかし、停止し続ける方法はありません`3`。 最遠のバス エンドポイントに到達すれば十分であると想定する不注意な実装では、誤って返される可能性があります。`1`。 

もう 1 つの微妙なケースは、複数のバスが同じ停留所で終わる場合です。```
2 2
0 2
1 2
```正しい答えは、`1`。 

2台目のバスは止まっているのでダメです`1`それ自体は到達不可能です。 で終わるバスのみをカウントする単純な実装`2`誤って生成する可能性があります`2`。 

バスが重なることも重要です。```
4 4
0 1
0 2
1 4
2 4
```正しい答えは、`2`。 

ジェラルドはどちらかを取ることができます`0→1→4`または`0→2→4`。 バスは重なり合うので、到達可能性を考慮せずに遷移を個別にカウントするとオーバーカウントが発生します。 

最も危険な間違いは、停止を直接処理しようとすることによって起こります。 以来`n`多分`10^9`、サイズの配列を割り当てる場合も`n+1`不可能です。 

## アプローチ

 強引なアイデアは再発に直接続きます。 

定義する`dp[x]`停留所に到着する方法の数として`x`。 当初は、`dp[0] = 1`。 すべてのバスに`(s, t)`、考えられるすべての乗車停留所に到達する方法の数を追加します。$$dp[t] += \sum_{i=s}^{t-1} dp[i]$$すべてのバスに対してこの合計を文字通り計算すると、最悪の場合、複雑さは 2 次になります。 と`10^5`バス、および各間隔がまたがる可能性がある`10^5`関連するポジションに応じて、総作業量が近づく可能性があります`10^{10}`操作。 

ボトルネックは明らかです。それは、大きな範囲を繰り返し合計することです。 

重要な観察は、反復が次のプレフィックスの合計にのみ依存するということです。`dp`。 

次のように維持すると、$$pref[i] = dp[0] + dp[1] + \dots + dp[i]$$それから：$$dp[t] += pref[t-1] - pref[s-1]$$これで、各遷移は一定時間になります。 

それだけではまだ不十分です。ストップ数は次のとおりです。`10^9`。 2 番目の観察は、バス エンドポイントのみが重要であるということです。 バスがどこかの停留所で始発または終点しない場合、そこでは何も興味深いことは起こりません。 

バス内に表示されるすべての個別の停留所の値を収集することで座標を圧縮します。`0`そして`n`。 それらを並べ替えた後は、圧縮されたインデックスのみを処理します。 

その後、バスは終点の停留所によって並べ替えられます。 左から右にスイープすると、圧縮された位置全体でプレフィックスの合計が維持されます。 すべてのバスは、目的地までの距離の合計に貢献します。 

これにより、問題はプレフィックス合計と座標圧縮を使用した動的プログラミングに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(㎡) | O(m) | 遅すぎる |
 | 最適 | O(m log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのバスを読み取り、入力に表示されるすべての停留所を収集します。`0`そして`n`。 

ストップが同じくらい大きい可能性があるため、元の座標範囲で作業することはできません。`10^9`。 
2. 収集された座標を並べ替えて重複を排除します。 

これにより、圧縮された座標系が作成されます。 
3. すべての元のストップ値をその圧縮インデックスにマッピングします。 

圧縮後、関連するすべてのストップが密な範囲内に収まります`[0, k-1]`。 
4. バスを目的地の停留所ごとにグループ化します。 

ストップを左から右に処理するため、あるストップに到達する方法を計算するとき`t`、以前のすべてのストップにはすでに最終的な値が設定されています。 
5.初期化`dp[start_index_of_0] = 1`。 

ジェラルドは停止からスタート`0`まさに一方向で。 
6. プレフィックスの合計を格納するフェンウィック ツリーを維持します。`dp`。 

フェンウィック ツリーは以下をサポートしています。 

- 圧縮されたストップに値を追加する
 - 圧縮されたストップの範囲にわたる合計をクエリする
 7. プロセス圧縮は昇順に停止します。 

すべてのバスに`(s, t)`現在の停留所で終了:

 - 任意の停留所に到達する方法の合計数をクエリします。`[s, t-1]`- その値をに追加します`dp[t]`これは漸化式と完全に一致します。 
8. 停留所で終わるすべてのバスが終了したら、`dp[stop]`フェンウィックの木の中へ。 

将来のバスはこの停留所を乗車位置として使用する可能性があります。 
9. 出力`dp[n] mod 10^9+7`。 

### なぜ効果があるのか

 不変条件は次のとおりです。`dp[x]`常にストップに到達するための有効な方法の数と等しくなります`x`目的地がすでに処理されているバスのみを使用します。 

バスを処理する場合`(s, t)`, ジェラルドは、到達可能な停留所であればどこでも乗車できます。`[s, t-1]`。 フェンウィック ツリーには、次の合計が正確に保存されます。`dp`処理されたストップの値があるため、その範囲をクエリすると、このバスを使用する有効な方法の合計数がわかります。 

ストップは昇順に処理されるため、すべてのパスが`dp[t]`すでに完成前に決まっている`t`が計算されます。 バスは前進のみであるため、将来の移行によって以前の停留所への経路を作成することはできません。 

したがって、すべての有効なルートは 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, idx, val):
        idx += 1
        while idx <= self.n:
            self.bit[idx] = (self.bit[idx] + val) % MOD
            idx += idx & -idx

    def sum(self, idx):
        idx += 1
        res = 0
        while idx > 0:
            res = (res + self.bit[idx]) % MOD
            idx -= idx & -idx
        return res

    def range_sum(self, left, right):
        if left > right:
            return 0
        return (self.sum(right) - self.sum(left - 1)) % MOD

def main():
    n, m = map(int, input().split())

    buses = []
    coords = {0, n}

    for _ in range(m):
        s, t = map(int, input().split())
        buses.append((s, t))
        coords.add(s)
        coords.add(t)

    coords = sorted(coords)
    comp = {x: i for i, x in enumerate(coords)}

    k = len(coords)

    ending = [[] for _ in range(k)]

    for s, t in buses:
        cs = comp[s]
        ct = comp[t]
        ending[ct].append(cs)

    dp = [0] * k

    start = comp[0]
    dp[start] = 1

    fw = Fenwick(k)
    fw.add(start, 1)

    for t_idx in range(k):
        if t_idx == start:
            continue

        ways = 0

        for s_idx in ending[t_idx]:
            ways += fw.range_sum(s_idx, t_idx - 1)
            ways %= MOD

        dp[t_idx] = ways
        fw.add(t_idx, ways)

    print(dp[comp[n]] % MOD)

if __name__ == "__main__":
    main()
```解決策は座標圧縮から始まります。 停留所の値は膨大になる可能性があるため、実際にバス内または終点として表示される停留所のみを保持します。`0`そして`n`。 

バスは目的地インデックスごとにグループ化されています。 これにより、スイープ中にすべてのバスを繰り返しスキャンすることがなくなります。 

フェンウィック ツリーには、到達可能なウェイのプレフィックスの合計が格納されます。 その`range_sum(l, r)`メソッドは以下を計算します:$$dp[l] + dp[l+1] + \dots + dp[r]$$対数時間で。 

実装の微妙な詳細の 1 つは、処理順序です。 まずすべての貢献を完了する必要があります`dp[t]`挿入する前に`dp[t]`フェンウィックの木の中へ。 それ以外の場合、バスの終点は`t`stop を誤って使用する可能性がある`t`それ自体が乗り場として機能します。 

もう 1 つの簡単な間違いは、空の範囲の処理です。 もし`s_idx > t_idx - 1`の場合、バスは何も貢献しません。 ヘルパー メソッドが返す`0`その場合。 

パスの数は指数関数的に増加するため、モジュロ演算は更新のたびに適用されます。

 ## 特殊なケース

 宛先が到達できない場合を考えてみましょう。```
3 1
0 2
```圧縮された座標は次のようになります`[0,2,3]`。 

最初に:```
dp[0] = 1
```処理停止`2`:

 - バス`(0,2)`クエリ範囲`[0,1]`- 停止するだけです`0`貢献する
 -`dp[2] = 1`処理停止`3`:

 - ここで終点となるバスはありません
 -`dp[3] = 0`アルゴリズムは正しく出力します`0`移行が学校に届かないからです。 

次に、オーバーラップするバスを考えてみましょう。```
2 2
0 2
1 2
```圧縮された座標は、`[0,1,2]`。 

処理停止時`2`:

 - バス`(0,2)`～に貢献する`[0,1]`- 停止するだけです`0`到達可能です

```これは、アルゴリズムが乗車範囲に到達できない停留所のみを含むバスを決してカウントしないことを確認します。
