 ## 解決策
 ## 問題の理解

 ジェラルドはキャンディー 1 つまたは石 1 つを繰り返し取り除きます。 すべての動きの後、マイクはジェラルドがすでに食べたキャンディーと石の数を確認します。 ジェラルドが食べてしまったら`a`キャンディーと`b`これまでの石、マイク賞$$f(a,b) = (x_a + y_b) \bmod p$$ポイント。 

ゲームは、次のような動きをする前に始まります。`(a,b) = (0,0)`、キャンディーと石が 1 つずつ残るとすぐに終了します。 ジェラルドはすべてのキャンディーまたはすべての石を消費することを禁じられているため、最終状態は常に次のようになります。$$(a,b) = (n-1,m-1)$$そして総移動数は固定されています。$$(n-1) + (m-1)$$ジェラルドが制御できる唯一のことは、キャンディーと石が消費される順序です。 

移動シーケンスはグリッド上のパスとして見ることができます。 州`(a,b)`ジェラルドはすでに食べていることを意味します`a`キャンディーと`b`石。 から`(a,b)`どちらかに移動するかもしれません`(a+1,b)`キャンディーを食べたり、`(a,b+1)`石を食べることによって。 訪問したすべての州が貢献`f(a,b)`ポイント。 

タスクは、以下から最大重みの単調パスを見つけることです。`(0,0)`に`(n-1,m-1)`。 

制約こそが本当の課題なのです。 両方`n`そして`m`せいぜい`20000`したがって、グリッドには最大で次のものを含めることができます。`4 * 10^8`州。 すべてのセルにわたる標準の動的プログラミング テーブルは時間的にもメモリ的にも不可能です。 すべての状態を 1 回繰り返すだけでも、Python ではすでに遅すぎます。 

スコア関数には特別な形式があります。$$f(a,b) = (x_a + y_b) \bmod p$$これは 1 つの行の値と 1 つの列の値にのみ依存します。 この構造の問題により、隣接する行間の遷移が規則的に動作するため、分割統治の最適化が可能になることがよくあります。 

見落としやすいエッジケースがいくつかあります。 

すべての値が等しいモジュロの場合`p`の場合、すべてのパスのスコアは同じになります。 次の当面の報酬を最大化しようとする貪欲な戦略は依然として有効ですが、再構築には一貫性を保つ必要があります。 

例えば：```
2 2 10
0 0
0 0
```どちらのパスでも同じ答えが得られます。 有効な長さのシーケンス`2`許容されます。 

モジュロがラップアラウンドするときに、別の微妙なケースが発生します。```
2 2 5
4 4
4 4
```ここですべての報酬は`(4+4)%5 = 3`、 ない`8`。 前処理中にモジュロを忘れると、まったく間違った答えが黙って生成されます。 

最終的な状態も重要です。 ジェラルドはすべてのキャンディーやすべての石を消費することはできません。 つまり、パスは次の地点で停止する必要があります。`(n-1,m-1)`まさに、それを超えるものではありません。 長さのパスを構築する不注意な実装`n+m`の代わりに`n+m-2`無効な戦略が生成されます。 

## アプローチ

 最も直接的な解決策は、グリッド上の標準的な動的プログラミングです。 

させて$$dp[a][b]$$状態に到達したときに取得できる最大合計スコアになります。`(a,b)`。 すべての動きはちょうど 1 つの座標を変えるので、`1`、再発は$$dp[a][b] = f(a,b) + \max(dp[a-1][b], dp[a][b-1])$$適切な境界条件を使用して。 

これが機能するのは、すべての有効なパスが`(a,b)`隣接する 2 つの州のいずれかから来ている必要があります。 

残念ながら、グリッドには以下のものが含まれています`4 * 10^8`細胞。 セルごとに 1 つの整数を格納するだけでもすでにメモリ制限を超えており、遷移数は 8 秒に収まる量をはるかに超えています。 

重要な観察は、遷移構造が非常に単純であるということです。 エッジの方向は単調で、セルの重みは行成分と列成分に分解されます。 

真ん中の行を修正するとします`mid`。 最適なパスはすべて、この行を 1 回だけ横切ります。 交差する列を知っていれば、上部と下部の部分問題を独立して解くことができます。 

これは、行を分割して征服することを示唆しています。 

残りの問題は、最適なパスが中央の行と交差する場所を決定することです。 ここで単調性が現れます。 最適なプレフィックスを上から計算し、最適なサフィックスを下から計算すると、列ごとに、以下を通過する最適なパスを評価できます。`(mid,col)`。 最大化する列が分割ポイントになります。 

この構造は、Hirschberg の LCS 再構成アルゴリズムとほぼ同じです。 最長共通部分列を再構成する代わりに、一度に 1 行の DP のみを保存しながら、最適な重み付き単調パスを再構成します。 

各分割統治レベルは長方形のストリップのみを処理し、すべてのセルは対数的に多くの部分問題のみに関与します。 結果として生じる複雑さは管理可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DP |$O(nm)$|$O(nm)$| 遅すぎる |
 | 分割統治 DP 再構築 |$O(nm)$|$O(m)$| 承認済み |

 時間の複雑さは残る`O(nm)`すべてのサブ問題は引き続きその四角形をスキャンしますが、メモリは数億のセルから数個の長さの配列に減少するためです。`m`。 それがこの問題の本当のボトルネックです。 

## アルゴリズムのチュートリアル

 1. セル値を定義します$$w(a,b) = (x_a + y_b) \bmod p$$訪問したすべての州がこの金額を寄付します。 

1. 有効な戦略はすべて、からの単調パスに対応することを観察します。`(0,0)`に`(n-1,m-1)`右と下の動きのみを使用します。 

お菓子を食べると増える`a`、石を食べると増加します`b`。 

1. 長方形に対して再構成問題を再帰的に解きます。 

現在の部分問題が次のような最適なパスを求めているとします。`(r1,c1)`に`(r2,c2)`。 

1. 中央の行を選択します$$mid = \lfloor (r1+r2)/2 \rfloor$$すべての有効なパスは、この行内の 1 つのセルを通過する必要があります。 

1. 行から順方向 DP を計算します`r1`まで`mid`。 

各列に、到達した時点での最高の達成可能なスコアを保存します。`(mid,col)`サブ長方形の内側に留まりながら。 

一度に必要な DP 行は 2 つだけです。 

1. 行から逆方向 DP を計算します。`r2`まで`mid`。 

この DP は、次から始まる取得可能な最良のサフィックス スコアを表します。`(mid,col)`そして終わる`(r2,c2)`。 

繰り返しますが、必要な行は 2 行だけです。 

1. 列ごとに`col`、2 つの値を組み合わせます。 

パス横断の合計スコア`(mid,col)`等しい$$forward[col] + backward[col] - w(mid,col)$$中央のセルは 2 回カウントされるため、1 回減算します。 

1. 合計値の最大値を示す列を選択します。 

これにより、最適なパスが中央の行と交差する場所が特定されます。 

1. 上半分と下半分を再帰的に解きます。 

上部の再帰では、次のパスが構築されます。`(r1,c1)`に`(mid,col)`。 

下位の再帰では、次のパスが構築されます。`(mid,col)`に`(r2,c2)`。 

1. 2 つのパス文字列を連結します。 

分割点付近で重複した動きをしないように注意する必要があります。 

1. 基本的なケースを処理します。 

もし`r1 == r2`、パスは石の移動のみで構成されます。 

もし`c1 == c2`、パスはキャンディーの動きのみで構成されます。 

### なぜ効果があるのか

 正確さは最適な下部構造から生まれます。 

長方形の最適なパスを修正します。 中列の列をまたいだとき`k`、前の部分`(mid,k)`それ自体がスタート コーナーから`(mid,k)`。 それ以外の場合は、より良いプレフィックスに置き換えて、パス全体を改善することができます。 

同じ議論が from のサフィックスにも適用されます。`(mid,k)`目的地のコーナーへ。 

フォワード DP は、交差する列ごとに可能な限り最良のプレフィックス スコアを正確に計算します。 逆方向 DP は、最良のサフィックス スコアを正確に計算します。 それらを結合すると、各交差点を使用して最適な完全なパスが評価されます。 最大交差列を選択すると、再帰を通じて少なくとも 1 つのグローバルに最適なパスが保持されることが保証されます。 

すべての再帰的分割で最適性が維持されるため、最終的に再構築されたシーケンスは最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = -(10**30)

def solve():
    n, m, p = map(int, input().split())
    x = list(map(int, input().split()))
    y = list(map(int, input().split()))

    w = [[0] * m for _ in range(n)]
    for i in range(n):
        xi = x[i]
        row = w[i]
        for j in range(m):
            row[j] = (xi + y[j]) % p

    sys.setrecursionlimit(1 << 25)

    def build(r1, c1, r2, c2):
        if r1 == r2:
            return "S" * (c2 - c1)

        if c1 == c2:
            return "C" * (r2 - r1)

        mid = (r1 + r2) // 2

        # forward dp
        prev = [INF] * (c2 - c1 + 1)

        prev[0] = w[r1][c1]

        for j in range(c1 + 1, c2 + 1):
            prev[j - c1] = prev[j - c1 - 1] + w[r1][j]

        for i in range(r1 + 1, mid + 1):
            cur = [INF] * (c2 - c1 + 1)

            cur[0] = prev[0] + w[i][c1]

            for j in range(c1 + 1, c2 + 1):
                idx = j - c1
                cur[idx] = max(cur[idx - 1], prev[idx]) + w[i][j]

            prev = cur

        forward = prev

        # backward dp
        prev = [INF] * (c2 - c1 + 1)

        prev[-1] = w[r2][c2]

        for j in range(c2 - 1, c1 - 1, -1):
            prev[j - c1] = prev[j - c1 + 1] + w[r2][j]

        for i in range(r2 - 1, mid - 1, -1):
            cur = [INF] * (c2 - c1 + 1)

            cur[-1] = prev[-1] + w[i][c2]

            for j in range(c2 - 1, c1 - 1, -1):
                idx = j - c1
                cur[idx] = max(cur[idx + 1], prev[idx]) + w[i][j]

            prev = cur

        backward = prev

        best_col = c1
        best_val = INF

        for j in range(c1, c2 + 1):
            idx = j - c1
            total = forward[idx] + backward[idx] - w[mid][j]

            if total > best_val:
                best_val = total
                best_col = j

        upper = build(r1, c1, mid, best_col)
        lower = build(mid, best_col, r2, c2)

        return upper + lower

    path = build(0, 0, n - 1, m - 1)

    a = b = 0
    ans = w[0][0]

    for ch in path:
        if ch == 'C':
            a += 1
        else:
            b += 1

        ans += w[a][b]

    print(ans)
    print(path)

solve()
```実装は再帰的再構築に正確に従っています。 

再帰関数`build(r1, c1, r2, c2)`現在の四角形内の移動の最適なシーケンスを返します。 移動するたびにキャンディーの数または石の数が増加するため、再帰は自然にサブパスに対応します。 

DP 配列には、単一行のスコアのみが保存されます。 これが重要なメモリ最適化です。 いっぱい`n x m`table は快適に収まりませんが、配列の長さは最大でも 2 つです`20000`小さいです。 

順方向 DP は、中央の行で終わる最適なプレフィックス値を計算します。 逆方向 DP は、そこから開始して最適なサフィックス値を計算します。 それらの組み合わせにより、最適な交差列が特定されます。 

微妙なディテールの 1 つが減算です`w[mid][j]`合体中に1回。 どちらの DP にも中央のセルが含まれているため、1 つのコピーを削除し損ねると、その影響は 2 倍になります。 

もう 1 つの簡単な間違いは、再構築の連結です。 再帰呼び出しはすでに隣接するパス セグメントを表しているため、移動文字列を直接連結するだけです。 スプリットポイントには余分な動きは挿入されません。 

最終スコアは、中間の DP 値を信頼するのではなく、生成されたパスから再計算されます。 これにより、サブ問題の重複やカウント規則によって発生するバグが回避されます。
