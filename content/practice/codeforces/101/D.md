 ## 解決策
 ## 問題の理解

 ジェラルドが開始するホール 1 に根を張る重み付けされたツリーが与えられます。 宝物は他のホールのいずれかに均一にランダムに隠されています。 ジェラルドは、最初に正しいホールに入ったときにのみ宝物を発見します。 

問題を完全に変える制限は、すべての回廊が 2 回通過すると崩壊するということです。 グラフはツリーであるため、Gerald は、コリドーが使用できなくなる前に、すべてのノードに 1 回だけ到達できるトラバースを計画する必要があることを意味します。 実際には、すべてのエッジは 1 回使用されるか、サブツリーに下りてから戻る過程の一部として 2 回使用されます。 

すべてのノードについて`v ≠ 1`、 定義する`t[v]`ジェラルドが初めて入ったとき`v`。 目標は、これらすべての最初の到着時間の平均を最小化することです。 

入力は、最大でツリーを記述します。`10^5`頂点と重み付けされたエッジ。 二次アルゴリズムや三次アルゴリズムは直ちに不可能です。 平`O(n log^2 n)`ここでは不必要なオーバーヘッドが発生します。 構造はツリーであるため、線形または`O(n log n)`DFS とローカルの決定に基づいたソリューション。 

難しいのは、ジェラルドが既知のターゲットへの最短経路を選択していないことです。 彼は宝がどこにあるのかを知る前に探索の順序を選択しています。 サブツリーの順序が異なると、予想される検出時間が大幅に変化します。 

よくある間違いは、局所的に最短エッジを最初に取ることが常に最適であると考えることです。 次のツリーを考えてみましょう。```
1 --(1)-- 2
|
(100)
|
3 --(1)-- 4
```最初にノード 2 にアクセスすると、検出時間は次のようになります。 

| ノード | 初診時間 |
 | --- | --- |
 | 2 | 1 |
 | 3 | 101 |
 | 4 | 102 |

 平均 =`(1 + 101 + 102) / 3 = 68`。 

代わりに、最初にノード 3 に移動すると、次のようになります。 

| ノード | 初診時間 |
 | --- | --- |
 | 3 | 100 |
 | 4 | 101 |
 | 2 | 203 |

 平均 =`134.67`。 

ここでは確かに小さいエッジが最初に来るはずですが、本当の理由はエッジの長さそのものではありません。 これは、残りの未探索ノードに課せられる将来の遅延量です。 

もう 1 つの簡単なバグは、2 つのサブツリーのサイズが大きく異なる場合に発生します。 考慮する：```
1 --(10)-- A
1 --(11)-- B
```サブツリーを仮定します`A`サブツリーには 100 個のノードが含まれます`B`ノードが 1 つだけ含まれています。 エッジの重みのみに基づく貪欲なルールでは、`A`まず、なぜなら`10 < 11`、しかしそれだけでは十分な推論ではありません。 正しい順序は、別のサブツリーを探索するときにどれだけのノードが遅延するかによって決まります。 

最後の微妙な点は、ルート自体は決して宝の場所ではないということです。 期待値は次のように割られます。`n - 1`、 ない`n`。 これを忘れると、すべての答えがわずかにずれてしまい、小さな手動テストに誤って合格してしまうことがよくあります。 

## アプローチ

 ブルートフォース手法では、すべての有効な走査順序が列挙されます。 すべてのノードで、子を探索する順序を選択することができ、これらの選択はツリー全体で再帰的に結合されます。 

次数を持つノードの場合`d`、 がある`d!`現地での注文も可能です。 ツリー全体にわたるグローバル トラバースの数は膨大になります。 分岐点の多い適度な木であっても、これは完全に不可能になります。 

それでも、この強引なアイデアから役立つことがわかります。 唯一意味のある決定は、兄弟サブツリーの相対的な順序です。 サブツリーに入ったら、そのエッジへのアクセスを永久に失う前に、最終的にはサブツリーの探索を終了する必要があります。 したがって、問題は、子サブツリーをどの順序で処理するかを決定することに帰着します。 

ノードに立っているとします。`u`2 つの子サブツリーを比較します`A`そして`B`。 

させて：

-`sz[A]`サブツリー内の宝物候補ノードの数になります`A`-`cost[A]`サブツリーを完全に探索する際に費やした合計走査時間になります。`A`そして戻る`u`加工すれば`A`前に`B`、その後、内部のすべてのノード`B`によって遅れます`cost[A]`。 

同様に処理すると、`B`最初に内部のすべてのノードを遅延させます`A`による`cost[B]`。 

それで：

-`A`前に`B`余分な遅延が追加される`cost[A] * sz[B]`-`B`前に`A`余分な遅延が追加される`cost[B] * sz[A]`配置すべきです`A`前に`B`まさに次のとき:$$cost[A] \cdot sz[B] < cost[B] \cdot sz[A]$$これが重要な洞察です。 この問題は、ジョブの順序付けにおけるスミスの法則によく似たスケジュールの問題になります。 

今必要なのは以下だけです:

 1. サブツリーのサイズ。 
2. 各サブツリーの総探索コスト。 
3. 上記の比較による地元の子供たちの種類。 

完全な探索中に各エッジが 2 回横断されるため、エッジが`(u,v)`重さがある`w`、 それから：$$cost[v] = dp[v] + 2w$$どこ`dp[v]`サブツリー内の総探索コストです`v`。 

子を最適に並べ替えた後、DFS 順序をシミュレートし、初回訪問時間を累積します。 

ソリューション全体は、各ノードでソートを行う 1 組の DFS トラバーサルになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノードでツリーをルート化します`1`。 

これにより、すべてのノードに親と子のセットが与えられ、サブツリー推論が可能になります。 
2. DFS を実行してサブツリーのサイズを計算します。 

させて`sz[u]`サブツリー内の宝物候補ノードの数を示します`u`、 含む`u`もしそれ自体`u ≠ 1`。 
3. 同じ DFS 中に、探査コストを計算します。 

させて`dp[u]`サブツリーを完全に探索するのに必要な合計時間`u`そしてまた戻ってきます`u`。 

すべての子供たちにとって`v`エッジウェイトで接続`w`:$$dp[u] += dp[v] + 2w$$なぜなら、私たちは下りて、後でその端に沿って戻らなければならないからです。 
4. すべてのノードについて、その子をソートします。 

二人の子供のために`a`そして`b`、 定義する：$$A = dp[a] + 2w_a$$

$$B = dp[b] + 2w_b$$配置します`a`前に`b`もし：$$A \cdot sz[b] < B \cdot sz[a]$$これにより、未探索のノードに課される合計待機時間が最小限に抑えられます。 
5. ソートされた順序に従って 2 番目の DFS を実行します。 

現在の経過時間を維持します。 

初めてノードに入るとき`v`、宝物がそ​​こにある場合、これはまさに発見時間であるため、グローバル回答に現在時間を追加します。 
6. 子サブツリーを完全に探索した後、総探索コストだけ現在の時間を進めます。 

これは、現在のノードに戻り、他の場所で探索を継続することを反映しています。 
7. 累積合計を次の値で割ります。`n - 1`。 

宝物はすべての非ルート ノードに均一に分散されます。 

### なぜ効果があるのか

 すべてのサブツリーは、次の 2 つのパラメータを持つジョブのように動作します。 

- 完全に処理するまでにかかる時間
 - 完了するまでブロックされた宝の場所の数。 

サブツリーの場合`A`サブツリーの前に探索される`B`、次にすべてのノード`B`～の探索時間全体を待つ`A`。 

ペアワイズ スワップ引数は最適性を証明します。 2 つの連続するサブツリーのみを比較するとします。 注文`A`前に`B`貢献します:$$cost[A] \cdot sz[B]$$待機中のノードの合計`B`。 

それらを逆転すると、次のような効果が得られます。$$cost[B] \cdot sz[A]$$私たちは小さい方を選びます。 比較は推移的であるため、このルールによる並べ替えにより全体的に最適な順序が得られます。 

2 番目の DFS はその最適なトラバーサルを正確にシミュレートするため、すべてのノードの最初の到着時間が最小限に抑えられます。 

## Python ソリューション```python
import sys
from functools import cmp_to_key

input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

n = int(input())

g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    a, b, w = map(int, input().split())
    g[a].append((b, w))
    g[b].append((a, w))

sz = [0] * (n + 1)
dp = [0] * (n + 1)

children = [[] for _ in range(n + 1)]

def dfs1(u, p):
    sz[u] = 1 if u != 1 else 0

    for v, w in g[u]:
        if v == p:
            continue

        dfs1(v, u)

        sz[u] += sz[v]
        dp[u] += dp[v] + 2 * w

        children[u].append((v, w))

    def cmp(x, y):
        vx, wx = x
        vy, wy = y

        cx = dp[vx] + 2 * wx
        cy = dp[vy] + 2 * wy

        left = cx * sz[vy]
        right = cy * sz[vx]

        if left < right:
            return -1
        if left > right:
            return 1
        return 0

    children[u].sort(key=cmp_to_key(cmp))

dfs1(1, 0)

ans = 0

def dfs2(u, p, cur_time):
    global ans

    if u != 1:
        ans += cur_time

    now = cur_time

    for v, w in children[u]:
        dfs2(v, u, now + w)
        now += dp[v] + 2 * w

dfs2(1, 0, 0)

print(ans / (n - 1))
```最初の DFS は 2 つの構造量を計算します。`sz[u]`サブツリー内に有効な宝の位置がいくつ存在するかをカウントします`u`。 ルートはそこから宝物が始まることはないので除外されます。`dp[u]`サブツリーを完全に探索するために必要な総走査時間を測定します。`u`そして戻ってきて`u`。 探索には入ることと戻ることの両方が必要となるため、すべてのエッジは 2 回貢献します。 

並べ替えのステップがソリューションの核心です。 よくある実装上の間違いは、次のような浮動小数点除算を使用することです。```
cost[a] / sz[a]
```これにより、精度の問題が発生する可能性があります。 相互乗算はそれを完全に回避します。 

2 番目の DFS は、実際の走査順序をシミュレートします。 変数`now`ノードに戻った時刻を表します`u`次の子サブツリーを開始する準備ができています。 

もう 1 つの微妙な点は、再帰呼び出しが子に入るということです。`v`時に`now + w`、 ない`now`。 エッジトラバーサル自体は、最初に到達するまでに時間がかかります。`v`。 

最大合計トラバース長は最大でも次の程度であるため、すべての算術演算は Python 整数に安全に適合します。$$2 \cdot (10^5 - 1) \cdot 1000$$いずれにせよ、これは 64 ビットの範囲内に十分収まります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各ノードの子は 1 回ソートされます。 
| スペース | O(n) | 隣接リスト、DFS 配列、再帰スタック |

これは簡単に制限内に収まります`n ≤ 10^5`。

 ## 特殊なケース

 星型のツリーを考えてみましょう。```
5
1 2 1
1 3 1
1 4 1
1 5 1
```すべての葉は、別の葉にアクセスする前にルートに戻る必要があります。 最初に訪問したリーフに到達した時刻`1`、2番目の`3`、3番目の`5`、4番目は`7`。 

アルゴリズムは以下を計算します。 

| 葉 | 先着 |
 | --- | --- |
 | 最初 | 1 |
 | 2番目 | 3 |
 | 3番目 | 5 |
 | 4番目 | 7 |

 平均：$$(1 + 3 + 5 + 7) / 4 = 4$$これにより、2 番目の DFS が往復コストを正しく累積していることが確認されます。 

ここで、エッジの重みよりもサブツリーのサイズが重要である場合を考えてみましょう。```
6
1 2 1
2 3 1
3 4 1
1 5 2
1 6 2
```をルートとするサブツリー`2`には 3 つのトレジャー ノードが含まれており、ノードあたりの追加コストは比較的わずかです。 単一ノードが離脱する前に、アルゴリズムにより優先順位が付けられます。`5`そして`6`。 

直接エッジの長さのみに基づいた単純な戦略では、3 つの子すべてを同様に誤って扱う可能性があります。 

コンパレータは以下を最小限に抑えるため、これを正しく処理します。$$cost \times delayed\_nodes$$単なるローカル走査時間ではありません。 

最後に、長さの深いチェーンを考えます。`10^5`。 再帰の深さを増やさない再帰 DFS はスタック オーバーフローでクラッシュします。 この実装では、最悪の場合のツリーを安全に処理するために、再帰制限が明示的に引き上げられます。
