 ## 解決策
 ## 問題の理解

 ベクトルから始めます`A = (x1, y1)`それを別のベクトルに変換したい`B = (x2, y2)`。 

2 つの操作が許可されます。 現在のベクトルを時計回りに 90 度回転し、ベクトルを追加します。`C = (x3, y3)`何度でも。 操作は任意の順序で組み合わせることができます。 

時計回りに 90 度回転すると、`(x, y)`の中へ`(y, -x)`。 これを繰り返し適用すると、可能な方向は 4 つだけ作成されます。 

-`(x, y)`-`(y, -x)`-`(-x, -y)`-`(-y, x)`加算演算は、ベクトルを次の整数倍でシフトします。`C`。 

課題は、これらの操作のシーケンスによって変換できるかどうかを判断することです。`A`の中へ`B`。 

座標は次のように大きくできます。`10^8`、ポジティブとネガティブの両方。 これにより、州を対象とした検索は即座に除外されます。 到達可能なベクトルに対する BFS であっても、座標には制限がなく、可能な加算の数は無限であるため、爆発する可能性があります。 

制限時間は 1 秒だけであるため、目的のソリューションは一定の作業のみを実行する必要があります。 回転では 4 つの状態しか生成されないため、問題全体は少数の代数条件をチェックすることに帰着します。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

次の場合を考えてみましょう`C = (0, 0)`:```
1 2
2 -1
0 0
```正しい答えは、`YES`、回転するので`(1,2)`一度与える`(2,-1)`。 のコンポーネントで分割する不用意な実装`C`クラッシュするか、このケースを拒否します。 

ここで、1 つのゼロ成分を持つベクトルを考えてみましょう。```
1 1
1 5
0 2
```正しい答えは、`YES`、追加できるので、`(0,2)`2回。 次のような比率だけを比較すると、`(dx / cx) == (dy / cy)`、ゼロによる除算が問題になります。 

もう 1 つの微妙なケースは、ターゲットが反対方向にある場合に発生します。`C`:```
0 0
-2 -2
1 1
```正しい答えは、`NO`。 の正の倍数のみを追加できます。`C`、決して減算しないでください。 整数乗算を許可する素朴な線形方程式チェックでは、これを誤って受け入れてしまいます。 

最後に、回転と加算は便利ではありますが、明白ではない方法で変換されます。 追加後回転`C`オリジナルを追加するのと同じではありません`C`追加されたベクトル自体は回転しないためです。 この区別が欠けていると、到達可能な状態についての誤った推論が発生します。 

## アプローチ

 ブルートフォースアプローチでは、到達可能なすべてのベクトルを探索しようとします。 現在のすべてのベクトルから、回転または追加することができます。`C`。 加算は無限に適用できるため、座標が人為的に制限されない限り、状態空間は無限になります。 

座標をある範囲に限定しようとしても、最悪の場合は膨大なものになってしまいます。 座標に到達する可能性があります`10^8`, そのため、グリッドベースの検索は不可能です。 

重要な観察は、回転によって 4 つの異なるバージョンのみが作成されるということです。`A`。 これら 4 つの方向の 1 つを選択した後、残る操作は繰り返し追加することだけです。`C`。 

回転したバージョンの 1 つを仮定します。`A`は`R`。 その場合、その状態から到達可能なすべてのベクトルは次の形式になります。```
R + kC
```ある整数に対して`k ≥ 0`。 

したがって、無限に多くの一連の演算を探索する代わりに、4 つの方程式をテストするだけで済みます。```
B = R + kC
```並べ替えると次のようになります。```
B - R = kC
```これは、差分ベクトルが次の負でない整数倍でなければならないことを意味します。`C`。 

これにより、問題が純粋な算術に変換されます。 

もし`C = (0,0)`の場合、シフトは不可能となり、ある回転が等しいかどうかのみをチェックします。`B`。 

それ以外の場合は、2 つの座標の差が同じ非負の整数乗数と一致するかどうかを検証します。 

これにより、問題全体が 4 つの定数チェックに減ります。

 ## アルゴリズムのチュートリアル

 1. ベクトルを読む`A`、`B`、 そして`C`。 
2. 可能な 4 つの回転を生成します。`A`。 

回転は次のとおりです。```
(x, y)
(y, -x)
(-x, -y)
(-y, x)
```時計回りに 4 回回転すると元のベクトルに戻るため、これらは回転によって取得できる唯一の明確な状態です。 
3. 回転されたベクトルごとに`R`、次を計算します。```
dx = Bx - Rx
dy = By - Ry
```どうかを判断する必要があります。`(dx, dy)`等しい`k * C`ある整数に対して`k ≥ 0`。 
4. 特殊なケースに対処する`C = (0,0)`。 

両方のコンポーネントの場合、`C`がゼロの場合、加算しても何も変化しません。 変換は次の場合にのみ可能です`(dx, dy)`もです`(0,0)`。 
5. ちょうど 1 つのコンポーネントの場合、`C`がゼロの場合は、互換性のある座標を個別に確認してください。 

たとえば、次の場合`Cx = 0`、 それから`dx`もゼロでなければなりません。 それから`dy`で割り切れる必要があります`Cy`、商は負でない必要があります。 

これにより、ゼロによる除算が回避されます。 
6. 両方のコンポーネントが`C`ゼロ以外の場合は、以下を確認してください。```
dx % Cx == 0
dy % Cy == 0
dx // Cx == dy // Cy
dx // Cx >= 0
```最初の 2 つの条件により、可算性が保証されます。 3 番目の方法では、両方の座標で同じ乗数が使用されるようにします。 最後は追加のみを保証します`C`、決して減算しないでください。 
7. いずれかの回転が条件を満たす場合、印刷します。`"YES"`。 
8. それ以外の場合は印刷します`"NO"`。 

### なぜ効果があるのか

 すべての操作シーケンスは 2 つのフェーズに再編成できます。 

まずすべての回転を実行します。 回転は 4 つのアプリケーションごとに循環するため、結果として得られるベクトルは、次の 4 つの回転バージョンのいずれかである必要があります。`A`。 

次に、次のすべての加算を実行します`C`。 追加`C`繰り返し、常に次の形式のベクトルを生成します。```
R + kC
```負でない整数の場合`k`。 

したがって、ターゲットベクトル`B`回転が存在する場合に正確に到達可能です`R`次のような:```
B - R = kC
```アルゴリズムは、考えられる 4 つの回転すべてについてこの条件を徹底的にチェックするため、到達可能なすべてのターゲットを受け入れ、到達できないすべてのターゲットを拒否します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def possible(rx, ry, bx, by, cx, cy):
    dx = bx - rx
    dy = by - ry

    if cx == 0 and cy == 0:
        return dx == 0 and dy == 0

    if cx == 0:
        if dx != 0:
            return False
        if dy % cy != 0:
            return False
        return dy // cy >= 0

    if cy == 0:
        if dy != 0:
            return False
        if dx % cx != 0:
            return False
        return dx // cx >= 0

    if dx % cx != 0 or dy % cy != 0:
        return False

    kx = dx // cx
    ky = dy // cy

    return kx == ky and kx >= 0

def solve():
    ax, ay = map(int, input().split())
    bx, by = map(int, input().split())
    cx, cy = map(int, input().split())

    rotations = [
        (ax, ay),
        (ay, -ax),
        (-ax, -ay),
        (-ay, ax)
    ]

    for rx, ry in rotations:
        if possible(rx, ry, bx, by, cx, cy):
            print("YES")
            return

    print("NO")

solve()
```解決策は数​​学的特性に直接従うものです。 

の`rotations`リストには、時計回りに 90 度回転を繰り返して到達できるベクトルが 4 つだけ含まれています。 それらを明示的に計算することは、ループ内で回転をシミュレートするよりも簡単で安全です。 

ヘルパー関数`possible()`差分ベクトルが次の非負の倍数として表現できるかどうかをチェックします。`C`。 

最もデリケートな部分は、ゼロコンポーネントを処理することです。`C`。 で直接割る`Cx`または`Cy`そのうちの 1 つがゼロの場合は失敗します。 コードでは、これらのケースを明示的に分割します。 

もう 1 つの微妙な点は、次のような非否定的な要件です。`k`。 たとえ比率が一致しても、演算では加算のみが許可されるため、負の乗数は無効です。`C`、引き算ではありません。 

Python の整数は、次の値まで自動的に処理します。`10^8`したがって、オーバーフローは心配ありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    ax, ay = map(int, input().split())
    bx, by = map(int, input().split())
    cx, cy = map(int, input().split())

    rotations = [
        (ax, ay),
        (ay, -ax),
        (-ax, -ay),
        (-ay, ax)
    ]

    def possible(rx, ry):
        dx = bx - rx
        dy = by - ry

        if cx == 0 and cy == 0:
            return dx == 0 and dy == 0

        if cx == 0:
            return dx == 0 and dy % cy == 0 and dy // cy >= 0

        if cy == 0:
            return dy == 0 and dx % cx == 0 and dx // cx >= 0

        if dx % cx != 0 or dy % cy != 0:
            return False

        kx = dx // cx
        ky = dy // cy

        return kx == ky and kx >= 0

    for rx, ry in rotations:
        if possible(rx, ry):
            return "YES"

    return "NO"

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# one zero component
assert run("1 1\n1 5\n0 2\n") == "YES", "vertical movement only"

 ## 特殊なケース

 次の場合を考えてみましょう`C = (0,0)`:```
1 2
2 -1
0 0
```アルゴリズムは 4 つの回転を生成します。```
(1,2)
(2,-1)
(-1,-2)
(-2,1)
```2 番目のローテーションは一致します`B`まさに、それで`dx = dy = 0`。 以来`C`がゼロの場合、アルゴリズムは完全一致のみを受け入れますが、これは正しいことです。 

次に、1 次元の移動の場合を調べます。```
1 1
1 5
0 2
```回転は 1 つずつチェックされます。 のために`(1,1)`:```
dx = 0
dy = 4
```以来`Cx = 0`、アルゴリズムが必要とするのは`dx = 0`。 次に、次のことをチェックします。```
4 % 2 == 0
4 // 2 = 2 >= 0
```したがって、答えは次のとおりです`YES`。 

最後に、誤解を招く負の倍数の場合を考えてみましょう。```
0 0
-2 -2
1 1
```回転ごとに、差分ベクトルは次のようになります。`(-2,-2)`。 両方の座標は次のように割り切れます。`(1,1)`、 しかし：```
k = -2
```アルゴリズムはこれを拒否します。`k`負ではない必要があります。 

追加するだけなので、これにより操作セットが正しくモデル化されます。`C`、決して減算しないでください。
