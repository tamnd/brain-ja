 ## 解決策
 ## 問題の理解

 小文字の文字列で始まり、最大でも削除できます`k`そこからのキャラクターたち。 文字を削除するとサブシーケンスが作成されるため、残りの文字は元の順序を維持する必要があります。 私たちの目標は、残りの長さを最大化することではなく、まだ表示される個別の文字の数を最小化することです。 

最終文字列に文字が 1 回でも出現する場合、その文字は 1 つの異なる文字としてカウントされます。 結果から文字を完全に削除するには、その文字が出現するすべてを削除する必要があります。 

これにより、「どの位置を消去するか」という問題が変わります。 「どの文字種を丸ごと消すべきか？」 キャラクターが 7 回出現した場合、そのキャラクターを削除するには 7 削除のコストがかかります。 一度出現した場合、削除にかかるコストは 1 回だけです。 

文字列の長さは次のとおりです`10^5`、これにより、指数関数または二次関数は即座に除外されます。`n`。 文字のすべてのサブセットを削除しようとすることはできません。また、ネストされたループで大きな文字列を繰り返し再構築することもできません。 アン`O(n log n)`または`O(n)`解決策が正しい目標です。 

誤って対処しやすい特殊なケースがいくつかあります。 

考慮する：```
aaaaa
4
```最大 4 文字を削除できますが、5 文字すべてを削除すると制限を超えます。 答えは、0 ではなく、依然として 1 つの異なる文字です。不注意な実装では、できるだけ多くの文字を貪欲に削除し、誤って文字列全体を削除してしまう可能性があります。 

ここで次のことを考えてみましょう。```
abc
10
```ここではすべての文字を削除できます。`k`文字列の長さよりも長いです。 正解は 0 で、結果の文字列は空になります。 一部のソリューションでは、誤って少なくとも 1 文字を強制的に残すことがあります。 

別の微妙なケースは次のとおりです。```
aabbbcccc
5
```周波数は次のとおりです。`2, 3, 4`。 削除したら`'a'`そして`'b'`、ちょうど 5 つの削除を費やし、答えを 1 つの異なる文字に減らします。 最大のグループを最初に削除する単純な貪欲な戦略は、ここでは大きく失敗します。`'c'`コストは 4 で、1 文字ではなく 2 つの異なる文字が残ります。 

重要な観察は、文字タイプの削除にはその頻度に等しい固定コストがかかるということです。 残る個別の文字の数を最小限にするには、最初に最も安価な文字タイプを削除する必要があります。 

## アプローチ

 ブルートフォースソリューションでは、個別の文字のすべてのサブセットを試し、それらの文字のすべての出現を削除するのに最大のコストがかかるかどうかを確認します。`k`。 アルファベットのサブセットが有効な場合は、残っている個別の文字の数をカウントし、最小値を維持します。 

これが機能するのは、基本的にポジションではなくキャラクターのタイプを選択するためです。 どの文字が完全に消えるかを決定すると、結果として得られる部分シーケンスは、他のすべての文字を保持することによって一意に決定されます。 

問題はサブセットの数です。 アルファベットには小文字の英字しか含まれていませんが、それでも`2^26`サブセット、つまり約 6,700 万通りの可能性があります。 これは 2 秒の制限には大きすぎます。 

重要な構造的特性は、すべての文字タイプに独立した削除コストがあるということです。 削除中`'a'`撤去費用には影響しません`'b'`。 私たちは、頻度が予算内に収まるできるだけ多くの文字タイプを効果的に選択しています。`k`。 

これは貪欲な問題になります。 2 つの文字タイプの頻度が 2 と 5 であるとします。どちらか 1 つしか余裕がない場合、頻度 2 の文字を削除することは常に、頻度 5 の文字を削除するのと少なくとも同じくらい効果的です。これは、どちらも個別のカウントをちょうど 1 だけ減らしますが、一方の方がコストが低いためです。 

その観察によって戦略が完全に決まります。 

1. 周波数を数えます。 
2. 文字の種類を頻度順に並べ替えます。 
3. 十分な削除が残っている間に、最初に最小のグループを削除します。 
4. 残りの文字タイプのみを使用して答えを再構築します。 

アルファベットのサイズはわずか 26 なので、ソート頻度は基本的に一定時間です。 主な作業は文字列のスキャンです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^26 · 26 + n) | お(26) | 遅すぎる |
 | 最適 | O(n + 26 log 26) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取る`s`そして整数`k`。 
2. 文字列内に各文字が何回出現するかを数えます。 

文字を完全に削除するとその頻度が正確に消費されるため、これらの頻度が必要になります。 
3. すべて保存する`(frequency, character)`ペアを作成し、頻度の昇順に並べ替えます。 

完全に削除された文字ごとに個別の数がちょうど 1 ずつ減るため、最も安価な文字タイプを最初に検討する必要があります。 
4. 並べ替えられたリストを調べます。 

現在の頻度が残りの削除予算以下の場合`k`、その文字タイプ全体を削除します。 

- その周波数をから引きます`k`- キャラクターを削除済みとしてマークします

 それ以外の場合は、文字の削除を中止してください。 

現在の最小周波数を許容できなくなると、リストがソートされているため、それ以降の周波数も許容できなくなります。 
5. 削除されなかった文字のみを保持して、最終的な文字列を構築します。 

これにより、元の順序が自動的に保存されるため、結果は有効なサブシーケンスになります。 
6. 残りの異なる文字の数を数えて出力します。 

- 残りの個別の文字の数
 - 結果のサブシーケンス

 ### なぜ効果があるのか

 削除された各文字タイプはまったく同じメリットをもたらし、個別カウントが 1 ずつ減ります。選択間の唯一の違いは、その頻度に等しいコストです。 

最適解が頻度 5 の文字を削除し、頻度 2 の別の文字を保持するとします。これらの選択肢を入れ替えても、使用される削除の合計を増やすことはできませんが、依然として 1 つの異なる文字が削除されます。 この交換議論を繰り返すと、最適な解は常に最小の周波数を最初に削除する解に変換されます。 

この性質のため、貪欲な戦略が最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
k = int(input())

freq = [0] * 26

for ch in s:
    freq[ord(ch) - ord('a')] += 1

pairs = []

for i in range(26):
    if freq[i] > 0:
        pairs.append((freq[i], chr(i + ord('a'))))

pairs.sort()

removed = set()

for cnt, ch in pairs:
    if cnt <= k:
        k -= cnt
        removed.add(ch)
    else:
        break

result = []

for ch in s:
    if ch not in removed:
        result.append(ch)

answer = ''.join(result)

print(len(set(answer)))
print(answer)
```最初のセクションでは、長さ 26 の固定サイズの配列を使用して頻度をカウントします。アルファベットが事前にわかっているため、これは辞書を使用するよりも高速かつ簡単です。 

の`(frequency, character)`ペアは、最も安価な文字タイプが最初に表示されるようにソートされます。 貪欲ループは、予算が許す限りキャラクター グループ全体を削除します。 

停止条件は重要です。 周波数が大きすぎると、配列がソートされるため、その後のすべての周波数も大きすぎます。 ループを続けても何も達成されません。 

最後の再構築ステップでは、元の文字列をスキャンし、削除された文字をスキップします。 これにより、相対的な順序が自動的に保持されるため、結果はサブシーケンスのままになります。 

微妙な点の 1 つは、空文字列の場合です。 すべての文字種を削除すると、`answer`になる`""`、 そして`len(set(answer))`正しく評価されるのは`0`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    s = input().strip()
    k = int(input())

    freq = [0] * 26

    for ch in s:
        freq[ord(ch) - ord('a')] += 1

    pairs = []

    for i in range(26):
        if freq[i] > 0:
            pairs.append((freq[i], chr(i + ord('a'))))

    pairs.sort()

    removed = set()

    for cnt, ch in pairs:
        if cnt <= k:
            k -= cnt
            removed.add(ch)
        else:
            break

    ans = ''.join(ch for ch in s if ch not in removed)

    print(len(set(ans)))
    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("aaaaa\n4\n") == "1\naaaaa\n", "sample 1"

# delete one entire character group
assert run("aaaabbb\n4\n") == "1\naaaa\n", "remove b"

# delete everything
assert run("abc\n10\n") == "0\n\n", "empty result"

# minimum size input
assert run("a\n0\n") == "1\na\n", "single character"

# exact budget match
assert run("aabbbcccc\n5\n") == "1\ncccc\n", "remove a and b"

# no deletions allowed
assert run("abac\n0\n") == "3\nabac\n", "unchanged string"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`a / 0`|`a`残る | 最小サイズの入力 |
 |`abc / 10`| 空の文字列 | 完全削除事件 |
 |`aaaabbb / 4`| 保管のみ`a`| 貪欲に小さい周波数を削除 |
 |`aabbbcccc / 5`| 保管のみ`cccc`| 正確な予算消費 |
 |`abac / 0`| 元の文字列 | ゼロ削除境界 |

 ## 特殊なケース

 すべての文字を削除することが不可能な場合を考えてみましょう。```
aaaaa
4
```周波数リストには次のものが含まれます。`(5, 'a')`。 以来`5 > 4`、貪欲ループは何も削除しません。 再構築ステップではすべての文字が保持され、`"aaaaa"`1 つの異なる文字を含む。 これにより、アルゴリズムが削除バジェットを決して超えないことが確認されます。 

次に、反対の極端な例を考えてみましょう。```
abc
10
```ソートされた周波数は次のとおりです。`(1, 'a')`、`(1, 'b')`、`(1, 'c')`。 

このアルゴリズムは、次の 3 つのグループをすべて削除します。 

| キャラクター | コスト | 残り k |
 | --- | --- | --- |
 | | 1 | 9 |
 | b | 1 | 8 |
 | c | 1 | 7 |

 再構築された文字列は空です。 個別カウントは 0 になります。すべての文字を削除してもコストは 3 だけなので、これは有効です。 

もう 1 つの微妙なシナリオは、複数の文字タイプが同じ頻度を共有する場合です。```
aabbcc
2
```すべての頻度は 2 です。アルゴリズムは、並べ替え順序に応じて、それらのいずれかを削除する可能性があります。 それが削除される場合`'a'`、結果は次のようになります`"bbcc"`2 つの異なる文字で。 

どの削除を選択してもコストは同じであるため、これは依然として最適です。 この問題は有効な答えを受け入れるため、同点は重要ではありません。
