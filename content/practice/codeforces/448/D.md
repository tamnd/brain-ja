 ## 解決策
 ## 問題の理解

 私たちは、行内のセルが配置される概念的な乗算グリッドを使用しています。`i`そしてコラム`j`値が含まれています`i × j`。 このテーブルを明示的に作成する代わりに、すべてをリストすることを想像します。`n × m`値を降順に並べ替えます。 タスクは、position に表示される値を見つけることです。`k`このソートされたリストにあります。 

重要な問題はスケールです。 テーブルの両方の次元は最大 500,000 まで大きくなり、要素の総数は最大 2.5 × 10¹¹ になります。 すべての値を生成または並べ替えようとするアプローチは、直ちに実行不可能になります。 すべての行と列を明示的に反復することさえ、時間制限内では不可能です。 

これにより、テーブルを直接構築することはなく、代わりに値の数を推論するという戦略に向かうことになります。 

繰り返し値が多数存在する場合、微妙なエッジ ケースが発生します。 たとえば、次のような小さなテーブルでは、`n = 3, m = 3`、値`2`が複数回出現します。 A naive flatten-and-sort approach would still work conceptually, but would fail due to memory and time limits. もう 1 つのエッジケースは次のような場合です`k = 1`、答えは常にあります`1`、そしていつ`k = n × m`、答えはどこにありますか`n × m`。 適切なソリューションでは、特別なケースを使用せずにこれらの境界を自然に処理する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 私たちはあらゆる製品を生み出します`i × j`、それらをリストに保存し、リストを並べ替えて、`k`- 番目の要素。 これは、注文するよう求められたマルチセットを明示的に構築するため、正しいです。 ただし、要素数は`n × m`、最悪の場合は約 2.5 × 10¹¹ です。 Python では、10⁷ の整数を格納するだけでもすでに限界があります。 10¹¹を保存することは不可能です。 並べ替えには対数係数も追加されるため、これはまったく使用できなくなります。 

重要な点は、実際には完全にソートされたリストは必要ないということです。 次の形式のクエリに答える必要があるだけです。テーブル内のエントリの数が、ある値以下であるかどうか`x`。 この数を効率的に計算できれば、答えに対して二分探索を使用できます。 

固定の場合`x`、各行`i`貢献する`min(m, x // i)`値、行にあるため`i`、すべての列`j`そのような`i × j ≤ x`満足する`j ≤ x // i`。 これをすべての行で合計すると、要素の総数 ≤ が得られます。`x`。 

これにより、問題は単調述語検索に変換されます。`x`増加、値の数 ≤`x`決して減りません。 その単調性により、応答空間に対する二分探索が可能になります。`1`に`n × m`。

 | --- | --- | --- | --- |
 | ブルートフォース | O(nm log(nm)) | O(nm) | 遅すぎる |
 | 最適化 (二分探索 + カウンティング) | O(n log(nm)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 次に、応答値に対する二分探索を使用して解を構築します。 

1. 関数を定義する`count(x)`乗算表内の以下のセルの数を返します。`x`。 行ごとに`i`、最大の有効な列は次のとおりです。`x // i`、ただしそれを超えることはできません`m`, そこで追加します`min(m, x // i)`。 
2. 二分探索範囲を次のように設定します。`lo = 1`そして`hi = n × m`。 この範囲には、テーブル内のすべての可能な値が安全に含まれます。 
3. 繰り返し計算する`mid = (lo + hi) // 2`。 
4. コンピューティング`count(mid)`。 この値が少なくとも`k`、 それから`mid`潜在的に答えになるのに十分な大きさなので、次に進みます`hi = mid`。 
5. それ以外の場合は、`k`要素は ≤`mid`したがって、より大きな値が必要なので、次のように移動します。`lo = mid + 1`。 
6. まで続けます`lo == hi`。 その時点で、`lo`少なくとも次のような最小値です`k`要素は ≤ it であり、マルチセット内の k 番目に小さい要素の定義と一致します。 

各ステップが有効である主な理由は、`count(x)`は単調です`x`。 一度の値`x`少なくとも含めるのに十分な大きさです`k`要素では、より大きな値もすべてこのプロパティを満たすため、二分探索では境界が正しく分離されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_leq(n, m, x):
    total = 0
    for i in range(1, n + 1):
        total += min(m, x // i)
    return total

def main():
    n, m, k = map(int, input().split())

    lo, hi = 1, n * m

    while lo < hi:
        mid = (lo + hi) // 2
        if count_leq(n, m, mid) >= k:
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    main()
```主要な実装の詳細は次のとおりです。`count_leq`関数。 テーブルの構築を回避し、代わりに寄与度を行ごとに計算します。 各行`i`すべての値に貢献します`i × 1`を通して`i × (x // i)`ですが、上限は次のとおりです。`m`テーブルには`m`列。 

二分探索では、答えが次の範囲内にあるという不変式が維持されます。`[lo, hi]`。 更新ルールは、正確さを維持しながらこの間隔を短縮します。 よくある間違いは、`hi = mid - 1`、これにより、重複に必要な下限スタイル検索が無効になります。 ここでは意図的に保持します`hi = mid`。

 ## 特殊なケース

 のために`n = 1`、テーブルは単一行に縮退します。`[1, 2, ..., m]`。 アルゴリズムは最小の二分探索に帰着します。`x`そのような`x ≥ k`、 以来`count(x)`まさになる`min(m, x)`。 行のみであるため、カウント関数はこれを自然に処理します。`i = 1`貢献します。 

のために`k = 1`、二分探索はすぐに次のように収束します。`1`なぜなら`count(1)`は常に少なくとも 1 です。特別なロジックは必要ありません。 

のために`k = n × m`、検索は最大の製品に向かって進みます`n × m`。 で`x = n × m`、すべてのエントリがカウントされ、述語が true になり、上限が正しく修正されます。 

次のような非常にアンバランスなテーブルの場合`n = 1`そして大きい`m`またはその逆の場合も、ループはすべての行にわたって実行されますが、チェックごとに線形のままであり、二分探索ではこのスキャンの対数反復のみが保証されます。
