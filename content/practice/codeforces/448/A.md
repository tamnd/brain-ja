 ## 解決策
 ## 問題の理解

 私たちには、固定された数の棚と、カップとメダルの 2 つのカテゴリに分けられた報酬のコレクションが与えられます。 各カテゴリはさらに 3 つのランクに分割されますが、配置ロジックでは、これらのランクは各カテゴリ内のアイテムの合計を数える以外には重要ではありません。 

各シェルフには 2 つの構造上の制約があります。 収納できるカテゴリーは 1 つだけなので、カップとメダルを同じ棚に混在させることはできません。 さらに、棚にはカテゴリに応じた容量制限があり、棚あたり最大 5 個のカップと、各棚あたり最大 10 個のメダルです。 

タスクは、これらの制約を尊重しながら、指定された数の棚にすべてのアイテムを配置できるかどうかを判断することです。 

重要な抽象化は、個々のアイテムを順序や順序で配置するのではなく、ビンごとの容量が固定されたビンに数量を詰め込み、ビンが種類ごとに 2 つの独立したグループに分割されるということです。 

制約は小さいです。 すべてのカウントは最大 100 であり、シェルフの数も最大 100 です。これにより、構成を検索したり後戻りしたりする必要がなくなります。 棚へのアイテムの指数関数的な割り当ては、たとえこの規模でも計算上は可能であっても、必要な量をはるかに超えてしまいます。 

素朴ではあるが考えられる間違いは、容量のグループ化を注意深く考慮せずに、貪欲に項目を割り当てようとすることです。 

間違ったアプローチの 1 つは、使用される棚の総数が n を超えないようにすることなく、カップとメダルを個別に配布することです。 たとえば、カップには 3 つの棚が必要で、メダルには 4 つの棚が必要であるが、同じ棚が再利用可能であると誤って想定されている場合、単純な実装ではそれらが誤ってマージされ、誤った YES が生成される可能性があります。 

もう 1 つの微妙なエッジ ケースは、1 つのカテゴリが空の場合です。 たとえば、カップしかない場合、答えは純粋に ceil(total_cups / 5) が n 内に収まるかどうかに依存し、メダル制約によって人為的に棚を消費してはなりません。 

## アプローチ

 強引な解釈では、容量の制約を尊重し、種類が混在しないようにしながら、個々のアイテムを棚に割り当てるすべての可能な方法をシミュレートすることになります。 各項目には最大 n 個の選択肢があり、合計で最大 600 個の項目があるため、これはすぐに天文学的に大きな状態空間との組み合わせになります。 枝刈りを行ったとしても、問題の構造は順序や個々の割り当ての選択に依存しないため、枝刈りは不要です。 

重要な観察は、各カテゴリ内では合計数のみが重要であるということです。 各棚には 1 種類のアイテムの最大数が固定されているため、カップに必要な棚の最小数は、5 個の完全なグループが何個必要かによって完全に決まります。同様に、メダルには 10 個のグループが必要です。カップとメダルにそれぞれ必要な棚の数を計算したら、残る唯一の問題は、必要な棚の合計が n に収まるかどうかです。 

シェルフがタイプ間で共有されないため、この削減は機能します。 棚がカップに割り当てられると、その棚はカップによって完全に消費され、メダルについても同様です。 棚の総数を競う以外の連結はありません。 

したがって、問題は単純な保圧計算とそれに続く実現可能性のチェックになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース割り当て | 指数 | O(n) | 遅すぎる |
 | カウント + 天井分割 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 3 つのカップ タイプをすべて合計して、カップの合計数を計算します。 棚の制約ではランクが区別されないため、これにより問題が単一の数量に集約されます。 
2. total_cups の上限を 5 で割った値として、カップに必要な棚の数を計算します。各棚には最大 5 個のカップを保持できるため、これが必要な棚の最小数を表します。 
3. 同様に、すべてのメダルの種類を合計して、メダルの総数を計算します。 
4. total_medals の上限を 10 で割った値として、メダルに必要な棚の数を計算します。各棚には最大 10 個のメダルを保持できます。 
5. 必要な 2 つの棚数を追加します。 これは、カップとメダルをそれぞれの制約内で最適に割り当てた場合に消費される棚の総数を表します。 
6. この合計を n と比較します。 n 以下の場合は YES、それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 各棚は 1 つのカテゴリに排他的であるため、問題は 2 つの独立したビンパッキング問題に分解されます。 各カテゴリ内では、部分的に満たされている可能性がある 1 つの棚を除いて、すべての棚が最適に満たされており、棚全体でアイテムを再配置しても、棚ごとの使用量を最大化する以上の利点はありません。 したがって、計算された天井値は正確な下限と達成可能な上部構造であり、それらの合計が必要な棚の正確な最小数であることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a1, a2, a3 = map(int, input().split())
    b1, b2, b3 = map(int, input().split())
    n = int(input())

    cups = a1 + a2 + a3
    medals = b1 + b2 + b3

    cup_shelves = (cups + 4) // 5
    medal_shelves = (medals + 9) // 10

    print("YES" if cup_shelves + medal_shelves <= n else "NO")

if __name__ == "__main__":
    solve()
```このソリューションは、容量の制約に影響を与えないため、内部分類を無視して、最初にすべての項目をタイプ別に集計します。 天井の除算は整数演算を使用して実装されます。5 で割る前に 4 を加算することでカップの正しい四捨五入が保証され、10 で割る前に 9 を加算することでメダルの場合も同様になります。 

最終的な比較では、利用可能な棚に対して実現可能性を直接チェックします。 

よくある間違いは、シェルフのタイプを混合できないことを忘れていることです。 もう 1 つは、種類ごとに最適な梱包が常に 1 つの棚を除いて満杯であることを認識せずに、貪欲に商品を配布しようとすることです。

 ## 特殊なケース

 主なエッジケースは、1 つのカテゴリが空の場合です。 カップがゼロだと仮定します。 

入力:```
0 0 0
10 0 0
1
```カップ棚は0、メダル棚は1、合計は1なので出力はYESとなります。 ゼロの天井除算はゼロのままであり、人工的な棚が無駄にならないため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、両方のカテゴリが独立して適合するが、合計すると n を超える場合です。 たとえば:

 入力:```
5 0 0
10 0 0
1
```カップ棚が1枚、メダル棚が1枚、合計2枚なので出力はNOです。 単純な間違いとしては、カップ棚の空きスペースにメダルを詰め込もうとすることが考えられますが、厳密な分離ルールにより無効となります。 アルゴリズムは設計によりこの分離を強制するため、ケースは正しく拒否されます。
