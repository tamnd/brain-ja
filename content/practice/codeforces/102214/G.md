 ## 解決策
 ## 問題の理解

 ゲームは有向グラフとしてモデル化できます。 各文字は頂点であり、すべての単語は最初の文字から最後の文字までの有向エッジです。 プレイヤーがエッジ (u \to v) で表される単語を言ったばかりの場合、次の単語は (v) から始まる必要があるため、次のエッジは頂点 (v) を離れる必要があります。 

タスクは、有効なゲームの動きを通じて、既存のすべての単語から最終的に他のすべての単語に到達できるように、新しい単語をできるだけ少なく、つまり有向エッジをできるだけ少なく追加することです。 入力には最大 (N,M\le 100000) が含まれます。(N) はアルファベットのサイズ、(M) は既存の単語の数です。 公式の制限は 2 秒および 256 MB です。 二次アルゴリズムでは、上限ですでに約 (10^{10}) 回の演算が必要となるため、解は本質的に線形、つまり (O((N+M)\log N)) である必要があります。 

モデリングには微妙な問題が 1 つあります。それは、単語の中に出現しない文字は答えに含めるべきではないということです。 例えば、```
5 1
1 2
```答えがあります`1`。 追加するだけです`2 -> 1`。 5 文字すべてに対して SCC を作成し、孤立した 3 文字を接続が必要なコンポーネントとしてカウントする不注意な実装では、より大きな答えが生成されます。 

もう 1 つのエッジ ケースは、すでに強く接続されているグラフです。 例えば、```
3 3
1 2
2 3
3 1
```答えがあります`0`。 すべての単語から他のすべての単語への有効なルートがすでに存在します。 SCC が 1 つだけであるかどうかを確認せずに、通常のソース/シンク式を盲目的に適用する実装では、誤った値が返されます。`1`。 

セルフループにも注目だ。 のために```
1 1
1 1
```答えは`0`。 単一の単語の後には文字 1 で始まる別の単語のみが続き、同じ文字がその始まりと終わりの両方になります。 アクティブな SCC は 1 つだけであるため、新しいワードは必要ありません。 

最後に、複数の単語が同じエンドポイント文字のペアを持つことができます。 これらはゲーム内では異なる単語ですが、到達可能性の観点からはグラフのエッジと同じように動作します。 SCC の計算では 2 つの文字の間にエッジが存在することだけが必要であるため、エッジが重複してもコンポーネントの構造は変わりません。 

## アプローチ

 直接的なアプローチでは、結果として得られるグラフが強く結びつくまで、候補となる単語を追加していきます。 (N^2) 個の可能な順序付き文字ペアが存在するため、候補単語の可能なサブセットが既に (2^{N^2}) 個存在します。 すべての候補サブセットについて、結果のグラフを構築して到達可能性をチェックする必要があり、最悪の場合は (O(N+M+N^2)) の作業が必要になります。 結果として生じる最悪の場合の演算数は (O(2^{N^2}(N+M+N^2))) ですが、これは非常に小さなアルファベットであっても完全に実行不可能です。 ブルート フォースは、ゲームに必要なプロパティを正確にテストするため、概念的には正しいですが、有向グラフの構造は無視されます。 

重要な観察は、ゲームの状態が、実際に単語に出現する文字によって形成されるグラフの強い接続性と同等であるということです。 単語の最後の文字 (A) から単語の最初の文字 (B) までのパスがあるとします。 (A) を再生し、中間の単語を使用してそのパスをたどり、最終的に (B) を再生することができます。 したがって、すべてのアクティブな文字が他のすべてのアクティブな文字に到達できるとき、すべての単語は他のすべての単語に正確に到達できます。 

問題がこのように表現されると、強く結びついたコンポーネントが全体の構造を与えます。 1 つの SCC 内では、すべての頂点が他のすべての頂点に到達できます。 すべての SCC を 1 つの頂点に縮小すると、結果として得られる凝縮グラフが DAG になります。 複数のコンポーネントがある場合、すべてのソース コンポーネントには入力エッジが必要で、すべてのシンク コンポーネントには出力エッジが必要です。 コンポーネント間に有向エッジを追加すると、両方の要件を解決できます。 

(S) をソース SCC の数、(T) をシンク SCC の数とする。 追加された 1 つの単語には開始点が 1 つだけあり、したがって最大 1 つのソース SCC に入力エッジを提供できるため、少なくとも (S) 個の新しい単語が必要です。 同様に、1 つの追加ワードが最大 1 つのシンク SCC から離れる可能性があるため、少なくとも (T) 個の新しいワードが必要です。 したがって、少なくとも (\max(S,T)) 語が必要です。 

その下限も達成可能です。 シンク コンポーネントをソース コンポーネントに周期的に接続し、カウントが異なる場合にソースまたはシンクを再利用できます。 (K=\max(S,T)) のエッジを追加すると、すべてのソースが入力エッジを受け取り、すべてのシンクが出力エッジを受け取り、結果として生じる凝縮グラフは強く結合されます。 したがって、答えは正確に (\max(S,T)) ですが、アクティブな SCC が 1 つだけあるグラフでは、すでに単語を追加する必要がありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^{N^2}(N+M+N^2))) | (O(N^2+N+M)) | 遅すぎる |
 | SCC凝縮 | (O(N+M)) | (O(N+M)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字を頂点、単語をエッジとして使用して有向グラフを構築します。 反転したグラフも作成します。 孤立した文字は単語間の遷移に影響を与えることができないため、単語の最初または最後の文字として出現する頂点のみが必要です。 
2. Kosaraju のアルゴリズムを使用して、すべての強接続コンポーネントを見つけます。 最初の DFS は頂点を終了順に記録し、反転グラフ上の 2 番目の DFS はコンポーネント ID を逆の終了順に割り当てます。 
3. すべてのアクティブな頂点が 1 つの SCC に属している場合、出力`0`。 すべての単語はすでに他のすべての単語に到達できます。 
4. すべての元のエッジ (u\to v) について、(u) と (v) の SCC 識別子を比較します。 それらが異なる場合、これは凝縮 DAG の 2 つの頂点間のエッジです。 宛先 SCC の内次数と送信元 SCC の出次数を増やします。 
5. 入次数が 0 の SCC と出次数が 0 の SCC をカウントします。 これらは、凝縮グラフのソース コンポーネントとシンク コンポーネントです。 
6. これら 2 つのカウントのうち大きい方を出力します。 これは、すべてのソースが受信接続を必要とし、すべてのシンクが送信接続を必要とする一方、上で説明した循環構造はまさにその数のエッジで両方の要件を達成するため、必要な新しいワードの最小数です。 

### なぜ効果があるのか

 SCC を縮小した後、残りのすべてのエッジが異なるコンポーネント間を移動し、結果として得られるグラフが DAG になります。 ソース コンポーネントには別のコンポーネントからの入力パスがないため、少なくとも 1 つの新しく追加された単語を入力する必要があります。 同様に、シンク コンポーネントは別のコンポーネントに到達できないため、少なくとも 1 つの新しく追加された単語がシンク コンポーネントから離れる必要があります。 したがって、有効な解決策には少なくとも (\max(S,T)) 個の新しい単語が必要です。 

逆に、シンク SCC とソース SCC を取得し、それらを周期的に接続します。 片側のコンポーネントが少ない場合は、必要に応じてその側のコンポーネントを再利用します。 その後、すべてのソースが着信エッジを受信し、すべてのシンクが発信エッジを受信し、循環接続に従ってすべての SCC から他のすべての SCC に移動できます。 各 SCC はすでに内部で強く結合されているため、グラフ全体が強く結合されます。 下限は達成可能であるため、(\max(S,T)) が最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n)]
    rev = [[] for _ in range(n)]
    edges = []
    active = [False] * n

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1

        graph[u].append(v)
        rev[v].append(u)
        edges.append((u, v))

        active[u] = True
        active[v] = True

    # First pass of Kosaraju: finishing order.
    visited = [False] * n
    order = []

    for start in range(n):
        if not active[start] or visited[start]:
            continue

        visited[start] = True
        stack = [(start, 0)]

        while stack:
            u, idx = stack[-1]

            if idx < len(graph[u]):
                v = graph[u][idx]
                stack[-1] = (u, idx + 1)

                if not visited[v]:
                    visited[v] = True
                    stack.append((v, 0))
            else:
                order.append(u)
                stack.pop()

    # Second pass on the reversed graph: assign SCCs.
    comp = [-1] * n
    comp_count = 0

    for start in reversed(order):
        if comp[start] != -1:
            continue

        comp[start] = comp_count
        stack = [start]

        while stack:
            u = stack.pop()

            for v in rev[u]:
                if comp[v] == -1:
                    comp[v] = comp_count
                    stack.append(v)

        comp_count += 1

    if comp_count == 1:
        print(0)
        return

    indeg = [0] * comp_count
    outdeg = [0] * comp_count

    for u, v in edges:
        cu = comp[u]
        cv = comp[v]

        if cu != cv:
            outdeg[cu] = 1
            indeg[cv] = 1

    sources = 0
    sinks = 0

    for c in range(comp_count):
        if indeg[c] == 0:
            sources += 1
        if outdeg[c] == 0:
            sinks += 1

    print(max(sources, sinks))

if __name__ == "__main__":
    solve()
```Kosaraju には 2 つの方向が必要であるため、入力ループは元のグラフと反転したグラフの両方を構築します。 の`active`配列は、孤立したアルファベット文字が意味のあるコンポーネントとして扱われないようにします。 

最初の DFS は再帰的ではなく反復的です。 (N=100000) の場合、再帰的 DFS は Python の再帰制限を超える可能性があり、不必要なインタープリターのオーバーヘッドが発生する可能性もあります。 スタックには、現在の頂点と次の出力エッジのインデックスの両方が格納されるため、再帰を行わずに再帰的な DFS 終了順序を再現できます。 

2 番目の DFS は、反転されたグラフを調べて、到達可能なすべての頂点に 1 つのコンポーネント識別子を割り当てます。 頂点は最初のパスから降順に処理されるため、各トラバースは 1 つの SCC 内に留まります。 

SCC がわかった後は、異なるコンポーネント間で交差するエッジのみが重要になります。 このようなエッジの正確な数は必要ありません。各コンポーネントに少なくとも 1 つの入力エッジまたは出力エッジがあるかどうかだけが必要です。`indeg`そして`outdeg`ブール型のような整数として格納されます。 1 つの SCC 内のエッジは、凝縮 DAG に影響を与えることができないため、無視されます。 

特別な場合`comp_count == 1`ソースとシンクを数える前に処理する必要があります。 単一の成分の場合、凝縮表現ではゼロの入次数とゼロの出力次数を持ちますが、正しい答えは次のとおりです。`0`、 ない`1`。 

Python の整数には任意の精度があるため、整数のオーバーフローの心配はありません。 グラフ ストレージの総量は、頂点とエッジの数に比例します。

```SCC の分解と凝縮に関する情報は次のとおりです。 

| SCC | 頂点 | 度数 | 出次数 | 役割 |
 | --- | --- | --- | --- | --- |
 | 0 | 1、2、3 | 0 | 1 | 出典 |
 | 1 | 4、5、6 | 1 | 0 | シンク |
 | 2 | 7、8、9 | 1 | 0 | シンク |

 ソース SCC が 1 つとシンク SCC が 2 つあるため、アルゴリズムは次のように計算します。`max(1, 2) = 2`。 

2 つの追加のワードにより、概念的には 2 つのシンク コンポーネントをソース コンポーネントに接続し直すことができます。 これらの接続が存在すると、3 つの SCC はすべて、1 つの強く接続された構造内に存在します。 この例は、ソース コンポーネントのみをカウントするだけでは不十分である理由を示しています。到達可能性の両方向を修復する必要があります。 

### 構築例 2

 次のことを考慮してください。```
4 3
1 2
2 3
3 4
```SCC はすべて単一の頂点です。 凝縮グラフは単なるチェーンです。 

| SCC | 頂点 | 度数 | 出次数 | 役割 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 0 | 1 | 出典 |
 | 1 | 2 | 1 | 1 | 内部 |
 | 2 | 3 | 1 | 1 | 内部 |
 | 3 | 4 | 1 | 0 | シンク |

 ソースとシンクが 1 つずつあるため、答えは次のようになります。`1`。 単語を追加する`4 -> 1`チェーンを閉じてサイクルにします。 

このトレースは、ソースとシンクの数が等しい最も単純なケースを示しています。 また、答えが SCC の数から 1 を引いたものではない理由も示しています。 追加された 1 つのエッジにより、最後のシンクを最初のソースに接続して、チェーン全体を修復できます。

            active[v] = True

 ## 特殊なケース

 孤立した文字の場合は、正確な入力を考慮してください```
5 1
1 2
```文字 1 と 2 のみがアクティブになります。 Kosaraju は、アクティブな各文字を含む 2 つの SCC を作成します。 1 つ目は入次数が 0、2 つ目は出次数が 0 であるため、ソース数とシンク数は両方とも 1 になります。 アルゴリズムは戻ります`1`、文字 3、4、5 は正しく無視されます。 

すでに強く接続されているグラフの場合、```
3 3
1 2
2 3
3 1
```3 つの頂点はすべて同じコンポーネント識別子を受け取ります。 アルゴリズムは次の時点ですぐに停止します。`comp_count == 1`チェックして印刷する`0`。 元のグラフでは単語の各ペア間の移動がすでに許可されているため、ソースまたはシンクのカウントは必要ありません。 

単一の非ループワードの場合、```
2 1
1 2
```SCCは2つあります。 頂点 1 はソース、頂点 2 はシンクです。 新しい言葉をひとつ、`2 -> 1`、サイクルを閉じるので、答えは次のようになります。`1`。 これにより、元のエッジが 1 つしかないときに誤ってゼロを返す実装が捕捉されます。 

長い一方向チェーンの場合、```
4 3
1 2
2 3
3 4
```すべての頂点は独自の SCC ですが、頂点 1 だけがソースであり、頂点 4 だけがシンクです。 答えはまだです`1`を追加するため、`4 -> 1`グラフ全体が強く結びつきます。 ソースおよびシンク SCC の代わりに SCC 自体をカウントすると、答えが大幅に過大評価されてしまいます。 

公式サンプルの場合、3 つのサイクルで 3 つの SCC が形成されます。 最初の SCC はソースであり、2 番目と 3 番目はシンクです。 答えは`2`、サンプル出力と一致します。 この例は、シンク コンポーネントの数がソース コンポーネントの数よりも大きい非対称のケースを示しています。これがまさに、式で次の値が使用される理由です。`max(sources, sinks)`。
