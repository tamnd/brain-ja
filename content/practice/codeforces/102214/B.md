 ## 解決策
 ## 問題の理解

 We have a sequence of positive integers`a1, a2, ..., an`。 位置の順序付きペアを数えなければなりません`(i, j)`、許可します`i = j`、二項係数

 [
 \binom{a_i}{a_j}
 】

 奇数です。 

順序は重要です。`(i, j)`そして`(j, i)`は異なるペアです。 異なる位置の等しい値も異なるペアを生成します。 制約により、最大で次のことが許可されます。`10^6`テスト ケース内の各要素間の`1`そして`10^6`、最大 10 個のテスト ケース。 公式声明では、時間制限は 5 秒、メモリ制限は 512 MiB とされています。 

すべてのペアを直接チェックするには、`n^2`小切手。 で`n = 10^6`、つまり`10^12`各二項係数を評価するコストを考慮する前に、ペアを決定します。 これは 5 秒間のコンテスト ソリューションでできることをはるかに超えているため、ソリューションではペアを個別に調べることを避ける必要があります。 

最初の微妙なケースは、`i = j`。 例えば、```
1
1
1
```シングルペアを持っています`(1,1)`、 そして`C(1,1) = 1`、したがって、答えは次のとおりです`1`。 異なる位置のペアのみをカウントするソリューションでは、誤った値が返されます。`0`。 

値の繰り返しも間違いのよくある原因です。 のために```
1
3
1 1 1
```それぞれの`3 * 3 = 9`順序ペアには係数があります`C(1,1) = 1`、したがって、答えは次のとおりです`9`。 位置ペアではなく個別の値ペアをカウントすると、間違った結果が得られます。 このサンプルは公式声明にも記載されています。 

ついに、`C(x,y)`ゼロのとき`y > x`、ゼロは偶数です。 例えば、```
1
2
1 2
```には 4 つの順序ペアがあります。`C(1,1)`そして`C(2,2)`奇数ですが、`C(1,2)=0`そして`C(2,1)=2`は偶数なので、答えは`2`。 ビット条件を正しく処理せずに、すべての値のペアを潜在的に有効なものとして扱う不注意な解決策は、ここで失敗します。 

## アプローチ

 ブルートフォース手法では、順序付けられたすべてのペアを検査します。`(i,j)`そして、`C(a_i,a_j)`奇数です。 まさにあります`n^2`ペアなので最大でも`n = 10^6`がある`10^12`繰り返し。 たとえ奇妙さのテストが定数時間の操作に減らされたとしても、これではすでに遅すぎます。 

有益な観察は、実際には二項係数の値が必要ないということです。 それが奇妙かどうかだけを知る必要があります。 これにより問題は完全に変わります。 

2 つの非負の整数の場合`x`そして`y`、ルーカスの定理モジュロ 2 は次のようになります。 

[
 \binom{x}{y} \equiv
 \prod_k \binom{x_k}{y_k} \pmod 2,
 】

 どこで`x_k`そして`y_k`は対応する 2 進数です。 2進数が貢献します`1`まさにいつ`y_k <= x_k`。 したがって、製品全体は、`1`正確に、すべての設定ビットが`y`にも設定されています`x`。 

ビット単位の表記では、

 [
 \binom{x}{y}\text{ は奇数です}
 \iff
 (x\mathbin{&}y)=y。 
】

 したがって、元の問題ははるかに単純になります。配列要素ごとに`x`、配列要素の数を数えます`y`のサブマスクです`x`。 

仮定する`freq[y]`値の倍数です`y`が発生します。 私たちが欲しいのは

 [
 \sum_x freq[x]\sum_{y\subseteq x}freq[y]。 
】

 内部合計は、まさに標準の Sum Over Subsets DP (一般に SOS DP と呼ばれます) です。 すべてのサブマスクを列挙する代わりに、`x`、すべてのマスクに含まれる配列要素の数を前処理します。 

1 つのペアをチェックするのは概念的には単純であるため、ブルート フォースは機能しますが、二次関数的に多くのペアがあるため失敗します。 奇数の二項係数がサブマスク関係に正確に対応するという観察により、ペアの列挙を可能なビットマスク上の 1 つの SOS DP に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(1) 入力以外 | 遅すぎる |
 | 最適 | O(n + M log M) | お(お) | 承認済み |

 ここ`M`配列の最大値より厳密に大きい 2 の最小累乗です。 以来`a_i <= 10^6`、 我々は持っています`M <= 2^20 = 1,048,576`。 

## アルゴリズムのチュートリアル

 1. 配列を読み取ってビルドする`freq[x]`、各値を含む位置の数`x`。 実際に発生する値のみを考慮するため、最大値も記録します。 
2. 選択します`M`最大値より大きい 2 の最小累乗。 考えられるすべての配列値は次のマスクになります。`[0, M)`。 
3. 配列を初期化する`dp`と`dp[x] = freq[x]`。 この時点で`dp[x]`正確に出現するもののみをカウントします`x`、そのサブマスクではありません。 
4. 各ビットを個別に処理します。 ちょっとの間`b`、そのビットが設定されているすべてのマスクは、そのビットがクリアされた対応するマスクからカウントを受け取ります。 

[
 dp[マスク] \mathrel{+}= dp[マスク \oplus 2^b]。 
】

 最初の数ビットを処理した後、`dp[mask]`すでに処理されたビットがサブマスクを形成するすべての値をカウントします。`mask`。 After all bits have been processed,`dp[x]`等しい

 [
 \sum_{y\subseteq x}freq[y]。 
】

 これは SOS DP の不変条件です。 各遷移によってサブマスクの特定のビットが 0 か 1 かが決定されるため、すべてのサブマスクが 1 回だけ含まれます。 

1. 元の配列を反復処理します。 要素の場合`x`、 がある`dp[x]`ポジション`j`誰の価値`a_j`のサブマスクです`x`。 このような各位置は、次のような奇数の二項係数を与えます。`a_i = x`。 
2.追加`dp[x]`配列の位置ごとに`i`。 応答では個別の値のペアではなく、順序付けされた位置のペアがカウントされるため、繰り返し値は出現ごとに 1 回処理する必要があります。 

### なぜ効果があるのか

 どのペアでも`(i,j)`、 させて`x = a_i`そして`y = a_j`。 ルーカスの定理モジュロ 2 により、`C(x,y)`のすべての設定ビットが正確に奇数になる`y`にも設定されています`x`、これは以下と同等です`(x & y) == y`。 

SOS DP は、ビットのセットを処理した後、次の不変条件を維持します。`dp[x]`処理されたビットが対応するビットのサブマスクである配列値を正確にカウントします。`x`、一方、制限されていないビットは後の遷移によって処理されます。 すべてのビットが処理された後、`dp[x]`したがって、配列のすべての位置をカウントします`j`満足のいく`(x & a_j) == a_j`。 

ポジションごとに`i`、追加`dp[a_i]`その結果、有効な位置が正確にカウントされます`j`とペアになった`i`。 すべての有効な順序付きペアは 1 回カウントされ、無効なペアはカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        mx = max(a)
        size = 1 << mx.bit_length()

        freq = [0] * size
        for x in a:
            freq[x] += 1

        dp = freq[:]

        bit = 1
        while bit < size:
            block = bit << 1
            for start in range(0, size, block):
                end = start + bit
                for j in range(start, end):
                    dp[j + bit] += dp[j]
            bit <<= 1

        ans = 0
        for x in a:
            ans += dp[x]

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```周波数配列には、整数値によって直接インデックスが付けられます。 最大値は最大ですので、`10^6`、その 2 のべき乗拡張は最大でも`1,048,576`エントリー。 

SOS 遷移はブロック単位で記述されます。 一定の長さのブロックの場合`2 * bit`、前半は現在のビットが 0 であるマスクを表し、後半は現在のビットが 1 であるマスクを表します。 後半の各マスクは、前半から対応する値を受け取ります。 これにより、最も内側のループ内の余分なビット テストが回避され、Python では少しクリーンになります。 

ループは次の場合に停止します。`bit == size`したがって、マスク空間によって表されるすべてのバイナリ位置が正確に処理されます。 使用する`mx.bit_length()`常に 20 ビットを固定するのではなく、小規模なテストの方が大幅にコストが安くなります。 

Python の整数はオーバーフローしません。答えは順序付きペアをカウントし、到達できるため、これは重要です。`n²`、 または`10^12`いつ`n = 10^6`。 
SOS DO の後に追加する必要があるため、元の配列は保持されます。`dp[a_i]`発生ごとに 1 回。 周波数配列のみを使用し、個別の値を反復処理するには、現在の値の周波数を個別に乗算する必要があります。これも有効ですが、配列を保持すると、順序付きペアとの対応が明示的になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + M log M) | 頻度の構築と回答の合計には O(n) のコストがかかりますが、SOS DP のパフォーマンスは`M/2`それぞれの追加`log₂M`ビット |
 | スペース | O(n + M) | 入力配列は O(n) を使用し、周波数/DP 配列は O(M) | を使用します。 

この問題については、`M <= 2^20`、したがって、SOS フェーズは約`20 * 2^19 = 10.5 million`最悪の場合は追加も。 これが、ソリューションが 5 秒の制限に適合する主な理由です。`10^12`ブルートフォースのペアチェックはできません。 公式の制限は 5 秒および 512 MiB です。
