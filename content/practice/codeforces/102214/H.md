 ## 解決策
 ## 問題の理解

 この問題では、(n) 個のレッスンを考慮する必要があります。ここで、レッスン (i) は時間間隔 ([l_i,r_i]) を占めます。 2 つのレッスンは、重複しない限り互換性があります。 1 つのエンドポイントでのタッチが許可されるため、([1,3]) と ([3,5]) は互換性があります。 

レッスンを 1 つだけキャンセルしなければなりません。 目標は、キャンセルされたすべての残りのレッスンがペアごとに重複しないすべてのレッスンを見つけることです。 出力は、そのようなレッスンの数と、それに続くインデックスの昇順です。 元の Codeforces の問題は、31C、スケジュール、(n \le 5000)、(l_i,r_i \le 10^6)、制限時間 2 秒、メモリ 256 MB としてリストされています。 

境界 (n \le 5000) はキー制約です。 (O(n^2)) アルゴリズムは最大で約 2,500 万のペア チェックを実行します。これはコンパイル言語では妥当であり、最適化された Python でも管理可能です。 (O(n^3)) アルゴリズムでは、最悪の場合、およそ (5000^3/2 = 625) 億回のペア比較が必要になりますが、これは制限をはるかに超えています。 したがって、キャンセルされる可能性のあるすべてのレッスンについて、すべてのペアを個別にチェックすることを避ける必要があります。 

この問題を考える最も有効な方法は、実際に矛盾する教訓のペアを特定することです。 競合するペアがない場合は、レッスンをキャンセルしても問題ありません。 競合するペアがある場合、レッスンは、競合するすべてのペアに属している場合にのみキャンセルできます。 

エンドポイントのケースは誤って扱われやすいものです。 入力用```
2
1 3
3 5
```正しい出力は```
2
1 2
```レッスンは時間に触れるだけなので 3. を使用した不注意な実装`r >= l`重複条件により、それらが競合していると誤ってみなされるためです。 

もう 1 つの重要なケースは、複数の競合が存在するが、1 つの教訓を共有している場合です。```
3
1 10
2 3
4 5
```正しい出力は次のとおりです```
1
1
```レッスン 1 と 2 は矛盾し、レッスン 1 と 3 は矛盾します。 レッスン 1 を削除すると、両方の競合が解消されます。 どちらかの短いレッスンを削除すると、もう一方の競合はそのまま残ります。 競合するペアを 1 つだけ見つけてその両方のエンドポイントを返すソリューションでは、レッスン 1 と 2 が誤って出力されます。 

最後の境界ケースは、スケジュールがすでに有効である場合に発生します。```
3
1 2
2 4
4 7
```正しい出力は次のとおりです```
3
1 2 3
```エンドポイントの接触が許可されているため、すべてのペアに互換性があります。 この問題ではキャンセルが 1 回だけ必要となるため、すべてのレッスンが有効な選択となります。 

## アプローチ

 直接的な総当たりアプローチでは、キャンセルされる可能性のあるすべてのレッスンが考慮されます。 各候補について、残りの (n-1) 個のレッスンのすべてのペアを調べ、それらの間隔が重複しているかどうかを確認します。 これは正しいです。なぜなら、残りのペアが交差しない場合に、結果として得られるスケジュールが正確に有効になるからです。 ただし、1 つの候補では (O(n^2)) 回の比較が必要で、候補が (n) 個あるため、(O(n^3)) 回の時間がかかります。 (n=5000) の場合、これは最悪の場合でも (625) 億ペア チェック程度になります。 

問題の構造により、この作業のほとんどすべてを繰り返す必要がなくなります。 キャンセルの可能性があるすべてのペアが重複するかどうかを尋ねる代わりに、最初に元のスケジュールでどのペアが重複しているかを判断できます。 (m) 個の競合するペアがあるとします。 レッスン (i) がキャンセルされた場合、まさに (i) を含む競合するペアが消滅します。 したがって、(m) 個の競合するペアのすべてに (i) が含まれている場合に、キャンセルが正確に機能します。 

これにより、非常に単純なカウント基準が得られます。 レッスンごとに、そのレッスンに含まれる競合するペアの数を数えます。 競合するペアの総数が (m) である場合、レッスン (i) は、その競合数が (m) のときに正確に有効なキャンセルになります。 

順序付けされていないペアをすべて 1 回チェックすることで、競合するペアをすべて見つけることができます。 このようなペアは (O(n^2)) 個だけなので、これは制約に適合します。 ペアを保存する必要さえありません。 必要なのは、競合の総数と、レッスンごとに、それに影響する競合の数だけです。 

2 つのアプローチは次のように比較できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^3)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n^2)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのレッスン間隔を読み取り、その開始時間と終了時間を元のインデックスとともに保存します。 
2. 配列を作成する`conflicts`どこ`conflicts[i]`レッスン (i) と重複する他のレッスンの数をカウントします。 メンテナンスも行います`total_conflicts`、重複する順序のないペアの総数。 
3. レッスンのすべてのペアを調べます (i<j)。 それらは正確に重なるとき`l[i] < r[j] and l[j] < r[i]`。 

この厳密な比較により、間隔共有のエンドポイントに互換性が生まれます。 ペアが重なった場合、インクリメントします`total_conflicts`、`conflicts[i]`、 そして`conflicts[j]`。 
4. すべてのペアが処理された後、すべてのレッスン (i) を調べます。 もし`conflicts[i] == total_conflicts`、そのインデックスを回答に追加します。 

その理由は、(i) をキャンセルすると、(i) を含む競合するペアが正確に削除されるためです。 すべての競合は、すべての競合に (i) が含まれる場合にのみ消滅します。 
5. 有効なインデックスの数を出力し、次にインデックス自体を昇順に出力します。 インデックス 1 から (n) までのレッスンを検査するため、収集されたインデックスには必要な順序がすでに設定されています。 

### なぜ効果があるのか

 競合するすべてのレッスン ペアのセットを考えます。 その大きさを(m)とします。 レッスン (i) をキャンセルすると、(i) を含む競合にのみ影響する可能性があるため、正確には`conflicts[i]`矛盾するペアが消えます。 すべて (m) の競合するペアが消えると、残りのスケジュールには重複がなくなります。 したがって、レッスン (i) は、まさに次の場合に有効な答えです。`conflicts[i] = m`。 

(m=0) の場合、すべてのレッスンの競合カウントは 0 であるため、すべてのレッスンが正しく受け入れられます。 (m>0) の場合、同じ等式により、すべての競合に関与するレッスンが正確に識別されます。 したがって、アルゴリズムはすべての有効なキャンセルを正確に出力します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    intervals = [tuple(map(int, input().split())) for _ in range(n)]

    conflicts = [0] * n
    total_conflicts = 0

    for i in range(n):
        li, ri = intervals[i]
        for j in range(i + 1, n):
            lj, rj = intervals[j]

            # The intervals overlap only if neither one ends
            # at or before the other one starts.
            if li < rj and lj < ri:
                total_conflicts += 1
                conflicts[i] += 1
                conflicts[j] += 1

    answer = [
        i + 1
        for i in range(n)
        if conflicts[i] == total_conflicts
    ]

    print(len(answer))
    print(*answer)

if __name__ == "__main__":
    solve()
```間隔リストには入力が指定されたとおりに保存されるため、元のレッスン インデックスは単に 0 から始まる位置に 1 を加えたものになります。 間隔を並べ替える必要がないため、出力順序も自然になります。 

ネストされたループでは、`i + 1`の出発点として`j`したがって、順序付けされていない各ペアは 1 回だけ検査されます。 重複条件では厳密な不等式が使用されます。 例えば、`[1,3]`そして`[3,7]`どちらも満たさない`1 < 7`そして`3 < 3`一緒にあるため、それらは重複しないものとして正しく扱われます。 

競合するペアごとに、そのペアの両方のエンドポイントが 1 つの競合カウントを受け取ります。 レッスンが 5 つの異なる競合ペアに参加している場合、そのカウンターは 5 になります。 競合がそれらのみの場合、合計カウンタも 5 になるため、そのレッスンは有効なキャンセルになります。 

Python の整数には任意の精度があるため、オーバーフローの心配はありません。 実際、競合するペアの最大数は (\binom{5000}{2}=12,497,500) のみであり、これは通常の整数演算には十分小さいです。

 ## 特殊なケース

 エンドポイントタッチについては、次の点を考慮してください。```
2
1 3
3 5
```ペアテストで評価されるのは、`1 < 5`本当ですが、`3 < 3`false であるため、ペアは競合としてカウントされません。 合計競合数は 0 で、両方のレッスンの競合数は 0 で、出力は次のようになります。```
2
1 2
```これが、厳密な不等式ではなく、厳密な不等式を使用する理由です。`<=`が不可欠です。 

よくある相反する教訓については、次のように考えてください。```
3
1 10
2 3
4 5
```ペア`(1,2)`そして`(1,3)`対立しながらも`(2,3)`しません。 競合カウントは次のとおりです。`[2,1,1]`競合の総数は`2`。 レッスン 1 のみ競合数が合計と等しいため、出力は次のようになります。```
1
1
```レッスン 1 を削除すると、両方の競合が一度に解消されます。 

すでに有効なスケジュールについては、次のことを考慮してください。```
3
1 2
2 4
4 7
```すべてのペアは、次のペアの前に完全に存在するか、エンドポイントで接触します。 したがって、競合の総数はゼロになります。 すべてのレッスンには競合がないため、すべてのインデックスは満たされます。`conflicts[i] == total_conflicts`、生産```
3
1 2 3
```密集した競合グラフの場合は、5000 個の同一間隔を考慮します。`[1,2]`。 すべてのペアは競合するため、競合するペアは 12,497,500 個になります。 各レッスンには 4,999 件が参加しています。 以来`4999 != 12497500`、どのようなレッスンもそれ自体ですべての矛盾を解消することはできず、正解はゼロです。 このアルゴリズムは、レッスンごとに合計数と 1 つのインシデント数のみを保存するため、競合するペアの膨大なセットを構築せずにこれを処理します。
