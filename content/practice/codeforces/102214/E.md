 ## 解決策
 ## 問題の理解

 長さ n の小文字の文字列があります。 暗号化中、最大の約数から始まり 1 で終わる n のすべての約数 d を調べます。そのような各約数について、最初の d 文字で構成されるプレフィックスを反転します。 

たとえば、n=10 の場合、その約数は降順で 10、5、2、1 になります。 したがって、暗号化では、最初に文字列全体、次に最初の 5 文字、次に最初の 2 文字、最後に最初の文字という 4 つのプレフィックス反転が実行されます。 

入力により、元の文字列ではなく、暗号化された文字列が得られます。 元の文字列を回復する必要があります。 

長さは最大 100 で、文字列には小文字の英字のみが含まれます。 100 という制限は小さいため、必要なすべての反転の単純なシミュレーションでも十分に高速です。 高度な文字列アルゴリズムやデータ構造は必要ありません。 主な困難は、可逆操作を適用する必要がある方向を認識することです。 

最初のエッジ ケースは n=1 です。 例えば：```
1z
```唯一の約数は 1 であり、1 文字の接頭辞を反転しても何も変わりません。 答えは次のとおりです。```
z
```逆にすべき重要なプレフィックスが常に存在すると想定する不注意な実装では、このケースを誤ってスキップしたり誤って処理したりする可能性があります。 

n 自体が関係する唯一の大きな除数である場合、別の特殊なケースが発生します。 例えば：```
2ab
```約数は 1 と 2 です。復号化ではこれらを昇順に処理します。 最初の文字を反転しても何も変化せず、最初の 2 文字を反転すると変化します`ab`の中へ`ba`したがって、正しい答えは次のとおりです。```
ba
```復号化中に約数を降順で処理する場合、演算を元に戻すのではなく、暗号化と同じ順序で実行することになります。 

3 番目のよくある間違いは、すべての除数演算がその除数で始まるブロックではなくプレフィックスに作用することを忘れていることです。 たとえば、n=6 の場合、除数 3 は位置 1 ～ 3 を反転することを意味します。位置 3 ～ 6 を反転することを意味するわけではありません。 

## アプローチ

 この問題を考える強引な方法は、考えられる元の文字列を列挙し、指定された暗号化文字列が生成されるまで各候補を暗号化することです。 暗号化操作自体は決定論的であるため、そのような候補を検証するのは簡単です。 ただし、長さ n の小文字文字列は 26 n 通りあります。 n=20 の場合でも、これは 26 20、およそ 2 94 となり、まったく実行不可能です。 ブルート フォースは概念的には正しいですが、暗号化プロセス自体は完全に元に戻せるにもかかわらず、膨大な空間を検索するため失敗します。 

重要な観察は、すべての暗号化操作は反転であり、反転はそれ自体の反転であるということです。 プレフィックスを 2 回反転すると、元のプレフィックスが正確に返されます。 他の唯一の問題は、操作の順序です。 

暗号化が操作に適用されると仮定します

 Rd1、Rd2、…、Rdk

 約数が満たされるところ

 d 1 >d 2 >⋯>d k 。 

暗号化された文字列は、

 R d k (…R d 2 (R d 1 (s))…)。 

これを元に戻すには、まず R d k を元に戻し、次に R d k−1 を元に戻す、という手順を繰り返す必要があります。 各反転はそれ自体の反転であるため、復号化では同じプレフィックス反転を逆の順序で適用するだけです。 

暗号化では最大から最小の約数を参照するため、復号化では最小から最大の約数を参照します。 

これにより、問題全体が直接的なシミュレーションに変わります。 1 から n までのすべての d について、d が n を割る場合、最初の d 文字を反転します。 これはまさに、公式の Codeforces 編集ソリューションで使用されているアプローチです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(26 n ⋅n) | O(n) | 遅すぎる |
 | 最適 | O(∑ d∣n d) | O(n) | 承認済み |

 n≤100 であるため、単純な実装でも問題なく制限内に収まります。 すべての約数の合計も漸近的に O(nloglogn) になるため、はるかに大きな境界の下でも直接シミュレーションは効率的です。 

## アルゴリズムのチュートリアル

 1. n と暗号化された文字列 t を読み取ります。 すべての復号化操作では文字の順序のみが変更されるため、この文字列を適切な場所で変更します。 
2. d を 1 から n まで繰り返します。 nmodd=0 の場合、d は暗号化中に反転されたプレフィックスの 1 つです。 
3. 長さ d のプレフィックスを反転します。 暗号化では同じ約数が降順で処理され、すべての反転はそれ自身の逆であるため、約数を昇順で処理します。 
4. すべての約数が処理されたら、結果の文字列を出力します。 この時点で、すべての暗号化操作はまったく逆の順序で元に戻されます。 

### なぜ効果があるのか

 n の約数を昇順に d 1 <d 2 <⋯<d k とします。 暗号化は、 d k 、d k−1 、…、d 1 の順序で反転を適用します。 復号化には R d 1 ,R d 2 ,…,R d k が適用されます。 すべてのプレフィックス反転 R d について R d (R d (x))=x であるため、各復号化操作は対応する暗号化操作をキャンセルします。 操作は逆の順序でも適用されるため、すべての変換は正確な時点でキャンセルされます。 したがって、最終的な文字列は一意の元の文字列になります。 

## Python ソリューション```python
Pythonimport sysinput = sys.stdin.readline

def solve():    n = int(input())    s = list(input().strip())
    for d in range(1, n + 1):        if n % d == 0:            s[:d] = reversed(s[:d])
    print(''.join(s))

if __name__ == "__main__":    solve()
```Python 文字列は不変であるため、文字列はリストに変換されます。 表現`s[:d]`は最初の d 文字を正確に表し、問題の接頭辞の反転と一致します。 

ループは次から始まります`1`そしてで終わります`n`, したがって、考えられるすべての約数が考慮されます。 チェック中`n % d == 0`必要なプレフィックス長を正確に識別します。 

課題```

```接頭辞をその逆の接頭辞に置き換えます。 順序は非常に重要です。 小さい約数から大きい約数まで反復すると、暗号化シーケンスの逆が実行されます。 

Python では整数オーバーフローの懸念はありません。 Python のスライスであるため、off-by-one の問題もありません。`s[:d]`インデックスが含まれています`0`を通して`d-1`、まさにd文字。

 ## 特殊なケース

 n=1 の場合、入力```
1z
```除数は 1 のみです。アルゴリズムは 1∣1 をチェックし、最初の文字を反転して、次の結果を取得します。`z`また。 印刷します`z`したがって、単一文字の接頭辞には特別なケースは必要ありません。 

n=2 の場合、次のように考えます。```
2ab
```除数の増加シーケンスは 1、2 です。 長さ 1 の反転葉`ab`変わらない。 長さ 2 の反転により、`ba`。 暗号化`ba`文字列全体を反転して返します`ab`、昇順が正しい逆順であることを確認します。 

すべての文字が等しい入力の場合、次のようになります。```
8aaaaaaaa
```反転するたびに、表示される文字列は変更されません。 アルゴリズムは引き続き約 1、2、4、8 を処理しますが、すべての中間状態は残ります。`aaaaaaaa`。 これにより、異なる文字に誤って依存する実装が捕捉されます。 

最後に考えてみましょう```
6fedcba
```約数は 1、2、3、6 です。 これらの長さのプレフィックスをその順序で反転すると、文字列は次のようになります。`abcdef`。 2、3、および 6 がすべて同じ最初の位置と相互作用するという事実により、これは、復号化中に約数を降順で処理するという最も一般的な間違いに対する有用なテストになります。 このソリューションでは、暗号化シーケンスを正確に逆にすることで、その間違いを回避します。
