 ## 問題の理解

 以下のみで構成されるバイナリ文字列が与えられます。`0`そして`1`。 私たちが注目する値は、この文字列内の反転の数です。反転は位置のペアです。`i < j`そのような`1`の前に表示されます`0`。 つまり、毎回、`1`の左側にあります`0`、これはコストに 1 単位を寄与します。 

最大 1 つの操作を実行できます。つまり、隣接する 2 つの文字を選択し、それらを交換します。 何もしないことを選択することもできます。 このオプションの 1 回のスワップ後の目標は、反転の総数を最小限に抑えることです。 

この問題は入力サイズが小さいですが、単一の隣接するスワップが局所的にだけでなく、スワップされたペアの両側のすべての文字との相互作用を通じて反転カウントを変更する可能性があるため、構造は微妙です。 

ここでの自然な制約は、文字列の長さが小さい (最大 100) ということです。 これにより、テスト ケースごとのおよそ 2 次推論よりも複雑なものは即座に排除されます。 考えられるすべてのスワップを試した後、反転カウントを最初から再計算するソリューションは、複雑さの点ではすでに許容可能ですが、重要な難点は、それをクリーンに実行し、スワップの下で反転カウントがどのように変化するかを見逃さないことです。 

いくつかの特殊なケースは、見た目よりも重要です。 なしの文字列`10`のようなパターン`0000`または`1111`隣接する等しい文字を交換しても何も変わらないため、動作は自明です。 のような文字列`1000`最初の 2 文字を交換すると、一度に複数の反転が減少するため、より興味深いです。 もう 1 つの注意が必要なケースは、最適なスワップがローカル インバージョンを直ちに削減するものではない場合です。たとえば、`1010`、完全な効果を計算しない限り、最適なスワップは明らかではありません。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべての可能な隣接スワップを試し、結果の文字列の反転数を計算し、最小値を取得します。 多くてもあります`n - 1`スワップ、および各反転計算は次のように実行できます。`O(n)`スキャンして数を数えることによって`1`これまでに何回見られましたか`0`彼らの後を追って来る。 これにより、`O(n^2)`テストケースごとに、これですでに十分です`n ≤ 100`。 

重要な点は、制約が小さいため、実際には最適化された方法ですべてを最初から再計算する必要がないということです。 ただし、交換によって反転が変化する理由を理解することは依然として重要です。隣接する 2 つの文字の交換は、交換されたインデックスの周囲の位置を含むペアにのみ影響します。 遠くにあるものはすべて変わらない。 つまり、完全な再計算の方が簡単で安全であるにもかかわらず、反転カウントの違いを局所的に推論できるということです。 

したがって、最適なアプローチは基本的に、正しい反転カウンターを使用した制御されたブルート フォースです。 本当の洞察は、アルゴリズムによる縮小ではなく、問題のサイズによってすべての状態を直接評価できることを認識することです。

 ## アルゴリズムのチュートリアル

 元の文字列と、1 つの隣接するスワップによって形成されたすべての文字列を評価するという考えを修正します。 

1. 元の文字列の反転回数を計算します。 これを行うには、左から右にスキャンし、その数を維持します。`1`が見られました。 私たちが見るたびに、`0`の数と同じだけ多くの反転に寄与します。`1`すでに見られています。 
2. 操作を実行することは許可されていないため、この元の反転カウントで答えを初期化します。 
3. インデックスごとに`i`から`0`に`n - 2`、スワップをシミュレートします`s[i]`そして`s[i + 1]`。 これにより、これら 2 つの位置のみが異なる候補文字列が作成されます。 
4. このような交換された文字列ごとに、ステップ 1 と同じスキャン方法を使用してその反転数を再計算します。 
5. すべての候補にわたって最小値を維持します。 

以前の答えを調整するのではなく明示的に再計算する理由は、文字列が十分に小さいため、微細な最適化よりも明確さの方が価値があるためです。 スワップは、ポジションに関係するすべての反転に影響します。`i`そして`i + 1`そして、これらすべての寄与を正しく追跡することは、複雑さの点で再計算と同等です。 

### なぜ効果があるのか

 許可された操作によって到達可能なすべての有効な状態は、元の文字列か、単一の隣接するペアを交換することによって形成された文字列のいずれかです。 アルゴリズムは、そのようなすべての状態を徹底的に評価します。 逆関数は状態ごとに完全に再計算されるため、スワップ間の相互作用が失われることはありません。 したがって、この有限セットの最小値が真の最適値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def inversion_count(s):
    ones = 0
    inv = 0
    for ch in s:
        if ch == '1':
            ones += 1
        else:
            inv += ones
    return inv

def solve():
    s = list(input().strip())
    n = len(s)

    best = inversion_count(s)

    for i in range(n - 1):
        s[i], s[i + 1] = s[i + 1], s[i]
        best = min(best, inversion_count(s))
        s[i], s[i + 1] = s[i + 1], s[i]

    print(best)

if __name__ == "__main__":
    solve()
```このソリューションでは、反転カウントをヘルパー関数に分離して、各候補状態を一貫して評価できるようにします。 スワップ ループは、各トライアル スワップの後に慎重に文字列を復元するため、偶発的な状態の破損が回避されます。 

微妙な点は、スワップ間で反転数を増分的に維持しようとしていないことです。 それは可能ですが、交換された位置の変化を伴う反転がどのように変化するかについて多くの特殊なケースが導入されます。 再計算により、この制約による無視できるコストで、これらの落とし穴がすべて回避されます。

 ## 特殊なケース

 すべて同一の文字の文字列は、反転を作成または削除できないため、自明に動作します。 アルゴリズムは引き続きスワップを評価しますが、各スワップは同じ反転カウントを生成するため、最小値は変わりません。 

のような文字列`1000`単一のスワップの最も強力な効果を示します。 最初は 3 つの反転があります。 最初の 2 文字を交換すると、`0100`これにより、すべての反転が排除されます。`1`の前にある`0`その後。 このアルゴリズムは、ローカルな変更のみを想定するのではなく、スワップされた状態ごとに反転カウントを再計算するため、これを正確に捉えます。 

のような文字列`0101`スワップが常に役立つとは限らないことを明らかにしています。 一部のスワップでは反転が増加しますが、アルゴリズムは常に元の構成と比較し、すべての候補にわたって最小値を維持するため、それらを安全に無視します。
