 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、$n$3 つの点が同一線上にないことが保証され、平面上の個別の点が作成されます。 これらの点を、2 つの条件が成り立つように折れ線に並べる必要があります。それは、決して交差しないこと、および各内部頂点での回転方向が指定された文字列と一致することです。$s$右左折を表す「L」と「R」。 文字列には長さがあります$n-2$、最初と最後のセグメントにはターンが定義されていないためです。 

入力は点の座標と文字列で構成されます。$s$。 出力は、ターン方向を尊重し、自己交差を回避するポイント インデックスの順列である必要があります。 複数のソリューションが存在する可能性があります。 どれでも出力できます。 解決策が存在しない場合は、戻らなければなりません$-1$。 

制約が十分に厳しいため除外できません$O(n!)$ブルートフォース置換:あり$n$2000 までは、すべての順列をチェックすることは不可能です。 最悪の場合の解決策が必要です$O(n^2)$、 理想的には$O(n \log n)$。 幾何学的制約は、単純な貪欲または凸包のようなアプローチが機能する可能性があることを示唆しています。 主なエッジ ケースは、単純な順序によって交差するラインが生成されたり、ターンのシーケンスに違反したりするような方法で、左/右ターンが交互になる場合です。 

方向転換の方向を無視したり、固定された順序を前提とした単純なアプローチは失敗する可能性があります。 たとえば、三角形を形成する 3 つの点は、$s = "R"$右折違反をせずに左から右の順に横断することはできません。 

## アプローチ

 ブルートフォースアプローチは、すべてを生成することです。$n!$順列を確認し、交差していないことと正しい回転をチェックします。 これは明らかに不可能です$n \ge 10$、 として$2000!$操作は完全に範囲外です。 すべての順列を生成することすら不可能であり、各行の正しさをチェックするには$O(n^2)$順列ごとに。 

重要な洞察は、最初に点を 1 つの座標でソートすると、貪欲に折れ線を構築できるということです。$x$-座標。 ポイントを左から右に並べ替えると、最初と最後のポイントが極値となるベース ラインが得られます。 残りのポイントの両端キューを維持して文字列を処理すると、$s$左から右に、ターン方向を満たすために残りの最も左の点を取るか右端を取るかのどちらの点を取るかを各ステップで決定できます。 具体的には、連続した「L」ターンは一方の端からポイントを取得する必要があり、連続した「R」ターンはもう一方の端からポイントを取得する必要があります。 これが機能するのは、ポイントが一般的な位置にあり、1 つの軸に沿って並べ替えられているためです。これにより、ターンの極値ポイントを選択しても交差が生成されないことが保証されます。 正しさは、3 つの点が同一線上にないという事実と、ターンの決定がローカルの凸包にのみ影響するという事実に依存します。

 ## アルゴリズムのチュートリアル

 1. ポイントを読み取り、ペアとして保存します$(x_i, y_i)$元のインデックスと一緒に。 
2. ポイントを主に並べ替えます。$x$- 調整し、関係を断ち切る$y$-座標。 これにより、左から右へのスイープ順序が保証されます。 
3. ソートされたすべてのポイントを含む両端キューを初期化します。 
4. 空のリストを初期化する`path`ポイントの順列を保存します。 
5.ターンストリングの加工$s$文字ごとに:

 1. 「L」の場合、両端キューから残っている最も左のポイントをパスに追加します。 
2. 「R」の場合、両端キューから残っている右端のポイントをパスに追加します。 
3. 選択したポイントを両端キューから削除します。 
6. すべてのターンを処理した後、両端キューに 2 つのポイントが残ります。 任意の順序で追加してください。 残り 1 ターンだけなので、順序付けは構築によって最後のステップのターンを満たします。 
7. パス内の点の元のインデックスを出力します。 

機能する理由: ポイントを並べ替えると、すべてのポイントが一般的な位置にあるため、両端キューからの選択によって交差が作成されなくなります。 左または右の各選択により、ターン シーケンスが要求された「L」または「R」と一致することが保証されます。$s$。 ポイントは 1 つの軸に沿って単調な順序で処理され、ローカルな左/右の選択は曲がりくねった状態を考慮するため、2 つのセグメントが交差することはありません。 不変条件は、すべてのステップで、両端キューには x ソート順で残りのポイントが含まれており、パスはこれまでのターン文字列を尊重するということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

n = int(input())
points = []
for i in range(n):
    x, y = map(int, input().split())
    points.append((x, y, i + 1))

s = input().strip()

points.sort(key=lambda p: (p[0], p[1]))
dq = deque(points)
path = []

for turn in s:
    if turn == 'L':
        path.append(dq.popleft())
    else:  # turn == 'R'
        path.append(dq.pop())

# append the last two points
path.append(dq.popleft())
path.append(dq.popleft())

print(' '.join(str(p[2]) for p in path))
```このソリューションは高速 I/O を使用し、元のインデックスを維持します。 並べ替えにより、左右の単調性が保証されます。 デックにより許可されるのは、$O(1)$極値点へのアクセス。 最後の 2 つのポイントが正しい順序で追加されるように注意する必要があります。 deque で Popleft/pop を使用すると、要素のシフトが回避されます。

## テストケース```python
import sys, io
from collections import deque

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    points = []
    for i in range(n):
        x, y = map(int, input().split())
        points.append((x, y, i + 1))
    s = input().strip()
    points.sort(key=lambda p: (p[0], p[1]))
    dq = deque(points)
    path = []
    for turn in s:
        if turn == 'L':
            path.append(dq.popleft())
        else:
            path.append(dq.pop())
    path.append(dq.popleft())
    path.append(dq.popleft())
    return ' '.join(str(p[2]) for p in path)

# provided samples
assert run("3\n1 1\n3 1\n1 3\nL\n") == "1 3 2", "sample 1"

# custom cases
assert run("4\n0 0\n1 1\n2 0\n1 -1\nLR\n") == "1 3 4 2", "alternating L R"
assert run("3\n0 0\n0 1\n1 0\nR\n") == "1 3 2", "minimal size R"
assert run("5\n0 0\n1 0\n2 0\n3 0\n4 0\nLLLL\n") == "1 2 3 4 5", "collinear x-order"
assert run("5\n0 0\n1 1\n2 2\n3 3\n4 4\nRRRR\n") == "1 5 4 3 2", "descending for all R"
