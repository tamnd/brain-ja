 ## 解決策
 ## 問題の理解

 からの数値の順列を再構築するように求められます。`1`に`n`という部分的に既知の配列が与えられると、`next`。 各要素`next[i]`最小のインデックスを表します`j`より大きい`i`そのような`p[j] > p[i]`。 そうでない場合`j`存在します、`next[i]`に設定されています`n+1`。 もし`next[i]`読めません、そうです`-1`。 

タスクは、指定された条件と一致する順列を見つけることです。`next`配列を使用するか、そのような順列が存在しないと判断します。 これは、可能性を数えることが求められるのではなく、有効な順列を 1 つ生成することが求められる建設的な問題です。 

制約は大きいです:`n`テスト ケースごとに最大 500,000 件に達する可能性があり、合計`n`すべてのテスト ケースは 500,000 です。 これにより、次のようなアルゴリズムが除外されます。`O(n^2)`複雑。 理想的には、テスト ケースごとに線形に近い時間が必要です。`O(n)`または`O(n log n)`。 

明らかではないエッジケースには次のようなものがあります。 

1.すべて`next[i] = -1`。 この場合、どのような順列も有効です。 
2.`next[i] = i + 1`繰り返し。 これにより、厳密に増加するサブシーケンスが強制されます。 
3. いくつか`next[i]`値は互いに矛盾します。例:`next[1] = 3`そして`next[2] = 2`。 有効な順列が存在しません。 

単純なアプローチでは、すべての順列を試行しようとする可能性がありますが、`n!`可能性はありますが、これは不可能です。 の制約を使用する貪欲な、または構造化されたアプローチが必要です。`next`効率的に配列します。 

## アプローチ

 ブルートフォースアプローチでは、すべての順列を試して、`next`配列。 これは`O(n!)`そして不可能です`n`500,000まで。 

問題を観察すると、次のことがわかります。`next[i]`基本的には一連の制約をエンコードします。`p[i] < p[next[i]]`。 これらを有向辺とみなすと、`i`に`next[i]`（もし`next[i] != -1`)、順列は一連の増加シーケンスを満たすものとみなすことができます。 重要な洞察は、定義された 2 つの間の関係です。`next`インデックスの場合、値は制約に違反することなく降順で入力できます。これは、次のように定義されたシーケンスの左端の値が右端の値より小さくなければならないためです。`next[i]`。 

現在開いているシーケンスを維持するためにスタックを使用して、配列を左から右に貪欲に処理できます (次に大きな要素のシーケンスを構築するのと同様)。 とき`next[i]`が定義されている場合、「次に大きい」要件を満たすために、使用可能な最大の数値がシーケンスの最後の位置に割り当てられていることを確認する必要があります。 制約のない位置の場合 (`-1`)、残りの利用可能な値の範囲内で任意に数値を入力できます。 

このアプローチでは、配列を 1 回反復し、開いているシーケンスを追跡し、各シーケンス内で降順に番号を割り当てるという問題が軽減されます。 結果は`O(n)`テストケースごとに、これは実現可能です。

 ## アルゴリズムのチュートリアル

 1. 利用可能な数値のセットを次から初期化します。`1`に`n`。 このセットから番号を割り当てます。 
2. から反復処理`n`まで`1`。 最大の数値は定義されていない位置に移動する必要があるため、最後から処理します。`next`または、「シーケンス」の最後は次のとおりです。`next`。 
3. 右側のより大きな番号を待機しているポジションを表すスタックを維持します。 インデックスごとに`i`、 もし`next[i]`が定義されており、`next[i] > i+1`、プッシュポジション`i`に`next[i]-1`をスタックに追加して降順の値を割り当てます。 
4. ポジションについては、`next[i] = -1`または`next[i] = i + 1`、次に大きい利用可能な番号を割り当てます。 これにより、柔軟性を最大限に高めながら、すべての制約が満たされます。 
5. ループ後、違反せずに番号を割り当てることができない場合`next`、 戻る`-1`。 
6. それ以外の場合は、構築された順列を出力します。 

不変条件は、以下の各シーケンスが`i`に`next[i]-1`厳密に降順で埋められます。`p[i] < p[next[i]]`。 これにより正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        nxt = list(map(int, input().split()))
        perm = [0] * n
        stack = []
        available = list(range(n, 0, -1))  # largest first
        
        possible = True
        i = 0
        while i < n:
            if nxt[i] == -1 or nxt[i] == n+1:
                perm[i] = available.pop(0)
                i += 1
            else:
                length = nxt[i] - i
                if length <= 0:
                    possible = False
                    break
                if len(available) < length:
                    possible = False
                    break
                for j in range(length):
                    perm[i+j] = available.pop(0)
                i += length
        
        if possible:
            print(" ".join(map(str, perm)))
        else:
            print(-1)

if __name__ == "__main__":
    solve()
```コードは、利用可能な最大の数値を最初に割り当てて、「次に大きい」関係が確実に保持されるようにすることで、貪欲な不変条件を維持します。 のために`-1`位置には、残っている最大のものから順に番号を割り当てます。 境界チェックにより、矛盾を示す負の長さのサブシーケンスが試行されないことが保証されます。

 ## 特殊なケース

 すべて`-1`: 任意の順列が機能します。 アルゴリズムは降順の数値を割り当てますが、これは空の制約を自明に満たします。 

Next[i] = n+1: 最大の数値は、next が定義されていない位置に移動します。 アルゴリズムは、それらを制約なしとして扱うことでこれを処理します。 

矛盾している`next`： もし`next[i] <= i`の場合、サブシーケンスの長さが正ではないため、アルゴリズムは直ちに不可能のフラグを立てます。 

疎な既知の値: 一部のみ`next[i]`定義されています。 アルゴリズムはシーケンスを正しく埋めて、`-1`残りの番号が最大のポジション。 

これにより、すべてのシナリオがカバーされ、ソリューションの堅牢性が保証されます。
