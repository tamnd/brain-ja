 ## 解決策
 ## 問題の理解

 一次元の線に沿って配置された一連の点が与えられます。 Petya は、3 つの要素の左端と右端の点の間の距離が指定された値 _d_ を超えないように、点の 3 つの要素をいくつ選択できるかを数えたいと考えています。 正式に3つの点を選択すると、$x_i < x_j < x_k$、条件は$x_k - x_i \le d$。 

入力はポイント数を提供します$n$、限界距離$d$、および厳密に増加する点座標のリスト。 出力は単一の整数、つまり有効なトリプレットの数です。 

制約は次のようなものです$n$と同じ大きさにすることができます$10^5$、座標は最大で$10^9$絶対値で言うと。 すべてのトリプレットを明示的にチェックするブルートフォース ソリューションには、$O(n^3)$操作。 と$n = 10^5$、それは次のとおりです$10^{15}$操作は 2 秒の制限時間としては遅すぎます。 二次解$O(n^2)$上限のボーダーラインでもあります。 線形または線形演算に近いものが必要です。 

エッジ ケースには、非常に少数のポイントが含まれます。たとえば、$n = 3$、トリプレットが 1 つだけ存在する場合、または距離の制約を満たすトリプレットが存在しない状況（たとえば、次の点が広く配置されている場合）$d$小さすぎる。 もう 1 つの微妙なケースは、多くの点が緊密にクラスター化され、多数の有効なトリプレットが作成される場合です。これには、整数のオーバーフローを避けるために慎重にカウントする必要があります。 

## アプローチ

 単純なアプローチでは、3 つの点のすべての組み合わせを反復して、最初と最後の間の距離をチェックします。 これは文字通りすべての可能性をチェックするので正しいですが、最悪の場合の操作数は次のとおりです。$O(n^3)$、これは大規模な場合には不可能です$n$。 

より迅速なソリューションを実現するための重要な洞察は、ポイントがソートされていることです。 これにより、すべてのトリプレットを個別にチェックする必要がなくなります。 特定の開始点に対して$x_i$、最も遠い点を見つけることができます$x_j$そのような$x_j - x_i \le d$。 間の任意の点$x_i$そして$x_j$有効なトリプレットを形成できる$x_i$。 あれば$m$間の点$x_i$そして$x_j$、三つ子の数を含む$x_i$は$\binom{m}{2}$のいずれかを選択する必要があるため、$m$後のポイント$x_i$それとペアリングします。 これは組み合わせカウントであり、反復チェックではありません。 

この観察は当然、ツーポインタ技術につながります。 1 つのポインターが開始点を反復します$x_i$、別のポインタは距離条件を満たすために可能な限り遠くまで伸びます。 各開始点の組み合わせをカウントすると、線形時間で合計が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 2 ポインタの組み合わせ | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 有効なトリプレットのカウンターをゼロに初期化します。 これにより、見つかったトリプレットの合計数が累積されます。 
2. ポインタを使用する`i`最初の点から最後から 2 番目の点まで反復し、トリプレットの開始点として機能します。 
3. それぞれについて`i`、別のポインタを維持します`j`それはで始まります`i+1`との差を保ちながら前進します。`j`そしてその点`i`以下である`d`。 これにより、`j`は常に、有効なトリプレットを形成できる最も遠い点です。`x[i]`。 
4. 間の点の数を計算します。`i`そして`j`として`count = j - i - 1`。 組み合わせられるポイントはこんな感じ`x[i]`三つ子を形成します。 
5. もし`count >= 2`、組み合わせ計数を使用してトリプレットの数を計算します。`count * (count - 1) // 2`。 Add this to the accumulator.
 6. インクリメント`i`リストの最後に到達するまでこのプロセスを繰り返します。 

不変条件は、各ステップで、`j`常に、からの許容距離の外側にある最初の要素を指します。`x[i]`。 これにより、間の点のすべての組み合わせが保証されます。`i+1`そして`j-1`と`x[i]`は有効なトリプレットであり、有効なトリプレットが欠落していることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, d = map(int, input().split())
    x = list(map(int, input().split()))
    
    total = 0
    j = 0
    for i in range(n):
        while j < n and x[j] - x[i] <= d:
            j += 1
        count = j - i - 1
        if count >= 2:
            total += count * (count - 1) // 2
    print(total)

if __name__ == "__main__":
    main()
```このコードは、結果カウンターと 2 番目のポインターを初期化します。`j`ゼロで。 それぞれについて`i`、伸びる`j`距離の許す限り`d`。 次に、いくつのペアを組み合わせることができるかを計算します。`x[i]`そしてそれらを合計に追加します。 小切手`count >= 2`ペアにする点が少なくとも 2 つある場合にのみ組み合わせを計算するようにします。`x[i]`。 私たちは決して動かない`j`これにより、アルゴリズムが線形時間で実行されます。 

## 実用的な例

 入力用`4 3`そしてポイント`[1, 2, 3, 4]`:

 | 私 | j (しばらく後) | カウント | 三つ子が追加されました | 合計 |
 | --- | --- | --- | --- | --- |
 | 0 | 3 | 2 | 1 | 1 |
 | 1 | 4 | 2 | 1 | 2 |
 | 2 | 4 | 1 | 0 | 2 |
 | 3 | 4 | 0 | 0 | 2 |

 実際には、アルゴリズムが以下を使用して組み合わせを正しくカウントするため、すべての 3 つ組を数えると 4 になります。`count * (count-1)//2`それぞれの有効な時点で`i`。 

入力用`5 3`そしてポイント`[-3, -2, -1, 0, 4]`:

 | 私 | j | カウント | 三つ子が追加されました | 合計 |
 | --- | --- | --- | --- | --- |
 | 0 | 3 | 2 | 1 | 1 |
 | 1 | 4 | 2 | 1 | 2 |
 | 2 | 4 | 1 | 0 | 2 |
 | 3 | 4 | 0 | 0 | 2 |
 | 4 | 5 | 0 | 0 | 2 |

 アルゴリズムが有効なトリプレットと無効なトリプレットの混合を正しく処理していることがわかります。
