 ## 解決策
 ## 問題の理解

 2 つの整数が与えられます。1 つは達成する必要がある合計を表し、もう 1 つは選択する必要がある正の整数の数を決定します。 サイズのマルチセットの構築を考える$k$ここで、各要素は正の整数のピッチです。 選択されたすべてのピッチの合計は等しくなければなりません$n$。 

有効なマルチセットはすべて「コード」を表します。 コードごとに、その要素の二乗和に等しいスコアを計算します。 タスクは、1 つの最適なコードを見つけることではなく、合計制約を満たすすべての個別のマルチセットを考慮し、それらの個々のスコアを合計することです。 

したがって、入力は順序が無視され、繰り返しが許可された制約付き整数分割問題を記述し、出力はすべての分割の重み付き合計であり、重みは各分割内の要素の二乗和になります。 

制約$n, k \le 5000$2 次元動的計画法ソリューションが期待されていることを意味します。 すべてのパーティションを明示的に列挙するソリューションは実行不可能です。$n$の中へ$k$部分は組み合わせて成長します。 ナイーブでも$O(n^k)$再帰はすぐに爆発し、さらには$O(n^2 k)$時間制限内に収めるためには、アプローチを慎重に最適化する必要があります。 

素朴な推論による微妙な失敗例は、値を貪欲に割り当てようとしたとき、または各パーティションを独立して処理し、多重度を考慮せずに平方和を計算しようとしたときに発生します。 たとえば、$n = 5, k = 3$、有効なコードは次のとおりです。$\{1,1,3\}$そして$\{1,2,2\}$。 「1 つの最適な構造を構築」しようとする単純なアプローチでは、両方の構成が最終的な合計に個別に寄与する必要があること、および異なる位置に現れる同一の値が異なるパーティション間で複数回寄与することを見落としてしまいます。 

主な困難は、制約された整数分割の組み合わせ族にわたって非線形関数 (二乗和) を集計しなければならないことです。 

## アプローチ

 ブルートフォース戦略では、あらゆる分割方法が生成されます。$n$の中へ$k$正の部分を計算し、各パーティションの二乗和を計算し、それを答えに加算します。 これは、残りの合計と残りのスロットを追跡しながら、次の部分のすべての値を試行する再帰によって実行できます。 探索される状態の数は基本的に組成の数であり、最悪の場合、その数は次のとおりです。$\binom{n-1}{k-1}$。 のために$n = 5000$、これは天文学的に大きいため、妥当な時間内にアプローチを完了することはできません。 

構造的な改善は、プロセスが全体にわたって対称的であることを認識することによってもたらされます。$k$そして、各値の寄与は、特定の配置ではなく、有効な構成全体にわたってその値が出現する回数のみに依存します。 これは、使用された合計の量と選択された要素の数という 2 つのパラメーターに関する動的プログラミングとして問題を再構成することを示唆しています。 

明示的にパーティションを構築する代わりに、すべての状態について 2 つの集計量、つまり、その状態に到達する方法の数と、それらすべての方法にわたる二乗値の累積寄与を追跡します。 新しい要素を追加して状態を拡張する場合$x$、カウントと平方和の両方を一貫して更新します。 これにより、完全な寄与情報を保持しながら、パーティションの列挙が回避されます。 

重要な洞察は、値を追加するとき、$x$サイズのすべてのシーケンスに$i-1$合計すると$s-x$、この拡張機能の寄与により、合計二乗和が次のように増加します。$x^2$そのようなシーケンスごとに。 これにより、組み合わせカウントを値の蓄積から分離することができます。

 ## アルゴリズムのチュートリアル

 各状態がプレフィックス長とターゲット合計に対応する DP テーブルを定義します。 

1. 定義する`dp[i][s]`選択する方法の数として`i`正の整数の合計`s`。 
2. 定義する`val[i][s]`このようなすべての方法の平方和の合計として。 
3. 基本ケースを初期化します。合計が 0 になるゼロの数値を選択する方法は 1 つだけあり、その二乗寄与はゼロです。 
4. すべての州について`(i, s)`、新しい数値を追加して拡張してみます`x ≥ 1`。 に移行します`(i+1, s+x)`。 

これが機能するのは、すべての有効な構成が最後の 1 つの要素を小さな構成に追加することによって構築され、これにより構築パスの一意性が維持されるためです。 
5. から延長する場合`(i, s)`に`(i+1, s+x)`、更新します:

 - ウェイの数は次のように増加します`dp[i][s]`。 
- 平方貢献度は次のように増加します。`val[i][s] + dp[i][s] * x^2`。 

2 番目の項は、既存のすべてのシーケンスに追加の要素が追加されるために表示されます。$x$、つまりそれぞれが貢献します$x^2$前回の合計に加えて。 
6. すべての状態を昇順に繰り返します。`i`そして`s`、それぞれについて、有効なものをすべて試してください`x`そのような`s + x ≤ n`。 
7. 最終的な答えは次のとおりです。`val[k][n]`。 

### なぜ効果があるのか

 すべての有効なコードは、要素ごとにそれを構築する増分選択の 1 つのシーケンスに正確に対応します。 DP は、そのような構築パスをすべて重複なく列挙します。 重要な不変条件は、すべての状態を処理した後のサイズです。`i`、`dp[i][s]`サイズのすべてのマルチセットを正しくカウントします`i`合計付き`s`、 そして`val[i][s]`それらすべてにわたって累積された合計平方和を保存します。 すべての拡張ステップでは二乗寄与のカウントと加算構造の両方が保持されるため、構成が失われたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k = map(int, input().split())

    dp = [[0] * (n + 1) for _ in range(k + 1)]
    val = [[0] * (n + 1) for _ in range(k + 1)]

    dp[0][0] = 1

    for i in range(k):
        for s in range(n + 1):
            if dp[i][s] == 0:
                continue
            ways = dp[i][s]
            base = val[i][s]

            for x in range(1, n - s + 1):
                ni = i + 1
                ns = s + x

                dp[ni][ns] = (dp[ni][ns] + ways) % MOD
                val[ni][ns] = (val[ni][ns] + base + ways * x * x) % MOD

    print(val[k][n] % MOD)

if __name__ == "__main__":
    solve()
```DP は次のように構成されています。`dp[i][s]`以前にカウントを蓄積します`val[i][s]`トランジションに使用され、一貫性が確保されます。 内側のループオーバー`x`可能な次の値を直接列挙します。制約により次のことが許可されるため安全です。$n \le 5000$、無効な合計を削除すれば、3 層構造は引き続き実現可能です。 

よくある実装ミスは更新です`val`方法の数を乗じることはありません。 各状態は多くの基礎となるシーケンスを表し、すべての拡張はそれらすべてに同時に影響します。

 ## 特殊なケース

 のために$n = 1, k = 1$、アルゴリズムは基本状態から開始します`(0,0)`そして直接遷移します`(1,1)`価値のあるもの$1^2 = 1$。 追加の遷移は存在せず、DP は正しく終了します。 

のために$k = n$、有効なコードはすべて強制的にすべて 1 になります。 DP パスは一意であり、各ステップには次のものしかありません。`x = 1`、二乗和が常に次のような単一の状態チェーンを生成します。`k`。 

大型用$n$小さいもので$k$、DP 層はまばらなままです。`i`でも広い`s`、遷移構造は、値空間の大きなジャンプを見逃すことなく、寄与を正しく蓄積します。
