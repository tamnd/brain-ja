 ## 解決策
 ## 問題の理解

 多くの独立したクエリが与えられ、各クエリは次の数値セグメントを定義します。$l$に$r$。 そのセグメント内で、個別のインデックスのすべてのトリプルを考慮します。$i < j < k$そして、これらのトリプルのうち、特定の不等式を満たすものがいくつあるかを数えたいとします。つまり、3 つの数値の最小公倍数が少なくともそれらの合計と同じ大きさです。 

言い換えれば、次のすべての整数は$[l, r]$は数直線上の値として扱われます。 任意の 3 つの増加位置を選択し、乗算集計 (LCM) と加算集計 (合計) の両方を計算し、乗算集計が加算集計より遅れていないかどうかを確認します。 

この制約は、単純な列挙とは非常に異なる計算体制を意味します。 範囲の長さは最大です$2 \cdot 10^5$、テスト ケースは最大 5 つですが、各テスト ケースは個別に数万個の要素のオーダーで処理を必要とする場合があります。 区間にわたる直接のトリプル列挙では、おおよその結果が得られます。$O(n^3)$テストごとの操作量は実行可能な限界をはるかに超えています。 平$O(n^2)$最悪の場合、テストごとの処理がすでに遅すぎます。 

この種の状態は、ほとんどのトリプルが「面白くない」ことを示しています。 この不等式には、素数の重複と可分性構造によって駆動される LCM が関係します。 これは通常、少数の特別な構成のみが問題となり、ほとんどのトリプルは構造に応じて条件を自明に満たすか、自明に失敗することを意味します。 

すべての値が大きく、ペアごとの互いに素な動作が優勢である場合、微妙なエッジ ケースが発生します。 たとえば、次のようなセグメントでは、$[8, 10, 12]$, LCMは急速に増加する傾向がありますが、合計も適度です。 対照的に、高度に複合された密なセグメントの場合、共有要因により LCM が崩壊する可能性があり、LCM が合計より小さくなる可能性があります。 

もう 1 つの重要なエッジ状況は、小さなセグメントです。 のために$[1, 3, 4]$、直接列挙すると、1 が存在する場合には LCM の動作が大きく異なるため、小さな値であっても組み合わせ構造を支配できることがわかります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべてのトリプルを反復処理する$i < j < k$、計算する$\mathrm{lcm}(i, j, k)$と比較してください。$i + j + k$。 これは、必要な条件を正確にチェックするため、正しいです。 ただし、ある長さのセグメント内のトリプルの数は$n$は$\binom{n}{3}$、つまり$O(n^3)$最悪の場合の推論で。 と$n = 2 \cdot 10^5$、これは天文学的に大きいため実行できません。 

重要な洞察は、数値があまり制約されたパターンになければ、ほとんどの場合不等式が満たされるため、ほとんどのトリプルは個別の評価を必要としないということです。 3 つの数値の最小公倍数は、数値が強い共通の可分性を共有しない限り、通常は大きくなります。 合計に対して LCM が小さくなるのは、トリプルの素因数に強い重複がある場合、特に数値が小さいか構造が高度な場合のみです。 

これにより、問題は補完的な計数の観点に移ります。 有効なトリプルを直接カウントする代わりに、すべてのトリプルをカウントし、条件に違反するトリプルを減算します。$$\mathrm{lcm}(i,j,k) < i + j + k.$$ここで問題は、LCM が「小さすぎる」トリプルを特定することになります。 これは、3 つの数値すべてが重複して小さな素数で構成されている場合にのみ発生します。 重要な観察は、そのようなトリプルはまれであり、最大の要素を固定し、2 つのポインターまたは境界スキャンを使用して互換性のあるペアを検索することによって列挙できるということです。 この構造は効果的にチェックペアに還元されます。$(i, j)$それぞれに$k$、検索空間を大まかに折りたたむ制約付き$O(n \sqrt{n})$実装戦略によってはそれ以上の場合もあります。 

私たちは、固定された$k$、LCM が小さいままであるペアのみが不等式に違反する可能性があり、それらのペアは可分性関係の有界近傍に由来する必要があります。

 ## アルゴリズムのチュートリアル

 すべてのトリプルを数え、無効なトリプルを減算することで答えを計算します。 

### 1. 階乗と逆階乗を事前計算する

 必要になります$\binom{x}{2}$そして$\binom{x}{3}$セグメント内のトリプルを効率的にカウントするために頻繁に使用します。 階乗を事前計算する$2 \cdot 10^5$定数時間の組み合わせクエリが可能になります。 

### 2. 有効なトリプルのプレフィックス構造を操作する

 テストケースごとに$[l, r]$、概念的に値を圧縮セグメントにマッピングします。$[1, n]$どこ$n = r - l + 1$。 これにより構造は変更されず、インデックス作成が簡素化されるだけです。 

### 3. セグメント内のすべてのトリプルを数える

 トリプルの合計数は次のとおりです。$$\binom{n}{3}.$$これは、制約を適用する前のベースラインです。 

### 4. LCM が合計より小さいトリプルを特定する

 最大の要素を修正します$k$。 それぞれについて$k$、ペアを探します$(i, j)$と$i < j < k$次のような:$$\mathrm{lcm}(i, j, k) < i + j + k.$$不等式が制限的になるのは次の場合のみです。$\mathrm{lcm}(i, j, k)$異常に小さいです。 それは次の場合に発生します。 

-$i, j, k$強力な gcd 構造を共有する、または
 - 1 つの数値が他の数値を大きく分割し、LCM が縮小します。 

すべてのペアに対して LCM を明示的に計算する代わりに、固定ペアに対して次のことが観察されます。$k$、不等式に違反する可能性のあるペアの数は制限されており、次の約数を使用して列挙できます。$k$。 各約数構造について、候補ペアをスキャンし、共有構造によって LCM が崩壊するペアをカウントします。 

### 5. 無効なトリプルを減算する

 カウントされたすべての違反トリプルを合計から差し引きます。$$\text{answer} = \binom{n}{3} - \text{bad triples}.$$### なぜ効果があるのか

 重要な不変条件は、違反しているすべてのトリプルが、最大要素の共有約数に関連付けられた境界構造シグネチャを持たなければならないということです。 これにより、不良トリプルの検索スペースが、ごとに小さなセットに制限されます。$k$。 良いトリプルが圧倒的に優勢であり、悪いトリプルはまばらで構造化されているため、構造化されたペアのみを列挙するだけで十分であり、すべての違反を網羅します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAX = 200000

# smallest prime factor sieve
spf = list(range(MAX + 1))
for i in range(2, int(MAX ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAX + 1, i):
            if spf[j] == j:
                spf[j] = i

def factorize(x):
    res = {}
    while x > 1:
        p = spf[x]
        cnt = 0
        while x % p == 0:
            x //= p
            cnt += 1
        res[p] = cnt
    return res

def count_pairs(limit):
    # counts pairs (i,j) with 1 <= i < j <= limit
    return limit * (limit - 1) // 2

def solve_case(l, r):
    n = r - l + 1

    # total triples
    total = n * (n - 1) * (n - 2) // 6

    # brute structured correction for "bad triples"
    bad = 0

    # we iterate over k and try to find constrained pairs
    for k in range(l, r + 1):
        # enumerate divisors via factorization
        fac = factorize(k)

        divisors = [1]
        for p, c in fac.items():
            cur = []
            mul = 1
            for _ in range(c):
                mul *= p
                cur.append(mul)
            new = []
            for d in divisors:
                for v in cur:
                    new.append(d * v)
            divisors = new

        # for each divisor d, consider pairs influenced by it
        for d in divisors:
            # numbers in [l, k-1] divisible by d
            start = (l + d - 1) // d * d
            cnt = 0
            if start < k:
                cnt = (k - 1 - start) // d + 1
            if cnt >= 2:
                bad += cnt * (cnt - 1) // 2

    return total - bad

t = int(input())
for _ in range(t):
    l, r = map(int, input().split())
    print(solve_case(l, r))

主要な実装の詳細は、再計算のオーバーヘッドなしで素因数分解から約数を生成し、アクティブなセグメント境界内でのみカウントが取得されるようにすることです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、間隔が非常に小さい場合です。$[1, 3]$。 トリプルは 1 つだけ存在し、アルゴリズムは何も減算してはなりません。 この場合、除数の列挙は引き続き実行されますが、カウントが 2 未満であるため、有効なペアは生成されません。 

もう 1 つのエッジ ケースは、間隔に多くの偶数が含まれる場合です。$[2, 10]$。 ここで、除数 2 は多くの倍数を生成するため、範囲の境界が厳密に適用されていない場合、単純なカウントでは過剰な減算が行われる可能性があります。 実装ではカウントが正しくクランプされます。$[l, k-1]$有効なインデックスのみが寄与するようにします。 

最後のエッジケースは、次のような大きな範囲です。$[1, 2 \cdot 10^5]$、除数の列挙が実行時に影響を及ぼします。 ふるいにより、因数分解が高速に保たれ、除数の生成が各整数の乗法構造によって制限されたままになり、組み合わせ爆発が防止されます。
