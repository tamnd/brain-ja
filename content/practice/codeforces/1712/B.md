 ## 解決策
 ## 問題の理解

 単一の整数が与えられます$n$、からの数字を並べる必要があります。$1$に$n$特定のスコアができるだけ大きくなるように順列に変換します。 スコアは位置ごとに計算されます: インデックスで$i$の最小公倍数をとります。$i$そしてそのインデックスに配置された値を計算し、これらすべての寄与を合計します。 

したがって、インデックスを自由に変更できるわけではなく、各位置に割り当てられた値のみを変更できます。 からの各番号$1$に$n$は 1 回だけ使用する必要があり、目標はすべてのポジションにわたって LCM 値がどれだけ大きくなるかを最大化することです。 

制約により、最大で$10^5$テストケースごと、また最大$10^5$すべてのテスト ケースの合計。 これにより、すべての順列を試行するソリューションは除外されます。$n!$非常に早く成長します。 テスト ケースごとの 2 次アプローチであっても、次の場合には遅すぎます。$n$大きいので、$10^5$二乗はすでに$10^{10}$、1秒の制限が許容するものをはるかに超えています。 これにより、直線または直線に近い構造が求められます。 

微妙なエッジケースが現れるのは、$n$小さいです。 たとえば、次のようなとき$n=1$、順列は 1 つだけなので、答えは強制されます。 いつ$n=2$要素を交換すると、LCM の寄与が非自明な方法で変化するため、「大きな数値を大きな位置に配置する」などの素朴な直感は、LCM 構造と照らし合わせて慎重にチェックしないとすでに失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべての順列を試し、それぞれの最小公倍数の合計を計算し、最良のものを選択します。 これは、考えられるすべての割り当てを評価するため、正しいです。 ただし評価が必要$n!$順列と各評価コスト$O(n)$、につながる$O(n \cdot n!)$、これはたとえ$n = 10$。 

重要な観察は、2 つの数値の最小公倍数が$i$そして$p_i$積が大きく、最大公約数が小さい場合に最大になります。 以来$\mathrm{lcm}(i, p_i) = \frac{i \cdot p_i}{\gcd(i, p_i)}$、可能な限り両方の値を大きく保ちながら、gcd ができるだけ小さいペアが必要です。 

これは、共有要素を回避する方法で数字を組み合わせることを示唆しています。 保証する最も簡単な方法$\gcd(i, p_i) = 1$できるだけ頻繁に、要素をペアで交換します。 ペアリングしたら$i$と$i+1$、 それから$\gcd(i, i+1)=1$、そして最小公倍数は次のようになります。$i \cdot (i+1)$これは、より小さい数を含む配置と比較して大きいです。 

したがって、複雑な方法でグローバルに最適化する代わりに、隣接する要素を交換することで貪欲に順列を構築できます。 これにより、すべてのペアが積のような大きな LCM に寄与することが保証され、小さなインデックスで大きな値を無駄にすることがなくなります。 

奇数の場合$n$の場合、最後の要素はペアにできないため、そのまま残ります。

 ## アルゴリズムのチュートリアル

 1. リストから始めます$[1, 2, 3, \dots, n]$。 これは、最適化前のベースラインの順列です。 
2. 2 のステップで配列を左から右に走査します。 
3. ペアごとに$(i, i+1)$、2 つの値を交換します。 これによりペアが作成されます$(2,1), (4,3), (6,5), \dots$。 
4. もし$n$が奇数の場合は、パートナーがないため、最後の要素を変更しないでください。 
5. 結果の配列を出力します。 

ペアで処理する理由は、隣接する整数が互いに素であることが保証されており、整数を順番に残す場合と比較して LCM が最大化されるためです。 

### なぜ効果があるのか

 スワップされた各ペア$(i, i+1)$2 つの LCM 項が生成されます。$$\mathrm{lcm}(i, i+1) = i(i+1), \quad \mathrm{lcm}(i+1, i) = i(i+1)$$立場に応じていくつかの順序で。 これは、次のように整列させておくよりも厳密に優れています。$\mathrm{lcm}(i,i)=i$そして$\mathrm{lcm}(i+1,i+1)=i+1$、 以来$2i(i+1)$二次関数的に成長しながら$2i+1$直線的です。 

各ペアは独立しており、スワッピングは他の位置に影響を与えないため、隣接するブロックごとに局所的に寄与を最大化することができ、最適な局所的な選択の合計により全体的な最適値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    p = list(range(1, n + 1))

    for i in range(0, n - 1, 2):
        p[i], p[i + 1] = p[i + 1], p[i]

    print(*p)
```このソリューションは、恒等順列を初期化し、すべての隣接するペアを交換することにより、線形時間で順列を構築します。 ループ`range(0, n - 1, 2)`有効なペアのみを交換し、最後の要素をそのままにすることで奇数の長さを自然に処理できるようにします。 

よくある間違いは、より複雑な gcd ベースのロジックを試行することですが、隣接関係によってローカルで最大のメリットがすでに保証されているため、何も必要ありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        p = list(range(1, n + 1))
        for i in range(0, n - 1, 2):
            p[i], p[i + 1] = p[i + 1], p[i]
        out.append(" ".join(map(str, p)))
    return "\n".join(out)

# provided samples
assert run("2\n1\n2\n") == "1\n2 1"

# custom cases
assert run("1\n3\n") == "2 1 3", "odd length"
assert run("1\n4\n") == "2 1 4 3", "basic pairing"
assert run("1\n5\n") == "2 1 4 3 5", "odd tail behavior"
assert run("1\n6\n") == "2 1 4 3 6 5", "full pairing"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 のために$n=1$、アルゴリズムが生成する$[1]$スワップ ループが実行されないためです。 これは唯一の有効な順列と一致するため、正確性がすぐにわかります。 

のために$n=2$、スワップによって生成される$[2,1]$。 ここで代替案$[1,2]$クロスペアリングによる大きな LCM ゲインが無駄になるため、スコアが小さくなり、最小ではないケースでも最適に処理されることが確認されます。 

奇数の場合$n$、 のような$n=5$、最後の要素はそのまま残ります。 この構造では依然として、以前のすべての要素が最適にペアリングされており、ペアになっていない要素はその位置で可能な唯一の値に寄与するため、より適切なペアを壊さずに要素を別の場所に移動しても改善は不可能です。
