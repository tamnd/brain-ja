 ## 解決策
 ## 問題の理解

 長さの文字列が与えられます$n$ここで、各位置には表示される ASCII 文字が保持されます。 それから私たちは与えられます$m$操作では、各操作で 2 つの異なる文字が選択されます$(x, y)$。 すべての操作について、ルールはグローバル スワップです。$x$になる$y$、およびすべての発生$y$になる$x$、文字列全体で同時に。 これは位置のローカルな交換ではなく、文字の完全な再ラベル付けです。 

すべての操作を順番に適用した後、最終的に変換された文字列を出力する必要があります。 

重要な制約は、両方とも$n$そして$m$と同じ大きさにすることができます$10^5$。 すべての操作で文字列全体をスキャンする直接シミュレーションには、最大で$10^5 \times 10^5 = 10^{10}$キャラクターの更新は 1 秒の制限をはるかに超えています。 操作ごとに 1 回文字列をスキャンするだけでも、すでに遅すぎます。 

スワップを独立した置換として解釈すると、微妙な落とし穴が生じます。 スワップは同時であるため、単一操作内の中間置換順序が結果に漏れてはなりません。 たとえば、誤ってすべてを置き換えてしまった場合、$x \to y$最初に、そしてすべて$y \to x$マッピング層を慎重に分離しないとロジックが破損します。 

もう 1 つの潜在的な間違いは、文字列自体を繰り返し書き換えることです。 文字は位置ではなくアイデンティティのみを変更するため、各操作中に文字列を直接変更する必要はありません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 それぞれの操作について$(x, y)$、文字列全体をスキャンし、出現するすべての文字列を置き換えます。$x$と$y$そしてあらゆる出来事が$y$と$x$。 各操作は均一に適用されるグローバル スワップであるため、これにより問題が正しくシミュレートされます。 

問題はパフォーマンスです。 それぞれのスキャンは、$O(n)$、そして私たちはそれをします$m$につながる$O(nm)$。 と$10^5$両方の次元において、これは実行不可能になります。 

重要な点は、操作中に文字列自体を変更する必要がないことです。 実際に変更されるのは、元の文字から現在の文字へのマッピングです。 各操作では 2 つのシンボル間の関係のみが更新され、文字列内の位置は更新されません。 

したがって、文字列に繰り返し触れる代わりに、考えられる ASCII 文字ごとに、それが現在何を表しているかを示すマッピング配列を維持します。 最初は、すべての文字がそれ自体にマッピングされます。 操作を処理するとき$(x, y)$の画像を交換します。$x$そして$y$このマッピングの内側。 すべての操作の後、この最終マッピングを元の文字列に 1 回適用します。 

これにより、問題は、一定サイズのアルファベット (最大 94 個の表示される ASCII 文字) の順列を維持することになります。 それぞれの交換は、$O(1)$、そして最終的な再構築は$O(n)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nm)$|$O(1)$| 遅すぎる |
 | マッピングスワップ |$O(n + m)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 すべての文字を、ASCII 値を表す固定サイズの配列内のインデックスとして扱います。 中心的な考え方は、操作ごとに進化する現在の ID マッピングを維持することです。 

1. 各文字がそれ自体にマップされるようにマッピング配列を初期化します。 これは、スワップが適用される前の恒等変換を表します。 
2. 各操作ごとに$(x, y)$、両方の文字をインデックスとして解釈し、マッピング配列内でマップされた値を交換します。 これは、文字列自体には触れずにグローバル スワップの適用をシミュレートします。 これが機能する理由は、文字列の内容ではなくラベルの変換を追跡しているためです。 
3. すべての操作を処理した後、元の文字列の各文字を反復処理し、マップされた値で置き換えることにより、最終的な文字列を構築します。 
4. 構築した結果を出力します。 

これが機能する理由は、マッピング配列が常に、すべての交換によって引き起こされる文字の累積的な並べ替えを表すためです。 各操作は文字セットに対する置換グループ内の転置であり、これらの転置を構成することは、マッピング配列を増分的に更新することと同等です。 スワップはグローバルかつ対称的に適用されるため、位置依存性は存在せず、元の各シンボルの最終文字は中間状態ではなく最終的な置換のみに依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    s = input().rstrip("\n")

    # visible ASCII range: 33 to 126 inclusive
    OFFSET = 33
    SIZE = 94

    mp = [i for i in range(SIZE)]

    for _ in range(m):
        x, y = input().split()
        xi = ord(x) - OFFSET
        yi = ord(y) - OFFSET
        mp[xi], mp[yi] = mp[yi], mp[xi]

    res = []
    for ch in s:
        idx = ord(ch) - OFFSET
        res.append(chr(mp[idx] + OFFSET))

    print("".join(res))

if __name__ == "__main__":
    solve()
```このソリューションは懸念事項を明確に分離します。 マッピング配列`mp`すべてのスワップの下に各キャラクターの現在のイメージを保存します。 各操作は、この配列内の 2 つのエントリのみを交換し、次の不変条件を保持します。`mp[c]`キャラクターの最終的に変換されたアイデンティティです`c`現在の操作に至るまで。 

最後のループではこの変換を 1 回適用し、文字列の長さに対する線形コス​​トのみを支払うようにします。 

## 実用的な例

 ### 例 1

 入力:```

abcd
a c
d z
```関連する可視文字のマッピングを追跡します。 

| ステップ | 操作 | マッピングの変更 | 結果のマッピング (関連) |
 | --- | --- | --- | --- |
 | 0 | 初期化 | アイデンティティ | a→a、b→b、c→c、d→d、z→z |
 | 1 | a c | aとcを入れ替える | a→c、c→a |
 | 2 | dz | d と z を入れ替える | d→z、z→d |

 次に文字列に適用します。 

- a → c
 - b → b
 - c → a
 - d→z

 出力は次のようになります。```
cbaz
```これは、処理中に文字列にはまったく触れず、マッピングのみに触れたことを示しています。 

### 例 2

 入力:```

| ステップ | 操作 | キーマッピングの変更 |
 | --- | --- | --- |
 | 0 | 初期化 | @→@、#→#、!→! |
 | 1 | # ! | ＃ そして ！ スワップ |

```このトレースは、中間状態に関係なく、繰り返されるグローバル スワップが単一の順列にきれいに構成されることを示しています。

 ## 特殊なケース

 エッジケースの 1 つは、複数のスワップがサイクルを形成する場合です。 例えば交換とか`a b`、 それから`b c`、 それから`c a`何も「壊さない」。 有効な順列が生成されます。 アルゴリズムはマッピング配列内で転置を構成するだけであるため、これを自然に処理します。 

入力：```
3 3
abc
a b
b c
c a
```ステップバイステップのマッピング:

 - a b の後: a↔b
 - b c の後: b↔c (サイクルが形成される)
 - c a 後: サイクルが完了します

 最終マッピングでは、すべての文字が回転された位置に戻され、一貫した最終文字列が生成されます。 実装は文字列内の順序に依存しないため、矛盾は発生しません。 

もう 1 つのエッジ ケースは、文字列に出現しない文字が交換に関与する場合です。 マッピング配列には ASCII 範囲全体が含まれるため、これらの文字が後で出現する場合や他のマッピングに影響を与える場合でも、これらの操作は今後の動作を正しく更新します。
