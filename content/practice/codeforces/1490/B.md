 ## 解決策
 ## 問題の理解

 長さが常に 3 で割り切れる配列が与えられます。 すべての数値について、3 を法とした剰余のみが重要です。 

1 回の移動で 1 つの配列要素が 1 ずつ増加します。剰余の観点から見ると、数値を 1 増やすと、サイクルに沿って数値が移動します。 

0→1→2→0

 私たちの目標は、剰余 0、1、2 の数値のカウントをすべて等しくすることです。 配列の長さは 3 で割り切れるため、各剰余クラスには最終的に正確に次の値が含まれる必要があります。`n / 3`要素。 

配列内の実際の値はほとんど無関係です。 答えに影響する唯一の情報は、各剰余クラスに現在属している数値の数です。 カウントが分かれば`c[0]`、`c[1]`、`c[2]`次に、タスクは、循環剰余グラフの周囲で可能な限り安価な転送を使用して、これら 3 つのバケットのバランスを取ることになります。 

制約は非常にフレンドリーです。 すべてのテスト ケースにわたる配列要素の合計数は最大 150,000 です。 各要素を一定の回数だけ処理するアルゴリズムは、簡単に十分に高速です。 たとえ`O(n)`テスト ケースごとの解決策は、制限内では自明です。 動的プログラミング、グラフ アルゴリズム、または重いデータ構造は必要ありません。 

すべての余分な要素が複数の剰余クラスを通過する必要がある場合、微妙なエッジ ケースが発生します。 

考慮する：```
n = 6
remainders: [0,0,0,0,0,0]
```カウントは次のとおりです。```
c0 = 6, c1 = 0, c2 = 0
target = 2
```正解は6です。 

2 つの要素がクラス 0 からクラス 1 に移動し、合計 2 つの移動コストがかかります。 さらに 2 つの要素をクラス 0 からクラス 2 に移動する必要があります。剰余 0 から剰余 2 への直接的な操作がないため、このような各移動のコストは 2 移動であり、さらに 4 つの移動に寄与します。 合計は6です。 

欠陥のあるクラスに直接転送するだけの不注意な解決策では、4 が誤って計算されてしまいます。 

もう 1 つの簡単な間違いは、バランス パスを 1 回行った後で停止することです。 

考慮する：```
n = 6
remainders: [2,2,2,2,2,2]
```カウント:```
c0 = 0, c1 = 0, c2 = 6
target = 2
```2 つの要素をクラス 2 からクラス 0 に移動すると、それぞれ 2 回の移動コストがかかり、次のものが作成されます。```
c0 = 2, c1 = 0, c2 = 4
```アレイはまだバランスが取れていません。 クラス 2 は過剰なままであり、さらに 2 つの要素をクラス 1 に送信する必要があります。最終的な答えは 6 です。シングルパス再分配では、この 2 番目の修正が見逃されます。 

3 番目のエッジ ケースは、アレイがすでにバランスされている場合に発生します。```
n = 6
a = [0,1,2,3,4,5]
```カウント:```
c0 = c1 = c2 = 2
```答えは 0 です。余剰カウントをチェックせずにやみくもに転送を実行するソリューションでは、不要な手が追加される可能性があります。 

## アプローチ

 最も直接的なアイデアは、個々の操作をシミュレートすることです。 残りのクラスに要素が多すぎる場合は、そのクラスから要素を 1 つ選択し、不足クラスに達するまで繰り返し要素を増やします。 

このアプローチは、許可された操作に正確に従っているため、正しいです。 問題は、カウントだけが重要な場合に、個別の数字について考えていることです。 このアイデアのより大きな変形では、多くの不必要なシミュレーションを実行する可能性があります。 実際の要素を追跡しても追加情報は得られません。 

重要な観察は、すべての操作で剰余クラスのみが変更されるということです。 数値を 1 回増やすと、クラスから 1 つのアイテムが移動します`r`クラスへ`(r+1) mod 3`。 

要素を操作する代わりに、カウントを操作できます。 

クラスを想定します`i`現在、目標量を超える量が含まれています。 余分なもの```
c[i] - target
```最終的にはこのクラスを離れなければなりません。 1 つの増分がまさにその遷移を実行するため、最も安価な宛先は常にサイクル内の次の残りのクラスになります。 

クラスに過剰な要素がある場合は、すべての超過を次のクラスに転送し、転送された要素ごとに 1 手を支払い、カウントを更新します。 これにより、次のクラスで余剰が生じる可能性がありますが、これについては後で処理します。 

残りのクラスは 3 つしかないため、サイクル全体で繰り返し伝播される余剰はすぐにバランスに達します。 クラスを数回通せば十分です。 標準ソリューションは 6 回の反復を実行します。これにより、余剰分はサイクル全体で最大 2 ラウンド移動できることが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 要素のブルート フォース シミュレーション | O(n + 答え) | O(n) | 不必要に遅い |
 | カウントの再配分 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 3 を法とした剰余 0、1、2 を持つ配列要素の数を数えます。 
2. 各クラスのターゲット サイズを計算します。```
target = n / 3
```3. 答えをゼロに初期化します。 
4. 残りのクラスを数回繰り返します。 クラスが 3 つしかなく、余剰はサイクルを複数回移動する必要がある場合があるため、6 回の反復で十分です。 
5. クラスごとに`i`、どうかを確認してください`c[i] > target`。 
6. 過度な場合は、```
extra = c[i] - target
```これらすべての要素をクラスに移動します`(i + 1) % 3`。 
7. 転送された各要素には 1 つの増分が必要なので、次の値を追加します。`extra`答えに。 
8. カウントを更新します。```
c[i] -= extra
c[(i + 1) % 3] += extra
```9. すべてのパスの後、カウントは均衡し、累積コストは最小移動数になります。 

### なぜ効果があるのか

 唯一許可される操作は、剰余クラスから 1 つの要素を移動することです`r`残りのクラスへ`(r+1) mod 3`ちょうど 1 回の移動の費用がかかります。 クラスに目標数を超える要素が含まれている場合は、超過した要素はすべて最終的にそのクラスから離れる必要があります。 超過分を次のクラスに直接送信することは、まさに 1 つのインクリメントが行うことであるため、可能な限り低コストのアクションです。 

このアルゴリズムは、余剰クラスに属さない限り要素は移動されないという不変条件を維持します。 異動のたびに、現在のクラスの余剰が可能な限り削減されます。 受信クラスが過剰になると、その超過は後で伝播されます。 余剰はサイクル内で前方にのみ移動でき、すべての移動は 1 回だけカウントされるため、総コストはバランスの取れたカウントに達するために必要な最小増分数に等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        cnt = [0, 0, 0]
        for x in a:
            cnt[x % 3] += 1

        target = n // 3
        moves = 0

        for i in range(6):
            r = i % 3

            if cnt[r] > target:
                extra = cnt[r] - target
                cnt[r] -= extra
                cnt[(r + 1) % 3] += extra
                moves += extra

        ans.append(str(moves))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```最初の部分では、3 つの剰余カウントを計算します。 これにより、問題はアレイのバランシング タスクから 3 バケットのバランシング タスクに軽減されます。 

変数`target`各バケットの必要なサイズを保存します。 以来`n`は 3 で割り切れるため、四捨五入の問題は存在しません。 

再配布ループはソリューションの中核です。 クラスに次の内容が含まれる場合は常に、`target`要素では、すべての超過分が 1 つの残りのステップによって前方に押し出されます。 転送された各要素は、正確に 1 つのインクリメント操作に対応します。`moves`同じ量だけ増加します。 

ループは 3 回ではなく 6 回実行されます。 1 つの完全なパスにより、次のクラスで新たな余剰が生じる可能性があります。 2 番目のパスでは、余剰が移動し続けることができます。 残りのクラスが 3 つだけであるため、すべての余剰を完全に伝播するには 6 回の反復で十分です。 

最大の答えは Python の整数の範囲に比べて小さいため、整数オーバーフローの懸念はありません。
