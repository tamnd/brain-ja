 ## 解決策
 ## 問題の理解

 正の整数の小さな配列がいくつか与えられています。 各配列について、既存の要素の間を含む任意の場所に新しい数値を挿入できます。 数値を挿入した後は、どちらの要素も他の要素の 2 倍を超えないという意味で、隣接する要素のすべてのペアが「滑らか」になるようにします。 

タスクは、この条件が最終的な配列内のすべての隣接するペアに当てはまるように、必要な挿入値の最小数を計算することです。 

制約構造は重要です。 各配列には最大 50 個の要素があり、最大 1000 個のテスト ケースがあります。 これにより、合計入力サイズが小さく保たれるため、たとえその作業に挿入の反復やシミュレーションが含まれる場合でも、隣接するペアごとに少量の作業を実行するソリューションが可能になります。 n の 3 次であれば何でも問題ありませんが、問題の構造から、シミュレーションではなく直接的な貪欲な式を目指す必要があることがわかります。 

隣接する 2 つの数値が大きく異なる場合、微妙な点が現れます。 たとえば、100 は依然として 4、8、16 などの 2 倍より大きいため、2 から 100 への移動は 1 回の挿入では修正できません。 重要な問題は、必要な挿入の数が、範囲内に留まりながら 2 の乗算または 2 の除算を何回繰り返すことができるかによって決まることです。 

よくある失敗例は、中間点のみ、または (a + b) / 2 のような単一の値を挿入しようとした場合に発生します。たとえば、1 と 100 の間では、100 は 50 の 2 倍より大きいため、50 を挿入してもまだ十分ではありません。正しい戦略には、中間値を連鎖する必要があります。 

## アプローチ

 単純なアプローチでは、すべての不良隣接ペアをローカルに修復しようとします。 一方が他方の 2 倍を超えている 2 つの隣接するものを見つけるたびに、それらの中点を挿入し、条件が成立するまで繰り返します。 このシミュレーションは最終的には機能しますが、1 つのペアへの挿入が将来の隣接関係に影響を及ぼし、スキャンの繰り返しが必要になるため、非効率的で概念的に面倒です。 

最悪の場合、値がギャップの 2 乗以上に増加した場合、修復のたびに両側に新しい違反が発生し、同じセグメントを繰り返し再訪することになる可能性があります。 n が小さい場合でも、このアプローチでは問題の実際の構造がわかりにくくなります。 

重要な観察は、実際には中間の配列状態を気にしていないということです。 許可された遷移を使用して、ある数値を別の数値に変換するのに必要なステップ数のみを考慮します。各ステップでは、最大でも値が 2 倍または半分になります。 2 つの隣接する値 a と b の間に、連続する比率が最大 2 になるシーケンスを使用して a から b に移動できるようにするには、いくつの数値を挿入する必要があるかが問題になります。 

これは比率に関する純粋な算術問題になります。 a ≤ b の場合、b に達するかそれを超えるまで a を 2 倍にします。 それぞれの 2 倍化は、ギャップを埋める値の挿入に対応します。 挿入数は、b と交差する前に 2 を何回掛けて、エンドポイント調整 1 回を引いたものによって決まります。 

これにより、問題全体が、隣接するすべてのペアの寄与を個別に合計することになります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。

1. 配列内のすべての隣接するペアを繰り返します。 各ペアは、密にする必要がある独立した「ギャップ」として扱われます。 
2. ペア (x, y) について、どちらが大きいかを決定します。 x が y に等しい場合、条件はすでに満たされているため、作業は必要ありません。 
3. x が y より大きい場合、概念的には、2 倍化を繰り返して y から x まで移動したいと考えます。 一時変数 cur = y を使用してこのプロセスをシミュレートします。 
4. cur * 2 はまだ厳密に x より小さいですが、cur を 2 倍にし、そのような 2 倍ごとに 1 回の挿入をカウントします。 各挿入は、比率制約をローカルで有効にする中間値の配置を表します。 
5. このペアに必要な 2 倍の数を全体的な答えに追加します。 
6. すべてのペアに対して繰り返し、合計を出力します。 

微妙な点は、cur がすでに x の 2 の係数内にあるときに停止することです。 この時点では、最後の隣接条件がすでに満たされているため、最後のセグメントに追加の番号を挿入する必要はありません。 

### なぜ効果があるのか

 挿入された番号はローカルな隣接関係にのみ影響するため、2 つの番号の間のプロセスは他のペアから独立しています。 任意のペア (x, y) について、最適解は常に各ステップが最大 2 倍される最短のチェーンを構築します。必要な中間値をスキップすると直ちに制約に違反するため、最適なシーケンスは 2 のべき乗で区切られた等比数列内に収まる値を通過する必要があります。 これにより、独自の最小長の倍加チェーンが強制され、貪欲な構築が最適化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ans = 0
        
        for i in range(n - 1):
            x, y = a[i], a[i + 1]
            
            if x == y:
                continue
            
            if x < y:
                x, y = y, x
            
            cur = y
            while cur * 2 < x:
                cur *= 2
                ans += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```コードは概念的なプロセスを直接反映しています。 隣接する各ペアは、x が常に大きい値となるように正規化されます。 次に、2 倍を繰り返すことで、小さい値から上に向かって上昇するシミュレーションを行います。 ループ条件`cur * 2 < x`厳密に必要な場合にのみ中間値を挿入するようにします。 より早く停止すると、係数 2 を超えるギャップが残りますが、後で停止すると、不必要な挿入が過剰にカウントされます。

 ### 例 1

 入力:```

```隣接する各ペアを処理します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、両方の数値が等しい場合です。 のような入力の場合`[7, 7]`、比率条件がすでに成立しているため、挿入は必要ありません。 アルゴリズムはこれらのペアを即座にスキップするため、不必要な作業は行われません。 

もう 1 つのケースは、値がすでに係数 2 の範囲内にあるものの等しくない場合です。`[3, 5]`。 5 は 3 の 2 の倍数ではありませんが、比率は 2 より小さいため、挿入は必要ありません。 ループ条件`cur * 2 < x`真の違反が存在しない限り、何も挿入しないようにします。 

より興味深いシナリオは、次のような大きなギャップです。`[1, 50]`。 このアルゴリズムは、1 を 1 → 2 → 4 → 8 → 16 → 32 と繰り返し 2 倍にし、再度 2 倍にすると 50 以上になるため停止します。これにより、最適な構築の構造と一致する、必要な中間体の最小数が正確に生成されます。
