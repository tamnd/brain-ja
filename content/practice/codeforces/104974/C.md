 ## 問題の理解

 部屋 1 が入り口である部屋のツリーを操作していますが、ルートは実際には計算にとって重要ではありません。 重要なアイデアは、どの部屋からでも`u`、アリスとボブは一緒に開始し、その後、異なる発信方向を選択してすぐに分かれます。`u`つまり、元の端を通って戻ることはできず、そこにとどまることを選択することもできます。`u`。 

各人はツリーの下に向かって歩いていきます (または留まり続けます)。そのため、各人は、ツリーから離れることによって到達可能なノードで終了します。`u`。 唯一の制限は、分割時に同じ親方向に戻ってはいけないことです。これは事実上、両方のエンドポイントが異なる「ブランチ」に存在することを意味します。`u`、または 1 つのエンドポイントは`u`自体。 

あらゆるクエリに対して`(u, k)`、最終位置の順序のないペアがいくつあるかを数えなければなりません`(a, b)`間の距離が次のように発生する可能性があります。`a`そして`b`少なくとも`k`、これらのエンドポイントは、次の分割ルールの下で達成可能です。`u`。 

制約は大きく、最大で`2 × 10^5`ノード以上`5n`クエリ。 距離を再計算したり、クエリごとに走査を実行したりするソリューションは、すぐに遅すぎます。 平`O(n)`クエリあたりの結果は約`10^6`最良の場合でも動作が低下する可能性があります。`10^7`に`10^8`、これは境界線であり、二次関数は不可能です。 

微妙な点は、「有効なペア」とはツリー内のノードのすべてのペアではなく、それらの間のパスが通過するノードのみであることです。`u`。 これは、次のことを削除するのと同じです。`u`ツリーをコンポーネントに分割します。2 つのエンドポイントは異なるコンポーネントに存在する必要があります。そうでない場合は、そのうちの 1 つが`u`。 

もう 1 つの微妙な問題は、二重カウントです。 サブツリーごとに独立してペアを集約しようとする場合は、同じブランチ内のペアをカウントしないようにする必要があります。これは、ペアは分割によって形成できないためです。`u`。 

単純な間違いは、これを単純な距離クエリとして扱うことです。`u`、ただしペアは無視されます`(a, b)`どちらのエンドポイントも存在しない場所`u`それでも彼らの道はまだ続いている`u`。 

## アプローチ

 ブルートフォース解釈によりクエリが修正される`(u, k)`から到達可能なすべてのノードを列挙しようとします`u`各ブランチで、すべての順序付けされていないペアをチェックし、BFS または LCA 計算を使用して距離を検証します。 分割の制約は簡単にシミュレートできるため、これは概念的には機能しますが、すぐに遅すぎます。各クエリが影響を受ける可能性があります。`O(n)`ノードとすべてのペアのコストを確認する`O(n^2)`最悪の場合、クエリごとに。 

重要な観察点は、ペアの有効性は 2 つのノード間のパスが通過するかどうかのみに依存するということです。`u`。 これにより、問題が動的な「動きのシミュレーション」から静的なツリーのプロパティに変換されます。`(a, b)`有効です`u`もし、そしてその場合に限り`u`の間の道にあります`a`そして`b`。 

ノードを修正したら`u`を削除すると、ツリーはいくつかのコンポーネントに分割されます。`u`。 有効なペアはすべて、2 つの異なるコンポーネントからエンドポイントを選択する必要があります (または、1 つのエンドポイントが`u`）。 距離条件はツリー メトリックのみに依存します。 

これは、各ノードの標準的なオフライン構造を示唆しています。`u`、パスが通過するすべてのペアを考慮したいとします。`u`、それらの距離を計算し、それらの距離に関するしきい値クエリに答えます。 クエリごとに再計算するのではなく、各ノードによって「生成された」すべてのペア距離を事前計算します。`u`。 

これをきれいに行う方法は重心分解です。 各重心はセパレータとして機能し、ノードの各ペアは、最初に分離されるパス上に一意の最高重心を持ちます。 その重心は、そのペアを正確に 1 回カウントする役割を果たします。 各重心で`c`からの距離を収集します。`c`各子コンポーネントのノードに追加し、これらのリストを結合して、通過するすべてのコンポーネント間ペアを形成します。`c`。 ペアの距離`(a, b)`通過する`c`は`dist(c, a) + dist(c, b)`。 

各重心について`c`、そのようなすべてのペアの距離のソートされたリストを作成します。 それからクエリ`(u, k)`に関連付けられた保存された距離の数をカウントするだけになります。`u`少なくとも`k`。 各ペアは重心ツリー構造に 1 回だけ保存されるため、二重カウントが回避されます。

 ## アルゴリズムのチュートリアル

 1. ツリーの重心分解を構築します。 重心ツリーの各ノードは、元のツリー内のサブツリー分割点を表します。 これにより、ノードのすべてのペアが、パスが最初に分岐する 1 つの重心に確実に関連付けられます。 
2. 各重心について`c`からの距離のリストを計算します。`c`分解された各子サブツリー内のすべてのノードに。 これらの距離は、そのサブツリーに限定された DFS によって取得されます。 
3. 各重心について`c`、子の距離リストを段階的にマージします。 1 つのサブツリーを処理した後、その距離がグローバル マルチセットに挿入されます。`c`。 新しいサブツリーを処理するとき、このサブツリーと以前に処理されたサブツリーとの間で形成されたすべてのペアは、次を通過する有効なペアに寄与します。`c`。 
4. マージ中に、ソートされたリストに対する 2 ポインター手法を使用してペアの距離を計算します。 一定距離の場合`da`1 つのサブツリーから、`db`もう一方からのペアの距離は`da + db`。 
5. 計算されたすべての重心ペア距離を保存します。`c`ソートされた配列内。 この配列は、パスが通過するすべての有効なペアを表します。`c`。 
6. すべての重心を前処理した後、各クエリに答えます`(u, k)`重心を見つけることによって`u`保存されているペアの距離以上のペアの数を数えます。`k`二分探索を使用します。 

### なぜ効果があるのか

 すべてのノードのペア`(a, b)`には固有の重心があり、分解によって最初にそれらが異なるコンポーネントに分離されます。 その重心はまさにそれらの接続パス上にあるノードであり、それらの寄与を生成する責任があります。 距離は次のように計算されるため、`dist(c, a) + dist(c, b)`分離の瞬間に、各ペアは正しい距離で 1 回カウントされます。 重心分解により割り当ての一意性が保証され、省略と重複の両方が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_left

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
g = [[] for _ in range(n)]
for _ in range(n - 1):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    g[a].append(b)
    g[b].append(a)

# Centroid decomposition structures
subsz = [0] * n
blocked = [False] * n
centroid_tree = [-1] * n

# store distances of pair contributions per centroid
pair_dist = [[] for _ in range(n)]

def dfs_size(v, p):
    subsz[v] = 1
    for to in g[v]:
        if to != p and not blocked[to]:
            dfs_size(to, v)
            subsz[v] += subsz[to]

def dfs_centroid(v, p, nsz):
    for to in g[v]:
        if to != p and not blocked[to] and subsz[to] > nsz // 2:
            return dfs_centroid(to, v, nsz)
    return v

def collect(v, p, d, arr):
    arr.append(d)
    for to in g[v]:
        if to != p and not blocked[to]:
            collect(to, v, d + 1, arr)

def build(c):
    blocked[c] = True

    all_lists = []
    for to in g[c]:
        if blocked[to]:
            continue
        arr = []
        collect(to, c, 1, arr)
        all_lists.append(arr)

    global_list = []

    for arr in all_lists:
        arr.sort()
        for d in arr:
            # pair with existing nodes in global_list
            # two pointers: count contributions efficiently
            pass  # replaced below conceptually

        for d in arr:
            global_list.append(d)

    # actually compute pair distances between lists
    active = []
    for arr in all_lists:
        arr.sort()
        for d in arr:
            for d2 in active:
                pair_dist[c].append(d + d2)
        for d in arr:
            active.append(d)

    blocked[c] = True
    for to in g[c]:
        if not blocked[to]:
            c2 = dfs_centroid(to, c, 0)
            centroid_tree[c2] = c
            build(c2)

# build centroid decomposition from node 0

croot = dfs_centroid(0, -1, n)

for i in range(n):
    pair_dist[i].sort()

for _ in range(q):
    u, k = map(int, input().split())
    u -= 1
    arr = pair_dist[u]
    # count pairs with distance >= k

主要な実装リスクは、各ペアが正確に 1 回カウントされるようにすることです。 重心分解では、これは、アクティブな構造にマージされる前に、さまざまな子コンポーネントからの距離を結合するだけで適用されます。 

## 実用的な例

 ノード 1 が 2 と 3 に接続し、2 と 3 の両方がさらに小さなチェーンに接続する小さなツリーを考えてみましょう。 問い合わせてみると`u = 1`、すべての有効なペアは 1 の異なる分岐に存在するか、1 自体を含む必要があります。 1 の重心は 2 のサブツリーと 3 のサブツリーからの距離を結合し、分岐間のパスに正確に対応するペアの距離を生成します。

 ## 特殊なケース

 星形のツリーは、ほとんどすべてのペアが中心を通過するため、最も敏感なケースです。 そのノードでは、すべてのペアが異なるコンポーネントに存在するため、重心はすべての距離を正しく集計する必要があります。 コンポーネントを段階的にマージすることを忘れた実装では、カウントが大幅に過大または過少になります。 

ディープチェーンは、パスが重心を通過するペアのみを分解で正しく分離するかどうかをテストします。 同じサブツリー内で距離が誤って結合された場合、重心を通過しないペアが誤って含まれてしまいます。 

最後に、葉の近くのノードは、「葉に留まるかどうか」をテストします。`u`” は暗黙的に処理されます。分解では、明示的に処理されない限り、距離がゼロの場合はペアの合計から自然に除外されるため、この特別な場合を見逃すと有効性が失われます。`(u, x)`ペアのとき`x`十分に遠いです。
