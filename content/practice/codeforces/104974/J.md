 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースにはいくつかの花の種類があり、各種類には固定の「美しさ係数」があり、正確に 100 個の同一の花が利用可能です。 個々の花の値段は 1 ディナールで、私たちが買えるのはせいぜい 1 ディナールです。`c`全部で花。 

花のコレクションを購入する場合、花束スコアは、選択した花の総合的な美しさを店で入手可能なすべての花の総合的な美しさで割った比率として定義されます。 すべてのタイプが 100 個の同一の花を提供するため、分母はテスト ケースに対して固定されており、何を購入するかではなく、入力配列のみに依存します。 

これにより、タスクは純粋な最大化問題に変わります。つまり、予算制約の下で選択した花の美しさの合計を最大化し、それを定数値で正規化したいと考えます。 

それぞれの花の種類`i`貢献する`a_i`合計すると 100 部になります。 したがって、ショップは次のものを持っていることに相当します。`100 * n`それぞれの項目`a_i`ちょうど 100 回表示されます。 多くても選ぶことができます`c`アイテム。 

出力は、この正規化された最大値を表す実数です。 

制約により、最大で`5 × 10^4`テスト ケースごとのタイプ、最大`10`テストケース。 すべての花を明示的に展開すると、最大で次のようになります。`5 × 10^6`項目は境界線にありますが、最適化された言語ではまだ実現可能ですが、不要です。 

主なエッジケースは次のような場合です`c`非常に大きく、最大で`10^9`。 その状況では、利用可能な制限を超えることはできないため、制約は事実上無関係になります。`100n`花。 

単純な間違いは、これを分数最適化問題または連続最適化問題として扱ったり、分母が選択されたサブセットに依存すると誤解したりすることです。 たとえば、選択によって分母が変化すると誤って仮定すると、貪欲な選択が無効になる可能性があります。 もう 1 つの微妙な落とし穴は、すべてを拡張することです`100n`多くの値が繰り返されることを考慮せずに項目を削除すると、不必要なオーバーヘッドが発生します。 

小さな例:

 入力:```
n = 2, c = 3
a = [5, 1]
```5 のコピーが 100 個と 1 のコピーが 100 個あります。最適な選択は、明らかに 5 のコピー 3 つであり、1 を混ぜないことです。 同一の値をグループ化できないアプローチでは、余分な作業が必要になりますが、それでもこの構造を尊重する必要があります。 

## アプローチ

 プロセスを直接シミュレートする場合、すべてを構築します。`100n`花を美しさ順に分類し、一番上のものを取りましょう`c`。 すべての花が合計に対して独立して寄与しているため、これは正しいです。 問題は規模です。テスト ケースごとに最大 500 万の要素を並べ替えるのは境界線にありますが、それでもある程度の制限内にはありますが、明らかに不要です。 

重要な観察は、構造がすでにグループ化されていることです。 個々の花の観点から考える代わりに、各タイプを 100 個の同一の値のブロックとして扱うことができます。 すべての項目は独立していて加算的なため、最適な選択では常に高い値が優先されます。`a_i`まず価値観。 タイプ内ではすべてのコピーが同一であるため、タイプの部分的な選択は予算がなくなった場合にのみ行われます。 

これにより、問題がソートに減ります。`n`種類別`a_i`降順で、予算がなくなるまで各タイプから最大 100 個を貪欲に取得します。`c`。 

達成可能な最大の合計を計算すると、最終的な答えは、この合計をすべての花の一定の合計の美しさで割ったものになります。`100 * sum(a_i)`。 分子と分母に 1 を乗算すると、式が簡略化されて安定した浮動小数点計算になります。

 | 最適 (ソート タイプ + 貪欲) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての美しさ係数の合計を計算します。`S = sum(a_i)`。 これは、定数係数までの正規化の分母を表します。 
2. 配列をソートする`a`降順で。 これにより、常に最も価値のある花を最初に考慮することが保証されます。これは、すべての花が高品質であるため、必要なことです。`a_i`下位の花を支配する`a_i`。 
3. 変数を初期化する`taken_sum = 0`残りの予算を追跡する`c`。 
4. ソートされたリストを繰り返し処理します。 それぞれの値について`a_i`、このタイプからどれだけの花を取り出せるかを決定します。`take = min(100, c)`。 これにより、可用性の制約と予算の制約の両方が考慮されます。 
5.追加`take * a_i`に`taken_sum`、減算します`take`から`c`。 
6. 次の場合は早めに中止してください。`c`それ以上の寄与は不可能であるため、ゼロになります。 
7. 最終的な答えを次のように計算します。`taken_sum / S`。 

### なぜ効果があるのか

 このプロセスは、独立した重み付けされた項目のマルチセットに対する貪欲な選択を直接適用するものです。 それぞれの花はその種類内で同一であるため、最適な解決策はすべての花のソートされたマルチセットの接頭辞を選択することと同じです。 並べ替えにより、このプレフィックスは寄与度の低い順に並べられるため、選択された値の低い花を選択されていない花の値が高いものに置き換えると、常に合計が改善または維持されます。 分母が一定であるため、比率を最大化すると分子が最大化されることになり、この貪欲な構築により最適な花束が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        a = list(map(float, input().split()))
        
        total = sum(a)
        a.sort(reverse=True)
        
        rem = c
        taken = 0.0
        
        for val in a:
            if rem == 0:
                break
            take = min(100, rem)
            taken += take * val
            rem -= take
        
        print(taken / total)

if __name__ == "__main__":
    solve()
```コードは最初にすべての花の種類を読み取り、正規化合計を計算します。 並べ替えにより、最も価値のあるタイプが最初に処理されるようになります。 ループは種類ごとに最大 100 個の花を貪欲に消費しますが、予算を超えることはありません`c`。 最後の除算では、蓄積された選択スコアを必要な正規化された値に変換します。 

実装の微妙な点は、入力と出力の両方に実数が含まれるため、一貫して浮動小数点演算を使用することです。 もう1つの重要な点は、次の場合に早期終了することです。`rem`ゼロに達すると、不必要な反復が回避されます。`c`に比べて小さいです`n`。

| ステップ | 現在のタイプ | レム | 取る | 合計額 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    t = int(input())
    out = []
    for _ in range(t):
        n, c = map(int, input().split())
        a = list(map(float, input().split()))
        total = sum(a)
        a.sort(reverse=True)

        rem = c
        taken = 0.0

        for v in a:
            if rem == 0:
                break
            take = min(100, rem)
            taken += take * v
            rem -= take

        out.append(str(taken / total))
    return "\n".join(out) + "\n"

# minimal case
assert run("1\n1 1\n5\n")[:10], "min case"

# small greedy split
assert run("1\n2 3\n5 1\n") is not None

# all equal
assert run("1\n3 150\n2 2 2\n") is not None

# large budget saturates all
assert run("1\n2 1000\n1 2\n") is not None

 ## 特殊なケース

 いつ`c`を超える`100n`、アルゴリズムはあらゆるタイプを完全に処理し、利用可能なすべての花を取得します。 ループはこれを自然に処理します。`min(100, rem)`予算がなくなるか、すべてのタイプが消費されるまで、常に 100 が上限となります。 

もしすべてなら`a_i`が等しい場合、並べ替えによって順序は変更されませんが、アルゴリズムは型を順番に埋めることで正しく動作します。 たとえば、`a = [2,2,2]`そして`c = 250`、最初の 2 つのタイプからそれぞれ 100 を取得し、3 番目のタイプから 50 を取得し、均一の重みと一致する比例結果を生成します。 

いつ`c`は非常に小さいため、最初のいくつかの最も高い値の型のみが操作されます。 アルゴリズムは常に降順で処理されるため、価値の高い花が使い果たされる前に価値の低い花を選択することはできず、予算が極度に不足している場合でも最適性が維持されます。
