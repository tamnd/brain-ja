 ## 解決策
 ## 問題の理解

 現在の合計に次々に適用される整数調整の短いシーケンスが与えられます。 各値は、正か非正かに応じて合計を増減できますが、実際にはそのまま加算されるだけです。 

問題は最後の完全なシーケンスだけに関するものではありません。 これらの値の任意のサブセットを選択し、元の値を保存し、合計が正確に 14 になるサブセットが少なくとも 1 つ存在するかどうかを判断することができます。そのような選択が存在する場合、出力は肯定となり、それ以外の場合は負になります。 

この構造は基本的に、負、ゼロ、正を含む整数の小さなリストからサブセット合計として 14 を形成できるかどうかを尋ねています。 

要素数の制約は非常に小さく、n は最大 19 です。この限界が問題の重要な信号です。 このサイズのリストでは、サブセットの総数が 2^19 (50 万をわずかに超える) であるため、すべてのサブセットにわたる指数関数的な探索が可能になります。 これは、中間者要求や動的プログラミング ビットセットなどの高度な最適化手法を必要とせずに、Python で時間制限内で直接評価できるほど小さいです。 

各要素の値の範囲は -10 から 19 までで、通常の整数演算を超える特別な処理は必要ありません。 ただし、中間合計がマイナスになるか 14 を超える可能性があることを意味するため、枝刈り戦略を適用する場合は慎重に使用する必要があります。 

いくつかのエッジな状況には注意が必要です。 すべての数値が正で 14 より大きい場合、サブセットは 14 に達することはなく、正解はすぐに負になります。 たとえば、入力`[20, 30]`逆に、14 に等しい単一の要素がある場合、答えはすぐに肯定になります。 もう 1 つの微妙なケースは、ゼロが存在する場合です。 ゼロは合計を変更しませんが、依然として個別のサブセットの選択肢としてカウントされるため、追加のゼロが含まれるかどうかに関係なく、14 に達するサブセットは有効なままになります。 

## アプローチ

 最も直接的なアプローチは、指定された数値の可能なサブセットをすべて試して、その合計を計算することです。 各要素には含めるか含めないかの 2 つの選択肢があるため、2^n 個の可能性が生じます。 各サブセットについて、O(n) で合計を計算するか、ビットマスク列挙中に増分合計を維持します。 したがって、単純な実装では、総作業量は n 倍 2^n のオーダーになります。 

n = 19 の場合、この上限はおよそ 19 × 524,288 で、これは約 1,000 万回の原始演算に相当します。 Python では、特に加算とビット演算が安価であるため、これはまだ許容されます。 したがって、力技でもすでに十分です。 

別の見方としては、達成可能な合計に対する動的プログラミングがありますが、値には負の値が含まれるため、固定オフセットを使用した古典的なナップザック DP は少し面倒になります。 範囲を変更するか、セットを使用して到達可能な合計を追跡する必要があります。 これも機能しますが、この制約条件における単純なサブセット列挙と比較して、漸近的な複雑さは改善されません。 

重要な洞察は、サブセットを列挙する以上の最適化を行う必要がないということです。 n に対する制約は、意図した解決策を網羅的に検索するために明示的に選択されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(n · 2^n) | O(1) または O(n) | 承認済み |
 | DP / 合計のセット | O(n · S) ここで、S は合計範囲 | O(S) | 受け入れられるが不要 |

 ## アルゴリズムのチュートリアル

 各サブセットを長さ n のバイナリ マスクとして扱います。 各ビットは、対応する要素がサブセットに含まれるかどうかを示します。 

1. 整数の配列を読み取り、リストに格納します。 これにより、サブセット構築のための直接インデックス付きアクセスが可能になります。 
2. 0 から 2^n − 1 までのすべての整数を繰り返します。各整数は配列のサブセットを表します。 バイナリ表現は、各要素の包含または除外をエンコードします。 
3. サブセット マスクごとに、対応するビットが設定されているすべての要素の合計を計算します。 これは、0 から n − 1 までのすべての位置をスキャンし、ビットがアクティブかどうかをチェックすることによって行われます。 増分合計を維持するのではなく再計算する理由は単純さのためであり、制約を考慮するとコストはまだ許容範囲内です。 
4. いずれかの時点で計算された合計が 14 に等しければ、有効なサブセットが 1 つ存在するだけでよいため、すぐに成功を返すことができます。 
5. すべてのマスクを使い果たした後にサブセットが合計 14 を生成しない場合、それは不可能であると結論付けます。 

### なぜ効果があるのか

 配列のすべてのサブセットは 1 つのバイナリ マスクに正確に対応し、すべてのバイナリ マスクは 1 つのサブセットに正確に対応します。 この全単射により、すべてのマスクを反復処理することで、可能なすべてのサブセットが省略や重複なく列挙されることが保証されます。 各サブセットの合計を明示的にチェックするため、反復中に合計が 14 になる有効な組み合わせが見つかる必要があります。 したがって、存在する場合、アルゴリズムはそれを見つけます。 存在しない場合、完全な列挙は成功をトリガーせずに完了します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = input().strip().split()
    if not data:
        return
    n = int(data[0])
    arr = list(map(int, data[1:]))

    # in case input is split across lines
    while len(arr) < n:
        arr.extend(map(int, input().split()))

    target = 14

    for mask in range(1 << n):
        s = 0
        for i in range(n):
            if mask & (1 << i):
                s += arr[i]
        if s == target:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```解析ステップでは、数値が行間で分割されたり、一貫性なく結合されたりする、若干不規則な入力書式設定が考慮されます。 コア ロジックはビットマスク列挙です。 各マスクは独立して解釈され、ローカル合計変数が蓄積されます。`s`。 検出結果 14 での早期終了により、有効なサブセットが見つかった後の不必要な探索が防止されます。 

微妙な実装の詳細は、入力解析で最初のトークンを超える厳密な行構造を想定しないようにすることです。 競技プログラミング環境では、防御的な解析により、不正なスペースによる実行時エラーが回避されます。 

## 実用的な例

 ### 例 1

 入力は配列に対応します`[3, 11]`。 

サブセットを列挙します。 

| マスク | 選択された要素 | 合計 | チェック |
 | --- | --- | --- | --- |
 | 00 | [] | 0 | いいえ |
 | 01 | [3] | 3 | いいえ |
 | 10 | [11] | 11 | いいえ |
 | 11 | [3、11] | 14 | はい |

 マスク時`11`の場合、合計はちょうど 14 になるため、アルゴリズムは停止し、YES を出力します。 

これは、アルゴリズムが枝刈りやヒューリスティックを必要とせずにフルセットを有効なサブセットとして正しく識別していることを示しています。 

### 例 2

 入力は以下に対応します`[6, -8, -4, -3, 0, 12, 17]`。 

部分的なトレース:

 | マスク | 選択された要素 | 合計 | チェック |
 | --- | --- | --- | --- |
 | 0000001 | [6] | 6 | いいえ |
 | 0000010 | [-8] | -8 | いいえ |
 | 0001000 | [-3] | -3 | いいえ |
 | 0010000 | [0] | 0 | いいえ |
 | 0100000 | [12] | 12 | いいえ |
 | 1000000 | [17] | 17 | いいえ |
 | 0001010 | [-8、-3] | -11 | いいえ |
 | 0100101 | [6、12] | 18 | いいえ |
 | 0100011 | [6、-8、12] | 10 | いいえ |
 | 0100101 | [6、12] 再びパターン | 18 | いいえ |

 最終的に、マスクの 1 つが合計 14 を生成し、列挙が停止します。 

この例は、貪欲な選択に依存できない理由を示しています。 正の数値だけでは 14 に達することが保証されず、合計を正確に調整するには負の値が不可欠な場合があります。

## 特殊なケース

 単一の要素が 14 に等しい場合は、その要素のみが選択されるサブセット マスクによって直ちに処理されます。 反復中に、その要素に対応する正確に 1 ビットが設定されたマスクは合計 14 を生成し、早期終了をトリガーします。 

すべての数値が負の場合は、どのサブセットも合計を正の目標まで増やすことができないことを示しています。 アルゴリズムは引き続きすべてのサブセットを列挙しますが、計算されたすべての合計は非正のままであるため、14 の等価性チェックはトリガーされず、最終出力は NO になります。 

ゼロを含む場合は、何も貢献しない余分な要素が正確さを妨げないことを示します。 要素 14 のみを含むサブセットは依然としてマスク間に存在し、追加のゼロは単に重複した合計を作成するだけで、ターゲット サブセットの検出には影響しません。
