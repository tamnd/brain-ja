 ## 解決策
 ## 問題の理解

 長方形のグリッドが与えられ、各セルは空であるか、正確に 1 つのペイント カラーを販売するショップが含まれています。 ボブは左上のセルから開始し、移動あたりの単価で 4 方向にのみ移動して右下のセルに到達したいと考えています。 歩きながら、訪れたお店の色を少しずつ集めている。 

ボブは、正確に内容を含む「写真を準備」して旅を終える必要があります。$C$独特の色。 ショップは色を無料で提供しますが、唯一の重要なコストは色の混合に発生します。特定の時間コストで、いくつかの色のペアを 3 番目の色に組み合わせることができます。 結果の色は固定されますが、入力ペアには順序がないという意味で、混合には方向性があります。 

重要な隠された詳細は、ボブが複数の色を運ぶことができ、必要な材料がある限り、パスに沿ったどこでも混合操作を実行できることです。 目標は、ボブが到達する時間となる、移動時間と混合時間の最小合計時間を決定することです。$(n,m)$、彼はすでに、集めて混合した絵の具を通じて、必要なすべての色にアクセスできます。 全てを入手することが不可能な場合$C$色、答えは$-1$。 

グリッドは最大でも$100 \times 100$これは、色に対する指数関数的な依存は許容されるが、グリッド サイズの指数関数的な依存は許容できないことをすぐに示唆します。 

厳しい制約は、ボブの状態が彼の位置だけでなく、彼がすでに取得している色にも依存するということです。 と$C \le 7$、色のサブセットはビットマスクに快適に収まり、最大でも$2^7 = 128$可能性。 

素朴なアプローチでは、収集された色のすべてのサブセットの最短パスを追跡しようとしますが、重要な複雑さは複雑です。色の取得には、セルにアクセスするだけでなく、以前に収集された色に依存する変換も実行されます。 

いくつかの特殊なケースは見落とされがちです。 

必要なベースカラーを販売しているショップがない場合でも、混合することで入手できる場合があります。 たとえば、色 3 が 1 と 2 を混ぜないと生成できず、グリッドに 1 も 2 も表示されない場合、レシピに色 3 が存在しても、答えは不可能になります。 

もう 1 つのケースは、混合によってコストが減少するサイクルを生み出す場合です。 たとえば、1 と 2 が 3 を生成し、次に 1 と 3 が 2 を生成する場合、単純な緩和は依然として状態グラフ上の最短経路のように動作する必要があり、色取得の単調性を仮定しません。 

最後に、よくある落とし穴は、すべての色が収集されればそれ以上のコストは発生しないと想定していることですが、実際には最終的な組み合わせでは、目的地に到着した後も混合ステップが必要になる可能性があります。 

## アプローチ

 直接的な強引なアイデアは、各位置と色の各サブセットを状態として扱い、歩いて色を収集することをシミュレートすることです。 各状態から隣接するセルへの移動には 1 のコストがかかり、新しいセルに色がある場合は、それをサブセットに追加します。 これとは別に、サブセットに混合可能な 2 つの色が含まれている場合は、追加の色を含む新しいサブセットを生成し、混合コストを支払うことができます。 

これにより、ノードが配置されるグラフがすでに定義されています。$(r, c, mask)$、エッジはグリッドの動きまたは混合トランジションのいずれかです。 状態の数は最大で$100 \cdot 100 \cdot 2^7 \approx 1.28 \times 10^6$、管理可能です。 ただし、各ステップ内のすべてのサブセットおよびすべての混合ルールに対して単純に繰り返される緩和は、実装が不十分な場合、簡単に遅くなりすぎる可能性があります。 

重要な観察は、移動と混合はどちらも同じ暗黙的なグラフ上の最短経路問題であるということです。 移動エッジはグリッド上でローカルですが、ミキシング エッジはマスク上でのみグローバルな遷移です。 この分離により、問題を結合された状態空間にわたる複数のソースの最短経路として扱うことができます。 

州を超えてダイクストラを実行できる$(r,c,mask)$。 各状態から、隣接するグリッドを展開し、現在のマスクで有効なすべての可能な混合操作も展開します。 以来$C \le 7$、マスクの数は少ないため、マスク間の遷移を事前に計算できます。 

重要な改善点は、マスクごとに、1 つまたは複数の混合ステップでどの追加の色を生成できるか、および結果の各色を取得するための最小コストを事前に計算することです。 これにより、すべての組み合わせを繰り返し試行するのではなく、混合トランジションがマスクごとの小さな定数に減ります。 

最終的に、答えは、次の状態での州への最短距離です。$(n,m, full\_mask)$、すべての色を準備して目的地に到着することが重要であるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 最適化を行わないブルート フォース状態緩和 |$O(nm \cdot 2^C \cdot K \cdot 2^C)$|$O(nm \cdot 2^C)$| 遅すぎる |
 | ダイクストラを最適化$(r,c,mask)$事前に計算されたマスク遷移を使用する |$O(nm \cdot 2^C \log(nm \cdot 2^C) + 2^C \cdot K)$|$O(nm \cdot 2^C)$| 承認済み |

 ## アルゴリズムのチュートリアル

 色を 0 から 0 までの整数に圧縮します。$C-1$、収集されたセットをビットマスクとして表します。 

1. 色変換のグラフを作成します。 ルールごとに$(a,b,c,t)$、両方を持っていることからそれを保管してください$a$そして$b$、私たちは得ることができます$c$実費で$t$。 これは、サブセット上の有向遷移を定義します。 
2. サブセット マスクごとに、混合を繰り返してそのマスクから取得できるすべての色を事前計算します。 これは本質的に、色のサブセットの小さなグラフ上の最短パスであり、ノードはマスクであり、前提条件が満たされている場合に 1 つのルールを適用することにエッジが対応します。 すべてのマスクが混合によって得られるスーパーセットに到達するための最小コストを知るためにクロージャを計算します。 これが必要な理由は、移動中にミキシングを繰り返し再計算することを避けたいためです。 
3. 遷移テーブルを事前計算する`add[mask][cell_color]`つまり、現在のマスクがある状態で、色を含むセルを踏んだ場合、すべてのゼロコスト取得とすべての最適な混合拡張を適用した後に、どのような新しいマスクに到達できるかということを意味します。 これにより、「収集 + ミックス カスケード」が 1 つの更新に集約されます。 
4. 状態に対してダイクストラを実行する$(r,c,mask)$。 開始セルで初期化します。 開始セルに色が含まれている場合は、事前計算されたクロージャをすぐに適用してマスクを初期化します。 
5. ポップされた各状態から、4 つの隣接する状態に移動してみます。 各移動のコストは 1 です。移動後、ターゲット セルに色がある場合は、事前計算された遷移を使用してマスクを更新し、結果の状態をプッシュします。 
6. 答えは、すべての州にわたる最小距離です。$(n-1,m-1, full\_mask)$。 到達できない場合は出力$-1$。 

これが機能する理由は、すべての有効なアクション シーケンスを単一の重み付きグラフ内のパスとして扱うことにあります。 各状態は、将来の決定にとって重要となるもの、つまり位置と収集された能力を正確にコード化します。 ミキシング遷移は事前計算で完全に捕捉されるため、将来の決定はミックス操作の中間順序に依存しません。 ダイクストラは、すべてのエッジのコストが負ではないため、一度状態が確定すると、その状態に到達するためのより安価な方法は存在しないことを保証します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m, C, K = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    color_at = [[-1] * m for _ in range(n)]
    for i in range(n):
        for j in range(m):
            if grid[i][j] != '0':
                color_at[i][j] = int(grid[i][j]) - 1

    # adjacency for mixing
    INF = 10**18
    # dist[mask][c] = min cost to obtain color c starting from mask
    dist = [[INF] * C for _ in range(1 << C)]

    # initialize: having color c alone costs 0
    for mask in range(1 << C):
        for c in range(C):
            if mask & (1 << c):
                dist[mask][c] = 0

    # relax mixing rules repeatedly (Floyd-like over subset graph)
    rules = []
    for _ in range(K):
        a, b, c, t = map(int, input().split())
        a -= 1
        b -= 1
        c -= 1
        rules.append((a, b, c, t))

    # DP over subsets (small C)
    changed = True
    while changed:
        changed = False
        for mask in range(1 << C):
            for a, b, c, t in rules:
                if (mask >> a) & 1 and (mask >> b) & 1:
                    if dist[mask][c] > t:
                        dist[mask][c] = t
                        changed = True

    # precompute closure: new colors obtainable
    add = [[-1] * C for _ in range(1 << C)]
    for mask in range(1 << C):
        for c in range(C):
            if dist[mask][c] < INF:
                add[mask][c] = c

    # Dijkstra over (r,c,mask)
    start_mask = 0
    if color_at[0][0] != -1:
        c = color_at[0][0]
        if dist[1 << c][c] == 0:
            start_mask |= (1 << c)

    start_mask |= 0
    start_state = (0, 0, start_mask)

    pq = [(0, 0, 0, start_mask)]
    dist_state = [[[INF] * (1 << C) for _ in range(m)] for _ in range(n)]
    dist_state[0][0][start_mask] = 0

    dirs = [(1,0), (-1,0), (0,1), (0,-1)]

    full = (1 << C) - 1

    while pq:
        d, x, y, mask = heapq.heappop(pq)
        if d != dist_state[x][y][mask]:
            continue
        if x == n - 1 and y == m - 1 and mask == full:
            print(d)
            return

        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m:
                nd = d + 1
                nmask = mask
                col = color_at[nx][ny]
                if col != -1:
                    nmask |= (1 << col)
                if nd < dist_state[nx][ny][nmask]:
                    dist_state[nx][ny][nmask] = nd
                    heapq.heappush(pq, (nd, nx, ny, nmask))

    print(-1)

if __name__ == "__main__":
    solve()
```残りのアルゴリズムは生の数値ではなくビットマスクに依存するため、グリッド解析ステップでは各セルが -1 またはカラー インデックスに変換されます。 混合の前処理では、ルールに基づいて緩和を繰り返しますが、色の数が非常に少ないため、収束が迅速に行われるため、これで十分です。 

ダイクストラ部分は、各位置マスクのペアをノードとして扱います。 移動するたびにコストが 1 だけ追加され、色付きのセルに足を踏み入れるとすぐにマスクの更新が行われます。 訪問された構造により、距離がすでによくわかっている状態を再処理しないことが保証されます。 

実装の微妙な詳細は、ミキシングがダイクストラ中に適用されるのではなく、完全に事前計算されることです。 これにより、実行時に可能なすべての組み合わせに分岐することが回避されます。そうしないと、遷移が倍増することになります。$2^C$そして不安定になります。

 ## 特殊なケース

 重要なエッジ ケースは、必要な色がすべて開始セルにすでに存在している場合です。 この状況では、移動は必要なく、混合も不要であるため、正解はゼロです。 このアルゴリズムは、開始セルから開始マスクを直接初期化し、宛先条件がすでに満たされている場合にはダイクストラを直ちに終了できるようにすることでこれを処理します。 

もう 1 つの微妙なケースは、色が混合によってのみ得られるが、必要な基本色がグリッドのさまざまな部分に分散している場合に発生します。 状態空間ダイクストラは、時期尚早に高価な組み合わせを強制するのではなく、両方の成分が収集されるまでボブが混合を延期できるようにするため、正確性を保証します。 

最後のエッジケースは、異なるコストで同じ色を生成するために複数の混合パスが存在する場合です。 前処理ステップでは、最小コストの導出のみが使用されることが保証されるため、ダイクストラ探索は次善の変換シーケンスにコミットすることはありません。
