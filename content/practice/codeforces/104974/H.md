 ## 解決策
 ## 問題の理解

 文字列のコレクションが与えられ、それぞれが 1 から N までの個別のインデックスに関連付けられています。ここでのタスクは、最初の 2 つの文字列を順番に連結すると、他の 2 つの文字列を順番に連結した場合とまったく同じ文字列が得られるように、4 つの異なるインデックスを選択できるかどうかを判断することです。 

出力は、そのような 4 つ組が存在しない場合は否定的な答え、または連結の等価性を満たす 4 つの異なるインデックスの有効な選択とともに肯定的な答えになります。 

N ≤ 1000 という制約は十分小さいため、インデックスに対する二次作業は許容されます。 ただし、すべての文字列の合計の長さは 10^6 に達する可能性があるため、すべてのペアに対して明示的に連結文字列を繰り返し構築するソリューションは即座に除外されます。 すべてのペアごとの連結を構築する単純なアプローチでは、最大 N^2 個の文字列が生成され、その合計長は最悪の場合、数十億文字を軽く超える可能性があり、これは実行不可能です。 

2 番目の隠れた問題は、事前計算された表現を使用しない限り、2 つの連結された結果を比較しても定時間ではないことです。 二重ループ内で文字列の連結と比較を繰り返し実行するアプローチでは、文字列の長さを考慮すると、三次的な動作に移行する危険があります。 

素朴な考え方による典型的な失敗例は、ペアの等価性チェックが直接実行できると仮定することです。 

入力:```
4
a
aa
aaa
aaaa
```不注意な方法では、すべてのペアを試して連結された文字列を直接比較する可能性があり、長い文字列が繰り返し構築され、不必要な再計算が行われる可能性があります。 これは小さなケースでは問題ありませんが、すべての文字列が長い場合は遅くなりすぎます。 

正しいソリューションでは、連結の実体化を回避し、代わりに高速な等価性チェックをサポートするコンパクトな表現に依存する必要があります。 

## アプローチ

 ブルートフォース戦略は単純です。 すべての順序付きペア (i, j) を反復し、連結された文字列 Si + Sj を形成します。 次に、それを他のすべてのペア (k, l) と比較し、すべてのインデックスが異なることを確認します。 これは問題定義を直接エンコードしているため、これは正しいです。 ただし、O(N^2) 個のペアがあり、2 つの連結された文字列の比較には O(L) のコストがかかります (L はそれらを組み合わせた長さです)。 最悪の場合、単純に実行するとおよそ O(N^4 * L) 個の動作が発生するか、よくても O(N^4) 個の比較となり、これは実行可能な限界をはるかに超えています。 

重要な点は、実際には完全な連結文字列が必要ないということです。 必要なのは、それを一意に識別し、効率的に比較する方法だけです。 これはまさに文字列ハッシュによって可能になることです。 各文字列が事前にハッシュされており、基数のべき乗も事前に計算されている場合、Si + Sj のハッシュは、個々のハッシュと長さから定数時間で計算できます。 

すべてのペア (i, j) を固定サイズのキーにマッピングできると、同じキーを生成する 2 つの異なるペアを見つけることが問題になります。 これにより、タスクがハッシュ テーブル内の衝突の検出に減り、同時に関連するインデックスが異なることも検証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^4・L) | お(1) | 遅すぎる |
 | ハッシュベースのペアリング | O(N^2) | O(N^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての文字列とその長さのローリング ハッシュを事前計算します。 これにより、任意の文字列のハッシュと長さを一定時間でクエリできるようになります。 これが必要な理由は、連結がハッシュ値だけでなく、一方のハッシュをもう一方の文字列の長さだけシフトすることにも依存するためです。 
2. 可能な最大文字列長までのハッシュ ベースの累乗を事前計算します。 これにより、文字列を次々に追加するときに、2 番目のハッシュを追加する前に最初のハッシュを正しくスケーリングできることが保証されます。 
3. インデックスの順序付けされたすべてのペア (i, j) を繰り返します。 各ペアについて、Si のハッシュを Sj の長さだけシフトし、Sj のハッシュを加算する式を使用して、連結された文字列 Si + Sj のハッシュを計算します。 
4. 計算された各ペア ハッシュを、それを生成したインデックスの最初のペアにマッピングする辞書を使用します。 辞書キーは、明示的に構築することなく、連結された文字列全体を表します。 
5. 新しく計算されたペア ハッシュが既に辞書に存在する場合は、以前に保存されたペア (k, l) を取得します。 4 つのインデックス i、j、k、l がすべて異なることを確認してください。 そうである場合、有効な解決策が見つかったので、それをすぐに出力できます。 
6. すべてのペアをチェックした後、衝突が 4 つの異なるインデックスを生成しない場合は、有効な 4 つ組が存在しないと結論付けます。 

正確性は、同一の連結によって同一のハッシュが生成されるという事実に依存しており、十分に強力なハッシュ スキームを使用すれば、競合プログラミングの制約に関して衝突は実際には無視できる程度になります。 区別性チェックにより、両方のペアで同じインデックスが再利用されていないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N = int(input())
    s = [input().strip() for _ in range(N)]

    base = 91138233
    mod = (1 << 64)

    # precompute powers up to total length
    max_len = sum(len(x) for x in s)
    pow_base = [1] * (max_len + 1)
    for i in range(1, max_len + 1):
        pow_base[i] = (pow_base[i - 1] * base) % mod

    # precompute prefix hash and length
    h = []
    L = []
    for st in s:
        cur = 0
        for c in st:
            cur = (cur * base + ord(c)) % mod
        h.append(cur)
        L.append(len(st))

    def concat_hash(i, j):
        return (h[i] * pow_base[L[j]] + h[j]) % mod

    mp = {}

    for i in range(N):
        for j in range(N):
            val = concat_hash(i, j)
            if val in mp:
                k, l = mp[val]
                if len({i, j, k, l}) == 4:
                    print("YES")
                    print(k + 1, l + 1, i + 1, j + 1)
                    return
            else:
                mp[val] = (i, j)

    print("NO")

if __name__ == "__main__":
    solve()
```この解決策は、すべての文字列を読み取り、それぞれの文字列に対して多項式ローリング ハッシュを計算することから始まります。 部分文字列のハッシュを繰り返し再計算する代わりに、各文字列が単一の整数値に圧縮されます。 文字列を追加することは、最初のハッシュに 2 番目の文字列の長さに等しい基数の累乗を乗算することと同じであるため、べき乗配列は連結時にハッシュを正しくシフトするために使用されます。 

ネストされたループは、順序付けられたすべてのペアを列挙します。 Si + Sj は Sj + Si とは異なり、両方とも有効な候補であるため、この順序は重要です。 辞書には、連結された各ハッシュの最初の出現が格納されます。 ハッシュが繰り返されると、インデックスが重複するかどうかをすぐにテストします。 これにより、同じ種類のチョコレートを再利用する無効なソリューションが返されることがなくなります。 

64 ビットのモジュラスを使用すると、自然なオーバーフロー演算がエミュレートされ、Python での演算の高速性が維持されると同時に、競合の制約に耐えられるほど衝突が少なくなります。

 | 測定 | 複雑さ | 説明 |

 | スペース | O(N^2) | 辞書には最大でもすべてのペア ハッシュが保存されます。

 ## 特殊なケース

 微妙なケースとしては、複数のペアが同じ連結結果にマッピングされるが、インデックスが再利用される場合があります。 たとえば、多くの文字列が同一である場合、ほとんどのペアで同じ連結が生成されます。 アルゴリズムはインデックスの区別性を保証する必要があります。そうでないと、両方のペアで同じ要素が誤って 2 回再利用されてしまいます。 

もう 1 つのケースは、インデックスが重複しているために最初に発生した衝突が無効である場合です。 辞書には、ハッシュごとに代表的なペアが 1 つだけ保存されます。 その代表が現在のペアとインデックスを共有している場合、そのインデックスは拒否され、検索が続行されます。 これにより、すべてのペアが列挙され、すべてのハッシュ衝突が少なくとも 1 回テストされるため、誤検知を回避しながら、有効な解決策が最終的に発見されることが保証されます。
