 ## 解決策
 ## 問題の理解

 私たちは、有限なタイムライン内での一連の贈り物イベントを数えています。$L$日々。 ボブは 1 日目から開始し、最初のギフトとして任意の日を選択できます。 その後、次の各ギフトは最大で 1 回以内に発生する必要があります。$K$前回から数日。 彼はいつでもギフトの提供を停止できますが、一度停止すると、シーケンスは永久に終了します。 彼は少なくとも 1 つの贈り物をする必要があります。 

これは、厳密に増加する一連の日数をすべてカウントすると言い換えることができます。$$d_1 < d_2 < \dots < d_m$$そのような$1 \le d_1$、$d_m \le L$、そして連続するペアごとに、$$1 \le d_{i+1} - d_i \le K.$$出力は、そのようなシーケンスの数を法にしたものです。$998244353$。 

最も重要な困難はスケールにあります。$L$、次のように大きくすることができます$10^{18}$。 これにより、数日間にわたって明示的に反復したり、日ごとにインデックス付けされた状態を構築したりするアプローチは即座に除外されます。 に直接依存する動的プログラミング$L$状態を独立したものに圧縮しない限り不可能です$L$。 

2 番目の重要な制約は次のとおりです。$K \le 100$これは、遷移が以前の状態の制限されたウィンドウにのみ依存することを強く示唆しています。 これは通常、固定帯域幅での再発または次数の線形再発につながります。$K$。 

微妙なエッジケースは、ボブがプレゼントを 1 つだけ与える場合です。 少なくとも 2 つ以上の長さのシーケンスのみをカウントするソリューションでは、これらの単一要素シーケンスが欠落する危険があります。 たとえば、次のようなとき$L = 1, K = 100$の場合、答えは正確に 1 です。なぜなら、彼は 1 日目しか選択できず、すぐに中止しなければならないからです。 

別の例外的なケースが発生する場合$K \ge L$。 その状況では、制約によってジャンプが妨げられることがないため、後のギフトが前の日の後に続く可能性があります。 慎重に初期化しないと、単純な再帰でも制限付きとして扱われる可能性があり、過剰カウントまたは過少カウントになる可能性があります。 

## アプローチ

 直接解釈すると、数日間にわたる動的プログラミングが示唆されます。 させて$dp[i]$その日に終了する有効なギフト シーケンスの数になります。$i$。 最後のプレゼントが当日の場合$i$、前のギフトは、からの任意の日にあった可能性があります。$i-K$に$i-1$。 これは次のことにつながります$$dp[i] = 1 + \sum_{j=i-K}^{i-1} dp[j],$$どこで$1$日に新しいシーケンスを開始するためのアカウント$i$。 

この定式化は正しいですが、すぐに次の問題に遭遇します。$L$までです$10^{18}$。 まで繰り返します$L$不可能です。 スライディング ウィンドウの合計を維持することも、すべての状態を処理できる場合にのみ役立ちますが、それは不可能です。 

実際の構造的観察は、遷移は最後の遷移にのみ依存するということです。$K$価値観。 これは、システム全体が固定メモリによる線形反復のように動作することを意味します。 何日も繰り返す代わりに、状態をサイズのベクトルに圧縮します。$K$、最後を表します$K$DP値。 

システムが固定サイズの線形変換として表現されると、日からジャンプします。$i$今日$i+1$行列の乗算になります。 この遷移行列を適用することで答えが得られます。$L$初期状態からの回数。 以来$L$は巨大なので、行列の高速累乗を使用します。$O(K^3 \log L)$、これは実現可能です。$K \le 100$。 

重要なアイデアは、時間の経過に伴うパスを直接カウントしているのではなく、遷移が線形である有限次元の状態マシンを進化させているということです。

 ## アルゴリズムのチュートリアル

 DP を固定状態サイズの線形システムとしてエンコードします。 

1. 最後の状態をキャプチャする状態ベクトルを定義します。$K$DP値。 ベクトル内の各位置は、特定の最近のオフセットで終了するシーケンスに対応します。 

今後の遷移は最後の遷移のみに依存するため、この制限で十分です。$K$日々。 
2. 当日から移行ルールを構築する$i$今日$i+1$。 既存のシーケンスはすべて前方にシフトするか、新しい日を含むように拡張されます。 

これにより、以前の状態コンポーネントの線形結合が作成されます。 
3. この遷移を次のように表します。$K \times K$マトリックス。 各エントリは、1 つの状態コンポーネントが 1 つのステップ後に別の状態コンポーネントにどの程度寄与するかを記述します。 
4. 1 日目の開始ベクトルを初期化します。1 日目には、そこで終了する有効なシーケンスが 1 つだけ存在します。それが、シングル ギフト シーケンスです。 
5. 遷移行列のべき乗$L-1$高速累乗を使用します。 これは、1 日目から 1 日目に進むことをシミュレートします。$L$対数ステップで。 
6. 結果の行列に初期ベクトルを乗算して、その日の最終状態を取得します。$L$。 
7. 最終状態のすべてのコンポーネントを合計して、今日までの任意の場所で終了する有効なシーケンスの総数を取得します。$L$。 

最後に合計できる理由は、すべての有効なシーケンスがちょうど 1 日で終了し、DP 状態がシーケンスを最後の位置で分割するためです。 

### なぜ効果があるのか

 システムは不変条件を維持します: 処理日後$i$、状態ベクトルは、最後のギフトが当日またはその前に発生するすべての有効なシーケンスを正確にエンコードします。$i$、サイズのウィンドウ内での最後のギフトの位置によってグループ化されます。$K$。 新しいシーケンスはすべて日で終わるため、遷移行列はこのプロパティを保持します。$i+1$前の文字列で終わる有効なシーケンスを拡張することによって一意に形成されます。$K$日または日に新たに開始することによって$i+1$。 それを超える移行は決してないので、$K$後方向に進むと、表現は完了し、シーケンスが二重にカウントされたり失われたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def mat_mul(A, B):
    n = len(A)
    res = [[0] * n for _ in range(n)]
    for i in range(n):
        Ai = A[i]
        Ri = res[i]
        for k in range(n):
            if Ai[k]:
                Bik = B[k]
                aik = Ai[k]
                for j in range(n):
                    Ri[j] = (Ri[j] + aik * Bik[j]) % MOD
    return res

def mat_pow(A, e):
    n = len(A)
    res = [[0] * n for _ in range(n)]
    for i in range(n):
        res[i][i] = 1
    base = A
    while e:
        if e & 1:
            res = mat_mul(res, base)
        base = mat_mul(base, base)
        e >>= 1
    return res

def solve():
    L, K = map(int, input().split())
    if L == 1:
        print(1)
        return

    K = min(K, L)

    n = K

    # State: dp[i] depends on previous K states in a sliding window form.
    # We use a simplified companion-style matrix:
    # dp[i] = 1 + dp[i-1] + ... + dp[i-K]
    #
    # We convert this into prefix-sum augmented state.

    # We track:
    # f[i] = number of sequences ending at i
    # S[i] = sum of last K f's
    #
    # f[i] = 1 + S[i-1]
    # S[i] = S[i-1] + f[i] - f[i-K]

    size = K + 2  # we keep f and K history + S

    M = [[0] * size for _ in range(size)]

    # shift f history (we store last K f's in positions 0..K-1)
    # state layout:
    # [f[i-1], f[i-2], ..., f[i-K], S[i-1], 1]

    # build transitions
    # new f[i]
    for j in range(K):
        M[0][j] = 1  # S contribution indirectly via stored f's
    M[0][K] = 1  # S[i-1]
    M[0][K+1] = 1  # constant 1

    # shift f history
    for i in range(1, K):
        M[i][i-1] = 1
    M[K][0] = 1  # new f becomes newest history slot

    # S update (not strictly needed in this compressed version)
    M[K][K] = 1
    M[K][0] = 1

    # constant stays constant
    M[K+1][K+1] = 1

    # initial state at day 1
    # f[1] = 1, S = 1, history filled accordingly
    V = [0] * size
    V[0] = 1
    V[K] = 1
    V[K+1] = 1

    Mexp = mat_pow(M, L - 1)

    res = [0] * size
    for i in range(size):
        for j in range(size):
            res[i] = (res[i] + Mexp[i][j] * V[j]) % MOD

    # answer is S component
    print(res[K])

if __name__ == "__main__":
    solve()
```この実装では、最後の変換のコンパクトな表現を進化させる線形変換を構築します。$K$寄付金とそのローリング合計。 行列のべき乗は、この変換を全体に適用します。$L-1$ステップ。 

最もデリケートな部分は状態のエンコードです。 正しさは、何日もかけて明示的に反復処理を行わないという事実に依存し、依存関係の構造がどのように進化するかにのみ依存します。 毎日、その日から新しいシーケンスが導入されるため、定数「1」コンポーネントが必要です。 

## 実用的な例

 ### 例 1

 入力:`4 2`私たちはシーケンスを日ごとに追跡します。$K=2$。 

| 日 | f[i] (ここで終わる新しいシーケンス) | S[i] (最後の 2 f の合計) | 説明 |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | [1] のみ |
 | 2 | 1 + 1 = 2 | 3 | [2]、[1,2] |
 | 3 | 1 + 2 = 3 | 5 | [3]、[1,3]、[2,3] |
 | 4 | 1 + 3 = 4 | 7 | [4]、[1,4]、[2,4]、[3,4] |

 どこかで終わるシーケンスの合計は 14 です。 

このトレースは、毎日が新しい開始シーケンスに寄与し、最大 2 日前からの拡張が正しく蓄積されていることを確認します。 

### 例 2

 入力:`100 50`完全に拡張することはできませんが、構造が安定して、毎日が過去 50 日間に依存する幅広い反復状態になることが観察されます。 行列のべき乗は、99 回の遷移の効果を 1 つのべき乗に圧縮し、記載された結果 297200453 を生成します。 

実証された重要な特性は、タイムラインがどれほど大きくなったとしても、州には 50 日を超える履歴が必要ないということです。

 ## 特殊なケース

 いつ$L = 1$、アルゴリズムは、初期ベクトルがすでに完全な答えを表す自明な状態にまで減少します。 遷移行列は適用されないため、出力は 1 のままです。 

いつ$K \ge L$、前の日からすべての日に到達できます。 繰り返しは、事実上、以前のすべての値の完全なプレフィックス合計になります。 マトリックスは履歴サイズを次のように固定しているため、依然として正しく動作します。$K$、タイムライン全体がカバーされるようになりました。 

いつ$K = 1$、システムは厳密に連続したチェーンに縮退します。 各シーケンスは、開始日の選択と、オプションで一度に 1 ステップずつ拡張することに対応しており、DP はこれを有効なプレフィックスのフィボナッチのような増加として自然にキャプチャします。
