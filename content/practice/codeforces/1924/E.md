 ## 解決策
 ## 問題の理解

 長方形の紙の切断とその一部の廃棄を繰り返す確率的プロセスをモデル化し、その面積がしきい値を下回るまでの予想ステップ数を計算するように求められます。 論文は寸法から始まる$n \times m$、各ステップで、境界ではない任意の整数の垂直線または水平線に沿ってカットが行われます。 垂直カットの場合は右側の部分が廃棄され、水平カットの場合は下部が廃棄されます。 ステップはすべての中から均一に選択されます$h+w-2$カットの可能性がある場合、$h$そして$w$現在の高さと幅です。 

入力は複数の独立したテスト ケースを与え、それぞれが指定します$n$、$m$、 そして$k$。 出力は予想されるステップ数のモジュロです。$10^9+7$、として表されます$p\cdot q^{-1} \bmod 10^9+7$期待値が分数の場合$p/q$。 まで対応しなければなりません$57{,}000$テストケース、そして$n$そして$m$と同じ大きさにすることができます$10^6$、すべてのテスト ケースの合計は次のように制限されます。$10^6$、これにより、$O(nm)$または$O(n+m)$テストケースのソリューションごとに。 

カット シーケンスの数は指数関数的に増加するため、すべてのカットをシミュレートする単純なアプローチは不可能です。 全体的に均一なメモ化$n \times m$部分長方形はメモリの関係で実行不可能です。 エリアがすでに下にある場合、エッジケースが発生します$k$開始時、この場合はゼロカットが必要、またはエリアが 1 つまたは 2 つ上のユニットの場合$k$、モジュロで表現する必要がある小さな整数の期待値が生じる可能性があります。$10^9+7$。 

## アプローチ

 ブルート フォース シミュレーションでは、すべてのカット シーケンスが試行され、平均ステップ数が計算されます。 これは原理的には正しいですが、シーケンスの数がおおよそ次のとおりであるため、実行できません。$2^{n+m}$最悪の場合、計算限界をはるかに超えてしまいます。 すべてのメモ化さえ$(h,w)$ペアの場合は保管が必要です$10^{12}$のエントリー$h \cdot w$、それは不可能です。 

重要な洞察は、プロセスには**期待の直線性**があるということです。 と表すと$E[h,w]$高さの長方形から始まる予想されるステップ数として$h$と幅$w$、繰り返しを書くことができます。$$E[h,w] = 0 \text{ if } h \cdot w < k$$それ以外の場合、各カット ライン (垂直または水平) の可能性は同等です。 所定の位置での垂直カット$x$幅の長方形を残します$x$そして高さ$h$、位置での水平カット$y$高さの長方形を残します$y$と幅$w$。 したがって：$$E[h,w] = 1 + \frac{1}{h+w-2} \left( \sum_{x=1}^{w-1} E[h,x] + \sum_{y=1}^{h-1} E[y,w] \right)$$合計が終わってしまうので、$x$そして$y$は期待値の算術級数であるため、プレフィックスの合計を計算して、$O(h+w)$ではなく長方形ごとに$O(hw)$。 この観察により、特に以下の合計が考慮されると、DP が実行可能になります。$n$そして$m$すべてのテストケースにわたって$10^6$。 

期待値のモジュロを計算するには、各ステップでモジュラー演算が必要です。$10^9+7$。 期待値は分数であるため、分子と分母を別々に保存し、分子 * 分母の逆剰余を計算します。$10^9+7$最後に。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース / シミュレーション | O(2^{n+m}) | O(nm) | 遅すぎる |
 | プレフィックス合計 + モジュラー分数を含む DP | テスト ケースごとに O(n+m) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n, m, k$。 もし$n \cdot m < k$、0を出力して続行します。 カットは必要ありません。 
2. DP 配列を初期化する`dp[h][w]`高さの長方形の予想される歩数を保存します`h`と幅`w`。 1 から始まるインデックスを使用します。 
3. プレフィックス合計配列を初期化する`hsum[h][w]`そして`wsum[h][w]`迅速な合計を可能にする`dp`行と列に沿った値。 これらの配列によりコンピューティングが可能になります$\sum_{x=1}^{w-1} E[h,x]$そして$\sum_{y=1}^{h-1} E[y,w]$前処理後の O(1) にあります。 
4. 反復する`h`1から`n`そして`w`1から`m`。 もし`h*w < k`、 セット`dp[h][w] = 0`。 それ以外の場合は、次のように計算します。$$dp[h][w] = \frac{( \text{hsum}[h][w-1] + \text{wsum}[h-1][w] + h + w -2)}{h + w -2}$$分子には以下が含まれます`h+w-2`を説明するために`+1`期待して。 

1. フェルマーの逆関数を使用して各ステップでモジュラー分数を保存し、除算モジュロを計算します。$10^9+7$。 
2. DP テーブルを入力したら、出力します。`dp[n][m]`モジュロ $10^9+7`。 

機能する理由: この DP は、考えられるすべてのカットの寄与を線形に加算することに基づいて、予想されるステップ数の繰り返しを直接エンコードし、プレフィックスの合計により計算が高速化されます。 モジュロ演算により、分数がモジュロで正しく処理されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

def modinv(a):
    return pow(a, MOD-2, MOD)

t = int(input())
for _ in range(t):
    n, m, k = map(int, input().split())
    if n * m < k:
        print(0)
        continue

    dp = [0] * (m + 1)
    for h in range(1, n + 1):
        new_dp = [0] * (m + 1)
        prefix = [0] * (m + 1)
        for w in range(1, m + 1):
            if h * w < k:
                new_dp[w] = 0
            else:
                sum_prev_w = prefix[w - 1]
                sum_prev_h = dp[w]
                num = (sum_prev_w + sum_prev_h + h + w - 2) % MOD
                den = h + w - 2
                new_dp[w] = num * modinv(den) % MOD
            prefix[w] = (prefix[w - 1] + new_dp[w]) % MOD
        dp = new_dp
    print(dp[m])
```このソリューションは、行ごとに DP テーブルを構築します。`dp[w]`は前の行を表します。`prefix[w]`現在の行に沿って合計を累積します。`sum_prev_w`O(1)で計算できます。 分数の除算は逆モジュラーによって実行されます。 境界条件はチェックによって処理されます`h*w < k`。
