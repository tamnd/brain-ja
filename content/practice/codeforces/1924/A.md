 ## 解決策
 ## 問題の理解

 文字列が与えられています`s`と 2 つの整数`n`そして`k`。 概念的には、すべての長さの文字列が`n`最初のものを使用して構築できます`k`アルファベットの文字が部分列としてどこかに現れます。`s`。 サブシーケンスでは文字をスキップできますが、順序は保持する必要があります。 1 つの長さの文字列でも`n`最初のものを使用して`k`文字が表示されない場合は、そのような文字列を証拠として出力する必要があります。 

制約は、何が実現可能かを理解するための鍵となります。`n`そして`k`両方とも最大 26 であり、長さは`s`最大 1000 です。これらの制限により、可能な長さの文字列の総数は`n`使用して`k`文字は`k^n`。 これは指数関数的に増加するため、可能性のあるすべての文字列がサブシーケンスであるかどうかをチェックする単純な総当りアプローチは、次の場合には実行不可能です。`n`そして`k`小さくない。 

重要なエッジケースが発生するのは、`s`文字を繰り返すには短すぎます。 たとえば、次の場合`s`は`"ab"`と`n = 2`そして`k = 2`、文字列`"aa"`サブシーケンスは 1 つしかないため、サブシーケンスにはできません`'a'`で`s`。 同様に、`s`特定の文字が完全に欠如している場合、その文字を必要とする文字列は直ちに不可能になります。 不用意なアプローチでは、文字の頻度をチェックせずにすべての文字列を生成しようとして、何も表示されずに失敗するか、タイムアウトになる可能性があります。 

## アプローチ

 ブルートフォース手法では、すべてのものが生成されます。`k^n`一定の長さの文字列`n`それぞれが次の部分列であるかどうかをテストします`s`。 1 つの文字列の長さをテストする`n`文字列に対して`s`長さの`m`のコストは O(m) であるため、最悪の場合の演算回数は O(m * k^n) となり、これは次の上限ではまったく実行不可能です。`n`そして`k`。 

重要な洞察は、すべての文字列を生成する必要はないということです。 部分列になり得ない辞書編集上の最小の文字列を見つけるだけで済みます。 これは、次の各文字の出現を数えることによって貪欲に行うことができます。`s`。 ターゲット文字列の各位置で、まだ残っている最小の文字を選択します。 ある位置で文字が利用できない場合、サブシーケンスとして形成できない文字列が即座に得られます。 左から右に繰り返して、可能な限り最小の文字を選択することにより、答えが「いいえ」の場合に欠落していることが保証される 1 つの文字列を構築します。 すべての位置に文字を正常に割り当てることができれば、すべての文字列が存在し、答えは「YES」になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m * k^n) | O(n) | 遅すぎる |
 | 貪欲な部分列のカウント | O(n * k + m) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. テスト ケースごとに、整数を読み取ります。`n`、`k`、 そして`m`、および文字列`s`。 
3. 配列を初期化する`count`サイズの`k`ゼロに。 反復処理`s`最初のそれぞれの回数を数えます`k`文字が表示されます。 
4. 空の文字列を初期化する`res`候補の欠落文字列の場合。 
5. ポジションごとに`i`長さのターゲット文字列内`n`からの文字を繰り返し処理します。`'a'`に`k`- 番目の文字:

 - 現在の文字に残りの出現箇所がある場合`s`、そのカウントをデクリメントし、それに追加します`res`。 
- 使用可能な文字がない場合は、最初の文字を辞書順に追加します。`res`残りのポジションと休憩のために。 これにより、作成中の文字列がサブシーケンスとして現れることがなくなります。 
6. 構築後`res`、長さが以下かどうかを確認します。`n`。 そうであれば、答えは「いいえ」であり、印刷します。`res`。 オカレンスを使い果たすことなく、すべてのポジションを正常に割り当てることができた場合、答えは「YES」です。 
7. すべてのテスト ケースに対して繰り返します。 

**機能する理由**: このアルゴリズムは、文字が利用可能な場合にのみ文字を使用する文字列を貪欲に構築します。`s`。 いずれかの位置で失敗した場合、少なくとも 1 つの長さの文字列が保証されます。`n`サブシーケンスにすることはできません。 それ以外の場合は、鳩の巣原理と貪欲な選択によって、すべての文字列を形成できます。 これは正確性と効率性の両方を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k, m = map(int, input().split())
    s = input().strip()
    freq = [0] * k
    for c in s:
        freq[ord(c) - ord('a')] += 1

    res = []
    found_missing = False
    for i in range(n):
        placed = False
        for j in range(k):
            if freq[j] > 0:
                freq[j] -= 1
                res.append(chr(ord('a') + j))
                placed = True
                break
        if not placed:
            # No letter available, fill remaining with 'a'
            res.extend(['a'] * (n - i))
            found_missing = True
            break

    if found_missing:
        print("NO")
        print(''.join(res))
    else:
        print("YES")
```**説明**: の各文字の出現を数えます。`s`そして貪欲にそれらを候補文字列に入れてみてください。 残りの文字が足りないためにその位置を埋めることができない場合は、表示できない文字列を構築し、有効な NO 応答を保証します。 それ以外の場合、すべての位置を割り当てることができれば、文字列にはすべての可能なサブシーケンスが含まれます。

    output = []
    t = int(input())
    for _ in range(t):
        n, k, m = map(int, input().split())
        s = input().strip()
        freq = [0]*k
        for c in s:
            freq[ord(c)-ord('a')] += 1
        res = []
        found_missing = False
        for i in range(n):
            placed = False
            for j in range(k):
                if freq[j]>0:
                    freq[j]-=1
                    res.append(chr(ord('a')+j))
                    placed=True
                    break
            if not placed:
                res.extend(['a']*(n-i))
                found_missing=True
                break
        if found_missing:
            output.append("NO")
            output.append(''.join(res))
        else:
            output.append("YES")
    return "\n".join(output)

## 特殊なケース

 文字列の場合、`s`各文字が 1 つだけ含まれている場合、アルゴリズムは、文字の部分シーケンスが繰り返されることは不可能であることを検出します。 例えば、`n=2`、`k=2`、`s="ab"`NO を正しく出力し、`aa`。 のために`n=1`、`k=1`、`s="a"`の場合、すべての文字列が存在し、YES が出力されます。 このメソッドは最大値を処理します`k`そして`n`可能な文字列をすべて生成することなく、利用可能な文字を貪欲にチェックすることで、指数関数的な複雑さを回避します。
