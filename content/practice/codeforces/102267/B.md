 ## 解決策
 ## 問題の理解

 次のように、指定された素数 (n) を 2 つの素数 (a) と (b) に分割する必要があります。 

[
 a+b=n。 
】

 任意の有効なペアが受け入れられるため、複数の分解が存在する場合に特定の分解を見つける必要はありません。 そのようなペアが存在しない場合は、(-1) が出力されます。 

境界 (n\le 10^7) は十分に大きいため、考えられるすべてのペアをチェックし、数値の素数を繰り返しテストするのは、1 秒の制限時間内ではコストがかかりすぎます。 ただし、(10^7) は十分小さいため、その平方根は約 (3162) にすぎないため、試行除算による単一の素数テストは非常に安価です。 主な課題は (n) のサイズではなく、(n) 自体が素数であるという事実により、可能なペアが大幅に制限されることを認識することです。 

間違いを引き起こしやすい境界状況は 3 つあります。 最小の素数 (n=2) の場合、これを正の素数の合計として記述する唯一の方法は、(2) より小さい素数を必要とするため、正しい出力は次のようになります。`-1`。 (n=3) の場合、最小の素数を使用できるのは (2+1) のみですが、(1) は素数ではないため、答えは次のようになります。`-1`。 (1) を素数として扱う不用意な実装は、このケースを誤って受け入れてしまいます。 

数値のパリティにより、別の一般的な罠が発生します。 たとえば、(n=11) の場合、奇数と奇数は偶数であるため、両方の素数が奇数になることはありません。 可能なペアは (2+9) のみですが、(9) は複合であるため、正しい出力は次のようになります。`-1`。 パリティを使用せずに任意のペアを試行すると、利用可能な時間のほとんどが無駄になる可能性があります。 

## アプローチ

 直接的なブルート フォース ソリューションでは、(2) から (n-2) までの可能なすべての (a) を試し、(b=n-a) を設定し、両方の数値の素数をテストできます。 この方法は正しいです。なぜなら、考えられるすべての分解にはその範囲内に素数の 1 つがあり、最終的にはすべての候補ペアが考慮されるからです。 ただし、試行除算によって素数性をチェックする場合、各テストで (O(\sqrt n)) 回の除算が必要になる可能性があります。 最悪の場合、これにより (O(n\sqrt n)) の仕事が得られます。 (n=10^7) では、これは (10^7\cdot3162\およそ 3.16\times10^{10}) 試行分割のオーダーであり、1 秒に収まる範囲をはるかに超えています。 

入力の構造により、より強力な観察が得られます。 (2) 以外のすべての素数は奇数です。 (n) は素数なので、(2) または奇数になります。 奇数の素数 (n) の場合、2 つの奇数の素数の合計は偶数になるため、有効なペアには (2) が含まれている必要があります。 可能なペアは 1 つだけです。 

[
 2+(n-2)=n。 
】

 したがって、問題全体は、(n-2) が素数であるかどうかを確認することに帰着します。 候補を検索したり、ふるいを構築したり、複数のペアを調べたりする必要はありません。 

ブルートフォース手法は、すべての分解を明示的に探索するため機能しますが、必要以上に多くの素数チェックを実行するため失敗します。 パリティ観測により、検索スペースが (O(n)) 個の候補ペアからちょうど 1 つの候補ペアに縮小されます。 単一の試行分割素数性テストは、指定された制限に対して十分に高速です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n\sqrt n)) | (O(1)) | 遅すぎる |
 | 最適 | (O(\sqrt n)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 素数 (n) を読み取ります。 (n=2) の場合、すぐに印刷します`-1`, なぜなら、2 つの素数はそれぞれ少なくとも (2) なので、それらの合計は少なくとも (4) になるからです。 
2. 奇数の素数 (n) の場合、パリティを使用して、必要な 2 つの素数のうちの 1 つが (2) でなければならないと結論付けます。 他の値は強制的に (n-2) となるため、他の候補を試す必要はありません。 
3. 試行除算を使用して (n-2) が素数であるかどうかをテストします。 (\sqrt{n-2}) までの約数をテストするだけで十分です。合成数に平方根より大きい因数がある場合、それに対応する因数は平方根より小さくなければならないからです。 
4. (n-2) が素数の場合、次のように出力します。`2 n-2`。 それ以外の場合は印刷します`-1`なぜなら、奇数の素数 (n) の有効なペアはすべて、まさにこのペアでなければならないからです。 

### なぜ効果があるのか

 すべての奇数の素数 (n) について、(a) と (b) の両方が素数である (n=a+b) と仮定します。 両方が奇数の場合、それらの合計は偶数になり、(n) が奇数であるという事実と矛盾します。 したがって、そのうちの 1 つは唯一の偶数素数でなければなりません (2)。 したがって、もう一方は (n-2) に等しくなければなりません。 アルゴリズムはこの強制候補を正確にチェックし、(n-2) が素数である場合に正確にそれを受け入れます。 (n=2) の場合、2 つの素数の最小和は (4) であるため、ペアは存在できません。 したがって、考えられるすべての入力が正しく処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_prime(x):
    if x < 2:
        return False

    if x % 2 == 0:
        return x == 2

    d = 3
    while d * d <= x:
        if x % d == 0:
            return False
        d += 2

    return True

def solve():
    n = int(input())

    if n == 2:
        print(-1)
        return

    other = n - 2

    if is_prime(other):
        print(2, other)
    else:
        print(-1)

if __name__ == "__main__":
    solve()
```の`is_prime`関数は最初に (2) より下の値を拒否し、(n=3) の場合を処理します。`other`(1) に等しい。 偶数も個別に扱います。 その後は、奇数の約数のみを考慮する必要があるため、ループは (3) から開始され、(2) ずつ増加します。 

条件`d * d <= x`は試行分割の標準境界です。 (\sqrt{x}) を超える約数をテストしても、すでにテストされているより小さい補完因子がなければ、新しい因子を発見できません。 浮動小数点平方根を計算する代わりに乗算を使用すると、精度の問題も回避できます。 

main 関数は、候補を作成する前に (n=2) を処理します。 他の有効な入力ごとに、`other = n - 2`唯一可能な 2 番目の素数です。 プログラムは不要なペア列挙を実行しません。 

ここでは Python の整数はオーバーフローせず、素数テストでの最大の乗算は (3162^2) 程度であるため、数値的な懸念はありません。 

## 実用的な例

 最初のサンプルの場合、(n=5)。 (5) は奇数であるため、可能な唯一のペアには (2) が含まれ、(5-2=3) が残ります。 

| (n) | 候補者 (n-2) | 除数チェック | 結果 |
 | --- | --- | --- | --- |
 | 5 | 3 | 偶数チェック以降は何も必要ありません |`2 3`|

 候補 (3) は素数であるため、強制ペアは有効です。 トレースは、他のペアを考慮する必要がない理由を示しています。 

2 番目のサンプルの場合は (n=11)。 ここでも、パリティにより 1 つの素数が (2) になり、(9) が残ります。 

| (n) | 候補者 (n-2) | 除数チェック | 結果 |
 | --- | --- | --- | --- |
 | 11 | 9 | (3\mid9) |`-1`|

 ループを続行する必要がある前に、除数 (3) が見つかります。 (9) は複合であるため、可能な唯一のペアは失敗し、答えが存在しないことが証明されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(\sqrt n)) | 素数性テストは 1 つだけ実行され、(\sqrt{n-2}) までの奇数の約数がチェックされます。 |
 | スペース | (O(1)) | このアルゴリズムは、一定数の整数のみを保存します。 |

 (n\le10^7) の場合、素数性テストでは最大でも大まかに (3162) 個の可能な除数の値が検査されますが、実際には約半分だけが検査されます。これは、除数さえスキップされるためです。 これは 1 秒の制限時間内に収まり、256 MB の制限に比べてメモリの使用量は無視できます。 

## テストケース```python
import sys
import io

def is_prime(x):
    if x < 2:
        return False

    if x % 2 == 0:
        return x == 2

    d = 3
    while d * d <= x:
        if x % d == 0:
            return False
        d += 2

    return True

def solve():
    n = int(input())
    if n == 2:
        print(-1)
        return

    other = n - 2
    if is_prime(other):
        print(2, other)
    else:
        print(-1)

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    output = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = output

    try:
        solve()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout
        input = old_input

    return output.getvalue().strip()

assert run("5\n") == "2 3", "sample 1"
assert run("11\n") == "-1", "sample 2"

assert run("2\n") == "-1", "minimum prime"
assert run("3\n") == "-1", "n - 2 equals 1"
assert run("7\n") == "2 5", "smallest successful odd case"
assert run("9999991\n") == "-1", "maximum valid prime input"

print("All tests passed.")

## 特殊なケース

 のために`n = 2`、アルゴリズムは明示的な境界チェックに入り、出力します。`-1`。 その理由は、単に候補が失敗するということよりも強力です。2 つの素数はそれぞれ少なくとも (2) であるため、それらの和は (2) にはなりません。 盲目的に計算するソリューション`n - 2`は (0) を取得しますが、これは素数ではありませんが、このケースを明示的に処理すると、推論が明確になります。 

のために`n = 3`の場合、強制される 2 番目の値は (3-2=1) です。 素数関数はすぐに戻ります`False`(2) より下の値は素数ではないため、プログラムは次のように出力します。`-1`。 これにより、カスタム素数性テストが (2) で除数ループを開始し、約数が見つからないために誤って (1) を素数として扱うというよくある間違いが見つかります。 

のために`n = 5`、強制ペアは (2+3) です。 素数性テストでは (3) が受け入れられるため、プログラムは次のように出力します。`2 3`。 これは、分解が存在する最小の有効な入力であり、候補境界が正しく処理されていることを確認します。 

のために`n = 11`、強制ペアは (2+9) です。 素数性テストは (3) をチェックし、(9) が (3) で割り切れることを確認し、次の値を返します。`False`。 プログラムは印刷します`-1`。 別のペアを試しても役に立ちません。2 つの奇数の素数の合計は偶数になるため、可能な構造は (2+9) だけです。 

等素分解の場合、(a=b=p) と仮定します。 次に (n=2p)、これは偶数です。 入力 (n) は素数であるため、唯一の偶数の可能性は (n=2) ですが、どの素数 (p) でも (2) が (2p) と等しくなることはありません。 したがって、有効な入力が 2 つの出力素数を等しくすることはできません。 理論上の最小の等素和は (2+2=4) になりますが、(4) は素数ではないため入力として許可されません。 

最大の有効な入力 (n=9,999,991) に対して、アルゴリズムは引き続き素数テストを 1 つだけ実行します (今回は (9,999,989))。 その候補は (223) で割り切れるため、その係数が見つかるとすぐにテストが停止し、プログラムが出力します。`-1`。 候補ペアの数は 1 つのままであるため、(n) のサイズは基本的な戦略を変更しません。
