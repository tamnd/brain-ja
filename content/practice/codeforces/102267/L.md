 ## 問題の理解

 文字列は 3 つのシンボルから構築されます。`a`、`b`、 そして`c`。 操作では、1 つのシンボルを固定の 2 つのシンボル パターンに拡張したり、出現する 1 つのシンボルを削除したりできます。`abc`。 このタスクは建設的です。最大でも次のシーケンスを生成します。`3n`文字列全体を空の文字列に変換する、またはそのようなシーケンスが存在しないことを証明する有効な操作。 

入力には最大 1 つの長さの文字列が含まれます`2 * 10^5`。 出力は単一の応答値ではありません。 これは実際の一連の操作であり、報告されるすべてのインデックスは、以前のすべての操作が適用された後の文字列を参照します。 元のステートメントとサンプルは Codeforces から入手できます。 

サイズ制限により、多くの可能な操作シーケンスを検討するものは除外されます。 二次シミュレーションでさえ、1 秒の制限の下ではすでに望ましくありませんが、必要な出力自体には次のものが含まれる可能性があります。`600000`操作。 意図したソリューションでは、入力を基本的に 1 回処理し、生成するだけで済みます。`O(n)`操作。 

不注意なアプローチを露呈するいくつかのエッジケースがあります。 入力`a`解決可能です: に展開します`ab`、 それから`abc`を選択し、3 つの操作を使用して削除します。 入力`c`最初の文字は次の文字になる可能性があるため、不可能です`ba`、しかし、最初の文字は`b`、およびで始まる文字列`b`最初の文字を削除することはできません。 すべてのキャラクターが最終的には変身できることを前提とした不注意な実装`abc`間違って受け入れてしまうだろう`c`。 

入力`bac`も不可能です。 その最初の文字は`b`, したがって、そのキャラクターを`a`の`abc`削除。 不用意に左から右へのシミュレーションを行うと、サフィックスが変換され、先頭のサフィックスを中心に無効な演算が誤って構築される可能性があります。`b`。 

もう一つの重要な事例は、`ac`。 最初に含まれていない場合でも解決できます。`abc`。 順序は`ac -> aba -> abca -> empty`: 最初に置き換えます`c`による`ba`、新しいものと交換します`b`による`bc`、削除します`abc`。 すでに存在するもののみを検索する実装`abc`この件を見逃す。 

ついに、`abb`不可能です。 最初のあと`b`前のものと一致します`a`、 残り`b`は残りの文字列の先頭にあり、消えることはありません。 これにより、貪欲に削除する実装が捕捉されます。`ab`すべてかどうかを確認せずに`b`先行がある`a`。 

## アプローチ

 直接的なブルートフォース手法では、現在の文字列を維持し、あらゆる正当な操作を試みます。 最大でも一定の長さの文字列で`4n`、あるかもしれません`O(n)`立場の選択肢、有効な回答には最大で以下を含めることができます。`3n`操作。 したがって、すべてのシーケンスを探索するには、次のオーダーが必要になる可能性があります。`(4n)^(3n)`最悪の場合は分岐。 到達可能な文字列の数は指数関数的に増加するため、メモ化してもアプローチは節約されません。 

有益な観察は、操作に含まれるローカル動作のセットが驚くほど少ないということです。 あらゆるものを排除できます`c`3 つのローカル構造の 1 つを使用します。 現在の削減されたプレフィックスが次で終わる場合`a`、接尾辞`ac`に戻すことができます`a`3 つの操作を使用します。 削減されたプレフィックスが次で終わる場合`ab`、新しい`c`すぐに与える`abc`、削除することができます。 削減されたプレフィックスが次で終わる場合`bb`、変更する別の 3 操作構造があります。`bbc`に戻る`bb`。 

結局`c`キャラクターのみを扱っています`a`そして`b`残る。 その時点で毎回`b`直前に生き残ったものとペアにすることができます`a`。 ペア`ab`を変更することで 2 つの操作で削除できます。`b`の中へ`bc`そして削除`abc`。 どれでも`a`結局残った`b`ペアになった文字は 3 つの操作で個別に削除できます。 

重要なのは、これらの変換を処理済みの接頭辞に適用できる一方、未処理の接尾辞はそのまま残せることです。 進化する完全な文字列ではなく、現在の縮小されたプレフィックスのみを覚えておく必要があります。 公式コンテストのチュートリアルでは、これと同じローカルの建設的な構造が使用されています。

### なぜ効果があるのか

 中心的な不変条件は次のとおりです`v`は、すでに処理された入力接頭辞から到達可能な文字列を表しますが、その接頭辞以降の文字はすべて変更されません。 毎`c`上記の 3 つのローカル ID のいずれかによって削除されるため、最初のスキャンの後は、`c`残った文字。 

2 番目のスキャンでは、同じ不変条件が維持されます。`g`: すべての処理済み`b`前の 1 つと一緒に完全に削除されました`a`。 いいえの場合`a`が利用可能な場合、残りの文字列は次で始まります`b`、永久にリーダーになることができません`a`取り外し可能なもの`abc`。 したがって、障害状態は、貪欲な選択の制限ではなく、真の不可能性です。 

スキャンが成功した場合のみ、`a`文字は残り、それぞれを 3 つの操作で個別に削除できます。`a -> ab -> abc -> empty`工事。 したがって、生成されたシーケンスは常に空の文字列に到達します。 

操作範囲の場合、すべてのオリジナル`c`最初のスキャン中に最大 3 回の操作がかかります。 生き残ったすべてのキャラクター`v`オリジナルです`a`または`b`、2 回目のスキャン中に最大 3 回の操作がかかります。 これら 2 つのグループは互いに素であるため、合計は最大でも`3n`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

BASE = 1_000_000

def solve_one(s):
    n = len(s)
    if s[0] != 'a':
        return None

    ops = []

    def add(tp, idx):
        ops.append(tp * BASE + idx)

    v = []

    for ch in s:
        if ch != 'c':
            v.append(ch)
            continue

        if not v:
            return None

        k = len(v)

        if v[-1] == 'a':
            # ac -> aba -> abca -> empty, leaving the old a.
            add(3, k + 1)
            add(2, k + 1)
            add(4, k)

        else:
            # The prefix ends in b.
            if k == 1:
                return None

            if v[-2] == 'a':
                # abc -> empty.
                add(4, k - 1)
                v.pop()
                v.pop()
            else:
                # bbc -> bcbc -> bbabc -> bb.
                add(2, k - 1)
                add(3, k)
                add(4, k + 1)

    g = []

    for ch in v:
        if ch == 'a':
            g.append(ch)
        else:
            if not g:
                return None

            k = len(g)

            # ab -> abc -> empty.
            add(2, k + 1)
            add(4, k)
            g.pop()

    for _ in g:
        # a -> ab -> abc -> empty.
        add(1, 1)
        add(2, 2)
        add(4, 1)

    out = [str(len(ops))]
    out.extend(f"{op // BASE} {op % BASE}" for op in ops)
    return "\n".join(out)

def main():
    s = input().strip()
    ans = solve_one(s)

    if ans is None:
        print(-1)
    else:
        print(ans)

if __name__ == "__main__":
    main()

リスト`v`処理されたプレフィックスの仮想表現です。 操作によって生成される実際の拡張文字は含まれません。 例えば、取り扱いの際に、`ac`、実際の文字列は一時的に次のようになります`aba`、 それから`abca`、その後負けます`abc`、 しかし`v`ただ残っている`a`。 縮小された形式のみを維持することで、アルゴリズムが線形になります。 

最初のスキャンのインデックスは以下に基づいています。`len(v)`。 のために`ac`ケース、オリジナル`c`位置にあります`k + 1`、つまり両方とも次のように入力します`3`そして入力してください`2`その位置を使用します。 最初の拡張の後、新しい`b`まさにそこにあります。 結果として得られる`abc`位置から始まります`k`、タイプです`4`索引。
