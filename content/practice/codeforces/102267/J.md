 ## 問題の理解

 動物園は次のサイクルです。`n`場所。 国民が出発地を選択する`a`、別の場所`b`、およびそれらを接続するサイクルの周りの 2 つの方向の 1 つ。 選択した単純なパスには最大でも`k`エッジ。 次に、市民はその道に沿って、次の地点で始まり次の地点で終わるまで歩きます。`a`、選択したパスのすべての場所を訪問します。`m`動く。 

タスクは、そのようなすべての歩行をモジュロでカウントすることです`10^9 + 7`。 

サイクルを一時的に忘れる有効な方法は、開始位置と 1 つの方向を固定することです。 その方向に沿って位置に番号を付けます。`0, 1, 2, ...`。 したがって、ウォークは単なる一連の動きになります。`+1`または`-1`。 から始まります`0`、決してマイナスになってはいけない、決してそれ以上に進んではいけない`k`、そして最終的にはに戻らなければなりません`0`。 ウォークでは選択したエンドポイントを訪問する必要があるため、`b`、その最大到達位置によって、選択したパスの終点が決まります。 

制約`n <= 10^5`～に比例するものはすぐに除外されます`n^2`、制限時間はわずか1秒です。 パラメータ`m <= 2000`ははるかに小さいため、実際の動的プログラミングは以下に依存する必要があることが強く示唆されます。`m`サイクルの大きさではなく。 以来`k`と同じ大きさにすることができます`10^5`また、サイクル位置のすべてのペアを含む状態空間を確保する余裕もありません。 

数え間違える簡単な方法がいくつかあります。 のために`2 1 1`、答えは`0`なぜなら、同じ場所で始まり同じ場所で終わる空ではない散歩は同じ長さだからです。 訪問した場所の数を歩行距離として扱うソリューションでは、ここで何かが誤ってカウントされてしまいます。 

のために`2 1 2`、答えは`8`。 開始場所は 2 つあり、方向は 2 つ選択できます。 それぞれの選択肢について、有効なウォークは次のとおりです。`a -> neighbor -> a`。 2 つの方向を忘れると、`4`の代わりに`8`。 

のために`3 2 4`、答えは`18`。 開始位置と方向が固定されている場合、有効な戻りの歩行には長さがあります。`2`そして`4`。 1 つの長さの歩道があります`2`、そして2つの長さの散歩`4`、それぞれに3つの四球を与えます。`2n = 6`開始方向の選択。 よくある間違いは、すべてのパスの長さを個別にカウントし、考えられる複数のエンドポイントに従って誤って同じ歩行をカウントしてしまうことです。 

## アプローチ

 直接的な総当たりソリューションでは、開始位置を選択し、2 つの方向のいずれかを選択し、終点までの距離を選択し、長さまでの左右の動きのすべてのシーケンスを列挙できます。`m`。 固定パスの場合は、`2^L`正確に考えられるシーケンス`L`移動するので、次までの長さをすべて列挙します。`m`必要`2 + 4 + ... + 2^m = 2^(m+1) - 2`シーケンス。 すべての開始位置、方向、経路の長さにわたる操作数は次のとおりです。`2 * n * k * (2^(m+1) - 2)`。 

最大値では、これにはおよその係数が含まれます。`2^2000`したがって、検索空間の最初の部分でさえ、処理できる範囲をはるかに超えています。 

ブルート フォースが概念的に機能する理由は、すべての四球が 2 つの可能な動きのシーケンスにすぎないためです。 問題は、これらのシーケンスのほとんどは、選択したパスから離れるか、開始位置に戻らないため、無関係であることです。 それらを生成する代わりに、各移動回数の後でまだ可能なシーケンスのみをカウントすることができます。 

開始位置と方向を修正します。 させて`j`その方向に沿った開始位置からの現在の距離になります。 散歩はから移動できます`j`に`j-1`または`j+1`。 選択したパスが開始点の後ろに残るため、負の位置に到達することはありません。 決して超えることはないかもしれない`k`選択したパスは最大でも長さがあるため、`k`。 

これにより、小さな動的プログラミング状態が得られます。 後`i`動き、`dp[i][j]`現在距離にあるすべての有効なプレフィックスをカウントします`j`。 帰りの散歩はまさに有る状態です`j = 0`。 までのすべての正の長さにわたってこれらの状態を合計すると、`m`1 つの開始位置と 1 つの方向について、考えられるすべての抽象的な歩行をカウントします。 

最後の乗算の背後には、特に有益な観察が 1 つあります。 固定された開始位置と方向に向けて、空ではない有効な戻り歩行を実行します。 させて`h`到達する最大距離になります。 ウォークは一度に 1 つのエッジを移動するため、あらゆる距離を訪問します。`0`を通して`h`。 エンドポイントを選択できる`b`離れた場所になる`h`、つまり、選択したパス全体を訪問することになります。 逆に、元の問題からのすべての有効なウォークでは、開始位置と方向についてそのようなシーケンスが 1 つだけ生成されます。 したがって、エンドポイントを個別に列挙する必要はありません。 

がある`n`開始位置と 2 つの方向の選択肢があるため、抽象的な歩行を数えた後、次の値を掛けます。`2n`。 これは、ソリューションで使用される中心的なリダクションです。

 ## アルゴリズムのチュートリアル

 1. 抽象開始位置を位置に固定します。`0`そしてサイクルの周りの一方向。 実際の開始位置と方向はすべて同じように動作するため、この 1 次元表現では歩行数をカウントするだけで済みます。 
2. 定義する`dp[j]`現在位置にある現在の長さの有効なウォークの数として`j`。 当初、歩行の長さは 0 であり、開始点にあります。`dp[0] = 1`そして他のすべての状態はゼロです。 
3. 次の移動ごとに、新しい配列を計算します。`next`。 位置で終了するウォーク`j > 0`から来た可能性があります`j-1`または`j+1`、 それで`next[j] = dp[j-1] + dp[j+1]`。 で終わる散歩`0`からしか来られなかった`1`、 それで`next[0] = dp[1]`。 
4. までのポジションのみ`min(i, k)`その後に検討する必要がある`i`動く。 散歩では以上の動きはできません`i`エッジイン`i`移動し、選択したパス自体の長さは最大でも`k`。 これにより、DP 幅が最大で次のように制限されます。`min(m, k)`。 
5. 長さの状態を計算した後`i`、 追加`dp[0]`答えに。 に戻るすべての非ゼロ長のウォーク`0`完全に有効な散歩です。 私たちはあらゆる人に対してこれを行います`i`から`1`を通して`m`、長さは以下によって制限されているため、`m`、等しい必要はありません`m`。 
6. 累積カウントを乗算します。`2n`。 がある`n`可能な開始位置と、各開始位置から可能な 2 つの方向。 1 次元 DP は、歩行によって到達する最大距離として終点を暗黙的にすでに決定しています。 
7. すべての加算と最終的な乗算の剰余を計算します。`10^9 + 7`。 歩行の数は指数関数的に増加するため、計算全体にわたってモジュラー演算が必要になります。 

### なぜ効果があるのか

 不変条件は、正確に処理した後、`i`動き、`dp[j]`長さを正確に数えます-`i`許可された間隔内に留まり、一定の距離で終了する移動シーケンス`j`最初から。 トランジションでは、以前の 2 つの可能なポジションが正確に考慮されますが、外側のポジションは省略されます。`[0,k]`したがって、無効なウォークが DP に入ることはなく、有効なウォークが失われることもありません。 完全なウォークは、次の時点で終了するのが特徴です。`0`そして、空ではないすべての戻りウォークが何らかの正の最大値に達するため、`h`、その最大値により、選択したパスの一意のエンドポイントが得られます。 したがって、DP でカウントされたすべての歩行は、固定された開始位置と方向に対する 1 つの有効な歩行に正確に対応します。 乗算`2n`その後、すべての実際の開始位置と方向が 1 回だけ計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k, m = map(int, input().split())

    width = min(k, m)

    # prev[j] = number of valid walks of the previous length
    # currently at distance j from the starting point.
    prev = [0] * (width + 2)
    prev[0] = 1

    ans = 0

    for length in range(1, m + 1):
        limit = min(length, k)
        cur = [0] * (width + 2)

        # Position 0 can only be reached from position 1.
        cur[0] = prev[1]

        for j in range(1, limit + 1):
            cur[j] = (prev[j - 1] + prev[j + 1]) % MOD

        ans += cur[0]
        ans %= MOD

        prev = cur

    ans = ans * (2 * n) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```最初の配列は、移動前の状態を表します。 設定`prev[0] = 1`開始位置に空のウォークが 1 つだけあることを意味します。 最初の移動の前に他の位置に到達することはできません。 

コードは長さごとに新しいものを構築します。`cur`配列。 ポジティブへの移行`j`2 つの隣接する位置から直接来ます。 表現`prev[j + 1]`配列には 2 つの余分なセルがあるため、安全です。 これらのセルはゼロのままであり、特別な場合を必要とせずに上限を便利に処理できます。 

下限は次のように個別に処理されます。`cur[0] = prev[1]`。 からの移行はありません`-1`位置ゼロよりも下に移動すると、選択したパスから離れることになるためです。 

ループは到達するだけです`min(length, k)`。 これで十分なので後は`length`ウォーカーはこれ以上遠くに移動することはできません`length`、選択したパスはそれを超えることはできません`k`。 

のみ`cur[0]`が回答に追加されます。 これは、長さごとに行うのではなく、長さごとに意図的に行われます。`m`、までのすべての偶数の長さのため、`m`異なる歩行を定義できます。 奇数の長さは自動的にゼロになります。 

長さの遷移はローリング配列で十分です。`i`長さだけに依存する`i-1`。 これにより、2 次元からのメモリが削減されます。`O(mk)`テーブルへ`O(min(m,k))`。 Python 整数にもオブジェクト オーバーヘッドがあるため、この削減は 256 MB のメモリ制限の下で役立ちます。 

の乗算`2 * n`DP カウントが蓄積された後にのみ発生します。 値は剰余として減算されます`10^9 + 7`そのため、Python は膨大な正確な答えを構築する必要がありません。
