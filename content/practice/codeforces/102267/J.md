 ## 解決策
 ## 問題の理解

 動物園は (n) 個の場所のサイクルです。 市民は、開始位置 (a)、サイクルの周囲の方向、および最大長の単純なパス (k) を選択します。 ウォークは、選択したパス内に留まり、(a) に戻り、パスのすべての場所を訪問する必要があります。 その移動数は (m) を超えてはなりません。 タスクは、すべての可能な歩行をモジュロ (10^9+7) でカウントすることです。 

一時的にサイクルを忘れる便利な方法は、(a) から選択した 1 つの方向を見ることです。 (a) を位置 (0)、次の位置を (1) などとラベル付けします。 有効なウォークは、(0) からある最大位置 (d) までの整数セグメント上のウォークとなり、移動するたびに現在の位置が (1) または (-1) ずつ変化します。 ウォークは (0) で開始および終了し、(0) を下回ることはなく、その最大位置は最大でも (k) です。 

ここには微妙な点があります。 (d) を明示的に選択する必要はありません。 歩行が最大位置 (d) に到達すると、パスの最後の位置を訪問する必要があるため、選択したパスはまさにその長さになります。 したがって、(0) と (k) の間にある歩行をカウントすると、選択されたすべての可能なパスが自動的に 1 回だけカウントされます。 方向と開始位置は (2n) 倍で復元できます。 

制約 (n\le 10^5) は、すべての開始位置とすべての可能な歩行を反復するものを除外します。 さらに重要なのは、(m\le2000) は動的プログラミングを可能にする小さなパラメーターであることです。 長さ (i) の歩行は開始点から (i) よりも遠くになることはできないため、時間 (i) での関連する位置は (0,\ldots,\min(i,k)) のみです。 すべての (i\le m) を合計すると、(O(m^2)) 個の状態が得られ、(m=2000) の場合、最大約 400 万個になります。 

簡単な間違いの 1 つは、移動ではなくエンドポイントを数えることです。 たとえば、入力 (4\ 3\ 3) の場合、唯一可能な空でない閉じたウォークは長さ (2) を持ち、つまり、隣接する場所に移動してすぐに戻ります。 (4) 出発地と (2) 方向があるので、答えは (8) です。 その歩行を長さ (3) を持つものとして扱うと、誤って破棄されてしまいます。 正しい出力は (8) です。 

もう 1 つの間違いは、歩行が正確な距離 (k) に到達する必要があると仮定することです。 たとえば、(n=5,k=4,m=4) の場合、最大距離が (1) のみであっても、歩行 (0\to1\to0) は有効です。 実際に選択されたパスの長さは (1) ですが、要件が最大 (k) であるため許可されます。 したがって、DP は、(k) に達する歩行だけでなく、最大値が (k) であるすべての歩行をカウントする必要があります。 

3 番目の境界ケースは (k=1) の場合に発生します。 唯一可能な移動は位置 (0) と (1) の間であるため、有効な歩行は偶数の長さの場合にのみ存在します。 (n=2,k=1,m=2) の場合、(2n=4) 個の開始点と方向の選択肢ごとに 1 つの歩行が存在し、出力 (4) が得られます。 誤って位置 (2) を許可する再発が発生すると、このケースは過大評価されます。 

## アプローチ

 直接的な総当たりソリューションでは、開始位置 (2 つの方向のいずれか) を選択し、長さ (m) までの可能なすべての動きのシーケンスを列挙できます。 各ステップには最大 2 つの選択肢があるため、(1) から (m) までの長さのシーケンスの数は次のようになります。 

[
 2+2^2+\cdots+2^m=2^{m+1}-2。 
】

 開始位置と方向には (2n) 通りの選択肢があります。 最悪の場合、これはおおよその意味です

 [
 2n(2^{m+1}-2)
 】

 候補配列。 (n=10^5) と (m=2000) では、これは完全に不可能です。 このブルート フォースは、可能なすべてのウォークを明示的にチェックするので正しいのですが、指数関数的なウォーク数が問題です。 

ウォークの構造により、状態空間がはるかに小さくなります。 始点と方向が決まれば、そのサイクルはただの線分になります。 時間 (i) において、歩行を続けるために必要な情報は、開始点からの現在の距離 (j) だけです。 (j) から、次の位置は (j-1) または (j+1) になります。 (0) より下の位置は禁止され、(k) より上の位置は禁止されます。

これは動的プログラミングの再発に直接つながります。 (dp[i][j]) を、(0) から開始し、決して ([0,k]) から離れず、位置 (j) で終了する長さ (i) のウォークの数とする。 移行は、

 [
 dp[i][j]=dp[i-1][j-1]+dp[i-1][j+1]。 
】

 位置 (0) では、(-1) への移動が禁止されているため、最初の項は存在しません。 位置 (k) では、(k) から (k+1) への遷移が禁止されます。 

ウォークは、最終位置が (0) になった時点で閉じられます。 (dp[i][0]) を (1\le i\le m) 全体で合計します。 開始位置には (n) 個の選択肢があり、方向には (2) 個の選択肢があるため、最終結果は (2n) 倍されます。 

見かけの (O(mk)) 複雑さも、見た目よりも優れています。 時間 (i) では、(i) より大きい位置に到達できないため、(\min(i,k)+1) 位置のみが関係します。 (m\le2000) なので、遷移の総数は (O(m\min(m,k))=O(m^2)) となります。

 | --- | --- | --- | --- |
 | ブルートフォース | (O(n2^m)) | (O(m)) | 遅すぎる |
 | 最適なDP | (O(m\min(m,k))) | (O(\min(m,k))) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (n,k,m) を読み取ります。 最初に 1 つの固定された開始位置と 1 つの固定された方向の歩行をカウントし、最後に (2n) 個の対称的な選択肢を復元します。 
2. 選択した方向を 1 次元の座標系として表します。 開始位置の座標は (0) で、選択した方向に沿って移動すると座標が増加し、戻ると座標が減少します。 選択したパスの長さは最大 (k) であるため、有効な座標は (0,\ldots,k) です。 
3. 初期化（dp[0][0]=1）します。 何らかの移動を行う前に、長さ 0 のウォークが 1 つだけ存在し、開始位置にあります。 
4. (1) から (m) までの各時間 (i) について、すべての可能な位置 (j) に到達する方法の数を計算します。 再発というのは、
 [
 dp[i][j]=dp[i-1][j-1]+dp[i-1][j+1]。 
】
 位置 (j) は、前回の隣接する 2 つの位置の 1 つからのみ到達できます。 
5. (j) を (0\le j\le\min(i,k)) に制限します。 長さ (i) の歩行は (i) を超える距離に到達できないため、(i) を超える位置は不要です。 下限 (0) は、開始エンドポイントで選択したパスからウォークが離れることを防ぎます。 
6. 時間層全体を計算した後、(dp[i][0]) を答えに追加します。 (0) で終了することは、市民が開始位置に戻ったことを意味するため、そのような状態はすべて有効なクローズド ウォークとなります。 
7. 累積カウントに (2n) を掛けます。 サイクルには (n) 個の可能な開始位置と 2 つの方向があります。 カウントされたすべての 1 次元ウォークはこれらの選択肢の 1 つを正確に決定し、そのようなすべての選択肢は同じ数のウォークを持ちます。 

### なぜ効果があるのか

 開始位置と方向が固定されている場合、不変条件は、(dp[i][j]) が許可されたセグメント内に残り、座標 (j) で終了する長さ (i) の歩行を正確にカウントすることです。 再帰では、可能な 2 つの以前の座標が正確に考慮されますが、制限 (j\ge0) および (j\le k) により、選択したパスの外側にあるすべての移動が削除されます。 したがって、(dp[i][0]) は長さ (i) の有効な閉じた歩行を正確にカウントします。 

カウントされた歩行には最大座標 (d<k) が含まれる場合がありますが、それは正しいことです。 実際に選択されたパスは座標 (d) で終了しますが、それでも許容最大値 (k) の範囲内にあります。 選択したパスの終点を訪問する必要があるため、(d) は歩行によって到達した最大座標によって一意に決定されます。 したがって、DP は複数の経路長に対する同じ歩行をカウントしません。 最後に、各ウォークを (n) 個の開始位置のいずれかに配置し、いずれかの方向にたどることができ、係数 (2n) が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k, m = map(int, input().split())

    limit = min(k, m)

    prev = [0] * (limit + 2)
    prev[0] = 1

    ans = 0

    for i in range(1, m + 1):
        cur = [0] * (limit + 2)
        upper = min(i, k)

        for j in range(upper + 1):
            ways = 0

            if j > 0:
                ways += prev[j - 1]

            if j + 1 <= limit:
                ways += prev[j + 1]

            cur[j] = ways % MOD

        ans += cur[0]
        ans %= MOD
        prev = cur

    ans = ans * (2 * n) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```DP は、すべて (m) のレイヤーを保存するのではなく、2 つの配列を使用します。`prev[j]`は前の時間ステップを表し、`cur[j]`は現在のものを表します。 これにより、メモリが (O(m^2)) から (O(m)) に減少します。 

表現`upper = min(i, k)`重要な境界最適化です。 時間 (i) では、座標 (j>i) は到達不可能ですが、座標 (j>k) は選択されたパスによって禁止されています。 他の位置を計算する必要はありません。 

のために`j > 0`、前の位置は次の場合があります`j - 1`。 のために`j + 1 <= limit`、前の位置は次の場合があります`j + 1`。 いつ`j == 0`(0) から (-1) への移動は選択されたパスから離れるため、最初の遷移は意図的に省略されています。 

追加のアレイ スロットは、`limit + 1`は有効な状態として使用されません。 単に繰り返しを読み取らせるだけです`prev[j + 1]`いつでも安全に`j == limit`、その値はゼロのままです。 

Python の整数はオーバーフローしませんが、各状態のモジュロ (10^9+7) を小さくすると、中間値が小さく保たれ、必要な出力モジュラスに従います。 (2n) による最後の乗算も、(10^9+7) を法として実行されます。

 サンプル 1 の入力は次のとおりです。`4 3 3`。 最大歩行長は(3)なので、各時点での取り得る位置は以下のようになります。

サンプル 2 の入力は次のとおりです。`10 5 6`。 長さ (6) の閉じた歩行は最大でも距離 (3) に到達できるため、上限 (k=5) はこれら 6 つのステップ中の DP に影響しません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(m\min(m,k))) | 時間 (i) では、(0) から (\min(i,k)) までのみに到達できます。 |
 | スペース | (O(\min(m,k))) | 以前と現在の DP レイヤーのみが保存されます。 |

 (m\le2000) 以降、状態遷移の数は最大でも 400 万程度です。 このアルゴリズムは、すべての (n) 個の位置を個別に反復することはありません。そのため、(n) は、(2n) による最終的な乗算にのみ表示されます。 これは、(n) の (10^5) 境界と 256 MB のメモリ制限に快適に適合します。 

## テストケース```python
# helper: run the algorithm on an input string and return its output
import sys
import io

MOD = 10**9 + 7

def solve_data(inp: str) -> str:
    data = list(map(int, inp.split()))
    n, k, m = data

    limit = min(k, m)
    prev = [0] * (limit + 2)
    prev[0] = 1

    ans = 0

    for i in range(1, m + 1):
        cur = [0] * (limit + 2)
        upper = min(i, k)

        for j in range(upper + 1):
            if j > 0:
                cur[j] += prev[j - 1]
            if j + 1 <= limit:
                cur[j] += prev[j + 1]
            cur[j] %= MOD

        ans = (ans + cur[0]) % MOD
        prev = cur

    return str(ans * (2 * n) % MOD)

# Provided samples
assert solve_data("4 3 3") == "8", "sample 1"
assert solve_data("10 5 6") == "160", "sample 2"

# Minimum feasible n, and an odd maximum length.
assert solve_data("2 1 1") == "0", "no nonempty closed walk of odd length"

# Maximum n with the smallest useful k and m.
assert solve_data("100000 1 2") == "400000", "maximum n boundary"

# The path limit is irrelevant here because m=4 cannot reach beyond distance 2.
assert solve_data("5 4 4") == "30", "Catalan walks of lengths 2 and 4"

# k=2 removes walks that would need to reach distance 3.
assert solve_data("3 2 6") == "42", "upper-bound restriction"

print("all tests passed")

 ## 特殊なケース

 最大パス長が (k=1) の場合、ウォークは位置 (0) と (1) の間でのみ交互に実行できます。 入力用`2 1 2`、DPは`dp[2][0] = 1`、一方、位置 (0) の奇数長の状態はすべて 0 です。 累積カウントは (1) であり、(2n=4) を掛けると出力が得られます。`4`。 位置 (1) からの遷移は位置 (0) にのみ戻ることができるため、上限が尊重されます。 

歩行距離が奇数の場合、スタート地点に戻ることはできません。 のために`2 1 1`、最初の動きは (0) から (1) に移動する必要があるため、`dp[1][0] = 0`そして答えは`0`。 より一般的には、移動するたびに現在の座標のパリティが変更されるため、(0) から始まる歩行は偶数回移動した後でのみ (0) に戻ることができます。 

(k) がすべての到達可能な距離より大きい場合、上限は結果に影響を与えません。 のために`5 4 4`、クローズドウォークの長さは (2) と (4) のみです。 長さ (2) のウォークが 1 つと長さ (4) のウォークが 2 つあり、開始点と方向が固定されたウォーク (3) が得られます。 因数 (2n=10) は次のようになります。`30`。 これは、DP が最大距離が (k) より小さいウォークを受け入れなければならない理由も示しています。 

(k) が制限的である場合、DP はその境界を越える歩行を削除する必要があります。 のために`3 2 6`、長さ (2,4,6) の制限されていない非負の閉じたウォークは (1,2,5) になりますが、5 つの長さ (6) のウォークのうち、位置 (3) に到達するウォークは、(k=2) であるため禁止されます。 したがって、固定された開始点と方向に対して (1+2+4=7) 個の歩行だけが残ります。 そのような選択肢は (2n=6) あります。`42`。 

最後に、(k<n) という事実により、選択したパスは、誤ってサイクル全体を折り返すのではなく、通常の線分として扱われます。 DP は、明示的に選択された方向に沿った距離のみを追跡し、係数 (2n) は、その (n) 個の位置を列挙することなく、サイクルの回転および方向の対称性を復元します。
