 ## 問題の理解

 入力は、明示的なエッジなしでエンコードされた兵士のルート ツリーを記述します。 すべての兵士は整数の ID として表示され、その ID の直後に直接の部下に関する 0 個以上の括弧付きの説明が続きます。 一対の括弧には、完全なサブツリーが 1 つだけ含まれます。 例えば、`2(3(4))(1)`は、ルートがソルジャー 2 で、子 3 と 1 があり、3 には子 4 があるツリーを示しています。 

任務は、すべての兵士の親を回復することです。 1 から 1 までの各 ID について`n`、その直属の上司の ID を出力します。 ルートにあるユニークな兵士の親は 0 です。 

最初の制約では最大 140,000 人の兵士が指定されますが、エンコードされた文字列には最大 100 万文字を含めることができます。 これは、兵士またはキャラクターの数に比例するアルゴリズムが容易に適していることを意味しますが、各兵士の文字列の大部分を繰り返しスキャンするのはコストがかかりすぎます。 制限時間は 1 秒なので、直線的なタイム、または最悪の場合でもそれに近いタイムを目指す必要があります。 100 万文字の文字列に対する 2 次アルゴリズムには、約`10^12`限界をはるかに超えたキャラクター操作。 

最初のエッジケースは 1 人の兵士です。 入力```
1
1
```括弧がまったくなく、正しい出力は次のとおりです。```
0
```すべての兵士に少なくとも 1 人の子供がいると仮定するパーサーは、ここでは失敗します。 

もう 1 つのエッジ ケースは、すべての兵士に 1 人の子供がいる連鎖です。```
4
1(2(3(4)))
```正しい出力は次のとおりです```
0 1 2 3
```遭遇後に最後に解析された兵士を兄弟として扱う不用意な実装`)`先祖との関係が失われる可能性があります。 ソルジャー 4 が終了した後、パーサーはソルジャー 3 に戻り、次にソルジャー 2 に戻り、次にソルジャー 1 に戻る必要があります。 

3 番目のケースは複数の兄弟です。```
4
1(2)(3)(4)
```答えは```
0 1 1 1
```ソルジャー 2 の右括弧は、ソルジャー 3 が解析される前に、ソルジャー 1 を現在のスーパーバイザーとして復元する必要があります。 完成した兵士をアクティブ パスから削除するのを忘れた実装では、誤って 2 が 3 の親になる可能性があります。 

最後に、ID には複数の数字が含まれる場合があるため、一度に 1 文字ずつ個別の ID として解析するのは正しくありません。 例えば、```
3
10(2)(30)
```ID 10、2、および 30 が選択された ID によって許可されている場合は、ID 10、2、および 30 が記述されます。`n`; パーサーは兵士を処理する前に、完全な一連の数字を消費する必要があります。 ID が正確に 1 ～ であるという実際の制約の下では、`n`、いつでも同じ問題が発生します`n >= 10`。 

## アプローチ

 簡単なアプローチは、各兵士を個別に処理することです。 ID が発生する位置を見つけた後、文字列を逆方向にスキャンして、どの兵士の括弧にその位置が含まれているかを判断できます。 括弧は、それを囲んでいるサブツリーを復元するのに十分な情報を提供するため、このアプローチは正しいです。 

問題は、同じ文字が何度もスキャンされることです。 次のような深くネストされたツリーを考えてみましょう。`1(2(3(4(...)))`。 最下位近くの兵士の場合、後方検索は文字列の接頭辞のほぼ全体を横断することができます。 あれば`n`兵士と紐には長さがある`L`、最悪の仕事は`O(nL)`。 と`n = 140000`そして`L`に近い`10^6`、これはおおよそ到達できます`1.4 × 10^11`性格検査。 両方の量の正確な最大値がすべての形状で独立して発生することはできませんが、この限界はすでに大きすぎます。 

エンコーディングの構造を見ると、さらによく観察できるようになります。 文字列を左から右に読んでいるどの時点でも、ルートから現在記述されているソルジャーまでの一意のパスが存在します。 その道はまさに兵士たちで構成されており、その開口部は`(`に遭遇しましたが、それに対応するものは`)`まだ遭遇していません。 

このアクティブ パスはスタックで維持できます。 新しい兵士 ID が読み取られると、スタックの最上位がそのスーパーバイザーになります。 次に、その子があればすべてその下に属するため、新しい兵士をプッシュします。 いつ`)`に遭遇すると、現在の兵士の説明全体が終了したため、それをポップします。 すべてのキャラクターは 1 回処理され、すべての兵士は 1 回プッシュおよびポップされます。 

この強引な方法が機能するのは、括弧によってどの兵士に別の兵士が含まれているかが暗黙的に示されるためですが、その関係が繰り返しゼロから​​再構築されます。 アクティブな祖先がまさにスタックであるという観察により、問題は単一の線形スキャンに縮小されます。

 | スタック解析 |`O(L)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そしてエンコードされた文字列。 長さの応答配列を割り当てます`n + 1`、 どこ`parent[x]`最終的には兵士の監督者が含まれることになる`x`。 
2. 空のスタックを初期化します。 スタックは、ルートから記述が処理されているソルジャーまでの現在のパスを表します。 そのトップは常に現役の兵士です。 
3. 文字列を左から右にスキャンします。 数字が見つかったら、完全な整数 ID が読み取られるまで数字の消費を続けます。 これは、次のような ID があるため必要です。`123`3人の別々の兵士ではなく、1人の兵士です。 
4.完全なIDが完成したら`x`解析されている場合は、スタックを調べてください。 空でない場合、その最上位はその直属のスーパーバイザーになります。`x`ので、設定します`parent[x]`その値に。 スタックが空の場合、`x`はルートであり、その親は 0 のままです。 
5.プッシュ`x`スタックに。 この時点から、対応する閉じ括弧まで、`x`は、そのサブツリー内で検出されるすべての直接の子に対するアクティブなスーパーバイザです。 
6. スキャンが発生した場合`(`、それを通り過ぎて進むだけです。 左括弧は新しい兵士を導入しないため、実行するスタック操作はありません。 
7. スキャンが発生したとき`)`、トップの兵士をポップします。 その完全なサブツリーが終了したばかりなので、アクティブなスーパーバイザになることはできません。 新しいスタックトップがその親です。 
8. 完全な文字列がスキャンされたら、出力します。`parent[1]`を通して`parent[n]`。 すべての兵士は一度だけ遭遇しているため、すべての親子関係がすでに決定されています。 

### なぜ効果があるのか

 重要な不変条件は、兵士 ID を読み取る直前に、スタックにはその兵士の先祖がルートから親の順序で正確に含まれていることです。 兵士の説明を開くとその兵士がプッシュされるため、その子にはその兵士がスタックの一番上に表示されます。 右括弧に到達すると、サブツリー全体が終了し、ポップすると、それ自体の親が最上位要素として復元されます。 したがって、ID が解析されるたびに、スタックトップはまさにその直接のスーパーバイザーになります。 ルートは空のスタックで解析される唯一の ID であるため、親 0 を正しく受け取ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(data):
    lines = data.splitlines()
    n = int(lines[0])
    s = lines[1].strip()

    parent = [0] * (n + 1)
    stack = []

    i = 0
    length = len(s)

    while i < length:
        c = s[i]

        if '0' <= c <= '9':
            x = 0

            while i < length:
                c = s[i]
                if c < '0' or c > '9':
                    break
                x = x * 10 + (ord(c) - 48)
                i += 1

            if stack:
                parent[x] = stack[-1]

            stack.append(x)
        elif c == ')':
            stack.pop()
            i += 1
        else:
            # '('
            i += 1

    return ' '.join(map(str, parent[1:]))

def main():
    data = sys.stdin.read()
    sys.stdout.write(solve(data))

if __name__ == "__main__":
    main()
```パーサーはインデックスを使用します`i`文字列を分割する代わりに。 これにより、一時的な部分文字列の大規模なコレクションの作成が回避され、入力を直接処理できるようになります。 

いつ`s[i]`が数字の場合、内側のループは完全な ID を数値的に構築します。 それが終わった後、`i`はすでに最初の非数字文字を指しているため、数字分岐の最後に追加の増分はありません。 この詳細により、後続の括弧をスキップすることがなくなります。 

スタックには、文字列の位置ではなく整数 ID が格納されます。 これにより、親の検索が即座に行われるようになります。`stack[-1]`まさに私たちが必要とするスーパーバイザーです。 

スタックが空のときに読み取られた ID の場合、応答配列はゼロで初期化されているため、割り当ては必要ありません。 入力は 1 つの根のあるツリーを表すため、そのような兵士は 1 つだけ存在します。 

いつ`)`が処理される場合、有効な入力に対してスタックを空にすることはできません。 ポップ操作により、説明が終了したばかりの兵士が削除されます。 開口部`(`開かれているソルジャーは ID が読み取られるときにプッシュされるため、スタック操作は必要ありません。 

ここでは、Python の整数にはオーバーフローの問題がありません。 最大の ID はわずか 140,000 で、文字列自体に含まれる文字数は最大でも 100 万文字です。 

実装では使用します`sys.stdin.read()`内部`solve`繰り返し電話するのではなく`input()`。 これは、100 万文字の入力に便利であり、ソルバーのテストも簡単になります。 必要な`input = sys.stdin.readline`メイン ソルバーは入力全体を一度に読み取りますが、標準の競合プログラミングの高速 I/O として定義されます。
