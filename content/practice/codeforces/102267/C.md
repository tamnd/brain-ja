 ## 解決策
 ## 問題の理解

 整数サイズの最大のマトリョーシカ人形があります`S`。 1 つの人形が別の人形の中に置かれている場合、内側の人形は最大でも`1/X`外側の人形のサイズ。 可能な限り長いネストチェーンが必要なので、問題は元のサイズからどれだけの人形を表示できるかです。`S`最小の正の整数サイズまで。 

現在の人形のサイズがあるとします。`A`。 次の人形の最大のサイズは次のとおりです。`floor(A / X)`。 次の人形を大きくすると、後のすべての人形のために少なくとも同じくらいのスペースが残るため、小さいものを選択することは決して役に立ちません。 この選択を繰り返すと、可能な限り長いチェーンが得られます。 

制約は、対数演算が自然なターゲットとなるのに十分小さいものです。 以来`X >= 2`、ネストの各ステップでサイズが少なくとも 2 分の 1 に減少します。 最大でも`10^9`、サイズがゼロになるまでに 31 回未満の削減が行われる可能性があります。 あらゆるサイズのリニアスキャン`10^9`1 秒の制限にはあまりにも高価すぎるでしょうが、`O(log S)`ソリューションは数十回の反復のみを実行します。 

実装でオフバイワンエラーが発生する可能性がある境界ケースがいくつかあります。 のために`S = 1, X = 2`、答えは`1`、元の人形自体はカウントされますが、その中に正の整数のサイズが収まらないためです。 成功した除算のみをカウントする不注意なループにより、次のような出力が出力される可能性があります。`0`。 

のために`S = 10, X = 2`、最適なチェーンは`10 -> 5 -> 2 -> 1`、与える`4`。 Python では、明示的にフロアを取得せずに通常の除算を使用する実装は、整数の除算がすでにフロアになっているため安全ですが、浮動小数点の除算を使用して後で変換すると、不必要な精度のリスクが生じる可能性があります。 

のために`S = 9, X = 2`、チェーンは`9 -> 4 -> 2 -> 1`、再び与えます`4`。 2つ目のサイズは、`4`、 ない`4.5`、人形のサイズは整数でなければならないためです。 サイズを実数として扱うアプローチでは、不正確なチェーン長が生成される可能性があります。 

いつ`S = X = 10^9`、チェーンは`10^9 -> 1`、したがって、答えは次のとおりです`2`。 よくある間違いは、次の人形のサイズが厳密に小さいことを要求することです。`S / X`、ただし、条件では等しいことが認められるため、サイズ`1`有効です。 

## アプローチ

 直接的な総当りの方法では、次の人形をあらゆる可能な整数サイズで検索できます。 現在のサイズの場合`A`、すべての候補者を検査できます`1`を通して`floor(A / X)`そしてどれが最大で有効であるかを判断します。 これは正しいです。次の人形について考えられるすべての選択肢が検討され、最大の有効な選択肢を選択することで最良の継続が得られるからです。 

問題は無駄な作業が多いことだ。 と`S = 10^9`そして`X = 2`、このような検索は大まかに調べます`floor(10^9 / 2) + floor(10^9 / 4) + floor(10^9 / 8) + ...`チェーン全体の候補者。 この合計は`10^9 - popcount(10^9) = 999,999,987`したがって、最悪の場合は実質的に 10 億回の反復になります。 これでは 1 秒の制限内に収まりません。 

すべての候補を検討した後で最適な次のサイズが明らかな空間を検索するため、総当り方式が機能します。 重要な観察は、実際にはその空間を検索する必要がないということです。 現在のサイズの場合`A`、次の有効なサイズは最大でも`floor(A / X)`、そしてその最大値を正確に選択すると、残りの人形の可能な最大の開始点が得られます。 したがって、問題は整数除算を繰り返し適用することになります。`X`。 

から始まる`S`、現在の人形を数え、そのサイズを次のように置き換えます。`S // X`、新しいサイズが正である間続行します。 以来`X`少なくとも`2`、反復数は対数です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(S)`最悪の場合 |`O(1)`| 遅すぎる |
 | 最適 |`O(log_X S)`|`O(1)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`S`そして`X`。 現在の人形のサイズは初期値です。`S`、答えは次から始まります`1`なぜなら、最大の人形自体がすでに入れ子チェーンの一部だからです。 
2. 現在のサイズが少なくとも`X`に置き換えてください`current // X`そして答えを増やします。 

その間のみ分割`current >= X`これは、別の正の整数の人形が内部に収まるかどうかを確認することと同じです。 もし`current < X`、 それから`floor(current / X) = 0`、サイズ`0`は人形ではないので、チェーンは停止する必要があります。 
3. 蓄積された回答を印刷します。 

正確さは、各反復の前に次の不変条件から導かれます。`current`は、すべての最適なチェーンの中で、その深さでの人形の可能な最大のサイズです。 サイズの人形から`current`、有効な内部人形はこれを超えることはできません`floor(current / X)`であり、その正確なサイズが正の場合は常に有効です。 可能な最大の次のサイズを選択しても、後の人形の最大達成可能数を減​​らすことはできません。これは、後のすべての制約が現在のサイズに関して単調であるためです。 したがって、すべての除算が可能な限り最良の次の人形を生成し、正の内部人形が存在しないときにループが正確に停止します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    S, X = map(int, input().split())

    ans = 1
    while S >= X:
        S //= X
        ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```変数`ans`から始まります`1`小さな人形を中に入れることができない場合でも、元の人形はカウントされるためです。 このハンドルは`S = 1`正しく。 

条件`S >= X`クリーンな境界チェックです。 それが成立すれば、`S // X`少なくとも`1`、つまり、別の正のサイズの人形が存在します。 それが成立しない場合、商はゼロとなり、ネストは停止する必要があります。 

更新では整数の除算が直接使用されます。 サイズは整数なので、`S // X`は、次の人形の有効な最大の整数サイズです。 浮動小数点演算は必要ありません。 

Python の整数では、オーバーフローの懸念も解消されますが、入力値はすでに十分小さいため、格納される値には 32 ビットの符号付き整数で十分です。 

入力にはテスト ケースが 1 つだけ含まれているため、外部のテスト ケース ループはありません。 必要な`sys.stdin.readline`setup は、高速で従来の競技プログラミングの入力に引き続き使用されます。 

## 実用的な例

 ### サンプル 1:`S = 10, X = 2`現在の人形は、その中に収まる最大の整数サイズに繰り返し置き換えることができます。 

| ステップ | 現在のサイズ | 新しいサイズ | 答え |
 | --- | --- | --- | --- |
 | 開始 | 10 | 5 | 2 |
 | 2 | 5 | 2 | 3 |
 | 3 | 2 | 1 | 4 |
 | 停止 | 1 | 不可能 | 4 |

 結果として得られる連鎖は、`10 -> 5 -> 2 -> 1`。 現在のサイズに達すると`1`、より小さいです`X = 2`、したがって、別の正の整数の人形は適合しません。 答えは`4`。 

### カスタム例:`S = 9, X = 2`| ステップ | 現在のサイズ | 新しいサイズ | 答え |
 | --- | --- | --- | --- |
 | 開始 | 9 | 4 | 2 |
 | 2 | 4 | 2 | 3 |
 | 3 | 2 | 1 | 4 |
 | 停止 | 1 | 不可能 | 4 |

 この例では、整数境界を実行します。 最初の内側の人形のサイズは`9 // 2 = 4`、 ない`5`、要件は次のとおりです。`2 * inner <= outer`。 チェーンは`9 -> 4 -> 2 -> 1`、与える`4`。

 ## 特殊なケース

 のために`S = 1, X = 2`、アルゴリズムは次から始まります`ans = 1`そして`S = 1`。 条件`1 >= 2`false であるため、ループは実行されず、出力は次のようになります。`1`。 これにより、元の最大の人形を数えるのではなく、内側の人形だけを数えるというよくある間違いを防ぐことができます。 

のために`S = 9, X = 2`、最初の更新は`9 // 2 = 4`。 以下のアップデートは、`4 // 2 = 2`そして`2 // 2 = 1`。 アルゴリズムは次で停止します`1`そして戻ってきます`4`。 これは、仮想の実数値チェーンには以下が含まれるため、商を整数としてとる必要がある理由を示しています`4.5`は許可されていません。 

のために`S = X = 10^9`、初期状態`10^9 >= 10^9`true であるため、アルゴリズムは次のサイズの内部人形を受け入れます。`10^9 // 10^9 = 1`そして答えをインクリメントします`2`。 次の条件は失敗します。`1 < 10^9`。 したがって、出力は次のようになります`2`、境界条件により、以下と正確に等しい内部人形が許可されることが確認されます。`S / X`。 

のために`S = 5, X = 10`、初期状態`5 >= 10`は誤りです。 アルゴリズムはすぐに戻ります`1`これは正しいです。なぜなら、正の内部整数のサイズは最大でも次のとおりである必要があるからです。`floor(5 / 10) = 0`。 

可能な限り最大のチェーンの場合、`S = 10^9, X = 2`に達するまでに、アルゴリズムは 29 回の除算を成功させます。`1`、つまり、元の人形とそれらの 29 個の内部人形を合わせると、`30`。 この極端なケースでも、対数的に多くの操作しか必要としません。これが、ソリューションが制約を快適に満たす主な理由です。
