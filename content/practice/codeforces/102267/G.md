 ## 問題の理解

 整然としたお部屋をご用意しております。 Each occupied room`i`～によって説明された患者が含まれています`a[i]`そして`b[i]`。 ロボットの始まりは、`x`食料の単位を受け取り、患者がすでに死亡した部屋をスキップしながら、左から右に部屋を訪問します。 生きている患者に対してロボットが提供できるのは、`a[i]`少なくとも食べ物だけ`a[i]`食べ物が残っている。 食物を受け取った後、ロボットにまだ食物が残っていると患者は死亡します。`b[i]`食べ物。 

タイプ 1 のクエリでは、2 つの数値が求められます。その移動中に死亡した現在生存中の患者の数と、ロボットの食料がなくなったため連絡が取れなかった生存中の患者の数です。 死亡した患者はプロセスから永久に除外されます。 タイプ 2 クエリは、患者が死亡したためにその部屋が以前に空になっていた場合でも、ある部屋の患者を新しい患者に置き換えます。 

重要な詳細は、タイプ 1 クエリがデータ構造を変更するということです。 死亡した患者は、タイプ 2 のクエリによって新しい患者がその部屋に入れられるまで、その後の診察には参加しません。 これにより、すべてのクエリを独立したシミュレーションとして扱うことができなくなります。 

まで`10^5`部屋と`10^5`クエリ、`O(n)`タイプ 1 クエリごとに実行できるシミュレーションは約`10^10`最悪の場合は患者の手術が必要になる場合もあります。 これは 2 秒という制限をはるかに超えています。 の値`a`、`b`、 そして`x`にも達する`10^18`したがって、すべての合計には 64 ビット整数を使用する必要があります。 Python の整数にはすでに任意の精度があるため、実装ではオーバーフローの問題は発生しません。 

誤って処理されやすい境界ケースがいくつかあります。 まず、死は厳密な不等号を使用します。 例えば、```
15 511 10
```患者が受け取るのは、`5`、出発`5`、これはまさに安全限界です。 出力は```
0 0
```を使用した不注意な実装`>= b[i]`の代わりに`> b[i]`誤って患者を殺すことになるだろう。 

第二に、食事を摂ることができない患者は死んでいません。 例えば、```
15 10011 4
```ロボットは必要なものを与えることができない`5`、そのため、患者は生き残り、単に食べ物を受け取らないだけです。 出力は```
0 1
```第三に、デッドルームは今後の旅行ではスキップされます。 例えば、```
15 021 61 1
```最初のクエリでは、ユニットが 1 つ残っているため、患者が死亡します。`1 > 0`。 すると部屋は空になります。 2 番目のクエリでは誰も殺すことができず、食事を与える患者もいないため、出力は次のようになります。```
1 00 0
```最後に、アップデートにより、死んだ部屋に再び人が住み着く可能性があります。 例えば、```
15 021 62 2 10 1
```最初のクエリは元の患者を殺します。 2 番目のクエリは、同じ部屋に新しい患者を挿入します。 死んだ部屋を永久に使用できないものとして扱うと、誤って新しい患者を失うことになります。 

## アプローチ

 直接的なアプローチは、現在の患者を各部屋に常駐させ、部屋からロボットをシミュレートすることです。`1`部屋を通して`n`タイプ 1 クエリごとに。 訪問した各部屋で減算します`a[i]`、患者が死亡したかどうかを確認し、死亡した患者を不在としてマークします。 これは、死亡した患者が今後の旅行から消えるという事実を含め、プロセスを正確に追跡しているため、正しいです。 

問題は最悪のケースだ。 あると仮定します`10^5`部屋とほぼすべてのクエリは、十分な量の食料に対するタイプ 1 のクエリです。 次に、1 つのクエリが調べます`10^5`部屋、そして`10^5`クエリには大まかに必要なものがあります`10^10`操作。 一つ一つのシミュレーションはシンプルでも、トータルすると膨大すぎます。 

重要な観察は、一度に 1 人の患者について考えるのをやめ、代わりに残りのシーケンス全体を 3 つの値で説明することです。 

生存している患者の連続するグループについて、次のようにします。`sum`それらの患者が要求する総食事量になります。 させて`cnt`彼らの番号になります。 最も重要なことは、`mn`の最小値になる`food already consumed before this patient + a[i] + b[i]`。 

ロボットが追加金額でグループを開始する場合`s`すでに消費された食物の量であり、この値が よりも小さいときに患者は死亡します。`x`。 したがって、このグループには、まさに次の時点で死亡する患者が含まれています。`mn + s < x`。 

この特性は、2 つの連続するセグメントが結合されると自然に組み合わされます。 左側のセグメントは、それ自体の最小値に寄与します。 右側のセグメントの場合、左側のセグメントで要求されたすべての食べ物が消費された後にすべての接頭辞が開始されるため、右側のすべての候補は次のようにシフトされます。`left.sum`。 

これにより、ノードに格納されるセグメント ツリーが得られます。`cnt`、`sum`、 そして`mn`。 

タイプ 2 の更新では 1 つのリーフのみが変更されるため、セグメント ツリーの再構築には時間がかかります。`O(log n)`時間。 

タイプ 1 クエリの方が興味深いです。 死亡条件を満たすすべての患者を再帰的に検索し、それらの葉を削除します。 セグメント全体が完了すると、`mn + consumed >= x`、その中のどこにも死が存在することはできないため、セグメント全体をスキップできます。 この方法で削除されたすべてのリーフは、アップデートによってそこに患者が再作成されるまで、永久に死んでいくことになります。 その結果、入力全体にわたって、すべてのタイプ 1 クエリの高価な部分が各患者をデッド リーフとして訪問できるのは、挿入の間に 1 回だけです。 

死亡した患者を排除した後、食事が提供されなかった患者の数が必要になります。 以来、`a[i]`がプラスである場合、生存患者が消費する累積食物は厳密に増加しています。 同じセグメント ツリーを下降して、累積需要が最大で何人の生存患者があるかを確認できます。`x`。 残りの生存患者には食事は与えられなかった。 

これは、公式コンテスト ソリューションで使用されているものと同じセグメント ツリー構造です。

 ## アルゴリズムのチュートリアル

 1. 部屋の上にセグメント ツリーを構築します。 生きている患者さんのために`(a, b)`、 店`cnt = 1`、`sum = a`、 そして`mn = a + b`。 空き部屋の店舗`cnt = 0`、`sum = 0`、 そして`mn = infinity`。 

連続する 2 つのノードの場合`L`そして`R`、それらを組み合わせた値は次のとおりです。`cnt = L.cnt + R.cnt`

`sum = L.sum + R.sum`

`mn = min(L.mn, L.sum + R.mn)`。 

2番目の候補者は、`L.sum`これは、右の子のすべての患者が、左の子の生きているすべての患者が食事を受け取った後にのみ到達できるためです。 
2. タイプ 2 クエリの場合`(a, b, c)`、部屋を交換します`c`葉が入ったもの`cnt = 1`、`sum = a`、 そして`mn = a + b`。 

これは両方のケースを均一に処理します。 古い患者が生存していれば、彼らは置き換えられます。 古い患者が死亡した場合、以前は空だったリーフが再び占有されます。 
3. 食品量に関するタイプ 1 クエリの場合`x`、ルートに保存されている生存患者の数を覚えておいてください。 

次に、死亡条件が満たされたすべての生きている患者を再帰的に削除します。 以降で始まるセグメントの場合`used`食物はすでに消費されており、その最小の死亡候補は`mn + used`。 これが少なくとも`x`、そのセグメント全体で死亡した患者はいないため、すぐに停止します。 
4. 再帰が候補が以下のリーフに到達したとき`x`、その患者の数と要求された食事の数をゼロに設定し、その最小値を無限大に設定して、その患者を削除します。 

厳密な比較が不可欠です。 患者が死亡するのは、残りの食物が次の量を超えた場合のみです。`b`、したがって、平等は生存を意味します。 
5. 削除パスの後、古いルート数から新しいルート数を減算します。 この差は、まさにこのクエリ中に死亡した患者の数です。 
6. 実際に食料を受け取ることができる生きている患者の数を数えます。 ルートから始める`used = 0`、左の子を検査します。 もし`used + left.sum <= x`、その子の生存しているすべての患者にサービスを提供できるため、次を追加します`left.cnt`答えに進み、次の子に移動します`used`増加しました`left.sum`。 それ以外の場合は、左側の子に進みます。 

ポジティブ`a[i]`値により累積需要が厳密に増加するため、ルートからリーフへのパスを 1 つだけ探索する必要があります。 
7. 食事を与えられなかった生存患者の数は、死亡後に残った数から提供できる数を引いた数です。 死亡数の後にこの未処理数を出力します。 

### なぜ効果があるのか

 不変条件は、すべてのセグメント ツリー ノードが、その区間内で現在生存している患者を元の部屋の順序で正確に記述することです。 その`sum`は彼らの食料需要の合計、`mn`の最小値です`consumed_before + a[i] + b[i]`あの患者たちを超えて。 

どんな患者さんにとっても、`a[i] + b[i]`患者が摂取した食物と比較されます。 したがって、患者はまさにそのときに死亡します。`consumed_before + a[i] + b[i] < x`、これはまさに次の条件です。`mn + used < x`セグメントの場合。 最小値がこの条件を満たさないセグメントには死亡した患者が含まれていないため、安全にスキップできます。 適格なリーフに向けて探索されるすべてのセグメントは、最終的に死亡条件を満たす患者を正確に削除します。 

そのような患者をすべて除去した後、残りの患者は`sum`値は生きている患者のみを表します。 すべての需要が正であるため、累積需要は単調であるため、2 回目のトラバースでは、食料を受け取ることができる生きている患者の数が正確にカウントされます。 残りの母集団からその数を引くと、まさに何も受けていない患者が得られます。

    def build(v, l, r):        if l == r:            cnt[v] = 1            sm[v] = a[l]            mn[v] = a[l] + b[l]            return

    def update(v, l, r, pos, na, nb):        if l == r:            cnt[v] = 1            sm[v] = na            mn[v] = na + nb            return
        m = (l + r) // 2        if pos <= m:            update(v * 2, l, m, pos, na, nb)        else:            update(v * 2 + 1, m + 1, r, pos, na, nb)
        pull(v)

        if l == r:            cnt[v] = 0            sm[v] = 0            mn[v] = INF            return

        if mn[lc] + used < x:            kill(lc, l, m, x, used)
        if mn[rc] + used + sm[lc] < x:            kill(rc, m + 1, r, x, used + sm[lc])
        pull(v)

        if used + sm[lc] <= x:            return cnt[lc] + served(                rc, m + 1, r, x, used + sm[lc]            )
        return served(lc, l, m, x, used)
    build(1, 0, n - 1)
    q = next(it)    out = []
    for _ in range(q):        typ = next(it)
        if typ == 1:            x = next(it)
            before = cnt[1]            kill(1, 0, n - 1, x, 0)            after = cnt[1]

## 複雑さの分析

        if l == r:            cnt[v] = 0            sm[v] = 0            mn[v] = INF            return

 ## 特殊なケース

 厳密な死の境界は条件によって直接処理されます。`mn + used < x`。 考慮する```
15 511 10
```リーフストア`mn = 5 + 5 = 10`。 以来`10 < 10`は誤りです、`kill`患者を生かしておく。 サービングトラバーサルでは次のようになります。`sum = 5 <= 10`、それで患者は栄養を与えられます。 出力は`0 0`。 厳密でない比較を行うと、患者が誤って削除される可能性があります。 

自分で食事をすることができない患者は、死とは別に扱われます。 のために```
15 10011 4
```葉にはある`mn = 105`、したがって死亡は起こりません。 サービングトラバーサルチェック`5 <= 4`、これは誤りで、治療を受けていない生存患者が 1 人いると報告しています。 出力は`0 1`。 

死亡した患者がセグメントツリーから消える`cnt`そして`sum`。 のために```
15 021 61 1
```最初のクエリは`mn = 5`、 そして`5 < 6`, そのため、葉は空になります。 ルートは次のようになります。`cnt = 0`そして`sum = 0`。 2 番目のクエリでは空のツリーが表示されるため、死亡数と未処理数は両方とも 0 になります。 

更新では、完全に新しいリーフを書き込むことで、死んだ部屋が復元されます。 のために```
15 031 62 2 10 11 2
```最初のクエリは元のクエリを削除します`(5, 0)`忍耐強い。 更新により、その空のリーフが次のように置き換えられます。`(2, 10)`、その死亡候補者は`12`。 と`x = 2`、候補者は以下ではありません`2`、そして患者は必要な費用を正確に支払うことができます`2`食べ物。 最終的な出力は次のとおりです`0 0`。 

すべて等しい場合は、再帰的削除が複数の連続するリーフを正しく処理するかどうかをテストします。 と```
42 12 12 12 111 8
```死亡候補者は`3, 5, 7, 9`。 最初の3つは以下にあります`8`したがって、正確に 3 人の患者が死亡し、4 人目が生き残ります。 セグメント ツリーは、最小値がすでに少なくとも以下であるサブツリーを枝刈りできます。`8`、対象となる葉を正確に削除します。 

最大サイズのケースは、`100000`部屋と全員を養うのに十分な食料を含む 1 つのクエリ。 毎`a`は`1`、したがって累積需要はちょうどに達します`100000`、その間、`b`は`10^18`。 死亡する患者はおらず、すべての患者が治療を受けます。 出力は`0 0`。 これにより、メモリ フットプリントと、死亡の可能性がない場合にはセグメント ツリーが患者ごとに不必要な作業を実行しないという事実の両方が検証されます。
