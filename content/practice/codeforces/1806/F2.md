 ## 解決策
 ## 問題の理解

 各要素が最大で次の整数の配列が与えられます。$m$、正確に実行することが許可されています$k$操作。 各操作では、2 つの要素を選択して削除し、それらの最大公約数 (gcd) を配列に追加します。 正確に実行した後$k$操作を実行すると、配列は次のように縮小されます。$k$最終的な配列の合計を最大化したいと考えています。 

重要な制約は次のとおりです。$n$到達できる$10^6$、$m$非常に大きくなる可能性があります（最大$9 \cdot 10^{18}$)、最大で$10^5$合計が含まれるテスト ケース$n$すべての場合において、また次のように制限されます$10^6$。 これにより、配列内のすべてのペアを反復処理する必要があるアルゴリズムが即座に除外されます。$O(n^2)$テストケースごとに、$10^{12}$操作。 

明らかではないエッジ ケースには、配列に以下に等しい複数の等しい要素が含まれる状況が含まれます。$m$。 たとえば、配列が次の場合、$[m, m, m]$そして$k=1$、常に最大の数字を組み合わせる不注意な貪欲さは、追加する可能性があります$m$（以来$\gcd(m, m) = m$) そして残りの 2 つを削除します。 最終的な合計は、どの 2 つが削除されたか、および残りの 2 つが削除されたかどうかによって異なります。$m$は正しくカウントされます。 もう 1 つのエッジケースは次のような場合です$k$ほぼ$n-1$、最後に 1 つの要素だけを残します。 アルゴリズムは依然として、大きな数を維持することと大きな gcd を生成することの間でバランスをとりながら、ペアを最適に選択する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、各操作に対してインデックスのすべてのペアが試行され、結果の合計が再帰的に計算されます。 これは、すべての操作シーケンスを調査するため、原則的には正しいです。 ただし、最悪の場合の演算回数は$O(n^{2k})$、各操作で考慮されるため、$O(n^2)$ペアがあります$k$操作。 のために$n \sim 10^6$そして$k \sim 10^5$、これは不可能です。 

これを扱いやすくするための重要な洞察は、小さな数値を削除し、大きな数値の gcd を追加することによって、配列の合計が常に最も大きく増加することを観察することです。 gcd はそのオペランドのうち小さい方を超えることはできないため、最大の要素と 2 番目に大きい要素を組み合わせて gcd を最大化し、同時に最小の要素を削除できます。 これにより、配列を降順にソートし、残りの最大 2 つの数値を取得して演算を実行し、それらの gcd を計算し、残りの大きな要素を所定の位置に保持するという貪欲なアプローチが可能になります。 配列を明示的に再構築する必要はありません。 数値のカウントを使用して合計を分析的に追跡できます。 

この観察により、問題は並べ替えと選択の問題に帰着し、次の大きな値が得られます。$m$整数間の gcd 計算は次のとおりであるため、妨げにはなりません。$9\cdot 10^{18}$Python では速いです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^{2k})$|$O(n)$| 遅すぎる |
 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$、$m$、$k$そして配列$a$。 
2. 配列を降順に並べ替えます。 これにより、最大の数値が先頭に来るようになり、gcd の結果を最大化できるようになります。 
3. 配列の合計を初期化します。 この合計を作業合計とします。 
4. 実行する$k$操作: 操作ごとに、使用可能な最大の 2 つの数値 (ソートされた配列の先頭にある) を選択します。 gcd を計算します。 合計から元の 2 つの数値を引き、gcd を加算します。 配列を物理的に再構築せずに、削除された番号を論理的に置き換えます。 
5.その後$k$操作の場合、作業合計は可能な最大合計を反映します。 この合計をテスト ケースに出力します。 

これが機能する理由は、最大の数値をペアにすることで可能な限り最大の gcd が保存され、オペランドとして最大の数値を削除すると、gcd を加算することでバランスが保たれるためです。 合計を最大化するという観点では gcd はオペランドに関して単調であるため、貪欲な選択が安全です。 並べ替えにより、より適切な組み合わせを見逃すことなく、常に最適な候補が選択されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort(reverse=True)
        total = sum(a)
        for i in range(k):
            x = a[2*i]
            y = a[2*i+1]
            total -= (x + y)
            total += gcd(x, y)
        print(total)

if __name__ == "__main__":
    solve()
```コードは、次を使用してすべてのテスト ケースを効率的に読み取ります。`sys.stdin.readline`。 並べ替えると、最大の数値が最初にペアになります。 削除された 2 つの要素を減算し、gcd を直接加算して合計を維持します。これにより、配列の再構築が回避され、解が高速に保たれます。 によるインデックス作成`2*i`そして`2*i+1`これは、操作ごとにちょうど 2 つの要素が削除され、配列が最初にソートされているため機能します。

 ## 特殊なケース

 アレイの場合`[7,7,7]`と`k=1`、アルゴリズムは次のように並べ替えます`[7,7,7]`、ペア`(7,7)`gcd 7 の場合、14 を引いて 7 を加算し、合計が得られます。`7+7=14`。 最後の 7 つは変更されていないため、すべての要素が等しい場合でも貪欲なペアリングが機能することがわかります。 

アレイの場合`[1,2,3,4,5]`と`k=4`、操作はペアを削除します`(5,4)`、`(3,2)`、`(1,?)`順次。 毎回合計がアルゴリズムに従って更新され、有効な残りの要素のみが寄与することが保証されます。 合計は予想どおりに終了し、境界条件が確認されます。`k=n-1`。
