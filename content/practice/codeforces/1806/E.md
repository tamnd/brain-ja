 ## 解決策
 ## 問題の理解

 ツリーのルートは頂点 1 です。すべての頂点には値があります。`a[v]`、ルートを除くすべての頂点には親があります。 

お問い合わせの場合`(x, y)`、両方の頂点が同じ深さにあることが保証されます。 これら 2 つの頂点から開始して、両方の頂点を一度に 1 つのエッジずつ繰り返し上に移動します。 すべてのステップで、現在の頂点ペアの値を乗算し、その積を答えに加算します。 

祖先チェーンを次のように書くと、`x = x0, x1 = parent(x0), x2 = parent(x1), ...`そして`y = y0, y1 = parent(y0), y2 = parent(y1), ...`答えは`a[x0]a[y0] + a[x1]a[y1] + a[x2]a[y2] + ...`両方のチェーンが根元に到達するまで。 

定義の中に隠された反復は次のとおりです。$$f(x,y)=a_xa_y+f(p_x,p_y)$$と$$f(0,0)=0.$$制約こそが本当の課題なのです。 両方`n`そして`q`到達できる`10^5`。 1 つのクエリに長さのパスが含まれる場合があります`10^5`したがって、すべてのクエリに対してルートに直接アクセスするには、次のような処理が必要になる可能性があります。`10^10`最悪の場合の運用。 クエリごとに祖先チェーン全体を処理するソリューションは直ちに除外されます。 

メモリ制限は 1024 MB と非常に寛大です。 これは、大量の情報をキャッシュできるが、すべてをキャッシュできるわけではないことを示す強力なヒントです。`n²`可能な頂点ペア。 

クエリされた両方の頂点が同じである場合、微妙なエッジケースが発生します。 

例：```
3 1
2 3 5
1 2
3 3
```正しい答えは、$$5^2+3^2+2^2=38.$$同一の頂点を正しく処理せずに対称性を利用しようとする不注意な実装では、誤って項を二重にカウントしたりスキップしたりする可能性があります。 

もう 1 つの簡単な間違いは、すべてのペアのメモ化が実現可能であると想定していることです。 

星を考えてみましょう。```
1
├── 2
├── 3
├── ...
└── 100000
```すべての葉の深さは同じです。 ほとんどあります`10^10`考えられる葉のペア。 すべてのペアの値を保存することは不可能です。 

3 番目の落とし穴は再帰の深さにあります。 繰り返しは当然再帰的な実装を示唆しますが、チェーンの長さは`10^5`Python の再帰制限を超えています。 承認された Python ソリューションでは、制限を慎重に増やすか、反復公式を使用する必要があります。 

## アプローチ

 ブルート フォース ソリューションは、定義に直接準拠します。 クエリごとに、繰り返し追加します`a[x] * a[y]`、次に両方の頂点をその親に置き換えます。 

再発$$f(x,y)=a_xa_y+f(p_x,p_y)$$これが正しいことを示しています。 残念ながら、ツリーが長いチェーンの場合、1 つのクエリにコストがかかります`O(n)`、 そして`10^5`クエリは次のようになります`O(nq)=10^{10}`操作。 

再発により、役立つことがわかります。 多くのクエリは最終的に同じペアに到達します`(u,v)`。 わかったら`f(u,v)`、その状態に到達した今後のすべての計算は直ちに停止する可能性があります。 

問題は、考えられるペアが多すぎることです。 それらすべてをメモすることはできません。 

重要な観察は深さに関するものです。 

させて`cnt[d]`深さの頂点の数になります`d`。 

しきい値を選択してください$$B \approx \sqrt n.$$最大で深さ`B`頂点は小さな深さと呼ばれます。 

小さな深さごとに、最大でも`B`その深さで可能な頂点。 これらの頂点を含む答えを保存することが手頃になります。 

各頂点にその深さレベル内の位置を割り当てるとします。 頂点の場合`y`奥行きが浅いので保管できる`f(x,y)`頂点ごとに`x`。 

保存される状態の数は、$$\sum_{\text{small depths}} n \cdot cnt[d].$$小さな深さには最大でも次のものが含まれるため、`B`頂点の合計は最大で`nB`。 

次にクエリを考えてみましょう。 上に登っているときに、現在の深さが大きい場合、その深さには以上のものが含まれています。`B`頂点。 頂点の総数は`n`、最大でもありえます`n/B`どのルートパスでもそのような深い深さがあります。 

せいぜい後`n/B`上に移動すると、小さな深さに到達します。 その時点で、事前計算された値をすぐに取得できます。 

これにより、$$O\!\left(\frac{n}{B}\right)$$クエリごとに作業し、$$O(nB)$$保存された状態の合計。 

選択する$$B \approx \sqrt n$$期間と利回りのバランスをとる$$O(n\sqrt n)$$全体的な複雑さ。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | 最適 | O(n√n + q√n) | O(n√n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ルート付きツリーを構築し、すべての頂点の深さを計算します。 
2. あらゆる深さに対して`d`、その深さに属する頂点の数を数えます。 
3. 各深さの内部で、ローカル インデックスを割り当てます。`h[v]`あらゆる頂点に。 このインデックスは、メモ化された状態をアドレス指定するために使用されます。 
4. しましょう`B = 320`（約`√100000`）。 
5. メモ化された関数を定義します。$$f(x,y)=a_xa_y+f(p_x,p_y).$$基本的なケースは`f(0,0)=0`。 

1. 現在の深度が`y`小さい、という意味`cnt[depth[y]] <= B`、答えをテーブルに保存します`dp[x][h[y]]`。 

同じ深度にあるすべての頂点は異なる位置を持っているため、ローカル インデックスで十分です。 

1. 質問に答えるため`(x,y)`、再発を評価します。 メモ化された値がすでに存在する場合は、すぐにそれを返します。 
2. それ以外の場合は計算します$$f(x,y)=a_xa_y+f(p_x,p_y),$$奥行きが浅い場合は保管し、返却してください。 

### なぜ効果があるのか

 繰り返しはクエリの定義と正確に一致します。 各再帰ステップでは、合計から頂点の 1 ペアが削除され、残りのサフィックスが親ペアに委任されます。 

メモ化によって返される値が変更されることはありません。 これは、以前にすでに解決された状態の再計算を回避するだけです。 

最大で以下を含む深さの場合`B`頂点、すべての状態`(x,y)`最初の計算後に保存されます。 より深い深さの場合`B`、各大きなレベルには次のものが含まれるため、どのルート パスにもそのようなレベルはほとんどありません。`B`頂点があり、ツリーには次の頂点しかありません。`n`頂点の合計。 

したがって、すべてのクエリは、キャッシュされた状態に到達する前に、制限された数のキャッシュされていない遷移のみを実行し、すべての返される値は、問題によって定義された反復値とまったく同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    parent = [0] * (n + 1)
    children = [[] for _ in range(n + 1)

]
    p = list(map(int, input().split()))

    for i in range(2, n + 1):
        parent[i] = p[i - 2]
        children[parent[i]].append(i)

    depth = [0] * (n + 1)

    cnt = [0] * (n + 1)
    pos = [0] * (n + 1)

    stack = [(1, 0)]
    while stack:
        v, d = stack.pop()
        depth[v] = d
        cnt[d] += 1
        pos[v] = cnt[d]

        for to in children[v]:
            stack.append((to, d + 1))

    B = 320

    dp = [[0] * (B + 2) for _ in range(n + 1)]

    sys.setrecursionlimit(300000)

    def ask(x, y):
        if x == 0:
            return 0

        if cnt[depth[y]] <= B:
            cached = dp[x][pos[y]]
            if cached:
                return cached

        ans = ask(parent[x], parent[y]) + a[x] * a[y]

        if cnt[depth[y]] <= B:
            dp[x][pos[y]] = ans

        return ans

    out = []
    for _ in range(q):
        x, y = map(int, input().split())
        out.append(str(ask(x, y)))

    sys.stdout.write("\n".join(out))

solve()
```最初の部分では、ルート付きツリーを構築し、深さを計算します。 ツリーをトラバースしている間、すべての頂点は独自の深さレベル内の位置を受け取ります。 深さに頂点が含まれる場合`{v1, v2, ..., vk}`、彼らの立場は`1..k`。 

テーブル`dp[x][pos[y]]`の深さの場合にのみ使用されます。`y`小さいです。 小さな深さにはせいぜい`B`頂点、`pos[y]`テーブルの幅を超えることはありません。 

再発`ask(parent[x], parent[y]) + a[x] * a[y]`答えの数学的定義を直接反映しています。 

キャッシュ ルックアップは再帰呼び出しの前に行われます。 浅い深さの状態が計算されると、その状態に到達する今後のクエリはすべて即座に停止します。 

実装の詳細が 1 つ重要です。 キャッシュが使用するのは、`0`「計算されていない」マーカーとして。 すべての頂点値が正であるため、これは安全であり、すべての有効な答えは厳密に正です。 

もう 1 つの詳細は再帰制限です。 チェーン状のツリーは奥行きを持たせることができます`100000`したがって、デフォルトの Python 再帰制限では不十分です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n√n + q√n) | 各クエリは最大で O(√n) 個のキャッシュされていないレベルを通過します。 
| スペース | O(n√n) | すべての小さな深さのメモ化された状態 |

    parent = [0] * (n + 1)
    children = [[] for _ in range(n + 1)]

    p = list(map(int, input_data.readline().split()))
    for i in range(2, n + 1):
        parent[i] = p[i - 2]
        children[parent[i]].append(i)

    depth = [0] * (n + 1)
    cnt = [0] * (n + 1)
    pos = [0] * (n + 1)

    stack = [(1, 0)]
    while stack:
        v, d = stack.pop()
        depth[v] = d
        cnt[d] += 1
        pos[v] = cnt[d]
        for to in children[v]:
            stack.append((to, d + 1))

    B = 320
    dp = [[0] * (B + 2) for _ in range(n + 1)]

    sys.setrecursionlimit(300000)

    def ask(x, y):

            return 0

        return ans

    out = []
    for _ in range(q):
        x, y = map(int, input_data.readline().split())
        out.append(str(ask(x, y)))

    return "\n".join(out)

 ## 特殊なケース

 頂点が同一の場合を考えてみましょう。```
4 1
1 2 3 4
1 2 3
4 4
```アルゴリズムは計算します`f(4,4) = 16 + f(3,3)`

`f(3,3) = 9 + f(2,2)`

`f(2,2) = 4 + f(1,1)`

`f(1,1) = 1 + f(0,0)`生み出すのは`30`。 再帰では等しい頂点が自然に処理されるため、特別なことは必要ありません。 

ここで星について考えてみましょう。```
5 1
1 2 3 4 5
1 1 1 1
2 3
```処刑は、`f(2,3) = 2*3 + f(1,1)`

`f(1,1) = 1`与える`7`。 

これにより、クエリされた頂点がすぐに分岐した場合でも、アルゴリズムがルートまで正しく続行されることが確認されます。 

最後に、同じ深度にある多くの頂点を考慮します。 スターと`99999`葉は膨大な数の潜在的なペアを作成します。 アルゴリズムはすべてのペア値を保存することはありません。 サイズが最大以下の深さを含む状態のみをキャッシュします。`B`、メモリを維持する`O(n√n)`それよりも`O(n²)`。 これはまさに、平方根分解引数が処理できるように設計された状況です。
