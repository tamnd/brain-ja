 ## 解決策
 ## 問題の理解

 瓶の順列が与えられています。 瓶`i`ようやく定位置に立つはずだ`i`, しかし、現在の配置はシャッフルされています。 

1 回の操作で、最大 5 つの位置のサブセットを選択し、それらの位置内の jar を任意に並べ替えることができます。 位置は連続している必要はありません。 タスクは、順列を並べ替えるだけでなく、可能な限り最小限の操作数を使用して並べ替えを実行し、同時に操作自体を出力することです。 

興味深いのは、1 回の操作が非常に強力であることです。 5 つの位置を選択すると、それらの 5 つの jar に一度の操作で任意の順列を適用できます。 つまり、問題はシミュレーションやローカル スワップに関するものではないということです。 それは、1回の手術でどの程度の障害を取り除くことができるかを理解することです。 

入力サイズが到達しました`10^5`したがって、状態を検索したり、指数関数的な手法を使用してグローバルに最適化を試みたりするアプローチは不可能です。 たとえ`O(n^2)`アルゴリズムは 2 秒の制限では危険です。 線形時間に近いものが必要です。 

順列構造は、サイクル分解を直ちに示唆します。 すべての順列は独立したサイクルに分割でき、1 つのサイクルを修正しても他のサイクルに影響を与えることはありません。 操作では選択した要素を最大 5 つまで任意に再配置できるため、自然な疑問は次のとおりです。1 回の操作で何サイクルを修復できるでしょうか?

 不注意な実装を簡単に破ってしまうようなエッジケースがいくつかあります。 

長さのサイクル`1`はすでに正しいため、無視する必要があります。 例えば：```
1
1
```答えは`0`。 サイクルの一部としてすべてのインデックスを盲目的に処理するバグのある実装では、不要な操作が発生する可能性があります。 

最大でも長さのサイクル`5`たった 1 回の操作で修正できます。 例えば：```
5
2 3 4 5 1
```これは単一の 5 サイクルです。 5 つのポジションをすべて選択し、それらを 1 回の動作で正しい順序に回転させます。 

長いサイクルは難しい部分です。 考慮する：```
8
2 3 4 5 6 7 8 1
```これは 1 サイクルの長さです`8`。 5 つの位置を独立して繰り返し修正する単純な貪欲な場合、すでに正しい位置を誤って破壊したり、操作を多用しすぎたりする可能性があります。 最適な分解を行うには、サイクルを慎重にチャンクに分割する必要があります。 

別の微妙なケースが長さのサイクルで現れる`6`。 最大でも 5 つの位置しか操作できないため、1 回の操作は不可能です。 ただし、次の 2 つの操作で十分です。```
6
2 3 4 5 6 1
```あらゆるサイクルのニーズを想定したソリューション`ceil(len / 5)`操作が与える`2`ここでは正しいですが、実際の構造が重要です。 構成が順列を並べ替える有効な操作を作成する必要があります。 

この問題の最も難しい部分は、カウント自体ではなく、最小値を正確に達成する操作を構築することです。 

## アプローチ

 ブルートフォースの観点は、順列の操作の観点から直接考えることです。 各ステップで、最大 5 つの位置を選択し、再配置を適用します。 おおよそありますので、`O(n^5)`可能なサブセットと各サブセットの多くの順列があると、分岐因子はすぐに爆発します。 たとえ`n = 20`、これはもう絶望的です。 

もう少し賢い強引なアイデアは、サイクルを独立して処理することです。 サイクルに長さがあると仮定します`k`。 1 回の操作で最大 5 つの位置を再配置できるため、一度に最大 5 つの間違って配置された要素を貪欲に修正できるかもしれません。 これは機能的には機能しますが、最適には機能しません。 長いサイクルを不用意に分解すると、操作が無駄になる可能性があります。 

重要な観察は、1 回の操作で最大 5 つの長さのサイクルを完全に解決できるということです。 

サイクルを実行してください。```
(a1 -> a2 -> a3 -> ... -> ak -> a1)
```もし`k <= 5`、すべてのサイクル位置を選択すると、1 回の移動ですべての jar を正しい場所に直接送ることができます。 

それは問題を完全に変えます。 任意の順列について考える代わりに、長いサイクルを 1 つの操作内にそれぞれ収まる小さなサイクルに分解する方法を理解するだけで済みます。 

サイクルに長さがあると仮定します`k > 5`。 

5 つの要素に対する 1 回の演算により、サイクル長を 4 短縮できます。 その理由は、4 つの要素を永続的に修正し、残りの要素をより小さなサイクル内に残しておく可能性があるためです。 

たとえば、長さのサイクルから`8`:```
(1 2 3 4 5 6 7 8)
```以下を含む 5 サイクルを抽出できます。```
(1 2 3 4 5)
```それらを適切に修正した後、残りの障害は長さのサイクルになります`4`。 

これにより、最適な式が得られます。```
operations = ceil((k - 1) / 4)
```なぜなら、各操作でサイクルから最大 4 つの独立した配置ミスを除去できるからです。 

残りの課題は建設的なものです。 サイクルを分割して有効な操作を出力する体系的な方法が必要です。 

標準的な手法は再帰的削減です。 サイクル長を超えると、`5`、サイクルから 5 つの連続する頂点を取得し、そのうちの 4 つを修正する 1 つの操作を適用し、小さい方の残りのサイクルを続行します。 

残りサイクル長が最大になったとき`5`、最後の操作で解決します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列を読み取り、それを素のサイクルに分解します。 

訪問済みの配列を維持します。 すべての未訪問の位置から開始して繰り返し追跡します`p[i]`振り出しに戻るまで。 
2. 長さのサイクルを無視する`1`。 

これらの位置はすでに正しいので、操作で使用する必要はありません。 
3. 最大長のサイクルごとに`5`、1回の操作で解決します。 

サイクルが次のようになっているとします。```
c0 -> c1 -> c2 -> ... -> ck-1 -> c0
```これらの位置を選択し、瓶を後方に回転させて、すべての瓶が正しい位置に移動するようにします。 
4. より長いサイクルの場合`5`、5つの位置に対する操作を繰り返し抽出します。 

現在のサイクルを次のようにします。```
[v0, v1, v2, ..., vm-1]
```私たちは次のように考えます。```
[v0, v1, v2, v3, v4]
```そして修正する操作を実行します`v1, v2, v3, v4`。 

この操作後の残りのサイクルは次のようになります。```
[v0, v5, v6, ..., vm-1]
```したがって、その長さは 4 減少します。 
5. 残りのサイクル長が最大になるまで続けます。`5`。 
6. 最後の小さなサイクルを 1 回の操作で解決します。 
7. すべての操作を出力します。 

### なぜ効果があるのか

 不変条件は、未完成のコンポーネントは常に単一サイクルのままであるということです。 

5 つの要素に対する各操作により、そのサイクルから 4 つの頂点が永久に削除されます。 これらの頂点は永久に固定され、二度と参加することはありません。 

長さのサイクル`k`少なくとも必要です`ceil((k - 1) / 4)`1 つの操作には最大 5 つの要素が含まれるため、最大 4 つの新しい位置が正しくなる可能性があります。 アルゴリズムは、サイクルを毎回 4 ずつ縮小することで、正確にこの制限を達成します。 

サイクルは独立しているため、各サイクルを最適に解決すると、全体的に最適なソリューションも得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = [0] + list(map(int, input().split()))

    vis = [False] * (n + 1)
    ops = []

    def apply_cycle(cyc):
        k = len(cyc)

        pos = cyc
        target = cyc[1:] + cyc[:1]

        ops.append((k, pos[:], target[:]))

    for i in range(1, n + 1):
        if vis[i]:
            continue

        cur = []
        x = i

        while not vis[x]:
            vis[x] = True
            cur.append(x)
            x = p[x]

        m = len(cur)

        if m == 1:
            continue

        while m > 5:
            part = cur[:5]

            apply_cycle(part)

            cur = [cur[0]] + cur[5:]
            m = len(cur)

        apply_cycle(cur)

    print(len(ops))

    for k, b, c in ops:
        print(k)
        print(*b)
        print(*c)

if __name__ == "__main__":
    solve()
```最初の部分では、標準の DFS スタイルの順列エッジの走査を使用して、順列をサイクルに分解します。 すべてのインデックスは 1 回だけアクセスされるため、このセクションは線形です。 

ヘルパーさん`apply_cycle`サイクルを 1 つのマシン操作に直接変換します。 サイクルが次のようになっているとします。```
[a, b, c, d]
```現在：```
p[a] = b
p[b] = c
p[c] = d
p[d] = a
```操作マップは次のとおりです。```
a -> b
b -> c
c -> d
d -> a
```これにより、すべての jar が正しい位置に送られます。 

最もデリケートな部分は、大きなサイクルを縮小することです。 最初の 5 つの頂点を取得した後、この操作によりそのうちの 4 つが永続的に固定されますが、最初の頂点はサイクルの残りの部分に接続されたままになります。 置換:```
[v0, v1, v2, v3, v4, v5, ...]
```と：```
[v0, v5, ...]
```残りの環状構造は保存されます。 

よくある実装上の間違いは、マッピングの方向を逆にしてしまうことです。 このステートメントでは、操作を「位置からの jar」として定義しています。`bi`位置に行く`ci`1 サイクルにつき、ポジションを 1 回だけ前方にシフトする必要があります。 

もう 1 つの簡単なバグは、後の操作ですでに固定されている頂点を誤って含めてしまう可能性があります。 削除された頂点は二度と表示されないため、縮小プロセスによりこの問題が自動的に回避されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    p = [0] + list(map(int, input().split()))

    vis = [False] * (n + 1)
    ops = []

    def apply_cycle(cyc):
        k = len(cyc)

        pos = cyc
        target = cyc[1:] + cyc[:1]

        ops.append((k, pos[:], target[:]))

    for i in range(1, n + 1):
        if vis[i]:
            continue

        cur = []
        x = i

        while not vis[x]:
            vis[x] = True
            cur.append(x)
            x = p[x]

        if len(cur) == 1:
            continue

        while len(cur) > 5:
            ops.append((5, cur[:5], cur[1:5] + [cur[0]]))
            cur = [cur[0]] + cur[5:]

        apply_cycle(cur)

    out = [str(len(ops))]

    for k, b, c in ops:
        out.append(str(k))
        out.append(" ".join(map(str, b)))
        out.append(" ".join(map(str, c)))

    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# sample 1
assert run("6\n3 5 6 1 2 4\n").splitlines()[0] == "2"

# already sorted
assert run("1\n1\n").splitlines()[0] == "0"

# single 5-cycle
assert run("5\n2 3 4 5 1\n").splitlines()[0] == "1"

# single 6-cycle
assert run("6\n2 3 4 5 6 1\n").splitlines()[0] == "2"

# long cycle

2

positions: 1 2
