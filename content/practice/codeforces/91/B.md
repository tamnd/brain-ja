 ## 解決策
 ## 問題の理解

 セイウチの列が与えられ、インデックスの順序は尾から頭へ向かっていきます。 位置にあるセイウチごとに`i`、最も遠い位置を見つけたい`j > i`つまり、前方のセイウチは厳密に若いということです。`a[j] < a[i]`。 

そのようなセイウチが存在しない場合、答えは次のようになります。`-1`。 

そのようなセイウチが存在する場合、不快感はそれらの間に立つセイウチの数に等しくなります。$$j - i - 1$$重要な点は、最も近い若いセイウチは必要ないということです。 私たちは、列の中で最も若いセイウチを先頭に置きたいと考えています。 

キューの長さは次のとおりです`10^5`、したがって、二次解は遅すぎます。 単純な二重ループはすべてのペアをチェックします`(i, j)`と`i < j`、おおよそ次のようになります`10^10`最悪の場合の運用。 これは 2 秒の制限をはるかに超えています。 周りに何かが必要です`O(n log n)`または`O(n)`。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

同じ年齢を考慮します。```
4
5 5 5 5
```正しい出力は次のとおりです。```
-1 -1 -1 -1
```を使用した不注意な実装`<=`の代わりに`<`同じ年齢を誤って若いものとして扱うことになります。 

もう 1 つの微妙なケースは、最も遠い若いセイウチが近くの最小値ではない場合です。```
5
10 9 8 7 6
```答えは次のとおりです。```
3 2 1 0 -1
```最初のセイウチの場合、年齢を重ねたセイウチが正しい選択です`6`、年齢を重ねて初めて若いセイウチではない`9`。 

もう 1 つのトリッキーなシナリオは、より大きな値の後にのみ若いセイウチが存在する場合に発生します。```
6
5 100 99 98 1 2
```年齢的には`100`、最も若いセイウチは`2`最後に、ではなく、`1`。 答えは、最低年齢ではなく、最も遠い有効なインデックスによって決まります。 

## アプローチ

 ブルート フォース ソリューションは、定義に直接準拠します。 あらゆるポジションについて`i`、以降の位置ごとにスキャンします`j > i`。 いつでも`a[j] < a[i]`、そのようなインデックスの最も遠いものを使用して回答を更新します。 

これは、すべての候補を明示的にチェックするため機能します。 ロジックは単純で正しいです。 

問題は走行時間です。 と`n = 10^5`、ネストされたループは次のことを実行します。$$\frac{n(n-1)}{2} \approx 5 \times 10^9$$最悪の場合の比較。 それは遅すぎます。 

重要な観察は、私たちは左の誰かにとって最も若いセイウチになる可能性のあるポジションだけを気にしているということです。 

配列を右から左に処理するとします。 左に移動しながら、接尾辞からの候補位置を含む構造を維持します。 

ポジションは、その年齢が右端に表示されるすべての年齢よりも小さい場合にのみ役立ちます。 これらの役職は、厳密に年齢が減少する順序を形成します。 例えば：```
10 8 5 3 50 45
```右から左にスキャンすると、候補最小値が生成されます。```
45 at index 5
3 at index 3
```右端に小さい値がすでに存在するため、他の値はすべて役に立ちません。 

次に、年齢を重ねたセイウチについて考えてみましょう`x`。 これらのサフィックス最小値の中で、年齢が以下より小さい最も遠いインデックスが必要です。`x`。 

候補者の年齢は、保存された順序で表示すると厳密に増加するため、最後の値を二分探索できます。`< x`。 

これにより、問題は次のように縮小されます。 

1. 右から左にスキャンしながらサフィックスの最小位置を構築します。 
2. 二分探索を使用して、最も遠い若いセイウチを見つけます。 

全体の複雑さは次のようになります。`O(n log n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. という名前の空のリストを作成します。`mins`。 

このリストにはペアが保存されます`(age, index)`右から左へのスキャン中に発見された接尾辞の最小値を表します。 
2. 配列の最後の位置から最初の位置に向かって処理を開始します。 

すべてのステップで、すでに処理された位置は、現在のセイウチの前のサフィックスに属します。 
3. 今の時代に合わせて`a[i]`、内部の二分探索`mins`。 

最も右に保存されている年齢は、厳密に次の値よりも小さくする必要があります。`a[i]`。 内部では保管年数が増えているため、`mins`、二分探索は正しく機能します。 
4. そのような要素が存在する場合、不快感を計算します。 

一致する保存位置が次であると仮定します。`j`。 答えは次のとおりです。$$j - i - 1$$5. これより小さい年齢が存在しない場合`mins`、 店`-1`。 

つまり、この先に若いセイウチはいないということだ。 
6. 立場を回答した後`i`、現在のセイウチをに挿入するかどうかを決定します。`mins`。 

その経過時間が最後に保存された最小値よりも小さい場合にのみ挿入します。 その場合、それが新しいサフィックスの最小値となり、将来のポジションに役立つ可能性があります。 
7. 回答は結果配列に直接書き込まれるため、リバースは必要ありません。 

### なぜ効果があるのか

 重要な不変条件は次のとおりです`mins`常に、現在のインデックスの右側の位置のサフィックス最小値が正確に含まれます。 

ポジションが末尾の最小値ではない場合、より遠いポジションの年齢はさらに小さくなります。 この問題では最も若いセイウチが求められているため、その遠い位置の方が常に優れています。 

したがって、最小以外のポジションはすべて安全に破棄できます。 

保存されている年齢は厳密に増加しています`mins`これは、右から左へのスキャン中に厳密に小さい値が出現した場合にのみ新しい要素を追加するためです。 この順序により二分探索が可能になります。 

より小さい右端の年齢を二分探索すると、`a[i]`、現在のセイウチよりもまだ若い、最も遠いサフィックス最小値を取得します。 有用な候補はすべて接尾辞の最小値でなければならないため、この位置はまさに正解です。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    ans = [-1] * n

    # stores (age, index)
    # ages are strictly increasing
    mins = []

    for i in range(n - 1, -1, -1):
        age = a[i]

        # find first age >= current age
        pos = bisect_left(mins, (age, -1))

        # elements before pos have smaller age
        if pos > 0:
            j = mins[pos - 1][1]
            ans[i] = j - i - 1

        # add new suffix minimum
        if not mins or age < mins[-1][0]:
            mins.append((age, i))

    print(*ans)

if __name__ == "__main__":
    solve()
```すべてのセイウチは前にいる人々のことだけを気にするため、ソリューションは右から左にスキャンします。 位置で`i`、接尾辞`[i+1 ... n-1]`すでに処理されています。 

の`mins`配列はサフィックス最小値を特別な順序で格納します。 年齢は厳密に増加していますが、逆方向にスキャンしているため、インデックスも増加しています。 この順序により二分探索が可能になります。 

電話の内容:```
bisect_left(mins, (age, -1))
```保存されている年齢が少なくとも次のペアを検索します。`age`。 その位置より前のすべてのものには厳密に小さい年齢が設定されており、これはまさに私たちが必要としているものです。 

右端の小さい要素は、最も遠い有効なセイウチを示します。 以来`mins`距離の増加順に並べられたサフィックス最小値が含まれており、最後の小さい要素を選択すると、自動的に最大のインデックスが得られます。 

微妙な詳細の 1 つは挿入条件です。```
if not mins or age < mins[-1][0]:
```使用する`<`の代わりに`<=`重要です。 年齢が同じであっても若くないわけではないため、同じ値が新しい接尾辞の最小値になってはなりません。 

もう 1 つの簡単な間違いは、不快感の公式です。 この問題では、距離そのものではなく、2 つの位置間のセイウチの数が求められます。 そのため、次のように計算します。```
j - i - 1
```の代わりに`j - i`。

# helper: run solution on input string, return output string
import sys
import io
from bisect import bisect_left

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    ans = [-1] * n
    mins = []

    for i in range(n - 1, -1, -1):
        age = a[i]

        pos = bisect_left(mins, (age, -1))

        if pos > 0:
            j = mins[pos - 1][1]
            ans[i] = j - i - 1

        if not mins or age < mins[-1][0]:
            mins.append((age, i))

    print(*ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run(
    "6\n10 8 5 3 50 45\n"
) == "2 1 0 -1 0 -1", "sample 1"

# minimum size
assert run(
    "2\n1 2\n"
) == "-1 -1", "strictly increasing"

# decreasing sequence
assert run(
    "5\n5 4 3 2 1\n"
) == "3 2 1 0 -1", "furthest younger always at end"

# all equal
assert run(
    "4\n7 7 7 7\n"
) == "-1 -1 -1 -1", "equal ages are not younger"

# mixed case with distant answer
assert run(
    "6\n5 100 99 98 1 2\n"
) == "3 3 2 0 -1 -1", "furthest younger is not necessarily minimum value"

# boundary style case
assert run(
    "5\n10 1 9 2 8\n"
) == "3 -1 1 -1 -1", "checks off-by-one distances"

print("All tests passed.")

 ## 特殊なケース

 すべての年齢が等しいと考えます。```
4
5 5 5 5
```右から左にスキャンしている間、構造には少なくとも 1 つのサフィックスのみが保存されます。`(5,3)`。 すべての二分探索では、以下よりも厳密に小さい値が求められます。`5`、しかしどれも存在しません。 アルゴリズムは次を出力します。```
-1 -1 -1 -1
```このケースでは、等しい年齢が正しく処理されていることを確認します。 

ここで、厳密に減少するシーケンスを考えてみましょう。```
5
9 8 7 6 5
```最後を除くすべてのセイウチには、若いセイウチが先にいます。 最も遠い若いセイウチは常に最後の位置になります。 

答えは次のようになります。```
3 2 1 0 -1
```サフィックス最小値が継続的に減少するため、アルゴリズムは成功します。```
(5,4), (6,3), (7,2), ...
```二分検索では常に、最も遠い有効なインデックスが選択されます。 

最後に、最も小さい若いセイウチが正解ではない場合を考えてみましょう。```
6
5 100 99 98 1 2
```年齢を重ねたセイウチにとって`100`、 両方`1`そして`2`若いです。 この問題では、最も若いセイウチを求めています。`2`最後に。 

不快感は次のとおりです。```
5 - 1 - 1 = 3
```サフィックスの最小構造では、位置が距離の増加順に格納されるため、二分探索では、年齢が最も小さいものではなく、最も遠い有効な位置が自然に選択されます。
