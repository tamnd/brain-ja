 ## 問題の理解

 ソース文字列があります`s1`、これは 1 つの新聞の見出しを表します。 この見出しのコピーを必要なだけ取得し、連結することができます。 結果として得られる長い文字列から、残りの文字の順序を維持したまま、任意の文字を削除することができます。 

対象の文字列`s2`連結された見出しのサブシーケンスとして表示される必要があります。 タスクは、次の最小コピー数を決定することです。`s1`構築するために必要な`s2`。 あるキャラクターの場合、`s2`決して登場しない`s1`、そのタスクは不可能です。 

この操作は完全にサブシーケンスに関するものです。 文字を並べ替えるのではなく、スキップするだけです。 たとえば、次の場合`s1 = "abc"`そして`s2 = "cab"`、1 部では不十分です。`"cab"`の続きではありません`"abc"`。 2 つのコピーが機能する理由は、`"cab"`の続きです`"abcabc"`。 

制約はソリューションを大きく左右します。 長さ`s1`せいぜい`10^4`、これは前処理には十分小さいです。 長さ`s2`到達できる`10^6`、つまり、フルスキャンを実行するアルゴリズムを意味します。`s1`のすべてのキャラクターに対して`s2`遅すぎるでしょう。 次のような二次形式の解決策`O(|s1| * |s2|)`前後が必要になる可能性があります`10^10`最悪の場合、2 秒以内に操作が不可能になる場合があります。 ターゲットの複雑さは線形に近い必要があります。`|s2|`、最大でも対数のオーバーヘッドが発生します。

現在の文字が存在する場合、微妙な境界条件が表示されます。`s1`ただし、現在の位置の後ではありません:```

 ## アルゴリズムのチュートリアル

 1. 前処理`s1`すべての文字のすべての出現位置を保存することによって。

### なぜ効果があるのか

 このアルゴリズムは、新しいコピーを開始する前に、常に現在のコピーから可能な限り多くを消費します。 新しいコピーを早く開始しても、現在のコピー内に追加の一致の機会が作成されないため、この貪欲な選択は最適です。 

あらゆる段階で、`pos`は、現在の新聞で最後に一致した位置を表します。 二分探索では、可能な限り最も早い有効な次の出現が選択されます。 最も早い出現を選択すると、将来の文字に使用できる最大の残りのサフィックスが残りますが、これは役に立ちます。 

その後何も発生しないときは常に`pos`、現在のコピー内のすべてのサブシーケンスの継続は不可能です。 新しいコピーを開始することは、単なる選択ではなく、必要なことです。 

このアルゴリズムは強制された場合にのみ新しいコピーを開始するため、コピーの総数は最小限で済みます。 

## Python ソリューション```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

def solve():
    s1 = input().strip()
    s2 = input().strip()

    positions = {}

    for i, ch in enumerate(s1):
        if ch not in positions:
            positions[ch] = []
        positions[ch].append(i)

    for ch in s2:
        if ch not in positions:
            print(-1)
            return

    ans = 1
    pos = -1

    for ch in s2:
        arr = positions[ch]

        idx = bisect_right(arr, pos)

        if idx == len(arr):
            ans += 1
            pos = arr[0]
        else:
            pos = arr[idx]

    print(ans)

solve()
```前処理ステップでは、文字からソートされた出現位置までの辞書を構築します。 スキャンするので`s1`左から右に、リストは自動的にソートされます。 

不可能性チェックはメインループの前に行われます。 これにより、文字の欠落により照合プロセスが繰り返し失敗するという特殊なケースが回避されます。 

変数`pos`の現在のコピー内で最後に一致したインデックスを追跡します`s1`。 使用する`-1`任意の文字の最初の有効な出現は常に より大きいため、initial は便利です。`-1`。 

実装の重要な詳細は、`bisect_right`。 厳密に現在の位置の後に最初に出現する必要があります。 使用する`bisect_left`同じ文字位置を複数回再利用することを誤って許可してしまう可能性があります。 

二分検索で有効な次の位置が見つからない場合は、新しいコピーを開始して、最初に出現した文字を使用する必要があります。 リセット忘れ`pos`正しくは、ここによくあるバグがあります。 

このアルゴリズムは、次の繰り返しコピーを明示的に構築することはありません。`s1`。 それらの間の遷移のみをシミュレートするため、答えが大きい場合でもメモリ使用量が少なく抑えられます。
