 ## 問題の理解

 整数のペアを出力するジェネレーターを構築するように求められます。$(a, b)$満足のいく$1 \le a \le b \le k$そして、新しい値をリクエストするたびに、有効な各ペアが等しい確率で生成されなければなりません。 

重要な要件は、有効なペアを生成するだけではなく、有効なペアのセット全体にわたって均一性を確保することです。 つまり、ある場合$T$合計で有効なペア。それぞれのペアには正確な確率がなければなりません$1/T$。 

入力は単一の上限で構成されます$k$、各ペアの両方のコンポーネントが取り得る値の範囲と整数を定義します。$n$、これは生成する必要があるペアの数です。 出力は単純に$n$独立して生成されたペア。 

有効なペアの数は三角形の構造になっています。 固定ごとに$a$、値$b$からの範囲が可能です$a$に$k$、与える$k - a + 1$ペア。 全体をまとめると$a$、ペアの合計数は$k(k+1)/2$。 と$k$まで$10^9$、この数値は明示的に列挙または保存するには大きすぎるため、解決策は数​​式または暗黙的なインデックス付けを使用する必要があります。 

すべてのペアを明示的に構築する単純なアプローチは、時間とメモリの両方ですぐに失敗します。 完全なリストを生成する場合でも、$O(k^2)$最悪の場合、スペースが確保できませんが、それは不可能です。 

選択しようとすると、より微妙な失敗例が表示されます。$a$そして$b$～から独立して一律に$[1, k]$次に、無効なペアを拒否します。$a > b$。 これにより、小さいペアが存在するため、偏った分布が生成されます。$a$棄却確率は正方形のすべての領域で均一ではないため、棄却後の有効な結果の中で過剰に代表されます。 

最も難しいのは、正方形の中に埋め込まれた三角形の領域にわたって均一なサンプリングを確保することです。 

## アプローチ

 ブルートフォースのアイデアは、すべての有効なペアを明示的にリストすることです。$(a, b)$、それらを配列に格納し、その配列から均一に選択します。 すべてのペアが 1 回だけ表現されるため、これは概念的に機能します。 ただしペア数は$k(k+1)/2$、中程度の場合でも天文学的に大きくなります$k$。 メモリ要件だけでは不可能であり、構築時間は 2 次関数になります。$k$。 

重要な点は、ペアの完全なセットが必要ではなく、ペアに均一にインデックスを付ける方法だけが必要であるということです。 各ペアを一意の整数にマッピングできれば、$[1, T]$そしてそのマッピングを効率的に反転すると、ペアの生成は均一な整数の生成とそれをデコードすることになります。 

ペアを辞書順に並べ替えることができます。$a$、その後、$b$。 固定の場合$a$、まさにあります$k - a + 1$ペア。 これにより、累積的な構造が得られます。すべてのペアは小さいものから始まります。$a$連続したブロックを形成します。 プレフィックス関数を定義すると$$P(a) = \sum_{i=1}^{a} (k - i + 1),$$それから$P(a)$ブロックまでのペアが何個存在するかを示します。$a$。 ランダムな整数をサンプリングしたら$x$で$[1, T]$、どれかを見つけることができます$a$それが含まれている場合は、そのブロック内のオフセットを計算して回復します$b$。 

残る唯一の課題は見つけることです$a$効率的に。 以来$P(a)$は二次関数です。二分探索を使用するか、二次公式を直接使用して逆変換できます。次のようになります。$O(1)$サンプルごとの計算。

 ## アルゴリズムのチュートリアル

 広い範囲の値を生成できる均一ランダム整数ジェネレーターへのアクセスを想定しています。 

### ステップ

 1. 有効なペアの合計数を計算します。$T = k(k+1)/2$。 これにより、均一なサンプリング空間が定義されます。 
2. それぞれについて$n$必要な出力、ランダムな整数を生成$x$均一に$[1, T]$。 これは、辞書編集上の順序でのペアのインデックスを表します。 
3. 最小値を決定する$a$ブロックまでのペアの数が$a$、つまり$P(a)$、少なくとも$x$。 このステップでは、ペアがどの最初の座標に属しているかを特定します。 
4. 1回$a$わかっているので、どれくらい離れているかを計算します$x$ブロックの中にあります$a$。 そのオフセットは、$b$範囲内で$[a, k]$、 それで$b = a + (x - P(a-1) - 1)$0 ベースのオフセット形式で。 
5. 出力$(a, b)$。 

唯一の重要な部分はステップ 3 です。線形にスキャンする代わりに、次の二次形式を反転します。$P(a)$。 以来$P(a)$は単調増加であり、反転は明確に定義されており、一意の結果が得られます。$a$。 

### なぜ効果があるのか

 この構造は、有効なペアのセット全体を固定の単位で連続したブロックに分割します。$a$。 各ブロックのサイズは正確です$k-a+1$したがって、インデックス作成スペースはこれらのブロック サイズと完全に一致します。 ランダムなインデックスは均一であるため、$[1, T]$、すべてのブロック位置は同じ可能性があり、各ブロック内ではすべての位置が同じである可能性があります。$b$同様の可能性があります。 この 2 レベルの均一性により、各ペアが$(a,b)$確率で正確に選択される$1/T$したがって、分布はすべての有効なペアにわたって均一になります。 

## Python ソリューション```python
import sys
import random
import math

input = sys.stdin.readline

def find_a(k, x):
    # Solve P(a) >= x where P(a) = a*k - a*(a-1)/2
    # Rearranged quadratic: a^2 - (2k+1)a + 2x <= 0
    # Take smaller root upper bound

    A = 2 * k + 1
    D = A * A - 8 * x
    s = int(math.isqrt(D))

    a = (A - s) // 2
    if a < 1:
        a = 1

    # fix boundary if needed
    while a * k - a * (a - 1) // 2 < x:
        a += 1
    while (a - 1) * k - (a - 1) * (a - 2) // 2 >= x:
        a -= 1

    return a

def prefix(k, a):
    return a * k - a * (a - 1) // 2

def solve():
    k = int(input())
    n = int(input())

    T = k * (k + 1) // 2

    for _ in range(n):
        x = random.randint(1, T)

        a = find_a(k, x)
        prev = prefix(k, a - 1)
        offset = x - prev - 1
        b = a + offset

        print(a, b)

if __name__ == "__main__":
    solve()
```機能`find_a`二次方程式からの閉形式近似を使用してプレフィックス合計の逆変換を実行し、正確な境界に到達するように最大 2 回の調整で修正します。 これにより、整数丸めの下で安全性を維持しながら、完全な二分探索が回避されます。 

の`prefix`関数は、指定された値までのペアの累積数をエンコードします。$a$これは、反転補正とブロック内のオフセットの計算の両方に使用されます。 

メイン ループは均一なインデックスを生成し、この逆マッピングを使用してそれをペアに変換します。 の使用`random.randint`インデックスの全範囲にわたって均一性を保証します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import random

    # deterministic seed for reproducibility in tests
    random.seed(1)

    k = int(sys.stdin.readline())
    n = int(sys.stdin.readline())

    T = k * (k + 1) // 2

    def find_a(k, x):
        A = 2 * k + 1
        D = A * A - 8 * x
        s = int(D ** 0.5)
        a = (A - s) // 2
        a = max(1, min(k, a))
        return a

    def prefix(k, a):
        return a * k - a * (a - 1) // 2

    out = []
    for _ in range(n):
        x = random.randint(1, T)
        a = find_a(k, x)
        b = a + (x - prefix(k, a - 1) - 1)
        out.append(f"{a} {b}")

    return "\n".join(out)

# provided sample-like sanity check (structure only)
assert run("5\n3\n") is not None

# minimum size
assert run("2\n5\n") is not None

# uniform generation sanity (non-deterministic structure check)
assert len(run("10\n10\n").splitlines()) == 10

 ## 特殊なケース

 重大なエッジケースが現れるのは、$x$ちょうど 2 つの境界線上にあります$a$-ブロック。 たとえば、次のようなとき$k = 4$、間の移行$a = 1$そして$a = 2$で発生します$x = 4$。 接頭辞の合計は、この値を最初のブロックの最後の要素に正確にマップする必要があります。$(1,4)$、2 番目のブロックの最初の要素ではありません。 

修正ステップは、`find_a`は、接頭辞の不等式が正確に満たされるまで近似二次解を調整することでこれを処理します。 これにより、整数の丸め誤差があっても、選択された$a$常に正しいブロックに対応します。 

もう 1 つのエッジケースは次のような場合です$x = 1$。 この式により生成される可能性があるのは、$a = 0$または丸めによるアンダーシュートが発生しても、クランプと修正によりすぐに高さまで引き上げられます。$a = 1$、その後$b = 1$ゼロオフセットから直接続きます。
