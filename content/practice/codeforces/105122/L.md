 ## 解決策
 ## 問題の理解

 2 つの式間の算術的等価性を表す 1 行の文字列が与えられています。 各式には 10 進数と記号を含めることができます。`+`そして`-`。 マイナス記号は、2 項減算演算子として、および後続の数値の符号を反転する単項記号として動作することができ、複数の単項記号を連続して使用できます。 

タスクは、入力文字列を 3 つのカテゴリに分類することです。 まず、文字列の形式が不正である可能性があります。これは、不正な文字が含まれている、構造が欠落している、または 1 つだけ含まれていないなど、言語自体の構文規則に違反していることを意味します。`=`。 第 2 に、構文的には有効でも、評価されると算術的には false になる可能性があります。 第三に、構文的に有効であり、数値的にも正しい可能性があります。 

重要な問題は、有効性が非常に寛容な文法、つまり反復単項文の解析に依存していることです。`+`そして`-`記号は使用でき、数字の先頭にゼロを付けることができ、式は空白文字や許可された文字を超える書式によって制限されません。 同時に、不正な入力は、たとえ数値的に解釈できたとしても、早期に拒否する必要があります。 

制約は 1 行に最大 300 万文字です。 これにより、文字列を繰り返しスライスしたり、大きな中間部分文字列を構築したり、バックトラッキングを伴う再帰的解析を使用したりするアプローチは即座に除外されます。 入力サイズが 2 次のものはすべて失敗します。また、線形ソリューションであっても、繰り返しの連結や正規表現のバックトラッキングなどの Python のオーバーヘッドを避けるために慎重に実装する必要があります。 

いくつかの特殊なケースは微妙です。 

最初の重要なケースは、演算子周辺の不正な構造です。 例えば、`2+2=4+`演算子が最後に数字なしで表示されるため、この形式は不正です。 単純な評価器は後続の演算子を無視し、それを有効な構文として誤って扱う可能性があります。 

2 番目のケースは無効な文字です。 のように入力してください`2*2=4`直ちに不正なものとして分類する必要があります。 数字のみに焦点を当て、不明な文字を無視するパーサーは、誤って処理します。`*`ノイズとして続行します。 

3 番目のケースは、近くのあいまいな単項鎖です。`=`。 例えば、`-+10=10`構文的には有効ですが、誤りです。 単項演算子を誤ってマージしたり、符号変更ルールを無視したパーサーは、左側の式を誤って評価する可能性があります。 

最後に、周囲の空の式`=`は無効です。 ような文字列`=1+2`または`1+2=`各辺に少なくとも 1 つの有効な数値トークンが含まれている必要があるため、形式が不正です。 

したがって、中心的な課題は、厳密な構文検証と効率的なシングルパス評価を組み合わせることにあります。 

## アプローチ

 ブルートフォース解釈では、まず各辺をトークンに完全に解析し、明示的な式ツリーを構築するか、後置表記に変換してから、両方の辺を評価します。 これには、文字列に対する複数のパスに加えて、入力サイズに比例したトークン リストまたはスタックの中間割り当てが必要です。 

最悪の場合、各文字はトークン、AST ノード、スタック フレームなどの複数の構造に寄与します。 これにより、文字列のスライスや繰り返しの連結を不用意に実装すると、重度の定数係数が発生し、二次的な動作が発生する可能性があります。 

重要な点は、実際には構造を構築する必要がないということです。 文法は非常に単純なので、各文字を読み取った瞬間に構文を検証しながら、累計と現在の符号を維持することによって 1 回のパスで各辺を評価できます。 

次に、等価性チェックは、2 つの整数をオンザフライで計算して比較することに減り、同時に小さな有限状態ロジックを使用して不正な構造を検出します。つまり、現在数値の中にいるかどうか、演算子が予期されているかどうか、式が正しく開始されているかどうかなどです。

 ## アルゴリズムのチュートリアル

 文字列を 1 回のスキャンで処理し、両側を個別に評価します。 

1. まず、正確に 1 つであることを確認します。`=`文字列の中に存在します。 そうでない場合、構造が等価ではないため、入力は直ちに不正な形式になります。 
2. 処理を論理的に 2 つに分割します。`=`。 文字列を物理的に分割しません。 代わりに、遭遇したときにコンテキストをスキャンして切り替えます。`=`。 
3. それぞれの側で、現在までの合計、現在の符号 (+1 または -1)、および現在数値を予期しているかどうかを示すフラグの 3 つの変数を維持します。 このフラグは、不正な構文を検出するために重要です。 
4. 出会ったとき`+`または`-`、現在の標識を更新します。 あ`+`変更しないままにしておきます。`-`それを裏返します。 複数の記号が連続して表示される場合、それらは自然に結合して数字の前の最後の記号になります。 
5. 数字に遭遇すると、連続する数字全体を解析します。 現在の符号を使用してそれを累計に乗算し、符号を正にリセットして、次に演算子を期待していることをマークします。 
6. 数字以外の文字に遭遇した場合、`+`、`-`、 または`=`、入力はすぐに不正な形式になります。 
7. 数値が予期される場所 (たとえば、別の演算子の後やサイドの先頭) に演算子が出現する場合、その式は単項の場合にのみ有効です。 これは許可することを意味します`+`または`-`数値を期待する場合は、次のような無効な位置に二項演算子を配置することは許可されません。`2+`最後か`=+`。 
8. 両側を処理した後、評価された合計を比較します。 一致する場合は出力します`YES`。 構文は有効だが値が異なる場合、出力`NO`。 

### なぜ効果があるのか

 不変条件は、スキャンのどの時点でも、累計は正しい累積符号効果を持つ完全に消費されたすべての数値の値を表し、現在の符号は最後の数値以降に見られたすべての単項演算子の結合効果を表すということです。 

すべての数値は 1 回だけ消費され、すべての符号は次の数値にのみ影響するため、遅延依存関係は存在しません。 これにより、ストリーミング評価が完全な式解析と同等であることが保証されます。 すべての不正な構造は、数値が期待されるが見つからないか、または禁止文字が表示される状態に対応しており、どちらもトラバーサル中に即座に検出されるため、不正な形式の検出が完了します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def evaluate(expr):
    n = len(expr)
    i = 0
    total = 0
    sign = 1
    expect_number = True

    if n == 0:
        return None, False

    while i < n:
        c = expr[i]

        if c in '+-':
            if expect_number:
                if c == '+':
                    pass
                else:
                    sign *= -1
                i += 1
            else:
                return None, False

        elif c.isdigit():
            j = i
            while j < n and expr[j].isdigit():
                j += 1
            num = int(expr[i:j])
            total += sign * num
            sign = 1
            expect_number = False
            i = j

        else:
            return None, False

    if expect_number:
        return None, False

    return total, True

def solve():
    s = input().rstrip('\n')

    if s.count('=') != 1:
        print("ERROR")
        return

    left, right = s.split('=')

    lv, ok1 = evaluate(left)
    rv, ok2 = evaluate(right)

    if not ok1 or not ok2:
        print("ERROR")
    elif lv == rv:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```このソリューションでは、解析を、1 つの式を線形時間で処理する再利用可能な評価器に分割します。 実行中の合計と符号アキュムレータを保持し、解析された各数値を即座に適用します。 の`expect_number`flag は構造の正確さを強制し、演算子が無効な位置に出現しないようにします。 

での分割`=`この問題では、整形式の場合には等号が 1 つだけ保証され、それ以外のものは直ちに不正として分類されるため、安全です。 

主な微妙な点は、単項演算子の処理です。 とき`+`または`-`数値が予期される位置に出現すると、二項演算子として扱われるのではなく、符号の状態が変更されます。 数値が表示されると、累積された符号が適用されてリセットされ、次のようなチェーンが保証されます。`-+-+-5`正しく処理されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、次のような複数の単項記号で始まる式です。`-+-+-5=5`。 解析中、各符号は数値が消費される前に現在の符号状態を反転または保持します。 エバリュエーターは数値を期待する状態で開始されるため、繰り返し更新されます。`sign`エラーがなければ、数字シーケンスが読み取られたらそれを適用します。 結果は、チェーンを単一の有効なサインに正しく縮小します。 

もう 1 つのエッジ ケースは、次のような末尾演算子です。`2+`。 解析時`2`、状態は「演算子を期待しています」に遷移します。 出会い`+`これは二項演算子の配置であるため有効ですが、`+`文字列が終わる前に数字はありません。 最終チェック`if expect_number`はこれをキャッチし、式が不正であるとマークします。 

3 番目の特殊なケースは、等号の周囲の辺が欠落していることです。 入力用`=1+2`、左側は空いています。 評価器は次で終了するため、すぐに不正な形式を返します。`expect_number`数値を消費しなくても真です。 同じロジックが対称的に適用されます。`1+2=`。
