 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$チェス盤とビショップが開始マスに配置されます。 ビショップは 1 回の移動で任意の数のセルを移動できますが、移動できるのは対角線に沿った場合のみです。 このタスクは、ビショップがターゲットの正方形に到達できるかどうかを判断するだけではなく、開始点から目的地までの最短移動ルートがいくつ存在するかを数えるということです。 

ここでの最短ルートとは、斜め方向の移動を最小限に抑えるパスを意味します。 ビショップの移動は直線の対角線のスライドであるため、可能な経路の長さは、すでに目的地から開始している場合は 0 移動、両方の正方形が同じ対角線上にある場合は 1 移動、ビショップが両方の終点と対角線上にある中間の正方形を迂回する必要がある場合は 2 移動のみです。 

ボードのサイズは次のように大きくできます。$10^9$これにより、グリッド上のあらゆるシミュレーションが即座に除外されます。 どのソリューションも、トラバースではなく純粋に座標ジオメトリで機能する必要があります。 すべての決定は、座標間の算術関係のみに依存します。 

最初の微妙な点は、ビショップが色のパリティによって制限されていることです。 チェス盤上では、ビショップは常に同じ値のマス目に留まります。$x + y \bmod 2$。 開始マスと終了マスのパリティが異なる場合、ボードのサイズに関係なく、一連の動きでそれらを接続することはできません。 

2 番目のエッジ ケースは、開始と終了が同一である場合です。 移動は実行されませんが、正解は長さ 0 のパスが 1 つだけ存在します。 

しばしば間違いを引き起こす 3 番目の状況は、2 つの異なる 2 つの動きの分解が可能であると思われる場合です。 ビショップの移動は完全な対角線セグメントであるため、開始対角線とターゲット対角線を接続する最大 2 つの異なる中間正方形が存在する可能性があります。 

## アプローチ

 直接シミュレーションでは、開始マスからすべての可能なビショップの移動を調査し、目的地までのすべての最短経路を追跡しようとします。 どの位置からでも、ビショップは最大 4 つの対角方向を持ち、各方向で最大 4 つの対角線方向を指定できます。$O(n)$着陸位置。 最短経路に限定したとしても、状態空間は次のようなグラフになります。$O(n^2)$ノードと高密度の対角接続。 BFS は概念的には機能しますが、$n$できる$10^9$したがって、ノードまたはエッジを列挙することは不可能です。 

重要な観察は、司教の運動構造が問題全体を幾何学的ケースの小さなセットに分解しているということです。 目的地は、開始点を通る 2 つの対角線のいずれかにあるか、そうでないかのどちらかです。 そうであれば、最短経路は 1 つだけ存在します。 そうでないが、正方形が同等である場合、最短ルートは正確に 2 移動でなければならず、有効なパスは、開始点からの対角線上と目的地からの対角線上に同時に存在する正方形を選択することによって完全に決定されます。 

これにより、2 つの対角線の交点を見つける問題が軽減されます。 ビショップの各移動は、次のいずれかのラインの選択に対応します。$x - y = c$または$x + y = c$, したがって、中間の正方形は、開始からの 1 つの対角線と終了からの 1 つの対角線の交点になります。 このような交差は最大でも 2 つあり、ボード内の有効な整数点がいくつあるかを数えるだけで済みます。

 ## アルゴリズムのチュートリアル

 1. 開始マスと終了マスが同一であるかどうかを確認します。 そうである場合、ビショップは移動することなくすでに要件を満たしているため、有効なパスは 1 つだけ存在します。 
2. 次を使用して両方の正方形のカラー パリティを計算します。$(x + y) \bmod 2$。 これらが異なる場合は、ビショップの移動シーケンスがカラー クラスをまたぐことができないため、0 を返します。 
3. 両方の正方形が同じ対角線上にあるかどうかを確認します。 これは、次のいずれかの場合に発生します$x_1 - y_1 = x_2 - y_2$または$x_1 + y_1 = x_2 + y_2$。 これが成り立つ場合、ビショップは 1 回の移動で直接進むことができ、そのようなパスは 1 つだけ存在します。 
4. それ以外の場合、最小移動数は 2 です。 有効なパスは、1 回の対角移動で両方のエンドポイントから到達可能な中間の正方形を通過する必要があります。 
5. 対角線を交差させて、最大 2 つの中間正方形の候補を作成します。 

最初の候補は解決策から得られます$x - y = x_1 - y_1$そして$x + y = x_2 + y_2$。 

2番目の候補は次の解決策から来ます$x + y = x_1 + y_1$そして$x - y = x_2 - y_2$。 
6. 各候補について、計算します。$x = \frac{(sum \pm diff)}{2}$、$y = sum - x$、両方の座標が整数であり、ボードの境界内にあることを確認します。 
7. これらの中間正方形の候補のうち、有効なものがいくつあるかを数えます。 有効な各中間点は、正確に 1 つの異なる最短パスに対応します。 

### なぜ効果があるのか

 最短の 2 移動パスはすべて、開始点から対角線上のいずれかのマス目までの最初の移動と、そのマス目からターゲットまでの 2 回目の移動で構成されなければなりません。 両方のステップで到達できる唯一の正方形は、端点によって定義された対角線の交点です。 各対角線のペアは最大 1 点で交差するため、候補となる中間正方形の総数は最大 2 つであり、それぞれが固有のパス分解に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    x1, y1 = map(int, input().split())
    x2, y2 = map(int, input().split())

    if x1 == x2 and y1 == y2:
        print(1)
        return

    if (x1 + y1) % 2 != (x2 + y2) % 2:
        print(0)
        return

    if x1 - y1 == x2 - y2 or x1 + y1 == x2 + y2:
        print(1)
        return

    def valid(x, y):
        return 1 <= x <= n and 1 <= y <= n

    count = 0

    s1 = x1 + y1
    d1 = x1 - y1
    s2 = x2 + y2
    d2 = x2 - y2

    if (s2 + d1) % 2 == 0:
        x = (s2 + d1) // 2
        y = s2 - x
        if valid(x, y):
            count += 1

    if (s1 + d2) % 2 == 0:
        x = (s1 + d2) // 2
        y = s1 - x
        if valid(x, y):
            count += 1

    print(count)

if __name__ == "__main__":
    solve()
```解決策は、座標が一致する場合に優先されるため、ゼロ手と 1 手の場合の早期終了を中心に構成されています。 パリティ チェックは、幾何学的な構築の前にすべての不可能なケースを除去し、不必要な演算を回避します。 

2 つの候補の中点は、対角方程式系を解くことで直接得られます。 対角線の交差には一貫したパリティが必要であるため、整数チェックは偶数和検証を通じて暗黙的に行われます。 次に、代数交差がボードの外側にある可能性があるため、各候補がボードの境界に対して検証されます。$n \times n$無限の対角線がそこで交差しているにもかかわらず、グリッドになります。 

## 実用的な例

 ### 例 1

 スタート地点が小さなボードであると考えてください。$(1,1)$そしてターゲットは$(3,3)$で$n = 5$ボード。 

| ステップ | ポジション | 同じ対角線 | アクション |
 | --- | --- | --- | --- |
 | 開始 | (1,1) | - | パリティを計算する |
 | ターゲット | (3,3) | はい | 1 回の移動で到達可能 |

 どちらの点も満たしています$x - y = 0$、ビショップが直接移動できるようになります。 

これにより、最短パスが 1 つ存在することが確認されます。 

### 例 2

 始めましょう$(1,3)$、ターゲット$(3,1)$、 と$n = 5$。 

| ステップ | 計算 | 結果 |
 | --- | --- | --- |
 | パリティ | (1+3) % 2 = (3+1) % 2 | 同じ |
 | 同じ対角線 | 偽 | 2 つの移動が必要 |
 | 候補 1 | (s2 + d1)/2 = (4 + -2)/2 | x = 1 |
 | 候補 2 | (s1 + d2)/2 = (4 + 2)/2 | x = 3 |

 両方の中間点$(1,1)$そして$(3,3)$ボードの中に横たわります。 

これは、それぞれの中間点を通過する 2 つの異なる最短パスが存在することを示しています。

 ## 特殊なケース

 開始と終了が一致すると、アルゴリズムは幾何学的推論の前にすぐに 1 を返します。 これにより、中間の正方形を示唆するような斜めの交差点を誤って数えることを回避できます。 

パリティが異なる場合、後続のすべての代数交差が依然として間違った色の正方形を表すため、計算は早期に停止し、ボードの形状に関係なくパスが不可能になります。 

両方の正方形が同じ対角線上にある場合、両方の候補の中点式によって端点または無効な点が生成される可能性があります。 初期の対角線チェックにより、偽の中間構造のカウントが防止され、答えが 1 つに正しく修正されます。
