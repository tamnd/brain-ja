 ## 解決策
 ## 問題の理解

 範囲内の整数を数えるように求められます$[a, b]$各整数は正確に 7 つの正の約数を持ちます。 この課題は、任意の数値をオンラインで効率的に因数分解することではなく、約数関数が 7 に等しい数値の構造を理解することです。 

入力は 2 つの非常に大きな整数で構成されます。$10^{18}$、閉じた間隔を定義します。 出力は、この間隔内の約数がちょうど 7 である整数の数です。 

この制約により、範囲内で反復されるアプローチは直ちに除外されます。 さまざまなサイズの単一パスでも$10^{18}$不可能です。 有効な解はすべて、正確に 7 つの約数ですべての数値を特徴付け、それらの候補のみを生成する必要があります。 

よくある落とし穴は、範囲内の数値ごとにその場で因数分解を試みることです。 それぞれの因数分解が最適化されていても、$O(\sqrt{n})$、範囲サイズにより、このアプローチは使用できなくなります。 

もう 1 つの微妙な問題は、「ちょうど 7 つの約数」が 2、4、または 6 つの約数のような一般的なケースと同様に動作すると仮定していることです。 7 の場合、構造は高度に制約されており、その構造が欠けていると完全に間違った解空間が生まれます。 

## アプローチ

 最も直接的なアイデアから始めます: 各数値について$x \in [a, b]$、最大まで反復して除数の数を計算します。$\sqrt{x}$、約数のペアを数えます。 これは正しいですが、まったく実行不可能です。 最悪の場合、近くの数字を1つ確認するだけでも$10^{18}$まで必要です$10^9$これを最大で繰り返し行う必要があります$10^{18}$数字。 

重要な観察は、正確に 7 つの約数を使用して数値を分類することです。 7 は素数であるため、約数の数式は素因数分解に非常に厳密な構造を強制します。 

数字の場合$n = p_1^{e_1} p_2^{e_2} \cdots$、約数の数は次のようになります。$(e_1+1)(e_2+1)\cdots$。 この積が素数の 7 に等しくなるには、因数は 1 つだけ存在できます。 つまり、数値は次の形式でなければなりません$p^6$、 どこ$p$プライムです。 

したがって、すべての有効な数値は正確に素数の 6 乗になります。 これにより、問題は以下のように簡素化されます: 素数を数える$p$そのような$p^6 \in [a, b]$。 同様に、区間内に素数が必要です。$$\lceil a^{1/6} \rceil \le p \le \lfloor b^{1/6} \rfloor.$$の範囲$p$せいぜい$(10^{18})^{1/6} = 10^3$したがって、最大 1000 までの素数だけが必要です。ふるいを使用して素数を 1 回事前計算し、境界を満たす素数の数を数えることができます。

 ## アルゴリズムのチュートリアル

 1. 素数塩基の整数の下限と上限を計算します。 すべての整数を求めます$p$そのような$p^6$にある$[a, b]$。 これは、次の整数の 6 乗根を計算することによって行われます。$a$そして$b$丸め誤差を調整するように注意してください。 
2. 以下のすべての素数を事前計算します。$\lfloor b^{1/6} \rfloor$エラトステネスのふるいを使って。 制限は最大 1000 であるため、これは効率的に機能します。 
3. すべての素数を反復処理します。$p$ふるいから。 
4. 各素数について$p$、計算された範囲内にあるかどうかを確認します。 「はい」の場合、有効な数値が 1 つだけ含まれます。$p^6$。 
5. このような素数をすべて数えて、結果を出力します。 

### なぜ効果があるのか

 divisor-count 関数は乗算的であり、素因数分解に 6 乗の素数が 1 つだけ含まれる場合にのみ 7 に等しくなります。 素因数を追加すると約数が少なくとも 2 倍になるため、他の因数分解では約数の素数を生成することはできません。この制限により、問題全体が非常に短い区間にわたる有界素数計数問題に縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def iroot6(x: int) -> int:
    lo, hi = 1, 10**3 + 5
    while lo <= hi:
        mid = (lo + hi) // 2
        v = mid**6
        if v <= x:
            lo = mid + 1
        else:
            hi = mid - 1
    return hi

def sieve(n: int):
    is_prime = [True] * (n + 1)
    is_prime[0] = is_prime[1] = False
    for i in range(2, int(n**0.5) + 1):
        if is_prime[i]:
            for j in range(i * i, n + 1, i):
                is_prime[j] = False
    return is_prime

def solve():
    a = int(input().strip())
    b = int(input().strip())

    hi = iroot6(b)
    lo = iroot6(a)

    if lo**6 < a:
        lo += 1

    is_prime = sieve(hi)

    ans = 0
    for p in range(lo, hi + 1):
        if is_prime[p]:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```ソリューションの中核は 6 乗根の計算です。 整数二分探索を使用することで浮動小数点の不安定性を回避し、大きな境界付近でも正確性を保証します。 調整`if lo**6 < a: lo += 1`計算された下限が 6 乗が依然として区間外の値に切り捨てられるというエッジ ケースを修正します。 

ふるいは最大約 1000 までしか実行されないため、非常に高速になります。 次に、有効な 6 乗に直接対応する、制限された範囲内の素数をフィルターします。

 ## 特殊なケース

 1 つのエッジ ケースは、下限が有効な 6 乗をわずかに上回る場合に発生します。 たとえば、次の場合$a = 65$、 それから$a^{1/6}$切り捨ては2になりますが、$2^6 = 64$区間内にありません。 調整ステップ`if lo**6 < a: lo += 1`この誤って含まれた候補を確実に除外します。 

もう一つのケースは次のような場合です。$a$そして$b$とても小さいです。 のために$a = b = 1$、6 乗根の計算により次のようになります。$lo = hi = 1$、しかし 1 は素数ではないので、ふるいは正しくゼロを返します。 

最後のケースは、範囲が広いものの、有効な数値がすべて含まれている場合です。 のために$a = 1$、$b = 10^{18}$、アルゴリズムは 1000 までのすべての素数を数えます。すべての有効な数値が素数の基底に一意に対応し、マッピングに重複やギャップが存在しないため、ふるいは正確さを保証します。
