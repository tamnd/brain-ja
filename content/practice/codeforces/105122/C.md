 ## 解決策
 ## 問題の理解

 正しくバランスの取れた長さの括弧文字列を使用しています。$2n$。 このような文字列は、次のシーケンスとして考えることができます。$n$開き括弧と$n$閉じ括弧は、すべての接頭語で開始部分の数が閉じ括弧よりも多くならないように配置され、最後に数が一致します。 

このようなバランスの取れた文字列すべてから、中央の 2 文字、特に位置を削除した後でもバランスが保たれている特別な文字列だけをカウントするように求められます。$n$そして$n+1$インデックスが 1 の文字列内。 削除すると長さの短い文字列が生成されます$2n-2$そして、この結果の文字列が依然として正しい括弧シーケンスであることが必要です。 

したがって、制約は単に全体的なバランスではなく、シーケンスの中央を中心とした構造的安定条件です。 私たちは、固定内部削除操作の下で有効なままのカタルーニャ語構造を効果的にカウントしています。 

制約$n \le 30$動的プログラミングを含むソリューションが十分に小さい$O(n^3)$あるいは$O(n^4)$合計の規模は数万回の操作未満であるため、これらの状態は許容されます。 これは、問題が貪欲やシミュレーションではなく、構造的なカウントに関するものであることを強く示唆しています。 

素朴なアプローチでは、すべてのカタロニア語シーケンスが生成されます。$C_n$を選択し、削除条件をテストします。 これはすでに実現可能ギリギリです$n = 30$、しかしそれでも本質的には指数関数的です。 さらに悪いことに、削除後に各シーケンスを検証すると、別の線形要素が追加され、非実用的になります。 

素朴な推論による微妙な失敗例は、元のバランスが取れていれば中央を削除しても常にバランスが保たれると仮定することです。 例えば、`((()))`3 桁目と 4 桁目を削除した後も有効ですが、`(()())`構造が恣意的に再配置された場合、常に同様に動作するとは限りません。 削除の影響は、グローバル バランスだけではなく、中間領域のネストの深さによって決まります。 

重要な問題は、削除によってシーケンスが 2 つの部分に分割され、その相互作用がカット境界でのプレフィックスとサフィックスのバランスの調整に依存することです。 

## アプローチ

 ブルートフォース戦略は、長さの正しい括弧シーケンスをすべて列挙します。$2n$、その後ポジションを削除します$n$そして$n+1$を実行し、結果のシーケンスがまだ有効かどうかを確認します。 条件を直接テストするため、正確性は簡単です。 バランスのとれたシーケンスの数はカタルーニャ数です$C_n$、これは$n=30$についてです$10^8$、大きすぎます。 枝刈りを行ったとしても、すべてのシーケンスの生成は指数関数的であるため、時間制限内に収まりません。 

完全な構造を列挙することを避けるために、代わりにバランスのとれたシーケンスがその中間付近でどのように動作するかを利用します。 この削除により、中点境界の各側から 1 文字が削除されます。これは、結合条件によって構造が左半分と右半分に分割できることを示唆しています。 

次を使用して、正しい括弧シーケンスをゼロ以下にならないパスとして再解釈します。$+1$'(' と$-1$のために '）'。 中央の削除では各側から 1 ステップが削除され、制約された方法で一致する寄与のペアが効果的に削除されます。 問題は、プレフィックスが位置までのパスをカウントすることになります。$n-1$、から始まるサフィックスと組み合わせる$n+2$、再結合後も有効な Dyck パスを形成します。 

重要な洞察は、中間の直前と中間の直後のバランスを修正することです。 プレフィックスを位置までにします$n-1$ある程度の高さで終わる$h$。 位置の文字$n$+1 または -1 のいずれかに寄与しますが、有効性と一致する開始括弧または終了括弧でなければならないため、状態遷移は制限されます。 ポジションに関しても同様$n+1$。 

両方を削除した後も、連結は非負性を維持する必要があります。 これにより、問題は、ローカル ペアの削除の下で境界の高さが揃う 2 つの部分に Dyck パスを分割する方法を数えることに減ります。 

プレフィックス長と現在の残高に対する DP を使用してこれを形式化し、削除されたセグメントの前か後かを追跡できます。 3 つの領域を考慮します。$n$、中央の 2 文字、およびその後の接尾辞$n+1$。 中間のペアは、削除が有効性に違反しないように強制しながら、2 つの DP 状態を接続するローカル遷移として扱うことができます。 

これにより、位置とバランスに関する動的なプログラミングが行われ、左側、中央、または右側のセグメントにあるかどうかをエンコードする追加の次元が使用されます。

 ## アルゴリズムのチュートリアル

 ブラケットのバランスを維持しながら、ある位置までに有効な部分構造がいくつ存在するかを追跡する DP 状態を定義します。 

1. DP テーブルを定義します。$dp[i][b]$長さのプレフィックスを構築する方法の数を表します$i$それはバランスで終わります$b$、潜在的な解シーケンスの有効なプレフィックスをまだ形成しているという制約の下で。 これは標準的な Dyck パス構築ルールであり、$b \ge 0$。 
2. この DP を、位置までのプレフィックス領域に対して個別に実行します。$n-1$。 この段階では、考えられるすべてのエンドポイントのバランスを記録します。$b$。 これは重要です。なぜなら、中間の削除は、削除された領域の直前に正確にどのようなバランスに達するかに依存するからです。 
3. 同様にサフィックス DP を計算しますが、逆に、位置から開始します。$2n$まで$n+2$。 考えられる開始残高ごとに、サフィックスが有効なまま残高ゼロに戻ることができる方法が何通りあるかを計算します。 これはプレフィックスの計算を反映していますが、時間が逆になります。 
4. 中央の 2 文字の位置を明示的に考慮します。$n$そして$n+1$。 '(' と ')' の可能な割り当てを列挙しますが、各ステップで残高が決してマイナスにならないようにします。 実現可能なペアごとに、プレフィックスとサフィックスの間の境界バランスをどのように変換するかを決定します。 
5. 実現可能な分割状態ごとに、誘導された境界条件に一致するプレフィックス DP とサフィックス DP からのウェイの数を掛けます。 すべての有効な組み合わせを合計すると、最終的な答えが得られます。 

本質的な考え方は、中間の欠失により、完全な構造ではなく、中間領域に出入りするバランスのみに依存する局所的な制約が引き起こされるということです。 

### なぜ効果があるのか

 正しいブラケット シーケンスは、任意の時点でプレフィックスとサフィックスに分解でき、そのインターフェイスは単一の整数、つまり現在の残高によって完全に記述されます。 DP は、Dyck パスのこのマルコフ特性を利用します。 

削除では隣接する 2 つの位置が削除されるため、一定サイズのウィンドウ全体の遷移にのみ影響します。 このウィンドウの外側にあるすべての制約は変更されません。 したがって、結果として得られるシーケンスの正確性は、この局所的な変更を通じてバランスがどのように変換されるかによってのみ決まります。 DP は、グローバルに有効な構造をすべて列挙すると同時に、ローカルな変更が非負性を保持することを保証するため、無効な構成がカウントされることはなく、有効な構成が見逃されることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    N = 2 * n

    # dp_left[i][b] = ways for prefix of length i with balance b
    dp_left = [[0] * (n + 2) for _ in range(n + 1)]
    dp_left[0][0] = 1

    for i in range(n):
        for b in range(n + 1):
            if dp_left[i][b] == 0:
                continue
            # add '('
            dp_left[i + 1][b + 1] += dp_left[i][b]
            # add ')'
            if b > 0:
                dp_left[i + 1][b - 1] += dp_left[i][b]

    # dp_right[i][b] for suffix from position i to end
    dp_right = [[0] * (n + 2) for _ in range(N + 2)]
    dp_right[N + 1][0] = 1

    for i in range(N, n + 1, -1):
        for b in range(n + 1):
            if dp_right[i][b] == 0:
                continue
            # if we place '(' at i
            dp_right[i - 1][b + 1] += dp_right[i][b]
            # if we place ')' at i
            if b > 0:
                dp_right[i - 1][b - 1] += dp_right[i][b]

    ans = 0

    # middle positions are n and n+1
    for b in range(n + 1):
        for mid1 in [1, -1]:  # '(' or ')'
            for mid2 in [1, -1]:
                b1 = b + mid1
                if b1 < 0:
                    continue
                b2 = b1 + mid2
                if b2 < 0:
                    continue

                # after removing both, balance returns to b
                ans += dp_left[n - 1][b] * dp_right[n + 2][b2]

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは 2 つの DP テーブルを中心に構成されています。 1 つ目は、最初に削除された位置まですべての有効なプレフィックスを構築し、残高を明示的に追跡します。 2 つ目は、有効なサフィックスを最後から 2 番目に削除された位置まで逆に構築します。 

中間の遷移ループは、位置に対して可能なすべてのローカル ブラケット構成を試行します。$n$そして$n+1$、中間ステップでバランス制約を破る可能性のあるものを除外します。 有効な中間構成ごとに、プレフィックス終了バランスを、中間エフェクトによって調整されたサフィックス開始バランスに接続します。 

サフィックス DP は長さではなく位置に基づいて定義されるため、インデックスを作成する際には注意が必要です。 重要な不変条件は、両方の DP テーブルが常に有効な Dyck パス セグメントを表すため、それらの境界バランスが一致する場合、乗算は安全であるということです。

 ## 特殊なケース

 のために$n=1$、括弧シーケンスは 1 つだけです`"()"`。 中間の 2 つの位置を削除すると、文字列全体が削除され、有効な空の文字列が残ります。 プレフィックスとサフィックス DP は両方とも単一の基本状態に還元され、中間ループには無効な遷移がないため、DP はこれを正しく処理します。 

のために$n=2$、有効なシーケンスは次のとおりです。`"()()"`そして`"(())"`。 位置 2 と 3 を削除した後のみ、`"()"`そのうちの 1 つについては有効なままであり、DP の単一の有効なバランス パスと一致します。 アルゴリズムは、中間バランスが異なるため、入れ子構造と順次構造を正しく区別し、DP はこれらの状態を明示的に分離します。
