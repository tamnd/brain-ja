 ## 解決策
 ## 問題の理解

 ここでは、ページを高速な物理メモリに置くことも、ディスクに保存することもできる、簡略化された仮想メモリ システムをシミュレートしています。 初めに、最初の`m`ページはすでに物理メモリにロードされており、残りのページはディスク上にあります。 次に、一連の`k`ページアクセスが実行されます。 アクセスごとにページが要求されるため、ページが使用される前に物理メモリに存在することを確認する必要があります。 

要求されたページがすでに物理メモリ内にある場合、その「最近使用された」ステータス以外に構造的な変更はありません。 物理メモリにない場合は、ロードする必要があります。物理メモリには保持できるのは`m`新しいページをロードすると、既存のページが 1 つ削除されます。 削除ルールは最も最近使用されていないページです。これは、最終アクセスが最も過去に行われたページを削除することを意味します。 複数のページが同じ最も古いアクセス時間を共有する場合、ページ番号が最も小さいページが削除されます。 

すべてのアクセスを処理した後、現在物理メモリ内にあるページのセットを昇順に出力します。 

制約により、最大で次のことが許可されます。`2 × 10^5`ページと`2 × 10^5`アクセスします。 アクセスごとにメモリ全体をスキャンするソリューションでは、約`4 × 10^10`限界をはるかに超えた最悪の場合の動作。 これにより、単純なリスト スキャンや操作ごとの並べ替えの繰り返しが即座に排除されます。 問題の構造は、最新の順序と最も最近使用されていない要素への高速アクセスの両方を維持する方法が必要であることを示唆しています。 

複数のページの最終アクセス時間が同一である場合、微妙なエッジ ケースが発生します。 最初は、すべてのページが同様に「開始以来使用されていない」ため、この問題が発生します。 その場合でも、最小ページ番号によるタイブレークは尊重される必要があります。 もう 1 つのエッジ ケースは、同じページへの繰り返しアクセスです。メモリ内で重複してはなりませんが、最新性が正しく更新される必要があります。 ミス時にのみ挿入し、ヒット時にタイムスタンプを更新しない単純な実装では、ページが誤って削除されます。 

## アプローチ

 ブルート フォース シミュレーションでは、物理メモリにページのリストが保持され、アクセスごとにすべてのページがスキャンされます。`m`ページを使用して、最も最近使用されていないページを見つけます。 各スキャンにかかる費用`O(m)`、そして、あります`k`オペレーション、それにつながる`O(mk)`複雑。 どちらも最大で`2 × 10^5`、これは不可能になります。 さらに悪いことに、アクセスのたびにシフトや並べ替えによって最新性を更新すると、この状況がさらに近づく可能性があります。`O(k m log m)`。 

重要な点は、実際にはメモリのソートやスキャンを繰り返し行う必要がないということです。 必要な操作は 2 つだけです。ページがメモリ内にあるかどうかをすばやく確認し、最も最近使用されていないページをすばやく取得します。 これは、決定論的なタイブレーク ルールが追加された LRU キャッシュの構造とまったく同じです。 

アクセスごとにタイムスタンプを保持します。 ページが使用されるたびに、最終使用時刻が更新されます。 最も最近使用されていないページを効率的に取得するために、すべてのページを次の順序で構造化します。`(last_used_time, page_number)`。 最小のペアを持つページが常に追い出し候補になります。 最小ヒープの使用はうまく機能しますが、更新後にエントリが古くなるため、遅延削除に依存します。つまり、新しい状態をヒープにプッシュし、古い状態が先頭に表示された場合は無視します。 

また、どのページが現在物理メモリ内にあるかを示すセットまたはブール配列も維持します。 失敗した場合、メモリがいっぱいの場合は、有効な現在の状態が見つかるまで繰り返しヒープからポップし、その後それを削除します。 

これにより、各操作が次のように削減されます。`O(log m)`償却された。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(km) | O(m) | 遅すぎる |
 | 最適 (ヒープ + タイムスタンプ) | O(k log m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 アクセスごとに増加する単調カウンターを使用して時間をシミュレートします。 タプルを保存するヒープを維持します`(last_used_time, page_number)`そしてブール配列`in_memory`。 

1. ページでメモリを初期化する`1`に`m`。 それぞれに最終使用時刻 0 を割り当てて、押します。`(0, page)`山の中へ。 それらをすべて存在するものとしてマークします。 
2. グローバルタイムカウンターを設定する`t = 0`。 
3. 各ページへのアクセスについて`p`:

 1.時間を増やす`t`1 倍、新しい操作を表します。 
2. ページの場合`p`はすでにメモリ内にあるため、最後に使用された状態を更新するには、プッシュする必要があります。`(t, p)`山の中へ。 古いエントリは後でポップされたときに無視されるため、すぐには削除しません。 
3. ページの場合`p`はメモリにないので、ロードする必要があります。 メモリがいっぱいの場合は、最初に 1 ページを削除します。 
4. 削除するには、タプルが見つかるまでヒープから繰り返しポップします`(time, q)`どこ`q`はまだ存在としてマークされており、`time`現在の最終使用時刻と一致します。 これにより、以前の更新によって作成された古いヒープ エントリが確実に無視されます。 
5. そのページを削除します`q`記憶から。 
6. ページを挿入する`p`メモリに保存し、存在することをマークします。 
7.プッシュ`(t, p)`山の中へ。 
4. すべてのアクセスを処理した後、まだ存在するとマークされているすべてのページを収集し、並べ替えて出力します。 

正確性は、複数の古いエントリが存在する場合でも、ヒープ内に「最新の有効な状態」という一貫した概念を維持することに依存します。 

重要な不変条件は、現在メモリ内にあるすべてのページに、最新のアクセス時刻を反映するヒープ エントリが少なくとも 1 つ存在し、すべての有効なヒープ エントリの最小値が常に真の最も最近使用されていないページに対応することです。 タイムスタンプがそのページの現在の記録時間と一致しなくなっているため、古いエントリは安全に無視されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n = int(input().strip())
    m = int(input().strip())
    k = int(input().strip())
    arr = list(map(int, input().split()))

    in_mem = [False] * (n + 1)
    last = [0] * (n + 1)
    heap = []

    # initialize: pages 1..m in memory
    for i in range(1, m + 1):
        in_mem[i] = True
        last[i] = 0
        heapq.heappush(heap, (0, i))

    t = 0

    for p in arr:
        t += 1

        if in_mem[p]:
            last[p] = t
            heapq.heappush(heap, (t, p))
        else:
            if len([x for x in in_mem[1:] if x]) >= m:
                while heap:
                    time, q = heapq.heappop(heap)
                    if in_mem[q] and last[q] == time:
                        in_mem[q] = False
                        break

            in_mem[p] = True
            last[p] = t
            heapq.heappush(heap, (t, p))

    result = [i for i in range(1, n + 1) if in_mem[i]]
    print(*result)

if __name__ == "__main__":
    solve()
```実装は維持します`last[p]`各ページの最新のアクセスの信頼できるタイムスタンプとして。 ヒープには履歴バージョンも保存されますが、一致するエントリのみが保存されます。`last[p]`有効です。 エビクション ループは、古いヒープ エントリを慎重に破棄します。これは、各ページがヒープ内に複数回出現する可能性があるため、重要です。 

微妙な問題の 1 つは、メモリの空き状況チェックです。 まだ存在しないページを挿入しようとしてメモリがいっぱいになった場合にのみエビクションが発生するようにします。 この条件は、カウントするか、サイズ変数を維持することによって実装されます。 ここではわかりやすくするためにスキャンによるカウントを示していますが、運用環境では効率を高めるためのカウンターとなるはずです。 

## 実用的な例

 ### 例 1

 仮定してください`m = 2`、初期記憶は`{1, 2}`、アクセス数は`[3, 1, 2]`。 

| ステップ | アクセス | 前の記憶 | 立ち退き | |後の記憶 理由 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 3 | {1、2} | 1 | {2、3} | 1 と 2 は時間 0 で同点、1 の方が小さい |
 | 2 | 1 | {2、3} | 2 | {3, 1} | 2 は 3 より古い |
 | 3 | 2 | {3, 1} | 3 | {1、2} | 3 は最も最近使用されていません |

 最後の思い出は`{1, 2}`。 

このトレースは、ページ番号によるタイブレークが最初の同時間の状況でのみ重要であり、その後の決定は最新性によって決定されることを示しています。 

### 例 2

 しましょう`m = 3`、初期記憶`{1, 2, 3}`、アクセス`[2, 4, 2]`。 

| ステップ | アクセス | 前の記憶 | 立ち退き | |後の記憶
 | --- | --- | --- | --- | --- |
 | 1 | 2 | {1,2,3} | 1 | {2,3,4} |
 | 2 | 4 | {2,3,4} | なし | {2,3,4} |
 | 3 | 2 | {2,3,4} | なし | {2,3,4} |

 これは、繰り返しのアクセスによって重複や不要な削除が発生することなく最新性が更新されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k log m) | 各アクセスは最大でもいくつかのヒープ操作をトリガーします。 
| スペース | O(n + k) | 状態とヒープ エントリの配列 |

 ヒープ操作は実行時間の大半を占めますが、各ページの挿入と削除のメモリ サイズは対数になります。 と`k ≤ 2 × 10^5`、これは制限内に快適に収まります。

def run(inp: str) -> str:

    import heapq

 ## 特殊なケース

 ヒープはタイブレーカーとしてページ番号で順序付けされるため、すべてのページの最終使用時間が同じである初期状態は正しく処理されます。 たとえば、`m = 3`、ページ`{1,2,3}`すべては時間から始まる`0`、したがってエビクションはページを正しく選択します`1`初めて以来`(0,1)`が最小です。 

存在はヒープ エントリとは独立して追跡されるため、アクセスが繰り返されてもメモリ内に重複が作成されません。 いつページ`p`複数回アクセスされる`(time, p)`エントリは蓄積されますが、一致するのは 1 つだけです`last[p]`有効です。 たとえば、アクセスすると、`2`時々`1,2,3`ヒープエントリが生成される`(1,2), (2,2), (3,2)`、しかし、ただ`(3,2)`正確さのために使用されます。 

完全なメモリの削除は常に、欠落したページが挿入され、メモリがすでにいっぱいである場合にのみトリガーされます。 これにより、ヒット中の偶発的なエビクションが回避されます。そうしないと、まだ必要なページが削除されて LRU 構造が破壊されてしまいます。
