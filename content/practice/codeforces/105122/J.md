 ## 解決策
 ## 問題の理解

 石の山を 1 つ使って 2 人用の持ち帰りゲームをプレイしています。 プレーヤーは交互にターンを行い、各ターンでプレーヤーは 1 から K 個の石を削除します。 面白いのは、プレイヤーは直前の手で相手が取ったのとまったく同じ数の石を取ることが禁じられていることです。 プレイヤーが自分の番に正当な手を打てなかった場合、そのプレイヤーは負けます。 

タスクは、独立したゲーム構成ごとに、最初のプレーヤーが強制的に勝利するかどうか、または両側からの最適なプレイを前提として 2 番目のプレーヤーが強制的に勝利できるかどうかを判断することです。 

この制約では、最大 10 個のテスト ケースが許可され、N は最大 5000 になります。これは、おそらく最後の手のサイズを追跡するための追加の状態ディメンションを備えた、石の数に対する動的プログラミング ソリューションを強く示唆しています。 テスト ケースごとの 3 次または高次 2 次の解は原則として許容されますが、N または K を超える指数関数は遅すぎます。 

「禁じられた最後の手」ルールから、微妙な特殊なケースが発生します。 残りの石に基づいてポジションが勝っているかどうかだけを追跡する単純なアプローチでは不十分です。 たとえば、N=4、K=3 のような小規模な構成では、最適なプレイは最後に取られた内容に大きく依存し、それを無視すると、前の手の制約に応じて同じパイル サイズでも勝ったり負けたりする可能性があるため、誤った結論につながります。 

## アプローチ

 ゲームの直接総当たりモデルでは、状態を (n, last) として定義します。ここで、n は残りの石、last は前のプレイヤーが取った石の数です。 この状態から、現在のプレイヤーは、i = last を除く 1 から K までのすべての動き i を試み、(n - i, i) に遷移します。 何らかの手が相手の負け状態につながる場合、現在の状態は勝ちです。 

この定式化は正しいですが、単純に実装すると、それぞれに最大 K 個の遷移を含む O(NK) 状態が作成され、テスト ケースごとに O(NK^2) になります。 N、K が 5000 までの場合、これは最悪の場合 10^11 回の演算に相当し、制限をはるかに超えています。 

重要な構造的観察は、遷移は各子状態が負けているか勝っているかのみに依存し、「最後の手を取ることができない」という制約は状態ごとに 1 つのオプションのみを除外することです。 遷移をそれぞれの最後のものに対して独立して再計算する代わりに、各 n 個と考えられる最後のそれぞれに対して、少なくとも 1 つの勝ち手が存在するかどうかを事前計算できます。 これは、n ごとに 1 から K までのすべての動きのカウントまたはブール値を維持し、禁止された動きを減算することによって加速できます。 これにより、内部遷移が状態ごとに O(1) の償却作業に変わります。 

DP テーブル dp[n][last] を構築できます。dp[n][last] は、現在のプレイヤーが残り n 個の石で勝つことができ、最後の手が最後である場合に true になります。 すべての遷移はより小さい n に進むため、n を増加させながら値を計算します。 各状態について、i ≠ last であり、dp[n - i][i] が false となるような手 i が存在するかどうかを知りたいと考えます。 

各 n について、どの手が状態を失うことになるかを示す、動きに関するプレフィックス構造を維持できます。 これにより、遷移の前処理後に状態ごとに O(1) で有効な移動の存在を確認できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N·K²) | O(N・K) | 遅すぎる |
 | 移動除外による最適化された DP | O(N・K) | O(N・K) | 承認済み |

 ## アルゴリズムのチュートリアル

 DP テーブル dp[n][last] を定義します。ここで、last は前の移動サイズです (0 は開始時に制限がないことを意味します)。

1. すべての最後に対して dp[0][last] = false を初期化します。 石がなくなった場合、現在のプレイヤーは何も動けず、すぐに負けます。これが基本ケースです。 
2. n を 1 から N まで繰り返します。[0, K] 内のすべての最後の dp[n][last] を計算します。 
3. 固定状態 (n、最後) について、1 から K までのすべての可能な手 i を考慮します。i > n の場合、利用可能な以上の石を取得できないため、停止します。 
4. i == last の場合、移動 i はルールで禁止されているためスキップします。 
5. すべての有効な手 i について、dp[n - i][i] をチェックします。 dp[n - i][i] が false となるような手が存在する場合、相手を強制的に負け状態にできるため、dp[n][last] は true になります。 
6. そのような手が存在しない場合、dp[n][last] は false になります。 
7. テスト ケースの答えは dp[N][0] で、制限のない初期状態を表します。 

### なぜ効果があるのか

 DP 状態は、関連するすべての履歴を完全にエンコードします。合法性に関して重要なのは、残りのパイル サイズと最後の手だけです。 各遷移は厳密に n を減らすため、DP は非巡回です。 この繰り返しは、勝ち位置のミニマックス定義と正確に一致します。つまり、相手の負け状態につながる動きが存在する場合に限り、その状態は勝利していることになります。 到達可能な状態はすべて使用前に評価されるため、各 dp 値は計算時に正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        N, K = map(int, input().split())

        dp = [[False] * (K + 1) for _ in range(N + 1)]

        for n in range(1, N + 1):
            for last in range(K + 1):
                win = False
                upper = min(K, n)
                for take in range(1, upper + 1):
                    if take == last:
                        continue
                    if not dp[n - take][take]:
                        win = True
                        break
                dp[n][last] = win

        print(1 if dp[N][0] else 2)

if __name__ == "__main__":
    solve()
```DP テーブルはボトムアップで構築され、n - take は厳密に n より小さいため、dp[n][last] を評価するときにすべての状態 dp[n - take][take] がすでに計算されていることを保証します。 ネストされたループは繰り返しを直接反映します。 条件`take == last`前の動きを繰り返すことはできないというルールを強制します。 

初期状態では last = 0 が使用されます。これは、正当な動きと決して競合しないダミー値として機能します。 

## 実用的な例

 ### 例 1: N = 4、K = 2

 dp を増分的に計算します。 

| n | 最後 | 有効な動き | 勝つ？ |
 | --- | --- | --- | --- |
 | 1 | 0 | 1 | 本当 |
 | 2 | 0 | 1,2 | 本当 |
 | 3 | 0 | 1,2 | 本当 |
 | 4 | 0 | dp[3][1]、dp[2][2] に依存します | 本当 |

 n=4、last=0 の場合、1 を取ると dp[3][1] になります。 この構成チェーンでは dp[3][1] が相手に負けているため、最初のプレーヤーが勝ちの手を持ちます。 

これにより、最初のサンプル出力が 1 であることが確認されます。 

### 例 2: N = 4、K = 3

 再び dp[4][0] を計算します。 考えられる手は 1、2、3 です。 

結果を確認します。 

- dp[3][1]へのリードを1つ取得します
 - 2 つのリードを dp[2][2] に導きます
 - dp[1][3]まで3つのリードを取る

 これらの各状態では、最初のプレーヤーが勝利を強制できないように、次のプレーヤーが最適に応答できるため、dp[4][0] は false になります。 

| 移動 | 次の状態 | 結果 |
 | --- | --- | --- |
 | 1 | dp[3][1] | 相手のパスに勝つ |
 | 2 | dp[2][2] | 相手のパスに勝つ |
 | 3 | dp[1][3] | 相手のパスに勝つ |

 したがって、後者のプレイヤーが勝ちます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、K が N より大きい場合です。その状況では、n が減少するにつれて、利用可能な手が動的に縮小します。 DP はこれを正しく処理します。`upper = min(K, n)`無効な動きを決して考慮しないようにします。 たとえば、n = 3 および K = 5 では、1 から 3 までの移動のみが考慮されます。 

もう 1 つの特殊なケースは、最後の手の制限によって唯一の可能な手が排除される場合です。 たとえば、n = 2、K = 2、last = 1 の場合、move 2 のみが有効です。 DP は残りの法的移行のみを正しく評価するため、無効なオプションが原因で州が誤って勝利とマークされることはありません。 

3 番目のエッジ ケースは、ゲームの開始時に発生し、last = 0 になります。0 は有効なテイク値ではないため、これはいかなる動きも除外してはなりません。 初期化では、初期状態からのすべての移動を許可することでこれを保証します。
