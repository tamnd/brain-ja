 ## 解決策
 ## 問題の理解

 正の整数のシーケンスが与えられ、三角形を形成できる要素の 3 倍が決して含まれないという意味で、空ではないサブシーケンスが「安全」であるものがいくつあるかを数えたいとします。 

トリプルは、次のようにソートした後、三角形とみなされます。$a \le b \le c$、満足です$a + b > c$。 重要な点は、連続したセグメントではなくサブシーケンスを選択しているため、ギャップのある要素を選択でき、相対的な順序のみを考慮しているということです。 

タスクは、選択された 3 つの要素がこの三角形条件を満たさないすべてのサブシーケンスをカウントすることです。 

制約$n \le 7000$指数関数的なものはすでに除外されています$n$、すべてを列挙するなど$2^n$後続。 平$O(n^2 \log n)$または$O(n^2)$境界線にありますが許容範囲です。 これは、値に対する何らかの構造を使用して段階的に更新できるものに問題を縮小する必要があることを強く示唆しています。 

微妙な問題がすぐに現れます。三角形の形成は、位置ではなく、値の相対的な順序にのみ依存します。 これは、並べ替えまたは値に基づくグループ化が中心となる可能性が高いことを意味します。 

単純な罠は、ローカル制約またはペアごとの制約をチェックするだけで十分であると想定することです。 たとえば、2 つの小さな要素が 3 番目の要素を超えるトリプルを避けるだけで十分だと思うかもしれませんが、サブシーケンスでは遠く離れた要素を選択して任意に結合する可能性があるため、ローカル チェックは失敗します。 

もう 1 つのよくある間違いは、これを「条件を形成する 3 つの増加インデックスがない」ように扱うことです。三角形の条件は純粋に数値であり、位置を完全に無視するため、これは正しくありません。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのサブシーケンスを列挙し、有効な三角形のトリプルが含まれているかどうかを確認します。 サブシーケンスごとに、すべてを調べる必要があります。$\binom{k}{3}$トリプルを並べ替えて、不等式をテストします。 あるので$2^n$後続の場合、このアプローチはすぐに実行不可能になります。$n = 30$、ましてや$7000$。 ボトルネックは、サブシーケンスの指数関数的な増加です。 

重要な観察は、三角形条件がトリプルに対して完全にローカルであり、値のみに依存するということです。 選択したサブシーケンスを並べ替えると、「三角形が存在しない」という条件により、強い構造上の制限が課せられます。つまり、大きな要素を多数の小さな要素でサポートすることはできません。 実際、並べ替えられた選択された値の観点から考えると、違反は、合計が大きな要素を超える小さな要素のペアによって判断されます。 

これは視点を逆転させることを示唆しています。 サブシーケンスをチェックする代わりに、新しい要素の追加によって不正なトリプルが許可されるかどうかを追跡しながらサブシーケンスを構築することを検討します。 重要な構造的洞察は、三角形のないセットは、要素が並べ替えられるときに、すべての要素が大きすぎて、選択された 2 つの小さな要素で「カバー」できない制約セットのように動作するということです。 

これにより、対話の制限されたウィンドウを使用して、ソートされた値に対する DP として問題を再解釈することができます。 なぜなら$n$十分に小さいです$O(n^2)$、要素間のペアリング制約に基づいて遷移を維持できます。 

「2 の合計に基づく 3 つの形成条件がない」を強制する標準的な方法は、サブシーケンスの最大の要素を修正するたびに、残りの選択された要素がそれに対するペアごとの合計制約を満たさなければならないことを保証することです。 これは当然、ペアを検討し、最後に選択された 1 つまたは 2 つの要素を記述する特定の「状態」を持つ有効なサブシーケンスがいくつ存在するかを維持することにつながります。 

結果として得られる DP は、選択された要素間のどのペアも後で選択された要素を超えないことを保証する追跡サブシーケンスに帰着します。 これにより、禁止されたパターンが、並べ替えられた順序での管理可能な移行に折りたたまれます。

 ## アルゴリズムのチュートリアル

 三角形の条件は相対的な大きさのみに依存し、並べ替えによって構造化された方法で妥当性を推論できるため、最初にシーケンスを並べ替えます。 

次に、要素の昇順でサブシーケンスを構築する動的プログラミングを使用します。 

1. 配列を降順でない順に並べ替えます。 これにより、サブシーケンスを拡張するときに、以前のすべての要素が新しい要素以下になることが保証され、三角形条件の推論が容易になります。 
2. 最後に選択した 1 つまたは 2 つの要素によってサブシーケンスを追跡する DP 状態を定義します。 多くても 2 つ必要なのは、どの三角形条件にも 3 つの要素が含まれており、並べ替えられたサブシーケンス内の最大の要素が常に三角形を完成させる最後の候補になるためです。 
3. DP を空のサブシーケンスで初期化します。三角形には 3 つの要素が必要なので、単一要素のサブシーケンスは常に有効です。 
4. 各要素について$x$ソートされた順序で、それをスキップするか含めるかを決定します。 スキップすると、既存の状態がすべて保持されます。 これを含めるには、DP 状態ですでに暗黙的に表現されているペアと三角形を形成できるかどうかを確認する必要があります。 
5.追加する場合$x$、最後の要素を表す状態を更新します。 最後に選択した 2 つの要素によってインデックス付けされた DP を維持する場合、次のように追加します。$x$新しいペアを形成しますが、ペアが存在しないことを確認する必要があります。$(a, b)$部分列は満たす$a + b > x$。 配列はソートされているため、DP 遷移の境界ペアのみをチェックするだけで十分です。 
6. すべての要素を処理した後、すべての有効な空でないサブシーケンスを合計して、すべての DP 状態を累積します。 

### なぜ効果があるのか

 正確かどうかは、シーケンスがソートされるときに、三角形がその最大の要素によって一意に決定されるという事実にかかっています。 違反が存在する場合は、最大の要素が存在する必要があります$c$トリプルでは、​​前の 2 つの要素が$a, b$満足する$a + b > c$。 要素を昇順に処理し、そのようなペアがより大きな要素と共存しないようにすることで、無効なトリプルが決して形成されないことを保証します。 禁止された構成は、最新の要素と、ソートされたサブシーケンス内の最後の 2 つの関連貢献者との間の相互作用にのみ依存するため、DP 状態で十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    # dp[i][j] = number of valid subsequences whose last two elements are i, j indices
    # We compress values by index; we also allow "no second element" as -1 state.

    dp = [[0] * n for _ in range(n)]
    single = [0] * n

    ans = 0

    for i in range(n):
        x = a[i]

        new_dp = [[0] * n for _ in range(n)]
        new_single = single[:]

        # start new subsequence with x
        new_single[i] = (new_single[i] + 1) % MOD

        # extend single-element subsequences
        for j in range(i):
            new_dp[j][i] = (new_dp[j][i] + single[j]) % MOD

        # extend pair states
        for j in range(i):
            for k in range(j):
                if a[k] + a[j] <= x:
                    new_dp[j][i] = (new_dp[j][i] + dp[k][j]) % MOD

        dp = new_dp
        single = new_single

        # add all states ending at i
        for j in range(i):
            ans = (ans + dp[j][i]) % MOD
        ans = (ans + single[i]) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```この実装は、ソートされた順序で最後に選択された 1 つまたは 2 つの要素によってサブシーケンスを明示的に追跡することに依存しています。 の`single`配列は各インデックスで終わるサイズ 1 のサブシーケンスをカウントします。`dp[j][i]`最後の 2 つの要素が次のようなサブシーケンスをカウントします。`a[j]`そして`a[i]`。 

新しい要素を処理するとき`i`では、部分的に更新された状態を再利用しないように、最初に新しい DP コンテナを作成します。 新しいサブシーケンスを開始することを常に許可します。`a[i]`。 次に、以前のすべての単一要素サブシーケンスをペアに拡張します。 最後に、追加する場合にのみ既存のペアを拡張します。`a[i]`三角形を作成しません。これは検証によってチェックされます。`a[k] + a[j] <= a[i]`。 

最終的な答えは、各位置で終わるすべての有効な状態から累積されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての値が同一である場合です。たとえば、`[5, 5, 5, 5]`。 どのトリプルも三角形を形成します。$5 + 5 > 5$。 アルゴリズムでは、サイズが 2 以下のすべてのサブシーケンスがカウントされ、それより大きなサブシーケンスはすべて除外されるようにする必要があります。 DP では、ペア状態を拡張しようとすると条件チェックに失敗するため、正しい組み合わせ数と一致するシングルトンとペア​​だけが生き残ります。 

もう 1 つのエッジ ケースは、次のように値が指数関数的に増加する場合です。`[1, 2, 4, 8, 16]`。 2 つの小さい値の合計が大きい値にならないため、三角形は存在しません。 DP は、不等式以降のすべての遷移を許可します。`a[k] + a[j] <= a[i]`常に成り立つので、答えは空ではないすべての部分列になります。$2^n - 1$、アルゴリズムが正しく蓄積します。 

最後のエッジケースは、次のような大きな外れ値が混在した小さな値が繰り返されることです。`[1, 1, 1, 1000]`。 可能な三角形のみが小さな値を含みますが、1000 に達するには小さすぎるため、大きな要素によって無効なトリプルが作成されることはありません。 DP は、ペアの合計を最新の要素に対して常にチェックすることで、これらの寄与を明確に分離します。
