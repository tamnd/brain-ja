 ## 解決策
 ## 問題の理解

 私たちはパーティーに座っている n 人の友人のセットを与えられ、それぞれが独自の好みの飲み物を持っています。 カズは各友人にちょうど 1 杯の飲み物を割り当て、サイズ n の順列を形成します。 正しい飲み物をすぐに受け取る友人もいれば、そうでない友人もいます。 

興味深いのは、この最初の割り当ての後に何が起こるかです。 すでに正しい飲み物を持っている人はシステムから離れます。 まだ不満を抱いている残りの人々は、飲んだ飲み物をすべて共用プールに戻しました。 これらの飲み物はランダムにシャッフルされ、残りの人々に再分配されます。 繰り返しになりますが、たまたま正しい飲み物を受け取った人は退場し、このプロセスが繰り返されます。 これは誰も残らないまで続きます。 

制御するよう求められる数量は、これらのシャッフル ラウンドの予想数です。 私たちは飲み物の最初の割り当てを選択することができますが、このランダムな「シャッフルによる修復」プロセスの繰り返しにかかる時間を予想どおり最大化したいと考えています。 

キー入力は参加者の数である n だけです。 出力は 2 つの部分で構成されます。1 つは予想されるラウンドの最大可能数を表す実数、もう 1 つはドリンクがどのように最初に割り当てられるかを説明する順列です。 

n ≤ 1000 という制約は、ランダム性を明示的にシミュレートしたり、指数構造を考慮したりする解は直ちに実行不可能であることを意味します。 O(n^2) の構築でも問題ありませんが、閉形式構造が存在する場合、繰り返しの確率的シミュレーションや順列にわたる動的状態を伴うものは遅すぎるか、概念的に不要になります。 

n = 1 の場合、微妙なエッジ ケースが発生します。自分の飲み物を受け取ったのが 1 人だけの場合、その人はすぐに立ち去り、プロセスは 0 ラウンドで終了します。 「常に少なくとも 1 つのラウンドがある」という単純な仮定は、ここでは失敗します。 

n = 2 の場合、構造は有益になります。 両方の人が入れ替わる場合、次のシャッフルで両方がすぐに解決されるため、プロセスはちょうど 1 回のシャッフル ラウンドで終了します。 これは、初期順列の構造がプロセスの開始時にアクティブな参加者の数を直接決定し、この初期状態が答えを支配することをすでに示唆しています。 

## アプローチ

 ブルートフォースの観点は、順列を修正し、説明された確率過程に基づいて予想されるラウンド数を計算しようとすることから始まります。 k 個の残りの参加者の状態については、一様なランダム順列が k 個の項目に適用されることをシミュレートし、出現する固定点の数を数え、それらを削除して続行します。 たとえすべての n を評価して、1 つの順列に対する期待値を効率的に計算できたとしてもです。 順列は不可能です。 

重要な単純化は、初期順列の役割をプロセスのランダム性から分離することによって実現します。 最初の割り当ての後、重要なのは最初に何人の人が「間違っている」かということだけです。後続の各ラウンドでは、残りのセットに新しい一様なランダム順列を適用することによって構造が完全に破壊されるためです。 誰が間違っているかは関係なく、残りのセットのサイズだけが重要です。 

重要な確率的事実は、k 要素の一様ランダム順列では、k ≥ 1 の場合、期待される固定点の数は常に正確に 1 であるということです。これは、少なくとも 1 人の参加者が残っているすべてのラウンドで、そのラウンドから抜ける人の期待数は 1 であることを意味します。 

したがって、システム内の k 人から開始した場合、システムが空になるまで、ラウンドごとのアクティブな参加者の数の予想される減少は毎回 1 です。 これにより、期待されるラウンド数は k になります。

Therefore, the entire problem collapses into maximizing k, the number of people who are initially wrong. This is achieved by minimizing the number of fixed points in the initial permutation. The best possible permutation is a derangement, where no index i satisfies p[i] = i, so k = n.

 ## アルゴリズムのチュートリアル

 1. n が 1 に等しい場合、1 のみを含む順列を出力し、期待値を 0 に設定します。唯一の参加者が既に正しいため、プロセスは空から開始され、シャッフルは発生しません。 
2. n が 1 より大きい場合は、固定点を持たない順列を作成します。 単純な構造は、すべてのインデックスを 1 位置ずつシフトし、i を i + 1 に送信し、n を 1 に送信することです。これにより、すべての友人が最初に間違った飲み物を飲むことが保証されます。 
3. 予想されるラウンド数を n として出力します。 This follows because all n participants begin in the exchange process and the expected number of participants removed per round is always 1.
 4. 構築された順列を出力します。 

The important design choice is ensuring zero fixed points initially. すべての固定点は交換プロセスにまったく参加しない参加者であるため、固定点はすぐに初期アクティブ セットを減らし、予想されるラウンド数を厳密に減らします。 

### なぜ効果があるのか

 Let k be the number of people who do not initially receive their correct drink. まさに、交換プロセスに参加する参加者です。 すべてのラウンドでは、履歴に関係なく、残りのセットが均一にランダムに再シャッフルされるため、少なくとも 1 人が残っている限り、ラウンドで退場する人の期待数は常に 1 人になります。 By linearity of expectation, the total expected number of rounds is exactly k. Since k cannot exceed n, the maximum is achieved when k = n, which happens exactly when the permutation is a derangement.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())

if n == 1:
    print("0.0")
    print(1)
    exit()

# build derangement: shift by 1
p = list(range(2, n + 1)) + [1]

print(float(n))
print(*p)
```最初のステップでは、交換プロセスが不可能な縮退ケースを処理します。 より大きなすべての n について、この構築では、単純な巡回シフトを使用して、固定小数点を使用しない順列が保証されます。 どのような混乱も最適であるため、これで十分です。 

出力された値は単純に浮動小数点形式に変換されます。 初期参加を最大限に確保すること以外に、構造への依存はありません。 

ここでよくある間違いは、プロセスをシミュレートしたり、確率を明示的に計算しようとしたりすることです。 重要なのは、プロセスがラウンドごとに「ランダム性をリセット」し、システムが履歴ではなく現在の設定サイズのみに依存するようにすることです。 

## 実用的な例

 n = 3 の順列 [2, 3, 1] を考えます。 

| ラウンド | アクティブ セットのサイズ | 予想される削除 | 残り |
 | --- | --- | --- | --- |
 | 0 | 3 | - | 3 |
 | 1 | 3 | 1 | 2 |
 | 2 | 2 | 1 | 1 |
 | 3 | 1 | 1 | 0 |

 このトレースは、システムが空になるまで、各ラウンドで 1 人の参加者が予想通りに削除されることを示しています。 初期サイズは、予想されるラウンド数を直接決定します。 

n = 1 で順列 [1] の場合、システムは空から開始されます。 

| ラウンド | アクティブ セットのサイズ | 予想される削除 | 残り |
 | --- | --- | --- | --- |
 | 0 | 0 | - | 0 |

 これにより、シャッフルが発生せず、予想されるラウンド数がゼロであることが確認されます。 

## 複雑さの分析

 | --- | --- | --- |
 | 時間 | O(n) | 単純な巡回置換を構築する |
 | スペース | O(n) | 順列を保存する |

 制約では最大 1000 個の要素が許可されるため、線形構造で十分です。 出力順列の構築以外に必要なシミュレーションや反復プロセスはありません。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(sys.stdin.readline().strip())

    if n == 1:
        return "0.0\n1\n"

    p = list(range(2, n + 1)) + [1]
    return f"{float(n)}\n" + " ".join(map(str, p)) + "\n"

# provided sample
assert run("2\n") == "2.0\n2 1\n"

# custom cases
assert run("1\n") == "0.0\n1\n", "minimum case"

assert run("3\n") == "3.0\n2 3 1\n", "small derangement"

assert run("5\n") == "5.0\n2 3 4 5 1\n", "cyclic shift correctness"

assert run("1000\n").split("\n")[0] == "1000.0\n".strip(), "large n format check"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 0.0 / 1 | 基本ケースの正確性 |
 | 3 | 3.0 / 2 3 1 | 小サイクル動作 |
 | 5 | 5.0 / 2 3 4 5 1 | 一般的な混乱構造 |
 | 1000 | 1000.0 / 順列 | スケーラビリティとフォーマット |

 ## 特殊なケース

 n = 1 の場合、参加者が交換プロセスに参加しないため、アルゴリズムは自明な順列を出力し、正しく 0.0 を返します。 構築されたロジックは、混乱のステップを完全にバイパスします。 

n = 2 の場合、順列 [2, 1] により、両方の参加者が最初は不正確であることが保証されます。 1 回のシャッフルの後、両方が期待値で同時に解決され、正確に 2 人の参加者に相当する期待ラウンドが与えられます。 

n が大きい場合、循環シフトによって固定点が保証されなくなり、すべての参加者が最初からプロセスに貢献することになります。 プロセスでは期待されるラウンドごとに参加者が 1 人だけ削除されるため、期待されるラウンド数は n に比例して増加します。
