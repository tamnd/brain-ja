 ## 解決策
 ## 問題の理解

 長方形のブロックを垂直に積み重ねたものが与えられます。 各ブロックには、その幅に比例した固定の重みと、固定された水平位置間隔があります。$[l_i, r_i]$。 ブロックは順番に上下に配置され、各ブロックは傾くことなくその上にあるすべてのものを支えなければなりません。 

身体の状態は重心を使って表現されます。 どのブロックでも$i$、その上のすべてのブロックを考慮します。 それらの中心の加重平均を取ると、その点は水平スパンの内側にあるはずです。$[l_i, r_i]$。 これがすべてのブロックに当てはまる場合、タワーは安定しています。 

現在、1 つのブロックが欠落していますが、どれがどれであるかはわかりません。 ブロックした場合$k$が削除されると、その上のすべてのブロックは 1 位置ずつ下にシフトしますが、それらの相対的な順序と水平位置は変わりません。 削除された可能性のあるブロックごとに確認する必要があります$k$、結果として得られるタワーが安定しているかどうか。 

制約は次のとおりです$n = 2 \cdot 10^5$したがって、削除ごとに安定性を最初から再計算するソリューションは遅すぎます。 ナイーブ$O(n^2)$または$O(n^2 \log n)$アプローチは通らないでしょう。 

除去によって構造がどのように変化するかという点に微妙な問題が生じます。 中央のブロックが削除されると、その「サポート セット」がちょうど 1 つの要素を失うため、その上にあるブロックのすべての安定条件が変化します。 これは、位置ごとの独立したチェックを扱っているのではなく、グローバルにシフトするプレフィックス合計を扱っていることを意味します。 

よくある落とし穴は、削除されたブロックの周囲の局所的な状態のみが重要であると想定していることです。 それは誤りです。 低いブロックを削除すると、その上のすべてのチェックが影響を受けます。これらのチェックはすべて累積質量に依存するためです。 

もう 1 つの微妙な問題は、元のタワーがすでに不安定である可能性があることです。 プレフィックスが元の構成で無効であっても、削除されたブロックが違反している質量分布の一部である可能性があるため、後のブロックを削除すると修正される可能性があります。 

## アプローチ

 直接的なアプローチは、各削除を個別にシミュレートすることです。 固定削除ブロックの場合$k$、プレフィックスの合計を再構築し、影響を受けるすべてのブロックのすべての重心を再計算します。 各シミュレーションの費用$O(n)$、そしてすべての人のためにそれを行う$k$につながる$O(n^2)$、これは大きすぎます$n = 2 \cdot 10^5$。 

主な障害は、各安定性チェックが重みと重み付けされた位置のプレフィックス合計に依存していることです。 要素を削除すると、その後のすべての接頭辞が一貫した代数的な方法で変更されます。 これは、プレフィックス集計を一度事前計算して再利用する必要があることを示唆しています。 

ブロックの場合$i$、 させて：$$W_i = \sum_{j=1}^i w_j, \quad X_i = \sum_{j=1}^i w_j c_j$$どこ$w_j = r_j - l_j$そして$c_j = \frac{l_j + r_j}{2}$。 すると上の重心は$i$は：$$\frac{X_{i-1}}{W_{i-1}}$$ブロックを外した後$k$、任意のブロック$i > k$今見ると：$$\frac{X_{i-1} - X_k}{W_{i-1} - W_k}$$これにより、あらゆる安定条件が次のような有理不等式に変換されます。$X_k$そして$W_k$、しかし多くの点で評価されました$i$。 固定の場合$k$、すべてが必要です$i > k$満足するために：$$l_i \le \frac{X_{i-1} - X_k}{W_{i-1} - W_k} \le r_i$$それぞれの不等式は、次の線形制約に再配置できます。$X_k$、によってパラメータ化されます$W_k$。 固定用$i$、これは次のようになります。$$X_k \le (X_{i-1} - l_i W_{i-1}) + l_i W_k$$

$$X_k \ge (X_{i-1} - r_i W_{i-1}) + r_i W_k$$したがって、固定の場合$k$、からのすべての制約$i > k$の線形上限と下限のセットになります$X_k$、ここで、各境界は、次の時点で評価される行です。$W_k$。 これは当然、線形関数のエンベロープを維持し、ある点でそれらをクエリすることになります。 

加工できます$k$右から左へ。 左に移動するにつれて、インデックスからの制約を徐々に追加します$i > k$。 そういったものごとに$i$では、2 つの行を追加します。1 つは上限に寄与し、もう 1 つは下限に寄与します。 次に、ポイントがあるかどうかをクエリします。$(W_k, X_k)$実行可能領域内にあります。 

ラインとポイント クエリの動的な挿入をサポートするには、Li Chao ツリーが最適です。 

最後に、プレフィックスが次までであることを確認する必要もあります。$k-1$元の配列内の はすでに有効です。 これは、標準のプレフィックス チェックを使用して 1 回だけ事前計算できます。 プレフィックスが無効な場合、削除された要素が違反しているプレフィックス内にない限り、後の要素を削除しても以前の違反を修正することはできないため、変更されていない部分にプレフィックス違反が残らないように慎重に強制する必要があります。

 ## アルゴリズムのチュートリアル

 各接頭辞が合計質量と合計モーメントの固定表現を持つように、重量と加重中心の接頭辞の合計を構築します。 

また、元の構成の各プレフィックスが安定性を満たしているかどうかも計算します。 これにより、すでに無効なプレフィックスをそのまま残す削除を拒否する方法が得られます。 

次に、2 つの Li Chao 構造 (上限用と下限用) を維持しながら、インデックスを右から左に処理します。 各構造体は変数に線形関数を格納します$W_k$でクエリを実行します。$W_k$現場での実現可能性を評価する$k$。 

### ステップ

 1. 重量を計算する$w_i = r_i - l_i$そして中心$c_i = \frac{l_i + r_i}{2}$。 プレフィックス配列の構築$W_i$そして$X_i$。 
2. プレフィックス センター チェックを使用して、元のタワーのプレフィックス安定性を事前計算します。 これにより、どのプレフィックスが削除前にすでに無効になっているかがわかります。 
3. 反復する$k$から$n$まで$1$、空に初期化された 2 つの Li Chao ツリーを維持します。 
4.加工前$k$、インデックスからの制約を挿入します$k+1$両方のリーチャオツリーに。 各指数は、再配置された安定性の不等式から導出される 2 つの直線に寄与します。 
5. 両方の構造を次の場所でクエリします。$W_k$。 上部の構造は、最大許容境界を与えます。$X_k$、そして下の構造は最小許容限界を与えます。 
6. もし$X_k$クエリされた間隔とプレフィックス条件の範囲内にあります$k-1$有効である場合は、回答を「はい」としてマークしてください。 
7. それ以外の場合は、「いいえ」とマークしてください。 

これが機能する主な理由は、すべてのサフィックス制約が次のもののみに依存するためです。$X_k$そして$W_k$、そのような依存関係はそれぞれ線形です。$W_k$。 これにより、将来のすべての実現可能性条件を線の集合として表現できるようになり、メンバーシップは 2 つのエンベロープの間に点が存在するかどうかをチェックすることに帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class LiChao:
    def __init__(self, xs):
        self.xs = sorted(set(xs))
        self.n = len(self.xs)
        self.INF = 10**30
        self.tree = [None] * (4 * self.n)

    def f(self, line, x):
        a, b = line
        return a * x + b

    def add_line(self, line, v, l, r):
        if self.tree[v] is None:
            self.tree[v] = line
            return

        mid = (l + r) // 2
        xl = self.xs[l]
        xm = self.xs[mid]
        xr = self.xs[r]

        cur = self.tree[v]

        if self.f(line, xm) > self.f(cur, xm):
            self.tree[v], line = line, self.tree[v]

        if l == r:
            return

        if self.f(line, xl) > self.f(cur, xl):
            self.add_line(line, v * 2, l, mid)
        else:
            self.add_line(line, v * 2 + 1, mid + 1, r)

    def query(self, x, v, l, r):
        if v >= len(self.tree) or self.tree[v] is None:
            res = -self.INF
        else:
            res = self.f(self.tree[v], x)

        if l == r:
            return res

        mid = (l + r) // 2
        if x <= self.xs[mid]:
            return max(res, self.query(x, v * 2, l, mid))
        else:
            return max(res, self.query(x, v * 2 + 1, mid + 1, r))

n = int(input())
l = [0] * n
r = [0] * n

w = [0] * n
c = [0] * n
W = [0] * (n + 1)
X = [0] * (n + 1)

coords = []

for i in range(n):
    li, ri = map(int, input().split())
    l[i], r[i] = li, ri
    w[i] = ri - li
    c[i] = (li + ri) / 2
    coords.append(w[i])

for i in range(n):
    W[i + 1] = W[i] + w[i]
    X[i + 1] = X[i] + w[i] * c[i]

bad_prefix = [False] * (n + 1)
for i in range(2, n + 1):
    cm = X[i - 1] / W[i - 1]
    if not (l[i - 1] <= cm <= r[i - 1]):
        bad_prefix[i] = True

pref_ok = [True] * (n + 1)
for i in range(2, n + 1):
    pref_ok[i] = pref_ok[i - 1] and not bad_prefix[i]

coords += W[1:]

upper = LiChao(coords)
lower = LiChao(coords)

ans = ["NO"] * n

def add_constraints(i):
    Wi = W[i]
    Xi = X[i]

    li = l[i]
    ri = r[i]

    A_upper = Xi - li * Wi
    A_lower = Xi - ri * Wi

    upper.add_line((li, A_upper), 1, 0, upper.n - 1)
    lower.add_line((ri, A_lower), 1, 0, lower.n - 1)

for k in range(n, 0, -1):
    if k < n:
        add_constraints(k)

    if not pref_ok[k - 1]:
        continue

    Wu = W[k - 1]
    Xu = X[k - 1]

    hi = upper.query(W[k], 1, 0, upper.n - 1)
    lo = lower.query(W[k], 1, 0, lower.n - 1)

    if lo <= X[k] <= hi:
        ans[k - 1] = "YES"

print("\n".join(ans))
```プレフィックス配列$W$そして$X$質量分布全体をエンコードすることで、すべての質量中心の計算が単純な減算に減ります。 Li Chao 構造はすべての接尾辞由来の線形制約を維持するため、各クエリは候補点が将来のすべての安定条件を同時に満たすかどうかをチェックします。 

実装の微妙な詳細は、すべての比較が浮動中心に依存していることです。$c_i$。 厳密なコンテストの実装では、すべての入力が整数であり、中間点は一貫して分数として表現できるため、精度の問題を回避するために、これを 2 倍の整数演算に置き換える必要があります。

 ## 特殊なケース

 重要なエッジケースは、削除されたブロックが上部近くにある場合です。 この状況では、ほとんどすべてのプレフィックス制約が変更されないため、プレフィックスの有効性だけが答えを支配します。 Li Chao の評価前にプレフィックスの実現可能性が独立してチェックされるため、アルゴリズムはこれを処理します。 

すべてのブロックが同じ幅と対称間隔を持っている場合、別のエッジ ケースが発生します。 このような場合、重心は除去しても不変のままであり、Li Chao エンベロープはほぼ同一の線に崩壊します。 各制約が厳密な分離ではなく等価性チェックに限定されるため、アルゴリズムは引き続き機能します。 

最後の微妙なケースは、スタックの一番下で削除が行われる場合です。 ここでは、ブロックの 1 つおきにプレフィックスが変更され、すべてのサフィックス制約がアクティブになります。 Li Chao 構造が最大限に活用されており、正確さは挿入されたすべての線形境界の一貫した維持に依存しており、右から左へのスイープによってそれが保証されます。
