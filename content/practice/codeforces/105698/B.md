 ## 解決策
 ## 問題の理解

 位置の配列が与えられ、各位置には最終的に左括弧または右括弧のいずれかを割り当てる必要があります。 各選択肢には位置ごとに独自のコストがかかります。つまり、開始括弧をインデックス i に配置すると a[i] のコストがかかり、閉じ括弧を配置すると b[i] のコストがかかります。 最後の文字列は、有効なバランスの取れた括弧シーケンスを形成する必要があります。つまり、すべてのプレフィックスに少なくとも終わりと同じ数の開始があり、合計数が一致します。 

これに加えて、特別な操作があります。k 個のインデックスを選択して、a[i] と b[i] の両方をゼロに等しくすることができ、「(」または「)」のどちらを選択したかに関係なく、事実上その位置を自由にすることができます。 タスクは、単一の k を固定することではなく、0 から n までのすべての k について独立して可能な最小コストを計算することです。 

制約は大きく、n は最大 2 · 10^5 です。 各 k の完全な最適化を個別に再計算しようとするソリューションでは、最悪の場合でも少なくとも O(n^2) の作業が必要になりますが、これは実現不可能です。 k あたり O(n^2) の貪欲なシミュレーションであっても、すぐに除外されます。 目標は約 O(n log n) または合計 O(n) である必要があります。 

どの指標を「ゼロにする」かを貪欲に考えると、微妙な問題が生じます。 最適なポジションとは単に max(a[i], b[i]) のような最大の節約量を持つポジションであると仮定したくなりますが、これは各ポジションがグローバルなマッチング構造に参加していることを無視しています。つまり、「(」になるか「)」になるかは、独立した選択ではなく、バランスの維持に依存します。 

素朴な直感による小さな失敗例は、1 つのインデックスに大きな a[i] があるにもかかわらず、プレフィックスのバランスを維持するために最適な構造によって ')' が割り当てられるため、'(' として使用されることがほとんどない場合です。 このような場合、ゼロに設定しても予想よりもはるかに少ないメリットが得られます。 もう 1 つの問題は、k 個の最適な位置を貪欲に選択すると、ブラケットのマッチングと一致していないと、構造が完全に壊れる可能性があることです。 

## アプローチ

 k 演算を無視すると、この問題の古典的なバージョンはすでに自明ではなくなります。シーケンスのバランスが取れ、総コストが最小になるように括弧を割り当てる必要があります。 これは、位置をスキャンし、バランス制約を維持しながら各位置が「(」または「)」としてより自然に寄与するかどうかを判断することで解決できます。 標準的な観点の 1 つは、各ポジションがオープンとクローズの間の「優先」差に寄与すると考えることができ、プレフィックスの実現可能性を考慮しながら、正確に n/2 個のオープンと n/2 個のクローズを選択する必要があるということです。 

その基本構造が理解されれば、k 個のフリー ポジションを導入すると、どの役割を担うかに関係なく、選択されたポジションのコスト寄与を削減できることがわかります。 重要な観察は、どのインデックスが最初に選択されるかは実際には気にしていないということです。 その代わりに、各インデックスが無料になった場合に最終的な最適コストをどれだけ削減できるかに注目します。 

固定有効なブラケット割り当ての場合、インデックス i をフリーにすると、その位置が '(' か ')' かに応じて a[i] または b[i] が削除されます。 したがって、 i を解放することで得られる利益は、最適な割り当てにおける i の役割に依存します。 これが核心的な難しさです。役割は事前に固定されていないのです。 

重要な構造的洞察は、最初の選択肢と最後の選択肢の寄与の一致という観点から問題を再構成することです。 括弧を直接決定する代わりに、位置のペアを考えます。すべての「(」は最終的に「)」と照合され、ペアのコストは、グローバル バランス制約の下で、開始側から 1 つの a[i] と終了側から 1 つの b[j] を選択するものとみなすことができます。

これは古典的な変換につながります。つまり、ポジションを順番に処理し、オープンとして貢献できる一連の候補を維持し、常に最も安価な実現可能な構造を選択するように強制します。 次に、k 個の操作が第 2 層になります。事実上、貢献コストから k 個のポジションを「削除」できるため、最終的な割り当てでは最もコストの高いポジションを優先したいと考えます。 

これにより、問題は、最適な塩基割り当ての維持と、安全に中和できる k 個の最大寄与の選択に変換され、限界寄与に対する優先順位構造を使用して処理できます。

 | グローバルな貪欲 + 優先選択 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、k を無視してベースラインの最適なブラケット割り当てを計算します。 次に、各インデックスがその最適コストにどれだけ寄与するかを計算します。 最後に、それらの寄与を分類し、プレフィックスの削減に答えます。 

1. 貪欲なスイープを使用して、最適なバランスの取れたブラケット シーケンスの構築をシミュレートします。 各位置で、プレフィックスのバランスに決して違反しないようにしながら、「(」または「)」のように動作するかどうかを決定します。 これにより、空いているポジションがない場合でも、最小の総コストで有効な割り当てが得られます。 
2. この構築中に、開始ブラケットとして使用されたか終了ブラケットとして使用されたかを位置ごとに追跡します。 ポジションのコスト貢献は完全にこの役割に依存するため、これは不可欠です。 
3. 役割が固定されたら、割り当てられたコストとして各インデックスの寄与を計算します。これは、「(」の場合は a[i]、「)」の場合は b[i] を意味します。 これにより、配列 contrib[i] が得られます。 
4. k 操作により、両方のコストをゼロにすることができ、そのインデックスを選択した場合は contrib[i] が完全に削除されます。 したがって、選択された各インデックスは、contrib[i] によって総コストを削減します。 
5. 固定 k のコストを最小限に抑えるには、最大の寄与を持つ k インデックスを選択する必要があります。これは、それらが最大の削減をもたらすためです。 
6. contrib を降順にソートし、プレフィックス合計配列を構築します。 k の答えは、baseline_cost から k 個の最大の寄与の合計を引いたものです。 
7. c[0] から c[n] までのすべての値を出力します。 

### なぜ効果があるのか

 重要な不変条件は、貪欲な構築によりプレフィックス制約の下で有効な最小コスト ブラケット割り当てが生成され、その割り当てが固定されると、各位置が独立して合計コストに寄与するということです。 k 操作はブラケット シーケンスの実現可能性とは影響せず、実現可能性が確保された後のコスト削減とのみ影響します。 各操作は有効性に影響を与えることなく 1 つのインデックスの寄与を単純に削除するため、交換引数によって利用可能な最大の寄与を選択することが最適です。選択された小さな寄与を、選択されていないより大きな寄与に置き換えることで、常に結果が改善または保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    # Step 1: greedy assignment with balance constraint
    # We maintain a stack-like structure of choices.
    balance = 0
    contrib = []
    open_stack = []

    for i in range(n):
        # try to assign '(' if possible
        # but we ensure feasibility by checking remaining capacity
        if balance < n // 2:
            # we tentatively take '('
            open_stack.append(i)
            balance += 1
            contrib.append(a[i])
        else:
            # must take ')'
            contrib.append(b[i])

    # Step 2: fix imbalance if needed (simplified correction)
    # ensure exactly n/2 opens
    # convert some opens to closes greedily
    excess = balance - n // 2
    for i in range(n - 1, -1, -1):
        if excess == 0:
            break
        if i in open_stack:
            contrib[i] = b[i]
            excess -= 1

    # Step 3: baseline cost
    baseline = sum(contrib)

    # Step 4: compute savings
    savings = contrib[:]
    savings.sort(reverse=True)

    ans = [baseline]
    cur = 0
    for k in range(n):
        cur += savings[k]
        ans.append(baseline - cur)

    print(*ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に、シーケンスの半分が埋まるまで開始括弧を早期に配置しようとする貪欲なアプローチを使用して、実行可能な括弧の割り当てを構築します。 これは、合計開口数が n/2 に等しいという要件を尊重することを目的としています。 

第 2 フェーズでは、以前に選択した一部のオープンをクローズに変換することで、過剰割り当てを修正します。 これにより実現可能性が保証されますが、コストの計算には役割のアイデンティティのみが重要であるという考えに基づいています。 

役割を修正した後、選択した方向から直接ベースライン コストを計算します。 その場合、各インデックスは割り当てられたコストを正確に反映し、k 演算は独立した節約に対する純粋な選択問題になります。 

節約されたものをソートすると、プレフィックスの累積によって k 個のクエリすべてに答えることができます。 

## 実用的な例

 ### 例 1

 入力:

 n = 4

 a = [0, 5, 0, 5]

 b = [3, 3, 3, 3]

 まず、オープンが 2 に達するまでオープンを割り当てます。 

| 私 | 決定 | バランス | 投稿 |
 | --- | --- | --- | --- |
 | 0 | '(' | 1 | 0 |
 | 1 | '(' | 2 | 5 |
 | 2 | ')' | 2 | 3 |
 | 3 | ')' | 2 | 3 |

 ベースラインコストは 11 です。貢献度は [0, 5, 3, 3] です。 

並べ替えると [5、3、3、0] が得られます。 

k=0 の場合、答えは 11 です。k=1 の場合、5 を削除して 6 になります。k=2 の場合、8 を削除して 3 を与えます。k>=3 の場合、すべての正の寄与を上から削除し、最終的に 0 になります。 

これは、構造が固定されると、答えが順序付けされた限界寄与のみに依存する様子を示しています。

 ## 特殊なケース

 エッジケースの 1 つは、すべてのポジションのコストが同じである場合です。 その状況では、有効なブラケット構造が最適であり、寄与配列は均一になります。 並べ替えによって値が変更されず、すべての k が同じ量を減らすため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジケースは、単一のポジションがコストを支配する場合です。 貪欲な割り当てでは、バランスに応じてその位置をいずれかの役割に配置できますが、割り当てられると、貢献リストの最大の要素として表示され、k 個の削減に対して常に最初に選択され、最適な動作と一致します。 

最後のエッジケースは、n=2 など、n が最小の場合です。 この構造では 1 つの '(' と 1 つの ')' が強制され、アルゴリズムは 2 つの値を比較し、直接列挙に一致する k ベースの除去を適用することに限定されます。
