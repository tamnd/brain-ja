 ## 解決策
 ## 問題の理解

 各セルに小文字が含まれる長方形のグリッドが与えられます。 カウントする有効なオブジェクトは、グリッド内のエッジで接続された正確に 13 個の個別のセルからなる単純なパスで、上下左右にのみ移動します。 このような道を歩きながら、訪問したセルの文字を順番に読み取って、13 文字の文字列を形成します。 

長さ 13 の任意の文字列を探しているわけではありません。この文字列は、長さ 13 の固定ターゲット単語、つまり「genshinimpact」の循環回転と一致する必要があります。つまり、ターゲット文字列を取得し、任意の位置数だけ左または右に回転すると、結果の文字列はパスから読み取られた文字のシーケンスと等しくなる必要があります。 

出力は、998244353 を法とした、このような単純なパスの数です。 

グリッド サイズは 500 x 500 まで大きくできるため、開始位置は最大 250,000 になります。 パスの長さは固定されており、非常に小さいため、これがこの問題を扱いやすくする唯一の構造上の制約になります。 長いパスを列挙したり、大規模なプルーニングを行わずにすべてのパスをグローバルに処理しようとするソリューションは合格しません。 

素朴な試みは、すべてのセルから DFS を開始し、深さ 13 のすべての単純なパスを探索することです。4 方向の移動であっても、これはあまりにも積極的に分岐します。 理論上の上限は次のように動作します。$O(4^{13})$1 回の起動あたりの数はすでに膨大であり、250,000 回の起動を掛けると完全に不可能になります。 

素朴な考えを打ち破る主なエッジケースは、「13 はどこでも総当たり攻撃を実行できるほど小さい」という仮定です。 たとえば、正しい文字で埋められた 1 つの行であっても、慎重に制限しないと、有効なパスの組み合わせ爆発が発生する可能性があり、アルゴリズムは依然として、ターゲット文字列から既に分岐しているすべての部分ウォークを列挙しようとします。 

2 番目の微妙な失敗モードは、早期に自己回避を無視することです。 拡張中ではなく最後にのみ再訪問をチェックする DFS は、ほとんどのブランチがすぐに「単純なパス」条件に違反するため、無効なプレフィックスを大量にカウントします。 

## アプローチ

 直接的な定式化は簡単です。セルごとに、長さ 13 の単純なパスをすべて構築しようとします。長さ 13 に達するたびに、収集された文字列がターゲット文字列の巡回シフトであるかどうかを確認します。 これは定義を正確に列挙しているため、正しいです。 

問題はパフォーマンスです。 密なグリッド内の長さ 13 の単純なパスの数は指数関数的に増加します。 13 は小さいですが、グリッドは十分に大きいため、部分的な DFS 状態の総数は膨大になります。 このアルゴリズムは重複する部分構造を繰り返し再計算するため、完全な深さに達するずっと前にコストが爆発的に増加します。 

重要な観察は、文字列には実際には自由がないということです。 DFS の各ステップで、次の文字はターゲット パターンによって完全に制約されます。 私たちは任意の道を探しているわけではありません。 パスが固定の 13 文字シーケンス (回転まで) に一致するかどうかをチェックしています。 これにより、問題は「すべてのパスを列挙してフィルターする」という問題から、「固定パターンのオートマトンで有効な遷移のみをたどる」という問題に変換されます。 

ターゲット文字列の 13 回転すべてを事前計算します。 有効なパスは、これらの回転のいずれかに正確に一致する必要があります。 DFS 中に深さ k にあるとき、現在のセルは、構築中のプレフィックスと一致する少なくとも 1 つのローテーションの k 番目の文字と一致する必要があります。 これにより、積極的な枝刈りが可能になります。セルが継続の可能性と一致しなくなるやいなや、ブランチ全体が破棄されます。 

ターゲットの長さは固定で小さいため、文字が回転の最初の文字と一致するすべての開始セルから深さ制限された DFS を実行できます。 再帰は、少なくとも 1 つの回転候補との互換性を維持するエッジに沿ってのみ続行されます。 自己回避は、訪問されたアレイに対して強制されます。 

これにより、検索は深さ 13 の制約付きツリーに変わり、文字の不一致によって分岐が大幅に枝刈りされます。 一般的なグリッドでは、分岐要素がすぐに崩壊するため、探索される状態の総数が管理可能になります。

 ## アルゴリズムのチュートリアル

 ターゲット単語とそのすべての回転を、深さ制限された検索をガイドする制約として扱います。 

1. 文字列「genshinimpact」を保存し、13 個の循環回転をすべて生成します。 各ローテーションは、有効なパスの候補ターゲット シーケンスを表します。 これは、どの回転でも一致として受け入れられるため、必要です。 
2. グリッド内のすべてのセルを反復処理します。 セルの文字が回転の最初の文字として表示されない場合は、その文字を完全にスキップします。 これにより、不必要な DFS の起動が削減されます。 
3. 有効な開始セルごとに、最大 13 の長さのパスを構築する DFS を実行します。訪問済みの配列を維持して、パスが単純なままであること、つまりセルが再訪問されないことを保証します。 
4. DFS 深さ k で、4 つの近隣のそれぞれに移動することを検討します。 移動は、隣接セルの文字が少なくとも 1 回の回転の k 番目の文字と一致し、それまでに構築されたプレフィックスと一貫性がある場合にのみ許可されます。 実際には、すべてのローテーションをチェックし、プレフィックスのアライメントが維持されているローテーションのみを保持します。 
5. 深さ 13 に到達すると、完全な回転一貫性のあるパスの一致に成功したため、答えがインクリメントされます。 

重要な枝刈りは暗黙的に行われます。どのローテーションにも一致しない DFS ブランチは直ちに破棄されるため、再帰によって無関係な文字列が探索されることはありません。 

### なぜ効果があるのか

 DFS の各ステップで、部分パスは、文字のシーケンスがそのプレフィックスと一致する場合にのみ、循環ローテーションのプレフィックスに対応します。 このアルゴリズムは、このプロパティを保持する状態のみを拡張します。 ローテーションは固定かつ有限であるため、完全な有効なパスは、プレフィックス長ごとに少なくとも 1 つのローテーションとの互換性を維持する必要があります。 したがって、有効なパスが破棄されることはなく、無効なパスは、ある位置で文字制約に違反するため、深さ 13 まで存続することはできません。 

これにより、不変条件が作成されます。アクティブな DFS 状態はすべて、ラベルが少なくとも 1 つの有効な回転ターゲット文字列のプレフィックスである部分的な単純パスに正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

TARGET = "genshinimpact"
L = len(TARGET)

# all rotations
rots = [TARGET[i:] + TARGET[:i] for i in range(L)]

r, c = map(int, input().split())
grid = [input().strip() for _ in range(r)]

# precompute which rotations expect which char at position k
pos_char = [dict() for _ in range(L)]
for i in range(L):
    for j in range(L):
        pos_char[i].setdefault(rots[j][i], []).append(j)

vis = [[False] * c for _ in range(r)]
ans = 0

dirs = [(1,0), (-1,0), (0,1), (0,-1)]

def dfs(x, y, depth, active_rots):
    global ans
    if depth == L:
        ans += 1
        return

    # prune if no rotation remains valid
    if not active_rots:
        return

    for dx, dy in dirs:
        nx, ny = x + dx, y + dy
        if nx < 0 or nx >= r or ny < 0 or ny >= c:
            continue
        if vis[nx][ny]:
            continue

        ch = grid[nx][ny]

        new_rots = []
        for rid in active_rots:
            if rots[rid][depth] == ch:
                new_rots.append(rid)

        if not new_rots:
            continue

        vis[nx][ny] = True
        dfs(nx, ny, depth + 1, new_rots)
        vis[nx][ny] = False

# start DFS
for i in range(r):
    for j in range(c):
        start_rots = []
        for rid in range(L):
            if rots[rid][0] == grid[i][j]:
                start_rots.append(rid)

        if not start_rots:
            continue

        vis[i][j] = True
        dfs(i, j, 1, start_rots)
        vis[i][j] = False

print(ans % 998244353)
```DFS は、位置と深さだけでなく、パス プレフィックスが与えられた場合にどの回転がまだ実行可能であるかを追跡します。 これが核となる枝刈りメカニズムです。 訪問されたマトリックスは「単純なパス」要件を強制し、各ブランチを探索した後にバックトラッキングによってそれが復元されます。 

実装の微妙な詳細は、回転フィルタリングがすべてのステップで行われることです。 アクティブな回転セットを前に進めないと、互換性を最初から繰り返し再計算することになるため、定数係数が大幅に増加し、密なグリッドでの解が遅くなります。 

## 実用的な例

 小さなグリッドの例を考えてみましょう。```
g e n
s h i
n i m
```そして開始位置は`(0,0)`手紙付き`g`。 ターゲットの複数の回転が次から始まるため、最初はすべての回転がアクティブになります。`g`。 DFS は段階的に進み、移動するたびに、次に必要な文字に基づいて回転を制限します。 

| 深さ | ポジション | キャラクター | アクティブなローテーション |
 | --- | --- | --- | --- |
 | 1 | (0,0) | g | g | で始まるすべての回転
 | 2 | (0,1) | e | 2 番目の文字が e | である回転のみ
 | 3 | (0,2) | n | 回転はまだ接頭辞 "gen" と一致します |
 | 4 | (1,2) | 私 | さらにフィルタリングされた回転 |

 各ステップで無効な回転が削除され、最終的には回転が残らなくなるか、深さ 13 に到達します。 

このトレースは、アルゴリズムが任意のパスを探索しているのではなく、13 個の候補の固定セットでパス制約と交差し続けていることを示しています。 

次に、失敗したプレフィックスの例を考えてみましょう。```
g x ...
```深さ 2 で、文字のあるセルに入ると`x`、ターゲットの回転はありません`x`位置 1 にあるため、アクティブ セットは空になり、DFS はすぐに終了します。 このことは、剪定が非常に早い段階でも効果的であることを裏付けています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(r \cdot c \cdot 4^{13})$最悪の場合、実際には大幅に削減される | DFS の深さは 13 に固定されており、分岐は文字制約と回転フィルタリングによってカットされます。 
| スペース |$O(r \cdot c + 13)$| 訪問された配列と再帰スタックと回転の追跡 |

 理論上の限界はパス長が指数関数的ですが、ほとんどのグリッド パスは固定の 13 文字パターンに一致しないため、有効な分岐係数はすぐに崩壊します。 r、c が最大 500 の場合、このソリューションは、探索される状態空間を十分に小さく保つために積極的な枝刈りに依存します。 

## テストケース```python
import sys, io

MOD = 998244353

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    TARGET = "genshinimpact"
    L = len(TARGET)
    rots = [TARGET[i:] + TARGET[:i] for i in range(L)]

    r, c = map(int, input().split())
    grid = [input().strip() for _ in range(r)]

    sys.setrecursionlimit(10**7)
    vis = [[False]*c for _ in range(r)]
    dirs = [(1,0),(-1,0),(0,1),(0,-1)]
    ans = 0

    def dfs(x,y,d,active):
        nonlocal ans
        if d == L:
            ans += 1
            return
        if not active:
            return
        for dx,dy in dirs:
            nx,ny = x+dx,y+dy
            if nx<0 or nx>=r or ny<0 or ny>=c:
                continue
            if vis[nx][ny]:
                continue
            ch = grid[nx][ny]
            nxt = []
            for rid in active:
                if rots[rid][d] == ch:
                    nxt.append(rid)
            if not nxt:
                continue
            vis[nx][ny] = True
            dfs(nx,ny,d+1,nxt)
            vis[nx][ny] = False

    for i in range(r):
        for j in range(c):
            start = []
            for rid in range(L):
                if rots[rid][0] == grid[i][j]:
                    start.append(rid)
            if not start:
                continue
            vis[i][j] = True
            dfs(i,j,1,start)
            vis[i][j] = False

    return str(ans % MOD)

 ## 特殊なケース

 主なエッジ ケースは、回転の開始点には一致するが、その後すぐに発散する文字がグリッドに多数含まれる場合です。 このような場合、DFS は頻繁に起動しますが、ほぼすぐに終了します。 回転フィルタリングが 1 ～ 2 ステップ以内に空になり、より深い状態を探索せずに強制的に早期終了するため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、グラフ内にサイクルが存在するグリッドです。たとえば、すべての文字が同一である 2×2 ブロックです。 Visited 配列により、多くの幾何学的サイクルがあっても DFS がセルを再訪問することがなくなり、無限再帰が防止され、パスが単純に保たれます。 

最後のケースは、有効なパスは存在するが、非常にまばらな場合です。 少数の完全長パスのみが回転制約を満たす場合でも、アルゴリズムは、有効な回転一貫性のあるプレフィックスをどの段階でも削除せず、完全性を維持しながら無効な分岐を早期に積極的に破棄するため、依然としてそれらを見つけます。
