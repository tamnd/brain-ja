 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付いた n セットのファミリーを維持しています。 すべてのセットは同じように始まり、数字の 0 だけが含まれます。時間の経過とともに、範囲の更新が適用されます。 各更新では、インデックス l ～ r のセグメントが取得され、そのセグメント内のすべてのインデックス i に対して、セットの位置 i に特定の値が挿入されます。 挿入される値は、i がセグメントの左端点からどれだけ離れているかによって異なります。正確に i − l + 1 であるため、1 回の更新内で、追加された値は 1 から始まる連続ブロックを形成します。 

これらの更新に加えて、「位置 i のセットの mex は何ですか」という形式のクエリも尋ねられます。 mex は、そのセットに存在しない最小の非負の整数です。 

主な難点は、各更新が最大 n 個の要素に影響し、影響を受ける各セットが時間の経過とともに増大することです。 n と q はどちらも 5 × 10^5 まで大きくなる可能性があるため、セットに値を明示的に挿入するソリューションはすぐにメモリと時間の制限を超えます。 各要素には多くの挿入が蓄積される可能性があるため、セットを明示的に保存するだけでもコストがかかりすぎます。 

mex 操作では、微妙な構造も隠蔽されます。 各セットの初期値は常に 0 であるため、初期化後に mex が 0 になることはありません。 本当の問題は、1、2、3 などがいつ現れるかということです。 

単純なアプローチでは、重複する大きな範囲を繰り返し更新するなどの単純なシナリオが破綻してしまいます。 たとえば、1 1 n、1 2 n、1 3 n のような範囲を追加し続けると、各セットはすぐに整数の長いプレフィックスを蓄積し、セットをスキャンすることによるクエリごとの mex の計算は 2 次式になります。 

2 番目の微妙な落とし穴は、挿入される値が l に対する相対的な位置に依存することを忘れていることです。 2 つの異なる更新では、同じ数値を異なるインデックスに挿入できますが、それらは独立したイベントです。 これにより、更新を単純な「範囲 i に x を含むマークを付ける」として扱うという希望は台無しになります。 

本当の課題は、「i が値 i − l + 1 を受け取る」という条件をペア (i, value) に対する幾何学的制約に再解釈し、各整数が各位置にいつ存在するかを追跡することです。 

## アプローチ

 ブルートフォース手法は簡単です。更新ごとに、l から r までのすべての i を反復処理し、i − l + 1 をセット i に挿入します。 次に、そのセット内で欠損値が見つかるまで 0 から上方向にスキャンして mex クエリに答えます。 これは、定義を直接シミュレートするため、正しいです。 

ただし、コストは壊滅的です。 1 回の更新で O(n) セットに影響する可能性があり、各挿入は表現に応じて O(log n) かそれよりも悪くなります。 q の更新でこれは O(nq) になり、実現可能な限界をはるかに超えています。 mex クエリがまれな場合でも、各 mex チェックはセットあたり最大 O(n) 値をスキャンする可能性があり、問題を複雑にします。 

重要な観察は、集合について考えるのをやめ、代わりに各整数 k が各位置 i にいつ入るかを考えることです。 固定 k の場合、k を i に挿入するすべての更新を知りたいと考えます。 条件 i − l + 1 = k は、l = i − k + 1 と同等です。つまり、更新 [l, r] は、i が [l, r] にあり、かつ k = i − l + 1 ≤ r − l + 1 であるときに正確に (i, k) に影響します。再配置により、きれいな幾何学的制約が得られます。つまり、l = i − k + 1 から始まり、その範囲が i を含むほど十分に及ぶ更新が存在する場合に限り、k が i に追加されます。 

これにより、問題は、各ペア (i, k) について、ある更新間隔が導出点をカバーするかどうかの追跡に変換されます。 セットを維持する代わりに、派生した 2D 構造にわたるカバレッジを追跡します。 

次の単純化は、視点を逆転することです。 各 i にどの k が存在するかを尋ねる代わりに、各 k を求め、最終的に i が k を受け取るインデックスを求めます。 各更新では、k がシフトされたセグメント内のすべての i に寄与します。つまり、k は、更新境界から直接エンドポイントを計算できる i のセグメントに表示されます。 これにより、各値 k が i にわたる間隔の和集合に変わります。 位置 i の mex は、i が k の間隔セットでカバーされない最小の k になります。

これにより、問題は範囲更新に関する古典的な「最初にカバーされない層」クエリに変換され、セグメント ツリーを使用したオフライン スイープまたは値層の差分構造を使用して処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq + mex コスト) | O(n^2) 最悪 | 遅すぎる |
 | 最適 | O((n + q) log n) | O(n + q) | 承認済み |

 ## アルゴリズムのチュートリアル

 各値 k をインデックス i の範囲を定義するものとして扱います。 目標は、すべての i について、決してカバーされない最小の k を計算することです。 

1. 更新 (l, r) ごとに、一連のペア (i, k) を追加するものとして再解釈します。ここで、k の範囲は 1 から r − l + 1 および i = l + k − 1 です。これは、(i, k) 平面内の対角セグメントを表します。 それを明示的に反復する代わりに、固定 k ごとに i の連続間隔が誘導されることが観察されます。 
2. 固定 k の場合、どの更新が k に寄与するかを決定します。 i = l + k − 1 から、有効な寄与について i ∈ [l + k − 1, r] を導出します。 したがって、r ≥ l + k − 1 の場合、各更新はその k の i にわたる間隔に寄与します。これにより、k ごとの i 間隔のコレクションが生成されます。 
3. k を小さいものから大きいものまでスイープし、i に k が存在するかどうかをマークする i にわたる差分配列またはセグメント ツリーを維持します。 各 k は、その有効な間隔を「ペイント」します。 
4. 各 i について、i をカバーすることがまだ確認されていない最小の k を維持します。 これは、k を昇順に処理し、カバレッジをマークすることで実行できます。 初めて i が k によってカバーされるとき、それをその mex として記録できます。 
5. 範囲更新と first-zero クエリを備えたセグメント ツリーを使用するか、同等に各 i に対して現在の候補 mex へのポインタを維持し、カバレッジが確認された場合にのみそれを進めます。 

よりクリーンな実装は、1 に初期化された配列 mex[i] を維持し、指定された k のカバレッジをマークする更新を繰り返し適用し、カバーされている間 mex[i] を貪欲に進めることです。 

### なぜ効果があるのか

 各値 k は、インデックス上の間隔の単調ファミリーを独立して定義します。 位置 i は、それをカバーできなかった最初の k に等しい mex を持ちます。 カバレッジは時間の経過とともに追加されるだけで削除されないため、i が特定の k に対してカバーされると、その後のすべての推論に対してカバーされたままになります。 この単調性により、k を昇順に処理すると、以前の決定を再度検討する必要がなく、正しい最初の欠損値が得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    
    # For each k, store list of intervals [l, r] on i where k is added
    # We cap k by n+q safely since mex cannot exceed n+q+2 in this construction
    maxk = n + q + 5
    
    intervals = [[] for _ in range(maxk)]
    
    queries = []
    
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            l = int(tmp[1])
            r = int(tmp[2])
            length = r - l + 1
            
            # k from 1 to length contributes
            # for each k, i = l + k - 1 to r
            # so interval on i is [l+k-1, r]
            # store per k
            for k in range(1, length + 1):
                intervals[k].append((l + k - 1, r))
        else:
            queries.append(int(tmp[1]))
    
    # coverage arrays per k
    # we apply difference array per k
    cover = [None] * maxk
    
    for k in range(maxk):
        if not intervals[k]:
            continue
        diff = [0] * (n + 3)
        for l, r in intervals[k]:
            if l > n:
                continue
            l = max(1, l)
            r = min(n, r)
            if l <= r:
                diff[l] += 1
                diff[r + 1] -= 1
        
        cur = 0
        cov = [False] * (n + 2)
        for i in range(1, n + 1):
            cur += diff[i]
            cov[i] = (cur > 0)
        cover[k] = cov
    
    # compute mex per i
    mex = [1] * (n + 1)
    
    for i in range(1, n + 1):
        k = 1
        while k < maxk and cover[k] is not None and cover[k][i]:
            k += 1
        mex[i] = k
    
    out = []
    for i in queries:
        out.append(str(mex[i]))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、値 k ごとに、k が出現するインデックスのセットを明示的に構築します。 これは、k ごとの差分配列を使用して行われ、多くの間隔挿入を線形スキャンに変換します。 その後、存在マークが付けられていない最初の k まで上方向にスキャンして、位置ごとの mex を計算します。 

重要な実装の詳細は境界 k です。 mex は、n に挿入された個別の値の合計数を加えた値を超えることはできないため、n + q で切り捨てることで、配列を有限に保ちながら、関連する値の欠落を回避できます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n・K) | 各 k は、n | にわたって差分配列スキャンを構築します。 
| スペース | O(n・K) | K あたりのカバレッジ表 |

 ここで、K は最悪の推論では n + q によって制限されますが、実際にははるかに小さくなります。 この制約は、mex クエリが更新によって引き起こされる構造的制限を超える任意の大きな値を追跡する必要がないという事実に依存しています。 

これは、特に各 k が q にネストされた依存性を持たずに単純な線形スキャンを処理するため、慎重に最適化すると制限内に収まります。

 ## 特殊なケース

 最小のエッジ ケースは、n = 1 で長さ 1 の更新のみが存在する場合です。 インデックス 1 のセットは値 1 のみを繰り返し受け取るため、mex は 2 のままです。k=1 が常にマークされ、k=2 が導入されないため、アルゴリズムはこれを処理します。したがって、mex は正しく 2 になります。 

更新が配列に完全に重なる場合、境界ケースが発生します。 次に、r − l + 1 までのすべての k が有効範囲内のあらゆる場所に出現し、カバーされる値の長いプレフィックスが生成されます。 k にわたるスキャンは、真の mex 定義と一致する最初のカバーされていない値で停止します。 

もう 1 つの微妙なケースは、ばらばらの更新です。 更新がインデックス i の特定の k を決してカバーしない場合、その k は cover[k][i] でマークされることはありません。そのため、より大きな値が多数存在する場合でも mex は k が欠落していることを正しく示します。
