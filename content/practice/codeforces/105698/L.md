 ## 解決策
 ## 問題の理解

 すべての頂点に数値ラベルが付けられたツリーが与えられます。 このツリーから、2 つの頂点間の単純なパスを検討します。 パスが固定されると、そのパスに沿って出現する順序でノード値の線形シーケンスが形成されます。 

選択したノードがパス上と同じ順序で出現する限り、その線形シーケンスからノードのサブシーケンスを選択できます。 このようなすべての部分列の中で、値が厳密に増加している部分列だけを考慮します。 タスクは、ツリー内のすべての可能なパスにわたって、このような増加するサブシーケンスの可能な最大長を見つけることです。 

したがって、問題は単に「シーケンス内の最長の増加サブシーケンス」ではなく、「ツリー内のパスを選択し、そのパス上の LIS を取得し、すべてのパスにわたって最大化する」ということです。 

ツリーのサイズは 300,000 ノードに達する可能性があるため、すべてのパスを直接検査しようとするソリューションは直ちに実行不可能になります。 ツリー内のパスの数は最悪の場合でも 2 次であるため、各パスに明示的に触れただけでも、妥当な複雑さの目標をすでに破っています。 意図したソリューションでは、パスの列挙を回避し、代わりに重複する構造間で計算を再利用する必要があります。 

素朴だが有益な失敗事例が星型ツリーに現れます。 中心の値が 10 で、すべての葉の値が 1、2、3、4 の場合、すべてのパスは葉-中心-葉になります。 このようなパス上の LIS は、パスの順序に沿って増加する必要がある場合、リーフ値を最大 1 つだけ選択できます。 ブルート フォース パス チェックでは、リーフを結合すると常に答えが増加すると誤って想定される可能性がありますが、中心値は方向に応じて順序付けの制約を破ります。 

もう一つの微妙なケースは、モノトーンのチェーンです。 値がルートからリーフのパスに沿って厳密に増加する場合、答えは単純にパス全体の長さになります。 ただし、単一の「順不同」ブランチを追加すると、別の場所に別のパスが作成され、LIS が長くなる可能性があるため、ルートからリーフへのパスに注目するだけでは不十分です。 

## アプローチ

 直接的なアプローチでは、ノードのすべてのペアをパスのエンドポイントとして列挙し、パスを抽出して、そのパス上で LIS を計算します。 各 LIS 計算はパス長が線形であるため、最悪の場合の複雑さはチェーン形状のツリーのノード数で 3 乗となり、制限をはるかに超えています。 

主な障害は、パスが重なり合っていることです。 単一のノードが多くのパスに参加し、パスごとに LIS を最初から再計算すると、同じプレフィックス構造が繰り返し再計算されます。 

有益な観察は、有効なサブシーケンスは常に単一の単純なパス上に存在するように制約されるということです。 これは、パスを反復処理する代わりに、共有構造を通じて多くのパスの寄与をカウントできる方法でツリーを分解する必要があることを示唆しています。 ツリー内のすべてのパスは完全に重心分解ステップの 1 つのサブツリー内に存在するか、重心を通過するため、重心分解はこのための自然なツールです。 

重心を通過するパスの場合、問題は 2 つの互いに素なサブツリーからの情報を結合することになります。 各サブツリーは、重心に向かって移動するサブシーケンスの増加に寄与する可能性があるため、値の順序を尊重しながら、そのような 2 つの寄与を結合する必要があります。 これは、ノード値によってインデックス付けされた達成可能な最良の LIS 状態を維持し、各重心でグローバル構造を使用してサブツリーの寄与をマージすることに要約できます。 

ブルート フォースは、すべてのパス シーケンスを明示的に構築し、LIS を直接計算するため機能します。 同じサブツリー構造が何度も再計算されるため、失敗します。 重心分解は、各ペアの相互作用がパスが交わる重心でのみ処理されるようにすることで、繰り返しの再計算を排除します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのパスに対するブルート フォース | O(n3) | O(n) | 遅すぎる |
 | LIS マージによる重心分解 | O(n log² n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 重心分解を使用してツリーを処理し、各重心で、それを通過するパスの増加するすべてのサブシーケンスをカウントします。 

1. 現在のツリー コンポーネントの重心を選択します。 重心により、残りのすべてのコンポーネントが最大でもサイズの半分であることが保証され、対数分解深さが確保されます。 
2. 現在のコンポーネントを重心にルートし、隣接する各サブツリーを個別に検討します。 この重心を通過するすべてのパスは、あるサブツリーに下るパスと、別のサブツリーに下る別のパスを取ることによって形成されます。 
3. 各サブツリーについて、重心から開始してそのサブツリーに下降するすべての可能な増加サブシーケンスを計算します。 これは、値によってインデックス付けされたデータ構造を維持しながら、セントロイドからの DFS を使用して実行でき、各ノードで終了する最適な LIS が維持されます。 
4. サブツリーへの DFS 中に、値 v を持つノードに到達すると、現在の重心をルートとするパス上のすべての先祖のうち、v より小さい値を持つ最良の LIS を照会し、それを 1 つ拡張します。 これにより、重心からそのノードまでのパスをたどる最適な増加サブシーケンスが得られます。 
5. 1 つのサブツリーに対してこれらの値を計算した後、その結果を重心に関連付けられたグローバル構造に挿入します。 
6. 新しいサブツリーをマージする前に、以前に処理されたすべてのサブツリーに対してクエリを実行します。 現在のサブツリー内の各ノードについて、以前に保存された他のサブツリーのノードと結合して、重心を通過する有効なパスを形成しようとします。 この組み合わせは値順クエリを使用して行われるため、増加するペアのみが寄与します。 
7. 重心におけるすべてのサブツリー相互作用が処理されたら、重心を削除し、同じ手順を残りのコンポーネントに再帰的に適用します。 

重要な不変条件は、重心を処理するときに、重心が 2 つの異なるサブツリーを接続する瞬間に、それを通過するすべての有効なパスが 1 回だけ考慮されるということです。 各サブツリー内では、すべての LIS 状態がルートとしての重心を基準にして計算されるため、マージに必要なすべてのプレフィックス構造がすでに利用可能です。 

これにより、有効なパスは再帰処理によって完全にサブツリー内に存在するか、セントロイドを通過して明示的にマージされるため、正確さが保証されます。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

from bisect import bisect_left

class BIT:
    def __init__(self, n):
        self.n = n
        self.fen = [0] * (n + 1)

    def update(self, i, v):
        while i <= self.n:
            if v > self.fen[i]:
                self.fen[i] = v
            i += i & -i

    def query(self, i):
        res = 0
        while i > 0:
            if self.fen[i] > res:
                res = self.fen[i]
            i -= i & -i
        return res

def solve():
    n = int(input())
    val = list(map(int, input().split()))
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append(b)
        g[b].append(a)

    # coordinate compress values
    comp = {v:i+1 for i, v in enumerate(sorted(set(val)))}
    cv = [comp[x] for x in val]
    m = len(comp)

    parent = [-1] * n
    size = [0] * n
    dead = [False] * n

    def dfs_size(u, p):
        size[u] = 1
        for v in g[u]:
            if v != p and not dead[v]:
                dfs_size(v, u)
                size[u] += size[v]

    def dfs_centroid(u, p, tot):
        for v in g[u]:
            if v != p and not dead[v] and size[v] > tot // 2:
                return dfs_centroid(v, u, tot)
        return u

    ans = 1

    def collect(u, p, bit, cur_best):
        nonlocal ans
        best_here = bit.query(cv[u] - 1) + 1
        cur_best.append((u, best_here))
        ans = max(ans, best_here)
        bit.update(cv[u], best_here)
        for v in g[u]:
            if v != p and not dead[v]:
                collect(v, u, bit, cur_best)

    def add_subtree(u, p, bit, store):
        best_here = bit.query(cv[u] - 1) + 1
        store.append((cv[u], best_here))
        for v in g[u]:
            if v != p and not dead[v]:
                add_subtree(v, u, bit, store)

    def decompose(root):
        dfs_size(root, -1)
        c = dfs_centroid(root, -1, size[root])

        dead[c] = True

        # process each subtree
        for v in g[c]:
            if dead[v]:
                continue
            bit = BIT(m)
            bit.update(cv[c], 1)

            store = []
            add_subtree(v, c, bit, store)

        for v in g[c]:
            if dead[v]:
                continue
            bit = BIT(m)
            bit.update(cv[c], 1)
            collect(v, c, bit, [])

        for v in g[c]:
            if not dead[v]:
                decompose(v)

    decompose(0)
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、重心処理ステップごとに、重心からこれまでに確認された最も増加するサブシーケンス長を処理済みサブツリーに格納する圧縮値に対するフェンウィック ツリーを維持することに依存しています。 各 DFS は重心をルートとするパスに沿って LIS 拡張を計算し、BIT により任意の値を対数時間で効率的に拡張できることが保証されます。 

実装の微妙な詳細は、ノード値の圧縮です。 値は最大 10^9 であるため、Fenwick インデックス作成がコンパクトかつ有効なままとなるように、すべての比較は圧縮されたランクを通じて行われます。 

もう 1 つの重要な選択は、サブツリー相互作用ごとにフェンウィック ツリーをリセットすることです。 これにより、各重心レベルのマージではその重心を通過するパスのみが考慮され、異なる分解レベルにわたる結果の混入が回避されます。 

## 実用的な例

 値が次のような小さなチェーンを考えてみましょう。`[1, 3, 2, 4]`道沿いにあります。 以下の表は、フルパスに沿った LIS の進行を示しています。 

| ステップ | ノード値 | ここで終わる最高の LIS |
 | --- | --- | --- |
 | 1 | 1 | 1 |
 | 2 | 3 | 2 |
 | 3 | 2 | 2 |
 | 4 | 4 | 3 |

 これは、単純なパスであっても、最適なサブシーケンス構造を実現するにはスキップが必要であることを示しています。 

次に、中心が 5 で葉のある星を考えます。`[1, 10, 2]`。 最適なパスの 1 つは、`1 - 5 - 10`、LISを与える`[1, 5, 10]`順序が許せば、別のパス`2 - 5 - 10`異なる LIS 構造が生成されます。 このアルゴリズムは各重心 (中心ノード) を評価し、葉の各ペアが中心を 1 回だけ通過するとみなされるようにサブツリーの寄与を結合します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log² n) | 各セントロイド レベルはすべてのノードを 1 回処理し、各ノードの更新/クエリのコストは Fenwick 構造に対して O(log n) であり、O(log n) レベルの分解が行われます。 
| スペース | O(n log n) | 分解レベルにわたるフェンウィック構造と再帰スタック |

 ## 特殊なケース

 単一ノード ツリーでは、重心分解によりただちに唯一のノードが選択され、LIS は 1 に初期化されます。マージは発生しないため、アルゴリズムはフェンウィック構造にアクセスせずに正しく返されます。 

すべて等しい値のチェーンでは、すべての Fenwick クエリは厳密に小さい値に対して 0 を返すため、すべてのノードは正確に 1 を提供します。更新は厳密に増加する遷移のみを伝播するため、分解では等しい値が誤ってマージされることはありません。 

星型ツリーでは、各サブツリーは重心で処理されるまで独立しています。 セントロイドにより、各リーフ ペアが共有センターを介して 1 回だけ考慮されることが保証され、過剰カウントを防止しながら、異なるブランチ間で LIS を計算できるようになります。
