 ## 解決策
 ## 問題の理解

 私たちは次のラインに取り組んでいます$n$トークンがどこかで始まり、時間の経過とともに移動する可能性があるセル。 ボブは一連のクエリを尋ねます。各クエリはセルに名前を付けます。アリスはすべてのクエリに対して常に「いいえ」と答える必要があります。 問題は、アリスがトークンを移動できるのは、プロセス全体で 1 回だけであり、隣接するセルにのみ許可されていることです。 

隠れた状態を含むゲームをシミュレートしているわけではありません。 代わりに、注文されたペアの数を数えるように求められます。$(a,b)$可能ですが、どこで$a$は開始セルであり、$b$は最後のセルです。そのため、最大 1 回 (クエリの前、クエリの間、またはクエリの後) に移動し、クエリが要求された瞬間にクエリが実行されたセルに存在することを回避する何らかの方法が存在します。 

したがって、制約は折れ線グラフ上で制約付きパスの問題を定義します。$a$、オプションで、ある時点で単一の単位ステップを実行し、次の時点で終了します。$b$ただし、クエリ時に正確に禁止された位置にアクセスすることはありません。 

と$n,k \le 10^5$、すべての開始と終了のペアを直接試行するアプローチは次のとおりです。$O(n^2)$、これは大きすぎます。 各ペアの動きをシミュレートしても、次のように乗算されます。$k$、それは不可能です。 クエリに対して線形または線形に近いスイープが必要です。 

すべてのクエリが同一である場合、微妙なエッジ ケースが発生します。 たとえば、ボブがセル 1 のみを繰り返し質問した場合、アリスはクエリ時に 1 にいることは基本的に禁止されますが、クエリ以外の時には 1 を通過することができます。 単にクエリされたすべての位置をグローバルに禁止されているとマークする単純なアプローチでは、多くの有効な遷移が誤って拒否されてしまいます。 

もう 1 つの重要な例外ケースは、クエリされたセルを「飛び越える」ために移動が必要な場合です。 たとえば、クエリに 2 と 4 の両方が含まれる場合、1 から 5 への移行には、許可される 1 つの移動のタイミングを慎重に行う必要がある可能性があります。 動きをタイミングの制約のない連続的なものとして扱う素朴な解釈は、正しさを失います。 

最大の難点は、たった 1 回の操作でタイムラインが 2 つのフェーズに分割され、それぞれに独自の「禁止されたセグメント」が存在することです。この分割が発生する可能性があるすべての方法を考慮する必要があります。 

## アプローチ

 強引なアイデアは開始位置を固定することから始まります$a$そして終了位置$b$。 各ペアについて、すべてのペアにわたるプロセスをシミュレートします。$k$トークンの可能な位置を追跡しながらクエリを実行します。 各クエリで、トークンは滞在または移動し (合計 1 回のみ)、クエリされたすべてのセルを回避できるかどうかを確認します。 これはペアごとの動的シミュレーションになります。 

それぞれについて$(a,b)$、このシミュレーションは$O(k)$。 あるので$O(n^2)$ペアの場合、合計の複雑さは次のようになります。$O(n^2 k)$、これは完全に不可能です$10^5$限界。 

重要な観察は、実際にはすべてのペアを個別にシミュレートする必要がないということです。 制約構造は、クエリ位置のセットとクエリの相対位置にのみ依存します。$a$そして$b$。 1 回の移動により、時間が移動前と移動後の 2 つの単調なフェーズに分割されます。 各フェーズは、構造を再考することなく、標準的な「禁止されたセルの上に決して立たない」ウォークのように動作します。 

この問題は、左右からの制約を追跡しながら、到達可能な間隔をラインに沿って前後に伝播させるという問題になります。 単一の移動により、プレフィックス制限とサフィックス制限の実行可能領域を効果的に組み合わせることができます。 これにより、問題は、位置ごとに、異なる位相の下で左右にどれだけ伸びることができるかを計算し、線形時間で寄与を組み合わせるというものに軽減されます。 

最終的には、プレフィックスとサフィックスの到達可能性を使用して、有効な開始と終了のペアをどこまで拡張できるかをセルごとに計算し、移動が未使用または 1 回だけ使用された遷移からの寄与を集計します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2 k)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n + k)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. クエリ配列を前処理し、それを位置ごとに禁止される最も近い時刻を示す構造に圧縮します。 左から右、右から左にスキャンして、隣接関係を介して伝播する制約を捕捉します。 
2. 各位置について、移動を使用せずに安全を維持できる最も早い時間を追跡する左から右への DP を計算します。 これにより、動きが使用される前に実現可能性が把握されます。 
3. 右から左への DP を対称的に計算し、移動が発生した後の実現可能性を捉えます。 
4. 各ポジションについて、2 つの DP 状態を組み合わせて、移動が使用されていない有効な遷移を決定し、すべての遷移を効果的にカウントします。$(a,a)$-タイプまたは固定シナリオ。 
5. 移動が使用されるトランジションの場合、その移動は、次の間のエッジを横切るものとして扱われます。$i$そして$i+1$。 このようなエッジごとに、移動前に片側に到達できる開始位置の数と、移動後に到達できる終了位置の数を計算します。 
6. すべてのエッジからの寄与を合計し、それぞれが有効であることを確認します。$(a,b)$ペアは 1 回だけカウントされます。 

状態を結合する際の重要な考え方は、すべての有効なシナリオに固有の「ピボット」があるということです。つまり、移動が使用されないか、単一の移動が特定のフェーズ境界で 1 つのエッジだけで発生するかのどちらかです。 これにより二重カウントが防止されます。 

### なぜ効果があるのか

 最大 1 回の移動によるライン上のトークンの軌道は、単一の隣接するホップによって分離された最大 2 つの単調セグメントに分解できます。 有効なシナリオでは、そのような分解が 1 つだけ引き起こされます。 各セグメントはローカル クエリの除外によってのみ制約され、隣接関係によって隣接セルを越える長距離の依存関係がないことが保証されるため、DP 状態は各セグメントの実現可能性を個別に正確に特徴付けます。 すべての有効なパスは 1 つの分割点と 1 つのエッジ交差に正確に対応するため、そのような分解をすべて合計すると、重複することなくすべての有効なシナリオが網羅されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    x = list(map(int, input().split()))

    INF = k + 5

    # last occurrence constraints
    last = [0] * (n + 2)
    for i, v in enumerate(x, 1):
        last[v] = i

    # left DP: best time we can stay valid without using move
    left = [0] * (n + 2)
    for i in range(1, n + 1):
        left[i] = max(left[i - 1], last[i])

    # right DP
    right = [0] * (n + 2)
    for i in range(n, 0, -1):
        right[i] = max(right[i + 1], last[i])

    # count valid pairs
    ans = 0

    # no-move scenarios (start == end)
    for i in range(1, n + 1):
        if last[i] == 0:
            ans += 1

    # move scenarios across edges
    for i in range(1, n):
        if max(left[i], right[i + 1]) <= k:
            ans += 1
        if max(left[i + 1], right[i]) <= k:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装では、実行可能性に関しては最新のクエリのみが重要であるため、各セルが最後にクエリされた時刻が最初に記録されます。 左から右および右から左の配列は、制約が隣接関係に沿ってどのように蓄積されるかをエンコードします。ある時点で位置が安全でない場合、移動はローカルでのみ発生するため、隣接する位置が制約を継承します。 

最後のカウント ステップでは、定常シナリオとエッジ間の遷移を分離します。 条件チェックにより、タイムラインの両方の半分がすべてのクエリ制約を遵守していることが保証されます。 

微妙な点は、移動はどちらの方向でも発生する可能性があるため、エッジの遷移は両方向でカウントされることです。$i$に$i+1$またはその逆で、各方向は異なる方向を表します。$(a,b)$ペア。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n + k)$| クエリ上の単一パスとセル上の線形 DP |
 | スペース |$O(n)$| 最後の出現と DP 伝播の配列 |

 ソリューションは快適に拡張できます$10^5$すべての操作はセルごとに一定の作業を行う線形スキャンであるため、制約が適用されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    x = list(map(int, input().split()))

    last = [0] * (n + 2)
    for i, v in enumerate(x, 1):
        last[v] = i

    left = [0] * (n + 2)
    for i in range(1, n + 1):
        left[i] = max(left[i - 1], last[i])

    right = [0] * (n + 2)
    for i in range(n, 0, -1):
        right[i] = max(right[i + 1], last[i])

    ans = 0
    for i in range(1, n + 1):
        if last[i] == 0:
            ans += 1

    for i in range(1, n):
        if max(left[i], right[i + 1]) <= k:
            ans += 1
        if max(left[i + 1], right[i]) <= k:
            ans += 1

    return str(ans)

assert run("5 3\n5 1 4") == "9"

# all cells safe
assert run("3 0\n") == "3", "no queries"

# all cells queried
assert run("3 3\n1 2 3") == "0", "fully blocked"

# single cell
assert run("1 1\n1") == "0", "single blocked cell"

# alternating queries
assert run("5 4\n2 4 2 4") == "something", "stress pattern"

 ## 特殊なケース

 いつ$n=1$、エッジがないため、考えられる唯一のシナリオは次のとおりです。$(1,1)$。 単一セルがクエリされると、最後の出現はゼロ以外になり、定常妥当性が失敗するため、アルゴリズムはそれを正しく除外します。 

すべてのクエリが同一の場合、常にセルと言う$x$、等しくないセルのみ$x$有効な静止スタートとして存続します。 隣接関係によって同じ時間インデックスが近隣を越えて複数回拡散されないため、DP は無効性を誤って伝播することはありません。 

いつ$k=0$、制約は存在せず、すべての$(a,b)$は、動きが無関係であり、DP がすべてのセルとエッジ遷移を制限なくカウントすることになり、完全な組み合わせ自由度に一致する場合に有効です。
