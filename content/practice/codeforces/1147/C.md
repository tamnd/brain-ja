 ## 解決策
 ## 問題の理解

 私たちは、それぞれにいくつかの石が含まれている一連の山でプレイされる 2 人用ゲームを分析するように求められています。 がある$n$杭、そして$n$均等であることが保証されています。 アリスが最初に動き、各ターンでプレイヤーは正確に選択する必要があります$n/2$空でない山を配置し、それぞれから少なくとも 1 つの石を取り除きます。 プレイヤーは、誰かが行動できなくなるまで順番を交互に繰り返します。行動できなくなるのは、$n/2$山は空ではありません。 動けなくなったプレイヤーが負けとなります。 

入力により杭の数が与えられます$n$そして配列$a_1, a_2, \dots, a_n$各山の石を表します。 出力は、「Alice」または「Bob」のいずれかが勝者である必要があります。 

制約は小さいです:$n$最大50まで上がり、それぞれ$a_i$は最大 50 です。これにより、二次関数のアルゴリズムが可能になります。$n$必要に応じて立方体にすることもできます。 ただし、このゲームは組み合わせなので、すべての動きを総当たりで実行するには検証が必要になります。$\binom{n}{n/2}$各ステップでの選択肢は急速に増大し、$n=50$。 

エッジケースは、山がすべて等しい状況、または最大の山と最小の山の間に大きな差がある状況で発生します。 たとえば、次の場合$n=2$両方の山が等しい場合、2 番目のプレーヤーはいつでも最初のものを反映することができ、勝利が保証されます。 不用意に実装すると、対称性の特性を見逃して、間違った勝者を予測する可能性があります。 

## アプローチ

 単純なアプローチでは、あらゆる可能な動きをシミュレートします。各プレーヤーに対して、次のすべての組み合わせを生成します。$n/2$空でない山を選択し、最終位置に到達するまで、選択した各山から再帰的にすべての可能な数の石を減算します。 これはすべての可能性を検討するため正しいですが、特に時間の複雑さは指数関数的です。$O\left((\text{max stones})^{n/2} \cdot \binom{n}{n/2}\right)$、これは明らかに不可能です$n=50$。 

重要な洞察は、ゲームが対称的であり、動きをシミュレートするのではなく杭を比較することに還元できるという観察から得られます。 各プレイヤーが取らなければならないため、$n/2$パイルの場合、ゲームは最大のペアを組むことと同等です。$n/2$最小のものに対して積み重ねる$n/2$山。 最大の合計の場合$n/2$パイルは最小の合計より厳密に大きくなります$n/2$パイルでは、最初のプレーヤーはいつでもアドバンテージを維持する方法で石を取り除くことができます。そうでない場合は、2 番目のプレーヤーが同じ動きをして勝利を強制することができます。 これにより、山を並べ替えて 2 つの半分の合計を比較するという、単純な線形時間の解決策が可能になります。

 | --- | --- | --- | --- |
 | ブルートフォース | O((50)^(n/2) * C(n, n/2)) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 杭数を読み取る$n$そしてパイルサイズの配列$a$。 

リストを手元に用意しておくと、並べ替えや操作が簡単になります。 
2. 配列をソートする$a$降順ではない順に。 

ソートにより、最初のものが確実に$n/2$要素は最小の山であり、最後の山です$n/2$要素は最大の山です。 
3. 最初の合計を計算します。$n/2$山(最小)と最後の合計$n/2$山（最大）。 

させて`small_sum`最小値の合計になる$n/2$杭、そして`large_sum`最大のものの合計になる$n/2$山。 
4. 比較する`large_sum`そして`small_sum`。 

もし`large_sum`アリスは常に最大の山を選択し、厳密な優位性を維持するためにそれらを減らすことができ、最終的にはボブを動かさずに残すことができます。 それ以外の場合、ボブはアリスの動きを反映して平等を維持し、勝つことができます。 
5. 次の場合は「アリス」を出力します。`large_sum`>`small_sum`; それ以外の場合は、「ボブ」と出力します。 

機能する理由: 利用可能な最大の山を常に選択することで、最初のプレーヤーは、2 番目のプレーヤーが直面する選択肢が少なくなる位置を強制できます。 並べ替えて半分に分割すると、明確な分離が作成されます。上半分の石の合計が下半分を超えた場合、最初のプレーヤーが常にコントロールを維持できます。 これにより、複雑な組み合わせゲームが単純な算術比較に縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

a.sort()
half = n // 2

small_sum = sum(a[:half])
large_sum = sum(a[half:])

if large_sum > small_sum:
    print("Alice")
else:
    print("Bob")
```コードは高速 I/O を使用して入力を読み取ります。 配列をソートすると、上半分と下半分が正しく識別されます。 合計を計算して比較することで、最適な戦略が直接実装されます。 Python のスライスであるため、off-by-one エラーはありません。`a[:half]`そして`a[half:]`偶数の場合は配列を正確に半分に分割します$n$。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()
    half = n // 2
    return "Alice" if sum(a[half:]) > sum(a[:half]) else "Bob"

# Provided samples
assert run("2\n8 8\n") == "Bob", "sample 1"
assert run("4\n1 2 3 4\n") == "Alice", "sample 2"

# Custom cases
assert run("2\n1 2\n") == "Alice", "first player has advantage"
assert run("4\n5 5 5 5\n") == "Bob", "all equal piles"
assert run("6\n1 1 1 1 10 10\n") == "Alice", "large disparity favors first"
assert run("50\n" + " ".join(["1"]*50) + "\n") == "Bob", "max n, equal stones"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2\n1 2\n | アリス | 最小ケースのメリット |
 | 4\n5 5 5 5\n | ボブ | 対称エッジケース |
 | 6\n1 1 1 1 10 10\n | アリス | 大格差チェック |
 | 50\n1 ... 1\n | ボブ | 等しい石の最大 n |

 ## 特殊なケース

 すべての山が等しい場合、アルゴリズムは正しく「Bob」を出力します。 例えば、`n=4, a=[5,5,5,5]`。 上半分と下半分の合計が等しいため、アリスは優位性を維持できません。 スライスの計算`a[:half]`そして`a[half:]`正しいパーティショニングを保証します。 単一の山が優勢な場合、次のように`n=6, a=[1,1,1,1,10,10]`、ソートにより、最大の山がアリスによって考慮されることが保証され、合計の比較によって彼女の勝利戦略が正確に特定されます。
