 ## 解決策
 ## 問題の理解

 ゲームは、2 つの等しい頂点グループを持つ完全な 2 部グラフでプレイされます。 左側のすべての頂点は右側のすべての頂点に接続されており、そのような各エッジには固有の重みがあります。 入力はこれらの重みを次のように与えます。$n \times n$マトリックス、エントリは$a_{ij}$左ノード間のエッジの重みです$i$そして右のノード$j+n$。 

トークンは選択した頂点から始まります。 各移動は、入射エッジを介して未使用の頂点を横断し、通過するエッジのシーケンスは、選択した方向に応じてエッジの重みを厳密に増加または厳密に減少させるという厳密な単調ルールに従う必要があります。 一度頂点を訪問すると、再度訪問することはできないため、プレイは常にこの 2 部グラフ内で単純なパスを形成します。 

プレイが始まる前に、プレイヤーの 1 人がシーケンスを増加するか減少させるかを選択し、(役割に応じて) 開始頂点も選択します。 その後、ボブが開始構成の選択者ではない場合、最初の強制的な動きを行うことができ、それ以降は両プレイヤーが交互に動きます。 

インタラクションの側面は対戦相手の選択を隠しますが、中心的なタスクは、ジャッジがどのように行動するかに関係なく、勝利の戦略を保証することです。 

制約は小さく、$n \le 50$、最大 100 個の頂点と最大 2500 個のエッジを意味します。 これにより、漸近的に重いグラフ検索や状態爆発の必要性が排除されます。 ローカルでエッジ順序を決定するか、動きごとに決定的な貪欲な戦略を構築するソリューションであれば、十分です。 

主要な構造特性は、すべてのエッジの重みが個別であり、比較がグローバルであることです。 これにより、問題はグラフ トポロジの複雑さではなく、順序付けに関する推論に変わります。 

グローバルな順序付けの方向を制御せずにローカルの貪欲な動きが安全であると仮定すると、単純な推論による微妙な失敗例が現れます。 たとえば、減少するゲームで局所的に最小の利用可能なエッジを選択すると、それが現在有効であっても、将来の注文の可能性を侵害する可能性があるため、プレーヤーはすぐに罠にかかる可能性があります。 もう 1 つの落とし穴は、残りの頂点のパリティを無視することです。すべての移動が頂点を消費するため、残りのパスの長さのパリティを制御するプレイヤーが結果を効果的に制御し、局所的に最適な移動によってこのパリティが誤って反転される可能性があります。 

## アプローチ

 ゲームの直接的なブルート フォース ビューでは、すべての状態が、現在の頂点、最後に使用されたエッジの重み、訪問されたセット、および誰のターンであるかで構成されるタプルとして扱われます。 各状態から、単調性と未訪問の制約を尊重するすべての有効なエッジに分岐します。 これにより、ミニマックスを使用して勝ちポジションと負けポジションをマークできる完全なゲーム ツリーが得られます。 

このアプローチは、可能なすべての継続を明示的に探索するので正しいですが、状態空間は指数関数的に増大します。 頂点が 100 個しかない場合でも、訪問したサブセットだけで次の結果が得られます。$2^{100}$可能性があり、移行によりこれがさらに増大します。 枝刈りを行ったとしても、これは実行可能な計算をはるかに超えています。 

重要な観察は、実際には訪問セット全体を追跡したり、任意のパスをシミュレートしたりする必要がないということです。 二部構造と重みのグローバルな順序付けは、最適なプレイは、選択された単調な方向と一致する極端な利用可能なエッジを繰り返し選択することに等しいことを意味します。 任意のパスという観点から考えるのではなく、未使用のエッジの間隔を繰り返し縮小するという観点から考えます。 

エッジが重みによってソートされると、ゲームはこのソートされた順序に対して 2 つのポインターを維持することと同等になります。 ゲームプレイを増やすと常にローエンドから上に向かってエッジが消費され、ゲームプレイが減少するとハイエンドから下に向かって消費されます。 2 部構成により、実際の制約はエンドポイントの可用性のみとなり、各側にはサイズがあるため、$n$の場合、プロセスは完全なパスを追跡するのではなく、各エンドポイント側から使用可能なエッジの数を維持することになります。 

これにより、問題はパス上の指数関数的な探索から、ローカルの実現可能性チェックを伴う順序付けされたエッジ上の決定論的な貪欲なシミュレーションに変換されます。

 ## アルゴリズムのチュートリアル

 重要なステップは、頂点トラバーサルではなくエッジ順序の観点からゲームを再解釈することです。 

まずすべてのエッジを平らにします$(i, j)$重量をリストにまとめ、重量順に並べ替えます。 これにより、遊びの増加または減少に応じてエッジが関連するグローバルな順序が与えられます。 

ここで、この命令において法的措置が何を意味するのかを考えてみましょう。 増加するゲームで、重量の限界に達すると$w$が使用される場合、次のすべてのエッジは、厳密に よりも大きい重みを持つ未使用のエッジのセットから取得する必要があります。$w$。 すべての重みは異なるため、ソートされたリスト内で常に前に進むことになります。 減少ゲームでは、対称的なステートメントが当てはまります。 

2 部構造により、それぞれの動きが常にサイドを切り替えるため、有効なプレイは左ノードと右ノードの間で交互に行われます。 これにより、エンドポイントの順序と可用性によってのみ制約されるシーケンスを構築するものとしてプロセスを扱うことができます。 

勝利の戦略は、各ステップで、ソートされた未使用のエッジの現在の両端からより制限的なエンドポイントを選択できるプレイヤーが、より長い継続を強制できるという事実から生まれます。 これは、残りのグラフのバランスを可能な限り保つエッジを常に選択することになります。 

これを実装するには、ソートされたエッジ リスト上の 2 つのポインターと、エンドポイントがまだ利用可能かどうかを示すブックキーピング構造を維持します。 移動するたびに、方向と一致する次の有効な極端なエッジを選択し、可用性を更新します。 

インタラクション要件は実装のみを変更します。各ジャッジの動きの後に、同じ構造を更新し、貪欲な有効な動きで応答します。 

### なぜ効果があるのか

 不変条件は、ゲームの状態がグローバル エッジ順序付けにおける現在の位置と利用可能なエンドポイントのセットによって完全に決定されるということです。 すべてのエッジは一意であり、トラバースは頂点を消費するため、これら 2 つの情報が固定されると、2 つの異なる履歴から将来の異なる正当な手セットを生成することはできません。 これにより、ゲームは単調なプロセスに崩壊し、最適な選択は常に実現可能な極限のエッジとなり、いかなる逸脱も新しい選択肢を生み出すことなく将来の選択肢を減らすだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = [list(map(int, input().split())) for _ in range(n)]

        edges = []
        for i in range(n):
            for j in range(n):
                edges.append((a[i][j], i, n + j))

        edges.sort()
        used = [False] * (2 * n)

        def next_move_inc(last):
            for w, u, v in edges:
                if w > last and not used[u] and not used[v]:
                    return w, u, v
            return None

        def next_move_dec(last):
            for w, u, v in reversed(edges):
                if w < last and not used[u] and not used[v]:
                    return w, u, v
            return None

        print("A")
        sys.stdout.flush()

        mode, start = input().split()
        start = int(start)

        used[start] = True

        last = 0
        cur = start

        if mode == "I":
            def get_move(last):
                for w, u, v in edges:
                    if w > last and not used[u] and not used[v]:
                        return w, u, v
                return None
        else:
            def get_move(last):
                for w, u, v in reversed(edges):
                    if w < last and not used[u] and not used[v]:
                        return w, u, v
                return None

        while True:
            mv = get_move(last)
            if mv is None:
                print(-1)
                sys.stdout.flush()
                break

            w, u, v = mv
            if used[u] and used[v]:
                print(-1)
                sys.stdout.flush()
                break

            nxt = v if used[u] else u

            print(nxt)
            sys.stdout.flush()

            used[nxt] = True
            last = w

            resp = int(input().strip())
            if resp == -1 or resp == -2:
                break

            used[resp] = True
            cur = resp

def main():
    solve()

if __name__ == "__main__":
    main()
```実装では完全なエッジ リストが構築され、テスト ケースごとに 1 回ソートされます。 中心的な考え方は、単調な方向に応じて、ソートされたエッジを前方または後方にスキャンすることによってすべての応答が選択されるということです。 の`used`配列は、無効なエッジが選択されないように、訪問した頂点を追跡します。 それぞれの動きの後に、ジャッジの応答が対称的に組み込まれます。 

主な微妙な点は、アルゴリズムが、ソートされた順序で最初の実行可能なエッジを選択することが常に安全であると想定していることです。 これは、極端な遷移へのゲームの構造的崩壊に依存しているため、代替分岐を考慮する必要はありません。 

## 実用的な例

 次の小さなケースを考えてみましょう$n=2$、エッジ:

 | エッジ | 重量 |
 | --- | --- |
 | 1-3 | 1 |
 | 1-4 | 3 |
 | 2-3 | 2 |
 | 2-4 | 4 |

 ノード 1 から開始する増加モードの場合:

 | ステップ | 前回の体重 | 利用可能なエッジ | 選択されたエッジ |
 | --- | --- | --- | --- |
 | 1 | 0 | すべて | 1-3 (1) |
 | 2 | 1 | 残り >1 | 2-3(2) |
 | 3 | 2 | 残り >2 | 1-4 (3) |
 | 4 | 3 | 残り >3 | 2-4 (4) |

 このプロセスは厳密に昇順でエッジを消費し、方向が固定されると分岐の選択肢が実際には必要ないことを確認します。 

減少モードの 2 番目のケースは対称性を示しています。最大のエッジから開始して、シーケンスは下向きに強制され、代替選択はすぐに単調性に違反するか、頂点を再利用します。 

これらのトレースは、ゲームがパスの選択ではなく、グローバルな順序の一貫性に依存していることを示しています。

 ## 特殊なケース

 単一のエッジを持つ最小限のグラフは、それ以上有効なエッジが存在しないため、1 回移動した後すぐに強制終了されます。 アルゴリズムは両方のエンドポイントを使用済みとして正しくマークし、移動を返しません。 

完全に密な$2 \times 2$重みがインターリーブされている場合、単調制約によって次の動きが単一の候補に即座に制限されることが保証され、ローカルでの貪欲な選択がグローバルな実現可能性と一致することが確認されます。 

一方の側の重みが系統的に大きくなるケースは、モード対称性が減少することを示しており、ハイエンドからのスキャンによって正当性が正しく維持され、利用可能な手を早期に使い果たすことが回避されます。
