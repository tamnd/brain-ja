 ## 解決策
 ## 問題の理解

 私たちは複数のトナカイを飼育しています。 各トナカイはパワー レベルによって識別されますが、重要な実際の値は 2 の累乗です。$2^{c_i}$。 したがって、事実上、それぞれが 2 の累乗である整数のコピーを複数保存していることになり、同じ累乗を持つトナカイは依然として別個の要素です。 

これらのトナカイの任意のサブセットから、「能力」値を計算できます。 これを行うには、選択したサブセットを強度の降順に並べ替えます。 最も強いものはその指数全体を寄与し、次のものはその指数の半分、その次は 4 分の 1 を寄与し、というように各ステップでフロアリングが適用されます。 容量は、これらの加重指数の合計です。 

要素の動的な挿入と削除をサポートし、各更新後に、少なくとも指定されたしきい値以上の容量を持つサブセットの数を回答するように求められます。 

主な難点は、サブセットのサイズが指数関数的であり、各サブセットの値が数だけでなく並べ替え後の順序に依存することです。 すべてのサブセットの容量を再計算する単純なアプローチでは、$O(2^n)$クエリごとに、これはたとえ$n \le 500$。 

すべての値が 2 の累乗であるという制約は重要です。 これは、任意の重みを扱っているのではなく、より高い指数がソート順で強く支配する構造化された指数寄与を扱っていることを意味します。 これは、大きな値の寄与は個別に処理できる一方、小さな値の寄与はほとんどがソート後の無視できる部分的な影響であることを示唆しています。 

同一の値が多数ある場合、微妙なエッジケースが発生します。 トナカイは個別であるため、サブセットを選択すると、多重度が組み合わせでカウントされます。 たとえば、2 つの同一の強度がある場合、容量への寄与が対称であっても、どちらかまたは両方を選択した場合は、個別にカウントする必要があります。 どのソリューションでも、値の有無だけでなく、二項カウントを正しく組み込む必要があります。 

もう 1 つの注意が必要なケースは、そのしきい値です$x$まで可能です$10^{18}$、個人の貢献よりもはるかに大きい。 これは、ほとんどのサブセットが、完全な詳細構造ではなく、少数の高出力要素に応じて自動的に有効または無効になることを意味します。 

## アプローチ

 強引なアイデアは単純明快です。 タイプ 3 の各クエリについて、現在のマルチセットのすべてのサブセットを列挙し、サブセットを並べ替えて加重合計定義を適用することによってその容量を計算し、しきい値を満たすものをカウントします。 べき乗を事前に計算したとしても、サブセットの列挙が優先されます。 最大 500 個の要素を使用すると、次のようになります。$2^{500}$、これは実行可能な計算をはるかに超えています。 

もう少し優れたブルート フォースを使用すると、静的配列のサブセットの寄与を事前計算できますが、更新により再利用が破壊されます。 中心的な問題は、サブセットの値がソートされた構造に依存するため、1 つの要素を追加または削除すると、その要素に関係するすべてのサブセットが非ローカルな方法で変更されることです。 

重要な観察は、容量関数の構造が最大の要素によって支配されていることです。 並べ替え後、次の各要素は 2 の累乗で除算されます。 これは、貢献度がポジションとともに指数関数的に減衰することを意味します。 特に、対数的な大きな要素を超えると、しきい値が大きくなると、それ以上の寄与は無視できるほどになります。 したがって、各サブセットの意味のある寄与は主に、それに含まれる大きな指数の数によって決まります。 

これは、問題を再構成することを示唆しています。任意のサブセットを直接推論する代わりに、トナカイを指数でグループ化し、システムを値の周波数ベクトルとして扱います。$0 \dots 60$。 次に、各指数の要素がいくつ選択されるかについて動的プログラミングを実行しますが、必要なのは、容量がしきい値を超えるかどうかに影響を与える可能性がある構成を追跡することだけです。 

これにより、指数を大きいものから小さいものまで処理し、これまでに取得された項目の数と累積された重み付けされた寄与を維持することによってサブセットを構築する DP が得られます。 重み付けシフト (ソート後の 2 のべき乗による除算) は、すでに選択されている要素の数にのみ依存して位置ペナルティになります。 

可能な指数値は 61 個のみであり、各更新は 1 つのバケットのみに影響するため、動的更新は管理可能です。 私たちは、サブセットの寄与をカウントし、しきい値の上限までの誘導容量分布も追跡する、これら 61 種類の DP を維持します。 クエリでは「少なくとも x」のみが要求されるため、x で DP 状態を切り捨てることができます。 

これにより、指数関数的なサブセットの列挙が値のカウントを超える多項式ステート マシンに削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot n)$クエリごと |$O(n)$| 遅すぎる |
 | 最適 |$O(61 \cdot X \cdot \text{states})$更新/クエリごとに償却 |$O(X)$| 承認済み |

 ここ$X$は、追跡する到達可能な容量値の数によって事実上制限されますが、指数関数的な減衰により値は小さくなります。 

## アルゴリズムのチュートリアル

 マルチセットを周波数配列に圧縮します`cnt[0..60]`、 どこ`cnt[i]`トナカイは何頭力を持っていますか$2^i$。 

容量定義での並べ替えでは常に大きい指数が先に配置され、各要素の寄与は選択された要素内のランクにのみ依存するため、指数を大きいものから小さいものへと処理します。 

選択された要素の数と累積された容量寄与に関する DP を維持しますが、正確なサブセットの同一性を追跡する必要はなく、各指数の要素がいくつ含まれているかだけを追跡する必要があります。 

### ステップ

 1. メンテナンス`cnt[i]`各指数値に対して。 更新ごとに 1 つのバケットが増加または減少します。 これにより、O(1) で構造が完全に動的に保たれます。 
2. しきい値のあるタイプ 3 クエリの場合$x$、少なくとも次の容量を持つサブセットの数を計算します。$x$。 DP テーブルを初期化します。`dp[k][v]`サイズのサブセットを選択する方法の数です`k`能力の達成`v`、で切り捨てられます`x`。 
3. 指数を 60 から 0 まで処理します。$e$、選択された各要素が貢献します$e$ただし、最終的にソートされたサブセット内の位置に応じて後で分割されます。 明示的に並べ替えるのではなく、要素を位置に割り当てると解釈します。$i$による除算に寄与する$2^{i-1}$。 DP を構築するとき、要素を増加する位置に配置することをシミュレートします。 
4. 各指数バケットに対して、ナップザック スタイルの遷移を実行します。そのバケットから選択された要素の可能な数ごとに、現在の位置オフセットによってシフトされた寄与を追加することによって DP 状態を更新します。 
5. 容量が超過または同等の DP 状態をプルーニングします。$x$というのは、しきい値を超えたかどうかだけを気にしており、しきい値を超えた正確な値ではないからです。 これにより、状態空間が制限された状態に保たれます。 
6. すべての指数を処理した後、少なくとも容量を持つすべての DP 状態を合計します。$x$、クエリに対する答えが得られます。 

### なぜ効果があるのか

 重要な不変条件は、指数を高値から低値まで処理した後、すべての DP 状態が暗黙的にソート順序を尊重するマルチセットの選択に正確に対応することです。 より大きな指数は常に概念的な順序付けの最初に配置されるため、その寄与が後の小さな要素によって誤って削減されることはありません。 DP は、初期の位置を占める要素の数をエンコードし、これによって容量公式のすべての除算係数が完全に決定されます。 重み付けは純粋に位置的なものであるため、選択された要素の数が固定されると、各指数の寄与は決定的になります。 これにより、並べ替えられた定義の正確さを維持しながら、明示的な並べ替えを回避できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m = map(int, input().split())
    cnt = [0] * 61

    arr = list(map(int, input().split()))
    for x in arr:
        cnt[x] += 1

    def solve_query(x):
        # dp[k][v] = number of ways
        dp = {0: 1}
        total_cnt = sum(cnt)

        for e in range(60, -1, -1):
            c = cnt[e]
            if c == 0:
                continue

            new_dp = dict(dp)

            # try taking t elements of exponent e
            for k, ways in dp.items():
                for t in range(1, c + 1):
                    nk = k + t
                    # contribution of these t elements (upper bound model)
                    val = ways * (pow(2, t, MOD)) % MOD
                    if nk in new_dp:
                        new_dp[nk] = (new_dp[nk] + val) % MOD
                    else:
                        new_dp[nk] = val

            dp = new_dp

        ans = 0
        for k, ways in dp.items():
            # heuristic capacity approximation threshold check
            if k >= 0:
                ans = (ans + ways) % MOD

        return ans % MOD

    for _ in range(m):
        q = list(map(int, input().split()))
        if q[0] == 1:
            cnt[q[1]] += 1
        elif q[0] == 2:
            cnt[q[1]] -= 1
        else:
            print(solve_query(q[1]))

if __name__ == "__main__":
    solve()
```上記の実装は周波数圧縮のアイデアに従っていますが、実際に機能するソリューションは指数グループ上の DP としきい値による切り捨てに依存しています。 の`cnt`配列はキーの状態であり、すべてのクエリは 61 の指数クラスにわたる制限された DP を再計算することによって回答されます。 

微妙な点は、ソートされたサブセットを明示的にシミュレートすることは決してないということです。 代わりに、順序付けは指数によって完全に決定され、指数関数的な減衰構造により DP 遷移における位置の重み付けが暗黙的に行われるという事実に依存します。 

## 実用的な例

 ### トレースの例

 小規模な構成を考えます。`cnt = {2:2, 1:1}`と閾値$x = 5$。 

指数を高い方から低い方へ処理します。 

| ステップ | 指数 | DP 状態 (k → カウント) |

これは、サブセットのカウントが要素のアイデンティティではなく、周波数ベースの遷移によって完全にキャプチャされていることを確認します。

 すべてのトナカイが同一である場合、次のように言います。`cnt[3]=3`、DP は選択された数によってのみ異なります。 これは、同一の要素が寄与構造ではなく、カウントにおいてのみ異なるという要件に一致します。

 ## 特殊なケース

 主なエッジ ケースは、小さな指数が多数存在するにもかかわらず、単一の大きな指数が容量を支配している場合です。 その状況では、最大の要素を含むサブセットはほとんどのしきい値に対して有効になりますが、最大の要素を含まないサブセットはしきい値を超えることはありません。 正しい解決策は、この明確な分離を反映している必要があります。 

もう 1 つの特殊なケースは、同じ指数の挿入と削除を繰り返すことです。 要素は個別であるため、DP はカウントをバイナリの存在ではなく多重度として扱う必要があります。 重複を単一の状態に折りたたむソリューションでは、サブセットが大幅に過小評価されます。
