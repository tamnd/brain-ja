 ## 解決策
 ## 問題の理解

 Monocarp は、限られた予算でできるだけ多くの友達を幸せにしたいと考えています。 彼にはたくさんの友達と一連の箱があります。 各ボックスには美しさの値があり、各友人には 3 つの要件があります。つまり、気になる最小のボックスの美しさ、最小のギフトの値、およびボックスに関係なく幸福を保証するより高いしきい値のギフトの値です。 Monocarp が使えるのは最大でも`k`合計コインがあり、各ボックスには最大 1 つのギフトを入れることができます。 課題は、これらの制約を考慮して、満足する友人の数を最大化することです。 

入力により複数のテスト ケースが提供されます。 各テスト ケースに対して、友達の数、ボックスの数、利用可能なコインの合計、各ボックスの美しさ、および 3 つの数字が与えられます。`x_i`、`y_i`、 そして`z_i`それぞれの友人のために。 出力はテスト ケースごとに 1 つの整数で、幸せになれる友達の最大数を示します。 

制約は大きいです。 1 つのテスト ケースには最大 200,000 のフレンドまたはボックスを含めることができます。`k`10^15 までの大きさになる可能性があります。 これにより、考えられるすべてのギフトボックスの割り当てやギフトの値の組み合わせを試みる強引なアプローチが即座に排除されます。 フレンドとボックスのすべての組み合わせを考慮した単純な解決策では、複雑さは O(n * m) となり、最大 4 * 10^10 の演算となり、実行不可能です。 

慎重な対応が必要なエッジケースには、すべての箱の美しさが低すぎて、お金を使いすぎることなく友人を満足させることができない場合や、予算が最低限のギフトを買うのにかろうじて十分であるが、より高い敷居を高くするには十分ではない場合が含まれます。 コインがすべてを満たすのに十分な場合、別のトリッキーなシナリオが発生します。`y_i`価値観はあるが、1つも買う余裕がない`z_i`価値があり、箱の美しさが不十分です。 たとえば、次の場合`k = 5`、`boxes = [1]`、そして一人の友人は`x=2, y=3, z=6`、その場合、手頃な価格の唯一のギフトは`y=3`、しかし、箱の美しさが低すぎるため、幸福は保証されません。 正しい答えは`0`。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての方法で各ボックスを友人に割り当て、その割り当てに対して幸福を満たすために最低限必要なギフトを計算し、予算が満たされているかどうかを確認します。`k`それを許可します。 このアプローチは、すべての可能性を考慮し、正確性を保証するため機能します。 ただし、最大 200,000 のフレンドとボックスの場合、割り当ての数は階乗スケールであり、単純な二重ループでフレンドとボックスを直接ペアリングしようとしても結果は O(n * m) となり、遅すぎます。 

重要な洞察は、友人は次の 2 つのことだけを気にしているということです。箱の美しさが彼らの閾値を超えているかどうかです。`x_i`またはギフトの価値が少なくとも`z_i`。 ギフトはいつでも下限を満たすことができます`y_i`予算の制約を満たすために。 これにより、問題をボックスと友達の間のマッチングの問題として扱うことができ、より高いしきい値を使用して幸せになる友達の数を最大化することを目指します。`z_i`必要に応じて。 関連するしきい値によってボックスとフレンドを並べ替え、貪欲な 2 ポインタまたは二分探索アプローチを使用することで、予算を超過することなく、どのフレンドが利用可能なボックスに満足できるかを効率的に判断できます。 

具体的には、友達を降順に処理すると、`x_i`（ボックス要件）、友人の要望を満たす利用可能な最高のビューティー ボックスを割り当てます。`x_i`、その場合、ボックスで満足できない友人は少なくともギフトを受け取らなければなりません`z_i`予算が許せば。 すべての合計`y_i`に適合することが保証されています`k`、したがって、価値のある贈り物の追加費用のみを考慮する必要があります。`z_i`。 ソートにより O(n log n + m log m) の効率が得られ、2 ポインタまたはバイナリ検索により、以前の決定を再検討することなく貪欲にボックスを一致させることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m) | O(n + m) | 遅すぎる |
 | ソート + 貪欲 + ツーポイント | O(n log n + m log m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ボックスの美しさの配列を昇順に並べ替えます。 これにより、2 ポインターまたは二分検索を使用した効率的なマッチングが可能になります。 
2. 友達ごとに、ボックス要件を満たすことができるかどうかを判断します。 これを行うには、友達を降順で並べ替えます`x_i`どのボックスが利用可能かを追跡します。 
3. 友人を繰り返して、少なくとも美しさを持つ利用可能な最小のボックスを割り当ててみます。`x_i`。 このボックスを使用済みとしてマークします。 これにより、ボックスが二重にカウントされなくなります。 
4. 適切なボックスを割り当てることができない友達の場合は、追加で必要なコインを計算します。`y_i`彼らを幸せにするために（`z_i - y_i`）。 これらの追加コストの現在までの合計を維持します。 
5.追加費用の合計が超過した場合`k - sum(y_i)`、より高いしきい値のギフトに友人を割り当てるのをやめてください。 この時点までに割り当てに成功した友達の数が、達成可能な最大の幸福になります。 
6. 合計`y_i`常に ≤`k`, そのため、必須の最低限のギフトを支払った後の残りの予算は、これらの追加費用に使用できます。 

機能する理由: ボックスと友達を並べ替えることで、各友達が最低限必要なリソース (ボックスまたは追加のコイン) に一致することが保証されます。 最大の要件を最初に処理することで、要件の低い友人によって小さな箱の美しさが消費され、要件の高い友人が満足できないままになるというシナリオを回避します。 不変条件は、検討された友人がいずれかを満たすボックスに一致していることです。`x_i`または、到達するための追加のコインで説明されます`z_i`。 ボックスは最大 1 回使用され、追加のコインは残りの予算と照合されるため、オーバーコミットメントは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        boxes = sorted(map(int, input().split()))
        friends = []
        sum_y = 0
        for _ in range(n):
            x, y, z = map(int, input().split())
            friends.append((x, y, z))
            sum_y += y
        
        friends.sort(reverse=True)  # sort descending by x_i

        used = [False] * m
        happy = 0
        extra_needed = []

        j = m - 1  # pointer to the largest available box
        for x, y, z in friends:
            while j >= 0 and boxes[j] >= x:
                j -= 1
            if j < m - 1:
                happy += 1  # friend happy with a box
            else:
                extra_needed.append(z - y)

        extra_needed.sort()
        remaining = k - sum_y
        for cost in extra_needed:
            if remaining >= cost:
                remaining -= cost
                happy += 1
            else:
                break

        print(happy)

if __name__ == "__main__":
    solve()
```コードは入力を効率的に読み取り、各テスト ケースを個別に処理します。 友達は降順にソートされます`x_i`最初に最大の要件を満たす可能性を最大限に高めるためです。 ボックスは最低限必要な美しさをすぐに見つけるために分類されます。 の`extra_needed`アレイは、ボックスに満足できない友人のために追加のコインコストを収集します。 仕分け`extra_needed`最小コストから最大コストまで予算を貪欲に使い、幸せな友人の数を最大化します。
