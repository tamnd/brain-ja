 ## 解決策
 ## 問題の理解

 双方向の道路で結ばれた都市のグラフが与えられています。 各道路には正確に 1 ステップのコストがありますが、バイナリ属性も持ちます。 普通の道路もあれば、高価な「橋」の道路もあります。 重要な制限は、開始都市から博物館都市まで移動するときに、合計で最大でも 1 つの橋の端を通過できることです。 

都市の一部には博物館が含まれています。 すべての都市について、経路に沿って複数の橋を使用できないという制約の下で、博物館に到達するための最短の移動距離 (エッジの数で測定) を知りたいと考えています。 そのようなパスが存在しない場合、答えは -1 です。 

グラフのサイズは大きく、最大 200,000 のノードとエッジがあるため、どのソリューションも線形または線形演算に近いものでなければなりません。 ノードごとの直接最短パス検索には、O(nm) または O(nm log n) のような値が必要になりますが、これは大きすぎます。 単一のマルチステート BFS であっても、再計算を回避する場合にのみ許容されます。 

微妙な点は、制約がエッジごとやクエリごとではなく、パスごとにグローバルであることです。ブリッジを使用すると、同じルート内で後から別のブリッジを使用することはできません。 これにより、標準的な最短経路問題が階層化された状態の問題に変わります。 

いくつかの特殊なケースが重要です。 

都市そのものが博物館である場合、エッジに関係なく答えはゼロです。 たとえば、n = 3 で都市 2 が博物館の場合、answer[2] = 0 となります。 

都市が 2 つ以上の橋を使用しなければ博物館に到達できない場合、たとえ実際の最短経路が短くても、その橋は拒否されなければなりません。 たとえば、長さが 2 であるが 2 つのブリッジを使用するパスは無効です。 

制約を無視しても経路がまったく存在しない場合、答えは -1 になります。 

## アプローチ

 単純なアプローチでは、BFS またはダイクストラを使用してすべての都市から任意の博物館までの最短経路を計算し、横断中に使用された橋の数を追跡します。 各状態は (node, used_bridge_count) になります。used_bridge_count は 0 または 1 です。 

これはすでに正しい定式化を示唆しています。つまり、2n 個のノードを持つ状態拡張グラフ内で効果的に検索を行っています。 各状態からすべての隣接するエッジをトラバースし、必要に応じてブリッジ数を増やし、1 を超える遷移を拒否します。各ソースから BFS を実行すると、同じ検索構造を n 回繰り返すため、コストが高くなりすぎます。 

重要な観察は、思考の方向を逆転できるということです。 すべての都市から開始する代わりに、すべての博物館から同時に開始できます。 任意のノードから最も近い有効な博物館パスまでの最小距離が必要なので、マルチソース BFS は自然です。 

ただし、「ブリッジは 1 つまで」という制約があるため、プレーンな BFS では十分ではありません。 すでに橋を使用したかどうかを追跡する必要があります。 これにより、各ノードが 2 つのレイヤーで表示されるレイヤード BFS が得られます。1 つはこれまでにブリッジを使用しなかったレイヤー、もう 1 つは 1 つのブリッジを使用したレイヤーです。 

次に、両州のすべての博物館から単一の BFS を実行します。 通常のエッジを横切るたびに、同じ状態が維持されます。 ブリッジのエッジを通過するたびに、状態 0 から状態 1 に移動するだけです。状態 1 はそれ以上のブリッジを通過することはできません。 

BFS は距離の増加順にノードを処理するため、最初に到達した状態が最適になります。

 | --- | --- | --- | --- |
 | 状態追跡を備えたノードごとの BFS | O(n(m+n)) | O(n) | 遅すぎる |
 | 拡張状態でのマルチソース BFS | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 各都市を 2 つの状態でモデル化します。状態 0 はまだ橋を使用していないことを意味し、状態 1 はすでに 1 つの橋を使用していることを意味します。 

博物館にいるということはすでに目標を満たしているため、両方の州のすべての博物館都市から距離 0 で開始して BFS を実行します。

(ノード、状態) にわたる距離配列を維持します。 また、処理する状態のキューも維持します。 

1. 両方の状態のすべての距離を無限大に初期化します。 
2. すべての博物館都市 s について、dist[s][0] = 0 および dist[s][1] = 0 を設定し、両方の状態を BFS キューにプッシュします。 これは、すでに有効なエンドポイントに到達しており、外側への伝播を開始できることを反映しています。 
3. キューが空でない間に、pop (u, state) を実行します。 これは、指定された数のブリッジを使用して u に到達する既知の最短の方法を表します。 
4. 各エッジ (u、v、t) について、遷移を検討します。 

t = 0 (通常の道路) の場合、コスト +1 で (v, state) に移動します。 

t = 1 (ブリッジ) の場合、状態 = 0 の場合にのみ遷移できます。その場合、コスト +1 で (v, 1) に移動します。 

無効な遷移は、最大 1 つのブリッジの制約に違反するため、無視されます。 
5. dist[v][new_state] を改善する場合は、それを更新し、新しい状態をキューにプッシュします。 
6. BFS が終了すると、各ノード i の答えは min(dist[i][0], dist[i][1]) になります。 両方が無限の場合、-1 を出力します。 

これが機能する理由は、頂点が (city, used_bridge_count) である拡張グラフ上で BFS が実行されるという事実から来ています。 元のグラフ内のすべての有効なパスは、この拡張されたグラフ内の 1 つのパスに正確に対応し、その逆も同様であり、すべてのエッジに単位重みがあります。 したがって、BFS はこの状態グラフでの最短距離を保証し、2 つの状態にわたって最小化することで最適な有効なルートが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

INF = 10**18

def solve():
    n, m, k = map(int, input().split())
    museums = list(map(int, input().split()))

    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, t = map(int, input().split())
        g[u].append((v, t))
        g[v].append((u, t))

    dist = [[INF] * 2 for _ in range(n + 1)]
    q = deque()

    for s in museums:
        dist[s][0] = 0
        dist[s][1] = 0
        q.append((s, 0))
        q.append((s, 1))

    while q:
        u, state = q.popleft()
        d = dist[u][state]

        for v, t in g[u]:
            if t == 0:
                ns = state
            else:
                if state == 1:
                    continue
                ns = 1

            if dist[v][ns] > d + 1:
                dist[v][ns] = d + 1
                q.append((v, ns))

    out = []
    for i in range(1, n + 1):
        ans = min(dist[i][0], dist[i][1])
        out.append(str(-1 if ans == INF else ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、エッジ タイプを保持したグラフを構築します。 距離テーブルにはノードごとに 2 つの列があり、ブリッジが使用されているかどうかに対応します。 BFS はすべての博物館の状態から開始されるため、単一の情報源からではなく、最も近い博物館までの距離が計算されます。 

重要な実装の詳細は、各博物館の両方の状態をゼロに初期化することです。 これにより、「まだブリッジが使用されていない」状態または「すでに使用されているブリッジ」状態のいずれかを一貫して伝播できるため、逆推論でブリッジがすぐに使用される場合の開始条件の特殊なケースが回避されます。 

遷移ロジックは、状態 1 からのブリッジの通過をブロックすることにより、制約を慎重に適用します。

 ## 特殊なケース

 重要なエッジケースは、都市が博物館であり、外部への直接の橋の多い経路がある場合です。 たとえば、博物館ノードがブリッジ チェーンのみを介して接続する場合でも、両方の状態をゼロ距離で初期化します。 BFS は外側に正しく拡張されますが、どのパスでも複数のブリッジが許可されることはないため、距離は有効なままになります。 

もう 1 つのケースは、同じノード間の複数の平行エッジ (1 つのノーマル エッジと 1 つのブリッジ) です。 両方のエッジが独立して処理され、通常のエッジが利用可能な場合には常に安価または同等の状態遷移を提供するため、アルゴリズムはこれを自然に処理します。 

最後の微妙なケースは、最適なパスが開始点のすぐ隣ではなく、中間のどこかにある橋を使用する場合です。 状態ベースの BFS は、ブリッジを消費する決定はそのエッジが実際に最短の拡張順序で通過されるまで延期されるため、これが自然にキャプチャされることを保証します。
