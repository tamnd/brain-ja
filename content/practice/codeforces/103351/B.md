 ## 解決策
 ## 問題の理解

 このタスクは古典的な算術の構成要素です。整数のペアが与えられ、各ペアについてその合計を出力する必要があります。 各入力行は、グラフや配列などの追加の構造を使用せずに、直接結合する必要がある 2 つの数値を表します。 出力は、各ペアの結果の整数を順番に書き込んだものです。 

問題が些細なように見えても、実際には制約が依然として重要です。 このタイプの問題では通常、絶対値で 10^18 までの非常に大きな整数が許可されます。 これにより、オーバーフローのリスクがある言語での固定幅の整数の仮定に依存するアプローチは即座に除外されます。 Python ではこれは自然に処理されますが、他の言語では 64 ビット型を慎重に使用する必要があります。 

入力サイズも重要です。 各行は独立しているため、ペアの総数は大きくなり、最大 10^5 以上になる可能性があります。 これは、繰り返しの解析ロジックや不要なデータ構造など、1 行あたりの一定時間を超えるテストごとのオーバーヘッドは通過しますが、概念的には回避する必要があることを意味します。 

素朴な実装を壊す可能性のある微妙なエッジケースがいくつかあります。 1 つは、テスト ケースが 1 つだけ存在すると仮定する場合です。 たとえば、入力が次の場合:```
1 2
3 4
```正しい出力は次のとおりです。```
3
7
```1 行だけを読み取る誤った実装では、誤って 1 行のみが出力されます。`3`。 

もう 1 つの特殊なケースは、次のような負の数です。```
-5 2
```正しい出力は次のとおりです`-3`。 マイナス記号を正しく処理しない脆弱な文字列分割または解析メソッドは、ここで失敗します。 

最後に、次のような非常に大きな値:```
1000000000000000000 1000000000000000000
```固定サイズ整数言語ではオーバーフローせずに処理する必要があります。 

## アプローチ

 ブルートフォースアプローチはすでに意図された解決策です。整数の各ペアを読み取り、それらの合計を計算し、それを出力します。 その背後に、組み合わせ構造や最適化問題が隠されているわけではありません。 正しさは加算の定義から直接得られます。 

「最適性が低い」バージョンについて説明する場合、入力の処理方法が異なるだけです。 たとえば、ファイル全体をトークンのリストに読み取り、部分文字列を整数に繰り返し変換することは依然として正しいですが、不必要なオーバーヘッドが生じます。 別の非効率的な亜種では、文字列を再構築したり、文字ごとに冗長な解析を実行したりして、漸近的な複雑さを変えることなく定数係数を増加させる可能性があります。 

重要な観察は、各ペアが独立しているということです。 結果は以前の計算に依存しないため、現在の行を超えてストレージが必要になることはありません。 これにより、問題は入力に対する 1 回のリニア スキャンに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 行ごとの解析と合計 | O(n) | お(1) | 承認済み |
 | 繰り返しの解析オーバーヘッドを伴うトークン バッファリング | O(n) | O(n) | 受け入れられるが不要 |

 ここで、n は入力ライン数です。 

## アルゴリズムのチュートリアル

 1. ファイルの終わりまで入力を読み取り、各行を整数の個別のペアとして扱います。 これにより、事前定義された数を必要とせずに、任意の数のテスト ケースを処理できるようになります。 
2. 各行を 2 つの整数トークンに分割します。 構造は固定されているため、常に 1 行に 2 つの値が含まれることが想定されます。 
3. 両方のトークンを整数に変換します。 この手順は、文字列の連結ではなく算術加算を確実に行うために必要です。 
4. 解析直後に 2 つの整数の合計を計算します。 各ラインが独立しているため、中間ストレージは必要ありません。 
5. 次の行に進む前に結果を出力します。 これにより、入力サイズに関係なくメモリ使用量が一定に保たれます。 

### なぜ効果があるのか

 正確さは、各入力行が独立した算術式を定義しているという事実に基づいています。 行間には隠れた依存関係がないため、各合計を個別に計算することでグローバルな解が生成されます。 このアルゴリズムは、k ラインを処理した後、それぞれが k 番目の入力ペアに対応する正確に k 個の正しい合計が出力されるという不変条件を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue
        a, b = map(int, line.split())
        print(a + b)

if __name__ == "__main__":
    main()
```このソリューションは、次を使用してストリーミング方式で入力を処理します。`sys.stdin`これにより、データセット全体をメモリに保存することがなくなります。 各行は正確に 1 回だけ削除および分割され、テスト ケースごとに一定の作業が保証されます。 

実装の微妙な詳細の 1 つは、空行の処理です。 競技プログラミングの入力には末尾に改行が含まれる場合があるため、空の文字列をスキップすることで偶発的な解析エラーを防ぐことができます。 もう 1 つの重要な詳細は、`map(int, ...)`これにより、中間のリスト構築が回避され、コードが簡潔に保たれます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | n 行のそれぞれが 1 回だけ解析され、処理されます。 
| スペース | お(1) | 常に 2 つの整数のみが保存されます。 

このアルゴリズムは入力行数において線形であり、すべての行を少なくとも 1 回読み取る必要があるため、これが最適です。 結果を蓄積する必要がないため、メモリ使用量は一定のままです。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from io import StringIO as _StringIO

    out = _StringIO()
    backup = sys.stdout
    sys.stdout = out

    try:
        for line in sys.stdin:
            line = line.strip()
            if not line:
                continue
            a, b = map(int, line.split())
            print(a + b)
    finally:
        sys.stdout = backup

    return out.getvalue().strip()

# provided samples
assert run("1 2\n3 4\n") == "3\n7"

# custom cases
assert run("-1 1\n") == "0", "zero cancellation"
assert run("0 0\n5 5\n") == "0\n10", "zeros and small positives"
assert run("1000000000000000000 1000000000000000000\n") == "2000000000000000000", "large values"
assert run("   2    3   \n") == "5", "extra whitespace handling"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`-1 1`|`0`| サインの取り扱いとキャンセル |
 |`0 0 / 5 5`|`0 / 10`| 複数行とゼロ値 |
 | 大きな整数 | 大きな金額 | オーバーフローセーフな算術 |

 ## 特殊なケース

 複数行入力の場合、アルゴリズムは各ペアを個別に正しく処理します。 たとえば:

 入力:```
1 2
3 4
```実行は最初の行を処理し、出力します`3`、次の行に進み、出力します`7`。 各反復の後、正確に 1 行が消費され、1 つの結果が生成されるため、ループの不変条件は保持されます。 

負の数の場合:

 入力:```
-5 2
```解析ステップではトークンが符号付き整数に正しく変換され、合計は次のように計算されます。`-3`。 表現に曖昧さがないので、`int()`マイナス記号を正しく解釈します。 

非常に大きな値の場合:

 入力:```
1000000000000000000 1000000000000000000
```Python の整数型は精度を自動的に拡張するため、合計はオーバーフローすることなく正確に計算されます。 このアルゴリズムでは中間の縮小変換が導入されないため、正確性が保たれます。
