 ## 問題の理解

 長さの循環構造が与えられています$n$、ここで、非表示配列内の各位置$a$観測値を生成します$b_i$次の近隣とのモジュロ演算を通じて。 具体的には、それぞれの値$b_i$ときの余りです$a_i$で割られる$a_{i+1}$、最後の要素が最初の要素に折り返されます。 

タスクは何かを計算することではありません$a$、ただし、このプロセスを逆にします。 剰余のみが与えられるので、正の整数配列が存在するかどうかを判断する必要があります。$a$それがそれらを生成した可能性があり、その場合は、1 つの有効な解決策を構築します。 

制約$n \le 1.4 \cdot 10^5$の値をブルートフォースしようとするアプローチを除外します。$a_i$またはポジションごとに候補者を検索します。 それぞれ$a_i$と同じ大きさにすることができます$10^{18}$これは、有効な構造が反復推測ではなく直接算術構造に依存する可能性が高いことを示唆しています。 

微妙な問題は循環依存性に起因します。 地元の選択肢$a_i$両方に影響を与える$b_{i-1}$そして$b_i$したがって、グローバルな一貫性のない貪欲なフォワード構築は失敗する傾向があります。 

いくつかのエッジパターンは特に危険です。 

多少なら$b_i = 0$、それは暗示します$a_i$の倍数です$a_{i+1}$、相対的なサイズを強く制限します。 可分性の連鎖を無視した単純な構造は、サイクルの後半で矛盾を引き起こす可能性があります。 

もしすべてなら$b_i$隣接するものと比べて大きく、特に の潜在的な値に近い$a_{i+1}$、不注意な割り当ては厳格な要件に違反する可能性があります$b_i < a_{i+1}$。 

最後に、循環一貫性が主な隠れた罠です。 たとえあらゆる局所的な制約があったとしても$b_i < a_{i+1}$が満たされていても、構築がグローバルに同期されていない限り、最後の方程式は依然として失敗する可能性があります。 

## アプローチ

 強引なアイデアは、それぞれを処理することです$a_i$を変数として使用し、値を順番に割り当ててみます。 それぞれのポジションについて、次のことを選択します。$a_{i+1}$十分な大きさなので、$a_i \mod a_{i+1} = b_i$。 これはつまり$a_i = k \cdot a_{i+1} + b_i$そして、整数の乗数を推測する必要があります。$k \ge 1$。 最悪の場合、各ステップは多くの可能性に分岐し、これらの制約がサイクル全体に伝播すると、指数関数的な爆発につながります。 最後の制約によって以前のすべての選択が無効になる可能性があるため、最小限の値に制限しても役に立ちません。 

重要な観察は、モジュロ方程式が非常に構造化された形式であるということです。 直したら$a_{i+1}$、 それから$a_i$等差数列になければなりません。 前進する代わりに、推論を逆にすることもできます。つまり、すべてを選択することで一貫性を確保しようとします。$a_i$すべての制約が同時に実現できるように十分な大きさにする必要があります。 

中心となるトリックは、各方程式を再解釈することです。$$a_i = k_i \cdot a_{i+1} + b_i, \quad k_i \ge 1$$これは直ちに次のことを意味します。$$a_i \ge a_{i+1} + b_i$$したがって、順序を任意にすることはできません。 サイクル全体に伝播する下限系を満たさなければなりません。 開始点を選択してすべての不等式を満たそうとすると、問題を周期的制約を考慮した一貫したサイズの割り当てを見つけることに帰着させることができます。 

建設的な解決策は、すべての移行の実現可能性を保証する「ベースライン スケール」を選択することで機能します。 このようなスケールが存在すると、それぞれを定義できるようになります。$a_i$順伝播と一致する最小値として、すべてのモジュラー剰余が正確に一致するようにします。

 ## アルゴリズムのチュートリアル

 モジュロ関係から派生した不等式を通じて一貫性を強制することにより、有効な配列を構築します。 

1. 各エッジについて$i$、条件を書き換えます$b_i = a_i \bmod a_{i+1}$として$a_i \ge a_{i+1} + b_i$または$a_i = b_i$いつ$a_i < a_{i+1}$。 これは、すべてのペアが相対的なサイズに対して厳密な構造的制約を課していることを示しています。 
2. 選択した場合は、次のことを観察してください。$a_{i+1}$、有効な最小値$a_i$まさに$a_i = a_{i+1} + b_i$不必要なスケーリングを行わずに最大限の一貫性を維持したいときはいつでも。 これは、各値が前の値を決定する順伝播モデルを示唆しています。 
3. 1 つの位置に任意の開始値を選択してサイクルを断ち切ります。$a_1$、そして再帰を使用してすべての値を前方に伝播します。$$a_{i+1} = \max(b_i + 1, \text{minimum value consistent with previous constraints})$$これにより、モジュロ制約が常に保持されることが保証されます。$a_{i+1} > b_i$。 
4. 候補配列を構築した後、すべての制約を検証します。$a_i \bmod a_{i+1} = b_i$。 どれかが失敗した場合、解決策は存在しません。 
5. 推測ではなく、恣意的なスケーリングの問題を回避するため$a_1$、各制約が可能な限り厳密に満たされる、慎重に選択されたアンカーから逆にシーケンスを構築します。 これにより、決定的な候補が生成されます。 
6. 完全な配列が構築されたら、有効であれば出力します。 

### なぜ効果があるのか

 各拘束力$a_i$合同クラスモジュロで嘘をつく$a_{i+1}$、しかし不等式$b_i < a_{i+1}$それを保証します$b_i$は、有効な解の剰余です。 すべてのステップが維持されるようにシーケンスを構築することで、$a_{i+1} > b_i$誘導された下限を尊重します$a_i \ge a_{i+1} + b_i$、すべてのモジュラー方程式が正確に満たされることを保証し、この構築では矛盾する剰余要件が決して導入されないため、サイクルが一貫して終了します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    b = list(map(int, input().split()))
    
    # We will construct a[i] by enforcing:
    # a[i] = k * a[i+1] + b[i], choose minimal k to keep values bounded
    a = [0] * n
    
    # Start from last element arbitrarily
    a[0] = max(b[0] + 1, 1)
    
    # Forward construction
    for i in range(1, n):
        a[i] = b[i-1] + 1
        if a[i] <= b[i]:
            a[i] = b[i] + 1
    
    # Fix consistency by ensuring constraints hold
    for i in range(n):
        j = (i + 1) % n
        if a[i] % a[j] != b[i]:
            # try to adjust multiplicatively
            k = (a[i] - b[i]) // a[j] if a[j] else 0
            if k <= 0:
                k = 1
            a[i] = k * a[j] + b[i]
    
    for i in range(n):
        j = (i + 1) % n
        if a[i] % a[j] != b[i]:
            print("NO")
            return
    
    print("YES")
    print(*a)

if __name__ == "__main__":
    solve()

 ## 特殊なケース

 重大なエッジケースは、次のような場合です。$b_i = 0$。 この状況では、あらゆる制約は次のようになります。$a_i \bmod a_{i+1} = 0$、強制的に$a_{i+1} \mid a_i$。 したがって、有効な構造は乗法連鎖を作成する必要があります。 アルゴリズムは、最終調整フェーズで前の値を除算するのに十分な大きさの次の各値が選択されるようにすることでこれを処理します。 

もう 1 つのエッジケースは、次のような場合です。$b_i$以前に選択したものに近い$a_{i+1}$。 たとえば、次の場合$b_i = 10^5$そして$a_{i+1} = 10^5 + 1$、 それから$a_i$少なくとも$2 \cdot a_{i+1} + b_i$モジュロ構造への違反を避けるため。 乗算補正ステップは、スケーリングによってこれを保証します。$a_i$残りの条件が正確に一致するまで上向きに進みます。 

最後の微妙なケースは、ローカル修正後の周期的な不一致です。 すべてのペアが個別にモジュロ方程式を満たしている場合でも、最後のエッジでサイクルが中断される可能性があります。 最後の検証ループはこの状況を直接検出し、サイレントエラーではなく拒否によって正確さを保証します。
