 ## 解決策
 ## 問題の理解

 整数グリッド上に動的な点のセットを維持します。 セットは挿入と削除によって時間の経過とともに変化します。 時折、仮定の質問を受けることがあります。原点と特定の方向点を通る線を引いた場合、現在のセットがその線に対して完全に対称になるようにするには、さらにいくつの点を追加する必要がありますか。 

ここでの対称とは、現在セット内にあるすべての点について、指定された線を横切る鏡面反射もセットに属している必要があることを意味します。 この操作ではポイントを削除することはできません。不足しているミラーリングされた対応部分を追加するだけです。 タイプ 3 の各クエリは独立しているため、永続的に変更することなく、その時点の現在のセットのみに基づいて対称性を評価します。 

最大 200,000 のクエリ、最大 100,000 のアクティブ セットの変更、最大 100,000 の対称クエリという制約により、完全に動的なソリューションが必要になります。 クエリごとにすべてのポイントの反射を再計算するアプローチは、単一の対称チェックでもセット全体を反復する必要があるため、非常に時間がかかりすぎます。 

単純な解決策では、タイプ 3 のクエリごとに、セット内のすべての点を反復処理し、その反射を計算します。 原点を通る線を横切る点の反射は、方向ベクトルへの投影に依存し、メンバーシップの確認にはハッシュ セットが必要です。 たとえメンバーシップが O(1) であっても、クエリごとに O(n) を支払うことになり、最悪の場合には約 10¹⁰ の操作が発生することになりますが、これは現実的ではありません。 

点が対称軸上にある場合、より微妙な問題が発生します。 線上にある点はそれ自体を反射するため、ペアの欠落には影響しません。 方向ベクトルとの共線性を明示的に検出しない場合、不注意な実装でもそれらを誤ってカウントする可能性があります。 

もう 1 つの特殊なケースは、方向性クエリの重複です。 各クエリは異なる対称軸を使用するため、固定方向に関連付けられた前処理は役に立ちません。 ソリューションでは、任意の方向を基準にしてジオメトリを再計算するか、効率的にクエリを実行する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、各対称クエリが個別に処理されます。 方向ベクトル v = (x, y) を固定し、一貫した方法で正規化し、セット内の各点 p に対してその反射 p' を計算します。 p' がセットにない場合、答えをインクリメントします。 これは正しいです。欠落しているミラーリングされた各ポイントが 1 つの必要な挿入に対応するからです。 

失敗点はパフォーマンスです。 各クエリはセット全体をスキャンし、最大 105 ポイントと 105 クエリを使用すると、これは 2 次になります。 

重要な観察は、原点を通る線を横切る反射により、方向ベクトルに沿った成分が保存され、直交成分が反転されるということです。 これは座標変換を示唆しています。標準座標で作業する代わりに、クエリ方向によって定義された座標系にすべての点を投影します。 その回転フレームでは、対称性は 1 つの軸上で単純な符号反転になります。 

これは、クエリ方向が固定されている場合、すべての点を垂直方向に沿ったスカラー座標にマッピングでき、対称性はペア値 +t と -t にまで減少することを意味します。 必要な挿入の数は、この 1D マルチセット ビュー内のペアになっていないオカレンスの数と正確に一致します。 

課題は、方向がクエリごとに異なるため、グローバルに変換された構造を維持できないことです。 ただし、各クエリ方向がプリミティブ整数ベクトルによって定義されるという事実を利用することができ、方向を正規化して重複を回避し、クエリ内で計算された射影を効率的に再利用できます。 

単一のクエリ内で、正規化された基底 (dx, dy) とその垂線 (-dy, dx) を計算します。 各点はこの垂直軸に投影され、スカラー値が生成されます。 次に、頻度をカウントし、t を -t と照合します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q・n) | O(n) | 遅すぎる |
 | クエリごとの投影 | O(q・n) 最悪の場合 | O(n) | まだ境界線にありますが、クエリごとのハッシュで最適化されています。 

## アルゴリズムのチュートリアル

 クエリをオンラインで処理し、現在のポイントのセットをハッシュ セットに維持します。 

タイプ 3 のクエリごとに、方向ベクトル (x, y) を構築します。 すべての共線方向が正準表現を共有するように、gcd(x, y) で除算してこれを削減します。 次に、垂直方向 (-y, x) を作成します。 

次に、現在のセット内のすべての点 (px、py) をこの垂直軸に投影します。 投影値は外積です。 

t = px * y - py * x

 点が対称軸上にあるとき、この値は正確にゼロになります。 

ゼロ以外のすべての t 値を頻度マップに保存します。 各 t に対して、-t と組み合わせます。 それぞれの不一致の出現により、必要な挿入が 1 つ発生します。 

### ステップ

 1. アクティブなポイントのハッシュ セットを維持します。 

これにより、O(1) の挿入、削除、およびメンバーシップの追跡が可能になります。 
2. タイプ 1 のクエリの場合、セットにポイントを挿入します。 タイプ 2 の場合は削除します。 

セットには常に現在の構成が反映されます。 
3. 方向 (x, y) のタイプ 3 のクエリの場合、gcd(x, y) で除算して正規化します。 

これにより、等価な行で同一の計算が行われることが保証されます。 
4. セット内のすべての点 (px, py) について、t = px * y − py * x を計算します。 

これは符号付き面積/外積であり、垂直変位を表します。 
5. 周波数マップで点を t でグループ化します。 
6. 各 t > 0 について、それを -t の頻度と組み合わせて、一致しない出現をカウントします。 

答えは、max(0, cnt[t] - cnt[-t]) の合計です。 
7. 合計不一致数を出力します。 

### なぜ効果があるのか

 外積は、すべての点をクエリ ラインに垂直な 1 次元軸にマッピングします。 2 つの点は、ラインに沿って同一の投影を共有しながら、その外積値が互いに負である場合にのみ、ラインを横切る鏡像になります。 追加されたポイントの実際の座標ではなく、存在のみを考慮するため、反対の値によるペアリングでは、欠落した反射が正確にカウントされます。 ゼロ投影の点は軸上にあり、自己対称であるため、ペアの欠落に寄与することはありません。 これにより、幾何学的対称条件が整数に関するマルチセットペアリング問題に帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import Counter
from math import gcd

def solve():
    q = int(input())
    pts = set()
    
    for _ in range(q):
        t, x, y = map(int, input().split())
        
        if t == 1:
            pts.add((x, y))
        elif t == 2:
            pts.remove((x, y))
        else:
            if not pts:
                print(0)
                continue
            
            g = gcd(x, y)
            x //= g
            y //= g
            
            cnt = Counter()
            for px, py in pts:
                val = px * y - py * x
                cnt[val] += 1
            
            ans = 0
            for v in list(cnt.keys()):
                if v > 0:
                    ans += abs(cnt[v] - cnt[-v])
            print(ans)

if __name__ == "__main__":
    solve()
```この実装では、更新が O(1) のままになるように、アクティブ ポイント セットを Python セットに保持します。 クエリごとに、現在のセットから直接対称投影を再計算します。 正規化ステップにより、同一のラインが一貫性のない投影を生成しないことが保証されます。 

外積計算は、中心となる幾何学的プリミティブです。 浮動小数点演算を完全に回避し、すべてを整数に保ちます。これは、座標が大きくなる可能性があるため必要です。 

微妙な点は、キーを 1 回だけ繰り返して、正の値と負の値を比較することで、二重カウントが防止されることです。 ゼロ値は対称軸上に正確に存在するため、無視されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import Counter
    from math import gcd

    q = int(sys.stdin.readline())
    pts = set()
    out = []

    for _ in range(q):
        t, x, y = map(int, sys.stdin.readline().split())
        if t == 1:
            pts.add((x, y))
        elif t == 2:
            pts.remove((x, y))

                out.append("0")

            ans = 0
            for v in cnt:
                if v > 0:
                    ans += abs(cnt[v] - cnt[-v])
            out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースは、すべての点が対称線上に正確に位置する場合です。 その場合、すべての外積はゼロと評価されるため、頻度マップにはゼロ バケットのみが含まれます。 ペアリングが必要なく、正または負のキーが存在しないため、アルゴリズムは正しくゼロを返します。 

もう 1 つのケースは、セットが空の場合です。 投影マップは空であり、アルゴリズムはペアリング ロジックを入力せずにすぐに 0 を返します。 

3 番目のケースには、多くの点が同じ投影値を共有する、非常に偏った分布が含まれます。 この状況でも、絶対差によるペアリングは、ペアになっていない各インスタンスが軸の反対側の欠落したミラーに対応している必要があるため、一致しない要素を正しくカウントします。
