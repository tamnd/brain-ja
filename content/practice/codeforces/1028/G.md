 ## 解決策
 ## 問題の理解

 未知の整数を特定しようとしています$x$～から非常に広い範囲で$1$に$M = 10004205361450474$。 「はい」または「いいえ」で直接質問する代わりに、最大 5 つのクエリを送信することができます。各クエリは整数の増加リストです。 各クエリの後、すぐに次のことを発見します。$x$がリスト内にあるか、その方法を説明する位置ヒントを受け取ります。$x$私たちが提出した順序付けされたシーケンスに関連しています。 フィードバックにより、次のことがわかります。$x$すべての要素より小さいか、すべての要素より大きいか、または 2 つの連続する要素の間に厳密に存在します。 

主な難点は、各クエリに最大でも次の内容を含めることができることです。$10^4$したがって、全範囲を直接カバーすることは期待できません。 同時に、許可されるクエリは 5 つだけであるため、どの戦略でも対話ごとに検索スペースを非常に積極的に削減する必要があります。 

素朴な考えとしては、二分探索のようなことを行うことですが、それには巨大なドメインにわたる 5 つの固定クエリではなく、対数クエリが必要です。 もう 1 つの素朴なアイデアは、範囲を等しいブロックに分割し、段階的に絞り込むというものですが、フィードバックはクエリ シーケンスに対してのみローカルであり、範囲全体にわたってグローバルではないため、これは失敗します。 

微妙なエッジケースは、インタラクターが適応型であることを忘れていることから発生します。 戦略がフィードバック構造に依存しない事前に固定されたパーティションに依存している場合、インタラクターは常に、$x$そのため、最後のクエリまであいまいなままになり、その時点で制約を超えるか、決定性を失います。 

## アプローチ

 ブルートフォースアプローチでは、全範囲にわたって等間隔のグリッドを繰り返しクエリすることで、間隔を狭めようとします。 サイズの各クエリ$k$範囲を分割します$k+1$間隔。 最大値を使用した場合$k = 10^4$、1 つのクエリにより検索スペースが約 1 分の 1 に削減されます。$10^4$。 これを5回繰り返してもまだ不十分です。$M$の順序です$10^{16}$、さらには$(10^4)^5 = 10^{20}$理想的な均一な収縮でのみ十分に見えます。 本当の問題は、各ステップでどの区間に含まれる内容がわかるかだけであるということです。$x$ただし、次のクエリが、シーケンスが増加しており、縮小間隔によって制限されているという制約を尊重することも保証する必要があります。 単純な均一グリッド戦略は、間隔のサイズと位置が十分に厳密に制御されていないため、すぐに脆弱になってしまいます。 

重要な観察は、任意の値の使用を強制されていないことです。 非常に圧縮された方法で位置情報をエンコードするように各クエリを構造化し、基本的に各クエリを大きな基数での答えの複数桁の表現として扱うことができます。 各応答は、どの「桁範囲」に該当するかを正確に示すため、制御された指数関数検索で数値を繰り返し絞り込むことができます。 

間隔を線形に縮小する代わりに、ベースを繰り返し使用します。$k$パーティション分割。 各クエリは、位置記数法で数値の桁を選択するように動作します。各レベルの絞り込みにより、検索スペースが最大 1 分の 1 に縮小されます。$10^4 + 1$。 5 つのクエリを使用すると、最大範囲内の任意の数値を一意に識別するには十分です。$10^{16}$。 

重要なトリックは、常に現在の間隔内の等間隔のポイントをクエリし、その応答を部分間隔の選択として解釈することです。 現在の候補セグメントを維持します$[L, R]$、最初は$[1, M]$。 各クエリはこの間隔を次のように分割します。$k+1$等しいまたはほぼ等しいパーツであり、各パーツの代表点を使用します。 応答インデックスにより、どのサブインターバルに含まれる内容がすぐにわかります。$x$と再帰していきます。

 | --- | --- | --- | --- |
 | ブルートフォースグリッド縮小 |$O(5 \cdot 10^4)$クエリごと、信頼性の低い絞り込み |$O(1)$| 遅すぎる/不安定 |
 | 適応型インターバルパーティショニング (最適) |$O(5 \cdot \log_{10^4} M)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 現在の間隔を維持します$[L, R]$含まれることが保証されているもの$x$。 

1. 私たちが選択します$k = 10^4$（間隔が小さくなるとさらに小さくなります）そして構築します$k$内部のポイントを増やす$[L, R]$。 これらの点は、間隔を次のように分割するように選択されます。$k+1$ほぼ等しいセグメント。 これにより、考えられる各応答インデックスが明確に定義された部分範囲に対応することが保証されます。 
2. シーケンスを出力し、応答を読み取ります。 応答が$-1$、無事に見つかったので即終了します。$x$。 有効なインデックスの場合$i$、間隔が狭くなっていると解釈します。 
3. もし$i = 0$、 それから$x < t_0$ので、更新します$R = t_0 - 1$。 
4. もし$i = k$、 それから$x > t_{k-1}$ので、更新します$L = t_{k-1} + 1$。 
5. それ以外の場合は、$t_{i-1} < x < t_i$ので、更新します$L = t_{i-1} + 1$そして$R = t_i - 1$。 
6. 安全に列挙できるほど間隔が小さくなるまで、またはインタラクターが戻るまで、このプロセスを繰り返します。$-1$。 

これが機能する理由は、各クエリが残りの有効な間隔を最大でも次の間隔に分割するためです。$k+1$互いに素な部分間隔であり、応答は常にどの部分間隔に含まれているかを正確に示します。$x$。 パーティションは厳密に順序付けされており、範囲全体をカバーしているため、次の不変条件が失われることはありません。$x \in [L, R]$、各ステップは約乗算係数によって間隔サイズを縮小します。$10^4$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

M = 10004205361450474
K = 10000

def ask(arr):
    print(len(arr), *arr)
    sys.stdout.flush()
    res = int(input())
    if res == -2:
        sys.exit()
    if res == -1:
        sys.exit()
    return res

def solve():
    L, R = 1, M

    while L <= R:
        if R - L + 1 <= K:
            # final brute force query
            arr = list(range(L, R + 1))
            res = ask(arr)
            return

        step = (R - L + 1) // (K + 1)
        if step == 0:
            step = 1

        arr = []
        for i in range(1, K + 1):
            val = L + i * step
            if val <= R:
                arr.append(val)

        res = ask(arr)

        if res == 0:
            R = arr[0] - 1
        elif res == len(arr):
            L = arr[-1] + 1
        else:
            L = arr[res - 1] + 1
            R = arr[res] - 1

    print(L)
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```実装では、縮小間隔を維持し、各ステップでその間隔の固定サイズのパーティションを構築します。 ステップ サイズは次のように選択されます。$K = 10^4$ポイントは均等に分散され、各応答が部分間隔にきれいにマッピングされるようになります。 

微妙な詳細は、間隔が小さくなった場合の境界ケースの処理です。 その時点で、制約が存在するため、直接列挙クエリに切り替えます。$k \le 10^4$安全に許可します。 もう 1 つの重要な点は、構築されたシーケンスが厳密に増加し、範囲内にあることを確認することです。これは、値を内側にクランプすることによって強制されます。$[L, R]$。 

## 実用的な例

 次のような単純化されたシナリオを考えてみましょう。$M = 100$、$K = 4$、 そして$x = 37$。 

当初は、$[L, R] = [1, 100]$。 点を選択するとします$20, 40, 60, 80$。 インタラクターは次のように応答します。$i = 1$、 意味$x < 20$。 間隔は$[1, 19]$。 

内部の次のクエリ$[1, 19]$：ポイント$4, 8, 12, 16$。 応答が次のようになったとします。$i = 3$、 意味$12 < x < 16$、 それで$[L, R] = [13, 15]$。 

Next query: interval is already small, we may directly query$[13, 14, 15]$。 応答が$1$と結論づけます$x = 14$。 

| ステップ | Ｌ | R | クエリポイント | 応答 | 新しい間隔 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 100 | 20、40、60、80 | 1 | [1、19] |
 | 2 | 1 | 19 | 4、8、12、16 | 3 | [13、15] |
 | 3 | 13 | 15 | 13、14、15 | 見つかりました | 14 |

 このトレースは、各クエリがどのように間隔を乗算的に短縮し、一貫したパーティショニングによって正確さを維持するかを示しています。

 ## 特殊なケース

 境界ケースは、非表示の数値がクエリによって作成された最初または最後のパーティション境界に正確に存在する場合に発生します。 この状況では、次のような応答が返される可能性があります。$i = 0$または$i = k$に対応します。$x < t_0$または$x > t_{k-1}$。 更新ロジックは、正確さを維持しながら、間隔の片側のみを縮小することで、これらのケースを明示的に処理します。 

もう 1 つのエッジ ケースは、間隔が より小さくなる場合です。$K$。 アルゴリズムは直接列挙に切り替わります。 たとえば、次の場合$[L, R] = [10, 15]$の場合、クエリはすべての候補の完全なリストになります。 その後、インタラクターは直接戻ります$-1$または正確な位置を特定して、制限内での終端を保証します。
