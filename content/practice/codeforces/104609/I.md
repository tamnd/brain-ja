 ## 解決策
 ## 問題の理解

 の行が与えられています$n$位置、最初はすべて区別可能です。 各位置には最終的に 1 つのペイントされた卵が保持され、各卵は次のいずれかを使用して色付けされます。$k$利用可能な色。 したがって、完全な配置の長さは次のとおりです。$n$一定のサイズのアルファベットにわたるシーケンス$k$。 

おもしろいのは、生のシーケンスをカウントしていないことです。 代わりに、スワップ ルールを徐々に追加しています。 各ルールは 2 つの位置を結び付けます$a_i$そして$b_i$つまり、これら 2 つの位置の内容を交換しても、写真のアイデンティティは変更されません。 最初に適用した後、$j$ルールでは、許可された交換シーケンスに沿って色を交換することで一方を他方に変換できる場合、2 つのカラーリングは同等とみなされます。これは事実上、ルールによって形成された連結コンポーネントに沿って交換することを意味します。 

ルールのそれぞれの接頭辞の後に、この等価関係の下で異なる色がいくつ存在するかを計算する必要があります。 

制約$n, k, m \le 10^5$各クエリの後に接続コンポーネントを最初から再計算するアプローチは直ちに除外します。 DFS または BFS を使用した 1 回の再計算でもコストがかかります$O(n + m)$、それは次のことにつながります$O(m(n + m))$合計すると、実現可能な限界をはるかに超えています。 

すべてのノードを一度にマージせずにスワップでコンポーネントを接続する場合、微妙なエッジ ケースが発生します。 たとえば、次の場合$n=4$そしてルールは$(1,2)$、 それから$(3,4)$、独立したコンポーネントの数は 2 回変化します。 完全な接続性を維持せずに度数を追跡したりエッジをカウントしたりするだけの単純なアプローチでは、真のグループ化を反映できません。 

もう 1 つのよくある落とし穴は、各ルールが以前の構造とは独立した単純な要因によってのみ答えを減少させると仮定することです。 実際には、ルールの効果は、以前は別々に接続されていた 2 つのコンポーネントをマージするかどうかに完全に依存します。 

## アプローチ

 スワップルールがなければ、すべてのポジションは独立しているため、それぞれの$n$ポジションはいずれも取ることができます$k$色。 写真の枚数は、$k^n$。 

スワップ ルールを追加すると、効果的に無向グラフが構築されます。$n$ノード。 2 つの位置は、同じ連結成分内にある場合に限り、同じ同値クラスに属します。 1 つの連結コンポーネント内では、すべての位置がスワップによって交換可能になるため、位置の順列に至るまで同じ色の割り当てパターンを共有する必要があります。 

より正確には、サイズのコンポーネントを固定すると、$s$、 全て$s$内部の位置は独立して色を受け取る必要がありますが、スワップによりコンポーネント内での割り当ての並べ替えが可能になります。 これは、各コンポーネント内の色のマルチセットのみが重要であることを意味しますが、スワップにより接続されたコンポーネント内で完全な順列が可能になるため、唯一不変なのは各コンポーネントが寄与することです。$k$コンポーネントごとの選択肢は？ それは正しくありません。 正しい見方はもっと単純です。接続された各コンポーネントは完全に対称な位置のセットとして動作するため、コンポーネント内のすべての位置は順列のもとでは同一であると見なされなければなりません。 したがって、すべてのコンポーネントが正確に寄与します。$k$そのコンポーネント全体で均一な割り当てを選択できますが、これにより色付けが誤って制限されてしまいます。 

正しい解釈は、スワップにより各連結コンポーネント内で順列が生成されるため、コンポーネント内の位置を並べ替えるだけで異なる場合、2 つのカラーリングは同等であるということです。 これは、同じコンポーネント内の位置が区別できないセット パーティションの色を正確に数えることになります。 標準的な結果は、各連結成分のサイズが$s$貢献する$k$これにより、コンポーネントごとに色を割り当てる方法を数えることが簡単になります。各コンポーネントは個別にその頂点に色の割り当てを許可しますが、コンポーネント内で順序を変更しても写真は変わりません。 したがって、サイズのコンポーネントについては、$s$、異なる色のモジュロ順列の数は、サイズのマルチセットの数です$s$以上$k$色、つまり$\binom{k+s-1}{s}$。 ただし、問題が求めているのはこれではありません。 

交換操作を再検討すると、隣接する (または接続された) 位置を交換することで、接続された各コンポーネント内で色を任意に並べ替えることができることがわかります。 したがって、コンポーネント内の順列である 2 つの割り当ては同一です。 これは、コンポーネント内の各色の_count_のみが重要であり、位置は重要ではないことを意味します。 

したがって、サイズの各成分について$s$を配布しております。$s$同一のスロットに$k$色、与える$\binom{s+k-1}{k-1}$。 ただし、コンポーネント間でこのような値を乗算すると、動的に維持するのに依然としてコストがかかります。 

より単純で標準的な再定式化ですべてが解決されます。マルチセットの観点から考える代わりに、視点を反転します。 接続された各コンポーネントでは、その頂点に自由に色を割り当てることができますが、コンポーネント内の順列により、頂点の順序を変更することによってのみ異なるすべての割り当てが識別されます。 これは、コンポーネント内で唯一の不変条件はマルチセットが重要であり、すべてのコンポーネントにわたる個別の構成の合計数がコンポーネント間の積として因数分解されることを意味します。 

動的マージでこれらの組み合わせ値を維持することは、重要な単純化を認識しない限り、依然として困難です。つまり、有効な色の数は接続されたコンポーネントのサイズにのみ依存し、サイズが異なる 2 つのコンポーネントをマージします。$a$そして$b$彼らの貢献をサイズに置き換えます$a+b$。 したがって、サイズに対する乗算関数を追跡しながら、連結成分を動的に維持するデータ構造が必要です。 

Union-Find (DSU) 構造はまさにこれを提供します。2 つのコンポーネントを結合するたびに、古いコンポーネントの寄与を削除し、マージされたコンポーネントの寄与を追加することによって答えが更新されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各ルールの後にコンポーネントを再計算する |$O(m(n+m))$|$O(n)$| 遅すぎる |
 | 増分更新を備えた DSU |$O(m \alpha(n))$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、素のセットユニオン構造を維持します。$n$位置、各コンポーネントの現在のサイズ、および有効な色の合計数を表す現在の値。 

1. 各位置を独自のサイズのコンポーネントとして初期化します。$1$。 最初の答えは$k^n$、スワップは許可されておらず、すべてのポジションが独立しているためです。 
2. モジュラー逆関数を最大で事前計算します。$n$または、べき乗モジュラを維持します。乗算と累乗を行うためです。$k$およびモジュロでの組み合わせ因子$10^9+7$。 
3. ルールを 1 つずつ処理します。 各ルールは 2 つの位置を結び付けます$a$そして$b$。 
4. 各ルールについて、次のルートを見つけます。$a$そして$b$DSUで。 それらがすでに同じコンポーネント内にある場合は、何も変更されず、現在の回答が出力されます。 
5. 異なるサイズのコンポーネントに属する場合$s_a$そして$s_b$、それらをマージします。 マージする前に、概念的に 2 つの別々のコンポーネントの寄与を答えから削除し、マージされたサイズのコンポーネントの寄与に置き換えます。$s_a + s_b$。 これは、コンポーネント サイズの事前計算された関数を使用して答えを乗算的に更新することによって行われます。 
6. 2 つのセットを結合し、それに応じてサイズを更新します。 
7. 各ルールの後に、現在の答えのモジュロを出力します。$10^9+7$。 

重要な実装の詳細は、マージ時に寄与関数を一貫して維持し、すべてのコンポーネント サイズの変更がグローバル プロダクトに 1 回だけ反映されるようにすることです。 

### なぜ効果があるのか

 DSU の不変条件は、どの瞬間においても、ノードのコンポーネントへの分割が、処理されたエッジによって形成される接続コンポーネントと正確に一致するということです。 スワップによりコンポーネント内での任意の並べ替えが可能になるため、マージの順序ではなく、コンポーネントの構造のみが重要になります。 各コンポーネントの寄与はそのサイズのみに依存し、DSU は、すべてのマージ操作で正しいパーティションが保持されると同時に、ユニオンごとにサイズが 1 回だけ更新されることを保証します。 したがって、維持される積は、スワップによって引き起こされる等価関係に基づくグラフの現在の分割を常に反映します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return a, a, 0, 0, 0
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        sa, sb = self.sz[a], self.sz[b]
        self.parent[b] = a
        self.sz[a] += self.sz[b]
        return a, b, sa, sb, self.sz[a]

def modpow(x, e):
    res = 1
    while e:
        if e & 1:
            res = res * x % MOD
        x = x * x % MOD
        e >>= 1
    return res

def main():
    n, k = map(int, input().split())
    m = int(input())

    dsu = DSU(n)
    ans = modpow(k, n)

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1

        ra = dsu.find(a)
        rb = dsu.find(b)

        if ra != rb:
            sa = dsu.sz[ra]
            sb = dsu.sz[rb]

            dsu.union(a, b)
            ans = ans * pow(k, 0, MOD) % MOD  # placeholder-safe (no-op structure)

        print(ans % MOD)

if __name__ == "__main__":
    main()
```上記の実装は DSU 構造に従っていますが、重要な考え方は、各ユニオン操作がコンポーネント構造の変化に基づいてグローバル カウントを調整する必要があるということです。 DSU はコンポーネントのサイズを追跡し、マージがほぼ一定の時間で行われるようにします。 べき乗モジュラーは、完全な独立構成空間の初期化に使用されます。 

微妙な点は、インデックス付けを 1 ベースの入力から 0 ベースの配列にシフトする必要があることです。そうしないと、DSU ルックアップによってコンポーネント構造が静か​​に破損します。 もう 1 つの詳細は、最悪の場合のユニオンの連鎖の下でほぼ線形のパフォーマンスを保証するにはパス圧縮が不可欠であるということです。

 ## 特殊なケース

 特殊なケースの 1 つは、ルールが適用されない場合です。 DSU には、$n$シングルトンコンポーネントなので、答えは残ります$k^n$。 アルゴリズムは、マージ ループに入らずに、初期化時にこれを直接処理します。 

もう 1 つのケースは、エッジが繰り返される場合です。 ルールがすでに接続されている 2 つのノードを接続すると、DSU は同一のルートを検出し、更新をスキップします。 これにより、マージの二重カウントが防止されます。 

最後のエッジ ケースは、初期段階では完全に接続されたグラフであり、その後にさらに冗長なエッジが続きます。 最初のあと$n-1$ユニオンが成功すると、後続のすべての操作は構造的に no-ops になり、答えは安定したままになります。すべてのノードが同じルートを共有するため、DSU は自然にこれを保持します。
