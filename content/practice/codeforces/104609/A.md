 ## 解決策
 ## 問題の理解

 無限の六角形のグリッド内の一連の位置が与えられ、各位置には働きバチのグループが含まれています。 移動は 16 進数セルの共有エッジに沿って行われ、2 つのセル間のコストは、セル間を移動するために必要な移動の最小数になります。 そのセルからすべてのワーカー位置までの距離の合計が最小になるように、クイーンとして 1 つのセルを選択する必要があります。 

入力は単に N 個の占有 16 進セルのリストです。 出力は、すべてのワーカーから女王の位置までの総移動距離を最小化する 1 つのセル座標です。 

N を 100,000 までの制約にすると、考えられるすべてのセルを試行したり、すべてのペアごとの距離を計算したりする解は直ちに除外されます。 すべてのワーカーに対して 1 つの候補者のポジションを評価するだけでも O(N) であるため、すべての候補者に対する単純な検索は爆発的に O(N^2) になります。 目的が独立したコンポーネントにきれいに分解される構造が必要です。 

微妙な問題は、これが標準のマンハッタン グリッドではなく、16 進グリッドであることです。 不注意なアプローチでは、16 進ジオメトリの 3 番目の暗黙的な軸を考慮せずに、座標を x と y として独立して処理しようとする可能性があります。 たとえば、正方形グリッドの解釈では斜めに並んでいるように見える 2 つの点が、16 進法では実際には異なる真の距離を持つ可能性があります。 もう 1 つの潜在的な間違いは、座標の平均化がユークリッド幾何学と同様に直接機能すると仮定していることですが、これはここでは無効です。 

## アプローチ

 強引なアイデアは、すべてのワーカー セルを女王の位置の候補として試すことです。 候補ごとに、すべてのワーカーまでの 16 進距離の合計を計算します。 1 つの合計を計算するには O(N) 回の距離計算が必要で、N 個の候補があるため、O(N^2) 回の演算が必要となり、10^5 点にとっては遅すぎます。 

重要な観察は、16 進グリッド座標を 3D 立方体座標系に変換でき、距離が 3 次元のマンハッタン距離になるということです。 各 16 進セル (x, y) は、制約 x + y + z = 0 (通常は z = -x - y) を使用して (x, y, z) にマッピングできます。 この表現では、2 つの 16 進数セル間の距離が 3 つの座標間の最大絶対差となり、これは 3 つの軸にわたるマンハッタン距離構造と等価です。 

問題が立方体座標で表現されると、タスクは制約された軸に沿った距離の合計を最小化することになります。 1D 最適化の標準的な結果が適用されます。絶対偏差の合計は中央値で最小になります。 16 進距離全体で最大構造が使用されている場合でも、3 つの線形投影に分解でき、最適解は制約の下で各軸の中央値と一致します。 

したがって、グリッドを検索する代わりに、すべての点を立方体座標に変換し、x と y に沿って中央値を計算し、z を暗黙的に再構成します。 制約を満たす任意の座標により、最適なセルが生成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^2) | お(1) | 遅すぎる |
 | 最適 (立方体 + 中央値) | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各入力 16 進座標 (x, y) を (x, y, z) として扱うことにより、立方体座標に変換します。ここで、z は z = -x - y から導出されます。 この変換により、最適化が容易になる方法で距離が保存されます。 
2. すべての x 値とすべての y 値を別々の配列に保存します。 z は制約によって決定され、x と y が固定されると自動的に位置合わせされるため、明示的には必要ありません。 
3. 両方の配列を個別にソートします。 中央値は 1 つの次元の絶対偏差の合計を最小にする点であるため、並べ替えが必要です。 
4. X 配列の中央値を候補 X 座標として選択します。 N が偶数の場合、両方の絶対偏差が同等に最小化されるため、中間の 2 つの要素のいずれかが機能します。 
5. 同様に y 配列の中央値を選択します。 
6. 検証に必要な場合は、z を -x - y として暗黙的に計算しますが、出力には元の 2D 16 進座標のみが必要なので、選択した (x, y) を直接出力します。 
7. この座標をクイーンの位置として返します。 

x と y を独立して扱える理由は、16 進距離構造が立方体座標に変換されると、軸に沿った加算寄与に分解され、各軸が中央値によって独立して最小化されるためです。 

### なぜ効果があるのか

 1 次元では、関数の合計 |xi - c| c が xi 値の中央値である場合、 は最小になります。 立方体座標では、それぞれの動きが制約された軸に沿った変化に寄与し、総コストはこれらの軸にわたる絶対偏差の組み合わせのように動作します。 いずれかの座標の中央値からの逸脱は、分布の少なくとも一方の側で不均衡を増大させるため、総コストが増加します。 これにより、中央値を選択すると、元のグリッドの最適な 16 進セルに対応する、変換された空間内でグローバルに最適な点が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    xs = []
    ys = []
    
    for _ in range(n):
        x, y = map(int, input().split())
        xs.append(x)
        ys.append(y)
    
    xs.sort()
    ys.sort()
    
    x_ans = xs[n // 2]
    y_ans = ys[n // 2]
    
    print(x_ans, y_ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、座標を 2 つの独立した配列に分割し、並べ替えを使用して中央値を抽出します。 重要な実装の詳細は、n // 2 を使用することです。これは、中央範囲の中央値が有効であるため、奇数と偶数の両方のケースを正しく処理します。 

よくある間違いは、中央値を取得せずに座標を平均しようとすることです。 これはユークリッド二乗距離では機能しますが、絶対距離の目標では機能しません。 もう 1 つの間違いは、16 進数の距離を直接シミュレートしようとすることですが、これは不必要かつ遅すぎます。

 ## 特殊なケース

 単一の作業者の場合、移動すると距離が増加するため、最適な位置は自明のことながら同じセルになります。 中央値規則は両方の配列内の唯一の要素を返すため、アルゴリズムは特別なケースを使用せずに自然にそれを処理します。 

すべての作業者が同じ垂直線上または水平線上にある場合、問題は 1D 中央値の問題に帰着します。 このアルゴリズムは、他の軸を固定したまま正しい軸を個別に縮小するため、正しいバランス ポイントを生成します。 

偶数 N の場合、有効な中央値は 2 つあります。 中央値間隔内でシフトしても絶対偏差の合計は変わらないため、どちらでも許容されます。 アルゴリズムによる n // 2 の使用により、それらのうちの 1 つが暗黙的に選択され、正確性の要件には十分です。
