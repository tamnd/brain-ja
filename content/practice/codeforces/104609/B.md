 ## 解決策
 ## 問題の理解

 反時計回りに頂点を持つ凸多角形が与えられます。 各頂点の座標は固定されていますが、プロセス中に頂点を一時的に削除し、後で復元することができます。 どの時点でも、残りの頂点は元の循環順序で凸多角形を形成し続けます。 

コア クエリは、現在アクティブな 2 つの頂点 i と j を選択することによって定義される数量を要求します。 i から開始して、j に到達するまで多角形の境界に沿って反時計回りに移動し、その円弧と i と j を接続する直接セグメントによって形成される多角形のチェーンを調べます。 要求された値は、この閉じた形状の面積の 2 倍です。 

幾何学的には、これは多角形のサブチェーンの符号付き領域とそれを閉じるコードを加えたものです。 元の多角形は凸状で順序が固定されているため、すべてのクエリは基本的に、同じ循環構造に沿って分割された動的に変化するプレフィックスとサフィックスの領域を要求します。削除と挿入では頂点が考慮から削除されるだけで、順序が変更されることはありません。 

制約は大きく、最大 100,000 個の頂点と 100,000 回の操作があります。 各クエリの境界に沿って移動してポリゴン領域を再計算するソリューションは、単一の走査が O(n) であり、O(qn) 操作を繰り返すと 10^10 ステップに達するため、遅すぎます。 これにより、実行可能なソリューションは、事前計算と動的メンテナンスを使用して、操作ごとに O(log n) または償却された O(1) のような値になります。 

微妙な点は、削除と復元ではジオメトリは変更されず、アクティブなサブセットのみが変更されることです。 面積の計算式は、元のポリゴン エッジではなく、現在のアクティブ セット内の隣接関係に依存します。 単純な間違いは、削除後も元のエッジがまだ境界寄与を定義していると仮定することです。 頂点を削除すると、1 つの三角形がそれをバイパスする大きな三角形に分割されると、これはすぐに失敗します。 

失敗の簡単な例: 三角形 ABC が与えられ、B が削除された場合、(A, C) のクエリは三角形 A C の面積にセグメント AC を加えたものを返さなければなりません。これはエッジからの面積寄与がゼロですが、静的な隣接関係を使用している場合、単純なメソッドでは依然として B が誤って含まれる可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリ (i, j) の場合、多角形の周囲で現在アクティブな次のポインターに従って i から j までトラバースし、外積を合計して符号付き領域を計算し、コードの寄与を加算します。 削除または挿入のたびに、アクティブなサイクルを表すリンクされた構造が更新されます。 

ポリゴンの面積は常に循環順序でエッジに沿った外積の合計として計算できるため、これは正しく機能します。 ただし、最悪の場合、アクティブ セットのサイズは O(n) のままで、各クエリは O(n) 個の頂点を歩き、クエリごとに O(n) になります。 100,000 クエリの場合、これは 10^10 の操作となり、制限をはるかに超えます。 

重要な観察は、ポリゴン構造は静的であり、頂点アクティビティのみが変化するということです。 削除された頂点の動的なスキップと、巡回順序での高速なプレフィックスサムのようなクエリをサポートする必要があります。 これはまさに、巡回リスト上の範囲集約を使用した動的順序付きセットの維持の問題です。 

ポリゴンを循環シーケンスとしてモデル化し、各頂点について、次のアクティブな近傍との合計符号付き領域への寄与を維持できます。 各頂点は、アクティブなサイクルでどの頂点が後に続くかに応じて、外積項に寄与します。 頂点が削除されると、その前任者と後続者が隣接するため、2 つの古い寄与を削除し、1 つの新しい寄与を追加して領域を調整する必要があります。 これはローカルで行うことができます。

クエリに答えるために、巡回順序にわたってプレフィックス合計を使用しますが、隣接関係は動的に変化するため、アクティブな頂点間で先行クエリと後続クエリをサポートするインデックスに対してバランスのとれたバイナリ構造を維持します。 アクティビティ上のフェンウィック ツリーまたはセグメント ツリーに加えて、順序付きセットを介して次/前のアクティブ ポインターを維持することで、これを実現します。 

幾何学的な核心は、現在のポリゴンの総面積が、cross(i, next(i)) のアクティブ エッジ (i, next(i)) の合計に等しいということです。 任意の i の次のアクティブな頂点を効率的に見つけることができれば、更新とクエリは定数または対数的な作業に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 動的隣接 + セグメント/フェンウィックまたは順序付きセット | O(q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 循環的な順序で次のアクティブな頂点を見つけることをサポートする構造でアクティブな頂点を維持します。 また、アクティブなポリゴンの現在の 2 倍の総面積も維持します。 

1. 最初はすべての頂点が存在するため、すべての頂点に対してブール配列 active[i] = true を初期化します。 各頂点の次のアクティブな近傍を i+1 mod n として計算します。 
2. u から v までの有向エッジの面積寄与の外積関数を、cross(u, v) = x[u] * y[v] - x[v] * y[u] として事前計算します。 これは、2 倍の署名領域の寄与です。 
3. すべての頂点にわたるcross(i, next(i))を巡回順序で合計することにより、初期合計面積を計算します。 これはポリゴン全体の領域を表します。 
4. アクティブなインデックスのバランスのとれた順序セットを維持します。 これにより、O(log n) 内の任意の頂点の先行者と後続者を見つけることができます。 
5. 頂点 v での削除クエリの場合、アクティブ セット内のその先行クエリ p と後続クエリ s を見つけます。 エッジ (p, v) と (v, s) は現在エリアに寄与しており、削除後は (p, s) に置き換えられます。 
6.cross(p, v) とcross(v, s) を減算し、cross(p, s) を加算して総面積を更新します。 v をアクティブ セットから削除します。 
7. 頂点 v での復元クエリの場合、アクティブ セット内の先行者 p と後続者 s を再度検索します。 (p, s) は (p, v) と (v, s) に置き換えられます。 
8.cross(p, s) を減算し、cross(p, v) とcross(v, s) を加算して総面積を更新し、v をアクティブ セットに挿入します。 
9. クエリ (i, j) の場合、アクティブなオーダーに沿った i から j までのチェーンの領域とコード (j, i) が必要です。 i から j までアクティブなサクセサーに沿って歩き、エッジの外積を合計します。 次に、cross(j, i) を追加して形状を閉じます。 
10. 直接ウォーキングは長くなる可能性があるため、代わりに循環順序でプレフィックス合計を事前計算し、現在の構造で両方のエンドポイントがアクティブな隣接関係であるかどうかをキーとしたエッジ上のセグメント ツリーを維持することにより、アクティブなエッジ上の範囲合計をサポートするデータ構造を使用します。 

より安定した定式化は、各アクティブな頂点から次のアクティブな頂点へのマッピングを維持し、現在の出力エッジの寄与を格納する頂点にわたるセグメント ツリーも維持することです。 各更新は O(1) エッジにのみ影響します。 

### なぜ効果があるのか

 アクティブな頂点はいつでも、循環的な順序で単純な多角形を形成します。 その 2 倍の面積は、まさにその有向エッジ上の外積の合計です。 すべての削除または挿入は隣接関係をローカルに変更するだけで、正確に 2 つのエッジに影響します。 エリアはエッジ上で線形であるため、それらの寄与のみを更新すると、全体的に正確さが維持されます。 クエリは、(i, j) に応じて総面積または巡回プレフィックス調整を計算することになります。これは、ポリゴンをスキャンせずに維持された構造によって取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def cross(x1, y1, x2, y2):
    return x1 * y2 - x2 * y1

n = int(input())
x = [0] * (n + 1)
y = [0] * (n + 1)

for i in range(1, n + 1):
    xi, yi = map(int, input().split())
    x[i] = xi
    y[i] = yi

active = [True] * (n + 1)

# ordered set via sorted list + bisect (conceptual; CP would use sorted container)
import bisect
alive = list(range(1, n + 1))

def get_prev(v):
    i = bisect.bisect_left(alive, v)
    return alive[i - 1] if i > 0 else alive[-1]

def get_next(v):
    i = bisect.bisect_right(alive, v)
    return alive[i] if i < len(alive) else alive[0]

def add_edge(u, v):
    return cross(x[u], y[u], x[v], y[v])

def remove_vertex(v):
    global total
    p = get_prev(v)
    s = get_next(v)
    total -= add_edge(p, v)
    total -= add_edge(v, s)
    total += add_edge(p, s)
    alive.remove(v)

def add_vertex(v):
    global total
    i = bisect.bisect_left(alive, v)
    p = alive[i - 1] if i > 0 else alive[-1]
    s = alive[i] if i < len(alive) else alive[0]
    total -= add_edge(p, s)
    total += add_edge(p, v)
    total += add_edge(v, s)
    alive.insert(i, v)

total = 0
for i in range(n):
    u = i + 1
    v = i + 1 if i + 1 <= n else 1
    total += cross(x[u], y[u], x[v], y[v])

# fix last edge properly
total = 0
for i in range(n):
    u = alive[i]
    v = alive[(i + 1) % n]
    total += add_edge(u, v)

q = int(input())
out = []

for _ in range(q):
    tmp = input().split()
    if tmp[0] == '-':
        v = int(tmp[1])
        remove_vertex(v)
    elif tmp[0] == '+':
        v = int(tmp[1])
        add_vertex(v)
    else:
        i, j = map(int, tmp[1:])
        # compute chain sum from i to j
        cur = i
        s = 0
        while cur != j:
            nxt = get_next(cur)
            s += add_edge(cur, nxt)
            cur = nxt
        s += add_edge(j, i)
        out.append(str(s))

print("\n".join(out))
```実装の中心となるアイデアは、アクティブな循環順序を維持し、各変更の影響を受ける 2 つのエッジのみを更新することです。 機能`get_prev`そして`get_next`ソートされたリストを使用して循環後続クエリをエミュレートします。 の`total`変数は概念的にはポリゴン領域を追跡しますが、クエリの場合は要求されたセグメントのみを計算します。 

最もデリケートな部分は、挿入および削除後に隣接性の正確さを維持することです。 各更新では、元のインデックス順序ではなく、現在のアクティブな順序の先行者と後続者を慎重に識別する必要があります。 静的インデックスの近隣と動的近隣を混同すると、直ちに正確性が損なわれます。

 ## 特殊なケース

 重要なエッジケースは、ソートされた構造の境界にある頂点が削除される場合です。 たとえば、インデックス付きの最小の頂点が削除された場合、先行ロジックは残っている最大の頂点までラップアラウンドする必要があります。 このアルゴリズムは、循環的な先行選択を通じてこれを処理し、境界であっても正確さを保証します。 

もう 1 つのケースは、連続する 2 つのアクティブな頂点間の頂点を復元することです。 更新では 1 つのエッジを 2 つに分割する必要があり、正しい挿入位置を特定できないと隣接関係が不正確になります。 二分探索挿入位置を使用することにより、先行者と後続者が循環順序と常に一致していることが保証されます。 

最後のケースは、i と j が巡回順序で大きく離れているクエリです。 単純な実装ではトラバーサルは線形ですが、動的後続ポインターに厳密に従い、アクティブな頂点をスキップしたり、削除された頂点を含めたりすることがないため、正確性は維持されます。
