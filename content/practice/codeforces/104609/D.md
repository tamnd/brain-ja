 ## 解決策
 ## 問題の理解

 円状に配置されたシーケンスが与えられます。これは、インデックス 1 がインデックス N に隣接することを意味します。各位置には値が含まれており、選択した値の合計を最大化するインデックスのサブセットを選択したいと考えています。 

制限は幾何学的なものです。2 つのインデックスを選択する場合、それらは円上で大きく離れていなければなりません。 選択した 2 つのインデックス間の円周距離は少なくとも D + 1 である必要があります。つまり、円に沿ってどちらかの方向に歩くと、選択した別のインデックスに到達する前に少なくとも D 個の他の位置を通過する必要があります。 

したがって、このタスクは、各頂点がすぐ隣の頂点だけでなく、両方向の次の D 頂点に接続されているサイクル グラフ上の重み付き独立集合問題です。 

入力サイズ N は最大 100000 まで可能で、すべてのペアにわたる指数サブセット列挙または二次 DP が直ちに除外されます。 10^10 の演算は制限をはるかに超えているため、O(N^2) のような演算は遅すぎます。 この構造は、各インデックスがほぼ 2D のサイズのローカル近傍とのみ相互作用することを示唆しているため、ソリューションは局所性またはスライディング構造を利用する必要があります。 

D が小さい場合と大きい場合には、微妙なエッジ ケースが発生します。 D = 0 の場合、制限はなく、すべての要素が取得されます。 D が N − 1 の場合、選択できる要素は最大 1 つであるため、答えは単純に配列内の最大要素になります。 もう 1 つの重要なケースは、値が負または混合である場合ですが、ステートメント内の値は常に正であるため、決定は符号のトレードオフではなく、純粋に間隔について行われます。 

単純なアプローチでは、各要素を検討し、それを取得するか、その禁止された近傍をスキップするかを再帰的に決定しようとする可能性があります。 これにより、すぐに部分問題の重複と指数関数的な分岐が発生します。 

## アプローチ

 直接的な総当たりアプローチでは、インデックスのすべてのサブセットが考慮され、各サブセットが間隔制約を満たしているかどうかが検証されます。 サブセットごとに、選択したインデックスをソートし、連続する選択した要素間の円周距離をチェックします。 たとえチェックが O(N) であっても、2^N 個のサブセットが存在するため、N = 40 の場合でもこれは完全に実行不可能になります。 

もう少し構造化されたブルート フォースは、ビットマスクに対する動的プログラミングです。各状態は、どのインデックスが既に選択されているかを表します。 これは依然として 2^N 個の状態として増加し、遷移では距離 D 内の競合をチェックする必要があるため、少なくとも O(N 2^N) 回の操作が必要になります。 

重要な観察は、制約が循環順序において純粋にローカルであるということです。 位置 i の要素を選択することにした場合、次に選択される要素は、i + D + 1 から始まり前方に伸びるセグメント内に存在する必要があります。 これにより、最小ギャップ制約を使用して円に沿って厳密に増加する一連のインデックスを選択するという問題に変換されます。 

ただし、最初と最後の要素が相互作用するため、循環構造では直接的な線形 DP が妨げられます。 これに対処する標準的な方法は、サイクルを断ち切ることです。つまり、位置 1 を選択しないか、位置 1 を選択したとおりに固定してラップアラウンド競合を禁止します。 どちらの場合も、問題は線形の「選択された 2 つの要素が距離 D 以内にない」最適化になります。 

線形化されると、i までの位置を考慮した最適な合計として DP[i] を定義できます。 各 i で、それをスキップするか、それを取り出して i − (D + 1) に戻ります。 これにより、固定長の競合を伴う加重間隔スケジューリングと同様のクリーンな繰り返しが生成されます。 

この効率は、各状態が前の 1 つの状態にのみ依存するという事実から得られるため、ペアごとの比較を完全に回避します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^N・N) | O(N) | 遅すぎる |
 | 最適なDP | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 循環依存関係を線形ケースに変換し、最小間隔制約を尊重する標準 DP を実行します。

1. 問題を 2 つのケースに分割します。1 つはインデックス 0 を選択しないケース、もう 1 つはインデックス 0 で円が壊れているものとして扱い、ラップアラウンドを慎重に処理するケースです。 これが必要なのは、そうしないと、選択された終端近くの要素が、円周距離ルールによって開始近くの要素と競合する可能性があるためです。 
2. 固定線形配置の場合、選択したインデックスが少なくとも D + 1 異なるという制約の下で、0 から i までのインデックスを使用して取得できる最大合計として dp[i] を定義します。 
3. 位置 i には 2 つの可能性があります。 A[i] を使用しない場合は、dp[i] = dp[i − 1] となります。 A[i] をとった場合、前の有効な選択肢は最大でも i − D − 1 でなければならないため、値は A[i] + dp[i − D − 1] になります。 
4. i − D − 1 が負の場合、dp インデックスを 0 として扱います。これは、事前の制限なしで A[i] を取得できることを意味します。 
5. dp を左から右に繰り返し計算し、各プレフィックスで達成可能な最良の合計を保存します。 
6. 循環処理では、インデックス 0 が取得される場合を考慮した場合、ラップアラウンド距離に違反する方法で最後の D 位置のインデックスが取得されることを許可しないようにします。 これは、無効な構成を除外するか、開始位置をシフトして線形化されたアレイの DP を再計算することによって処理されます。 

### なぜ効果があるのか

 DP は、dp[i] が i までのインデックス間の有効な選択のみを使用して達成可能な最大合計であるという不変条件を維持します。 i で終わる解は、すでに dp[i − 1] でカバーされている i を除外するか、i を含みます。この場合、範囲 (i − D, i) 内の互換性のないインデックスはすべて除外され、最後に選択されたインデックスは最大でも i − D − 1 になります。これにより、すべての有効な可能性が重複せずにすべて網羅されるため、すべての実行可能なサブセットが反復内で 1 回だけ表されます。 

円形の場合は、境界を固定することで線形の場合に減らされ、選択されたペアがカットを横切らないようにします。これにより、すべての有効な円形サブセットがそのサイクル表現の少なくとも 1 つのエッジを回避するため、正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(arr, D):
    n = len(arr)
    if n == 0:
        return 0

    # dp[i] = best up to i
    dp = [0] * n

    for i in range(n):
        take = arr[i]
        if i - D - 1 >= 0:
            take += dp[i - D - 1]
        skip = dp[i - 1] if i > 0 else 0
        dp[i] = max(skip, take)

    return dp[-1]

def solve():
    N, D = map(int, input().split())
    A = list(map(int, input().split()))

    if N == 1:
        print(A[0])
        return

    # Case 1: do not take index 0
    ans1 = solve_case(A[1:], D)

    # Case 2: take index 0, so we must forbid last D elements
    # effectively only consider A[0] + solve on middle part
    cut = N - D - 1
    if cut <= 0:
        ans2 = A[0]
    else:
        ans2 = A[0] + solve_case(A[1:cut], D)

    print(max(ans1, ans2))

if __name__ == "__main__":
    solve()
```このソリューションは、各状態が位置までの達成可能な最良の合計を表すプレフィックス動的プログラミング配列を構築します。 トランジションは現在の要素をスキップするか、現在の要素を取得して D + 1 位置分ジャンプして戻ります。これにより、間隔制約が直接エンコードされます。 

循環制約は 2 つの線形ケースに分割することで処理されます。 最初の例では、インデックス 0 が除外されるため、配列は単純な行になります。 2 番目の例では、インデックス 0 が含まれており、インデックス 0 から距離 D 以内にある終端近くのインデックスが強制的に除外されます。 これが、2 番目の DP が中央のセグメントでのみ実行される理由です。 

ここでよくある落とし穴は、循環隣接によって最初と最後の D 要素が結合されることを忘れていることです。 もう 1 つは、dp[i - D - 1] が適切な処理を行わずに負の位置にインデックスを付けることを誤って許可しているため、コードは境界を明示的にチェックします。 

## 実用的な例

 ### 例 1

 入力:```
6 2
1 5 3 2 6 1
```2 つのケースを計算します。 

ケース 1 ではインデックス 0 が除外され、[5, 3, 2, 6, 1] で DP が実行されます。 DP は次のように進化します。 

| 私 | 値 | 候補を取る | スキップ | dp[i] |
 | --- | --- | --- | --- | --- |
 | 0 | 5 | 5 | 0 | 5 |
 | 1 | 3 | 3 | 5 | 5 |
 | 2 | 2 | 2 + 0 = 2 | 5 | 5 |
 | 3 | 6 | 6 + 5 = 11 | 5 | 11 |
 | 4 | 1 | 1 + 5 = 6 | 11 | 11 |

 ケース 2 にはインデックス 0 = 1 が含まれるため、最後の D 要素を削除した後の中間部分 [5, 3] のみを考慮します。 そこでのDPはベスト5となるため、合計は6になります。 

最終的な答えは max(11, 6) = 11 です。 

これは、ローカル競合をスキップすることで、まばらな高値ピークを選択できることを示しています。 

### 例 2

 入力:```
4 1
2 1 1 2
```[1,1,2] のケース 1:

 | 私 | 値 | 取る | スキップ | DP |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 1 | 0 | 1 |
 | 1 | 1 | 1 | 1 | 1 |
 | 2 | 2 | 2 + 1 = 3 | 1 | 3 |

 ケース 2 にはインデックス 0 = 2 が含まれ、中間部分は [1,1]、DP は 1 を与えます。 

答えは max(3, 3) = 3 です。 

これは、DP が隣接しない高価値のピックを正しく優先していることを示しています。

 ## 特殊なケース

 D が N − 1 に近い場合、重大なエッジ ケースが発生します。この状況では、ほとんどすべてのインデックスが互いに競合するため、アルゴリズムは最大の要素を選択する必要があります。 入力用`5 4 / 1 2 3 4 5`、DP は、すべての「テイク」トランジションが残りのすべての要素をスキップすることを保証するため、dp は単一の最大値に折りたたまれ、正しく 5 が生成されます。 

もう 1 つのエッジ ケースは、D = 0 の場合です。反復は dp[i] = max(dp[i − 1], A[i] + dp[i − 1]) となり、常にすべての要素を取得することを単純化します。 i − D − 1 は i − 1 になるため、実装ではこれが自然に処理され、take は常に dp[i − 1] に基づいて構築され、すべての要素の累積和が生成されます。 

最後の微妙なケースは、循環ラップ相互作用です。 のために`4 1 / 2 1 1 2`2 番目のケースではインデックス 0 を選択するとインデックス 3 が除外されますが、インデックス 0 を選択するとインデックス 1 と 3 を一緒に選択できます。 分割ケース処理により、両方の構成が確実に評価され、最大値が 3 として正しく選択されます。
