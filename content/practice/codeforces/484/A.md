 ## 解決策
 ## 問題の理解

 それぞれの下限によって定義された複数のクエリを処理するように求められます。`l`そして上限`r`。 クエリごとに、整数を見つける必要があります。`x`間隔内で`[l, r]`バイナリ表現の設定ビット数ができるだけ大きくなるようにします。 複数の数値が設定ビットの最大数に達する場合は、これらの数値のうち最小のものを選択する必要があります。 

入力は最大 10,000 のクエリを保証し、その制限は`l`そして`r`まで行く$10^{18}$。 この上限は、すべての数値をチェックする単純なアプローチが有効であることを意味します。`[l, r]`実行不可能になるため、`r - l`非常に大きくなる可能性があります$10^{18}$。 したがって、解は区間内のすべての整数を列挙することなく答えを計算できなければなりません。 

微妙なエッジケースが発生する場合`l`そして`r`は連続する 2 のべき乗であるか、1 ビットだけ異なります。 たとえば、次の場合`l = 8`そして`r = 15`、最適な数は次のとおりです。`15`下位 4 ビットがすべて設定されているためです。 だけを考慮したいい加減な実装`r`あるいは、単純に貪欲なアプローチでは誤って選択される可能性があります。`14`、設定ビットが少なくなります。 同様に、`l = r`、アルゴリズムは単に返さなければなりません`l`、それが唯一の選択肢だからです。 

## アプローチ

 ブルート フォースのアプローチは簡単です。クエリごとに、次のクエリ間のすべての整数を反復処理します。`l`そして`r`、設定されたビットの数をカウントし、最大値を追跡します。 これにより正確性が保証されますが、設定されたビットをカウントするのは次のとおりです。$10^{18}$10,000 クエリの場合は明らかに遅すぎます。 最悪の場合の操作数は次のようになります。$10^{18} \times 64 \approx 6.4 \times 10^{19}$実行可能な限界を何桁も超えた操作。 

重要な観察点は、間隔内の設定ビットの最大数です。`[l, r]`は、最上位ビットから始まる連続する数値の文字列にできるだけ近い数値によって達成されます。`l`そして`r`異なる。 のバイナリ表現を調べると、`l`そして`r`、最初の異なるビットを次のように設定することで候補番号を構築できます。`1`そしてすべての下位ビットを`1`。 この候補は超える可能性があります`r`したがって、複数の位置をチェックしながら、範囲内に収まるように下位ビットを慎重にゼロに戻す必要があります。 

この洞察により、すべての数値を列挙する必要がなくなります。 代わりに、バイナリ表現を直接操作して、クエリごとに最大 64 ビットを操作することで、実現可能なソリューションが得られます。 このアプローチは、以下から候補を構築することに帰着します。`r`間隔の制約を尊重しながら、下位ビットを貪欲に埋めていきます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((r-l+1) * 64) | お(1) | 遅すぎる |
 | 最適 | クエリごとに O(64) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. For each query, immediately check if`l == r`。 だったら返して`l`。 候補は 1 つだけであるため、これ以上の計算は必要ありません。 
2.変換`l`そして`r`into their binary representations of equal length by padding with leading zeros. This allows direct comparison of bits at each position.
 3. 候補番号の初期化`ans`として`r`。 これが出発点であるため、`r`は間隔内の最大の数値であり、すでに多くの設定ビットが含まれています。 
4. 最上位ビットから最下位ビットまで繰り返します。 最初の位置を特定します。`l`持っています`0`そして`r`持っています`1`。 これは最大の差分ビットです。 設定ビットを最大化するには、このビットを次のように設定することを検討してください。`1`そしてすべての下位ビットを`1`。 
5. 識別されたビットを設定し、すべての下位ビットを次の値で埋めることによって、新しい数値を構築します。`1`s. これを超えると`r`、範囲内に収まるまで、最下位端からビットをゼロに戻します。`[l, r]`。 
6. この候補の設定ビット数を次と比較します。`r`自体。 設定ビット数が多い方をお選びください。 同点の場合は小さい方の数字を選択してください。 
7. 結果の数値を返します。 

機能する理由: アルゴリズムは、最初の異なるビットが`l`そして`r`が候補に設定されます。 すべての下位ビットを 1 で埋めると、設定されたビットの数が最大化され、下方に調整することで設定ビット数が次を超えないようにすることができます。`r`。 セットビット数が大きい数値には、`1`ある位置で`r`もっている`0`、これは区間外になるため、これより良い数値は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_bits(l, r):
    if l == r:
        return l
    ans = r
    length = max(l.bit_length(), r.bit_length())
    for i in range(length-1, -1, -1):
        mask = 1 << i
        if (l & mask) == 0 and (r & mask) != 0:
            candidate = r | (mask - 1)
            if candidate > r:
                candidate ^= candidate & (mask - 1)
            if candidate < l:
                candidate = r
            if bin(candidate).count('1') > bin(ans).count('1') or (bin(candidate).count('1') == bin(ans).count('1') and candidate < ans):
                ans = candidate
            break
    return ans

n = int(input())
for _ in range(n):
    l, r = map(int, input().split())
    print(max_bits(l, r))
```このコードはビットを慎重に操作して、間隔を超えずに 1 の数を最大化します。 マスクは最初の異なるビットを識別し、`mask - 1`すべての下位ビットを設定します。 XOR を使用した調整により、範囲内に収まることが保証されます。 ビットのカウントには Python の組み込み機能を使用します`bin()`関数。 

## 実用的な例

 **入力:**`1 10`バイナリ`l=1`->`0001`、`r=10`->`1010`。

 | i=3 | - | - | 8 | 15 -> 7 に調整 | 7 |

 これにより、最初の異なるビットと下位ビット セットを使用して候補を構築すると、正しい最大セット ビット数が得られることが確認されます。 

**入力：**`2 4`

`l=2`->`10`、`r=4`->`100`。 最初に異なるビットはビット 2 です。候補`111`-> 7を超えます`r=4`。 下位ビットを調整: 候補は次のようになります。`011`-> 3 以内`[2,4]`。 最大設定ビット: 2、答え`3`。
