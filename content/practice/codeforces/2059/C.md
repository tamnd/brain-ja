 ## 解決策
 ## 問題の理解

 この問題は、次のようなシナリオを示しています。`n`キュー、最初は空、および一連の`n`離散的な瞬間。 それぞれの瞬間に、どのキューにも一定数の新規顧客が入ります。 到着後、単一のキューにサービスを提供でき、顧客数がゼロにリセットされます。 結局`n`時間が経過すると、すべてのキューに残っている顧客の中で最小除外数 (MEX) を最大化するように求められます。 

MEX は、残りの顧客数のセットに存在しない最小の非負の整数です。 たとえば、最終的なカウントが次の場合、`[0, 1, 3]`、MEX は`2`なぜなら`0`そして`1`登場しますが、`2`しません。 目標は、毎回どのキューを処理するかを最適に選択することで、達成可能な最大の MEX を決定することです。 

とすれば`n`最大 300 まで指定でき、次の合計は`n^2`すべてのテスト ケースで最大でも`2×10^5`、サービス注文の考えられるすべての順列を反復するソリューションは遅すぎます。 単純な総当たりアプローチでは、次のことが必要になります。`n!`シミュレーションは全く不可能です。 エッジケースには、すべてのキューが同じ数値を受信するシーケンスや、一部のキューが非常に大きな数値を早期に受信するシーケンスが含まれ、サービスが適切に行われていない場合、小さな MEX 値で最終シーケンスを構築することが不可能になります。 

## アプローチ

 ブルートフォース手法では、各時点で処理されるキューの可能な順序をすべてシミュレートしようとします。 順列ごとに、累積顧客数を追跡し、各ステップで選択したキューをリセットし、最終的な MEX を計算します。 このアプローチは原理的には正しいですが、まったく手に負えません。`n!`よりも早く成長する`10^300`のために`n=300`。 

重要な洞察は、目標がゼロから始まる連続する整数をできるだけ多く含むように最終的なキュー数を生成することであるという観察から得られます。 この問題は、最終的なキュー サイズを表す整数の複数セットを構築するものであると解釈できます。 各キューは 1 回だけ処理されるため、各キューの最終的なカウントは、受信したすべての増分の合計から、処理された時点の増分を引いたものになります。 増分は厳密に正であるため、サービス後に列に並んでいる顧客の達成可能な最小数は、**サービス前の到着**の累積合計です。 MEX を最大化するには、現在まだ処理されていない到着の累積合計が最小であるキューを常に処理する必要があります。 言い換えれば、可能な限り最小の最終数値を、ゼロから始まる最小の整数に割り当てる必要があります。 

したがって、最適な戦略はすべてを並べ替えることになります。`n×n`顧客数を非減少順に増加させ、それらを最終的なカウントに貪欲に割り当てます`0, 1, 2, …`。 具体的には、行の合計をソートした後、達成可能な最大 MEX が最大の整数になります。`k`少なくともそうなるように`k`キューの最終カウントは以上です`0, 1, …, k-1`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! × n^2) | O(n^2) | 遅すぎる |
 | 貪欲 / 建設的 | O(n^2 log n) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして`n×n`到着の行列`a`。 
3. 各キューの到着数の合計を計算します。`total[i] = sum(a[i])`。 
4. 並べ替え`total`降順ではない順に。 
5.初期化`mex = 0`。 
6. ソートされた合計を繰り返し処理し、それぞれについて`total[i]`、 もし`total[i] >= mex`、増分`mex`by 1. これにより、MEX の場合、`k`、最終カウントが表すことができるキューが少なくとも 1 つ存在します。`k-1`。 
7. 出力`mex`テストケース用。 

**機能する理由:** 各時点で最小の累積合計でキューを処理すると、可能な限り最小の最終カウントが 0 から上の連続する整数を占めることが保証されます。 ソートされた合計を反復処理して増加させることにより、`mex`whenever a queue can satisfy the next required integer, we effectively compute the largest possible consecutive prefix, which is the maximal MEX.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    total = []
    for _ in range(n):
        row = list(map(int, input().split()))
        total.append(sum(row))
    total.sort()
    mex = 0
    for val in total:
        if val >= mex:
            mex += 1
    print(mex)

t = int(input())
for _ in range(t):
    solve()
```**説明:** ソリューションはすべての到着を読み取り、行を合計して潜在的な最終合計数を取得し、それらを並べ替えます。 ソートされた合計を反復処理することで、MEX を最大化する方法で最小の整数をキューに貪欲に割り当てることができます。 比較`val >= mex`0 から上の各数値を表現できることを保証します。

 ## 特殊なケース

 すべてのキューが各瞬間に同じ数値を受信した場合、アルゴリズムは最大 MEX が`n`、各キューは 0 から 0 までの連続する整数の 1 つを表すことができるため、`n-1`。 1 つのキューが非常に大きな増分を早期に受信した場合、そのキューは当然貪欲な順序付けでは最後に処理され、小さなキューは MEX を最大化するために必要なより小さな数を受信します。 このアプローチでは、合計と範囲内の整数のみを比較するため、大きな値を安全に処理します。`[0, n]`。
