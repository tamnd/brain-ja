 ## 解決策
 ## 問題の理解

 頂点 1 を首都とする重み付き無向グラフが与えられます。 

私たちはすべての都市を結ぶ一連の道路を選択しなければなりません。 選択したグラフは接続されており、合計の重みが最小である必要があるため、解が存在する場合、解は常にスパニング ツリーになります。 

追加の制限はまさにそれです`k`スパニング ツリーのエッジは首都に沿う必要があります。 

したがって、タスクは次のとおりです。 

頂点の次数が次である最小重みスパニング ツリーを検索します。`1`まさに`k`、そのエッジインデックスを出力します。 

グラフには最大 5000 個の頂点と 100000 個のエッジが含まれます。 古典的な最小スパニング ツリーは、次の Kruskal で見つけることができます。`O(m log m)`、それはまったく問題ありません。 難しいのは、単一の特別な頂点に次数制約を適用することです。 

制約サイズは、キャピタル エッジのサブセットを列挙するものを即座に除外します。 頂点 1 の次数についてすべての可能性をチェックすることさえ絶望的です。なぜなら、入射エッジの数は`10^5`。 

重要な観察は、この制限が 1 つの特別なクラスのエッジ、つまり頂点 1 に接触するエッジにのみ影響するということです。この構造はまさにラグランジュ緩和 (競技プログラミングでは WQS 二分探索と呼ばれることが多い) を可能にするものです。 

明らかではないエッジケースがいくつかあります。 

すべてのエッジが利用可能な場合でもグラフが切断されていると仮定します。```
3 1 1
1 2 5
```頂点 3 は分離されています。 スパニングツリーは存在しないので、答えは次のようになります。`-1`。 

もう 1 つの重要なケースは、キャピタル エッジが少なすぎる場合です。```
4 2 2
1 2 1
2 3 1
```頂点 1 に接触するエッジは 1 つだけなので、首都で次数 2 を取得することは不可能です。 

より微妙なケースは、バイナリ検索中に多くのスパニング ツリーが同じ変更コストを持つ場合に発生します。 同点が正しく処理されない場合、選択されたキャピタル エッジの数の単調性が崩れ、再構築が失敗します。 実装では、同じ変更された重みの中でキャピタル エッジを明示的に優先する必要があります。 

## アプローチ

 ブルートフォースの観点は、実際に最適化しているものを明らかにするので便利です。 

すべてのスパニング ツリーを列挙することを想像してください。 すべての木について、頂点 1 に属するエッジの数を数えます。`k`このようなエッジは、総重量が最小のものを使用してください。 

これは答えの定義と直接一致するため、明らかに正しいです。 残念ながら、頂点が 5000 個あるグラフには、天文学的な数のスパニング ツリーが存在する可能性があります。 それらを生成することさえ不可能です。 

次に自然なアイデアは、使用されているキャピタル エッジの数を何らかの形で追跡しながら Kruskal を実行することです。 するとすぐに問題が発生します。Kruskal は総重みのみを最適化し、次数制約については何も知りません。 

重要な観察は、すべてのキャピタル エッジが同じカテゴリに属しているということです。 正確に強制するのではなく`k`それらのうち、重みを一時的に変更できます。 

させて`C`パラメータになります。 

頂点 1 に接触するすべてのエッジについて、その重みを次のように置き換えます。`w + C`。 

他のすべてのエッジは元の重みを維持します。 

次に、これらの変更された重みに対して標準の MST アルゴリズムを実行します。 

もし`C`が非常に大きいため、キャピタル エッジが高価になり、MST はキャピタル エッジをほとんど使用しません。 

もし`C`が非常にネガティブな場合、キャピタルエッジは魅力的となり、MST はキャピタルエッジの多くを使用します。 

これにより、単調関数が作成されます。`cnt(C) = number of capital edges in the MST`。 

として`C`増加し、`cnt(C)`決して増えません。 

この単調性により二分探索が可能になります。 

の最大値を見つけた後、`C`MST には少なくとも次の内容が含まれています。`k`キャピタル エッジを使用してスパニング ツリーを再構築します。`k`同じ変更された重みでもう一度クラスカルを実行し、それ以上の重みを取ることを拒否することで、資本の優位性を高めます。`k`キャピタルエッジ。 

これが機能する理由は、標準的なラグランジュ緩和特性にあります。 二分探索境界では、すべての最適な修正 MST は、次数制約のある最適な元の解に対応します。`k`。

 | 二分探索 + クラスカル | O(log W · m log m) | O(m) | 承認済み |

 ここ`W`重量範囲です。 

## アルゴリズムのチュートリアル

 1. 1 つのエンドポイントが首都である場合、それが次のように保存されるように、すべてのエッジを正規化します。`(1, x)`。 
2. 関数を定義する`count_capital(C)`。 

追加`C`すべてのキャピタル エッジの重みを計算し、変更された重みですべてのエッジを並べ替えて、Kruskal を実行します。 

2 つのエッジの修正ウェイトが同じである場合は、大文字エッジを最初に配置します。 これにより、すべての最適な修正 MST の中で選択されたキャピタル エッジの数が最大化されます。 

使用されているキャピタル エッジの数を返します。 
3. 二分探索`C`。 

の最大値が必要です`C`そのような`count_capital(C) >= k`。 

増加中`C`大文字のエッジが魅力的ではなくなるため、述語が単調になります。 
4. 結果のパラメータを次のようにします。`best`。 
5. によって変更された重みを使用して Kruskal を再度実行します。`best`。 
6. ツリーの構築中は、選択したキャピタル エッジの数を決して超えないようにしてください。`k`。 

大文字以外のエッジは通常どおり処理されます。 

キャピタル エッジは次の場合にのみ受け入れられます。 

- 2 つの異なるコンポーネントを接続します。 
- 未満`k`キャピタルエッジはすでに選択されています。 
7. 正確に取得できなかった場合`n - 1`端に到達するか、正確に到達できない`k`キャピタル エッジ、有効なスパニング ツリーが存在しません。 
8. それ以外の場合は、選択したエッジ インデックスを出力します。 

### なぜ効果があるのか

 固定パラメータの場合`C`、クラスカルは、次の追加によって重みが変更されるグラフ内で最小スパニング ツリーを見つけます。`C`あらゆる首都の端まで。 

木に含ませる`d`キャピタルエッジ。 その修正コストは`original_cost + C * d`。 

二分探索では、最適に修正された MST が少なくとも使用する最大のパラメータを見つけます。`k`キャピタルエッジ。 

この境界では、次数が次よりも大きいすべてのツリーが存在します。`k`および次数が以下のすべての木`k`ラグランジュ緩和の同じサポートラインの周りでバランスが取れています。 最適な制約付きソリューションは、最適な修正 MST の中にあります。 MST を再構築し、正確に制限することで、`k`等コストの選択肢が存在する場合は常に、最適な制約付きツリーの 1 つを取得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n + 1))

    def find(self, x):
        p = self.p
        while p[x] != x:
            p[x] = p[p[x]]
            x = p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        self.p[a] = b
        return True

def solve():
    n, m, k = map(int, input().split())

    edges = []

    for idx in range(1, m + 1):
        u, v, w = map(int, input().split())

        if u > v:
            u, v = v, u

        edges.append([u, v, w, idx])

    def count_capital(add):
        arr = []

        for u, v, w, idx in edges:
            if u == 1:
                arr.append((w + add, 0, u, v))
            else:
                arr.append((w, 1, u, v))

        arr.sort()

        dsu = DSU(n)
        cnt = 0
        taken = 0

        for _, typ, u, v in arr:
            if dsu.union(u, v):
                taken += 1
                if typ == 0:
                    cnt += 1
                if taken == n - 1:
                    break

        return cnt

    L = -100000
    R = 100000
    best = None

    while L <= R:
        mid = (L + R) // 2

        if count_capital(mid) >= k:
            best = mid
            L = mid + 1
        else:
            R = mid - 1

    if best is None:
        print(-1)
        return

    arr = []

    for u, v, w, idx in edges:
        if u == 1:
            arr.append((w + best, 0, u, v, idx))
        else:
            arr.append((w, 1, u, v, idx))

    arr.sort()

    dsu = DSU(n)

    answer = []
    capital_used = 0

    for _, typ, u, v, idx in arr:
        if typ == 0 and capital_used == k:
            continue

        if dsu.union(u, v):
            answer.append(idx)

            if typ == 0:
                capital_used += 1

    if len(answer) != n - 1 or capital_used != k:
        print(-1)
        return

    print(n - 1)
    print(*answer)

solve()
```最初の重要な詳細は並べ替え順序です。 キャピタルエッジ受信タイプ`0`および大文字以外のエッジはタイプを受け取ります`1`。 Python はタプルを辞書順にソートするため、変更された重みが等しい場合は自動的に大文字のエッジが優先されます。 このタイブレーカーがないと、二分探索で使用される単調性が失敗する可能性があります。 

二分検索では、MST に少なくとも次の内容が含まれる最大のパラメータが検索されます。`k`キャピタルエッジ。 その正確な方向性が重要です。 これを逆にすると、再構築の議論が変わり、正しさが失われます。 

再構築中に、同じ変更された重みで Kruskal を再度実行します。 唯一の追加ルールは、1 回だけです。`k`キャピタル エッジはすでに選択されており、それ以降のキャピタル エッジはすべてスキップされます。 これは、最適緩和解を正確な次数要件を満たす最適解に変換するステップです。 

DSU 実装ではパス圧縮が使用されます。 これらの制約にはランクによる結合は不要です。

 ## 特殊なケース

 切り離されたグラフを考えてみましょう。```
3 1 1
1 2 5
```Kruskal は最大 1 つのエッジを選択できます。 3 つの頂点上のスパニング ツリーには 2 つのエッジが必要です。 再構築中、アルゴリズムは以下の数で終了します。`n - 1`エッジとプリント`-1`。 

資本エッジが不十分であることを考慮してください。```
4 2 2
1 2 1
2 3 1
```二分探索パラメータがどれほど負になっても、グラフには物理的に大文字エッジが 1 つだけ含まれます。 復興フェーズに到達できない`capital_used = 2`したがって、最終的な有効性チェックでインスタンスが拒否されます。 

変更された重みが等しいことを考慮します。 いくつかの資本エッジと非資本エッジが同一の修正コストを持つと仮定します。 アルゴリズムは常にキャピタル エッジを順序付けの最初に配置します。 これにより、次のことが保証されます`count_capital(C)`は、最適な修正 MST 間のキャピタル エッジの最大可能数を表します。これは、まさに二分探索で必要な単調量です。 このタイブレーク ルールがないと、Kruskal の実行が異なると、同じパラメータに対して異なるカウントが生成され、検索が中断される可能性があります。
