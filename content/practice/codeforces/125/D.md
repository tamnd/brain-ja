 ## 解決策
 ## 問題の理解

 固定された順序で一連の個別の整数が与えられます。 すべての要素は、2 つのサブシーケンスのうちの 1 つに正確に割り当てられる必要があります。 各サブシーケンス内では、元の順序が保持される必要があります。 

目標は、両方の部分列を等差数列にすることです。 長さ 1 または 2 の進行は常に有効です。 長さ 0 の進行は許可されないため、結果として得られる両方のサブシーケンスには少なくとも 1 つの要素が含まれている必要があります。 

シーケンスの長さは最大 30000 です。要素のさまざまな割り当てを試行するアプローチはすぐに不可能になります。 全部チェックしても$2^n$パーティションが異常に大きいです。 このソリューションは、等差数列の強力な構造特性を利用し、ほぼ直線的な時間で実行する必要があります。 

この問題の最も微妙な部分は、等差数列が並べ替えではなく順序によって定義されていることです。 例えば：```
1 5 3
```続いて`1 3`算数ですが、`1 5 3`そうではありません。 最初に配列をソートするソリューションでは、別の問題が解決されます。 

もう 1 つの簡単な間違いは、1 つの数列を推測したら、一致するすべての値がその数列に属している必要があると仮定することです。 考慮する：```
1 2 3 -2 -7
```次の両方が有効です。```
1 2 3
-2 -7
```そして```
1 2
3 -2 -7
```アルゴリズムはこの曖昧さを許容する必要があります。 

3 番目の落とし穴は、1 つの進行がほぼ正しく、最後に選択された要素だけが間違っている場合に発生します。 例えば：```
4 1 2 7 3 10
```進歩を構築すれば`1 2 3`、すべてが機能します。 他の推測の場合、最後に選択した要素をある進行から別の進行に移動するまで、残りの要素は算術演算に失敗する可能性があります。 

## アプローチ

 強引なアイデアは、シーケンスのすべてのパーティションを 2 つのサブシーケンスに分けて試し、両方が算術的であるかどうかを確認することです。 これは、考えられるすべての答えを直接テストするため、正しいです。 残念ながら、あります$2^n$パーティション。 たとえ$n=50$これはもう絶望的です、そしてここで$n$30000に達します。 

重要な観察は、最初の 3 つの要素から得られます。 

3 つの要素が 2 つのサブシーケンスに分散されている場合、鳩の穴の原理により、そのうちの少なくとも 2 つは同じ数列に属します。 これら 2 つの要素によって、その進行の共通の違いが決まります。 

最初の 3 つの位置のうち、可能なペアは 3 つだけです。```
(1,2), (1,3), (2,3)
```したがって、考慮に値する候補の違いは 3 つだけです。 

これらのペアの 1 つを選択し、それが進行 A に属すると仮定します。その違いは固定されています。 差が修正されると、数列 A 全体が決定されます。最初に選択した値から始まり、次の値は正確に一致する必要があります。`start + d`、 それから`start + 2d`、 等々。 

シーケンスを左から右にスキャンします。 A の次の期待値に遭遇するたびに、それを A に入れます。それ以外はすべて一時的に B に入れられます。 

この構築後、B はすでに等差数列であるか、そうでないかのどちらかになります。 

残りのトリックは、唯一明らかではない部分です。 B が算術でない場合は、A に選択された最後の要素を B に移動して、再度チェックします。 それでも失敗する場合は、この候補の違いから有効な答えを導き出すことはできません。 

最後の要素のみを移動するだけで十分なのはなぜですか? この候補の違いに対して何らかの解決策が存在すると仮定します。 貪欲な構築では、常に A の利用可能なすべての期待値が取得されます。B に安全に「返す」ことができる唯一の値は、最後に取得された値です。 最後の要素を移動しても B が修復されない場合は、さらに多くの要素を移動しても役に立ちません。 元の Codeforces ソリューションはこのプロパティに依存し、これら 2 つの構成のみをチェックします。 

候補の違いは 3 つだけであり、各チェックは線形であるため、アルゴリズム全体は線形です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. もし`n = 2`、2 つの要素を 2 つの単一要素進行として出力します。 
2. 最初の 3 つの位置のうちの 3 つのペアを検討します。`(1,2)`、`(1,3)`、`(2,3)`。 
3. 選択した 1 つのペアについて`(l,r)`、 させて：`d = a[r] - a[l]`。 
4. 貪欲に進行 A を構築します。 

期待値から始める`a[l]`。 

シーケンスを左から右にスキャンします。 

現在の要素が期待値と等しい場合は常に、それを A に配置し、期待値を だけ増加させます。`d`。 
5. A に取り込まれないすべての要素は B に配置されます。 
6. B が等差数列であるかどうかを確認します。 

長さ 1 と長さ 2 は常に受け入れられます。 
7. B が有効な場合、A と B を出力します。 
8. それ以外の場合は、A に挿入された最後の要素を削除し、それを B に移動して、B を再度チェックします。 
9. B が有効になった場合は、変更した A と B を出力します。 
10. どちらのチェックも成功しない場合は、次の候補ペアを試します。 
11. 3 つの候補ペアがすべて失敗した場合は、次のように出力します。`"No solution"`。 

### なぜ効果があるのか

 最初の 3 つの要素のうち、一部のペアは有効なパーティション内の同じ進行に属している必要があります。 そのペアによって差異の候補が決定されるため、3 回の試行のうち 1 つで正しい差異が使用されます。 

差が固定されている場合、貪欲な構築により、その差と一致する最大の等差数列が回復されます。 すべての数値は個別であるため、期待値が表示されるたびにそれをスキップすると、後の進行にその用語が表示されなくなります。 

唯一可能な過度の選択は、最後に選択した要素です。 この最後の要素を他の進行に移動すると、残りの有効な構成がカバーされます。 元のパーティションも、最後に選択した要素を移動して得られたパーティションも等差数列 B を生成しない場合、その差を使用するパーティションは存在しません。 したがって、3 つの候補の相違点を試すだけで、相違点が存在する場合は必ず解決策を見つけることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_ap(v):
    m = len(v)
    if m == 0:
        return False
    if m <= 2:
        return True

    d = v[1] - v[0]
    for i in range(2, m):
        if v[i] - v[i - 1] != d:
            return False
    return True

def try_pair(a, l, r):
    n = len(a)

    d = a[r] - a[l]
    expected = a[l]

    used = [False] * n
    A = []
    last_idx = -1

    for i in range(n):
        if a[i] == expected:
            used[i] = True
            A.append(a[i])
            expected += d
            last_idx = i

    B = [a[i] for i in range(n) if not used[i]]

    if is_ap(B):
        return A, B

    A.pop()
    used[last_idx] = False

    B = [a[i] for i in range(n) if not used[i]]

    if is_ap(B):
        return A, B

    return None

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    if n == 2:
        print(a[0])
        print(a[1])
        return

    pairs = [(0, 1), (0, 2), (1, 2)]

    for l, r in pairs:
        res = try_pair(a, l, r)
        if res is not None:
            A, B = res

            if len(A) == 0 or len(B) == 0:
                continue

            print(*A)
            print(*B)
            return

    print("No solution")

if __name__ == "__main__":
    solve()
```機能`is_ap`等差数列の正確な定義を実装します。 長さ 1 と 2 は自動的に有効になりますが、問題では両方のサブシーケンスが空でないことが必要であるため、長さ 0 は拒否されます。 

機能`try_pair`候補チェックを 1 つ実行します。 違いは、最初の 3 つの要素の間で選択されたペアによって決まります。 スキャン中に、変数`expected`進行 A に出現する必要がある次の値を格納します。 

配列`used`A にどのポジションが割り当てられたかを記録します。B を次から再構成します。`used`スキャン中に両方のサブシーケンスを維持しようとするよりも簡単で、エラーが発生しにくくなります。 

繊細なディテールが収納されています`last_idx`。 最初のバージョンが失敗した場合、最後に選択された要素のみが A から削除されます。更新されたバージョンから B を再計算します。`used`配列は、相対的な順序が正しいままであることを保証します。 

すべての算術演算では Python 整数が使用されるため、値が次の値に達する場合でもオーバーフローは心配ありません。$10^8$。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = out

    def solve():
        input = sys.stdin.readline

        def is_ap(v):
            if len(v) == 0:
                return False
            if len(v) <= 2:
                return True
            d = v[1] - v[0]
            for i in range(2, len(v)):
                if v[i] - v[i - 1] != d:
                    return False
            return True

        def try_pair(a, l, r):
            d = a[r] - a[l]
            expected = a[l]

            used = [False] * len(a)
            A = []
            last = -1

            for i, x in enumerate(a):
                if x == expected:
                    used[i] = True
                    A.append(x)
                    expected += d
                    last = i

            B = [a[i] for i in range(len(a)) if not used[i]]
            if is_ap(B):
                return A, B

            A.pop()
            used[last] = False
            B = [a[i] for i in range(len(a)) if not used[i]]

            if is_ap(B):
                return A, B

            return None

        n = int(input())
        a = list(map(int, input().split()))

        if n == 2:
            print(a[0])
            print(a[1])
            return

        for l, r in [(0, 1), (0, 2), (1, 2)]:
            res = try_pair(a, l, r)
            if res:
                A, B = res
                if A and B:
                    print(*A)
                    print(*B)
                    return

        print("No solution")

    solve()

    sys.stdout = old_stdout
    return out.getvalue()
