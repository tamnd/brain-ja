 ## 解決策
 ## 問題の理解

 入力は、フォームのタグから構築された有効な XML のようなテキストです。`<a>`そして`</a>`、タグ名は 1 つの小文字です。 タグはネストすることができ、複数の XML フラグメントを次々に出現させることができます。 

タスクは XML を検証することではありません。 有効性はすでに保証されています。 再フォーマットするだけです。 

各タグは独自の行に印刷する必要があります。 インデントはネストの深さによって異なります。 深さのタグ`h`の前にある`2 * h`スペース。 

たとえば、```
<a><b></b></a>
```タグ`<a>`深みにある`0`、`<b>`中にあります`<a>`だからそれは深いところにある`1`、 そして`</b>`奥行きも印刷されます`1`。 

入力長は最大 1000 文字です。 これは小さいですね。 たとえ`O(n²)`解決策は問題なく適合しますが、問題の構造により、当然単純な線形スキャンが必要になります。 

主な課題は、終了タグのインデントを正しく処理することです。 よくある間違いは、現在の深さを使用して終了タグを出力し、その後のみ深さを減らすことです。 考慮する：```
<a></a>
```正しい出力:```
<a>
</a>
```印刷したら`</a>`ネスト レベルを下げる前は、誤って 2 つのスペースでインデントされて表示されます。 

もう 1 つの微妙なケースは、開始タグの直後に終了タグがあることです。```
<a><b></b></a>
```正しい出力:```
<a>
  <b>
  </b>
</a>
```の深さ`</b>`の深さと同じです`<b>`。 終了タグを出力する前に、ネスト レベルを下げる必要があります。 

3 番目のケースは、複数の兄弟要素です。```
<a></a><b></b>
```正しい出力:```
<a>
</a>
<b>
</b>
```1 つの要素が終了したら、次の兄弟が正しいインデントで開始されるように、ネスト レベルを前の値に戻す必要があります。 

## アプローチ

 この問題を解決する強引な方法は、次のタグを繰り返し見つけ、以前に処理されたすべてのタグを調べてそのネスト レベルを決定し、それを出力することです。 このようなアプローチでは、奥行き情報が何度も再計算されます。 長さの文字列で`n`、それは次のことにつながる可能性があります`O(n²)`仕事。 

入力サイズは十分小さいため、これでも問題ありませんが、よりクリーンな解決策があります。 

重要な観察は、タグに遭遇した場合にのみネストの深さが変化するということです。 

開始タグにより、その中にあるすべてのものの深さが増します。 終了タグは現在のネストされた領域を終了し、深さを減らします。 

これは、XML テキストを左から右に 1 回だけ処理できることを意味します。 タグに遭遇すると、それが開いているのか閉じているのかを判断します。 

開始タグの場合:```
<a>
```現在の深さを使用してそれを印刷し、その後深さを増やします。 

終了タグの場合:```
</a>
```まず深さを減らしてから印刷します。 

この 1 つのルールにより、有効な XML 構造ごとに正しいインデントが自動的に生成されます。 

各文字はタグの抽出中に 1 回だけ検査されるため、ソリューションは線形時間で実行されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 受け入れられるが不要 |
 | 最適 | O(n) | O(n) | 承認済み |

 の`O(n)`補助スペースは、出力行を印刷する前に保存することで得られます。 

## アルゴリズムのチュートリアル

 1. XML 文字列を読み取ります。 
2. 文字列を左から右にスキャンします。 
3. いつでも`<`が見つかった場合は、一致するまで続行します`>`完全なタグを抽出します。 
4. タグが終了タグであるかどうかを確認します。 終了タグは次で始まります`</`。 
5. タグが終了タグの場合は、印刷する前に現在の深さを 1 つ減らします。 閉じられている要素は、それ自体の内部のレベルではなく、親レベルに属します。 
6. タグの前に次の文字を出力します。`2 × depth`スペース。 
7. タグが開始タグの場合は、印刷後に深さを 1 つ増やします。 その要素内のすべては 1 レベル深くなります。 
8. 文字列全体が処理されるまで続行します。 

### なぜ効果があるのか

 不変条件を維持する`depth`は常に、終了タグがまだ処理されていない現在開いているタグの数と等しくなります。 

開始タグが印刷される前は、そのタグは現在のネスト レベルに属しているため、現在の深さで印刷するのは正しいことです。 印刷後、そのタグがアクティブになるため、深さが 1 つ増加します。 

終了タグが出力されるまでは、対応する要素はアクティブとはみなされません。 深さを減らすと、まず親要素のネスト レベルが復元されます。 この更新された深さを使用して印刷すると、ステートメントで必要なインデントが正確に得られます。 

すべてのタグは XML ネスト規則に従って深さを更新するため、すべての行が正しいレベルで出力されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    depth = 0
    lines = []

    i = 0
    n = len(s)

    while i < n:
        j = i
        while s[j] != '>':
            j += 1

        tag = s[i:j + 1]

        if tag.startswith("</"):
            depth -= 1
            lines.append("  " * depth + tag)
        else:
            lines.append("  " * depth + tag)
            depth += 1

        i = j + 1

    sys.stdout.write("\n".join(lines))

if __name__ == "__main__":
    solve()
```スキャンでは 2 つのポインターが使用されます。`i`現在のタグの始まりをマークし、`j`マッチングまで進みます`>`が見つかりました。 

終了タグの操作順序は、実装において最も重要な詳細です。 くぼみを生成する前に、深さを減らす必要があります。 これら 2 つの操作を逆にすると、すべての終了タグが 1 レベル右に移動しすぎます。 

タグを開くには、逆の順序が必要です。 タグ自体は現在のレベルに属しているため、最初に出力され、その後でその内容のネストの深さが増加します。 

入力には有効な XML テキストのみが含まれることが保証されているため、スタックや検証ロジックは必要ありません。
