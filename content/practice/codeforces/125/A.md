 ## 解決策
 ## 問題の理解

 バーデンでは変換ルールが現実世界とは異なります。 1 インチは 3 センチメートルに相当し、1 フィートには 12 インチが含まれます。 

長さはセンチメートル単位で与えられます。 ここでの課題は、その長さをフィートとインチの組み合わせとして表現することです。 元の長さは正確な整数のインチに対応しない可能性があるため、最初にステートメントで説明されている特別な丸め規則に従って最も近い整数インチに丸める必要があります。 その後、すべての等価表現の中で、フィートの数を最大化する必要があります。 

1 インチはちょうど 3 センチメートルなので、センチメートルをインチに変換すると、最も近い整数を計算することになります。$n / 3$。 このステートメントでは、1 cm が 0 インチになる、2 cm が 1 インチになるなどの例が示されており、最も近い整数への通常の丸めが確認されます。 

制約が非常に小さいので、$1 \le n \le 10000$。 非効率的なソリューションであっても、制限内に簡単に収まります。 課題はパフォーマンスではなく、四捨五入ルールを正しく処理し、インチをフィートと残りのインチに変換することです。 

最も一般的な間違いの原因は、丸めのステップです。 

入力を考慮してください:```
1
```我々は持っています$1/3 = 0.333...$、0 インチに丸められます。 正しい出力は次のとおりです。```
0 0
```小数値を常に切り上げる不注意な実装では、誤って 1 インチが生成されてしまいます。 

入力を考慮してください:```
2
```我々は持っています$2/3 = 0.666...$、1 インチに丸められます。 正しい出力は次のとおりです。```
0 1
```フロア分割を使用した不注意な実装では、0 インチが生成されます。 

もう 1 つの微妙なケースは、丸めによって総インチ数が増加し、追加のフィートが作成される場合に発生します。 

例えば：```
35
```以来$35/3 = 11.666...$、四捨五入した値は 12 インチです。 12 インチは 1 フィートに等しいため、正しい出力は次のようになります。```
1 0
```四捨五入する前にセンチメートルをフィートとインチに直接変換する実装では、この移行が見逃されます。 

## アプローチ

 ブルートフォース ソリューションでは、考えられるすべてのフィート数を試し、それをインチに変換し、どの表現が四捨五入された長さに一致するかを確認することができます。 入力サイズが小さいため、これでも即座に実行されます。 丸めて最大約 3333 インチの長さの場合、数百の可能性のみをテストします。 

問題の実際の構造ははるかに単純です。 長さを丸められた整数のインチに変換すると、フィートを最大化するという要件は明白に解釈されます。つまり、できるだけ多くの 12 インチのグループを使用します。 

問題は当然ながら 2 つの独立した部分に分かれます。 

まず、最も近い整数のインチ数を計算します。 1 インチは 3 センチメートルに等しいため、次の最も近い整数が必要です。$n/3$。 正の整数の場合、これは完全に整数演算で行うことができます。$$\text{inches} = \left\lfloor \frac{n+1}{3} \right\rfloor$$この式は、必要な丸め動作を再現します。 

- 1cm → 0インチ
 - 2cm → 1インチ
 - 4cm → 1インチ
 - 5cm → 2インチ

 合計インチ数がわかったら、フィートを最大化するということは、12 インチの完全なグループをできるだけ多く取得することを意味します。 フィートの数は 12 で割った整数であり、残りのインチは 12 を法とした余りです。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$n$、センチメートル単位の長さ。 
2. センチメートルを最も近い整数のインチに変換します。 

1 インチは 3 センチメートルに等しいため、正確な値は次のようになります。$n/3$。 必要な丸めは次のように実装できます。$$\text{inches} = (n + 1) // 3$$小数部は常に 0、1/3、または 2/3 であるため、これは機能します。 
3. 最大フィート数を計算します。 

各フィートには 12 インチが含まれるため、次のようになります。$$\text{feet} = \text{inches} // 12$$4. 残りのインチを計算します。$$\text{rem} = \text{inches} \bmod 12$$5. 出力`feet`そして`rem`。 

### なぜ効果があるのか

 四捨五入後、長さは正確な整数のインチ数で表されます。 フィートとインチで表​​現する場合は、次の条件を満たす必要があります。$$12 \cdot \text{feet} + \text{inches\_remaining} = \text{total\_inches}$$残りのインチは 0 ～ 11 です。 

12 による整数除算により、可能な限り最大数の 12 インチの完全なグループが生成されます。 残りは、それらのグループを取得した後に残った正確なインチ数です。 整数除算で得られるよりも完全なグループを含む表現はないため、結果として得られるフィート数は最大になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

inches = (n + 1) // 3
feet = inches // 12
rem = inches % 12

print(feet, rem)
```最初のステップでは、四捨五入されたインチ数が計算されます。 使用する`(n + 1) // 3`浮動小数点演算を完全に回避し、ステートメントの丸め規則と正確に一致します。 

次の 2 行では、インチからフィートおよび残りのインチへの標準変換を実行します。 整数除算では、合計インチ数に収まる完全なフィートの数がカウントされ、モジュロでは残りのインチが求められます。 

順序が重要です。 まずセンチメートル値をインチに四捨五入してから、フィートに変換する必要があります。 四捨五入する前に変換を実行すると、35 cm などの値に対して不正確な答えが得られます。この場合、四捨五入により 11.666... インチが 12 インチに変更され、追加のフィートが作成されます。

# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(sys.stdin.readline())
    inches = (n + 1) // 3

    rem = inches % 12

    return f"{feet} {rem}"

# provided sample

 ## 特殊なケース

 最初のトリッキーなケースは次のとおりです。```
1
```アルゴリズムは以下を計算します。$$(1+1)//3 = 0$$つまり全長は0インチになります。 それから：$$0//12 = 0,\quad 0\%12 = 0$$出力は次のようになります。```
0 0
```これは、必要な丸めルールと一致します。 

2 番目のトリッキーなケースは次のとおりです。```
2
```アルゴリズムは以下を計算します。$$(2+1)//3 = 1$$したがって、丸みを帯びた長さは1インチです。 それから：$$1//12 = 0,\quad 1\%12 = 1$$出力は次のとおりです。```
0 1
```これにより、2 cm が 1 インチに切り上げられることが確認されます。 

3 番目のトリッキーなケースは次のとおりです。```
35
```アルゴリズムは以下を計算します。$$(35+1)//3 = 12$$それから：$$12//12 = 1,\quad 12\%12 = 0$$出力は次のとおりです。```
1 0
```このケースでは、結果をフィートとインチに分割する前に丸めが完了していることを検証します。 順序が逆であれば、答えは間違っています。
