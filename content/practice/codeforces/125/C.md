 ## 解決策
 ## 問題の理解

 私たちは持っています`n`ホビットとできるだけ多くのパーティーの日を作りたいと思っています。 

毎日は、ホビットの空ではないサブセットであるゲスト リストに対応します。 

ゲスト リストは 2 つの条件を満たしている必要があります。 

異なる日のペアごとに、両方の日に少なくとも 1 人のホビットが招待されなければなりません。 セット用語では、2 つのゲスト リストごとに交差する必要があります。 

異なる日の 3 日ごとに、3 日すべてに招待されたホビットが存在してはなりません。 ホビットは 1 日または 2 日現れることもありますが、3 日以上現れることはありません。 

入力には次のみが含まれます`n`、利用可能なホビットの数。 日数を最大限に増やす必要がある`k`、その後、毎日 1 つの有効なゲスト リストを出力します。 

制約`n ≤ 10000`十分に小さいため、出力サイズが実際の制限になります。 受け入れられた建設物は、合計で最大約 1 万個のホビットを生成する必要があります。 による解決策`O(n²)`記憶は不可能だろうから`10000² = 10^8`要素。 おおよその解決策`O(n)`作業と出力はまったく問題ありません。 

厄介な点は、この問題では単に有効なスケジュールではなく、可能な最大日数が求められることです。 

考慮する`n = 3`。 不用意に建設すると、わずか 2 日しかかからない可能性があります。```
1 2
2 3
```これは条件を満たしていますが、最大ではありません。 正解は 3 日です。```
1 2
1 3
2 3
```もう 1 つの簡単な間違いは、3 日以内に 1 匹のホビットを出現させることです。 例えば：```
Day 1: {1,2}
Day 2: {1,3}
Day 3: {1,4}
```すべての日々が交差するけど、ホビット`1`3 日すべてに属し、2 番目の条件に違反します。 

別の落とし穴は、すべての日が交差する必要があることを忘れていることです。 例えば：```
Day 1: {1,2}
Day 2: {2,3}
Day 3: {3,4}
```1 日目と 3 日目は連続していないため、構築は無効です。 

課題は、可能な限り最も強力な日数の上限を理解し、それを達成するスケジュールを構築することです。 

## アプローチ

 ブルートフォースの考え方は、毎日をホビットの任意の部分集合として見ることから始まります。 サブセットのさまざまなコレクションを試して、2 つの条件を確認することができます。 1 人の候補者を検証するには、すべての日のペアとトリプルを調べる必要があります。 たとえ何らかの方法で数百日のみに制限したとしても、サブセットの検索空間は指数関数的に増加します。`n`、これは完全に不可能になります。 

重要な観察は、一匹のホビットを見ることから得られます。 

どのホビットも 3 つの異なる日に参加できないため、各ホビットは最大 2 日間に所属できます。 

ホビットがちょうど 2 日、たとえば数日間に属すると仮定します。`A`そして`B`。 すると、そのホビットはそのペアを表していると考えることができます。`(A,B)`。 

次に最初の条件を考えてみましょう。 どの曜日にも共通のホビットが必要です。 ホビットは 3 日に属することはできないため、1 人のホビットが目撃できるのは 1 組の日だけです。 同時に 2 つの異なるペアの共通ゲストとして機能することはできません。 

あれば`k`日、日のペアの数は$$\binom{k}{2}.$$各ペアには少なくとも 1 つの専用のホビットが必要です。 しかないので、`n`ホビット、$$\binom{k}{2} \le n.$$これによりすぐに上限が決まります`k`。 

次の問題は、この限界が達成可能かどうかです。 

そうです。 取る`k`日々。 一日ごとに`(i,j)`、まさにその 2 日間に招待されたホビットを 1 つ作成します。 次に、そのホビットのためにすべての日のペアが交差し、それぞれが正確に 1 つのペアに割り当てられているため、3 つの日に属するホビットはありません。 

この構築では正確に使用します$$\binom{k}{2}$$ホビット。 

もし`n`が大きい場合、残りのホビットは使用されません。 この声明では、ゲスト リストが住民の空でないサブセットであることのみを要求しており、すべてのホビットが登場する必要があるというわけではありません。

## アルゴリズムのチュートリアル

 1. 最大の整数を見つける`k`そのような`k(k-1)/2 ≤ n`。 
2.作成`k`空のゲストリスト。 
3. から始まるホビットの番号を付けます。`1`。 
4. 2 日ごとに`(i,j)`と`i < j`、新しいホビットを作成し、両方の日に追加します。`i`そしてその日`j`。 

このホビットは、その 2 日が交差するユニークな目撃者となります。 
5. すべてのペアを処理した後、正確に`k(k-1)/2`ホビットが使われていました。 
6. 出力`k`。 
7. 各ゲストリストを出力します。 

### なぜ効果があるのか

 あります`k(k-1)/2`数日間。 この構造では、各ペアに 1 つの異なるホビットが割り当てられます。 

任意の 2 つの異なる日を取ります。 彼らの対応するペアは、まさにその 2 日に現れるホビットを受け取りました。そのため、その日が交差します。 

ホビットなら誰でも連れて行きましょう。 これは、特定の 1 組の日のために作成され、まさにこれら 2 つのゲスト リストに挿入されました。 したがって、3 つの異なる日にホビットが現れることはありません。 

構造は正確に使用します`k(k-1)/2`ホビット。 以来`k`を満たす最大値として選択されました`k(k-1)/2 ≤ n`、以上のスケジュール`k`日数はそれ以上必要になります`n`ホビット、カウントの議論に矛盾します。 したがって、日数は最大になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    k = 1
    while (k + 1) * k // 2 <= n:
        k += 1

    groups = [[] for _ in range(k)]

    cur = 1
    for i in range(k):
        for j in range(i + 1, k):
            groups[i].append(cur)
            groups[j].append(cur)
            cur += 1

    print(k)
    for g in groups:
        print(*g)

solve()
```最初のループでは、実行可能な最大の日数を見つけます。 以来`k`約 141 を超えることはなく、単純な線形探索でも十分です。 

配列`groups[i]`その日のゲストリストを保存します`i`。 

ネストされたループは、順序のない日のペアごとに繰り返されます。 ペアごとに、新しいホビット識別子が作成され、対応する両方のゲスト リストに挿入されます。 識別子が再利用されることはありません。 

よくある間違いは、正確に到達するまでホビットを割り当て続けることです。`n`。 それは不必要です。 証明に必要なのはせいぜい`n`ホビット。 未使用のホビットは許可されます。 

もう 1 つの微妙な点はインデックスです。 プログラムでは日は 0 から始まるインデックスで保存されますが、ホビットのラベルは次から始まります。`1`なぜなら、声明では住民の数が次のとおりであるためです。`1`に`n`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k²) | 2 日ごとに 1 回の反復 |
 | スペース | O(k²) | 割り当てられたすべてのホビットをゲスト リストに保存します。 
| 出力サイズ | O(k²) | その通り`k(k-1)`印刷されたゲスト出演 |

 以来`k`は最大の整数です`k(k-1)/2 ≤ n`、 我々は持っています`k = O(√n)`。 のために`n = 10000`、`k ≤ 141`したがって、保存および印刷されるゲスト出演は 2 万件未満です。 これは簡単に制限内に収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(input())

    k = 1
    while (k + 1) * k // 2 <= n:
        k += 1

    groups = [[] for _ in range(k)]

    cur = 1
    for i in range(k):
        for j in range(i + 1, k):
            groups[i].append(cur)
            groups[j].append(cur)
            cur += 1

    out = [str(k)]
    for g in groups:
        out.append(" ".join(map(str, g)))

    return "\n".join(out)

 ## 特殊なケース

 最小限の入力を考慮してください。```
3
```アルゴリズムは次のことを見つけます`k = 3`なぜなら`3·2/2 = 3`。 3組の日はホビットを受け取ります`1`、`2`、 そして`3`。 毎日ちょうど2人のゲストが来ます。 この構造は最小の境界でも有効です。 

考慮する：```
5
```まだ入手可能です`k = 3`なぜなら`4·3/2 = 6 > 5`。 ホビットは 5 匹存在しますが、アルゴリズムでは 3 匹だけを使用します。 これは、未使用のホビットが無害であることを示しています。 この問題では、住民全員が登場する必要はありません。 

三角数と正確に等しい値を考えます。```
10
```アルゴリズムは次のことを見つけます`k = 5`なぜなら`5·4/2 = 10`。 利用可能なすべてのホビットが、1 組の日に 1 つずつ使用されます。 これは、カウントの上限に正確に到達する最も厳しいケースです。 

次の三角数のすぐ下の値を考えてみましょう。```
9
```よくある off-by-one バグでは、誤った選択が発生します。`k = 5`, しかし、それには10組のペアのホビットが必要になります。 アルゴリズムは正しく維持します`k = 4`なぜなら`10 > 9`。 最大性の証明により、5 日間は不可能であることが保証されます。
