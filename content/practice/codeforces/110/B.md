 ## 解決策
 ## 問題の理解

 長さの小文字の文字列を構築する必要があります`n`繰り返される文字に関する特別な条件を満たすもの。 

すべてのキャラクターについて、それが出現するすべての位置を調べます。 キャラクターが複数回出現する場合、連続する位置の差は常に幸運な数字でなければなりません。 この問題では、ラッキー ナンバーは、10 進表現に数字のみが含まれる整数です。`4`そして`7`。 

タスクは、有効な文字列を構築するだけではありません。 すべての有効な長さの文字列の中で`n`、辞書編集的に最小のものを出力する必要があります。 

制約は十分に小さいため、答えを直接構築することが意図した方向です。 と`n ≤ 10^5`、直線的な時間、あるいは`O(n log n)`ただし、指数関数的なものや、文字列に対するブルート フォース検索に基づくものは不可能です。 小さなアルファベット上のすべての文字列を試しても、すぐに爆発してしまいます。`26^n`小文字の文字列も可能です。 

重要な問題は、辞書編集上の最小限性です。 単純に貪欲な選択をすると、誤って無効な将来の状態が作成される可能性があります。 常に有効であり、証明可能な最小限のパターンが必要です。 

見落としやすいエッジケースが次のような場合に現れます。`n < 4`。 最小のラッキーナンバーは`4`、距離が離れる前に文字を繰り返すことはできません`4`。 たとえば:

 入力:```
3
```正しい出力:```
abc
```文字を繰り返すのが早すぎる不用意な解決策は、次のような問題を引き起こす可能性があります。`"aba"`、しかし二人は`'a'`位置はによって異なります`2`、これは幸運ではありません。 

もう 1 つの微妙なケースは、文字列の長さが正確に一致する場合です。`5`。 

入力：```
5
```正しい出力:```
abcda
```繰り返された`'a'`ポジションは`1`そして`5`、 違い`4`、それは幸運です。 試してみたら`"abcab"`代わりに、`'a'`位置はによって異なります`3`、 無効。 

3 番目の罠は、多くの幸運な距離が必要であると仮定していることです。 実際の距離では、`4`それだけで答え全体を構築するには十分です。 一部のソリューションでは、混合することで構築が過度に複雑になります。`4`そして`7`、しかしそれは不要です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 辞書順に文字列を生成し、それぞれが条件を満たすかどうかを確認します。 文字列を検証するために、各文字のすべての位置を保存し、隣接するすべての違いが幸運であることを確認します。 

検証自体は大まかに言うと安価です`O(n)`。 問題は候補文字列の数です。 小さなアルファベットの上でも`{a,b,c,d}`、すでにあります`4^100000`可能性はありますが、それは完全に不可能です。 

次の観察により、問題は完全に変わります。 実際には、任意の幸運な距離は必要ありません。 最小の幸運の数字は、`4`、そして、繰り返される文字がすべて正確に一致する場合、`4`位置が離れている場合、条件は自動的に満たされます。 

これは、同じ長さのブロックが繰り返されることを示唆しています`4`。 

次のパターンを考えてみましょう。```
abcdabcdabcd...
```毎`'a'`異なる位置に表示されます`4`。 同じことが当てはまります`'b'`、`'c'`、 そして`'d'`。 以来`4`幸運なことに、文字列は有効です。 

ここで、このパターンが辞書編集的に最小限である理由を示さなければなりません。 

辞書編集的に最小化するには、すべての位置で、条件に違反しない最小の文字が必要です。 最初の文字は明確に次のようにする必要があります`'a'`。 2番目はできません`'a'`距離があるから`1`ついてないからこうなる`'b'`。 3番目はできません`'a'`または`'b'`, となるので、`'c'`。 4番目は次になります`'d'`。 

5 番目の位置では、再利用できます。`'a'`なぜなら、以前の`'a'`まさにそうでした`4`前の位置にあります。 以来`'a'`は最小の有効な選択肢であるため、それを採用します。 同じ推論が永遠に繰り返され、周期的な文字列が生成されます。`"abcd"`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 繰り返しのベースパターンを作成する`"abcd"`。 
2. 答えを 1 文字ずつ作成します。 
3. ポジションについて`i`、追加`pattern[i % 4]`。 

これにより、次のシーケンスが繰り返されます。```
a b c d a b c d ...
```4. 結果の文字列を出力します。 

これが機能する理由は、同じ文字が繰り返し出現するたびに、正確に一致するためです。`4`離れた位置にあります。 以来`4`が幸運な数字である場合、各文字リスト内の隣接関係の違いはすべて有効です。 

### なぜ効果があるのか

 この構造は 2 つの特性を同時に維持します。 

まず、有効性。 すべての文字は正確に一致した後にのみ繰り返されます`4`ポジション。 連続する等しい文字`'a'`、`'b'`、`'c'`、 そして`'d'`常に異なる`4`、それは幸運です。 

第二に、辞書編集的な最小性です。 どの位置でも、ルールに違反しない最小の文字を選択します。 最初の 4 つの位置はすべて異なるものである必要があります。`1`、`2`、 そして`3`幸運ではありません。 それは強制する`"abcd"`。 それ以降は 4 つ前の位置からの再利用が有効となり、それより小さいものを選択することはできません。 帰納法により、周期的`"abcd"`pattern は有効な最小の文字列です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pattern = "abcd"

    ans = []
    for i in range(n):
        ans.append(pattern[i % 4])

    print("".join(ans))

solve()
```構築自体がソリューション全体であるため、実装は意図的に単純になっています。 

変数`pattern`繰り返しブロックを保存します。 あらゆるポジションについて`i`、私たちは取る`pattern[i % 4]`、インデックスを循環します。`0, 1, 2, 3`。 

リストを使用して、`"".join()`これは、Python で大きな文字列を構築するための標準的な効率的な方法です。 ループ内で文字列の連結を繰り返すと、2 次になる可能性があります。 

1 ベースの推論を頭の中で使用すると、インデックス作成は間違いやすくなります。 モジュロ演算は、ゼロベースのインデックスで自然に機能します。 

| 私 | i % 4 | キャラクター |
 | --- | --- | --- |
 | 0 | 0 | |
 | 1 | 1 | b |
 | 2 | 2 | c |
 | 3 | 3 | d |
 | 4 | 0 | |

 これにより、意図した周期シーケンスが正確に生成されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())
    pattern = "abcd"

    ans = []
    for i in range(n):
        ans.append(pattern[i % 4])

    print("".join(ans))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    backup_stdout = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup_stdout
    return out.getvalue().strip()

# provided sample
assert run("5\n") == "abcda", "sample 1"

# minimum size
assert run("1\n") == "a", "single character"

# small boundary
assert run("4\n") == "abcd", "first full block"

# repeat begins
assert run("8\n") == "abcdabcd", "two full blocks"

# off-by-one check
assert run("9\n") == "abcdabcda", "correct modulo cycling"

# large input
res = run("100000\n")
assert len(res) == 100000, "maximum size length"
assert res[:8] == "abcdabcd", "pattern consistency"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`8`|`abcdabcd`| 有効な周期的繰り返し |
 |`9`|`abcdabcda`| モジュロインデックス作成の正確性 |

 ## 特殊なケース

 いつ`n = 1`、アルゴリズムは次のように出力します。```
a
```繰り返される文字がないため、条件は空に true になります。 この構造はパターンの最初の文字を取得するだけなので、これを自然に処理します。 

いつ`n = 3`、アルゴリズムは次のように出力します。```
abc
```トレース:

 | ポジション | キャラクター |
 | --- | --- |
 | 0 | |
 | 1 | b |
 | 2 | c |

 文字が繰り返されないため、次のような無効な距離が回避されます。`1`、`2`、 または`3`。 再利用した不注意で貪欲なソリューション`'a'`早すぎるとここで失敗します。 

いつ`n = 5`の場合、出力は次のようになります。```
abcda
```二人`'a'`ポジションは`1`そして`5`、 違い`4`。 これは繰り返しが合法と​​なる最初の瞬間であり、アルゴリズムはすぐにそれを利用して辞書編集上最小限に留まります。 

次のような非常に大きな入力の場合`100000`、パターンは追加のロジックなしで定期的に継続します。 繰り返されるすべての出来事は依然として正確に異なります`4`したがって、正確さは文字列の長さに依存しません。
