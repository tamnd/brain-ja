 ## 解決策
 ## 問題の理解

 正の整数が与えられ、それがほぼ幸運な数字であるかどうかを判断する必要があります。 幸運の数字の数 (数字が 4 または 7 に等しい) 自体が幸運な数字である場合、その数字はほぼ幸運な数字であるとみなされます。 ラッキーナンバーには、10 進数表現で 4 と 7 のみが含まれます。 たとえば、数字 40047 には 3 つの幸運な数字 (4 が 2 つと 7 が 1 つ) が含まれていますが、3 は幸運な数字ではないため、40047 はほとんど幸運ではありません。 一方、44777 には吉数が 5 つあり、5 は縁起ではないため、ほとんど幸運ではありません。 

入力範囲は最大 10^18 です。 これは、数値が 32 ビット整数に収まるとは想定できないことを意味しますが、Python は任意の長さの整数を自然に処理します。 また、n は最大 18 桁であるため、n までのすべての数値を反復したり、その桁を 1 回パスする以上のことはできません。 したがって、アルゴリズムは桁数に対して線形時間で実行する必要があります。 エッジ ケースには、幸運の数字が 0 の数字、それ自体が幸運な数字、および C++ などの言語で不注意に他の型に変換するとオーバーフローする可能性がある非常に大きな数字が含まれます。 

たとえば、数字 4444 には 4 つの幸運な数字が含まれています。 4 は幸運な数字なので、4444 はほぼ幸運な数字です。 不用意に実装すると、カウント自体の幸運のチェックを忘れたり、正確に 4 または 7 ではない桁を数え間違えたりする可能性があります。 

## アプローチ

 ブルートフォース手法では、数字を読み取り、各桁を反復処理し、各桁についてそれが 4 か 7 かを確認します。幸運の数字を数えた後、1 からそのカウントまで反復して、一連の数字が幸運の数字を形成するかどうかを確認できます。 これは正しいですが、不必要に複雑です。 数値に 4 と 7 のみが含まれているかどうかのチェックは、数値を生成するのではなく、単一の文字列チェックで行うことができます。 また、ブルートフォース手法では、18 (最大桁数) までのすべてのラッキーナンバーを計算しようとする可能性がありますが、ラッキーナンバーの数は最大でも n の桁数、つまり 18 であるため、これは過剰です。 

重要な洞察は、幸運の数字の数を数えるだけで済み、その数字自体が 4 と 7 だけで構成されているかどうかを確認するだけでよいということです。 これにより、問題は単純な 2 パス文字列スキャンに帰着します。 最初のパスでは、n の 4 と 7 をカウントします。 2 番目のパスでは、結果のカウントがその桁を調べて幸運な数字であるかどうかを確認します。 他の数値演算は必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (カウントまでのすべての数値をチェック) | O(d^2)、d は桁数 | お(1) | 不必要な複雑さ |
 | 最適 (2 パス数字チェック) | O(d)、ここで d ≤ 18 | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数のサイズを気にしないように、数値を文字列として読み取ります。 これにより、変換の問題なく 10^18 までの数値を処理できるようになります。 
2. カウンタをゼロに初期化します。 文字列内の各文字を反復処理します。 文字が「4」または「7」の場合、カウンターをインクリメントします。 これは、n 内の幸運の数字の合計数を数えます。 
3. カウンタを文字列に変換して、その桁を確認します。 この文字列の各桁を反復処理します。 すべての数字が「4」または「7」の場合、その数字はほぼ幸運です。 それ以外の場合はそうではありません。 
4. カウントが幸運な場合は「YES」を出力し、そうでない場合は「NO」を出力します。 

機能する理由: カウンターが幸運の数字の数を正しく追跡するという不変条件を維持し、このカウントを幸運の数字のプロパティでチェックすることで、ほぼ幸運の数字を正しく分類することが保証されます。 すべてのステップは、無関係な数値に対する近似や反復を行わずに、問題の定義を直接実装します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = input().strip()

lucky_count = 0
for ch in n:
    if ch == '4' or ch == '7':
        lucky_count += 1

lucky_count_str = str(lucky_count)
for ch in lucky_count_str:
    if ch != '4' and ch != '7':
        print("NO")
        break
else:
    print("YES")
```最初のループでは幸運の数字を数えます。 カウンターを文字列に変換すると、カウント自体が幸運であることを簡単に 2 番目のループで検証できるようになります。 の`else`for ループでは、そうでない場合にのみ実行されます。`break`これは、すべての桁が 4 または 7 であることを意味します。これにより、ネストされた条件文と off-by-one エラーが回避されます。 Python はすべての整数サイズを処理するため、大きな n に対して特別な処理は必要ありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(d) | n の各桁を 1 回スキャンし、lucky_count の各桁を最大 2 回スキャンします (d ≤ 18) |
 | スペース | お(1) | 少数の整数変数と文字列変数のみが保存されます。 余分なデータ構造はありません |

 d ≤ 18 であるため、このアルゴリズムは非常に高速で、最小限のメモリ使用量で 2 秒の制限時間内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    
    n = input().strip()
    lucky_count = 0
    for ch in n:
        if ch == '4' or ch == '7':
            lucky_count += 1
    lucky_count_str = str(lucky_count)
    for ch in lucky_count_str:
        if ch != '4' and ch != '7':
            return "NO"
    return "YES"

# Provided samples
assert run("40047\n") == "NO", "sample 1"
assert run("447777\n") == "NO", "sample 2"

# Custom cases

assert run("7777777\n") == "YES", "all lucky digits, count 7"
assert run("123456789\n") == "NO", "no lucky digits"
assert run("47474747\n") == "YES", "8 lucky digits, 8 is not lucky, should be NO"
assert run("447447447447447447\n") == "YES", "count 18, 18 not lucky, output NO"

 ## 特殊なケース

 123 など、幸運の数字がない数字の場合、カウントは 0 です。アルゴリズムは 0 を、4 も 7 も含まない文字列 '0' に変換します。for ループはこれを検出し、NO を出力します。 

可能な最大の数値 10^18 - 1 の場合、文字列表現は 18 文字です。 アルゴリズムは 4 または 7 を数え、大きな数字を自然に処理して、ほぼ幸運な正しいチェックを生成します。 

カウントが 4 や 7 など、正確に 1 桁の幸運な数字である場合、アルゴリズムはその数字をほぼ幸運であると正確に識別し、カウンターの文字列変換がすべての大小のカウントに対して機能することを示しています。
