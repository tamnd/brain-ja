 ## 解決策
 ## 問題の理解

 この問題は一連の数値から始まり、要素のすべてのペアに対してグローバルな式を計算するように求められます。 入力に現れる配列ごとに、要素間のペアごとの違いに依存する関数を効果的に集約しています。 一見すると、これはすべてのペアにわたる二重和のように見えますが、これはすべてのインデックスにわたる二次計算を示唆しています。 

主な難点は、式には値間の絶対的な差が含まれるため、通常は代数の単純化が妨げられることです。 直接解釈するには、すべてのペアを反復処理し、次のような項を計算する必要があります。$|p_i - p_j|$、これはすぐに次のことを示唆します。$O(N^2)$アプローチ。 

ただし、このタイプの Codeforces 問題によって暗示される制約により、通常は最大約$10^5$要素。これにより、二次ペアごとの反復が除外されます。 おおよそを超えたもの$10^8$厳密な時間制限の下では、Python での操作は安全でなくなります。 これにより、ペアごとの相互作用を線形または線形に近いものに減らす定式化が可能になります。 

すべての値が同一の場合、微妙なエッジケースが発生します。 単純な実装では、ペアごとの寄与を正しく計算できる可能性がありますが、式を単純化するときに誤って計算しすぎたり、対称性を誤って処理したりする可能性があります。 絶対値を削除する代数的並べ替えでは符号の処理を正確に保持する必要があるため、値が大きいか負の場合には、別のエッジ ケースが発生します。 3 番目の問題は、ペアの寄与がインデックス間でどのように分散されるかを考慮せずに配列を誤って並べ替えたり変換しようとした場合に発生します。 

## アプローチ

 まず強引な解釈から始めます。 この式は基本的に、絶対差を含む要素の順序付きまたは順序なしのすべてのペアの合計です。 最も直接的なアプローチは、すべてのペアを反復処理することです。$(i, j)$、そのペアの寄与を計算し、結果を累積します。 これは定義を正確に反映しているため、概念的には単純で正しいものです。 問題はそれが実行されることです$N^2$配列ごとの操作。次の場合には実行できなくなります。$N$大きいです。 のために$N = 10^5$、これには約が必要になります$10^{10}$これは許容範囲をはるかに超えています。 

最初の簡略化は、1 次元の設定で絶対値を削除することから生じます。 シーケンスがソートされると、$p_i - p_j$インデックスの順序に応じて決定的になります。 これにより、プレフィックスの寄与に関してペアごとの合計を書き直すことができます。 各要素は、その後のすべての要素にプラスに寄与し、その前のすべての要素にマイナスに寄与し、位置によって重み付けされた線形結合を生成します。 これにより、double sum が単一パス式に折りたたまれます。$p_i$インデックスのみに応じて係数が乗算されます。 

2 番目の重要な観察は、問題は実際には 1 次元ではないということです。 式は座標のペアまで拡張されます$(p_i, q_i)$であり、注目量は絶対座標差の最大値になります。 これはまさにチェビシェフ距離であり、座標系を 45 度回転するとマンハッタン距離に分解できます。 

変換された座標を導入することで$a_i = p_i + q_i$そして$b_i = p_i - q_i$、チェビシェフ距離は 2 つの独立した 1 次元絶対差分問題に分割されます。 これらのそれぞれは、以前に導出された同じ線形削減手法を使用して評価できます。 これにより、問題全体が、同じ関数を 2 回計算し、結果を代数的に結合することに帰着します。 

最後に、注意深く代数を行うと、元の座標の寄与から変換後の寄与の半分を引いたものの線形結合として元の式を再構成できることがわかります。

 ## アルゴリズムのチュートリアル

 このアルゴリズムは、すべてのペアごとの絶対差を 1 つの加重合計に換算することを中心に展開します。 

1. 配列を読み取る$p$そして$q$、それぞれの長さ$N$。 これらは点の座標を表し、各インデックスは 2D 空間内の 1 つの点に対応します。 
2. 2 つの補助配列を構築する$a_i = p_i + q_i$そして$b_i = p_i - q_i$。 この変換は、チェビシェフ距離を 1 次元の絶対差分に分離できるように座標系を回転します。 
3. 各シーケンスについて$p$、$q$、$a$、 そして$b$、並べ替えられた要素の重み付き線形結合として定義された関数値を計算します。 これは、配列をソートし、ペアワイズ展開から導出されたインデックスベースの係数式を使用して寄与を累積することによって行われます。 
4. ID を使用して結果を結合します。$\text{answer} = value(p) + value(q) - \frac{value(a) + value(b)}{2}$。 

これは、最大絶対差構造を回転された座標寄与に書き換え、二重カウントを修正することから来ています。 
5. 最終結果を出力します。 

重要な計算ステップは、各配列をソートし、同じ線形スキャンを適用してその寄与を効率的に計算することです。 

### なぜ効果があるのか

 正しさは 2 つの構造的事実に依存します。 まず、1 次元の差の絶対値の合計は、ソートされた要素の一次関数として正確に書き直すことができます。これは、各要素の寄与は、それより小さい要素の数または大きい要素の数にのみ依存するためです。 これにより、二次相互作用が決定論的な係数の合計に変わります。 

第 2 に、点間のチェビシェフ距離は 2 つの独立した回転軸の最大値に等しく、変換を適用した後はマンハッタン距離として表現できます。$(p+q, p-q)$。 マンハッタン距離自体は各座標軸上の絶対差に分解されるため、2D 問題全体は 4 つの独立した 1 次元問題の組み合わせになります。 最終的な式は、これらの分解された寄与を代数的に再結合したものにすぎません。 

各変換ではペアごとの距離が必要な形式で正確に保存されるため、近似は導入されず、すべてのペアが両方の表現で同様に寄与します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def value(arr):
    arr.sort()
    n = len(arr)
    res = 0
    for i, x in enumerate(arr, 1):
        res += (2 * i - n - 1) * x
    return res

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    q = list(map(int, input().split()))

    a = [p[i] + q[i] for i in range(n)]
    b = [p[i] - q[i] for i in range(n)]

    vp = value(p[:])
    vq = value(q[:])
    va = value(a)
    vb = value(b)

    ans = vp + vq - (va + vb) // 2
    print(ans)

if __name__ == "__main__":
    solve()
```コア ヘルパー関数は、並べ替え後のシーケンスの線形化された寄与を計算します。 係数$(2i - n - 1)$ソートされた配列内の現在位置の両側にある要素の数を取得します。これはまさに、ペアごとの絶対差分展開を置き換えるものです。 

main 関数は、回転された座標配列を構築し、4 つのシーケンスすべてに対して同じ関数を評価します。 微妙な点の 1 つは、ペアごとの展開の対称性により、結合された変換された寄与の合計は常に偶数になるため、整数の 2 による除算は安全であるということです。

def run(inp: str) -> str:

        arr.sort()
        n = len(arr)

            res += (2 * i - n - 1) * x

        vq = value(q[:])

        vb = value(b)

    solve()
    return sys.stdout.getvalue().strip()

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての値が$p$または$q$は同一です。 その状況では、すべてのペアごとの差はゼロとなり、アルゴリズムはすべての変換後にもゼロを生成する必要があります。 ソートされた配列は一定のままであるため、各要素は完全にキャンセルされる係数を受け取ります。 変換された配列$a$そして$b$も一定になり、同じキャンセルが維持されます。 

別の特殊なケースには、負の数が含まれます。$p - q$、配列に値を設定します$b$。 このアルゴリズムはソート後の順序付けのみに依存するため、符号は重要ではありません。 値が大きく負の場合でも、並べ替えによって値は正しく配置され、係数式は引き続き左右の寄与を正確にカウントします。 

3 番目のケースは次の場合です。$p$そして$q$大きいですが、次のような構造になっています。$p+q$そして$p-q$単純な 32 ビット演算のオーバーフロー。 Python 整数を使用するとこの問題は回避されますが、型付き言語では、変換全体で正確さを維持するために 64 ビット以上の精度が必要になります。
