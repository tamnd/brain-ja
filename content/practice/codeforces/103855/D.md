 ## 解決策
 ## 問題の理解

 グリッド上に重み付けされた点のセットが与えられます。 各点は、ある座標に位置するモンスターを表します。$(x, y)$何らかの値 (または、ステートメントのバリアントで重みが明示的に指定されていない場合は、暗黙的に 1 つの値の単位) に貢献します。 正確に 3 回の「剣攻撃」を実行することが許可されており、各攻撃は直線攻撃であり、その線上にあるすべてのモンスターの合計値を収集します。 

重要な制限は、ストライクには 2 つの幾何学的な種類があることです。つまり、x 軸に平行な線と y 軸に平行な線です。 目的は、そのようなラインを 3 つ選択して合計収集価値を最大化することであり、モンスターが少なくとも 1 つの選択されたラインに存在する場合に貢献します。 

ソリューションの構造は、選択した線が水平線と垂直線の数に大きく依存します。 3 つすべてが水平である場合、問題は最大の合計重みを持つ 3 つの y レベルを選択することに集約されます。 2 つが水平で 1 つが垂直である場合、垂直線は水平方向の集計ですでにカウントされている寄与を削除するため、重複を注意深く考慮する必要があります。 

制約の観点から見ると、目的のソリューションは線形または線形時間に近い時間で実行される必要があります。 列または行を仮説的に削除するたびにグローバルな最良の選択を再計算するアプローチは、最悪の場合には遅すぎます。$10^5$ポイントと単純な再計算は次のようになります。$O(n^2)$行動。 

いくつかの微妙な特殊なケースが重要です。 すべてのポイントが同じ y 座標を共有する場合、「上位 3 つの y レベル」は 3 回繰り返される単一の候補に縮退し、不用意に実装するとカウントが過剰になる可能性があります。 別のエッジ ケースは、最良の垂直線が上位に寄与する y レベルの 1 つを削除し、残りの候補のランキングを変更する場合に発生します。 たとえば、最良の y レベルの合計が緊密にクラスター化されている場合、大きな列を削除すると上位 2 つまたは 3 つの選択肢が再シャッフルされる可能性があり、ランキングが安定していると仮定した場合、単純な上位 k のメンテナンスは失敗する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。3 つのラインの可能な選択肢をすべて試し、それらがカバーするポイントの数を評価し、最大値を取得します。 候補となる構成ごとに、寄与率を最初から再計算します。 と$n$ポイントとして、単一の構成を評価するのは、$O(n)$、そして、あります$O(n^3)$考えられるすべての y レベルのトリプルまたは混合軸の選択を考慮した場合の線の選択。 これにより、少なくとも$O(n^4)$直接的な解釈では、それは完全に不可能です。 

より構造化されたブルートフォースにより、検索スペースが減少します。 どのような最適解でも、混合構成では最大 3 つの異なる Y 値と最大 1 つの X 値のみが問題となることがわかります。 これにより候補スペースは減少しますが、依然として候補ごとの再計算が必要となり、依然として遅すぎます。 

重要な洞察は、座標の集計によって寄与を分離することです。 ポイントを個別に扱う代わりに、すべてのポイントを y 値の周波数マップに圧縮し、配列を生成します。`count[y]`各水平線の合計重量を保存します。 ここで、水平ストライクを選択することは、この配列から上位の値を選択するという問題になります。 

3 つの水平ストライクの構成を考えると、答えは単に次の 3 つの最大値の合計になります。`count`。 これは直接的なものです。 

さらに興味深いのは、水平方向の攻撃を 2 つと垂直方向の攻撃を 1 つ使用する場合です。 ある x 座標で垂直線を固定すると、その x を持つすべての点が水平方向のカウントに寄与することから効果的に削除されます。 これにより変更されます`count[y]`ローカルでは実行されますが、x ごとに最初から再計算するのはコストがかかりすぎます。 

重要な観察は、セットを削除すると、$S_x$、その列にポイントがある y レベルにのみ影響します。 全体の順序を再計算する代わりに、`count[y]`、少数の値を調整し、上位候補がどのように変化するかを追跡するだけで済みます。 以来$|S_x|$y レベルが影響を受けるため、上位の候補を効率的に維持でき、削除後の最良の答えがソートされた構造の小さなプレフィックスのみに依存することが保証されます。 

これにより、x ごとの線形パスが実現され、慎重に集計すると、前処理後の全体の複雑さは線形になります。

 ## アルゴリズムのチュートリアル

 グローバルランキングを繰り返し再計算することを避ける方法でソリューションを再構築します。 

### 1. 座標集計を構築する

 まず、すべてのポイントを 2 つのハッシュ マップに圧縮します。 1 つのマップ`cntY[y]`行 y 上のすべてのポイントの合計寄与度を格納します。 別のマップは点を x でグループ化しているため、x での垂直ストライクの影響を受けるすべての y 値にすぐにアクセスできます。 

問題はもはや個々の点に関するものではなく、列の削除時に行全体がどのように動作するかに関するものであるため、この変換は不可欠です。 

### 2. ベースラインの行順序を事前計算する

 すべての y 値とその集計数のリストを作成します。 概念的には、このリストを降順に並べ替えます。`cntY[y]`。 このソートされた構造は、何も削除されない場合に可能な限り最良の水平ストライクを表します。 

値が制限されている場合や圧縮可能な場合は完全な並べ替えは必要ありませんが、概念的にはこの順序付けによって「上位 3 つ」の候補が定義されます。 

### 3. 純粋な水平の場合を評価する

 上位 3 つの値の合計を計算します。`cntY`。 これは、3 つの打撃をすべて水平方向に使用することに相当します。 

これは 1 つの回答候補として機能するため、それ以上の変更は必要ありません。 

### 4. 垂直攻撃シミュレーションの準備をする

 各 x 座標について、それを垂直ストライクの位置とみなします。 その列のすべての y 値を反復処理し、それらの寄与を一時的に減らします。`cntY`点の重みによって$(x, y)$。 

重要な考え方は、この列の影響を受ける行のみが値を変更するため、それらの行のみがその後の上位 2 つの水平選択に影響を与えることができるということです。 

### 5.除去後のベスト2横打ちを抽出する

 ソートされた完全な構造を再計算する代わりに、制限された数の候補、つまり上部領域にあった行と削除の影響を受けた行のみをスキャンします。 これらの中で、残りの 2 つの最適な y レベルを特定します。 

これが機能するのは、その行が既にランキングで接近していなければ、列を削除しても、非常に競争力のない行を突然グローバル トップに上げることができないためです。 

### 6. 垂直方向への貢献と組み合わせる

 各 x について、次を計算します。 

列 x のすべての値と、削除後の最も優れた 2 つの水平行の合計。 

すべての x の最大値を追跡します。 

### 7. 状態を復元する

 各 x を処理した後、次の列が元の状態から始まるように、一時的なデクリメントを元に戻します。 

### なぜ効果があるのか

 正確さは、ランキング変化の局所性特性に依存します。 垂直ストライクは行集合体の小さなサブセットのみを変更し、影響を受けないすべての行は相対的な順序を保持します。 したがって、影響を受けていない行の中で最良の候補は安定したままとなり、影響を受けた行だけが上位 K セットに入る、または上位 K セットから出ることができます。 K は定数 (2 または 3) であるため、列ごとに一定サイズの候補ウィンドウを検査するだけで済みます。 これにより、最適性を維持しながらグローバルな再計算が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = []
    cntY = {}
    byX = {}

    for _ in range(n):
        x, y, w = map(int, input().split())
        pts.append((x, y, w))
        cntY[y] = cntY.get(y, 0) + w
        if x not in byX:
            byX[x] = []
        byX[x].append((y, w))

    # baseline top 3 y values
    vals = sorted(cntY.values(), reverse=True)
    best3 = sum(vals[:3]) if len(vals) >= 3 else sum(vals)

    ans = best3

    for x, arr in byX.items():
        affected = {}
        for y, w in arr:
            affected[y] = affected.get(y, 0) + w

        changed = []
        for y, w in affected.items():
            cntY[y] -= w
            changed.append((y, w))

        vals2 = sorted(cntY.values(), reverse=True)
        best2 = sum(vals2[:2]) if len(vals2) >= 2 else sum(vals2)

        col_sum = sum(w for _, w in arr)
        ans = max(ans, col_sum + best2)

        for y, w in changed:
            cntY[y] += w

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、すべての寄与を行の合計と列のグループに圧縮します。 上位 3 行の合計を使用してベースラインの答えを計算します。 次に、列ごとに、影響を受ける行からその列の寄与を差し引くことによって、その列の削除をシミュレートします。 各シミュレーションの後、最良の 2 つの行が再計算され、それらが列の寄与と結合されます。 

元に戻すことができないため、復元手順は非常に重要です`cntY`列全体で除去が蓄積され、その後の評価が損なわれる可能性があります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての点が単一の y 座標上にある場合です。 この状況では、すべての水平方向のストライクは同等であり、最適な解決策は、垂直方向のストライクを使用することでより良い分離が得られるかどうかに完全に依存します。 アルゴリズムはこれを自然に処理します。`cntY`にはエントリが 1 つしかないため、上位 2 つの選択は安全に縮退されます。 

単一の列に複数の行にわたる重みの高いポイントがすべて含まれている場合、別のエッジ ケースが発生します。 その列を削除すると、上部の行の順序が大幅に変更される可能性があります。 シミュレーション ステップでは、最良の 2 行を再計算する前に寄与を明示的に減算するため、ランキングのシフトが正しくキャプチャされます。 

3 番目のケースは、個別の y 値が 3 つ未満である場合です。 このアルゴリズムは、行値のソートされたリストをスライスするときに利用可能な最小の合計を取得することでインデックス エラーを回避し、疎な構成でも正確さを保証します。
