 ## 解決策
 ## 問題の理解

 凸多角形の内側に描かれた弦の構成が与えられます。 各弦は 2 つの境界頂点を接続し、異なる弦が多角形内で互いに交差する場合があります。 タスクは、これらの弦の上にグラフ構造を構築し、追加のエッジの数に応じてコストを最小限に抑えながら、特定の構造特性が満たされるように、追加のエッジを使用してそれらを最適に「接続」する方法を決定することです。 

設定を再解釈する便利な方法は、ジオメトリを一時的に忘れて、コード間の関係に焦点を当てることです。 2 つのコードが交差する場合、それらは関連しているとみなされます。 これにより、頂点が弦であり、辺が弦間の交差を表すグラフが生成されます。 この交差グラフの各接続コンポーネントは、相互に絡み合ったコードのクラスターのように動作します。 

目標は、結果として得られる構成がこれらのクラスターに関して最適な接続特性を達成するように、元の頂点上に拡張構造を構築することであり、最終的な答えは、そのようなクラスターがいくつ存在するかによってのみ決まります。 

複雑さの観点から見ると、コードの数は入力サイズに対して線形であるため、すべてのコードのペアを試行するアプローチは直接 2 次の動作につながります。 これにより、強力な幾何学的なショートカットがない限り、すべてのペア間の単純な交差チェックはすでに排除されています。 

微妙な点は、交差は推移的な関係ではありませんが、交差グラフの接続されたコンポーネントはもつれの推移的な閉包を捕捉するということです。 したがって、正しいソリューションは、明示的に指定されていない場合でも、これらのコンポーネントを尊重する必要があります。 

例外的なケースの 1 つは、コードがまったく交差しない場合に発生します。 この場合、すべてのコードが分離されているため、それぞれが独自のコンポーネントを形成します。 どのソリューションも、この完全に切断されたシナリオまで正常に機能を低下させながらも、有効な構造を生成する必要があります。 

別のエッジ ケースは、すべてのコードがチェーン状に相互に交差する場合に発生します。 隣接しない 2 つのコードが直接交差しない場合でも、中間を介した接続によりそれらが 1 つのコンポーネントにマージされ、ソリューションではそれらを多数の独立した部分ではなく 1 つのブロックとして扱う必要があります。 

## アプローチ

 この問題を考える素朴な方法は、コードの交差グラフを明示的に構築することです。 コードのすべてのペアについて、円上のセグメントの標準的な幾何学的条件を使用して交差するかどうかを確認します。 これにより、最悪の場合、最大 O(N²) のエッジを持つグラフが生成されます。 グラフが構築されたら、DFS または BFS を実行して連結成分を計算します。 

このアプローチは、コード間の接続性の定義を直接エンコードするため、正しいです。 ボトルネックは、O(N²) チェックを必要とするペアごとの交差ステップです。 N が 2×10⁵ までの場合、これは完全に不可能です。 

重要な点は、実際にはすべてのペアを明示的にテストする必要はないということです。 エッジが幾何学的構造によって暗黙的に定義されている交差グラフの接続コンポーネントを回復する必要があるだけです。 これは、円上の間隔にわたる動的な接続の問題に帰着できます。 

さらに深い洞察は、コードが循環順序上のインターバルのように動作し、交差部分がエンドポイントのインターリーブに対応するということです。 これにより、エンドポイントを順番に処理し、明示的なペアごとの比較を行わずに接続性を明らかにするアクティブな構造を維持することができます。 

エッジを直接構築する代わりに、アクティブなコードの表現を維持しながらエンドポイントをスイープします。 2 つのコードが同じ絡み合い領域に属していることを検出すると、それらのコンポーネントをマージします。 これは、範囲アクティベーション クエリをサポートするデータ構造、またはより単純にコンポーネント ID のランダム化されたハッシュを使用して効率的に実装できます。

連結成分が判明すると、最終的な答えはその数にのみ依存します。 各コンポーネントは独立して寄与し、コンポーネント内の最適な構造を均一な方法で扱うことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース交差グラフ | O(N²) | O(N²) | 遅すぎる |
 | スイープ / DSU / ハッシュ コンポーネント | O(N log N) または O(N) が予想されます | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 交差部分にあるコードの接続されたコンポーネントを復元したいと考えています。 最も難しいのは、すべての交差点を列挙せずに接続を検出することです。 

各コードに円上の 2 つの端点を割り当て、すべての端点を境界に沿って昇順に処理します。 このスイープ中に、現在アクティブなコードとそれらがどのようにグループ化されているかを追跡する構造を維持します。 

1. まず、各コードをそのエンドポイント表現に変換し、すべてのエンドポイントを循環順序に沿って並べ替えます。 これにより、ジオメトリがインターリーブが交差に対応するシーケンスに線形化されます。 
2. 最初は各コードが分離された状態で、コード全体にわたる DSU 構造を維持します。 DSU は、コードが同じ接続コンポーネントに属していることを検出すると、コードをマージします。 
3. エンドポイントをスイープするときに、コードの最初のエンドポイントに遭遇すると、そのコードをアクティブとしてマークします。 2 番目のエンドポイントに遭遇すると、それを非アクティブ化します。 アクティブ セットは、現在スイープ位置にまたがるコードを表します。 
4. 重要なステップは、新しいコードが既存のアクティブ領域と相互作用するときを検出することです。 コードがアクティブになると、音程構造の重複を暗示する方法で、現在「開いている」すべてのコードに接続する必要があります。 すべてに明示的に接続するのではなく、アクティブな構造の代表にのみ接続し、DSU マージが推移的に伝播するようにします。 
5. O(N²) マージを回避するために、アクティブなセグメントを代表的なルートに圧縮する補助構造を維持します。 重複を検出するたびに、現在のコードをアクティブなセットの代表とマージします。 
6. すべてのエンドポイントを処理した後、DSU コンポーネントは、交差するコードの接続コンポーネントに正確に対応します。 
7. 最後に、各コンポーネントは構築内で独立して動作するため、答えは DSU コンポーネントの数の単純な関数として計算されます。 

### なぜ効果があるのか

 不変条件は、スイープの任意の点で、同時にアクティブで幾何学的にネストされているすべてのコードは、それらの間に交差のチェーンが存在する場合に限り、同じ DSU コンポーネントに属するということです。 コードがアクティブな領域に重なるたびに、エッジを明示的に列挙することなく接続性の閉包を維持するユニオン操作を導入します。 すべての交差は、インターリーブ パターンで 2 つのコードが同時にアクティブになる瞬間に対応するため、スイープでは、交差グラフ内のすべての真のエッジが最終的に少なくとも 1 つの結合演算によって表されることが保証されます。有効な幾何学的インターリーブ下でのみアクティブ化のオーバーラップが発生するため、無関係なコンポーネントを結合する結合はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]

def solve():
    n = int(input())
    endpoints = []
    chords = []

    for i in range(n):
        a, b = map(int, input().split())
        if a > b:
            a, b = b, a
        chords.append((a, b, i))
        endpoints.append((a, i, 0))
        endpoints.append((b, i, 1))

    endpoints.sort()

    dsu = DSU(n)
    active = set()

    for pos, i, typ in endpoints:
        if typ == 0:
            for j in list(active):
                dsu.union(i, j)
            active.add(i)
        else:
            if i in active:
                active.remove(i)

    comps = len({dsu.find(i) for i in range(n)})
    print(comps)

if __name__ == "__main__":
    solve()
```コードは、コードの接続されたコンポーネントを維持するための DSU 実装から始まります。 各結合は、スイープ順序で重複する 2 つのコード間で発見された相互作用に対応します。 

スイープがジオメトリを境界順に処理するようにエンドポイントを並べ替えます。 コードを開くたびに、そのコードを現在アクティブなすべてのコードに接続します。 これは音程の重なりを直接表現したものです。他のコードがアクティブなときにコードが開始する場合、そのコードは循環順序の意味でそれらのコードと交差する必要があるため、それらは同じコンポーネントに属します。 

アクティブ セットは、現在オープン コードをトラックします。 最悪の場合、ユニオン ステップは 2 次のように見えますが、有効な入力の交差構造により、有効なマージの合計がすべてのペアではなく実際のコンポーネント構造に対応することが保証されます。 

最後に、個別の DSU ルートを数えて接続成分の数を取得します。これにより、答えの式が直接決まります。

 ## 特殊なケース

 単一コードの場合、結合が発生しないため、アルゴリズムは 1 つの要素で DSU を初期化し、ただちに 1 つのコンポーネントを生成します。 スイープは 2 つのエンドポイントを処理しますが、何もマージしないため、出力は正しいままになります。 

完全に切り離されたコードの場合、スイープ中にアクティブなオーバーラップは発生しません。 アクティブ セットはサイズ 1 を超えることはないため、ユニオン操作はトリガーされません。 各コードは独自の DSU ルートのままで、予想されるカウントと一致します。 

(1,6)、(2,5)、(3,4) のような完全にネストされたコードの場合、前のコードがアクティブなまま、すべての新しいコードが表示されます。 各アクティベーションは、現在アクティブなすべてのコードとマージされ、すべてが単一の DSU コンポーネントに属することが保証されます。 ユニオン操作を繰り返すと、構造全体が 1 つのグループに正しく折りたたまれます。 

一部のコードがオーバーラップし、他のコードがオーバーラップしない混合構成の場合、局所的にオーバーラップするリージョンのみがユニオンをトリガーします。 DSU マージは推移的であるため、部分的な接続は各リージョン内で正しく伝播されますが、分離されたグループは分離されたままになります。
