 ## 解決策
 ## 問題の理解

 私たちは、複数の領域にわたる色の固定ターゲット構成を持つシステムと、それらの色を変更できるツールのセットを使用して作業しています。 各領域はいくつかの可能な色のうち 1 つを取ることができ、各ツールは構造化された方法で色を変更します。 システムの状態は、すべての領域の現在の色と各ツールのオンまたはオフのステータスという 2 つのことで定義されます。 

目標は、各領域が最終的に特定の目的の色になる必要がある、初期構成をターゲット構成に変換するために必要なツール操作の最小数を見つけることです。 操作はツールの切り替えまたは適用に対応し、各操作は状態を決定的に変更します。 

単純な解釈では、これを非常に大きな暗黙的なグラフ上の最短経路問題として扱います。各ノードは色とツールの状態の完全な割り当てであり、エッジは有効な操作に対応します。 課題は、すべての領域が独立して K 色のいずれかを取り、すべてのツールがアクティブまたは非アクティブになるため、生の状態空間が非常に急速に増大することです。 

入力は、領域の数、ツールの数、初期の色、ターゲットの色、および各ツールが領域に与える影響を記述します。 出力は、ターゲット構成に到達するために必要な操作の最小数、またはその状態グラフの到達可能性の同等の尺度です。 

重要な問題は、K が十分に大きいため、すべての色を個別の値として扱うと状態空間が扱いにくくなる可能性があることです。 フルカラー割り当てに対する直接 BFS は直ちに不可能になります。 

複数の色がターゲットと一致するかどうかを除いて無関係である場合、微妙なエッジケースが発生します。 たとえば、領域のターゲット カラーが 3 である場合、正確性の観点からは、カラー 1 または 2 であることは同等です。 単純な BFS は依然としてそれらを区別し、膨大な量の状態空間を無駄にする可能性があります。 もう 1 つのエッジ ケースは、複数のツール操作が互いにキャンセルされるときに発生し、状態が正規化されていない場合に、同じ効果的な構成を簡単に再検討できるようになります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 状態を、ツールのアクティブ化のビットマスクとともに領域の色の完全なベクトルとして表します。 各状態からすべてのツール操作を適用して、新しい状態に遷移します。 初期状態から目標状態に到達するまで BFS を実行します。 

これは概念的に機能します。すべての操作には単位コストがあるため、BFS は最短シーケンスを保証します。 問題は州の数です。 N 個の領域があり、それぞれに K 個の可能な色と M 個のツールがある場合、状態の数は K^N * 2^M のオーダーになります。 これを保存することさえ不可能であり、BFS 遷移では状態ごとにこの爆発が M 倍になり、最悪の場合の複雑さは O(K^N * 2^M * M) になります。 

重要な観察は、実際にはターゲット以外の異なる色を区別する必要がないということです。 各領域について重要なのは 2 つの条件だけです。ターゲットの色と一致するかどうかです。 今後の操作では特定の間違った色を保持するのではなく、不一致の修正のみを考慮するため、不一致はすべて同等です。 

これにより、各領域がバイナリ状態に還元されます。 K^N 個の可能性の代わりに、2^N 個の可能性ができるようになりました。 ツールの状態と組み合わせると、完全な状態空間は 2^(N+M) になります。 これはすでに劇的な削減です。 

次の改善は、ツールエフェクトの適用方法です。 フルカラー変換を再計算する代わりに、ツールの適用がビットのサブセットの反転または更新に対応するようにビット単位の表現を使用します。 この表現を使用すると、すべての領域をスキャンするのではなく、実装の詳細に応じて遷移を O(1) または O(K + M) で計算できます。 

これにより、BFS がコンパクトなビットマスク状態空間にわたるグラフ走査に変わり、実行可能になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(K^N・2^M・M) | O(K^N・2^M) | 遅すぎる |
 | ビットマスク BFS 最適化 | O(2^(N+M) · (K + M)) | O(2^(N+M)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各領域を、ターゲットの色と一致するかどうかを表すバイナリ条件に変換します。 これにより、色の次元が縮小されて不一致マスクになります。 これが有効である理由は、中間の誤った色の識別ではなく、ターゲットに対する相対的な正しさのみが重要であるためです。 
2. 構成全体を領域のビットマスクとツール状態のビットマスクとしてエンコードします。 これにより、完全なシステム状態を表す単一のコンパクトな整数表現が作成され、定数時間のハッシュと比較が可能になります。 
3. 領域の不一致状態に対する各ツールの効果をビットマスク変換として事前計算します。 これにより、BFS 移行中の領域ごとのカラー更新の再計算が回避されます。 
4. BFS キューを初期状態と距離 0 で初期化し、訪問済みとしてマークします。 BFS が使用されるのは、すべての操作のコストが等しいため、最初の訪問で最適性が保証されるためです。 
5. キューから状態を取り出し、可能なすべてのツール操作を試みます。 各操作では、領域マスクにビット単位の変換を適用し、該当する場合はツールの状態を切り替えることによって、新しい状態が生成されます。 
6. 生成されたステートがこれまでに見たことがない場合は、そのステートを訪問済みとしてマークし、距離を 1 つ増分してキューにプッシュします。 これにより、各状態が最大 1 回処理されることが保証されます。 
7. ターゲットのビットマスク構成に到達したら停止し、その距離を返します。 

### なぜ効果があるのか

 正確性は、システムの到達可能なすべての構成が 1 つの正規ビットマスク状態に正確に対応し、すべての操作がこれらの正規状態間を曖昧さなく遷移するという不変条件に基づいています。 BFS は操作の数を増やしながら状態を探索するため、初めてターゲット構成に到達するときは、最小限のステップ数を使用する必要があります。 K 色からバイナリ一致ステータスへの削減では、間違った色間の中間区別が将来の有効性や遷移に影響を与えないため、ターゲットに到達することに関連する情報が失われません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, k = map(int, input().split())
    
    init = list(map(int, input().split()))
    target = list(map(int, input().split()))
    
    # mismatch bitmask for regions
    def build_mask(arr):
        mask = 0
        for i, v in enumerate(arr):
            if v != target[i]:
                mask |= (1 << i)
        return mask
    
    start_mask = build_mask(init)
    
    # tool effects: each tool flips certain region bits
    tool_effect = []
    for _ in range(m):
        data = list(map(int, input().split()))
        cnt = data[0]
        effect = 0
        for i in range(1, cnt + 1):
            effect |= (1 << (data[i] - 1))
        tool_effect.append(effect)
    
    # BFS over (region_mask, tool_mask)
    start_state = (start_mask, 0)
    target_state = (0, 0)
    
    q = deque([start_state])
    dist = {start_state: 0}
    
    while q:
        mask, tmask = q.popleft()
        d = dist[(mask, tmask)]
        
        if mask == 0:
            print(d)
            return
        
        for i in range(m):
            new_mask = mask ^ tool_effect[i]
            new_tmask = tmask ^ (1 << i)
            state = (new_mask, new_tmask)
            
            if state not in dist:
                dist[state] = d + 1
                q.append(state)

    print(-1)

if __name__ == "__main__":
    solve()
```コードは、各領域をターゲットに対して不一致のビットマスクに変換することから始まります。 これが中心的な単純化です。正確な色を追跡する代わりに、領域ごとの正確性のみを追跡します。 

各ツールは、影響を受ける領域のビットマスクとしてエンコードされます。 ツールを適用することは、このマスクと現在の不一致状態との XOR 演算に相当します。これは、ツールを切り替えると、影響を受ける領域がターゲットに対して正しい領域と正しくない領域との間で反転するためです。 

BFS 状態には、不一致マスクとツール起動マスクの両方が含まれます。 キューは距離が増加する順に状態を展開し、辞書によって状態を再訪問することがないことが保証されます。 

終了条件は、すべての領域が正しいかどうかをチェックします。これは、ゼロ不一致マスクに対応します。 その時点で、BFS は最小限の操作を保証します。 

実装の微妙な詳細は、すべてを 1 つの整数に詰め込むのではなく、状態をタプルとして表現することです。 これにより、正当性の推論が簡素化され、わずかに高いオーバーヘッドを犠牲にしてビット パッキングの間違いが回避されますが、このモデルの一般的な制約では許容範囲内です。 

## 実用的な例

 ### 例 1

 3 つの領域と 2 つのツールがあるとします。 

初期色：[1、2、3]

 対象色：[1、1、3]

 ツール 1 は領域 2 を反転します

 ツール 2 は領域 1 と 3 を反転します

 ミスマッチマスクを作成します。 

| ステップ | マスク | ツールマスク | アクション |
 | --- | --- | --- | --- |
 | 開始 | 010 | 00 | リージョン 2 は間違っています |
 | ツール 1 を適用 | 000 | 01 | 領域 2 を修正 |
 | ツール 2 を適用 | 101 | 10 | 領域 1 と 3 を切り替えます |

 BFS はツール 1 を適用した後、最初にマスク 000 に到達するため、答えは 1 になります。 

このトレースは、正しさをビットマスクとして表すことで、目標に向けた進捗状況が正しくキャプチャされることを確認します。 

### 例 2

 イニシャル: [1、1、1]

 ターゲット: [2、2、2]

 ツールはすべての領域を反転します。 

| ステップ | マスク | ツールマスク | アクション |
 | --- | --- | --- | --- |
 | 開始 | 111 | 0 | すべて間違っています |
 | 適用ツール | 000 | 1 | すべて修正されました |
 | ツールを再度適用します | 111 | 0 | 最初に戻る |

 訪問した状態により無限ループが防止されるため、BFS はシステムが循環しても 1 ステップで解を見つけます。 

これは、ツールによって導入されたサイクルによって正確性が損なわれないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(2^(N+M) · (M + N)) | すべてのビットマスク状態にわたる BFS、各遷移スキャン ツール |
 | スペース | O(2^(N+M)) | 訪問した状態とキューを保存する |

 指数関数状態空間は、カラーの 2 進数削減とツール効果のビットマスク エンコードによって制御されます。 これにより、このアプローチは、問題の意図した制約と一致する小さな N と M に対してのみ実行可能になります。

## 特殊なケース

 重要なエッジ ケースの 1 つは、初期構成がすでにターゲットと一致している場合です。 入力には必要な操作がないため、BFS はすぐに終了する必要があります。 この状況では、開始マスクはゼロであるため、キューの状態は次のようになります。`mask == 0`展開の前にトリガーします。 

ツールが以前の状態に戻るサイクルを作成する場合、別のエッジ ケースが発生します。 たとえば、1 つのツールで領域を 2 回反転すると、元の構成に戻ります。 訪問済みセットは、状態が一度処理されると再エンキューされないため、無限ループを防ぎます。 

最後のエッジケースは、複数のツールが同じ領域で重なっている場合です。 たとえツール適用のシーケンスが異なっていても、状態を次のように表す同一のマスクが得られる可能性があります。`(mask, tool_mask)`これらが必要な場合にのみ個別に扱われることを保証し、BFS はアクセスされたディクショナリを通じて同等の構成を折りたたみます。
