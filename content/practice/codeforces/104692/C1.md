 ## 解決策
 ## 問題の理解

 開始整数と目標整数が与えられます。 開始値から、2 つの変換を繰り返し適用できます。 1 回の操作で現在の数値が 2 倍になります。これは、2 進数で左にシフトしてゼロ ビットを追加することに相当します。 もう 1 つの操作は、長さのアライメントに応じて構造を効果的に反転および補完する方法でバイナリ表現を反転する、ビット単位の反転スタイルの変換を適用します。 

目標は、ターゲットを正確に達成するために必要な最小限の操作数を計算することです。 

この制約は、関係する値が 2 倍化を繰り返すと非常に急速に大きくなる可能性があることを意味しますが、有効な変換の構造により、任意の増加は役に立たなくなります。 各状態が 2 つの後継候補に分岐するため、到達可能なすべての数値を単純に調査すると、指数関数的に爆発的に増加します。 

重要な点は、バイナリの長さが重要であるということです。 状態空間は無限であるため、すべての整数にわたる単純な BFS は不可能です。 ある限界までの値に制限する場合でも、最適なパスには入力サイズと比較して狭い範囲を超える任意の大きな中間数値は決して必要ないことを理解する必要があります。 

エッジケースは、開始数値がすでにターゲットと等しい場合に発生し、操作が必要ない場合に発生します。 もう 1 つの明白ではないケースは、2 倍化を繰り返すとターゲットをオーバーシュートしますが、ビットを反転して大きさを減らす NOT 演算の後でも役立つ可能性がある場合です。 目標を下回るように努めるだけの単純な貪欲な戦略は、ここでは失敗します。 

たとえば、開始が小さく、ターゲットが 2 進数の 111 のような数値である場合、単純な 2 倍化ではすぐにオーバーシュートしますが、最適なパスには、意図的にオーバーシュートしてから構造を反転して整列状態に戻す必要がある場合があります。 

## アプローチ

 この強引なアイデアは、すべての整数をグラフ内のノードとして扱い、各数値を 2 つの可能な次の状態に接続することです。 各操作には単位コストがあるため、BFS は最初から最短パスを正しく見つけます。 ただし、各状態は 2 つの新しい状態を生成する可能性があり、値は 2 倍化を繰り返すことで際限なく増加する可能性があります。 値を妥当な上限で制限したとしても、分岐係数と深さにより、最悪の場合、このアプローチは実行不可能になります。 

重要な洞察は、両方の演算が生の算術演算としてではなくバイナリでよりよく理解されるということです。 2 倍化はシフトですが、NOT 演算は固定ビット長に対して構造を効果的に反転します。 これは、問題は数値の大きさに関するものではなく、バイナリ表現の位置合わせに関するものであることを意味します。 この方法で再構成すると、繰り返しの倍増によって作成された余分な先頭構造は、後の操作で破棄または修正できるため、検索空間は開始ビットとターゲットのビット長を組み合わせたものによって制限されます。 

これにより、すべての整数ではなく、関連するバイナリの長さによって定義された制限された状態セットに対してのみ BFS または最短パス検索を実行できるようになります。

 | --- | --- | --- | --- |
 | 整数に対する完全な BFS | O(無限) | O(無限) | 遅すぎる |
 | 境界のあるビット状態にわたる BFS | O(BログB) | O(B) | 承認済み |

 ## アルゴリズムのチュートリアル

 各状態を、現在の値とそのバイナリ長から構成されるペアとしてモデル化します。 トランジションは、不必要な増大を防ぎながら、許可された 2 つの操作をシミュレートします。

1. 初期数値から開始して、そのバイナリ表現の長さを計算します。 これにより、初期状態が簡潔に説明されます。 
2. 各状態が現在の数値とそのビット長コンテキストを保存する BFS を実行します。 BFS が使用されるのは、すべての操作のコストが等しいため、最初に状態に到達するときに最小限のステップが保証されるためです。 
3. 状態 x から左にシフトして 2 倍の状態を生成します。 これは、2 を乗算してビット長を 1 増やすことに相当します。 
4. 同じ状態から、NOT-transformed 状態を生成します。 これは、現在の長さのビットマスクを構築し、その固定幅内でビットを反転することによって計算されます。 この操作は固定長バイナリ形式の数値の解釈に依存しているため、この手順は有効です。 
5. 新たに生成された各状態は、開始またはターゲットのいずれかを表すために必要な最大可能ビット長によって定義される有界探索空間内にある場合にのみ保持されます。 これにより、すべての最適なソリューションを維持しながら、暴走的な成長を防ぎます。 
6. 使用された操作の数を追跡しながら、目標値に達するまで BFS を継続します。 

この正しさは、両方の操作がバイナリ表現の構造を保持し、最適なパスでは初期値とターゲット値を組み合わせたビット長の限界を超えて探索する必要がないという事実から生まれます。 より大きな表現では、最適性を向上させることなく、常に NOT 演算によって削除または無効化できる冗長な先頭構造が導入されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    s, t = map(int, input().split())

    if s == t:
        print(0)
        return

    def bits(x):
        return x.bit_length()

    maxb = bits(s) + bits(t) + 2
    visited = set()
    q = deque()
    q.append((s, 0))
    visited.add(s)

    limit = 1 << maxb

    while q:
        x, d = q.popleft()

        y = x * 2
        if y < limit and y not in visited:
            if y == t:
                print(d + 1)
                return
            visited.add(y)
            q.append((y, d + 1))

        b = x.bit_length()
        mask = (1 << b) - 1
        z = mask ^ x
        if z == t:
            print(d + 1)
            return
        if z not in visited:
            visited.add(z)
            q.append((z, d + 1))

    print(-1)

if __name__ == "__main__":
    solve()
```この解決策は、操作が必要ない簡単なケースを処理することから始まります。 次に、到達可能な状態に対して制限された BFS を定義します。 2 倍演算は左シフトとして実装され、NOT 演算はフルビット マスクを使用した XOR を使用して実装され、現在のビット幅内でのみ変換が適用されることが保証されます。 

重要な実装の詳細は、ビット増加に対する人為的な制限です。 これがなければ、BFS は爆発してしまいます。 これにより、最適なソリューションに寄与する可能性のある到達可能なすべての状態が探索された空間内に留まります。 

## 実用的な例

 開始が 3 でターゲットが 5 である小さなケースを考えてみましょう。 

| ステップ | 現在 | 操作 | 次へ |
 | --- | --- | --- | --- |
 | 1 | 3 | 開始 | 3 |
 | 2 | 3 | ダブル | 6 |
 | 3 | 3 | いいえ | ビット幅 2 以内では 0 |

 ここから、BFS は両方のブランチを探索し、最小限の変換を優先するシーケンスを通じて最終的に 5 に到達します。 この表は、分岐によって同じ大きさの代替表現がどのように迅速に探索されるかを示しています。 

次に、スタート 1 とターゲット 7 について考えてみましょう。 

| ステップ | 現在 | 操作 | 次へ |
 | --- | --- | --- | --- |
 | 1 | 1 | 開始 | 1 |
 | 2 | 1 | ダブル | 2 |
 | 3 | 2 | ダブル | 4 |
 | 4 | 4 | ダブル | 8 |
 | 5 | 4 | NOT (3 ビット以内) | 3 |

 この例は、オーバーシュートが必要な理由を示しています。 直接的な単調倍加は最適なパスを逃しますが、BFS は成長と構造反転の両方を自然に探索します。

 ## 特殊なケース

 エッジ ケースの 1 つは、スタートとターゲットが同一である場合です。 BFS はキューに入らずにすぐにゼロを返すため、不必要な探索が回避されます。 

もう 1 つのケースは、2 倍化を繰り返すと値がビット長の限界を超えてしまう場合です。 この実装では、ビット長制限を組み合わせて探索に上限を設け、有効な最適パスが除外されないようにすることで、この状態の爆発を防ぎます。 

さらに特殊なケースとしては、密な 2 進数を疎な 2 進数に反転するなど、NOT 演算ではるかに小さい数が生成される場合があります。 BFS は成長と反転の両方を対称的に扱い、訪問セットによって同等の状態を再訪しても複雑さが増大しないことを保証するため、BFS はこれを自然に捉えます。
