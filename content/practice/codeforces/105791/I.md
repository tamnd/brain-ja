 ## 解決策
 ## 問題の理解

 2 人のプレイヤーが交互にヤシの木に登ります。 最初の登りでサミュエルは一定の金額を受け取ります$x$そして2番目の登りでレウマスは$y$。 3 回目以降、各プレイヤーは戦略を変更します。新たに登るたびに、プレイヤーは前回の登攀で取得したものと、他のプレイヤーが前回の登攀で取得したものを正確に取得します。 

これにより、2 つの進化する値のシーケンスが定義されます。 1 つのシーケンスは Samuell の収量に対応し、もう 1 つは Lleumas の収量に対応します。 タスクはこれらの値を直接シミュレートすることではありません。$n$非常に大きくなる可能性があり、最大で$10^{18}$。 代わりに、誰が実行するかを決定する必要があります。$n$- 回目の登りとその登りで摘んだココナッツの数、モジュロ$10^9 + 7$。 

交互の構造により、登山者の身元がすぐにわかります。奇数のインデックスは Samuell に対応し、偶数のインデックスは Lleumas に対応します。 本当の難しさは、段階的に反復せずに多くの遷移後の値を計算することにあります。 

単純なシミュレーションでは、次のステップごとに両方のシーケンスが更新されます。$n$。 それは不可能です$n = 10^{18}$、さえ$10^7$厳格な制限の下では、運用はすでに限界に達しているだろう。 繰り返しは閉じた形式に折りたたむ必要があります。 

エッジケースは次の場合に発生します。$n = 1$または、一方または両方の初期値がゼロの場合。 たとえば、次の場合$x = 0$そして$y = 5$、その後、すぐに 2 番目のステップになります。$5$、その後はすべてが決定的に成長します。 すべてに一律の公式を仮定する軽率な試み$n$最初のステップにも誤って累乗を適用してしまいます。 

もう一つの微妙なケースは、$n = 2$ここで、値はまだ初期移行段階にあり、指数関数的な 2 倍化領域にはまだ入っていません。 

## アプローチ

 直接的なアプローチは、プロセスを段階的にシミュレートすることです。 2 つの変数 (Samuell 用と Lleumas 用) を維持し、反復を繰り返し適用します。 新しい値はそれぞれ、両方のプレーヤーの以前の値にのみ依存します。 これは定義に正確に従っているため、正しいです。 

ただし、これには次のことが必要です$O(n)$トランジション。 以来$n$と同じ大きさにすることができます$10^{18}$、単一の直線パスさえ不可能です。 状態空間は複雑にはなりませんが、ステップ数が多いためシミュレーションが不可能になります。 

重要な観察は、2 番目のステップの後、両方のシーケンスが同一になることです。 ステップ 2 で得られるのは、$x + y$両プレイヤーにとっても。 その時点以降、新しい値はそれぞれ前の 2 つの同一の値の単純な合計になります。これは、シーケンスがステップごとに 2 倍になることを意味します。 

これにより、問題は、一定の接頭辞の後の単純な指数関数的な増加に変換されます。 遷移をシミュレートする代わりに、高速累乗を使用して 2 のべき乗を計算します。

 ## アルゴリズムのチュートリアル

 最初の 2 つのステップを個別に処理し、次に指数関数領域を処理します。 

1. もし$n = 1$、答えは直接、価値のあるサムエルです$x$まだ再発はしていないので。 これは純粋に基本定義のケースです。 
2. もし$n = 2$、答えは価値のあるLleumasです$x + y$2 番目のステップは最初の値のペアから直接計算されるためです。 
3. すべての人のために$n \ge 3$、ステップ 2 以降、両方のシーケンスが同一になることがわかります。 統一されたシーケンスを定義します$T$そのような$T_2 = x + y$。 
4. どのステップでも$i \ge 3$、再発は次のようになります。$T_i = T_{i-1} + T_{i-1}$、両方のプレイヤーが以前と同じ値を貢献するようになるためです。 これを単純化すると、$T_i = 2 \cdot T_{i-1}$。 
5. これはつまり、$T_n = (x + y) \cdot 2^{n-2}$みんなのために$n \ge 2$。 
6. 計算します$2^{n-2} \bmod (10^9 + 7)$高速累乗を使用して乗算します。$(x + y) \bmod (10^9 + 7)$。 
7. 最後に、パリティに基づいて出力名を決定します。$n$： 奇数$n$サミュエルにさえ与える$n$リーマスに与える。 

### なぜ効果があるのか

 重要な不変条件は、ステップ 2 以降、両方のシーケンスがすべてのインデックスで等しいということです。 等価性が確立されると、漸化式は単一のスカラー数列に崩壊し、各項は前の項の正確に 2 倍になります。 反復により再び非対称性が導入されることはないため、等価性プロパティは後のすべてのステップで維持され、単一の共有値から基数 2 での指数関数的な増加が強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def mod_pow(a, e):
    res = 1
    while e > 0:
        if e & 1:
            res = (res * a) % MOD
        a = (a * a) % MOD
        e >>= 1
    return res

n = int(input().strip())
x, y = map(int, input().split())

if n == 1:
    print("Samuell")
    print(x % MOD)
elif n == 2:
    print("Lleumas")
    print((x + y) % MOD)
else:
    total = (x + y) % MOD
    val = total * mod_pow(2, n - 2) % MOD

    if n % 2 == 1:
        print("Samuell")
    else:
        print("Lleumas")
    print(val)
```実装では特殊なケースが分離されます$n = 1$そして$n = 2$なぜなら、指数公式はステップ 2 以降でのみ有効になり始めるからです。 高速べき乗関数を使用して計算します。$2^{n-2}$モジュロ演算で効率的に実行し、非常に大規模なデータの正確性を保証します。$n$。 

最後のパリティ チェックは交互のターン構造を直接エンコードし、ターンのシミュレーションを回避します。

## テストケース```python
import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdin
    input = stdin.readline

    n = int(input().strip())
    x, y = map(int, input().split())

    def mod_pow(a, e):
        res = 1
        while e > 0:
            if e & 1:
                res = (res * a) % MOD
            a = (a * a) % MOD
            e >>= 1
        return res

    if n == 1:
        return "Samuell\n" + str(x % MOD)
    elif n == 2:
        return "Lleumas\n" + str((x + y) % MOD)
    else:
        val = (x + y) % MOD * mod_pow(2, n - 2) % MOD
        name = "Samuell" if n % 2 == 1 else "Lleumas"
        return name + "\n" + str(val)

# provided samples
assert run("2\n5 3\n") == "Lleumas\n8", "sample 1"

# custom cases
assert run("1\n10 20\n") == "Samuell\n10", "n=1 base case"
assert run("2\n0 0\n") == "Lleumas\n0", "zero propagation"
assert run("3\n1 1\n") == "Samuell\n4", "first exponential step"
assert run("10\n2 1\n") == "Lleumas\n1536", "large doubling check"

 ## 特殊なケース

 いつ$n = 1$、漸化式はまったく適用されていないため、次の式が含まれます。$x + y$誤って過大カウントしてしまいます。 アルゴリズムは明示的に繰り返しをバイパスして出力します。$x$。 

いつ$n = 2$、システムは 2 人のプレイヤー間の対話を 1 回だけ確認しました。 これは、値がまだ指数構造に支配されていない唯一のステップです。 アルゴリズムは直接計算します$x + y$、時期尚早の倍増を避けます。 

いつ$x = 0$そして$y = 0$、その後のすべての値は、べき乗に関係なくゼロのままになります。 ゼロによる乗算はモジュラー演算でもゼロを保持するため、アルゴリズムはこれを自然に処理します。 

いつ$n$など非常に大きいです$10^{18}$、パリティ決定と高速累乗は、モジュラー算術演算と指数のビット演算のみに依存し、最大までの反復には依存しないため、安定したままになります。$n$。
