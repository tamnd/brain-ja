 ## 解決策
 ## 問題の理解

 私たちは、1 から n + 1 までの階数が付けられた建物を見ています。ペップは最上階に住んでおり、エレベーターを使って階下に降りたいと考えています。 彼が x 階からエレベーターを呼ぶと、エレベーターは動き始めますが、移動中に近所の人がランダムに呼び出すため、途中の階で停止することがあります。 

1 から n までの各階 i は独立して動作します。エレベーターが通過している間、階 i は確率 pi で停止をトリガーします。 最終フロア n + 1 はペップの目的地であり、ランダムな停止には影響しません。 

ペップは、エレベーターが出発階と目的地を除く中間階で最大 1 回停止した場合に限り、その日を「良い」と考えます。 停止が 0 回またはちょうど 1 回の場合、彼は授業に行きます。 2 つ以上の異なる中間階で停止した場合、彼はあきらめます。 

初期確率配列 pi が与えられ、2 種類の演算を処理する必要があります。 1 つは 1 つの階の確率を更新し、もう 1 つは「エレベーターが x 階から開始する場合、厳密に x と n + 1 の間にある階の最大 1 つが停止をトリガーする確率はいくらか?」と尋ねます。 

制約 n と q は最大 2・10^5 になるため、クエリごとに O(n) を超える確率を再計算するソリューションは遅すぎます。 すべてのクエリに影響を与える単一の更新のコストはすでに O(nq) であり、制限をはるかに超えています。 これにより、ポイントの更新と高速なプレフィックスまたはサフィックスの集約をサポートする構造が推進されます。 

「最大でも 1 ストップ」について考えると、微妙な問題が生じます。 単純な間違いは、オーバーラップを慎重に処理せずに、ゼロ ストップまたは正確に 1 ストップの確率のみを独立して計算し、それらを合計することです。 もう 1 つの間違いは、開始フロア x が対象セグメントを動的に変更することを認識せずに、独立性により区間にわたる単純な合計が可能であると仮定することです。 

注目に値するエッジ ケースは、確率 0 と確率 99 のフロアです。0 のフロアは寄与することがなく、事実上問題が縮小しますが、99 の場合、「停止なし」が非常にまれになり、モジュラー算術形式で正確に処理されない場合、浮動直感エラーが増幅されます。 

## アプローチ

 ブルート フォース ソリューションは、各クエリを個別に処理します。 x で始まるクエリの場合、i > x のすべてのフロアをスキャンし、これらのベルヌーイ イベントの最大 1 つが成功する確率を計算します。 これには、サイズ 0 または 1 のすべてのサブセットを列挙する必要があり、これは成功数の完全な分布を計算することになります。 各クエリの直接動的計算ではクエリごとに O(n) のコストがかかり、結果として O(nq) になりますが、両方とも 2 · 10^5 までの場合は遅すぎます。 

重要な構造的観察は、配列のサフィックスに対する 2 つのグローバル集計が必要なだけであるということです。 qi = pi/100 とし、si = 1 − qi と定義します。 セグメントの場合、停止をトリガーするフロアがない確率は si の積になります。 正確に 1 つのフロアが停止を引き起こす確率は、j ≠ i の場合、qi の i にわたる合計にすべての sj の積を乗じたものになります。 セグメント内のすべての sj の積を因数分解すると、これは積項と比 qi/si の合計の積になります。 

この因数分解は、組み合わせサブセット確率を 2 つの乗算プレフィックス構造に変換します。 si のプレフィックス積と qi/si のプレフィックス和を維持するだけで済みます。 ポイント更新では、セグメント ツリーを使用して両方を維持できます。 

x で始まるクエリの場合は、サフィックス [x, n] を考慮します。 P をこの範囲の si の積、S を同じ範囲の qi/si の合計とする。 この場合、ゼロストップの確率は P で、ちょうど 1 ストップの確率は P・S です。 答えはP(1+S)です。 

これにより、セグメント ツリーに対する各クエリが O(log n) 個の更新とクエリに削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとに O(n) | お(1) | 遅すぎる |
 | 因数分解を使用したセグメント ツリー | 操作ごとに O(log n) | O(n) | 承認済み |

## アルゴリズムのチュートリアル

 qi = pi * inv(100) を使用して、確率をモジュラー算術に変換します。 すべての計算は 1e9+7 を法として行われます。 

1. 各フロア i について、si = 1 − qi を計算し、比率 ri = qi / si も計算します。 この書き換えにより、独立して集計する 2 つの量が分離されます。 
2. 各ノードが 2 つの値 (セグメント上の si の積とセグメント上の ri の合計) を格納するセグメント ツリーを構築します。 商品は「どこにもストップなし」を捕捉し、合計は「重み付けされた単一ストップの貢献」を捕捉します。 
3. 位置 x での更新クエリの場合、新しい確率から sx と rx を再計算し、インデックス x でセグメント ツリーを更新します。 これにより、両方の集計と現在の配列の一貫性が保たれます。 
4. x に関するタイプ 2 クエリの場合、範囲 [x, n] にわたってセグメント ツリーをクエリして、P と S を取得します。 
5. P * (1 + S) モジュロ MOD を返します。 この式は、ゼロストップ (P) と正確に 1 ストップ (P・S) の確率を単一のコンパクトな式に結合します。 

なぜ効果があるのか:

 核となる不変条件は、すべてのセグメントについて、格納された積がセグメント内に停止をトリガーするフロアがない確率に等しいのに対し、格納された合計は、グローバルな「停止なし」条件を考慮した後でセグメント内の停止フロアを 1 つだけ選択する線形化された寄与に等しいということです。 各フロアは独立して動作するため、ストップが 1 つまでのイベントは、何も選択しないか、インデックスを 1 つだけ選択するかのどちらかに分解され、どちらの場合も共有積項とセグメントローカル合計の積に明確に考慮されます。 この分離は、積と線形和の両方が独立性に必要な方法で正確に結合するため、マージセグメントの下でも保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

class SegTree:
    def __init__(self, arr_s, arr_r):
        self.n = len(arr_s)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.prod = [1] * (2 * self.size)
        self.sums = [0] * (2 * self.size)

        for i in range(self.n):
            self.prod[self.size + i] = arr_s[i]
            self.sums[self.size + i] = arr_r[i]

        for i in range(self.size - 1, 0, -1):
            self.prod[i] = self.prod[2 * i] * self.prod[2 * i + 1] % MOD
            self.sums[i] = (self.sums[2 * i] + self.sums[2 * i + 1]) % MOD

    def update(self, idx, s_val, r_val):
        i = self.size + idx
        self.prod[i] = s_val
        self.sums[i] = r_val
        i //= 2
        while i:
            self.prod[i] = self.prod[2 * i] * self.prod[2 * i + 1] % MOD
            self.sums[i] = (self.sums[2 * i] + self.sums[2 * i + 1]) % MOD
            i //= 2

    def query(self, l, r):
        l += self.size
        r += self.size
        prod_left = 1
        prod_right = 1
        sum_res = 0

        while l <= r:
            if l % 2 == 1:
                prod_left = prod_left * self.prod[l] % MOD
                sum_res = (sum_res + self.sums[l]) % MOD
                l += 1
            if r % 2 == 0:
                prod_right = prod_right * self.prod[r] % MOD
                sum_res = (sum_res + self.sums[r]) % MOD
                r -= 1
            l //= 2
            r //= 2

        prod = prod_left * prod_right % MOD
        return prod, sum_res

def solve():
    n, q = map(int, input().split())
    p = list(map(int, input().split()))

    inv100 = modinv(100)

    s = []
    r = []

    for x in p:
        qv = x * inv100 % MOD
        sv = (1 - qv) % MOD
        rv = qv * modinv(sv) % MOD if sv != 0 else 0
        s.append(sv)
        r.append(rv)

    st = SegTree(s, r)

    out = []
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            x = int(tmp[1]) - 1
            val = int(tmp[2])
            qv = val * inv100 % MOD
            sv = (1 - qv) % MOD
            rv = qv * modinv(sv) % MOD if sv != 0 else 0
            st.update(x, sv, rv)
        else:
            x = int(tmp[1]) - 1
            prod, sm = st.query(x, n - 1)
            ans = prod * (1 + sm) % MOD
            out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、各確率を 2 つの導出値にエンコードし、セグメント ツリーに格納します。 積配列はセグメント全体の「ノーストップ」確率を追跡し、合計配列は正規化された単一ストップの寄与を追跡します。 クエリはセグメントの両方の半分を慎重にマージします。積は互いに素な部分にわたって乗算されますが、合計は直接加算されます。 

微妙な点は、siの逆剰余の扱いです。 pi = 100 の場合、si はゼロになる可能性があるため、コードはこのケースを保護します。 このような状況では、セグメント積はゼロになり、その下限を含む範囲で最終確率がすでにゼロに強制されるため、比率項は無関係になります。

| ステップ | 製品P | 和S |
 | --- | --- | --- |
 | ビルド範囲 [1,3] | 9/10 * 1/2 * 1/2 = 9/40 | 1/9*5? (比率変換後の正規化された合計) |

これは、フロアがトリガーされないか、フロアトリガーが 1 つだけ発生するという考えと一致します。

```重要なのはフロア 2 ～ 5 だけですが、最後の 3 つは確率が 0 であるため、寄与しません。

これらの例は、ゼロ確率の下限がどのように乗法構造から効果的に消える一方で、非ゼロの下限が積和因数分解を通じてどのように組み合わされるかを示しています。

 ## 特殊なケース

 1 つのエッジ ケースは、下限の確率が 100 である場合に発生します。この状況では、si がゼロになり、それを含むセグメント上の積が強制的にゼロになります。 セグメント積はすぐに崩壊し、合計項に関係なく最終的な答えがゼロになるため、アルゴリズムはこれを正しく処理します。 比率という用語は、そのセグメントでは意味のある意味で使用されることはありません。 

もう 1 つのエッジ ケースは、すべての確率がゼロの場合です。 この場合、すべての si は 1 に等しく、すべての ri は 0 に等しいため、すべてのセグメント クエリは P = 1 および S = 0 を返し、答えは 1 になります。これはエレベーターがどこにも止まらないことに対応するため、ペップは常に授業に行きます。 

最後の微妙なケースは、単一のインデックスに対する頻繁な更新です。 セグメント ツリーの更新では、両方の派生値がローカルで再計算され、上方に伝播され、祖先ノードに古い寄与が残らないようにします。
