 ## 解決策
 ## 問題の理解

 各テストでは、単純な構造化された戦闘について説明します。n 回の敵の波があり、i 番目の波にはちょうど i 個の風船が含まれています。 ウェーブ内のすべての風船は同じパワー レベル k を持ち、1 つの風船を破壊するコストは i の k 乗になります。 したがって、レベル全体に必要なダーツの総数は、1 から n までのすべての i の i^k の合計になります。 

言い換えれば、このタスクは、大きな係数の下で S_k(n) = 1^k + 2^k + … + n^k の形式の古典的な電力和を計算することです。 

難しいのは定義ではなく規模です。 項の数 n は 10^9 に達する可能性があるため、すべての i を反復処理することは不可能です。 指数 k は最大 1000 であり、これは n ではなく k に多項式構造があることを示唆しています。 

単純な実装では、テスト ケースごとに 1 から n までループし、i^k を蓄積しようとします。 これは、n = 10^9 の単一テストであっても、10 億回のべき乗剰余演算が必要になるため、すぐに失敗します。 

もう 1 つのよくある失敗は、n までのすべての i の事前計算です。 また、n が大きすぎて実現できないため、メモリと時間の制約も破られます。 

より微妙なエッジ ケースは、k = 0 または k = 1 の場合です。k = 0 の場合、すべての項は 1 で答えは n で、k = 1 の場合、答えは n(n+1)/2 です。 一般式は、数値が不安定になることなく、これらのケースに正しく縮退する必要があります。 

## アプローチ

 ブルート フォース手法では、各項 i^k を直接評価し、それらを合計します。 これは数学的には正しいですが、計算的には実行不可能です。 各テスト ケースでは O(n) のべき乗が実行され、各べき乗のコストは O(log k) となり、最悪の場合にはテストごとにおよそ 10^9 の演算が発生し、これは時間制限をはるかに超えます。 

重要な観察は、S_k(n) が n の任意の関数ではないということです。 これは、k+1 次の n の多項式です。 これは累乗和に関するよく知られた事実であり、スターリング数を含む有限差分または二項展開恒等式を使用して導出できます。 

この構造を受け入れると、問題は大きな点 n で多項式を効率的に評価するという問題になります。 i を反復する代わりに、第 2 種スターリング数を使用して i^k を書き換えます。 

i^k = S(k, j) * j! の 0 から k までの j の合計 * C(i, j)

 i を 1 から n まで合計すると、合計を交換できます。 

S_k(n) = S(k, j) * j の j の合計! * C(i, j) の i の合計

 内和はきれいな閉じた形式になります。 

sum_{i=1..n} C(i, j) = C(n+1, j+1)

 これにより、問題全体が固定 k のスターリング数の計算と n でのいくつかの二項係数の評価に縮小されます。 

したがって、n を反復する代わりに、最大 1000 である k だけを反復します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n · log k) | お(1) | 遅すぎる |
 | スターリング + 組合せ論 | テストあたり O(k^2) | O(k^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの n と k を読み取ります。 目標は、1 から n までの i にわたる i^k の合計である S_k(n) を計算することです。 
2. 漸化式 S(k, j) = j * S(k-1, j) + S(k-1, j-1) を使用して、指定された k に対する第 2 種スターリング数 S(k, j) を事前計算します。 これにより、べき乗を組み合わせに変換する係数が構築されます。 
3. 各項には乗数 j! も含まれるため、k までの階乗を事前計算します。 これにより、評価中に一定時間のアクセスが可能になります。 
4. 0 から k までの各 j について、二項係数 C(n+1, j+1) を計算します。 n が大きいため、下降積 (n+1)(n)…(n-j+1) を (j+1) で割ったものとして計算します。 モジュロ演算の下で。 
5. 各 j に対して、S(k, j)、j!、および C(n+1, j+1) を乗算し、その結果を累積して答えを求めます。 
6. 10^9 + 7 を法とする最終的な合計を出力します。

これが機能する理由: この変換は、各単項式 i^k を二項基底関数 C(i, j) の線形結合に置き換えます。 これらの基底関数の i にわたる合計は単一の二項項 C(n+1, j+1) に分解されるため、合計全体は長い接頭辞の合計ではなく、閉じた形式の有限線形結合になります。 正確さは、両方の表現がすべての整数 i に関して一致するという同一性から得られるため、任意の接頭辞に対するそれらの合計も一致する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def build_stirling(k):
    S = [[0] * (k + 1) for _ in range(k + 1)]
    S[0][0] = 1
    for i in range(1, k + 1):
        for j in range(1, i + 1):
            S[i][j] = (S[i - 1][j - 1] + j * S[i - 1][j]) % MOD
    return S

def solve():
    t = int(input())
    tests = []
    max_k = 0
    for _ in range(t):
        n, k = map(int, input().split())
        tests.append((n, k))
        max_k = max(max_k, k)

    fact = [1] * (max_k + 2)
    invfact = [1] * (max_k + 2)
    for i in range(1, max_k + 2):
        fact[i] = fact[i - 1] * i % MOD

    invfact[max_k + 1] = pow(fact[max_k + 1], MOD - 2, MOD)
    for i in range(max_k, -1, -1):
        invfact[i] = invfact[i + 1] * (i + 1) % MOD

    stir = build_stirling(max_k)

    for n, k in tests:
        if k == 0:
            print(n % MOD)
            continue

        ans = 0
        # compute C(n+1, j+1) using falling product
        for j in range(0, k + 1):
            # compute numerator (n+1)P(j+1)
            num = 1
            x = n + 1
            for t2 in range(j + 1):
                num = num * (x - t2) % MOD

            comb = num * invfact[j + 1] % MOD

            ans = (ans + stir[k][j] * fact[j] % MOD * comb) % MOD

        print(ans % MOD)

if __name__ == "__main__":
    solve()
```このソリューションは、前処理をテストごとの計算から分離することを中心に構成されています。 スターリング数は、すべてのテストにわたって最大 k まで一度計算されるため、再計算が回避されます。 階乗および逆階乗も、高速二項評価のために 1 回事前計算されます。 

各テスト内で、二項項 C(n+1, j+1) は、n の階乗ではなく下降積を使用して計算されます。これは、n が階乗ベースの直接の組み合わせには大きすぎるためです。 これによりオーバーフローが回避され、すべての算術演算がモジュール化されます。 

よくある落とし穴は、合計が i = 1 から始まることを忘れていることです。そのため、恒等式では C(n, j+1) ではなく C(n+1, j+1) が生成されます。 

## 実用的な例

 n = 3、k = 2 について考えてみましょう。正解は 1^2 + 2^2 + 3^2 = 14 です。 

k = 2 のスターリング数を計算します: S(2,1) = 1、S(2,2) = 1。 

| j | S(k,j) | じ！ | C(n+1,j+1) | 貢献 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 1 | C(4,1)=4 | 0 |
 | 1 | 1 | 1 | C(4,2)=6 | 6 |
 | 2 | 1 | 2 | C(4,3)=4 | 8 |

 合計すると 14 になります。 

これにより、変換が直接評価と一致し、高次構造が正しく二項項に折りたたまれることが確認されます。 

ここで、n = 5、k = 1 について考えます。期待される結果は 1 + 2 + 3 + 4 + 5 = 15 です。 

| j | S(1,j) | じ！ | C(6,j+1) | 貢献 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 1 | 6 | 0 |
 | 1 | 1 | 1 | 15 | 15 |

 これにより、式が正しく三角数恒等式に帰着することが確認されます。

 ## 特殊なケース

 k = 0 の場合、すべての項 i^0 は 1 に等しいため、合計は n に等しくなります。 アルゴリズムでは、これはスターリング展開を完全にバイパスし、n モジュロ MOD を直接返します。これは単位 C(n+1,1) = n+1 と一致しますが、1 から始まる合計の正しいインデックス付けによってシフトされます。 

n = 1 の場合、和には単一の項が含まれるため、すべての上位構造が崩壊します。 二項評価では C(2, j+1) が生成されます。これは j = 0 の場合にのみ非ゼロとなり、結果は k に関係なく常に 1^k = 1 になります。 

k が n に比べて大きい場合、多くの高次スターリング項が計算に依然として表示されますが、二項係数 C(n+1, j+1) は j > n の場合に自然に消えるため、式は安定したままとなり、大きなインデックスからの不必要な寄与が回避されます。
