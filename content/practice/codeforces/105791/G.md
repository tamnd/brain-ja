 ## 解決策
 ## 問題の理解

 領域をモデル化する無向重み付きグラフが与えられます。 2 つの特別な頂点が区別されます。1 つは大学の正門、もう 1 つは IC と呼ばれる目的地です。 すべてのクエリ頂点に対して$x$, IC に到達する 2 つの方法を比較します。 

最初の方法は最適な方法であり、$x$グラフ内のICに直接接続します。 2 番目の方法は、Grisi が使用する固定戦略です。$x$, 彼はいつも最初に最短経路で入り口まで行き、次に入り口から最短経路でICまで行きます。 クエリの迂回コストは、Grisi の固定戦略が、クエリからの真の最短パスと比較してどれだけ長くかかるかです。$x$ICに。 

入力は、最大 200,000 の頂点とエッジを含むグラフを記述し、その後に最大 200,000 のクエリが続きます。 各クエリは独立しているため、クエリごとに最短パスを再計算するソリューションはすぐに時間制限を超えてしまいます。 グラフ全体にわたる単一の最短パス計算は許容されますが、クエリごとにそれを繰り返すことは許容されません。 

重要な隠された構造は、グリシのルートが 2 つの特別な頂点のみに依存する 2 つの最短経路セグメントで構成されていることです。 これにより、必要なすべての距離を一度に事前計算し、一定時間内にすべてのクエリに答えることが可能になります。 

開始頂点がすでに IC である場合、微妙なエッジ ケースが発生します。 Grisi のパスの式を機械的に適用すると正の値が生成されますが、正解は 0 です。 これには明示的な処理が必要です。 

## アプローチ

 各クエリに対する直接的なアプローチは、最短パス アルゴリズムを実行することです。$x$IC までの最短経路を実行することでグリシのルートをシミュレートします。$x$次に、事前に計算された入口から IC までの距離を加算します。 IC への入口に事前に計算された値を再利用したとしても、クエリごとの最短パスの計算が必要になり、おおよその結果が得られます。$q$ディクストラの実行。 と$q$200,000 までになると、これは計算上不可能になります。 

ターニングポイントは、各クエリの唯一の変化点が開始頂点であることに気づくことです。$x$、両方の特別な頂点は固定されています。 つまり、固定ソース (入口) から固定ターゲット (IC) までの最短経路距離のみが必要になります。 無向グラフでは、IC からダイクストラを実行することによって、IC からの最短経路距離も計算できます。 

これら 2 つの距離配列を取得すると、すべてのクエリは単純な算術式になります。$x$入口までの距離に入口から IC までの距離を加えたものから、IC までの最適距離を引いたもの$x$ICに。 これにより、クエリごとのグラフ走査が完全に削除されます。

 ## アルゴリズムのチュートリアル

 私たちは、ダイクストラを使用すると、固定ソースからの最短パスを事前に計算できるという事実に依存しています。 

1. 入口頂点から始めてダイクストラを実行します。$X_1$、配列を計算する$d_1[v]$からの最短距離を保存します。$X_1$あらゆる頂点に$v$。 これは、Grisi が任意の地点から入り口までどのように移動するかをキャプチャします。 
2. IC 頂点から開始してダイクストラを実行します。$X_2$、配列を計算する$d_2[v]$からの最短距離を保存します。$v$ICに。 グラフには方向性がないため、これは IC からすべてのノードまでの距離に相当します。 
3. 定数値を事前計算する$d_1[X_2]$、入口からICまでの最短距離です。 これはグリシの固定ルートの 2 番目のセグメントです。 
4. 各クエリ頂点について$x$、最短パスのベースラインを次のように計算します。$d_2[x]$、からの真の最適な移動時間を表します。$x$ICに。 
5. Grisi の移動時間を次のように計算します。$d_1[x] + d_1[X_2]$、彼が最初に行ったときから$x$入口まで、入口からICまで。 
6. 延長時間はグリシのルートと最適ルートの差です。 もし$x = X_2$、直接 0 を出力します。それ以外の場合は出力します。$(d_1[x] + d_1[X_2]) - d_2[x]$。 

明示的なチェック$x = X_2$移動が必要ない場合でも両方の最短経路セグメントがカウントされるため、式によって引き起こされる誤解を招く正の値が防止されます。 

### なぜ効果があるのか

 最短パス距離は最適な下部構造を満たします。2 つの固定頂点間の最短パスは、中間点間の最短パスに分解できます。 ダイクストラは、固定ソースからこれらの距離を正確に計算します。 

グリシの戦略は、あらゆる経路を次から次へと強制します。$x$IC までは入口を通過するため、経路の長さは 2 つの独立した最短経路の合計となります。 最適なルートはその制約とは無関係です。 両方の量がすべてのノードに対して 1 回だけ計算されるため、各クエリの比較は正確であり、再計算は必要ありません。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline
INF = 10**30

def dijkstra(n, adj, src):
    dist = [INF] * (n + 1)
    dist[src] = 0
    pq = [(0, src)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

def solve():
    n, m, q, x1, x2 = map(int, input().split())

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        adj[u].append((v, w))
        adj[v].append((u, w))

    d1 = dijkstra(n, adj, x1)
    d2 = dijkstra(n, adj, x2)

    base = d1[x2]

    out = []
    for _ in range(q):
        x = int(input())
        if x == x2:
            out.append("0")
        else:
            extra = d1[x] + base - d2[x]
            out.append(str(extra))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは隣接リストを構築し、ダイクストラを 2 回 (各特別な頂点から 1 回ずつ) 実行します。 2 つの距離配列はすべてのクエリで再利用されます。 値`base`入口からICまでの固定費を蓄積します。 

各クエリは、事前に計算された距離を使用して一定時間内に応答されます。 特殊な場合のチェック`x2`開始点がすでに目的地である場合の正確性を保証します。 

よくある実装上の間違いは、クエリごとに最短パスを再計算したり、IC への入口セグメントを各クエリ内で再計算するのではなく 1 回だけ事前計算する必要があることを忘れたりすることです。 

## 実用的な例

 入口が 1、IC が 4 の小さなグラフを考えてみましょう。 

入力グラフ:

 1-2 (1)、2-4 (1)、1-3 (1)、3-4 (10)

 1 からの最短距離は、d1[1]=0、d1[2]=1、d1[3]=1、d1[4]=2 となります。 

4 からの最短距離は、d2[4]=0、d2[2]=1、d2[3]=2、d2[1]=2 になります。 

クエリ x = 2 の場合:

 グリシルートは2→1→4、コスト=d1[2]+d1[4]=1+2=3です。 

最適なルートは d2[2] = 1 です。 

延長戦は２。 

クエリ x = 3 の場合:

 グリシルートは3→1→4、コスト=1+2=3。 

最適なルートは d2[3] = 2 です。 

延長戦は1。 

| クエリ x | d1[x] | d1[X2] | d2[x] | グリシ | 最適 | 番外編 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 2 | 1 | 2 | 1 | 3 | 1 | 2 |
 | 3 | 1 | 2 | 2 | 3 | 2 | 1 |

 これは、距離が事前計算されると、各クエリが強制パス メトリックと最短パス メトリックの間の直接比較に帰着することを確認します。

| スペース |$O(n + m)$| 隣接リストと 2 つの距離配列 |

 ## 特殊なケース

 クエリ頂点が IC の場合、式は$d_1[x] + d_1[X_2] - d_2[x]$になる$d_1[X_2] + d_1[X_2]$、旅行が必要ない場合でも、これは常にプラスです。 明示的な等価性チェックにより、このケースの出力がゼロになり、問題の定義と一致することが保証されます。 

複数のパスの重みが等しいグラフでも、ダイクストラはパスの一意性ではなく緩和順序にのみ依存するため、一貫した最短距離が生成されます。 これにより、最短パスが一意でない場合でも、両方の距離配列が有効なままであることが保証されます。
