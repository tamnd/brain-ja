 ## 解決策
 ## 問題の理解

 壁は、セルの n × m グリッドとして与えられます。 各セルは空であるか、釘でブロックされています。 ポスターは壁の長方形の領域にのみ掛けることができ、その長方形内のすべてのセルには釘が入っていない必要があります。 ポスターは、軸の配置を変更するような方法で任意に回転することはできないため、常にグリッド内の軸が配置された長方形に対応します。 

タスクは、爪のないセルのみで構成される可能な最大の長方形を見つけることです。 

グリッド サイズは最大でも 250 x 250 で、行または列にわたる 2 次解が実現できるほど十分小さいですが、すべての O(n²m²) 長方形を直接試すアプローチには大きすぎます。 すべての部分長方形に対するブルート フォースには、最悪の場合、およそ 10¹⁰ の可能性が伴いますが、これは 1 秒の許容範囲をはるかに超えています。 

微妙な点は、入力エンコーディングが直感とは逆になっていることです。`.`は釘（ブロックされた状態）を表し、`#`空の壁セルを表します。 したがって、必要な長方形はすべての中で最大のものです。`#`部分行列。 

典型的なエッジケースは、グリッドが完全にブロックされているか、完全にフリーである場合に発生します。 すべてがそうなら`.`の場合、有効な四角形が存在しないため、答えはゼロになります。 すべてがそうなら`#`、壁全体が使えるので答えはn・mです。 

## アプローチ

 直接的なアプローチは、考えられるすべての左上と右下の座標のペアを考慮し、それらの間の長方形に次の要素のみが含まれているかどうかを確認することです。`#`。 これには、プレフィックス合計またはスキャンを使用して四角形ごとに O(1) 個のセルをチェックする必要があります。O(n²m²) 個の四角形があるため、総作業量は O(n²m²) となり、250 x 250 のグリッドでは 4×10¹⁰ チェック程度になります。 最適化を行っても、これは実現できません。 

重要な観察は、この問題はバイナリ行列内の 1 の中で最大の長方形を見つけることと同じであるということです。`#`は 1 として扱われ、`.`2D 長方形について直接推論する代わりに、各行をヒストグラムのベースとして再解釈できます。 各行について、高さの配列を維持します。高さ[j]は連続する数をカウントします。`#`セルは行 i 列 j で終わります。 次に、各行は問題をヒストグラム内の最大の四角形を見つけるように変換します。 このヒストグラム問題は、単調スタックを使用して行ごとの線形時間で解決できることがよく知られています。 

すべての長方形には下境界があるため、縮小が機能します。 長方形の一番下の行を固定すると、そこで終わる最適な長方形は、各列が衝突せずにどれだけ上に伸びることができるかによってのみ決まります。`.`、これはまさに高さ配列がエンコードするものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての四角形を総当たりで実行する | O(n²m²) | お(1) | 遅すぎる |
 | 行 + スタックごとのヒストグラム | O(nm) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドをバイナリ解釈に変換します。`#`使用可能なスペースと`.`ブロックされています。 これにより、以降のすべての計算の基本表現が確立されます。 
2. 配列を維持する`height`サイズは m で、最初はすべて 0 です。 この配列は、行ごとに作成されたヒストグラムを表します。 
3. 各行 i を上から下に繰り返します。 各列 j について、更新します`height[j]`。 セルが`#`、増分`height[j]`1 ずつ増加し、それ以外の場合は 0 にリセットします。これにより、`height[j]`現在の行で終わる連続した空きセルの数を常に反映します。 
4. 行 i のヒストグラムを更新した後、このヒストグラム内の最大の長方形領域を計算します。 これは、単調増加するインデックスのスタックを使用して行われます。 スタックにより、各バーがその有効範囲にわたる最大の長方形の制限高さになるように、高さが昇順に処理されることが保証されます。 
5. ヒストグラムの処理中、現在の高さがスタック上部の高さより小さい場合は常に、スタックからポップし、ポップされた高さを制限要素として使用して長方形の面積を計算します。 幅は現在のインデックスと新しいスタックトップによって決まります。 
6. すべてのバーが処理されるまで続行し、センチネル境界をフラッシュすることで残りのスタック要素も解決されていることを確認します。 
7. すべての行にわたる最大面積を追跡します。 最終的な答えは、ヒストグラム内で見つかった最大の長方形です。 

中心的な考え方は、グリッド内のすべての有効な四角形には最下位の行が必要であり、各最下位の行について、ヒストグラム処理によってそこで終わるすべての四角形を徹底的に考慮するということです。 

### なぜ効果があるのか

 それぞれ`height[j]`行 i と列 j で終わる四角形の可能な最大垂直範囲を正確にエンコードします。 行 i で終わる四角形はヒストグラム内の連続したセグメントに対応し、その高さはそのセグメント内の最小の高さによって制限されます。 単調スタックにより、そのようなすべてのセグメントが正しい制限高さで 1 回だけ考慮されることが保証されます。 これにより、四角形の欠落や無効な四角形のカウントがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def largest_histogram(heights):
    stack = []
    best = 0
    n = len(heights)

    for i in range(n + 1):
        cur = 0 if i == n else heights[i]
        while stack and cur < heights[stack[-1]]:
            h = heights[stack.pop()]
            left = stack[-1] + 1 if stack else 0
            width = i - left
            best = max(best, h * width)
        stack.append(i)

    return best

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    height = [0] * m
    ans = 0

    for i in range(n):
        for j in range(m):
            if grid[i][j] == '#':
                height[j] += 1
            else:
                height[j] = 0

        ans = max(ans, largest_histogram(height))

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは実行中のヒストグラムを維持します。`height`、行ごとに更新されます。 各行は完全なヒストグラム評価をトリガーします。 単調スタック ルーチンは線形時間で最大の長方形を計算し、各インデックスのプッシュとポップが最大 1 回行われるようにします。 

よくある落とし穴は、ヒストグラム ループでセンチネルの反復を忘れることです。 追加の反復は`i == n`残りのスタック要素を強制的に処理します。そうしないと、右側の境界に伸びる四角形が失われます。 

もう 1 つの微妙な詳細は、遭遇したときに高さをゼロにリセットすることです。`.`。 以来`.`はブロックされたセルを表しており、それを通過する長方形は無効であるため、垂直方向の累算を再開する必要があります。

 ## 特殊なケース

 すべてのセルが存在する完全にブロックされたグリッド`.`、すべてゼロの高さ配列を生成します。 正の高さが存在しないため、各ヒストグラム呼び出しはすぐに 0 を返し、その結果、答えは全体を通して 0 のままになります。 

すべてのセルが存在する完全にオープンなグリッド`#`、行ごとに着実に増加するヒストグラムが生成されます。 スタックはフラッシュ時を除いて早期ポップをトリガーすることはなく、最大の四角形は最後の行の完全な行列に拡張されます。 

ブロックされたセルの海にある 1 つの孤立したフリー セルは、高さ 1 のスパイクを作成し、すぐにリセットされます。 ヒストグラム ステップでは、すべての候補四角形が幅または高さ 1 に正しく制限され、拡張には高さ 0 の列が含まれるため、オーバーカウントが発生しないことが保証されます。
