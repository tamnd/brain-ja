 ## 解決策
 ## 問題の理解

 与えられた間隔内で、連続する 3 つの整数の積という非常に特殊な形式で表現できる数値がいくつあるかを数えるように求められます。 このような数値はすべて、整数を選択することで得られます$x$そして形成$x \cdot (x+1) \cdot (x+2)$。 この問題では、多くのクエリが提供され、各クエリは範囲を提供します。$[L, R]$そして、この形式の個別の値がその範囲内にいくつ入るかを判断する必要があります。 

したがって、任意の数値を扱う代わりに、有効な値の範囲は単一の整数パラメーターによって完全に決定されます。$x$。 それぞれ$x$は候補値を 1 つだけ生成し、タスクはこれらの生成された値が指定された間隔内にいくつあるかを数えるようになります。 

制約は非常に大きいです。$L$そして$R$まで行くことができます$10^{16}$、最大で$10^6$クエリ。 これにより、範囲をスキャンしたり各値を個別にチェックしたりしても、実行可能な制限をはるかに超えるため、その間隔にわたるクエリごとの反復が即座に排除されます。 解決策は、有効な候補の前処理または高速な数学的位置特定に依存する必要があります。 

微妙なエッジの考慮事項は、有効な値がまばらであるということです。 機能$f(x) = x(x+1)(x+2)$は立体的に成長するため、値はすぐに大きく離れてしまいます。 これは、すべての有効な値を可能な最大値まで事前計算できる可能性があることを示唆しています。$R$、二分検索を通じてクエリに答えます。 

潜在的な落とし穴の 1 つは、複数の異なるものを想定することです。$x$値は同じ製品にマッピングされる場合があります。 関数は厳密に増加しているため、正の整数ではこれは起こりません。$x \ge 1$。 もう 1 つの問題は、値が最大まで大きくなるため、生成中のオーバーフローです。$10^{16}$, したがって、生成を慎重に停止する必要があります。 

## アプローチ

 簡単なアイデアは、可能な限りすべてのことを試してみることです$x$そして計算する$x(x+1)(x+2)$次に、クエリごとにすべての値をスキャンし、その中に含まれる値を数えます。$[L, R]$。 これは正しいですが、まったく現実的ではありません。 制限しても$x$、最大$x$そのような$x^3 \le 10^{16}$周りにいる$10^5$。 それはすでに約を与えています$10^5$価値観。 まで$10^6$クエリの場合、クエリごとのリニア スキャンにより、$10^{11}$操作が大きすぎます。 

重要な観察は、有効な数値の構造がクエリにまったく依存していないことです。 すべての有効な値は、次のものにのみ依存するため、一度だけ独立して生成できます。$x$。 この関数は単調増加であるため、すべての値を並べ替えられた配列に格納できます。 次に、各クエリは並べ替えられたリストに対する範囲カウントの問題になり、2 つの二分探索で答えることができます。 

これにより、問題は「クエリごとの構造の再計算」から「事前計算は 1 回、クエリは高速」に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース スキャン |$O(t \cdot n)$|$O(n)$| 遅すぎる |
 | 事前計算 + 二分探索 |$O(n + t \log n)$|$O(n)$| 承認済み |

 ここ$n$は有効な数です$x$、 だいたい$10^5$。 

## アルゴリズムのチュートリアル

 まず、フォームのすべての有効な値を生成します。$x(x+1)(x+2)$その値を超えるまで$10^{16}$。 関数は立体的に成長するため、反復するだけで済みます。$x$くらいまで$10^5$、安全です。 

計算されたすべての値をリストに保存します。 関数は厳密にポジティブに増加しているため$x$、リストはすでに並べ替えられているため、追加の並べ替えは必要ありません。 

クエリごとに$[L, R]$、二分探索を使用して、区間内に事前計算された値がいくつあるかを見つけます。 具体的には、value が少なくとも である最初の位置を見つけます。$L$、および値がより大きい最初の位置$R$。 これら 2 つの位置の違いから答えが得られます。 

### ステップ

 1. 反復する$x = 1, 2, 3, \dots$そして計算する$v = x(x+1)(x+2)$。 

停止するとき$v > 10^{16}$この範囲を超えると、クエリにそれを含めることができないためです。 
2. 生成されたすべての値を配列に格納する`vals`。 

すべての有効な数値が 1 つに一意に対応するため、これは機能します。$x$。 
3. クエリごとに$[L, R]$、二分検索を実行して以下を見つけます。 

最小のインデックス`vals[i] >= L`そして最小のインデックスは、`vals[i] > R`。 
4. クエリの答えは、これら 2 つのインデックスの差です。 

二分探索の使用が正しいかどうかは、次の事実に依存します。`vals`は厳密に増加しているため、すべての有効な数値が順序付けされます。 

### なぜ効果があるのか

 核となる不変条件は次のとおりです`vals`考えられるすべての有効な製品が昇順で 1 回だけ含まれます。 すべてのクエリは範囲内に事前計算された値がいくつあるかを尋ねるだけであるため、問題はソートされた配列内の要素をカウントすることに帰着します。 二分探索では、スキャンを行わずに正確な境界位置が得られるため、複雑さを軽減しながら正確性を維持できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 10**16

vals = []
x = 1
while True:
    v = x * (x + 1) * (x + 2)
    if v > MAXV:
        break
    vals.append(v)
    x += 1

# binary search helpers
def lower_bound(a, target):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo

def upper_bound(a, target):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] <= target:
            lo = mid + 1
        else:
            hi = mid
    return lo

t = int(input())
out = []

for _ in range(t):
    L, R = map(int, input().split())
    left = lower_bound(vals, L)
    right = upper_bound(vals, R)
    out.append(str(right - left))

print("\n".join(out))
```前処理ループは、すべての有効な凡例の値を一度に構築し、クエリごとに再計算を行わないようにします。 での停止条件$10^{16}$オーバーフローや不必要な作業を回避します。 

二分探索ルーチンは標準の境界ファインダーです。`lower_bound`以下の最初の有効な値を見つけます$L$、 その間`upper_bound`より厳密に大きい最初の値を見つけます$R$。 それらの差は、範囲内の有効なエントリを直接カウントします。 

実装の微妙な点の 1 つは、オーバーフローを懸念せずに Python 整数を安全に使用することです。 ただし、明示的に停止すると、$10^{16}$生成されたリストをコンパクトに保ち、不必要な増加を回避します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MAXV = 10**16
    vals = []
    x = 1
    while True:
        v = x * (x + 1) * (x + 2)
        if v > MAXV:
            break
        vals.append(v)
        x += 1

    def lower_bound(a, target):
        lo, hi = 0, len(a)
        while lo < hi:
            mid = (lo + hi) // 2
            if a[mid] < target:
                lo = mid + 1
            else:
                hi = mid
        return lo

    def upper_bound(a, target):
        lo, hi = 0, len(a)
        while lo < hi:
            mid = (lo + hi) // 2
            if a[mid] <= target:
                lo = mid + 1
            else:
                hi = mid
        return lo

    t = int(input())
    out = []
    for _ in range(t):
        L, R = map(int, input().split())
        out.append(str(upper_bound(vals, R) - lower_bound(vals, L)))
    return "\n".join(out)

 ## 特殊なケース

 重大なエッジ ケースは、間隔が有効な最小値を完全に下回る場合です。 最小の製品は、$1 \cdot 2 \cdot 3 = 6$。 のような入力の場合$[1, 5]$の場合、両方のバイナリ検索でインデックス 0 が返され、値が含まれないため、アルゴリズムは空のカウントを生成します。 

もう一つのケースは次のような場合です。$L$または$R$有効な製品と完全に一致します。 のために$[6, 6]$、`lower_bound`インデックス 0 を返し、`upper_bound`インデックス 1 を返し、正しいカウント 1 を生成します。単調な構造により、境界の一致において曖昧さがなくなります。 

大きな間隔など$[1, 10^{16}]$フルカバレッジをテストします。 この場合、すべての有効な値が範囲内に収まるため、バイナリ検索は事前計算されたリスト全体を対象とし、そのフルサイズを返します。
