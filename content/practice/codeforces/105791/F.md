 ## 解決策
 ## 問題の理解

 私たちは、目的地までの交通手段を必要とする X 人のマラソン選手のグループを与えられました。 N 個の利用可能な乗り物オプションがあり、各乗り物オプションは最大 1 回使用できる 1 台の乗り物のように動作します。 各乗り物には 2 つのプロパティがあります。1 つはグループから最大 pi 人の乗客を乗せられることを意味する定員 pi、もう 1 つは料金 vi、つまりその乗り物を選択した場合、実際に使用する座席の数に関係なく vi を支払わなければならないことです。 

目標は、総コストを最小限に抑えながら、総輸送容量が少なくとも X になるように乗り物のサブセットを選択することです。 乗車が選択されると、その乗車はグループをカバーするためにその最大の乗車能力に貢献するため、当社では、定員制限を超えて乗客を個別に乗車に割り当てることはありません。 

制約 X、N ≤ 1000、および pi ≤ 4 は、二次または低三次動的計画法の解決が実現できるほど十分に小さいです。 乗り物のすべてのサブセットを試行するソリューションは、N で指数関数的であり、2^1000 の組み合わせを評価する必要があるため、すぐには実行不可能です。 コスト効率は、最適なパッキングを保証する加法的なものではないため、単位容量あたり最も安い乗り物を貪欲に選択しようとする単純なアプローチでも失敗する可能性があります。 

貪欲な推論が微妙に失敗するケースは、容量が多く、少し高価な乗り物を利用することで複数の小さな乗り物を避けることができる場合に現れます。 たとえば、乗り物 (4, 20)、(3, 10)、(3, 8) の X = 6 を考えてみましょう。 最も低いコストを最初に選択する貪欲な戦略では、(3, 8) と (3, 10) を使用し、コスト 18 を達成します。しかし、(4, 20) と他に何も選択しないことは無効であり、(4, 20) と (3, 8) を選択すると、容量 7 とコスト 28 が得られ、これはさらに悪いことです。 これは、コストまたは容量あたりのコストに基づいたローカルな決定が適切に機能しないことを示しています。 

もう 1 つのエッジ ケースは、利用可能な総容量が不十分な場合です。 乗り物 (3, 10) および (2, 5) を含む X = 6 の場合、合計容量は 5 であるため、どの選択肢もターゲットに到達できず、正解は -1 になります。 DP または貪欲メソッドは、この到達不可能な状態を明示的に処理する必要があります。 

## アプローチ

 強引なアイデアは、乗り物のすべてのサブセットを考慮し、その総定員と総コストを計算することです。 これが機能するのは、すべての有効なソリューションが検索スペースに含まれているため、少なくとも X 容量に達するソリューションの中から最小コストを選択できるためです。 ただし、これには 2^N のサブセットを反復処理し、サブセットごとに値を合計する必要があるため、O(N・2^N) 個の演算が必要になります。これは、N が 1000 の場合、合理的な制限をはるかに超えています。 

重要な点は、これは古典的なナップザックの構造ですが、ひねりが加えられているということです。重量を正確に一致させようとしているのではなく、少なくとも X の容量に到達しようとしているのです。 各乗り物は 1 回乗車できるアイテムであり、少量の重量 (最大 4 個) とコストに貢献します。 これは、達成可能な容量に対する動的プログラミングの定式化を直ちに示唆します。 

0 から X までのすべての j について正確に j 人の輸送乗客を達成するために必要な最小コストを追跡する状態を定義します。要件を超えても答えがさらに改善されないため、X を超える定員はすべて X として安全に扱うことができます。 これにより、重みが小さく、ターゲットの次元が 1000 で制限される標準的な 0/1 ナップザックに問題が圧縮されます。 

ライドを反復処理し、DP 配列を逆に更新して、各ライドが最大 1 回使用されるようにします。 すべての乗り物を処理した後、答えはすべての j ≥ X に対する最小 dp[j] であり、実際には単なる dp[X] です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N・2^N) | O(N) | 遅すぎる |
 | DP が容量を超えています | O(N・X) | O(X) | 承認済み |

 ## アルゴリズムのチュートリアル

 これをコスト最小化のナップザックとして扱います。「重量」は乗客定員、「価値」はマイナスのコスト最小化です。

1. DP 配列 dp を作成します。ここで、dp[j] はちょうど j 人の乗客 (j は 0 から X まで) を輸送するために必要な最小コストを表します。ゼロの乗客の輸送にはコストがかからないため、ゼロである dp[0] を除くすべての値は無限大に初期化されます。 これにより、すべての遷移の開始元となる基本状態が確立されます。 
2. 各ライド (pi、vi) について、以前に到達できた状態を改善するためにそれを使用しようとします。 各ライドは 1 回しか利用できないため、j を X から 0 まで反復します。逆の反復により、単一の遷移ステップで同じライドを複数回再利用することがなくなります。 
3. 各 j について、dp[j] がすでに到達可能であれば、状態 min(j + pi, X) への移行を検討します。 コストが改善される場合は、dp[min(j + pi, X)] を dp[j] + vi で更新します。 X でクランプすると、「まさに X」と「X を超える」が区別されなくなります。両方で十分であるためです。 
4. すべてのライドを処理した後、dp[X] をチェックします。 まだ無限である場合は、乗り物のサブセットが必要な容量に到達できないことを意味するため、-1 を出力します。 それ以外の場合は、dp[X] が最小コストになります。 

### なぜ効果があるのか

 DP 状態は、最初の k 個の乗り物を処理した後、dp[j] が正確に j (X で上限) の容量を達成する、これらの k 個の乗り物のすべてのサブセットの中での最小コストであるという不変条件を維持します。 すべての遷移では現在のライドが除外または含まれ、逆反復により、各ライドがサブセットごとに最大 1 回寄与することが保証されます。 すべての有効なサブセットはそのような決定のシーケンスを通じて表現できるため、実現可能な解決策が失われることはなく、到達可能な容量あたりの最小コストを常に保存することで最適性が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    X, N = map(int, input().split())
    INF = 10**18
    
    dp = [INF] * (X + 1)
    dp[0] = 0
    
    for _ in range(N):
        p, v = map(int, input().split())
        
        for j in range(X, -1, -1):
            if dp[j] == INF:
                continue
            nj = j + p
            if nj > X:
                nj = X
            dp[nj] = min(dp[nj], dp[j] + v)
    
    print(-1 if dp[X] == INF else dp[X])

if __name__ == "__main__":
    solve()
```DP 配列は、到達不能な状態を表す大きなセンチネル値で初期化されます。 j に対する逆ループは、選択の 0/1 の性質を強制する重要な実装の詳細です。 次の状態を X にクランプすると、メモリの無駄や余剰容量の追跡にかかる時間が回避されます。 

よくある間違いは、j を昇順で反復することです。これにより、1 回の反復で同じ乗り物が複数回再利用されることになり、事実上、問題が無制限のナップザックになり、誤った結果が生成されます。 

## 実用的な例

 ### 例 1

 入力:```
6 3
3 10
4 20
3 8
```各乗車後の dp 状態を追跡し、関連する圧縮値のみを表示します。 

| ステップ | 乗る | dp[0..6] (最もよく知られている X=6 状態として圧縮) |
 | --- | --- | --- |
 | 初期化 | - | dp[0]=0、その他=∞ |
 | 1 | (3,10) | dp[3]=10 |
 | 2 | (4,20) | dp[4]=20、dp[6]=30 (3+3 は無効なので、4 および 3+4 状態のみ) |
 | 3 | (3,8) | dp[6]=18 |

 最終的な答えは 18 で、定員 3、3、および 4 の乗り物を選択することで得られますが、最適な (3,8) + (3,10) は、別の組み合わせよりも悪くなります。 DP は、すべてのサブセットの中から最適な組み合わせが見つかることを保証します。 

このトレースは、中間の部分容量を再利用してより大きな容量を形成する方法と、容量あたりの最良のコストのみを保存するだけで十分である理由を示しています。 

### 例 2

 入力:```
6 2
3 10
2 5
```| ステップ | 乗る | dp 状態 |
 | --- | --- | --- |
 | 初期化 | - | dp[0]=0 |

 6 に達する状態はないため、答えは -1 になります。 

これにより、DP が「達成可能な最良のコスト」と「実現不可能な目標」を正しく区別していることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N・X) | 各ライドは最大 X DP 状態を 1 回更新します。 
| スペース | O(X) | 容量を超える 1 つの DP 配列のみが保存されます。 

積 N·X は最大 10^6 であり、特に単純な整数演算の場合、DP ループを超えるネストされたオーバーヘッドがない場合、Python では 1 秒の制限内で快適に高速です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    X, N = map(int, sys.stdin.readline().split())
    INF = 10**18
    
    dp = [INF] * (X + 1)
    dp[0] = 0
    
    for _ in range(N):
        p, v = map(int, sys.stdin.readline().split())
        for j in range(X, -1, -1):
            if dp[j] == INF:
                continue
            nj = min(X, j + p)
            dp[nj] = min(dp[nj], dp[j] + v)
    
    return str(-1 if dp[X] == INF else dp[X])

# provided sample (interpreted correctly)
assert run("""6 3
3 10
4 20
3 8
""") == "18"

# unreachable case
assert run("""6 2
3 10
2 5
""") == "-1"

# minimum case
assert run("""1 1
1 10
""") == "10"

# exact boundary
assert run("""4 2
2 5
2 6
""") == "11"

# redundant large capacity
assert run("""5 2
4 7
4 8
""") == "7"

 | --- | --- | --- |
 | シングルミニマルライド | 10 | 基本ケースの正確性 |
 | 容量不足 | -1 | 到達不能の検出 |
 | 正確な塗りつぶし | 11 | 正確な容量の累積 |
 | 冗長オーバーラップ | 7 | 最適なサブセットの選択 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのライドを組み合わせても X に到達できない場合です。入力 X = 10 およびライド (3, 5)、(4, 6)、(2, 3) の場合、DP は dp[10] に到達せず、最終状態は無限のままです。 一連の遷移によって有効な全容量状態が生成されないため、アルゴリズムは正しく -1 を出力します。 

もう 1 つのエッジケースは、1 回の乗車ですでに要件を満たしている場合です。 X = 3 およびライド (4, 100) の場合、遷移は結果を直ちに dp[3] = 100 にクランプします。 クランプ ステップが不可欠なのは、クランプ ステップがないと、DP が X を超える容量を別の状態として誤って扱い、最適な遷移を逃す可能性があるためです。 

最後のエッジケースには、異なるコストで同じ容量を生成する複数の重複する組み合わせが含まれます。 DP は、各容量レベルで最小コストのみが存続することを保証するため、多くのサブセットが同じ j に達した場合でも、最良のサブセットのみが保持されます。
