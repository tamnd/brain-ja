 ## 解決策
 ## 問題の理解

 私たちはビーチアベニューに沿ってキオスクの列を与えられ、各キオスクでちょうど 1 杯の飲み物が提供されます。 旅行者は満足度値 1 から開始し、通過するキオスクの単一の連続セグメントを選択します。 そのセグメントを歩きながら、彼は現在の満足度に各ドリンクの価値を順番に掛け合わせます。 

各ドリンク値は 0 または符号付き 2 のべき乗のいずれかであり、整数 k に対して 0 または ±2^k として書き込むことができます。 値 0 は、満足度を即座に 0 にリセットし、増殖連鎖を効果的に断ち切る特別な飲み物を表します。 負の値は、通常の乗法で現在の満足度の符号を反転させる「悪い」飲み物を表します。ただし、現在の満足度がすでに負の場合を除き、問題ステートメントでは、別の負の値を飲むと陽性が回復することが強調されており、これは通常の乗算​​ルールと一致します。 

目標は、最終的な満足度が最大になるように、単一の連続セグメントの開始位置と終了位置を選択する (またはまったく入力しないことを選択する) ことです。 答えは 1e9 + 7 を法として出力する必要がありますが、結果の比較は法を求める前に実際の整数値に対して行われます。 

制約 n は最大 200,000 にすることができ、すべてのセグメントの O(n^2) 列挙が直ちに除外されます。 最悪の場合、二次走査には 4e10 程度の演算が必要となり、これは 1 秒では実行不可能であるため、いかなる解決策も線形または線形に近いものでなければなりません。 

微妙な点は、ゼロを指定するとプロセスが完全に分割されることです。 ゼロと交差するセグメントはその時点で積がゼロにリセットされるため、最適なセグメントがゼロと交差する必要はありません。 

もう 1 つの重要なエッジ ケースは、旅行者がセグメントをまったく取得せず、満足度 1 を維持できることです。このベースラインは重要です。なぜなら、負の積は、モジュロ後に大きく見える場合でも、実際の整数順序付けでは常に 1 よりも悪いためです。 

単純な間違いは、最終結果を純粋にモジュロ 1e9 + 7 で解釈し、モジュラー剰余が大きい負の積を誤って優先してしまうことです。 最大化はモジュロの前に行われるため、これは不正確です。 

## アプローチ

 直接的なアプローチは、実行中の製品を維持しながら、可能なすべての開始位置を試し、それを可能なすべての終了位置まで拡張することです。 これにより、すべての部分配列の積が正しく計算されます。 ただし、各拡張は O(1) で、O(n^2) 個の部分配列があるため、最悪の場合、およそ 2e10 回の演算が必要となり、これでは遅すぎます。 

問題の構造は、各位置で終わる最良の製品を追跡するだけでよいことを示唆しています。 これは古典的な「最大積部分配列」のアイデアですが、2 つの複雑な点があります。ゼロはすべてをリセットし、値は符号付きの 2 のべき乗であるため、追跡の大きさは追跡指数の合計と等価になります。 

実際の製品を追跡する代わりに、2 の指数を追跡します。 値 ±2^k は k を指数に寄与しますが、符号は個別に追跡されます。 乗算は指数の加算と符号反転になります。 

これにより、問題は、指数合計の観点から、ポジションごとに、そこで終わる最良のプラスの積と、そこで終わる最良のマイナスの積を維持することになります。 ゼロは両方の状態をリセットし、最初からやり直すことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのサブ配列に対するブルート フォース | O(n^2) | お(1) | 遅すぎる |
 | 正/負の指数状態の DP | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を左から右に処理し、2 つの実行状態を維持します。つまり、現在の位置で終わる最良の正の積と、現在の位置で終わる最良の負の積です。 また、有効なセグメントに対するグローバル最良の指数も維持します。

すべての値は符号までの 2 のべき乗であるため、積は 2 の指数で表されます。 

### ステップ

 1. 最良の答えの指数を 0 として初期化し、値 1 を持つ空の選択肢を表します。また、現在の正と負の状態を空として初期化します。 
2. 配列内の各要素について、その値に基づいて処理します。 
3. 値がゼロの場合は、両方の状態をリセットします。 これは、ゼロを通過するセグメントは乗算チェーンとして無効になるためです。 リセット後は、いつでもゼロから新たに開始できるため、グローバル応答を 0 で更新します。 
4. 値が正の 2^k の場合、この要素から新たに開始するか、指数に k を加算して前の正の状態を拡張することにより、正の状態を更新します。 負の状態が存在する場合、正の数を乗算すると符号が保持されるため、k を追加することによっても拡張されます。 
5. 値が負の -2^k の場合、前の負の状態を拡張することによって新しい正の候補を計算し (負の値に負の値を掛けると正になるため)、前の正の状態を拡張するか単一の負の要素として新たに開始することによって新しい負の候補を計算します。 
6. 各要素を処理した後、現在の正の指数でグローバル最良を更新します。これは、実際の値の順序付けにおいてベースライン 1 を超えることができるのは正の結果のみであるためです。 

### なぜ効果があるのか

 どの位置でも、そこで終わるすべての有効なサブ配列は、2 つの履歴のいずれかに由来する必要があります。つまり、前のインデックスで開始されたか、最新の 0 で開始されたかのいずれかです。 DP の州はまさにこれらの可能性を捉えています。 ±2^k の乗算は符号にのみ影響し、指数に固定量が追加されるため、正と負の状態を分離するだけで十分です。そのため、他の情報は必要ありません。 ゼロは、セグメント間の状態の相互汚染を防ぐハード リセットとして機能します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    best_exp = 0
    
    pos = None
    neg = None
    
    for x in a:
        if x == 0:
            best_exp = max(best_exp, 0)
            pos = None
            neg = None
            continue
        
        sign = 1 if x > 0 else -1
        k = x.bit_length() - 1 if x != 0 else 0
        
        new_pos = None
        new_neg = None
        
        if sign > 0:
            if pos is not None:
                new_pos = max(new_pos or 0, pos + k)
            else:
                new_pos = k
            
            if neg is not None:
                new_neg = neg + k
        
        else:
            if neg is not None:
                new_pos = max(new_pos or -10**30, neg + k)
            else:
                new_pos = k
            
            if pos is not None:
                new_neg = pos + k
            else:
                new_neg = k
        
        pos = new_pos
        neg = new_neg
        
        if pos is not None:
            best_exp = max(best_exp, pos)
    
    print(pow(2, best_exp, MOD))

if __name__ == "__main__":
    solve()
```実装では、各値が符号と指数に圧縮されます。 すべての非ゼロ値は正確に ±2^k であるため、指数はビット長を使用して抽出されます。 DP は 2 つの実行状態を維持し、要素ごとにその場で更新されます。 ベースライン 1 を超える可能性のある有効な候補にのみ対応するため、グローバル ベストは正の指数値のみを追跡します。 

よくある実装の落とし穴は、ゼロが両方の状態を完全にリセットする必要があることを忘れていることです。 もう 1 つの微妙な問題は、負の終了状態が最終的な答えに影響を与えることを誤って許可していることです。これにより、大きな負の積が誤って優先順位付けされてしまいます。

 ## 特殊なケース

 重要なエッジケースは、配列全体がゼロで構成されている場合です。 その状況では、すべてのセグメントは無効であり、正しい答えはベースライン 1 です。アルゴリズムはこれを処理します。ゼロごとにリセットが強制され、明示的に 0 による最良の更新が許可されるためです。一方、最終的な答えは、1 に対応する少なくとも 0 指数のままです。 

もう 1 つのエッジ ケースは、[-2, 2, -2] など、ゼロのない交互の符号のシーケンスです。 DP は正の状態と負の状態の両方を正確に追跡し、2 番目の負の状態が現れたときに、偶数の長さの負のチェーンが正の候補に変換されるようにします。 

最後の微妙なケースは、単一要素の配列です。 正の場合、答えはその要素の値です。 それが負の場合、ペアにできない限り最良のものは 1 のままですが、それは不可能であるため、DP は有害な単一の負のセグメントの選択を正しく回避します。
