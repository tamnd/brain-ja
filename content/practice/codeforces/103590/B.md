 ## 解決策
 ## 問題の理解

 一連の正の整数と固定乗数が与えられます。$x$。 目標は、可能な限り最小の数の新しい正の整数を追加してシーケンスを拡張し、最終的な値のマルチセットをペアに完全に分割できるようにすることです。 各ペアには厳密な乗法関係がなければなりません。ペア内の 1 つの値が$v$、もう一方はそうでなければなりません$v \cdot x$。 

ペアリングはシーケンス内で順序付けされていません。つまり、ペアリング前に要素を任意に再配置できます。 重要なのは、値の複数セットと、乗算ルールを満たす 1 つのパートナーとすべての要素を一致させることができるかどうかだけです。 

出力は、このような完全なペアリングを可能にするために必要な追加要素の最小数です。 

この制約は、シーケンスが最大で大きくなる可能性があることを示唆しています。$10^5$要素と値が到達可能$10^9$。 これにより、配列全体で繰り返しスキャンまたはネストされたマッチングを使用してペア形成を明示的にシミュレートしようとするアプローチが除外されます。 おそらく周波数カウントに基づく、線形または線形に近い方法が必要です。 

正確さに影響を与える微妙なエッジケースがいくつかあります。 

いつ$x = 1$、有効なペアはすべて同じ番号で構成されている必要があります。 値が奇数回出現する場合は、偶数にするためにコピーを 1 つ追加する必要があります。 すべての要素はそれ自体とペアになるだけであるため、個別の値を一致させようとする単純なアプローチはここでは失敗します。 

いつ$x = 0$、ルールは数値とゼロのペアに縮退します。 ゼロ以外の数値はゼロと一致しない限り有効なペアを形成できませんが、ゼロはゼロとのみペアになります。 これにより、他のすべてのケースとは異なる非対称制約が作成されます。 

もう 1 つの微妙なケースは、値が長い乗算チェーンを形成する場合に発生します。たとえば、$1, x, x^2, x^3$。 貪欲なローカル ペアリング戦略は、値を正しい順序で処理しないと失敗する可能性があります。これは、値のペアリングが早すぎると、後で有効なチェーンを形成する能力が破壊される可能性があるためです。 

## アプローチ

 ブルートフォース手法では、マルチセットを繰り返しスキャンして、ペアになっていない要素を選択します。$v$、一致するものを検索します$v \cdot x$、両方を使用済みとしてマークします。 存在しない場合は、新しい要素を追加して不一致を修正します。 これはペアリング ルールを直接適用するため、概念的には正しいですが、パートナーを検索するたびにコストがかかる可能性があります。$O(n)$、この操作を実行する場合があります$O(n)$につながる$O(n^2)$行動。 と$n = 10^5$、これは実現可能な限界をはるかに超えています。 

重要な観察は、ペアリングは周波数と固定変換のみに依存するということです。$v \rightarrow v \cdot x$。 これは、個々の要素の観点から考えるのではなく、むしろ要素の数と、それらがこの変換全体でどのように流れる必要があるのか​​という観点から考える必要があることを示唆しています。 

値を大きさで並べ替え、最小から最大まで処理すると、値を処理するときに次のことが保証されます。$v$、ペアにできる可能性のあるすべての小規模な貢献者$v$除算による$x$すでに解決済みです。 利用可能な出現を貪欲に一致させることができます。$v$の発生により$v \cdot x$、それに応じて両方のカウントを減らします。 残り物は$v$パートナーが見つからない問題は、次の場所に新しい要素を追加して修正する必要があります。$v \cdot x$、それらのみがペアリングできるためです。 

微妙な部分は、残りが乗算チェーンに沿って前方に伝播することです。 値の場合$v$一致しないままの場合は、今後の挿入が強制されます。$v \cdot x$、そしてそれらはさらにカスケードする可能性があります。 この方向の依存関係により、値による並べ替えが不可欠になります。 

特別な取り扱いが必要な場合$x = 1$変換によって値が変更されなくなるためです。 その場合、ペアリングはすべての周波数を均一にすることになります。

 ## アルゴリズムのチュートリアル

 1. シーケンス内のすべての数値の頻度を数えます。 これにより、ペアリングの決定はカウントのみに依存するため、個々の要素ではなく多重度の管理に問題が軽減されます。これは必要なことです。 
2. もし$x = 1$、すべての周波数を反復して追加します。$f \bmod 2$答えに。 同一の値内でペアリングを完了するには、各奇数カウントに 1 つの追加要素が必要です。 
3. もし$x \neq 1$、すべての個別の値を昇順に並べ替えます。 並べ替えにより、値を処理するときに、値によって生じる不足分を一貫した方向に進めることができます。 
4. ソートされた順序で値を調べます。 それぞれの値について$v$周波数が残っている場合$f[v] > 0$と合わせてみてください。$f[v \cdot x]$。 させて$m = \min(f[v], f[v \cdot x])$。 両方の周波数を次のように下げます。$m$。 これにより、この段階で考えられるすべての有効なペアリングが実行されます。 
5. After matching, if$f[v]$がまだ正の場合、これらは対になっていないため、修正する必要があります。 このような事態が発生するたびに、対応するものを追加する必要があります。$v \cdot x$なので、答えを増分します。$f[v]$そしてまた増加します$f[v \cdot x]$による$f[v]$、次に設定します$f[v] = 0$。 
6. すべての値が処理されるまで続行します。 累積加算数が最終的な答えとなります。 

### なぜ効果があるのか

 このアルゴリズムは、値間のすべてのペア可能な相互作用が不変であることを維持します。$v$そしてその前任者$v / x$すでに解決されているとき$v$処理されます。 ソートにより、以前の状態に戻ることがなくなり、すべての変更は順方向にのみ流れるようになります。$v \rightarrow v \cdot x$。 すべての要素には可能なパートナー値が 1 つだけあるため、後で結果を改善する可能性のあるあいまいさや代替ペアの選択はありません。 あらゆる赤字$v$新しい要素を導入する以外に解決できない$v \cdot x$, したがって、貪欲にすぐに修正するのが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    freq = defaultdict(int)
    for v in a:
        freq[v] += 1

    if x == 1:
        ans = 0
        for v in freq:
            ans += freq[v] % 2
        print(ans)
        return

    vals = sorted(freq.keys())
    ans = 0

    for v in vals:
        if freq[v] == 0:
            continue

        f = freq[v]
        nx = v * x

        match = min(f, freq[nx])
        freq[v] -= match
        freq[nx] -= match

        f = freq[v]
        if f > 0:
            ans += f
            freq[v] = 0
            freq[nx] += f

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、入力を周波数マップに圧縮することから始まります。 すべての操作は位置ベースではなく多重度ベースであるため、これは不可欠です。 特別な場合$x = 1$変換グラフが自己ループに崩壊し、一般的な貪欲な伝播が無効になるため、個別に処理されます。 

のために$x \neq 1$、キーをソートすると、値を処理するときに、より小さな値がすべてすでに確定されていることが保証されます。 マッチング ステップでは、間ですぐに考えられるすべてのペアが削除されます。$v$そして$v \cdot x$。 残りの余剰分は、$v$新しい要素を追加することで強制的に解決されます。$v \cdot x$、そしてその効果をすぐに広めます。 

微妙な実装の詳細は、への挿入を含め、常にその場で周波数マップを更新することです。$freq[nx]$たとえそれが以前はゼロだったとしても。 これにより、新しく作成された値が後の一致に参加する必要がある伝播チェーンの欠落が回避されます。
