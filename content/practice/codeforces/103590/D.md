 ## 問題の理解

 私たちは、感染の可能性がある人や健康な人の列を与えられますが、彼らの個々の状態を直接観察することはありません。 代わりに、線のセグメントに関するステートメントを受け取ります。 

タイプ 0 の各ステートメントは、l から r までのインデックスの間隔を記述し、その間隔内に少なくとも 1 人の感染者がいるかどうか、またはその間隔が完全にクリーンであるかどうかを主張します。 これらの声明は、感染者と健康な人の少なくとも 1 つの隠された割り当てと一致することが保証されています。 

これらのステートメントには、特定の人物 j について尋ねるタイプ 1 のクエリが組み込まれています。 このようなクエリごとに、収集された間隔情報がすでに人 j を感染させているのか、健康であることを強制しているのか、あるいは両方の可能性を残しておくのかを判断する必要があります。 

主な問題点は、情報が間隔にわたる集合形式でのみ与えられるため、各制約によって、長さ n の配列にわたる可能なバイナリ代入のセットが制限されることです。 クエリは、単一の位置の値がすべての有効な割り当てにわたって固定されているかどうかを尋ねます。 

n、q 10^5 の 2 倍までの制約により、クエリごとにグローバルな一貫性を維持または最初から再計算しようとするソリューションは直ちに除外されます。 実行可能な完全な割り当てを再構築したり、一定期間にわたってクエリごとの伝播を実行したりする方法は、遅すぎます。 

情報がローカルでは矛盾しているが、グローバルでは一貫している場合、微妙なエッジケースが発生します。 たとえば、セグメントに少なくとも 1 人の感染者が含まれていることがわかっていて、後で別の重複セグメントにより、その感染が区間の別の部分に強制的に存在する可能性があります。 正しい答えは、単一の再構成が存在するかどうかではなく、すべての一貫した割り当てが単一の位置に一致するかどうかによって決まります。 

## アプローチ

 ブルートフォースのアイデアは、長さ n のすべての有効なバイナリ配列のセットを間隔制約と一致させて維持することです。 各クエリの後、位置 j がすべてのクエリで固定されているかどうかを確認します。 これは概念的には正しいですが、実際には不可能です。有効な代入の数は n で指数関数的であり、制約が任意に重複する場合にはそれらを暗黙的に表すことさえ困難になるためです。 

問題をより構造的に見る方法は、各制約を範囲内で可能な構成を制限するものとして扱うことです。 区間に感染者が含まれていないというステートメントは、その区間内のすべての位置をゼロに固定します。 ある区間に少なくとも 1 人の感染者が含まれているというステートメントは、その区間内のすべての位置が同時にゼロになる可能性を排除します。 

重要な洞察は、視点を逆転させることです。すべての有効な配列を追跡するのではなく、有効な割り当てにおいてまだ 0 または 1 のいずれかである可能性があるという意味で、どの位置がまだ「未決定」であるかを追跡します。 これを実現可能にする構造は、「すべてゼロ」制約はローカル割り当てであるのに対し、「少なくとも 1 つ 1」制約は、既知の強制制約によってまだ満たされていない場合にのみ問題となるということです。 

これにより、標準的なオフライン削減が行われます。 制約とクエリを順番に処理しますが、2 つの操作を効率的にサポートする構造を維持しています。1 つは範囲を強制ゼロとしてマークする操作、もう 1 つは、満たされていない「少なくとも 1 つの」間隔の唯一の可能性があるために位置が強制 1 であるかどうかを確認する操作です。 これをサポートするために、各セグメントが完全にゼロ強制であるかどうかを維持するセグメント ツリーを使用できます。また、アクティブな「少なくとも 1 つの」制約のカバレッジ カウントも維持します。

本質的な考え方は、他のすべての位置がすでにゼロに強制されているある間隔を満たす必要がある場合、その位置は強制的に 1 になるということです。 これにより、グローバルな一貫性に関する質問が、一定期間にわたる動的な「固有の証人」クエリに変換されます。

 ## アルゴリズムのチュートリアル

 私たちは 2 つの補完的な構造を維持しています。 「感染なし」の間隔でゼロに強制されたポジションを追跡します。 もう 1 つは、「少なくとも 1 回の感染」間隔がどのように満たされるかを追跡します。 

また、各ポジションについて、アクティブな間隔の証人として潜在的に使用できるかどうかも維持します。 

### ステップ

 1. 長さ n の配列 is_zero を初期化します。最初はすべて false で、強制的に健全な位置がないことを意味します。 
2. 位置を強制ゼロとしてマークする範囲更新と、位置がすでに強制ゼロであるかどうかを尋ねるポイント クエリをサポートするセグメント ツリーを維持します。 これにより、感染を封じ込めることができないポジションを迅速に排除できることが保証されます。 
3. すべての「[l, r] に感染している少なくとも 1 人」の制約のリストまたは構造を維持します。 このような各制約はアクティブであり、その範囲内のすべての位置が現在強制的にゼロになっている場合、満たされていないと見なされます。 
4. x = 0 でタイプ 0 のクエリを処理する場合、セグメント ツリー内で区間 [l, r] 全体を強制ゼロとしてマークします。 これにより、その領域からすべての潜在的な感染が即座に除去されます。 
5. x = 1 でタイプ 0 のクエリを処理する場合、この間隔を内部に少なくとも 1 つの非ゼロ位置を必要とするライブ制約として登録します。 この制約は、強制ゼロではない少なくとも 1 つの位置によって満たされるまで、適切なままになります。 
6. 各更新の後、アクティブな「少なくとも 1 つの」間隔ごとに、強制ゼロではない候補位置がすでにあるかどうかを維持します。 これは、セグメントが完全にゼロかどうかをチェックするセグメント ツリー クエリを使用して追跡できます。 
7. 位置 j について尋ねるクエリ タイプ 1 の場合、2 つの条件をチェックします。 is_zero[j] が true の場合、j は間違いなく健全です。 それ以外の場合は、まだ満たされていないアクティブな区間内で j が唯一可能な非ゼロ位置であるかどうかを確認します。 j が唯一の候補として残っている区間が存在する場合、j は感染しているはずです。 
8. 強制ゼロ条件も強制 1 条件も当てはまらない場合、答えは曖昧になります。 

### なぜ効果があるのか

 このアルゴリズムは、タイプ x = 0 のすべての制約はその区間内のすべての感染の可能性を永久に排除し、タイプ x = 1 のすべての制約はその区間内で少なくとも 1 つの生き残った候補位置によってサポートされなければならないという不変式に依存しています。 アクティブな制約の唯一残っている候補である位置は、論理的にその制約を満たすように強制されます。 候補を削除しても一貫性が決して無効にならないという意味で、すべての制約は単調であるため、位置が一意に必要になると、すべての有効な補完においてその位置が維持されます。 これにより、条件を満たすすべての構成にわたって強制割り当てが一貫していることが保証されます。
