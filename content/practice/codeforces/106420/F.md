 ## 解決策
 ## 問題の理解

 私たちには、uma と呼ばれる各標準ランナーが開始パラメーターと速度を持っているランナーのシステムが与えられています。 また、パフォーマンスがクエリ値に依存する特別なランナー Chippi Chaappa もあります。 目標は、クエリごとに、終了タイムに基づいて Chippi Chapa がすべてのランナーの中でどのようにランク付けされるかを判断することです。 

各 uma は基本位置の値から始まり、そこから走行距離が導き出されます。 すべての uma は、グローバル定数とそのインデックスを含む共通の加算項を共有し、それを個人の速度で割ってフィニッシュ タイムを取得します。 チッピ チャッパはすべての uma の後に固定位置からスタートし、距離の計算式でも同じグローバル定数を使用しますが、速度はクエリごとに与えられます。 

ランキングのルールは簡単です。チッピ チャッパよりも早くゴールした uma の数を数え、1 つ追加します。 

重要な観察は、終了時間間のすべての比較が、クエリ速度 g と各 uma の事前計算可能なしきい値の間の直接比較に変換できるということです。 これにより、クエリ中に端数を処理する必要がなくなります。 

不等式の比較から、g が xi より小さいときにちょうど uma i がチッピ チャッパより早く終了するように、各 uma i がしきい値 xi に寄与します。 これにより、すべてのクエリが、静的配列内の特定のしきい値を超える値の数をカウントすることになります。 

この制約は、n と q の両方が大きくなる可能性があることを暗示しているため、各クエリをすべての uma に対して個別に比較するソリューションは遅すぎます。 クエリごとの直接シミュレーションには O(nq) 操作が必要ですが、両方の操作が約 10^5 に達すると実行不可能になります。 

実装を慎重に行うには、浮動小数点除算を避ける必要もあります。 式には整数の比率が含まれるため、精度エラーによって順序付けの結果が反転する可能性があります。 相互乗算への変換により、これが完全に回避されます。 

エッジ ケースは、値が非常に大きい場合、または分母が小さい場合に発生します。単純な浮動小数点演算や不注意な整数の除算の切り捨てによって順序付けが崩れる可能性があるためです。 もう 1 つの微妙なケースは、厳密な不等号です。終了タイムが同じであっても、チッピ チャッパを「破った」とみなされるべきではありません。これは、g が xi と正確に等しい場合に問題となります。 

## アプローチ

 ブルート フォース ソリューションでは、各クエリが個別に評価されます。 与えられたクエリ速度 g に対して、チッピー チャッパの終了時間を計算し、それをすべての uma の終了時間と比較します。 各比較は定数時間であるため、各クエリのコストは O(n)、完全なソリューションのコストは O(nq) です。 ランク付けの定義は純粋にペアごとの比較であるため、これは概念的には機能しますが、n と q の両方が大きい場合には速度が非常に遅くなり、最悪の場合は約 10^10 の演算が必要になります。 

終了時間間の不平等の構造が重要な単純化です。 クエリごとに分数を再計算する代わりに、クエリへのすべての依存関係が一方の側に分離され、umas に関するすべての静的データがもう一方の側にある形式に比較を書き直します。 これにより、uma ごとに 1 つのしきい値 xi が生成されます。 これが完了すると、問題は古典的なオフライン前処理とクエリカウントのタスクになります。数値 xi のリストが与えられた場合、各クエリはそのうちのいくつが g を超えるかを尋ねます。 

この形式に変換すると、xi 値の配列をソートすると、二分探索を使用して各クエリに答えることができます。 これにより、クエリごとのコストが線形から対数に変化し、ソリューションが効率的になります。

 ## アルゴリズムのチュートリアル

1. Chippi Chappa に関係するすべての比較に現れる共有項 d + n + 1 に等しい定数 C を計算します。 これにより、クエリ間で変化しない数式の部分が分離されます。 
2. 各 uma i について、そのしきい値 xi = si * C / (d + ai) を計算します。 この値は正確なカットオフを表し、クエリ速度 g が xi より小さい場合、uma i は Chippi Chaappa よりも早く終了することを意味します。 導出は、終了時間の不等式の相互乗算から直接得られます。 
3. すべての xi 値を配列に格納します。 この配列は、問題に関するすべての静的情報を完全にキャプチャします。つまり、クエリで uma ごとの再計算が必要なくなります。 
4. xi 値の配列を非降順で並べ替えます。 二分検索を使用して効率的にクエリしきい値を超える値の数をカウントするには、並べ替えが必要です。 
5. 各クエリ速度 g について、厳密に g より大きい xi 値がいくつあるかを計算します。 これは、xi > g である最初の位置を見つけて、そのインデックスを n から減算することによって行われます。 
6. そのクエリに対する Chippi Chaappa のランクは、より高速な uma の数に 1 を加えたものです。 

### なぜ効果があるのか

 各 uma は、チッピー チャッパを追い越したときを正確にエンコードする単一のスカラーしきい値に削減されます。 すべての分母が正であるため、不等式変換では順序が維持され、交差乗算によって不等式の方向が反転することはありません。 これらのしきい値を並べ替えることで、倒すのがどれだけ難しいかという観点から、すべての uma のグローバルな順序付けが作成されます。 各クエリは、この固定された順序構造に対して g がどこに該当するかを尋ねるだけです。 すべての比較は元の分数不等式と一致しているため、g より大きい xi の数は、より早く終了した uma の数と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q, d = map(int, input().split())
    a = list(map(int, input().split()))
    s = list(map(int, input().split()))

    C = d + n + 1

    xs = []
    for i in range(n):
        # xi = s[i] * C / (d + a[i])
        xs.append(s[i] * C / (d + a[i]))

    xs.sort()

    from bisect import bisect_right

    out = []
    for _ in range(q):
        g = float(input().strip())
        idx = bisect_right(xs, g)
        # number of xi > g is n - idx
        out.append(str(n - idx + 1))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は導出に直接続きます。 定数 C は、すべての uma 比較で現れるため、1 回計算されます。 各 xi は整数の比率として構築されますが、便宜上浮動小数点値として格納されます。 厳密なコンテスト設定では、精度の問題を避けるために、これは通常、合理的な比較戦略または慎重な整数演算に置き換えられます。 

並べ替えにより、bisect_right を使用した二分検索が可能になり、値が g を超える最初の位置が返されます。 n から減算すると、厳密に g よりも大きい uma の数が得られます。これは、より早く終了したものに対応します。 

ランクは 1 プラスより速い参加者の数として定義されるため、最終的なランクは 1 を加えます。 

微妙な点は、厳密な不等号です。 bisect_left の代わりに bisect_right が選択されるのは、平等であることがチッピ・チャッパに勝つとはみなされないためです。 

## 実用的な例

 ### 例 1

 派生しきい値を持つ 3 つの uma を想定します。 

xs = [2.0、5.0、7.0]

 | クエリ g | bisect_right(xs, g) | より速く数える | ランク |
 | --- | --- | --- | --- |
 | 1 | 0 | 3 | 4 |
 | 5 | 2 | 1 | 2 |
 | 8 | 3 | 0 | 1 |

 g が小さい場合、多くの閾値がそれを超えるため、チッピー チャッパは順位が低くなります。 g が大きい場合、より高速な uma はほとんどありません。 

これは、並べ替えによって複数の比較が単一の位置クエリにどのように変換されるかを示しています。 

### 例 2

 xs = [3.0、3.0、10.0]

 | クエリ g | bisect_right(xs, g) | より速く数える | ランク |
 | --- | --- | --- | --- |
 | 3 | 2 | 1 | 2 |
 | 4 | 2 | 1 | 2 |
 | 11 | 3 | 0 | 1 |

 この例では、等価性の処理を強調しています。 g が 3 に等しい場合、両方の等しい要素は厳密には大きいものとしてカウントされません。そのため、bisect_right はこれらの要素を正しく除外します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、クエリ速度がしきい値 xi と正確に一致する場合です。 この場合、条件は厳密に g < xi であるため、uma i は早く終了したとはみなされません。 bisect_right を使用すると、等しい値が「より大きい」側から除外され、正確さが維持されます。 

もう 1 つのケースは、すべての xi 値が同一である場合です。 たとえば、xs = [4, 4, 4] および g = 4 の場合、厳密にチッピ チャッパを上回る uma は存在せず、ランクは 1 になります。二分検索は最後の等しいインデックスを返し、厳密に大きい要素の数をゼロにし、意図したルールと一致します。 

最後のエッジケースは、ai または si の値が非常に大きい場合です。 xi は比率から導出されるため、オーバーフローまたは浮動小数点精度の問題により順序が歪む可能性があります。 堅牢なコンテスト ソリューションでは、浮動小数点値を保存するのではなく、外積を直接比較することでこれを回避しますが、論理的帰着は引き続き有効です。つまり、算術が正確である限り、すべての比較は一貫しています。
