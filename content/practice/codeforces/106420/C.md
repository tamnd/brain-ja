 ## 解決策
 ## 問題の理解

 レーサーの 2 つの順序付きリストが与えられます。各レーサーには固有の名声値があります。 タスクは、最初のリストの先頭または 2 番目のリストの先頭から次のレーサーを繰り返し選択し、常に一度に 1 つの要素を消費して、単一の最終ラインナップを構築することです。 目標は、2 つのリストの現在の先頭での威信比較に基づいた貪欲な優先ルールを尊重する組み合わせシーケンスを形成することです。 

各ステップでは、各リストの最初に残ったレーサーのみが重要です。 マージされたシーケンスの次にどれを配置するかを決定し、それをリストから削除します。 このプロセスは、両方のリストがなくなるまで続行されます。 

この種の結合問題における典型的な制約の重要な意味は線形性です。レーサーの総数が約 200,000 に達する場合、O(nm) または O((n+m)²) 戦略は直ちに実行不可能になります。 唯一実行可能な方向は、両方のリストを介してポインタを 1 回だけ進めて O(n + m) の解を生成するアルゴリズムです。 

リストの 1 つが早期に空になると、微妙なエッジ ケースが発生します。 空かどうかをチェックせずに常にヘッドを比較する単純な実装は失敗します。 たとえば、A が空で、B にまだ要素がある場合、唯一の有効なアクションは B から取得することです。もう 1 つのエッジ ケースは、最初の要素の値が等しい場合です。 この問題はグローバルに一意であることを示していますが、実装では等価性の処理が想定され、順序付けロジックを壊す可能性のある不要な分岐が導入されることがあります。 

## アプローチ

 ブルートフォース解釈では、2 つのリストをインターリーブする可能なすべての方法をシミュレートします。 各ステップでは最大 2 つの選択肢があるため、最悪の場合、高さ n + m の二分決定木を探索します。 これにより、およそ O(2^(n+m)) という指数関数的な複雑さが生じ、数十要素を超える非常に小さな入力の場合でも不可能になります。 

重要な点は、実際には両方の選択肢を検討する必要はないということです。 どのステップでも、現在のプレフィックスの選択によって辞書編集的により良いシーケンスが得られるかどうかだけを考慮します。 すべての値は個別であるため、残りのサフィックスを比較すると、局所的に現在のヘッドのみを比較することになります。 一方のヘッドが他方よりも厳密に小さい場合、それを最初に選択すると、常にグローバルに優れたプレフィックスが生成されるため、将来の継続でこれより悪くなることはありません。 

この局所的な最適性により、決定プロセス全体が単純な貪欲マージにまとめられます。これは、順序が固定ソートではなくヘッド比較によって動的に決定されることを除いて、2 つのソートされた配列のマージと同様です。 

2 つのポインタを維持し、小さい方の現在のヘッドを繰り返し取得して、そのポインタを進めます。 一方のリストが使い果たされると、もう一方のリストの残りの要素が直接追加されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(n+m)) | O(n+m) | 遅すぎる |
 | 最適な貪欲なマージ | O(n+m) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 各リストに 1 つずつ、2 つのインデックスを使用してマージ プロセスをシミュレートします。 

1. 配列 A と B の先頭で 2 つのポインター i と j を初期化します。これらは、各リストの最初の未消費のレーサーを表します。 
2. i が A 内にあり、j が B 内にあるときに、A[i] と B[j] を比較します。 小さい値が出力シーケンスの次のレーサーとして選択されます。 すべての値が異なる場合、以降の決定は利用可能な小さいプレフィックスをスキップすることに依存しないため、この選択は正しいです。 
3. A[i] の方が小さい場合は、それを結果に追加し、i をインクリメントします。 それ以外の場合は、B[j] を追加し、j をインクリメントします。 これにより、ステップごとに 1 つの要素のみが消費され、直線的な進行が維持されます。 
4. 1 つのポインタがその配列の末尾に到達したら、もう 1 つの配列の残りの要素をすべて順番に追加します。 ソースが 1 つだけ残っているため、この時点では選択の余地はありません。

これが機能する理由: すべてのステップで、各リストの最初に残っている要素である 2 つの候補の間で決定が行われます。 すべての値は一意であるため、小さい方の先頭を選択すると、マージされたシーケンスの辞書編集的に小さいプレフィックスが常に生成されます。 代替選択を行うと、最初の異なる位置が即座に増加し、後の要素がシーケンス内で前に移動できないため、その後のスワップによってその順序を修復することはできません。 これにより、最適な下部構造と組み合わせた貪欲な選択特性が確立され、利用可能な小さいヘッドを常に選択する正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    i = j = 0
    res = []
    
    while i < n and j < m:
        if a[i] < b[j]:
            res.append(a[i])
            i += 1
        else:
            res.append(b[j])
            j += 1
    
    while i < n:
        res.append(a[i])
        i += 1
    
    while j < m:
        res.append(b[j])
        j += 1
    
    print(*res)

if __name__ == "__main__":
    solve()
```このソリューションは、配列内を独立して移動する 2 つのポインターを中心に構成されています。 メイン ループは両方のリストにまだ要素がある間のみ続行され、すべての比較が意味のあるものになることが保証されます。 各反復では要素が 1 つだけ消費されるため、要素が再検討されることはありません。 

最後の 2 つのループは枯渇のケースを処理します。 これらが必要なのは、1 つの配列が空になるとそれ以上の比較ができなくなり、残りのすべての要素を順番に追加する必要があるためです。 

よくある実装上の間違いは、両方のポインターではなく、いずれかのポインターが限界に達したときにマージ ループを停止する必要があることを忘れていることです。 もう 1 つの微妙な問題は、等価性の処理が間違っていることですが、ここでは一意性により厳密な順序付けが保証されるため、残りのすべてのケースが else ブランチで安全に処理されます。 

## 実用的な例

 A = [3, 7, 10] および B = [2, 6, 8, 11] を考えてみましょう。 

ポインタの位置を追跡して出力します。 

| 私 | j | A[i] | B[j] | 選ばれた | 出力 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 3 | 2 | 2 | [2] |
 | 0 | 1 | 3 | 6 | 3 | [2、3] |
 | 1 | 1 | 7 | 6 | 6 | [2、3、6] |
 | 1 | 2 | 7 | 8 | 7 | [2、3、6、7] |
 | 2 | 2 | 10 | 8 | 8 | [2、3、6、7、8] |

 このトレースは、アルゴリズムが 2 つのソートされたシーケンスをマージするのとまったく同じように動作し、利用可能な最小のプレフィックス要素を常に保持していることを示しています。 

ここで、A = [5] および B = [1, 2, 3] について考えてみましょう。 

| 私 | j | A[i] | B[j] | 選ばれた | 出力 |

 これにより、1 つのリストが早期に枯渇した場合の正しい処理が確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各要素は 1 回だけ追加され、ポインターは前方にのみ移動します。 
| スペース | O(n + m) | 出力配列にはマージされたすべての要素が格納されます。 

線形の複雑さは、合計入力サイズが数十万に達する可能性がある制約条件に一致するため、シングルパス ソリューションが必要かつ十分になります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    i = j = 0
    res = []
    
    while i < n and j < m:
        if a[i] < b[j]:
            res.append(a[i])
            i += 1
        else:
            res.append(b[j])
            j += 1
    
    while i < n:
        res.append(a[i])
        i += 1
    
    while j < m:
        res.append(b[j])
        j += 1
    
    return " ".join(map(str, res))

 ## 特殊なケース

 一方のリストが最初から空の場合、アルゴリズムは比較ループを完全にスキップし、もう一方のリストを直接出力します。 入力 A = [] および B = [4, 1, 2] の場合、ポインタ i は 0 に留まり、j は 0 から 3 に進み、要求どおりに [4, 1, 2] を生成します。 

一方のリストのすべての要素が他方のリストよりも小さい場合、アルゴリズムは一貫してそのリストを最初に排出します。 A = [1, 2, 3] および B = [10, 11] の場合、すべての比較では A が枯渇するまで選択され、その後 B が追加されます。 ポインタが前方にのみ移動するという不変条件により、要素がスキップされたり、誤って並べ替えられたりすることはありません。 

A = [1, 3, 5, 7] および B = [2, 4, 6, 8] など、インターリーブが最大の場合、各ステップは配列間で交互に行われます。 このアルゴリズムは、追加の分岐を行わずにこれを処理します。これは、各比較が独立して次に小さいヘッドを解決し、厳しい交替下でも正確性が維持されるためです。
