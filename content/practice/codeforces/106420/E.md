 ## 解決策
 ## 問題の理解

 私たちには一連の敵の攻撃波が与えられています。 各ウェーブには、1 秒あたりのダメージ率と持続時間という 2 つのパラメーターがあります。 プレイヤーがレベル ℓ を選択した場合、すべての波はダメージ率から ℓ を減算することによって弱められますが、ゼロを下回ることはありません。 したがって、波 i は 1 秒あたり最大 (0, dᵢ − ℓ) のダメージのみを与え、tᵢ 秒間持続します。 

すべての波で受ける合計ダメージは、これらの寄与の合計です。 目標は、累積ダメージの合計が所定の健康閾値 h よりも厳密に小さくなる、つまりプレイヤーが生き残れるような最小レベル ℓ を見つけることです。 

重要な計算オブジェクトは関数 D(ℓ) = Σ max(0, dᵢ − ℓ) · tᵢ です。 波ごとに独立した決定の中から選択するのではなく、すべての波を均一に低減する単一のグローバル パラメータ ℓ を選択します。 

入力サイズでは、n と dᵢ および tᵢ の大きな値までが許可されます。 単純な方法で完全なダメージ表現を繰り返し再計算するソリューションでは、クエリごとにすべてのウェーブを処理する必要があります。 max(dᵢ) までの可能な ℓ 値に対して線形スキャンを試みると、dᵢ が大きくなる可能性があるため、これは大きくなりすぎ、O(max(dᵢ) · n) アプローチは実行不可能になります。 

主な構造観察は単調性です。ℓ を増加しても各項 max(0, dᵢ − ℓ) を減少させることしかできないため、ℓ が増加しても D(ℓ) が増加することはありません。 これは、ある程度のℓで生存が可能になると、それより大きなℓもすべて機能するというクリーンな閾値動作を意味します。 

微妙なエッジケースは、ℓ がすべての dᵢ を超える場合です。 この場合、すべての項がゼロになるため、D(ℓ) = 0 となり、生存は自明に保証されます。 これにより、検索スペースが制限され、答えが常に存在することが保証されます。 

もう 1 つの特殊なケースは、ℓ = 0 であってもすでに D(0) < h が得られる場合です。 この場合、答えは 0 であり、二分探索では、オフバイワンの間違いによって下限をスキップすることなく、下限が有効であることを正しく許可する必要があります。 

## アプローチ

 最も直接的なアイデアは、ゼロから始めてすべての可能なレベル ℓ を試し、それぞれの選択肢に対する合計ダメージを計算することです。 固定 ℓ の場合、すべての波をスキャンし、max(0, dᵢ − ℓ) · tᵢ を計算して合計します。 これは損害の定義に直接従うため、正しいです。 ただし、各評価は O(n) であり、ℓ の範囲が max(dᵢ) までの場合、総コストは O(n · max(dᵢ)) となり、dᵢ が大きくなる可能性がある場合、これはあまりにも大きすぎます。 

この改善は、任意の関数を最適化しているのではなく、単調な述語を検索していることを認識することで得られます。 「D(ℓ) < h」という条件は一貫して動作します。ある ℓ に当てはまる場合は、それより大きなすべての ℓ にも当てはまります。 これにより、問題は単調減少関数のしきい値点を見つけることに変換されます。 

この構造が可視化されると、二分探索が自然なツールになります。 0 から max(dᵢ) までの検索範囲を定義します。 ℓ が max(dᵢ) に達すると、すべての項が消滅し、ダメージがゼロになるため、上限は十分です。 各チェックは線形時間で D(ℓ) を評価し、評価の合計対数数を与えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n · max(dᵢ)) | お(1) | 遅すぎる |
 | 最適 (二分探索) | O(n log max(dᵢ)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 総ダメージが h を下回るような最小の ℓ を見つけたいと考えています。

1. すべての dᵢ の最大値を計算して、検索スペースの上限を定義します。 これが機能するのは、この点を超える ℓ がすべてのダメージ寄与を無効にするためです。 
2. 二分探索境界を low = 0 および high = max(dᵢ) で設定します。 離散的な単調領域を探索しています。 
3. low ≤ high の間、mid = (low + high) // 2 を計算します。これは候補レベルを表します。 
4. すべてのウェーブを反復し、max(0, dᵢ − Mid) · tᵢ を合計することにより、レベル Mid での合計ダメージを評価します。 これは問題定義を直接シミュレートします。 
5. 計算ダメージが h 以上の場合、中では足りないので、低から中 + 1 に移動します。これは、ℓ を増やすことがダメージを軽減する唯一の方法であるためです。 
6. それ以外の場合は、mid で十分であるため、これを回答候補として保存し、high からmid − 1 に移動して、より小さい有効なレベルを見つけてみます。 
7. ループ終了後、保存される候補は最小有効ℓとなります。 

なぜ効果があるのか

 関数 D(ℓ) は、個々の項 max(0, dᵢ − ℓ) が非増加であるため、ℓ において非増加です。 これにより、整数行に無効な値の連続領域が作成され、その後に有効な値の連続領域が作成されます。 二分探索は、無効な領域と有効な領域の間の境界を維持しながら、探索空間の半分を繰り返し破棄することによってこの構造を利用します。 このアルゴリズムは、低値を下回る値はすべて無効であり、高値を超える値はすべて有効であるという不変条件を維持するため、答えは区間内にとどまる必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, h = map(int, input().split())
    d = []
    t = []
    mx = 0

    for _ in range(n):
        di, ti = map(int, input().split())
        d.append(di)
        t.append(ti)
        if di > mx:
            mx = di

    def damage(l):
        total = 0
        for i in range(n):
            if d[i] > l:
                total += (d[i] - l) * t[i]
                if total >= h:
                    return total
        return total

    low, high = 0, mx
    ans = mx

    while low <= high:
        mid = (low + high) // 2
        if damage(mid) >= h:
            low = mid + 1
        else:
            ans = mid
            high = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装は二分探索構造に直接に従います。 ダメージ関数には、累積合計が h に達した場合の早期終了が含まれており、これにより大規模な場合の不必要な計算が防止されます。 D(ℓ) が h 以上であるかどうかを区別するだけでよいため、これは正確さに影響しません。 

二分検索は、ans 内の最も有効な答えを追跡します。 中間値が条件を通過した場合でも、最小性を確保するために左の検索を続けます。 

一般的な実装上の落とし穴は、早期停止条件を忘れたり、dᵢ ≤ ℓ の場合でもすべての i に対して (dᵢ − ℓ) を計算したりすることです。これにより、不要な演算が追加され、負の値が含まれる場合に誤った累算が行われる危険性があります。 

## 実用的な例

 3 つの波がある小さなインスタンスを考えてみましょう。 

n = 3、h = 10

 波: (d, t) = (5, 2), (8, 1), (3, 4)

 候補となるℓ値を計算します。 

| ℓ | ウェーブ 1 | ウェーブ 2 | ウェーブ 3 | 合計D(ℓ) |
 | --- | --- | --- | --- | --- |
 | 0 | 10 | 8 | 12 | 30 |
 | 2 | 6 | 6 | 4 | 16 |
 | 4 | 2 | 4 | 0 | 6 |
 | 5 | 0 | 3 | 0 | 3 |

 ℓ=2の場合はダメージが10を超えているので無効です。 ℓ=4の場合はダメージが10以下になるので有効です。 最小有効ℓは4です。 

このトレースは D(ℓ) の単調減少を示しており、これはまさに二分探索が依存しているものです。 

ここで、すでに生存が容易である場合を考えてみましょう。 

n = 2、h = 5

 (2, 10)、(1, 10)

 | ℓ | 合計D(ℓ) |
 | --- | --- |
 | 0 | 30 |
 | 1 | 10 |
 | 2 | 0 |

 ここで、答えは ℓ = 1 です。二分探索は、ダメージが h を下回る最初のレベル付近で正しく収束します。

 ## 特殊なケース

 1 つのエッジ ケースは、ℓ = 0 がすでに条件を満たしている場合に発生します。 たとえば、すべての波が非常に弱い場合、または h が大きい場合は、次のようになります。 

n = 2、h = 100

 (1, 1)、(2, 1)

 ℓ = 0 では、合計ダメージは 3 となり、すでに h を下回ります。 二分探索では、中間値が常に有効であることが正確に識別されるため、高値はゼロに向かって縮小します。 アルゴリズムは、有効な Mid が見つかるとすぐに ans = 0 を維持します。 

もう 1 つのエッジ ケースは、最適な ℓ が max(dᵢ) に等しい場合です。 たとえば:

 n = 2、h = 1

 (3, 1)、(3, 1)

 ℓ = 2 では、ダメージは依然としてプラスです。 ℓ = 3 では、すべての寄与が消えます。 二分探索には high = max(dᵢ) を含める必要があります。そうでない場合は、正しい境界点が除外されます。
