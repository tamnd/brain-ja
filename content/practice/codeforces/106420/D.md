 ## 解決策
 ## 問題の理解

 非常に小さな複数の文字セットが与えられ、それらの文字の一部またはすべてを再配置することで形成できるすべての個別の文字列を考慮するように求められます。 各文字は最大でも入力内に出現する回数だけ使用できるため、入力文字の空ではないすべての可能なサブセットの一意の順列をすべて効率的に構築することになります。 

出力は、この文字列ファミリー全体にわたる情報の集約に基づいています。 すべての有効な文字列がその長さに寄与するため、タスクは、形成可能なすべての個別の文字列を生成し、その長さを 1 回ずつ累積することになります。 

重要な構造上の制約は、文字数が非常に少なく、最大でも 8 文字であることです。これにより、問題の性質がすぐに変わります。 一般的な重複のある順列問題は入力サイズが指数関数的になりますが、ここでは絶対的な最悪の状態空間は 8 項目の順列数によって制限されており、直接列挙できるほど小さいです。 

単純な落とし穴は、重複を無視することです。 入力に繰り返し文字が含まれている場合、異なる構築パスによって同じ文字列が得られる可能性があります。 たとえば、「AAB」と入力すると、どちらの「A」が最初に選択されるかに応じて、「AAB」を構築する 2 つの同一の方法が生成されます。 重複排除を行わないと、文字列の数と長さの合計の両方が過剰にカウントされてしまいます。 

もう 1 つの微妙な問題は、空の構築をカウントすることです。 文字を配置せずに再帰を終了できるようにする場合は、空の文字列を含めることになります。 その寄与は長さがゼロであるため、合計には影響しませんが、明示的に除外しない場合、正確性に関する推論が複雑になる可能性があります。 

## アプローチ

 ブルートフォースアプローチは、文字の頻度表に対するバックトラック列挙として問題を扱うことです。 利用可能な文字の数を維持し、残りの文字を選択して追加し、続行することで文字列を再帰的に構築します。 完全な文字列に到達するたびに、それをセットに挿入して、重複が複数回カウントされないようにします。 

このアプローチは正しいです。すべての有効な文字列が、頻度制約を尊重する選択のシーケンスに対応し、再帰によってそのようなシーケンスがすべて調査されるからです。 ただし、再帰状態の数は分岐係数が 8 まで急速に増加し、最悪の場合、構築される文字列の生の数は約 109,600 に達する可能性があります。これはまだ管理可能ですが、過度に複雑にする必要はありません。 

重要な観察は、n ≤ 8 という制約により、階乗スケールの列挙が実行可能になるということです。 再帰状態またはハッシュ セットを介して重複を慎重に取り除く代わりに、ソートされたマルチセット表現に対する次の順列のような標準的な順序付け手法を使用して、すべてのサブセット長のすべての順列を直接生成できます。 これにより、再帰のオーバーヘッドが回避され、ソートされた順序とセットの挿入に依存することで重複の処理が簡単になります。 

私たちは基本的に、アルゴリズムの洗練性と引き換えに、総当たりの列挙を行っていますが、これは入力の制限が小さいことによって完全に正当化されています。

 ## アルゴリズムのチュートリアル

1. 入力文字列内の各文字の頻度をカウントします。 これにより、生のインデックスを操作するのではなく、構築できるものをコンパクトに表現できます。 
2. 入力文字列内の位置に対するビットマスクを使用して、空ではない文字の可能なすべてのサブセットを生成します。 n ≤ 8 であるため、サブセットは最大でも 2^8 − 1 = 255 個あり、これは非常に小さいです。 
3. サブセットごとに、選択したインデックスに対応する文字のマルチセットを構築します。 このステップでは、そのサブセットで使用されている正確な文字を分離します。 
4. サブセット内の文字を並べ替えます。 並べ替えにより、同一のマルチセットから生成された重複する順列を一貫して処理できるようになります。 
5. 次の置換ロジックを使用して、このソートされたリストのすべての個別の置換を生成します。 各順列は、そのサブセットの一意の文字列配置に対応します。 
6. 生成された各順列をセットに挿入します。 このセットは、異なるサブセットからの同一の文字列または重複した文字が 1 回だけカウントされることを保証します。 
7. セットに格納されているすべての一意の文字列の長さの合計を累積します。 
8. すべてのサブセットと順列が処理された後、最終的な合計を出力します。 

### なぜ効果があるのか

 すべての有効な文字列は、元の入力から位置のサブセットを選択し、選択した文字を並べ替えることに対応します。 サブセットの列挙により、あらゆる文字の選択が考慮されることが保証されますが、順列の生成により、すべての順序がマルチセットごとに 1 回だけ到達されることが保証されます。 このセットにより、複数のサブセット選択が文字の繰り返しにより同じ文字列になる場合でも、カウントされるのは 1 回のみであることが保証されます。 すべての有効な文字列が少なくとも 1 つのサブセット順列パスでカバーされており、文字数の考慮により無効な文字列が生成されないため、結果は完全で正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from itertools import combinations
from collections import Counter

def solve():
    s = input().strip()
    n = len(s)

    seen = set()

    # enumerate all non-empty subsets via bitmask
    for mask in range(1, 1 << n):
        chars = []
        for i in range(n):
            if mask & (1 << i):
                chars.append(s[i])

        chars.sort()

        # generate permutations of sorted multiset
        used = [False] * len(chars)

        def backtrack(path):
            if len(path) == len(chars):
                seen.add("".join(path))
                return

            for i in range(len(chars)):
                if used[i]:
                    continue
                if i > 0 and chars[i] == chars[i - 1] and not used[i - 1]:
                    continue
                used[i] = True
                path.append(chars[i])
                backtrack(path)
                path.pop()
                used[i] = False

        backtrack([])

    total = sum(len(x) for x in seen)
    print(total)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず入力文字列に対してビットマスクを使用してサブセットを列挙します。 n ≤ 8 であるため、これは安全であり、最大 255 のサブセットでさえ自明です。 

各サブセット内で、ソートされた文字のリストを作成します。 ソートは、順列生成で標準の重複スキップ ルールを適用できるため、重要です。2 つの同一の文字が存在する場合、最初の文字が現在の再帰パスですでに使用されている場合にのみ、2 番目の文字が使用されます。 これにより、同じ順列が複数回生成されることがなくなります。 

バックトラッキング関数は、選択されたマルチセットのすべての順列を構築します。 それぞれの完全なパスが Python セットに挿入されるため、さまざまなサブセット間でグローバルな一意性が保証されます。 

最後に、すべての一意の文字列の長さの合計を計算します。 これは、必要な出力に直接対応します。 

微妙な点は、重複スキップ条件が並べ替えに依存していることです。 ソートを行わないと、同一の文字が任意の順序で表示され、枝刈り条件が失敗し、出力が重複してしまいます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(2^n・n!) | Each subset generates up to n! permutations in the worst case |
 | スペース | O(S) | Storage of all unique strings in the set |

 The bound n ≤ 8 makes the worst-case 2^n · n! 十分に受け入れられます。 最大の場合でも、これは数十万回の操作未満にとどまり、一般的な制限内に問題なく収まります。

 ## 特殊なケース

 特殊なケースの 1 つは、すべての文字が同一である場合です。 入力「AAAA」の場合、多くの再帰パスは同じ文字列「A」または「AA」を生成しますが、このセットでは、それぞれ異なる文字列のインスタンスが 1 つだけカウントされることが保証されます。 このアルゴリズムはサブセットを構築しますが、サイズ k のすべてのサブセットは、k 回繰り返される「A」で構成される一意の文字列を 1 つだけ生成するため、最終的な合計は単純に 1 + 2 + 3 + 4 になります。 

もう 1 つの特殊なケースは、すべての文字が異なる場合です。 「ABC」では、重複した枝刈りは決してトリガーされないため、順列の生成は最大になります。 各サブセットは正確に k! に寄与します。 文字列であり、サブセット間でセットの衝突は発生しません。 

最後の微妙なケースは、「AAB」のようなインターリーブ構造を持つ重複重複です。 ソート順列枝刈り条件がないと、「AAB」と「ABA」が過剰生成されてしまいます。 サブセットごとにソートされた入力と、同じ文字が順番どおりに再利用されないように条件を組み合わせることで、グローバル セット レベルでの重複排除の前に、各順列が正確に 1 回生成されることが保証されます。
