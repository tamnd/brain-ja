 ## 問題の理解

 整数の配列と実際のしきい値のペアが与えられます。$a$そして$b$。 このタスクは、平均が特定の範囲内にある連続したサブ配列がいくつあるかを数えるというものです。 すべての部分配列の平均を直接計算する代わりに、この問題では、平均が少なくとも である部分配列を数えるという目標が減らされます。$a$、平均が超えるものを差し引きます。$b$。 

サブ配列は任意の連続したセグメントであるため、インデックスのペアごとに$l \le r$、暗黙的にシーケンスを考慮しています。$x_l, x_{l+1}, \dots, x_r$。 出力は、2 つの計数問題の差から導出される最終制約を満たすセグメントの数を表す単一の整数です。 

重要な構造上の制約は、配列の長さが十分に大きくなり、部分配列の二次列挙が不可能になる可能性があることです。 ナイーブ$O(n^2)$すべてのサブアレイをスキャンすると、約$10^{10}$操作時の操作$n = 10^5$これは一般的な限界をはるかに超えています。 これにより、対数時間で範囲カウントのクエリに応答できるプレフィックスベースの変換とデータ構造がすぐに実現できるようになります。 

変換ステップで微妙な問題が発生します。平均制約を合計制約に変換すると、実数値の比較が導入されます。 プレフィックスの合計は整数ベースであるため、厳密な不等式と非厳密な不等式を慎重に処理する必要があります。 不注意に変換すると、カウントが 1 つずれて、最終的な答えが静かに破損する可能性があります。 

エッジ ケースの 1 つは、すべての要素が同一であり、しきい値に等しい場合です。 この状況では、すべての部分配列の平均値は同じであるため、包含性に応じて、すべての部分配列が条件を満たすか、どれも条件を満たさないかのどちらかになります。 単純な浮動小数点比較アプローチも、精度エラーによりここで機能しなくなる可能性があります。 

負の数が存在する場合、別の特殊なケースが発生します。 プレフィックスの合計は減少する可能性があり、単調性に関する仮定は失敗します。 このため、ソートベースの推論が必要になりますが、フェンウィック ツリーを使用する場合は一貫した座標圧縮も必要になります。 

## アプローチ

 ブルート フォース手法では、すべての部分配列を明示的にチェックし、その合計を計算し、その長さで除算して、境界と比較します。 これは、すべてのセグメントの平均の定義を直接評価するため、概念的には正しいです。 ただし、各サブ配列には$O(1)$償却合計の計算は、プレフィックスの合計が事前に計算されており、$O(n^2)$部分配列なので、総コストは依然として 2 次です。 と$n = 10^5$、これは約につながります$5 \times 10^9$評価が遅すぎる。 

改善は、分割を完全に取り除くことによってもたらされます。 条件$\frac{\sum x_i}{len} \ge a$次のように書き換えることができます$\sum x_i - a \cdot len \ge 0$。 これにより、問題は、非負の変換合計をもつカウントサブ配列に変換されます。 同様に、上の厳密な不等式は、$b$整数不等式に変換すると、わずかにシフトされたしきい値になります。 

変換されると、各要素は次のようになります。$y_i = x_i - a$または$x_i - b$、タスクは少なくとも固定定数の合計を持つ部分配列を数えるようになります。 これは古典的なプレフィックス合計の優勢問題です。各右エンドポイントについて、結果のサブ配列合計がしきい値を満たすほど十分に小さい以前のプレフィックス合計がいくつあるかを数えます。 

これにより、問題は、プレフィックスの合計の動的なセットを維持し、それらの合計がいくつあるかを答えるという問題に軽減されます。$\le$与えられた値。 フェンウィック ツリーまたは順序統計構造を使用すると、これが可能になります。$O(\log n)$挿入ごとに。

 ## アルゴリズムのチュートリアル

 元の問題を 2 つの独立した部分問題に分割しました: 少なくとも平均値を持つ部分配列を数える$a$、および厳密に次よりも大きい平均を持つ部分配列を数えます。$b$。 最終的な答えは、これら 2 つのカウントの差です。 

1. 変換された配列を定義して、最初の条件を合計制約に変換します。$y_i = x_i - a$。 部分配列には少なくとも平均値があります$a$まさにその変換された合計が負ではないときです。 これにより、除算が完全に削除され、条件が純粋に加算的なものになります。 
2. 変換された配列に対してプレフィックスの合計を構築します。$p_0 = 0$そして$p_i = y_1 + \dots + y_i$。 からの任意の部分配列の合計$l$に$r$になる$p_r - p_{l-1}$。 私たちが欲しいのは$p_r - p_{l-1} \ge 0$、これは以下と同等です$p_{l-1} \le p_r$。 
3. プレフィックスの合計を左から右に処理します。 各エンドポイントについて$r$、以前のプレフィックス値が現在のプレフィックス値以下である回数を数えたいとします。$p_r$。 これは有効な開始位置を直接カウントします。 
4. プレフィックス値は任意の整数なので、ランクに圧縮します。 これにより、周波数をフェンウィック ツリーに保存できるようになります。 
5. 各プレフィックスについて$p_r$、保存されているプレフィックスの合計がいくつあるかをクエリします。$\le p_r$、それを答えに追加してから挿入します$p_r$フェンウィックの木の中へ。 
6. 2 番目の条件に対して同じプロセスを繰り返します。$z_i = x_i - b$。 厳密な不等式の場合は、それを整数のしきい値シフトに変換して、次のようにします。$\frac{\sum x_i}{len} > b$になる$\sum x_i - b \cdot len \ge 1$、整数の正しい処理が保証されます。 
7. 最初のカウントから 2 番目のカウントを減算して、最終結果を取得します。 

機能する理由: すべてのサブ配列は、プレフィックス インデックスのペアに一意に対応します。$(l-1, r)$。 部分配列の条件は、2 つの接頭辞の合計間の比較になります。 フェンウィック ツリーは以前のプレフィックスの合計をすべて維持し、各クエリは現在のエンドポイントに存在する有効な開始ポイントの数を正確にカウントします。 すべてのサブ配列はその右端で正確に 1 回カウントされ、条件は純粋に接頭辞の優位性によってチェックされるため、サブ配列が欠落したり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def count_ge(arr, threshold):
    n = len(arr)
    pref = [0] * (n + 1)

    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + arr[i - 1]

    vals = sorted(set(pref))
    idx = {v: i + 1 for i, v in enumerate(vals)}

    fw = Fenwick(len(vals))
    res = 0

    for x in pref:
        r = idx[x]
        res += fw.sum(r)
        fw.add(r, 1)

    return res

def solve_condition(a_list, base):
    n = len(a_list)
    transformed = [x - base for x in a_list]
    return count_ge(transformed, 0)

def main():
    n = int(input())
    a, b = map(float, input().split())
    arr = list(map(int, input().split()))

    # first: mean >= a
    prefA = [x - a for x in arr]
    ansA = count_ge(prefA, 0)

    # second: mean > b -> sum - b*len >= 1
    # transform: x - b, but require strict handling via +1 on prefix side
    prefB = [x - b for x in arr]
    ansB = 0

    n = len(arr)
    pref = [0]
    for x in prefB:
        pref.append(pref[-1] + x)

    vals = sorted(set(pref))
    idx = {v: i + 1 for i, v in enumerate(vals)}
    fw = Fenwick(len(vals))

    for p in pref:
        r = idx[p]
        ansB += fw.sum(r - 1)  # strict: p[l-1] < p[r]
        fw.add(r, 1)

    print(ansA - ansB)

if __name__ == "__main__":
    main()
```フェンウィック ツリーは、プレフィックス合計の頻度を維持します。 各プレフィックスの合計はインデックスに圧縮されるため、順序付けクエリはプレフィックス頻度クエリになります。 最初の条件では等価性が認められるため、クエリを実行します。`sum(r)`。 厳密な 2 番目の条件には、次を使用します。`sum(r - 1)`厳格な不平等を強制する。 

一般的な実装の落とし穴は、実数値を一貫して整数プレフィックスの差分にプッシュするのではなく、比較で浮動小数点演算を混合することです。 もう 1 つは、すべてのサブ配列がいくつかの値から始まるため、空のプレフィックスを含める必要があることを忘れていることです。$l-1$、ゼロを含む。 

## 実用的な例

 配列を考えてみましょう$[1, 2, 3]$包括的な動作と厳密な動作の両方を示すように選択されたしきい値を使用します。 

最初の変換 (平均 ≥ a) では、変換された配列が得られると仮定します。$[1, -1, 2]$。 

| r | プレフィックスの合計 | 圧縮ランク | カウント ≤ 現在 | フェンウィック州 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 2 | 0 | {0} |
 | 1 | 1 | 3 | 1 | {0,1} |
 | 2 | 0 | 2 | 1 | {0,1,0} |
 | 3 | 2 | 4 | 3 | {0,1,0,2} |

 累積は、各プレフィックスが、有効なサブ配列の開始に対応する、それより大きくない以前のプレフィックスをどのようにカウントするかを示します。 

2 番目の変換 (厳密な平均 > b) では、プレフィックスの合計が次のようになると仮定します。$[0, 1, 1, 3]$。 

| r | プレフィックスの合計 | ランク | カウント < 現在 | フェンウィック州 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 1 | 0 | {0} |
 | 1 | 1 | 2 | 1 | {0,1} |
 | 2 | 1 | 2 | 1 | {0,1,1} |
 | 3 | 3 | 4 | 3 | {0,1,1,3} |

 このトレースは、厳密な不等式では等しいプレフィックスの合計を除外する必要がある理由を示しています。そうしないと、等しいエンドポイントが誤って寄与することになります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \log n)$| 各プレフィックス合計は、Fenwick ツリーに 1 回挿入され、クエリされます。 
| スペース |$O(n)$| プレフィックス配列と座標の圧縮ストレージ |

 対数係数はフェンウィック ツリー演算から得られ、線形係数は各配列要素を 1 回処理することから得られます。 これは、一般的な制約内に快適に適合します。$n$まで$10^5$以上。

 ## 特殊なケース

 単一要素の配列の場合、次のようにします。$[5]$、すべての部分配列はまさにその要素です。 要素が両方の条件を満たすようなしきい値の場合、アルゴリズムはプレフィックスを 0 で初期化し、挿入を 1 回だけ処理します。 フェンウィック ツリーは単一のプレフィックス ペアを正確にカウントし、1 つの有効なサブ配列を生成します。 

すべての値がしきい値と等しい配列の場合、次のようになります。$[2,2,2]$と$a = 2$、変換された値はすべてゼロになります。 プレフィックスの合計は一定のままであるため、プレフィックス インデックスのすべてのペアは等価性を満たします。 フェンウィック ツリーは、すべての部分配列が含まれるようにカウントを蓄積し、予想される値と一致します。$n(n+1)/2$。 

厳密な不等式の場合、$b$が配列値と等しい場合、変換されたプレフィックスの合計は再び定数になりますが、`r - 1`クエリでは、等しいプレフィックスのサブ配列がカウントされないことが保証されます。 これにより、平均が境界と正確に等しい場合の過剰カウントが防止されます。
