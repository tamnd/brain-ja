 ## 解決策
 ## 問題の理解

 隣接する値のセグメントを繰り返しマージまたは「検証」することで構造を構築する、順列のようなプロセスが与えられます。 この問題では、プロセスを直接シミュレートするのではなく、与えられた数値の順序が、最終的にすべてを 1 から N までの 1 つの連続した有効な範囲に縮小するようなマージの有効なシーケンスの結果として解釈できるかどうかを尋ねます。 

タスクを再構成する便利な方法は、位置ではなく値の観点から連続する整数のグループを維持しながら、配列を左から右にスキャンすることを考えることです。 各要素は、最初はそれ自体のみからなる自明なセグメントを形成します。 より多くの要素を処理すると、値の範囲が正確に隣接している場合、つまり 1 つのセグメントが x で終了し、次のセグメントが x+1 で開始する、またはその逆の場合、一部の隣接するセグメントをマージできます。 最終的な目標は、すべての要素を 1 つの連続した数値区間 [1, N] にまとめることができるかどうかを判断することです。 

入力はサイズ N の単一の順列であり、これらのマージ ルールに基づいてこの順列を区間 [1, N] に完全に縮小できるかどうかを判断する必要があります。 出力は、これが可能かどうかを示す二者決定です。 

制約は非常に直接的な意味で重要です。 N は大きくなる可能性があるため、ネストされた方法で繰り返しスキャンまたはセグメントの隣接性をチェックするものは二次的な動作に劣化します。 現在のすべてのセグメントをスキャンして有効なカット ポイントの検出やマージを繰り返し試行する単純なアプローチでは、新しい要素ごとに現在の構造に対する一連の再計算がトリガーされる可能性があるため、O(N²) 動作が発生します。 

隣接関係がローカルに存在しない場合、微妙なエッジ ケースが発生します。 たとえば、順列 [2, 4, 1, 3] を考えてみましょう。 隣接する値のペアが早期にマージできるような形で隣り合って現れることはなく、構造がより大きな間隔に安定することはありません。 単純なアプローチでは、部分的な重複に基づいてマージをシミュレートしようとする可能性がありますが、この構成では有効な完全な間隔が形成されることはないため、正しい答えは NO です。 

一方、[1, 3, 4, 2] のような順列では、隣接関係がグローバルに明らかではない場合でも、有効なマージ シーケンスが可能になります。 重要なのは、マージが中間間隔で伝播し、最終的には完全な崩壊が可能になるということです。 

## アプローチ

 この強引なアイデアは、マージ プロセスを明示的にシミュレートすることです。 現在のセグメントのリストを維持し、各セグメントがそれに含まれる最小値と最大値を追跡します。 すべてのステップで、セグメント リストを繰り返しスキャンし、値の間隔が連続している 2 つの隣接するセグメントをマージします。 マージができなくなるまで続行します。 

これが機能するのは、プロセスの定義を直接反映しているためです。 ただし、マージごとにセグメント構造の完全な再スキャンがトリガーされる可能性があります。 最悪の場合、各要素によって直線的な数の比較が発生し、以前のセグメントを繰り返し再訪問した後でのみマージが行われる可能性があります。 これにより、二次複雑さが生じます。 

重要な観察は、このプロセスが複雑なグローバル構造の影響を受けないことです。 スイープ中に連続した値の間隔を形成できるかどうかのみを考慮します。 各要素は単位間隔 [x, x] に寄与します。唯一の意味のある操作は、隣接する間隔が数値的に連続している場合にそれらをマージすることです。 これは、間隔のスタックを維持し、可能な限り貪欲にマージできることを示唆しています。 この正しさは、間隔がマージ可能になると、将来の要素は既存の数値境界を拡張または接続するだけであるため、マージを遅らせても後で新しい可能性が生じることはないという事実から来ています。 

これにより、ローカル マージによる単一パスで問題が軽減されます。

## アルゴリズムのチュートリアル

 素の数値間隔のスタックを維持しながら、左から右へ順列を処理します。 

1. 順列内の要素 x ごとに、新しい間隔 [x, x] を作成し、スタックにプッシュします。 これは、新しい孤立した値を構造に導入することを表します。 
2. スタックに少なくとも 2 つの間隔が含まれている間に、上位 2 つの間隔をチェックします。 それらの値の範囲が数値的な意味で隣接している場合、つまり、下限間隔の最大値と上限間隔の最小値がどちらの順序でも 1 だけ異なる場合は、それらを両方にまたがる単一の間隔にマージします。 2 つの区間をそれらの和集合に置き換えます。 
3. スタックの最上位がその前のスタックと有効な連続間隔を形成し続ける限り、マージを続けます。 これにより、新たに生み出された統合の機会がすべて即座に実現されることが保証されます。 
4. すべての要素を処理した後、スタックがちょうど 1 つの間隔に折りたたまれているかどうかを確認します。 
5. 単一の間隔が正確に [1, N] の場合、YES を出力します。 それ以外の場合は NO を出力します。 

結合ルールはアルゴリズムの中核です。 これは、位置的な隣接性ではなく、数値的な隣接性のみが重要であるという事実をエンコードしています。 2 つの間隔が数値的に連続すると、それ以上の推論ではそれらを単一の連続したブロックと区別できなくなります。 

### なぜ効果があるのか

 不変条件は、すべてのステップで、スタックが処理されたプレフィックスの最大間隔への分割を表し、現在の情報ではこれ以上マージできないということです。 マージは数値的に隣接する間隔間でのみ発生し、それらは常にスタックによって即座に検出されるため、有効な最終構築ではこのパーティションを改良する必要があります。 

将来マージが可能である場合、それは 2 つの区間が最終的に値空間で隣接するようになるためであるに違いありません。 ただし、これは、以前のマージがすでにトリガーされている中間値を含めることによってのみ発生します。 これにより、マージの遅延によって新たな機会が生み出されることがなくなり、貪欲なマージが安全になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    st = []

    for x in a:
        st.append([x, x])

        while len(st) >= 2:
            l2, r2 = st[-1]
            l1, r1 = st[-2]

            if r1 + 1 == l2 or r2 + 1 == l1:
                st.pop()
                st.pop()
                st.append([min(l1, l2), max(r1, r2)])
            else:
                break

    if len(st) == 1 and st[0][0] == 1 and st[0][1] == n:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```実装では間隔のスタックが保持されます。 各要素はシングルトン間隔として開始され、while ループによって最大限のマージが強制されます。 間隔は挿入によって厳密に順序付けされない可能性があるため、重要な詳細は両方向の隣接性をチェックすることです。 最終チェックでは、値の範囲全体が隙間なくカバーされていることを確認します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、隣接関係が隣接関係ではなく推移的閉包によってのみ形成される場合です。 たとえば、[2, 4, 1, 3] では、初期段階では直接の連続ペアは存在しませんが、最終的なマージにより完全なカバレッジが作成されます。 スタックは、必要な近傍が表示されるまでマージを延期し、その後すべてを [1, 4] に正しく折りたたむことでこれを処理します。 

もう 1 つのエッジ ケースは、[3, 1, 4, 2] のように、要素が低い値と高い値の間で交互に配置される順列です。 スタックには複数の互いに素な間隔が一時的に保持されますが、接続する値が表示されるとすぐに、それらはカスケードでマージされます。 このアルゴリズムにより、中間の断片化によって最終的な統合が妨げられないことが保証されます。
