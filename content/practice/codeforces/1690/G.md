 ## 解決策
 ## 問題の理解

 各キャリッジには独自の最高速度があります。 すべての台車が動き始めると、その前の台車よりも早く移動することはできないため、実際の速度は左から見た最小値になります。 

最高速度が```
a = [10, 13, 5, 2, 6]
```最終的な速度は```
[10, 10, 5, 2, 2]
```なぜなら、どの車両もその前にある最も遅い車両によって覆われているからです。 

列車は、最終速度が等しい最大の連続セグメントです。 上の例では、電車は次のようになります。```
[10,10] [5] [2,2]
```したがって、答えは 3 です。 

その後、更新情報を受け取ります。 更新により、配列の要素が 1 つ減少します。 更新のたびに、新しい列車の数を報告する必要があります。 

重要な観察は、キャリッジの最終速度です。`i`は```
min(a[1], a[2], ..., a[i])
```新しいトレインは、このプレフィックスの最小値が減少したときに正確に開始されます。 

これは、トレインの数が、新しいプレフィックスの最小値を作成する位置の数に等しいことを意味します。 

制約が十分に大きいため、更新のたびにすべてのプレフィックス最小値を再計算することは不可能です。 Across all test cases, both`n`そして`m`合計して`10^5`、したがって、何か必要があります`O((n + m) log n)`。 各更新後にアレイ全体をスキャンするソリューションは、約`10^10`最悪の場合の運用。 

微妙な点は、更新では値が減少するだけであるということです。 何も増えることはありません。 この単調性により、効率的な動的構造が可能になります。 

考慮する：```
a = [5, 8, 6]
```列車の出発位置は次のとおりです。```
1 (value 5)
```今は減ります`a[2]`に`4`。```
a = [5, 4, 6]
```位置 2 は、以前のどの値よりも小さいため、新しいトレインの開始位置になります。 

インデックス 2 の情報のみを更新する不注意な解決策では、右側の列車の境界が消える可能性があるという事実を見落とすことになります。 

もう 1 つの注意が必要なケースは等価性です。```
a = [5, 5, 5]
```電車は1本しかありません。 

位置は、その値が以前のすべてのプレフィックス最小値より**厳密に小さい**場合にのみ、新しいトレインを作成します。 使用する`<=`の代わりに`<`列車が 3 つと誤ってカウントされてしまいます。 

## アプローチ

 ブルート フォース ソリューションは定義に直接従います。 

更新するたびに、プレフィックス最小配列を再構築します。 プレフィックスの最小値が減少するたびに、新しいトレインが開始されます。 これらの減少を数えることで答えが得られます。 

各キャリッジの最終速度は正確にそのプレフィックスの最小値であるため、これは正しいです。 残念ながら、プレフィックスの再構築には最小限のコストがかかります`O(n)`クエリごとに、`O(nm)`全体的に仕事をする。 両方の値が存在する場合`10^5`、これでは遅すぎます。 

重要な観察は、実際にはすべての車両を気にしているわけではないということです。 新しい接頭辞の最小値を作成する位置のみを考慮します。 

このような役職を**リーダー**と呼ぶことにします。 

例えば：```
a = [10, 13, 5, 2, 6]
```リーダーは次のとおりです。```
1 (10)
3 (5)
4 (2)
```リーダーの数はまさに列車の数です。 

次に、減少後に何が起こるかを見てみましょう。 

位置を仮定します`k`小さくなります。 起こり得ることは 2 つだけです。 

初め、`k`以前のリーダーの値を下回った場合、新しいリーダーになる可能性があります。 

2回目、1回`k`がリーダーになる (または既存のリーダーがさらに小さくなる) と、その右側の一部のリーダーは、新しいプレフィックスの最小値が早く到達するため、リーダーでなくなる可能性があります。 

リーダーには当然のことながら立場による序列があり、その価値は厳密に下がっていく。 これにより、より小さい値を持つリーダーに遭遇するまで右に歩くことで、影響を受けるリーダーを削除することができます。 

私たちは現在のリーダーのセットを動的に維持します。 順序付けられた構造により、前後のリーダーを見つけることができます。`O(log n)`時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n) | 遅すぎる |
 | 最適 | O((n + m) log n) 償却 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. リーダーの初期セットを構築します。 

これまでに確認された最小値を維持しながら、左から右にスキャンします。 位置`i`リーダーになるなら`a[i]`厳密にその最小値より小さいです。 
2. リーダーを順序付けられた構造に保管します。 

ポジションの直前または直後のリーダーを素早く見つける必要があります。 リーダー位置上のフェンウィック ツリーがこの機能を提供します。 
3. アップデートを処理する`(k, d)`。 

減少`a[k]`による`d`。 
4. 前に前のリーダーを見つけます`k`。 

前のリーダーがいない場合は、`k = 1`事実上、左からの制限はありません。 
5. かどうかを確認します。`k`リーダーであるべきだ。 

位置`k`まさにそのときのリーダーです```
a[k] < value_of_previous_leader
```または最初の位置の場合。 
6. もし`k`がリーダーになり、まだリーダーになっていない場合は、リーダー構造に挿入します。 
7. もし`k`が現在リーダーである場合は、その右側にある無効なリーダーを削除します。 

次のリーダーを繰り返し見てください。`k`。 

その値が以上である間、`a[k]`、新しいプレフィックスの最小値を作成できなくなるため、削除します。 

より小さい値のリーダーに到達するとすぐに停止します。 
8. 現在のリーダーの数は、このアップデート後の答えです。 

### なぜ効果があるのか

 リーダーは、まさにプレフィックスの最小値が減少するポジションです。 列車の境界はプレフィックスの最小値が減少するときに正確に発生するため、リーダーと列車は同じオブジェクトです。 

リーダーのセットは常に厳密に減少する値を持ちます。 位置に値がある場合`k`減少、で始まるプレフィックス最小値のみ`k`変えることができる。 前の位置`k`影響を受けません。 

もし`a[k]`前のリーダー値よりも小さくなり、`k`新しいリーダーにならなければなりません。 値が小さくない以降のリーダー`a[k]`プレフィックスの最小値の減少を表すことができなくなるため、削除する必要があります。 より小さい値を持つ最初の後のリーダーは有効なままであり、リーダー値は厳密に減少しているため、その後のすべてのリーダーも有効なままです。 

したがって、維持されるリーダー セットは常に正確にプレフィックス最小位置のセットであるため、そのサイズは常にトレインの数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, idx, delta):
        n = self.n
        bit = self.bit
        while idx <= n:
            bit[idx] += delta
            idx += idx & -idx

    def sum(self, idx):
        bit = self.bit
        res = 0
        while idx > 0:
            res += bit[idx]
            idx -= idx & -idx
        return res

    def kth(self, k):
        idx = 0
        bitmask = 1 << (self.n.bit_length() - 1)

        while bitmask:
            nxt = idx + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                idx = nxt
            bitmask >>= 1

        return idx + 1

def solve():
    t = int(input())

    for _ in range(t):
        line = input()
        while line.strip() == "":
            line = input()

        n, m = map(int, line.split())
        a = [0] + list(map(int, input().split()))

        fw = Fenwick(n)
        leader = [False] * (n + 1)

        cur_min = 10**18
        trains = 0

        for i in range(1, n + 1):
            if a[i] < cur_min:
                cur_min = a[i]
                leader[i] = True
                fw.add(i, 1)
                trains += 1

        def next_leader(pos):
            cnt = fw.sum(pos)
            if cnt >= trains:
                return 0
            return fw.kth(cnt + 1)

        ans = []

        for _ in range(m):
            k, d = map(int, input().split())
            a[k] -= d

            cnt_before = fw.sum(k - 1)

            if cnt_before == 0:
                should_be_leader = True
            else:
                prev_leader = fw.kth(cnt_before)
                should_be_leader = a[k] < a[prev_leader]

            if should_be_leader and not leader[k]:
                leader[k] = True
                fw.add(k, 1)
                trains += 1

            if leader[k]:
                nxt = next_leader(k)

                while nxt and a[nxt] >= a[k]:
                    leader[nxt] = False
                    fw.add(nxt, -1)
                    trains -= 1
                    nxt = next_leader(k)

            ans.append(str(trains))

        print(" ".join(ans))

if __name__ == "__main__":
    solve()
```フェンウィックの木には`1`あらゆるリーダーの立場で、`0`他の場所で。 これにより、バランスのとれた BST を保存せずに、リーダーの間で前任者と後任者を見つけることができます。 

の`kth()`このメソッドは、標準的なフェンウィック順序統計演算です。 ランクを指定すると、そのリーダーの位置を返します。 

更新ロジックはその証拠を反映しています。 まず、次のことを決定します。`k`リーダーになります。 そうすると、`k`がリーダーである場合、その右側にある支配的なリーダーを繰り返し削除します。 

よくある間違いは、`<=`ポジションがリーダーになるかどうかを決定するとき。 値が等しい場合は新しいプレフィックスの最小値は作成されないため、条件は厳密に次のようにする必要があります。`<`。 

もう 1 つの簡単な間違いは、リーダーを次のように削除することです。`>`の代わりに`>=`。 2 人のリーダーの値が等しい場合、後者のリーダーは真のプレフィックス最小位置ではないため、削除する必要があります。
