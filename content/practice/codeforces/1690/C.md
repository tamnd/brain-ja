 ## 解決策
 ## 問題の理解

 2 つの増加する配列が与えられます。 

配列`s`各タスクの到着時間が含まれます。 タスク`i`時間に応じて利用可能になります`s[i]`。 

配列`f`各タスクの完了時間が含まれます。 タスク`i`時間通りに終わる`f[i]`。 

Polycarp はタスクを FIFO 順序で処理します。 タスクが到着したときに彼がビジーであれば、タスクはキュー内で待機します。 タスクが終了し、キューが空でない場合は、待機中の次のタスクをすぐに開始します。 キューが空の場合は、別のタスクが到着するまで待ちます。 

不明な値は実際の実行時間です。`d[i]`タスクの。 すべての期間を再構築する必要があります。 

すべてのテスト ケースにわたるタスクの合計数は最大で次のとおりです。`2 · 10^5`。 これは、線形または線形に近い解決策が必要であることを直ちに示唆しています。 二次関数に必要なものはおおよそ`4 · 10^10`制限時間を大幅に超えた最悪の場合の作戦。 

難しいのは、タスクが到着しても必ずしも開始されるわけではないということです。 前のタスクがまだ処理中の場合は、キュー内で待機する必要があります。 を前提とした素朴な実装`duration = finish - arrival`間違っていることが多いでしょう。 

考慮する：```
s = [0, 3]
f = [10, 12]
```2 番目のタスクが時間通りに到着します`3`、ただし、最初のタスクは時間にのみ終了します`10`。 2 番目のタスクは実際に 時刻に開始されます`10`、したがって、その期間は```
12 - 10 = 2
```ない```
12 - 3 = 9
```もう 1 つの簡単な間違いは、プロセッサがアイドル状態になる可能性があることを忘れることです。 

例：```
s = [0, 10]
f = [2, 15]
```最初のタスクは時間どおりに終了します`2`。 何も待っていないので、Polycarp は時間が来るまで何もせずに座っています`10`。 2 番目のタスクは到着時にすぐに開始され、継続時間があります。```
15 - 10 = 5
```前回の終了時刻を無条件に使用すると、誤って次の結果が生成されます。```
15 - 2 = 13
```ソリューションでは、これら 2 つの状況を正確に区別する必要があります。 

## アプローチ

 直接シミュレーションが可能です。 

タスクごとに、いつ開始するかを明示的に決定できます。 開始時刻は、その到着時刻または前のタスクが終了した瞬間のいずれか遅い方です。 開始時間が判明すると、期間は単に完了時間から開始時間を引いたものになります。 

タスクは厳密に順序どおりに処理されるため、このシミュレーションはすでに効率的です。 実際のキュー構造や検索操作はまったく必要ありません。 タスクに必要な唯一の情報`i`タスクのとき`i - 1`終了した。 

重要な観察点は、タスクの開始時刻です。`i`は 2 つの値によって完全に決定されます。```
start[i] = max(s[i], f[i-1])
```のために`i > 0`。 

新しいタスクが到着する前に前のタスクが終了した場合、Polycarp は待機して次の時点から開始します。`s[i]`。 

新しいタスクが到着した後に前のタスクが終了した場合、タスクはキュー内で待機しており、次の時点ですぐに開始されます。`f[i-1]`。 

開始時間が分かりましたら、```
d[i] = f[i] - start[i]
```これにより、単純な線形スキャンが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 明示的なキュー追跡を使用したブルート フォース シミュレーション | O(n) | O(n) | 承認済み |
 | 最適な直接再構成 | O(n) | O(1) おまけ | 承認済み |

 どちらも線形ですが、2 番目のアプローチはキューの状態を維持する代わりに開始時間を直接導出するため、よりクリーンです。 

## アルゴリズムのチュートリアル

 1.読む`n`、到着配列`s`、および補完配列`f`。 
2. 最初のタスクは、到着するとすぐに開始されます。```
start = s[0]
d[0] = f[0] - s[0]
```3. あらゆるタスクに対して`i > 0`、実際の開始時間を計算します。```
start = max(s[i], f[i-1])
```タスクの前にプロセッサがアイドル状態だった場合`i`到着しました、タスクは次から始まります`s[i]`。 それ以外の場合はキュー内で待機しており、前の完了時刻に開始されます。 
4. 期間を計算します。```
d[i] = f[i] - start
```5. すべての継続時間を出力します。 

### なぜ効果があるのか

 完了時間は厳密に増加しており、タスクは到着したのと同じ順序で完了します。 そのため、タスク`i`タスクの前に開始できません`i - 1`終わります。 

There are only two possibilities.

 タスクの場合`i`タスクの後に到着する`i - 1`はすでに終了しており、Polycarp はアイドル状態であり、すぐに開始されます。`s[i]`。 

タスクの場合`i`タスクの前に到着する`i - 1`終了したらキューで待機し、タスクが開始されると正確に開始します`i - 1`完了、つまり`f[i-1]`。 

したがって、開始時間は常に```
max(s[i], f[i-1])
```期間は完了時間からこの開始時間を引いたものになります。 すべてのタスクの開始時間が正確に再構築されるため、すべての期間も正確に再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    s = list(map(int, input().split()))
    f = list(map(int, input().split()))

    ans = [0] * n

    ans[0] = f[0] - s[0]

    for i in range(1, n):
        start = max(s[i], f[i - 1])
        ans[i] = f[i] - start

    print(*ans)
```最初のタスクは、以前の完了時刻がないため、個別に処理されます。 

以降のすべてのタスクについて、唯一の微妙な点は、開始時刻を正しく計算することです。 使用する`max(s[i], f[i - 1])`キューで待機している場合と、到着後すぐに開始している場合の両方の考えられる状況をキャプチャします。 

すべての値は Python 整数内に快適に収まります。 最大のタイムスタンプは`10^9`なので、オーバーフローは心配ありません。 

実装では、回答配列のみを保存し、タスクを 1 回実行します。 

## 実用的な例

 ### 例 1

 入力:```

f = [2, 10, 11]
```| 私 | s[i] | f[i-1] | 開始 | f[i] | 期間 |

### 例 2

 入力:```

f = [11, 16]
```| 私 | s[i] | f[i-1] | 開始 | f[i] | 期間 |

 | 0 | 10 | - | 10 | 11 | 1 |

 出力：```

```時間通りに最初のタスクを終えた後`11`、ポリカルプは時が来るまで待ちます`15`。 2 番目のタスクは到着するとすぐに開始されます。 

この例では、プロセッサがアイドル状態の場合を例に説明します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        s = list(map(int, input().split()))
        f = list(map(int, input().split()))

        ans = [0] * n
        ans[0] = f[0] - s[0]

        for i in range(1, n):
            ans[i] = f[i] - max(s[i], f[i - 1])

        out.append(" ".join(map(str, ans)))

    return "\n".join(out)
