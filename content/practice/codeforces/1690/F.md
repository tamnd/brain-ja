 ## 解決策
 ## 問題の理解

 文字列が与えられています`s`長さの`n`そして順列`p`からの整数のうち`1`に`n`。 それぞれの順列`p`並べ替え操作を定義します。1 回適用した後、位置の文字が`i`新しい文字列の位置に移動します`p[i]`。 私たちの仕事は、文字列が元の形式に戻るまでにこの操作を何回適用する必要があるかを決定することです。 

制約が教えてくれるのは`n`テスト ケースの数は最大 200 まで、テスト ケースの数は最大 5000 まで可能です。`n`文字の移動の場合、少数の操作の単純なシミュレーションは機能するかもしれませんが、文字列を元の状態に戻すために必要な操作の数は非常に多くなる可能性があります。 したがって、特にサイクル長の最小公倍数 (LCM) が急速に増大する可能性があるため、各操作の総当りシミュレーションは遅すぎます。 

明らかではないエッジケースには、次のような順列の下ですでに不変である文字列が含まれます。`s = "aaaa"`そして`p = [1, 2, 3, 4]`。 ここで、順列によって文字が移動しても、文字列は変化せず、答えは 1 になります。もう 1 つの微妙な点は、サイクルの中に繰り返し文字が含まれる場合です。 サイクルを復元するための操作の数は、必ずしもその長さではなく、そのサイクルに沿った文字列の最小期間になります。 

## アプローチ

 ブルート フォース アプローチでは、操作を段階的にシミュレートします。繰り返し適用します。`p`に`s`文字列が元の文字列と一致するまで操作をカウントします。 概念的には単純で正しいですが、このアプローチは非常に時間がかかる可能性があります。 考慮する`n = 200`そして`p`長さ 200 の単一サイクルを形成します。 LCM は非常に大きくなり、100 万を超える可能性があります。 5000 のテスト ケースに対してこれだけの数の文字列操作を実行することは不可能です。 

重要な洞察は、順列が互いに素なサイクルに分解されることを観察することで得られます。 順列の各サイクルは独立して動作します。 文字の各サイクルが元の順序に戻ると、文字列は元の状態に戻ります。 サイクルの場合、必要な操作の数は、サイクルをたどることによって形成される部分文字列の最小期間です。 文字列の操作の全体数は、これらのサイクル固有の期間の LCM です。 

順列をサイクルに分割し、各サイクルの最小期間を計算することで、潜在的に数十億の演算をシミュレートすることから、効率的な少数の期間と最小公倍数を計算することに問題を軽減します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * L) ここで、L はサイクル LCM | O(n) | 大きい L には遅すぎる |
 | 最適 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.変換から始めます`p`1 ベースから 0 ベースのインデックス付けにより、配列へのアクセスが容易になります。 
2. を初期化します。`visited`長さの配列`n`どのポジションがすでに処理されているかを追跡します。 
3. 各位置を反復処理します。`i`文字列の中で。 もし`i`すでに訪問されている場合はスキップしてください。 
4. 訪問していない場合は、次から始まる順列サイクルに従います。`i`。 サイクルに沿ったすべての文字を部分文字列に収集し、その位置を訪問済みとしてマークします。 
5. この部分文字列の最小期間を計算します。 素朴な方法は、サイクル長のすべての約数をテストすることです`l`そして、その長さの部分文字列を繰り返すと完全なサイクルが再構築されるかどうかを確認します。 最初の有効な約数はサイクルの期間です。 
6. すべてのサイクル期間の LCM を追跡します。 この LCM は、文字列全体が元の構成に戻るのに必要な操作の数を表します。 
7. すべてのサイクルを処理した後、最終的な LCM を出力します。 

なぜ機能するのか: 各サイクルは順列のもとで独立して進化します。 最小期間は、そのサイクルを繰り返すために必要な順列の適用の回数を捉えます。 サイクルは独立しているため、すべてのサイクルが同時に繰り返されるときに全体的な繰り返しが発生します。これは、まさに個々の期間の最小公倍数です。 これにより正確さが保証されます。 

## Python ソリューション```python
import sys
from math import gcd
input = sys.stdin.readline

def lcm(a, b):
    return a * b // gcd(a, b)

def minimal_period(s):
    n = len(s)
    for k in range(1, n+1):
        if n % k == 0:
            if all(s[i] == s[i % k] for i in range(n)):
                return k
    return n

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    p = list(map(lambda x: int(x)-1, input().split()))
    visited = [False] * n
    answer = 1
    for i in range(n):
        if visited[i]:
            continue
        cycle = []
        x = i
        while not visited[x]:
            visited[x] = True
            cycle.append(s[x])
            x = p[x]
        answer = lcm(answer, minimal_period(cycle))
    print(answer)
```このソリューションでは、まず入力を読み取り、処理を容易にするために順列インデックスを 0 ベースに変換します。 次に、同じサイクルが 2 回処理されることを避けるために、訪問したインデックスを追跡します。 の`minimal_period`この関数は、サイクル長の各約数をテストして、サイクルを繰り返すために必要な操作の数を決定します。 サイクル期間の LCM を使用すると、文字列全体が初期状態に戻ります。 

## 実用的な例

 ### サンプル入力 1```

```| 私 | サイクル位置 | サイクル文字列 | 最小期間 |
 | --- | --- | --- | --- |
 | 0 | 0→2→4→0 | a b a | 1 |
 | 1 | 1→3→1 | b a | 2 |

 期間の LCM: LCM(1,2) = 2。ただし、サイクル文字列以降`aba`1 文字ごとに繰り返します。答えは 1 です。これにより、文字が繰り返されるサイクルの有効期間が短くなる可能性があることが確認されます。 

### サンプル入力 2```
s = "ababa", p = [2,1,4,5,3]
```サイクル分解：0→1→0、2→4→3→2

 サイクル文字列: "ab"、"aba"

 最小期間: 2、3

 LCM(2,3) = 6、サンプル出力と一致します。 

これらのトレースは、アルゴリズムが些細な繰り返しと複雑な複数サイクルの置換の両方を正しく処理していることを示しています。

 ## 特殊なケース

 のような文字列の場合`s = "aaaa"`順列あり`p = [4,3,2,1]`、アルゴリズムは 1 つのサイクルを構築します: 位置 0→3→0、1→2→1。 どちらのサイクルでも文字列が生成されます`"aa"`。 最低期間`"aa"`は 1、LCM(1,1) = 1 です。アルゴリズムはサイクル長 2 の代わりに 1 を正しく返し、サイクルで繰り返される文字を処理します。 

単一文字列の場合`s = "x"`、サイクルは自明です (0→0)。 最小期間は 1 で、1 サイクルにわたる LCM は 1 です。アルゴリズムは正しく 1 を出力します。 

この社説では、単純なシミュレーションから原則に基づいたサイクルベースの分析に移行し、最小期間と最小公倍数を計算して最初の繰り返しを効率的に決定する方法を示します。
