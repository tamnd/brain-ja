 ## 解決策
 ## 問題の理解

 負でない整数の 2 つの配列が与えられています。`a`そして`b`、両方の長さ`n`。 許可される操作は、次のすべての正の要素を同時にデクリメントすることです。`a`1つずつ。 課題は、変換可能かどうかを判断することです。`a`の中へ`b`この操作はゼロを含む任意の回数使用できます。 

入力には複数のテスト ケースがあり、`n`まで行くことができます`5 * 10^4`テストケースごとの合計`n`すべてのテストケースにわたって以下を超えない`2 * 10^5`。 各デクリメント操作はすべての非ゼロ要素に同時に影響を与えるため、デクリメントのブルートフォース シミュレーションは、`a`一致するまで`b`最悪の場合、特に値が次の場合には遅すぎます。`a`到達できる`10^9`。 

明らかではないエッジケースには、次のような位置が含まれます。`b[i]`ゼロですが、`a[i]`はゼロではありません。 これらは、最小の減分数を次のように強制します。`a[i]`。 もう 1 つの注意が必要な状況は、1 つの要素が`b`内の対応する要素よりも大きいです`a`; 増加することはできず、減少することしかできないため、これは不可能です。 例えば、`a = [1, 2]`そして`b = [0, 3]`不可能だから`b[2] > a[2]`。 

## アプローチ

 単純なアプローチでは、操作を段階的にシミュレートします。 それぞれの正の要素を繰り返しデクリメントします。`a`最終的に一致するかどうかを確認します`b`。 これは原理的には正しいですが、非効率的です。最悪の場合、`a = [10^9, 10^9, ..., 10^9]`までパフォーマンスします。`10^9`単一のテスト ケースに対して繰り返しを行うことは不可能です。 

重要な点は、演算が均一であることです。つまり、すべての非ゼロ要素が`a`decreases by exactly one each time. したがって、各要素に必要な操作の数は`i`は`a[i] - b[i]`もし`b[i] <= a[i]`、そしてそれは不可能です`b[i] > a[i]`。 各操作ではすべての正の要素が同時にデクリメントされるため、変換が成功するには、ゼロ以外の差がすべて等しい必要があります。 ただし、次のような要素は無視できます。`b[i]`はゼロです。これは、操作の最大数を制限するだけであり、他の要素との同等性を強制するものではないためです。 

したがって、各位置に必要なデクリメント数を計算します。`b[i] > 0`、すべてが平等であることを保証します。 いずれかの要素がこの最大値を超えるデクリメントを必要とする場合、または`b[i] > a[i]`どこにいても変身は不可能です。 それ以外の場合は可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(最大(a) * n) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`max_diff`ゼロに。 これにより、変換に必要なデクリメントの数が追跡されます。`a`の中へ`b`。 
2. 各インデックスを反復処理します。`i`から`0`に`n - 1`。 もし`b[i] > a[i]`、要素を増やすことができないため、すぐに「NO」を返します。 
3. それぞれについて`i`どこ`b[i] > 0`、差を計算します`a[i] - b[i]`。 アップデート`max_diff`この差が現在よりも大きい場合`max_diff`。 
4. すべての要素を再度繰り返します。 それぞれについて`i`どこ`b[i] > 0`、どうかを確認してください`a[i] - b[i]`等しい`max_diff`。 そうでない場合は、必要な減分に一貫性がないため、「NO」を返します。 
5. 要素の場合、`b[i] = 0`、それを確認してください`a[i] - max_diff >= 0`。 もし`a[i] - max_diff < 0`、ゼロ未満に減分することになるため、「NO」を返します。 
6. すべてのチェックに合格した場合は、「YES」を返します。 

機能する理由: この操作により、すべてのポジティブな要素が均一に削減されます。 最も多くのデクリメントを必要とする要素によって、必要な操作の数が決まります。 他のすべての正の要素は、まさにこの減分数でターゲット値に到達できる必要があります。 要素を含む`b[i] = 0`操作の最大数を制限するだけです。操作はゼロを下回ることはできないためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        max_diff = 0
        for i in range(n):
            if b[i] > a[i]:
                print("NO")
                break
            if b[i] > 0:
                max_diff = max(max_diff, a[i] - b[i])
        else:
            for i in range(n):
                if b[i] > 0 and a[i] - b[i] != max_diff:
                    print("NO")
                    break
                if b[i] == 0 and a[i] - max_diff < 0:
                    print("NO")
                    break
            else:
                print("YES")

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、ゼロではない要素に必要なデクリメントの最大数を計算します。`b`。 次に、ゼロ以外のすべての要素の一貫性を検証し、ゼロ要素がゼロ未満にデクリメントされないことを保証します。 の使用`else`の条項`for`ループは、ブレークにフラグの使用を避けるための巧妙な方法です。
