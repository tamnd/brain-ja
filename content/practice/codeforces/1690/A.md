 ## 解決策
 ## 問題の理解

 いくつかの同一の構成要素が与えられ、それらを表彰台を表す 3 つのスタックに分割する必要があります。 各スタックは、3 位、2 位、1 位のランクに対応します。 主な制約は、すべてのスタックに少なくとも 1 つのブロックが含まれている必要があり、その高さは厳密に 3 番目 < 2 番目 < 1 番目の順序で増加する必要があることです。 

ブロックを分割するすべての有効な方法の中で、最も高いスタック (最初の場所) をできるだけ小さくしながら、すべてのブロックを 1 回だけ使用する 1 つの配置を構築することが求められます。 最適な構成が複数存在する場合は、どれを選択しても問題ありません。 

制約の構造は十分に厳しいため、合計が n になる正の整数のトリプルをすべて単純に検索すると、テスト ケースごとに境界線が大きすぎます。 n は最大 100000 で、テスト ケースは最大 10000 個あるため、テストごとに O(1) または O(log n) を超えるソリューションは失敗します。 これは、答えが反復によって構築されるのではなく、直接式から導出される必要があることを直ちに示唆しています。 

微妙な点は、条件により厳密な順序付けが強制されるため、最小スタックが n に対して大きすぎることはできないことです。 たとえば、最初のスタックを非常に小さく、たとえば 4 にしようとしても、残りの 7 ブロックは依然として 2 つの厳密に小さい正の部分に分割する必要があり、それは不可能になる可能性があります。 これにより、最大高さの隠された下限が作成されます。 

よくある間違いは、厳密な不等式が依然として成り立つことを確認せずに、1、2、3 のような小さな値を貪欲に割り当て、残りを最大の山にダンプすることです。 たとえば、n = 6 の場合、(1, 4, 1) を選択すると、最小スタックと 3 番目のスタックのサイズが等しいため、厳密な順序付け条件が破られます。 

## アプローチ

 ブルートフォース手法では、h3 + h2 + h1 = n となるすべてのトリプル (h3、h2、h1) を試し、h3 < h2 < h1 かどうかを確認します。 これには、h3 を 1 から n まで、h2 を h3 + 1 から n まで反復して、h1 を導出する必要があります。 枝刈りを行ったとしても、組み合わせの数はテスト ケースあたり n² のオーダーであり、制約を考慮すると遅すぎます。 

重要な洞察は、視点を逆転させることです。 有効なトリプルを検索する代わりに、考えられる最小の最大高さ h1 がいくらになるかを尋ねます。 h1 を固定する場合、それを最小限に抑えるために、h1 よりも下に留まりながら、残りの h2 と h3 をできるだけ大きくパックする必要があります。 固定 h1 の最適なパッキングは、値が厳密な不等式 (h2 = h1 - 1 および h3 = h1 - 2) によって許容される限り近い場合に行われます。この配置では、正確に 3h1 - 3 ブロックが使用されます。 

これは直接的な実現可能条件を与えます: 3h1 - 3 ≤ n が必要です。 これから、すべてのブロックを収容できる最小の h1 を導き出します。 h1 が固定されると、残りのブロックは厳密な順序を維持する方法で分散され、最適な構造がほぼ連続したトリプルとして自然に現れます。

 ## アルゴリズムのチュートリアル

 1. 有効な厳密なトリプルを許容できる h1 の最小値を計算することから始めます。 固定 h1 の最適なパッキングは h1、h1-1、h1-2 であるため、この合計が n に達するか超えるかどうかを確認します。 
2. 不等式 3h1 - 3 ≥ n を解きます。 これにより、h1 の下限が決まります。 この条件を満たす最小の整数として h1 を採用します。 
3. h1 が決定されたら、厳密な不等式を維持しながら、それにできるだけ近い h2 と h3 を割り当てます。つまり、h2 = h1 - 1 および h3 = n - h1 - h2 を意味します。 
4. 構築上必要に応じて h3 を調整します。h1 を最小限に固定したため、残りの値は常に 1 ≤ h3 < h2 を自動的に満たします。 
5. 問題に応じて (h2、h1、h3) をこの順序で出力します。

重要な考え方は、h1 が最小化されると、最適解の構造が固定化されるということです。 合計の制約や厳密な順序付けを破ることなく、値を任意に再配置する自由は残されていません。 

### なぜ効果があるのか

 最適な構成では、厳密な不等式を尊重しながら、h2 と h3 を常に可能な限り高くします。 h1 が減少すると、有効なトリプルの最大可能総和、具体的には 3h1 - 3 が強制的に減少します。正確に n ブロックをカバーする必要があるため、実現可能な最小の h1 はこの境界によって一意に決定されます。 h1 が固定されると、残りの値は、すべてのブロックを消費しながら厳密な順序を維持する唯一の構造に強制的に組み込まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        # minimal h1 such that h1 + (h1-1) + (h1-2) >= n
        h1 = (n + 2) // 3 + 1

        # adjust if necessary to ensure feasibility
        while h1 + (h1 - 1) + (h1 - 2) < n:
            h1 += 1

        h2 = h1 - 1
        h3 = n - h1 - h2

        print(h2, h1, h3)

if __name__ == "__main__":
    solve()
```この実装は、可能な限り最小の最大スタック高さを選択し、残りのブロックを分散するというアイデアを直接エンコードしています。 h1 の計算は、可能な限り密なパッキングを実現するための実現可能性の不等式を解くことから得られます。 h2 を h1 - 1 として構築すると、厳密な順序が先頭で保持され、h3 は合計制約によって強制されます。 

微妙な点は、h3 が独立して選択されるのではなく、派生されることです。 これにより、残ったブロックを手動で配布しようとしたときによく発生する off-by-one エラーが回避されます。 

## 実用的な例

 ### 例 1: n = 11

 h1 + (h1 - 1) + (h1 - 2) ≥ 11 となる最小値として h1 を計算します。 

| ステップ | h1 | h2 | h3 | 合計 |
 | --- | --- | --- | --- | --- |
 | 開始 | 3 | - | - | - |
 | チェック | 3 | 3 | 1 | 7 |
 | 増加 | 4 | 3 | 2 | 9 |
 | 増加 | 5 | 4 | 2 | 11 |

 最終出力は (4, 5, 2) です。 これは、h1 = 5 に達すると、残りの値が自然に厳密な減少シーケンスを形成することを確認します。 

### 例 2: n = 6

 | ステップ | h1 | h2 | h3 | 合計 |
 | --- | --- | --- | --- | --- |
 | 開始 | 2 | - | - | - |
 | チェック | 2 | 2 | 0 | 無効 |
 | 増加 | 3 | 2 | 1 | 6 |

 最終出力は (2, 3, 1) です。 これは、h1 のより小さな選択は、3 つの正の厳密に増加するパイルに対応できないため、失敗することを示しています。 

これらの例は、構造が完全に可能な限り厳密なトリプルを適合させる実現可能性によって推進されていることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(sys.stdin.readline())
    for _ in range(t):
        n = int(sys.stdin.readline())

        h1 = (n + 2) // 3 + 1
        while h1 + (h1 - 1) + (h1 - 2) < n:
            h1 += 1

        h2 = h1 - 1
        h3 = n - h1 - h2
        output.append(f"{h2} {h1} {h3}")

    return "\n".join(output)

 ## 特殊なケース

 n = 6 の場合、アルゴリズムは最小の有効なトリプルを (2, 3, 1) として計算します。 h1 = 2 を試行するとすぐに失敗します。厳密な順序付けで可能な最大合計は 2 + 1 + 0 であり、これは肯定性に違反するためです。 このアルゴリズムは、実現可能性が満たされるまで h1 を正しく増加させ、有効な構成を生成します。 

n = 7 の場合、計算により h1 = 4、h2 = 3、h3 = 1 が得られます。これは、厳密な不等式を維持しながら残りのブロックが最小のスタックに自然に蓄積される様子と、順序付け制約を強制する以外に手動によるバランス調整が必要ないことを示しています。
