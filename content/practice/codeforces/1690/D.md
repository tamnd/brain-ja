 ## 解決策
 ## 問題の理解

 それぞれ白または黒のタイルのストライプが与えられます。目標は、少なくとも 1 つのセグメントが正確に一致することを確認することです。`k`連続するタイルは完全に黒になります。 入力は複数のテスト ケースを提供し、それぞれがストライプの長さ、必要なセグメント長、およびタイルのシーケンスを指定します。 私たちのタスクは、長さの連続した黒いセグメントを実現するために黒に再ペイントする必要がある白いタイルの最小数を計算することです。`k`。 そのようなセグメントがすでに存在する場合、答えはゼロです。 

制約により許可されるのは、`n`最大 200,000、およびすべての合計`n`テスト ケース全体の上限も 200,000 です。 これは、テスト ケースごとに O(n) よりも複雑なソリューションはタイムアウトになる可能性が高いことを意味します。 単純な O(n*k) アプローチは遅すぎるため、`k`に匹敵することができる`n`。 

必要なセグメントの長さが全長と等しい場合、微妙なエッジケースが発生します。`k = n`、またはいつ`k = 1`。 たとえば、ストライプ`W`長さ1の`k=1`1 回の再ペイントが必要です。 別のシナリオは、長さの完全に黒いストライプです。`n`と`k<n`; 答えはゼロです。 このようなエッジケースの処理が間違っている場合は、多くの場合、セグメントのインデックス付けにおける off-by-one エラーや、最初または最後の位置から始まるセグメントを考慮していないことが原因で発生します。 

## アプローチ

 ブルートフォース手法は簡単です。長さの考えられるすべての連続セグメントを調べます。`k`、その中にある白いタイルの数を数え、最小値を取得します。 これが機能するのは、各セグメントが独立しており、再描画の数がそのセグメント内の白いタイルの数と正確に一致するためです。 ただし、ブルート フォースの複雑さは O(n_k) です。`n-k+1`セグメントを反復処理します`k`タイル。 最悪の場合、`n = 2*10^5`そして`k ≈ n`とすると、約 4_10^10 回の演算が必要になりますが、これは実行不可能です。 

重要な洞察は、問題がスライディング ウィンドウの特性を示しているということです。 一定の長さのセグメント内の白いタイルの数`k`ウィンドウを 1 つ右に移動すると、予測どおりに変化します。つまり、ウィンドウから出ていくタイルの寄与を減算し、入ってくるタイルの寄与を加算します。 これにより、長さの各セグメント内の白いタイルの数を計算できます。`k`O(n) 時間以内に。 

スライディング ウィンドウ内の白の合計を段階的に更新できるという観察により、解は O(n*k) から O(n) に減少します。 実行する白の数を維持し、ウィンドウの移動に応じてそれを更新するだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n*k) | お(1) | 遅すぎる |
 | スライディングウィンドウ | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`、`k`、そしてストライプの文字列。 
3. カウンタの初期化`current_whites`最初の長さのウィンドウの場合`k`位置 0 から k-1 までの白いタイルの数を数えることによって。 
4.セット`min_whites`に`current_whites`。 
5. ウィンドウを位置 1 から n-k までスライドさせます。 各ステップで、ウィンドウから出るタイルが白の場合、デクリメントします。`current_whites`。 ウィンドウに入るタイルが白の場合、増加します`current_whites`。 
6.アップデート`min_whites`それ自体を最小限に抑え、`current_whites`。 
7. ストライプ全体をスライドさせた後、出力します。`min_whites`必要な最小限の再ペイント回数として。 

機能する理由: スライディング ウィンドウの不変条件により、次のことが保証されます。`current_whites`現在の長さのセグメント内の白いタイルの数を常に正確に反映します`k`。 すべてのセグメントを正確に 1 回反復し、最小値を追跡することで、最適な再描画回数を見つけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    s = input().strip()
    
    # initial window count
    current_whites = sum(1 for c in s[:k] if c == 'W')
    min_whites = current_whites
    
    for i in range(1, n - k + 1):
        if s[i-1] == 'W':
            current_whites -= 1
        if s[i+k-1] == 'W':
            current_whites += 1
        min_whites = min(min_whites, current_whites)
    
    print(min_whites)
```最初のループでは、最初のセグメント内の白をカウントします。 ウィンドウを一度に 1 位置ずつスライドすると、カウントが効率的に更新されます。 境界処理は重要です。ウィンドウから出る最初のインデックスは`i-1`、そして新しいタイルが入るのは`i+k-1`。 使用する`sum(1 for c in ...)`白を数える際の 1 つずつ異なるエラーを回避します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        current_whites = sum(1 for c in s[:k] if c == 'W')
        min_whites = current_whites
        for i in range(1, n - k + 1):
            if s[i-1] == 'W':
                current_whites -= 1
            if s[i+k-1] == 'W':
                current_whites += 1
            min_whites = min(min_whites, current_whites)
        print(min_whites)
    
    return output.getvalue().strip()

 ## 特殊なケース

 のために`n=1, k=1, s="W"`、最初のウィンドウには 1 つの白いタイルが含まれています。 アルゴリズムが重要`current_whites=1`、`min_whites=1`これは正しいです。唯一のタイルを再ペイントする必要があります。 次の場合にはスライディング ウィンドウ ループが実行されないため、インデックス エラーは発生しません。`n-k=0`。 

のために`n=5, k=5, s="BBBBB"`、唯一のウィンドウにはすでに白が含まれていません。`current_whites=0`、`min_whites=0`。 アルゴリズムはループに入らずに正しく 0 を出力します。 

次のような交互パターンの場合`WBWB`、`current_whites`1 から始まります (最初のウィンドウの場合)。 ウィンドウをスライドするとカウントが正確に更新され、増分更新が白と黒のさまざまな分布を処理していることが確認されます。
