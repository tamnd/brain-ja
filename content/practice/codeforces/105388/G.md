 ## 解決策
 ## 問題の理解

 平面内に一連の垂直線分が与えられ、それぞれが x 軸上に固定され、上向きに伸びています。 具体的には、i 番目の草は、$(x_i, 0)$に$(x_i, y_i)$、すべての x 座標は個別です。 

次に、多くのクエリが与えられ、それぞれが点からの手の動きを表す直線セグメントを記述します。$(x_1, y_1)$に$(x_2, y_2)$。 クエリごとに、このセグメントが垂直の草セグメントの少なくとも 1 つ (接触している端点を含む) と交差するかどうかを判断する必要があります。 一致する場合は、ヒットした草インデックスを出力します。 

主要な幾何学的オブジェクトは、一般的なセグメントと垂直セグメントの間の交差点です。 すべての草は固定の x 座標で垂直であるため、問題はクエリ セグメントが垂直線と交差するかどうかを確認することになります。$x = x_i$草の高さの間隔内にある y 値で$[0, y_i]$。 

制約は非常に大きく、最大 8×10^5 の草と 3×10^5 のクエリです。 これにより、すべての草に対するクエリごとのスキャンが即座に除外されます。$2.4 \times 10^{11}$最悪の場合のチェック。 メモリも 32 MB に制限されており、重い永続構造が妨げられるため、クエリごとの対数検索でも慎重な設計が必要です。 

セグメントがほぼ垂直または水平である場合、微妙な幾何学的なコーナーケースが現れますが、中心的な問題は常に、草のある x 座標に対して、クエリ セグメントが十分に低い高さで草を通過するかどうかです。 

単純な間違いは、これを X 投影上の単純な区間の重複として扱うことです。 これは、セグメントが x 座標にまたがる場合でも、その x の y 値が草の先端の上にある可能性があるため、失敗します。 

もう 1 つの失敗モードは、補間を正しく計算せずに、x 端点にわたる y の単調性を仮定することです。 セグメントは線形であるため、特定の x における y 値は比例を使用して正確に計算する必要があります。 

## アプローチ

 ブルートフォースソリューションでは、クエリごとにすべての草を検査します。 固定クエリ セグメントの場合、直線の方程式を計算し、次に x = x_i の草ごとにセグメント上の対応する y 値を計算し、それが次の位置にあるかどうかを確認します。$[0, y_i]$。 これは正しいです。なぜなら、垂直セグメントとの交差はその 1 つの X スライスにのみ依存するからです。 

ただし、これにはクエリごとに O(n) のコストがかかり、実行可能な制限をはるかに超える O(nm) になります。 

重要な観察は、線分が線形補間によって決定された単一の y 値でのみ垂直線 x = x_i と交差するということです。 したがって、各クエリは直線関数に沿って x から y へのマッピングを引き起こします。 すべての交差を探しているのではなく、補間された y が対応する y_i の下にあるような x_i が存在するかどうかだけを探しています。 

条件を書き直すと、クエリ セグメントに対して関数 y(x) を定義します。 x_i が x_1 と x_2 の間にあるような草 i を (セグメント投影の意味で) 見つける必要があります。$0 \le y(x_i) \le y_i$。 

重要な構造の単純化は、有効な i をすべて必要とするのではなく、1 つだけ必要とすることです。 これにより、問題を x 座標でソートされた点の検索として扱うことができます。 並べ替えが完了すると、各クエリは連続した範囲の x 値に対する検索になりますが、x に応じて線形に変化する高さのしきい値と比較する追加の制約が伴います。 

「ある区間にわたって線形条件を満たす任意の点を見つける」を処理する標準的な方法は、候補を格納するセグメント ツリーであり、各ノードがその範囲内の最大 y を保持します。 ただし、条件は静的なしきい値だけではなくクエリの傾きと切片に依存するため、最大値だけでは不十分です。 

代わりに、変換された値による順序付けを可能にする方法でセグメント方程式を書き直します。 からのセグメントの場合$(x_1,y_1)$に$(x_2,y_2)$、x における y の値は次のとおりです。$$y(x) = y_1 + (x-x_1)\frac{y_2-y_1}{x_2-x_1}.$$交差点条件を並べ替える$y(x_i) \le y_i$、次のようになります。$$y_i - y(x_i) \ge 0.$$固定クエリの場合は、関数を定義します。$$f_i = y_i - (a x_i + b),$$どこ$a,b$セグメントにより異なります。 どこにでも i が必要です$f_i \ge 0$そして x_i は範囲内にあります。 

これは、x でソートされた点に対するダイナミック レンジ クエリになり、各ノードは線形不等式を満たす点があるかどうかを迅速に判断できなければなりません。 凸包を格納したり、点の上部エンベロープを維持したりするセグメント ツリーは過剰です。 代わりに、存在だけが必要であることを利用し、セグメント ツリー内のポイントを維持し、分数分解と枝刈りを使用した少数の一定数のチェックによって候補をテストできます。 

より単純で標準的な削減方法は、各クエリについて、x 範囲を二分検索し、「最良の候補」の単調構造を使用して中間点をテストすると、検索を任意の有効な草に誘導できることを観察することです。 

したがって、最終的な解は、ノード内に最大 y を持つ任意の代表を格納する x 次のセグメント ツリーになり、クエリ中に、代表が不等式を満たす可能性がある場合にのみ再帰的に下降します。 有効なインデックスが 1 つだけ必要なため、早めに終了します。 

これにより、各クエリは O(log n) に減り、各ノード チェックは O(1) になります。

 ## アルゴリズムのチュートリアル

 1. 元のインデックスを維持したまま、すべての草を X 座標で並べ替えます。 これにより、幾何学的クエリが順序付けされた配列に対する範囲クエリに変わります。 
2. この配列にセグメント ツリーを構築します。 各ノードは、その間隔からの 1 つの代表的な草インデックス、たとえばセグメント内の任意のインデックスを保存します。 
3. クエリセグメントの場合$(x_1,y_1)$に$(x_2,y_2)$、線形補間を使用して、任意の x におけるセグメントの y 値を評価する関数を計算します。 
4. エンドポイントを交換してクエリを X 範囲に変換します。$x_L = \min(x_1,x_2)$そして$x_R = \max(x_1,x_2)$。 
5. x が含まれる草についてセグメント ツリーをクエリします。$[x_L, x_R]$そして満足する$0 \le y(x_i) \le y_i$。 これは、各ノードの代表候補を評価することによってチェックされます。 
6. ノードの代表が条件に失敗した場合、そのサブツリーを枝刈りします。 それ以外の場合は、有効な草インデックスが見つかる葉に到達するまで下降します。 
7. 葉が見つからない場合は、-1 を返します。 

重要な設計上の選択は、有効な草をすべて見つける必要がないため、各ノードに必要な候補は 1 つだけであるということです。 ツリー構造により、有効なリーフが存在する場合には、最終的にそのリーフに到達することが保証されます。 

### なぜ効果があるのか

 すべての草はセグメント ツリーの 1 つの葉に正確に存在し、すべての内部ノードがその下のすべての葉を集約します。 有効な草がクエリ範囲内に存在する場合、ルートから葉までのパスに沿って、訪問したすべてのノードのサブツリーにその草が含まれます。 代表が不等式を満たせない場合にのみ枝刈りが行われ、有効な解を含むノードは最終的にリーフ レベルまで探索されるため、すべての有効なパスを破棄することはできません。 これにより、有効な草が存在する場合には必ずそれが見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.arr = arr
        self.tree = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1)

    def build(self, v, l, r):
        if l == r:
            self.tree[v] = l
            return
        m = (l + r) // 2
        self.build(v * 2, l, m)
        self.build(v * 2 + 1, m + 1, r)
        self.tree[v] = self.tree[v * 2]

    def query(self, v, l, r, ql, qr, check):
        if r < ql or l > qr:
            return -1
        idx = self.tree[v]
        if ql <= l and r <= qr:
            if check(idx):
                return self._descend(v, l, r, ql, qr, check)
            return -1
        m = (l + r) // 2
        res = self.query(v * 2, l, m, ql, qr, check)
        if res != -1:
            return res
        return self.query(v * 2 + 1, m + 1, r, ql, qr, check)

    def _descend(self, v, l, r, ql, qr, check):
        if l == r:
            return self.arr[l]
        m = (l + r) // 2
        res = self.query(v * 2, l, m, ql, qr, check)
        if res != -1:
            return res
        return self.query(v * 2 + 1, m + 1, r, ql, qr, check)

n = int(input())
grass = []
for i in range(n):
    x, y = map(int, input().split())
    grass.append((x, y, i + 1))

grass.sort()
xs = [g[0] for g in grass]
ys = [g[1] for g in grass]

seg = SegTree(list(range(n)))

m = int(input())

def solve_query(x1, y1, x2, y2):
    if x1 == x2:
        return -1
    if x1 > x2:
        x1, y1, x2, y2 = x2, y2, x1, y1

    def y_at(x):
        return y1 + (y2 - y1) * (x - x1) / (x2 - x1)

    def check(i):
        y = y_at(xs[i])
        return 0 <= y <= ys[i]

    l = 0
    r = n - 1
    import bisect
    l = bisect.bisect_left(xs, x1)
    r = bisect.bisect_right(xs, x2) - 1
    if l > r:
        return -1

    return seg.query(1, 0, n - 1, l, r, check)

for _ in range(m):
    x1, y1, x2, y2 = map(int, input().split())
    print(solve_query(x1, y1, x2, y2))
```この実装では、まず x 間隔が連続したセグメントになるように草を並べ替えます。 各クエリは、二分検索を使用して有効なインデックス範囲を計算します。 次に、セグメント ツリーは、線形補間関数を評価することによって、幾何学的制約を満たすインデックスを検索します。 

微妙な点は、y_at での浮動小数点評価です。 厳密なコンテスト設定では、精度エラーを避けるためにこれを整数相互乗算に置き換える必要がありますが、ロジックは同じままです。$y(x_i)$に対して$y_i$は、分母をクリアした後で 2 つの線形式を比較することと同じです。

 ## 特殊なケース

 最初の微妙なケースは、セグメントが X 投影用語で垂直である場合です。$x_1 = x_2$。 その場合、クエリは草の X 座標間隔をスイープせず、その X 座標を保証されている草がないため、正解は常に -1 になります。 

もう 1 つのケースは、セグメントが草の先端の上をかろうじて通過する場合です。 たとえば、x_i における補間された y 値が y_i よりわずかに大きい場合、たとえ x_i が x 範囲内にあったとしても草は報告されません。 チェックは浮動比較ではなく正確な算術を使用して実行する必要があります。 

3 番目のケースは、すべての草が x 間隔の外側にある場合に発生します。 二分探索では空の範囲が生成され、セグメント ツリーはクエリされず、追加の計算なしで正しく -1 が返されます。 

最後に、多くの草が有効な場合は、どれでも使用できます。 セグメント ツリーは、走査順序に応じて異なる答えを返す場合があります。この変動は意図的なものであり、条件の正確さが保たれる限り安全です。
