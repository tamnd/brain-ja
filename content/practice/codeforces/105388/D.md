 ## 解決策
 ## 問題の理解

 次のサイズの長方形グリッドが与えられます。$n \times m$、最初は空です。 移動は固定された順序で 1 つずつ到着し、各移動がそれまで塗られていなかったセルを黒く塗りつぶします。 各移動の後に、その移動を許可するかどうか、またはスキップする必要があるかどうかを決定する必要があります。 

技を無効にするルールは微妙です。 黒いセルのセットに 4 近傍隣接グラフ内の単純なサイクルが含まれており、そのサイクルが少なくとも 1 つのグリッド セルをその境界内に厳密に囲むと、プロセスは停止し、その移動は適用されません。 それ以外の場合、移動は受け入れられ、セルは黒のままになります。 

したがって、概念的には、グリッド グラフのサブグラフを動的に構築しており、「幾何学的に囲む」サイクルが最初に出現したときを検出する必要があります。 

制約は大きく、最大で$3 \cdot 10^5$セルは全体として存在することができ、すべての動きは異なります。 これにより、各ステップ後のグリッドまたはグラフ全体にわたる再計算が除外されます。 移動ごとに BFS または DFS を実行しようとするソリューションは、すぐに失敗します。$O(k(nm))$最悪の場合の行動。 

重要な問題は、サイクルだけでは十分ではないことです。 グリッド グラフ内のサイクルは、必ずしも「有効なゲーム エンディング」であるとは限りません。空ではない内部物質を囲むサイクルのみです。 境界に触れたり、空きスペースの周囲で縮退したりする小さなローカル サイクルは、注意深く区別する必要があります。 

よくある落とし穴は、これを「増分グラフ内のサイクルを検出する」ものとして扱うことです。 これは失敗します。なぜなら、サイクルは囲み領域なしで存在する可能性があり、また、条件がグラフ構造だけでなく平面構造に結び付けられているためです。 

もう 1 つの失敗例は、サイクルが出現したら最新のノードの周囲でローカルに検出するだけで十分であると想定している場合です。 遠く離れた古いコンポーネントを通じてサイクルが形成される場合があります。 

## アプローチ

 直接的なアプローチは、現在の黒いグラフを維持し、新しい移動ごとに新しいノードから DFS または BFS を実行して、内部とのサイクルを形成するそれ自身へ戻るパスが既に存在するかどうかを確認することです。 サイクルが見つかった場合、その移動は拒否されます。 

これは原理的には正しいですが、遅すぎます。 各 BFS/DFS は最大でトラバースできます。$O(nm)$ノード、そしてこれを行うかもしれません$O(k)$回、与える$O(k \cdot nm)$、それは限界をはるかに超えています。 

構造的な洞察は、状態を再構成することから得られます。 実際に求められているのは、任意のサイクルを検出することではなく、現在の黒い領域が「平面内で単純に接続されていない」状態になるかどうか、つまり平面的な意味で森林のような領域でなくなるかどうかを検出することです。 グリッド グラフでは、これを Disjoint Set Union (DSU) を使用して段階的に追跡できますが、標準の DSU は接続のみを追跡し、サイクルは追跡しません。 

重要な観察点は、平面グリッド グラフでは、各セルの次数が最大 4 であり、エッジの挿入ごとに 2 つのコンポーネントがマージされるか、接続されたコンポーネント内に 1 つの新しいサイクルが作成されるということです。 領域を囲むのに十分な構造をすでに備えているコンポーネント内にサイクルが作成される瞬間は、初めて「2D 空間でループを閉じる」ことに対応します。 

これを正確に行うために、セル上で DSU を維持します。 さらに、各接続コンポーネント内のエッジの数を追跡します。 2 つのセルを接続するたびに、セルがすでに同じ DSU コンポーネント内にある場合、冗長エッジが追加され、サイクル候補が形成されます。 重要な点は、すべての冗長エッジが致命的であるわけではなく、どのコンポーネントでも最初の冗長エッジはサイクルが出現する瞬間であるということです。 グリッド グラフでは、コンポーネントの最初のサイクルは閉ループに正確に対応します。グリッド サイクルは平面であり、面積ゼロのループに縮退できないため、その時点で必ず少なくとも 1 つのセルを囲みます。 

したがって、ゲームは、すでに接続されている 2 つのノードを初めて結合しようとした時点で終了します。 

したがって、問題をサイクル検出による動的接続に帰着させます。

 ## アルゴリズムのチュートリアル

 各セルをグラフ内のノードとして扱います。 すべてのセルにわたって DSU 構造を維持し、最初は各セルが分離され非アクティブになっています。 

また、セルがアクティブ化された (黒く塗られた) かどうかを示すブール グリッドも維持します。 

### ステップ

 1. DSU を初期化します。$n \cdot m$ノード。 各ノードは独自のセットで開始します。 また、すべてのセルに対して、訪問済みまたはアクティブな配列の初期値を false に維持します。 
2. プロセスは順番に進みます。 移動用$i$、セルを考慮してください$(r_i, c_i)$。 
3. セルをアクティブとしてマークします。 これは、グラフの一部になることを意味します。 
4. このセルの 4 つの隣接セルのそれぞれについて、隣接セルがアクティブかどうかを確認します。 アクティブでない場合は、現在のグラフの一部ではないため、無視してください。 
5. 隣接セルがアクティブな場合は、DSU 内の隣接セルと現在のセルを結合しようとします。 結合を実行する前に、それらがすでに同じ DSU コンポーネントに属しているかどうかを確認してください。 
6. 同じ DSU コンポーネント内に既に存在する隣接セルが少なくとも 1 つ見つかった場合、これは、このセルを追加するとそのコンポーネントにサイクルが導入されることを意味します。 その場合、この動きに対して直ちに 0 を出力し、それ以上アクティブ化またはマージしません。 
7. そのような競合が発生しない場合は、セルをすべてのアクティブな隣接セルと結合し、1 を出力します。 

微妙な順序が重要です。マージする前にサイクルを検出する必要があります。そうしないと、この移動で「すでに接続されている」ステータスを正しく検出できなくなります。 

### なぜ効果があるのか

 DSU は、黒セルの接続されたコンポーネントを 4 隣接で維持します。 すでに接続されている 2 つのノードを接続しようとすると、そのコンポーネントのスパニング ツリーの一部ではないエッジが導入されることになります。 これにより、平面グリッド グラフにサイクルが作成されます。 グリッドでは、そのようなサイクルは閉じた多角形チェーンに対応します。エッジはグリッドの中心間の軸に沿ったセグメントであるため、その埋め込みは必ず少なくとも 1 つの単位正方形を囲みます。 したがって、最初の冗長エッジは、ゲーム終了条件が初めて満たされたときとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        return True

def solve():
    n, m, k = map(int, input().split())
    idx = lambda r, c: (r - 1) * m + (c - 1)

    dsu = DSU(n * m)
    active = [False] * (n * m)

    out = []

    for _ in range(k):
        r, c = map(int, input().split())
        v = idx(r, c)

        if active[v]:
            out.append('0')
            continue

        active[v] = True
        cycle = False

        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if 1 <= nr <= n and 1 <= nc <= m:
                u = idx(nr, nc)
                if active[u]:
                    if dsu.find(u) == dsu.find(v):
                        cycle = True
                    else:
                        dsu.union(u, v)

        if cycle:
            out.append('0')
            active[v] = False
        else:
            out.append('1')

    print(''.join(out))

if __name__ == "__main__":
    solve()
```DSU は、アクティブ セル間の接続を保存します。 の`active`配列により、既に描画された正方形のみが接続されることが保証されます。 

サイクル検出は、同じ DSU コンポーネント内ですでにアクティブなネイバーが見つかったときに正確にトリガーされます。 これは、新しいエッジがそのコンポーネント内で冗長であることを示します。 

また、ノードを再度追加すると、インクリメンタルな構築に矛盾が生じることは明らかであるため、入力位置が繰り返される場合には、それらを即座に拒否することで処理します。 

## 実用的な例

 単純なことを考えてみましょう$2 \times 2$正方形を形成する動きを持つグリッド。 

入力：```

1 1
1 2
2 2
2 1
```各ステップの後に DSU ルートを追跡します。 

| ステップ | セル | | 前にアクティブ 隣人チェック | サイクルが検出されました | 出力 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (1,1) | なし | なし | いいえ | 1 |
 | 2 | (1,2) | {(1,1)} | (1,1) に接続します | いいえ | 1 |

 4 番目の動きは正方形の周りのサイクルを閉じるため、拒否されます。 

これは、最初の冗長エッジが平面埋め込みのサイクル形成に対応するという不変条件を裏付けます。

 ## 特殊なケース

 すでにアクティブ化されているセル上での繰り返しの移動は、次の理由により直ちに拒否されます。`active[v]`それはすでに真実です。 このガードがないと、DSU は誤ってノードを自身または近隣ノードと再度マージしようとし、誤ったサイクル信号が作成される可能性があります。 

外側のエッジに沿ってループを形成する境界ウォークは、サイクル検出が純粋に構造的なものであるため、正しく処理されます。最後のエッジがループを閉じるとき、DSU はすでに 1 つのコンポーネント内のすべての頂点を持っており、最後の結合試行で冗長性が検出されます。 

すべての結合が以前は個別だったコンポーネントを接続するため、分岐を伴う「ツリー状」の展開が拒否されることはありません。 エッジが既に同じコンポーネント内にある 2 つの頂点を接続している場合にのみ、アルゴリズムは平面サイクルが完了した瞬間に一致して拒否します。
