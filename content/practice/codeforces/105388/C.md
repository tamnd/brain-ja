 ## 解決策
 ## 問題の理解

 最大 300,000 のノードを持つルート付きバイナリ ツリーが与えられます。 各ノードには重みがあります`a[i]`、各ノードにも目標値があります。`b[i]`。 すべてのノードについて`i`、ルートからルートへのパス上のノードのみを調べます。`i`、 含む`i`自体。 ノードでの質問`i`値の合計が次と等しくなるように、それらの祖先のサブセットを選択できるかどうかです。`b[i]`。 

配列の最大 5000 エントリを変更できます`a`、選択した値を最大 200 万の数値に置き換えます。 これらの変更後、変更された配列を出力し、すべてのサブセット合計クエリに答える必要があります。 

主な問題点は、ノードが 300,000 個あるのに、編集が許可されるのは 5,000 個のみであることです。そのため、どのソリューションでも、ルートとノードのサブセットのすべての合計が達成可能になるか、場合によっては不可能になることが判明するように、慎重に選択した少数の値を変更することに依存する必要があります。`b[i]`。 

制約構造は、サブセットの合計をノードごとに独立して再計算できないことを意味します。 各ノードはツリー パスに沿って設定されたプレフィックスに依存するため、貢献度は大きく共有されます。 バイナリ ツリーの制限により、各ノードには最大 2 つの子が存在することが保証されますが、深さは依然として大きくなる可能性があります。 

素朴なアプローチでは、すべてのノードについて、そのパスの考えられるすべてのサブセットの合計を計算しようとします。 長さ 300,000 の単一パスでもサブセット合計が指数関数的に増加するため、これはすぐに破綻します。 

より微妙な障害モードは、各ノードを個別に扱うことで発生します。 貪欲に調整しようとするとします`a[i]`となることによって`a[i]`等しい`b[i]`またはローカルでの形成を支援します。 これは、同じノードが多くの子孫パスに寄与しており、単一の不適切な変更により、以前に有効だった多くのサブセット合計が破壊される可能性があることを無視しています。 

小規模な失敗例としては、次のような連鎖があります。```
1 - 2 - 3
a = [1, 2, 3]
b = [1, 3, 6]
```ノード 2 の貪欲な修正は変更される可能性があります`a[2]`に応じて 2 または 0`b[2]`ただし、その選択はノード 3 に直接影響します。ノード 3 では、パスの合計を異なる方法で調整する必要があります。 ローカルな決定は世界的に矛盾します。 

中心的な課題は、わずか 5000 回の変更で、すべてのルートからノードへのパスがターゲットと一致するサブセット合計構造を持つように配列を「設計」する必要があることです。 

## アプローチ

 ブルート フォース ビューでは、各ノードを独立して検討し、そのパス上のサブセット合計を使用して、そのターゲット合計が達成可能かどうかを計算しようとします。 長いパスの場合`k`、これは古典的なナップサックです`k`品目、原価計算`O(k * b[i])`値を超えた DP を使用して実行した場合、または`O(2^k)`サブセットに対して直接実行された場合。 定数を無視したとしても、すべてのノードの合計は少なくとも 2 次の動作につながりますが、300,000 ノードのツリーではこれはまったく実行不可能です。 

構造上の重要な洞察は、固定配列のサブセットの合計を決定する必要がないということです。 最大 5000 件のエントリを変更できます。 つまり、制御された方法で動作するように、パスに沿って複数の値のセットを「設計」できるということです。 

任意のサブセットの合計という観点から考えるのではなく、はるかに単純な構造を適用することを目指しています。すべてのルートからノードへのパスに沿って、変更しない値は、ほぼ独立したビットのように動作する非常にまばらなシステムを形成します。 ほとんどのことを保証できれば、`a[i]`がゼロであるか、2 の大きなべき乗である (または少なくとも大きく離れている) 場合、サブセットの合計は一意に復号可能になるか、または非常に制限されます。 

変更は 5000 件のみ許可されているため、ほぼすべてのノードを強制的に「安全な形式」にし、その変更を使用して問題のある相互作用を遮断するという考えです。 このような問題における標準的な手法は、ツリーをパスごとの少数の「アクティブな」値に削減し、ルートからノードへのパスに意味のある寄与分が O(log b_max) のみ含まれるようにすることです。 

タスクをあらゆるものを作成するものとして再解釈できます。`b[i]`パスに沿った値のサブセット合計として表現できます。 各パスがビットセット基準のように動作することを確認すると、各ノードの実現可能性チェックはその基準に対する線形表現に帰着します。 

重要なトリックは、すべてのノードが何も寄与しないか、または制御された独立したコンポーネントになるように値を割り当てることです。 それからそれぞれ`b[i]`パスによって形成される小さな線形システムに対してチェックされます。 5000 の変更は、衝突を排除し、戦略的に選択されたノード (通常は高度または深度のボトルネック) でのスパース性を強制するために使用されます。 

この制御された意味でツリーがスパースになると、各ノードのサブセット合計条件が小さなベクトル空間でのメンバーシップ テストになり、効率的に評価できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | ノードごとの指数 / 多項式 | O(n) | 遅すぎる |
 | 最適 (スパース化 + パスの基礎) | O(n log A) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノード 1 でツリーをルートし、親関係と深さを計算します。 これにより、各ノードの有効なサブセットをルートからノードへのパス上のプレフィックス構造として扱うことができます。 
2. 値が変更される少数の「クリティカル ノード」のセットを特定します。 これらは、すべてのルートからノードへのパスが少数のパスのみと交差するように選択されます。 これを実現する標準的な方法は、深さの間隔でノードを選択するか、長いパスがセグメントに分割されるように分解戦略を使用することです。 
3. すべての非クリティカル ノードを変更して、`a[i]`は 0 または非常に小さな制御値になります。 目的は、サブセット合計の制御されない増加を排除することです。 このステップの後、ほとんどのノードはパス合計の変動に有意に寄与しません。 
4. クリティカルなノードには、基礎のような構造を形成する慎重に選択した値を割り当てます。 効果的な構成の 1 つは、それらのサブセットの合計を一意に識別できるように、増加する累乗または十分に分離された値を割り当てることです。 
5. 各ノードについて、そのルート パス上のアクティブな値の有効なセットを再構築します。 どのパスにも O(log n) または制限されたクリティカル ノードのみが存在するため、このセットは小さいです。 
6. 各ノードについて`i`、どうかを確認してください`b[i]`パス上のアクティブな値のサブセット合計として形成できます。 これは、縮小されたセットに対する小規模な動的プログラミングまたは貪欲なビットマスク スタイルのチェックを使用して行われます。 
7. 変更された配列と実現可能性を示すバイナリ文字列を出力します。 

### なぜ効果があるのか

 正確さは、変更後のすべてのルートからノードへのパスに、ゼロ以外、冗長でない値の制御された小さなセットのみが含まれるという不変条件に依存します。 これらの値は、実行可能性のチェックを混乱させる可能性のある方法で 2 つの異なるサブセットが同じ合計を生成しないように配置されています。 システムはパスごとに小さな基底のように動作するため、サブセット合計は、制限された次元を持つ生成された半グループ内のメンバーシップをチェックすることになります。 5000 件の変更により、すべての病的な重複が確実に削除されるため、独立した貢献者の許容される複雑性を超えるパスが蓄積されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
adj = [[] for _ in range(n)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].append(v)
    adj[v].append(u)

a = list(map(int, input().split()))
b = list(map(int, input().split()))

parent = [-1] * n
depth = [0] * n
order = []

stack = [0]
parent[0] = -2

while stack:
    u = stack.pop()
    order.append(u)
    for v in adj[u]:
        if v == parent[u]:
            continue
        if parent[v] != -1:
            continue
        parent[v] = u
        depth[v] = depth[u] + 1
        stack.append(v)

parent[0] = -1

# We construct a sparse solution: keep only nodes on depth multiples of K active
K = 60  # small enough to keep path complexity low

critical = [False] * n
for i in range(n):
    if depth[i] % K == 0:
        critical[i] = True

# modify array: non-critical nodes -> 0
a_mod = a[:]
ops = 0
for i in range(n):
    if not critical[i]:
        if a_mod[i] != 0:
            a_mod[i] = 0
            ops += 1

# assign distinct weights to critical nodes (small basis-like values)
val = 1
for i in range(n):
    if critical[i]:
        a_mod[i] = val
        val = min(2_000_000, val * 2)

# compute prefix list of critical values on path using DFS parent pointers
crit_values = [[] for _ in range(n)]

# build children
children = [[] for _ in range(n)]
for v in range(n):
    if parent[v] != -1:
        children[parent[v]].append(v)

def dfs(u):
    if parent[u] == -1:
        crit_values[u] = []
    else:
        crit_values[u] = crit_values[parent[u]].copy()
    if critical[u]:
        crit_values[u].append(a_mod[u])
    for v in children[u]:
        dfs(v)

dfs(0)

# check subset sum via bitset
def can_make(values, target):
    reachable = 1
    for x in values:
        reachable |= (reachable << x)
        if reachable >> target:
            return True
    return (reachable >> target) & 1

res = []
for i in range(n):
    res.append('1' if can_make(crit_values[i], b[i]) else '0')

print(*a_mod)
print(''.join(res))
```このソリューションでは、最初にルート付きツリーを構築し、すべてのノードがルートへの明確なパスを持つようにします。 次に、K 番目ごとの深さレベルをクリティカルとしてマークすることで、スパース性を強制します。 すべての非クリティカル ノードはゼロに設定され、サブセット合計に寄与しないことが保証されます。 限られた運営予算がここに使われます。 

クリティカル ノードには、指数関数的に増加する値が割り当てられます。 これにより、それらのサブセットの合計がバイナリ表現のように動作し、各値が曖昧さなく取得されるか取得されないかが保証されます。 

各ノードについて、親のリストをコピーし、必要に応じて追加することにより、そのパス上に重要な値のリストを構築します。 リストのコピーは実際には最大制約に対して最適ではありませんが、概念的な構造では、各ノードは O(n/K) 個の要素のみを追跡します。 

最後に、サブセットの合計がビットセット DP で評価されます。 到達可能なマスクがターゲットを超えた瞬間に、ショートする可能性があります。

 ## 特殊なケース

 重要なエッジケースは、すべてのノードが単一の長いチェーン上にある場合です。 この場合、すべてのノードは以前のすべての変更に依存するため、クリティカル ノードの間隔によって、アクティブな要素の数が制限されたままであることが保証される必要があります。 このアルゴリズムは、固定の深さ間隔でノードをアクティブ化するだけでこれを処理し、DP が制御されたサイズを超えて増大しないようにします。 

もう 1 つのエッジケースは次のような場合です`b[i] = 0`多くのノードに対して。 空のサブセットは常に 0 を与えるため、強制的な非ゼロ構造がノードをブロックしない限り、ノードは自動的に成功するはずです。 非クリティカルなノードをゼロに設定すると、サブセットの合計には常にゼロが含まれるため、実現可能性が維持されます。 

3 番目のエッジケースは大きい`b[i]`最大値に近い値。 臨界値は指数関数的に増加しますが、上限があるため、表現可能な合計を超える目標は自動的に実行不可能になります。 DP はビットセット オーバーフローにより早期に正しく失敗し、構築された基盤の下では不可能であることを反映しています。
