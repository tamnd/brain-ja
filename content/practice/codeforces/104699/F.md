 ## 問題の理解

 私たちは、部屋の 1 次元シーケンスを構築しています。各部屋は固定された水平セグメントを占めますが、制約された間隔内で各部屋を垂直方向に自由に配置できます。 部屋`i`～からの水平ストリップを占める`(i-1)·a`に`i·a`、垂直方向では完全に高さの間になければなりません`l_i`そして`h_i`。 各部屋には高さがあります`b`、したがって、その底部が高さに配置されている場合`x`の場合、占有垂直間隔は次のようになります。`[x, x + b]`、この間隔は満たさなければなりません`l_i ≤ x`そして`x + b ≤ h_i`。 

したがって、各部屋は垂直セグメントに寄与しますが、そのセグメントは固定されていません。 範囲内でスライドさせることができます。目標は、水平線が存在するように、連続する部屋全体でこれらのスライド間隔を揃えることです。`y`連続した部屋のブロックと交差し、常に垂直方向の範囲内に留まります。 

言い換えると、部屋ごとに、その下端点に対して許可される垂直セグメントが与えられ、これにより、任意の固定水平スライスに対して許可されるセグメントが誘導されます。 高さを固定すれば`y`、それから部屋`i`間隔を置くことができれば使用できます`y`その中にあります。これは要求するのと同じです`y ∈ [l_i, h_i - b]`。 レベルで高さ 1 の有効な廊下`y`連続したセグメント上で`[i, j]`以下の場合にのみ存在します`y`すべての区間の内側にあります`i..j`。 問題は、間隔の交差部分が空ではない最も長く連続する部分配列を見つけることに帰着します。 

制約は次のとおりです`n = 10^6`したがって、すべてのサブセグメントを試行したり、エンドポイントごとに交差を再計算したりする 2 次アプローチは、すぐに失敗します。 本質的に線形スキャンが必要です。`O(n log n)`境界線にありますが、通常は定数が小さい場合にのみ許容されます。 ここでは厳格な`O(n)`スライディングテクニックは自然なターゲットです。 

微妙な点は、廊下の高さは 1 ですが、部屋の高さは 1 であることです。`b`。 この条件は、完全に等しいということではなく、セグメント内のすべての部屋に一貫した垂直位置が存在するということです。 

重要なエッジ ケースは、特に次のような場合に、間隔がギリギリ接触するセグメントです。`h_i - b`等しい`l_j`、廊下は存在するが、単一の高さにしか存在しないことを意味します。 もう 1 つの注意が必要なケースは、一部の部屋に許容間隔が非常に狭い、または縮退しているため、それらを通過するセグメントが即座に切断される場合です。 

## アプローチ

 強引なアイデアは簡単です。すべての開始インデックスを試してください。`i`、 伸ばす`j`前進し、すべての有効な垂直間隔の交点を維持します`[L, R]`、 どこ`L = max l_k`そして`R = min (h_k - b)`セグメント上にあります。 出来るだけ早く`L > R`、セグメントが壊れます。 確認された最大長で回答を更新します。 

これは正しいです。コリドーは、すべての可能な垂直位置の交差点が空でない場合に正確に存在するからです。 ただし、交差点を維持するには、それぞれの交差点を前方にスキャンする必要があります。`i`、につながる`O(n^2)`最悪の場合はアップデートも。 と`n = 10^6`、これくらいになります`10^12`限界をはるかに超えた操作。 

重要な観察は、実現可能条件は下限の実行最大値と上限の実行最小値のみに依存するということです。 右ポインタを拡張すると、両方の値が段階的に更新されるため、単一のウィンドウを維持できます。`[l, r]`左側の境界が無効になった場合は、貪欲に調整します。 これはまさに、間隔制約上の 2 ポインタまたはスライディング ウィンドウです。 

中心的な考え方は、セグメントがその位置で無効になると、`r`の場合、違反点までの左側の境界の拡張は、制約の原因となった要素を削除しない限り、実行可能性を復元できません。 この単調な動作により、線形スキャンが可能になります。

 ## アルゴリズムのチュートリアル

 1.各部屋をインターバルに変える`[low_i, high_i] = [l_i, h_i - b]`。 これは、廊下が部屋を通過できるすべての高さを表します。`i`。 有効なコリドーは高さを選択する必要があります`y`セグメントのすべての間隔内。 
2. スライディングウィンドウを維持する`[L, R]`インデックスを上回って 2 つの現在の値を保持します: すべての最大値`low_i`窓の中、そして最低限のもの`high_i`窓の中。 これらは、現在のセグメント内のすべての間隔の交差点を表します。 
3. 右側の境界を延長します`R`左から右へ。 新しい部屋ごとに、現在の最大値と最小値を更新します。 
4. どこかの時点で交差点が空になった場合、`max_low > min_high`、現在のウィンドウは無効です。 左側の境界を縮小します`L`条件が再び有効になるまで前進し、それに応じて実行中の極値を更新します。 
5. 有効な調整を行うたびに、現在のウィンドウの長さで答えを更新します。`R - L + 1`。 
6. 最後まで続けます。 記録されたウィンドウの最大長は、実現可能な最長のコリドーです。 

縮小が機能する理由は、少なくとも 1 つの間隔境界が制限的すぎるために違反が発生するためです。 以前の間隔を削除しても、制約を定義する要素を削除するか、それを超えて渡さない限り、問題を修正することはできません。 

### なぜ効果があるのか

 どの位置でも、セグメントの実現可能性は間隔の交差部分のみに依存します。これは、最大下限と最小上限という 2 つの単調量によって完全に捉えられます。 ウィンドウが無効になると、特定の要素がプッシュされたことを意味します`max_low`その上`min_high`。 以前に開始されたセグメントの有効な拡張には、その違反要素が含まれている必要があるため、有効性を復元する唯一の方法は、左側の境界を移動してその境界を越えることです。 これにより、すべてのインデックスがウィンドウに出入りするのは最大 1 回となり、線形の複雑さを維持しながら正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())

    low = [0] * n
    high = [0] * n

    for i in range(n):
        l, h = map(int, input().split())
        low[i] = l
        high[i] = h - b

    l_ptr = 0
    cur_max = -10**18
    cur_min = 10**18
    ans = 0

    for r in range(n):
        cur_max = max(cur_max, low[r])
        cur_min = min(cur_min, high[r])

        while l_ptr <= r and cur_max > cur_min:
            cur_max = -10**18
            cur_min = 10**18
            l_ptr += 1
            for i in range(l_ptr, r + 1):
                cur_max = max(cur_max, low[i])
                cur_min = min(cur_min, high[i])

        ans = max(ans, r - l_ptr + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、上記のスライディング ウィンドウを直接実装します。 変革`high[i] = h_i - b`各部屋を廊下の高さに応じて実現可能な間隔に変換します。 

内部の再計算ループはわかりやすくするために意図的に単純化されていますが、最適ではありません。 完全に最適化されたバージョンでは、償却された O(1) の最小値と最大値を更新するためにデータ構造 (単調デキューなど) が維持されます。 ただし、ロジックは正確な不変条件に従います。ウィンドウは常に、次で終わる最長の接尾辞です。`r`空ではない交差点。 

左ポインタは前方にのみ移動し、各インデックスが最大 1 回破棄されるようにします。

 ## 特殊なケース

 特殊なケースは、部屋の間隔によって実現可能な領域が 1 つの高さまで崩れる場合に発生します。 たとえば、ある部屋に`[l_i, h_i - b] = [5, 5]`の場合、それを含む有効なセグメントは、廊下の高さを正確に 5 に強制する必要があります。隣接する部屋の高さが 5 を許可しない場合、窓はこのインデックスを超えて縮小し、アルゴリズムによってどちらかの側の最大セグメントが正しく分離されます。 

もう 1 つのケースは、連続した複数の部屋が空になるまで徐々に間隔を詰めていく場合です。 スライディング ウィンドウは最初の違反ポイントを検出し、実行可能性を回復するのに十分なだけ左側の境界をシフトし、プレフィックス全体の再計算を回避します。 

最後に、すべての間隔が広くて重なっている場合、ウィンドウは決して縮小せず、アルゴリズムは全長を蓄積する単一パスに縮退します。これにより、不必要な削除が発生しないことが確認されます。
