 ## 解決策
 ## 問題の理解

 私たちには、無向グラフとしてモデル化されたソーシャル ネットワークが与えられています。 各人は固定の整数値を持っています$p_v$そしてそれぞれの友情には価値がある$d_{u,v}$。 人なら$v$一定の友情を維持している場合、彼らの「不満」はあらゆる出来事のエッジを考慮して計算されます$(u,v)$、 形にする$p_v \oplus d_{u,v}$、これらの貢献を合計します。 社会全体の不満の合計は、すべての頂点の合計です。 

エッジを削除することはできますが、グラフは接続されたままにしておく必要があります。 目標は、接続性が維持され、不満の合計ができるだけ小さくなるように、どのエッジを残すかを選択することです。 

主な問題点は、エッジの削除が両方のエンドポイントに独立して影響するため、一見すると目的は標準的な「エッジの合計」式ではないことです。 

制約により、最大で$2 \cdot 10^5$したがって、サブグラフを列挙したり、すべてのスパニング ツリーを試行したりするアプローチは不可能です。 周りの何かを目指すべきです$O(m \log m)$または$O(m \alpha(n))$。 

問題が「局所的に良いエッジ」を選択することにあると仮定すると、微妙な失敗例が現れます。 たとえば、頂点ごとにエッジを最小化するものを選択します。$p_v \oplus d$すべての選択が局所的に最適であるように見えても、グラフが切断される可能性があります。 もう 1 つの間違った考え方は、頂点ごとの寄与を独立して扱うことですが、エッジは 2 つの頂点に同時に影響を与えるため、調整なしでは 2 回最適化することはできません。 

## アプローチ

 ブルート フォース ビューでは、接続されているすべてのスパニング サブグラフを考慮します。 すべての有効な解は、接続されたエッジのセットに対応しており、そのようなセットごとに、頂点とそれに付随して選択されたエッジを合計することによって、合計の不満足度を計算できます。 ただし、接続された部分グラフの数は指数関数的になります。$m$、スパニング ツリーの生成だけでも、次のように成長します。$n^{n-2}$密集した場合。 これにより、徹底的な検索が完全に不可能になります。 

重要な観察は、エッジのセットが固定されると、視点を頂点からエッジに移すことによって総コストを書き換えることができるということです。 選択された各エッジ$(u,v)$貢献する$p_u \oplus d_{u,v}$に$u$そして$p_v \oplus d_{u,v}$に$v$。 これは、すべてのエッジが含まれている場合は独立して固定コストに寄与し、除外されている場合は何も寄与しないことを意味します。 

したがって、目的は、これらの導出されたエッジの重みの合計を最小限に抑えながら、グラフの接続を維持するエッジのセットを選択することになります。 これはまさに、重み付きグラフにおける最小スパニング ツリー問題の定義です。 

すべての元のエッジを新しい重みに変換します。$$w(u,v) = (p_u \oplus d_{u,v}) + (p_v \oplus d_{u,v})$$次に、このグラフの MST を計算します。

 | 接続されているすべてのサブグラフを列挙する | 指数関数 | 高い | 遅すぎる |
 | 変換された重みを含む MST |$O(m \log m)$|$O(m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 各エッジを単一のコストに変換します

 あらゆるエッジに$(u,v,d)$、次を計算します。$$w = (p_u \oplus d) + (p_v \oplus d)$$これにより、頂点ベースのコストが単一のエッジ値に圧縮され、全体の目的がエッジにわたって加算されるようになります。 

### 2. グラフを重み付き無向グラフとして扱う

 元の各エッジをこの計算された重みで置き換えます。 接続の構造は変わりません。 

### 3. エッジを重みで並べ替えます

 すべてのエッジを、計算されたコストに基づいて徐々に並べ替えます。 これにより、接続を維持する最も安価なエッジを貪欲に選択できるようになります。 

### 4. Kruskal のアルゴリズムを実行する

 ソートされた順序でエッジを反復処理し、素のセット共用体構造を使用します。 2 つの異なるコンポーネントを接続する場合に限り、エッジを追加します。 終わったらやめてください$n-1$エッジ。 

このステップが機能する理由は、現在、変換された重みに関する標準の最小スパニング ツリー問題を解いているからです。 

### 5. 選択したエッジの合計重みを出力します。 

選択したエッジの重みの合計は、まさに考えられる最小の不満足度の合計となります。 

### なぜ効果があるのか

 重要な特性は、変換後の目的は、高次の相互作用ではなく、選択されたエッジのみに依存するということです。 すべての有効な解は、接続されたスパニング サブグラフに対応します。すべての重みが負ではないため、そのようなすべてのサブグラフの中でサイクルを削除すると、コストが削減または維持されるだけです。 これにより、最適性を損なうことなく、検索スペースがスパニング ツリーに縮小されます。 Kruskal のアルゴリズムは、最小の総重みスパニング ツリーを保証します。これは、最小限の不満足に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

n, m = map(int, input().split())
p = list(map(int, input().split()))

edges = []
for _ in range(m):
    u, v, d = map(int, input().split())
    u -= 1
    v -= 1
    w = (p[u] ^ d) + (p[v] ^ d)
    edges.append((w, u, v))

edges.sort()

dsu = DSU(n)
ans = 0
cnt = 0

for w, u, v in edges:
    if dsu.union(u, v):
        ans += w
        cnt += 1
        if cnt == n - 1:
            break

print(ans)
```DSU は、Kruskal がエッジを昇順に処理するときに、接続されたコンポーネントを維持します。 計算された重みは両方のエンドポイントの寄与をすでにエンコードしているため、アルゴリズム中に頂点の状態を追跡する必要はありません。 

よくある間違いは、両方のエンドポイントが独立して貢献していることを忘れていることです。 まさにこれが、エッジの重みが 1 つの項ではなく 2 つの XOR 式の合計である理由です。

 ## 特殊なケース

 重要なエッジ ケースは、複数のエッジが同じ頂点のペアを接続する場合です。 Kruskal は各エッジを独立して処理するため、接続に役立つ場合は最も安価なバージョンが自動的に選択されます。 この変換により、平行エッジが計算された重みだけで比較できることが保証されます。 

別のケースは、すべてが$p_v$は同一です。 次に、各エッジの重みは次のように単純化されます。$2 \cdot (p \oplus d)$となり、問題は変換された重みに対する標準 MST に帰着します。 アルゴリズムは同様に動作し、均一なノード値の特別な処理が必要ないことを確認します。 

最後に、グラフがすでにツリーである場合、接続にはすべてのエッジが必要であるため、アルゴリズムは変換されたすべてのエッジの重みを単純に合計します。 これは、接続を切断せずにエッジを削除できないという事実と一致します。
