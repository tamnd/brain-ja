 ## 解決策
 ## 問題の理解

 円形のテーブルが与えられました。$n$座席と$n$各ゲストには制約間隔が付いています$[l_i, r_i]$。 この間隔は、ゲストが座ることを許可される場所を表します。ゲストを割り当てる場合$i$どこかの席へ$j$ならば、それはそれを保持する必要があります$l_i \le j \le r_i$。 

タスクは、すべての制約が満たされるようにすべてのゲストを個別の座席に割り当てることができるかどうかを判断し、可能であれば 1 つの有効な割り当てを作成することです。 言い換えれば、各ゲストが許可されたセグメント内に着地するように、座席上のゲストの順列を構築しようとしています。 

この構造は、間隔制約のある 2 つの順序付きセット間の古典的な 1 対 1 マッチングです。 各座席は 1 回だけ使用できるため、問題は間隔ごとの実現可能性を確認するだけではなく、重複する範囲間の競合を調整することになります。 

制約により許可されるのは、$n$まで$10^5$、これは直ちに除外します$O(n^2)$シミュレーションまたは間隔の繰り返しスキャン。 どのソリューションも、操作ごとに対数または償却定数時間でイベントを処理する並べ替えまたはデータ構造に依存する必要があります。 

単純なアプローチが微妙に失敗するケースは、多くの区間が重なり合っているものの、適切なエンドポイントが狭い場合に発生します。 たとえば、すべての間隔が$[1, n]$一人を除いては$[1,1]$、注文せずに貪欲な「範囲内で利用可能な座席を割り当てる」戦略は、座席 1 を簡単に遅すぎたり早すぎたりして消費する可能性があり、正しい割り当てが存在する場合でも実現性が妨げられます。 

もう 1 つのエッジ ケースは、間隔が非常に短いにもかかわらず、処理順序が遅い場合に発生します。 狭い間隔を優先しないと、唯一可能な座席を別のゲストに早めに割り当てる可能性があり、たとえ有効なグローバルな取り決めが存在していたとしても、避けられない失敗が発生する可能性があります。 

## アプローチ

 強引なアイデアは、座席を 1 つずつ割り当て、各座席について、その間隔が含まれる未使用のゲストを選択することです。 これには、すべての座席のすべてのゲストをスキャンし、実現可能性を動的にチェックする必要があります。 これは制約を直接強制するため概念的には機能しますが、座席の配置ごとにコストがかかる可能性があります。$O(n)$、につながる$O(n^2)$最悪の場合、動作が遅すぎて、$10^5$。 

重要な観察は、ライン上で割り当ての問題を解決していることです。座席は順番に処理され、各ゲストは次の時点で利用可能になります。$l_i$有効期限は次のとおりです$r_i$。 どの座席位置でも$i$、関連するゲストは、インターバルがすでに開始されているがまだ終了していないゲストのみです。 それらの中で、割り当てるのに最適な候補は、最小の正しいエンドポイントを持つものです。これは、最も制約があり、後で最初に不可能になるためです。 

これにより、問題は貪欲なスケジューリング プロセスに変わります。 私たちは座席を左から右に移動し、利用可能なゲストのセットを維持し、常に最も狭い座席を選択します。

 ## アルゴリズムのチュートリアル

 1から各シートポジションまで扱います$n$タイムステップとして。 

1. ゲストを出発点順に並べ替える$l_i$。 これにより、ゲストの有効期間が始まるときに正確にゲストをアクティブ化することができます。 
2. 座席の位置を 1 から$n$。 それぞれのポジションで$i$、すべてのゲストを優先構造に挿入します。$l_j = i$。 これらはこの時点から着席できるようになります。 
3. をキーとする最小ヒープを維持します。$r_j$、現在利用可能なすべてのゲストを保存します。 ヒープは、間隔が現在の座席をカバーするすべてのゲストを表します。 
4. ゲストを座席に割り当てる前に$i$、ヒープからゲストを削除します$r_j < i$、有効な場所に配置できなくなるためです。 
5. ヒープが空になると、ゲストは席を占有することができなくなります$i$, そのため、有効な割り当ては不可能です。 
6. それ以外の場合は、最小のゲストを選択します$r_j$ヒープから取り出して座席に割り当てます$i$。 再度使用されないように完全に削除してください。 

### なぜ効果があるのか

 どの座席位置でも、常に現時点で可能なゲストを割り当てます。 すべての実行可能なゲストの中で、最小の適切なエンドポイントを持つゲストを選択すると、将来の割り当てがブロックされるリスクが最小限に抑えられるため、安全です。 より大きなものを選択する代替選択肢$r_j$小さいほど実現可能性が向上することはありません。$r_j$ゲストの将来のオプションは厳密に少ないため、配置する場合はより早く配置する必要があります。 これにより、アルゴリズムが早期に失敗しない限り、残りの割り当てられていないすべてのゲストが残りの座席内で利用可能な少なくとも 1 つの有効なポジションを保持しているという不変条件が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    add = [[] for _ in range(n + 2)]
    
    for i in range(1, n + 1):
        l, r = map(int, input().split())
        add[l].append((r, i))
    
    import heapq
    heap = []
    ans = [0] * (n + 1)
    
    for pos in range(1, n + 1):
        for r, i in add[pos]:
            heapq.heappush(heap, (r, i))
        
        while heap and heap[0][0] < pos:
            heapq.heappop(heap)
        
        if not heap:
            print("NO")
            return
        
        r, i = heapq.heappop(heap)
        ans[pos] = i
    
    print("YES")
    print(*ans[1:])

if __name__ == "__main__":
    solve()
```このソリューションでは、最初にゲストを左側のエンドポイントごとにグループ化し、スイープが開始位置に到達したときに正確にアクティブ化できるようにします。 ヒープにより、各座席で最も緊急のゲスト (最小値で定義) を迅速に取得できることが保証されます。$r_i$。 

期限切れの間隔を削除するクリーンアップ ループは不可欠です。クリーンアップ ループがないと、アルゴリズムが有効範囲外のゲストを割り当てる可能性があるためです。 空性のチェックにより、不可能性が即座に検出されることが保証されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、複数のゲストが次のような同じ間隔で狭い場合です。$[1,1]$。 席 1 にはそれらのゲストのみが利用可能であり、ヒープはその中から任意に 1 人を選択します。 利用可能なポジションよりもそのようなゲストが多い場合、ヒープはある時点で空になり、正しく NO が返されます。 

もう 1 つのケースは、ゲストの開始時間は遅いものの、締め切りが非常に早い場合です。 ヒープにはゲストのみが含まれるため、$l_i \le i$、そのようなゲストは期限前にシステムに入ることさえなく、割り当てられることもなく、正しくは失敗を引き起こします。 

最後の微妙なケースは、広い間隔が常に利用可能な場合です。 これらは自然に後の席に押しやられます。$r_i$が大きく、より適切な代替手段が存在しない場合にのみ選択されます。 これにより、以前のすべての制約付き割り当ての実現可能性が維持されます。
