 ## 解決策
 ## 問題の理解

 未知の整数値を決定しようとしています$p$までの非常に広い範囲にあります。$10^{12}$。 直接クエリすることはできませんが、2 つの異なる種類の対話が許可されています。 

最初のインタラクションは、一種の制限付きメンバーシップ テストです。$p$。 値を尋ねると$t \le 10^6$、システムは次のことを教えてくれます。$t$厳密に上にあります$\sqrt{p}$そしてせいぜい$p$。 言い換えれば、このクエリは次のことを明らかにします。$t$平方根のしきい値を超えるには「十分大きい」ですが、隠れた数より大きくはありません。 

2 番目のインタラクションは、選択されたものを使用した実験です。$t \le 10^{12}$。 もし$t > p$、プログラムはすぐに失敗するため、確実でない限り、そのようなクエリは安全ではありません。 もし$t \le p$、エンドポイントが依存する間隔から一様にサンプリングされたランダムな実数を受け取ります。$p$そして$t$。 重要な構造は、戻り値が次のようにスケールされることです。$p/t$ですが、対称的に二乗されます。$[p/t, (p/t)^2]$。 これにより、出力はノイズが多くなりますが、比率に関する構造化された信号になります。$p/t$。 

最後に、の正確な値を出力する必要があります。$p$どちらのタイプでも最大 22 クエリ以内。 

この制約は、総当たり検索や二分探索ができないことを意味します。$p$直接。 候補者をスキャンすることに依存するあらゆる戦略$10^{12}$不可能です。 平$O(\log p)$各ステップで慎重に制御された実験が必要な場合、このアプローチは弱すぎるため、ソリューションではクエリごとに大量の情報を抽出する必要があります。 

最も危険なエッジケースは、実験クエリを盲目的に使用することです。 もし私たちが選ぶとしたら$t > p$、プログラムはすぐにクラッシュします。 以来$p$は未知であり、境界が緩やかであるため、単純な指数関数または倍加検索はそれを踏み越える危険があります。 もう 1 つの微妙な問題は、戻り値のランダム性です。出力が決定的ではないため、単一の観測に依存する解は分散に対して堅牢である必要があります。 

さらに問題なのは、アドバイス クエリが次の場合にのみ機能することです。$t \le 10^6$、 その間$p$はるかに大きくなる可能性があります。 これによりスケールの不一致が生じます。小さなクエリで構造情報が明らかになります。$\sqrt{p}$一方、大規模なクエリを使用して比率を調査することはできますが、それが安全に行えるのは、すでに適切な境界が設定されている場合に限られます。 

## アプローチ

 強引なアイデアは、可能な値をすべて試してみることです。$p$応答と一致しているかどうかをシミュレーションします。 範囲が最大であるため、これはすぐには不可能です$10^{12}$、各シミュレーションには複数の対話型チェックが必要になります。 二分探索を使用して検索を絞り込もうとしても、上記の推測は無効な実験クエリになる危険を冒さずに中間点を安全にテストすることはできません。$p$即座に失敗を引き起こします。 

重要な観察は、アドバイス クエリが周囲の直接のしきい値を提供していることです。$\sqrt{p}$。 私たちは事実上、その期間のメンバーシップオラクルを与えられています$(\sqrt{p}, p]$、これにより両方を見つけることができます$\sqrt{p}$そして$p$許容されるクエリ範囲内の制限された不確実性まで。 概算すると$\sqrt{p}$、大まかなスケールが得られます。$p$、 以来$p \approx (\sqrt{p})^2$。 

実験クエリは検索ツールではなく絞り込みツールになります。 私たちが選ぶなら$t$に近い$p$、比率$p/t$は 1 に近く、戻り値は 1 に近い狭い範囲内にあります。より小さい値を選択すると、$t$、戻り値は広がりますが、それでも乗法関係をエンコードします。 慎重に選ぶことで$t$推定規模に基づく値$p$、不確実性を幾何学的に減らすことができます。 

最適な戦略は、まず特定することです$\sqrt{p}$アドバイスクエリを使用して再構築する$p$慎重に選択した実験を使用して候補範囲を繰り返し狭めることによって、$t$安全に下に$p$可能な値の間隔を縮小しながら。

 ## アルゴリズムのチュートリアル

 1. アドバイス クエリを使用して、周囲のしきい値領域を特定します。$\sqrt{p}$。 範囲内の値を試します$[1, 10^6]$、最大の値が見つかるまで、YES/NO の答えに基づいて適応します。$t$そのような$t \le \sqrt{p}$。 これにより、平方根境界の正確な推定値が得られます。 
2. 1回$\sqrt{p}$はおおよそわかっているので、それを二乗して最初の粗い推定値を取得します。$p$。 これにより、小さな乗算係数まで正しいスケールの候補が得られます。 
3. 初期実験値を選択する$t$安全に推定値を下回ります$p$。 目標は確実にすることです$t \le p$保ちながら$p/t$有益な出力を生成する範囲内で。 
4. 実験を実行し、戻り値を使用して推定値を調整します。$p$。 出力は次の場所にあるため、$[p/t, (p/t)^2]$、この関係を逆にして、範囲を推測できます。$p$与えられた$t$そして観察された$x$。 
5. より厳しい境界を再計算します。$p$それぞれの実験結果を用いて説明します。 各反復では、候補区間が乗算的に縮小されます。 
6. 間隔が単一の整数値になるまで繰り返します。 これを答えとして出力します。 

重要な不変条件は、すべてのステップで有効な間隔を維持することです。$[L, R]$そのような$p \in [L, R]$、すべての実験クエリは値を使用します$t \le L$、安全性を保証します。 実験ごとに比率が減少します$R/L$、許可されたクエリ数内で確実に収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask_advice(t):
    print(f"ADVICE {t}")
    sys.stdout.flush()
    return input().strip()

def ask_experiment(t):
    print(f"EXPERIMENT {t}")
    sys.stdout.flush()
    parts = input().strip().split()
    return parts[0], float(parts[1]) if len(parts) > 1 else None

def answer(p):
    print(f"SUCCESS {p}")
    sys.stdout.flush()

def main():
    # Step 1: find floor(sqrt(p)) using advice
    lo, hi = 1, 10**6
    sqrt_p = 1

    while lo <= hi:
        mid = (lo + hi) // 2
        res = ask_advice(mid)
        if res == "YES":
            sqrt_p = mid
            lo = mid + 1
        else:
            hi = mid - 1

    # Step 2: initial bounds
    L = sqrt_p * sqrt_p
    R = (sqrt_p + 1) * (sqrt_p + 1)

    # Step 3: refine using experiments
    for _ in range(18):
        t = max(1, int((L + R) ** 0.5))
        if t > L:
            t = L

        status, val = ask_experiment(t)
        if status == "BOOM":
            return

        # approximate inversion of interval [p/t, (p/t)^2]
        # we use midpoint heuristic in log space
        if val is None:
            continue

        approx_ratio = (val + val ** 0.5) / 2
        p_est = approx_ratio * t

        # widen slightly to avoid rounding issues
        L = max(L, int(p_est * 0.8))
        R = min(R, int(p_est * 1.2))

        if R - L <= 1:
            break

    answer(L)

if __name__ == "__main__":
    main()
```最初のフェーズでは、許可されたアドバイス範囲にわたって二分検索を実行して、最大のアドバイスを特定します。$t$それでも満足できる$t \le \sqrt{p}$。 アドバイス クエリは失敗する危険がないため、これは安全です。 

2 番目のフェーズでは、狭い間隔を初期化します。$p$推定ルートの二乗に基づきます。 この間隔は絶対的には広いかもしれませんが、元の検索空間よりもすでに多項式的に小さくなっています。 

実験ループが選択するのは、$t$現在の間隔の幾何平均として、安全に以下に保たれます。$p$作りながら$p/t$安定した規模に近い。 返された値はヒューリスティックに反転されて、洗練された推定値が回復されます。 ノイズ下での正確性を確保するために、間隔は控えめに更新されます。

 ## 特殊なケース

 重要なケースの 1 つが次のような場合です。$p$は完全な正方形です。 そのような状況では、アドバイスフェーズはまさに次の点に到達します。$\sqrt{p}$、第 2 フェーズでは、推定値を 2 乗する際のオーバーシュートを回避する必要があります。 間隔更新には常に境界の両側が含まれ、早期に崩壊するのを防ぐため、アルゴリズムはこれを処理します。
