 ## 解決策
 ## 問題の理解

 いくつかの独立した研究グループが与えられ、それぞれに必要なしきい値が設定されています。 グループが少なくともその閾値量のウランを受け取った場合、そのグループは「臨界状態」に達したとみなされる。 

重要な点は、ウランがグループ間でどのように分配されるかを私たちが制御していないことです。 私たちはウランの総量を選択するだけで、その後、敵対者はそれをグループ全体に任意の方法で自由に配布できます。 私たちは、分布がどのように行われたとしても、少なくとも 1 つのグループが必ずそのしきい値に達するか、それを超えることを保証したいと考えています。 

したがって、問題は賢明な配分戦略に関するものではありません。 これは最悪の場合の保証に関するものであり、グループ間でその合計が分割される可能性があるたびに、少なくとも 1 つのグループが必要なしきい値を超えることになる最小の合計金額はいくらかということです。 

各グループは、それを引き起こすことなく内部にどれだけのウランを「隠す」ことができるかについての制約に貢献します。 グループにしきい値がある場合$a_i$、その後、まで$a_i - 1$ユニットは起動を引き起こすことなく安全にそこに配置できます。 すべてのグループのトリガーを回避したい場合は、すべてのグループを厳密にしきい値以下に維持しようとします。 

敵対者の目標はまさにそれです。すべてのグループが最大でも受け取れるようにウランを配布することです。$a_i - 1$。 これが可能であれば、どのグループも重要ではなくなります。 

これにより、すぐにタスクが再構成されます。これを不可能にする最小の合計金額を探します。 

エッジケースはゼロしきい値から発生します。 どこかのグループが持っていれば、$a_i = 0$、ウランがまったく存在しない状態ではすでに臨界状態にあります。 たとえば、入力`n = 1, a = [0]`出力する必要があります`0`、保証はすでに満たされているためです。 

もう 1 つの微妙なケースは、すべてのしきい値が大きいものの、不均等である場合です。 例えば、`a = [5, 1, 10]`。 制限要因は、安全に配置できるものの合計です。各グループが吸収できるのは、$a_i - 1$。 

単純な解釈では、分布をシミュレートしたり、最悪の場合の割り当てを明示的にチェックしたりする可能性があります。 容量に焦点を当てると、それはすぐに不要になります。 

制約により許可されるのは、$n$まで$2 \cdot 10^5$、だからどれでも$O(n^2)$分布のシミュレーションは不可能です。 平$O(n \log n)$それは問題ありませんが、実際の構造は単一の直線パスに縮小されます。 

## アプローチ

 直接的な強引なアイデアは、与えられた合計金額を考慮することです。$S$の分布が存在するかどうかを尋ねます。$S$どのグループもそのしきい値に達しないように、グループ全体で。 これは実現可能性の問題になります: 値を割り当てることができるか$x_i$そのような$0 \le x_i \le a_i - 1$そして$\sum x_i = S$?

 もし与えられた場合$S$そのような分布が存在する場合、$S$アクティベーションを保証するには十分ではありません。 存在しない場合は、すべてのディストリビューションが$S$少なくとも 1 つのグループがそのしきい値を超えるように強制します。 

固定の場合$S$、このチェックは簡単です。「非表示」にできる最大量は次のとおりです。$\sum (a_i - 1)$。 もし$S$この合計を超えると、安全な分布は存在しません。 

したがって、ブルートフォースアプローチでは、増加させようとします$S$ゼロから上に向かって、毎回この条件をテストします。 それは、$O(n)$までチェックを繰り返した$O(\sum a_i)$、値が最大であることを考えると、これは完全に実行不可能です。$10^9$。 

重要な点は、検索する必要がないということです。$S$。 すべての合計である最大安全合計を直接計算できます。$a_i - 1$(負の値の場合はゼロに固定されます)。 それを超える追加ユニットは、少なくとも 1 つのグループをそのしきい値に到達させる必要があります。 

したがって、答えは正確に次のようになります。$$\left(\sum a_i\right) - (n - \text{count of zeros})$$あるいはもっときれいに、$\sum \max(0, a_i - 1)$、トリガーを保証したい場合はさらに 1 ユニット追加します。 ただし、タスクでは少なくとも 1 つのグループがしきい値に達することを保証する最小合計を要求するため、安全な容量よりも厳密に大きい最小値を採用するだけです。 

それは次のようになります:$$\sum (a_i - 1) + 1$$しかし、すべての場合にのみ$a_i > 0$。 多少なら$a_i = 0$、答えは次のようになります$0$、ウランがなくても条件はすでに満たされているためです。 

したがって、問題はコーナーケースでの単純な合計を計算することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(S・n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのしきい値を読み取り、各グループが危険にならずに安全に吸収できるウランの量を計算します。 閾値ありグループの場合$a_i$、この安全容量は$a_i - 1$ただし、ゼロ以下になることはありません。 これは、グループのトリガーを回避するための敵対者の最善の努力をモデル化します。 
2. すべてのグループにわたる合計安全容量を累積します。 これは、どのグループにもその閾値に達することを強制せずに配布できる最大のウラン総量を表します。 
3. しきい値がゼロのグループがあるかどうかを追跡します。 そのようなグループが存在する場合、それは何も受け取らなくてもすでに臨界状態にあり、これは、たとえ総ウランがゼロであっても必要な保証が満たされることを意味します。 
4. ゼロしきい値グループが存在する場合は、成功を保証するために正の量は必要ないため、すぐに 0 を返します。 
5. それ以外の場合は、安全容量の合計に 1 を加えた値を返します。 この追加単位は、考えられるすべての安全な分布を破り、少なくとも 1 つのグループがそのしきい値を超えることを強制する最小量です。 

### なぜ効果があるのか

 中心的な不変条件は、すべてのグループのトリガーを回避するウランの分布は、最大でも各グループに割り当てる必要があるということです。$a_i - 1$。 これらのグループごとの制限の合計により、分配が成功しない場合の最大総質量が決まります。 合計がこの限界を超えると、鳩の穴効果が避けられなくなります。少なくとも 1 つのグループが少なくともその閾値量を受け取らなければなりません。 したがって、解は、このグローバルな安全容量を超える正確な最小の整数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if any(x == 0 for x in a):
        print(0)
        return
    
    total_safe = 0
    for x in a:
        total_safe += x - 1
    
    print(total_safe + 1)

if __name__ == "__main__":
    solve()
```このコードは、他のすべての推論よりも優先されるため、最初にゼロしきい値のエッジ ケースをチェックします。 いずれかのグループがすでにしきい値 0 を持っている場合、答えはすぐに修正されます。 

それ以外の場合は、合計して安全容量の合計を計算します。$a_i - 1$。 これは、しきい値に達することを強制せずに配布できる最大ウランを直接エンコードします。 1 つ追加すると、この実現可能性を破る最小限の量が得られます。 

制約は純粋に追加的であり、グループ間で独立しているため、並べ替えや高度な構造は必要ありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if any(x == 0 for x in a):
        print(0)
        return
    
    total_safe = sum(x - 1 for x in a)
    print(total_safe + 1)

# provided samples

assert run("1\n2\n") == "2"

# minimum size, zero case
assert run("1\n0\n") == "0"

# all equal
assert run("4\n5 5 5 5\n") == "17"

# boundary mix
assert run("3\n1 1000000000 1\n") == "1000000000"

# many zeros
assert run("5\n0 10 20 30 40\n") == "0"

 ## 特殊なケース

 入力など、しきい値がゼロの単一グループの場合`1 / [0]`の場合、アルゴリズムは合計を計算せずにすぐに 0 を返します。 ループ条件はゼロを検出して早期に終了し、システムがすでに危機的な状態にあるという事実と一致します。 

次のような混合入力の場合`3 / [1, 1000000000, 1]`、安全容量は`0 + 999999999 + 0 = 999999999`、したがって、答えは次のとおりです`1000000000`。 中央の大きな値が全体を支配しており、2 つの値は何も寄与していないため、1 を超える値のみが容量に影響を与えることがわかります。
