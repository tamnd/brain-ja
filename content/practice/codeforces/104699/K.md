 ## 解決策
 ## 問題の理解

 私たちは、Barbies と Kens という 2 つの異なるグループに属する文字列の動的なコレクションを維持しています。 更新ごとに、グループの 1 つに文字列が挿入されるか、以前に挿入された文字列が削除されます。 更新のたびに、バービー セットから 1 つの文字列とケン セットから 1 つの文字列を取得して、それらの連結が回文を形成することによって形成できる有効なペアがいくつあるかを報告する必要があります。 

カウントされるキー オブジェクトは個々の文字列ではなく、グループ間のペアです。 バービーの紐なら`b`そしてケンストリング`k`が選択されているかどうかを確認します`b + k`前方と後方で同じように読みます。 各操作後の答えは、現在のすべての文字列に対するそのような有効なペアの合計数です。 

制約は 2 つの点で大きいです。 操作の数は 100 万に達する可能性があるため、どのソリューションでもほぼ一定の時間で各更新を処理する必要があります。 同時に、挿入されるすべての文字列の合計長は 500 万に制限されます。つまり、更新間で完全な文字列を繰り返し比較するアプローチは、操作ごとの線形スキャンにより失敗します。 

単純なアプローチでは、更新のたびに 2 つのグループ間のすべてのペアをチェックして、答えを最初から再計算します。 あれば`n`バービー人形と`m`ケンズ、これは`O(nm)`これは、中程度のサイズであってもすぐに実行不可能になります。 逆文字列を事前計算して最適化しても、二次ペアリングの問題が残ります。 

単純なハッシュ手法が微妙に失敗するケースは、更新が頻繁に削除される場合に発生します。 たとえば、同じ文字列の追加と削除を繰り返した場合、すべてのペアを毎回再計算すると、たとえ最終的な変更が小さいとしても、データセット全体を繰り返し走査することになります。 

もう 1 つのよくある間違いは、回文性には文字の比較またはペアごとのローリング ハッシュの使用のみが必要であると想定することです。 ハッシュを使用しても、クエリごとにすべてのクロスペアを再計算するのは依然として遅すぎます。 

## アプローチ

 中心的な観察は、連結対称性が非常に剛直な構造を課すということです。 2本の弦の場合`b`そして`k`、文字列`b + k`は、2 番目の文字列が最初の文字列の逆である場合に限り、回文になります。 これは、連結境界を越える対称位置の一致、つまりすべての文字から得られます。`b`の文字をミラーリングする必要があります`k`逆の順序で行うと、部分的なオーバーラップに対する柔軟性がなくなります。 

これにより、問題は周波数一致タスクに縮小されます。 すべてのペアをチェックする代わりに、各文字列が Barbies で何回出現するか、およびその反転バージョンが Kens で何回出現するかを知る必要があるだけです。 各更新は 1 つの文字列にのみ影響するため、カウントを増分的に維持できます。 

ブルート フォース アプローチでは、更新のたびにすべての有効なペアを再計算し、両方のグループに保存されているすべての文字列を反復処理します。 これは定義を直接評価するため概念的には機能しますが、操作ごとに二次時間がかかります。 重要な洞察は、各文字列が独立して寄与しているため、その文字列の逆に関連付けられた寄与を追加または削除することで、累計を維持し、更新ごとに一定時間で調整できることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(nm) | O(n + m) | 遅すぎる |
 | 最適 | クエリごとの O(L) | O(n + m) | 承認済み |

 ここ`L`更新された文字列の長さです。 

## アルゴリズムのチュートリアル

 私たちは、バービーとケンの文字列の出現をカウントする 2 つのハッシュ マップと、有効なペアの累計を維持しています。 

1. 2 つの周波数マップ (バービー用とケン用) を初期化し、答えを 0 に設定します。 マップには、それぞれの正確な文字列が現在何回存在するかが保存されます。 
2. 操作ごとに、タイプ、グループ、および文字列を読み取ります。 構造を変更する前に、この文字列が追加または削除された場合にその寄与を計算します。 これにより、グローバル カウントが正しく更新されます。 
3. 操作がバービー人形への挿入である場合、現在この文字列の逆に等しい Ken の数を計算します。 この値は`freqKen[reverse(b)]`、それを答えに追加します。 次にインクリメントします`freqBarbie[b]`。 
4. 操作が Barbies からの削除である場合、最初にデクリメントします。`freqBarbie[b]`、次に減算します`freqKen[reverse(b)]`答えから。 減算は、文字列が以前に追加した寄与を反映します。 
5. 同じロジックが Kens にも対称的に適用されます。挿入すると追加されます。`freqBarbie[reverse(k)]`、削除はそれを差し引きます。 
6. 各操作の後に、現在の答えを出力します。 

削除時には、減分と寄与分の削除の順序が重要になります。 文字列がまだ存在する状態を使用して寄与度を計算し、それを削除する必要があります。そうしないと、正しいカウントが失われます。 

### なぜ効果があるのか

 アルゴリズムは次の不変条件を維持します。`answer`すべてのバービー文字列の合計と常に等しい`b`の`freqBarbie[b] * freqKen[reverse(b)]`。 各更新では、正確に 1 つの周波数エントリが変更されるため、逆一致に関してその文字列の寄与分だけ合計が変更されます。 他のすべてのペアは影響を受けないため、合計をローカルに調整するだけで十分であり、すべての操作を通じて正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    from collections import defaultdict
    
    barbie = defaultdict(int)
    ken = defaultdict(int)
    ans = 0
    
    out = []
    
    for _ in range(t):
        parts = input().split()
        if not parts:
            continue
        
        tp = parts[0]
        grp = parts[1]
        s = parts[2].strip()
        
        rs = s[::-1]
        
        if grp == '+':
            if tp == '1':
                ans += ken[rs]
                barbie[s] += 1
            else:
                ans += barbie[rs]
                ken[s] += 1
        else:
            if tp == '1':
                barbie[s] -= 1
                ans -= ken[rs]
            else:
                ken[s] -= 1
                ans -= barbie[rs]
        
        out.append(str(ans))
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は増分更新戦略に直接に従います。 逆文字列は操作ごとに 1 回計算されるため、全長の制約の下では効率的です。 ハッシュ マップにより、頻度の更新とクエリに対して予想される一定時間のアクセスが保証されます。 

重要な点は、寄与が常に反転文字列に基づいており、部分一致や部分文字列のロジックには決して基づいていないことです。 これにより、任意の挿入や削除が行われてもソリューションの安定性が保たれます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、同じ文字列の挿入と削除を繰り返すことです。 各挿入では現在の逆一致数が正確に追加され、各削除では正確に同じ数が削除されるため、アルゴリズムはこれを処理します。 文字列が何度も出現する場合でも、頻度マップにより寄与が正しくスケールされることが保証されます。 

もう 1 つのエッジ ケースは、文字列がそれ自体の反転である場合です。`"aba"`。 その場合、グループ間の頻度のみが問題となり、同じロジックが変更なしで適用されます。`reverse(s) == s`。 

最後のケースは、すべての文字列が一意である場合です。 各更新では 1 つの辞書エントリのみにアクセスするため、アルゴリズムは引き続き機能します。そのため、グローバルな再計算を必要とせず、純粋にローカルな調整によって答えが進化します。
