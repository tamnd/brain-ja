 ## 解決策
 ## 問題の理解

 高さのある非常に大きなグリッドが与えられています$h$と幅$w$ただし、意味のあるセルは少数です。 ほとんどのセルは空ですが、動きを妨げる岩が含まれているセルや、パスがセルを通過するとスコアが増加する値が含まれているセルもあります。 

パスは左上のセルから始まります$(1,1)$右下のセルで終わる必要があります$(h,w)$。 各ステップでは、左、右、または下への移動のみが許可されます。 上に移動することは禁止されています。つまり、パスは行ごとに上から下に進みますが、行内では下に進む前に水平にさまようことができます。 

パスが報酬値を持つセルに入るたびに、その値が合計スコアに追加されます。 岩のある独房は一切立ち入ることができません。 

タスクは、収集された報酬の合計を最大化する有効なパスを選択することです。 

この制約がこの問題を興味深いものにしています。 グリッド幅は最大です$10^9$したがって、すべての列を保存したり反復したりすることは不可能です。 特別なセルの数は最大で$10^5$したがって、ソリューションはグリッド全体ではなく、主にこれらのセルに依存する必要があります。 行と列を明示的に反復するソリューションには、最大で$10^{14}$最悪の場合、操作が不可能になる可能性があります。 

主要な構造上の制約は、動きが列内で単調であることです。 Once we move down from a row, we never return. これは、行による動的プログラミング アプローチを強く示唆しています。 

素朴な考えを打ち破る微妙なエッジケースがいくつかあります。 

行に岩が含まれていない場合、前の行の任意の列から次の行の任意の列に最適な値を自由に運ぶことができると誤って仮定する可能性があります。 垂直遷移は列固定であるため、これは false です。下に移動すると列インデックスが保持されます。 

別の失敗例は、岩が列を分割するときに発生します。 For example, consider a row like:```
. + . # + .
```単純な左から右へのスイープでは誤って影響が岩を通過する可能性がありますが、実際には岩が水平方向の接続をブロックするため、同じ行内の左側から岩の右側の値に到達することはできません。 

最後に、よくある間違いは、セルに垂直にステップした場合にのみ報酬を収集できると想定していることです。 実際、水平方向のトラバースを含め、パスがセルを通過するたびに報酬が収集されます。これにより、行内伝播のモデル化方法が変わります。 

## アプローチ

 ブルートフォース解釈では、各セルがノードであり、エッジが左、右、および下に隣接するセルを接続するグラフとしてグリッドを扱います。 このグラフ上で最短パスまたは最長パス スタイルの DP を実行することは、概念的には簡単です。 ただし、グリッドには最大で次のものが含まれます。$10^5 \times 10^9$そのため、ごく一部のノードに明示的にアクセスすることさえ不可能になります。 最悪の場合の状態の数は、実行可能な計算をはるかに超えています。 

重要な観察は、垂直方向の移動は厳密に列からのものであるということです。$i$漕ぐ$i+1$、行内では移動自体に関連するコストは発生しません。 これは、各行が 1D セグメント問題のように動作することを意味し、岩石によって行が独立したコンポーネントに分割される点を除き、接続されたセグメント内で DP 値を自由に再配分することができます。 

個々のセルの観点から考えるのではなく、各列を岩石間の間隔の集合として扱います。 各間隔内で、ある位置での最良の値は、前の行からその間隔への最良のエントリ ポイントと、水平パスに沿って蓄積された報酬によって決まります。 

これにより、問題は各行を個別に処理し、固定列で DP 値を垂直に伝播し、その後、岩のない各セグメント内で左から右および右から左への緩和を実行するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 グリッドを行ごとに処理し、すべての列ではなく重要な列で達成可能な最高のスコアのみを維持します。 

1. 各行の特別な列 (報酬セルや岩など) をすべて抽出し、並べ替えます。 また、最初の列と最後の列が遷移に重要な場合にはそれらが考慮されるようにします。 これが必要なのは、水平方向の移動では、何かが起こった位置でのみ意味のある状態が変化するためです。 
2. 辞書を管理する`dp_prev`前の行の関連する各列で達成可能な最高のスコアを保存します。 最初だけ、$(1,1)$値は 0 です。 
3. 現在の行について、最初に暫定的な垂直遷移を計算します。 列ごとに$j$この行に存在し、岩ではないものは、次のように設定します。$$dp_{cur}[j] = dp_{prev}[j] + value(j)$$細胞が岩の場合、それは完全に無視されます。 このステップは、上からセルに入る唯一の方法は同じ列から直接入力することであるという事実をモデル化します。 
4. ここで、行内の水平方向の動きを考慮する必要があります。 岩は列を独立したセグメントに分割します。 各セグメント内で 2 つのスイープを計算します。 

左から右へのスイープでは、フォームの最適な値を追跡します。$$dp_{cur}[k] - prefix\_sum(k)$$これにより、右側の値を効率的に更新できるようになります。 

右から左へのスイープでは、情報を反対方向に対称的に伝播します。 これにより、方向に関係なく、セグメント内の任意の 2 点間の最適なパスが確実に考慮されます。 
5. すべてのセグメントを処理した後、上書きします`dp_prev`と`dp_cur`、次の行に意味のある位置のみを保持します。 
6. すべての行を処理した後の答えは、次の場所に保存されている値になります。$(h,w)$、有効な伝播を通じて到達した必要があります。 

### なぜ効果があるのか

 固定列セグメント内では、移動コストはゼロで、岩を除いて方向制限もありません。 これにより、セグメント内のすべてのパスは、エントリ ポイントを選択し、すべての中間報酬を収集しながら任意のターゲット セルにスイープすることと同等になります。 DP 変換は、次の不変式を保持します。`dp_prev[j]`行に入ったときに達成可能な最高のスコアを表します$i$列で$j$。 水平緩和ステップでは、移動制約に違反することなく、行内の到達可能なすべての状態のクロージャを計算します。 行は昇順に処理され、垂直方向の移動は列ストレートであるため、将来の行が過去の決定を遡って改善することはできず、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict

NEG = -10**30

def solve():
    h, w, n = map(int, input().split())

    rows = defaultdict(list)
    has_start = False

    for _ in range(n):
        parts = input().split()
        i = int(parts[0])
        j = int(parts[1])
        if parts[2] == '#':
            rows[i].append((j, None))
        else:
            val = int(parts[3])
            rows[i].append((j, val))

    dp_prev = {1: 0}

    for i in range(1, h + 1):
        cells = rows.get(i, [])

        # collect columns in this row
        cols = set(dp_prev.keys())
        for j, v in cells:
            cols.add(j)

        cols = sorted(cols)

        blocked = set()
        reward = {}
        for j, v in cells:
            if v is None:
                blocked.add(j)
            else:
                reward[j] = v

        dp_cur = {j: NEG for j in cols}

        # vertical transitions
        for j in cols:
            if j in blocked:
                continue
            if j in dp_prev:
                dp_cur[j] = dp_prev[j] + reward.get(j, 0)

        # horizontal propagation per segment
        new_dp = dp_cur.copy()

        # left to right
        best = NEG
        for j in cols:
            if j in blocked:
                best = NEG
                continue
            best = max(best, dp_cur[j])
            if best != NEG:
                new_dp[j] = max(new_dp[j], best + reward.get(j, 0))

        # right to left
        best = NEG
        for j in reversed(cols):
            if j in blocked:
                best = NEG
                continue
            best = max(best, dp_cur[j])
            if best != NEG:
                new_dp[j] = max(new_dp[j], best + reward.get(j, 0))

        dp_prev = new_dp

    ans = dp_prev.get(w, 0)
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、行ごとの動的プログラミング状態のスパース表現が維持されます。 辞書`dp_prev`全幅にわたる反復を回避し、遷移に重要な列のみが含まれます。 

垂直遷移ステップでは、行から行への移動で列インデックスが保持されるというルールが適用されます。 水平スイープは、岩に遭遇するたびにリセットしながら、列セグメント内での自由な動きをシミュレートします。 

の使用`NEG`到達不可能な状態がスイープ中に値を誤って伝播しないようにします。 これがないと、無効な遷移によって到達可能なセグメントが汚染される可能性があります。

 ## 特殊なケース

 岩石に遭遇するたびにスイープによって最適な伝播値がリセットされるため、孤立した単一セル セグメントに完全に分割された行は正しく処理されます。 これにより、行の切断された部分に DP 値が漏れるのを防ぎます。 

行内のすべての列が開始列または終了列を除いてブロックされている場合、垂直遷移は当然有効な状態を生成せず、DP は実行可能な位置のみを正しく伝播します。 

同じ接続されたセグメントに複数の報酬が存在する場合、最適なプレフィックスが継続的に繰り越されるため、水平スイープによってすべての報酬が確実に寄与するため、走査順序に関係なく報酬がスキップされません。
