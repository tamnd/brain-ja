 ## 解決策
 ## 問題の理解

 との店舗がございます。`n`それぞれに特定の価格が設定されているアイテム。 その店では、顧客が少なくとも購入すると、`x`アイテム、`y`それらのアイテムの中で最も安いものは無料です。 クエリごとに`(x, y)`、顧客が無料で入手できるアイテムの最大合計価値を決定したいと考えています。 

入力は商品価格を配列として与えます。`p`サイズの`n`その後`q`独立したクエリ。 各クエリはプロモーションパラメータを指定します`(x, y)`、出力はクエリごとに 1 つの整数、つまり最も安価なクエリの最大合計です。`y`選択したアイテムの中から`x`アイテム。 

主な制約は次のとおりです。`n`そして`q`アイテムの価格は最大 200,000、アイテムの価格は最大 100 万になります。 サイズのすべてのサブセットを反復する単純なアプローチ`x`サブセットの数は組み合わせ的に増加するため、これは不可能です。 可能な限りすべてを繰り返しても`x`-アイテムの選択は明示的に超過します`10^10`最悪の場合の運用。 に関してほぼ線形時間で機能するソリューションが必要です。`n`、 理想的には`O(n log n)`プラス`O(1)`クエリごとに。 

明らかではないエッジケースとしては、すべての商品が同じ価格である場合や、`x`等しい`n`顧客にすべてを購入するよう強制したり、`y`等しい`x`したがって、選択したアイテムはすべて無料です。 たとえば、価格が次の場合、`[5, 5, 5]`そしてクエリは`(3, 3)`、無料の値は`15`。 常に世界的に最も安い商品を選択しようとする不用意なアプローチは、他の商品の合計を誤って計算する可能性があります。`x`価値観。 

## アプローチ

 ブルートフォースアプローチは、サイズの可能なすべてのサブセットを生成することです。`x`クエリの場合、各サブセットをソートし、`y`最も安い商品を選択し、その価格を合計します。 これは論理的に機能しますが、法外に高価です。 中程度の場合でも`n = 20`、考慮すべきサブセットは 100,000 を超えており、`n = 2 * 10^5`完全に難治性だ。 

重要な観察は、`y`無料アイテムを選択したい`x`可能な限り最も高価なアイテム、`y`その中で最も安いものでも、選択範囲外のより安価な商品よりも価値が高くなります。 配列全体を降順に並べ替えると、最初の配列を選択できるようになります。`x`すぐにアイテムを。 では、その中で、`x`アイテム、`y`最も安い値は、プレフィックス合計配列を使用して合計できます。 これにより、問題は 1 つの並べ替え操作とクエリごとの単純な算術に軽減されます。 

無料アイテムは常に選択されたアイテムから取得されるため、この貪欲な洞察は正しいです。`x`したがって、無料アイテムの合計を最大化することは、最も高価なアイテムを獲得することと同じです。`x`そしてそれらを合計すると`y`最安。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n は x * x log x を選択します) | クエリごとに O(x) | 遅すぎる |
 | 最適 | O(n log n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. アイテム数を読み取る`n`そしてクエリの数`q`。 商品の価格を配列に読み込みます`p`。 
2. 並べ替え`p`降順で。 これにより、最初の`x`の要素`p`あらゆるクエリに対して`(x, y)`最も高価な選択肢です。 
3. プレフィックス合計配列を構築する`prefix`どこ`prefix[i]`最初の合計です`i`の要素`p`。 これにより、連続したセグメントの合計を高速に計算できます。 
4. 各クエリについて`(x, y)`、`x`最も高価なアイテムが最初です`x`の要素`p`。 このうち、`y`最安は最後です`y`このセグメントの要素。 それらの合計を次のように計算します`prefix[x] - prefix[x-y]`。 
5. 各クエリの合計を出力します。 

機能する理由: 並べ替えにより、`x`無料アイテムの合計を最大化するサイズの選択が最初です`x`要素。 プレフィックス合計により、定数時間の計算が可能になります。`y`その選択肢の中で最も安いもの。 より高価な項目を最初のセットの外側に移動するため、アルゴリズムは次善のセットを選択することはありません。`x`無料アイテムの合計が減ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
p = list(map(int, input().split()))

p.sort(reverse=True)

# prefix[i] = sum of first i elements
prefix = [0] * (n + 1)
for i in range(n):
    prefix[i + 1] = prefix[i] + p[i]

for _ in range(q):
    x, y = map(int, input().split())
    # sum of y cheapest in first x items
    print(prefix[x] - prefix[x - y])
```コードは最初に価格を降順に並べ替えて、常に最も高価なものを選択できるようにします。`x`アイテム。 プレフィックス合計配列を使用すると、連続したセグメントの合計を一定時間で計算できます。 微妙な点は、インデックス付けです。`prefix[x] - prefix[x - y]`:`prefix[x]`最初の合計`x`項目と減算`prefix[x - y]`より高価な金額の合計を削除します`x-y`項目だけを残して、`y`最安。

 | クエリ 1 | [5,5,3,2,1] | [0,5,10,13,15,16] | 3 | 2 | 13-5=8 |

 これは、ソートとプレフィックスの合計により、`x`項目と合計`y`クエリあたり O(1) で最も安価です。 

**エッジケースの例**

 価格`[1,1,1]`、クエリ`(3,3)`。 並べ替えられた価格`[1,1,1]`、プレフィックス`[0,1,2,3]`。 最初の 3 つのうち最後の 3 つの合計は次のとおりです`3-0=3`。 これにより、アルゴリズムのハンドルが確認されます。`y=x`正しく。

 ## 特殊なケース

 すべての価格が等しい場合でも、アルゴリズムは正しく合計します。`y`一番安いので、`prefix[x] - prefix[x-y]`平等に関係なく機能します。 のために`y=x`、最初にすべての合計`x`項目は正しく計算されます。 もし`y=1`、それでも最初の最後のものを選択します`x`ソート後のアイテムを削除し、そのセグメントの最小値を確保します。 これにより、特殊なケースを使用せずにすべての微妙な境界が処理されます。
