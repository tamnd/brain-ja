 ## 解決策
 ## 問題の理解

 頂点 1 が開始点であり、すべてのノードが猫が通過した可能性のある位置を表す根付きツリーが与えられます。 猫はノードを再訪問することなくルートからツリーの下に移動するため、そのパスは単純にルートから葉までのパスになります。 

すべての頂点にモニターがあります。 頂点 i でモニターを検査することを選択した場合、コスト ai を支払います。 この検査により、猫がその頂点を訪れたかどうか、また、葉でない場合は猫がその頂点からどの子に移動したかが明らかになります。 言い換えれば、ノードを検査すると、そのノードの隠しパスの次のステップが明らかになります。 

葉を直接検索することもできます。 最初の i 個の葉を (固定された葉の順序で) 検索すると ti がかかります。ここで ti は i とともに減少しません。 葉の検索は、猫がそこで終わったかどうかを直接解決します。 

目標は、検査する頂点モニターのサブセットを選択し、総当たり検索するリーフの数を選択して、収集されたすべての情報を組み合わせた後、ルートからリーフへのパスが 1 つだけ観測結果と一致するようにすることです。 そのような戦略の中で、私たちは総コストを最小限に抑えたいと考えています。 

この構造は、単に葉を識別するだけでなく、内部ノードが分岐の決定点のように機能するルート付きツリーの不確実性を解決することも目的としています。 各モニターはローカルで不確実性を軽減し、リーフ検索はエンドポイント全体をグローバルに排除します。 

テスト ケースあたり n ≤ 2000 という制約は、テスト ケースあたり O(n²) または O(n log n) 付近の解決策を強く示唆しています。 ノードのすべてのサブセットまたはすべてのルートからリーフへのパスを列挙するようなことは指数関数的であり、すぐには実行不可能です。これは、縮退した場合にはツリーのルートからリーフへのパスが指数関数的に多くなる可能性があるためです。 

単純なアプローチでは、どのノードを検査するか、どのリーフをテストするかを推測しようとします。 たとえば、チェーン状のツリーでは、各ノードを検査するかスキップするかを決定すると 2ⁿ の可能性が生じますが、これは n = 2000 の場合でも不可能です。 

木がスターである場合、微妙なエッジケースが現れます。 根が多くの葉に直接つながっていると仮定します。 次に、ルートを検査するか (出力エッジを介して正確なリーフを即座に識別します)、ルートをスキップして葉を順番に検索する必要があります。 サブツリー構造を考慮せずに ai と ti を比較する単純な貪欲な戦略は、ここでは失敗します。ノードの検査がサブツリー全体に与える影響は分岐に応じて異なるためです。 

## アプローチ

 重要な問題は、ノードの検査が単に「コストがかかり、ローカルな何かが明らかになる」だけではなく、実際にはサブツリー全体の決定を決定論的な選択にまとめてしまうということです。 これは、サブツリーにわたる再帰的な構造を示唆しています。 

総当り的な考え方は、すべてのノードについて、それを検査するかどうかを決定することです。 それを検査する場合、ai を支払い、事実上、正確に 1 つの子サブツリーに従うように強制します。 それを検査しない場合、構造情報が失われるため、そのサブツリー内の可能性を区別するためにリーフ検索に依存する必要があります。 

すべてのノードの決定はそのすべての子孫に依存するため、これは状態の爆発につながります。 最悪の場合、各ノードには検査の有無にかかわらず 2 つの状態があり、O(2ⁿ) になります。 決定はサブツリーの不確実性によって密接に結合されているため、枝刈りさえもあまり役に立ちません。 

重要な観察は、問題は根本的に、猫の通り道があいまいなままであるコンポーネントにツリーを分割することにあるということです。 ノードが検査されない場合、明示的に検索しない限り、そのサブツリー内のすべての葉は区別できないままになります。 検査されると、サブツリーはその時点で決定的となり、そのブランチ内でのリーフ検索は必要ありません。 

これにより、問題はツリー DP に変換され、各サブツリーが、モニターまたはリーフ検索のどちらで解決するかに応じて、その中の猫を一意に決定するのにどれだけのコストがかかるかを記述するコスト関数に寄与します。

各ノード u で DP を定義します。u のサブツリー内の猫のパスを解決する 2 つの方法を検討します。 

1 つの方法は、au を支払って u のモニターを「アクティブ化」することです。これにより、どの子供が連れて行かれたのかが正確に明らかになります。 これにより、パスが固定されるため、問題は 1 つの子サブツリーのみを解決できるようになります。 

もう一つの方法は、あなたを検査しないことです。 その場合、u のサブツリー内の不確実性は純粋にリーフ検索によって解決されなければなりません。 リーフのコストは t_i によってグローバルに定義され、t_i はソートされるため、正しいリーフを区別するためにどれだけのリーフを支払わなければならないかという選択問題になります。 

これは当然、サブツリーの寄与を結合し、曖昧なままの葉の数を維持することにつながります。 

重要な単純化は、各ノードが事実上要件に寄与していることを認識することです。ノードを検査しない場合、リーフ検索コストを支払うまで、そのサブツリー内のすべてのリーフは区別できないままになります。 それを検査すると、分岐要素が減り、決定が下方に押し下げられます。 

この構造により、各サブツリーが可能な数の未解決のリーフに対してコスト プロファイルを計算するボトムアップ DP が可能になります。 

2 番目の重要な観察は、ti が減少しないため、k 個の葉を選択するということは常に最も安価な k 個の葉探索操作を行うことを意味するということです。 したがって、リーフの処理は、ソートされたリーフのプレフィックス合計に減ります。 

したがって、最適なソリューションは、分岐を早期に解決するために AI に支払うか、解決を延期してリーフ コストを後で支払うという 2 つのリソースのバランスを取ることになります。 

DP は最終的に、リーフ数に対してナップザックのような方法でサブツリー状態を結合しますが、n ≤ 2000 であるため、子に対して慎重に構造化された O(n²) マージで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ノード選択に対するブルートフォース | O(2ⁿ) | O(n) | 遅すぎる |
 | 未解決の葉の上のツリー DP | O(n²) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを 1 にルートし、事後走査を実行します。 

各ノード u で DP 配列 dp[u][k] を維持します。これは、そのサブツリー内の正確に k 個の葉がまだ解決されておらず、リーフ検索操作で処理する必要があると仮定して、u のサブツリーを一意に決定するための最小コストを意味します。 

また、t_i のプレフィックス合計も維持します。ここで、prefix[k] は、k 個のリーフを検索するコストです。 

### ステップ

 1. ツリーを 1 でルートし、走査順序を計算します。 これにより、リーフから上に向かって DP が計算されるため、子は常に親より先に解決されます。 
2. すべてのリーフ ノード u について、dp[u][0] = 0 および dp[u][1] = 0 を初期化します。解釈としては、リーフはすでに構造的に決定されており、後でグローバル リーフ メカニズムを通じてその料金を支払うことを選択する場合と選択しない場合があります。 
3. 内部ノード u の場合、u 自体によって提供される単一の未解決の状態を表す dp[u] から開始します。 これは、子を処理する前に、サブツリーが 1 単位の不確実性をもたらすことを反映しています。 
4. u の子 v ごとに、未解決のリーフ数の畳み込みを使用して dp[u] と dp[v] をマージします。 マージでは、サブツリー間で未解決のリーフを分散するあらゆる方法が考慮され、そのコストが合計されます。 独立したサブツリー全体にわたって不確実性が蓄積されるため、このステップが必要です。 
5. 子の処理後、u でモニターをアクティブ化することを検討します。 au を支払う場合、どの子パスが選択されるかが完全に解決されるため、すべての子を結合する代わりに、dp[u] を、最良の子寄与分と au のみを保持する状態に置き換えます。 これは、u での検査が分岐を折りたたむことをモデル化します。 
6. あなたにとって、検査しないという選択肢も検討してください。 この場合、dp[u] 内のすべての未解決のリーフは、最終的にリーフ検索コストによって解決される必要があります。 したがって、k ごとに prefix[k] を dp[u][k] に追加します。 
7. 各ノードについて、すべての有効な戦略の最小値を取得し、未解決のリーフ数ごとに dp が最小値を維持するようにします。 
8. ルートで、dp[1][k] + prefix[k] のすべての k の最小値を計算します。これは、残りの未解決のリーフがリーフ検索によって支払われる必要があるためです。 

### なぜ効果があるのか

DP 状態は、サブツリーの決定がモニターによって構造的に解決されるか、リーフ クエリに延期されるかという、曖昧さの正確な原因を中心に構造化されています。 すべての操作は、分岐 (ai の支払い) を減らすか、構造を区別できない葉の平らなセットに変換します。 猫のパスはルートからリーフへの単一のチェーンであるため、サブツリーはこの解像度境界を除いて独立しています。この解像度境界はまさに DP がエンコードするものです。 2 つの異なる DP 遷移が同じ最終情報状態を表すことはできないため、すべての状態の最小値が最適な戦略を正確に捕捉します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        a = [0] + list(map(int, input().split()))
        t = [0] + list(map(int, input().split()))

        adj = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            x, y = map(int, input().split())
            adj[x].append(y)
            adj[y].append(x)

        parent = [0] * (n + 1)
        order = []
        stack = [1]
        parent[1] = -1

        while stack:
            u = stack.pop()
            order.append(u)
            for v in adj[u]:
                if v == parent[u]:
                    continue
                parent[v] = u
                stack.append(v)

        children = [[] for _ in range(n + 1)]
        for v in range(2, n + 1):
            children[parent[v]].append(v)

        INF = 10**30

        dp = [None] * (n + 1)

        # prefix sums of leaf costs
        prefix = [0] * (n + 2)
        for i in range(1, n + 1):
            prefix[i] = prefix[i - 1] + t[i]

        def dfs(u):
            if not children[u]:
                dp[u] = [0, 0]
                return

            cur = [0] + [INF] * len(children[u])

            for v in children[u]:
                dfs(v)
                ndp = [INF] * (len(cur) + len(dp[v]) - 1)
                for i in range(len(cur)):
                    if cur[i] >= INF:
                        continue
                    for j in range(len(dp[v])):
                        if dp[v][j] >= INF:
                            continue
                        ndp[i + j] = min(ndp[i + j], cur[i] + dp[v][j])
                cur = ndp

            # option: pay a[u] and collapse decision at u
            best_child = INF
            for v in children[u]:
                best_child = min(best_child, dp[v][0])
            if best_child < INF:
                cur = [min(cur[i], best_child + a[u]) if i < len(cur) else best_child + a[u]
                       for i in range(len(cur))]

            dp[u] = cur

        dfs(1)

        ans = INF
        for k in range(len(dp[1])):
            if k <= n:
                ans = min(ans, dp[1][k] + prefix[k])

        print(ans)

if __name__ == "__main__":
    solve()
```実装はポストオーダー DP に従います。 隣接リストは明示的にルート化されるため、各ノードは明確な親子構造を持ちます。 dp 配列はサブツリーのサイズとともに増加し、畳み込みは未解決のリーフの数を維持しながら子の寄与をマージします。 

プレフィックス合計配列は、「k 個の葉の検索」を O(1) ルックアップに変換します。そうしないと、ti を繰り返し合計すると複雑さが高くなりすぎるため、これは不可欠です。 

微妙な部分は、子を結合した後に「ノード u で崩壊」オプションが確実に適用されるようにすることです。これは、その時点で不確実性の意味が変わるためです。 この順序により、部分的なサブツリー情報が誤って折りたたまれることがなくなります。 

## 実用的な例

 ノード 1 に 2 つのリーフの子 2 と 3 がある単純なツリーを考えます。モニター コストは a1 = 5、a2 = 2、a3 = 2、リーフ検索コストは t1 = 3、t2 = 6、t3 = 10 です。 

葉では、dp[2] と dp[3] は [0, 0] として始まります。 

ノード 1 で子を結合すると、dp[1][0] = 0、dp[1][1] = 0、dp[1][2] = 0 が得られます。これは、両方の葉が未解決のままであるか、構造的に解決されている可能性があるためです。 

ここで、ノード 1 を検査すると、5 を支払い、どの子が取得されたかがすぐにわかるので、dp[1][0] は折りたたみによって 5 になる可能性があります。 

最終的な答えは、dp[1][k] + prefix[k] を考慮します。 k = 0 の場合、コストは 5。k = 1 の場合、コストは 3。k = 2 の場合、コストは 9。最小値は 3。つまり、監視をスキップし、最初のリーフのみを検索します。 

ここで、4 が唯一の葉であるチェーン 1-2-3-4 を考えてみましょう。 

| ノード | dp 状態 | 解釈 |
 | --- | --- | --- |
 | 4 | [0,0] | 葉の基部 | 写真
 | 3 | [0,0] | まだ単一のパス |
 | 2 | [0,0] | まだ単一のパス |
 | 1 | [0,0] | フルパス |

 唯一意味のある決定は、任意の AI が t1 よりも安いかどうかです。 これは、DP が線形比較に正しく縮退していることを示しています。 

これらの例は、DP が特別なケースを使用せずに分岐と縮退チェーンの両方の動作をキャプチャすることを示しています。

 ## 特殊なケース

 単一ノードのツリーは、猫がすでに葉の上にいる最も単純なケースです。 DP はただちに未解決のリーフをゼロに割り当て、監視コストも必要ないため、答えはゼロです。 

ディープチェーンは、DP が不必要な分岐ロジックを正しく回避するかどうかをテストします。 すべてのノードには子が 1 つだけあるため、畳み込みは何も行わず、解決策はパスに沿ったモニター コストとリーフ検索コストを比較することに帰着します。これは人為的なインフレなしで一貫して動作するはずです。 

星形の木は、根元の崩壊が適切に処理されているかどうかをテストします。 ルート モニターのコストが大きく、リーフ検索のコストが小さい場合、アルゴリズムはリーフ検索を優先する必要があります。 ルート コストが小さい場合は、構造全体を 1 つのステップで即座に解決する必要があります。
