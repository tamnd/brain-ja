 ## 問題の理解

 私たちに与えられたシナリオは、$n$異なる人々が配置される$m$ステーションにはラベルが付けられており、各ステーションにはキューが保持されます。 ここでのキューは単なるセットではなく、順序付けられたリストであるため、各ステーション内の人の内部順序が重要になります。 

固定されていないのは、駅への人の配置と各駅内の順序の両方です。 すべてのステーションについて、どのサブセットの人々がそこに行き、どのような順序で現れるかを決定すると、すべての有効な構成が完全に記述されます。 

割り当てられた人のセットが異なるか、順序が異なるステーションが少なくとも 1 つ存在する場合、2 つの構成は異なるものとみなされます。 

したがって、タスクは純粋に組み合わせです。分割できる方法が何通りあるか数えてください。$n$ラベル付き要素を$m$ラベル付きの順序付けされたシーケンス。一部のステーションが空であることを許可し、結果のモジュロ 998244353 を返します。 

制約から、$n$と同じ大きさにすることができます$10^5$テストケースは最大 100 個あります。 これにより、指数列挙またはサブセット上の DP が即座に排除されます。 平$O(n^2)$最悪の場合、テストケースごとの処理が遅すぎます。 ソリューションでは、前処理後に各テスト ケースを一定数の組み合わせ評価に減らす必要があります。 

空いている駅について考えると、微妙な特殊なケースが現れます。 たとえば、次のようなとき$n = 1, m = 3$、1 人を 3 つのステーションのいずれか 1 つに割り当てることができ、他の 2 つは空のままになります。 正しい式には当然、空のキューを含む構成が含まれている必要があります。 もう 1 つのエッジケースは次のような場合です$m = 1$この場合、答えは、次のすべての順列を数えることになります。$n$すべてが単一の順序付けられたキューに強制的に入れられるためです。 

## アプローチ

 直接的な強引なアプローチでは、各人を次のいずれかに割り当てようとします。$m$ステーションを選択し、各ステーションを個別に注文します。 これにより、州の数が膨大になります。 課題だけで考えても、$m^n$人々を分配する方法、そしてそれぞれの分配について、各ステーション内の順列を考慮する必要があります。 これは実行可能な計算をはるかに超えています。 

重要な構造的観察は、内部順序と代入が複雑さを打ち消す形で相互作用しているということです。 キューを直接構築する代わりに、最初にすべての内部注文をグローバルに決定し、次にそれらをキューに分割する方法を決定するという観点から考えることができます。 

構造を再構成する便利な方法は、最初にすべてを並べると想像することです。$n$単一の順列の人々。 順列を修正すると、各ステーションは順序を維持しながらその順列のサブシーケンスを抽出することに対応します。 残された唯一の自由は、順列内の各人を次のいずれかにどのように割り当てるかです。$m$しかし、各ステーション内の相対的な順序は、グローバルな順列によってすでに決定されています。 

この観点では、問題を 2 つの独立した部分に分割します。つまり、すべての人々のグローバルな順序を選択し、次にその順序をどのように分割するかを決定します。$m$ラベル付きのサブシーケンス。空の可能性があります。 スプリットを選択する方法の数は、古典的な星とバーの数です: 私たちは配布しています$n$要素を次の順序で並べ替える$m$順序付けられたバケット。空になることが許可されます。これは、選択に対応します。$m-1$間の区切り文字$n + m - 1$ポジション。 

これにより、きれいな閉じた形式が得られます。答えは次の順列の数になります。$n$要素に弱い組成の数を掛けたもの$n$の中へ$m$部品。

 ## アルゴリズムのチュートリアル

 1. 階乗および逆階乗を最大値まで事前計算します。$n + m$すべてのテストケースにわたって。 これは両方の理由から必要です$n!$また、二項係数は繰り返し必要になるため、テスト ケースごとに再計算すると時間がかかりすぎます。 
2. 各テスト ケースについて、次の内容を読んでください。$n$そして$m$。 有効な構成の構造は、これら 2 つの値のみに依存し、追加の入力構造には依存しません。 
3. コンピューティング$n!$、すべてをグローバルに順序付ける方法の数を表します。$n$人々。 これにより、後でステーションに配布できるすべての可能な相対順序が取得されます。 
4. コンピューティング$\binom{n + m - 1}{m - 1}$、順序付けられたシーケンスを分割する方法の数を表します。$m$相対的な順序のみが重要な場合は、空の連続グループが使用される可能性があります。 これは、順序を尊重しながら各駅に行く人の数を選択することに相当します。 
5. 2 つの数量を法 998244353 で乗算し、結果を出力します。 

### なぜ効果があるのか

 核となる不変条件は、すべての有効な構成が 2 つの独立した選択によって一意に表現できるということです。つまり、すべての人々のグローバルな順列と、すべての人々の弱い構成です。$n$その順列から各ステーションに属する要素の数を決定します。 順列はすべての個体の相対的な順序を固定し、構成はステーション間のカット サイズのみを決定します。 2 つの異なるペアが同じ最終構成を生成することはなく、有効な構成はすべてそのようなペアに一意に分解できるため、これらのペアを数えることでスキームの正確な数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAX = 200000

fact = [1] * (MAX + 1)
invfact = [1] * (MAX + 1)

for i in range(1, MAX + 1):
    fact[i] = fact[i - 1] * i % MOD

invfact[MAX] = pow(fact[MAX], MOD - 2, MOD)
for i in range(MAX, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def C(n, r):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    ans = fact[n] * C(n + m - 1, m - 1) % MOD
    print(ans)
```階乗テーブルは一度構築されるため、各テスト ケースは一定時間内に応答できます。 結合関数は、事前計算された逆階乗を使用して、モジュラー逆乗を繰り返し再計算することを回避します。 表現$C(n + m - 1, m - 1)$選択した事前計算制限の下では安全です。$n + m \le 2 \cdot 10^5$。 

よくある実装の落とし穴は、ステーションが空である可能性があることを忘れることです。そのため、厳密な構成ではなく弱い構成が必要になります。 もう 1 つの微妙な問題は、テスト ケースごとの階乗のオーバーフローまたは再計算であり、最悪の場合の入力では TLE が発生します。 

## 実用的な例

 ### 例 1

 しましょう$n = 2, m = 2$。 

私たちは計算します$2! = 2$、 そして$\binom{2 + 2 - 1}{2 - 1} = \binom{3}{1} = 3$。 

したがって、答えは次のとおりです$2 \cdot 3 = 6$。 

| ステップ | 値 |
 | --- | --- |
 |$n!$| 2 |
 |$C(n+m-1, m-1)$| 3 |
 | 結果 | 6 |

 これにより、両方の人が 1 つのステーションにいる場合や複数のステーションに分かれている場合などのケースが正しくカウントされていることを確認できます。 

### 例 2

 しましょう$n = 3, m = 1$。 

私たちは計算します$3! = 6$、 そして$\binom{3}{0} = 1$。 

| ステップ | 値 |
 | --- | --- |
 |$n!$| 6 |
 |$C(n+m-1, m-1)$| 1 |
 | 結果 | 6 |

 これは、単一のステーションでは、すべての配置はすべての人々の単なる並べ替えであるという直観と一致します。

## テストケース```python
import sys, io

MOD = 998244353

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MOD = 998244353
    MAX = 200000

    fact = [1] * (MAX + 1)
    invfact = [1] * (MAX + 1)

    for i in range(1, MAX + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[MAX] = pow(fact[MAX], MOD - 2, MOD)
    for i in range(MAX, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(n, r):
        if r < 0 or r > n:
            return 0
        return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        out.append(str(fact[n] * C(n + m - 1, m - 1) % MOD))
    return "\n".join(out)

# provided samples (structure-based sanity)
assert solve("1\n1 1\n") == "1"
assert solve("1\n2 1\n") == "2"

# custom cases
assert solve("1\n1 3\n") == str(1 * 3), "single person multiple stations"
assert solve("1\n2 2\n") == str(2 * 3), "basic split case"
assert solve("1\n3 1\n") == str(6), "single queue permutation case"

## 特殊なケース

 いつ$m = 1$、式は次のようになります。$n! \cdot \binom{n}{0} = n!$これは、すべての人が 1 つの順序付けられたキューに並ばなければならないことを正しく反映しています。 二項係数は 1 と評価されるため、アルゴリズムはこれを自然に処理します。 

いつ$m = n$、多くの構成では、すべてのステーションに最大 1 人しか収容できません。 式は次のようになります$n! \cdot \binom{2n-1}{n-1}$これには、一部のステーションが空であり、他のステーションに 1 つの要素が含まれている場合も正しく含まれます。 結合部分は、すべての有効な分布を考慮します。 

いつ$n = 1$、式は次のようになります$1! \cdot \binom{m}{m-1} = m$、これは、どの局が 1 人を受信するかを選択することに相当します。 順列コンポーネントは簡単で、組み合わせコンポーネントは空のキューの意図された動作と一致する答えを完全に決定します。
