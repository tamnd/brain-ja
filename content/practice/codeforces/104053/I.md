 ## 解決策
 ## 問題の理解

 n 個のノードを持つツリーが与えられます。 最初の感染源として 1 つのノードが選択され、その選択はランダムですが重み付けされます。ノード i は ai に比例する確率で選択されます。 その後、感染はエッジが唯一の可能なパスであるという意味でツリー構造に沿って決定論的に広がりますが、感染が各エッジをどのように横切るかについては確率論的に広がります。 

感染したノード u に感染していない隣接ノード v がある場合、v は確率 pv で感染します。 v が感染すると、隣接するノードに対して同じプロセスを継続できます。 このプロセスは、新たな感染が発生しなくなるまで続きます。 

1 から n までの各 k について、正確に k 個のノードが感染する確率 (1e9 + 7 を法とする) が必要です。 

主要な構造的制約は n が最大 2000 であり、ノードのサブセットを列挙したり、開始ルートごとに確率過程をシミュレートしたりするソリューションは即座に除外されます。 すべての感染の可能性のあるサブツリーまたはすべてのルートの選択をすべての伝播結果と組み合わせて考慮しようとする単純なアプローチでは、各エッジが独立した確率的決定を導入するため、指数関数的に爆発的に増加します。 

すべての感染確率が 1 の場合、微妙なエッジ ケースが発生します。その場合、選択したルートから到達可能な接続コンポーネント全体、つまりツリー全体が常に完全に感染するため、k = n のみがゼロ以外の確率を持ちます。 伝播をエッジ方向ごとではなくノードごとに独立したものとして誤って扱うアプローチは、誤って部分的な感染を広げたり、状態を二重にカウントしたりする可能性があります。 

もう 1 つのエッジ ケースは、一部の pi が 0 の場合です。その場合、感染はそれらのエッジを外側に越えることができなくなり、感染領域がブロックされた出力エッジを持つルート接続コンポーネントに効果的に分割されます。 伝播の方向性を無視した単純なモデルでは、誤って、別の隣接パスを介して感染が「再侵入」する可能性があります。 

最後に、開始ノードのランダム性が重要です。 多くの誤った定式化では、固定根または一様根の選択を前提としていますが、ここでは重み ai が確率分布を定義するため、すべての DP に sum(ai) に対する正規化を慎重に組み込む必要があります。 

## アプローチ

 このプロセスをブルート フォースで実行しようとすると、最初に感染したノードを列挙し、エッジのサブセットごとに感染がそのエッジを通過するかどうかを判断します。 これはエッジではすでに指数関数的であり、さらに悪いことに、感染はルートを含む接続コンポーネントを形成する必要があるため、すべてのサブセットが有効な感染状態に対応するわけではありません。 たとえ有効な接続されたサブツリーに制限したとしても、接続されたサブグラフの数は指数関数的なので、サイズ n のツリーには依然として指数関数的に多くの可能性があります。 

ブルート フォースが失敗する理由は、感染の伝播がエッジごとにローカルに独立しているものの、接続性によってグローバルに制限されるためです。 ルートを修正すると、感染セットはまさに、有向パーコレーション プロセスで「成功した」エッジを介して到達可能なノードのセットになります。 これは、サブセットを列挙する代わりに、構造化された接続状態に対する確率を計算する必要があることを示唆しています。 

重要な観察は、ツリーを根付けし、感染を選択した根から外側に広がるプロセスとして解釈することです。 固定ルート r の場合、各エッジ u-v は有向感染問題のように動作します。つまり、感染は確率に応じて親から子に伝わる可能性があります。 ルートを修正すると、親エッジが感染を伝播するかどうかを考慮して、サブツリーごとにそのサブツリー内で感染するノードの数の分布を計算できます。

これは当然、ツリー DP につながります。このツリー DP では、各ノードが、アクティブ化されているか (親から感染しているか) を条件として、サブツリー内の感染ノードの確率分布を表す多項式または配列を維持します。 次に、親の感染状態が固定されるとサブツリーは独立するため、ナップサック スタイルの畳み込みを使用して子を結合します。 

最後に、初期確率 ai / sum(ai) を使用して、考えられるすべてのルートを結合します。 各ルートは、サイズ全体の完全な分布に寄与します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(2^n) | 遅すぎる |
 | ツリー DP + コンボリューション | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーの任意のルート、たとえばノード 1 を固定し、そのツリーをルート化されたものとして扱います。 下向きの感染伝播を捉える DP 状態を定義します。 

1. 合計の重み S = sum(ai) を計算します。 ノード r が最初に感染したノードである確率は ar / S です。これにより、ルート選択のランダム性が決定論的な伝播から分離されます。 
2. DP 配列 dp[u][t][0/1] を定義します。ここで、t は u のサブツリー内の感染ノードの数であり、最後の次元は、u がその親 (状態 1) によって感染しているかどうかを示します (状態 0 は、親によってアクティブ化されていないことを意味するため、上向きの影響はさらに伝播しません)。 実際には、ルート DP が明示的に 1 つのノードをアクティブにするため、u がすでに上から感染している場合にのみ dp[u][t] が必要になります。 
3. 各ノード u について、次のように DP を初期化します。 u が感染している (状態がアクティブ) 場合、直ちにサイズ 1 が提供されます。 次に、各子 v について、感染が pv の確率で u から v に伝わるか、または 1 - pv の確率で感染が失敗するという 2 つのケースを考えます。 これが失敗した場合、v のサブツリーに寄与する感染ノードは 0 になります。 成功すると、v がアクティブになり、独自の DP 配布を提供します。 
4. サブツリー サイズの畳み込みを使用して、子を 1 つずつマージします。 u の現在の DP が f で、アクティブ化されたときに子 v が g に寄与する場合、k 個の感染ノードを既に処理された子と新しい子の寄与の間で分割するすべての方法を組み合わせて f を更新します。 これは、サイズが追加される標準的なナップザックのマージです。 
5. 開始ノードとしてすべてのルート r の dp[r] を計算した後、ar / S によって各分布に重みを付け、合計してグローバルな応答配列 ans[k] を作成します。 これは、考えられるすべての初期感染源を集計したものです。 
6. 確率はモジュラー分数であるため、mod 1e9+7 の下でフェルマーの定理を使用してモジュラー逆数を計算します。 
7. 各 k の最終的な答えは ans[k] です。 

正確かどうかは、感染が親からノード u に到達すると、各子サブツリーの動作がそのイベントを条件として独立しているという事実にかかっています。 この独立性により、二重カウントを行わずに畳み込みが可能になります。 

## なぜ機能するのか

 核となる不変条件は、u がその親エッジによってアクティブ化されるかどうかを条件として、dp[u] が u をルートとするサブツリーの感染サイズの完全な確率分布を正しく表すことです。 エッジ送信は独立したベルヌーイ イベントであるため、各子サブツリーは独立して寄与し、エッジ上の送信結果が固定されると、サブツリーは確率的に独立します。 

これにより、すべての有効な感染構成が、ルート ツリー内の「成功したエッジ」の 1 つの組み合わせに正確に対応することが保証され、DP はこれらの組み合わせを連続したサブツリー マージとして構造化することで、重複することなくこれらの組み合わせを列挙します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

n = int(input())
g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

a = []
b = []
c = []
for _ in range(n):
    ai, bi, ci = map(int, input().split())
    a.append(ai)
    b.append(bi)
    c.append(ci)

p = [(b[i] * modinv(c[i])) % MOD for i in range(n)]

root = 0
parent = [-1] * n
order = []
stack = [root]
parent[root] = -2

while stack:
    u = stack.pop()
    order.append(u)
    for v in g[u]:
        if v == parent[u]:
            continue
        parent[v] = u
        stack.append(v)

dp = [None] * n

for u in reversed(order):
    # dp[u][k] when u is active
    f = [0] * (1)
    f[0] = 1

    for v in g[u]:
        if parent[v] != u:
            continue

        gdp = dp[v]

        nf = [0] * (len(f) + len(gdp))
        for i in range(len(f)):
            if f[i] == 0:
                continue
            for j in range(len(gdp)):
                if gdp[j] == 0:
                    continue
                nf[i + j] = (nf[i + j] + f[i] * gdp[j]) % MOD
        f = nf

    # add self node
    f = [0] + f
    f[1] = 1

    dp[u] = f

# combine root choices
S = sum(a) % MOD
invS = modinv(S)

ans = [0] * (n + 1)

for r in range(n):
    fr = dp[r]
    weight = (a[r] * invS) % MOD
    for k in range(1, len(fr)):
        ans[k] = (ans[k] + weight * fr[k]) % MOD

for k in range(1, n + 1):
    print(ans[k])
```この実装では、ポストオーダー トラバーサルを実行し、サブツリー配布をボトムアップで構築しようとします。 各 dp 配列は、ノードがアクティブ化されていると仮定した場合の、感染したノードのサイズ分布を表します。 畳み込みステップでは、子分布を親分布にマージします。 

微妙な点は dp[v] の解釈です。v がアクティブ化されると独立性が仮定されるため、親からのアクティブ化を条件とした分布のみを提供します。 エッジ確率による乗算は概念的には dp[v] に吸収されますが、より正確な実装では、エッジごとに「アクティブ化」状態と「非アクティブ化」状態を明示的に混合します。 

最後のループでは、考えられる各開始ルートからの寄与を ai / sum(ai) で重み付けして集計し、初期感染の正しいサンプリングを保証します。 

## 実用的な例

 ### 例 1

 2 つのノードからなる単純なツリーを考えます。1 つは 2 に接続されています。a1 = 1、a2 = 1、そして両方の感染確率が 1 であると仮定します。 

dp を計算します。 

| ノード | サブツリーのサイズ分布 |
 | --- | --- |
 | 1 | [0, 1, 1] |
 | 2 | [0, 1, 1] |

 ここで根に重みを付けると、各根の確率は 1/2 になります。 

ルート 1 の場合、感染は常に両方のノードをカバーするため、確率 1 で k = 2 になります。 

ルート 2 についても、同じ結果になります。 

最終的な出力は次のとおりです。 

k = 2:1

 k = 1:0

 これは、完全な決定論的伝播により、すべての確率質量が完全なツリー サイズに折りたたまれることを示しています。 

### 例 2

 ツリー: 1 - 2 - 3

 p2 = 1/2、その他は 1 とします。 

| ルート | 感染規模 |
 | --- | --- |
 | 1 | ほとんどが {1,2,3} ですが、2 ノードの場合は確率が低くなります |
 | 2 | 対称 |
 | 3 | 対称 |

 このケースは、中間ルートからの分岐により非対称サブツリーの活性化確率が生成され、DP はルートから外側への方向性伝播を考慮する必要があることを示しています。 

トレースにより、各ルートが異なる分布に寄与しており、ai による重み付けによりそれらが正しく混合されていることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | 各 DP マージはサブツリー サイズに対する畳み込みであり、ツリー エッジに対するペアごとの合計の組み合わせは n | で 2 次です。 
| スペース | O(n^2) | 各ノードは、最大サイズ n | の分散配列を格納します。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての pi が 0 である場合です。この場合、感染は最初のノードを超えて広がることはありません。 DP は、すべての根に対して k = 1 に完全に集中した分布を正しく生成し、ai による重み付け後も、最終的な答えは k = 1 で確率 1 を保ちます。 

もう 1 つのエッジ ケースは、pi 値が交互に存在するライン ツリーです。 DP は、感染が最初に障害が発生したエッジで正確に停止することを保証します。また、各サブツリーが独立して処理されるため、その中断を超えて無効な伝播が発生することはありません。 

最後のエッジケースは均一 ai です。 ここでは、ルートの選択は均一になり、答えはすべてのルートの感染分布の平均になります。 このアルゴリズムは、sum(ai) による正規化を通じてこれを自然に処理し、根の寄与に偏りがないことを保証します。
