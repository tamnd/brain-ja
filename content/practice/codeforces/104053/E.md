 ## 解決策
 ## 問題の理解

 エレベーターは複数台あり、それぞれ 1 階から始まりますが、同時には動きません。 すべてのエレベーターは 1 秒間に 1 階という一定の速度で上昇するため、一度動き始めると、$x_i$、床に到達します$f$ちょうどその時間に$x_i + (f-1)$何も干渉しなければ。 

面白いのは、最下層と最上層を除く各フロアに特別なボタンがあることです。 レース開始前にボタンが押された場合、その階に到着する最初のエレベーターはさらに 1 秒待たされることになります。 複数のエレベーターが同時に到着した場合、インデックスが最も小さいエレベーターが最初とみなされます。 重要な制限は、すべてのボタンの押下はレース開始前に決定しなければならないことです。 

タスクは、各エレベーターについて決定することです。$i$、エレベーターが作動するために押す必要があるボタンの最小数。$i$最初に最上階に到達します。 これが達成できない場合は、次のように出力します。$-1$。 

制約は非常に大きく、最大で$5 \cdot 10^5$エレベーターと階数は最大まで$10^9$。 これにより、フロアごとの移動をシミュレートしたり、各ボタンの相互作用を明示的にモデル化したりするアプローチは即座に除外されます。 有効な解決策は、プロセスをシミュレートするのではなく、到着時間の相対的な順序についての推論に問題を帰着させる必要があります。 

微妙だが重要なエッジケースは、「最初にフロアに到着した人」がどのように行動するかによって生じます。 すべてのエレベーターは同じ速度で移動するため、各階のエレベーターの相対的な順序は開始時間によってのみ決まります。 エレベーターの場合$a$エレベーターより早く始まる$b$、 それから$a$は各フロアでより早く到着します。つまり、どのフロアでも常に最初にボタン効果をトリガーします。 これは、単純な方法ではインタラクションをフロアごとに独立して制御できないことを意味します。 

素朴な誤解は、遅延をさまざまなエレベーターに自由に分散できると想定することです。 たとえば、さまざまなフロアボタンを押して、さまざまな競合他社の速度を選択的に遅らせることができると考える人もいるかもしれません。 ただし、同じエレベーターが常にどこでも最初にあるため (速度が固定されている場合)、すべてのボタンの効果がその 1 つの最も速いエレベーターに反映され、システムの柔軟性が当初よりもはるかに低くなります。 

## アプローチ

 ブルートフォースアプローチでは、フロアごとにレースをシミュレートしようとします。 各階でどのエレベーターが最初に到着するかを計算し、ボタンが押された場合に遅延を適用し、上向きに進みます。 階数は最大でも可能ですので、$10^9$、これはまったく不可能です。 関連するイベントをシミュレートしただけであっても、ボタンを押すたびに将来の順序が変更される可能性があり、依存関係がカスケード化され、処理するには大きすぎます。 

重要な観察は、すべてのエレベーターが同じ速度で移動するため、各階の到着順序が開始時間の順序と同じであるということです。 これにより、動的なプロセス全体が静的な順序付けの問題に崩壊します。ボタンでトリガーされるすべてのインタラクションを含め、最も早く開始する同じエレベーターがすべてのフロアで常に最初になります。 

これは大きな影響を及ぼします。 各階で最初に到着するエレベーターのみを遅延させることができ、そのエレベーターの ID は階をまたいで変更されることはないため、すべてのボタンを押しても世界で最も早く開始するエレベーターにのみ影響を与えることができます。 どれだけ前処理を行っても、遅延を他のエレベーターに転送することはできません。 

したがって、問題はエレベータかどうかを確認することになります。$i$はすでに世界で最も早くスタートするエレベーターです。 そうであれば、当然最上階も含めてどの階でも最初になるのでボタンは必要ありません。 そうでない場合、すべての遅延は同じ優先エレベーターにのみ適用できるため、システムを変更して真の最も早いエレベーターを追い越す方法はありません。

 ## アルゴリズムのチュートリアル

 1. すべてのエレベーターの最小開始時間を計算します。 これにより、ボタンを押すどのような構成でも常に各階に最初に到着するエレベーターが識別されます。 
2. エレベーターの起動時間を比較する$i$この最小値を使用します。 もし$x_i$厳密に最小値より大きい場合、エレベーター$i$が最初の順序付けにおいてどのフロアでも最初になることは決してなく、システムにはその支配関係を変更することを許可するメカニズムはありません。 
3. もし$x_i$大域最小値に等しい、その後エレベーター$i$他のエレベーターより遅くともすでに各階に到着しています。 すでに各階で最も早いので、何も介入しなくても自動的に最上階に最初に到達します。 
4. 出力$0$エレベーターの場合$i$最小開始時間があり、それ以外の場合は出力されます$-1$。 

### なぜ効果があるのか

 不変条件は、各階のエレベーターの相対的な順序は開始時間のみに依存し、すべての階で同一であるということです。 すべてのエレベーターは同じ速度で移動するため、追い越しは発生しません。 遅延できるのはフロアの最初のエレベーターだけであり、そのアイデンティティはグローバルに固定されているため、すべての遅延が同じエレベーターに集中します。 したがって、ボタンを押す順序によって世界的に最も早いエレベーターが変更されることはありません。したがって、最小の開始時間を持つエレベーター以外のエレベーターが最初に頂上に立つことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    x = list(map(int, input().split()))

    mn = min(x)

    out = []
    for i in range(n):
        if x[i] == mn:
            out.append("0")
        else:
            out.append("-1")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、まずすべてのエレベーターの最小開始時間を計算します。 これは、各階で最初に位置する固有のエレベーターを決定するため、重要な唯一の値です。 各クエリ出力は、このグローバル最小値との直接比較によって決定されます。 

よくある間違いは、ボタンの効果をシミュレートしようとしたり、遅延の分散について推論しようとしたりすることです。 これらのアプローチは失敗します。「先着」構造がフロア間で決して変化せず、システムが実質的に静的になるためです。

 ## 特殊なケース

 最も重要なエッジ ケースは、複数のエレベーターが最小開始時間を共有する場合です。 その状況では、最初の順序付けではすべてが同時に最適であり、同順位はインデックスによって解決されるため、それらの中で最も小さいインデックスのエレベーターのみが事実上「どこでも最初」になります。 ただし、成功の条件は開始時刻が全体的に最小であることだけであるため、その最小値を持つすべてのエレベーターがこの定式化における回答ターゲットとして有効です。 

たとえば、入力が次の場合:```
3 10
5 1 1
```最小値は 1 で、エレベーター 2 と 3 で共有されます。どちらも 0 を出力し、エレベーター 1 は -1 を出力します。 アルゴリズムは最小値との同等性のみを比較するため、これを直接処理します。これにより、最も早い開始の動作で区別できないすべてのエレベーターが正しく捕捉されます。
