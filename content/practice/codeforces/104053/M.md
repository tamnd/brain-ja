 ## 問題の理解

 長さのシーケンスが与えられます$k$, ここで、各要素は$a_i$は負ではない整数であり、次の値で囲まれます。$m$。 このようなシーケンスの場合、その値は、ペアのビットごとの XOR のうち、2 番目のインデックスが最初のインデックスを超えないすべてのペアの合計として定義されます。$$\sum_{i=1}^{k} \sum_{j=1}^{i} (a_i \oplus a_j).$$これは、すべての要素がそれ自体および以前のすべての要素との XOR に寄与し、それらすべての XOR 値が 1 つの整数スコアに累積されることを意味します。 タスクは、正確に目標スコアを生成するシーケンスの数をカウントすることです$n$、すべての値を法として取得します$10^9+7$。 

主な難点は、この関数がペアごとの XOR 相互作用を通じてすべての位置を結合することです。 要素が個別に制限されていても、スコアは要素間のグローバルな相互作用に依存するため、インデックスごとのローカル推論では不十分です。 

制約の長さは短いですが、値の範囲は大きくなります。 と$k \le 18$、指数関数的なものを買う余裕はありません。$m$、しかし指数関数的に$k$まだ実行可能です。 価値観$m$まで行く$10^{12}$したがって、数値をビット単位で扱うことが必須です。 ターゲット$n$まで上がります$10^{15}$これもビットごとの分解を強く示唆しています。 

単純な試みでは、すべてを生成しようとするでしょう。$(m+1)^k$シーケンスを調べ、XOR ペアの合計を計算し、一致をカウントします。 これは、中程度の場合でもすぐには実行不可能です。$m$、これは爆発します。 削減さえ$m$小規模な場合、シーケンスごとの二重和を計算するのは次のとおりです。$O(k^2)$が鈍くなるにもほどがあります。

 ## アルゴリズムのチュートリアル

 中心的なアイデアは、シーケンスがどのように形成されるか、およびこれまでにどれだけの XOR 寄与が蓄積されているかに関する DP を維持しながら、数値を最上位ビットから下に向かって少しずつ処理することです。 

処理した要素の数、まだ厳密であるかどうかを追跡する DP 状態を定義します。$m$、XOR への累積寄与が現在のビットに合計されます。 

1. ビットを処理します$m$最高から（約40以降）$m \le 10^{12}$これにより、何かを決定するときに、$a_i$、制約を尊重します$a_i \le m$辞書順にバイナリ形式で表示されます。 
2. シーケンス位置ごとに、ビットを 1 つずつ割り当てます。 与えられたビットで、それぞれ$a_i$にはバイナリの選択肢がありますが、まだプレフィックスと一致している場合、この選択肢は制限されます。$m$。 これは、複数の数値を並列に使用する標準的な数値 DP 構造です。 
3. 各 DP 状態について、現在のビットで 1 を持つ要素の数を維持します。 特定のビットで$c$中のもの$k$要素の場合、このビットは XOR 合計に正確に寄与します。$c \cdot (k-c+1)$自己ペアの包含に依存する - のような構造。 正しい寄与度は、XOR によって引き起こされる順序付けされていない寄与度をカウントすることで得られ、これは増分的に計算されます。 
4. ビットを下降するときに累積された XOR 合計を同時に維持し、以前の寄与を 1 ビットシフト (2 倍) し、現在のビットの寄与を加算します。 
5. 構築されたプレフィックスがまだ次と等しいかどうかも追跡します。$m$(厳しい制約)、ビットを自由に割り当てることができるか、強制的に割り当てられるかを決定します。 

すべてのビットを処理した後、累積値が以下に等しい DP 状態をカウントします。$n$。 

### なぜ効果があるのか

 正しさは 2 つの分離から生まれます。 まず、XOR はビットごとに独立しているため、位置の重みを除いて、各ビットが最終的な数値に独立して寄与します。 第 2 に、辞書編集数字 DP over bit により、構築されたすべての数値が範囲内に収まることが保証されます。$m$。 各ビットで、最終合計へのすべての寄与は、ビット間の 0 と 1 の分布によって完全に決定されます。$k$したがって、2 の乗算によってすでに処理されているシフトを超える隠れたクロスビット依存関係は存在しません。これにより、すべての有効なシーケンスが DP 状態を通る 1 つのパスに正確に対応するため、DP は完全でオーバーカウントされなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m, k = map(int, input().split())

    MAXB = 60

    # dp[tight][mask of k bits] -> we compress by count of ones at each bit step
    # Since k <= 18, we track counts of how many numbers have current bit = 1
    # dp[tight][c][value]
    
    from collections import defaultdict

    dp = [defaultdict(int), defaultdict(int)]
    dp[1][(0, 0)] = 1  # (ones_count, value)

    for b in reversed(range(MAXB)):
        ndp = [defaultdict(int), defaultdict(int)]
        mb = (m >> b) & 1

        for tight in (0, 1):
            for (ones, val), ways in dp[tight].items():
                for assign in range(1 << k):
                    if tight and assign > mb:
                        continue

                    cnt1 = bin(assign).count("1")

                    # contribution of this bit to XOR sum
                    # pairs with XOR = 1 are cnt1 * (k - cnt1)
                    contrib = cnt1 * (k - cnt1)
                    new_val = (val << 1) + contrib

                    ntight = tight and (assign == mb)
                    ndp[ntight][(cnt1, new_val)] = (ndp[ntight][(cnt1, new_val)] + ways) % MOD

        dp = ndp

    ans = 0
    for tight in (0, 1):
        for (ones, val), ways in dp[tight].items():
            if val == n:
                ans = (ans + ways) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、すべての数値を同時にバイナリ表現するビット DP に従います。 各 DP 層は、すべての DP 層で 1 つのビット位置を固定することに対応します。$k$要素。 

の`tight`フラグは、構築された数値が超過しないように強制します$m$。 各状態は、現在のビットに 1 を持つ要素の数と、これまでに蓄積された XOR 寄与も追跡します。 遷移では、すべてのビット割り当てが列挙されます。$k$ポジション、これは実現可能です。$k \le 18$、だからせいぜい$2^{18}$パターンが存在します。 

ビットの XOR 寄与は、異なるビットの各ペアがその位置で 1 つの XOR に寄与するため、選択されたビットの数にのみ依存します。$cnt1 \cdot (k - cnt1)$。 

上位ビットから下位ビットに移動し、最終的な整数を効果的に構築するため、累積値は各ステップで左にシフトされます。
