 ## 解決策
 ## 問題の理解

 個別の非負の整数の初期セットが与えられます。 アリスとボブの 2 人のプレイヤーが、このセットに任意の整数を順番に挿入します。 各プレイヤーが正確に作成します`k`移動するので合計すると`2k`新しい番号が追加されます。 挿入によって要素が削除されることはありません。また、常にセットを操作しているため、重複は問題になりません。 

すべての移動の後、最終セットの MEX を計算します。これは、そのセットに現れない最小の非負の整数を意味します。 この MEX が偶数であればアリスが勝ち、それ以外の場合はボブが勝ちます。 

重要な問題は、両方のプレイヤーが最適にプレイし、必要な整数を挿入できることです。 したがって、本当の問題は、最終セット自体に関するものではなく、アリスとボブが最小の欠損数にどのような影響を与えるかということです。 

制約により、最大で次のことが許可されます。`2 × 10^5`テストごとの要素とテスト全体の合計、最大`10^4`テストケース。 これにより、ターンのシミュレーションや移動ごとの値の貪欲な増分充填が即座に除外されます。`k`テストごとのプレーヤーごとの挿入数、最悪のケースにつながる`10^10`操作。 

正しい解決策は、代わりに、MEX の構造と、最初に存在する欠落している小さな数がいくつあるかを直接推論する必要があります。 

初期セットにゼロから始まる長いプレフィックスが既に含まれている場合、微妙なエッジ ケースが発生します。 たとえば、次の場合`S = {0,1,2,3,4}`そして`k = 2`、その場合、MEX は 5 から始まります。合計で 4 つの数字しか追加できないため、MEX は限られた範囲までしか前進できません。 「各プレイヤーは足りない数字を貪欲に埋めるだけ」といった素朴な考えは、両方のプレイヤーが戦略的に干渉したり値をスキップしたりできるため、破綻します。 

もう 1 つのエッジケースは次のような場合です`0`最初は欠落しています。 たとえば、次の場合`S = {1,2,3}`そして`k = 5`の場合、MEX はすでに`0`、そして、誰かが明示的に挿入しない限り、挿入によって 0 が存在しないという事実は変更できないため、アリスは動きに関係なくすぐに勝ちます。 ここでの最適なプレイは些細なものになりますが、正しく認識される必要があります。 

## アプローチ

 ブルートフォースアプローチでは、ゲームをシミュレートしようとします。 移動するたびに、アリスまたはボブは可能なすべての整数を試して挿入し、結果の MEX パリティを再帰的に評価します。 分岐係数が無限であり、候補を最大で関連する値に制限することさえあるため、これはすぐに不可能になります。`n + 2k`おおよそのサイズの状態爆発につながります`(2k)!`可能性。 

重要な観察は、最小の欠損数の有無のみが重要であるということです。 小さい数値がすべてすでに存在しない限り、MEX に影響を与えることはないため、大きな数値は無関係です。 

そこで、最初に欠落している整数を追跡し、ゼロから始まるプレフィックスに欠落している整数がいくつ存在するかを追跡することに問題を圧縮します。 させて`mex`初期セットの現在の MEX になります。 次に、すべての数字が`[0, mex-1]`存在し、そして`mex`それ自体が欠けています。 

ここで、ゲームは、プレイヤーが特定の小さな整数の出現を「遅らせる」ことができるか、それとも「強制」できるかどうかになります。 すでに存在する数値を挿入しても意味がないため、最適な再生は、最終的な MEX より小さい欠落した整数を挿入することに完全に焦点を当てます。 

重要な考え方は、現在の MEX を下回る欠落しているすべての数値が事実上「ターゲット」であるということです。 挿入ごとに、このような欠損値を最大 1 つ修正できます。 両方のプレイヤーが最終的な MEX が偶数になるか奇数になるかを制御したいため、唯一意味のある数量は、重要なプレフィックス ウィンドウに欠損値がいくつ存在するかということです。 

ゲームは比較することに帰着することが判明`k`最初のプレフィックスの欠落している整数の数に対して、最適な充填後の MEX インデックスのパリティ シフトについて推論します。 プレフィックスが使い果たされるか、影響を受けることができなくなると、残りの有効な動きが MEX をさらに 1 歩進めることができるかどうかによって、最終的な MEX のパリティが決定されます。 

したがって、動きをシミュレートする代わりに、初期 MEX を計算し、プレーヤーが欠落している整数を最大まで消費することでそれを拡張できるかどうかを推論します。`mex + k`次に、残りのコントロールが実質的に中立であるか、移動順序によりアリスが有利であるかに基づいてパリティを決定します。

 ## アルゴリズムのチュートリアル

 私たちは、ゲームを MEX がどこまで押し込めるかについての推論に落とし込みます。 

1. セットのどの値をマークすることによって、セットの初期 MEX を計算します。`0`上向きに現れます。 最初の欠損値で停止します。これにより、次のことが定義されます。`mex`。 これは、その後のすべての構造を決定する最小の数値です。 
2. 中の数字が何個あるか数えます`[0, mex-1]`初期セットでは欠落しています。 MEX の定義により、このカウントはゼロであるため、意味のある欠落領域は次から始まります。`mex`。 
3. 現在の MEX より小さい数値を挿入すると、先頭のギャップが埋まるため、MEX が 1 だけ増加することに注目してください。 これは、各移動が実質的に MEX を増分しようとする試みであることを意味します。 
4. 両プレイヤーが交互に行うので、`k`移動すると、最大で MEX を増やすことができます`2k`ただし、消費する欠落整数が連続して存在する場合に限ります。 
5. から始める`mex`、概念的に前方に拡張します: から連続する整数がいくつあるかを尋ねます。`mex`それ以降は初期セットには含まれていません。 これをそのままにしておきます`gap`。 
6. もし`k`プレーヤーがこのセグメントの欠落している数字をすべて使い果たすのに十分な大きさである場合、MEX は次のようになります。`mex + gap`。 それ以外の場合、ゲームはより早く停止し、パリティは誰のターンが最後の増分を効果的に制御しているかによって決まります。 
7. アリスが最初に移動するため、完全に使い果たした後の残りの有効な移動のパリティによって、アリスとボブのどちらが最終的な MEX パリティを強制できるかが決まります。 クリティカル増分の数が奇数の場合、アリスが最終ステップを制御します。 それ以外の場合はボブがそうします。 

### なぜ効果があるのか

 不変条件は、MEX を変更する唯一の方法は現在の値を埋めることであるということです。 現在の MEX をターゲットにしない動きは、欠落している最小の整数に影響を与えないため、戦略的に無関係です。 これにより、MEX 境界で単一の進化するポインターに最適な再生が強制されます。 すべてのステージで、ゲームの状態は「現在の MEX から連続して欠落している整数が何個残っているか」に分類され、有用な手ごとにそのカウントが 1 ずつ減ります。 プレイヤーが交代するため、勝者は、そのような強制削減の合計数がアリスのターンとボブのターンのどちらに一致するかによってのみ決まり、これが最終的な MEX の同等性を直接決定します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        arr = list(map(int, input().split()))
        s = set(arr)

        mex = 0
        while mex in s:
            mex += 1

        # simulate how far we can extend MEX using at most 2k insertions,
        # but only consecutive missing values matter
        steps = 0
        cur = mex
        while steps < 2 * k and cur not in s:
            steps += 1
            cur += 1

        final_mex = cur

        if final_mex % 2 == 0:
            print("Alice")
        else:
            print("Bob")

if __name__ == "__main__":
    solve()
```この解決策は、O(1) メンバーシップ チェックのハッシュ セットを使用して MEX を計算することから始まります。 これにより、ゲーム全体の要となる最小の欠損値が特定されます。 

次に、MEX から始まる関連領域のみをシミュレートし、次の制限の下で連続して欠落している整数が何個消費できるかをカウントします。`2k`挿入。 現在の MEX を埋めるだけが次の MEX 値に影響するため、これは機能します。 

ループは、許可された挿入がなくなった場合、またはすでに存在する値に遭遇した場合に停止し、それ以上の強制的な MEX インクリメントがブロックされます。 その後、最終的な MEX を使用してパリティが決定され、勝者が決定されます。 

重要な実装の詳細は、シミュレーションの範囲を制限します。`2k`全体的な制約を尊重しながら、テストごとの直線的な複雑さを確保します。 

## 実用的な例

 ### 例 1

 検討してください`S = {0,1,2,4}`そして`k = 2`。 

| ステップ | 現在のメキシコ | アクション | 残りの手数 |
 | --- | --- | --- | --- |
 | 開始 | 3 | 初期状態 | 4 |

 ここで、MEX は 3 から始まります。プレイヤーは欠損値 3 と 4 を操作できます。最適なプレイの後、MEX は 5 になり、これは奇数であるため、ボブが勝ちます。 

このトレースは、MEX の周囲の連続する欠損値のみが問題であり、無関係な大きな数値を挿入しても結果は変わらないことを示しています。

| ステップ | 現在のメキシコ | アクション | 残りの手数 |

これにより、最初に MEX が 0 の場合、アリスはすぐに上向きに影響を与えることができますが、拡張の数が十分であればボブは依然として最後の動きの効果を得ることができることが確認されています。

 ## 特殊なケース

 初期 MEX がすでにゼロである場合、アルゴリズムは状態を挿入によって完全に制御されているものとして直ちに分類します。 アリスが先に動くのですぐに挿入可能`0`、MEX をにシフト`1`、その後の交替により最終的なパリティが決定されます。 初期スキャンはゼロから始まり、すぐに強制増分をカウントするため、シミュレーションはこれを正確に反映します。 

配列にゼロから始まる長いプレフィックスがすでに含まれている場合、スキャンは MEX をさらに進め、連続して欠落している末尾のみが考慮されます。 アルゴリズムは値が存在せず、値が存在する間のみ前進するため、`2k`、シーケンスがブロックされたとき、または移動バジェットが使い果たされたときに正しく停止します。 

いつ`k`が欠損値と比較して非常に大きい場合、ループは移動の枯渇ではなく、既存の要素に遭遇するために停止します。これは、連続的なギャップがないと MEX を任意に遠くまでプッシュできないことを正しく反映しています。
