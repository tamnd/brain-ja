 ## 問題の理解

 長さの配列が与えられます$n$以下の範囲の整数$-1$に$n$。 の$-1$値は、負でない整数を取ることができるプレースホルダーです。 タスクは、$-1$配列は次のように生成される可能性があります$f(A)$ある配列の場合$A$正の整数の。 ここ、$f(A)_i$位置の前の最後の要素のインデックスを示します$i$それは厳密に以下よりも小さいです$A_i$、 または$0$そのような要素が存在しない場合。 

事実上、「かわいい配列」、つまり基礎となる配列の最後の小さな要素パターンを記述するインデックスの配列をカウントしていることになります。 出力は記入方法の合計数です。$-1$配列がかわいいままになるように、モジュロを適用します$998{,}244{,}353$。 

制約は次のことを意味します$n$テスト ケースごとに最大 5000 であり、合計は$n$すべてのテスト ケースの値も 5000 によって制限されます。これにより、すべての配列を明示的に生成する単純な総当りアプローチが除外されます。$2^n$操作が多すぎるでしょう。 この問題には、配列にエントリがある場合という隠れた微妙な点もあります。$X_i > i-1$、を満たすことができる以前のインデックスが存在しないため、直ちに無効になります。$f(A)_i$。 ゼロが繰り返される配列や、増加シーケンスによって生成できないパターンも、ゼロ解を生成します。 不注意なアプローチでは、これらの暗黙のインデックス制約が無視される可能性があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。すべての配列を生成します。$X'$置き換えることで$-1$0 から 0 までの有効な整数を含む s$n$、そして各配列が次のように表現できるかどうかを確認します。$f(A)$ある配列の場合$A$。 チェック自体には、次の構築をシミュレートする必要があります。$f(A)$から$A$、つまり$O(n^2)$。 と$n=5000$、n^{\text{# of -1s}} 配列を生成することは不可能です。 適度な数の小さなテスト ケースであっても、$-1$s は組み合わせ的に爆発します。 

より高速なソリューションを実現するための重要な観察結果は次のとおりです。$f(A)$単調な構造を強制します。 インデックスごとに$i$、 もし$f(A)_i = j > 0$、 それから$A_i$厳密に次より大きくなければなりません$A_j$、およびその間の要素$j$そして$i$以下を超えてはなりません$A_i$。 これは典型的な動的プログラミングの状況であり、配列のプレフィックスごとに、考えられる各値で終わる有効な配列の数を維持できます。 可能な最大値から逆算し、プレフィックス合計を使用してカウントを累積することで、複雑さを最小限に抑えます。$O(n^2)$、これは n の和制約に適合します。

 ## アルゴリズムのチュートリアル

 1. DP テーブルの初期化`dp[i][v]`最初の有効な配列の数を表します。`i`値で終わる位置`v`位置にある`i`。`v`範囲は0から`n`。 から始める`dp[0][0] = 1`、空のプレフィックスを表します。 
2. 各位置を反復処理します。`i`1から`n`。 もし`X[i] != -1`、次の値`i`は固定されており、計算するだけです`dp[i][X[i]]`。 それ以外の場合は、すべてを考慮してください`v`可能な選択肢は 0..n です。 
3. それぞれについて`v`位置にある`i`、以前のすべてのポジションからの貢献を計算します`j`そのような`j < i`そして`f(A)_i = j`のパターンと一致します`X`。 これは、プレフィックス合計配列を使用して効率的に実行されます。`pref[j] = sum(dp[j][*])`まで`j`。 のために`v`で有効になる`i`、 全て`dp[j][u]`どこ`u < v`それを代表して貢献できる`A_i > A_j`。 
4. 貢献度を剰余として累積する`998244353`の中へ`dp[i][v]`。 もし`X[i]`は固定されているため、対応する値のみを計算します`v`。 
5. すべての位置を埋めると、答えは次の合計になります。`dp[n][v]`全体`v`最後の位置制約に一致するもの。 

The core insight is that the recurrence leverages the monotonic property of the underlying array`A`でエンコードされた`f(A)`。 考えられる最後の値に対して DP を維持し、プレフィックス合計を使用することで、組み合わせ爆発を回避し、互換性のあるすべての配列を直接カウントします。 

### なぜ効果があるのか

 DP は次の不変条件を維持します。`dp[i][v]`位置までのすべての有効なシーケンスをカウントします`i`値で終わる`v`すべてを尊重しながら`f(A)`入力パターンによって課される制約。 各ステップでは、最後の小さな要素パターンと一致する方法で配列を拡張するだけです。 プレフィックスの合計により、すべての有効な以前の位置からの寄与が効率的に含まれることが保証され、有効な配列が欠落したり、無効な配列がカウントされたりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        X = list(map(int, input().split()))
        
        dp = [0] * (n + 1)
        dp[0] = 1  # empty prefix
        for i in range(n):
            ndp = [0] * (n + 1)
            total = 0
            for j in range(n + 1):
                total = (total + dp[j]) % MOD
            if X[i] == -1:
                for v in range(n + 1):
                    ndp[v] = total
            else:
                if X[i] > i:
                    ndp[X[i]] = 0
                else:
                    ndp[X[i]] = total
            dp = ndp
        print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```DP アレイ`dp`特定の最後の小さいインデックス値で終わるシーケンスの数を保持します。 次を使用して、各ポジションの DP を前方にロールします。`total`以前のすべてのカウントに対するプレフィックスの合計として。 モジュロ演算により、数値がオーバーフローしないことが保証されます。 次のようなポジションの取り扱いには特別な注意が払われます。`X[i]`は修正され、更新はその値のみに制限されます。
