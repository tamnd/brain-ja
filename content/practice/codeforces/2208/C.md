 ## 解決策
 ## 問題の理解

 一連のタスクが与えられ、それぞれにポイント値と難易度のパーセンテージが設定されています。 スタミナは 1 から始まります。各タスクはスキップすることも、完了することもできます。 タスクを完了すると、現在のスタミナが倍増します。`(1 - p_i / 100)`次のタスクに向けて、あなたに与えながら、`stamina * c_i`すぐにポイントがつきます。 タスクをスキップするとスタミナは変化せず、ポイントも得られません。 目標は、タスク シーケンスの終了までに蓄積される合計ポイントを最大化することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースには多数のタスクが含まれています`n`に続く`n`ペア`(c_i, p_i)`。 の合計`n`すべてのテスト ケースの数は最大 100,000 です。 以来`n`最大 10^5 で、制限時間は 2 秒であるため、これよりも複雑なソリューションを検討することはできません。`O(n)`テストケースごとに。 単純な総当たり再帰や 2^n 状態を使用した動的プログラミングなど、タスクのすべてのサブセットを試行するアプローチは直ちに除外されます。 

困難な場合に微妙なエッジケースが発生します。`p_i`タスクの場合は 100 です。 それを完了すると、その後のすべてのタスクのスタミナがゼロになります。 適切なタイミングでそのようなタスクをスキップしないと、将来の利益を意図せずゼロにしてしまう可能性があります。 同様に、次のようなタスクも`p_i = 0`スタミナを減らさないので、いつでも安全に完了できます。 非常に高いタスク`c_i`でも高い`p_i`慎重なトレードオフが必要です。トレードオフを選択すると、すぐにポイントが得られる可能性がありますが、将来の可能性が減ります。 たとえば、入力が次の場合:```
2
100 100
1 0
```最初のタスクを実行すると 100 ポイントが得られますが、スタミナがゼロになるため、2 番目のタスクは何も貢献しません。 最初のタスクをスキップすると、2 番目のタスクで 1 ポイントが得られますが、これは明らかに悪いです。 正解は最初の課題の 100 点を取ることです。 

## アプローチ

 ブルートフォースソリューションでは、タスクのすべてのサブセットを試行して、合計ポイントを最大化するシーケンスを見つけます。 これには、テスト ケースごとに最大 2^n の可能性が含まれますが、これは実行不可能です。`n = 10^5`。 スタミナは継続的であるため、個別のステップで各タスクのスタミナを追跡する動的プログラミング ソリューションでさえ遅すぎ、メモ化は非現実的になります。 

重要な洞察は、どのようなタスクでも、現在のスタミナがわかっていれば、タスクを完了することによる当面の利益とスタミナの低下による将来の潜在的な損失を比較することが最適な決定であるということです。 スタミナ減少は現在値に を乗算するため、`(1 - p_i / 100)`、すべてのタスクを順番に検討する必要があるため、貪欲なアプローチを採用できます。 ランニングスタミナを維持し、`stamina * c_i`タスクを完了することが有益な場合は、スタミナを合計に乗算します。`(1 - p_i / 100)`減少を説明するため。 決定は簡単です。`p_i = 100`そして将来の課題は前向きです`c_i`、タスクをスキップする必要があります。 それ以外の場合は、常にタスクを実行します`p_i < 100`なぜなら、壊滅的な損失を与えることなくプラスに貢献できるからです。 

より正確な定式化は、次の場合を除いて常にタスクを実行することです。`stamina`極端に低いか、`p_i = 100`。 この問題ではタスクを放棄できるため、タスクから最適なポイントを再帰的に考えることができます。`i`以降はタスクをスキップした結果の値です`i`またはタスクを完了する`i`スタミナを減らして残りのタスクから最適なポイントを獲得します。 演算は乗算的かつ線形であるため、`c_i`、ランニングスタミナ変数を使用して、単一の前方パスでこれを計算できます。

 | 貪欲なフォワードパス | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`stamina = 1`そして`points = 0`。 スタミナは、完了したタスクの現在の乗数を表します。 
2. タスクを順番に繰り返します。 タスク用`i`価値のあるもの`c_i`そして難易度`p_i`:

 1. このタスクを次のように完了した場合に獲得できるポイントを計算します。`stamina * c_i`そしてそれを合計ポイントに加算します。 
2. 次のタスクのスタミナを次のように更新します。`stamina *= (1 - p_i / 100)`。 
3. すべてのタスクが処理された後、蓄積された`points`変数には達成可能な最大ポイントが保持されます。 
4. 出力`points`十分な精度 (小数点以下 10 桁以上) であること。 

機能する理由: このアルゴリズムはスタミナに関するポイントの直線性を利用しています。 すべてのタスクはスタミナを乗算的に減少させるため、タスクをスキップしてもメリットはありません。`p_i < 100`なぜなら、そうすることは将来の乗数を増加させることなく利益を延期するだけだからです。 とのタスク`p_i = 100`スタミナがゼロになります。 ゼロ以外のタスクが続く場合`c_i`、スキップするのが最適ですが、ゼロを乗算するとさらにポイントがゼロになるため、これは自然に処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        tasks = [tuple(map(int, input().split())) for _ in range(n)]
        stamina = 1.0
        points = 0.0
        for c, p in tasks:
            points += stamina * c
            stamina *= (1 - p / 100)
        print(f"{points:.10f}")

solve()
```コードは、以下を使用して複数のテスト ケースを効率的に読み取ります。`sys.stdin.readline`。 各タスクのポイントは、現在のスタミナにその値を乗算して計算されます。 スタミナはタスク後に更新されます。 必要な精度には浮動小数点演算で十分であり、print ステートメントでは少なくとも小数点以下 10 桁の正確性が保証されます。 指定されたタスクを直接反復処理することでオフバイワンエラーが回避され、操作の順序によりポイントを追加した後にスタミナが更新されます。

import sys, io

def run(inp: str) -> str:

    out = io.StringIO()
    sys.stdout = out
    solve()
    return out.getvalue().strip()
