 ## 解決策
 ## 問題の理解

 私たちに与えられたデッキは、`n`カードにはエネルギーコストがかかります。 ボブは、総エネルギー予算を超えずに、特別な「勝利条件」カードをできるだけ多くプレイしたいと考えています。`m`。 各ターン、ボブは最初のカードからのみカードを選択できます。`k`現在のデッキ内のポジション。 カードがプレイされると、そのカードは山札の一番下に移動し、残りのカードは前方に移動します。 勝利条件カードは次の位置から始まります`p`(1 インデックス付き)。 出力は、エネルギー制限を考慮してボブがこのカードをプレイできる最大回数でなければなりません。 

制約は小さいです。`n`、`m`、`k`、 そして`p`すべて ≤ 5000 であり、すべての合計`n`テスト ケース全体の数 ≤ 5000。これは、おおよそ次のようなアルゴリズムを使用できることを意味します。`O(n^2)`最悪の場合の総操作数は約 2,500 万未満にとどまるため、テスト ケースごとに、1 秒の制限としては許容可能です。 

勝利条件カードが最初のカード以外で始まる場合、微妙なエッジケースが発生します。`k`ポジション。 そのような場合、最初のカードに持ち込むために他のカードをプレイする必要があるかもしれません。`k`スロット。 たとえば、次の場合`n=2`、`k=1`、`p=2`、エネルギー`m=42`費用がかかる`[42,1]`、勝利条件は 2 番目のカードですが、プレイできるのは最初のカードのみです。 プレイするとすべてのエネルギーが消費されるため、答えは次のとおりです。`0`、勝利条件をプレイするのに十分なエネルギーがあるにもかかわらず。 デッキの順序を無視した不注意で貪欲なアプローチは、勝利条件をプレイすることを誤って示唆する可能性があります。 

## アプローチ

 素朴なアプローチは、考えられるすべてのプレーのシーケンスをシミュレートすることです。 エネルギーがなくなるまで、各ステップでどのカードを選ぶかというすべての組み合わせを試すことができます。 これは正しく動作しますが、明らかに遅すぎます。最悪の場合、`n=5000`そして`m=5000`、シーケンスの数が指数関数的になります。 エネルギーによる剪定でも、まだ多くの可能性が残されています。 

重要な洞察は、最適な戦略には、勝利条件カードが利用可能になったらすぐに、最初のカードが出る前にそれをプレイすることが含まれることに気づくことです。`k`場合によっては、その前にある他の安価なカードをいくつか削除する必要があるかもしれません。 したがって、この問題は、前から「捨てる」カードを特定の枚数選択するものとして扱うことができます (`x`最初からのカード`p-1`) と最初の末尾から削除する特定の数値`k`窓（`y`カードは右から）。 これにより、問題は二重ループに短縮されます。先頭から何枚、最後から何枚取り除くかを列挙し、残りのエネルギーで勝利条件のカードを何回プレイできるかを計算します。 内部計算には基本的な算術のみが必要です。 

これにより、指数関数的検索は次のように変換されます。`O(k^2)`テストケースごとに。 以来`k ≤ n ≤ 5000`そしてすべての合計`n`テスト ケースが 5000 以下であれば、ソリューションは十分に効率的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(2^n) | O(n) | 遅すぎる |
 | 最適な前後列挙 | テスト ケースごとに O(k^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力デッキを 0 インデックスに変換し、勝利条件カードの位置を次のように記録します。`p-1`。 
2. 前面から取り除くカードの数を繰り返します。`front_removals`からの範囲`0`に`min(p-1, k-1)`。 前からカードを取り除くと、プレイ可能なウィンドウから勝利条件までの距離が減少します。 
3. それぞれについて`front_removals`、最初のカードの後ろから取り除かれたカードの数を繰り返します。`k`カード`back_removals`から`0`に`k-1-front_removals`。 これにより、勝利条件カードが最初のカード内に収まるようになります。`k`ポジション。 
4. これらのカードを除去するのに費やされる合計エネルギーを計算します。前から除去されたカードと後から除去されたカードのコストを合計します。 
5. 残りのエネルギーを使用して、勝利条件カードを何回プレイできるかを計算します。`(remaining_energy) // (cost of win-condition card)`。 
6. すべての有効な組み合わせの最大数を追跡します。 

**機能する理由:** 反復のたびに、ウィンドウ サイズを超えずに勝利条件カードをプレイ可能なウィンドウに取り込むためのあらゆる方法を検討します。`k`。 両端から取り外されたカードの数を列挙することで、すべての有効な構成が考慮されます。 除去が固定されるとエネルギーは順序に依存しないため、勝利条件カードをプレイできる回数の計算は単なる整数の除算になります。 これにより正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k, p, m = map(int, input().split())
    a = list(map(int, input().split()))
    p -= 1  # convert to 0-indexed
    res = 0

    # enumerate number of cards removed from front
    for front in range(min(p, k) + 1):
        # enumerate number of cards removed from back of first k cards
        for back in range(k - front + 1):
            if front + back > k:
                continue
            energy_spent = sum(a[:front]) + sum(a[p+1-p+back:p+1+back]) if back > 0 else sum(a[:front])
            if energy_spent > m:
                continue
            remaining_energy = m - energy_spent
            max_win_plays = remaining_energy // a[p]
            res = max(res, max_win_plays)
    print(res)
```このソリューションは、勝利条件カードの位置を 0 から始まるインデックスに慎重に変換します。 二重ループには、最初のループの表と裏からカードを削除するすべての方法が列挙されています。`k`ポジション。 の`sum`計算では、取り除かれたカードのエネルギー コストが処理され、整数の除算で勝利条件カードをプレイできる回数が求められます。 計算するときはインデックスに注意する必要があります`back`撤去。
