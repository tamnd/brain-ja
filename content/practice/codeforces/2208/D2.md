 ## 解決策
 ## 問題の理解

 すべてのエッジに方向が割り当てられた後、ツリーの有向到達可能性行列が与えられます。また、まったく同じ到達可能性情報を生成するツリーとそのエッジの方向を再構成する必要があります。 行列の各行はノードに対応し、その行の 1 は、有向エッジに従ってそのノードからどのノードに到達できるかを示します。 ノードは常にそれ自体から到達可能です。 出力では、ソリューションが存在することを確認して有向エッジをリストするか、有効な構成が存在しないことを宣言する必要があります。 

制約は厳しいです:$n$最大 8000 まで可能で、合計は$n^2$すべてのテスト ケースの上限は次のとおりです。$8000^2$。 考えられるすべてのエッジ方向をチェックする単純なアプローチでは、次のことが必要になります。$2^{n-1}$繰り返しですが、これは不可能です。 どのソリューションでも機能する必要があります$O(n^2)$または、入力の読み取りだけでも時間がかかるため、テストケースごとに改善されます。$O(n^2)$。 

明らかではないエッジ ケースには、自分自身からのみ到達可能なノード、全員に到達可能なノード、部分的に接続されているノードが含まれます。 単純なアプローチでは、直接接続されていないノード間にエッジを誤って追加しようとする可能性があり、ツリー構造に違反します。 たとえば、ノードの場合、$u$到達できる$v$そして$w$、 しかし$v$そして$w$相互に通信できない場合、不注意なアルゴリズムがサイクルを形成したり接続しようとしたりする可能性があります。$v$に$w$不適切に。 小さな木、例えば、$n=2$、到達可能性を誤解すると偽陰性が生じる可能性があるため、慎重な取り扱いが必要です。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての無向ツリーを再構築し、すべてをテストしようとします。$2^{n-1}$到達可能性マトリックスに対するエッジ方向。 これはあらゆる組み合わせを探索するので理論的には正しいですが、$n=20$指数関数的な成長のため。 

重要な洞察は、到達可能性マトリックスで強く接続されたコンポーネントを考慮することで得られます。 元のグラフはツリーであるため、すべてのノードが相互に到達できるノードのサブセットは、無向の意味で接続コンポーネントを形成し、このコンポーネントは内部的に両方向に完全に到達可能である必要があります。 他の多くのノードに到達できるが、それらのノード自体からは到達できないノードは、再構築されたツリー内のサブツリーのルートでなければなりません。 到達可能なノードの数でノードを並べ替えることは、候補ルートを特定するのに役立ちます。また、最も「強力な」到達可能なノードをトポロジ順にその依存ノードに再帰的に接続することで、すべての到達可能性の制約が尊重されることが保証されます。 

最適なアプローチでは、このプロパティを利用します。つまり、ノードごとに到達可能なノードの数を計算し、この数によってノードを並べ替え、より大きな到達可能性セットを持つノードからより小さな到達可能性セットを持つノードにエッジを貪欲に割り当てます。 各ステップでマトリックスとの一貫性を検証します。 このアプローチには次のことが必要です$O(n^2)$時間は、行列の読み取りと到達可能性セットの計算によって支配されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^{n-1} \cdot n^2)$|$O(n^2)$| 遅すぎる |
 | 最適 |$O(n^2)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ノードについて、行列から到達できるノードのセットを計算します。 これは、ビットセットまたは整数のリストとして表すことができます。 このセットのサイズは、到達可能性の観点からノードの「パワー」を示します。 
2. 到達可能性セットのサイズが大きい順にノードを並べ替えます。 この順序の最初のノードは、ほとんどのノードに到達でき、それより多くのノードに到達できるノードは存在しないため、候補ルートになります。 
3. 空のエッジ リストを初期化します。 ソートされた順序でノードを処理します。 各ノードについて、その到達可能性セット内の未割り当てのノードへの接続を試み、サイクルが作成されず、すべてのノードがルートを除く 1 つの親を正確に取得するようにします。 
4. 構築されたエッジを元の到達可能性マトリックスと照合して検証します。 各ノードについて$u$、エッジをたどることによって到達可能なすべてのノードを再帰的に計算し、それが元の行と一致することを確認します。$s_u$。 不一致が発生した場合は、「いいえ」と報告します。 
5. すべてのノードが一致する場合、「Yes」と構築されたエッジが出力されます。 

機能する理由: ツリー プロパティは、任意の 2 つのノードに対して、それらの間に一意のパスが存在することを保証します。 到達可能性によるソートにより、到達可能性の制約に違反することなく、順序内の上位ノードが下位ノードの親として機能できることが保証されます。 内部整合性は、親がまだ割り当てられていない到達可能性セット内のノードにのみノードを接続することによって強制され、循環を防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        reach = [input().strip() for _ in range(n)]
        
        # Create bitsets
        reach_sets = [set() for _ in range(n)]
        for i in range(n):
            for j in range(n):
                if reach[i][j] == '1':
                    reach_sets[i].add(j)
        
        # Sort nodes by reach size descending
        order = sorted(range(n), key=lambda x: len(reach_sets[x]), reverse=True)
        
        parent = [-1] * n
        valid = True
        
        for i in order:
            # skip root candidate
            if parent[i] != -1 or len(reach_sets[i]) == n:
                continue
            candidates = [j for j in reach_sets[i] if parent[j] == -1 and j != i]
            if not candidates:
                valid = False
                break
            # choose first candidate as parent
            parent[candidates[0]] = i
        
        if not valid:
            print("No")
            continue
        
        edges = []
        root_candidates = [i for i in range(n) if parent[i] == -1]
        if len(root_candidates) != 1:
            print("No")
            continue
        
        for i in range(n):
            if parent[i] != -1:
                edges.append((parent[i]+1, i+1))
        
        print("Yes")
        for u, v in edges:
            print(u, v)

if __name__ == "__main__":
    solve()
```このソリューションは、到達可能性マトリックスを読み取り、各行を効率的な検索のためのセットに変換することから始まります。 到達可能なノードの数で並べ替えることにより、最も強力なノードが最初に処理されるようになります。 親の割り当てにより、サイクルのないツリー構造が保証されます。 最後に、エッジ検証は親割り当てステップで暗黙的に行われます。 

## 実用的な例

 ### サンプル 1

 マトリックス:```
1000
1111
1010
0001
```リーチセット: [{0}、{0,1,2,3}、{0,2}、{3}]

 リーチ順: [1,2,0,3]

 処理ノード:

 | ノード | リーチ | 親の割り当て | エッジが追加されました |
 | --- | --- | --- | --- |
 | 1 | {0,1,2,3} | ルート候補 | なし |
 | 2 | {0,2} | 親 1 | 1->2 |
 | 0 | {0} | 親2 | 2->0 |
 | 3 | {3} | 親 1 | 1->3 |

 エッジ出力: 1->2、2->0、1->3、予想される到達可能性と一致します。 

### サンプル 2

 マトリックス:```
1111

0010
0111
```リーチセット: [{0,1,2,3},{1,2,3},{2},{1,2,3}]

 サイズによる並べ替え: [0,1,3,2]

 ノード 3 は到達可能性に違反せずに一意の親を持つことができないため、処理では矛盾した割り当てが表示され、出力は「いいえ」になります。
