 ## 解決策
 ## 問題の理解

 有向グラフのバイナリ到達可能性行列が与えられます。$n$ノード。 行列は、すべての順序ペアについて、$(i, j)$、ノードかどうか$i$ノードに到達できる$j$有向エッジを介して。 この行列を生成した基礎となるグラフは、無向ツリーの有向バージョンであることが保証されています。つまり、元の構造は正確に$n-1$エッジはあり、サイクルはありませんが、各エッジには任意の方向が割り当てられています。 

タスクは、無向ツリー構造が存在するかどうかを判断することです。$n$結果として得られる到達可能性行列が指定されたものと正確に一致するように、ノードとそのエッジの方向割り当てを組み合わせます。 存在する場合は、1 つの有効なツリーと方向を構築する必要があります。 

重要なオブジェクトはツリーだけではなく、その推移的な到達可能性構造です。 有向ツリーでは、到達可能性は完全に方向パターンによって決まります。 一部の方向では、すべてのノードがサブツリーに到達するルート構造が生成されますが、他の方向では、より断片化された到達可能性パターンが作成されます。 マトリックスは、直接のエッジだけでなく、このクロージャをエンコードします。 

テストごとの制約は小さいですが、$n \le 500$、までありますが、$10^4$合計三次和の境界を使用してテストします。 これは、$O(n^3)$テストごとに許容されますが、3 次よりも悪いものは壊れます。 特に、多数の候補ツリーの到達可能性を最初から再計算するのは遅すぎますが、Floyd スタイルまたは BFS ベースのチェックを使用して 1 つの候補を検証するのは問題ありません。 

微妙なエッジ ケースは、複数のノードが相互に到達する場合です。 有向ツリーでは、相互到達可能性は、それらが同じ強く接続されたコンポーネント内にあることを意味します。これは、それらの間のすべてのエッジが双方向である場合にのみ発生しますが、エッジは単一に方向付けられるため、ツリーでは不可能です。 したがって、1 より大きい SCC は直ちに疑わしいものになります。 別の失敗モードは、ツリー誘導クロージャではなく、任意の到達可能性として行列を解釈することです。 多くの行列は推移性を満たしますが、構造的疎性が欠落しているため、ツリーから取得することができません。 

## アプローチ

 強引な観点は、ツリー構造とその方向の両方を同時に再構築しようとすることです。 ルートを推測し、エッジを外側に向けて、結果の到達可能性が行列と一致するかどうかを確認することもできます。 ルート化された外向きツリーは非常に特殊な構造を生成するため、これはすでに失敗しています。つまり、到達可能性は祖先と子孫の関係に対応し、サブツリー内のノードのみが到達可能です。 すべてのルートとすべての可能なツリー構造を試すことは、ラベル付きツリーの数が次のとおりであるため、本質的に指数関数的です。$n^{n-2}$、各候補をチェックするだけでも$O(n^2)$到達可能性の検証により、実行不可能な検索スペースが与えられます。 

重要な観察は、到達可能性行列が、ある方向によって引き起こされる部分的な順序をすでにエンコードしているということです。 If ノード$i$ノードに到達できる$j$そうすると、有効な構造では、$j$の「下流領域」に存在する必要があります。$i$指向性ツリー内。 これは、到達可能性の包含という観点から考えることを示唆しています。各ノードは、それが支配するノードのセットに対応します。 

ここで、有向ツリーの構造を考えてみましょう。 ノードを修正すると$r$、エッジをそこから離れる方向に向けると、到達可能性セットはネストされます。$u$より根元に近いです$v$、 それから$v$の到達可能なセットはのサブセットです$u$の到達可能なセット。 この入れ子特性が、テストできる主な構造シグネチャになります。 

重要な洞察は、有効なノードは、到達可能性ベクトルをセットに含めることによって順序付けできるということです。 ソートが完了すると、この包含順序で隣接するノードは、基礎となるツリー内の潜在的な親子関係に対応します。 これにより、問題はグローバルな再構築からローカルな隣接関係の回復まで軽減されます。 

各行を解釈すると$s_i$到達可能なノードのビットセットとして、そのノードを定義できます。$u$ノードの親になることができます$v$もし$s_v \subset s_u$中間ノードはありません$w$そのような$s_v \subset s_w \subset s_u$。 これはまさに、インクルージョンによって引き起こされるポセットにおけるカバー関係です。 基礎となる構造はツリーであるため、これらのカバー関係は正確に形成されます。$n-1$マトリックスが有効な場合はエッジ。 

この候補ツリーを再構築した後、到達可能性セットの観点から各エッジをスーパーセットからサブセットに向け、最終的に再計算された到達可能性が入力と一致することを検証します。

 ## アルゴリズムのチュートリアル

 行ごとに処理します$s_i$どのノードから到達可能かを記述する整数ビットマスクまたは文字列として$i$。 

1. ノードのペアごとに$i, j$かどうかを計算します。$s_i$のスーパーセットです$s_j$、 意味$j$から到達可能です$i$。 これにより、到達可能性の包含に基づいたノード上の半順序構造が得られます。 このステップが必要なのは、直接隣接性が与えられず、推移的閉包のみが与えられるためです。 
2. ノードを到達可能なノード数の降順に並べ替えます。 より多くのノードに到達するノードは、方向階層で「上位」になります。 この順序付けは包含に近似します。つまり、より大きなセットが祖先となる傾向があります。 
3. 各ノードについて$v$、親を見つけてください$u$そのような$s_v \subset s_u$そしてノードはありません$w$と$s_v \subset s_w \subset s_u$。 この順序で最も近い厳密なスーパーセットを選択します。 これにより、カバー関係のみを接続することが保証され、ツリーの最小性に違反するショートカットが回避されます。 
4. 有向エッジを追加する$u \rightarrow v$。 方向性が一貫しているのは、$u$すべてに到達する$v$プラス以上に達すると、$u$上に横たわる必要があります$v$到達可能性階層内。 
5.施工後$n-1$エッジでは、各ノードから BFS/DFS を使用して到達可能性を再計算し、指定された行列と比較します。 不一致があった場合は「No」を出力します。 

### なぜ効果があるのか

 有向ツリー内の到達可能性セットは、正しい方向階層を通じて解釈される場合、包含の下で層状ファミリーを形成します。 すべてのノードの到達可能なセットは、構造の仮想的なルート表現のサブツリーに対応します。 元のツリーの親子関係は、この包含ポセットのカバー関係に正確に対応します。 なぜなら、木にはサイクルがなく、まさに$n-1$エッジでは、行列が有効であれば、このポーズセットのカバー グラフ自体がツリーである必要があります。 推移性の違反または中間包含の欠落はこのプロパティを破り、検証中に検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = [input().strip() for _ in range(n)]

    # precompute reachability sets as bitsets (integers)
    reach = []
    for i in range(n):
        mask = 0
        for j in range(n):
            if s[i][j] == '1':
                mask |= 1 << j
        reach.append(mask)

    def is_subset(a, b):
        return (a | b) == b

    parent = [-1] * n

    # try to assign parent as minimal strict superset
    for v in range(n):
        best = -1
        for u in range(n):
            if u == v:
                continue
            if is_subset(reach[v], reach[u]):
                if best == -1:
                    best = u
                else:
                    # choose tighter superset
                    if is_subset(reach[u], reach[best]):
                        best = u
        parent[v] = best

    # validate we got a tree
    if parent.count(-1) != 1:
        print("No")
        return

    # build adjacency
    g = [[] for _ in range(n)]
    edges = []
    root = parent.index(-1)

    for v in range(n):
        if v == root:
            continue
        u = parent[v]
        if u == -1:
            print("No")
            return
        g[u].append(v)
        edges.append((u, v))

    # recompute reachability
    def dfs(start):
        stack = [start]
        vis = [0] * n
        vis[start] = 1
        while stack:
            x = stack.pop()
            for y in g[x]:
                if not vis[y]:
                    vis[y] = 1
                    stack.append(y)
        return vis

    for i in range(n):
        got = dfs(i)
        for j in range(n):
            if (got[j] == 1) != (s[i][j] == '1'):
                print("No")
                return

    print("Yes")
    for u, v in edges:
        print(u + 1, v + 1)

t = int(input())
for _ in range(t):
    solve()
```この構築は、各到達可能性行をビットマスクとしてエンコードすることに依存しているため、サブセット チェックは高速なビット単位の操作になります。 親選択では、厳密なスーパーセットをスキャンし、包含の下で最も近いスーパーセットを選択します。これにより、ポーズセット内の直接のカバー関係が再構築されます。 候補ツリーを構築した後、完全な到達可能性検証によって正確性が保証されます。これは、次の理由により実現可能です。$n \le 500$そしてDFSが実行される$n$回。 

微妙な点は、ルートの一意性を確保することです。 ルートは、到達可能なセットが最大であるノードであり、通常はそれ自体を含むすべてのセットであり、厳密なスーパーセットを持つべきではありません。 このようなノードが複数出現すると、構築に一貫性がなくなり、拒否されます。

 次の小さなケースを考えてみましょう$n = 4$:

| ノード | 到達可能なセット |
 | --- | --- |

 | 3 | {2,3} |

 ノード 2 には最大のセットがあるため、ルートになります。 {2,3} ⊂ {1,2,3} であるため、ノード 3 はノード 2 の下に接続するのが最適であり、ノード 1 も適合しますが、ジャンプが大きすぎます。 ノード 4 は、そのセットが {2,3} に含まれていますが、中間構造なしでは直接 {1,2,3} に含まれていないため、ノード 3 の下に接続されます。 

結果として得られるエッジは、最小限のスーパーセットの選択に応じて追加の分岐 2 → 1 を備えたチェーン状の構造 2 → 3 → 4 を形成します。

 ## 特殊なケース

 重要なエッジ ケースは、2 つのノードに同一の到達可能性行がある場合です。 この状況では、どちらも他方の厳密なスーパーセットではないため、どちらも親になることはできません。 サイクルまたは双方向構造を導入せずに同一の非自明な到達可能性をエンコードできる有効なツリーがないため、アルゴリズムは正しく失敗します。 

もう 1 つのエッジ ケースは、1 つのノードが他のすべてのノードに到達するが、他のノードは相互に到達しない、星型の到達可能性パターンです。 ここでは、最大の行がルートになり、他の行はすべてルートの厳密なサブセットであるため、その下に直接接続されます。 この構築により、有効なスターが自然に生成されます。 

3 番目のケースには、次のような一貫性のない推移性が含まれます。$i$到達する$j$、$j$到達する$k$、 しかし$i$届かない$k$。 DFS 検証はこれを即座に検出します。これは、どのツリー方向の到達可能性も、構築されたエッジと一致する推移閉包でなければならず、不一致があると強制的に拒否されるためです。
