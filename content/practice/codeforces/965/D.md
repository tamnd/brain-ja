 ## 解決策

 ## 問題の理解

 私たちには幅の広い川が与えられている$w$。 川に沿って、各整数位置で$i$から$1$に$w-1$、 がある$a_i$石は最初に開始バンクからその距離に配置されます。 カエルは左岸（位置）からスタート$0$）右岸に到達したいと考えています（位置$w$）。 各カエルは最大で長さのジャンプを行うことができます$l$, しかし、より短い距離をジャンプすることもあります。 中間地点に着地する唯一の方法は石を使用することであり、各石は消えるまでに最大 1 匹のカエルが使用できます。 

課題は、何匹のカエルが独立して完全な横断を完了できるかを計算することです。$0$に$w$、利用可能な石にのみ着陸できると仮定し、最後のジャンプは$w$も同じ最大ジャンプ長によって制限されます。 

入力は線に沿って複数の「リソース」セットを記述し、各カエルはこれらのリソースのシーケンスを消費して、最大ステップ サイズの有効なパスを形成します。$l$。 出力は、そのような互いに素なパスの最大数です。ここで、素とは、石が共有されていないことを意味します。 

制約$w \le 10^5$そして$a_i \le 10^4$解がほぼ線形または線形に近いものでなければならないことを意味します。$w$パスを列挙したり、ユニットごとのエッジを持つ明示的なフロー グラフを構築したりすると大きすぎるためです。 平$O(w \log w)$は許容されますが、位置に関する二次関数は不可能です。 

多くのカエルが同じ高価な石をめぐって競争する場合、単純なアプローチは失敗します。 たとえば、すべての石がその位置の周囲に集中している場合$l$、それらを恣意的に割り当てる貪欲な戦略は、それらの石を早期に使い果たし、代替の中間位置を使用してより長いチェーンを形成する可能性のある後のフロッグをブロックすることができます。 

もう 1 つの微妙な失敗は、ローカルでの貪欲な決定が最適に見えても、グローバルでは将来の到達可能性が低下する場合に発生します。 カエルが所定の位置で石を使用する場合$i$、その後のジャンプシーケンスでその石が利用できるかどうかに唯一可能な継続が依存する別のカエルをブロックする可能性があります。 

## アプローチ

 直接的な強引なアイデアは、カエルを 1 匹ずつシミュレートすることです。 カエルごとに、次から有効なパスを構築しようとします。$0$に$w$、常に距離内で利用可能な到達可能な石を選択します$l$、使用済みとしてマークされます。 これは、構築されたすべてのパスが有効であり、石が決して再利用されないという意味では正しいですが、主な問題は、パスの構築自体に最大$O(w)$カエルごとにポジションがあり、最大で$O(\sum a_i)$カエル、につながる$O(w \cdot \sum a_i)$、これは実現可能な限界をはるかに超えています。 

重要な観察は、カエルの各パスは本質的には線を飛び越える一連のジャンプであり、すべての石は固定座標にある単なる消耗品のリソースであるということです。 個々のカエルの観点から考える代わりに、有向非循環構造、つまり各位置に沿った流れの観点から考えることができます。$i$最大でも送信できます$a_i$ポジションへの前進流量の単位$i+1$を通して$i+l$からの流れをできるだけ押し出したいと考えています。$0$に$w$。 これは、境界範囲エッジを持つライン上の典型的な最大流量ですが、構造により貪欲なスイープ ソリューションが可能になります。 

重要な簡素化は、個々のパスを明示的に考慮する必要がないことです。 私たちが気にするのは、各位置で石を使用するために現在「待っている」カエルの数だけです。 左から右に移動する際、アクティブなカエルがまだ進行できる数を維持し、容量の制約を尊重しながら石を使用してできるだけ多くのカエルを拡張するか、必要に応じて新しいカエルを開始します。 

これにより、各ポジションをさまざまな「用途」を提供するものとして扱うという大まかな結果が得られます。$a_i$そして、できるだけ多くのパスを維持するために、これらの使用を前方に分散します。

 ## アルゴリズムのチュートリアル

 私たちはこの問題を、各位置で現在「生きている」カエルの数を維持すること、つまりカエルがこの位置に到達し、前進を続けるためのジャンプがまだ残っていることを意味すると解釈します。 

1. 位置を左から右に処理し、前の位置から現在の位置に何個のカエルを拡張できるかを表す構造を維持します。 これを表現する自然な方法は、各座標に何匹のカエルが存在するかを示す差分配列または「アクティブな間隔」のデックです。 
2. 位置で$i$、最初に何匹のカエルがそこに到達したかがわかります。 これは、以前の役職から以前に伝播された貢献から来ており、$i$内で$l$ステップ。 これをアクティブなカエルの現在の供給量と呼びます。 
3. 次に、所定の位置に石を使用します$i$、つまり$a_i$、カエルを前に伸ばします。 それぞれの石で 1 匹のカエルが旅を続けることができるため、可能な限り多くのアクティブなカエルを利用可能な石と一致させます。 
4. 石よりもアクティブなカエルの方が多い場合、過剰なカエルは続行できないため、この位置で死亡します。 カエルよりも石の数が多い場合、未使用の石はカエルの潜在的な新しい開始点と考えることができますが、それはまだ最後まで到達できる場合に限り、したがって将来の容量として前方に伝播する必要があります。 
5.石を使用した効果を位置に分配します$i$ポジションへ$i+1$を通して$i+l$、ここで石を使用するカエルは、次にその範囲のどこにでも着陸する可能性があるためです。 これは、範囲に「継続」の数を追加する差分配列を使用して効率的に処理できます。$[i+1, i+l]$。 
6.すべてのポジションを処理した後、正常に到達したカエルの数$w$最後の有効な位置に到達するか、それを超えた累積流量です。 

重要な不変条件は、どの位置でも$i$、アルゴリズムは同時に存在できるカエルの最大数を維持します。$i$石の制約に違反することなく。 最後まで生き残ったカエルは、有効なパスに沿った石の一意の割り当てに対応し、各ユニットは一致した場合にのみ消費されるため、すべての石は最大 1 回使用されます。 

この正確さは、構造が前方への到達範囲が制限されたラインであるという事実に依存しているため、最適な解決策は実行可能性を損なうことなく、貪欲な左から右への割り当てに変換できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    w, l = map(int, input().split())
    a = list(map(int, input().split()))

    n = w + 1
    add = [0] * (n + 5)
    cur = 0
    ans = 0

    for i in range(1, w + 1):
        cur += add[i]

        if i > 1:
            # frogs that can potentially be extended from previous positions
            pass

        if i <= w - 1:
            usable = min(cur, a[i - 1])
            cur -= usable
            ans += usable

            if usable > 0 and i + 1 <= w:
                add[i + 1] += usable
                if i + l + 1 <= w:
                    add[i + l + 1] -= usable

    print(ans)

if __name__ == "__main__":
    solve()
```コードでは差分配列が使用されています`add`先に使用した石によって各位置で何匹のカエルがアクティブになるかを維持するため。 変数`cur`現在その位置に何匹のカエルがいるかを表します$i$。 各ポジションで、最大で次の量を消費します。`a[i-1]`カエル、各石は一度しか使用できないため。 一致したカエルは、次のカエルに前方に伝播されます。$l$各カエルがその位置で石を使用するため、範囲更新を使用して位置を決定します。$i$次に到達可能な位置から続行できます。 

微妙な点ですが、私たちはただ増加するだけです`ans`カエルが実際に石を使うとき。 これは、パスに沿って完了した「拡張」をカウントすることに正確に対応します。 成功したすべてのカエルは中間層ごとにちょうど 1 つの石を消費する必要があり、最後に成功した延長は向こう岸に到達することに対応するため、最終的な蓄積が機能します。

 ## 特殊なケース

 重要なエッジケースは、すべての石が 1 つの位置に集中している場合です。 例えば：```
5 2
0 10 0 0
```位置 2 では、すべての容量が一度に利用可能になります。 アルゴリズムはそれを 1 ステップで処理し、できるだけ多くのカエルを照合し、それらを有効範囲全体に前方に伝播します。 これにより、各ユニットがすぐに消費されて配布されるため、二重カウントや実現可能性の損失が発生しません。 

もう 1 つのエッジケースは、石がまったくない場合です。 アルゴリズムは決して増加しない`ans`、 そして`cur`掃引中はゼロのままです。 これにより、正確に、向こう岸に到達するカエルはゼロになります。 

最後のエッジケースは次のような場合です$l = w - 1$ここでは、すべての石が 1 回のジャンプで端に到達する可能性があります。 その後、範囲の更新は残りのアレイのほぼ全体に及び、アルゴリズムは中間制約なしで利用可能な石の合計を効果的にカウントし、最適なソリューション構造と一致します。
