 ## 解決策

 ## 問題の理解

 あるグループが同じ紙飛行機を作りたいと考えていますが、飛行機を作る唯一の方法は紙を介して間接的に作ることです。 各シートは固定枚数の飛行機に折り畳むことができ、紙はパック単位でのみ販売され、各パックには固定枚数のシートが含まれています。 

要件の構造は単純ですが、制約が階層化されています。 すべての人が独立して一定数の飛行機を製造できなければなりません。 複数の飛行機が 1 枚のシートから得られるため、最初に飛行機の要件を 1 人あたりのシート要件に変換し、次に人数に応じてスケールし、最後にシートをパックに変換します。これは、分割パックを購入することができないためです。 

重要な数量は、合計で何枚必要かです。 各シートが生成する場合`s`飛行機なら各人が必要とする`ceil(n / s)`部分的なシートが存在しないため、シート。 横切って`k`必要なシートの合計は次のようになります。`k * ceil(n / s)`。 シートの枚数がわかったら、それをサイズのパックに換算します`p`別の天井分割を使用します。 

制約は十分に小さいため、定数時間の算術解はどれでも十分です。 すべての変数は最大 10^4 であるため、直接乗算でも 10^8 にしか達しません。これは Python の整数の範囲内に収まり、O(1) 計算を超える最適化は必要ありません。 

間違いが発生する主な場所は、丸めを正しく処理する場合です。 たとえば、人が 5 機の飛行機を必要とし、各シートで 2 機の飛行機が作成される場合、2 枚のシートで作成できるのは 4 機の飛行機だけであり、これでは不十分です。 単純な整数除算では、3 シートではなく 2 シートが誤って割り当てられてしまいます。シートをパックに変換するときにも同じ問題が発生します。 

もう 1 つの微妙な間違いは、天井分割の適用が遅すぎる、または早すぎることです。 たとえば、乗算後の四捨五入`k`ここでは直線性があるため、「per person」の代わりに機能しますが、不注意に実装するときに間違った段階で丸めると、1 つずつずれたエラーが発生することがよくあります。 

## アプローチ

 この問題を考える強引な方法は、パックを 1 つずつ購入し、シートを配布し、全員が十分な飛行機を生産できるかどうかを確認することをシミュレーションすることです。 パックを追加するたびに、何機の飛行機を製造できるかを再計算し、要件を検証します。 概念的には単純ですが、このアプローチは非効率的です。なぜなら、パックの数が膨大になる可能性があり、各チェックですべてのシートにわたる合計生産量を再計算する必要があり、パックの候補数ごとに O(k) 評価が繰り返されることになるからです。 

ただし、問題の構造により、シミュレーションは必要ありません。 各パックは固定数のシートを提供し、各シートは固定数の飛行機を提供し、各人の要件は同じです。 これにより、問題は決定論的な変換パイプラインに変わります。つまり、1 人あたりの飛行機数から 1 人あたりのシート数、そして合計シート数、そしてパックへと変わります。 

重要な観察は、分割境界での切り上げを除いて、すべての変換が線形であるということです。 全体的な最小シート数を満たすだけでよいことが分かると、問題は 1 つの天井分割を 2 回計算することになります。

 ## アルゴリズムのチュートリアル

 1. 1人が何枚作る必要があるかを計算します。`n`飛行機。 1枚ごとに作っているので、`s`飛行機、私たちは計算します`need_per_person = ceil(n / s)`。 これにより、飛行機がシートごとに均等に分割しない場合でも、人員への供給が不足することはありません。 
2. この 1 人あたりの要件を人数で乗算して合計要件に変換します。`total_sheets = k * need_per_person`。 この集約が機能するのは、各人の要件が独立していて同一であるためです。 
3. シートをパックに変換します。 各パックの内容は、`p`シートなのでパック数は`packs = ceil(total_sheets / p)`。 これにより、部分的なパックを購入することがなくなります。 
4. 計算されたパック数を出力します。 

主な微妙な点は、両方の部門が床部門ではなく天井部門であることを確認することです。 丸めステップが 1 つ欠けていると、要件が過小評価され、無効なソリューションが生成されます。 

### なぜ効果があるのか

 このアルゴリズムが機能するのは、すべての制約が単調かつ線形であるためです。シートを増やしても飛行機の製造能力が低下することはなく、各変換は実現可能性を維持します。 唯一の不連続点は、飛行機ごとのシートとシートごとのパックの分割不可能性によって生じ、両方とも天井分割によって正確に処理されます。 両方の丸めポイントが考慮されると、計算された数値はすべての制約を満たす最小値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

k, n, s, p = map(int, input().split())

need_per_person = (n + s - 1) // s
total_sheets = k * need_per_person
packs = (total_sheets + p - 1) // p

print(packs)
```最初の行は、シートごとの飛行機の天井分割を計算します。 2 番目はすべての人々を集計します。 最後のラインでは、同じ天井パターンを使用してシートをパックに変換します。 表現`(x + d - 1) // d`は、Python の上限除算の標準的な整数トリックであり、浮動小数点演算を回避し、制約内のすべての整数範囲の正確さを維持します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    k, n, s, p = map(int, input().split())

 ## 特殊なケース

 特殊なケースとしては、1 人あたり 1 枚のシートですでに十分な場合があります。 入力の場合:```
k=4, n=1, s=10, p=3
```人それぞれ必要なもの`ceil(1/10)=1`シート。 合計シートは4枚で、パックは`ceil(4/3)=2`。 このアルゴリズムは、シートの端数による過小評価を正しく回避します。 

もう 1 つの特殊なケースは、パック サイズが合計シート要件よりも大きい場合です。 入力の場合:```
k=1, n=5, s=2, p=100
```得ます`ceil(5/2)=3`シートなので合計3枚になります。 必要なシートは 3 枚だけですが、1 パック購入する必要があります。 アルゴリズムが生成するのは、`ceil(3/100)=1`、パックの粒度によって引き起こされる過剰供給を正しく処理します。
