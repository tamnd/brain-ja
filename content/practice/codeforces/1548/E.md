 ## 解決策
 ## 問題の理解

 天井はグリッドに分割されており、各行は固定量のペイントを提供し、各列は別の固定量を提供します。 これにより、すべてのセルのペイント レベルが 2 つの配列によって完全に決定されます。1 つは行にアタッチされ、もう 1 つは列にアタッチされます。 セルは、行と列の合計ペイントが十分に小さい場合、特に合計が所定のしきい値を超えない場合、「不良」とみなされます。 タスクは不良セルを数えることではなく、エッジを共有するセルを接続したときに現れる不良セルの接続されたクラスターの数を数えることです。 

グリッドには最大がありますが、$2 \cdot 10^5$行と列の場合、各セルの値は行の項と列の項に分離できるため、構造は任意ではありません。 この付加的な構造は、グリッドを非構造化グラフとして扱うことを妨げる重要な制限です。 

グラフを直接解釈すると、次のことが示唆されます。$4nm$隣接エッジは実現不可能です。 制約$n, m \le 2 \cdot 10^5$グリッド上の二次または二次に近いものはすべて除外されます。 グリッドを保存することさえ不可能であるため、すべてのソリューションはセルについて暗黙的に推論する必要があります。 

素朴だが重要なベースラインは、グリッドを明示的に構築し、不良セルをマークし、フラッド フィルを実行することです。 これはメモリ上ですでに失敗していますが、メモリが無視されたとしても、次のことが必要です。$O(nm)$仕事。 

すべてのセルが不良であるか、すべてが良好な場合には、微妙なエッジ ケースが発生します。 まったく悪いケースでは、答えは 1 ですが、単純なフラッド フィルは依然として横断を試みる可能性があります。$4nm$トランジションとタイムアウト。 すべて正常な場合、答えは 0 ですが、少なくとも 1 つの不良セルを想定した不注意な実装では、コンポーネント数が誤って 1 に初期化されることがよくあります。 

本当に難しいのは、接続性が 2D グリッド上で定義されているにもかかわらず、その条件が分離可能な方法で行と列のインデックスにのみ依存することです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての値を計算します$a_i + b_j$、セルに満足のマークを付けます$a_i + b_j \le x$、グリッド上で DFS または BFS を実行します。 これらのマークされたセルでは接続が正確に定義されているため、これは正しいです。 

コストは、次のような事実から発生します。$nm$細胞。 と$n, m \approx 2 \cdot 10^5$、すべてのペアを反復処理することすら不可能です。$4 \cdot 10^{10}$操作。 ボトルネックはグリッドの生成または検査です。 

重要な構造観察は、固定列の場合です。$i$、条件$$a_i + b_j \le x$$と同等です$$b_j \le x - a_i.$$したがって、行ごとに、不良セルは列のソート順でプレフィックスを形成します。$b_j$。 同様に、固定列の場合、条件はソート順に行の接頭辞になります。$a_i$。 これにより、2D しきい値の形状が単調な間隔に変わります。 

グリッドについて考える代わりに、不良セルと正常なセルの境界について考えるようになります。 各行は列のしきい値に影響し、各列は行のしきい値に影響します。 接続性は、これらのしきい値が交差する場合にのみ変更されます。 

重要な洞察は、行の不良セグメントが列の不良セグメントと出会う「境界交差点」をたどることによって、すべての接続されたコンポーネントを追跡できることです。 各遷移は、ソートされた配列とポインターを使用して対数時間で処理することも、明示的なグリッドの走査を回避する 2 次元スイープを使用してより明確に処理することもできます。 

私たちは問題を、行ごとに、不良セルの最大の列プレフィックスを列に対して対称的に追跡することに帰着します。 コンポーネントは、これらの単調な境界によって形成される最大の一貫した領域に対応します。

 | 境界/スイープ |$O(n \log n + m \log m)$|$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ソートされた行と列の寄与を使用してグリッドを暗黙的に処理します。 

1. 配列のソート$b$そしてインデックスを追跡します。 これにより、各行の不良領域を、ソートされた列の順序で連続するプレフィックスとして扱うことができます。 このステップでは、列の次元をモノトーン構造に変換します。 
2. 各行について$i$、最大のインデックスを計算します$p_i$そのような$a_i + b[p_i] \le x$。 これは、その行内の不良列の間隔を定義します。 そのようなインデックスが存在しない場合、その行には不良セルはありません。 
3. 同様に、各列について$j$、最大のインデックスを計算します$q_j$そのような$a[q_j] + b_j \le x$、列ごとに不良行を定義します。 これら 2 つの方向のビューは、同じ不良セルのセットを異なる視点からエンコードします。 
4. これらの行と列の間隔によって生じるすべての最大の長方形状の領域を間隔のグラフとして扱います。 ここで、アクティブな列間隔を維持しながら、行を順番にスキャンします。 行間隔の開始または終了が前の行と異なる場合は常に、新しいコンポーネント境界が表示されることがあります。 
5. 列を上から下にスイープします。 不良列の現在アクティブなセットをセグメントとして維持します$[0, p_i]$。 いつでも$p_i$と比較した変化$p_{i-1}$、コンポーネント間の潜在的な分離を検出します。 
6. 不良セグメントがこれまでに見られなかった切断された列ブロックを導入する行を検出するたびに、新しいコンポーネントをカウントします。 これは、行間隔が前の行の間隔に垂直に接続されていない領域で始まるときに発生します。 

### なぜ効果があるのか

 不良セルの構造は両方向とも単調であり、右に行くほど増加します。$b_j$、下に行くほど増加します$a_i$したがって、セルが正常であれば、そこからのすべても正常になります。 この単調性により、不良セルと良好なセルの間の境界が階段状になることが保証されます。 

各行の不良領域はソートされた列順序のプレフィックスであり、各列の不良領域はソートされた行順序のプレフィックスであるため、連結コンポーネントを任意に分割することはできません。 これらのプレフィックスが変更されるポイントでのみ開始またはマージできます。 行のスイープでは、そのようなすべての変更が 1 回だけキャプチャされるため、すべてのコンポーネントは 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, x = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    b_sorted = sorted(b)

    # for each row, compute maximal prefix in b_sorted
    p = []
    j = 0
    for ai in a:
        while j < m and ai + b_sorted[j] <= x:
            j += 1
        p.append(j)

    # now we sweep rows and count segments
    ans = 0
    prev = 0

    i = 0
    while i < n:
        if p[i] == 0:
            i += 1
            continue

        # start of a new component
        ans += 1
        cur = p[i]

        # consume all rows connected to this component
        i += 1
        while i < n and p[i] > 0:
            cur = max(cur, p[i])
            i += 1

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、ソートによって列構造を圧縮します。$b$。 各行について、不正なプレフィックスがソートされた順序でどこまで広がっているかを調べます。 2 ポイント スキャンは、両方の理由により機能します。$a_i$そして$b_j$ソートされると単調になるため、プレフィックス境界は一方向にのみ移動します。 

行に対する外側のループは、正常な行を完全にスキップします。これは、正常な行は不正なコンポーネントに属することができないためです。 不正な行が見つかると、新しいコンポーネントが開始され、列カバレッジ内で重複する連続する行を拡張します。 これにより、個々のセルに触れることなく接続がシミュレートされます。 

微妙な点は、2 ポインタのポインタが上にあることです。$b$行ごとにリセットしてはなりません。 それは単調性に依存します$a_i$分別するか、慎重に扱った後にのみ使用してください。 単調な動作を維持する方法で行が処理されない場合、この最適化は失敗します。

 ## 特殊なケース

 重大なエッジケースは、不良セルがない場合です。 アルゴリズムでは、コンポーネント数が時期尚早に初期化されることを回避する必要があります。 この状況では、計算されたすべてのプレフィックスはゼロであるため、スイープによってコンポーネントが開始されることはなく、答えはゼロのままです。 

もう 1 つのエッジ ケースは、1 行に不良セルが含まれている場合です。 アルゴリズムは単一のコンポーネントを正しく作成し、他のすべての行は不良ではないとしてスキップされるため、それを垂直方向にマージすることはありません。 

最後のエッジ ケースは、行と列のしきい値が交互に配置され、複数の切断された四角形が生成される場合です。 モノトーンのプレフィックス表現により、新しい行が前のアクティブ領域と重ならない列プレフィックスを導入したときに各四角形が開始されるため、それぞれが 1 回だけカウントされます。
