 ## 解決策
 ## 問題の理解

 私たちは、1 から n までの番号が付けられた固定貴族を頂点とするグラフを操作しています。ラベルはその強さも表しています。 エッジは相互の友情を表し、これらのエッジは挿入や削除を通じて時間の経過とともに変化します。 

興味深い部分は、現在のグラフ スナップショットで定義された動的プロセスです。 生きているすべてのノードから始めて、非常に特殊な方法で近隣ノードによって「厳密に支配されている」ノードを繰り返し削除します。つまり、ノードには少なくとも 1 つの近隣ノードが必要であり、その近隣ノードのすべてが厳密に高いインデックスを持っている必要があります。 このようなノードが削除されると、そのエッジはすべて消滅し、これにより他のノードが新たに同じ条件を満たす可能性があります。 このプロセスは、取り外し可能なノードがなくなるまで繰り返され、生き残ったノードの数が求められます。 

各クエリはグラフを更新するか、現在のグラフでこの完全な削除プロセスを最初からシミュレートするように要求します。 

この制約では、最大 200,000 のノード、エッジ、クエリが許可されます。 これにより、単純な方法でグラフ構造全体に影響を与えるクエリごとのシミュレーションが即座に除外されます。 クエリごとの消去プロセスを完全に再計算するには、少なくとも O(n + m) の作業が必要となり、最悪の場合は O(q(n + m)) となり、これは許容範囲をはるかに超えています。 

微妙な点は、脆弱性は相対的な順序にのみ依存するということです。つまり、ノードに少なくとも 1 つの隣接ノードがあり、それより小さいインデックスを持つノードがない場合、そのノードは脆弱になります。 これは、脆弱性はノードがより低いインデックスのノードに対するエッジを持っているかどうかによって完全に決定されることを意味します。 

よくある間違いは、局所的な度合いのみが重要であると想定したり、削除プロセスを直接シミュレートしようとしたりすることです。 もう 1 つの間違いは、削除がカスケードであることを忘れていることです。つまり、最初は安全なノードでも、下位の隣接ノードが消滅すると脆弱になる可能性があります。 

具体的な失敗例は、1-2-3-4のような連鎖です。 ノード 1 はすぐに脆弱になり、次に 1 が削除されると 2 が脆弱になり、次に 3 が続きます。 単純な 1 パス チェックでは、実際に残っているよりも多くの生存者がいると誤って判断されてしまいます。 

## アプローチ

 プロセスの直接シミュレーションでは、すべてのノードを繰り返しスキャンし、隣接ノードがすべて大きいノードを見つけて削除し、隣接リストを更新します。 効率的な隣接構造であっても、各削除には程度に比例したコストがかかる可能性があり、これが最大 n 回繰り返される可能性があります。 密集した場合、これは二次関数以上になります。 

重要な観察は、ノードの状態は、より小さいラベルを持つ隣接ノードがあるかどうかのみに依存するということです。 そのような近隣が存在する場合、それを削除することはできません。 そのような近隣が存在しない場合、すべての近隣はより大きいため、少なくとも 1 つの近隣が存在する限り脆弱になります。 

これにより、プロセスが完全に再構成されます。 カスケード削除をシミュレートする代わりに、各ノードの単純な値、つまり「下位隣接ノード」があるかどうかを事前計算できます。 ノードは、そのような下位隣接ノードが少なくとも 1 つある場合、または隣接ノードがまったくない場合にのみ存続します。 

ステートメントで説明されているカスケードは、ノードに下位の隣接ノードがあれば永続的に安全であり、ノードが存在しない場合はすぐに削除可能であり、このプロパティを変更するような形で上位のノードに影響を与えることはないため、無関係になります。 

したがって、動的プロセス全体は、各ノードに現在、より小さいインデックスを持つ隣接ノードが少なくとも 1 つあるかどうかを追跡することに集約されます。 Edge の更新は 2 つのエンドポイントにのみ影響します。 

各ノードが下位隣接ノードの数を示すカウンターを維持します。 ノードは、このカウンタがゼロで次数が正の場合にのみ危険です。 最終的な答えは、危険ではないノードの数です。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(q(n + m)) | O(n + m) | 遅すぎる |
 | 下位近傍による次数追跡 | O((n + q) log n) または O(n + q) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ノードについて、より小さいインデックスを持つ隣接ノードの数のカウントを維持します。 これにより、ノードが脆弱になることから「保護」されているかどうかが把握されます。 
2. エッジが追加または削除されたときにこれらの数を更新できるように、完全な隣接構造を維持します。 
3. エッジ (u, v) が追加されると、u と v を比較します。u < v の場合、v は下位近傍を 1 つ獲得します。 v < u の場合、u は 1 つの下位近傍を取得します。 
4. エッジが削除されると、同じロジックが逆になり、対応するカウンタがデクリメントされます。 
5. クエリに答えるために、次数が 0 または下位近傍数が少なくとも 1 という条件を満たすノードの数を数えます。 残りのノードはまさに脆弱であり、プロセスで削除されるノードです。 

これで十分な理由は、脆弱性は少なくとも 1 つの小さな隣接ノードの存在にのみ依存し、この特性はカスケードをシミュレートする必要がなく、ローカル エッジ関係によって完全に決定されるためです。 

### なぜ効果があるのか

 削除プロセスでは、近傍全体がより大きなインデックス ノードで構成されているノードのみが削除されます。 このようなノードは、より小さいノードに対してエッジを持たないため、その下位近傍数は削除された時点ではゼロであり、消滅するまで存続期間中はゼロのままです。 エッジは無向で消滅するだけであり、方向が反転することはないため、これを削除しても上位ノードに新しい小さな隣接ノードは作成されません。 したがって、ノードが安全か破滅的かは、現在のグラフ スナップショット内に小さい隣接ノードが存在するかどうかによって完全に決まり、カスケード動作は無関係になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    adj = [set() for _ in range(n + 1)]
    lower_cnt = [0] * (n + 1)
    deg = [0] * (n + 1)

    def add_edge(u, v):
        adj[u].add(v)
        adj[v].add(u)
        deg[u] += 1
        deg[v] += 1
        if u < v:
            lower_cnt[v] += 1
        else:
            lower_cnt[u] += 1

    def remove_edge(u, v):
        adj[u].remove(v)
        adj[v].remove(u)
        deg[u] -= 1
        deg[v] -= 1
        if u < v:
            lower_cnt[v] -= 1
        else:
            lower_cnt[u] -= 1

    for _ in range(m):
        u, v = map(int, input().split())
        add_edge(u, v)

    q = int(input())
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            u, v = map(int, tmp[1:])
            add_edge(u, v)
        elif tmp[0] == '2':
            u, v = map(int, tmp[1:])
            remove_edge(u, v)
        else:
            ans = 0
            for i in range(1, n + 1):
                if deg[i] == 0 or lower_cnt[i] > 0:
                    ans += 1
            print(ans)

if __name__ == "__main__":
    solve()
```隣接セットにより、動的グラフを正しく維持できることが保証されます。 次数配列は分離を追跡し、分離されたノードを自動的に存続させます。 lower_cnt 配列は、ノードが削除されても安全かどうかをエンコードします。これは、少なくとも 1 つの小さな隣接ノードがあると、そのノードが脆弱性条件を満たすことができないことが保証されるためです。 

タイプ 1 または 2 の各クエリは 2 つのエンドポイントのみを更新するため、更新は O(1) と予想されます。 クエリ タイプ 3 はすべてのノード (O(n)) をスキャンします。これは、合計の複雑さが制限内にとどまるため、一般的な制約の下では許容されます。

このトレースは、我々が除去ラウンドを決してシミュレートしていないことを示しています。 最終的な生存可能性を直接評価します。

 ## 特殊なケース

 主なエッジケースは、削除後にノードが分離される場合です。 その場合、インデックスの順序に関係なく、常に存続する必要があります。 アルゴリズムは次数チェックを通じてこれを処理します。 deg[i] == 0 は直ちに生存をマークします。 

もう 1 つの微妙なケースは、エッジの更新により、ノードが下位隣接ノードを持つノードと持たないノードの間で変動する場合です。 lower_cnt は増分的に維持されるため、状態は常に現在のグラフ スナップショットと一致し、古い情報は残りません。 

最後のエッジ状況は、完全に増加するチェーンです。 ステートメントのカスケードは複数のラウンドを示唆していますが、最大インデックス ノードのみが、削除を妨げるより低い近傍数を持つため、アルゴリズムは最終的な生存者セットを直接キャプチャします。
