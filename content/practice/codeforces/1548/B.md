 ## 解決策
 ## 問題の理解

 個別の正の整数のリストが与えられ、すべての要素が 2 以上の整数を法として一致する最大の連続部分配列を特定したいと考えています。もっと簡単に言うと、配列上でウィンドウをスライドさせることを想像してください。 そのウィンドウ内には番号が存在する必要があります$m \ge 2$ウィンドウ内のすべての数値を次の値で割ったときに同じ余りが残るようにする$m$。 目標は、各テスト ケースの「フレンド グループ」と呼ばれるそのようなウィンドウの最大サイズを報告することです。 

制約は、ソリューションを設計するために非常に重要です。 各配列には最大 200,000 個の要素を含めることができ、数値自体は最大 200,000 個まで大きくすることができます。$10^{18}$。 すべてのテスト ケースにわたるすべての要素の合計は 200,000 に制限されているため、テスト ケースごとの線形解は実現可能であることがわかりますが、二次関数はすべて$n$遅すぎるでしょう。 可能なすべての部分配列に対して可能なすべての係数を直接試すには、最大で値を反復処理する必要があります。$10^{18}$、それは不可能です。 可能な限り総当たり的な探索を回避するソリューションが必要です$m$。 

明らかでないエッジ ケースには、数値が 2 つだけ含まれる配列、数値が連続する整数である配列、数値間の差がすべて素数または非常に大きい配列などが含まれます。 たとえば、入力`[2, 4]`どちらの数値も 2 で割り切れるため、2 を返す必要があります。法が常に最小の数値であると仮定したり、連続した差分のみをチェックしたりする不注意なアプローチでは、誤った処理が行われる可能性があります。`[3, 7, 11]`ここで、正しい係数は 4 で、サイズ 3 のフレンド グループが生成されます。 

## アプローチ

 ブルートフォースアプローチでは、すべての連続するサブ配列とすべての可能な配列をチェックしようとします。$m$2 からその部分配列内の最小の要素まで。 各部分配列について、すべての要素が合同モジュロであることを検証します。$m$。 この方法は正しいですが、実用的ではありません。$n$まで$2 \cdot 10^5$、部分配列の数は$O(n^2)$、各サブ配列を複数のモジュライに対してチェックするには、最大で 3 時間かかる場合があります。$O(n^3)$最悪の場合。 

重要な洞察は、係数は部分配列内の連続する数値の差を除算するだけでよいということです。 部分配列内のすべての数値が合同モジュロである場合$m$、 それから$m$すべてのペアごとの差を除算します。 したがって、連続する差分の最大公約数 (GCD) を計算するだけで十分です。 これにより、問題は、連続する差分が少なくとも 2 の共通 GCD を共有する最長の連続セグメントの検索に変換されます。 

配列を差分配列に変換し、少なくとも 2 の GCD でセグメントを追跡することにより、複雑さが大幅に軽減されます。 配列を 1 回反復して GCD を更新し、GCD が 2 を下回ったときにセグメントをリセットするだけで済みます。このアプローチは、当然のことながら、各テスト ケースの要素数に関して線形時間のソリューションに役立ちます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 最適 | O(n log(max(a))) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず、テスト ケースの数を読み取ります。 テスト ケースごとに、整数の配列を読み取ります。 配列値は非常に大きくなる可能性があるため、値自体に応じてスケーリングする操作を避ける必要があります。 
2. 差分配列を構築する`diff`そのような`diff[i] = abs(a[i+1] - a[i])`連続するすべてのペアに対して。 これにより、差分の GCD が少なくとも 2 であるセグメントを見つける問題が軽減されます。 
3. 現在の GCD セグメントと見つかった最大セグメント長を追跡するために変数を初期化します。 セグメントの開始インデックスも追跡します。 
4. 差分配列を反復処理します。 各ステップで、新しい差分を使用して現在のセグメントの GCD を計算します。 GCD が 2 を下回った場合は、現在の差から新しいセグメントを開始します。 それ以外の場合は、セグメントを拡張します。 
5. 各反復後に最大長を更新します。 差分配列の各セグメントは、元の配列の 1 要素長いセグメントに対応するため、最大値を更新するときに差分セグメントの長さに 1 を加えます。 
6. すべての差異を処理した後、最大長は最大の友人グループに対応します。 この値をテスト ケースごとに印刷または保存します。 

なぜ機能するのか: 友人グループ内のすべての数値が、ある剰余を剰余として共有するという性質$m \ge 2$直訳すると$m$すべての連続する差を除算します。 連続した差分の GCD を維持することで、共通の係数が存在するセグメントのみを考慮することが保証され、GCD が 2 を下回ったときに再起動することで、セグメントの不変性が維持されることが保証されます。 

## Python ソリューション```python
import sys
from math import gcd
input = sys.stdin.readline

def largest_friend_group(arr):
    n = len(arr)
    if n == 1:
        return 1
    diffs = [abs(arr[i+1] - arr[i]) for i in range(n-1)]
    max_len = 1
    current_gcd = diffs[0]
    start = 0
    for i in range(len(diffs)):
        if i > 0:
            current_gcd = gcd(current_gcd, diffs[i])
        if current_gcd == 1:
            current_gcd = diffs[i]
            start = i
        max_len = max(max_len, i - start + 2)
    return max_len

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(largest_friend_group(a))
```解決策は、入力を効率的に読み取ることから始まります。 差分配列は、問題をモジュラス検査から GCD 検査に変換します。 反復中に現在の GCD が更新され、2 を下回るとセグメントが再起動されます。 最大長は、元の配列の長さを考慮して、差分のセグメントの長さに 1 を加えたものとして計算されます。 単一要素配列のエッジ ケースは明示的に処理されます。 

## 実用的な例

 サンプル入力`[1, 5, 2, 4, 6]`違いを生み出す`[4, 3, 2, 2]`。 繰り返して GCD を追跡します。 

| 私 | 差分[i] | 現在の_gcd | 開始 | 最大長 |
 | --- | --- | --- | --- | --- |
 | 0 | 4 | 4 | 0 | 2 |
 | 1 | 3 | 1 | 1 | 2 |
 | 2 | 2 | 2 | 2 | 3 |
 | 3 | 2 | 2 | 2 | 3 |

 友達グループの最大長は 3 で、これは次のとおりです。`[2, 4, 6]`。 

サンプル入力`[8, 2, 5, 10]`違いを生み出す`[6, 3, 5]`:

 | 私 | 差分[i] | 現在の_gcd | 開始 | 最大長 |
 | --- | --- | --- | --- | --- |
 | 0 | 6 | 6 | 0 | 2 |
 | 1 | 3 | 3 | 0 | 3 |
 | 2 | 5 | 1 | 2 | 3 |

 最大のセグメント長は 3 で、これは一致します。`[8, 2, 5]`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())

        a = list(map(int, input().split()))
        output.append(str(largest_friend_group(a)))
    return "\n".join(output)
