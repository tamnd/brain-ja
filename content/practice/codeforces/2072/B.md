 ## 解決策
 ## 問題の理解

 ダッシュとアンダースコアの 2 つの記号のみで構成される文字列が与えられます。 この文字列は任意に並べ替えることができます。 順序を固定した後、文字列はパターン「-_-」に等しいサブシーケンスの数として定義された値を表します。これは、これらの位置の文字がこの順序でダッシュ、アンダースコア、ダッシュとなるように 3 つのインデックス i < j < k を選択することを意味します。 

タスクは、そのようなトリプルの数が最大になるように文字を並べ替えることです。 

入力により、複数の独立したテスト ケースが得られます。 再配置は完全に許可されているため、それぞれについて、元の順序ではなく文字数のみを考慮します。 

すべてのテスト ケースの全長が最大 2·10^5 であるという制約は、テスト ケースごとに最悪でも O(n) または O(n log n) の解が必要であることを意味します。 単一の文字列に対する二次関数はすでに遅すぎます。 

配置についてローカルに考えると、微妙な失敗例が現れます。 単純な考えとしては、文字列を左から右に貪欲に構築し、直接的な影響を最大化するように文字を配置するというものがあるかもしれません。 ダッシュの寄与は、ローカルの隣接関係ではなく、ダッシュ間のアンダースコアのグローバルな分布に依存するため、これは失敗します。 

もう 1 つの特殊なケースは、文字列にダッシュが 2 つ未満であるか、アンダースコアがない場合です。 たとえば、ダッシュが 1 つしかない場合、配置に関係なく「-_-」の部分シーケンスは存在できないため、答えはゼロでなければなりません。 3 つの文字タイプがすべて存在すると仮定する単純な組み合わせ式では、誤って正の値が生成されてしまいます。 

## アプローチ

 ブルートフォース手法では、文字列のすべての順列を試し、各配列内の「-_-」サブシーケンスの数を数えます。 長さ n の文字列の場合、これは n! 順列ごとに O(n^2) または O(n^3) の部分列を数えると、n = 10 の場合でも完全に実行不可能になります。 

重要な点は、ダッシュとアンダースコアの数のみが重要であり、最適な配置ではすべての同一文字が連続したブロックに配置されるということです。 順列を修正すると、サブシーケンス「-_-」の数は、各アンダースコアの前後に現れるダッシュの数のみに依存します。 

アンダースコアの場合、その前に L ダッシュがあり、その後に R ダッシュがある場合、L · R サブシーケンスに寄与します。 すべてのアンダースコアを合計すると合計値が得られます。 

すべてのアンダースコアの左側に x ダッシュを配置し、残りの d − x ダッシュを右側に配置すると、すべてのアンダースコアが x(d − x) に寄与します。 アンダースコアが u 個ある場合、合計は u · x(d − x) となります。 問題は、この二次式を最大化するために x を選択することに帰着します。 

式 x(d − x) は、x が d/2 にできるだけ近いときに最大化されるため、最適な分割は、すべてのアンダースコアの両側にダッシュを均等に分散することです。 すべてのアンダースコアを中央にまとめて配置する必要があります。アンダースコアを複数のブロックに混在させると、製品の構造が低下するだけであるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n^2) | O(n) | 遅すぎる |
 | 最適 | テストごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列内のダッシュ d とアンダースコア u の数を数えます。 配置はこれらのカウントのみに依存し、元の順序には依存しません。 
2. d < 2 または u = 0 の場合、0 を返します。ダッシュが 2 つ未満の場合は、有効なパターン「-_-」を形成できません。 
3. すべてのアンダースコアの左側と右側にダッシュが何個入るかを計算します。 x(d − x) を最大化するには、一方の側に x = d // 2 を設定し、もう一方の側に d − x を設定します。 
4. サブシーケンスの総数を u · x · (d − x) として計算します。 
5. この値を出力します。

機能する理由: 単一のブロックにアンダースコアを配置すると、各アンダースコアの左右に同じ数のダッシュが表示されます。 アンダースコアを別の領域に移動するような偏差があると、対称性が低下し、乗算の寄与の少なくとも 1 つが減少します。 最適な構造は、アンダースコアの中央ブロックの周囲でダッシュを 2 つのグループに分割することによって完全に決定され、すべてのアンダースコアの積が同時に最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        d = s.count('-')
        u = n - d

        if d < 2 or u == 0:
            print(0)
            continue

        left = d // 2
        right = d - left
        print(u * left * right)

if __name__ == "__main__":
    solve()
```この解決策により、問題は文字数のカウントのみに減ります。 ダッシュの 2 つの半分への分割は、整数除算を使用して計算されます。これは、余分なダッシュを片側に配置することで奇数のカウントを自然に処理します。 

主な微妙な点は、配置構造が常に「ブロック」内で最適であり、インターリーブなしでは貢献の積の形式を改善できないことを認識していることです。 

## 実用的な例

 サンプルセットから 2 つのケースを追跡します。 

最初のケース:`--_`d = 2、u = 1

 | ステップ | ダッシュ (d) | アンダースコア (u) | 左 | 右 | 結果 |

 これにより、ダッシュ 2 つとアンダースコア 1 つを使用した場合、最適な配置は「-_-」であることがわかります。 

2番目のケース:`__-__`d = 1、u = 4

 d < 2 であるため、すぐに 0 を返します。アンダースコアの両側にダッシュを付けることはできないため、有効なサブシーケンスは存在しません。 

これら 2 つのケースは、サンドイッチ構造を形成するのに十分なダッシュがあるか、不可能であるかの 2 つの状況を示しています。

 ## 特殊なケース

 ダッシュが 2 つ未満の場合、アルゴリズムはすぐに 0 を返します。 たとえば、入力`_-`は d = 1、u = 1 を与え、条件 d < 2 は直接ゼロ出力をトリガーします。 どのような配置であっても、アンダースコアの少なくとも片側が空のままであるため、有効なトリプルを形成することはできません。 

アンダースコアがない場合、次のようになります。`-----`、ゼロも返します。 ダッシュを分割することはできますが、数式では u (ゼロ) が乗算され、「-_-」サブシーケンスが存在しないという事実と一致します。 

ダッシュが奇数の場合、たとえば d = 5 の場合、分割は 2 と 3 になります。これは、すべてのアンダースコアを中央に配置し、ダッシュをできるだけ均等に分散することに対応します。 u = 1 の場合、結果は 1 · 2 · 3 = 6 となり、1 と 4 のような不均等な分割では 4 のみが生成され、フロア分割の分割が最適であることが確認されます。
