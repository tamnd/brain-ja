 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、単一の操作を実行するように求められます。それは、連続した部分配列を選択し、それを左に 1 つ循環的にシフトすることです。 この操作の後、配列内の反転の総数をできるだけ少なくする必要があります。 反転はインデックスのペアです`(i, j)`と`i < j`最初の要素が 2 番目の要素よりも大きくなるようにします。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、配列と配列自体の長さが示されます。 出力はインデックスのペアです`(l, r)`シフトするサブ配列を示します。 最適な選択肢が複数ある場合は、どれを選択しても問題ありません。 

制約により、次のことがわかります。`n^2`すべてのテスト ケースで最大でも`4 * 10^6`。 これは、`O(n^2)`テストケースごとのソリューションは実現可能です。 とすれば`n`最大 2000、アルゴリズムは 2000 より遅い`O(n^2)`テストケースごとに実行するのは非現実的です。 

エッジ ケースには、すでに並べ替えられている配列、すべての要素が等しい配列、少数の要素だけが順序が狂っている配列が含まれます。 たとえば、`[1, 2, 3]`、どのようなシフトでも反転が増加するため、正しい答えは次のような些細なシフトである可能性があります。`(1, 1)`それは事実上何もしません。 のために`[3, 1, 2]`、最適なシフトでは、反転を減らすためにプレフィックスを回転する必要があります。 固定シフト サイズを仮定したり、隣接する要素を無視したりする不注意なアプローチでは、最適ではないセグメントが選択される可能性があります。 

## アプローチ

 ブルートフォース手法はシンプルです。すべての可能なペアを反復処理します。`(l, r)`と`1 ≤ l ≤ r ≤ n`、巡回シフトを適用し、結果の配列内の反転の数を数え、最も少ない反転を生成するペアを追跡します。 シフトされた配列ごとに反転をカウントすると、単純にコストがかかります`O(n^2)`、そして、あります`O(n^2)`シフトの可能性があり、その結果、`O(n^4)`テストケースごとに。 これは明らかに遅すぎます`n`2000年まで。 

重要な観察は、この問題には 1 つの循環シフトのみが必要であるということです。`a[l]`位置を決める`r`そして残りを左にスライドさせます。 反転に対する影響は局所的です。反転には外部の要素が関与します。`[l, r]`ほとんど変わらないままです。 したがって、毎回合計反転を計算する代わりに、各シフトが要素にどのような影響を与えるかを追跡できます。`[l, r]`配列の残りの部分に関して。 

配列のサイズが適度であるという事実により、さらに単純化されます。 すべてのサブ配列をチェックする余裕があります`[l, r]`シフト後の反転数を直接計算します`a[l]`位置を決める`r`を使用して`O(n)`サブアレイごとにスイープします。 これにより、全体的な複雑さは次のようになります。`O(n^2)`テスト ケースごとに、次の制約内に収まります。`∑ n^2 ≤ 4 * 10^6`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォースの完全反転カウント | O(n^4) | O(n) | 遅すぎる |
 | 最適化されたサブアレイスイープ | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、長さの配列を読み取ります。`n`。 
2. 変数を初期化して最適なペアを追跡する`(best_l, best_r)`観察された最小の反転。最初は元の配列内の反転に設定されます。 
3. 可能なすべてのサブ配列開始インデックスを反復処理します。`l`1から`n`。 
4. それぞれについて`l`、繰り返します`r`から`l`に`n`。 
5. シフトの効果をシミュレートする`a[l]`位置を決める`r`:

 - 関係する反転を数える`a[l]`位置に要素がある`[l+1, r]`(これらは減少します。`a[l]`彼らの後に移動します）。 
- 関係する反転を数える`a[l]`外側の要素を含む`[l, r]`(これらは相対値に応じて増減する可能性があります)。 
6. 最小反転数と記録を更新する`(l, r)`この部分配列が生成する反転が少ない場合。 
7. すべてのサブ配列をチェックした後、ペアを出力します。`(best_l, best_r)`。 

機能する理由: 各巡回シフトは独立して評価でき、配列が十分に小さいため、すべての部分配列を評価することでグローバル最小値が見つかることが保証されます。 を含む反転への影響のみを追跡する`a[l]`これにより、シフトの影響を受けない配列部分に対する冗長な計算が確実に回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_inversions(arr):
    n = len(arr)
    inv = 0
    for i in range(n):
        for j in range(i+1, n):
            if arr[i] > arr[j]:
                inv += 1
    return inv

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        min_inv = count_inversions(a)
        best_l, best_r = 1, 1
        
        for l in range(n):
            for r in range(l, n):
                # simulate left cyclic shift on a[l:r+1]
                b = a[:l] + a[l+1:r+1] + [a[l]] + a[r+1:]
                inv = count_inversions(b)
                if inv < min_inv:
                    min_inv = inv
                    best_l, best_r = l+1, r+1  # 1-indexed output
        print(best_l, best_r)

if __name__ == "__main__":
    solve()
```解決策はヘルパー関数を定義することから始まります。`count_inversions`小さな配列の場合。 メインループはテストケースの数を読み取り、それらを繰り返します。 サブ配列ごとに`[l, r]`、巡回シフト後に新しい配列を構築し、反転をカウントします。 印刷時に、0 ベースのインデックスを 1 ベースのインデックスに変換するように注意が必要です。 この単純なシミュレーションは制約内で機能します。`n ≤ 2000`そして`∑ n^2 ≤ 4 * 10^6`。

 | 測定 | 複雑さ | 説明 |
