 ## 解決策
 ## 問題の理解

 次の配列から始めます`n`ゼロ。 1 回の操作で、任意の位置を選択し、範囲内の任意の整数で上書きできます。`[-p, p]`。 このような上書きを何回か実行した後、配列の合計が正確になるようにしたいと考えています。`k`、できるだけ少ない手でこれを実行したいと考えています。 各移動は 1 つの位置にのみ影響し、その位置の前の値を完全に置き換えます。 

したがって、実際の決定は位置ではなく、最大でどれだけの合計を配列に「注入」できるかによって決まります。`n`それぞれの割り当てが、間の値に寄与します。`-p`そして`p`。 

制約は小さいです。`n ≤ 50`、`|k| ≤ 2500`、 そして`p ≤ 50`。 これは、直接的な事例分析や貪欲な公式でも十分であることを意味します。 州に対するDPのようなものは不要であり、ポジションごとの割り当ての可能性を強引に決めることさえ、理論的には十分に制限されますが、実際にはやりすぎです。 

よくある失敗例は、同じインデックスを複数回上書きできることを忘れていることです。 インデックスごとに重要なのは最終値のみであるため、重要なのはインデックスをどれだけ頻繁に操作するかではなく、使用するインデックスの数です。 

もう一つの微妙なケースは次のような場合です。`k = 0`。 配列の合計は既にゼロになるため、正しい答えは常にゼロ演算です。`p`。 

## アプローチ

 ブルートフォースのアイデアでは、値を割り当てるあらゆる方法を試行します。`n`位置を決めて、どの組み合わせの合計が以下になるかを確認します`k`。 各ポジションには次のような特徴があるため、これはすぐに爆発します。`2p + 1`選択肢、それにつながる`(2p + 1)^n`可能性は、たとえ`n = 50`。 

重要な観察は、各操作が独立して合計に寄与しているということです。 後`x`作戦において、私たちができる最善のことは、`x * p`、各割り当てが貢献できるのは最大でも`p`または`-p`。 したがって、正確に後の到達可能な合計は`x`操作は間隔を形成します`[-x p, x p]`。 まさに欲しいので`k`、唯一の問題は、`k`その範囲内にあるもの、そしてそのような最小のものは何ですか`x`は。 

これにより、問題は最小値を見つけるだけになります。`x`そのような`x * p ≥ |k|`を確保しながら、`x ≤ n`私たちにはそれしかないから`n`変更する位置。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`、`k`、 そして`p`。 私たちが気にするのは絶対値だけです`k`なぜなら、負の代入を対称的に使用できるからです。 
2. もし`k`ゼロの場合は戻ります`0`操作は必要なく、初期配列がすでに条件を満たしているため、すぐに実行されます。 
3. コンピューティング`need = |k|`。 これは、演算を使用して構築する必要がある合計の大きさを表します。 
4. 各操作は最大でも貢献します`p`合計の大きさに。 したがって、必要な操作の最小数は次のようになります。`ceil(need / p)`。 
5. この数値が次の値より大きい場合`n`とすると、すべての要素を 1 回変更しても、必要な合計に達するのに十分ではないため、答えは次のようになります。`-1`。 
6. それ以外の場合は、計算された値を出力します。 

機能する理由: 各操作は独立して合計に寄与し、最大で正または負の値を自由に割り当てることができます。`p`。 唯一の制限要因は合計容量であり、操作数は線形です。 容量が許す限り、必要な合計に正確に一致する値を常に選択できるため、上限は必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, p = map(int, input().split())

        if k == 0:
            print(0)
            continue

        need = abs(k)

        # minimum operations needed if each contributes at most p
        ops = (need + p - 1) // p

        if ops > n:
            print(-1)
        else:
            print(ops)

if __name__ == "__main__":
    solve()
```実装は、派生した境界に直接従います。 天井分割`(need + p - 1) // p`浮動小数点演算を回避し、すべての整数の場合の正確性を保証します。 小切手`ops > n`以上のことは実行できないという制約が課せられます。`n`独立した割り当て。

## テストケース```python
import sys, io

def solve_io(data):
    sys.stdin = io.StringIO(data)
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, k, p = map(int, input().split())
        if k == 0:
            out.append("0")
            continue
        need = abs(k)
        ops = (need + p - 1) // p
        out.append(str(ops if ops <= n else -1))
    return "\n".join(out)

# provided samples

assert solve_io("1\n5 1 10\n") == "1"
assert solve_io("1\n5 100 1\n") == "-1"
assert solve_io("2\n10 -25 5\n3 9 2\n") == "5\n-1"

 ## 特殊なケース

 いつ`k = 0`の場合、アルゴリズムは考慮せずにすぐにゼロを返します。`p`変更する必要がないためです。 いつ`p`に比べて大きい`k`の場合、単一の代入で合計全体が吸収される可能性があるため、数式は 1 つの演算にまとめられます。 いつ`p = 1`、操作の数は正確になります。`|k|`、そして実現可能性は純粋に次のとおりであるかどうかに依存します。`|k| ≤ n`。 シーリング除算は、割り切れる大きさと割り切れない大きさの両方を正しく処理するため、これらすべてのケースで 1 による誤差が発生しないようにします。
