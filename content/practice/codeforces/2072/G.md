 ## 問題の理解

 私たちには番号が与えられています`n`そして限界`k`。 あらゆる拠点に`p`から`2`まで`k`、私たちは書きます`n`基地内で`p`、その数字を反転し、反転した数字シーケンスを基数の数値として再度解釈します。`p`、それを 10 進数に変換し直します。 その結果得られる値が累計に加算されます。 タスクは、この和の剰余を計算することです`10^9 + 7`。 

キーオブジェクトは単なる表現ではありません`n`ベースが異なりますが、その表現が逆になったときにどのように動作するか。 一部の基地では、`n`は多くの桁を持ちますが、少数の桁しか持たない場合もあり、ほとんどの大きな基底では非常に短い表現に崩壊します。 この変動性は、ソリューションが活用する必要がある中心的な構造的特徴です。 

制約により、自明ではないアプローチが強制されます。 テストケースの数は最大5000と多く、`k`と同じ大きさにすることができます`10^18`。 すべての塩基にわたる単純なループは直ちに不可能です。 まで繰り返しても`k`考えられない。 唯一有益な観察は、`k`は巨大です、の表現`n`基地内で`p`非常にシンプルになるとき`p`を超える`sqrt(n)`桁数が最大 2 になるためです。この構造の崩壊が問題を解決可能にします。 

よくある隠れた落とし穴は、桁を反転すると常に値が大幅に変わると想定していることです。 これは、表現の長さが少なくとも 3 である場合にのみ当てはまります。ベースが十分に大きくなると、`n`1 桁または 2 桁の場合、反転は簡単になるか、単純な閉じた形式の式が生成されます。 

もう一つの微妙なエッジケースは、`n = 1`。 すべての塩基において、それは 1 桁として表されるため、逆にしても何も起こらず、答えは純粋に範囲内に塩基の数を数えることになります。 

## アプローチ

 ブルート フォース手法は定義に直接に従います。 各拠点ごとに`p`、 変換する`n`基地に`p`、数字を保存し、反転して、反転した数値を評価します。 各変換コスト`O(log_p n)`最大数の数字`O(log n)`。 全体`p`まで`k`、これは約につながります`O(k log n)`テストケースごとの操作。 以来`k`できる`10^18`、このアプローチは不可能です。 

ターニングポイントは、次の桁数を認識することです。`n`基地内で`p`せいぜい`t = floor(log_p n) + 1`。 いつ`p > sqrt(n)`、私たちはいつも持っています`t ≤ 2`。 これにより、問題が 2 つの領域に分割されます。1 つは表現が長くなる可能性のある小さな基底で、もう 1 つは表現が常に 1 桁または 2 桁で代数的に処理できる大規模な基底です。 

大規模基地体制の場合、次のように仮定します。`n = a p + b`と`0 ≤ b < p`。 ベースは――`p`表現は`[a, b]`。 逆にすると`[b, a]`、値に対応します`b p + a`。 置き換える`a = n // p`そして`b = n % p`、反転した値は次のようになります。`(n % p) * p + (n // p)`。 

これにより、桁反転演算が単純な算術式に変換され、区間グループ化を使用して効率的に合計できます。`n // p`そして`n % p`の範囲にわたって一定です`p`。 

小規模基地制度に関しては、`p ≤ sqrt(n)`、塩基の数は最大で約`sqrt(n)`、管理可能です。 このような基数ごとに、変換を直接シミュレートし、桁を逆にして、値を計算します。 

最後の戦略は、両方の部分を組み合わせたものです。小さな基底の直接シミュレーションと、フロア関数構造を使用した大きな基底のグループ化された算術加算です。

 ## アルゴリズムのチュートリアル

 ### 1. 塩基の範囲を分割する

 閾値を選択します`B = floor(sqrt(n)) + 1`。 全拠点`p ≤ B`ダイレクトディジットシミュレーションで処理され、すべて`p > B`は 2 桁の計算式を使用して処理されます。 この分割により、すべての大基数表現が最大 2 桁になることが保証されます。 

これが機能する理由は次のとおりです。`p > sqrt(n)`、 我々は持っています`p^2 > n`、 それで`n`基数に 3 桁以上を含めることはできません`p`。 

### 2. 小規模な塩基の直接計算

 それぞれについて`p`から`2`に`B`、分割を繰り返します`n`による`p`数字を抽出します。 これらの数字を保存し、反転して、反転した数値を基数で再構築します。`p`。 

桁の長さが 2 を超える場合は簡略化できないため、この手順が必要です。 コストは依然として制限されているため、`B`せいぜい約くらいです`sqrt(n)`。 

### 3. 大きな塩基の場合は、反転した値を閉じた形式で表現します

 各拠点ごとに`p > B`、 書く：`n = a p + b`、 どこ`a = n // p`そして`b = n % p`。 

反転後の値は次のようになります。`rev(n, p) = b p + a = (n % p) * p + (n // p)`。 

この恒等式は、桁の反転を除算と剰余のみに依存する算術に変換します。 

### 4. 定数商による塩基のグループ化

 として`p`増加し、`n // p`変更のみ`O(sqrt(n))`回。 範囲を反復処理します。`q = n // p`は一定です。 固定の場合`q`の間隔を求めます。`p`そのような`n // p = q`、つまり`p ∈ [l, r] = [n // (q + 1) + 1, n // q]`。 

このようなセグメント内では、次のように合計できます。`(n % p) * p + q`全体`p`で`[l, r]`。 

拡大中`n % p = n - q p`、次のようになります。`(n - q p) p + q = n p - q p^2 + q`。 

これにより、セグメントの合計が次の多項式の合計に減算されます。`p`そして`p^2`、標準的な公式を使用して計算できます。 

### 5. 結果を安全に蓄積する

 答えのモジュロを維持します`10^9 + 7`すべてのセグメントの計算にモジュラー演算を慎重に適用します。 

### なぜ効果があるのか

 正確さは、すべての塩基を 2 つの素のセットに分割することで得られ、そこでは塩基表現の構造が完全に決定されます。 小規模な基地の場合は、強引な攻撃が正確です。 大きな基数の場合、表現は最大 2 桁であることが保証され、反転が決定論的な代数変換になります。 定数商によるグループ化により、すべての基数が 1 回だけ寄与することが保証され、代数展開により各項の等価性が個別に維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def rev_small(n, p):
    digits = []
    x = n
    while x:
        digits.append(x % p)
        x //= p
    # reverse digits means reading digits in forward order
    res = 0
    for d in digits:
        res = res * p + d
    return res

def range_sum(l, r):
    # sum p and sum p^2 will be needed outside
    return l, r

def solve_case(n, k):
    ans = 0

    B = int(n ** 0.5) + 2
    lim = min(k, B)

    # small bases
    for p in range(2, lim + 1):
        ans += rev_small(n, p)
        ans %= MOD

    if k <= B:
        return ans

    # large bases p > B
    p = B + 1
    while p <= k:
        q = n // p
        r = min(k, n // q if q != 0 else k)
        l = p

        # sum over p in [l, r]:
        # rev = (n % p) * p + q = (n - q*p)*p + q
        # = n*p - q*p^2 + q

        def sum1(a, b):
            return (b * (b + 1) // 2 - (a - 1) * a // 2) % MOD

        def sum2(a, b):
            # sum of squares
            def sq(x):
                return x * (x + 1) * (2 * x + 1) // 6
            return (sq(b) - sq(a - 1)) % MOD

        s1 = sum1(l, r)
        s2 = sum2(l, r)

        cnt = (r - l + 1) % MOD

        seg = (n % MOD) * s1 % MOD
        seg = (seg - (q % MOD) * s2) % MOD
        seg = (seg + (q % MOD) * cnt) % MOD

        ans = (ans + seg) % MOD

        p = r + 1

    return ans

def main():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        print(solve_case(n, k))

if __name__ == "__main__":
    main()
```この実装では、計算が小ベースのループと大ベースのセグメンテーション ループに分割されます。 小さな部分は基数変換を直接シミュレートしますが、範囲が次のように制限されているため安全です。`sqrt(n)`。 

The large part relies on quotient stability of`n // p`。 各セグメントは固定して導出されます`q`そして反転した値を次の二次式に展開します。`p`。 合計の計算には注意が必要です`p`そして`p^2`効率的に; これらは閉じた形式の式で処理されます。 

One subtle implementation detail is handling modulo subtraction in`seg = seg - q * s2`。 Without normalization, intermediate values may become negative, so every subtraction must be corrected modulo`MOD`。

 ## 特殊なケース

 ### ケース: n = 1

 入力`n = 1, k = 10`。 

すべての基本表現は次のとおりです。`1`。 小底ループの合計`1`それぞれに`p`、正確に生産`k - 1`。 大規模ベースのセグメントに到達することはありません。`B ≥ 1`。 

これにより、一様数字表現が正確であることが確認されます。 

### ケース: k が sqrt(n) より小さい

 いつ`k ≤ B`、小さなループのみが実行されます。 例えば`n = 100000, k = 50`。 すべての塩基は直接シミュレートされ、セグメンテーションは使用されません。 このアルゴリズムは、範囲を狭めてブルート フォースにきれいに縮退します。 

### ケース: 大きなベースセグメント

 テイク`n = 20, p = 7`。 表現は`26`、逆は`62`、に等しい`(20 % 7) * 7 + (20 // 7) = 6 * 7 + 2 = 44`、代数的一貫性を確認します。 これは、大規模ベース領域で使用される閉形式変換を検証します。
