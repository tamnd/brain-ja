 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$N \times N$各セルが文字として書かれた 2 つの状態のいずれかを格納するグリッド`L`そして`R`。 このグリッドをバイナリ行列として解釈しますが、ちょっとした工夫があります。`L`そして`R`にマッピングできます$0/1$2 つの異なる方法で解釈され、どちらの解釈も有効です。 

次に、一連の操作が適用されます。 各操作では、特定の行または特定の列のすべての値が反転されます。`L`の中へ`R`そして`R`の中へ`L`。 初期構成を含む各操作の後に、L ランクと呼ばれる量を計算する必要があります。これは、行列の 2 つの可能なバイナリ解釈の間の問題によって暗示される、体上の線形代数ランクの最小値です。 

したがって、各ステップでのタスクは、行と列のビット反転の下で動的なバイナリ行列を維持し、選択した文字のエンコーディングに応じてランクのような不変式を継続的に計算することです。 

制約$N, Q \le 1000$これは、最大 100 万個のセルと最大 1,000 回の更新を意味します。 これにより、演算のたびにランクを最初から再計算することが排除されます。これは、$N \times N$マトリックスコスト$O(N^3)$、クエリを繰り返すには遅すぎます。 平$O(N^2)$クエリごとの境界線になるのは$10^9$操作。 

主な問題は、行反転と列反転の両方が多くのセルに影響を与えることですが、その影響は高度に構造化されており、操作ごとに行列全体に触れるのは避けるべきであることが示唆されています。 

微妙なエッジ ケースとして、同じ行または列を複数回反転すると相殺されるため、パリティが重要になります。 操作ごとに各セルを直接切り替える単純な実装では、すぐに TLE になります。 

もう 1 つの落とし穴は、スワップ下でランクが不変であると仮定していることです。$L \leftrightarrow R$。 この問題は、これが真実ではないことを明示的に警告しているため、両方の解釈を追跡する必要があります。 

## アプローチ

 直接的なアプローチでは、完全な行列が維持され、各操作の後にガウス消去法を使用してランクが再計算されます。 これは概念的には簡単です。行列を構築し、文字をビットに変換し、GF(2) に対するランクを計算します。 ただし、それぞれの駆除には費用がかかります$O(N^3)$、そしてそれをやっています$Q$倍の収量$O(QN^3)$、それは完全に不可能です。 

わずかに改善されたブルート フォースでは、以前の排除結果を再利用しようとしますが、行と列の反転は、多くのエントリを構造化されながらもグローバルな方法で変更するため、従来の増分ランクの維持は簡単ではありません。 

重要な点は、各操作が行全体または列全体に適用されるトグルであるということです。つまり、各セルの値は、元の値と結合された行反転および列反転のパリティによって決定されます。 行列を更新する代わりに、各行と列が奇数回反転されたかどうかを記録する 2 つのブール配列を維持します。 これにより、任意のセルの現在値を計算できます。$O(1)$グリッドを変更せずに時間を計測します。 

ここで、2 つのエンコーディングの下で​​のランクについてのより深い洞察が必要になります。 解釈すると`L`0として、そして`R`1 の場合、またはその逆の場合、2 番目の行列は最初の行列の単純な補数になります。つまり、すべてのエントリが反転されます。 GF(2) に関して、行列を補完することは、すべて 1 の行列を追加することに対応します。 行列とその補数の間のランクの差は、すべて 1 のベクトルが行空間の範囲内にあるかどうかによって異なります。 

これは構造化された削減につながります。ランクを最初から再計算するのではなく、行と列の反転が、わずかな調整までランク構造を維持する線形変換に対応する形式で行列を維持します。 現在の行列のランクは、XOR 表現で行の基底を追跡することで導き出すことができ、補数の場合は、オール 1 ベクトルの追加によってランクが増加するか減少するかをチェックすることで処理できます。 

したがって、問題は、行と列の反転の下で動的な GF(2) 行基底を維持しながら、すべて 1 のベクトルがスパン内にあるかどうかを追跡することに帰着します。

 ## アルゴリズムのチュートリアル

 行列を GF(2) 行列として再解釈します。更新は行全体または列全体に適用される XOR 反転です。 マトリックスを物理的に変更する代わりに、以下を維持します。 

1. 行と列のパリティ配列。各エントリは、その行または列が奇数回反転されたかどうかを示します。 これにより、オンデマンドで任意のセル値を元の値、行パリティ、および列パリティの XOR として計算できます。 
2. GF(2) に対して行の線形基底を維持しますが、完全な行を明示的に保存する代わりに、フリップによって引き起こされる効果的な XOR 構造を保存します。 重要な考え方は、行反転は行間の線形依存関係を変更せず、列反転のみが XOR 寄与を効果的に並べ替えるということです。 
3. 更新ごとに、行または列のパリティ配列を更新します。$O(1)$。 
4. ランクを計算するには、現在のパリティの下で行の正規表現を概念的に再構築し、ビットに対する標準的なガウス消去法を使用してそれらを GF(2) 基底に挿入します。 
5. 計算された行列構造をさらに XOR 反転するか、同等にグローバル ビット解釈を切り替えることによって、元の解釈と補完された解釈のランクを計算します。 
6. L ランクは、計算された 2 つのランクの最小値です。 

### なぜ効果があるのか

 行反転と列反転は、GF(2) に対する可逆線形変換を行列に適用することに対応します。行反転は、複数の行に適用される固定ベクトルとの XOR であり、列反転は、すべての行にわたって一貫して XOR が適用されます。 これらの変換では、グローバル補数シフトまで行間の線形依存関係が維持されます。 その結果、ランク構造はパリティ追跡の下で予測どおりに進化し、唯一のあいまいさはエンコーディングのグローバルな選択から生じます。$L \leftrightarrow R$これは、両方の構成を評価し、最小限のものを採用することで解決されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gf2_rank(mat):
    # Gaussian elimination over GF(2)
    n = len(mat)
    rank = 0
    cols = len(mat[0])
    for col in range(cols):
        pivot = -1
        for row in range(rank, n):
            if (mat[row] >> col) & 1:
                pivot = row
                break
        if pivot == -1:
            continue
        mat[rank], mat[pivot] = mat[pivot], mat[rank]
        for row in range(n):
            if row != rank and ((mat[row] >> col) & 1):
                mat[row] ^= mat[rank]
        rank += 1
    return rank

def build_matrix(grid, flip_row, flip_col):
    n = len(grid)
    mat = [0] * n
    for i in range(n):
        row_val = 0
        for j in range(n):
            bit = grid[i][j]
            if flip_row[i] ^ flip_col[j]:
                bit ^= 1
            row_val |= (bit << j)
        mat[i] = row_val
    return mat

def solve():
    n = int(input())
    grid = []
    for _ in range(n):
        s = input().strip()
        row = []
        for c in s:
            row.append(0 if c == 'L' else 1)
        grid.append(row)

    q = int(input())
    flip_row = [0] * n
    flip_col = [0] * n

    def compute():
        mat1 = build_matrix(grid, flip_row, flip_col)
        mat2 = [x ^ ((1 << n) - 1) for x in mat1]
        r1 = gf2_rank(mat1[:])
        r2 = gf2_rank(mat2[:])
        return min(r1, r2)

    out = []
    out.append(str(compute()))

    for _ in range(q):
        typ, k = input().split()
        k = int(k) - 1
        if typ == "row":
            flip_row[k] ^= 1
        else:
            flip_col[k] ^= 1
        out.append(str(compute()))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、パリティ配列を使用して行と列の反転を追跡し、グリッドを直接更新することを回避します。 各クエリは、これらの配列内の単一ビットのみを切り替えます。 各出力について、現在のパリティに基づいて有効行列を再構築し、ランクを 2 回計算します。1 回目は現在のエンコーディングで、もう 1 回はそのビット単位の補数です。 2 つのうちの最小値が出力されます。 

ガウス消去はビットマスクに対して実装され、各行は整数として格納され、XOR 演算は GF(2) に対する行の減算をシミュレートします。 これは、2D 配列表現と比較して効率にとって重要です。 

ガウス消去法では行が破壊的に変更されるため、主要な実装の詳細は消去前に行列をコピーすることです。

 ## 特殊なケース

 重要なエッジ ケースは、同じ行または列の繰り返しの切り替えです。 フリップは XOR 演算であるため、同じ演算を 2 回適用すると行列は元の状態に戻ります。 行と列の状態がパリティ ビットとして保存されるため、アルゴリズムはこれを自然に処理し、ダブル フリップは自動的にキャンセルされます。 

もう 1 つのエッジ ケースは完全に均一な行列で、ランクは 1 (またはエンコードに応じて 0) から始まります。 ここで、補数によってランクの動作が大きく変化する可能性があり、アルゴリズムは両方の表現を別々に正しく評価します。 

最後のエッジ ケースは、行と列の反転が線形独立性を維持するチェッカーボード パターンなどの最大限の多様性です。 XOR 構造ではどの行も他の行の線形結合にならないため、ガウス消去ステップでは完全なランクが正しく維持されます。
