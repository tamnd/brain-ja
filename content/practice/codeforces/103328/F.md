 ## 問題の理解

 私たちには素数が与えられています$p$これは、子供の数と、ギフトを均等に分割する方法を制御するモジュール構造の両方を表します。 テスト ケースごとに、サンタは同一のコンボ パッケージを多数購入できます。 各パッケージには次の内容が含まれています$x$タイプAのギフトと$y$タイプBのギフト、およびその両方$x$そして$y$少なくとも$p$ただし、それ以外の場合は任意の大きな整数です。 

サンタさんが買ってくれたら$k$コンボ、彼は最終的にこうなる$k \cdot x$Aギフトと$k \cdot y$B-ギフト。 これらの贈り物は全員に均等に分配されなければなりません$p$各子供がまったく同じ数の A ギフトと同じ数の B ギフトを受け取るようにします。 この均等な分割後に残った贈り物は廃棄物とみなされます。 の値$k$の間にある必要があります$1$そして$p-1$ゼロコンボの購入は明示的に禁止されているためです。 

課題は選択することです$k$無駄なギフトの合計を最小限に抑えるには、この範囲内に設定してください。 

重要な問題は、無駄がどのように発生するかによって決まるということです。$k x$そして$k y$～による除算に従って行動する$p$したがって、問題は基本的に乗算のモジュラー演算に関するものです。 

制約は、すべてに対してブルート フォースであることをすぐに示します。$k$不可能です。 と$T$まで$10^5$そして$p$まで$10^9$、可能な限りすべてを反復します$k$値には最大で$10^9$テスト ケースごとの操作量は、実現可能な制限をはるかに超えています。 テストケースごとに一定時間の評価が必要です。 

両方の場合に微妙なエッジケースが発生します。$x$そして$y$で割り切れます$p$。 そのような状況では、あらゆる$k$完全に割り切れる合計が得られるため、無駄がまったくありません。 このケースを無視した素朴なアプローチでもモジュラー式が計算され、不必要な複雑さが生じる可能性がありますが、正しい答えは単にゼロです。 

もう 1 つの特殊なケースは、次のいずれか 1 つだけの場合です。$x$または$y$で割り切れます$p$。 この場合、1 つの次元だけがきれいに寄与し、もう 1 つの次元は、$k$。 この非対称性により、誤った貪欲なアプローチやシミュレーションベースのアプローチが失敗する傾向があります。 

## アプローチ

 自然な出発点は、可能な限りのコンボ数を試すことです$k$から$1$に$p-1$、計算する$k x$そして$k y$、で割る$p$、剰余を合計します。 これは正しいですが、各テスト ケースでは次のことが必要になります。$O(p)$仕事。 と$p$と同じくらい大きい$10^9$、これは単一のテストケースであっても完全に実行不可能です。 

構造の単純化は、剰余のみが剰余であることを観察することで得られます。$p$案件。 書き込み$a = x \bmod p$そして$b = y \bmod p$、無駄は方法によってのみ異なります$k a \bmod p$そして$k b \bmod p$振る舞う。 以来$p$が素数である場合、非ゼロ残基による乗算はすべての非ゼロ残基を並べ替えます。$k$基本的に、フィールドのモジュロ内の循環構造を通過します。$p$。 

すべてを探索するのではなく、$k$、無駄の表現が非常に少数の極端な構成に単純化されることがわかります。 最小値は、境界に揃えられた乗数の 1 つ、具体的には次の位置で発生します。$k = 1$または$k = p - 1$。 他のすべての値は対称またはこれら 2 つの極端な値に勝てない順列です。$k \mapsto (ka \bmod p, kb \bmod p)$厳密に小さい合計を生成する可能性のある追加の構造を持たない単一の周期軌道を形成します。 

これにより、大規模な組み合わせ検索の問題が 2 つの候補値のみの評価に軽減されます。

 ## アルゴリズムのチュートリアル

 各テスト ケースをモジュール残基に削減し、2 つの意味のある構成のみを評価します。 

1. コンピューティング$a = x \bmod p$そして$b = y \bmod p$。 これにより、除算後の剰余に影響を与える部分のみが分離されます。$p$。 
2. 両方が当てはまるような些細なケースを処理します。$a = 0$そして$b = 0$。 このような状況では、どの製品も$k x$そして$k y$で割り切れます$p$、したがって無駄は一切出ず、答えはゼロです。 
3. 最初の候補を評価する$k = 1$。 無駄はどうやって決まるのか$a + b$～に対して相対的に動作する$p$。 もし$a + b < p$ラップが発生せず、廃棄物が簡単に排出されます。$a + b$。 もし$a + b \ge p$、サイズの完全なブロック 1 つ$p$分割で除去され、無駄が残る$a + b - p$。 
4. 2 番目の候補を評価する$k = p - 1$。 乗算$p - 1$残基を次のように反映します$p - a$そして$p - b$(with zero preserved). 結果として生じる廃棄物は、$2p - a - b$。 
5. 計算された 2 つの無駄の最小値を返します。 

重要な考え方は、他のすべての値は$k$は同じモジュラー軌道上にあり、これら 2 つの極値アライメントより小さい剰余の合計を生成することはできません。 

### なぜ効果があるのか

 ペア$(k a \bmod p, k b \bmod p)$有限体で固定ベクトルを乗算することで進化します$\mathbb{F}_p^2$。 以来$p$プライムであり、$k$すべての非ゼロ剰余にわたる範囲、これにより次のサイズの単一の周期軌道が生成されます。$p - 1$。 最小化する関数は座標の剰余の合計であり、次の変換の下で対称です。$k \leftrightarrow p - k$。 この対称性により、すべての内部構成が反射された構成とペアになり、周囲の相補的な合計が生成されます。$2p$。 結果として、最小値は境界代表の 1 つで発生する必要があり、これは次のように捕捉されます。$k = 1$そして$k = p - 1$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        p, x, y = map(int, input().split())
        a = x % p
        b = y % p

        if a == 0 and b == 0:
            out.append("0")
            continue

        # k = 1
        s1 = a + b
        if s1 >= p:
            s1 -= p

        # k = p - 1
        s2 = 2 * p - a - b

        out.append(str(min(s1, s2)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、派生したリダクションを直接反映しています。 まず入力を剰余モジュロに圧縮します$p$の絶対値なので、$x$そして$y$これ以上は無関係です。 次に、以下に対応する 2 つの候補構成を明示的に評価します。$k = 1$そして$k = p - 1$、最初のケースでのみモジュラーキャリーを適用します。単一のラップのみが可能であるためです。$p$起こる。 

2 番目の候補は、条件分岐なしの閉じた形式で計算されます。$2p - a - b$リフレクション中の正しい剰余構造がすでに反映されています。 最後に最小値を出力します。 

ここでよくある間違いは、乗算のモジュロをシミュレートしようとすることです。$p$複数の$k$、これは不必要であり、拡張できません。 もう 1 つの微妙な問題は、次の場合に調整を忘れることです。$a + b \ge p$、これにより、実効剰余が変更されます。$k = 1$場合。

 ## 特殊なケース

 両方のとき$x$そして$y$の正確な倍数です$p$の場合、すべての分布は完全に均等であるため、アルゴリズムはすぐにゼロを返します。$k$。 モジュラー リダクションでは両方の剰余がゼロに折りたたまれるため、両方の候補式もゼロに評価され、正確さが維持されます。
