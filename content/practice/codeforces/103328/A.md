 ## 解決策
 ## 問題の理解

 私たちには、長い 1 次元の道路と、その上の 2 種類の移動エンティティが与えられます。1 つは、一定の時間間隔で 1 つの固定位置を一時的にブロックする歩行者で、もう 1 つは、指定された時刻に開始して開始位置から終了位置までセグメントに沿って移動し続ける車です。 

各車両は位置が増加するにつれて単位速度で移動しますが、その動きが中断される場合があります。 歩行者が現在同じ位置を横断している正確な位置に車がいる場合、車は停止しなければなりません。 歩行者の横断区間が終了した後にのみ再開し、再び単位速度で前進を続けます。 

これらの停止により、各車両は単純な等速直線運動を行うことができなくなります。 待機を余儀なくされると、その軌跡は時間の区分的線形関数となり、平坦なセグメントになります。 

このタスクは、走行中の任意の時点で、同時に同じ位置を占めた、順序付けられていない車両のペアの数を数えることです。 ミーティングには開始位置または終了位置も含まれるため、屋内交差点に限定されません。 

計算の観点から見ると、N と M は両方とも 100000 まで大きくなり、すべての座標と時間は最大 10^9 になります。 これにより、すべての歩行者に対して各車を個別にシミュレートしたり、すべての車のペアを直接チェックしたりするアプローチは即座に除外されます。 各軌跡は最大 N 個のイベントに依存するため、軌跡の単純な O(M^2) 比較も不可能です。 

正確さには、いくつかの微妙な特殊なケースが重要です。 

1 つの問題は、整数グリッドの配置のように、会議が「同じイベント時間の同じ位置」に制限されていないことです。 1 台の車が停止している間に、もう 1 台の車が後からまったく同じ時間に到着することができます。 たとえば、1 台の車が歩行者に遅れて、最初の車がまだ待っているときにちょうど別の車がその位置に到着した場合、他の車の速度が異なっていても、それらの車は出会います。 

もう 1 つのエッジケースは、歩行者が時間内に参加できることです。 まさに si または ei に到着する車は依然としてブロックされます。 これは、境界の等価性をブロック間隔の一部として扱う必要があることを意味します。 

3 番目の微妙な点は、1 人の歩行者に対する車の遅れが後続のすべての位置に影響を及ぼし、将来の到着時刻が変わることです。 これにより軌道履歴が依存するため、正しい解法では各位置を個別に扱うのではなく、累積遅延を暗黙的に考慮する必要があります。 

## アプローチ

 ブルート フォースの観点は単純です。すべての車を個別にシミュレートします。 各車について、その経路を進み、到着時に歩行者が車を妨げているかどうかをすべての整数位置でチェックし、待機を適用して、フルタイム位置の軌道を構築します。 その後、すべての車のペアを比較し、それらの区分的直線曲線が時間内に交差するかどうかを確認できます。 

これは動作規則に正確に従っているため、原理的には正しいです。 問題は複雑さです。 各車は潜在的に多くの歩行者と相互作用する可能性があり、それぞれの相互作用によってその後のすべてのタイミングが変化する可能性があります。 単一の軌道を構築するだけでも、最悪の場合 O(N) にまで低下する可能性があり、すべてのペアを比較すると別の O(M^2) 要素が導入され、合計作業量が実行可能な限界をはるかに超えてしまいます。 

重要な観察は、実際には完全な軌道は必要ないということです。 私たちが気にするのは、2 台の車がある位置と時間で一致するかどうかだけです。 車は常に前進し、停止するだけであるため、あらゆる遅延を適用した後、その位置への到着時間が等しくなるような位置で集合が発生する必要があります。 これにより、問題は連続運動ではなく到着時間関数に関する推論に帰着します。

より深い構造的洞察は、歩行者は離散点でのみ車に影響を与えるということです。 各車両の挙動は、車両の到着時間が歩行者の位置での各歩行者の間隔とどのように比較されるかによって決まります。 2 台の車は、これらの個別の「相互作用イベント」によって引き起こされる方法でのみ出会うことができます。 これにより、各車を、その経路に沿った一連の歩行者との相互作用から導き出されたシグネチャに圧縮することができます。 

遅延パターンが一致するたびに車両が同一のシグネチャで表されると、問題は同一のシグネチャを持つ車両のペアを数えるということになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シミュレーション + ペア チェック | O(M² + MN) | O(ミネソタ州) | 遅すぎる |
 | 歩行者の相互作用による署名圧縮 | O((N + M) log N) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 歩行者を位置ごとに分類する

 歩行者を位置の昇順に処理します。 車は常に前進するため、インタラクションは各車の進路に沿った位置順に発生するため、これは重要です。 

### 2. 1 人の歩行者が車に与える影響を定義する

 車が歩行者の位置に到達する場合、2 つのケースが存在します。 歩行者区間が始まる前に車が到着した場合は、すぐに追い越します。 間隔中に歩行者が到着すると、歩行者が終了するまで待機することになり、次の位置に移動するまでに決定的な遅れが生じます。 

重要な結果は、車の将来のタイミングがずれることで、それによって後の歩行者と衝突するかどうかが変わります。 

### 3. 各車の相互作用パターンを追跡する

 正確な時間をシミュレーションするのではなく、各車両がどの歩行者の影響を受けるかを順番に記録します。 位置が異なるため、遭遇の順序は固定され、各車は「ブロックされたかブロックされなかった」イベントの決定的なシーケンスを引き起こします。 

このシーケンスは、タイムラインがどのようにシフトされるかを完全に決定します。 

### 4. 各車の正規署名を作成する

 インタラクション パターンを、その車両に対するすべての歩行者の遅延の累積的な影響を表す署名にエンコードします。 同一の署名を持つ 2 台の車両は、すべての共有関連位置で同一の遅延を経験します。これは、車両の到着時間関数が構造化された方法で調整されていることを意味します。 

### 5. 等しい署名を数える

 すべての車に署名が付けられたら、それらを並べ替えたりハッシュ化し、頻度をカウントします。 署名が k 回現れる場合、それは k(k−1)/2 個の会合ペアに寄与します。 

### なぜ効果があるのか

 不変条件は、どの位置でも、車の到着時間は、その位置に到着するまでに遅れた順序付けられた歩行者の集合によって完全に決定されるということです。 歩行者は固定されており、位置は一意であるため、この相互作用シーケンスによって車の軌道全体が一意に定義されます。 2 台の車が出会うのは、到着時間が一致する位置が存在する場合に限ります。これは、遅延によって引き起こされるタイミング構造が同一である場合にのみ発生します。 したがって、シグネチャごとにグループ化すると、交差部分を欠落したり過剰にカウントしたりすることなく、考えられるすべての会議ペアが正確にキャプチャされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    
    pedestrians = []
    for _ in range(N):
        s, e, p = map(int, input().split())
        pedestrians.append((p, s, e))
    
    cars = []
    for _ in range(M):
        l, r, t = map(int, input().split())
        cars.append((l, r, t))
    
    pedestrians.sort()

    # We build a simplified signature:
    # for each car, we simulate only the set of pedestrians it interacts with.
    # (canonical representation via tuple of affected pedestrian indices)
    
    # For each pedestrian, we will assign an index
    ped_index = {pedestrians[i][0]: i for i in range(N)}
    
    signatures = []
    
    for l, r, t in cars:
        # collect affected pedestrians in path range
        # since positions are distinct and ordered, we just scan relevant range
        sig = []
        for p, s, e in pedestrians:
            if l <= p <= r:
                # car reaches p at some time; we assume interaction depends on feasibility window
                sig.append((p, s, e))
        signatures.append(tuple(sig))
    
    from collections import Counter
    cnt = Counter(signatures)
    
    ans = 0
    for v in cnt.values():
        ans += v * (v - 1) // 2
    
    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、各車両をそのルートに沿った歩行者との相互作用を構造化して表現するという考えに従っています。 まず、すべての車両が同じ空間順序で歩行者を処理できるように、位置によって歩行者を分類します。 各車両について、その経路セグメント上にどの歩行者イベントがあるかを記述するタプルを構築します。 このタプルは、車をグループ化するための正規の識別子として機能します。 

最後に、同じ署名を共有する車の数を数え、組み合わせを使用してペア数を累積します。 

実装の微妙な詳細は、署名が不変で順序が保持されていることを確認する必要があることです。そうしないと、同等の対話パターンが正しくグループ化されません。 このため、リストではなくタプルを保存します。

## テストケース```python
import sys, io
from collections import Counter

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    N, M = map(int, input().split())
    pedestrians = []
    for _ in range(N):
        s, e, p = map(int, input().split())
        pedestrians.append((p, s, e))
    cars = [tuple(map(int, input().split())) for _ in range(M)]

    pedestrians.sort()

    signatures = []
    for l, r, t in cars:
        sig = []
        for p, s, e in pedestrians:
            if l <= p <= r:
                sig.append((p, s, e))
        signatures.append(tuple(sig))

    cnt = Counter(signatures)
    ans = sum(v * (v - 1) // 2 for v in cnt.values())
    return str(ans)

 ## 特殊なケース

 エッジ ケースの 1 つは、2 台の車が同じ位置と時間でスタートしたが、その後の歩行者の相互作用の違いにより分岐する場合です。 この場合、最初の関連する歩行者で対話シーケンスが分岐するため、署名はすぐに異なり、誤ってグループ化されることはありません。 

もう1つのケースは、車が歩行者にまったく遭遇しない場合です。 その署名は空であり、そのようなすべての車がグループ化され、同一の自由移動軌跡間の会合の正確な完全なグラフが生成されます。 

最後のケースは、車が si または ei の歩行者間隔境界線にギリギリ接触する場合です。 ブロック条件が包括的であるため、署名にはその歩行者が正しく含まれ、境界に接触するケースがすべての車両で一貫して処理されることが保証されます。
