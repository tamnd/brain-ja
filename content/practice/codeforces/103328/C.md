 ## 解決策
 ## 問題の理解

 サボテンであることが保証された単純な無向グラフが与えられました。これは、すべてのエッジが最大でも 1 つの単純なサイクルに属することを意味します。 課題は、このグラフが完全なグラフであるかどうかを判断することです。 

ここでの完全性は、定義から直接計算できるものではありません。すべての誘導サブグラフをチェックしたり、クリーク数を彩色数と比較したりすることは実行不可能だからです。 代わりに、完全なグラフを、少なくとも 5 の長さの奇数サイクルが誘発されず、その補数も含まれないグラフとして特徴付ける強力な完全グラフ定理に依存します。 

したがって、問題はサボテンの構造的な問題に帰着します。サボテンには少なくとも 5 の長さの誘導された奇数サイクル、または誘導された奇数のアンチホールが含まれているかどうかです。 

サボテンの制約が重要な単純化です。 エッジは最大 1 つのサイクルに属するため、サイクルは明確に分離され、複雑に重なり合うことはありません。 これは、ツリー以外の動作は単純なサイクルに局在化されており、ツリーのアタッチメントを介した穏やかな相互作用のみで各サイクルを独立して推論できることを意味します。 

入力サイズは頂点とエッジが 100,000 に達するため、どのソリューションも線形に近いものでなければなりません。 二次関数や重い定数を含む n log n は問題ありませんが、部分グラフを列挙したり、単純に循環したり、色付けをシミュレートしようとするものは遅すぎます。 

微妙な点は、サボテン内のすべてのサイクルが自動的にグラフ内の誘導サイクルになるわけではないことです。 サイクルにコードがある場合、それはサボテンの単純なサイクルではないため、そこでは安全です。 ただし、主な落とし穴は、ツリー エッジを介したサイクルへのアタッチメントがサイクル自体の誘導されたサブグラフ構造に影響を与えないため、各サイクルを誘導されたものとして扱うことができることです。 

エッジ ケースは、グラフがツリーである場合、サイクルが 1 つだけある場合、または複数のサイクルがアーティキュレーション ポイントを共有する場合に発生します。 たとえば、ツリーは二部構成であるため、常に完全です。 単一の 5 サイクルは完璧ではありませんが、4 サイクルは完璧です。 補数条件はより微妙ですが、サボテンの場合、違反は少なくとも 5 の長さの奇数サイクルの存在から直接発生することがわかります。 

一般的な完全なグラフ認識アルゴリズムを実行しようとする単純なアプローチは失敗します。これらのアルゴリズムはサボテンの制約下でははるかに複雑で不必要であるためです。 

## アプローチ

 ブルートフォースの観点は定義から始まります。つまり、誘導されたすべてのサブグラフについて、クリーク数と色彩数を比較する必要があります。 強力な完全グラフ定理を使用して制限したとしても、誘導された奇数サイクルと誘導された奇数アンチホールを検出する必要があります。 

一般的なグラフの場合、あらゆる長さの誘導サイクルとその補数を検出するにはコストがかかります。 すべての単純なサイクルを列挙するには、最悪の場合、すでに指数関数的な時間がかかります。 サボテンの場合でも、サイクルのリスト化は管理可能ですが、アンチホールを直接チェックすることは困難です。 

重要な観察は、サボテンの構造が問題を崩壊させているということです。 すべてのサイクルは関節点を除いて分離されているため、グラフ内に存在する誘導サイクルはまさにサボテン内の単純なサイクルの 1 つです。 さらに、誘導された奇数のアンチホールは、非常に小さな構造化されたケースに対応しない限り、サボテン内に出現することはできず、これらは単純化すると同じサイクル条件になります。 

これは、問題がサボテン内のすべての単純なサイクルをスキャンし、少なくとも 5 の長さのサイクルが奇数かどうかをチェックすることを意味します。 

この短縮を受け入れると、タスクは簡単になります。DFS を使用してサボテン内のすべてのサイクル長を見つけ、そのパリティを計算し、禁止されたサイクルが存在するかどうかを確認します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォースによるサブグラフ チェック | 指数 | O(n) | 遅すぎる |
 | cactus でのサイクル抽出 + パリティ チェック | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

サボテンを任意の場所に根付け、DFS を実行してサイクルを形成するバックエッジを検出します。 グラフはサボテンであるため、各エッジは最大 1 つのサイクルに属し、各バック エッジが一意にサイクルを決定します。 

1. 各頂点の親ポインターと深さを維持しながら DFS を実行します。 これにより、バックエッジ経由で遭遇したあらゆるサイクルを再構築できるようになります。 
2. ノード u から祖先 v へのバック エッジに遭遇すると、u から親ポインターを通って v まで戻ることによってサイクルを再構築します。サイクルの長さは、このバックトラッキングで訪問した頂点の数に終了エッジの 1 を加えたものです。 グラフには重複するサイクルがないため、これはきれいに機能します。 
3. 検出された各サイクルについて、その長さを計算します。 長さが少なくとも 5 で奇数の場合、グラフは完全ではないと直ちに結論付けられます。 
4. すべてのエッジを探索した後にそのようなサイクルが存在しない場合、グラフは完璧であると結論付けます。 

サボテンでは、DFS ツリーによって非ツリー エッジが 1 つの単純なサイクルに正確に対応し、サイクル構造に曖昧さが存在しないことが保証されるため、再構成ステップは安全です。 

### なぜ効果があるのか

 サボテンでは、すべてのサイクルは他のサイクルとエッジを共有しないという意味で分離されています。 したがって、DFS バック エッジを通じて検出されたサイクルは、グラフ内の固有の単純なサイクルに正確に対応します。 サイクル上の誘導サブグラフは保存される (余分なコードは存在しない) ため、完全性を侵害する唯一の方法は、長さが少なくとも 5 の奇数サイクルを含めることであり、これはサイクル長をスキャンすることで直接検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
g = [[] for _ in range(n)]
for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

parent = [-1] * n
depth = [0] * n
vis = [0] * n

bad = False

def dfs(u, p):
    global bad
    vis[u] = 1
    for v in g[u]:
        if v == p:
            continue
        if not vis[v]:
            parent[v] = u
            depth[v] = depth[u] + 1
            dfs(v, u)
        else:
            if depth[v] < depth[u]:
                length = 1
                cur = u
                while cur != v:
                    length += 1
                    cur = parent[cur]
                if length >= 5 and length % 2 == 1:
                    bad = True

for i in range(n):
    if not vis[i]:
        dfs(i, -1)

print("No" if bad else "Yes")
```DFS は親ポインター ツリーを維持しているので、バック エッジに遭遇したときに上向きに歩いてサイクルを再構築できます。 深さチェックにより、先祖に向かってバック エッジのみがカウントされ、無向走査でのクロス エッジの二重カウントが回避されます。 

サイクル再構成はサイクル長において線形であり、サボテンの各エッジは最大 1 つのサイクルに属するため、すべてのサイクルにわたる合計再構成作業は全体として線形です。 

微妙な実装の詳細は、直接の親エッジをスキップすることです。そうしないと、すべての無向エッジがバック エッジとして誤分類されてしまいます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各エッジは DFS で 1 回処理され、サボテンの構造により、すべてのサイクルにわたるサイクルの再構築は合計で線形になります。 
| スペース | O(n + m) | 隣接リストと DFS ブックキーピング配列 |

 線形の複雑さは、100,000 個の頂点とエッジの制約内に快適に収まります。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * n
    depth = [0] * n
    vis = [0] * n
    bad = False

    sys.setrecursionlimit(10**7)

    def dfs(u, p):
        nonlocal bad
        vis[u] = 1
        for v in g[u]:
            if v == p:
                continue
            if not vis[v]:
                parent[v] = u
                depth[v] = depth[u] + 1
                dfs(v, u)
            else:
                if depth[v] < depth[u]:
                    length = 1
                    cur = u
                    while cur != v:
                        length += 1
                        cur = parent[cur]
                    if length >= 5 and length % 2 == 1:
                        bad = True

    for i in range(n):
        if not vis[i]:
            dfs(i, -1)

    return "No" if bad else "Yes"

 ## 特殊なケース

 ツリー入力にはサイクルが含まれていないため、DFS はバックエッジ再構築をトリガーしません。 アルゴリズムは終了します`bad`false と正しく出力され、Yes となります。 

純粋な 4 サイクルは、長さ 4 の 1 サイクルの再構築を正確にトリガーします。条件には少なくとも 5 の長さが必要なため、不良フラグは設定されません。これは、4 サイクルが 2 部構成であるため完全であるという事実と一致します。 

5 サイクルは、この設定における唯一の最小限の禁止構造です。 バック エッジがサイクルを閉じる瞬間、再構築はちょうど 5 つのノードを歩き、グラフが完全ではないと直ちにマークされます。
