 ## 解決策
 ## 問題の理解

 各道路が現在、ある都市から別の都市への移動を許可している都市の有向グラフが与えられます。 すべての道路について、次の 3 つの方法のうちの 1 つでそのステータスを変更することができます。つまり、そのままにするか、特定のコストを支払って方向を反転するか、別のコストを支払って完全に削除します。 

すべての変更を加えた後、唯一のグローバル制限は流入交通に関するものであり、すべての都市は最大で K 個の流入道路を持つことが許可されます。 外側の道路はまったく重要ではなく、最終構成の各ノードで終了するエッジの数だけが重要です。 

タスクは、総コストを最小限に抑えながら、すべてのノードで次数制約が満たされるように、すべての道路に対してアクションを選択することです。 

この制約は、エッジごとに 3 つのオプションを単純に指数関数的に選択することは不可能であることをすでに示唆しています。 最大 3000 のエッジの場合、総当たり検索ではおよそ 3^M の構成を探索することになりますが、これは完全に不可能です。 すべての選択がグローバルな入次数に影響を与えるため、これをエッジごとのローカルな貪欲な決定として処理しようとしても失敗します。 

複数のエッジが同じノードをめぐって競合する場合、微妙な問題が発生します。 たとえば、多くのエッジが単一の都市を安価にポイントしたい場合、K を超え、後でそれらの一部を元に戻すか削除する必要が生じる可能性があるため、ローカルな決定は信頼できません。 

貪欲な直感が失敗する典型的なケースは、ノードが K = 1 で、2 つの入力エッジが両方とも維持コストがゼロであるが、そのうちの 1 つを反転することも低コストである場合です。 ローカルで「エッジごとに最も安いもの」を選択すると、簡単に容量を超えてしまい、後で高価な修正が必要になる可能性があります。 

この問題は基本的にグローバルです。ノードごとの容量制限を尊重しながら、いずれかのエンドポイントに最大 1 単位の度数を寄与するように各エッジを割り当てています (または破棄されます)。 

## アプローチ

 ブルートフォース解釈では、各エッジを独立して処理し、3 つの選択肢をすべて試して、結果の次数制約が満たされるかどうかを確認します。 これは問題を正しくモデル化していますが、各エッジの構成数が 3 倍になるため、状態空間は M とともに指数関数的に増加します。 無効な部分割り当てを早期に削除しても、最悪の場合は保存されません。これは、内次数違反は多くの決定が蓄積された後でのみ検出できるためです。 

重要な構造的洞察は、問題を制約付き割り当てシステムとして再解釈することです。 各エッジは最大 1 単位の「次数寄与」を生成し、その単位は 2 つのエンドポイントのいずれかに割り当てることも、破棄することもできます。 各ノードは最大 K 個のそのようなユニットを受け入れることができます。 これはまさに、割り当てにコストがかかる、容量が制限された割り当ての問題です。 

このように考えると、問題は最小コスト フローのインスタンスになります。 各エッジは、配線する必要がある 1 つのユニットの供給のように動作します。 エッジを 1 つのエンドポイントにルーティングすることは、エッジをそのエンドポイントに向けることに相当し、ダミー シンクにルーティングすることはエッジを削除することに相当します。 ノード容量により K 制限が適用されます。 

この変換は、グローバルな組み合わせ制約を、まさに min-cost max-flow が処理するように設計されている流量保存と容量制約に変換するため、強力です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | エッジの選択に対するブルートフォース | O(3^M) | お(お) | 遅すぎる |
 | 最小コストの最大流量配合 | O(F · E log V) (または同様のもの) | O(E + V) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### モデルの構築

 私たちは、すべての決定が構造化されたパスを介してフローの 1 単位を送信することに対応するフロー ネットワークを構築します。 

### 段階的な構築

 1. ソース ノードを作成し、それを容量 1、コスト 0 のすべてのエッジ ノードに接続します。 

これにより、すべての元の道路に 1 つの決定を行うことが強制されます。 
2. u と v の間の各エッジ i に対して、そのエッジを表す中間ノードを作成します。 
3. エッジ ノード i から、3 つの発信オプションを追加します。

コスト ai で u への 1 つのエッジ (これは、u が入力エッジを受け取るように道路を反転することに対応します)、

 コスト 0 で v への 1 つのエッジ (v が次数を受け取るように元の方向を維持)、

 そして 1 つのエッジをコスト Bi の特別な「ゴミ箱」ノードに追加します (エッジを削除します)。 

これにより、許可される 3 つのアクションがフローの選択肢として正確にエンコードされます。 
4. すべての都市ノード x について、容量 K およびコスト 0 のシンクに接続します。 

これにより、最大 K 単位のフローが x を通過できるようになります。つまり、最大 K 個の入力エッジを x に割り当てることができます。 
5. 削除されたエッジはノード制約に影響を与えないため、ゴミ箱ノードを無限の容量とゼロコストでシンクに接続します。 
6. ソースからシンクに正確に M ユニットを送信する min-cost max-flow を実行します。 
7. 結果として得られる最小コストが答えです。 

### なぜ効果があるのか

 重要な不変条件は、すべてのエッジが 1 つのフロー単位を 3 つの宛先 (u、v、ゴミ箱) のいずれかに正確に送信することです。 u または v に進むと、そのノードの容量の 1 ユニットが消費されます。これは、次数が 1 増加することに正確に対応します。 各ノードの容量 K は、どのノードも K を超える入力寄与を受け取らないことを保証します。 実行可能なすべての再構築はそのようなフローの 1 つに正確に対応し、その逆も同様であり、コストは選択された操作に正確に一致するため、最適なフローは最適な再構築に対応する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from heapq import heappush, heappop

INF = 10**18

class MinCostMaxFlow:
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(n)]

    def add_edge(self, u, v, cap, cost):
        self.adj[u].append([v, cap, cost, len(self.adj[v])])
        self.adj[v].append([u, 0, -cost, len(self.adj[u]) - 1])

    def min_cost_flow(self, s, t, f):
        n = self.n
        res = 0
        h = [0] * n

        while f > 0:
            dist = [INF] * n
            parent_v = [-1] * n
            parent_e = [-1] * n
            dist[s] = 0
            pq = [(0, s)]

            while pq:
                d, u = heappop(pq)
                if d != dist[u]:
                    continue
                for i, e in enumerate(self.adj[u]):
                    v, cap, cost, rev = e
                    if cap > 0 and dist[v] > d + cost + h[u] - h[v]:
                        dist[v] = d + cost + h[u] - h[v]
                        parent_v[v] = u
                        parent_e[v] = i
                        heappush(pq, (dist[v], v))

            if dist[t] == INF:
                return res

            for i in range(n):
                if dist[i] < INF:
                    h[i] += dist[i]

            addf = f
            v = t
            while v != s:
                u = parent_v[v]
                ei = parent_e[v]
                addf = min(addf, self.adj[u][ei][1])
                v = u

            f -= addf
            res += addf * h[t]

            v = t
            while v != s:
                u = parent_v[v]
                ei = parent_e[v]
                self.adj[u][ei][1] -= addf
                rev = self.adj[u][ei][3]
                self.adj[v][rev][1] += addf
                v = u

        return res

def solve():
    n, m, k = map(int, input().split())

    S = 0
    T = 1 + m + n + 1
    edge_base = 1
    node_base = 1 + m
    trash = T - 1

    mcmf = MinCostMaxFlow(T + 1)

    for i in range(m):
        u, v, a, b = map(int, input().split())
        u += node_base - 1
        v += node_base - 1
        ei = edge_base + i

        mcmf.add_edge(S, ei, 1, 0)
        mcmf.add_edge(ei, u, 1, a)
        mcmf.add_edge(ei, v, 1, 0)
        mcmf.add_edge(ei, trash, 1, b)

    for i in range(n):
        node = node_base + i
        mcmf.add_edge(node, T, k, 0)

    mcmf.add_edge(trash, T, m, 0)

    print(mcmf.min_cost_flow(S, T, m))

if __name__ == "__main__":
    solve()
```実装はモデリングを直接反映します。 各エッジ ノードは単一の決定を強制しますが、ノードからシンクまでの容量によって次数制約が強制されます。 唯一の微妙な点はインデックス付けです。制約が明確に表現されるように、エッジとノードは個別のインデックス範囲に分離されています。 

最小コスト フローはポテンシャル (ジョンソンのトリック) を使用して、ダイクストラが非負の削減コストで機能することを保証します。これは制約下でのパフォーマンスに不可欠です。 

## 実用的な例

 ### 例 1

 入力:```
3 3 1
1 2 2 5
3 2 1 5
3 1 10 10
```エッジごとに決定を追跡します。 

| エッジ | 選択されたオプション | 角度変化 | コスト |
 | --- | --- | --- | --- |
 | 1→2 | キープ | ノード 2 +1 | 0 |
 | 3→2 | 逆 | ノード 3 +1 | 1 |
 | 3→1 | 削除 | なし | 10 |

 そうでない場合、両方のエッジがノード 2 を指している場合、ノード 2 は K=1 を超えるため、最適なソリューションは流れの集中を回避します。 最適な構造は、逆コストを最小限に抑えながら、多角度に広がります。 

このトレースは、たとえ維持コストが低い場合でも、方向付けにコストのかかるエッジを削除することが必要な場合があることを示しています。 

### 例 2

 入力:```
3 3 1
1 2 100 100
2 3 100 100
3 1 100 100
```すべてのアクションはコストが対称であるため、ノードごとに 1 つの入力エッジを有効に割り当てることが最適です。 

| エッジ | アクション | 割り当てられたノード | コスト |
 | --- | --- | --- | --- |
 | 1→2 | キープ | 2 | 100 |
 | 2→3 | キープ | 3 | 100 |
 | 3→1 | キープ | 1 | 100 |

 これにより、どこでも K=1 に関する有向サイクルが形成されます。 フロー定式化により、サイクルに関する明示的な推論を必要とせずに、循環割り当てが自動的に強制されます。

 ## 特殊なケース

 重要なエッジ ケースは、多くの安価なエッジが K を超える単一のノードをターゲットにする場合です。このような場合、貪欲な戦略では、早い段階で度数を過剰に割り当ててしまいます。 フローの定式化では、これはノードからシンクまでの容量エッジによって処理され、K を超える追加の割り当てがブロックされます。 

もう 1 つの特殊なケースは、削除がどの方向よりも常に安価である場合です。 モデルはすべてのエッジ フローをゴミ ノードを介して自然にルーティングし、あらゆる場所で角度ゼロを生成し、すべての制約を満たします。 

最後の微妙なケースは、一部のエッジを保持するよりも反転する方が安価ですが、エンドポイントで不均衡が生じる場合です。 インディグリーの各ユニットがノードに付随するすべてのエッジにわたってグローバルに競合するため、フローはこれを自動的にバランスさせ、局所的に最適な反転ではなく、最も安価な実現可能な組み合わせが選択されるようにします。
