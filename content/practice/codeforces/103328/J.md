 ## 解決策
 ## 問題の理解

 最大 20 人のプレイヤー間の有向関係グラフが与えられます。 各プレイヤーは他のプレイヤーを何人か知っていますが、この知識は対称的ではありません。 ゲームは、プレイヤー 1 がトークンを持っていることから始まります。 プレイヤーがトークンを保持するときは常に、これまでにトークンを保持したことのない知り合いにトークンを渡さなければなりません。 それができない場合は、即時に負けとなり、その時点でゲームが終了します。 

重要な点は、プレイヤーがトークンを渡すための有効な選択肢を複数持っている場合、利用可能なすべての候補の中から均一にランダムに選択することです。 すべてのプレイヤー i について、プレイヤー i が最終的にゲームに負ける確率、つまりトークンが i に到達した後、有効な次の手がなくなる確率を計算するように求められます。 

入力は、グラフの有向エッジを記述するサイズ n × n の隣接行列です。 プレーヤー i からプレーヤー j への値 1 は、j が以前に訪問されていない場合に限り、i がトークンを j に渡すことができることを意味します。 これにより、このプロセスは、未訪問の発信近隣ノードがないノードに到達すると終了する自己回避ランダム ウォークになります。 

制約は非常に小さく、n ≤ 20 です。これは、2^20 が約 100 万であるため、訪問ノードのサブセットにわたる指数関数的な状態が実行可能であることを直ちに示唆します。 これは、特に遷移がそれほど高価でない場合、サブセットに対する動的プログラミングの制限内に十分収まります。 

複数の出力未訪問エッジを持つすべてのノードでランダム性が分岐するため、プロセスの単純なシミュレーションでは十分ではありません。 このプロセスは単一のパスではなく、指数関数的に多くのパスにわたる確率分布です。 

プレイヤーに発信エッジがまったくない場合、またはすべての発信エッジがすでに訪問したノードにつながる場合、微妙なエッジ ケースが発生します。 その場合、そのプレイヤーは即敗者状態となります。 もう 1 つのエッジ ケースは、複数のプレーヤーが同一の出力選択肢を持っている場合です。これにより、正確に保存する必要がある対称的な確率分割が生じる可能性があります。 3 番目の重要なケースは、グラフにサイクルが含まれる場合です。 訪問済みの制限により再訪問が防止されるため、サイクルは無限ループではなく、利用可能な順序付けの制約に関してのみ重要になります。 

## アプローチ

 ブルートフォース解釈では、有効なパスの考えられるすべてのシーケンスをシミュレートし、訪問したセットを追跡し、プレーヤーに複数の選択肢がある場合は常に分岐します。 各状態は、現在のプレーヤーと訪問したプレーヤーのセットによって定義されます。 各状態から、すべての有効な出力エッジにわたって確率を均等に分配します。 

このブルート フォースは概念的には正しいですが、メモ化せずに単純な再帰として実装すると、同じ状態を指数関数的に何度も再計算することになります。 メモ化を行った場合でも、状態の数は O(n · 2^n) であり、各状態は最大 O(n) 個の遷移をスキャンして、およそ O(n^2 · 2^n) になりますが、n ≤ 20 の場合、これはまだ実現可能です。 

重要な観察は、プロセスがペア (現在のプレーヤー、訪問セット) によって完全に決定されるということです。 その状態を知ると、未来は私たちがどのようにしてそこに到達したかに依存しません。 これは、サブセットに対する古典的なマルコフ決定構造です。 したがって、任意の状態から開始して特定のプレイヤーが最終的に敗者になる確率を返す動的プログラミング関数を定義したり、同様に最終状態までの遷移確率を計算して負け確率を累積したりすることができます。 

より明確な定式化は、dp[mask][u] を、現在プレイヤー u が正確にマスクを訪問している確率として定義し、確率を前方に伝播することです。 u に有効な出力エッジがない場合、その状態は u の損失確率に直接寄与します。 

これにより、問題は均一な遷移を持つサブセット状態にわたる有限の DP に変換されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | メモなしのブルートフォース再帰 | 指数関数 (2^n パスよりも非常に悪い) | O(n) スタック | 遅すぎる |
 | ビットマスク DP over (マスク, u) | O(n^2 · 2^n) | O(n · 2^n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちはすべての状態をゲームの構成として扱います。つまり、どのプレイヤーがすでにポテトに触れているか、どのプレイヤーが現在ポテトを保持しているかということです。 

1. dp[mask][u] がゲームが現在状態 (mask, u) にある確率を表す DP テーブルを初期化します。 最初はプレイヤー 1 だけがポテトを持っており、プレイヤー 1 だけが訪問されるため、 dp[1 << 0][1] = 1 から始めます。 
2. 小さいマスクから大きいマスクまですべてのマスクを反復処理し、状態を処理するときに、そこに至るすべての状態がすでに考慮されていることを確認します。 遷移ごとに訪問マスクが増加するため、この順序は自然です。 
3. 確率がゼロではない各状態 (マスク、u) について、有効な次の動きのリストを計算します。 u → v の移動は、エッジがあり、v がマスク内にない場合に有効です。 これは、どのプレイヤーもポテトを 2 回受け取ることができないというルールを反映しています。 
4. 有効手数が 0 の場合、この状態で u は強制的に負けます。 dp[mask][u] を ans[u] に追加します。これにより、u が負けたプレイヤーである確率が累積されます。 
5. k 個の有効な手が存在する場合、次の各状態 (マスク ∪ {v}, v) は dp[マスク][u] / k の確率を受け取ります。 これにより確率が均一に分配され、ランダムな選択ルールに一致します。 
6. すべての状態を処理した後、配列 ans[u] には、プレイヤー u が移動できなくなりゲームを終了する合計確率が含まれます。 
7. 各確率を短縮分数 ai / bi に変換し、ai * bi^{-1} mod 1e9+7 を出力します。 

これが機能する理由は単純な不変式に基づいています。つまり、dp は常に、探索の各段階で到達可能なすべてのゲーム状態にわたる正確な確率分布を表します。 各状態はその確率をすべての正当な次の動きに均等に分配し、終端状態は対応する敗者バケットに確率マスを削除するため、すべての遷移では合計確率マスが保存されます。 すべての有効なプレイ シーケンスはこの状態グラフを通る 1 つのパスに正確に対応し、すべてのパスはそれに沿った一様な分岐確率の積によって重み付けされるため、ノードの累積された最終質量は、そのノードが移動できずにゲームが終了する確率に等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

n = int(input())
g = [list(map(int, input().split())) for _ in range(n)]

N = 1 << n

# dp[mask][u] stored as probability numerator in modular form
dp = [[0] * n for _ in range(N)]
dp[1][0] = 1  # only player 0 visited, at node 0

ans = [0] * n

for mask in range(N):
    for u in range(n):
        cur = dp[mask][u]
        if cur == 0:
            continue

        # collect valid moves
        moves = []
        for v in range(n):
            if g[u][v] and not (mask >> v) & 1:
                moves.append(v)

        if not moves:
            ans[u] = (ans[u] + cur) % MOD
            continue

        invk = modinv(len(moves))
        nxt_mask_base = mask

        for v in moves:
            dp[mask | (1 << v)][v] = (dp[mask | (1 << v)][v] + cur * invk) % MOD

# convert probabilities (they are already modular sums)
print(*ans)
```実装はサブセット DP 解釈に直接続きます。 dp テーブルには、各状態にある確率質量が格納されます。 状態を展開するときは、すべての有効な出力エッジを列挙し、確率を均等に分配します。 

微妙な点は、マスクには現在のノードが含まれている必要があることです。 したがって、初期マスクは 1 ではなく 1 << 0 であり、すべての遷移で次のノード ビットが設定されます。 もう 1 つの詳細はモジュラー除算です。これは、選択肢の数のモジュラー逆数を使用して処理されます。 

ans 配列は、負けイベントに対応するノードごとの終了確率を累積します。 

## 実用的な例

 すべてのプレーヤーが他のすべてのプレーヤーを知っている対称的な三角形を考えてみましょう。 プレイヤー 1 から開始して、すべての動きが残りの未訪問のノード間で均等に分岐します。 

最初のいくつかのステップでは、DP は次のように進化します。 

| マスク | 現在 | 有効な動き | 遷移確率 |
 | --- | --- | --- | --- |
 | {1} | 1 | 2,3 | 1/2 ～ (1,2)、1/2 ～ (1,3) |
 | {1,2} | 2 | 3 | 1 から (1,2,3) |
 | {1,3} | 3 | 2 | 1 から (1,3,2) |

 最終的に、両方のフル パスは最後に残ったノードで終了しますが、このノードには未訪問の出力エッジがないため、失われます。 対称性のため、最後の 2 人のプレイヤーはそれぞれ最終敗者となる確率が同じになり、プレイヤー 2 と 3 はそれぞれ 1/2 になります。 

このトレースは、DP が分岐点で確率を正しく分割し、それを終端状態で集約していることを確認します。 

ここで、後方エッジのない線形チェーン 1 → 2 → 3 を考えてみましょう。 

| マスク | 現在 | 有効な動き | 遷移確率 |
 | --- | --- | --- | --- |
 | {1} | 1 | 2 | 1 から (1,2) |
 | {1,2} | 2 | 3 | 1 から (1,2,3) |
 | {1,2,3} | 3 | なし | 3敗 |

 ここではチェーンが強制されているため、プレイヤー 3 が負ける確率は 1 です。 DP はすべての確率マスをプレーヤー 3 に正しくルーティングします。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2 · 2^n) | 2^n マスクのそれぞれは最大 n 個の状態を処理し、それぞれが最大 n 個の遷移をスキャンします。 
| スペース | O(n · 2^n) | サブセットと現在のノードにわたる DP テーブル |

 n ≤ 20 の場合、2^n は約 100 万回であるため、合計操作は数千万回程度となり、時間制限内に十分収まります。

 ## 特殊なケース

 重要なエッジ ケースは、開始ノードにすでに発信エッジがない場合です。 その場合、プレイヤー 1 が直ちに敗者になります。 初期状態には動きがなく、ans[1] に直接追加されるため、DP はこれを自然に処理します。 

もう 1 つのケースは、ノードがすでに訪問したノードへの発信エッジのみを持つ場合です。 これは、訪問されたマスクが大きい場合、DP の奥深くで発生する可能性があります。 アルゴリズムは、元のグラフ構造に関係なく、これを終了状態として正しく処理します。 

最後の微妙なケースは、複数のパスが同じ状態に至る、対称性の高いグラフです。 確率が同じ dp[mask][u] に累積されるため、DP はこれらの寄与を自然にマージし、二重カウントや質量の欠落がないことを保証します。
