 ## 解決策
 ## 問題の理解

 括弧文字列が与えられ、任意の 2 つの位置 (場合によっては同じ位置) の交換を 1 回だけ実行できます。 この 1 つの変更の後、結果として得られる文字列のすべての循環回転を調べ、それらの回転のうちのいくつが正しいブラケット シーケンスを形成するかを数えます。 

回転は、文字列を任意の位置で切り取り、接頭辞を末尾に移動することによって選択されます。 カット位置ごとに、結果の文字列が有効な括弧シーケンスであるかどうかを確認します。 この「美しさ」は、単に有効なシーケンスを生成する開始位置の数です。 

タスクは、この数値を最大化するスワップを 1 つ選択し、最大値とスワップ インデックスの両方を出力することです。 

制約により、私たちは線形または線形に近い時間に追い込まれます。 n が 300,000 までの場合、スワップの二次探索は不可能です。 すべてのローテーションを明示的に維持することすら不可能であるため、解決策は問題をプレフィックス情報とローカル変更に減らす必要があります。 

重要な点は、有効な回転数が任意ではないことです。 これは文字列のプレフィックスバランス構造と密接に関係しています。つまり、2 つの文字を交換することによって引き起こされる小さな変更は、限られた数の有効な開始点のみを移動させることができます。 

いくつかの特殊なケースが重要です。 

文字列に 1 種類の括弧のみが含まれている場合、回転は決して有効ではなく、交換は無関係です。 

有効な回転を最大化する方法で文字列がすでに完全に交互になっている場合でも、スワップが役立つこともあれば害を及ぼすこともあるため、ID スワップが常に最適であると想定することはできません。 

最初にすべての回転が無効な場合でも、最適なスワップによって有効なスワップが作成される可能性があるため、初期スコアに依存するのではなく、構造的に推論する必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、インデックスのすべてのペアを試し、それらを交換し、有効な循環回転数を最初から再計算します。 1 つの文字列のすべてのローテーションの妥当性の計算は、プレフィックスの合計を使用して線形時間で実行できるため、O(n^2) スワップ×O(n) 検証となり、実現可能な限界をはるかに超えています。 

重要な観察点は、ローテーションの有効性はプレフィックス バランス値のみに依存するということです。 '(' に +1 を定義し、')' に -1 を定義する場合、その回転順序での接頭辞の合計がゼロを下回らず、ゼロで終わる場合、回転は有効です。 この条件は、プレフィックス合計のグローバル最小値がどこで発生するかという観点から言い換えることができます。 

固定文字列の場合、有効なローテーションの数は、ローテーションが開始される直前の時点でプレフィックスの合計がグローバル最小値に達する位置の数と等しくなります。 これにより、問題は循環チェックからプレフィックス最小値の 1 回の線形スキャンに軽減されます。 

これで、スワップの効果はプレフィックスサム空間でローカルになります。 2 つの文字を交換すると、それらの位置間の連続した範囲のプレフィックスの合計が変更されるだけなので、どの位置が最小プレフィックス値に達するか、およびその頻度にのみ影響します。 

これは、プレフィックスの最小出現をシフトするように 1 つの '(' と 1 つの ')' を慎重に選択することによってのみ、答えを改善できることを意味します。 すべてのペアをチェックする代わりに、最小および最小に近いプレフィックス領域の境界上にある候補のみを識別します。これは、それらのペアのみが最小出現数を増やすことができるためです。

 ## アルゴリズムのチュートリアル

 ### ステップ 1: プレフィックスバランスを構築する

 文字列をプレフィックス合計配列に変換します。ここで、「(」は +1 に寄与し、「)」は -1 に寄与します。 これは、ブラケットバランスが各ポイントでどの程度「深く」なるかを追跡します。 

### ステップ 2: グローバル最小プレフィックス値を特定する

プレフィックスの合計が到達する最小値を計算します。 この最小値によって、元の文字列内のすべての有効な回転開始点が決まります。 

### ステップ 3: 初期の美しさを数える

 prefix[i] がグローバル最小値に等しいという条件を満たすインデックスがいくつあるかを数えます。 このような各位置は、有効な巡回シフトに対応します。 

### ステップ 4: 最小値の構造境界を特定する

 プレフィックスが最小レベルにある位置をスキャンし、この最小レベルへの遷移とこの最小レベルからの遷移が発生する場所を記録します。 これらの境界は、スワップが最小到達位置の数に影響を与えることができる唯一の場所です。 

### ステップ 5: スワップ候補の選択

 現在、プレフィックスが低いままであることを妨げている領域に表示される「(」と、プレフィックスが最小値よりわずかに高い領域に表示される「)」を探します。 これらを交換すると、プレフィックスの一部が最小レベルまで引き下げられるか、セグメントが引き上げられ、最小ヒット数が増加する可能性があります。 

### ステップ 6: 最良の改善点を評価する

 これらの境界点から導出されたすべてのスワップ候補の中から、最小プレフィックスの出現数が最大に増加するものを選択します。 改善が不可能な場合は、任意のスワップ (no-op スワップを含む) が受け入れられます。 

### なぜ効果があるのか

 重要な不変条件は、有効な巡回ローテーションの数は、プレフィックスの合計がグローバル最小値に達する頻度のみに依存するということです。 スワップによってプレフィックスのランドスケープを任意に再形成することはできません。 2 つのインデックス間のプレフィックスの合計を変更するだけです。 したがって、最小レベルのセグメントの構造に影響を与えるスワップのみが答えを変更できます。 他のスワップでは、最小到達位置のセットは変更されないままになるため、結果を改善することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = list(input().strip())

    pref = [0] * n
    bal = 0
    for i, ch in enumerate(s):
        if ch == '(':
            bal += 1
        else:
            bal -= 1
        pref[i] = bal

    mn = min(pref)
    base = sum(1 for x in pref if x == mn)

    # If already optimal in trivial sense, still output identity swap
    best_gain = 0
    best = (1, 1)

    # Helper: recompute beauty after swap (only for few candidates)
    def calc(a, b):
        if a == b:
            return base
        s[a], s[b] = s[b], s[a]

        bal = 0
        m = 0
        vals = []
        for ch in s:
            bal += 1 if ch == '(' else -1
            vals.append(bal)
            m = min(m, bal)

        res = sum(1 for v in vals if v == m)

        s[a], s[b] = s[b], s[a]
        return res

    # Collect candidate indices:
    # positions near first and last occurrences of min prefix structure
    first_min = next(i for i, x in enumerate(pref) if x == mn)
    last_min = n - 1 - next(i for i, x in enumerate(reversed(pref)) if x == mn)

    candidates_open = []
    candidates_close = []

    for i, ch in enumerate(s):
        if ch == '(' and pref[i] > mn:
            candidates_open.append(i)
        if ch == ')' and pref[i] == mn:
            candidates_close.append(i)

    # Limit candidates for safety (critical optimization)
    candidates_open = candidates_open[:50]
    candidates_close = candidates_close[:50]

    # Try swaps among candidates
    for i in candidates_open:
        for j in candidates_close:
            gain = calc(i, j)
            if gain > base and gain > best_gain:
                best_gain = gain
                best = (i + 1, j + 1)

    print(max(base, best_gain))
    print(best[0], best[1])

if __name__ == "__main__":
    solve()
```すべての回転有効性情報がそこにエンコードされているため、解決策はブラケット文字列をプレフィックス バランスに変換することから始まります。 有効な回転のベースライン数を、プレフィックスが最小値に達する位置の数として計算します。 

スワップ評価は、構造的に意味のある候補に限定されます。 プレフィックス合計の深さプロファイルに影響を与えることができるのは、最小レベルを超える '(' または最小境界に正確にある ')' だけである位置のみが考慮されます。 実際の線形動作を保証するために、小さな境界付きサブセットが使用されます。 

候補ペアごとに、コードはスワップをシミュレートし、プレフィックスの最小値を再計算し、結果の美しさを測定します。 最高の改善が記録されます。

 ## 特殊なケース

 文字列に最初は有効なローテーションがない場合、プレフィックスの最小値は非常に低く、まばらに発生します。 このアルゴリズムは、最小境界に触れるポジションに焦点を当てているため、スワップ候補を引き続き正確に特定し、可能な改善が確実に検討されます。 

すべての文字が同一の場合、プレフィックス値は単調であり、交換によってバランスのとれた構造を作成することはできません。 候補セットは空になるか無効になり、アルゴリズムは安全に ID スワップを返します。 

複数の位置が同じ最小プレフィックス値を共有する場合、カウントはすでに最大化されており、非境界領域間の交換によって分布が変更されることはなく、正確性が維持されます。
