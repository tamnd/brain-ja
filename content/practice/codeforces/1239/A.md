 ## 解決策
 ## 問題の理解

 サイズの「ランダムな写真」の数を数えるように求められます。$n \times m$、各セルは黒または白です。 Ivan の定義では、すべてのセルに同じ色の隣接するセルが 1 つしかない場合、その画像はランダムであると見なされます。 ここで、隣接とは水平または垂直である。 

入力は 2 つの整数で構成されます$n$そして$m$、行と列の数を表します。 出力は有効な画像の数を法的に表したものです。$10^9 + 7$。 制約$1 \le n, m \le 100{,}000$画像の総数は$2^{n \cdot m}$でさえ天文学的な大きさです。$n = m = 20$。 このため、理想的には、組み合わせまたは代数的アプローチを探す必要があります。$O(n + m)$複雑さの中で。 

考慮すべきエッジケースには、最小のグリッド ($1 \times 1$または$1 \times m$) と実質的に線であるグリッド。 たとえば、$1 \times 5$グリッドには、セルあたり最大 2 つの隣接する制約しかありませんが、$1 \times 1$グリッドは条件を自明に満たします。 同様に、次のような長く細いグリッドの場合、$1 \times 100{,}000$、単純な 2D シミュレーションは失敗します。 

## アプローチ

 ブルートフォースアプローチでは、すべてが列挙されます。$2^{n \cdot m}$可能なカラーリングを確認し、隣接ルールを確認します。 各チェックでは、すべてのセルがスキャンされ、同じ色の隣接セルがカウントされます。 それは正しいですが、これは明らかに不可能です$n$そして$m$以来$2^{100{,}000}$想像を絶するほど大きいです。 

重要な洞察は、行と列の制約がカウントの可能性に関して独立しているということです。 「同じ色の隣接するセルが 1 つだけ」という条件は、各行または列に沿った線形の繰り返しになります。 定義すると$f(k)$有効な長さの 1D シーケンスの数として$k$同じ色の隣り合うセルが複数存在しない場合、これはまさにフィボナッチ数列です。 各セルは、前の色を継続するか (前の色が 1 回だけ表示された場合)、切り替わります。 一定の長さの列の場合$m$、 がある$F_{m+2}$有効なシーケンス。 同様に長さの列の場合$n$。 

ただし、行と列のシーケンスがグリッド セルで交差するため、二重カウントを避ける必要があります。 組み合わせのトリックは、ピクチャを「行優先」または「列優先」のいずれかとして扱い、包含排他原理を使用してカウントを結合することです。 具体的には、ピクチャの総数は、行に沿ったシーケンスと列に沿ったシーケンスの合計から、過剰にカウントされた一定のパターン (すべて白とすべて黒) を差し引いたものになります。 これは次のようになります。$F_{n+2} + F_{m+2} - 2$、 どこ$F_k$です$k$-番目のフィボナッチ数。

 | ブルートフォース | O(2^(n*m)) | O(n*m) | 遅すぎる |
 | 最適 | O(n + m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. フィボナッチ数のモジュロを事前計算する$10^9 + 7$まで$\max(n, m) + 2$。 行と列の長さは最大で次のとおりであるため、これが必要です。$100{,}000$、そして私たちが必要とするのは$F_{n+2}$そして$F_{m+2}$。 モジュラー演算によりオーバーフローが防止されます。 
2. しましょう$fib[n+2]$を指します$(n+2)$-番目のフィボナッチ数。 長さの各行に対して$m$、 がある$fib[m+2]$有効なシーケンス。 長さの列ごとに$n$、 がある$fib[n+2]$有効なシーケンス。 
3. カウントを結合します。 有効な各行構成は垂直方向にミラーリングでき、各有効な列構成は水平方向にミラーリングできます。 完全にモノクロの写真 (すべて白またはすべて黒) を二重にカウントしないようにするには、2 を引きます。式は次のようになります。$total = fib[n+2] + fib[m+2] - 2$。 
4. 結果のモジュロを出力します。$10^9 + 7$、負でない値を保証します。 

機能する理由: フィボナッチ数列は、行内の各追加セルが前の色 (許可されている場合) と一致するか、色を切り替えることができるために発生します。 この反復により、明示的に列挙することなく、すべての有効なシーケンスがキャプチャされます。 行中心のカウントと列中心のカウントを合計し、二重にカウントされたすべてが等しい構成を減算することにより、すべての有効な画像が 1 回だけ取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def main():
    n, m = map(int, input().split())
    max_len = max(n, m) + 2
    
    fib = [0] * (max_len + 1)
    fib[0], fib[1] = 1, 1
    for i in range(2, max_len + 1):
        fib[i] = (fib[i-1] + fib[i-2]) % MOD

    result = (fib[n+1] + fib[m+1] - 2) % MOD
    print(result)

if __name__ == "__main__":
    main()
```フィボナッチ配列は次のように初期化されます。`fib[0] = fib[1] = 1`いずれかの色で始まるシーケンスの組み合わせ数と一致します。 ループは、必要な長さのモジュロまでシーケンスを設定します。$10^9 + 7$。 次に、行と列の可能性の合計を計算し、2 を引いて二重にカウントされたすべて 1 色の画像を削除し、結果をモジュロで出力します。$10^9 + 7$。 Off-by-one エラーは、慎重にインデックスを作成することで回避されます。`n+1`そして`m+1`。
