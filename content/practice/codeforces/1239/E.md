 ## 解決策
 ## 問題の理解

 ちょうど 2 行 n 列のグリッドが与えられています。 すべてのセルには値が含まれており、これらの 2n 個の値をセル間で任意に並べ替えることができます。 最終的な配置を選択した後、タートルは左上のセルから開始し、右下のセルに到達するまで右または下にのみ移動します。 このようなすべてのパスの中から、タートルは訪問したセル値の合計を最大化するパスを選択します。 

私たちの目標は、この可能な最良のパスの合計ができるだけ小さくなるように、指定された数値を並べ替えることです。 

重要な相互作用は、パスを直接制御していないことです。 私たちはグリッドを制御していますが、収集された値を最大化するためにパスは敵対的に選択されます。 したがって、配置に関するあらゆる決定が、最適なパスが選択される内容に影響を与えます。 

n ≤ 25 という制約は十分小さいため、列の状態またはビットマスクに対する組み合わせ推論を含む解決策が実現可能です。 おおよそ 2^n までの n の指数関数はすべて許容されますが、階乗や 50 個の要素の無制限の置換を伴うものは許容されません。 

すべての値を並べ替えて行間で均等に分散することが最適であると考えるのは、単純な誤解です。 これが失敗するのは、タートルのパス構造により、行を 1 回切り替える可能性がある単調な左から右のルートを選択することが強制され、これにより、大きな値を 1 つの最適なパスに沿ってグループ化できる構造化された「カット ポイント」が作成されるためです。 

具体的な失敗例は、大きな値が交互の行に配置され、任意のパスで複数の大きな値を強制的に収集する場合です。 たとえば、大きな値が列にわたってインターリーブされている場合、パスはそれらすべてを強制的に選択する可能性があります。 

## アプローチ

 2×n グリッド内のパスの構造は単純ですが、制限があります。 (1,1) から (2,n) へのパスは、一番上の行のプレフィックス、次に列境界での 1 つの下方向への移動、そして一番下の行のサフィックスで構成されます。 同様に、パスは分割インデックス k によって完全に記述されます。行 1 で右に進み、列 1 から k まで進み、次に下に進み、次に行 2 で右に進み、列 k から n まで進みます。 

固定配置の場合、最良のパスは、上部のプレフィックスと下部のサフィックスの合計を最大化する k を選択します。 これは、すべてのカット ポイントで関数を最大化することと同じです。 

最大の困難は、値を再配置した後、その最大カット値を最小限に抑えたいことです。 したがって、考えられるすべてのカット位置で「左上 + 右下」の合計が小さくなるように 2 つの行を設計しています。 

ブルートフォースアプローチでは、位置に番号を割り当て、配置のすべての順列を評価します。 それは50です！ 最悪の場合、それは完全に不可能です。 上の行と下の行を独立して選択しようとしても、組み合わせが爆発的に増えます。 

重要な洞察は、列ごとの構造の観点から考えることです。 各列に 2 つの値を配置します。1 つは上の行に、もう 1 つは下の行にあります。 タートルの最適パス値は、上の行のプレフィックスの合計と下の行のサフィックスの合計を使用して表現できます。 これは、問題が 2D の意味での絶対位置ではなく、列ごとのペアの順序にのみ依存していることを示唆しています。 

分割を検討するときに、選択した上部の接頭辞と下部の接尾辞の合計がすべての分割の最大値で最小になるように、列に番号を割り当てたいと考えています。 これは、貪欲なペアリング戦略につながります。つまり、すべての数値を並べ替え、制御された交互構造で大きい値と小さい値をペアにすることで、分割によって同時に多くの大きな値が蓄積されないようにします。 

すべての 2n 値を並べ替えるという、建設的な最適解が得られます。 次に、上の行が残りの最小値と最大値を交互に受け取り、下の行が相補的な割り当てを受け取るようにそれらを割り当てます。 これにより、どのカットでも、上部のプレフィックスと下部のサフィックスの値のセットが同時に極端に集中することがなくなります。

これをより正確に確認する方法は、値をペアにして (最小値と最大値、2 番目に小さい値と 2 番目に大きい値など)、各ペアを列全体に分散して、1 つの要素が一番上の行に、もう 1 つが一番下の行に配置され、インデックスによって一貫して配置されるようにすることです。 これにより、すべてのプレフィックスとサフィックスの境界のバランスがとれます。

 ## アルゴリズムのチュートリアル

 1. すべての 2n 値を 1 つのリストに収集し、非降順で並べ替えます。 並べ替えにより、極端な値を対称的に制御できるグローバルな順序が作成されます。 
2. 最小値と最大値、2 番目に小さい値と 2 番目に大きい値などをペアにします。 各ペアは「バランスのとれたユニット」を表し、1 つの高い値が常に 1 つの低い値と結合されます。 
3. n 列を作成し、各ペアを 1 つの列に割り当てます。 各ペア（低値、高値）について、どちらが上に行くのか、どちらが下に行くのかを決定します。 すべての大きな値が同じ行に配置されるのを避けるために、この割り当てを交互に行います。 
4. 列の半分について、各ペアの最初の要素を上の行に、2 番目の要素を下の行に割り当て、残りの半分を交互に配置します。 これにより、すべての大きな値の接頭辞の位置合わせが防止されます。 
5. 2 行を出力します。 

この構造が機能する理由は、すべてのパスが単一の分割インデックスによって決定されるためです。 このような分割では、タートルは上の行の値のプレフィックスと下の行の値のサフィックスを収集します。 このペアリングにより、どの分割においても、分割の前後で大きな値の寄与が常に小さな値によって相殺され、集中が防止されます。 

### なぜ効果があるのか

 固定グリッドのパス コストはカット インデックス k のみに依存し、top[1..k] とbottom[k..n] の合計に等しくなります。 この構造により、k ごとに、これら 2 つのセグメントに寄与する要素が対の極値から得られることが保証されます。 すべての大きな値が小さな値と照合され、割り当てによりすべての可能なカットの両側にペアが分散されるため、どのカットも両方の寄与セグメントで同時にあまりにも多くの大きな値を分離することはできません。 これにより、最大パス合計にグローバルな上限が強制され、すべての順列間で構築が最適化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a1 = list(map(int, input().split()))
    a2 = list(map(int, input().split()))
    
    arr = a1 + a2
    arr.sort()
    
    top = [0] * n
    bot = [0] * n
    
    l, r = 0, 2 * n - 1
    
    for i in range(n):
        if i % 2 == 0:
            top[i] = arr[l]
            bot[i] = arr[r]
            l += 1
            r -= 1
        else:
            top[i] = arr[r]
            bot[i] = arr[l]
            l += 1
            r -= 1
    
    print(*top)
    print(*bot)

if __name__ == "__main__":
    solve()
```最終的な配置では初期位置が無視されるため、実装は両方の行を平坦化することから始まります。 選別は両極端の間にペア構造を生み出すため、不可欠です。 

2 つのポインターは、未使用の最小値と最大値を保持します。 各列で、ソートされた配列の両端を消費し、それらをペアとして配置します。 代入方向を交互にすると、大きな値が隣接する列にわたって同じ行を常に占有することがなくなり、不適切な分割が発生する可能性があります。 

微妙な点は、交互に配置する必要があるということです。 常に同じ行に大きな値を入れると、ブロックの直後のカットで大きな値が集まりすぎてしまいます。 

## 実用的な例

 小さなケースを考えてみましょう。 

入力:```
n = 2
a1 = [1, 4]
a2 = [2, 3]
```ソートされた配列は [1,2,3,4] です。 

2 つのポインターを使用してペアを形成します。 

| 私 | l | r | トップ[i] | ボット[i] | 残り |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 3 | 1 | 4 | [2,3] |
 | 1 | 1 | 2 | 3 | 2 | [] |

 出力：```
1 3
4 2
```カット k=1 の場合、上部のプレフィックスは [1]、下部のサフィックスは [2]、合計 = 3。k=2 の場合、上部のプレフィックスは [1,3]、下部のサフィックスは []、合計 = 4。k を超える最大値は、他の配置と比較して最小化されます。 

次に、対称の場合を考えてみましょう。 

入力:```
n = 3
a1 = [10, 20, 30]
a2 = [1, 2, 3]
```ソートされた配列は [1,2,3,10,20,30] です。 

| 私 | l | r | トップ[i] | ボット[i] |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 5 | 1 | 30 |
 | 1 | 1 | 4 | 20 | 2 |
 | 2 | 2 | 3 | 10 | 3 |

 出力：```
1 20 10
30 2 3
```これは、大きな値が行と列にまたがって分離され、カットで複数の大きな値が同時に収集されるのを防ぐ方法を示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a1 = list(map(int, input().split()))
    a2 = list(map(int, input().split()))
    
    arr = a1 + a2
    arr.sort()
    
    top = [0] * n
    bot = [0] * n
    
    l, r = 0, 2 * n - 1
    
    for i in range(n):
        if i % 2 == 0:
            top[i] = arr[l]
            bot[i] = arr[r]
            l += 1
            r -= 1
        else:
            top[i] = arr[r]
            bot[i] = arr[l]
            l += 1
            r -= 1
    
    return "\n".join([" ".join(map(str, top)), " ".join(map(str, bot))]) + "\n"

# provided sample
assert run("2\n1 4\n2 3\n") == "1 3\n4 2\n"

# custom cases
assert run("1\n5\n1\n") == "1\n5\n", "min case"
assert run("2\n0 0\n0 0\n") in ["0 0\n0 0\n"], "all equal"
assert run("3\n1 2 3\n4 5 6\n") is not None, "basic structure"
assert run("4\n1 100 2 99\n3 98 4 97\n") is not None, "boundary extremes"

 ## 特殊なケース

 n=1 の最小ケースは制約によって許可されませんが、n=2 ではすでにコア構造が公開されています。 入力の場合:```
1 100
2 99
```ソートすると [1,2,99,100] が得られます。 このアルゴリズムは、1 が 100 の反対側、2 が 99 の反対側になるように、極端な値をペアにします。同じ行に大きな値をクラスタリングしようとすると、カットで 100 と 99 の両方が一緒にキャプチャされ、最大パス合計が増加します。 

この入力に対して、構築により次の結果が得られます。```
1 99
100 2
```列 1 の後のカットでは、上部のプレフィックス 1 と下部のサフィックス 2 が与えられ、単一のアクセス可能なパスに大きな値をスタックする配置と比較して、寄与が小さく抑えられます。 

このアルゴリズムは、すべての大きな値が小さな値とペアになって行に分割されることを保証することでこれを処理します。そのため、小さな補正値へのアクセスを犠牲にすることなく、単一のパスで複数の大きな値を収集することはできません。
