 ## 解決策
 ## 問題の理解

 すべてのテストケースに対して、裁判官は有理数を選択しました

 [
 x=\frac pq、
 \qquad 1\le p,q\le 10^9.
 】

 (x) を直接求めることはできません。 代わりに、素数 (m>10^9) の場合、次を満たす剰余 (y) を求めます。 

[
 y\equiv p q^{-1}\pmod m.
 】

 同様に、

 [
 p\equiv yq\pmod m.
 】

 目標は、同じ有理数を記述する有効なペア (p,q) を復元することです。 (1/2)、(2/4)、および (500000004/1000000008) は同じ有理数を表し、プロトコルはその値を表す範囲内の任意のペアを受け入れるため、このペアは最初に選択された正確なペアである必要はありません。 公式サンプルでは、​​(1/2) が (2/4) として応答されることで、これを明示的に示しています。 

(10) クエリの制限は、数理論的な再構築には十分な量ですが、多くのモジュライを試したり、可能な分母を検索するには小さすぎます。 (10^5) 個のテスト ケースが存在する可能性があるため、ケースごとに (O(10^9)) 個の演算アルゴリズムがあっても、最悪の場合は (10^{14}) 個の演算を意味します。 目的のソリューションでは、テスト ケースごとに 2 つのクエリのみを使用し、対数のユークリッド アルゴリズム ステップを実行します。 

この問題を考えるのに最も役立つ方法は、モジュール式の答えによって未知の分子と分母の間の線形合同が得られるということです。 (10^9) 付近の 1 つの法は、その合同を一意にするほど大きくありませんが、許容される 2 つの素数の積は (10^{24}) 付近になる可能性があります。 これは、分子と分母が (10^9) で囲まれた 2 つの異なる分数を区別するために必要なスケールである (2\cdot10^{18}) よりもはるかに大きくなります。 

誤った解決策につながりやすい 3 つの特殊なケースがあります。 

まず、1 つの係数だけでは十分ではありません。 (m=1000000007) を取得し、応答が (500000004) であると仮定します。 (2\cdot500000004\equiv1\pmod m) であるため、分数 (1/2) はこの剰余を生成します。 しかし、整数部分 (500000004/1) はまったく同じ剰余を生成します。 分子と分母の両方が範囲を満たしているため、この法だけを使用した解ではどの有理数が選択されたかを知ることができません。 2 つのモジュライにより、この曖昧さが解消されます。 

第二に、隠れたペアを削減する必要がありません。 たとえば、隠れた表現 (1000000000/1000000000) は単なる有理数 (1) です。 元の分子と分母を正確に復元することを要求する再構成アルゴリズムは、裁判官が求めていない問題を解決することになります。 正解は (1/1) です。 

第三に、合理的な再構築から回復されたペアは減少すると予想される必要があります。 非表示の値が (2/4) であるとします。 モジュラー方程式は有理値 (1/2) を記述しますが、ユークリッド再構成では当然 (2/4) ではなく (1/2) が見つかります。 両方のペアが同じ値を表すため、これは有効です。 

## アプローチ

 直接的なアプローチでは、1 つの素数 (m) をクエリし、(1) から (10^9) までの可能な分母 (q) をすべて試します。 それぞれの (q) について、次のように計算します。 

[
 p=(yq\bmod m)
 】

 (1\le p\le10^9) かどうかを確認します。 真の分母はこのテストに合格する必要があるため、有効なペアを受け入れればメソッドは正しいことになります。 

問題は、(10^9) 個の可能な分母です。 (10^5) 個のテスト ケースでは、最悪のケースは (10^{14}) 個のモジュラー乗算とモジュラー約分に達します。 1 つのテスト ケースでも、6 秒の制限にはすでに大きすぎます。 

重要な観察は、2 つのモジュラー答えを 2 つの素数の積を法とする 1 つの答えに組み合わせることができるということです。 これはまさに中国の剰余定理です。 剰余を結合すると、次のような整数 (r) がわかります。 

[
 r\equiv pq^{-1}\pmod M、
 】

 どこで

 [
 M=m_1m_2。 
】

 同様に、

 [
 p\equiv rq\pmod M.
 】

 2 つの固定素数

 [
 m_1=999999999989,\qquad
 m_2=1000000000039
 】

 両方とも必要な範囲内の有効な素数です。 これらは、標準の素数表では (10^{12}) 付近の連続する素数としてリストされます。 彼らの積はおおよそ (10^{24}) なので、

 [
 M>2\cdot10^{18}。 
】

ここで、2 つの異なる有界分数 (p_1/q_1) と (p_2/q_2) が同じ剰余を生成したと仮定します。 それから

 [
 p_1q_2\equiv p_2q_1\pmod M、
 】

 だから (M) は割る

 [
 p_1q_2-p_2q_1。 
】

 ただし、各分子と分母は最大 (10^9) なので、

 [
 |p_1q_2-p_2q_1|\le2\cdot10^{18}<M.
 】

 その間隔内の (M) の倍数はゼロのみです。 したがって、

 [
 p_1q_2=p_2q_1、
 】

 これは、2 つの分数が等しいことを意味します。 

したがって、CRT の後は、この問題は標準的な合理的再構成問題になります。 合理的再構成は、拡張ユークリッド アルゴリズムおよび連分数と密接に関係しています。 

拡張ユークリッド アルゴリズムは、次の形式の残りの部分を生成します。 

[
 r_i=s_iM+t_ir。 
】

 したがって、すべての中間ペアは次の条件を満たします。 

[
 r_i\equiv t_ir\pmod M.
 】

 剰余が最初に最大 (10^9) になると、大係数条件により、対応する係数 (t_i) も必要な範囲内にあり、望ましい分子と分母が得られることが保証されます。 これは、合理的な再構成に対する古典的なユークリッド アルゴリズムのアプローチです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースごとの (O(10^9)) | (O(1)) | 遅すぎる |
 | 最適 | テスト ケースごとの (O(\log M)) の算術ステップ | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 剰余モジュロ (m_1=999999999989) を求め、次に剰余モジュロ (m_2=1000000000039) を求めます。 どちらの数値も素数であり、厳密に (10^9) と (10^{12}) の間にあるため、どちらのクエリも有効です。 これほど大きな素数を使用すると、その積は (10^{18}) の外積限界を大幅に超えます。 
2. 2 つの剰余を中国剰余定理と結合します。 答えを (y_1) と (y_2) とします。 書く

 [
 r=y_1+m_1k。 
】

 必要です

 [
 y_1+m_1k\equiv y_2\pmod {m_2},
 】

 それで

 [
 k\equiv(y_2-y_1)m_1^{-1}\pmod {m_2}。 
】

 最小の非負値 (k) を選択すると、一意の剰余 (r) のモジュロが得られます。 

[
 M=m_1m_2。 
】

 CRT ステップは、2 つの小さなモジュラー方程式を、(10^{24}) 付近の係数を持つ 1 つの方程式に変換します。 

1. (r) の係数も追跡しながら、(M) と (r) に対して拡張ユークリッド アルゴリズムを実行します。 初期化する

 [
 R_0=M、\quad R_1=r、
 】

 そして

 [
 T_0=0、\quad T_1=1。 
】

 不変式は

 [
 R_i=S_iM+T_ir。 
】

 その結果、

 [
 R_i\equiv T_ir\pmod M.
 】

 係数(T_i)は、分子候補(R_i)に対応する分母候補である。 

1. 通常のユークリッド除算を繰り返し実行する

 [
 R_{i-1}=a_iR_i+R_{i+1}、
 】

 そして更新します

 [
 T_{i+1}=T_{i-1}-a_iT_i。 
】

 現在の余りが最大 (10^9) になった時点で停止します。 剰余は通常のユークリッド アルゴリズムとまったく同じように減少するため、(O(\log M)) 回の反復のみが必要です。 

1. 分母が正になるように符号を正規化します。 裁判官によって隠された肯定的な合理性の場合、成功した再構成は正の分子と分母を持ちます。 
2. 結果の分子と分母を出力します。 隠れたペアが縮小されなかった場合、ユークリッド アルゴリズムは同じ有理数の縮小表現を与えますが、これは依然として有効な答えです。 

### なぜ効果があるのか

 中心的な不変式は

 [
 R_i=S_iM+T_ir、
 】

 したがって、すべてのユークリッド状態は、モジュラー値が (r) である有理候補 (R_i/T_i) を表します。 実際の換算された隠れ分数 (p/q) は次の条件を満たします。 

[
 p\equiv rq\pmod M.
 】

 (M>2\cdot10^{18}) であるため、分子と分母が最大 (10^9) である 2 つの異なる有理値は同じ合同を満たすことができません。 古典的な合理的再構築では、(10^9) 境界を越える最初のユークリッド剰余がまさに有界解であると言われます。 

一意性の議論は特に単純です。 2 つの候補が存在する場合、それらの外積は (M) の倍数になりますが、その絶対値は最大でも (2\cdot10^{18}) となり、厳密には (M) より小さくなります。 したがって、外積はゼロでなければならないため、両方の候補は同じ有理数を表します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

M1 = 999999999989
M2 = 1000000000039
LIMIT = 10**9

def crt(a1, a2):
    # x = a1 (mod M1)
    # x = a2 (mod M2)
    inv = pow(M1, -1, M2)
    k = ((a2 - a1) * inv) % M2
    return a1 + M1 * k

def reconstruct(r, mod):
    # Extended Euclidean algorithm.
    #
    # rem = s * mod + t * r
    # so rem == t * r (mod mod).
    old_rem, rem = mod, r
    old_t, t = 0, 1

    while rem > LIMIT:
        q = old_rem // rem

        old_rem, rem = rem, old_rem - q * rem
        old_t, t = t, old_t - q * t

    numerator = rem
    denominator = t

    if denominator < 0:
        numerator = -numerator
        denominator = -denominator

    # The original fraction may not have been reduced.
    # The Euclidean reconstruction is normally already reduced,
    # but reducing here also makes the returned representation explicit.
    g = __import__("math").gcd(numerator, denominator)
    numerator //= g
    denominator //= g

    return numerator, denominator

def ask(m):
    print("?", m, flush=True)
    return int(input())

def main():
    t = int(input())

    for _ in range(t):
        y1 = ask(M1)
        y2 = ask(M2)

        r = crt(y1, y2)
        p, q = reconstruct(r, M1 * M2)

        print("!", p, q, flush=True)

if __name__ == "__main__":
    main()
```上部の 2 つの定数は固定された正当な素数であるため、相互作用中に素数性テストは行われません。 これらの素数の積は (10^{24}) 程度で、必要なしきい値 (2\cdot10^{18}) を余裕で超えています。 

の`crt`関数は方程式を実装します

 [
 r=y_1+m_1k。 
】

 2 番目の合同式により (k) が決定され、`pow(M1, -1, M2)`逆モジュラーを計算します。 Python の 3 つの引数`pow`Python 3.8 以降では、逆モジュラーの負の指数がサポートされています。 

の`reconstruct`関数は、(r) の剰余とその係数のみを保存します。 不変式が確立された後は係数の係数は不要になるため、実装が小さく保たれます。 

ループ条件は`rem > LIMIT`、 ない`rem >= LIMIT`。 (10^9) に等しい剰余はすでに有効であり、受け入れる必要があります。 これは間違いやすい境界条件です。 

Python の整数は任意精度であるため、(10^{24}) 付近の CRT 積はオーバーフローしません。 符号付き 64 ビット整数を使用する C++ 実装では、この積を符号付き整数に格納することも避ける必要があります。`long long`なぜなら、(10^{24}) はその範囲をはるかに超えているからです。 Python にはこの問題はありません。 

最後の gcd リダクションは、元のペア (p,q) が互いに素である必要がないという事実を処理します。 たとえば、非表示の値 (2/4) は (1/2) として再構築されますが、これは有効な答えです。 

すべてのクエリはすぐにフラッシュされます。 それなし`flush=True`、対話型ソリューションは、出力バッファーに残っているクエリを裁判官が受信できない可能性があるため、無限に待機する可能性があります。 

## 実用的な例

 提供されたサンプルでは、テスト ケースごとに 1 つのクエリを使用し、対話プロトコルを示します。 (m=1000000007) の場合、応答 (500000004) は (1/2) に相当し、裁判官は応答 (2/4) を受け入れます。 ここで説明する最適解では、単一の係数では十分な情報が得られないため、代わりに 2 つのより大きな素数を求めます。 

最初の再構成トレースでは、解からの 2 つの素数を使用して、同じ有理値 (x=1/2) を考慮します。 残留物は、

 [
 y_1=\frac{m_1+1}{2}=499999999995
 】

 そして

 [
 y_2=\frac{m_2+1}{2}=500000000020。 
】

 CRT の結果は、(1/2) モジュロ (M=m_1m_2) の剰余です。つまり、

 [
 r=\frac{M+1}{2}。 
】

 | ユークリッド状態 | 残り | (r) の係数 | 意味 |
 | --- | --- | --- | --- |
 | イニシャル | (男) | (0) | (M=1\cdot M+0\cdot r) |
 | イニシャル | ((M+1)/2) | (1) | (r=0\cdot M+1\cdot r) |
 | 後 (q=1) | ((M-1)/2) | (-1) | (R=-M+r) |
 | 後 (q=1) | (1) | (2) | (1=2r-M) |

 最後の行には剰余 (1) と係数 (2) があるため、再構成された分数は (1/2) になります。 (2r\equiv1\pmod M) であるため、不変式はモジュラー関係を直接検証します。 

2 番目のトレースには、(x=2/3) を使用します。 (M\equiv2\pmod3) なので、(2/3) 剰余 (M) は次のようになります。 

[
 r=\frac{M+2}{3}。 
】

 ユークリッド数列は特に短くなります。 

| ユークリッド状態 | 残り | (r) の係数 | 意味 |
 | --- | --- | --- | --- |
 | イニシャル | (男) | (0) | (M=1\cdot M+0\cdot r) |
 | イニシャル | ((M+2)/3) | (1) | (r=0\cdot M+1\cdot r) |
 | 後 (q=2) | ((M-4)/3) | (-2) | (R=M-2r) |
 | 後 (q=1) | (2) | (3) | (2=3r-M) |

 (10^9) より下の最初の剰余は (2) で、係数は (3) です。 したがって、結果は (2/3) になります。 これは、ユークリッド係数を追跡するだけで十分である理由と、可能な分母を検索する必要がない理由を示しています。 

公式サンプルには (1/1)、(1/2)、(2/1) のケースも含まれており、(1/2) に対しては (2/4) のような非縮約解答が有効であることを具体的に指摘しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(t\log M)) 算術ステップ | テスト ケースごとに 2 つの CRT 操作と 1 つの拡張ユークリッド アルゴリズム |
 | スペース | (O(1)) | 一定数の整数のみが格納されます。 

ここで (M=m_1m_2) は約 (10^{24}) であるため、そのビット長は約 (80) にすぎません。 したがって、ユークリッド アルゴリズムでは、テスト ケースごとに数十回の反復しか必要としません。 (10^5) 個のケースでは、これは依然として実用的ですが、総当たりアプローチでは最大 (10^{14}) 個の分母チェックが必要になります。 

インタラクション自体は、テスト ケースごとに 2 つのクエリを使用しますが、制限の 10 を大幅に下回ります。 

## テストケース

 元のタスクは対話型であるため、そのサンプル入力は通常の完全な入力ファイルではありません。 入力として表示されるセリフは非表示のジャッジからの応答であるため、オフラインでは`run()`この関数は文字通りサンプルを再生できません。 送信されたロジックを単体テストする便利な方法は、既知の有理値から 2 つのモジュール応答を生成することによって純粋な再構成ルーチンをテストすることです。```python
import sys
import io
from math import gcd

M1 = 999999999989
M2 = 1000000000039
LIMIT = 10**9

def crt(a1, a2):
    inv = pow(M1, -1, M2)
    k = ((a2 - a1) * inv) % M2
    return a1 + M1 * k

def reconstruct(r, mod):
    old_rem, rem = mod, r
    old_t, t = 0, 1

    while rem > LIMIT:
        q = old_rem // rem
        old_rem, rem = rem, old_rem - q * rem
        old_t, t = t, old_t - q * t

    if t < 0:
        rem = -rem
        t = -t

    g = gcd(rem, t)
    return rem // g, t // g

def modular_image(p, q, m):
    return (p * pow(q, -1, m)) % m

def run(inp: str) -> str:
    # Offline test harness.
    # Each line contains the hidden p and q.
    out = []

    for line in inp.strip().splitlines():
        if not line.strip():
            continue

        p, q = map(int, line.split())

        y1 = modular_image(p, q, M1)
        y2 = modular_image(p, q, M2)

        r = crt(y1, y2)
        a, b = reconstruct(r, M1 * M2)

        out.append(f"{a} {b}")

    return "\n".join(out)

# Values represented by the provided interactive sample.
assert run("1 1\n1 2\n2 1\n") == (
    "1 1\n"
    "1 2\n"
    "2 1"
), "provided sample values"

# Minimum-size numerator and denominator.
assert run("1 1\n") == "1 1", "minimum-size values"

# Maximum allowed numerator and denominator, both equal.
# The rational value is 1, so 1/1 is the canonical answer.
assert run("1000000000 1000000000\n") == "1 1", "maximum equal values"

# Numerator and denominator are both close to the upper boundary
# and are coprime.
assert run("999999999 1000000000\n") == "999999999 1000000000", (
    "upper-bound coprime fraction"
)

# Small denominator and maximum numerator.
assert run("1000000000 1\n") == "1000000000 1", (
    "maximum numerator with denominator 1"
)

print("all tests passed")

 ## 特殊なケース

 1 モジュラス衝突は、最も基本的な故障モードです。 (m=1000000007) の場合、応答 (500000004) は (1/2) によって生成されます。 

[
 2\cdot500000004=1000000008\equiv1\pmod m.
 】

 (500000004/1) によっても同じ応答が生成されます。 この係数のみを使用する解には、2 つの値を区別する数学的方法がありません。 最適解は 2 番目の独立した素数を求め、その答えを組み合わせて (10^{18}) を超える法を作成し、そのような衝突を不可能にします。 

非縮小表現も微妙なケースです。 入力値 (1000000000/1000000000) の場合、元の数値は両方とも最大許容サイズですが、有理数自体は (1) です。 モジュラー応答は、クエリされたすべての素数に対して (1) です。 有理再構築は (1/1) を返し、プロトコルは正確な隠れたペアの復元ではなく、有理値の表現を要求するため、答えは受け入れられます。 

(2/4) のような値の場合、(1/2) の場合と同じモジュラー観測が生成されます。 ユークリッド再構成により、縮小ペア (1/2) が見つかります。 両方の成分を gcd で割っても、表現される有理数値は変わらないため、結果は有効なままです。 

最後に、(10^9) に正確に等しい剰余を受け入れる必要があります。 再構築ループは次を使用します。`rem > LIMIT`、 ない`rem >= LIMIT`。 平等を大きすぎるものとして扱うと、法的な分子がスキップされ、ユークリッドのプロセスが正しい再構成を超えてしまう可能性があります。 

したがって、完全なアイデアは非常にコンパクトです。2 つの大きなプライム クエリは CRT を通じて 1 つの巨大な係数を与え、その巨大な係数はモジュールの有理回復を、拡張 Euclid によって解決される標準の有界有理再構成問題に変換します。 元の問題と独立した論説は、同じ CRT とユークリッド再構築の観点を説明しています。
