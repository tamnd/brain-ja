 ## 解決策
 ## 問題の理解

 すべてのテスト ケースについて、裁判官は密かに正の有理数 (x=p/q) を選択します。ここで、(p) と (q) は両方とも最大 (10^9) です。 (p) と (q) を直接見ることはできません。 代わりに、大きな素数 (m) を選択し、(p q^{-1}\pmod m) の値を求め、返された剰余を使用して有理数を回復できます。 答えには、同じ有理値を表す最大 (10^9) の正の分子と分母を使用できるため、分数の削減は常に許可されます。 この問題は対話型です。つまり、プログラムはクエリを出力し、フラッシュし、裁判官の応答を読み、最後に復元された部分を出力する必要があります。 

分子と分母の両方の上限 (10^9) が重要な数値制約です。 これは、境界を満たす 2 つの異なる換算分数の外積の違いが最大 (10^{18}) である可能性があることを示しています。 (10^9) よりわずかに大きい係数だけではそれらを区別するのに十分ではないため、一般に 1 つのクエリでは十分な情報を提供できません。 クエリ制限の 10 は、積が (10^{18}) よりはるかに大きい 2 つのモジュライを結合するのに十分な広さです。 テスト ケースの数は (10^5) に達する可能性があるため、各クエリ後のローカル計算は、(10^9) に比例するのではなく、係数が対数である必要があります。 テスト ケースごとに 2 つのクエリと 1 つの拡張ユークリッド計算は、簡単に十分に小さいです。 

入力部分を減らす必要がないという事実によって引き起こされる別の微妙な点があります。 非表示の値が (2/4) であるとします。 正しい数学的値は (1/2) であり、戻り値は`! 1 2`有効です。 正確な隠れペア (2,4) のみを検索する再構成アルゴリズムは、必要以上に強力な問題を解決することになり、元の表現を復元することを要求すると間違った答えが生成される可能性があります。 

2 番目のエッジ ケースは (p=q=10^9) です。 分数は正確に (1) なので、正しい応答は次のようになります。`! 1 1`必ずしもそうではありません`! 1000000000 1000000000`。 与えられた範囲を元の分子と分母を必要とするものとして扱う不注意なアルゴリズムは、同じ有理数の表現を不必要に区別することになります。 

3 番目のエッジ ケースは、モジュラー剰余が非常に大きい場合に発生します。 たとえば、(x=1/2) と奇数素数 (m) の場合、返される剰余は ((m+1)/2) であり、(m/2) に近く、(10^9) をはるかに上回ります。 したがって、戻り値自体を分子として解釈しようとすると失敗します。 分子と分母は剰余から直接読み取るのではなく、合同式 (p\equiv rq\pmod M) から再構築する必要があります。 

## アプローチ

 直接的なアプローチは、1 つの係数をクエリし、(1) から (10^9) までのすべての可能な分母 (q) を試すことです。 各 (q) について、合同式により分子候補が (p=rq\bmod m) として決定されます。 その値が (1) と (10^9) の間にある場合、有効な表現が見つかりました。 これは、隠れたペアがこれらの候補の中に含まれることが保証されているため機能しますが、最悪のケースでは 1 つのテスト ケースに対して (10^9) のモジュラー乗算が必要になります。 (10^5) 個のテスト ケース全体では (10^{14}) 回の反復になりますが、これは完全に非現実的です。 

重要な観察は、複数のモジュール形式の回答を組み合わせることができるということです。 2 つの異なる素数 (m_1、m_2) を尋ね、中国剰余定理を使用して 2 つの答えを 1 つの剰余 (r) モジュロに変換します。 

[
 M=m_1m_2。 
】

 (M>2\cdot 10^{18}) となるように 2 つの素数を選択できます。 価値観

 [
 m_1=999999999989,\qquad m_2=1000000000039
 】

 両方とも素数であり、必要なクエリ範囲を満たします。 彼らの積は約 (10^{24}) であり、必要な限界を余裕で超えています。 

ここで、この問題は標準的な合理的再構成問題になります。 私たちは知っています

 [
 r\equiv pq^{-1}\pmod M、
 】

 または同様に、

 [
 rq\equiv p\pmod M.
 】

 換算された隠れ分数は (1\le p,q\le10^9) になります。 2 つの異なる還元分数 (p_1/q_1) と (p_2/q_2) が同じ剰余を生成した場合、

 [
 p_1q_2-p_2q_1\equiv0\pmod M.
 】

 左辺の絶対値は最大でも (2\cdot10^{18}) ですが、(M) はそれより大きくなります。 したがって、差は実際にはゼロでなければならず、したがって分数は同一になります。 これはまさに、拡張ユークリッド アルゴリズムを使用して実行できる合理的再構成の背後にある一意性条件です。 

ユークリッド アルゴリズムは一連の恒等式を与えます

 [
 R_i=A_iM+B_ir。 
】

 剰余 (R_i) が最初に最大 (10^9) になったとき、対応する係数 (B_i) は、共通の符号までの再構成された分数の分母になります。 法は (N=10^9) で (2N^2) よりも大幅に大きくなっているため、ユークリッド数列のこの時点で必要な分子と分母が出現する必要があります。 

ブルートフォースアプローチと最適アプローチは次のように要約できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースごとの (O(10^9)) | (O(1)) | 遅すぎる |
 | CRT + 合理的な再構成 | (O(\log M)) テスト ケースごと | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 隠れ剰余モジュロ (m_1=999999999989) を求めます。 この数値は素数であり、厳密に (10^9) と (10^{12}) の間にあるため、正当なクエリです。 
2. 剰余モジュロ (m_2=1000000000039) を求めます。 2 つの異なる素数を使用すると、同じ有理数を記述する 2 つの合同式が得られます。 
3. 2 つの答えを中国剰余定理と組み合わせます。 応答が (r_1) と (r_2) の場合、次のように書きます。 

[
 r=r_1+m_1k。 
】

 (r\equiv r_2\pmod {m_2}) となるように (k) を選択します。 したがって、

 [
 k\equiv(r_2-r_1)m_1^{-1}\pmod {m_2}。 
】

 結果の (r) は、両方のクエリを満たす一意の剰余モジュロ (M=m_1m_2) です。 

1. (r) の係数を追跡しながら、(M) と (r) に対して拡張ユークリッド アルゴリズムを実行します。 最初に関連する 2 つのペアは次のとおりです。 

[
 (M,0),\qquad(r,1)。 
】

 すべてのユークリッド遷移は形式の同一性を保持します

 [
 R=AM+Br.
 】

1. (R\le10^9) で最初のユークリッド剰余 (R) で停止します。 有理的再構成定理は、(M>2\cdot10^{18}) であるため、この剰余とその (r) の係数により、必要な範囲内で固有の換算された分子と分母が得られると述べています。 
2. 必要に応じて、両方の符号を変更して係数を正にします。 この問題の有効な正の再構成では、最後のペアは正ですが、符号を正規化することで実装が堅牢になります。 
3. 再構成された分子と分母を最終的な答えとして出力します。 裁判官が最初に非縮小表現を選択した場合でも、再構成された分数は隠れた分数と同じ有理値になります。 

ユークリッド位相全体にわたる不変条件は、すべての現在の剰余 (R) が既知の表現 (R=AM+Br) を持つということです。 (r\equiv pq^{-1}\pmod M) なので、後者の合同式に (q) を掛けると (rq\equiv p\pmod M) が得られます。 したがって、隠れたペア自体は、このユークリッド格子で表される小さな解の 1 つです。 限界 (M>2N^2) により、その小さな換算された解が一意になるため、ユークリッドが最初の十分に小さな剰余に達したとき、それが別の有効な分数になることはできません。 

## Python ソリューション

 元のタスクは対話型であるため、以下のプログラムが実際の対話型ソリューションです。 ステートメントに示されているサンプルは、通常の入力ではなく対話のトランスクリプトであるため、従来の stdin から stdout へのバッチ テストとして実行することはできません。```python
import sys
input = sys.stdin.readline

P1 = 999999999989
P2 = 1000000000039
N = 10**9

def extended_gcd(a, b):
    old_r, r = a, b
    old_s, s = 1, 0
    old_t, t = 0, 1

    while r:
        q = old_r // r
        old_r, r = r, old_r - q * r
        old_s, s = s, old_s - q * s
        old_t, t = t, old_t - q * t

    return old_r, old_s, old_t

def crt(r1, r2):
    # r = r1 + P1 * k
    # P1 * k == r2 - r1 (mod P2)
    _, inv, _ = extended_gcd(P1, P2)
    inv %= P2

    k = ((r2 - r1) % P2) * inv % P2
    return r1 + P1 * k

def rational_reconstruct(r, mod):
    # Euclidean sequence:
    # remainder = A * mod + B * r
    old_r, cur_r = mod, r
    old_b, cur_b = 0, 1

    while cur_r > N:
        q = old_r // cur_r

        old_r, cur_r = cur_r, old_r - q * cur_r
        old_b, cur_b = cur_b, old_b - q * cur_b

    numerator = cur_r
    denominator = cur_b

    if denominator < 0:
        numerator = -numerator
        denominator = -denominator

    return numerator, denominator

def ask(m):
    print("?", m, flush=True)
    ans = int(input())

    if ans == -1:
        sys.exit(0)

    return ans

def main():
    t = int(input())

    for _ in range(t):
        r1 = ask(P1)
        r2 = ask(P2)

        r = crt(r1, r2)
        mod = P1 * P2

        p, q = rational_reconstruct(r, mod)

        print("!", p, q, flush=True)

if __name__ == "__main__":
    main()
```定数はテスト ケースを処理する前に固定されます。 どちらも許可された間隔内で有効な素数であるため、素数の検索にクエリや計算を費やす必要はありません。 それらの積は (2\cdot10^{18}) より大きく、これが合理的再構築に必要な唯一のサイズ条件です。 

の`ask`関数はクエリを出力し、すぐに標準出力をフラッシュします。 インタラクティブな問題では、ジャッジは受け取っていない質問に答えることができないため、フラッシングは必須です。 の返事`-1`通常、これは対話が失敗したことを意味するため、プログラムは追加の出力を送信せずにすぐに終了します。 

の`crt`関数は直接 2 係数 CRT 式に従います。 拡張ユークリッド アルゴリズムは、(P_1) を法 (P_2) として逆算し、最終剰余を構築する前に乗算を法 (P_2) で縮小します。 Python の整数には任意の精度があり、(P_1P_2) が約 (10^{24}) であり、符号付き 64 ビットの範囲をはるかに超えているため便利です。 

の`rational_reconstruct`関数は、クエリされた剰余の係数のみを追跡します。 弾性率の係数を保持する必要はありません。 いつ`cur_r`最初は最大 (10^9) になり、対応する係数が分母となり、剰余が分子となります。 停止条件は次を使用します`>`それよりも`>=`なぜなら、(10^9) に等しい剰余はすでに有効な分子であり、受け入れられる必要があるからです。 

このアルゴリズムでは、結合係数を法とする元の分母で除算することはありません。 分母は最大でも (10^9) ですが、クエリされた素数は両方とも (10^9) より大きいため、各素数を法として自動的に反転されます。 これにより、有理数のモジュラー表現が明確に定義されます。 

## 実用的な例

## テストケース

 これは対話型であるため、リテラルのサンプル入力を通常の文字列としてソリューションに供給することはできません。 次のオフライン ハーネスは、既知の部分から裁判官の 2 つのモジュール式応答をシミュレートすることによって、決定論的再構成コアをテストします。 提供されたサンプルからの 3 つの画分が最初のテストとして含まれています。```python
import sys
import io
from math import gcd

P1 = 999999999989
P2 = 1000000000039
N = 10**9

def extended_gcd(a, b):
    old_r, r = a, b
    old_s, s = 1, 0
    old_t, t = 0, 1

    while r:
        q = old_r // r
        old_r, r = r, old_r - q * r
        old_s, s = s, old_s - q * s
        old_t, t = t, old_t - q * t

    return old_r, old_s, old_t

def crt(r1, r2):
    _, inv, _ = extended_gcd(P1, P2)
    inv %= P2
    k = ((r2 - r1) % P2) * inv % P2
    return r1 + P1 * k

def rational_reconstruct(r, mod):
    old_r, cur_r = mod, r
    old_b, cur_b = 0, 1

    while cur_r > N:
        q = old_r // cur_r
        old_r, cur_r = cur_r, old_r - q * cur_r
        old_b, cur_b = cur_b, old_b - q * cur_b

    p, q = cur_r, cur_b

    if q < 0:
        p = -p
        q = -q

    return p, q

def solve_fraction(p, q):
    # Simulate the two interactive replies.
    r1 = (p * pow(q, -1, P1)) % P1
    r2 = (p * pow(q, -1, P2)) % P2

    r = crt(r1, r2)
    return rational_reconstruct(r, P1 * P2)

def run(inp: str) -> str:
    out = []

    for line in inp.strip().splitlines():
        if not line.strip():
            continue

        p, q = map(int, line.split())
        a, b = solve_fraction(p, q)
        out.append(f"{a} {b}")

    return "\n".join(out) + "\n"

""", "provided sample values"

""", "non-reduced fraction"

 CRT は 2 つの観測値を (1/2) の剰余に結合し、合理的な再構築により結果が返されます。`1 2`。 必要な出力は元のエンコードではなく有理値であるため、これは正しいです。 

最大値が等しい場合については、次のように考えます。`1000000000 1000000000`。 両方のモジュラー応答は (1) であるため、CRT は (r=1) を与えます。 最初のユークリッド剰余は係数 (1) ですでに (10^9) 限界を満たしており、次のようになります。`1 1`。 隠蔽された表現を保存しようとした解決策は、不必要に還元されていないペアを返しますが、ジャッジは値の有効な表現を受け入れます。 

(x=1/2) の場合、分子と分母は両方とも最大 (10^9) ですが、モジュラー応答は約 (5\cdot10^{11}) になります。 ユークリッド数列は最終的に係数 (2) の剰余 (1) に達します。 これは、返されたモジュラー値自体が分子でなければならないと想定するというよくある間違いを捕らえます。 

上限分数の場合`1000000000 999999999`、分子はちょうど許容限度内にあります。 結合係数は、関連するすべての外積よりもはるかに大きいため、境界での等価性について特別な処理を必要とせずに、有理再構成定理が適用されます。 アルゴリズムは同じ縮小ペアを返し、停止条件が (10^9) より厳密に小さい剰余だけでなく、(10^9) に等しい剰余を受け入れる必要があることを確認します。 

本質的なアイデアは、使用可能な 10 個のクエリのうち 2 個を使用して (10^{24}) 付近の法を計算し、交互作用について考えるのをやめて純粋に算術問題を解決することです。 CRT は 1 つの合同モジュロに十分大きなモジュラスを与え、拡張ユークリッド アルゴリズムはその合同を固有の小さな有理数に戻します。
