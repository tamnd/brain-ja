 ## 解決策
 ## 問題の理解

 正の有理数 (x=p/q) を回復する必要があります。ここで、(p) と (q) は両方とも最大 (10^9) です。 (p) と (q) を直接見ることはできません。 代わりに、選択された素数係数 (m) に対して、裁判官は以下を満たす範囲 (0\le r<m) の整数 (r) を与えます。 

[
 r\equiv p q^{-1}\pmod m.
 】

 (m) が素数であり、(q<m) であるため、逆関数 (q^{-1}) が存在します。 同様に、クエリによって返される情報は、まさにステートメントです。 

[
 rq\equiv p\pmod m.
 】

 このタスクは対話型であるため、すべてのテスト ケースについて、プログラムはクエリを出力し、審査員の回答を読み取り、最終的に隠れた有理数を表すペア (p,q) を出力します。 ペアを減らす必要はありません。 たとえば、(1/2)、(2/4)、(500000000/1000000000) はすべて同じ値を表し、いずれか 1 つが受け入れられます。 公式声明では、最大 (10^5) 個のテスト ケースと、ケースごとに最大 10 個のクエリが指定されています。 

境界 (p,q\le10^9) は中心的な構造制約です。 可能な分母を直接検索するには、1 つのテスト ケースに対して最大 (10^9) 回の反復がすでに必要です。 (10^5) の場合、それは (10^{14}) 個のモジュラー計算となり、6 秒の制限がサポートできる範囲をはるかに超えます。 対数時間数理論を使用して、モジュラー情報を正確な合理的な再構成に変換する必要があります。 

独自性と再構築の間には微妙な違いもあります。 何らかの方法で法 (M>10^{18}) を法とする値がわかっている場合、有理数は分子と分母が最大 (10^9) であるすべての分数の中ですでに一意になります。 実際、(p_1/q_1) と (p_2/q_2) の両方が同じ剰余を生成した場合、

 [
 p_1q_2\equiv p_2q_1\pmod M.
 】

 したがって、(M) は (p_1q_2-p_2q_1) を除算します。 その差の絶対値は最大でも (10^{18}) であるため、法が厳密に (10^{18}) よりも大きい場合、差は強制的にゼロになります。 この独自性の観察は、問題に対する標準的な解決策の基礎でもあります。 

不注意な実装によって誤って処理される可能性のあるエッジケースがいくつかあります。 1 つ目は非還元分数です。 たとえば、非表示の値は (2/4) である可能性があります。 正しい出力は`1 2`、サンプルは選択しますが、`2 4`。 有理値ではなく正確な元のペアを回復することを要求する実装では、完全に有効な答えが拒否されます。 

2 番目は (2/1) などの整数です。 ここでモジュラー剰余は単純に (2) であるため、正しい答えは次のようになります。`2 1`。 自明ではない連分数の分母のみを検索する再構成ルーチンは、誤って最初の剰余自体をスキップし、この場合に失敗する可能性があります。 

3 番目は値 (1/1) です。 クエリされたすべてのモジュラスに対して、返される剰余は (1) です。 剰余が大きいと仮定する不注意な CRT またはユークリッドの実装は、この可能な最小の有理数を誤って処理する可能性があります。 正しい出力は次のとおりです`1 1`。 

4 番目は数値境界の分数です。 たとえば、(1000000000/999999999) は、分子と分母が両方とも上限に近い場合でも有効です。 関連する整数が CRT 後に (10^{24}) 付近になる可能性があるため、浮動小数点の再構築はここでは安全ではありません。 ソリューションでは、全体を通して正確な整数演算を使用する必要があります。 

## アプローチ

 ブルートフォースアプローチは合同から始まる

 [
 rq\equiv p\pmod M.
 】

 (1) から (10^9) までのすべての可能な (q) について、次のように計算できます。 

[
 p=(rq)\bmod M
 】

 (1\le p\le10^9) かどうかを確認します。 非表示のペアはこのテストに合格することが保証されているため、最初の有効なペアが正しい答えを返します。 これは概念的に単純で完全に正しいものです。クエリは、(rq\bmod M) が真の分母に等しくなければならないものを正確に示すからです。 

問題は動作回数です。 最悪の場合、1 つのテスト ケースでは (10^9) の剰余乗算が必要になります。 (10^5) 個のテスト ケース全体で、これは (10^{14}) 回の反復に達する可能性があります。 すべての可能な分母を個別にチェックできるため、総当り攻撃は機能しますが、分母の範囲が大きすぎるため失敗します。 

重要な観察は、係数を選択できるということです。 (10^9) よりわずかに大きい法を使用する代わりに、(10^{12}) に非常に近い 2 つの固定素数を選択します。 

[
 m_1=999999999989,\qquad
 m_2=999999999997。 
】

 どちらもクエリ制限を満たしており、素数です。 

2 つのクエリで十分です。 中国剰余定理により、2 つの剰余を 1 つの剰余 (r) を法として結合できます。 

[
 M=m_1m_2。 
】

 この係数はおよそ (10^{24}) であるため、特に

 [
 M>2\cdot10^{18}。 
】

 このより強い境界により、標準的な連分数有理再構成を使用できるようになります。 

から

 [
 rq\equiv p\pmod M
 】

 次のような整数 (k) が存在します。 

[
 rq-kM=p。 
】

 (Mq) で割る:

 [
 \frac rM-\frac{k}{q}=\frac{p}{Mq}。 
】

 (p,q\le10^9) と (M>2\cdot10^{18}) なので、

 [
 \left|\frac rM-\frac{k}{q}\right|
 =\frac{p}{Mq}
 <\frac{1}{2q^2}。 
】

 古典的な連分数の性質は、(r/M) にこれほど近い有理近似がその収束の 1 つである必要があることを示しています。 したがって、隠れ分母 (q) は、(M) と (r) に適用されるユークリッド アルゴリズム中に自然に表示されます。 連分数接続は、この正確な有理再構成問題を解決する標準的な方法です。 

これにより、(10^9) 個の可能な分母に対する検索が (O(\log M)) ユークリッド アルゴリズムに変わります。 (M) には 10 進数が約 24 桁しかないため、テスト ケースあたりのユークリッド反復は数十回しかありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースごとの (O(10^9)) | (O(1)) | 遅すぎる |
 | CRT + 連分数 | (O(\log M)) テスト ケースごと | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初の固定素数 (m_1=999999999989) をクエリし、返された剰余 (r_1) を呼び出します。 (m_1) は素数であり、厳密に (10^9) と (10^{12}) の間にあるため、クエリは正当です。 
2. 2 番目の固定素数 (m_2=999999999997) をクエリし、(r_2) を取得します。 2 つの法は別個の素数であるため互いに素であり、これはまさに中国の剰余定理が要求するものです。 
3. 2 つの合同式を結合します。 

[
 R\equiv r_1\pmod {m_1}、
 \qquad
 R\equiv r_2\pmod {m_2}
 】

 単一剰余 (R) モジュロ (M=m_1m_2) に変換します。 書く

 [
 R=r_1+m_1t。 
】

 2 番目の合同式に代入すると、

 [
 m_1t\equiv r_2-r_1\pmod {m_2}。 
】

 (m_1) には逆モジュロ (m_2) があるため、1 つの逆モジュロを使用して (t) を計算できます。 

1. CRT 以降、私たちは知っています

 [
 R\equiv pq^{-1}\pmod M、
 】

 それで

 [
 Rq\equiv p\pmod M.
 】

 したがって、次を満たす整数 (k) が存在します。 

[
 Rq-kM=p。 
】

 ここでの目標は、この方程式から小さな正の整数 (p,q) を回復することです。 

1. 有理数 (k/q) を考えます。 前の式から、

 [
 \frac RM-\frac{k}{q}
 =\frac{p}{Mq}。 
】

 (p,q\le10^9) および (M>2\cdot10^{18}) であるため、右辺は厳密に (1/(2q^2)) より小さくなります。 したがって、(k/q) は (R/M) の連分数の収束です。

1. (M) と (R) に対してユークリッド アルゴリズムを実行し、各剰余の (R) の係数も追跡します。 初期化する

 [
 M=0\cdot R+1\cdot M
 】

 そして

 [
 R=1\cdot R+0\cdot M.
 】

 Euclid が 2 つの連続する剰余を次のように変換すると、

 [
 a\左矢印 b,\qquad
 b\左矢印 a-\lf フロア a/b\r フロア b、
 】

 同じ変換を (R) の係数に適用できます。 したがって、すべてのユークリッド剰余は次の形式になります。 

[
 s=cR+dM。 
】

 1. (1\le s\le10^9) と正の係数 (c\le10^9) による剰余 (s) を探します。 隠れた分数の場合、関係は正確に次のようになります。 

[
 p=qR-kM、
 】

 したがって、分子 (p) はユークリッド剰余であり、分母 (q) は (R) の正の係数です。 

1. そのペアを出力します。 元の分数が約分されていない場合、ユークリッド再構成はその約分された形式を返す可能性があり、これは同じ有理数を表し、受け入れられます。 

### なぜ効果があるのか

 中心的な不変条件は、すべてのユークリッド剰余が (R) と (M) の整数線形結合として表され、追跡される係数が (R) の乗数を記録することです。 隠れたペアは満たす

 [
 p=qR-kM、
 】

 したがって、(p) は係数 (q) を持つこれらの剰余の 1 つです。 大きな CRT 係数により、近似限界が得られます。 

[
 \left|\frac RM-\frac{k}{q}\right|<\frac1{2q^2}、
 】

 これにより、(k/q) が強制的に連分数収束になります。 Euclid は、再構成に必要な収束構造を正確に列挙します。 (M>10^{18}) であるため、分子と分母の両方が (10^9) で囲まれた 2 つの異なる有理値は存在できません。そのため、アルゴリズムによって検出される候補は必然的に隠れた有理数になります。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

B = 10**9

# Both are primes and satisfy 10^9 < m < 10^12.
M1 = 999999999989
M2 = 999999999997

def crt(a1, m1, a2, m2):
    """
    Return x in [0, m1*m2) such that
        x == a1 (mod m1)
        x == a2 (mod m2)
    """
    t = ((a2 - a1) % m2) * pow(m1, -1, m2) % m2
    x = a1 + m1 * t
    return x, m1 * m2

def recover(r, mod):
    """
    Recover p, q with 1 <= p, q <= B from
        r == p * q^{-1} (mod mod).
    We have mod > 2 * B^2.
    """
    # r0 = s0 * r + ...
    # r1 = s1 * r + ...
    r0, r1 = mod, r
    s0, s1 = 0, 1

    while r1:
        # The first remainder is r itself, which matters for
        # integer answers such as 2/1.
        if 1 <= r1 <= B and 1 <= s1 <= B:
            if (r * s1) % mod == r1:
                return r1, s1

        q = r0 // r1

        r0, r1 = r1, r0 - q * r1
        s0, s1 = s1, s0 - q * s1

    raise RuntimeError("rational reconstruction failed")

def ask(m):
    print("?", m, flush=True)
    ans = int(input())
    if ans == -1:
        sys.exit(0)
    return ans

def main():
    t = int(input())

    for _ in range(t):
        r1 = ask(M1)
        r2 = ask(M2)

        r, mod = crt(r1, M1, r2, M2)
        p, q = recover(r, mod)

        print("!", p, q, flush=True)

if __name__ == "__main__":
    main()
```2 つの定数は (10^{12}) に近い値が意図的に選択されています。 彼らの製品は、

 [
 M=999999999986000000000033、
 】

 これは (2\cdot10^{18}) よりもはるかに大きいです。 このような大きな係数を使用すると、連分数の証明で標準の (1/(2q^2)) 近似限界を使用できるようになります。 

の`ask`関数はクエリを出力し、すぐに stdout をフラッシュします。 インタラクティブな問題ではフラッシュが必須です。そうしないと、Python の出力バッファーに残っているクエリを審査員が永遠に待つことになる可能性があるからです。 裁判官の返答は、`-1`従来は無効な対話を通知するため、プログラムは直ちに終了します。 

の`crt`関数は表現を使用します

 [
 R=r_1+m_1t。 
】

 (t) の値は、(m_1) モジュロ (m_2) の逆モジュラーを使用して求められます。 Python の整数には任意の精度があるため、約 (10^{24}) の CRT モジュラスではオーバーフローが発生しません。 固定幅言語では、この製品には符号付き 64 ビット算術演算よりも広い整数型が必要になります。 

の`recover`関数はユークリッド アルゴリズムの拡張バージョンです。`r1`は現在の剰余であり、`s1`は元の剰余 (r) に対する係数です。 不変条件は、現在の剰余が次のように書けることです。 

[
 r_1=s_1r+cM
 】

 ある整数 (c) の場合。 

候補チェックはユークリッド更新の前に行われます。 この境界は、剰余自体がすでに目的の分子であり、分母が (1) である (2/1) のような場合に必要です。 このチェックをスキップすると、整数の答えが失われます。 

追加のモジュラーチェック```
(r * s1) % mod == r1
```は数学的証明には必要ありませんが、候補条件を明示的にし、無関係な係数を含む剰余を実装が受け入れないよう保護します。 

浮動小数点演算は使用されません。 特に、(R/M) も合理的な答えも決して変換されません。`float`なぜなら、CRT モジュラスは約 (10^{24}) であり、浮動小数点表現が関連するすべての整数情報を保持できる範囲をはるかに超えているからです。 

## 実用的な例

 提供されたサンプルは、通常のバッチ入力/出力のペアではなく、対話型のトランスクリプトです。 これは単一の係数 (1000000007) を使用しますが、上記の解決策では意図的に 2 つの大きな素数を使用するため、連分数再構成が十分に強い係数を持つようになります。 サンプルの`1/2`ケースの返品`500000004`、サンプルは受け入れます`2/4`; 私たちのアルゴリズムは代わりに縮小された表現を返します`1/2`。 

最初に実行した例では、サンプルの値 (x=1/2) を取得します。 と

 [
 m_1=999999999989
 】

 (2) の逆数は (500000000000) であるため、裁判官は (500000000000) を返します。 と

 [
 m_2=999999999997、
 】

 (2) の逆数は (499999999999) です。 CRT はこれらを組み合わせて、

 [
 R=499999999993000000000017。 
】

 結合係数は次のようになります。 

[
 M=999999999986000000000033。 
】

 (M=2R-1) なので、最初のユークリッド ステップは特に単純です。 

| ユークリッド状態 | 現在の残り | (R) の係数 | 候補者 |
 | --- | --- | --- | --- |
 | イニシャル | 499999999993000000000017 | 1 | 大きすぎる |
 | 後（M-R） | 499999999992999999999? | -1 | 負の係数 |
 | 次の分割後 | 1 | 2 | (p=1,q=2) |

 正確な中間剰余は (R-1=499999999993000000000016) です。 最後の小さな剰余は満たされます

 [
 1=2R-M、
 】

 したがって、(R) の係数は (2) となり、(p=1,q=2) となります。 これは、係数追跡がなぜ有用であるかを示しています。ユークリッド アルゴリズムは、小さな分子とそれに対応する分母を同時に見つけます。 

2 番目の実際の例では、サンプルの整数値 (x=2/1) を取得します。 裁判官は両方の大きな素数に対して (2) を返すため、CRT はすぐに結果を返します。 

[
 R=2。 
】

 ユークリッドの再構築は剰余そのものから始まります。 

| ユークリッド状態 | 現在の残り | (R) の係数 | 候補者 |
 | --- | --- | --- | --- |
 | イニシャル | 2 | 1 | (p=2,q=1) |
 | 次へ | 1 | 負の係数が大きい | 拒否されました |
 | 最終回 | 0 | 考慮されていない | 停止 |

 最初の状態はすでに有効な答えです。 これは、最初のユークリッド除算を実行する前に初期剰余をチェックする動機となる特殊なケースです。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(t\log M)) | テスト ケースごとに 2 つのクエリ、CRT、および 1 つのユークリッド アルゴリズム |
 | スペース | (O(1)) | 一定数の整数のみが保存されます。 

ここで (M) は約 (10^{24}) であるため、ユークリッド アルゴリズムには (O(\log M)) だけがかかり、およそ数十回の反復が必要になります。 (10^5) テスト ケースの場合、これは算術作業の観点から簡単に管理できます。 すべてのテスト ケースでは 2 回のクエリと応答の交換が必要ですが、それでもケースごとに許容される 10 クエリの範囲内であるため、対話型プロトコル自体が実際のコストの大半を占めます。 

## テストケース

 これは対話型の問題であるため、提供されたサンプルを通常のバッチ入力としてプログラムに渡すことはできません。 サンプル入力はジャッジの応答で構成されていますが、プログラムはそれらの応答を受信する前にクエリを出力することが期待されています。 次のテスト ハーネスは、代わりに、いくつかの隠れた分数に対する判定をシミュレートすることによって、数学的再構成を独立してテストします。```python
import io
import sys

B = 10**9
M1 = 999999999989
M2 = 999999999997

def crt(a1, m1, a2, m2):
    t = ((a2 - a1) % m2) * pow(m1, -1, m2) % m2
    return a1 + m1 * t, m1 * m2

def recover(r, mod):
    r0, r1 = mod, r
    s0, s1 = 0, 1

    while r1:
        if 1 <= r1 <= B and 1 <= s1 <= B:
            if (r * s1) % mod == r1:
                return r1, s1

        q = r0 // r1
        r0, r1 = r1, r0 - q * r1
        s0, s1 = s1, s0 - q * s1

    raise AssertionError("reconstruction failed")

def residue(p, q, mod):
    return p * pow(q, -1, mod) % mod

def solve_hidden(p, q):
    r1 = residue(p, q, M1)
    r2 = residue(p, q, M2)

    r, mod = crt(r1, M1, r2, M2)
    return recover(r, mod)

## 特殊なケース

 未約分数 (2/4) の場合、隠れた値は (1/2) です。 最初の大きな素数の残基は (500000000000)、2 番目の残基は (499999999999) です。 CRT は、(1/2) の場合と同じ結合剰余を生成します。これは、モジュラー除算が、どの分子と分母の表現が使用されたかには依存せず、有理数値のみに依存するためです。 再構成では (1/2) が返されますが、サンプル トランスクリプトで (2/4) が使用されている場合でも、これは受け入れられます。 

整数 (2/1) の場合、クエリされた両方の剰余は正確に (2) であるため、CRT は (R=2) を返します。 再構成では、初期ユークリッド状態 (R=2) を係数 (1) でチェックし、すぐに (p=2,q=1) を取得します。 このため、最初のユークリッド除算の前に候補チェックを行う必要があります。 

(1/1) の場合、すべてのクエリは (1) を返し、CRT も (R=1) を返します。 初期状態には剰余 (1) と係数 (1) があるため、アルゴリズムは直ちに (1/1) を出力します。 数値 (1) の特殊な場合の分岐は必要ありません。 

最大の等しいペア (10^9/10^9) の場合、分数は (1/1) になるため、モジュラー値は依然として正確に (1) です。 アルゴリズムは (1/1) を返し、出力が正確な隠れたペアではなく有理値として解釈されなければならない理由を示しています。 

(1000000000/999999999) のような境界分数の場合、分子と分母は両方とも許容範囲内に収まりますが、それらの積は (10^{18}) に近くなります。 CRT の弾性率は約 (10^{24}) であり、非常に大きな安全マージンが残されています。 ユークリッド アルゴリズムは整数を完全に処理し、精度を損なうことなく分数を再構築します。 

最も危険な実装上の間違いは、(10^9) 付近の法だけを使用し、連分数が自動的に十分であると仮定することです。 標準の収束限界には (M>2B^2) が必要ですが、元の問題の個々のクエリ係数ははるかに小さくなります。 2 つの大きな素数は、まさにこの問題を解決します。それらの積は (2B^2) よりはるかに大きくなりますが、個々のクエリは許容範囲内に留まります。 これが、最終的なアルゴリズムが短く、厳密である主な理由です。
