 ## 解決策
 ## 問題の理解

 各テストケースに対して、裁判官は正の有理数を選択しました

 [
 x=\frac{p}{q}、
 \qquad 1\le p,q\le 10^9.
 】

 (p) と (q) を直接見ることはできません。 代わりに、(10^9) と (10^{12}) の間の素数係数 (m) について、剰余を求めることができます。 

[
 y\equiv p q^{-1}\pmod m.
 】

 (m>10^9\ge q) なので、逆関数 (q^{-1}\pmod m) が常に存在します。 私たちのタスクは、同じ有理値を表す (1\le P,Q\le10^9) を持つ任意のペア (P,Q) を復元することです。 ペアを減らす必要はないため、(2/4) の代わりに (1/2) を返すことも同様に有効です。 元の問題は対話型であるため、表示されるサンプルは、通常の固定入力/出力ペアではなく、プログラムと審査員の間の対話です。 

境界は、列挙ではなく数理論的な再構成を中心に設計されています。 (10^5) 個のテスト ケースが存在する可能性がありますが、クエリ自体はモジュール値のみを提供します。 すべてのテスト ケースですべての (10^9) 個の可能な分母を試すには、最大 (10^{14}) 回の反復が必要になりますが、これは 6 秒の制限をはるかに超えています。 有益な事実は、許可されるモジュラスがほぼ (10^{12}) になる可能性があるため、2 つのクエリで (10^{24}) 付近の結合モジュラスが得られることです。 これは、未知の分子と分母の (10^{18}) スケールの積よりもはるかに大きくなります。 

単純な実装が黙って失敗する可能性があるケースがいくつかあります。 まず、1 つの係数が有理値を特定するとは限りません。 (m=10^9+7) の場合、2 つの異なる有理数は

 [
 \frac{600000000}{1}
 \quad\text{および}\quad
 \frac{199999993}{2}
 】

 同じ残留物が生成されるため、

 [
 199999993\equiv 2\cdot600000000\pmod {10^9+7}。 
】

 分子と分母の両方が必要な範囲を満たしているため、十分に大きな係数が 1 つあれば十分であると仮定するのは誤りです。 

第 2 に、入力部分を減らす必要がありません。 サンプルには (1/2) と同じ値の (2/4) が含まれています。 元の (p) と (q) を正確に復元することにこだわる実装は、裁判官が求めるよりも強力な問題を解決していることになります。 合理的再構成では、当然、縮小された表現が返されますが、これは許容可能です。 

第三に、(p=q=10^9) などの境界値は、単に換算された分数が (1/1) であるという理由だけで拒否されるべきではありません。 元の表現は法的であり、必要な回答は同じ値の法的表現です。 

## アプローチ

 直接的なアプローチでは、法を選択し、その剰余 (r) を取得し、(1) から (10^9) までのすべての分母 (q) を試します。 候補者ごとに、次のように計算できます。 

[
 p=(rq)\bmod m
 】

 (1\le p\le10^9) の場合はペアを受け入れます。 テストはジャッジによって提供された一致を正確に行うため、有効なペアが見つかった場合は常に正しいことになります。 問題は反復回数です。 最悪の場合、1 つのテストでは (10^9) 個の剰余乗算が必要となり、(10^5) 個のテストでは (10^{14}) 回の反復が行われます。 インタラクションのオーバーヘッドを無視しても、これは絶望的です。 

重要な観察は、クエリが合理的再構築で使用される形式と正確に一致することです。 

[
 p\equiv rq\pmod M.
 】

 (M) を (2\cdot10^9\cdot10^9=2\cdot10^{18}) より大きくすることができれば、この合同を満たす (10^9) で囲まれた分子と分母を持つ簡約有理数が最大 1 つ存在する可能性があります。 標準の有理再構成アルゴリズムは、拡張ユークリッド アルゴリズムを使用してそのペアを見つけます。 目的の方程式は次のように書き換えることができるため、ユークリッドとの関係はここでは特に自然です。 

[
 p=rq-kM
 】

 ある整数 (k) の場合。 したがって、(p) と (q) は、ユークリッド アルゴリズムにおける小さな剰余とそれに対応する係数として発生します。

1 つの許容モジュラスが一意性の限界に対して小さすぎます。 ただし、(10^{12}) に近い 2 つの素数では、(10^{24}) に近い積が得られます。 まず各素数を法とする剰余を求め、その 2 つの剰余を中国の剰余定理と組み合わせます。 結果として生じる係数は、膨大なマージンによって制限された合理的な再構成を満たします。 公式の問題の制約では最大 10 個のクエリが許可されているため、2 つのクエリを使用しても問題なく制限内に収まります。 

以下で使用される 2 つの固定素数は (999999999989) と (999999999997) です。 どちらも (10^{12}) より下、(10^9) より上、そして素数です。 1 つ目は 12 桁の最大の素数で、2 つ目は (10^{12}) 付近にある先行する既知の素数です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(t\cdot10^9)) | (O(1)) | 遅すぎる |
 | 2 つのクエリ + CRT + 合理的な再構成 | (O(t\log 10^{12})) 算術ステップ | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 裁判官に剰余モジュロ (m_1=999999999989) を尋ねます。 答えを (r_1) として保存します。 すべての可能な分母よりも大きな素数を使用するため、(q) 法 (m_1) による除算は明確に定義されます。 
2. 剰余モジュロ (m_2=999999999997) を求め、それを (r_2) として保存します。 2 つのモジュライは別個の素数であるため、互いに素であり、中国の剰余定理と組み合わせることができます。 
3. (0\le R<M=m_1m_2) を満たす一意の (R) を構築します。 

[
 R\equiv r_1\pmod {m_1}、
 \qquad
 R\equiv r_2\pmod {m_2}。 
】

 便利な公式は、

 [
 R=r_1+m_1
 \left((r_2-r_1)m_1^{-1}\bmod m_2\right)。 
】

 重要な点は、2 つの元の合同が、1 つの合同法をはるかに大きい法 (M) で表されることです。 

1. (M) と (R) に対して拡張ユークリッド アルゴリズムを実行します。 を満たす係数 (t) を維持する

 [
 \text{余り}=sM+tR。 
】

 余りが(10^9)以下になったら停止します。 有理的再構成では、必要に応じて両方の符号を変更した後の対応する係数 (t) が、最大 (10^9) であれば、目的の換算分数の分母となることが保証されます。 標準の有理再構成アルゴリズムは、正確には分子と分母の境界を持つ拡張ユークリッド手順です。 

1. 結果の正のペアを ((P,Q)) とします。 概念的に検証してください

 [
 P\equiv RQ\pmod M.
 】

 (M>2\cdot10^{18}) であるため、分子と分母の両方が最大 (10^9) でこの合同を満たす 2 つの異なる短縮分数は存在できません。 したがって、再構成された分数は、隠れた分数と同じ有理数になります。 

1. 出力`! P Q`。 再構成されたペアは、裁判官が最初に非縮小ペアを選択した場合でも縮小される可能性がありますが、これは問題によって明示的に許可されています。 

### なぜ効果があるのか

 4 つの値すべてが最大 (10^9) である 2 つの換算分数 (p/q) と (a/b) が同じ剰余 (M) を法として生成したとします。 それから

 [
 pq^{-1}\equiv ab^{-1}\pmod M
 】

 暗示する

 [
 pb-aq\equiv0\pmod M.
 】

 でも

 [
 |pb-aq|
 \le pb+aq
 \le2\cdot10^{18}
 <M.
 】

 (M) よりも絶対値が小さい (M) の倍数だけがゼロであるため、(pb=aq) になります。 両方の分数は約分されるので、それらは等しくなります。 有理再構成ではユークリッド関係に対応する小さなペアが見つかるので、それはこの一意の分数である必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

M1 = 999999999989
M2 = 999999999997
LIMIT = 10**9

def crt(r1, r2):
    # R = r1 + M1 * k
    # R == r2 (mod M2)
    # M1 * k == r2-r1 (mod M2)
    inv = pow(M1, -1, M2)
    k = ((r2 - r1) * inv) % M2
    return r1 + M1 * k

def rational_reconstruct(r, mod):
    # We maintain:
    # rem = s * mod + t * r
    rem0, rem1 = mod, r
    t0, t1 = 0, 1

    while rem1 > LIMIT:
        q = rem0 // rem1
        rem0, rem1 = rem1, rem0 - q * rem1
        t0, t1 = t1, t0 - q * t1

    if t1 < 0:
        rem1 = -rem1
        t1 = -t1

    # The problem guarantees that a valid reconstruction exists.
    assert 1 <= rem1 <= LIMIT
    assert 1 <= t1 <= LIMIT
    assert (r * t1 - rem1) % mod == 0

    return rem1, t1

def ask(m):
    print("?", m, flush=True)
    return int(input())

def main():
    t = int(input())

    for _ in range(t):
        r1 = ask(M1)
        r2 = ask(M2)

        r = crt(r1, r2)
        p, q = rational_reconstruct(r, M1 * M2)

        print("!", p, q, flush=True)

if __name__ == "__main__":
    main()
```上部の 2 つの定数は、固定された有効なクエリ係数です。 固定素数を使用すると、対話中の素数テストにクエリや計算を費やすことがなくなります。 

の`crt`関数は中国の剰余定理を直接実装します。 (R=r_1+m_1k) と書き、それを 2 番目の合同式に代入し、(k) に対する 1 つの線形合同式を解きます。 Python の整数は任意の精度を持っているため、積 (m_1m_2) (約 (10^{24})) はオーバーフローしません。 

の`rational_reconstruct`関数は拡張ユークリッド部分です。 最初に 2 つの剰余は (M) と (R) で、(R) の係数は (0) と (1) です。 ユークリッド除算が行われるたびに、剰余とまったく同じ商を使用して係数が更新されます。 剰余が最初に最大 (10^9) に達すると、有理再構成により、この剰余とその係数が目的の分子と分母をエンコードしていることがわかります。 

ユークリッドの係数は符号が交互になるため、符号の修正が重要になります。 分母の係数が負の場合、両方の値が一緒に否定されます。 最後のアサーションは定義の合同性をチェックし、ローカル テスト中に実装エラーも検出します。 

クエリ呼び出しで使用されるのは、`flush=True`。 フラッシュしないと、ジャッジが出力ストリームにバッファリングされたままのクエリを待っている間、プログラムはジャッジの応答を待つことができます。 

## 実用的な例

 提供されたサンプルは、係数 (10^9+7) の相互作用転写物です。 私たちのソリューションでは意図的に 2 つの異なるプライムを使用するため、実際のクエリ行と残基はトランスクリプトとは異なりますが、復元された有理値は同じです。 サンプルの 3 つの非表示の値は、(1/1)、(1/2)、および (2/1) です。 

(1/1) の場合、クエリされたすべての剰余は (1) になります。 

| 隠し値 | (r_1) | (r_2) | 再構築(P) | 再構築 (Q) |
 | --- | --- | --- | --- | --- |
 | (1/1) | 1 | 1 | 1 | 1 |

 (1/2) の場合、剰余は (2) の逆モジュラーです。 選択された素数は両方とも奇数であるため、これらは ((m+1)/2) になります。 CRT 後、結合された残留物は次のようになります。 

[
 R=\frac{M+1}{2}
 =499999999993000000000017。 
】

 ユークリッド アルゴリズムは最終的に次の関係に到達します。 

[
 1=2R-M、
 】

 したがって、小さい正のペアは (P=1,Q=2) です。 

| 隠し値 | (R) ブラウン管後 | 残りわずか | 係数 | 出力 |
 | --- | --- | --- | --- | --- |
 | (1/2) | 499999999993000000000017 | 1 | 2 | (1/2) |

 (2/1) の場合、結合された剰余は単純に (2) になります。 それはすでに最大 (10^9) であり、その (R) の係数は (1) であるため、再構成はすぐに停止します。 

| 隠し値 | (R) ブラウン管後 | 残りわずか | 係数 | 出力 |
 | --- | --- | --- | --- | --- |
 | (2/1) | 2 | 2 | 1 | (2/1) |

 これらのトレースは、アルゴリズムが特別な場合を必要とせずに非常に小さな分子と分母も処理する理由を示しています。 ユークリッド プロセスでは、すぐに答えが見つかるか、対数回の除算だけで答えが得られます。 

2 番目の例として、境界部分を考えてみましょう。 

[
 x=\frac{10^9}{10^9}=1。 
】

 モジュラーの答えは両方とも (1) であるため、CRT は (R=1) を返します。 アルゴリズムは (1/1) を返します。これは、たとえ裁判官が使用したのと同じ表現ではないとしても、有効な答えです。 

| 隠し値 | (r_1) | (r_2) | (R) | 出力 |
 | --- | --- | --- | --- | --- |
 | (10^9/10^9) | 1 | 1 | 1 | (1/1) |

## テストケース

 元の問題は対話型であるため、リテラルのサンプルを通常のプログラムに渡すことはできません。`run(input_string)`機能: 入力の下に表示される数字は審査員の応答であり、完全なオフライン入力形式ではありません。 次のテスト ハーネスは、隠れた (p,q) 値から 2 つの正当な剰余を生成し、それらを再構成ルーチンに入力することによって、完全な数学的コアをチェックします。```python
import sys
import io
from math import gcd

M1 = 999999999989
M2 = 999999999997
LIMIT = 10**9

def crt(r1, r2):
    inv = pow(M1, -1, M2)
    k = ((r2 - r1) * inv) % M2
    return r1 + M1 * k

def rational_reconstruct(r, mod):
    rem0, rem1 = mod, r
    t0, t1 = 0, 1

    while rem1 > LIMIT:
        q = rem0 // rem1
        rem0, rem1 = rem1, rem0 - q * rem1
        t0, t1 = t1, t0 - q * t1

    if t1 < 0:
        rem1 = -rem1
        t1 = -t1

    assert 1 <= rem1 <= LIMIT
    assert 1 <= t1 <= LIMIT
    assert (r * t1 - rem1) % mod == 0

    return rem1, t1

def reconstruct(p, q):
    r1 = p * pow(q, -1, M1) % M1
    r2 = p * pow(q, -1, M2) % M2
    r = crt(r1, r2)
    return rational_reconstruct(r, M1 * M2)

def run(cases):
    out = []
    for p, q in cases:
        a, b = reconstruct(p, q)
        g = gcd(p, q)
        expected = (p // g, q // g)
        out.append((a, b))
        assert (a, b) == expected
    return out

# Provided sample values.
assert run([
    (1, 1),
    (1, 2),
    (2, 1),
]) == [
    (1, 1),
    (1, 2),
    (2, 1),
], "sample 1"

# Minimum-size values.
assert run([
    (1, 1),
]) == [
    (1, 1),
], "minimum values"

# Maximum numerator and denominator, with a reduced answer.
assert run([
    (10**9, 10**9),
]) == [
    (1, 1),
], "maximum equal values"

# Opposite boundaries.
assert run([
    (1, 10**9),
    (10**9, 1),
]) == [
    (1, 10**9),
    (10**9, 1),
], "boundary values"

# Non-reduced representation and large coprime values.
assert run([
    (999999999, 999999999),
    (999999937, 1000000000),
]) == [
    (1, 1),
    (999999937, 1000000000),
], "reduction and large values"

print("all tests passed")

 ## 特殊なケース

 最初のエッジ ケースは、単一のモジュラスの障害です。 (m=10^9+7) の場合、分数 (600000000/1) と (199999993/2) は同じ剰余になります。 したがって、1 つのクエリの実装には、どちらかを選択するための数学的根拠はありません。 2 つのクエリの解決策では、独立した残基がおよそ (10^{24}) の法に結合され、その後、一意性の不等式が計算されます。 

[
 2\cdot10^9\cdot10^9<M
 】

 両方の部分が同時に有効な再構成であることは除外されます。 

2 番目のエッジ ケースは、非縮小隠れ分数です。 隠れた値 (2/4) の場合、各モジュラー応答は (1/2) の応答と同一です。 したがって、CRT は縮小されたペア (1/2) を再構築します。 これは正しいです。なぜなら、必要な出力は、裁判官が最初に選択した正確な表現ではなく、合理的な値を記述しているからです。 

3 番目のエッジ ケースは (p=q=10^9) です。 隠れた分数は数値的に (1) であり、そのモジュラー剰余は、許可されるすべての素数に対して (1) になります。 CRT は (R=1) を返すため、有理再構成は (1/1) を返します。 元の分子と分母が両方とも最大値であったという事実は、特別な処理を必要としません。 

4 番目のエッジ ケースは、(1/10^9) など、正確に (10^9) の分母です。 再構成条件は次のとおりです。`<= LIMIT`、 ない`< LIMIT`問題が境界自体を許可しているためです。 同じことが正確に (10^9) の分子にも当てはまります。 

5 番目のエッジ ケースは、ユークリッド係数の符号です。 拡張 Euclid の間、モジュラー剰余に関連付けられた係数の符号が変わります。 たとえば、(1/2) の場合、次のユークリッド ステップの前に、目的の関係が負の係数として現れる可能性があります。 剰余と係数の両方を否定すると合同が維持され、必要な正の分子と分母が得られます。 この符号補正を無視すると、基礎となる再構成が有効であっても、負の分母が生成される可能性があります。
