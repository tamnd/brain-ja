 ## 解決策
 ## 問題の理解

 原点の周りに点衛星のコレクションがあります。 各衛星には、角度位置、原点からの距離、および質量があります。 エルファバは原点から始まる光線を選択し、その光線に沿った総重力が、彼女が訪問するどの点においても光線に垂直な成分を持たないことを望んでいます。 

中心的な観察は、有効な飛行ラインは重み付けされた衛星構成全体の反射軸でなければならないということです。 ラインを越えた反射では、すべての衛星の位置とその質量の両方を保存する必要があります。 これは、問題の意図された幾何学的な縮小でもあります。有効な線は、重み付けされた構成の対称軸とまったく同じであり、その後、問題は回文問題になります。 

角度は整数の円弧秒で指定され、1 回転には正確に 129600 の位置が含まれます。 この有限な角度分解能は非常に便利です。 長さ 129600 の配列を作成できます。`(rho, mass)`すべての占有角度でマークし、他の場所では空のマーカーを使用します。 

の値`n`は 200000 まで大きくできますが、角度座標は 0 ～ 129599 の個別の整数であるため、有効な入力には最大 129600 個の衛星を含めることができます。 2 秒という制限時間により、二次関数は排除されます。`n`。 129600 の 2 乗でも約 168 億回の比較に相当し、Python が時間内に実行できる量をはるかに超えています。 固定角度宇宙にわたる線形または線形に近いアルゴリズムが正しい目標です。 公式の問題には 256 MiB のメモリ制限があり、サイズが約 260,000 のいくつかの配列には十分です。 

直接的な幾何学的実装では誤って処理される可能性のあるいくつかの特殊なケースがあります。 まず、対称軸は衛星を通過できますが、衛星が進行方向にある場合、対応する飛行光線は禁止されます。 例えば、```
2
1 0 1
1 64800 1
```には、64800 を法とする 0 と 32400 アーク秒に対称軸があります。方向 0 と 64800 は衛星によってブロックされますが、32400 と 97200 はクリアであるため、正しい出力は次のようになります。```
2
32400.0000000
97200.0000000
```実際の光線を確認せずに対称軸を報告する不注意な実装では、誤って 4 方向が出力されてしまいます。 

第 2 に、軸は整数の角度である必要はありません。 角度 0 と 1 にある 2 つの等しい衛星は、問題の秒角単位で 0.5 度、より正確には 0.5 秒角に対称軸を持っています。```
2
1 0 1
1 1 1
```正しい出力は次のとおりです```
2
0.5000000000
64800.5000000000
```整数の中心のみをチェックする実装は、両方の答えを黙って見逃します。 

第三に、質量が異なる場合、幾何学的対称性だけでは十分ではありません。 考慮する```
4
1 0 1
1 64800 2
1 32400 3
1 97200 3
```幾何学的位置は水平軸を中心に対称ですが、その軸上の 2 つの衛星の質量は異なります。 加重鏡映対称ではない構成となっており、水平方向も遮断されます。 正しい出力は次のとおりです```
0
```座標のみをチェックして質量を無視すると、方向が誤って受け入れられてしまいます。 

最後に、空の角度位置が重要です。 2 つの衛星が大きな角度ギャップによって分離されている場合、反射は衛星自体だけでなくそのギャップも維持する必要があります。 完全な 129600 位置の角度配列を明示的な空のシンボルで埋めると、これが自動的に処理されます。 入力を占有位置のみに圧縮すると、角距離に関する情報が失われ、誤った対称性が生じる可能性があります。 

## アプローチ

 ブルートフォースアプローチは、可能なラインを選択し、そのラインを横切るすべての衛星を反射し、反射された構成が質量も含めて同一であるかどうかを確認することです。 すべての有効な軸は角座標での動作によって決定されるため、軸は 180 度を法として決定され、整数または半整数弧秒に位置する可能性があるため、可能な軸は O(129600) 個だけです。 1 つの軸をすべての軸に対してチェックする`n`衛星は O(n) を必要とし、実現可能な最大入力で O(129600n)、つまり約 1.7 × 10^10 の比較を行います。 Python のオーバーヘッドを考慮する前でも、これは遅すぎます。 

角度座標は離散的であるため、より良い方法があります。 衛星ラベルを貼ります`(rho, mass)`角度に応じて、1 つおきの整数角度に空の値を入れます。 2 倍の角度を持つ軸の周りの反射`k`角度を送信します`x`に`k-x`したがって、円形配列が適切な点で切断されると、軸の両側のラベルは回文を形成する必要があります。 

複雑なのは円形の境界だけです。 角度配列を複製することでこれを解決します。 元の円の対称は、二重化された配列のどこかを中心とする長さ 129600 の回文になります。 整数中心と半整数中心の両方が発生するため、Manacher のアルゴリズムからの奇数回文半径と偶数回文半径を使用します。 Manacher は、すべての最大回文半径を線形時間で計算します。 

物理パラメータには浮動小数点計算はまったく必要ありません。 2 つの反射位置が正確に等しいとき、`(rho, mass)`ペアは等しいです。 これは、タプル比較で十分であり、ハッシュ衝突を完全に回避できることを意味します。 

すべての反射軸が見つかると、各軸は 2 つの反対の飛行方向を表します。 方向は、その光線上に衛星が正確に存在しない場合にのみ有効です。 すべての衛星角度は整数であるため、半整数の方向に衛星が含まれることはありませんが、整数の方向は角度配列で直接チェックできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(129600n) | O(n) | 遅すぎる |
 | 最適 | O(129600 + n + A) | O(129600 + n) | 承認済み |

 ここ`A`は出力方向の数です。 最終スキャンは実際には O(259200) であるため、解全体は固定角度の世界では事実上線形です。 

## アルゴリズムのチュートリアル

 1.角度配列を作成する`a`長さの`C = 129600`。 位置で`phi`、 店`(rho, mass)`その角度の衛星の場合。 1 つおきの位置に格納`None`。 タプルは、リフレクションが保持する必要がある完全な情報です。 
2. この配列を複製して取得します。`s = a + a`。 反射軸は角度 129599 と角度 0 の間の人為的な境界を横切る可能性があるため、1 つのコピーだけで作業すると有効な回文が失われます。 2 番目のコピーには、すべての円形回文を通常の回文として表現するのに十分な余地があります。 
3. Manacher のアルゴリズムを実行します。`s`奇数回文半径を計算します`d1`回文半径さえも`d2`。 奇数の半径`d1[i]`位置を含む一致するレイヤーの数です`i`、 その間`d2[i]`直前のギャップの周囲に一致するレイヤーの数です。`i`。 
4. 可能な軸を次のように表します。`k = 2alpha`、 どこ`alpha`その角度です。 ある軸と180度回転した同軸は同一であるため、`k`0 から 0 までの値のみが必要です`C-1`。 平`k`整数では軸角度が得られますが、奇数では`k`は半整数の軸角度を与えます。 
5. 偶数の場合`k`、軸は位置の中心にあります`C + k/2`二重化された配列内。 完全な円形反射には、以下の距離が等しい必要があります。`C/2 - 1`このセンターから。 Manacher の記法では、これがまさにその条件です`d1[C + k/2] >= C/2`。 
6. 奇数の場合`k`、軸は 2 つの配列位置の間にあります。 その中心は偶数回文インデックスで表されます`C + (k+1)/2`。 必要です`C/2`ペアが一致するため、条件は次のようになります。`d2[C + (k+1)/2] >= C/2`。 
7. すべてにマークを付けます`k`有効な反射軸として対応する回文条件を満たします。 回文には角円全体が含まれているため、このテストは単に構成の局所的な部分をチェックするだけではありません。 すべての衛星とすべての空の角度位置を、反射された対応物と比較してチェックします。 
8. スキャン方向角度を 2 倍にする`x`0から`2C-1`。 実際の飛行方向は、`x/2`アーク秒、その反射軸は`k = x mod C`。 その軸が対称でない場合、その方向は拒否されます。 もし`x`が奇数の場合、方向は半整数の角度であり、衛星を含めることはできません。 もし`x`偶数であるかどうかを確認してください`a[x/2]`は空です。 空の方向のみが出力されます。 
9. フォーマット時に 2 で割って、2 倍の方向角度を昇順に出力します。 走査`x`in昇順では、必要なソート出力がすでに得られているため、別個のソートは必要ありません。 

### なぜ効果があるのか

 固定飛行ラインの場合、各衛星の位置をそのラインに平行な座標と垂直な座標に分解します。 その重力の垂直成分は次のように比例します。 

[
 \frac{m_i b_i}
 {(t^2-2a_i t+\rho_i^2)^{3/2}}、
 】

 どこで`t`は光線に沿った原点からのエルファバの距離です。`a_i`は衛星の平行座標であり、`b_i`はその垂直座標です。 合計は毎回消えなければなりません`t > 0`。 

軸外衛星には、その平行座標、原点からの距離、および質量によって決定される特異な寄与があります。 唯一可能なキャンセルは、ラインを越えたミラーイメージからのものです。ミラーには同じものがあるためです。`a_i`そして`rho_i`しかしその反対`b_i`。 キャンセルするには、大衆も平等である必要があります。 軸上の衛星には、`b_i = 0`そして垂直方向の力には寄与しません。 したがって、重み付けされた衛星構成は、飛行経路を横切る反射の下でも不変でなければなりません。 

角度配列はこの構成を正確に記録します。 2 倍の角度を持つ軸の周りの反射`k`地図の位置`i`に`k-i`モジュロ`C`、これはまさに円回文を定義する等価関係です。 二重化された配列は、その円形回文を通常の回文に変換し、Manacher は必要な完全長の回文が存在するかどうかを見つけます。 したがって、マークされたすべての軸は真の対称軸であり、すべての真の対称軸はマークされます。 

最終的なレイ チェックでは、衛星を含むハーフラインが正確に削除されます。 したがって、放出された方向は、まさに物理的に許容される飛行方向です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

C = 129600
HALF = C // 2

def manacher_odd_even(s):
    n = len(s)

    d1 = [0] * n
    l = 0
    r = -1

    for i in range(n):
        if i > r:
            k = 1
        else:
            k = min(d1[l + r - i], r - i + 1)

        while i - k >= 0 and i + k < n and s[i - k] == s[i + k]:
            k += 1

        d1[i] = k

        k -= 1
        if i + k > r:
            l = i - k
            r = i + k

    d2 = [0] * n
    l = 0
    r = -1

    for i in range(n):
        if i > r:
            k = 0
        else:
            k = min(d2[l + r - i + 1], r - i + 1)

        while i - k - 1 >= 0 and i + k < n and s[i - k - 1] == s[i + k]:
            k += 1

        d2[i] = k

        k -= 1
        if i + k > r:
            l = i - k - 1
            r = i + k

    return d1, d2

def solve():
    n = int(input())

    a = [None] * C

    for _ in range(n):
        rho, phi, mass = map(int, input().split())
        a[phi] = (rho, mass)

    s = a + a
    d1, d2 = manacher_odd_even(s)

    good = [False] * C

    for k in range(C):
        if k & 1:
            center = C + (k + 1) // 2
            if d2[center] >= HALF:
                good[k] = True
        else:
            center = C + k // 2
            if d1[center] >= HALF:
                good[k] = True

    out = []

    for x in range(2 * C):
        k = x % C

        if not good[k]:
            continue

        if x & 1:
            out.append(f"{x / 2:.10f}")
        else:
            phi = x // 2
            if a[phi] is None:
                out.append(f"{phi:.10f}")

    sys.stdout.write(str(len(out)) + "\n")
    sys.stdout.write("\n".join(out))
    if out:
        sys.stdout.write("\n")

if __name__ == "__main__":
    solve()
```の最初の部分`solve`完全な循環シーケンスを構築します。 の使用`None`意図的です。 これは、反映された空の位置が別の空の位置と一致する必要があることを意味するため、回文チェックではすべての角度ギャップも検証されます。 

の`manacher_odd_even`関数は、標準的な線形時間の奇数および偶数の回文計算です。 軸は整数の角度位置を直接通過することも、2 つの整数位置の間を通過することもできるため、2 つの配列が必要になります。 このアルゴリズムでは等価比較のみが使用されるため、大きな座標を浮動小数点に変換することなく、サテライト タプルを直接比較できます。 

偶数軸の場合は、`d1`。 のために`k = 2alpha`、複製された配列の中心は`C + alpha`、必要な半径は`C/2`。 正確なしきい値は次のとおりです。`HALF`、 なぜなら`d1`中心自体を 1 つのレイヤーとしてカウントするため、半径は`HALF`0 から 0 までの距離をカバーします`HALF-1`。 正確な距離にあるペア`HALF`は 1 回完全に回転した後の同じ角度位置を表し、追加の条件は課しません。 

奇数軸の場合は、`d2`。 ここで、軸は 2 つの整数の角度位置の間にあり、正確に`HALF`完全な円の周囲に異なる反射ペアが存在します。 したがって、必要な偶数回文半径は正確に次のようになります。`HALF`。 

最終スキャンでは 2 倍の角度が使用されます。 これにより、浮動小数点エラーの蓄積が回避され、ソートされた出力が無料で提供されます。 奇数の 2 倍角の場合、方向は半整数円弧秒であり、入力衛星と一致することはできません。 偶数 2 倍の角度の場合、対応する整数の位置がチェックインされます。`a`。 

Python では整数オーバーフローの問題はありません。 保存されている最大の整数はおよそ`10^18`Python の整数はとにかくそれを正確に処理します。 さらに重要なのは、アルゴリズムは三角関数の計算を決して実行しないため、`rho`または`phi`浮動小数点に変換する必要があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(C + n + A) | 角度配列を構築し、Manacher を実行します。`2C`位置、スキャン`2C`行き方 |
 | スペース | O(C + n) | 角度ラベルと 2 つの Manacher 半径配列を保存します。 

ここ`C = 129600`そして`A`報告された方向の数です。 以来`C`ステートメントによって修正され、`A <= 200000`実際のワークロードは、数十万の配列操作と入出力処理です。 これは意図した制限内に問題なく収まっており、実装では O(n²) の作業は実行されません。 

## テストケース```python
import sys
import io
from contextlib import redirect_stdout

C = 129600

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    with redirect_stdout(out):
        solve()

    sys.stdin = old_stdin
    return out.getvalue()

def parse_output(out: str):
    tokens = out.split()
    count = int(tokens[0])
    values = list(map(float, tokens[1:]))
    assert count == len(values)
    return count, values

# Provided sample
sample1 = """\
2
1 0 1
1 64800 1
"""

assert run(sample1) == (
    "2\n"
    "32400.0000000000\n"
    "97200.0000000000\n"
), "sample 1"

# Minimum-size input with a half-integer symmetry axis.
case2 = """\
2
1 0 1
1 1 1
"""

count, values = parse_output(run(case2))
assert count == 2, "half-integer axis count"
assert abs(values[0] - 0.5) < 1e-9, "half-integer first direction"
assert abs(values[1] - 64800.5) < 1e-9, "half-integer second direction"

# Weighted configuration with geometric symmetry but no valid weighted symmetry.
case3 = """\
4
1 0 1
1 64800 2
1 32400 3
1 97200 3
"""

count, values = parse_output(run(case3))
assert count == 0, "unequal masses must break symmetry"

# Square: cardinal axes are blocked, diagonal axes are clear.
case4 = """\
4
1 0 1
1 32400 1
1 64800 1

## 特殊なケース

 最初のエッジ ケースは、衛星を含む対称軸です。 のために```
2
1 0 1
1 64800 1
```反射により角度 0 がそれ自体に送信され、64800 がそれ自体に送信されるため、0 の軸が検出されます。 対応する倍増軸インデックスは次のとおりです。`k = 0`。 出力スキャン中、方向`x = 0`角度 0 にマッピングされます。`a[0]`占有されているため拒否されます。 方向`x = 129600`角度 64800 にマップされます。`a[64800]`も占有されているため、拒否されます。 垂直軸は存続し、32400 と 97200 を生成します。 

2 番目のエッジ ケースは半整数軸です。 のために```
2
1 0 1
1 1 1
```0.5 付近の反射で 2 つの衛星が交換されます。 その 2 倍の軸の値は、`k = 1`したがって、アルゴリズムでは偶数回文半径が使用されます。 どちらの光線も 2 倍の角度 1 と 129601 を持っているため、半整数の方向になります。 どちらの入力角度も等しくならないため、どちらの方向も安全です。 出力は 0.5 と 64800.5 です。 

3 番目のエッジ ケースは、質量が不等であることです。 のために```
4
1 0 1
1 64800 2
1 32400 3
1 97200 3
```32400 と 97200 の位置には同じラベルが付いていますが、0 と 64800 のラベルは異なります。 これら 2 つの位置を交換する反射は質量を変化させるため、重力場の対称性ではありません。 両方の不等質量衛星を固定したままにする唯一の幾何学的軸は水平軸ですが、その軸の両方の光線には衛星が含まれています。 最終的な答えは空です。 

4 番目のエッジ ケースは、円形の境界を横切る対称性です。 のために```
2
1 129599 7
1 0 7
```2 つの衛星は 0 度の境界を越えて隣接しています。 それらの対称軸は 129599.5 にあり、180 度を 64799.5 で割って表されます。 この普通の回文を可視化しているのは、二重配列構造です。 角度シーケンスを複製しないと、ペアはデータ構造の反対側にあるように見え、ローカルの回文実装ではそれを見逃す可能性があります。 

5 番目のエッジ ケースは、完全に占有された角円です。 0 ～ 129599 のすべての整数の角度に同じ値が含まれる場合`(rho, mass)`、すべての反射軸は幾何学的対称として有効です。 すべての整数光線はブロックされますが、すべての半整数光線は透明になります。 有効な方向は正確に 129600 あり、半整数角度ごとに 1 つずつ存在します。 回文テストでは完全に均一なシーケンスが確認され、最後の光線テストでは占有されている整数の位置が正確に削除されるため、アルゴリズムは特別なケースを使用せずにこれを処理します。
