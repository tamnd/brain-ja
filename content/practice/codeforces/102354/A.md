 ## 解決策
 ## 問題の理解

 正の整数の配列 (a_1,\dots,a_n) があります。 最初の平方根には常にプラス記号が付けられますが、その後の各項は独立して (+) または (-) のいずれかを受け取ることができます。 選択が何回行われるかを数える必要があります

 [
 \sqrt{a_1}\pm\sqrt{a_2}\pm\cdots\pm\sqrt{a_n}=0。 
]

 答えは、結果として得られる明確な合計ではなく、記号の選択肢をカウントします。 最初の符号は固定されているため、方程式を適用する前に (2^{n-1}) 個の可能な選択肢があります。 

制約 (n\le 36) は主要なアルゴリズム信号です。 許可されているすべての (2^{35}) 個の符号パターンを列挙すると、すでに (3.44\times10^{10}) ほどになり、3 秒の制限をはるかに超えています。 (2^n) からおおよそ (2^{n/2}) への通常の中間削減は、まさに (n) のサイズが示すとおりです。 

(a_i) のはるかに大きな境界は、異常な部分です。 (a_i) の 10 進数は 100,000 桁を超える場合があるため、数値を因数分解したり、数値を通常の Python 整数に直接変換したりすることは、合理的な実装戦略ではありません。 実際、標準の整数文字列変換制限のある Python バージョンでは、その制限が変更されない限り、そのような入力は拒否されます。 各数値を 10 進数の文字列として読み取り、それを固定素数を使って 1 桁ごとに減算することで、この問題を完全に回避できます。 

不注意な解決策を露呈するエッジケースがいくつかあります。 と```
2
1 1
```(1-1=0) なので、答えは (1) です。 両方の符号を独立したものとして扱い、完全な (2^2) の割り当てをカウントし、大域符号の対称性を忘れる解決策では、代わりに (2) が得られます。 

と```
3
2 2 8
```答えは (1) です。 

[
 \sqrt2+\sqrt2-\sqrt8=0。 
]

 浮動小数点の実装では、特に入力で許可される巨大な値の場合、これが信頼性の低い比較に暗黙的に変換される可能性があります。 

2番目の危険なケースは、```
4
4 9 25 49
```その答えは (0) です。 すべての平方根は整数であるため、この特定の入力は通常の符号付き部分集合和のように見えますが、(2,3,5,7) にゼロ和を与える符号を選択​​することはできません。 合計が偶数であるかどうかだけをチェックするソリューションや、正確に (\pm1) ではなく誤って任意の係数を許可するソリューションでは、それが誤って受け入れられる可能性があります。 

最後に、値が非常に大きくなり、入力自体をテキストとして扱う必要がある場合があります。 たとえば、(10^{100000}) は有効です。 それを因数分解しようとしたり、浮動小数点平方根を実行したりすると、問題に必要な正確な構造が失われます。 

## アプローチ

 直接的なアプローチは、考えられるすべての符号の割り当てを試すことです。 割り当てごとに式を評価し、それがゼロかどうかを確認します。 すべての法的割り当ては 1 回だけ出現するため、これは正しいです。 固定された最初の符号を他のすべての符号と一緒に列挙すると、(2^n) 個の割り当て、または最悪の場合 (2^{36}=68,719,476,736) が存在します。 定数時間演算を行ったとしても、それは遅すぎます。 

通常サイズの整数の場合、自然な次のステップは次のように書くことです。 

[
 \sqrt{x}=c\sqrt{d}、
 ]

 ここで (d) は自由平方であり、同じ (d) を持つ項をグループ化し、結果として得られる符号付き部分集合の合計を独立して解きます。 これは数学的にはきれいですが、100,000 桁の整数の二乗しない部分を取得するには、制約によって利用できないように設計されているものと本質的に同じ難しい因数分解情報が必要です。 

重要な観察は、実際には平方自由分解が必要ないということです。 関連する符号付き和を区別するのに十分な加法等価性が維持される平方根の表現のみが必要です。 意図した解決策では、大きな素数と二次残基を使用してそのような表現を構築し、その後に中間で満たします。 このモジュール式のアプローチは、この問題に対して利用可能なソリューションの説明でも説明されています。 

(P\equiv3\pmod4) を満たす大きな素数 (P) を選択します。 私たちが使用するのは

 [
 f(x)=x^{(P+1)/4}\pmod P.
 ]

 非ゼロ (x) の場合、オイラーの基準では 2 つのケースが与えられます。 (x) が (P) を法とする二次剰余の場合、

 [
 f(x)^2=x。 
]

 (x) が非残基の場合、

 [
 f(x)^2=-x。 
]

 2 番目のケースは、文字通り (x) の平方根を与えないため、問題があるように見えます。 便利な特性は、マップが乗法的であることです。 

[
 f(xy)=f(x)f(y)。 
]

 したがって、このマップは、すべての (a_i) の平方自由部分を明示的に識別する代わりに、すべての根号に一貫した代数表現を割り当てます。 根号クラス内では、考えられる追加要素が固定されており、(+) または (-) を選択すると、その固定された符号が符号の選択に吸収されることがすでに許可されています。 したがって、ゼロ符号付きの組み合わせの数は保存されます。 

残る唯一の問題は、有限体が有理数を超えて異なる 2 つの異なる代数量を識別できることです。 約 60 ビットの素数では、無関係な衝突の確率は (1/P) 程度ですが、意図したランダム化ハッシュの解釈では無視できます。 元のソリューションでは、まさにこの目的のために大きな固定素数を使用しています。 

すべての (\sqrt{a_i}) がそのモジュール表現 (b_i) に置き換えられると、問題は標準的な符号付き和問題になります。 

[
 \pm b_1\pm b_2\pm\cdots\pm b_n\equiv0\pmod P.
 ]

 用語を 2 つに分割します。 前半のすべての符号付き合計を生成し、その頻度をカウントします。 次に、後半のすべての符号付き合計を生成し、前半のテーブルでその否定を検索します。 各ペアは 1 つの完全なゼロサム割り当てを与えます。 

最初の符号を修正するのではなく、すべての (2^n) 個の符号割り当てを列挙します。 最初の符号が固定されているすべての正当な代入は、正確に 2 つの完全な符号の代入に対応し、1 つはもう 1 つの大域的な否定です。 したがって、最終的なモジュール数は 2 で割られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^n n)) | (O(1)) | 遅すぎる |
 | 最適 | (O(n2^{n/2})) | (O(2^{n/2})) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての (a_i) を 10 進数の文字列として読み取り、それを剰余 (P) で減算します。 モジュラー計算にはその剰余モジュロ (P) のみが必要であるため、潜在的に 100,001 桁の Python 整数を構築することはありません。 
2. すべての縮小値 (x_i) について、計算します。 

[
 b_i=x_i^{(P+1)/4}\bmod P.
 ]

 (P\equiv3\pmod4) という理由で指数が選択され、これにより、上で説明した二次剰余の動作が得られます。 

1. (n) 個の変換された値を 2 つのサイズ (\lfloor n/2\rfloor) と (\lceil n/2\rceil) に分割します。 2 つの半分にはそれぞれ最大 18 個の要素があるため、各辺の符号付き合計は最大 (2^{18}=262,144) になります。 
2. 前半のすべての符号付き合計を生成します。 各和の否定を頻度辞書に保存します。 否定を保存するということは、後半の合計を直接クエリできることを意味します。 
3. 後半のすべての符号付き合計を生成します。 合計 (s) については、(-s) モジュロ (P) に等しい前半の合計がいくつあるかを調べます。 このような各ペアは、変換された合計がゼロになる完全な符号付き代入を形成するため、その頻度を答えに追加します。 
4. 累積カウントを 2 で割ります。 列挙では最初の項で両方の符号が許可されましたが、実際の式では最初の項が正として固定されます。 すべての符号を否定すると、ゼロ式が別のゼロ式に変更され、完全な割り当てが正確にペアになります。 最初の符号が固定されている各法的割り当てには、最初の符号が負であるそのようなパートナーが 1 つだけあります。 
5. 結果の整数を出力します。 

重要な不変条件は、辞書に、前半の各代入をゼロ符号付き和に完了するために必要なモジュラー補数が正確に含まれていることです。 2 つの半分のマッチングによってカウントされるすべてのペアは、変換された和がゼロである 1 つの完全な符号付き代入に対応し、すべての変換されたゼロの代入は、1 つの前半の和と 1 つの後半の和に一意に分割されます。 有限体構築は、因数分解を必要とせずに、巨大な根号をコンパクトな代表に置き換えるためにのみ使用されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# A large prime with P % 4 == 3.
# 411191981019260843 is the prime used by the standard solution.
P = 411191981019260843
EXP = (P + 1) // 4

def read_mod(s):
    x = 0
    for c in s:
        if '0' <= c <= '9':
            x = (x * 10 + ord(c) - 48) % P
    return x

def signed_sums(values):
    sums = [0]

    for x in values:
        old = sums
        sums = [v - x for v in old] + [v + x for v in old]
        sums = [v % P for v in sums]

    return sums

def solve():
    n = int(input())
    raw = input().split()

    values = [pow(read_mod(s), EXP, P) for s in raw]

    m = n // 2
    left = values[:m]
    right = values[m:]

    left_sums = signed_sums(left)

    freq = {}
    for x in left_sums:
        freq[x] = freq.get(x, 0) + 1

    answer = 0

    right_sums = signed_sums(right)
    for x in right_sums:
        answer += freq.get((-x) % P, 0)

    print(answer // 2)

if __name__ == "__main__":
    solve()
```の`read_mod`関数は最も重要な実装詳細の 1 つです。 計算します

 [
 (((d_1\cdot10+d_2)\cdot10+d_3)\cdots)\bmod P
 ]

 10進数を読み取っているとき。 これにより、入力サイズが 10 進数の桁数で線形になり、Python の巨大な整数の変換制限が回避されます。 

への呼び出し`pow(x, EXP, P)`Python の組み込みのべき乗モジュラーを使用します。これは、二乗によってべき乗を実行し、大きな中間整数を構築しません。 この係数の指数には約 59 ビットしかないため、各変換は低コストです。 

の`signed_sums`関数は空の符号付き合計 (0) から始まります。 値 (x) を加算すると、既存のすべての合計から 2 つの新しい合計 (s-x) と (s+x) が生成されます。 (k) 個の値を処理すると、正確に (2^k) 個のエントリが存在します。 モジュロ演算では、すべての値が固定範囲内に収まります。 

辞書には、合計のセットだけではなく度数も保存されます。 異なる符号パターンでも同じモジュラー和が生成される可能性があり、それらのすべてが答えに寄与する必要があります。 頻度カウントを忘れると、特に等しい値を含む配列の場合、繰り返しの合計が過小評価されます。 

Python には整数オーバーフローはありません。 すべての算術演算は任意精度ですが、モジュラー値自体はわずか約 59 ビットです。 

最後の 2 による除算は、恣意的な補正ではありません。 コードでは、最初の項に両方の符号を意図的に列挙しています。 全符号ベクトルが ((s_1,\dots,s_n)) の場合、その否定 ((-s_1,\dots,-s_n)) も和がゼロになります。 ペアのうちの 1 つだけが (s_1=+1) を持ちます。これは、元の式で必要な規則です。 

## 実用的な例

 サンプル 1 の場合、```
3
2 2 8
```正確な実際の関係は

 [
 \sqrt2+\sqrt2-\sqrt8=0。 
]

 (f(x)=x^{(P+1)/4}\bmod P) とします。 重要な構造関係は (8=2^3) であるため、(8) の変換値は (2) の変換値と乗算的に関係します。 モジュラー表現は根号クラスに対して異なる固定方向を選択する可能性がありますが、利用可能な記号はその方向を吸収します。 

(n=3) の場合、分割は (1+2) になります。 

| ステージ | 左の状態 | 正しい状態 | 貢献 |
 | --- | --- | --- | --- |
 | 変換 | (f(2)) | (f(2)、f(8)) | 0 |
 | 左に生成 | (+f(2),-f(2)) | まだ生成されていません | 2 件のエントリ |
 | 権利を生成 | 変更なし | 4 つの符号付き和 | 4 件のエントリ |
 | 補数の一致 | 格納された否定された左の和 | 各権利の合計をクエリする | 2 つの完全なモジュラーゼロ割り当て |
 | グローバル記号を削除する | 2 | 2 | 1 |

 最後の除算は (1) となり、最初の符号が固定された単一の法的選択肢と一致します。 この例は、完全な符号ベクトルをカウントし、最後にのみ正規化する理由を示しています。 

サンプル 2 の場合、```
4
4 9 25 49
```平方根は (2,3,5,7) です。 どのような記号もその和をゼロにすることはできません。 分割は (2+2) です。 

| ステージ | 左符号付き合計 | 右符号付きの合計 | マッチング結果 |
 | --- | --- | --- | --- |
 | 変換 | (2,3) の代表 | (5,7) の代表 | 0 |
 | 左の列挙 | (2+2=4)、(2-3=-1)、(-2+3=1)、(-2-3=-5) | まだ | 4つの合計 |
 | 右の列挙 | 格納された補数 | (5+7=12)、(5-7=-2)、(-5+7=2)、(-5-7=-12) | 0 |
 | 最終部門 | 0 | 0 | 0 |

 このトレースは、基本的な中間者不変条件を示しています。 すべての完全な割り当ては、正反対のモジュールである左和と右和に分割する必要があります。 ここにはそのようなペアは存在しません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(D+n\log P+n2^{n/2})) | (D) は入力桁の合計数です。 べき乗剰余コスト (O(\log P)) が値ごとに発生し、2 つの半分には最大で (2^{18}) 個の合計が含まれます。 
| スペース | (O(2^{n/2})) | 頻度ディクショナリには、最大 (2^{18}) 個の個別の左半分の合計と、生成された合計配列が格納されます。 

(n=36) の場合、中間者側には最大で (262,144) の割り当てがあります。 これは、総当たり攻撃による割り当て (687 億件) よりも桁違いに小さいです。 100,000 桁の境界は、入力サイズが線形である最初の 10 進解析にのみ影響します。 このアルゴリズムでは、これらの巨大な整数を因数分解したり構築したりすることはありません。 

モジュラー構造はハッシュ スタイルの有限体削減であるため、理論的な方法では絶対的な決定性が保証されるのではなく、衝突確率が無視できます。 固定素数は意図したコンテスト設定に対して十分な大きさであり、この手法はこの問題に使用される標準的なアプローチです。

    old_input = globals().get("input")

        old_stdout = sys.stdout

 すべて等しい場合は、合計が存在するかどうかのみを格納する辞書実装を捕捉する場合に特に便利です。 複数の符号パターンは同じ合計を生成するため、それらの頻度を累積する必要があります。 

大規模テストでは、まったく異なる種類の間違いが見つかります。 値には 100,001 の 10 進数が含まれていますが、解では剰余モジュロ (P) のみが維持されます。 Python の大きな整数の変換や因数分解は必要ありません。 

## 特殊なケース

 最初のエッジケースでは、```
2
1 1
```変換された値は同一です。 4 つの完全な符号の割り当てには、(+,+) と (-,-) という 2 つのゼロ和が含まれます。 他の 2 つはゼロ以外の合計を返します。 アルゴリズムは 2 つの一致するペアを記録し、2 で割って (1) を生成します。これは、必要な (+\sqrt1-\sqrt1) に対応します。 

2 番目のエッジケースでは、```

最も微妙なエッジ ケースは、(\sqrt2) などの非正方形の根号です。 (2) は 2 次の非剰余である可能性があるため、べき乗剰余は整数法 (P) の通常の平方根を常に返すとは限りません。 これはメソッドのバグではありません。 この構築は、根号の有限体類似物を意図的に使用しており、非剰余の場合は固定二次拡張係数に寄与します。 すべての項にはすでに独立した (+) または (-) の選択肢があるため、これらの固定方向によって符号付きゼロの組み合わせの数は変わりません。 これが、モジュラー トリックが他の方法では不可能な平方自由因数分解を置き換えることができる主な理由です。
