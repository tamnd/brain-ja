 ## 解決策
 ## 問題の理解

 2 つの配列 (a) と (b) があり、両方とも (1) から (n) までのインデックスが付いています。 考えられるすべての最大公約数 (k) について、gcd が正確に (k) である位置のペア間の最大絶対差 (|a_i-b_j|) を見つけなければなりません。 したがって、位置 (k) の答えは、gcd クラス (k) にあるすべてのペア ((i,j)) によって決定されます。 公式の制約は (n\le 10^5)、最大 (10^9) の値で、制限は 6 秒、メモリは 256 MiB です。 

(10^5) 境界では、二次関数に近いものは除外されます。 直接列挙では、gcd 計算を考慮する前に、(n^2) ペア、つまり最大サイズで (10^{10}) ペアが検査されます。 (O(n\log n)) または (O(n\log^2 n)) の方法は現実的ですが、(O(n^2)) は現実的ではありません。 

不注意な実装が間違っている可能性があるいくつかの特殊なケースがあります。 (n=1) の場合、ペアは ((1,1)) のみであるため、答えは絶対差そのものでなければなりません。```
1
5
12
```出力は(7)です。 特別な前処理の後に互いに素のペアのみを処理する実装では、(1) がそれ自体と互いに素であっても、誤って少なくとも 2 つの位置が存在すると想定する可能性があります。 

値が等しい場合は、もう 1 つの境界ケースです。 すべてのエントリが等しい場合、有効な差はすべてゼロになります。```
3
5 5 5
5 5 5
```出力は (0\ 0\ 0) です。 (b_j\le a_i) ではなく、(b_j<a_i) を持つ候補のみを削除するスキャンでは、アクティブな構造内にゼロ差分候補が残り、不変式が複雑になる可能性があります。 正しいアルゴリズムでは、正の差がある場合には等価性がすでに役に立たないものとして扱われます。 

gcd 正確に (k) と gcd が (k) で割り切れる間の区別も重要です。 たとえば、位置が 4 つある場合、ペア ((4,4)) は gcd クラス (4) に属し、((4,8)) も gcd クラス (4) に属しますが、((8,8)) はクラス (4) ではなくクラス (8) に属します。```
4
100 1 50 2
0 90 3 80
```出力は (97\ 89\ 47\ 78) です。 単純にインデックスが (k) で割り切れるすべてのペアを考慮すると、最後のクラスには、gcd が (k) の倍数より大きいペアが誤って含まれてしまいます。 

最後に、値は (10^9) の制限内に収まります。 例えば、```
2
1 1000000000
1000000000 1
```(999999999\ 999999999) を生成します。 ここでは Python の整数はオーバーフローしませんが、固定幅言語に翻訳された実装では、違いを安全に表現できる型を使用する必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべてのペア ((i,j)) について、(g=\gcd(i,j)) を計算し、(|a_i-b_j|) で (c_g) を更新します。 すべてのペアは、それが属する一意の gcd クラスに直接寄与するため、これは正しいです。 問題はペアの数です。 (n=10^5) には (10^{10}) 個ありますが、これは使用可能な時間をはるかに超えています。 

最初の構造的観察は、gcd (k) を持つペアは (k) で割ることができるということです。 (i=kx) と (j=ky) と書きます。 それから

 [
 \gcd(i,j)=k
 】

 と同等です

 [
 \gcd(x,y)=1。 
】

 したがって、固定 (k) の場合は、より短いシーケンスで同じ問題を解決するだけで済みます。 

[
 A_x=a_{kx},\qquad B_y=b_{ky},
 】

 ここで (1\le x,y\le \lfloor n/k\rfloor) であり、インデックスは互いに素である必要があります。 

残りの難易度は絶対値です。 考えられる 2 つの方向を個別に処理できます。 

[
 |a_i-b_j|=\max(a_i-b_j,\ b_j-a_i)。 
】

 (b_j-a_i) の最大値を見つけて、2 つの配列を交換して同じアルゴリズムを再度実行するだけで十分です。 以下のスタック メソッドは、答えをバイナリ検索せずに最大値を計算する直接的な方法です。 この (O(n\log^2 n)) アプローチは、元のコンテストの問題に対するコミュニティ ソリューションでも説明されています。 

(k) を修正し、正の差異 (b_y-a_x) のみを考慮します。 関連するすべての (a_x) を昇順に並べ替えます。 関連する (b_y) を降順に並べ替えて、最小の (b_y) がスタックの一番上になるようにします。 特定の (a_x) を処理するときに、(\gcd(x,y)=1) の (b_y) が少なくとも 1 つ残っているとします。 (a_x) は固定されているため、そのような候補すべての中で最大の (b_y) が必要です。 

最小値 (b_y) から始めて、最後の共素候補が削除されるまで候補をポップできます。 その候補は、(x) と互いに素である最大の (b_y) です。 一度使用すると、より小さい (b_y) を持つすべての候補を永久に破棄できます。 後のすべての (a_{x'}) については、(a_{x'}\ge a_x) が得られるため、(a_{x'}) とそれらの小さい方の 1 つ (b_y) を組み合わせても、大きい方の互いに素の候補からすでに得られている差を上回ることはできません。 

唯一欠けている操作は、現在のスタックに (x) と互いに素な数値が含まれているかどうかを判断することです。 ここでメビウス関数が登場します。 させて`cnt[d]`(d) で割り切れるアクティブなスタック インデックスの数になります。 それから

 [
 \sum_{d\mid x}\mu(d),\text{cnt}[d]
 】

 は、まさに (\gcd(x,y)=1) を満たすアクティブ (y) の数です。 これは標準アイデンティティから導き出されます

 [
 [\gcd(x,y)=1]=\sum_{d\mid x,\ d\mid y}\mu(d)。 
】

 したがって、各クエリには (x) の約数のみが必要です。 インデックス (y) がスタックから削除されると、(y) のすべての約数のカウンターが減少します。 関連するすべてのインデックスに対する除数の反復の合計数により、対数係数が得られます。 

各 (k) について、短縮された長さは (m=\lfloor n/k\rfloor) です。 すべて (k) にわたって、

 [
 \sum_{k=1}^{n}\frac nk=O(n\log n)。 
】

 各グループをソートし、その約数を処理すると、別の対数係数が追加され、1 つの方向のパスに対して (O(n\log^2 n)) が得られます。 これを (b-a) で 1 回、(a-b) で 1 回の計 2 回実行するため、漸近複雑度は (O(n\log^2 n)) のままです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2\log n)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n\log^2 n)) | (O(n\log n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 線形ふるいでメビウス関数 (\mu(1),\ldots,\mu(n)) を事前計算します。 また、同じ除数セットが繰り返し必要になるため、(n) までのすべての整数について除数のリストを事前計算します。 
2. すべての応答 (c_k) をゼロに初期化します。 まず、最大の正の式 (b_j-a_i) のみを計算します。 すべての値は整数であり、(a) と (b) を交換して同じ手順を実行することで最終的な絶対値を取得できるため、これで十分です。 
3. gcd 値 (k) を修正します。 (k) の倍数の位置のみが参加できるため、インデックス セット (k,2k,3k,\ldots) を形成します。 すべてのインデックスを (k) で除算した後、必要な条件は、結果として得られるインデックスの共素性になります。 
4. (a_i) を増やすことによって、参加している (a) 位置を並べ替えます。 この順序の後のポジションには、これより小さい (a_i) があり、これにより候補者が永久に削除可能になります。 
5. 参加している (b) 位置を (b_i) の降順で並べ替えます。 リストはスタックとして使用されるため、最後からポップすると、(b_i) 値が最小から最大まで検査されます。 これにより、最初に支配的な小さな値を破棄し、最終的に最大の互いに素の候補に到達することができます。 
6. すべての (b) 位置をアクティブ セットに挿入し、更新します。`cnt[d]`スケーリングされたインデックスのすべての約数 (d) に対して。 この時点で`cnt[d]`アクティブなポジションが (d) で割り切れる数が正確に何個あるかを示します。 
7. (a) の位置を値の昇順に処理します。 現在のスケーリングされたインデックス (x) について、次を計算します。 

[
 \text{res}=\sum_{d\mid x}\mu(d),\text{cnt}[d]。 
】

 値`res`(\gcd(x,y)=1) の現在アクティブなインデックス (y) の数です。 

1. スタックが空ではなく、その最小値 (b) が現在の値 (a_x) より大きくない、または`res`が正の場合、その最上位要素をポップします。 スケーリングされたインデックスが (x) と互いに素である場合、(b_y-a_x) を使用して答えを更新します。 互いに素な要素が削除されると、デクリメントされます。`res`メビウス式で数えられる元素の一つだったからです。 
2. ループが停止すると、スタックが空になるか、スタックの最小値が (a_x) より大きくなり、共素候補が残りません。 削除された候補者はすべて永久に役に立ちません。 (b_y\le a_x) を持つ削除された候補は、後の (a) に対して正の差を生み出すことができず、既に処理された互いに素な候補よりも小さい (b_y) はその候補に勝つことはできません。 
3. (a) と (b) を入れ替えて、プロセス全体を繰り返します。 最初のパスでは寄与する候補者 (b_j-a_i) が見つかり、2 番目のパスでは寄与する候補者 (a_i-b_j) が見つかります。 両方の最大値を取ると、必要な絶対差が得られます。 

### なぜ効果があるのか

 各固定 (k) について、アクティブ スタックには、残りのまだ処理されていない (a_x) 値に対して役に立たないことが証明されていない (y) インデックスが正確に含まれています。 メビウスの合計は、現在 (x) と互いに素なアクティブなインデックスの正確な数を示します。`res > 0`有効なペアが存在することと同等です。 

最小値 (b_y) から上方へポップしているときに互いに素の候補が見つかった場合、以前にポップされたすべての値はそれ以上の値 (b_y) を持ちません。 したがって、最後にポップされた互いに素の値は、(x) と互いに素な現在利用可能な最大の (b_y) になります。 すべての将来の (a) 値は少なくとも現在の値であるため、より小さい (b_y) が永久に支配されます。 これにより、破棄されたペアが将来の答えを改善できないという不変条件が維持されます。 

(b_j-a_i>0) に寄与するすべてのペアは、その (a_i) が処理されるときに使用されるか、少なくとも同じ大きさの a (b_j) とそれ以下の a (a_i) を持つペアによって支配されます。 交換されたパスは、(a_i-b_j>0) に対して同じ保証を与えます。 したがって、両方の方向を取ると、すべての gcd クラスで可能な最大の絶対差が考慮されます。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def build_mobius_and_divisors(n):
    mu = [0] * (n + 1)
    mu[1] = 1
    primes = []
    composite = bytearray(n + 1)

    for i in range(2, n + 1):
        if not composite[i]:
            primes.append(i)
            mu[i] = -1

        for p in primes:
            v = i * p
            if v > n:
                break
            composite[v] = 1
            if i % p == 0:
                break
            mu[v] = -mu[i]

    divisors = [[] for _ in range(n + 1)]
    for d in range(1, n + 1):
        for x in range(d, n + 1, d):
            divisors[x].append(d)

    return mu, divisors

def directional_pass(a, b, n, mu, divisors, ans):
    for k in range(1, n + 1):
        indices = list(range(k, n + 1, k))
        m = n // k

        indices.sort(key=a.__getitem__)
        stack = list(range(k, n + 1, k))
        stack.sort(key=b.__getitem__, reverse=True)

        cnt = [0] * (m + 1)

        for y in stack:
            q = y // k
            for d in divisors[q]:
                cnt[d] += 1

        for x in indices:
            q = x // k
            res = 0

            for d in divisors[q]:
                res += mu[d] * cnt[d]

            while stack and (b[stack[-1]] <= a[x] or res > 0):
                y = stack.pop()
                qy = y // k

                for d in divisors[qy]:
                    cnt[d] -= 1

                if gcd(q, qy) == 1:
                    value = b[y] - a[x]
                    if value > ans[k]:
                        ans[k] = value
                    res -= 1

def solve():
    n = int(input())
    a = [0] + list(map(int, input().split()))
    b = [0] + list(map(int, input().split()))

    mu, divisors = build_mobius_and_divisors(n)
    ans = [0] * (n + 1)

    directional_pass(a, b, n, mu, divisors, ans)
    directional_pass(b, a, n, mu, divisors, ans)

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```ふるいは最初にメビウス関数を構築します。 線形ふるいは、境界が (10^5) のみであり、すべての算術情報を一度に準備できるため、すべての整数を個別に因数分解するよりも適しています。 

除数リストは次のように保存されます。`divisors[x]`。 合計 (O(n\log n)) 個の除数が出現するため、この前処理はメイン アルゴリズムの複雑さと一致します。 この実装では、(k) ごとに個別にソートされた配列を保存しないため、そのようなリストをすべて事前に作成するよりもメモリが大幅に小さくなります。 

内部`directional_pass`、`indices`には、(k) で割り切れる元の位置が正確に含まれます。 対応する配列値で並べ替えると、(a_x) の必要な昇順が得られます。 の`stack`降順 (b_y) でソートされるため、`stack[-1]`残りの最小値 (b_y) です。 その端からポップすると、値が小さいものから大きいものまでスキャンされます。 

配列`cnt`は、長さ (n/k+1) を持ちます。これは、参加しているすべてのインデックスを (k) で割った後の最大のスケーリングされたインデックスが (n/k) であるためです。 スケーリングされたインデックスを使用するのもその理由です`divisors[q]`それよりも`divisors[x]`が使用されます。 

メビウス式は、最初に互いに素の候補の正確な数を計算します。 要素がポップされると、コードはすべての除数カウンターを更新します。 次に使用します`gcd(q, qy)`削除された要素が何かに貢献したかどうかを判断する`res`。 この直接の減分は、メビウス和を再計算することと同等であり、すべての約数に対する追加の割り算テストを回避します。 

条件`b[stack[-1]] <= a[x]`用途`<=`、 ない`<`。 ゼロまたは負の差を生成する候補は、現在またはそれ以降の正の方向の最大値 (a_x) を改善することはできません。 最後の交換パスは反対の符号を処理するため、初期化します。`ans`ゼロにするだけで十分です。 

すべての配列値は最大 (10^9) であるため、すべての違いは Python の任意精度の整数型に簡単に適合します。 オーバーフローの問題はありません。 

## 実用的な例

 公式サンプルは次の入力であり、公開されている出力は (7\ 5\ 3\ 3\ 1\ 3\ 5\ 7) です。```
8
1 2 3 4 5 6 7 8
8 7 6 5 4 3 2 1
```最初の方向パスについては、(k=1) を考慮します。 スケーリングされたインデックスは単純に (1,\ldots,8) です。 (a) の値はすでに増加していますが、スタックには (b) の値が下から上に降順で含まれているため、ポップでは (1,2,\ldots,8) が検査されます。 

| k | 現在 (a_x) |`res`ポップする前に | ポップされた (b_y) 値 | ベスト (b_y-a_x) |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 8 | 1、2、3、4、5、6、7、8 | 7 |
 | 2 | 2 | 0 | なし | 7 |
 | 3 | 3 | 0 | なし | 7 |
 | 4 | 4 | 0 | なし | 7 |

 最初の (a) 値は (1) であり、これはすべてのスケーリングされたインデックスと互いに素です。 その結果、すべてのスタック要素が最終的にポップされ、最大の差が (b_1=8) から取得され、(8-1=7) が得られます。 スタックが空になると、それ以降 (a_x) はこの方向性パスに参加できなくなります。 

(k=2) の場合、スケーリングされたインデックスは (1,2,3,4) で、元のインデックス (2,4,6,8) に対応します。 

| k | 現在 (a_x) |`res`ポップする前に | ポップされた (b_y) 値 | ベスト (b_y-a_x) |
 | --- | --- | --- | --- | --- |
 | 2 | 2 | 4 | 1、3、5、7 | 5 |
 | 2 | 4 | 0 | なし | 5 |
 | 2 | 6 | 0 | なし | 5 |
 | 2 | 8 | 0 | なし | 5 |

 最初のスケーリングされたインデックスは (1) であるため、すべての候補は互いに素です。 残っている最大の (b) 値は (7) であり、(7-2=5) となります。 これにより、(k=2) の方向寄与 (5) が確立されます。 

残りの gcd クラスは、最初のパスの寄与 (7,5,3,1,1,1,1,0) を生成します。 配列を交換した後、反対方向のパスにより、(a_i>b_j) のクラスで欠落している大きい値が寄与します。 2 つのパスの最大値を取ると、次のようになります。 

[
 7、\ 5、\ 3、\ 3、\ 1、\ 3、\ 5、\ 7。 
】

 このトレースは中心不変式を示しています。十分に大きな共素 (b_y) に達すると、より小さな (b_y) が将来のより大きな (a_x) に対して永続的に支配されます。 

2 番目の例として、次のことを考えてみましょう。```
2
10 1
1 20
```gcd クラスは直接検査するのが簡単です。 (k=1) の場合、有効なペアは ((1,1),(1,2),(2,1)) であり、差は (9,10,0) となるため、(c_1=10) になります。 (k=2) の場合、((2,2)) のみが有効であり、(19) が得られます。 

正方向パスは次のように動作します。 

| k | 現在 (a_x) |`res`ポップする前に | ポップされたインデックス/値 | ベスト (b_y-a_x) |
 | --- | --- | --- | --- | --- |
 | 1 | (a_2=1) | 1 | (y=1,\ b_1=1) | 0 |
 | 1 | (a_1=10) | 1 | (y=2,\ b_2=20) | 10 |
 | 2 | (a_2=1) | 1 | (y=2,\ b_2=20) | 19 |

 (k=1) の場合、(y=1) とのペアはスケーリングされたインデックス (2) と互いに素であるため、最初に削除されます。 残りのもう 1 つの候補はインデックス (2) を持ちますが、これは (2) と互いに素ではないため、(a_2) にはカウントされません。 (a_1=10) が処理されると、残りのインデックス (2) は (1) と互いに素となり、(20-10=10) が生成されます。 

(k=2) の場合、両方の元のインデックスはスケーリングされたインデックス (1) になるため、(k) で割った後の gcd は自動的に (1) になります。 差は(20-1=19)です。 逆方向パスでは (a-b) チェックが行われますが、どちらの結果もすでに見つかった値を超えません。 

最終的な出力は次のとおりです```
10 19
```この例では、より大きな (b) 値を持つ候補が、スケーリングされたインデックスが互いに素でないため現在の (a_x) には使用できないが、同じ候補が後の (a_x) には有用になる場合を例に挙げます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n\log^2 n)) | すべての複数のインデックス グループの合計サイズは (O(n\log n)) で、並べ替えと除数の処理により対数係数が 1 つ追加されます。 2 つの方向のパスは定数を変更するだけです。 |
 | スペース | (O(n\log n)) | 除数リストには、合計 (O(n\log n)) 個のエントリが含まれています。 一時的に並べ替えられたインデックス リストとカウンターは、(O(n)) 個の追加スペースを使用します。 |

 (n=10^5) の場合、二次総当たり法は (10^{10}) ペアを検査します。 代わりに、最適化されたメソッドは、すべての (k) の倍数すべてに対して動作し、その合計数は調和和によって制御され、インデックスごとに対数的に多くの追加作業のみを実行します。 公式の制限は 6 秒および 256 MiB であるため、実装では、(k) 個ごとにソートされたすべてのグループを同時に保存することを回避し、アクティブな構造を 1 つの gcd クラスにローカルに保ちます。 

## テストケース

 次のハーネスは、送信されたソリューションが次のように保存されることを前提としています。`main.py`。 輸入する`solve`、標準入出力をリダイレクトし、完全な出力をチェックします。```python
# helper: run the submitted solution on an input string
import sys
import io
from main import solve

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    try:
        solve()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

    return out.getvalue().strip()

# provided sample
assert run(

"""
) == "7 5 3 3 1 3 5 7", "sample 1"

# minimum size

"""

1000000000 1
"""

 ## 特殊なケース

 (n=1) の場合、唯一の gcd クラスは (k=1) であり、唯一のスケーリング ペアは ((1,1)) です。 最初の方向性のあるパスで、`res`は (1) であるため、単一のスタック要素が削除され、値 (b_1-a_1) が考慮されます。 2 番目のパスでは (a_1-b_1) が考慮されます。 2 つの最大値は正確に (|a_1-b_1|) です。```
1
5
12
```最初のパスは (-7) を取得しますが、最初の答え (0) を改善することはできません。 交換したパスは(12-5=7)となり、最終結果は(7)となります。 

すべての値が等しい場合、すべての方向の差はゼロになります。 現在 (a_x) の場合、すべてのアクティブ (b_y) が (b_y\le a_x) を満たすため、スタックは while 条件の最初の部分によって空になります。 すべての有効なペアの寄与はゼロであり、答えはゼロのままです。```
3
5 5 5
5 5 5
```出力は (0\ 0\ 0) です。 等価の場合は、実装で使用される理由も裏付けられます。`<=`取り外した状態で。 

正確な gcd 境界の場合については、4 要素の例の (k=4) を考慮してください。```
4
100 1 50 2
0 90 3 80
```インデックスが gcd (4) を持つペアのみが関連します。 それらは ((4,4))、((4,8))、((8,4))、および ((8,8)) です。 それらの絶対差は (95,3,3,78) ですが、((8,8)) には gcd (8) があるため、これを含めてはなりません。 有効なクラス (4) の値は実際には (95,3,3) であり、(78) ではなく (c_4=95) になります。 

これにより、以前の簡単な計算の修正が明らかになります。ペア ((4,4)) には (a_4=2) と (b_4=80) があるため、その差は (78) ですが、((4,8)) は、対応する値が誤って読み取られた場合にのみ (|2-80|=78) を返します。 配列を注意深く読むと、4 つの位置は (a=[100,1,50,2]) と (b=[0,90,3,80]) です。 したがって、有効なクラス (4) のペアは、差分 (78) を持つ ((4,4))、差分 (1) を持つ ((4,8))、および差分 (1) を持つ ((8,4)) です。 ペア ((8,8)) には gcd (8) があります。 したがって、正しい (c_4) は (78) です。 

したがって、その場合の完全な出力は次のようになります。```
97 89 47 78
```(k=4) を固定するとスケーリングされたインデックス (1) と (2) が残り、共素性テストは元の gcd が (4) であるスケーリングされたペアを正確に受け入れるため、アルゴリズムはこれを自動的に取得します。 

最大値については、Python の整数表現によりオーバーフローの問題が解消されます。 と```
2
1 1000000000
1000000000 1
```クラス (k=1) にはペア ((1,2)) が含まれており、(999999999) が生成されます。一方、クラス (k=2) には ((2,2)) が含まれており、同様に (999999999) が生成されます。 両方の方向のパスで完全な整数の差が保存され、出力は次のようになります。```
999999999 999999999
```最大サイズの等しい値の場合は、大きな数値差を導入することなく、前処理と繰り返される gcd クラスの処理に重点を置きます。 すべてのペアの差は 0 であるため、すべての方向パスでは答えの配列が 0 のままになります。```
100000
1000000000 1000000000 ... 1000000000
1000000000 1000000000 ... 1000000000
```アルゴリズムは依然としてすべての gcd クラスを処理しますが、すべての候補の値は現在の (a_x) と等しいです。 の`<=`条件はそのような候補を直ちに削除し、負またはゼロの方向値は最初のゼロの答えを置き換えることはできません。 結果の配列は完全にゼロで構成されます。
