 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 私たちは、すべての位置の値が変化するが、合計はまったく同じままになる、同じ長さの別の配列を構築できるかどうかを知りたいと考えています。 

2 番目の配列は任意ではありません。 各位置は元の位置と異なっている必要がありますが、すべての要素を合計しても全体的には何も変わりません。 この質問は純粋に存在に関するものです。配列を構築する必要はなく、そのような再配置が存在するかどうかを判断するだけです。 

制約はテスト ケースの数と配列の合計サイズが大きいため、ソリューションはテスト ケースごとに線形である必要があります。 すべてのテストの要素の合計数が$10^5$。 

主な微妙な点は、これが順列や再配置に関するものではないということです。 新しい配列は、正の値を尊重し、合計を不変に保つ限り、値を自由に変更できます。 これは、ローカルなマッチングの問題ではなく、グローバルなバランスの問題になります。 

よくある失敗例は次のような場合に発生します。$n=1$。 その場合、同じ合計を持つ唯一の可能な配列は配列自体であるため、条件を満たすことは不可能です$a_1 \ne b_1$。 もう 1 つの重要なエッジ ケースは、すべての要素が等しい場合です。$n$は小さいため、合計制約を注意深くチェックしない限り、「値を移動する」という直感が誤った結論につながることがよくあります。 

## アプローチ

 ブルートフォースパースペクティブは、残りの合計を追跡しながら、各位置に元の値とは異なる新しい値を割り当てようとします。 考えられるすべての代入を反復することを想像することもできますが、各位置には無限に多くの有効な正の整数があるため、列挙は有限の意味でさえ明確に定義されていません。 配列内に現れる値、または合計によって制限される値に限定したとしても、可能性の数は次のように指数関数的に増加します。$n$そのため、このアプローチは非常に小さな入力を超えると実行不可能になります。 

重要な点は、配列を明示的に構築する必要がないということです。 和の制約と「インデックスごとに固定小数点がない」制約を同時に満たせるかどうかを判断するだけで済みます。 合計制約により、すべてのポジションにわたる合計の増減が正確に相殺されます。 これは、少なくとも 1 つの要素を増加し、少なくとも 1 つの要素を減少させる必要があることを直ちに示唆しており、そうでない場合、合計は変更されないままにすることができません。 

次の場合、構造は特に硬くなります。$n=1$再配布ができないためです。 いつ$n \ge 2$、値をある位置から別の位置にシフトすることはいつでも可能です。つまり、要素を 1 つ減らします。$1$そしてもう一つを増やす$1$、すべての要素を正に保ち、どの位置も元の値を保持しないようにします。 ずっと$a_i \ge 1$、少なくとも 1 つの要素を減らす余地が常にあります。 

したがって、問題は完全に次の点に基づいた単純な二分法に崩壊します。$n$。

 | --- | --- | --- | --- |
 | ブルートフォース | 明確に定義されていない | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列のサイズを読み取る$n$。 
2. もし$n = 1$、すぐに「NO」を出力します。 単一要素の場合、合計制約により次のことが強制されます。$b_1 = a_1$に違反します$a_1 \ne b_1$。 
3. もし$n \ge 2$、「YES」を出力します。 この場合、1 つの要素を減らして別の要素を増やし、正の値を維持して合計を維持することで、常に有効な配列を構築できます。 
4. すべてのテスト ケースに対して繰り返します。 

### なぜ効果があるのか

 合計制約により、総質量が保持されることが強制されます。 少なくとも 2 つのポジションがあれば、1 つのユニットを 1 つのインデックスから別のインデックスに再分配できます。 これにより、少なくとも 1 つのインデックスが生成されます。$b_i < a_i$そして一つはどこ$b_j > a_j$、不等式条件と合計の保存の両方を保証します。 いかなる指数の低下も他の部分で補うことができるため、変更を強制されることはありません。 のために$n=1$、そのような再分配は不可能であるため、制約は互換性がなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    input().split()  # values not needed
    if n == 1:
        print("NO")
    else:
        print("YES")
```実現可能性は配列の長さのみに依存するため、このソリューションでは実際の配列値を意図的に無視しています。 唯一意味のある決定は、少なくとも 2 つのインデックスにわたる再分配が可能かどうかです。 

ここでよくある間違いは、パリティや要素構造を分析しようとすることですが、それはどれも重要ではありません。 合計制約は、少なくとも 2 つの自由度を必要とする以上に実現可能性を制限するものではありません。$n \ge 2$提供します。 

## 実用的な例

 異なるサイズのいくつかのケースを含む入力を考えてみましょう。 

のために$n=3$、次のような任意の配列$[1,5,9]$十分な柔軟性を持っています。 再配布が存在するため、答えは「YES」です。 

のために$n=1$、 のような$[1]$、同じ合計を持つ代替の正の整数はそれ自体以外に存在しないため、答えは「NO」です。 

もう一つのために$n=3$のようなケース$[1,2,3]$、いつでも次のような新しい配列を構築できます。$[2,1,3]$またはバランスの取れたシフトなので、答えは再び「YES」です。 

| テストケース | n | 決定 | 理由 |
 | --- | --- | --- | --- |
 | [1、5、9] | 3 | はい | 再配布可能 |
 | [1] | 1 | いいえ | sum は同一の配列を強制します |
 | [1、2、3] | 3 | はい | スワップ的な調整が可能 |

 これらのトレースは、値の分布ではなく、配列のサイズのみが重要であることを確認します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        input().split()
        out.append("NO" if n == 1 else "YES")
    return "\n".join(out)

## 特殊なケース

 のために$n=1$場合、アルゴリズムはすぐに「NO」を返します。 同じ合計を持つ唯一の可能な候補配列は元の配列と同一であるため、不等式制約を満たすことができません。 

のために$n=2$の場合、アルゴリズムは「YES」を返します。 のような入力の場合$[10,10]$、構築できます$[11,9]$、合計を保持し、両方の位置を変更します。 これは、価値を再分配するには少なくとも 2 つのポジションがあれば十分であることを裏付けています。 

次のようなより大きな均一配列の場合$[1,1,1,1,1]$の場合、正の値と合計を維持しながら常に 1 つの単位をある位置から別の位置に移動でき、変更されない要素がないことが保証されるため、アルゴリズムは「YES」を返します。
