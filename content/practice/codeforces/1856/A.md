 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 Alphe は 1 つの演算を繰り返し実行でき、配列のすべての要素が 1 ずつ減りますが、ゼロ未満になる要素はありません。 彼は、配列が減少しなくなるまで、つまり各要素が少なくともその前の要素と同じ大きさになるまで、この操作を実行し続けます。 私たちのタスクは、各テスト ケースにこの操作を何回適用する必要があるかを決定することです。 

配列の長さは小さく、最大 50 要素ですが、要素の値は最大 50 個まで大きくなる可能性があります。$10^9$。 これは、すべての要素を段階的に減少させる単純なシミュレーションでは、最悪の場合、時間がかかりすぎることを意味します。 たとえば、次の要素が 1 つある配列は、$10^9$必要になるだろう$10^9$直接シミュレートした場合の操作。 したがって、各操作を個別に実行しないアプローチが必要です。 

明らかではないエッジケースは、配列がすでに非減少特性を満たしている場合に発生します。`[1, 2, 3]`。 答えはゼロでなければなりません。 もう 1 つの微妙なケースは、最初の要素が配列内で最大である場合です。たとえば、`[1000000000, 1, 2]`。 配列がゼロから始まるまですべての要素が同時に減らされるため、演算の数は正確に最初の要素になります。 これを考慮しない単純なアプローチは失敗します。 

## アプローチ

 ブルートフォースアプローチは簡単です。 テスト ケースごとに、配列がソートされるまですべての要素を 1 ずつ減らすという操作を繰り返し実行できます。 各操作では、減算を適用するために配列全体をスキャンする必要があり、配列がソートされているかどうかを確認する必要があります。 最悪の場合、最大の要素が$10^9$、これにはかかります$10^9 \times n$ステップが大きすぎます。 

重要な点は、操作がすべての要素に均一に影響を与えるということです。 各演算の後、いずれかの要素がゼロになるまで、すべての要素が 1 ずつ減少します。 配列が減少しなくなることだけを考慮しているため、必要な演算数は、最初の要素を残りの要素の最大値以下にするために必要な最大のドロップによって決まります。 より具体的には、最初の要素がその最大値より大きい場合、答えは最初の要素を除いた配列内の最大要素になります。 配列がすでに非減少である場合、操作は必要ありません。 

この観察により、問題は、テスト ケースごとに 1 回配列をスキャンし、最大値を見つけて、最初の要素との差を計算することに帰着します。 各操作のシミュレーションを回避し、数値が大きくても機能します。$10^9$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * max(a_i)) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取り、$t$。 
2. 各テスト ケースについて、次の内容を読んでください。$n$そして配列$a$。 
3. 配列がすでに非減少であるかどうかを確認します。 そうであれば、答えは 0 です。最大要素ロジックに従えば、数式は自動的に 0 を返すため、このステップは省略できます。 
4. 最初の要素を除いた配列の最大要素を見つけます。 これに電話してください`max_rest`。 
5. 最初の要素の場合`a[0]`以下である`max_rest`、配列はすでに非減少であるか、非減少になるためにリダクションを必要としないため、必要な演算数は次のようになります。`max_rest`。 
6. それ以外の場合、`a[0]`より大きい`max_rest`、最初の要素が等しくなるまで、最初の要素と他のすべての要素を削減する必要があります。`max_rest`。 すべての要素が同時に減少するため、必要な演算数はちょうど`a[0]`。 
7. 計算された演算数を出力します。 

**機能する理由**: 各操作では、すべての要素が均一に削減されます。 非減少配列を実現するためのボトルネックは、最初の要素が残りの要素よりも大きい場合です。 最初の要素が残りの要素の最大値以下になると、配列はすでにソートされているか、すべての要素を 0 に減らした後にソートされることになります。 したがって、残りの要素を基準にして最初の要素を追跡することで、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        # Maximum of the rest of the array
        max_rest = max(a[1:]) if n > 1 else 0
        # The answer is either 0 if first element <= max_rest or a[0] otherwise
        if a[0] <= max_rest:
            print(max_rest)
        else:
            print(a[0])

if __name__ == "__main__":
    main()
```このソリューションは、高速 I/O を使用してすべての入力を読み取ります。 計算します`max_rest`インデックス 1 以降の配列の最大値として。 最初の要素との比較により、操作の数が直接決まります。 すべての減少をシミュレートすることは避けます。 単一要素の配列やすでにソートされている配列などのエッジ ケースは、`max`そして比較ロジック。 

## 実用的な例

 サンプル入力 1:`[3, 1 2 3]`| ステップ | 配列 | 最大残り | オペレーション |
 | --- | --- | --- | --- |
 | イニシャル | 1 2 3 | 2 | 0 |

 最初の要素は 1、`max_rest`は 2 です。1 ≤ 2 なので、配列はすでに非減少です。 出力は0です。 

入力例 2:`[3, 1000000000 1 2]`| ステップ | 配列 | 最大残り | オペレーション |
 | --- | --- | --- | --- |
 | イニシャル | 1000000000 1 2 | 2 | 1000000000 |

 最初の要素は 10^9 で、`max_rest`は 2.最初の要素が より大きいため、`max_rest`、配列をソート順に減らすには 10^9 の演算が必要になります。 出力は1000000000です。 

これらのトレースは、アルゴリズムが配列がすでにソートされているか、削減が必要であるかを正しく識別し、テスト ケースごとに一定時間で演算数を計算していることを示しています。
