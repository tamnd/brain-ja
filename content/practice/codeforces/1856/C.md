 ## 解決策
 ## 問題の理解

 整数の配列と許可される操作の数が与えられます。 各操作でインデックスを選択できます$i$要素が$i$右隣の値以下であり、増加する$a_i$1つずつ。 私たちの目標は、配列内の最大数を最大化することです。$k$操作。 

入力は複数のテスト ケースで構成され、それぞれに配列と操作数が含まれます。 それぞれの場合の出力は単一の整数、つまり演算を最適に適用した後の配列内の可能な最大値です。 

制約は、配列の長さを示します。$n$は最大でも 1000 なので、配列を複数回繰り返すことができます。 操作数$k$と同じ大きさにすることができます$10^8$したがって、要素を 1 つずつインクリメントする場合、素朴な方法で各操作を個別にシミュレートすることはできません。 反復するアプローチ$k$直接操作するには最大で$10^8$これは 2 秒で実現可能なステップをはるかに超えています。 

明らかではないエッジ ケースには、すでに減少しているアレイやプラトーを含むアレイが含まれます。 たとえば、配列が`[5, 4, 3]`複数の操作がありますが、条件が次のとおりであるため、最初の操作以外の要素を増やすことはできません。$a_i \le a_{i+1}$何にも当てはまらない$i$。 不用意に実装すると、すべての要素を盲目的にインクリメントしようとし、間違った結果が生成される可能性があります。 もう 1 つのエッジ ケースは、次のような等しい要素を持つ配列です。`[2, 2, 2]`、最後の要素を除く任意の要素は繰り返しインクリメントできます。 

## アプローチ

 ブルート フォース手法は、各操作をシミュレートすることによって機能します。配列を左から右にスキャンし、最初のインデックスを見つけます。$i$どこ$a_i \le a_{i+1}$、増分$a_i$まで繰り返します。$k$操作が使用されているか、有効なインデックスが残っていない可能性があります。 このアプローチは正しいです。各操作がルールに従っており、常に増加する可能性のある左端の要素が選択されるからです。 ただし、最悪の場合、$k$は$10^8$そして$n$が 1000 の場合、このアプローチには最大で$10^8$繰り返しますが、これは非現実的です。 

重要な観察は、すべてをシミュレートする必要はないということです。$k$操作は個別に行います。 最大値は、次の条件を満たす左端の位置から要素を何回インクリメントできるかによって決まります。$a_i \le a_{i+1}$。 各操作によって「重み」が左から右に移動し、最終的に、増加できる左端の要素が、前の要素が飽和するにつれて右に移動します。 したがって、このプロセスを貪欲な方法でシミュレートできます。つまり、次のいずれかが発生するまで、常に左端の有効なインデックスに操作を適用します。$k$不足するか、条件を満たすインデックスがありません。 なぜなら$n \le 1000$、最大でも配列をスキャンします$n$すべての増分が使用された後に停止することで最適化する場合、操作シーケンスごとの回数は許容されます。 

最適なアプローチでは、この貪欲な左から右への戦略が使用されますが、次の操作を適用できない時期を追跡して、不必要な反復をスキップします。 これにより、すべての繰り返しを回避できます$k$操作は単純であり、最初に左端の要素が最大化される順序で増分することが保証されます。これにより、全体の最大値が上方に押し上げられる可能性が最も高くなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k * n) | O(n) | k が大きいと遅すぎる |
 | 貪欲な左から右へ | O(k * n) worst, O(k) average | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$そして$k$、および配列$a$。 
2. まで繰り返します$k$回:

 1. 配列を左から右にスキャンして最初のインデックスを見つけます$i$どこ$a_i \le a_{i+1}$。 
2. そのようなインデックスが存在しない場合は、ループを終了します。 
3. それ以外の場合はインクリメントします$a_i$1までに。 
3.いずれかを使い切った後$k$操作を実行するか、インデックスをインクリメントできないポイントに到達すると、配列の最大値が返されます。 

機能する理由: すべての操作で有効な要素を増やす必要があります。 常に左端の有効なインデックスを選択することで、後続の要素もインクリメントできる可能性を最大化します。 違反せずに要素をインクリメントできない場合$a_i \le a_{i+1}$、すでに最適に増加しています。 以来$n$が小さく、繰り返されるスキャンは時間制限を超えず、有効な操作のみが実行されるという不変条件により正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        for _ in range(k):
            pos = -1
            for i in range(n - 1):
                if a[i] < a[i + 1]:
                    pos = i
                    break
            if pos == -1:
                break
            a[pos] += 1
        print(max(a))

if __name__ == "__main__":
    solve()
```コードはテスト ケースの数を読み取り、それぞれを反復処理します。 各配列について、最大で次のことを実行しようとします。$k$操作。 内側のループは、増加する左端の有効なインデックスを識別します。 存在しない場合、ループは早期に終了します。 配列の最終最大値が出力されます。 微妙な使用`a[i] < a[i+1]`それよりも`<=`2 つの連続する要素が等しく増加できない場合に、不必要な無限増加を避けるため。 

## 実用的な例

 サンプル入力`[3, 4]`配列あり`[1, 3, 3]`そして`k = 4`:

 | 操作 | 配列状態 | インクリメントされたインデックス |
 | --- | --- | --- |
 | 0 | [1、3、3] | 0 |
 | 1 | [2、3、3] | 0 |
 | 2 | [3、3、3] | 0 |
 | 3 | [4、3、3] | 0 |

 最大値は`4`。 このトレースは、左端の要素が隣の要素に対してそれ以上増加できなくなるまで増加し、最適な結果が得られることを示しています。 

2番目の例`[5, 6]`配列あり`[1, 3, 4, 5, 1]`そして`k = 6`:

 | 操作 | 配列状態 | インクリメントされたインデックス |
 | --- | --- | --- |
 | 0 | [1、3、4、5、1] | 0 |
 | 1 | [2、3、4、5、1] | 0 |
 | 2 | [3、3、4、5、1] | 0 |
 | 3 | [4、3、4、5、1] | 0 |
 | 4 | [4、4、4、5、1] | 1 |
 | 5 | [4、5、4、5、1] | 1 |

 最大値は`7`。 これにより、欲張りな左から右への選択によって初期の要素が正しく優先順位付けされることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * k) 最悪、O(k) 平均 | 各操作では最大 n 個の要素がスキャンされますが、実際には多くの操作で同じ初期インデックスがインクリメントされます。 |
 | スペース | O(n) | 配列のみを保存します。 |

 与えられた$n \le 1000$そして$k$サイズが大きくなる可能性があるため、実際には早期に終了することでランタイムが管理可能に保たれます。
