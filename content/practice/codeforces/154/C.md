 ## 解決策
 ## 問題の理解

 ソーシャル ネットワークを表す無向グラフが与えられています。 各頂点はプロファイルであり、各エッジは友情です。 

2 つの異なるプロファイル`i`そして`j`他のすべてのプロファイルがそれらをまったく同じように認識する場合、それらは二重であるとみなされます。 頂点ごとに`k ≠ i, j`、両端のいずれか`(i, k)`そして`(j, k)`存在するか、どちらも存在しません。 二人の友人関係は、`i`そして`j`それ自体はこの定義では重要ではありません。 

グラフ用語で言えば、頂点自体を無視すると、`i`そして`j`同一の近隣が必要です。 唯一微妙なのはエッジの有無です`(i, j)`比較には影響しないはずです。 

この特性を満たす、順序付けされていない頂点のペアがいくつあるかを数えなければなりません。 

制約は非常に大きいです。 両方`n`そして`m`到達できる`10^6`。 100 万個の頂点を持つグラフでは、隣接リストをペアごとに比較するアルゴリズムは直ちに除外されます。 保管しても`n × n`構造的には無理です。 3 秒の制限時間では、線形または`O(m log n)`。 

グラフがまばらなため、`m ≤ 10^6`、完全なグラフは`10^6`頂点にはおおよそ次のものが含まれます`5·10^11`エッジ。 これは、隣接リスト ベースの処理が正しい方向であることを示唆しています。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

孤立した頂点を考慮します。```
4 0
```すべての頂点には同じ近傍、つまり空のセットがあります。 すべてのペアは double なので、答えは次のようになります。```
6
```エッジに現れる頂点のみを処理するソリューションでは、孤立した頂点が完全に忘れられる可能性があります。 

もう 1 つの微妙なケースは、2 つの頂点が相互に接続されているという理由だけで異なる場合です。```
2 1
1 2
```答えは次のとおりです。```
1
```3 番目の頂点がないため、この条件は事実上真です。 通常の隣接リストを比較すると、次のようになります。`{2}`対`{1}`、それらは異なります。 近傍を直接比較すると、このペアは誤って拒否されます。 

もう少し大きな例でも同じ現象が示されています。```
3 2
1 3
2 3
```頂点`1`そして`2`どちらも頂点にのみ接続されているため、double になります。`3`。 

次にエッジを追加します`(1,2)`:```
3 3
1 2
1 3
2 3
```頂点`1`そして`2`まだダブルスです。 隣接リストの唯一の違いは相互です。 これを考慮せずに完全な近傍を比較するアプローチは失敗します。 

最も難しいのは、「その他すべての頂点」というフレーズを効率的に処理することです。 

## アプローチ

 最も直接的な解決策は、頂点のすべてのペアを調べることです。`(i,j)`。 各ペアについて、残りのすべての頂点との関係を比較します。 3 つおきの頂点が見える場合`i`そして`j`同様に、ペアを数えます。 

これは定義に文字通り従っているため、正しいです。 残念ながら、あります`O(n²)`ペアであり、それぞれの比較を調べる必要がある場合があります。`O(n)`頂点。 最悪のケースは、`O(n³)`、それはまったく不可能です`n = 10^6`。 

条件を再定式化する必要があります。 

仮定する`N(v)`頂点の近傍の集合を表します`v`。 

頂点の場合`u`そして`v`が隣接していない場合、定義は単純に次のようになります。```
N(u) = N(v)
```どちらの近傍にも他の頂点が含まれていないためです。 

頂点の場合`u`そして`v`が隣接している場合、各近傍には他の頂点が含まれます。 お互いを削除した後、残りの隣接要素は一致する必要があります。```
N(u) \ {v} = N(v) \ {u}
```この観察により、問題は近傍シグネチャによる頂点のグループ化に変換されます。 

課題は、隣接リストには最大 100 万個の頂点が含まれる可能性があるため、セットを直接比較するとコストが高すぎることです。 代わりに、各頂点にハッシュ値を割り当て、そのメンバーのハッシュの合計によって近傍を表します。 

させて`rnd[x]`頂点に割り当てられるランダムな 64 ビット番号である`x`。 

すべての頂点について:```
H(v) = Σ rnd[x]   over all x in N(v)
```圧倒的な確率で、等しい近傍セットは等しい合計を生成し、異なるセットは異なる合計を生成します。 

次に 2 つの場合について考えてみましょう。 

隣接しないダブルの場合は、等しい通常の近傍が必要です。 頂点を単純にグループ化できます。`H(v)`。 

隣接する double の場合は、次のものが必要です。```
N(u) \ {v} = N(v) \ {u}
```同様に:```
H(u) - rnd[v] = H(v) - rnd[u]
```定義する：```
G(u,v) = H(u) + rnd[u]
```次に、次の場合に、隣接する頂点が有効なペアを形成します。```
H(u) + rnd[u] = H(v) + rnd[v]
```これは非常に効率的な戦略につながります。 

まず、同一の頂点のペアをすべて数えます。`H(v)`。 これらは隣接しないダブルです。 

次に、同一の頂点のペアをすべて数えます。`H(v)+rnd[v]`。 これには隣接ペアと非隣接ペアの両方が含まれるため、すべてを追加することはできません。 代わりに、実際のエッジのみを調べます`(u,v)`そして、次のことを確認してください。```
H(u)+rnd[u] = H(v)+rnd[v]
```このようなエッジはすべて、追加の二重ペアを 1 つ追加します。 

グラフには、`m ≤ 10^6`エッジがあるため、この最終チェックは安価です。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | お(1) | 遅すぎる |
 | 最適 | O(n + m) が期待されます | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての頂点にランダムな 64 ビット整数を割り当てます。`rnd[i]`。 
2. 配列を作成する`H`ゼロに初期化されます。 
3. あらゆるエッジに`(u,v)`、 追加`rnd[v]`に`H[u]`そして追加します`rnd[u]`に`H[v]`。 

このステップの後、`H[v]`頂点の近傍のハッシュです`v`。 
4. すべての頂点をグループ化します。`H[v]`。 

グループに次のものが含まれる場合`k`頂点に以下を追加します。```
k(k-1)/2
```答えに。 

これらは、同一の通常の近傍を持つペアです。 
5. すべての頂点について次の計算を行います。```
T[v] = H[v] + rnd[v]
```6. あらゆるエッジに`(u,v)`、次のことを確認します。```
T[u] = T[v]
```true の場合、答えに 1 を追加します。 

これは次のものに正確に対応します。```
H(u)-rnd[v] = H(v)-rnd[u]
```これは、近傍が互いに除去された後は同一になることを意味します。 
7. 最終的なカウントを出力します。 

### なぜ効果があるのか

 隣接していない頂点の場合、二重条件はその近傍セット全体が等しいことと同等です。 ハッシュ`H(v)`のすべての近隣から構築されます`v`したがって、等しい近傍は等しいハッシュを生成します。 等しいハッシュをグループ化すると、それらのペアが正確にカウントされます。 

隣接する頂点の場合、各近傍は他の端点の存在によって異なります。 両側からそのエンドポイントを削除すると、次の条件が得られます。```
N(u)\{v} = N(v)\{u}
```ハッシュ表現はこれを次のように変換します。```
H(u)-rnd[v] = H(v)-rnd[u]
```これは代数的に次と等価です。```
H(u)+rnd[u] = H(v)+rnd[v]
```既存のエッジのみでこの等価性をチェックすると、隣接する二重ペアが正確にカウントされます。 

すべてのダブル ペアはこれら 2 つのカテゴリのいずれかに分類され、どのペアも 2 回カウントされません。 したがって、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
import random
from collections import defaultdict

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    rnd = [0] * (n + 1)
    rng = random.Random(154154)

    for i in range(1, n + 1):
        rnd[i] = rng.getrandbits(64)

    h = [0] * (n + 1)
    edges = []

    for _ in range(m):
        u, v = map(int, input().split())
        edges.append((u, v))

        h[u] += rnd[v]
        h[v] += rnd[u]

    groups = defaultdict(int)

    for i in range(1, n + 1):
        groups[h[i]] += 1

    ans = 0

    for cnt in groups.values():
        ans += cnt * (cnt - 1) // 2

    t = [0] * (n + 1)
    for i in range(1, n + 1):
        t[i] = h[i] + rnd[i]

    for u, v in edges:
        if t[u] == t[v]:
            ans += 1

    print(ans)

solve()
```最初のフェーズでは、ランダムな 64 ビット値をすべての頂点に割り当てます。 これらの値は、近隣の建設の指紋として機能します。 

エッジの読み取り中に、コードは両方のエンドポイントの近傍ハッシュを更新します。 すべてのエッジを処理した後、`h[v]`すべての近傍のフィンガープリントの合計が含まれます。`v`。 

辞書`groups`同じ近傍ハッシュを共有する頂点の数をカウントします。 If a hash appears `
