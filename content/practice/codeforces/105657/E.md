 ## 解決策
 ## 問題の理解

 各タスクは、1 台のエレベーターを使用して開始階から迎えに行き、上の階に降ろす必要がある人を表します。 エレベーターは最初の階から始まり、一度に 1 人しか乗せられません。 上方への移動には移動するフロア数に比例したエネルギーがかかりますが、下方への移動は無料です。 

すべての人は、出発階と目的地の階の間の距離に等しい固定の交通費を負担します。 その部分は避けられないものであり、サービスを受ける順番には依存しません。 注文に依存する唯一の部分は、エレベーターが一人の人を終えてから次の人を開始するまで移動するときの「デッドトラベル」です。特に、前の降車フロアから次のピックアップフロアまで上向きに移動する必要がある場合です。 

したがって、問題は個々の移動を最適化することではなく、エレベーターが連続するジョブ間の不必要な上向きジャンプを回避するようにこれらの移動を調整することです。 

この制約により、テスト ケースごとに最大 100,000 人、合計で最大 300,000 人が許可されます。 これにより、順列に対する二次順序付けの試みが即座に除外されます。 どのソリューションも、ソートに加えて、線形または線形に近い貪欲な構造 (優先キューまたはソートにより、通常は O(n log n)) に依存する必要があります。 

単純なアプローチでは、人々のすべての並べ替えや、貪欲なローカル スワップさえも試行することになります。 コストの相互作用がグローバルであるため、これは失敗します。わずかに悪い次の間隔を選択すると、後でゼロコスト移行の長いチェーンが可能になる可能性があります。 

貪欲な選択が将来の可用性を無視した場合、微妙な失敗のケースが発生します。 

たとえば、次のことを考えてみましょう。```
f = 1
(1, 100), (2, 3), (3, 4)
```最初に (1, 100) を選択すると、100 で終了し、その他はすべて自由になります。 最初に (2, 3) を選択した場合、3 で終了し、無料で (3, 4) を取得できますが、その後、多額のコストを支払って (1, 100) にジャンプする必要があります。 順序付けは非ローカルな方法で重要となるため、将来のアクセシビリティを最大限に保つ構造が必要です。 

## アプローチ

 重要な観察は、各人が乗車距離に等しい一定の費用を負担しているということです。 その部分は注文によって変わることはありません。 唯一の最適化ターゲットは、連続する乗車間の上向きのジャンプの合計です。 

これにより、問題は、各ジョブが現在位置を li から ri に移動する間隔でのスケジューリング タスクに縮小されます。 ジョブが完了すると、システムは ri 状態になります。 次のジョブに移動するには、max(0, next_li − current_position) のコストがかかります。 

ブルートフォースソリューションでは、すべての順列を列挙し、プロセスをシミュレートします。 各シミュレーションは O(n) で、全体では O(n · n!) になりますが、これは n が 10 程度であっても実現可能性をはるかに超えています。 

より良いアプローチですが、依然として間違っているのは、li または ri だけで並べ替えることです。 li の増加による並べ替えは、ピックアップ間のジャンプを減らすため自然に感じられますが、早い段階で低い r 値に陥り、将来の到達範囲が制限され、後で高価なジャンプを強いられる可能性があります。 

正しい構造は、プロセスを「リーチの拡大」問題として見ることから生まれます。 ある程度の地位に就いたら、上昇コストを支払わずにすぐに開始できる仕事、つまり li ≤ 現在の地位を常に優先する必要があります。 その中で、私たちは最も自分を押し上げてくれる仕事を選びたいと思っています。なぜなら、ri が高くても、無料で就ける将来の仕事のセットが増えるだけだからです。 現在到達可能なジョブがない場合は、次に利用可能な li にジャンプする必要があります。 

これにより、ソートされた li をスイープし、ri を優先キューで処理する貪欲なプロセスが発生します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・n!) | O(n) | 遅すぎる |
 | 貪欲 + ヒープ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての人を間隔（リ、リ）として処理します。 ソートされた間隔に対するポインターと、ri をキーとする最大ヒープを維持します。 

1. すべての人々を li の昇順に並べ替えます。 これにより、エレベーターが上昇するにつれてどの仕事が利用可能になるかを効率的に見つけることができます。 
2. 現在位置を開始階 f に初期化します。 
3. ソートされたリストと最大ヒープ上のポインタ i を維持します。 ヒープには、li ≤ 現在の位置を持つすべての人々が、最大の ri によって優先順位付けされて保存されます。 これにより、すぐに実行可能なすべての仕事の中から、自分の範囲を最も広げる仕事を常に選択することができます。 
4. 未処理の人々が存在するか、ヒープが空ではない場合、最初に li ≤ 現在の位置を持つすべての人々をヒープに押し込みます。 これは、追加の移動を支払わずに現在開始できるすべてのジョブを明らかにすることをシミュレートします。 
5. ヒープが空でない場合は、最大の ri を持つ人をポップします。 この人物を出力順序に追加し、概念的にエレベーターを ri に移動します。 li ≤ 現在の位置ではピックアップが無料であることが保証されるため、このステップでは上向きのコストは追加されません。 
6. ヒープが空の場合、現在到達可能なジョブはありません。 次に利用可能なジョブの li まで上に移動する必要があります。 残りのジョブの中で最小の li を選択し、max(0, li − 現在位置) を支払い、そのジョブの処理後に現在位置を ri に設定します。 
7. すべての人が処理されるまで繰り返します。 

### なぜ効果があるのか

 li ≤ 現在の位置を持つすべてのジョブは、即時実行可能性の観点からいつでも交換可能です。 最大の ri を持つものを選択すると、現在のコストを増加させることなく将来の可用性が最大化されるため、他のものよりも厳密に優先されます。 到達可能なジョブがない場合、次の強制ジャンプは避けられず、最小の li を選択することで、必要な上方への移動が最小限に抑えられます。 これにより、すでに支払われたコストを考慮すると、現在のポジションが常に可能な限り大きくなるという不変条件が維持され、将来の不必要な上昇が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    T = int(input())
    for _ in range(T):
        n, f = map(int, input().split())
        people = []
        for i in range(n):
            l, r = map(int, input().split())
            people.append((l, r, i + 1))
        
        people.sort()
        
        ans = []
        heap = []
        i = 0
        cur = f
        
        while i < n or heap:
            while i < n and people[i][0] <= cur:
                l, r, idx = people[i]
                heapq.heappush(heap, (-r, l, idx))
                i += 1
            
            if heap:
                neg_r, l, idx = heapq.heappop(heap)
                ans.append(idx)
                cur = -neg_r
            else:
                l, r, idx = people[i]
                cur = max(cur, l)
                heapq.heappush(heap, (-r, l, idx))
        
        print(sum(people[idx - 1][1] - people[idx - 1][0] for idx in ans), *ans)

if __name__ == "__main__":
    solve()
```この実装では、最初に開始フロアごとにすべての間隔を並べ替えます。これにより、現在のエレベーターの位置が増加するにつれて、利用可能なジョブを徐々に明らかにする線形スイープが可能になります。 ヒープには、到達可能なジョブが最上位の宛先フロア順に格納され、常に可能な限り積極的に到達可能な範囲を拡張できるようにします。 

現在の位置はジョブが終了するたびに更新され、到達可能なジョブがない場合は、次の開始フロアに直接ジャンプします。 これにより、実行不可能な候補を繰り返しスキャンすることが回避されます。 

微妙な点は、この実装で出力される最終コストが定数和観測を使用して選択された次数から再計算されることです。 運用設定では、通常、シミュレーション中に移行コストを段階的に累積しますが、再計算の方が簡単で、ヒープ移行での間違いを回避できます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    input = sys.stdin.readline
    import heapq

    def solve():
        T = int(input())
        out = []
        for _ in range(T):
            n, f = map(int, input().split())
            a = []
            for i in range(n):
                l, r = map(int, input().split())
                a.append((l, r, i + 1))
            a.sort()

            i = 0
            cur = f
            heap = []
            order = []

            while i < n or heap:
                while i < n and a[i][0] <= cur:
                    l, r, idx = a[i]
                    heapq.heappush(heap, (-r, l, idx))
                    i += 1
                if heap:
                    nr, l, idx = heapq.heappop(heap)
                    order.append(idx)
                    cur = -nr
                else:
                    l, r, idx = a[i]
                    cur = max(cur, l)
                    heapq.heappush(heap, (-r, l, idx))

            # cost recompute
            pos = f
            cost = 0
            for idx in order:
                l, r = [(a[j][0], a[j][1]) for j in range(n) if a[j][2] == idx][0]
                cost += max(l - pos, 0)
                cost += r - l
                pos = r

            out.append(str(cost))
            out.append(" ".join(map(str, order)))
        return "\n".join(out)

    return solve()

assert run("1\n3 1\n10 20\n1 2\n2 3\n")  # forced jump case
assert run("1\n2 100\n1 2\n2 3\n")  # high start

 ## 特殊なケース

 重要なエッジ ケースは、開始フロアがすでにすべての li 値を超えている場合に発生します。 このアルゴリズムは、すべてのジョブをすぐに到達可能として扱い、最大 ri の選択のみに依存するため、最初から不必要な上向きの動きが回避されます。 

もう 1 つのエッジ ケースは、間隔が大きく離れており、複数回のリセットが強制される場合です。 このような場合、ヒープは繰り返し空になり、正確さは常に次に小さい li にジャンプするかどうかに依存します。 貪欲な構造により、次の必須のジャンプを減らすことになる小さな li をスキップすることがなくなります。 

最後のエッジケースは、複数の区間が同じ li を共有しているが、ri が異なる場合です。 ヒープは、最大の ri を持つ間隔だけが最初に選択されることを保証し、到達可能性を維持し、下位の宛先への時期尚早なコミットメントを回避します。
