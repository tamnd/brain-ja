 ## 解決策
 ## 問題の理解

 英語の小文字のアルファベットの上に 3 つの文字列が与えられ、文字から文字へのマッピングを定義できます。 このマッピングは全単射である必要はなく、複数の文字を同じ文字にマッピングできますが、すべての文字は正確に 1 つの文字にマッピングする必要があります。 

マッピングが修正されたら、それを文字列に 1 文字ずつ適用し、暗号化された形式を生成します。 タスクは、最初の 2 つの文字列が暗号化後に同一になる一方で、3 番目の文字列がそれらと同一にならないようなマッピングが存在するかどうかを判断することです。 

言い換えれば、文字に色を割り当てようとしています。暗号を適用すると各文字がその色に置き換えられ、最初の 2 つの文字列が同じ結果の文字列に折りたたまれ、3 番目の文字列は異なるままになります。 

テスト ケースごとの制約は小さいですが、テスト ケースの数は多く、すべての文字列の合計長は 3×10^4 で制限されます。 これは、テスト ケースごとに線形または線形に近い処理を行う余裕はありますが、テスト ケースごとに二次関数を実行すると遅すぎることを意味します。 

この問題の単純な危険性は、S1 と S2 を位置ごとに同一にすれば十分であると仮定することから生じます。 繰り返される文字間の一貫性も確保しない限り、これは当てはまりません。 もう 1 つの微妙な問題は、S3 は 1 つの位置でのみ異なる必要があると想定していることです。 マッピングはグローバルであるため、S1 と S2 を修正する変更により、意図せずに S3 も強制的に一致させる可能性があります。 

## アプローチ

 ブルートフォースの観点では、26 文字から 26 文字への可能なマッピングをすべて試すことを考えます。 このような関数は 26^26 個あり、これは天文学的な大きさです。 S1 と S2 の制約を使用して制限したとしても、3 つの文字列すべてのすべての文字にわたる一貫性を考慮する必要があり、関係する個別の文字の数は依然として指数関数的に増加します。 このアプローチは、組み合わせ爆発によりすぐに失敗します。 

重要な観察は、問題は完全なマッピングを自由に選択することではなく、2 種類の制約を満たす文字の等価クラスの一貫した割り当てが存在するかどうかであるということです。 

最初の制約は、F(S1) = F(S2) を強制することから生じます。 これは、すべての位置 i で、文字 S1[i] と S2[i] が同じ値にマップされる必要があることを意味します。 これにより、等価クラスの結合が引き起こされます。つまり、同一になる必要がある文字を効果的に結合していることになります。 

2 番目の制約は、このマージ後、S3 が S1/S2 と同一になってはいけないということです。 つまり、誘導されたマッピング文字列が異なる位置が少なくとも 1 つ存在する必要があります。 

等価関係のみが重要であることが分かると、問題は、S1 と S2 の制約を使用して文字に対して素セット構造を構築し、次に S3 がマージされたバージョンと強制的に一致するかどうか、またはそれを異なるままにする自由があるかどうかをチェックすることに帰着します。 微妙な部分は、一貫性が保たれる限り、最終的にマップされた文字を各等価クラスに任意に割り当てることができるということです。 

したがって、タスクは次のようになります。S1 と S2 の制約を統合し、何らかの割り当ての下で S3 を異なるものにできるかどうかを確認します。 これは、一貫性を損なうことなく S3 を S1/S2 から分離できる「柔軟な」位置が少なくとも 1 つ存在するかどうかをチェックすることになります。

 ## アルゴリズムのチュートリアル

 各文字をグラフ内のノードとして扱います。 S1 および S2 からの制約により、強制等価エッジが作成されます。

1. 26 個の小文字を使用して素セット共用体構造を初期化します。 この構造は、暗号が適用された後にどの文字が同一になる必要があるかを表します。 
2. すべての位置 i について、S1[i] と S2[i] を結合します。 これにより、これら 2 つの文字が同じ最終文字にマップされる必要があります。 その理由は、暗号を適用した後、その出力がすべての位置で一致する必要があるためです。 
3. すべての位置を処理した後、各 DSU コンポーネントは、F(S1) = F(S2) という要件の下で区別できない文字のグループを表します。 
4. ここで、各文字をその DSU を表す文字に置き換えて、S3 の概念的な「圧縮文字列」を構築します。 これにより、各キャラクターがどの同等クラスに属するかがわかります。 
5. S1 (結合後は同等であるため、S2) に対して同じ圧縮を実行します。 次に、圧縮された S3 が圧縮された S1 と同一であるかどうかを比較します。 
6. 圧縮 S3 がすでに圧縮 S1 と同一である場合、S1 = S2 を満たす有効なマッピングは自動的に S3 も強制的に一致させるため、答えは NO です。 
7. それ以外の場合は、S3 が S1/S2 とは異なる同値クラスに属する位置が少なくとも 1 つ存在します。つまり、これらのクラスに個別の出力文字を割り当てて違いを保存できるため、答えは YES です。 

### なぜ効果があるのか

 DSU は、条件 F(S1) = F(S2) によって強制される等価性を正確に捕捉します。 有効な暗号は、同じコンポーネント内の文字に同一の出力を割り当てる必要がありますが、コンポーネント間で異なる出力を自由に割り当てることができます。 したがって、圧縮後、2 つの文字列は、その圧縮表現が同一である場合に限り、常に同じ暗号化結果にマップされます。 S3 が圧縮形式で異なる場合、少なくとも 1 つのコンポーネントに個別のシンボルを割り当ててその違いを保存し、有効な暗号が存在することを保証できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def compress(s, dsu):
    return [dsu.find(ord(c) - 97) for c in s]

def solve():
    s1 = input().strip()
    s2 = input().strip()
    s3 = input().strip()

    dsu = DSU(26)

    for a, b in zip(s1, s2):
        dsu.union(ord(a) - 97, ord(b) - 97)

    c1 = compress(s1, dsu)
    c3 = compress(s3, dsu)

    if c1 == c3:
        print("NO")
    else:
        print("YES")

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```この解決策は、26 文字にわたる DSU を構築することから始まります。 S1 と S2 の整列された文字のすべてのペアがマージされ、暗号化後に区別できなければならないという要件がエンコードされます。 圧縮ステップでは、文字列を DSU ルートのシーケンスに変換します。これは、強制的な制約の下での構造的等価性を表します。 最後の比較では、これらの制約の下で S3 が S1 と構造的に同一であるかどうかがチェックされます。 

よくある間違いは、実際のキャラクターの割り当てについて推論するのが早すぎることです。 DSU 抽象化は、実現可能性に影響を与える唯一の情報である強制された等価性のみを追跡することでこれを回避します。 

## 実用的な例

 入力:

| ステップ | S1コンプ | S2コンプ | S3コンプ | S1 と S3 が等しい |
 | --- | --- | --- | --- | --- |

 S3 は構造的に異なるため、S1 = S2 になるようにコンポーネントに個別の出力を割り当てることができますが、S3 は異なるままであるため、出力は YES になります。 

### 例 2

 入力:

 S1 = アバブ

 S2 = cdcd

 S3 = abcd

 前と同じ DSU: a~c、b~d。 

圧縮:

 S1 → ABAB

 S2→ABAB

 S3→ABAB

 | ステップ | S1コンプ | S2コンプ | S3コンプ | S1 と S3 が等しい |
 | --- | --- | --- | --- | --- |
 | DSU後 | アバブ | アバブ | アバブ | はい |

 ここで、S3 は S1/S2 と同じ構造に崩壊するため、有効なマッピングでは等価性が強制され、S3 を分離することができなくなります。 答えは「ノー」です。 

これらの例は、決定が実際の文字ではなく、強制的な識別の下での構造的平等のみに依存していることを示しています。

 ## 特殊なケース

 1 つのエッジ ケースは、S1 と S2 がすでに同一である場合に発生します。 この状況では、自己マップを超える結合は導入されません。 S3 も同一の場合、圧縮形式は完全に一致するため、強制的に NO となります。 S3 が 1 つの位置でも異なる場合、DSU 圧縮ではその差が保持され、答えは YES になります。 

S1 と S2 がすべての位置で異なる場合、別のエッジ ケースが発生し、大きな同値クラスが強制されます。 S3 がその誘導された構造と誤って一致した場合、S3 は完全に同じ圧縮表現に崩壊し、マッピングによって分離することはできません。
