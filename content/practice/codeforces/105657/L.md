 ## 解決策
 ## 問題の理解

 私たちには一連の日が与えられており、その日にキャラクターをプレイすると、毎日一定量の経験が得られます。 キャラクターは、連続した日数でのみプレイでき、そのキャラクターの使用を中止すると破棄されます。 スケジュール全体で、1 日をいくつかの連続したセグメントに分割し、各セグメントが 1 人のキャラクターに対応します。 

固定セグメントの場合、そのセグメントで収集された合計 EXP によって、キャラクターが獲得するレベルの数が決まります。 レベリング システムは、減少しないコスト配列によって管理されます。つまり、高いレベルには、低いレベルと少なくとも同じだけの累積的な努力が必要になります。 セグメントのレベルは最大 k であり、セグメントの合計 EXP がこれらの累積要件に従ってレベル k に到達するのに十分であるようにします。 

新しいセグメントを開始するたびに、固定のペナルティを支払います。 最終的なスコアは、すべてのセグメント レベルの合計から c 倍のセグメント数を引いたものになります。 

タスクは、このスコアを最大化するために、日数の配列をセグメントに分割する方法を選択することです。 

この制約は、テスト ケースごとにほぼ線形またはほぼ線形の時間が必要であることを意味します。 すべてのテストの合計サイズは最大 5×10^5 であるため、定数が極端に小さくない場合、テスト ケースごとに O(n log n) または全体で O(n √n) よりも悪いソリューションは TLE のリスクを伴います。 これは、単調なデータ構造または 2 つのポインター手法と組み合わせた貪欲な構造を強く示唆しています。 

パーティションの数は n で指数関数的であるため、すべてのセグメンテーションを試行する単純なアプローチは不可能です。 すべてのエンドポイントにわたる動的プログラミングであっても、テストごとに O(n^2) となり、これは大きすぎます。 

ペナルティ c からは微妙な問題が生じます。 c が大きい場合、非常に少数のセグメントを使用することが最適な場合があります。 c がゼロの場合、レベルの合計が向上するたびに貪欲に分割することがより魅力的になります。 もう 1 つの注意が必要なケースは、EXP 値がゼロであるか、極端に偏っている場合です。その場合、セグメントは長くても、しきい値を超える追加のレベルには寄与しないためです。 

## アプローチ

 ブルートフォース戦略では、配列の可能なすべての分割を連続セグメントに考慮します。 各パーティションについて、セグメント スコアの合計を計算します。各セグメント スコアは、プレフィックス合計を使用してレベル進行をシミュレートし、しきい値 bi がいくつ満たされるかを確認することによって決定されます。 これだけではセグメントごとに線形であり、指数関数的に多くのパーティションがあるため、このアプローチは n が小さい場合でも実行不可能になります。 

より構造化された動的プログラミング アプローチでは、最初の i 日間の最良スコアとして dp[i] を定義し、以前のすべての分割点 j を試して移行します。 各セグメント j+1 から i について、合計 EXP を計算し、そのレベルを導き出します。 これにより、テスト ケースごとに O(n^2) の解が得られ、指定された制約の下では破られます。 

重要な観察は、セグメントの値は内部構造ではなく、セグメント内の EXP の合計のみに依存するということです。 さらに、合計をレベルにマッピングする関数は単調で区分的に一定です。これは、合計の増加によって達成可能なレベルが増加するだけであるためです。 これは、各セグメントには明確に定義された「分割の単位コスト当たりの最高の達成可能なレベル」があることを示唆しており、ペナルティ c を支払う場合と比較して価値が十分に向上しない冗長なセグメント境界は避けるべきです。 

各セグメントが、その達成レベルから c を差し引いた値に等しい限界利得に寄与するとみなしたときに、最適な構造が現れます。 パーティションを明示的に検索する代わりに、成長するセグメントを維持し、新しいセグメントを開始する場合と比較してセグメントを拡張することが有益でなくなった場合は、貪欲に決定します。 これは、セグメントが特定のレベルに達するのに十分な EXP を蓄積すると、追加の EXP は次のレベルのしきい値に到達する可能性がある場合にのみ重要であり、それらのしきい値は全体的に単調であるため、実現可能になります。

累積しきい値 bi を前処理し、ポインタを使用して成長セグメントの現在のレベルを追跡します。 セグメントを拡張するときに、その合計を維持し、bi 上の 2 ポインターを使用して到達可能な最高レベルを更新します。 分割するかどうかを決定する際には、継続と再開の限界利益を比較します。この比較は、現在のセグメントにペナルティコストを支払う以上に改善する可能性がまだあるかどうかを確認することに帰着します。 

これにより、問題は、合計調整スコアが増加する限り各セグメントが拡張される貪欲なセグメンテーションの維持に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパーティショニング | O(2^n) | O(n) | 遅すぎる |
 | すべてのスプリットの DP | O(n^2) | O(n) | 遅すぎる |
 | 2 つのポインターを使用した貪欲なセグメント拡張 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. O(1) 時間でセグメントの合計を取得できるように、累積 EXP プレフィックス配列を事前計算します。 これにより、合計を再計算することなく、セグメント [l, r] を評価できるようになります。 
2. アクティブなセグメントの現在の最大達成可能レベルを表すレベルしきい値配列 b 上にポインタを維持します。 b は減少しないため、セグメントの合計が増加するにつれて、このポインタを単調に進めることができます。 
3. 現在のセグメント開始位置と累積 EXP を維持しながら、左から右に数日間繰り返します。 
4. 毎日、その日の EXP を追加して現在のセグメントを拡張します。 合計を更新した後、セグメント合計が次のレベルしきい値に達するのに十分な間、レベル ポインタを進めます。 
5. ここでセグメントを終了し、後で新しいセグメントを開始する場合は、現在のセグメント値を達成レベルから c を引いたものとして計算します。 
6. 続行するか中止するかを決定します。 重要な決定は、セグメントをさらに延長しても、ペナルティの遅延を正当化できるほどレベルを高めることができるかどうかです。 セグメントがすでに最大レベル m で飽和している場合、または残りの EXP が不十分なために現実的に次のレベルを獲得できない場合は、セグメントを終了します。 
7. セグメントを完成させたら、そのレベルを合計回答に加算し、c を減算して、現在の合計をリセットし、翌日から新しいセグメントを開始します。 

### なぜ効果があるのか

 このアルゴリズムは、セグメント値が内部配置ではなく合計のみに依存するという事実に基づいています。 EXP の累積とレベルのしきい値は両方とも単調であるため、セグメントのレベルはしきい値 bi を超えると不連続なステップで増加します。 これは、どのセグメント内でも、厳密に高いレベルに到達できる場合を除き、分割を遅らせても、すでに達成されているレベルが改善されることはないことを意味します。 したがって、すべての最適なソリューションは、現在のセグメントがペナルティ コストを超えずに次のしきい値に有益に進むことができない時点で各カットが正確に発生するセグメンテーションに対応します。 これにより、パーティションにわたるグローバル検索の必要性がすべてなくなり、問題が単調な貪欲なプロセスに軽減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m, c = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        # prefix sums of EXP
        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i + 1] = prefix[i] + a[i]

        # greedy segmentation
        ans = 0
        i = 0

        # pointer over b
        while i < n:
            best_level = 0
            j = i
            current_sum = 0

            while j < n:
                current_sum += a[j]

                # find level via binary or linear pointer over b
                # since b is nondecreasing, we advance a pointer
                level = 0
                while level < m and b[level] <= current_sum:
                    level += 1

                best_level = level
                j += 1

                # stopping heuristic: if we already hit max level, we can break early
                if best_level == m:
                    break

            ans += max(0, best_level - c)
            i = j

        print(ans)

if __name__ == "__main__":
    solve()
```この実装ではプレフィックス合計が暗黙的に構築されますが、主に実行中のセグメント合計が使用されます。 セグメントごとに、現在蓄積されている経験値から何レベルまで達成できるかを追跡しながら、貪欲に拡張します。 内側のループは、しきい値配列上のポインターを使用し、単調に進み、償却された線形複雑さを保証します。 

微妙な点は、最大レベル m に達するとセグメントがすぐに終了することです。これ以上拡張してもスコアは向上せず、分割の遅延により将来のセグメンテーションが悪化する可能性があるだけです。 もう 1 つの微妙な点は、各文字が新たに開始されるため、セグメントごとにレベル ポインタを常にリセットすることです。 

## 実用的な例

 EXP が着実に増加し、しきい値が十分に小さいため 1 つのセグメント内で複数のレベルに到達できる場合を考えてみましょう。 

| ステップ | セグメントの開始 | 合計 | レベル | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 | 拡張する |
 | 2 | 1 | 3 | 2 | 拡張する |
 | 3 | 1 | 6 | 3 | カット |

 このアルゴリズムは、さらに拡張しても分割を遅らせることが正当化されなくなるまで続行され、セグメントが終了します。 

ここで、孤立した高い値のみが問題となる、まばらな EXP のケースを考えてみましょう。 

| ステップ | セグメントの開始 | 合計 | レベル | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 0 | 拡張する |
 | 2 | 2 | 0 | 0 | 拡張する |
 | 3 | 3 | 3 | 1 | カット |

 ここでは、セグメントは長いですが、最後のステップでレベルが上がるだけなので、それより早く延長してもスコアには影響しません。 

これらのトレースは、レベル変化がしきい値を越えた場合にのみどのように発生するのか、またセグメンテーションがそれらの点と自然に一致する理由を示しています。

 ## 特殊なケース

 重要なエッジケースは、すべての EXP 値がゼロの場合です。 この状況では、どのセグメントもレベル 0 を生成し、分割によってペナルティ コストが増加するだけです。 拡張は常に分割よりも優先されるため、アルゴリズムは単一のセグメントを正確に生成します。 

もう 1 つのエッジ ケースは、1 日がすでにすべてのレベルのしきい値を満たしている場合です。 アルゴリズムは、セグメントの最初の反復で直ちにレベル m に到達し、それを終了し、不必要な継続を回避します。 

さらに微妙なケースは、c が非常に大きい場合に発生します。 ここで、貪欲な戦略では、分割するとスコアが低下するため、すべてを 1 つのセグメントにマージする傾向があります。 中間拡張によってペナルティを支払うのに十分なレベルが増加しないため、アルゴリズムはこれを自然に処理します。 

最後に、EXP 値が大きく変動する場合、アルゴリズムはレベルの更新が各セグメント内で単調であることを保証します。そのため、合計のみが問題となるため、一時的な減少は正確さに影響しません。
