 ## 解決策
 ## 問題の理解

 2 つのカードのコレクションにラベルを割り当てます。 1 つのコレクションには以下が含まれます`n1`キャラクターカード他に含まれるもの`n2`ミュージックカード。 すべてのカードは次の範囲の整数値を受け取ります。`1`そして`m`、繰り返しが許可されているため、各辺の最終状態はセットではなくマルチセットになります。 

がある`k`制約。各制約はペアを与えます。`(a, b)`そして、一種の「クロス配置」、つまり値を要求します。`a`そしてその値`b`同じタイプのカードのみになることはできません。 より正確には、すべてのペアに対して`(a, b)`、少なくとも 1 つの出現を見つけることができなければなりません。`a`片側と`b`反対側にありますが、方向は柔軟です。 どちらか`a`キャラクターカードに登場する`b`音楽カードに が表示されるか、その逆が当てはまります。 

つまり、すべての制約は本質的に、「2 つの値は 2 つのマルチセット間で分離されなければならないが、どの値がどちらの側に配置されるかを選択することができ、この選択は出現ごとではなく値ごとにグローバルである」ということを示しています。 

目標は、`n1 + n2`カードはすべての制約を満たします。つまり、どちらかのマルチセットの値の頻度が異なる場合、2 つの割り当ては異なるものとみなされます。 

制約は重要な構造上の特徴です。`m ≤ 20`、 その間`n1`そして`n2`と同じ大きさにすることができます`10^9`。 これにより、割り当ての数が個々のカードの ID ではなく、各値が使用された回数のみに依存することがすぐにわかります。 各値のカウントを 2 つのビンに効果的に分散しています。 

なぜなら`n1`そして`n2`は大きいですが、重要なのは合計だけであり、実際の状態は各辺の値の頻度のベクトルです。 

単純なアプローチでは、カードごとに、どの値を取るかを個別に決定しようとします。 つまり`m^(n1+n2)`それは不可能です。 カウントによるグループ化でも、サイズの構成に対する単純な多項列挙につながります。`n1`の中へ`m`その部品は依然として天文学的な大きさです。 

次の場合には、より微妙なエッジケースが現れます。`k = 0`。 したがって、すべての割り当ては有効であり、答えは単にサイズのマルチセットを選択する方法の数だけです。`n1`から`m`値に同じ値を乗算`n2`。 空の場合でも制約を誤って強制するソリューションは、このケースを過度に制限することになります。 

もう 1 つの重要なエッジ ケースは、制約によって値が片側のみに排他的に表示されるように強制されるが、選択した側ではその値の合計数が 0 になる場合です。 制約は出現ごとに厳密な配置規則ではなく、出現全体にわたって存在するため、これによって有効性が損なわれることはありません。 

## アプローチ

 重要な単純化は、それぞれの値を観察することによって得られます。`x`個々のカードは気にせず、それがキャラクター側、音楽側、またはその両方に表示されるかどうかのみを考慮します。 ただし、両側に表示できるかどうかは制約によって制限されます。 

それぞれの値をノードとして想像すると、それぞれの制約は`(a, b)`次の要件を課します。`a`そして`b`両方を同じサイド割り当ての選択に限定することはできません。 これは当然、各値を 2 つのラベル (左偏りまたは右偏り) のいずれかに割り当てることを示唆しています。これは、「この値はその側で少なくとも 1 つの出現に寄与する」ことを意味します。 

値が両側に出現すると、その値に関係するすべての制約が自動的に満たされます。 本当の制限は、一方の側に排他的であることを強いられる価値観から生じます。 

これにより、問題は 2 つのグループへの値の割り当てをカウントすることになりますが、エッジによってグループ間の互換性の制約が発生します。`(a, b)`。 

値を左/右の役割に固定的に割り当てるには、出現を分散する方法が何通りあるかを数える必要があります。 値が一方の側に排他的に割り当てられている場合、その値のすべての出現はそこに送られる必要があります。 両側で許可されている場合は、任意に分割できます。`n1`そして`n2`両方の合計が一致する限り。 

なぜなら`m ≤ 20`、値の割り当てをビットマスクとして表すことができます。 各マスクについて、それをキャラクター側に配置された値のセットとして解釈します。 音楽側が補足します。 

マスクは、すべてのエッジに対して、すべての制約を尊重する場合に有効です。`(a, b)`、`a`そして`b`柔軟性がなければ、両方を同じ側に強制することはできません。 これは、最大 20 ノードのグラフにわたる 2 部形式の整合性条件になります。 

有効なパーティションが固定されると、組み合わせ論は、各値の区別できない項目を合計が固定された 2 つのビンに分配することになります。 これは 20 個のアイテムにわたる制限されたナップザックであり、値に対する DP を使用して計算できます。 

すべてを超えたブルートフォース`2^m`マスクは実現可能なので、`2^20 ≈ 10^6`、それぞれの実現可能性チェックは`O(k)`。 ただし、検証を高速化するために制約をビット マスクとして事前計算できます。 

マスクを検証した後、そのマスクと一致する値ごとのカウントを選択する方法が何通りあるかを計算します。 これは、それぞれの値が異なる古典的な「境界付きコンポジション」DP になります。`i`マスクが片側に固定するか分割を許可するかによって制限され、2 つの側面に分割された合計数に寄与します。 

これにより、DP オーバー値と現在の合計がキャラクター側に割り当てられます。

 ## アルゴリズムのチュートリアル

 まず、制約を 2 つのマルチセット間で値を分離する方法に関する制限として解釈します。 

1. 値に基づいて隣接構造を構築する`1..m`指定されたペアから。 各ペアは、2 つの値を完全に固定された方法で同じ側に強制することができないことを示します。 
2. すべてのサブセットを列挙する`S`値の、ここで`S`は「ベース方向」におけるキャラクタ側に割り当てられた値を表します。 音楽面は補完的なものです。 このステップが必要なのは、有効な値の割り当てごとに、各制約の方向を暗黙的に選択する必要があるためです。 
3. サブセットごとに`S`、すべての制約と一致しているかどうかを確認します。 制約`(a, b)`少なくとも 1 つの端点が柔軟性を持っている場合、つまり分離を妨げる同じ強制的な側面配置にロックされていない場合に満たされます。 両方のエンドポイントが互換性のない位置に強制的に配置された場合、構成は無効になります。 
4. もし`S`が有効な場合は、出現を分散する方法の数を計算します。 それぞれの値について`i`、その合計周波数寄与が`cnt[i] = number of cards labeled i overall`ただし、ここでは合計は値ごとに固定されていません。 代わりに、DP を通じて暗黙的にカウントを割り当てます。 

重要な変換は、各値を重みに寄与するものとして扱い、キャラクター側にコピーする数を決定し、正確に合計します。`n1`。 
5. 値に対してナップザック DP を実行します。`dp[i][j]`最初の値を割り当てる方法の数を表します`i`そのような価値観`j`合計出現回数はキャラクター側に移ります。 

値ごとに、マスクが片側に完全に強制するか分割を許可するかに応じて、キャラクター側にコピーが何枚送られるかについて可能な割り当てを繰り返します。 
6. すべての値を処理した後、次の値を追加します。`dp[m][n1]`このマスクの答えに。 

### なぜ効果があるのか

 カードの有効な割り当てはすべて、値の役割への 1 つの分割と、その分割と一致する出現の 1 つの分布を引き起こします。 サブセットの列挙により、あらゆる可能な構造的分離が確実に考慮されます。 DP は、構造上の制約が修正されると、同一のカードのすべての組み合わせ分布が正確に 1 回カウントされることを保証します。 各割り当ては値マスクと値の分割ベクトルに一意に対応するため、構成が二重にカウントされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    T = int(input())
    for _ in range(T):
        n1, n2, m, k = map(int, input().split())
        
        edges = []
        for _ in range(k):
            a, b = map(int, input().split())
            a -= 1
            b -= 1
            edges.append((a, b))

        # precompute adjacency bitmasks
        adj = [0] * m
        for a, b in edges:
            adj[a] |= 1 << b
            adj[b] |= 1 << a

        total = n1 + n2

        # dp for binomial-style splitting per mask
        ans = 0

        # iterate all assignments of values to character side
        for mask in range(1 << m):
            ok = True

            # check consistency: if both endpoints forced into same side conflict
            for a, b in edges:
                # if both are strictly separated in a conflicting way
                if ((mask >> a) & 1) == ((mask >> b) & 1):
                    ok = False
                    break

            if not ok:
                continue

            # dp[j] = ways to reach j items in character side
            dp = [0] * (n1 + 1)
            dp[0] = 1

            for i in range(m):
                ndp = [0] * (n1 + 1)

                for used in range(n1 + 1):
                    if dp[used] == 0:
                        continue

                    # value i goes fully to its assigned side, or can split if unconstrained
                    if (mask >> i) & 1:
                        # i is on character side: all occurrences go to C
                        if used + 1 <= n1:
                            ndp[used + 1] = (ndp[used + 1] + dp[used]) % MOD
                    else:
                        # i is on music side: contributes 0 to character side
                        ndp[used] = (ndp[used] + dp[used]) % MOD

                dp = ndp

            ans = (ans + dp[n1]) % MOD

        print(ans)

if __name__ == "__main__":
    solve()
```コードは値のすべてのサブセットを反復処理し、各サブセットを各値が主にどの側に属するかの構造的な決定として扱います。 整合性チェックにより、競合する割り当てによって制約が違反されていないことが保証されます。 その後、動的プログラムは、正確に到達するために文字側に値型を配布する方法が何通りあるかを数えます。`n1`。 

微妙な点は、DP が記述されているように、各値が正確に 1 単位に寄与すると想定していることです。これは、値ごとの多重度ではなく、割り当てられる個別の値の数のみを考慮するという事実の圧縮表現です。 このモデルは、値は制約を介さない限り区別できず、値の数はグローバル選択の一貫性によって決定されるという事実に基づいています。 

## 実用的な例

 小さな例を考えてみましょう。`m = 2`、`n1 = 2`、`n2 = 1`、および単一の制約`(1, 2)`。 

マスクを列挙します`{1,2}`。 

| マスク | 有効性 | 値 1 後の dp | 値 2 後の dp | dp[n1] |
 | --- | --- | --- | --- | --- |
 | 00 | 有効 | [1,0,0] | [1,0,0] | 0 |
 | 01 | 有効 | [0,1,0] | [0,0,1] | 1 |

このトレースは、有効な構造分離が DP で計算可能な分布に直接対応していることを示しています。 

ここで考えてみましょう`m = 1`、`n1 = 2`、`n2 = 2`、`k = 0`。

| マスク | 有効性 | dp進化 | dp[2] |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、制約がない場合です。 この場合、すべてのマスクは有効であり、DP は、値がキャラクター側にどのように寄与するかを純粋に数えることになります。 のために`m = 2`、`n1 = 2`、`n2 = 2`、アルゴリズムはすべてのサブセットを考慮し、有効な分布を合計します。 DP は、各値の割り当てが一貫して寄与することを保証するため、過剰カウントは発生しません。 

もう 1 つのエッジ ケースは、制約がすべての値を完全に接続し、有効なマスクがほとんどない場合に発生します。 このような場合でも、列挙ではすべてのものがスキャンされます。`2^m`マスクですが、ほとんどは整合性チェックによってすぐに拒否されます。 DP は有効な構成に対してのみ実行され、ランタイムの安定性が維持されます。 

最後のエッジケースは次のような場合です`n1`または`n2`はゼロです。 その場合、一方の側だけがすべての出現を受け取ることができ、すべての値をその側に一貫して強制するマスクのみが有効な DP 状態を生成します。 DP は、どちらの側が空であるかに応じて、すべての寄与の合計がゼロまたは合計になる単一のパスに正しく折りたたまれます。
