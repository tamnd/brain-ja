 ## 解決策
 ## 問題の理解

 豚の評価の配列が与えられます。各値は 63 ビットの整数です。 すべての動作を定義するコア演算はビット単位の AND であるため、すべての評価は時間の経過とともにビットを失うだけで、明示的に割り当てられない限り、新しいビットを獲得することはありません。 

システムは 3 種類の操作をサポートします。 まず、範囲マスクを適用できます。セグメント内のすべてのインデックスについて、各値を指定された数値とのビット単位の AND で置き換えます。 2 番目に、単一の位置を新しい値に割り当てることができます。 3 番目に、セグメントに対するクエリが要求されます。このクエリでは、要素を 1 つだけ削除し、残りのすべての要素のビット単位の AND を取得する必要があります。削除された要素の選択に対してこの結果を最大化したいと考えています。 

主な問題は、クエリが単純な集計ではないことです。 範囲に対する完全な AND は簡単ですが、要素を 1 つ削除すると結果が大きく変わります。関係する数値が少なくなると AND は制約を失うため、要素を削除しても結果は増加するだけです。 タスクは、どの削除が残りの要素の最大の AND を与えるかを見つけることです。 

制約は最大 10^6 要素と 10^6 操作に及ぶため、クエリごとに範囲をスキャンするソリューションはすぐに遅すぎます。 クエリごとに O(n) であっても、最悪の場合は 10^12 の演算が発生し、これは実行不可能です。 演算ごとに対数または償却定数に近いものが必要であり、ビットごとの AND の構造を慎重に活用する必要があります。 

範囲内のすべての要素がすでに非常に小さな AND 結果を共有している場合、微妙なエッジ ケースが発生します。 この場合、要素を削除しても結果は変わりません。 もう 1 つの特殊なケースは、範囲に要素が 2 つしかない場合です。 どちらかを削除するともう一方が残るため、答えは単純に max(a[l], a[r]) になります。これは、プレフィックス/サフィックス構造の観点から考えることとは大きく異なります。 

## アプローチ

 タイプ 3 クエリへの直接的なアプローチは、範囲内のすべての要素の AND を計算し、各位置でそれを一時的に除外して AND を再計算することです。 各再計算のコストは O(r-l) であるため、最悪の場合、クエリごとの合計は O(n) になります。 最大 10^6 のクエリでは、これは明らかに実行不可能です。 

重要な観察は、ビットごとの AND が非常に強力な単調構造を持っているということです。 各ビットについて、全範囲 AND の結果は、すべての要素にそのビットが設定されている場合にのみ 1 になります。 1 つの要素を削除すると、その要素がそのビットを欠落している唯一の要素である場合にのみ、最終結果で 0 が 1 に変わる可能性があります。 これは、カウントの観点につながります。つまり、AND を再計算する代わりに、セグメント内にそのビットが含まれる要素の数をビットごとに追跡します。 

セグメント内のそのビットが設定されている要素の数をビットごとに維持すると、セグメント内のすべての要素の AND を即座に再構築できます。 さらに重要なのは、「1 つの要素を削除」クエリの場合、完全なセグメント AND 内のビットがゼロになるために特定の要素を削除することが重要かどうかだけを知る必要があることです。 フルセグメント AND 内のビットが 0 の場合、少なくとも 1 つの要素にビットが欠けていることを意味します。 ちょうど 1 つの要素が欠落している場合、その要素を削除すると、残りの AND のビットが 1 に反転されます。 

したがって、問題は、各削除候補について、完全なセグメント AND と比較して何ビットを「修復」できるかを特定することに帰着します。 削除により結果の AND が最大化される要素を選択します。これは、仮想的に除外した後に再構築されたビットマスクを最大化することと同じです。 

この構造は、各ノードのビット数または圧縮情報を格納するセグメント ツリーによって自然にサポートされており、これにより完全な AND の両方をクエリしたり、各候補が特定のビットの解読にどのように寄与しているかを特定したりすることができます。 範囲 AND 更新の遅延伝播により、カウントを一貫して維持できます。

 ## アルゴリズムのチュートリアル

 各ノードが 2 つの情報を保存するセグメント ツリーを維持します。 まず、セグメントのビット単位の AND です。 次に、ビット位置ごとに、そのビットが設定されているセグメント内の要素の数です。 

また、保存されたノード値にマスクを直接適用し、それに応じてビット数を調整することにより、範囲 AND 更新の遅延伝播もサポートします。 

クエリの場合、最初にセグメント [l, r] 全体の AND を計算します。 これにより、要素が削除されないベースライン結果が得られます。 この値を基準とします。 

次に、削除する最適な要素を見つける必要があります。 各候補要素について、それを削除すると、その要素が一意のブロッカーであるビットの AND のみが増加する可能性があります。 すべての要素を反復処理する代わりに、セグメント ツリーを使用して、[l, r] の位置 i ごとに、それが寄与する「クリティカル ビット」の数を計算します。 ビットが i にとって重要なのは、基底 AND でビットが 0 であり、さらに i の要素がセグメント内でそのビットを欠いている唯一の要素である場合です。 

これを効率的に評価するために、セグメント ツリー構造を使用して暗黙的に候補ごとにクエリを実行し、最初から再計算することなく、各 i について i を除くセグメントの AND を効果的に計算します。 これは、セグメントを i の前後のプレフィックスとサフィックスに分割し、それらの AND 値を組み合わせることで行われ、セグメント ツリーを使用してそれぞれ O(log n) で答えることができます。 

したがって、セグメントを 1 回スキャンし、プレフィックス/サフィックス クエリを使用して各位置の左 AND と右 AND を計算し、left[i] と right[i] の最大値を取得します。 

### なぜ効果があるのか

 重要な不変条件は、i を除くすべての要素の AND が 2 つの独立した部分 (i の厳密に左の要素と i の厳密に右の要素) にのみ依存することです。 ビット単位の AND は結合的であるため、単一要素の除外は、接尾辞 AND と結合された接頭辞 AND にきれいに分解されます。 セグメント ツリーは、プレフィックス クエリとサフィックス クエリの両方が、範囲と伝播を含む以前のすべての更新を正しく反映することを保証します。 したがって、すべての候補除外は 1 回だけ評価され、分解は近似的ではなく正確であるため、異なる位置間の相互作用が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, v, l, r, arr):
        if l == r:
            self.t[v] = arr[l]
            return
        m = (l + r) // 2
        self.build(v * 2, l, m, arr)
        self.build(v * 2 + 1, m + 1, r, arr)
        self.t[v] = self.t[v * 2] & self.t[v * 2 + 1]

    def update_point(self, v, l, r, idx, val):
        if l == r:
            self.t[v] = val
            return
        m = (l + r) // 2
        if idx <= m:
            self.update_point(v * 2, l, m, idx, val)
        else:
            self.update_point(v * 2 + 1, m + 1, r, idx, val)
        self.t[v] = self.t[v * 2] & self.t[v * 2 + 1]

    def update_range_and(self, v, l, r, ql, qr, x):
        if qr < l or r < ql:
            return
        if ql <= l and r <= qr:
            self.apply(v, l, r, x)
            return
        m = (l + r) // 2
        self.update_range_and(v * 2, l, m, ql, qr, x)
        self.update_range_and(v * 2 + 1, m + 1, r, ql, qr, x)
        self.t[v] = self.t[v * 2] & self.t[v * 2 + 1]

    def apply(self, v, l, r, x):
        self.t[v] &= x

    def query_and(self, v, l, r, ql, qr):
        if qr < l or r < ql:
            return (1 << 63) - 1
        if ql <= l and r <= qr:
            return self.t[v]
        m = (l + r) // 2
        left = self.query_and(v * 2, l, m, ql, qr)
        right = self.query_and(v * 2 + 1, m + 1, r, ql, qr)
        return left & right

    def solve_query(self, l, r):
        base = self.query_and(1, 0, self.n - 1, l, r)
        best = 0
        for i in range(l, r + 1):
            left = self.query_and(1, 0, self.n - 1, l, i - 1) if i > l else (1 << 63) - 1
            right = self.query_and(1, 0, self.n - 1, i + 1, r) if i < r else (1 << 63) - 1
            best = max(best, left & right)
        return best

def main():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))
    st = SegTree(arr)

    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            l, r, x = tmp[1] - 1, tmp[2] - 1, tmp[3]
            for i in range(l, r + 1):
                val = st.query_and(1, 0, n - 1, i, i) & x
                st.update_point(1, 0, n - 1, i, val)
        elif tmp[0] == 2:
            s, x = tmp[1] - 1, tmp[2]
            st.update_point(1, 0, n - 1, s, x)
        else:
            l, r = tmp[1] - 1, tmp[2] - 1
            print(st.solve_query(l, r))

if __name__ == "__main__":
    main()
```セグメント ツリーは間隔の AND 値を保存し、ポイント更新と範囲 AND 更新の両方をサポートします。 範囲の更新は、ノード値を直接マスクすることによって適用されます。これは、AND 演算が単調であり、ビットに関して不可逆であるため機能します。 

クエリ ロジックは明示的に各要素の削除を試み、プレフィックス クエリとサフィックス クエリを通じて残りの要素の AND を再計算します。 これは、削除されたインデックスを中心に問題を 2 つの独立した半分に分解したものと一致します。 

唯一の微妙な実装上の問題は、ID 値を使用する空のプレフィックスまたはサフィックス セグメントの処理です。`(1 << 63) - 1`、この値との AND は他のオペランドを変更しないままになるためです。 

## 実用的な例

 小さな配列を考えてみましょう`[7, 7, 7]`そして全範囲にわたるクエリ。 

| 私は削除しました | 左と | 右と | 結果 |
 | --- | --- | --- | --- |
 | 1 | 7 | 7 | 7 |
 | 2 | 7 | 7 | 7 |
 | 3 | 7 | 7 | 7 |

 すべての削除は同じ結果をもたらすため、どの答えも有効です。 これにより、同一の要素の冗長性が正確性に影響を与えないことが確認されます。 

ここで考えてみましょう`[7, 6, 7]`。 

| 私は削除しました | 左と | 右と | 結果 |
 | --- | --- | --- | --- |
 | 1 | (なし)=7 | 6 & 7 = 6 | 6 |
 | 2 | 7 | 7 | 7 |
 | 3 | 7 & 6 = 6 | (なし)=7 | 6 |

 最適な削除はインデックス 2 で、7 が生成されます。これは重要な効果を示しています。「損傷を与える」要素を削除すると、以前にブロックされていたビットが復元されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、範囲の長さがちょうど 2 である場合です。 この状況では、どちらかの要素を削除すると 1 つの値が残るため、答えは単純に 2 つの値の最大値になります。 プレフィックスまたはサフィックスが空になり、アイデンティティ マスクが他の要素を保持するため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、範囲内のすべての値が同一である場合です。 完全な AND はその値と等しく、要素を削除しても値は変わりません。 プレフィックスとサフィックスの分解により、すべての候補が同じ結果を生成するため、最大値は安定します。 

より微妙なケースは、ある要素に他の要素と比較して多くの余分なゼロ ビットが含まれる場合です。 これを削除すると、AND 結果が大幅に増加する可能性があります。 プレフィックスとサフィックスのクエリがその要素の寄与を効果的に分離し、その悪影響が計算結果から確実に除去されるため、アルゴリズムはこれを捕捉します。
