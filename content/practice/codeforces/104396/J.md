 ## 解決策
 ## 問題の理解

 いくつかの地名のセットが与えられており、各セットについて、名前のすべてのペアを比較したいと考えています。 2 つの名前の比較は、共有される連続する文字ブロックの最長の長さによって定義されます。 言い換えると、2 つの文字列について、両方に出現する部分文字列を探し、そのような部分文字列の可能な最大長が必要になります。 

このタスクは複数のテスト ケースにわたって繰り返されます。 各テスト ケースについて、この意味で最も強い重複を共有する文字列のペアを特定し、その最大重複長を出力する必要があります。 

制約は十分小さいため、直接ペアごとの推論が実行可能です。 各テスト ケースには最大 50 個の文字列があり、各文字列の長さは最大 50 です。これにより、テスト ケースあたりの合計文字数はすぐに数千に制限されます。 文字列と部分文字列に対する三次アプローチはすでに安全です。$50^3 \cdot 50$スタイル操作は Python の制限内に十分収まります。 

主な微妙な点は、「類似性」が編集距離やサブシーケンスの一致に基づいていないことです。 これは厳密には連続する部分文字列に関するものであり、構造が完全に変わります。 よくある間違いは、誤って最長共通部分列を代わりに計算してしまうことです。これにより、一致する文字が分離されている場合に類似性が過大評価されてしまいます。 

2 番目の微妙な問題は、単純な部分文字列の生成に現れます。 両方の文字列のすべての部分文字列を個別に生成して比較すると、慎重に処理しないと、重複とスキャンの繰り返しにより、静かに複雑さが高くなりすぎたり、二重カウントが発生したりする可能性があります。 

## アプローチ

 ブルートフォースアプローチは定義から始まります。 文字列のすべてのペアについて、最初の文字列のすべての部分文字列を試し、その部分文字列が 2 番目の文字列に出現するかどうかを確認できます。 存在する場合、その長さを追跡し、最良の回答を更新します。 

単一の長さの文字列の場合$L$、 がある$O(L^2)$部分文字列。 単純な検索を使用して部分文字列が別の文字列に存在するかどうかを確認するとコストがかかります$O(L)$。 したがって、2 つの文字列のコストを比較すると、$O(L^3)$。 テスト ケースごとに最大 50 個の文字列があるため、約 1250 ペアがあり、各ペアのコストは最大で$50^3 = 125000$最悪の場合、テスト ケースごとに約 1 億 5,000 万回のプリミティブ チェックが発生します。 複数のテスト ケースでは、これは境界線にありますが、Python では依然として危険です。 

重要な点は、すべての部分文字列を個別に明示的に列挙してテストする必要がないということです。 代わりに、動的プログラミングを使用して、2 つの文字列間の最長の共通部分文字列を計算できます。 これにより、問題は構造化されたオーバーラップ計算に変換されます。 

2本の弦の場合$a$そして$b$、次の DP テーブルを定義します。$dp[i][j]$の最長の共通接尾辞の長さを表します。$a[:i]$そして$b[:j]$。 文字が一致する場合は、前のサフィックスを拡張します。 それ以外の場合はリセットします。 この表の最大値は、共通部分文字列の最長の長さです。 

各ペアは次のように解決できます。$O(L^2)$これは完全な入力に対して十分効率的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース部分文字列 + 検索 |$O(n^2 L^3)$|$O(1)$番外編 | 危険 |
 | ペアごとの DP の最長共通部分文字列 |$O(n^2 L^2)$|$O(L^2)$または$O(L)$最適化された | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. テスト ケース内のすべての文字列を読み取ります。 答えは最適なペアに依存しており、比較を安全にスキップできる構造はないため、すべてのペアを比較します。 
2. グローバル応答をゼロとして初期化します。 これにより、すべてのペアにわたって見られる最大の類似性が保存されます。 
3. 個別の文字列のペアごとに、動的プログラミングを使用して最長の共通部分文字列の計算を実行します。 DP 状態は、2 つの文字列の特定の位置で一致が終了する場合に、一致がどのくらい継続するかを追跡します。 
4. ペアの DP を計算する際、一致するサフィックスを拡張するたびに極大値を更新します。 この極大値は、このペアが共有する最良の部分文字列を表します。 
5. ペアが終了したら、その極大値と全体的な答えを比較し、必要に応じて更新します。 
6. すべてのペアが処理された後、グローバル最大値を出力します。 

DP 遷移は単純です。文字が一致すると、対角値が拡張されます。 一致しない場合、貢献度はゼロにリセットされます。 これにより、連続した一致のみがカウントされるようになります。 

### なぜ効果があるのか

 DP 状態は、2 つの位置で終わる最長の共有サフィックスをエンコードします。 共通の部分文字列はいずれかのインデックスのペアで終了する必要があります$(i, j)$、その時点の DP 値は、そこで終わる最長の有効な部分文字列を正確にキャプチャします。 考えられるすべての共通部分文字列には終了位置があるため、すべての DP 状態の最大値を取ることで、省略や過剰カウントを行わずにすべての可能性がカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def lcs_substring(a, b):
    n, m = len(a), len(b)
    dp = [0] * (m + 1)
    best = 0

    for i in range(1, n + 1):
        prev_diag = 0
        for j in range(1, m + 1):
            temp = dp[j]
            if a[i - 1] == b[j - 1]:
                dp[j] = prev_diag + 1
                if dp[j] > best:
                    best = dp[j]
            else:
                dp[j] = 0
            prev_diag = temp

    return best

t = int(input())
for _ in range(t):
    n = int(input())
    s = [input().strip() for _ in range(n)]

    ans = 0
    for i in range(n):
        for j in range(i + 1, n):
            ans = max(ans, lcs_substring(s[i], s[j]))

    print(ans)
```コア関数は、ローリング DP 配列を使用して最長の共通部分文字列を計算します。 完全な行列を保存する代わりに、前の行のみを保持し、一時変数を使用して対角依存関係を再構築します。 これにより、正確性を維持しながら、不必要なメモリ使用が回避されます。 

文字列ペアに対するネストされたループにより、すべての組み合わせが 1 回だけテストされることが保証され、冗長な比較が防止されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def lcs_substring(a, b):
        n, m = len(a), len(b)
        dp = [0] * (m + 1)
        best = 0
        for i in range(1, n + 1):
            prev_diag = 0
            for j in range(1, m + 1):
                temp = dp[j]
                if a[i - 1] == b[j - 1]:
                    dp[j] = prev_diag + 1
                    best = max(best, dp[j])
                else:
                    dp[j] = 0
                prev_diag = temp
        return best

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = [input().strip() for _ in range(n)]
        ans = 0
        for i in range(n):
            for j in range(i + 1, n):
                ans = max(ans, lcs_substring(s[i], s[j]))
        out.append(str(ans))
    return "\n".join(out)

# minimum size
assert run("1\n2\na\nb\n") == "0"

# identical strings
assert run("1\n2\nabc\nabc\n") == "3"

# partial overlap
assert run("1\n2\nabcd\nxbcdy\n") == "3"

# multiple pairs
assert run("1\n3\nabc\ndef\ncba\n") == "1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2 つの単一文字 | 0 | 一致しないケース |
 | 同一の文字列 | 全長 | 最大類似度 |
 | 部分的なオーバーラップ | 3 | 内部部分文字列一致 |
 | 混合トリプル | 1 | ペアの正しい最大値 |

 ## 特殊なケース

 一般的なエッジケースは、すべての文字列が完全に切り離されている場合です。 たとえば、次のような場合です。```
3
abc
def
ghi
```どの文字の一致も正の遷移をトリガーしないため、DP 中にすべてのペアはゼロを生成します。 アルゴリズムは維持します`best = 0`最終的な答えは 0 のままで、定義と一致します。 

もう 1 つのケースは、複数のペアが同じ最大部分文字列長を共有する場合です。 例えば：```
3
abcd
abxy
zzab
```最良のオーバーラップは 2 で、いくつかの異なるペアから得られます。 アルゴリズムは、どのペアがそれを生成したかを追跡する必要はなく、値のみを追跡する必要があります。 各 DP 実行は独立して極大値を計算し、グローバル最大値はそれらを干渉なしに安全に集計します。
