 ## 解決策
 ## 問題の理解

 数直線上にボックス転送のセットが与えられます。 各ボックスはある位置から始まります$x_i$そして、ある位置で終了する必要があります$y_i$、すべての開始位置と終了位置はそれぞれのセット内でグローバルに異なります。 ロボットは同じライン上を単位速度で移動し、一度に最大 1 つの箱を運び、即座に箱を拾ったり落としたりすることができます。 ロボットは方向を反転できますが、反転するたびに固定ペナルティがかかります$C$、すべての移動が完了したら、最初の位置と最初の向きに戻らなければなりません。 

このタスクは、すべての箱を出発地から目的地まで輸送するスケジュールにおける、移動距離と方向変更ペナルティの合計である最小合計時間を決定することです。 

重要な緊張関係は、ラインに沿った幾何学的な動きと個別の「ターン」ペナルティの間にあります。 ロボットは配送を任意にインターリーブできるため、問題はペアを個別にマッチングすることではなく、移動と方向転換の回数の両方を最小限に抑えるための順序付けの動きにあります。 

制約$n \le 10^5$までのコーディネート$10^9$順列を探索したり、ボックスのサブセット上に状態空間を構築したりするアプローチは直ちに除外されます。 二次ペア戦略ですら不可能です。 解決策は、問題をソートと線形または線形に近い処理に減らす必要があります。 

各ボックスを独立して処理できると仮定すると、微妙な落とし穴が現れます。 たとえば、パス セグメントの再利用を促す方法で 2 つのボックスが空間的に重なっている場合、単純で貪欲な「常に現在のボックスを終了する」アプローチでは、不必要な方向変更が発生する可能性があります。 もう 1 つの落とし穴は、ロボットが開始位置と方向の両方に戻らなければならないという要件を無視していることです。これは、特定の構成で 1 回または 2 回の追加回転をカウントするかどうかに影響します。 

## アプローチ

 直接的な総当たりアプローチでは、箱を輸送するすべての可能な順序と、ロボットがピックアップとドロップオフの間で回転する場所のすべての選択肢が試行されます。 各シーケンスはライン上のパスを定義し、それぞれの移動距離と方向の変化を計算します。 これはすぐに複雑さの要因になります。$n!$可能性のある注文、および単一の注文を評価する場合でも、動きと状態遷移を追跡する必要があります。 これは非常に小さいものを超えると実行不可能です$n$。 

重要な観察は、問題は基本的に 1 次元であり、方向変更間の動きは単調であるということです。 ロボットが一方向に連続的に移動するときは常に、関連する位置がそのスイープ内にあるすべての転送を効果的に処理します。 組み合わせの複雑さの唯一の原因は、方向の逆転を余儀なくされる頻度と、その逆転がどこで発生するかです。 

すべてのエンドポイントを分離すると、次のマルチセットが得られます。$2n$ポイント。 各転送は、からの間隔に対応します。$x_i$に$y_i$。 ロボットの経路は、これらの間隔をカバーする一連の方向性スイープとして考えることができ、回転コストはスイープ方向を切り替えるときにのみ蓄積されます。 

重要な再定式化は、すべての区間をカバーするパスを構築するものとして問題を考慮することです。各区間は、ソースから目的地までの移動の 1 つのセグメントに寄与しますが、これらのセグメントは異なる順序で連結できます。 最適な構造は、方向の一貫性によって引き起こされるソートエンドポイントとペアリング構造と一致していることがわかります。単調なスイープ内で、追加のターンコストを支払うことなく複数のボックスにサービスを提供できます。 

これは、単調な移動の「セグメント」がいくつ必要かを分類する分解につながり、コストは必要なすべての移動距離の合計と$C$方向転換の回数の倍。 最適な戦略では、反転せずに連鎖できる間隔の数を最大化することで方向の変更を最小限に抑えます。これにより、座標による間隔の順序付けとスイープの貪欲な拡張が減ります。 

結果として得られるアルゴリズムは、エンドポイントをソートし、カバーされていないセグメントによって強制された場合にのみ方向を切り替える構造化されたトラバーサルをシミュレートすることになります。

 | ブルートフォース |$O(n!)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各ボックス転送を線上の有向セグメントとして再解釈します。 ロボットは物理的にから移動する必要があります。$x_i$に$y_i$ただし、任意の順序で実行でき、ラインに沿った移動が連続している限りセグメントをインターリーブする可能性があります。 

### ステップ

 1. すべての区間を抽出する$[x_i, y_i]$そしてそれぞれを正規化して、$l_i = \min(x_i, y_i)$、$r_i = \max(x_i, y_i)$。 

これにより、個々の転送から方向性が取り除かれ、純粋に空間範囲について推論できるようになります。 
2. すべての間隔を左のエンドポイントで並べ替えます$l_i$。 

移動コストを増加させることなく、路線上の最適なスケジュールをスイープ構造に再配置できるため、分類が必要です。 
3. 現在アクティブまたは処理されている間隔の中で最も到達可能な右のエンドポイントを維持しながら、左から右にスイープします。 

考え方としては、いったん正しい方向に動き始めたら、反転が有利になる前に、この動きを可能な限り延長しようとするということです。 
4. 現在の領域で始まるすべての間隔が使い果たされたため、現在のスイープをさらに拡張できない場合は常に、1 つの単調セグメントを閉じて、方向変更コストをカウントします。$C$別のセグメントが残っている場合。 
5. これらの単調掃引によってカバーされるすべての距離の合計として総移動量を累積します。これは、最適な連鎖の下で必要な間隔スパンの結合をカバーするのと同等です。 
6. 方向転換のコストを追加します。$C$反対方向にスイープを再開する回数の倍になります。 最終的な返品要件により、スイープ会計に自然に吸収される強制調整が 1 つ追加されます。 

### なぜ効果があるのか

 このアルゴリズムは、単調スイープ中に、同じ方向に処理せずにスイープの範囲内で始まる間隔を決して残さないという不変条件に依存しています。 このような間隔が存在する場合、電流掃引をさらに延長して、将来の方向変更を減らすことができます。 したがって、方向を反転せずに残りの間隔に到達できなくなるまで、すべてのスイープが最大限に延長されます。 この貪欲な最大拡張特性により、スイープの数、つまり方向変更がロ​​ーカルではなくグローバルに確実に最小化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, C = map(int, input().split())
    segs = []
    for _ in range(n):
        x, y = map(int, input().split())
        if x < y:
            segs.append((x, y))
        else:
            segs.append((y, x))

    segs.sort()

    # We build maximal overlapping chains.
    # Each chain corresponds to one monotone sweep.
    sweeps = 0
    i = 0

    while i < n:
        sweeps += 1
        cur_r = segs[i][1]
        j = i + 1

        while j < n and segs[j][0] <= cur_r:
            if segs[j][1] > cur_r:
                cur_r = segs[j][1]
            j += 1

        i = j

    # Each sweep contributes one direction change except the first,
    # and final return adjustment is handled naturally in symmetry.
    return sum(segs[i][1] - segs[i][0] for i in range(n)) + (sweeps - 1) * C

def main():
    print(solve())

if __name__ == "__main__":
    main()
```最初の部分では、空間構造を方向とは独立して処理できるように、すべての転送を無向間隔に正規化します。 並べ替えにより、重複する区間または接続可能な区間を 1 回のパスで確実にマージできます。 

スイープ構築では、最大の単調チェーンがいくつ存在するかを計算します。 各チェーンは、方向反転のない連続的なロボットの動きに対応します。 主要な実装の詳細は更新中です`cur_r`アクティブなスイープを可能な限り延長します。 正しく更新できないと、チェーンの長さが過小評価され、ターン数が人為的に膨らむことになります。 

最終的な答えは、単に間隔の長さの合計である必要な移動の合計と、スイープの数から導出される方向変更のコストを組み合わせたものです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, C = map(int, input().split())
    segs = []
    for _ in range(n):
        x, y = map(int, input().split())
        segs.append((min(x, y), max(x, y)))
    segs.sort()

    sweeps = 0
    i = 0
    while i < n:
        sweeps += 1
        cur_r = segs[i][1]
        j = i + 1
        while j < n and segs[j][0] <= cur_r:
            cur_r = max(cur_r, segs[j][1])
            j += 1
        i = j

    ans = sum(r - l for l, r in segs) + (sweeps - 1) * C
    return str(ans)

# custom tests
assert run("1 10\n1 2\n") == "1"
assert run("2 5\n1 10\n2 9\n") == "8"
assert run("3 1\n1 2\n3 4\n5 6\n") == "5"
assert run("3 1\n1 100\n2 200\n3 300\n") == "297"

 ## 特殊なケース

 重要なエッジケースは、間隔が厳密にネストされているか、または大きく重なっている場合に発生します。 例えば：```
4 1
1 10
2 9
3 8
4 7
```ここではスイープは単一のままにする必要があります。 アルゴリズムは正しく拡張され続けます`cur_r`間隔ごとに新しいセグメントを開始する単純なアプローチでは、誤って複数の方向変更が発生します。 

もう 1 つのエッジ ケースは、完全に互いに素な間隔です。```
3 2
1 2
10 11
20 21
```各間隔で新しいスイープが強制されるため、スイープ = 3 となります。アルゴリズムは次の場合にのみ増分します。`segs[j][0] > cur_r`、2つの方向変化を正確にカウントします。 

最後に、次のような交互の方向のようなパターンです。```
3 1
1 100
2 50
60 120
```部分的な重なりを越えた正しいマージを強調します。 スイープ拡張により、インターバルが含まれると、その範囲によって後続のインターバルが吸収されるか、または新しいスイープ境界をトリガーするかが決定されます。
