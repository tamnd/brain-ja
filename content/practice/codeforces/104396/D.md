 ## 問題の理解

 平面内の一連の点が与えられます。 各点は星を表します。 すべてのスターのために$i$、私たちはその星に立って、その星を通る直線を引くことを想像します。 この線は他の星を通過しないようにする必要があります。 線を引くと、他のすべてが分割されます$n-1$星は線のどちら側にあるかに応じて 2 つのグループに分けられます。 

固定スターティングスターの場合$i$、私たちは、両側の一方に正確に含まれるようにそのような線を選択できるさまざまな方法が何通りあるかに興味があります。$k$星。 各有効な行は、対応する 1 つの選択肢に寄与します。$k$。 私たちが必要とする答えは、次のような行列です。$A_{i,k}$ポイントを通る線の数を数えます$i$正確にサイドを生成します$k$ポイント。 

重要な問題は、ラインが固定されていないことです。 点を中心に回転できます$i$、すべての方向で残りのポイントの異なる分割が生成されます。 各点の周囲で何方向の分割が可能性のある各辺のサイズを生成するかを効果的に数えています。 

制約が意味するのは、$n \le 2000$。 点ペアの二次数はすでに約に達しています$4 \cdot 10^6$慎重に扱えば、Python では問題ありません。 立方体のものは遅すぎます。 これは、各中心点を個別に処理し、中心ごとに線形または線形に近い時間を費やす必要があることを直ちに示唆しています。 

微妙なエッジ ケースは、多くの点が参照点とほぼ同一線上にある場合です。 「半平面の境界」を慎重に処理しない単純な角度ソートのアプローチでは、二重にカウントされたり、構成を見逃したりする可能性があります。 もう 1 つのよくある間違いは、境界線上の点を厳密に避けて開いた半平面を数えていることを忘れていることです。そのため、他の点が選択した方向に正確に存在しないことを確認する必要があります。 

## アプローチ

 強引なアイデアは、ポイントを修正することです$i$、次に、考えられるすべての行を列挙します。$i$ペアリングで決まる$i$他の点ごとに$j$。 このような各線の方向は、有向線のどちら側にあるかに応じて、残りのすべての点を 2 つのセットに分割することを定義します。 方向ごとに、片側にある点の数を数え、対応する値を増分します。$A_{i,k}$。 

これは正しいです。有効な区切り線はすべて$i$によって定義される線と平行でなければなりません$i$もう 1 つの点は、線はその方向によって決まり、有限の点の集合をどのように分割するかだけを考慮するためです。 ただし、固定ごとに$i$、これには必要になります$O(n)$方向と各方向について$O(n)$ポイントの分類、付与$O(n^3)$合計の操作は遅すぎます$n = 2000$。 

重要な観察は、固定中心の場合です。$i$重要なのは、周囲の他のすべての点の角度順序だけです。$i$。 すべてのベクトルをソートすると$i \to j$極角によって、任意の半平面は、長さ未満の連続する円弧に対応します。$180^\circ$この循環注文について。 各方向のポイント数を再計算する代わりに、2 ポインター スイープを使用して、各方向から始まる半円ウィンドウ内にあるポイントの数を維持できます。 これにより、センターあたりのコストが削減されます。$O(n \log n)$ソートプラス用$O(n)$スキャン用。

 ## アルゴリズムのチュートリアル

 それぞれのポイントについて$i$、それを原点として扱い、それに関連する他のすべての点を分析します。 

1.固定の場合$i$、からベクトルを計算します$i$1つおきの点まで$j$。 各ベクトルには角度があります。$[0, 2\pi)$。 これにより、幾何学的分割問題が角度順序付け問題に変換されます。 
2. これらすべてのベクトルを極角で並べ替えます。 ソートされた順序はポイントの周りを歩くことを表します$i$完全な円で。 
3. 角度を付けて各ベクトルを再度追加して、ソートされたリストを複製します。$+2\pi$。 これにより、線形構造を使用して円形のラップアラウンドをシミュレートできるようになります。 
4. 2 ポインタテクニックを使用します。 開始インデックスごとに$l$、ポインタを移動します$r$角度差が以下である限り前方に進みます$180^\circ$。 窓$[l, r)$方向から始まる有効な半平面内にあるすべての点を表します$l$。 
5. このウィンドウ内のポイントの数を次のようにします。$w = r - l - 1$。 これは、方向に合わせて境界線を選択することを意味します。$l$正確に生成します$w$片側にポイント。 
6. インクリメント$A[i][w]$から始まる有効なウィンドウごとに 1 ずつ増加します$l$。 これにより、すべての個別の区切り線が 1 回ずつカウントされます。 
7. すべてに対して繰り返します$i$、完全な行列が生成されます。 

重要な点は、すべての有効な有向線が$i$は正確に 1 つの角度開始方向に対応し、スイープにより各最大半平面が正確に 1 回カウントされることが保証されます。 

### なぜ効果があるのか

 角度スイープは、可能なすべての分離線をエンコードします。$i$ある点と角度順で次の点との間の境界として。 半平面制約は、厳密に以下の角度スパンに相当するため、$180^\circ$、すべての実現可能な構成は、循環順序付けにおける連続した円弧に対応します。 2 ポインター ウィンドウは、各方向から始まるすべての最大の円弧を検索し、そのような各円弧は有効な直線の片側の点のセットを一意に決定します。 問題の構築により、他の点が境界上に正確に存在することはないため、構成が欠落したり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    ans = [[0] * (n - 1) for _ in range(n)]

    for i in range(n):
        x0, y0 = pts[i]
        arr = []

        for j in range(n):
            if i == j:
                continue
            x, y = pts[j]
            dx = x - x0
            dy = y - y0
            arr.append((math.atan2(dy, dx), dx, dy))

        arr.sort(key=lambda t: t[0])
        m = n - 1

        ext = arr + [(a + 2 * math.pi, dx, dy) for a, dx, dy in arr]

        r = 0
        for l in range(m):
            if r < l:
                r = l
            while r < l + m and ext[r][0] - ext[l][0] < math.pi:
                r += 1
            w = r - l - 1
            ans[i][w] += 1

    out = []
    for i in range(n):
        out.append(" ".join(map(str, ans[i])))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では、次を使用して各点の周囲に角度ベクトルを構築します。`atan2`これにより、すべての象限で正しい順序が保証されます。 複製ステップ`+2π`モジュラー演算を行わずにラップアラウンドを処理するには不可欠です。 

2 ポインター ウィンドウは、左のエンドポイントごとに右のエンドポイントを前方にのみ拡張して、センターごとの償却線形時間を確保するように慎重に維持されます。 引き算`r - l - 1`ピボット方向自体をカウントから削除します。 

よくある落とし穴はリセットを忘れることです`r`それが遅れたとき`l`これにより、単調性が崩れ、ウィンドウ サイズが不正確になります。

 ## 特殊なケース

 縮退したように見える構成とは、多くの点がピボットとほぼ同一線上にある場合です。 このような場合、浮動小数点精度の小さな誤差が発生します。`atan2`順序付けにより、角度リスト内の隣接関係が変更される可能性があります。 このアルゴリズムは厳密な順序付けに依存しているため、半平面境界の誤分類を避けるために、安定した並べ替えと一貫した角度表現が必要です。 

もう 1 つのエッジ ケースは、すべてのポイントがピボットを中心とした半円内にある場合です。 この状況では、スライディング ウィンドウは常にすべてのポイントを含むように拡張され、行内に 0 以外のエントリが 1 つだけ生成されます。 条件が次のとおりであるため、アルゴリズムはこれを正しく処理します。`angle < π`オーバーフローやラップアラウンドの問題のない、到達可能な完全なセットが含まれています。 

最後の微妙なケースは、点が円の周りにほぼ均等に分布している場合です。 ここでは、開始方向ごとに異なる最大円弧が生成され、アルゴリズムは各円弧が正確に 1 回カウントされることを保証する必要があります。 右ポインタの厳密な単調な進行により、開始インデックスとカウントされる構成の間の 1 対 1 マッピングが保証されます。
