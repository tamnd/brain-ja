 ## 解決策
 ## 問題の理解

 あります`n`あなた自身を含め、エレベーターの中にいる人々。 誰もが目的階を選択しています。 選択したすべての目的地のうち、正確に`m`個性的なフロアが現れます。 

目的階は自由に選択できます。目標は、自分を含む何人が同じ階で一緒にエレベーターから降りるかを最大化することです。 まさにそれ以来`m`異なるフロアを表す必要があり、目的地は他のフロアに割り当てられます。`n - 1`この要件を満たす有効な方法であれば、どのような方法でも人員を分散させることができます。 

各テスト ケースでは、合計人数と個別の目的階の数のみが与えられます。 私たちと同じフロアから出ることができる最大のグループを計算する必要があります。 

最大の入力値はほんのわずかです`10^4`そして、すべてのテスト ケースには 2 つの整数だけが含まれます。 あったとしても`10^4`テストケース、`O(1)`ケースごとのソリューションは、全体として少数の算術演算のみを実行します。 答えは単純なカウント引数のみに依存するため、これ以上複雑なアルゴリズムは必要ありません。 

簡単な間違いの 1 つは、各フロアに少なくとも 1 人の乗客が必要であることを忘れることです。 

例えば、```
n = 5
m = 5
```正しい答えは、`1`。 すべての乗客は異なるフロアを選択する必要があるため、誰もあなたの目的地を共有することはできません。 

もう 1 つのよくある間違いは、残りの乗客がいつでもフロアを選択できると想定していることです。 

例えば、```
n = 6
m = 3
```正しい答えは、`4`、 ない`6`。 自分のフロアの他に、別の 2 つの異なるフロアがまだ存在する必要があります。 これらの各フロアには少なくとも 1 人の乗客を割り当てる必要があり、そのフロアには 4 人だけが残されます。 

最小の入力にも注目する必要があります。```
n = 1
m = 1
```答えは`1`。 乗客はあなただけなので、みんなで一緒に出発します。 

## アプローチ

 強引な視点は、すべてを分散させることを想像することです。`n`まさに乗客の間で`m`異なるフロアをチェックし、有効なディストリビューションをすべてチェックします。 分布ごとに、単一のフロアに割り当てられた最大のグループを記録し、あらゆる可能性の最大値を保持します。 

このアプローチは、すべての法的割り当てを検査するため、正しいです。 残念なことに、そのようなディストリビューションの数は、`n`そのため、中程度の入力サイズであってもまったく実用的ではありません。 

重要な観察は、正確な分布を知る必要がないということです。 私たちと一緒に出発する人の数を最大にするために、別のフロアに強制的に移動させられないすべての乗客は、代わりに私たちのフロアを選択する必要があります。 

まさにあるはずなので、`m`別々のフロアがあり、そのうちの 1 つは私たちのものですが、残りは`m - 1`各フロアには少なくとも 1 人の乗客が必要です。 他の各フロアに 1 人の乗客を正確に割り当てます。 これは、`m - 1`人々、去っていく```
n - (m - 1) = n - m + 1
```私たちも含めて、フロアにいる人々。 

追加の人がフロアに移動するたびに、必要な個別のフロアの 1 つが空になるため、これ以上の答えはありません。

 ## アルゴリズムのチュートリアル

 1. 値を読み取る`n`そして`m`。 
2. 乗客を 1 名ずつ予約します。`m - 1`個性的なフロア。 これは、必要なすべてのフロアを表現し続けるための最小限の割り当てです。 
3. 残りの乗客全員をフロアに配置します。 他に制約が存在しないため、これにより、一緒に出発する可能な最大のグループが生成されます。 
4. 答えを次のように計算します。`n - m + 1`。 
5. 現在のテスト ケースの結果を出力します。 

### なぜ効果があるのか

 すべての有効な割り当てには、それぞれの座席に少なくとも 1 名の乗客が含まれている必要があります。`m - 1`あなたとは違うフロア。 それらの乗客も一緒に出発することはできません。 これは少なくとも`m - 1`グループから人が除外されるため、グループのサイズは最大でも`n - (m - 1)`。 アルゴリズムは、1 人の乗客だけを 1 つおきのフロアに割り当て、他の乗客全員を自分のフロアに配置することで、まさにこの値に達します。 上限に達しているため、結果は最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        out.append(str(n - m + 1))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```プログラムはまずテスト ケースの数を読み取ります。 各テスト ケースは独立して処理されるため、ケース間で情報を保存する必要はありません。 

解全体は算術式です`n - m + 1`。 これは、アルゴリズムで開発されたカウント引数から直接得られます。 乗客やフロアを覆うループは必要ありません。 

使用する`sys.stdin.readline`テスト ケースの数が最大値に達した場合でも、入力を高速に保ちます。 回答はリストに蓄積され、最後にまとめて印刷されるため、多くの個別の出力操作が不要になります。 

Python の整数には任意の精度があり、問題の制約がすでに小さいため、オーバーフローの懸念はありません。 唯一の境界条件は次の場合です。`m = n`、この場合、数式は正しく評価されます。`1`。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline
    t = int(input())
    ans = []
    for _ in range(t):
        n, m = map(int, input().split())
        ans.append(str(n - m + 1))
    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out

# custom cases
assert run("1\n1 1\n") == "1", "minimum case"
assert run("1\n6 3\n") == "4", "general case"
assert run("1\n5 5\n") == "1", "all floors distinct"
assert run("1\n10 1\n") == "10", "everyone can leave together"
assert run("1\n10000 9999\n") == "2", "boundary values"
