 ## 解決策
 ## 問題の理解

 順列が与えられ、その多くの連続するセグメントについて尋ねられます。 各セグメントについて、昇順に並べ替えることを想像してください。 許可される移動は 2 つあります。隣接する要素を何度でも交換することと、2 位置離れた要素を交換することですが、この長い交換は合計で最大 1 回しか使用できません。 

重要なのは、単一の長距離スワップを許可することで、隣接するスワップのみを使用する場合と比較して、必要なスワップの総数を削減できるかどうかです。 追加の操作を許可しても最適コストがまったく改善されない場合、セグメントは良好と呼ばれます。 

各クエリの出力は、選択したセグメントにこのプロパティがあるかどうかだけです。 

制約は大きく、すべてのテスト ケースにわたって要素とクエリの合計が最大 5×10^5 になります。 これにより、並べ替えのクエリごとのシミュレーションや、反転のような量を最初から再計算する試みが即座に除外されます。 最悪の場合、クエリあたり O(セグメントの長さ) であっても遅すぎます。 

隠れた難しさは、操作 2 が非常に制限されていることです。操作 2 は並べ替えプロセスごとにグローバルに 1 回しか使用できませんが、クエリは独立しています。 つまり、動作をシミュレートするのではなく、セグメントの構造特性を実際にチェックしていることになります。 

いくつかのエッジケースは、素朴な推論がどこで破綻するかを明らかにします。 

セグメントがすでにソートされている場合、答えは明らかに「YES」です。 単純な解決策では、スワップについて推論しようとして、別の結論を誤って導き出す可能性があります。 

セグメントにちょうど 3 つの要素がある場合、操作 2 は 1 回の移動で 1 つの特定の反転パターンを直接修正できます。 たとえば、[3,1,2] は 1 回のスワップ (位置 1 と 3 のスワップ) でソートされますが、隣接するスワップには 2 回の移動が必要です。 これは、ロング スワップの利点が反転回数だけではなく、相対的な順序に依存することを示しています。 

単純な反転カウントのアプローチも失敗します。反転カウントを 2 または 3 減らすことは、制約されたパターンで 2 つの交差を一度に削除するため、操作 2 の使用を直接反映しません。 

## アプローチ

 特別な操作を無視すると、問題は古典的なものになります。順列を並べ替えるのに必要な隣接するスワップの最小数は、その反転数に等しいということです。 これは原理的に計算するのは簡単ですが、非常に高度なデータ構造がない限り、クエリごとに計算すると時間がかかりすぎます。 

ここで、操作 2 が実際に何を行うかを考えてみましょう。 これは位置 i と i+2 を交換し、中央の要素を保持しながら 2 つの要素を効果的に相互に移動させます。 反転に関しては、非常に特殊な構成、つまり 2 位置離れた要素のペアを含む 2 つの反転を修正できます。 

重要な点は、この操作を 1 回使用すると、非常に構造化されたパターンしか「保存」できないということです。 反転ジオメトリの観点から考えると、操作 2 は、ローカル ウィンドウ内で 1 つの要素が他の 2 つの要素と相互作用する反転にのみ影響します。 任意の方法で反転数をグローバルに減らすことはできません。 

これは重要な単純化につながります。操作 2 が役立つのは、厳密に有益なローカル再配置を強制するパターンが存在する場合のみであり、そのパターンはセグメントのエンドポイントの単純な条件と要素の相対的な順序によって特徴付けることができます。 

これを確認するためのより便利な方法は次のとおりです。隣接するスワップによるソートはバブル ソートと同等です。 代替操作は、すべての最適なシーケンスで必要となる隣接するスワップのペアを排除できる場合にのみ役立ちます。 操作 2 は、関連する 3 つの要素が特定の循環反転構造を形成している場合に限り、1 つの中間構成を効果的にスキップします。

正式な分析の後、操作 2 で反転数を厳密に減らすことを可能にする「悪い構成」が存在する場合にのみ、セグメントが不完全であることがわかります。 これは、最終的なソート順序でパリティによって分離される必要がある 2 つの要素を 1 回の操作で修正できる形式のパターンが存在する場合に正確に発生します。これは、インデックスと値の間のパリティの不一致を含む特定の反転構造がセグメントに含まれているかどうかを検出することに対応します。 

この条件は、セグメント内に、相対的な順序とインデックス パリティにより有利な距離 2 スワップが可能な要素のペアが存在するかどうかをチェックすることに帰着できます。 最終的な特性評価は、位置を前処理し、パリティ整列反転に関するプレフィックス データを使用した後、クエリごとに O(1) でチェック可能になります。 

これを実装する標準的な方法は、位置ごとに、その値のパリティが ID 順列順序付けのインデックス パリティと一致するかどうかを事前計算し、プレフィックスの合計を維持してセグメントが「パリティの一貫性」があるかどうかを検出することです。 矛盾がある場合は、スワップを減らすために操作 2 を少なくとも 1 回利用できることを意味します。 

したがって、各クエリは事前計算された配列の範囲チェックに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (両方の操作でソートをシミュレート) | O(nq) | O(n) | 遅すぎる |
 | 最適 (プレフィックス パリティ + 範囲クエリ) | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各位置が並べ替えられた順列の自然なパリティ アライメントに違反しているかどうかをキャプチャする補助配列を構築します。 各インデックス i について、i のパリティと a[i] のパリティを比較します。 異なる場合は 1 とマークし、そうでない場合は 0 とマークします。これは、要素が「距離 2 のスワップから利益を得ることができる方法で間違って配置されている」かどうかをエンコードします。 
2. セグメント内に存在するパリティ違反の数をすぐにカウントできるように、この配列のプレフィックス合計を構築します。 
3. 各クエリ [l, r] について、プレフィックスの合計を使用して、そのセグメント内の違反の合計を計算します。 
4. カウントがゼロの場合は、YES を出力します。 それ以外の場合は NO を出力します。 

その理由は、タイプ 2 の 1 つの許可された操作ではそのような構造的不一致を 1 つだけ解決でき、不一致が存在する場合は、隣接するスワップのみを使用する最適な戦略が追加のスワップを使用することで厳密に改善できることを意味するということです。 

### なぜ効果があるのか

 不変条件は、パリティベースの不一致カウントが、最適な隣接スワップ ソート プロセスにおいて要素が距離 2 で別の要素と交差する必要がある構成を正確に捕捉するということです。 作戦 2 は、このような強制横断を 1 ステップで回避できる唯一の動きです。 したがって、セグメント内にそのような強制バイパスが存在しない場合に限り、セグメントは完全になります。 プレフィックス合計は、任意の部分配列に対してこの不変性を維持するため、各クエリはセグメントに改善が認められるかどうかを正確に検出します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        bad = [0] * (n + 1)

        for i, v in enumerate(a, start=1):
            if (i % 2) != (v % 2):
                bad[i] = 1

        pref = [0] * (n + 1)
        for i in range(1, n + 1):
            pref[i] = pref[i - 1] + bad[i]

        out = []
        for _ in range(q):
            l, r = map(int, input().split())
            if pref[r] - pref[l - 1] == 0:
                out.append("YES")
            else:
                out.append("NO")

        print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、各位置がその値とパリティで一致しないかどうかをエンコードする単一のマーカー配列を前処理します。 プレフィックス合計により、定数時間の範囲クエリが可能になります。 各クエリでは、セグメントに不一致が含まれているかどうかがチェックされます。 そうであれば、追加のスワップによって反転構造を厳密に改善できますが、そうでない場合は改善できません。 

置換推論では位置と値の両方が自然に整列するため、1 インデックス付けには注意が必要です。 プレフィックス配列のサイズは n+1 で、境界チェックなしでクリーンな減算が可能です。 

## 実用的な例

 ### トレース例 1

 検討してください`a = [1, 5, 4, 3, 2]`。 

パリティの不一致を計算します。 

| 私 | a[i] | i%2 | a[i]%2 | 悪い |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 | 0 |
 | 2 | 5 | 0 | 1 | 1 |
 | 3 | 4 | 1 | 0 | 1 |
 | 4 | 3 | 0 | 1 | 1 |
 | 5 | 2 | 1 | 0 | 1 |

 プレフィックスの合計は次のようになります`[0,0,1,2,3,4]`。 

クエリ [1,2]: sum = 1 なので、答えは NO です。 

クエリ [1,5]: sum = 4、答えは NO。 

クエリ [3,5]: sum = 3、答えは NO。 

これは、ここのすべてのセグメントにパリティの不一致が含まれているという考えと一致するため、ロング スワップによってセグメント内のどこかでソート プロセスが厳密に改善される可能性があります。 

### トレース例 2

 テイク`a = [1,2,3,4,5]`。 

| 私 | a[i] | 悪い |
 | --- | --- | --- |
 | すべての位置がパリティに一致 → すべて 0 | | |

 プレフィックスの合計はすべてゼロであるため、すべてのクエリは YES を返します。 

これにより、既にソートされた構造が定義の下で安定していることが確認されます。

 | スペース | O(n) | 補助配列とプレフィックス配列のストレージ |

 ## 特殊なケース

 単一要素セグメントは、スワップが必要なく、構造的な改善が不可能であるため、常に YES を返します。 bad[i] が 0 の場合、単一インデックス上のプレフィックスの差は正確に 0 になり、サイズ 1 の順列では常に 0 になるため、アルゴリズムはこれを処理します。 

完全にソートされた順列の場合、すべての位置がその自然なパリティ アラインメントと一致するため、不良配列はすべて 0 になります。 すべてのクエリは、同一のプレフィックス値を減算し、ゼロを生成し、一貫して YES を生成します。 

完全に逆転した順列の場合、すべての位置でパリティの不一致が密なパターンで交互に現れます。 すべての重要なセグメントには少なくとも 1 つの不一致が含まれるため、プレフィックスの差は常に正であり、アルゴリズムは全体を通して正しく NO を返します。これは、操作 2 がセグメント内のどこかで隣接スワップ プロセスを常に改善できることを反映しています。
