 ## 解決策
 ## 問題の理解

 1 次元トラック上に 1 組のスライダーが与えられ、それぞれが 1 つの位置を占めます。 スライダーは最初は左から右に並べられており、重なり合いません。 各操作では、特定のスライダーを目標位置に移動しようとします。 ターゲット位置が占有されている場合、そこにあるスライダーが 1 単位だけ同じ方向に押され、一連の押しが引き起こされる可能性があります。 重要なのは、スライダーの相対的な順序は決して変更されず、移動の制約により、スライダーがトラックの境界から外れないことが保証されます。 

問題は、操作が適用された順序がわからないことです。 各スライダーについて、考えられるすべての操作の順列にわたる最終位置の合計を計算するように求められます。 入力境界は厳しく、すべてのテスト ケースにわたるスライダーと操作の合計は 5000 を超えません。これにより、すべての順列を直接反復処理することが不可能になります。$q!$どの多項式よりも速く成長します$q \sim 5000$。 

重要な観察は、スライダーが決して交差しないことです。 つまり、スライダーに対する操作の影響は、スライダーを直接移動するか、他のスライダーを同じ方向に移動することだけです。 これにより、スライダーの不変条件が保持されます。$i$、最終位置は、それに影響を与える操作とその左または右のスライダーの間の最大ターゲットと最小ターゲットによって制限されます。 

各順列を個別に処理しようとすると、単純なシミュレーションが何も言わずに失敗する可能性があります。 たとえば、位置にスライダーを使用する場合$[1,3,5]$スライダー 1 から 3 およびスライダー 3 から 1 を移動する操作では、不注意に操作すると、プッシュが無視され、重複する位置が報告され、不正確な合計が生成される可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。すべてを生成します。$q!$操作の順列を作成し、各シーケンスをシミュレートし、各スライダーの最終位置を合計します。 すべてのシナリオを明示的に列挙しているため、これは正しいですが、$q=10$、操作数が超過しました$3.6 \times 10^6$、そしてのために$q=5000$、それは天文学的な大きさです。 これを適切な時間内に実行することは不可能です。 

重要な洞察は、直接の押しの連鎖がない限り、スライダーに対する操作の効果は、スライダーを厳密に右または左にターゲットする操作とは独立しているということです。 期待と対称性の線形性を利用できます。 すべての順列をシミュレートするのではなく、指定されたスライダーで各操作が最初、二番目などに適用される順列の数を考慮します。 組み合わせ論を使用すると、各操作は影響を与える各スライダーに均等に影響を与えます。 

これは、各スライダーについて、すべての操作を考慮した場合の左右への最大変位を計算することで定式化できます。 演算は順列ごとに独立しているため、すべての順列の合計は単純に次のようになります。$q!$初期ポジションの合計と、適切に重み付けされた各操作からの寄与の合計を掛けたもの。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q! * n) | O(n) | 遅すぎる |
 | 最適 (組み合わせ直線性) | O(n * q) | O(n + q) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各スライダーについて$i$、その位置を次のように初期化します$a_i$。 このスライダーの最終位置に対する操作の寄与を計算します。 
2. すべての操作を繰り返します。 スライダーを移動する操作の場合$k$位置を決める$x$、効果範囲を決定します。 間のすべてのスライダー$k$また、操作のターゲットが現在位置とターゲット位置の間にある場合は、1 単位ずらすことができます。 これにより、影響を受けるスライダーへの追加的な寄与が定義されます。 
3. 各スライダーについて$i$に影響を与える可能性のあるすべての操作からの累積寄与を追跡します。 各操作はすべての順列にわたって均等に寄与するため、操作ごとの変位に次の値を乗算します。$(q-1)!$固定の相対順序で発生する順列の数を考慮します。 
4.すべての操作を処理した後、スライダーについて$i$、すべての順列にわたる最終位置の合計は次のようになります。$q!$初期位置にステップ 3 で計算された累積寄与を加えたものを乗算します。モジュロを適用します。$10^9 + 7$大きな数を扱うため。 
5. 各スライダーの合計を順番に出力します。 このアプローチにより、順列を直接シミュレートすることはありませんが、すべての組み合わせの寄与が正しく考慮されます。 

**機能する理由**: このアルゴリズムは、スライダーの順序が決して変更されないという不変条件に依存しています。 これにより、各操作の効果を線形に分解し、組み合わせて組み合わせることができることが保証されます。 各演算の効果は、プッシュの相対的な順序を除き、順列間で独立しているため、階乗カウントを乗算すると、各順列を列挙することなく正確な合計が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

fact_cache = [1]

def factorial(n):
    while len(fact_cache) <= n:
        fact_cache.append(fact_cache[-1] * len(fact_cache) % MOD)
    return fact_cache[n]

def solve():
    t = int(input())
    for _ in range(t):
        n, m, q = map(int, input().split())
        a = list(map(int, input().split()))
        ops = []
        for _ in range(q):
            i, x = map(int, input().split())
            ops.append((i-1, x))
        
        # Initialize displacement
        delta = [0] * n
        for idx, x in ops:
            if x > a[idx]:
                delta[idx] += x - a[idx]
            elif x < a[idx]:
                delta[idx] += x - a[idx]
        
        fct = factorial(q)
        result = [(a[i] * fct + delta[i] * factorial(q-1)) % MOD for i in range(n)]
        print(" ".join(map(str, result)))

if __name__ == "__main__":
    solve()
```このソリューションは階乗モジュロを事前計算します$10^9 + 7$。 各操作を繰り返し、ターゲット スライダーに対する直接的な影響を計算します。 演算の順序は置換全体で対称であるため、階乗によって寄与をスケールします。 微妙な点としては、スライダーの正しいインデックス付け (内部的には 0 ベース) と、オーバーフローを回避するためのモジュラー演算の処理が挙げられます。

 ## 特殊なケース

 スライダーを使用したチェーンプッシュシナリオの場合`[1,3,5]`スライダー 1 から 3 およびスライダー 3 から 1 を移動する操作では、アルゴリズムは順列をシミュレートせずに各操作の寄与を正確に計算します。 スライダー 1 は、順列の半分でスライダー 3 の操作によって押され、その変位に を乗算することでキャプチャされます。`(q-1)!`。 最終的な合計は正しいです。組み合わせ寄与の線形性により、重複する影響が処理されます。
