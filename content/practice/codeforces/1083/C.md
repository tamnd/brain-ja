 ## 解決策
 ## 問題の理解

 私たちは根を張った木を与えられています$n$ノード。 各ノードは、次の異なる値を保存します。$0$に$n-1$, したがって、値は順列を形成します。 これに加えて、ツリー構造は固定されていますが、値はスワップ操作を通じて時間の経過とともに変化する可能性があります。 

2 つの操作がサポートされています。 2 つのノードに格納されている値を交換します。 もう 1 つは、グローバルな最適化問題を要求します。ツリー内のすべての単純なパスのうち、そのパスに現れる値のセットを考慮し、その MEX (存在しない最小の非負の整数) を計算します。 すべてのパスにわたって可能な最大 MEX を報告する必要があります。 

重要な問題は、答えが値のどの接頭辞にのみ依存することです。$0,1,2,\dots$何らかのパスで完全にカバーできます。 パスに少なくとも MEX がある場合$k$、以下のすべての値が含まれている必要があります。$0$に$k-1$。 したがって、問題は最大のものを求めることになります。$k$現在値を保持しているすべてのノードを含むツリー パスが存在するようにする$0$を通して$k-1$。 

これは、最大で次の動的なツリー問題です。$2 \cdot 10^5$したがって、クエリごとにパス情報を再計算したり、すべてのパスをチェックしたりするソリューションは、直ちに不可能になります。 パスの数がすでに制限されているため、パス上の 3 次または 2 次スキャンは失敗します。$O(n^2)$。 

値が交換されると、微妙なエッジケースが発生します。 素朴な解決策では、値の位置は維持されますが、私たちが関心を持っている構造は、移動するノードのセット間で誘導されるサブツリー パスの実現可能性であるということを忘れてしまう可能性があります。 もう 1 つのよくある間違いは、ノードに次のものがあると仮定することです。$0 \dots k-1$常に接続されたサブツリーを形成します。 そうではなく、接続性はツリーの LCA 構造に依存します。 

## アプローチ

 ブルート フォース アプローチでは、すべての単純なパスが考慮され、現在のラベル付けに基づいてその MEX が計算されます。 すべてを事前計算したとしても$O(n^2)$LCA を使用したパスでは、クエリごとに MEX を再計算するには、パスに沿って値をスキャンする必要があるため、$O(n^3)$最悪の場合の総作業量。 これは限界をはるかに超えています。 

中心的な観察は、任意の値のセットが決して必要ないということです。 MEX 条件では、順列の接頭辞のみを考慮する必要があります。 固定の場合$k$の場合、問題は次のようになります。値を含むノードを実行します。$0$を通して$k-1$何か単純な道に横たわっていますか？ ノードのセットは、オイラー次数でソートされた配置における連続するノード間の距離の合計が直径に似た鎖の長さの条件と等しい場合に限り、単純なパス上にあります。より具体的には、そのセットが単一のパスに含まれている場合に限り、LCA とエンドポイントでテストできます。 

より有用な変換は、ノードのセットをカバーする最小限のパスを維持するという観点から考えることです。 セットの場合$S$、その仮想ツリー直径の端点を定義します: の最も遠いペア$S$。 すべてのノードがこれら 2 つのエンドポイント間のパス上にある場合に限り、セットは単一のパス上にあります。これは距離と LCA を使用して検証できます。 

私たちは値のポジションを維持し、スワップをサポートします。$\{0,\dots,k-1\}$ダイナミックです。 問題は、ツリー内でノードが同一線上にある最大のプレフィックスを維持することになります。 

高速チェックをサポートするために、プレフィックス パスの現在のエンドポイントを維持し、新しく追加された値を段階的に検証します。 それぞれについて$k$、現在の直径エンドポイントを追跡し、LCA 距離アイデンティティを使用してすべてのノードがそれらの間のパス上にあることを検証することで、セットがパスの一貫性を維持しているかどうかを維持できます。 

これを順列値に対するセグメント ツリーのようなメンテナンスと組み合わせて、更新位置を交換します。$O(\log n)$または$O(1)$、最大有効プレフィックスの再計算はバイナリ リフティング チェックによって行われます。 

本質的に、この構造は、動的に順序付けられたノードのセットを維持し、ノードがツリー内でチェーンを形成しているかどうかを検証することに要約されます。

 ## アルゴリズムのチュートリアル

 ノードでツリーをルートします$1$LCA と距離のバイナリ リフティング テーブルを前処理します。 

配列を維持します`pos[v]`ノードが現在保持している値を与える$v$。 

現在の回答プレフィックス境界も維持します`best_k`、これが最大です$k$ノードが値を保持するように$0$を通して$k-1$単一の単純な道の上に横たわります。 

1. 以下の値をスキャンして初期化します。$0$上向きで、2 つのエンドポイントによって定義された現在の候補パスを維持します$a$そして$b$。 最初は両方とも以下を含むノードです。$0$。 
2. 付加価値を付ける場合$k$、ノードを挿入します$pos[k]$現在のセットに追加します。 セットが以前に有効だった場合、無効になる唯一の方法は、このノードが間の現在のパスの外側にある場合です。$a$そして$b$。 
3. もし$k=0$、設定しました$a=b=pos[0]$そして、有効性を true としてマークします。 
4. のために$k>0$、新しいノードが次の間のパス上にある場合$a$そして$b$の場合、現在のプレフィックスは有効なままであり、エンドポイントは変更されません。 
5. それ以外の場合は、候補パスを拡張する必要があります。 新しい直径の端点は次のペアになります。$(a, pos[k])$そして$(b, pos[k])$離れているものは更新されます$a,b$それに応じて。 
6. 各更新の後、プレフィックス内のすべてのノードが次の間のパス上に残っていることを確認します。$a$そして$b$。 これは、任意のノードに対して次の条件を使用して行われます。$x$、$dist(a,b) = dist(a,x) + dist(x,b)$。 これが失敗すると、プレフィックスは次の位置で中断されます。$k-1$。 
7. スワップクエリの場合、更新します`pos`次に、ロールバックまたは二分探索を使用して、影響を受けるプレフィックス境界の周囲でローカルにのみ有効性を最初から再計算します。$k$上記の確認手順で。 

重要な考え方は、プレフィックスの有効性が単調であるということです。つまり、プレフィックスが失敗すると、より大きなプレフィックスもすべて同様に失敗するため、有効な最大値を二分探索できるということです。$k$各アップデートの後。 

### なぜ効果があるのか

 ノードのセットは、セット内のすべてのノードがそれらの間の一意のパス上に存在するようなエンドポイントのペアが存在する場合にのみ、単純なパス上に存在します。 アルゴリズムは、これらのエンドポイントを動的直径候補として正確に維持します。 LCA 距離 ID は、パス上のメンバーシップ チェックの正確さを保証します。 プレフィックスは一度に 1 要素ずつ増加し、失敗は単調であるため、二分探索は$k$常に最大の実現可能なプレフィックスに収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
p = list(map(int, input().split()))
g = [[] for _ in range(n)]
par = list(map(int, input().split()))

for i in range(1, n):
    g[i].append(par[i-1]-1)
    g[par[i-1]-1].append(i)

LOG = 20
up = [[-1]*n for _ in range(LOG)]
depth = [0]*n

def dfs(v, p):
    up[0][v] = p
    for to in g[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        dfs(to, v)

dfs(0, -1)

for k in range(1, LOG):
    for v in range(n):
        if up[k-1][v] != -1:
            up[k][v] = up[k-1][up[k-1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for i in range(LOG):
        if diff & (1 << i):
            a = up[i][a]
    if a == b:
        return a
    for i in reversed(range(LOG)):
        if up[i][a] != up[i][b]:
            a = up[i][a]
            b = up[i][b]
    return up[0][a]

def dist(a, b):
    c = lca(a, b)
    return depth[a] + depth[b] - 2 * depth[c]

pos = [0]*n
for i, v in enumerate(p):
    pos[v] = i

def on_path(a, b, x):
    return dist(a, x) + dist(x, b) == dist(a, b)

def check(k):
    if k == 0:
        return True, pos[0], pos[0]
    a = pos[0]
    b = pos[0]
    for i in range(1, k):
        x = pos[i]
        if on_path(a, b, x):
            continue
        # expand diameter
        if dist(x, a) > dist(a, b):
            b = x
        elif dist(x, b) > dist(a, b):
            a = x
        else:
            a = a
    # final verification
    for i in range(k):
        x = pos[i]
        if not on_path(a, b, x):
            return False, a, b
    return True, a, b

def get_answer():
    lo, hi = 0, n + 1
    best = 0
    while lo <= hi:
        mid = (lo + hi) // 2
        ok, _, _ = check(mid)
        if ok:
            best = mid
            lo = mid + 1
        else:
            hi = mid - 1
    return best

q = int(input())
for _ in range(q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 1:
        _, i, j = tmp
        i -= 1
        j -= 1
        p[i], p[j] = p[j], p[i]
        pos[p[i]] = i
        pos[p[j]] = j
    else:
        print(get_answer())
```このコードは、定数時間距離クエリのバイナリ リフティングに依存しています。 の`pos`array は主要な動的構造であり、各値を現在のノードにマッピングします。 の`check`関数は、すべてのプレフィックス ノードが単一のツリー パス上に存在する必要があるという幾何学的条件をエンコードし、LCA 距離を使用して検証します。 

二分探索では、スワップのたびに実現可能性が再計算されます。 これは高価に見えるかもしれませんが、各小切手は$O(k \log n)$最悪のケースではありますが、実際および意図されたソリューション構造では、プレフィックスはすぐに安定し、より最適化されたバージョンが候補プレフィックスをキャッシュして段階的に維持します。 

## 実用的な例

 ノードがチェーン状に配置され、値が最初はチェーンに沿って増加する小さなツリーを考えてみましょう。 すべてのノードが単一のパス上にあるため、プレフィックス条件は長距離にわたって保持されます。 スワップが発生すると、値がチェーンから外れて直径のエンドポイントが強制的にシフトされ、最終的にはプレフィックス条件が壊れる可能性があります。 

2 番目の例として、星形の木を想像してください。 最初は、センターと 1 つのリーフを含むプレフィックスのみが有効です。 値が交換されると、プレフィックスはすぐに無効になります。これは、2 つのリーフを含めるとパスが中心を通過する必要があり、偏差があると共線性が崩れるためです。 

これらのトレースは、アルゴリズムが基本的に、最小値がツリー内の線形構造を占めるかどうかを追跡していることを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての最小値が単一のルートからリーフへのパス上にある場合です。 この状況では、答えは大きなプレフィックスに成長し、そのパスから小さな値を移動するスワップは、実行可能なプレフィックスを即座に崩壊させます。 移動されたノードに対する LCA ベースのパス テストが失敗し、バイナリ チェックでプレフィックスが正しく縮小されるため、アルゴリズムがこれを処理します。 

もう 1 つのケースは、ツリーが高度に分岐していて値が大きい場合です。$0$そして$1$遠くのサブツリーから始めます。 サイズ 2 のプレフィックスはすでに失敗しており、スワップによって単一のパスに移行するまで拡張はできません。 距離条件は、LCA が深く、3 番目のノードがパスの一貫性に違反しているため、単一のパスに両方のエンドポイントを含めることができないことをすぐに検出します。 

最後のケースは、隣接する値の繰り返し交換です。 2 つの位置が変わるだけでも、プレフィックスの実現可能性は繰り返し反転する可能性があります。 このアルゴリズムは、以前のプレフィックスの有効性に関する構造的な仮定に依存するのではなく、不変の LCA 距離チェックを通じてメンバーシップを再計算するため、正しいままです。
