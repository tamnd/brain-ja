 ## 解決策
 ## 問題の理解

 2 つの垂直の壁があり、それぞれの長さの文字列で表されます。`n`。 位置`i`壁に置いたほうが安全です (`-`) またはブロックされた (`X`）。 忍者は位置から開始します`0`左側の壁の。 

毎秒、彼は次の 3 つの位置のいずれかに移動します。 

1. 同じ壁の上に 1 つのセルを上向きに配置します。 
2. 同じ壁の下向きに 1 つのセル。 
3. 反対側の壁、`k`セルが高くなります。 

立場を超えて移動する`n - 1`直ちに渓谷から脱出することを意味します。 

厄介なのは水位の上昇だ。 時間に`t`、インデックス付きのすべての位置`<= t - 1`すでに水没している。 を作った後、`t`- 番目の動き、水は再び上昇します。 ポジションはまだフラッディングされていない場合にのみ使用できます。 

課題は脱出が可能かどうかを判断することです。 

壁の高さは到達可能です`100000`これにより、指数関数的な検索が即座に除外されます。 二次アルゴリズムでも約`10^10`最悪の場合、限界をはるかに超えて動作する可能性があります。 線形時間に近いものが必要です。 

問題の最も微妙な部分は、動きと時間の相互作用です。 水は低い位置を取り除き続けるため、異なる時間に同じ位置に到達することは同等ではありません。 

考慮する：```
3 1
---
---
```正しい答えは、`YES`。 位置から`0`、その位置で他の壁にジャンプします`1`、そして再び壁を越えてジャンプします。 

ここでは、壁の障害物だけをチェックして時間を無視する不用意な実装は機能しますが、唯一の経路がすでに浸水している位置を訪問する必要がある場合には、同じ間違いが失敗します。 

もう 1 つの簡単な間違いは、すでに水中にある位置への移動を許可することです。```
4 2
----
----
```私たちがその位置にいると仮定します`2`時に`3`。 位置`1`はすでに浸水しているため、たとえ安全であるとマークされていても、そこに移動することは違法です。 

正しい状態は、単に「境界内にあり、ブロックされていない」というだけではありません。 宛先インデックスも厳密に現在時刻より大きくなければなりません。 

3つ目の罠はジャンプによる脱出です。```
5 3
-----
-----
```位置から`3`、ジャンプがその位置に着地する`6`、壁の外にあります。 忍者はすぐに逃げます。 一部の実装では、宛先インデックスが次の値を超える移動が誤って拒否されます。`n - 1`、有効なエスケープがありません。 

## アプローチ

 強引なアイデアは、考えられるあらゆる一連の動きをモデル化することです。 それぞれの州から登ったり、降りたり、飛び越えたりしてみます。 同じ位置は多くの異なるパスを通じて再訪できるため、移動シーケンスの数は時間の経過とともに指数関数的に増加します。 適度な高さの壁の場合でも、これは実行不可能になります。 

重要な観察は、ゲームが自然にグラフを形成するということです。 状態は、どの壁にいるか、どの位置を占めているかという 2 つの情報によって完全に決定されます。 すべての移動にはちょうど 1 秒かかるため、時間を個別に保存する必要はありません。 幅優先検索では、開始点からの距離が、ある状態に到達するまでの経過時間となります。 

州の到着時刻がわかれば、移動が合法かどうかを判断できます。 目的地の位置は安全で人が入っていない状態で、到着時にまだ水面より上にある必要があります。 

これにより、問題は最大でも最短パスの検索に変わります。`2n`州。 各状態には最大 3 つの出力エッジがあるため、グラフ全体を線形時間で探索​​できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適なBFS | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 本の壁掛けひもを保管します。 
2. 状態を次のように表現します。`(wall, position)`どこ`wall`は`0`左側の壁については、`1`右の壁用。 
3.BFSを開始します`(0, 0)`時に`0`。 
4. 状態が`(wall, pos)`がキューから削除され、その BFS 距離が現在時刻になります`t`。 
5. 3 つの可能な動きを生成します。 

-`(wall, pos + 1)`-`(wall, pos - 1)`-`(1 - wall, pos + k)`6. いずれかの宛先インデックスが少なくとも`n`、忍者はすぐに逃げて、私たちは印刷します`YES`。 
7. 壁の内側の目的地については、次のとおりです。 

- セルは安全でなければなりません (`'-'`）。 
- この州はこれまでに訪れたことがないものでなければなりません。 
- 宛先インデックスは厳密に次より大きくなければなりません`t + 1`。 

最後の条件は水をモデル化します。 次の動きをした後の時間は、`t + 1`。 最大でもインデックスを持つ任意の位置`t + 1`すでに浸水していて占拠できない。 
8. すべての有効な宛先が距離とともに BFS キューに追加されます`t + 1`。 
9. BFS がエスケープせずに終了した場合は、次のように出力します。`NO`。 

### なぜ効果があるのか

 BFS は、経過時間の増加順に状態を探索します。 ある州を初めて訪問したとき、その州への可能な限り最も早い到着時間が判明しました。 

水分制限は到着時間のみに依存します。 最も早い到着時間にその位置に到着すると安全でない場合、後で到着しても水位は上昇するだけなので役に立ちません。 この単調な性質のため、各州を 1 回訪問するだけで十分です。 

すべての正当な一連の動きは BFS によって探索されるパスに対応し、すべての BFS 遷移はゲーム内の正当な動きに対応します。 脱出は移動が壁から離れると正確に報告されるため、アルゴリズムは戻ります。`YES`有効なエスケープ パスが存在する場合に限ります。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    walls = [input().strip(), input().strip()]

    visited = [[False] * n for _ in range(2)]
    visited[0][0] = True

    q = deque()
    q.append((0, 0, 0))  # wall, position, time

    while q:
        wall, pos, t = q.popleft()

        moves = [
            (wall, pos + 1),
            (wall, pos - 1),
            (1 - wall, pos + k)
        ]

        for nw, np in moves:
            if np >= n:
                print("YES")
                return

            if np < 0:
                continue

            if np <= t + 1:
                continue

            if walls[nw][np] == 'X':
                continue

            if visited[nw][np]:
                continue

            visited[nw][np] = True
            q.append((nw, np, t + 1))

    print("NO")

solve()
```キューには、現在の壁、位置、経過時間が保存されます。 BFS は、状態が時間の増加順に処理されることを保証します。 

条件`np <= t + 1`は、ソリューションの中で最も重要な行です。 1秒後に届く手を考えています。 その時点で、インデックスを持つポジションは最大でも`t + 1`はすでに水面下に消えており、そのような動きは違法です。 

壁から離れるとすぐにゲームに勝利するため、障害物を検証する前に脱出がチェックされます。 頂点を超えて着地したジャンプは、そこに何が存在していたかに関係なく成功します。 

訪問済み配列により、状態を再訪問することができなくなります。 BFS は可能な限り早い時間にすべての州に到達するため、遅れて到着しても利点は得られません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | それぞれの`2n`州は最大 1 回訪問されます。 
| スペース | O(n) | 最大でキューおよびアクセスされたアレイ ストア`2n`状態 |

 ## 特殊なケース

 可能な限り小さな峡谷を考えてみましょう。```
1 1
-
-
```BFS は次から始まります`(0,0)`。 ジャンプ移動のターゲット位置`1`、壁の外にあります。 アルゴリズムチェック`np >= n`最初にすぐに戻ります`YES`。 This handles instant escapes correctly.

 下に移動すると浸水領域に入ることになる場合を考えてみましょう。```
4 2
----
----
```BFS が位置に到達すると仮定します`3`時に`2`。 下に移動するとターゲット位置になります`2`。 到着時間は`3`、および条件`np <= t + 1`になる`2 <= 3`, そのため、移動は拒否されます。 このアルゴリズムでは、水没したセルの上に立つことは決して許可されません。 

峡谷から出るジャンプを考えてみましょう。```
5 3
-----
-----
```位置の状態`3`位置へのジャンプを生成します`6`。 以来`6 >= 5`、逃走はすぐに検出されます。 壁の検索は試行されないため、範囲外のエラーが回避され、ゲーム ルールが正しくモデル化されます。 

最後に、後で状態を再訪することを検討してください。```
6 2
------
------
```特定の位置には、複数のルートを通じて到達できる場合があります。 BFS は可能な限り早い時間にアクセスし、アクセスしたことをマークします。 遅れて到着した場合でも、同じかそれ以上の水位に直面することになり、新たな機会は決して生まれません。 訪問された配列は、正確さを維持しながら、冗長な探索を安全に削除します。
