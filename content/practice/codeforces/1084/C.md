 ## 問題の理解

 小文字で構成される文字列が与えられており、次の 2 つの文字の位置のみに関心があります。`'a'`そして`'b'`。 この文字列から、選択した各インデックスが`'a'`。 

順序は任意ではありません。 複数選択する場合`'a'`、その後、選択された 2 つの連続する位置ごとに、少なくとも 1 つの位置が存在する必要があります。`'b'`厳密にこれらのインデックスの間のどこかにあります。 言い換えれば、次のサブシーケンスを選択しています。`'a'`ただし、サブシーケンスを別の位置を超えて拡張することのみが許可されています`'a'`それらの間のセグメントに少なくとも 1 つが含まれている場合`'b'`。 

出力は、単一要素のサブシーケンスを含むすべての可能な長さにわたってカウントされた、そのような有効なサブシーケンスの数です。 

文字列の長さは最大 100000 です。これにより、文字列のサブシーケンスを列挙しようとするソリューションは即座に除外されます。`'a'`ポジション。 それだけに限定しても`'a'`文字数は最大 100,000 文字まで存在する可能性があり、そのサブセットのサイズはすでに指数関数的になります。 位置の組み合わせを明示的に試したり、サブシーケンスを再帰的に構築したりするアプローチは、時間内に完了しません。 

2 番目の微妙な点は、この状態は個人に局所的なものではないということです。`'a'`文字。 2つかどうか`'a'`有効なシーケンス内で位置が隣接できるかどうかは、それらの間に何があるかによって異なります。 つまり、それぞれを治療することはできません`'a'`独立して使用することも、それらの間の構造を追跡せずに、それらの位置に対する単純な組み合わせカウントを使用することもできます。 

この依存関係を明らかにするエッジ ケースの 1 つは、次のような文字列です。`"aaaa"`。 ここでは、連続するペアはありません`'a'`がないため、ポジションは延長に有効です。`'b'`どこでも。 したがって、答えは単純にシングルの数です。`'a'`位置、つまり 4。`'a'`有効である場合、誤って 15 が返されます。 

もう一つのエッジケースは、`"ababa"`。 これで、連続した間のすべてのギャップが`'a'`には、が含まれています`'b'`、つまり、次のすべての部分列は`'a'`ポジションが有効になり、$2^3 - 1 = 7$。 正しい解決策は、純粋に、`'b'`関連する間隔で出現しました。 

## アプローチ

 ブルートフォースソリューションでは、以下を含む位置のサブシーケンスをすべて列挙しようとします。`'a'`、各候補シーケンスについて、すべての隣接するペアが「中間条件」を満たすかどうかを確認します。`'b'`「存在する」という制約があります。たとえ次を事前計算したとしても`'b'`位置、すべてのサブセットを生成`'a'`は依然として指数関数的です。 最大 100,000 文字の場合、`'a'`一人で到達できる$2^{100000}$、それは不可能です。 

重要な洞察は、位置の観点から考えることを避け、代わりに、位置によって引き起こされる構造の観点から考えることです。`'b'`。 の存在`'b'`二人の間`'a'`s は、シーケンスを「継続」できるか、それとも新しい独立した選択を開始する必要があるかを決定します。 

有効なサブシーケンスの動的カウントを維持しながら、文字列を左から右に処理できます。 私たちが見るとき、`'a'`、次の 2 つの可能性があります。これで新しいサブシーケンスを開始するか、`'a'`、または、以前に有効だったサブシーケンスにそれを追加しますが、それは現在許可されている場合に限ります。`'b'`最後のグループ化境界以降。 の効果`'b'`未来にわたる継続を「ロック解除」することです`'a'`s.

 これは、単純なステートマシンの解釈につながります。 私たちは価値を維持します`dp`現在の位置で終了する有効なサブシーケンスの数と、からのフラグのような寄与を表します。`'b'`これにより、以前に開始されたサブシーケンスが新しいときに拡張できるようになります。`'a'`が表示されます。

 ## アルゴリズムのチュートリアル

 文字列を左から右に処理し、2 つの量を維持します。 1 つは現在拡張できる有効なサブシーケンスの数を追跡し、もう 1 つは最終的な答えを蓄積します。 

1.初期化`dp = 0`そして`ans = 0`。 ここ`dp`有効な場合に拡張できるサブシーケンスの数を表します。`'a'`、 その間`ans`合計数を保存します。 
2. 文字列内の各文字をスキャンします。 
3. キャラクターが`'b'`、更新します`dp = dp + 1`。 このステップは、`'b'`将来の可能性を開く`'a'`■ 既存のサブシーケンスを拡張します。 その理由は、どんな未来でも`'a'`現在、この地域を合法的に橋渡しできるようになりました。 
4. キャラクターが`'a'`、更新します`dp = dp * 2 + 1`。 2 の乗算は、以前にアクティブだったすべてのサブシーケンスがこれを含むか除外できることを表します。`'a'`、そして`+1`これのみからなる新しいサブシーケンスを開始することに対応します`'a'`。 
5.各加工後`'a'`、追加します`dp`の中へ`ans`。 これは、この位置で終了するか、この位置を有効な最後の位置として含むすべてのサブシーケンスを累積します。`'a'`。 

核となる考え方は、`'b'`将来的に利用可能な「組み合わせの自由」が増加します`'a'`配置、その間`'a'`既存の構造を 2 倍にし、新しいシングルトンの選択肢を追加します。 

### なぜ効果があるのか

 どの時点でも、すべての有効なサブシーケンスは最後に選択されたものによってのみ決定されます。`'a'`。 唯一の制約は、少なくとも 1 つ存在するかどうかです。`'b'`連続して選択されたものの間`'a'`s. それぞれ`'b'`将来を可能にするセパレータとして効果的に機能します。`'a'`s 以前に形成されたすべてのサブシーケンスと再接続します。 繰り返しは、それぞれの新しいものが何通りあるかを正確にエンコードします。`'a'`以前の有効な構成にアタッチして、二重にカウントすることなくすべての有効な継続を保持できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    s = input().strip()
    
    dp = 0
    ans = 0
    
    for ch in s:
        if ch == 'b':
            dp = (dp + 1) % MOD
        elif ch == 'a':
            dp = (2 * dp + 1) % MOD
            ans = (ans + dp) % MOD
    
    print(ans)

if __name__ == "__main__":
    solve()
```実装は実行中の動的値を維持します`dp`これは、現在、拡張可能なサブシーケンスの数を要約したものです。`'a'`。 それぞれ`'b'`構造の柔軟性が 1 ユニットずつ増加します。`'a'`既存のすべての可能性を 2 倍にし、それだけで構成される新しいサブシーケンスを追加します`'a'`。 

答えは処理時にのみ蓄積されます`'a'`これらの位置のみが有効なシーケンスのエンドポイントとして機能できるためです。 

モジュロ演算は、オーバーフローを回避し、問題の要件に一致させるために、すべてのステップで適用されます。
