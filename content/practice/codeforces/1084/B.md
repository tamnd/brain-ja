 ## 解決策
 ## 問題の理解

 私たちはクワスの樽をいくつか与えられ、それぞれに初期量が入っています。 1 回の操作で、任意の 1 つの樽をちょうど 1 リットル減らすことができ、そのような操作ごとに、「注ぎ出す」合計量に 1 リットルが寄与します。 目標は正確に削除することです$s$すべての樽の合計でリットル。 そうした後は、残りのクワス レベルが重要になります。すべての樽の最小値を最大化することに注意します。 

したがって、タスクは単に削除できるかどうかを確認するだけではありません。$s$リットルですが、単一の樽が小さくなりすぎないように、それらの除去を分配することについてです。 

重要な制約は、$n \le 10^3$そして$s \le 10^{12}$。 小さいもの$n$二次関数または$n \log n$行動、しかし巨大な$s$一度に 1 リットルずつ減らそうとするシミュレーションは直ちに除外されます。 どのようなソリューションも、段階的な操作ではなく、総合的に推論する必要があります。 

合計 kvass が 未満の場合、微妙なエッジ ケースが発生します。$s$。 その場合、たとえすべての樽を空にしたとしても、除去の配分は目標に到達できません。 もう 1 つの注意が必要な状況は、ローカルで最大の樽を貪欲に減らすことが正しいように見えても、実際には必要以上に最小値を下げる方法で削除の割り当てを誤っている場合です。 

## アプローチ

 強引なアイデアは、リットルを 1 つずつ削除することをシミュレートすることです。 各ステップで、現在の最大値を持つ樽を選択し、それを 1 つ減らします。 小さな樽に触れることを避けるため、これにより、ローカルでの最小値が可能な限り大きく保たれます。 後$s$このような操作では、最小値を計算します。 

各操作では次のステップのために可能な限り最良の状態が保存されるため、これは正しく機能します。 ただし、複雑さは、$O(s \log n)$ヒープを維持すると、$s$まで可能です$10^{12}$、そのため、このアプローチは完全に実行不可能になります。 

重要な観察は、最終的な答えは閾値の問題であるということです。 操作をシミュレートする代わりに、候補となる最小値を仮定します。$x$。 すべての樽を少なくとも$x$、その後、上記の超過分$x$自由に取り外し可能です。 固定資産の総除去可能量$x$になる$$\sum \max(0, v_i - x).$$この合計が少なくとも$s$であれば、少なくとも最小値を達成することが可能です$x$。 そうでなければ不可能です。 

これにより、問題は最大の値を見つけることに変わります。$x$という条件が成り立つように。 実現可能性は単調なので、$x$、答えを二分探索できます。

 | --- | --- | --- | --- |
 | 貪欲なシミュレーション |$O(s \log n)$|$O(n)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. すべての樽の合計を計算します。 未満の場合$s$、すぐに -1 を返します。 削除するのに十分なクワスがありません$s$戦略に関係なくリットル。 
2. 答えの二分探索範囲を設定します。 可能な最終値の最小値は 0 で、最大値は次のとおりです。$\max(v_i)$, どの樽も初期値を超えることができないためです。 
3. 候補値について$x$、すべての樽が少なくとも次の量まで減った場合にどれだけのクワスを除去できるかを計算します。$x$。 樽ごとに、$v_i > x$、削除できます$v_i - x$、それ以外の場合はゼロ。 
4. 取り外し可能なクワスの合計が少なくとも$s$、 それから$x$実現可能です。 これは、すべての樽が少なくとも$x$, そこで増加してみます$x$。 
5. 取り外し可能なクワスの合計が以下の場合$s$、 それから$x$大きすぎます。 十分なクワスを除去しながら、その高い最小値を維持することはできないため、減少させます。$x$。 
6. 二分探索を実行して、実現可能な最大値を見つけます。$x$。 それを答えとして返します。 

### なぜ効果があるのか

 重要な特性は単調性です。 値の場合$x$最小値を下げても、利用可能な取り外し可能な kvass が増加するだけであるため、さらに小さな値も実行可能です。 これにより、単調な述語が作成されます。$x$、二分探索で最適なしきい値が見つかることが保証されます。 有効な最終構成は、各樽の削減量に関する何らかの選択に対応し、しきい値制約によって完全に特徴付けられるため、実現可能性チェックでは、除去を分散する有効なすべての方法が正確に把握されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(v, s, x):
    total = 0
    for a in v:
        if a > x:
            total += a - x
    return total >= s

n, s = map(int, input().split())
v = list(map(int, input().split()))

if sum(v) < s:
    print(-1)
    sys.exit()

lo, hi = 0, max(v)
ans = 0

while lo <= hi:
    mid = (lo + hi) // 2
    if can(v, s, mid):
        ans = mid
        lo = mid + 1
    else:
        hi = mid - 1

print(ans)
```利用可能な kvass を超える取り決めは存在できないため、コードは合計額の実現可能性チェックから始まります。 ヘルパー関数`can`すべての樽に蓋をした場合に除去できる合計量を計算します。`x`。 次に、二分探索により候補最小値が実行可能な場合は上方に調整され、そうでない場合は下方に調整され、最終的に最大有効最小値に収束します。 

ここでよくある間違いは、しきい値を固定すると、異なる樽からの取り出しが独立していることを忘れることです。 もう 1 つは、問題を単調な決定関数に変換するのではなく、貪欲にシミュレーションしようとすることです。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    n, s = map(int, input().split())
    v = list(map(int, input().split()))

    if sum(v) < s:
        return "-1"

    def can(x):
        total = 0
        for a in v:
            if a > x:
                total += a - x
        return total >= s

    lo, hi = 0, max(v)
    ans = 0

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    return str(ans)

def run(inp: str) -> str:
    return solve(inp)

# provided sample
assert run("3 3\n4 3 5\n") == "3"

# minimum case
assert run("1 1\n5\n") == "4"

# impossible case
assert run("2 10\n1 2\n") == "-1"

# all equal
assert run("4 4\n5 5 5 5\n") == "4"

# large skew
assert run("3 5\n10 1 1\n") == "3"

 ## 特殊なケース

 合計クワスが以下の場合$s$の場合、アルゴリズムはすぐに -1 を返します。 たとえば、入力`2 10`樽付き`[1, 2]`合計 3 が生成されますが、これでは不十分です。 早期チェックにより、バイナリ検索で意味のない値が生成されるのを防ぎます。 

すべての樽が等しい場合、次のように言います。`[5, 5, 5]`と$s = 2$、実現可能性チェックでは、すべての樽で合計 2 つの除去しか利用できないため、3 を超える最小値は不可能であることがわかります。 二分探索は 3 で正しく安定します。 

ある樽が他の樽よりも著しく大きい場合。`[10, 1, 1]`、除去物は大きな樽に集中します。 しきい値の定式化は、超過分のみをカウントするため、引き続き機能します。$x$、削除がどこから来たかは関係ありません。
