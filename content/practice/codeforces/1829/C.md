 ## 解決策
 ## 問題の理解

 Victor には習得したい 2 つの独立したスキルがあり、彼が読むことができるそれぞれの本は、スキル 1、スキル 2、またはその両方を教えているか、まったく教えていないかのいずれかです。 どの本にも時間コストがかかります。 課題は、総合的な読書時間を最小限に抑えながら、必要なスキルの両方をカバーできる組み合わせの書籍セットを選択することです。 

各ブックは本質的に小さな「バンドル」です。2 ビットにわたるビットマスクを提供し、コストがかかります。 私たちは書籍のどのサブセットを選ぶこともできますが、順序や繰り返しではなく、獲得したスキルの結合のみを考慮します。 目標はフルマスクに到達することです`11`最小限の総コストで。 

入力サイズはテスト ケース全体で大きく、書籍の総数は最大 200,000 冊に達します。 これにより、すべてのテスト ケースのすべてのサブセット、さらにはペアごとの組み合わせを個別に試行するソリューションは即座に除外されます。 二次関数や指数関数的なアプローチは生き残れません。 

微妙な点は、重複するスキルを教える複数の本を読むことは許可されていますが、スキルとコストの両方で 1 つの本が別の本を厳密に上回る場合は、決して有益ではないということです。 もう 1 つのエッジケースは、個々のスキルが個別に存在するにもかかわらず、両方のスキルを組み合わせてもカバーできない場合です。 

たとえば、本があるとします。```
3 10
4 01
```答えは`7`ただし、両方の本が提供するだけの場合は、`00`、答えは`-1`本は存在するのに。 

もう 1 つの落とし穴は、1 冊の本で十分だと思い込むことです。 正しいソリューションでは、1 つのブックに既に`11`。 

## アプローチ

 直接的な総当たりアプローチでは、書籍のすべてのサブセットを試し、各サブセットのスキルの結合を計算します。 各サブセット チェックは O(n) であり、2^n 個のサブセットが存在します。これは、2e5 はおろか、n = 30 の場合でも不可能です。 

可能なスキル状態が 4 つだけであることに注目することで、構造を簡略化できます。`00`、`01`、`10`、 そして`11`。 これにより、問題は、結合して形成される最大 2 冊の本を選択することになります。`11`、またはおそらくすでに同等の単一の本`11`。 

重要な観察は、必要なのは次のものだけであるということです。 

- 提供する最も安い本`10`- 提供する最も安い本`01`- 提供する最も安い本`11`最適なソリューションは 2 つのカテゴリのいずれかに分類される必要があります。 どちらかを選択しましょう`11`本を買うか、持って行きます`10`本と一冊`01`本。 追加の書籍を追加しても、範囲を超えて改善することなくコストが増加するだけであるため、これを改善する他の組み合わせはありません。`11`。 

したがって、問題は、入力を 1 回スキャンする間に 3 つの最小値を維持することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | O(2^n) | O(n) | 遅すぎる |
 | 最適な候補者を追跡する | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、すべての書籍をいくつかの代表的な候補に絞り込みます。 

1. 3 つの変数を初期化します。`best_01`、`best_10`、 そして`best_11`無限のように。 これらは、各スキル パターンを提供する書籍の最小コストを追跡します。 ここでは、各タイプの最も安価な代表値のみを考慮します。 
2. すべてのブックを反復処理します。 各書籍について、そのバイナリ文字列を検査し、4 つのタイプのいずれかに分類します。 
3. 本が与えてくれたら`11`、 アップデート`best_11`最小限のコストで。 この問題は 1 冊の本ですでに解決できるため、これは重要です。 
4. 本が与えてくれたら`01`、 アップデート`best_01`。 
5. 本が与えてくれたら`10`、 アップデート`best_10`。 
6. 無視する`00`なぜなら、本は最終的なスキルセットには決して寄与しないからです。 
7. すべての書籍を処理した後、次の最小値として最良の答えを計算します。 

の費用`best_11`、および合計`best_01 + best_10`。 
8. 両方の場合`best_11`は無限か、どちらかです`best_01`または`best_10`が無限である場合、形成することは不可能です`11`ので、出力します`-1`。 

### なぜ効果があるのか

 状態空間は 2 ビットによって完全にキャプチャされます。 3 冊以上の本を使用するソリューションはすべて、次のように圧縮できます。`10`本は安いものだけが重要です。 同様に`01`。 複数のタイプを混合した場合でも、最終的な組み合わせは単一のいずれかになります。`11`または1つ`10`プラスワン`01`。 したがって、タイプごとの最小コストのみを追跡すると、すべての最適な構造が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

t = int(input())
for _ in range(t):
    n = int(input())

    best_01 = INF
    best_10 = INF
    best_11 = INF

    for _ in range(n):
        parts = input().split()
        cost = int(parts[0])
        s = parts[1]

        if s == "11":
            best_11 = min(best_11, cost)
        elif s == "10":
            best_10 = min(best_10, cost)
        elif s == "01":
            best_01 = min(best_01, cost)

    ans = min(best_11, best_01 + best_10)

    if ans >= INF:
        print(-1)
    else:
        print(ans)
```このコードは、3 つの候補の削減を直接実装したものです。 各書籍は一定の時間で分類されます。 最終的な決定では、2 つの構造的可能性のみが比較されます。 

よくある実装上の間違いは、候補を大きな値に初期化するのを忘れることです。これにより、欠落しているカテゴリの寄与が誤ってゼロになる可能性があります。 もう一人は治療中です`"00"`これは不必要であり、扱いを誤ると誤った最小値が発生する可能性があります。

 ## 特殊なケース

 すべての本が終わったら、`00`、アルゴリズムはすべての候補を無限大に保ち、正しく出力します。`-1`状態を改善する組み合わせはないからです。 

どちらか一方だけのときは、`01`または`10`存在する場合、1 つの項は無限大のままであるため、合計は不可能になり、偽の有効な答えが防止されます。 

複数の最適な候補が存在する場合、アルゴリズムは継続的にコストを最小に保ちます。`min`更新により、大量の重複や並べ替えが行われた場合でも正確性が保証されます。
