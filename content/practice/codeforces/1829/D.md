 ## 問題の理解

 を含む単一の山から始めます。`n`金塊。 唯一許可されている移動は、既存の 1 つの杭を取得し、それを厳密な構造を持つ 2 つの小さな杭に分割します。新しい杭の 1 つは、もう 1 つの杭のちょうど 2 倍のサイズでなければなりません。 小さい部分の場合は、`x`、分割により山が生成されます`x`そして`2x`、したがって、元のパイルにはサイズがある必要があります`3x`。 

これは、すべての操作がサイズの山を置き換えることを意味します`3x`2 つの杭のサイズを合計するとそれに相当しますが、比率は非常に制限されています。 問題は、中間パイルに対してそのような分割を何度も実行した後、正確なサイズのパイルを取得できるかどうかです。`m`。 

この制約により、最大 1,000 個のテスト ケース、最大 1,000 万個のパイル サイズが許可されます。 可能なすべての分割を杭の状態空間としてシミュレートしようとするソリューションは、すぐに爆発します。これは、分割ごとに杭の数が増加し、次にどの杭を分割するかの選択全体にわたって分岐係数が事実上制限されないためです。 ステートに対する単純な BFS では、膨大な数の同等の構成を再検討することになります。 

重要なエッジケースは、数値的なものではなく構造的なものです。 もし`m > n`、大きな杭を小さなコンポーネントと大きなコンポーネントに分割することで、より大きな杭を間接的に「構築」できる状況がまだありますが、それは、繰り返し 3 で分割することで構造が一致する場合に限られます。もう 1 つの微妙なケースは次のような場合です。`m = n`これは、操作を行わずに常に簡単に実行できます。 最後に、いつ`n < 3`、分割はまったく不可能であるため、平等のみが機能します。 

不注意で貪欲なアプローチは、分割しているので値は常に減少し、したがって、`m ≤ n`重要です。 それは次のようなケースを見逃します`9 → 6 + 3`、ここでは小さな山`3`たとえ存在しても`m = 4`よりも小さいです`n`。 

## アプローチ

 ブルートフォース解釈では、杭の各構成を状態として扱います。 任意の状態から、3 で割り切れる山を選択し、それを次のように置き換えます。`(x, 2x)`。 サイズの山が見つかるまで続けます`m`あるいは可能性を枯渇させる。 

これは、有効な変換をすべて調査するため、概念的に機能します。 問題は、州の数が非常に急速に増加していることです。 分割するたびに山の数が 1 つずつ増加し、3 で割り切れる場合は各山を独立して分割できるため、状態空間は組み合わせ的に増加します。 中程度の場合でも`n`、到達可能なマルチセットの数は膨大になります。 

構造的な洞察は、視点を逆転させることです。 すべての山を拡張するのではなく、山のサイズに何が必要かを尋ねます。`n`最終的には大きなサイズの山を生成する`m`。 すべての有効な分割は厳密な不変条件を保持します。すべての演算で置き換えられるため、到達可能なすべてのパイル サイズは 3 のべき乗で繰り返し乗算または除算することによって形成されます。`3x`と`x`そして`2x`。 これは、到達可能なすべての数値が最終的に繰り返し分解に対応することを意味します。`n`3 のような成分の累乗の和に変換します。 もっと明確な観察は、このプロセスは制御された方法で因子 2 と因子 3 を繰り返し分割することに相当し、到達可能性は分解できるかどうかにのみ依存するということです。`n`再配置できるチャンクに分割`m`3 による除算を繰り返し使用します。 

それを確認するためのより直接的かつ標準的な方法は、から逆算して作業することです。`m`。 もし`m`から到達可能です`n`そうすると、操作を逆にすることを想像できます: マージ`x`そして`2x`に戻る`3x`。 そこで私たちは繰り返し表現しようとします`m`2の累乗×3の累乗の和として 内部に収まる構造`n`。 これは、分解できるかどうかを確認することになります。`n`大きさに分けて`m`可能な場合は、2 と 3 で割ることを繰り返します。 実際には、これは貪欲な削減になります。つまり、繰り返し変換します。`n`2 または 3 で割り切れる一方で、`m`到達可能な分解に表示されます。

 ## アルゴリズムのチュートリアル

 私たちは問題を繰り返し単純化するものとして扱います`n`有効な逆推論によって生成できるすべてのサイズに変換し、`m`その構造に適合します。 

1. もし`m > n`、マージは杭の数を減らすだけで、開始杭よりも大きな総質量を作成することはないため、すぐに拒否します。 これは厳密な不変条件です。合計のゴールドは常に保存されるため、これより大きな山は存在しません。`n`いつでも現れることができます。 
2. もし`n == m`, 操作は不要ですので、すぐに受け付けます。 
3. その間`n`これは、分割および結合操作により、到達可能なパイル サイズの構造内で 2 の因数を分離できるという事実を反映しています。 
4. ながら`n`は 3 で割り切れます。推論を少し調整して 3 で割ります。マージを繰り返す逆構造をシミュレートします。`(x, 2x)`の中へ`3x`したがって、3 の因数を削除すると、分解が正規化されます。 
5. 完全に低減した後`n`、どうかを確認してください`m`同じ縮小構造を使用して表現できます。 具体的には削減します`m`同じプロセスを使用して正規形式を比較します。 両方が同じコア値に減少する場合、変換は可能です。 

重要な考え方は、到達可能なすべての数値が`n`操作が許可する唯一の方法で係数 2 と 3 を取り除くことによって得られる正規の「縮小バックボーン」を共有します。 

### なぜ効果があるのか

 すべての操作で合計が保持され、あらゆる変換を反転して次のマージにできることが強制されます。`(x, 2x)`の中へ`3x`。 これは、プロセスがまさにこれらの分解を生成することを意味します。`n`各成分は最終的に 2 と 3 で除算して共有既約形式に還元されます。このアルゴリズムは、両方を圧縮することでこれを利用します。`n`そして`m`それらの還元不可能な表現を作成し、それらを比較します。 表現が一致する場合、一連の有効な分割とマージを通じて一方をもう一方に変換できます。 そうしないと、許可された操作の構造により位置合わせができなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def reduce(x):
    # remove factors of 2
    while x % 2 == 0:
        x //= 2
    # remove factors of 3
    while x % 3 == 0:
        x //= 3
    return x

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())

    if m > n:
        print("NO")
        continue

    if n == m:
        print("YES")
        continue

    if reduce(n) == reduce(m):
        print("YES")
    else:
        print("NO")
```この実装では、すべての因数 2 と 3 を取り除くことによって、両方の数値を標準形式に還元します。直観的には、許可される操作は、既約バックボーンを変更せずに、因数 2 と 3 の間で質量を再配置するだけであると考えられます。 両方の番号がこのバックボーンを共有すると、一連の分割とマージをシミュレートして位置を揃えることができます。 

早めのチェックは、`m > n`そして`n == m`不必要な削減作業を防止し、明らかなケースに直接対処します。 

## 実用的な例

 ### 例 1:`n = 9, m = 4`正規のリダクションを計算します。 

| ステップ | n | アクション | 結果 |

 | 1 | 9 | 2 ずつ減らす | 9 |

これは、たとえ`9`次のような中間値を生成できます`6`そして`3`、サイズの山に再構築することはできません`4`, 既約分解が異なるためです。

 | --- | --- | --- |

 正規形はまた異なるため、答えは「NO」です。 

これは、分割された大きな柔軟なツリーであっても、構造ベースの不一致を克服できないことを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def reduce(x):
        while x % 2 == 0:
            x //= 2
        while x % 3 == 0:
            x //= 3
        return x

    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        if m > n:
            out.append("NO")
        elif n == m:
            out.append("YES")
        else:
            out.append("YES" if reduce(n) == reduce(m) else "NO")
    return "\n".join(out) + ("\n" if out else "")

 ## 特殊なケース

 いつ`n = m`の場合、アルゴリズムは削減の前にすぐに YES を返します。 これにより、ストリッピング要因により削減が発散するケースを誤って拒否することが回避されます。 

いつ`m > n`、アルゴリズムは早期に拒否し、異なる大きさを同じバックボーンに折りたたむリダクションによって引き起こされる誤解を招く正準等価性を防ぎます。 

次のような小さな数値の場合`n = 3`、繰り返しの還元収量`1`、同じ基底に還元可能なターゲットのみが成功します。 これにより、分割が不可能なケースが正しく処理され、構造が到達可能性を誤って拡張しないことが保証されます。
