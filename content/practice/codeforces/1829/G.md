 ## 解決策
 ## 問題の理解

 この問題の構造は、番号が付けられた缶の固定ピラミッドであり、ピラミッド内の各位置に平方数が含まれています。 三角形のスタック内の位置によって缶にインデックスを付けることを想像すると、各缶に書かれた値はその位置インデックスではなく、整数ラベルの 2 乗になります。 重要な仕組みは、缶が当たったときに何が起こるかということです。積み重ね関係でその「上」にあるすべてのものも同様に落下し、ピラミッドを通って上に向かうチェーンを形成します。 

タスクは、ラベルの付いた缶を叩いたときに発生するすべての缶の値の合計を計算することです。$n^2$。 落下は決定論的な構造を通じて上方に伝播するため、結果は純粋に次の関数になります。$n$動的シミュレーションではありません。 

クエリの数と規模の点で制約が大きくなります。$n$まで可能です。$10^6$。 缶の落下をシミュレートしたり、明示的にピラミッドを構築したりするソリューションは、時間とメモリの両方で非常に遅すぎます。 構造のテストケースごとの走査でも、$n$届くだろう$10^9$最悪の場合の運用。 

正しいアプローチでは、各クエリを定数時間または対数時間に短縮する必要があります。 これは、落下領域が閉じた構造を持っているか、または既知の算術パターンに対応していることを強く示唆しています。 

エッジケースは次の場合に発生します。$n$小さいです、例えば$n=1$、缶が1つだけ落ちている場所。 単純な解釈では、誤って上方にトラバースしようとして、存在しない要素が含まれたり、重複が過剰にカウントされたりする可能性があります。 もう 1 つの微妙な問題は、下降領域が「以下のすべての数値」ではないことです。$n$」ですが、三角形の階層化に依存するスパースなサブセットです。これが欠けていると、たとえトラバーサル ロジックが一貫しているように見えても、不正確な合計が発生します。 

## アプローチ

 ブルートフォース解釈は、ピラミッドを明示的にシミュレートすることから始まります。 ピラミッドの列を構築し、開始位置から BFS または DFS を実行することを想像することもできます。$n^2$、「真上」の関係に続きます。 訪問した各ノードは、その二乗値を答えに寄与します。 

これは、下降伝播を正確にモデル化しているため、原理的には正しいです。 ただし、ピラミッドの高さは最大です。$2023$、複数のテスト ケースにわたる場合、クエリごとの完全なシミュレーションは不要であり、依然としてコストがかかります。 さらに悪いことに、制約によって暗示されるより大きな隠れた構造に一般化すると、上向きのトラバースが発生する可能性があります。$O(n)$クエリごとに、次のようになります$10^6$テストケースごとに最大$10^9$トータルオペレーション。 

重要な観察は、落下する構造が任意に分岐しないことです。 各缶には上向きに一意に決定された「親」のチェーンがあり、これらのチェーンは整数の三角形座標への特定の分解に対応します。 親関係を注意深く追跡すると、訪問インデックスのセットは、増加するオフセットを繰り返し減算することによって生成された整数のセットであることがわかります。これは、バイナリ表現がピラミッドの特定の構造レベルに対応するインデックスを選択することと同じです。 

これにより、問題が純粋な算術計算に変換されます。グラフ内の動きをシミュレートする代わりに、どのインデックスが合計に寄与するかを決定し、貪欲な分解を使用してそれらの 2 乗値を直接累積します。

 ## アルゴリズムのチュートリアル

 缶の落下構造は、整数の層を繰り返し剥離していると解釈できます。$n$ここで、各層はピラミッド インデックス システムの三角形の境界に対応します。 

1. 与えられたものから始める$n$、最も下にある影響を受ける缶のラベルを表します。$n^2$。 上方向にどれだけ伝播したかを追跡する実行ポインタを維持します。 
2. 各ステップで、構造が次の構造境界にジャンプする前に、現在の「層」内の連続する整数がいくつ寄与するかを決定します。 ピラミッドの各行に含まれる要素の数が増加するため、これは三角形の成長によって支配されます。 
3. から実現可能な最大レイヤー サイズを減算します。$n$、そのレイヤー内のすべての整数を寄与値として記録します。 それぞれがその二乗を答えに貢献します。 
4. 値がなくなるまで、残りの縮小インデックスに対してプロセスを繰り返します。 これにより、構造的な祖先をスキップしたり二重にカウントしたりすることなく、正確な上向きのチェーンをたどることができます。 
5. 分解中に、選択したすべての整数の二乗和を累積します。 

重要な考え方は、分解の各整数が祖先のチェーン内の 1 つの缶に正確に対応し、分解によって選択の一意性が保証されるということです。 

### なぜ効果があるのか

 任意の缶からの上向きの伝播は、有効なラベルの厳密に減少するシーケンスを形成し、各ステップはピラミッドの形状に基づいて一意に決定された親に移動します。 この一意性により、すべての有効なフォールト缶が分解の 1 つのステップに正確に対応し、重複するインデックスが 2 つのステップで生成されることがないことが保証されます。 このアルゴリズムは、祖先チェーンを明示的に走査することなく効果的に再構築し、寄与の完全性と素性の両方を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Precompute prefix sums of squares up to 1e6
MAXN = 10**6
pref = [0] * (MAXN + 1)
for i in range(1, MAXN + 1):
    pref[i] = pref[i - 1] + i * i

def solve_one(n):
    # greedy decomposition based on triangular layer structure
    res = 0
    cur = n
    step = 1

    while cur > 0:
        take = min(cur, step)
        # sum of squares in this segment
        res += pref[step] - pref[step - take]
        cur -= take
        step += 1

    return res

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str(solve_one(n)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```このソリューションは、セグメント クエリに定数時間で応答するために、正方形のプレフィックス合計配列に依存しています。 メイン ループは階層化された分解を実行します。反復ごとに消費される要素の数が増加します。これは、ピラミッド行の幅の拡大を反映しています。 プレフィックス配列により、平方和を繰り返し再計算することが回避されます。 

微妙なディテールは、`step`現在のレイヤーのサイズとして。 それは決定論的に増加し、各層がピラミッド内の固有の構造レベルに対応することが保証されます。 オフバイワンの間違いは通常、プレフィックス合計のインデックス作成時に発生します。 正しい引き算は`pref[r] - pref[l-1]`、ここでは次のように実装されています`pref[step] - pref[step - take]`。

 ## 特殊なケース

 のために$n=1$、アルゴリズムが初期化されます`cur = 1`で要素を 1 つだけ取ります`step = 1`。 接頭辞の減算が返されます。$1^2$、ループはすぐに終了します。 これにより、ベース レイヤが無効な状態にならずに正しく処理されることが確認されます。 

非常に大きい場合$n$、 のような$10^6$、ループは段階的に拡大しますが、各反復で消費される要素の数が増加するため、反復数は少ないままです。 プレフィックス合計により、大きなセグメントであっても一定時間内に集約されることが保証され、パフォーマンスの問題が防止されます。 

小さな中間値の場合、`cur < step`、`take = min(cur, step)`このロジックにより、残りの有効な要素のみが消費されるようになり、利用可能な構造のオーバーシュートが回避されます。
