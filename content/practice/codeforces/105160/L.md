 ## 解決策
 ## 問題の理解

 次のサイズの長方形グリッドが与えられます。$n \times m$そのセルには次の整数が入力されます。$1$に$n \cdot m$。 入力順序は行方向または列方向ではありません。 代わりに、マトリックスは外側から内側に向​​かって層ごとに剥がされ、各層はその層の左上隅から時計回りの螺旋で横断されます。 

言い換えれば、残りの部分行列の外側の境界を繰り返し取得し、その境界に沿って時計回りに歩き、その順序で数字を書くことを想像してください。 外側のリングが使い果たされたら、次の内側の長方形に移動し、同じプロセスを繰り返します。 

各クエリに対して、次のものが与えられます。$n$、$m$、および値$x$そして、正確な行と列を決定する必要があります。$x$このスパイラル充填の中に現れます。 

制約は非常に大きく、$n$そして$m$まで$10^9$そして最大$10^5$クエリ。 これにより、グリッドのシミュレーションや部分的なトラバースさえも即座に除外されます。 完全な構築には次のことが必要です$10^{18}$最悪の場合、時間的にもメモリ的にも不可能です。 スパイラルに沿ってクエリごとに歩いても、境界線だけが影響を受ける可能性があるため、遅すぎます。$O(n + m)$、それでも大きすぎます。 

主な困難は、行列を生成せずに数値がどこに到達するかを直接推論しなければならないことです。 

微妙なエッジケースは、縮退層から生じます。 残りの長方形が単一の行または単一の列になると、スパイラルの動作は直線に崩壊します。 たとえば、$1 \times 5$グリッドでは、塗りつぶしは単純に左から右に行われます。 で$5 \times 1$グリッド、上から下にあります。 常に 4 つの側面を想定する単純なスパイラル シミュレーションでは、このような場合、セルが誤って二重カウントされたり、再訪されたりする可能性があります。 

## アプローチ

 ブルートフォース手法では、スパイラルの塗りつぶしを明示的にシミュレートします。つまり、現在の上下左右の境界を維持し、境界を内側に縮小しながら時計回りの順序で数値を書き込みます。 各割り当ては 1 つの数値を書き込むため、テスト ケースごとの合計作業量は次のようになります。$O(nm)$。 これは大規模なグリッドではすでに不可能であり、$10^5$テストケースでは完全に実行不可能になります。 

重要な観察は、らせんには強い構造的規則性があるということです。 グリッドは同心の長方形の「リング」で構成されます。 各リングは、その周囲のサイズに等しい予測可能な数の要素を提供します。 外側のレイヤ全体で消費される数値の数がわかれば、どのレイヤに含まれる数値が正確に判断できるようになります。$x$、そして、単純な算術を使用してそのレイヤー内の位置を計算します。 

各レイヤーは独立して動作し、現在の四角形の寸法によって決定される固定形状を持ちます。 走査順序は決定的です: 上の行、右の列、下の行が反転、左の列が反転し、次元が折りたたまれた場合は調整されます。 

したがって、段階的にシミュレーションするのではなく、層ごとに計算し、から全周を差し引きます。$x$正しいリングに着地するまで。 次に、そのリング内のオフセットを直接デコードします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nm)$テストごと |$O(1)$| 遅すぎる |
 | 層の分解 |$O(\min(n,m))$テストごと |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 現在のレイヤーを表す 4 つの境界 (上の行、下の行、左の列、右の列) を維持します。 初めにこれらは$1, n, 1, m$。 

1. 現在の外側リング内の要素の数を計算します。 長方形に複数の行と複数の列がある場合、リングの長さは次のようになります。$2 \cdot (bottom - top + 1 + right - left + 1) - 4$。 1列の場合はリング幅がちょうどになります。 単列の場合は高さだけです。 そうしないとコーナーが 2 回カウントされてしまうため、この区別は重要です。 
2. もし$x$現在のリングのサイズより大きい場合は、からリングのサイズを引きます。$x$、次に境界をすべての側面で 1 レイヤーずつ内側に縮小します。 これにより、次の内側の長方形に移動します。 
3. までこのプロセスを繰り返します。$x$現在のリング内にあります。 その時点で、答えが含まれている正確なレイヤーがわかります。 
4. 正しいリングに入ったら、4 つのセグメントに分けて論理的に横断します。 まず、上の行に沿って左から右に移動します。 もし$x$このセグメントに含まれる場合、その位置は直接決定されます。 それ以外の場合は、そのセグメントを差し引いて続行します。 
5. 次に、右の列を下に移動し、次に下の行に沿って右から左に移動し、最後に左の列を下から上に移動します。 各セグメントは順番にチェックされ、一度チェックされます。$x$セグメントに該当する場合は、適切な境界からオフセットすることによってその座標を計算します。 

重要な考え方は、すべてのセグメントが行インデックスまたは列インデックスの直線の等差数列であるということです。 

### なぜ効果があるのか

 各層は閉じたサイクルを形成し、その長さは周囲のセルの数と同じになります。 全サイクルを減算することで、停止時に次のことが保証されます。$x$単一の単純な境界サイクル内にあります。 そのサイクル内では、すべての動きは行または列に沿って単調であるため、位置の回復は線形オフセットの計算に減ります。 不変条件は、レイヤーに入る前にすべての外側のレイヤーが完全に考慮され、レイヤーに入った後に残る構造は、走査順序に曖昧さのない単純な長方形の境界であるということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(n, m, x):
    top, bottom = 1, n
    left, right = 1, m

    while True:
        if top > bottom or left > right:
            return (1, 1)

        if top == bottom:
            # single row
            length = right - left + 1
            if x <= length:
                return (top, left + x - 1)
            return (top, left)

        if left == right:
            # single column
            length = bottom - top + 1
            if x <= length:
                return (top + x - 1, left)
            return (top, left)

        height = bottom - top + 1
        width = right - left + 1
        ring = 2 * (height + width) - 4

        if x > ring:
            x -= ring
            top += 1
            bottom -= 1
            left += 1
            right -= 1
            continue

        # now x is inside this layer
        # top row
        top_len = right - left + 1
        if x <= top_len:
            return (top, left + x - 1)
        x -= top_len

        # right column
        right_len = bottom - top
        if x <= right_len:
            return (top + x, right)
        x -= right_len

        # bottom row
        bottom_len = right - left + 1
        if x <= bottom_len:
            return (bottom, right - x + 1)
        x -= bottom_len

        # left column
        return (bottom - x, left)

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, m, x = map(int, input().split())
        r, c = solve_one(n, m, x)
        out.append(f"{r} {c}")
    print("\n".join(out))

if __name__ == "__main__":
    main()
```コードは層の分解を直接反映しています。 ループは、残りのリングがなくなるまで、完全なリングを繰り返し削除します。$x$現在の境界内に収まります。 境界を縮小するステップにより、シミュレーションの必要がなくなります。 

有効なリングの内部では、各セグメントは単純なオフセット計算として処理されます。 一番上の行は、直接の水平方向のインデックス シフトです。 右の列が下に移動します。 一番下の行は逆インデックスであるため、右側の境界から減算します。 左の列も同様に上向きにマッピングされます。 

よくある落とし穴は、右列と左列での 1 つ違いの処理です。 実装では慎重に使用します`bottom - top`の代わりに`bottom - top + 1`垂直セグメントの場合、コーナーは水平セグメントですでに考慮されているためです。 

## 実用的な例

 ### 例 1

 検討してください$n = 4, m = 5, x = 10$。 

まず外輪のサイズを計算します。 完全な境界には、$2(4 + 5) - 4 = 14$要素。 以来$x = 10 \le 14$、外環に留まります。 

| セグメント | 残り x | アクション | ポジション |
 | --- | --- | --- | --- |
 | 上の行 | 10 | 5セル | スキップ |
 | 右列 | 5 | 4セル | スキップ |
 | 一番下の行 | 1 | 5セル | 取る |

 最下段のセグメントに着陸します。 右下から開始して左に移動すると、最初の位置は次のようになります。$x = 1$、したがって、答えは次のとおりです$(4, 5)$。 

このトレースは、明示的なシミュレーションを行わなくても、セグメントの分解が時計回りの走査順序と一致していることを確認します。 

### 例 2

 検討してください$n = 3, m = 3, x = 8$。 

外輪サイズは$2(3 + 3) - 4 = 8$したがって、答えは正確に外側の境界にあります。 

| セグメント | 残り x | アクション | ポジション |
 | --- | --- | --- | --- |
 | 上の行 | 8→5 | スキップ 3 | (1,3) |
 | 右列 | 5→3 | スキップ 2 | (3,3) |
 | 一番下の行 | 3→1 | スキップ 2 | (3,1) |
 | 左列 | 1 | 取る | (2,1) |

 これは、最終セグメントが垂直エッジに正確に到達する値をどのように解決し、正しい境界処理を検証するかを示しています。

 ## 特殊なケース

 単一行のグリッドは、アルゴリズムが完全なリング式を誤って適用しているかどうかを明らかにします。 入力用$n = 1, m = 5, x = 4$、正しいトラバースは純粋に左から右です。 アルゴリズムは即座に検出します`top == bottom`そして戻ってきます$(1, 4)$単純なオフセットによって、角を二重にカウントすることになる周囲を計算する試みを回避します。 

単一列グリッドも同様に動作します。 のために$n = 5, m = 1, x = 3$、正解は$(3, 1)$。 条件`left == right`これにより、垂直方向のみに移動し、4 方向への移動は決して試行されなくなります。 

薄い内輪など$n = 4, m = 2$、1回剥がすと線に減ります。 境界縮小ステップにより、外側のサイクルを削除した後、アルゴリズムは、上部と下部が重なる縮退した長方形の走査を試行するのではなく、線形処理ケースに切り替わります。
