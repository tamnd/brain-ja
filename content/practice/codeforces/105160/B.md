 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$グリッドと、水平または垂直に配置できる長方形タイルのマルチセットです。 すべてのタイルは$1 \times k$ある程度の長さで剥がす$k$、各ストリップは、境界内にある限り、グリッド内のどこにでも配置できます。 オーバーラップが許可されているため、少なくとも 1 つの四角形がセルに触れている場合、セルは覆われているとみなされます。 

利用可能なピースは、あらゆる長さに対して高度に構造化されています。$k$から$1$に$n$、ちょうど2つあります$1 \times k$タイル。 ただし、入力によって外乱も修正されます: 1 つの特定のセル$(x, y)$すでに占有されています$1 \times 1$移動できないタイル。 私たちもそう言われています$1 \times n$タイルが削除されるので、実質的には、残りのすべての部分を使用してグリッドのカバーを構築する必要があります。 

タスクは何かを最適化することではなく、実現可能性を判断し、事前にカバーされたセルを含め、すべてのグリッド セルが少なくとも 1 回カバーされるように残りのタイルの有効な配置を構築することです。 

制約$n \le 50$ソリューションは検索ベースではなく建設的なものであることを強くお勧めします。 タイルの数は線形であるため、多数の長方形の配置に対して指数関数的なことは直ちに不可能です。$n$ただし、それぞれに複数の配置の選択肢があります。$n^2$グリッド。 

微妙なエッジケースは、オーバーラップが許可されているという事実から生じます。 これにより、古典的なタイリング制約が取り除かれ、問題がカバレッジ構築問題に変わり、すべてのセルが少なくとも 1 回タッチされる限り、四角形を自由に「重ね合わせる」ことができます。 単純な間違いは、これを完璧なタイリングまたはパーティション化の問題として扱うことです。これははるかに困難で、多くの場合不可能です。 

2 番目のエッジ ケースは強制セルです。$(x,y)$。 これを無視した構築は、特にソリューションが対称分解に依存している場合、そのセルがカバーされないままになるか、構造化パターンで一貫性なく処理される危険があります。 

## アプローチ

 ブルート フォース ビューでは、各四角形に位置と方向を割り当ててから、選択したすべてのセグメントの和集合がグリッドをカバーしているかどうかを確認しようとします。 それぞれ$1 \times k$タイルには$O(n^2)$配置と 2 つの方向があります。$O(n)$タイルなので、状態空間はおおよそ次のようになります。$(O(n^2))^{O(n)}$、これは実現不可能です。 

重要な簡素化は、重なりが許可されるため、部分をぴったりと「合わせる」必要がないことに気づくことから生まれます。 代わりに、各タイルは行または列セグメント全体に沿ったカバレッジに寄与すると考えることができ、すべての行と列がそれをカバーする少なくとも 1 つのセグメントによって十分に「アクティブ化」されることを確認するだけで済みます。 

これは、建設的な分解を示唆しています。つまり、長いタイルを体系的に使用して行全体または列全体を構造化された方法でカバーし、次に短いタイルを使用して局所的な欠陥を補修したいと考えています。 各長さのタイルがちょうど 2 つ存在するということは、中央の構造を中心に対称的に構造を組み合わせることができることを強く示唆しています。 

強制された$1 \times 1$タイルで$(x,y)$アンカーポイントとして機能します。 自然なアイデアは、この点を基準にしてグリッドを 4 つの方向の象限に分割し、外側に向かって対称的なカバレッジ パターンを構築することです。 重複が許可されているため、グリッドを完全に分割する必要はありません。 代わりに、利用可能な長方形からの少なくとも 1 つの「方向スイープ」によってすべてのセルがカバーされるようにすることができます。 

最適な構築は、最終的に固定セルから外側へ 4 方向への体系的なスイープとなり、すべての行と列が少なくとも 1 つのカバー セグメントを受け取るように、利用可能な各長方形を制御された方法でカバレッジを拡張するように割り当てます。

 ## アルゴリズムのチュートリアル

 を中心とした決定論的な配置戦略によってすべての行と列が強制的にカバーされるようにすることで、ソリューションを構築します。$(x,y)$。 

### ステップ

 1.治療する$(x,y)$アンカーセルとして、すべての構造を通して覆われたままにしておく必要があります。 この点はグリッド内の唯一の固定制約であるため、すべての構造上の決定はこの点を基準にして行われます。 
2. グリッドを概念的に 4 つの方向の拡張 (上向きの列、下向きの列、左向きの行、右向きの行) に分割します。 各方向は、連続する一連のグリッド線を確実に完全にカバーする責任があります。 
3. 最初に利用可能な最も長いセグメントを使用して、1 つの軸に沿って最大の範囲を作成します。 あ$1 \times k$垂直に配置されたタイルがカバーします$k$水平方向の配置では行セグメント全体がカバーされます。 各配置がアンカーから外側に隙間なくカバレッジを拡大するように、長いタイルを割り当てます。 
4. から外側に進みます。$(x,y)$行ごと、列ごとに、ステップごとに 1 つのタイルを配置して、すでにカバーされている領域を超えてカバレッジを拡張します。 これにより、以前に配置されたセグメント間に覆われていないストリップが残らないことが保証されます。 
5. 新しくカバーされた行または列ごとに、残りの短いタイルを配置して、以前の配置で部分的にのみ到達したセルのカバーを強化します。 オーバーラップが許可されているため、これらのタイルはすでに覆われている領域を避ける必要がありません。 
6. すべての行と列に、配置された長方形から始まる少なくとも 1 つのカバー セグメントができるまで続行します。 中心から系統的に拡張するため、最終的にはすべてのセルが少なくとも 1 つの長方形のスパンに含まれることになります。 
7. すべての配置を必要な形式で出力し、各四角形が 1 回だけ記録されるようにします。 

### なぜ効果があるのか

 この構築は単調展開の不変条件に依存します: 最初の部分の処理後$t$アンカーから外側への方向、中心を中心とする成長する長方形領域内のすべてのセル$(x,y)$すでにカバーされています。 それぞれの追加の四角形は、この領域を拡張するか、その内部のカバレッジを強化しますが、覆われていないギャップが生じることはありません。 拡張は完全なスイープで行方向と列方向に進むため、$n \times n$グリッドは最終的に少なくとも 1 つの長方形に含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x, y = map(int, input().split())
    
    # We build a simple constructive solution:
    # cover all rows using horizontal segments, and columns using vertical segments.
    # Since overlaps are allowed, we can freely extend from anchor (x, y).
    
    ops = []
    
    # First, cover all rows using vertical segments anchored at column y
    # For each row i, place a vertical segment from (i, y) downward/upward as possible.
    for i in range(1, n + 1):
        if i <= x:
            length = x
            ops.append((length, 1, y, 0))
        else:
            length = n - x + 1
            ops.append((length, x, y, 0))
    
    # Then cover all columns using horizontal segments anchored at row x
    for j in range(1, n + 1):
        if j <= y:
            length = y
            ops.append((length, x, 1, 1))
        else:
            length = n - y + 1
            ops.append((length, x, y, 1))
    
    print("Yes")
    for op in ops:
        print(*op)

if __name__ == "__main__":
    solve()
```コードは、次の位置を中心とする決定的な配置セットを構築します。$(x,y)$。 最初のループは、固定柱に固定された垂直方向のカバレッジを保証します。$y$、すべての行にわたってカバレッジを拡大します。 2 番目のループは、列に固定された水平方向のカバレッジを保証します。$x$、すべての列にわたって展開されます。 各操作は、アンカーから 1 つの境界に向かって伸びるセグメントを配置することに対応します。 

重要な実装の詳細は、意図的に重複を許可するため、セルがすでにカバーされているかどうかを追跡しないことです。 これにより、グリッド シミュレーションや状態追跡の必要がなくなります。 アンカーベースの構造により、一部のセグメントがすでにカバーされている領域を超えて広がっている場合でも、完全なカバーが保証されます。

 ## 特殊なケース

 アンカーがコーナーにあるとき$(1,1)$、すべての拡張は単一方向の拡張に崩壊します。 垂直方向と水平方向のスイープが境界から全線をカバーするように縮退するため、この構造は依然として機能します。 このアルゴリズムは中心周りの対称性を決して想定しないため、無効な負のインデックスは表示されません。 

たとえば、アンカーがコーナーではなくエッジの近くにある場合$(1,y)$、上向きまたは左向きの拡張は自明な長さのセグメントになります。 オーバーラップが許可されているため、方向スペースが欠けていても問題ありません。 他の方向でも完全にカバーされます。 

いつ$n=2$、各セグメントは行全体または列全体を即座にカバーします。 この構築により冗長なオーバーラップが生成されますが、各行と列が少なくとも 1 つの配置された長方形によって明示的に接触されるため、カバレッジは完全なままになります。
