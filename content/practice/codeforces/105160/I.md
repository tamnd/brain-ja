 ## 解決策
 ## 問題の理解

 平面内に 2 つの円が与えられます。 各円は、その中心座標と半径によって定義されます。 すべてのテスト ケースについて、線が両方の円に同時に接するような、明確な直線が何本存在するかを数える必要があります。 そのような行が無限にある場合は、-1 を出力する必要があります。 

幾何学的に、線は、内部を切断せずに、各円の 1 点で正確に接触する場合に有効です。 同じ幾何学的な線は、たとえそれが異なる「接線構成」から来ているように見える場合でも、1 回だけカウントされます。 

テスト ケースの制約は最大 100000 と大きく、座標と半径は最大 10000 です。これにより、候補線を明示的に列挙したり、考えられるすべての接線に対して交差チェックを実行したりするテストごとの幾何学的構築が即座に除外されます。 ソリューションでは、各テスト ケースを一定量の演算に削減する必要があります。 

2 つの円が一致する場合、微妙な特殊なケースが発生します。 両方の中心と半径が同一の場合、その円のすべての接線は同時に両方に接し、無限に多くの有効な線が生成されます。 別の特殊なケースは、円が入れ子になっている場合、または一方が接触せずに厳密に他方の内側にある場合に発生します。 このような場合、共通の接線は存在しません。 半径の合計に対して中心距離をチェックするだけの単純なアプローチでは、外部接線構成と内部接線構成を正しく区別できないことがよくあります。 

## アプローチ

 強引な解釈では、最初の円に対するすべての接線を作成し、次に各線を 2 番目の円に対してテストしようとします。 単一の円には無限に多くの接線があるため、実際には方向を離散化するか、角度サンプリングまたは傾斜パラメータ化を介して接線を列挙しようとします。 接触点によって定義される接線に限定したとしても、これには依然として連続パラメーターと候補方向ごとの二次方程式の解が含まれます。 各候補線について、両方の円への接線を検証するには、距離の計算と根のチェックが必要であり、いくつかの大きな K についてはテスト ケースごとに少なくとも O(K) の作業が必要になります。これは 100,000 のテスト ケースでは基本的に不可能です。 

重要な点は、2 つの円の共通接線は 4 つの古典的な幾何学的タイプのいずれかでなければならないということです。外部共通接線 (中心を結ぶ線分の同じ側で両方の円に接する) または内部共通接線 (中心を結ぶ線分を横切り、反対側に接する) のいずれかになります。 各タイプは、円の中心と半径の間の距離条件に帰着します。 

中心を A と B、半径 r1 と r2 とし、中心間の距離を d とします。 接線の存在は、d を r1 + r2 および |r1 − r2| と比較することによってのみ決まります。 これは、一方の円を接線の法線方向に沿ってもう一方の円を拡大または縮小して点に移動することで得られます。 それぞれの有効な構成は特定の幾何学的不等式に対応し、有効な接線の数はこれらの構成がいくつ可能かによって決まります。 

特殊な縮退は、円が一致する場合 (接線が無限に多い場合)、円が内部または外部で接触する場合 (一部の接線タイプは 1 つの線に折りたたまれます)、または一方の円がもう一方の円の内側に完全に横たわっている場合 (接線がない場合) に発生します。 

したがって、問題全体は、中心距離、半径の合計、半径の絶対差の 3 つの量のみを使用して 2 つの円の相対位置を分類することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (接線の構築) | テストごとに O(∞) | お(1) | 不可能 |
 | 幾何学分類 | テストごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

各テスト ケースでは、浮動小数点エラーを回避するために中心間の二乗距離を計算します。 次に、それを半径から導出された二乗しきい値と比較します。 

1. 2 つの円 (x1, y1, r1) と (x2, y2, r2) を読み取ります。 円の中心と半径の両方が同一である場合、単一の円のすべての接線が両方に有効であるため、-1 を出力します。 
2. dx = x1 − x2 および dy = y1 − y2 を計算し、d2 = dx・dx + dy・dy を定義します。 これは中心間の二乗距離を表します。 
3. sumR = r1 + r2 および diffR = |r1 − r2| を計算します。 これらの値は、外部接線構成と内部接線構成のしきい値を定義します。 
4. d2 がゼロであっても円が同一でない場合、円は同じ中心を共有しますが、半径は異なります。 この場合、一方の円の接線はもう一方の同心円の完全に外側にあるため、両方の円に接する線は存在しません。 0を出力します。 
5. d2 < diffR² の場合、一方の円は接触することなく他方の円の内側に厳密に存在します。 接線が両方の境界に同時に触れることはできないため、0 を出力します。 
6. d2 が diffR² に等しい場合、円は内部で接しています。 内部共通接線が 1 つだけ存在します。 
7. d2 > diffR² かつ d2 < sumR² の場合、円は重なり合います。 この領域には、ちょうど 2 つの共通外部接線が存在します。 
8. d2 が sumR² に等しい場合、円は外側に接します。 この場合、2 つの外部共有接線と 1 つの縮退共有接線の 3 つの異なる共通接線が存在します。 
9. d2 > sumR² の場合、円は互いに素です。 4 つの古典的な共通接線はすべて存在します。 

### なぜ効果があるのか

 すべての共通接線は、接点の半径に垂直な方向ベクトルによって決定されます。 固定線の場合、その法線方向に沿ってシフトすると、中心から線までの符号付き距離を比較するという問題が軽減されます。 接線によって課される制約は、その符号付き距離における線形方程式に変換されます。 これらを 2 つの円について同時に解くと、d、r1、および r2 を含む条件が正確に得られます。 解の数は、一貫した符号割り当てが可能な数に対応します。これは、まさに上記の事例分析で列挙したものです。 分類は相対距離のみに依存するため、これらの比較を超える幾何学的構築は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        x1, y1, r1 = map(int, input().split())
        x2, y2, r2 = map(int, input().split())

        dx = x1 - x2
        dy = y1 - y2
        d2 = dx * dx + dy * dy

        if x1 == x2 and y1 == y2 and r1 == r2:
            out.append("-1")
            continue

        sumR = r1 + r2
        diffR = abs(r1 - r2)

        if d2 == 0:
            out.append("0")
        elif d2 < diffR * diffR:
            out.append("0")
        elif d2 == diffR * diffR:
            out.append("1")
        elif d2 < sumR * sumR:
            out.append("2")
        elif d2 == sumR * sumR:
            out.append("3")
        else:
            out.append("4")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は分類を直接反映します。 最初のガードは、同一の円が無限に存在する場合を処理します。 精度の問題を回避するために、平方距離が全体で使用されます。 後続の各分岐は、円が入れ子になっているか、接しているか、交差しているか、または互いに素であるかどうかによって定義される幾何学的領域に正確に対応します。 誤分類を避けるために、厳密な不等式の前に等価のケースを分離する必要があるため、チェックの順序は重要です。 

## 実用的な例

 ### 例 1

 入力:```
1
0 0 1
0 3 1
```ここで、dx = 0、dy = −3、つまり d2 = 9 です。 sumR = 2 および diffR = 0 であるため、sumR² = 4 および diffR² = 0 となります。 

| ステップ | d2 | 差分R² | 和R² | 決定 |
 | --- | --- | --- | --- | --- |
 | 距離を計算する | 9 | 0 | 4 | ばらばらのケース |

 d2 > sumR² であるため、円は分離され、4 つの接線がすべて存在するため、答えは 4 になります。 

これは、十分に分離された円には内部接線と外部接線の両方が許容されるという解釈を裏付けます。 

### 例 2

 入力:```
1
0 0 2
3 0 1
```ここでは、dx = 3、dy = 0、つまり d2 = 9 です。 sumR = 3、diffR = 1 であるため、sumR² = 9、diffR² = 1 となります。 

| ステップ | d2 | 差分R² | 和R² | 決定 |
 | --- | --- | --- | --- | --- |
 | 比較 | 9 | 1 | 9 | 外接線 |

 d2 == sumR² であるため、円は外部接であり、3 つの共通接線が生成されます。 

このケースは、等価性処理の重要性を示しています。等価性分岐が欠落していると、これが素または重複として誤って分類されてしまいます。

 ## 特殊なケース

 円が同一の場合、アルゴリズムは最初の条件をトリガーし、すぐに -1 を出力します。 たとえば、(0,0,1) と (0,0,1) は距離の計算が重要になる前に捕捉され、無限に多くの共有接線を正しく表します。 

(0,0,5) や (0,0,2) など、半径が異なる同心円の場合、二乗距離はゼロですが、diffR² は正になります。 d2 < diffR² という条件がトリガーされ、0 が生成されます。これは、一方の円の接線がもう一方の同心円に触れることはできないという幾何学的事実と一致します。 

(0,0,2) や (3,0,1) のような外接円の場合、d2 == sumR² が得られます。 等価分岐により、確実に 3 が返されます。厳密な不等号のみの実装では、これが素であると誤分類され、誤って 4 が出力されます。 

(0,0,1) や (10,0,1) などの互いに素な円の場合、距離条件は sumR² を超え、構成は 4 つの接線を持つ最終ケースに配置され、外部接線と内部接線の完全なセットが反映されます。
