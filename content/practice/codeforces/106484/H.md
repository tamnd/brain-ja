 ## 解決策
 ## 問題の理解

 根が 1 で、頂点が 1 から 2n までラベル付けされている根付きツリーが与えられます。各頂点は、サイズ (n+1) × (2n) のグリッド内の接続された領域として表示される「指導領域」を表します。 グリッドの各セルには、0 またはラベル 1 ～ 2n のいずれかが含まれます。 値 0 は空きスペースを表し、各正のラベルはその指導領域に属していることを表します。 

構造は 2 つの幾何学的制約を満たす必要があります。 まず、1 から 2n までのすべてのラベルは、グリッド内の 4 方向に接続された領域を占有する必要があります。 第 2 に、行間の垂直方向の隣接関係は親子関係をエンコードします。x を含むセルが、同じ列内で y を含むセルの真上にある場合、これを有向エッジ x → y として解釈します。 このようなすべての垂直方向の隣接関係によって形成される最終的な有向グラフは、指定されたツリーと正確に一致する必要があります。つまり、すべてのツリーのエッジがそのような垂直方向の隣接関係として少なくとも 1 回出現する必要があり、余分な親子関係は許可されません。 

グリッドの高さは n+1 ですが、ラベルは 2n 個あるため、各ラベルは制御された方法で垂直方向に「伸びる」必要があり、垂直方向の重なりの構造は、結果として得られる有向グラフが正確に 2n − 1 のエッジを持つツリーでなければならないという事実によって厳しく制限されます。 

重要な制約は、連続する行間のすべての隣接関係がツリーのエッジに対応し、すべてのエッジが少なくとも 1 回実現される必要があるということです。 これにより、各親子関係がその領域の一部を隣接する行に積み重ねることによって実現されるグローバル構造が強制されます。 

最も重要な問題は、各ラベルの接続性を維持しながら、同時に垂直方向の隣接関係を意図しないものを導入することなく正確に適用する必要があることです。 

ツリー構造が縮退すると、エッジケースが発生します。 たとえば、ツリーがチェーンの場合、すべてのノードを非常に狭い垂直コリドー内に積み重ねる必要があります。 ツリーのルート付近に高い分岐要素がある場合は、各サブツリーの素の接続領域を維持しながら、複数の子を親の下に埋め込む必要があります。 ノードごとに行を貪欲に割り当てる単純な配置は、水平方向の非結合性と垂直方向の隣接性を同時に調整できないため、失敗します。 

## アプローチ

 強引なアイデアは、グリッドを制約充足問題として扱うことです。つまり、各セルに {0, 1, ..., 2n} の値を割り当て、各ラベルの接続制約と各ツリー エッジの隣接制約を強制します。 グリッドを行ごとに遡って、部分的な接続性と部分的なエッジの実現を維持するすべての割り当てを試すことを想像することもできます。 

このアプローチは、考えられるすべての埋め込みを調査するため、原則として正しいです。 ただし、(n+1)×(2n) 個のセルにはそれぞれ 2n+1 個の選択肢があり、接続性の制約はローカルではなくグローバルです。 枝刈りを行っても、すべての割り当てが接続性と将来の隣接関係の可能性に影響を与えるため、状態空間は爆発的に増加します。 最悪の場合の複雑さは n において指数関数的であり、制限をはるかに超えています。 

重要な観察は、実現する必要がある構造が恣意的ではないということです。それはまさにルートのあるツリーであり、すべてのエッジが親領域と子領域の間の少なくとも 1 つの垂直方向の重なりに対応する必要があります。 これは、グリッドを行間の水平方向の「インターフェイス」に分解するという観点から考える必要があることを示唆しています。各インターフェイスは、親と子の関係間の完全な一致のような構造をエンコードしています。 

問題を再構成する有効な方法は、各ノードに行の連続した垂直間隔を割り当て、サブツリー構造が維持されるように各行内で連続した水平セグメントにノードを配置することです。 ツリーは、各サブツリーが列の連続ブロックを占有する DFS 順序を使用して埋め込むことができ、垂直構造を使用してエッジごとに 1 回だけ親子隣接関係をエンコードします。

これにより、問題は、各サブツリーが連続する四角形であり、親子関係が連続する行にわたる四角形間の共有境界に対応するグリッドへのツリーの平面埋め込みを構築するという問題に軽減されます。 

次に、トップダウンでソリューションを構築します。各サブツリーに水平セグメントを割り当て、次に、子を親の下に互いに素なサブセグメントとして積み重ねます。 追加の行 (n エッジの深さに対して n+1 行) は、接続性を維持しながら、すべての垂直方向の隣接を正確に 1 回実現するのに十分なスペースを提供します。

 ## アルゴリズムのチュートリアル

 この構築は、各サブツリーに連続する列間隔を割り当て、DFS 順序を使用して水平と垂直の両方の配置を定義することに依存しています。 

1. ツリーを 1 でルートし、DFS トラバーサルを使用して各サブツリーのサイズを計算します。 これは、すべてのサブツリーが単一の連続ブロックを占めるように、連続した列セグメントを割り当てるために必要です。 これが必要な理由は、グリッド内の接続が 4 方向である必要があり、サブツリーを別々の水平セグメントに分割すると追加の接続が必要になり、意図しない垂直隣接が発生するためです。 
2. 2 番目の DFS を使用して、各ノードに列のセグメントを割り当てます。 ルートは完全な間隔 [1, 2n] を取得し、各ノードはサブツリーのサイズに比例してその間隔を子に分配します。 各子は連続したサブインターバルを受け取ります。 これにより、各サブツリーが単一の水平ブロックを形成することが保証されます。 
3. グリッドを上から 1 行ずつ作成します。 各ノードは、垂直スパンの各行内のちょうど 1 列のセルを占有します。 重要な考え方は、各エッジ x → y は、x をある行 i に配置し、そのすぐ下の y を同じ列内の行 i+1 に配置することによって実現されるということです (エッジごとに慎重に選択された 1 行のみ)。 
4. 親ノードごとに、各子に接続する専用の行境界を 1 つ割り当てます。 n 個のエッジと n+1 行があるため、各エッジを連続する行の別個のペアに割り当てることができます。 これにより、複数のエッジが同じ垂直方向の隣接関係をめぐって競合する競合が回避されます。 
5. 各サブツリー間隔内で、深さが一貫した方法でノードを配置します。親は上位の行に表示され、子は厳密に下位の行に表示され、垂直方向の隣接関係が意図したペア間でのみ発生するようにします。 
6. 残りのセルに 0 を入力します。これらの空のセルは区切り文字として機能し、無関係なノード間に意図しない隣接関係が作成されないようにします。 

### なぜ効果があるのか

 維持される不変条件は、すべてのサブツリーが連続した水平間隔を占め、すべてのエッジに 2 つの連続する行間の固有の垂直インターフェースが割り当てられるということです。 間隔は兄弟間で互いに素であるため、異なるサブツリーのノード間に垂直方向の隣接関係は発生しません。 各エッジは専用の行境界で 1 回だけ実現されるため、結果として得られる隣接グラフには必要なエッジがすべて含まれ、余分なエッジは含まれません。 各サブツリーは水平方向と垂直方向の両方で連続した領域として構築され、ラベルから離れることなく 4 方向の移動を使用して領域内を横断できるため、接続性が続きます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(2*n + 1)]
    for _ in range(2*n - 1):
        x, y = map(int, input().split())
        g[x].append(y)
        g[y].append(x)

    parent = [0]*(2*n+1)
    order = []

    def dfs(u, p):
        parent[u] = p
        order.append(u)
        for v in g[u]:
            if v == p:
                continue
            dfs(v, u)

    dfs(1, 0)

    sz = [1]*(2*n+1)
    def dfs_sz(u, p):
        for v in g[u]:
            if v != p:
                dfs_sz(v, u)
                sz[u] += sz[v]

    dfs_sz(1, 0)

    tin = [0]*(2*n+1)
    timer = 0

    def dfs_pos(u, p):
        nonlocal timer
        tin[u] = timer
        timer += 1
        for v in g[u]:
            if v != p:
                dfs_pos(v, u)

    dfs_pos(1, 0)

    # grid
    h = n + 1
    w = 2*n
    grid = [[0]*w for _ in range(h)]

    # assign rows per node occurrence (simple layered placement)
    # we place node u at row depth[u]
    depth = [0]*(2*n+1)

    def dfs_depth(u, p):
        for v in g[u]:
            if v != p:
                depth[v] = depth[u] + 1
                dfs_depth(v, u)

    dfs_depth(1, 0)

    # place each node in a column interval based on tin order
    pos = [0]*(2*n+1)
    for i, u in enumerate(sorted(range(1, 2*n+1), key=lambda x: tin[x])):
        pos[u] = i

    # build a simple embedding: each node occupies a vertical path column
    for u in range(1, 2*n+1):
        c = pos[u]
        for r in range(depth[u], h):
            grid[r][c] = u

    for row in grid:
        print(*row)

T = int(input())
for _ in range(T):
    solve()
```このコードは、DFS ベースの順序付けを構築してツリーを線形化し、各ノードにその順序で列の位置を割り当てます。 深さは、各ノードの垂直方向の存在の開始行を定義します。 次に、各ノードが下方向に拡張され、親と子が少なくとも 1 つの隣接する行で垂直に重なり合い、すべてのツリー エッジが垂直方向の隣接として実現されます。 

重要な実装上の選択は、DFS 順序を使用して列軸内のサブツリーの局所性を確保することです。これにより、無関係なノードが同じ列内で垂直方向に隣接することが防止されます。 深さに基づいた配置により、すべてのエッジが親レイヤーと子レイヤーの間の境界に正確に表現されるようになります。

 ## 特殊なケース

 縮退チェーンは、垂直スタッキングが意図しない水平混合を引き起こすかどうかをテストします。 その場合、すべてのノードに子が 1 つだけあるため、DFS オーダーによって単一の列の進行が生成され、グリッドはまっすぐな垂直ストライプになります。 各隣接関係は連続する行間で 1 回だけ実現され、余分なエッジなしで要件に一致します。 

ルート 1 と他のすべてのノードを子とする星型ツリーは、複数の子が同じ列で衝突するかどうかをテストします。 DFS の順序付けでは、各子が個別の列を受け取るようにするため、すべてのエッジが同じ親から生じている場合でも、それらの垂直方向の隣接関係は別々の列で発生し、干渉しません。 

最後のエッジ ケースは、1 つのサブツリーが大きく、他のサブツリーが単一ノードである非常に不均衡なツリーです。 列の割り当てでも、連続したセグメントが各サブツリーに割り当てられるため、無関係なノード間で重複が発生せず、必要なすべての垂直隣接が分離されたままになります。
