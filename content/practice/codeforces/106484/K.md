 ## 解決策
 ## 問題の理解

 1 から 1 までのラベルが付いた頂点にルート ツリーが与えられます。$x$、頂点 1 がルートであり、他のすべての頂点です。$i$より小さいラベルを持つ親が 1 つだけあります。 したがって、ラベルはすでに有効な親構造を強制していますが、ツリーの実際の構造はそれ以外は自由です。 

このようなツリーから、頂点の順列を生成する 2 つの決定論的な走査を定義します。 どちらの走査もルートから開始され、概念的には「最初に親を訪問し、次に子を訪問」しますが、違いは子が処理される順序です。 最初の走査では、子はラベルの昇順でアクセスされ、2 回目の走査では、子はラベルの降順でアクセスされます。 

すべてのノードは 1 回だけ訪問されるため、両方の走査でいくつかの順列が出力されます。$1 \ldots x$。 異なるツリーが、特定の走査の下で同じ順列を生成する場合があります。 

最初の走査を使用して順列を生成するツリーが少なくとも 1 つ存在し、さらに 2 番目の走査を使用して順列を生成する (おそらく同じツリー、おそらく異なるツリー) 場合、その順列は曖昧であると呼ばれます。 

入力は順列を直接与えるものではありません。 代わりに、部分的に既知の長さの順列が与えられます。$n+m$、ここでの値は$1$に$n$ちょうど 1 回出現し、残りは$m$位置は不明であり、ゼロで表されます。 タスクは、この部分情報と一致する曖昧な完全な順列の数を数えることです。つまり、有効なツリーから両方の走査スタイルでそれらが生成される可能性があります。 

制約$n+m \le 10^5$テスト セットごとに、最大で$10^5$テスト ケースでは、テストごとに線形または線形に近い解決策が強制されます。 テスト間の合計制約$3 \cdot 10^5$は、各位置を平均して一定の回数処理する必要があることを示します。 

欠落しているすべての順列またはすべてのツリーを列挙する単純なアプローチは、すぐには実行不可能です。$n=20$ツリーと順列の数は組み合わせ的に爆発的に増加します。 

微妙なエッジケースは、未知の位置がない場合です。 次に、完全に固定された順列があいまいであるかどうかを判断するように求められます。 もう 1 つのエッジ ケースは、すべての位置が不明な場合です。これにより、組み合わせの自由度が最大化されますが、それでも線形時間で解決する必要があります。 

## アプローチ

 ブルートフォースパースペクティブでは、タイプ 1 トラバーサルで特定の順列を生成できるすべての有効なツリーを再構築し、次にタイプ 2 トラバーサルですべてのツリーを個別に再構築し、順列レベルでそれらの交差をカウントしようとします。 順列に限定した場合でも、欠損値のすべての補完を列挙し、各補完について両方の走査制約と一致するツリーが存在するかどうかをテストする必要があります。 完成数は、$m!$、 そして$m$テストごとに最大 80 になる可能性がありますが、テスト全体では、組み合わせ爆発が繰り返されるため、この構造は依然として実行不可能になります。 ツリー互換性チェック自体は少なくとも線形であるため、階乗乗算は線形になります。 

重要な点は、実際にツリーを構築する必要がないということです。 両方の走査ルールは、順列自体に対する構造的制約を定義します。これらは、2 つの反対の単調子順序分解に対応します。 順列は、特定の「最小から最大までの連続サブツリー構造」を尊重する場合にタイプ 1 によって正確に実現可能であり、逆の順序で同じ構造を尊重する場合にタイプ 2 によって実現可能です。 あいまいさは、順列が両方の解釈を許容することを意味します。これは、両方の順序が有効なままになるように、未知の値によって引き起こされるセグメントをどのように配置できるかという条件に帰着します。 

固定値とゼロの存在は、反転下で対称である全体的な構造的単調性条件を維持しながら、欠落した数値をスロットに割り当てる方法を本質的に数えていることを示唆しています。 この問題は、どちらの方向でも順序制約に違反しない既知のセグメントの有効なインターリーブをカウントすることに帰着します。 

主要な削減点は、順列が既知の値によって決定されるブロックに分割されていると見なせることです。 各ゼロは柔軟な区切り文字として機能します。 曖昧性条件は、すべての誘導ブロック内で、子の増加トラバーサルと子の減少トラバーサルによって課される相対順序制約が矛盾しないという要件に変換されます。 これは最終的に、これらのブロック全体で欠損値の有効な配置を組み合わせてカウントすることになります。各ブロックは、利用可能なスロットに基づいて乗算的に寄与します。 

このように再構成すると、ソリューションは、利用可能な挿入位置の動的なカウントを維持し、両方のトラバース方向によって課せられる順序付け制約の一貫性を確保する線形スキャンになります。

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、配列を 1 から 1 までの固定値のシーケンスとして扱います。$n$散りばめられた$m$空のスロット。 

1. まず配列をスキャンし、すべての固定値の位置を記録します。 これらの位置は、配列の自然な分割を定義します。$n+1$各間隔にはゼロのみが含まれます。 
2. 各間隔について、その長さを計算します。 これは、そのセグメント内で潜在的に割り当てられる未知の値の数を表します。 すべての間隔にわたるこのような未知の配置の合計数は正確に$m$したがって、これらの長さは次のパーティションを形成します。$m$。 
3. 曖昧性条件では、子の増加トラバースと子の減少トラバースによって引き起こされる順序付けが、いずれかのツリーによって両方とも満たされることが必要です。 これは、各固定値が独立して並べ替え可能な領域を区切る境界として機能することを意味します。 
4. 連続する固定値間の各間隔を、どちらの走査順序にも違反しない方法で欠落した数値を配置できるコンテナとして解釈します。 重要な制約は、そのようなコンテナ内では、挿入された要素の相対的な順序によって 2 つの子順序ルールの間に矛盾が生じてはいけないということです。 
5. 各コンテナは、残りの未使用の値と一致するスロットを割り当てる方法の数に等しい組み合わせ係数を提供します。 値はグローバルに一意であり、唯一の構造は境界から得られるため、これは次の多項分布に帰着します。$m$間隔にわたる欠損値。 
6. 最終的な答えは、各区間に入る欠損値の数を選択する組み合わせのすべての区間にわたる積に、各区間内の階乗配置を乗算したものです。 これは標準的な多項係数に単純化されます。$$\frac{m!}{\prod_{i} len_i!}$$計算されたモジュロ$10^9+7$。 
7. 階乗を事前計算します。$3 \cdot 10^5$一度実行すると、モジュラー逆関数を使用して高速二項計算を実行できます。 

### なぜ効果があるのか

 不変条件は、すべての有効な補完が、$m$欠損値をゼロ区間に変換し、各区間内ですべての順列が両方の走査定義に関して局所的に等価になります。 2 つの走査順序は、固定値間の相対的な順序付けに制約を課すだけであり、それらの制約は固定順列構造によってすでに満たされています。 ゼロは順序付けの優先順位を導入しないため、間隔にわたる値のすべての分布は有効なあいまいな順列を生成し、すべてのあいまいな順列はそのような分布の 1 つに正確に対応します。 この全単射により、多項カウントの正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
MAXN = 300000 + 5

fact = [1] * MAXN
invfact = [1] * MAXN

for i in range(1, MAXN):
    fact[i] = fact[i - 1] * i % MOD

invfact[MAXN - 1] = pow(fact[MAXN - 1], MOD - 2, MOD)
for i in range(MAXN - 2, -1, -1):
    invfact[i] = invfact[i + 1] * (i + 1) % MOD

def comb_multinomial(n, parts):
    res = fact[n]
    for x in parts:
        res = (res * invfact[x]) % MOD
    return res

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, v in enumerate(a):
            if v != 0:
                pos[v] = i

        parts = []
        prev = -1
        for v in range(1, n + 1):
            cur = pos[v]
            if prev == -1:
                parts.append(cur)
            else:
                parts.append(cur - prev - 1)
            prev = cur
        parts.append(len(a) - prev - 1)

        print(comb_multinomial(m, parts) % MOD)

if __name__ == "__main__":
    solve()
```すべてのクエリを効率的にサポートするために、コードは階乗を 1 回事前計算します。 テスト ケースごとに、固定値を特定し、その位置をゼロのセグメント長に変換して、それらのセグメント長にわたる多項係数を計算します。 

配列`pos`1 から 1 までの各値を格納します。$n$と表示されるため、線形時間でセグメント構造を復元できます。 の`parts`配列は、最初の固定値の前、連続する固定値の間、最後の固定値の後にゼロがいくつあるかを収集します。 最終的な答えは配布方法の数です$m$明確な欠損値をこれらのセグメントに追加します。 

主な微妙な点は、多項カウントではセグメント内の順列がすでに考慮されているため、セグメントごとに階乗を追加する必要がないことです。

 ## 特殊なケース

 エッジケースの 1 つは、すべての位置が不明な場合です。 この状況では、固定値によって作成される境界がないため、配列全体が 1 つの長さのセグメントになります。$m$。 多項係数は次のようになります。$m! / m! = 1$これは、すべての補完が曖昧さに関して構造的に同等であり、アルゴリズムが正しく 1 を出力することを意味します。 

もう 1 つのエッジ ケースは、未知のものがない場合です。 セグメント リストにはゼロのみが含まれており、式は次のようになります。$0! = 1$したがって、固定順列が一貫している場合、答えは 1 になります。これは、完全な順列が 1 つだけ存在するという事実と一致します。 

3 番目のケースは、未知数が多くの固定値で分割されているものの、不均一に分散されている場合です。 たとえば、単一の大きなブロックに 2 つの連続する固定数値の間にすべて 0 が含まれている場合、すべての柔軟性がそのブロックに集約され、アルゴリズムは他のセグメントを重複してカウントすることなく、すべての組み合わせ自由度をそこに割り当てます。
