 ## 問題の理解

 数字のようなパラメータが与えられます`k`1 ～ 9 と位置`x`。 1 から数え上げることを想像してください。ただし、すべての整数が有効であるとは考えられません。 数値は、次の 2 つの条件のうち少なくとも 1 つを満たす場合にのみ「読み上げ」られます。`k`、またはその 10 進表現には数字が含まれます`k`。 このルールを使用して自然数を概念的にフィルタリングし、無限に増加する「音声」数値シーケンスを生成します。 タスクは、の値を見つけることです。`x`このフィルタリングされたシーケンス内の - 番目の数値。 

制約により許可されるのは、`x`最大100,000、`k`は一桁です。 これは、数値ごとのチェックが安価であれば、潜在的に数百万以上の各整数を検査するあらゆるソリューションが受け入れられることを直ちに示唆しています。これは、通常、100,000 個の受け入れられた要素では、密度に応じて数十万個から数百万個の候補のスキャンが必要になるためです。 したがって、直接シミュレーションが可能になります。 

主な微妙な点はフィルタリング条件です。「数字 k を含む」のチェックは、数値プロパティとしてではなく、10 進数形式で慎重に行う必要があります。 両方の条件が重なる可能性があるという事実から、別の特殊なケースが発生します。 たとえば、33 のような数字の場合、`k = 3`は 3 で割り切れ、数字 3 が含まれますが、シーケンス内で数えられるのは 1 回だけです。 カウンターを数値ごとに 2 回インクリメントする単純な実装では、黙ってオーバーカウントしてしまいます。 

2 番目の潜在的な落とし穴は、数を数える際の 1 つ違いの処理です。`x`- 番目の有効な数値。 配列ではなく有効な数値のストリームを扱っているため、カウンターが次の値に等しい場合に現在の候補を返すのは簡単です。`x`インクリメントロジックが正しいかどうかを確認せずに。 

## アプローチ

 ブルートフォースのアイデアは単純です。1 から開始して、各整数をテストし、ルールを満たす数値の数のカウンターを維持します。 各整数について`i`かどうかを確認します。`i % k == 0`または文字列形式が`i`の文字表現が含まれています`k`。 条件が成立するたびに、カウンタをインクリメントします。 カウンターに着いたら`x`、現在の整数を返します。 

これが機能するのは、すべての整数が 1 回だけチェックされ、フィルタリング ルールが数値ごとに独立しているためです。 このアプローチの弱点は、定数係数の意味でのみパフォーマンスが向上することです。`x`有効な数値が一様に分布していないためです。 たとえば、次のようなとき`k = 9`、9 の倍数と 9 を含む数値は比較的頻繁に使用されるため、数十万の整数をスキャンしただけで有効な数値が 100,000 に達する可能性があります。 最悪の場合でも、`k = 1`、ほぼすべての数値が有効なので、まだ大まかにスキャンするだけです`x`数字。 これにより、制約の下でもアプローチが十分に効率的になります。 

より高度な組み合わせ最適化や数値 DP は必要ありません。数えたり、答えに直接ジャンプしたりする必要はなく、制限されるまで列挙するだけであるためです。

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`cnt = 0`そして反復を開始します`i`1から上へ。 定義は増加する自然数に依存するため、順序が必要です。 
2. 数字ごとに`i`、シーケンスに含めるかどうかを決定します。 まず確認してください`i % k == 0`。 これはすべての倍数を捕捉します`k`数字処理なしで直接。 
3. 割り算によってまだ含まれていない場合は、数字が含まれているかどうかを確認します。`k`に登場する`i`の 10 進数表現。 これは変換することで実現できます`i`文字列に変換し、文字のメンバーシップを確認する`str(k)`。 
4. いずれかの条件が成立する場合、インクリメントします。`cnt`by 1. シーケンスでは各有効な数値が 1 回だけカウントされるため、両方の条件が真である場合でも、この増分は数値ごとに 1 回だけ発生することが重要です。 
5. いつ`cnt == x`、すぐに出力`i`そしてやめてください。 これにより、x 番目の有効な数値が昇順で返されることが保証されます。 

### なぜ効果があるのか

 アルゴリズムは単純な不変式を維持します。次のとおりです。すべての整数を処理した後、`i`、カウンター`cnt`の整数の数と正確に等しくなります`[1, i]`ルールを満たすもの。 昇順にスキャンし、候補をスキップすることはありません。`cnt`到達する`x`、 現在`i`は、少なくとも次のような最小の数です。`x`有効な数値は ≤ です`i`。 これは、順序付けされたシーケンスの x 番目の要素の定義と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k, x = map(int, input().split())
    target = str(k)

    cnt = 0
    i = 0

    while True:
        i += 1
        if i % k == 0 or target in str(i):
            cnt += 1
            if cnt == x:
                print(i)
                return

if __name__ == "__main__":
    solve()
```実装は直接シミュレーション戦略に従います。 変数`target`の数字形式を格納します`k`したがって、繰り返し再計算することは避けます。 ループはインクリメントします`i`必要な数に達するまで無期限に。 会員テストは`target in str(i)`数字の状態をきれいに捉えます。 

微妙な点は、インクリメントすることです。`cnt`1回につき1回のみ`i`両方の条件が真である場合でも。 の`if`ステートメントは使用します`or`、正確性を保証します。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。`k = 1`。 この場合、すべての数値は 1 で割り切れるので、シーケンス全体は単なる自然数になります。 アルゴリズムはこれを即座に処理します。すべての反復で次の条件が満たされます。`i % 1 == 0`、 それで`cnt`は毎回増加し、その答えは`x`単純に`x`。 

もう 1 つのケースは、数字の包含が可算性を支配する場合です。 たとえば、`k = 9`、19、29、39 などの数値は、9 で割り切れない場合でもすべて対象となります。条件が単純な OR であるため、シミュレーションは引き続き機能します。そのため、有効とされる理由の数に関係なく、各数値は 1 回カウントされます。 

最後の微妙なケースは、次のようなオーバーラップです。`k = 3`OR 条件により二重カウントが防止されるため、アルゴリズムにより正確さが保証されます。 割り切れる可能性と数字の存在が両方とも真である場合でも、カウンターは整数ごとに 1 回だけ増加し、シーケンスの正確な構造が維持されます。
