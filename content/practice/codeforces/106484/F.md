 ## 解決策
 ## 問題の理解

 上から下に並べられた大文字のスタックが与えられます。 タスクは、現在の一番上のカードまたは現在の一番下のカードを繰り返し削除し、その選択したカードを新しいシーケンスの最後に追加することによって、これらのカードを新しいシーケンスに再構築することです。 目標は、辞書編集上可能な限り最小の最終文字列を生成することです。 

重要な制約は、各ステップで選択肢が 2 つだけであり、文字が取得されると、その文字は結果の最後に永続的に配置されることです。 これは、早期の決定が世界全体でのより良い結果を妨げる可能性があることを意味するため、貪欲な選択は慎重に正当化される必要があります。 

入力サイズは最大 500,000 枚のカードまで可能です。 これにより、考えられるすべての選択や後戻りをシミュレートするソリューションは即座に除外されます。 O(n^2) のアプローチでも、あまりにも遅すぎます。 各文字を一定の回数、または最悪の場合対数的に処理するものが必要です。 

微妙な失敗例は、上部と下部の局所的な比較が不十分な場合に発生します。 たとえば、上が「B」で下が「A」の場合、「A」を取るのが正しいように見えます。 ただし、実際の決定は、これらの手紙の背後にあるものによって異なります。 一方を選択した後に残った接尾辞が辞書編集的に悪い場合、単純な貪欲な選択は破綻します。 

小さなイラスト:

 入力:

 A B C D E

 常に両端のうち小さい方を選択すると、次のような場合に間違って選択する可能性があります。 

A ... Z 対 A ... Y

 正しい決定は、現在のエンドポイントだけでなく、より詳細なサフィックスの比較に依存します。 

## アプローチ

 ブルートフォース戦略では、左端または右端から選択するすべての可能なシーケンスが試行されます。 各状態は 2 つの可能性に分岐し、高さ n の二分決定木を形成します。 これにより、2^n 通りの結果が考えられ、それぞれの構築と比較に O(n) 時間がかかり、n が約 30 の場合でも天文学的に大きくなります。 

問題の構造は貪欲なアプローチを示唆していますが、問題は 2 つのエンドポイントだけを比較するだけでは十分ではないことです。 正しい決定は、片側を削除した後の残りの間隔が辞書編集的にどちらが小さいかによって決まります。 

重要な観察は、残りの間隔の接尾辞である 2 つの候補文字列を常に比較していることです。 両方を完全に具体化する代わりに、2 つのポインタを使って内側に進むことで、それらをゆっくりと比較できます。 各ステップで、現在の左右の候補を、片側から一貫して取得することによって形成されたシーケンスとして辞書編集的に比較します。 この比較は、完全な文字列を構築しなくても実行できます。 

これは戦略につながります。各ステップで、左から取得するか右から取得することで辞書編集的により小さい残りの構造が生成されるかを決定し、その選択にコミットします。 比較自体は、差異が見つかるまでポインタを内側に進める可能性があります。 

これにより、指数関数的な分岐が線形スキャンに減り、プロセス全体で償却される時折の線形比較が行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 最適 | O(n) 償却 | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 2 つのポインターを維持します。1 つは残りの間隔の左端に、もう 1 つは右端にあります。 各ステップで、左から取るか右から取るかを決定します。

1. 2 つのインデックス l = 0 および r = n - 1、および空の結果文字列を初期化します。 これらのポインターは、現在利用可能なカードの間隔を表します。 
2. l ≤ r の場合、2 つの候補シーケンスを検討します。1 つは左からの取得で開始し、もう 1 つは右からの取得で開始します。 目標は、どの選択が辞書編集的により小さな最終結果につながるかを決定することです。 
3. 2 つのオプションを比較するために、一時ポインター l2 = l、r2 = r を使用して「先読み比較」をシミュレートします。 私たちは文字を貪欲に比較します。s[l2] と s[r2] が異なる場合、どちらが優れているかすぐにわかります。 それ以外の場合は、l2 をインクリメントし、r2 をデクリメントすることで内側に移動します。 
4. ある時点で左の文字が右の文字より小さい場合、左から取得すると辞書編集結果が小さくなるため、結果に s[l] を追加して l をインクリメントします。 
5. 右の文字の方が小さい場合は、右から取得して s[r] を追加し、r を減分します。 
6. 違いが見つからずに比較を完了した場合 (残りのセグメントは事実上対称です)、どちらの側からでも安全に取ることができます。 決定論を確実にするために、一貫して左を選択します。 
7. すべての文字が消費されるまで繰り返します。 

重要な部分は比較ステップです。 これは単純な一定時間の決定ではありませんが、プロセス全体を通じて、各ポインターの移動は償却された意味で位置ごとに 1 回だけ発生します。 

### なぜ効果があるのか

 このアルゴリズムは、どのステップでも、残りの間隔が部分的に構築された結果の可能なすべての継続を表すという不変条件を維持します。 left-first 構造と right-first 構造を比較するとき、同じ間隔の互いに素ではあるが相補的な走査から形成された、辞書編集的に順序付けられた 2 つのシーケンスを比較していることになります。 内向き比較の最初の不一致によって、どの選択がより小さいグローバル文字列につながるかが決まります。 辞書編集上の順序は異なる位置の最も早い順に決定されるため、一度決定されると、その後の操作では最初の不一致と矛盾することなくそれを元に戻すことはできません。 これにより、各貪欲な選択が残りのサフィックスに対してグローバルに最適であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = [input().strip() for _ in range(n)]
    
    l, r = 0, n - 1
    res = []

    while l <= r:
        i, j = l, r
        take_left = False

        while i <= j:
            if s[i] < s[j]:
                take_left = True
                break
            elif s[i] > s[j]:
                take_left = False
                break
            i += 1
            j -= 1

        if i > j:
            take_left = True

        if take_left:
            res.append(s[l])
            l += 1
        else:
            res.append(s[r])
            r -= 1

    sys.stdout.write("".join(res))

if __name__ == "__main__":
    solve()
```このコードは、2 ポインター構造を直接実装しています。 内側のループは、可能な 2 つの方向間の辞書編集的な比較を実行します。 変数`take_left`は決定結果をエンコードし、それが決定されると、エンドポイントを 1 つだけ消費して間隔を縮小します。 

よくある微妙な間違いは、次の場合に等号の場合を忘れることです。`i > j`これは、両側が残りの中央まで同一であることを意味します。 この場合、どちらを選択しても安全ですが、一貫して左を選択することで曖昧さが回避され、確定的な出力が保証されます。 

もう 1 つの重要な詳細は、アルファベット順に一致する Python の単一文字列の辞書編集順序に依存して、文字を文字列として直接比較することです。 

## 実用的な例

 ### 例 1

 入力:

 A B C

 l = 0、r = 2 から始めます。 

| l | r | 比較 (i, j) | 決定 | 結果 |
 | --- | --- | --- | --- | --- |
 | 0 | 2 | A vs C | A < C | 左折 |
 | 1 | 2 | B vs C | B < C | 左折 |
 | 2 | 2 | C | 1 つだけ | 左折 |

 結果はABCになります。 

このトレースは、シーケンスが増加する場合、アルゴリズムは一貫して左側を優先することを示しています。これは、左側の方が辞書順でより小さい文字につながるからです。 

### 例 2

 入力:

 B A C B

 l = 0、r = 3 から始めます。 

| l | r | 比較 (i, j) | 決定 | 結果 |
 | --- | --- | --- | --- | --- |
 | 0 | 3 | B 対 B、A 対 C | A < C | 左折 |
 | 1 | 3 | A vs B | A < B | 左折 |
 | 2 | 3 | C vs B | C > B | 右を取る |
 | 2 | 2 | C | 1 つだけ | 左折 |

 結果はA A B Cになります。 

この例は、アルゴリズムがエンドポイントに対して純粋に貪欲ではないことを示しています。 B が右側にある場合でも、より詳細に比較すると、最初に左側を選択すると、最終的な接尾辞が小さくなることがわかります。

 ## 特殊なケース

 残りの文字がすべて同一である場合、内部比較では違いが見つからず、最終的にポインタが交差します。 その場合、アルゴリズムは一貫して左から選択します。 たとえば、入力 A A A A は、i > j まで同点比較を繰り返し、その後は毎回左が選択され、AAAA が得られます。 

最初の異なる文字が間隔の奥深くに出現すると、アルゴリズムはその不一致が見つかるまで決定を正しく延期します。 たとえば、B A A A C と C A A A B では、決定的な比較の前に複数の等価ステップが発生し、エンドポイントではなく最も古い辞書編集上の差異に基づいて正しい側が選択されるようになります。
