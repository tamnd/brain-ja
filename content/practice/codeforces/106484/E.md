 ## 解決策
 ## 問題の理解

 2 人の旅行者が反対側の端から開始する有向重み付きグラフが与えられます。1 人はノード 1 から始まり、もう 1 人はノード n から始まります。 普通に歩いた場合、各エッジにはスタミナコストがかかります。 歩くことに加えて、エッジに沿って「タクシー」するオプションもあります。共有予算の 1 単位を支払うと、そのエッジのスタミナ コストが完全に削除されます。 

2 人の旅行者は独立して移動し、タクシー オプションをいつ使用するかを自由に選択できます。 両方のタクシーの合計利用回数が w を超えることはできません。 彼らの目標は、どこかのノードで会うことであり、私たちは予算を最適に使用した後、両方の旅行者が費やす合計スタミナを最小限に抑えたいと考えています。 

入力は複数のテスト ケースを記述します。 各テスト ケースでは、すべてのテスト全体で合計最大約 1,000 個のノードとエッジを含むグラフが得られ、予算 w は最大 1,000 になります。エッジの重みは大きくなる可能性がありますが、追加または削除されるだけであるため、問題の構造は、算術的な複雑さではなく、割引のために選択されたエッジの数によって決まります。 

単純な解釈では、1 からある会議ノード v までと、n から同じ v までの 2 つのパスを選択し、最大 w 個のクーポンを使用してこれらのパスに沿ったどのエッジを解放するかを決定しているということになります。 

最善の戦略が常に独立して最短パスを選択し、クーポンを貪欲に適用することであると仮定すると、微妙な問題が発生します。 パスの選択は、どのエッジを割り引く予定であるかによって決まるため、これは失敗します。 重いエッジは、クーポンに選択すると空きになるため、たとえベース パスの長さが長くなったとしても、配線する価値があるかもしれません。 

2 番目の明白ではない失敗例は、グラフ内の最大のエッジに常にクーポンをグローバルに適用する必要があると仮定している場合です。 選択したパスで実際に使用されているエッジのみが割引の対象となるため、これは不正確です。 

## アプローチ

 ブルートフォース戦略では、1 からすべてのノードへ、および n からすべてのノードへのすべての可能なパスを列挙しようとし、パスのペアごとに、両方のパスにわたる最大のエッジの重みを選択することによって、最大 w クーポンを適用する最適な方法を計算します。 単純なパスに限定したとしても、可能なパスの数は n で指数関数的に増加するため、このアプローチは実行不可能になります。 

重要な構造的観察は、2 つのパスと会議ノードが固定されると、クーポンの効果が順序とは無関係になるということです。使用された各クーポンは、どちらかのパスで選択された 1 つのエッジをコスト 0 に変えるだけです。 したがって、固定パスの場合は、それに沿ったエッジの重みのマルチセットのみを考慮します。 

これは、問題を次のように再構成することを示唆しています。パスを修正した後にどのエッジを割引くかを明示的に選択する代わりに、クーポンの使用状況をパスの状態自体に組み込むのです。 1 つのパスについて、これまでに使用したクーポンの数を追跡し、クーポンを使用するか、スタミナ コストを通常どおり支払うかをエッジごとに決定します。 

これにより、各単一ソース問題が、拡張された状態空間上の最短経路問題に変換されます。ここで、状態は、ノードと既に使用されているクーポンの数で構成されるペアです。 

この動的な最短パスをノード 1 から実行して、使用済みクーポンのすべての可能な数を持つすべてのノードに到達するための最良のコストを取得し、ノード n からも同じことを実行します。 次に、考えられるすべての会議ノードを試し、2 人の旅行者の間で予算を分割します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パスを列挙し、後でクーポンを割り当てる | 指数 | 指数 | 遅すぎる |
 | クーポン数を含む状態展開された最短パス | O((n + m) · w) | O(n・w) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に扱います。

1. グラフとその反転バージョンを作成します。 反転グラフは、ノード n がソースであるかのようにノード n からの距離を計算するために使用されます。これは、その計算ではエッジを後方にトラバースする必要があるためです。 
2. 順方向プロセスの距離テーブルを定義します。ここで、dp1[v][k] は、ちょうど k 個のクーポンを使用しながらノード 1 からノード v に到達するための最小スタミナ コストを表します。 この状態が必要なのは、異なる残りの予算配分で同じノードに到達する可能性があり、それらが将来の異なる可能性につながるためです。 
3. dp1[1][0] = 0 およびその他すべての状態を無限として初期化します。 次に、状態 (ノード、使用済みクーポン) に対して最短パス プロセスを実行します。 コスト z のエッジ u → v に沿った遷移は 2 つの方法で機能します。 クーポンを使用しない場合は、コスト z を追加して dp1[u][k] から dp1[v][k] に移動します。 クーポンを使用し、k + 1 ≤ w の場合、追加コストなしで dp1[u][k] から dp1[v][k + 1] に移動します。 
4. 逆グラフのノード n から同じプロセスを繰り返し、k 個のクーポンを使用して n から v までの最良のコストを表す dp2[v][k] を生成します。 
5. 各ノード v について、2 人の旅行者間の予算のすべての分割を試みます。 最初のクーポンが k 個のクーポンを使用し、2 番目のクーポンが t 個のクーポン (k + t ≤ w) を使用する場合、合計コストは dp1[v][k] + dp2[v][t] になります。 すべての v とすべての有効な分割の最小値を取得します。 
6. どのノードも到達可能な状態がない場合、答えは -1 です。 

これが機能する決定的な理由は、クーポンの使用がエッジに対して完全にローカルであり、グローバル カウント制約を介する場合を除いて、パスの異なる部分間で相互作用しないためです。 クーポン カウントを状態に埋め込むことで、最適なサブ構造が保存されます。k 個のクーポンが使用されているノードに到達する最良の方法は、互換性のあるクーポン使用量を持つ初期の最適なサブパスのみに依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    T = int(input())
    for _ in range(T):
        n, m, w = map(int, input().split())
        g = [[] for _ in range(n + 1)]
        rg = [[] for _ in range(n + 1)]

        for _ in range(m):
            x, y, z = map(int, input().split())
            g[x].append((y, z))
            rg[y].append((x, z))

        def dijkstra(source, graph):
            dp = [[INF] * (w + 1) for _ in range(n + 1)]
            dp[source][0] = 0

            import heapq
            pq = [(0, source, 0)]

            while pq:
                dist, u, k = heapq.heappop(pq)
                if dist != dp[u][k]:
                    continue

                for v, z in graph[u]:
                    if dp[v][k] > dist + z:
                        dp[v][k] = dist + z
                        heapq.heappush(pq, (dp[v][k], v, k))

                    if k < w and dp[v][k + 1] > dist:
                        dp[v][k + 1] = dist
                        heapq.heappush(pq, (dist, v, k + 1))

            return dp

        dp1 = dijkstra(1, g)
        dp2 = dijkstra(n, rg)

        ans = INF
        for v in range(1, n + 1):
            for k in range(w + 1):
                if dp1[v][k] == INF:
                    continue
                for t in range(w - k + 1):
                    if dp2[v][t] == INF:
                        continue
                    ans = min(ans, dp1[v][k] + dp2[v][t])

        print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```この実装では、拡張状態に対して優先キューを使用します。 各状態には、現在のノードとこれまでに使用されたクーポンの数が保存されます。 重要な実装の詳細は、各エッジが 2 つの緩和を生成することです。1 つはクーポンを消費せず、エッジの重みによってコストを増加させるもので、もう 1 つはクーポンを消費し、クーポン数を増加しながらコストをゼロに追加するものです。 

よくある間違いは、クーポンの使用により状態の次元が変化すること、つまり、異なる k 値で同じノードを再訪することが不可欠であることを忘れていることです。 dp をノードごとに 1 つの配列に集約すると、最適なソリューションが失われます。 

## 実用的な例

 ノード 1 がコスト 5 で 2 に接続し、ノード 2 がコスト 5 で 3 に接続し、ノード n が 3 である小さなグラフを考えます。w = 1 であると仮定します。 

ノード 1 からノード 3 に到達するには、2 つの可能性があります。クーポンがない場合はコスト 10 が生成され、どちらかのエッジで 1 つのクーポンを使用するとコスト 5 が生成されます。ノード 3 の dp テーブルはこれら 2 つの状態を反映しています。 

ノード 3 からノード 3 自体に戻ると、dp2[3][0] = 0 になります。 

| ステップ | ノード | 使用済みクーポン | コスト |
 | --- | --- | --- | --- |
 | 開始 | 1 | 0 | 0 |
 | 1→2ノーマル | 2 | 0 | 5 |
 | 2→3クーポン | 3 | 1 | 5 |

 このトレースは、クーポンの使用を分割することで到達可能なコストがどのように変化するかを示しています。 

次に、2 つの会議オプションを含む 2 番目の例を考えてみましょう。 ノード 1 が 2 と 3 の両方に接続し、両方が異なる重みで n に接続する場合、アルゴリズムは両方の会議ノードを独立して正しく評価し、順方向状態と逆方向状態を組み合わせます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) · w + n · w²) | 2 つの状態ダイクストラが実行 (ノード、クーポン) し、さらに会議ノードをマージします。 
| スペース | O(n・w) | 前進距離と後進距離の DP テーブル |

 この制約により、n、m、w は約 1000 に保たれるため、拡張された状態空間は数百万遷移程度にとどまります。これは、優先キュー実装を備えた Python の制限内に十分収まります。

 ## 特殊なケース

 エッジケースの 1 つは、両方の旅行者が、すべてのクーポンを集合場所の片側に集中させることで恩恵を受ける場合です。 分割ループでは一方の側で k = 0 から w を許可し、もう一方の側で独立して補償するため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、クーポンの使用状況に応じて最適なパスが変化する場合です。 直接の高コストエッジは、クーポンが利用可能な場合にのみ最適になる可能性があります。 DP では異なるクーポン カウントを通じて同じノードに到達でき、同じ位置の異なる「バージョン」を効果的にエンコードできるため、これは正しく処理されます。 

最後のエッジ ケースは、前方または後方の DP がノードに到達しない、切断されたグラフです。 これらの状態は無限のままであり、最終的な最小値を計算するときに当然無視され、有効な会合点が存在しない場合には -1 が生成されます。
