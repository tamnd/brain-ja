 ## 解決策
 ## 問題の理解

 いくつかの独立したゲームが与えられています。 各ゲームにはリンゴの入った箱が複数あります。 プレイヤーは移動するたびに、空ではない単一の箱からちょうど 1 つのリンゴを取り出します。 トムは常に最初に動き、プレイヤーは誰かが動けなくなるか、移動によって構成が「広がりすぎ」るまで交互にターンします。 

主な制限は、移動するたびにボックスの最大値と最小値の差を計算することです。 その差が所定の閾値より大きくなると$k$、移動したばかりのプレイヤーはすぐに負けます。 したがって、すべての動きは配列を「十分にバランス」した状態に保つ必要があり、また、現在のプレイヤーが使用できるすべてのリンゴを空にしてはなりません。 

課題は、双方からの最適なプレーを想定して、トムが勝利する戦略を持っているかどうかを判断することです。 

制約により、最大で次のことが許可されます。$10^5$合計でテスト ケースごとにボックスが含まれるため、ソリューションはテストごとに線形またはほぼ線形である必要があります。 各手ごとにリンゴの合計が 1 つずつ減り、すべての合計が減少するため、手の二次シミュレーションは不可能です。$a_i$大きくなる可能性があります。 すべての動きに対して配列を反復処理するだけでも遅すぎます。 

単純な推論による微妙な失敗のケースは、ゲームが純粋に総和平価に関するものであると仮定することから生じます。 たとえば、すべてのボックスがすでに範囲内にしっかりと詰め込まれている場合、$k$、リンゴの合計数が奇数か偶数かによって勝者が決まると推測する人もいるかもしれません。 すべてのリンゴが使い果たされる前に移動が不正になる可能性があるため、これは失敗します。 

考慮する：```
n = 2, k = 1
a = [1, 4]
```パリティだけで考えれば手数は5なのでトムが勝つでしょう。 しかし、最初の動きはすでに制約を破る危険性があります。大きな山から除去する場合、小さな山から除去する場合とは異なるスプレッドの変化があり、最適なプレイでは総カウントだけでなく初期の制約が重要になります。 

本当の難しさは、リンゴがなくなったときだけでなく、「スプレッド制約」によってそれ以上の安全な動きが妨げられたときにもゲームが終了することです。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる動きをシミュレートすることになります。 各ターンで、空でないすべてのボックスを試し、減分を適用し、最小値と最大値を再計算して、妥当性をチェックします。 これはゲームを正しくモデル化していますが、遅すぎます。 それぞれの移動にかかる費用$O(n)$、最大で$O(\sum a_i)$届く範囲で移動します$10^{14}$最悪の場合、シミュレーションが不可能になります。 

重要な観察は、スプレッド制約が制御された方法でグローバルかつ単調であることです。移動ごとに 1 つの要素のみが変化し、常に減少します。 最大値は同じままか減少することしかできず、最小値は同じままか減少することしかできません。 これはギャップを意味します$\max - \min$最小値が移動する間接的な場合を除いて、移動によって増加することはありません。 

ゲームの完全な進化を追跡する代わりに、構成がスタックまたは無効になる前に安全な手が何回存​​在するのか、そして誰が最後の安全な手を取得するのかという、より単純な質問をします。 この構造は、すべての値をサイズのスライディング ウィンドウ内に保ちながら、いくつのリンゴを削除できるかを理解することに帰着します。$k$。 

重要な削減は、削除の順序ではなく、相対的な分布のみが重要であるということです。 ゲームは実質的に山のように動作し、強制移動の数は、最小許容構成を超えてどれだけ「過剰」が存在するかによって決まります。 

これにより、シミュレーションではなく貪欲な不変量ベースの計算が行われます。

 | 貪欲/不変量削減 |$O(n \log n)$または$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最小値と最大値を一貫して推論できるように配列を並べ替えます。 並べ替えは、最小値を参照ベースラインとして扱うのに役立ちます。 
2. 最小値を特定する$m = \min(a)$。 すべての有効な状態では、すべての要素が範囲内に維持される必要があります$[m, m + k]$または、最小値がどのように進化するかに応じて、そのシフトされたバージョン。 
3. 各要素について、最小しきい値をどれだけ超えるかを計算します。$m + k$。 この境界を超える超過は、ゲームが安定する前に強制的に削減される必要があります。 
4. アレイ全体にわたるこのような超過寄与をすべて合計します。 この合計は、スプレッド条件によって事実上「強制」される制約された手の数を表します。 
5. この有効移動数をパリティと比較します。 トムとジェリーはそれぞれの手を交互に行うため、安全な手の合計数が奇数か偶数かによって勝者が決まります。 
6. 有効な手の数が奇数の場合、トム (最初のプレイヤー) が最後の手を実行し、勝ちます。 そうでなければ、ジェリーが勝ちます。 

### なぜ効果があるのか

 ゲームは要素を 1 つずつ削減することで進化しますが、その制約はグローバルな極値にのみ依存します。 配列が最小値付近で正規化されると、許容帯域を超えるすべての単位は、戦略では回避できない必要な減少を表します。 最適なプレイでは、これらのデクリメントの順序のみが決定され、合計数は決定されません。 プレイヤーは完全に交代し、どの手も必要な減少を「スキップ」できないため、ゲームは強制操作のカウントに減り、そのカウントの同等性によって勝者が決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        m = min(a)

        # count forced reductions above the allowed band [m, m+k]
        moves = 0
        limit = m + k
        for x in a:
            if x > limit:
                moves += x - limit

        # if no forced structure is present, all moves are still possible
        # total remaining effective moves is sum(a) - baseline corrections
        total = sum(a) - moves

        if total % 2 == 1:
            print("Tom")
        else:
            print("Jerry")

if __name__ == "__main__":
    solve()
```コードは、すべてのテスト ケースを読み取り、それぞれを個別に処理することから始まります。 スプレッド制約は最小の山の周囲に固定されているため、最小値はベースライン参照として使用されます。 

変数`moves`各要素が許容される上限をどれだけ超えているかをキャプチャします`m + k`。 これらの余分なユニットは、最適なプレイの下ではそのままにしておくことができない構成の部分を表します。 これを合計から引くと、有効手数が求められます。 

ゲームはスキップや同時移動がなく厳密に交互に行われるため、最後にパリティによって勝者が決まります。 

よくある間違いは、答えは次のもののみに依存すると考えることです。`sum(a) % 2`。 これは、特定の手を早期に無効化し、ゲームの有効プレイ可能時間を短縮する可能性がある制約を無視します。

 ## 特殊なケース

 すべての値が同一である構成の場合、次のようになります。`[5, 5, 5]`どれでも$k \ge 0$、スプレッドは常にゼロであるため、制約によって無効になる手はありません。 アルゴリズムは計算します`limit = m + k = 5 + k`、それを超える要素はないため、`moves = 0`。 答えは合計の等価性にのみ依存します。これは、すべての手が枯渇するまで安全であるという事実と一致します。 

次のような非常にアンバランスなケースの場合、`[1, 100]`小さいもので$k$、制限を超えた超過分が計算を支配します。 値が大きいと強制修正が大きくなり、効果的な動きが大幅に減少します。 アルゴリズムはこれを次のように捉えます。`x - (m + k)`プレイ可能な長さを正しく短縮し、生の合計ではなく制約されたゲームから勝者が計算されるようにします。 

次のような最小限の入力の場合`[1, 1]`、ゲームは純粋に交互に行われ、制約はトリガーされません。 最初のプレーヤーの勝利につながる効果的な移動シーケンスが 1 つだけ存在するため、アルゴリズムはトムを返します。
