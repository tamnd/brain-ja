 ## 解決策
 ## 問題の理解

 長方形の LED マトリックスと、それを右から左にスクロールする長方形のパターンが与えられています。 マトリックスの次元は固定されており、各セルは機能しているか壊れています。 機能している LED は点灯しますが、壊れた LED は点灯しません。 

パターンは同じ高さのグリッドですが、幅が異なる場合があります。 スクロールすると、パターンはマトリックス上で水平方向に繰り返し移動します。 シフトごとに、パターンの垂直スライスがマトリクスの一部の列と位置合わせされ、特定のパターン セルでは、その時点で対応するマトリクス LED がオンになる必要があります。 

重要な問題は、アニメーションをシミュレートすることではなく、スクロール プロセス全体の中で壊れた LED を点灯する必要がある瞬間が存在するかどうかを判断することです。 そうなった場合は表示不可能なので答えは「N」、そうでない場合は「Y」となります。 

入力は、行ごとに、行列の状態とパターン行の両方を記述します。 制約が行間で独立しているため、この行ごとの結合が重要になります。各行は、行列の列とパターンの列の間の 1D 相互作用のように動作します。 

行、列、パターン幅の境界は最大 1000 です。 行、行列の列、およびシフトにわたる三次シミュレーションは約 10^9 の演算に達しますが、これでは遅すぎます。 シフトごとに二重にネストされたスキャンでも大きすぎるため、ソリューションでは各スクロール ステップを明示的にシミュレートすることを避ける必要があります。 

パターンがマトリックスよりも小さい場合、微妙なエッジ ケースが表示されます。 それでも、スクロールは完全なオーバーラップを超えて継続します。これは、パターン列が時間の経過とともに多くのマトリックスの位置に揃う可能性があることを意味します。 もう 1 つのエッジ ケースは、セルが壊れているが、パターンでは「初期」位置合わせでセルがずれていればよいだけである場合です。 後のシフトでも有効になる可能性があります。 これはまさに、1 つのアライメントだけを調べる単純なチェックが不正確になる原因です。 

## アプローチ

 強引なアイデアは、すべてのスクロール位置をシミュレートすることです。 シフトごとに、マトリックス上にパターンを配置し、重なっているセルをすべてチェックします。 パターンセルの場合、`*`マトリックスセルに着地します。`-`、失敗します。 

これは、アニメーションのすべての状態を明示的にチェックするため、正しいです。 ただし、シフト数はマトリックス幅とパターン幅の合計に比例し、各シフトで最大 R×C セルがチェックされます。 これにより、およそ O(R・C・(C+K)) 個の演算が行われますが、これはすべての次元が 1000 に達すると制限をはるかに超えます。 

重要な観察は、パターン セルが行列セルにいつヒットするかを実際に知る必要はなく、実際にヒットするかどうかだけを知る必要があるということです。 固定行と固定行列列については、もっと簡単な質問をすることができます。`*`スクロール中にパターン行がこのマトリックスの位置と一致することはありますか?

 このように問題を書き直すと、時間の次元はなくなります。 各行列セルは、そのセルにマップされるパターン列が少なくとも 1 つ存在するかどうかだけを知る必要があります。 これはパターン行に対する範囲存在クエリとなり、プレフィックスの合計で答えることができます。 

これにより、問題は、すべての行列セルについて、対応する配列間隔に少なくとも 1 つの配列が含まれているかどうかをチェックするだけになります。`*`パターンで。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(R・C・(C+K)) | O(1) おまけ | 遅すぎる |
 | プレフィックス範囲のチェック | O(R・(C+K)) | O(R・K) | 承認済み |

 ## アルゴリズムのチュートリアル

 行は相互作用しないため、各行を独立して処理します。 

1. 固定行の場合、各位置にいくつ格納されているパターン行のプレフィックス合計を事前計算します。`*`文字はそのインデックスまで表示されます。 これにより、高速な範囲クエリが可能になります。 
2. マトリックスの各列について`c`、フルスクロール中にどのパターン列をそれに合わせることができるかを決定します。 このセットは、パターン行内で連続した間隔を形成します。 
3. この間隔の左側の境界を計算します。 パターン列`j`マトリックスの列に到達できる`c`スクロールによって所定の位置に移動した場合`c`、これは、間の単純な線形関係を意味します。`c`そして`j`。 これにより、下限が減ります。`j`。 
4. この間隔に何かが含まれている場合は、`*`パターン行、次にマトリックスセル`(row, c)`機能的である必要があります。 マトリックス セルが壊れている場合、構成は直ちに無効になります。 
5. すべての行とすべての列について繰り返します。 矛盾がなければ表示可能です。 

### なぜ効果があるのか

 各パターン セルは、スクロール中に占有できるマトリックス セルにのみ制約を与えます。 動きは純粋に線形であるため、各パターン列は連続する範囲の行列列に影響を与えます。 つまり、各行列セルは、必須オン パターン セルがそれにマップされるかどうかだけを知る必要があります。 このようなマッピングが存在し、行列セルが壊れている場合、その要件は決して満たされないため、正確性はそのような禁止された交差を検出することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    R, C, K = map(int, input().split())

    mat = []
    pat = []

    for _ in range(R):
        line = input().split()
        mat.append(line[0])
        pat.append(line[1])

    for i in range(R):
        # prefix sum of '*' in pattern row
        pref = [0] * (K + 1)
        for j in range(K):
            pref[j + 1] = pref[j] + (1 if pat[i][j] == '*' else 0)

        for c in range(C):
            if mat[i][c] == '*':
                continue

            # earliest pattern column that can reach c
            L = max(0, c - (C - 1))

            # check if there is any '*' in pat[i][L:K]
            if pref[K] - pref[L] > 0:
                print("N")
                return

    print("Y")

if __name__ == "__main__":
    solve()
```このソリューションでは、行列とパターンの両方を行ごとに読み取ります。 行ごとに、パターンに対してプレフィックスの合計を構築し、定数時間のチェックをサポートします。`*`サフィックスに存在します。 

壊れた行列セルごとに、そのセルに到達できる最も早いパターン インデックスが計算されます。 これは、シフトをシミュレートする代わりに、スクロールが線形であり、すべてのパターン列が行列列の連続範囲にわたってスイープするという事実を利用します。 必須オン パターン セルがその到達可能な範囲内にある場合、そのセルは無効になります。 

主要な実装の詳細は、次の計算です。`L = max(0, c - (C - 1))`。 これは、行列列に到達する可能性のある最も古いパターン列をエンコードします。`c`フルスクロール中。 

## 実用的な例

 1 行の小さな概念的な例を考えてみましょう。 

マトリックス:`* - -`パターン：`*-*`パターンのプレフィックスの合計は次のとおりです。`[0,1,1,2]`。 

列 1 の壊れたセルについては、次のように計算します。`L = max(0, 1 - 2) = 0`。 接尾語`[0:3]`には星が含まれているため、このセルはある時点で点灯する必要がありますが、壊れています。 アルゴリズムは正しく拒否します。 

次に、次のことを考えてみましょう。 

マトリックス:`* * *`パターン：`*-*`すべてのマトリックス セルは機能するため、パターンがどのように変化しても、故障状態はありません。 一部の配置には星が必要ですが、必要なセルはすべて有効です。

 ## 特殊なケース

 微妙なケースとしては、パターンに何も含まれていない場合があります。`*`全然。 この場合、マトリックス セルを点灯する必要はないため、完全に壊れたマトリックスでも有効です。 すべてのプレフィックス範囲クエリがゼロを返すため、アルゴリズムはこれを自然に処理します。 

もう 1 つの特殊なケースは、パターンがマトリックスよりも幅が広い場合です。 各行列セルの派生間隔は、実際に行列上をスイープできるパターンの部分のみをキャプチャするため、引き続き機能します。 特別な取り扱いは必要ありません。 

最後のエッジ ケースは、1×1 など、行列とパターンの両方が最小である場合です。 このアルゴリズムは、単一のプレフィックス チェックに削減され、互換性のある状態と互換性のない状態を正確に区別します。
