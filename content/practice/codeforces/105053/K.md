 ## 解決策
 ## 問題の理解

 複数の単語に分割されたフレーズが与えられ、各単語から接頭辞を取得し、これらの接頭辞を順番に連結することで頭字語を構築できます。 選択した各プレフィックスの長さは 1 ～ 3 文字にする必要があるため、すべての単語が最終的な文字列に少なくとも 1 文字、最大で 3 文字含まれます。 

結果として得られる頭字語は可読性の制約を満たす必要があります。つまり、左から右にスキャンされ、連続する 3 つの子音が決して含まれない場合に発音可能であるとみなされます。 母音はセット {A、E、I、O、U、Y} に固定されており、その他の大文字はすべて子音です。 

タスクは、単語ごとに 1 つのプレフィックス長を選択して、連結された結果が発音可能になり、全体の長さが最小限になるようにすることです。 そのような選択が存在しない場合は、失敗マーカーが出力されます。 

制約は合計すると大きくなり、すべての単語の合計文字数は 10^6 に達することがあります。 各単語には最大 3 つの選択肢があり、最大 3^N 通りの可能性があり、これは控えめな N の場合でも実行不可能であるため、これにより、考えられる接頭辞の組み合わせをすべて列挙しようとする解決策は即座に除外されます。 

微妙なエッジケースは、最初の文字がすでに強制的な子音の連続を作成している単語から発生します。 たとえば、複数の単語が子音で始まる場合、1 文字の接頭辞だけを選択しただけでもすでに制約に違反している可能性があります。 

もう 1 つの重要な例外ケースは、単語が非常に短い場合です。 単語の長さが 1 または 2 の場合、その接頭辞の選択肢は限られており、場合によっては、グローバル シーケンスを有効に保つことが不可能になる子音を取ることを余儀なくされることがあります。 

最後に、最も困難な失敗モードは、ローカルでは有効な接頭辞の選択肢がすべての単語に存在するが、グローバルではどのような組み合わせでも必然的に 3 つの子音の連続が作成される場合です。 単語ごとに最適化する素朴な貪欲なアプローチは、1 つの単語での決定がその後の子音の蓄積に影響を与えるため、ここでは失敗します。 

## アプローチ

 ブルートフォースアプローチでは、単語ごとに 1 から 3 までのプレフィックスの長さの可能な選択肢をすべて試し、結果として得られる頭字語を構築し、それが発音可能かどうかを確認します。 各チェックは結果の文字列を線形時間でスキャンします。 これにより、3^N 個の候補が生成され、それぞれに O(全長) の検証が必要になりますが、これは制限をはるかに超えています。 

重要な構造は、制約が子音に関して最大​​ 2 つの長さの現在の接尾辞にのみ依存するということです。 文字列の完全な履歴は考慮せず、処理された単語と次の接頭辞の間の境界に現在連続する子音がいくつあるかだけを考慮します。 

これは、単語に対する動的プログラミングを即座に示唆しており、状態は現在末尾にある子音の数を追跡し、上限は 0、1、または 2 です。3 番目の連続する子音を作成しようとする試みは無効であり、破棄されます。 

各単語で、接頭辞の長さ 1、2、または 3 を選択し、その単語が寄与する子音の数 (最初の数文字に応じて) を計算し、それに応じて DP 状態を移行します。 各単語の最初の最大 3 文字のみが重要であるため、各接頭辞の長さが子音の実行状態にどのような影響を与えるかを事前に計算します。 

DP は、各単語インデックスと後続の子音カウントについて、達成可能な最小全長を保持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^N・L) | O(L) | 遅すぎる |
 | 最適なDP | O(N・3・3) | O(N・3) | 承認済み |

 ## アルゴリズムのチュートリアル

 小さな状態空間を維持しながら、単語を左から右に処理します。

1. dp[i][c] が最初の i 単語を処理した後の最小合計長を表す DP テーブルを定義し、ちょうど c 個の連続する末尾子音で終わります。c は {0, 1, 2} にあります。 c ≥ 3 の状態は無効であり、保存されることはありません。 これにより、将来の意思決定に必要なすべての情報が取得されます。 
2. dp[0][0] = 0 を初期化します。これは、単語を処理する前には文字がなく、末尾の子音がゼロであるためです。 
3. 各単語 i について、考えられるすべての前の状態 dp[i][c] を考慮します。 状態に到達できない場合、その状態はスキップされます。 この状態から、{1, 2, 3} 内のすべてのプレフィックス長 len を試しますが、実際のワード長によって制限されます。 
4. 選択した接頭辞の長さ len について、単語の最初の len 文字を調べ、この接頭辞が追加された場合に後続の子音に寄与する数を計算します。 これは、接頭辞をスキャンし、ローカルの子音ストリークを更新することによって行われます。子音が検出されるたびに、カウンターがインクリメントされます。 母音が出現すると、それをゼロにリセットします。 結果として得られる最終的なストリークは、グローバル状態に適用される貢献です。 
5. 以前の末尾子音カウント c を、選択した接頭辞の寄与と組み合わせます。 境界を越えてストリークを継続することにより、連結をシミュレートします。プレフィックスが子音で始まり、c がゼロ以外の場合、ストリークは継続します。 それ以外の場合は、母音が出現したときに適切にリセットされます。 
6. いずれかの時点で、結果の末尾子音カウントが 2 を超えた場合、この遷移は破棄されます。 それ以外の場合は、最小コスト (dp[i][c] + len) で dp[i+1][new_c] を更新します。 
7. すべての単語を処理した後、答えは dp[N][0]、dp[N][1]、dp[N][2] の最小値になります。 すべてが到達できない場合は、不可能を出力します。 

正しさは、唯一の禁止パターンが 3 つの連続する子音であるという事実にかかっており、そのため、DP 状態は後続の子音を 2 つまで記憶するだけで済みます。 

## なぜ機能するのか

 今後の決定は最後の 1 文字か 2 文字が子音かどうかのみに依存するため、このアルゴリズムは頭字語の全履歴を一定サイズの状態に圧縮します。 同じ数の末尾子音で終わる 2 つの部分構造は、将来のすべての拡張子に対して交換可能です。これは、制約をチェックするときに将来の接頭辞が相互作用するのは最大 2 つの前の子音であるためです。 これにより、プレフィックスに対する有効な等価関係が得られ、DP の最適な部分構造が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

VOWELS = set("AEIOUY")

def is_vowel(ch):
    return ch in VOWELS

def run_word_prefix(word, start_state, length):
    c = start_state
    for i in range(length):
        if is_vowel(word[i]):
            c = 0
        else:
            c += 1
            if c >= 3:
                return -1
    return c

def solve():
    n = int(input())
    words = [input().strip() for _ in range(n)]

    INF = 10**18
    dp = [[INF] * 3 for _ in range(n + 1)]
    dp[0][0] = 0

    for i in range(n):
        word = words[i]
        m = len(word)

        for c in range(3):
            if dp[i][c] == INF:
                continue

            for L in range(1, min(3, m) + 1):
                nc = c
                ok = True
                for j in range(L):
                    if is_vowel(word[j]):
                        nc = 0
                    else:
                        nc += 1
                        if nc >= 3:
                            ok = False
                            break
                if not ok:
                    continue

                dp[i + 1][nc] = min(dp[i + 1][nc], dp[i][c] + L)

    ans = min(dp[n])
    if ans == INF:
        print("*")
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```DP テーブル`dp[i][c]`処理後に達成可能な最適な頭字語の長さを保存します`i`との言葉`c`末尾の子音。 この遷移では、最大 3 までの接頭辞の長さを列挙し、選択した接頭辞に対してのみ母音子音規則をシミュレートしながら、前の末尾の子音の状態を前に進めます。 

重要な実装の詳細は、複雑な接頭辞構造を事前計算しようとするのではなく、境界を越える子音のストリークを明示的にシミュレートしていることです。 プレフィックスの長さは最大 3 であるため、このシミュレーションは遷移ごとに一定時間になります。 

無限値は到達不可能な状態をマークするために使用され、最終的な答えはすべての有効な終了状態の最小値になります。 

## 実用的な例

 ### 例 1

 入力:```
3
KNUTH

```各単語の後に dp 状態を追跡します。 

| 私 | 単語 | c=0 | c=1 | c=2 |
 | --- | --- | --- | --- | --- |
 | 0 | 開始 | 0 | ∞ | ∞ |
 | 1 | クヌート | プレフィックスの後の小さな値 | ... | ... |
 | 2 | モリス | 更新されたトランジション | | |
 | 3 | プラット | 最終最小値 | | |

 有効な最適な構成は、「KMOP」を生成するプレフィックスを選択し、有効な最小長 4 を達成することです。長さ 3 に留まろうとする試みは失敗します。これは、何らかの境界で禁止された子音トリプルが強制されるためです。 

これは、単語ごとの局所的な選択がいかに十分でないかを示しています。 DP は、プレフィックス長のバランスをグローバルに調整するために必要です。 

### 例 2

 入力:```
2
KNUTH
M
PRATT
```「M」を処理した後、単一の子音単語が既存の子音ストリークを拡張する可能性があるため、DP はさらに制約されます。 「PRATT」を処理するときに、短いプレフィックスを保持しようとすると無効なストリークが発生し、より長いプレフィックスの選択が強制されます。 

DP は、3 つの連続する子音を作成する状態を拒否することで無効な遷移を正しく回避し、最終的には実行可能な最小限の構成を見つけます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | 各単語は最大 3 つのプレフィックス長と 3 つの状態を試行します。 
| スペース | O(N) または O(1) | サイズ 3 の DP レイヤーは 2 つだけ必要です。 

トランジションの合計数はワードごとに 9 に比例し、合計入力サイズはプレフィックス スキャンにのみ影響し、トランジションごとに 3 に制限されるため、アルゴリズムは制限内で快適に実行されます。

 ## 特殊なケース

 重大なエッジケースは、単語自体が 3 つの連続する子音で始まる場合です。 たとえば、「SCH」のような単語は、プレフィックス長 3 で取得するとすでに制約に違反しているため、アルゴリズムはそのプレフィックス長の選択を回避する必要があります。 DP は、当然のことながら、3 の連続を生成するトランジションを破棄することでこれを処理します。 

もう 1 つの特殊なケースは、すべて子音である一連の 1 文字の単語です。 K M P のような入力の場合、考えられる頭字語はすべて子音の連結にすぎず、長さが 3 以上のものは直ちに無効になります。 DP はすべての状態に到達できない状態で終了し、必要な障害出力が生成されます。 

最後に、母音がストリークを完全にリセットするケースが重要です。 子音の多い単語の間に「A」のような単語を挿入すると、状態が完全にリセットされ、より短い解決策が得られる可能性がありますが、貪欲な戦略では見逃しがちです。
