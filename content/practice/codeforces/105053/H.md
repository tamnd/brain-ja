 ## 解決策
 ## 問題の理解

 固定文字列と、それを繰り返し変換する一連の操作が与えられます。 各操作は、文字列の完全な反転、または左または右への一定量の循環回転のいずれかです。 これらの操作は順番に適用され、すべての操作後の最終文字列ではなく、操作リストのすべての連続セグメントに関心があります。 

演算のすべての部分配列に対して、概念的に元の文字列から開始して変換のブロックを適用し、最終的に元の文字列に正確に戻るかどうかを尋ねます。 タスクは、文字列を初期形式に戻すそのような部分配列の数を数えることです。 

主な問題点は、部分配列の数が演算数において 2 次であるため、各セグメントを明示的にシミュレートするアプローチは、演算数が 20 万に達すると直ちに遅すぎることです。 

文字列自体はクエリごとに独立して変更されるのではなく、参照オブジェクトとしてのみ機能します。 実際に重要なのは、各操作が文字列内の位置をどのように並べ替えるかです。 2 つの異なる操作シーケンスがインデックスに同じ効果をもたらす可能性があり、シーケンスが恒等順列を生成するたびに、結果の文字列が元の文字列と一致することが保証されます。 

単純な実装では、文字列の変換をシミュレートすることによって、すべての部分配列の完全な効果を再計算します。 これは、各シミュレーションが文字列の長さにおいて線形であり、全体的に三次的な動作につながるため、失敗します。 

各部分配列の後に文字列が等しいかどうかを直接比較しようとすると、さらに微妙な問題が発生します。 これも遅すぎて、文字列の等価性が基礎となる順列の等価性を直接反映しないため、文字列に繰り返し文字が含まれている場合に誤解を招く可能性があります。 

正しい見方は、各操作がインデックスの順列を引き起こし、これらの順列を合成しているということです。 問題は、恒等順列を生成するサブ配列の数を数えることになります。 

## アプローチ

 ブルート フォース アプローチでは、部分配列のすべての開始インデックスが考慮され、終了インデックスまで演算が繰り返し適用され、結果の文字列または順列が維持されます。 各サブ配列には線形時間がかかるため、最悪の場合、合計の複雑さは 3 次となり、限界をはるかに超えます。 

構造的な洞察は、すべての演算が文字列のサイズに等しい長さのサイクルの二面体群に属しているということです。 すべての変換は、文字列が反転されるかどうかを示す方向ビットと、インデックスがどれだけ回転されるかを示すシフト オフセットの 2 つの情報のみを使用して記述できます。 

これは、順列全体を追跡する必要がないことを意味します。 操作のプレフィックスごとにコンパクトな状態を追跡するだけで済みます。 2 つの接頭辞が同じ変換状態を生成する場合、それらの間の操作は恒等変換を構成します。これは、サブ配列が元の文字列を復元することを意味します。 

問題は、プレフィックスの状態を計算し、各状態が何回発生するかをカウントすることに帰着します。

 | ブルートフォース | O(K・N)以上 | O(N) | 遅すぎる |
 | プレフィックス状態ハッシュ | O(K) | O(K) | 承認済み |

 ## アルゴリズムのチュートリアル

 演算の各接頭辞をインデックスの変換としてモデル化します。 変換は常に「逆転の可能性と循環シフトを加えた」形式になります。 

ブール方向フラグとシフト値の 2 つの値を使用して状態を表します。 

### 1. ID 状態を初期化する

 何も操作を適用しない状態で開始します。 これは、文字列が変更されない恒等変換に対応するため、方向は正規でシフトは 0 です。 

### 2. 各操作が状態を更新する方法を定義する

 現在の状態を維持しながら、操作を 1 つずつ処理します。

右に回転すると、文字列が現在反転しているかどうかに関係なく、その量だけシフトが増加します。 左に回転すると、やはり方向とは無関係に、その量だけシフトが減少します。 これは、反転が循環シフトの蓄積方法ではなく、インデックスの解釈方法にのみ影響するため、機能します。 

反転すると、方向フラグが反転され、一貫した方法でシフトが変更されるため、変換は同じ標準形式で正しく表現されたままになります。 具体的には、反転は現在のアフィン変換をサイクルの周りのミラーにマッピングし、一定時間で更新できます。 

### 3. プレフィックスの状態を維持する

 操作を処理するとき、各接頭辞の後の状態を辞書に保存します。 それぞれの個別の状態は、元の文字列に適用されるインデックスの特定の並べ替えを表します。 

### 4. 等しいプレフィックス状態を数える

 2 つの接頭辞インデックス i と j が同じ状態を生成する場合、i+1 から j までの演算を適用すると、ネット恒等変換が行われます。 このようなすべてのペアは有効な部分配列に対応します。 

状態の頻度をカウントし、各頻度バケット内の組み合わせカウントを使用してペアの数を累積します。 

### 5. 合計数を出力します。 

最終的な答えは、周波数×周波数 -1 を 2 で割ったすべての状態の合計です。 

### なぜ効果があるのか

 すべての操作シーケンスは、合成が結合的で可逆的なグループ内の順列に対応します。 プレフィックスの状態は、その順列を完全に特徴づけます。 部分配列は、その端点が等しいグループ要素に対応する場合に正確に同一性を生成します。これは、等しいプレフィックス状態と同等です。 この全単射により、有効な部分配列を見逃したり、無効な部分配列をカウントしたりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    S = input().strip()
    n = len(S)

    K = int(input())
    
    # state: (dir, shift)
    # dir = 0 normal, 1 reversed
    d = 0
    s = 0

    from collections import defaultdict
    freq = defaultdict(int)
    freq[(0, 0)] = 1

    for _ in range(K):
        parts = input().split()
        op = parts[0]

        if op == 'I':
            # reverse
            d ^= 1
            s = (n - 1 - s) % n

        else:
            val = int(parts[1])
            if op == 'R':
                s = (s + val) % n
            else:
                s = (s - val) % n

        state = (d, s)
        freq[state] += 1

    ans = 0
    for c in freq.values():
        ans += c * (c - 1) // 2

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、各プレフィックスによって引き起こされる変換のコンパクトな表現が維持されます。 反転更新は方向フラグを反転し、アフィン表現の一貫性が保たれるようにシフトを調整します。 回転はシフト値を変更するだけです。 

辞書は、各変換状態が出現する回数を蓄積します。 最終的な合計は、有効な部分配列に直接対応する等しい状態のペアが何組存在するかをカウントします。 

微妙な点は、操作を処理する前にアイデンティティ状態の頻度を初期化することです。 これにより、最初の演算から始まるサブ配列が正しくカウントされるようになります。 

## 実用的な例

 文字列が「abc」で、右回転を 1 つ適用し、その後左回転を 1 つ適用するという小さなケースを考えてみましょう。 

| ステップ | 操作 | 方向 | シフト | 状態 | 更新頻度 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 開始 | 0 | 0 | (0,0) | (0,0):1 |
 | 1 | R1 | 0 | 1 | (0,1) | (0,1):1 |
 | 2 | L1 | 0 | 0 | (0,0) | (0,0):2 |

 2 番目の操作の後、状態は ID に戻るため、両方の操作をカバーする部分配列は有効です。 

このトレースは、プレフィックス状態の等価性が変換のキャンセルを正しく捉えていることを示しています。 

次に、反転のあるケースを考えてみましょう。「abc」、次に反転、そして再び反転します。 

| ステップ | 操作 | 方向 | シフト | 状態 | 更新頻度 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 開始 | 0 | 0 | (0,0) | (0,0):1 |
 | 1 | 私 | 1 | 2 | (1,2) | (1,2):1 |
 | 2 | 私 | 0 | 0 | (0,0) | (0,0):2 |

 二重反転により恒等状態が復元され、状態表現において反転が自己反転であることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(K) | 各操作では、一定サイズの状態と辞書が更新されます。 
| スペース | O(K) | プレフィックスごとに最大 1 つの状態が保存されます。 

時間とメモリの両方が操作数 (最大 20 万) に比例して増加するため、このソリューションは制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    S = input().strip()
    n = len(S)
    K = int(input())

    d = 0
    s = 0
    freq = defaultdict(int)
    freq[(0, 0)] = 1

    for _ in range(K):
        parts = input().split()
        op = parts[0]

        if op == 'I':
            d ^= 1
            s = (n - 1 - s) % n
        else:
            v = int(parts[1])
            if op == 'R':
                s = (s + v) % n
            else:
                s = (s - v) % n

        freq[(d, s)] += 1

    ans = sum(c * (c - 1) // 2 for c in freq.values())
    return str(ans)

 ## 特殊なケース

 特殊なケースの 1 つは、反転が繰り返されることです。 同一状態から開始して、反転を 2 回適用すると、同一状態に戻る必要があります。 状態の更新では、方向を 2 回反転し、元のシフトを復元することでこれを保証します。 

もう 1 つのエッジ ケースは、回転のみによる完全なキャンセルです。 n を法として合計が 0 になる一連の右回転と左回転は、恒等状態に戻らなければなりません。 シフト更新はモジュロ n を直接累積するため、キャンセルは自然に捕捉されます。 

3 番目のケースは、反転と回転を交互に行うケースです。 たとえば、反転、回転、そして再度反転するには、方向とシフトの両方が一貫して更新される必要があります。 アフィン表現は、これらの操作の下でも合成が閉じられたままであることを保証するため、接頭辞の状態は変換を正しく要約したままになります。
