 ## 問題の理解

 1 というラベルの付いたスロットに置かれた単一のポインターから開始し、現在のスロットに応じてランダム化された遷移を繰り返し実行します。 各ステップで値をサンプリングします$y$から$1$に$N$与えられた重み付き確率で。 現在の位置から$x$、新しい位置を計算します$z = \mathrm{lcm}(x, y)$。 この値を超えると$N$、プロセスが停止します。 それ以外の場合は、トークンをスロットに移動します$z$and earn one coin, then repeat the same procedure.

 The task is to compute the expected total number of coins earned before the process terminates.

 制約により許可されるのは、$N$まで$10^5$これにより、プロセスを段階的にシミュレートしたり、単純な状態空間ですべての可能なパスを明示的にモデル化しようとするソリューションは直ちに除外されます。 プロセスは確率的ですが、サンプリングされたデータが与えられると構造は決定的になります。$y$したがって、課題はシーケンスを列挙するのではなく、グラフのような状態システムに対する期待値を集約することです。 

微妙な点は、状態空間が次のような任意の整数ではないことです。$1$に$N$ただし、1 から始まる LCM 操作を繰り返すことで到達可能なもののみです。もう 1 つの隠れた詳細は、遷移では常に分割する値、または以前に見た構造と一致する値が生成されるということです。つまり、$N$。 

単純な間違いは、遷移を独立したものとして扱ったり、すべての遷移を仮定したりすることです。$x$あらゆるものに移行できる$z \le N$。 たとえば、次の場合$N=6$、 から$x=2$そして$y=3$、6に進みますが、LCM遷移では1から5に到達する方法はまったくありません。 この構造を無視すると、確率集計が不正確になります。 

もう 1 つの落とし穴は、遷移が除数格子内でサイクルを形成する可能性があることを忘れていることです。 たとえば、$x=1$、どこにでも行くことができます$y$ただし、6 のような複合状態からは、特定の LCM 結果のみが可能であり、これらの制限は期待値を正しく伝播するために重要です。 

## アプローチ

 ブルートフォースの観点は関数を定義することです$E(x)$スロットから始まる予想コイン数として$x$。 州から$x$のすべての可能な値を反復処理します。$y$、計算する$z = \mathrm{lcm}(x,y)$、そしてもし$z \le N$、私たちは貢献します$1 + E(z)$それ以外の場合は 0 を寄与します。これにより、直接の再帰が得られます。$$E(x) = \sum_{y=1}^{N} p(y)\cdot
\begin{cases}
1 + E(\mathrm{lcm}(x,y)), & \mathrm{lcm}(x,y)\le N \\
0, & \text{otherwise}
\end{cases}$$この定式化は正しいですが、すぐに問題になります。$E(x)$独立して、最大で再帰的な依存関係が発生します。$10^5$州、そして各州がすべてを試みる$y$、につながる$O(N^2)$トランジション。 それは遅すぎます。 

重要な構造的洞察は、次の状態が次の状態の最小公倍数のみに依存するということです。$x$そして$y$、これは常に次の倍数です$x$。 これは、遷移は常に割り切れる半順序で上に移動するため、状態を値の昇順に処理できることを意味します。 状態を処理したら$x$、下からそれに到達できるすべての州は、期待への貢献という観点からすでに説明されています。 

また、固定の場合、$x$、の多くの値$y$結果として得られる LCM に関しては同じように動作します。 すべてを繰り返すのではなく$y$、LCM の結果に基づいて遷移をグループ化できます。 与えられた$x$、有効な遷移は値に正確に対応します。$z$そのような$x \mid z$そして$z \le N$、そして皆様からの貢献$y$それを生み出すのは$z$の約数を考慮することで事前に計算できます。$z$そして LCM 条件を逆転させます。 

これにより、問題が可分性格子上の除数ふるいスタイルの DP に変換され、各状態に到達する確率が累積され、期待値が上方に伝播されます。 

最終的な計算は DP となり、各状態がそれを生成できるすべての小さな約数から確率質量を収集し、それを使用して期待される寄与を計算します。

 ## アルゴリズムのチュートリアル

 1. 正規化された確率を計算する$p(y) = \frac{W_y}{\sum W}$。 これにより重みが適切な分布に変換されるため、期待値を線形に計算できます。 期待値は確率のみに依存し、生の重みには依存しません。 
2. 各値の事前計算$z$すべてのペアからの貢献$(x,y)$そのような$\mathrm{lcm}(x,y) = z$。 これは、約数を反復することによって行われます。$z$、 なぜなら$x$分けなければなりません$z$、そして次にどれをチェックするか$y$値は正確に生成することと互換性があります$z$。 
3. 定義する$E[x]$状態から始まるコインの予想数として$x$。 これらの値を昇順に計算します。$x$、すべての遷移は次の倍数になるため、$x$。 
4. 州ごとに$x$、初期化します$E[x]$有効な全員が貢献した即時報酬が期待されます$y$そのような$\mathrm{lcm}(x,y) \le N$。 この用語は、成功した移行ごとに「+1 コイン」を計算します。 
5. 有効な遷移ごとに$x \to z$、貢献度を蓄積する$p(y)\cdot E[z]$の中へ$E[x]$。 This propagates future expectation backward through the transition graph.
 6. 戻る$E[1]$プロセスは常にスロット 1 から開始されるためです。 

これが機能する理由は、LCM 遷移の単調性特性からわかります。 からのあらゆる動き$x$の倍数の状態になります$x$したがって、状態グラフは、割り算によって順序付けされた DAG です。 このため、期待値を昇順に計算することで、評価するたびに、$E[x]$、 全て$E[z]$到達可能なもののために$z > x$すでに最終決定されています。 期待の反復は線形であるため、各状態は、二重にカウントすることなく、考えられるすべての次の動きからの独立した寄与を集計します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    N = int(input())
    W = list(map(int, input().split()))
    
    total = sum(W)
    p = [0.0] * (N + 1)
    for i in range(1, N + 1):
        p[i] = W[i - 1] / total

    E = [0.0] * (N + 1)

    for x in range(N, 0, -1):
        exp_val = 0.0

        for y in range(1, N + 1):
            if p[y] == 0:
                continue
            z = (x * y) // __import__("math").gcd(x, y)
            if z <= N:
                exp_val += p[y] * (1.0 + E[z])

        E[x] = exp_val

    print(f"{E[1]:.10f}")

if __name__ == "__main__":
    main()
```このコードは直接期待値の再帰を実装しています。 最初に重みから確率を計算し、次に配列を定義します$E$期待のために。 州ごとに$x$、可能な限りすべてを繰り返します$y$、標準の gcd ID を使用して LCM を計算し、ゼロまたは$1 + E[z]$遷移が範囲内にとどまるかどうかに応じて。 

からの計算の方向$N$1 まで下げることは数学的に厳密には必要ありませんが、アクセスするときに確実に$E[z]$、すでに計算されています。$z \ge x$。 必要な精度を考慮すると、浮動小数点演算を使用すれば十分です。

 ## 特殊なケース

 エッジケースの 1 つは、すべての重量が集中している場合です。$y = 1$。 それから$\mathrm{lcm}(x,1)=x$, したがって、プロセスは決して移動せず、最初のコインの後にすぐに終了します。 アルゴリズムはこれを処理します。$E[x] = p(1)\cdot(1 + E[x])$有限の幾何学的期待に解決されます。 

別のエッジケースは、すべての重量が$y = N$。 から$x=1$に直接ジャンプします$N$、さらに LCM が超過するため、そこからプロセスは直ちに終了します。$N$またはそのままにします$N$。 DP は、これを中間蓄積のない単一の大きな遷移として捉えます。 

最終的な構造上のエッジケースは次のような場合です。$x$はすでに大きく、ほとんどの LCM 結果は次の値を超えています$N$。 このような状態では、期待値は少数の遷移に崩壊し、無効な遷移は合計に何も寄与しないため、アルゴリズムはゼロに近い継続値を正しく割り当てます。
