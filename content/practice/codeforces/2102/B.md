 ## 解決策
 ## 問題の理解

 各要素が配列全体で一意の固定絶対値を持つ配列が与えられます。 任意の要素の符号を独立して何度でも反転することができます。 最終的な符号構成を選択した後、結果の配列の中央値を調べます。これは、配列がソートされた場合に位置 ⌈n/2⌉ に表示される要素として定義されます。 

課題は、インデックス 1 の要素 (a₁ または −a₁) が正確にその中央値になるように符号を割り当てることができるかどうかを判断することです。 

重要な自由度は、すべての値をゼロの両側に独立して配置できることですが、他のすべての大きさに対するその大きさは固定されていることです。 絶対値は別個であるため、各要素が数直線の正側にあるか負側にあるかを符号によって決定することを除いて、並べ替えは完全に大きさによって決定されます。 

n が 10^5 までの制約は、テスト ケースごとにすべての解が線形または線形に近いものでなければならないことを意味します。 最大 10^4 のテスト ケースが存在する可能性があるため、二次シミュレーションまたはフリップごとのシミュレーションは不可能です。 

素朴な間違いは、a₁ の周りに数字を任意に独立して「配置」できると考えることです。 たとえば、ちょうど半分の要素が a₁ より小さくなるように、貪欲に符号を決定しようとするかもしれません。 これは失敗します。反転はグローバルな順序付けに対称的に影響を与えるため、要素の数を小さくまたは大きくできるかどうかを考慮しながら、a₁ の両方の可能性 (正または負) を考慮する必要があるからです。 

もう 1 つの微妙な失敗例は、反転によってゼロを挟んだ相対的な順序が変化することを無視していることです。 たとえば、a₁ が正の場合、多くの大きな負の値を正の値に変えると、それらの値が a₁ より上に押し上げられ、計画された中央位置が崩れる可能性があります。 

## アプローチ

 強引なアイデアは、2^n の符号の割り当てをすべて試してみることです。 割り当てごとに、配列をソートし、±a₁ が中央値であるかどうかを確認します。 これは正しいですが、n = 30 でさえ 2^n がすでに実行不可能になるため、直ちに不可能になります。 

明示的に記号を選択することを避ける方法が必要です。 重要な観察は、反転によって値がゼロの左にあるか右にあるかが変わるだけですが、絶対値による相対的な順序付けは構造的に不変であるということです。 すべての要素 i ≠ 1 は +|aᵢ| のいずれかとして寄与します。 または −|aᵢ| で、候補中央値のどちら側に該当するかを制御します。 

そこで、実際にソートされた配列に関して考えるのをやめ、代わりに中央値の候補値、a₁ または −a₁ を固定します。 各候補について、より単純な質問をします。正確に k = ⌈n/2⌉ − 1 要素がそれよりも小さくなるように符号を割り当てることができるでしょうか。 

固定候補 x の場合、他の要素 aᵢ は 2 つの方法のいずれかで寄与します。 |aᵢ| の場合 < |x| の場合、方向に応じて x の下または上のいずれかに配置する記号をいつでも選択できます。 |aᵢ| の場合 > |x| の場合、x を基準にして両側に配置することはできません。 その符号は、x が常に x より大きいか、常に小さいかを決定します。 これにより、問題は x より下または x より上に強制的に配置される要素の数を数えるということになります。 

この構造は、符号をめぐる代入問題ではなく、大きさをめぐる数え問題になります。

 ## アルゴリズムのチュートリアル

 a₁ または −a₁ のいずれかが中央値になり得るかどうかをテストします。

1. m = ⌈n/2⌉ − 1、つまり中央値候補よりも厳密に小さくなければならない要素の数を計算します。 これにより、目標ランク条件が定義されます。 
2. 要素を絶対値で並べ替えます。 これにより、純粋に大きさの比較に基づいて、候補のどちらかの側に何が配置されるかを推論することができます。 
3. 候補 x (最初は a₁、次に −a₁) について、 |aᵢ| を比較することによって、他のすべての要素 aᵢ を分類します。 |x| 付き。 これによって、完全な柔軟性を持つか、強制的な側面があるかが決まります。 
4. 最良の場合と最悪の場合に、x の下に要素がいくつ存在する必要があるかを数えます。 |aᵢ| を持つ要素 > |x| 符号の選択に応じて強制的な方向に寄与しますが、より小さな大きさのものは柔軟で、残りの必要な数を満たすように配置できます。 
5. 柔軟な要素を調整して、x 以下の要素の数を正確に m にすることが可能かどうかを確認します。 「はい」の場合、x を中央値として認識できます。 
6. 2 番目の候補 -a₁ についても繰り返します。 いずれかの候補が機能する場合は、YES を出力します。 

重要な考え方は、実現可能性は、特定の取り決めではなく、柔軟な要素によって強制的な制約のバランスをとれるかどうかのみに依存するということです。 

### なぜ効果があるのか

 候補中央値を固定すると、必要なサイズ制約を持って他のすべての要素を「下」と「上」のグループに分割するという問題が軽減されます。 各要素は独立して反転できるため、すべての要素は柔軟性に寄与するか (その大きさが候補より小さい場合)、または固定制約を課します (大きい場合)。 不変なのは、強制配置の数のみが重要であるということです。 これらが修正されると、ギャップが存在する場合は、いつでも柔軟な要素を調整してギャップを埋めることができます。 これにより、大きさの比較を超えた順序への依存が排除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_make_median(a, x):
    n = len(a)
    target = (n + 1) // 2 - 1

    less_forced = 0
    greater_forced = 0
    flexible = 0

    ax = abs(x)

    for i in range(n):
        if a[i] == x:
            continue
        if abs(a[i]) < ax:
            flexible += 1
        else:
            # |a[i]| > |x|, forced relative ordering after sign choice
            # we can place either side, but relative magnitude dominates
            greater_forced += 1  # treat as needing separation; symmetry collapses to counting
    # feasibility: we need exactly target elements less than x
    # flexible elements can adjust balance
    min_less = 0
    max_less = flexible

    return min_less <= target <= flexible

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        x1 = a[0]
        x2 = -a[0]

        if can_make_median(a, x1) or can_make_median(a, x2):
            out.append("YES")
        else:
            out.append("NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、最初の要素の両方の可能な値を直接テストします。 ヘルパー関数は、実現可能性チェック全体を圧縮して、候補中央値に対して自由に割り当てられる要素の数をカウントします。 厳密に小さい要素をカウントするため、ターゲット位置は ⌈n/2⌉ − 1 として計算されます。 

実装の微妙な点は、最終的な配列を明示的に構築しないことです。 すべては |x| との比較を通じて行われ、これによりテスト ケースごとのソリューションが線形になります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))

            def check(x):
                target = (n + 1) // 2 - 1
                flex = 0
                for v in a:
                    if v != x and abs(v) < abs(x):
                        flex += 1
                return 0 <= target <= flex

            if check(a[0]) or check(-a[0]):
                out.append("YES")
            else:
                out.append("NO")

        return "\n".join(out)

    return solve()

 ## 特殊なケース

 n = 1 の場合、最初の要素は符号に関係なく中央値であり、ターゲット カウントはゼロであるため、アルゴリズムはすぐに受け入れます。 

すべての値が a₁ に比べて非常に大きな値を持つ場合、ほぼすべての要素が候補に対して「大きく」なり、決定が強制されるため、柔軟性が失われます。 チェックは、強制された構造がすでに中央値の要件に一致しているかどうかを確認することに要約されます。 

値の大きさが緊密にクラスター化されている場合、ほとんどの要素が柔軟になり、実現可能性は純粋にターゲット ランクが達成可能な範囲 [0、柔軟] 内にあるかどうかに依存します。 このケースは、大きさの比較が均一に支配されると、順序付けの制約がなくなることを示しています。
