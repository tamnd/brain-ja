 ## 解決策
 ## 問題の理解

 連続する 4 つの位置に対して、置換と 1 つの許可された演算があります。$$[a_i,a_{i+1},a_{i+2},a_{i+3}] \rightarrow [a_{i+2},a_{i+3},a_i,a_{i+1}]$$別の見方をすると、要素の位置$i$と交換します$i+2$、および位置の要素$i+1$と交換します$i+3$。 

タスクは、ターゲットの順列に到達できるかどうかを判断することではありません。 この演算を何度も適用した後に得られる辞書編集上の最小の順列を見つけなければなりません。 

すべてのテスト ケースの合計の長さは最大でも$2 \cdot 10^5$。 操作を繰り返しシミュレートしたり、状態空間を検索したりするソリューションは不可能です。 平$O(n^2)$最悪の場合、テスト ケースごとの処理が遅すぎる可能性があります。 周りに何かが必要です$O(n \log n)$。 

最初の微妙な観察は、すべての要素が常に同じパリティの位置に留まるということです。 位置 1 から始まる要素は、位置 3、5、7 などにのみ移動できます。 位置 2 から始まる要素は、位置 4、6、8 などにのみ移動できます。 

よくある間違いは、単に奇数位置の要素をソートし、偶数位置の要素を個別にソートできると結論付けることです。 

考慮する：```
n = 4
3 2 1 4
```奇数の位置には以下が含まれます`[3,1]`、偶数の位置には以下が含まれます`[2,4]`。 

各グループを並べ替えると次のようになります。```
1 2 3 4
```しかし、この構成には到達できません。 唯一の操作では次のものが生成されます。```
1 4 3 2
```欠けている成分は、2 つのグループ内に適用される順列に対するパリティ制約です。 

見落としやすいもう 1 つのケースは、ソートされた奇数グループと偶数グループが一致しない置換パリティを必要とする場合に発生します。 その場合、完全にソートされたマージには到達できなくなり、答えを辞書編集的に最小限に保ちながら、1 つのグループを意図的にわずかに悪化させる必要があります。 

## アプローチ

 ブルートフォース手法では、各順列をグラフ ノードとして扱い、各演算をエッジとして扱います。 幅優先検索では、最終的に辞書編集上で到達可能な最小の状態が見つかります。 

到達可能なすべての順列が探索されるため、これは正しいです。 残念ながら、状態空間には次のものが含まれます$n!$順列。 たとえ$n=10$、これはすでに完全に実行不可能です。 

何かをより速く取得するには、操作が実際に何を行うのかを理解する必要があります。 

現在奇数の位置にある要素のサブシーケンスを取得し、それを呼び出します$O$。 偶数の位置でサブシーケンスを取得し、それを呼び出します$E$。 

すべての操作は内部で 1 つの隣接するスワップを実行します$O$内部に隣接する 1 つのスワップ$E$同時に。 隣接するスワップによって対称グループ全体が生成されるため、奇数位置の要素を任意に再配置し、偶数位置の要素を任意に再配置できます。 

ただし、各操作は両方のグループに 1 つの転置のみをもたらします。 適用される置換のパリティ$O$そして適用される順列のパリティ$E$いつも一緒に変化していきます。 

つまり、次の不変条件が成り立ちます。 

奇数の位置に適用される順列と偶数の位置に適用される順列は同じパリティを持つ必要があります。 

これが唯一の制限であることがわかります。 等しいパリティを持つ再配置の任意のペアに到達可能です。 

ここで、問題は純粋に組み合わせの問題になります。 

辞書編集的に最小の候補は、奇数位置の要素と偶数位置の要素を別々にソートし、それらをマージして元の位置に戻すことによって取得されます。 

これらのソートされた順序に到達するために必要な置換パリティが等しい場合、この候補は到達可能であり、最適です。 

パリティが異なる場合、候補には到達できません。 正確に 1 つのグループのパリティを変更する必要があります。 最も安価な方法は、ソートされた奇数グループの最後の 2 つの要素を交換するか、ソートされた偶数グループの最後の 2 つの要素を交換することです。 グループはソートされているため、最後の 2 つの要素を変更しても、辞書編集上の損傷は最小限に抑えられます。 両方の可能性を構築し、結果として小さい順列を選択します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n!)$|$O(n!)$| 遅すぎる |
 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 奇数の位置にある要素を配列に抽出します。`odd`偶数の位置にある要素を配列に格納します`even`。 
2.作成`odd_sorted`そして`even_sorted`それらの配列をソートすることによって。 
3. 変換する順列のパリティを計算します。`odd`の中へ`odd_sorted`。 
4. 変換する順列のパリティを計算します。`even`の中へ`even_sorted`。 
5. 2 つのパリティが等しい場合、マージします。`odd_sorted`そして`even_sorted`交互の位置に戻り、結果を出力します。 
6. それ以外の場合は、2 つの回答候補を作成します。 

1. の最後の 2 つの要素を交換します。`odd_sorted`、マージします。 
2. の最後の 2 つの要素を交換します。`even_sorted`、マージします。 
7. 辞書編集的に小さい候補を出力します。 

最後の 2 つの要素を交換すると、ちょうど 1 つのグループの順列パリティが反転します。 パリティの不一致はちょうど 1 ビットであったため、どちらの候補にも到達可能になります。 

### なぜ効果があるのか

 すべての演算は、奇数位置のサブシーケンス内で 1 つの転置を実行し、偶数位置のサブシーケンス内で 1 つの転置を実行します。 したがって、2 つの誘発された置換のパリティは常に等しいです。 

隣接する転置によりすべての置換が生成されるため、唯一の不変条件はこのパリティの等価性です。 

両方のグループを別々にソートすると、位置パリティを考慮したすべての置換の中で辞書編集上最小の配列が生成されます。 パリティ条件がすでに満たされている場合、これより適切な到達可能な答えは存在しません。 

パリティ条件が失敗した場合、1 つのグループのパリティを変更する必要があります。 パリティの変更には奇数の順列が必要です。 ソートされた配列から開始して、最後の 2 つの要素を交換することによって、辞書編集的に最小の奇数順列が取得されます。 そうすることで、答えができるだけ遅く変更され、辞書編集上のダメージが最小限に抑えられます。 奇数グループの変更と偶数グループの変更を比較すると、到達可能な最良の順列が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def permutation_parity(original, target_sorted):
    pos = {v: i for i, v in enumerate(target_sorted)}
    p = [pos[x] for x in original]

    n = len(p)
    vis = [False] * n
    parity = 0

    for i in range(n):
        if vis[i]:
            continue

        cur = i
        length = 0

        while not vis[cur]:
            vis[cur] = True
            cur = p[cur]
            length += 1

        parity ^= (length - 1) & 1

    return parity

def build(odd_vals, even_vals, n):
    res = [0] * n
    oi = 0
    ei = 0

    for i in range(n):
        if i % 2 == 0:
            res[i] = odd_vals[oi]
            oi += 1
        else:
            res[i] = even_vals[ei]
            ei += 1

    return res

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    odd = a[::2]
    even = a[1::2]

    odd_sorted = sorted(odd)
    even_sorted = sorted(even)

    p_odd = permutation_parity(odd, odd_sorted)
    p_even = permutation_parity(even, even_sorted)

    if p_odd == p_even:
        ans = build(odd_sorted, even_sorted, n)
    else:
        cand1_odd = odd_sorted[:]
        cand1_odd[-1], cand1_odd[-2] = cand1_odd[-2], cand1_odd[-1]
        cand1 = build(cand1_odd, even_sorted, n)

        cand2_even = even_sorted[:]
        cand2_even[-1], cand2_even[-2] = cand2_even[-2], cand2_even[-1]
        cand2 = build(odd_sorted, cand2_even, n)

        ans = min(cand1, cand2)

    print(*ans)
```この解決策は、位置パリティに従って順列を分割することから始まります。 操作では要素が奇数位置と偶数位置の間で移動することはないため、これは自然な分解です。 

パリティの計算にはサイクル分解が使用されます。 順列が長さのサイクルで構成されている場合$c_1,c_2,\dots$、そのパリティは次と等しい$$(c_1-1)+(c_2-1)+\cdots \pmod 2.$$これにより、線形時間でパリティを計算できるようになります。 

再構成ステップでは、奇数位置リストと偶数位置リストの要素を交互に配置します。 Python はゼロベースのインデックスを使用するため、インデックス`0,2,4,...`元の問題の奇数の位置に対応します。 

最もデリケートな部分はパリティ修正の場合です。 ソートされたグループの最後の 2 つの要素を交換すると、そのパリティが変更され、辞書編集上の増加が最小限に抑えられます。

 ## 特殊なケース

 次のことを考慮してください。```
4
3 2 1 4
```奇数の位置には以下が含まれます`[3,1]`、偶数の位置には以下が含まれます`[2,4]`。 

両方のグループを並べ替えると、次のようになります。```
odd_sorted = [1,3]
even_sorted = [2,4]
```必要な順列パリティが異なるため、この結合された配置には到達できません。 

このアルゴリズムは、ソートされた 1 つのグループの最後の 2 つの要素を交換します。 より良い候補者は次のようになります。```
1 4 3 2
```これはまさに到達可能な最適値です。 

ここで次のことを考えてみましょう。```
5
5 4 3 1 2
```ソートされた奇数グループと偶数グループには、すでに一致するパリティがあります。 修正の必要はありません。 アルゴリズムは次を出力します。```
2 1 3 4 5
```これは、到達可能なすべての順列の中で辞書編集的に最小です。 

最後に、1 つのグループに要素が 2 つだけある場合を考えてみましょう。```
4
4 1 3 2
```パリティ修正操作では、必要に応じてこれら 2 つの要素が交換されます。 すべてのグループの長さが少なくとも 2 であるため、アルゴリズムは範囲外の位置にアクセスすることはありません。$n \ge 4$、制約によって保証されているとおりに。
