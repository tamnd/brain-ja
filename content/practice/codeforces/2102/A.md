 ## 問題の理解

 長さの整数シーケンスを構築しようとしています$n$, ここでは、2 つの異なる制約が同時に成立するように、負の値を使用できます。 まず、シーケンス全体の合計が指定された値に等しくなければなりません。$m$。 第二に、正確にすべての連続ブロック$p$要素は同じ合計を持つ必要があり、その合計は次のように固定されます。$q$。 

2 番目の条件は、見た目よりもはるかに強力です。 これは個々のセグメントを制約するだけでなく、一定の長さのウィンドウが重なり合うため、配列全体に厳格な繰り返し構造を強制します。$p$すべて同じ値に評価される必要があります。 

テスト ケースごとの入力サイズは小さく、$n \le 100$ただし、テスト ケースの数は最大で大きくなる可能性があります。$10^4$。 これは、テスト ケースごとに線形または定数の解は問題ありませんが、テスト ケースごとに 2 次の解は不要ですが、制約を考慮すると許容できることを意味します。 本当の困難は計算ではなく、固定和ウィンドウの重なりによって課せられる構造を認識することです。 

単純な間違いは、スライディング ウィンドウの制約を満たすために値を個別に割り当てるものとして問題を扱うことです。 たとえば、値を貪欲に構築しようとすることはもっともらしいように思えるかもしれませんが、重複するウィンドウは隣接する位置を緊密に結合するため、ローカルな決定がグローバルに伝播します。 

もう一つの微妙なエッジケースは次のような場合です。$p = 1$。 したがって、すべての要素は等しくなければなりません$q$したがって、配列全体は固定されており、唯一のチェックは、$n \cdot q = m$。 反対の極端な場合、$p = n$、ウィンドウが 1 つしかないため、2 番目の条件は最初の条件と同じであり、実現可能性は次のことを確認することになります。$q = m$。 

これらの境界例は、問題が基本的に構造ではなく周期構造にあることをすでに示唆しています。 

## アプローチ

 強引なアイデアは、配列に値を代入し、作業中に制約を強制することです。 位置ごとに、すべての整数を試して、すべてのスライディング ウィンドウが一貫しているかどうかを確認できます。 ただし、各割り当ては最大に影響します。$p$値は無制限の整数であるため、可能性の数は際限なく増加します。 一貫性は大きさではなく全体的な重複に依存するため、小さな値に制限しても役に立ちません。 

重要な洞察は、隣接するウィンドウの合計を比較することで得られます。 2 つの連続するウィンドウを考えてみましょう。$$(a_i + a_{i+1} + \dots + a_{i+p-1}) = q$$

$$(a_{i+1} + a_{i+2} + \dots + a_{i+p}) = q$$これらの方程式を減算すると、ほとんどの項が削除され、次のものが残ります。$$a_i = a_{i+p}$$これは重要な構造上の制約です。 シーケンスがピリオドで繰り返されることを意味します$p$。 すべての要素はその位置モジュロによって決定されます$p$したがって、配列は最初の要素によって完全に定義されます。$p$価値観。 

この周期構造がわかると、最初のウィンドウの合計が次の場合、スライディング ウィンドウ条件は自動的に満たされます。$q$。 1 つおきのウィンドウは、同じ複数セットの位置を回転させたものであるため、合計は次のようになります。$q$。 

これで、配列全体が同じ長さのブロックの繰り返しで構成されます。$p$、最後に部分ブロックが追加される可能性があります。 合計は最初の点に関して単純な算術式になります。$p$値、および条件はグローバル合計かどうかをチェックすることになります。$m$ブロックサムを固定したまま達成できます。 

させて$k = \lfloor n / p \rfloor$そして$r = n \bmod p$。 すると配列は$k$ベースブロックの完全なコピーと長さのプレフィックス$r$。 制約は、単純な実現可能条件、つまり固定ブロック合計に帰着します。$q$は総和と一致する必要があり、値は無制限の整数であるため、構造自体に矛盾が生じない限り、残りの自由度は調整できます。 

唯一の本当の障害は、周期構造によって配列全体が合計を完全に決定する単一の固定パターンの繰り返しとなり、一致する自由がなくなる場合に発生します。$m$。 

具体的には、周期的な制約が一貫している限り、系は常に解くことができ、自由に選択できるため、それらの制約は常に一貫しています。$p-1$値を調べて最後の値を解決します。 

最後の条件は、合計が配列構造全体で繰り返される固定ウィンドウの合計と互換性があるかどうかをチェックすることであり、これは直接式に基づくチェックにつながります。

 ## アルゴリズムのチュートリアル

 この解決策は、問題を、両方の制約を満たす一貫した周期配列が存在するかどうかをチェックすることに集約します。 

1. すべての長さが等しいことを観察します。$p$部分配列の合計が意味するもの$a_i = a_{i+p}$両方のインデックスが有効な場合はいつでも。 これにより、周期の周期構造が確立されます。$p$。 
2. 配列インデックスを次のように分割します。$p$剰余クラスのモジュロ$p$。 各クラスには、すべて同じ値を共有する必要がある独立した位置が含まれています。 
3. 合計を表現する$m$これらの剰余クラスの合計として、各クラスが配列内に出現する回数で重み付けされます。 
4. ウィンドウ合計制約を同じ範囲にわたる単一の線形方程式として表現します。$p$変数: すべての合計$p$基本値は等しい必要があります$q$。 
5. 自由度を数えます。 我々は持っています$p$変数とウィンドウ条件からの 1 つの線形制約だけを残し、$p-1$自由変数。 
6. 自由変数を使用して総和制約を満たす。 整数には制限がないため (負の値を含む)、必要な調整は 1 つの自由変数に吸収されます。 
7. すべてのケースに対して解決策が存在すると結論づけます。 

この推論が失敗する唯一のケースは、周期構造が矛盾する制約を課した場合ですが、ここでは常に、十分な自由度を持つ単一の一貫した線形システムに還元されます。 

### なぜ効果があるのか

 スライディング ウィンドウ制約により、配列が周期系に折りたたまれ、各位置がその剰余モジュロのみに依存します。$p$。 システムは、独立した制約よりも多くの変数を含む整数にわたる一連の線形方程式になります。 整数変数には制限がないため、少なくとも 1 つの自由変数が存在すると、ウィンドウ合計制約を満たした後で合計が常に一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, p, q = map(int, input().split())

        if p > n:
            print("NO")
            continue

        # If p == 1, every element must be q
        if p == 1:
            print("YES" if n * q == m else "NO")
            continue

        # If p == n, only one window, so sum constraints must match exactly
        if p == n:
            print("YES" if q == m else "NO")
            continue

        # For 1 < p < n, periodic structure gives enough freedom to always construct
        print("YES")

if __name__ == "__main__":
    solve()

中間のケースは複雑になりすぎないように注意する必要があります。 重要なのは、負の値を使用すると線形システムを任意に調整できるため、境界ケースを超えて追加の算術チェックが必要ないことです。
