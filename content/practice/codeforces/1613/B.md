 ## 解決策
 ## 問題の理解

 一連の異なる正の整数が与えられます。 私たちのタスクは、シーケンスの長さのおよそ半分の数のペアを構築することです。各ペアは次のようになります。$(x, y)$、両方の数値はシーケンスから取得され、別個のものであり、剰余は次のようになります。$x$で割られる$y$シーケンスには登場しません。 各テストケースが求めるのは、$\lfloor n/2 \rfloor$そんなペアたち。 

入力サイズはテスト ケースごとに最大 200,000 要素にすることができ、すべてのテスト ケースの合計も 200,000 によって制限されます。 つまり、考えられるすべてのペアを検査するソリューションは遅すぎるということになります。$O(n^2)$アプローチは周囲で実行されます$4 \cdot 10^{10}$最悪の場合の操作は 2 秒では実現不可能です。 したがって、線形または$O(n \log n)$アプローチ。 

素朴な解決策をつまずく可能性のあるエッジ ケースには、一方または両方の数値が 1 である可能性がある非常に小さな配列が含まれます。$x \mod 1 = 0$、0 は配列に現れる場合もあれば、現れない場合もあります。 もう 1 つの微妙な点は、貪欲なペアリングにより、任意の要素を選択した場合にシーケンス内に存在する剰余が誤って生成される可能性があることです。 たとえば、配列では$[1, 4]$、ペアリング$1$と$4$収量$1 \mod 4 = 1$、これは配列内にあるため無効です。 どのような解決策でも、小さい数と大きい数を組み合わせると配列内の要素が再現される可能性があるという事実を考慮する必要があります。 

## アプローチ

 ブルートフォースアプローチは、すべてのペアを反復処理することです。$(x, y)$、計算する$x \mod y$、配列内に存在するかどうかを確認します。 これは正しいですが、非現実的です。$n = 2 \cdot 10^5$、それは必要です$O(n^2)$モジュロ演算とメンバーシップ チェックですが、遅すぎます。 

重要な洞察は、大きな数を小さな数で割ると、剰余が小さくなる傾向があるということです。 配列をソートすると、次のように大きな数値を選択できます。$x$そして小さな数字としては$y$。 それから、$x \mod y$は厳密に以下であることが保証されています$y$。 私たちが選ぶなら$y$ソートされた配列の最小半分から、$x$最大半分から、残り$x \mod y$最大の数は指定できません。選択したセットは$y$が小さい場合、最大値と競合しないことが保証されます。 この貪欲なペアリングは常に機能し、並べ替え後は直線的な時間で実装できます。 

並べ替えることにより、後半の各要素を前半の要素と安全に組み合わせることができます。 配列要素は個別であり、floor 関数によってハーフペアリングが保証されるため、衝突を心配することなく、必要な数のペアが正確に生成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 貪欲にソートされたペアリング | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、配列を読み取り、昇順に並べ替えます。 並べ替えると、最小値と最大値を簡単に識別できます。 
2. 必要なペアの数を次のように計算します。$\lfloor n/2 \rfloor$。 
3. 最大のものをペアリングします$\lfloor n/2 \rfloor$最小の数字$\lfloor n/2 \rfloor$番号を順番に。 つまり、ペアリングします$i$- 番目に大きい数値$i$- 番目に小さい数値。 
4. 各ペアを印刷します。$(x, y)$選択した順序で。 施工により、$x$は常により大きいです$y$、 それで$x \mod y < y$配列内の最大の数値の中に出現することはできません。 これにより、配列に剰余が存在しないことが保証されます。 

機能する理由: 並べ替えにより、配列が下半分と上半分に分離されます。 常に多数のペアリングを行うことで$x$小さな数字で$y$、残り$x \mod y$よりも小さいです$y$。 異なる半分の要素のみをペアにするため、残りは、すべての潜在的な要素を含む上半分の要素と一致することはできません。$x$価値観。 この不変式により、すべてのペアがモジュロ条件を満たすことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()
    half = n // 2
    for i in range(half):
        print(a[n - i - 1], a[i])
```コードは最初にテスト ケースの数を読み取ります。 テスト ケースごとに、配列を読み取り、並べ替えて、必要なペアの数を計算します。 インデックスを反復処理します$0$に$half-1$そして、上半分の各要素を下半分の対応する要素と組み合わせます。 並べ替えにより、追加のチェックを行わずにモジュロ条件が満たされていることを保証できるため、並べ替えが重要です。

import sys, io

    sys.stdin = io.StringIO(inp)
    output = io.StringIO()

    t = int(input())
    for _ in range(t):

        a.sort()
        half = n // 2

    return output.getvalue().strip()

 ## 特殊なケース

 アレイの場合`[1, 4]`、アルゴリズムは最大の 4 と最小の 1 を組み合わせます。`4 % 1`は 0 であり、配列内に存在しないため、有効なペアが生成されます。 単純に 1 と 4 を組み合わせた場合、残りは`1 % 4`は 1 となり、配列内に表示され、ルールに違反します。 最大値と最小値を並べ替えてペアにすることで、この失敗は自動的に回避されます。 同様に、次のような奇数長の配列の場合、`[3, 8, 5]`、アルゴリズムは生成するだけです`floor(n/2)=1`ペア、こちら`(8,3)`、正確性を保証します。
