 ## 解決策
 ## 問題の理解

 この問題の各番号は、拡張された形式ではなく、簡潔な説明として示されています。 完全な整数を書き込む代わりに、基本値が与えられます。`x`および末尾のゼロの数`p`、つまり実際の数値は`x × 10^p`。 

したがって、すべてのテスト ケースでは、そのような 2 つの「10 進数シフト」数値が得られます。 タスクは、結果として得られる 2 つの整数のどちらが大きいか、またはそれらが等しいかどうかを判断するだけです。 

重要な難点は、`p`最大 10^6 までの大きさになる可能性があります。 10^6 桁を書き出すことはすでにメモリと時間の制約をはるかに超えているため、実際の数値を構築することは不可能になります。 比較は純粋に数値の構造から行う必要があります。 

この制約により、最大 10^4 のテスト ケースが許可されます。 完全な数値を明示的に構築またはシミュレートしようとするソリューションは、時間とメモリの爆発の両方によりすぐに失敗します。 1 つのテスト ケースで最大 100 万桁が必要になる可能性があるため、文字列ベースの構築さえも実行不可能です。 

基数が小さいが指数が異なる場合、微妙なエッジケースが発生します。 たとえば、比較すると、`1 × 10^5`そして`10 × 10^4`比べているようです`100000`そして`100000`、基本値は異なりますが、これらは等しいです。 比較する素朴なアプローチ`(x, p)`辞書編集的には、次のように誤って結論付けられてしまいます。`10 × 10^4`より大きい理由は`10 > 1`。 

別の失敗例は、一方の数値の指数が他方の数値の大きさを完全に支配する場合に発生します。`999 × 10^0`対`1 × 10^3`。 正しい答えは、基本の大きさではなく、拡張後の桁の長さに完全に依存します。 

したがって、比較では、数値を構築せずに算術絶対値をシミュレートする必要があります。 

## アプローチ

 直接的なブルート フォース手法では、次のコードを追加することで各数値の完全な整数表現を構築します。`p`ゼロを 10 進数文字列に変換`x`、結果の文字列を数値的に比較します。 これは実際の数値を反映しているため、概念的には単純で正しいものです。 

ただし、最悪の場合、各数値は最大 10^6 桁になる可能性があります。 最大 10^4 のテスト ケースでは、理論上の出力サイズは 10^10 文字程度になります。 メモリ制限を無視したとしても、これらの文字列を単に書いたり比較したりするだけでは、時間の制約をはるかに超えてしまいます。 

重要な点は、末尾のゼロは数値の位取りにのみ影響し、内部の桁構造には影響しないということです。 唯一意味のある比較は、拡張後の合計桁長から得られます。 2 つの数値の有効長が異なる場合、長い方が直ちに大きくなります。 それらの長さが同じである場合、後続のゼロが完全に揃っているため、比較は重要なプレフィックスを桁ごとに比較することになります。 

これにより、桁の長さのバランスをとり、同じ長さの数値の正規化表現を比較するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 各数値は 2 つの要素を持つものとして扱います。`x`そして大きさの変化`p`。 

1. 各数値の有効長を次のように計算します。`len(str(x)) + p`。 

これは、完全に展開された数値を構築しない場合の桁数を表します。 
2. 2 つの長さが異なる場合、長さの大きい方の数値が自動的に大きくなります。 

これは、末尾にゼロを追加すると常に大きさが 10 桁増加するという事実から直接得られます。 
3.長さが等しい場合、長さだけでは判断できません。 この場合、両方の数値が完全に展開されたかのように、桁ごとに比較します。 
4. 拡張せずに比較するために、概念的に両方の数値を揃えます。 

指数が大きいほど、小さい底に末尾のゼロが追加されるため、効果的に比較します。`x1 × 10^(p1 - p2)`そして`x2 × 10^(p2 - p1)`どちらの指数が大きいかに応じて。 
5. 小さい表現に論理的にゼロを埋め込み、重複する重要な部分のみを比較することによってこれをシミュレートします。 
6. 比較は、構築された整列表現の文字列比較として実行されますが、実際に完全な文字列を具体化することはありません。 

### なぜ効果があるのか

 すべての数値は次の形式になります。`x × 10^p`、これは の 10 進表現をシフトするのと同じです。`x`左側に`p`ポジション。 10 進数の数値の大きさは、最初に桁数によって決定され、次に長さが一致する場合の桁の辞書編集的な比較によってのみ決定されます。 

各数値を「長さクラス」と「整列された数字シーケンス」に分離することで、実整数の正確な順序が保持されます。 10 のべき乗による乗算は桁の位置にのみ影響し、桁の値には影響しないため、変換によって相対順序は変更されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
out = []

for _ in range(t):
    x1, p1 = map(int, input().split())
    x2, p2 = map(int, input().split())

    s1 = str(x1)
    s2 = str(x2)

    len1 = len(s1) + p1
    len2 = len(s2) + p2

    if len1 > len2:
        out.append(">")
        continue
    if len1 < len2:
        out.append("<")
        continue

    # same length case: compare digit by digit
    i = 0
    j = 0
    zero1 = p1
    zero2 = p2

    while i < len(s1) or j < len(s2):
        d1 = int(s1[i]) if i < len(s1) else 0
        d2 = int(s2[j]) if j < len(s2) else 0

        if d1 != d2:
            out.append(">" if d1 > d2 else "<")
            break

        i += 1
        j += 1
    else:
        out.append("=")

sys.stdout.write("\n".join(out))
```実装は、数字へのアクセスが効率的になるように、各基本数値を文字列に変換することから始まります。 最初に合計有効長が比較され、ほとんどの場合はすぐに解決されます。 

長さが一致すると、コードは同期した桁比較を実行します。 1 つの文字列の桁数がなくなると、欠落した位置を暗黙的にゼロとして扱います。これは、元の数値の末尾のゼロの影響に正確に対応します。 

微妙な点は、埋め込まれた文字列を明示的に構築しないことです。 代わりに、比較中に範囲外の位置をゼロとして扱うことでパディングをシミュレートします。 これにより、正確性を維持しながら、メモリ オーバーフローのリスクが回避されます。 

## 実用的な例

 サンプルペアを考えてみましょう`(2, 1)`そして`(19, 0)`。 

有効長を比較します。`2 × 10^1`長さは 2 ですが、`19 × 10^0`長さも 2 です。長さが等しいため、桁ごとに比較します。 

| ステップ | s1桁 | s2 桁 | 決定 |
 | --- | --- | --- | --- |
 | 1 | 2 | 1 | 2 > 1 → 最初の方が大きい |

 したがって、出力は`>`。 

ここで考えてみましょう`(10, 2)`そして`(100, 1)`。 

有効長: どちらも 3 桁です。 

| ステップ | s1桁 | s2 桁 | 決定 |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 等しい |
 | 2 | 0 | 0 | 等しい |
 | 3 | 0 | 0 | 等しい |

 すべての数字が一致するため、結果は次のようになります`=`。 

これらの例は、アルゴリズムが最初に構造的優位性 (長さ) を使用し、必要な場合にのみ桁の位置合わせに戻ることを示しています。

 このアルゴリズムは、依存関係を回避するため効率的です。`p`、非常に大きくなる可能性があります。 すべての演算は桁数によって制限されます。`x`、小さいです。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        x1, p1 = map(int, input().split())
        x2, p2 = map(int, input().split())

        s1 = str(x1)
        s2 = str(x2)

        len1 = len(s1) + p1
        len2 = len(s2) + p2

        if len1 > len2:
            out.append(">")
        elif len1 < len2:
            out.append("<")
        else:
            i = j = 0
            while i < len(s1) or j < len(s2):
                d1 = int(s1[i]) if i < len(s1) else 0
                d2 = int(s2[j]) if j < len(s2) else 0
                if d1 != d2:
                    out.append(">" if d1 > d2 else "<")
                    break
                i += 1
                j += 1
            else:
                out.append("=")

    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは、基数が小さいにもかかわらず、末尾のゼロにより 1 つの数値が大幅に長くなる場合です。 入力用`1 5`そして`999 0`、最初の数値は 100000 になりますが、2 番目の数値は 999 のままです。アルゴリズムはただちに長さを比較し、最初の数値が長いことを見つけて出力します。`>`数字を検査せずに。 

もう 1 つの特殊なケースは、両方の数値の有効長が同じになるが、桁の位置合わせが必要な場合に発生します。 のために`10 2`そして`100 1`、どちらも 3 桁に展開されます。 アルゴリズムは桁ごとに比較し、すべての位置で等しいことを見つけて、正しく出力します。`=`。 

3 番目のケースには、次のように、異なる指数を持つ同一の基底値が含まれます。`10 1`そして`10 2`。 有効な長さが異なるため、比較は桁検査なしで即座に解決され、末尾にゼロを追加すると大きさが増加することが正しく反映されます。
