 ## 解決策
 ## 問題の理解

 私たちには一連の攻撃時間とドラゴンが与えられています。`h`ヒットポイント。 各攻撃は持続する毒を適用します`k`秒間持続し、1秒ごとに1ダメージを与えます。 新しい攻撃が行われたときにドラゴンがすでに毒されている場合、毒タイマーはリセットされます。 私たちの仕事は最小値を見つけることです`k`すべての攻撃による合計ダメージが少なくとも`h`。 

入力は次のように指定します`n`厳密に回数を増やして攻撃する`a_1, a_2, ..., a_n`、出力は単一の整数でなければなりません`k`テストケースごとに。 の値`h`非常に大きくなる可能性があるため (最大 10^18)、ダメージを秒ごとにシミュレートしようとするアルゴリズムは非常に遅すぎます。 攻撃回数`n`は最大 100 です。これにより、計算制限を超えることなく、攻撃または攻撃間の間隔を繰り返すことができます。 

単純なソリューションを簡単に破ってしまう可能性のあるエッジ ケースには、非常に接近した攻撃が含まれるシーケンスが含まれます。 たとえば、次の場合`n=2`、`h=2`、 そして`a=[1,2]`、その後毒の持続時間`k=1`毎秒1ダメージしか与えませんが、2回目の攻撃は`a_2=2`前の毒の最初の 1 秒と重複します。これは、継続時間の単純な合計がダメージを過大評価することを意味します。 同様に、攻撃が遠く離れている場合、ソリューションは次のことを可能にする必要があります。`k`孤立した攻撃をカバーするのに十分な大きさにする必要があります。 

## アプローチ

 ブルートフォースアプローチは、あらゆる可能性を試すことです`k`1 から開始し、最初の攻撃から毒が切れるまでのすべての秒間を反復して合計ダメージをシミュレートします。 各攻撃が重複する場合、毒の持続時間を延長します。 これはダメージを正確に計算できるため機能しますが、大規模な場合には非常に非効率的です。`h`必要になるかもしれないから`k`最大 10^18 になるため、単純なシミュレーションは実行不可能になります。 

重要な洞察は、毎秒シミュレーションする必要はないということです。 与えられたダメージ`k`重複を考慮して、各攻撃の寄与を合計することで直接計算できます。 具体的には、時々連続攻撃のペアごとに、`a_i`そして`a_{i+1}`、によって寄与された損害`i`- 番目の攻撃は`min(k, a_{i+1} - a_i)`。 最後の攻撃は常に正確に貢献します`k`ダメージ。 これを使用すると、あらゆる場合の合計ダメージを O(n) で計算できます。`k`。 

これにより、二分探索アプローチが可能になります。 特定の場合は、`k`少なくとも取引する`h`ダメージ、それ以上`k`も十分です。 逆に、ある特定の場合は、`k`小さすぎる、それ以上小さい`k`失敗します。 したがって、範囲にわたって二分探索を実行できます。`[1, h]`最小限のものを見つけるために`k`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n * k) | お(1) | h が大きいと遅すぎる |
 | 区間和による二分探索 | O(n log h) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`、`h`、および攻撃時間`a_1, ..., a_n`。 
2. 関数を定義する`damage(k)`与えられた毒の持続時間の合計ダメージを計算します`k`。 初期化する`total=0`。 それぞれについて`i`0から`n-2`、 追加`min(k, a_{i+1} - a_i)`に`total`。 ループの後に追加します`k`最後の攻撃に向けて。 戻る`total`。 
3. 二分探索境界を初期化する`low=1`そして`high=h`。 その間`low < high`、計算する`mid=(low+high)//2`。 もし`damage(mid) >= h`、 セット`high=mid`; それ以外の場合は、設定します`low=mid+1`。 
4. 二分探索後、`low`最小値に等しい`k`少なくとも到達する`h`ダメージ。 出力してください。 

なぜ機能するのか: ダメージ関数は単調です。`k`。 Increasing`k`それぞれのダメージが減少することはありません。`min(k, a_{i+1}-a_i)`同じままか増加し、最後の攻撃が常に貢献します`k`。 これにより、バイナリ検索で最小の十分な値が正しく見つかるようになります。`k`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, h = map(int, input().split())
        a = list(map(int, input().split()))

        def total_damage(k):
            dmg = 0
            for i in range(n-1):
                dmg += min(k, a[i+1] - a[i])
            dmg += k
            return dmg

        low, high = 1, h
        while low < high:
            mid = (low + high) // 2
            if total_damage(mid) >= h:
                high = mid
            else:
                low = mid + 1
        print(low)

if __name__ == "__main__":
    solve()
```の`total_damage`関数は毎秒シミュレーションせずに正確なダメージを計算します。 二分探索は効率的に最小値を絞り込みます。`k`。 私たちが使用するのは`low < high`最小値に収束するループ条件として`k`。 エッジ条件は、追加することで正しく処理されます。`k`最後の攻撃に向けて。

## 特殊なケース

 のために`n=2, h=2, a=[1,2]`、テスト`k=1`:

 -`damage(1)`= min(1,2-1) + 1 = 1 + 1 = 2、これは次の条件を満たします。`h=2`。 
- アルゴリズムは正しく返します`k=1`。

 -`damage(50)`= min(50, 99) + 50 = 50 + 50 = 100、h=10 を超えます。
