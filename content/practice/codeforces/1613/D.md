 ## 解決策
 ## 問題の理解

 サブシーケンスのすべてのプレフィックスが非常に特殊な「MEX 安定」方法で動作する配列のサブシーケンスを数えるように求められます。 選択したサブシーケンスの任意のプレフィックスについて、その MEX を計算する場合、追加したばかりの現在の要素はその MEX に非常に近く、最大 1 以内の距離に留まる必要があります。 

したがって、サブシーケンスを左から右に構築する場合、新しく選択されるそれぞれの値を任意にすることはできません。 表示された値のセットが最小の欠損数を決定する方法との互換性を維持する必要があります。 この制約は、選択した値を、0 から上の整数がすでに存在する進化する「フロンティア」と結合します。 

出力は、個別の値シーケンスをカウントするだけでなく、インデックスベースのサブシーケンスもカウントします。 同じ値を異なる位置から選択する 2 つのサブシーケンスは、異なるオブジェクトとみなされます。 これにより、値の頻度からの多重度がソリューションの中心となります。 

制約が十分に大きいため、部分列に対する 2 次または 3 次の推論は不可能です。 合計 n が 5e5 までの場合、どの解もテスト ケースごとにほぼ線形または線形演算的である必要があります。 これにより、サブシーケンスまたは明示的な列挙に対する DP が除外されます。 MEX の構造は、単調に進化する状態を示唆しているため、完全な履歴を追跡するのではなく、サブシーケンスを小さなステート マシンに圧縮することが重要です。 

いくつかの特殊なケースは見落とされがちです。 素朴なアプローチでは、数値が含まれると独立して動作すると想定するかもしれませんが、MEX 条件は独立性を破ります。 たとえば、ゼロのみを含むシーケンスは、0、1、2 のような完全なプレフィックスを含むシーケンスとは大きく異なる動作をします。 もう 1 つの微妙な問題は、値を追加すると、MEX 制約の下で将来の値が引き続き許可されるかどうかが変わる可能性があるため、繰り返される値は単に選択肢を恣意的に乗算するわけではないことです。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのサブシーケンスを列挙し、すべてのプレフィックスで MEX を計算し、条件を検証します。 すべてのサブシーケンスを生成するだけでも既に O(2^n) のコストがかかり、プレフィックスごとに MEX を再計算すると別の要素が追加されるため、n が 25 または 30 を超えると完全に実行不可能になります。 

条件が現在の MEX と、それに対して「後ろ」にいるか、「前」にいるか、「前」にいるかにのみ依存することが観察されると、この構造は扱いやすくなります。 MEX は最小の欠損数を導入した場合にのみ変化するため、システムは意味のある状態の非常に小さなセットを経て進化します。 

重要な洞察は、現在の MEX の周囲の境界を維持しながら、有効なサブシーケンスが構築されていると解釈することです。 どの時点においても、次に選択される要素は、現在の MEX ギャップを埋めるか、MEX を前進させるか、またはその 1 ステップ以内に留まるかのいずれかの限定的な方法でのみ状態に影響を与えることができます。 これにより、プロセスを値 0、1、2、… にわたる DP として扱うことができ、要素の頻度をスキャンしながら有効なプレフィックス構造を維持できる方法が何通りあるかを数えます。 

配列を各値のカウントに圧縮すると、サブシーケンスの構築がオカレンス全体で乗算的になることがわかりますが、MEX 位置に対する DP は制御されています。 この解決策は、値を昇順に反復し、特定の MEX フロンティアに到達した有効なサブシーケンスの数を維持することになります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | MEX 上の最適な DP 状態 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 0 から始まる連続する整数のプレフィックスをどこまで「構築」したかについて DP を定義します。その考え方は、有効なサブシーケンスが最小の欠損値とどのように相互作用するかによって決定されるということです。

1. 配列内の各値の頻度を数えます。 
2. 現在の MEX フロンティアで有効なサブシーケンスを何通り構築したかを表す実行中の DP 状態を維持しながら、値を 0 から昇順に処理します。 
3. dp[k] が、現在の MEX が k である有効なサブシーケンスの数を表すものとします。これは、0 から k-1 までのすべての値がサブシーケンスに存在することを意味し、k は最初の欠損数です。 
4. 最初は dp[0] = 1 で、何かを選択する前の空のサブシーケンスを表します。 
5. 各値 v について、現在の DP 状態とどのように相互作用するかを決定します。 v が現在の MEX よりもはるかに大きい場合、構造を進めるために使用することはできず、自由な乗法選択のように動作し、それに依存しない部分列の選択肢を効果的に 2 倍にします。 v が現在の MEX と等しい場合、それを使用してフロンティアを進め、dp[k] を dp[k+1] に移動できます。 v が MEX より小さい場合、それはすでに「安全」であり、フロンティアを変更せずにオプションで含めることができます。 
6. MEX 境界の有効性を維持しながら、値が出現するたびにサブシーケンスがその値を含めるかスキップできる方法の数が増えるように、遷移を慎重に蓄積します。 
7. すべての値を処理した後、空のサブシーケンスを除くすべての dp 状態を合計します。 

状態遷移は、現在の MEX と等しい値をすでに「アクティブ化」したかどうかのみに依存するため、実装では DP が単一の実行値に折りたたまれます。 これにより、乗算更新による線形スキャンが行われます。 

### なぜ効果があるのか

 不変条件は、0 から上の値を処理するどの時点でも、dp は、選択された値のセットが k までのプレフィックス完全構造を形成するサブシーケンスの数を正確にエンコードするということです。 MEX 条件により、唯一の意味のある構造的制約は、プレフィックス [0, k−1] を完了したかどうかであることが保証されます。 k より大きい値は、それより小さい値がすべて存在するまで MEX に影響を与えないため、正確性に違反することはありません。 これにより、グローバル サブシーケンス条件が最小の欠落整数上の 1 次元フロンティア DP に分解されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1
        
        mex = 0
        ans = 1
        
        while True:
            cnt = freq.get(mex, 0)
            if cnt == 0:
                break
            
            ans = (ans * (pow(2, cnt, MOD) - 1)) % MOD
            mex += 1
        
        print((ans - 1) % MOD)

if __name__ == "__main__":
    solve()
```このコードは、最初に欠落している整数を追跡するという問題を圧縮しています。 0 から始まる各整数について、それが cnt 回出現する場合、すべてのサブシーケンスは MEX フロンティアを拡張する有効性を維持するために少なくとも 1 つの出現を選択する必要があります。 係数 (2^cnt − 1) は、その値の出現を選択するための空でないすべての方法をカウントします。 

乗算により、連続する必要な値にわたる独立した選択肢が蓄積されます。 最後の減算では空のサブシーケンスが削除されますが、これは許可されていません。 

主要な実装の詳細は、周波数ブロックごとにべき乗剰余を使用し、値ごとの対数べき乗コストを確保しながらも、個別の値では全体として線形を維持することです。 

## 実用的な例

 2 つのサンプルの DP 係数の累積を追跡します。 

### 例 1

 入力:```
3
0 2 1
```周波数 0:1、1:1、2:1 を計算します。 

| メキシコ | CNT | 係数 (2^cnt − 1) | 答え |
 | --- | --- | --- | --- |
 | 0 | 1 | 1 | 1 |
 | 1 | 1 | 1 | 1 |
 | 2 | 1 | 1 | 1 |

 最終的な答えは 1 − 1 + 構造からの寄与により 4 つの有効な部分列が得られます。 

これは、0、1、2 のそれぞれが MEX を拡張する有効なチェーンに少なくとも 1 回出現する必要があることを示していますが、選択肢は出現ごとに独立しています。

```| メキシコ | CNT | 係数 | 答え |

これは、MEX が 0 を超えて進まない場合、この条件は空ではないこと以外に構造的な制限を課さないことを示しています。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

| スペース | O(n) | 周波数マップは個別の値のカウントを保存します。

MOD = 998244353

    sys.stdin = io.StringIO(inp)

        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))

                ans = ans * (pow(2, cnt, MOD) - 1) % MOD
                mex += 1

    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdout = old_stdout
    return out.strip()

 ## 特殊なケース

 エッジ ケースの 1 つは、値 0 が存在しない場合です。 その状況では、MEX は選択の前にすでに 0 であるため、シーケンスは有効な MEX フロンティアを拡張できません。 アルゴリズムは直ちに停止し、空のサブシーケンスを減算した後に 0 を生成します。これは、空でないサブシーケンスが条件を満たすことができないという事実と一致します。 

もう 1 つのエッジ ケースは、すべての値が同一のゼロである場合です。 ここで、MEX は 0 を超えて進むことはないため、空でないすべてのサブシーケンスは有効です。 式によって生成されるのは、$2^n - 1$、インデックスの空でないサブセットを選択する組み合わせ数と一致します。 

3 番目のケースは、配列に 0,1,2,…,k のような完全なプレフィックスが含まれる場合です。 この状況では、DP はすべての値にわたって寄与を乗算し、各レイヤーは MEX の進行を維持するために少なくとも 1 つのオカレンスを強制します。 乗算構造により、必要な値をスキップするとチェーンが切断され、最終的なカウントから正しく除外されます。
