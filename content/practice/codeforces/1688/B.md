 ## 解決策
 ## 問題の理解

 私たちは、すべてのトークンが奇妙な魔法の力を持つように、魔法のトークンのコレクションを変換するように求められます。 各トークンは、何らかの正の整数乗で始まります。 Fusion 操作を使用して 2 つのトークンを 1 つに結合し、それらのパワーを合計したり、パワーが等しいトークンを 2 で割って減らすことができます。 目標は、すべてのトークンを奇数にするために必要なこれらの操作の最小数を決定することです。 

入力は複数のテスト ケースで構成され、それぞれがトークンの数とその初期パワーを示します。 各テスト ケースの出力は、操作の最小数を表す単一の整数です。 

制約により、すべてのテスト ケースにわたるトークンの合計数は最大 200,000 であり、個々の検出力は 1e9 まで増加する可能性があることがわかります。 これは、トークンの数に対してほぼ線形または線形計算時間で実行されるアルゴリズムが必要であることを示しています。 トークンのすべてのペアを考慮する二次解は遅すぎます。 

すべてのトークンが偶数であるが、べき乗が異なる 2 のべき乗である場合、明らかではないエッジ ケースが発生します。 例えば、`[2, 4, 8]`慎重な計画が必要です。最初に小さな数を盲目的に減らすと、トークンを戦略的に組み合わせるよりも多くの操作が必要になる可能性があります。 もう 1 つのエッジ ケースは、すべてのトークンが奇数である場合であり、これには操作が必要ありません。 単純なアルゴリズムでは、依然として不必要な操作が試行される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、可能なすべての融合とリダクションのシーケンスをシミュレートして、どれが最も少ない操作を生成するかをチェックします。 融合ごとに、すべてのトークンのペアを試します。 各削減について、すべての偶数トークンをチェックします。 これは原理的には機能しますが、シーケンスの数はトークンの数とともに指数関数的に増加するため、このアプローチは実行不可能になります。 

最適なアプローチの重要な点は、すべてのシーケンスをシミュレートする必要がないということです。 融合は偶数のトークンを結合する場合にのみ役立ち、各縮小は奇数になるまで偶数を半分にします。 それぞれの偶数は独立して減らすことができますが、複数の偶数がある場合は、それらのいくつかを最初に融合することで操作を節約できます。 具体的には、最小の操作数は、偶数のトークンが奇数になるまでに必要な 2 で割る最小回数によって決まります。これは、常に戦略的にトークンを組み合わせて、コストが最も低いトークンに焦点を当てることができるためです。 

これは、建設的な貪欲戦略につながります。つまり、偶数のトークンごとに、奇数に達するために 2 で割る回数を数えます。 複数のトークンが同じ分割数を必要とする場合、最小の分割数のみを個別に実行する必要があります。 他のものはそれにマージでき、操作を節約できます。 奇数には演算は必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n log A) | O(n) | 承認済み |

 ここ、`A`トークンの最大値です。 各トークンは最大 2 で割ることができます`log2(A)`回。 

## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そしてトークンパワーのリスト。 
3. 空のリストを初期化して、各偶数トークンに必要なリダクション操作の数を保存します。 
4. 各トークンが奇数の場合は、次のトークンに進みます。 偶数の場合は、何回 2 で割れば奇数になるかを数え、この数値を保存します。 
5. 偶数のトークンがない場合、答えはゼロです。 
6. それ以外の場合は、カウントを昇順に並べ替えます。 最初のカウントは、1 つのトークンに必要な最小削減量を表します。 後続の各カウントはプロセスにマージできる追加のトークンに対応し、必要に応じて追加のトークンごとに 1 つの操作を追加します。 
7. すべてのトークンを奇数にするために必要な最小ステップ数を取得するために必要な操作を合計します。 
8. 各テスト ケースの答えを出力します。 

機能する理由: このアルゴリズムは、最小の偶数トークンを最も少ない回数で分割することで最小限の操作が達成されるという不変条件を利用します。 より大きなトークンをそれに融合しても、最小削減ステップは増加しません。これは、偶数を融合しても、奇数に到達するために必要な分割数が減らないためです。 この貪欲な戦略により、合計操作数が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_operations(tokens):
    even_counts = []
    for x in tokens:
        if x % 2 == 0:
            count = 0
            while x % 2 == 0:
                x //= 2
                count += 1
            even_counts.append(count)
    if not even_counts:
        return 0
    even_counts.sort()
    # minimum reductions for the first token + 1 for each remaining even token
    return even_counts[0] + len(even_counts) - 1

t = int(input())
for _ in range(t):
    n = int(input())
    tokens = list(map(int, input().split()))
    print(min_operations(tokens))
```最初のループは、偶数トークンごとに 2 による除算のカウントを収集します。 ソートにより、必要な操作が最も少ないトークンに最初に焦点を当てることができます。 追加`len(even_counts) - 1`Fusion を使用して残りの偶数トークンを効率的に組み合わせることができます。

 ## 特殊なケース

 入力用`[16, 8, 4]`、アルゴリズムは分割をカウントします。`16→4`、`8→2`、`4→1`。 並べ替えると得られるもの`[1, 2, 3]`。 最小限の操作:`1 + 2 = 3`。 これは予想される最小シーケンスと一致します: ヒューズ`4`そして`8`次に、縮小し、融合します`16`そしてreduceして、すべての奇数を効率的に生成します。 

入力用`[1, 3, 5, 7]`、すべてのトークンは奇数です。 アルゴリズムは偶数を見つけられず、次の値を返します。`0`すぐに、不要な操作を回避します。 これは、ゼロオペレーションのエッジケースを正しく処理することを示しています。
