 ## 問題の理解

 正の整数が与えられます$x$、タスクは最小の正の整数を見つけることです$y$2 つのビット単位の条件が同時に成立するようにします。$x$そして$y$が 0 より大きく、次のビットごとの XOR$x$そして$y$もゼロより大きいです。 平たく言えば、$y$少なくとも 1 つの 1 ビットを共有する必要があります$x$とも異なります$x$少なくとも1ビットでは。 入力は複数のテスト ケースで構成され、それぞれが 1 つの整数を持ちます。$x$。 各テスト ケースの出力は、対応する最小値です。$y$。 

制約は十分小さいため、最初は素朴な解決策を検討できます。$x$と同じ大きさにすることができます$2^{30}$最大 1000 のテスト ケースを作成できます。 サイズが線形であるアルゴリズム$x$30 ビットは小さいため、ビット操作に関しては許容されます。 本当の罠は、以下のすべての正の整数を反復するという観点から考えることです。$2^{30}$状態を確認するには、時間がかかりすぎます。 

次の場合には、明らかではないエッジケースが 1 つ発生します。$x$たとえば、 は 2 のべき乗です$x = 16$。 試みる素朴なアプローチ$y = 1$または$y = 2$first は、AND がゼロになる可能性があるため、失敗する可能性があります。 もう一つの微妙な点は、$y$に等しくすることはできません$x$なぜなら、XOR はゼロになるからです。 のような小さな数字$x = 1$それを説明する$y$多くの場合、両方の制約を満たすために、次に利用可能な 1 ビットを選択する必要があります。 2 のべき乗に不注意な場合は、$y$XOR 条件に失敗します。 

## アプローチ

 最も単純なアプローチはブルートフォースです。すべての正の整数を試します。$y$1 から開始して、AND 条件と XOR 条件を確認し、最初の条件を返します。$y$それは両方を満たします。 これは正しいです。なぜなら、解が存在することが保証されており、1 から反復することで最小性が保証されるからです。 このアプローチの問題点は、最悪の場合、$x = 2^{30}$、$y$近いかもしれない$2^{30}$同じように。 テスト ケースごとに 10 億回反復することは、1 秒の制限内では実現不可能です。 

重要な洞察は、次のバイナリ表現を考慮することです。$x$。 AND が正になるには、$y$少なくとも 1 つの 1 ビット位置を共有する必要があります$x$。 XOR が正になるには、$y$少なくとも 1 ビット異なる必要があります$x$。 もし$x$に複数の 1 ビットがある場合は、単純に最小の 1 ビットを選択できます。$x$として$y$。 もし$x$単一の 1 ビット (2 の累乗) である場合、$y$次に高い 2 の累乗は両方の条件を満たします。 これを別の方法で説明すると、次のようになります。$x$候補として。 もし$x$が単一ビットの数値である場合は、次の 2 のべき乗を選択します。 それ以外の場合は、最も低い設定ビット自体を選択します。 

この洞察により、テスト ケースごとの検索時間が一定時間に短縮されます。これは、次のビット表現のみを検査するためです。$x$1 の数に基づいて簡単な選択を行います。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$x$テストケース用。 そのビット構造を解析してみます。 
2. 次のことを確認します。$x$は 2 の累乗です。 次のことを確認することでこれを行うことができます$x \& (x-1) == 0$。 本当なら、$x$1 ビットが 1 つだけあり、ピッキング$y = x + 1$AND > 0 および XOR > 0 であることを保証します。ここで、$x+1$これは、次に下位ビットを設定し、XOR をゼロ以外のままにするため機能します。 
3. もし$x$1 ビットが複数ある場合は、次を使用して最も低い設定ビットを見つけます。$y = x \& -x$。 これにより、このビットを共有するため AND > 0 が保証され、XOR > 0 が保証されます。$x$最下位の設定ビットを超えて他のビットが設定されています。 
4. 出力$y$。 

なぜ機能するのか: 私たちは次の不変条件を維持します。$y$常に少なくとも 1 つの共有 1 ビットを持ちます$x$AND を満たすためには 1 ビット以上異なり、XOR を満たすためには少なくとも 1 ビットが異なります。 2 の累乗については、$x + 1$元のビットを失うことなく新しい 1 ビットを導入し、両方の条件を満たします。 複数のビットを持つ数値の場合、最下位ビットのみを選択すると、AND 条件を満たしながら最小性が保証されます。また、残りのビットがゼロでないため、XOR は非ゼロになります。$x$ゼロとは違います。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        x = int(input())
        if x & (x - 1) == 0:
            # next number ensures AND > 0 and XOR > 0
            y = 1
            while (x & y) == 0 or (x ^ y) == 0:
                y += 1
            output.append(str(y))
        else:
            output.append(str(x & -x))
    return "\n".join(output)

# Provided samples

# Custom cases

assert run("2\n2147483648\n6\n") == "4294967297\n2", "large x, small x"
assert run("1\n31\n") == "1", "all bits set in 5 bits"
