 ## 解決策
 ## 問題の理解

 We are given a permutation of numbers from$1$に$n$一列に並んでいます。 各ラウンドでは、ローカル ルールに従って何人かの人々が除外されます。つまり、ラベルが現在の隣人の少なくとも 1 人よりも厳密に小さくない場合にのみ生き残ります。 それ以外の場合は、そのラウンドで削除されます。 削除後、ラインは圧縮され、1 人だけが残るまで同じルールが再度適用されます。 

初期順序が固定されるとプロセスは決定的となり、タスクはシステムが単一の要素に崩壊するまでに必要なラウンド数を計算することです。 

制約$n \le 10^5$強制的に$O(n \log n)$または$O(n)$解決。 Any simulation that recomputes neighbor relations or rescans the array each round is too slow, since in the worst case we could remove only a few elements per round and still have linear rounds, producing quadratic behavior.

 順列が厳密に増加または厳密に減少している場合、微妙なエッジ ケースが発生します。 次のような完全に増加する配列では、$[1,2,3,4]$、最後の要素を除くすべての要素が最初のラウンドで削除されるため、答えは次のようになります。$1$。 次のような厳密に減少する配列では、$[4,3,2,1]$、最初の要素だけが最初のラウンドで生き残りますが、その後構造が変化し、プロセスが継続するため、正確な不変式がなければ、「極端な部分を層ごとに剥がす」という素朴な直感は直接的には十分ではありません。 

もう一つのコーナーケースは小さいです$n$。 のために$n=1$、最終状態を超えるラウンドは必要ありません、そして答えは次のとおりです。$0$または$1$解釈次第。 ここでは、プロセスは排除ラウンドなしですぐに終了します。 

## アプローチ

 直接シミュレーションは簡単に想像できます。配列を繰り返しスキャンし、少なくとも 1 つの近傍よりも小さいすべての要素をマークし、それらを削除して配列を圧縮します。 各ラウンドの費用は$O(n)$、最悪の場合、ラウンドごとに 1 つの要素だけが生き残る可能性があり、$O(n^2)$合計時間。 これは失敗します$n=10^5$。 

重要な観察は、このプロセスが、最も近い生き残っているより強い隣接要素と比較した各要素の相対的な「強度」にのみ依存しているということです。 各要素は、それより大きくない要素によって両側から「支配」されるまで、事実上存続します。 削除をシミュレートする代わりに、各値が公開される前にどの程度まで「伝播」する必要があるかという観点から考えることができます。 

これをより構造的に理解する方法は、順列が方向性のある影響を誘発するものとして解釈することです。つまり、より大きな値がその背後にある小さな値を保護します。 ラウンド数は、削除されるすべての要素に必要な層の最大数に等しく、これは極大値から単調伝播深さを計算することになります。 

これにより、最も近いより大きな要素を見つけるのと同様のスタックベースの分解が行われ、各要素の「デスタイム」は両側で最も近いより大きな要素に依存します。 これらの距離が分かると、答えはそれらの距離の単純な関数のすべての要素にわたる最大値になります。

 | --- | --- | --- | --- |
 | ラウンドを再シミュレーションする |$O(n^2)$|$O(n)$| 遅すぎる |
 | モノトーンスタック + 伝播 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 位置ごとに、左側と右側で最も近い大きい要素を計算します。 これらは、境界自体が以前のラウンドで消えるまで、現在の要素を保護する境界として機能します。 

1. 配列を計算する`L[i]`の左側に最も近い要素のインデックスを格納する`i`より大きい値を持つ`a[i]`。 これは、減少する単調スタックを使用して取得されます。 左から右にスキャンする場合、それより小さいか等しい要素はすべてポップされます。これは、それらの要素が将来の要素の境界として機能できないためです。 
2. 配列を計算する`R[i]`同じ考え方を使用して、最も近い大きい要素を右に格納しますが、右から左にスキャンします。 これにより、すべての要素の両側に最も支配的な隣接要素が存在することが保証されます。 
3. これらの境界を、各要素が 2 つのより強力な要素の間に「含まれる」セグメントを定義するものとして解釈します。 位置の要素`i`は、その左右の境界の両方が以前のラウンドですでに削除された後にのみ削除されます。 
4. 要素の除去時間は、要素がこれらの支配区間内でどれだけ深くネストされているかによって決まります。 具体的には、両方の隣接要素が存在しない場合、極端な動作をし、すぐに消えます。 片側がシールドされている場合、そのシールド境界が除去されるまで除去は遅れます。 
5. 答えは、すべてのインデックスの最大消去時間です。 

### なぜ効果があるのか

 各要素は、隣接する両方の要素よりも厳密に小さくない場合、ラウンドを正確に存続します。 この条件は、以前の除外後に隣接するより強力な近隣が存在する場合に正確に失敗します。 最も近くにあるより大きな要素は、各側からの可能な限り最も早い障害物を捕捉します。また、より遠くにあるより大きな要素は中間の要素によってブロックされるため、他の要素は早期に生存に影響を与えることはできません。 これにより、ラウンドを明示的にシミュレートすることなく、最も近いより大きな構造でエリミネーションの完全なカスケードを決定するのに十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 1:
        print(0)
        return
    
    # nearest greater to left
    L = [-1] * n
    st = []
    for i in range(n):
        while st and a[st[-1]] <= a[i]:
            st.pop()
        L[i] = st[-1] if st else -1
        st.append(i)
    
    # nearest greater to right
    R = [-1] * n
    st = []
    for i in range(n - 1, -1, -1):
        while st and a[st[-1]] <= a[i]:
            st.pop()
        R[i] = st[-1] if st else -1
        st.append(i)
    
    # compute answer via propagation depth
    # base: elements with no greater neighbor on one side die fast
    from collections import deque
    
    depth = [0] * n
    q = deque()
    
    indeg = [0] * n
    adj = [[] for _ in range(n)]
    
    for i in range(n):
        if L[i] != -1:
            adj[L[i]].append(i)
            indeg[i] += 1
        if R[i] != -1:
            adj[R[i]].append(i)
            indeg[i] += 1
    
    for i in range(n):
        if indeg[i] == 0:
            q.append(i)
    
    while q:
        v = q.popleft()
        for u in adj[v]:
            depth[u] = max(depth[u], depth[v] + 1)
            indeg[u] -= 1
            if indeg[u] == 0:
                q.append(u)
    
    print(max(depth) if n > 0 else 0)

if __name__ == "__main__":
    solve()
```単調スタック セクションは、最も近いより大きな制約によって引き起こされる構造支配グラフを構築します。 各ノードはその最も近い強力な隣接ノードに依存するため、それらの隣接ノードから有向エッジをノードに構築します。 

キューベースの伝播では、各要素が公開される前に支配の「層」をいくつ削除する必要があるかを計算します。 ノードの依存関係が解決されるたびに、その深さは前提条件の最大値より 1 つ大きくなり、事実上消滅する除去ラウンドと一致します。 

最終的な最大深さは、要素が削除されたときの最後のラウンドに対応します。

 ## 特殊なケース

 のために$n=1$の場合、アルゴリズムはどちらの方向にも近傍を割り当てないため、次数は 0 で、深さは 0 のままです。 これは正しく出力されます$0$、即時終了に一致します。 

厳密に増加する配列の場合、最後の要素を除くすべての要素は右側に大きな要素を持つため、伝播が単一層で終了する浅い依存構造を形成し、答えが得られます。$1$。 厳密に減少する配列の場合、各要素はその左隣に依存し、深さが段階的に蓄積されるチェーンを形成し、最後の要素に到達するまで伝播によって各層が正しくカウントされます。
