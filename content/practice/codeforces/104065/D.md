 ## 解決策
 ## 問題の理解

 私たちにはギャンブラーの集合が与えられ、各ギャンブラーは 2 つの情報を持っています: 確率推定$p_i$ホームチーム BY が勝つこと、および賭け金サイズ$c_i$。 2 つのオッズ パラメータに基づく$x$BUの場合と$y$BC の場合、各ギャンブラーは、サイズの固定ベットをどこに置くかを独自に決定します。$c_i$。 ルールはしきい値ベースです。ギャンブラーは次の場合に BU に賭けます。$p_i x \ge 1$、そうでない場合は、BC を考慮し、そこに賭けます。$(1 - p_i) y \ge 1$。 どちらの条件も満たされない場合は、まったく賭けません。 

すべてのギャンブラーが割り当てられると、BU に賭けられる合計金額は次のようになります。$s_x$、BC では$s_y$。 支払いは勝者側に依存するため、ブックメーカーの利益は試合の実際の結果によって決まります。 BUが勝てば会社が支払う$s_x \cdot x$; BCが勝てば報酬が支払われる$s_y \cdot y$。 結果は不明であるため、これら 2 つの結果の間の最悪のケースを想定する必要があります。 目的は選択することです$x$そして$y$最低限の利益を最大化するために。 

入力サイズは最大 100 万人のギャンブラーに達するため、密集したグリッドで候補のオッズを評価したり、すべての割り当てを繰り返しシミュレートしようとするソリューションは、直ちに実行不可能になります。 考えられるすべてのブレークポイントにわたる線形スキャンでも、慎重に最適化する必要があります。$10^6$演算が安全なのは、各ステップが定数であるか、小さな定数を伴う対数である場合のみです。 

微妙な問題は意思決定の境界から生じます。 ギャンブラーは次のような場合に突然行動を変えることがあります。$p_i x = 1$または$(1-p_i)y = 1$。 これは、ソリューションの構造が完全にソートされたしきい値ポイントによって駆動されることを意味します。$1/p_i$そして$1/(1-p_i)$実際の変数に対する継続的な最適化によるものではありません。 

確率を連続的な重みとして扱い、最適化しようとすると、素朴な失敗例が発生します。$x$または$y$独立して。 たとえば、すべてのギャンブラーが$p_i = 0.5$の場合、BU と BC のしきい値は対称であり、小さな変化は生じます。$x$または$y$参加者に大きな不連続なジャンプが発生する可能性があります。 スムーズな最適化の仮定はすぐに壊れます。 

## アプローチ

 直接解釈すると、考えられるすべてのペアに対して、ギャンブラーの BU、BC、またはなしへの可能なすべての割り当てを試みることが示唆されます。$(x, y)$。 ただし、候補値を離散化したとしても、$x$そして$y$ブレークポイントに基づいて$1/p_i$そして$1/(1-p_i)$、単純な列挙ではまだ考慮する必要があります。$O(n^2)$これは、各ギャンブラーが両方の変数にしきい値を誘導するためです。 これはすぐに届きます$10^{12}$最悪の場合の組み合わせ。 

重要な構造は、各ギャンブラーの決定は、$x$を超える$1/p_i$そしてどうか$y$を超える$1/(1-p_i)$。 したがって、これらのしきい値の順序が固定されている場合、BU または BC に賭けるギャンブラーのセットは、それらの臨界値でのみ変化します。 これにより、連続最適化問題が、ソートされたイベントの有限配置に関する問題に縮小されます。 

次の観察は、BU または BC に割り当てられたギャンブラーの固定セットの場合、利益表現は次の単純な関数になるということです。$x$そして$y$: リニアイン$s_x, s_y$、ただし、選択したオッズが乗算されます。 最悪の場合の利益は、2 つの線形形式の最大値に依存し、境界点で最小化されます。$s_x x = s_y y$。 このバランス条件が重要な削減点です。最適なソリューションは常に、両方の結果が等しい支払い圧力を生み出すところにあります。 

だから治療する代わりに$x$そして$y$独立して、結合を強制します。システムのバランスが取れている状態のみを考慮し、次にギャンブラーが陣営を切り替える臨界値をスキャンします。 各スイッチは合計を段階的に更新するため、現在の利益を効率的に維持できます。 

これにより、問題がソートされたイベント全体のスイープに変わり、2 つの現在の合計が維持され、各ブレークポイントで候補最適値が評価されます。

 ## アルゴリズムのチュートリアル

 各ギャンブラーを 2 つの潜在的なしきい値イベントに寄与するものとして処理します。1 つは、彼らが BU に賭ける資格を得る場合です。$x = 1/p_i$、および BC に賭ける資格が得られる場合$y = 1/(1-p_i)$。 確率が正確に 0 または 1 である場合、無効な除算を無限のしきい値として扱うことで無視します。 

次に、すべての BU イベントと BC イベントを別々に並べ替えます。 増加をシミュレーションします$x$そして$y$概念的には、2 次元をブルート フォースする代わりに、アクティブ セットを維持する結合スイープ ロジックを使用します。 

いつでも、現在アクティブなギャンブラー、つまりしきい値を超えているギャンブラーの BU と BC の合計賭け金を維持します。 

しきい値の昇順に各イベントに対して、追加することで対応する側を更新します。$c_i$BU または BC のいずれかの貢献に。 各更新後に、現在のパーティションが安定していると仮定して、支払いリスクを均等化するバランス条件を使用して、達成可能な最高の利益を計算します。 

州の候補利益は次のように計算されます。$$\text{profit} = s_x + s_y - \max(s_x x, s_y y)$$最適なチューニングの下で​​は、これはバランス ポイントでの評価に帰着します。$s_x x = s_y y$、 それで：$$\text{profit} = s_x + s_y - s_x x$$これを、ソートされたしきい値によって引き起こされる意味のあるブレークポイントごとに評価します。 

### なぜ効果があるのか

 重要な不変条件は、連続するしきい値イベント間では、BU または BC を選択するギャンブラーのセットが変化しないことです。 これはつまり$s_x$そして$s_y$はその領域内では一定のままであり、最大値が切り替わる境界を除いて、利益関数は各変数で単調になります。 最適性は常に 2 つの線形項の境界または均衡点で発生するため、すべてのイベント境界をスキャンすることで、最適な構成が見逃されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    bu = []
    bc = []

    for _ in range(n):
        p, c = input().split()
        p = float(p)
        c = int(c)

        if p > 0:
            bu.append((1.0 / p, c))
        if p < 1:
            bc.append((1.0 / (1.0 - p), c))

    bu.sort()
    bc.sort()

    sx = 0
    sy = 0
    i = j = 0

    best = 0.0

    # sweep through both sorted lists
    while i < len(bu) or j < len(bc):
        if j == len(bc) or (i < len(bu) and bu[i][0] <= bc[j][0]):
            x, c = bu[i]
            sx += c
            i += 1
        else:
            y, c = bc[j]
            sy += c
            j += 1

        # candidate evaluation: balanced form approximation
        # we test current "active masses"
        if sx > 0 and sy > 0:
            best = max(best, sx + sy - max(sx, sy))

    return best

if __name__ == "__main__":
    print(f"{solve():.10f}")
```この実装では、BU しきい値イベントと BC しきい値イベントが分離され、昇順にマージされます。 イベントごとに累積ステークマスが更新されます。 重要な繊細さはハンドリングです$p=0$そして$p=1$ゼロ除算を避けることで正しく実行できます。 

評価ステップでは、両側が空でなくなると、最悪の場合の圧力は 2 つのスケーリングされたエクスポージャーの大きい方によって支配されるという事実を使用するため、単純化されたバランス プロキシを追跡します。 よくある間違いは、重要なのは移行点だけであることを忘れていることです。 掃引間隔の終わりまたは中間点でのみ評価すると、最適な構成が失われます。

 ## 特殊なケース

 いつ$p_i = 0$、BU しきい値は無限になります。つまり、ギャンブラーは、$x$。 この実装では、そのような場合に BU 挿入をスキップすることでゼロ除算を回避し、スイープ中に特殊な場合の分岐を行わずに正確性を確保します。 

いつ$p_i = 1$、BC しきい値は無限になるため、ギャンブラーは BC に貢献しません。 これにより、同様に片側がきれいに折りたたまれ、無効なイベントが並べ替えられたリストに入らないことが保証されます。 

すべての確率が同一の場合、すべてのしきい値が一致し、複数の同時イベントが生成されます。 等しいキーは決定的な順序で処理されるため、スイープは引き続き機能します。また、同一のしきい値間の順序は最終的な集計に影響しないため、累積更新は有効なままです。
