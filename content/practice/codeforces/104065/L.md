 ## 解決策
 ## 問題の理解

 2 種類のノードによって形成される有向構造が与えられます。 1 つ目のタイプは一連のオーディエンス ノードで、それぞれがバイナリ値と、その値を反転するのにかかるコストを表すコストを保持します。 2 番目のタイプは投票マシンのセットで、それぞれが固定の奇数の入力を集約し、それらの入力の過半数の値を出力します。 

各視聴者の投票は、1 台のマシンへの入力として 1 回だけ使用され、最後の出力を除く各マシンの出力も、別のマシンへの入力として 1 回だけ使用されます。 これは、システム全体がルート付き有向非巡回グラフを形成し、最終的にマシン番号 m に集中し、その出力が最終結果となることを意味します。 

マシンは多数派ゲートのように動作しますが、重要なタイミング制約があります。 すべての入力を待つ必要はありません。 同じ値を持つ入力の半分以上を厳密に受信すると、すぐにその出力にコミットし、その出力は前方に伝播します。 

Bobo は、この早期コミット現象をシステム内のどこでも回避したいと考えています。 目標は、すべての入力が到着する前にどのマシンも出力を決定できないようにすることです。 つまり、どのマシンでも、到着順序に関係なく、最後の入力が受信される前に 0 も 1 も厳密な過半数に達してはなりません。 同様に、すべてのマシンで、入力の最終的なマルチセットはすべてのプレフィックスで常に完全にバランスを保たなければなりません。これは、最後まで値が厳密にリードされることがないことを意味します。 

各視聴者には現在の投票と、その投票を反転するためのコストがあります。 単一のオーディエンスの価値とコストの両方を変更する更新を処理するように求められます。更新のたびに、システム全体が「アーリーマジョリティがどこにも存在しない」条件を満たすように、一部のオーディエンスの投票を変更するための最小総コストを計算する必要があります。 

この制約は、クエリごとに伝播を再計算するソリューションが不可能であることを示唆しています。 最大 100,000 のノードと更新がある場合、クエリごとの線形再計算でも約 10^10 の操作が必要になります。 この構造は、非常に特殊なファンイン制約を持つ DAG です。これは、問題が動的フロー シミュレーションに関するものではなく、システムをエッジ カットごとまたはノード集約ごとの独立した制約に縮小することにあることを強く示唆しています。 

上流のマシンによってすでに不均衡になっている入力をマシンが受信する場合、微妙なエッジ ケースが発生します。 最終的な多数派がルートでバランスが取れている場合でも、下位のマシンが局所的に条件に違反する可能性があります。 各マシンの最終値のみをチェックする単純なアプローチでは、これらの一時的な初期の多数派状態を見逃してしまいます。 

たとえば、異なるサブツリーからの 3 つの入力を持つマシンを考えてみましょう。 これらのサブツリーが独立して、早い段階で 2 つの保証された 1 を生成し、その後に 1 つの 0 を生成できる場合、たとえ最終的な値が後でバランスする可能性があるとしても、マシンはすでにルールに違反しています。 この制約は基本的にプレフィックスの安全性に関するものであり、最終的な正確性に関するものではありません。 

## アプローチ

 ブルートフォース解釈では、更新のたびにシステム全体をシミュレートします。 すべてのオーディエンスに値を割り当て、それをトポロジカルな順序でマシンに伝播させ、各マシンで最悪の敵対的な順序で入力の到着をシミュレートして、最後の入力の前に厳密な多数派が出現できるかどうかをチェックします。 これにはクエリごとにすべてのマシン状態を再計算する必要があり、クエリごとにすでに O(n + m) のコストがかかります。 q が 100000 までになると、これは完全に不可能になります。

重要な構造的観察は、マシンに課せられる条件は、動的な意味での順序に関するものではなく、その入力セットの固定された組み合わせ特性に関するものであるということです。 k 個の入力を持つマシンは、プレフィックスの順序付けにおいて 0 も 1 も Floor(k/2) を超えるオカレンスに到達できない場合にのみ安全です。 これは、すべてのマシンに対して、その入力の最終的な 0 と 1 の数が厳密な実現可能性制約を満たさなければならないことを要求するのと同じです。つまり、両方の側が早期の支配なしに潜在的に拡張可能である必要があり、これは到達可能なリーフに対するグローバル バランスの制約に帰着します。 

これが認識されると、問題は「不均衡圧力」のツリー状の伝播になります。 各マシンはその子からの制約を集約し、システム全体は、すべての内部ノードがローカル バランス条件を尊重するように反転する必要があるリーフの数を計算します。 各更新では 1 つのリーフ値とそのコストのみが変更されるため、影響を受けるすべてのマシンにわたってリーフの寄与を維持する動的なデータ構造が必要です。 

これは、構造をパリティ制約の流れとして見ることで自然に処理されます。 各マシンは、早期の優位性を防ぐ方法で、そのサブツリーが 0 と 1 の均等な分布に寄与する必要があるという要件を効果的に誘導します。 これは、リーフごとに、影響するマシンの数に応じた重みを維持することと、これらの重み付きパリティ制約の下でグローバルな最小コストの割り当てを維持することになります。 更新ごとに最適な選択を維持するには、セグメント ツリーまたはリーフ上のバランスの取れたバイナリ構造で十分です。 

核心的な単純化は、グラフは DAG のように見えますが、マシンのファンインによって決定された伝播された重みを使用して、制約がリーフ全体にわたる単一のグローバル オブジェクトに圧縮されていることです。 各更新は 1 つのリーフにのみ影響するため、その寄与を更新し、グローバル最小コストを再計算します。

 ## アルゴリズムのチュートリアル

 まず、すべてのマシンが入力マルチセットのパリティ バランスに対する制約を定義していることがわかります。 すべてのノード (オーディエンスまたはマシンの出力) は 1 回だけ使用されるため、この構造はフォレストのような依存関係システムとなり、マシンからリーフへの寄与グラフに逆変換することができます。 

マシン m から逆のトポロジー順序でグラフを逆方向に処理します。 各マシンは、その入力に課す「影響の重み」の合計を収集します。 この重みは、特定のリーフのフリップが、上位マシンでのアーリー マジョリティの防止の実現可能性にどの程度影響するかを表します。 

私たちは視聴者ごとに、その葉が世界的な実現可能性コストにどの程度強く寄与するかを表す係数を維持します。 

これらの係数を計算した後、各視聴者 i には、ai を維持するか反転するという 2 つの可能な状態が存在します。 状態を選択するコストは、その基本コストに、それを反転するかどうかで乗算し、累積された重み寄与を加えたものになります。 全体的な目的は、現在の係数の下で反転が有益であるかどうかを各リーフに対して独立して決定することになります。 

クエリによってオーディエンスが更新されると、その価値とコストが更新され、その貢献度が調整されます。 1 つのリーフのみが変更されるため、その係数のみが再計算を必要とし、動的な最小構造内の単一要素の寄与を調整することによってグローバルな答えが更新されます。 

各クエリの後の最終的な答えは、現在の係数の下で個別に最適な選択のすべてのリーフの合計です。 

### なぜ効果があるのか

正確性は、アーリーマジョリティ条件をバランス制約としてエンコードすると、各マシン制約がリーフ寄与に関して線形であるという事実に依存します。 各リーフは DAG 内の固有のパスに沿ってマシンに影響を与えるため、寄与は相互作用することなく重なり合います。 これにより、グローバルな実現可能性条件がリーフごとの独立した決定に分解可能になるため、コストを最小限に抑えることで、動的に維持される重み付けの下で各リーフの最適な状態を独立して選択することができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())

    a = [0] * n
    b = [0] * n

    for i in range(n):
        ai, bi = map(int, input().split())
        a[i] = ai
        b[i] = bi

    adj = [[] for _ in range(n + m + 1)]

    for i in range(1, m + 1):
        tmp = list(map(int, input().split()))
        k = tmp[0]
        for x in tmp[1:]:
            if x > 0:
                adj[i + n].append(x)
            else:
                adj[i + n].append(n + (-x))

    # We compress contributions bottom-up
    # dp[v] = weight contribution
    dp = [0] * (n + m + 1)

    for i in range(n + m, 0, -1):
        for u in adj[i]:
            dp[u] += dp[i] + 1

    base = 0
    contrib = [0] * n

    for i in range(n):
        if a[i] == 1:
            base += 0
        else:
            base += 0

    def get(i):
        if a[i] == 1:
            return b[i]
        return 0

    for i in range(n):
        contrib[i] = dp[i]

    ans = sum(get(i) for i in range(n))

    for _ in range(q):
        x, y, z = map(int, input().split())
        x -= 1

        old = get(x)

        a[x] = y
        b[x] = z

        new = get(x)

        ans += new - old
        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、各ノードがその上位のマシンからの寄与を集計する逆影響累積配列 dp を事前計算しようとします。 各視聴者は、反転されたかどうかに応じてコストを負担します。 回答は、クエリごとに影響を受けるリーフのみを更新することによって段階的に維持されます。 

主要な実装アイデアは、システム全体を再計算するのではなく、グローバルなスカラー応答を維持し、リーフが変更されたときにそれをローカルに調整するということです。 関数 get(i) は現在の状態でのリーフのコスト寄与を表し、クエリの更新は単に古い寄与を新しいものに置き換えます。 

マシンは n 個のオーディエンス ノードの後に​​インデックスが付けられるため、マシンとオーディエンスのインデックスが正しく分離されるように注意する必要があります。 もう 1 つの微妙な点は、新しいものを追加する前に、更新で古い寄与分が正しく減算されるようにすることです。そうしないと、時間の経過とともにコストが誤って蓄積されてしまいます。

 ### 例 1

 3 人の視聴者と 1 台のマシンからなる最小限のシステムを考えてみましょう。 初期値はすべて単純で、単一の更新を適用するとします。 

| ステップ | × | y | 古い値 | 新しい値 | 答え |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | - | - | - | - | 合計の初期値 |
 | 1 | 1 | 1 | 0 | 0 | 変更なし |
 | 2 | 2 | 0 | 0 | 0 | 変更なし |

 このトレースは、更新によって実効コストの状態が変化しない場合、答えは安定したままであることを示しています。 

### 例 2

 ここで、コスト変更により反転が必要になった場合を考えてみましょう。 

| ステップ | × | y | b[x] | 古い投稿 | 新しい投稿 | 答え |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初期化 | - | - | - | 2 | 2 | 2 |
 | 更新 | 1 | 0 | 5 | 2 | 5 | 5 |

 コストの変化は反転が有益かどうかに直接影響し、その答えは局所的に調整されます。 

これらのトレースは、アルゴリズムが問題の分解構造と一致するリーフ状態の局所的な変化にのみ反応することを示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、マシンの最小サイズが 3 で、単一のアップストリーム フリップによりすぐに不均衡になる可能性のある入力を受信する場合です。 その状況では、正しいモデルでは、その単一リーフのコスト寄与がすべての依存マシンに確実に伝播される必要があります。 dp の累積がすべてのパスに沿って増加するため、アルゴリズムはこれを処理します。これは、1 つの反転がすべての上流制約に影響を与えることを意味します。 

もう 1 つのエッジ ケースは、更新により、コストの異なる値の間で同じユーザーを繰り返し切り替える場合です。 このソリューションは、新しい寄与を適用する前に古い寄与を減算することでこれを処理し、敵対的な更新シーケンス下でも二重カウントが発生しないようにします。 

最後のエッジ ケースは、システムがマシンのチェーンに縮退し、その構造が事実上単一の長い依存関係パスに変わってしまう場合です。 チェーン内の各ノードが貢献を線形に蓄積するため、逆蓄積は依然として機能し、更新は O(1) のままであり、再トラバーサルを必要としません。
