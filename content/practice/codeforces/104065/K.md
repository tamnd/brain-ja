 ## 問題の理解

 2 つの文字列が与えられます: パターン文字列`s`とテキスト文字列`t`。 タスクは、開始位置が何個あるか数えることです。`t`～の発生を引き起こす`s`連続した部分文字列として。 重複は許可されているため、すべての有効な一致が独立して答えに寄与します。 

これを直接確認する方法は、スライドしてみることです。`s`あらゆる可能な配置にわたって`t`すべての文字が一致するかどうかを確認します。 出力は、完全に一致するアライメントの合計数です。 

制約は極端です。両方の文字列の長さは次のとおりです。$10^7$。 これにより、ネストされた方法で文字を繰り返し比較するソリューションは除外されます。 アライメントごとのリニアスキャンであっても、最大で次のことを意味します。$10^{14}$最悪の場合、文字の比較が可能になりますが、これは実現不可能です。 

名目上の制限は大きいものの、メモリも精神的にきついです。 シーケンシャル アクセスと「低スペース」フレーミングに関する注記は、非常に大規模な連結やランダム アクセス パターンを必要とするマルチパス前処理のための完全なプレフィックス関数テーブルなどの大規模な補助構造の格納を避ける必要があることを示唆しています。 

微妙なエッジケースは、繰り返しの多い文字列から発生します。 もし`s = "aaaaa"`そして`t = "aaaaaaaaaa"`、すべての配置は重複して有効です。 単純な不一致早期終了戦略は、不一致がまれで比較が繰り返し再開されるため、依然として 2 次の動作に低下する可能性があります。 

もう 1 つのエッジケースは次のような場合です`s`長さは 1 です。すると、次のすべての文字が`t`は独立した一致チェックであり、答えは単純にその文字の頻度です。 これにより、スライディング実装で off-by-one エラーが発生することがよくあります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 あらゆるポジションについて`i`で`t`から`0`に`m - n`、比較します`s`部分文字列を使用して`t[i:i+n]`文字ごとに。 すべての文字が一致する場合、答えがインクリメントされます。 

これは、部分文字列の等価性の定義を直接強制するため、正しいです。 故障モードはパフォーマンスです。 各調整には最大で次のものが必要となる場合があります`n`比較、そして、`m - n + 1`最悪の場合の複雑さは次のとおりです。$O(nm)$。 どちらも最大で$10^7$、これは完全に不可能になります。 

重要な点は、シフトごとに文字を最初から再比較する必要がないということです。 パターン内で繰り返されるプレフィックス情報の構造により、部分一致を再利用できます。 不一致が発生した場合、ゼロからやり直すことなく、パターン内でどこまで「後退」できるかを知りたいと考えます。 

これはまさに、Knuth-Morris-Pratt アルゴリズムの接頭辞関数が捉えているものです。 最長の適切なプレフィックスをエンコードします。`s`これは、次のすべての接頭辞の接尾辞でもあります。`s`。 この情報を使用して、スキャンできます`t`一度、何文字維持するか`s`現在マッチングしております。 の各キャラクター`t`最大でも一定数のポインタ調整が発生します。`s`。 

プレフィックス配列のサイズが大きいため、メモリの問題は解決されます。`n`これは許容可能であり、スキャンは純粋にシーケンシャルです。

 ## アルゴリズムのチュートリアル

 KMP を使用して、テキスト上の 1 回のパスでのパターンの出現をカウントします。 

### ステップ

 1. 接頭辞関数を計算する`pi`文字列用`s`。 

ポジションごとに`i`、`pi[i]`～の最長の適切なプレフィックスを保存します`s[:i+1]`これはこの部分文字列の接尾辞でもあります。 この構造は、不一致の後、ゼロからやり直すことなくどこまでマッチングを継続できるかを示します。 
2. ポインタを初期化する`j = 0`、何文字かを表します`s`現在マッチングされているのは`t`。 
3. テキストをスキャンします`t`インデックスを使用して左から右へ`i`。 キャラクターごとに`t[i]`、現在の一致を延長しようとします。 
4. もし`t[i] != s[j]`を使用して繰り返しフォールバックします。`j = pi[j-1]`どちらかになるまで`j == 0`または一致が見つかりました。 

これにより、最初からやり直すのではなく、常に最長の有効な部分一致が保持されます。 
5. もし`t[i] == s[j]`、増分`j`1 ずつ増やして、一致したプレフィックスを拡張します。 
6. もし`j == n`、完全一致`s`位置で終了`i`。 答えをインクリメントしてリセットする`j = pi[j-1]`重複する一致を許可します。 

### なぜ効果があるのか

 あらゆる位置で`t`、変数`j`の最長プレフィックスの長さを表します`s`の処理されたプレフィックスのサフィックスと一致するもの`t`。 prefix-function は、不一致の後でも一致する可能性のある短いプレフィックスがすでにエンコードされていることを保証します。`pi`したがって、有効な位置合わせを見逃すことはありません。 すべての完全一致は現時点で 1 回だけ検出されます`j`到達する`n`、重複や漏れのない正確性を確保します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_pi(s):
    n = len(s)
    pi = [0] * n
    j = 0
    for i in range(1, n):
        while j > 0 and s[i] != s[j]:
            j = pi[j - 1]
        if s[i] == s[j]:
            j += 1
        pi[i] = j
    return pi

def solve():
    n, m = map(int, input().split())
    s = input().strip()
    t = input().strip()

    pi = build_pi(s)

    j = 0
    ans = 0

    for ch in t:
        while j > 0 and ch != s[j]:
            j = pi[j - 1]
        if ch == s[j]:
            j += 1
        if j == n:
            ans += 1
            j = pi[j - 1]

    print(ans)

if __name__ == "__main__":
    solve()
```実装は当然、プレフィックス関数の構築とストリーミング一致フェーズに分割されます。 プレフィックス配列はもう一度構築されます`s`、その後、スキャン中に再利用されます。`t`。 

メイン スキャンでは、現在のインデックスという 2 つの変数のみが維持されます。`s`そして解答カウンター。 フォールバック ループは不可欠です。これにより、不一致によって不必要に再起動が行われることがなくなります。 

よくある落とし穴はリセットを忘れることです`j`一致するものを見つけた後。 それなし`j = pi[j - 1]`、重複する一致は失われます。 もう 1 つの問題はインデックス作成です。`s[j]`の場合にのみ有効です`j < n`したがって、境界を超えてアクセスする前に等価性チェックを行う必要があります。これは、以下のチェックによって保証されます。`j == n`インクリメント直後。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、パターンに大きな自己オーバーラップがある場合です。 例えば、`s = "aaaa"`そして`t = "aaaaaaaa"`。 スキャン中に、`j`繰り返し 4 に到達し、4 にリセットされます。`pi[3] = 3`、すぐに継続できるようになります。 これにより、ほぼ完全に重複するものも含め、すべての有効な配置が確実にカウントされます。 

もう 1 つのケースは、次のような完全に不一致のテキストです。`s = "abc"`そして`t = "zzz..."`。 ここ`j`は繰り返しゼロに留まり、アルゴリズムはフォールバック ループに入らずに単純な比較のみを実行し、KMP の償却一定の動作を示します。 

3 番目のケースは、単一文字のパターンです。 このアルゴリズムは、プレフィックス構造を使用せずに出現回数をカウントするようにきれいに退化します。`j`は常に 0 または 1 のいずれかであり、`pi`は些細なことです。
