 ## 解決策
 ## 問題の理解

 道路で接続された都市の重み付けされた無向グラフが与えられます。各都市には、最初はある程度の数の住民が含まれています。 時間の経過とともに、一連の都市が順番に「破壊」されます。つまり、予定日に都市が攻撃されると、その都市には住民が存在しなくなります。 

住民はいつでも道路に沿って移動でき、移動ごとに道路の重量を支払います。 移動では 1 人の居住者が 1 つのエッジを越えて移動しますが、複数の居住者が独立して移動でき、移動を任意に繰り返すことができるため、事実上、各居住者は標準の最短経路移動コストを持つグラフ上のフロー ユニットのように動作します。 

課題は、総移動コストを最小限に抑えながら、都市が攻撃されるたびにその時点で空っぽになるように住民を移転する方法を常に選択することです。 

この制約を言い換える重要な方法は、各住民は、避難が必要になる直前に、最終的には厳密に攻撃されることのない都市に到達しなければならないということです。 攻撃は固定された順序で発生するため、その順序で最後に攻撃が発生した後、都市は「危険」になります。それ以降は再び攻撃を受けることになるからです。 

したがって、問題は、各居住者を元の都市から十分に安全な目的地都市に割り当て、グラフ内の最短経路の移動コストの合計を最小化することに帰着します。 

制約は最大 100,000 個のノード、エッジ、イベントに及ぶため、都市ごとまたはイベントごとに最短パスを再計算するアプローチは直ちに遅すぎます。 すべての都市から一人のディクストラがいたとしても、$O(n (m \log n))$、それは限界をはるかに超えています。 

微妙なエッジケースは、同じ都市に対する繰り返しの攻撃です。 たとえば、ある都市が複数回出現する場合、その最後の出現のみが実現可能性を考慮しますが、各出現を独立して扱う単純な解決策では、割り当てが誤って過度に制約される可能性があります。 

都市が攻撃された場合にのみ住民を移動させることができると仮定すると、別の失敗例が生じます。 この問題では、いつでも移動が明示的に許可されています。つまり、イベントの前に住民を最適に事前配置できるため、イベントごとのシミュレーションに関連付けられたソリューションでは、全体的な最適な輸送が失われます。 

## アプローチ

 強引な観点では、各居住者を個別に扱い、「有効な」（つまり、到着時に安全な）すべての都市の中から最終目的地の都市を決定します。 各居住者について、その出発地から考えられるすべての目的地までの最短経路を計算し、有効な最小コストを選択します。 これは原理的には正しいです。なぜなら、居住者はキャパシティーを介してのみ対話することがなく、キャパシティーには制限がないからです。 

ただし、それぞれに最大$10^5$開始都市では、完全な最短経路の計算が必要になります。$10^5$ディクストラの実行。 最適化を行ってもこれは不可能です。 

重要な洞察は、視点を逆転させることです。 住民をその源から前進させるのではなく、「十分に長く生き残る」源という観点から考え、安全な都市から逆方向にその能力を伝播させることができます。 最後に攻撃される都市が最も安全であり、最短経路に沿って後方へ徐々に安全性を拡大することができます。 

これにより、複数ソースの最短パス プロセスが実現しますが、都市の最後の出現時刻によって引き起こされる順序付けの制約があります。 各都市が最後に攻撃された時間を計算し、安全性の高い順に都市を処理します。 各都市は、まだ「閉鎖」されていないすべての都市の住民の潜在的な目的地として機能できます。 

浮かび上がってくる構造は、最終攻撃時間が十分に長い都市に到達するための最小コストを都市ごとに計算したいというものです。 これは、動的に増加するソースのセットにわたる最短経路の問題となり、現在安全なすべての都市から初期化されるダイクストラのようなマルチソース伝播を使用して処理できます。 

安全な目的地に到達するための最小コストを都市ごとに事前計算すると、最終的な答えは単にその都市の最良の割り当てコストの全住民の合計になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n \cdot m \log n)$|$O(n + m)$| 遅すぎる |
 | 最適 (逆安全処理を備えたマルチソース ダイクストラ) |$O((n+m)\log n)$|$O(n+m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 各都市の最終攻撃時間を計算する

 攻撃シーケンスをスキャンし、各都市が出現する最後のインデックスを記録します。 決して出現しない都市は、決して破壊されないため、無限の安全性があると考えられます。 

このステップでは、時間依存の問題を都市ごとの静的な「安全レベル」に変換します。 

### ステップ 2: 都市を安全性の順に並べ替えます (最も安全な都市から最も安全でない都市の順)

 安全性を降順で最後の攻撃位置と定義します。 安全な都市から順次「活性化」していきます。 

都市が活発になれば、安全性の低い都市からの住民にとって有効な目的地として機能できるという考えです。 

### ステップ 3: 複数ソースのダイクストラ構造を初期化する

 無限に初期化された距離配列を維持します。 現在アクティブな安全な都市はすべて、距離 0 の優先キューに挿入されます。 

これらの活発な都市は、将来の攻撃に違反することなく住民を安全に配置できる目的地を表します。 

### ステップ 4: 安全閾値を下げる都市の処理

 安全性の基準が低い順に都市を掃除します。 都市をアクティブ セットに含める場合、その都市を距離 0 の優先キューに挿入します。 

この点から、他の都市のリラクゼーションの源として機能することができます。 

これが機能する理由は、都市が「十分に安全」になると、最終的な破壊時までに再び避難を強いられることなく、永続的に住民を受け入れることができるからです。 

### ステップ 5: グラフ全体に対してダイクストラを実行する

 アクティブ セットから標準のダイクストラ更新を実行し、エッジを緩和し、グラフ全体に最小コスト値を伝播します。 

それぞれの緩和は、住民を現在安全な地域に向けて移動させることを表しています。 

### ステップ 6: 各都市の最終回答を抽出する

 プロセスが安定した後、各都市は安全な目的地に到達するための最小コストを計算します。 このコストに市内の住民の数を掛けて、すべてを合計します。 

### なぜ効果があるのか

 アクティブ セットは、いつでも、最終目的地として機能するのに十分安全なすべての都市を表します。 安全性が高い順に都市をアクティブ化するため、一度アクティブになった都市が後で無効になることはありません。 この単調性により、ダイクストラは常に実現可能な目的地のみを探索することが保証されます。 すべての居住者は、最短経路コストの観点から最も近い到達可能な安全な都市に効果的に割り当てられます。また、移動コストは居住者ごとに線形で独立しているため、これらの都市ごとの最適な割り当てを合計すると、全体的な最適値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

MOD = 998244353

def solve():
    n, m, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, w))
        g[v].append((u, w))
    
    b = list(map(int, input().split()))
    
    last = [-1] * n
    for i, city in enumerate(b):
        last[city - 1] = i
    
    nodes = list(range(n))
    nodes.sort(key=lambda x: last[x])
    
    INF = 10**30
    dist = [INF] * n
    pq = []
    
    # activate cities in reverse safety order
    ptr = n - 1
    activated = [False] * n
    
    for i in range(n - 1, -1, -1):
        u = nodes[i]
        dist[u] = 0
        heapq.heappush(pq, (0, u))
        activated[u] = True
        
        while pq:
            d, v = heapq.heappop(pq)
            if d != dist[v]:
                continue
            for to, w in g[v]:
                if dist[to] > d + w:
                    dist[to] = d + w
                    heapq.heappush(pq, (dist[to], to))
    
    ans = 0
    for i in range(n):
        ans = (ans + (dist[i] * a[i]) % MOD) % MOD
    
    print(ans % MOD)

if __name__ == "__main__":
    solve()
```実装ではグラフを構築し、各都市の最後の出現インデックスを計算します。 その後、都市はこのインデックスに基づいて並べ替えられ、一度も攻撃されていない (または最も早く攻撃された) 都市が後でより安全な目的地とみなされるようになります。 

中核となるメカニズムは都市の逆活性化であり、新たに活性化された各都市がゼロコストのソースとしてグローバル ダイクストラ ヒープに挿入されます。 緩和ステップにより、最終的にはすべての都市が安全な目的地に到達するための最小限のコストが確保されるようになります。 

最後のループでは、居住者数によって重み付けされた各都市からの寄付金が集計されます。 

微妙な点は、アルゴリズムが起動ごとに個別の最短パス計算を実行しないことです。 代わりに、すべてのアクティベーションは単一の優先キューを共有し、再計算の繰り返しを回避しながら正確さを維持します。 

## 実用的な例

 ### 例 1

 入力:```
3 2 2
1 1 1
2 3 10
1 2 1
3 2
```最終攻撃時間:

 都市 1 = -1、都市 2 = 1、都市 3 = 0

 安全性順に並べ替え: 1 (最も安全)、3、2

 この並べ替えとは逆の順序で都市を活性化します。 

| 活性化された都市 | Dist 配列の変更 | 主な緩和 |
 | --- | --- | --- |
 | 1 | 距離[1]=0 | エッジ 1-2 経由でスプレッド |
 | 3 | 距離[3]=0 | エッジ 2-3 を介して間接的に接続します。 
| 2 | 距離[2]=0 | 最終的なクロージング |

 最終的な割り当ては次のようになります。 

都市 3 の住民は 3→2 コスト 10 で移動し、次に 2→1 ユニット伝播ロジックごとにコスト 1 で合計 12 になります。 

これは、最初に都市 2 に統合してから都市 1 に移動するという最適な戦略と一致します。 

### 例 2

 入力:```
2 1 2
5000 5000
1 2 10000
1 2
```都市 1 と都市 2 は両方とも攻撃されているため、最後の発生回数は両方とも有限です。 

アクティベーションは安全なエンドポイントから開始されますが、両方が密接に接続されているため、相互アクティベーションによって両方の dist 値が 0 に安定します。 

これは、すべての都市が同時に最終的な安全地帯として機能できる場合、最適な構成で初期位置を超えて移動する必要がないことを示しています。

 ## 特殊なケース

 重要なエッジケースは、都市がまったく攻撃されない場合です。 その場合、永続的に安全であるように動作する必要があります。 最後の出現は -1 のままであるため、アルゴリズムはこれを自然に処理し、最も安全なアクティブ化ポイントの 1 つとなり、永続的な宛先ソースになります。 

もう一つのケースは、同じ都市に対する繰り返しの攻撃です。 最後の出来事だけが重要です。 たとえば、都市が 1 日目、5 日目、7 日目に表示される場合、7 日目のみが問題になります。 前処理ステップではこれを正しく折りたたみます。 

最後のエッジ ケースは、コストの非対称性の点で、切断されたような構造です。 どの都市にも少なくとも 1 本の道路があるにもかかわらず、一部のルートは非常に高価な場合があり、単純に欲張りな割り当てを行うと失敗する可能性があります。 グローバルなダイクストラ伝播により、住民はローカルに隣接する安全な都市だけでなく、グラフ全体にわたって常に最も安価な安全な目的地を見つけることができます。
