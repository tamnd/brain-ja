 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$各セルに 0 から 4 までの値が含まれるグリッド。すべての行とすべての列から正確に 1 つのセルを選択する必要があります。これは、行の列の順列を効果的に選択していることを意味します。 行の場合$i$列を選択します$p(i)$、収集された合計値は次の合計です。$a_{i, p(i)}$。 

この合計を計算した後、$S$、それを5人で均等に分け、残りは$S \bmod 5$寄付されています。 タスクは、1 つの最適な選択を計算することではなく、すべての有効な順列にわたって 5 を法とする剰余がどれかを決定することです。 

制約から得られる重要な観察点は次のとおりです。$n \le 1000$。 順列の数は$n!$、これは中程度の場合でも天文学的に大きくなります。$n$。 順列を列挙したり、サブセットに対して動的プログラミングを使用したりするソリューションは、直ちに不可能です。 典型的な許容可能なソリューションは大まかに実行する必要があります$O(n^2)$または$O(n^2 \log n)$、入力だけを読み取るのは$O(n^2)$。 

すべての値が同一であるか、多くの順列が同じモジュロ クラスを生成するように構造化されている場合、微妙なエッジ ケースが発生します。 たとえば、すべてのセルが 0 の場合、すべての順列は次のようになります。$S = 0$したがって、剰余 0 のみが可能であり、出力は次のようにする必要があります。`YNNNN`。 組み合わせの柔軟性によりすべての剰余が可能であると仮定する単純なアプローチは、ここでは正しくありません。 

別の特殊なケースは、値が 5 を法とする均一であるが同一ではない場合、たとえばすべての値が 2 である場合に発生します。この場合、任意の順列は次のようになります。$S = 2n$したがって、剰余クラスは 1 つだけ可能です。 これは、順列の自由だけではなく、値の構造が答えを制御することを示しています。 

## アプローチ

 ブルート フォース ソリューションでは、列のすべての置換を試行し、それぞれの合計を計算し、5 を法とする剰余を記録します。これは、有効な選択の定義に直接従うため、正しいです。 ただし、$n!$順列、さらには$n = 15$これはすでに実行不可能になっています。 それぞれの順列には次のものが必要です$O(n)$合計すると、合計作業量は次のようになります。$O(n \cdot n!)$、それは限界をはるかに超えています。 

重要な単純化は、実際にはどの順列が選択されるかは気にせず、行全体で選択された列インデックスのマルチセットのみを気にすることに気づくことから来ます。 各行には 1 つの数値が含まれ、各列は 1 回だけ使用されます。 これは、完全な 2 部グラフで完全に一致するものを選択することと同じですが、5 を法とする和のみを考慮します。 

すべてのエントリは 0 ～ 4 であるため、各セルの寄与は小さく、周期的なモジュロ 5 です。これは、正確な列の割り当てを記憶せずに、行の処理中に到達可能な剰余を動的に追跡することを示唆しています。 ただし、完全な割り当て状態はまだ大きすぎます。 

重要な洞察は、この問題は各行と列から要素を 1 つだけ選択することに相当しますが、モジュロ 5 では、選択された値の位置ではなく、選択された値のカウント分布のみが重要であるということです。 グリッドを行ごとの値のコレクションとして扱い、行の寄与をどのように再配置できるかを推論できます。 各行は列の置換に寄与しますが、モジュロ 5 で重要なのは、列の制約が満たされるように各行から 1 つの値を選択することです。 これは、加法重みモジュロ 5 を使用した順列選択のように動作するシステムで特定の剰余クラスが到達可能かどうかをチェックすることに帰着します。 

この構造により、剰余状態に対する多項式畳み込みのような DP への還元が可能になりますが、行と列ごとに 1 つのエントリを選択することで列を対称的に扱うことができるため、さらに単純化できます。 重要な唯一の不変式は、各列セットの 5 を法とする値の分布です。列ごとに 1 つだけ選択しているため、この問題は、合計が各剰余クラスに一致する順列を形成できるかどうかを確認するものと解釈できます。 

この問題に対するより直接的かつ標準的な観察は、グリッドは完全に一般的ですが、値は 5 を法として小さいため、行ごとに、列の選択によって考えられる寄与のマルチセットを追跡し、5 つの状態にわたる DP を使用して行を結合できるということです。 可能な合計のモジュロ 5 に対してブール DP を維持し、行ごとにすべての列の選択肢を使用して更新しますが、同じ列を 2 回選択しないようにする必要があります。 これは、完全な 2 部構造のモジュロ算術に対するこのような対称代入問題では、到達可能な和のセットは畳み込みによって集約された行単位の選択にのみ依存し、列制約は順列の存在を保証する以上にモジュロの到達可能性を制限しないという古典的な事実によって解決されます。これは完全な 2 部グラフに常に当てはまります。 

したがって、各行を独立して扱い、列の使用が順列対称性によって暗黙的に強制されるようにしながら、行の寄与を蓄積する DP を構築することで、各剰余クラス 0 ～ 4 が達成可能かどうかを計算できます。

 ## アルゴリズムのチュートリアル

 1. 各行について、そこから要素を 1 つだけ選択できる場合に、その行が 5 を法とする合計にどのように寄与するかを計算します。 

これは、列の選択が有効な順列の一部である可能性があるため、その行のすべての列値を考慮することによって行われます。 
2. ブール配列を維持する`dp`サイズ 5 の場合、`dp[r]`剰余を含む部分和を得ることが可能かどうかを示します`r`いくつかの行を処理した後。 

当初は、`dp[0] = True`、ゼロ和に寄与する行がないためです。 
3. 行を 1 つずつ処理します。 行ごとに一時配列を構築します`next_dp`すべて False に初期化されます。 
4. 以前に到達可能な各剰余について`r`、および各値に対して`v`現在の行で更新します`next_dp[(r + v) % 5] = True`。 

これは、行から 1 つのエントリを選択し、以前に到達可能なすべての合計を拡張することを表します。 
5. 行を処理した後、置換します。`dp`と`next_dp`。 
6. すべての行が処理された後、i 番目の文字が である 5 文字の文字列を出力します。`Y`もし`dp[i]`True、それ以外の場合`N`。 

これが機能する理由は、順列の存在のみを考慮する場合、列制約によって各行からどの値を選択するかが制限されないためです。 各行が正確に 1 つの列を選択している限り、完全な 2 部構造で後から常に個別の列を貪欲に割り当てることができるため、行ごとに 1 つの要素を選択すると、列の少なくとも 1 つの有効な置換に対応します。 したがって、モジュロの到達可能性は行単位の選択のみに依存し、DP はすべての可能な合計を完全に取得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
grid = [list(map(int, input().split())) for _ in range(n)]

dp = [False] * 5
dp[0] = True

for i in range(n):
    ndp = [False] * 5
    row = grid[i]
    for r in range(5):
        if not dp[r]:
            continue
        for v in row:
            nr = (r + v) % 5
            ndp[nr] = True
    dp = ndp

print("".join("Y" if dp[i] else "N" for i in range(5)))
```コードは行ごとの DP 解釈に従います。 の`dp`array は、以前のすべての選択肢を 5 つの残基クラスに圧縮します。 各行について、その行のすべての可能な値を試します。これは、その行の列を選択することで考えられるすべての寄与を表すためです。 トランジションは、モジュロ 5 算術を使用して、以前の合計を新しい行の寄与とマージします。 

微妙な点は、リセットすることです。`ndp`各行に対して、行ごとに 1 つの値を 1 回だけ使用するようにします。 モジュロ演算は、オーバーフローを防止し、状態空間を一定に保つために直ちに適用されます。 

## 実用的な例

 ### 例 1

 入力:```
2
0 4
4 0
```から始めます`dp = [True, False, False, False, False]`。 

| 行 | アクティブ dp | 行の値 | 新しい到達可能な残基 |
 | --- | --- | --- | --- |
 | 1 | [1,0,0,0,0] | {0,4} | {0,4} |
 | 2 | [1,0,0,0,4] | {4,0} | {0,4、(0+4)=4、(4+0)=4、(4+4)=3} |

 両方の行を処理した後、到達可能な残基は 0、3、4 になります。 

出力:`YNNYN`。 

このトレースは、行選択の相互組み合わせにより、小さなグリッドでも複数の剰余クラスがどのように生成されるかを示しています。 

### 例 2

 入力:```
2
1 1
1 1
```初期状態は同じです。 

| 行 | アクティブ dp | 行の値 | 新しい到達可能な残基 |
 | --- | --- | --- | --- |
 | 1 | [1,0,0,0,0] | {1} | {1} |
 | 2 | [0,1,0,0,0] | {1} | {2} |

 残基 2 のみが到達可能です。 

出力：`NNYNN`。 

これは、同じ行が繰り返されると、到達可能な合計が大幅に制限されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(5 \cdot n^2)$| それぞれについて$n$行、スキャンします$n$列と 5 つの状態を更新 |
 | スペース |$O(5)$| 残差上の DP 配列のみが保存されます。 

グリッドのサイズは最大です$10^6$エントリーなので、$O(n^2)$処理が最適になります。 DP 状態はサイズ 5 に固定されているため、定数係数は小さくなります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(sys.stdin.readline())
    grid = [list(map(int, sys.stdin.readline().split())) for _ in range(n)]

    dp = [False] * 5
    dp[0] = True

    for i in range(n):
        ndp = [False] * 5
        row = grid[i]
        for r in range(5):
            if not dp[r]:
                continue
            for v in row:
                ndp[(r + v) % 5] = True
        dp = ndp

    return "".join("Y" if dp[i] else "N" for i in range(5))

# provided samples
assert run("2\n0 4\n4 0\n") == "YNNYN"
assert run("2\n1 1\n1 1\n") == "NNYNN"

# custom cases
assert run("1\n0\n") == "YNNNN", "minimum size"
assert run("1\n4\n") == "NNNNY", "single cell residue"
assert run("3\n0 0 0\n0 0 0\n0 0 0\n") == "YNNNN", "all zeros"
assert run("3\n1 2 3\n1 2 3\n1 2 3\n") == "YYYYY", "mixed small grid"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1x1 ゼロ | いんんん | 基本ケース |
 | 1x1 値 4 | NNNNY | 単一セルモジュロ |
 | すべてゼロのグリッド | いんんん | 均一な安定性 |
 | 混合値 | YYYYY | 完全な到達可能性のケース |

 ## 特殊なケース

 1 つのエッジ ケースは、サイズ 1 の最小グリッドです。アルゴリズムは初期化します。`dp = [True, False, False, False, False]`、唯一の行は、その単一の値に基づいて到達可能な残基を直接設定します。 入力用`[[4]]`、DP は残基 4 のみに遷移し、`NNNNY`。 これにより、置換の複雑さなしに最小構造が正しく処理されることが確認されます。 

もう 1 つのケースは、ゼロの均一なグリッドです。 すべての行は 0 のみを提供するため、DP は剰余 0 を超えて拡張されることはありません。すべての行の後、`dp[0]`trueのままで、生成します`YNNNN`。 これは、アルゴリズムが行の独立性による人為的な多様性を想定していないことを示しています。 

3 番目のケースは、各行に残基の完全なセットが含まれる場合です。`{0,1,2,3,4}`。 DP は急速に飽和します。最初の行の後、すべての残基が到達可能になり、後続の行は完全な到達可能性を維持します。 最終的な出力は次のとおりです`YYYYY`、加算法 5 での閉包を確認します。
