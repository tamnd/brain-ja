 ## 解決策
 ## 問題の理解

 私たちには偶数人の学生、具体的には 2n 人が与えられ、各学生には化学の数値的スキルが備わっています。 教師はそれらを n 個の互いに素なペアに分割し、すべての生徒が正確に 1 つのペアに属するようにする必要があります。 ペアは、2 つのスキル間の絶対差が最大 A である場合にのみ有効です。それ以外の場合、ラボは爆発し、パーティション全体が無効になります。 

有効なペアの中から、2 番目のしきい値 B によって品質を分類します。差が最大 B であれば、ペアは完璧な結果を生成します。 B と A の間にある場合、結果は単に許容範囲内です。 目標は、有効なペアが存在するかどうかを判断し、存在する場合は「完璧な」カテゴリに分類されるペアの数を最大化することです。 

入力は複数の独立したテスト ケースで構成され、それぞれが複数のスキルセットと 2 つのしきい値を記述します。 各テスト ケースについて、不可能であることを報告するか、有効なペアリング制約の下で達成可能な完全なペアの最大数を計算します。 

制約が十分に大きいため、フルセットにわたる二次ペアリング戦略は遅すぎます。 テスト全体で合計 2n が 2⋅10^5 になると、テストごとに O(n^2) の構築を行うことさえ完全に不可能になります。 これは、ソートベースの貪欲な構造または 2 ポインター構造を直ちに示唆します。 

重要な微妙な失敗例は、単純な貪欲さが A 制約をグローバルに尊重せずに常に最近隣をペアにしようとするときに発生します。 たとえば、A が非常に小さく、ローカル ペアリングによって不可能な残留物が強制されるクラスター構造を考えてみましょう。 別の失敗は、A の下で実現可能性を保証せずに最初に完全なペアを最大化しようとしたときに発生し、後で有効なペアに完成できない構成が生成される可能性があります。 

課題は、A の実現可能性と B のカウントの最大化という 2 つの競合する目標のバランスを取ることです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。2n 個の要素を n 個のペアに分割するあらゆる方法を試し、すべてのペアが A 制約を満たすかどうかを確認し、B 制約を満たすものがいくつあるかを数えます。 これは、サイズ (2n−1)!! の組み合わせ空間を探索しますが、これは指数関数よりも速く増加します。 n = 10 の場合でも、これはすでに膨大な量であるため、リモートで使用することさえできません。 

配列をソートすると、問題の構造は完全に変わります。 ソート後、A での実現可能性は、行上のペアリングの問題になります。ソートされた順序で 2 つの要素が大きく離れている場合、それらをより近い一致に置き換えることは実現可能性を高めるだけです。 これは、最適なソリューションは常にソート順で近い要素をペアにし、最適な構築は順序付けの制約を考慮した構築に変換できることを示唆しています。 

重要な洞察は、問題を 2 つのフェーズに分けることです。 まず、有効なペアリングがしきい値 A の下に存在するかどうかを判断します。これは古典的な「ソート後に隣接するペア」の実現可能性チェックです。配列をソートする場合、有効なペアリングは、A に違反せずに順番にペアリングできる場合にのみ存在します。これは、2 つのポインターを使用する貪欲なスキャンになります。 

実現可能性が保証されたら、差 ≤ B を持つペアを最大化したいと考えます。A での有効なペアは、エッジが十分に近い要素間にのみ存在する制約されたマッチングと考えることができます。 これらの中で、より厳しいしきい値 B に該当するエッジの数を最大化したいと考えます。この構造は、2 つの距離領域を持つ線上の貪欲なマッチング問題になります。 最初に B-good ペアの形成を貪欲に試みることができますが、それは残りの要素の A-実現可能性を破壊しない方法でのみです。 ソートされた構造により、2 つのポインターを維持し、制約を尊重しながら常に最も古い要素と一致させることができます。 

最終的な解決策は、ソートされた配列を貪欲にスイープして、可能な限り B ペアの形成を試みることになります。そうでない場合は、A 実現可能なペアを確保するために要素を予約します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((2n)!) | O(n) | 遅すぎる |
 | 最適 (ソート + 貪欲なペアリング) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての生徒のスキルを降順でない順に並べ替えます。 ここからは、隣接する構造についてのみ推論します。 

配列に対するポインターを維持し、常に次に利用可能な要素を取得して、ペアを順番に構築します。 

1. サイズ 2n の配列をソートします。 
2. 左から右にスキャンし、A 制約に決して違反しない方法で要素を貪欲にペアリングしようとします。 

いずれかの時点で、有効なパートナーを使用して現在の要素を距離 A 内でペアリングできない場合は、有効なペアリングが存在しないと結論付けます。 
3. このスキャン中に、2 つの連続する利用可能な要素の差が ≤ B である場合は常に、それらを「完全な」ペアとして直ちにペアリングするとみなします。 
4. A 内で次に考えられるペアリングが、より大きなギャップを介してのみ可能である場合、ペアは形成されますが、完全なものとはみなされません。 
5. すべての要素がペアになるまで続行します。 

重要な設計上の決定は、利用可能な B-valid 隣接ペアのペアリングを決して遅らせないことです。 このようなペアの遅延は、残りのすべての候補がソート順でさらに遠くにあるため、後でより悪いペアに置き換えられるだけです。 

### なぜ効果があるのか

 並べ替えると、問題は、近接性が実現可能性を完全に決定する線に絞り込まれます。 A に基づく有効なペアリングは、要素がはるか前方の誰かとペアになる場合、すべての中間要素が同じ間隔内でペアになる必要があることを考慮する必要があり、ペアがローカルである構造への変換が常に許可されます。 

この標準構造内では、B 有効な隣接ペアを貪欲に選択しても最適性を損なうことはありません。2 つの近い要素をペアにしないままにしておくと、最終的にそれらがまたがる必要がある距離が増加するだけであり、後で別の B ペアを形成する可能性が向上することはないからです。 A 制約により、禁止されたギャップを越えないことが保証され、貪欲なペアリングにより有効なマッチング間隔が間隔ごとに維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, A, B = map(int, input().split())
        arr = list(map(int, input().split()))
        arr.sort()
        
        i = 0
        ok = True
        perfect = 0
        
        # greedy pairing from left to right
        while i < 2 * n:
            if i == 2 * n - 1:
                ok = False
                break
            
            # if we can form a perfect pair, take it
            if arr[i + 1] - arr[i] <= B:
                if arr[i + 1] - arr[i] > A:
                    ok = False
                    break
                perfect += 1
                i += 2
            else:
                # otherwise we must still pair i and i+1 to maintain feasibility locally
                if arr[i + 1] - arr[i] > A:
                    ok = False
                    break
                i += 2
        
        if not ok:
            out.append("-1")
        else:
            out.append(str(perfect))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードはまずスキルを並べ替えて、すべての候補となる適切なペアがローカルになるようにします。 ポインタ`i`配列内を歩き回り、常に連続する要素のペアを消費します。 Aさんにとって隙間が大きすぎると工事が不可能となり中止となります。 

決断のポイントはいつ`arr[i+1] - arr[i] <= B`。 その場合、それを完璧なペアとしてカウントします。延期する理由はなく、延期すると、後でより大きなギャップを持つペアに追い込まれるだけだからです。 

すべての反復で 2 つの要素が消費されるため、並べ替え後の直線的な時間が保証されます。 

微妙な点は、要素を「スキップ」しようとしていないことです。 この構造では、スキップすると、連続セグメント内の A 内で残りの要素が依然としてペア可能でなければならないという不変条件が崩れます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての要素が同一である場合です。 ソート後、隣接するすべてのペアの差分がゼロ (≤ B) になるため、すべてのペアが完全になり、アルゴリズムはすべての n ペアを正しくカウントします。 

もう 1 つのケースは、実現可能性を損なう大きなギャップが 1 つだけ存在する場合です。 ソート後、隣接する差分が A を超える場合、そのギャップは一致する構造によって埋めることができないため、ペアリングはまったく不可能になります。 アルゴリズムは、ギャップを越えてペアリングを試みるとこれを即座に検出し、正しく -1 を返します。 

B が非常に小さく、A がわずかに大きい場合には、微妙なケースが発生します。 アルゴリズムは頻繁に「有効だが完璧ではない」分岐に分類される可能性がありますが、完全なペアは局所的に最適な場合にのみカウントされ、A 境界を越えて強制されることはないため、これは正確さに影響しません。
