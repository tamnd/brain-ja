 ## 解決策
 ## 問題の理解

 棚を表す位置の行が与えられています。 各位置は空であるか、本が置かれています。 目標はすべての位置を「クリーン」にすることですが、制限があります。本が含まれる位置を直接クリーンにすることはできません。 本に対処する唯一の方法は、本を隣接する空の位置に移動することですが、そのような移動ごとに 1 ユニットの電力がかかります。 

すべての移動が完了した後は、すべての位置がきれいになる必要があります。これは暗黙的に、最初に占有されていたすべての位置が空になり、自由に掃除できるように、すべての本を再配置する必要があることを意味します。 

重要な相互作用はローカルです。本は隣接する空のスロットを通ってのみ移動でき、空のスロット自体は自由に掃除できます。 コストは、本が構造物に押し込まれる回数によって完全に決まります。 

制約はすべてのテスト ケースにわたって大きく、全長は最大 2×10^5 になります。 これにより、個々の本をステップごとに繰り返し移動させるシミュレーションは除外されます。これは、単一の本が長く伸びた空きスペースを移動する最悪のケースでは、二次的な動作に低下するためです。 

本が密集しているか孤立している場合、微妙な特殊なケースが発生します。 

たとえば、次のような構成を考えてみましょう。`1010`。 各本を個別に移動するのが最適だと考える人もいるかもしれませんが、空のスロットは共有リソースであるため、相互作用は重要です。 

もう一つの厄介なケースは、`111000`。 素朴なアプローチでは、距離に比例した最小限のコストで本が空のスペースに単に「落ちる」と想定するかもしれませんが、グローバルな戦略がなければ、空の位置の再利用を数えすぎたり見逃したりする可能性があります。 

主な課題は、ブックと空のスロットの間の相対的な順序のみが重要であり、単独の絶対的な位置ではないことを認識することです。 

## アプローチ

 ブルートフォース解釈は、文字通りプロセスをシミュレートします。 まだ存在する本を繰り返し選択し、可能な限り近くの空いている位置に移動し、各ステップのコストを減らします。 これは、配列をスキャンし、移動可能な本を見つけて、無効な位置に本がなくなるまで移動を実行することで実装できます。 

これは移動ルールを正確に尊重するので正しいのですが、状態が交互に現れる長い回廊を本が移動しなければならない場合、その非効率性が明らかになります。 最悪の場合、移動するたびにブックが 1 位置移動し、ブックご​​とにそのようなシフトが O(n) 回あり、テスト ケースごとに合計作業量が O(n²) になる可能性があります。 

重要な観察は、動きを明示的にシミュレートする必要がないということです。 各本は最終的には空の位置を占めますが、重要なのは、本の注文方法に関連して、空のスロットが宛先として「消費」される数です。 棚を左から右に見ると、本に出会うたびに、その左または右にある次に利用可能な空の位置と最適なマッチングの意味でペアになっていると考えることができます。 このプロセスは、書籍を「吸収」するために利用可能な空のスロットの数を追跡し、書籍が地域の在庫状況を超えた場合に必要なシフトを蓄積することに要約されます。 

これにより、問題は単一のリニア スキャンにわたる貪欲なアカウンティング プロセスに変換されます。

 ## アルゴリズムのチュートリアル

 棚を左から右に処理し、後で出会う本を吸収する可能性がある、左側で現在利用可能な空のスロットの数を表すカウンターを維持します。 

1. 変数を初期化する`empty = 0`そして`cost = 0`。 の`empty`カウンタは使用可能な空の容量を追跡しますが、`cost`必要な運動パワーを蓄積します。 
2. 文字列を左から右に移動し、各位置を検査します。 
3. 現在の位置が空の場合は、インクリメントします。`empty`これは、以前または後で表示された書籍の宛先として機能する、新しく利用可能なスロットを表します。 
4. 現在の位置に本があり、`empty > 0`、その本を利用可能な空のスロットの 1 つに割り当てます。 簿記を超えて追加の動きをしなくても概念的に一致させることができるため、これによってコストが増加することはありません。`empty`1までに。 
5. 現在の位置に本があり、`empty == 0`の場合、この本の左側にはペアリングできる空きスロットがありません。 将来の空のスペースを「押し出す」必要があるため、インクリメントします`cost`これは、将来の空のポジションによって解決される遅延不一致の作成を表します。 
6. 文字列の最後まで続けて出力します。`cost`。 

ステップ 5 の背後にある直感は、十分な空きスロットが出現する前に本を見つけるたびに、再配置の料金を支払わなければならないということです。 このような欠損はそれぞれ、世界的に避けることのできない 1 つの運動単位に対応します。 

### なぜ効果があるのか

 スキャンの任意のプレフィックスで、`empty`は、可逆的な方法で書籍を吸収できる無料の宛先がいくつ存在するかを表します。 そんなときに出会った本`empty > 0`グローバルな妨害を引き起こすことなく、ローカルでマッチングすることができます。 いつ`empty == 0`、その本は、利用可能なローカル スペースの点で事実上「比類のない」ものであり、最適なソリューションで正確に 1 ユニットのコストがかかる構造の再配置を余儀なくされています。 

この不変式により、インクリメントするたびに次のことが保証されます。`cost`、私たちは本の数とプレフィックス構造内の利用可能な空のポジションの間の根本的な不均衡を数えており、少なくとも1ユニットを先に支払わなければ、その後の操作はその不均衡を解消することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        empty = 0
        cost = 0

        for ch in s:
            if ch == '0':
                empty += 1
            else:
                if empty > 0:
                    empty -= 1
                else:
                    cost += 1

        print(cost)

if __name__ == "__main__":
    solve()
```実装はスキャンベースの推論に直接従います。 の`empty`カウンタは利用可能なスロットのプールのように動作し、すべての本は 1 つを消費するか、利用可能なスロットがない場合はコスト増加をトリガーします。 重要な点は、明示的に何かを移動しようとしないことです。 構造全体が不均衡追跡でエンコードされます。

 ## 特殊なケース

 次のようなすべてゼロの構成`00000`すべての位置がすでにクリーニング可能であり、利用可能な容量が増えるだけであるため、コストが発生することはありません。 アルゴリズムは増加するだけです`empty`、 それで`cost`全体を通してゼロのままです。 

次のようなすべてを含む構成`11111`初期の本を無力化する空のスロットは出現しないため、本の数から 1 を引いたコストが発生します。 スキャンは増加します`cost`これは、最後の本を除く各本が構造の再配置を強制しなければならないという事実と一致しています。 

のような混合ケース`100001`は、初期の空きスペースが後の書籍を吸収できることを示していますが、その容量までしか吸収できません。 最初のゼロが増加します`empty`、最後のブックでそれが消費され、容量が構築される前に初期の不均衡が発生した場合、コストは完全に初期不均衡によって決まります。
