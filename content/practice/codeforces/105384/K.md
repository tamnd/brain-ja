 ## 問題の理解

 小さな正の整数の初期配列が与えられます。 1 回の操作で正の整数が選択されます$x$、その後、配列のすべての要素が、次の値で除算されたときの余りで同時に置き換えられます。$x$。 この操作は、さまざまな値を選択して、何度でも適用できます。$x$毎回。 

元の配列から始めて、このようなグローバルなモジュロ演算のシーケンスを通じて、さまざまな配列を生成できます。 タスクは、これまでに出現できる個別の配列の数を数えることであり、少なくとも 1 つの位置が異なる場合、2 つの配列は異なるものとみなされます。 

重要な制約は、配列の長さと値の両方が最大 500 であることです。これは、操作の完全なシーケンスを明示的に追跡したり、すべての可能性をシミュレートしようとするソリューションは大きすぎることを直ちに示唆しています。これは、値が 500 個までの中程度の分岐プロセスであっても、すぐに爆発してしまうためです。 実行可能なアプローチでは、考えられるすべての操作シーケンスの影響をコンパクトな状態記述に圧縮する必要があります。 

微妙なエッジ ケースは、操作がグローバルに相互作用することです。$x$すべての要素に一度に適用されます。 これにより、単純な要素ごとの独立性の推論が除外されます。 たとえば、1 つの要素がある値に到達でき、別の要素が個別に別の値に到達できる場合、両方が同じ操作シーケンスと一致しない限り、そのペアが同時に達成可能であることを自動的に意味するわけではありません。 

2 番目の自明ではないケースは、繰り返しの削減から生じます。 異なる係数を順番に適用すると、単一の係数のように動作しないため、「最終値は単に$a_i \bmod x$たとえば、10 から開始して mod 6 を適用すると 4 が得られ、次に mod 4 を適用すると 0 が得られますが、10 mod 4 は 2 となり、順序が重要な点で重要であることがわかります。 

## アプローチ

 ブルートフォースのアイデアは、各配列を状態として扱い、各操作を遷移として扱うことです。 任意の配列から、可能な値をすべて試すことができます。$x$、結果の配列を計算して続行します。 これは原理的には正しいですが、個別の配列の数は膨大になります。 値は 500 で制限されていますが、長さ 500 の配列の状態空間は次のようになります。$501^{500}$また、BFS または DFS による積極的なプルーニングでも、指数関数的な爆発を防ぐことはできません。 

重要な観察は、視点を逆転させることによって得られます。 配列を順方向に生成する代わりに、最後の操作後に最終配列が到達可能になるために満たす必要がある条件を尋ねます。 最後の操作で次のものが使用されたとします。$x$。 したがって、すべての最終値は剰余モジュロでなければなりません$x$、つまり、各要素は次のとおりです。$[0, x-1]$、前の配列は、次の倍数を加算することによってのみ最後の配列と異なる必要があります。$x$要素的に。 

これは、最後の操作が剰余クラスのモジュロによって値を効果的にグループ化することを意味します。$x$、到達可能な構成は、いずれかの選択と一致している必要があります。$x$最終的な「カットオフスケール」として。 すべての値は 500 で制限されているため、関連する値はすべて$x$も最大500です。 

これは、考えられる「最後の操作のしきい値」を超える動的プログラミング構造を示唆しています。$x$ここで、最後の係数を修正した場合に完了できる構成の数を数えます。 各要素の状態間の遷移は、値を維持するか、値の倍数を加算して値を引き上げることに対応します。$x$、範囲内に留まる限り。 これにより、問題は一連の操作ではなく、値レイヤーにわたる構造化された DP に変わります。

 ## アルゴリズムのチュートリアル

 私たちは定義します$V = 500$、配列内の最大値。 重要なアイデアは、最後の操作係数の可能​​な値を処理することです。$x$大きいものから小さいものまで、そのレベルで「終了」できる配列の数を計算します。 

1. の候補値を処理します。$x$1から500まで、通訳$x$最終操作で使用される係数として。 最終値は次の値より小さい必要があるため、これは有効です。$x$、 それで$x$は、最終的な配列の最大要素によって制限されます。 
2. 固定の場合$x$、すべてのエントリが存在する配列に注目を限定します。$[0, x-1]$。 これらは、最終的な MOD を適用した直後に表示される唯一の配列です$x$手術。 
3. 各要素について、値がどのように設定されるかを検討します。$[0, x-1]$以前の到達可能な値から生じる可能性があります。 以前の値は次の形式でなければなりません$b + kx$、 どこ$b < x$は最後の余りであり、$k \ge 0$は次のような整数です$b + kx \le 500$。 
4. これにより、剰余クラスのモジュロごとに階層構造が作成されます。$x$: 各最終値$b$可能なリフト値のスタックとして考えることができます$b, b+x, b+2x, \dots$。 DP は、到達可能性との一貫性を保ちながら、このスタックから代表者を選択できる方法が何通りあるかを追跡します。 
5. 実現可能性を下方向に伝播します。スタック内のより高い値が到達可能であれば、それと互換性のあるすべてのより小さな剰余が、同じモジュラス制約の下で最終状態の候補として残ります。 
6. 計算後、それぞれの寄与を合計します。$x$、配列が最終操作として機能する最小の係数で正確に 1 回カウントされるようにします。 

正確さは、到達可能なすべてのシーケンスに明確に定義された最後の操作があるという事実にかかっています。$x$、そして一度それが$x$が固定されている場合、すべての有効な配列は、初期限界を超えることなく以前の到達可能な状態に一貫してリフトできるものです。 

不変条件は、各係数における$x$、パラメータを使用した最終操作を適用した直後に表示されるすべての配列を完全に特徴付けます。$x$、有効なシーケンスはすべて、そのようなレイヤーの 1 つで終了する必要があります。 これにより二重カウントが防止され、構築の完全性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

n = int(input())
a = list(map(int, input().split()))
MAXV = 500

# dp[x] will represent number of valid ways contributed by fixing last modulus = x
dp = [0] * (MAXV + 1)

# We precompute for each x how many choices each value has in its "lifting chain"
# count[b] = number of possible values b + kx within bounds for a given x

for x in range(1, MAXV + 1):
    # for each residue b, compute how many lifted values exist <= MAXV
    ways_per_residue = [0] * x
    for b in range(x):
        # values: b, b+x, b+2x, ...
        ways_per_residue[b] = (MAXV - b) // x + 1

    # for each array element, count choices independently under this x
    total = 1
    for val in a:
        # only residues < x matter after final mod
        choices = 0
        for b in range(x):
            if b <= val:
                choices += ways_per_residue[b]
        total = (total * choices) % MOD

    dp[x] = total

print(sum(dp) % MOD)
```コードは考えられるすべての最終モジュールを反復します。$x$。 それぞれについて$x$、剰余クラスごとにリフト表現がいくつ存在するかをカウントします。$b < x$ここで、リフトされた表現は、最後の操作の前に存在していた可能性のある値に対応します。 

オリジナル要素ごとに$a_i$、残基の数を数えます$b$～と一致している$a_i$に還元される$b$モジュラスで終わる何らかの一連の操作の下で$x$。 これらの寄与は要素間で乗算されます。$x$が固定されると、リフトされたプリイメージに関して、さまざまな位置の選択が独立します。 

最終的な答えは、考えられるすべての最終係数の選択肢にわたる寄与を合計します。 

## 実用的な例

 配列を考慮してください$[1, 2, 4, 8, 16]$。 小型用$x$、少数の残基のみが可能であり、$x$増加すると、より多くの残基が利用可能になりますが、リフティングチェーンは短くなります。 DP は各機関からの寄付を蓄積します。$x$、最終弾性率によってアレイが「崩壊」する可能性のあるさまざまな構造的方法を捉えています。 

のために$[6, 5]$、小さなモジュラスのような$x=2$または$x=3$多くの崩壊が発生しますが、弾性率が大きいほど構造が維持されます。 アルゴリズムは、範囲内に戻すことができるすべての有効な最終剰余構成をカウントします。$[0,500]$、配列が次のようになることを保証します$[0,0]$、$[2,1]$、 または$[6,5]$それらはすべて、対応する最後の操作スケールの下に 1 回だけ含まれます。

これは、最後の係数を修正すると、問題が独立した要素ごとのカウントにきれいに分離されることを示しています。

 ## 特殊なケース

 単一要素などの最小限の入力は、プロセスの完全な動作を強調表示します。到達可能なすべての構成は、何らかのモジュラス シーケンスの適用から得られる必要があり、DP は、その単一の値に対して有効な剰余リフティング チェーンをカウントすることになります。 アルゴリズムはすべてを反復することでこれを処理します。$x$たとえ$n=1$、要素間の乗算は単一の項に縮退します。 

すべての要素が等しい場合、すべての係数は位置間で対称的に動作します。 DP は値の独立性を仮定せず、固定された最終係数に基づいて条件付けされた独立性のみを仮定するため、同一のエントリでもオーバーカウントすることなく正しい乗法寄与を生成します。 

何度も繰り返される 500 などの最大値の場合、小さな係数のリフティング チェーンは長くなりますが、大きな係数はほとんど残基に寄与しません。 すべての計算は次の形式の整数除算によって制限されるため、アルゴリズムはこれをスムーズに処理します。$(500 - b) / x$オーバーフローや無効なインデックス作成が発生しないようにします。
