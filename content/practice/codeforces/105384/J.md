 ## 解決策
 ## 問題の理解

 長さの順列が与えられています$n$。 ジェシーはポジションを空ではない 2 つのグループに分割することができます。 1 つのグループは黄色、もう 1 つのグループは青に色付けされます。 その後、各グループが値によって個別に並べ替えられ、並べ替えられた値がインデックスの昇順でそのグループの元の位置に書き戻されます。 

最終的な配列は完全にこのパーティションによって決定されます。各カラー クラス内で、最小の位置にはそのクラスの最小値が取得され、2 番目に小さい位置には 2 番目に小さい値が取得されます。 

スコアはインデックスの数です$i$このプロセスの後、位置の値が$i$まさになる$i$。 タスクは、このスコアを最大化するパーティションを選択し、それを達成する有効な構造を出力することです。 

制約により、最大で$10^5$テストケースと合計$n$まで$10^6$したがって、解はテスト ケースごとに線形である必要があります。 ネストされたスキャン、推測に基づいてソートされた構造の再計算、またはサブセットの組み合わせ検索を伴うものは、すぐに遅すぎます。 

ソートと位置の関係に微妙な問題が生じます。 素朴なアプローチでは、各位置または各値を個別に最適化できると想定するかもしれませんが、この操作では、各カラー グループ内のランクを通じてインデックスと値が結合されます。 もう 1 つのよくある間違いは、値が近い要素をまとめれば十分であると想定することですが、実際には、グループ内のインデックスの順序も重要です。 

小さなエッジケースはカップリングを明確に示します。 のために$p = [2, 1]$、両方の位置を同じ色に着色すると、ソート後に恒等順列が得られ、2 つの固定点が得られます。 ただし、この問題ではすべてを 1 色にまとめることができないため、分割せざるを得なくなり、スコアは 0 になります。 これは、全体的な最適性が、順列の構造が「2 つのグループに分割しなければならない」という制約とどのように相互作用するかに大きく依存していることを示しています。 

## アプローチ

 強引にカラーリングを行おうとすると、すべてを検査することになります。$2^n - 2$有効なパーティション。 各パーティションについて、各グループ内の並べ替えプロセスをシミュレートし、配列を再構築し、固定小数点をカウントします。 1回のシミュレーションでも費用がかかります$O(n \log n)$、これは大規模では完全に不可能になります。 総作業量はこれを超えて爆発的に増加するでしょう$O(n 2^n)$。 

主要な構造の単純化は、グループ内で操作が何を行うかを観察することで得られます。 どのグループ内でも、最終的な割り当ては、並べ替えられたインデックスと並べ替えられた値の間の完全な一致になります。 ポジション$i$インデックス間のランクが値のランクと等しい場合にのみ正しくなります。$i$同じグループ内の値の間で。 これは、グローバルな相互作用がローカルな選択ではなくグループ構造によって媒介されていることを強く示唆しています。 

重要な観察は、順列を一連の素なサイクルとして見ることです。 サイクル内では、インデックスと値は密接に結合されています。 サイクルのすべての要素が同じグループに配置されている場合、そのグループをソートした後、サイクルはそれらの位置にわたって完全にソートされたブロックに折りたたまれ、サイクル内のすべての要素が固定点に変わります。 サイクルが 2 つのグループに分割されると、その構造的配置が破壊され、サイクルが固定点に寄与することが保証されなくなります。 

これにより、問題は非常に単純な組み合わせの決定に帰着します。つまり、両方の色が空であってはならないという要件によって強制されない限り、サイクルを分割すべきではありません。 少なくとも 2 つのサイクルがある場合は、サイクル全体を黄色と青に個別に割り当て、すべてのサイクルをそのまま維持し、完全にソートされたグローバルな結果を達成できます。 サイクルが 1 つしかない場合は、それを分割する必要があり、潜在的な固定点がすべて破壊されます。

 ## アルゴリズムのチュートリアル

 ### サイクルベースの建設

 1. インデックスに対する標準的な訪問を使用して、順列を素のサイクルに分解します。 順列は関数グラフを定義するため、各インデックスは正確に 1 つのサイクルに属します。 
2. 存在するサイクルの数を数えます。 この数値は、両方の色を使用するという要件を満たしながら、サイクルの分割を回避できるかどうかを決定します。 
3. 少なくとも 2 つのサイクルがある場合は、1 つのサイクルを黄色に、少なくとも 1 つの異なるサイクルを青色に選択します。 両方のグループが空でないことを保証しながら、残りのすべてのサイクルを任意に割り当てることができます。 これにより、色間でサイクルが壊れないことが保証されます。 
4. サイクルが 1 つだけある場合は、それを分割する必要があります。 有効な構成は、1 つの位置を黄色、残りを青色とすることです。 
5. 黄色のセットとそのサイズを出力します。 

ステップ 3 の重要な点は、サイクルをそのまま維持することで、各グループ内でのソート後にインデックスの順序と値の順序の間の内部一貫性が維持されるということです。 この問題では両方のグループが空でないことが必要であるため、ステップ 4 は避けられません。 

### なぜ効果があるのか

 単一グループ内で、並べ替えにより、k 番目に小さいインデックスから k 番目に小さい値までの単調なマッピングが作成されます。 置換サイクルは、インデックス値対応の閉じた構造をすでに表しているため、そのままの状態にしておくと、これら 2 つの順序が完全に整列します。 サイクルがグループ間で分割されると、ランクが各グループで個別に計算されるため、その調整は崩れ、サイクルの相対的な構造は保持されなくなります。 したがって、サイクルは、固定点への寄与を保存するための原子単位として機能します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = [0] + list(map(int, input().split()))

        vis = [False] * (n + 1)
        cycles = []
        for i in range(1, n + 1):
            if not vis[i]:
                cur = []
                v = i
                while not vis[v]:
                    vis[v] = True
                    cur.append(v)
                    v = p[v]
                cycles.append(cur)

        k = len(cycles)
        yellow = []

        if k == 1:
            cyc = cycles[0]
            yellow.append(cyc[0])
        else:
            yellow.extend(cycles[0])
            # ensure blue is non-empty by not taking all cycles
            # so we leave at least one cycle for blue
            # if only 2 cycles, cycles[1] is blue implicitly

        print(n)
        print(len(yellow))
        print(*yellow)

if __name__ == "__main__":
    solve()
```実装は、標準の訪問ウォークを使用して順列内のサイクルを抽出することから始まります。 未訪問の各インデックスは、訪問済みのノードに戻るまで順列を経て 1 つのサイクルを形成します。 

サイクル分解後の決定はサイクル数のみに依存します。 単一サイクルがある場合、両方の色を持つという要件を満たすために、黄色の要素を 1 つだけ選択します。 複数のサイクルがある場合、1 つのサイクル全体を黄色とし、少なくとも 1 つの完全なサイクルを青色のままにして、サイクルが分割されないようにします。 

出力には、黄色のセットのサイズとインデックス自体が表示されます。 

実装の微妙な点は、青のセットを明示的に構築する必要がないことです。 この問題には黄色のサブセットのみが必要です。 青は暗黙的にその他すべてです。 

## 実用的な例

 ### 例 1: 順列$[2, 1]$| ステップ | 状態 |
 | --- | --- |
 | サイクル分解 |$(1 \leftrightarrow 2)$|
 | サイクル数 | 1 |
 | 黄色を選択 |$\{1\}$|
 | 青の暗黙 |$\{2\}$|
 | 最終結果 | 固定点なし |

 単一サイクルは分割を強制するため、1 つのカラー内で完全なサイクル構造が存続することはありません。 並べ替え後、各グループには要素が 1 つだけあるため、固定位置に整列するものはありません。 

### 例 2: 順列$[2, 1, 4, 3]$| ステップ | 状態 |
 | --- | --- |
 | サイクル分解 |$(1 \leftrightarrow 2), (3 \leftrightarrow 4)$|
 | サイクル数 | 2 |
 | 黄色を選択 |$\{1,2\}$|
 | 青の暗黙 |$\{3,4\}$|
 | 最終結果 | すべての位置が固定 |

 各サイクルはグループ内でそのまま保持されるため、各グループをソートすると、両方のサイクルがインデックスに対する ID マッピングに変わります。 

これにより、複数のサイクルによりソートされた順列を完全に回復できることが確認されます。

 ## 特殊なケース

 順列が単一の大きなサイクルである場合、アルゴリズムは 1 つの要素だけを黄色として選択することを強制されます。 サイクル分解を実行すると、すべてのインデックスを含む 1 つのサイクルが生成されます。 この構造では、たとえば、単一のインデックスが選択されます。$1$、それを黄色に割り当て、残りは青色のままにします。 両方のグループに少なくとも 1 つの要素が含まれているため、この構造は有効です。 ソート後は両方のグループがシングルトンになるため、どの位置も固定点になることはできません。 

複数のサイクルがある場合、1 つのサイクルが他のサイクルよりもはるかに大きい場合でも、1 つのサイクルのすべての要素を黄色にし、少なくとも 1 つのサイクル全体を青にすることで、完全なサイクルの整合性が維持されます。 各サイクルは独立してそのインデックス上の完全なアイデンティティ マッピングに分類されるため、再構築後にすべての位置が正しくなります。
