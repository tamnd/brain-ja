 ## 問題の理解

 配列のペアが何ペアあるかを数えています$a$そして$b$、両方の長さ$n$の値を使用して形成できます。$1$に$m$、特定の対称条件がすべての位置のペア間で保持されるようにします。 

任意の 2 つのインデックスを選択します$i < j$。 2 つの「交差」ペアに注目します。$(a_i, b_j)$そして$(a_j, b_i)$。 各ペアから最小値を取得します。 要件は、これら 2 つの最小値が常に等しいことです。$i$そして$j$あなたが選びます。 

したがって、配列の構造は位置ごとに独立していません。 すべての位置は、この交差最小制約を通じて他のすべての位置と相互作用し、インデックス間で値を配置する方法を強く制限します。 

入力サイズが到達しました$10^6$両方にとって$n$そして$m$したがって、すべてのインデックスのペアを検査したり、ポジションの各ペアを個別に推論しようとするソリューションは、直ちに実行不可能になります。 二次関数の何か$n$、または線形でも$n$要素ごとに大量の作業が行われるため、すでに限界に達しています。 意図したソリューションでは、構造を以下にのみ依存するものに削減する必要があります。$m$、本質的に定数または対数の値ごとの処理を使用します。 

局所的に推論しようとすると、微妙な落とし穴が現れます。 たとえば、隣接するインデックスにのみ条件を適用したり、単調性を仮定したりすることができます。$a$または$b$。 条件にはすべてのペアが含まれるため、これは失敗します$(i,j)$、隣接する位置だけでなく。 

もう 1 つのよくある失敗は、条件をインデックスのペアごとの独立した制約として扱うことです。 のために$n=2, m=2$、 がある$2^4=16$配列のペアは可能ですが、有効なのは 10 個だけです。 単純なペアごとの制約アプローチでは、グローバルな一貫性の効果が欠けているため、過大評価される傾向があります。 

## アプローチ

 直接的な総当りのソリューションでは、すべてのものが生成されます。$m^{2n}$配列のペアを調べ、すべてのインデックスのペアの条件を確認します。 単一の候補をチェックする場合でも、$O(n^2)$比較するため、全体の複雑さは次のようになります。$O(m^{2n} \cdot n^2)$、小さな入力であってもまったく届きません。 この構造には、強力なグローバル順序原理が明らかに隠されています。 

重要な観察は、制約が最小値を介して異なるインデックス間の値を比較することだけに依存するということです。 2 つの値の間の最小値は、2 つの値のどちらが小さいかによってのみ決まります。 これは、重要なのは正確な値そのものではなく、しきい値に対する相対的な順序であることを示唆しています。 

閾値を固定すると$x$、各ポジション$i$かどうかによって分類できます。$a_i \ge x$そしてどうか$b_i \ge x$。 これにより、すべての位置がしきい値ごとに 4 つの状態の 1 つに減らされます。 交差最小条件により、これらの状態がすべてのインデックスにわたってグローバルに一貫性を持つように強制され、パターンの恣意的な混合が排除されます。 

この一貫性がすべてのしきい値を同時に通過すると、構造は驚くほど単純な特徴付けに崩壊します。各インデックスは、単一の実効スカラー値とそのペア全体があるかのように動作します。$(a_i, b_i)$変換された空間内の単一の数値を通じてエンコードできます。 これは、有効なペアの数が、可能な値レベルにわたる単純な累乗式の合計にのみ依存するという事実につながります。 

結果として得られる閉じた形式は次のようになります。$$\sum_{x=1}^{m} (2x - 1)^n$$この式は、小規模なケースに正確に一致し、制約によって引き起こされる組み合わせ構造を捕捉します。

 ## アルゴリズムのチュートリアル

 目標は以下を評価することです。$$\sum_{x=1}^{m} (2x - 1)^n \bmod 998244353$$1. 係数を事前計算する$MOD = 998244353$。 結果は非常に急速に増大するため、すべての演算はこの値を法として実行されます。 
2. 各整数について$x$から$1$に$m$、基本値を計算します$v = 2x - 1$。 これはレベルの変換された寄与を表します$x$最終的な組み合わせ構造で。 
3. コンピューティング$v^n \bmod MOD$高速累乗を使用します。 このステップは非常に重要です。$n$と同じ大きさにすることができます$10^6$したがって、単純な乗算は遅すぎます。 
4. 結果を累計して累計します。 
5. 最終的な合計モジュロを出力します。$MOD$。 

重要な計算負荷は累乗です。 各項は独立しているため、ループオーバー$m$避けられませんが、各べき乗が実行されます。$O(\log n)$、完全なソリューションを管理しやすくします。 

### なぜ効果があるのか

 クロス最小制約により、すべてのインデックス ペアがしきい値比較の下で一貫して動作するように強制されます。 この一貫性により、問題は、値間の有効な「中央値レベル」によってインデックス付けされた寄与をカウントするという問題に分解されます。$a$そして$b$。 各レベル$x$独立して寄与し、構成がレベルで寄与する方法の数$x$まさに$(2x-1)^n$。 すべてのレベルを合計すると、有効な各構成はどのしきい値間隔に属するかによって一意に決定されるため、二重にカウントすることなく合計カウントが再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modpow(a, e):
    res = 1
    while e > 0:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

n, m = map(int, input().split())

ans = 0
for x in range(1, m + 1):
    base = 2 * x - 1
    ans += modpow(base, n)
    ans %= MOD

print(ans)
```実装は派生した式に直接に従います。 唯一の重要なコンポーネントは 2 進累乗関数です。これにより、べき乗を繰り返し計算する必要がなくなります。 各反復で新しいベースが計算されます$2x-1$、ループステップ間に依存関係がないことが保証されます。 

よくある間違いは、中間パワーを異なるもの間で再利用しようとすることです。$x$しかし、基底が十分に異なるため、追加の多項式機構がなければ、このような再利用ではきれいな再帰が生成されません。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$m = 1$。 数式は単一の項に折りたたまれます$(1)^n$したがって、答えは常に 1 になります。$n$。 ループが 1 回実行され、べき乗が 1 を返すため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジケースは次のような場合です$n = 1$。 式は奇数の合計になります$1 + 3 + \dots + (2m-1)$に等しい$m^2$。 各べき乗は自明であり、ループは等差級数を累積するため、実装ではこれが正しく計算されます。 

3 番目のエッジケースは大きい$n$。 直接乗算ではオーバーフローやタイムアウトが発生しますが、2 進累乗では各項が対数時間に短縮されるため、次のような場合でもパフォーマンスが安定します。$n = 10^6$。
