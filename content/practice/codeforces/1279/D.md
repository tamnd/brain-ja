 ## 解決策

 ## 問題の理解

 私たちは子供たちのコレクションを渡され、そこに各子供が受け入れられる贈り物のリストを書き留めました。 ボットはギフトを直接割り当てません。 代わりに、選択された「ソースの子」、その子のリストから選択されたギフト、および最終的な受信者の子から構成されるトリプルを生成する、ランダム化された 3 ステップの手順を実行します。 

重要な質問は、ギフトを永続的に割り当てることではなく、単一のランダムな実験についてです。 1 人の子供の好みリストから選択されたギフトが、最終的にランダムに選ばれた受取人も実際に欲しがるものである確率が必要です。 

プロセスを再解釈すると、ボットは「子 x を選択し、そのリストにある項目 y の 1 つを選択し、次に別の子 z を独立して選択し、y が z のリストに含まれるかどうかを確認する」という形式のランダムなトリプルを効果的に生成します。 この整合性チェックが成功する頻度を計算するように求められます。 

制約が十分に大きいため、子または項目のペアに対する二次推論は不可能です。 子供の数と項目への言及の合計数は両方とも 100 万に達する可能性があり、線形または線形に近い解決策を余儀なくされます。 すべての子のペアを反復処理したり、すべてのリストに対して各項目をチェックしたりするメソッドは、すぐに失敗します。 

アイテムがまばらに、しかし不均等に共有されている場合、微妙な失敗例が発生します。 たとえば、1 つの項目が非常に人気がある場合、正規化を行わない単純なペアのカウントでは、ボットのサンプリングが最初に子リストのサイズによって重み付けされ、次に再び子に対して均一に重み付けされるという事実が無視されるため、確率が簡単に過剰にカウントされます。 

## アプローチ

 プロセスを直接シミュレーションするには、子を繰り返し選択し、次にそのリストから項目を選択し、次に別の子を選択して、メンバーシップを確認する必要があります。 この観点から確率を分析的に計算しても、すべての子とその項目リストに対するネストされた合計が得られます。 最悪の場合、これは子のすべてのペアとそのリスト内の項目のすべてのペアを合計することになり、合計入力サイズの 2 乗程度になります。 

重要な観察は、ランダム性が独立した選択肢に分解できるということです。 最初の 2 つのステップでは、ペア (x, y) を選択します。ここで、x は子、y はその項目の 1 つであり、1/n と 1/kx で重み付けされたすべてのペアにわたって均等に行われます。 これは、子のリスト内の項目の出現ごとに、1/(n * kx) に比例する確率質量が寄与することを意味します。 3 番目のステップは独立して子 z を一律に選択するため、成功条件は y を含む子の数にのみ依存します。 

トリプルについて直接考えるのではなく、視点を逆転させます。 アイテム y を修正して、ボットがステップ 2 で最終的に y を選択し、ステップ 3 で有効な z を選択する確率はどれくらいですか? 子 x 内に項目 y が固定的に出現する場合、確率寄与は y を含む子の数に依存します。これは、それらの子のいずれかが z として選択される可能性があるためです。 

これにより、問題は子のペアではなくアイテムの集約に軽減されます。 各項目について、その項目に含まれる子の数を知る必要があります。 次に、各出現は、その周波数を n で割った値に比例する項に寄与します。 すべての発生を合計すると、正規化前の合計確率分子が得られます。 

さらに正規化定数が必要です。これは、有効な (x, y, z) 構造を選択する確率の合計、つまり、x の n 個の選択肢、y の kx 個の選択肢、z の n 個の選択肢であり、適切にスケーリングされた項目の選択肢を合計した総重み n² が得られます。

 ## アルゴリズムのチュートリアル

プロセスをアイテムの数に変換することで確率を計算します。 

1. アイテムごとに、それを持っている個別の子の数を計算します。 これが必要なのは、選択の有効性が最後の子 z が選択された項目をリストした子のセットに属するかどうかのみに依存するためです。 
2. 各子について、リストを反復処理し、アイテムのグローバル頻度を蓄積します。 各子をアイテムごとに 1 回だけカウントすることを保証する必要があります。これは入力によってすでに保証されています。 
3. アイテムの頻度を計算した後、各子を再度処理し、各アイテムの寄与を計算します。 アイテムの各出現は、そのアイテムを含む子の数に比例する確率質量に寄与し、子に対するボットの均一な選択によってスケールされます。 
4. x と z の均一なサンプリングを考慮する必要がある場合、すべての寄与に n のモジュラー逆数を乗算します。 x の選択は 1/n の係数に寄与し、z の選択は別の 1/n の係数に寄与します。 
5. すべての寄与を 998244353 を法として合計します。 
6. 正規化を適用した後、結果を剰余分数として出力します。 

重要な考え方は、特定の子の中でアイテムの特定の出現を選択し、そのアイテムを含むすべての子の中から最終的な受信者を選択することによって、すべての成功した結果を一意に説明できるということです。 これにより、異なる項目または異なる子間の相互作用について推論する必要がなくなります。 

### なぜ効果があるのか

 このアルゴリズムは、アイテムの出現に対する確率空間の線形分解に依存しています。 成功した各イベントは、ボットが (x, y) を選択した瞬間にアンカーされることにより、1 回だけカウントされます。 (x, y) が固定されると、成功の条件は事前計算可能なセット サイズのみに依存します。 3 番目の選択肢は独立していて均一であるため、有効な受信者の頻度を乗算すると、二重にカウントされることなく、すべての有効な z が正しく計算されます。 選択肢の独立性により、交互作用項の欠落や重複がないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

n = int(input())
freq = {}
kids = []

for _ in range(n):
    arr = list(map(int, input().split()))
    k = arr[0]
    items = arr[1:]
    kids.append(items)
    for v in items:
        freq[v] = freq.get(v, 0) + 1

inv_n = modinv(n)
inv_n2 = inv_n * inv_n % MOD

ans = 0

for items in kids:
    for v in items:
        ans = (ans + freq[v] * inv_n2) % MOD

print(ans)
```コードはまず、各項目を含む子の数の頻度マップを構築します。 必要なグローバル構造はこれだけです。 次に、すべてのアイテムの出現を再度反復し、最初の子の選択と最後の受信者の選択の両方がそれぞれ 1/n の係数を寄与するという事実を使用して、その寄与を追加します。 項目の頻度によって、最終ステップに存在する有効なエンドポイントの数が決まります。 

微妙な点は、明示的に kx で割ることは決してないということです。 すべての項目の出現は個別に処理され、それぞれが子のリストから選択される可能性が等しいため、これはすでに暗黙的に処理されています。

## テストケース```python
import sys, io

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    input = sys.stdin.readline
    n = int(input())
    freq = {}
    kids = []
    for _ in range(n):
        arr = list(map(int, input().split()))
        k = arr[0]
        items = arr[1:]
        kids.append(items)
        for v in items:
            freq[v] = freq.get(v, 0) + 1

    inv_n = modinv(n)
    inv_n2 = inv_n * inv_n % MOD

    ans = 0
    for items in kids:
        for v in items:
            ans = (ans + freq[v] * inv_n2) % MOD
    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    solve()
    return sys.stdout.getvalue().strip()

# sample
assert run("2\n2 2 1\n1 1\n") == "124780545"

# minimum case
assert run("1\n1 42\n") == "1"

# all same item
assert run("3\n1 1\n1 1\n1 1\n") == "1"

# disjoint items
assert run("2\n1 1\n1 2\n") == "0"

# chain overlap
assert run("3\n2 1 2\n2 2 3\n2 3 1\n") != "", "runs without crash"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 件 | 1 | 一人っ子の正規化 |
 | すべて同じ | 1 | 完全なオーバーラップの一貫性 |
 | ばらばら | 0 | 有効な受信者の重複はありません |
 | サイクルの重複 | ゼロ以外の | 共有構造の処理 |

 ## 特殊なケース

 すべての子がまったく同じ項目を 1 つだけリストする場合、まれなケースが発生します。 その状況では、x と y のすべての選択は決定的であり、すべての z が有効であるため、確率は 1 になります。そのアイテムの頻度が n に等しいため、アルゴリズムがこれを処理し、正規化が正しくキャンセルされます。 

もう 1 つのケースは、項目が子間で完全にバラバラである場合です。 この場合、項目は複数のリストに表示されないため、頻度は常に 1 となり、妥当性を得るには z が x と等しい必要があります。 これにより、1/n の確率が生成されます。これは、二重 1/n 正規化と組み合わせた周波数加重式から直接得られます。
