 ## 解決策
 ## 問題の理解

 本質的に 0 から n − 1 までの単一の有向駅チェーンである交通システムが与えられています。駅 i − 1 と i の間には、固定長の道路セグメントが 1 つだけ存在し、そのセグメントでは K 個の合計モードのサブセットから選択された特定の交通モードのみが許可されます。 

各交通モードは、固定乗車料金、メートル当たりの移動コスト、および移動速度 (距離から時間を計算できるように逆数を介して間接的に与えられる) という 3 つのコスト要素を備えた発券サービスのように動作します。 モードを使用してセグメントを移動する場合、適用される場合は乗車料金を支払い、常に距離に比例したメーター当たりの料金を支払います。 移動時間は、距離にモードの 1 メートルあたりの時間の値を掛けたものです。 

面白いのは、「バーチャル転送」ルールにより、搭乗料金が省略される場合があることです。 あるモード A からモード C に切り替え、その間に別のモード B を 1 つだけ使用し、その中間セグメント中に B で費やした合計時間が厳密に T よりも短い場合、C に乗車するときは、搭乗料金を支払いません。 また、同じモードを連続してご利用の場合、その搭乗料金は1回限りとなります。 

したがって、本当の難しさは、エッジのコストが現在のモードだけでなく、1 ステップ前に何が起こったか、具体的には割引された移行条件が満たされたかどうかにも依存することです。 

ステーション 0 からステーション n − 1 までの最小総コストを計算する必要があります。 

制約の構造は小さいですが、力任せの柔軟性はありません。n は最大 64、K は最大 8 です。これは、グラフの幅は小さいが長さは深く、指数関数または K での 2 次の状態追跡が妥当であることを直ちに示唆します。 歴史は n とともに指数関数的に増大するため、すべての歴史にわたる単純な状態空間は不可能です。 ただし、重要な点は、最後の 2 つのモードとタイミング条件のみが重要であるため、完全な履歴は無関係であるということです。 

割引が連続モードのみに依存すると仮定すると、微妙な失敗例が現れます。 たとえば、A → B → C が発生するが、B の移動時間が長いとします。 B の滞在期間を誤って無視すると、誤って C の無料乗船料を許可してしまう可能性があります。 

もう 1 つの落とし穴は、仮想転送を対称または再利用可能として扱うことです。仮想転送は、単一の中間セグメントと厳密な「まったく 1 つの異なるモード」構造に厳密に関連付けられています。 「どんな短い時間のギャップでも割引が可能」と誤解すると、無効な遷移を過大にカウントすることにつながります。 

## アプローチ

 直接的なアプローチは、各ステーションを最短パス グラフ内のノードとして扱い、最後に使用されたトランスポート モードと、場合によっては最後から 2 番目のモードで状態を拡張することです。 K ≤ 8 であるため、最後から 2 番目のモードも追跡でき、ステーションごとに K3 状態が得られます。 トランジションは (ステーション、最後、前) から (ステーション + 1、次、最後) に進みます。 遷移ごとに、そのモードでセグメントを使用するコストを計算し、(前、最後、次) が仮想転送条件を満たすかどうかに基づいて搭乗料金が適用されるかどうかを決定します。 

このアプローチは正しいですが、時間がかかります。チェーンに沿って n 個の状態があり、各状態は次のモードの K 個の可能性に拡張され、各遷移は O(1) です。 これにより、約 64 · 512 ≈ 3e4 の遷移である O(n · K³) が得られ、簡単に問題ありません。 ただし、prev と last は K によって制限されているため、レイヤーごとの DP が実際には K³ ではなく K² であることに注目することで、さらに絞り込むことができます。 

これをチェーンに沿った階層化された DP と考えることもできます。各セグメントで、以前のモードから現在のモードに移行し、以前の移行に応じて現在のモードの搭乗料金が免除されるかどうかを知る必要があります。 これは事実上、次数 2 のモードにわたるマルコフ連鎖です。

フルパスに対する総当り攻撃では、セグメントごとに K 個の選択肢が列挙され、Kⁿ の可能性が得られ、これは天文学的に大きい (8⁶⁴) ものになります。 割引条件が前の 2 つのモードに依存するため、最後のモード (K 状態) のみに対する動的計画法でも失敗します。 二次依存関係は、K² 状態を強制する重要な構造的ボトルネックです。 

したがって、位置と最後の 2 つのモードによってインデックス付けされた DP に落ち着きます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパス | O(Kⁿ) | O(n) | 遅すぎる |
 | 最後の 2 つのモードを備えた DP | O(n · K²) | O(K²) | 承認済み |

 ## アルゴリズムのチュートリアル

 dp[i][a][b] が、セグメント i − 1 → i ではモード a を使用し、セグメント i − 2 → i − 1 ではモード b を使用して、ステーション i に到達するための最小コストを表す DP テーブルを維持します。 

各セグメントの遷移は、これら 2 つのモードと次に選択されたモードのみに依存します。 

1. 以前のモードが存在しない単一のダミー状態を除き、dp[0][a][b]を無限大として初期化します。 これは、a と b を特別な「なし」値とコスト 0 に設定することで表すことができます。 
2. 0 から n − 2 までの各セグメント i について、到達可能なすべての状態 dp[i][a][b] を考慮します。 この状態は、最後に使用された 2 つのモードが順番に b、a であることをエンコードします。 
3. セグメント i で許可されているすべての次のモード c を試します。 各 c について、距離[i] × コスト[c] と移動時間として基本移動コストを計算します。割引条件のチェックを除き、総コストには関係ありません。 
4. c の乗船料金がかかるかどうかを決定します。 通常、c が a と異なる場合に課金されます。 ただし、a ≠ b かつ c ≠ a で、旅行 b → a → c がこの区間のモード a の使用時間が T 未満であることを満たしている場合は、c の乗車料金をスキップします。 この条件は、a を介した有効な仮想転送を正確にエンコードします。 
5. c が最後のモードになり、a が最後から 2 番目になるため、dp[i + 1][c][a] を最小コストで更新します。 
6. すべてのセグメントを処理した後、すべての dp[n − 1][a][b] の最小値を取得します。 

重要な点は、履歴のシフトです。各ステップで、前の 2 つのモードのウィンドウが前に移動します。 これにより、割引条件をローカルで確認できるようになります。 

これが機能する理由は地域性の特性に基づいています。条件により仮想転送が 1 つの中間モードに明示的に制限されているため、乗車料金を免除できるかどうかの決定は最後の 2 つのセグメントと現在のセグメントにのみ依存します。 トリプル (b、a、c) を修正すると、すべての関連情報が含まれ、古い履歴が合法性やコストに影響を与えることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, K, T = map(int, input().split())
    w = list(map(int, input().split()))
    invv = list(map(int, input().split()))
    cost = list(map(int, input().split()))

    dist = []
    allowed = []

    for _ in range(n - 1):
        tmp = list(map(int, input().split()))
        d = tmp[0]
        t = tmp[1]
        modes = tmp[2:]
        dist.append(d)
        allowed.append(set(modes))

    INF = 10**30

    # dp[a][b] = last mode a, second last b
    dp = [[INF] * (K + 1) for _ in range(K + 1)]
    dp[K][K] = 0  # K used as "none"

    def time(mode, seg_idx):
        return dist[seg_idx] * invv[mode]

    for i in range(n - 1):
        ndp = [[INF] * (K + 1) for _ in range(K + 1)]
        for a in range(K + 1):
            for b in range(K + 1):
                cur = dp[a][b]
                if cur >= INF:
                    continue
                for c in allowed[i]:
                    # travel cost
                    add = dist[i] * cost[c]

                    # boarding fee logic
                    fee = 0
                    if a != K and c != a:
                        # check virtual transfer
                        if b != K and b != a and c != a:
                            # time spent using a is just this segment
                            if time(a, i) < T:
                                fee = 0
                            else:
                                fee = w[c]
                        else:
                            fee = w[c]
                    elif a == K:
                        fee = w[c]

                    ndp[c][a] = min(ndp[c][a], cur + add + fee)
        dp = ndp

    ans = min(min(row) for row in dp)
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、ローリング DP テーブルに最後の 2 つのモードのみが保持されます。 ダミー値 K は「以前のモードなし」を表します。これにより、初期化が簡素化され、最初のセグメントの特殊なケースが回避されます。 

時間関数は、仮想転送条件をテストするためにのみ使用されます。 時間はセグメントの長さとモード速度のみに依存するため、セグメントごとに直接計算されます。 よくある実装上の間違いは、セグメント全体の累積時間を事前計算することです。これは、条件が中間モードを使用する中間セグメントにのみ適用されるため、正しくありません。 

搭乗料金ロジックは、最初にモードを継続しているか切り替えているかを確認し、次に有効なトリプルが存在するかどうか、最後に時間条件が割引を許可するかどうかを確認するように構成されています。 無効なトリプルが割引をトリガーしてはいけないため、順序は重要です。 

## 実用的な例

 このステートメントでは不完全なサンプルが 1 つしか提供されていないため、小さな例を示します。 

n = 3、K = 2、T = 10 を考えてみましょう。2 つのセグメントが存在します。 

セグメント 0 の距離は 5 で、モード {0, 1} が許可されます。 セグメント 1 の距離は 5 で、{0, 1} も許可されます。 w[0] = 10、w[1] = 10、cost[0] =cost[1] = 1、invv[0] = invv[1] = 1と仮定します。 

dp の状態を追跡します。 

開始時は dp[none][none] = 0。 

セグメント 0 の後:

 | 状態 (最後、2 番目) | コスト |
 | --- | --- |
 | (0、なし) | 5 + 10 = 15 |
 | (1、なし) | 5 + 10 = 15 |

 セグメント 1 の後に (0, none) から 1 を選択すると、有効な中間チェーンがないため割引が適用されません。 

| 遷移 | コスト |
 | --- | --- |
 | 0→1 | 15 + 5 + 10 = 30 |
 | 0 → 0 | 15 + 5 + 10 = 30 |

 同様に (1, none) から:

 | 遷移 | コスト |
 | --- | --- |
 | 1 → 0 | 30 |
 | 1→1 | 30 |

 したがって、最終的な答えは 30 です。 

この例は、完全な 3 モード パターンがないと割引メカニズムがトリガーされず、初期化では「履歴なし」を個別の状態として保存する必要があることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · K²) | 各セグメントは、K ≤ 8 の定数で、最大 K² 状態と状態ごとに K 個の遷移を処理します。 
| スペース | O(K²) | 常に 2 つの DP レイヤーのみが保存されます。 

n ≤ 64 および K ≤ 8 という制約により、合計操作数が数万件前半にとどまるため、Python であってもこれが快適に高速になります。

 ## 特殊なケース

 重要なエッジ ケースは、n = 1 または n = 2 の場合です。これらの場合、有効な 3 つのセグメントがないため、仮想転送ルールはアクティブ化できません。 DP はダミー履歴でも正しく動作する必要があります。 初期化状態 (K, K) により、最初の実セグメントが誤って割引を継承しないことが保証されます。 

もう 1 つのエッジ ケースは、T = 0 の場合です。この条件では T 未満が厳密に要求されるため、仮想転送は決して許可されません。 < の代わりに ≤ を使用する実装では、誤って割引やコストの過少カウントが許可されます。 条件が単一セグメントに限定され、直接チェックされるため、DP は引き続き機能します。 

3 番目のエッジ ケースは、セグメントで 1 つのモードのみが許可される場合です。 その場合、スイッチングは不可能になり、DP は事実上単一パスの蓄積になります。 許可されたセットが遷移を制限するため、アルゴリズムはこれを自然に処理しますが、フィルタリングせずにステップごとに K 個の選択肢を想定する実装では、無効な状態が発生します。
