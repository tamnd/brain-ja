 ## 解決策
 ## 問題の理解

 各テスト ケースは単一の整数を与えます$n$。 タスクは、この数値を 2 つの異なる正の整数に分割することです。$x$そして$y$それらの合計が等しくなるように$n$。 このようなペアが存在できない場合、出力は 2 つの負の値でなければなりません。 

入力サイズは次のとおりです$10^5$テストケースとそれぞれの$n$せいぜい$10^5$。 これは、あらゆる解法がテスト ケースごとに一定時間である必要があることをすでに示唆しています。$O(\sqrt{n})$テストごとに不必要に感じ始め、$O(n)$テストごとに実行すると明らかに遅すぎるでしょう。 

微妙な点は、両方とも$x$そして$y$ポジティブで異なるものでなければなりません。 これにより、すぐに次の最小値の境界問題が発生します。$n$。 もし$n = 1$、2 つの正の整数への分解は存在しません。 もし$n = 2$、唯一の方法は$1 + 1$, しかし、値が異なっていないので無効です。 のために$n \ge 3$、有効な構造が突然簡単になります。 

単純なアプローチではすべてのペアを試す可能性があります$(x, y)$と$x + y = n$、しかし、構造が実行可能な解決策に対して単一の候補形式を強制するため、これでもやりすぎです。 唯一の危険は、最小値での区別性制約を忘れることです。これにより、誤った出力が発生します。$1, 1$のために$n = 2$。 

## アプローチ

 最も直接的な解釈は、合計が次になる 2 つの数値を構築してみることです。$n$。 ブルートフォース手法では、考えられるすべての値を反復処理します。$x$から$1$に$n-1$、 セット$y = n - x$、どうかを確認してください。$x \ne y$。 これはすべての分解を徹底的にチェックするので常に正しいですが、無駄です。 テストケースごとに、次のことを実行します。$O(n)$仕事、につながる$O(Tn)$最悪の場合、それは$10^{10}$操作は不可能であり、完全に実行不可能です。 

重要な点は、実際には検索する必要がないということです。 選択したら$x = 1$、唯一の制約は次のとおりです。$y = n - 1$とは異なります$1$。 これは次の場合にのみ失敗します。$n = 2$。 すべての大きな値については、$1$そして$n - 1$は、正しく合計される明確な正の整数であることが保証されます。$n$。 問題全体は、定数時間の条件付き構造に崩壊します。

 ## アルゴリズムのチュートリアル

 有効な分解の構造から直接答えを構築します。 

1.読む$n$。 目標は、それを 2 つの異なる正の整数の合計として表現することです。 
2. かどうかを確認します。$n \le 2$。 この範囲では、最小の個別の正のペアは次のとおりであるため、有効なペアは存在しません。$(1,2)$、すでに合計は次のようになります$3$。 これより小さい合計は、繰り返しを強制するかゼロを含むかのいずれかであり、どちらも無効です。 
3. もし$n \ge 3$、 セット$x = 1$。 最小の正の整数を選択すると、2 番目の値に対する制約が最小限に抑えられ、正の値が保証されます。 
4. コンピューティング$y = n - 1$。 これは合計条件によって強制されます。 
5. 出力$x$そして$y$。 これらは自動的に区別されます。$n - 1 \ne 1$のために$n \ge 3$。 

### なぜ効果があるのか

 有効な解決策には、次のものが必要です。$x + y = n$と$x \ne y$そして両方ともポジティブです。 のために$n \ge 3$、ペア$(1, n-1)$すべての制約を満たします。 構築は特別な性質に依存しないため、$n$少なくともであること以外は$3$、有効な分解が存在する場合は常に、有効な分解が生成されます。 のために$n \le 2$、肯定性と区別性に関する不等式制約によりすべての可能性が排除されるため、否定的な答えが強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        if n <= 2:
            out.append("-1 -1")
        else:
            out.append(f"1 {n-1}")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装はその推論を正確に反映しています。 各テスト ケースは一定時間内に独立して処理されます。 唯一の条件分岐は、有効な分解が存在するかどうかをチェックします。 有効な場合の選択は、$1$これは自動的に区別性を保証し、追加のチェックの必要性を回避するため、意図的に行われます。 

誤って出力しないように注意する必要があります$n$そして$0$ゼロは正の整数ではないためです。 建設$1$そして$n-1$これを完全に回避します。

 ## 特殊なケース

 のために$n = 1$、アルゴリズムは直接出力します$-1 -1$なぜなら、1 を 2 つの正の整数に分割する方法がないからです。 どの試行にもゼロまたは負の値が必要ですが、これらの値は許可されていません。

全員にとって$n \ge 3$、建設は常に生成します$(1, n-1)$。 境界線でも$n = 3$、これは次の結果をもたらします$(1, 2)$、例外なく積極性と明確性を満たします。
