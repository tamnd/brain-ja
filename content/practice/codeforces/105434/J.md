 ## 解決策
 ## 問題の理解

 私たちには学生の列が与えられました。 各生徒は 1 から m までの「幸運な数字」を 1 つ持っているため、この線は m 個のカテゴリにわたる長さ n の配列 S として見ることができます。 

1 から m までの順列を選択することで、これらの m 個の幸運な数字に順位を割り当てることができます。 この順列は、各数値の「ランク」または「ギフト レベル」を示します。すべての値 x はランク p[x] を取得します。ここで、ランクの小さいまたは大きいこと自体は問題ではなく、スコア ルールを通じてランク間の相対的な違いのみが問題になります。 

順位が決まったら、列内の隣接する生徒のペアをすべて調べます。 位置 i−1 と i の間の各境界について、それらのラッキーナンバーのランクを比較します。 右側の生徒が左側の生徒よりも高いか同等のランクを持っている場合、ランクの差に比例したコストを支払います。 正しいもののランクが低い場合は、代わりにランクの合計に応じて異なるコストを支払います。 

タスクは、ライン内のすべての隣接ペアにわたる合計コストが最小化されるように、m 値のランクの順列を選択することです。 

構造上の重要な点は、n は 100000 まで大きくなり得るが、m は最大 20 であるということです。これは、どの状態空間でも学生を個別に扱うことができないことがすぐにわかります。 ランクの順列または州ごとの学生を反復するソリューションは失敗します。 唯一管理可能な次元は個別の値の数であるため、ソリューションでは配列 S を値間の相互作用に圧縮する必要があります。 

素朴な解釈では、すべての M を試してみることを提案するかもしれません。 ランクの割り当て。 それは20歳ですでに爆発しています！ そしてそれは完全に不可能です。 

さらに微妙な問題は、コストが任意の相互作用ではなく、元の行の隣接するペアにのみ依存することです。 これは、入力を値間の遷移カウントに集約できることを意味します。 cnt[a][b] を、値 a を持つ生徒の直後に値 b が続く回数として定義すると、問題全体は値 1..m の順位を決定することになります。 

よくある間違いは、最適化中に生徒の順序が動的に重要であると考えることです。 そうではありません。 cntが出来上がったら、学生の順序は関係なくなる。 

エッジ ケースは、m=1 の場合 (隣接関係が意味のある比較に寄与しない場合)、およびすべての S 値が同一の場合 (すべての遷移が自己ペアであり、順列が無関係である場合) に発生します。 

## アプローチ

 ブルートフォースアプローチは、m 値のランクのすべての順列を列挙することです。 各順列について、すべての n−1 個の隣接するペアをスキャンし、ルールを直接適用することでコストを計算します。 これは定義を文字通りに評価するため、正しいです。 ただし、各評価のコストは O(n) であり、m 個あります。 順列は O(m!·n) につながりますが、これは実現可能性をはるかに超えています。 

重要な観察は、入力ラインが周波数ペア cnt[a][b] を通じてのみ寄与しているということです。 これらが判明すると、固定ランキングのコストは、選択された順列の下で順序付けされた値の各ペアがどのように相互作用するかによってのみ決まります。 これにより、問題は各値に 1 から m までの一意の位置を割り当てることに変換されます。 

次に、位置 1 から m を値に割り当てるものとして順列を再解釈します。 2 つの値 a と b が位置 pa と pb を持つ場合、隣接関係 a→b が発生するたびに、pa と pb にのみ依存する決定論的コストに寄与します。 これにより、問題は m 項目にわたる割り当てに変わり、目的は cnt で重み付けされたペアごとの相互作用の合計になります。 

m が小さいため、サブセットに対して動的計画法を使用できます。 各 DP 状態は、既に割り当てられている値のセットを表し、これらは暗黙的に最初の |マスク| に割り当てられます。 何らかの順序で位置を決めます。 次の位置を 1 つの未使用の値に割り当て、以前に配置されたすべての値の増分寄与を計算します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | O(m! · n) | お(1) | 遅すぎる |
 | 割り当て上のサブセット DP | O(2^m · m^2) | O(2^m・m) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、入力シーケンスを遷移テーブル cnt[a][b] に圧縮し、元の行で値 a の直後に値 b が続く回数を数えます。 

次に、値のサブセットに対して動的プログラミングを実行します。 状態マスクは、どの値にすでにランクが割り当てられているかを表します。 マスク内のビット数は、割り当てられた位置の数と正確に一致するため、割り当てる次のランクは位置 t = Popcount(mask) + 1 になります。 

各状態マスクについて、位置 t に配置するマスクにない値 x を選択してみます。 x を配置することによって発生する増分コストは、マスク内に以前に配置されたすべての値 y との相互作用に依存します。 

このような各 y については、それぞれが DP 構築に入ったときに割り当てられているため、割り当てられた位置がすでにわかっています。 px を t、py を以前に y に割り当てた位置とします。 

次に、両方の直接的な貢献を考慮します。 

エッジ x→y の場合、各出現は px ≤ py の場合は k1・(py − px) に寄与し、それ以外の場合は k2・(px + py) に寄与します。 

エッジ y→x の場合、各出現は py ≤ px の場合は k1・(px − py) に寄与し、それ以外の場合は k2・(px + py) に寄与します。 

これらをマスク内のすべての y にわたって合計し、位置 t に x を配置する遷移コストを生成します。 それに応じて dp[mask ∪ {x}] を更新します。 

答えは、すべてのフルマスクの最小 dp です。 

正確さは、すべての隣接関係 cnt[a][b] が、ペアの後の端点が以前に割り当てられた構造に対して完全に固定された瞬間に 1 回だけ計算されるという事実から得られます。 DP 状態は、ランクの完全かつ一貫した部分割り当てを保存するため、すべてのペア (a、b) は、構築によって暗示される最終的な相対順序に基づいて評価されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k1, k2 = map(int, input().split())
    S = list(map(int, input().split()))
    S = [x - 1 for x in S]

    cnt = [[0] * m for _ in range(m)]
    for i in range(n - 1):
        cnt[S[i]][S[i + 1]] += 1

    INF = 10**30
    dp = [INF] * (1 << m)
    dp[0] = 0

    # positions are implicit: mask size = next position
    for mask in range(1 << m):
        t = mask.bit_count() + 1
        if t > m:
            continue
        for x in range(m):
            if mask & (1 << x):
                continue
            nmask = mask | (1 << x)

            cost = dp[mask]
            px = t

            # compute interaction of x with all y in mask
            for y in range(m):
                if not (mask & (1 << y)):
                    continue
                py = bin(mask & ((1 << y) - 1)).count("1") + 1

                cxy = cnt[x][y]
                cyx = cnt[y][x]

                if cxy:
                    if px <= py:
                        cost += cxy * k1 * (py - px)
                    else:
                        cost += cxy * k2 * (px + py)

                if cyx:
                    if py <= px:
                        cost += cyx * k1 * (px - py)
                    else:
                        cost += cyx * k2 * (px + py)

            if cost < dp[nmask]:
                dp[nmask] = cost

    print(dp[(1 << m) - 1])

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に遷移マトリックスを構築するため、長い生徒ラインを再訪する必要がありません。 

DP は値のサブセットを反復します。 各遷移は、次に利用可能なランク位置に 1 つの新しい値を割り当てます。 重要な点は、値の位置が明示的に格納されず、常に 1 から上のランクを埋めるため、サブセットのサイズによって決定されることです。 

すべての配置について、cnt テーブルを使用して、すでに配置されている値との相互作用を計算します。 y に対するネストされたループが必要なのは、以前に割り当てられた各値がその相対位置に応じて異なる影響を与える可能性があるためです。 

DP 更新では、次の値のすべての可能な選択肢の中から最小コストが使用されます。 

## 実用的な例

 n=3、m=3、S=[1,2,3]という単純なケースを考えてみましょう。 遷移カウントは cnt[1][2]=1 および cnt[2][3]=1 で、その他はすべて 0 です。 

マスク=000から始めます。 t=1 で、各値を配置してみます。 最初に 1 を配置した場合、まだコストは発生しません。 

t=2 で、次に 2 が配置されたとします。 1→2 からの寄与はそれらの位置に依存し、1 が 2 の前にあるため k1・1 が生成されます。最後に 3 を配置すると、2→3 から別の k1・1 が生成されます。 合計は 2 であり、最適な構造と一致します。 

| ステップ | マスク | 付加価値 | ポジション | 新たなコスト貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | 000 | 1 | 1 | 0 |
 | 2 | 001 | 2 | 2 | cnt[1][2]・k1 |
 | 3 | 011 | 3 | 3 | cnt[2][3]・k1 |

 これは、値が自然な順序で整列している場合、前方エッジのみが寄与し、常に差分形式を使用することを示しています。 

次に、サンプル パターンの反転構造 S=[1,1,4,5,1,4,1,9,1,9,8,10] を考えます。 ここでは、小さい値と大きい値の間で多くの遷移が繰り返されるため、DP は、上位または下位の順位を早く配置することで、逆順序による高価な k2 ペナルティを軽減するかどうかを決定する必要があります。 DP は単調な割り当てを想定していないため、両方の可能性を正確に調査します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

| スペース | O(2^m) | サブセット上の DP |

 ## 特殊なケース

 すべての生徒が同じラッキーナンバーを持っている場合、遷移行列には cnt[x][x] のみが含まれます。 すべてのエッジの両方の端点が同一であるため、どのような並べ替えでもその値に同じランクが割り当てられ、意味のある比較によって結果が変化することはありません。 すべてのペアは異なる値間でトリガーされることのない差分ゼロまたは同一の合計として評価されるため、DP は即座にゼロコストを生成します。 

m=1 の場合、DP には 1 つの状態しかありません。 アルゴリズムは唯一の値を位置 1 に配置し、処理する対話がないため、結果はゼロになります。 これにより、境界外または空のマスクの問題が回避されます。 

n が大きくても遷移がまばらな場合、少数の cnt エントリだけがゼロ以外になります。 DP は依然としてすべてのマスクを調査しますが、重みゼロのエッジは早期に演算をスキップし、ランタイムの安定性を保つため、ほとんどのコスト計算では何も追加されません。
