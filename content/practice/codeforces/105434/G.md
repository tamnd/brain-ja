 ## 解決策
 ## 問題の理解

 1 から n までのラベルが付けられた頂点上にルート付きツリーを構築するように求められます。ここで、1 はルートとして固定されます。 ツリーの構造には大きな制約があります。すべてのエッジは小さいラベルから大きいラベルに移動する必要があるため、ラベルはルートからのパスに沿って厳密に増加します。 さらに、すべてのノード i には、最大でも持つことができる子の数について厳しい制限があります。 最後に、頂点は深さによってグループ化され、各深さレベルはラベルの連続したブロックで構成されている必要があります。 

目標は、ツリーを明示的に構築することではなく、最も深いレベル、つまりルートから最も遠いノードのセットの最大可能サイズを決定することです。 

制約は非常に大きく、n は最大 10^12 であるため、どのソリューションでも明示的な構築やノードの反復を避ける必要があります。 n が線形または対数であれば問題ありませんが、ノードごとのシミュレーションに依存するものは不可能です。 

この問題について素朴に考える方法は、実際にレベルを 1 つずつ構築してみて、各深さに連続したラベルを割り当て、ノードの容量制約によって次のレベルを「サポート」できるかどうかを確認することです。 ただし、1 つのレベルの実現可能性は累積容量に依存し、ローカルでの貪欲な選択によってグローバルな実現可能性が損なわれる可能性があるため、これはすぐに脆弱になります。 

n が小さいにもかかわらず、容量がすでに不足している場合、微妙なエッジ ケースが発生します。 たとえば、n = 3 の場合、ノード 1 は子を 1 つだけ持つことができ、ノード 2 は子を 2 つ持つことができますが、ラベル制約により厳密な順序付けが強制されます。 レベルを早期に広くしすぎると、残りのノードをより深く配置する機能がブロックされ、最後のレイヤーが誤って最大化される可能性があります。 

本当の難しさは、「レベルの連続性」と「ラベルの増加」によってツリーの形状が強く制限され、問題が事実上、組み合わせツリー検索ではなくグローバルな容量チェックになってしまうことです。 

## アプローチ

 制約を無視して総当りを試みる場合、ラベル増加条件を満たすすべての可能なルートツリーを列挙し、各ノードがその次数制限を遵守しているかどうかを確認し、レベルの連続性を検証し、最も深いレベルのサイズを追跡することになります。 根を張った木の数は超指数関数的に増加し、増加するラベルの木に限定してもカタルーニャ語のような可能性の爆発が残ります。 このアプローチは、小さな n を超えると完全に実行不可能になります。 

重要な観察は、制約によって課される構造により、レベルの正確な形状が総容量よりも重要ではなくなるということです。 各ノード i は、最大で i 個の発信エッジに寄与します。 ツリー内のすべてのエッジは親子関係であるため、有効なツリー内のエッジの総数は正確に n - 1 であり、これらのエッジは、子のない最終レベルのノードを除くすべてのノードの合計容量によってサポートされなければなりません。 

「レベルごとに連続」制約により、間隔 [1, n] が連続したセグメントに効果的に分割されますが、エッジが利用可能な総容量によってグローバルに制限されるという事実は変わりません。 これにより、問題は、必要なすべてのエッジを「ホスト」し、残りを最も深い層として残すのに十分な最小のラベルがいくつあるかを見つけることになります。 

したがって、ツリーを明示的に構築する代わりに、これらのノードの総容量がすべての n - 1 エッジをサポートするのに十分であるように、最小のプレフィックス [1..s] を決定します。 そのプレフィックスが固定されると、残りのすべてのノードが自然に最後の層を形成し、サイズは n - s になります。

 ## アルゴリズムのチュートリアル

 問題は、ツリー内のすべてのエッジを「運ぶ」ために必要な最小ラベル付きノードの数を決定することに帰着します。

1. すべてのノード i は最大 i 個の子を持つことができるため、セット S 内のノードから利用できる子の総数は S 内のラベルの合計であることに注目してください。これは、そのセットの合計送信容量です。 
2. n 個のノード上の有効なツリーには、正確に n - 1 個のエッジがあります。 これらのエッジは親ノードに割り当てる必要があり、どのノードもその容量を超えることはできません。 
3. したがって、最後の層にある点 s + 1 から n までのノードが含まれていると判断した場合、すべてのエッジが [1..s] のノードによってサポートされなければなりません。 最後の層のノードは出力エッジに寄与しません。 
4. これは必要な条件を与えます。[1..s] の容量の合計、つまり s(s + 1)/2 は少なくとも n - 1 でなければなりません。そうでない場合、これらのノードのみを使用してすべてのエッジを割り当てる方法はありません。 
5. 最後の層に残されるノードの数 (n - s) を最大化したいため、最小の s を選択します。 
6. したがって、最終的な答えは、s(s + 1)/2 ≥ n - 1 となる、n から最小の整数 s を引いたものになります。 

### なぜ効果があるのか

 重要な不変条件は、すべてのエッジが、あるノードからの容量の正確に 1 ユニットによってサポートされなければならず、ノード i がそのようなユニットを最大 i 個提供するということです。 エッジは、ラベルの増加によって強制されるプレフィックスとサフィックスの分割を超えるレベル構造から独立しているため、実現可能性は、利用可能な合計容量が少なくとも必要な n - 1 エッジであるかどうかによってのみ決まります。 この条件がプレフィックスに当てはまれば、残りのノードは葉として現れるだけでよいため、常に有効な最も深いレベルに配置できます。 これにより、プレフィックスしきい値が必要かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    
    # we need smallest s such that s(s+1)/2 >= n-1
    target = n - 1
    
    s = 0
    # we could binary search, but direct sqrt-based logic is enough
    # find minimal s
    lo, hi = 0, int(2 * (10**12) ** 0.5) + 5
    
    while lo < hi:
        mid = (lo + hi) // 2
        if mid * (mid + 1) // 2 >= target:
            hi = mid
        else:
            lo = mid + 1
    s = lo
    
    print(n - s)

if __name__ == "__main__":
    solve()
```実装では、不等式 s(s + 1)/2 ≥ n - 1 の二分探索を使用して、最小プレフィックス長 s を直接計算します。Python は大きな整数を安全に処理するため、これによりオーバーフローの問題が完全に回避されます。 最終的な答えは、このプレフィックスの後に残っているノードの数として計算されます。 

微妙な点は、ツリーやレベルを明示的に構築しないことです。 正しさの引数により、プレフィックスの容量が十分であれば、有効な配置が常に存在することが保証されるため、 s の計算だけで十分です。 

## 実用的な例

 ### 例 1

 n = 10 を考えてみましょう。 s(s + 1)/2 ≥ 9 となるような最小の s が必要です。 

| ミッド | s(s+1)/2 | 状態 |
 | --- | --- | --- |
 | 3 | 6 | いいえ |
 | 4 | 10 | はい |

 したがって、s = 4、答えは 10 - 4 = 6 となります。 

これは、すべてのエッジをサポートするには最初の 4 つのノードだけが必要で、最も深い層に 6 つのノードが残ることを示しています。 

### 例 2

 n = 6 とします。 s(s + 1)/2 ≥ 5 となるような s が必要です。 

| ミッド | s(s+1)/2 | 状態 |
 | --- | --- | --- |
 | 2 | 3 | いいえ |
 | 3 | 6 | はい |

 したがって、s = 3、答えは 6 - 3 = 3 となります。 

これは、n が小さい場合でも、容量制約により内部構造とリーフの間で自明ではない分割が強制されることを示しています。

 ## 特殊なケース

 n = 2 の場合、この条件に必要なエッジは 1 つだけであり、ノード 1 だけですでにこの条件をサポートできます。 最小の s は 1 になるため、最後の層には単一のノードが含まれます。ノード 2 には残りの構造制約がないため、これは正しいです。 

10^12 などの非常に大きな n の場合、容量合計の二次関数の性質により、計算される s は最大約 10^6 までしか増加しません。 このアルゴリズムは依然として少数の二分探索ステップを実行しますが、Python は大きな整数をネイティブに処理するため、オーバーフローや精度の問題は発生しません。 

s(s + 1)/2 がちょうど n - 1 と交差する遷移点が唯一の重要な境界です。 他のすべてはそのしきい値から決定的に続きます。
