 ## 解決策
 ## 問題の理解

 私たちは日々の株価の系列を与えられています。 最大で 1 組の日を選択し、早い日に買って、後の日に売ることができ、価格の上昇分を保有日数で割ったものに等しい利益を得ることができます。 正式には当日購入の場合$x$そして当日販売$y$、スコアは$(a_y - a_x) / (y - x)$。 収益性の高い取引が選択されなかった場合、スコアは 0 として定義されます。 

タスクは、すべての有効なペアに対するこの比率の最大値を計算することです。$x < y$。 

入力サイズが到達しました$10^5$これにより、すべての日のペアをチェックするソリューションは即座に除外されます。 全体にわたる二次スキャン$(x, y)$ペアには約$5 \cdot 10^9$3 秒の制限をはるかに超える最悪の場合の評価。 たとえわずかに最適ではないとしても$O(n \log n)$あるいは、比率の構造がより強い単調特性を利用できることを示唆しているため、大規模な前処理は不要です。 

重要なエッジケースは、価格が単調減少している場合です。 たとえば、入力$5, 4, 3, 2, 1$プラスの利益は得られないため、答えは 0 でなければなりません。空の選択を明示的に許可しないアルゴリズムでは、問題定義で禁止されている場合でも、ペアから誤って負の比率が出力されます。 

もう 1 つの微妙なケースは、最大の利益が大きなジャンプではなく短い間隔で得られる場合です。 例えば、$1, 100, 2, 3$極端なものを選択する貪欲な戦略を誘惑するかもしれませんが、最適なセグメントは分子と分母のバランスを同時にとることに依存します。 

## アプローチ

 ブルートフォース手法では、すべての日のペアを列挙します。$x < y$、値を計算します$(a_y - a_x)/(y - x)$、最大値を追跡します。 すべての有効なトランザクションがチェックされるため、これは正しいです。 ただし、適切なエンドポイントごとに$y$、以前にすべてを調べます$x$、おおよそにつながります$n(n-1)/2$評価。 と$n = 10^5$、これは不可能になります。 

この式の構造は幾何学的な解釈を示唆しています。 毎日$x$点として見ることができる$(x, a_x)$、ペアの値は 2 点を結ぶ線の傾きです。 問題は、x 座標の増加に伴う任意の 2 点間の最大の傾きを見つけることに帰着します。 

これは古典的な凸包最適化シナリオになります。各点について、現在の点で最大の傾きを与える最小切片をクエリできる構造を維持する必要があります。 重要な洞察は、時間の経過とともに、以前の点のサブセットのみが最適な候補となり得、これらの点は、連続する点間の傾きが単調である凸包内に維持できるということです。 

これにより、ポイントの下凸包を維持し、単調ポインタまたはデクを使用して、償却定数時間で新しい日ごとに前の最良のポイントをクエリすることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 凸包 / 単調包 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは毎日再解釈します$i$ポイントとして$(i, a_i)$。 2 点間のスコアは、それらを結ぶ線の傾きです。 インデックスが増加するすべてのペアにわたる最大の傾きが必要です。 

候補ポイントの凸包を維持します。各ポイントは、最適な購入時間として機能する前日を表します。 

1. 空のデキューから開始して、候補インデックスを格納します。 デキューは、連続するポイント間の勾配が単調になるように構造内のポイントを維持します。 
2. 毎日繰り返す$i$左から右へ。 
3. 現在のポイントを挿入する前に、傾きを最大にする両端キュー内の最良の前のポイントをクエリします。$(a_i - a_j) / (i - j)$。 
4. これを見つけるには$j$、deque 内の候補を比較します。 傾斜関数は船体全体にわたって単峰性であるため、次の候補が傾斜を改善している間にポインターを進めることができます。 
5. その日に見つかった最良の傾きを使用して全体的な答えを更新します。$i$。 
6. 現在のポイントを挿入します$i$凸性を維持しながらデックに変換します。 最後の 2 点と新しい点が凸性に違反している場合は、中間点を削除します。 
7. すべての日が処理されるまで続行します。 

挿入とクエリの両方における重要な考え方は、支配されたポイントが再び最適になることはなく、安全に削除できるということです。 

### なぜ効果があるのか

 表現$(a_y - a_x)/(y - x)$平面内の 2 点間の傾きです。 凸包のプロパティにより、任意の点のセットについて、新しい点への最大傾斜が、船体の内部ではなく、船体の端点で達成されることが保証されます。 インデックスの昇順で極端な候補のみを維持することにより、将来のすべてのクエリに対して、削除されたすべてのポイントがその近傍の組み合わせよりも悪いことが証明されます。 これにより、検索スペースが全体的に線形サイズに削減されながら、正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def slope(i, j, a):
    return (a[i] - a[j]) / (i - j)

def bad(a, i, j, k):
    return (a[j] - a[i]) * (k - j) >= (a[k] - a[j]) * (j - i)

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    from collections import deque
    dq = deque()

    ans = 0.0

    for i in range(n):
        while len(dq) >= 2:
            j = dq[0]
            k = dq[1]
            if slope(i, j, a) <= slope(i, k, a):
                dq.popleft()
            else:
                break

        if dq:
            ans = max(ans, slope(i, dq[0], a))

        while len(dq) >= 2 and bad(a, dq[-2], dq[-1], i):
            dq.pop()

        dq.append(i)

    print(f"{ans:.3f}")

if __name__ == "__main__":
    solve()
```このソリューションは、購入候補日の満了日を維持します。 の`slope`関数は、候補ペアの 1 日あたりの利益を評価します。 クエリ ステップはデクの前から移動しますが、より良い傾斜がさらに先に存在し、凸包上の傾斜の単調構造を利用します。 

の`bad`関数は、凸性を維持するために中間点が不要になった場合に中間点を削除します。 最終的な答えは float で計算されますが、相互乗算された傾きを比較して、船体のメンテナンス ステップでの浮動小数点精度の問題を回避します。 

「取引なし」オプションを尊重するため、答えは 0.0 から始まります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各インデックスはデキューに出入りするのは最大 1 回であり、各インデックスは償却定数時間で処理されます。 
| スペース | O(n) | Deque は、最悪の場合、プルーニングの前に最大でもすべてのインデックスを保存します。 

線形複雑さが必要なのは、次の理由からです。$n = 10^5$、二次探索は時間制限を超えてしまいます。 整数インデックスのみが保存されるため、メモリ使用量は 512 MB 未満に安全に保たれます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))

    from collections import deque

    def slope(i, j):
        return (a[i] - a[j]) / (i - j)

    def bad(i, j, k):
        return (a[j] - a[i]) * (k - j) >= (a[k] - a[j]) * (j - i)

    dq = deque()
    ans = 0.0

    for i in range(n):
        while len(dq) >= 2:
            j = dq[0]
            k = dq[1]
            if slope(i, j) <= slope(i, k):
                dq.popleft()
            else:
                break

        if dq:
            ans = max(ans, slope(i, dq[0]))

        while len(dq) >= 2 and bad(dq[-2], dq[-1], i):
            dq.pop()

        dq.append(i)

    return f"{ans:.3f}"

 ## 特殊なケース

 次のような 1 日の入力の場合`10`、両端キューには 1 つのポイントのみが含まれており、有効なトランザクションは存在しません。 アルゴリズムは傾きを計算しないため、答えは 0.0 のままです。 

次のような厳密に減少するシーケンスの場合`5 4 3 2 1`、計算されたすべての傾きは負ですが、アルゴリズムは依然としてデキューを更新し、候補をチェックします。 答えは 0.0 から始まり、プラスの改善のみが重要となるため、更新は行われません。 

最適なペアが隣接している場合など`1 100`、最初の比較では傾き 99 が直接評価され、これがすぐに最良の答えになります。 新しいインデックスは挿入前に現在のハルに対してテストされるため、デキュー ロジックはこのケースを遅延したりスキップしたりしません。 

振動入力の場合、船体のメンテナンス中に支配的なポイントが削除され、構造的に関連する候補のみが残り、適切なエンドポイントが到着したときに潜在的な最適な傾斜がすべて評価されます。
