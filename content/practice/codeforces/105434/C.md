 ## 解決策
 ## 問題の理解

 ノード 1 がルートであるルート付きツリーが与えられ、各エッジには入力順序に応じたインデックスがあります。 すべてのエッジはアクティブ状態で開始します。これは、すべてのノードが最初は完全に接続されていることを意味します。 

各操作は 2 つのアクションで構成されます。 まず、特定のエッジの状態を切り替えて、エッジがオフの場合はオンに、オンの場合はオフにします。 次に、クエリ ノード y を取得し、y を含む現在アクティブなエッジのみによって形成される接続コンポーネントを調べます。 そのコンポーネント内のすべてのノードの中で、深さの点でルートに最も近いノード、つまり最小の深さ値を持つ祖先を出力するように求められます。 

重要な動的側面は、エッジが継続的に切り替えられるため、時間の経過とともにフォレストが変化し、各クエリが現在の接続構造を反映する必要があることです。 

制約は大きく、最大 10^6 ノードと最大 5 × 10^5 演算です。 これにより、クエリごとに接続を最初から再計算するアプローチは即座に除外されます。 クエリごとの線形走査でさえ遅すぎます。 各コンポーネントの代表ノードを抽出できる高速接続クエリによる動的なエッジのアクティブ化と非アクティブ化をサポートする構造が必要です。 

微妙な問題は、答えが接続コンポーネント内の任意のノードではなく、特に元のルート ツリー内の最小の深さのノードであることです。 これは、任意の接続情報を要求されるのではなく、各コンポーネントが正規の「最上位」ノードを維持する必要がある動的フォレストを要求されることを意味します。 

単純な間違いは、切り替えのたびに BFS または DFS を使用して接続コンポーネントを再計算することです。 たとえば、チェーン 1-2-3-4-5 があり、エッジ 3 を繰り返し切り替えると、チェーンの大部分を繰り返し走査することになり、二次的な動作が発生します。 

もう 1 つの微妙な落とし穴は、親ポインターのみを維持すれば十分であると想定していることです。 エッジを削除できるため、構造は静的なツリーではなくなり、コンポーネントが分割と結合を繰り返す動的なフォレストになります。 

## アプローチ

 ブルート フォース ソリューションでは、各クエリが個別に処理されます。 エッジを切り替えた後、アクティブなエッジのみを使用して隣接関係を再構築し、y から BFS または DFS を実行してコンポーネント内のすべてのノードを収集し、最小の深さでノードを追跡します。 これは接続の定義に直接従うため、正しいです。 ただし、隣接関係を再構築したり、クエリごとにコンポーネントを走査したりすると、最悪の場合でも O(n) のコストがかかります。 最大 5 × 10^5 の操作では、最悪の場合、約 5 × 10^11 の操作が必要になりますが、これは現実的ではありません。 

重要な観察は、ツリー内のエッジを削除または復元するだけであること、そしてツリーには特別な特性があるということです。すべてのエッジを削除すると、1 つの接続されたコンポーネントが 2 つに正確に分割されます。 これは、ダイナミックな森林構造が維持されていることを示唆しています。 

ダイナミックな森を作るための自然なツールは、リンクカットツリーです。 ただし、完全なパスのクエリや任意の再ルート操作は必要ありません。 必要なのは、接続されたコンポーネントを維持し、コンポーネント内の最小深さのノードを返すクエリをサポートすることだけです。 

ツリーをルート化されたものとして扱い、どのエッジがアクティブであるかに応じてノードごとに親子関係を維持できます。 任意の接続を維持する代わりに、標準の DSU では処理できない削除をサポートする、union-find のような構造を維持します。 

標準的なトリックは、ノード集合体で拡張されたリンクカット ツリーを使用することです。各ノードはその深さを保存し、各接続コンポーネントは最小深さノードを維持値として維持します。 エッジが切り替わると、対応するエンドポイントが切断またはリンクされます。 次に、各クエリ ノード y について、そのルート代表にアクセスし、そのコンポーネントの格納された最小深さのノードを報告します。 

リンクカット ツリーは、償却対数時間で動的接続を維持するため、各操作が O(log n) に削減されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | リンクカットツリー | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在のアクティブなエッジを動的なフォレストとしてモデル化します。 各ノードは、優先パスを維持し、エッジの切断とリンクの両方をサポートするリンクカット ツリー構造内に格納されます。 

1. n 個のノードすべてでリンクカット ツリーを初期化します。各ノードは元のルート ツリーにその深さを格納します。 この深さは決して変わらないため、どのノードがコンポーネントの「ルート」であるかを決定するためのキーとして機能します。 
2. すべてのエッジに対して反復処理を行います。 各エッジについて、後ですぐに切り替えられるように、そのエンドポイントを保存します。 エッジが現在アクティブな場合、2 つのエンドポイントがリンクカット ツリー内でリンクされていることを確認します。 非アクティブな場合、接続は切断されます。 
3. エッジ x のトグル操作については、その現在の状態を確認します。 アクティブな場合は、その端点間のエッジをカットします。 非アクティブな場合は、そのエンドポイントをリンクします。 これにより、リンクカット ツリーが現在アクティブなフォレストを正確に表すという不変条件が維持されます。 
4. 切り替え後、リンクカット ツリー内の代表ルートにアクセスして、ノード y に対してクエリを実行します。 リンクカット ツリーは各コンポーネントに関する集約された情報を保持するため、そのコンポーネントを表すサブツリー内の最小の深さのノードを取得します。 
5. そのノードをこの操作の答えとして出力します。 

重要な考え方は、リンクカット ツリーは接続を追跡するだけでなく、接続された各コンポーネントにわたる動的な集約も維持するということです。 各ノードにはその深さが含まれるため、合計の最小値は当然そのコンポーネント内の最も浅いノードに対応します。 

### なぜ効果があるのか

 正確さは、リンクカット ツリー フォレストがアクティブ エッジによって形成されたグラフと正確に一致するという不変条件にすべてのステップで依存します。 すべてのトグルで 1 つのエッジだけを分割または結合することによってこの構造が更新されるため、隠れた接続の変更は発生しません。 リンクカット構造内の各コンポーネントは、アクティブなグラフ内の接続コンポーネントに正確に対応するため、その構造上で計算される集計、特に最小深さのノードは、元のツリー内の真のコンポーネントと一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class LCTNode:
    __slots__ = ("l", "r", "p", "rev", "val", "best", "id")
    def __init__(self, i, depth):
        self.l = None
        self.r = None
        self.p = None
        self.rev = False
        self.id = i
        self.val = (depth, i)
        self.best = self.val

def is_root(x):
    return not x.p or (x.p.l is not x and x.p.r is not x)

def push(x):
    if x and x.rev:
        x.l, x.r = x.r, x.l
        if x.l: x.l.rev ^= True
        if x.r: x.r.rev ^= True
        x.rev = False

def pull(x):
    x.best = x.val
    if x.l and x.l.best < x.best:
        x.best = x.l.best
    if x.r and x.r.best < x.best:
        x.best = x.r.best

def rotate(x):
    p = x.p
    g = p.p
    push(p); push(x)
    if p.l is x:
        p.l = b = x.r
        x.r = p
    else:
        p.r = b = x.l
        x.l = p
    if b: b.p = p
    x.p = g
    p.p = x
    if g:
        if g.l is p: g.l = x
        elif g.r is p: g.r = x
    pull(p); pull(x)

def splay(x):
    while not is_root(x):
        p = x.p
        g = p.p
        if not is_root(p):
            if (p.l is x) == (g.l is p):
                rotate(p)
            else:
                rotate(x)
        rotate(x)

def access(x):
    last = None
    v = x
    while v:
        splay(v)
        v.r = last
        pull(v)
        last = v
        v = v.p
    splay(x)

def find_root(x):
    access(x)
    while True:
        push(x)
        if x.l:
            x = x.l
        else:
            break
    splay(x)
    return x

def link(x, y):
    access(x)
    x.p = y

def cut(x, y):
    access(x)
    splay(y)
    if y.r is x:
        y.r.p = None
        y.r = None
        pull(y)

def main():
    n, q = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    edges = []

    for _ in range(n - 1):
        u, v = map(int, input().split())
        edges.append((u, v))
        adj[u].append(v)
        adj[v].append(u)

    depth = [0] * (n + 1)

    stack = [(1, 0)]
    while stack:
        u, p = stack.pop()
        for v in adj[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            stack.append((v, u))

    nodes = [None] + [LCTNode(i, depth[i]) for i in range(1, n + 1)]

    active = [True] * (n - 1)

    for i, (u, v) in enumerate(edges):
        link(nodes[u], nodes[v])

    for _ in range(q):
        x, y = map(int, input().split())
        u, v = edges[x - 1]

        if active[x - 1]:
            cut(nodes[u], nodes[v])
            active[x - 1] = False
        else:
            link(nodes[u], nodes[v])
            active[x - 1] = True

        root = find_root(nodes[y])
        access(root)
        print(root.best[1])

if __name__ == "__main__":
    main()
```このソリューションは、各ノードが深さとインデックスで構成されるペアを格納するリンクカット ツリーを構築します。 ペア比較により、コンポーネント内の最小深さのノードをルート集合体から直接取得できることが保証されます。 

の`link`そして`cut`操作はエッジのトグルに正確に対応します。 DFS は初期深度を計算するために 1 回だけ使用され、実行中は固定されたままになります。 クエリで使用されるのは、`find_root`連結成分の代表を特定し、集計された最小値を読み取ります。 

実装の微妙な点は、格納される値がタプルであることです。`(depth, node_id)`これにより、辞書編集的な比較で最も浅いノードが正しく選択され、より小さいインデックスによって関係が分割されます。 

## 実用的な例

 最初にエッジがすべてアクティブになっている、小さなチェーン 1-2-3-4 を考えてみましょう。 エッジ 2 (2 と 3 の間) を切り替えて、ノード 4 をクエリするとします。 

| ステップ | アクション | アクティブエッジ | 4 のコンポーネント | 最良 (最小深さノード) |
 | --- | --- | --- | --- | --- |
 | 1 | イニシャル | (1-2、2-3、3-4) | {1,2,3,4} | 1 |
 | 2 | カットエッジ2-3 | (1-2、3-4) | {3,4} | 3 |
 | 3 | クエリy=4 | 変更なし | {3,4} | 3 |

 このトレースは、単一のカットがコンポーネントを分割し、新しいサブツリーのルートへの答えを即座に変更する様子を示しています。 

ここで、ルート 1 で葉 2、3、4 を持つスターのエッジを切り替えることを考えてみましょう。 エッジ (1,2) をカットし、次に (1,3) をカットして、ノード 4 をクエリするとします。 

| ステップ | アクション | アクティブエッジ | 4 のコンポーネント | ベスト |
 | --- | --- | --- | --- | --- |
 | 1 | イニシャル | すべてのエッジ | {1,2,3,4} | 1 |
 | 2 | カット1-2 | (1-3、1-4) | {1,3,4} | 1 |
 | 3 | カット1-3 | (1-4) | {1,4} | 1 |
 | 4 | クエリy=4 | 変更なし | {1,4} | 1 |

 各操作では、再計算を行わずに接続が動的に維持されます。

 ## 特殊なケース

 重要なエッジ ケースは、同じエッジを繰り返し切り替えることです。 構造は切断と再リンクの両方をサポートする必要があるため、単調な削除を前提とした実装は失敗します。 このソリューションでは、各トグルが現在の状態を明示的にチェックし、逆の操作を適用するため、リンクカット ツリーの一貫性が維持されます。 

もう 1 つのケースは、クエリされたノード自体がそのコンポーネントのルートである場合です。 たとえば、ノード 1 が分離されてクエリされた場合でも、単一ノード コンポーネントの集合体はそれ自身の格納値にすぎないため、アルゴリズムは引き続き 1 を返します。
