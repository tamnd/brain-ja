 ## 解決策
 ## 問題の理解

 各頂点には、頂点が削除されると変化する現在の次数が関連付けられているツリーが与えられます。 頂点を削除できるのは、頂点を選択した時点でその次数が偶数である場合のみです。 頂点が削除されると、すべての入射エッジが消えるため、その近傍の次数が減少します。 

タスクは、選択された頂点が現在偶数次数を持つ必要があるというルールを常に尊重しながら、すべての頂点を削除する一連の削除が存在するかどうかを判断することです。 このようなシーケンスが存在する場合は、有効な順序を 1 つ出力する必要があります。 

入力表現はツリーのルート記述です。各頂点 i は親 p[i] に接続されているか、p[i] が 0 に等しい場合はルートになります。 これは、n から 1 を引いたエッジを持つ無向ツリーを定義します。 頂点の削除によって度合いがグローバルに変更されるため、プロセス自体は動的であり、ローカルな決定が将来の可用性に影響します。 

n が 2 · 10^5 までの制約は、すべての解が線形または線形演算に近くなければならないことを意味します。 次数を繰り返し再計算したり、ステップごとに隣接リストを更新して単純な削除をシミュレートしたりすると、密な相互作用パターンで二次的な動作が発生する危険があります。 考えられるすべての順序を試す解決策は階乗的であり、すぐには不可能です。 

いくつかの故障モードが自然に発生します。 

現在偶数次のノードを繰り返し削除する貪欲な戦略は、利用可能なノードの構造を注意深く維持しないと失敗する可能性があります。局所的に偶数の頂点がサブツリー内のパリティ構造を破壊することで将来の進行を妨げる可能性があるためです。 

パリティが独立していると仮定すると、2 番目の微妙な失敗が発生します。ノードを削除すると、隣接するすべてのノードのパリティが変更されるため、ローカルな選択により、多くのノードが偶数から奇数に、またはその逆に反転する可能性があります。 この依存関係を無視すると、有効なグローバル順序付けが存在する場合でも、行き止まりにつながります。 

たとえば、3 つのノード 1-2-3 の単純なパスを考えてみましょう。 最初の次数は 1、2、1 です。次数が偶数であるため、ノード 2 の削除は有効であり、2 つの孤立したノードが残りますが、これらは簡単に削除できます。 代わりに、パリティの進化を考慮せずに最初にリーフを削除すると、大きなツリーでは順序によっては行き詰まってしまう可能性があります。 

重要な問題は、削除可能性をチェックすることではなく、すべての削除を完了する可能性を維持する順序を選択することです。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての削除シーケンスをシミュレートしようとします。 各ステップで、偶数の頂点を選択して再帰します。 最初に最大 n 個の選択肢が存在し、削除されるたびに構造が変化するため、状態空間は本質的に頂点の置換であり、最悪の場合でも O(n!) 個の可能性が得られます。 枝刈りを行っても、パリティ制約によって十分な量の分岐が早期に削除されないため、分岐は指数関数的なままになります。 

重要な観察は、問題は基本的にツリー内のパリティ伝播に関するものであるということです。 頂点を削除すると、隣接するすべての頂点のパリティが反転されます。 これは、正確な次数を追跡しているのではなく、どの頂点が現在偶数であるか、およびエッジに沿った切り替えの下でそのセットがどのように進化するかを追跡していることを意味します。 

重要な構造的洞察は、ツリーがボトムアップの削除戦略を可能にするということです。リーフは最初に次数 1 を持ち、親が削除された後、またはパリティ フリップが隣接する削除に伝播した後にのみ削除可能になるため、制御された方法で処理できます。 これは、事後探索と一致する順序で頂点を処理することを示唆していますが、実際の条件は静的な次数ではなく動的なパリティです。

これをより正確に確認する方法は、以前の削除を考慮した後で現在の状態が均等になるリーフを繰り返し削除する貪欲な削減を検討することです。 リーフが削除されると、ツリー内に唯一残っている隣接するリーフの親にのみ影響します。 これにより、更新がローカルになり管理しやすくなります。 

現在の学位を維持しながら削除をシミュレートします。 頂点を削除するたびに、その親の次数が更新され、新たに適格になる可能性があります。 新しく適格な頂点を常に処理する場合、有効な削除シーケンスの建設的な順序を反映する方法で削除を効果的に上方に伝播します。

 ## アルゴリズムのチュートリアル

 1. 親配列からツリーの隣接構造を構築します。 各ノードの初期次数も計算します。 これが必要なのは、取り外し可能かどうかは構造だけではなく、現在の程度の同等性に依存するためです。 
2. 現在の次数が偶数であるすべての頂点を含むキューを初期化します。 これらは時間 0 で削除の対象となる唯一の頂点であり、すべての有効なプロセスはそれらの 1 つから開始する必要があります。 
3. 頂点がすでに削除されているかどうかを追跡するために配列を維持します。 これにより、二重処理が防止され、各頂点が出力順序で 1 回だけ出現することが保証されます。 
4. キューから頂点 v を繰り返し抽出し、削除がまだ有効かどうかを確認します。 すでに削除されている場合、または以前の更新により現在の程度が奇数である場合は、スキップします。 それ以外の場合は、それを削除して出力シーケンスに追加します。 
5. 頂点 v を削除するとき、ツリー内に唯一残っている隣接頂点の次数を減らします。 ルート化された表現では、これは通常、その親とまだ存在する子です。 次数が変化する各隣接要素は均等になる可能性があるため、まだ削除されておらず、次数が均等になっている場合は、それをキューに追加します。 
6. キューが空になるまで続行します。 最後に、すべての頂点を削除したら、記録された順序を出力します。 それ以外の場合は、有効なシーケンスが存在しません。 

この順序で十分である理由は、すべての削除は隣接するパリティにのみ影響し、ツリーではこれらの影響が長距離の依存関係を作成しないためです。 キューにより、頂点が適格になったときに常に正確に処理されるため、他の頂点のロックを解除する可能性がある有効な削除を見逃すことはありません。 

### なぜ効果があるのか

 このアルゴリズムは、キュー内のすべての頂点が現在偶数次であり、まだ削除されていないという不変条件を維持します。 すべての削除は、隣接するものの程度の同等性を変更するだけであり、これらは適格性について直ちに再検討されます。 グラフは非巡回であるため、各エッジは 1 つのローカル依存関係に寄与するため、有効なグローバル順序付けが存在する場合、巡回依存関係によって最終的な処理が妨げられることはありません。 これにより、有効な完全削除命令が存在する場合は常に、キュー駆動プロセスが後戻りすることなくそれを検出できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    adj = [[] for _ in range(n)]
    deg = [0] * n

    for i in range(n):
        if p[i] != 0:
            v = i
            u = p[i] - 1
            adj[v].append(u)
            adj[u].append(v)
            deg[v] += 1
            deg[u] += 1

    removed = [False] * n
    q = deque()

    for i in range(n):
        if deg[i] % 2 == 0:
            q.append(i)
