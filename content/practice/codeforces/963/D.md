 ## 解決策

 ## 問題の理解

 固定のテキスト文字列が与えられ、その後、多くの独立したパターン クエリが与えられます。 各クエリはパターン文字列と必要な頻度を与えます。 各クエリについて、パターンを含むメイン文字列のすべての部分文字列を十分な頻度で確認し、それらの部分文字列の中から最も短いものを選択する必要があります。 パターンがメイン文字列に全体的に十分な回数出現しない場合、答えは不可能です。 

重要なオブジェクトは、パターンが発生するかどうかだけではなく、そのパターンがメイン文字列内のどこに存在するかです。 パターンの開始位置がすべてわかったら、連続する出現ブロックを選択し、ブロック内の最初の出現からブロック内の最後の出現までウィンドウを拡張することによって、すべての有効な部分文字列が決定されます。 答えは、少なくとも k 回の出現を含む可能な最小のスパンです。 

制約により、グローバルな前処理戦略が強制されます。 パターンの長さの合計は最大 10^5 で、クエリは最大 10^5 であるため、クエリごとにパターン マッチを再計算すると、時間とメモリの両方を超過します。 クエリごとにメイン文字列をスキャンするソリューションは、最悪の場合 O(n^2) になり、すぐに失敗します。 

パターンが長くても、「aaaaa」のような文字列のように重なって表示される場合、微妙なエッジ ケースが表示されます。 「aaa」の出現は重なり合っており、最小ウィンドウは、重なりを個別の出現としてどのようにカウントするかによって異なります。 k が 1 の場合、別の問題が発生します。この場合、答えは単にパターンが存在する場合の長さになりますが、ばらばらの出現を仮定する単純なアプローチでは、依然として境界をカウントしすぎたり、境界を誤ったりする可能性があります。 

## アプローチ

 直接的な解決策では、メイン文字列をスキャンし、出現するパターンをすべて収集することで、各クエリを個別に処理します。 次に、パターンごとにその出現位置を取得し、k 回の連続出現をカバーする最小ウィンドウを計算します。 これは正しいです。k 個の出現を含むサブストリングには、出現順にいくつかの k 個の連続するものが含まれている必要があるからです。 問題はコストです。クエリごとに完全な文字列をスキャンすると、最悪の場合 O(|s| * n) が得られますが、これは約 10^10 の演算に相当し、実行不可能です。 

重要な点は、すべてのパターンが事前にわかっており、その全長が短いことです。 これは、多くのパターンについて「このパターンは のどこに発生するか」を一度に回答できるグローバル構造を構築することを示唆しています。 LCP を備えた接尾辞オートマトンまたは接尾辞配列も機能しますが、ここで最も自然に適合するのは、終了位置追跡で強化された接尾辞オートマトンです。 

接尾辞オートマトンは s のすべての部分文字列をコンパクトに表し、O(|pattern|) 内の任意のパターンに対応する状態を見つけることができます。 各状態は部分文字列の出現セットを表し、接尾辞リンクを通じて終了位置を伝播することにより、一致したパターンごとにすべての出現インデックスを収集できます。 すべての出現を取得したら、k 個の連続するソート位置をカバーする最適なウィンドウを計算するだけで済みます。これは、ソートされたリストに対する単純なスライディング ウィンドウの最小値です。 

したがって、解決策は次のようになります。SAM を構築し、それに各クエリ文字列をフィードし、その状態のすべての終了位置を取得し、それらを並べ替えて、k 回の連続出現をカバーする最小スパンを計算します。

 ## アルゴリズムのチュートリアル

メイン文字列に対して接尾辞オートマトンを構築します。 各状態は、文字、サフィックス リンク、および長さごとに遷移を保存します。 さらに、各状態は、その状態の部分文字列が発生する終了位置のリストを保存します。 構築中に、各プレフィックスの最終状態をマークし、状態の長さの降順にオカレンスを伝播することによって、これらのリストにデータを追加します。 

クエリ パターンごとに、オートマトンを 1 文字ずつ実行します。 いずれかのステップで遷移を追跡できない場合、そのパターンは存在せず、答えは -1 になります。 

ある状態に正常に到達すると、その状態はパターンのすべての出現を表します。 文字列内のすべての一致の終了位置を含む出現リストを抽出します。 各終了位置からパターン出現の開始位置を導き出します。 

これらの開始位置を並べ替えます。 次に、この並べ替えられたリストに対してサイズ k のウィンドウをスキャンします。 各ウィンドウについて、最初の出現の開始点から最後の出現の終了点までの部分文字列の範囲を計算します。 最良の答えは、すべてのウィンドウにわたる最小のスパンです。 

最後に、この最小長を出力するか、出現回数が k 未満の場合は -1 を出力します。 

### なぜ効果があるのか

 パターンの k 個の出現を含む部分文字列は、その内部に k 個の出現開始位置を引き起こし、これらは昇順で出現する必要があります。 出現をスキップしてもスパンが増加するだけであるため、k 個の出現をカバーする最も緊密な部分文字列は、常にソート順に並べられた k 個の出現の連続するブロックによって定義されます。 オートマトンは、すべての出現を正確に列挙することを保証し、スライディング ウィンドウは、構成を見逃さずにすべての最適な連続グループをテストすることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SAM:
    def __init__(self, n):
        self.next = [dict()]
        self.link = [-1]
        self.length = [0]
        self.pos = [[]]
        self.last = 0

    def extend(self, c, idx):
        cur = len(self.next)
        self.next.append({})
        self.length.append(self.length[self.last] + 1)
        self.link.append(0)
        self.pos.append([idx])

        p = self.last
        while p != -1 and c not in self.next[p]:
            self.next[p][c] = cur
            p = self.link[p]

        if p == -1:
            self.link[cur] = 0
        else:
            q = self.next[p][c]
            if self.length[p] + 1 == self.length[q]:
                self.link[cur] = q
            else:
                clone = len(self.next)
                self.next.append(self.next[q].copy())
                self.length.append(self.length[p] + 1)
                self.link.append(self.link[q])
                self.pos.append([])

                while p != -1 and self.next[p].get(c) == q:
                    self.next[p][c] = clone
                    p = self.link[p]

                self.link[q] = self.link[cur] = clone

        self.last = cur

    def build(self, s):
        for i, ch in enumerate(s):
            self.extend(ch, i)

    def propagate(self):
        order = sorted(range(len(self.next)), key=lambda x: self.length[x], reverse=True)
        for v in order:
            if self.link[v] != -1:
                self.pos[self.link[v]].extend(self.pos[v])

    def match(self, t):
        v = 0
        for ch in t:
            if ch not in self.next[v]:
                return None
            v = self.next[v][ch]
        return v

s = input().strip()
sam = SAM(len(s))
sam.build(s)
sam.propagate()

q = int(input())
for _ in range(q):
    k, m = input().split()
    k = int(k)

    v = sam.match(m)
    if v is None:
        print(-1)
        continue

    occ = sam.pos[v]
    if len(occ) < k:
        print(-1)
        continue

    starts = [p - len(m) + 1 for p in occ]
    starts.sort()

    ans = 10**18
    for i in range(len(starts) - k + 1):
        l = starts[i]
        r = starts[i + k - 1] + len(m) - 1
        ans = min(ans, r - l + 1)

    print(ans)
```接尾辞オートマトンは文字列に対して増分的に構築され、作成されるたびに各状態が 1 つの終了位置を記録します。 構築後、出現リストはサフィックス リンクに沿って伝播され、各状態がそれが表す部分文字列のすべての終端位置を蓄積するようになります。 match 関数は遷移をたどって、パターンに対応する状態を見つけます。 

微妙な実装の詳細は、伝播が長さの降順で発生する必要があることです。そうしないと、短い状態が長い状態に依存するため、サフィックス リンク アグリゲーションが正確さを失います。 もう 1 つの重要な詳細は、終了位置を開始位置に慎重に変換することです。`p - len(m) + 1`、SAM は終了インデックスを格納するためです。 

最終的なウィンドウの計算では、出現がソートされていることを前提としています。 SAM の伝播では順序が保証されないため、明示的なソートが必要です。
