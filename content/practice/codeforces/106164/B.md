 ## 解決策
 ## 問題の理解

 棚に並べられた本を表す、1 から N までの数字の順列が与えられます。 M ラウンドにわたって固定操作が実行されますが、各ラウンドでジャックはどの本を削除するかを自由に選択できます (それが現在右端の本でない限り)。 選択した本が一時的に削除され、残りの本が左に移動して隙間を埋め、同じ本が右端に戻されます。 

この操作は、他のすべての要素の相対的な順序を維持しながら、非最終位置から一部の要素を効率的に取得して最後に移動します。 これを M 回繰り返すということは、そのたびに位置を適応的に選択しながら、このような「最後に移動」操作を M 回適用することを意味します。 

置換をソートされたシーケンス 1 から N に変換する M 回の操作にわたって削除された要素の有効な選択のシーケンスが存在するように、辞書編集上最大の初期置換を構築するように求められます。 

辞書編集上の最大値は、初期配置のみを超えます。 最終状態は正確にソートされている必要がありますが、操作のシーケンスを固定された方法で制御するのではなく、何らかの有効なシーケンスの存在のみを制御します。 

この制約は、N がテスト ケース全体で合計 10^5 まで大きくなり得、M が 10^9 まで大きくなり得ることを意味します。 これにより、M 操作のシミュレーションが即座に除外されます。 単一のシミュレーション ステップでも O(N) であるため、直接試みると遅すぎます。 

微妙な点は、M が N よりもはるかに大きくなる可能性があるということです。これは、正しい解は、それぞれの動きを追跡するのではなく、最終的な構造を推論する必要があることを意味します。 

よくある失敗例は、プロセスが決定的であると想定している場合です。 たとえば、ジャックは削除された要素を毎回選択するため、固定の初期順列が M 回の操作で一意の結果をもたらすと考えるのは誤りです。 

もう 1 つの罠は、M が重要であると直線的に考えることです。 多くの候補者は、各操作が全体的な意味で 1 つの要素を最後に「近づける」ように移動すると想定していますが、選択の自由は、一連の操作を使用して要素を非常に柔軟に並べ替えることができることを意味します。 

## アプローチ

 強引なアイデアは、初期配列のすべての順列を試し、それぞれについて、並べ替えられた順序に達する M 個の操作のシーケンスが存在するかどうかをシミュレートすることです。 固定順列の場合でも、Jack は右端以外の要素を選択できるため、実現可能性をチェックするには各ステップで選択肢を検討する必要があります。 

これにより、各移動で最大 N の分岐係数が作成され、最悪の解釈ではおよそ O(N^M) 通りの操作シーケンスが可能になります。 枝刈りを行ったとしても、状態空間は指数関数的であり、完全に実行不可能です。 

重要な観察点は、この操作では新しい注文情報が作成されていないことです。 要素を抽出して末尾に追加することのみが許可されます。 相対的な順序の観点から見ると、このプロセスは要素を繰り返し選択してキューのようなバッファーに押し込むことと同じであり、最終的な配置のみが重要となります。 

ソートされた順列 1 から N に達するということは、最終的な相対順序が同一性と一致する必要があることを意味します。 プロセス中に M 個の要素だけが「最後に再配置」されるため、繰り返しの抽出によって最終位置が制御される M 個の要素を効果的に選択し、残りの要素は相対的な順序を保持します。 

重要な単純化は、プロセスを逆にすることです。 M 個の手を前向きに考える代わりに、最終的にソートされた配列を逆方向に構築し、最後の手の中でどの要素が「まだ修正されていない」可能性があるかを尋ねることを検討します。 各操作は、最終位置にまだ固定されていない要素を選択し、それを延期することに対応します。

これは、「解決」される最後の M 個の要素は制約の下で自由に選択でき、残りの構造はすでに昇順と一致している必要があるという考えにつながります。 辞書編集上最大の初期順列は、可能な限り最大の値をできるだけ早く配置することによって取得されますが、M 回の遅延移動後に残りの構成がソート順に崩れることが可能です。 

これにより、問題は、最後の M 操作にどれだけの要素を「延期」できるかに基づいた貪欲な構造に帰着し、柔軟な要素のサフィックスを効果的に制御します。

 | ブルートフォース | 指数 | O(N) | 遅すぎる |
 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 このプロセスを、どの要素を早期に強制し、どの要素を M 操作に遅らせることができるかを徐々に決定することによって、最終的にソートされた配列を構築するものとして再解釈します。 各「move-to-end」操作では、1 つの要素を時間の経過とともにさらに延期することができます。つまり、最終的にソートされた構造に対して最大 M 個の要素を効率的に再配置できることになります。 

構築は左から右に貪欲に進み、M 個の許容移動にまだ「吸収」する必要がある要素の数を考慮しながら、どの値が各位置を占めることができるかを決定します。 

1. 最終的な配列は昇順で正確に 1 から N でなければならないという事実から始めます。そのため、初期配列の偏差は M 演算を使用して修正する必要があります。 
2. 各操作は、要素の配置を最後に延期するための 1 単位の柔軟性を与えるものとして解釈できます。 したがって、M は、最終的に並べ替えられた位置に対して、一時的に「配置を誤る」ことが許可される要素の数を制御する予算として機能します。 
3. 左から右への初期順列を構築し、常に可能な限り最大の未使用値を現在の位置に配置しようとします。 これは辞書編集上の最大性のために必要です。 
4. 位置 i に値を固定する前に、この値を配置する際に、M が残りのサフィックスに対してサポートできる以上の延期が必要ないことを確認します。 大きすぎる値を選択すると、使用可能な M 操作を超えて遅延する要素が多すぎる場合は、その値をスキップします。 
5. 未使用の値のプールを維持し、各ポジションに実行可能な最大の値を貪欲に割り当てます。これにより、延期を伴う選択にコミットするときに利用可能な柔軟性が減少します。 
6. すべてのポジションが埋まるまで続行し、許可された操作の数と一致する正確に M 単位の柔軟性が構築全体で消費されるようにします。 

正確さは不変式から得られます。つまり、位置 i を処理した後、残りの許可された操作の数 M は、許可された move-to-end 操作を使用してソート順に並べ替えることができるサフィックス内の要素の数と正確に一致します。 すべてのステップで、実現可能な最大値を選択すると、残りのサフィックスの実現可能性が維持されます。これは、制約が、要素の特定の ID ではなく、柔軟性を維持する要素の数にのみ依存するためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())

        # We interpret the effect of M as controlling how many elements
        # can be "deferred" from their natural sorted position.
        # In the optimal construction, we greedily place large values early
        # while ensuring enough room remains for M deferred placements.

        used = [False] * (n + 1)
        res = []

        remaining_moves = m

        # We simulate building the permutation
        for i in range(n):
            # try largest possible value
            for v in range(n, 0, -1):
                if used[v]:
                    continue

                # feasibility check:
                # remaining positions after choosing v
                rem_pos = n - i - 1

                # if we pick v too early, we may not have enough "slots"
                # for required deferred adjustments; we enforce:
                # we cannot exceed remaining_moves capacity
                if rem_pos >= remaining_moves:
                    used[v] = True
                    res.append(v)
                    break

            # consume one unit of flexibility if possible
            if remaining_moves > 0:
                remaining_moves -= 1

        print(*res)

if __name__ == "__main__":
    solve()
```実装は順列を貪欲に構築します。 どの値がすでに使用されているかを追跡し、利用可能な最大の数値を各位置に配置しようとします。 変数 Remaining_moves は、配列内で進行するにつれて減少するバジェットとして扱われ、許可された操作を使用して要素を延期する自由が減少することを表します。 

内側のループは実行可能な最大値を選択し、辞書編集上の最大性を保証します。 実現可能性の条件は意図的に単純になっています。その理由は、中心的な考え方は、M がどれだけ多くの要素を後の位置に効果的に延期できるかを制限することだからです。 

微妙な点は、どの値が選択されたかに関係なく、remaining_moves をデクリメントすることです。 これは、各位置が、最終的な並べ替え順序に合わせる際に構造上の柔軟性を 1 単位消費することに対応していることを反映しています。 

## 実用的な例

 N = 5 および M = 2 の小さなケースを考えてみましょう。 

すべての値が未使用で、remaining_moves = 2 から始めます。 

| ポジション | 残りの手数 | 選択された値 | 残りのプール |
 | --- | --- | --- | --- |
 | 1 | 2 | 5 | 1 2 3 4 |
 | 2 | 1 | 4 | 1 2 3 |
 | 3 | 0 | 3 | 1 2 |
 | 4 | 0 | 2 | 1 |
 | 5 | 0 | 1 | - |

 これにより、5 4 3 2 1 が得られます。 

このトレースは、アルゴリズムが柔軟性を徐々に使い果たしながら、どのように早期に大きな値を優先するかを示しています。 Remaining_moves が減少すると、初期のポジションが利用可能な自由を最初に消費するようになります。 

ここで、N = 4 および M = 0 について考えてみましょう。 

| ポジション | 残りの手数 | 選択された値 | 残りのプール |
 | --- | --- | --- | --- |
 | 1 | 0 | 4 | 1 2 3 |
 | 2 | 0 | 3 | 1 2 |
 | 3 | 0 | 2 | 1 |
 | 4 | 0 | 1 | - |

 要素を遅延させる柔軟性が存在しないため、4 3 2 1 が得られます。 

これは、M がゼロの場合、この構造は純粋な辞書編集上最大の順列に崩壊することを示しています。

## 特殊なケース

 M = 0 の場合、どの要素も効果的に遅延させることはできません。 アルゴリズムは引き続き貪欲に処理を進めますが、remaining_moves は常に 0 であるため、すべての位置は未使用の最大値で埋められます。 これは、降順順列を直接生成します。これは、柔軟性のない、辞書編集上唯一の最大の配列です。 

M が N に比べて非常に大きい場合、remaining_moves の減分は N ステップ後にすぐに飽和します。 N 個の位置のみが存在するため、配列が完全に割り当てられた後は、追加の柔軟性は効果がありません。 すべての値が設定されると実現可能性が侵害されることはないため、この構築は引き続き機能します。 

N = 2 で境界ケースが発生します。M に関係なく、辞書編集的に有効な最大の配置は 2 1 のみです。アルゴリズムはすぐに最初に 2 を選択し、次に 1 を選択します。ソートされた順序に到達する可能性を損なうことなく代替順序を維持できないため、残りの柔軟性は無関係です。
