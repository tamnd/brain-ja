 ## 解決策
 ## 問題の理解

 各エッジが 2 つの都市の間の通りを表す有向グラフが与えられます。 すべての道路には、移動時間と必要な通行レベルという 2 つの属性があります。 エレナがレベルのパスを所有している場合$P$、彼女は要件が最大でも以下の通りのみを使用することを許可されます。$P$。 より高いレベルのパスでは、使用可能なエッジのセットが厳密に拡張されます。 

パスレベルが固定されると、移動は要件のあるエッジによって引き起こされるサブグラフ上の標準的な最短経路問題になります。$\le P$。 私たちが気にする重要な量は、選択した開始都市について、その都市から他の都市までの最大最短経路距離です。 都市があるノードに到達できない場合、そのパス レベルはその都市では無効であるとみなされます。 

最初のタイプのクエリは、開始都市と制限時間を修正します。 指定された制限時間内にそのスタート地点からすべての都市に到達できるようにするための最低パス レベルを見つける必要があります。 

2 番目のタイプでは、固定開始が削除され、最適な開始都市を選択するように求められます。 都市ごとに、到達可能な最遠距離が制限時間内に収まるように必要な最低通過レベルを計算します。 次に、必要な合格レベルを最小限に抑えて都市を返し、より小さいインデックスで同点を解消します。 

制約は特定の点で厳しいです。$N \le 100$しかし$Q \le 10^5$。 これにより、クエリごとのグラフ計算、特にクエリごとのダイクストラやフロイドのような計算は不可能であることがすぐにわかります。 この構造は、小さな処理よりも重い前処理を示唆しています。$N$、その後、ほぼ一定の時間でクエリに回答します。 

微妙な点は、パスレベルが以下であることです。$10^9$ただし、実際の大きさではなく、パス レベルによるエッジの順序が重要です。 これは、合格レベルを単調パラメータとして扱い、しきい値を超える回答を事前計算する必要があることを示唆しています。 

エッジ ケースの 1 つは、すべてのエッジが有効になっているにもかかわらず、都市が他のすべての都市に到達できない場合に発生します。 たとえば、2 つのコンポーネントを含むグラフでそれらを接続するエッジがない場合、一部の回答は不可能であることを意味します。 タイプ 1 の場合、これは次のようになります。$-1$。 タイプ 2 の場合、次のようになります。$-1 -1$どの都市も制限時間内に他の都市に到達できない場合。 

もう 1 つの重要な故障モードは、対称性を仮定するか、方向を無視することです。 都市は他の都市に到達する可能性がありますが、戻って到達することはできません。また、最短経路は有向エッジを尊重する必要があります。 

最後に、同じノード間の複数のエッジが重要になります。パス要件が異なると、どのエッジがどのしきい値で使用可能になるかが変化する可能性があり、許可されるエッジが増えるにつれて最短時間の構造が非線形に変化するためです。 

## アプローチ

 ブルートフォースのアイデアは簡単です: 特定のパスレベルに対して$P$を超える要件を持つすべてのエッジを破棄します。$P$、指定された開始点 (ダイクストラ) から複数のソースの最短パスを実行し、最大距離を計算します。 タイプ 1 クエリの場合、エッジに存在するすべての可能なパス レベルを試し、制約を満たす最小のものを選択します。 タイプ 2 については、都市ごとに同じことを行います。 

しきい値が固定されるとグラフは標準となるため、これは概念的には機能しますが、遅すぎます。 それぞれのディクストラは、$O(M \log N)$まで繰り返します。$10^5$すでに限界を突破しています。 すべての個別の合格レベルを試しても、別の要素が追加されます。$10^4$、実現不可能な製品につながります。 

重要な観察は、閾値がエッジ要件の 1 つを通過した場合にのみグラフが変化するということです。 以来$N$が小さい場合、各しきい値を状態として扱い、すべてのペアの最短パスを段階的に事前計算できます。 

エッジをパスレベルごとに分類し、徐々に「アクティブ化」します。 各活性化ステップの後、フロイドのような緩和を使用して最短経路を更新します。 なぜなら$N \le 100$, 慎重に構造化されていれば、フロイド-ウォーシャル スタイルの更新は許容され、各しきい値の距離行列を維持できます。 すべてのしきい値が処理されると、すべての可能なパス レベルについて、すべてのペア間の最短パス距離が得られます。 

これから、各しきい値を事前計算できます。$P$そして各スタート都市$u$、値:$$\max_v dist_P(u, v)$$その後、両方のクエリ タイプがしきい値を超えた二分探索に減ります。

 ## アルゴリズムのチュートリアル

 現在アクティブ化されているエッジ セットのすべての都市間で最もよく知られている最短パスを維持しながら、パス要件の昇順にエッジを処理します。 

1. すべてのエッジを必要なパス レベルで並べ替えます。 これにより、先に進むときに、現在のしきい値以上で使用可能になるエッジのみが追加されることが保証されます。 
2. 距離行列を初期化する$dist$どこ$dist[i][j]$を除いては無限大です$dist[i][i] = 0$。 すべてのエッジを移動時間とともに挿入しますが、パス要件がアクティブ化されている場合に限ります。 
3. 同一のパス レベルでグループ化されたエッジをスイープします。 特定のレベルのすべてのエッジを挿入した後、新しく利用可能なエッジを使用して最短パスを更新する緩和ステップを実行します。 これは、新しく接続されたエッジを通過するパスを考慮し、既存の距離を改善することによって行われます。 
4. 各パス レベル グループが処理された後、都市ごとに計算します。$u$値$ecc[u] = \max_v dist[u][v]$。 もしあれば$v$到達不能です、マーク$ecc[u]$無限のように。 
5. 合格レベルから達成可能な最良の値までのマッピングを保存します。 

すべての都市における最小の偏心性、そしてそれを達成する最良の都市。 
6. タイプ 1 クエリの場合$(u, h)$、次のような最小の合格レベルが必要です。$ecc[u] \le h$。 保存されたレベルをバイナリ検索します。 
7. タイプ 2 クエリの場合$(h)$、同様に二分探索を行いますが、各レベルで事前に計算された最適な都市を使用します。 

重要な構造上の決定は、パス レベルがグラフの単調なシーケンスを定義することです。 エッジは一度利用可能になると消えることはないため、最短パスは時間の経過とともに改善されます。 

### なぜ効果があるのか

 任意の固定パスレベルで$P$、グラフは正確に要件を満たしたエッジで構成されます$P$。 私たちのスイープにより、レベルを処理するときに確実に$P$、そのようなエッジはすべて含まれます。 緩和ステップでは、新しく追加されたすべてのエッジが距離行列に完全に統合されるため、この誘導グラフ内のすべての最短パスが正しく計算されることが保証されます。 より多くのエッジが追加されるにつれて距離は減少するだけであるため、離心率のシーケンスはノードごとに単調に増加せず、パス レベルにわたる二分探索が有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def floyd_update(dist, n):
    for k in range(n):
        dk = dist[k]
        for i in range(n):
            di = dist[i]
            dik = di[k]
            if dik == INF:
                continue
            for j in range(n):
                nd = dik + dk[j]
                if nd < di[j]:
                    di[j] = nd

def build_states(n, edges):
    edges.sort(key=lambda x: x[2])
    dist = [[INF]*n for _ in range(n)]
    for i in range(n):
        dist[i][i] = 0

    levels = []
    ecc_by_level = []
    best_city = []
    best_val = []

    i = 0
    m = len(edges)

    while i < m:
        p = edges[i][2]
        while i < m and edges[i][2] == p:
            u, v, _, h = edges[i]
            if h < dist[u][v]:
                dist[u][v] = h
            i += 1

        floyd_update(dist, n)

        ecc = [0]*n
        best = INF
        best_u = 0

        for u in range(n):
            mx = 0
            for v in range(n):
                if dist[u][v] == INF:
                    mx = INF
                    break
                if dist[u][v] > mx:
                    mx = dist[u][v]
            ecc[u] = mx
            if mx < best:
                best = mx
                best_u = u

        levels.append(p)
        ecc_by_level.append(ecc)
        best_val.append(best)
        best_city.append(best_u)

    return levels, ecc_by_level, best_city, best_val

def solve():
    n, m, q = map(int, input().split())
    edges = []
    for _ in range(m):
        u, v, p, h = map(int, input().split())
        edges.append((u-1, v-1, p, h))

    levels, ecc_by_level, best_city, best_val = build_states(n, edges)

    def first_ok(u, limit):
        lo, hi = 0, len(levels)-1
        ans = -1
        while lo <= hi:
            mid = (lo + hi) // 2
            if ecc_by_level[mid][u] <= limit:
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1
        return ans

    def first_best(limit):
        lo, hi = 0, len(levels)-1
        ans = -1
        while lo <= hi:
            mid = (lo + hi) // 2
            if best_val[mid] <= limit:
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1
        return ans

    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            _, u, h = tmp
            u -= 1
            idx = first_ok(u, h)
            if idx == -1:
                print(-1)
            else:
                print(levels[idx])
        else:
            _, h = tmp
            idx = first_best(h)
            if idx == -1:
                print("-1 -1")
            else:
                print(best_city[idx] + 1, levels[idx])

if __name__ == "__main__":
    solve()
```この実装では、パス レベルでソートされたエッジのプレフィックスにそれぞれ対応する一連の状態が構築されます。 各状態は、指定されたしきい値のすべてのエッジを挿入した後にトリガーされるフロイド・ウォーシャル スタイルの緩和を使用して最短パスを再計算します。 これにより、毎回最初から再計算しなくても正確さが保証されます。 

二分探索はこれらの状態の上に重ねられます。 タイプ 1 クエリの場合、固定都市の事前計算された離心率をしきい値全体でスキャンします。 タイプ 2 では、しきい値ごとに事前に計算された最適な都市を使用します。 

主な微妙な点は、各しきい値の更新後に、距離行列にすべてのマルチホップの改善が完全に反映されるようにすることです。そのため、新しく追加されたエッジを 1 回だけ緩和するのではなく、フロイド スタイルのトリプル ループが必要です。 

## 実用的な例

 ### トレースの例

 3 つの都市とエッジを含む簡略化されたグラフを考えてみましょう。 

1→2 (p=1、h=3)、2→3 (p=1、h=4)、1→3 (p=2、h=10)。 

| レベル | アクティブ化されたエッジ | 距離 [1] 最大 | 距離 [2] 最大 | 距離 [3] 最大 |
 | --- | --- | --- | --- | --- |
 | 1 | 1→2、2→3 | 7 | 4 | 0 |
 | 2 | +1→3 | 7 | 4 | 0 |

 レベル 1 では、都市 1 はコスト 7 で 1→2→3 を経由して 3 に到達します。レベル 2 では、直接エッジが存在しますが、最大距離は改善されません。 

これは、下位レベルの接続性がすでに優勢である場合、上位レベルのエッジを追加しても必ずしも最短パスが改善されるわけではないことを示しています。 

### クエリトレース

 クエリが制限 6 で都市 1 から要求したとします。 

レベル 1 では、偏心量は 7 であり、限界を超えています。 レベル 2 では、離心率は再び 7 ですが、依然として無効です。 したがって、答えは -1 です。 

これは、実現可能性が平均または部分的な到達可能性ではなく、最悪の到達可能ノードによって決定されることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、最大パス レベルでもグラフが接続されない場合です。 その状況では、一部のノードではすべての離心率が無限大となり、二分探索は正しく失敗を返さなければなりません。 到達不能なノードはすべての状態を通じて INF として距離を維持するため、アルゴリズムはこれを処理します。そのため、条件を満たすしきい値は存在しません。 

もう 1 つのエッジ ケースは、通過レベルと時間が異なる同じ都市間の複数のエッジです。 アルゴリズムは距離行列の最小移動時間を常に維持するため、後のより高価なエッジがより優れたエッジを上書きすることはありません。 

最後の微妙なケースは、都市がいくつかのしきい値でタイプ 2 クエリに最適である場合です。 各レベルで最良の都市を再計算して明示的に保存するため、厳密に優れた値が表示された場合にのみ更新されるため、インデックスによるタイブレークはスキャン中に自然に保持されます。
