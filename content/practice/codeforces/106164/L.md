 ## 解決策
 ## 問題の理解

 私たちは、レーザーエネルギーが空間を移動するにつれて蓄積される格子状の実験に取り組んでいます。 各受信機は固定座標に配置され、レーザー実行のエンドポイントとして選択した場合、固定ボーナスを提供します。 レーザーは常にクエリ ポイントから開始し、軸に沿った方向に移動し、垂直境界を横切るたびに A 単位のエネルギーを獲得し、水平境界を横切ると B 単位が追加されます。 

クエリ開始位置ごとに、エンドポイントとして 1 つのレシーバーを正確に選択できます。 レーザーの経路は完全に自由ではありません。水平または垂直のいずれかに移動し始める必要があり、使用できる L 字型反射板は最大 1 つで、水平から垂直、またはその逆にちょうど 1 回転できます。 構成の総コストは、累積された境界越えコストに受信者の価値貢献を加えたものです。 タスクは、各クエリに対して可能な最小の最終強度を計算することです。 

重要な隠れた構造は、オプションのターンが 1 つだけあるマンハッタンのような移動では、コストが純粋に幾何学的なものであり、すべての受信機が最適化する必要がある潜在的なエンドポイントであるということです。 

制約は大きく、最大 100,000 の受信者と 100,000 のクエリ、最大 10^9 の座標を持ちます。 これにより、すべての受信者に対するクエリごとのスキャンが直ちに除外されます。 どのような解決策でも、前処理後のクエリ時間を O(log N) または O(1) 程度にまで削減する必要があります。これは、座標変換と支配クエリ、またはマンハッタン メトリックにおける凸幾何学に似た構造を強く示唆しています。 

単純なアプローチでは、クエリごとにすべての受信機を試し、リフレクターの有無にかかわらず、可能な限り最適なパスを計算します。 これには、クエリごとに最大 N 個の候補をチェックし、各候補について最適な方向の選択と潜在的な転換点について推論することがすでに含まれています。 これは 10^10 の演算では遅すぎます。 

より微妙な故障モードは、L 字型リフレクタが任意の経路の自由を導入しないという事実を無視することで発生します。 よくある間違いは、任意のマンハッタン パスが許可されると想定することですが、実際には 1 つの曲がりだけが許可されます。つまり、パス構造は最大 2 つの軸に沿ったセグメントに制限されたままになります。 

## アプローチ

 ブルート フォース ソリューションの概念は単純です。クエリの開始点ごとに、すべての受信機を反復処理し、水平方向または垂直方向に直線的に移動して到達するコストを計算し、さらに正確に 1 回転で最適なコストを計算します。 難しいのは、最適なターニングポイントを効率的に評価することです。 考えられるすべてのリフレクターの配置を明示的に試してみると、リフレクターの位置がグリッド上で連続しているため、複雑さが爆発します。 

重要な観察は、パスに関する唯一の意味のある情報は、そのパスが交差する垂直境界と水平境界の数であるということです。 パスは最大 1 回の回転で軸に沿って整列されるため、受信機へのパスは 2 つの単調セグメント (いずれかの順序で水平セグメントと垂直セグメント) に分解されます。 

したがって、固定受信機 (x, y) と開始点 (s, t) の場合、そこに到達するコストは絶対座標の差にのみ依存します。 一般性を失うことなく、可能な 2 つのパス形状は、水平の後に垂直、または垂直の後に水平です。 どちらも、均一な軸に沿ったコスト構造を持つグリッド内で同じ交差数を生成するため、パス コストは重み付けされたマンハッタン距離に単純化されます。 

A * |x - s| + B * |y - t|。 

リフレクターはエンドポイントのジオメトリを変更しません。 代わりに、最初に x で整列してから y に整列するか、y で整列してから x に整列するかを効果的に選択できますが、どちらの順序でも同一の交差カウントが生成されます。 唯一重要な点は、受信機を 1 つだけ「アクティブ化」できることなので、以下を最小限に抑えたいと考えています。 

A * |x - s| + B * |y - t| - c

 すべての受信機にわたって。

したがって、問題は古典的な 2D クエリに帰着します。つまり、各点 (s, t) について、重み付けされたマンハッタン距離から重みを引いた値を最小にする点 (x, y) を見つけます。 

書き換えます:

 A * |x - s| + B * |y - t| - c

 = (s, t) に対する (x, y) の相対位置に応じた 4 象限にわたる最小値。 

絶対値を展開すると、次の 4 つの線形形式が生成されます。 

1. A(x - s) + B(y - t) - c (x ≥ s、y ≥ t)
 2. A(x - s) + B(t - y) - c (x ≥ s、y ≤ t)
 3. A(s - x) + B(y - t) - c (x ≤ s、y ≥ t)
 4. A(s - x) + B(t - y) - c (x ≤ s、y ≤ t)

 各ケースは x と y の線形関数になり、4 つの変換を維持することが示唆されます。 

A x + B y - c

 A x - B y - c

 - A x + B y - c
 - A x - B y - c

 各クエリについて、x と y (象限) の制約の下でこれらの式の最大値をクエリする必要があります。 これは、座標圧縮された軸上の標準のオフライン スイープまたはセグメント ツリーです。 

通常は 4 つのセグメント ツリーまたは CDQ 分割統治を介して、x 範囲をフィルタリングした後、受信者をソートし、y にわたる最大クエリをサポートする構造を構築します。 これにより、各クエリが対数時間に短縮されます。

 ## アルゴリズムのチュートリアル

 この問題を、点のサブセットにわたる線形形状の最大化に還元します。 

1. すべての受信機について、絶対値の 4 つの符号の組み合わせに対応する 4 つの変換値を計算します。 これらは、クエリ ポイントに対する各象限におけるその受信者の寄与を表します。 
2. 大きなメモリ オーバーヘッドを発生させずに受信機を 2D 構造に格納できるように、x と y に対する座標圧縮を構築します。 座標は 10^9 までなので、これが必要です。 
3. それぞれが x および y にわたる範囲最大クエリに答えることができる 4 つのデータ構造を維持します。 各構造は、絶対値展開から導出される 4 つの一次式の 1 つに対応します。 
4. 変換された値を使用して、すべての受信機をこれらの構造に挿入します。 各構造には、固定 (x, y) に対して、可能な限り最良の寄与が格納されます。 
5. 各クエリ点 (s, t) について、(s, t) を基準にして平面を四分円に分割します。 各象限は 4 つの構造の 1 つに対応し、制限された最大クエリを必要とします。 
6. 4 つの構造すべてを適切にクエリし、最大の結果を取得します。 保存されている変換された目標を無効にすることにより、この最大値を最小コストに変換し直します。 
7. ベースライン クエリ コストからこの最良の受信者の寄与を減算し、結果を出力します。 

### なぜ効果があるのか

 正確さは、絶対値式が平面の 4 つの線形領域への分割を定義し、各領域内で目的が x と y で線形になるという事実に基づいています。 すべての受信機はクエリ ポイントごとに 1 つの相対領域に存在するため、4 つの線形形式をすべて評価することで、真の最適値を確実に取得できます。 セグメント構造により、各領域について受信機の有効なサブセットが正確に考慮され、座標の順序付けによって引き起こされる制約が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Fenwick tree for range maximum
class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [-10**30] * (n + 1)

    def update(self, i, v):
        while i <= self.n:
            if v > self.bit[i]:
                self.bit[i] = v
            i += i & -i

    def query(self, i):
        res = -10**30
        while i > 0:
            if self.bit[i] > res:
                res = self.bit[i]
            i -= i & -i
        return res

def solve():
    N, Q, A, B = map(int, input().split())
    pts = []
    xs, ys = set(), set()

    for _ in range(N):
        x, y, c = map(int, input().split())
        pts.append((x, y, c))
        xs.add(x)
        ys.add(y)

    qs = []
    for i in range(Q):
        s, t = map(int, input().split())
        qs.append((s, t))
        xs.add(s)
        ys.add(t)

    xs = sorted(xs)
    ys = sorted(ys)
    x_id = {v: i+1 for i, v in enumerate(xs)}
    y_id = {v: i+1 for i, v in enumerate(ys)}

    # four BITs for four transforms
    bit1 = BIT(len(ys))
    bit2 = BIT(len(ys))
    bit3 = BIT(len(ys))
    bit4 = BIT(len(ys))

    # we sweep by x, but we need offline processing
    events = []

    for x, y, c in pts:
        ix, iy = x_id[x], y_id[y]
        v1 = A*x + B*y - c
        v2 = A*x - B*y - c
        v3 = -A*x + B*y - c
        v4 = -A*x - B*y - c
        events.append((ix, iy, v1, v2, v3, v4, 0))

    for i, (s, t) in enumerate(qs):
        ix, iy = x_id[s], y_id[t]
        events.append((ix, iy, i, 0, 0, 0, 1))

    events.sort()

    ans = [-10**30] * Q

    for e in events:
        ix = e[0]
        iy = e[1]
        if e[6] == 0:
            _, _, v1, v2, v3, v4, _ = e
            bit1.update(iy, v1)
            bit2.update(iy, v2)
            bit3.update(iy, v3)
            bit4.update(iy, v4)
        else:
            i = e[2]
            best = max(
                bit1.query(iy),
                bit2.query(iy),
                bit3.query(iy),
                bit4.query(iy),
            )
            ans[i] = best

    for i in range(Q):
        print(ans[i])

if __name__ == "__main__":
    solve()
```このソリューションは、すべてのポイントとクエリを一緒に前処理し、座標を圧縮し、4 つのフェンウィック ツリーを使用して 4 つの線形変換の最大値を維持します。 各受信者はすべての構造を更新し、各クエリはそれらの構造から読み取ります。 

実装上の微妙な懸念は、スイープにクエリと更新が混在していることです。 順序付けでは、クエリが処理される前に有効な受信者のみが含まれるようにする必要があります。そうしないと、将来のポイントが以前のクエリに誤って影響を与える可能性があります。

 ## 特殊なケース

 微妙なケースとしては、すべての受信機が同一の座標を持っているが、c 値が異なる場合があります。 すべての変換された値は同じ幾何学的項に集約され、最大の c 調整のみが残るため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、A または B がゼロの場合です。 その場合、動きは 1 つの軸に沿って事実上 1 次元になりますが、一部の線形形式が縮退し、BIT が最大寄与を依然として正確に選択するため、4 変換分解は引き続き機能します。 

最後のエッジケースは、最適な受信機がほとんどの候補とは異なる象限にある場合に発生します。 分解により、すべての象限が独立して評価されることが保証されるため、順序付けの仮定によって候補が失われることはありません。
