 ## 解決策
 ## 問題の理解

 私たちには最大 200,000 個の惑星からなる木が与えられています。 各惑星には 3D 空間内に固定点があります。 どの惑星のペアでも、2 つの独立した量が「満足度」を定義します。 

最初のものは木から来ます。 2 つのノード間の一意のパスに沿って歩くと、正または負のエッジの重みが蓄積され、このパスに沿った合計がトレイン満足度になります。 

2 つ目は幾何学から来ています。 代わりに木を無視して宇宙に直接飛んだ場合、満足感はそれらの座標間のマンハッタンの距離になります。 

選択した惑星のペアの合計スコアは、これら 2 つの値の合計です。 タスクは、すべてのペアが正でない値を与える場合、答えはゼロになるという追加ルールを使用して、すべてのペアにわたってこの合計スコアを最大化することです。 

200,000 ノードという制約により、ペア上の二次関数は即座に除外されます。 すべてのペアのインタラクションを保存することさえ不可能です。 有効な解決策は、通常はツリー分解または構造化ペア列挙を使用して、検索空間を線形または線形対数の複雑さに近い値に削減する必要があります。 

素朴なアプローチは、さまざまな微妙な点で失敗します。 まず、LCA を使用してすべてのペアのパス合計を計算すると、ペアごとにすでに O(n) のコストがかかり、O(n² log n) になります。 第 2 に、たとえツリー クエリが無料だったとしても、マンハッタン距離ではすべてのペアを比較する必要があり、ツリー パスとジオメトリの間の相互作用によって目的が分離不可能になります。 

よくある落とし穴は、2 つのコンポーネントを独立して扱うことです。 たとえば、ツリー パスの合計を最大化するだけでは、重み付きツリー上で最長パスのような問題が発生しますが、マンハッタン距離を単独で最大化することは古典的な 3D 極値変換です。 ただし、同じペアで両方を同時に最適化する必要があるため、それらを個別に解決することによってそれらの組み合わせを実現することはできません。 

別の失敗例は、ツリーをルート化し、パスの合計をプレフィックスの差で置き換え、幾何学的な最大値と貪欲に結合しようとしたときに発生します。 これは、最下位の共通祖先が選択されたペアに依存し、ローカルに修正できないため、問題になります。 

## アプローチ

 直接的なブルート フォースにより、ノードのすべてのペアが評価されます。 各ペアについて、LCA を使用してツリー パスの合計を計算し、マンハッタン距離を直接計算します。 これは正しいですが、O(n²) ペアが必要であり、各評価のコストは O(log n) であり、制限をはるかに超えています。 

重要な観察は、どちらのコンポーネントも「最大化と変換の組み合わせ」に適した形式に書き換えることができますが、それはツリー部分を慎重に扱った後にのみ可能であるということです。 

ツリーをルート化し、距離配列を事前計算します。`base[u]`、ルートからノードまでのエッジの重みの合計です。`u`。 次に、どのペアでも`(u, v)`、ツリー パスの合計は次のようになります。`base[u] + base[v] - 2 * base[lca(u, v)]`。 

難しいのは、2 つのエンドポイントを結合する LCA 用語です。 ここで重心分解が役に立ちます。 重心を修正すると`c`、次に任意の 2 つのノードについて`u`そして`v`削除後に別のコンポーネントに存在する`c`、元のツリーの LCA は正確に一致する必要があります。`c`。 これにより、未知の LCA への依存関係が削除され、ツリー項が次の条件のみに依存する定数シフトに変わります。`c`。 

ここで、問題は局所的なものになります。重心ごとに`c`、ペアを最大化したい`(u, v)`異なる子サブツリー内:`base[u] + base[v] - 2*base[c] + Manhattan(u, v)`。 

以来`-2*base[c]`重心に対して一定である場合、最適化は最大化に帰着します。`base[u] + base[v] + Manhattan(u, v)`。 

これは、ノードの重みが追加された 3D における古典的な最大ペア問題になりました。`base[u]`。 マンハッタン距離は、標準の 8 符号変換を使用して線形化できます。 各符号トリプルについて`(sx, sy, sz)`、次のように書き換えます。`|x_u - x_v| + |y_u - y_v| + |z_u - z_v|`になる`max over signs of sx*(x_u - x_v) + sy*(y_u - y_v) + sz*(z_u - z_v)`。 

全期間のグループを並べ替える`u`そして`v`個別に、変換ごとにこれまでに確認された最高の値を維持するスイープが可能になります。 

重心分解により、各有効なペアが、LCA が重心となる正確に 1 つの重心レベルで処理されるため、ペアが欠落することはありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log n) | O(n) | 遅すぎる |
 | 重心 + 3D 変換 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 任意のノードでツリーをルートし、計算します。`base[u]`、ルートからエッジまでのエッジの重みの合計`u`。 これにより、LCA を使用して任意のツリー パスが差分式に変換されます。 
2. ツリーの重心分解を構築します。 各ステップで重心を選択します`c`現在のコンポーネントの。 これにより、すべてのノード ペアがそれらの相互作用が局所化されたレベルで考慮されるようになります。 
3. 現在の重心の場合`c`、各子サブツリーを 1 つずつ処理します。 以前に処理されたサブツリーからの最適な値を保存するグローバル構造を維持します。 
4. 各ノードについて`u`サブツリーで、マンハッタン距離の 8 つの符号構成すべての変換値を計算します。`val = base[u] + sx*x[u] + sy*y[u] + sz*z[u]`。 

これにより、ツリーの寄与と幾何学的方向の両方が統一されたスカラーで取得されます。 
5. 新しいサブツリーを処理する場合、ノードごとに`u`、前のサブツリーを含むグローバル構造に対してクエリを実行して、最適なペアを見つけます。 これにより最良の結果が得られます`base[u] + base[v] + Manhattan(u, v)`異なる子コンポーネントに分割します。 
6. サブツリーを処理した後、そのすべてのノードをグローバル構造に挿入して、後のサブツリーがそのサブツリーとペアになるようにします。 これにより、ペアが常に異なるサブツリーから取得されることが強制されます。 
7. 重心のすべてのサブツリーを終了した後`c`、重心分解の各サブツリーに再帰します。 

### なぜ効果があるのか

 ノードの各ペアは、異なる子コンポーネントに存在する分解において一意の最高重心を持ちます。 その重心では、分解によって元のツリーの LCA が正確にその重心であることが保証され、ツリー パスの合計が定数とエンドポイントの独立した寄与を加えたものに分解されます。 マンハッタン変換は、幾何学的距離を線形形式の最大値に変換し、増分ベストプレフィックス追跡を使用したペアごとの最適化を可能にします。 2 つのノードが重心で分離されると、より深い再帰レベルで再び出会うことはないため、ペアは複数回カウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

# ---------- input ----------
n = int(input())
edges = [[] for _ in range(n)]

for _ in range(n - 1):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1
    edges[u].append((v, w))
    edges[v].append((u, w))

coords = []
for _ in range(n):
    x, y, z = map(int, input().split())
    coords.append((x, y, z))

# ---------- root distances ----------
base = [0] * n

def dfs(u, p):
    for v, w in edges[u]:
        if v == p:
            continue
        base[v] = base[u] + w
        dfs(v, u)

dfs(0, -1)

# ---------- centroid decomposition ----------
subsz = [0] * n
used = [False] * n

def get_size(u, p):
    subsz[u] = 1
    for v, _ in edges[u]:
        if v != p and not used[v]:
            get_size(v, u)
            subsz[u] += subsz[v]

def get_centroid(u, p, tot):
    for v, _ in edges[u]:
        if v != p and not used[v]:
            if subsz[v] > tot // 2:
                return get_centroid(v, u, tot)
    return u

def collect(u, p, arr):
    arr.append(u)
    for v, _ in edges[u]:
        if v != p and not used[v]:
            collect(v, u, arr)

ans = 0

def process(centroid):
    global ans

    best = {}

    def relax(u, sign):
        x, y, z = coords[u]
        sx, sy, sz = sign
        key = (sx, sy, sz)
        val = base[u] + sx * x + sy * y + sz * z
        if key not in best:
            best[key] = val
        else:
            best[key] = max(best[key], val)

    def query(u, sign):
        x, y, z = coords[u]
        sx, sy, sz = sign
        key = (-sx, -sy, -sz)
        if key in best:
            return best[key] + base[u] + sx * x + sy * y + sz * z
        return -10**30

    subtrees = []

    for v, _ in edges[centroid]:
        if used[v]:
            continue
        nodes = []
        collect(v, centroid, nodes)
        subtrees.append(nodes)

    for nodes in subtrees:
        for u in nodes:
            for sx in [1, -1]:
                for sy in [1, -1]:
                    for sz in [1, -1]:
                        ans = max(ans, query(u, (sx, sy, sz)))
        for u in nodes:
            for sx in [1, -1]:
                for sy in [1, -1]:
                    for sz in [1, -1]:
                        relax(u, (sx, sy, sz))

    used[centroid] = True
    for v, _ in edges[centroid]:
        if not used[v]:
            get_size(v, centroid)
            c = get_centroid(v, centroid, subsz[v])
            process(c)

def build():
    get_size(0, -1)
    c = get_centroid(0, -1, n)
    process(c)

build()

print(max(0, ans))
```この実装では、まずツリー パスがルート距離の差に変換されます。 重心分解により、2 つのノードが重心で処理されるときに、それらの最も低い共通の祖先が固定され、ツリーの寄与が比較に吸収される定数にまで減少します。 

8 つの符号ループはマンハッタン距離の線形化を実装します。 最適なペアはどの座標が差を支配するかによって決まるため、各ノードはすべての方向で評価されます。 

の`best`Dictionary には、方向ごとにこれまでに確認された最良の変換値が格納され、サブツリーの走査中に定数時間のペアリングが可能になります。 

## 実用的な例

 重心分解によって最初に中間ノードが選択される小さなツリーを考えてみましょう。 さまざまなサブツリーのノードがどのように相互作用するかを追跡します。 

| ステップ | 処理されたサブツリー | 最適な状態のサイズ | ベストアクション |
 | --- | --- | --- | --- |
 | 1 | 最初の子のサブツリー | 8キー | 初期化 |
 | 2 | 2 番目のサブツリー | 8 つのキーが更新されました | クロスペアを計算する |

 これは、ペアリングが重心の異なる子コンポーネント間でのみ発生し、同じサブツリー内では決​​して発生しないことを示しています。 

ここで、マンハッタンがすべてのエッジの重みを支配するケースを考えてみましょう。 アルゴリズムはまだ機能します。`base[u]`は値をシフトするだけですが、符号変換は幾何学的最大値がツリー構造とは独立して取得されることを保証します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各ノードは O(log n) セントロイド レベルに参加し、各レベルは 8 つの変換を処理します。 
| スペース | O(n) | 隣接リスト、セントロイドブックキーピング、および一時ストレージ |

 このソリューションは、すべてのノードが対数回処理され、ノードごとのすべての操作が 8 符号構成によって制限される定数因数であるため、制限内に問題なく収まります。

 ## 特殊なケース

 重要なエッジ ケースは、すべてのエッジの重みが負であるが、マンハッタン距離が大きい場合です。 その状況では、最適なペアは純粋に幾何学的であることが多く、セントロイド処理によりパス和の符号に依存せずにノードをペアリングできるため、アルゴリズムはそれを正しく捕捉します。 

もう 1 つのケースは、最適なペアが 1 つの深いサブツリー内に完全に存在する場合です。 セントロイド分解は最終的にそのサブツリーに再帰し、同じペアリング ロジックをローカルで繰り返すため、これは依然として処理されます。 

最後に、すべての合計スコアが正でない場合、最終`max(0, ans)`問題の制約に一致する、必要なゼロ出力を保証します。
