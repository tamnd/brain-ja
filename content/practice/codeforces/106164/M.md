 ## 解決策
 ## 問題の理解

 順列を間接的に構築する非常に特殊な構築プロセスをシミュレートしています。 カードの最終的な配置を与えられる代わりに、デッキがどのように構築されるかを段階的に説明され、望ましい最終構成を生み出す決定をリバースエンジニアリングするように求められます。 

プロセスは空の山から始まります。 1 から N までの各値について、その値を山の一番上に置きます。 配置した直後に、番号 xi を選択することができ、山の一番上の xi カードを取り、内部の順序を維持しながら一番下に移動します。 N ステップすべての後、パイルには 1 から N の順列が含まれます。私たちのタスクは、最終的なパイルが指定されたターゲット順列 P と一致するように、すべての xi を選択することです。ここで、P1 が一番上、PN が一番下です。 

この制約により、N は 200000 まで許可され、xi の選択に対する単純なバックトラッキングをシミュレートしたり、状態を検索しようとしたりする解は即座に除外されます。 どのソリューションでも、各インデックスを基本的に一定時間または対数時間で処理する必要があります。 これは、高速な循環回転をサポートする線形構造またはデータ構造を強く示唆しています。 

微妙な点は、この操作が単純なスタック プッシュではないことです。 各挿入の後に、プレフィックスが下位にローテーションされます。これは、早期の決定が非ローカルな方法でグローバルな順序に影響を与えることを意味します。 もう 1 つの重要なエッジ ケースは、最終的な順列が任意であるため、利用できる単調構造や並べ替えられたプロパティがないことです。 

単純な試みでは、各ステップで考えられるすべての xi の選択肢をシミュレートし、最終的な順列を一致させようとしますが、各ステップには i 個の選択肢があるため、この計算は指数関数的に爆発的に増加します。 推測されたシーケンスに対して順方向のシミュレーションを試みるのは問題ありませんが、課題はシーケンス自体を構築することです。 

## アプローチ

 ブルートフォースの観点では、考えられるすべての回転シーケンスを試して、最終的な順列をゼロから構築することを考えます。 カード i を配置した後、1 から i まで xi を選択し、結果として得られる山をシミュレートできます。 これにより、i とともに増加する分岐因子が得られ、可能なシーケンスの総数はすべての i の積 (階乗増加) になります。 1 つの候補シーケンスに対する 1 つのシミュレーションでも O(N) であるため、全体的なアプローチは非常に小さい N を超えると完全に実行不可能になります。 

重要な洞察は、構築プロセスを元に戻すことですが、操作を直接元に戻すという意味ではありません。 代わりに、最終構成をプロセスの最後から再構築できるものとして再解釈します。 重要な観察は、ステップ i で存在するカードのセットが正確に {1, 2, ..., i} であり、操作は接頭辞の末尾への巡回シフトのみを実行することです。 これは、制御された回転を除いて相対的な順序が維持されることを意味します。そして重要なことに、新しく挿入されたカード i は常に予測可能な方法で関与し、回転の直前に右上から始まります。 

これについて考える正しい方法は、現在の最終的な順列を維持し、N から 1 までの各ステップの効果を「抽出」することによって、プロセスを逆方向に再構築することです。ステップ i では、カード i が最初の i カードの中で最後に挿入されているはずであることがわかり、その後の操作ではプレフィックスが回転するだけなので、現在の構造内で i がどこに行き着くのかを特定し、どの程度の回転が発生したのかを推定することができます。 xi を決定したら、その回転を元に戻して前の状態に戻すことができます。 

これにより、問題はプレフィックスの回転下で動的なシーケンスを維持し、要素の位置を効率的に抽出することに変換されます。 トレプや暗黙的バランスバイナリツリーのようなバランスの取れた構造は、ある位置での分割と O(log N) でのセグメントの再接続をサポートしますが、これで十分です。

 ## アルゴリズムのチュートリアル

 すべての操作が適用された後、杭を表す現在のシーケンスを維持します。 N から 1 までの値を処理し、状態 i-1 から状態 i への遷移を作成したはずの操作を復元します。 

暗黙的なバランスの取れたバイナリ ツリー (トレプ) を使用します。このツリーでは、順序トラバーサルが上から下へのパイルを表します。 各ノードはサブツリーのサイズを保存するので、位置を見つけて効率的に分割できます。 

### ステップ

 1. ターゲットの順列 P から初期トリープを構築します。これは、すべての操作が適用された後のパイルの最終状態を表します。 
2. N から 1 までの i について、現在のトリープ内の値 i の位置を見つけます。 この位置は、ステップ i ですべての回転後にカード i がどこに到達したかを示します。 
3. 現在の treap 内の i の位置に 1 を加えた値として xi を計算します。 これは、ステップ i でカード i が上部 (位置 0) に挿入され、次にサイズ xi のプレフィックスが下部に移動され、i が最後に観察された位置に移動したという事実から来ています。 
4. 逆の操作を実行します。トレプをサイズ xi のプレフィックスとサフィックスに分割し、プレフィックスが一番下に移動するようにそれらを交換します。 これにより、ステップ i が適用される前の状態が復元されます。 
5. i が 1 に等しくなるまで続けます。この時点で、すべての演算が反転され、すべての xi が決定されます。 

重要な非明白な部分は、ステップ i での相対順序に影響を与える唯一の操作がプレフィックスの 1 回の巡回シフトであるため、現在の構造内の i の位置によって xi が一意に決定されることです。 つまり、i の変位は、その接頭辞がどれくらいの大きさであるかを正確にエンコードします。 

### なぜ効果があるのか

 逆プロセスの各段階で、treap は 1 から i までの操作を適用した後の山の正確な状態を表します。 カード i は存在することが保証されており、その位置を調べると、i の挿入直後に適用された単一のプレフィックス回転の累積効果が事実上観察されます。 後の操作では再構築中に i を超える新しい要素が導入されることはないため、{1, ..., i} 間の相対構造は保存され、xi で定義された回転を元に戻すと前の構成が正確に復元されます。 これにより、ステップ i の処理後、treap はステップ i-1 の後の状態を表すという厳密な不変条件が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import random

class Node:
    __slots__ = ("val", "prio", "left", "right", "size")
    def __init__(self, val):
        self.val = val
        self.prio = random.randint(1, 1 << 30)
        self.left = None
        self.right = None
        self.size = 1

def sz(t):
    return t.size if t else 0

def upd(t):
    if t:
        t.size = 1 + sz(t.left) + sz(t.right)

def split(t, k):
    if not t:
        return (None, None)
    if sz(t.left) >= k:
        l, r = split(t.left, k)
        t.left = r
        upd(t)
        return (l, t)
    else:
        l, r = split(t.right, k - sz(t.left) - 1)
        t.right = l
        upd(t)
        return (t, r)

def merge(a, b):
    if not a or not b:
        return a or b
    if a.prio > b.prio:
        a.right = merge(a.right, b)
        upd(a)
        return a
    else:
        b.left = merge(a, b.left)
        upd(b)
        return b

def inorder_build(arr):
    root = None
    for x in arr:
        root = merge(root, Node(x))
    return root

def find_pos(t, val, add=0):
    if not t:
        return -1
    if t.val == val:
        return add + sz(t.left)
    if t.left:
        res = find_pos(t.left, val, add)
        if res != -1:
            return res
    return find_pos(t.right, val, add + sz(t.left) + 1)

def move_prefix_to_bottom(t, k):
    a, b = split(t, k)
    return merge(b, a)

n = int(input())
p = list(map(int, input().split()))

root = None
for x in p:
    root = merge(root, Node(x))

ans = [0] * (n + 1)

for i in range(n, 0, -1):
    pos = find_pos(root, i)
    x = pos + 1
    ans[i] = x
    root = move_prefix_to_bottom(root, x)

print(*ans[1:])
```このコードは、最終的な順列からトリープを構築し、各値 i が現在どこにあるかを繰り返し識別します。 この位置は、ステップ i で回転する必要があるプレフィックスの長さを直接決定します。 xi を記録した後、ステップ i の影響を除去した状態と一致するように、同じ回転がトリープ構造に逆方向に適用されます。 

微妙な部分は、分割とマージでは、ランダムな優先順位によってバランスのとれた構造を維持しながら、順序を維持する必要があるということです。 サイズ フィールドは、対数時間で位置を計算するために不可欠です。 

## 実用的な例

 最後の山がどこにあるのかという小さな順列を考えてみましょう。`[4, 1, 3, 2]`。 

最初の treap を構築し、4 から下に向かって処理します。 

| 私 | i の位置 | xi | 適用された操作 |
 | --- | --- | --- | --- |
 | 4 | 0 | 1 | 最初に回転 1 |
 | 3 | 1 | 2 | 最初の 2 を回転します |
 | 2 | 3 | 4 | 最初の 4 を回転 |
 | 1 | 3 | 4 | 最初の 4 を回転 |

 再構築により、一貫した一連の操作が回復されるまで、構造が徐々にシフトされます。 

ここでソートされた順列を考えてみましょう`[1, 2, 3, 4, 5]`。 

| 私 | i の位置 | xi | 適用された操作 |
 | --- | --- | --- | --- |
 | 5 | 4 | 5 | フル回転 |
 | 4 | 3 | 4 | フル回転 |
 | 3 | 2 | 3 | フル回転 |
 | 2 | 1 | 2 | フル回転 |
 | 1 | 0 | 1 | つまらない |

 これは、同一性の順列でも、最大のプレフィックス回転の一貫したシーケンスに対応していることを示しています。 

各トレースは、現在の最大要素の位置によって必要なプレフィックス サイズが一意に決定されることを確認します。

 ## 特殊なケース

 重要なエッジ ケースは、ターゲットの順列がすでにほぼ順序付けられており、ほとんどの xi 値が小さいか均一になる場合です。 このような場合、アルゴリズムは各 i が予想される位置に近いことを繰り返し検出し、一貫した小さなプレフィックス回転を生成します。 Treap は、ランダム化されたバランシングによる劣化なしにこれを処理します。 

もう 1 つのケースは、順列が完全に逆になっている場合です。 ここでは、各 xi が最大になる傾向があり、完全な回転が繰り返されます。 分割およびマージ操作は値の分散には依存せず、位置のみに依存するため、構造は引き続き正しく動作します。 

最後の微妙なケースは N = 1 で、唯一の有効な出力は x1 = 1 です。些細ではありますが、これは、トレプに単一のノードがあり、位置クエリがすぐに 0 を返すという再構成ロジックの基本ケースを確認します。
