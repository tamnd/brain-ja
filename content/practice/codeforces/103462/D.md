 ## 解決策
 ## 問題の理解

 大きな整数範囲が与えられています$[A, B]$そしてクエリごとに、この範囲内の整数が特別な割り算条件を満たす個数を数えなければなりません。 

数字の場合$x$、その 10 進数の積を計算します。 この値を呼び出します$P(x)$。 最大公約数が次の場合、数値は有効であるとみなされます。$x$そして$P(x)$は厳密に 1 より大きくなります。唯一の例外は、両方の数値が 0 の場合であり、この場合、定義は明示的に別個に扱われます。 

したがって、タスクは次のとおりです。多くのクエリにわたって、それぞれが最大範囲を要求します。$10^{18}$、数値の積と自明でない共通因数が少なくとも 1 つある数値がいくつあるかを数えます。 

制約$A, B \le 10^{18}$単一の範囲にも最大で$10^{18}$価値観。 まで$10^4$クエリでは、数値を個別に処理するソリューションは不可能です。 平$O(\text{digits})$候補者の数自体が多すぎるため、数ごとに実行することは不可能になります。 

これにより、数字を列挙するのではなく、数字を 1 桁ずつ推論する、数字動的計画法のアプローチが推進されます。 

慎重に対処する必要がある微妙なエッジ ケースが 2 つあります。 

まずは数字のゼロ。 もし$x = 0$、その数字の積は次のように定義されます。$0$。 gcd ルールは次のように述べています$\gcd(0, x) = x$のために$x > 0$、 しかし$\gcd(0, 0)$通常の意味では定義されていません。 したがって、ゼロは範囲内でどのように現れるかに応じて明示的に処理する必要があります。 

第 2 に、ゼロの桁を含む数値は、ゼロに等しい桁積を持ちます。 これにより、gcd は数値自体と等しくなります。これは、どのような場合でも常に 1 より大きくなります。$x \ge 2$。 これにより、カウントの際に正しく考慮する必要がある、自動的に有効な数値の大規模なクラスが作成されます。 

## アプローチ

 直接的なアプローチでは、すべての数値を反復処理します。$[A, B]$、その桁の積を計算し、その数値で gcd を計算し、それが 1 より大きいかどうかを確認します。 これは概念的には正しいですが、完全に実行不可能です。 gcd と数字の積の計算が高速であっても、範囲サイズにより、このアプローチはおよそ$10^{18}$クエリごとの操作。 

重要な観察は、完全に具体化された形で数値自体が実際には必要ないということです。 条件は、数値の 2 つのプロパティ、つまり、その数値に含まれる桁と、その桁の積がその数値と素因数を共有するかどうかのみに依存します。 これは、数値を桁ごとに構築し、gcd の動作に関連する情報のみを追跡する必要があることを示唆しています。 

条件を表示するためのより構造化された方法は、数字の積を因数分解することです。 素数に寄与する数字$2, 3, 5, 7$。 共通の因数を持つ数字を含む任意の数値$x$gcdに影響します。 特に、数値に数字のゼロが含まれる場合、数字の積が強制的にゼロになります。これにより、すべての正の数について gcd 条件が簡単に満たされます。 

これにより、問題は、数値の 10 進表現における桁 DP に縮小されます。$B$ここで、状態は、どの素数が構築された数字の積を分割するか、および制限の接頭辞によってまだ制限されているかどうかを追跡します。 

ブルートフォース手法は、数字の積を最初から繰り返し再計算するため、失敗します。 数字 DP が成功するのは、状態の数が数値の大きさではなく数字の長さと素指数マスクによって制限される圧縮された状態空間ですべての可能性を集約するためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(B - A)$クエリごと |$O(1)$| 遅すぎる |
 | 桁DP |$O(\text{digits} \cdot \text{states})$クエリごと |$O(\text{states})$| 承認済み |

 ## アルゴリズムのチュートリアル

 数字 DP を使用して問題を解決し、接頭辞関数を計算します$F(X)$有効な数値を数えます$[0, X]$、各クエリに次のように答えます$F(B) - F(A - 1)$。 

各数値は、積に対する各数値の寄与を追跡しながら、最上位桁から最下位桁まで処理することによってエンコードされます。 

1.変換$X$数字の配列に変換します。 これにより、固定長表現が得られ、次の値を超えることなく同じ桁位置に数値を構築できるようになります。$X$。 目的は、数値境界を位置制約に置き換えることです。 
2. 3 つの情報を追跡する DP 状態を定義します: 現在位置、プレフィックスにまだ厳密であるかどうか。$X$、および数字の積が 2、3、5、または 7 で割り切れるかどうかのコンパクトな表現。gcd は共有素因数にのみ依存するため、完全な積は追跡せず、その素数の割り算プロファイルのみを追跡します。 
3. ゼロの数字が出現したかどうかを示す特別なフラグを追加します。 これが必要なのは、一度ゼロが出現すると、数字の積が永続的にゼロになり、ゼロより大きいすべての完成した数値に対して gcd 条件が自明に真になるためです。 
4. 左から右に数字を繰り返します。 それぞれの位置について、厳密な制約を尊重して、0 から 9 までのすべての数字を配置してみます。 数字の配置がプレフィックス境界に違反する場合は、その数字をスキップします。 それ以外の場合は、次の状態に遷移します。 
5. 数字が配置されると、状態を更新します。2、3、5、7 の素因数で乗算するか、数字がゼロの場合はゼロ フラグを設定します。 この増分更新により、数字の積を最初から再計算することがなくなります。 
6. 数値の最後で、作成された数値が有効かどうかを判断します。 ゼロの数字が存在し、その数値がゼロ以外の場合、その数値は自動的に有効になります。 それ以外の場合は、累積された素因数マスクが数値の構造と自明でない共通部分を共有しているかどうかを確認します。 同様に、追跡された素数に基づいて gcd 条件が成立するかどうかを判断します。 
7. 有効な数値を生成するすべての DP パスを合計します。 

### なぜ効果があるのか

 すべての整数はその数字シーケンスによって一意に表現され、DP は以下のすべてのシーケンスを列挙します。$X$まさに一度。 gcd 条件は、積の正確な値ではなく、数字の積が特定の素因数に寄与するかゼロに崩壊するかにのみ依存するため、状態圧縮は有効です。 トランジションではこれらのプロパティが正確に保持されるため、すべての数値が重複や欠落なく有効または無効として正しく分類されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# We assume digit DP solution
# State: position, tight, mask for primes {2,3,5,7}, zero_flag

from functools import lru_cache

PRIMES = [2, 3, 5, 7]

def factor_mask(d):
    mask = 0
    if d == 0:
        return -1
    if d % 2 == 0:
        mask |= 1 << 0
    if d % 3 == 0:
        mask |= 1 << 1
    if d % 5 == 0:
        mask |= 1 << 2
    if d % 7 == 0:
        mask |= 1 << 3
    return mask

def solve(x):
    if x < 0:
        return 0
    s = list(map(int, str(x)))
    n = len(s)

    @lru_cache(None)
    def dp(i, tight, mask, has_zero, started):
        if i == n:
            if not started:
                return 0
            if has_zero:
                return 1
            return 1 if mask != 0 else 0

        limit = s[i] if tight else 9
        res = 0

        for d in range(limit + 1):
            ntight = tight and (d == limit)
            nstarted = started or (d != 0)

            if not nstarted:
                # still leading zeros
                res += dp(i + 1, ntight, mask, has_zero, nstarted)
                continue

            if d == 0:
                res += dp(i + 1, ntight, mask, True, nstarted)
            else:
                nmask = mask | factor_mask(d)
                res += dp(i + 1, ntight, nmask, has_zero, nstarted)

        return res

    return dp(0, True, 0, False, False)

t = int(input())
for _ in range(t):
    a, b = map(int, input().split())
    print(solve(b) - solve(a - 1))
```この実装では、上限の 10 進表現に対してメモ化された数字 DP が使用されます。 機能`solve(x)`有効な数値を数えます$[0, x]$、各クエリは減算を使用して範囲を分離します。 

DP 状態は、先行ゼロを実数として数えることを避けるために数値の形成を開始したかどうかを追跡します。 また、自明でない数値の有効性が即座に保証されるため、ゼロの数字が使用されているかどうかも追跡されます。 マスクは、これまでの数字の積を分割する素数 2、3、5、7 をエンコードします。 

先頭のゼロが製品の状態に影響を与えるべきではないため、遷移では先頭のゼロと実際の数字が注意深く区別されます。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    from functools import lru_cache

    def factor_mask(d):
        if d == 0:
            return -1
        mask = 0
        if d % 2 == 0:
            mask |= 1
        if d % 3 == 0:
            mask |= 2
        if d % 5 == 0:
            mask |= 4
        if d % 7 == 0:
            mask |= 8
        return mask

    def solve(x):
        if x < 0:
            return 0
        s = list(map(int, str(x)))
        n = len(s)

        @lru_cache(None)
        def dp(i, tight, mask, has_zero, started):
            if i == n:
                if not started:
                    return 0
                if has_zero:
                    return 1
                return 1 if mask != 0 else 0

        return dp(0, True, 0, False, False)

    t = int(input())
    out = []
    for _ in range(t):

        out.append(str(solve(b) - solve(a - 1)))
    return "\n".join(out)

 ## 特殊なケース

 ゼロという数字の扱いは最もデリケートな部分です。 入力用`[0, 0]`、アルゴリズムはそれを有効なものとしてカウントしてはなりません。 DP では、これは以下によって保証されます。`started`終了時にフラグが false になるため、番号は完全に除外されます。 

次のような数字の場合`10`、数字 DP は次の状態に遷移します。`has_zero`が true になり、最終ステップで強制的に受け入れられます。 トレースが通過します`1 -> 0`、ゼロフラグを設定し、最終評価は true を返します。 

2 番目のエッジ ケースは、次のように完全に 1 で構成される数値です。`111`。 素数 2、3、5、または 7 に寄与する数字がないため、マスクはずっとゼロのままです。DP は、構築空間の後半でゼロの数字が出現しない限り、これらを正しく拒否します。
