 ## 解決策
 ## 問題の理解

 整数のペアによってインデックス付けされたフィボナッチ数の二重合計を非常に大きな限界まで評価するように求められます。 具体的には、注文されたペアごとに$(i, j)$と$1 \le i, j \le n$それらのインデックスのフィボナッチ数を取得し、その gcd を計算し、それらの gcd 値をすべて加算し、最終的に固定素数を法とした結果を取得します。$998244353$。 

したがって、この関数は基本的に、各フィボナッチ値がインデックスのすべてのペアにわたって gcd として現れる頻度を累積し、その gcd 構造を生成するペアの数によって重み付けされます。 

重要な問題は、フィボナッチ値自体ではなく、サイズの密な正方形上の gcd の構造です。$n \times n$、 どこ$n$と同じ大きさにすることができます$10^{10}$。 インデックスを反復しようとするソリューションは直ちに不可能です。$n^2$天文学的に大きくて均等です$n$それ自体を列挙することはできません。 

これにより、問題を算術構造、つまり gcd プロパティ、除数のグループ化、および数論関数上の接頭辞の合計に圧縮する必要があります。 

最初の微妙なエッジ ケースは、最小の入力から発生します。 いつ$n = 1$、一組しかありません$(1,1)$、答えは簡単です。$\gcd(F_1, F_1) = 1$。 数式ベースのソリューションでは、この基本ケースを維持する必要があります。特に、多くの変換では、小さな境界で動作が異なる接頭辞の合計や除数分解などの式が導入されるためです。 

2 番目に重要なエッジケースは次のような場合です。$n$は大きいですが、すべての寄与は非常に小さい gcd インデックスから来ています。 これにより、次のような除数範囲の処理における間違いが明らかになります。$n / d$特に、整数の除算で多くの値がまとめられる場合に顕著です。 

## アプローチ

 ブルートフォースの解釈は簡単です。すべてのペアを反復処理します。$(i,j)$、フィボナッチ数を計算し、gcd を取得し、累積します。 フィボナッチ値が事前計算されていても、ボトルネックは二重ループです。$n^2$ペア。 と$n$まで$10^{10}$、これは遠隔的には実現可能ではありません。 

最初の構造の単純化は、古典的なフィボナッチ恒等式から来ています。$$\gcd(F_i, F_j) = F_{\gcd(i,j)}.$$これにより、問題はフィボナッチ値での作業からインデックスの gcd での直接作業へと分解されます。 関数は次のようになります。$$\sum_{i=1}^{n} \sum_{j=1}^{n} F_{\gcd(i,j)}.$$この問題は、次の整数ペアの gcd 構造のみに依存します。$n \times n$グリッド。 

次の標準的な変換は、gcd 値によってペアをグループ化することです。 直したら$d = \gcd(i,j)$、そして、次のように書くことができます$i = d a$、$j = d b$、 どこ$\gcd(a,b) = 1$、そして両方$a,b \le n/d$。 これにより、問題は次のように縮小されます。$$\sum_{d=1}^{n} F_d \cdot \#\{(a,b) \le n/d : \gcd(a,b)=1\}.$$したがって、全体の難易度は 2 つの要素にシフトします。1 つは正方形内の互いに素のペアを数える作業、もう 1 つは範囲内のフィボナッチ値を合計する作業です。 

共素対のカウントアップは$m$は既知の閉じた構造を持っています。$$C(m) = \sum_{a=1}^{m}\sum_{b=1}^{m} [\gcd(a,b)=1] = 2\sum_{k=1}^{m}\varphi(k) - 1.$$したがって、答えは次のようになります。$$\sum_{d=1}^{n} F_d \cdot \bigl(2\sum_{k \le n/d}\varphi(k) - 1\bigr).$$この時点で、直接反復処理を行います。$d$まだ無理だから$n$巨大です。 ただし、式は次の条件にのみ依存します。$n/d$でのみ変化します。$O(\sqrt n)$明確な価値観。 これによりグループ化が可能になります$d$セグメントに分割される$\lfloor n/d \rfloor$は一定です。 

各セグメント内では、範囲にわたるフィボナッチ値の合計が必要です。これは次のように計算できます。$O(\log n)$プレフィックスサム拡張による高速倍増を使用します。 残りの不足している部分は、任意の大きな値までのオイラーの合計関数の接頭辞の合計を高速に評価することです。$m$、これは大まかにメモ化された除数分割方法を使用して処理できます。$O(n^{2/3})$時間。 

ブルート フォースは次の理由で失敗します。$n^2$一方、最適化されたソリューションは両方の次元を折りたたむことで機能します。gcd 構造はグリッドを約数に削減し、算術恒等式はフィボナッチ集計と全集合の両方をプレフィックス計算に削減します。

 ## アルゴリズムのチュートリアル

 1. 恒等式を使用してフィボナッチ値の gcd を置き換えます。$\gcd(F_i, F_j) = F_{\gcd(i,j)}$。 これにより、インデックスの gcd に関して問題が完全に書き直され、gcd 演算の内部からフィボナッチ算術が削除されます。 
2. gcd 値に従ってペアをグループ化することにより、二重和を再定式化します。$d$、グリッドを、gcd が正確に一致するすべてのペアからの寄与に変換します。$d$。 これにより、フィボナッチ値が gcd クラスに付加された重みとして分離されます。 
3. 各ペアを表現する$(i,j)$として$(d a, d b)$そして制約を次のように減らします$\gcd(a,b)=1$と$a,b \le n/d$。 これにより、スケーリングが次のように分離されます。$d$共原理構造から。 
4. 共素対の数を ID に置き換えます。$C(m)=2\sum_{k\le m}\varphi(k)-1$。 これは、2 次元の条件を、オイラーの十を使った 1 次元の接頭関数に変換します。 
5. 関数がのみに依存していることを確認します。$m=n/d$、非常に多くの連続した値$d$同じ貢献の重みを共有します。 範囲を分割する$d$ブロックに分割$\lfloor n/d \rfloor$は一定です。 
6. ブロックごとに、フィボナッチ値の合計を計算します。$F_l + \dots + F_r$両方を返す高速倍増ルーチンを使用する$F_n$対数時間でのプレフィックスの合計。 
7. それぞれの個別の値について$m = n/d$、計算する$C(m)$プレフィックス合計に対してメモ化された除数和法を使用します。 
8. ブロック貢献度を次のように蓄積します。$\text{sumFib}(l,r) \cdot C(m)$、モジュロ演算を全体に適用します。 

正確さは、すべてのペアが次のような不変条件に依存します。$(i,j)$1 つの gcd クラス内で 1 回だけカウントされます$d$、各クラスは、に応じてプロパティによってのみ重み付けされます。$n/d$、これは各セグメント内で一定です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

# Fast doubling for Fibonacci with prefix sum
# returns (F_n, F_{n+1}, S_n) where S_n = sum_{i=1..n} F_i

def fib_sum(n):
    if n == 0:
        return (0, 1, 0)
    a, b, sa = fib_sum(n >> 1)
    c = (a * ((2 * b - a) % MOD)) % MOD
    d = (a * a + b * b) % MOD

    sc = (sa + (c * b) % MOD) % MOD

    if n & 1:
        F_n = d
        F_np1 = (c + d) % MOD
        S_n = (sc + d) % MOD
        return (F_n, F_np1, S_n)
    else:
        return (c, d, sc)

# prefix phi sum via memoized recursion
phi_memo = {}

def sum_phi(n):
    if n in phi_memo:
        return phi_memo[n]
    res = n * (n + 1) // 2
    i = 2
    while i <= n:
        v = n // i
        j = n // v
        res -= (j - i + 1) * sum_phi(v)
        i = j + 1
    phi_memo[n] = res
    return res

def coprime_count(n):
    if n <= 0:
        return 0
    return (2 * sum_phi(n) - 1) % MOD

def fib_range_sum(l, r):
    return (fib_sum(r)[2] - fib_sum(l - 1)[2]) % MOD

def solve():
    n = int(input().strip())

    ans = 0
    l = 1
    while l <= n:
        v = n // l
        r = n // v

        c = coprime_count(v)
        s = fib_range_sum(l, r)

        ans = (ans + s * c) % MOD
        l = r + 1

    print(ans)

if __name__ == "__main__":
    solve()
```フィボナッチ処理は、値とプレフィックスの合計を同時に計算する高速 2 倍ルーチンにカプセル化されているため、範囲を合計する際の再計算が回避されます。 重要な点は、各再帰的分割がフィボナッチ状態と累積されたプレフィックス寄与の両方を伝播する必要があることです。 

トーティエント プレフィックス関数は、次の値まで線形に反復する代わりに、標準の調和分解を使用します。$n$、間隔をまたいでジャンプします。$n / i$は定数であり、グループ化された寄与分を再帰的に減算します。 

最後に、メイン ループは等しいセグメントを反復します。$\lfloor n/d \rfloor$、各 gcd クラスが一貫した重み付けで 1 回だけ貢献するようにします。 

## 実用的な例

 小さな実例を考えてみましょう$n = 5$。 次の値によってグループ化します。$v = \lfloor 5/d \rfloor$。 

| セグメント d 範囲 | v = n/d | 繊維範囲 | フィブサム | 共素数 C(v) |
 | --- | --- | --- | --- | --- |
 | [1,1] | 5 | F1 | 1 | C(5) |
 | [2,2] | 2 | F2 | 1 | C(2) |
 | [3,5] | 1 | F3+F4+F5 | 2+3+5=10 | C(1)=1 |

 最終的な答えは、これらの寄与度の加重合計です。 これは、gcd クラスがどのように divisor ブロックに折りたたまれるのか、そしてなぜセグメント化が不可欠なのかを示しています。 

ここで考えてみましょう$n = 1$。 ブロックは1つだけですが、$d=1$、 と$v=1$。 計算は次のようになります。$F_1 \cdot C(1) = 1 \cdot 1 = 1$、直接の定義と一致します。
