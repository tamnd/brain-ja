 ## 解決策
 ## 問題の理解

 私たちは原点から始まる無限のグリッドの上に立っています。 各テストではターゲット座標が与えられ、最終的にその点に到達する歩行を構築する必要があります。 

移動ルールは特殊です。時間が複数のフェーズに分割されます。 最初のフェーズでは正確に 1 単位ステップ、第 2 フェーズでは正確に 2 ステップ、第 3 フェーズでは正確に 3 ステップというように実行する必要があります。 単位ステップは、1 つのセルを 4 つの基本方向のいずれかに移動します。 フェーズ i の終了後、自分の位置を記録します。最終的な答えは、各フェーズ後の位置のシーケンスです。 t フェーズ後の実際のユニットの移動回数の合計は、三角数 t(t+1)/2 になります。 

したがって、タスクは、(x, y) に到達できるかどうかを判断するだけでなく、フェーズ数 t を選択し、すべての移動が完了した後に正確に (x, y) に到達できるように、全長 t(t+1)/2 の一連の単位移動を構築することです。 各フェーズ後のエンドポイントのみが出力されます。 

制約 |x|、|y| ≤ 10^9 は、位置に対する境界検索や動的プログラミングに依存できないことを意味します。 どのような解も、構築されるパスの長さは線形である必要があり、その長さ自体は注意深く制御する必要があります。 t は原則として最大でも約 10^5 ですが、通常ははるかに小さいため、O(t^2) または状態空間の探索は不可能です。 

単純な間違いは、マンハッタンの最短経路をたどれば十分だと考えることです。 たとえば、(0, 0) から (1, 0) まで、t = 1 を試みる可能性がありますが、フェーズ 1 では 1 ステップしか許可されないため、機能します。 ただし、(2, 0) の場合、t = 2 は合計 3 ステップとなり、パリティが 1 ステップオーバーシュートするため、パリティを注意深く制御しない限り、直接最短経路の思考は失敗します。 

もう 1 つのよくある失敗は、t(t+1)/2 ≥ |x| となるように t を選択することです。 + |y| パリティをチェックせずに。 たとえば、奇数の移動を必要とするポイントに到達する必要があるが、許可される合計ステップが偶数である場合、各移動がグリッド パリティを反転するため、一連の移動がターゲットに正確に着地することはできません。 

## アプローチ

 ブルートフォース ビューでは、t を増加させ、各 t について、(x, y) に到達する正確に t(t+1)/2 ステップのパスを構築しようとします。 これには、指数関数的に多くのパスを検索するか、少なくとも長さ t(t+1)/2 の巨大な分岐プロセスをシミュレートする必要がありますが、t が小さな値を超えて大きくなると実行不可能になります。 

重要な観察は、パスを検索する必要がまったくないということです。 重要なのは、総ステップ数と最終的な変位だけです。 グリッド上では、「どこかに行ってすぐに戻る」形式の迂回は、終点を変更せずにちょうど 2 つのステップを追加します。 これにより、パリティが尊重される限り、パス長の調整を完全に制御できます。 

したがって、問題は、ステップの総数 T = t(t+1)/2 が少なくともマンハッタン距離 D = |x| となるような適切な t を選択することになります。 + |y|、T と D は同じパリティを持ちます。 このような t が選択されたら、最初に (x, y) までの最短ルートを歩き、次に前後の移動として T − D 個の追加のステップを挿入することによってパスを構築します。 

完全なユニットステップ パスを構築した後、それをシミュレートし、長さが 1、3、6、10、… に等しい各プレフィックスの後の位置、つまり各フェーズ境界の後の位置を記録します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パス上のブルート フォース | 指数 | 指数 | 遅すぎる |
 | パリティ正しいウォークを構築する | O(T) | O(T) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. マンハッタン距離 D = |x| を計算します。 + |y|、これは制約なしで必要なユニット移動の最小数です。 
2. t(t+1)/2 ≥ D かつ (t(t+1)/2 − D) が偶数となる最小の t を見つけます。 

最初の条件は十分なステップがあることを保証し、2 番目の条件はエンドポイントに影響を与えることなく 2 ステップ キャンセルを使用してパスを調整できることを保証します。 
3. (0, 0) から (x, y) への最短パスを構築します。 

x > 0 の場合は右に x 回移動し、それ以外の場合は左に -x 回移動します。

次に、y > 0 の場合は y 回上に移動し、それ以外の場合は -y 回下に移動します。 

これにより、正確に D ステップのパスが生成されます。 
4. 残りのスラック S = t(t+1)/2 − D を計算します。これは構造上均等です。 
5. 「右、左」などの 2 ステップ サイクルの S/2 コピーを追加します。 

各サイクルは 2 ステップを消費しながら現在位置を保持するため、延長後の経路長は正確に t(t+1)/2 になります。 
6. ユニットが移動するたびに現在の位置を追跡しながら、完全な移動を段階的にシミュレートします。 
7. 各フェーズ i の終了後、つまり 1 から t までの i の累積ステップ数 i(i+1)/2 後の位置を記録します。 

### なぜ効果があるのか

 この構造では、追加されたすべての迂回が正味変位に寄与しないことが保証されるため、最終的な位置は (x, y) への最初の最短経路のみに依存します。 パリティ条件により、残りのすべての追加ステップをキャンセル サイクルに組み込むことができます。 すべての位相境界は固定プレフィックス長に対応しており、正確なウォークをシミュレートするため、記録された各位置は必要な位相構造と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_path(x, y):
    path = []
    if x > 0:
        path += ['R'] * x
    else:
        path += ['L'] * (-x)
    if y > 0:
        path += ['U'] * y
    else:
        path += ['D'] * (-y)
    return path

def solve_case(x, y):
    D = abs(x) + abs(y)

    # find t
    t = 0
    total = 0
    while total < D or (total - D) % 2 != 0:
        t += 1
        total += t

    path = build_path(x, y)
    slack = total - len(path)

    # add canceling pairs
    for _ in range(slack // 2):
        path.append('R')
        path.append('L')

    # simulate
    cx = cy = 0
    pos = []
    idx = 0
    checkpoints = set()
    s = 0
    for i in range(1, t + 1):
        s += i
        checkpoints.add(s)

    res = []
    for i, mv in enumerate(path, 1):
        if mv == 'R':
            cx += 1
        elif mv == 'L':
            cx -= 1
        elif mv == 'U':
            cy += 1
        else:
            cy -= 1

        if i in checkpoints:
            res.append((cx, cy))

    return t, res

def main():
    T = int(input())
    for tc in range(1, T + 1):
        x, y = map(int, input().split())
        t, res = solve_case(x, y)

        print(f"Case #{tc}:")
        print(t)
        for x0, y0 in res:
            print(x0, y0)

if __name__ == "__main__":
    main()
```この実装では、最初に、到達可能性とパリティ条件の両方が満たされるまで三角形の成長を増分合計することによって、実現可能な最小のフェーズ数が選択されます。 パスの構築では、決定論的なマンハッタン ルートとそれに続く中立的な 2 ステップ ループが使用され、検索なしで正確さが保証されます。 

出力は生の動きではなくフェーズのエンドポイントに関して定義されるため、シミュレーション ステップは不可欠です。 中間位置の直接解析式は、構築されたシーケンスに対するシングル パス シミュレーションよりも維持するのが困難です。

 ## 特殊なケース

 単一軸上のターゲットの場合、マンハッタン パスはすでに直線になっており、構築は中立 RL ループの挿入に減ります。 たとえば、(0, 5) はキャンセルが続く真っ直ぐな上向きのパスを生成し、フェーズ チェックポイントは単に中間の垂直位置をサンプリングするだけです。 

(-3, 2) などの負の座標の場合、すべての変位が L および D の移動の符号付きカウントとしてエンコードされるため、方向構築は正しく反転します。 パリティとスラックのメカニズムは方向には依存せず、全長のみに依存します。 

原点 (0, 0) の場合、アルゴリズムは三角数が偶数である有効な t を選択し、パスは純粋にループをキャンセルします。 すべてのフェーズのエンドポイントは (0, 0) のままで、必要な宛先に一致します。
