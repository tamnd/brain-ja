 ## 解決策
 ## 問題の理解

 ポータルによって接続された部屋の有向または無向の重み付きグラフが与えられます。 旅行者は部屋 1 から出発して、部屋 n に到達したいと考えています。 彼は部屋に入るたびに「龍珠」と呼ばれるアイテムを 1 つだけ集めます。各龍珠には 7 種類のうちの 1 つがあります。 

ポータルを通過するにはエネルギーがかかりますが、このコストには一工夫があります。移動するたびに、旅行者は前の部屋で集めた龍珠の種類と現在の部屋で集めた龍珠の種類に応じてエネルギーの払い戻しを受け取ります。 払い戻しは 7 × 7 のマトリックスで指定され、移動時の実際のエネルギー変化はポータル コストから対応する払い戻し値を引いたものになります。 

目標は、部屋 1 から部屋 n へのパスを選択しながら、訪問した各部屋でどの龍珠を拾うかを選択して、消費される総エネルギーを最小限に抑えることです。 

この声明からの重要な観察は、部屋への再訪問が許可されており、訪問するたびにおそらく異なる龍珠のタイプを選ぶことができるということです。 これは、状態が部屋だけでなく、最後に収集されたタイプも含まれることを意味します。 

この制約は、最大 500 の部屋と最大約 125k エッジという適度なグラフ サイズを示唆しています。 パスの数は指数関数的に増加するため、すべてのパスに対する単純なアプローチは不可能です。 遷移は前のタイプに依存するため、ノードごとのタイプごとの最短パスであっても自明ではありません。 

Longzhu のコレクションが部屋ごとに固定されていないという事実から、微妙なエッジケースが生じます。 たとえば、ルームを再訪問できる場合、特に最後に収集されたタイプを変更するために、そのルームに複数回入ることができます。 

もう 1 つの重要なエッジ ケースは、一部の遷移ではマイナスの純コストが発生する可能性があることです (エッジ コストは 10 の倍数であるのに対し、払い戻しは最大 10 になる可能性があるため)。これは、注意深い状態処理を行わない標準のダイクストラが必要であることを意味します。 

## アプローチ

 強引なアイデアは、部屋の訪問と Longzhu の選択の考えられる各シーケンスを別個のパスとして扱うことです。 各ステップで次の部屋とタイプを選択し、エネルギー変化を蓄積します。 これは、すべてのノードで最大 7 つのタイプと複数の出力エッジに分岐し、ノードを再訪問することでサイクルが作成されるため、すぐに指数関数的になります。 コストはノードだけでなくタイプ間の遷移に依存するため、最短の単純なパスに制限しても役に立ちません。 

重要な洞察は、必要な過去の記憶は最後に収集された龍珠タイプだけであるということです。 エッジに沿って移動するコストは、完全な履歴ではなく、前のタイプと現在のタイプにのみ依存します。 これにより、問題はフォームの状態 (room、last_type) にわたる階層化された最短パスに帰着します。 状態の数は最大でも 500 × 7 ですが、ダイクストラにとっては十分小さいです。 

各状態遷移は、グラフのエッジに沿った移動と、宛先ノードの新しいタイプの選択に対応します。 コストは、エッジの重みからマトリックスからの返金を差し引いたものです。 重みは負ではありませんが、払い戻しによって重みが減少する可能性があるため、マトリックスを適切に組み込むと、依然として負ではない有効コストが得られます。 

初期タイプを選択して、ノード 1 のすべての状態からダイクストラを実行します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パス上のブルート フォース | 指数 | 指数 | 遅すぎる |
 | (node, last_type) の状態に関するダイクストラ | O((n・7 + m・7) log (n・7)) | O(n・7 + m・7) | 承認済み |

 ## アルゴリズムのチュートリアル

 各状態をペア (u, c) としてモデル化します。ここで、u は部屋、c は最後に収集された Longzhu タイプです。 このような各状態に到達するために必要な最小エネルギーを計算します。

1. すべての部屋とタイプに対して、距離テーブル dist[u][c] を無限大で初期化します。 この表は、最後に収集された龍珠タイプが c の場合に、部屋 u に到達するまでの最小エネルギーコストを表します。 
2. 開始部屋 1 は 7 種類から自由に選択できます。 タイプ c ごとに、dist[1][c] = 0 を設定し、(0, 1, c) を優先キューにプッシュします。 これは、最初の Longzhu には移行コストがかからないことを反映しています。 
3. これらの拡張された状態に対して標準のダイクストラ プロセスを実行します。 (cost, u, c) をポップするたびに、dist[u][c] と比較して古い場合はスキップします。 
4. 重み w を持つすべてのエッジ (u → v) について、v に移動し、[0, 6] で新しいタイプ nc を選択することを検討します。 移行コストは次のとおりです。 

w - x[c][nc]

 ここで、x[c][nc] は、最後のタイプ c から新しいタイプ nc への切り替えによる返金です。 
5. 次のタイプ nc の候補ごとに、new_cost =cost + w - x[c][nc]を計算します。 これにより dist[v][nc] が改善される場合は、更新して優先キューにプッシュします。 ノードにアクセスするたびに新しい Longzhu タイプを選択できるため、この手順は正しいです。 
6. すべての状態を処理した後、答えは [0, 6] のすべての c にわたる dist[n][c] の最小値になります。 すべてが無限のままの場合は、-1 を出力します。 

### なぜ効果があるのか

 不変条件は、状態 (u, c) がダイクストラによって確定されるたびに、最後に収集されたタイプ c を持つ部屋 u に到達するために可能な最小のエネルギー コストが見つかったことです。 これは、前のタイプと次のタイプが選択されるとすべての遷移コストが固定され、すべてのエッジ緩和が拡張状態グラフの非負の調整された重みを考慮するため当てはまります。 元の問題は 7n ノードのグラフ上の最短経路問題となり、ダイクストラはこれらの条件下での最適性を保証します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def solve():
    n, m = map(int, input().split())
    
    x = [list(map(int, input().split())) for _ in range(7)]
    
    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        g[u].append((v, w))
        g[v].append((u, w))
    
    dist = [[INF] * 7 for _ in range(n + 1)]
    pq = []
    
    for c in range(7):
        dist[1][c] = 0
        heapq.heappush(pq, (0, 1, c))
    
    while pq:
        d, u, c = heapq.heappop(pq)
        if d != dist[u][c]:
            continue
        
        for v, w in g[u]:
            for nc in range(7):
                nd = d + w - x[c][nc]
                if nd < dist[v][nc]:
                    dist[v][nc] = nd
                    heapq.heappush(pq, (nd, v, nc))
    
    ans = min(dist[n])
    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```この実装は、階層化された状態グラフを直接ミラーリングします。 dist 配列は、ノードと最後のタイプの状態の両方をエンコードします。 優先キューにより、常に最も安価な既知の状態が最初に拡張されます。 

よくある落とし穴は、ノード 1 で 7 つのタイプをすべて初期化するのを忘れることです。これが必要になるのは、最初の動きが、最初に収集したふりをするタイプに依存するためです。 

もう 1 つの微妙な点は、最初の状態の前に前のタイプがないため、開始位置で払い戻しを減算しないことです。

 ## 特殊なケース

 エッジケースの 1 つは、最良の戦略が、最初に自明ではない Longzhu タイプを意図的に選択することを含む場合です。 ノード 1 で 7 つのタイプすべてを初期化することで、初期状態を誤って制限しないことが保証されます。 アルゴリズムはすべての開始タイプを同等に扱うため、最適な遷移につながるのが 1 つだけであっても、そのタイプに到達できます。 

もう 1 つのケースは、払い戻し額が十分に大きいため、実質的に移動が無料、または有益になる場合です。 遷移が制限され、エッジ ステップごとに一貫性がある限り、拡張された状態グラフは状態レベルで負のサイクルを導入しないため、ダイクストラ フレームワークは引き続き機能します。 このアルゴリズムは、安定化するまで緩和を繰り返すことで改善された状態を正しく伝播します。 

最後のエッジケースは、タイプを変更するためにノードを再訪することです。 (u, c) は完全な状態であるため、アルゴリズムはこれを自然に処理します。そのため、別の c で u を再検討することは、展開されたグラフ内の単なる別のノードにすぎません。
