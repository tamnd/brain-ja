 ## 問題の理解

 長さの配列を構築しています$n$チャンクで成長させるプロセスを使用します。 最初は配列は空です。 いつでも、現在の長さが$m$、数字を選択します$x$間$1$そして$n-m$。 選択した後$x$、シーケンスを追加します$1, 2, 3, \dots, x$配列に。 配列の長さが正確になるまでこれを繰り返します$n$。 

重要な点は、すべての決定は単に数値を加算するのではなく、1 から始まり選択した値まで増加するブロック全体を加算することです。$x$。 異なる選択順序により、異なる最終配列が生成される可能性があります。タスクは、特定の場合に可能な個別の最終配列の数を数えることです。$n$、モジュロ$10^9+7$。 

制約$n \le 10^6$そして最大まで$10^3$テスト ケースでは、すべての構造をシミュレートしようとするアプローチや、テスト ケースごとに指数関数的な再帰を実行しようとするアプローチは直ちに除外されます。 平$O(n^2)$最悪の場合、テストケースごとに時間がかかりすぎる可能性があります。 解決策は、問題を閉じた形式、または最悪の場合でも単純な線形事前計算に縮小する必要があります。 

微妙なエッジケースが現れるのは、$n = 1$。 このプロセスでは単一の選択を迫られます$x = 1$、配列のみを生成します$[1]$。 正しい式であれば、ここでは当然 1 が生成されます。 素朴な誤解は、選択されたブロックの合計が同じであっても、異なるシーケンスが異なる配列を生成する可能性があると考えることです。しかし、ここでは、すべてのブロックは一度完全に決定的になります。$x$が選択されているため、次のシーケンスのみが選択されます。$x$-価値観が重要です。 

## アプローチ

 この構造は、長さを正確に埋めるまで、追加する要素の数を繰り返し選択するものとみなすことができます。$n$。 選択した値を次のように記録するとします。$x_1, x_2, \dots, x_k$。 それぞれ$x_i$まさに貢献する$x_i$要素を最終配列に追加するため、$$x_1 + x_2 + \cdots + x_k = n.$$このシーケンスが固定されると、各ブロックは常に固定パターンであるため、最終的な配列が完全に決定されます。$1,2,\dots,x_i$。 ブロック内には追加の自由はありません。 

したがって、問題は、正の整数の順序付けされたシーケンスの合計がいくつあるかを数えるということになります。$n$。 これはまさに の作曲数です$n$。 

これを確認する強引な方法は動的プログラミングです。$dp[i]$合計に達する方法を数えます$i$。 州から$i$、可能なすべての次のブロック サイズを試します$x \ge 1$に移行中$i+x$。 これは正しいですが、明確なコストがかかります。$i$まで繰り返すことができます$n-i$、与える$O(n^2)$最悪の場合のテスト ケースごとに、遅すぎる$n = 10^6$。 

構造的な洞察は、$n$間に区切り文字を置くのと同じです$n$原子単位。 一連の長さの要素の隣接する各ペアの間$n$、切るか切らないかのどちらかです。 がある$n-1$ギャップがあり、各ギャップは新しいブロックが始まるかどうかを独立して決定します。 これは正確に生成します$2^{n-1}$可能性。 

これにより、問題全体が累乗剰余に帰着します。

 ## アルゴリズムのチュートリアル

 1. すべての構造が、選択したブロック サイズのシーケンスに対応していることを観察します。$x_1, x_2, \dots, x_k$。 これは、各操作が正確に追加するためです。$x_i$要素なので、プロセスはこれらの値によって完全に記述されます。 
2. 構築上の制約を方程式に変換します。$x_1 + x_2 + \cdots + x_k = n$、どこでも$x_i \ge 1$。 これにより、配列構造が完全に削除され、問題は有効な正の整数のシーケンスをカウントするようになります。 
3. 各ソリューションを行の分割として解釈します。$n$位置を連続したセグメントに分割します。 各セグメントは選択された 1 つのブロックに対応し、内部的に次のように固定されます。$1,2,\dots,x_i$。 内部値はカウントに影響しません。 
4. パーティション ビューを二分決定問題に変換します: 隣接する位置のすべてのペアの間$i$そして$i+1$、カットする (新しいブロックを開始する) かカットしない (現在のブロックを継続する) かを決定します。 がある$n-1$そういった決断。 
5. 考えられるすべてのカットパターンを数えます。 それぞれの$n-1$ギャップには 2 つの独立した選択肢があるため、構築の総数は次のようになります。$2^{n-1}$。 
6. 最大 2 の累乗を事前計算します。$10^6$モジュロ$10^9+7$、その後、事前計算された値を返すことによって、一定時間内に各クエリに応答します。 

### なぜ効果があるのか

 正しさは、有効な構築シーケンスとそのサブセット間の全単射に基づいています。$n-1$ポジション間の境界線。 ブロック サイズの有効なシーケンスはすべて、配列を連続して増加するセグメントにカットする 1 つの方法を定義しており、カットのすべての選択によって有効なブロック サイズのシーケンスが独自に決定されます。 両方の方向が決定的で損失がないため、カウントはサイズのセットのサブセットをカウントすることになります。$n-1$、つまり$2^{n-1}$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
MAXN = 10**6

# precompute powers of 2
pow2 = [1] * (MAXN + 1)
for i in range(1, MAXN + 1):
    pow2[i] = (pow2[i - 1] * 2) % MOD

t = int(input())
out = []

for _ in range(t):
    n = int(input())
    out.append(str(pow2[n - 1]))

print("\n".join(out))
```このソリューションでは、2 の累乗をすべて 1 回だけ事前計算するため、最大で累乗を繰り返す必要がなくなります。$10^3$テストケース。 再発$pow2[i] = 2 \cdot pow2[i-1]$潜在的なカット位置をもう 1 つ追加することによる倍増の性質を直接エンコードします。 

各クエリは単純にマッピングします$n$に$2^{n-1}$基本ケースの処理に注意してください$n=1$、正しく生成されます$2^0 = 1$。

## テストケース```python
import sys, io

MOD = 10**9 + 7
MAXN = 10**6

pow2 = [1] * (MAXN + 1)
for i in range(1, MAXN + 1):
    pow2[i] = (pow2[i - 1] * 2) % MOD

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str(pow2[n - 1]))
    return "\n".join(out)

# minimum size

# small case

# multiple tests
assert solve("3\n1\n2\n5\n") == "1\n2\n16", "mixed cases"

# large boundary check (just structure)
assert solve("1\n10\n") == str(pow2[9]), "n=10 check"

 ## 特殊なケース

 のために$n = 1$、アルゴリズムは戻ります$2^{0} = 1$。 これは可能な唯一の構造と一致します: 選択してください$x=1$、配列を生成します$[1]$。 内部ギャップを決定する必要がないため、境界定式化は引き続き成立し、カット パターンの数は 1 つになります。 

非常に大きい場合$n$、 のような$n = 10^6$ただし、アルゴリズムは事前に計算されたべき乗剰余演算のみに依存しているため、引き続き一貫して動作します。 値$2^{n-1} \bmod (10^9+7)$は明確に定義されており、オーバーフローや再帰の深さを考慮することなく事前に計算されます。
