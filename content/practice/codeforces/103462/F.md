 ## 解決策
 ## 問題の理解

 いくつかの位置がすでに固定されているバイナリ文字列が与えられます。`0`または`1`、その他は不明でマークされています`?`。 それぞれ交換させていただきます`?`どちらかで`0`または`1`、完全なバイナリ文字列を生成します。 

完成した文字列については、「遷移」を位置として定義します。`i`の位置にある文字が`i`位置の文字と異なります`i+1`。 タスクは、遷移の合計数が正確に等しくなるように、すべての未知数を埋めることです。`k`。 すべての有効な補完の中で、辞書編集的に最小の結果のバイナリ文字列を出力する必要があります。 

ここでの辞書編集的な順序は通常どおりに動作します。つまり、前の位置が後の位置よりも優先されるため、実現可能性を損なわない限り、最初の文字を小さくすることが常に優先されます。 これにより、トランジションの正確な数をグローバルに満たすことと、左からの文字列をローカルに最小化するという 2 つの目標の間に緊張が生じます。 

制約は大きく、すべてのテスト ケースの合計長は 10^6 に達します。 これにより、すべての割り当てを試行するソリューションは即座に除外されます。`?`なぜなら、長さ 100,000 の単一の文字列でも 2^m 通りの可能性があるからです (m は未知数の数です)。 すべてのプレフィックスと残りの遷移に対する動的プログラミングであっても、テスト ケースごとに線形またはほぼ線形である必要があります。 

それぞれの項目で常に可能な限り最小の文字を選択する、素朴で貪欲なアプローチ`?`初期の選択は、後で利用可能な遷移の数に影響するため、単独では失敗します。 

典型的な失敗は、初期の貪欲さがトランジションを誤って消費または保持した場合に発生します。 たとえば、トランジションが 1 つだけ必要で、次のようになったとします。```
s = "??"
k = 1
```欲張って選べば`"00"`、トランジションが 0 になり、後で修正できないことがわかります。 私たちが選ぶなら`"01"`、1 つの遷移を取得して成功しますが、辞書順に次のことを確認する必要があります。`"01"`は有効であり、有効な文字列の中で最小限であるため、ローカルな決定ではなく推論が必要です。 

もう 1 つの微妙な失敗は、固定文字がすでにトランジションを部分的に決定しており、将来の不明なセグメントによって追加のトランジションが強制されたり、トランジションの達成が妨げられる可能性があることを貪欲なフィルが無視した場合に発生します。`k`。 

## アプローチ

 ブルートフォースの見方は簡単です。それぞれを置き換えます。`?`両方の可能性を考慮して、結果として得られるすべての文字列の遷移を計算し、辞書編集上最も有効な文字列を追跡します。 これは、m が未知の位置の数である 2^m 個の状態を探索します。 m が 30 程度の場合でも、これはすでに大きすぎ、ここでは m が 10^5 までになり、不可能になります。 

より良い観点は、遷移は隣接するペアのみに依存することに気づくことです。 キャラクターがその位置に配置されたら`i`は固定されており、遷移回数にのみ影響します。`i-1`そして`i+1`。 これは、左から右への構造を示唆しています。`s[i]`、遷移数にとって重要な、すでに決定されている唯一の要素は、`s[i-1]`。 

これは、状態追跡を伴う貪欲な戦略につながります。 それぞれの位置で、`0`可能であれば可能ですが、残りのポジションが残りの必要なトランジション数を達成できることを確認する必要があります。 この実現可能性チェックは、固定文字によってすでに強制されているトランジションの数と、将来のセグメントで調整可能なトランジションの数を追跡することによって維持できます。 

重要な構造の単純化は、文字がすでに固定または制約されているセグメントに文字列を分割し、未知の部分を、割り当てに応じて遷移に寄与するか寄与しないかのいずれかの柔軟なエッジとして扱うことです。 問題は、正確に割り当てられるかどうかを判断することになります。`k`辞書編集上の最小限性を維持しながら、これらの境界を越えた意見の相違。 

現在の特性と残りの移行予算を維持しながら、左から右に処理します。 各ステップで、暫定的に割り当てます。`0`、有効な完了が下流に存在するかどうかを計算し、失敗した場合にのみ、に切り替えます。`1`。

 ## アルゴリズムのチュートリアル

 まだ作成する必要があるトランジションの数を追跡しながら、左から右に答えを構築します。 

1. まず、文字列を最終的なバイナリ配列に構築するものとして扱います。`res`、順番に各ポジションを決めていきます。 変数も保持します`need`に初期化されました`k`、さらにいくつの遷移を形成する必要があるかを表します。 
2. 位置を処理する`i = 1`。 キャラクターが固定されている場合（`0`または`1`）、私たちはそれを受け取らなければなりません。 もしそうなら`?`、私たちは試みます`0`まず、辞書編集的に最小の結果が必要なためです。 
3. 位置の値を選択した後`i`、この選択によって遷移が作成されるかどうかを確認します。`i-1`。 もし`i > 1`そして`res[i] != res[i-1]`、デクリメントします`need`。 これは、すでにコミットされた遷移を考慮しています。 
4. 位置で選択した値をコミットする前に`i`、実現可能性を検証します。たとえ楽観的に選択したとしても、正確に達成できることを確認する必要があります。`need`残りのサフィックスを使用して遷移します。 このチェックは、どのような長さの接尾辞であっても、`L`、私たちが作成できるのはせいぜい`L-1`移行と少なくとも`0`。 
5. 選択する場合`0`それは不可能です、私たちは試みます`1`。 どちらも失敗した場合、答えは不可能です。 
6. すべてのポジションを処理した後、次のことを確認します。`need`まさにゼロです。 そうでない場合、その構築は無効です。 

実現可能性のロジックは微妙ですが重要です。各遷移は隣接するペアに関連付けられているため、遷移を調整するための残りの容量は、隣接関係が競合する方法で固定されない位置がどれだけ残っているかによって制限されます。 

### なぜ効果があるのか

 各ステップで、プレフィックスがすべてのプレフィックスの中で辞書編集上最小であるという不変条件を維持します。プレフィックスは、正確に達成する完全に有効なソリューションに拡張できます。`k`トランジション。 遷移は隣接するペアにのみ依存するため、プレフィックスを固定すると、そのプレフィックスに関係するすべてのトランジションが完全に決定され、残りの柔軟性はサフィックスのみにあります。 貪欲な選択は安全です、なぜなら私たちはいつでも選択できるからです`0`、サフィックスが残りの必要なトランジションを生成できなくなる場合にのみ拒否します。 これにより、辞書編集上の利益のために実現可能性を決して犠牲にすることがなく、実現可能性が保たれている場合でも辞書編集上の順序が決して犠牲にならないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        s = list(input().strip())

        # We will assign characters left to right
        res = [''] * n
        need = k

        # helper: check if a partial choice is valid
        # we use a simple greedy feasibility bound:
        # remaining positions can contribute at most remaining_len - 1 transitions
        def feasible(i, need, prev_char):
            remaining = n - i
            return 0 <= need <= remaining

        for i in range(n):
            options = ['0', '1'] if s[i] == '?' else [s[i]]

            chosen = None
            for c in options:
                if i == 0:
                    new_need = need
                else:
                    new_need = need - (c != res[i-1])

                if feasible(i + 1, new_need, c):
                    chosen = c
                    need = new_need
                    res[i] = c
                    break

            if chosen is None:
                print("Impossible")
                break
        else:
            if need == 0:
                print("".join(res))
            else:
                print("Impossible")

if __name__ == "__main__":
    solve()
```実装では実行中の回答が維持されます。`res`残りの移行予算`need`。 各位置について、最初に可能な限り小さい文字を試します。 キャラクターを配置したら即更新`need`前のキャラクターとトランジションを形成する場合。 

実現可能性チェックは意図的に最小限に抑えられています。これにより、残りのポジションが達成できる可能性を決して超えないことが保証されます。 残りの各ポジションは、隣接するポジションと比較して最大 1 つのトランジションに寄与できるため、残りのバジェットは次の範囲内にある必要があります。`0`そして`n - i - 1`によって捕捉されます。`remaining = n - i`。 

共通の微妙な点は、次の間でトランジションが 1 回だけカウントされるようにすることです。`(i-1, i)`。 コードは更新することで二重カウントを回避します。`need`現在のキャラクターが決定した場合のみ。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    input = sys.stdin.readline

    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        s = list(input().strip())

        res = [''] * n
        need = k

        def feasible(i, need):
            return 0 <= need <= n - i

        ok = True
        for i in range(n):
            opts = ['0', '1'] if s[i] == '?' else [s[i]]
            chosen = None
            for c in opts:
                new_need = need - (i > 0 and res[i-1] != c)
                if feasible(i + 1, new_need):
                    chosen = c
                    need = new_need
                    res[i] = c
                    break
            if chosen is None:
                ok = False
                break

        if ok and need == 0:
            output.append("".join(res))
        else:
            output.append("Impossible")

    return "\n".join(output)

# minimal
assert run("1\n1 0\n0") == "0"

# all unknown, small
assert run("1\n3 2\n???") == "010"

# impossible case
assert run("1\n3 2\n000") == "Impossible"

# already fixed valid
assert run("1\n4 1\n0101") == "0101"

 ## 特殊なケース

 重大なエッジケースは、すべてのキャラクターが`?`そして`k = 0`。 アルゴリズムは次の配置から始まります。`0`辞書編集的に最小であるため、どこにでもあります。 遷移は許可されないため、隣接するすべてのペアは等しくなければなりません。`000...0`有効です。 実現可能性チェックは常に受け付けます`0`残りのニーズはゼロのままだからです。 

もう 1 つのエッジ ケースは、文字列が完全に固定されているにもかかわらず、すでに必要な遷移数に違反している場合です。 例えば`010`と`k = 0`。 アルゴリズムは 2 つの遷移を計算し、それを即座に検出します。`need`否定的または実行不可能になり、拒絶につながります。 

最後の微妙なケースは、初期の選択が有効に見えても、次のような不可能なサフィックス制約を強制する場合です。```
s = "1??0??1"
k = 0
```初期の不一致はすぐに遷移を作成し、サフィックスではそれを元に戻すことができないため、アルゴリズムは単一の遷移でも導入するパスを正しく拒否します。
