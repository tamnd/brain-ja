 ## 問題の理解

 整数配列と特別な値が与えられます。$k$。 このプロセスは動的です。配列に以下に等しい要素が少なくとも 1 つ含まれている限り、$k$、配列のすべての正の要素を 1 ずつ減らす操作を繰り返し適用します。 ゼロは変化せず、値がゼロを下回ることはありません。 

固定長の連続した部分配列の場合$m$、このグローバルプロセスが終了するまで実行されることを想像します。$k$が配列全体に残り、プロセスが安定した後にその部分配列内に現れるゼロの数を数えます。 最終的な答えは、すべての長さにわたるこれらのゼロカウントの合計です。$m$サブアレイ。 

重要な点は、デクリメント操作がグローバルで繰り返されるため、すべての要素が「ラウンド」ごとに 1 回だけ減少するのに対し、すべての要素が減少するということです。$k$配列内のどこかにまだ存在します。 

この制約により、私たちは線形または線形に近い動作をするようになります。 と$n$まで$10^6$、各減分ラウンドを明示的にシミュレートする解決策は直ちに不可能になります。 平$O(n^2)$スライディング ウィンドウを超えると遅すぎます。$O(n)$窓とそれぞれのサイズ$O(n)$。 したがって、ターゲットは、配列上の単一パスまたは少数のパスです。$O(n)$または$O(n \log n)$複雑。 

微妙な問題は、停止条件を理解することです。 グローバル デクリメントの数は事前に固定されていません。 それは、すべての発生に必要な最大ラウンド数によって異なります。$k$消えること。 シミュレーションが不可能になるまでシミュレートしようとする単純なアプローチ$k$存在すると、配列が過剰にデクリメントされたり、繰り返しスキャンされたりしますが、どちらもコストがかかりすぎます。 

エッジケースは次の場合に発生します。 

などの最小限のケース$n = m = 1$グローバルプロセスの解釈を混乱させる可能性があります。 

配列に何も含まれていない場合$k$まったく、操作はトリガーされないため、配列は変更されず、ゼロも作成されません。 少なくとも 1 ラウンドを想定したソリューションでは、値が誤って削減されます。 

すべての要素が次と等しい場合$k$、ラウンドごとにすべての正の値が均一に減少するため、配列はすべてがゼロになるまで単一の減少タイムラインのように動作します。 ラウンド数は正確になります$k$、最後にはすべての要素がゼロになり、すべての部分配列の寄与に大きな影響を与えます。 

## アプローチ

 強引なアイデアは、説明されたプロセスを各サブ配列に対して直接シミュレートすることです。 あらゆる長さのウィンドウに対して$m$、サブ配列をコピーし、すべての正の要素を繰り返し減少させます。$k$が存在し、最後にゼロを数えます。 これは論理的には正しいですが、そのコストは膨大です。 

各サブ配列には潜在的に次のものが必要です$O(\max a_i)$ラウンドをデクリメントし、各ラウンドがタッチする$O(m)$要素。 まで$10^6$部分配列、これは次のようなものに縮退します。$10^{12}$最悪の場合は手術が不可能になります。 

重要な点は、操作がグローバルかつ均一であることです。プロセスが停止するまで、すべての要素がまったく同じステップ数ずつ減少します。 重要なのは、すべてのラウンドが発生する前に何ラウンド発生するかということだけです。$k$排除される。 その数字を$T$。 それからすべての要素$a_i$になる$\max(0, a_i - T)$。 

したがって、問題全体は見つけることに帰着します$T$次に、ウィンドウごとに、正確にいくつの要素が存在するかを数えます。$T$なぜなら、これらは正確にゼロに到達する要素だからです。 

これにより、問題は繰り返しのシミュレーションから単一の導出しきい値問題に変換され、その後スライディング ウィンドウの周波数計算が続きます。

 ## アルゴリズムのチュートリアル

 ### 重要なアイデア: ダイナミクスを単一のしきい値に抑える

 まず、グローバル デクリメント操作がすべて行われる前に、何回発生するかを決定します。$k$価値観が消える。 各演算によりすべての正の値が 1 ずつ減算されるため、要素は次と等しくなります。$k$正確に生き残る$T = k$ゼロになる前に丸めます。 少なくとも 1 つあれば$k$、プロセスは正確に続きます$k$ステップ。 ない場合$k$、それはゼロステップ続きます。 

したがって、すべての要素はルールによって変換されます$a_i \to \max(0, a_i - T)$、 どこ$T = k$もし$k$存在する、それ以外の場合$T = 0$。 

変換後のウィンドウ内のゼロの数は、次の条件を満たす要素の数と同じになります。$a_i \le T$。 ただし、正確にゼロに到達する要素のみが重要であるため、元の値がいくつ満たされるかを数えます。$a_i \le T$、次の場合にのみ完全に等価に寄与します。$a_i \le k$具体的にはゼロになります。 

### ステップ

 1. 配列を 1 回スキャンして、値が$k$が表示されます。 そうでない場合は、設定してください$T = 0$; それ以外の場合は設定$T = k$。 これにより、グローバル デクリメント ラウンドの合計数が決まります。 
2. 長さの部分配列ごとに、問題をカウントに変換します。$m$、を満たす要素はいくつありますか$a_i \le T$。 これらはまさに、プロセスが終了するとゼロになる要素です。 
3. バイナリ配列を構築する$b$どこ$b_i = 1$もし$a_i \le T$、 さもないと$0$。 これは、各位置が最終状態でゼロに寄与するかどうかをエンコードします。 
4. 長さ全体の合計を計算します。$m$合計のウィンドウ$b$価値観。 これは、スライディング ウィンドウを使用して実行できます。つまり、現在のウィンドウの合計を維持し、入力要素を追加し、出力要素を削除し、結果を累積します。 
5. 最終的な答えは、累積ウィンドウ合計の合計です。 

### なぜ効果があるのか

 このプロセスでは、すべての要素に同じ数のデクリメント操作が適用されるため、相対的な順序は重要ではありません。 各要素は、その初期値が最大の場合、独立してゼロになります。$T$。 したがって、この変換により、問題は静的しきい値フィルターとそれに続く標準のスライディング ウィンドウ集計に軽減されます。 不変条件は次のとおりです$T$ステップごとに、すべての要素の値は位置や相互作用ではなく元の値のみに依存するため、ウィンドウの寄与は加算的で独立したものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    has_k = any(x == k for x in a)
    T = k if has_k else 0
    
    b = [1 if x <= T else 0 for x in a]
    
    window_sum = sum(b[:m])
    ans = window_sum
    
    for i in range(m, n):
        window_sum += b[i] - b[i - m]
        ans += window_sum
    
    print(ans)

if __name__ == "__main__":
    solve()
```解決策は、特別な値かどうかを判断することから始まります。$k$が存在します。 これは、デクリメントラウンドが発生するかどうかを制御します。 次に、配列は、最終的にゼロになる要素をマークするブール インジケーター配列に変換されます。 

スライディング ウィンドウは、長さの各サブ配列内のそのような要素の数を維持します。$m$。 各更新ではウィンドウが一定時間で調整され、現在の合計にはすべてのウィンドウからの寄与が累積されます。 

よくある間違いは、デクリメント プロセスを明示的にシミュレートしようとすることです。 もう 1 つは、各ウィンドウの合計を最初から再計算することです。$O(nm)$そして大規模に失敗する。

 ## 特殊なケース

 配列に次の出現が含まれていない場合$k$、変換ステップは決してトリガーされません。 アルゴリズムは設定によってこれを処理します。$T = 0$、どの要素も満たさないことを意味します$a_i \le T$ただし、すでにゼロになっている場合は除きますが、制約の下ではゼロになることはありません。 したがって、スライディング ウィンドウはすべてのサブ配列にわたって合計が 0 になり、何も変化しないという事実と一致します。 

すべての要素が等しい場合$k$、すべての位置がしきい値条件を満たします。 バイナリ配列はすべて 1 になり、各ウィンドウの合計は次のようになります。$m$。 スライディングウィンドウは正確に蓄積されます$n - m + 1$の貢献$m$、プロセス完了後の均一なフルゼロの動作と一致します。 

単一要素配列の場合、ウィンドウの合計は、次のいずれかに応じて 1 または 0 になります。$k$要素と一致します。 スライディング ウィンドウは、特別な処理を行わなくても、単一の値に正しく縮退します。
