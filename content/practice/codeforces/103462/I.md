 ## 解決策
 ## 問題の理解

 ツリーが与えられています。これは、接続された非巡回グラフを意味します。$n$ノード$n-1$エッジ。 タスクは、このツリー内に出現する特定の形状の個別のサブグラフの数をカウントすることです。 2 つのサブグラフがまったく同じエッジのセットで構成されている場合、2 つのサブグラフは同一であるとみなされます。そのため、必要なパターンを形成する個別のエッジのセットを効果的に数えることになります。 

非公式に「鶏の足」と表現されるこのパターンは、Y 字型または三叉の星のように、ノードを中心として 3 つの別々のエッジに分岐する小さな接続された構造に対応します。 有効な各インスタンスは、中心ノードを選択し、その入射エッジを 3 つ選択することによって完全に決定されます。これは、ツリーでは、そのような選択によって 3 つの隣接ノードとそれらを接続するエッジが一意に決定されるためです。 

制約$n \le 5 \cdot 10^5$サブグラフを列挙したり、ノードやエッジの組み合わせを明示的に試行したりするアプローチは直ちに除外されます。 エッジの数は線形であるため、すべてのトリプルのエッジを反復処理するだけでも遅すぎます。$n$最悪の場合、その組み合わせは爆発的に三次的な動作を引き起こす可能性があります。 したがって、解決策は、理想的には各ノードでの局所的な構造情報を集約することによって、問題を線形または線形に近い時間で計算できるものに減らす必要があります。 

ツリーが小さい場合、または低次数のノードがある場合には、微妙なエッジ ケースが発生します。 もし$n < 4$、どのノードも 3 つの入射エッジを持つことはできないため、答えはゼロでなければなりません。 もう 1 つのよくある落とし穴は、異なるサブグラフを構成するものを誤解していることです。2 つの星が異なるノードの中心にあり、たまたま構造的に似ているように見えても、エッジ セットが異なれば、それらは異なります。 

## アプローチ

 この問題を考える直接的な方法は、接続されている可能性のあるすべてのサブグラフを列挙し、それが必要な 3 本の構造を形成しているかどうかを確認することです。 木の中で$n$ノードの場合、接続を維持するエッジの各サブセットが候補となるため、接続されたサブグラフの数は最悪の場合でもすでに指数関数的になります。 サイズ 4 ノードの小さなサブグラフのみに限定したとしても、エッジの組み合わせを探索し、構造を検証する必要があります。これにより、少なくとも次のことが可能になります。$O(n^2)$または、密度の高い領域では動作が悪化します。 これはすぐに実行不可能になります$5 \cdot 10^5$ノード。 

重要な観察は、「鶏の足」構造が単一の中心ノードによって完全に決定されるということです。 中心が固定されると、唯一の自由は、どの 3 つの近隣が参加するかを選択することです。 ツリーでは、ノードに付随する 3 つの異なるエッジは、必要な形状の有効なサブグラフを自動的に形成します。これは、サイクルがなく、各エッジが一意のサブツリーにつながるためです。 これにより、グローバルな計数の問題が純粋にローカルな組み合わせの問題に崩壊します。 

各ノードについて$v$学位付き$\deg(v)$、3 つの入射エッジを選択する方法は次のとおりです。$\binom{\deg(v)}{3}$。 これをすべてのノードで合計すると、有効な「チキンフィート」サブグラフの総数が得られます。

 | 部分グラフのブルートフォース列挙 |$O(n^2)$に$O(2^n)$|$O(n)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 計算はツリー構造全体で 1 回のパスになります。 

1. ツリーを読み取り、それに付随するエッジの数を数えることによって、すべてのノードの次数を計算します。 カウントしている構造はグローバル トポロジではなくローカル隣接関係のみに依存するため、これで十分です。 
2. 答えがゼロになるようにアキュムレータを初期化します。 この変数には、各ノードからの寄与の合計が格納されます。 
3. 各ノードについて$v$、その程度を調べる$d$。 もし$d \ge 3$、隣接リストから 3 つの近隣を選択する方法の数を計算します。$d(d-1)(d-2)/6$、この値を答えに追加します。 次数が 3 未満のノードは、必要な分岐構造を形成できないため、何も寄与しません。 
4. 累積和モジュロを出力します。$998244353$。 

これが問題なく機能する理由は、すべての有効な構成にセンターが 1 つだけ存在するためです。 星型のサブグラフは、ツリー内の複数のノードの中心に置くことはできません。これは、そのサブグラフ内で次数 3 を持つ唯一の頂点が中心であり、他の頂点の次数が 1 であるためです。 この一意性により、中心ノードを処理するときにすべての有効な構造が 1 回だけカウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def nC3(x):
    if x < 3:
        return 0
    return x * (x - 1) * (x - 2) // 6

def main():
    n = int(input())
    deg = [0] * (n + 1)

    for _ in range(n - 1):
        u, v = map(int, input().split())
        deg[u] += 1
        deg[v] += 1

    ans = 0
    for i in range(1, n + 1):
        ans += nC3(deg[i])

    print(ans % MOD)

if __name__ == "__main__":
    main()
```実装の中核は度数配列で、エッジの読み取り中にローカル構造を追跡します。 各エッジはエンドポイントごとに 1 つずつ 2 度ずつ増分し、最終的なアレイが隣接情報を完全に取得できるようにします。 

結合関数は整数演算を直接使用します。 Python は大きな整数を安全に処理するため、オーバーフローの心配はありませんが、最終結果は剰余を削減されます。$998244353$必要に応じて。 

微妙な点は、6 による除算が整数空間での乗算の後に行われることです。 連続する 3 つの整数の積は常に 6 で割り切れるため、精度の問題は発生しないため、これは安全です。 

## 実用的な例

 4 つの葉に接続された中心ノードのような形をした小さな木について考えてみましょう。 エッジを$(1-2), (1-3), (1-4), (1-5)$。 

| ノード | 学位 | 貢献$\binom{d}{3}$|
 | --- | --- | --- |
 | 1 | 4 | 4 |
 | 2 | 1 | 0 |
 | 3 | 1 | 0 |
 | 4 | 1 | 0 |
 | 5 | 1 | 0 |

 答えは 4 で、ノード 1 に付随する 4 つのエッジのうち任意の 3 つを選択することに対応します。これにより、3 つの葉を選択するたびに個別のサブグラフが生成されることが確認されます。 

ここで、5 つのノードのパスを考えてみましょう。$1-2-3-4-5$。 

| ノード | 学位 | 貢献 |
 | --- | --- | --- |
 | 1 | 1 | 0 |
 | 2 | 2 | 0 |
 | 3 | 2 | 0 |
 | 4 | 2 | 0 |
 | 5 | 1 | 0 |

 すべてのノードの次数は 3 未満であるため、有効な「チキン フィート」は存在しません。 答えは 0 で、これはパスに分岐点がないという直観と一致します。

 ## 特殊なケース

 星形の入力では、アルゴリズムはすべての構造を中心ノードに割り当てます。 たとえば、中心ノード 1 が他の 4 つのノードに接続されている場合、ノード 1 の次数は 4 になり、他のすべてのノードは 1 のままになります。$\binom{4}{3} = 4$は 3 つのエッジのすべての異なる選択を正確にカウントし、それぞれが一意のエッジ セットに対応するため、過剰カウントは発生しません。 

単純なパスでは、すべてのノードの次数が最大 2 であるため、組み合わせ公式は決してトリガーされません。 このアルゴリズムは、特別なケースを使用せずに自然に 0 を生成します。これは、分岐点として機能するノードがないという事実と一致します。 

異なるサブツリー内で両方とも高い次数を持つ 2 つの隣接するノードなど、複数の分岐ノードを持つツリーでは、各ノードが独立して寄与します。 有効な「チキンフィート」には一意の中心がなければならないため、寄与間に重複はなく、局所的な合計は正しいままです。
