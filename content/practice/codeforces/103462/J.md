 ## 解決策
 ## 問題の理解

 具体的には、長さが正確に 2 のべき乗である配列が与えられています。$2^k$、 どこ$k$各操作は現在の配列を取得し、ちょうどその半分 (左半分または右半分のいずれか) を破棄し、残りの半分は変更しないままにします。 これは停止するまで繰り返されます。 

目標は、配列を完全に並べ替えることではなく、残りの配列が減少しない状態に到達することです。 それぞれの操作でサイズが半分になるため、$t$残りの配列の長さを持つ演算$2^{k-t}$。 したがって、このプロセスは実際には、長さが 2 のべき乗である連続ブロックで終わる、左/右半分のシーケンスを選択することになります。 

重要な問題は、すべての連続した長さのセグメントが存在するわけではないことです。$2^d$到達可能です。 繰り返しの半分化によって作成された暗黙のバイナリ分割構造と一致するセグメントのみが有効な結果となります。 

制約から、$k \le 20$、 それで$n \le 2^{20}$、約100万の要素。 これはすぐに次のことを示唆しています。$O(n \log n)$あるいは$O(n k)$解決策は実行可能ですが、二次関数を超えるものは何でも$n$遅すぎるでしょう。 

考えられるすべての左/右削除シーケンスを試す単純なアプローチでは、次のようになります。$2^k$ただし、各選択は後続の配列の構造に影響を与えるため、これはすぐに最悪の意味で指数関数的となり、非常に小さいサイズを超えて拡張することはできません。$k$。 

微妙なエッジ ケースは、配列がすでに減少していない場合です。 その場合、操作はゼロにする必要があります。 もう 1 つは、非常に小さなセグメントのみが単調な場合です。たとえば、配列が上下に交互に配置されているため、長さ 1 のセグメントのみが有効な場合です。 ソリューションは正しく返される必要があります$k$単一の要素に縮小する必要があるためです。 

## アプローチ

 直接総当り戦略では、考えられるすべての削除シーケンスをシミュレートします。 各ステップで、左半分を保持するか右半分を保持するかを選択し、結果の配列を再帰的に調べて、最後に残った配列が減少していないかどうかを確認します。 これは、深さのバイナリ決定木を調査します。$k$、あります。$2^k$各パスには、最大で条件の検証が含まれます。$2^k$中間状態の要素。 たとえチェックが最適化されたとしても、状態の数だけではこれを実行できません。$k = 20$。 

重要な観察は、このプロセスがブロック内に新しい相対的な順序を決して作成しないことです。 すべての操作では、現在のセグメントの半分のみが破棄され、残りのセグメントは常に、長さが 2 のべき乗で二進パーティションに位置合わせされた連続した間隔になります。 したがって、一連の操作について考える代わりに、最終状態について直接考えることができます。それは常にある長さのセグメントです。$2^d$繰り返しの半分化によって決定される境界上に位置合わせされます。 

これにより、問題は、長さの整列された最大のセグメントを見つけることに軽減されます。$2^d$それはすでに減少していません。 その最大値を超えると$d$はわかっていますが、答えは単純に何回半分にする必要があるかです。$2^k$まで$2^d$、つまり$k - d$。 

セグメントが非減少であるかどうかを効率的にテストするために、反転が発生する場所、つまり位置を事前計算します。$i$そのような$a[i] > a[i+1]$。 セグメントは、その中に反転が含まれていない場合にのみ有効です。

 ## アルゴリズムのチュートリアル

 1. 配列が減少するすべての位置をマークする補助配列を構築します。$a[i] > a[i+1]$。 これにより、「ソートされていない」という概念が 1 つの点に圧縮されます。 
2. このマーカー配列に対してプレフィックスの合計を計算して、任意の間隔にいくつの反転が存在するかを定数時間でクエリできるようにします。 
3. 考えられるすべての 2 のべき乗の長さについて$2^d$、その長さに一致するすべての有効な開始位置をスキャンします。つまり、次で割り切れるインデックスを意味します。$2^d$。 このようなセグメントごとに、その中の反転の数がゼロかどうかを確認します。 
4. の最大値を追跡します。$d$少なくとも 1 つの整列された長さのセグメント$2^d$全く減りません。 
5. この達成可能な最良のセグメント サイズを答えに変換します。 最適なセグメントに長さがある場合$2^d$、から始めました。$2^k$そして必要です$k - d$それに到達するまでの半分。 

アライメントが重要な理由は、各操作が常に現在の配列を正確に半分にカットするため、到達可能なセグメントの開始インデックスはこのバイナリ分割構造を尊重する必要があるためです。 

### なぜ効果があるのか

 すべての操作シーケンスは、元の配列の完全なバイナリ分解をたどることに対応し、各レベルですべての候補セグメントが同時に半分になります。 これにより、最後のセグメントは任意の部分配列ではなく、二進間隔になります。 配列は決して並べ替えられないため、有効であることを妨げる唯一の障害は、セグメント内に減少する隣接ペアが存在することです。 したがって、妥当性は、候補二項セグメントに反転が含まれているかどうかを確認することに完全に帰着し、そのサイズを最大化することで、必要な半分の最小数が直接決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    k = int(input().strip())
    n = 1 << k
    a = list(map(int, input().split()))

    bad = [0] * (n - 1)
    for i in range(n - 1):
        if a[i] > a[i + 1]:
            bad[i] = 1

    pref = [0] * (n)
    for i in range(n - 1):
        pref[i + 1] = pref[i] + bad[i]
    pref[n - 1] = pref[n - 2] + 0 if n > 1 else 0

    def has_bad(l, r):
        if l == r:
            return False
        return (pref[r] - pref[l]) > 0

    best_d = 0

    for d in range(k + 1):
        length = 1 << d
        ok = False
        for start in range(0, n, length):
            if start + length <= n:
                if not has_bad(start, start + length - 1):
                    ok = True
                    break
        if ok:
            best_d = d

    print(k - best_d)

if __name__ == "__main__":
    main()
```この実装では、最初にすべての障害情報を隣接する比較のバイナリ配列に圧縮します。 プレフィックス合計構造により、セグメントに違反が含まれているかどうかを定期的にチェックできます。 外側のループはセグメント サイズを 2 の累乗で増加させようとしますが、内側のループは有効な二進数で整列された開始位置のみをチェックします。 特定のサイズで有効なセグメントが見つかると、達成可能な最適な深さが更新されます。 

一般的な微妙な点は、サイズの配列を扱うため、プレフィックス合計の境界処理です。$n-1$比較用ですが、元の配列のインデックス範囲に対するクエリを実行します。 実装では、セグメント クエリが隣接する比較の範囲に正確に対応するようにインデックスを慎重にシフトします。 

## 実用的な例

 配列を考慮してください$[1, 3, 2, 4]$と$k = 2$。 

反転マーカーを計算します: のみ$3 > 2$は違反です。 

| d | 長さ | 開始 | セグメント | 内部が悪い | 有効 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 0、1、2、3 | 単一の要素 | いいえ | はい |
 | 1 | 2 | 0,2 | [1,3]、[2,4] | [2,4] わかりました | はい |
 | 2 | 4 | 0 | 完全な配列 | 3>2 を含む | いいえ |

 最適な有効な二項セグメント長は次のとおりです。$2^1 = 2$、したがって、答えは$2 - 1 = 1$。 

次に、完全にソートされた配列を考えてみましょう。$[1,2,3,4]$。 

| d | 長さ | 開始 | セグメント | 内部が悪い | 有効 |
 | --- | --- | --- | --- | --- | --- |
 | 2 | 4 | 0 | 完全な配列 | なし | はい |

 ここで一番いいのは、$d = 2$、したがって、答えは$0$。 これは、操作が必要ないという事実と一致します。 

これらのトレースは、任意の部分配列を検索しているのではなく、二項整列された部分配列のみを検索しており、その中で内部単調性が成立するかどうかのみをチェックしていることを示しています。

## 特殊なケース

 配列がすでに非減少である場合、すべてのレベルのすべての二項セグメントが有効です。 アルゴリズムはこれを可能な限り最大で検出します$d = k$これは、完全なセグメントには反転が含まれておらず、すぐにゼロの操作が返されるためです。 

配列が厳密に減少している場合、長さが 1 を超えるすべてのセグメントに反転が含まれます。 チェックはすべて失敗します$d > 0$、残すのみ$d = 0$有効。 これにより、答えは次のようになります$k$、半分化を繰り返すことで単一の要素に縮小することに相当します。 

反転がまばらな場合 (ソート済みの大きな領域内の単一のローカル ドロップなど)、その正確な位置を回避する二項セグメントのみがカウントされます。 アラインメントによってテスト可能なセグメントが制限されるため、アルゴリズムは到達不可能な間隔を正しく無視し、構造的に有効な間隔のみに焦点を当てます。
