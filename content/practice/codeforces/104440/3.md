 ## 解決策
 ## 問題の理解

 1 から n までの番号が付けられた家がある通りが与えられています。 キャラクターが通りを 2 回歩き、分割ルールに従って家にポスターを貼ります。 最初のパスでは、インデックスが a で割り切れるすべてのハウスが選択されます。 2 回目のパスでは、b で割り切れるすべての家が考慮されますが、その家が最初のパスでまだポスターを受け取っていない場合にのみポスターが追加されます。 

タスクは、両方のパス後に少なくとも 1 枚のポスターを受け取った別個の家が何軒あるかを計算することです。 

これは、[1, n] の範囲内で a で割り切れる、または b で割り切れる整数をカウントし、重複したものは 1 回だけカウントするのと同じです。 

制約により、n、a、b は最大 10^9 まで許可されます。 通常の制限では最大 10^9 の線形スキャンは不可能であるため、これによりすべてのハウスの反復処理が即座に除外されます。 解決策は、シミュレーションではなく算術カウントに依存する必要があります。 

単純な間違いは、両方のパスで家をマークすることをシミュレートすることです。 たとえば、n = 10、a = 2、b = 3 の場合、2、4、6、8、10 を明示的にマークし、次に 3、6、9 をマークします。これは、n が小さい場合には機能しますが、n が大きい場合は完全に失敗します。 

もう 1 つの微妙な問題は、二重カウントです。 a と b の両方で割り切れるハウスは 2 回数えてはなりません。 たとえば、n = 12、a = 3、b = 4 の場合、ハウス 12 は両方で割り切れます。 正しい解決策は、そのような重複を差し引く必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 1 から n までのすべてのハウスを反復処理し、a または b で割り切れるかどうかを確認します。 そうであれば、答えをインクリメントします。 これは、説明されているプロセスを直接反映しているため、正しいです。 ただし、そのコストは O(n) であり、n が 10^9 に達すると、何十億ものチェックが必要になるため、実行不可能になります。 

重要な観察は、割り算が規則的な算術パターンを形成するということです。 [1, n] 内の a で割り切れる整数の数は、正確に Floor(n / a) です。 同様に、b で割り切れる数は、floor(n / b) です。 重複、つまり a と b の両方で割り切れる数値は、lcm(a, b) で割り切れるため、二重カウントを避けるために、floor(n / lcm(a, b)) を 1 回減算します。 これにより、問題は定数時間の演算に縮小されます。 

元のプロセスは 2 つの周期セットの結合にすぎないため、変換は機能します。 要素を列挙する代わりに、期間の長さを使用して要素をカウントします。

 ## アルゴリズムのチュートリアル

 [1, n] 内の数が a で割り切れる数、b で割り切れる数がいくつあるかを計算し、両方で割り切れる数を減算します。 

1. 範囲内の a の倍数をカウントする ca = n // a を計算します。 これは、すべての a 番目の数値が 1 つの有効なハウスに寄与するため機能します。 
2. 同じ理由で、b の倍数を数えて cb = n // b を計算します。 
3. gcd(a, b) を使用して lcm(a, b) を計算します。 最小公倍数は a と b の両方で同時に割り切れる数であるため、重複は正確に最小公倍数の倍数で発生します。 
4. cab = n // lcm(a, b) を計算します。 これは、前の 2 つのカウントに 2 回含まれていた住宅を正確にカウントします。 
5. 最終的な答えは ca + cb - cab です。 

重複する各ハウスは ca で 1 回、cb で 1 回カウントされるため、減算が必要ですが、投稿するポスターは 1 枚だけである必要があります。 

### なぜ効果があるのか

 [1, n] のすべての整数は、a のみで割り切れる、b のみで割り切れる、または両方で割り切れるという 3 つの素なカテゴリのいずれかに正確に属します。 最初の 2 つのカテゴリは個別にカウントされますが、3 番目のカテゴリは 2 回カウントされます。 3 番目のカテゴリのサイズを減算すると、正しいカウントが復元されます。 可分性は lcm の倍数によって完全に特徴付けられるため、他の重複は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd

def lcm(x, y):
    return x // gcd(x, y) * y

n = int(input())
a = int(input())
b = int(input())

ca = n // a
cb = n // b
cab = n // lcm(a, b)

print(ca + cb - cab)
```この解決策は、整数の除算プロパティに依存します。 n // k は、[1, n] に k の倍数がいくつあるかを数えます。 lcm の計算では gcd を使用してオーバーフローの問題を回避し、a と b が大きい場合でも正確さを保証します。 

一般的な実装上の落とし穴は、 lcm を a * b として直接計算することであり、中間算術でオーバーフローしたり不正確になる可能性があります。 // gcd(a, b) * b を使用すると、それを回避できます。 

もう 1 つの微妙な点は、整数の除算が一貫して使用されるようにすることです。 浮動小数点除算は正確性を損なう可能性があります。

これにより、両方の割り算セットが空である場合も式が自然に処理されることが確認されます。

## テストケース```python
import sys, io
from math import gcd

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import gcd

    n = int(sys.stdin.readline())
    a = int(sys.stdin.readline())
    b = int(sys.stdin.readline())

    def lcm(x, y):
        return x // gcd(x, y) * y

    ca = n // a
    cb = n // b
    cab = n // lcm(a, b)

    return str(ca + cb - cab)

# provided samples
assert run("10\n2\n3\n") == "7"
assert run("5\n10\n20\n") == "0"

# custom cases
assert run("1\n1\n1\n") == "1", "single house always covered once"
assert run("12\n3\n4\n") == "6", "check overlap at lcm"
assert run("100\n7\n5\n") == str(100//7 + 100//5 - 100//35), "random correctness"
assert run("30\n6\n10\n") == str(30//6 + 30//10 - 30//30), "lcm equals both overlap"

 ## 特殊なケース

 1 つのエッジ ケースは、a と b が等しい場合に発生します。 たとえば、n = 20、a = 4、b = 4 です。両方のパスで同じ家が選択されるため、正しい結果は単純に Floor(20 / 4) になります。 lcm(a, b) が a に等しいため、数式はこれを処理します。したがって、減算によって重複したカウントが 1 回だけ削除されます。 

もう 1 つのケースは、1 つの約数が n を超える場合です。 n = 5、a = 10、b = 3 の場合、最初のパスの寄与はゼロで、2 番目のパスは通常どおりに動作します。 lcm は 30 であるため、オーバーラップは差し引かれません。 このアルゴリズムは、有効な倍数のみをカウントするように正しく処理されます。 

最後のケースは、a と b の両方が n を超える場合です。 この場合、すべてのフロア区分はゼロになり、特別な処理を行わなくても結果は正しくゼロになります。
