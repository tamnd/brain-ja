 ## 問題の理解

 という隠された注文があります。`n`ボタン。 ボタンは、その順序で次に正しいボタンである場合にのみ押されたままになります。 どこかの時点で間違ったボタンを押すと、それまでに押したボタンがすべて元に戻り、最初からシーケンスの構築をやり直す必要があります。 

マナオはその順序を知りませんが、ボタンが押されたままになっているかどうか、またはロックがリセットされるかどうかを観察することはできます。 彼は常に、必要なプレス回数を最小限に抑えるアクションを選択します。 考えられる最悪の隠れた順序で必要なボタンを押す回数を計算する必要があります。 

入力には単一の整数が含まれています`n`、ボタンの数。 出力は、最良の戦略を使用する場合にマナオが必要とする可能性のある最大プレス数です。 

制約が非常に小さいので、`n ≤ 2000`。 たとえ`O(n²)`ソリューションは約 400 万の操作のみを実行しますが、これは制限内では取るに足らないものです。 高度な最適化は必要ありません。 課題は、数え方の公式を認識することです。 

よくある間違いは、失敗した試行のみをカウントし、成功したボタンの押下も消費されることを忘れることです。 

考慮する：```
n = 2
```答えは`3`、 ない`2`。 

最悪の場合、まずマナオがボタンの掛け違いをしてしまう。 そうすれば、彼は正しい最初のボタンを知ることができます。 ボタンを正常に押した後も、ロックを開けるために 2 番目のボタンを押す必要があります。 

もう 1 つの簡単な間違いは、すべての段階で残りのボタンをすべてテストする必要があると考えることです。 

考慮する：```
n = 3
```最初の 2 つのボタンがわかっていて押し続けると、最後のボタンが自動的に決定されます。 テストする必要はありません。 正しい答えは、`7`、 ない`9`。 

エッジケース`n = 1`も重要です。```
1
```出力：```
1
```ボタンは1つだけなので、1回押すだけでロックが開きます。 

## アプローチ

 この問題を考える最も直接的な方法は、マナオがどのようにシーケンスを発見するかをシミュレートすることです。 

彼が最初のことをすでに知っていると仮定します`k - 1`シーケンスのボタン。 を発見するには、`k`- 番目のボタンには、`n - k + 1`候補ボタンが残っています。 

最悪の場合、正しいボタンが最後の候補になります。 

間違った候補ごとに、最初に既知の長さのプレフィックスを再構築する必要があります。`k - 1`、その後、間違った試みをしてください。 それには費用がかかります`k`を押します。 

間違った候補がすべて失敗した後、最後にもう一度プレフィックスを再構築し、正しいボタンを押します。 

ブルートフォース シミュレーションでは、すべてのポジションにこれらのコストを明示的に追加できます。 以来`n ≤ 2000`、このカウントプロセスでも十分に高速です。 難しいのは全体をきれいに表現することです。 

重要な観察は、位置についてです。`k`、まさにあります`n - k`間違った候補者。 

間違った候補者ごとにコストがかかる`k`プレス:```
(k - 1) presses to rebuild the prefix
+ 1 press for the wrong button
= k
```したがって、ポジションの貢献度の合計は`k`は：```
k · (n - k)
```最後を除くすべての位置が検出された後も、ロックには完全なシーケンスの構築が 1 回成功する必要があります。 それは貢献します`n`さらにプレス。 

すべてを合計すると次のようになります。```
answer = n + Σ k(n - k)
         for k = 1..n-1
```これはすでに十分に効率的です。 合計を直接計算できます`O(n)`時間。

3. ポジションごとに`k`から`1`に`n - 1`、 追加`k × (n - k)`。

4. 蓄積された回答を出力します。 

### なぜ効果があるのか

 を決定するときは、`k`- 番目のボタン、正確に`n - k`ボタンが間違っています。 最悪の場合、正しいものが見つかる前にすべてがテストされます。 

このような失敗したテストはすべて、既知の長さのプレフィックスを再構築する必要があります。`k - 1`ボタンを 1 つ間違えると、合計コストは`k`を押します。 

数量`k(n - k)`を検出しながら、すべての障害の合計コストを正確に計算します。`k`-番目の位置。 これをすべてのポジションで合計すると、失敗した試行はすべて 1 回だけカウントされます。 最後に、すべての位置がわかった後、完全なシーケンスを 1 回正常に実行するには、`n`を押します。 押下は省略されず、2 回カウントされることもないため、式は正確な最悪の場合のボタン押下数を生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    ans = n
    for k in range(1, n):
        ans += k * (n - k)

    print(ans)

solve()
```変数`ans`から始まります`n`、最後に成功したオープニング試行を表します。 

ループは位置を処理します`1`を通して`n - 1`。 ポジションごとに`k`、 がある`n - k`間違った候補者が残っています。 不合格になった各候補者のコスト`k`を押すので追加します`k * (n - k)`。 

最終的な位置には検出フェーズは必要ありません。 一度最初の`n - 1`ボタンが既知である場合、最後のボタンは強制されます。 そのため、ループは次の時点で停止します。`n - 1`。 

Python では整数オーバーフローは問題になりません。 たとえ`n = 2000`、答えは数十億のオーダーにすぎません。

# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(sys.stdin.readline())
    ans = n
    for k in range(1, n):
        ans += k * (n - k)

    return str(ans)

# provided sample
