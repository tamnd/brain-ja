 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの整数配列が与えられ、2 つの位置を選択し、両方の配列のそれらの位置にある要素を同時に交換するという 1 種類の操作を適用できます。 言い換えれば、各配列内で値を個別に交換しているのではなく、ペア全体を交換しているため、各インデックスはペアを保持する「カード」のように動作します。$(a_i, b_i)$、これらのカードを並べ替えることができます。 

限られた数のスワップを実行した後、最初の配列が左から右に減少せず、2 番目の配列も左から右に減少しないように、これらのペアの順序を変更することが目標です。 

したがって、再配置される実際のオブジェクトは 2 つの別々の配列ではなく、一連の 2D 点です。 各操作はこれらの点を並べ替えますが、両方の座標が同時に並べ替えられる並べ替えが必要です。 

この制約は、テストあたりのインスタンス サイズが小さいことを意味しており、通常は$O(n^2)$あるいは$O(n^3)$建築物。 これにより、階乗的に増加するため、インデックスのすべての順列を試すようなことは即座に除外されます。 また、単に実現可能性をチェックするのではなく、順列を明示的に生成する、建設的な並べ替え手順が期待されることも示唆しています。 

2 つの配列の順序が「一致しない」場合、微妙なエッジ ケースが発生します。 たとえば、1 つのインデックスに小さな値がある場合、$a$しかし大きい$b$、もう1つは大きな$a$でも小さい$b$の場合、両方を正しく配置することはできません。 

例:

 入力:```
a = [1, 2]
b = [2, 1]
```ここで、インデックス 1 をインデックス 2 の前に置くと、$a$並べ替えられたが壊れた$b$、修正を元に戻しながら$b$しかし壊れる$a$。 したがって、答えは不可能です。 

この種の対立は、この問題の主要な構造的障害です。 

## アプローチ

 各インデックスはポイントとして考えることができます$(a_i, b_i)$。 スワップを使用してインデックスを任意に並べ替えることができるため、課題は次のようになります。両方の座標が減少しないように、これらの点を 1 つのシーケンスに配置できるか?

 ブルートフォースアプローチでは、インデックスのすべての順列を試し、両方の配列がソートされているかどうかを確認します。 これは正しいですが、中程度の人でも実行不可能です$n$、そうですので$O(n!)$、そしてさらに$n = 10$、これは大きくなりすぎます。 

より構造化された試みは、1 つの座標でソートすることです。$a$、そしてそれを願っています$b$も自動的に並べ替えられます。 これは機能する場合もありますが、2 つの点が交差する順序がある場合、つまり一方の点の方が小さい場合には失敗します。$a$でももっと大きい$b$、もう1つはそれよりも大きいです$a$でも小さい$b$。 その場合、次のように並べ替えると、$a$増加を強制する$a$しかし、それによって減少が生じます$b$、要件を破っています。 

重要な点は、両方の次元で一貫した単一の順序付けが必要であるということです。 つまり、ポイントには座標間の「反転」が含まれてはなりません。 あるペアの場合$i, j$、 我々は持っています$a_i < a_j$しかし$b_i > b_j$の場合、これら 2 つの要素は、有効な最終シーケンスで一貫して順序付けることができません。 

したがって、実現可能性の条件は次のようになります。$a$、のシーケンス$b$値はすでに減少していない必要があり、あいまいさを持ち込まないように関係も一貫している必要があります。 同様に、次の基準で並べ替えます。$a$そして並べ替え$b$要素の相対順序が同じになるようにする必要があります。 

有効なターゲット順序が確立されると、答えを構築するのは簡単です。選択ソートと同様に、要素をターゲット位置に入れ替えるシミュレーションを行い、各入れ替え操作を記録します。

 | ソート + 実現可能性チェック + 建設的スワップ | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 最適な構造

 1. 各インデックスの処理$i$ペアとして$(a_i, b_i)$、元の位置に関連付けます。 
2. インデックスをペアでソートする$(a_i, b_i)$辞書順に。 これにより、そのような配置が存在する場合、両方の座標が減少しない候補の最終配置が得られます。 
3. このソート順で両方のシーケンスが一致していることを確認して、実現可能性を検証します。$a$そして$b$は減少していません。 いずれかの配列に減少が見られる場合は、有効な順列が存在しないと結論付けます。 
4. 可能であれば、インデックスの目標順序がわかります。 配列を構築する`pos`作業順列内の各インデックスの現在位置を保存します。 
5. 位置を左から右に繰り返します。 ポジションごとに$i$、ターゲットの順序に従ってそこに配置する必要があるインデックスを見つけます。 
6. そのインデックスがまだその位置にない場合$i$、一連のスワップを使用して、所定の位置にスワップします。 各スワップは 2 つのポジションを交換し、記録されたポジションを更新します。 各操作を記録します。 
7. すべてのポジションがターゲットの順序と一致するまで続行します。 結果として生じる一連のスワップが答えです。 

### なぜ効果があるのか

 正しさは、問題をペアのグローバルな合計順序を尊重する順列の構築に縮小することで得られます。 ペアによるソート順序が両方の座標の減少を維持することが検証されると、それからの逸脱は必然的にいずれかの反転を引き起こすことになります。$a$またはで$b$。 構築フェーズは、許可されたスワップを使用してこの順列を実現する制御された方法にすぎません。スワップはあらゆる順列を実現できるため、唯一の実際の制約は、ターゲットの順序が有効かどうかです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        idx = list(range(n))
        idx.sort(key=lambda i: (a[i], b[i]))

        # check feasibility
        ok = True
        for i in range(n - 1):
            if a[idx[i]] > a[idx[i + 1]] or b[idx[i]] > b[idx[i + 1]]:
                ok = False
                break

        if not ok:
            print(-1)
            continue

        # build current permutation
        pos = list(range(n))
        where = list(range(n))
        target = idx[:]

        ops = []

        for i in range(n):
            if where[i] == target[i]:
                continue
            j = pos[target[i]]

            # swap i and j
            x, y = where[i], where[j]
            where[i], where[j] = where[j], where[i]
            pos[x], pos[y] = pos[y], pos[x]

            ops.append((i + 1, j + 1))

        print(len(ops))
        for i, j in ops:
            print(i, j)

if __name__ == "__main__":
    solve()
```コードはまず、ペアの辞書編集的並べ替えを使用して、インデックスの順序付けの候補を構築します。 次に、この順序付けがどちらの配列でも単調性に違反していないことを検証します。 そうなった場合は、直ちに不可能を返します。 

第 2 フェーズは、直接置換の構築です。 配列`pos`そして`where`各インデックスの現在位置と、どのインデックスが各位置にあるかを追跡します。 各スワップ操作は、許可された移動形式に変換されて記録されます。 

ここでの一般的な実装の落とし穴は、スワップのたびに両方の追跡配列を一貫して更新できないことです。 どちらかの場合`pos`または`where`一貫性がなくなると、後のスワップで間違った位置が参照され、構造が破損します。 

## 実用的な例

 ### 例 1

 入力:```
n = 3
a = [3, 1, 2]
b = [3, 2, 1]
```| ステップ | 現在の順序 | アクション |
 | --- | --- | --- |
 | イニシャル | (3,3)(1,2)(2,1) | 開始 |
 | ソートされたターゲット | (1,2)(2,1)(3,3) | 目標順序 |
 | 位置 1 を固定 | インデックス 2 を所定の位置に交換します | (1,2)(3,3)(2,1) |
 | 位置 2 を修正 | インデックス 3 を所定の位置に交換 | (1,2)(2,1)(3,3) |

 これは、スワップがどのようにグローバル順序を徐々に強制するかを示しています。 

### 例 2

 入力:```
n = 2
a = [1, 2]
b = [2, 1]
```並べ替え基準-$a$注文は$(1,2),(2,1)$、しかしこれはすぐに減少を引き起こします$b$。 実現可能性チェックが失敗したため、出力は次のようになります。`-1`。 

これにより、アルゴリズムが矛盾する座標順序を正しく拒否していることが確認されます。

 ## 特殊なケース

 重要なエッジ ケースは、値が一方の座標では等しいが、もう一方の座標では異なる場合です。 例えば：```
a = [1, 1, 2]
b = [3, 2, 1]
```ここで、つながります$a$私たちに完全に依存するよう強制する$b$、 しかし$b$タイブロック内では厳密に減少しています。 実現可能性チェックはこれを検出します。$a$減少していない、$b$ソート後の単調性に違反します。 

もう 1 つのエッジ ケースは、有効な順列が複数存在する場合です。 このアルゴリズムはスワップを最小限に抑えようとするものではなく、正確性を保証するだけであるため、一貫したスワップ シーケンスは許容されます。
