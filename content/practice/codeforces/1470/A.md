 ## 問題の理解

 私たちは、一連の制約の下で友人グループにプレゼントを贈る場合の総コストを最小限に抑えるよう求められています。 各友達には好みのプレゼント番号があり、$k_i$。 プレゼントには番号が付けられています$1$に$m$そして固定費がかかる$c_1 \le c_2 \le \dots \le c_m$。 特定の友人については 2 つの選択肢があります: 数量を超えないプレゼントを購入するか$k_i$または単にその友人に与える$c_{k_i}$直接ドル。 各プレゼントは 1 回のみ購入できます。 目標は、すべての友人の最小合計支出を計算することです。 

入力には最大で次のものを含めることができます$3 \cdot 10^5$テスト ケース全体で累積的に友達やプレゼントを追加します。 この境界により、二次複雑性を伴う解は除外されます。 友達ごとに、すべてのプレゼントを最大まで反復します。$k_i$に達する可能性があるため、遅すぎるでしょう$O(n \cdot m)$最悪の場合の運用。 代わりに、並べ替えや貪欲な割り当てを使用して、友人の数を線形または線形にするアプローチが必要です。 

エッジケースには、複数の友人が低レベルのステータスを持っている状況が含まれます。$k_i$価値観や安いプレゼント、あるいはいつ$k_i$価値観はすでに安価なプレゼントと一致しています。 を考慮せずに、最も安価なプレゼントを不用意に貪欲に割り当てます。$k_i$制限を超えると使いすぎる可能性があります。 たとえば、友達全員が好む場合$k_i = 1$ただし、最も安いプレゼントはリストの最後にあるため、入手可能な最も安いものを盲目的に選択すると制約に違反します。 

## アプローチ

 強引な方法は、各友人を反復処理し、それぞれの友人からのすべてのプレゼントをスキャンすることです。$1$に$k_i$最も安価な未割り当てのプレゼントを選択します。 これは原理的には正しいですが、明らかに遅すぎます。 もし$n$そして$m$両方とも周りにいます$3 \cdot 10^5$、スキャン$O(k_i)$それぞれの友人が簡単に連絡できるように$10^{10}$操作。 

より迅速な解決策の重要な観察は、より大きな番号のプレゼントを受け入れる友人のほうがより柔軟であるということです。 逆に小さいものは、$k_i$値の選択肢が少なくなります。 友人を次の基準で分類することでこれを悪用できます。$k_i$降順で残りの最も安いプレゼントをより高い友達に割り当てます。$k_i$。 私たちは、最も高価なプレゼントを喜んで受け取る友人から、最も小さなプレゼントを受け取る友人まで、繰り返し調べます。$k_i$。 各ステップで、入手可能な最も安いプレゼントと贈るものを比較します。$c_{k_i}$直接ドルを入力して最小値を選択します。 これにより、当社が決して違反しないことが保証されます。$k_i$制約があり、より安価なプレゼントを順番に使用することも保証されます。 

このアプローチは、当然のことながら、友人の数とソートのステップを加えた線形のツーポインターまたは貪欲な方法につながります。$O(n \log n)$。

 ## アルゴリズムのチュートリアル

 1. 各テストケースについて、友人の数を読み取ります。$n$、プレゼントの数$m$、お気に入りのプレゼントの数々$k$、そして費用$c$プレゼントの。 
2. 友達を並べ替える$k_i$降順で。 これにより、より高価なプレゼントを喜んで受け入れる友人が最初に処理されるため、制限に違反することなく、より安価なプレゼントを割り当てることができます。 
3. ポインタを初期化する`p`0 で次に安いプレゼントを追跡します`c`。 
4.初期化`total_cost`0として。 
5. 各友人を降順で反復処理します。$k_i$注文:

 ａ． この友人の直接コストを次のように計算します。$c[k_i - 1]`. b. If the pointer `p` is within bounds (`p < m`) and the present `c[p]` is cheaper than $c[k_i - 1]`, assign present `c[p]` and increment `p`。 

c. それ以外の場合は友達にあげてください$c[k_i - 1]$直接ドル。 

d. 選択したコストを追加します`total_cost`。 
6. すべての友達を処理した後、出力します`total_cost`。 

なぜ効果があるのか​​: より高いレベルを受け入れようとする友人を処理することによって$k_i$まず、最も安価なプレゼントが最も柔軟な友人に贈られることを保証します。 もっと小さい友達なら誰でも$k_i$プレゼントは安いものから順に使用し、限度額を超えることはありませんので、限度額を超えるプレゼントを強制されることはありません。$k_i$。 ポインタ`p`各プレゼントが最大 1 回割り当てられることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        k = list(map(int, input().split()))
        c = list(map(int, input().split()))
        
        k.sort(reverse=True)
        p = 0
        total_cost = 0
        for ki in k:
            direct_cost = c[ki - 1]
            if p < m and c[p] < direct_cost:
                total_cost += c[p]
                p += 1
            else:
                total_cost += direct_cost
        print(total_cost)

if __name__ == "__main__":
    solve()
```コードは、テスト ケースの数を読み取ることから始まります。 各テスト ケースの内容は次のとおりです。`n`、`m`、友達の好みのプレゼント、プレゼントにかかる費用。 の`k`配列は、より高価なプレゼントを受け取ることができる友人を優先するために降順にソートされます。 ポインタ`p`どのプレゼントが使用されたかを追跡します。 友人ごとに、範囲内で入手可能な最も安いプレゼントと直接の金額のどちらかを選択します。 選択は累積に追加されます`total_cost`。 各テスト ケースが必要な出力形式と一致した後で合計を出力します。 微妙な点としては、`ki - 1`Python でのゼロベースのインデックス作成と境界チェックの調整`p < m`。
