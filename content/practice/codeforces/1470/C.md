 ## 解決策
 ## 問題の理解

 私たちにはサークルがあります$n$選手、それぞれの持ち場$k$カード。 毎ターン、各プレイヤーはカードの半分を左に、半分を右に配り、必要に応じて四捨五入します。 このルールを破り、代わりにすべてのカードを右側のプレイヤーに渡す詐欺師がいます。 目的は、特定のプレイヤーが現在何枚のカードを持っているかを尋ねる一連のクエリによって詐欺者を特定することです。 各クエリの後、すべてのプレイヤーはこれらのルールに従って 1 つの動きを実行します。 

この問題は対話型です。つまり、プログラムは移動シーケンスを注意深く尊重しながら、クエリの出力と応答の読み取りを交互に行う必要があります。 まで$10^5$選手たちと$k$まで$10^9$、すべてのプレイヤーの各ターンを明示的にシミュレートするソリューションは遅すぎます。 の限界$1000$クエリにより、時間の経過とともに各プレイヤーの進化を総当たり的に検査することなく、詐欺師を効率的に隔離する戦略が制約されます。 

単純な実装では、すべてのプレイヤーに繰り返しクエリを実行したり、すべてのターンのカードの動きをシミュレートしたりする可能性があります。 たとえば、次の場合$n = 6$そして$k = 4$、通常のシャッフルに従って各プレイヤーのカードの数が毎ターン変化することは想像できますが、次の方法では詐欺師を十分に早く捕まえることはできません。$1000$queries. エッジ ケースには、最初または最後にクエリされたプレーヤーの隣に詐欺師がいることや、単純な線形チェックが失敗するような円の回り込みが含まれます。 

微妙な点の 1 つは、最初のクエリの後、後続のすべてのカード カウントには詐欺師の効果が含まれていることです。 したがって、最初の測定値は均一です ($k$）、偏差は最初の動きの後にのみ表示されます。 

## アプローチ

 ブルートフォース手法では、複数ターンにわたる各プレイヤーのカードの動きをシミュレートし、予想される正規分布と観察されたカウントを比較します。 プレイヤーの値が予想される伝播パターンから逸脱している場合、そのプレイヤーは詐欺師であると疑われます。 正規分布は予測可能であるため、これは機能しますが、$n = 10^5$、各ターンに必要な$O(n)$詐欺師を見分けるには数百回の動きが必要になる可能性があります。 これでは制限時間を軽く超えてしまいます。 

重要な観察は、詐欺師が常にカードを右に押すことで、円に沿って蓄積効果​​が生じるということです。 1 つの位置を繰り返しクエリすると、最終的にカード数は予測可能な方法で変動します。つまり、詐欺師の右隣が余分なカードを受け取り、パターンが時計回りに伝播します。 このプロパティを使用すると、予想されるカードの広がりに比例した間隔で円をサンプリングする一連のクエリによって、詐欺師を検出できます。 逸脱は偽者から単調に伝播するため、円上の二分探索が適用可能になり、異常の位置を効率的に特定できるようになります。 

最適なアプローチでは、戦略的にクエリを実行し、連続する観察間の差異を追跡します。 隣接する位置で連続するターン間のカード数の増加を比較することで、過剰なカードが到着する方向を特定できます。 これにより、偽者を特定できるようになります。$O(\log n)$クエリ数は 1000 クエリ制限内に十分収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * t) | O(n) | 遅すぎる |
 | 最適 | O(log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレーヤーにクエリを実行することから始めます$1$シャッフルを開始します。 応答は$k$そしてベースラインとして機能します。 
2. 連続する 2 つのポジションのスライディング ウィンドウを維持します。 変更を追跡するには、そのうちの 1 つを繰り返しクエリします。 詐欺師はカードを右に押すため、詐欺師の右隣の人だけが異常な増加を確認します。 
3. 新しい応答をそれぞれ前の応答と比較します。 カードの数が予想される半分の分割を超えて増加する場合、質問されたプレイヤーの左隣のプレイヤーが詐欺師である可能性があります。 
4. 円に対して修正された二分探索を使用します。 最後に観察された異常から円のおよそ半分の位置を選択します。 カードがベースラインを超えているかどうかをクエリして確認します。 「はい」の場合、偽者は左側のセグメントにいます。 それ以外の場合、それらは正しいセグメントにあります。 
5. このプロセスを繰り返し、候補が 1 つだけ残るまでセグメントを絞り込みます。 このプレイヤーを偽者として出力します。 

不変条件は、詐欺師が常に時計回りに動く余剰カードの根源であるということです。 最初の増加がどこで発生するかを観察し、セグメントの二分探索を続行することで、クエリごとに候補セットが約半分に減少することが保証されます。 これにより、正確性とクエリ制限内での終了が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def query(pos):
    print(f"? {pos}")
    sys.stdout.flush()
    return int(input())

def solve(n, k):
    left, right = 1, n
    baseline = query(1)  # first query
    prev = baseline
    
    while left < right:
        mid = (left + right) // 2
        val = query(mid)
        if val > k:
            right = mid
        else:
            left = mid + 1
        prev = val

    print(f"! {left}")
    sys.stdout.flush()

if __name__ == "__main__":
    n, k = map(int, input().split())
    solve(n, k)
```の`query`関数は対話型の入出力を処理します。 位置の最初のクエリ`1`シャッフルを初期化します。 二分検索では、現在のセグメントの中点を繰り返しクエリし、カード カウントが予想される通常のカウントから最初に逸脱する場所を追跡します。`k`。 中間点を選択すると、反復ごとに検索スペースが半分になります。 アイドル状態のタイムアウトを避けるために、クエリのたびにフラッシュします。 

## 実用的な例

 のために`n = 4, k = 2`詐欺師と一緒に`2`、最初のクエリは戻ります`[2]`。 最初の移動後のカウントは次のようになります。`[1, 4, 2, 1]`。 順番にクエリを実行すると、次のようになります。 

| クエリ | プレーヤー | カード | 注 |
 | --- | --- | --- | --- |
 | 1 | 1 | 2 | ベースライン |
 | 2 | 1 | 1 | 1 減少、詐欺師の左側 |
 | 3 | 2 | 4 | 不審な増加、詐欺師の権利 |
 | 4 | 3 | 2 | 通常 |
 | 5 | 4 | 1 | 通常 |

 最初に観察された増加の左側のプレイヤーとして偽者を検出し、プレイヤーを確認します`2`。 

より大きな円に向けて`n = 6, k = 4, p = 5`、クエリする`[1, 3, 5]`明らかにする`[4, 4, 8]`1回移動した後。 プレイヤー側の超過分`5`詐欺師がプレイヤーであることを示します`5`。

 ## 特殊なケース

 最初の位置にいる詐欺師の場合、`n=6, k=4`、プレイヤーに問い合わせ中`1`収量`[4]`。 1 回移動した後のカウントは次のようになります。`[0, 4, 4, 2, 2, 2]`。 プレイヤーでの増加を観察する`2`詐欺師がすぐ左側にいることを確認します。 アルゴリズムはプレーヤーでのラップアラウンドを正しく処理します`n`二分探索では円をモジュール的に考慮するためです。 同様に、詐欺師が最後の位置にいるとき、プレイヤーのカードの蓄積は`1`が検出され、偽者がプレイヤーとして正しく識別される`n`。 この伝播特性により、アルゴリズムはすべての位置に対して堅牢です。
