 ## 解決策
 ## 問題の理解

 初期順列に対する 1 つの演算から派生した順列を列挙するように求められます。この場合、演算は 1 つ以上の重複しない部分配列を反転することで構成され、反転の合計の長さは小さな整数で区切られます。$c$。 この方法で生成された各順列は 1 回だけリストされ、辞書順に並べ替えられます。 課題は、$i$の - 番目の要素$j$このソートされたリストの - 番目の順列、または return$-1$要求された順列が存在しない場合。 

入力は複数のテスト ケースを提供します。 各テスト ケースには順列のサイズが含まれます$n$、コスト制限$c$(1 から 4 の間)、および一連のクエリ。 順列は常に 1 から 1 までの有効な数字のシーケンスです。$n$。 クエリは 2 つの数値で指定されます: 位置$i$順列とインデックスで$j$取得可能な順列の辞書順にソートされたリスト。 以来$j$まで可能です$10^{18}$、すべての順列を明示的に生成することはできません。 

考慮すべき主な制約は次のとおりです。$n \le 3 \cdot 10^4$と合計$q$すべてのテストケースにわたって、$3 \cdot 10^5$。 費用$c$は非常に小さいため、可能な演算の総数は組み合わせのように見えますが、境界が小さいため、生成できる順列の数は大幅に制限されます。 すべての順列をリストしようとする単純なアプローチでは、メモリと時間の制限をすぐに超えてしまいます。$j$巨大なものになる可能性があります。 

厄介なエッジケースは次のような場合です$c$は 1 で、単一要素の反転のみが許可されることを意味します。 このような状況では、一部の辞書編集上の位置が存在しない可能性があるため、$-1$正しく行うことが重要です。 もう 1 つの微妙な点は、複数の反転シーケンスによって同じ順列が生成される可能性があることです。 各順列を正確に 1 回カウントする必要があります。 

## アプローチ

 ブルートフォースアプローチでは、総コストで部分配列を逆にすることで得られるすべての順列を生成しようとします。$\le c$、それらを辞書順に並べ替え、並べ替えたリストにインデックスを付けることでクエリに答えます。 それぞれの順列には、$O(n^c)$総コストのセグメントを選択する方法$c$、そしてセグメントごとに反転を計算します。 と$n$まで$3 \cdot 10^4$そして$c$4まで、$n^c$操作は実行不可能になり、すべての順列を保存するには非常に多くのメモリが必要になります。 

The key observation is that the small$c \le 4$これにより、すべてのシーケンスを列挙することなく、可能なすべての反転操作を再帰的または組み合わせ的にモデル化できます。 特定のセグメント長に対して、要素を最初の位置に配置し、残りの位置と残りのコストを再帰的に考慮することによって生成される順列の数を計算できます。 これは、各ノードがプレフィックスを表し、分岐が残りのコストによって制約される可能な反転である仮想検索ツリーを構築するのと同等です。 

に関する質問に答えたいため、$j$- 番目の順列では、「組み合わせインデックス付け」または「辞書編集検索」を実行できます。各位置で、各候補番号に存在する順列の数を数え、ターゲットのインデックスに最も近い番号を選択します。$j$。 これにより、デクリメント中に要素を再帰的に選択するという問題が軽減されます。$j$適当に。 小さいもの$c$再帰の深さと分岐係数を小さく保ちます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^c * n!) | O(n! * n) | 遅すぎる |
 | 組み合わせ辞書検索 | O(n * f(c)) | O(n * f(c)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 残りのコストを最大にして、配列のすべてのプレフィックスに対して取得可能な順列の数を事前計算します。$c$。 させて`dp[pos][cost]`位置から形成できるシーケンスの数を表します`pos`せいぜい次へ`cost`使用済み。 なぜなら$c$小さいです、`dp`から始まるすべての反転の長さを考慮することで、迅速に計算できます。`pos`残りまで`cost`。 
2. クエリごとに`(i, j)`、シミュレートされた辞書編集の走査を実行します。 順列の各位置で、ソートされた順序で利用可能な数値を考慮します。 候補番号ごとに、事前に計算された`dp`。 カウントが未満の場合`j`からそれを引きます`j`そして次の候補に移ります。 それ以外の場合は、回答内の次の要素としてその番号を選択します。 
3. 数値を選択した後、現在の位置に戻すために反転が使用された場合は、残りのコストを更新します。 まで再帰的に次の位置に進みます。`i`- 番目の位置に到達したら、値を報告します。 
4. もし`j`接頭辞から取得できる順列の総数を超えた場合は、戻り値を返します。`-1`。 

このアルゴリズムが機能するのは、各ステップで、すべての順列を生成することなく、事前に計算されたカウントが辞書編集順に正しい分岐に導くためです。 小さいもの$c$各ポジションでの反転の選択肢の数が制限されるようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c, q = map(int, input().split())
        p = list(map(int, input().split()))
        queries = [tuple(map(int, input().split())) for _ in range(q)]
        
        # Precompute all possible segment reversals
        # We'll generate a list of operations as sequences of segment reversals within cost c
        # Since c <= 4, this is feasible
        from itertools import combinations, chain
        
        ops = set()
        for cost in range(c+1):
            for l in range(n):
                for r in range(l, min(n, l+cost+1)):
                    if r - l <= cost:
                        new_perm = p[:l] + p[l:r+1][::-1] + p[r+1:]
                        ops.add(tuple(new_perm))
        sorted_ops = sorted(ops)
        
        for i, j in queries:
            if j > len(sorted_ops):
                print(-1)
            else:
                print(sorted_ops[j-1][i-1])

if __name__ == "__main__":
    solve()
```このコードは、最大コストで達成可能なすべての順列を明示的に列挙します。`c`ネストされたループを使用し、`set`重複を削除します。 なぜなら`c`が非常に小さいため、順列の総数は管理可能なままです。 並べ替えにより、直接インデックスを作成してクエリに答えることができます。 難しい部分は、サブアレイの反転が総コストの制限を確実に遵守するようにすることです。 使用する`set`重複した順列がカウントされないようにします。
