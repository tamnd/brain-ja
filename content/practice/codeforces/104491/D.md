 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、その連続するセグメントを繰り返し調べますが、長さが偶数のセグメントのみを調べます。 このような各セグメントは、2 つの等しい半分に分割されます。 各半分の最大値のみを検査します。 これら 2 つの最大値の差が十分に小さい場合、具体的には最大でも$k$、このセグメントを「良好」と呼びます。 

適切な長さのセグメントごとに$2m$, we do not simply count it. 代わりに、左半分の右端点、つまり位置を取得します。$i + m - 1$、配列内のその位置の値を確認し、10 を加算してシフトし、事前に計算された重みを乗算します。$f_m$。 最終的な答えは、すべての良好なセグメントに対するこれらの寄与の合計です。 

シーケンス$f$任意ではありません。 線形項と乗法項の両方を含む非線形漸化式によって定義されるため、その値は急速に増大するため、事前に計算された定数モジュロとして扱う必要があります。$998244353$。 

ここでは制約が実際の信号です。 すべてのテスト ケースの合計配列サイズは最大です。$5 \cdot 10^5$、テスト ケースの数は次のように大きくなる可能性があります。$10^4$。 この組み合わせでは、すべてのサブセグメントを明示的にスキャンするアプローチは除外されます。 ナイーブ$O(n^2)$テスト ケースごとに列挙すると、すぐに制限時間を超えてしまいます。 平$O(n \log n)$極端に最適化しない限り、テスト ケースごとにリスクが高まります。 

主な問題点は、各候補セグメントが 2 つの半分に対して最大のクエリを必要とし、これを可能な限り多くの長さに対して実行する必要があることです。 どのようなソリューションでも、最大値を繰り返し再計算することは避けなければなりません。 

微妙なエッジケースが現れるのは、$k = 0$。 この場合、2 つの半最大値が正確に等しいセグメントのみを受け入れます。 これにより、値が繰り返される配列内に重複する有効なセグメントが多数作成される傾向があり、単純なカウント手法では、セグメントのエンドポイントを必要なインデックスに適切に整列させないため、二重にカウントしたり、寄与を見逃したりすることがよくあります。$i + m - 1$。 

もう 1 つの特殊なケースは、すべての値が等しい場合です。 その場合、すべてのセグメントは良好であり、答えは純粋にセグメント構造の組み合わせカウントと固定位置の寄与に依存しますが、中間点を慎重に扱わないと位置がずれやすくなります。 

## アプローチ

 ブルートフォース ソリューションでは、考えられるすべての開始インデックスに対して反復処理が行われます。$i$、その後、可能な限りすべての偶数の長さ$2m$、両方の半分の最大値を直接計算します。 それぞれの最大コストを単純に計算する$O(m)$, したがって、合計は最悪の場合3次になります。 半分ごとにスライディング ウィンドウの最適化を行ったとしても、最終的にはおよそ$O(n^2)$テスト ケースあたりのセグメント数は非常に遅すぎます。$5 \cdot 10^5$合計要素。 

ボトルネックは、重複するウィンドウにわたって最大のクエリが繰り返されることです。 各セグメントはその構造の大部分を隣接するセグメントと共有するため、最大値を個別に再計算するのは無駄です。 

重要な観察は次のとおりです$k \le 10$、「最大値の差が小さい」という条件を強く制約します。 すべてのセグメントを同等に扱う代わりに、最大値付近の潜在的な値の範囲を固定し、有効なセグメントには緊密にクラスター化された最大値が必要であるという事実を利用できます。 これは、スライディング ウィンドウの最大構造を維持し、中間点構造によってセグメントをグループ化することを示唆しています。 

問題を再構成することもできます。各セグメントはその中点の境界によって決まります。$i + m - 1$。 中間点を固定すると、その中間点で終わる左のウィンドウとその直後から始まる右のウィンドウが事実上ペアになることになります (どちらも長さは異なります)。$m$。 これにより、長さごとに 2 つの単調デキューを維持したり、最大制約を段階的に追跡しながら各中間点の周りを拡張することで寄与をより効率的に処理したりすることができます。 

慎重な前処理により、最大値を制御しながら左右にどこまで伸ばせるかについての情報を位置ごとに維持します。 これにより、問題はセグメントの列挙から、それぞれが固定式項に寄与する各中間点の周囲の有効な展開を数えることに軽減されます。

 ## アルゴリズムのチュートリアル

 私たちは、2 つの等しい長さの隣接するブロックの最大値を比較するだけでよいという事実を利用します。 これにより、考えられる各中間点を中心に計算を行うことができます。 

### ステップ

 1. シーケンスを事前計算する$f[i]$まで$n$。 

これが必要なのは、有効なセグメントがすべて半長であるためです。$m$要因に寄与する$f_m$。 再帰モジュロを使用して一度計算します$998244353$。 
2. ポジションごとに$c$配列では、セグメントの左半分の右端として扱います。 

この位置は中点構造を一意に定義します。左半分は次の位置で終了します。$c$、右半分は から始まります$c+1$。 
3. から外側に拡張する$c$左右同時に、両方の半分の最大値を維持して増加します$m$。 

2 つの実行最大値を追跡します。1 つは左側のウィンドウ用です。$[c-m+1, c]$そして右側のウィンドウ用に 1 つ$[c+1, c+m]$。 

拡張ステップごとに増加します$m$1までに。 
4. ウィンドウが配列の境界を超えた場合、または 2 つの最大値の差が超えた場合、拡張を停止します。$k$。 

条件が失敗すると、さらに大きくなります$m$ウィンドウを拡張しても最大値を増やすことしかできないため、有効性を回復することはできません。 
5. 特定の条件が満たされるたびに$m$、貢献を追加します$(a_c + 10) \cdot f_m$答えに。 
6. すべての有効なセンターに対してこのプロセスを繰り返します。$c$、結果を剰余として累積する$998244353$。 

### なぜ効果があるのか

 重要な不変条件は、固定中心の場合です。$c$、長さの両方の半分の正しい最大値を維持します。$m$拡大していきます。 すべてのステップで、アルゴリズムは 1 つあたり 1 つの有効なセグメントを考慮します。$(c, m)$、すべての偶数長のセグメントに一意の中間点インデックスがあるため、セグメントが欠落することはありません。$c = i + m - 1$。 この拡張により、可能な限りすべてのことが保証されます。$m$は再計算せずに昇順でテストされ、最大値の単調な性質により、違反後の早期終了時に正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def precompute_f(n):
    f = [0] * (n + 2)
    if n >= 1:
        f[1] = 3240 % MOD
    if n >= 2:
        f[2] = 3081 % MOD
    if n >= 3:
        f[3] = 2841 % MOD
    if n >= 4:
        f[4] = 343 % MOD

    for i in range(5, n + 1):
        f[i] = (f[i-1] * 223 +
                f[i-2] * 229 +
                f[i-3] * f[i-4] * 239 +
                17) % MOD
    return f

def solve():
    t = int(input())
    data = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        data.append((n, k, a))

    max_n = max(n for n, _, _ in data)
    f = precompute_f(max_n)

    out = []

    for n, k, a in data:
        ans = 0

        for c in range(n):
            left_max = a[c]
            right_max = a[c]

            m = 1
            while c - (m - 1) >= 0 and c + m < n:
                if m > 1:
                    left_max = max(left_max, a[c - (m - 1)])
                    right_max = max(right_max, a[c + (m - 1)])

                if abs(left_max - right_max) <= k:
                    ans = (ans + (a[c] + 10) * f[m]) % MOD
                else:
                    break

                m += 1

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()

テストケースごとに、考えられるすべての中点位置を反復します。$c$。 各中点は、2 つの半分の間の境界を定義します。 外側に対称に拡張し、半分の長さを増やします$m$一歩ずつ。 左の最大値は、新しく追加された左の要素を使用して更新され、右の最大値は同様に、対応する右の要素を使用します。 

停止条件は非常に重要です。 最大差を超えると$k$、両方の半分が増加するだけであり、最大値は単調非減少であるため、さらに拡張しても妥当性を復元できません。 これにより、内側のループを早期に終了できます。 

有効な各構成は、中点要素から導出された値に寄与します。$a[c]$セグメント全体からではなく、事前に計算された重みを乗算します。$f[m]$。

 ## 特殊なケース

 配列の要素が 1 つの場合、有効な偶数長のセグメントがないため、答えは 0 になります。 長さ 1 のハーフペアを形成できる中間点がないため、アルゴリズムは拡張ループに入ることはありません。 

すべての値が同一の場合、すべての拡張はすべての拡張に対して有効なままになります。$m$境界線まで。 最大値は常に両方の半分で等しいため、アルゴリズムはすべての中間点とすべての有効な長さの寄与を正しく累積します。 

いつ$k = 0$、有効性は最大値が正確に等しいかどうかによって決まります。 新しい要素によって不均衡が生じると、拡張は直ちに中断されます。 単調更新により、一度不均衡が発生すると持続または悪化するため、無効なセグメントがカウントされることはありません。 

値が高値と低値の間で変動すると、最大値の発散が急速に発生します。 アルゴリズムは中間点ごとに早期に終了し、二次爆発を防ぎながら、少数の有効な短いセグメントを正しく評価します。
