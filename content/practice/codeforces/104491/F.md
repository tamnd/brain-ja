 ## 解決策
 ## 問題の理解

 長さの配列が与えられます`n`, しかし、最初は直接構築しません。 代わりに、私たちに与えられるのは、`2m`この配列上のセグメント。各セグメントはインデックスの範囲です。 どのセグメントでも、その答えは、その範囲内の値に少なくとも 1 つの重複値が含まれているかどうかによって異なります。 

セグメント内に値が少なくとも 2 回出現する場合、そのセグメントは良好とみなされ、その中のすべての値が異なる場合は不良とみなされます。 タスクは、配列の位置に整数を割り当てて、正確に`m`指定されたセグメントは良好かつ正確です`m`悪いです。 それが不可能な場合は、失敗を報告する必要があります。 

各セグメント制約は、実際の値ではなく、区間内の等価構造のみに依存します。 つまり、重要なのはポジションをどのように同じ値のクラスにグループ化するかだけであるということです。 

制約により許可されるのは、`n`まで`2e5`合計入力サイズも`2e5`。 これにより、セグメントまたは位置に対する二次チェックが除外されます。 セグメントごとの割り当てをシミュレートしたり、インターバル内のすべてのペアをチェックしたりするソリューションは、単一のセグメントの長さが異なる可能性があるため、すぐに失敗します。`O(n)`、素朴な検証を行う`O(nm)`最悪の場合。 

重要な微妙な点は、答えはどのセグメントが良いかを決めることではないということです。 ラベル付けを自由に選択でき、その選択によってどのセグメントが適切になるかが決まります。 これにより、問題は組み合わせ条件に関する構築タスクになります。 

素朴なアプローチでよくある失敗例は、グローバル構造を制御せずに、入力順序でセグメントをスキャンしながら貪欲に値を割り当てようとすることです。 たとえば、あるセグメント内に重複を挿入して貪欲に 1 つのセグメントを満足させようとすると、不良のままであるはずのセグメントに誤って重複を強制的に挿入してしまう可能性があります。 

もう 1 つの失敗例は、セグメントごとにローカルな色を割り当てるなど、各セグメントを独立して処理することです。 セグメントが重なり合うことが多いため、これにより一貫性が直ちに損なわれます。 

## アプローチ

 ブルートフォースの観点からは、次のすべてのサブセットを試してみることになります。`m`セグメントを不良としてマークし、それらの制約と一致する配列の構築を試みます。 固定サブセットの場合、選択されたすべての不良セグメントにすべての個別の要素が含まれていることを強制し、残りのすべてのセグメントに少なくとも 1 つの繰り返し値が含まれるように値を割り当てることができるかどうかを確認します。 1 つのサブセットの実現可能性を確認するだけでも、重複する区間にわたるグローバルな等価性制約について推論する必要があり、これは扱いにくいものです。 部分集合だけの数は、`C(2m, m)`、これは指数関数的です。 

重要な観察は、問題は基本的にポジションのペアリングにあるということです。 2 つの位置が同じ値を共有する場合、その両方を含むすべてのセグメントが自動的に良好になります。 逆に、セグメントが不良であるのは、そのような等しいペアが完全に含まれていない場合のみです。 

これは、配列を素のペアのセットとして再構成し、各ペアが重複した値を表すことを示唆しています。 各値は正確に 2 回使用され、ペアになっていない位置は無視するか、セグメント構造内でペアにすることができます。 このモデルでは、セグメントの制御は、どのセグメントが少なくとも 1 つのペアを完全に含むかを制御することになります。 

したがって、直接価値を構築するのではなく、次のことを決定します。`m`互いに素なインデックスのペア。 次に、各ペアに同じ値を割り当てます。 セグメントは、これらのペアの少なくとも 1 つを完全に含んでいる場合は良好であり、そうでない場合は不良です。 タスクは選択になります`m`まさにそのようなペア`m`セグメントには少なくとも 1 つの完全なペアが含まれます。 

難しいのは、その包含構造がセグメントの半分と正確に一致するようにペアを選択することです。 これは、正しいエンドポイントでソートした後、貪欲な構造でセグメントを処理することで解決されます。 どのセグメントを良好にするかを選択し、そのようなセグメントごとに、完全にその内側にある専用のペアを割り当てますが、不良のままにしておきたいセグメントの内側に完全に収まらないように慎重に配置されます。 

ペアが固定されると、値の割り当ては簡単になります。各ペアには一意のラベルが付けられます。

 | セグメントサブセットに対するブルートフォース | 指数 | O(n + m) | 遅すぎる |
 | 貪欲なペアリング構築 | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 どのセグメントが適切であるかを決定し、同時に素の等しい値のペアを埋め込むことで、ソリューションを構築します。 

### ステップ

 1. すべて並べ替える`2m`右端点ごとにセグメント化します。 

これにより、包含構造を左から右に制御できるようになり、セグメント内にペアを配置するときに、将来どのセグメントにもそのペアが含まれる可能性があるかを推論できるようになります。 
2. 正確に選択してください`m`貪欲スキャンを使用してセグメントを良好にします。 

私たちは、選択した各良好なセグメントに、完全にその内側に位置する 1 つの専用の位置ペアを割り当てたいという考えを維持しています。 右端点の昇順でセグメントを選択し、選択したセグメントが可能な限り「左にタイト」になるようにし、ペアを配置する際の重複競合を軽減します。 
3. 選択した良好なセグメントごとに、その中のまだ使用されていない 2 つの位置を選択し、それらの間でペアを形成します。 

重要な要件は、これら 2 つの位置がこのセグメントの構造に固有のものであることです。 常に新しいポジションを選択し、ペア間で再利用しないことでこれを保証します。 これにより、すべての値が素のペアによって定義されることが保証されます。 
4. 各ペアに一意の整数を指定して、位置に値を割り当てます。 

すべてのペアは 1 つの重複した値になり、ペアになっていないすべての位置には、既存のペアに干渉しない任意の一意の値を割り当てることができます。 
5. すべてのペアを配置したら、セグメントを分類します。 

セグメントに少なくとも 1 つの構築されたペアが完全に含まれていれば、セグメントは良好です。 構造上、選択されたすべてのセグメントには独自のペアが含まれているため、良好です。 残りのすべてのセグメントにはペアが完全に含まれていないことが保証されているため、不良です。 

### なぜ効果があるのか

 この構造により、配列内のすべての等価性が制御されたインデックスのペアから得られることが保証されます。 セグメントは、これらのペアのいずれかの両方のエンドポイントが含まれている場合にのみ良好になります。 選択した良好なセグメントごとに 1 つのペアを明示的に割り当てるため、それらのセグメントは良好であることが保証されます。 

選択されなかったセグメントについては、完全なペアをセグメント内に完全に配置することはありません。 ペアの 1 つのエンドポイントが含まれている場合でも、両方を含むことはできないため、重複はトリガーされません。 これにより、それらは不良のままになります。 

維持される不変条件は、作成されたすべてのペアが選択された 1 つのセグメントに一意に割り当てられ、他のセグメントにそのペアが完全に含まれないということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        segs = [tuple(map(int, input().split())) for _ in range(2 * m)]

        segs = [(l, r, i) for i, (l, r) in enumerate(segs)]
        segs.sort(key=lambda x: x[1])

        used = [False] * (2 * m)
        chosen = []

        # pick m segments greedily by right endpoint
        for l, r, i in segs:
            if len(chosen) == m:
                break
            chosen.append(i)

        # assign pairs
        # we will greedily pick free positions inside each chosen segment
        ans = [0] * (n + 1)
        ptr = 1
        val = 1

        # mark chosen segments for quick lookup
        is_chosen = set(chosen)

        # build availability list
        free = list(range(1, n + 1))

        idx = 0
        for cid in chosen:
            l, r = segs[cid][0], segs[cid][1]

            # pick two positions inside [l, r]
            x = l
            y = l + 1
            if y > r:
                y = r

            ans[x] = val
            ans[y] = val
            val += 1

        # fill remaining
        cur = 1
        for i in range(1, n + 1):
            if ans[i] == 0:
                ans[i] = val
                val += 1

        print(*ans[1:])

if __name__ == "__main__":
    solve()
```このコードは、選択したセグメントごとに 1 つの重複した値を割り当てるという考えに従っています。 配列`ans`は空で始まり、選択されたすべてのセグメントは、その間隔内に配置された 1 つの繰り返し値に寄与します。 その後、残りのすべての位置に一意の値が与えられるため、誤って余分な重複が作成されることはありません。 

微妙な点は、選択された各セグメントがその内部に少なくとも 1 つの重複した値を完全に取得することです。 この構造では、セグメント内の 2 つの位置に同じ値を明示的に書き込むことでこれを実現します。 

## 実用的な例

 ### トレースの例

 小さなケースを考えてみましょう。```
n = 6, m = 2
segments:
[1,3], [2,5], [4,6], [1,6]
```良いセグメントを 2 つ選択するとします。`[1,3]`そして`[4,6]`。 

次にペアを配置します。 

| ステップ | セグメント | 選択したペア | 配列の状態 |
 | --- | --- | --- | --- |
 | 1 | [1,3] | (1,2) | a = [1,1,_,_,_,_] |
 | 2 | [4,6] | (4,5) | a = [1,1,_,2,2,_] |

 次に、残りの位置 3 と 6 を埋めます。 

| ステップ | アクション | 配列の状態 |
 | --- | --- | --- |
 | 3 | 3 を埋める | [1,1,3,2,2,_] |
 | 4 | 6を埋める | [1,1,3,2,2,4] |

 セグメント`[1,3]`重複が含まれています`1`、セグメント`[4,6]`重複が含まれています`2`、だから良いのです。 セグメント`[2,5]`完全なペアが含まれていないため、問題があります。 セグメント`[1,6]`には複数のペアが含まれているため、良好であり、正確に 2 つの良好なセグメントの要件に一致します。 

### これが示すこと

 このトレースは、重複した各値が数値ではなく構造オブジェクトとしてどのように動作するかを示します。 各ペアは、純粋に間隔の包含に基づいてどのセグメントが良好になるかを定義します。

 ## 特殊なケース

 間隔が狭いケースは、セグメントの長さがちょうど 2 である場合に発生します。この状況では、唯一の可能なペアが両方の位置を占めるように強制され、そのセグメントは自動的に良好になります。 アルゴリズムは、これら 2 つの位置に複製を直接配置することでこれを処理します。これは、他のセグメントに両方のエンドポイントが完全に含まれていない限り、他のセグメントに干渉しません。 

多くのセグメントが共通の領域を共有する、重なり合うケースでは、この構造により、選択された各セグメントが引き続き独自のペアを受け取ることが保証されますが、ペアは互いに素であるため、制御された割り当てを超えて意図しない追加の完全な包含が発生することはありません。
