 ## 解決策
 ## 問題の理解

 ほぼツリーのように動作する接続されたグラフが与えられますが、いくつかのサイクルが含まれており、すべてのエッジがそれらのサイクルの最大 1 つに属している点が異なります。 追加の制限は、すべてのサイクルが非常に小さく、実際には常に三角形であることです。 

タスクは単一のパスを見つけることではなく、パスが正確に一致するように、指定された 2 つの頂点間に存在する異なる単純なパスがいくつあるかを数えるということです。$k$エッジ。 異なるパスは、開始点と終了点が同じであっても、途中で異なる頂点またはエッジを使用する場合、異なるものとみなされます。 

この制約は十分に大きいため、ソリューションで明示的にパスを列挙したり、クエリごとに検索を実行しようとすると失敗します。 まで$2 \cdot 10^5$頂点とクエリも$O(n)$クエリごとの速度はすでに遅すぎます。 グラフはまばらですが、クエリの数により、一定のサイズの構造を構築した後、対数または定数時間で各クエリに応答する前処理ベースのソリューションが必要になります。$O(n)$。 

微妙な難しさはサイクルに起因します。 ツリーでは、任意の 2 つの頂点間に単純なパスが 1 つだけ存在するため、長さが一致するかどうかに応じて、答えは 1 または 0 になります。 ここでは、三角形によって分岐が導入されています。パスが三角形に入るときは常に、1 つのエッジを直接横切るか、3 番目の頂点を通る 2 段階の迂回を選択する必要があります。 これにより、同じエンドポイント間に複数の単純なパスが作成されますが、その場所は非常に制御された場所に限られます。 

よくある失敗例は、グラフ内またはスパニング ツリー内でさえもパスの一意性を想定していることです。 

たとえば、単一の三角形について考えてみましょう。$1-2-3-1$。 から$1$に$2$、単純なパスが 2 つあります。1 つは長さ 1 (直接エッジ)、もう 1 つは長さ 2 (頂点 3 経由) です。 単純な DFS は通常、これらの 1 つだけをカウントするか、サイクル選択を明示的にモデル化していない場合、パス長を誤って混合します。 

より長いルートに沿って複数の三角形を結合する場合、別の問題が発生します。 有効なパスの数は乗算的に増加しますが、それは構造化された方法でのみ増加し、ステップごとに分岐して指数関数的に増加するわけではありません。 

## アプローチ

 ブルートフォースアプローチでは、間の単純なパスをすべて列挙しようとします。$s$そして$f$そして長さが次のものを数えます$k$。 サボテンの場合でも、単純なパスの数がルート上の三角形の数に応じて指数関数的に増加する可能性があります。 各三角形は二分決定を導入するため、パスが通過します。$t$三角形はすでに以下を暗示しています$2^t$亜種。 と$t$潜在的に直線的$n$、これはすぐに実行不可能になります。 

重要な構造的観察は、グラフにはサイクルがありますが、そのサイクル構造はツリー状であるということです。 各エッジは最大 1 つのサイクルに属し、サイクルが複雑に重なり合うことはありません。 これにより、グラフをコンポーネントのツリー (ブロック構造またはブロックカット ツリーと呼ばれることが多い) に圧縮できます。 

この圧縮された構造では、元の頂点はすべてコンポーネントのシーケンスに属し、任意の 2 つの頂点間にはコンポーネント ツリー内に一意のパスが存在します。 複数のパスの複雑さは、三角形コンポーネントの内部に完全に押し込まれています。 

三角形の内側、任意の 2 つの頂点の間には、長さ 1 のルートと長さ 2 のルートの 2 つの単純なルートがあります。これは、すべての三角形が、パス上の他の三角形から独立して、単一の 2 値選択に寄与することを意味します。 

これにより、問題は、$s$そして$f$、そのうちのいくつが三角形であるかを数え、どの三角形を「迂回」するかを選択できる方法が何通りあるかを決定します。 各迂回により、パスの長さはちょうど 1 だけ増加します。 

コンポーネントツリー内のパスに次のものが含まれている場合、$t$三角形コンポーネントの場合、すべての単純なパスはこれらの三角形のサブセットの選択に対応します。 私たちが選ぶなら$x$三角形を迂回すると、経路の合計の長さは$x$。

 | コンポーネントツリー + 組み合わせ論 |$O((n+q)\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 グラフをツリー構造に変換し、サイクルが特別なノードになります。 その後、すべてのクエリは、ツリー上の単純なパス クエリと組み合わせカウント ステップになります。 

### 1. グラフをブリッジとトライアングルに分解します。 

まず、どのエッジが三角形の一部で、どのエッジがブリッジであるかを特定します。 サボテン グラフでは、すべての非ブリッジ エッジが 1 つの三角形に属します。 低リンク値を持つ標準の DFS はブリッジを識別します。 ブリッジではないエッジはすべてサイクル上に存在する必要があり、すべてのサイクルの長さは 3 であるため、そのサイクルは一意に決定されます。 

各三角形について、個別のコンポーネントとして記録します。 

### 2. コンポーネントツリーを構築する

 片側が元の頂点で構成され、もう一方の側がコンポーネントで構成される 2 部ツリーを構築します。 各ブリッジは、その 2 つのエンドポイントに接続されたコンポーネントになります。 各三角形は、その 3 つの頂点に接続されたコンポーネントになります。 

元のすべてのサイクルが単一のノードに分離されており、変換されたグラフにはサイクルが存在しないため、この構造はツリーです。 

### 3. LCA とパス集計を事前計算する

 コンポーネント ツリーを任意にルート化し、最低共通祖先クエリのバイナリ リフティング テーブルを計算します。 

深さとともに、ルートから各ノードまでに出現する三角形コンポーネントの数をカウントするプレフィックス値を維持します。 

これにより、任意のパスで計算できるようになります。 

対数時間での成分の数と三角形の成分の数。 

### 4. 各クエリを処理する

 お問い合わせの場合$(s, f, k)$間のパスを計算します。$s$そして$f$LCA を使用してコンポーネント ツリーに表示されます。 

させて：

-$B$パス上のコンポーネントの数になります
 -$T$パス上の三角形コンポーネントの数になります

 すべてのコンポーネントは 1 エッジの基本コストに影響します。 内部の長いルートを選択した場合、すべての三角形で追加のエッジが 1 つ許可されます。 

それで:

 - 最小パス長 =$B$- 各三角形は +1 を追加できます
 - 合計の余分な長さは、迂回する三角形の数を選択することによって決まります。 

必要なものは次のとおりです。$$k - B = x$$正確に選択する方法$x$三角形の外$T$、つまり:$$\binom{T}{x}$$### なぜ効果があるのか

 コンポーネント ツリーにより、コンポーネント間の構造ルートが 1 つだけ存在することが保証されます。$s$そして$f$。 元のグラフのあいまいさはすべて、三角形コンポーネントの内部に局在化されています。 各三角形の内部で、2 つの可能なルートは 1 つの余分なエッジだけが異なり、他の三角形とは相互作用しません。 この独立性により、合計カウントは、パス上の三角形ごとに 1 つずつ、独立した 2 値の選択肢に因数分解されます。 LCA 構造により、一意のパス上のコンポーネントを正確にカウントし、その外側には何もカウントしないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

MOD = 998244353

# ----------------------------
# Combinatorics
# ----------------------------
def build_ncr(n):
    fact = [1] * (n + 1)
    inv = [1] * (n + 1)
    ifact = [1] * (n + 1)

    for i in range(2, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    inv[1] = 1
    for i in range(2, n + 1):
        inv[i] = MOD - MOD // i * inv[MOD % i] % MOD

    for i in range(2, n + 1):
        ifact[i] = ifact[i - 1] * inv[i] % MOD

    def C(n, r):
        if r < 0 or r > n:
            return 0
        return fact[n] * ifact[r] % MOD * ifact[n - r] % MOD

    return C

# ----------------------------
# DSU for bridge/triangle building
# (we use DFS for bridges)
# ----------------------------
n, m = map(int, input().split())
g = [[] for _ in range(n)]

edges = []
for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append((v, len(edges)))
    g[v].append((u, len(edges)))
    edges.append((u, v))

# ----------------------------
# Find bridges (Tarjan)
# ----------------------------
tin = [-1] * n
low = [0] * n
timer = 0
is_bridge = [False] * m

def dfs(v, pe):
    global timer
    tin[v] = low[v] = timer
    timer += 1

    for to, eid in g[v]:
        if eid == pe:
            continue
        if tin[to] != -1:
            low[v] = min(low[v], tin[to])
        else:
            dfs(to, eid)
            low[v] = min(low[v], low[to])
            if low[to] > tin[v]:
                is_bridge[eid] = True

dfs(0, -1)

# ----------------------------
# Build adjacency again, classify edges
# ----------------------------
tree_adj = [[] for _ in range(n + m)]
node_id = 0

# vertex nodes: 0..n-1
# component nodes: n..n+m-1 (we'll assign selectively)
comp_id = n

comp_nodes = [None] * m  # edge -> component node id or None

for eid, (u, v) in enumerate(edges):
    if is_bridge[eid]:
        cid = comp_id
        comp_id += 1
        comp_nodes[eid] = cid

        tree_adj[cid].append(u)
        tree_adj[u].append(cid)
        tree_adj[cid].append(v)
        tree_adj[v].append(cid)
    else:
        cid = comp_id
        comp_id += 1
        comp_nodes[eid] = cid

        tree_adj[cid].append(u)
        tree_adj[u].append(cid)
        tree_adj[cid].append(v)
        tree_adj[v].append(cid)

# ----------------------------
# LCA on component tree
# ----------------------------
N = comp_id
LOG = (N).bit_length()

up = [[-1] * N for _ in range(LOG)]
depth = [0] * N
is_tri = [0] * N
pref_tri = [0] * N

# mark triangle nodes (degree 3 component nodes in this construction are triangles)
for cid in range(n, N):
    deg = len(tree_adj[cid])
    if deg == 3:
        is_tri[cid] = 1

def dfs2(v, p):
    up[0][v] = p
    for to in tree_adj[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        pref_tri[to] = pref_tri[v] + is_tri[to]
        dfs2(to, v)

dfs2(0, -1)

for i in range(1, LOG):
    for v in range(N):
        if up[i - 1][v] != -1:
            up[i][v] = up[i - 1][up[i - 1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]

    i = 0
    while diff:
        if diff & 1:
            a = up[i][a]
        diff >>= 1
        i += 1

    if a == b:
        return a

    for i in reversed(range(LOG)):
        if up[i][a] != up[i][b]:
            a = up[i][a]
            b = up[i][b]

    return up[0][a]

def path_tri(a, b):
    c = lca(a, b)
    return pref_tri[a] + pref_tri[b] - 2 * pref_tri[c]

def path_len(a, b):
    c = lca(a, b)
    return depth[a] + depth[b] - 2 * depth[c]

C = build_ncr(2 * 10**5 + 5)

q = int(input())
for _ in range(q):
    s, f, k = map(int, input().split())
    s -= 1
    f -= 1

    # convert vertex to node
    # vertices are nodes in same tree
    base = path_len(s, f)
    t = path_tri(s, f)

    need = k - base
    print(C(t, need))
```この実装は、元の頂点とコンポーネント ノードを交互に配置する単一のツリーを構築することに依存しています。 ブリッジとトライアングルはどちらも中間ノードになりますが、さらなる柔軟性に寄与するのはトライアングル ノードのみです。 このツリーに対する LCA クエリは、パス長と三角形数の両方を対数時間で示します。これは、完全な入力サイズには十分です。 

最もデリケートな部分は、三角形のコンポーネントが正しく識別され、LCA に使用されるのと同じルート構造でプレフィックスの合計が計算されるようにすることです。

 ## 特殊なケース

 唯一の構造として使用される三角形は、重要な組み合わせメカニズムをすでに明らかにしています。 単一の三角形では、コンポーネント ツリーには三角形ノードが 1 つだけ含まれます。$T = 1$。 アルゴリズムは基底長を 1 として計算し、可能性のある両方のパスを正しくカウントします。$k$。 

純粋なツリー (サイクルなし) では、すべてのエッジが強制的にブリッジになるため、$T = 0$。 この場合、答えが 1 になるのは次の場合のみです。$k$は木の距離に等しく、それ以外の場合は 0 です。結合式は自然にこの動作に崩壊します。$\binom{0}{0} = 1$他のすべての値はゼロです。 

三角形のチェーンは、複数のサイクル コンポーネントにわたって独立性が保持されていることを確認します。 各三角形は 1 つの二項決定に寄与し、アルゴリズムは干渉することなくすべての三角形の組み合わせをカウントし、明示的に列挙することなく、予想される可能性の指数関数的な増加に対応します。
