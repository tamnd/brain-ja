 ## 解決策
 ## 問題の理解

 整数線上のセグメントのコレクションが与えられます。 各セグメントは、「放出」できる値の範囲を記述しており、重みも持っています。 これらのセグメントから、元の順序でいくつかのサブシーケンスを選択します。 

サブシーケンスが固定されたら、選択したすべてのセグメントに独自の範囲から具体的な整数を割り当てます。 これにより、一連の整数が生成されます。 非減少シーケンスを形成するようにこれらの整数を選択できる場合、シーケンスは有効であると見なされます。 

すべての有効なサブシーケンスの中で、必要なものが 2 つあります。 まず、選択したセグメントの重みの最大合計です。 次に、その最大重みに達するサブシーケンスの数 (998244353 を法とする)。 

主な問題点は、有効性が、セグメントのエンドポイント自体だけではなく、選択したセグメントに互換性のある値を割り当てられるかどうかによって決まることです。 単純に解釈すると、これが標準的な重み付き部分列問題であると思われるかもしれませんが、実現可能性は間隔を非減少割り当てに連鎖できるかどうかによって決まります。 

この制約により、すべてのテスト ケースにわたって最大 20 万のセグメントを処理する必要があるため、すべてのサブシーケンスを試行したり、セグメントに対して 2 次動的計画法を実行したりするソリューションは直ちに不可能になります。 テスト ケースごとにほぼ線形または線形に近い動作が必要です。通常は次のようなものです。$O(n \log m)$。 

微妙な特殊なケースは、実現可能性がペアごとの重複だけでは決定されないことです。 互換性のない中間値を選択すると、2 つの間隔が重複しても、より長いチェーンでは失敗する可能性があります。 たとえば、$[1,2]$、$[2,3]$、$[1,1]$この順序は無効です。ペアごとのオーバーラップが存在する場合でも、最後の間隔により以前の割り当ての後にドロップが強制されるためです。 

正しい見解は、実現可能性は、制約を尊重しながら貪欲に値を割り当てられるかどうかにかかっており、これにより、最後の間隔だけではなく、現在選択されている値を追跡する状態が得られるということです。 

## アプローチ

 ブルート フォース アプローチでは、セグメントのすべてのサブシーケンスを試し、実行可能性をチェックするために貪欲に値を割り当てようとします。 長さの部分列の場合$k$、実現可能性のチェックは線形です$k$したがって、全体として、これは指数関数的になります。$n$、の注文で$2^n \cdot n$、それは限界をはるかに超えています。 

主な構造上の観察は、サブシーケンスの順序を固定すると、実現可能性は単一の「現在の値」を維持することになるということです。 選択したセグメントを処理するとき$[l_i, r_i]$、常に最小の有効な値を選択できます。$\max(l_i, \text{current})$。 失敗する唯一の方法は、この値が超過した場合です$r_i$。 これにより、実現可能性が 1 つのパラメータ (現在の値) を持つステート マシンに変換されます。 

これは、DP 状態が位置だけでなく、現在の値も含まれる重み付きサブシーケンス選択を行っていることを意味します。$[1, m]$。 遷移は、セグメントがスキップされるか取得されるか、また取得される場合には現在の値がどのように変換されるかによって異なります。 

全体的にナイーブなDP$n \times m$状態はまだ遅すぎるため、値の範囲にわたって遷移を一括して処理する必要があります。 各セグメントは、現在の値の範囲に対して 2 つの動作のみを引き起こします。これにより、範囲の更新とプレフィックス クエリによるセグメント ツリー ベースの最適化が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot n)$|$O(n)$| 遅すぎる |
 | DP over (i, 値) |$O(nm)$|$O(m)$| 遅すぎる |
 | セグメントツリーの最適化された DP |$O(n \log m)$|$O(m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 選択したセグメントを処理した後、「現在の値」を超える DP を維持します。 させて`dp[x]`現在の値が正確に一致する場合、達成可能な最良の総重量を保存します。`x`、それを達成するためのさまざまな方法も併せて説明します。 

セグメントを選択する前にシステムを初期化します。現在の値は事実上 1 で、合計の重みは 0 です。 

### ステップ

 1. 値に対してセグメント ツリーを初期化します。$1 \ldots m$。 各ノードはペアを保存します$(\text{best weight}, \text{count})$。 セット`dp[1] = (0, 1)`そして他のすべての人に$-\infty$。 
2. セグメントを入力順に処理します。 各セグメントごとに$[l, r]$重さで$c$、現在の構造を更新することで新しい DP を構築します。 
3. まず、現在の値が存在する状態のセグメントを取得することを検討します。$(l, r]$。 現在の値が$x$この範囲内では、次の値が残ります$x$と単純に追加します$c$総重量に。 これが機能する理由は、$x \ge l$、したがって、選択される値は次のようになります$x$、実現可能性は保たれます。 の範囲加算を実行します$c$以上$(l, r]$。 
4. 次に、現在の値が最大である状態を検討します。$l$。 このようなすべての状態について、セグメントを取得した後の次の値は次のようになります。$l$少なくともセグメントの左端まで上げる必要があるためです。 これらすべての状態の中で、セグメントを取得する前に達成可能な最適な重みが必要であるため、プレフィックスの最大値をクエリします。$[1, l]$。 
5.追加$c$この最適なプレフィックス値に設定し、それを使用して状態を更新します$l$の既存の値の間の最大値を取ることにより、$l$そして今回の新候補者。 等しい場合は、ウェイの数を合計します。 
6. すべての更新が現在の構造の上に適用されるため、以前の DP を変更せずに引き継ぐことによって、暗黙的にセグメントをスキップすることもできます。 
7. すべてのセグメントを処理した後、DP をスキャンして、すべての状態の最大値と、それを達成する状態の合計数を見つけます。 

### なぜ効果があるのか

 DP の不変条件は、セグメントのプレフィックスを処理した後、`dp[x]`最終的に構築された値が正確に一致するすべての有効なサブシーケンスの中で、達成可能な最良の重みを正確に表します。`x`。 すべての遷移では、現在の値の状態を通じてモノトーン構築ルールが明示的に適用されるため、実現可能性が維持されます。 セグメント ツリーにより、更新ルールに従って均一に動作する範囲全体に遷移が常に適用されるため、状態が部分的に更新されたり、誤って更新されたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
NEG = -10**30

class SegTree:
    def __init__(self, n):
        self.n = n
        self.mx = [NEG] * (4 * n)
        self.cnt = [0] * (4 * n)
        self.lz = [0] * (4 * n)

    def _apply(self, idx, val):
        self.mx[idx] += val
        self.lz[idx] += val

    def _push(self, idx):
        if self.lz[idx]:
            v = self.lz[idx]
            self._apply(idx * 2, v)
            self._apply(idx * 2 + 1, v)
            self.lz[idx] = 0

    def _pull(self, idx):
        if self.mx[idx * 2] > self.mx[idx * 2 + 1]:
            self.mx[idx] = self.mx[idx * 2]
            self.cnt[idx] = self.cnt[idx * 2]
        elif self.mx[idx * 2] < self.mx[idx * 2 + 1]:
            self.mx[idx] = self.mx[idx * 2 + 1]
            self.cnt[idx] = self.cnt[idx * 2 + 1]
        else:
            self.mx[idx] = self.mx[idx * 2]
            self.cnt[idx] = (self.cnt[idx * 2] + self.cnt[idx * 2 + 1]) % MOD

    def build(self, idx, l, r):
        if l == r:
            if l == 1:
                self.mx[idx] = 0
                self.cnt[idx] = 1
            else:
                self.mx[idx] = NEG
                self.cnt[idx] = 0
            return
        m = (l + r) // 2
        self.build(idx * 2, l, m)
        self.build(idx * 2 + 1, m + 1, r)
        self._pull(idx)

    def range_add(self, idx, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            self._apply(idx, val)
            return
        self._push(idx)
        m = (l + r) // 2
        if ql <= m:
            self.range_add(idx * 2, l, m, ql, qr, val)
        if qr > m:
            self.range_add(idx * 2 + 1, m + 1, r, ql, qr, val)
        self._pull(idx)

    def query_max(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.mx[idx], self.cnt[idx]
        self._push(idx)
        m = (l + r) // 2
        best = NEG
        ways = 0
        if ql <= m:
            v, c = self.query_max(idx * 2, l, m, ql, qr)
            if v > best:
                best, ways = v, c
            elif v == best:
                ways = (ways + c) % MOD
        if qr > m:
            v, c = self.query_max(idx * 2 + 1, m + 1, r, ql, qr)
            if v > best:
                best, ways = v, c
            elif v == best:
                ways = (ways + c) % MOD
        return best, ways

    def point_chmax(self, idx, l, r, pos, val, ways):
        if l == r:
            if val > self.mx[idx]:
                self.mx[idx] = val
                self.cnt[idx] = ways % MOD
            elif val == self.mx[idx]:
                self.cnt[idx] = (self.cnt[idx] + ways) % MOD
            return
        self._push(idx)
        m = (l + r) // 2
        if pos <= m:
            self.point_chmax(idx * 2, l, m, pos, val, ways)
        else:
            self.point_chmax(idx * 2 + 1, m + 1, r, pos, val, ways)
        self._pull(idx)

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        segs = [tuple(map(int, input().split())) for _ in range(n)]

        st = SegTree(m)
        st.build(1, 1, m)

        for l, r, c in segs:
            if l <= r:
                st.range_add(1, 1, m, l + 1, r, c)
                best, ways = st.query_max(1, 1, m, 1, l)
                if best != NEG:
                    st.point_chmax(1, 1, m, l, best + c, ways)

        ans_val, ans_cnt = st.query_max(1, 1, m, 1, m)
        print(ans_val, ans_cnt % MOD)

if __name__ == "__main__":
    solve()
```セグメント ツリーには、達成可能な最大の重みと、その最大値を達成する方法の数の両方が保存されます。 遅延伝播は、範囲の追加にのみ使用されます。これは、セグメントを取得した後に現在の値が変更されないままになる状態の遷移に正確に対応します。 

プレフィックス クエリは、単一の値に集約されるすべての状態をキャプチャするため、必須です。$l$セグメントを取得した後。 ポイント更新は$l$これらの貢献を正しくマージします。 

よくある落とし穴は、プレフィックス全体に均一な更新を適用しようとすることですが、これらの状態は 1 つの宛先に集約されるため、更新する前にまず集約する必要があります。 

## 実用的な例

 ### 例 1

 セグメントを考慮してください。$[1,2], c=1$、$[2,3], c=2$値 1 ～ 3 にわたって dp を追跡します。 

| ステップ | セグメント | アクション | dp 状態の概要 |
 | --- | --- | --- | --- |
 | 0 | 初期化 | dp[1]=0 | (1:0) |
 | 1 | [1,2] | prefix=0 → 更新 1、範囲追加 | (1:1、2:1) |
 | 2 | [2,3] | prefix(1..2)=1 → dp[2]=3、3 に加算 | (1:1、2:3、3:3) |

 最終的な答えは 1 通りの 3 です。 

これは、範囲の追加とプレフィックスの縮小がどのように相互作用するかを示しています。状態 1 はプレフィックスを介して 2 に伝播し、その後、中間範囲の状態とは異なる形で進化します。 

### 例 2

 セグメント:$[1,1], c=3$、$[1,2], c=3$| ステップ | セグメント | アクション | dp 状態の概要 |
 | --- | --- | --- | --- |
 | 0 | 初期化 | dp[1]=0 | (1:0) |
 | 1 | [1,1] | プレフィックス=0 → dp[1]=3 | (1:3) |
 | 2 | [1,2] | prefix=3 → dp[1]=6、2 に加算 | (1:6、2:6) |

 どちらの状態も同じ最適値を達成し、両方ともカウントに寄与します。 

これは、複数の状態が同じ最大値にどのように収束するのかを強調しており、等しい最大値を慎重にカウントする必要があります。

 ## 特殊なケース

 重要なエッジケースは、すべてのセグメントが同じ値の範囲を共有する場合です。 DP は、二重にカウントすることなく、同じ最終状態につながる複数の方法を正しく累積する必要があります。 セグメント ツリーのマージ ロジックにより、値が等しい場合にのみカウントが合計されるようになります。 

もう 1 つの微妙なケースは、セグメントの左端が 1 の場合です。この場合、すべての状態は直接状態 1 に集約され、プレフィックス クエリはアクティブな範囲全体に及びます。 アルゴリズムは常にクエリを実行することでこれを正しく処理します。$[1, l]$、そのシナリオでは完全な DP になります。 

最後に、プレフィックス クエリで到達可能な状態がない場合、最適な値が残ります。$-\infty$となり、ポイント更新はスキップされます。 これにより、到達不能な設定が DP に無効に伝播されるのを防ぎます。
