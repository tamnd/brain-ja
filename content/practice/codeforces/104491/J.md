 ## 解決策
 ## 問題の理解

 私たちには非常に大きなものが与えられています$k \times k$すべてのセルに頂点が含まれるグリッド。 各セルからは通常、コストを払って隣接する 4 つのセルに移動できます。$1$したがって、2 つのセル間の基本距離がマンハッタン距離になります。 

このグリッドの上には、$n$特別な「高速橋」。 各ブリッジは 2 つの異なるセルを接続します$(x_1,y_1)$そして$(x_2,y_2)$、そしてそれを使用すると、具体的にはマンハッタンの距離を歩くよりも1つ安くなります$|x_1-x_2| + |y_1-y_2| - 1$。 これは、通常の歩行と比較して、橋を使用するとちょうど 2 分の 3 を節約できることを意味します。$1$最短パスの一部として使用される場合。 

タスクは、この変更されたグラフ内のすべての順序付けされていないセルのペア間の最短経路距離の合計を計算することです。 

制約$k \le 10^9$セルを反復したり、グリッド構造を明示的に保存したりするアプローチは直ちに除外されます。 グリッドは概念的には完全ですが、計算上はそれを連続的な組み合わせオブジェクトとして扱う必要があります。 橋の数はせいぜい少ない$500$、これは、次のようなアルゴリズムが含まれることを示唆しています。$O(n^2)$あるいは$O(n \cdot \text{poly}(1))$橋を越えるという推論はもっともらしいですが、状況に応じて何でも構いません。$k$直接的にはそうではありません。 

素朴なアプローチでは、グラフ上のすべてのペアの最短経路を次のように計算します。$k^2$ノードが存在しますが、単一の最短パスの計算さえもサイズの関係で不可能です。 セルのペアごとに推論しようとしても不可能です。$O(k^4)$ペア。 

ブリッジが存在しない場合、微妙なエッジケースが発生します。 その場合、答えは純粋にグリッド内のすべてのペアにわたるマンハッタン距離の合計になります。 もう 1 つのエッジ ケースは、複数のブリッジの影響が重なっている場合です。セルのペアは複数のブリッジから恩恵を受ける可能性がありますが、最短パスは構造化された一連のブリッジを利用することしかできず、ジオメトリを考慮せずにブリッジを任意に組み合わせることができないため、節約は単純な方法では相加的ではありません。 単純に「各ブリッジが独立して使用するすべてのペアに対して 1 を減算する」とすると、節約額が誤って二重にカウントされます。 

## アプローチ

 開始点は、橋を無視し、グリッド内のすべてのセルのペアにわたるマンハッタン距離の合計を計算することです。 これは純粋な組み合わせ量です。 長さの 1D ラインの場合$k$、すべての順序なしペアにわたる距離の合計は次のようになります。$$\sum_{i<j} (j-i) = \frac{k^3 - k}{6}.$$グリッドでは、マンハッタン距離は x 成分と y 成分に分割され、対称性により次元を独立して扱うことができます。 各 x 距離の寄与は、y ペアのすべての選択肢に対してカウントされ、逆も同様で、基本的な結果が得られます。$$\text{Base} = 2 \cdot k^2 \cdot \frac{k^3 - k}{6}.$$次に橋について考えてみましょう。 各ブリッジは距離を正確に短縮します$1$2 つのエンドポイント間の最短パスで実際に使用される場合。 したがって、最短パスをグローバルに再計算する代わりに、問題を次のように再解釈します。$$\text{Answer} = \text{Base Manhattan Sum} - \sum_{\text{bridges}} (\text{number of pairs whose shortest path uses this bridge}).$$重要な観察は、ブリッジが恣意的なグローバル再ルーティングを作成しないことです。 これは、2 つのセル間のマンハッタンの最短パスが両方の端点を正しい幾何学的順序で通過する必要がある場合にのみ問題になります。 その場合、中央のセグメントをブリッジに置き換えることで、ちょうど 1 つのユニットを節約できます。 

これにより、ブリッジごとにペアの数を数えるという問題が軽減されます。$(u,v)$からのマンハッタンの最短経路であるという特性を持っています。$u$に$v$両方のエンドポイントを順番に通過します。 これは、端点によって決定される軸に沿った長方形に対する純粋に幾何学的な計数問題です。 

なぜなら$n \le 500$、各ブリッジの寄与を独立して計算できます。$O(1)$、全体的な$O(n)$基本式を修正します。

 ## アルゴリズムのチュートリアル

 答えは 2 段階で計算されます。つまり、マンハッタンの合計を計算し、次に橋から寄与分を差し引きます。 

### 1. グリッド上の基本合計を計算します。 

1. 長さの 1D 直線上の距離の合計を計算します。$k$:$$S_1 = \sum_{i<j} (j-i) = \frac{k^3-k}{6}.$$2. x と y の寄与を分離してグリッドに拡張します。 各 x 距離は次とペアになります。$k^2$y 座標の選択、および y 距離の場合も同様です。 
3. マンハッタンの合計は次のようになります。$$\text{Base} = 2 \cdot k^2 \cdot S_1.$$このステップは、マンハッタン距離が独立した軸間で加算され、ペアのカウントがきれいに因数分解されるため機能します。 

### 2. 各橋をユニット節約イベントとしてモデル化する

 各ブリッジは 2 つのポイントを接続します$A=(x_1,y_1)$そして$B=(x_2,y_2)$。 仮定する$x_1 < x_2$。 幾何学的なケースは 2 つあります。$y_1 < y_2$または$y_1 > y_2$。 

一対の細胞$(u,v)$この橋は、マンハッタンからマンハッタンへの最短経路を通る場合にのみ使用できます。$u$に$v$両方のエンドポイントを順番に通過します。 これにより、$u$にまたがる長方形に対して 1 つの隅の領域に位置する$A$そして$B$、 そして$v$反対側のコーナー領域に位置します。 

具体的には、グリッドは長方形の角を基準にして 4 つの単調領域に分割され、有効なペアは 2 つの対向する角から得られます。 このような各ペアは、正確に 1 つの保存ユニットに貢献します。 

### 3. ブリッジごとに有効なペアを数える

 各ブリッジについて:

 1. 比較して方向性を決定する$y_1$そして$y_2$。 
2. 「入口」領域にあるグリッド点の数を計算します。$U$、パスが最初に到達できるコーナーです$A$単調性を損なうことなく。 
3. 「出口」領域にあるポイントの数を計算します。$V$、通過後の有効な目的地が含まれる反対側の角$B$。 
4. 貢献を追加する$2 \cdot |U| \cdot |V|$、無向ペア設定での順序付けされた使用の両方向を説明します。 

### 4. 最終的な答え

 マンハッタンの基本合計からすべての橋の負担金の合計を引きます。 

### なぜ効果があるのか

 重要な不変条件は、ブリッジが 2 つのエンドポイント間の単調なマンハッタン パスのセグメントを置き換える場合、ブリッジは最短パスにのみ影響を与えることができるということです。 グリッド内の最短パスは各座標で単調であるため、x 座標と y 座標の相対的な順序によって、パスが迂回せずに両方の端点を通過できるかどうかが完全に決まります。 これにより、ブリッジのすべての有効な使用が固定された対向する長方形のペアに制限され、各ブリッジの寄与数が独立します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def main():
    n, k = map(int, input().split())
    
    bridges = []
    for _ in range(n):
        x1, y1, x2, y2 = map(int, input().split())
        bridges.append((x1, y1, x2, y2))

    # 1D sum of distances on [1..k]
    # sum_{i<j} (j-i) = (k^3 - k) / 6
    s1 = (k * k * k - k) // 6 % MOD

    base = (2 * (k % MOD) * (k % MOD) % MOD * (k % MOD) % MOD * s1) % MOD

    total = 0

    for x1, y1, x2, y2 in bridges:
        # ensure x1 < x2 already guaranteed
        if y1 < y2:
            # bottom-left to top-right structure
            u = (x1) * (y1)
            v = (k - x2 + 1) * (k - y2 + 1)
        else:
            # top-left to bottom-right structure
            u = (x1) * (k - y1 + 1)
            v = (k - x2 + 1) * (y2)

        total = (total + 2 * u % MOD * v % MOD) % MOD

    ans = (base - total) % MOD
    print(ans)

if __name__ == "__main__":
    main()
```コードは、1D ペア和への閉形式リダクションを使用してマンハッタン和を計算することから始まります。 重要な実装の詳細は、中間のオーバーフローを避けるために乗算の最終段階でのみ適用されるモジュラー演算です。 

各ブリッジは独立して処理されます。 このロジックは、端点の垂直方向の順序に応じて平面を 1 組の長方形に分割し、有効な入口領域と出口領域にあるグリッド点の数を数えます。 係数 2 は、順序なしペアのカウントにおける対称性を説明します。 

よくある落とし穴は、最短のパスや鎖橋をシミュレートしようとすることです。 各橋は純粋なマンハッタン形状に対する単一ユニットの改善として独立して貢献するため、これは不要です。

 ## 特殊なケース

 ブリッジがない場合、アルゴリズムは完全に閉形式のマンハッタン和になります。 計算ではブリッジ処理が完全に無視され、基本式が直接出力されるため、無効なジオメトリにアクセスしたり、修正を適用したりするリスクはありません。 

橋がグリッドの境界近くにある場合、次のようになります。$(1,1)$に$(k,k)$、入口領域と出口領域のサイズは完全な象限に折りたたまれます。 カウント式は各軸に沿ったプレフィックスとサフィックスのサイズのみに依存するため、依然として適用されます。これらのサイズは境界であっても有効です。 

複数のブリッジがジオメトリ内で重なっている場合でも、それらは個別に処理されます。 2 つのブリッジがエンドポイントを共有したり領域を交差したりした場合でも、各補正はそのブリッジの単一ユニットの節約を一意に有効にする最短パス構造を持つペアのみをカウントするため、それらの寄与は干渉しません。
