 ## 解決策
 ## 問題の理解

 同じ規模の 2 つのチームが与えられ、各プレーヤーは固定のスキル値を持っています。 試合は、最初のチームのすべてのプレーヤーと 2 番目のチームの 1 人の異なるプレーヤーを組み合わせることによって形成されるため、その組み合わせは 2 番目のチームのインデックスの順列になります。 

このようなペアの場合、すべての試合を調べて、ペアになったプレーヤー間の絶対的なスキルの差を計算します。 ペアリング全体の品質は、最も弱い一致によって決まります。これは、すべてのペアにわたる絶対差の最小値を取ることを意味します。 目標は、この最も弱い試合を可能な限り強力にする組み合わせを構築することです。 

簡単に言うと、合計の差や平均の差を最大化しようとしているわけではありません。 私たちは「近すぎる」一致を避けるよう努めています。 最も類似したペアであっても可能な限り異なるように順列を調整したいと考えています。 

制約は十分小さいため、両方の配列をソートし、テスト ケースごとに線形または線形に近い作業を実行するだけで十分です。 すべてのテストにわたる n の合計は最大 3000 であるため、テスト ケースごとの O(n^2) 解はすでに安全であり、O(n log n) 解は快適に最適です。 

単純な間違いは、関係が減ると考えて、最も近い値を貪欲に一致させることです。 これは実際には逆のことを行います。最も近い値をペアにすることにより、局所的な差異は最小限に抑えられますが、他の場所では少なくとも 1 つの非常に小さなギャップが生じることがよくあります。 もう 1 つの誤った直感は、個々の違いを貪欲に最大化しようとすることです。これにより、1 つのペアが非常に接近せざるを得なくなる構成に陥る可能性もあります。 

たとえば、次のように考えてみましょう`a = [1, 10, 20]`、`b = [2, 11, 21]`。 貪欲に最も近いものを一致させると、違いが生じます`1, 1, 1`したがって、最小値は 1 になります。しかし、これより良い配置はここでは不可能であり、局所的な選択が大域的な最小値を強く制約していることがわかります。 

問題の核心は、1 つのペアを改善すると、他の部分の最小の差がさらに悪化する可能性があることです。そのため、体系化されたグローバル戦略が必要です。 

## アプローチ

 ブルート フォース ソリューションでは、2 番目のチームのすべての順列を試し、それぞれの最小絶対差を計算します。 これは、考えられるすべての組み合わせを評価するため正しいですが、n 個あります。 順列。 n = 12 の場合でも、これはすでに実行不可能であり、ここでは n が 3000 になる可能性があるため、まったく不可能です。 

より構造化されたアイデアは、何が最小絶対差を決定するかを考えることから生まれます。 候補しきい値 x を固定し、すべてのペアが |a[i] - b[p[i]]| を満たすような完全なマッチングを構築できるかどうかを尋ねるとします。 ≧×。 これを効率的にチェックできれば、最大の x を探すことができます。 

これにより、問題は実現可能性の問題に変わります。 x が固定されると、各要素 a[i] は、≤ a[i] - x または ≥ a[i] + x のいずれかの b の値とのみ一致します。 禁止領域は a[i] の周囲の区間であり、それを完全に避ける必要があります。 

重要な観察は、両方の配列がソートされていることです。 これにより、実現可能性を維持しながら、貪欲に一致を割り当てることができます。 a[i] を順番に処理し、常にそれを有効な最小の有効な b、または最大の有効な b と照合しようとすると、将来の制約が厳しくなるだけなので、正確さを維持できます。 

ただし、二分探索を行わずに最適なペアリングを直接構築する方法については依然として疑問が残ります。 最終的な洞察は、最小ギャップを最大化したいということです。これは、「タイトなインターリーブ」の意味で重複を避ける方法で 2 つの配列を分離することに相当します。 最適な構築は、構造化された方法で 2 つのソートされた配列間のすべての回転を試行することです。b を 2 つの半分に分割し、小さい値が遠い値とペアになるように極値をインターリーブします。 

この問題のより直接的かつ標準的な構成は、両方の配列をソートし、すべての k について a[i] と b[(i + k) % n] のマッチングを試みることです。ただし、すべての k をテストする必要はありません。 代わりに、最適なペアリングは、両方の配列をソートし、最大の分離を保証する制御された巡回シフトで最小値と最大値をペアにすることによって得られます。 

より単純で正しい構築的な戦略は、ソートされた順序で b のすべての可能なシフトを試し、O(n) の最小の差を計算し、最良のシフトを選択することです。 n は合計で最大 3000 なので、O(n^2) で問題ありません。 

これが機能するのは、最小ギャップを悪化させることなく、最適な順列をソートされたシーケンスの巡回シフト アラインメントに変換できるためです。

 ## アルゴリズムのチュートリアル

 1. 配列 a と配列 b の両方をソートします。 絶対的な違いには相対的な順序のみが重要であるため、並べ替えは不可欠です。 
2. インデックス シフト k を修正します。これは、a[i] を b[(i + k) mod n] と照合することを意味します。 これにより、k ごとに有効な順列が生成され、最適なものを含むマッチングの構造化されたサブセットがカバーされます。 
3. 各シフト k について、すべてのペアにわたる最小絶対差を計算します。 これにより、マッチングの品質が直接評価されます。 
4. これらの最小値の最大値を与えるシフト k を追跡します。 これにより、最も近い一致をできるだけ避けるペアリングが選択されます。 
5. 最良のシフトに対応する順列を出力します。 

任意の順列ではなく循環シフトを行う理由は、ソートされた配列が単調な構造を持ち、最適な配置における最悪のペアが常に 2 つの整列されたソートされたシーケンス間の境界に現れるためです。 シフトすると、これらの境界がどこに当てはまるかが変わります。 

### なぜ効果があるのか

両方の配列をソートした後、相対的な順序を尊重して、任意の順列をペアの位置として見ることができます。 最小絶対差は、2 つの並べ替えられたシーケンス間の「隣接する交差点」によって決まります。 巡回シフトは、これらのシーケンスのすべての個別の相対アラインメントを列挙するのに十分です。 これらのアライメントの中で、1 つの交差の改善はインデックスの絶対的な同一性ではなく相対的な順序付けにのみ依存するため、最小ペア距離を増やすことなく最適なペアリングをローテーションに変換できるため、大域最適が達成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort()
        b.sort()

        best_k = 0
        best_val = -1

        for k in range(n):
            cur = 10**18
            for i in range(n):
                diff = abs(a[i] - b[(i + k) % n])
                if diff < cur:
                    cur = diff
                    if cur <= best_val:
                        break
            if cur > best_val:
                best_val = cur
                best_k = k

        res = [b[(i + best_k) % n] for i in range(n)]
        pos = {v: [] for v in b}
        for i, v in enumerate(b):
            pos[v].append(i)

        used = [False] * n
        ans = [0] * n

        for i in range(n):
            target = res[i]
            idx = pos[target].pop()
            ans[i] = idx + 1

        print(*ans)

if __name__ == "__main__":
    solve()
```実装では、最初に両方の配列を並べ替えて、すべての意味のある構造が元のインデックスではなく順序どおりになるようにします。 次に、最初の配列に対する 2 番目の配列のすべての巡回シフトを試行し、各シフトの最小差を評価します。 現在の候補のシフトが最良の候補に勝てない場合、小規模な最適化は早期に中断されます。 

最適なシフトが見つかったら、シフトされた順序の位置を元のインデックスに照合して順列を再構築します。 値は繰り返される可能性があるため、各値のすべてのインデックスをリストに保存し、使用時にポップします。 

実装の微妙な詳細は、b での重複の処理です。 値が異なることが保証されていないため、複数の値を保存せずに値をインデックスに直接マッピングすることはできません。 そのため、値ごとのリストを維持しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、両方の配列のすべての値が同一である場合です。 この場合、すべてのペアの最小差は 0 であり、任意の順列が有効です。 このアルゴリズムは引き続きすべてのシフトを評価し、特別なケースを使用せずに任意の有効なシフトを正確に返します。 

もう 1 つのエッジ ケースは、b に重複が存在する場合です。 値ごとにインデックスを保存するため、各出現箇所は 1 回だけ使用されるため、値が何度も繰り返される場合でも再構築は有効なままになります。 

最後のエッジ ケースは、最適なマッチングが ID シフトではない場合です。 例えば`a = [1, 100, 200]`、`b = [50, 51, 52]`。 恒等度シフトでは最小差は 49 ですが、シフトによりアライメントに応じてこれを維持または改善できます。 このアルゴリズムはすべての循環アライメントを評価し、最適なものを自然に選択します。
