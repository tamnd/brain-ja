 ## 解決策
 ## 問題の理解

 私たちは、文字「v」と「w」のみを含む VwV 言語で書かれた Polycarp のメモを処理するように求められます。 この問題は、単一の「w」が連続する 2 つの「v」と視覚的に同一である可能性があり、連続する「v」自体が「w」を形成する可能性があるために発生します。 私たちの目標は、文字列内のできるだけ少ない文字に下線を引いて、すべての文字が明確になるようにすることです。「w」が「vv」と間違われたり、連続する「v」のペアが「w」と間違われたりすることはありません。 入力は複数のテスト ケースで構成され、各テスト ケースは最大 100 文字の文字列です。 曖昧さをすべて取り除くために、文字列ごとに、下線を引く最小の文字を表す単一の整数を出力する必要があります。 

制約を考慮すると、文字列は短いため、文字列ごとに O(n) アルゴリズムが許容され、より複雑な最適化について心配する必要はありません。 微妙なのは、あいまいさが特定のパターン、つまり 2 つ以上の連続する「v」のシーケンスやすべての「w」でのみ発生することです。 単一の孤立した「v」は決して曖昧ではなく、単一の「w」は常に曖昧です。 不注意な実装では、重複するシーケンスを誤ってカウントする可能性があります。たとえば、「vvv」の両方の「v」に不必要に下線を引いたり、「vwvvwv」のようなパターンで正しいカウントを欠落したりする可能性があります。 

注意すべきエッジ ケースには、全体が「v」で構成された文字列、全体が「w」で構成された文字列、交互パターン、長さ 1 の文字列 (単一の「v」の場合は下線が不要) などがあります。 

## アプローチ

 ブルートフォースアプローチは、長さ 2 以上の考えられるすべての部分文字列をチェックし、曖昧さを解決するために下線をマークすることです。 すべての「w」に下線を引きます。 連続する「v」のペアごとに、そのうちの 1 つに下線を引きます。 これは、「w」または「vv」があいまいなため機能しますが、シーケンスが重複する場合の二重カウントを慎重に避ける必要があります。 最悪の場合の操作数は、t 回繰り返される各文字列の n に比例します。これはここでは実行可能ですが、不必要に複雑になる可能性があります。 

重要な洞察は、あいまいさが長さ 2 以上の連続する 'v' のシーケンスとすべての 'w' でのみ発生するということです。 一連の「v」の隣接する各ペアが潜在的な「w」を形成するため、連続する「v」の各シーケンスは (長さ - 1) の下線を引きます。 各「w」は独立しており、1 つの下線に寄与します。 したがって、文字列を線形にスキャンし、「v」と個々の「w」の実行を数え、下線を合計します。 これにより、潜在的に複雑な重複カウント問題が、より単純かつ高速な単純な線形パスに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 動作しますが、不必要に複雑です。 
| 最適 | O(n) | お(1) | 受け入れられ、きれいです |

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`underlines`ゼロとインデックスへ`i`文字列を左から右にスキャンするにはゼロにします。 
2. その間`i`が文字列の長さより小さい場合は、現在の文字を確認します。 

1.「w」の場合はインクリメントします`underlines`常にあいまいであるため、1 で指定します。 次の文字に移動します。 
2. それが「v」の場合、連続する「v」の数を数え始めます。 変数を初期化する`count_v`0 に設定し、連続する文字が「v」の間はインクリメントします。 
3. 連続する「v」の実行が終了したら、インクリメントします。`underlines`による （`count_v`- 1) 隣接する「v」の各ペアが 1 つのあいまいな位置に寄与するため。 
4.移動`i`連続する「v」を超えて。 
3. 文字列の終わりまで続けます。 
4. 合計を印刷します`underlines`このテストケースでは。 

機能する理由: このアルゴリズムは、「w」と連続する「v」のみが曖昧さを生み出すという不変式に依存しています。 各「w」は 1 回カウントされます。 それぞれの実行`k`連続する 'v' には正確に含まれます`k - 1`「w」と間違われる可能性のある重複したペアとカウント`k - 1`下線を引くと曖昧さがなくなります。 左から右にスキャンすることで、一連の「v」が 1 つのパスで処理され、二重カウントは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    n = len(s)
    underlines = 0
    i = 0
    while i < n:
        if s[i] == 'w':
            underlines += 1
            i += 1
        elif s[i] == 'v':
            count_v = 0
            while i < n and s[i] == 'v':
                count_v += 1
                i += 1
            if count_v >= 2:
                underlines += count_v - 1
    print(underlines)
```この実装では、各文字を 1 回だけ処理します。 連続する「v」は、重複するペアの二重カウントを避けるために慎重にカウントされます。 各「w」は独立してインクリメントされます。 の`strip()`末尾の改行が長さの計算に影響しないようにします。 の`while`ループを使用すると、ネストされたループを使用するのではなく、スキャン実行を効率的に行うことができます。 

## 実用的な例

 サンプル入力`vv`:

 | 私 | s[i] | カウント_v | 下線 |
 | --- | --- | --- | --- |
 | 0 | v | 1 | 0 |
 | 1 | v | 2 | 1 |

 ここでは、2 つの連続する「v」が 1 つのあいまいな位置を形成するため、1 つの文字に下線を引きます。 

サンプル入力`vwvvwv`:

 | 私 | s[i] | カウント_v | 下線 |
 | --- | --- | --- | --- |
 | 0 | v | 1 | 0 |
 | 1 | w | - | 1 |
 | 2 | v | 2 | 2 |
 | 4 | w | - | 3 |
 | 5 | v | 1 | 3 |

 これにより、重複する「vv」実行と個々の「w」が正しくカウントされたことが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 文字列を 1 回スキャンし、「v」と「w」の実行をカウントします。 各文字は 1 回処理されます。 |
 | スペース | お(1) | 使用されるカウンターはわずか数個だけです。 入力サイズに比例する追加のストレージはありません。 |

 n ≤ 100 および t ≤ 100 の場合、最悪の場合の合計操作数は 10,000 であり、2 秒の制限内に十分収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)
        underlines = 0
        i = 0
        while i < n:
            if s[i] == 'w':
                underlines += 1
                i += 1
            elif s[i] == 'v':
                count_v = 0
                while i < n and s[i] == 'v':
                    count_v += 1
                    i += 1
                if count_v >= 2:
                    underlines += count_v - 1
        print(underlines)
    return output.getvalue().strip()

# Provided samples

# Custom test cases

assert run("1\nv"*100 + "\n") == "0", "100 isolated v's"
assert run("1\nw"*100 + "\n") == "100", "100 w's"

## 特殊なケース

 単一の 'v' だけで構成される文字列の場合、次のようになります。`v`、アルゴリズムは正しくゼロの下線をカウントします。 のような文字列の場合`vvv`、アルゴリズムが重要です`3 - 1 = 2`下線は、曖昧な「vv」ペアをすべて過剰にカウントせずにカバーします。 次のような交互パターンの場合`vwvvwv`、各曖昧なシーケンスは独立して処理され、境界を越えて正確性が維持されます。 スキャンでは境界が自然に処理されます。`while`ループは文字列の終わりで終了するため、追加のロジックは必要ありません。
