 ## 解決策
 ## 問題の理解

 個別の整数のコレクションが与えられます。 ゲームは一連のラウンドで行われ、各ラウンドで 2 つの数字が削除され、その差がスコアに変換されます。 プレイヤー間の対話は非対称です。アリスが最初に選択しますが、現在の最大要素を取得することは制限されています。一方、ボブはアリスの選択に反応し、アリスが選択した数値よりも厳密に大きい数値を選択する必要があります。 両方の数字が選択されると、それらは消え、ボブの値からアリスの値を引いた分だけスコアが増加します。 これが一定ラウンド数繰り返され、両プレイヤーは反対の目標を持って最適にプレイします。 

このプロセスが微妙なのは、アリスが単に任意のペアを選択しているわけではなく、ボブが固定された方法で貪欲にペアを組んでいないことです。 代わりに、各ラウンドは残りのマルチセットに依存する制約付きの敵対的ペアリング プロセスです。 

入力サイズが十分に小さいため、二次またはわずかに超二次的な方法さえも妥当です。 と$n \le 400$、三次動的計画法ソリューションは依然として許容される可能性があります。 これは、問題が段階的に貪欲にシミュレートされることを意図したものではなく、間隔または並べ替えられた位置にわたって最適な下部構造について慎重に推論することによって解決されることを直ちに示唆しています。 

単純なシミュレーションでは、削除のたびに両方のプレイヤーにとって最適な応答を繰り返し再計算しようとします。 たとえ各ラウンドが$O(n)$、のためにやっている$k \approx n/2$ラウンドは～につながります$O(n^2)$、しかし本当の問題は、それぞれの決定が局所的に貪欲ではないということです。 初期のラウンドでのアリスの選択は、後で特定の高価値の組み合わせが可能になるかどうかに影響します。 単純で貪欲な「常に最も近い大きい要素をペアにする」戦略は、グローバル構造を無視するため失敗します。 

典型的な失敗例は、ローカルで早期にペアリングすることが有益であるように見えても、後のペアリングのために大量の数を予約しておく必要がある場合です。 

たとえば、次のことを考えてみましょう。```
n = 6, k = 2
a = [1, 2, 3, 100, 101, 102]
```貪欲なアプローチでは、(1,2) と (3,100) をペアにして、(101,102) を未使用のままにし、早い段階で小さな利益を得ることができます。 ただし、最適なプレイでは、ローカルではなくラウンド全体での差を最大化する方法で最大値が使用されるようにペアを構築することが優先されます。 

重要な問題は、ボブが常にアリスの後に反応するため、アリスは実質的に「ピボット」を選択し、ボブはその上にあるものを選択することを強制されますが、ボブは結果を最小限に抑えていることです。 これにより、問題は制約の下でのグローバル マッチング問題に変わります。 

## アプローチ

 最適なプレイを無視する場合、強引なアイデアは、アリスの選択とボブの応答の可能なすべてのシーケンスをシミュレートすることです。 各ステップで、アリスは任意の有効な要素を選択し、ボブは任意の有効なより大きな要素で応答します。 両方を削除した後、再帰します。 分岐因子は大まかに$O(n^2)$各ステップと深さは$k$、これは、たとえ$n=20$。 

ブルート フォースの失敗は、同等の状態を何度も再計算することで発生します。 重要な観察は、要素の実際のアイデンティティは、元のラベルではなく、並べ替えられた順序によってのみ重要であるということです。 ソートが完了すると、どの要素が残り、それらがどのようにペアになるかによってゲームが完全に決まります。 

これは、ソートされた配列の間隔にわたる動的プログラミングを示唆しています。 絶対値について考えるのではなく、並べ替えられた順序でインデックスの観点から考えます。 それぞれの動きは 2 つの要素を削除します。1 つはアリスによって選択され、もう 1 つはアリスの選択の右側からボブによって強制されます。 

中心的な洞察は、ボブの最適な応答は常に、アリスの選択よりもまだ大きい、利用可能な最小の要素を選択することであるということです。 より大きなものを選択すると、スコアが増加するだけであり、それは彼にとって悪いことです。 これにより、不確実性が大幅に減少します。アリスが位置を選択すると、$i$, ボブの反応は決まっています。 

さて、問題は次のとおりです。$k$ペア$(i, j)$そのような$a_j > a_i$、それらを削除した後、残った構造によりさらに最適なペアリングが可能になるという制約があります。 課題は、選択肢がラウンド間で相互作用することです。 

これをプレフィックスを介した DP によって解決します。配列をソートし、使用される要素の数とサフィックスから形成するペアの数に基づいて状態を定義し、「ペアになっていない」要素の数が事実上予約されている状態を維持します。 トランジションは、要素のスキップまたは強制的なペアの形成をシミュレートします。 

これは古典的な DP につながり、左側からいくつの要素がアリスの選択肢として機能し、右側からいくつがボブの応答として機能するかを決定し、実現可能性の制約が確実に尊重されるようにします。 

結果として得られる構造は、$O(n^3)$残りの要素のすべての分割を試行する DP。

 ## アルゴリズムのチュートリアル

 まず配列を並べ替えて、すべての制約が値の比較ではなくインデックスの比較に限定されるようにします。 

1. 配列を徐々にソートし、アリスに対する有効なボブの選択がその位置になるようにします。$i$右側から来なければなりません。 
2. プレフィックスに対する部分問題を表す DP 状態を定義します。ここで、まだ利用可能な要素の数と形成する必要があるペアの数を追跡します。 
3. 各状態について、2 つの構造上の決定を検討します。要素を今は未使用のままにするか、将来のペアリングでのアリスの選択としてコミットします。 
4. 位置でアリスの要素を選択した場合$i$、ボブの応答を、それより大きい最小の利用可能な要素として割り当てる必要があります。 これにより、スコアへの貢献度が即座に決定されます。 
5. 両方の要素を削除して問題のサイズを縮小し、その差を DP 値に累積することで移行します。 
6. 私たちは正確なパフォーマンスを保証します$k$このようなペアリングのため、DP はカウント制約を強制します。 

同じプロセスをより明確に見る方法は、構築することを考えることです。$k$左から右にスキャンし、選択された各アリス要素を可能な限り最も早い有効なボブ要素と貪欲に照合することでペアを作成しますが、どの要素がアリスが選択するかは DP が決定できます。 

### なぜ効果があるのか

 重要な不変条件は、要素がソートされると、アリスの選択を考慮すると、ボブの最適な応答が決定的になるということです。 これにより、状態空間から敵対的な分岐が削除されます。 したがって、すべての DP 状態は、どの要素がアリス ピボットとして機能するかの組み合わせの選択のみを表します。 ボブは常に最小の有効な応答者を選択するため、逸脱すると損失が増大するだけであるため、最適な戦略では複数のボブの選択肢を考慮する必要はありません。 これにより、ゲームは有効な一致する構造を選択するように折りたたまれ、DP は二重にカウントすることなく、実行可能なすべての構造を列挙します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    # dp[i][j] = best score using first i elements forming j pairs
    # interpreted in structured selection form
    dp = [[-10**18] * (k + 1) for _ in range(n + 1)]
    dp[0][0] = 0

    for i in range(n + 1):
        for j in range(k + 1):
            if dp[i][j] < 0:
                continue

            if i < n:
                dp[i + 1][j] = max(dp[i + 1][j], dp[i][j])

            if j < k and i < n:
                # try making a pair where i is Alice
                # and choose Bob from some later position t > i
                for t in range(i + 1, n):
                    if j + 1 <= k:
                        dp[t + 1][j + 1] = max(
                            dp[t + 1][j + 1],
                            dp[i][j] + a[t] - a[i]
                        )

    print(dp[n][k])

if __name__ == "__main__":
    solve()
```DP テーブルは、ソートされた配列をどのように使用するかを追跡します。 最初の遷移では要素がスキップされます。つまり、要素はアリスの選択として使用されません。 2 番目のトランジションは、左エンドポイントを選択し、それを後の有効な右エンドポイントとペアにすることでペアを形成し、その差がスコアに寄与します。 

三重構造により、順序付け制約が暗黙的に尊重されることが保証されます。$i$に$t+1$、それらの間にあるすべての要素はペアリング構造で効果的に消費され、再利用が防止されます。 

重要な実装の詳細は、DP インデックスです。$t+1$ボブの選択をその位置でエンコードします$t$その要素を削除してペアリングを終了しますが、中間要素は再検討されません。 

## 実用的な例

 ### サンプル 1

 入力:```
5 2
3 4 1 5 2
```ソートされた配列:`[1, 2, 3, 4, 5]`いくつかの DP 遷移を追跡します。 

| ステップ | 私 | j | アクション | ペアが形成されました | スコア |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | アリス=1を選択 | (1,2) | 1 |
 | 2 | 2 | 1 | アリス=3を選択 | (3,5) | 3 |
 | 3 | 5 | 2 | 完了 | - | 4 |

 DP はペア (1,2) と (3,5) を選択します。 残りの要素 4 は未使用です。 

これは、後のペアリングの柔軟性を最大化するには、中間要素をスキップすることが最適である可能性があることを示しています。

```ソートされた配列はすでに与えられています。 

| ステップ | 私 | j | アクション | ペアが形成されました | スコア |

 | 1 | 0 | 0 | アリス=1を選択 | (1,100) | 99 |

 | 3 | 6 | 2 | 完了 | - | 197 |

 これは、小さな値と最小の有効な大きな値を組み合わせても、残りの構造を効率的に一致させる柔軟性がまだ残っていることを示しています。

 ## 特殊なケース

 主なエッジ ケースは、連続する整数など、要素が密に詰め込まれている場合です。 このような場合、貪欲なペアリングが最適であるように見えますが、早期のペアリングの決定によってより優れたグローバル構造が妨げられないようにするには、依然として DP が必要です。 

例えば：```
n = 5, k = 2
a = [1, 2, 3, 4, 5]
```単純な戦略では、(1,2) と (3,4) を組み合わせて、5 を未使用のままにする可能性があります。 アルゴリズムはすべての有効なジャンプ構造を調査し、これが最適であることを確認します。 

もう 1 つのエッジ ケースは、非常に大きな要素が 1 つ存在する場合です。 最適な戦略では、構造に応じて複数の候補アリスの選択肢を提供できるため、早すぎるペアリングを回避することがよくあります。 DP は、最大の限界利益が得られる場合にのみ使用されることを保証します。 

最後に、値が等間隔のケースでは、DP が値の大きさには依存せず、純粋に順序に依存していることが確認されます。これは正確性にとって重要です。
