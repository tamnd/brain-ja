 ## 解決策
 ## 問題の理解

 それぞれに一定の体力を持つ一連の敵と、初期の体力ポイントを持つクリーチャーが与えられます。 目標は、彼女自身の健康状態がゼロ以下にならないようにしながら、すべての敵を順番に倒すことができるかどうかを決定することです。 

攻撃オプションは 2 つあります。 1 つは、敵 1 人につき最大 1 回使用できる強力な攻撃で、高いダメージを与えますが、大量の体力を消費します。 もう 1 つは、無制限に使用できる弱い攻撃で、使用ごとに与えるダメージは小さくなり、使用ごとにある程度の体力も消費されます。 

主な難しさは、各敵の体力をゼロにする必要があり、2 つの攻撃タイプを混合できることです。 早期に体力を消耗しすぎると、後の戦闘が不可能になる可能性があるため、この決定は敵ごとに局所的に行われるだけではありません。 したがって、問題は、各敵を確実に完全に倒しながら、全体の自己ダメージを最小限に抑えることです。 

制約は最大 100,000 人の敵に及ぶため、敵ごとに攻撃割り当てのすべての組み合わせを試すソリューションは不可能です。 敵ごとに二次推論しても遅すぎるため、敵ごとに貪欲または算術的な決定が必要です。 

よくある落とし穴は、各敵を個別に扱い、常に「コストあたり最高のダメージ」攻撃を使用することです。 これは失敗します。強力な攻撃は敵ごとに 1 回に制限されており、たとえ局所的には良く見えても、効果的ではない小さな敵には無駄になる可能性があるからです。 

もう 1 つの微妙な問題は、弱い攻撃を部分的に使用する場合、残りの体力を正確に使い切る必要があるため、1 回の強い攻撃の後に残った体力には依然として十分な弱い攻撃が必要であり、そのコストが全体として重要であることを忘れていることです。 

## アプローチ

 ブルートフォースアプローチでは、敵ごとに攻撃タイプの割り当てをすべて試行します。敵ごとに、弱い攻撃を何回使用するか、強い攻撃を適用するかどうかを決定します。 これにより、大まかに言うと、指数関数的な数の可能性が生まれます。$2^M$, 各敵には複数の使用パターンの組み合わせがあるためです。 弱い攻撃の回数は依然として変動するため、敵ごとに「強い攻撃を使用するかどうか」に減らすだけでも不十分です。 

M が 30 や 40 を超えて成長すると、これはすぐに実行不可能になります。 

重要な観察は、各敵について、それを倒すために必要な最小限の自己ダメージのみを考慮しているということです。 敵は体力要件が独立しているため (HP 残存以外に状態を引き継ぐことはありません)、敵ごとに HP をゼロに減らす最も安価な方法を計算し、それらのコストを合計することができます。 

特定の敵に対して、弱い攻撃のみを使用するか、1 つの強力な攻撃に続いて残りの体力を使い切るのに十分な弱い攻撃を使用する 2 つの戦略を比較します。 私たちは安い方を選びます。 各敵のコストが減少したら、初期 HP から合計コストを差し引くだけです。 

これにより、問題は単純な累積チェックに変わります。

 ## アルゴリズムのチュートリアル

 各敵に体力を持たせる$a_i$。 

1. 敵ごとに、完全に倒すために必要な弱い攻撃の数を計算します。 それぞれの弱い攻撃に与える影響$Q_1$損害と費用$Q_2$HPなので弱攻撃の回数は$\lceil a_i / Q_1 \rceil$。 これにより、弱いのみの戦略の総コストは次のようになります。$cost_weak = \lceil a_i / Q_1 \rceil \cdot Q_2$。 
2. 強力な攻撃を一度使用すると、敵を減少させます$P_1$。 もし$a_i \le P_1$の場合、強力な攻撃は 1 回で十分であり、コストは単純です。$P_2$。 
3. それ以外の場合、強力な攻撃の後、残りの体力は$a_i - P_1$。 まだ必要です$\lceil (a_i - P_1) / Q_1 \rceil$攻撃が弱いので、コストは$cost_strong = P_2 + \lceil (a_i - P_1) / Q_1 \rceil \cdot Q_2$。 
4. 敵ごとに、$min(cost_weak, cost_strong)$必要最小限のHP損失として。 
5. すべての敵のこれらの最小コストをすべて合計します。 
6.初期HPの場合$N$厳密に総コストより大きい場合は「YES」を出力し、それ以外の場合は「NO」を出力します。 

敵ごとに最小値を取る理由は、HP 予算の共有以外に敵間に相互作用がないため、最適なグローバル戦略が最適なローカル選択に分解されるためです。 

### なぜ効果があるのか

 各敵はダメージ要件に関して独立しており、有効な戦略はすべて敵の HP を完全にゼロにする必要があります。 固定された敵の場合、追加の強力な攻撃は許可されず、弱い攻撃のコストは直線的であるため、コストを増加させることなく、一連のアクションを「すべての弱い攻撃」または「1 つの強い攻撃とその後の弱い攻撃」に再配置できます。 したがって、敵ごとの最小コストは、合計すると全体的に最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    P1, P2 = map(int, input().split())
    Q1, Q2 = map(int, input().split())
    a = list(map(int, input().split()))

    total = 0

    for hp in a:
        weak_hits = (hp + Q1 - 1) // Q1
        cost_weak = weak_hits * Q2

        if hp <= P1:
            cost_strong = P2
        else:
            rem = hp - P1
            weak_after = (rem + Q1 - 1) // Q1
            cost_strong = P2 + weak_after * Q2

        total += min(cost_weak, cost_strong)

    print("YES" if total < N else "NO")

if __name__ == "__main__":
    solve()
```このソリューションはすべてのパラメーターを読み取り、敵を倒すための最も安価な方法を計算して各敵を反復処理します。 重要な実装の詳細は、弱い攻撃数を計算する際の天井分割を慎重に行うことです。 どちらの戦略も、強力な攻撃がオーバーシュートしたり、残りの HP に正確に一致したりするエッジケースに関する推論ミスを避けるために明示的に計算されます。 

イギーは HP を厳密にゼロ以上に保つ必要があるため、最後の比較では厳密な不等式を使用します。 

## 実用的な例

 ### 例 1

 入力:```
N = 8, M = 3
P1 = 5, P2 = 2
Q1 = 3, Q2 = 1
a = [5, 8, 6]
```敵ごとに計算します。 

| 敵 | 弱いコスト | 強力なコスト | 選ばれた |
 | --- | --- | --- | --- |
 | 5 | ceil(5/3)=2 → 2 | P2=2 | 2 |
 | 8 | ceil(8/3)=3 → 3 | 2 + ceil(3/3)=1 → 3 | 3 |
 | 6 | ceil(6/3)=2 → 2 | 2 + ceil(1/3)=1 → 3 | 2 |

 Total cost = 2 + 3 + 2 = 7.

Remaining HP = 8 − 7 = 1, so output is YES.

 このトレースは、強力な攻撃が常に有益であるとは限らないことを示しています。 それは弱い攻撃効率に対する残りの体力に依存します。 

### 例 2

 入力:```
N = 10, M = 2
P1 = 4, P2 = 5
Q1 = 2, Q2 = 3
a = [3, 7]
```敵1:

 弱 = 天井(3/2)=2 → 6

 強 = 5 (3 <= 4 のため) → 5 を選択

 敵2:

 弱 = 天井(7/2)=4 → 12

 強 = 5 + ceil(3/2) = 2 → 11 → 11 を選択

 合計 = 5 + 11 = 16。 

残りHP = 10 − 16 ≤ 0 なので、答えはNOです。 

これは、強力な攻撃を使用した場合でも、累積コストが初期 HP を超えて結果が得られなくなる可能性があることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import ceil

    def solve():
        N, M = map(int, input().split())
        P1, P2 = map(int, input().split())
        Q1, Q2 = map(int, input().split())
        a = list(map(int, input().split()))

        total = 0
        for hp in a:
            weak = (hp + Q1 - 1) // Q1 * Q2
            if hp <= P1:
                strong = P2
            else:
                rem = hp - P1
                strong = P2 + (rem + Q1 - 1) // Q1 * Q2
            total += min(weak, strong)

        return "YES" if total < N else "NO"

    return solve()

 ## 特殊なケース

 重要なエッジケースは、敵の HP が弱い攻撃のダメージで正確に割り切れる場合に発生します。 その場合、天井分割＝ぴったり分割となり、無駄な攻撃が発生しません。 整数上限除算のため、アルゴリズムはこれを自然に処理します。`(hp + Q1 - 1) // Q1`に崩壊する`hp / Q1`。 

別のエッジケースは、強力な攻撃によって HP がちょうどゼロになるときに発生します。 コードは条件を通じてこれを処理します`hp <= P1`、その後弱い攻撃が追加されないようにし、1 つだけ追加コストが発生するのを防ぎます。 

最後に、両方の攻撃タイプが非常に非効率的である場合、M が小さい場合でも総コストが N を超える可能性があり、アルゴリズムは早期に決定を下すのではなく、比較する前に敵ごとのコストをすべて正確に集計します。
