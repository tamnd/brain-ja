 ## 解決策
 ## 問題の理解

 各イグアナが 1 から N までのノードに位置し、すべてのノードが配列 p で定義された出力エッジを 1 つだけ持つ有向グラフが与えられます。 1 つのタイム ステップで、すべてのイグアナが i から p[i] まで同時に移動します。 唯一の例外はノード 1 です。イグアナ 1 は決して移動せず、代わりに他のユーザーが到達しようとする固定ルートとして機能します。 

各イグアナはこの決定的な規則に従います。 一部のイグアナは、おそらくいくつかのステップを経て、最終的にノード 1 に着陸します。 他のものは 1 を決して含まないサイクルに閉じ込められる可能性があり、その場合、リーダーに到達することはなく、期待値から無視されます。 

必要な量は、最終的にノード 1 に到達できるすべてのイグアナが初めてそこに到着するまでの平均時間であり、時間 0 からステップ単位で測定されます。 Iguana 1 自体は含まれており、貢献時間はゼロです。 

入力サイズは大きく、すべてのテスト ケースで最大 2·10^5 ノードです。 これにより、イグアナごとに段階的に進むノードごとのシミュレーションが除外されます。単純にチェーンをたどると、長いチェーンまたはサイクルで二次的な動作に劣化する可能性があるためです。 

サイクルが存在する場合、微妙な問題が発生します。 1 に接続しない 2 → 3 → 2 のようなサイクルを考えてみましょう。逆エッジで 1 からの単純な BFS は、これらのノードをカウントすることを回避します。これは正しいことですが、長い機能チェーンを通じて 1 に到達するノードの正しい距離が依然として必要です。 もう 1 つの微妙なケースは、グラフがツリーではないため、サイクルまたはノード 1 にマージする前に複数のノードがサフィックス チェーンを共有できることです。 

エッジケースには次のようなものがあります。 

単純な連鎖: 1 ← 2 ← 3 ← 4。ここでの答えは単純な距離 0、1、2、3 であり、平均は 1.5 です。 誤ってグラフを無向として扱うメソッドは過剰カウントになります。 

1 → 2 → 3 → 1 に素のサイクル 4 → 5 → 4 を加えたような、1 へのアクセスのない純粋なサイクル。ノード 4 と 5 は完全に無視する必要があります。 

p1 は存在しますが、1 は決して移動しないため、ノード 1 での自己ループが暗黙的に示されます。 この詳細は、逆構造を計算するときに重要です。 

## アプローチ

 強引なアイデアは、各イグアナを個別にシミュレートすることです。 各 i に対して、p[i]、次に p[p[i]] というように、1 に達するか繰り返しが検出されるまで繰り返し適用します。 ステップ d で 1 に達した場合、d を合計に寄与します。 それ以外の場合は無視します。 これは正しいです。なぜなら、各軌道は決定的であり、最初に 1 に到達するタイミングが明確に定義されているからです。 

ただし、最悪の場合、各ウォークには O(N) ステップがかかる可能性があり、これをすべてのノードに対して行うため、テスト ケースあたり O(N^2) になります。 N が全体で最大 2・10^5 であるため、これは遅すぎます。 

重要な観察点は、すべてのノードには出力エッジが 1 つだけあるため、その構造は関数グラフであるということです。 各コンポーネントは、そこに木が供給される有向サイクルで構成されます。 パスが最終的にノード 1 に到達するノードのみが問題となるため、グラフの逆の意味で引力 1 の領域にあるノードのみを考慮します。 

到達可能なノードに注目を限定すると、問題は、すべてのエッジが重み 1 を持つグラフ内のノード 1 までの最短距離を計算することになりますが、エッジは p に沿って前方に向けられます。 関数グラフ内の固定ターゲットまでの距離を計算する自然な方法は、エッジを反転し、ノード 1 から開始して BFS を実行することです。これにより、各ノードから 1 に到達するのに必要な最小ステップ数が得られます。これは、各イグアナにかかる時間とまったく同じです。 

したがって、解決策は次のようになります。逆隣接関係リストを作成し、ノード 1 から BFS を実行し、距離を計算し、有限距離のノードのみで平均します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N^2) | お(1) | 遅すぎる |
 | 逆グラフBFS | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

1. 逆隣接リスト rev を構築します。ここで、rev[v] には、p[u] = v となるすべてのノード u が含まれます。これにより、「次にどこに行けばよいか」が「1 ステップで誰に到達できるか」に変換されます。これは、後方検索に不可欠です。 
2. すべてのノードに対して距離配列 dist を -1 で初期化します。 これにより、すべてのノードが最初はノード 1 から到達不能としてマークされます。 
3. dist[1] = 0 に設定し、ノード 1 をキューにプッシュします。 ノード 1 は、BFS に到達するまでに必要なステップ数を測定するため、BFS のソースとなります。 
4. キューが空でない間に、ノード u をポップします。 rev[u] 内のすべてのノード v について、dist[v] がまだ -1 の場合は、dist[v] = dist[u] + 1 を設定し、v をキューにプッシュします。 これにより、最短到着時間が逆エッジに沿って外側に伝播します。 
5. BFS が完了したら、すべてのノードを反復処理します。 dist[i] != -1 の各ノード i について、dist[i] を累計に加算し、カウンターをインクリメントします。 
6. 答えを合計/個数として計算します。 これは、実際にノード 1 に到達できるノードのみの平均をとります。 

機能する理由: 反転したグラフのすべてのエッジは、正確に 1 ステップでノード 1 に向かう有効な前進を表します。 BFS は 1 からステップ数を増やしながらノードを探索します。すべてのエッジの重みが等しいため、最初にノードに距離を割り当てるときは、ノード 1 に到達するために必要な最小ステップ数であることが保証されます。訪問されていないノードは、まさに 1 から切り離されたサイクルまたはコンポーネント内にあるノードであるため、正しく除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        rev = [[] for _ in range(n + 1)]
        for i in range(n):
            rev[p[i]].append(i + 1)

        dist = [-1] * (n + 1)
        q = deque([1])
        dist[1] = 0

        while q:
            u = q.popleft()
            for v in rev[u]:
                if dist[v] == -1:
                    dist[v] = dist[u] + 1
                    q.append(v)

        total = 0
        cnt = 0
        for i in range(1, n + 1):
            if dist[i] != -1:
                total += dist[i]
                cnt += 1

        out.append(str(total / cnt if cnt else 0.0))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、BFS の逆の考え方を直接反映しています。 逆隣接リスト rev は、問題の定義に一致する 1 から始まるインデックスを使用して構築されます。 BFS キューはノード 1 から始まり、Iguana 1 がすでにリーダーにあるため、dist[1] は正しく 0 に設定されます。 

よくある間違いは、p を逆にせずに順方向に反復することです。 これは 1 に向かうのではなく、1 から遠ざかる動きをシミュレートするため、到着時間は計算されません。 もう 1 つの微妙な問題は、到達不能なノードを除外するのを忘れていることです。 dist 配列チェックにより、有効なイグアナのみが平均化されることが保証されます。

 ## 特殊なケース

 重要なエッジ ケースは、グラフの大部分がノード 1 に接続されていないサイクルで構成されている場合です。このような場合、ノード 1 からの BFS は決してそれらのサイクルに到達せず、平均に影響を与えるべきではありません。 たとえば、2 → 3 → 2 と 4 → 5 → 4 があり、1 が孤立しているグラフでは、ノード 1 のみがカウントされます。 逆 BFS では、他のすべてのノードは当然 dist = -1 のままになるため、それらはきれいに除外されます。 

もう 1 つのエッジ ケースは、長いチェーンにおいてすべてのノードが最終的に 1 につながる場合です。 たとえば、1 ← 2 ← 3 ← … ← N です。BFS では距離 0 ～ N−1 が割り当てられ、平均は (N−1)/2 になります。 各ノードは距離の増加順に 1 回だけ検出されるため、アルゴリズムはこれを変更せずに処理します。 

3 番目の微妙なケースは、サイクルまたはノード 1 に到達する前に複数のブランチがマージする場合です。リバース BFS はこれを正しく処理します。これは、ノードが一度訪問されると再訪問することはなく、複数の順方向パスが存在する場合でも、1 への最短パスのみが確実に記録されるためです。
