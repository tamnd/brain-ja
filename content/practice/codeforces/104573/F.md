 ## 解決策
 ## 問題の理解

 私たちは卵のコレクションを与えられ、それぞれの卵は 3 つの方法のいずれかで使用できます。揚げたり、スクランブルしたり、完全に無視したりできます。 それぞれの選択により、その卵の異なる満足度値が得られ、その値は卵間で独立しています。 

目玉焼きの数とスクランブルエッグの数には容量制限があります。 せいぜい$F$卵は揚げてもよく、せいぜい$S$卵はスクランブルエッグでもよい。 利用可能なすべてのスロットを使用する必要はなく、各卵の決定はグローバルです。つまり、1 つの卵を目玉焼きまたはスクランブルに割り当てると、他のすべての卵の利用可能性が減ります。 

課題は、各卵を 2 つの調理方法のうち最大 1 つに割り当てるか、完全にスキップすることによって、総合的な満足度を最大化することです。 

制約によって与えられるのは、$N \leq 10^4$そして$F + S \leq 100$。 この組み合わせが重要です。卵の数は多くなりますが、「選択されたアイテム」の総数は少なくなります。 卵ごとのすべての割り当てを直接調査しようとするソリューションでは、$3^N$可能性はありますが、それは完全に不可能です。 すべての卵と両方の容量にわたる動的計画法さえも、状態空間が小さく保たれている場合にのみ妥当です。 

素朴な二次元ナップサックオーバー$N \times F \times S$最悪の場合、すでに大きすぎます。$10^4 \times 100 \times 100 = 10^8$これは Python では限界であり、遷移が重要な場合には 1 秒未満では遅すぎます。 

両方の場合に、微妙なエッジケースが発生します。$f_i$そして$s_i$は否定的です。 素朴な貪欲なアプローチでは、最大までの選択を強制される可能性があります。$F+S$いずれにせよ、スキップは常に許可されているため、これは不正確です。 たとえば、すべての値が負の場合、$F, S > 0$、正解は$0$、何も選択しないことで達成されます。 やみくもに容量を埋めるアプローチは失敗します。 

もう 1 つのエッジ ケースは、次のいずれかの場合です。$F$または$S$はゼロです。 その場合、すべての卵は 1 つの次元のみで評価されなければならず、選択肢を混合することは不可能になります。 これにより、最大で選択できるようになります。$S$スクランブルまたは最大$F$揚げたてが一番美味しいですが、それでも卵ごとの独占性があります。 

主な問題点は、各品目に 2 つの独立した「利益のタイプ」があり、2 つのグローバルな容量制約がある場合、品目ごとに最大 1 つのタイプを選択する必要があることです。 

## アプローチ

 強引なアプローチでは、これまでに使用された揚げ卵とスクランブル卵の数を追跡しながら、各卵を揚げ、スクランブル、または未使用の 3 つの状態のいずれかに割り当てようとします。 これにより、おおよそ次の状態空間が得られます。$3^N$それぞれの割り当てには継続的な評価が必要です。 制約に違反する前に分岐が発生するため、容量制約による枝刈りもあまり役に立ちません。 これはすぐに指数関数的になります。 

より構造化されたブルート フォース ビューは、項目と容量に対する動的プログラミングです。$dp[i][f][s]$最初のことを考慮して最良の答えを表します$i$卵入り$f$揚げたものと$s$スクランブル使用。 各卵は 3 つの可能性に移行します。 これは正しいですがコストがかかります$O(NFS)$、最悪の場合、$10^4 \cdot 10^4 = 10^8$状態が変化し、各遷移は一定であるため、これは Python では遅すぎます。 

重要な観察は、容量状態の数が少ないことです。$F + S \leq 100$。 すべての卵と両方の次元にわたる DP を直接考える代わりに、卵ごとに 1 つのナップザックのような次元に決定を圧縮し、卵を 1 つずつ処理して DP テーブルを維持することができます。$(f, s)$のみ。 

問題は、容量が小さい古典的な 2D ナップザックになります。 各アイテムには 3 つの選択肢があります: 揚げて食べる、スクランブルして食べる、またはスキップする。 各卵はいずれかの次元に独立して寄与するため、小さなグリッド上で直接 DP を実行できます。 

私たちは、各州が加工卵の一部を使用して達成できる最大の満足度を保存する DP テーブルを管理しています。 各卵は、揚げた数またはスクランブルされた数を増やすことによってテーブルを更新します。 容量が小さいため、同じ卵を何度も再利用することを避けるために、状態を逆方向に安全に反復できます。 

これにより、問題が指数関数的に減少したり、$NFS$複雑さへの$N(F+S)^2$、これは実現可能です。$F+S \leq 100$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 |---|---|---|

 | ブルートフォース列挙 |$O(3^N)$|$O(N)$| 遅すぎる |

 | アイテムと容量に関する 3D DP |$O(NFS)$|$O(NFS)$| 遅すぎる |

 | 容量を超えた 2D DP のみを最適化 |$O(N(F+S)^2)$|$O((F+S)^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 この問題は、すでに選択した目玉焼きとスクランブルエッグの数によってインデックスが付けられた 2 次元テーブルを埋めるものとして扱われます。 

1. DP テーブルを作成します`dp[f][s]`、非常に負の値に初期化されます。`dp[0][0] = 0`。 これは、卵の一部のプレフィックスを正確に使用しながら処理した後に達成可能な最高の満足度を表します。`f`揚げたものと`s`スクランブルスロット。 負の無限大を使用して到達不可能な状態をマークするため、無効な構成に基づいて構築することはありません。 
2. 各卵を 1 つずつ繰り返します。 各エッグは、多くの状態を改善する可能性がある決定点であるため、まだ読み取る必要がある状態を上書きせずに、慎重に DP を更新する必要があります。 
3. 卵ごとに、新しい DP テーブルを作成します`ndp`のコピーとして初期化される`dp`。 これにより、スキップは以前のすべての値を変更せずに維持することに相当するため、卵のスキップが常に保持されることが保証されます。 
4. 次に、現在の卵を目玉焼きとして割り当てることを検討します。 すべての州について$(f, s)$どこ$f < F$に移行しようとします。$(f+1, s)$価値のあるもの`dp[f][s] + f_i`。 更新します`ndp[f+1][s]`これにより価値が向上する場合。 このステップは、この卵に揚げスロットを 1 つ使用し、揚げた満足度を蓄積することを表します。 
5. 同様に、スクランブルエッグとして割り当てることを検討します。 すべての州について$(f, s)$どこ$s < S$に移行します$(f, s+1)$価値のあるもの`dp[f][s] + s_i`、更新中`ndp[f][s+1]`それに応じて。 これにより、スクランブルされた容量制約が強制されます。 
6. すべての状態の両方の遷移を処理した後、次のように置き換えます。`dp`と`ndp`。 これにより、すべての組み合わせの正確性を維持しながら、1 つの卵の処理が完了します。 
7. すべての卵が処理された後、すべての状態をスキャンします`dp[f][s]`そして最大値をとります。 未使用の容量は許容され、場合によっては最適であるため、すべての容量を使用する必要はありません。 

### なぜ効果があるのか

 DP は、加工卵の実現可能なすべての構成の完全な表現を維持しており、揚げ卵とスクランブル卵の選択の数によってのみインデックス付けされます。 すべてのステップで、各状態は前のエッグの決定の有効なサブセットに対応します。 新しい卵を処理する場合、当社はこれらの有効な設定をすべての合法的な方法で拡張するだけで、卵を目玉焼きまたはスクランブルとして追加するか、まったく使用しません。 以前の DP をコピーするため、`ndp`、状態が使用される前に上書きされることはありません。そのため、すべての遷移では、卵の前のプレフィックスからの情報のみが使用されます。 これにより、考えられるすべての有効な割り当てが何らかの DP 状態で 1 回だけ表現され、最終的な最大値がそれらの中で最良のものを抽出することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, F, S = map(int, input().split())
    
    NEG = -10**30
    dp = [[NEG] * (S + 1) for _ in range(F + 1)]
    dp[0][0] = 0

    for _ in range(N):
        fi, si = map(int, input().split())
        ndp = [row[:] for row in dp]

        for f in range(F + 1):
            for s in range(S + 1):
                if dp[f][s] == NEG:
                    continue
                val = dp[f][s]
                
                if f + 1 <= F:
                    ndp[f + 1][s] = max(ndp[f + 1][s], val + fi)
                if s + 1 <= S:
                    ndp[f][s + 1] = max(ndp[f][s + 1], val + si)

        dp = ndp

    ans = 0
    for f in range(F + 1):
        for s in range(S + 1):
            ans = max(ans, dp[f][s])

    print(ans)

if __name__ == "__main__":
    solve()
```実装は DP 定義に直接準拠します。 コピーしたテーブルの使用`ndp`1 回の反復内で同じ卵が複数回再利用されるのを防ぐため、これは重要です。 適切な場所で更新すると、現在のエッグからの遷移が誤って連鎖し、複数回カウントされる可能性があります。 

大きな負の数で初期化すると、到達不能な状態が正の値を伝播することがなくなります。 使用する数が少ないため、最終的な答えはすべての州で採用されます。$F$または$S$スロットは許可されています。

 ## 特殊なケース

 重要なエッジ ケースは、すべての満足度の値が負の場合です。 例えば：```
3 1 1
-10 -20
-5 -7
-8 -3
```DP は 0 から始まり、遷移するたびに値が減少します。 スキップは常に許可されているため、状態`dp[0][0] = 0`到達可能な状態を維持し、すべてのネガティブな状態を支配します。 したがって、最終的な最大値は 0 となり、卵を選択しないことを表します。 アルゴリズムはこれを正しく保存します。`ndp`のコピーとして開始されます`dp`、したがって、非選択は常にオプションです。 

もう 1 つのエッジ ケースは、容量がゼロの場合です。 もし$F = 0$、フライドトランジションは次の条件のため不可能です。`f + 1 <= F`それらをブロックします。 このアルゴリズムは、特別なケースを必要とせずに、1D スクランブル ナップザックにきれいに縮退します。 同様に、$S = 0$。 これは、DP 定式化が個別の分岐を必要とせずに自然に制約を尊重していることを示しています。 

最後の微妙なケースは、最適なソリューションが使用する量が以下の場合です。$F + S$卵の合計。 最終的な答えは全体の最大値をとるため、アルゴリズムがこれを処理します。$(f, s)$、全容量境界状態だけではありません。
