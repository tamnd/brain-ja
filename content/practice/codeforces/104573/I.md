 ## アルゴリズムのチュートリアル

 各アイランドを、グランディの寄与を表す単一のビット値に変換します。 

1. 各アイランド i について、そのパイルが XOR 結果に 0 または 1 のどちらに寄与するかを表す値 g[i] を計算します。 

のために$f_i = 1$、これは単純に$q_i \bmod 2$。 これは、すべての移動で正確に 1 ユニットが削除されるため機能し、そのためパイルはサイズの Nim ヒープに相当します。$q_i$。 
2. のために$f_i > 1$、分解を繰り返す$q_i$基地内で$f_i$、ゼロ以外の桁の数を数えます。 

ゼロ以外の各桁は、サイズの移動を使用して個別に縮小できる位置に対応します。$f_i^k$, したがって、それぞれがグランディ価値の 1 単位に貢献します。 
3. g[i] を非ゼロ桁のカウントのパリティとして保存します。 
4. g に対してプレフィックス XOR 配列を構築します。 
5. 各クエリ [l, r] について、プレフィックス XOR を使用して g[l..r] の XOR を返します。 

各クエリは一定時間内に応答されます。 

### なぜ効果があるのか

 各島は独立した公平なゲームを形成します。 許可される手は常に、底の純粋なべき乗を減算し、底の 1 桁を分離します。$f_i$表現。 これは、ゲームが桁の位置ごとに独立した 2 値の選択肢に分解され、そのような各位置がグランディ値に 0 以外の場合、正確に 1 単位を与えることを意味します。 選言和は XOR を介して結合されるため、セグメント全体はアイランドごとの寄与に対する XOR に減ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def island_value(f, q):
    if f == 1:
        return q & 1

    cnt = 0
    while q > 0:
        if q % f != 0:
            cnt ^= 1
        q //= f
    return cnt

def solve():
    n, q = map(int, input().split())
    f = list(map(int, input().split()))
    a = list(map(int, input().split()))

    g = [0] * n
    for i in range(n):
        g[i] = island_value(f[i], a[i])

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] ^ g[i]

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        xor_val = pref[r] ^ pref[l - 1]
        out.append("Ivan" if xor_val else "Isabel")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```The solution first compresses each island into a single parity-like invariant. ヘルパー関数`island_value`ベースを実行します-$f$数字をスキャンし、ゼロ以外の数字が表示されるたびにビットを切り替えます。 これにより、完全な表現を保存せずに、ゼロ以外の数字のパリティが効果的に計算されます。 

プレフィックス XOR 配列は、各クエリを XOR 空間での減算に変換します。 Ivan が勝つ条件は、セグメントの XOR がゼロ以外であることです。 

注意が必要です$f = 1$なぜなら、そうしないと基本分解ループが終了しないからです。 これを個別に処理することで、正確性と直線的な実行時間が保証されます。

 ## 特殊なケース

 重大なエッジケースの 1 つは次のような場合です。$f_i = 1$。 この状況では、1 で割っても値が減らないため、基本分解ロジックは終了しません。 このアルゴリズムは、これを直接のパリティ チェックとして扱うことで、これを完全に回避します。$q_i$。 これは、すべての移動で 1 ユニットが削除されるパイルに正確に対応します。 

別のエッジケースが発生するのは次の場合です。$q_i < f_i$。 その場合、ベースは、$f_i$表現には以下の 1 桁が含まれます$f_i$, そのため、ループが 1 回実行され、ゼロ以外の数字が登録され、寄与分が 1 として正しくマークされます。 

いつ$q_i$まさに力です$f_i$、その基数は 1 桁だけです -$f_i$表現はゼロではないため、寄与は 1 のままです。アルゴリズムは特別な分岐を行わずにこれを自然に処理します。 

最後に、最大の大きな値は、$10^9$桁の分解は対数時間で実行され、値の大きさに直接依存しないため、オーバーフローやパフォーマンスの低下が保証されないため、安全です。
