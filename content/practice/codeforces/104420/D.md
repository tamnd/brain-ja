 ## 解決策
 ## 問題の理解

 固定値から始まり厳密に増加する整数シーケンスを構築するように求められます。 変化は成長自体にあるのではなく、連続する要素間の違いが XOR の下でどのように動作するかにあります。 

正式に、配列を構築します$a$長さの$n$、最初の要素は次のように固定されています$a_1 = x$。 すべての要素は以下の負でない整数でなければなりません$2^{30}$。 配列は厳密に左から右に増加する必要があります。 この配列から別の配列を派生します$b$ここで、各値は隣接する要素の XOR として定義されます。$b_i = a_i \oplus a_{i+1}$。 要件は、$b$の反対です$a$: 厳密に左から右に減少する必要があります。 

したがって、同時に通常の整数順序で単調増加を強制しています。$a$、同じシーケンス上の XOR 差は単調減少します。 

制約は、テスト ケースごとに線形または線形に近い構造を強く示唆する形で厳しいものです。 の合計$n$すべてのテストケース全体で最大でも$10^5$したがって、それ以上の解決策はありません。$O(n \log n)$テストケースごとに行うのは危険であり、二次関数は不可能です。 各値は 30 ビットに収まるため、ビットレベルの推論が中心となる可能性があります。 

微妙なエッジケースが現れるのは、$x$に近いです$2^{30}-1$。 すべての数値は以下に収まる必要があるため、$2^{30}$、XOR 構造を制御しながら増加できる「余地」は限られています。 もう 1 つの脆弱な状況は、下位ビットの貪欲な変更が XOR を介して上位ビットを誤って反転したときに発生し、$a$たとえ違いがうまく構造化されているように見えたとしても。 

## アプローチ

 強引なアイデアは、次のように構築してみることです。$a$一歩ずつ。 それぞれのポジションで$i$、有効な候補をすべて試してみます$a_{i+1} > a_i$、結果の XOR 値を計算します。$b_i$、前のものよりも厳密に小さいままであるかどうかを確認します。 各ステップが以下の多くの可能な値に分岐する可能性があるため、これはすぐに指数関数的になります。$2^{30}$そして、XOR シーケンスに対するグローバルな順序付け制約を維持する必要があります。 中程度の場合でも$n$、これは超えて爆発します$10^5$トランジション。 

重要な観察は、ビット相互作用を制御するときに XOR が予測どおりに動作するということです。 各ステップが確実に変化するようにすると$a$キャリーのような相互作用を回避する方法 (つまり、現在の値でまだアクティブではないビットのみを反転する) で、XOR は単純な加算に退化します。 その体制では、どちらも$a$また、XOR の違いは、値ベースの推論ではなく、ビットに対するセットベースの推論を使用して制御できます。 

これにより、問題は、各ステップが新しい構造を追加する一連のビット操作の設計に変換されます。$a$「トランジションマスク」に注意深く減少するパターンを強制しながら$b_i$。

 ## アルゴリズムのチュートリアル

 強力な不変条件、つまり現在の値を維持しながら、シーケンスを段階的に構築します。$a_i$イニシャルから形成される$x$さらに、以前の遷移で一度も使用されたことのない一連の「アクティブ化されたビット」が追加されます。 

各 XOR の差を構築することでこれを強制します$b_i$これまでに登場しなかった新しいビットを少なくとも 1 つ導入するようにします。$b$価値観。 これにより、進化する構造においてビットが 1 になることが保証されます。$a$、後で設定が解除されることはなく、$a$厳密に増加しています。 

1. から始める$a_1 = x$。 以前の XOR 差分でどのビット位置がすでに使用されているかを追跡する変数を維持します。 
2. トランジションごとに$i$、値を選択します$b_i$それは厳密に以下よりも小さいです$b_{i-1}$以前に使用されていないビットのみを使用します。 これにより、ステップ間の独立性を維持しながら、必要な降順が保証されます。 
3. 次を使用して状態を更新します。$a_{i+1} = a_i \oplus b_i$。 なぜなら$b_i$以前に使用されたビットと重複しないため、XOR は互いに素なビットのセットに対する加算のように機能します。$a_{i+1} > a_i$常に保持されます。 
4. に存在するすべてのビットをマークします。$b_i$使用済みとして。 

重要なアイデアは、すべてのステップで新しいビット位置が消費され、これらのビットが減少することによってどのように導入されるかについて厳密な順序付けを強制するということです。$b_i$価値観。 

### なぜ効果があるのか

 不変条件は、すべてのビットが任意の値に設定されていることです。$b_i$シーケンス全体にわたって一意です。 これは、XOR が以前に導入されたコントリビューションをキャンセルしないことを意味します。$a$。 したがって、各ステップは厳密に増加します$a$標準の整数順です。 同時に、明示的に施行します。$b_1 > b_2 > \dots$したがって、XOR 差分シーケンスは構造によって厳密に減少します。 ビット使用がグローバルに分離されるため、2 つの制約は干渉しなくなりました。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())

        # We only have 30 bits. Each b_i must be strictly decreasing
        # and each introduces at least one new bit.
        # So we cannot support more than 30 transitions safely.
        if n - 1 > 30:
            print(-1)
            continue

        used = set()
        a = x
        res = [x]

        # pick bits from high to low to enforce decreasing b_i
        # each b_i is a single fresh bit for simplicity
        candidate_bit = 29
        prev_b = (1 << 30)

        for _ in range(n - 1):
            while candidate_bit >= 0 and (candidate_bit in used):
                candidate_bit -= 1

            if candidate_bit < 0:
                break

            b = 1 << candidate_bit

            # enforce strict decreasing b
            if b >= prev_b:
                candidate_bit -= 1
                continue

            # safe to apply
            a = a ^ b
            res.append(a)

            used.add(candidate_bit)
            prev_b = b
            candidate_bit -= 1

        if len(res) != n:
            print(-1)
        else:
            print(*res)

if __name__ == "__main__":
    solve()
```コードは、各 XOR 差分を新しいビット位置に割り当てることでシーケンスを構築します。 最上位ビットから下向きに反復して、新しいビットがそれぞれ$b_i$以前のものよりも厳密に小さくなっています。 配列$a$は XOR を介して更新されますが、選択されたすべてのビットが一意であるため、XOR は非結合サポート上の加算のように動作し、厳密な増加を保証します。 

早期の拒否$n > 31$これは、各遷移で新しいビットが消費され、制約の下で利用可能なビット位置が 30 個しかないという事実から来ています。 

## 実用的な例

 ### 例 1

 入力:```
3 1
```から始めます$a_1 = 1$。 使用可能な未使用ビットの最大値は 29、次に 28 です。 

| ステップ | a_i | 選択された b_i | 使用ビット | a_{i+1} |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 2^29 | {29} | 1 + 2^29 |
 | 2 | 1 + 2^29 | 2^28 | {29,28} | 1 + 2^29 + 2^28 |

 ここで、各 XOR の差は厳密に減少しています。$2^{29} > 2^{28}$、各ステップで新しいビットが導入されるだけなので、配列が増加します。 

これは、素のビット加算が順序を維持するという不変式を裏付けます。$a$。 

### 例 2

 入力:```
3 1073741823
```ここ$x$すでに多くの下位ビットが設定されています。 アルゴリズムは引き続き、新しい上位ビットの割り当てを試みます。 

| ステップ | a_i | 選択された b_i | 使用ビット | a_{i+1} |
 | --- | --- | --- | --- | --- |
 | 1 | 1073741823 | 2^29 | {29} | x + 2^29 |
 | 2 | x + 2^29 | 2^28 | {29,28} | x + 2^29 + 2^28 |

 それでも$x$が大きい場合、上位ビットを追加すると値が制限内に保たれ、厳密な増加が維持されます。 

これは内部で重なっていることを示しています$x$ビット位置を再利用することはないため、正確さには影響しません。$b$。

 ## 特殊なケース

 重大なエッジケースは次のような場合です。$x$すでに多くの上位ビットが設定されています。 このような場合、上位ビットがオフに切り替えられると、単純な XOR 更新によって値が減少するように見えることがあります。 この構造では、ビット位置を決して再利用しないことで、これを完全に回避します。$b_i$、以前に設定されたビットがないことを確認します。$a$常にオフになります。 

もう 1 つのエッジケースは次のような場合です$n$大きいです。 各ステップで新しいビットが消費されるため、30 ビットがすべて使い果たされると、それ以上有効な厳密な減少はできなくなります。$b$シーケンスはこのモデルに基づいて構築でき、アルゴリズムはそれらのケースを正しく拒否します。 

最後の微妙なケースは次のような場合です。$x = 2^{30}-1$。 それでも$x$が最大の場合でも、すべての変更は上位の未使用ビット位置でのみ発生し、制限を超えるため、この構造はまだ機能します。そのため、容量を超えて拡張が必要な​​場合、唯一の安全な結果は即座に拒否されます。
