 ## 解決策
 ## 問題の理解

 すべてのセルに値が含まれるグリッドで作業しています。 プレイヤーはこのグリッド内を移動し、訪問したセルから値を「収集」します。 移動は制限されています。どのセルからでも、右、左、または下に移動できますが、上には移動できません。 各移動には固定ペナルティがかかるため、経路を長くさまようと最終スコアが減少します。 

スコアは、すべての個別の訪問セルの値の合計から移動数を差し引いた値に移動あたりのコストを掛けたものとして計算されます。 セルを再訪問しても合計は再び増加しませんが、それでも移動を消費するため、ペナルティが増加します。 タスクは、開始セル、終了セル、およびこのスコアを最大化する有効なパスを選択することです。 

重要な問題は、パスが単純な指示された歩行ではないことです。 左右の移動が許可されているため、ジグザグに行を移動できますが、これは下に移動するか、同じ行レベルに留まっている場合に限られます。 この構造は、水平方向の探索と制御された垂直方向の進行を組み合わせたものになります。 

この制約により、パスに対する強引な攻撃は不可能になります。 グリッドはテストごとに 2000 × 2000 まで大きくでき、テスト ケースは最大 1000 個あり、テスト全体のグリッド サイズの合計は 2000 × 2000 に制限されます。これは、テストごとに O(nm) または O(nm log nm) のアプローチが期待されることを強く示唆しています。 

単純な考えは、すべてのパスを試すか、これを「訪問済みセット」状態のグラフ上の最短パス/最長パスとして扱うことです。 構造とパスの組み合わせ論を再検討すると指数関数的に爆発的に増加するため、これはすぐに失敗します。 

より巧妙な単純なアプローチは、開始セルを修正し、何らかの方法で圧縮された訪問セットを使用して位置に対して動的プログラミングを試みることです。 これも失敗します。再訪すると標準の DP 単調性が破られるからです。 

明らかではない重要な落とし穴は、セルを再訪問することが常に無駄であると想定していることです。 そうではない。 有益な回り道を繋ぐには、時には再訪が必要だ。 たとえば、次の行について考えてみましょう。```
5  -100  5
```右に移動するコストが 2 の場合、両方のプラスを再利用して複数の高価値セルにわたってコストを償却できるのであれば、左 5 から右 5 に移動して戻るのが最適である可能性があります。 貪欲な「肯定的な隣人を一度だけ採用する」アプローチはここで破綻します。 

もう 1 つの微妙な失敗例は、最適なパスが単調な下方向と単調な右方向であると仮定することです。 左への移動が許可されているため、下降する前に列を複数回蛇行することができ、多くの場合これが最適な構造になります。 

## アプローチ

 ブルート フォース解釈では、各状態が一連の訪問ノードを持つセルにあると見なされます。 遷移は、左、右、下への移動、訪問セットの更新、および移動ごとのコストの支払いに対応します。 これは正しいですが、状態空間は nm 単位で指数関数的であるため、実行不可能です。 

次のステップは、「訪問済みセット」の依存関係を削除することです。 重要な観察は、セルを再訪問しても、そのセルが既に含まれているかどうかを除いては重要ではないということです。 したがって、パスからのゲインは、セルが何回訪問されるかではなく、どのセルが少なくとも 1 回含まれるかによってのみ決まります。 これにより、問題は移動制約の下で接続された構造を選択することに変換されます。 

次に、有効なパスがどのような構造を形成できるかを考えてみましょう。 行内では左右に自由に移動できますが、行間では下方向にしか移動できないため、各行は複数回横断する可能性があるセグメントと考えることができますが、垂直方向の遷移は隣接する行間でのみ発生します。 これは、遷移のコストを考慮しながら各行を走査する方法を決定する、行ごとの動的プログラミングを強く示唆しています。 

重要な変換は、移動コストを連続する訪問間のエッジ コストとして解釈することです。 パスの観点から考えるのではなく、行エントリごとの寄与と行間の遷移の観点から考えます。 行内での最適な動作は、連続するセグメントを選択するか、バックトラッキング コストを伴うセグメントを結合することになります。 

これは古典的な最適化につながります。行ごとに、上から入り、コストを考慮しながら左右のセグメントを横断し、下に抜けるための最良の方法を計算します。 この問題は、行ごとの列ごとに達成可能な最良の値を維持し、水平方向の緩和を許容しながら下方向に伝播することに帰着します。 

dp[i][j] が行 i の処理後のセル (i, j) で終わる最良のスコアである DP を維持します。 行ごとに 2 つのパス (左から右と右から左) で計算し、移動コストを差し引きながら最良のゲインを蓄積します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (訪問セットのあるパス) | 指数 | 指数 | 遅すぎる |
 | 水平緩和を伴う行方向の DP | O(nm) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 グリッドを行ごとに処理し、現在の行の各セルで終了する達成可能な最良のスコアを維持します。

1. 開始には移動が必要ないため、各セルが独自の値から移動コストを差し引いた値で始まる最初の行の DP 配列を初期化します。 これは、一番上の行の任意のセルでパスが開始されることを表します。 
2. 各行について、左から右へのパスを計算します。 パスを水平に延長することを表す実行中の最適値を維持します。 列 j-1 から j に移動するとき、コスト c を減算し、現在のセル値を加算します。 これは、同じ行でパスを継続することをモデル化します。 
3. 左から右へのパスからの最良の値を一時配列に保存します。 
4. 同じ列で右から左へのパスを実行します。 これは前のステップを反映しており、右側から入るパスも確実に考慮されます。 ここでも、ランニングベストを維持し、ステップごとの移動コストを適用します。 
5. いずれかの方向から各セルで達成可能な最大値を取得して、両方のパスを結合します。 これにより、行内の最適なジグザグ移動が確実にキャプチャされます。 
6. 行の水平方向の最適化後、値を下方向に伝播します。 次の行の各セルについて、現在の行のセルから真下に移動し、移動のコスト c を減算し、次の行のセル値を加算することを検討します。 それに応じて DP を更新します。 
7. 最後の行が処理されるまで繰り返します。 答えは、すべての DP 状態にわたる最大値です。 

### なぜ効果があるのか

 DP 状態は、すべてのパス履歴を各セルで終わる達成可能な最良のスコアに圧縮します。 水平パスは、行内のすべての可能な左右のウォークを正確にシミュレートします。これは、そのようなウォークは一連の隣接する動きに分解され、各動きのコストは均一であるためです。 垂直遷移は独立しており、前の行の終了位置にのみ依存するため、追加の履歴は必要ありません。 再訪問しても価値は増加しないため、複数の訪問をセルごとに 1 つの最適なプレフィックスに集約することで最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, c = map(int, input().split())
        a = [list(map(int, input().split())) for _ in range(n)]

        dp = [-10**30] * m

        for i in range(n):
            left = [-10**30] * m
            cur = [-10**30] * m

            for j in range(m):
                if i == 0:
                    best = 0
                else:
                    best = dp[j]
                if j > 0:
                    best = max(best, left[j - 1] - c)
                left[j] = best + a[i][j]
                cur[j] = left[j]

            right = [-10**30] * m
            for j in range(m - 1, -1, -1):
                if i == 0:
                    best = 0
                else:
                    best = dp[j]
                if j + 1 < m:
                    best = max(best, right[j + 1] - c)
                right[j] = best + a[i][j]
                cur[j] = max(cur[j], right[j])

            if i < n - 1:
                new_dp = [-10**30] * m
                for j in range(m):
                    new_dp[j] = cur[j] - c + a[i + 1][j]
                dp = new_dp
            else:
                dp = cur

        print(max(dp))

if __name__ == "__main__":
    solve()
```コードは行ごとにローリング DP を維持します。 左側と右側の配列は、コストの累積を伴うすべての可能な水平走査をシミュレートします。 重要な実装の詳細は、水平方向の拡張を適用する前に、常に最良の前行の寄与を現在の行に持ち込むことです。 行間の遷移では、移動コストが差し引かれ、すぐに次の行のセル値が追加されます。これは、すべての移動でコストが発生し、訪問されたすべてのセルが 1 回貢献するというルールに一致します。 

最初の行の初期化では、開始に上から入力する必要がないため、ベースとして 0 が使用されます。 これにより、最初に訪問したセルに誤ってペナルティが課されることが回避されます。 

## 実用的な例

 ### 例 1

 小さなグリッドを考えてみましょう。```
1  -2
3   4
```コスト c = 1

 dp を行ごとに追跡します。 

行0:

 | j | 上からの dp | 左/右リラックス | 最終 |
 | --- | --- | --- | --- |
 | 0 | 0 | 0 + 1 = 1 | 1 |
 | 1 | 0 | max(-1, 1-1)=0 → 0 + (-2) = -2 | -2 |

 行 1:

 | j | 上の dp | 水平 | 最終 |
 | --- | --- | --- | --- |
 | 0 | 1 | 1 + 3 = 4 | 4 |
 | 1 | -2 | max(4-1, -2) = 3 → 3 + 4 = 7 | 7 |

 答えは7です。 

このトレースは、水平緩和により、行間で値を保持し、有益な場合には行内の複数のセルを結合できる方法を示しています。 

### 例 2

 グリッド:```
-1  9  1
 2 -5  3
```コスト c = 2

 行0:

 最適なパスは右に移動して 9 と 1 を収集します。 

| j | 値 |
 | --- | --- |
 | 0 | -1 |
 | 1 | 9 |
 | 2 | 10 - 2 = 8 |

 行 1:

 下方向に伝播し、以下を組み合わせます。 

| j | 上の dp | 最高の水平 | 最終 |

これらの例は、最適なパスが下方向への移動をコミットする前に、値の高いセルを 1 つの行に「収集」することが多いことを強調しています。

    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, m, c = map(int, input().split())
        a = [list(map(int, input().split())) for _ in range(n)]

        dp = [-10**30] * m
        for i in range(n):
            left = [-10**30] * m
            cur = [-10**30] * m

            for j in range(m):
                best = dp[j] if i > 0 else 0
                if j > 0:
                    best = max(best, left[j-1] - c)
                left[j] = best + a[i][j]
                cur[j] = left[j]

            right = [-10**30] * m
            for j in range(m-1, -1, -1):
                best = dp[j] if i > 0 else 0
                if j + 1 < m:
                    best = max(best, right[j+1] - c)
                right[j] = best + a[i][j]
                cur[j] = max(cur[j], right[j])

                for j in range(m):
                    new_dp[j] = cur[j] - c + a[i+1][j]
                dp = new_dp
            else:
                dp = cur

        out.append(str(max(dp)))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジケースは、下に移動するよりも 1 つの行内に留まる方が良い場合です。 例えば：```
1  100  1
```移動コストが高いため、アルゴリズムは dp を同じ行に保ち、水平緩和を使用して不必要な降下を行わずに両方の陽性セルを捕捉します。 左右のパスにより、移動コストを誤って二重にカウントすることなく、両端に到達できることが保証されます。 

もう 1 つのエッジ ケースは、単一列グリッドです。 この場合、水平方向の遷移は完全に消え、アルゴリズムは列を下る直線の DP に減少します。 左パスと右パスは何も役に立たず、垂直トランジションのみがアクティブのままであるため、実装は引き続き機能します。 

最後のエッジ ケースは、あらゆる移動にコストがかかるネガティブ グリッドです。 dp 初期化により移動を強制することなく任意の開始を選択できるため、アルゴリズムは単一セルを正しく優先します。そのため、最良の答えは単一セルの最大値です。
