 ## 解決策
 ## 問題の理解

 ちょうど 2 行のグリッドが与えられ、`n`列。 各セルには負ではない整数が含まれています。 左上のセルから始まるウォークを構築する必要があります`(1,1)`そして右下のセルで終わります`(2,n)`。 各ステップで、右、上、または下に移動できますが、どのセルにも複数回訪問することはできません。 

訪問したセルから値を収集してセットにします`S`。 パスの値は次のように定義されます。`mex(S)`、以下に現れない最小の非負の整数。`S`。 タスクは、この mex を最大化する有効なパスを選択することです。 

制約は大きく、すべてのテスト ケースにわたる列の合計数は最大です。`10^5`、最大で`10^5`テストケース。 これにより、パスを明示的に列挙するものや、訪問したセルのサブセットに対して状態ごとの動的プログラミングを行うものは直ちに除外されます。 テストケースごとの線形解であっても、合計が厳密に O(n) である場合にのみ許容されます。 

主要な構造上の制約は、グリッドに 2 行しかないことです。 そのため、移動スペースが非常に狭くなります。上下の移動は許可されていますが、ジオメトリにより、基本的に右方向に移動しながら行間を切り替える場所を選択するような動作をパスに強いられます。 

いくつかの微妙な特殊なケースが重要です。 

単純な考えでは、すべての小さな値を順番に含めようとするかもしれませんが、セルへのアクセスはパス ジオメトリによって制限されるため、失敗する可能性があります。 たとえば、欠落している最小の数値が 3 の場合、0、1、2 がどこかに存在することを知るだけでは十分ではなく、それらは単一の単純なパスで収集可能でなければなりません。 

もう 1 つの落とし穴は、パスがどの列でも行間を自由にジグザグに移動できると想定していることです。 垂直方向の移動は許可されていますが、ある列で行 1 から行 2 に移動すると、以前の列に戻ることはできないため、並べ替えが強く制限されます。 

## アプローチ

 ブルートフォースアプローチでは、すべての有効なパスをシミュレートしようとします。`(1,1)`に`(2,n)`移動制約の下で、収集された値の mex を計算します。 状態を注意深くエンコードしたとしても、有効なパスの数は次のように指数関数的に増加します。`n`なぜなら、各列で現在の行に留まるか切り替えるかを選択でき、スイッチは以前に訪問した構造と相互作用するからです。 これは非常に小さいものを超えるとすぐに実行不可能になります`n`。 

重要な観察は、2 行 n 列のグリッドでは、セルを再訪問しない有効なパスは非常に単純な形状でなければならないということです。行を切り替えながら右に移動しますが、任意の再訪問パターンを形成することはできません。 実際、どのパスも列の選択に対応します。`k`ここでは、トラバーサル スイッチが構造化されており、パスは 1 つの行のプレフィックスともう 1 つの行のサフィックスを効果的にカバーしており、切り替えポイントに短い「ブリッジ」が存在する可能性があります。 

この構造は、あらゆる値に対して、より強力なものを意味します。`x`パスに含めたい場合は、より小さい必要な値へのアクセスをブロックせずに、どちらかの行にパスを含める方法が存在するかどうかだけを知る必要があります。 したがって、パスを検索する代わりに、すべての値をカバーする実現可能性について推論します。`0`に`mex-1`。 

値を昇順に処理します。 メキシコ人候補者にとって`m`、すべての値がどうかを尋ねます。`0..m-1`有効なパスに沿って収集できます。 各値は、行ごとに 1 つずつ、最大 2 つの位置に表示されます。 唯一の自由は、値ごとに、どのオカレンスを使用するかを選択することです。 パス制約は、列に沿った単調な順序制約になります。値の側を選択したら、パスの左から右の構造と一貫性を保つ必要があります。 

これにより、問題は各値を割り当てられるかどうかを確認するだけになります。`x < m`選択した位置が単一の非後戻りパスと互換性があるように、行 1 または行 2 のいずれかに移動します。 重要な単純化は、動作を切り替える前に、各行でその行で使用される最大列インデックスのみを考慮することであり、これにより、貪欲な実現可能性チェックが行われます。 

したがって、答えを二分探索します`mex`、固定の場合`m`、各値を貪欲に配置しようとします。`0`に`m-1`パスの単調構造に違反しない、可能な限り最も早い発生を選択することによって。 これが成功すれば、`m`達成可能です。

 ## アルゴリズムのチュートリアル

 1. グリッド内の各値の位置を事前計算します。 

あらゆる値を保存します`x`、最大 2 つのポジション`(row, column)`。 これにより、実現可能性チェック中に一定時間のアクセスが可能になります。 
2. 関数を定義する`can(m)`すべての値が正しいかどうかをチェックします`0`に`m-1`集めることができる。 

左から右へのパスによって課される制約を維持しながら、これらの値の出現を昇順で選択することをシミュレートします。 
3. 2 つのポインターを維持する`r1`そして`r2`、それぞれ行 1 と行 2 でコミットした最も遠い列を表します。 

これらは、一度トラバースの構造にコミットすると、列内で後戻りすることはできないという事実を表しています。 
4. 各値について`x`から`0`に`m-1`、置いてみてください。 

将来を可能な限り柔軟に保つ方法で配置することを好み、通常は現在の制約境界より前に発生しないものを選択します。 両方が無効な場合、構成は失敗します。 
5. すべての値を一貫して配置できる場合は、true を返します。 それ以外の場合は false を返します。 
6. 最大の二分探索`m`そのような`can(m)`それは本当です。 

mex は単調です: 収集できれば`0..m-1`、任意の小さなプレフィックスを収集することもできます。 

### なぜ効果があるのか

 この正しさは、2 行グリッド内の有効なパスが訪問セルに左から右への順序制約を引き起こすという事実から得られます。 値の出現箇所を修正したら`0..m-1`が選択されると、パスはローカル行スイッチに至るまで一意に決定されます。実現可能性は、列インデックスの単調性に違反することなく、これらの選択された位置を順序付けできるかどうかにかかっています。 貪欲な選択が機能するのは、後の値はさらに右側の制約を課すだけであるため、以前の有効な出現を選択しても将来の実現可能性が必要以上に低下することがないためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(m, pos):
    # r1, r2 track furthest used column in each row path projection
    r1 = -1
    r2 = -1

    for x in range(m):
        p1 = pos[x][0] if len(pos[x]) > 0 else None
        p2 = pos[x][1] if len(pos[x]) > 1 else None

        candidates = []
        if p1 is not None:
            candidates.append(p1)
        if p2 is not None:
            candidates.append(p2)

        best = None

        # try placing x in row 1 or 2 consistent with current constraints
        for r, c in candidates:
            if r == 0:
                if c >= r1:
                    best = min(best, (r, c)) if best else (r, c)
            else:
                if c >= r2:
                    best = min(best, (r, c)) if best else (r, c)

        if best is None:
            return False

        r, c = best
        if r == 0:
            r1 = c
        else:
            r2 = c

    return True

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a1 = list(map(int, input().split()))
        a2 = list(map(int, input().split()))

        pos = [[] for _ in range(2 * n + 1)]

        for j, v in enumerate(a1):
            pos[v].append((0, j))
        for j, v in enumerate(a2):
            pos[v].append((1, j))

        lo, hi = 0, 2 * n + 1
        ans = 0

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(mid, pos):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()
```実装では、実現可能性チェックが O(m) になるように、各値の位置リストを構築します。 の`can`関数は、行投影ごとに単調な列の使用を強制します。これは、2 行グリッド内の単純な非バックトラック パスの構造的制約をキャプチャします。 二分探索はこのチェックをラップして、達成可能な最大 mex に効率的に到達します。 

実装上の微妙な懸念事項はインデックス付けです。列はゼロベースとして扱われ、前方への移動を維持するために比較は厳密に非減少になります。 もう 1 つの重要な詳細は、グリッドに存在しない値は、それを下回るとすぐに実現可能性を無効にすることです。`m`、mex は完全にカバーする必要があるため、`0..m-1`。

 ## 特殊なケース

 重要なエッジケースの 1 つは、次のような場合です。`0`グリッドに存在しません。 その場合、答えは必ず次のようになります。`0`、mex は開始時にすでに違反されているためです。 アルゴリズムはこれを自然に処理します。`can(1)`すぐに失敗する場合`0`有効な配置がありません。 

もう 1 つのケースは、すべての値が存在するものの、行の競合が早期に強制されるような方法で配置されている場合です。 例えば：```
top:    0 2 4
bottom: 1 3 5
```それを超えて拡張しようとする`mex=2`配置しているため失敗します`0`そして`1`すでに行の進行を修正しています。`2`単調な順序を壊すことなく到達することはできません。 実行可能性チェックは、一貫した非減少列シーケンスを割り当てることができない場合にこれを検出します。 

最後の微妙なケースは、値の両方の出現が存在するが、前の制約のために後の方の値しか使用できない場合です。 貪欲チェックでは常に両方のポジションが考慮されるため、自然に適応し、無効な初期配置に早まってロックすることを回避します。
