 ## 解決策
 ## 問題の理解

 Monocarp のコンテスト ログは長さの文字列です$n$どこで$i$- 番目の文字は、その分の間に彼が取り組んでいた問題を表します$i$。 「A」から「Z」までの各問題には、解くのに必要な時間が関連付けられています。「A」は 1 分、「B」は 2 分、「Z」までは 26 分かかります。 Monocarp が累積的に少なくとも必要な時間をその問題に費やした場合、問題は解決されたとみなされます。 目標は、コンテストが終わるまでに彼がいくつの個別の問題を解決したかを数えるということです。 

入力は複数のテスト ケースで構成され、それぞれにコンテストの期間とログ文字列が含まれます。$n$最大 500 個、テスト ケースは最大 100 個まであるため、すべてのテスト ケースにわたる合計作業量は最大で$5 \cdot 10^4$操作。 これにより、テスト ケースごとに文字列全体を線形時間で処理するソリューションが可能になります。 すべての問題を文字列全体に対して複数回チェックする単純なアプローチでは、不必要に複雑になり、エラーが発生する可能性があります。 エッジ ケースには、Monocarp が 1 つの問題を完了せずに繰り返し作業するログ、または同じ問題の複数の解決を含むログが含まれます。 アルゴリズムは、必要な時間を満たした後、各問題を最大 1 回カウントする必要があります。 

## アプローチ

 ブルート フォース手法では、テスト ケースごとに 26 個の問題すべてを繰り返し、問題ごとに、その問題に対応するログの分数がカウントされます。 カウントが必要な時間を満たしているか超えている場合は、解決されたカウントを増分します。 この方法は正しいですが、最大で$26 \cdot n$テストケースごとの操作。 制約が与えられているため、これは許容できますが、同じスキャンを複数回繰り返すため、若干非効率的です。 

最適な方法では、ログを 1 回走査する際の問題ごとの時間を直接蓄積します。 私たちは、各問題に対応する 26 個のカウンターを維持しています。 1 分ごとに、ログで示された問題のカウンターが増加します。 トラバース後、どのカウンタが対応する問題の所要時間を満たしているか、またはそれを超えているかを確認します。 このメソッドは各ログインを処理します$O(n)$時間と$O(1)$追加のスペースが確保され、スキャンの繰り返しが回避されます。 重要な洞察は、問題に必要な時間はアルファベット順のインデックスによって厳密に決定され、順序を考慮せずに 1 回のパスで時間を蓄積できるということです。

 | --- | --- | --- | --- |
 | ブルートフォース | O(26 * n) | お(26) | 承認済み |
 | 最適 | O(n) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`times[26]`ゼロに。 各要素は問題「A」から「Z」に対応しており、Monocarp がその問題に費やした累積分数を追跡します。 
2. キャラクターごとに`c`コンテスト ログで、そのインデックスを次のように計算します。`idx = ord(c) - ord('A')`そして増加します`times[idx]`1つずつ。 このステップでは、コンテスト中に各問題に費やした時間が蓄積されます。 
3. カウンタの初期化`solved = 0`。 
4. 反復処理`i`0 ～ 25 で、問題「A」から「Z」を表します。 問題ごとに次のことを確認します。`times[i] >= i + 1`問題「A」には 1 分、「B」には 2 分、...、「Z」には 26 分かかるためです。 条件が成立する場合はインクリメントします`solved`。 
5. 出力`solved`このテスト ケースで Monocarp が解決した問題の数として。 

このアルゴリズムが機能するのは、各問題の所要時間が独​​立しており、ログ全体の時間を累積すると、費やしたすべての分が正確に計算されるためです。 不変条件は、ログを処理した後、`times[i]`Monocarp が問題に費やした合計時間を正確に表します`chr(ord('A') + i)`。 照合中`i + 1`問題が解決したかどうかを正しく判断します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    log = input().strip()
    times = [0] * 26
    for c in log:
        times[ord(c) - ord('A')] += 1
    solved = sum(1 for i in range(26) if times[i] >= i + 1)
    print(solved)
```各テストケースを個別に処理します。 配列`times`問題ごとの時間を追跡し、ASCII 算術を使用して文字をインデックスに変換します。 最後に配列を合計すると、どの問題に十分な累積時間があるかがチェックされます。 これにより、スキャンの繰り返しが回避され、毎分を 1 回正確にカウントすることで正確さが保証されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | 各ログ文字は 1 回処理され、配列の合計は O(26) |

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        n = int(input())
        log = input().strip()
        times = [0]*26
        for c in log:
            times[ord(c)-ord('A')] += 1
        solved = sum(1 for i in range(26) if times[i] >= i+1)
        print(solved)
    return output.getvalue().strip()

 ## 特殊なケース

 Monocarp が必要なしきい値に達せずに 1 つの問題に何分も費やした場合、アルゴリズムは正しくゼロを報告します。 たとえば、問題 'F' (6 が必要) の 5 分間のログは次のようになります。`times[5] = 5 < 6`, そのためカウントされません。 同じ問題の複数の解決が発生した場合、累積により二重にカウントされることなく合計時間が正しくカウントされ、長く繰り返されるシーケンスであっても正確さが保証されます。
