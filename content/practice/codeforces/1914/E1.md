 ## 解決策
 ## 問題の理解

 各色は、両方のプレイヤーが所有するビー玉の独立した山です。 移動すると、両側にまだ存在する色が選択されます。 

色を仮定します`i`アリスが選んだものです。 アリスはその色のビー玉を 1 つだけ捨てますが、ボブはすべてを失います`b_i`その色のビー玉。 その移動の後、ボブの色のビー玉はゼロになりました`i`, そのため、その色は二度と再生できなくなります。 

同様に、ボブが色を選択した場合`i`、ボブはビー玉を 1 つ失い、アリスはビー玉をすべて失います。`a_i`その色のビー玉。 

選択した色はすぐに永久に使用できなくなるため、どの色も最大 1 回しか再生されません。 このゲームは実際、誰が各色の最終解像度の所有権を取得するかを決定することを目的としています。 

最終的なスコアは、$$\text{Alice's remaining marbles} - \text{Bob's remaining marbles}.$$アリスはこの値をできるだけ大きくすることを望み、ボブはこの値をできるだけ小さくすることを望みます。 

簡単バージョンには、`n ≤ 6`。 それは極めて小さいことです。 色の数が少ないため、考えられるすべての動作シーケンスを試すことも可能です。 ゲーム状態の数はおおよそ次のように増加します`n!`、これは`n = 6`だけです`720`。 せいぜい`1000`テスト ケースでは、完全なミニマックス検索は依然として快適に高速です。 

最もよくある間違いは、色は独立しており、個別に最適化できると考えることです。 ターン順序によって誰が色を獲得できるかが決まるため、そうではありません。 

考慮する：```
n = 2
a = [100, 1]
b = [1, 100]
```アリスが色 1 を取得し、ボブが色 2 を取得した場合、結果は逆の割り当てとは大きく異なります。 ゲーム全体がターンの奪い合いです。 

もう 1 つの簡単な間違いは、最後に残ったビー玉ではなく、プレイ中に削除されたビー玉だけを評価することです。 

例えば：```
n = 1
a = [5]
b = [7]
```アリスが唯一の色を選択した場合、彼女はビー玉を 1 つ失い、ボブは 7​​ つすべてを失います。最終的な状態は次のとおりです。```
Alice: 4
Bob: 0
```スコアは`4`、 ない`7 - 1 = 6`。 ゲームは残りのビー玉によって決まります。 

3 番目の微妙な点は、どちらかのプレイヤーが選択した色が永久に消えることです。 

例：```
a = [10]
b = [10]
```アリスが色を演奏した後、ボブは同じ色を演奏することはできません。 1 つの色を複数回使用できるソリューションは、別のゲームをモデリングすることになります。 

## アプローチ

 なぜなら`n`が最大 6 の場合、最も直接的なアプローチはミニマックスです。 

どの州でも、どの色がまだ入手可能であるかがわかります。 アリスの番の場合、彼女はプレイ可能なすべての色を試し、最終的に最大のスコアを生み出す手を選択します。 ボブの番の場合、ボブは最終的に最小のスコアを選択します。 

課題は、終末状態を効率的に評価することです。 

有益な観察は、誰がそれを主張したかが分かると、各色が独立して寄与するということです。 

色を仮定します`i`決して再生されません。 最終スコアへの貢献度は次のようになります。$$a_i - b_i.$$アリスが色を演じるとしましょう`i`。 

アリスが飼う`a_i-1`ビー玉とボブのキープ`0`, したがって、貢献度は次のようになります。$$(a_i-1)-0 = a_i-1.$$手つかずの貢献と比較`a_i-b_i`、スコアは次のように変化します$$(a_i-1)-(a_i-b_i)=b_i-1.$$同様に、ボブが色を演奏する場合`i`、貢献度は$$0-(b_i-1)=-(b_i-1),$$これは、手付かずの貢献とは異なります。$$-(b_i-1)-(a_i-b_i)=-(a_i-1).$$これにより、ゲーム全体を、選択した色による利益と損失の蓄積として表現できます。 

ただし、簡単なバージョンでは、実際には高度な貪欲な議論は必要ありません。 状態空間は小さいため、サブセットに対するメモ化されたミニマックスで十分であり、正しいことを証明するのは非常に簡単です。 

すべての動きで 1 色だけが永久に削除されるため、総当り攻撃が機能します。 最大でも 6 つの手でゲームが終了します。 状態の総数は$$2^6 \times 2 = 128.$$メモ化により、検索は基本的に瞬時に行われます。

 ## アルゴリズムのチュートリアル

 しましょう`base`どの色もプレイされなかった場合のスコアになります。$$base = \sum (a_i-b_i).$$再生された色によって引き起こされる追加の変化のみを計算します。 

色について`i`:$$gainAlice_i = b_i - 1$$アリスがそれを選択すると、相対的にその量だけスコアが増加するため、`base`。$$gainBob_i = -(a_i - 1)$$ボブがそれを選択すると、相対的にその量だけスコアが減少するためです。`base`。 

すでに使用されている色のビットマスクとその順番によって DP 状態を定義します。 

### 1. 基本スコアを計算する

 すべてを合計します`a_i - b_i`。 

これは、再生された色を考慮する前のスコアです。 

### 2. ゲームの状態をビットマスクで表現する

 ビット`i`色の場合に設定されます`i`すでに誰かに選ばれています。 

すべての移動により、以前に設定されていなかったビットが 1 つだけ設定されます。 

### 3. ミニマックス関数を定義する

 しましょう```
dp(mask, turn)
```は、現在の状態以降の最適なスコア調整になります。`turn = 0`アリスが次に移動することを意味します。`turn = 1`ボブが次に移動することを意味します。 

### 4. 終了状態の処理

 すべての色がすでに使用されている場合、それ以上の調整はできません。 

戻る`0`。 

### 5. アリスの移行

 アリスは未使用の色をすべて試します`i`。 

色の選択`i`すぐに貢献する$$b_i-1.$$その後、ゲームは新しいマスクとボブのターンから続きます。 

アリスはすべての選択肢の中から最大値を選択します。 

### 6. ボブの移行

 ボブは未使用の色をすべて試します`i`。 

色の選択`i`すぐに貢献する$$-(a_i-1).$$その後、ゲームは新しいマスクとアリスの番から続きます。 

ボブはすべてのオプションの中から最小値を選択します。 

### 7. 基本スコアと組み合わせる

 答えは$$base + dp(0,\text{Alice turn}).$$### なぜ効果があるのか

 重要な特性は、すべての色を最大 1 回選択できることです。 プレイヤーが色を選択すると、その色はゲームから永久に消えます。 このため、将来の状態は、どの色がすでに使用されているか、そして誰の番であるかによってのみ決まります。 

技の貢献度は、その色が選ばれた瞬間に完全に決定されます。 後で何が起こってもその色を再び変えることはできません。 ミニマックスの反復は最適プレイのルールと正確に一致します。アリスは最終スコアを最大化し、ボブはそれを最小化します。 すべての法的継続が調査されメモ化されるため、計算された値は真のゲーム価値と等しくなります。 

## Python ソリューション```python
import sys
from functools import lru_cache

input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        base = sum(ai - bi for ai, bi in zip(a, b))
        full = (1 << n) - 1

        @lru_cache(None)
        def dp(mask, turn):
            if mask == full:
                return 0

            if turn == 0:  # Alice
                best = -10**30
                for i in range(n):
                    if not (mask & (1 << i)):
                        best = max(
                            best,
                            (b[i] - 1) + dp(mask | (1 << i), 1)
                        )
                return best

            else:  # Bob
                best = 10**30
                for i in range(n):
                    if not (mask & (1 << i)):
                        best = min(
                            best,
                            -(a[i] - 1) + dp(mask | (1 << i), 0)
                        )
                return best

        ans.append(str(base + dp(0, 0)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```解決策は、手つかずのスコアを計算することから始まります。`base`。 すべての動きは、そのベースラインに対する単純な調整になります。 

DP 状態には、使用されたカラー マスクと移動するプレーヤーのみが含まれます。 色を選択するとその色の全体的な効果が決定されるため、大理石の数を保存する必要はありません。 

アリスの移行が追加`b[i] - 1`。 ボブの移行が追加`-(a[i] - 1)`。 これらの値は、色がプレイされた後のスコアと、その色が変更されなかった場合のスコアを比較することで直接得られます。 

再帰の深さがこれを超えることはありません`n`、これは最大 6 であるため、再帰は完全に安全です。

 ### 例 1```
n = 3
a = [4, 2, 1]
b = [1, 2, 4]
```基本スコア:$$(4-1)+(2-2)+(1-4)=0$$調整値:

 | 色 | アリスゲイン | ボブゲイン |
 | --- | --- | --- |

 | ターン | プレーヤー | 色 | 即時変更 | 走行調整 |

 | 1 | アリス | 1 | 0 | 0 |

base + adjustment = 0 + 1 = 1
```この例は、即時ゲインがゼロの動きでも、対戦相手がより価値のある色を要求するのを防ぐため、依然として最適である可能性があることを示しています。

 ## 特殊なケース

 対称的な位置を考えてみましょう。```
1
2
5 5
5 5
```どの色にもアリスゲインがあります`4`そしてボブ・ゲイン`-4`。 アリスは 1 つの色を選択し、ボブはもう 1 つの色を選択します。 調整は正確にキャンセルされ、最終的なスコアが得られます`0`。 DP は両方の可能性を検討し、同じ結果に達します。 

次に、次のことを考えてみましょう。```
1
2
100 1
1 100
```手つかずのスコアはゼロです。 アリスのゲイン値は`[0, 99]`、ボブのゲイン値は`[-99, 0]`。 アリスはすぐに 2 番目の色の価値を主張します`99`。 ボブは残りの色を取得することを余儀なくされます`-99`。 答えは次のようになります`198`。 現在の大理石の合計のみに基づく貪欲なルールでは、この相互作用を簡単に見逃してしまう可能性がありますが、minimax はこれを自然に処理します。 

最後に、片面に膨大な数のビー玉がある色を考えてみましょう。```
1
2
1000000000 1
1 1
```スコア調整には、次の値が含まれます。`10^9`。 Python の整数には任意の精度があるため、オーバーフローは発生しません。 DP はこれらの値を正確に保存して組み合わせ、正しい最適スコアを生成します。
