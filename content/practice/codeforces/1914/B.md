 ## 解決策
 ## 問題の理解

 私たちは困難を伴う問題を抱えています`1`を通して`n`。 これらの数値を、Monocarp が解く順序を表す順列に配置する必要があります。 

選択した順序で問題が直前の問題より難しい場合、Monocarp は興奮します。 比較する以前の問題がないため、最初に解決された問題はカウントされません。 

順列の場合`p`、位置で興奮が起こります`i > 1`いつ`p[i] > p[i-1]`。 タスクは、次の順列を構築することです。`1...n`それは正確に生成します`k`そういったポジション。 

制約は非常に小さいです。 テストケースは最大 1000 個まで存在できますが、`n`最大でも 50 です。`O(n²)`建設は簡単でしょう。 課題は効率ではなく、常に必要な数の増加する隣接ペアを正確に作成する単純な構造を見つけることです。 

よくある間違いは、興奮の数が順列の後半に現れる大きな要素の数に依存すると考えることです。 隣接する比較のみが重要です。 

たとえば、```
5 4 3 2 1
```シーケンスの前半に多数の大きな数値が存在するにもかかわらず、隣接する比較ごとに減少するため、興奮はゼロになります。 

別の簡単な落とし穴が現れるのは、`k = n - 1`。 その場合、隣接するすべての比較は増加する必要があるため、有効な並べ替えは厳密に増加する順序のみです。```
1 2 3 4 5
```誤って 1 つでも減少が導入された構築では、`n - 2`興奮。 

その反対の極端は、`k = 0`。 次に、隣接する比較はすべて減少する必要があるため、厳密に減少する順列が機能します。```
5 4 3 2 1
```大きな数字の前に小さな数字を配置する構造は、すぐに望ましくない興奮を引き起こします。 

## アプローチ

 ブルートフォースのアイデアは単純です。 の順列を生成します`1...n`、満たす位置がいくつあるか数えます`p[i] > p[i-1]`、カウントが等しいときに停止します`k`。 

カウント自体には時間がかかります`O(n)`順列あたりの時間。 問題は順列の数です。 がある`n!`可能性。 たとえ`n = 10`、これはすでに 360 万以上の順列となっており、網羅的な検索は非現実的です。 

重要な点は、検索する必要がないということです。 必要なのは、所定の数の増加する隣接するペアを含む順列だけです。 

数字を配置するとします```
1 2 3 ... k+1
```初めに。 このプレフィックス内の隣接する比較はすべて増加しているため、正確に寄与します。`k`興奮。 

次に、残りの数値を考えてみましょう。```
k+2, k+3, ..., n
```逆の順序で追加すると、次のようになります。```
n, n-1, ..., k+2
```その場合、そのサフィックス内のすべての比較は減少します。 

2 つの部分の境界はどうなるのでしょうか? 増加するプレフィックスの最後の要素は次のとおりです。`k+1`、反転されたサフィックスの最初の要素は次のとおりです。`n`。 以来`n > k+1`、この境界はさらに興奮をもたらします。 

つまり、上記の構築により、`k+1`興奮ではなく、`k`。 

これを修正するには、代わりに増加部分に正確に含まれるようにします。`k`数字:```
1 2 3 ... k
```そして残りを逆にします:```
n, n-1, ..., k+1
```間の比較`k`そして`n`が増えて、ひとつの興奮を与えます。 プレフィックス自体が寄与します`k-1`興奮。 一緒に：```
(k - 1) + 1 = k
```まさに私たちが必要としているものです。

 ## アルゴリズムのチュートリアル

 1. 数値を含むリストを作成します。`1, 2, ..., k`。 

このプレフィックス内には正確に次のものがあります`k - 1`隣接する比較を増やします。 
2. 残りの数字を取得します`k + 1, k + 2, ..., n`。 

これらはすべてまだ使用されていない値です。 
3. 残りの数字を逆の順序で追加します。```
n, n-1, ..., k+1
```このサフィックス内の隣接するすべての比較は減少しています。 
4. 結果の順列を出力します。 

2 つの部分の境界は、`k`に続く`n`、これはちょうど 1 つの追加の興奮に貢献します。 

### なぜ効果があるのか

 接頭語`1, 2, ..., k`含まれています`k-1`すべての隣接ペアが増加するため、隣接ペアが増加します。 

接尾語`n, n-1, ..., k+1`すべての隣接ペアが減少するため、増加する隣接ペアはゼロになります。 

境界を越える唯一の比較は、`k`そして`n`、そしてそれ以来`n > k`、それはちょうど 1 つの増加する隣接ペアに寄与します。 

したがって、興奮の総数は次のようになります。```
(k - 1) + 1 + 0 = k.
```いつ`k = 0`、プレフィックスは空であり、順列全体は次のようになります。```
n, n-1, ..., 1
```それは興奮がゼロです。 したがって、この構築はすべての有効な値に対して機能します。`k`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, k = map(int, input().split())

    ans = list(range(1, k + 1))
    ans.extend(range(n, k, -1))

    print(*ans)
```構築の最初の行は、増加するプレフィックスを作成します。`1...k`。 

2 行目は、残りのすべての数値を降順で追加します。 電話```
range(n, k, -1)
```生成する```
n, n-1, ..., k+1
```これはまさに証明に必要な接尾辞です。 

ケース`k = 0`自動的に処理されます。 それから```
range(1, 1)
```空のプレフィックスが生成され、サフィックスは次のようになります。```
n, n-1, ..., 1.
```特別な分岐は必要ありません。 

ケース`k = n - 1`も自然に処理されます。 プレフィックスは次のようになります```
1, 2, ..., n-1
```接尾辞には次のみが含まれます`n`、完全に増加する順列を生成します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n, k = map(int, input().split())
        ans = list(range(1, k + 1))
        ans.extend(range(n, k, -1))
        out.append(" ".join(map(str, ans)))

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

# provided sample properties
assert run("1\n6 2\n") == "1 2 6 5 4 3"

# minimum size, k = 0
assert run("1\n2 0\n") == "2 1"

# minimum size, k = 1
assert run("1\n2 1\n") == "1 2"

# fully increasing
assert run("1\n5 4\n") == "1 2 3 4 5"

# fully decreasing
assert run("1\n5 0\n") == "5 4 3 2 1"

# larger boundary case
assert run("1\n7 3\n") == "1 2 3 7 6 5 4"
```### テスト範囲の概要

 | テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 0`|`2 1`| 最小サイズ、興奮ゼロ |
 |`2 1`|`1 2`| 最小のサイズ、最大の興奮 |
 |`5 4`|`1 2 3 4 5`| 完全に増加する順列 |
 |`5 0`|`5 4 3 2 1`| 完全に減少する順列 |
 |`7 3`|`1 2 3 7 6 5 4`| 正しい境界寄与 |

 ## 特殊なケース

 ### ケース 1: 興奮しない

 入力:```
1
5 0
```プレフィックスが空です。 接尾辞は次のようになります。```
5 4 3 2 1
```隣接するすべての比較が減少するため、興奮カウントはゼロになります。 この構築により、必要な値が正確に生成されます。 

### ケース 2: 最大限の興奮

 入力:```
1
5 4
```プレフィックスは次のとおりです。```
1 2 3 4
```接尾辞には以下のみが含まれます。```
5
```最終的な置換は次のとおりです。```
1 2 3 4 5
```4 つの隣接する比較がすべて増加し、正確な値が得られます。`n - 1 = 4`興奮。 

### ケース 3: 境界の寄与

 入力:```
1
6 2
```この構造により次のことが得られます。```
1 2 6 5 4 3
```接頭辞は 1 つの興奮に貢献します (`1 → 2`）。 境界は 1 つの興奮に貢献します (`2 → 6`）。 サフィックスは何も寄与しません。 合計はちょうど2つです。 

このケースは、構築の背後にある中心的な考え方を示しています。プレフィックスは次のことを提供します。`k - 1`興奮、そして境界が最後の境界を提供します。
