 ## 解決策
 ## 問題の理解

 1 人から 6 人までの友人のグループがあります。ベンチにはちょうど 6 つの座席があり、すべてのグループが 1 つのベンチを占有する必要があります。 合計サイズが 6 を超えない限り、異なるグループがベンチを共有することができます。 

各テスト ケースについて、6 つの入力数値は、サイズ 1、2、3、4、5、および 6 のグループの数を示します。タスクは、ベンチの数を最小限に抑えることです。 

陽性者の総数は、1 つの検査ケースに対して最大 10,000 人です。 テスト ケースは最大 1,000 件あります。 各グループには少なくとも 1 人が含まれるため、1 つのテスト ケースには最大 10,000 のグループが存在します。 これは、すべてのグループにわたる線形スキャンには十分小さいですが、問題の構造により、より適切な処理が可能になります。最適な解は、一定数の算術演算のみを使用して計算できます。 可能なグループ化に対する二次探索や指数探索はまったく必要ありません。 

主なエッジケースは、ベンチをほぼ埋めるグループからのものです。 たとえば、```
1
1 0 0 0 0 0
```1 つのグループには 1 つのベンチが必要なので、答えは 1 です。 

と```
1
0 0 0 1 1 0
```4 人のグループと 2 人のグループがちょうど 1 つのベンチを埋めるため、答えも 1 になります。 人数の合計のみに基づいた不注意な解決策でもこのケースは正しく処理されますが、各グループ サイズを個別に処理する解決策では 2 つのベンチを使用する可能性があります。 

もう一つの境界ケースは、```
1
0 0 1 0 0 1
```ベンチが2つ必要です。 6 人のグループはベンチを誰とも共有できませんが、3 人のグループにはもう 1 つのベンチが必要です。 

少人数のグループでは逆の間違いが起こります。 のために```
1
8 0 0 0 0 0
```1 人のグループが 8 つあるので、答えは 8 ではなく 2 です。6 つのグループが 1 つのベンチを共有し、残りの 2 つが別のベンチを共有できます。 

## アプローチ

 直接的な総当たりの解決策では、すべてのグループをアイテムとして扱い、可能なすべてのベンチ割り当てを再帰的に試行します。 グループを処理するときは、それを互換性のある既存のベンチに入れることも、新しいベンチを開くこともできます。 これは正しいです。考えられるすべての座席配置が検索の分岐によって表されるからです。 

問題はアレンジメントの数です。 (n) 個のグループがある場合、それらをベンチの任意のセットに割り当てることは、セットのパーティションを列挙することに関連しており、そのカウントはベル数 (B_n) です。 グループが 10,000 もある場合、(n^n = 10000^{10000}) などのはるかに小さい上限でさえ、すでに絶望的です。 ブルートフォース手法は、指定された制限に対して遅すぎるだけでなく、比較的小さな入力に対してさえ実行不可能です。 

問題を起こしやすい構造はベンチ定員が6人固定であること。 大規模なグループには、パートナー候補がほとんどいません。 6人グループにはパートナーがいません。 5 人のグループは 1 人のグループとのみペアリングできます。 4人グループなら2人グループでも、1人グループでも2つ利用できます。 3 人のグループは、別の 3 人とペアになったり、より小さなグループを使用して残りの席を埋めることができます。 最後に、2 人のグループはベンチごとに最大 3 人まで詰めることができ、1 人のグループは残っている席をすべて埋めることができます。 

これにより、貪欲な戦略が得られます。 常に最大の有用な補完グループを使用して、より大きなグループを最初に処理します。 より大きなグループが配置されると、残りの問題はサイズ 2 と 1 のグループのみで構成され、最適なパッキングが即座に行われます。 

重要なのは、単に「大きなグループを最初に置く」ということではありません。 それぞれの貪欲な選択は、大規模なグループの方が小規模なグループよりも配置可能な場所が少ないという事実によって正当化できます。 5 人のグループは 2 人や 3 人のグループを使用することはできません。そのため、1 人のグループをそれに費やすことは、そのグループを他の選択肢のあるグループに残すことよりも悪いことはありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(B_n)) | (O(n)) | 遅すぎる |
 | 最適な貪欲さ | テスト ケースごとの (O(1)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. サイズ 1 ～ 6 のグループの数を読み取ります。それらを (c_1,c_2,\ldots,c_6) とします。 
2. サイズ 6 の各グループをそれぞれのベンチに置きます。 このようなグループには、別のグループが使用できる残存容量がないため、これらのベンチは強制的に使用されます。 
3. サイズ 5 のグループを処理します。各グループには 5 つの座席が必要で、サイズ 1 の 1 つのグループとのみ共有できます。できるだけ多くの 5 グループを 1 グループとペアにし、残りの 1 グループは脇に置きます。 
4. サイズ 4 のグループを処理します。最初にそれらをサイズ 2 のグループと組み合わせます。(4+2) の組み合わせでベンチが正確に埋められます。 有用な 2 グループをすべて使用した後、さらに 4 グループがある場合は、残りの 4 グループごとに最大 2 つの 1 グループを配置します。 

1 グループが 2 つある場合でも、4 と 2 の組み合わせは安全です。 どちらの場合でも、4 グループにはすでにベンチが必要であり、代替の配置によって他のグループに必要なベンチの数は減りません。 
5. サイズ 3 のグループを互いにペアにします。 3 グループの各ペアが 1 つのベンチを正確に埋めるため、(\lfloor c_3/2\rfloor) ベンチが強制されます。 
6. 3 グループが 1 つ残っている場合は、そのグループのためにもう 1 つのベンチを開きます。 2 グループが利用可能な場合は、3 グループと一緒に配置します。 1 グループも利用可能な場合は、同じベンチに参加して、(3+2+1=6) を生成できます。 2 グループがない場合は、残りの席に 1 グループを 3 つまで埋めます。

残りの 2 グループを 1 つ使用しても、一致しない 3 グループを使用しても、答えは増加しません。 1 つの 2 グループを削除すると、残りのすべての 2 グループに必要なベンチの数が (\lceil b/3\rceil) から (\lceil(b-1)/3\rceil) に変わりますが、これは変わらないか、または減少することしかありません。 
7. 残っているグループはサイズ 1 と 2 だけです。2 つのグループをベンチごとに 3 つ詰めます。 (b) 2 つのグループが残っている場合は、(\lceil b/3\rceil) 個のベンチが必要です。 これらのベンチには (6\lceil b/3\rceil-2b) の未使用の席があるため、それらの席をできるだけ多くの 1 グループで埋めてください。 
8. まだ残っている 1 グループには、6 グループごとに 1 つのベンチが必要です (上向きに切り上げ)。 この番号を答えに追加して印刷します。 

### なぜ効果があるのか

 不変条件は、グループ サイズを最大から最小まで処理した後、すべての処理済みグループが、未処理のグループに必要なベンチの最小数を増やせない方法で配置されることです。 

サイズ6のグループには選択肢がありません。 サイズ 5 グループはサイズ 1 グループのみを使用できるため、1 グループが存在する場合は必ずペアリングが強制されます。 サイズ 4 のグループは、2 グループまたは 2 つの 1 グループのいずれかを使用でき、最初に 2 グループを使用しても、後で追加のベンチがかかることはありません。 サイズ 3 グループは互いに最適にペアリングされ、一致しない 3 グループが最大 1 つ残ります。 その後、サイズ 2 と 1 だけが残り、1 つのベンチで可能な最大数は 2 グループ 3 つであるため、(\lceil c_2/3\rceil) ベンチが必要になります。 未使用の席を 1 グループで埋めることは問題にはなりません。そうしなければ空席になるからです。 残りの 1 グループには正確に (\lceil c_1/6\rceil) のベンチが必要です。 

したがって、すべての決定は強制されるか、またはベンチを使用せずに可能なパッキングを別のパッキングに置き換えることになります。 したがって、最終的なカウントは最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(c):
    c1, c2, c3, c4, c5, c6 = c

    ans = c6

    # Groups of 5 can only share with groups of 1.
    use = min(c1, c5)
    c1 -= use
    ans += c5

    # Groups of 4 should use groups of 2 first.
    use = min(c2, c4)
    c2 -= use
    remaining4 = c4 - use
    ans += c4

    # Remaining groups of 4 can take two groups of 1 each.
    use = min(c1, 2 * remaining4)
    c1 -= use

    # Pair groups of 3.
    ans += c3 // 2

    # One group of 3 may remain.
    if c3 % 2:
        ans += 1

        if c2 > 0:
            c2 -= 1
            if c1 > 0:
                c1 -= 1
        else:
            c1 -= min(c1, 3)

    # Pack groups of 2, three per bench.
    benches2 = (c2 + 2) // 3
    ans += benches2

    # Use the unused seats on those benches for groups of 1.
    free = 6 * benches2 - 2 * c2
    c1 = max(0, c1 - free)

    # Remaining groups of 1, six per bench.
    ans += (c1 + 5) // 6

    return ans

def main():
    t = int(input())
    out = []

    for _ in range(t):
        c = list(map(int, input().split()))
        out.append(str(solve_case(c)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```内側の最初の 3 行`solve_case`6 つのグループ数を解凍します。 答えは、サイズ 6 のすべてのグループから始まります。なぜなら、各グループがベンチ全体を消費するからです。 

サイズ5の場合、`min(c1, c5)`5 グループが 1 グループを受信できる正確な数を示します。 残りの 1 グループは、より小さなグループ用に保存されます。 

サイズ 4 の場合、コードは最初にできるだけ多くの 2 グループを削除します。`remaining4`は 2 グループを取得できなかった 4 グループの数なので、それぞれに 2 つの 1 グループが入る余地があります。 表現`2 * remaining4`利用可能な座席の合計数です。 

サイズ 3 の処理では、整数の除算を使用して 3 つのグループをペアにします。 の`% 2`ブランチは、一致しない可能性のある 1 つのグループを処理します。 3 グループと 2 グループでは配置が困難になる容量を使用するため、コードでは残りの 2 グループを優先します。 1組も空いていればベンチはちょうど満席になる。 

残りの2グループについては、`(c2 + 2) // 3`(\lceil c_2/3\rceil) の整数形式です。 これらのベンチの空き座席の数は、次のように直接計算されます。`6 * benches2 - 2 * c2`。 残りの 1 グループはベンチごとに 6 つにグループ化されます。 

すべての値は負ではなく、Python の整数はオーバーフローしません。 の使用`min`そして`max`また、残りのカウントが負になるのを防ぎます。

 ## 特殊なケース

 1 つの単一グループの場合、入力は次のようになります。`1 0 0 0 0 0`。 アルゴリズムは、より大きなグループをすべてスキップし、最終的なサイズ 1 の計算に到達し、`(1 + 5) // 6 = 1`。 結果はちょうど 1 つのベンチです。 

6 人のグループの場合、入力は次のようになります。`0 0 0 0 0 1`。 初期の`ans = c6`すぐにベンチを 1 つ提供します。 このグループの容量はすでにいっぱいであるため、他の操作でこのグループと何かを結合することはできません。 

ぴったりフィットするケースの場合`0 1 0 1 0 0`、サイズ 4 グループはサイズ 2 グループを消費します。 アルゴリズムは 4 グループにベンチを 1 つ追加し、2 グループを削除して、正解 1 を生成します。 

3 人のグループと 2 人のグループおよび 1 人のグループが一致しない場合、入力`1 1 1 0 0 0`size-3支店で取り扱っております。 残りの 3 グループは 2 グループと 1 グループを消費し、6 席の完全に埋まった 1 つのベンチが得られます。 

1 つのグループが多数ある場合、入力`10000 0 0 0 0 0`やっと最終段階に到達。 各ベンチには 6 つのグループが収まるので、答えは (\lceil10000/6\rceil=1667) になります。 天井は次のように実装されます`(c1 + 5) // 6`、浮動小数点演算を回避します。 

最もデリケートなケースは、3 グループは残っているが 1 グループが存在しない場合です。 例えば、`0 1 1 0 0 0`1 つの 3 グループと 1 つの 2 グループが与えられます。 アルゴリズムはそれらをまとめて、未使用の 1 つの座席を残します。 それらを分離すると 2 つのベンチが必要になりますが、既存の 3 グループ上で 2 グループを使用しても、残りの 2 グループに必要なベンチの数を増やすことができないため、これは依然として最適です。
