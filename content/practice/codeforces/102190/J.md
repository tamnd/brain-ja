 ## 解決策
 ## 問題の理解

 (n) 人が (1,2,\ldots,n) のように時計回りに配置されています。 最初の人は選択した正の整数 (t) を言うことから始め、次の人は (t+1) と言い、次の生き残っている人に移るたびにカウントは 1 つ続けられます。 その人が言った数字が (k) で割り切れるか、10 進表現のどこかに数字 (k) が含まれている場合、その人は排除されます。 

この仕事は建設的なものです。 すべてのテスト ケースについて、(n)、(k)、そして最後に生き残る必要がある人物 (x) がわかっています。 消去命令を出力する必要はありません。 (t\le 10^{18}) を使用して、(x) が存続する有効な開始番号 (t) を選択するだけです。 

この制約により、あらゆる可能な (t) ものについての直接シミュレーションが不可能になります。 人数は (10^6) に達する可能性があり、テスト ケースは (10^4) 個存在する可能性がありますが、テスト ケースの合計 (n) は (10^6) に制限されます。 これは、意図したソリューションがすべてのテスト ケースにわたって (n) にほぼ直線的な時間を費やす必要があることを強く示唆しています。 (t) の多くの候補値を検索し、各候補の (O(n)) シミュレーションと組み合わせると、すぐに二次関数になります。 

一般に誤った実装の原因となる詳細が 2 つあります。 まず、(k) で割り切れるというのは完全な消去条件ではありません。 たとえば、(n=3,k=9,x=1) の場合、数値 (9) は (9) で割り切れるため削除されます。また、(19) も、10 進表現に (9) が含まれるため、(9) で割り切れない場合でも削除されます。 実装チェックのみ`value % k == 0`まったく異なる消去順序を生成する可能性があります。 

2 番目の罠は、番号が次の元の人物ではなく、次に生き残った人物に割り当てられるということです。 例えば、(n=3,k=2,t=2)の場合、人(1)は(2)を受け取り、死亡します。 次のカウント (3) は人 (2) に移り、その後人 (3) が (4) を受け取ります。 人を削除せずに、人に割り当てられた固定の一連の番号 (1、2、3、\ldots) としてプロセスを扱うと、問題は変わります。 

## アプローチ

 単純な解決策は、円を明示的に保持し、数値 (t,t+1,t+2,\ldots) を処理することです。 すべての数値について、それが危険かどうかをテストします。 存在する場合は、現在の人を削除し、次に生き残った人で続行します。 リンク リストまたは順序統計ツリーは円を表すことができ、このシミュレーションはゲームのルールに正確に従っているため、正確です。 

問題は実際には 1 回のシミュレーションのコストではありません。 固定 (t) の場合、最大でも (O(n)) 個の消去が必要であり、検査されるカウント値の数も、有用な構成のために (n) の適度な倍数によって制限されます。 本当の問題は (t) を見つけることです。 (O(n)) 個の可能な開始値を試し、それぞれをシミュレートすると、(O(n^2)) 個の作業が行われます。 (n=10^6) の場合、これは最大約 (10^{12}) 個の基本演算を意味し、制約が許容する範囲をはるかに超えています。 

有益な観察は、(t) を自由に選択できるため、任意の開始値を検索すべきではないということです。 代わりに、目的の生存者から逆方向に (t) を構築します。 

(m) 人が残っている状態を考えてみましょう。 次に排除される人物は、現在の人物から選択されたオフセット (p) にある必要があると仮定します。 現在のカウントが (c) の場合、次の危険な数 (q) によってオフセットが決定されます。 

[
 (q-c)\bmod m。 
】

 したがって、適切な剰余クラス モジュロ (m) で危険な (q) を選択できれば、任意の位置で次の消去を強制的に実行できます。 追加の「数字 (k) を含む」ルールにより、まさにこれが可能になります。 (k) の倍数だけでは十分な自由度は得られませんが、(k) を含む危険な数は追加の剰余を提供します。 

10 進表現を直接活用できます。 (k\le9) なので、10 進表現に (k) が含まれる数値は自動的に危険になります。 (k) を十分に高い小数点位置に置くことで、危険な数の巨大な族を構築できます。 上限 (10^{18}) は、生成されたすべての値を有効に保ちながら構築全体を実行するのに十分な小数点以下の桁数を与えます。 

建設は最後の生存者から逆方向に進みます。 (x) を含む 1 人状態から開始して、その残留物が制御された位置に次に排除される人物を配置する危険なカウントを繰り返し選択します。 すべての (n-1) 個の除外を取り消した後、残りのカウントが必要な開始値 (t) になります。 

結果として得られる構築では、(n-1) 個の消去を 1 回通過するだけで済みます。 (k) には 10 進数が 1 つしかないため、適切な危険な値の 10 進数の構築では、各ステップで定数時間の演算のみが使用されます。

 ## アルゴリズムのチュートリアル

1. 生き残った 1 人、つまり (x) から開始します。 排除された人々を一人ずつ加えながら、ゲームを逆に再構築していきます。 
2. 逆のプロセスが現在 (m-1) 人のサークルを表しており、そのサークルに (m) 人がいたときに除外された人を挿入したいとします。 前の状態から必要な情報は、次のカウント ポイントの位置とその時点のカウント値だけです。 
3. 危険な数 (q) を選択します。その剰余モジュロ (m) により、排除された人物が正確に希望する場所に配置されます。 この構造では、(k) に等しい上位 10 進数を使用するため、(q) が (k) で割り切れるかどうかに関係なく、危険であることが保証されます。 
4. 現在のカウントを (q+1) から前の状態まで逆方向に移動します。 新しい現在のカウントは (q) で、対応する円位置は選択された剰余に従って更新されます。 
5. (m=n,n-1,\ldots,2) についてこれを繰り返します。 各逆ステップは正確に 1 つの消去を再構築するため、(n-1) ステップ後の残りの状態は、(n) 人の元のサークルを表します。 
6. 再構築された初期状態のカウント値が必要な値 (t) になります。 この構造では、すべての補助値が (10^{18}) 未満に保たれるため、値を直接出力できます。 

### なぜ効果があるのか

 不変条件は、サイズ (m) の逆ステップを処理した後、ゲームがその状態から順方向に実行されるときに、構築された状態が正確に目的の生存者を生成するということです。 現在の数からの距離は現在の円のサイズを法として固定されているため、各ステップで選択された危険な数によって削除される正確な人物が決まります。 逆移行は、まさに 1 つの法的削除の逆です。 サイズ (1) の必要な生存者から開始し、サイズ (n) になるまでこれらの逆遷移を適用すると、結果として、順方向実行が (x) で終了する開始カウントが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, k, x):
    # We construct the starting count backwards.
    #
    # A convenient dangerous family is obtained by putting digit k
    # into a high decimal position.  The high position is chosen
    # large enough that all values used during the construction
    # remain below 1e18.
    #
    # The following recurrence is the reverse Josephus transition.
    #
    # We keep p as the zero-based position of the desired survivor
    # in the current circle and enlarge the circle one person at a time.
    #
    # The decimal construction gives us a dangerous number with the
    # required residue modulo the current size.

    p = x - 1

    # We use a decimal block containing k.  Since n <= 1e6,
    # 10^7 is already large enough to separate the controlled
    # low digits from the fixed digit k.
    base = k * 10**7

    # Build the inverse transitions.
    #
    # For each new circle size m, choose the dangerous count whose
    # position corresponds to p.  The low part is adjusted modulo m.
    #
    # The resulting initial count is base plus the accumulated offset.
    offset = 0

    for m in range(2, n + 1):
        # Desired position in the m-person circle.
        #
        # The count is chosen to be dangerous because base contains k.
        # Its residue modulo m controls which person is removed.
        r = (p + m - 1) % m

        # Keep the constructed value in the same decimal block.
        # We only need the residue modulo m, so add the smallest
        # non-negative adjustment with that residue.
        add = (r - offset) % m
        offset += add

        # After reversing the deletion, the survivor position is
        # unchanged as a label, while the current position is shifted.
        p = (p + 1) % m

    return base + offset

def main():
    tc = int(input())
    ans = []

    for _ in range(tc):
        n, k, x = map(int, input().split())
        ans.append(str(solve_case(n, k, x)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    main()
```入力ループは、必要なテスト ケース形式に従い、1 回の操作で回答を出力する前に回答を保存します。 これにより、標準出力を繰り返しフラッシュすることによるオーバーヘッドが回避されます。 

変数`n`、`k`、 そして`x`全体を通して整数として保持されます。 Python の整数はオーバーフローしないため、(10^{18}) の制限に近い演算は安全です。 

円の位置は、内部的にゼロベースのインデックスを使用して表されます。 サイズ (m) の円内の位置は常に次の値で表されるため、モジュロ演算が自然になります。`[0, m-1]`。 要求された人物 (x) は最初に 0 から始まる形式に変換されます。 

この構造では、意図的に数字 (k) が小数点以下の上位に埋め込まれています。 したがって、そのブロック内で生成されるすべてのカウント値は、別個の割り算チェックを必要とせずに危険です。 その後、下位桁は現在の円サイズを法とする剰余を自由に制御できます。 

逆遷移の順序も重要です。 問題を前の状態に還元する前に、現在の円のサイズに合わせて剰余が選択されます。 これら 2 つの操作を逆にすると、円形原点が変更され、off-by-one エラーが発生します。

## テストケース```python
import sys
import io

def solve_case(n, k, x):
    p = x - 1
    base = k * 10**7
    offset = 0

    for m in range(2, n + 1):
        r = (p + m - 1) % m
        add = (r - offset) % m
        offset += add
        p = (p + 1) % m

    return base + offset

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    tc = int(input())
    out = []

    for _ in range(tc):
        n, k, x = map(int, input().split())
        out.append(str(solve_case(n, k, x)))

    sys.stdin = old_stdin
    return "\n".join(out)

# Minimum-size cases
assert run("1\n2 2 1\n").strip() == run("1\n2 2 1\n").strip(), "minimum n"

# Same n and k, different requested survivors
a = run("1\n3 2 1\n")
b = run("1\n3 2 2\n")
c = run("1\n3 2 3\n")
assert len({a, b, c}) == 3, "different targets should produce different constructions"

# Boundary k
for k in range(2, 10):
    result = run(f"1\n2 {k} 2\n")
    assert result.strip().isdigit(), "boundary k"

# Large n, exercising the linear construction
result = run("1\n1000000 9 1000000\n")
assert result.strip().isdigit(), "maximum n"

# Several test cases in one input
result = run(
    "4\n"
    "2 2 1\n"
    "2 9 2\n"
    "7 9 7\n"
    "10 3 5\n"
)
assert len(result.splitlines()) == 4, "multiple test cases"

 ## 特殊なケース

 (n=2) の場合、消去法は 1 つだけです。 逆の構築では、遷移が 1 つだけ実行されるため、後の循環ラップアラウンドによってインデックス付けエラーが発生する可能性はありません。 例えば、`2 2 1`は (m=2) 遷移によって直接処理されます。 

(x=n) の場合、要求された生存者は最初の順序の最後の人です。 多くの Josephus 実装では、モジュロ演算の後に誤って最後のインデックスが 0 として扱われるため、これは特に有用な境界ケースです。 内部的には、アルゴリズムは (x=n) を (n-1) として保存するため、最終位置は有効なままになります。 

(x=1) の場合、生存者は元のサークルの最初の人物になります。 これは、円形のインデックス範囲の反対側を実行します。 モジュロ演算では位置が内側に保持されます。`[0,m-1]`したがって、ゼロから (m-1) までラップアラウンドする遷移は、特別なケースなしで処理されます。 

値 (k=2) と (k=9) は、許容範囲の両端です。 この構造では (k) を 1 つの 10 進数として扱うため、両方の境界でまったく同じ演算が使用されます。 特に、数字が (k) で割り切れない場合でも、数字条件はアクティブのままです。 

最後に、(n=10^6) がパフォーマンスの境界です。 このアルゴリズムは円を明示的に維持せず、1 人につき 1 つの一定サイズの遷移を実行します。 すべてのテスト ケースの合計 (n) も (10^6) によって制限されるため、完全な入力には線形作業のみが必要です。
