 ## 解決策
 ## 問題の理解

 (n) 個の頂点上に完全な無向グラフができました。 (n-1) ラウンドのそれぞれの間に、以前に使用されていなかった 2 つのエッジを提示する必要があります。 ドナルドはそれらの 1 つを赤いグラフに割り当て、もう 1 つを緑のグラフに割り当てます。 彼の選択はランダムですが、私たちの戦略は考えられるどちらの答えに対しても機能する必要があります。 

正確に (n-1) 回の丸めを行った後、各色は正確に (n-1) 個のエッジを持ちます。 両方のカラー クラスがスパニング ツリーを形成する場合にのみ勝利します。 

主な難点は、1 ラウンドで提示された 2 つのエッジは再利用できないことです。ドナルドはペアを見た後でのみ、どのエッジがどのツリーに属するかを決定します。 どのエッジがどの色になるかを制御できないため、特定の 1 つの赤いツリーと 1 つの特定の緑のツリーを構築するだけの戦略では十分ではありません。 

境界 (n\le 10^5) は、すべての合計 (n) の境界と合わせて、2 次数のエッジを検査するものを除外します。 幸いなことに、完全なグラフにより、未使用のエッジが大量に得られます。 このソリューションは、最初の 5 つの頂点に一定量の労力のみを費やし、ドナルドの答えに関係なく安全な方法で残りのすべての頂点をアタッチします。 

下限 (n\ge5) はまさにこれを可能にするものです。 同じ一定サイズの構築には 4 つの頂点では十分ではありませんが、5 つの頂点があると、徹底的な探索によって完全に解決できる小さなゲームが得られます。 

元の問題は対話型であるため、表示されるサンプルは通常の入出力ペアではなく、通信記録です。 たとえば、次のような行```
3 4 1 5
```は、プログラムがエッジ ((3,4)) と ((1,5)) を提案し、その後インタラクターが次の回答を提供することを意味します。 これは、通常のバッチ プログラムに供給できるスタンドアロンのテスト ケースではありません。 サンプルを通常の入力として解析しようとする不注意なオフライン実装では、結果としてデータを意味のある解釈することができなくなります。 

もう 1 つの微妙なケースは (n=5) です。 一定サイズの構築後に余分な頂点は存在しないため、5 つの頂点自体での完全なゲームを解決する必要があります。 このソリューションは、(K_5) の勝利戦略を事前計算することで、まさにこのケースを処理します。 

(n>5) の場合、追加の頂点 (i) はすべて ((1,i))、((2,i)) のペアで処理されます。 このラウンドの前には、頂点 (i) にはどちらのツリーにもエッジがありません。 ドナルドが色に割り当てたこれら 2 つのエッジのどちらも、孤立した頂点 (i) をすでに接続されているコンポーネントに接続するため、サイクルを作成することはできません。 他の色は他のエッジを取得し、まったく同じ理由で安全です。 

## アプローチ

 直接的な総当たりアプローチでは、考えられるすべての通信履歴を検索しようとします。 各ターンで 2 つの未使用のエッジから (\binom{m}{2}) 個の選択肢があり、ドナルドには 2 つの可能な答えがあります。 (K_5) であっても、手作業で設計されたソリューションにはこれは不要ですが、グラフ全体では可能性の数は膨大です。 (n=10^5) では、最初のラウンドだけでもおよそ (5\cdot10^9) 個の可能なエッジのペアがあるため、グラフ全体を検索することは完全に非現実的です。 

有益な観察は、実際には大きなグラフを解く必要がないということです。 5 つの頂点の固定セット上に 2 つのスパニング ツリーを作成すると、追加の頂点をすべて独立してアタッチできます。 

頂点 (1,\ldots,5) がすでに赤い木と緑の木を形成しているとします。 新しい頂点 (i) の場合、2 つのエッジ ((1,i)) と ((2,i)) を提示します。 このターンの前に、(i) は両方のツリーで分離されます。 ドナルドは一方のエッジを赤に、もう一方のエッジを緑に与えるので、両方の木は (i) に関連する 1 つのエッジを正確に取得します。 (i) は以前は次数 0 を持っていたため、どちらの加算も循環を形成できません。 2 本の木は手術後も木のままです。 

これにより、問題全体が (K_5) 上の一定サイズのゲームに縮小されます。 可能なエッジは 10 個だけで、ターンはちょうど 4 つだけです。 この 4 ターンの賢いクローズドフォーム戦略を発見しようとする代わりに、動的プログラミングを使用してこの小さなゲームを徹底的に解決できます。 状態は、現在どのエッジが赤いツリーに属し、どのエッジが緑のツリーに属しているかを記録します。 すべての状態について、未使用のエッジのすべてのペアを試し、ドナルドからの考えられる答えが両方とも勝利状態につながる場合はペアを保持します。 

徹底的な検索は 10 個のエッジに対してのみ実行されます。 そのコストは (n) に依存しない固定定数ですが、その後の実際のインタラクションは追加の頂点ごとに 1 つの操作で構成されます。 結果として得られる戦略は (n) において線形です。

 | フルゲーム総当たり | (n^2) の指数 | (n^2) の指数 | 遅すぎる |
 | 徹底(K_5)攻略＋アタッチメント | (O(n)) 定数前処理後 | (O(1)) 再帰テーブルは別 | 承認済み |

 ## アルゴリズムのチュートリアル

1. 頂点 (1、2、3、4、5) をコアとして予約します。 網羅的戦略で使用されるすべてのエッジは完全にこの (K_5) 内にあります。 
2. (K_5) の 10 個のエッジを列挙し、それらのすべてのサブセットを 10 ビット マスクで表します。 1 つのマスクは赤色のエッジを記述し、もう 1 つのマスクは緑色のエッジを記述します。 
3. 状態をマスクのペア ((R,G)) として定義します。 エッジは、そのビットがどちらのマスクにも存在しない場合には使用されません。 各ターンは 2 つのエッジを消費するため、すでにプレイされたターン数は (\operatorname{popcount}(R\mathbin{|}G)/2) になります。 
4. プレイされたターンが 4 ターン未満のすべての状態について、未使用の個別のエッジ (e_1、e_2) のすべてのペアを試します。 ドナルドには、正確に 2 つの結果が考えられます。 最初の結果では、(e_1) が赤になり、(e_2) が緑になります。 2 番目では、色が交換されます。 
5. 結果として得られる両方の状態が勝っている場合、(e_1,e_2) をその状態の勝ち手として保持します。 再帰はメモ化されているため、すべての状態は 1 回だけ解決されます。 
6. 4 つのターンで、ちょうど 8 つのコア エッジが使用されています。 赤と緑の両方に 5 つのコア頂点上にツリーを形成する 4 つのエッジが含まれている場合、状態は勝ちです。 各色には 4 つのエッジがあるため、非循環性はスパニング ツリーであることと同等ですが、実装では接続性とエッジ数を直接チェックするだけです。 
7. 実際のインタラクション中は、空のコア状態から開始し、現在の状態に対して事前に計算された移動を使用します。 両端を印刷し、すぐに洗い流します。 
8. ドナルドの答えを読みます。 もしそうなら`0`、最初のエッジを赤に、2番目のエッジを緑に配置します。 もしそうなら`1`、最初のエッジを緑に、2番目のエッジを赤に配置します。 事前計算では 2 つの後続候補が勝っている手だけが選択されたため、結果として得られる状態は勝ち続けることが保証されます。 
9. 4 つのコアが回転した後、すべての頂点 (i=6,\ldots,n) をペア ((1,i))、((2,i)) で処理します。 ドナルドが赤に送信したエッジは、既に接続されている赤のツリーのコアに接続され (i)、もう一方のエッジは緑に対しても同じことを行います。 
10. インタラクターは現在のエッジのペアを受信するまで応答できないため、クエリのたびにフラッシュします。 最終応答の後、プログラムは終了できます。 

### なぜ効果があるのか

 最初の 4 ラウンドの間の不変条件は、現在の (K_5) 状態がダイナミック プログラミング ゲームの勝利状態であるということです。 構造上、選択された手には 2 つの後継手があり、どちらも勝っているため、ドナルドの答えは不変条件を破ることはできません。 

4 ラウンド後、両方の色が頂点 (1,\ldots,5) のツリーにまたがります。 後のすべての頂点 (i) について、各色は (i) に付随するエッジを 1 つだけ受け取ります。(i) は操作前にその色から分離されています。 孤立した頂点から接続されたツリーにエッジを追加すると、ツリーのプロパティが保持されます。 したがって、残りのすべての頂点を処理した後、各色は新しい頂点ごとに 1 つの追加のリーフを持ち、スパニング ツリーのままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from functools import lru_cache
from itertools import combinations

# The ten edges of K5, indexed from 0 to 9.
core_edges = []
for u in range(1, 6):
    for v in range(u + 1, 6):
        core_edges.append((u, v))

M = len(core_edges)

def is_tree(mask):
    """Return True iff mask is a spanning tree of K5."""
    if mask.bit_count() != 4:
        return False

    parent = list(range(6))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    for i, (u, v) in enumerate(core_edges):
        if mask >> i & 1:
            ru = find(u)
            rv = find(v)
            if ru == rv:
                return False
            parent[ru] = rv

    root = find(1)
    for v in range(2, 6):
        if find(v) != root:
            return False

    return True

tree_masks = set()
for comb in combinations(range(M), 4):
    mask = 0
    for e in comb:
        mask |= 1 << e
    if is_tree(mask):
        tree_masks.add(mask)

winning_move = {}

@lru_cache(maxsize=None)
def win(red, green):
    used = red | green

    if used.bit_count() == 8:
        return red in tree_masks and green in tree_masks

    unused = [i for i in range(M) if not (used >> i & 1)]

    for a_pos in range(len(unused)):
        a = unused[a_pos]
        for b_pos in range(a_pos + 1, len(unused)):
            b = unused[b_pos]

            # Donald gives a to red and b to green.
            if not win(red | (1 << a), green | (1 << b)):
                continue

            # Donald gives b to red and a to green.
            if not win(red | (1 << b), green | (1 << a)):
                continue

            winning_move[(red, green)] = (a, b)
            return True

    return False

assert win(0, 0)

def interactive_solve():
    t = int(input())

    for _ in range(t):
        n = int(input())

        red = 0
        green = 0

        # Solve the complete game on the first five vertices.
        for _turn in range(4):
            a, b = winning_move[(red, green)]
            u1, v1 = core_edges[a]
            u2, v2 = core_edges[b]

            print(u1, v1, u2, v2, flush=True)

            ans = int(input())

            if ans == 0:
                red |= 1 << a
                green |= 1 << b
            else:
                green |= 1 << a
                red |= 1 << b

        # Every remaining vertex is attached to both core trees.
        for v in range(6, n + 1):
            print(1, v, 2, v, flush=True)
            ans = int(input())

            # No further state is needed. Both possibilities are safe.
            if ans < 0:
                return

interactive_solve()
```プログラムの最初の部分は、(K_5) の 10 個のエッジを構築します。 戦略テーブルにはエッジ インデックスが格納されており、手が印刷されるたびに同じ順序が使用されるため、それらの正確な順序は関係ありません。`is_tree`(K_5) の 4 つのエッジのサブセットをチェックします。 このようなサブセットは (\binom{10}{4}=210) 個だけであるため、それらすべてをテストするのは事実上定数時間です。 小さな素セット構造により、テストが簡単になります。`win(red, green)`コアゲームソルバーです。 労働組合`red | green`どのエッジがすでに消費されているかを示します。 すべての再帰的遷移は、それまでに使用されていなかったエッジをちょうど 2 つ消費するため、8 つの使用済みエッジの後、4 ターンのコア ゲームが終了します。 

2 つの再帰呼び出しが中心的な正確性条件です。 候補ペアは、両方の色の割り当てが勝っている場合にのみ受け入れられます。 私たちはドナルドがランダムであることに決して依存しません。 どちらの答えでも戦略は成功するため、ステートメントの確率 (1/2) は正しさとは無関係です。 

の`winning_move`ディクショナリには、再帰によって到達した状態ごとに 1 つの成功したペアが格納されます。 実際の対話フェーズでは、検索を再度実行することなく、すぐにペアを検索できます。 

外部頂点ループは常に出力します。`(1,v)`そして`(2,v)`。 コアでは頂点 (1,\ldots,5) のみが使用され、以降の各頂点には独自の 2 つのエッジがあるため、これらのエッジはコア ゲームには表示されません。 エッジが偶然に繰り返されることはありません。 

の`flush=True`引数は必須です。 これがないと、Python はクエリをバッファリングし、インタラクターはプログラムの出力バッファーに残っている出力を永遠に待機する可能性があります。 

答えは`0`は最初の印刷エッジが赤であることを意味します。`1`最初の印刷エッジが緑色であることを意味します。 これら 2 つのケースを逆にすることは、対話型プログラミングの一般的なバグです。

## テストケース

 元の問題は対話型であるため、実稼働プログラムは固定入力文字列を使用して呼び出すだけではテストできません。 適切なオフライン テストでは、所定の回答を提供する偽のインタラクターを使用し、クエリされたすべてのエッジが正当であること、および最終的な赤と緑のグラフがツリーであることをチェックします。 

次のテスト ハーネスは、同じコア戦略を抽出し、ドナルドをシミュレートします。 決定的な極端な応答と混合応答の両方を含む、いくつかの応答シーケンスをチェックします。```python
import io
import sys
from itertools import combinations
from functools import lru_cache

core_edges = []
for u in range(1, 6):
    for v in range(u + 1, 6):
        core_edges.append((u, v))

def is_tree(mask):
    if mask.bit_count() != 4:
        return False

    parent = list(range(6))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    for i, (u, v) in enumerate(core_edges):
        if mask >> i & 1:
            a = find(u)
            b = find(v)
            if a == b:
                return False
            parent[a] = b

    root = find(1)
    return all(find(v) == root for v in range(2, 6))

tree_masks = set()
for c in combinations(range(10), 4):
    mask = 0
    for x in c:
        mask |= 1 << x
    if is_tree(mask):

moves = {}

@lru_cache(None)
def win(r, g):

    if used.bit_count() == 8:

        for jj in range(ii + 1, len(unused)):

            b = unused[jj]

            if not win(r | (1 << b), g | (1 << a)):

            return True

                gmask |= 1 << b
                red.add(e1)
                green.add(e2)
            else:
                gmask |= 1 << a
                rmask |= 1 << b
                green.add(e1)
                red.add(e2)

        else:
            v = turn + 2
            e1 = (1, v)
            e2 = (2, v)

            if answers[answer_pos] == 0:
                red.add(e1)
                green.add(e2)
            else:
                green.add(e1)
                red.add(e2)

        assert e1 not in used_edges
        assert e2 not in used_edges
        assert e1 != e2

        used_edges.add(e1)
        used_edges.add(e2)
        answer_pos += 1

    assert len(red) == n - 1
    assert len(green) == n - 1

 ## 特殊なケース

 ### 最小値 (n=5)

 (n=5) の入力の場合、ターンはちょうど 4 つあるため、アルゴリズムは (K_5) 戦略のみを実行します。 愛着段階はありません。 再帰的ソルバーは、ドナルドの 4 つの回答のすべての可能なシーケンスが 2 つのスパニング ツリーに到達することを証明したため、これは直接処理される最小の有効なケースです。 

### 最大値 (n=10^5)

 (n=10^5) の場合、最初の 5 つの頂点のみが一定サイズの検索を必要とします。 6 から (10^5) までの各頂点はちょうど 1 つのクエリを消費するため、(99999) 回のアタッチメント ラウンドがあります。 グラフ全体にわたる二次走査は実行されません。 

### ドナルドは必ず戻ってくる`0`コードは解釈します`0`赤が最初のエッジを受け取り、緑が 2 番目のエッジを受け取ります。 (K_5) 戦略は、移動を受け入れる前にこの後継者を明示的にチェックしますが、新しい頂点が両方の色で分離されているため、接続フェーズは安全です。 

### ドナルドは必ず戻ってくる`1`同じ議論が色を交換しても当てはまります。 コア ソルバーはこの分岐を明示的にチェックし、接続フェーズでは赤 ((2,i)) と緑 ((1,i)) が与えられます。 両方のエッジは、新しい孤立した頂点を既存のツリーに接続します。 

### さまざまな答え

 次のような混合シーケンス`0 1 1 0`コアラウンドごとに赤と緑のマスクを変更します。 メモ化された戦略では、固定された回答順序は想定されていません。 正確な現在の状態から次のペアを選択し、再帰的証明により、考えられる次の状態が両方とも勝っていることが保証されます。 

### エッジの再利用

 コアは、エンドポイントが (1,\ldots,5) の間にあるエッジのみを使用します。 以降の各ラウンドでは、((1,i)) と ((2,i)) を (i) の新しい値として使用します。 したがって、どのアタッチメント エッジも、コア エッジや以前のラウンドのアタッチメント エッジと等しくすることはできません。 

### 出力バッファリング

 すべてのクエリは次のように出力されます。`flush=True`。 これは最適化の詳細ではありません。 インタラクティブな問題では、インタラクターが現在のクエリを受け取った後でのみ、次の入力値が生成されます。 フラッシュに失敗すると、プログラムはインタラクターも生成を待っている応答を待機したままになる可能性があります。
