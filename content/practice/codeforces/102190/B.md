 ## 解決策
 ## 問題の理解

 すぐに見えるすべてのペアが削除されると、すべてのランクは 3 つの状況のいずれかになります。 このランクの両方のカードが同じ手札にあり、ペアとして消えた可能性があります。 2 枚のカードはブレットとカオイムヘの間で分割される場合があり、その場合、そのランクは各ハンドに 1 枚のアクティブ カードを提供します。 最後に、ちょうど 1 つのランクに残っているカードは 1 枚だけ、老メイドです。 そのカードはブレットかカオイムヘのどちらかのものです。 

アクティブなペアのランクの ID は重要ではありません。 (m) 個のランクがあり、その 2 枚のカードがプレイヤー間で分割されるとします。 このような各ランクは同じように動作します。一方のプレイヤーが他のプレイヤーからカードを受け取ると、2 枚のカードはすぐにペアを形成して消えます。 唯一の特別なカードは老メイドです。これを取得してもペアは作成されません。 

入力により、(n) ランクと、各ハンドに各ランクのカードが何枚あるかを記述する 2 つの文字列が与えられます。 文字列を 1 回スキャンするだけで、どのプレイヤーが一意のシングルトンを所有しているか、および各手に 1 枚のカードを持っているランクがいくつあるかを判断できます。 テスト ケースのすべての (n) の合計は最大で (10^6) であるため、テスト ケースごとに (O(n)) 個のソリューションが意図されたスケールになります。 考えられるドローシーケンスの数はアクティブなランクの数に応じて指数関数的に増加するため、個々のゲーム履歴を調査するアプローチは絶望的です。 

よくある実装上の間違いは、合計が 2 であるすべてのランクをアクティブなペアとしてカウントすることです。 両方のカードがすでに同じ手札にある場合、そのペアはゲームが始まる前に消えるため、これは間違っています。 たとえば、```
1
2
10
01
```ブレットはすでにランク 1 のカードを両方持っているので、それらは捨てられます。 残っている唯一のカードは Caoimhe のランク 2 の老メイドであり、ランク 1 を別のアクティブなペアとして扱うことによって得られる確率ではなく、確率 (1) でブレットが勝ちます。 

逆の間違いも考えられます。 どちらのプレイヤーも最初は自分の手札にペアを持っていないため、各手に 1 枚のカードがあるランクは引き続き有効です。 例えば、```
1
2
11
11
```にはシングルトンがなく、有効な入力ではありませんが、ランク構造は区別を示しています。分割された各ランクは 1 枚のカードを両方の手に与え、それらのカードの 1 つが引かれるまでゲームに留まらなければなりません。 

アクティブな分割ランクがない場合には、別途注意が必要です。 例えば、```
1
2
10
02
```最初のペアが破棄された後、残っているのは老メイドだけです。 ブレットが開始しますが、別の動きをトリガーするペアが残っていないため、ブレットはすぐに負けます。 答えは (0) です。 

## アプローチ

 直接シミュレーションでは、すべてのアクティブなカードが保持され、現在のプレイヤーが引く可能性のあるすべてのカードに分岐します。 これはゲームに正確に従っているので正しいですが、(m) 個のアクティブ ランクでは、予想されるドロー履歴が指数関数的に多くなる可能性があります。 たとえすべての状態がコンパクトに表現されていたとしても、履歴を列挙するのは (2^m) 程度であり、(10^5) 程度の (m) ではすでに不可能です。 

有益な観察は、すべてのアクティブなランクが交換可能であるということです。 現在どのランクがプレイされているかを思い出す必要はありません。 必要なのは、アクティブなペアの数 (m)、誰の番であるか、そして現在誰が老メイドを保持しているかだけです。 

現在のプレイヤーとババアのオーナーによって決定される 4 つの状態があります。 ブレットが移動し、カオイムヘが老メイドを抱いたときに、最終的にブレットが勝つ確率を (A_m) とします。 Caoimhe が移動し、Bret が老メイドを抱きかかえたときの確率を (B_m) とします。 他の 2 つの状態は、通常の動きを 1 回行うだけで得られます。 

Caoimhe が老メイドを所有している間に、Bret が引っ越すことになったとします。 ブレットは、カオイムヘの手札に、(m) 枚の普通のカードと老メイドからなる (m+1) 枚のカードが見えます。 (1/(m+1)) の確率で、彼はその老女を連れて行きます。 確率 (m/(m+1)) で、彼は通常のカードを取り、アクティブなペアを 1 つ取り除きます。 

同様の議論は、ブレットが老メイドを所有している間にカオイムヘが引っ越しする場合にも当てはまります。 これらの遷移は小さな線形反復を形成します。 重要な単純化は、レベル (m) の 2 つの状態はレベル (m-1) の 2 つの状態から直接解くことができるため、大規模な動的計画法テーブルが必要ないことです。 

繰り返しは次のように書くことができます

 [
 A_m=\frac{(m+1)A_{m-1}+B_{m-1}}{m+2}、
 】

 そして

 [
 B_m=\frac{A_{m-1}+(m+1)B_{m-1}}{m+2}。 
】

 基本状態は (A_0=1) と (B_0=0) です。 アクティブなペアが残っていないため、Caoimhe が老メイドを所有している場合はブレットがすでに勝ち、ブレットが所有している場合は負けます。 

本来の開始状態はブレットのターンです。 Caoimhe がその老メイドを所有している場合、答えは (A_m) です。 ブレットがそれを所有している場合、ブレットは最初の移動状態遷移を行ったばかりであるため、答えは (B_{m-1}) になります。

 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^m)) | (O(m)) | 遅すぎる |
 | 最適 | (O(n)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのランクをスキャンしてカウントする`pairs`、両方の文字列にちょうど 1 枚のカードが含まれる位置の数。 これらはまさに、最初のペアの削除後にアクティブなペアとして生き残るランクです。 同時に、合計が 1 になる固有の位置を見つけて、そのカードをブレットとカオイムのどちらが所有しているかを記録します。 
2. ゼロアクティブペアの動的プログラミング値を初期化します。 セット (A_0=1)。アクティブなペアがなく、Caoimhe が老メイドを抱いているため、Brett が勝者です。 セット (B_0=0)。アクティブなペアがなく、ブレットが老メイドを保持しているため、ブレットは負けます。 
3. (1) から (1) までの (m) ごとに`pairs`を使用して 2 つの確率を更新します。 
[
 A_m=\frac{(m+1)A_{m-1}+B_{m-1}}{m+2}
 】
 そして
 [
 B_m=\frac{A_{m-1}+(m+1)B_{m-1}}{m+2}。 
】
 因数 (m+1) は関連するトランジション内のすべての通常カードを表し、残りの 1 つの項は老メイドを引くことを表します。 
4. 老メイドが Caoimhe に属している場合、(A_m) を出力します。実際のゲームはブレットがまさにその状態で移動することから始まるためです。 
5. 老メイドがブレットに属しており、(m=0) の場合、ペアが残っておらず、ブレットは老メイドとくっついているため、(0) を出力します。 それ以外の場合は、Caoimhe が老メイドを連れて行く最初の確率的な機会を得る前の、Brett の最初の決定論的な通常の抽選に対応する出力 (B_{m-1})。 

### なぜ効果があるのか

 不変条件は、完了したターンごとに、生き残っているすべての通常ランクがそれぞれの手にちょうど 1 枚のカードを提供するということです。 したがって、ゲームの通常の部分全体は、生き残ったランクの数によって完全に説明されます。 カードの中で動作が異なるのは老メイドだけなので、その所有者とそのターンのプレイヤーを知ることで、将来の確率が完全に決まります。 各遷移では、現在のプレイヤーが引くことができるあらゆる種類のカードが考慮され、その結果の状態では、アクティブなペアが 1 つ少なくなるか、古いメイドと同じ数のペアが転送されます。 したがって、この繰り返しにより、可能なすべてのゲーム継続が 1 回だけ計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, b, c):
    pairs = 0
    old_owner = -1

    for i in range(n):
        x = ord(b[i]) - 48
        y = ord(c[i]) - 48

        if x == 1 and y == 1:
            pairs += 1
        elif x + y == 1:
            old_owner = 0 if x == 1 else 1

    if pairs == 0:
        return 0.0 if old_owner == 0 else 1.0

    a = 1.0
    d = 0.0

    for m in range(1, pairs + 1):
        na = ((m + 1) * a + d) / (m + 2)
        nd = (a + (m + 1) * d) / (m + 2)
        a, d = na, nd

    if old_owner == 1:
        return a

    return d

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        b = input().strip()
        c = input().strip()

        ans = solve_case(n, b, c)
        out.append("{:.15f}".format(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```文字列に対する最初のループは、元のハンドから小さな確率状態への構造的還元を正確に実行します。 を含むポジション`1`両方の文字列にアクティブなペアがあります。 合計が 1 である位置は、老メイドとその所有者を識別します。 を含むポジション`2`一方の手札は、その 2 枚のカードが既にペアを形成して消滅しているため、無視されます。 

変数`a`そして`d`繰り返しの前のレベルのみを保存します。 更新では両方の新しい状態に対して古い値を使用する必要があるため、コードは次のように計算します。`na`そして`nd`割り当てを戻す前に。 更新中`a`最初に、計算時に新しい値を使用します`d`間違った依存関係を暗黙のうちに導入してしまいます。 

すべての演算は整数による少数の加算、乗算、除算であるため、ここでは Python の浮動小数点型で十分です。 必要な誤差許容値は (10^{-9}) ですが、すべての値が区間 ([0,1]) 内に留まるため、反復は数値的に適切に動作します。

 ## 特殊なケース

 ゼロペアの場合は、(m-1) の繰り返しにアクセスする前に処理する必要があります。 ブレットがシングルトンを所有しており、分割ランクがない場合、引くものは何も残っておらず、ブレットはすぐに負けます。 と`b = 10`そして`c = 02`、答えはまさにそのとおりです`0`。 

Caoimhe がシングルトンを所有しており、ランクが分割されていない場合、唯一生き残っているカードが Caoimhe の手札にあるため、Brett がすでに勝利しています。 と`b = 01`そして`c = 10`、答えはまさにそのとおりです`1`。 

片手に 2 枚のカードがあるランクは、`pairs`。 たとえば、`b = 20`そして`c = 01`、ランク 1 の 2 枚のカードはすでにブレットの手札に表示されており、ゲームが始まる前に消えます。 そのランクをアクティブとしてカウントすると、後続のすべての分母が変化します。 

各手に 1 枚のカードを持つランクは、アクティブなペアを 1 つだけ提供する必要があります。 どちらのプレイヤーも両方のカードを持っていないため、これら 2 枚のカードを最初から捨てることはできません。 どちらかのプレイヤーがもう一方のプレイヤーのコピーを引くまで、それらはゲームに残ります。 

繰り返しには、前の値も同時に必要になります。 したがって、実装では、古いペアを置き換える前に、次の値を両方とも一時変数に計算します。 これにより、2 回目の繰り返しで (A_{m-1}) の代わりに (A_m) が使用されるという微妙な評価順序のバグが回避されます。
