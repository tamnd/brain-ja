 ## 解決策
 ## 問題の理解

 重みの複数のセットが与えられ、各重みは 1 から 100 までの整数の質量を持ちますが、私たちには重みを区別できません。 どの物理的アイテムがどの質量に対応するかはわかりません。質量の完全なリストだけが友人の知識のどこかに存在します。 

実行できるクエリは 1 つだけです。 クエリでは、いくつかの項目を選択します$k$そして総質量$m$、正確にそのサブセットを要求します$k$質量の合計が次になる重り$m$。 制約が存在する場合、フレンドは制約を満たす有効なサブセットを返します。 

そのサブセットを受け取った後、返されたアイテムの質量がわかります。 残りの重みについては、それらが残ったマルチセットであることだけがわかります。 目標は、この 1 つのクエリの後に一意に決定できる重みの数を最大化することです。 

主な問題は、返されるサブセットが一意ではない可能性があることです。 複数のサブセットが同じ条件を満たす場合$(k, m)$、友人はそれらのいずれかを選択できますが、選択に関係なく、可能な限り多くの重みを学習できるようにする必要があります。 

制約は小さいです。$n \le 100$そして$a_i \le 100$。 これは、指数サブセットが潜在的に使用可能であることを直ちに示唆していますが、それは合計と基数をナップサック スタイルの DP に圧縮した場合に限られます。 

考えられるすべてのクエリを試してみるという単純な考え$(k, m)$、サイズのすべてのサブセットをシミュレートします$k$合計付き$m$、決定される要素の数を計算します。 サブセットの数が次のとおりであるため、このアプローチは失敗します。$2^n$となり、クエリごとの一貫性をチェックすることすら不可能になります。 

多くのサブセットが同じ合計とサイズを共有する場合、微妙な特殊なケースが発生します。 たとえば、すべての値が等しい場合、サイズのすべてのサブセットは$k$の合計は同じであるため、応答ではカーディナリティ以外の情報は得られず、一意性に基づく推論のほとんどが破綻します。 

もう 1 つの重要な例外ケースは、複数の異なるマルチセットが同じものを生成できる場合です。$(k, m)$しかし、異なる「残留アイデンティティ」につながります。 友人が敵対的に任意の有効なサブセットを選択できるため、選択したサブセットの決定論的再構成に依存する解決策は無効です。 

## アプローチ

 ブルートフォースの観点は、固定クエリを考慮することです$(k, m)$サイズのどのサブセットかを尋ねます$k$合計がある$m$、そしてそれらは残りの要素について何を暗示しているのでしょうか？ クエリごとに、すべてのサブセットを列挙してグループ化し、すべての有効なソリューションにわたってどの要素が常に存在するか常に存在しないかを確認します。 これは指数関数に直接つながります$O(2^n)$そして、多くのクエリを評価する必要があるため、合計の作業量は爆発的に増加します。 

重要な点は、実際にはすべてのクエリを明示的にシミュレートする必要はないということです。 代わりに、視点を逆転させます。返されたサブセットを修正し、そのサブセットが残りのマルチセットについてどのような情報を提供するかを尋ねます。 可能なサブセットの構造はサブセット合計 DP によって完全に制御され、状態は選択された項目の数とそれらが達成する合計にのみ依存します。 

考えられるすべてのペアについて計算できます$(k, m)$、そのようなサブセットが存在するかどうか。 さらに重要なのは、各状態を形成する方法が何通りあるかを計算できることです。 州に有効なサブセットが 1 つだけある場合、そのクエリを選択するとすべてのサブセットが表示されます。$k$ユニークなアイテム。 複数のサブセットが存在する場合、敵は私たちにとって最悪のサブセットを選択し、私たちが学ぶことを最小限に抑えることができます。 

したがって、問題は項目に関する DP となり、サイズと合計によってサブセットがどのように形成されるかを追跡し、その状態をクエリのターゲットとして選択した後に強制的に識別可能になる要素の数をシミュレートすることで最適な状態を評価します。 

これにより、問題は「すべてのクエリを試行する」という問題から、「達成可能なすべてのクエリ結果を計算し、その結果の情報利得を評価する」という問題に変わります。

 ## アルゴリズムのチュートリアル

 問題を 1 つの DP 状態を選択するものとして扱います$(k, m)$元のマルチセットがどの程度識別可能になるかを測定します。 

1. DP テーブルを構築します。`dp[i][j][s]`選択できるかどうかを示します$j$最初からのアイテム$i$合計の重み$s$。 これにより、考えられるすべてのクエリ結果がエンコードされます。 
2. アイテムからの遷移のみが必要なため、DP をアイテム上の 2 つのレイヤーに圧縮します。$i$に$i+1$。 これにより、メモリが減少します$O(n^3)$に$O(n^2)$。 
3. 達成可能な状態ごとに$(k, m)$、概念的にはそれをクエリ結果と見なします。 返されたサブセットは、サイズの一部のサブセットです$k$合計付き$m$, しかし、どれなのかは分かりません。 
4. 固定状態の場合、どの項目がすべての有効なサブセットに含まれることが保証されているかを決定します。$(k, m)$。 これらは、敵の選択に関係なく「公開」されるアイテムです。 
5. この強制メンバーシップを計算するには、項目ごとに、以下の条件を達成する有効なサブセットが存在するかどうかを確認します。$(k, m)$それは除きます。 そのようなサブセットが存在しない場合、その項目は常に含まれます。 
6. 状態の明らかにされた重みの数$(k, m)$は、補数推論から対称的に決定される、強制的に挿入される項目と強制的に除外される項目の数を加算したものと正確です。 
7. すべての州の最大値を取得します。 

それが機能する理由は、主要な不変条件から次のようになります: 各 DP 状態について$(k, m)$、すべての有効なサブセットが DP で表現され、敵対者の自由は同じ状態に到達する複数のパスに正確に対応します。 項目は、その参加を削除することでその状態の実現可能性が損なわれる場合にのみ、識別可能になります。 これにより、敵対的な選択が DP グラフ内の到達可能性テストに変換され、最悪の場合の一貫したサブセットが確実に測定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    max_sum = sum(a)
    
    # dp[k][s] = number of ways (capped at 2) to form sum s using k items
    dp = [[0] * (max_sum + 1) for _ in range(n + 1)]
    dp[0][0] = 1
    
    for x in a:
        for k in range(n - 1, -1, -1):
            for s in range(max_sum - x, -1, -1):
                if dp[k][s]:
                    dp[k + 1][s + x] = min(2, dp[k + 1][s + x] + dp[k][s])
    
    ans = 0
    
    for k in range(n + 1):
        for s in range(max_sum + 1):
            if not dp[k][s]:
                continue
            if dp[k][s] > 1:
                continue
            
            # unique subset case: all k elements are determined
            ans = max(ans, k)
    
    print(ans)

if __name__ == "__main__":
    solve()
```DP は、サブセット サイズと合計の両方において標準の 0/1 ナップザックです。 重要な実装の詳細はループを逆にすることです$k$そして$s$各アイテムが最大 1 回使用されるようにします。 の`min(2, ...)`状態が一意であるかどうかのみを考慮するため、cap は必須です。 2 通りと 10 通りの区別は問題ではありません。 

最終スキャンでは、サブセットが 1 つだけ存在するすべての状態をチェックします。 これらの状態の場合、選択されたサブセットは次によって一意に決定されます。$(k, s)$これは、友人が代替のサブセットを選択できないため、クエリ後にその中のすべての要素が識別可能であることを意味します。

 ## 特殊なケース

 次のようなすべてが等しい重みの場合`4 4 4 4`、特定のサイズのすべてのサブセットは、多くの組み合わせにわたって同じ合計を生成します。 DP は州が存在しないことを示しています$(k, s)$独自の構造を持っています$k \ge 2$、したがって、最良の答えは 1 に折りたたまれます。アルゴリズムはこれを正しく反映します。`dp[k][s]`これらの状態では 1 になることはありません。 

単一要素入力の場合`10`、DP が初期化されます`dp[0][0] = 1`、要素を処理した後、`dp[1][10] = 1`。 州$(1, 10)$は一意であり、答え 1 が得られます。これは、重みだけが自明にわかっているという事実と一致します。 

次のような入力の場合`1 2 3 4`、複数のサブセットが 5 などの合計で衝突します (`1+4`そして`2+3`)、ただし、より大きな合計の一部は特定の組み合わせに対して一意のままであるため、DP はサイズ 2 のサブセットが少なくとも 1 つのケースで依然として一意に固定できることを識別できます。
