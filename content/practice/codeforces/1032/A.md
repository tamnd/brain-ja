 ## 解決策
 ## 問題の理解

 宴会後に残った複数の食器セットと出席者の数が与えられます。 各ゲストにはいくつかの同一の「料理」が提供され、各料理には決まった調理器具のセットが付属していました。 すべての料理は同じタイプのセットを使用します。つまり、すべての料理は同じ調理器具タイプのマルチセットに寄与し、1 つのセット内で調理器具タイプが繰り返されることはありません。 

私たちは、ゲストへの料理の分配が可能な限り最も「寛大な」方法で行われたと仮定して、最後に残った食器から、合計で何個の食器が持ち去られたかを判断するよう求められます。つまり、制約を遵守しながら盗難を最小限に抑えるということです。 

重要な問題は、何皿が出されたのか、また 1 つの皿の調理器具セットがどれくらいの大きさなのかがわからないことです。 私たちが知っているのは、各ゲストが同じ数の料理を受け取ったということだけです。 

制約は非常に小さく、ツール エントリは最大 100 個、値は最大 100 個です。これにより、複雑な組み合わせ論やグラフベースのモデリングの必要性が即座に排除されます。 可能なカウントを反復したり、制限された範囲内で割り切れる条件をチェックしたりするソリューションであれば、十分です。 

微妙なエッジ ケースは、一部の器具タイプが残りのコレクションに 1 回しか表示されないにもかかわらず、複数のゲストが存在する場合です。 たとえば、あるタイプが 1 回表示されてもゲストが 2 人いる場合、その器具は少なくとも 1 つの提供セットの一部である必要があり、すべてのゲストに均等に分配することはできません。 これにより、少なくとも 1 つの器具が失われることになります。 

もう 1 つのエッジ ケースは、すべての調理器具がゲスト間で均等に分配されている場合です。この場合、重複が存在する場合でも答えがゼロになる可能性があります。これは、残りのマルチセットはゲストごとの均等な消費量で完全に説明できるためです。 

## アプローチ

 ブルートフォースの観点では、各ゲストが受け取った皿の数と、1 つの皿の調理器具セットのサイズを推測することから始まります。 それぞれの推測について、すべてのゲストにわたる固定セットの完全なコピーをいくつか削除することによって残りのマルチセットを形成できるかどうかを再構築しようとします。 考えられるセットのサイズと数のスペースが大きく、構成ごとに割り当てと削除をシミュレートする必要があるため、これはすぐに扱いにくくなります。 

重要な観察は、実際には完全な構造を再構築する必要がないということです。 重要なのは、同一の食器セットでグループ化した後、各調理器具の種類をすべてのゲストに均等に説明できるかどうかです。 すべてのゲストは同じ数の同一のセットを受け取るため、盗難により紛失したものを除いて、各種類の器具の合計数は本来、ゲストの数で割り切れるはずです。 

これにより、問題は器具の種類ごとの単純な計数の不一致に帰着します。 タイプごとに、残っている数と、すべてがゲスト間で完全に分割できる場合に予想される数を比較します。 残りは盗難品を示します。 

これを強制する最も簡単な方法は、モジュロ k でカウントをグループ化することです。 各器具タイプの頻度について、それを超えない最大の k の倍数に減らします。 違いはそのタイプの盗まれた数です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース再構築 | 指数関数 | お(1) | 遅すぎる |
 | 周波数モジュロ推論 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各種類の器具が何回出現するかを分析し、k 人のゲストにどの程度均等に分配できるかを確認することから進めます。 

1. 各器具の種類の頻度を数えます。 これにより、順序に関係なく、タイプごとの残りの項目の合計数が得られます。 

2. 各タイプの周波数 c に対して、c mod k を計算します。 これは、k 人のゲストに均等に分割できない項目の数を表します。 

3. 余りをすべて加算します。 残りの各アイテムは、完全な k サイズの分布に割り当てることができないため、少なくともその数の盗まれた器具に対応します。

4. 残りの合計を盗まれた食器の最小数として返します。 

ステップ 2 が有効である理由は、タイプごとに k 個の同一の投稿の完全なグループが元々ゲスト間で均等に分配されていた可能性があるため、残った部分のみが欠落アイテムを示しているためです。 

### なぜ効果があるのか

 各用具の種類は、もともとゲストの数に合わせてバッチで登場したはずです。 k で割り切れないカウントは、そのタイプの一部のアイテムがゲストごとの完全な割り当てに含まれていないことを意味します。 盗難を最小限に抑えることを目的としているため、k の完全なグループはすべて無傷で、残ったアイテムだけが紛失していると仮定します。 これにより、観察されたマルチセットと一致して、盗まれた器具の数が可能な限り最小になることがわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
arr = list(map(int, input().split()))

freq = [0] * 101
for x in arr:
    freq[x] += 1

ans = 0
for c in freq:
    ans += c % k

print(ans)
```器具タイプは 100 で制限されるため、実装は固定サイズの頻度配列に依存します。これにより、辞書のオーバーヘッドが回避され、タイプごとの操作が一定時間に保たれます。 

中心的なステップはコンピューティングです`c % k`。 これにより、同じアイテムを k 個のグループに均等に分配するときに避けられない不均衡が分離されます。 これらの不均衡を合計すると、最小数の欠落項目が直接生成されます。 

問題は位置や構造ではなくカウントのみに依存するため、順序付けや再構築は必要ありません。 

## 実用的な例

 ### 例 1

 入力:```
5 2
1 2 2 1 3
```頻度は次のとおりです。 

| タイプ | カウント | カウント %2 |
 |------|-------|-----------|
 | 1 | 2 | 0 |
 | 2 | 2 | 0 |
 | 3 | 1 | 1 |

 したがって、答えは 1 です。 

これは、タイプ 3 の単一の調理器具を 2 人のゲスト間でペアにすることができず、1 つのアイテムだけが欠落することを強制することを示しています。 

### 例 2

 入力:```
3 3
1 1 2
```周波数:

 | タイプ | カウント | カウント %3 |
 |------|-------|-----------|
 | 1 | 2 | 2 |
 | 2 | 1 | 1 |

 合計 = 3。 

これは、k が個々の周波数より大きい場合、ほとんどのアイテムが完全なグループに「ペアリングできなくなり」、答えに直接寄与することを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))
    
    freq = [0] * 101
    for x in arr:
        freq[x] += 1

    ans = 0
    for c in freq:
        ans += c % k

    return str(ans)

# provided sample
assert run("5 2\n1 2 2 1 3\n") == "1"

# all equal
assert run("4 2\n1 1 1 1\n") == "0"

# all distinct, k large
assert run("3 5\n1 2 3\n") == "3"

# single type only
assert run("6 3\n7 7 7 7 7 7\n") == "0"

# minimal case
assert run("1 2\n1\n") == "1"
```| テスト入力 | 期待される出力 | 検証内容 |
 |---|---|---|
 | すべて等しい | 0 | 完全な可分性 |
 | すべて異なる、k が大きい | 3 | 残り全額の貢献 |
 | シングルタイプ 分割可能 | 0 | 正確に分割すれば盗難はありません |

 ## 特殊なケース

 すべての器具タイプが正確に k 回出現する場合、次のようになります。`k=3`そして入力`1 1 1 2 2 2`、アルゴリズムはすべての型のゼロ剰余を計算し、正しくゼロを出力します。 これは、すべてのアイテムを欠けることなくゲストに均等に分配できるという解釈と一致します。 

のようなケースの場合`k=4`そして入力`1 1 1`、頻度は 3、そして`3 % 4 = 3`, したがって、すべてのアイテムは盗まれたものとしてカウントされます。 これは、あるタイプの利用可能なアイテムよりもゲストの数が多い場合、ゲストごとの完全な割り当てを形成できるものがないため、すべてのアイテムが欠落した構造の一部である必要があることを反映しています。
