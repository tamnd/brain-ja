 ## 解決策
 ## 問題の理解

 私たちは 2 種類の道路に沿った移動のみが許可されている都市で働いています。 1 つ目のタイプは標準の整数グリッドです。任意の垂直線 x = k または水平線 y = k に沿って自由に移動でき、コストはこれらの線に沿った単純なユークリッド距離となり、座標の絶対的な差に換算されます。 2 番目のタイプは 1 つの追加の道路であり、ax + by + c = 0 で与えられる無限の直線であり、移動もユークリッド コストの線に沿って連続的です。 

整数座標を持つ 2 つの固定点 A と B が与えられます。 グリッド線に沿って歩くことができ、オプションで斜めの道路を近道として使用できる場合、A から B までの移動距離を可能な限り短くする必要があります。 

制約境界では、最大 10^9 の大きさの座標と線係数が許可されます。 これにより、すべての交点の幾何学的グラフを明示的に構築したり、グリッド セルを列挙したりするアプローチは除外されます。 正しい解決策は、問題を一定数の幾何学的評価または小規模な継続的な最適化に削減する必要があります。 

単純な試みでは、対角線とすべてのグリッド線の交点をモデル化し、大きなグラフ上で最短パスを実行しようとします。 A と B の周囲の境界領域に制限しても、依然として O(R^2) 個の交差候補が得られますが、これは実現可能性をはるかに超えています。 

より微妙な故障モードは、対角線を複数回使用すると効果があると仮定することで生じます。 たとえば、A 行から行に行こうとして、そこから離れ、後でもう一度行に入ろうとする場合があります。 実際には、このようなパスは対角線との単一の接点にショートカットできるため、これで答えが改善されることはありません。 

もう 1 つのよくある間違いは、対角線上の最良の点が常に A または B の直交投影であると仮定することです。コストには単一のユークリッド投影目的ではなく、2 つのマンハッタン距離の合計が含まれるため、これは誤りです。 

## アプローチ

 斜めの道路を完全に無視すると、問題は標準的なマンハッタンの幾何学構造に陥ります。 最短パスは単純に |x1 − x2| です。 + |y1 − y2|。 これが機能するのは、グリッド道路が水平方向と垂直方向に独立して移動できるためです。 

この複雑さは、離れた 2 つのグリッド位置間の連続的なショートカットとして機能する可能性がある対角線から発生します。 強引なアイデアは、対角線とグリッド線の間のすべての交点を考慮し、それらをグラフ内のノードとして扱い、最短経路検索を実行することです。 ただし、座標の周囲の適切な境界ボックス内では、交差の数は座標の範囲に比例し、その範囲は 10^9 に達する可能性があるため、このアプローチは不可能です。 

重要な観察は、対角線は最適なパス内の 1 つの連続セグメントでのみ使用できるということです。 点 P で対角線に入り、点 Q で対角線から出る場合、マンハッタン距離は三角不等式を満たすため、Q を P に置き換えてもコストが増加することはありません。 これにより、問題は、A から P へ、および B から P への総移動コストを最小化する対角線上の単一点 P を選択することになります。 

したがって、問題を連続直線上の関数の最小化に要約します。 f(P) = distManhattan(A, P) + distManhattan(B, P)、ここで P は ax + by + c = 0 上にあります。マンハッタン距離は凸であり、アフィン ラインへの制限により凸性が維持されるため、これは直線に沿った凸関数です。 したがって、行のパラメータ化に対する三分探索で十分です。

 ## アルゴリズムのチュートリアル

点と方向ベクトルを使用して対角線をパラメータ化します。 便利な方向は (b, −a) で、法線 (a, b) に対して垂直です。 直線上の任意の点は、P(t) = P0 + t · (b, −a) と書くことができます。ここで、P0 は、ax + by + c = 0 を満たす任意の固定点です。 

1. 線上で有効な点 P0 を 1 つ見つけます。 これを行うには、可能であれば x = 0 を固定し、そうでない場合は y = 0 を固定して一次方程式を解きます。 これにより、具体的な出発点が得られます。 
2. 方向ベクトル dir = (b, −a) を定義します。 これにより、a(b) + b(−a) = 0 となるため、移動が線上に留まることが保証されます。 
3. P(t) を選択するコスト、つまり A から P(t) と B から P(t) までのマンハッタン距離の合計を計算する関数 f(t) を定義します。 これは、P(t) で一度対角線に入り、そこですべての転送を行うという考えを表しています。 
4. t の適切な検索間隔を計算します。 A と B のライン方向への射影パラメータを推定し、その範囲をわずかに拡大します。 この領域の外側では両方のマンハッタン距離が直線的に増加するため、最適な点はこの領域内またはその近くにある必要があります。 
5. この間隔で t に対して三項検索を実行します。 f は直線に沿って凸であるため、f(m1) と f(m2) を比較すると、探索空間が最小値に向かって確実に縮小されます。 
6. 最適なパスは対角線を完全に無視する可能性があるため、最終候補 P(t) を評価し、A と B の間の直接のマンハッタン距離と比較します。 

### なぜ効果があるのか

 重要な性質は、対角線上の実現可能な集合が凸集合 (線) であり、目的関数がユークリッド空間における凸関数の和であることです。 凸関数を直線に制限すると凸性が維持されるため、f(t) は単一のグローバル最小値を持ちます。 Convexity により、三項検索におけるローカル比較は真のミニマイザーに向かって移動し、それをスキップすることができなくなります。 

三角形不等式の議論により、対角線上に複数の点が必要になることがなくなります。 コストを増加させることなくマルチエントリ パスを短縮できるため、最適化空間は単一のパラメータ t によって完全にキャプチャされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def solve():
    a, b, c = map(int, input().split())
    x1, y1, x2, y2 = map(int, input().split())

    def manhattan(xa, ya, xb, yb):
        return abs(xa - xb) + abs(ya - yb)

    direct = manhattan(x1, y1, x2, y2)

    # find a point on the line ax + by + c = 0
    if b != 0:
        x0 = 0.0
        y0 = -c / b
    else:
        y0 = 0.0
        x0 = -c / a

    dx, dy = b, -a

    def f(t):
        px = x0 + dx * t
        py = y0 + dy * t
        return manhattan(px, py, x1, y1) + manhattan(px, py, x2, y2)

    # approximate bounds using projections of A and B
    def proj_t(x, y):
        vx = x - x0
        vy = y - y0
        return (vx * dx + vy * dy) / (dx * dx + dy * dy)

    t1 = proj_t(x1, y1)
    t2 = proj_t(x2, y2)

    l = min(t1, t2) - 5e6
    r = max(t1, t2) + 5e6

    for _ in range(80):
        m1 = l + (r - l) / 3
        m2 = r - (r - l) / 3
        if f(m1) < f(m2):
            r = m2
        else:
            l = m1

    best = min(direct, f(l))
    print(best)

if __name__ == "__main__":
    solve()
```解決策は、斜めの道路が完全に無視された場合を表す、ベースラインのマンハッタン距離を計算することから始まります。 

対角線上の具体的な点は、x または y のいずれかをゼロに設定し、一次方程式を解くことによって構築されます。 線上の有効な点はパラメータ化のアンカーとして機能するため、これで十分です。 

方向ベクトル (b, −a) は、すべての実数 t に対してパラメトリック表現が線上に留まることを保証します。 関数 f(t) は、その地点を通過する総移動コストを評価します。 

三分探索を安定させるために、ライン方向への A と B の射影を中心とした区間を選択します。 これにより、真のミニマイザーが検索範囲内に確実に収まり、数値のドリフトが回避されます。 

最後に、最適な対角線アシスト パスと純粋なグリッド パスを比較し、最小値を取得します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、対角線上の最適点が A と B の射影によって広がるセグメントのはるか外側にある場合に発生します。検索間隔が狭すぎる場合、三値検索で真の最小値を見逃す可能性があります。 これは、最適化前に凸関数が完全に括弧内に収まるように間隔を拡張することで処理されます。 

もう 1 つのエッジ ケースは、a または b が 0 に等しい場合で、これにより線が純粋に水平または垂直になります。 この場合でも方向ベクトルは機能しますが、アンカー ポイントを構築する際にはゼロによる除算を避ける必要があります。 この実装では、座標解決を明示的に切り替えて、有効な開始点を保証します。
