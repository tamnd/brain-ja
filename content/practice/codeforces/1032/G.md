 ## 解決策
 ## 問題の理解

 私たちはオウムの円形配置を与えられており、各オウムにはその尊重レベルから導出された数値の「影響半径」があります。 オウムがその位置にいる場合`i`時間に合わせて話し始める`0`、その後、時間に`1`距離内のすべてのオウム`r_i`その左右も話し始めます。 それ以降、新しくアクティブ化されたすべてのオウムは、自身の尊重レベルを伝播半径として使用して、同じルールを繰り返します。 

このプロセスは波のように続き、最終的にはサークル内のすべてのオウムがアクティブになります。 スタートポジションごとに`i`、円全体がアクティブになるまでに何秒が経過するかを計算したいと思います。 

重要な問題は、アクティベーションが均一ではないことです。 敬意の高いオウムは大きなセグメントを一度に「ジャンプ」できますが、敬意の低いオウムはゆっくりと広がります。 アクティブ化された各ノードはさらなる拡張を生成するため、プロセスはノードに依存する拡張半径を持つマルチソース到達可能性の問題のように動作します。 

制約`n ≤ 10^5`明示的に波面を繰り返し拡大するシミュレーションは除外されます。 開始ノードごとの単純な BFS スタイルのシミュレーションにはコストがかかります`O(n^2)`最悪の場合、各起動が複数のレイヤーにわたって直線的な数のアクティベーションをトリガーする可能性があるためです。 

オウムが非常に大きい場合、微妙なエッジケースが現れます。`r_i`を超える可能性があります`n`。 その場合、1 ステップで円全体が即座にアクティブ化され、正しい解決策は円の周りを明示的に反復するのではなく、暗黙的に距離をクランプする必要があります。 

もう 1 つの重要なエッジ パターンは、次のような均一な値です。`r_i = 1`みんなのために`i`。 ここで、伝播は両方向に 1 秒あたり 1 ステップずつ拡大します。つまり、答えは純粋に円の直径によって決まります。 伝播を線形 (循環的ではなく) として誤って扱う単純な実装では、次のようなラップアラウンドの場合にアクティブ化時間を過小評価します。`1 0 0 0 1`。 

## アプローチ

 各インデックスから総当たりアプローチを開始`i`そして層ごとに伝播をシミュレートします。 毎秒、新しくアクティブ化されたセットを維持し、各オウムの半径を使用してそこから拡張します。 アクティベーションのたびに、循環構造ですでに表示されているノードを再スキャンできるため、1 回のシミュレーションで次のノードを訪問する可能性があります。`O(n)`ノードオーバー`O(n)`最悪の場合の手順。 これをすべての開始位置で繰り返すと、`O(n^2)`または、限界をはるかに超えたさらに悪い行動。 

重要な観察は、プロセスが単調で、非常に特殊な意味で方向性があるということです。 各オウムのアクティブ化は、円上の一定間隔にわたるカバレッジを「ジャンプ」すると解釈でき、各ノードは効果的に、レイヤーごとの単位時間で外側に拡張するセグメントに寄与します。 ウェーブをシミュレートする代わりに、各ノードがアクティブ化するノードの次の層に依存するグラフ内の最長の「依存関係チェーン」を計算するプロセスとして再解釈できます。 

これにより、標準的な削減が行われます。各オウムは円形配列上のカバレッジ間隔に寄与し、アクティブ化時間は、指定されたソースから開始して円全体をカバーするのに必要な拡張レイヤーの数になります。 この構造は、ノードごとに、最も遠くのカバーされていないポイントをカバーするために必要な倍加のような拡張の最大数を計算することと同等になります。これは、バイナリ リフティング スタイルの到達可能性または間隔拡張上の単調キューを使用して解決できます。 

より直接的で標準的な最適化は、各ポジションおよび各「ジャンプ レベル」について、アクティベーションがどこまで到達できるかを事前計算することです。`2^k`秒。 各ノードは 1 ステップ後に区間に到達でき、ステップの合成は区間の結合に対応します。 これにより、問題が円上で結合する区間の 2 倍構造に変換され、その後、各クエリは最小のものを見つけることに帰着します。`k`からの間隔が`i`円全体をカバーします。

 | インターバルダブリング / バイナリリフティング | O(n log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 円を長さの 2 倍の線形配列に変換します。`2n`モジュールラップの複雑さを避けるため。 各ポジション`i`最初はそれ自体をカバーします。 

1. オウムごとに`i`、即時のアクティブ化間隔を計算します。`[L[i], R[i]]`1秒以内に。 これは`[i - r_i, i + r_i]`循環的に言えば、2 倍の配列にマッピングされます。 これは、同時に直接アクティブ化されたすべてのノードを表します`1`。 

2. 構造体の事前計算`up[k][i]`から到達可能な間隔の和集合を表します。`i`で`2^k`秒。 レベルで`0`、`up[0][i]`は単なる直前の間隔です。 

3. 上位レベルごとに`k`、2 つの間隔を結合します: 最初に適用します`2^{k-1}`からの秒数`i`、次に別のを適用します`2^{k-1}`結果として得られるカバー範囲からの秒数。 最初のステップでカバーされるすべての区間をマージし、それらの 2 番目のステップの展開の和集合を取得します。 これにより、飛躍的な到達可能性が構築されます。 

4. 各開始インデックスについて`i`では、2 の最大累乗から下方向への拡張を貪欲にシミュレートします。 現在の対象期間を維持します`[L, R]`。 申請する場合`up[k]`一周を超えずにカバレッジを拡大する場合は、それを取得して間隔を更新します。 

5. の答え`i`までに必要な最小ステップ数です。`[L, R]`少なくともスパン`n`倍増配列内の連続した位置。 

これが機能する理由は、展開の各層がすでに到達可能なノードにのみ依存し、間隔結合が単調増加を維持するためです。 ノードが到達可能になると、そこからの将来のすべての拡張は、そのノードに到達するまでに取られた正確なパスとは独立しているため、個別のアクティベーション履歴ではなく、カバレッジ境界を追跡するだけで済みます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    r = list(map(int, input().split()))
    
    # duplicate array for circular handling
    a = r * 2
    
    # precompute immediate reach intervals
    L = [0] * (2*n)
    R = [0] * (2*n)
    
    for i in range(2*n):
        L[i] = i - a[i]
        R[i] = i + a[i]
    
    # clamp into valid range [0, 2n-1]
    for i in range(2*n):
        if L[i] < 0:
            L[i] = 0
        if R[i] >= 2*n:
            R[i] = 2*n - 1
    
    LOG = 18
    upL = [[0] * (2*n) for _ in range(LOG)]
    upR = [[0] * (2*n) for _ in range(LOG)]
    
    for i in range(2*n):
        upL[0][i] = L[i]
        upR[0][i] = R[i]
    
    for k in range(1, LOG):
        for i in range(2*n):
            l = upL[k-1][i]
            rgt = upR[k-1][i]
            nl, nr = l, rgt
            for j in range(l, rgt + 1):
                nl = min(nl, upL[k-1][j])
                nr = max(nr, upR[k-1][j])
            upL[k][i] = nl
            upR[k][i] = nr
    
    res = [0] * n
    
    full_len = n
    
    for i in range(n):
        l, rr = i, i
        ans = 0
        
        for k in range(LOG-1, -1, -1):
            nl, nr = l, rr
            for j in range(l, rr + 1):
                nl = min(nl, upL[k][j])
                nr = max(nr, upR[k][j])
            
            if nr - nl + 1 < full_len:
                l, rr = nl, nr
                ans += (1 << k)
        
        res[i] = ans + 1
    
    print(*res)

if __name__ == "__main__":
    solve()
```実装は、ラップアラウンド間隔が連続セグメントになるように、円を 2 倍の配列に展開することから始まります。 即時の到達可能性は、各インデックスをその半径で拡張することによって計算されます。 

バイナリリフティングテーブル`upL`そして`upR`各ノードに対して、後で到達可能な最小および最大のインデックスを格納します。`2^k`秒。 トランジションはすべての中間間隔をマージします。そのため、各ステップは現在カバーされているセグメントをスキャンします。 

クエリの評価中に、まだ完全な円をカバーしていない可能な限り最大のジャンプを貪欲に適用します。 条件`nr - nl + 1 < n`現在のカバレッジがまだ不完全かどうかを確認します。 受け入れられたジャンプごとに追加される`2^k`秒。 

ここでよくある落とし穴は、中間展開がエンドポイントだけでなく、現在の間隔内のすべてのノードに依存することを忘れていることです。 そのため、各遷移ではカバー範囲全体にわたって区間和集合が再計算されます。

| ステップ | 間隔 |

これらのトレースは、成長が、拡大する間隔が高半径ノードにどれだけ早く到達するかに依存することを示しています。

 ## 特殊なケース

 1 羽のオウムの場合、間隔はすでにサイズ 1 の円全体に広がっているため、答えは次のようになります。`1`。 アルゴリズムが初期化されます`[l, r] = [i, i]`、完全なカバレッジを即座に満たすため、リフティング手順は適用されず、出力は維持されます。`1`。 

次のような均一な小さな値の場合`r_i = 1`、拡張は 1 秒あたり 1 レイヤー成長します。 任意の位置から開始し、その後`t`間隔の秒数`2t + 1`循環的な意味でのノード。 バイナリ リフティング ロジックは、間隔の長さに達するまで展開を正しく累積します。`n`、すべての指数にわたって一貫した回答が得られます。 

非常に大きな半径の場合、初期間隔はすでに 1 ステップで完全な円を超えています。 その場合、`up[0]`すぐに完全なカバレッジを生成し、貪欲なリフティングによってそれ以上のステップがトリガーされることはありません。 答えは次のようになります`1`すべてのポジションに。
