 ## 解決策

 ## 問題の理解

 私たちは一連の音符を与えられており、各音符はピアノの鍵盤上の水平方向の位置に配置されています。 目標は、1 から 5 までの番号が付けられた 5 つの指のいずれかを各ノートに割り当て、同じ長さの別のシーケンスを生成することです。 

割り当ては、連続するノートがキーボード上でどのように移動するかによって制限されます。 次の音符が右側にある場合は、指の番号を厳密に増やす必要があります。 左に移動する場合は、厳密に指の番号を減らす必要があります。 次の音符が同じ位置にある場合、指を切り替える必要があるため、この場合平等は禁止されます。 

これにより、メロディーが、指シーケンス内の連続する位置間の不等制約のシーケンスに変わります。 何かを最適化しようとするわけではなく、有効な割り当てが存在するかどうかを判断し、それらのいずれかを出力するだけです。 

n が 100000 までの制約により、線形または線形に近い解が強制されます。 各位置には最大 5 つの選択肢があり、単純に探索すると 5^n 個の状態につながるため、考えられるすべての指の割り当てを遡って追跡しようとするアプローチは爆発的に増加します。 以前の選択に依存する剪定であっても、それが非常に局所的なものでない限り危険です。 

同じ値が複数回出現する可能性を考慮せずに貪欲な選択をした場合、微妙な失敗例が発生します。 たとえば、3 3 3 3 のような平坦なセグメントでは、フィンガーを交互に使用する必要がありますが、初期の決定で制限しすぎると、使用できるフィンガーが限られているため、長時間の一定の実行を満たすことが不可能になる可能性があります。 

本当の難しさは、制約が隣接する要素間の比較のみに依存することです。 この局所性は、「現在の位置と現在の指」の状態を越える動的プログラミングまたはグラフの横断を示唆しています。 

## アプローチ

 強引なアイデアは、これを状態のグラフとして扱うことです。 各状態はインデックス i とフィンガー f によって定義されます。 各状態から、a[i] および a[i+1] に関する不等式制約を満たす 1 から 5 までのすべての可能な次のフィンガー f2 を試します。 これにより、各層に 5 つのノードがある階層化グラフが構築されます。 

これは、すべての有効な運指遷移を明示的に調査するため、正しいです。 ただし、インデックスごとに 5 つの状態と状態ごとに最大 5 つの遷移を処理するため、約 25n の操作が発生しますが、これは問題ありません。 本当の問題は、単純な実装がフルパスの列挙やバックトラッキングを試行することが多く、それが指数関数的に増大することです。 

重要な観察は、位置ごとに 5 つの状態にわたる到達可能性のみが必要であり、有効なパスも再構築したいということです。 これは、レイヤーごとの小さな固定状態空間上の古典的な DP です。 フィンガーの数は一定であるため、遷移を安全に保存し、実現可能性を前方に伝播することができます。 

この構造は本質的に、サイズ n × 5 の層状グラフを通るパスです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースバックトラッキング | O(5^n) | O(n) | 遅すぎる |
 | DPオーバー（人差し指、指） | O(25n) | O(5n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各位置 i と各指 f を「指 f で終わる i まで演奏可能」を意味する状態として扱います。

1. 最初の音には事前の制約がなく、どの指からでも開始できるため、1 から 5 までのすべての f に対して dp[1][f] = true を初期化します。 また、後でソリューションを再構築するために、先行ポインターも保存します。 
2. i を 1 から n - 1 まで反復し、位置 i の到達可能なすべての指 f から位置 i + 1 の指 f2 への遷移を試みます。 a[i] と a[i+1] の間の関係を尊重する遷移のみを許可します。 a[i] < a[i+1] の場合、f < f2 が必要です。 a[i] > a[i+1] の場合、f > f2 が必要です。 a[i] == a[i+1] の場合、f != f2 が必要です。 
3. 遷移が有効で、dp[i][f] が true の場合は常に、dp[i+1][f2] を true に設定し、そこに到達した方法を記憶するためにparent[i+1][f2] = f を保存します。 任意の有効なパスが受け入れられるため、保存する必要があるのは 1 つの親だけです。 
4. テーブルに記入した後、dp[n][f] が true であるかどうかを確認します。 どれも true でない場合は、有効な運指が存在しないため、-1 が出力されます。 
5. それ以外の場合は、有効な終了状態を選択し、親ポインターを (n, f) から (1, *) まで逆方向にたどることによってシーケンスを再構築します。 

重要な考え方は、すべての決定はローカルであり、最後に選択された指を除く以前の選択とは独立しているということです。これがまさにこれを有効な DP 状態定義にするものです。 

### なぜ効果があるのか

 不変条件は、指 f で終わる i までの接頭辞に有効な指使いが少なくとも 1 つ存在する場合に限り、dp[i][f] が true であるということです。 トランジション ステップでは、連続するノート間で必要な不等式制約を満たす移動のみが許可されるため、有効性が維持されます。 すべての有効な完全な解はこの層状状態グラフ内のパスに対応する必要があり、マークしたすべての状態はそのようなパスによって到達可能であるため、有効な解を見逃したり、無効な解を導入したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    dp = [[False] * 6 for _ in range(n)]
    parent = [[-1] * 6 for _ in range(n)]

    for f in range(1, 6):
        dp[0][f] = True

    for i in range(n - 1):
        for f in range(1, 6):
            if not dp[i][f]:
                continue
            for nf in range(1, 6):
                if a[i] < a[i + 1] and f >= nf:
                    continue
                if a[i] > a[i + 1] and f <= nf:
                    continue
                if a[i] == a[i + 1] and f == nf:
                    continue
                if not dp[i + 1][nf]:
                    dp[i + 1][nf] = True
                    parent[i + 1][nf] = f

    end_f = -1
    for f in range(1, 6):
        if dp[n - 1][f]:
            end_f = f
            break

    if end_f == -1:
        print(-1)
        return

    res = [0] * n
    cur_f = end_f
    for i in range(n - 1, -1, -1):
        res[i] = cur_f
        if i > 0:
            cur_f = parent[i][cur_f]

    print(*res)

if __name__ == "__main__":
    solve()
```DP テーブルは位置と指によってインデックスが付けられます。 明確にするために、明示的に 1 から始まるフィンガー インデックスを維持します。これにより、トランジションを比較する際の 1 つずつの間違いが回避されます。 親テーブルには、再構築用の前のフィンガーが格納されます。このフィンガーは、単一の一貫した再構築パスを確保するために、状態ごとに 1 回だけ埋められます。 

トランジション ロジックは、隣接する音符から 3 つの制約を直接エンコードし、無効な運指が到達可能とマークされることはありません。

```このトレースは、等価性制約により平坦なセグメントでの交互の強制が行われる一方で、ランの増減に柔軟性を持たせていることがわかります。

 ## 特殊なケース

 すべての指が有効であるため、単一の音符の入力は簡単です。 DP は 5 つの開始状態すべてを有効なものとして初期化するため、再構築ではただちに 1 つのフィンガーが返されます。 

2 2 2 2 のような一定のシーケンスでは、指を厳密に交互に配置する必要があります。 アルゴリズムはこれを処理します。トランジションでは等しい指は許可されませんが、残りの 4 つのオプション間の移動は許可され、任意の長さの実現可能性を維持するのに十分であるためです。 

1 2 3 4 5 のように厳密に増加するシーケンスには、フィンガー割り当てを厳密に増加する必要があります。 DP は自然に状態を上位のフィンガーに集中させ、無効な後方移動を排除し、1 2 3 4 5 などの増加パスを少なくとも 1 つ残します。 

厳密に減少するシーケンスは対称的に動作し、同じ状態の伝播により、可能であれば有効な厳密に減少するフィンガー パスが存在することが保証されます。
