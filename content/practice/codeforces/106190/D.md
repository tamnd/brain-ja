 ## 解決策
 ## 問題の理解

 この問題では、トラネコに似た生き物の失われた中尾の可能な長さを回復することが求められます。 3つの尾の長さは次のとおりです。`a`、`b`、 そして`c`、 どこ`a < b < c`。 最短と最長の長さはすでにわかっていますが、真ん中の長さがありません。 私たちにも与えられています`m`、これは、以下に現れるすべての異なる素因数の積です。`a * b * c`、製品の部首とも呼ばれます。 可能な最小値と最大値が必要です。`b`、またはそのような値が存在しないことを報告します。 元の問題は Codeforces Gym 106190 からのものです。 

入力には、いくつかの独立したケースが含まれています。 それぞれのケースが与えるもの`m`、`a`、 そして`c`。 答えは、有効な中央テールの長さの最小値と有効な中央テール長の最大値のペアの値です。 中間の長さは、既知の 2 つの長さの間に厳密に存在する必要があります。 

重要な制約は、`a`そして`c`せいぜい`10^6`、 その間`m`と同じ大きさにすることができます`10^18`。 これにより、考えられるすべての因数分解を試行することが直ちに除外されます。`m`あるいはその価値に比例した仕事をする。 上限`c`が鍵です: 考えられるすべての答え`b`よりも小さいです`10^6`したがって、比較的少数の候補数について推論する必要があるだけです。 

主なエッジケースは、ラジカルと元の製品を混同することから生じます。 数値には同じ素数を何度も含めることができますが、根号は素数が存在するかどうかのみを考慮します。 

例えば：```
Input:
210 5 21

Output:
6 20
```不注意なアプローチは、`b`まさに不足している素因数の積になります。 欠けている素因数は、`2 * 3 = 6`、 しかし`20`素数を追加するだけなので機能します`2`また。 過激派は残る`2 * 3 * 5 * 7`。 

もう 1 つの注意が必要なケースは次のような場合です。`a`または`c`に存在しない素数がすでに含まれています`m`。```
Input:
35 5 7

Output:
-1 -1
```ここ`a * c = 35`、したがって、ラジカルにはすでに含まれています`5`そして`7`。 値`m`しか持っていない`5`そして`7`もですが、その間の任意の値`5`そして`7`候補がこれしかないので無理です`6`、その根元には素数が追加されます`2`。 

3 番目のケースは次の場合です。`m`どちらの側にも含まれない素数が含まれています。```
Input:
12 2 6

Output:
-1 -1
```製品`a * c`すでに素因数を与えています`2`そして`3`。 可能な唯一の中間値は次のとおりです。`2`そして`6`, しかし、その区間内のすべての数値は、禁止された素数を導入するか、部首を正しく変更しません。 

## アプローチ

 直接的な解決策は、考えられるすべての中間尾部の長さをテストすることです。 あらゆる人にとって`b`から`a + 1`に`c - 1`、根号を計算できます。`a * b * c`そしてそれを比較してください`m`。 この範囲には考えられるすべての答えが含まれているため、これは正解です。 問題は繰り返し作業の量です。 すべてのテストが`c`に近い`10^6`、すべての候補をチェックし、それぞれを因数分解することは、多くのテストケースにとってコストがかかりすぎます。 

重要な点は、実際には製品全体が必要なわけではないということです。 部首は、どの素数が現れるかによってのみ決まります。 まず要因`a`そして`c`そして、それらがすでに寄与しているすべての素因数を収集します。 これらの素数のいずれかが含まれていない場合、`m`、即答は不可能です。 

ここで次の素数を考えてみましょう`m`。 それらのいくつかはすでに存在しています`a * c`。 残りの素数は次のように表示される必要があります`b`。 製品に電話をかける`need`。 すべての有効な`b`の倍数でなければなりません`need`。 

もう 1 つ制限があります。`b`外部に素数を導入することはできません`m`なぜなら、それだと最後の部首が大きくなりすぎるからです。 そこで、必要な部分を削除した後、`need`、残りの乗数は以下の素数のみを使用できます。`m`。 

以来`b < 10^6`、素因数が許可されたセットに属するすべての数値を生成し、次の最小倍数と最大倍数を見つけることができます。`need`合間に`(a, c)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((c-a) * sqrt(c)) | お(1) | 遅すぎる |
 | 最適 | テストごとに O(生成された候補の数)、10^6 | 未満の値で制限されます。 O(候補者数) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 要因`a`そして`c`そしてそれらの異なる素因数を保存します。 これらの素数は最後の部首にすでに強制的に表示されているため、これらの素数が必要です。 
2. 要因`m`それぞれの異なる素因数に分けられます。 もし`m`素数が含まれています。小さい方の辺の数字は説明されていません。後で強制的に適用します。`b`。 
3. すべての素因数が一致していることを確認します。`a`そして`c`に存在します`m`。 これが失敗した場合、値は失われます`b`ラジカルから余分な素数を削除できます。 
4. コンピューティング`need`、内のすべての素数の積`m`それが欠けている`a * c`。 これは、からの最低限必要なプライム寄与です。`b`。 
5. の素因数のみから作られるすべての値を生成します。`m`。 生成されたすべての値に対して`x`、それを乗算します`need`以下に留まる場合`c`。 結果はミドルレングス候補です。 
6. すべての候補者の中で厳密に次の条件を満たしている`a`厳密にそれより小さい`c`、最小値と最大値を保持します。 

この世代が機能する理由は、すべての有効な`b`2つの部分に分割できます。 1 つの部分には追加する必要がある不足している素数が含まれており、もう 1 つの部分はすでに許可されている素数の累乗のみを増加します。 ジェネレーターはまさにこれらの可能性のある追加パーツを作成します。 

なぜ機能するのか: 最後の根号は、以下の素因数の結合です。`a`、`b`、 そして`c`。 小切手はそれを保証します`a`そして`c`禁止された素数が含まれていないこと。 必要な部分がそれを保証します`b`不足している素数をすべて供給します`m`。 生成された乗数は新しい素数を追加できないため、受け入れられたすべての候補は必要な根号を正確に持ちます。 すべての有効な`b`もこの形式で表すことができるので、答えを見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def factor(x):
    res = []
    d = 2
    while d * d <= x:
        if x % d == 0:
            res.append(d)
            while x % d == 0:
                x //= d
        d += 1 if d == 2 else 2
    if x > 1:
        res.append(x)
    return res

def solve_case(m, a, c):
    fm = set(factor(m))
    fa = factor(a)
    fc = factor(c)

    for p in fa + fc:
        if p not in fm:
            return -1, -1

    need = 1
    base = set(fa + fc)
    for p in fm:
        if p not in base:
            need *= p

    allowed = list(fm)
    limit = c // need

    vals = [1]
    for p in allowed:
        cur = []
        for x in vals:
            y = x
            while y * p <= limit:
                y *= p
                cur.append(y)
        vals += cur

    ans_min = 10**18
    ans_max = -1

    for x in vals:
        b = x * need
        if a < b < c:
            ans_min = min(ans_min, b)
            ans_max = max(ans_max, b)

    if ans_max == -1:
        return -1, -1
    return ans_min, ans_max

def main():
    t = int(input())
    out = []
    for _ in range(t):
        m, a, c = map(int, input().split())
        x, y = solve_case(m, a, c)
        out.append(f"{x} {y}")
    print("\n".join(out))

main()
```の`factor`累乗の累乗は根号にとって重要ではないため、関数は個別の素因数のみを保存します。 要因を見つけた上で、`m`、コードは最初に不可能なケースを拒否します。`a`または`c`ターゲットラジカルの外側に素数を導入します。 

変数`need`の必須部分を表します`b`。 残りの生成された値は、次の素数のみを使用できます。`m`これにより、誤ってより大きなラジカルを作成することを防ぎます。 

生成ループは、既存の値に許可された素数を乗算して数値を増やします。 限界は`c // need`なぜなら乗算すると`need`その後も候補を下に保持する必要があります`c`。 中央の尾部は 2 つの既知の尾部と等しくなく、それらの間になければならないため、厳密な不平等チェックが必要です。

 ## 特殊なケース

 いつ`m`は`1`、素因数はどこにも出現しない可能性があります。 可能な値は、完全に次の範囲外の素因数で構成される数値だけです。`m`、つまり、使用できる唯一の数値は`1`。 ジェネレーターは次から始まります`1`なので、このケースは正しく検出されます。 

いつ`a`または`c`に含まれない素数が含まれています`m`の場合、アルゴリズムは検索前にケースを拒否します。 例えば：```
35 5 7
```既知の尾部はすでに素数を強制します`5`そして`7`、ただし、ターゲットのラジカルは追加の中間値と互換性がありません。 答えは残っている`-1 -1`。 

欠けている素数の積が大きい場合、`need`それ自体が近くにある可能性があります`c`。 生成された乗数は非常に小さくなりますが、最後の間隔チェックにより戻りが妨げられます。`a`または`c`偽の回答として。 これにより、厳密な不等式に関する境界エラーが処理されます。
