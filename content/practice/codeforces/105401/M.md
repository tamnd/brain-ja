 ## 解決策
 ## 問題の理解

 すべての頂点が最初に白または黒のいずれかに着色されているツリーが与えられます。 ツリー構造は固定されていますが、任意のエッジの 2 つの端点の色を交換する操作を実行することができ、そのような交換ごとに 1 ユニットのコストがかかります。 

これらの交換のシーケンスを実行すると、最終的に新しいカラーリング構成が得られます。これを最終構成と呼びます。 この最終的な構成は、使用したスワップの数だけでなく、すべてのスワップが完了した後に計算された構造コストによっても判断されます。 色ごとに、その色のすべての頂点を接続するツリーの最小接続部分グラフを考慮します。 色のコスト寄与は、この最小の接続部分グラフ内のエッジの数であり、これはツリー内のその色クラスにわたる最小のシュタイナー ツリーのサイズと正確に一致します。 

目標は、一連のスワップを選択し、スワップ コストの合計と白のシュタイナー ツリー サイズと黒のシュタイナー ツリー サイズの合計を最小化する最終的な色付けを選択することです。 

重要な点は、交換によってツリー内の色が存在する場所が変わりますが、実際のコストがかかると同時に、その後同じ色の頂点を接続するコストも変化するということです。 

制約$N \le 5 \cdot 10^5$あらゆる解を線形時間または線形演算時間に近づけます。 仮想的な交換後に距離や接続コストを繰り返し再計算するものは、すぐに遅すぎます。これは、色の再配置の空間が指数関数的であるためです。$N$。 

スワップを色の恣意的な再配置として扱うという単純な考えは、すぐに失敗します。 スワップはエッジに沿ってのみ行われますが、スワップを繰り返すことで、接続されたパスに沿って色を効果的に並べ替えることができます。 これは、最終的には任意の頂点が任意の色を保持できることを意味しますが、コストはツリー内の距離に比例します。 これはすでに最短パス スタイルの構造を示唆しています。 

白と黒を個別に最適化できると仮定すると、微妙な失敗例が現れます。 たとえば、色が交互になるライン ツリーでは、白の接続を局所的に最小化すると、白の頂点が押し寄せられる可能性がありますが、黒の広がりが劇的に増加し、スワップ コストが両方の決定を同時に結びつけます。 

もう 1 つの落とし穴は、交換後、元の色を無視して頂点を単に白と黒に「最適な分割を選択」できると仮定していることです。 これは、各頂点が固定色で始まり、色を移動するにはパスに沿って支払う必要があることを無視しています。 

## アプローチ

 総当り的な観点では、色の最終的な割り当てをすべて考えてコストを計算することになります。 各候補カラーリングについて、初期カラーリングをターゲットカラーリングに変換するために必要な隣接するスワップの最小数としてスワップコストを計算します。これは、ツリー上の最小コストフローまたは輸送距離問題と同等です。 次に、両方の色のシュタイナー ツリーのサイズを計算します。 

これはすでに巨大です。 着色数は、$2^N$、単一のものを評価する場合でも、グローバルな計算が必要です。 したがって、このアプローチは完全に実行不可能です。 

重要な構造的洞察は、両方のコスト要素が非常に似た方法でエッジ上で分解されるということです。 ツリー上では、ある色のシュタイナー ツリーのサイズは、両側にその色の頂点が少なくとも 1 つあるエッジの数と等しくなります。 同様に、エッジの場合、そのエッジを削除することによって誘導された両方のサブツリーにその色が表示される場合、その色のシュタイナー ツリーに寄与します。 

次にスワップコストを考えてみましょう。 エッジに沿った交換では、カット全体で 1 単位の白い塊と 1 単位の黒い塊が効果的に移動します。 エッジに注目する場合、重要なのは、そのエッジを通過する必要がある白の数と比較して、そのエッジを通過する必要がある白の数です。これは、スワップがエッジに沿って色単位を転送するものと解釈できるためです。 

これは流れの解釈を示唆しています。 私たちは基本的に初期分布を最終分布に変換しようとしているのですが、各エッジには色の不均衡がどの程度交差するかに比例したコストがかかります。 一方、スタイナー ツリーのコストも、各辺に特定の色の頂点が少なくとも 1 つ含まれるかどうかによってのみ決まります。 

重要な単純化は、ツリーをルート化し、最終構成の各サブツリーに必要な白と黒の頂点の数を検討することです。 スワップはグローバルカウントを変更しないため、分配のみが問題になります。 最適な戦略は、最終的に各サブツリーに配置する白の数のみに依存し、コストはサブツリーの白数の関数のエッジの合計になります。 

これにより、各エッジについて、初期状態で片側に何個の白が存在するかのみに依存する寄与を計算するという問題が軽減されます。 最終的な解決策は、サブツリー数とエッジ寄与のツリー DP/リルート スタイルの計算になります。

 ## アルゴリズムのチュートリアル

 任意のノード (ノード 1 など) でツリーをルート化し、サブツリー情報を計算します。 

1. すべてのノードについて、初期カラーリングでのサブツリー内の白い頂点の数を計算します。 これにより、白色質量のベースライン分布が得られます。 
2. ルート付きツリー内のノードとその親の間のすべてのエッジについて、そのエッジの下にあるサブツリーを考慮します。 させて$w$はそのサブツリー内の白い頂点の数であり、$b$黒い頂点の数。 
3. 重要な観察は、色の再配置によってエッジの両側に白と黒がどのように分布するかが変わるだけで、総数をグローバルに変えることはできないということです。 このエッジにわたるスワップ コストは、望ましい分布と現在の分布の間で可能な限り一致するときに最小化され、不一致がある場合はエッジ全体でカラー ユニットが移動することに対応します。 
4. 固定エッジの場合、各スワップがそのエッジに沿った不均衡の 1 単位しか修正できないため、最小限の避けられない寄与はサブツリー内の白と黒のカウント間の不均衡に比例することになります。 
5. 各エッジは、最終コストの 2 つの部分に寄与します。 まず、スタイナー ツリーの寄与は、再配置後に両方の色がエッジの両側に表示される場合は 1 で、それ以外の場合は 0 になります。第 2 に、スワップ コストは、再配分を達成するためにそのエッジを横切る必要があるユニットの数を反映します。 
6. 最適な構成はサブツリーのサイズと合計数にのみ依存するため、初期のサブツリーのホワイト カウントを使用してエッジごとの寄与を集計できます。 最終的な答えは、次の固定関数を合計することによって計算されます。$w$そして$b$すべてのエッジにわたって。 

### なぜ効果があるのか

 ツリーの各エッジは、頂点を 2 つの独立した部分に分離するカットです。 スワップ操作とシュタイナー ツリー エッジの両方は、このカット全体に色がどのように分布するかのみに依存します。 グローバル構成では、カットごとに独立した要件が発生しますが、基礎となるグラフはツリーであるため、これらの要件は干渉しません。 したがって、最適な解決策は、色数の全体的な保存を一貫して各エッジの寄与を最小化することによって得られます。 このエッジ間の分離により、集約アプローチの正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input().strip())
    s = input().strip()

    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * n
    order = []
    stack = [0]
    parent[0] = -2

    # iterative DFS to avoid recursion depth issues
    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            if parent[v] != -1:
                continue
            parent[v] = u
            stack.append(v)

    white = [0] * n
    for i in range(n):
        white[i] = 1 if s[i] == 'W' else 0

    for u in reversed(order):
        for v in g[u]:
            if v == parent[u]:
                continue
            white[u] += white[v]

    total_white = white[0]

    # edge contribution
    ans = 0
    for v in range(1, n):
        u = parent[v]
        if u == -1:
            continue
        w = white[v]
        b = (sub := 0)
        # subtree size of v
        # recompute via white + black
        # black in subtree = size - white
        # but we compute size via DFS order accumulation
        # easier: store subtree size separately
        pass

    # correct second pass to compute subtree sizes
    size = [1] * n
    for u in reversed(order):
        for v in g[u]:
            if v == parent[u]:
                continue
            size[u] += size[v]

    ans = 0
    for v in range(1, n):
        u = parent[v]
        if u == -1:
            continue
        w = white[v]
        b = size[v] - w

        # each edge contributes:
        # white crossing + black crossing in optimal balancing interpretation
        ans += min(w, b) + min(total_white - w, (n - total_white) - b)

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、ツリーを構築し、それをノード 1 でルート化することから始まります。再帰制限を回避するために、非再帰的 DFS が使用されます。$N$大きくなる可能性があります。 

事後探索を使用してサブツリーのホワイト カウントを計算します。 これにより、子と親の関係によって暗黙的に表されるすべてのエッジについて、子側にある白の数がわかります。 

また、サブツリー サイズも計算します。これにより、2 番目の DP 配列を維持せずに黒数を推測できるようになります。 

最後のループでは、すべてのエッジが 1 回だけ処理されます。 各サブツリーについて、その下に白人と黒人の数を計算し、それらをグローバル合計と比較します。 使用される式は、両方の色に関してカット全体にどれだけの不一致が存在するかを反映します。これは、そのエッジ全体にわたる避けられないスワップ フローと、誘発されるシュタイナー分離コストに相当します。

 ## 特殊なケース

 重要なエッジ ケースは、本質的にパスであるツリーです。 その場合、すべてのエッジがプレフィックスとサフィックスを分離するため、サブツリー数はプレフィックス数に直接対応します。 アルゴリズムは各エッジを 1 回処理し、寄与はプレフィックスの白数のみに依存するため、特別な処理は必要ありません。 

もう 1 つのエッジケースは、星型のツリーです。 ここでは、すべてのエッジが葉を中心に接続します。 各サブツリーは単一のノードであるため、寄与はその葉の色が全体的な不均衡と一致するかどうかにのみ依存します。 DFS ベースのサブツリー計算では、依然として正しいサイズと白数が生成され、各エッジは独立して評価され、予想される構造と一致します。 

3 番目のエッジ ケースは、すべての白人が 1 つのサブツリーにクラスター化されている場合です。 その状況では、1 つのエッジには大きな不均衡が生じますが、他のエッジにはバランスが取れています。 このアルゴリズムは、色分布が変化する境界エッジにのみ大きな寄与を正しく割り当てます。これは、サブツリーの白数がそのカットでのみ全体の合計と大きく異なるためです。
