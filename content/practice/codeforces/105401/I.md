 ## 解決策
 ## 問題の理解

 2 人のプレイヤーがじゃんけんを繰り返し行う確率的なターンベースのゲームをシミュレートしていますが、結果によってすぐに勝者が決まるわけではありません。 代わりに、ラウンドごとに次のラウンドの「攻撃者」になる人が決定され、誰かがすでに攻撃している場合に同点の場合のみゲームが終了する可能性があります。 

入力により、ラウンドごとに、A と B の手の選択肢に対する独立した確率分布が得られます。 これらの分布から、各ラウンドの 3 つの意味のある確率を導き出すことができます。A がラウンドに勝つ (ジャンケンの有利)、B がラウンドに勝つ、またはラウンドが引き分けです。 

ゲームは、攻撃者が存在しない、A が現在の攻撃者、B が現在の攻撃者であるなど、隠れた状態で時間の経過とともに進化します。 攻撃側がいないときに同点になった場合は、特別なことは何も起こらず、ゲームは続行されます。 誰かがすでに攻撃者であるときに同点になった場合、その攻撃者が即座に勝ち、ゲームは終了します。 同点でない場合は、そのラウンドの勝者が次のラウンドの攻撃者になります。 

タスクは、プロセスが B に有利に終了するか、勝者なしで終了する前に、最終的に A が勝者になる確率を計算することです。 最終的な答えは、998244353 のモジュール値として返される必要があります。 

制約は最大 2×10^5 ラウンドに及ぶため、すべての確率的パスを明示的にシミュレートするアプローチは不可能です。 すべての歴史にわたる状態空間の拡大でさえ、指数関数的に増加するでしょう。 少数の状態にわたる線形時間動的プログラムが唯一の実行可能な方向です。 

微妙なエッジケースは、攻撃者が確立された後、同点になるまで攻撃者が現れない場合です。 たとえば、ある時点で A がアタッカーになり、その後引き分けになった場合、ゲームは直ちに終了します。 攻撃者の遷移を追跡するだけで、同点によってプロセスが終了する可能性があることを忘れた単純なシミュレーションでは、継続確率を過大評価し、不正確な結果が生成されます。 

すべてのラウンドが期待値で同点である場合 (たとえば、対称性をもたらす同一の分布)、別の特殊なケースが発生します。 このような場合、ゲームが終了する唯一の方法は、攻撃者の初期状態を経由することです。攻撃者状態からの最終遷移を伝播することを忘れると、無限継続を誤って仮定する答えが得られます。 

## アプローチ

 ブルートフォース解釈では、n ラウンドにわたるすべての可能な結果シーケンスを明示的にシミュレートします。 各ラウンドには 3 つの結果があります。A が攻撃者になる、B が攻撃者になる、または引き分けです。 これにより 3^n 通りの可能な軌跡が生成され、攻撃者のステータスがパスに依存した方法で終了条件と相互作用するため、同一の状態をマージしても役に立ちません。 これは実現可能な計算をはるかに超えています。 

重要な観察は、プロセスを続行するために必要な唯一の情報は、完全な履歴ではなく、現在のラウンド インデックスと攻撃者の状態の 2 つの部分だけであるということです。 選択は独立しており、次の状態にのみ影響するため、他のすべてはラウンド間で独立しています。 

これにより、問題は、攻撃者なし、攻撃者 A、攻撃者 B の 3 つの状態を含むマルコフ プロセスに縮小されます。 各ラウンドは、これらの状態間の固定遷移確率に寄与し、さらにプロセスが終了するところでの遷移を吸収します。 これを認識すると、問題全体が n ステップにわたる順動的プログラムになります。 

各ラウンドの開始時に 3 つの状態にわたる確率分布を維持し、そのラウンドの事前計算された結果確率を使用してそれを前方に伝播します。 攻撃側の状態で同点に遭遇すると、吸収的な「A の勝ち」または「B の勝ち」イベントに移行し、最終的な答えへの貢献を蓄積します。

 ## アルゴリズムのチュートリアル

 各ラウンドを 3 つの確率 (A が B に勝つ、B が A に勝つ、同点) に圧縮します。 これらは、指定された独立分布から直接計算されます。 

次に、各ラウンドの開始時にゲームが特定の状態にある確率を超えて DP を維持します。 

### ステップ

 1. 各ラウンド i について、A が勝ち、B が勝ち、引き分けに対応する確率 pA[i]、pB[i]、および pT[i] を計算します。 

これらは、R、S、および P の選択の独立した積確率の合計から得られます。 
2. ラウンド 1 で、dp_none = 1、dp_A = 0、dp_B = 0 で DP を初期化します。 

これは、最初は攻撃者が存在しないことをエンコードします。 
3. 1 から n までの各ラウンド i で、pA[i]、pB[i]、pT[i] を使用して 3 つの状態からプロセスが遷移します。 
4. 「攻撃者なし」状態から、非終端遷移のみを伝播します。 

勝利すると次のラウンドの確率マスが状態 A に送信され、B が勝利すると状態 B に送信され、引き分けの場合は攻撃者がいない状態に保たれます。 
5. 「攻撃者」状態からは、結果を慎重に処理します。 

勝利すると、A は次のラウンドの攻撃者として残ります。 

B勝利でアタッカーをBに切り替え、

 この場合、A が勝ち、確率は続行されないため、同点はすぐに答えに寄与します。 
6. 状態「B 攻撃者」から、同様に次のようにします。 

勝利すると攻撃者がAに切り替わり、

 B が勝利すると、B はアタッカーとして維持されます。 

同点の場合は B の勝利でゲームが終了するため、A の答えには影響しません。 
7. すべてのラウンドを処理した後、残りの確率の塊は、終了しなかったゲームに対応します。 これらは A の勝率にはまったく寄与しません。 
8. A が勝つ累積確率を法 998244353 で返します。 

### なぜ効果があるのか

 いつでも、将来の動作は現在のラウンド インデックスと攻撃者の状態にのみ依存します。 過去の歴史はすべて、この状態を通じてのみ将来に影響を与えるため、これは十分な統計です。 DP はこれらの状態全体で正確な確率質量を保存し、すべての遷移でプロセスが保存されるか、イベントを吸収するターミナルに 1 回だけ移動され、過剰カウントや確率の損失が保証されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n = int(input())
    
    A = []
    B = []
    
    for _ in range(n):
        r, s, p = map(int, input().split())
        tot = r + s + p
        A.append((r * modinv(tot)) % MOD)
        A.append((s * modinv(tot)) % MOD)
        A.append((p * modinv(tot)) % MOD)
    
    Ar = []
    As = []
    Ap = []
    for i in range(n):
        r, s, p = map(int, input().split())
        tot = r + s + p
        Ar.append((r * modinv(tot)) % MOD)
        As.append((s * modinv(tot)) % MOD)
        Ap.append((p * modinv(tot)) % MOD)
    
    dp0 = 1
    dpA = 0
    dpB = 0
    ans = 0
    
    for i in range(n):
        ar, as_, ap = A[3*i], A[3*i+1], A[3*i+2]
        br = Ar[i]
        bs = As[i]
        bp = Ap[i]
        
        pAwin = (ar * bs + as_ * bp + ap * br) % MOD
        pBwin = (br * as_ + bs * ap + bp * ar) % MOD
        pTie = (pAwin + pBwin) % MOD
        pTie = (1 - pTie) % MOD
        
        ndp0 = ndpA = ndpB = 0
        
        ndp0 = (ndp0 + dp0 * pTie) % MOD
        ndpA = (ndpA + dp0 * pAwin) % MOD
        ndpB = (ndpB + dp0 * pBwin) % MOD
        
        ndpA = (ndpA + dpA * pAwin) % MOD
        ndpB = (ndpB + dpA * pBwin) % MOD
        ans = (ans + dpA * pTie) % MOD
        
        ndpA = (ndpA + dpB * pAwin) % MOD
        ndpB = (ndpB + dpB * pBwin) % MOD
        
        dp0, dpA, dpB = ndp0, ndpA, ndpB
    
    print(ans % MOD)

if __name__ == "__main__":
    solve()
```この実装では、各ラウンドの開始時の攻撃者の状態に対応する 3 つのローリング確率集合が維持されます。 重要な微妙な点は、攻撃側の状態での同点の結果は前方に遷移するのではなく、最終的な答えに直接寄与するということです。そのため、これらの結果は次のように累積されます。`ans`次の DP 層ではなく。 

確率の計算では全体でモジュラー演算が使用され、998244353 未満の端数を表すために逆モジュラーが使用されます。各ラウンドは一定時間で処理され、線形パフォーマンスが保証されます。 

## 実用的な例

 ### 例 1

 結果が十分に決定的であり、A が常にすぐに優勢である単純化されたケースを考えます。 

| ラウンド | dp0 | dpA | dpB | パウィン | pBwin | ピータイ | アクション |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 0 | 1 | 0 | 0 | 攻撃者に移動 |

 プロセスはすぐに A が攻撃者に移行し、同点が決して発生しないため、終了条件によって A が勝つことはありませんが、最終的には状態の進化を通じて確率が蓄積され、A の勝利が保証されます。 

このトレースは、攻撃者の作成が初期のダイナミクスをどのように支配しているかを示しています。 

### 例 2

 対称構成では、すべての結果の可能性が等しくなります。 

| ラウンド | dp0 | dpA | dpB | パウィン | pBwin | ピータイ | 答え |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 0 | 1/3 | 1/3 | 1/3 | 0 |
 | 2 | 1/3 | 1/3 | 1/3 | ... | ... | ... | 蓄積する |

 これは、答えが純粋な優位性の遷移ではなく、攻撃者の状態でのタイ イベントによって完全に駆動されることを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、攻撃者が早期に確立され、次のインタラクションが引き分けになった場合に発生します。 その状況では、ゲームは即座に終了し、現在の攻撃者の勝利確率に正確に影響します。 DP は、攻撃者の状態からのすべての同点確率の質量を応答アキュムレータに明示的にルーティングするため、継続状態が誤って存続することはありません。 

もう 1 つのエッジ ケースは、攻撃者が作成されず、ゲームが同点のみを確認する場合です。 その場合、dp0 は単純に減衰する一方、dpA と dpB はゼロのままであり、応答に寄与はまったく追加されません。 A に有利な終了条件がトリガーされないため、結果は正しくゼロになります。 

最後のエッジケースは、攻撃者の状態が A と B の間で同点なしで変動する場合に発生します。 DP は、ラウンド全体にわたって両方の可能性を正しく保存します。これは、引き分けでない結果は終了せずに攻撃者の状態を更新するだけであるため、確率量が失われたり、時期尚早に吸収されたりしないことが保証されます。
