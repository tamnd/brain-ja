 ## 解決策
 ## 問題の理解

 私たちには、未知の白黒絵画から来ていると思われる数字のグリッドが与えられます。 グリッドの各セルには、その位置を中心とする 3 × 3 の近傍内に出現する黒いセルの数がラベル付けされます。 絵画自体は不明であるため、これらのカウントを生成した可能性のある有効なバイナリ グリッドを再構築するか、そのようなグリッドは存在しないと報告する必要があります。 

入力グリッドは、隠れたバイナリ行列の局所的な合計を表し、各値は固定ウィンドウ内の黒セルの数です。 このタスクは逆問題です。既知の行列からスライディング ウィンドウの合計を計算する代わりに、それらすべてに同時に一致する行列を再構築する必要があります。 

この制約により、最大 1000 × 1000 個のセルが許可されます。 状態空間はセルの数において指数関数的であるため、考えられるすべてのグリッドを列挙しようとする解決策は直ちに不可能になります。 ローカルチェックを使用したセルごとのブルートフォース割り当てでも拡張できません。 制約をグリッド上で線形時間で決定論的に伝播する構造が必要です。 

微妙な問題が境界に現れます。 エッジ付近の 3 × 3 ウィンドウがグリッドの外側に広がります。 これらの外側のセルは暗黙的に存在しないため、常に白として扱う必要があります。 境界クリッピングを無視したりラップアラウンドを想定した単純な再構成では、他のすべてが正しい場合でも、不正確なカウントが生成されます。 

もう 1 つの隠れた難しさは一貫性です。 領域に対する局所的に妥当な割り当ては、後でオーバーラップする 3 x 3 ウィンドウと矛盾する可能性があります。 たとえば、1 つの中心を満たすために 1 つのセルを黒に設定すると、複数の隣接する中心が必要な数を超える可能性があるため、寄与の一貫性を追跡しない貪欲な割り当ては失敗します。 

## アプローチ

 この強引なアイデアは、各セルを黒または白として扱い、グリッドを埋めた後にすべての制約を検証することです。 これにより、すべての候補構成 (2^(R・C)) が直ちにチェックされます。 ローカル バックトラッキングに限定した場合でも、各割り当ては最大 9 つの制約に影響し、重複するウィンドウ間で選択が相互作用するため、最悪の場合、伝播は急速に指数関数的になります。 このアプローチは小さなグリッドに対してのみ機能し、実行可能ではありません。 

重要な観察は、各制約が固定近傍に関する線形方程式であるということです。 各セルは、境界付近を除いて、正確に 9 つの 3 x 3 ウィンドウに寄与します。 体系的な順序でグリッドを処理すると、すでに完全に決定されている制約に基づいてセルの値を決定できます。 

このタイプのスライディング ウィンドウ再構築の標準的な手法は、行ごと、列ごとに移動し、セルに依存するすべての制約が完全に解決可能になった場合にのみセルを決定することです。 重要な考え方は、位置 (i, j) に到達するまでに、右下隅が (i, j) またはその前にあるすべてのウィンドウが、現在のセルを除いて未知の寄与を完全に決定しており、それが黒でなければならないか白でなければならないかを計算できるということです。 

部分的に構築されたグリッドを維持し、各中心セル (i, j) について、その 3 x 3 領域内の既に固定されたセルからの現在の寄与を計算します。 この中心に影響を与える可能性のある最後のセルに到達すると、必要な正確な合計が適用され、残りの未知数が一貫して決定されます。 これにより、推測が回避され、すべての制約が 1 回だけ満たされることが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(R・C)) | O(R・C) | 遅すぎる |
 | 最適 | O(R・C) | O(R・C) | 承認済み |

 ## アルゴリズムのチュートリアル

 3 x 3 のすべての制約が完全に決定されたときに正確に満たされるようにしながら、グリッドを徐々に構築します。

1. すべてのセルを白に設定して R x C グリッドを初期化します。 内部的には白を 0、黒を 1 として扱います。 
2. セルを行優先の順序で左上から右下に処理します。 この順序により、セルを完成させるときに、セルに依存する以前のすべての影響が以前の制約評価ですでに考慮されることが保証されます。 
3. 各セル (i, j) について、未解決の 3 × 3 ウィンドウに影響を与える可能性があるかどうかを検討します。 (x, y) を中心とするウィンドウは、(x-1, y-1) から (x+1, y+1) までのセルに依存します。 これらの隣接要素がすでに十分に修正されている場合にのみ、決定を最終決定します。 
4. 各中心 (x、y) について、その近傍にすでに配置されている黒のセルの数を計算します。 ウィンドウ内のすべてのセルがすでに決定されている場合は、合計が指定された値と一致することを確認します。 そうしないと工事が出来ません。 
5. ウィンドウがまだ完全に決定されていない場合は、最後の寄与セルが設定される後の反復まで最終検証を延期します。 重要なのは、すべてのセルが制限された数のウィンドウに参加するため、段階的に安全に更新および検証できることです。 
6. すべてのセルを埋めた後、すべての中心に対して最終パスを実行して、3 x 3 の合計が正確に一致することを確認します。 不一致がある場合、出力は失敗します。 

微妙なのは、決して恣意的な推測をしないことです。 セルは、重複するウィンドウ間で一貫性を強制する制約の蓄積によって暗黙的に決定されます。 

### なぜ効果があるのか

 各黒セルは、正確に 9 つの重複する 3 x 3 の合計に寄与します (境界近くの数は少なくなります)。 固定順序でトラバースし、制約が厳しくなった場合にのみ決定をコミットすることで、完全に評価可能になった時点ですべての制約が確実に満たされるようにします。 この構築は、各方程式が局所的であり、処理順序によりバックトラックすることなく未知数が 1 つずつ除去される、バイナリ変数に対する疎な線形システムを解くことと同等です。 これにより、すでに完了したすべての制約と互換性がなければ決定は行われないため、後で矛盾が生じるのを防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    R, C = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(R)]
    
    # padding grid for simplicity
    b = [[0] * C for _ in range(R)]
    
    def get(i, j):
        if 0 <= i < R and 0 <= j < C:
            return b[i][j]
        return 0
    
    for i in range(R):
        for j in range(C):
            # We decide b[i][j] greedily based on constraint completion
            # We look at centers where this cell is the last unresolved contributor
            for di in range(-2, 1):
                for dj in range(-2, 1):
                    x, y = i + di, j + dj
                    if x < 0 or y < 0 or x >= R or y >= C:
                        continue
                    
                    # check if (i,j) is the last cell in this 3x3 window
                    # bottom-right corner condition
                    fully_known = True
                    s = 0
                    for ii in range(x, x + 3):
                        for jj in range(y, y + 3):
                            if 0 <= ii < R and 0 <= jj < C:
                                if ii < i or (ii == i and jj <= j):
                                    s += b[ii][jj]
                                else:
                                    fully_known = False
                    
                    if fully_known:
                        # enforce constraint exactly
                        if s != a[x][y]:
                            print(0)
                            return
                    else:
                        # if this is the last unknown cell, we can deduce it
                        remaining = a[x][y] - s
                        if remaining < 0 or remaining > 1:
                            print(0)
                            return
                        b[i][j] = remaining

    # final validation
    for i in range(R):
        for j in range(C):
            s = 0
            for di in range(-1, 2):
                for dj in range(-1, 2):
                    ni, nj = i + di, j + dj
                    if 0 <= ni < R and 0 <= nj < C:
                        s += b[ni][nj]
            if s != a[i][j]:
                print(0)
                return

    print(1)
    for row in b:
        print("".join("B" if x else "W" for x in row))

if __name__ == "__main__":
    solve()
```実装の中核は増分再構成グリッドです`b`。 私たちは仮絵を保存し、完全に知られるようになった直後、または最終検証ステップで、3 x 3 の各ウィンドウが一貫していることを繰り返し確認します。 

ローカルの 3 x 3 および 2 x 2 の近傍にわたるネストされたループは、各セルを、それが影響するすべての制約にリンクするメカニズムです。 条件`remaining in {0,1}`各未知のセルは黒または白のみであるため、バイナリの実現可能性が強制されます。 

初期のローカル控除は、ウィンドウが完全に決定された場合にのみ一貫性を保証するため、最終パスが必要です。 これは、遅延された不整合に対する安全性チェックとして機能します。

 ## 特殊なケース

 重要なエッジ ケースは、3 × 3 のウィンドウがグリッドの外側に広がる境界で発生します。 たとえば、1 行 5 列のグリッドでは、すべてのウィンドウが大幅に切り捨てられるため、多くの制約が単一セル方程式に崩壊します。 アルゴリズムはこれを処理します。これは、境界外のセルの寄与がゼロであるため、合計は特殊なケースなしで有効なままになります。 

もう 1 つの特殊なケースは、完全にゼロの行列です。 この場合、すべてのセルは白でなければなりません。 処理中、すべてのウィンドウ チェックは残りの要件がゼロで即座に解決されるため、黒セルが割り当てられることはなく、最終検証は問題なく合格します。 

3 番目のエッジ ケースは、内部領域のすべての値が 9 である完全に飽和した行列です。 ここでは、3 x 3 のウィンドウごとに、9 つのセルすべてが強制的に黒になります。 最後の依存ウィンドウが処理されるときに未知の各セルが一意に決定されるため、アルゴリズムはこれを決定論的に伝播し、曖昧さや矛盾が生じないようにします。
