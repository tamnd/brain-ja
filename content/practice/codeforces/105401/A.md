 ## 解決策
 ## 問題の理解

 長さの文字列が与えられます$n$アルファベット以上の大きさ$C$ただし、文字列を直接操作する代わりに、KMP プレフィックス関数 (失敗関数) を通じてその構造を調べます。 ポジションごとに$i$、関数$f(i)$で終わる接尾辞にも一致する、文字列の最も長い適切な接頭辞の長さを示します。$i$。 これにより、各位置からの有向エッジが自然に定義されます。$i$より小さいインデックスへ$f(i)$、ノード付き$0$普遍的なルートとして機能します。 

ノードを配置すると$0,1,2,\dots,n$水平線上に順番にすべての端を描きます$i \to f(i)$線の上の円弧として、これらの障害リンクの幾何学的画像が得られます。 この問題は、どの文字列がこれらの円弧を交差せずに描くことができる構成を生成するかを尋ねます。 

タスクは、長さの文字列が何個あるかをカウントすることです$n$以上$C$文字はこのような非交差構造を生成します。$998244353$。 

この制約により、位置の反復処理に依存する構築から即座に遠ざけられます。 の値$n$と同じ大きさにすることができます$10^{18}$これは、プレフィックス関数の構築をシミュレートすることも、文字列について明示的に推論することもできないことを意味します。 有効な解はすべて、構造全体を一定サイズの漸化式または迅速にべき乗できる直接式に折りたたむ必要があります。 

この種の問題の微妙な落とし穴は、埋め込み制約が複雑で構造に依存した方法で文字列の大部分をフィルタリングすると仮定していることです。 それが本当であれば、答えは境界線の複雑な組み合わせに依存することが予想されます。 ただし、次の制約があります。$n$反対のことを強く示唆します。条件は、のみに依存するものに単純化する必要があります。$n$単純な指数または線形再帰を通じて。 

小さな健全性チェックですでにこれが示唆されています。 のために$n=3, C=3$、答えは$27$に等しい$C^n$。 これは、少なくとも小規模な場合には、実際には文字列を削除する制限はないことを示唆しています。 

## アプローチ

 ブルートフォースの観点は定義から始まります。「すべてを生成する」$C^n$文字列を取得し、その接頭辞関数を計算し、故障リンクのグラフを構築し、数直線上に描画したときに 2 つの円弧が交差するかどうかをテストします。 プレフィックス関数は次のように計算できます。$O(n)$、単純な交差テストは、実装に応じて線形時間または二次時間で実行することもできます。 これにより、全体的に次のような複雑さが生じます。$O(C^n \cdot n)$、それはすでに不可能です$n=30$、そして全く無関係です$n \le 10^{18}$。 

重要な観察は、KMP 障害リンクの構造が任意のポインターよりもはるかに制約されていることです。 各ノード$i$厳密に小さいインデックスに接続します$f(i)$、これらのリンクは常にプレフィックスの境界を表します。 文字列の境界線は本質的に入れ子になっています: プレフィックスの長さの場合$a$も接尾辞である場合、その接頭辞の短い境界線はすべて元の文字列の境界線でもあります。 このネスト特性により、直線上に描画するときに交差する円弧を生成するために必要なインターリーブが防止されます。 

これを幾何学に変換すると、各エッジは$i \to f(i)$間隔に相当する$[f(i), i]$。 交差には、インターリーブする 2 つの間隔が必要ですが、境界構造により、これらの間隔は常に入れ子になるか、互いに素になることが保証されます。 失敗関数は、交差構成に必要なインターリーブ パターンを生成することはありません。 

これは、アルファベット上のすべての文字列が自動的に平面埋め込みを生成することを意味します。 埋め込み条件は特に制限はありません。 

これが確立されると、問題は考えられる長さの文字列をすべて数えることになります。$n$以上$C$シンボル、つまり単純に$C^n$モジュロ$998244353$。 以来$n$と同じ大きさにすることができます$10^{18}$、高速累乗を使用してこれを計算します。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(C^n \cdot n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(\log n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 有効な文字列の数は、同じ長さの文字列をすべて数えることと同じであることを認識します。$n$以上$C$埋め込み制約によって構築が排除されるわけではないためです。 これは、KMP 障害リンクのネスト プロパティに由来します。 
2. 問題を計算として書き直す$C^n \bmod 998244353$。 
3. 2 進累乗を使用して、べき乗を効率的に計算します。 各ステップで、上位ビットに移動するときに現在の基数を 2 乗します。$n$、現在のビットが返されるたびに答えに乗算します。$n$が設定されています。 
4. 最終的な累積結果を返します。 

正確さは、すべての文字列が有効な非交差構造を誘導するかどうかにかかっており、文字列の完全な組み合わせ空間をカウントする以上のフィルタリング手順はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def mod_pow(a, e):
    res = 1
    a %= MOD
    while e > 0:
        if e & 1:
            res = (res * a) % MOD
        a = (a * a) % MOD
        e >>= 1
    return res

n, C = map(int, input().split())
print(mod_pow(C, n))
```この実装により、問題全体がべき乗剰余演算に還元されます。 注目に値する唯一の詳細は、$C$modulo は、べき乗ループを開始する前の定数モジュラスです。$C$と同じ大きさにすることができます$10^9$。

## テストケース```python
import sys, io

MOD = 998244353

def mod_pow(a, e):
    res = 1
    a %= MOD
    while e > 0:
        if e & 1:
            res = (res * a) % MOD
        a = (a * a) % MOD
        e >>= 1
    return res

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, C = map(int, input().split())
    return str(mod_pow(C, n))

# provided samples
assert solve("3 3") == "27"
assert solve("1000000000000000000 1000000000") == "609226805"

# custom cases
assert solve("1 5") == "5"              # minimum length
assert solve("0 10") == "1"             # empty string edge (if allowed interpretation)
assert solve("2 2") == "4"              # all binary strings valid
assert solve("10 1") == "1"             # single-letter alphabet

 ## 特殊なケース

 のために$n=0$、空の文字列が 1 つだけ存在し、その失敗構造は自明であり、弧は生成されないため、埋め込み条件は満たされます。 アルゴリズムは戻ります$C^0 = 1$、この解釈と一致します。 

いつ$C=1$、すべての文字列は強制的に 1 つの文字の繰り返しになります。 カウントは次のようになります$1^n = 1$、そして失敗構造は再び自明であり、交差する可能性のないネストされた自己境界のみで構成されます。 

いつ$n=1$、以外に障害リンクはありません。$1 \to 0$、したがって、構造は常に単一の円弧であり、何かを横切ることはできません。 結果$C^1 = C$考えられるすべての単一文字列を正確にカウントします。
