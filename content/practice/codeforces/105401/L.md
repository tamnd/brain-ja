 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$N$頂点。 エッジのサブセットを削除することができます。 これらのエッジが削除されると、ツリーは接続されたコンポーネントに分割されます。 要件は、結果として生じるすべての接続コンポーネントのサイズが次のいずれかである必要があることです。$A$または$B$。 タスクは、有効な分解を生成するエッジ サブセットの数を数えることであり、答えは剰余として求められます。$10^9+7$。 

構造は重要です。グラフはツリーであるため、エッジを削除すると常にフォレストが生成され、すべてのコンポーネント自体がツリーになります。 したがって、問題は頂点の任意の分割に関するものではなく、結果として得られる各サブツリーのサイズが制限されるようにエッジを切断することに関するものです。 

この制約により、線形または線形に近い解が求められます。$N$。 と$N$まで$10^5$、ノードまたはエッジ上の二次関数はすぐに遅すぎます。 平$O(N \sqrt{N})$定数によってはすでに疑わしいものであり、エッジまたはノードごとの状態にわたるサブセット DP が指数関数的に関与するものはすべて不可能です。 

微妙な点は、答えが頂点の分割ではなくエッジのセットをカウントしていることです。 カットの構造が異なる場合にのみ、異なるエッジ除去パターンによって同じ頂点のパーティションを作成できます。 これにより、カウントはパーティションだけではなくツリーのエッジにわたって組み合わせられます。 

素朴なアプローチでは、すべてのエッジをカットまたはカットされないとみなそうとします。$2^{N-1}$。 それはまったく不可能です。 もう 1 つの単純なアイデアは、ツリーをルート化し、サブツリーを有効なコンポーネントに分割できるかどうかをボトムアップで決定しようとすることです。ただし、部分的なサブツリーのサイズがどのように組み合わされるかを慎重に処理しないと、複数のカットがブランチ間で相互作用する構成の過大なカウントや欠落が発生します。 

具体的な失敗例は、星型ツリーで発生します。 仮定する$A=1, B=2$、中心は多くの葉を接続します。 各リーフは、他の選択に応じて分離することも、中心とペアにすることもできます。また、リーフが有効なコンポーネントを形成できるかどうかは、他のエッジがどれだけカットされるかによって決まるため、エッジの切断に関する単純なローカル決定は独立して失敗します。 

## アプローチ

 ブルートフォース手法では、エッジのすべてのサブセットを反復処理し、それらを削除し、DFS または Union-find を使用して連結成分を計算し、すべての成分のサイズが次のいずれかであるかどうかを確認します。$A$または$B$。 コンピューティングコンポーネントには次の時間がかかります$O(N)$、そして、あります$2^{N-1}$サブセットなので、全体の複雑さは$O(N \cdot 2^N)$、それは限界をはるかに超えています。 

重要な観察は、グラフはツリーであるため、有効な分解はすべて、ノードをサイズの接続されたサブツリーにグループ化する方法に対応しているということです。$A$または$B$、そのようなグループ化はすべてボトムアップで構築できます。 エッジを直接選択する代わりに、ルート化されたツリーを処理し、カットが配置されているかどうかに応じて、部分的なサブツリー サイズがどのように「上向きに流れる」ことができるかを計算します。 

最大の難点は、各ノードがその子が有効なコンポーネントの形成にどのように貢献するかを決定しなければならないことです。 サイズのサブツリー$A$または$B$はそのノードで「閉じる」ことができます。これは、親へのすべてのエッジがカットされることを意味します。または、後で完成する必要がある上向きの不完全なサイズに寄与する可能性があります。 

以来$A$そして$B$小さい (最大 500) 場合、最大でサブツリー サイズの状態を明示的に扱うことができます。$B$、より大きいサイズのため$B$無効であることを除いて無関係です。 これにより、各ノードが部分的なコンポーネント サイズを生成できる方法の数を維持する DP が可能になります。$k$、遷移は子の上にナップサックのように子状態を結合します。 

洞察としては、各ノードのサブツリーが「未完成のサイズ」の可能性のあるマルチセットに寄与しており、これらのマルチセットを子全体でマージするということです。 サイズがぴったりになったとき$A$または$B$、有効なコンポーネントとして閉じることができ、上向きには何も貢献しません。 これにより、問題は、境界のあるナップザック遷移を含むツリー DP に変換されます。

 ## アルゴリズムのチュートリアル

 ノード 1 でツリーをルートし、各ノードの DP を定義します。DP は、そのサブツリーがまだ閉じられていない指定サイズの部分的に形成されたコンポーネントをどのように生成できるかを記述します。 

1. DP テーブルを定義します`dp[v]`どこ`dp[v][k]`ノードのサブツリーのウェイの数です$v$次のように分解できます$v$の現在接続されている部分 (まだ親に接続されている部分) のサイズは次のとおりです$k$。 この部分はまだ上に伸びる可能性があります。 
2. リーフ ノード用に初期化します。唯一の可能性があるのはサイズ 1 のコンポーネントであるため、`dp[v][1] = 1`。 これは、単一のノードがサイズ 1 の部分コンポーネントであることを反映しています。 
3. 子を 1 つずつ処理します。 child をマージするとします。$u$ノードに$v$。 現在の DP を取得します。$v$それをDPと組み合わせます$u$。 
4. 現在の各サイズについて$i$で$v$、各サイズ$j$子供から$u$、2つの可能性を考えます。 間のエッジをカットするか、$v$そして$u$、その場合$u$のサブツリーはすでに有効なコンポーネントに完全に分割されている必要があり、上向きのサイズには寄与しません。そうでない場合はエッジを保持します。その場合、部分的なコンポーネントのサイズが結合され、$i + j$で新しいサイズになります$v$。 
5.組み合わせる場合、$i + j$等しい$A$または$B$、私たちはそれを上向きに伝播しません。 代わりに、完成したコンポーネントを形成し、カウントに乗算係数 1 を加えます。 もし$i + j < B$と等しくありません$A$、新しい部分的な状態として保存します。 
6. また、「すぐにカットする」オプションも許可します。これは、子サブツリーを独立して完全に分割できる方法の数を乗算することを意味します。これは、すでに有効なクロージャである子のすべての DP 状態を合計することに対応します。 
7. すべての子を処理した後、`dp[v]`部分コンポーネントを形成するすべての方法を表します。$v$。 ルートについては、最終的なサイズが正確である構成のみを受け入れます。$A$または$B$、ルートは上に何も渡すことができないためです。 

### なぜ効果があるのか

 DP は厳密な不変条件を維持します。すべての状態はサブツリーの処理された部分の有効な分解を表します。ここで、すべての内部コンポーネントはすでに完成しており、すべての不完全なコンポーネントは正確に現在のノードに接続された部分です。 ツリーにはサイクルがないため、親子マージではすべてのエッジが 1 回だけ考慮され、すべての有効な分解は、各エッジでの切断またはマージのいずれかの 1 つの選択肢に正確に対応する必要があります。 制限されたサイズ制約により、すべての部分構成が明示的に追跡されるため、有効な構成が省略されたり、無効な部分マージがカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    N, A, B = map(int, input().split())
    g = [[] for _ in range(N)]
    for _ in range(N - 1):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        g[x].append(y)
        g[y].append(x)

    sys.setrecursionlimit(10**7)

    # dp[v]: dict size -> ways
    def dfs(v, p):
        dp = [0] * (B + 1)
        dp[1] = 1

        for to in g[v]:
            if to == p:
                continue
            child = dfs(to, v)

            newdp = [0] * (B + 1)

            # option 1: cut edge, child must be fully valid (sum of finished states)
            child_sum = sum(child[s] for s in range(B + 1)) % MOD

            for i in range(1, B + 1):
                if dp[i] == 0:
                    continue

                # cut child edge
                newdp[i] = (newdp[i] + dp[i] * child_sum) % MOD

                # merge child
                for j in range(1, B + 1):
                    if child[j] == 0:
                        continue
                    if i + j > B:
                        continue
                    ways = dp[i] * child[j] % MOD
                    if i + j == A or i + j == B:
                        # closed component, do not carry upward
                        newdp[i] = (newdp[i] + ways) % MOD
                    else:
                        newdp[i + j] = (newdp[i + j] + ways) % MOD

            dp = newdp

        return dp

    dp_root = dfs(0, -1)
    print((dp_root[A] + dp_root[B]) % MOD)

if __name__ == "__main__":
    solve()
```このソリューションは、各ノードが最大サイズの有界配列を維持する DFS ベースのツリー DP を構築します。$B$より大きい部分コンポーネントがないため、$B$いつか役に立つかもしれない。 各マージ ステップでは、エッジの切断とマージの両方が考慮されます。 切断では、すべての有効な子補完の事前に集計された合計が使用されますが、マージでは、部分的なサイズがどのように結合されるかを明示的に追跡します。 

実装の重要な詳細は、「クローズされた子コントリビューション」と「オープンな子状態」を分離することです。これは、これらが乗算において異なる役割を果たすためです。 もう 1 つの微妙な点は、次の状態を確実に超えることです。$B$遷移を制限するために早期に破棄されます。 

## 実用的な例

 次の 3 つのノードの単純なチェーンを考えてみましょう。$A=1, B=2$。 

ノード 1 をルートとします。 

| ノード | 前の dp | 子が結合されました | |後の dp
 | --- | --- | --- | --- |
 | 葉3 | [0,1,0] | なし | [0,1,0] |
 | ノード 2 | [0,1,0] | マージリーフ 3 | [0,0,1] |
 | ノード 1 | [0,0,1] | マージノード 2 | [0,0,1] |

 最終結果では、チェーン全体がサイズ 2 コンポーネントを形成するか、サイズ 1 コンポーネントに分割される有効な構成がカウントされます。 このトレースは、部分サイズが有効なクロージャに到達するまでどのように上方に移動するかを示しています。 

ここで、中心 1 と葉 2、3、4 を持つ星を考えます。$A=1, B=2$。 

各葉は次のように始まります`[0,1,0]`。 中央で、各葉を切り取るか結合することができます。 切断ではリーフごとに構成が個別に増加しますが、マージでは一度に 1 つのリーフとセンターをペアリングできます。 DP は、各エッジの決定がマージ ステップで独立して処理されるため、二重にカウントすることなく、すべての有効なペアを正しく累積します。

 ## 特殊なケース

 主なエッジケースは次のような場合です$A=1$。 この場合、すべての単一ノードが独立して有効なコンポーネントを形成できます。 アルゴリズムは、マージによって不必要なグループ化が誤って強制されないようにする必要があります。 DP はこれを処理します。これは、サイズが 1 に達するとすぐに有効なクロージャとみなされるため、ノードの結合から生じたものでない限り、1 を超える状態は保持されません。 

もう 1 つのエッジケースは次のような場合です$B$サブツリーのサイズに比べて大きいです。 小さなツリーでは、多くの DP エントリがゼロのままになります。 この実装はゼロエントリをスキップすることに依存しており、不必要なエントリを回避します。$B^2$実際に働きます。 

最後のエッジ ケースは、歪んだツリー (パス) です。 ここで、すべてのマージは線形であり、DP は基本的にチェーン上のナップザックのように動作します。 正確性は、各中間状態が後のノードと結合するのに十分な期間保持されるかどうかに依存しており、これはボトムアップ DFS によって保証されます。
