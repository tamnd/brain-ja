 ## 解決策
 ## 問題の理解

 ゲームの構成は次のとおりです。`n`それぞれの質問には何らかの基本値が含まれています`a[i]`。 一部の質問はオークションとしてマークされています。 チーム R2 は最初の質問を選択することから始めます。 その後、前の質問に正しく答えた人が次の質問を選択できます。 

このシナリオでは、R2 は信じられないほど幸運です。 彼らは質問を試みるたびに、正しく答えます。 タスクは、質問を最適に選択した場合に R2 が達成できる最大合計スコアを計算することです。 

興味深いのはオークションのルールです。 オークションの質問では、それを選択したプレイヤーはその値を増やすことができますが、これは現在のスコアが元の値よりも厳密に大きい場合に限ります。 選択する値は、元の値とプレーヤーの現在のスコアの間の任意の値にすることができます。 正しく答えるとその量がスコアに追加されるため、オークションでは現在のスコアが 2 倍になる可能性があります。 

制約はわずかです。`n`せいぜい`100`、オークションの質問数は最大で`30`。 すべての問題に対する指数関数的な解法さえ不可能ですが、ゲームの構造は見た目よりもはるかに単純であるため、スコア状態に対する動的プログラミングも必要ありません。 

重要な観察は、最初の正解後の質問の順序が R2 によって完全に制御されていることです。 R2 は常に正解するため、順番は永久に維持されます。 唯一意味のある決定は、質問を受ける順序です。 

いくつかの特殊なケースは誤解されやすいものです。 

次の入力を考えてみましょう。```
2 1
10 5
2
```オークションの質問には基本価値があります`5`ただし、R2 はスコアから始まります`0`。 現在のスコアが厳密には以下の値を超えていないため、値を上げることはできません。`5`。 ベストスコアは`10 + 5 = 15`、 ない`20`。 

次に、次のことを考えてみましょう。```
3 1
5 1 100
2
```R2 がオークションの質問相当額を取得した場合`1`を解決した後、`5`ポイント質問の場合、スコアは次のようになります`10`オークションの価値が上がる可能性があるため`5`。 そうすると、最終的な答えは、`110`。 オークションの基本価値を常に追加する不注意な実装では、誤って生成される可能性があります。`106`。 

もう 1 つの微妙なケースは、現在のスコアがオークション価格と等しい場合です。```
2 1
5 5
2
```このルールでは、現在のスコアが基本値より厳密に大きいことが必要です。 平等だけでは十分ではありません。 最初の問題を解いた後のスコアは、`5`, したがって、オークションはまだ増やすことができません。 最終的なスコアは、`10`、 ない`15`。 

## アプローチ

 ブルートフォースアプローチでは、考えられるあらゆる順序の質問が試行されます。 順列ごとにゲームをシミュレートし、結果のスコアを計算します。 せいぜいあるので`100`という質問があれば、これはすぐに不可能になります。 平`15!`すでに大きすぎます。 

スコアの進化は選択された順序のみに依存するため、総当たりは概念的に機能します。 R2 が制御を取得すると、敵対的な決定はありません。 問題は単純に、多すぎる順列を検索することです。 

画期的な進歩は、オークションの質問がどのように動作するかを理解することによってもたらされます。 

現在のスコアが`S`。 

価値のある通常の質問の場合`x`、新しいスコアは次のようになります。```
S + x
```基本価格のあるオークションの質問の場合`x`：

もし`S <= x`、オークションを増やすことはできないため、結果は依然として次のとおりです。```
S + x
```もし`S > x`、オークション価格を次のように設定する場合があります。`S`、与える:```
S + S = 2S
```したがって、オークションの質問は事実上「スコアを 2 倍にする」操作ですが、それはスコアがすでに基本値を超えた場合に限られます。 

これにより全体の視点が変わります。 オークションの質問の正確な値は、いつ倍増が利用可能になるかを決定するしきい値としてのみ重要です。 

最終スコアを最大化するには、できるだけ早くダブリングのロックを解除したいと考えています。 つまり、基本値が小さいオークション質問が最初に使用される必要があります。 オークションが使用可能になる前に、十分なスコアを構築するためにいくつかの定期的な質問を解決する必要がある場合があります。 

これは貪欲なプロセスにつながります。 

スコアから始める`0`。 次に小さなオークションを利用できるようにするために必要なすべての通常の質問に繰り返し答えます。 オークションが使用可能になったら、すぐに使用してください。後で 2 倍にするよりも、早く 2 倍にする方が常に良いためです。 

すべてのオークションが処理された後、通常どおり、残りの通常の質問をすべて追加します。 

オークションの数は最大で`30`なので、並べ替えやシミュレーションは簡単です。

 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 質問を通常の質問とオークションの質問の 2 つのグループに分けます。 

オークションの質問は、入力からのインデックスによって識別されます。 
2. すべてのオークションの質問の値を 1 つの配列に保存し、すべての通常の質問の値を別の配列に保存します。 

最初の成功後の順序は R2 が制御するため、質問の実際の位置は重要ではありません。 
3. 両方の配列を昇順に並べ替えます。 

オークションのしきい値が小さいほど、早めにロックを解除する必要があります。 各倍増の前に必要な最小限の金額のみを費やしたいため、小規模な通常の質問が役立ちます。 
4. 現在のスコアを初期化する`ans = 0`。 
5. オークションの質問を最小のものから最大のものまで処理します。 

現在のオークション価格については`x`、定期的な質問を続けながら、`ans <= x`。 

受ける通常の質問はそれぞれ、単にその価値を追加するだけです`ans`。 
6. 1回`ans > x`オークション質問をお受けします。 

現在のスコアは厳密に次の値よりも大きいため、`x`、オークション価格を以下に設定する場合があります。`ans`、スコアが2倍になります。 
7. すべてのオークションが処理された後、残りのすべての通常の質問をスコアに追加します。 

倍増の機会はもう残っていないため、通常の質問が直接追加されるだけです。 

### なぜ効果があるのか

 重要な特性は、早く 2 倍にすることは常に、後で 2 倍にするのと少なくとも同じくらい良いということです。 

定期的なゲインがあると仮定します`r`オークション倍増が 1 つあります。 2 つの可能性を比較します。 

最初に追加`r`、次に 2 倍します:```
(S + r) * 2 = 2S + 2r
```最初に 2 倍してから加算します`r`:```
2S + r
```最初の値の方が大きい`r`。 

これは、各オークションの前に、そのオークションをアクティブにするために必要な最小限の通常のスコアのみを費やす必要があることを意味します。 追加の定期的な利益は、倍増後の価値が高くなります。 

閾値が小さいほどアクティベートしやすく、将来の倍増のロックをより早く解除することが容易になるため、オークションを昇順で処理することも最適です。 

これらの事実が総合的に、貪欲な戦略を一意に決定します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    is_auction = [False] * n
    for x in b:
        is_auction[x - 1] = True

    auctions = []
    regular = []

    for i in range(n):
        if is_auction[i]:
            auctions.append(a[i])
        else:
            regular.append(a[i])

    auctions.sort()
    regular.sort()

    ans = 0
    ptr = 0
    k = len(regular)

    for x in auctions:
        while ptr < k and ans <= x:
            ans += regular[ptr]
            ptr += 1

        if ans > x:
            ans *= 2
        else:
            ans += x

    while ptr < k:
        ans += regular[ptr]
        ptr += 1

    print(ans)

solve()
```最初の部分はオークションと通常の質問に分かれています。 入力のインデックスは 1 から始まるため、実装ではオークションの質問をマークするときにそれらを 0 から始まる位置に変換します。 

どちらの配列も昇順でソートされます。 ソートされた順序は貪欲な議論にとって不可欠です。 小規模なオークションを最初にロック解除する必要があり、小規模な通常の質問は必要な場合にのみ消費されます。 

ポインタ`ptr`すでに使用されている通常の質問の数を追跡します。 しきい値を使用してオークションの質問を処理する前に`x`、現在のスコアが厳密に より大きくなるまで、ループは通常の質問を追加し続けます。`x`。 

その瞬間、オークションではスコアが2倍になる可能性があるので、`ans *= 2`。 

微妙な分岐が 1 つあります。```
if ans > x:
    ans *= 2
else:
    ans += x
```2 番目のブランチは、通常の質問をすべて消費した後でもオークションをアクティブ化できない場合を処理します。 その場合、オークションは通常の質問と同様に動作し、基本価値のみを提供します。 

すべての算術演算は 64 ビット整数に安全に収まり、Python 整数はオーバーフローを心配することなくこれを自然に処理します。

import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    def solve():
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        is_auction = [False] * n

        for x in b:
            is_auction[x - 1] = True

        auctions = []
        regular = []

        for i in range(n):
            if is_auction[i]:
                auctions.append(a[i])
            else:
                regular.append(a[i])

        auctions.sort()
        regular.sort()

        ans = 0
        ptr = 0

        for x in auctions:
            while ptr < len(regular) and ans <= x:
                ans += regular[ptr]
                ptr += 1

            if ans > x:
                ans *= 2
            else:
                ans += x

        while ptr < len(regular):
            ans += regular[ptr]
            ptr += 1

        return str(ans)

    return solve()

 ## 特殊なケース

 厳密な不等式の場合を考えてみましょう。```
2 1
5 5
2
```アルゴリズムはオークションを次のように分類します`[5]`そして定期的な質問として`[5]`。 

最初は`ans = 0`。 

ループは通常の質問を追加します。`0 <= 5`、生産`ans = 5`。 

今の状態は`ans > 5`平等では十分ではないため、それでも失敗します。 オークションでは基本価格のみが提供されるため、`10`。 

を使用した不注意な実装`>=`誤って生成してしまう`15`。 

ここで、どのオークションも起動できない場合を考えてみましょう。```
3 3
5 6 7
1 2 3
```定期的な質問は一切ありません。 

このアルゴリズムは、ソートされた順序でオークションを処理します。 以来`ans`オークションのしきい値を超えることはなく、オークションごとに基本値が追加されるだけです。```
0 -> 5 -> 11 -> 18
```これは実際のルールと正確に一致します。 既存のスコアが十分でない場合、オークションは通常の質問のように動作します。 

最後に、初期の小規模オークションが重要となるケースを考えてみましょう。```
5 2
2 1 10 3 20
2 4
```並べ替えられたオークションは、`[1, 3]`。 

定期的に摂取した後、`2`、スコアは次のようになります`2`、オークションをアクティブ化します`1`そして倍増して`4`。 

すぐにオークションが開始されます`3`、再び2倍になり、`8`。 

より大きなオークションが最初に処理された場合、2 番目の倍増は後で行われ、最終的なスコアは小さくなります。 これは、オークションが昇順で処理される必要がある理由を裏付けています。
