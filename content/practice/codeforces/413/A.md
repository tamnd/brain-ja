 ## 解決策
 ## 問題の理解

 この問題により、一連のプロセッサー温度が記録されます。`n`ステップ。 主任技術者は観測された最低温度と最高温度の信頼できるメモを持っていますが、助手は記録しただけです`m`の`n`気温。 報告されたかどうかを判断するよう求められます。`m`温度は、主任技術者の報告に一致するように追加の値で拡張できます。`min`そして`max`。 

具体的には、整数があります`n`そして`m`すでにわかっている温度とサブセットの合計数を表します。 整数もあります`min`そして`max`これらは、最終シーケンスに表示する必要がある絶対的な最低温度と最高温度です。 のリスト`m`記録された気温には、これらの極端な温度がすでに含まれている場合と含まれていない場合があります。 追加できる場合、出力は「正しい」になります。`n - m`極端な温度を満たすように温度を設定し、それ以外の場合は「不正解」となります。 

制約は小さいです。`n`は最大でも 100 であり、線形スキャンまたは温度を数回通過するアルゴリズムはどれも十分に効率的であることがすぐにわかります。 温度自体は 1 ～ 100 の間であるため、特別なデータ構造は必要ありません。 エッジケースには、現在次のような状況が含まれます。`m`温度はすでに制約に違反しています。たとえば、記録されたすべての温度は次の値を超えています。`max`またはそれ以下`min`。 もう 1 つの特殊なケースは、次のような場合です。`min`または`max`アシスタントのリストにすでに存在します。 この場合、再度追加する必要はありませんが、シーケンスでは、到達するのに十分な追加温度を考慮する必要があります。`n`。 

単純な実装が失敗する可能性がある例としては、アシスタントが次の温度より高い温度を報告した場合です。`max`。 アルゴリズムが次のことのみをチェックする場合、`min`そして`max`がセット内にある場合、既存の温度が必要な極端値と一致しない場合でも、誤って「正しい」と表示される可能性があります。 

## アプローチ

 最も単純なアプローチは、次のシーケンスをすべて列挙することです。`n`を含む温度`m`報告されたものがあり、満たすものがあるかどうかを確認します`min`そして`max`制約。 これは技術的には正しいですが、組み合わせ的には爆発的です。 のために`n = 100`そして`m = 1`、チェックするシーケンスの数は天文学的に膨大です。 追加された温度ごとに 2 つのオプションしかない場合でも (どちらか`min`または`max`)、最悪のケースでは、2^99 の可能性をチェックする必要があります。 

よりシンプルな解決策を導き出す重要な洞察は、温度の正確な順序は気にせず、極値の存在だけを気にするということです。 現在報告されている温度が既に極値を満たしているか、または極値を満たすために拡張できるかを確認するだけで済みます。 実際には、これは報告された温度の最低値が最高以下であるかどうかをチェックすることになります。`min`報告された温度の最高値が少なくとも以下であるかどうか`max`。 どちらかの極端な値が欠けている場合は、いつでも追加で追加できます。`n - m`スロット、なぜなら`n - m >= 1`問題の制約によって。 

この観察により、報告された温度を 1 回スキャンし、いくつかの単純な比較を行うことで、問題を線形時間で解決できます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(100^(100)) | O(100) | 遅すぎる |
 | 最適 | O(m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`、`m`、`min`、`max`入力から、その後に次のリストが続きます`m`気温。 
2. 記録された温度の最小値と最大値を計算します。 これらに電話してください`current_min`そして`current_max`。 
3. 次のことを確認します。`current_min <= min`。 そうでない場合、追加の温度を追加して最小値を記録された最小値よりも下げることは不可能です。 その場合は「不正」と出力します。 
4. 次のことを確認します。`current_max >= max`。 そうしないと、記録された最大値を超える最大値を増やすことはできません。 「不正解」を出力します。 
5. 両方のチェックに合格した場合は、いつでも追加の温度を追加できるため、「Correct」を出力します (おそらく繰り返し`min`または`max`) 残りを埋める`n - m`スロット。 

機能する理由: 欠落している温度が既存の極端値を超えている場合にのみ、最小値または最大値に影響を与える可能性があるため、アルゴリズムは正確さを保証します。 既存の値が必要な条件に違反しない限り、追加の温度を自由に選択できるため、`min`または`max`、欠落している極値をいつでも挿入できます。 この特性により、問題は 2 つの単純な比較に減ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, min_temp, max_temp = map(int, input().split())
temps = list(map(int, input().split()))

current_min = min(temps)
current_max = max(temps)

if current_min > min_temp or current_max < max_temp:
    print("Incorrect")
else:
    print("Correct")
```最初の行はパラメータを読み取り、次の行は記録された温度を読み取ります。 の`min`そして`max`関数はアシスタントのレポートで極端な値を特定します。 条件式は、これらの極端な値を必要な値と比較します。`min`そして`max`。 使用することに注意してください`>`そして`<`制約を満たす可能性のないシーケンスのみを拒否することを正確に保証します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m, min_temp, max_temp = map(int, input().split())
    temps = list(map(int, input().split()))
    current_min = min(temps)
    current_max = max(temps)
    if current_min > min_temp or current_max < max_temp:
        return "Incorrect"
    return "Correct"

# provided samples
assert run("2 1 1 2\n1\n") == "Correct", "sample 1"
assert run("3 1 1 3\n2\n") == "Incorrect", "sample 2"

# custom cases
assert run("5 3 2 5\n2 3 4\n") == "Correct", "missing max"
assert run("4 2 1 4\n1 2\n") == "Correct", "already includes min"
assert run("3 2 2 5\n2 5\n") == "Correct", "already includes min and max"
assert run("3 2 1 3\n2 2\n") == "Correct", "needs both min and max"
assert run("3 2 1 2\n3 3\n") == "Incorrect", "all temps exceed max"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 5 3 2 5、2 3 4 | 正しい | 不足している最大値を追加して制約を満たすことができます |
 | 4 2 1 4、1 2 | 正しい | すでに最小値が含まれていますが、最大値を追加できます |
 | 3 2 2 5、2 5 | 正しい | 極端な現象はすでに存在します |
 | 3 2 1 2、2 2 | 正しい | シーケンスを満たすために min を追加できます |
 | 3 2 1 2、3 3 | 不正解 | 既存の温度により最小/最大を満たすことができません |

 ## 特殊なケース

 微妙なケースの 1 つは、報告されたすべての温度が必要な範囲外である場合です。 例えば、`n = 3`、`m = 2`、`min = 1`、`max = 3`、報告された温度は次のとおりです。`[4, 5]`。 アルゴリズムは計算します`current_min = 4`そして`current_max = 5`。 以来`current_min > min`の場合、最初のチェックは失敗し、「不正」と出力されます。 これにより、追加の温度を追加しても最小値を必要な値まで下げることができないシナリオが正しく処理されます。 もう 1 つのエッジ ケースは、アシスタントのリストにすでに両方の情報が含まれている場合です。`min`そして`max`。 のために`n = 4`、`m = 2`、`min = 1`、`max = 4`、`temps = [1,4]`の場合、アルゴリズムは両方のチェックに合格し、「正しい」を出力します。これにより、残りのスロットを任意の温度で埋めることができます。 

これらのエッジケースは、ソリューションが不足している両方の要素を適切に考慮していることを裏付けています。
