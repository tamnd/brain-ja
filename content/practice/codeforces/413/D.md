 ## 解決策
 ## 問題の理解

 一連のタイルを処理します。各タイルは次のいずれかになります。`2`または`4`。 タイルは右端から始まり、左にスライドします。 同じ値に触れると、2 つが結合して 2 倍の値になり、新しいタイルは動き続けます。 これが通常の 2048 との決定的な違いで、マージは 1 回の移動中に連鎖する可能性があります。 

部分的に指定された長さのシーケンスが与えられます。`n`。 一部のポジションは次のように固定されています`2`または`4`、そしていくつかは`0`、どちらかを選択できることを意味します`2`または`4`そこには。 少なくとも値を持つ少なくとも 1 つのタイルを生成する完了の数をカウントする必要があります。`2^k`。 

制約によって、必要なソリューションの種類が完全に決まります。 シーケンスの長さが次の値に達しました`2000`なので、指数関数的なものは何でも`n`不可能です。 すべての代替品に対する総当りの攻撃はすでに達成されています`2^2000`。 次元が多すぎる状態 DP でも失敗します。 

興味深いのは、`k ≤ 11`。 対象タイルは最大でも`2^11 = 2048`、つまり、以下のレベルまでのマージのみを意味します。`11`案件。 この小さな境界は、ボードの状態をビットマスクまたは小さな DP 状態に圧縮することを示唆しています。 

微妙な点は、ストリップがどのように進化するかです。 マージされたタイルは移動し続けるため、最後のストリップは常にバイナリ キャリーのように動作します。 

例えば：```
2 2 2
```にはなりません:```
4 2
```その代わり：```
2 -> 4
4 + 2 -> 4 2
```最終的な状態は、`4 2`。 

もう 1 つの簡単な間違いは、同じパワーを持つタイルの順序は重要ではないと仮定することです。 それはそうです。 

例：```
2 4 2 2
```以下とは異なる進化を遂げます。```
2 2 4 2
```挿入中にマージが発生するためです。 

もう 1 つのエッジ ケースは、長いキャリー チェーンの後にのみ勝ちタイルが形成される場合に発生します。 

例：```
2 2 2 2
```プロセスは次のとおりです。```
2
4
4 2
8
```挿入ごとに 1 回だけマージする単純なシミュレーションでは、誤って次の時点で停止します。`4 4`。 

出力では、有効な置換の数を法的に求めます。`10^9 + 7`したがって、カウントは DP 全体でモジュラー演算に基づいて実行する必要があります。 

## アプローチ

 最も直接的な解決策はブルートフォースです。 ごとに交換`0`両方とも`2`そして`4`、ゲーム全体をシミュレートし、タイルが少なくとも`2^k`が表示されます。 

シミュレーション自体は簡単です。 ストリップはバイナリ加算とまったく同じように動作します。 エンコードすると`2^1`レベルとして`1`、`2^2`レベルとして`2`、などのように、レベルを挿入すると、キャリー付きのバイナリカウンタに 1 を加算するのと同じように動作します。 

たとえば、`2`レベルにトークンを追加することを意味します`1`。 レベルの場合`1`すでに存在する場合、レベルにマージされます`2`、そしてキャリーは続きます。 

文字通りゲームのルールに従っているので、総当り攻撃は正しいです。 問題は複雑さです。 せいぜい`2000`不明な位置なので確認する必要があります`2^2000`シーケンス。 

重要な観察は、ボードの状態が小さいということです。 

いつでも、以下のレベルごとに`k`、パリティのみが重要です。 2 つの等しいタイルはすぐに上にマージされるため、レベルには最大でも 1 つのタイルを含めることができます。 これは、関連するボード全体を次のサイズのビットマスクで表現できることを意味します。`k`。 

噛まれたら`i`が設定されている場合、ストリップには現在タイルが含まれています`2^i`。 

タイルの挿入は、このマスクのキャリー プロセスになります。```
while bit exists:
    remove bit
    carry upward
set first empty bit
```キャリーがレベルに達した場合`k`それ以上であれば、すでに勝利しています。 

これにより、問題はプレフィックスとマスクを介した DP に変換されます。 

させて：```
dp[pos][mask]
```最初の処理方法の数になります`pos`要素とボードの状態で終了`mask`生産せずに`2^k`。 

マスクの数はたったの`2^k ≤ 2048`、各移行コストは最大でも`k`ステップを運びます。 

全体の複雑さは次のようになります。```
O(n * 2^k * k)
```周りにあるのは`2000 * 2048 * 11 ≈ 4.5e7`原始的な操作。慎重に実装した最適化された Python で受け入れられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^z · n · k) | O(k) | 遅すぎる |
 | 最適 | O(n · 2^k · k) | O(2^k) | 承認済み |

 ここ`z`ゼロの数です。 

## アルゴリズムのチュートリアル

 1. 各タイルを指数で表します。 

マッピングします:```
2 -> 1
4 -> 2
```目標は指数に達しています`k`。 
2. ストリップの状態をビットマスクとして表します。 

少し`i`タイルを意味します`2^i`存在します。 レベルのみを保存します`0..k-1`。 それを超えるキャリーは成功を意味します。 
3. 遷移関数を定義します。 

レベルを挿入するとします`x`。 

ビットから始める`x`。 

そのビットはマスク内にすでに存在していますが、次のようになります。 

- ビットを取り外します。 
- インクリメント`x`、
 - 上に運び続けます。 

空のポジションが見つかった場合:

 - そこにビットを置きます。 

もし`x >= k`の場合、シーケンスはすでに勝利しています。 
4. ポジションに対する動的プログラミングを構築します。 

させて：```
dp[mask]
```何らかのプレフィックスを処理した後、まだ勝利していない間にこのマスクに到達する方法の数を格納します。 
5. シーケンスを左から右に処理します。 

各ポジションについて:

 - 値が次のように固定されている場合`2`、指数のみを挿入します`1`、
 - 次のように修正された場合`4`、指数のみを挿入します`2`、
 - もしそうなら`0`、両方試してみてください。 
6. トランジションを適用します。 

現在のすべてのマスクと許可されているすべての挿入について:

 - キャリープロセスを使用して次のマスクを計算します。 
- キャリーが指数に達した場合`k`、現在のカウントを答えに直接追加します。 
- それ以外の場合は、次の DP 層を更新します。 
7. すべての演算を剰余として取得する`10^9 + 7`。 

### なぜ効果があるのか

 不変条件は、レベルのタイルがないことを前提として、何らかのプレフィックスを処理した後のすべての DP 状態が一意のストリップ構成を正確に表すことです。`k`or larger has appeared yet.

 キャリーのプロセスはゲームの仕組みと正確に一致しています。 2 つの等しいタイルが結合して移動を続けます。これはキャリーを伴う 2 進加算と同じです。 安定化後は各レベルに最大 1 つのタイルを含めることができるため、ビットマスク表現はロスレスになります。 

シーケンスの可能なすべての完了は、正確に 1 つの DP 遷移チェーンに従い、すべての DP 遷移は合法的なゲームの進化に対応します。 このアルゴリズムはシーケンスを見逃したり、シーケンスを 2 回カウントしたりすることはありません。 

## Python Solution```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    size = 1 << k

    # trans[level][mask] = next_mask
    # if next_mask == -1, reaching >= 2^k occurs
    trans = [[0] * size for _ in range(3)]

    for level in (1, 2):
        for mask in range(size):
            x = level
            cur = mask

            while x < k and (cur >> x) & 1:
                cur ^= (1 << x)
                x += 1

            if x >= k:
                trans[level][mask] = -1
            else:
                trans[level][mask] = cur | (1 << x)

    dp = [0] * size
    dp[0] = 1

    ans = 0

    for val in a:
        ndp = [0] * size

        if val == 0:
            options = [1, 2]
        elif val == 2:
            options = [1]
        else:
            options = [2]

        for mask in range(size):
            ways = dp[mask]
            if not ways:
                continue

            for level in options:
                nxt = trans[level][mask]

                if nxt == -1:
                    ans = (ans + ways) % MOD
                else:
                    ndp[nxt] = (ndp[nxt] + ways) % MOD

        dp = ndp

    print(ans % MOD)

solve()
```実装における最初の重要な考え方は、値を指数に変換することです。 との作業`1`そして`2`の代わりに`2`そして`4`キャリーハンドリングが自然になります。 

遷移テーブルは、DP が開始する前に事前に計算されます。 これにより、メイン ループ内で繰り返されるキャリー シミュレーションが削除されます。 挿入タイプは最大でも 2 種類しかないため、`2048`マスク、前処理は安価です。 

キャリーシミュレーションは一時的なマスクを変更します`cur`。 すでにビットが存在する場合は、それを削除して上に運びます。 これは、ゲーム内で繰り返されるマージと正確に一致します。 

実装の微妙な詳細は、勝利状態の処理です。 レベルを含むマスクは保管しません`k`なぜなら、そのようなタイルが出現すると、シーケンスはすでに成功しているからです。 それらの移行は次のことに直接貢献します。`ans`。 

DP 自体はローリング配列を使用します。 前の層のみが重要であるため、2 つの配列を保持するだけで十分です。 

間違いやすいもう 1 つの詳細は、ビットのインデックス付けです。 少し`1`タイルを表します`2`、そしてビット`2`タイルを表します`4`。 少し`0`は使用されません。これにより、べき乗と指数の間のマッピングが簡素化されます。

 ## 特殊なケース

 次のことを考慮してください。```
4 4
2 2 2 2
```挿入ごとに 1 回だけマージするバグのある実装は、次のところで停止します。```
4 4
```そして誤って失敗と結論付けます。 

遷移シミュレーションは、空のレベルが表示されるまで上向きに進み続けます。```
2 + 2 -> 4
4 + 4 -> 8
8 + 8 -> 16
```したがって、DP はこのシーケンスを勝利として正しくカウントします。 

ここで次のことを考えてみましょう。```
3 3
2 4 2
```プロセスは次のようになります。```
2
4
4 2
```いいえ`8`が表示されます。 

しかし：```

4 2 2
```は次のようになります:```

8
```両方に 2 つが含まれているにもかかわらず、答えは異なります。`2`と 1`4`。 DP は挿入を厳密に順序どおりに処理するため、この区別が正しく保存されます。 

最後に、次のことを考慮してください。```

私たちの遷移表では、そのような遷移を次のようにマークします。`-1`、DP は無効なマスクを保存するのではなく、それらを最終回答に直接追加します。
