 ## 解決策
 ## 問題の理解

 私たちは非常に狭いグリッドで作業しています。行は 2 つだけですが、列数は多数あります。 この 2 x n ストリップ内の各セルは、フリーまたはブロックされています。 移動は横に隣接する空きセル間でのみ許可されるため、グリッドは自然に、各セルに最大 3 つの隣接セル (左、右、および場合によっては同じ列の真上または下のセル) を持つグラフを形成します。 

タスクは、任意の空きセルのペア間の多くの最短パスのクエリに答えることです。 各クエリは、指定された 2 つの位置間を移動するために必要な最小移動数を要求するか、パスが存在しないことを報告します。 

主な難点は、グリッド サイズとクエリ数の両方が最大 200,000 まで大きくなる可能性があることです。 クエリごとに直接最短パスを計算すると、時間がかかりすぎます。 

素朴なアプローチでは、クエリごとに BFS またはダイクストラを実行します。 BFS であってもグリッド サイズは線形であるため、各クエリのコストは O(n) となり、最悪の場合、総作業量は O(nm) となり、これは 4e10 オペレーション程度になります。 これはまったく実現不可能です。 

さらに微妙な問題は、障害物による接続の変化によって発生します。 2 行グリッドでは、1 つの列をブロックすると、接続が非明確な方法で分割される可能性があります。 たとえば、列 i の両方のセルがブロックされている場合、グリッドは独立した左右の部分に分割されます。 1 つのセルだけがブロックされている場合、パスはまだ存在する可能性がありますが、他の行を迂回することになります。 

素朴な推論による 2 番目の失敗モードは、マンハッタンの距離が十分であると仮定することです。 フリーグリッドではそうなりますが、障害物によって水平方向に長い迂回路が強制されたり、直接的な幾何学的な推論が無効になる行切り替え制約が発生したりする可能性があります。 

## アプローチ

 2 列のグリッドの構造は、時折の垂直方向の移行を除いて、動きがほぼ 1 次元であることを示唆しています。 障害物がなければ、最短パス クエリはインデックスの単純な演算に還元されます。 

強引なアイデアは、グリッドをグラフとして扱い、クエリごとに BFS を実行することです。 BFS は重み付けされていないグラフでの最短パスを保証するため、これは正しいです。 ただし、グリッド サイズが大きく、BFS を最初から繰り返すと、クエリ間の構造の大量の再利用が無視されます。 

重要な観察点は、グラフがほぼ折れ線グラフであり、行間に時折「切り替えの機会」があることです。 各列は小さなガジェットのように動作します。列を切り替えるか、完全に通路をブロックします。 これは、個々のセルではなく列間の接続のみを考慮する構造にグリッドを圧縮することを示唆しています。 

列をセグメントとして処理し、2 つの列が接続されているかどうか、および開始状態間の最短移動コストがいくらかを迅速に判断できる接続情報を維持します。 これは、列範囲にわたる分割統治を使用して自然に処理されます。各セグメントは、エンドポイント セルからの入力が終了にどのようにつながるかを説明する遷移構造を維持します。 

境界ノードが左上、左下、右上、右下の 4 つだけであるため、各セグメントには一定サイズの状態が格納されます。 セグメントごとに、これらの境界状態間の最短パスを計算します。 これにより、各セグメントが、一定時間内に別のセグメントとマージできる小さな「転送行列」に変換されます。 

クエリは、セグメント ツリーを使用して 2 つの列間の範囲を分解し、パスに沿ってこれらの伝達行列を結合し、開始境界状態と終了境界状態の間の最小コストを評価することによって回答されます。 

これにより、各クエリが O(log n) 個のセグメント マージに削減され、各マージは O(1) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース BFS | O(nm) | O(n) | 遅すぎる |
 | 境界 DP を持つセグメント ツリー | O((n + m) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

各列を小さな 2 ノードの垂直構造としてインデックス付けします。 各ノードはセルを表し、セルが空いている場合はエッジが水平に存在し、列で許可されている場合は垂直にエッジが存在します。 

列の上にセグメント ツリーを構築します。 ツリーの各ノードには、行の入口と出口の構成ごとに 2 x 2 の遷移コスト構造が格納されます。 具体的には、セグメントについて、その 4 つの境界状態のいずれかから他の境界状態に移行するための最小コストを保存します。 

### ステップ

 1. 各セルをノードに変換しますが、各列を最大 2 つのノードのミニグラフとして扱います。 列内で、両方のセルが空いている場合は、重み 1 の垂直エッジを追加します。 

これが必要なのは、行の切り替えはローカルでのみ可能であり、明示的にエンコードする必要があるためです。 
2. セグメントツリーのリーフノードを構築します。 各リーフは単一の列に対応し、その境界状態間の最短距離を格納します。 

このレベルでは、距離は簡単です。左上が空いていれば右上に接続され、下も同様で、可能であれば垂直方向の遷移が存在します。 
3. 共有インターフェイスを通過するすべての可能な境界間パスを考慮して、2 つの隣接するセグメント A と B をマージします。 

A の任意の境界から B の任意の境界までのコストは、それらの間の境界にあるすべての中間状態を試行することによって計算されます。 
4. セグメントごとに 4 つの境界から境界への最短パス値のみを保存します。 これにより、状態のサイズが一定に保たれます。 
5. クエリごとに、2 つのエンドポイントの列を特定します。 それらが異なる連結コンポーネント (セグメント構造によって決定される) にある場合は、-1 を返します。 
6. それ以外の場合は、2 つの列の間の範囲にわたってセグメント ツリーをクエリし、遷移状態を組み合わせて、開始セル状態からターゲット セル状態までの最良のコストを計算します。 

### なぜ効果があるのか

 重要な不変条件は、すべてのセグメント ツリー ノードが、その境界セルを出入りするすべての可能な最短パスを完全に要約していることです。 2 点間の有効なパスはすべてセグメント境界を順番に横切る必要があり、各境界でアルゴリズムはすべての入口と出口の組み合わせに対する正確な最適コストを保持します。 すべてのパスはセグメント レベルの遷移に分解でき、各セグメントには境界状態間の正確な最短距離が格納されるため、合成された答えは全体的に最適になります。 

セグメント境界で考えられるすべての中間構成がマージ中に明示的に考慮されるため、近似は行われません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def idx(r, c):
    return r * n + c

def merge(a, b):
    # a, b: 2x2 matrices flattened (4x4 transitions)
    res = [[INF] * 4 for _ in range(4)]
    for i in range(4):
        for j in range(4):
            for k in range(4):
                res[i][j] = min(res[i][j], a[i][k] + b[k][j])
    return res

n, m = map(int, input().split())
g = [input().strip() for _ in range(2)]

# state mapping: 0 top-left, 1 bottom-left, 2 top-right, 3 bottom-right within a segment boundary view
# we build per column transitions

def build_col(c):
    # 4 states: (top,c) and (bottom,c)
    # represent as 0,1 for left side of column, and 2,3 for right side
    mat = [[INF]*4 for _ in range(4)]

    # identity transitions
    for i in range(4):
        mat[i][i] = 0

    # within column vertical move
    if g[0][c] == '.' and g[1][c] == '.':
        mat[0][1] = mat[1][0] = 1

    # horizontal moves inside same row
    if c + 1 < n:
        if g[0][c] == '.' and g[0][c+1] == '.':
            mat[0][2] = 1
        if g[1][c] == '.' and g[1][c+1] == '.':
            mat[1][3] = 1

    return mat

size = 1
while size < n:
    size <<= 1

seg = [[[INF]*4 for _ in range(4)] for _ in range(2*size)]

for i in range(n):
    seg[size+i] = build_col(i)

for i in range(size-1, 0, -1):
    seg[i] = merge(seg[2*i], seg[2*i+1])

def query(l, r):
    l += size
    r += size
    left = None
    right = None

    while l <= r:
        if l % 2 == 1:
            left = seg[l] if left is None else merge(left, seg[l])
            l += 1
        if r % 2 == 0:
            right = seg[r] if right is None else merge(seg[r], right)
            r -= 1
        l //= 2
        r //= 2

    if left is None:
        return right
    if right is None:
        return left
    return merge(left, right)

def solve_query(a, b):
    a -= 1
    b -= 1
    ra, ca = divmod(a, n)
    rb, cb = divmod(b, n)

    if ca > cb:
        ca, cb = cb, ca
        ra, rb = rb, ra

    mat = query(ca, cb)

    start = ra
    end = rb

    res = INF
    for i in range(2):
        for j in range(2):
            if i == start and j == end:
                res = min(res, mat[i][j])
    return res if res < INF else -1

for _ in range(m):
    a, b = map(int, input().split())
    print(solve_query(a, b))
```セグメント ツリーは列上に構築され、各ノードにはそのセグメント全体の最短パスをエンコードしたコンパクトな遷移行列が格納されます。 リーフ構造は、列内のローカルな動きと次の列への水平方向の動きをエンコードします。 マージでは、すべての中間境界状態をチェックして 2 つの隣接するセグメントを結合し、最短パスの正確さを維持します。 

微妙な点は、状態のエンコードです。 各列は 2 つのノードに寄与しますが、遷移は 4 状態インターフェイスとして保存されるため、開始方向と終了方向が明示的に追跡されます。 これにより、パスが上の行から来たのか、下の行から来たのかに関する情報が失われることがなくなります。垂直方向の移動でアクセシビリティ パターンが変化するため、これは不可欠です。

    from sys import stdout
    out = []

    # --- solution embedded ---
    INF = 10**18
    input = sys.stdin.readline

    n, m = map(int, input().split())
    g = [input().strip() for _ in range(2)]

    def merge(a, b):
        res = [[INF]*4 for _ in range(4)]
        for i in range(4):
            for j in range(4):
                for k in range(4):
                    res[i][j] = min(res[i][j], a[i][k] + b[k][j])
        return res

    size = 1
    while size < n:
        size <<= 1

    seg = [[[INF]*4 for _ in range(4)] for _ in range(2*size)]

        mat = [[INF]*4 for _ in range(4)]
        for i in range(4):

            mat[0][1] = mat[1][0] = 1

            if g[0][c] == '.' and g[0][c+1] == '.':
                mat[0][2] = 1
            if g[1][c] == '.' and g[1][c+1] == '.':
                mat[1][3] = 1
        return mat

    for i in range(n):
        seg[size+i] = build_col(i)

    for i in range(size-1, 0, -1):
        seg[i] = merge(seg[2*i], seg[2*i+1])

    def query(l, r):
        l += size
        r += size
        left = None
        right = None
        while l <= r:
            if l % 2:
                left = seg[l] if left is None else merge(left, seg[l])
                l += 1
            if not r % 2:
                right = seg[r] if right is None else merge(seg[r], right)
                r -= 1
            l //= 2
            r //= 2
        if left is None:
            return right
        if right is None:
            return left
        return merge(left, right)

    def solve(a, b):
        a -= 1
        b -= 1
        ra, ca = divmod(a, n)
        rb, cb = divmod(b, n)
        if ca > cb:

 ## 特殊なケース

 主なエッジケースは、柱が垂直方向の動きを妨げる場合です。 上のセルがブロックされているが、下のセルが空いている列を考えてみましょう。 単純なモデルでは、その列を介して行を切り替えることができると想定する可能性がありますが、実際にはそうではありません。 セグメント表現では、両方のセルが空いている場合にのみ遷移をエンコードすることでこれを回避します。 

2 つのコンポーネントが完全にブロックされたカラムによって分離されている場合、別のエッジ ケースが発生します。 たとえば、列 2 が完全にブロックされている場合、それをまたぐクエリは -1 を返す必要があります。 セグメント ツリー表現では、そのセグメントにわたるすべての遷移が INF になるため、マージされたパスも INF になり、構造全体に切断が正しく伝播されます。 

最後の微妙なケースは、開始と終了が同じ列にある場合です。 このアルゴリズムは、列内の遷移に垂直方向の移動が含まれるリーフ マトリックスを通じてこれを処理します (可能な場合)。 クエリは単一のセグメントに縮退し、対角線のエントリは移動が可能かどうかを正確に捕捉します。
