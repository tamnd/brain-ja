 ## 解決策
 ## 問題の理解

 合計がゼロになる整数の配列が与えられます。 タスクは、連続する部分配列の最大絶対合計が配列内の最大要素と最小要素の差よりも厳密に小さくなるように要素を再配置することです。 言い換えると、最大要素を次のように表すと、`max_val`そして最小値は`min_val`、連続する数値ブロックの絶対値の合計が次の値にならないような配列の順列を見つける必要があります。`max_val - min_val`またはそれ以上。 

入力には複数のテスト ケースが含まれています。 各配列の要素数は最大 300,000 個で、すべてのテスト ケースの合計は 300,000 に制限されます。 2 秒の制限時間がある場合、これよりも複雑なアルゴリズムはすべて使用できません。`O(n log n)`テストケースごとに実行すると遅すぎる可能性があります。 これにより、すべての順列を試行したり、すべての順列の合計を計算したりするアプローチが除外されます。`O(n^2)`サブ配列を直接使用します。 

すべての数値がゼロの場合、明らかではないエッジ ケースが発生します。 部分配列の合計はゼロであり、次の差以上になります。`0 - 0 = 0`。 もう 1 つの厄介な状況は、配列に互いに打ち消し合う大きな正の数値と負の数値が含まれている場合に発生します。 単純にソートまたはシャッフルを試みると、合計が合計スパンに等しいプレフィックスまたはサフィックスが誤って生成される可能性があります。`max - min`、条件に違反します。 

たとえば、与えられた`a = [0, 0, 0]`、任意の順列が得られます。`max(abs(sum)) = 0`そして`max - min = 0`したがって、出力は次のようになります。`No`。 もう一つのケースは、`a = [5, -5]`; どのような順序付けでも、部分配列の絶対和は 5 になります。これは、次と等しくなります。`max - min = 10`、条件を満たしています。 これらの境界ケースを認識すると、常に有効な取り決めを構築できるという誤った想定を防ぐことができます。 

## アプローチ

 ブルート フォース ソリューションでは、配列のすべての置換を試行し、サブ配列の合計の最大値をチェックします。 これが機能するのは、条件が決定論的であるためです。順列ごとに、すべての連続する部分配列の合計を計算し、不等式を検証できます。 ただし、置換の数は、`n!`、そしてさらには`n = 10`、これは 3,628,800 操作です。 各順列のすべての部分配列の合計を計算すると、これを次のように乗算します。`O(n^2)`、与えられた制約ではまったく実行不可能になります。 

重要な洞察は、正の数と負の数の関係を観察することで得られます。 配列の合計はゼロであるため、正の合計は負の合計の絶対値に等しくなります。 数値を並べ替えて、すべての正の値の後にすべての負の値を配置すると (またはその逆)、最大の部分配列の合計がいずれかの端に表示され、その絶対値は最大ですべての正の合計に達する可能性があります。`max_val - min_val`配列に少なくとも 1 つの厳密に正の数値と 1 つの厳密に負の数値が含まれている場合。 この配置により、サブアレイの合計が中間位置の合計スパンに正確に一致するリスクが回避されます。 

したがって、最初に正の数と負の数を分離することによって、有効な順列を構築できます。 すべての正の合計が絶対値ですべての負の合計と等しく、どちらもゼロではない場合、最初に正、次に負、または最初に負、次に正の順序により、サブ配列の合計がスパン制限に達しないことが保証されます。 すべての数値がゼロの場合、必要な不等式が厳密であるため、タスクは不可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n^2) | O(n^2) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 各テスト ケースを繰り返します。 それぞれのケースで、配列の長さを読み取ります。`n`そして配列`a`。 
2. 最大要素と最小要素を計算します。`max_val`そして`min_val`。 もし`max_val - min_val`ゼロ、出力`No`。 これは、すべてゼロまたはすべて等しい場合を処理します。 
3. 配列を 2 つのリストに分割します。`pos`すべての正の数を含む、そして`neg`すべての負の数が含まれます。 オプションで、別のリストにゼロを収集しますが、ゼロはどこにでも追加できます。 
4. 正の数値を降順に、負の数値を昇順に並べ替えます。 これにより、最大の数値が構築された配列の端に配置されるようになり、サブ配列の合計が許容制限を超える可能性が低くなります。 
5. 再配置した配列を連結して構築します。`pos`そして`neg`。 必要に応じてゼロを中央に配置できますが、ゼロは合計に寄与しないため、配置は条件に影響しません。 
6. 出力`Yes`そして再配置された配列。 

機能する理由: 正の数値と負の数値を分離すると、配列に沿った部分和の変動が少なくなります。 最大の正の数は、反対側の最大の負の数によってバランスが取られ、連続するサブ配列が配列の全範囲に絶対値で合計されるのを防ぎます。 これにより、条件が満たされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    max_val = max(a)
    min_val = min(a)
    
    if max_val - min_val == 0:
        print("No")
        continue
    
    pos = [x for x in a if x > 0]
    neg = [x for x in a if x < 0]
    zero = [x for x in a if x == 0]
    
    pos.sort(reverse=True)
    neg.sort()
    
    ans = pos + neg + zero
    print("Yes")
    print(" ".join(map(str, ans)))
```この解決策は、正の数と負の数を分離して、部分配列の最大合計を減らします。 並べ替えると、最大の数値が端に配置されます。 ゼロは部分配列の合計に影響を与えないため、最後に配置されます。 ゼロの配列やすべての値が等しい配列などのエッジ ケースは、次のことをチェックすることで正しく識別されます。`max_val - min_val`ゼロに等しい。 

## 実用的な例

 ### 例 1

 入力:`[3, 4, -2, -5]`

`max_val = 4, min_val = -5, max_val - min_val = 9`正の数:`[3, 4]`、負の数:`[-2, -5]`| ステップ | 位置 | 否定 | と |
 | --- | --- | --- | --- |
 | 個別 | [3、4] | [-2、-5] | - |
 | 並べ替え | [4、3] | [-5、-2] | - |
 | 結合 | - | - | [4、3、-5、-2] |
 部分配列の絶対合計の最大値は次のとおりです。`7`より小さい`9`。 

### 例 2

 入力:`[0, 1, -1]`

`max_val = 1, min_val = -1, max_val - min_val = 2`ポジティブ：`[1]`、 ネガティブ：`[-1]`、 ゼロ：`[0]`組み合わせる：`[1, -1, 0]`部分配列の絶対合計の最大値:`1`、 未満`2`。
