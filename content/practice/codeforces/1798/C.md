 ## 解決策
 ## 問題の理解

 各キャンディーの種類には 2 つの番号が付いています。 がある$a_i$その種類のキャンディーの在庫と各キャンディーの価格$b_i$コイン。 

タイプごとにパックサイズを選択する必要があります$d_i$。 唯一の制限は、ストック全体を同じパックに分割する必要があることです。$d_i$分けなければなりません$a_i$。 

1パックの価格は、$$c_i = b_i \cdot d_i.$$すべてのパック サイズを選択した後、一連のパック価格を取得します。$$c_1,c_2,\dots,c_n.$$ブロック内のすべてのパックの価格がまったく同じである場合、単一の値札で連続したブロックをカバーできます。 目標は、必要な連続した同価格ブロックの数ができるだけ少なくなるようにパック サイズを選択することです。 

すべてのテスト ケースを合わせた長さは最大でも$2 \cdot 10^5$。 これにより、約数を検索したり、すべてのセグメント内で高価なペアごとのチェックを実行しようとするアプローチは即座に排除されます。 線形に近いものが必要です。$O(n \log C)$、 どこ$C$関係する数値の大きさです。 

微妙な点は、最終的なパック価格を直接選択しているわけではないということです。 各価格は次の形式でなければなりません$b_i \cdot d_i$、 そして$d_i$分けなければなりません$a_i$。 

A common mistake is to think only about pairwise compatibility. 例えば：```
(a,b):
(6,2)
(10,3)
(15,5)
```最初の 2 つのタイプは 1 つの有効なパック価格を共有し、最後の 2 つのタイプは別の有効なパック価格を共有する可能性がありますが、3 つすべてに同時に機能する単一の価格は存在しない可能性があります。 条件はセグメント全体に対して一度にチェックする必要があります。 

もう 1 つの簡単な間違いは、約数を使って作業することです。$d_i$直接。 実際の制約は共通パックの価格に関するものです$X$を作ることではなく、$d_i$等しい。 

例えば：```
a=6, b=2
a=10, b=3
```共通価格$X=6$機能するので$$d_1 = 6/2 = 3,\qquad d_2 = 6/3 = 2.$$パックのサイズは異なりますが、パックの価格は一致します。 

## アプローチ

 強引な見方では、考えられるすべてのセグメントを検討し、そのセグメント内のすべてのキャンディー タイプが共通のパック価格を共有できるかどうかを尋ねます。 セグメントが有効な場合は、1 つの値札で表すことができます。 

問題は、1 つのセグメントを素朴にチェックするだけでもコストがかかることです。 すべてのキャンディーの種類には割り算の制約があり、次のような制約があります。$O(n^2)$セグメント。 と$n$まで$2 \cdot 10^5$、これはまったく不可能です。 

重要な観察は、共通のパック価格の条件を書き換えることから得られます。 

セグメントで共通の価格が使用されているとします。$X$。 

以来$$X = b_i \cdot d_i,$$私たちは知っています$X$で割り切れる必要があります$b_i$。 

また、$$d_i = \frac{X}{b_i}$$分けなければなりません$a_i$。 両辺を乗算すると、$b_i$、$$X \mid (a_i b_i).$$したがって、すべてのキャンディーの種類には 2 つの条件が課せられます。$$b_i \mid X,$$そして$$X \mid a_i b_i.$$セグメント全体については、$X$次のようにする必要があります:

 1. すべての倍数$b_i$。 
2. すべての約数$a_i b_i$。 

最初の要件を満たす最小の数は次のとおりです。$$L = \operatorname{lcm}(b_i).$$2 番目の要件を満たす最大の数は次のとおりです。$$G = \gcd(a_i b_i).$$有効な$X$の倍数のときに正確に存在します$L$分割する$G$。 それはまさに次のときに起こります$$L \mid G.$$これにより、成長するセグメントの維持に問題が変わります。$$L = \operatorname{lcm}(b_i),$$そして$$G = \gcd(a_i b_i).$$セグメントは次の場合にのみ有効です。$$G \bmod L = 0.$$今度は、解決策が貪欲になります。 条件が true である限り、現在のセグメントを拡張します。 false になった瞬間、同じ位置で始まるより大きなセグメントは再び有効になりません。要素を追加しても gcd が減少し、lcm が増加するだけであるためです。 新しいセグメントを開始する必要があります。

 ## アルゴリズムのチュートリアル

 1. 最初のキャンディータイプで新しいセグメントを開始します。 
2. 現在のセグメントの 2 つの値を維持します。$$G = \gcd(a_i b_i)$$セグメント全体にわたって、そして$$L = \operatorname{lcm}(b_i)$$セグメント上にあります。 
3. 新しい種類のキャンディーが到着したら、次を計算します。$$G'=\gcd(G, a_i b_i),$$

$$L'=\operatorname{lcm}(L,b_i).$$4. かどうかを確認します。$$G' \bmod L' = 0.$$これが当てはまれば、拡大セグメントはまだ実行可能であるため、置き換えます。$G,L$による$G',L'$。 
5. 条件が満たされない場合、拡大されたセグメントに共通のパック価格は存在しません。 現在のセグメントを終了し、回答を増分して、現在のキャンディー タイプのみを含む新しいセグメントを開始します。 
6. すべての種類のキャンディーが処理されるまで続行します。 
7. この貪欲なプロセスによって形成されるセグメントの数は、必要な値札の最小数です。 

### なぜ効果があるのか

 セグメントの場合、共通のパック価格は、セグメントの lcm が以下の場合にのみ存在します。$b_i$セグメントの gcd を分割します。$a_i b_i$。 

セグメントを拡張する場合、gcd は同じままか減少することしかできませんが、lcm は同じままか増加することしかできません。 分割条件が崩れると、さらに要素を追加しても修復できません。 左側は大きくすることしかできず、右側は小さくすることしかできません。 

この単調性により、貪欲な戦略が最適化されます。 すべてのセグメントは可能な限り拡張されます。 どのソリューションでも、条件が不可能になる最初の位置から新しい値札を開始する必要があるため、貪欲パーティションでは可能な限り最小限のセグメント数が使用されます。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def lcm(a, b):
    return a // gcd(a, b) * b

t = int(input())

for _ in range(t):
    n = int(input())

    ans = 1
    g = 0
    l = 1

    for _ in range(n):
        a, b = map(int, input().split())

        ng = gcd(g, a * b) if g else a * b
        nl = lcm(l, b)

        if ng % nl == 0:
            g = ng
            l = nl
        else:
            ans += 1
            g = a * b
            l = b

    print(ans)
```この実装は数学的条件を直接反映しています。 

変数`g`すべての値の gcd を保存します$a_i b_i$現在のセグメント内。 変数`l`すべての lcm を保存します$b_i$現在のセグメントの値。 

新しいキャンディーの種類ごとに、暫定的にセグメントを拡張します。 割り切れる条件が依然として成立する場合は、拡張を維持します。 それ以外の場合は、現在のキャンディー タイプから始まる新しいセグメントを開始します。 

実装の詳細の 1 つは、`g`ゼロに初期化されます。 以来$$\gcd(0,x)=x,$$これにより、最初の要素でセグメントを自然に初期化できます。 

もう 1 つの詳細は、lcm の計算です。```
a // gcd(a, b) * b
```中間値の不必要な増加を避けるために、除算は乗算の前に実行されます。

 ## 特殊なケース

 完全に 1 種類のキャンディーで構成されるセグメントを考えてみましょう。```
1
2
10 7
20 3
```最初のキャンディ タイプは、常にそれ自体で有効なセグメントを形成します。$d_1=1$有効なパック料金が表示されます。 アルゴリズムは次から始まります`G=a_1b_1`そして`L=b_1`、そして明らかに`G % L = 0`。 

ここで、lcm が急速に増大する場合を考えてみましょう。```
1
3
2 2
3 3
5 5
```最初の 2 種類の後は、$$G=\gcd(4,9)=1,$$

$$L=\operatorname{lcm}(2,3)=6.$$以来$1 \not\equiv 0 \pmod 6$、セグメントを分割する必要があります。 セグメントが大きくなると、gcd はさらに減少し、lcm はさらに増加するだけなので、障害は永続的になります。 

最後に、パック サイズが異なる場合でも、共通の価格が存在する場合を考えてみましょう。```
1
2
6 2
10 3
```我々は持っています$$G=\gcd(12,30)=6,$$

$$L=\operatorname{lcm}(2,3)=6.$$なぜなら$6 \bmod 6 = 0$、セグメントは有効です。 一般的なパック料金は、$X=6$、パックサイズを与える$3$そして$2$。 これは、パック サイズの平等が無関係であることを裏付けています。 重要なのはパック料金の平等だけです。
