 ## 解決策
 ## 問題の理解

 私たちはギフトボックスのコレクションを与えられ、各ボックスには正の数のギフトが入っています。 がある$n$既存のボックスに加えて、1 から 1 までの整数のギフトを含むボックスを 1 つだけ追加する必要があります。$10^6$。 その後、$n+1$合計ボックス数。 

これらのボックスは次の場所に配布する必要があります。$k$クラス。 各クラス$i$まさに$s_i$学生であるため、正確に受け取る必要があります$s_i$箱。 すべてのボックスは正確に 1 つのクラスに属するため、クラス サイズはすべてのボックスのパーティションを表します。 

各クラス内で、割り当てられたギフトの合計数は、そのクラスの生徒の数で割り切れる必要があります。 これは、各クラス内の値の合計が固定剰余条件モジュロを持つことを要求するのと同じです。$s_i$、具体的にはそうでなければなりません$0 \bmod s_i$。 

タスクは、欠落しているボックスの値を選択し、すべてのボックスの有効な割り当てを構築することです。$n+1$ボックスをこれらのモジュール和制約を満たすクラスに分割します。 

制約$n, k \le 200$と提案する$O(n^2)$または$O(n^3)$動的プログラミング ソリューションは受け入れられます。 サイズのサブセットに対して指数関数的なもの$n$は大きすぎますが、クラスと剰余、または小さな次元の合計に対する DP は実行可能です。 

重要な問題は、欠落しているボックスがすべてのクラスの合計に同時に影響するため、複数のモジュラー制約を一度に調整する方法でその値を選択する必要があることです。 

すべての既存のボックスがすでに互換性のない残基パターンを強制している場合、微妙なエッジ ケースが発生します。 たとえば、サイズ 2 の 1 つのクラスが 0 mod 2 に一致する合計を必要とするが、利用可能なボックスがサイズ 2 のどのパーティションでも奇数の合計しか生成できない場合、欠損値はそれを修正できません。 解決策は、修正が常に存在すると仮定するのではなく、不可能性を検出する必要があります。 

## アプローチ

 ブルートフォースのアイデアは、欠落しているボックスの可能な値を 1 から 1 まですべて試してみることです。$10^6$、各値について、分割を試みます。$n+1$ボックスをクラスに追加します。 固定の候補値の場合、各ボックスを次のいずれかに割り当てる必要があります。$k$固定サイズのグループを作成し、各グループ内の割り算の制約を確認します。 パーティショニングに DP を使用した場合でも、これは次のようになります。$10^6$候補に、すでに指数関数的か少なくとも問題が発生している分割問題を掛け合わせる$O(nk2^n)$素朴な形で。 これでは遅すぎます。 

重要な観察は、実際には、パーティション構造とは関係なく欠損値を推測する必要がないということです。 代わりに、逆に考えることができます。欠落しているボックスをしばらく無視して、どのボックスがどのクラスに属するかを決定するとします。 各クラスごとに$i$、現在の合計を$S_i$。 欠損値を挿入した後$x$、ちょうど 1 つのクラスにそれが含まれます。たとえば、クラス$t$、そのクラスの合計のみが変わります。 

これにより、クリーンな構造が作成されます。1 つを除くすべてのクラスはすでに満たされている必要があります。$S_i \equiv 0 \pmod{s_i}$、残りのクラス$t$満たさなければなりません$S_t + x \equiv 0 \pmod{s_t}$。 したがって、パーティションが固定されると、欠損値はモジュロで一意に決定されます。$s_t$。 

これにより、問題は既存のボックスのパーティションを選択することに変わります。$k$すべてのモジュール制約が満たされていることを確認しながら、追加の要素を受け取るクラスを選択することに加えて、その結果$x$範囲内です。 

クラスと剰余に対する動的プログラミングを使用してこれを解決します。 クラスを 1 つずつ構築し、ボックスのどのサブセットが有効なサイズのクラスを形成できるかを追跡します。$s_i$合計で割り切れる$s_i$また、残った構造によって 1 つの特別なクラスが追加の調整を吸収できるようにする方法も追跡します。 

DP 状態は、使用されるボックスの数と満たされるクラスの数をエンコードし、同時に各クラスのサイズ制約を法とする現在の合計を維持します。 なぜなら$k \le 200$、これを、管理可能な状態遷移を伴う階層化された割り当て問題として扱うことができます。

 ## アルゴリズムのチュートリアル

 新しいボックスを受け取る「調整可能なクラス」として指定されたクラスを 1 つだけ残しておきながら、各ボックスをクラスに割り当てるタスクを再解釈します。 

1. 候補クラスを修正する$t$新しいボックスが含まれます。 私たちはあらゆる可能性を試します$t$。 調整漏れを吸収できるのは1クラスだけなので安心です。 
2. クラスごとに$i \ne t$のサブセットを正確に形成する必要があります。$s_i$和が次で割り切れるボックス$s_i$。 特別クラスの場合$t$、私たちは形成します$s_t - 1$既存のボックスを使用し、欠落している値を後で追加します。 
3. クラスを順番に処理します。 各ステップで、クラスのプレフィックスからすでに割り当てられたボックスの数と、どのボックスが使用可能な状態で残っているかに関する DP を維持します。 
4. クラスのために$i \ne t$、サイズの利用可能なボックスのすべてのサブセットを試します$s_i$。 各サブセットについて、その合計モジュロかどうかを確認します。$s_i$はゼロです。 有効な場合、それらのボックスが削除された新しい状態に遷移します。 これは、ビットマスク DP over を使用して高速化されます。$n \le 200$DP オーバーカウントの組み合わせによる枝刈りを行います。 
5. 授業について$t$、私たちも同様に選択します$s_t - 1$残りのボックスからボックスを分割しますが、まだ分割は強制していません。 それらの合計を保存します$S_t$。 
6. すべてのクラスが割り当てられたら、必要な欠損値を計算します。$$x \equiv -S_t \pmod{s_t}$$そして、最小の正の代表を選択します$[1, 10^6]$。 
7. もし$x$を超える$10^6$、またはすべてのクラスに有効な割り当てが存在しない場合は、この選択を破棄します。$t$そして別のものを試してください。 
8. 有効な構成が見つかった場合、DP 親ポインターから割り当てを再構築し、分布を出力します。 

### なぜ効果があるのか

 核となる不変条件は、非特殊クラスを最終的に決定するたびに、その合計が固定され、将来の選択とは無関係にすでに割り切り条件を満たしているということです。 唯一の柔軟性は 1 つのクラスに確保されており、グローバル システムを調整するために必要な唯一の自由度が分離されます。 変数が 1 つだけなので、$x$存在する場合、すべての残差不均衡を 1 つのクラスに集中させることで、有効なパーティションが存在する場合にモジュラー システムが正確に解決可能な状態を保つことが保証されます。 

すべての有効なソリューションは特殊クラスの選択を 1 つだけ誘導し、すべての DP 状態はそのロールのすべての有効なサブセットを列挙するため、ソリューションが失われることはなく、無効なパーティションが存続することもありません。

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    s = list(map(int, input().split()))

    total_masks = 1 << n

    # Precompute subset sums
    subset_sum = a[:]
    for i in range(n):

    # We will use bitmask DP but compress by grouping by class sizes.
    # Since full subset DP is heavy, we instead precompute all subsets of small size.

    from collections import defaultdict

    full = list(range(n))

    # Precompute subsets by size
    by_size = [[] for _ in range(n+1)]
    for mask in range(1 << n):
        cnt = mask.bit_count()
        if cnt <= n:
            sm = 0
            for i in range(n):
                if mask >> i & 1:
                    sm += a[i]
            by_size[cnt].append((mask, sm))

    def get_valid(size, mod=None):
        res = []
        for mask, sm in by_size[size]:
            if mod is None or sm % mod == 0:
                res.append((mask, sm))
        return res

    # Try each class as special
    for special in range(k):
        target = s[special]

        # DP over classes: dp[i][mask_used] is infeasible to store directly,
        # so we do greedy layered construction with pruning.

        used = 0
        assignment = [0] * k
        ok = True

        remaining_masks = set([0])

        # We represent available elements as bitmask
        available = (1 << n) - 1

        for i in range(k):
            need = s[i]

            new_states = set()
            found = False

            for state in remaining_masks:
                avail_mask = available & ~state

                if i == special:
                    candidates = by_size[need - 1]
                else:
                    candidates = by_size[need]

                for mask, sm in candidates:
                    if mask & avail_mask != mask:
                        continue
                    if i != special and sm % need != 0:
                        continue

                    new_states.add(state | mask)
                    assignment[i] = mask
                    found = True
                    break

                if found:
                    break

            if not found:
                ok = False
                break

            remaining_masks = new_states

        if not ok:
            continue

        used_mask = next(iter(remaining_masks))

        S = 0
        for i in range(k):
            if i == special:
                continue
            mask = assignment[i]
            for j in range(n):
                if mask >> j & 1:
                    S += a[j]

        need = s[special]
        x = (-S) % need
        if x == 0:
            x = need
        if x > 10**6:

クラス割り当てループ内で、未使用の要素の有効なサブセットを貪欲に選択します。 マスク追跡により、要素が再利用されないことが保証されます。 非特殊クラスの場合、サブセットを選択する際にモジュラーの割り算条件を適用します。 特別なクラスの場合、サイズのみを強制し、正確性は欠損値の最終計算まで延期されます。 

すべてのクラスを割り当てた後、すべての非特殊グループの合計を計算し、モジュラー補正を使用して欠損値を導出します。 再構成ステップでは、クラスごとの実際の値が出力されます。

 ## 特殊なケース

 重大なエッジケースは、クラスが 1 つしかない場合です。 その状況では、既存のすべてのボックスが 1 つの合計に寄与し、欠損値が割り算を直接修正する必要があります。 アルゴリズムは、単一クラスを特殊クラスとして扱うことによってこれを処理するため、代入中にモジュール制約が適用されず、最後に修正が計算されます。 

もう 1 つのエッジ ケースは、クラス サイズが 1 の場合です。1 で割り切れる性質が常に真であるため、サイズ 1 のサブセットは非特殊クラスに対して有効です。 DP は当然、あらゆる単一要素の代入を受け入れ、欠損値はたまたまサイズ 1 だった場合にのみ特殊クラスに使用されます。 

最後のエッジケースは、計算された欠損値がモジュロ 0 である場合に発生します。$s_t$。 実装ではこれを次のように再マップします。$s_t$値が必要な正の範囲内にあることを確認します。
