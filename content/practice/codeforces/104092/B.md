 ## 解決策
 ## 問題の理解

 長さの動的配列が与えられます`n`、そして、大量のクエリの下で 2 種類の操作を効率的にサポートする必要があります。 

最初の操作では、配列内の 1 つの位置を更新し、その値を新しい数値に置き換えます。 2 番目の操作では範囲を要求します`[L, R]`ですが、クエリは単純な合計を求めていません。 代わりに、すべてのサブ配列が内部に完全に含まれていると考慮する必要があります。`[L, R]`、そのような各部分配列内の要素の合計を計算し、それらの部分配列の合計をすべて合計します。 

したがって、セグメントを修正すると`[L, R]`、すべてのサブ配列からの貢献を効果的に蓄積しています。`a[l] + a[l+1] + ... + a[r]`どこ`L ≤ l ≤ r ≤ R`。 

入力サイズが大きい: 最大`2 × 10^5`要素と`2 × 10^5`クエリ。 これにより、範囲にわたって線形時間でクエリごとに何かを再計算することは即座に除外されます。`10^10`最悪の場合の運用。 

更新操作も頻繁に行われるため、すぐに更新できない前処理は失敗します。 これは、対数時間でのポイント更新と範囲クエリの両方をサポートするデータ構造を強く示唆しています。 

部分配列を列挙して固定セグメントの答えを直接計算しようとすると、単純な落とし穴が発生します。 たとえば、`[1, 3, 5]`、部分配列は`[1]`、`[1,3]`、`[1,3,5]`、`[3]`、`[3,5]`、`[5]`、そしてそれらを合計すると、複数のクエリを考慮する前でも、クエリごとにすでに O(n²) になります。 

もう 1 つの微妙なエッジ ケースはオーバーフローです。各要素が組み合わせ頻度で多くのサブ配列に寄与するため、多くのサブ配列にわたって繰り返される中程度の値であってもすぐに増幅されます。 

## アプローチ

 ブルートフォースアプローチは簡単です。 クエリごとに`[L, R]`、すべての開始点を反復処理します。`l`範囲内で、それぞれについて`l`私たちはすべての人に拡張します`r ≥ l`、累計を維持します。 各部分配列の合計が答えに加算されます。 これは定義と正確に一致するため、必要な数量が正しく計算されます。 

ただし、これには 3 つのネストされたレベルの作業が必要です。`l`、反復`r`、各拡張機能内で合計します。 プレフィックス累積を使用して 2 つのループに最適化した場合でも、各クエリは依然として O(length²) です。 と`n`そして`q`まで`2 × 10^5`、これは不可能になります。 

重要な観察は、部分配列の合計を合計しているが、各要素は`a[i]`この合計には均等に現れません。 代わりに、その寄与は、サブ配列の数に依存します。`[L, R]`それを含めてください。 

インデックスを修正する`i`内部`[L, R]`。 以下を含む部分配列を形成するには`i`、その左端点は次のいずれかから選択できます。`L`に`i`、およびその右のエンドポイントはどこからでも`i`に`R`。 それは与える`(i - L + 1) × (R - i + 1)`選択肢。 したがって、貢献度の合計は、`a[i]`クエリには次のようになります。`a[i] × (i - L + 1) × (R - i + 1)`この式を拡張すると、次の 2 次多項式が得られます。`i`これは、配列に対するいくつかのプレフィックスの合計の組み合わせとして書き換えることができます。 

の合計を維持する必要があります`a[i]`、`i·a[i]`、 そして`i²·a[i]`。 

これにより、問題は 3 つの個別のフェンウィック ツリー (またはセグメント ツリー) の維持に変わります。 各クエリはこれらの構造からの範囲合計の組み合わせとなり、更新ごとに対応する位置が調整されます。 

これにより、両方の操作が対数時間に短縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n²) | お(1) | 遅すぎる |
 | フェンウィックの分解 | 操作ごとに O(log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 貢献度の式を次のように書き換えます。 

各要素`a[i]`貢献する`(i - L + 1)(R - i + 1)`回。 

拡張:`(i - L + 1)(R - i + 1) = (i+1-L)(R+1-i)`これは次の二次式になります。`i`したがって、クエリ合計の合計は、これらのグローバル合計の線形結合として表すことができます。 

私たちは以下を維持します:`S0 = sum a[i]`

`S1 = sum i · a[i]`

`S2 = sum i² · a[i]`どのセグメントでも`[L, R]`、プレフィックスの違いを使用して必要な組み合わせを計算できます。 

### 手順:

 1. アレイ上に 3 つのフェンウィック ツリーを構築します。1 つは`a[i]`、 1 つ`i·a[i]`、および 1 つ`i²·a[i]`。 

これが必要なのは、最終的な式がこれら 3 つの独立した集合体に分解されるためです。 
2. インデックスごとに`i`、次のように 3 つのツリーを初期化します。`a[i]`、`i·a[i]`、 そして`i²·a[i]`。 
3. アップデートについて`i → x`、計算する`delta = x - a[i]`そして適用します:

 フェンウィック ツリー 0 を更新します`delta`フェンウィック ツリー 1 を更新します`delta · i`フェンウィック ツリー 2 を更新します`delta · i²`次に、新しい値を保存します。 
4. お問い合わせの場合`[L, R]`、各フェンウィック ツリーからプレフィックスの合計を抽出します。`A = sum a[i]`

`B = sum i·a[i]`

`C = sum i²·a[i]`代数を使った展開`(i-L+1)(R-i+1)`、 組み​​合わせる`A, B, C`最終的な答えを計算します。 
5. 結果のモジュロを返します`1e9+7`。 

### なぜ効果があるのか

 各要素は最終的な合計に独立して寄与し、その重みはインデックスとクエリ境界にのみ依存します。 重みは 2 次多項式なので、`i`、クエリ全体は、範囲にわたる二次形式を評価することに帰着します。 のプレフィックス合計を維持する`a[i]`、`i·a[i]`、 そして`i²·a[i]`このような二次加重和を正確に再構築するには、これで十分です。 フェンウィック ツリーは、更新時にこれらのプレフィックスの合計が常に一貫していることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        n = self.n
        bit = self.bit
        while i <= n:
            bit[i] = (bit[i] + v) % MOD
            i += i & -i

    def sum(self, i):
        bit = self.bit
        res = 0
        while i > 0:
            res = (res + bit[i]) % MOD
            i -= i & -i
        return res

    def range_sum(self, l, r):
        return (self.sum(r) - self.sum(l - 1)) % MOD

def solve():
    n = int(input())
    a = [0] + list(map(int, input().split()))

    bit0 = Fenwick(n)
    bit1 = Fenwick(n)
    bit2 = Fenwick(n)

    for i in range(1, n + 1):
        bit0.add(i, a[i])
        bit1.add(i, a[i] * i)
        bit2.add(i, a[i] * i * i)

    q = int(input())
    for _ in range(q):
        t, x, y = map(int, input().split())
        if t == 1:
            i, val = x, y
            delta = val - a[i]
            a[i] = val

            bit0.add(i, delta)
            bit1.add(i, delta * i)
            bit2.add(i, delta * i * i)

        else:
            L, R = x, y

            A = bit0.range_sum(L, R)
            B = bit1.range_sum(L, R)
            C = bit2.range_sum(L, R)

            # derived closed form
            # contribution = Σ a[i] * (i-L+1)(R-i+1)
            # expand:
            # (i-L+1)(R-i+1) = -(i^2) + i(R+L) + (1-L)(R+1)

            term1 = (-(C % MOD)) % MOD
            term2 = (B * (L + R)) % MOD
            term3 = (A * ((1 - L) * (R + 1))) % MOD

            ans = (term1 + term2 + term3) % MOD
            print(ans)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、必要な 3 つの加重合計を維持します。 各更新では、3 つの構造すべてにわたって正確に 1 つの位置が調整されます。 

クエリ部分は、寄与の重みの代数的展開を適用します。 表現`(i-L+1)(R-i+1)`を使用して評価できるように、慎重に二次形式に拡張されます。`A`、`B`、 そして`C`。 オーバーフローを避けるために、モジュロ演算がすべてのステップで適用されます。 

微妙な点は、展開後の負の値の処理です。特に、`-(C)`学期。 コードはそれを係数に基づいてすぐに正規化します。 

## 実用的な例

 配列を考えてみましょう`a = [1, 2, 3, 4, 5]`そしてクエリ`[2, 4]`。 

寄与を手動で計算します: 内部の部分配列`[2,4]`は`[2]`、`[2,3]`、`[2,3,4]`、`[3]`、`[3,4]`、`[4]`。 

それらの合計は`2, 5, 9, 3, 7, 4`、 合計`30`。 

ここで式を使用すると、各要素が次のように寄与します。 

| 私 | a[i] | (i-L+1)(R-i+1) | 貢献 |
 | --- | --- | --- | --- |
 | 2 | 2 | (1)(3)=3 | 6 |
 | 3 | 3 | (2)(2)=4 | 12 |
 | 4 | 4 | (3)(1)=3 | 12 |

 合計 = 30。 

これにより、組み合わせ重み付けが直接列挙と一致することが確認されます。 

2 番目の例は単一要素クエリです。`[3,3]`の上`[10,20,30]`。 部分配列は 1 つだけ存在するため、答えは次のようになります。`30`。 式は次のようになります`(i-L+1)(R-i+1)=1`、つまり貢献度はまさに`a[3]`、一致します。

 ## 特殊なケース

 重要なエッジ ケースは、クエリ間隔の長さが 1 である場合です。 この場合、部分配列の数はちょうど 1 つであるため、答えは 1 つの要素と等しくなければなりません。 アルゴリズムはこれを処理します。`(i-L+1)(R-i+1)`になる`1`、すべての高次構造が正しく崩壊します。 

もう 1 つの特殊なケースは、同じインデックスで更新が繰り返されることです。 フェンウィック ツリーはデルタを保存するため、構造を再構築する必要がなく、複数の更新が正しく蓄積されます。 

近くの大きな値`10^9`インデックス 2 乗を乗算すると 32 ビット算術演算がオーバーフローする可能性がありますが、Python は大きな整数を安全に処理します。 唯一の要件は、各演算後の一貫したモジュロ リダクションです。 

最後の微妙なケースは、二次展開における負の中間値です。 この実装では、モジュロ演算に基づいてすべての項が正規化され、減算時に不正なラップアラウンドが発生しないことが保証されます。`C`貢献。
