 ## 問題の理解

主な問題は、制約がグローバルな方法で相互作用することです。 合計が実行可能に見えても、ビンごとの最小値を尊重しながら合計を均等に分配すると、割り算とエピソードごとの下限により失敗する可能性があります。

 ## アルゴリズムのチュートリアル

 有効なパーティションの構造から直接条件を導き出します。 

1. 総話数を計算する`S = c + d`。 もし`S`で割り切れない`n`、すべてのストーリーを分割する方法はありません。`n`エピソードが等しいので、すぐに停止します。 
2. エピソードのサイズを定義する`k = S / n`。 すべてのエピソードが等しく、すべてのストーリーが使用される必要があるため、これが各エピソードで可能な唯一のサイズです。 
3. エピソードごとの最小要件を確認します。各エピソードには少なくとも次のものが含まれている必要があります。`a + b`少なくとも必要なストーリー`a`子猫の話と`b`子犬の話。 もし`k < a + b`の場合、最小の有効なエピソードでも制約に違反するため、拒否されます。 
4. 子猫の配布の実現可能性を確認します。子猫の合計ストーリーは、提供するのに十分でなければなりません。`a`エピソードごとに、`c >= n * a`。 
5. 同様に、子犬の物語も満足感を与えるものでなければなりません`d >= n * b`。 
6. すべての条件が満たされる場合、分割は可能です。 そうでなければ不可能です。 

ステップ 4 と 5 の背後にある理由は、最小制約はグローバルではなくエピソードごとにあるということです。 各エピソードは独立して少なくとも`a`子猫と`b`子犬の話なので、合計がサポートされている必要があります`n`これらの要件の繰り返し。

 有効な構築では正確に代入する必要があります`k`エピソードごとにストーリーがあるため、完全な分割が必要です。 それが修正されると、すべてのエピソードには必須の基本コストがかかります。`a`子猫と`b`子犬の話。 合計からこのベースを差し引くと、エピソード間で任意に分配できるストーリーの空きプールが残ります。 この制約により、この空きプールが決して負にならず、エピソードごとに利用可能な容量を超えないことが保証されるため、これらの算術チェックを超えるさらなる構造上の制限は存在しません。

input = sys.stdin.readline

n = int(input())

 ## 特殊なケース

 主なエッジケースは次のような場合です`n = 1`。 この場合、本全体が 1 つのエピソードとなるため、合計自体が最低限の制約を満たしていればよいことになります。 アルゴリズムは、次のことをチェックすることに要約されます。`c >= a`そして`d >= b`、これは正しく適用されます。`k = c + d`そして`k >= a + b`両方の合計が十分である場合にのみ、一緒に実行可能性が示唆されます。 

もう 1 つのエッジケースは次のような場合です`a = 0`または`b = 0`。 その後、制約の 1 つが消え、解決策は全体の可分性と残りの制約のみをチェックすることになります。 算術条件は特別な処理を必要とせずに自然に簡素化されます。
