 ## 解決策
 ## 問題の理解

 一連の単語が与えられ、それぞれの単語には正または負の整数値が含まれます。 まで挿入可能です`k`コンマ。シーケンスを連続したセグメントに分割します。 各セグメントは合計スコアに寄与しますが、その寄与の符号は、そのセグメントの前後に特別な単語「нельзя」を配置するかどうかによって異なります。 

ステートメントで説明されているように、コンマの直前または直後に「нельзя」を挿入することで、各セグメントを「反転」としてマークすることもできますが、最終的な効果は単純です。各セグメントは通常どおり追加されるか減算され、この選択は配置ルールによって間接的に制御されます。 各セグメントに最大 1 つの「нельзя」を含めることができるという制約は、各セグメントが独立してその寄与においてプラスまたはマイナスのいずれかになることを意味しますが、個々の単語に任意に記号を割り当てることはできず、セグメント全体にのみ符号を割り当てることができます。 

したがって、実際の構造は次のようになります。配列を最大で次のように分割します。`k+1`連続したセグメントと各セグメント`l..r`どちらかに貢献する`+sum(a[l..r])`または`-sum(a[l..r])`。 すべてのセグメントの合計を最大化したいと考えています。 

制約`n ≤ 500`すぐに、二次または三次動的計画法が実行可能であることが示唆されます。 大まかに言えば、セグメンテーションの数は組み合わせ爆発のように増加するため、指数関数的な分割のようなものは不可能です。`2^n`。 

素朴な考え方による微妙な失敗例は、負の和を持つセグメントにのみ「нельзя」を配置すべきであると仮定することです。 これは誤りです。セグメントを反転すると符号が変わるため、制限されたカットの下でより良いグローバル構造が可能になる場合は、プラスサムのセグメントを意図的にマイナスにしたい場合があります。 

もう 1 つの失敗モードは、貪欲なセグメンテーションを試行することです。つまり、最適なローカル分割位置を選択します。 たとえば、局所的に最良の正のブロックを選択すると、残りの要素がより悪い構成に強制される可能性があり、符号の選択によりセグメントがグローバルに結合されます。 

## アプローチ

 ブルートフォースソリューションでは、配列を最大で分割するすべての方法を列挙します。`k+1`セグメントを分割し、各セグメントに符号を割り当てます。 符号の割り当てを無視しても、パーティションの数は指数関数的になります。 のために`n = 500`、これはまったく不可能です。 

より構造化された観察は、セグメントの境界を修正すると、残る自由は各セグメントが正であるか負であるかだけであるということです。 ただし、これらの選択は合計と線形に相互作用するため、それらを DP 状態に折りたたむことができます。 

重要な洞察は、これをプレフィックス上の間隔 DP として扱うことです: すべてのプレフィックスについて`1..i`、指定された数のセグメントについて、達成可能な最良の値を追跡します。 トランジションでは、次で終了する最後のセグメントが考慮されます。`i`、ある時点から始まります`j+1`。 そのセグメントの貢献度は次のいずれかです`+(prefix[i] - prefix[j])`または`-(prefix[i] - prefix[j])`。 これにより、各遷移は 2 つの線形形式の間で選択することになります。 

この構造は古典的な「プレフィックスの合計と符号の選択を備えたパーティション DP」となり、次のように解決できます。`O(n^2 k)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパーティション | O(2^n) | O(n) | 遅すぎる |
 | セグメントおよびエンドポイント上の DP | O(n^2k) | O(nk) | 承認済み |

 ## アルゴリズムのチュートリアル

 O(1) でセグメントの合計を取得できるように、プレフィックスの合計を事前に計算します。 させて`pref[i]`最初の合計になる`i`価値観。 

DP テーブルを定義します。`dp[t][i]`正確に使用して達成可能な最大スコアを表します`t`最初のセグメントをカバーするセグメント`i`要素。 

全てを使用しない可能性も含みます`k`有効なすべての最大値を取得してカットします`t`。 

### ステップ

 1. プレフィックス合計配列を構築する`pref`どこ`pref[i] = a[1] + ... + a[i]`。 これにより、定数時間のセグメント合計クエリが可能になります。 
2. を除くすべての状態に対して DP を非常に小さな値で初期化します。`dp[0][0] = 0`、ゼロ要素をカバーするゼロセグメントを意味します。 
3. セグメント数を繰り返す`t`から`1`に`k+1`。 各セグメント数は次のようになります。`t-1`カンマ。 
4. 各エンドポイントについて`i`、以前の可能なすべての分割ポイントを試してください`j < i`。 最後のセグメントは、`(j+1 .. i)`。 
5. セグメントの合計を計算します。`S = pref[i] - pref[j]`。 セグメントは次のいずれかに貢献できます。`+S`または`-S`。 それで、私たちは取る`max(S, -S)`、つまり`|S|`。 
6. 移行:`dp[t][i] = max(dp[t][i], dp[t-1][j] + abs(pref[i] - pref[j]))`。 
7. 答えは次の最大値です。`dp[t][n]`のために`t ≤ k+1`。 

### なぜ効果があるのか

 重要な不変条件は、すべての有効な構造がセグメントへの 1 つの分割に正確に対応し、各セグメントが独立してその合計または否定された合計のいずれかに寄与することです。 DP は、プレフィックスごとに考えられる最後のセグメントをすべて列挙し、そのようなセグメントごとに、以前のプレフィックスに対する最適なソリューションをすでに想定しています。 絶対値はセグメントごとに最適な符号の選択を独立して取得するため、以前の決定を再考する必要はありません。 これにより、すべての有効な構成が、一連の遷移を通じて 1 回だけ表現されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    NEG = -10**18
    dp = [[NEG] * (n + 1) for _ in range(k + 2)]
    dp[0][0] = 0

    for t in range(1, k + 2):
        for i in range(1, n + 1):
            best = NEG
            for j in range(i):
                if dp[t - 1][j] == NEG:
                    continue
                seg = pref[i] - pref[j]
                best = max(best, dp[t - 1][j] + abs(seg))
            dp[t][i] = best

    ans = 0
    for t in range(1, k + 2):
        ans = max(ans, dp[t][n])

    print(ans)

if __name__ == "__main__":
    solve()
```プレフィックス合計配列は、繰り返し行われる O(n) セグメント合計の計算を削除する、中核となる単純化です。 DP層`t`これまでに使用されたセグメントの数をカウントします。 内部遷移はすべての分割ポイントを明示的に試行します。これは有効です。`n ≤ 500`。 

の使用`abs(seg)`各セグメントは他のセグメントに影響を与えることなく反転または反転できるため、他のセグメントとは独立して、そのセグメントの「нельзя」の最適な配置をエンコードします。 

## 実用的な例

 ### 例 1

 入力:```
2 1
-100 100
```プレフィックスの合計を計算します。`pref = [0, -100, 0]`。 

We allow up to 2 segments.

 | t (セグメント) | 私 | j の選択 | セグメント合計 | 貢献 | dp[t][i] |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | -100 | 100 | 100 |
 | 1 | 2 | 0 | 0 | 0 | 0 |
 | 1 | 2 | 1 | 100 | 100 | 100 |
 | 2 | 2 | スプリットベスト | 混合 | 100 + 100 | 200 |

 最適な構成は 2 つのセグメントに分割し、負の部分を反転して正の寄与にし、200 を生成します。 

これは、合計がゼロの場合でも、セグメンテーションと符号の選択により正の値を生み出すことができることを示しています。 

### 例 2

 入力:```
8 3
2 -100 10 5 -10 3 -20 40
```主要な最適な遷移のみを追跡します。 

| ステップ | 最後のセグメント | 接頭辞の差分 | 腹筋値 | 蓄積された |
 | --- | --- | --- | --- | --- |
 | 開始 | - | - | - | 0 |
 | [1..2] を取る | 2 | -98 | 98 | 98 |
 | [3..4] を取る | 2 | 15 | 15 | 113 |
 | [5..7] を取る | 3 | -27 | 27 | 140 |
 | [8..8] を取る | 1 | 40 | 40 | 180 |

 このトレースは、最適な構造では、強い負のランと正のランを絶対和が大きいセグメントにグループ化することが優先されることを示しています。 

また、貪欲な分割が失敗する理由も示しています。有害に見える中間セグメント (負のプレフィックス合計など) は、一度反転すると価値のあるものになります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n²k) | k+1 個のセグメント数のそれぞれについて、すべてのペア (j, i) の遷移を試行します。 
| スペース | O(nk) | セグメントの状態を格納する DP テーブル × プレフィックス長 |

 と`n ≤ 500`、最悪の場合の操作は約 1 億 2,500 万回であり、これはタイトなループを備えた Python に快適に適合します。

 ## 特殊なケース

 単一の大きなネガティブ ブロックは、アルゴリズムがセグメンテーションを回避する代わりに符号反転を正しく使用しているかどうかをテストします。 例えば、`[-10, -20, -30]`十分なセグメントがあれば、`60`、DP はセグメント全体を取得して 1 回反転することでこれを実現します。 

完全にポジティブな配列は、不必要な分割によって答えが改善されないことをチェックします。 のために`n=500`ポジティブで小さい`k`、最適な戦略は大きな絶対セグメントを取得することに崩壊し、絶対値は大きな連続した合計を保持するため、DP は自然に人為的な分割を行わない全範囲セグメントを優先します。 

交互の符号は、セグメンテーションと絶対値の間の相互作用をテストします。 のような入力`[100, -100, 100, -100]`DP が局所最大値に依存せず、潜在的な符号反転後に合計の大きさが最大になるセグメントに要素をグループ化することを保証します。
