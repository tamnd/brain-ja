 ## 解決策
 ## 問題の理解

 バルーン ボリュームの動的なコレクションを維持します。 各イベントは、このコレクションに新しい値を挿入するか、現在の状態についてクエリを実行します。 クエリでは、現在の値をすべて選択し、最小の A 値と最大の B 値を破棄し、残った値を合計することを想像します。 タスクは、実際には何も削除せずに、各クエリの時点でその合計をレポートすることです。 

イベントの流れはオンラインであるため、各クエリにはその時点までに入手可能な情報のみを使用して回答する必要があります。 値は最大 10^18 と非常に大きくなる可能性があるため、頻度配列や直接インデックス付けに依存することはできません。 すべてのテスト ケースにわたるイベントの数は最大 2 × 10^5 です。これは、更新とクエリごとに約 O(log n) が必要であることを意味します。 

単純なアプローチでは、クエリごとにアクティブ セットを並べ替えて、最小の A 要素と最大の B 要素を削除します。 Q 個のクエリと最大 N 個の要素がある場合、これは O(Q · N log N) となり、非常に遅すぎます。 

微妙な落とし穴は、A と B がクエリごとではなくテスト ケースごとに固定されていることです。 これは、いくつの要素が「中間」とみなされるか「削除された極端」とみなされるかを常に把握できる構造を維持できるため、重要です。 

A + B が E − 1 に近い場合、別のエッジ ケースが発生します。その場合、要素は 1 つだけ中央に残り、範囲への分割に依存する多くの構造は、「中間セット」が小さい場合に正確さを注意深く維持する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。挿入されたすべての値のマルチセットを維持します。 クエリごとに、すべてを配列にコピーして並べ替え、最小の要素 A と最大の要素 B を破棄し、残りを合計します。 この定義は並べ替えに直接一致するため、概念的には機能します。 ただし、すべてのクエリでコピーと並べ替えを行うと、各クエリが O(n log n) になり、最大 2 × 10^5 の演算を行うと、これはすぐに実行不可能になります。 

重要な点は、A の最小要素と B の最大要素は任意ではなく、常にランクによって定義されるということです。 コレクションを暗黙的にソート順に維持できる場合は、コレクションを 3 つの部分、つまり最小の A 要素、最大の B 要素、および残りの中間セグメントに分割できます。 必要な合計は、単に中央のセグメントの合計です。 

これは、左側の部分のマルチセット、右側の部分のマルチセット、および答えに寄与する要素を正確に格納する中央の構造という 3 つの構造を維持することを示唆しています。 要素は時間の経過とともに挿入されるため、左側に常に正確に A の最小要素が含まれ、右側に常に正確に B の最大の要素が含まれるようにバランスを調整することもできなければなりません。 他のものはすべて真ん中に留まります。 

また、クエリが O(1) になる一方で、挿入とリバランスのコストが O(log n) になるように、各構造のプレフィックスの合計も維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(Q · N log N) | O(N) | 遅すぎる |
 | 山積みのバランスのとれた3構造 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 左、中央、右の 3 つのマルチセット (またはヒープ) を維持します。 中間セットの要素の合計も維持します。 

不変条件は、左には常に挿入されたすべての数値の中で正確に A の最小要素が含まれ、右には常に正確に B の最大の要素が含まれ、中央にはその他すべてが含まれるということです。 したがって、中間和は常にクエリに対する答えになります。

1. 最初に新しい値 x を中間セットに挿入し、x を中間の合計に加算します。 すぐにリバランスして不変条件を復元するため、これは最も単純な安全な挿入ポイントです。 
2. left が空でなく、left の最大要素が x より大きい場合、x をその要素と交換します。 これにより、左側にはこれまでに確認された最小値が引き続き含まれることが保証されます。 その理由は、中央のものよりも大きい要素は左側に留まるべきではないということです。 
3. 同様に、right が空でなく、right の最小要素が x より小さい場合、x をその要素と交換します。 これにより、right が常に最大値を保持することが強制されます。 
4. 挿入後のサイズは制約に違反する可能性があります。 左側に A 個以上の要素がある場合、その最大の要素を中央に移動し、それに応じて中央の合計を調整します。 これにより、左が必要な最小要素数を超えることがなくなります。 
5. 右側には B 個以上の要素がありますが、その最小要素を中央に移動し、それに応じて中央の合計を調整します。 これにより、必要な最大要素数を超えることがなくなります。 
6. 最後に、左の要素が A よりも少ない場合は、最小の要素を中央から左に移動します。 これにより、左側に必要なカウントが復元されます。 同様に、右の要素が B よりも少ない場合は、最大の要素を中央から右に移動します。 
7. クエリ イベントの場合は、現在の中間合計を単純に出力します。 

正確かどうかは、挿入のたびに順序とサイズの制約の両方を復元するかどうかにかかっています。 すべての要素は常にランクによって分割されるため、中間セットは常にランクが A+1 と N−B の間にある要素に正確に対応します。 

### なぜ効果があるのか

 常に、3 つのセットが要素の完全なパーティションを形成します。 再バランス手順では、左側の要素が中央の要素よりも大きくならないようにし、中央の要素も右側の要素より大きくならないようにします。 厳密なサイズ制約と組み合わせると、左が正確に A の最小要素になり、右が正確に B の最大の要素になります。 中間はそれ以外のすべてであるため、その合計が各クエリに必要な答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import bisect

class Multiset:
    def __init__(self):
        self.a = []

    def add(self, x):
        bisect.insort(self.a, x)

    def discard(self, x):
        i = bisect.bisect_left(self.a, x)
        self.a.pop(i)

    def pop_min(self):
        return self.a.pop(0)

    def pop_max(self):
        return self.a.pop()

    def __len__(self):
        return len(self.a)

    def min(self):
        return self.a[0]

    def max(self):
        return self.a[-1]

MOD = 1000000009

def solve():
    data = sys.stdin.read().strip().split()
    it = iter(data)
    c = int(next(it))
    out = []

    for _ in range(c):
        E = int(next(it))
        A = int(next(it))
        B = int(next(it))

        left = Multiset()
        mid = Multiset()
        right = Multiset()
        mid_sum = 0

        def add_mid(x):
            nonlocal mid_sum
            mid.add(x)
            mid_sum += x

        def rem_mid(x):
            nonlocal mid_sum
            mid.discard(x)
            mid_sum -= x

        def rebalance():
            nonlocal mid_sum

            while len(left) > A:
                x = left.pop_max()
                add_mid(x)

            while len(right) > B:
                x = right.pop_min()
                add_mid(x)

            while len(left) < A and len(mid) > 0:
                x = mid.pop_min()
                rem_mid(x)
                left.add(x)

            while len(right) < B and len(mid) > 0:
                x = mid.pop_max()
                rem_mid(x)
                right.add(x)

        for _ in range(E):
            op = next(it)
            if op == 'H':
                x = int(next(it))
                if len(left) and x < left.max():
                    x, t = left.max(), x
                    left.pop_max()
                    add_mid(x)
                    left.add(t)
                    x = t

                if len(right) and x > right.min():
                    x, t = right.min(), x
                    right.pop_min()
                    add_mid(x)
                    right.add(t)
                    x = t

                add_mid(x)
                rebalance()

            else:
                out.append(str(mid_sum % MOD))

        out.append('---')

    print('\n'.join(out))

if __name__ == '__main__':
    solve()
```この実装では、ソートされた 3 つのマルチセットが保持されます。 中央のマルチセットも、クエリが O(1) になるように累計を追跡します。 挿入では、まず左右の境界要素と比較して要素を正しいパーティションに配置しようとします。次に、サイズ違反を修正する再バランス ルーチンを呼び出します。 

重要な点は、セット間の移動はすべて、中央のセットの累計のみを更新する必要があることです。 左と右は答えに寄与しないため、集計する必要はありません。 

このコードでは二分ベースのリストが使用されており、最悪の場合の制約には最適ではありませんが、ロジックは意図したヒープベースまたはバランスツリーのソリューションと一致しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ある瞬間に A + B が E − 1 に等しくなる場合です。これは、中央に要素が 1 つだけ含まれていることを意味します。 1 つの構造が空になった場合でも、すべてのリバランス操作で順序が維持されるため、アルゴリズムは引き続き機能します。 たとえば、A = 2、B = 2、値が [1,2,3,4,5] の場合、中央は [3] となり、クエリは正しく 3 を返します。 

挿入されたすべての値が同一である場合、別の特殊なケースが発生します。 順序が変わらないため、要素は純粋にサイズ制約に基づいてセット間を移動し、要素が移動するにつれて中間合計は予測どおりに変化します。
