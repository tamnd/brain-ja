 ## 解決策
 ## 問題の理解

 私たちは、ブロックが上から落ちて成長する「タワー」を形成する 2D グリッドの構造を構築しています。 各ブロックは 2×1 のサイズのドミノであり、水平または垂直に配置できます。 ブロックが配置されると、テトリスのような物理学における重力とまったく同じように、地面またはすでに配置されている別のブロックに接触するまで真っすぐに落ちます。 

タワー制約はすべてを形作る重要なルールです。すべての新しいブロックは、以前に配置されたブロックの少なくとも 1 つのセルと重複する必要があります。これは、配置のシーケンスが、以前のブロックから上向きに成長する単一の接続された構造を形成することを意味します。 切り離された構造を開始したり、グリッドの別の領域に「ジャンプ」したりすることはできません。 

ボード上のいくつかのセルにはコインが含まれており、それぞれに値が設定されています。 コインが最終スコアに寄与するのは、ゲームが終了した時点でそのセルを占有しているブロックがある場合のみです。 コインが最後のタワーの頂上で覆われていない、または部分的に覆われていない場合、それは何も貢献しません。 

タワーが最大許容高さ L を超えると、このプロセスは終了します。これは、高さ制限を超えないと法的に続行できなくなるまで、効果的にブロックを積み上げることを意味し、最終的に占有されるセルがカバーするコインの価値の合計が最大になるように配置を選択したいと考えています。 

入力サイズでは、最大 1000 万のコインを含む最大 1000 x 1000 のグリッドが可能です。 これにより、配置を明示的にシミュレートしたり、ブロック配置のすべてのシーケンスを評価しようとするアプローチは即座に除外されます。 どのようなソリューションでも状態を大幅に圧縮する必要があり、2D 構造を 1D 動的計画法の問題、さらには独立した列ごとの推論に縮小する可能性があります。 

素朴な解釈は、ドミノのあらゆる可能な配置シーケンスをシミュレートし、その結果の最終的なカバレッジを計算すると考えることです。 各配置には複数の方向と位置があり、オーバーラップ制約により各配置が将来のすべての配置に影響を与えるため、これは組み合わせ的に爆発的に発生します。 

2 番目の単純な間違いは、幾何学的制約を考慮せずに、価値の高いコインを貪欲に取得できると仮定して、各コインを独立して処理することです。 1 つのコインを覆うと他のコインへのアクセスがブロックされたり、高さが強制的に増加して後でより適切な構成が妨げられる可能性があるため、これは失敗します。 

典型的な失敗シナリオは、非効率な垂直構造を強制する構成の下に高額コインが置かれている場合です。 たとえば、価値 100 のコインが (2, 0) にあるが、それを取得すると、その上の価値 60 と 50 の 2 枚のコインをブロックする高いスタックが強制される場合、たとえローカルの価値がより高くても、貪欲な選択は間違っています。 

中心的な問題は、タワーの制約が柱と高さにわたる決定を結び付けるため、ジオメトリを構造化された最適化問題に変換する必要があることです。 

## アプローチ

 強引なアイデアは、タワーを構築するためのすべての有効な方法をシミュレートすることです。 各ブロックの配置は前のブロックに依存し、各状態はタワーの現在の設置面積に依存します。 配置を列挙しようとすると、各ステップには O(W・L) 個の可能な位置と 2 つの方向があり、最大 L 個のブロックを配置できます。 無効な配置を削除した場合でも、配置ごとにタワーの形状が変化し、可能なタワーの形状の数が高さと組み合わせて増加するため、状態空間は指数関数的に増加します。 

このアプローチはすべての有効な構造を探索するため、原理的には正しいですが、W または L が 20 などの小さな値を超えると、ほぼ即座に実行不可能になります。 

重要な構造的洞察は、塔が 2D で進化するにもかかわらず、「各ブロックが前のブロックと重なりなければならない」という制約により、その形状が柱の高さのヒストグラムとして表現できる接続された単調領域のままであることです。 これがわかると、問題はスカイラインが時間の経過とともにどのように変化するかという決定プロセスになります。

各配置では、方向に応じて 1 つの列または隣接する 2 つの列の高さが増加します。 したがって、このプロセスは、隣接性を制約した高さの 1D 配列に対して一連の増分を構築することと同等です。 このように再定式化すると、プロセスを列に対する動的計画問題として扱うことができ、高さレイヤーごとに達成可能な最良の寄与を計算します。 

重要な観察は、コインの貢献度は、各列の最終的な高さがコインの y 座標を超えるかどうかにのみ依存するということです。 これにより、プロセスを逆転させることができます。配置をシミュレートする代わりに、ドミノ増分を使用してそのようなプロファイルを構築する実現可能性を条件として、収集されたコインの合計価値を最大化する最終的な高さのプロファイルを尋ねます。 

これは古典的な削減につながります。行を下から上に処理し、水平および垂直ドミノによって引き起こされる列構成上の DP を維持します。これは、タイルベースの DP と同等です。 幅は最大 1000 であるため、遷移がローカルであり、隣接する列のみに依存するという事実を利用します。

 ## アルゴリズムのチュートリアル

 最終的なタワーは、下から上に層ごとに構築されるものとして再解釈します。 各高さレベル y で、最終構成で各列が占有されているかどうかのいずれかであり、列が占有されている場合は、その高さでのコインの価値が収集されます。 

列 x から高さ h までを考慮して、達成可能な最良のスコアを表す dp[x][h] を計算します。 完全な dp を明示的に維持する代わりに、高さのローリング配列を使用してトランジションを圧縮します。 

1. 各列について、高さにわたるプレフィックスの合計を事前計算し、任意の垂直セグメントの合計コイン価値を迅速にクエリできるようにします。 これにより、列を特定の高さまで拡張することに対する報酬を計算できます。 
2. 行に対して DP を定義します。この状態は、現在垂直方向の継続を配置しているのか、それとも 2 列にわたる水平方向のドミノを開始しているのかを表します。 これは、レイヤーがタワーをローカルに拡張できる 2 つの唯一の有効な方法をエンコードします。 
3. 行を下から上に処理します。 各行 y で、列内に垂直カバレッジを配置するか、隣接する列間を水平に拡張するかを決定します。 それぞれの決定はそのレイヤーからのコイン価値に貢献し、将来のレイヤーの実現可能性に影響を与えます。 
4. 列全体でローリング DP を使用します。 dp[x] には、現在処理されている高さの列 x で終わる構成の最良のスコアが保存されます。 
5. 高さステップごとに、垂直方向の延長 (同じ列) と水平方向のペア (x、x+1) を考慮して dp を更新します。新しいレイヤーはそれぞれ前の構造に接続する必要があるため、オーバーラップ制約が暗黙的に保持されるようにします。 
6. 答えは、高さ L までのすべてのレイヤーを処理した後の最大 dp 値です。 

水平方向の遷移が必要な理由は、ドミノが列間でサポートを移動できるため、列を独立して扱うことができないためです。 

### なぜ効果があるのか

 建設プロセスではコンポーネントがバラバラになることは決して許されないため、あらゆる高さでアクティブなフロンティアが接続されます。 これにより、有効な構成を隣接する列間のローカル遷移に分解できることが保証されます。 DP はこれらのローカル遷移を正確にキャプチャし、有効なすべてのタワーはそのような遷移の一意のシーケンスに対応します。 すべての遷移は有効性を保持し、考えられるすべての遷移を考慮するため、有効な構成が見逃されることはなく、無効な構成はカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    W, L = map(int, input().split())
    N = int(input())
    
    grid = [[0] * W for _ in range(L)]
    for _ in range(N):
        x, y, v = map(int, input().split())
        grid[y][x] += v

    # prefix sums per column
    col_pref = [[0] * (L + 1) for _ in range(W)]
    for x in range(W):
        for y in range(L):
            col_pref[x][y + 1] = col_pref[x][y] + grid[y][x]

    # dp[x] = best score ending at column x at current height layer
    dp = [0] * W

    for h in range(1, L + 1):
        ndp = [-10**18] * W

        for x in range(W):
            # vertical extension in same column
            best = dp[x] + grid[h - 1][x]

            # horizontal transfer from x-1 to x
            if x > 0:
                best = max(best, dp[x - 1] + grid[h - 1][x])

            ndp[x] = best

        dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```コードは、各高さレイヤーが独立して処理される列ごとの動的プログラミング状態を維持します。 グリッドは事前に蓄積されているため、コインの値は O(1) でアクセスできます。 遷移は、特定の層のタワー サポートが垂直方向に継続するか、隣接する柱から水平方向に移動するかを反映し、ドミノ接続制約を暗黙的にモデル化します。 

初期化では空のベース状態を想定し、各高さで既存の柱構造を拡張するか、サポートを横方向に移動します。 最終的な答えは、全高を処理した後のすべての列の最大スコアです。 

微妙な点は、セルがカバーされているかどうかを明示的に保存することはなく、レイヤーを通過するときにコインの値を蓄積することであり、これは「最終的なカバーのみが重要である」ルールと一致します。 

## 実用的な例

 2 番目のサンプル グリッドを考えてみましょう。ここでは、高額のコインが同じ列内のさまざまな高さに配置されており、離れた別の列の中間の高さに非常に高額のコインが配置されています。 

高さ全体の dp を追跡します。 

| h | 前の dp | h での遷移 | |後の dp
 | --- | --- | --- | --- |
 | 0 | [0,0,0,0,0] | 開始 | [0,0,0,0,0] |
 | 1 | ベース | y=0 にコインを追加します | 列ごとに更新 |
 | 2 | ... | 30 価値コイン層を含む | 列 2 に移動するのが最適 |
 | 3 | ... | 小さなコイン | 伝播した |
 | 5 | ... | 大型60価値コイン | 最後のピーク |

 たとえその列が初期段階では最適でなかったとしても、dp は自然に最高の垂直報酬を蓄積する列に向かってシフトします。 

最初のサンプルは、コインが均等に分散され、単一の列が優勢でないケースを示しています。 DP は値を列全体に分散し、水平遷移を介して寄与をマージし、最終的にバランスのとれた最適なパスに収束します。

 ## 特殊なケース

 すべてのコインが 1 つの列にある場合は、特殊なケースが発生します。 DP は水平方向の遷移を必要とせず、解決策はその列を合計することになりますが、垂直方向の拡張では常にレイヤー値が同じ状態に直接蓄積されるため、これは正しく処理されます。 

もう 1 つのケースは、コインが最上層にのみ存在する場合です。 DP は引き続きすべての中間層を処理しますが、最終ステップまで値は追加されないため、結果はアルゴリズムがリセットせずに空の層に状態を正しく伝えるかどうかに完全に依存します。 

最後のエッジ ケースは、最適なパスが列を複数回切り替える場合です。 水平方向の遷移により、dp が各層の隣接する列に最適な値を伝播できることが保証されるため、最適な構造が交互になった場合でも、DP は中間ゲインを失うことなく、達成可能な最大の累積を維持します。
