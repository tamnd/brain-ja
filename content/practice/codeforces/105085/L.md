 ## 解決策
 ## 問題の理解

 私たちには、双方向の道路で接続された都市のネットワークが与えられており、各道路には所要時間が設定されています。 標準の最短経路問題との主な違いは、一部の都市のみに Nexter が含まれており、それらの Nexter 都市間の距離のみを考慮していることです。 

少なくとも 1 つの Nexter がある都市ごとに、すべての Nexter 都市が指定された制限時間内に少なくとも 1 つの企業のオフィス都市に到達できるようにオフィスが配置されているコワーキング会社が少なくとも 1 つ存在するかどうかを知りたいと考えています。$T$。 移動は対称的であり、道路網に沿って 2 つの都市間の移動時間は可能な限り最短になります。 

各企業は、オフィスがある都市のサブセットによって定義されます。 すべての Nexter 都市に、以下の距離内に少なくとも 1 つのオフィス都市がある場合、会社は有効です。$T$。 

出力は、この条件を満たす企業の指数のリストです。 

グラフはノードの点では小さく、全体で最大 200 都市ですが、エッジの密度は中程度である可能性があります。 企業の数は最大 50 であるため、最短経路が効率的に事前計算されていれば、各企業を個別にチェックすることが可能です。 

単純なアプローチでは、会社ごと、または Nexter と都市のペアごとに最短パスを繰り返し計算しようとしますが、すべてのペアの最短パスを繰り返し解いたり、ダイクストラを不必要に何度も実行したりすることになります。 

いくつかの特殊なケースが重要です。 

重要なケースの 1 つは、企業が Nexters を含む都市にオフィスを持たない場合です。 たとえば、すべての Nexter 都市が {1, 2} で、企業が都市 3 にのみオフィスを提供している場合、都市 3 がいくつかのノードに近くても、すべての Nexter ノードがその都市に到達できない限り意味がありません。$T$。 

もう 1 つのケースは、グラフが切断されているが、Nexter 都市が複数のコンポーネントに存在する場合です。 企業が到達可能なすべてのコンポーネントにオフィスを配置しない場合、一部の Nexter 都市が到達不能になり、企業は無効になります。 

最後に条件が厳しいので「以下」$T$”、以下に等しい任意のパス$T$拒否する必要がありますが、これを使用すると誤って処理されやすくなります。$\le T$偶然。 

## アプローチ

 直接的な強引なアプローチは、フロイド・ウォーシャル法またはダイクストラ法の繰り返しを使用して、都市の各ペア間の最短経路を計算し、各企業について、すべての Nexter 都市の距離以内に少なくとも 1 つのオフィス都市があるかどうかを確認することです。$T$。 フロイド＝ウォーシャルが駆けつける$O(N^3)$、で$N = 200$反復回数は約 800 万回で、Python では問題ありませんが、複数のテスト ケースを考慮すると不要なオーバーヘッドが発生します。 さらに重要なのは、事前計算を行わずに企業ごとに再計算または確認すると、距離を繰り返しスキャンすることになり、時間が無駄になります。 

重要な観察は、各 Nexter 都市から他のすべての都市までの距離だけが必要であり、しきい値と比較することだけが必要であるということです。 以来$N \le 200$、すべてのペアの最短パスを一度に計算することは安価で、すべてを簡素化します。 

距離マトリックスを取得したら、企業のチェックは単純なスキャンになります。すべての Nexter 都市について、許可されているオフィス都市の少なくとも 1 つの距離が厳密に以下であるかどうかを確認します。$T$。 これにより、問題は、事前に計算された行列に対するセット メンバーシップ チェックの繰り返しに軽減されます。 

したがって、ソリューションの構造は、すべてのペアの最短経路を一度計算し、次に各企業を個別に評価することになります。$O(N \cdot X)$、 どこ$X$は企業の数であり、各企業は最大でリストに掲載されます$N$都市。

 ## アルゴリズムのチュートリアル

 私たちはこの問題を 2 つの段階で扱います。つまり、最短経路を構築し、次に各企業を検証します。 

1. サイズの距離行列を初期化します。$N \times N$ここで、ゼロの対角線を除き、すべての値は無限大として始まります。 これは、最初は自分自身の距離だけが分かり、道路が分からないことを表します。 
2. あらゆる道路に$u, v, c$、間の距離を設定します。$u$そして$v$に$c$、との間$v$そして$u$に$c$。 複数のエッジが存在する場合は、最小の重みを維持します。 このステップでは、基本グラフを構築します。 
3. 三つの都市すべてに対してフロイド・ウォーシャルを実行する$k, i, j$、距離を次のように更新します$dist[i][j] = \min(dist[i][j], dist[i][k] + dist[k][j])$。 これにより、都市の各ペア間の最短の移動時間が計算されます。 
4. Nexter 都市のリストを読み取り、セットまたはリストに保存します。 適用範囲を確認する必要があるのはこれらの都市だけです。 
5. 企業ごとに、Nexter の各都市を反復処理します。 特定の Nexter 都市の場合$u$、少なくとも 1 つのオフィス都市が存在するかどうかを確認します。$v$あの会社ではそんなこと$dist[u][v] < T$。 そうでない場合$v$Nexter の都市に存在する場合、その会社は無効です。 
6. 有効なすべての企業のインデックスを収集し、昇順に出力します。 どれも有効でない場合は、必要な失敗文字列を出力します。 

重要な効率は、すべての企業に対して同じ事前計算された距離マトリックスを再利用することによってもたらされます。 

### なぜ効果があるのか

 フロイド-ウォーシャル以降、距離行列は都市のペア間の真の最短移動時間を表します。 したがって、Nexter 都市がある企業によって「カバーされている」かどうかを確認することは、事前に計算された計量空間のしきい値距離内に少なくとも 1 つのオフィス都市があるかどうかを確認することになります。 

フロイド-ウォーシャル中に維持される不変条件は、中間ノードを処理した後の不変条件です。$k$、行列には​​、中間ノードのみを使用する最短パスが格納されます。$[1, k]$。 すべてのノードが処理されると、考えられるすべての中間パスが考慮されるため、結果は全体的に最適になります。 これにより、最終的な距離の比較が保証されます。$T$は正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    N, E, X, T = map(int, input().split())
    if N == 0 and E == 0 and X == 0 and T == 0:
        return False

    dist = [[INF] * N for _ in range(N)]
    for i in range(N):
        dist[i][i] = 0

    for _ in range(E):
        u, v, c = map(int, input().split())
        u -= 1
        v -= 1
        if c < dist[u][v]:
            dist[u][v] = c
            dist[v][u] = c

    for k in range(N):
        dk = dist[k]
        for i in range(N):
            di = dist[i]
            dik = di[k]
            for j in range(N):
                nd = dik + dk[j]
                if nd < di[j]:
                    di[j] = nd

    nexters = list(range(N))
    # determine Nexter cities by reading companies? Actually problem implies:
    # "cities where Nexters are" is given implicitly as all N cities in sample? 
    # BUT in statement: "N cities where Nexters are" => all cities are Nexter cities.
    # So we treat all cities as required nodes.

    valid = []
    companies = []
    for _ in range(X):
        data = list(map(int, input().split()))
        o = data[0]
        offices = [x - 1 for x in data[1:]]
        companies.append(offices)

    for idx, offices in enumerate(companies, start=1):
        ok = True
        for u in range(N):
            best = INF
            for v in offices:
                if dist[u][v] < best:
                    best = dist[u][v]
                    if best < T:
                        break
            if best >= T:
                ok = False
                break
        if ok:
            valid.append(idx)

    if valid:
        print(*valid)
    else:
        print("NO HAY EMPRESAS")

    return True

def main():
    while True:
        if not solve():
            break

if __name__ == "__main__":
    main()

企業チェックループは、都市ごとにオフィスとの最適な距離を維持できるように構成されています。 より小さい距離を見つけるとすぐに、$T$、その都市に向けて早めに停止するため、定数がわずかに減少します。 

微妙な点の 1 つは、厳格な不平等チェックです。`best >= T`。 これにより、「T 未満」という条件が強制され、これを省略すると、境界線のケースが誤って受け入れられてしまいます。

            return False

            v -= 1

            for i in range(N):

                    break

    return solve()

 エッジ ケースの 1 つは、企業が 1 つの都市にのみオフィスを配置し、すべての Nexter 都市がそこに到達する必要がある場合です。 距離行列が真の最短経路を捕捉しており、いずれかの都市がしきい値を超えると最小チェックは当然失敗するため、アルゴリズムはこれを正しく処理します。
