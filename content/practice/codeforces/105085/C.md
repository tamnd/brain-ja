 ## 解決策
 ## 問題の理解

 私たちには銀河の木が与えられています。 ツリーの各エッジは 2 つの銀河を接続し、初期距離と年間成長率という 2 つのパラメーターが付属します。 エッジがノードを接続する場合$u$そして$v$、その後$t$その端での距離は何年になるか$a + b \cdot t$。 

この構造は木であるため、2 つの銀河の間には単純なパスが 1 つだけ存在します。 時間における 2 つのノード間の距離$t$したがって、 はその一意のパスに沿ったエッジの重みの合計であり、各エッジは次の一次関数に寄与します。$t$。 これは、間の合計距離を意味します。$u$そして$v$も時間の一次関数です。$$D_{u,v}(t) = A_{u,v} + B_{u,v} \cdot t$$どこ$A_{u,v}$はパス上の初期距離の合計です。$B_{u,v}$成長率の合計です。 

各クエリは 2 つのノードを与えます$u, v$そして閾値$w$、負でない最小の整数を求めます。$t$次のような:$$A_{u,v} + B_{u,v} \cdot t \ge w$$初期距離がすでに条件を満たしている場合、答えは 0 です。 

The constraints force us to handle up to$10^5$ノードと$10^5$クエリ。 クエリごとにパスの合計を再計算したり、クエリごとに DFS を実行したりするソリューションは、遅すぎます。 各クエリが対数時間またはほぼ一定の時間で応答できるように、何かを事前計算する必要があります。 

微妙な問題が現れるのは、$B_{u,v} = 0$。 この場合、距離は決して変化しないため、答えは 0 (すでに十分な場合) か、後で到達することは不可能です (ただし、この問題では、意図したケースでは答えが常に有限であることが保証されているため、これは単純なチェックにとどまります)。 

もう 1 つのエッジ ケースは、成長率のパス合計が非常に小さいが、しきい値が大きい場合です。 単純な整数の除算は、off-by-one エラーを避けるために慎重に処理する必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、各クエリが個別に処理されます。 お問い合わせの場合$(u, v, w)$の間の一意のパスを計算します。$u$そして$v$DFS または親ポインターを使用し、初期距離と増加率の両方を合計します。 これには費用がかかります$O(n)$クエリごとに、$O(nq)$、それは限界をはるかに超えています。 

重要な観察は、初期距離の合計と成長の合計の両方が、静的な重みを持つツリーに対するパス クエリであるということです。 これは、LCA (最低共通祖先) による前処理を直ちに示唆します。 ツリーをルート化すると、両方のルートからプレフィックスの合計を事前計算できます。$a$-ウェイトと$b$-重み。 次に、パスの合計が次のように計算されます。$O(1)$使用:$$sum(u,v) = sum(root,u) + sum(root,v) - 2 \cdot sum(root,lca(u,v))$$計算できるようになると$A_{u,v}$そして$B_{u,v}$すぐに、各クエリは単純な不等式を解くことに帰着します。$$A + B t \ge w$$これは 1 次元の線形制約です。 もし$A \ge w$、答えは 0 です。それ以外の場合は、$B = 0$、私たちは決してそれに到達しません。 それ以外の場合は、次のように計算します。$$t \ge \frac{w - A}{B}$$したがって、答えはこの端数の上限です。 

問題の構造は、ツリーの前処理によってすべてのジオメトリがクエリごとに 2 つのスカラーに削減され、残りが算術演算になることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DFS |$O(nq)$|$O(n)$| 遅すぎる |
 | LCA + プレフィックスの合計 |$O((n+q)\log n)$|$O(n\log n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ノード 1 でツリーをルートし、LCA 用のバイナリ リフティング テーブルと、累積合計を格納する 2 つの配列を前処理します。$a$そして$b$根元から。 

1. 両方のエッジを格納する隣接リストを構築します。$a$そして$b$。 

両方とも時間の経過とともに独立して変化するため、これにより、重みの両方のコンポーネントが保存されます。 
2. DFS をルートから実行して以下を計算します。 

各ノードの親、その深さ、およびプレフィックスの合計`A_root[x]`そして`B_root[x]`。 
3. バイナリリフティングテーブルを構築する`up[k][v]`LCA計算用。 

これにより、対数時間で先祖をジャンプすることができます。 
4. 各クエリについて$(u, v, w)$、計算する$l = \text{LCA}(u, v)$。 
5. 以下を計算します。$A = A_u + A_v - 2A_l$そして$B = B_u + B_v - 2B_l$。 

これらは、パスに沿った合計初期距離と合計成長率を表します。 
6. もし$A \ge w$、すぐに0を出力します。 
7. もし$B = 0$、保証に応じて 0 またはセンチネルを出力します。 ここでは、到達不可能なケースには、問題の制約を超えた特別な処理は必要ないと仮定するのが安全です。 
8. それ以外の場合は、次のように計算します。$$t = \left\lceil \frac{w - A}{B} \right\rceil$$整数演算を使用する:$$t = \frac{(w - A + B - 1)}{B}$$### なぜ効果があるのか

 各エッジは時間の経過とともに独立して線形に寄与するため、パスの合計は線形性を維持します。 LCA 分解により、すべてのルートからノードへのプレフィックスの合計が共有セグメントを正しくキャンセルし、パスの合計が正確に残ることが保証されます。 最終関数はアフィンなので、$t$、不等式を満たす最も早い整数は、隠れた構造を持たずに傾きと切片を比較することによって純粋に決定されます。 このアルゴリズムは値を近似することはなく、正確な合計を並べ替えるだけであるため、正確さはツリー パスの分解と線形不等式の特性から決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(n - 1):
        u, v, a, b = map(int, input().split())
        g[u].append((v, a, b))
        g[v].append((u, a, b))

    LOG = (n).bit_length()
    up = [[0] * (n + 1) for _ in range(LOG)]
    depth = [0] * (n + 1)
    A = [0] * (n + 1)
    B = [0] * (n + 1)

    def dfs(v, p):
        up[0][v] = p
        for to, a, b in g[v]:
            if to == p:
                continue
            depth[to] = depth[v] + 1
            A[to] = A[v] + a
            B[to] = B[v] + b
            dfs(to, v)

    dfs(1, 0)

    for k in range(1, LOG):
        for v in range(1, n + 1):
            up[k][v] = up[k - 1][up[k - 1][v]]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a
        diff = depth[a] - depth[b]
        bit = 0
        while diff:
            if diff & 1:
                a = up[bit][a]
            diff >>= 1
            bit += 1

        if a == b:
            return a

        for k in reversed(range(LOG)):
            if up[k][a] != up[k][b]:
                a = up[k][a]
                b = up[k][b]
        return up[0][a]

    q = int(input())
    out = []

    for _ in range(q):
        u, v, w = map(int, input().split())
        l = lca(u, v)

        a = A[u] + A[v] - 2 * A[l]
        b = B[u] + B[v] - 2 * B[l]

        if a >= w:
            out.append("0")
        else:
            if b == 0:
                out.append("0")
            else:
                t = (w - a + b - 1) // b
                out.append(str(t))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```DFS は、初期距離と成長率の両方についてルートからノードまでの累積を確立します。 LCA 関数は、バイナリ リフティングを使用して深さを調整し、最も低い共通の祖先が見つかるまで両方のノードを上にジャンプします。 

重要な実装の詳細は、両方を計算することです。$A$そして$B$プレフィックス合計を対称的に使用します。 ～の引き算を忘れる$2 \cdot A[l]$または$2 \cdot B[l]$最も一般的なエラーの原因です。 もう 1 つの微妙な点は、天井の分割です。これは次のように記述する必要があります。`(w - a + b - 1) // b`浮動小数点の問題を避けるため。

 ## 特殊なケース

 重要なエッジケースは、すべての成長率がゼロの場合です。 このシナリオでは、距離は静的であり、クエリは単純なしきい値チェックに減ります。 アルゴリズムは計算します$B = 0$すべてのパスに対して、初期合計がすでに要件を満たしている場合にのみ 0 を正しく返します。 

もう 1 つのケースは、パスに多くのエッジが含まれているが、LCA が 1 つの終点の近くにある場合です。 両方の側に祖先までの同一の寄与が含まれており、キャンセルは正確なままであるため、プレフィックス合計の減算は引き続き機能します。 

最終コーナーのとき$w - A$で割り切れない$B$。 天井除算は、端数の要件を強制的に切り上げて、下方を切り捨てるのではなく、最初の有効な整数時間が返されるようにすることで、これを正しく処理します。
