 ## 解決策
 ## 問題の理解

 このタスクでは、さまざまな種類のセルで構成される 2D グリッド上を移動するロボットについて説明します。このグリッドでは、一部のセルは通過可能ですが、他のセルはブロックされます。 ロボットは常に向いている方向を持っており、その動作ルールは方向転換と前進を区別します。 回転すると方向のみが変わりますが、前進すると現在向いている方向に 1 セル進みます。 

重要な制約は、前方への動きは制限されるが、回転には制限がないことです。 これにより、問題の性質がすぐに変わります。ロボットはコストをかけずに何度でも任意に方向を変えることができますが、隣接するセルへの実際のステップごとに、有限の前進量が消費されます。 目標は、開始位置からターゲット セルに到達するために必要な前進の最小回数を決定するか、不可能であると報告することです。 

このステートメントによって暗示されるグリッド構造では、セルの種類を表す文字が使用されます。 1 つのシンボルはロボットの出発地を示し、別のシンボルは目的地を示します。残りは空かブロックされています。 移動は有効な空のセルに制限され、ロボットは方向に関係なくブロックされたセルを通過できません。 

複雑さの観点から見ると、このタイプのグリッドは通常、合計で最大約 10^5 から数百万のセルになります。 この範囲では、状態ごとにパスを繰り返し再計算したり、方向履歴に対して指数関数的な探索を使用したりするソリューションは直ちに除外されます。 向きを明示的に追跡し、ターンと移動のすべてのシーケンスを試行する単純なシミュレーションでは、ステップごとに 4 つの方法に効果的に分岐し、パスが指数関数的に増加します。 

微妙な失敗例は、ソリューションが方向を状態の一部として誤って扱い、回転シーケンスに異なるコストを割り当てる場合に発生します。 たとえば、ロボットが上を向いて開始するが、最適なパスでは最初は右に移動する必要がある場合、単純な方法では最初に方向を「揃える」ことを試行し、誤ってステップ数を増やしたり、有効なパスを切り捨てたりする可能性があります。 回転は無料であるため、回転にコストを課すアプローチは真の最小値を過大評価することになります。 

もう 1 つのよくある落とし穴は、ロボットが回転する前に壁にぶつかるまで前進し続けなければならないと想定している場合に発生します。 その解釈では、動作シーケンスが誤って制限されてしまいます。 実際には、ロボットはすべてのセルで方向転換とステップを交互に行うことができます。つまり、以前の方向に関係なく、隣接するすべてのセルが 1 回の前進で常に到達可能になります。 

## アプローチ

 強引な解釈では、問題を位置と方向からなる拡張された状態空間上の最短経路として扱います。 各状態から、ロボットはコストをかけずに左または右に回転でき、次のセルが有効であれば前進できます。 この状態グラフに対して標準の BFS またはダイクストラを実行するのは正しいでしょう。 ただし、向きの次元では状態の数が 4 倍になり、各セル遷移では複数の冗長な方向変更が考慮される場合があります。 最悪の場合、回転はコストに寄与しないため、これは不要なオーバーヘッドになります。 

重要な点は、回転が自由であるため、方向によって到達可能性が制限されることがないことです。 どのセルからでも、ロボットは移動する前に 4 つの方向のいずれかを選択できます。 これにより、すべての方向状態がグリッド セルごとの 1 つのノードに折りたたまれます。 各移動は、ターゲット セルがブロックされていない限り、単位コストで 4 つの隣接するセルのいずれかにステップすることと同等になります。 この問題は、グリッド グラフ上の重み付けされていない最短経路に帰着します。 

これにより、ソリューションはセルのみに対する標準的な幅優先検索に変換されます。

 ## アルゴリズムのチュートリアル

### 1. グリッドを解析し、キーの位置を特定します。 

グリッド全体を 1 回スキャンして、開始セルとターゲット セルを特定します。 BFS 初期化のために座標を保存します。 このステップにより、曖昧さのない正しい原点から探索を開始できるようになります。 

### 2. グリッドをセルのグラフとしてモデル化する

 各開いたセルをノードとして扱います。 2 つのノードが垂直または水平に隣接しており、両方がブロックされていない場合、それらのノードは接続されています。 ロボットの回転能力により、方向を完全に無視できるため、追加の状態は必要ありません。 

### 3. 開始セルから BFS を初期化します。 

開始位置をキューにプッシュし、訪問済みとしてマークします。 前方への移動がまだ使用されていないため、このセルの BFS 距離はゼロです。 

### 4. 隣接するものをレベルごとに展開します

 各ステップでセルをデキューし、4 つの基本方向に移動しようとします。 まだ訪問されていない有効な近隣ノードごとに、現在の距離に 1 を加えたものに等しい距離を割り当て、キューに入れます。 これにより、初めて任意のセルに到達するときに、最小限の前進移動数が使用されることが保証されます。 

### 5. 目標に到達したら停止する

 ターゲット セルがデキューされるか、最初に検出されるとすぐに、その記録された距離を返します。 BFS は、これが必要な前進移動の最小数であることを保証します。 

### なぜ効果があるのか

 不変条件は、BFS が使用された前方移動の非降順でセルを処理することです。 すべてのエッジのコストは等しく、回転はコストに影響を与えないため、セルへのパスは一連の順方向ステップに正確に対応します。 BFS は最初にすべての短いパスを探索するため、セルにアクセスすると、より少ない前進で代替パスに到達することはできません。 向きの変更は各移動の前にコストをかけずに実行できるため、向きを削除しても正確さが失われることはありません。つまり、すべての隣接が以前の状態とは関係なく常に利用可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    grid = [line.rstrip("\n") for line in sys.stdin if line.strip() != ""]
    if not grid:
        return

    n = len(grid)
    m = len(grid[0])

    start = None
    target = None

    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'S':
                start = (i, j)
            elif grid[i][j] == 'T':
                target = (i, j)

    dist = [[-1] * m for _ in range(n)]
    q = deque()

    si, sj = start
    ti, tj = target

    dist[si][sj] = 0
    q.append((si, sj))

    dirs = [(1,0), (-1,0), (0,1), (0,-1)]

    while q:
        x, y = q.popleft()

        if (x, y) == (ti, tj):
            print(dist[x][y])
            return

        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m:
                if grid[nx][ny] != '#' and dist[nx][ny] == -1:
                    dist[nx][ny] = dist[x][y] + 1
                    q.append((nx, ny))

    print(-1)

if __name__ == "__main__":
    solve()
```この実装では、まずグリッドを抽出し、開始マーカーとターゲット マーカーを見つけます。 次に、キューを使用して標準的な BFS を実行し、距離を行列に保存します。 方向リストは、自由回転後に可能な 4 つの前進移動をエンコードします。 訪問された配列により、セルの再訪問が防止され、線形の複雑さが保証されます。 

微妙な点は、方向を決して保存しないことです。 これが主な単純化です。回転が自由であるため、ロボットは移動する前に常に位置を調整できるため、ステップ間で方向を維持する必要がありません。

 ## 特殊なケース

 主なエッジケースは、スタートとターゲットが隣接しているが、一方向を除くすべての方向に壁によって分離されている場合に発生します。 BFS は方向に依存せずに 4 つの方向すべてを独立して探索するため、単一の有効なルートを引き続き正確に識別します。 

もう 1 つのケースは、グリッドに同じくらい短いルートが複数ある場合です。 BFS は最初の検出時に訪問したセルにマークを付けるため、短いパスを長いパスで上書きすることはありません。 たとえば、2 つのパスが同じ深さの同じセルに到達した場合、1 つだけがキューに入れられますが、すべてのパスのコストが等しいため、正確性は保たれます。 

最後のケースは、パスがまったく存在しない場合です。 BFS は到達可能なコンポーネントを使い果たし、ターゲットは未訪問のままになり、出力として -1 が正しく生成されます。
