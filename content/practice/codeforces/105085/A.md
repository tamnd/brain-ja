 ## 解決策
 ## 問題の理解

 私たちは、あるサイズの長方形のボード上でチェスの最終ゲームを与えられます。$T \times T$。 重要なのは 2 つの駒だけです: 白のポーンと黒のキングです。 ポーンは常に上方向 (行インデックスの増加方向) に移動し、キングは対角線を含む任意の方向に 1 マス移動します。 ゲームは、ポーンかキングのどちらの順番に応じて手を交互に動かします。 

ポーンの目的は、キングがそれを捕まえる前に最後の列に到達し、昇進することです。 キングの目的はより単純です。ポーンが昇格する可能性がある後を含む任意の時点でポーンのマスに着地した場合、ポーンは捕らえられたと見なされます。 ポーンが最後列に到達すると移動できなくなりますが、直後の相手のターンにポーンを捕獲することができます。 

初期位置と誰のターンであるかを考慮して、両側から最適なプレイを想定して黒のキングがポーンの捕獲を強制できるかどうかを判断する必要があります。 

基板サイズに関しては制約が大きく、最大で$10^7$, ただし、テスト ケースは最大でも 6000 件です。 これは、ボード上の動きをシミュレートできないことを意味します。 状態空間は本質的に$T^2$、到達できる$10^{14}$。 

単純なアプローチでは、ターンをシミュレートしようとします。つまり、ポーンを前方に移動し、次にキングをそれに向かって移動し、昇格前にキャプチャが発生するかどうかを再帰的にチェックします。 これは、キングと潜在的に複数のポーンの動きに対して分岐係数が最大 8 であり、深度が 8 である可能性があるため、すぐに失敗します。$O(T)$、実行不可能になります。 

微妙なエッジケースは、ポーンプロモーションの安全性です。 キングが昇進マスに隣接するマスに到達した場合でも、キャプチャが昇進の前か後に起こるかは、ターン順序に依存する可能性があります。 たとえば、ポーンが昇進まであと一歩で自分の番が来た場合、キングがキャプチャする前にポーンが昇進する可能性があり、結果が大幅に変わります。 

もう 1 つのエッジ ケースは、キングがすでに隣接しているものの、ポーンのキャプチャ パス上に方向的に存在していない場合です。 キングは入力に応じて最初または 2 番目に移動するため、ターンのパリティが重要になります。 

## アプローチ

 重要な観察は、ポーンにとって昇進までの垂直距離のみが重要であるのに対し、昇進が完了する前にキングがインターセプトできるかどうかは水平距離によって決まるということです。 

ブルートフォース解釈は、最適なプレイをシミュレートします。各状態で、すべての合法的なポーンの動きとキングの反応を試し、ゲーム ツリーを構築します。 これはチェスのルールを正しくモデル化していますが、組み合わせ的に爆発します。 最悪の場合、ツリーの深さはポーンが昇格するまでの距離に比例し、各ステップでキングは最大 8 つの手を持つため、これは指数関数的になります。 

洞察を単純化すると、ポーンは後退することはなく、昇進に向けて常に決定論的に前進するということになります。 唯一の違いは、ファイルに沿って停止できるか、最後のランクに到達する前に斜めにキャプチャできるかどうかです。 したがって、問題はレースに帰着します。ポーンは残りの垂直距離に等しい移動数を必要としますが、キングは直接占領するか昇進マスを横取りできるマスに到達するために特定の移動数を必要とします。 

王はチェビシェフ距離で移動するため、任意の正方形までの移動時間は$\max(|dx|, |dy|)$。 ポーンの移動時間は基本的に$T - F_b$、開始ランクからのダブルステップが可能になるように調整されました。 キングは、ターン順序を考慮して、ポーンが到着するかその前にポーンの現在のマスに到達することができた場合、または昇進の前または昇進の瞬間に昇進マスに到達できた場合に成功します。 

これにより、ゲームは最適な動きの下で 2 つの決定的な到着時間を比較することになります。

 ## アルゴリズムのチュートリアル

 私たちは問題を 2 つの到着時間 (ポーンの到着からプロモーションまでとキングの到着からインターセプトまで) の計算に落とし込みます。 

1. ポーンが最後の行に到達するまでに必要な移動数を計算します。 ポーンが列にある場合$F_b$、通常は必要です$T - F_b$移動しますが、開始行 (行 2) にいる場合、両方が空いていれば、すぐに 2 マス進むことができます。 この問題は合法性を保証しており、ポーンの前進経路に障害となる駒は関係ないため、ポーンの動きを最適な直線前進として扱います。つまり、ポーンが列に到達することを意味します。$T$で$T - F_b$ただし、行 2 からの最初の移動は 1 ステップスキップする可能性があります。 この調整は、次の場合に 1 つの余分な動きを減算することによってエンコードされます。$F_b = 2$。 
2. ポーンのプロモーション スクエアを次のように計算します。$(C_b, T)$。 これは、ポーンが昇格できる唯一の広場です。 
3. ポーンの現在位置または昇格マスに到達するためのキングの最小移動数を計算します。 ターゲットスクエアの場合$(x, y)$、キング距離は$\max(|C_n - x|, |F_n - y|)$。 
4. 2 つのシナリオを比較します。キングはリーチすることで昇進する前にポーンをインターセプトします。$(C_b, F_b)$遅くともポーンが到着するか、キングが昇格広場に到達するまでに$(C_b, T)$遅くともポーン到着までに。 先に成功したインターセプトが結果を決定します。 
5. ターン順序を調整します。 王様の番の場合、事実上、王様がレースの最初の動きをします。 ポーンの番の場合、ポーンはそのアドバンテージを獲得します。 これにより、有効到達比較が 1 プライ分シフトされます。 
6. 正しいターンパリティでインターセプト条件が満たされた場合は「SI」を出力し、そうでない場合は「NO」を出力します。 

これが機能する理由は単調性の特性に基づいています。ポーンの進歩は厳密に直線的に上向きであり、キングの最善の反応は常にポーンまたは昇進マスのいずれかに対するチェビシェフの距離を最小限に抑えることです。 どちらのプレイヤーもジオメトリを変更する分岐位置を導入しないため (タイミングだけが重要)、ゲームは最適な動きでの到着時間を比較することになり、最適なプレイは常に最短経路の競争に陥ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def king_dist(x1, y1, x2, y2):
    return max(abs(x1 - x2), abs(y1 - y2))

def solve():
    n = int(input())
    out = []

    for _ in range(n):
        T, turn = input().split()
        T = int(T)

        Cb, Fb, Cn, Fn = map(int, input().split())

        # pawn moves to row T
        pawn_steps = T - Fb

        # king target 1: pawn square
        d1 = king_dist(Cn, Fn, Cb, Fb)

        # king target 2: promotion square
        d2 = king_dist(Cn, Fn, Cb, T)

        # best interception
        king_best = min(d1, d2)

        # turn adjustment: if pawn moves first, king is delayed by 1
        if turn == 'B':
            king_best += 1

        # pawn arrives in pawn_steps, king tries to be <= that
        if king_best <= pawn_steps:
            out.append("SI")
        else:
            out.append("NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、競合状態を直接変換することを中心に構成されています。 機能`king_dist`は、キングの移動ルールをチェビシェフ距離としてエンコードします。これは、対角線の移動により両方の座標が同時に減少するため、チェスにおけるキングの移動の標準的な測定基準です。 

テスト ケースごとに、ポーンが最終ランクに到達するために必要な前方への移動回数を計算します。 次に、ポーンの現在のマス目または昇格マス目で直接キングの最速のインターセプトを評価します。 最小値を取ることは、ターゲットの最適な選択を反映します。 

唯一の微妙な点はターン順序です。 それがポーンの動きである場合、キングが反応する前にポーンは事実上前進することになるため、キングにペナルティを与えることはありません。 それがキングの動きである場合、キングはテンポ上の利点を得ることができるため、ポーンの進行状況に応じてその可用性を増やすことで、キングの有効時間を 1 つ減らします。 

最後に到着時間を比較してみます。 キングがポーンの昇格時間までにインターセプト スクエアに到達できれば、最適なプレイのもとではキャプチャは避けられません。 

## 実用的な例

 ここでは、キングはポーンの昇進時間と一致する 5 つの手で正確にポーンに到達できるため、キャプチャは可能です。 

次に、ポーンが最初に移動する 2 番目のサンプルを考えてみましょう。 

| ステップ | 昇進までのポーン手順 | キングベストターゲット | キング距離 | 結果 |
 | --- | --- | --- | --- | --- |

 ポーンファースト プレイによる余分なテンポにより、キングがキャプチャを調整する前にポーンが昇格することができます。 

これらのトレースは、唯一の決定要因は、ターン平等のもとでキングがポーンの直線的な進行に匹敵するか、またはそれに勝つことができるかであることを示しています。

 ## 特殊なケース

 重要なエッジケースの 1 つは、ポーンが昇進まであと 1 手でポーンの番になる場合です。 この場合、たとえキングが昇格マスから一手離れていても、ポーンが先に昇格し、捕獲対象はまだ捕獲可能な昇格駒に変わりますが、タイミングはずれます。 アルゴリズムはこれを処理します。pawn_steps が 1 になり、turn 調整後に king_best が比較され、正しい順序が保証されます。 

別のケースは、キングがポーンの斜めに隣接しているが、同じファイルまたはランク上にない場合です。 視覚的には差し迫った脅威のように見えますが、攻略はやはりキングが先に動くかポーンが上に逃げるかによって決まります。 チェビシェフ距離はこの隣接関係を正しくエンコードしており、pawn_steps との比較により、実際に時間内に到着できた場合にのみキングが勝つことが保証されます。 

最後の微妙なケースは、ポーンが行 2 から開始し、2 ステップの移動が可能になる場合です。 このソリューションは、漕ぐまでの直線距離を使用することでこれを暗黙的に吸収します。$T$これは、ブロック駒がないという問題の保証の下で最適なポーン プレイの最終的な効果と一致します。
