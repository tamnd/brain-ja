 ## 問題の理解

 英語の小文字で構成される文字列が与えられます。 各テスト ケースでは、元の文字列で重複しない 2 つの部分文字列を選択する必要があります。 選択された各部分文字列は頻度制約を満たす必要があります。その部分文字列内では、次の文字を超えて出現することはできません。`m`回。 目標は、選択した 2 つの部分文字列の合計の長さを最大化することです。 

ここでの部分文字列は、単に元の文字列の連続した区間です。 非重複要件は、1 つの部分文字列が次の位置で終了する場合を意味します。`r`、もう一方は厳密にその後に開始する必要があります`r`、またはその逆。 

主要な制約は、選択した各セグメントに対してローカルです。グローバルな周波数を制限するのではなく、選択した各間隔内の周波数のみを制限します。 これは、実現可能性がセグメント間の相互作用ではなく、セグメント内の文字の内部分布のみに依存することを意味します。 

入力サイズはテスト ケース全体で大きく、合計`n`最大約 10^6。 これにより、部分文字列に対する二次関数のアプローチが即座に排除されます。 すべてのセグメントのペアを列挙したり、すべての有効なセグメントを明示的に列挙したりするソリューションは、遅すぎます。 テスト ケースごとに線形または線形演算に近いものを期待する必要があります。 

微妙なエッジ ケースは、たとえ長い部分文字列が無効であっても、その中の短い部分文字列は依然として有効である可能性があり、重複を避けるために 1 つの間隔を短くする必要があるという事実から生じます。 たとえば、最大の有効なセグメントが次に最適なセグメントと重なっている場合、それをわずかに縮小する必要があるかもしれませんが、縮小するとその寄与が減少するため、調整せずに貪欲に最大のセグメントを取得するのではなく、両方の可能性を考慮する体系的な方法が必要です。 

## アプローチ

 直接的なアプローチは、すべての部分文字列を列挙し、それぞれが制約を満たすかどうかを確認することです (次の文字列以上の文字は表示されません)。`m`回)、次に、互いに素な有効な部分文字列のすべてのペアを試して、長さの合計を最大化します。 部分文字列の有効性チェックは頻度カウントを使用して実行できますが、プレフィックスの合計を使用した場合でも、およそ O(n^2) 個の部分文字列と O(1) または O(26) 個のチェックが必要となり、これは実現可能性をはるかに超えています。`n`10^6 に達します。 

最初の単純化は、開始位置が固定されている場合に観察することです。`l`、独特の最遠位置があります`r[l]`部分文字列が`[l, r[l]]`有効のままです。 で始まる任意の短い部分文字列`l`も有効ですが、それを超えて拡張されます`r[l]`制約を破ります。 これにより、問題が任意の部分文字列から、各開始位置が最大の有効な間隔を導き出し、その開始位置からのすべての有効な選択肢がその間隔のプレフィックスとなる構造に変換されます。 

計算できる`r[l]`26 文字にわたる頻度配列を持つスライディング ウィンドウを使用します。 前方にのみ移動する右ポインタと 1 つずつ進む左ポインタを維持し、それに応じてカウントを縮小します。 これにより、線形時間でのすべての最大有効ウィンドウが得られます。 

取得したら`r[l]`、各開始位置`l`有効な部分文字列のファミリーを定義します`[l, r]`みんなのために`r ≤ r[l]`。 このような部分文字列の長さは次のとおりです。`r - l + 1`。 

次に、2 つの互いに素な部分文字列を選択する必要があります。 から始まる左の部分文字列を修正するとします。`i`で始まる右の部分文字列`j`、 と`i < j`。 相互作用は、次の最大間隔かどうかによって決まります。`i`重なる`j`。 

もし`r[i] < j`の場合、最初のセグメントの最良の選択はその最大延長であり、2 番目のセグメントは独立しています。 合計は単純に`best[i] + best[j]`、 どこ`best[x] = r[x] - x + 1`。 

もし`r[i] ≥ j`の場合、最初のセグメントはそれを超えて拡張できません。`j - 1`なので、その効果的な寄与は次のようになります。`j - i`。 2 番目のセグメントは可能な限り最適な長さのままです。 これにより、事前に計算された間隔の長さだけでなく、相対位置への依存関係が作成されます。 

これにより、問題はペアごとに 2 つのケースに分割されますが、どちらも最適化できます。 それぞれについて`i`、次のように考えることができます。 

2 番目のセグメントを強制的に開始すると、`r[i]`の場合、最初のセグメントはいつでも完全な長さを取ることができ、必要なのは最良のものだけです。`best[j]`サフィックスに。 

2 番目のセグメントを強制的に最大範囲内で開始すると、`i`に応じてペナルティを支払います。`i`そして`j`を最大化する必要があります`best[j] + j`ある範囲にわたって。 

どちらの場合も、事前計算された配列に対するクエリの範囲が最大に減り、プレフィックス/サフィックスの最大値またはセグメント ツリーで処理できます。

 ## アルゴリズムのチュートリアル

 まず、すべてのポジションについて計算します`l`、最も遠い位置`r[l]`部分文字列が`[l, r[l]]`を超える文字は決して含まれません`m`回。 これは、2 ポインター ウィンドウと 26 文字にわたる頻度配列を使用して行われます。 右ポインタは文字列内を前方にのみ移動するため、各文字は一定の回数だけ追加および削除されます。 

この前処理の後、次のように定義します。`best[l] = r[l] - l + 1`、これは、で始まる部分文字列の達成可能な最大長です。`l`。 

次に補助配列を準備します`val[l] = best[l] + l`これは、最初のセグメントの一部を 2 番目のセグメントの開始位置とトレードオフする必要がある重複ケースを処理するのに役立ちます。 

サフィックス最大配列も構築します`suf_best[i] = max(best[i..n])`これにより、指定された境界の後に始まる最適な 2 番目のセグメントをすばやくクエリできます。 

次に、考えられるすべての開始位置を反復します。`i`最初のセグメントの場合。 

それぞれについて`i`、2つの場合を考えます。 まず、2 番目のセグメントが次の後に始まると仮定します。`r[i]`。 その状況では、最初のセグメントは安全に全長を使用できます。`best[i]`、2番目のセグメントが貢献します`max(best[j])`みんなのために`j > r[i]`。 これにより、次のような回答候補が得られます`best[i] + suf_best[r[i] + 1]`。 

次に、2 番目のセグメントが内部で始まる場合を考えます。`[i, r[i]]`。 どれについても`j`この範囲では、最初のセグメントは次で終了する必要があります。`j - 1`、貢献します`j - i`、2番目は貢献します`best[j]`。 合計は次のようになります`best[j] + j - i`。 固定用`i`、これを有効以上に最大化します`j`の最大値を取ることになります`val[j]`で`(i, r[i]]`、そして減算`i`。 

すべての条件について両方の候補を計算します。`i`グローバル最大値を維持します。 

### なぜ効果があるのか

 重要な構造特性は、すべての有効な部分文字列がその開始位置によって完全に決定され、その使用可能な右境界がその開始位置で単調であることです。 これにより、任意の間隔を考慮する必要がなくなります。すべての最適解は、各部分文字列が完全に最大になるか、他の開始位置で正確に切り詰められた 2 つの開始インデックスを使用して表現できます。 セグメント間の相互作用は単一の境界点でのみ発生するため、2 区間の最適化が事前計算された配列に対する範囲最大クエリに削減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    s = input().strip()
    
    # compute r[i]
    r = [0] * n
    cnt = [0] * 26
    
    j = 0
    for i in range(n):
        while j < n:
            c = ord(s[j]) - 97
            if cnt[c] + 1 > m:
                break
            cnt[c] += 1
            j += 1
        r[i] = j - 1
        
        c = ord(s[i]) - 97
        cnt[c] -= 1
    
    best = [0] * n
    val = [0] * n
    
    for i in range(n):
        best[i] = r[i] - i + 1
        val[i] = best[i] + i
    
    suf_best = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suf_best[i] = max(suf_best[i + 1], best[i])
    
    suf_val = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suf_val[i] = max(suf_val[i + 1], val[i])
    
    ans = 0
    
    for i in range(n):
        # case 1: j > r[i]
        if r[i] + 1 < n:
            ans = max(ans, best[i] + suf_best[r[i] + 1])
        
        # case 2: j in (i, r[i]]
        if i + 1 <= r[i]:
            ans = max(ans, suf_val[i + 1] - i)
    
    print(ans)

t = int(input())
for _ in range(t):
    solve()
```この実装では、まず、シングル パス 2 ポインター展開を使用して、各開始位置の最大有効ウィンドウ終了境界を構築します。 周波数配列により、どの文字も次の値を超えないことが保証されます。`m`窓の中での出来事。 

の`best`配列は、各開始点から許可されたセグメント全体を取得した値をエンコードします。 の`val`配列はこの値をシフトして、2 番目のセグメントの開始インデックスへの依存を吸収します。これにより、重複の場合を単純な範囲最大クエリにすることができます。 

静的な範囲の最大値のみが必要であり、両方のクエリが接尾辞ベースであるため、線形前処理で十分であるため、セグメント ツリーの代わりに接尾辞配列が使用されます。 

最後のループでは、考えられる最初のセグメントの開始をそれぞれ評価し、それを 2 つの構造ケースの下で 2 番目のセグメントの事前計算された最適な選択肢と組み合わせます。

 ## 特殊なケース

 重要なエッジ ケースは、1 つの最大有効セグメントが長すぎるため、2 番目のセグメントが大幅に縮小される場合です。 たとえば、次のような文字列では`aaaaaa`小さいもので`m`の場合、最初のセグメントが文字列の大部分を占める可能性がありますが、最適解では依然として 2 番目のセグメントの小さな末尾が確保されています。 このアルゴリズムは、2 番目のセグメントが最初のセグメントの範囲内で開始するケースを明示的に考慮し、正確な境界分割を強制するため、これを処理します。`j - 1`。 

もう 1 つの微妙なケースは、最適解が最大セグメントをまったく使用しない場合です。 これは、長いセグメントをわずかに短くすると、より大きな 2 番目のセグメントが可能になる場合に発生します。 アルゴリズムのオーバーラップの場合は、考えられるすべての分割点を評価することでこれを正確に捉えます。`j`セグメントの長さを貪欲に固定するのではなく、最大ウィンドウ内で調整します。
