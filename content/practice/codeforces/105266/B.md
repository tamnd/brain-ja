 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースには整数の配列があり、それを任意に並べ替えることができます。 順列を選択した後、順列配列のすべての分割点を調べます。 

インデックス i と i+1 の間のすべての分割位置について、i までのプレフィックスのビット単位の OR と、i+1 から始まるサフィックスのビット単位の OR を計算します。 要件は、これら 2 つの値がすべての可能な分割点で常に等しいことです。 このプロパティを満たす配列の順列の数を数え、998244353 を法とする結果を出力する必要があります。 

この制約では、すべてのテスト ケースにわたって要素の合計数が 200,000 まで許可されるため、すべての順列を試行したり、各順列を明示的にチェックしたりするソリューションは直ちに除外されます。 n = 2e5 の 1 つのテストでも、順列ごとに O(n^2) または O(n log n) を実行することはすでに不可能になっているため、解決策は問題をテスト ケースごとの単純なカウント式、理想的には事前計算を使用した線形または線形算術に縮小する必要があります。 

小さな配列について考えると、微妙な特殊なケースが現れます。 たとえば、n = 2 で配列が [1, 2] の場合、並べ替えはそれ自体または交換だけですが、どの順序でも条件を満たすことができるかどうかは明らかではありません。 素朴な解釈では、多くの有効な置換が示唆されるかもしれませんが、実際には、この条件は非常に制限的であり、特に特定の値の少数の場合には、厳密な構造を強制することがよくあります。 

## アプローチ

 ブルートフォースのアイデアは単純です。配列のすべての順列を生成し、すべてのプレフィックス OR とサフィックス OR を計算し、分割ごとにそれらが一致するかどうかを確認します。 これは正しいですが、実行不可能です。 nを生成中！ 順列は n = 12 ですでに管理不能になり、各チェックのコストは O(n) となり、最適化で取り除くことができない階乗増加につながります。 

重要な観察は、条件を書き換えることから得られます。 すべての分割位置 i について、接頭辞 OR が接尾辞 OR と等しい場合、これらすべての値はすべての i で同一でなければなりません。 配列全体は限定的な意味でプレフィックスまたはサフィックスとしてみなされるため、その共通の値は配列全体の OR に等しくなければなりません。 

このグローバル OR 値を S と呼びます。この条件は、すべての i に対して、プレフィックス a1 | の両方が含まれることを意味します。 ... | ai とサフィックス ai+1 | ... | an はすでに S と等しくなっている必要があります。 

これにより、強力な構造上の制約が生じます。すべてのプレフィックスには、S のすべてのビットがすでに含まれている必要があります。つまり、配列内のどこかに現れるビットを「ミス」するプレフィックスは存在しません。 対称的に、すべての接尾辞には S のすべてのビットも含まれている必要があります。 

次に、これが個々の要素に何を意味するかを考えてみましょう。 最初の要素が S に等しくない場合、1 つの要素の後の接頭辞は何らかのビットを欠落し、既に S に等しくなければならないという要件に矛盾します。したがって、最初の要素は正確に S でなければなりません。接尾辞側からの同じ推論により、最後の要素も S になることが強制されます。 

両端が S 要素として固定されると、残りのすべての要素は新しいビットを導入する必要がなく、S がすでに両端に完全に存在するため条件を破ることができないため、S の任意のサブセットにすることができます。 

これにより、問題は純粋な組み合わせ論のタスクに還元されます。S に等しい要素が k 個ある場合、これらの S 要素が占める 2 つの異なる位置 (最初と最後) を選択し、残りの n−2 要素を自由に並べ替える必要があります。 

k < 2 の場合、n ≥ 2 に対して有効な順列は存在しません。それ以外の場合、ウェイの数は、順序付けされたエンドポイントの k × (k − 1) 個の選択肢に (n − 2) を乗算したものになります。 残りを整理するため。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n) | O(n) | 遅すぎる |
 | 最適 | 前処理後のテストあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 配列全体のビット単位の OR を計算し、これを S と呼びます。この値は、すべてのプレフィックスとサフィックスの OR が一致する必要がある唯一の可能な値を表します。これは、すべての場所で等しいように制約されているためです。 
2. 配列内の S に等しい要素の数を数えます。この数を k と呼びます。 これらは、すべてのビットを完全にカバーする位置を占めることができる唯一の候補です。 
3. k が 2 未満の場合は、すぐに 0 を返します。全論理和要素が 2 つ未満の場合、最初と最後の位置の両方に S のすべてのビットがすでに含まれている必要があるという要件を満たすことができません。 
4. すべてのテスト ケースで、998244353 を法とする最大可能 n までの階乗を事前計算します。これにより、残りの要素の順列を高速に計算できます。 
5. 各テスト ケースについて、k × (k − 1) × (n − 2) として答えを計算します。 モジュロ 998244353。 
6. 結果を出力します。 

エンドポイントのみを修正する背後にある理由は、最初の要素がすでにすべての欠落ビットに寄与しているため、両端が S になると、すべてのプレフィックスに自動的に S が含まれるからです。 同様に、最後の要素がすでにすべてのビットに寄与しているため、すべてのサフィックスには S が含まれます。 内部順序は OR プロパティに影響しなくなりました。 

### なぜ効果があるのか

 不変条件は、すべての有効な置換が、すべてのプレフィックス OR とすべてのサフィックス OR がグローバル OR S に等しいというプロパティを維持する必要があるということです。これにより、最初の要素が既に S を完全に実現することが強制されます。そうでない場合、最初のプレフィックスは S より小さくなります。同じロジックが最後の要素に対称的に適用されます。 

両方のエンドポイントが S に等しい要素に固定されると、残りの要素はすべて OR 制約とは無関係になります。これは、S を超える新しいビットを導入したり、既存のビットを削除したりできないためです。 したがって、問題は完全に、制約されたエンドポイントでの順列をカウントすることに帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    tests = []
    maxn = 0

    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        tests.append((n, arr))
        maxn = max(maxn, n)

    fact = [1] * (maxn + 1)
    for i in range(1, maxn + 1):
        fact[i] = fact[i - 1] * i % MOD

    out = []

    for n, arr in tests:
        S = 0
        for x in arr:
            S |= x

        k = 0
        for x in arr:
            if x == S:
                k += 1

        if k < 2:
            out.append("0")
            continue

        ans = k * (k - 1) % MOD
        if n >= 2:
            ans = ans * fact[n - 2] % MOD

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、最初にすべてのテスト ケースを集約して階乗を 1 回構築するため、テストごとに O(n) 回の前処理を繰り返す必要がなくなります。 次に、各テストでグローバル OR が計算され、それを達成する要素の数がカウントされます。 最終的な式は直接適用されます。 

よくある間違いは、エンドポイントがセットとして選択されているだけではなく、順序付けされていることを忘れていることです。 結合項の代わりに k × (k − 1) が登場するのはそのためです。 

## 実用的な例

 配列 [1, 2, 3] について考えてみましょう。 グローバル OR は 3 であるため、3 に等しい要素のみがエンドポイントに関係します。 このような要素が 1 つあるため、k = 1 となり、答えはすぐに 0 になります。 

| ステップ | 値 |
 | --- | --- |
 | S | 3 |
 | k | 1 |
 | 有効な順列 | 0 |

 これは、配列内に 3 が現れる可能性があるとしても、単一の出現では両端を制御するという要件を満たすことができないことを示しています。 

次に [3, 3, 1] を考えてみましょう。 グローバル OR は 3、k = 2 です。 

| ステップ | 値 |
 | --- | --- |
 | S | 3 |
 | k | 2 |
 | 最後の選択肢 | 2×1 |
 | 中間の順列 | 1! |
 | 最終的な答え | 2 |

 これは、エンドポイントが固定されると、有効性に影響を与えることなく残りの要素を自由に配置できることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テストごとに O(n)、全体で O(合計 n) | 各テストは OR を計算し、一致を 1 回カウントします。 
| スペース | O(最大n) | 事前計算用の階乗配列 |

 すべてのテスト ケースにわたる要素の合計数は 2 × 10^5 で制限されており、すべての演算は単純な算術で線形であるため、ソリューションは制限内に問題なく収まります。 

## テストケース```python
import sys, io

MOD = 998244353

def solve_io(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    tests = []
    maxn = 0
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        tests.append((n, arr))
        maxn = max(maxn, n)

    fact = [1] * (maxn + 1)
    for i in range(1, maxn + 1):
        fact[i] = fact[i - 1] * i % MOD

    res = []
    for n, arr in tests:
        S = 0
        for x in arr:
            S |= x
        k = sum(1 for x in arr if x == S)

        if k < 2:
            res.append("0")
        else:
            ans = k * (k - 1) % MOD
            ans = ans * fact[n - 2] % MOD
            res.append(str(ans))

    return "\n".join(res)

# provided-style sanity checks
assert solve_io("1\n2\n1 2\n") == "0"
assert solve_io("1\n2\n3 3\n") == "2"

# custom cases
assert solve_io("1\n3\n1 1 1\n") == str(3 * 2 % MOD * 1 % MOD), "all equal"
assert solve_io("1\n3\n1 2 4\n") == "0", "no full-or duplicates"
assert solve_io("1\n4\n7 1 7 7\n") == str(3 * 2 % MOD * 2 % MOD), "multiple S elements"
assert solve_io("2\n2\n1 1\n2\n1 2\n") == "2\n0", "multi-test mix"

 | すべて等しい配列 | ん！ エンドポイント ルールによるバリアント | すべての要素が S | の場合の正しさ
 | S | の重複はありません 0 | k < 2 | の場合は不可能
 | 混合カウント | k*(k-1)*(n-2)! | 複数の S 要素の処理 |
 | マルチテストミックス | 行ごとの正確性 | バッチ処理の安定性 |

 ## 特殊なケース

 すべての要素が同一の場合、すべての要素はグローバル OR S に等しいため、k = n となります。 式は n × (n − 1) × (n − 2)! となり、これは n! に簡略化され、すべての置換が分割ごとに同一の OR 値を自明に保持するという事実と一致します。 

グローバル OR に等しい要素が 1 つだけ存在する場合、アルゴリズムは正しく 0 を返します。内部要素は柔軟に見えても、エンドポイントの要件を満たすことはできず、式はこの失敗を即座に正しく捕捉します。 

複数の要素が S に等しいが、n が大きい場合、階乗項が優先されます。 実現可能性に影響を与えるのはエンドポイントの選択だけであり、内部の置換は完全に制限されていないため、アルゴリズムは引き続き正しく動作します。
