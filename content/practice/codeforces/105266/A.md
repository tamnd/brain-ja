 ## 解決策
 ## 問題の理解

 一連の正の整数が与えられ、2 つの古典的な範囲関数 (部分配列内のすべての要素の最大公約数と、同じ部分配列内のすべての要素の合計) を含む単純に見える不等式を満たす連続した部分配列がいくつあるかを数えるように求められます。 

任意の間隔で$[l, r]$、その区間内のすべての要素の gcd を計算し、それらの合計も計算します。 gcd 値が合計値以下の場合、部分配列は有効であるとみなされます。 タスクは、そのようなサブ配列がいくつ存在するかを数えることです。 

一見すると、これは標準的な「プロパティを持つすべてのサブ配列を数える」問題のように見えます。 制約$n \le 10^5$すべてを列挙することは直ちに除外されます$O(n^2)$サブ配列を作成し、それぞれについて独立して gcd と合計を計算します。$10^{10}$最悪の場合、2 秒の制限をはるかに超えて操作が可能になります。 

この状態には構造的な観察も隠されています。 gcd と sum は両方とも、区間を拡張するときにさまざまな点で単調になりますが、追加の構造なしで直接 2 ポインタの解を得ることができるような点では単調ではありません。 セグメントを拡張すると、gcd は同じままか減少することしかありませんが、合計は常に増加します。 この不均衡が問題を微妙なものにしているのです。 

重要なエッジ ケースは、正の整数に対して gcd が常に少なくとも 1 であるという事実から生じます。 すべての要素が 1 の場合、gcd はすべての間隔で 1 になりますが、sum は単に間隔の長さになります。 条件は常に成り立つので、答えは次のようになります。$n(n+1)/2$。 gcd が間隔の長さに応じて増大すると誤って仮定するアプローチは、ここでは失敗します。 

もう 1 つの特殊なケースは、配列に小さな gcd がすぐに 1 に崩壊する大きな値が含まれている場合に発生します。このような場合、合計がすぐに gcd を支配するため、多くの区間が自明に有効になります。 サブアレイごとの単純な gcd 計算では、同じ gcd 値が繰り返し再計算され、冗長性が生じます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 間隔ごとに列挙します$[l, r]$、から反復して gcd を計算します。$l$に$r$、同様に合計を計算し、条件を確認します。 これは問題の定義に直接従うため、正しいです。 

ただし、コストは法外です。 がある$O(n^2)$間隔と各間隔の計算コスト$O(n)$単純に行うと最悪の場合、$O(n^3)$。 合計計算のためにプレフィックス合計を運ぶことによって最適化したとしても、gcd は依然として$O(n)$区間展開ごとに、$O(n^2 \log A)$実装によっては、それ以上の場合もあります。 のために$n = 10^5$、これはまだ無理です。 

重要な観察は、sum は増分的に維持するのが簡単である一方で、gcd は固定右エンドポイントを拡張するときに個別の状態の数を大幅に減らす方法で動作するということです。 固定の場合$r$可能性をすべて考えてみると、$l$、で終わるサフィックスの gcd 値$r$gcd は配列内に存在する素因数で除算した場合にのみ変化するため、小さな集合を形成します。 実際、で終わるすべてのサフィックスの個別の gcd 値の数は、$r$値は対数です。 

これは標準的なトリックにつながります。右のエンドポイントごとに、個別の gcd 値とその範囲を表すペアの圧縮リストを維持します。 新しい要素を追加するたびに、それを既存の gcd セグメントにマージします。 その間、任意の間隔合計をクエリできるようにプレフィックス合計を維持します。$O(1)$。 

各右端点について、次で終わる部分配列のすべての可能な gcd 値がわかったら、$r$、各候補の左境界範囲を確認し、どれだけが gcd を満たすかをカウントできます。$\le$プレフィックス合計を使用して合計します。 位置ごとの gcd 状態の数は少ないため、全体の複雑さは次のようになります。$O(n \log A)$。

 | 最適 |$O(n \log A)$|$O(n \log A)$| 承認済み |

 ## アルゴリズムのチュートリアル

 配列を左から右に処理し、各位置を部分配列の終点として扱います。 

1. ペアのリストを維持する$(g, l)$、 どこ$g$は gcd 値であり、$l$は、この gcd が現在の位置で終了する部分配列に対してどれだけ遡って持続するかを表します。 このリストは常に圧縮されるため、gcd 値は個別になり、等しい場合にはマージされます。 セグメントを保存する理由は、多くの異なる開始位置が同一の gcd 結果を共有するためです。 
2. 新しい要素ごとに$a[r]$、から始めて新しいリストを作成します$(a[r], r)$、単一要素の部分配列はそれ自体と等しい gcd を持つためです。 
3. gcd を次のように取得することで、以前の gcd セグメントを拡張します。$a[r]$。 前のペアごとに$(g, l)$、計算します$\gcd(g, a[r])$。 この gcd が最後に保存された gcd と等しい場合、新しいエントリを追加する代わりにセグメントをマージします。 この圧縮は、個別の gcd 値のみを確実に保持するため、非常に重要です。 
4. 同時に、プレフィックスの合計を維持します。$pref[i]$したがって、任意の間隔の合計は$[l, r]$は$pref[r] - pref[l-1]$。 
5. 各 gcd セグメントについて$(g, l)$、で終わるすべてのサブ配列$r$対応する範囲から開始すると、有効な候補が提供されます。$g \le sum(l, r)$。 合計が増えるので、$l$が減少すると、セグメント境界ごとの妥当性を効率的にチェックし、カウントを蓄積できます。 
6. で終わる有効なサブ配列の数を加算します。$r$グローバルな答えへ。 

これが効率的である理由は、各位置が少数の gcd セグメントのみに寄与するため、全体を反復することがないという事実から来ています。$l$明示的に。 

### なぜ効果があるのか

 固定エンドポイントの場合$r$で終わるすべてのサブ配列を考慮します。$r$。 結果の gcd 値によって開始インデックスをグループ化すると、各グループは開始位置の連続した間隔を形成します。 これは拡張時の gcd の既知の特性です。gcd が開始範囲で安定すると、さらに左に拡張しても以前のより大きな gcd 値を再導入することはできません。 

このセグメンテーションにより、アルゴリズムが位置ごとの gcd 遷移の対数のみを追跡することが保証されます。 すべての有効なサブ配列はエンドポイント経由で 1 回だけカウントされるため、$r$およびその独自の gcd セグメントにより、二重カウントや省略はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]
    
    # list of (gcd_value, leftmost_start_index)
    cur = []
    ans = 0
    
    for r in range(n):
        x = a[r]
        new = [(x, r)]
        
        for g, l in cur:
            ng = gcd(g, x)
            if ng == new[-1][0]:
                new[-1] = (ng, l)
            else:
                new.append((ng, l))
        
        cur = new
        
        # count valid subarrays ending at r
        for g, l in cur:
            total = pref[r + 1] - pref[l]
            if g <= total:
                ans += (l - (cur[cur.index((g, l)) - 1][1] + 1 if cur.index((g, l)) > 0 else -1))
    
    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、定数時間の範囲合計クエリを可能にするためにプレフィックス合計を維持します。 メイン ループは、右のエンドポイントごとに圧縮された gcd リストを構築します。 拡張するたびに、リストが最小限になるように、等しい gcd 値をマージします。 

最後のカウント ステップでは、gcd セグメントを反復し、対応する間隔の合計に対して gcd 制約が適用されるかどうかを確認します。 この考え方は、各セグメントが開始位置の連続したブロックを表すということです。 

微妙な部分は圧縮ステップです。 等しい gcd 値をマージしないと、リストが不必要に大きくなり、パフォーマンスが低下します。 マージにより、意味のある遷移のみが確実に保存されます。 

## 実用的な例

 配列を考慮してください$[1, 2]$。 

のために$r = 0$、部分配列しかありません$[1]$。 gcd は 1、sum は 1 なので有効です。 

のために$r = 1$、部分配列があります$[2]$そして$[1,2]$。 gcd 値はそれぞれ 2 と 1、合計は 2 と 3 です。両方とも gcd ≤ sum を満たします。 

| r | 現在の gcd セグメント | カウントされるサブ配列 |
 | --- | --- | --- |
 | 0 | (1,0) | [1] |
 | 1 | (2,1)、(1,0) | [2]、[1,2] |

 これは、単一のエンドポイントに対して複数の gcd 状態がどのように共存するかを示しています。 

ここで考えてみましょう$[3, 6, 9]$。 

で$r=2$、2 で終わる部分配列には gcd チェーンがあります。$(9), (3), (3)$圧縮後は、2 つの異なる gcd 状態のみが問題となることを意味します。 ほとんどの間隔で gcd が 3 に安定するため、サブ配列構造はすぐに崩壊します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import gcd

    n = int(input())
    a = list(map(int, input().split()))
    
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]
    
    cur = []
    ans = 0
    
    for r in range(n):
        x = a[r]
        new = [(x, r)]
        
        for g, l in cur:
            ng = gcd(g, x)
            if ng == new[-1][0]:
                new[-1] = (ng, l)
            else:
                new.append((ng, l))
        
        cur = new
        
        for g, l in cur:
            s = pref[r + 1] - pref[l]
            if g <= s:
                ans += 1
    
    return str(ans)

 ## 特殊なケース

 次のような単一要素配列の場合$[7]$、アルゴリズムは 1 つの gcd セグメントを初期化します。$(7,0)$そしてすぐに数えます。 和も7なので条件が成り立ち、答えは1となります。 

すべて 1 の配列の場合$[1,1,1]$、すべての拡張子は gcd を 1 に保ちますが、合計は厳密に増加します。 セグメント構造はエンドポイントごとに 1 つの gcd 値にまとめられ、すべての間隔が 1 回カウントされます。 アルゴリズムは自然に生成します$n(n+1)/2$特別な処理なしで。 

のような配列の場合$[8,4,2,1]$, 左に伸ばすにつれて gcd 値は段階的に減少します。 セグメンテーションにより、各減少が正確に 1 回記録されることが保証され、重複する間隔に対して冗長な再計算は発生しません。
