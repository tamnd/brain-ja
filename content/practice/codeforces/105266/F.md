 ## 解決策
 ## 問題の理解

 5 つの固定された役割があり、正確に 5 人の異なるプレーヤーがそれらを果たさなければなりません。 各プレーヤーには、長さ 5 のバイナリ文字列としてエンコードされた制約が付属しています。`1`プレイヤーが対応する役割を演じることができることを示します。 有効なラインナップとは、割り当てられたすべてのプレーヤーがその役割に適格であるように、5 つの役割と 5 人の異なるプレーヤーの間で 1 対 1 で割り当てられるものです。 

このタスクは、プールから 5 人の異なる選手の可能なすべての選択を引き継ぎ、それらを 5 つのポジションに割り当てるための有効なすべての方法を対象として、有効な割り当てがいくつ存在するかを数えることです。 少なくとも 1 つの役割を別のプレーヤーが担当している場合、2 つのラインナップは異なるものとみなされます。 

入力サイズは最大 20 万プレーヤーに達します。 各プレーヤーは、能力の 5 ビット マスクを提供します。 単純な解釈では、任意の 5 人のプレイヤーを選択し、すべての順列をチェックすることがすぐに示唆されます。これは、列挙で処理できる範囲をはるかに超えた組み合わせの爆発をすでに示しています。 n が 2×10^5 までの場合、1 秒の制限の下では O(n^5) または O(n^3 · 5!) に近いものは実行不可能です。 O(n^2) でさえ境界線にありますが、非常に小さな定数でのみ許容される可能性があるため、解決策はプレイヤーの任意のサブセット間のペアごとの相互作用を回避する必要があります。 

複数のプレーヤーが同一の能力パターンを共有する場合、単純な推論による微妙な失敗例が現れます。 たとえば、10 人のプレーヤー全員がすべての役割をプレイできる場合、有効なラインナップの数は単に「5 人のプレーヤーを選択する」ではなく、「5 つの順序付けされた割り当てを選択する」ことになり、役割の割り当ての順列を無視した単純なカウントは、対称性の処理方法に応じて過小カウントまたは過大カウントになります。 もう 1 つの落とし穴は、プレイヤーをマスクだけで交換可能であるかのように扱うことです。これにより、別々の選択に貢献しているにもかかわらず、別々の個人が誤って統合されてしまいます。 

## アプローチ

 直接的な総当たりアプローチでは、5 人のプレイヤーのすべてのサブセットを列挙し、妥当性をチェックしながら 5 つの役割にわたってそれらを並べ替えようとします。 選択したセットごとに最大 5 つあります。 割り当て、有効性のチェックは割り当てごとに一定の時間かかります。 部分集合だけの数は、$\binom{n}{5}$、これは n^5 / 120 のオーダーで増加し、n が 2×10^5 のときすでに 10^25 を超えています。 たとえ何らかの方法で小さなサブセットに限定したとしても、組み合わせ構造は明示的に調査するには大きすぎるままです。 

重要な観察は、問題の規模が実際にはプレイヤーの数ではなく、役割の数によって制御されるということです。 ポジションは 5 つしかないため、部分的な割り当てを表す状態は、どの役割がすでに満たされているかによってのみ決まります。 これは、プレーヤーを 1 人ずつ処理し、満たされた役割の各サブセットを達成できる方法の数を維持する動的プログラミングの定式化を示唆しています。 

各プレイヤーは無視することも、彼らが果たせるまだ空の役割の 1 つを正確にこなすために使用することもできます。 ロールが 5 つしかないため、状態空間はわずか 2^5 = 32 となり、すべての構成を効率的に追跡することが可能になります。 各プレーヤーを処理すると、これらの 32 の状態が更新され、合計の複雑さは n で線形になります。 

ブルートフォース手法は、すべての制約を明示的に尊重するため概念的には機能しますが、同等の部分割り当てを繰り返し再計算するため失敗します。 すでに満たされたロールのセットのみが重要であるという観察により、n への指数関数的な依存がロールのサブセットにわたる一定サイズの状態マシンに崩壊します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^5・5!) | お(1) | 遅すぎる |
 | プレーヤー上のビットマスク DP | O(n · 2^5 · 5) | O(2^5) | 承認済み |

 ## アルゴリズムのチュートリアル

 どの選手を使用するか、そして彼らが 5 つの役割を果たすのにどのように貢献するかを徐々に決定するというプロセスをモデル化します。 

1. dp[mask] がビットマスクに対応する役割を割り当てる方法の数を表す DP 配列を定義します。`mask`プレーヤーのプレフィックスを使用します。 マスクの各ビットは、すでに満たされている 1 つの役割に対応します。 これにより、すべての部分的な有効な割り当てがコンパクトにキャプチャされます。 
2. dp[0] = 1 を初期化します。これは、ロールに何も割り当てない方法が 1 つだけあるためです。 
3. 各プレーヤーを入力順に繰り返します。 各プレーヤーに対して、最初は dp に等しい新しい DP 配列 ndp を構築し、このプレーヤーをスキップするという選択を表します。 
4. 現在の状態マスクごとに、マスクがまだ埋められておらず、プレーヤーの能力文字列に`1`。 このようなロールごとに、 dp[mask] を追加して ndp[mask ∪ {j}] を更新します。 これは、このプレーヤーを使用して部分的な割り当てを延長することを表します。 
5. プレーヤーを処理した後、dp を ndp に置き換えます。 これにより、各プレーヤーが最大 1 回使用され、1 回だけ考慮されることが保証されます。 
6. すべてのプレイヤーを処理すると、答えは dp[(1<<5) - 1] となり、5 つの役割すべてが満たされたことを表します。 

正確さは、すべての有効な割り当てが、それが構築されたプレーヤーの処理順序内で一意の「最後の出現」を持っているという事実に基づいています。 プレーヤー シーケンスを前に進むだけで、プレーヤーを再利用しないため、各割り当ては 1 回だけカウントされます。 

維持される不変条件は、最初の i 人のプレーヤーを処理した後、dp[mask] がそれらの i 人のプレーヤーのサブセットを選択し、互換性を考慮してマスク内の役割に正確に割り当てる方法の数に等しいということです。 各トランジションはサブセットを保持するか (スキップ)、現在のプレーヤーを新しいロールに割り当てることでサブセットを拡張しますが、一意性や互換性の制約に違反することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def main():
    n = int(input())
    can = [input().strip() for _ in range(n)]

    dp = [0] * 32
    dp[0] = 1

    for i in range(n):
        ndp = dp[:]  # skipping player i
        mask_allowed = 0

        for j in range(5):
            if can[i][j] == '1':
                mask_allowed |= (1 << j)

        for mask in range(32):
            if dp[mask] == 0:
                continue
            base = dp[mask]
            # try assign this player to each available role
            avail = mask_allowed & (~mask)
            sub = avail
            while sub:
                bit = sub & -sub
                ndp[mask | bit] = (ndp[mask | bit] + base) % MOD
                sub -= bit

        dp = ndp

    print(dp[31] % MOD)

if __name__ == "__main__":
    main()
```この実装では、5 つの役割のすべてのサブセットに対応する 32 要素の DP 配列が保持されます。 各プレイヤーについて、彼らが果たせる役割のビットマスクを計算します。 移行では、現在のマスクでまだ使用されていないロールにのみプレーヤーが割り当てられるように慎重に行います。 

マスク サイズが 5 に固定されているため、使用可能なロールのサブマスクに対する内部ループは安全です。そのため、サブセットに対する反復処理は実際には一定時間です。 モジュロは、オーバーフローを防ぐために遷移中に適用されます。 

微妙な点はコピーの使用です。`ndp = dp[:]`。 これは、1 人のプレイヤーが同じ反復内で複数回貢献できることを避けるために不可欠です。 この分離がないと、同じプレーヤーの処理内で更新が誤って連鎖してしまいます。

トレースは、プレーヤーが処理されるたびに、すべての役割が満たされるまで、既存のすべての部分割り当てが 5 つの可能な拡張に分岐することを示しています。 

## 複雑さの分析

 | --- | --- | --- |

| スペース | O(2^5) | 役割サブセット上の DP 配列のみが保存されます。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MOD = 10**9 + 7

    n = int(input())
    can = [input().strip() for _ in range(n)]

    dp = [0] * 32
    dp[0] = 1

    for i in range(n):
        ndp = dp[:]
        mask_allowed = 0
        for j in range(5):
            if can[i][j] == '1':
                mask_allowed |= (1 << j)

        for mask in range(32):
            if dp[mask] == 0:
                continue
            avail = mask_allowed & (~mask)
            sub = avail
            while sub:
                bit = sub & -sub
                ndp[mask | bit] = (ndp[mask | bit] + dp[mask]) % MOD
                sub -= bit

        dp = ndp

    return str(dp[31] % MOD)

assert run("5\n11111\n11111\n11111\n11111\n11111\n") == "120", "all flexible"

# minimal structured case
assert run("5\n10000\n01000\n00100\n00010\n00001\n") == "1", "fixed matching"

# mixed constraints

 ## 特殊なケース

 重大なエッジケースは、どのプレイヤーも特定の役割を果たせない場合です。 たとえば、すべての文字列に`0`3 番目の位置では、そのロールを含めようとするすべての DP 状態は到達不可能なままとなり、dp[11111] が形成されないため、最終的な答えは正しく 0 のままになります。 

多くのプレイヤーが同じ能力マスクを共有する場合、別のケースが発生します。 アルゴリズムはそれらを折りたたむことはありません。 それぞれが独立して順番に処理されます。 これにより、たとえトランジションが同一であっても、dp は別個の処理ステップを通じて進化するため、同一のプレーヤーの異なるサブセットの選択が依然として個別にカウントされることが保証されます。 

最後の微妙なケースは、プレイヤーが複数の役割を果たすことができる場合です。 サブマスクの反復により、単一の反復内で割り当てを混合することなく、同じプレーヤーが DP 状態ごとに 1 回だけ、すべての有効なロールの選択に貢献することが保証されます。
