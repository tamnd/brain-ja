 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 いずれの場合も、重りには数種類があり、それぞれの種類に制限はありません。 ただし、その使用方法には制限があります。選択したすべての分銅は天秤の同じ側に配置する必要があります。 これらの重みをいくつか選択して、1 から m までのすべての整数の重みを表現できるようにしたいと考えています。つまり、その範囲内の各ターゲット値 x について、合計が正確に x になる利用可能な重みの複数セットを選択できなければなりません。 

目標は、表現可能な範囲を最大化することではなく、できる限り少ない個々の重み部分を使用しながら、間隔 [1, m] を完全にカバーすることです。この場合、型は再利用できますが、選択された各コピーは、使用される部分の合計数にカウントされます。 

重要な点は、入力によって個々の部分ではなく重みの種類が与えられることです。 各ウェイト タイプのコピー数を効果的に選択し、それらのコピーが使用可能なセットになります。 問題は、選択したコピーを無制限に繰り返して 1 から m までのすべての合計が達成できるような、合計コピーの最小数はいくらかということです。 

制約は全体として大きく、最大 50 のテスト ケース、ケースごとに最大 10,000 の重みタイプ、m は 1e9 に達する可能性があります。 サブセットの合計を m まで直接シミュレートしようとする解決策は、テスト ケースあたり O(m) でさえすでに制限を超えており、O(n·m) はまったく実行不可能であるため、不可能です。 

素朴な間違いは、表現可能な間隔を追跡せずに重みを貪欲に選択できると想定することです。 たとえば、m = 4 のときに重み 2 と 3 を選択すると、なんとかすべてをカバーできると思うかもしれませんが、1 にはすぐに到達できなくなります。 これは、表現可能性が 1 から始まる連続範囲を構築できるかどうかに大きく依存していることを示しています。 

もう 1 つのよくある失敗例は、ギャップを無視することです。 重み {1, 3} を選択するとします。 1 と 3 は形成できますが、2 が欠けています。その後、1 と 3 の加算だけではギャップを埋めることができないため、システムは完全に機能しません。正しい戦略では、表現可能な範囲が連続したままであることが保証されなければなりません。 

## アプローチ

 この強引なアイデアは、取得する可能性のあるウェイト コピーのすべてのサブセットを検討し、それらの選択されたウェイトを無制限に使用して、最大 m までのすべての可能な合計をシミュレートすることです。 最大 k 個のコピーを選択するように制限したとしても、それらを選択する方法の数は n 個の組み合わせであり、各選択には最大 m のナップザック スタイルの DP が必要です。 これはすぐに爆発します。1e9 までの単一の DP ですら不可能であり、サブセットの列挙は指数関数的に悪化します。 

重要な観察は、すでに形成できる現在の連続プレフィックスを超える個々の合計を実際には気にしていないということです。 [1, R] のすべての値を形成できることがすでにわかっている場合、新しい重み w は非常に構造化された方法で動作します。これを使用すると、w が最大 R + 1 である場合に限り、適用範囲を [1, R + w] に拡張できます。そうでない場合は、R + 1 にギャップが発生し、後から修正することはできません。 

これは、最小限の要素で到達可能な金額を構築することを彷彿とさせる貪欲な構築につながります。 重みを昇順に処理し、最大の連続表現可能なプレフィックス R を維持します。表現可能なものがないため、最初は R = 0 です。 重み w を取得することを決定するたびに、そのコピーを 1 つ使用します。これにより、w が現在の制約下で使用可能であれば、範囲を R + w まで拡張できます。 最小の残りの重みが R + 1 より大きい場合、1..m を完了できないと結論せざるを得ません。 

選択するピースの数を最小限に抑えるには、常に範囲を拡張するために利用可能な最小のウェイトを選択する必要があります。これは、ウェイトが大きいほど、アイテムごとに多くの「電力」を消費し、小さなギャップを埋めるのに役立たないためです。

 ## アルゴリズムのチュートリアル

 常に小さい値が最初に考慮されるように重みを並べ替えます。 

1. 現在形成できる最大連続和を表す変数 R = 0 を初期化します。 また、インデックス i = 0 とカウンタ ans = 0 を初期化します。 
2. R < m の間、範囲を拡張しようとします。 未使用の最小の重み w = a[i] を調べます。 
3. そのような重みが存在しない場合、または w > R + 1 の場合は、すぐに停止して -1 を返します。 これは、R + 1 を形成できないため、範囲が永久に切断されてしまうためです。 
4. それ以外の場合は、この重みを 1 回取得し、ans を 1 ずつ増分し、R = R + w を更新します。 次に、i を先に進めます。 
5. R >= m になるまで繰り返します。この時点で、ans は必要なウェイト コピーの最小数になります。 

重要な設計上の選択は、到達可能な間隔を延長できる最小限の重量を常に消費することです。 大きな重みは、小さな欠損値を埋めるのに役立ちず、プレフィックスがすでに大きくなってからでなければ役に立たないため、初期段階では大きな重みを使用することは決して良いことではありません。 

### なぜ効果があるのか

 いつでも、[1, R] ですべての整数を表現できると仮定します。 新たに選択した重み w は、R + 1 を超えない場合にのみ意味のある寄与をすることができます。それ以外の場合は、既存の重みを w とどのように組み合わせても R + 1 に到達できないためです。 w ≤ R + 1 の場合、w のコピーを 1 つ追加すると、到達可能な区間が [1, R + w] まで拡張されます。これは、R までのすべての値を形成し、その後 w だけシフトして次のセグメントを連続的に埋めることができるためです。 この不変式により、R は選択されたマルチセットで達成可能な最大の連続プレフィックスを常に表すことが保証され、貪欲な選択により、後でギャップを埋めるために重要になる可能性があるときに小さな重みを無駄にしないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []
    for _ in range(T):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        R = 0
        i = 0
        ans = 0

        while R < m:
            if i == n or a[i] > R + 1:
                out.append("-1")
                break
            R += a[i]
            ans += 1
            i += 1
        else:
            out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは貪欲な構造を直接反映しています。 並べ替えると、常に最小の候補が最初に表示されます。 変数`R`到達可能なプレフィックスを追跡し、ループ不変条件により、すべての値が`[1, R]`現在選択されている重みで達成可能です。 条件`a[i] > R + 1`は、ギャップが生じる正確な故障点です。`R + 1`避けられなくなる。 

微妙なディテールは、`while-else`この構造は、成功した完了 (R が m に達する) と早期終了を明確に区別します。

 ## 特殊なケース

 重要なエッジ ケースは、利用可能な最小の重みが 1 より大きい場合です。たとえば、入力が 2 で始まる場合、1 を形成できないため、すぐに失敗し、したがって連続した間隔を開始することはできません。 アルゴリズムは初期化時にこれを検出します。R = 0 であるため、重み ≤ 1 が必要ですが、2 はこれに違反します。 

もう 1 つのケースは、[1, 100, 101] のように、重みが急激に増加する場合です。 1 を取得した後は、R = 1 になりますが、次に使用可能な重みは ≤ 2 でなければなりません。100 は大きすぎるため、すぐに終了します。 このアルゴリズムは、後で補正しようとするのではなく、早期に正しく拒否します。 

最後の微妙なケースは、非常に大きな重みがソートされたリストの最初に現れるが、より小さな重みが後に存在する場合です。 並べ替えにより、ここでの誤った決定が防止され、大きなジャンプの前に小さなブリッジ重みが常に考慮されることが保証されます。
