 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられています。 配列から始めます`a`、オプションで単一の連続セグメントを選択し、それを反転することができます。 この操作を最大 1 回実行した後、結果の配列を固定配列と比較します。`b`同じ長さの。 

構成のコストは、2 つの配列の整列された要素間のビットごとの XOR のすべてのインデックスの合計として定義されます。 セグメントを反転する`a`のどの要素を変更するか`a`のどの要素とペアになっているか`b`したがって、操作はローカルではありません。1 回の反転で、構造化された方法で多くのペアが同時に再シャッフルされます。 

タスクは、反転する最適なセグメントを選択した後、または何も反転しないことを選択した後、最小の XOR 合計合計を見つけることです。 

制約`n ≤ 5000`すべてのセグメントを試して全コストを最初から再計算するソリューションはすぐに除外します。`O(n^3)`最悪の場合の運用。 平`O(n^2)`ソリューションを 2 秒で快適に完了するには、慎重な増分更新が必要です。 

欲張って考えると微妙な問題が見えてきます。 XOR は順序を保持しないため、セグメントを反転していくつかの順位を局所的に改善すると、他の多くの順位が目に見えない形で悪化する可能性があります。 たとえば、境界付近の大きな不一致を修正するセグメントを反転すると、セグメント内のすでに良好な一致がいくつか崩れる可能性があります。 この相互依存こそが、貪欲な選択を妨げるものなのです。 

## アプローチ

 逆演算を無視すれば、問題は簡単です。`sum(a[i] XOR b[i])`。 難しいのは、セグメントを反転したときにこの合計がどのように変化するかを理解することです`[l, r]`。 

ブルートフォースアプローチでは、考えられるすべてのセグメントが試行されます。 それぞれについて`(l, r)`、逆転をシミュレートします`a[l..r]`そして完全な XOR 合計を再計算します。 ゼロから再計算するコスト`O(n)`セグメントごとに、`O(n^2)`セグメントにつながる`O(n^3)`トータルオペレーション。 と`n = 5000`、これは実現不可能です。 

反転がペアリングにどのような影響を与えるかを観察することで、再計算コストを削減できます。 反転セグメント内でインデックスを作成します`i`パートナーを交換する`b[i]`に`b[l + r - i]`ペアリング構造の観点から。 したがって、内側のポジションのみ`[l, r]`外部のすべては変更されないまま、貢献を変更します。 これにより、セグメントごとの再計算が次のように削減されます。`O(n)`まだですが、セグメントの貢献度の迅速な評価に焦点を当てる必要があることを示唆しています。 

重要な洞察は、完全な配列の観点から考えるのをやめ、代わりにペア構造の観点から考えることです。 反転するたびに、次のインデックス間の新しい一致が定義されます。`a`そして`b`。 セグメント外のインデックスの場合、ペアリングは変更されません。 セグメント内では、対称的な位置をペアにしています`(i, l + r - i)`。 これにより、問題はセグメントの選択と、構造化されたペアのコストの評価に変わります。 

ここで重要な観察は、反転セグメント内の対称位置によって形成されるペアの寄与と、変化しない外部コストを計算するだけでよいということです。 これにより、ベースラインコストを事前計算し、各セグメントを評価することができます。`O(r - l)`または償却された`O(1)`セグメントを注意深く拡張すると、トランジションごとに更新されます。 

すべての中心を反復処理し、ペアリングの効果を維持しながら外側に拡張します。`(l, r)`私たちが成長するにつれて。 各拡張では、2 つの元のペアを 2 つの新しいペアに置き換えることによってコストが更新され、定数時間で計算できます。 

これにより、ソリューションは次のように変換されます。`O(n^2)`拡張プロセスではなく、`O(n^3)`再計算。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (セグメントごとの合計を再計算) | O(n^3) | お(1) | 遅すぎる |
 | 増分 XOR 更新で間隔を拡張 | O(n^2) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 反転が適用されないベースラインから開始します。 初期費用は以下の合計となります`a[i] XOR b[i]`。 

1. それぞれをペアにしてベースラインコストを計算します。`a[i]`と`b[i]`。 これは何も操作を行わない場合を表します。 
2. 考えられるすべての反転中心を検討します。 各インデックスをセグメントの潜在的な中間として扱い、2 つの方法で外側に拡張します。1 つは奇数長のセグメントの場合、もう 1 つは偶数長のセグメントの場合です。 
3. 拡張ステップごとに、現在のセグメントを維持します。`[l, r]`。 最初は`l = r = i`奇数長の場合、または`l = i`、`r = i + 1`偶数長の場合。 
4. セグメントを外側に 1 位置拡張すると、2 つの新しいインデックスが含まれます。`l - 1`そして`r + 1`。 反転スワップのペア構造では、代わりに`(l - 1 with b[l - 1])`そして`(r + 1 with b[r + 1])`、これらの位置は次のようにペアになります。`(l - 1 with b[r + 1])`そして`(r + 1 with b[l - 1])`。 
5. これら 2 つのポジションの古い寄与分を削除し、新しく交換された寄与分を追加することにより、現在のコストを更新します。 この更新は 4 つの XOR 評価のみに依存するため、一定時間です。 
6. すべての拡張およびすべてのセンターにわたる最小コストを追跡します。 

### なぜ効果があるのか

 考えられるすべてのセグメント`[l, r]`は、ある中心を中心とした奇数長または偶数長の拡張として一意に生成されます。 各セグメントについて、アルゴリズムは、反転によってペアリングがどのように変化するかを正確に反映するローカル更新を使用して、一定時間で前のセグメントから変換することにより、正確なコストを計算します。 すべての反転はエンドポイントのペアの方法にのみ影響し、展開は帰納的に正確さを維持するため、セグメントが欠落したり、寄与が二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    base = 0
    for i in range(n):
        base += a[i] ^ b[i]

    ans = base

    # odd length segments
    for c in range(n):
        cur = base
        l = c - 1
        r = c + 1
        while l >= 0 and r < n:
            cur -= (a[l] ^ b[l]) + (a[r] ^ b[r])
            cur += (a[l] ^ b[r]) + (a[r] ^ b[l])
            ans = min(ans, cur)
            l -= 1
            r += 1

    # even length segments
    for c in range(n):
        l = c
        r = c + 1
        if r >= n:
            continue
        cur = base
        cur -= (a[l] ^ b[l]) + (a[r] ^ b[r])
        cur += (a[l] ^ b[r]) + (a[r] ^ b[l])
        ans = min(ans, cur)

        l -= 1
        r += 1
        while l >= 0 and r < n:
            cur -= (a[l] ^ b[l]) + (a[r] ^ b[r])
            cur += (a[l] ^ b[r]) + (a[r] ^ b[l])
            ans = min(ans, cur)
            l -= 1
            r += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、反転を行わずにベースライン XOR コストを計算することから始まります。 この操作はオプションであるため、その値はすでに回答の候補として機能します。 

実装の核心は、各中心の周りの対称的な拡張です。 奇数長のセグメントの場合は、単一の中心要素から開始して外側に拡張します。 偶数長のセグメントの場合は、2 つの要素の中心から始めます。 セグメントを拡張するたびに、新しく含まれたエンドポイントの寄与分が変更されていないかのように削除され、反転後の寄与分で置き換えられます。この場合、エンドポイントはその寄与分を交換します。`b`パートナー。 

減算と加算のパターンは、実装の重要な詳細です。 これにより、新しく追加された 2 つの位置のみが更新され、他のすべては前の状態から変更されません。 この段階的な移行により、複雑さが 2 次的に維持されます。 

## 実用的な例

 セグメント反転によって配列を完全に整列させることができる最初のサンプルを考えてみましょう。 1 つのセンターのプロセスを追跡します。 

| ステップ | l | r | 現在のコスト |
 | --- | --- | --- | --- |
 | ベース | - | - | 初期合計額 |
 | 1を展開 | 1 | 3 | エンドポイントを交換した後に更新されました |
 | 展開 2 | 0 | 4 | さらに洗練された |

 各拡張は、内部のすでに処理された構造に影響を与えることなく、エンドポイントのペアを厳密に置き換えます。 

これは、セグメントが確立されると、境界ペアのみが変更されるため、さらなる拡張が一貫して動作することを示しています。 

ここで、反転を行わないと答えが改善されない場合を考えてみましょう。 このような場合、拡張するたびにコストが増加するか変更されず、最小値はベースラインのままになります。 

| ステップ | l | r | 現在のコスト |
 | --- | --- | --- | --- |
 | ベース | - | - | 初期合計額 |
 | 任意の拡張 | - | - | ≥ ベース |

 これは、有益なセグメントが存在しない場合でも、アルゴリズムが元の答えを自然に保存することを示しています。

 ## 特殊なケース

 単一要素の配列は、反転しても何も変わらない最も単純なケースです。 両方の展開ループが内側の while ループに入らずにすぐに終了し、ベースラインが変更されないままになるため、アルゴリズムはこれを処理します。 

いつ`n = 2`、偶数長のセグメントが 1 つだけ存在します。 アルゴリズムが正しく初期化される`l = 0, r = 1`そして、唯一の可能な反転に対応する更新を 1 回だけ実行します。 

値が同じ場合`a`そして`b`、すべての XOR はゼロであり、すべての更新はコストゼロを維持します。 各展開では同一の値が減算および加算されるため、コストが変更されないという不変条件が実行全体にわたって保持されます。
