 ## 解決策
 ## 問題の理解

 各テスト ケースでは 2 つの分数が得られます。$\frac{a}{b}$そして$\frac{c}{d}$。 1 回の操作で、4 つの数字のうち 1 つを正確に選択できます。$a, b, c, d$そしてそれにゼロ以外の整数を掛けます。 目標は、そのような動きをできるだけ少なくして、2 つの分数が同じ実際の値を表すようにすることです。 

言い換えると、2 つの有理数を等しい値に変換しようとしていますが、唯一の操作は単一の分子または分母に毎回選択した整数を掛けることです。 乗算は任意に行うことができるため、重要なのは中間値ではなく、各分数の縮小形を公比に変形できるかどうかです。 

制約により、最大で$10^4$テスト ケース。それぞれの数値は次のように大きくなります。$10^9$。 どのソリューションでも、各テスト ケースを一定時間または対数時間で処理する必要があります。 テスト ケースごとに 2 次または値の線形アプローチさえも不可能です。$10^4$ケース。 

両方の分数の値がゼロ (分子がゼロ) の場合、微妙なエッジ ケースが発生します。 この状況では、分母に関係なくすべての分数はゼロに等しいため、答えは常にゼロになります。 もう 1 つの例外的なケースは、正確に 1 つの分数がゼロである場合です。有効な一連の乗算では非ゼロの分数をゼロに変えることはできないため、分子ゼロを介して非ゼロの分数をゼロに変換することによって平等を達成する必要がありますが、これは不可能であり、別の解釈を強いられます。代わりに、唯一の方法は両方の分子をゼロにすることであり、一方の分子がすでにゼロの場合は最大 1 手、それ以外の場合は 2 手かかります。 

もう 1 つの隠れた問題は、平等は生の値ではなく換算された比率のみに依存することです。 分子と分母を個別に一致させようとする素朴な試みは、一方の側をスケーリングすると両方の成分が一緒に変更されるため、失敗します。 

## アプローチ

 直接的だが素朴なアイデアは、演算をシミュレートすることです。4 つの値の 1 つを繰り返し選択し、2 つの分数を近づける方法でそれを乗算します。 これは、各移動で無限に多くの乗数の選択肢が導入され、検索スペースが爆発的に増加するため、すぐに管理できなくなります。 各ステップが比率の関係に非局所的に影響を与えるため、小さな乗数に制限しても依然として指数分岐が発生します。 

重要な点は、変換をシミュレートする必要がないということです。 各分数は有理数を表し、等しいことを意味します。$$a \cdot d = b \cdot c$$いくつかの乗算が 4 つの変数に個別に適用された後。 各演算では 1 つの変数のみがスケーリングされるため、最終的に重要なのは、素指数に関して両側が一致するように係数を調整できるかどうかです。 

値を追跡する代わりに、構造の観点から推論します。 各分数は最も単純な形に還元できます。 許可された乗算では、4 つの位置の 1 つにのみ素因数を導入または削除できます。 これは、2 つの換算された分数を効果的に整列させようとしていることを意味し、各移動により、対応する辺間の素因数分解における 1 つの不一致を修正できます。 

これにより、問題は 2 つの分数のうちのいくつが縮小形式ですでに一致しているのか、またそれらを同一にするためにはいくつの独立した調整が必要なのかを確認することに分解されます。 分子と分母の不一致はいつでも個別に修正できるため、答えは最大 2 になります。 

最後の単純化は、両方の分数を削減した後、それらがすでに等しい場合、答えは 0 です。一方の側を 1 回スケーリングした後でクロス乗算の等価性がすでに成立している場合、答えは 1 です。そうでない場合は、両方の比率を揃えるのに常に 2 回の演算が必要です。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースの a、b、c、d を読み取り、両方の分数が 0 であるかどうかを直ちに確認します。 そうである場合、スケーリングに関係なくすでに等しいため、0 を出力します。 
2. 1 つの分子のみがゼロの場合は、一致させる唯一の方法は両方の分数をゼロ値にすることであり、そのためには両方の分子をゼロに設定する必要があることに注意して、状況を正規化します。 ゼロ以外の各分子には 1 つの演算が必要なので、ちょうど 1 つの分子がすでにゼロであれば答えは 1、それ以外の場合は 2 になります。 
3. 両方の分数がゼロ以外の場合、交差乗算を使用して等価条件を計算します。$a \cdot d = b \cdot c$。 これがすでに成立している場合は、0 を出力します。 
4. 等しくない場合は、1 回の乗算で不一致を修正できるかどうかを確認します。 これは、2 つの分数間の比率が 4 つの変数のうちの 1 つの整数スケーリングとしてすでに表現可能である場合に可能です。 具体的に言うと、$a \cdot d$で割り切れます$b \cdot c$またはその逆の場合は、1 回の操作で十分です。 
5. どちらの条件も当てはまらない場合は、出力 2 が出力されます。これは、分子または分母の位置合わせを個別に修正することにより、等価性を強制するには 2 つの独立した調整で常に十分であるためです。 

### なぜ効果があるのか

 不変条件は、各演算で 4 つの要素のうち 1 つの要素にのみ素因数を導入または削除できるため、因数分解間の不一致は存在しないということです。$a/b$そして$c/d$最大 2 つの独立した位置を修正することで解決できます。 最初のステップで外積の片側を調整し、2 番目のステップで残りの不均衡を解決します。 比率のマッチングには分子スケーリングと分母スケーリングという 2 つの自由度しかないため、3 つ以上の構成は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c, d = map(int, input().split())

        # both zero-valued fractions
        if a == 0 and c == 0:
            print(0)
            continue

        # one side zero, other not
        if a == 0 or c == 0:
            print(1)
            continue

        # already equal
        if a * d == b * c:
            print(0)
            continue

        # check if one move can fix via integer scaling
        if (a * d) % (b * c) == 0 or (b * c) % (a * d) == 0:
            print(1)
        else:
            print(2)

if __name__ == "__main__":
    solve()
```このソリューションは、算術チェックのみを使用して各テスト ケースを個別に処理します。 除算ベースの推論がそこで中断されるため、ゼロ ケースが最初に処理されます。 相互乗算チェックにより、浮動小数点エラーが完全に回避されます。 可分性チェックでは、2 つの独立した修正を必要とするのではなく、1 回のスケーリング操作で不一致が解決可能かどうかが判断されます。 

よくある間違いは、gcd を使用して明示的に分数を単純化しようとすることですが、これは不必要であり、間違って実行するとオーバーフローの危険があります。 相互乗算を使用すると、すべての推論が整数空間に保持されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            a, b, c, d = map(int, input().split())

            if a == 0 and c == 0:
                out.append("0")
                continue
            if a == 0 or c == 0:
                out.append("1")
                continue
            if a * d == b * c:
                out.append("0")
                continue
            if (a * d) % (b * c) == 0 or (b * c) % (a * d) == 0:
                out.append("1")
            else:
                out.append("2")

        return "\n".join(out) + "\n"

    return solve()

 ## 特殊なケース

 重要なエッジケースは、次のように両方の分子がゼロの場合です。`0 1 0 100`。 アルゴリズムは、両方の分数がゼロ値であることを検出し、等価性を維持するためにスケーリングを必要としないため、すぐに 0 を返します。 

もう 1 つのエッジ ケースは、次のような 1 つの分子だけがゼロである場合です。`0 1 228 179`。 アルゴリズムは 1 を返します。これは、ゼロ以外の分子を削除するか、スケーリングによって分子を揃えるのに必要な調整が 1 回だけであることを反映しています。 

最後の微妙なケースは、分数がすでに等しいが、構文的に同一ではない場合です。`100 3 25 6`。 相互乗算により次の結果が得られます$100 \cdot 6 = 3 \cdot 200$、明示的に分数を減算せずに等しいことを確認するため、アルゴリズムは正しく 0 を返します。
