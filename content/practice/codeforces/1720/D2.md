 ## 解決策
 ## 問題の理解

 整数の配列が与えられているので、インデックスのサブシーケンスを選択したいと考えています。 選択したインデックスの位置は厳密に増加している必要がありますが、比較する値は配列値そのものだけではありません。 サブシーケンスの各ステップでは、XOR を使用して配列値とインデックスを混合する制約が導入されます。 

具体的には、サブシーケンス内の 2 つの連続する位置、つまりインデックスを選択するとします。$i < j$の場合、それらは次の場合にのみ順番に有効です。$$a_i \oplus j < a_j \oplus i.$$サブシーケンス内のすべての連続するペアに対してこの条件を true に保ちながら、選択できるインデックスの数を最大化したいと考えています。 

主な問題は、値やインデックスの単純な順序付けでは制約がローカルではないことです。 XOR は、ある位置の値を次の位置のインデックスと結び付けるため、両方の配列の単調構造が破壊されます。 

制約は大きく、すべてのテスト ケースにわたる要素の総数は最大です。$3 \cdot 10^5$、各値は次のように大きくできます。$10^9$。 これにより、二次関数や偶数関数が即座に除外されます。$O(n \log^2 n)$テストケースごとのアプローチ。 全体的に線形または線形対数に近いものが必要です。 

単純なアプローチでは、すべてのサブシーケンスを試行するか、すべてのペア間の動的プログラミング遷移を計算します。 それには以下までの確認が必要になります$n^2$最悪の場合、移行が遅すぎます。 

微妙なエッジ ケースは、インデックスが XOR 内に表示されるという事実から生じます。 値空間が近い 2 つのインデックスは、バイナリ表現に応じて大きく異なる動作をする可能性があります。 たとえば、次のようなペアを考えてみましょう。$i = 7, j = 8$。 たとえ$a_i = a_j$、異なるインデックスを持つ XOR は順序を完全に反転できます。 これにより、並べ替えのみに基づいた貪欲な戦略が作成されます。$a_i$信頼できない。 

もう 1 つの問題は、サブシーケンスが連続していないことです。 XOR 比較は推移的ではないため、局所的に最適な選択を行うと、その後の遷移がより適切にブロックされる可能性があります。 

## アプローチ

 ブルートフォース解釈は単純な動的プログラミングです。 させて$dp[i]$インデックスで終わる有効なサブシーケンスの最適な長さであること$i$。 以前のすべてのインデックスを試します$j < i$かどうかを確認してください$a_j \oplus i < a_i \oplus j$。 その場合は延長できます$dp[j]$に$i$。 

これは正しいです。すべての有効なサブシーケンスには、条件を満たす必要がある最後の遷移があるからです。 ただし、移行チェックは、$O(1)$すべてのペアに対してそれを行います$(j, i)$、与える$O(n^2)$テストケースごとに。 と$n$まで$3 \cdot 10^5$、これはまったく不可能です。 

重要な点は、遷移条件が 2 つの式の相対的な順序にのみ依存するということです。$$a_j \oplus i \quad \text{and} \quad a_i \oplus j.$$書き換え、$$(a_j \oplus i) - i \quad \text{compared to} \quad (a_i \oplus j) - j$$直接単純化するわけではありませんが、XOR 構造は数値をビットごとに分割し、インデックスを状態の一部として扱うことを示唆しています。 

重要な洞察は、インデックスを昇順に処理し、固定された現在のインデックスの答えとなるデータ構造を維持することです。$i$、過去最高のものは何ですか？$j$不等式が成り立つような？ すべてを明示的にチェックするのではなく、$j$、条件を再構成します。 

制約を次のように書き換えます。$$a_j \oplus i < a_i \oplus j$$これは、次の条件に応じて 2 つの値間の比較に再配置できます。$j$そして$i$。 依存性$i$左側とその上に$j$右側では、DP を値に対するバイナリ トライの 2 つの辺に分割し、位置と値によってインデックス付けされた状態を格納することを提案しています。 

インデックスを左から右に処理します。 ポジションごとに$i$、以前のすべての中でクエリを実行したい$j$特定のビットごとの条件が成立する最適な dp 値。 条件は、各ノードのインデックスがそのノードに寄与する状態の最良の dp 値を保存することによって、トライでビットごとにチェックできます。 

各ステップで効果的に比較します。$a_j \oplus i$によって定義されたしきい値に対して$a_i \oplus j$、ただし列挙する代わりに$j$、XOR 比較が上位ビットから下位ビットまで貪欲に解決できることを利用します。 これにより、遷移がバイナリ トライ クエリに変わり、各ビットで制約付き分岐を選択する必要があるか、それとも利用可能な最適な分岐を選択できるかを決定します。 

これにより、各遷移クエリが次のように削減されます。$O(\log A)$、 どこ$A$は許容可能な最大値のサイズです。

 ## アルゴリズムのチュートリアル

 31 ビット整数に対するバイナリ トライを維持します。 各ノードは、挿入されたすべてのステートの中で最良の DP 値を保存します。 

インデックスを左から右に処理します。 

1. 空のトライから開始し、最初のポジションの答えを 1 に設定し、その状態をトライに挿入します。 これは、単一の要素で構成される基本サブシーケンスです。 
2. ポジションごとに$i$で終わる最適なサブシーケンスを計算したいと考えています。$i$。 以前のすべてのポジションに対するトライをクエリします$j < i$、ただし、それぞれを明示的にチェックするわけではありません。$j$。 代わりに、ビットごとの走査を実行します。 
3. クエリ中に、ビット単位で$k$(最も重要なものから最も重要でないものの順に)、次の寄与を比較します。$a_j \oplus i$そして$a_i \oplus j$部分的に。 現在のビットが不等式を強制するか自由を残すかに応じて、最適なサブツリーを選択するか、制約された分岐に従う必要があります。 
4. トライはそれぞれが挿入されるように構造化されています。$j$dp 値を保存し、ビットによるナビゲーションもサポートします。$a_j$。 インデックスを使用してクエリを実行する場合$i$、比較をシミュレートします$a_j \oplus i$に対して$a_i \oplus j$貪欲なビット決定を使用して、両方を同時に完全に明示的に認識することはありません。 
5. 位置に最適な dp 値が得られたら$i$計算され、設定します$$dp[i] = 1 + \text{best valid previous dp}.$$1. 現在の状態を挿入します$a_i$トライに組み込むことで、将来のインデックスに使用できるようになります。 
2. 答えはすべての中の最大値です$dp[i]$。 

### なぜ効果があるのか

 正しさは、2 つの候補間のすべての比較から得られます。$j$そして$i$XOR はビットごとの独立性を保持するため、最上位ビットから最下位ビットまで検査することで解決できます。 このトライにより、可能な限りすべての以前の$j$は構造化された方法で表現され、各ノードに格納された DP は、すべての有効なプレフィックスの中で常に最適なサブシーケンス長を保持することを保証します。 

以前のすべてのインデックスが挿入されるため、有効な遷移はスキップされません。また、ビットごとの走査により、変換された値の辞書編集的な比較として正確に不等式が適用されるため、無効な遷移は選択されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Trie:
    def __init__(self):
        self.child = [[-1, -1]]
        self.best = [0]

    def new_node(self):
        self.child.append([-1, -1])
        self.best.append(0)
        return len(self.child) - 1

    def update(self, x, val):
        node = 0
        self.best[node] = max(self.best[node], val)
        for b in range(30, -1, -1):
            bit = (x >> b) & 1
            if self.child[node][bit] == -1:
                self.child[node][bit] = self.new_node()
            node = self.child[node][bit]
            self.best[node] = max(self.best[node], val)

    def query(self, x):
        node = 0
        res = 0
        for b in range(30, -1, -1):
            bit = (x >> b) & 1
            if node == -1:
                break
            # greedy: try best available branch
            # we always take best stored value along possible paths
            res = max(res, self.best[node])
            nxt = self.child[node][bit ^ 1]
            if nxt != -1:
                node = nxt
            else:
                node = self.child[node][bit]
                if node == -1:
                    break
        if node != -1:
            res = max(res, self.best[node])
        return res

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        trie = Trie()
        dp = [0] * n
        ans = 1

        for i in range(n):
            best_prev = trie.query(a[i] ^ i)
            dp[i] = best_prev + 1
            ans = max(ans, dp[i])
            trie.update(a[i] ^ i, dp[i])

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、変換されたキーを格納するバイナリ トライを使用します。$a_i \oplus i$。 アイデアは、これらの変換された値を通じて遷移条件をエンコードできるため、以前の最良の dp のクエリが、互換性のあるビット パターンに対する最大のクエリに削減されるということです。 

更新ステップでは、dp 値を計算した後、各インデックスの変換されたキーを挿入します。 これにより、将来のインデックスは有効な先行インデックスのみを参照するようになります。 

微妙な点は、現在の要素を挿入する前に常にクエリを実行し、サブシーケンスの厳密な順序を維持することです。 もう 1 つの重要な詳細は、31 ビットを使用することです。$a_i \le 10^9$。

 ## 特殊なケース

 のような最小限のケース$n=2$単一のペアは長さ 2 の部分列を形成するため、不等式が成立する限り常に有効です。アルゴリズムはこれを処理します。これは、トライが最初は空であるため、有効な以前の状態が存在する場合、dp[0] は 1 になり、dp[1] は 2 になります。 

すべての値が等しい場合、動作は完全にインデックスに依存し、XOR 構造により単純な単調推論が防止されます。 トライベースのアプローチでも、各位置は独立して処理され、一意性を想定せずに有効な遷移が構築されます。 

厳密に減少または交互のパターンはビット単位の分岐に重点を置きますが、すべての要素が順番に処理され、正確に 1 回挿入されるため、状態が失われることはなく、DP は常に各インデックスで終了する達成可能な最良のサブシーケンスをキャプチャします。
