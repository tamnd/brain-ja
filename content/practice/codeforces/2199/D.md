 ## 解決策
 ## 問題の理解

 2 つの配列が与えられ、それぞれが非降順でソートされ、奇数の要素を持ちます。 タスクは、一連の操作を使用して 2 つの配列を同一にできるかどうかを判断することです。 操作により、配列の 1 つを選択し、その要素の奇数をマークし、マークされたセグメントをその中央値で置き換え、その中央値を同じ配列内の任意の場所に再挿入することができます。 

重要な観察点は、この操作により、マークされたセグメントの外側の要素の相対的な順序が保持されるということです。 さらに重要なのは、これらの操作を繰り返し適用すると、奇数長のセグメントを中央値に折りたたむことができるようになります。 両方の配列の長さが奇数であるため、必要に応じて各配列を最終的に単一の値に減らすことができます。 

制約は重要です。 テスト ケース全体のすべての配列の長さの合計は最大 300,000 です。 セグメントを繰り返しマークして中央値を移動する総当りシミュレーションでは、配列の長さの二次作業が必要になる可能性があり、これでは非常に時間がかかります。 これは、操作を直接シミュレートすることを回避するソリューションが必要であることを意味します。 

注意すべきエッジケースには、長さ 1 の配列、すべての要素が等しい配列、または分布が大きく異なる配列が含まれます。 たとえば、与えられた配列`[1, 3, 5]`そして`[3]`、最初のものを次のように減らすことができます。`[3]`、しかし、`[1, 2, 3]`そして`[4, 5, 6]`、どのような操作順序でも配列を等しくすることはできません。 

## アプローチ

 ブルートフォースアプローチは、すべての有効な操作をシミュレートし、各配列のすべての奇数長のサブセットを試し、それらの中央値を計算し、再挿入することです。 この方法は、問題の定義で任意の奇数長のサブセットが許可されるため、原理的には正しいですが、法外に高価です。 長さ 301 の配列の場合、奇数長のサブセットが数百個存在する可能性があり、テスト ケース全体の配列長が 300,000 になると、これはすぐに実行不可能になります。 

最適なアプローチは、演算によりすべての可能な奇数長セグメントの中央値のマルチセットが保存されるという洞察にかかっています。 言い換えれば、両方の配列がソートされており、操作では配列全体または任意の部分配列を選択できるため、重要な情報は最初の配列の最大要素と 2 番目の配列の最小要素だけです。 中央値を介して配列を繰り返し折りたたんだ後、最初に折りたたむことを選択した配列に応じて、最初の配列の最大値が 2 番目の配列の最小値を超えない場合に限り、配列を等しくすることができます。逆も同様です。 

この観察により、各配列を効率的に 1 つの数値に減らすことができ、配列全体の中央値を選択することができます。 次に、一方の配列の最大中央値がもう一方の配列の最小中央値と一致するかどうかを確認するだけで十分です。 並べ替えはすでに提供されているため、配列の最後の要素と最初の要素を取得すると、テスト ケースごとに O(1) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースごとに O(n^2 + m^2) | O(n + m) | 遅すぎる |
 | 最適 | 入力後のテスト ケースごとに O(1) | テスト ケースごとに O(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 
2. テスト ケースごとに、ソートされた 2 つの配列の長さと要素を読み取ります。 
3. 各配列の中央値を特定します。これは、両方の配列の長さが奇数であるため、中央の要素になります。 ソートされた配列では、これは単純に`a[n//2]`そして`b[m//2]`。 
4. 中央値を比較します。 最初の配列の中央値が 2 番目の配列の中央値と等しい場合は、YES を出力します。 それ以外の場合は、NO を出力します。 

正確さは、奇数長の配列は繰り返しの操作によって中央値まで折りたたむことができるという不変条件に基づいています。 両方の配列をそれぞれの中央値に換算すると、等価性は簡単になります。 この操作では中央値選択による完全な削減が可能であるため、中間要素は重要ではありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        median_a = a[n // 2]
        median_b = b[m // 2]
        print("YES" if median_a == median_b else "NO")

if __name__ == "__main__":
    main()
```解決策は整数除算を使用します`n // 2`そして`m // 2`中央の要素に直接アクセスします。 これは、並べ替えられたプロパティと奇数長制約を利用して、O(1) の中央値を見つけます。 Python リストはゼロインデックスであり、整数の除算は自然に中央の要素を指すため、off-by-one エラーは発生しません。 入力読み取りは次のように最適化されます。`sys.stdin.readline`大規模なテストケースを効率的に処理します。 

## 実用的な例

 **例 1:**

 入力配列:`a = [1, 2, 3, 4, 5]`、`b = [1, 3, 7]`

`median_a = 3`、`median_b = 3`出力: はい

 | ステップ | | b | 中央値_a | 中央値_b | 比較 |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | [1,2,3,4,5] | [1,3,7] | 3 | 3 | 3 == 3 → はい |

 このトレースは、各配列をその中央値まで折りたたむだけで同等であることを判断するのに十分であることを示しています。 

**例 2:**

 入力配列:`a = [11, 17, 19]`、`b = [19, 20, 26, 29, 37]`

`median_a = 17`、`median_b = 26`出力: いいえ

 | ステップ | | b | 中央値_a | 中央値_b | 比較 |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | [11,17,19] | [19,20,26,29,37] | 17 | 26 | 17 != 26 → いいえ |

 これにより、配列を等しくすることができない場合にアルゴリズムが正しく識別されることが確認されます。

 ## 特殊なケース

 次のような長さ 1 の配列を考えてみましょう。`[5]`そして`[5]`。 中央値が唯一の要素であり、アルゴリズムは正しく YES を返します。 配列の場合`[5]`そして`[6]`、中央値が異なるため、NO が返されます。 すべての要素が同一の場合、`[7, 7, 7]`そして`[7, 7, 7]`の場合、中央値は両方とも 7 であるため、YES が返されます。 順列であるが中央値が同じ配列、`[1, 2, 3]`そして`[3, 2, 1]`も YES を返し、アルゴリズムが中央値崩壊の重要な不変式を正しくキャプチャしていることを確認します。
