 ## 解決策

 ## 問題の理解

 小文字で構成される開始文字列が与えられ、それを繰り返し変更する一連の操作が与えられます。 各操作では、位置から文字列のセグメントを指定します。`l`に`r`、および文字のペア`c1`そして`c2`。 そのセグメント内で発生するすべての`c1`に置き換えられます`c2`、他のすべての文字は変更されません。 

重要な点は、各操作が選択的であるということです。 セグメント全体を上書きするのではなく、指定された範囲内にある文字を別の文字に変換するだけです。 後の操作はすでに変更された文字列に作用するため、時間の経過とともに変換が蓄積されます。 

制約は非常に小さく、文字列長も演算数も最大 100 です。これにより、二次または三次解であっても安全であることがすぐにわかります。 Python では、およそ 10^6 の演算までは簡単なので、高度なデータ構造や最適化のコツは必要ありません。 直接のシミュレーションで十分です。 

通常、間違いが発生する主な場所は、置換の条件付きの性質を誤解することです。 単純な間違いは、すべての文字を置き換えることです。`[l, r]`と`c2`に等しいものだけを置き換えるのではなく、`c1`。 

たとえば、文字列が次の場合、`abca`そして私たちは申請します`(1, 4, a, b)`、のみ`a`キャラクターは変化し、`bbc b`(つまり、`bbcb`）。 セグメント全体を置き換えると、誤った結果が得られます。`bbbb`。 

もう 1 つの微妙な問題はインデックス作成です。 この問題では 1 から始まるインデックスが使用されていますが、Python 文字列は 0 から始まります。 インデックスの調整に失敗すると、特に次のような境界でオフバイワンエラーが発生します。`l = 1`または`r = n`。 

## アプローチ

 最も簡単なアプローチは、文字列の可変表現に対して各操作を直接シミュレートすることです。 更新が効率的に行われるように、文字列を文字のリストに変換します。 

操作ごとにセグメントをスキャンします。`[l-1, r-1]`そして各文字を確認してください。 一致する場合`c1`で置き換えます。`c2`。 それ以外の場合は、変更しないままにしておきます。 これは正しいです。問題の定義は純粋にローカルであり、異なる位置間の依存関係が含まれていないからです。 

このブルートフォースアプローチのパフォーマンスは最大でも`m * n`性格チェック。 と`n, m ≤ 100`、これは最大 10,000 回の操作であり、完全に安全です。 

更新は範囲の割り当てや集計ではないため、前処理やセグメント ツリーのようなデータ構造は必要ありません。 これらは単純な条件付き文字置換です。

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取り、文字をその場で変更できるようにリストに変換します。 これにより、Python では非効率となる文字列の再構築の繰り返しが回避されます。 
2. 各操作ごとに`(l, r, c1, c2)`、から 1 を減算して、インデックスを 0 ベースの形式に調整します。`l`そして`r`。 これにより、Python インデックス作成との正しい調整が保証されます。 
3. すべての位置を反復処理します。`l`に`r`。 各インデックスで、現在の文字が以下と等しいかどうかを確認します。`c1`。 
4. 一致する場合は、次のように置き換えます。`c2`。 一致しない場合は、変更しないでください。 この操作はグローバルではなく選択的であるため、この条件チェックは不可欠です。 
5. すべての操作を処理した後、リストを結合して文字列に戻し、出力します。 

### なぜ効果があるのか

 各操作は指定された順序で正確に適用され、各文字は現在の値とアクティブな範囲内にあるかどうかのみに基づいて個別に更新されます。 このアルゴリズムは、k 番目の操作を処理した後、文字列は順番に適用される最初の k 個の変換の効果を正確に反映するという不変条件を維持します。 すべての操作は定義どおりに正確に実装されるため、無関係な位置間で意図しない相互作用が発生することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    s = list(input().strip())

    for _ in range(m):
        l, r, c1, c2 = input().split()
        l = int(l) - 1
        r = int(r) - 1

        for i in range(l, r + 1):
            if s[i] == c1:
                s[i] = c2

    print("".join(s))

if __name__ == "__main__":
    main()
```Python 文字列は不変であるため、このソリューションでは文字列の代わりにリストを使用します。つまり、変更するたびに新しい文字列が作成されてしまいます。 ここではそれでも問題ありませんが、リストによるアプローチの方がよりクリーンで、繰り返しの割り当てを回避できます。 

境界の処理は簡単です。`r + 1`ループ内で使用されるため、右のエンドポイントが含まれます。 両方から 1 を引いたもの`l`そして`r`1 から始まるインデックスからの正しい変換が保証されます。 

各操作は即座に適用され、問題で必要とされる順次セマンティクスが維持されます。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です`l == r`、つまり、操作は 1 つの位置にのみ影響します。 例えば、`s = "abc"`、 手術`(2,2,'b','x')`。 アルゴリズムセット`l = 1`-ベースに`1`-ベースの修正なので、0 ベースの形式でインデックス 1 のみがチェックされます。 ループは 1 回実行され、その文字のみが正しく更新され、`"axc"`。 

もう一つのケースは次のような場合です。`c1 == c2`。 例えば、`(1,3,'a','a')`の上`"aba"`。 条件`if s[i] == c1`は引き続き有効ですが、同じ文字に置き換えると文字列は変更されません。 アルゴリズムは、特別なケースを使用せずにこれを自然に処理します。 

最後のケースは、セグメント内に一致する文字がない場合です。`c1`。 のために`"abc"`と`(1,3,'z','a')`の場合、条件はトリガーされないため、文字列は変更されません。 スキャンは引き続きセグメント上で実行されますが、変更は行われず、正確性が維持されます。
