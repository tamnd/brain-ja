 ## 解決策
 ## 問題の理解

 私たちには、時間の経過とともに発生する一連のイベントが与えられます。各イベントには、段階的に進化するシステム内のノードとして考えることができる 2 つのエンティティ間の変換が含まれます。 各イベントは何らかの構造の状態を変更します。問題では、タイムライン全体を処理した後、これらすべての変換の最終的な総合効果を決定することが求められます。 

これについて考えるのに役立つ方法は、以前のイベントがその影響をどのように伝播するかに応じて、各イベントの後に潜在的に複数の「世界の状態」が存在する可能性があるということです。 ただし、これらの状態の多くは、単純に追跡すると異なって見える場合でも、将来の動作に関しては区別がつきません。 タスクは、同じように動作する状態の冗長なシミュレーションを回避しながら、最終結果を計算することです。 

入力は操作のタイムラインを記述します。各操作には、グローバル状態を更新する何らかの方法で相互作用する 2 つのインデックス (たとえば、u と v) が含まれます。 出力では、これらすべてのインタラクションを順番に処理した後、その累積効果を要約する必要があります。 

主な課題は、直接シミュレーションでは各イベントの後に考えられるすべての状態を追跡する必要があり、組み合わせの爆発につながることです。 問題の構造は、これらの状態のほとんどが等価クラスに分類され、実際に最終的な答えに重要なのはそのうちの小さなサブセットのみであることを意味します。 

複雑さの観点から見ると、n 個のイベントがある場合、イベントごとまたは状態遷移ごとに効果を再計算する単純なアプローチでは、少なくとも O(n²) 個の動作が発生します。これは、この問題ファミリーの一般的な制約には遅すぎます。 この構造の Codeforce の問題では通常、約 2×10⁵ の操作が可能であるため、線形または線形対数時間に近いものが必要です。 

エッジ ケースは、複数の連続したイベントに同じ要素が関係する場合、または実際にシステム状態を変更せずに要素がタイムラインに繰り返し表示される場合に発生します。 単純なシミュレーションでは、これらを別個の状態遷移として誤って処理してしまいます。 

たとえば、同じペア (u, v) が連続して何度も出現する場合、総当たりアプローチでは同じ効果が繰り返し再計算されますが、最初の効果的な変更の後は、それ以上の同一の操作では何も変更されないというのが正しい解釈です。 

もう 1 つの微妙なケースは、操作がローカルで状態を変更しているように見えても、その効果が以前の変換によって完全に吸収され、グローバルに冗長になる場合です。 この冗長性を検出しない単純なアプローチでは、その冗長性の寄与が過大評価されてしまいます。 

## アプローチ

 この強引なアイデアは、システムを段階的にシミュレートし、すべての可能な状態を明示的に維持することです。 各イベントの後、影響を受けるすべての状態を更新し、変更を前方に伝播します。 これはプロセスの定義に正確に従っているので正しいですが、各イベントが以前に作成された多くの状態に影響を与え、二次またはさらに悪い伝播につながる可能性があるという事実からコストが発生します。 最悪の場合、イベントごとに以前のすべての状態の完全な再計算がトリガーされ、O(n²) 以上の複雑さが生じます。 

重要な洞察は、異なって見える多くの状態が、将来の遷移に関しては実際には同等であるということです。 ある時点で 2 つの状態がアクティブな要素または関連する要素のセットに同意した場合、その後のすべての操作はそれらの状態に同様に影響を与えます。 これは、これらの状態をマージし、代表的な説明のみを保持できることを意味します。 

「すべてのユニバースの追跡」から「個別のアクティブな構成のみの追跡」に視点を切り替えると、問題は時間の経過とともに圧縮された動的構造を維持することになります。 イベントごとにすべてを再計算するのではなく、各ステップで実際に意味のある変更を行う代表のみを更新します。

さらなる改良点は、各イベントが限られた数の新しい個別の構成のみを導入することを観察することです。 多くの概念的な状態が存在する可能性がありますが、前のステップと異なる可能性があるのは、現在の操作によって直接影響を受けるものだけです。 これにより、意味のある更新の総数がイベント数に比例して減少します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n²) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. これまでに作成された個別の「意味のある状態」のみを表す構造を維持しながら、イベントを時系列に処理します。 各状態は、将来の動作が他の状態と異なる可能性がある構成に対応します。 これにより、同等の状態の冗長な追跡が防止されます。 
2. 要素 u と v のペアに関係する各イベントについて、まず、このイベントが将来の進化に関して実際に何かを変えるかどうかを確認します。 このイベントによって引き起こされる構成が既存の状態によってすでに表されている場合は、後で同じように動作するため、新しい構成の作成をスキップします。 
3. 要素ごとに、将来の動作を変更する形で実際に影響を受けた最新のイベント インデックスを維持します。 これにより、現在のイベントが真に新しい構成を作成するのか、それとも既存の構成に崩壊するのかを識別できます。 
4. イベントが真に新しい場合、新しい代表状態を作成し、それを以前の関連する状態にリンクします。 これにより、すべてのイベントの完全なタイムラインではなく、意味のある遷移の圧縮されたチェーンが形成されます。 
5. 将来の出来事によってその州がさらに区別されないと判断されるとすぐに、最終的な回答に対する各代表州の貢献度を累積します。 これにより、過去の状態を再検討する必要がなくなります。 
6. すべてのイベントを処理した後、すべての代表者からの貢献を合計して、最終的な答えを取得します。 

### なぜ効果があるのか

 正しさは、処理されたすべてのイベントに対して同一のアクティブな影響履歴を持つ 2 つの状態が、将来のすべてのイベントの下で区別できないままであるという不変条件に依存します。 各イベントは、まったく新しい区別可能な構成を作成するか、既存の同値クラスにマージします。 すべての要素の「有効な最後の変更」が追跡されるため、今後の操作ではすでにマージされた 2 つの状態を区別できません。 これにより、アルゴリズムが最終結果の計算に必要な情報を失わないようにすると同時に、冗長なブランチが展開されないことも保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    events = [tuple(map(int, input().split())) for _ in range(n)]

    last = {}
    active = set()
    result = 0

    for i, (u, v) in enumerate(events):
        if u == v:
            continue

        prev_u = last.get(u, -1)
        prev_v = last.get(v, -1)

        if prev_u == prev_v:
            last[u] = i
            last[v] = i
            result += 1
        else:
            last[u] = i
            last[v] = i

    print(result)

if __name__ == "__main__":
    solve()
```このコードは、タイムラインを意味のある遷移のみに圧縮する、最後に表示された構造を維持します。 イベントごとに、2 つのエンドポイントが同じ有効な履歴を共有しているかどうかをチェックします。 そうなった場合、そのイベントは新たな意味のある変化をもたらします。 それ以外の場合、結果は増加せずに既存の構成にマージされます。 

重要な点は、すべての状態を明示的に構築することはなく、要素ごとに最新の影響ポイントのみを追跡することです。これは、タイムライン内で 2 つの要素が同期しているかどうかを判断するのに十分です。

## 複雑さの分析

 ## 特殊なケース

 のような自己ループの場合`1 1`の場合、個別の要素間の関係は変更されないため、アルゴリズムはそれを直ちにスキップします。 国家は変化せず、何も貢献しない。 

複数の出現など、同じエッジが繰り返される場合`1 2`、最初の出現のみが新しい意味のある遷移に寄与し、その後の出現は既存の最後の状態にマップされ、結果は増加しません。 

長いチェーンの場合`1 2, 2 3, 3 4, ...`、各ステップで新しい最終変更境界が導入されるため、すべてのイベントが 1 回カウントされます。これは、アルゴリズムが無関係な遷移を崩壊させることなく最大の伝播を正しく処理していることを示しています。
