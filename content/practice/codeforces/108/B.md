 ## 問題の理解

 いくつかの符号なし整数データ型が与えられ、それぞれがそのビット長によって定義されます。 データ型`a`ビットは以下のすべての整数を格納できます。`0`まで`2^a - 1`。 

何らかの整数が存在するかどうかを知りたい`x`サイズのある 2 つのデータ型`a[i] < a[j]`次のような:

 1.`x`より小さいデータ型内に収まります。 
2.`x * x`より大きなデータ型には収まりません。 

そのようなペアが存在する場合、言語は非常に奇妙な動作をするため、Tuftuf はそれを放棄することを決定します。 

重要な観察点は、実際の値は`x`2 の累乗によってのみ問題になります。 で表現できる最大数なので、`a`ビットは`2^a - 1`、適合する数値から可能な最大の正方形`a`ビットはおおよそです`(2^a)^2 = 2^(2a)`。 したがって、質問は次のようになります。 

から数値を二乗できます`a`-bit タイプには以上が必要です`b`ビット、ここで`a < b`?

 入力サイズが到達しました`10^5`したがって、二次時間ですべてのペアを直接チェックするアルゴリズムは、次のように実行されます。`10^10`最悪の場合の比較。 これは 2 秒の制限をはるかに超えています。 もっと近いものが必要です`O(n log n)`または`O(n)`。 

問題の微妙な部分は、この条件には普遍性ではなく存在が関係しているということです。 必要な整数は 1 つだけです`x`これにより、より大きなデータ型が壊れます。 不用意なソリューションでは、より小さいデータ型の最大値のみをテストし、より単純な検証を見逃してしまう可能性があります。 

次の入力を考えてみましょう。```
2
3 4
```正しい答えは、`"YES"`なぜなら`x = 7`3ビットに収まりますが、`49`4ビットに収まらない。 非公式にビット数だけで判断する単純な実装では、データ型を 1 ビット増やすだけで常に十分であると誤って考える可能性があります。 

もう 1 つの簡単な間違いは、等しいデータ型サイズを誤って処理することです。```
3
5 5 5
```正しい答えは、`"NO"`条件が明示的に要求しているため、`a[i] < a[j]`。 同じサイズでは有効なペアを形成できません。 

3 番目の落とし穴は、固定幅の整数を使用する言語でのオーバーフローです。 誰かが計算したら`2^a`直接大規模な`a`、次のような値`2^10^9`保管することは不可能です。 意図した解には実際の 2 の累乗は必要なく、指数間の関係のみが必要です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 データ型サイズの順序付けられたペアごとに`(a, b)`どこ`a < b`に適合する値が存在するかどうかを尋ねます。`a`二乗が表現可能な最大値を超えるビット`b`ビット。 

数字が入る`a`次の場合のビット:```
x ≤ 2^a - 1
```その正方形は収まりません`b`次の場合のビット:```
x^2 > 2^b - 1
```可能な最大の正方形は次のようになります。`x = 2^a - 1`。 二乗するとおおよその値が得られます`2^(2a)`。 つまり、平方は次の値を超える可能性があります。`b`-bit 制限は次の場合に常に行われます。```
2a > b
```したがって、総当たりの解決策は次のようになります。 

1. すべてのペアをチェックします`(a, b)`と`a < b`。 
2. もし`2a > b`、 答え`"YES"`。 

このロジックは正しいですが、すべてのペアをチェックするとコストがかかります`O(n^2)`。 と`n = 10^5`、これは使用できなくなります。 

重要な洞察は、ソート後は関連するデータ型の最小サイズと最大サイズのみが重要であるということです。 

配列がソートされていると仮定します。```
a[0] ≤ a[1] ≤ ... ≤ a[n-1]
```一部のデータ型サイズの場合`a[i]`、より大きなデータ型が存在するかどうかを知りたいのです`a[j]`満足のいく：```
a[j] < 2 * a[i]
```配列はソートされているため、最も簡単な候補は、厳密に次のデータ型よりも大きい最小のデータ型です。`a[i]`。 そのデータ型さえ少なくとも`2 * a[i]`の場合、その後のすべてのデータ型も大きすぎるため、このデータ型に有効なペアが存在しません。`a[i]`。 

したがって、並べ替えた後は、隣接する個別のサイズを比較するだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n log n) | 並べ替え以外の O(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. データ型のサイズを配列に読み取ります。 
2. 配列を非降順で並べ替えます。 

ソートにより、データ型のサイズを昇順に調べて、より大きな候補を効率的に推論できます。 
3. ソートされた配列内の隣接するペアを反復処理します。 
4. 隣接するペアごとに`(a[i], a[i+1])`, まず厳密に異なるかどうかを確認してください。 

問題では必要なため、等しいサイズでは条件を満たすことができません。`a[i] < a[j]`。 
5. もし`a[i+1] < 2 * a[i]`、印刷`"YES"`そして終了します。 

これは、より小さいサイズのデータ​​型が存在することを意味します`a[i]`サイズの大きなデータ型`a[i+1]`そのため、小さい型からある数値を 2 乗するには、大きい型が保持できるよりも多くのビットが必要になります。 
6. そのようなペアが見つからずにループが終了した場合は、次のように出力します。`"NO"`。 

### なぜ効果があるのか

 データ型`a`ビットには最大の数値を保存できます`2^a - 1`。 可能な最大値を二乗すると、次のようになります。```
(2^a - 1)^2 = 2^(2a) - 2^(a+1) + 1
```この値は少なくとも`2^b`いつでも`2a > b`、つまり、中に収まらなくなったということです。`b`ビット。 

したがって、問題全体は、次のような 2 つのデータ型サイズを見つけることに帰着します。```
a < b < 2a
```ソート後、そのようなペアがどこかに存在する場合は、隣接する個別の値の間にも 1 つ存在する必要があります。 仮定する`(a[i], a[j])`で有効です`i < j`。 配列はソートされているため、次のようになります。```
a[i+1] ≤ a[j] < 2a[i]
```したがって、隣接するペアは`(a[i], a[i+1])`すでに十分です。 有効な構成をすべて検出するには、隣接するペアをチェックするだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    for i in range(n - 1):
        if a[i] < a[i + 1] and a[i + 1] < 2 * a[i]:
            print("YES")
            return

    print("NO")

solve()
```最初の部分は入力を読み取り、データ型のサイズを並べ替えます。 並べ替えは、検索対象を隣接する値に減らすことができるため、最適化の基礎です。 

ループは隣接するペアのみをチェックします。 条件:```
a[i] < a[i + 1]
```ステートメントによれば無効な等しいデータ型サイズをフィルターで除外します。 

2 番目の条件:```
a[i + 1] < 2 * a[i]
```数学的導出から直接得られます。 この不等式が成り立つ場合、ある数値は次のようになります。`a[i]`ビットには、以上のものを必要とする正方形があります。`a[i+1]`ビット。 

この実装では実際の 2 の累乗は決して計算されないため、データ型のサイズがこの値に達した場合でもオーバーフローのリスクはありません。`10^9`。 

問題はそのようなペアが存在するかどうかのみを尋ねるため、有効なペアが 1 つ見つかった後、解決策はすぐに終了します。

def run(inp: str) -> str:

    backup_stdout = sys.stdout

    sys.stdin = backup_stdin

 ## 特殊なケース

 すべてのデータ型のサイズが等しい場合を考えてみましょう。 

入力：```
4
5 5 5 5
```ソート後も配列は変わりません。 すべての隣接するペアは厳密な比較に失敗します。```

```したがって、アルゴリズムは成功条件に入ることはなく、次のように出力します。`"NO"`。 

これにより、より大きなデータ型が実際にさらに大きくなければならないという要件が処理されます。 

ここで、正確な倍加境界を考えてみましょう。 

入力：```
2
16 32
```アルゴリズムは以下をチェックします。```
32 < 2 * 16
32 < 32
```それは誤りです。 

出力は`"NO"`32 ビット データ型は、すべての 16 ビット数値の 2 乗を含むのに十分な大きさであるためです。 

最後に、元の入力で有効なペアが隣接していない場合を考えてみましょう。 

入力：```
5
100 3 8 20 5
```並べ替え後:```
[3, 5, 8, 20, 100]
```アルゴリズムは隣接するペアをチェックします。```
5 < 6
```これは true なので、すぐに出力されます`"YES"`。 

これは、並べ替えが重要である理由を示しています。 元の順序では関係が隠されていますが、並べ替えられた順序では、各値の最小のより大きいデータ型が明らかになります。
