 ## 解決策
 ## 問題の理解

 最終的な長さの配列が与えられます`n`これは、ラベルを増やしてセグメントを繰り返しペイントすることによって生成されました。`1`に`q`。 その間、`i`- 回目の操作では、選択したセグメントが値で完全に上書きされます。`i`、後の操作により以前の操作が上書きされる可能性があります。 すべての位置は少なくとも 1 つのセグメントによってカバーされていることが保証されているため、最終的にはすべてのインデックスがそのインデックスにアクセスした最後の操作の値を保持します。 

すべての操作の後、いくつかの位置は、次の間の固定数として明らかになります。`1`そして`q`、他のものは非表示になり、次のように表示されます。`0`。 ゼロは真の値が不明であることを意味しますが、次のいずれかの整数でなければなりません。`1`に`q`。 

タスクは、すべてのセグメントのシーケンスが存在するかどうかを判断することです。`q`これらの制約と一致する配列を生成する操作を実行し、そうであれば、有効な最終配列を構築します。 

重要な問題は、値が_最後のペイント時間_を表すことです。 価値のあるポジション`x`オペレーションに属している必要があります`x`のセグメントであり、後でいかなる操作によっても上書きされてはなりません`> x`。 これにより、すべてのインデックスにわたってグローバルな一貫性制約が導入されます。 

制約は大きく、`n, q ≤ 2 * 10^5`これにより、セグメントに対する二次推論やクエリごとのシミュレーションの繰り返しが除外されます。 どのソリューションも、各位置を一定回数処理し、操作ごとのシミュレーションではなく間隔構造に依存する必要があります。 

固定値によって互換性のないセグメントの順序付けが強制される場合、微妙な失敗例が発生します。 たとえば、後のラベルが、前のラベルに強制的に属する領域内に厳密に出現する場合、後の操作のセグメントでその領域を完全に回避する必要がありますが、その領域に後のラベルの必須の出現が含まれている場合、これは不可能な場合があります。 

もう 1 つの注意が必要なケースは、「最後の出現」制約に違反しているかどうかを隠すようにゼロが配置されている場合です。 例えば、`a = [1, 0, 1]`大きい`q`無害に見えるかもしれませんが、構築されたセグメントが`1`両端をカバーし、後で強制される値との重複を避ける必要があるため、配置によっては実現可能性が損なわれる可能性があります。 

## アプローチ

 強引なアイデアは、すべてのセグメントを直接構築してみることです。 それぞれの値について`i`で終わる必要があるすべての位置をカバーするセグメントの選択を試みることができます。`i`より大きい異なる値に固定された位置は避けてください。`i`。 これにより、セグメント エンドポイントの多くの組み合わせを試行することになり、最悪の場合、それぞれの`q`操作は可能性があります`O(n^2)`複数の操作を組み合わせると、指数関数的または少なくとも 3 次的な動作が得られます。 これはまったく不可能です`2 * 10^5`。 

視点を逆にすると問題の構造は単純になります。 値を作成するセグメントについて考える代わりに、各値に何が必要かについて考えることができます。 値の場合`i`最終配列に出現し、その後すべての位置に値が含まれます`i`操作のために選択されたセグメント内に存在する必要があります`i`。 また、ポジションに価値がある場合、`j > i`、その後操作`i`妨げる場合には、その位置に手を伸ばしてはなりません`j`最後の上書きから。 これは、それぞれの値が`i`自然に、すべての発生をカバーする最小間隔が生じます。 

これらの最小間隔が特定されると、主な問題は、すべての間隔に割り当てることができるかどうかになります。`i`これらの間隔を尊重しつつ、完全なカバレッジを保証するセグメント。 重要な点は、セグメントを自由に拡大できるが、必要なオカレンス以下に縮小することはできないということです。 これにより問題は、有効な上書きシーケンスを形成するように間隔をチェックし、場合によっては延長することに変わります。 

各値の最小境界間隔を構築します。 次に、後の値が以前に強制された構造と矛盾しないことを確認します。 値が表示される場合、その間隔は有効である必要があり、必須のカバレッジ制約の欠如によって「壊れ」てはいけません。 ゼロは、許容範囲内の任意の値に戦略的に割り当てることができるため、必要に応じていつでもギャップを埋めるために使用できます。

 ## アルゴリズムのチュートリアル

 各値を連続した要件を定義するものとして扱うことで、ソリューションを構築します。 

1. まず、すべてのゼロをプレースホルダー値に置き換えます。 ゼロは何にでもなれるため、一時的に柔軟なものとして扱い、後で割り当てます。 
2. の各値について`1`に`q`、配列内の左端と右端の出現を計算します。 これにより最小間隔が得られます`[L[i], R[i]]`操作に有効なセグメント`i`カバーしなければなりません。 
3. 内部のすべての位置について、`[L[i], R[i]]`、すでに次のいずれかに等しい`i`またはゼロです。 異なる固定値が見つかった場合`i`この間隔内で、その後の操作`i`禁止された位置を上書きする必要があり、後で元に戻すことはできないため、構築は失敗します。 
4. 次に、各操作に実際のセグメントを割り当てます。 から始めます`i = 1`に`q`のセグメントを設定します`i`まさに`[L[i], R[i]]`。 これより大きなセグメントは不必要な制約を導入するだけであるため、これで十分です。 
5. 塗装プロセスをシミュレートして、最終的なアレイを構築します。 空の配列から開始して操作を順番に適用し、指定されたとおりにセグメントを上書きします。 このシミュレーション中、ゼロは最後に書き込まれたものと一致する値として扱われます。 
6. 最後に、すべての位置が少なくとも 1 回カバーされていることを確認します。これは、すべての間隔が有効で空でないカバレッジが存在する場合に構築によって保証されます。 

### なぜ効果があるのか

 正確さは、各値の最後に出現した値によって、後の操作では変更できない必須領域が決定されるという事実に基づいています。 最小限の境界間隔を使用することで、必要な位置が失われないようにします。 後の操作は上書きするだけであり、以前の間隔が競合する固定値に強制的に拡張されることはないため、順序付けの制約は保持されます。 制約に違反することなく、任意のゼロを任意の区間に吸収できるため、実現可能性はこれらの境界区間の一貫性によって決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    L = [n] * (q + 1)
    R = [-1] * (q + 1)
    present = [False] * (q + 1)

    # compute bounds
    for i, v in enumerate(a):
        if v != 0:
            present[v] = True
            L[v] = min(L[v], i)
            R[v] = max(R[v], i)

    # check feasibility of fixed constraints
    for v in range(1, q + 1):
        if not present[v]:
            continue
        for i in range(L[v], R[v] + 1):
            if a[i] != 0 and a[i] != v:
                print("NO")
                return

    # build segments
    segL = [0] * (q + 1)
    segR = [0] * (q + 1)

    for v in range(1, q + 1):
        if present[v]:
            segL[v] = L[v]
            segR[v] = R[v]
        else:
            segL[v] = 0
            segR[v] = 0

    # simulate painting
    res = [0] * n
    for v in range(1, q + 1):
        l, r = segL[v], segR[v]
        for i in range(l, r + 1):
            res[i] = v

    # final check coverage
    if any(x == 0 for x in res):
        print("NO")
        return

    print("YES")
    print(*res)

if __name__ == "__main__":
    solve()
```実装では、まず各ラベルの必須範囲を抽出します。 これらの範囲は観察された出来事から直接得られ、避けられない制約を表します。 範囲内に矛盾があると、そのインスタンスは即座に拒否されます。 

その後、各値に最小間隔が割り当てられます。 これにより、人為的な競合が発生する可能性があるセグメントの過度の拡張が回避されます。 シミュレーション ステップでは、すべての制約と一致する 1 つの有効な最終構成を構築します。 

最終的な検証では、構築された配列にペイントされていない位置がないことが確認されます。 これにより、値が決して出現せず、意味のあるセグメントが割り当てられなかったケースが捕捉されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    return solution(inp)

def solution(inp: str) -> str:
    data = inp.strip().split()
    n, q = map(int, data[:2])
    a = list(map(int, data[2:]))

    L = [n] * (q + 1)
    R = [-1] * (q + 1)
    present = [False] * (q + 1)

    for i, v in enumerate(a):
        if v:
            present[v] = True
            L[v] = min(L[v], i)
            R[v] = max(R[v], i)

    for v in range(1, q + 1):
        if present[v]:
            for i in range(L[v], R[v] + 1):
                if a[i] and a[i] != v:
                    return "NO"

    res = [0] * n
    for v in range(1, q + 1):
        if present[v]:
            for i in range(L[v], R[v] + 1):
                res[i] = v

    if any(x == 0 for x in res):
        return "NO"

    return "YES\n" + " ".join(map(str, res))

 ## 特殊なケース

 値が 2 つの互いに素な領域に出現する場合、まれなケースが発生します。 例えば、`1 0 2 0 1`。 アルゴリズムは間隔を構築します`[0, 4]`価値のために`1`、これには他の値が存在する領域が含まれます。 その間隔内の固定値が異なる場合、構築はそれを直ちに拒否します。 これにより、分離されたコンポーネントの無効な結合が防止されます。 

もう 1 つのケースは、値が表示されない場合です。 例えば、`0 0 0`大きい`q`。 アルゴリズムは空の間隔を割り当てますが、これらのラベルは最終的な構築を制約しません。 それらは単に未使用または簡単に割り当てられたセグメントになるため、不可能なカバレッジを強制することがなくなります。 

3 番目のケースは、次のように、矛盾する固定値の間にゼロが位置する場合です。`1 0 2`。 ここでは、両方の値が分離されており、その間隔が重複していないため、競合することなく各値を独自のセグメントに配置することで代入が成功します。
