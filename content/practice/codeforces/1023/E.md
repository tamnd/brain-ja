 ## 解決策
 ## 問題の理解

 私たちには未知のものが与えられている$n \times n$各セルが開いているかブロックされているグリッド。 セルから右隣または下隣への移動は、移動先のセルが開いている場合にのみ許可されます。 目標は、左上のセルから右下のセルまでの有効なパスを正確に決定することです。$n-1$下に移動して、$n-1$右に移動します。 

問題は、グリッドを直接見ることができないことです。 代わりに、2 つのセルが与えられた場合に、長方形の到達可能性をクエリできます。$(r_1, c_1)$そして$(r_2, c_2)$、最初から 2 番目までのグリッド内に単調なパス (右/下への移動のみ) が存在するかどうかがわかります。 ただし、クエリは制限されています。クエリ対象のエンドポイント間のマンハッタン距離は少なくとも$n-1$これにより、任意の小さな部分問題をチェックすることができなくなります。 

この問題により、少なくとも 1 つの有効なパスが$(1,1)$に$(n,n)$存在します。 そのようなパスは、最大でも次の値を使用して再構築する必要があります。$4n$クエリ。 

素朴な誤解は、これをクエリ後に完全に可視化された最短経路の問題として扱うことです。 小さな領域をローカルに調査できないため、これは失敗します。 たとえば、右に行くか下に行くかを決めようとしているとします。$(1,1)$チェックすることで$(2,2)$違法な場合$n > 3$マンハッタン距離の制約により、そのようなきめの細かいクエリがブロックされるためです。 

最大の問題は、ローカルな決定が直接観察できないことです。 すべてのクエリは長距離にわたる必要があるため、グローバルに推論し、構造化されたステップで不確実性を軽減する必要があります。 

## アプローチ

 強引なアイデアは、すべてのセル ペアの到達可能性を再構築するか、接続性を繰り返しクエリすることで未知の空きセル上で BFS をシミュレートすることです。 これは不可能です。なぜなら、到達可能性チェックを 1 回行うだけでも高価で制限があり、次のことが必要になるからです。$\Theta(n^2)$州をはるかに超えています$4n$クエリ制限。 

重要な構造的洞察は、グリッドを完全に再構築する必要はなく、到達可能なすべての状態を知る必要さえないということです。 左上から右下への単調なパスが 1 つだけ必要です。 有効なパスはすべて次のもので構成されます。$n-1$右に移動して、$n-1$は下に移動するため、プレフィックスを宛先に確実に拡張できるようにしながら、各ステップの方向を決定することが問題となります。 

局所的な実現可能性をチェックする代わりに、一定数のステップ後に到達可能なセルのフロンティアを維持します。 どの時点でも、すべての有効なパスは「レイヤー」上にあります。$r + c$は一定です。 大きな四角形のクエリを使用して、候補の次のセルから目的地までのパスが存在するかどうかをテストできます。これはマンハッタン制約により許可されています。 これにより、方向を選択することでグローバルな到達可能性が維持されるかどうかを判断できます。 

貪欲に道を築いていきます$(1,1)$に$(n,n)$、そして各ステップで右または下に移動してみて、どのオプションが目的地に到達できるかを確認します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース（グローバル再構築） |$O(n^2)$クエリ |$O(n^2)$| 遅すぎる |
 | 到達可能性のクエリに貪欲 |$O(n)$クエリ |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 このソリューションでは、パスを段階的に構築し、常に右下隅までの有効な単調ルート内に留まります。 

1. セルから開始$(1,1)$そして文字列を維持します$S$答えのパスについては。 正確に追記させていただきます$2n-2$動く。 
2. 各ポジションで$(r,c)$、次の 2 つの可能な動きを考えてみましょう。$(r, c+1)$そして下まで$(r+1, c)$グリッド内に留まる限り。 
3. どちらかを決定するために、右に移動しても到達できるかどうかをテストします。$(n,n)$。 からのパスが存在するかどうかを尋ねます。$(r, c+1)$に$(n,n)$グリッドの内側。 これは、単一の長方形のクエリを使用して行われます。 
4. 正しい手が有効な場合 (答えが YES)、それを採用します。 そうでなければ、私たちは下に行かなければなりません。 完全なパスが存在することが保証されるため、2 つの方向のうちの少なくとも 1 つが常にエンドポイントに到達可能な状態に保たれます。 
5. 選択した動きを追加します。$S$、現在のセルを更新し、到達するまで繰り返します。$(n,n)$。 
6. 構築された文字列を出力します。 

重要な考え方は、すべてのステップが世界的な実現可能性を維持するということです。 現在位置と目的地を切り離すような動きは決して選びません。 

### なぜ効果があるのか

 任意の時点で、からの有効な単調パス上にあるセルにいると仮定します。$(1,1)$に$(n,n)$。 そのパスは、現在のセルから右または下に継続する必要があります。 両方の可能性をテストすると、少なくとも 1 つが目的地への到達可能性を維持します。 大きな四角形に対する到達可能性クエリは、そのような継続が存在するかどうかを正確に検出するため、貪欲な選択によって有効な補完がすべて削除されることはありません。 この不変条件により、最後まで少なくとも 1 つの有効なパスに常に留まることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
print = sys.stdout.write

def ask(r1, c1, r2, c2):
    sys.stdout.write(f"? {r1} {c1} {r2} {c2}\n")
    sys.stdout.flush()
    return sys.stdin.readline().strip()

def solve():
    n = int(input().strip())
    
    r, c = 1, 1
    path = []

    for _ in range(2 * n - 2):
        if r < n:
            res = ask(r + 1, c, n, n)
            if res == "YES":
                path.append('D')
                r += 1
                continue

        path.append('R')
        c += 1

    sys.stdout.write("! " + "".join(path) + "\n")
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```コードは現在の位置を維持し、応答文字列を段階的に構築します。 機能`ask`インタラクション処理をラップし、クエリごとにフラッシュを保証します。これはインタラクティブな問題では重要です。 

決定ロジックでは常に、下に移動することで到達可能性が維持されるかどうかのチェックが優先されます。$(n,n)$。 そうでない場合は、デフォルトで右に移動します。 この順序は任意です。 一貫性が維持されている限り、方向の交換も機能します。 

ループは正確に実行されます$2n-2$必要なパス長と一致するステップ。 各ステップにより、残りの行距離または列距離のいずれかが減少し、終了が保証されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、2 番目の行への 1 つの強制的なエントリを除いて、1 番目の行がほとんどブロックされている場合です。 このアルゴリズムは、下方向への移動をテストするたびに、強制列に到達するまでクエリがすぐに NO を返し、唯一の実行可能な遷移まで右への移動を強制するため、これを処理します。 

もう 1 つのケースは、最適なパスの方向が頻繁に切り替わる場合です。 各決定は独立しており、最終セルへの到達可能性に基づいているため、アルゴリズムは、局所的には最適だが全体的には無効な選択にコミットすることはありません。 継続が存在するかどうかのみがチェックされるため、実現可能性が維持されます。 

最後のケースは、初期段階で両方の動きが可能であるように見える場合です。 貪欲ルールは任意に 1 つを選択します (この実装では下にあります)。 これにより水平方向の迂回が長くなったとしても、到達可能性クエリは目的地を分離する移動のみを拒否するため、不変条件により完全なパスが依然として存在することが保証されます。
