 ## 解決策
 ## 問題の理解

 完全に規則的なおもちゃの価格の範囲が与えられます。おもちゃの価格は 1 から n まであり、各整数の価格は 1 回だけ表示されます。 私たちは、合計価格が k に正​​確に等しい、異なるおもちゃの順序付けされていないペアがいくつあるかを数えたいと考えています。 各ペアは、1 ≤ a < b ≤ n および a + b = k である 2 つの異なる整数 a および b によって決定されます。 

出力は単にそのような有効なペアの数です。 

制約は極端で、n と k は両方とも 10^14 まで大きくすることができます。 これにより、さまざまなおもちゃを反復するアプローチは即座に排除されます。 最大 n までの線形スキャンには最大 10^14 の操作が必要ですが、これは実行可能な制限時間をはるかに超えています。 対数または n 内多項式のアプローチも不要です。 問題の構造は、ドメイン全体の反復を避け、代わりに有効なペアについて代数的に推論する必要があることを示唆しています。 

ここで最も一般的な微妙な失敗のケースは、境界処理に起因します。 単純な試みでは、有効なパートナー b = k - a を計算し、b も [1, n] に含まれるように [1, n] 内のすべての a をカウントする可能性があります。 この間違いは、ペアが a < b を満たす必要があることを忘れた場合に発生します。そうでない場合、ペアは二重にカウントされます。 もう 1 つの一般的なエラーは、a = b を許可する場合に発生します。これは、k が偶数で a = k/2 の場合にのみ発生します。 たとえ範囲内であっても除外する必要があります。 

たとえば、n = 8 および k = 5 の場合、有効なペアは (1, 4) と (2, 3) です。 a < b を強制せずにすべての有効な a をカウントする不注意な実装では、(1, 4) と (4, 1) の両方がカウントされ、答えが 2 倍になります。 同様に、n = 10 および k = 10 の場合、明示的に除外しない限り、ペア (5, 5) が誤って含まれてしまいます。 

## アプローチ

 ブルートフォースのアイデアは簡単です。最初に考えられるすべてのおもちゃ a を 1 から n まで試し、b = k - a を計算し、b が [a + 1, n] にあるかどうかを確認します。 これは、すべての制約を直接強制するため、正しいです。 ただし、すべての n 値を反復処理する必要があるため、時間計算量は O(n) となり、n が 10^14 までの場合は不可能になります。 

重要な観察は、a が固定されると b は完全に決定されるということです。したがって、問題は実際には、2 つの不等式を同時に満たす有効な整数 a を数えることです。b = k - a は [1, n] 内になければならず、また a < b も成立しなければなりません。 これらの条件は、問題を交差する整数区間に変換します。 

b = k - a から、制約 1 ≤ b ≤ n は 1 ≤ k - a ≤ n になり、k - n ≤ a ≤ k - 1 に再配置されます。制約 a < b は a < k - a、または同等の 2a < k になります。これは、a ≤ (k - 1) // 2 を意味します。最後に、すでに次の式から 1 ≤ a ≤ n が得られます。 有効なおもちゃの定義。 

したがって、 a は 3 つの区間の交点になければなりません。 

1 ≤ a ≤ n

 k - n ≤ a ≤ k - 1

 1 ≤ a ≤ (k - 1) // 2

 この交差部分がわかれば、答えは単純にその中の整数の数、つまり max(0, R - L + 1) になります。

 ## アルゴリズムのチュートリアル

 1. 有効な a 値の下限を L = max(1, k - n) として計算します。 これにより、b = k - a が n を超えないことが保証されます。 
2. 有効な a 値の上限を R = min(n, k - 1) として計算します。 これにより、b が少なくとも 1 になることが保証されます。 
3. 上限を R = min(R, (k - 1) // 2) に厳しくすることで、区別条件 a < b を強制します。 
4. L > R の場合、すべての制約を満たす有効な整数は存在しないため、答えは 0 になります。 
5. それ以外の場合、有効な a の数は R - L + 1 です。 

これらのステップがこのように順序付けされている理由は、各制約が a の可能な値を独立して制限するためです。 すべての有効な間隔の交差を取得すると、すべての条件を同時に満たすペアを正確にカウントできることが保証されます。 

### なぜ効果があるのか

すべての有効なペア (a, b) は、正確に 1 つの整数 a に対応し、a は導出されたすべての不等式を満たさなければなりません。 逆に、最後の区間のすべての整数 a は、範囲内にあり厳密に a より大きい一意の有効な b = k - a を生成します。 この変換により、元の組み合わせ計数の問題が 1 つの間隔内の整数点を計数する問題に縮小され、このマッピングでは有効な構成が失われたり重複したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

L = max(1, k - n)
R = min(n, k - 1)
R = min(R, (k - 1) // 2)

ans = max(0, R - L + 1)
print(ans)
```コードは、アルゴリズムで導出された区間交差を直接実装します。 最初の境界は、2 番目のおもちゃが最大価格 n 内に存在することを強制します。 2 番目の方法では、確実に a と b が順序付け形式で区別されるようにします。 3 番目は a < b を強制し、対称の重複と無効な中間点のケースを削除します。 

実装の微妙な詳細は、制約を適用する順序です。交差は数学的に可換ですが、対称制約を最後に適用すると、k が偶数の場合に k/2 などの無効な中点値を誤ってカウントすることが回避されます。 

## 実用的な例

 ### 例 1

 入力: n = 8、k = 5

 | ステップ | Ｌ | R (対称前) | R (対称後) |
 | --- | --- | --- | --- |
 | イニシャル | 1 | 4 | 2 |

 L = max(1, 5 - 8) = 1 を計算します。 R は min(8, 4) = 4 として開始します。 次に、対称性を適用します: (k - 1) // 2 = 2 なので、R は 2 になります。 最終的に有効な a 値は {1, 2} で、ペア (1, 4) と (2, 3) が生成されます。 

これは、interval メソッドがすべての有効なペアをキャプチャしながら、逆のペアまたは無効なペアのカウントを正しく回避していることを確認します。 

### 例 2

 入力: n = 10、k = 10

 | ステップ | Ｌ | R (対称前) | R (対称後) |
 | --- | --- | --- | --- |
 | イニシャル | 1 | 9 | 4 |

 ここで、L = max(1, 10 - 10) = 1 です。対称前の R は min(10, 9) = 9 です。対称を適用した後は、R = 4 です。有効な a 値は {1, 2, 3, 4} で、ペア (1,9)、(2,8)、(3,7)、(4,6) に対応します。 無効な中間点 (5,5) は自動的に除外されます。 

これは、条件 a < b が明示的なチェックではなく境界のみによってどのように強制されるかを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import *
    n, k = map(int, sys.stdin.readline().split())

    L = max(1, k - n)
    R = min(n, k - 1)
    R = min(R, (k - 1) // 2)

    return str(max(0, R - L + 1))

# provided samples
assert run("8 5\n") == "2"

# k too small
assert run("10 1\n") == "0"

# only one valid pair
assert run("10 19\n") == "1"

# midpoint excluded case
assert run("10 10\n") == "4"

# large symmetric case
assert run("1000000000000 1000000000001\n") == "500000000000"

 ## 特殊なケース

 重要なエッジ ケースは、k が小さい場合、具体的には k ≤ 2 の場合です。この状況では、k - n は常に ≤ 0 であるため、L は 1 になりますが、R は min(n, k - 1) になり、最大でも 1 になります。k = 1 または k = 2 の場合、R ≤ 1 で、a < b を強制した後、R は 0 になり、空の区間が生成されます。 アルゴリズムは正しく 0 を返します。 

もう 1 つの重要なケースは、k が n に比べて非常に大きい場合です。たとえば、n = 5 および k = 100 です。この場合、k - n = 95 なので、L = 95、R = min(5, 99) = 5 となります。L > R であるため、区間は空であり、正しく 0 が得られます。これは、[1, n] 内の 2 つの数値の合計がそのような大きな k にならないことを反映しています。 

最後の微妙なケースは、k が偶数で、k/2 が [1, n] 内にある場合です。 たとえば、n = 10、k = 10 では中間点 5 が得られます。区間の構築には最初は a = 5 が含まれますが、R ≤ (k - 1) // 2 を強制するとそれが削除されます。 これにより、無効な自己ペア (5, 5) がカウントされないことが保証され、特殊な場合の分岐が発生することなく正確さが維持されます。
