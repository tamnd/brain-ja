 ## 解決策
 ## 問題の理解

 任意の配列に対して$x$、その接頭辞最大値のシーケンスは完全に決定されます。 位置で$i$、プレフィックスの最大値は$$\max(x_1,x_2,\dots,x_i).$$別の配列を構築することができます$z$その接頭辞の最大値は次のものと同じです$x$。 このような配列すべての中で$z$、ポジションの数を最大化したいと考えています。$z_i=y_i$。 その最大値はと呼ばれます$f(x,y)$。 

実際のタスクはさらに大きくなります。 2 つの配列が与えられています$a$そして$b$長さの$n$。 すべてのサブ配列について$[l,r]$、私たちは形成します$$x=a_l,a_{l+1},\dots,a_r,$$そして$$y=b_l,b_{l+1},\dots,b_r.$$合計しなければなりません$f(x,y)$すべてのサブ配列にわたって。 

最初の課題は、プレフィックスの最大値を維持しながら、単一の位置でどのような値が許可されるかを理解することです。 2 番目の課題は、明白なことを避けることです$O(n^2)$部分配列の列挙。 

すべてのテスト ケースの合計の長さは最大でも$2\cdot 10^5$。 二次アルゴリズムはおおよそのパフォーマンスを発揮します$4\cdot 10^{10}$最悪の場合の操作は完全に不可能です。 に近いものが必要です$O(n \log n)$。 

現在のプレフィックスの最大値に等しい値が以前にすでに発生していた場合、微妙なエッジ ケースが発生します。 

考慮する：```
a = [2, 2]
b = [0, 1]
```2 番目の位置については、次のように設定できます。$z_2=1$、最初の要素がすでにプレフィックスの最大値を次の値に保持しているためです。$2$。 厳密に大きい以前の値のみを探す不注意な解決策は、このケースを誤って拒否することになります。 

もう 1 つの重要なケースは次のような場合です。$b_i$よりも大きいです$a_i$。```
a = [5, 1]
b = [0, 4]
```2 番目の位置は次のようになります。$4$以前の値があるという理由だけで$5$これにより、プレフィックスの最大値は変更されません。 そのような以前の値がなければ、増加します$z_i$プレフィックスの最大シーケンスが変更されます。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべてのサブ配列を列挙する$[l,r]$。 その部分配列について、一致できる位置の最大数を決定します。 たとえ 1 つのサブ配列を線形時間で処理したとしても、すでに$O(n^2)$サブ配列、結果として$O(n^3)$仕事。 

ブルートフォースが概念的に機能する理由は次のとおりです。$f(x,y)$は、それぞれの立場での独立した決定の合計にすぎません。 位置かどうか$i$と等しくすることができます$y_i$は、その位置より前のプレフィックスの最大構造のみに依存します。 

この観察が鍵となります。 

1 つの位置を調べてみるとします$i$一部のサブ配列内。 

もし$a_i=b_i$の場合、何も変更せずにすでに一致しています。 

もし$a_i\neq b_i$、いつ強制できますか$z_i=b_i$?

 させて$M$位置の前のプレフィックスの最大値になります$i$。 

もし$M\ge \max(a_i,b_i)$、その後は自由に選択できます$z_i=b_i$。 以前のプレフィックス最大値が依然として優勢であるため、プレフィックス最大シーケンスは変わりません。 

以前の値に達しない場合$\max(a_i,b_i)$、次に位置を決めます$i$それ自体が新しい最大値を作成する責任があり、その値は制限されます。 その状況で$z_i=b_i$不可能です。 

したがって、次のいずれかが当てはまる場合に、ポジションは正確に寄与します。 

-$a_i=b_i$。 
- 値が少なくとも次の以前の要素が存在します。$\max(a_i,b_i)$。 

ここで、すべてのインデックスについて、問題は深刻になります。$i$、この条件が真になるサブ配列の数。 

させて$$T_i=\max(a_i,b_i).$$定義する$p_i$前の右端のインデックスとして$i$その値は少なくとも$T_i$。 

そのようなインデックスが存在しない場合は、$p_i=0$。 

以下を含む任意の部分配列に対して$i$、 位置$i$左のエンドポイントがその前またはその前にある場合に寄与します$p_i$。 その後、その条件を満たす前の要素はサブ配列内に残ります。 

つまり、ポジションの貢献度は$i$は：

-$i(n-i+1)$もし$a_i=b_i$。 
-$p_i(n-i+1)$さもないと。 

残っている唯一のタスクは、次の条件を計算することです。$p_i$効率的に。 

配列を左から右に処理します。 それぞれの値について、それが出現した最新の位置を保存します。 見つけるには$p_i$、少なくともすべての値の中で最大の格納位置が必要です$T_i$。 

すべての値が最大であるため、$2n$、値座標上のセグメント ツリーは以下をサポートします。 

- ポイント更新: 値の最新の位置、
 - 範囲最大クエリ$[T_i,2n]$。 

これにより、$O(\log n)$インデックスごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |

 | 最適 |$O(n\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を左から右に処理します。 
2. ポジションについて$i$、計算する$$T_i=\max(a_i,b_i).$$3. 値の範囲についてセグメント ツリーをクエリします。$[T_i,2n]$。 

結果は、値が少なくとも次の右端にある前のインデックスです。$T_i$。 電話してください$p$。 
4. もし$a_i=b_i$、 追加$$i\cdot(n-i+1)$$答えに。 

を含むすべてのサブ配列$i$このポジションで貢献しています。 
5. それ以外の場合は追加します$$p\cdot(n-i+1).$$任意の開始位置$l\le p$サブ配列内の条件を満たす前の要素とすべての終了位置を保持します。$r\ge i$有効です。 
6. 現在の値を挿入します$a_i$座標を更新してセグメント ツリーに追加する$a_i$ポジション付き$i$。 
7. すべての位置が処理されるまで続行します。 

### なぜ効果があるのか

 固定サブ配列と固定位置の場合、重要なのは、そのサブ配列内の以前の要素がすでに到達しているかどうかだけです。$\max(a_i,b_i)$。 

このような要素が存在する場合、その前のプレフィックスの最大値は、$i$すでに十分な大きさです。 私たちは自由に選ぶことができます$z_i=b_i$プレフィックスの最大値には影響しません。 

そのような要素が存在しない場合は、位置を指定します。$i$それ自体がプレフィックスの最大レベルを決定します。 に変更します$b_i\neq a_i$プレフィックスの最大シーケンスを変更することになるため、これは禁止されています。 

したがって、各ポジションは独立して貢献します。 有効な左端点の数は正確に次のとおりです$p_i$、有効な右エンドポイントの数は$n-i+1$。 すべてのポジションにわたるこれらの貢献を合計すると、必要な合計が正確に計算されます。 

セグメント ツリーはすべてのセグメントを計算します。$p_i$これは常に、厳密に以前の位置間のすべての値の最新の出現を保存するため、正確です。$i$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.seg = [0] * (4 * n)

    def update(self, idx, val, node, l, r):
        if l == r:
            self.seg[node] = max(self.seg[node], val)
            return

        mid = (l + r) >> 1
        if idx <= mid:
            self.update(idx, val, node * 2, l, mid)
        else:
            self.update(idx, val, node * 2 + 1, mid + 1, r)

        self.seg[node] = max(
            self.seg[node * 2],
            self.seg[node * 2 + 1]
        )

    def query(self, ql, qr, node, l, r):
        if ql <= l and r <= qr:
            return self.seg[node]

        mid = (l + r) >> 1
        res = 0

        if ql <= mid:
            res = max(res, self.query(ql, qr, node * 2, l, mid))
        if qr > mid:
            res = max(res, self.query(ql, qr, node * 2 + 1, mid + 1, r))

        return res

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        mx = 2 * n
        seg = SegTree(mx)

        ans = 0

        for i in range(1, n + 1):
            ai = a[i - 1]
            bi = b[i - 1]

            if ai == bi:
                ans += i * (n - i + 1)
            else:
                threshold = max(ai, bi)
                p = seg.query(threshold, mx, 1, 1, mx)
                ans += p * (n - i + 1)

            seg.update(ai, i, 1, 1, mx)

        print(ans)

solve()
```セグメント ツリーは、位置ではなく値によってインデックス付けされます。 価値のあるもの$v$、最新のインデックスを保存します。$a_j=v$これまで登場してきました。 

クエリは終了しました$[T_i,2n]$少なくとも以前のすべての値の中で最大の位置を返します$T_i$。 まさにその通りです$p_i$。 

よくある間違いは、最新の出現ではなく最初の出現を使用することです。 最も右側の適格なインデックスが必要です。そのインデックスまでのすべての開始位置が機能し、正確な結果が得られるためです。$p_i$選択肢。 

もう 1 つの簡単なバグは、値が次の値に制限されていることを忘れることです。$2n$ではなく、$n$。 セグメント ツリーは値の範囲全体をカバーする必要があります。 

Python の整数は、回答のサイズを自動的に処理します。 寄与するサブ配列の総数はおよそに達する可能性があります$n^3$そのため、32 ビット整数は多くの言語でオーバーフローします。

## 特殊なケース

 次のことを考慮してください。```
a = [2, 2]
b = [1, 1]
```2 番目の位置では、しきい値は次のようになります。$2$。 セグメント ツリー クエリはインデックスで以前の出現箇所を検索します。$1$、 それで$p=1$。 このアルゴリズムは、有効なサブ配列を 1 つカウントします。 

そのサブ配列内では、最初の値によってプレフィックスの最大値がすでに維持されています。$2$、2 番目の値が次のようになります。$1$。 このため、条件は「厳密に大きい」ではなく「少なくとも」である必要があります。 

ここで次のことを考えてみましょう。```
a = [5, 1]
b = [0, 4]
```2 番目の位置のしきい値は次のとおりです。$4$。 クエリはインデックスを見つけます$1$、 以来$5 \ge 4$。 したがって$p=1$、そしてポジションが貢献します。 

以前の値$5$現在の値が から増加する間、プレフィックスの最大値を保持します。$1$に$4$。 

最後に次のことを考慮してください。```
a = [3, 1]
b = [0, 5]
```位置 2 のしきい値は次のとおりです。$5$。 それ以前の値には達しません$5$, したがって、クエリは次の結果を返します。$0$。 アルゴリズムは何も貢献しません。 

それは正しいです。 2 番目の値を次のように設定します。$5$新しいプレフィックス最大値が作成され、必要なプレフィックス最大シーケンスが変更されます。
