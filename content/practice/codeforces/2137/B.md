 ## 問題の理解

 順列が与えられています$p$サイズの$n$、以下の各整数が含まれることを意味します。$1$に$n$まさに一度。 別の順列を構築する必要があります$q$同じサイズの、並べ替えも$1$に$n$、隣接する位置をリンクする構造的制約を伴う。 

隣接するインデックスのペアごとに$i$そして$i+1$、次の 2 つの合計を形成します。$p_i + q_i$そして$p_{i+1} + q_{i+1}$。 要件は、これら 2 つの合計の最大公約数が少なくとも 3 であることです。言い換えると、連続するポジションは、少なくとも 3 のサイズの自明でない公約数を常に共有する合計を生成する必要があります。 

出力は単一の値ではなく、完全な順列です。$q$、有効な構造はすべて受け入れられます。 

制約により、最大で次のことが許可されます。$2 \cdot 10^5$すべてのテスト ケースにわたる要素の合計。これにより、位置のペアを考慮したり、順列を検索しようとしたりするアプローチは直ちに除外されます。 テスト ケースごとに線形または線形に近い時間を超えるものは失敗します。 

微妙な点は、条件が完全にローカルであるということです。問題となるのは隣接する位置だけです。 ただし、各立場は 2 つの制約に影響するため、一貫性を確保せずに単独で貪欲に意思決定を行うことはできません。 

素朴な間違いは、$q_i$独立して一致する$p_i$何らかの数値のモジュロは調整なしで機能する可能性があります。 たとえば、試してみると$q_i = n+1 - p_i$、gcd 条件は個々の剰余ではなく合計に依存するため、誤って一部の隣接関係を満たす可能性がありますが、他の隣接関係では失敗する可能性があります。 

のランダムな並べ替えを試みると、別の失敗モードが表示されます。$q$。 多くのランダムな構築がいくつかの局所的な gcd 制約を満たすとしても、すべてを満たす確率は$n-1$制約は同時に、大規模な場合には無視できます。$n$、そのようなソリューションは信頼できません。 

## アプローチ

 ブルートフォースの観点からは、次のようなものを構築してみることになります。$q$段階的に。 それぞれのポジションで$i$の残りの値を選択します。$q_i$条件が満たされているかどうかを確認します$i-1$満足しています。 これにより、サイズの順列を後戻りすることになります。$n$、階乗複雑度を持ちます。 枝刈りを行ったとしても、隣接関係の gcd 制約は、指数関数的な爆発を回避するのに十分なほど初期の領域を制限しません。 

重要な洞察は、個々の位置について考えるのをやめ、代わりに合計に対してグローバルな算術構造を適用することです。$p_i + q_i$。 条件$\gcd(x, y) \ge 3$両方の数値が 3 の公倍数を共有する場合、つまり両方が 3 の倍数である場合、確実に保証されます。 

これにより、問題はすべての隣接する合計が 3 を法とする同じ剰余クラスに存在すること、特にすべてが 3 で割り切れることを保証することになります。$p_i + q_i$が 3 の倍数である場合、隣接するすべての gcd は自動的に少なくとも 3 になります。 

したがって、問題は順列を構築することになります$q$それぞれの合計が$p_i + q_i$は 3 で割り切れます。これは強制と同等です。$$q_i \equiv -p_i \pmod 3.$$ここで、各数値を 1 回だけ使用しながら、これらの剰余制約を尊重する順列を構築する必要があります。 残基 mod 3 は数値を 3 つのバランスのとれたグループに分割するため、それぞれをペアにすることができます。$p_i$互換性のあるもの$q_i$対応する残基クラスから抽出されます。 この構築は剰余クラス間のマッチング問題になりますが、両側が同じ集合の順列であるため、剰余グループ内の単純な巡回シフトで十分です。 

これにより、問題は剰余クラスごとにインデックスをソートし、各クラス内で代入をローテーションすることに変わります。

 ## アルゴリズムのチュートリアル

 1. パーティションインデックス$1$に$n$に基づいて 3 つのバケットに分割されます$p_i \bmod 3$。 これはそれぞれの理由で必要です。$p_i$に必要な剰余クラスを決定します$q_i$。 
2. 同様に、値を分割します。$1$に$n$モジュロ 3 値に基づいて 3 つのバケットに分割されます。 これらは、各残基クラスの利用可能な候補を表します。$q$。 
3. 各残基クラスについて$r \in \{0,1,2\}$のインデックスをペアにします。$p$-バケット内の値$q$-バケツを順番に。 この割り当てにより、すべての$q_i$必要な残留条件を尊重します。 
4.割り当て$q_i$これらの組み合わせに従って、すべてのポジションを埋めます。 
5. 結果の順列を出力します。 

ステップ 3 と 4 の重要なアイデアは、モジュロ 3 は gcd 制約を完全に切り離すため、1 つのグローバル順列問題ではなく 3 つの独立したマッチング問題を解決するということです。 

### なぜ効果があるのか

 この構造により、すべてのインデックスに対して次のことが保証されます。$i$、合計$p_i + q_i$は 3 で割り切れます。$q_i \equiv -p_i \pmod 3$。 したがって、そのようなすべての合計は少なくとも 3 の倍数であり、その結果、すべての隣接する合計のペアは少なくとも 3 の公約数を共有します。この不変条件はすべての位置で独立して適用されるため、隣接関係がこれに違反することはできないため、グローバルに保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        
        buckets_p = {0: [], 1: [], 2: []}
        buckets_q = {0: [], 1: [], 2: []}
        
        for i, x in enumerate(p):
            buckets_p[x % 3].append(i)
        
        for v in range(1, n + 1):
            buckets_q[v % 3].append(v)
        
        q = [0] * n
        
        for r in range(3):
            for i, v in zip(buckets_p[r], buckets_q[r]):
                q[i] = v
        
        print(*q)

if __name__ == "__main__":
    solve()
```実装は残差分割戦略に直接従います。 まず、ポジションを次の値によって分類します。$p_i \bmod 3$、次に、使用可能な数値を独自のモジュロ 3 クラスによって分類します。 次に、それらを 1 対 1 の方法で照合します。 

微妙な点は、インデックス付けが位置によって行われることです。$p$、値によるものではありません。$q$位置を揃える必要があります。 もう 1 つの重要な詳細は、構築ではバケット サイズが等しいことを前提としているということです。これは次の理由から当てはまります。$p$そして$1..n$各剰余クラスに同じ数の要素が含まれます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        b0, b1, b2 = [], [], []
        for i, x in enumerate(p):
            (b0 if x % 3 == 0 else b1 if x % 3 == 1 else b2).append(i)

        c0, c1, c2 = [], [], []
        for v in range(1, n + 1):
            (c0 if v % 3 == 0 else c1 if v % 3 == 1 else c2).append(v)

        q = [0] * n
        for a, b in [(b0, c0), (b1, c1), (b2, c2)]:
            for i, v in zip(a, b):
                q[i] = v

        out.append(" ".join(map(str, q)))
    return "\n".join(out)
