 ## 解決策
 ## 問題の理解

 次のような有向非巡回グラフが与えられます。`n`ノードと`m`エッジ。 各ノードは青色で始まり、プレイヤー Cry と River が 2 プレイヤー トークン ゲームをプレイします。 トークンはノードから始まります`s`。 最初にクライが動き、次にリバーが交互に動きます。 トークンが発信エッジなしでノードに到達した場合、Cry が勝ちます。 トークンが赤いノードに到達するとリバーの勝ちとなります。 ノードが赤でターミナルの両方である場合、River が勝ちます。 

私たちは複数のクエリに答える必要があります。ノードを赤に更新するものもあれば、最適なプレイを前提として Cry が特定のノードから勝利を強制できるかどうかを尋ねるものもあります。 グラフは DAG であることが保証されており、ノード、エッジ、クエリの数はすべてのテスト ケースで合計 200,000 に達する可能性があります。 

この制約は、すべてのクエリに対してすべてのゲームをシミュレートすることはできないことを示しています。 単純なシミュレーションでは、クエリが実行されるたびにノードからの考えられるすべてのパスを調べる必要があります。 と`n`最大 2·10^5 および`q`最大 2·10^5 の場合、O(nq) 操作が発生する可能性があり、これはおよそ 4·10^10 となり、2 秒の制限には遅すぎます。 

微妙なエッジ ケースには、終端ノードであり、後で赤く塗られるノードが含まれます。 クエリすると、正しい結果はクライではなくリバーが即座に勝ちます。 また、発信エッジのないノードでは、最初は Cry がすぐに勝つことができます。 これらの条件を単純に無視すると、不正確な答えが生じる可能性があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。タイプ 2 のクエリごとに、考えられるすべての一連の動きを再帰的にシミュレートし、どのプレイヤーのターンであるかを追跡し、勝者を返します。 これが機能するのは、グラフが非周期的であるため、再帰は最終的に終了します。 ただし、最悪のケースではノードからのすべてのパスが探索され、最長パス長が指数関数的に増加する可能性があります。 更新を効率的に処理しないメモ化でも、タイプ 1 クエリが動的に色を変更すると失敗し、以前にキャッシュされた結果が無効になります。 

最適化のための重要な観察は、これが DAG であり、ノードのトポロジー的な順序付けが可能であるということです。 逆方向動的計画法を使用して各ノードの Cry の勝敗状態を計算し、値を終端ノードから上に伝播します。 発信エッジのないターミナル ノードは、最初は Cry で勝ち、赤いノードは Cry で負けています (River で勝ち)。 他のノードの場合、子ノードが次のプレイヤーに負けている場合、Cry は強制的に勝利をもたらすことができます。 これは、標準の「DAG 上のゲーム」DP またはグランディ数の計算に似ています。 

動的更新 (ノードを赤で塗る) は状況を複雑にします。 DAG は静的であるため、唯一の変化は勝敗状態が逆方向に伝播することです。 ノードが赤になると、Cry はそこで勝つことができなくなります。 この変更は、この赤いノードに到達できるノードにのみ影響するため、反転グラフのキュー (BFS スタイル) を使用して新しい状態を逆方向に伝播し、勝敗状態が変化するノードのみを更新できます。 

これにより、すべてのクエリに対して効率的なオンライン アルゴリズムが可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(クエリごとに 2^n) | O(n) | 遅すぎる |
 | 最適 | O(n + m + q) 償却 | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフを読み取り、隣接リストとその逆リストの両方を作成します。 逆隣接リストでは、ノードが赤く塗られている場合に状態変化を逆方向に伝播できます。 
2. 各ノードの状態を初期化します。 Cry では、発信エッジのないターミナル ノードが勝利を収めています。 すべての赤いノード (最初は何もありません) が Cry に負けています。 発信エッジを持つ青色のノードは、最初は未定義です。 
3. トポロジ順のボトムアップ DP を使用して、各ノードの初期の勝敗状態を計算します。 各ノードで、次のプレイヤー (つまり、リバー) に負けている子がいる場合、Cry はそこに移動することで勝つことができます。 すべての子が次のプレイヤーに勝っている場合、Cry は勝利を強制することができず、このノードは負けています。 
4. 各クエリについて:

 - タイプ 1 (ノードを赤でペイント) の場合、そのノードを Cry の負けとしてマークします。 状態が変化した場合は、その変化を反転エッジに沿って逆方向に伝播し、勝敗状態がこのノードに依存する祖先を更新します。 
- タイプ 2 (クエリ) の場合は、そのノードの Cry の現在の状態を単純に出力します。 

機能する理由: DAG はサイクルを保証しないため、すべてのノードの状態はその子孫にのみ依存します。 最初に逆のトポロジー順序で処理し、更新を逆方向に伝播することにより、常に正しい勝敗状態を維持します。 ノードを赤でペイントすると、そのノードに到達できるノードの状態が変更されるだけであり、伝播によって状態の一貫性が確保されます。 

## Python ソリューション```python
import sys
from collections import deque
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, q = map(int, input().split())
        adj = [[] for _ in range(n)]
        radj = [[] for _ in range(n)]
        outdeg = [0] * n
        
        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            radj[v].append(u)
            outdeg[u] += 1

        # 0 = unknown, 1 = Cry wins, -1 = River wins
        state = [0] * n
        queue = deque()

        # initialize terminal nodes
        for i in range(n):
            if outdeg[i] == 0:
                state[i] = 1
                queue.append(i)

        # compute initial states using BFS from terminals
        while queue:
            node = queue.popleft()
            for prev in radj[node]:
                if state[prev] != 0:
                    continue
                if state[node] == -1:
                    state[prev] = 1
                    queue.append(prev)
                else:
                    outdeg[prev] -= 1
                    if outdeg[prev] == 0:
                        state[prev] = -1
                        queue.append(prev)

        red = [False] * n

        for _ in range(q):
            tp, u = map(int, input().split())
            u -= 1
            if tp == 1:
                if red[u]:
                    continue
                red[u] = True
                if state[u] == 1:
                    state[u] = -1
                    queue = deque([u])
                    while queue:
                        node = queue.popleft()
                        for prev in radj[node]:
                            if state[prev] == 1:
                                continue
                            # check if Cry has a move to a losing node
                            can_win = any(state[v] == -1 and not red[v] for v in adj[prev])
                            if not can_win and not red[prev]:
                                state[prev] = -1
                                queue.append(prev)
            else:
                if red[u]:
                    print("NO")
                else:
                    print("YES" if state[u] == 1 else "NO")

if __name__ == "__main__":
    solve()
```説明: 端末ノードを Cry の勝利として初期化します。 BFS の伝播により、他のノードもそれに応じて設定されます。 ノードを赤く塗ると、そのノードが Cry に負けたことをマークし、リバース グラフによる逆方向伝播をトリガーして、影響を受けるすべての祖先を更新します。 その後、クエリは状態を即座に読み取ります。 微妙な点としては、ノードが負けになったときを検出するために外次数を減分することや、そこで Cry が「勝つ」ことを決して許さないように赤いノードを正しく処理することが含まれます。
