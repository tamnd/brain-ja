 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、特別な変換を複数回実行するように求められます。 配列内の各要素を、配列内の他のどこにも現れない最小の非負の整数に置き換えます。 この変換はすべての要素に同時に適用され、指定された回数だけ繰り返されます。 すべての操作の後、配列の合計が求められます。 

主な課題は、演算数が最大 10 億と非常に大きくなり、配列も最大 20 万要素と大きくなる可能性があることです。 大規模な配列を 10 億回通過するだけでも時間がかかりすぎるため、すべての操作を明示的にシミュレートするソリューションは除外されます。 

配列にゼロから最大値までのすべての整数が隙間なく含まれている場合、微妙なエッジ ケースが発生します。 その場合、各要素は最終的に最大要素に 1 を加えた値に収束します。 もう 1 つのエッジ ケースは、配列に繰り返し値が既に含まれている場合、または初期範囲に欠落している整数がある場合です。 これらの条件は、明らかではない形で変換に影響を与えます。つまり、一部の要素は 1 ステップ後に一定になる可能性がありますが、他の要素は増加する可能性があります。 

たとえば、配列を考えてみましょう。`[0, 0]`2つの操作で。 最初の演算の後、各ゼロは他のゼロを参照するため、他の要素の MEX は次のようになります。`1`。 2 回目の操作の後、両方の要素が再び互いに認識し、MEX は残ります。`1`。 収束を考慮しない単純な実装では、さらに反復することで時間が無駄になります。 

## アプローチ

 ブルート フォース アプローチでは、説明どおりに操作がシミュレートされます。 各ステップで、他のすべての要素に基づいてすべての要素の MEX を計算します。 サイズの配列の場合`n`、1 つの要素の MEX の計算には O(n) のコストがかかるため、1 つの完全なパスのコストは O(n^2) になります。 これを繰り返すと、`k`このステップは O(n^2 * k) になりますが、これは n が 2×10^5 まで、k が 10^9 までの場合は実行不可能です。 

重要な洞察は、アレイが非常に早く安定することに気づくことです。 最大 2 回の操作の後、配列は一定のままになるか、予測可能な方法で増加します。 具体的には、最初の操作は欠落している最小の数値を埋めますが、2 番目の操作では最大値と MEX の平均の上限である新しい値を 1 つしか生成できません。 その後、k が 2 より大きい場合、それ以降の演算では合計は変わりません。 

このプロパティは、配列の現在の MEX と最大要素という 2 つの重要な値を特定することで活用できます。 MEX が最大要素より大きい場合、すべての操作で要素が MEX に置き換えられ、すべての要素が直ちに MEX に収束します。 それ以外の場合、各操作で作成される新しい要素は 1 つだけであり、配列は最大 1 つまたは 2 つのステップで安定します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 * k) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、現在の MEX と最大要素を決定します。 MEX は、配列内にない最小の非負の整数です。 最大値は配列内の最大値です。 
2. MEX が最大要素より大きい場合、配列はすぐに安定します。 MEX より小さい各要素は 1 回の操作で MEX に置き換えられますが、後続の操作はすべて影響しないため、後の合計は`k`オペレーションは`n * MEX`。 
3. MEX が最大値以下の場合、新しい候補値を次のように計算します。`(max + MEX + 1) // 2`。 これは、既存の値を減らさずに新しい値を挿入することによって表示できる MEX より大きい最小の整数を表します。 まだ存在しない場合は、配列要素のセットに追加します。 
4. 新しい値を追加すると、次の操作では新しい値を生成できないため、配列は安定します。 将来のすべての要素はすでに存在するか、新しい要素が MEX 自体になります。 Compute the sum of the updated array.
 5. 合計を出力します。 

機能する理由: 各操作により、配列内の一連の数値が増加または維持されます。 配列に 0 から最大値までのすべての整数が含まれたら、次の値を追加します。`(max + MEX + 1) // 2`可能な変更は だけであり、それ以上の操作によって合計は変更されません。 この不変条件により、すべてをシミュレートする必要がないことが保証されます。`k`ステップ。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        s = set(a)
        mex = 0
        while mex in s:
            mex += 1
        mx = max(a)
        if k == 0:
            print(sum(a))
            continue
        if mex > mx:
            # All numbers less than mex exist; array will be filled with new mex
            print(sum(a) + k * mex)
        else:
            new_elem = (mx + mex + 1) // 2
            if new_elem not in s:
                s.add(new_elem)
                print(sum(s))
            else:
                print(sum(a))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず O(1) メンバーシップ チェックのセットを使用して MEX と最大要素を効率的に計算します。 次に、MEX が最大値を超えているかどうかの 2 つのケースを確認します。 2 番目のケースでは、候補値を計算し、それが新しい場合にのみ追加します。 k = 0 のようなエッジケースは個別に処理されます。 

## 実用的な例

 アレイの場合`[0, 2, 1]`と`k = 3`、初期 MEX は`3`そして最大値は`2`。 MEX > max であるため、任意の回数の演算後の合計は次のようになります。`0 + 2 + 1 = 3`。 アレイはすぐに安定します。 

のために`[0, 0]`と`k = 2`、初期 MEX は`1`そしてマックスは`0`。 MEX > max であるため、配列は次のようになります。`[1, 1]`最初の手術後。 合計 = 2。それ以降の操作では、合計は 2 に保たれます。 

| ステップ | 配列 | メキシコ | マックス | 合計 |
 | --- | --- | --- | --- | --- |
 | イニシャル | [0,0] | 1 | 0 | 0 |
 | 最初の手術後 | [1,1] | 2 | 1 | 2 |
 | 2回目の手術後 | [1,1] | 2 | 1 | 2 |

 このトレースは、アレイが 1 回の操作後に安定したことを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | O(n) で MEX と max を計算し、償却された O(1) で集合演算を実行します。 |
 | スペース | O(n) | このセットには、配列の一意の要素がすべて格納されます。 |

 制約を考慮すると、このソリューションはすべてのテスト ケース ≤ 2×10^5 の n の合計を簡単に処理できます。

 ## 特殊なケース

 k = 0 の場合、配列は変更されません。 アルゴリズムは初期合計を正しく返します。 

MEX > max の配列の場合、次のように`[0,2,1]`、配列はすでに安定しており、合計はすぐに正確になります。 要素が繰り返される配列の場合、次のようになります。`[0,0]`、最初の操作でそれらが MEX に置き換えられ、合計が 1 回更新されます。 このアルゴリズムは、不必要に反復するのではなく、安定性条件をチェックすることによって、非常に大きな k を処理します。
