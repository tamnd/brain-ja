 ## 解決策
 ## 問題の理解

 私たちには一列のカメが与えられ、それぞれの位置に異なる数の卵が保持されています。 初期の配置は任意であり、目的は、非常に特殊なローカル操作を使用して、このシーケンスを厳密に増加する順序に変換できるかどうかを判断することです。 

唯一許可される移動は、任意の 3 つの連続する位置を取得し、固定された循環方法でそれらを並べ替えます。$(a_i, a_{i+1}, a_{i+2})$、次のように置き換えることができます$(a_{i+2}, a_i, a_{i+1})$。 他の再配置は許可されず、この操作は有効な位置に何度でも適用できます。 

質問は純粋に構造的なものです。この制限されたローカル回転はすべての置換を生成するのでしょうか、それともサブセットのみを生成するのでしょうか? ターゲットのソートされたシーケンスに到達できるかどうかを判断する必要があります。 

入力はサイズの単一の順列です$n$、すべての値が異なることが保証されます。 出力は二分決定であり、1 はシーケンスをソート順に変換できることを意味し、0 は変換できないことを意味します。 

制約は大きく、$n$最大 200,000 まで、変換に対するシミュレーションやブルート フォース検索が即座に排除されます。 ステートを明示的にモデル化したり、操作を繰り返し適用しようとするソリューションは、ステップごとの操作の線形数さえすでに 2 次以下になるため、爆発する可能性があります。 

微妙なエッジケースが現れるのは、$n$小さいです。 のために$n = 1$または$n = 2$の場合、適用できる操作はまったくないため、答えは配列がすでにソートされているかどうかだけです。 のために$n = 3$の場合、操作はどちらの方向にも 1 回だけ適用できるため、特定の順列のみに到達できます。 たとえば、から始めて、$[3,1,2]$に到達するための操作を適用できます。$[2,3,1]$ただし、すべての順列を取得することは決してできないため、「ローカルで再配置できる」という素朴な直感は誤解を招きます。 

本当に難しいのは、操作でどのようなグローバル不変式が保持されるかを認識することです。 

## アプローチ

 ブルートフォース解釈では、状態全体にわたって BFS または DFS を使用して、到達可能なすべての置換をシミュレートしようとします。ここで、各状態は置換であり、遷移は許可された 3 要素操作です。 各ノードが$O(n)$近傍の場合、状態空間のサイズは$n!$したがって、これは、たとえ$n = 10$。 

重要な点は、この操作が恣意的ではないということです。 これはインデックス上の 3 サイクルであり、順列のパリティを維持することを意味します。 すべての操作は偶数の順列です。3 サイクルは 2 つのスワップとして記述できるため、順列の符号は変わりません。 

これは、グローバルな不変条件を直ちに意味します。つまり、順列のパリティ (並べ替え順序に対して偶数であるか奇数であるかに関係なく) は、許可された一連の操作の下では決して変化しません。 したがって、最初の順列のパリティが奇数である場合、それを偶数である恒等順列 (ソート順序) に変換することはできません。 

残っているのは、パリティだけで十分かどうかを確認することです。 隣接スワップはすべての順列を生成し、パリティが許可される場合にのみ隣接スワップは 3 サイクルで構成できるため、この演算セットは正確に交互グループを生成します。 つまり、偶数の順列はすべて到達可能ですが、奇数の順列はすべて到達不可能です。 

したがって、問題は配列の反転パリティの計算に帰着します。

 ## アルゴリズムのチュートリアル

 問題を、置換が偶数パリティであるかどうかを判断することに集約します。 

1. 問題を配列の反転数の確認に変換します。 反転はペアです$(i, j)$と$i < j$しかし$a_i > a_j$。 これは順列パリティを直接測定します。 
2. 完全な反転をカウントするのではなく、反転パリティを効率的に計算します。 カウントが偶数か奇数かだけが必要です。 
3. フェンウィック ツリー (またはマージ ソート ベースのカウント) を使用して、要素を左から右に処理します。 値を挿入するたびに、以前に確認された値よりも大きい値がいくつあるかを数えます。 
4. 奇数の反転寄与に遭遇するたびに反転する単一ビットとしてパリ​​ティを維持します。 
5. 配列全体を処理した後、パリティが偶数の場合は 1 を出力し、それ以外の場合は 0 を出力します。 

### なぜ効果があるのか

 許可される各操作は 3 サイクルであり、これは偶数の順列であるため、反転パリティが保持されます。 ソートされた配列には反転がゼロ、つまり偶数であるため、偶数の反転パリティを持つ配列のみを配列に変換できます。 逆に、偶数の順列はそのような 3 サイクルのシーケンスに分解でき、到達可能であることを意味します。 したがって、パリティは必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # coordinate compression
    vals = sorted(a)
    comp = {v: i + 1 for i, v in enumerate(vals)}

    fw = Fenwick(n)
    parity = 0

    for i, x in enumerate(a):
        x = comp[x]
        leq = fw.sum(x)
        inversions_here = i - leq
        parity ^= (inversions_here & 1)
        fw.add(x, 1)

    print(1 if parity == 0 else 0)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、すでに表示されている要素の数を維持します。 新しい要素ごとに、以前に挿入された大きいものすべてが反転に寄与します。 その数値が奇数か偶数かを追跡するだけなので、完全なカウントを累積するのではなく、パリティ ビットの XOR を計算します。 

値が次の値に達するため、座標圧縮が必要です。$10^9$一方、Fenwick インデックスは連続している必要があります。 

実装の重要な詳細は、完全な反転カウントは 64 ビット範囲を超える可能性があるため、決して保存しないことです。 パリティのみが重要です。

```値を圧縮して、$[3,1,2] \rightarrow [3,1,2]$ランク$[3,1,2]$。

これは、配列が最初はソートされていないにもかかわらず、到達可能なセット内にあることを示しています。

 ## 特殊なケース

 のために$n = 1$、演算は存在せず、配列は自明にソートされるため、答えは常に 1 になります。 

のために$n = 2$の場合、操作は使用できないため、ID 順列のみが有効です。 反転パリティが直接区別するため、アルゴリズムはこれを正しく処理します。$[1,2]$から$[2,1]$。 

配列がほぼソートされているが単一の反転が含まれる大規模なケースでは、単一の反転は奇数パリティを意味し、偶数の 3 サイクルのみを使用して修正できないため、アルゴリズムはそれらを正しく拒否します。
