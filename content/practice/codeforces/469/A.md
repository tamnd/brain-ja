 ## 解決策
 ## 問題の理解

 1 から _n_ までのレベル番号が付けられたゲームがあります。 Little X はこれらのレベルの一部のサブセットを完了でき、Little Y は別のサブセットを完了できます。 彼らは協力することにしました。これは、少なくとも 1 人がそのレベルを完了できれば、レベルは合格とみなされます。 

タスクは、彼らの能力を組み合わせてゲームのあらゆるレベルをカバーできるかどうかを判断するだけです。 1 から _n_ までのすべてのレベルが X または Y によって完了できる場合、次のように出力します。`"I become the guy."`。 それ以外の場合、少なくとも 1 つのレベルは両方のプレイヤーにとって不可能なままとなり、次のように表示されます。`"Oh, my keyboard!"`。 

制約は非常に小さいです。 レベル数は最大 100 なので、比較的非効率なアプローチでも制限時間内に快適に実行できます。 高度なデータ構造や高度なアルゴリズムは必要ありません。 すべてのレベルのカバレッジをチェックする簡単な実装で十分です。 

A few edge cases are easy to overlook.

 Suppose one player can pass no levels at all.

 入力：```
1
0
1 1
```正しい出力は次のとおりです。```
I become the guy.
```X は何も貢献しませんが、Y だけで唯一のレベルをカバーします。 

もう 1 つのケースは、両方のプレイヤーが同じレベルのリストをいくつか挙げている場合です。 

入力：```
4
2 1 2
2 2 3
```正しい出力は次のとおりです。```
Oh, my keyboard!
```レベル 1、2、および 3 はカバーされていますが、レベル 4 は含まれていません。 読み取られた数値の数だけをカウントする不注意な実装では、4 つのエントリが 4 つのカバーされるレベルを意味すると誤って認識する可能性があります。 

最後のエッジケースは、どちらのプレイヤーも個別にすべてのレベルをカバーせず、一緒にすべてのレベルをカバーする場合に発生します。 

入力：```
4
2 1 2
2 3 4
```正しい出力は次のとおりです。```
I become the guy.
```ここでは各プレイヤーを個別にチェックすると失敗します。 それらの到達可能なレベルの統合を考慮する必要があります。 

## アプローチ

 最も直接的な強引なアイデアは、1 から _n_ までのすべてのレベルを調べることです。 各レベルについて、X のリストと Y のリストをスキャンして、どちらかのプレイヤーがそれを完了できるかどうかを確認します。 両方のリストに何らかのレベルが含まれていない場合、答えは否定になります。 

このアプローチは、問題に必要な条件、つまりすべてのレベルをカバーする必要があることを明示的に検証するため、正しいです。 With at most 100 levels and at most 100 entries per list, the worst case performs roughly 100 × 200 = 20,000 comparisons, which is already fast enough.

 レベルが両方のプレイヤーのリストに少なくとも 1 回出現するかどうかだけを気にすることを観察することで、ソリューションをよりクリーンにすることができます。 重複した出現は問題ではありません。 これは当然、セットの使用を示唆しています。 

X が渡すことができるすべてのレベルをセットに挿入し、次に Y が渡すことができるすべてのレベルを同じセットに挿入します。 セットは各レベルを 1 回だけ自動的に保存します。 セットのサイズが _n_ になると、すべてのレベルが表現されます。 それ以外の場合は、一部のレベルが欠落しています。 

ブルート フォース手法は、カバレッジ レベルをレベルごとに直接チェックするため機能します。 重要な観察は、カバレッジが 2 人のプレーヤーのレベル セットの結合とまったく同じであるということです。 その結合を明示的に表現すると、単一のサイズ比較で質問に答えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n(p + q)) | お(1) | 承認済み |
 | 最適 | O(p + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. レベルの数を読み取り、`n`。 
2. リトル X のセリフを読みます。 最初の数字は`p`、続いて`p`レベル X を完了できます。 
3. リトル Y のセリフを読みます。 最初の数字は`q`、続いて`q`レベル Y を完了できます。 
4. 空のセットを作成します。 
5. X のリストのすべてのレベルをセットに挿入します。 

このセットには一意のレベルのみが保持されており、これがまさに必要なものです。 
6. Y のリストのすべてのレベルを同じセットに挿入します。 

このステップの後、セットはいずれかのプレイヤーが通過できるレベルの結合を表します。 
7. セットのサイズを比較します。`n`。 

セットに正確に含まれている場合`n`個別のレベル、1 から 1 までのすべてのレベル`n`カバーされています。 
8. 印刷`"I become the guy."`すべてのレベルがカバーされている場合。 それ以外の場合は印刷します`"Oh, my keyboard!"`。 

### なぜ効果があるのか

 このセットには、少なくとも 1 人のプレイヤーがクリアできるレベルが正確に含まれています。 X または Y によって挿入されたすべてのレベルがセットに表示され、他のレベルはセットに表示されません。 

設定されたサイズが等しい場合`n`、次に 1 から 1 までのすべてのレベル`n`つまり、プレイヤーは共同してゲーム全体を完了できます。 

設定サイズがこれより小さい場合`n`、結合に少なくとも 1 つのレベルがありません。 どちらのプレイヤーもそのレベルを完了できないため、ゲーム全体を完了することは不可能です。 

アルゴリズムは問題ステートメントに必要な和集合を正確にチェックするため、常に正しい答えが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    x_data = list(map(int, input().split()))
    y_data = list(map(int, input().split()))

    levels = set()

    for level in x_data[1:]:
        levels.add(level)

    for level in y_data[1:]:
        levels.add(level)

    if len(levels) == n:
        print("I become the guy.")
    else:
        print("Oh, my keyboard!")

solve()
```最初の行には、レベルの合計数が表示されます。 次の 2 行にはプレーヤーの情報が含まれます。 各行の最初の値はカウントであり、それ自体はレベル番号ではないため、インデックス 1 以降をスライスすることでスキップします。 

セットが使用されるのは、レベルが何回出現するかではなく、レベルがカバーされているかどうかのみを考慮するためです。 両方のプレイヤーがレベル 2 に合格できる場合でも、セットには 2 のコピーが 1 つだけ保存されます。 

最後の比較では、共用体にすべての要素が含まれているかどうかがチェックされます。`n`レベル。 レベルには1から1までの番号が付いているので、`n`、持っている`n`個別のカバー対象レベルとは、すべてのレベルがカバーされることを意味します。 

微妙な点の 1 つは、カウント値の使用を避けることです。`p`そして`q`レベルとして。 これらを誤って含めると、一部の入力で不正確な回答が生成される可能性があります。 使用する`x_data[1:]`そして`y_data[1:]`その間違いをきれいに避けます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(p + q) | リストされた各レベルはセットに 1 回挿入されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(input())

    x_data = list(map(int, input().split()))
    y_data = list(map(int, input().split()))

    levels = set(x_data[1:]) | set(y_data[1:])

    if len(levels) == n:
        return "I become the guy."
    return "Oh, my keyboard!"

# provided sample

 ## 特殊なケース

 1 人のプレイヤーが何も貢献しない場合を考えてみましょう。 

入力：```
1
0
1 1
```セットは空から始まります。 X はレベルを追加しません。 Y はレベル 1 を追加し、`{1}`。 セットサイズは 1 となり、`n`したがって、アルゴリズムは次のように出力します。```
I become the guy.
```次に、重複するレベルを考えてみましょう。 

入力：```
4
2 1 2
2 2 3
```X を処理した後のセットは次のようになります。`{1, 2}`。 Y を処理すると、レベル 2 とレベル 3 が再度追加され、`{1, 2, 3}`。 重複レベルによってセット サイズが増加することはありません。 最終的なサイズは 4 ではなく 3 であるため、アルゴリズムは次のように正しく出力します。```
Oh, my keyboard!
```最後に、協力が必要な場合を考えてみましょう。 

入力：```
4
2 1 2
2 3 4
```X が貢献します`{1, 2}`そしてYは貢献する`{3, 4}`。 彼らの結合は、`{1, 2, 3, 4}`。 設定されたサイズは次のとおりです`n`したがって、出力は次のようになります。```
I become the guy.
```これは、各プレーヤーを個別にチェックするのではなく、総合的なカバレッジを評価する必要がある理由を示しています。
