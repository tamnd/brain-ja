 ## 解決策
 ## 問題の理解

 私たちは、リトル X がオンラインでリトル Z と重なるように目覚めることができるさまざまな瞬間が何回あるかを数えるよう求められます。 Little Z には、複数のセグメントで構成される固定スケジュールがあります。 小さな X には、起床時間に応じてスケジュールが定義されています。その時間に起床するかどうか`t`、彼のスケジュールの各セグメントは、次のように前方にシフトされます。`t`。 整数のウェイクアップ回数を決定するように求められます`t`範囲内で`[l, r]`リトル X のシフトされたスケジュールのセグメントとリトル Z のスケジュールのセグメントの間に、少なくとも 1 つの重複する瞬間を考慮してください。 

制約は控えめです。`p`そして`q`、セグメントの数は最大 50、ウェイクアップ ウィンドウ`[l, r]`各セグメントの長さは最大 1000 ですが、セグメントの総数が少ないため、セグメントごとに重複をチェックするアプローチが可能です。 

セグメントが端点で正確に接触する場合、微妙なエッジ ケースが発生します。 たとえば、Little Z が 2 から 3 までオンラインで、Little X が 3 から 4 までオンラインである場合、それらは時間 3 で重複します。単純な「厳密に小さい」重複チェックではこれを見逃してしまいます。 同様に、シフトにより最初または最後のウェイクアップ時間にオーバーラップが生じる可能性があります。 境界を含めるのを忘れがちです`l`そして`r`有効な候補として。 

## アプローチ

 ブルートフォースアプローチは簡単です。 候補者ごとの起床時間`t`で`[l, r]`、Little X のすべてのセグメントを次のようにシフトします。`t`次に、セグメントのすべてのペアを確認します`(X_segment, Z_segment)`オーバーラップ用。 各重複チェックには一定の時間がかかるため、合計操作数は次のようになります。`O((r-l+1) * p * q)`。 最悪の場合、これはおおよそ次のとおりです`1001 * 50 * 50 = 2.5 million`1 秒以内であれば許容されます。 このアプローチはシンプルで実装が簡単で、制約内で動作することが保証されています。 

さらにクリーンな実装につながる観察結果は、次の場合に重複が発生するということです。`max(start_X + t, start_Z) <= min(end_X + t, end_Z)`。 これにより、2 つのセグメントが重なっているかどうかをチェックするための直接的な定数時間の式が得られ、セグメント内の個々の時間を反復処理する必要がなくなります。 セグメント数が少ないため、このアプローチは効率的で読みやすく、off-by-one エラーを回避できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((r-l+1) * p * q) | O(p+q) | 承認済み |
 | 最適化されたチェック | O((r-l+1) * p * q) | O(p+q) | 承認済み |

 ここでは、ブルート フォースと最適化されたオーバーラップ チェックのアプローチの漸近的な複雑さは本質的に同じですが、直接式を使用することで微妙な間違いが回避され、コードがクリーンになります。 

## アルゴリズムのチュートリアル

 1. すべての入力を読み取ります: セグメントの数`p`そして`q`、ウェイクアップ範囲`[l, r]`、Little Z のセグメント`[a_i, b_i]`、および Little X のセグメント`[c_j, d_j]`。 簡単にアクセスできるように、セグメントを整数のペアとして保存します。 
2. カウンタの初期化`answer`ゼロに。 これにより、有効なウェイクアップ時間の数が追跡されます。 
3. すべての整数を反復処理します。`t`から`l`に`r`。 それぞれについて`t`、Little X のセグメントが次のようにシフトしたかどうかを確認します。`t`Little Z のどの部分とも重なります。 
4. それぞれについて`t`、セグメントのすべてのペアを反復します。`(c_j + t, d_j + t)`Xと`(a_i, b_i)`Z について。開始点の最大値と終了点の最小値を計算します。 もし`max(c_j + t, a_i) <= min(d_j + t, b_i)`、これにマークを付けます`t`有効として。 
5. 現在のデータに対して少なくとも 1 つの重複が見つかった場合`t`、増分`answer`そして早めに休憩して次へ`t`。 
6. すべての候補者がテストされたら、印刷します。`answer`。 

これが機能する理由は、チェック`max(start_X_shifted, start_Z) <= min(end_X_shifted, end_Z)`間隔が交差するかどうかを正確にキャプチャします。 起床時間の重複が 1 つ見つかるとすぐに中断されるため、それぞれの有効な時間が保証されます。`t`は 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

p, q, l, r = map(int, input().split())
z_segments = [tuple(map(int, input().split())) for _ in range(p)]
x_segments = [tuple(map(int, input().split())) for _ in range(q)]

answer = 0
for t in range(l, r + 1):
    can_chat = False
    for (c, d) in x_segments:
        c_shifted, d_shifted = c + t, d + t
        for (a, b) in z_segments:
            if max(c_shifted, a) <= min(d_shifted, b):
                can_chat = True
                break
        if can_chat:
            break
    if can_chat:
        answer += 1

print(answer)
```セグメントとウェイクアップ範囲を入力から直接読み取り、タプルのリストとして保存します。 ネストされたループはすべてのセグメントのペアをチェックしますが、内部のブレークにより、重複が見つかった場合は不要なチェックを確実に停止します。 シフトは次を使用してオンザフライで適用されます`c + t`そして`d + t`、コードをきれいに保ちます。 すべての比較にはエンドポイントが含まれるため、off-by-one エラーが回避されます。
