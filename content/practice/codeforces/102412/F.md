 ## 問題の理解

 を含むセットから始めます`0`、`1`、 そして`2`。 1 回の操作で任意の 2 つの数字を選択します`x`そして`y`すでにセットに含まれており、挿入されています

 x 2 −y。 

挿入された値は次の範囲内にある必要があります。`0`と 10 18 までにパフォーマンスを行う可能性があります`43`操作。 目標を与えられた`n`、操作の数を最小限に抑える必要はなく、構築するだけで済みます。 公式声明では、これらの制限内で有効な構築を許可しています。 

ターゲットは 10 18 まで大きくなる可能性があるため、考えられるすべての構造を検索しようとしても絶望的です。 操作に便利な構造は正方形です。 何らかの数値を構築したい場合`p`、選択できます`x`p に近いため、構築するには両方の数値が必要になります。`p`よりも劇的に小さい`p`。 

小さな値`0`、`1`、 そして`2`はすでに利用可能であるため、終了状態として扱う必要があります。 たとえば、次の場合`n = 2`の場合、ターゲットはすでに初期セットに含まれているため、正しい出力は単に空の出力です。 常に生成しようとする不用意な実装`n`不必要に別の値を構築し、無効な再帰ループを作成する可能性もあります。 

もう 1 つのエッジケースは完全な正方形です。 のために`n = 9`、選択する`x = 3`与える`y = 0`、 それで`3^2 - 0 = 9`。 正しい構築は次のとおりです。```
3 0
```を前提とした不注意な実装`y`ステートメントが明示的にゼロを許可している場合でも、must が正である場合は、完全に有効な構造が拒否されます。 

もう 1 つの境界ケースは、正方形のすぐ下の値です。 例えば、`n = 15`与える`x = 4`そして`y = 1`、4 2 −1=15 であるため。 重要な詳細は、`x`平方根の床ではなく天井でなければなりません。 使用する`x = 3`3 2 −15 が負になり、出力条件に違反します。 

実際の制約は、平方根換算に非常に適しています。 ターゲットは最大 10 18 であるため、その平方根は最大 10 9 です。平方根を繰り返し計算すると、大きさは非常に急速に減少し、わずか数レベルで小さな値に達します。 公式の制限は 1 秒および 256 MiB で、最大 43 の操作が許可されます。 

## アプローチ

 ブルートフォースアプローチでは、各操作の後に到達可能なセットを探索しようとします。 現在のセットを考慮すると、順序付けられたすべてのペアを選択できます`(x, y)`、計算する`x²-y`を実行し、結果の状態を再帰的に探索します。 これは正しいです。なぜなら、あらゆる法的構造は、そのような選択のシーケンスによって表現されるからです。 

問題は選択肢の多さです。 初期セットからでも 3 2 =9 個の順序ペアがあります。 43 の操作に対してすべてのペアで単純に分岐すると、考えられる選択シーケンスの数だけがすでに

 9 43 ≈10 41 。 

セットに含まれる値が増えると、実際の分岐はさらに大きくなります。 セット全体を追跡すると巨大な状態空間が作成されるため、総当たり攻撃は現実的ではありません。 

重要な観察は、最終操作を逆にすることです。 構築したいとします`p`。 すでに構築可能なものが必要です`x`そして`y`満足のいく

 x 2 −y = p。 

選択してください

 x=⌈ p ⌉,y=x 2 −p。 

その後、方程式は自動的に満たされます。 興味深いのは、2 つの新しいターゲットのサイズです。 以来`x`は x 2 ≥p の最小の整数です。 

(x−1) 2 <p≤x 2 。 

したがって、

 0≤y=x 2 −p<x 2 −(x−1) 2 =2x−1。 

それで`x`は約 p であり、`y`せいぜい2p程度です。 1 つのサイズの数値を構築する代わりに`p`、サイズがおおよそ次の平方根である 2 つの数値を再帰的に構築します。`p`。 

p≤10 18 の場合、最初の`x`最大でも 10 9 であり、`y`次の再帰レベルはおよそ 10 5 に下がり、次に数百、次に数十、そして最後に初期値になります。`0`、`1`、 そして`2`。 結果として得られる構造は、必要な 43 回の操作を快適に下回ります。 

この構造は基本的に分割統治ですが、分割は半分ではなく平方根に基づいています。 最初に依存関係を再帰的に構築し、次に現在の数値を作成する操作を出力します。

 ## アルゴリズムのチュートリアル

 1. すでに使用可能な数値のセットを次のように初期化します。`0`、`1`、 そして`2`。 これらの数値には操作が必要ないため、これらの数値のいずれかに達すると再帰は直ちに停止します。 
2. ターゲットについて`p`まだ利用できない場合は、x=⌈ p ⌉ を計算します。 Python では、これは次のように正確に取得できます。`math.isqrt`、10 18 に近い値の浮動小数点精度の問題を回避します。 
3. y=x 2 −p を計算します。 構造上、x 2 −y=p なので、1 回`x`そして`y`構築が完了したら、最後の操作で`p`。 
4. 再帰的に構築する`x`そして`y`録音する前に`(x, y)`。 この操作は両方のオペランドがすでにセットに属している場合にのみ有効であるため、この順序が必要です。 
5. 構築されたすべての値を`seen`セット。 これにより、2 つの異なる再帰的分岐が同じ中間値を必要とする場合に、同じ操作を繰り返すことが防止されます。 
6. 両方の依存関係が利用可能になったら、`(x, y)`答えとマークへ`p`構築されたとおり。 すべての演算はそのオペランドに必要な演算の後に出現するため、結果のリストはすでに有効な実行順序になっています。 

### なぜ効果があるのか

 不変条件は、いつでも`build(p)`終わり、`p`は構築されたセットに属しており、これまでに保存されたすべての操作は、出力された順序で正当です。 新しいもののために`p`、x=⌈ p ⌉ および y=x 2 −p を選択するため、正確に x 2 −y=p となります。 再帰呼び出し構造`x`そして`y`最初に、その後、最後の操作が正当になり、挿入されます。`p`。 以来`x`そして`y`よりもはるかに小さい`p`、再帰は到達します`0`、`1`、 または`2`そして終了します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import isqrt

def solve():
    n = int(input())

    # These numbers are present before any operation.
    seen = {0, 1, 2}
    operations = []

    def build(p):
        if p in seen:
            return

        # x is the smallest integer with x^2 >= p.
        x = isqrt(p)
        if x * x < p:
            x += 1

        y = x * x - p

        # Both operands must already exist before we can use them.
        build(x)
        build(y)

        operations.append((x, y))
        seen.add(p)

    build(n)

    out = []
    for x, y in operations:
        out.append(f"{x} {y}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`seen`set は、シミュレーションされた建設で現在利用可能な数値を正確に表します。 から始める`0`、`1`、 そして`2`問題の初期状態と一致します。 

平方根の計算には注意が必要です。 使用する`int(math.sqrt(p))`浮動小数点数は 10 18 までのすべての整数を正確に表現できないため、一般的な整数手法としては安全ではありません。`isqrt`整数の平方根を正確に計算します。 もし`x*x < p`、増加します`x`天井の平方根を与えます。 

再帰呼び出しは前に発生します`operations.append((x, y))`。 これら 2 行を逆にすると、出力された操作がまだ生成されていない数値を参照する可能性があるため、無効な応答が生成されます。 

Python の整数には任意の精度があるため、オーバーフローの問題はありません。 実は一番大きいのは、`x`はわずか 10 9 ですが、`y`たとえターゲット自体が 10 18 であっても、それは 10 9 のオーダーにすぎません。 

の`seen`check は共有依存関係も処理します。 同じ中間値が 2 つの分岐に出現する場合、その中間値は 1 回だけ生成され、操作数が制限内に安全に保たれます。

## テストケース

 出力は一意ではないため、テスト ハーネスは、生成されたシーケンスを 1 つの固定文字列と比較するのではなく、検証する必要があります。 以下のバリデータは、すべてのオペランドがすでに使用可能であること、生成されたすべての値が正当であること、ターゲットが最終的に生成されること、出力される操作が 43 個以下であることをチェックします。```python
# helper: run solution on input string, return output string
import sys
import io
from math import isqrt

def solution(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        n = int(sys.stdin.readline())

        seen = {0, 1, 2}
        operations = []

        def build(p):
            if p in seen:
                return

            x = isqrt(p)
            if x * x < p:
                x += 1

            y = x * x - p

            build(x)
            build(y)

            operations.append((x, y))
            seen.add(p)

        build(n)

        sys.stdout.write(
            "\n".join(f"{x} {y}" for x, y in operations)
        )
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def validate(inp: str, output: str) -> bool:
    n = int(inp.strip())

    available = {0, 1, 2}
    lines = output.strip().splitlines() if output.strip() else []

    assert len(lines) <= 43, "too many operations"

    for line in lines:
        parts = line.split()
        assert len(parts) == 2, "each operation needs x and y"

        x, y = map(int, parts)

        assert x in available, f"x={x} was not constructed"
        assert y in available, f"y={y} was not constructed"

        value = x * x - y
        assert 0 <= value <= 10**18, "generated value is out of range"

        available.add(value)

    assert n in available, f"target {n} was not constructed"
    return True

# Provided sample 1.
out = run("5\n") if False else solution("5\n")
assert validate("5\n", out), "sample 1"

# Provided sample 2.
out = solution("7\n")
assert validate("7\n", out), "sample 2"

# Minimum-size input: target already exists initially.
out = solution("0\n")
assert out == "", "zero needs no operations"

# All-equal / smallest nontrivial construction.
out = solution("4\n")
assert validate("4\n", out), "constructing a perfect square"

# Boundary case just below a square.
out = solution("15\n")
assert validate("15\n", out), "value just below 16"

# Maximum-size target.
out = solution("1000000000000000000\n")
assert validate("1000000000000000000\n", out), "maximum target"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`0`| 空の出力 | 初期設定境界 |
 |`4`| 任意の有効な構造 | 完全二乗処理とゼロ`y`|
 |`15`| 任意の有効な構造 | 天井と平方根の境界 |

 ## 特殊なケース

 のために`n = 0`、アルゴリズムが入ります`build(0)`、すぐにそれがわかります`0`すでに入っています`seen`と返します。 正確な入力は次のとおりです```
0
```そして正しい出力は空です。 操作は必要ありません。不要な操作を印刷すると構築が長くなるだけです。 

次のような完全な正方形の場合`n = 9`、`isqrt(9)`返品`3`そして`3*3`すでに等しい`n`、 それで`y = 0`。 再帰呼び出しは、`3`そして`0`構築する`3`そして印刷します```
3 0
```これは 3 2 −0=9 を与えます。 ゼロは最初から存在するため、正当なオペランドです。 

正方形のすぐ下の数値の場合、次のようになります。`n = 15`、床の平方根は`3`, しかし、 3 2 −15 は負なので使えません。 アルゴリズムが検出するのは、`3*3 < 15`、増分`x`に`4`を取得し、`y = 1`。 最後の操作は、```
4 1
```これにより、16−1=15 となります。 まさにこれが、天井平方根が必要な理由です。 

最大の目標としては、```
1000000000000000000
```最初の選択は`x = 1000000000`そして`y = 0`。 アルゴリズムは構築するだけで済みます`1000000000`、その後、ターゲットは次によって生成されます。```
1000000000 0
```の再帰的構築`1000000000`は平方根付近の値を使用し、初期値のみが残るまで同じ削減が続けられます。 規模は急速に縮小するため、依存関係ツリー全体が許可された 43 の操作の範囲内に留まります。
