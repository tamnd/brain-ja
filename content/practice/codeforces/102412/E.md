 ## 解決策
 ## 問題の理解

 (n) 個の頂点と (m) 個のエッジ、および正確に (s) 個のトークンを持つ無向マルチグラフがあります。 すべての頂点 (v) に対して非負の整数 (a_v) を選択します。ここで、(a_v) はそこに配置されたトークンの数であり、合計は正確に (s) です。 

エッジ ((u,v)) には容量 (\min(a_u,a_v)) があります。 目標は、すべてのエッジの容量の合計ができるだけ大きくなるようにすべてのトークンを配布することです。 平行なエッジは個別にカウントされるため、同じ頂点のペアが 5 つのエッジで接続されている場合、それらの寄与は同じ最小値の 5 倍になります。 必要な出力は、最大値に達するトークン分布です。 

制約の頂点の数は異常に少ないですが、エッジの数は多くなります。 (n \le 18)、(m \le 100000)、(s \le 100) があります。 (2^{18}=262144) であるため、境界 (n \le 18) は頂点のサブセットを列挙できるという信号です。 (m) の値が大きいということは、サブセットごとにすべてのエッジを繰り返しスキャンできないことを意味します。 公式の制限時間は 512 MiB のメモリで 4 秒であるため、(O(2^n n)) のサブセット計算は妥当ですが、サブセット列挙内に (m) の余分な係数や (s) の大きな多項式を含むアルゴリズムは望ましくありません。 

不注意な実装が間違っている可能性があるいくつかの特殊なケースがあります。 まず、(s) はゼロにすることができます。 例えば、```
1 0 0
```生産しなければならない```
0
```トークンもエッジも存在しないからです。 少なくとも 1 つのトークンを想定する実装、またはその DP を 1 つのトークンで開始する実装は、ここで失敗する可能性があります。 

次に、平行なエッジが重要です。 のために```
2 5 3
1 2
1 2
1 2
1 2
1 2
```最適な答えは```
2 1
```5 つのエッジのそれぞれに容量 (1) があり、合計容量は (5) になるためです。 エッジが存在するかどうかのみを保存する不注意な実装では、これら 5 つのエッジが 1 つのエッジとして扱われ、係数 5 が失われます。 

第三に、サブセット DP 中に使用される最適なセットは、発見されたときにネストする必要がありません。 たとえば、同じサイズでも異なる最適なサブセットは異なる場合があります。 サイズ (i) で記憶されるサブセットが、サイズ (i+1) で記憶されるサブセットに自動的に含まれると仮定するのは誤りです。 この解決策は、目標を下げることなく、ネストされていないセットの交差を解除できるため、機能します。 

最後に、(s) は (n) よりもはるかに大きくなる可能性があります。 2 つの頂点が 1 つのエッジで結合されている場合 (s=100)、```
2 1 100
1 2
```答えは```
50 50
```すべてのトークンを 1 つの頂点に配置するのではなく。 関連する DP では、同じサイズのサブセットを繰り返し使用できる必要があります。 

## アプローチ

 直接的な総当たりアプローチでは、可能なすべてのトークン分布 ((a_1,\ldots,a_n)) を合計 (s) で列挙し、すべて (m) のエッジを評価します。 そのような分布の数は

 [
 \binom{s+n-1}{n-1}。 
]

 最大境界では、これは (\binom{117}{17}) であり、1 つの分布を評価するために使用されるエッジ (100000) を乗算する前でさえ、すでに実現可能な値をはるかに超えています。 

より情報に基づいたブルート フォース アプローチでは、すべての頂点サブセットを列挙し、頂点のすべてのペアをチェックすることで、その誘発されたエッジを直接カウントします。 (2^n) 個のサブセットと (O(n^2)) 個の可能な頂点ペアがあるため、これには (O(2^n n^2)) のコストがかかります。 (n=18) では、これはおよそ (262144 \cdot 324)、約 8,500 万ペアのチェックになります。 これは最適化された C++ で使用でき、既存の論説で説明されている標準的なビットマスク ソリューションですが、Python にとっては不必要に高価です。 

重要な点は、トークンを個別に考えるのをやめるということです。 最終的な割り当て (a_v) が与えられた場合、次のように定義します。 

[
 X_k={v\mid a_v\ge k}。 
]

 セットはネストされたシーケンスを形成します。 

[
 X_1 \supseteq X_2 \supseteq X_3 \supseteq \cdots。 
]

 エッジは、両方のエンドポイントが属する (X_k) レベル (k) ごとに 1 ユニットを提供します。 (f(X)) が 2 つの端点が両方とも (X) 内にあるグラフ エッジの数を表す場合、目的の合計は次のようになります。 

[
 \sum_k f(X_k)。 
]

 また、

 [
 \sum_k |X_k|=\sum_v a_v=s。 
]

 したがって、元の問題は、サイズの合計が (s) になるネストされた頂点サブセットを選択し、それらの誘導エッジ数の合計を最大化することになります。 この再定式化は、既知のビットマスクおよびナップザック ソリューションの背後にある中心的なアイデアです。 

すべてのサイズ (k) について、次のようにします。 

[
 F_k=\max_{|X|=k} f(X)。 
]

 選択したサブセットをネストする必要があるという要件を一時的に無視すると、問題は無制限のナップザックになります。 サイズ (k) の項目には重み (k) と値 (F_k) があり、複数のトークン レベルが同じ頂点セットを持つことができるため、同じサイズを複数回使用することがあります。 

驚くべきことは、ネスト要件を削除しても最適値は変わらないことです。 誘導エッジ関数はスーパーモジュラーです。 

[
 f(A)+f(B)\le f(A\カップ B)+f(A\キャップ B)。 
]

 選択した 2 つのセット (A) と (B) がネストされていない場合は、(A\cup B) と (A\cap B) に置き換えます。 合計サイズは変わりませんが、合計値は減少しません。 この非交差プロセスを繰り返すと、最終的にはネストされたファミリーが生成されます。 したがって、ナップザック最適値は常に有効なトークン分布に変換できます。 

残りの問題は、すべての (F_k) を効率的に計算する方法です。 ビットマスクで表されるサブセットの場合、選択した 1 つの頂点 (v) を削除します。 大きい方のサブセットの誘導エッジ数は、小さい方のサブセットの誘導エッジ数に (v) から小さいサブセットまでのエッジの数を加えたものと等しくなります。 (n) は 18 にすぎないため、(O(n2^n)) の計算が行われ、Python では十分に高速です。 平行エッジは、その多重度を (n\times n) 行列に格納することによって処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | トークンの配布を列挙する | (O\left(m\binom{s+n-1}{n-1}\right)) | (O(n+m)) | 遅すぎる |
 | サブセット + すべての頂点ペア | (O(2^n n^2 + ns)) | (O(2^n)) | 最適化された言語で受け入れられます |
 | 増分エッジ数を持つサブセット | (O(n2^n + ns)) | (O(2^n+n^2)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての無向エッジの多重度を行列に保存します`edges[u][v]`。 入力に同じエッジのコピーが複数含まれている場合、その多重度は数倍に増加します。 
2. ビットマスクを使用して頂点のすべてのサブセットを列挙します。 空ではないマスクごとに、頂点 (v) に対応する最も低い設定ビットを削除し、残りのサブセットを呼び出します。`prev`。 

内側に誘導されたエッジ`mask`内部にすでに存在するすべてのエッジで構成されます`prev`、および (v) を頂点に接続するすべてのエッジ`prev`。 したがって、

 [
 f(マスク)=f(前)+\sum_{u\in prev}edges[v][u]。 
]

 これにより、計算済みのより小さいサブセットからすべての誘導エッジ カウントが計算されます。 
3. 各サブセットについて、頂点の数を次のように計算します。`mask.bit_count()`。 誘導エッジ数がそのサブセット サイズの現在の値よりも優れている場合は、値とマスクの両方を保存します。 

この通過後、`best[k]`は、任意の (k) 頂点サブセットによって引き起こされるエッジの正確な最大数であり、`best_mask[k]`1 つのサブセットがその値に達したことを記憶します。 
4. トークンの総数に対して無制限のナップザックを実行します。 させて`dp[x]`正確に (x) 個のトークンを使用して取得できる最大値になります。 

合計 (x) ごとに、(k) 個の頂点を含むレイヤーをもう 1 つ取り出してみます。 そのコストは (k)、その値は`best[k]`。 移行は、

 [
 dp[x]=\max_{1\le k\le \min(n,x)}
 \left(dp[x-k]+best[k]\right)。 
]

 (k)は繰り返し使えるので、無制限のナップザックです。 
5. 各 DP 状態によってどのサブセット サイズが選択されたかを保存します。 (s) から始めて、これらの選択肢を逆方向に繰り返し実行します。 選択したサイズ (k) ごとに、それに含まれるすべての頂点のトークン数を増分します。`best_mask[k]`。 

結果として得られるサブセットのコレクションをネストする必要はありません。 交差しない引数は、その値がすでにネストされたコレクションによって達成可能な最適値であることを証明しているため、これは問題ありません。 選択したすべてのサブセットを追加することによって生成されるトークン カウントは、対応するセットが交差解除された後の同じレイヤーのコレクションを直接表します。 
6. DP が (s) 個よりも少ないトークンの使用を許可された場合、未使用のトークンはエッジ容量を減らすことなくどこにでも配置できます。 この実装では、DP は正確に (s) 実行されるため、通常は追加の充填は必要ありません。 

これが機能する理由: すべての有効なトークン配布は、レベル セット (X_k) のネストされたシーケンスに正確に対応し、その目的は (\sum f(X_k)) です。 すべての (f(X_k)) をそのサイズの可能な最大値で置き換えると、ナップザックで表される上限が得られます。 逆に、ナップザックによって選択されたすべてのコレクションは、スーパーモジュール性を使用してペアごとに交差を解除することができ、セット サイズの合計を保持し、誘導エッジの合計値が減少することはありません。 交差されていないファミリーはネストされているため、実際のトークンの配布に対応します。 したがって、ナップザックの値は上限であると同時に達成可能であり、最適性が証明されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, s = map(int, input().split())

    # Multiplicity of the edge between every pair of vertices.
    edges = [[0] * n for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges[u][v] += 1
        edges[v][u] += 1

    limit = 1 << n

    # f[mask] = number of edges completely inside mask.
    f = [0] * limit

    # best[k] = maximum f(mask) over masks of size k.
    best = [0] * (n + 1)

    # best_mask[k] = one mask attaining best[k].
    best_mask = [0] * (n + 1)

    for mask in range(1, limit):
        bit = mask & -mask
        v = bit.bit_length() - 1
        prev = mask ^ bit

        value = f[prev]

        # Add all edges from v to vertices already in prev.
        x = prev
        row = edges[v]
        while x:
            b = x & -x
            u = b.bit_length() - 1
            value += row[u]
            x ^= b

        f[mask] = value

        size = mask.bit_count()
        if value > best[size]:
            best[size] = value
            best_mask[size] = mask

    # Unbounded knapsack.
    dp = [0] * (s + 1)
    choice = [0] * (s + 1)

    for total in range(1, s + 1):
        upper = min(n, total)
        best_value = -1

        for size in range(1, upper + 1):
            candidate = dp[total - size] + best[size]
            if candidate > best_value:
                best_value = candidate
                choice[total] = size

        dp[total] = best_value

    # Reconstruct the selected subsets.
    answer = [0] * n
    total = s

    while total > 0:
        size = choice[total]
        mask = best_mask[size]

        x = mask
        while x:
            b = x & -x
            v = b.bit_length() - 1
            answer[v] += 1
            x ^= b

        total -= size

    print(*answer)

if __name__ == "__main__":
    solve()
```実装の最初の部分では、ブール型の隣接関係ではなくエッジの多重度が保存されます。 平行エッジは独立して目的に寄与するため、これは不可欠です。 

サブセット DP は、新しく追加された頂点を識別するために最も低い設定ビットを使用します。`prev = mask ^ bit`まさにその頂点を削除しますので、`f[prev]`はすでに計算されています。 のビットにわたるループ`prev`次に、新しい頂点から古いサブセットまでのすべてのエッジの多重度を追加します。 

の`best`array は、すべての (2^n) 個のサブセットを (n) 個の有用な値のみに圧縮します。 考えられる各サブセット サイズの最大誘導エッジ数が判明すると、問題のグラフ固有の部分は終了します。 

ナップザックの用途が増えています`total`、 それで`dp[total - size]`はすでに利用可能です。 同じサブセット サイズが多くのトークン レベルで発生する可能性があるため、アイテムは意図的に再利用可能です。 

再構築は、保存されたサブセット サイズを逆方向にたどります。 選択したサブセットごとに、そのサブセット内のすべての頂点が 1 つのトークンを受け取ります。 これは、そのサブセットをレベルセット表現の 1 つのレイヤーとして追加することと同じです。 

Python の整数はオーバーフローしませんが、目的は (100000 \cdot 100=10^7) まで大きくなる可能性があるため、通常の Python 整数で十分です。 唯一のデリケートなインデックス作成の問題は、設定された最下位ビットを頂点インデックスに変換することです。`bit_length() - 1`。 

## 実用的な例

 ### サンプル 1

 グラフには、頂点 (1、2、3) で三角形を形成する 4 つの頂点と 4 つのエッジ、および頂点 (1) から頂点 (4) までのエッジがあります。 トークンは6枚あります。 

サブセット サイズごとの最適な誘導エッジ数は次のとおりです。 

[
 F_1=0、\qquad F_2=1、\qquad F_3=3、\qquad F_4=4。 
]

 ナップザックはサイズ 3 の 2 層を好み、値 (3+3=6) を与え、正確に 6 つのトークンを使用します。 

| DP合計 | 選択したレイヤー サイズ | DP値 | 再構築されたトークン数 |
 | --- | --- | --- | --- |
 | 3 | 3 | 3 | (1,1,1,0) |
 | 6 | 3 | 6 | (2,2,2,0) |

 最終的な答えは、```
2 2 2 0
```三角形の 3 つの頂点はそれぞれ 2 つのトークンを受け取るため、3 つの三角形のエッジはそれぞれ容量 2 を持ち、4 番目のエッジは容量 0 を持ちます。 合計は (6) となり、サンプルの最適値と一致します。 

### サンプル 2

 頂点が 3 つ、エッジが 7 つ、トークンが 7 つあります。 グラフには、提供されたサンプル分布の 2 トークンの最小値に寄与する 5 つのエッジがあり、残りの 2 つのエッジも容量 2 を受け取ります。 

重要な DP 状態は、最良の 3 頂点サブセットがグラフ全体であり、その誘導エッジ数が 7 であることです。 そのサブセットを 2 回取得すると、6 つのトークンが使用され、14 が寄与します。 残りの 1 つのトークンは、すでに取得されている寄与を増減させることなく、1 つの頂点に配置できます。 

| DP合計 | 選択したレイヤー サイズ | DP値 | 再構築後のトークン数 |
 | --- | --- | --- | --- |
 | 3 | 3 | 7 | (1,1,1) |
 | 6 | 3 | 14 | (2,2,2) |
 | 7 | 1 | 14 | (3,2,2) |

 結果の出力は次のとおりです。```
3 2 2
```すべてのエッジには最初の 2 つのレベルで容量 2 があり、最後の単一トークンは追加のエッジ寄与を作成しません。 サンプルに示すように、結果の合計は 14 になります。

## テストケース

 次のテスト ハーネスは、ソリューションを関数として埋め込み、提供されたサンプルといくつかの対象ケースの両方を検証します。 この問題ではあらゆる最適な分布が受け入れられるため、サンプル チェックでは、特定の 1 つの有効な出力を要求するのではなく、生成された分布の目的を検証します。```python
import sys
import io

def solve_data(inp: str) -> str:
    data = list(map(int, inp.split()))
    it = iter(data)

    n = next(it)
    m = next(it)
    s = next(it)

    edges = [[0] * n for _ in range(n)]

    for _ in range(m):
        u = next(it) - 1
        v = next(it) - 1
        edges[u][v] += 1
        edges[v][u] += 1

    limit = 1 << n
    f = [0] * limit
    best = [0] * (n + 1)
    best_mask = [0] * (n + 1)

    for mask in range(1, limit):
        bit = mask & -mask
        v = bit.bit_length() - 1
        prev = mask ^ bit

        value = f[prev]
        x = prev
        row = edges[v]

        while x:
            b = x & -x
            u = b.bit_length() - 1
            value += row[u]
            x ^= b

        f[mask] = value
        size = mask.bit_count()

        if value > best[size]:
            best[size] = value
            best_mask[size] = mask

    dp = [0] * (s + 1)
    choice = [0] * (s + 1)

    for total in range(1, s + 1):
        for size in range(1, min(n, total) + 1):
            candidate = dp[total - size] + best[size]
            if candidate > dp[total]:
                dp[total] = candidate
                choice[total] = size

    ans = [0] * n
    total = s

    while total:
        size = choice[total]
        mask = best_mask[size]

        x = mask
        while x:
            b = x & -x
            v = b.bit_length() - 1
            ans[v] += 1
            x ^= b

        total -= size

    return " ".join(map(str, ans))

    assert len(ans) == n
    assert sum(ans) == s
    assert all(0 <= x <= s for x in ans)

    return sum(min(ans[u], ans[v]) for u, v in edges)

def brute_optimum(inp: str) -> int:
    data = list(map(int, inp.split()))
    it = iter(data)

    n = next(it)
    m = next(it)
    s = next(it)

    edges = []
    for _ in range(m):
        edges.append((next(it) - 1, next(it) - 1))

    best = -1

    def dfs(pos, remaining, a):
        nonlocal best

        if pos == n - 1:
            a[pos] = remaining
            value = sum(min(a[u], a[v]) for u, v in edges)
            best = max(best, value)
            return

        for x in range(remaining + 1):
            a[pos] = x
            dfs(pos + 1, remaining - x, a)

    dfs(0, s, [0] * n)
    return best

def run(inp: str) -> str:
    return solve_data(inp)

 ## 特殊なケース

 (s=0) の場合、レベル セットはまったくありません。 ナップザックはで始まり、で終わります`dp[0]`、再構築では反復は実行されず、すべての回答エントリはゼロのままです。 正確な入力のために```
1 0 0
```アルゴリズムの出力```
0
```総容量はゼロです。 

平行なエッジがある場合、行列には​​その多重度が格納されます。 のために```
2 5 3
1 2
1 2
1 2
1 2
1 2
```唯一有用なサブセットは ({1,2}) であり、その誘導エッジ数は 5 です。 ナップザックは、その 2 つの頂点レイヤーを 1 回選択し、1 つの頂点レイヤーを 1 回選択して、`2 1`。 5 つの平行なエッジはすべて容量 1 を持っているため、合計は 5 になります。 ブール隣接行列は、サブセット値を誤って 1 として計算します。 

(s) が (n) よりもはるかに大きい場合、同じサブセットが何度も選択される可能性があります。 のために```
2 1 100
1 2
```最適なレイヤーのサイズは 2、値は 1 です。 ナップザックは、100 個のトークンすべてを使用して、そのようなレイヤーを 50 個選択します。 したがって、両方の頂点は 50 個のトークンを受け取り、単一のエッジの容量は 50 個になります。 

5 つのトークンを持つ 3 つの頂点上の完全なグラフの場合、```
3 3 5
1 2
2 3
1 3
```最適なサイズ 3 のサブセットには 3 つのエッジがありますが、最適なサイズ 2 のサブセットには 1 つのエッジがあります。 最適なナップザックの分解では、サイズ 3 のレイヤーを 1 つとサイズ 2 のレイヤーを 1 つ使用します。 再構築された割り当ては、`2 2 1`、その 3 つのエッジ容量は (2,1,1) で、合計 4 つです。 このケースでは、サブセット サイズを繰り返し実行し、レベルセットの解釈が個々のトークンについて直接推論するよりも役立つ理由を示します。 

最大サイズの場合は (n=18) なので、(262144) 個のサブセットがあります。 誘導エッジ数はグラフ全体を再スキャンするのではなく、以前に計算されたサブセットから取得されるため、この実装では依然としてすべてのサブセットが処理されます。 これはまさに (n\le18) 制約が利用される場所です。指数部分は頂点の数に依存しますが、多数の入力エッジは (18\times18) 多重度行列に吸収されます。
