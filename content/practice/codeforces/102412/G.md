 ## 解決策
 ## 問題の理解

 (n) 個の要素を含むセット (S) があり、(S) のすべてのサブセットは赤または青でペイントする必要があります。 サブセット (T) の場合、赤にペイントすると (R_T)、青にペイントすると (B_T) のコストがかかります。 コストがマイナスになる可能性があるため、単に安い色を単独で選択することが目的ではありません。 

カラーリングには構造上の制限が 1 つあります。 2 つのサブセット (A) と (B) が同じ色を持つ場合、それらの和集合 (A\cup B) も同じ色を持つ必要があります。 言い換えれば、各色のサブセットは和集合をとって閉じる必要があります。 

入力はビットマスクによってサブセットを表します。 マスク (i) は、対応するビットが設定されている要素を正確に含むサブセットを表します。 したがって、2 つの配列にはそれぞれ (2^n) 個のコストが含まれます。 すべての (2^n) サブセットにわたる選択されたペイント コストの最小合計が必要です。 

境界 (n\le20) が主信号です。 サブセットは最大で (2^{20}=1,048,576) 個であるため、(O(2^n)) または (O(n2^n)) の解が現実的です。 2 秒の制限では、(3^{20}=3,486,784,401) であるため、(O(3^n)) などは (n=20) ですでに大きすぎます。 (256) MiB のメモリ制限は、いくつかのサブセットによってインデックス付けされた大きな DP テーブルを保存するのではなく、サイズ (2^n) の配列を少数だけ保持する必要があることも意味します。 公式の制約と制限は、(n\le20)、コストは (-10^9) ～ (10^9)、2 秒、および (256) MiB です。 

誤って対処しやすい特殊なケースがいくつかあります。 まず、(n=0) は空のサブセットのみを残します。 例えば、```
0
-129363358
227605714
```答えがあります`-129363358`というのは、サブセットが 1 つだけ存在し、その安価な色を選択するだけだからです。 このサンプルは元のステートメントに含まれています。 

マイナスのコストもミスの原因です。 コストが負ではないと仮定する解決策は、問題を通常の最小コストの色として解釈しようとするかもしれませんが、和集合の制限により多くのサブセットが結合されるため、コストが負の場合、一見高価に見える色が全体的に好ましいものになる可能性があります。 

最後に、空のサブセットは通常のサブセットとして扱う必要があります。 (n=1) の場合、空のセットとシングルトンの 2 つのサブセットが存在します。 空のセットには、色付けルールからの特別な例外はありません。 基本ケースにそのコストを含めることを忘れると、ちょうど 1 つのサブセット コストだけずれた答えが生成されます。 

## アプローチ

 この問題を直接考える方法は、すべてのサブセットに対して有効な色を決定することです。 つまり、(2^{2^n}) 個の可能な色付けを検討し、結合条件をチェックすることを意味します。 これは非常に小さい (n) ではすでに絶望的であるため、結合閉包の特殊な構造を利用する必要があります。 

より有用な総当たり動的プログラミング アプローチでは、固定セット (S) を検討します。 (S) が赤だとします。 (S) のすべての青い部分集合のうち、それらの和集合を取り出して、それを (V) と呼びます。 青のサブセットは結合の下で閉じているため、(V) 自体が青であり、唯一の最大の青のサブセットになります。 (V) に含まれないすべてのサブセットは赤でなければなりません。そうしないと、(V) との結合が (V) よりも大きくなる別の青のサブセットになるからです。 

これにより、(V\subseteq S) を列挙する DP が得られます。 それぞれの (S) について、考えられるすべての (V) を試し、(V) の内側の色付けの問題を解決し、(V) の外側のすべてのサブセットを赤で支払うことができます。 これをすべてのペア (V\subseteq S) に対して行うと (O(3^n)) 時間がかかります。 (n=20) では、これは約 (34 億 9) 億のサブセット関係となり、制限をはるかに超えています。 (S) が青の場合も同じ理由が当てはまります。 この構造的 DP は正しいですが、あまりにも多くの可能性を検討しています。 (O(3^n)) の観点も、より速い再発を発見するのに役立つ方法です。 

重要な観察は、実際には最大の反対色のサブセットを識別する必要がないということです。 (S) が赤だとします。 (e\in T\subseteq S) を満たすすべてのサブセット (T) が赤になるような、何らかの要素 (e\in S) が存在する必要があります。 その理由を理解するには、逆のことを想定してください。 次に、すべての要素 (e) に​​対して、(e) を含む青色のサブセットが存在します。 これらすべての青色のサブセットを結合すると、(S) が得られます。 青のサブセットは和集合が閉じているため、(S) 自体は青でなければならず、(S) が赤であることと矛盾します。 

このような要素 (e) が選択されると、(e) を含むすべてのサブセットの色が強制的に赤になります。 残りのサブセットはまさに (S\setminus{e}) のサブセットであり、独立した小さなインスタンスとして最適に色付けできます。 これにより、構造観察がマスク上の反復に変わります。 

(R(S)) が (S) のすべてのサブセットの赤コストの合計を表すものとし、同様に (B(S)) を定義します。 (S) から (e) を削除すると、(R(S)-R(S\setminus{e})) は正確に、(e) を含む (S) のすべてのサブセットの赤コストの合計になります。 青についても同様です。 

(dp[S]) が、(S) の色を固定せずに、(S) のすべてのサブセットを着色するための最小コストを表す場合、

 最初の項は、(e) を含まないすべてのサブセットを再帰的に色付けします。 2 番目の項は、(e) を含むすべてのサブセットが赤であるか、すべてが青であるかを選択します。 

(R(S)) と (B(S)) を計算するだけで済みます。これは、(O(n2^n)) の標準サブセット合計、つまり SOS DP です。 最後の反復でも各セット要素が 1 回考慮されるため、合計は (O(n2^n)) のままになります。 これは、受け入れられているソリューションで使用される最適なアプローチです。

 ## アルゴリズムのチュートリアル

1. Read the two cost arrays. Mask (s) represents a subset of the original set, so there are (2^n) masks.
 2. Transform the red array into (R[s]), the sum of red costs over every submask of (s). Perform the same transformation on the blue array to obtain (B[s]). これは標準的な SOS DP であり、終了後の (t=s\setminus{e}) の差 (R[s]-R[t]) は、まさに (e) を含む (s) のサブセットの赤コストの合計になります。 
3. Set (dp[0]=\min(R[0],B[0])). The empty set has no elements to remove, so it is the base case. Since it is the only subset when (n=0), this also immediately handles the smallest possible instance.
 4. Process every nonempty mask (s) in increasing numerical order. For every set bit (e) of (s), let (t=s\setminus{e}). Because (t<s), its DP value has already been computed.
 5. Assume the selected element is (e). Every subset of (s) containing (e) must receive one common color. If that color is red, their total contribution is (R[s]-R[t]). If it is blue, their contribution is (B[s]-B[t]). The smaller of these two values is the best choice for this particular (e).
 6.アップデート

 \分\左(
 dp[s]、
 dp[t]+\min(R[s]-R[t],B[s]-B[t])
 \右）。 
】

 1. すべてのマスクが処理された後、(dp[2^n-1]) を出力します。このマスクは完全なセット (S) を表すため、元のセットのすべてのサブセットが考慮されています。 

### なぜ効果があるのか

 The invariant is that (dp[S]) is the minimum cost of a valid coloring of every subset of (S). Consider any optimal coloring of a nonempty (S), and suppose (S) is red. 和集合閉合条件は、ある要素 (e\in S) が、(e) を含むすべてのサブセットが赤であるという特性を持つことを保証します。 (e) を削除すると (S\setminus{e}) のサブセットがそのまま残り、その最適コストは (dp[S\setminus{e}]) になります。 All remaining subsets containing (e) are forced to red and contribute (R[S]-R[S\setminus{e}]). The same argument applies when (S) is blue. Thus every optimal coloring is represented by one of our transitions, while every transition produces a valid coloring. Taking the minimum gives exactly (dp[S]).

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(data=None):
    if data is None:
        n = int(input())
        m = 1 << n
        red = list(map(int, input().split()))
        blue = list(map(int, input().split()))
    else:
        it = iter(map(int, data.split()))
        n = next(it)
        m = 1 << n
        red = [next(it) for _ in range(m)]
        blue = [next(it) for _ in range(m)]

    # SOS DP:
    # red[s] = sum(red[t]) for all t subset of s.
    # blue[s] = sum(blue[t]) for all t subset of s.
    step = 1
    while step < m:
        block = step << 1
        for base in range(0, m, block):
            end = base + step
            for s in range(base, end):
                red[s + step] += red[s]
                blue[s + step] += blue[s]
        step <<= 1

    INF = 10**30
    dp = [INF] * m
    dp[0] = min(red[0], blue[0])

    for s in range(1, m):
        best = INF
        x = s
        while x:
            bit = x & -x
            t = s ^ bit

            add = red[s] - red[t]
            other = blue[s] - blue[t]
            if other < add:
                add = other

            cand = dp[t] + add
            if cand < best:
                best = cand

            x ^= bit

        dp[s] = best

    return str(dp[m - 1])

if __name__ == "__main__":
    print(solve())
```The first part stores the two original cost arrays. The SOS transform then changes their meaning from “cost of exactly this subset” to “total cost of all submasks”. インプレース変換は、各ビットが 1 回処理され、ビットがマスクに追加されるときに、そのビットを除いた値が現在のステージですでに確定されているため、安全です。 

基本ケースでは、`min(red[0], blue[0])`、SOS 変換後は両方とも`red[0]`そして`blue[0]`は依然として空のサブセットのみのコストを表します。 

マスクごとに、`x & -x`セットビットを1つ抽出します。 そのビットを削除すると、`t = s ^ bit`。 すべて (n) の位置ではなく、設定されたビットを反復処理することで、不必要なチェックが回避され、正確に (\operatorname{popcount}(s)) の遷移が実行されます。 

表現`red[s] - red[t]`まさにこれらのサブマスクの赤のコストの合計です。`s`削除された要素が含まれているもの。 対応する青色の式も同じ解釈になります。 Python の整数には任意の精度があるため、考えられる総コストはおよそ (2^{20}\cdot10^9) に達する可能性がありますが、特別なオーバーフロー処理は必要ありません。 

DP の順序付けには、マスクの番号順でも十分です。 設定されたビットを削除すると、常に小さなマスクが生成されるため、`dp[t]`前に利用可能です`dp[s]`評価されます。

 ## 特殊なケース

 (n=0) の場合、マスク空間にはマスクのみが含まれます。`0`。 SOS 変換は何も行わず、DP は初期化されます。`dp[0]`2つのコストのうち安い方に。 具体的なインプットとしては```
0
-129363358
227605714
```アルゴリズムが計算します`dp[0] = min(-129363358, 227605714)`、与える`-129363358`。 これはまさに、単一の空のサブセットに必要な動作です。 

マイナスのコストについては、次の点を考慮してください。```
1
-5 -10
0 -1
```空のサブセットは赤色で最も安価です。`-5`、シングルトンも赤で最も安価です。`-10`、したがって、答えは次のとおりです`-15`。 DP は次から始まります`dp[0] = -5`。 マスク用`1`、そのビットのみを削除するとマスクが残ります`0`; 赤い増分は`-10`、青の増分は`-1`。 最小増分は`-10`、生産`dp[1] = -15`。 繰り返しのどこにもコストのプラスに関する仮定は現れません。 

すべてのコストが等しい場合、次のことを考慮します。```
2
5 5 5 5
7 7 7 7
```4 つのサブセットのそれぞれにコストがかかります`5`赤と`7`青で。 赤のファミリーがパワーセット全体であり、自明に結合が閉じられているため、すべてのサブセットを赤に着色することは有効です。 結果的に答えは`4*5 = 20`。 すべての遷移で赤の増分が選択されるため、繰り返しでも同じ結果が得られます。`5`の青の増分ではなく、新たに強制されたサブセットごと`7`。 

最大サイズの境界は (n=20) です。ここで、マスクは`2^20-1 = 1,048,575`最大の有効なインデックスです。 よくある実装エラーは、誤って割り当てを行うことです。`2^n-1`エントリ、またはインデックスにアクセスする包含ループの使用`2^n`。 ソリューションは正確に割り当てます`1 << n`エントリとプロセスのマスク`1`を通して`m-1`したがって、最大のマスクは範囲外アクセスなしで 1 回だけ処理されます。 

主な論理的なエッジ ケースは、最適なカラーリングに両方の色が含まれるセットです。 反復では、セット全体が単色であることは想定されていません。 代わりに、サブセット ラティスの半分を含む全体がフルセットと同じ色を持つ 1 つの要素の存在のみに依存します。 その要素が修正されると、残りの半分が再帰的に最適化されます。 これはまさに、完全な色を列挙する必要がなく、結合閉鎖条件が役立つ理由です。
