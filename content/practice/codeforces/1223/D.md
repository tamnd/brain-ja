 ## 解決策
 ## 問題の理解

 複数の独立したシーケンスが与えられており、それぞれのシーケンスを非常に特殊な演算を使用して非減少配列に変換したいと考えています。 許可される唯一の操作は値を選択することです`x`そして、すべての出現を取得します`x`配列内ですべての要素を完全に前方または完全に後方に再配置し、内部順序は維持しますが、元の位置は維持しません。 

この操作は、1 つの値を配列の端で 1 つのブロックに「クラスター化」できるため、強力です。 ただし、追加の操作を行わずに値の出現を複数のグループに分割したり、任意の方法でそれらをインターリーブしたりすることはできないため、制限的でもあります。 

目標は、各配列を非降順でソートするために必要なこのような演算の最小数を計算することです。 

制約は大きく、すべてのクエリにわたる要素の総数は最大 300,000 です。 これにより、クエリごとに二次的な解が即座に除外されます。 クエリごとに O(n log n) アプローチを使用する場合でも、慎重な実装が必要ですが、テスト ケースごとに全体的に線形またはほぼ線形のアプローチが期待されます。 

値が複雑なパターンで繰り返される場合、微妙な問題が発生します。 単純な直観では、ソートされた配列との「反転」または不一致をカウントする必要があるかもしれませんが、1 回の操作で散在する値の多数の出現を一度に修正できるため、それは失敗します。 たとえば、値が多くのセグメントに表示される場合、値を 1 回移動すると、複数の障害点を同時に修復できます。 

よくある失敗例は、値が交互のパターンで表示される場合です。 

例:

 入力:`[1, 2, 1, 2, 1, 2]`単純なアプローチでは、複数の修正が必要であると考えるかもしれませんが、実際には、単一の値を慎重にグループ化することで操作を大幅に削減できます。 個々の立場よりも、「同じ値のブロック」の構造が重要です。 

もう 1 つのエッジケースは、配列がすでにソートされている場合です。 正しい解はすぐにゼロを返す必要がありますが、変換または貪欲な動きに依存するアプローチでは、明示的に並べ替えをチェックしないと、誤って操作がカウントされたままになる可能性があります。 

## アプローチ

 強引なアイデアは、プロセスをシミュレートすることです。各ステップで、考えられるすべての値を試します。`x`および両方向 (前または後) に操作を適用し、残りのコストを再帰的に計算します。 各状態が最大で分岐するため、これはすぐに指数関数的になります。`2 * distinct_values`可能性があり、シーケンスの長さは依然として大きいままです。 たとえメモ化を行ったとしても、繰り返される値の順列により多くの同等だが異なる表現が作成されるため、状態空間が大きすぎます。 

重要な洞察は、立場の観点から考えるのをやめ、代わりに価値の推移の観点から考えることです。 すべての操作が完了すると、それぞれの個別の値が、最終的に並べ替えられた配列内の連続したセグメントを占有します。 したがって、問題は、どれだけの「価値セグメント」を積極的に再配置する必要があるかを決定することになります。 

連続する等しい値を圧縮した後に配列を見ると、一連のブロックが得られます。 重要な観察は、操作で修正できるのは異なる値のブロック間の「不正な境界」を 1 つだけであり、実際、最適な戦略は、ソートされた順序に対してシーケンスの方向が何回変わるかに密接に関係しているということです。 

これをより正確に見るには、等しい値が連続し、個別の値の順序が単調になるように操作を最小限に抑えたいと考えています。 これは、自然な実行構造から切り離す必要がある「価値グループ」の数を数えることに帰着します。 

連続する重複を圧縮した後、異なる値の間の遷移を調べます。 答えは、各値が並べ替えられた順序で単一の連続した間隔を形成するように、値の出現の互いに素なセグメントをいくつ調整する必要があるかによって決まります。 値を他の値と「インターリーブ」するたびに、少なくとも 1 つの操作が強制され、最適なマージにより、必要な分離ごとに 1 回の支払いだけが保証されます。 

したがって、解決策は圧縮ブロックに対する線形スキャンとなり、ソートされたグループ化構造に違反するセグメントの数を追跡します。

 ## アルゴリズムのチュートリアル

 各クエリを個別に解決します。 

1. 配列を同じ値の連続したブロックに圧縮します。 これにより、繰り返される値がすでに局所的な連続性を形成しており、演算数に影響を与えない冗長な構造が削除されます。 
2. 圧縮シーケンスをスキャンし、あるブロックから別のブロックに値が変化する遷移を記録します。 
3. 各値について、その出現が複数の分離された領域に現れるかどうかを追跡します。 これは、圧縮構造内で連続していない複数のブロック グループに値が出現するかどうかをチェックすることと同じです。 
4. 各分割値を統合するには少なくとも 1 つの操作が必要となるため、このような「分割値」がいくつ存在するかを数えます。 
5. このカウントを答えとして返します。 

ステップ 3 の背後にある直感は非常に重要です。値が他の値によって区切られた複数の互いに素な領域に表示される場合、その値を少なくとも 1 回明示的に移動しない限り、それを修正することはできません。 このような各値は、1 つの避けられない操作に寄与します。 

### なぜ効果があるのか

 この操作により、出現するすべての値を取得して一方向に移動することができますが、部分的な再配置はできません。 したがって、各値は 1 回の操作で「修正」できますが、これは、それに対処することを選択した場合に限られます。 複数の操作が必要な唯一の理由は、1 つを修正しても他の値が自動的に修正されないような方法で複数の値がインターリーブされている場合です。 圧縮されたブロック構造により、繰り返されるローカル ノイズではなく、真のインターリーブのみがカウントされます。 これにより不変条件が作成されます。処理後、すべてのカウント値は必ず配列全体で断片化され、少なくとも 1 つの専用操作がなければ解決できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        a = list(map(int, input().split()))

        # compress consecutive duplicates
        b = []
        for x in a:
            if not b or b[-1] != x:
                b.append(x)

        # count segments per value
        first_pos = {}
        last_pos = {}

        for i, x in enumerate(b):
            if x not in first_pos:
                first_pos[x] = i
            last_pos[x] = i

        # count how many values are "split" in compressed array
        ans = 0
        for x in first_pos:
            if first_pos[x] != last_pos[x]:
                ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```値が断片化されているかどうかを判断するには遷移のみが重要であるため、実装では連続する重複を削除することから始めます。 次に、この圧縮シーケンス内の各値の最初と最後の出現を記録します。 値が複数の分離されたブロックに出現する場合、その最初と最後の位置は異なります。これは、値が構造全体に分割されていることを意味します。 

最終的な答えは、そのような値がいくつ存在するかを数えます。 それぞれが必要な操作を 1 つだけ提供します。 

微妙な点は、移動する値を明示的にシミュレートする必要がないことです。 圧縮された表現には、すべての意味のある構造情報がすでに取り込まれています。 

## 実用的な例

 ### 例 1

 入力:`[3, 1, 6, 6, 3, 1, 1]`圧縮シーケンス:`[3, 1, 6, 3, 1]`| ステップ | 圧縮された | 最初/最後の追跡 | 分割値 |
 | --- | --- | --- | --- |
 | 開始 | [3,1,6,3,1] | 空 | 0 |
 | プロセス | 同じ | 3:(0,3)、1:(1,4)、6:(2,2) | 3,1 |

 ここでは、3 と 1 の両方が複数の離れた位置に出現するため、両方ともカウントされます。 答えは２になります。 

これは、値が局所的に繰り返される場合でも、重要なのは、値が圧縮構造内の複数の切断された領域に現れるかどうかであることを示しています。 

### 例 2

 入力:`[1, 1, 4, 4, 4, 7, 8, 8]`圧縮:`[1, 4, 7, 8]`| ステップ | 圧縮された | 追跡 | 分割値 |
 | --- | --- | --- | --- |
 | 開始 | [1,4,7,8] | 1:(0,0)、4:(1,1)、7:(2,2)、8:(3,3) | なし |

 値が分割されていないため、答えは 0 になります。 

これにより、すでに単調なブロック構造には操作が必要ないことが確認されます。

 ## 特殊なケース

 次のような単一要素配列の場合`[5]`、圧縮収量`[5]`、分割値がないため、答えはゼロになります。 最初と最後の出現が一致するため、アルゴリズムは正しくゼロを生成します。 

次のようなすべて同じ値を持つ配列の場合`[2,2,2,2]`、圧縮すると 1 つのブロックに減ります。 複数の分離された値が含まれる値はないため、やはり答えはゼロになります。 

次のような高度に交互の配列の場合`[1,2,1,2,1,2]`、圧縮により交互が維持されます。 両方の値が複数の離れた位置に現れるため、両方がカウントされ、単調な順序付けを達成するために両方の値を分離する必要性と一致する 2 つの演算が生成されます。
