 ## 解決策
 ## 問題の理解

 多数の一致が与えられたので、それらを「a + b = c」という形式の有効な算術方程式に整理したいと思います。ここで、各数値は厳密に正です。 各数字は、古典的な問題で暗示される通常の 7 セグメント スタイルのマッチ棒を使用して表現されますが、重要な単純化は、数字の正確な形状ではなく、必要な一致の数のみを考慮することです。 

課題は、使用するマッチの数を自由に選択することではありません。 指定されたすべての一致を使用する必要がありますが、必要に応じて追加の一致を購入して、合計を有効な方程式に再配置することができます。 

各クエリの出力は、一致の総数が a + b = c を満たす 3 つの正の整数 a、b、c に分割できるようにするために必要な追加一致の最小数です。 

n ≤ 10^9 および最大 100 個のクエリという制約により、考えられる数字の構成に関するシミュレーションは直ちに除外されます。 どのような解決策でも、問題をクエリごとの定数時間の算術チェックに削減する必要があります。 

微妙な問題は、単純なアプローチでは、貪欲に数字を形成したり、小さな方程式をテストしようとしたりする可能性があることです。 これは、数値によって使用される一致の数がその 10 進表現に依存し、組み合わせが無限に存在するため、失敗します。 もう 1 つの間違った考えは、繰り上げ加算について直接推論しようとすることですが、問題は桁の和に関するものではありません。 それは、n を有効な正の整数に対応する一致カウントに分解できるかどうかです。 

重要な隠れた制約は、一致で有効な a + b = c を形成するための最小の「構造コスト」が固定されており、追加の一致を購入する必要があるかどうかを決定するのはその構造の剰余だけであるということです。 

## アプローチ

 総当り攻撃を試す場合は、正の整数のトリプル (a、b、c) をすべて列挙し、それらを表すために必要な一致の数を計算し、合計が n に等しいかそれを超えているかどうかを確認します。 数値は任意に大きくなる可能性があり、最大 n の値に制限しても、それぞれが c を生成する (a, b) の候補ペアが n² 個必要になるため、これはすでに実行不可能です。 n が 10^9 までの場合、これは不可能です。 

重要な観察は、実際の数字の構造が非常に単純な不変式に崩壊することです。a + b = c の有効な構築はすべて、n 法 2 に常に一致する一致の数を消費します。直観的に、マッチ棒の数字を使用して方程式を構築する場合、一致を追加するたびにパリティが変更され、有効な方程式の構造により、すべてのコンポーネントにわたって固定パリティ パターンが適用されます。 CME を形成する一致の最小限の「有効ブロック」は、不均衡の単位ごとに 2 つの一致を使用します。重要なのは、n を残り物なくそのようなブロックに分割できるかどうかだけです。 

具体的には、この解決策は、n がすでに有効な構成を形成できるかどうかを確認することになります。 そうでない場合は、最も近い有効な構造に到達するために 1 つまたは 2 つの一致を追加する必要があります。 すべての有効な構成は基本構造からの偶数の合計シフトに対応するため、答えは n mod 2 のみに依存することになります。 

したがって、最適な戦略は、n が有効なパリティ クラスにすでに適合しているかどうかを判断することです。 そうでない場合は、次の有効な構成に増分します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | (a, b, c) の総当たり列挙 | O(n²) 以上 | お(1) | 遅すぎる |
 | パリティベースの直接計算 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 解決策は、有効な方程式構造を形成できる最も近い一致数を特定することに基づいています。

1. 各クエリは独立しており、状態が共有されていないため、クエリごとに n を読み取ります。 
2. n がマッチ棒数字を使用して a + b = c への有効な分解をすでに許可しているかどうかを確認します。 これは、n が 2 で割り切れるかどうか、より正確には、n が到達可能な有効な構造のセットに属しているかどうかをチェックすることになります。 
3. n がすでに有効な構成に一致する場合、追加の一致は必要ないため、0 を出力します。 
4. それ以外の場合は、次の有効な構成に到達するためにいくつの一致を追加する必要があるかを計算します。 有効な構成は 2 つの一致の固定周期で発生するため、調整は、n が最も近い有効な構造からどれだけ離れているかに応じて、常に 1 または 2 になります。 
5. その差分を出力します。 

### なぜ効果があるのか

 有効な方程式 a + b = c は、安定した算術構造を形成する一致カウントを使用します。 肯定的制約を破ることなく実現可能性を変更できる最小の構成要素は、固定パリティ パターンによって合計一致数をシフトします。 その結果、達成可能なすべての合計がステップ 2 の等差数列を形成します。したがって、答えは、n をこの数列に移動する最小の非負の増分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        
        # If n is even, it can be arranged into a valid CME configuration.
        # If n is odd, we need to add 1 match to make it even.
        if n % 2 == 0:
            print(0)
        else:
            print(1)

if __name__ == "__main__":
    solve()
```コードは各クエリを独立して処理します。 重要な決定は、n のパリティ チェックです。 n が偶数の場合、追加の一致は必要ありません。 n が奇数の場合、一致するものを 1 つだけ追加して合計が偶数になるようにします。これは、次の有効な構築クラスに対応します。 

微妙な点は、方程式を明示的に構築しようとしていないことです。 この推論は、すべての有効な一致分布には合計の均等性が必要であるため、パリティだけで実現可能性が完全に決まるという構造的事実に基づいています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    out = []

        out.append("0" if n % 2 == 0 else "1")

 ## 特殊なケース

 重要なエッジ ケースは、考えられる最小の入力 n = 2 です。これにより、すでに「1 + 1 = 2」を形成できるため、答えは 0 でなければなりません。アルゴリズムは 2 % 2 = 0 をチェックし、正しく 0 を出力します。 

n = 3 の場合、有効な構築には偶数の合計が必要であるため、正確に 3 つの一致を使用して有効な方程式を作成することはできません。 アルゴリズムは 3 % 2 = 1 を識別し、1 を出力します。これは、4 に到達するには 1 つの一致を購入する必要があることを意味します。 

n = 10^9 のような大きな値の場合でも、パリティがすべてを決定します。 n が偶数の場合、加算は必要ありません。 奇数の場合は、正確に 1 つの一致が必要です。 このアルゴリズムは大きさに依存しないため、上限に達しても安定しています。
