 ## 解決策
 ## 問題の理解

 それぞれ整数の長さを持つログのコレクションが与えられます。 これらの丸太から部分を切り出すことは許可されていますが、部分を接着することは許可されていません。 目標は、x と y と呼ぶ 2 種類の辺の長さを必要とする長方形のいかだ構造を組み立てることです。 いかだには、長さ x の 2 つの辺と、長さ y の x 個のコピーが必要であり、その「面積」は x と y の積として定義されます。 x と y は両方とも 2 以上の整数でなければなりません。 

主な問題点は、1 つのログが複数の使用可能なセグメントに分割される可能性があるため、1 つの長いログが多数の小さな部分に寄与する可能性があることです。 ただし、すべての部分は長さを消費するため、ログ間をマージせずに元のログから取得する必要があります。 

入力サイズは最大 5×10^5 ログと大きく、それぞれの長さも最大 5×10^5 になります。 これにより、切断の選択肢をシミュレートしたり、ログのすべてのパーティションを列挙しようとするアプローチは即座に排除されます。 最大長の二次関数であっても不可能です。 ソリューションでは、すべてのログを何らかの集約構造に効果的に圧縮し、取得可能なセグメントの数を推論する必要があります。 

微妙な点は、実現可能性は、セグメントがどのログから来たのかではなく、生成されたセグメントの数に依存するということです。 ログが切断されると、それは整数の長さの複数セットになり、問題はセグメント頻度に関するグローバルなカウント制約の問題になります。 

単純な間違いは、元のログの長さを x と y の候補として考慮するだけでよいと仮定することです。 これは、大きなログが多数の小さなセグメントに分割され、入力に現れない値が可能になる可能性があるため、失敗します。 たとえば、長さ 100 の単一のログは長さ 2 のセグメントを 50 個生成できます。これは、入力に 2 が現れない場合でも、x または y の制約をサポートするには十分です。 

別の失敗モードは、元の値の周波数配列から独立して x と y を選択するものとして問題を扱うことです。 これは、各丸太が切断方法に応じて複数の需要または供給単位に寄与すること、および実現可能性が生の数ではなく全長の分布によって制限されることを無視しています。 

## アプローチ

 ブルート フォースの観点では、すべての整数ペア (x, y) を試し、各ペアについて、要件を満たすのに十分なセグメント (長さ x の少なくとも 2 つのセグメントと長さ y の少なくとも x つのセグメント) に丸太を切断できるかどうかをシミュレートします。 実現可能性を確認するために、各丸太を可能な限り多くの x または y の部分に貪欲に切断し、残った断片を追跡します。 

これは原則として正しいです。すべての有効な構造が丸太ごとのカットの割り当てに対応しているからです。 ただし、候補ペアの数は O(M^2) で、M は最大 5×10^5 であり、これはまったく実行不可能です。 除数または入力値のチェックのみに減らしても、依然として多すぎるペアが残ります。 

重要な観察は、実現可能性はすべてのログから特定の長さのセグメントをいくつ生成できるかによってのみ決まるということです。 固定の候補長 L の場合、各ログはサイズ L のフロア(a_i / L) セグメントに寄与します。これにより、問題はすべての L にわたるグローバル周波数関数 f(L) に変換されます。 

ここで問題は、f(x) ≥ 2 および f(y) ≥ x となり、x・y が最大化されるように x と y を選択することです。 関数 f は L において単調減少するため、可能な L に対して反復処理を行い、ふるいのような方法で寄与を集計することで効率的に計算できます。 すべての L について f がわかったら、任意のペアリングではなく構造化された反復を使用して最適なペアを検索します。 

除数累積アプローチを使用して、すべての L について f(L) を事前計算できます。対数長 a_i ごとに、度数テーブルでその約数を反復処理し、L の倍数ずつ段階的にステップ実行することによってすべての L ≤ a_i に寄与を追加します。これは本質的に分割数の式を効率的に逆転させます。

f を計算した後、可能な x 値を反復処理します。 f(x) ≥ 2 の各 x について、f(y) ≥ x となるような最適な y を見つける必要があります。 f は非厳密な意味で単調であるため、y 値に対して接尾語の最大構造を維持して、各 x に対して実現可能な最大の y を迅速に見つけることができます。 

これにより、問題はリニア スキャンによる O(M log M) または O(M √M) タイプの前処理に縮小されます。

 ## アルゴリズムのチュートリアル

 1. 対数長にわたる周波数配列を計算します。 これにより、各サイズのログがいくつ存在するかがわかり、ログを個別に処理するのではなく、寄与を効率的に集約できるようになります。 
2. 配列 f を構築します。ここで、f[L] は、すべてのログから取得できる長さ L のセグメントの数を表します。 考えられる L ごとに、floor(a_i / L) を追加することによって、すべてのログからの寄与を蓄積します。 このステップでは、切断ロジックを算術集計に変換します。 
3. f を計算した後、すべての L をスキャンし、f[L] ≥ 1 のものだけを保持します。これは、これらのみが有効な辺の長さとして機能するためです。 
4. 考えられる各 x について昇順で、f[x] ≥ 2 かどうかを確認します。これにより、長さ x の必要な 2 つの辺を形成できることが保証されます。 
5. このような x ごとに、f[y] ≥ x となる最大の y が必要です。 これを効率的に行うために、f[y] の任意のしきい値に対して達成可能な最良の y を格納する有効な y 値にわたるサフィックス最大配列を維持します。 
6. 有効な x ごとに候補領域 x・y を計算し、グローバル最大値を更新します。 

### なぜ効果があるのか

 核となる不変条件は、f(L) が、ログごとの分割を超えた重複競合なしに、すべてのログから長さ L の互いに素なセグメントをいくつ抽出できるかを正確にカウントすることです。 ログは独立した長さのソースであるため、floor(a_i / L) を合計すると、すべての実行可能なセグメントが正しくキャプチャされます。 有効な建築物はこの数を尊重する必要があり、これを尊重する選択は、各丸太を貪欲に L サイズの断片に切断することで実現できます。 これにより、実現可能性が完全に f のしきい値制約に限定され、x と y の検索が完了することが確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    max_a = max(a)

    freq = [0] * (max_a + 1)
    for x in a:
        freq[x] += 1

    # f[L] = number of segments of length L we can form
    f = [0] * (max_a + 1)

    # For each L, sum over all multiples
    for L in range(1, max_a + 1):
        s = 0
        for k in range(L, max_a + 1, L):
            s += freq[k] * (k // L)
        f[L] = s

    # best_y[x] = maximum y such that f[y] >= x
    best_y = [0] * (max_a + 2)

    ptr = max_a
    for x in range(1, max_a + 1):
        while ptr >= 1 and f[ptr] < x:
            ptr -= 1
        best_y[x] = ptr

    ans = 0
    for x in range(2, max_a + 1):
        if f[x] >= 2:
            y = best_y[x]
            if y >= 2:
                ans = max(ans, x * y)

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、まずログを周波数配列に圧縮し、次に L の倍数を反復して f[L] を計算します。これは、すべてのフロア区分を集計形式で評価する標準的な方法です。 

サフィックス ポインター手法により best_y が構築されるため、必要な数の x セグメントに対して、使用可能な最大の y を即座に見つけることができます。 ポインタは下方向にのみ移動するため、全体の複雑さは長さの範囲にわたって線形のままです。 

最後に、すべての x 候補をスキャンし、最適な組み合わせを計算します。

これは、L を大きくすることは可能ですが、ペアリングの制約により使用可能な組み合わせが制限されることを示しています。

 ## 特殊なケース

 エッジケースの 1 つは、すべてのログが同一である場合です。 その場合、f[L] は非常に規則的な構造を持ち、最適な解決策は多くの場合、多くの小さな等しいセグメントに分割することから得られます。 f[L] はグローバルに計算され、入力の多様性に依存しないため、アルゴリズムはこれを正しく処理します。 

1 つの非常に大きなログが他のすべてのログを支配する場合、別のエッジ ケースが発生します。 そのログからの寄与だけで f[L] の高いしきい値を満たすのに十分であり、サフィックス ポインターが実現可能な y 値を正確に捕捉するため、この解決策は依然として機能します。 

3 番目の特殊なケースは、最小長 2 のみが関係する場合です。 f[2] がすべての偶数長の寄与を累積し、実行可能性チェックが x ≥ 2 から開始されることを保証するため、アルゴリズムはこれを正しく捕捉し、無効な縮退ケースを回避します。
