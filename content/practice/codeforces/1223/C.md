 ## 解決策
 ## 問題の理解

 弊社ではチケット価格をまとめており、チケットの販売順序は自由に選択できます。 

2 つの寄付プログラムが存在します。 毎`a`- 番目に販売されたチケットが貢献します`x%`その価格とすべての`b`- 番目に販売されたチケットが貢献します`y%`その価格の。 チケットの位置が両方で割り切れる場合`a`そして`b`、両方のパーセンテージが適用され、貢献度は次のようになります。`(x + y)%`。 

各クエリについて、チケットを最適に配置した後、合計貢献度が少なくとも`k`。 チケットを全て販売しても届かない場合`k`、出力します`-1`。 

重要な自由は、好きなようにチケットを再注文できることです。 実際のチケットの ID は重要ではなく、価格のみが重要です。 

この制約により、多くの順列を試行するソリューションは即座に除外されます。 1 つのクエリには最大で次のクエリを含めることができます。`2 · 10^5`チケット、およびすべてのクエリにわたるチケットの合計数も`2 · 10^5`。 並べ替えを繰り返したり、回答候補ごとに多くのアレンジメントを試したりするようなアプローチでは、コストがかかりすぎます。 

目標値`k`と同じ大きさにすることができます`10^14`したがって、すべての計算では 64 ビット整数演算を使用する必要があります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

一方のパーセンテージが他方のパーセンテージより大きいとします。```
prices = [1000, 100]
x = 10, a = 1
y = 50, b = 2
```最初に販売されたチケットは 10% のみを受け取りますが、2 番目に販売されたチケットは 60% を受け取ります。 最も高価なチケットは 60% の位置に割り当てられる必要があります。 パーセンテージを任意の順序で処理する実装では、損失が発生し、より多くのチケットが必要であると誤って判断される可能性があります。 

ポジションが両方のプログラムに属している場合、別の微妙なケースが発生します。```
prices = [1000]
x = 50, a = 1
y = 50, b = 1
```寄付額はチケット価格の 100% であり、2 枚の別々のチケットがボーナスを受け取ることはありません。 正しい貢献度は 1000 です。チケットを二重にカウントすると、不可能な結果が生じます。 

最後のコーナーケースは不可能です。```
1
100
50 1
49 1
100
```唯一のチケットの貢献度は 99 で、これは 100 未満です。答えは次のとおりです。`-1`。 二分探索では、すべてのチケットを使用してもターゲットに到達できないことを確認する必要があります。 

## アプローチ

 強引な視点は構造を明らかにするのに役立ちます。 

答えが次のように推測されるとします。`m`。 最初の計算から得られる最大の寄与を決定する必要があります。`m`売られたポジション。 チケットの順序は私たちの管理下にあるため、あらゆる方法でポジションにチケットを割り当ててみて、最適な配置を選択することができます。 

これは明らかに実行不可能です。 数十枚のチケットであっても、並べ替えの数は膨大になります。 

重要な観察は、ポジションの違いは寄付率だけであるということです。 1 つのポジションが 60% を寄与し、別のポジションが 10% を寄与する場合、より大きなパーセンテージが、より小さなパーセンテージに割り当てられたチケットと少なくとも同じ価格のチケットを受け取る必要があります。 

これは典型的な交換議論です。 より大きなチケットがより小さなパーセンテージに割り当てられ、より小さなチケットがより大きなパーセンテージに割り当てられている場合、それらを交換しても合計貢献度は増加するだけです。 

その結果、獲得したポジションの数がわかったら、`(x+y)%`、受信のみをいくつ`x%`、受信のみの数はいくつありますか`y%`とすると、最適な配置が明らかになります。 

チケット価格を降順に並べ替えます。 最大の価格を最大のパーセンテージに割り当てます。 

次に、答えの候補を考えてみましょう`m`。 

ポジション間`1..m`:

 - 両方で割り切れるポジション`a`そして`b`受け取る`(x+y)%`。 
- でのみ割り切れる位置`a`受け取る`x%`。 
- でのみ割り切れる位置`b`受け取る`y%`。 

これらの数は、次の最小公倍数を使用して計算できます。`a`そして`b`。 

かどうかを効率的に確認できるようになると、`m`チケットで十分です、答えは二分探索になります`m`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n log n + n log n) | O(n) | 承認済み |

 2番目`n log n`係数は二分探索の実行から得られます`O(log n)`実現可能性チェック、それぞれに必要なのは最大でも`O(n)`仕事。 

## アルゴリズムのチュートリアル

 ### 前処理

 すべてのチケット価格を降順に並べ替えます。 

すべての価格は 100 の倍数なので、すぐに各価格を 100 で割ります。 これにより、整数演算を使用してパーセント値を直接操作できるようになります。 

### 実現可能性のチェック

 候補値としては`m`:

 1. コンピューティング`l = lcm(a, b)`。 
2. 最初の順位の間で順位を数える`m`両方のボーナスを受け取る販売。`both = m // l`3. 最初のボーナスのみを受け取るポジションをカウントします。`only_x = m // a - both`4. 2 番目のボーナスのみを受け取るポジションをカウントします。`only_y = m // b - both`5. 大きい割合が最初に処理されるようにします。 

もし`y > x`、交換`(x, only_x)`と`(y, only_y)`。 

これにより、より大きなパーセンテージがより大きなチケット価格と一致することが保証されます。 
6. チケット価格の最も高いものから始めます。 
7. 最初の値を割り当てます`both`パーセンテージへのチケット`(x+y)`。 
8. 次の項目を割り当てます`only_x`パーセンテージへのチケット`x`。 
9. 次の項目を割り当てます`only_y`パーセンテージへのチケット`y`。 
10. これらの割り当てによってもたらされる合計貢献度を計算します。 
11. 貢献が少なくとも`k`、 それから`m`チケットで十分です。 

### 二分探索

 1.すべて使用しているかどうかを確認します`n`チケットは届く`k`。 
2.そうでない場合は出力`-1`。 
3. それ以外の場合は、回答範囲の二分探索`[1, n]`。 
4. 各中間点に対して、実現可能性チェックを実行します。 
5. 中間点が機能する場合は、左半分を検索します。 
6. それ以外の場合は、右半分を検索します。 
7. 最初の実現可能な値が答えです。 

### なぜ効果があるのか

 一定枚数のチケットを販売した場合`m`、すべてのポジションは次の 3 つのパーセンテージのいずれかに貢献します。`(x+y)`、`x`、 または`y`。 

価格が割り当てられた 2 つのチケットを考えてみましょう`p1 > p2`とパーセンテージ`c1 < c2`。 

彼らの貢献は、`p1*c1 + p2*c2`。 

交換後:`p1*c2 + p2*c1`。 

違いは`(p1-p2)(c2-c1) > 0`。 

したがって、より大きなパーセンテージに、より大きな価格を割り当てることは決して悪いことではなく、場合によっては役に立ちます。 

この交換引数を繰り返し適用すると、あらゆる取り決めが、チケット価格がパーセンテージで降順に一致する取り決めに変換され、可能な限り最大限の貢献が得られます。 

実現可能性チェックでは、最初の最適な寄与を正確に計算します。`m`ポジション。 二分探索は次の場合に有効です。`m`tickets are sufficient, then any larger number of tickets is also sufficient. 実現可能性述語は単調です。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def solve():
    q = int(input())

    for _ in range(q):
        n = int(input())

        p = list(map(int, input().split()))
        p = [x // 100 for x in p]
        p.sort(reverse=True)

        x, a = map(int, input().split())
        y, b = map(int, input().split())

        k = int(input())

        if x < y:
            x, y = y, x
            a, b = b, a

        l = a * b // gcd(a, b)

        def check(m):
            both = m // l
            cnt_x = m // a - both
            cnt_y = m // b - both

            idx = 0
            total = 0

            for _ in range(both):
                total += p[idx] * (x + y)
                idx += 1

            for _ in range(cnt_x):
                total += p[idx] * x
                idx += 1

            for _ in range(cnt_y):
                total += p[idx] * y
                idx += 1

            return total >= k

        if not check(n):
            print(-1)
            continue

        lo, hi = 1, n

        while lo < hi:
            mid = (lo + hi) // 2

            if check(mid):
                hi = mid
            else:
                lo = mid + 1

        print(lo)

solve()
```最初の重要な実装詳細は、最初に一度価格を並べ替えることです。 すべての実現可能性チェックは、同じ降順のチケット値を使用することに依存します。 

2 番目の微妙な点は、次の場合に実行されるスワップです。`x < y`。 常に、小さいパーセンテージよりも大きいパーセンテージを割り当てる必要があります。 このスワップがなければ、貪欲な割り当てにより、弱いボーナスで高価なチケットが無駄になる可能性があります。 

寄与度は、すでに 100 で割られた価格を使用して計算されます。元の価格はすべて 100 の倍数であるため、寄与度は次のようになります。```
(price / 100) * percentage
```数値的には実際の金銭的貢献と同じです。 これにより、浮動小数点演算が完全に回避されます。 

実現可能性関数は、実際の売り注文を作成する必要はありません。 各パーセンテージカテゴリを獲得したポジションの数のみをカウントし、残りの最大のチケット値を貪欲に割り当てます。
