 ## 解決策
 ## 問題の理解

 各クエリは同じ長さの 2 つの文字列を返します。 どちらの文字列にも操作を繰り返し適用することができます。つまり、隣接する 2 つの文字を選択し、一方を他方で上書きします。 これは、情報が隣接する位置に沿って流れることができることを意味しますが、新しい文字を導入するのではなく、既存の文字をコピーすることによってのみ可能になります。 

構造的な観点から見ると、各文字列はセルの行のように動作し、任意の文字が反復伝播によって文字列全体に広がる可能性があります。 ただし、どの操作でも、開始時にその文字列に存在しなかった文字が導入されることはありません。 

課題は、このような伝播ステップを任意の数だけ両方の文字列に個別に適用した後、それらを同一にすることができるかどうかを判断することです。 

制約は小さく、クエリは最大 100 個、各文字列の長さは最大 100 です。これにより、文字列に対する変換や状態シミュレーションの指数関数的な探索が即座に排除されます。 クエリごとの 3 次または 2 次シミュレーションでも問題なく通過できますが、本当の目標は、何かをシミュレートするのではなく、基礎となる不変式を見つけることです。 

よくある誤った直感は、順序が重要である、または周波数を一致させる必要があると考えることです。 それは過度に複雑な推論につながります。 もう 1 つの間違いは、文字の移動をシミュレートする必要があると想定していることです。これはすぐに煩雑になり、操作の真の自由をまだ捉えていません。 

変換による間接的な場合を除いて文字列がまったく文字を共有しない場合、微妙なエッジ ケースが発生します。 たとえば、1 つの文字列が次のものだけで構成されている場合、`a`そしてもう一つだけ`b`、それらを和解させる方法はありません。 一方、文字が 1 つでも共有されていれば、両方を完全にその文字に変えることができ、それらを自明に同等にすることができます。 

## アプローチ

 強引なアイデアでは、到達可能なすべての文字列をモデル化しようとします。`s`そしてから`t`。 各位置は隣接する位置によって繰り返し上書きされる可能性があるため、各ステップは複数の可能性に分岐します。 可能な文字列の数は長さに応じて指数関数的に増加し、長さが 100 の場合でもこれは完全に不可能になります。 

重要な点は、この操作では新しいキャラクターが作成されることはなく、既存のキャラクターがコピーされるだけであるということです。 これは、変換後に残る唯一の情報は、最初に各文字列にどの個別の文字が存在するかであることを意味します。 文字列内の任意の場所に文字が存在すると、その文字があらゆる位置に伝播され、文字列内の構造が事実上消去されます。 

これにより、各文字列が単純な文字のセットに縮小されます。 2 つのセットに少なくとも 1 つの共通の文字がある場合、その文字をターゲットとして選択し、両方が均一になるまで両方の文字列に独立してそれを伝播できます。 共通の文字がない場合、それらを同期する方法はありません。 

したがって、問題は設定された交差チェックに集約されます。

 ## アルゴリズムのチュートリアル

 各クエリを個別に処理します。 

まず、文字列をスキャンします`s`そしてその中にどの文字が現れるかを記録します。 文字列に対しても同じことを行います`t`。 アルファベットは英小文字のみであるため、サイズ 26 の固定ブール配列を使用してこれを表すことができます。 

次に、両方のセットに登場するキャラクターが存在するかどうかを確認します。 これは、これら 2 つの文字セットの共通部分が空でないかどうかを確認することと同じです。 

少なくとも 1 つの共有文字が見つかった場合は、両方の文字列を完全にその文字で構成される文字列に変換できるとすぐに結論付け、出力します。`YES`。 それ以外の場合は出力します`NO`。 

### なぜ効果があるのか

 この操作により、既存の文字を文字列全体に無制限に伝播できます。 これにより、初期文字列内のすべての文字がその文字列内で効率的にグローバルに使用できるようになります。 新しい文字は決して出現できないため、最終的な共通文字列に対する唯一の制約は、使用されるすべての文字が両方の元の文字列に存在する必要があることです。 両方の文字列を完全に埋めるように拡張できるため、単一の共有文字で十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    out = []
    
    for _ in range(q):
        s = input().strip()
        t = input().strip()
        
        seen_s = [False] * 26
        seen_t = [False] * 26
        
        for ch in s:
            seen_s[ord(ch) - 97] = True
        for ch in t:
            seen_t[ord(ch) - 97] = True
        
        ok = False
        for i in range(26):
            if seen_s[i] and seen_t[i]:
                ok = True
                break
        
        out.append("YES" if ok else "NO")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、各クエリを個別に処理します。 文字列ごとに、アルファベットのプレゼンス配列を構築します。 最後のループでは、共有インデックスがないかチェックします。 早期終了により、共通の文字が見つかると一定時間の動作が保証されます。 

よくある実装上の間違いは、完全な文字列または頻度を比較しようとすることです。 この操作ではカウントが保存されないため、頻度は無関係です。 もう 1 つの間違いは、変換を段階的にシミュレートしようとすることですが、到達可能性はキャラクターの存在のみに依存するため、これは不必要です。 

## 実用的な例

 次のクエリを考えてみましょう。`s = "xabb"`そして`t = "aabx"`。 

次のように文字セットを追跡します。 

| ステップ | の文字 | t 文字 | 共通の文字が見つかりました |
 | --- | --- | --- | --- |
 | スキャン後 | {x、a、b} | {a、b、x} | はい |

 少なくとも 1 つの共有文字があるため、両方の文字列をすべてに縮小できます。`a`たとえば、答えは次のようになります`YES`。 

ここで考えてみましょう`s = "a"`そして`t = "z"`。 

| ステップ | の文字 | t 文字 | 共通の文字が見つかりました |

 | スキャン後 | {a} | {z} | いいえ |

 重複がないため、許可された一連の操作がギャップを埋めることはできません。`NO`。 

最初の例は、構造と順序が無関係であることを示していますが、2 番目の例は、アルファベットがバラバラであるため変換が不可能であることを示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、両方の文字列がすでに同一である場合に発生します。 のような入力の場合`s = "abba"`そして`t = "abba"`の場合、アルゴリズムは両方の文字列の同じ文字セットをマークするため、交差部分は空ではなく、出力は次のようになります。`YES`。 このプロセスは平等性に依存しませんが、平等性を正しく受け入れます。 

もう 1 つのエッジ ケースは、文字列に繰り返し文字が含まれているものの、互いに素なセットが含まれている場合です。`s = "aaaa"`そして`t = "bbbb"`。 どちらも均一ではありますが、共通の特徴がないため、どの伝播シーケンスもそれらを調和させることはできません。 アルゴリズムは正しく返します`NO`交差チェックがすぐに失敗するためです。 

3 番目のケースは、文字列が長いが、正確に 1 つの文字を共有する場合です。`s = "abcabc..."`そして`t = "zzzazzz..."`。 ほとんどのキャラクターは異なりますが、共通の`a`両方の文字列を均一な文字列に折りたたむには十分です。`a`、アルゴリズムは空ではない交差条件を通じてこれをキャプチャします。
