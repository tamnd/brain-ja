 ## 解決策
 ## 問題の理解

 最終レースの前に現在のチャンピオンシップの順位が分かります。 すべてのレーサーはすでにある程度のポイントを持っており、最後のレースでは上位に追加ポイントが分配されます。`m`フィニッシャー。 レースで1位になったレーサーは賞品を受け取ります`b[0]`ポイント、2位のレーサーが獲得`b[1]`、 等々。 

最終レース終了後、合計ポイントの高い順に順位付けを行います。 2 人のレーサーが同じポイント数でフィニッシュした場合、辞書順に小さいニックネームを持つレーサーが上位とみなされます。 

Vasya のレーサーには 2 つの値が求められます。 

1. 彼がまだ達成できる最終チャンピオンシップの最高の順位。 
2. 彼がまだ落ち得る最悪の最終チャンピオンシップ順位。 

最終レースの順位は完全に私たちの管理下にあります。 どのレーサーにも、一度だけゴール地点を割り当てることができます。 これは、Vasya を最も助けるか傷つける方法でボーナス ポイントを自由に分配できることを意味します。 

制約があるため、私たちは慎重に考える必要があります。 まであります`10^5`レーサーなので、二次関数はすでに高価すぎます。 考えられるすべての点の割り当てを繰り返し試行する単純なシミュレーションでは、組み合わせが爆発的に増加します。 たとえ`O(n^2)`で確認してください`10^5`レーサーには約`10^10`4秒以内には不可能な操作です。 

難しいのはタイブレークのルールです。 スコアが等しいだけでは、ランキングを平等にするのに十分ではありません。 辞書編集上の順序によって、同点の場合の勝者が決まります。 

次の入力を考えてみましょう。```
2
alex 10
vasya 10
0
vasya
```ボーナスポイントの配布はございません。 両選手とも10ポイントでフィニッシュ。 以来`"alex" < "vasya"`, アレックスはヴァシャよりも上位に位置するため、答えは次のようになります。```
2 2
```スコアのみを比較する不注意な実装では、誤った出力が発生します。`1 1`。 

一部のボーナス値がゼロの場合、別の微妙なケースが発生します。```
3
aaa 5
bbb 5
vasya 5
2
10 0
vasya
```Vasya に 1 位のレー​​スボーナスを与えると 15 ポイントが得られ、総合 1 位が保証されます。 しかし、Vasya がボーナスをゼロにすれば、タイは再び重要になります。 獲得した順位が常にランキングを変動すると仮定することはできません。 

もう 1 つの危険なエッジケースは次のような場合です。`m = 0`。```
3
a 100
vasya 100
z 100
0
vasya
```ポイントは一切加算されません。 最終的な順序は、等しいスコア間の辞書編集上の順序によってのみ決定されます。 ヴァシャが2位に終わった。 

Vasya が報酬を獲得したレーサーに参加することを常に前提とする実装は、ここでは失敗します。 

## アプローチ

 ブルートフォースの観点は単純明快です。 Vasya の可能なすべてのフィニッシュ順位を試し、残りのレース順位をあらゆる方法で他のすべてのレーサーに割り当て、最終的に結果として得られるチャンピオンシップランキングを計算することができます。 

これは、前回のレースの有効な結果をすべて調査するため、正しいです。 問題は順列の数です。 たとえ 15 人のレーサーであっても、すべての課題を試すのはすでに不可能です。 と`10^5`レーサーの皆さん、徹底的な探索は絶望的です。 

重要な観察は、私たちは他の全員の正確な順序をまったく気にしていないということです。 私たちが気にするのは、レーサーがヴァシャより上でゴールできるかどうかだけです。 

Vasyaが受け取るボーナスを修正するとします。 彼の最終スコアは次のようになります。```
vasya_score = current_score + chosen_bonus
```さて、質問は次のようになります。 

何人のレーサーが彼を越えることを強いられるか、あるいは彼の上を行くのを阻止できるでしょうか?

 他のレーサーにとって、ヴァシャに勝つかどうかは、最終スコアを厳密にヴァシャよりも良くする、または辞書的に小さい名前と同等にする未使用のボーナスが存在するかどうかによって決まります。 

これにより、問題はレーサーと利用可能なボーナスの間の貪欲なマッチングの問題に変換されます。 

可能な限り最高の最終ランクを得るには、Vasya より上のレーサーをできるだけ少なくする必要があります。 当然、危険なボーナスはやむを得ない場合にのみ与えるべきです。 各レーサーには、最小限の十分なボーナスを使用する必要があります。 

最悪の最終順位を考慮して、できるだけ多くのレーサーがヴァシャより上になるようにしたいと考えています。 そして、可能な限りレーサーに強力なボーナスを貪欲に与えます。 

どちらのバージョンも、ボーナスを貪欲に割り当てて、何人のレーサーが固定目標スコアを超えることができるかをチェックすることに留まっています。 並べ替えるとこれが効率的になります。 

最終的な複雑さは次のようになります。`O(n log n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 可能な限り最善のポジション

 1. Vasya が受け取れるすべてのボーナスを試してください。 

Vasya は報酬の順位外で終了する可能性があるため、ボーナスが未使用のまま残っている場合は追加ポイントをゼロで受け取ることも可能です。 
2. ボーナスを受け取った後の Vasya の最終スコアを計算します。 
3. 利用可能なプールからそのボーナスを削除します。 
4. 残りのボーナスを昇順に並べ替えます。 
5. 他のすべてのレーサーについて、Vasya より上でフィニッシュするために必要な最小追加ポイントを計算します。 

レーサーは次の場合にヴァシャに勝ちます。 

- 合計スコアが大きくなる、または
 - 合計スコアが等しくなり、ニックネームが辞書順に小さくなります。 
6. レーサーを必要なボーナスの昇順に処理します。 

各レーサーに、十分な最小の利用可能なボーナスを貪欲に割り当てます。 

より困難なケースでも強力なボーナスが保持されるため、これにより、Vasya を超えることができるレーサーの数が最小限に抑えられます。 
7. 何人のレーサーがヴァシャを超えることに成功したか数えてください。 
8. Vasya の最終的な位置は、そのカウントに 1 を加えたものです。 
9. Vasya のボーナスのすべての選択肢から最小値を取得します。 

### 考えられる限り最悪のポジション

 1. Vasya が受け取ることができるすべてのボーナスをもう一度試してください。 
2. 最終スコアを計算します。 
3. Vasya が選択したボーナスを利用可能なプールから削除します。 
4. 残りのボーナスを昇順に並べ替えます。 
5. 他のすべてのレーサーについて、Vasya を超えるために必要な最小ボーナスを決定します。 
6. レーサーを満足させるのが最も難しいものから最も簡単なものまで処理します。 

私たちは今、Vasya を超えるレーサーの数を最大化したいと考えています。 最適な戦略は、最も助けを必要とするレーサーに最大のボーナスを与えることです。 
7. 残りの最大ボーナスを貪欲に一致させます。 
8. 何人のレーサーがヴァシャの上に押し上げられるかを数えてください。 
9. Vasya の最終的な位置は、そのカウントに 1 を加えたものになります。 
10. Vasya のボーナスのすべての選択肢から最大値を取得します。 

### なぜ効果があるのか

 重要な特性は、各レーサーが少なくともあるしきい値と同じ大きさのボーナスを受け取るかどうかのみに依存するということです。 

これにより、問題はしきい値と利用可能なボーナスの間のマッチング問題に変換されます。 

成功したレーサーの数を最小限にするには、最小限の十分なボーナスを割り当てることが常に最適です。 これ以上のボーナスは、後で別のレーサーを助けることができるリソースを無駄にするだけです。 

成功するレーサーの数を最大化するには、最も高い要件を持つレーサーに最大のボーナスを割り当てることが最適です。 大きな要件を今満たすことができない場合、後で小さなボーナスでは満たすことはできません。 

どちらの貪欲戦略も古典的な交換議論です。 貪欲でない割り当ては、結果を悪化させることなく貪欲な割り当てに再配置できます。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def better(name1, score1, name2, score2):
    if score1 != score2:
        return score1 > score2
    return name1 < name2

def solve():
    n = int(input())

    names = []
    scores = []

    for _ in range(n):
        s, a = input().split()
        names.append(s)
        scores.append(int(a))

    m = int(input())
    b = list(map(int, input().split())) if m else []

    vasya = input().strip()
    vid = names.index(vasya)

    bonus_options = b[:] + [0]

    best = n
    worst = 1

    for used_bonus in bonus_options:
        vasya_score = scores[vid] + used_bonus

        remaining = b[:]
        removed = False

        for i in range(len(remaining)):
            if remaining[i] == used_bonus and not removed:
                remaining.pop(i)
                removed = True
                break

        remaining.sort()

        need = []

        for i in range(n):
            if i == vid:
                continue

            cur = scores[i]

            if names[i] < vasya:
                req = vasya_score - cur
            else:
                req = vasya_score - cur + 1

            req = max(req, 0)
            need.append(req)

        need.sort()

        # best rank
        ptr = 0
        above = 0

        for req in need:
            pos = bisect_left(remaining, req, ptr)
            if pos == len(remaining):
                continue
            above += 1
            ptr = pos + 1

        best = min(best, above + 1)

        # worst rank
        rem_ptr = len(remaining) - 1
        above = 0

        for req in reversed(need):
            if rem_ptr >= 0 and remaining[rem_ptr] >= req:
                above += 1
                rem_ptr -= 1

        worst = max(worst, above + 1)

    print(best, worst)

solve()
```この解決策は、Vasya が受け取る可能性のあるあらゆるボーナスについて反復されます。 多くてもあります`m + 1`ポイントを受け取らない可能性も含めて、そのような選択肢があります。 

レーサーを比較するためのヘルパー条件は、必要なボーナス計算を通じてエンコードされます。 別のレーサーが現在持っていると仮定します。`cur`ポイント。 

彼らの名前が辞書編集上ヴァシャの名前よりも小さい場合、平等であれば彼より上位にランクされるのに十分であるため、次のことが必要です。```
cur + bonus >= vasya_score
```それ以外の場合は、厳密にさらに多くのポイントが必要です。```
cur + bonus > vasya_score
```この区別は、間違った答えを引き起こす最も一般的な原因です。 

最高ランクの計算では、各レーサーが満足できる最小のボーナスを貪欲に割り当てます。 の`bisect_left`呼び出しは、最初に使用可能なボーナスを効率的に見つけます。 

最悪ランクの計算では、両方の配列を逆にして、残っている最大のボーナスを貪欲に消費します。 これにより、マッチングの成功率が最大化されます。 

このコードは、Vasya が選択したボーナスを 1 回だけ削除します。 これは、複数のボーナスの価値が等しい場合に重要になります。
