 ## 解決策
 ## 問題の理解

 各表示モードでは、在庫をサイズのページにグループ化します。`a_i`。 在庫に含まれている場合は、`k`アイテムを選択すると、ゲームが表示されます$b_i = \left\lceil \frac{k}{a_i} \right\rceil$そのモードのページ。 

Vasya は実際の価値を知りません。`k`、それだけです`2 ≤ k ≤ x`。 何かを見る前に、彼はモードのサブセットを選択します。 対応するページ数をすべて確認した後、次のことを判断できる必要があります。`k`ユニークに。 

私たちにはあらゆる価値が与えられている`a_i`、そして、一意の再構成に必要なモードの最小数を見つけなければなりません。`k`。 機能するサブセットがない場合は、次のように出力します。`-1`。 

制約`n ≤ 10^5`モードのすべてのサブセットを比較するアプローチは直ちに除外されます。 考えられる在庫サイズのすべてのペアを確認するだけでも、すでに約`10^18`操作時の操作`x`大きいです。 に近いものが必要です`O(n log n)`または`O(n log x)`。 

値`x`到達できる`10^9`そのため、考えられるすべての在庫サイズを反復処理することは不可能です。 成功する解決策は、候補を列挙するのではなく、間隔と割り算について象徴的に推論する必要があります。 

いくつかのモードのページ サイズが同じ場合、微妙なエッジ ケースが発生します。 

例：```
n = 3, x = 10
a = [2, 2, 2]
```3 つのモードはすべて、まったく同じ情報を提供します。 より多くのコピーを使用しても役に立ちません。 モードを個別にカウントする不注意で貪欲なソリューションは、誤った答えを返します。`3`、正解は`-1`なぜなら次のような価値観があるからです`3`そして`4`常に同一の観測結果を生成します。 

もう 1 つの注意が必要な状況は、モードが上限付近で有用な区別を提供しない場合に発生します。 

例：```
n = 1, x = 5
a = [100]
```あらゆる可能な在庫サイズに対して、`2`に`5`、ページ数は常に`1`。 単純な実装では、出力が生成されるため 1 つのモードで十分だと考えるかもしれませんが、出力は決して変化しません。 

最も難しいケースは、複数のモードがどのように組み合わされるかを理解することです。 

例：```
n = 2, x = 6
a = [2, 3]
```観察結果は次のとおりです。 

| k | 天井(k/2) | 天井(k/3) |
 | --- | --- | --- |
 | 2 | 1 | 1 |
 | 3 | 2 | 1 |
 | 4 | 2 | 2 |
 | 5 | 3 | 2 |
 | 6 | 3 | 2 |

 価値観`5`そして`6`区別がつかないので、答えは`-1`。 モードのペアごとの一意性のみをチェックする単純なアプローチでは、モードを組み合わせれば十分であると誤って結論付けることになります。 

## アプローチ

 ブルートフォース解釈は簡単です。 あらゆる可能な在庫サイズに対して`k`から`2`に`x`、ベクトルを計算します$\left(\left\lceil\frac{k}{a_1}\right\rceil,\left\lceil\frac{k}{a_2}\right\rceil,\dots\right)$次に、モードのすべてのサブセットを試し、結果として投影されたベクトルがすべてのサブセットを一意に識別するかどうかを確認します。`k`。 

これは正しいです。選択したモードによって異なるページ数が生成される場合、2 つのインベントリ サイズを正確に区別できるからです。 

問題は規模だ。 すべてのベクトルを保存するだけでもすでにコストがかかります`O(nx)`となり、`10^14`最悪の場合の運用。 サブセットを試すと指数関数的に悪化します。 

重要な点は、ページ サイズのあるモードであることです。`a`同じ間隔内の数値を区別しません。$((t-1)a,\; ta]$このような間隔内のすべての数値がページ数を生成します`t`。 

つまり、各モードが範囲を分割します`[2, x]`ブロックに。 いくつかのモードを組み合わせると、これらのパーティションを交差させることに対応します。 すべての最終ブロックには整数が 1 つだけ含まれるようにしたいと考えています。 

ここで重要な数論的洞察が始まります。 

2つの数字を仮定します`u < v`モードの区別がつかないままになる`a`。 それから：$\left\lceil\frac{u}{a}\right\rceil = \left\lceil\frac{v}{a}\right\rceil$これはまさに、次の倍数がない場合に発生します。`a`厳密に間`u`そして`v`。 

連続した数字の場合`k`そして`k+1`、次の場合に区別できます。`a`分割する`k`。 

それは問題全体を一変させます。 すべての整数を次の整数から区別するには、`k`で`[2, x-1]`少なくとも 1 つ選ばれる必要があります`a_i`分割する`k`。 

したがって、タスクは次のようになります。 

値の最小数を選択してください`a_i`からのすべての整数が`2`に`x-1`少なくとも 1 つの選択された値で割り切れます。 

次に、別の単純化を観察します。 もし`a > x-1`、それは有益なものを何も分割しません。 もし`a = 1`、すべてを分割しますが、ページ数は各ステップで同じように増加するため、まったく役に立たない情報が得られます。 

意味のある約数は次の間の整数のみです。`2`そして`x-1`。 

さらに重要なことは、いくつかを選択すると、`a > 1`、その後、次のすべての倍数`a`区別できる境界線になります。 隣接するすべてのペア、すべての数字を分離するには`k`から`2`に`x-1`それ自体が、選択されたモードの間の約数として現れる必要があります。 さもないと`k`が明らかになります。 

つまり、成功する可能性のある唯一のセットは、正確にすべての整数です`2, 3, ..., x-1`。 

それで:

 - に整数が入っている場合`[2, x-1]`が入力にありません、答えは`-1`。 
- それ以外の場合、モードの最小数はその範囲内の個別の整数の数と等しくなります。`x-2`。 

難しそうなパーティションの問題全体は、単純なカバレッジの議論に集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nx + 2^n) | O(nx) | 遅すぎる |
 | 最適 | O(n) | O(x) または O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての値を読み取る`a_i`。 
2. ごとに挿入します`a_i`セットに。 

考慮するのは、約数が少なくとも 1 回存在するかどうかだけです。 重複モードでは同一の情報が提供されます。 
3. すべての整数について`k`から`2`に`x-1`、どうかを確認してください`k`セットの中に存在します。 

その理由は隣接する数字にあります。 区別するには`k`から`k+1`、選択されたモードの一部は以下を満たす必要があります。$k \equiv 0 \pmod{a}$以来`a > k`分けられない`k`、および任意の適切な約数`k`また、正確に境界を作成せずに、近くの数値を分割します。`k`、唯一保証されている区切り文字は`a = k`。 

1. に数字がある場合`[2, x-1]`がありません、出力`-1`。 
2. それ以外の場合は出力`x-2`。 

これらすべてのモードが必要であり、それらを正確に使用することで機能します。 

### なぜ効果があるのか

 ページサイズのあるモード`a`の倍数で出力を正確に変更します。`a`。 ペア`(k, k+1)`選択されたモードがこれら 2 つの値の間で変化する場合、つまり選択されたモードが変化するかどうかを区別できます。`a`分割する`k`。 

考えられるすべての在庫サイズを一意に区別するには、隣接するすべてのペアが区別可能でなければなりません。 選択したすべてのモードで隣接するペアが 1 つでも等しい場合、これら 2 つのインベントリ サイズは同一の観測値を生成します。 

与えられた`k`、任意の約数`a`それは分ける`k`そして`k+1`分けなければなりません`k`。 考えられる最も強力なセパレータは次のとおりです。`a = k`。 もし`k`それ自体が利用可能なモードにないため、その境界の分離を保証する方法はありません。 したがって、からのすべての整数は、`2`に`x-1`モード間に存在する必要があります。 

すべてを選択すると明らかに機能します。`k`間の境界を正確に分離します`k`そして`k+1`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())

    if n > 0:
        a = list(map(int, input().split()))
    else:
        a = []

    s = set(a)

    for v in range(2, x):
        if v not in s:
            print(-1)
            return

    print(x - 2)

solve()
```数学的削減により複雑な構造がすべて削除されるため、実装は短くなります。 

セット`s`利用可能なすべてのモード サイズを保存します。 同一のモードでは余分な情報が提供されないため、重複は自動的に破棄されます。 

ループは、必要な区切り値をすべてチェックします。`2`に`x-1`。 値が 1 つでも欠落している場合は、その数値と次の数値の間の境界を一意に識別できないことを意味します。 

答えは次のようになります`x-2`なぜなら、間隔内に必要な整数がちょうど同じ数だけ存在するからです。 

微妙なディテールの処理`n = 0`。 ステートメントではそれが許可されているため、2 行目を無条件に読み取ると失敗します。 コードはそのようなケースから保護します。 

もう 1 つの重要な詳細は、ループ範囲です。```
range(2, x)
```これには正しく含まれます`x-1`そして除外します`x`。 内部の隣接するペアを区別するだけで済みます`[2, x]`、つまり:```
(2,3), (3,4), ..., (x-1,x)
