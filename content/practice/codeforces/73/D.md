 ## 解決策
 ## 問題の理解

 都市が頂点、道路がエッジである無向グラフが与えられます。 グラフの接続された各コンポーネントは州と呼ばれます。 Vasya はさらに都市間にトンネルを建設する可能性がありますが、トンネルには 2 つの制限があります。 

まず、各都市は最大 1 つのトンネルに参加できます。 第二に、各州には最大でも`k`その内部のトンネルエンドポイント。 各トンネルは各側に 1 つのエンドポイントを提供するため、これは、州が参加できるのは最大でも 1 つだけであることを意味します。`k`トンネル接続。 

目標は、道路とトンネルを一緒に使用してグラフ全体を接続することです。 トンネルを配置する前に、州間に道路を追加することができます。 道路を追加すると、2 つの州が 1 つの大きな州に永久に統合されます。 その後、何らかのトンネル構成で国全体を接続できるように、必要な追加道路の最小数を計算する必要があります。 

グラフが大きいですね。 到達可能な都市と道路の数の両方`10^6`, したがって、二次関数はすべて不可能です。 たとえ`O(n log n)`ソリューションには慎重な実装が必要です。 時間があるのは、グラフを線形またはほぼ線形に移動することだけです。 

最初の観察は、トンネルだけでは各州を恣意的に接続することはできないということです。 あると仮定します`c`道路を追加した後の州。 接続されているグラフ`c`ノードには少なくとも必要です`c - 1`トンネルの端。 すべてのトンネル エンドポイントは何らかの州に属しているため、どの州もトンネル ネットワークに参加するのに十分な「容量」を必要とします。 

微妙な点は、制限が都市数ごとではなく州ごとであることです。 どの都市も複数のトンネルに接続できないため、都市が 1 つしかない州では依然として複数のトンネルを使用できません。 

もう 1 つの簡単な間違いは、道路を追加すると容量が統合されるということを忘れていることです。 州 A の容量が 1、州 B の容量が 1 である場合、それらを道路で接続すると、容量 2 の 1 つの州が作成されます。これにより、どのようなトンネル構造が可能になるかが変わります。 

次の例を考えてみましょう。```
4 0 1
```4 つの孤立した都市があるため、サイズ 1 のプロヴィンスが 4 つあります。各プロヴィンスは 1 つのトンネル エンドポイントのみをサポートします。 4 つの州に接続されたグラフには少なくとも 3 つのトンネルが必要ですが、4 つのノードを持つツリーには 2 つの葉と 2 つの内部ノードがあります。 内部ノードには少なくとも次数 2 が必要ですが、制限 1 では不可能です。まず道路を使用して州を結合する必要があります。 正しい答えは、`2`。 

不注意な解決策では、エンドポイントの総容量が十分であるかどうかのみをチェックする可能性があります。```
total capacity = 4
needed endpoints = 2 * (4 - 1) = 6
```これはすでに失敗していますが、たとえ合計が一致したとしても、構造は依然として重要です。 

もう 1 つの注意が必要なケースは次のとおりです。```
6 0 2
```現在、すべてのプロヴィンスは最大 2 の次数をサポートできます。単純なパスを使用して 6 つのプロヴィンスを実際に接続できます。 余分な道路は必要ありません、答えてください`0`。 

間違った貪欲な人は、ツリーには高次ノードが含まれる場合があるため、制限 2 を持つすべてのプロヴィンスをマージする必要があると考えるかもしれません。 パスの構築はそれを回避します。 

もう 1 つの危険なエッジケースは、単一の州です。```
3 3 2
1 2
2 3
3 1
```グラフはすでに接続されているため、トンネルは必要ありません。 答えは`0`技術的にはこの州には未使用のトンネル容量があるにもかかわらず。 

## アプローチ

 強引な視点は、州間のトンネルグラフを直接考えることです。 各州の最大学位は次のとおりです。```
min(size_of_component, k)
```すべてのトンネルのエンドポイントは個別の都市を使用する必要があるためです。 

州と道路を統合するあらゆる方法を試し、その結果生じる容量によって接続されたグラフが可能かどうかを確認することも想像できます。 これはすぐに組み合わせ的に爆発します。 まで`10^6`最悪の場合、マージの可能性をすべて保存することさえ不可能です。 

より洗練された総当り攻撃では、実行可能なトンネル ネットワークが存在するまで、「悪い」プロヴィンスを繰り返しマージします。 問題は、実現可能性を効率的に判断することです。 次数制約の下ですべての可能な接続グラフをテストすること自体、自明ではありません。 

重要な洞察は、使用可能なトンネル エンドポイントの合計のみが重要であるということです。 

最終的なグラフが次のようになったとします。`c`地方。 接続されているグラフ`c`頂点には正確に含まれます`2(c - 1)`合計度。 したがって、州は次の条件を満たす必要があります。```
sum(capacity_i) >= 2(c - 1)
```驚くべきことに、この条件も十分です。 

なぜ？ すべての州に少なくとも 1 の定員がある場合、合計学位が少なくとも 1 つ以上の学位シーケンスがあるためです。`2(c - 1)`接続されたグラフを実現できます。 能力を尊重しながらいつでもツリーを構築できます。 

問題ははるかに単純になります。 

最初は、各コンポーネントが以下に貢献します。```
capacity_i = min(size_i, k)
```2 つのコンポーネントを道路と結合すると、それらのサイズが合計されるため、新しい容量は次のようになります。```
min(size_a + size_b, k)
```州の総数は 1 つ減少します。 

重要な点は、統合によって総容量が決して減少しないことです。 場合によってはそれが増加します。 

2 つのコンポーネントに容量があるとします。`a`そして`b`。 統合後の容量は最大になります`k`したがって、ゲインは次のようになります。```
min(size_a + size_b, k) - a - b
```容量を増やす唯一の方法は、一方または両方のコンポーネントが小さすぎてすでに到達できない場合です。`k`。 

最適な戦略は、最初に最小のコンポーネントを貪欲にマージすることです。容量がまだ増加できるのは小さなコンポーネントだけであるためです。 

最終的には、よりクリーンな状態を導き出すことができます。 

させて：```
S = sum(min(size_i, k))
C = number of components
```次の場合に、実現可能なトンネル ネットワークが存在します。```
S >= 2(C - 1)
```2 つのコンポーネントを 1 つの道路と結合すると、次のようになります。```
C decreases by 1
S may increase
```したがって、実現可能性は単調に向上します。 

残りのタスクは、必要な最小限のマージを計算することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DFS または反復スタック トラバーサルを使用して、グラフの接続されたコンポーネントを構築します。 

すべての接続されたコンポーネントは 1 つの州に対応します。 
2. 各コンポーネントについて、そのサイズを計算します。 

コンポーネントに`s`最大でも都市をサポートできます`min(s, k)`各都市は最大 1 つのトンネルに参加できるため、トンネル エンドポイントにアクセスできません。 
3. 以下を計算します。```
C = number of components
S = sum(min(size_i, k))
```4. 現在のグラフがすでに実現可能かどうかを確認します。 

州間のトンネルグラフには少なくとも次のものが必要です`2(C - 1)`合計度。 もし：```
S >= 2(C - 1)
```それから答えてください`0`。 
5. それ以外の場合は、最も収益性の高い方法でコンポーネントを繰り返しマージします。 

マージが減少する`C`1. 可能な限り最善の増加`S`以下の容量の小さなコンポーネントを組み合わせることで得られます。`k`。 
6. 1 回のマージ後に何が起こるかを観察します。 

容量が`a`そして`b`。 統合された容量は次のとおりです。```
min(a + b, k)
```以来`a = min(size_a, k)`そして同様に`b`。 

総容量の増加は次のとおりです。```
gain = min(a + b, k) - a - b
```1 つのコンポーネントの下に未使用のスペースがない限り、これは決して正ではありません。`k`。 
7. 赤字を導き出します。 

必要なものは次のとおりです。```
S >= 2(C - 1)
```並べ替え:```
deficit = 2(C - 1) - S
```8. マージするたびに、必要な右辺が 2 ずつ減ります。`C`1ずつ減少します。 

たとえ`S`増加しない場合、実現可能性は 2 向上します。 
9. したがって、その後`x`マージすると、実現可能条件は次のようになります。```
S' >= 2(C - x - 1)
```10. 最適なマージ数は貪欲に取得され、常に獲得容量が最大化されます。これは事実上、不足がなくなるまで最初に小さなコンポーネントをマージすることを意味します。 
11. より強力な構造の単純化が見られます。 

少なくともサイズのあるコンポーネント`k`すでに飽和しているため、これ以上容量を増やすことができません。 以下のサイズのコンポーネント`k`正確にそのサイズに貢献します。 

1. 次のようにしましょう。```
T = total number of cities inside components with size < k
```その場合、将来得られる可能性のある総利益は制限されます。 
2. 最適なマージをシミュレートすると、コンポーネント サイズに対する直接的な貪欲なプロセスが行われます。 以下のコンポーネントのサイズを並べ替えます`k`、条件が true になるまで、最小のものを繰り返しマージし、容量を更新します。 

### なぜ効果があるのか

 正確さは、実現可能なトンネル ネットワークの特徴付けから得られます。 

接続されたグラフ`C`地方は少なくとも必要とする`2(C - 1)`合計度。 州で取得可能な学位`i`等しい`min(size_i, k)`。 利用可能な度数の合計が必要な度数よりも小さい場合、建設は不可能です。 

逆に、利用可能な次数の合計が十分であれば、すべての空でないコンポーネントが少なくとも 1 つの可能な端点に寄与し、次数制約がツリー次数合計条件を満たすため、常に接続されたグラフを実現できます。 

コンポーネントのマージは、利用可能な次数の合計が増加し、必要なトンネル エッジの数が常に減少する可能性があるためのみ有用です。 サイズの小さいコンポーネントを貪欲に結合すると、道路ごとの改善が最大化されるため、不等式が真になる最初の瞬間が最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

def solve():
    n, m, k = map(int, input().split())

    g = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    vis = [False] * n
    sizes = []

    for i in range(n):
        if vis[i]:
            continue

        stack = [i]
        vis[i] = True
        sz = 0

        while stack:
            v = stack.pop()
            sz += 1

            for to in g[v]:
                if not vis[to]:
                    vis[to] = True
                    stack.append(to)

        sizes.append(sz)

    comps = len(sizes)

    if comps == 1:
        print(0)
        return

    caps = [min(x, k) for x in sizes]
    total = sum(caps)

    need = 2 * (comps - 1)

    if total >= need:
        print(0)
        return

    small = []

    for x in sizes:
        if x < k:
            small.append(x)

    small.sort()

    ans = 0
    cur_total = total
    cur_comps = comps

    ptr = 0

    while cur_total < 2 * (cur_comps - 1):
        if ptr + 1 < len(small):
            a = small[ptr]
            b = small[ptr + 1]

            before = a + b
            after = min(a + b, k)

            cur_total += after - before

            small[ptr + 1] = after
            ptr += 1
        else:
            pass

        cur_comps -= 1
        ans += 1

    print(ans)

solve()
```実装の最初の部分では、接続されたコンポーネントを繰り返し構築します。 再帰的 DFS は危険です。グラフには最大 100 万個の頂点が含まれる可能性があり、制限を増やしても Python の再帰スタックがオーバーフローする可能性があります。 

コンポーネントごとに、そのサイズを保存します。 コンポーネントのトンネル容量は次のとおりです。`min(size, k)`すべてのトンネルのエンドポイントは異なる都市を使用する必要があるためです。 

中心的な不等式は次のとおりです。```
sum(capacity) >= 2 * (components - 1)
```これがすでに成立している場合、追加の道路は必要ありません。 

それ以外の場合は、以下のサイズのすべてのコンポーネントが収集されます。`k`。 これらは、マージ後に容量が増加する可能性がある唯一のコンポーネントです。 並べ替えることで、最小容量から順に貪欲に組み合わせることができます。 

ループ内では、マージごとにコンポーネント数が 1 つずつ減ります。 2 つの不飽和コンポーネントを結合すると、総容量が増加する可能性があります。 式:```
after - before
```マージによって生じる合計トンネル容量の正確な増加を計算します。 

実装の微妙な詳細の 1 つは、飽和したコンポーネントをマージしても容量は決して向上しませんが、それでもコンポーネントの数が減少するため、必要な次数の合計が減少することです。 すべてのマージが削減されるため、ループはこれを自然に処理します。`cur_comps`。 

もう 1 つの微妙な点は、マージ後のポインターの移動です。 2 番目のコンポーネントをマージされたサイズで上書きし、ポインタを進めて、将来のマージでより大きなマージされたコンポーネントの構築を継続できるようにします。
