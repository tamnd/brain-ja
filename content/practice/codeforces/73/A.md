 ## 問題の理解

 寸法を持つ単位立方体で作られた長方形のブロックがあります。`x × y × z`。 単一のカットは常にグリッド線に沿って行われ、ボックスのいずれかの面と平行である必要があります。 カットは無限に長く、ピースは元の位置から離れることがないため、1 つのカットがすでに作成された多数のピースを一度に通過できます。 

目標は、作成した最終ピースの数を最大化することです。`k`カット。 

重要な詳細は、カットがどのように動作するかです。 作ったら`a`に垂直にカットします`x`軸に応じて、ボックスは次のように分割されます。`a + 1`その方向に沿ってレイヤーを重ねていきます。 同様に、`b`沿ってカットします`y`生産する`b + 1`そこのセクション、そして`c`沿ってカットします`z`生産する`c + 1`セクション。 もし`a + b + c = k`、ピースの合計数は次のようになります。$(a+1)(b+1)(c+1)$寸法により、各方向に可能なカットの数が制限されます。 長さに沿って`x`、あるだけです`x - 1`有効なグリッド平面なので、次のようになります。$0 \le a \le x-1$他の 2 つの次元についても同様です。 

制約により、カットのシミュレーションは即座に除外されます。 到達可能な寸法`10^6`、 その間`k`到達できる`10^9`。 状態またはカットの数に比例するアルゴリズムは非常に遅すぎます。 すべてのトリプルを反復しても`(a,b,c)`素朴に必要になるでしょう`10^{18}`最悪の場合の組み合わせは不可能です。 

この問題は実際には 3 つの整数に関する最適化問題です。 次元が 3 つしかないため、数学的観測を使用して探索空間を積極的に縮小できます。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

入力が次のとおりであるとします。```
1 1 1 100
```各次元にはすでにサイズがあるため、カットはできません`1`。 正しい答えは、`1`、関与するものではありません`k`。 

もう一つの微妙なケースは次のような場合です。`k`使用可能な切断面の総数を超えています:```
2 2 2 10
```各寸法で許可されるカットは 1 つだけなので、最大でも 3 つのカットが役に立ちます。 最大個数はまだです`8`。 

よくある間違いは、カットが常に均等に分配されるべきであると仮定することです。 考慮する：```
10 1 1 5
```1次元目のみカット可能です。 答えは`6`、のようなバランスの取れたものではありません`2 × 2 × 2`。 

もう 1 つの危険な実装バグは、32 ビット整数を使用する言語の整数オーバーフローによって発生します。 答えは次のとおりです。$10^6 \cdot 10^6 \cdot 10^6 = 10^{18}$Python はこれを自動的に処理しますが、C++ ソリューションでは`long long`。 

## アプローチ

 ブルートフォースソリューションでは、各方向で可能な限りの数のカットを試みます。 すべてのトリプルを反復処理できます`(a,b,c)`満足のいく：$a+b+c \le k$各値が寸法制限内にあるかどうかを確認します。 有効なトリプルごとに次を計算します。$(a+1)(b+1)(c+1)$そして最大値を維持します。 

すべての有効な切断戦略は、各軸に割り当てられる切断の数によって一意に記述されるため、これは論理的に機能します。 問題は探索空間のサイズです。 までを繰り返しただけでも、`10^6`、トリプルループは完全に不可能になります。 

重要な観察は、答えがカットの順序ではなく、軸ごとのカット数のみに依存するということです。 決めたら`a`、`b`、 そして`c`、個数は固定です。 

これにより、問題は制約の下で製品を最大化することに変わります。 

寸法の上限がない場合、値のバランスが可能な限り整ったときに製品が最大になります。 これは標準的な算術平均および幾何平均の直感です。 ただし、各方向で受けられるカットの数には寸法の制限があるため、最適な配分が限界に達する可能性があります。 

変数が 3 つしかないため、そのうち 2 つを反復処理して 3 つ目を導出できます。 さらに最適化すると、これが実用的になります。 寸法は対称なので、並べ替えます。 次に、最小の 2 次元の実行可能なカットを繰り返し、3 番目の次元は自動的に決定されます。 

寸法が小さくなるとループが大幅に制限されるため、反復の総数は管理可能なままになります。

 ## アルゴリズムのチュートリアル

 1.読む`x`、`y`、`z`、 そして`k`。 
2. 3 つの次元を並べ替えます。 軸は交換可能であるため、答えは変わりません。 並べ替えは、ネストされたループを小さく保つのに役立ちます。 
3. 可能なすべてのカット数を繰り返します。`a`最初の次元に沿って。 

有効な範囲は次のとおりです。$0 \le a \le \min(k, x-1)$4. それぞれについて`a`、可能なすべてのカット数を繰り返します。`b`二次元に沿って。 

有効な範囲は次のとおりです。$0 \le b \le \min(k-a, y-1)$5. 残りのカットは 3 次元に進みます。$c = \min(k-a-b, z-1)$余分なカットが増えるため、できるだけ多くの残りのカットを使用します。`c`常に製品を増やします。 
6. 結果として得られるピースの数を計算します。$(a+1)(b+1)(c+1)$7. すべての反復にわたって最大値を追跡します。 
8. 最大値を出力します。 

### なぜ効果があるのか

 軸に垂直なカットごとに、その軸に沿ったセクションの数が 1 つずつ増加します。 最終的なピースは 3D グリッドを形成するため、ピースの総数は各次元のセクション数の積になります。 

アルゴリズムは、実行可能なすべてのペアを列挙します。`(a,b)`。 それらが修正されれば、可能な限り最善の状態が得られます`c`積は次のように単調増加するため、常に最大許容残り値になります。`c`。 

有効なカットの分布はすべて 1 回だけ考慮され、分布ごとに正しいピース数が計算されるため、アルゴリズムによって見つかった最大値が真の最適値となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, y, z, k = map(int, input().split())

    dims = sorted([x, y, z])
    x, y, z = dims

    ans = 1

    max_a = min(k, x - 1)

    for a in range(max_a + 1):
        max_b = min(k - a, y - 1)

        for b in range(max_b + 1):
            c = min(k - a - b, z - 1)

            pieces = (a + 1) * (b + 1) * (c + 1)
            ans = max(ans, pieces)

    print(ans)

solve()
```最初のステップでは、最小の境界が外側のループを制御するように次元を並べ替えます。 これにより、ランタイムが管理しやすくなります。 

外側のループは、最初の軸に沿ったカットの数を選択します。 しかないので、`x - 1`有効なプレーンの場合、ループはその値を超える必要はありません。 

あらゆる人にとって`a`、2 番目のループは 2 番目の軸のカットを選択します。 繰り返しますが、残りのカット数または利用可能なプレーンのいずれかを超えることはできません。 

3 番目の値には別のループは必要ありません。 一度`a`そして`b`が固定されている場合、3 番目の軸に沿った追加のカットは厳密に積を増加させます。 最良の選択とは、単に実現可能な最大値です。 

乗算では、`(a + 1)`、`(b + 1)`、 そして`(c + 1)`なぜなら`n`カットを作成する`n + 1`セグメント。 

よくある 1 つ違いの間違いは、`x`代わりにカットします`x - 1`。 長さの寸法`x`正確に含まれています`x - 1`内部の切断面。 

もう 1 つの微妙な点は、`min(k - a - b, z - 1)`のために`c`。 利用可能な平面を超える余分なカットは役に立たないため、カウントしてはなりません。

import io

def solve():
    input = sys.stdin.readline

    x, y, z = sorted([x, y, z])

    ans = 1

    for a in range(min(k, x - 1) + 1):
        for b in range(min(k - a, y - 1) + 1):

            ans = max(ans, (a + 1) * (b + 1) * (c + 1))

def run(inp: str) -> str:

    out = io.StringIO()
    backup = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup
