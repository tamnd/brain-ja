 ## 解決策
 ## 問題の理解

 ゲーム内のキャラクターの名前を表す文字列が与えられ、その文字の最大 _k_ 個を変更して、euphony と呼ばれるスコアを最大化できます。 ユーフォニーは、文字列内の連続する文字ペアごとのボーナスの合計として計算されます。 文字の各ペアには、プラスまたはマイナスのボーナスが関連付けられている場合があります。ペアがリストされていない場合、そのボーナスはゼロです。 

入力は、文字列 _s_、整数 _k_、および対応するボーナスを持つ文字のペアのセットで構成されます。 出力は単一の整数で、最大 _k_ 件の変更を加えた後に可能な最大のユーフォニーです。 

制約はかなり厳しく、文字列の長さは最大 100、_k_ も最大 100 です。文字ペアの数は最大 676 (可能なすべての小文字ペア) です。 これらの制限は、文字列長に対する多項式の時間計算量を使用するアプローチが実現可能であることを示しています。 複雑度 O(n * k * 26^2) のアルゴリズム (n は文字列長) は、100 * 100 * 676 が約 670 万回の演算に相当し、2 秒の制限内に収まるため許容されます。 エッジ ケースには、変更が許可されない _k_ = 0、およびすべてのペア ボーナスがゼロになる _n_ = 0 が含まれます。 不注意なアプローチでは、すべてのペアにボーナスがあると仮定したり、_k_ = 0 を無視したりして、不正確な結果が生じる可能性があります。 

## アプローチ

 ブルートフォース手法では、文字列内の最大 _k_ 文字を変更する可能なすべての方法を列挙します。 それぞれの位置について、文字をそのままにすることも、他の 25 文字のいずれかに置き換えることもでき、膨大な数の可能性が生まれます。 長さが 100 で _k_ = 100 の文字列の場合、O(26^100) の可能性が生じますが、これは完全に実行不可能です。 有益な変更のみを考慮して最適化を試みても、依然として指数関数的な検索スペースが残ります。 

重要な洞察は、問題には最適な部分構造と重複する部分問題があり、動的プログラミングに適しているということです。 DP 状態は次のように定義できます。`dp[i][changes][last]`、最初のパラメータを使用して達成可能な最大のユーフォニーを表します。`i`手紙、使用した`changes`置換、使用される最後の文字は`last`。 各ステップで、元の文字を変更するか、現在の位置で考えられるすべての文字を試すことができます（`k`) またはそれを保持し、最後と現在のレターのボーナスに基づいて DP を更新します。 アルファベットが小さく (26 文字)、文字列の長さが制限されているため、このアプローチは扱いやすくなっています。 

これは、プレフィックスのスコアがプレフィックスの最後の文字と使用される変更の数にのみ依存するという観察を利用して、問題を指数総当たりから多項式 DP ソリューションに変換します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(26^n) | お(1) | 遅すぎる |
 | 動的プログラミング | O(n * k * 26^2) | O(n * k * 26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 3D DP 配列を初期化する`dp[i][changes][last]`、 どこ`i`文字列内のインデックスです。`changes`は置換される文字数であり、`last`は、最後に使用された文字のインデックスです。 最大化するので、大きな負の数を入力します。 
2. 入力文字列を、文字「a」～「z」に対応する数値インデックス 0～25 に変換します。 
3. ボーナスペアを 26x26 の行列に解析します。`bonus`どこ`bonus[x][y]`ペアのスコアを与えます`xy`。 リストされていないペアのデフォルトは 0 です。 
4. 最初の文字の基本文字を設定します。 インデックス 0 の可能な文字ごとに、それを変更すると、使用された変更が増分されます。 アップデート`dp[0][changes][letter]`ボーナスを生成する前に文字がないため、0 を使用します。 
5. 文字列をインデックス 1 から n-1 まで繰り返します。 これまでに使用された可能性のある変更の数ごと、および可能性のある前の文字ごとに、現在の位置に配置できるすべての文字を考慮します。 新しい変更カウントと、前の文字で形成されたペアのボーナスを計算します。 アップデート`dp[i][new_changes][current_letter]`以前の値と前の値の間の最大値になります。`dp[i-1][changes][prev_letter] + bonus[prev_letter][current_letter]`。 
6. 文字列全体を処理した後、最大ユーフォニーを追跡しながら、インデックス n-1 および変化 ≤ k のすべての DP 状態を反復処理します。 
7. 見つかった最大値を出力します。 

機能する理由: DP では、各ポジションで、指定された数の置換と最後の文字でそのポジションに到達するためのあらゆる可能な方法を考慮します。 更新時に常に最大値を採用することで、より良い構成が見落とされることがないことを保証します。 最後の文字のディメンションを使用すると、連続する文字間にペア ボーナスが正しく適用されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s, k = input().split()
k = int(k)
n = int(input())

bonus = [[0]*26 for _ in range(26)]
for _ in range(n):
    x, y, c = input().split()
    bonus[ord(x)-97][ord(y)-97] = int(c)

m = len(s)
dp = [[[-10**18]*26 for _ in range(k+1)] for _ in range(m)]

# Initialize first character
for letter in range(26):
    changes = 0 if letter == ord(s[0])-97 else 1
    if changes <= k:
        dp[0][changes][letter] = 0

# Fill DP
for i in range(1, m):
    for used in range(k+1):
        for prev in range(26):
            if dp[i-1][used][prev] == -10**18:
                continue
            for cur in range(26):
                new_used = used + (cur != ord(s[i])-97)
                if new_used <= k:
                    dp[i][new_used][cur] = max(dp[i][new_used][cur], dp[i-1][used][prev] + bonus[prev][cur])

# Get result
ans = max(dp[m-1][used][letter] for used in range(k+1) for letter in range(26))
print(ans)
```コードはまず入力を読み取り、変換します。 ボーナス行列は単純で、DP の初期化では、不可能な状態を表すために大きな負の数が使用されます。 最初の文字には前の文字がないため、慎重に個別に処理します。 可能性のある前の文字と現在の文字を反復すると、すべての遷移が考慮されることが保証されます。 使用する`max`各状態で最適なユーフォニーを確実に追跡します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * k * 26^2) | 位置ごとに、使用される可能性のある変化がそれぞれ変化し、以前の文字ごとに、現在の 26 個の可能性のある文字が考慮されます。 |
