 ## 解決策
 ## 問題の理解

 位置 0 から位置 n まで、一列に配置された一連のパイロンが与えられます。 最初のパイロンは高さ 0 に固定されており、他のすべてのパイロンは指定された高さを持ちます。 プレイヤーはエネルギーゼロでパイロン 0 からスタートし、パイロン k からパイロン k+1 まで、一度に 1 歩ずつ厳密に前進します。 

それぞれの動きは、現在の高さと次の高さの差によってエネルギーを変化させます。 次のパイロンが低ければエネルギーは増加し、高ければエネルギーは減少します。 重要な制約は、移動中のどの時点でもエネルギーがゼロ以下になることは許されないということです。 

単位増加ごとに 1 ドルを費やすことで、任意のパイロンの高さを増やすことができます。0 から n への移動が実現可能になるように、費やされる合計ドルを最小限に抑えたいと考えています。 

n ≤ 100000 という制約により、考えられるすべての高さの変更を試行したり、構成に対する高価な検索をシミュレートしたりするアプローチは即座に除外されます。 すべての解は n において線形または線形に近いものでなければなりません。 O(n log n) であっても許容されますが、二次関数は許容されません。 

単純なアプローチでは、旅行をシミュレートし、エネルギーがマイナスになるたびに、明確な戦略を持たずに貪欲に以前または現在の高さをいくらか上げようとする可能性があります。 これは、初期の調整が非局所的な方法で後の移行に影響を与えるため、失敗します。 

局所的な修正が近視眼的である場合、微妙な失敗例が発生します。 たとえば、高さが次の場合:```
n = 3
h = [5, 1, 5]
```貪欲なシミュレーションにより、5 から 1 への低下は修正される可能性がありますが、その後も 1 から 5 で失敗し、冗長または間違ったアップグレードにつながります。 正しい解決策は、段階的に対応するのではなく、パスに沿って遭遇する最悪の欠陥について全体的に推論する必要があります。 

## アプローチ

 この強引なアイデアは、走行をシミュレートし、エネルギーがマイナスになるたびに、パイロンの高さをいくらか上げて補償しようとすることです。 それぞれの失敗点でどこにお金を使うかについてあらゆる選択肢を試みることもできます。 これはすぐに組み合わせ的なものになります。修正するたびに将来の差異が変化し、最悪の場合、以前の決定を繰り返し再検討する可能性があります。 n が最大 100,000 の場合、数千の分岐修正でも爆発的に限界を超えるのに十分です。 

重要な洞察は、エネルギー進化の観点から考えるのをやめ、代わりに実際に重要なことを書き直すことです。 各移動は、差 h[k] - h[k+1] に寄与します。 これらを時間の経過とともに合計すると、プレフィックスの動作のみに依存する累積エネルギーが得られます。 エネルギーが問題となるのは、これらの差のプレフィックスの合計がゼロを下回るときだけです。 

式を整理すると、危険な瞬間は高さ h[i] が蓄積されたエネルギーから許容できる高さよりも大きいときだけであることがわかります。 エネルギーを明示的に追跡する代わりに、どれだけの「自由予算」があるかを維持し、それが決してマイナスにならないようにすることができます。 お金を支払う必要があるのは、減少によって以前の増加をカバーできない場合だけです。 

より単純な解釈が生まれます。つまり、これまでのすべての有効高さよりも高い高さに遭遇するたびに、マイナスのエネルギーなしでその高さに到達できるように、ベースラインを上げるために「お金を払う」必要があります。 これにより、問題は、現在の最大高さを追跡し、開始レベルと比較して不足分が蓄積するという問題に軽減されます。 

したがって、最適な解決策は線形です。左から右にスキャンして、これまでに確認された最高の高さを維持し、次の高さが現在の有効容量よりも高くなるたびに、その差額を正確に支払います。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちはこの旅を、非負のエネルギーを保証するベースラインの高さを維持するものとして再解釈します。 

1. 高さ 0、エネルギー 0 のパイロン 0 から開始するため、ベースライン 0 から開始します。 また、答えを 0 として初期化し、費やした合計金額を表します。 
2. パイロンを 1 から n まで繰り返します。 各ステップで、現在の高さをベースライン要件と比較します。 
3. 現在の高さがベースラインより大きい場合は、それに一致するようにベースラインを大きくする必要があります。 この差は、この時点でどれだけのドルを費やさなければならないかを正確に表しています。なぜなら、より前のパイロンを効果的に上げないと、このより高いパイロンに足を踏み入れるときにエネルギーがマイナスになるからです。 
4. この違いを答えに追加します。 これは、移行が引き続き実現可能であるように、適切な鉄塔を増やすために資金を投じることをモデル化しています。 
5. ベースラインを現在の値と現在の高さの最大値になるように更新します。 
6. 最後のパイロンが処理されるまで続行します。 累計コストは最低限必要な支出です。 

### なぜ効果があるのか

 重要な不変条件は、鉄塔 i を処理した後、ベースラインがこれまでに確認された最大の高さに等しいということです。 これにより、以前に処理されたすべての遷移が安全であることが保証されます。つまり、動きの接頭語に負のエネルギーが含まれていないことになります。 新しい高さがこの最大値を超えるたびに、そのステップでのマイナスのエネルギー低下を回避する唯一の方法は、以前のパイロンを上げてそれをすでに補償しておくということです。 適用される場所に関係なく、単位の増加ごとにちょうど 1 ドルのコストがかかるため、新しい最大値に達した瞬間にベースラインを段階的に増加させるのが最適であり、過剰な支払いになることはありません。 遅れた補正は同じ高さのギャップに一致する必要があるため、この貪欲な蓄積は最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    h = list(map(int, input().split()))

    current_max = 0
    cost = 0

    for x in h:
        if x > current_max:
            cost += x - current_max
            current_max = x

    print(cost)

if __name__ == "__main__":
    solve()
```この実装により、これまでに確認された実行中の最大高さが維持されます。 新たな高さがそれを超える場合は、その差額を料金に加算させていただきます。 これは、新しいピークに会うために以前の地形を「持ち上げる」必要があるという考えを直接エンコードしています。 

よくある間違いは、プレフィックスの違いを使用してエネルギーを直接シミュレートしようとすることです。 このアプローチでは問題が複雑になり、不必要な状態が生じます。 貪欲な最大追跡アプローチにより、明示的なエネルギー追跡が完全に回避されます。 

もう 1 つの微妙な点は、配列内で明示的に何も調整しないことです。 この推論は等価性に基づいています。つまり、以前のパイロンを増やすか、概念的にベースラインを増やすと、将来のすべての差異に対して同じ効果が生じます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | すべてのパイロンを 1 回通過、要素ごとに一定の作業 |
 | スペース | お(1) | 入力サイズに関係なく、少数の変数のみが使用されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    h = list(map(int, input().split()))

    current_max = 0
    cost = 0

    for x in h:
        if x > current_max:
            cost += x - current_max
            current_max = x

    return str(cost)

# provided sample
assert run("5\n3 4 3 2 4\n") == "4"

# minimum input
assert run("1\n1\n") == "1"

# already decreasing sequence
assert run("4\n5 4 3 2\n") == "5"

# strictly increasing
assert run("4\n1 2 3 4\n") == "4"

# all equal
assert run("5\n2 2 2 2 2\n") == "2"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1 | 1 | 最小限のケース処理 |
 | 5 4 3 2 | 5 | 降順 |
 | 1 2 3 4 | 4 | シーケンスの累積を増加する |
 | 2 2 2 2 2 | 2 | 繰り返しの出費はありません |

 ## 特殊なケース

 のような最小限のケース`n = 1, h = [1]`最初のパイロンがゼロを超えてもまだ消費しなければならないことを示しています。 アルゴリズムは正しく追加します`1 - 0 = 1`すぐに。 

次のような厳密に減少するシーケンス`5 4 3 2`最初のステップの後に追加の支出を引き起こすことはありません。 最初の値は必要なベースラインを設定し、それ以降の値はすべて安全にそのベースラインを下回ります。 アルゴリズムはこれを更新することで処理します`current_max`最初のステップで 5 に変更し、それを再度変更しないと、合計コストは 5 になります。 

次のような厳密に増加するシーケンス`1 2 3 4`新しい高さは以前の最大値を超えるため、すべてのステップで支出が強制されます。 このアルゴリズムは、継続的にベースラインを上げるという直感的なニーズに合わせて、差を 1、次に 1、次に 1、次に 1 と累積的に追加します。
