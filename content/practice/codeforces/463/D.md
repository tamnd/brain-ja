 ## 解決策
 ## 問題の理解

 1 から _n_ までの数値の _k_ 通りの順列が与えられます。 順列とは、単にこれらの数値を並べ替えることです。 私たちの目標は、すべての _k_ 順列で同じ相対順序で現れる最長の数値シーケンスの長さを見つけることです。 言い換えれば、2 つの文字列またはシーケンスだけでなく、複数の順列にわたって最長共通部分列 (LCS) を計算することが求められます。 

制約により、_n_ は最大 1000、_k_ は最大 5 になります。長さ _n_ のサブシーケンスの数は 2^n であり、_n_ = 1000 の場合は天文学的に大きいため、これにより、すべてのサブシーケンスを反復する総当りアプローチは即座に排除されます。2 つのシーケンス (O(n^2)) に対する標準的な動的プログラミング アプローチでも、_n_ = に対して適切に拡張できます。 1000 ですが、_k_ シーケンスまで効率的に拡張するソリューションが必要です。 

微妙な特殊なケースは、すべての順列が同一である場合です。 その場合、LCS は長さ _n_ の完全な順列にすぎません。 別のケースは、順列が互いに完全に逆の順序である場合です。 たとえば、n=3、k=2 でシーケンスが [1,2,3] と [3,2,1] の場合、LCS は単に [2] または [1] または [3]、つまり長さ 1 になります。最初のシーケンスのみをペアごとに他のシーケンスと比較する不用意なアプローチでは、要素をカウントしすぎて間違った答えが得られる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、最初の順列のすべての部分列を生成し、それぞれが他のすべての順列に現れるかどうかを確認しようとします。 これは、別の置換におけるシーケンスのメンバーシップのチェックが線形であるため機能しますが、サブシーケンスの数は 2^n であるため、n=20 の場合でもすでに遅すぎます。 n=1000 の場合、それは実行不可能です。 

これを効率的に解決するための重要な洞察は、すべての順列に 1 から n までの数字が正確に含まれていることです。 これにより、数値を各順列の位置にマッピングすることができます。 すべての順列にサブシーケンスが現れるには、すべてのシーケンスのインデックス位置でこれらの数値の相対順序が増加している必要があります。 したがって、問題は、インデックスがすべての順列で同時に増加する 1..n の最長の数列を見つけることに帰着します。 

各数値を k 個の順列すべてにわたる位置のタプルとしてエンコードすると、問題は k 次元空間で最長の増加シーケンスを見つけることと同等になります。 n ≤ 1000 および k ≤ 5 であるため、最初の順列の順序で数値を反復し、前の数値をチェックする動的プログラミング アプローチが機能します。 具体的には、dp[x] を番号 x で終わる最長の共通部分列の長さとして定義できます。 最初の順列の順序で数値を繰り返し、各数値について、以前のすべての数値をチェックして、他のすべての順列の中で先に出現するかどうかを確認します。 そうであれば、dp[y] + 1 から dp[x] を拡張できます。 

これにより、O(n^2 * k) の解が得られます。これは、n^2 * k ≤ 1000^2 * 5 = 5 * 10^6 演算であるため、実行可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n * k) | O(n) | 遅すぎる |
 | 位置マッピングを使用した動的プログラミング | O(n^2 * k) | O(n * k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 要素の数 n と順列の数 k を読み取ります。 
2. 簡単にアクセスできるように、k 個の順列すべてをリストのリストに保存します。 
3. 各順列の位置マップを構築します。pos[i][x] は、順列 i 内の数値 x の 0 から始まるインデックスを格納します。 これにより、数値のインデックスを定数時間で検索できるようになります。 
4. 長さ n+1 の配列 dp を初期化します。 dp[x] には、番号 x で終わる最長の共通部分列の長さが格納されます。 
5. 最初の順列の順序で数値を繰り返します。 それぞれの番号について`current`、この数値のみを含むサブシーケンスの長さは 1 であるため、dp[current] = 1 を初期化します。 
6. 数字ごとに`previous`前に来たこと`current`最初の順列で、前に出現するかどうかを確認します。`current`他のすべての順列でも。 これは、1 から k-1 までのすべての i について pos[i][previous] < pos[i][current] を比較することによって行われます。 
7. もし`previous`前に現れます`current`すべての順列で、 dp[current] = max(dp[current], dp[previous] + 1) を更新します。 
8. すべての数値を処理した後の dp の最大値は、最長の共通部分列の長さになります。 
9. この最大値を出力します。 

機能する理由: dp[x] は、すべての順列において有効な先行要素である数値を持つシーケンスのみを拡張するため、x で終わる最長の共通部分シーケンスを正しく格納します。 最初の順列の順序で数値を処理することにより、サブシーケンスが最初のシーケンスに従って順序付けされたままであることが保証され、他の順列にわたるチェックによってサブシーケンスの順序がグローバルに尊重されることが保証されます。 この不変式により正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
perms = [list(map(int, input().split())) for _ in range(k)]

# position mapping: pos[i][x] = index of x in permutation i
pos = [{} for _ in range(k)]
for i in range(k):
    for idx, val in enumerate(perms[i]):
        pos[i][val] = idx

dp = [0] * (n + 1)
first_perm = perms[0]

for current in first_perm:
    dp[current] = 1
    for previous in first_perm:
        if previous == current:
            break
        if all(pos[i][previous] < pos[i][current] for i in range(1, k)):
            dp[current] = max(dp[current], dp[previous] + 1)

print(max(dp))
```位置マップにより、順列間の相対的な順序を迅速に比較できるようになります。 最初の順列で数値を繰り返すことにより、少なくとも 1 つの順列のシーケンスに従って dp が構築されることが保証されます。 の`all`check は、すべてのシーケンスにわたって LCS 状態を確認します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    perms = [list(map(int, input().split())) for _ in range(k)]
    pos = [{} for _ in range(k)]
    for i in range(k):
        for idx, val in enumerate(perms[i]):
            pos[i][val] = idx
    dp = [0] * (n + 1)
    first_perm = perms[0]
    for current in first_perm:
        dp[current] = 1
        for previous in first_perm:
            if previous == current:
                break
            if all(pos[i][previous] < pos[i][current] for i in range(1, k)):
                dp[current] = max(dp[current], dp[previous] + 1)
    return str(max(dp))
