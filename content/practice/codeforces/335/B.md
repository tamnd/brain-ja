 ## 解決策
 ## 問題の理解

 小文字で構成される単一の文字列が与えられます。 この文字列から、残りの文字の順序を維持しながら文字を削除することができ、結果として生じる回文である部分列のみに関心があります。 

タスクは 2 つあります。 まず、長さがちょうど 100 の回文部分列が存在するかどうかを判断する必要があります。そのような部分列が存在する場合は、それらのいずれかを出力できます。 存在しない場合は、指定された文字列から構築できる最長の回文サブシーケンスを出力するように求められます。 

主な難点は、部分文字列ではなくサブシーケンスを最適化していることです。つまり、順序が保たれていればどこからでも文字を選択できることになります。 このため、候補者のスペースが非常に大きくなり、直接列挙することは不可能になります。 

長さの制約は、ソリューションの重要な推進力です。 文字列の長さは最大 50,000 まで可能ですが、ここで考慮するのは長さ 100 の回文を組み立てられるかどうかだけです。古典的な LPS の DP は O(n^2) であり、最悪の場合で約 25 億回の演算に相当するため、文字列全体にわたる最長回文部分列の完全な DP テーブルを計算しようとするソリューションは遅すぎます。 

文字列に繰り返し文字が多数含まれているが、それらがまばらに分散している場合、微妙なエッジ ケースが発生します。 たとえば、文字が交互に並ぶような文字列では、多くの短い回文は許可されますが、長さ 100 は決して許可されません。逆に、1 つの文字がほぼすべての場所を占める文字列には、長い回文が含まれることは明らかです。 計画を立てずに端から一致する文字を選択する単純な貪欲なアプローチは、早い段階で行き詰まり、全長 100 の回文が存在する場合でも構築する可能性を逃してしまう可能性があります。 

別の失敗例は、最良の回文が最も頻繁に出現する文字を中心にしていない場合に発生します。 頻度ベースの貪欲なソリューションでは、最も頻繁に使用される文字から答えが構築されると想定できますが、構造がインターリーブされてお​​り、一致するペアが異なるセグメント間でのみ存在する場合には失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、文字列全体に対して動的プログラミングを使用して最長の回文部分列を計算しようとします。 これは、すべての間隔を考慮し、その範囲内で最適な回文を計算することで機能します。 正確さは標準ですが、状態空間は O(n^2) で、各遷移は O(1) であるため、n = 50000 の場合に約 25 億回の操作が発生し、2 秒の制限には遅すぎます。 

重要な観察は、100 を超える場合、正確な最長回文部分列は必要ないということです。長さ 100 の回文を構築できるかどうかのみを考慮し、そうでない場合は、最大限の構築のみが必要です。 これにより、問題は全体的な最適化から制御された構築へと移行します。 

回文の重要な構造特性は、回文が中心を中心に鏡映された一致する文字のペアによって定義されることです。 これは、文字の出現のペアの観点から考えることができることを意味します。 各文字について、左端と右端からの出現をペアにすることができます。 各ペアは回文に 2 つの文字を提供します。 文字全体のペアを蓄積すると、回文の外側の層を効果的に構築することになります。 

合計で少なくとも 50 のペアを集めることができれば、長さ 100 の回文を形成できます。そうでない場合は、利用可能なすべてのペアと、場合によっては残っている 1 つの中間文字を取得し、可能な限り最大の回文を作成します。 

したがって、この構造は、各キャラクターの位置を追跡し、反対側の端から貪欲にペアを形成することになります。 これが機能するのは、有効な回文部分列が出現のペアに対応する必要があり、順序が保たれている限り有効なペアを自由に選択できるためです。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DP | O(n^2) | O(n^2) | 遅すぎる |
 | 貪欲なペア構築 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各文字について、それが出現するインデックスのリストを維持します。 各リストから、外側から内側へのペアを取り出します。 

1. 文字列をスキャンし、各文字のインデックスを個別に保存します。 これにより、有効なサブシーケンスに必要な順序が維持されます。 
2. 各文字について、左端と右端の未使用の文字列を繰り返し取得し、ペアを形成します。 このような各ペアは、回文に 2 つの文字を提供します。 
3. すべてのキャラクターにわたるそのようなペアをすべて収集して、使用可能なミラーリングされたペアのグローバル リストを作成します。 
4. ペアの合計数が少なくとも 50 の場合、ちょうど 50 ペアを取得します。 これらは回文の左半分を決定します。 次に、それらをミラーリングして右半分を形成します。 
5. 50 ペア未満の場合は、利用可能なすべてのペアを採用します。 左半分は各ペアの最初の要素を順番に取得することによって形成され、右半分は 2 番目の要素を反転することによって形成されます。 
6. ペアを形成した後に未使用の文字が残っている場合は、その 1 つを回文の中心として配置します。 
7. 結果のシーケンスを出力します。 

ペアリングが機能する理由は、すべての回文サブシーケンスが、互いに素な対称ペアと、オプションで 1 つの中心要素に分解できるためです。 任意のサブシーケンスを自由に選択できるため、ペアになった要素を削除しても他のペアの実現可能性が低下しないため、貪欲に極端なペアを作成しても将来の有効なペアがブロックされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    pos = [[] for _ in range(26)]
    
    for i, c in enumerate(s):
        pos[ord(c) - 97].append(i)
    
    pairs = []
    
    for i in range(26):
        arr = pos[i]
        l, r = 0, len(arr) - 1
        while l < r:
            pairs.append((arr[l], arr[r], i))
            l += 1
            r -= 1
    
    # sort pairs by left index to preserve order
    pairs.sort(key=lambda x: x[0])
    
    k = min(50, len(pairs))
    
    left = []
    right = []
    
    used = set()
    
    for i in range(k):
        l, r, c = pairs[i]
        left.append(chr(c + 97))
        right.append(chr(c + 97))
        used.add(l)
        used.add(r)
    
    # if we need center
    center = ""
    if len(pairs) < 50:
        # pick any unused character
        used_set = set()
        for i in range(len(s)):
            used_set.add(i)
        for u in used:
            used_set.discard(u)
        if used_set:
            center = s[next(iter(used_set))]
    
    print("".join(left + [center] + right[::-1]))

if __name__ == "__main__":
    solve()
```この実装では、最初に文字ごとにインデックスをグループ化し、利用可能なすべての出現を確実に把握します。 次に、ミラーリングされたペアの候補を外側から内側に構築します。左のインデックスで並べ替えることにより、ペアを選択するときにサブシーケンスの順序が有効なままであることが保証されます。 

の建設`left`そして`right`配列は回文の 2 つの半分をエンコードします。 回文は構造を反映しているため、右側は選択した文字を単に反転したものになります。 

センターの選択は、50 ペアに達しない場合にのみ重要になります。 その場合、未使用の文字がまだ残っている可能性があり、それらのいずれかが奇数長の回文の中央として機能する可能性があります。 

微妙な点は、ペアは常に左側のインデックスの増加と右側のインデックスの減少によって形成され、サブシーケンスの有効性が維持されるため、ペアリング後に順序付けの実行可能性を明示的にチェックする必要がないことです。

| ステップ | 選択されたペア | 左 | 右 |

### 例 2

 入力:```
abacabadabacaba
```a の位置は密であり、その他の位置は疎です。 「a」については多くのペアが得られ、「b」と「c」についてはいくつかのペアが得られます。 

アルゴリズムは、各文字ブロック内の極端な組み合わせを優先します。 

| ステップ | アクション | 左 | 右 |
 | --- | --- | --- | --- |
 | 1 | ペアa | ああ、ああ... | ああ、ああ... |

 ここでも 50 ペアに達するか、可能なペアをすべて使い果たすかのどちらかです。 

これは、アルゴリズムが文字の頻度だけではなく構造の可用性に純粋に基づいて適応することを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    s = input().strip()
    pos = [[] for _ in range(26)]
    for i, c in enumerate(s):
        pos[ord(c) - 97].append(i)

    pairs = []
    for i in range(26):
        arr = pos[i]
        l, r = 0, len(arr) - 1
        while l < r:
            pairs.append((arr[l], arr[r], i))
            l += 1
            r -= 1

    pairs.sort()
    k = min(50, len(pairs))

    left = []
    right = []
    used = set()

    for i in range(k):
        l, r, c = pairs[i]
        left.append(chr(c + 97))
        right.append(chr(c + 97))
        used.add(l)
        used.add(r)

    center = ""
    if len(pairs) < 50:
        for i in range(len(s)):
            if i not in used:
                center = s[i]
                break

    return "".join(left + [center] + right[::-1])

 ## 特殊なケース

 2 回出現する文字を除いて、すべての文字が 1 回だけ出現する場合、注意が必要なケースが発生します。 例えば、`abcdeffedxyz`スタイル入力。 このアルゴリズムは、繰り返された文字から 1 つのペアのみを形成し、実現可能性に応じて、他のすべてを中心または破棄として正しく配置します。 ペアリング ロジックにより、文字を使いすぎないようにすることができます。 

別のケースは、多くのペアがあるが 50 に達するのに十分ではない場合です。そのような場合、アルゴリズムは単純に利用可能なすべてのペアを使用して、可能な限り最大の回文を構築します。 各ペアは正確に 2 文字を提供し、中心は最大 1 つであるため、追加のチェックを必要とせずに構造は有効なままです。 

最後のエッジケースは、文字列に長さ 100 以上の完全な回文がすでに含まれている場合です。 その場合、少なくとも 50 の素なペアが存在し、アルゴリズムは自然にそれらのうち 50 を選択し、連続した構造を明示的に検索する必要なく、有効な長さ 100 の回文部分列を生成します。
