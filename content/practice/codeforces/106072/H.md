 ## 解決策
 ## 問題の理解

 すべての頂点が最初にそのインデックスに等しい個別のラベルを持つツリーが与えられます。 許可される唯一のアクションは、これらのラベルの一部を変更する単一のグローバル操作です。 

この操作では、まずツリー内の単純なパスを選択します。 次に、このパスに沿って、均等なサイズの頂点のマルチセットを選択し、選択した頂点のペア間でラベルを繰り返し交換します。 選択した要素間での交換は無制限であるため、パスの外側のすべての頂点は変更されないまま、選択した頂点の任意の置換を実現できるという効果があります。 

したがって、ツリーの最終的な構成は、1 つの単純なパスを選択し、その頂点の一部のサブセット間でラベルを並べ替え、他のすべては固定されたままにすることによって取得されます。 この方法でツリー全体の異なるラベルをいくつ作成できるかを数えるよう求められます。 

この制約では、テスト ケースごとに最大 3000 個の頂点、全体で合計 15000 個の頂点が許可されます。 これは、テスト ケースごとに 2 次に近い解は全体としては合格する可能性がありますが、テストごとに 3 次のアプローチは安全ではないことを直ちに示唆しています。 すべてのパスまたは頂点のすべてのサブセットを明示的に列挙する方法は、ツリー内の単純なパスの数がすでに 2 次であるため、遅すぎます。 

微妙な点は、パスとサブセットの異なる選択によって、最終的に同じ順列が生成される可能性があることです。 たとえば、単一の頂点に影響を与える置換は、その頂点を含む多くの異なるパスによって実現できます。 素朴なカウントオーバー操作は大幅にオーバーカウントしてしまうため、問題は基本的にどの順列がどのように生成されるかではなく、どのような順列が可能であるかを特徴づけることにあります。 

重要なエッジケースは、木が線である場合に現れます。 その場合、頂点のすべてのサブセットが何らかのパスに含まれるため、接続されたすべての間隔が順列に寄与します。 単純なパス列挙では、同じ最終的な置換を複数回オーバーカウントしてしまいます。 

## アプローチ

 最初の本能は、操作をシミュレートすることです。 すべてのパスについて、頂点のすべてのサブセットとそれらのサブセットのすべての順列が考慮されます。 これはすぐに実行不可能になります。 長さ k の固定パスの場合でも、サブセットの数は 2^k であり、順列により階乗増加が導入され、各パス内で指数関数的になります。 O(n^2) 個のパスがあるため、このアプローチは破綻します。 

構造の単純化は視点を逆転させることで実現します。 操作の観点から考えるのではなく、最終的な並べ替えに注目します。 この操作は 1 つの単純なパス上の頂点にのみ影響し、そのパス内では、選択した頂点間でラベルを任意に並べ替えることができます。 これは、最終的な置換の影響を受けるすべてのコンポーネントが完全に単純なパス上にあることを意味します。 

したがって、最終的な置換は次のように説明できます。 ツリーには単純なパスが存在し、ラベルが変更されるすべての頂点がそのパス上にあり、そのセット内で頂点が任意に並べ替えられます。 したがって、順列のサポートは、ツリー内の単純なパスのサブセットである必要があります。 

これは、すべての有効な結果は、S が単一の単純なパスに含まれるように頂点 S のセットを選択し、S のラベルを任意に並べ替えることによって決定されることを意味します。 |S| の場合 = k なら、k 個あります! そのセットの可能な順列。 

したがって、答えは頂点セットに関する純粋な組み合わせの合計になります。単純なパス上に完全に存在するすべての頂点サブセット S に対して、|S| を追加します。 答えに。 

ここで問題は、そのようなサブセットをすべて効率的にカウントすることになります。 サブセットは、誘導されたサブグラフがパスである場合に限り、単純なパス上にあります。これは、頂点がツリー内で接続されており、誘導された構造内のすべてのノードの次数が最大 2 であると言うのと同じです。もう 1 つの同等の特徴は、頂点がツリー内で単純なパス セグメントを形成するということです。

これにより、問題はツリー内のすべての単純なパスをカウントし、その長さに基づいて階乗重みを合計することに軽減されます。 エンドポイント u と v のペアごとに、それらの間のパスは一意であるため、(dist(u, v) + 1) を合計します。 すべての順序付けされていないペアと 1! に寄与する単一の頂点にわたって。 

ボトルネックは、各距離に存在するノードのペアの数をカウントすることです。 距離 d にあるペアの数がわかったら、それに (d + 1) を掛けます。 そして合計。 

すべてのペアの距離を直接計算すると、テストごとに O(n^2) となり、これは多くのテストの境界線に当たります。 代わりに、重心分解を使用して距離周波数を効率的にカウントします。 各重心で深度分布を計算してサブツリーにし、畳み込みを使用してそれらを結合し、サブツリー間のペアの寄与を蓄積します。

 ## アルゴリズムのチュートリアル

 (u, u) を含む、順序のない頂点のすべてのペアの合計として答えを再定式化します。 各ペアは (距離(u, v) + 1)! に寄与します。 

次に、重心分解を使用して距離の分布を計算します。 

1. 現在のツリーの重心を選択します。 この考え方は、パスが最初に重心によって分割されたときに、ノードのすべてのペアが 1 回だけカウントされるようにすることです。 
2. 重心から各サブツリーに DFS を実行し、各深さのノード数を記録します。 これらの深さのカウントは、重心からの距離を表します。 
3. 各重心で最初は空であるグローバル周波数配列 freq[d] を維持します。 サブツリーを処理するとき、その深さの分布と頻度を組み合わせて、パスが重心を通過するペアをカウントします。 現在のサブツリーの深さ a にあるノードと、すでに freq にある深さ b にあるノードの場合、それらの距離は a + b であるため、その距離に対する寄与を追加します。 
4. コントリビューションを処理した後、サブツリー分布を freq にマージし、将来のサブツリーがそれとペアになるようにします。 
5. すべてのサブツリーが処理された後、重心を削除した後に残った各サブツリーを再帰的に分解します。 

階乗重みは累積中に適用されます。距離 d でペアを識別するたびに、(d + 1) を追加します。 答えに。 単一ノードの貢献度は 1! これらは、freq を重心自体で初期化することによって自然に処理されます。 

### なぜ効果があるのか

 ノードの各ペアには、分解ツリー内で固有の最高重心があり、そこでパスが最初に異なるサブツリーに分割されます。 その重心では、1 つのエンドポイントは 1 つのサブツリーに存在し、もう 1 つは別のサブツリーに存在するため、これら 2 つの深さの寄与が結合されると、ペアは 1 回だけカウントされます。 距離は重心に対する深さの合計として保存されるため、計算は正確であり、再帰レベル全体でペアが二重にカウントされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

MOD = 998244353

# precompute factorials up to max n
MAXN = 3000
fact = [1] * (MAXN + 1)
for i in range(1, MAXN + 1):
    fact[i] = fact[i - 1] * i % MOD

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    removed = [False] * n
    sub_size = [0] * n

    def dfs_size(u, p):
        sub_size[u] = 1
        for v in g[u]:
            if v != p and not removed[v]:
                dfs_size(v, u)
                sub_size[u] += sub_size[v]

    def dfs_centroid(u, p, total):
        for v in g[u]:
            if v != p and not removed[v]:
                if sub_size[v] > total // 2:
                    return dfs_centroid(v, u, total)
        return u

    def dfs_depth(u, p, d, arr):
        arr.append(d)
        for v in g[u]:
            if v != p and not removed[v]:
                dfs_depth(v, u, d + 1, arr)

    ans = 0
    freq = {}

    def add_contrib(depths):
        nonlocal ans, freq
        for d in depths:
            for cd, cnt in freq.items():
                ans = (ans + cnt * fact[d + cd + 1]) % MOD

        for d in depths:
            freq[d] = freq.get(d, 0) + 1

    def decompose(root):
        dfs_size(root, -1)
        c = dfs_centroid(root, -1, sub_size[root])

        nonlocal freq
        freq = {0: 1}

        for v in g[c]:
            if removed[v]:
                continue
            depths = []
            dfs_depth(v, c, 1, depths)
            add_contrib(depths)

        removed[c] = True

        for v in g[c]:
            if not removed[v]:
                decompose(v)

    decompose(0)

    print(ans % MOD)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```すべてのペアの寄与は距離のみに依存するため、コードは階乗を事前計算します。 重心分解により、パスが重心サブツリー間で分割されるときに、ノードの各ペアが正確に 1 回カウントされることが保証されます。 

の`freq`ディクショナリには、現在の重心の以前に処理されたサブツリーからこれまでに検出された各深さのノードの数が格納されます。 新しい各サブツリーは、この構造に対するクロスペアに寄与し、周波数マップにマージされます。 

微妙な実装の詳細がリセットされています`freq`カウントはその分解レベルに対してローカルであるため、すべての重心で行われます。 もう 1 つの重要な詳細は、サブツリー ノードの深さが 1 から始まるのに対し、重心自体は深さ 0 として扱われることです。これにより、シングルトンの寄与が正確に考慮されます。`fact[1]`。

 ## 特殊なケース

 単一の頂点ツリーの場合、重心は頂点そのものです。 周波数マップは {0:1} で始まりますが、処理するサブツリーがないため、ペアの寄与は追加されません。 唯一の有効なサブセットは空の動きまたはシングルトン頂点であり、貢献度 1! = 1、アルゴリズムの初期化と一致します。 

線状のツリーの場合、重心を分割するたびに問題が左右のセグメントにきれいに分割されます。 中央でセントロイドを処理する場合、すべてのクロスサブツリー ペアが 1 回だけカウントされ、より深い再帰によってセグメント内の内部ペアが処理されます。 これにより、複数の重心レベルが存在する場合でも、ペアの欠落や重複がなくなります。 

星型ツリーの場合、中心はすぐに重心になります。 各リーフは深さ 1 で独立して寄与し、リーフのすべてのペアは重心の周波数の累積を通じて正確に 1 回カウントされます。
