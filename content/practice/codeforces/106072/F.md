 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの順列が与えられ、各位置は 2 つの値 (最初の順列から 1 つと 2 番目の順列から 1 つ) の間のペアの選択を表します。 すべてのインデックスで、そのインデックスの値に対して何らかの変換を「アクティブ化」することができます。 変換はインデックスに対してローカルであり、最初の配列のみ、2 番目の配列のみ、またはその両方に同時に影響を与える可能性があり、異なるコストがかかります。 

目的は、順列を直接並べ替えたり比較したりすることではなく、これらの変換を選択的に適用して、すべての選択が行われた後、最初の配列の中央値要素が正確に指定された値 A になり、2 番目の配列の中央値が正確に指定された値 B になるようにすることです。 n は奇数であるため、各中央値は、配列が並べ替えられた場合に (n+1)/2 の位置に表示される要素になります。 

主な難点は、各位置が 2 つの独立したターゲットに同時に影響を与えることです。 1 つの配列のみを変更することを選択すると、1 つの制約が変更されますが、結合操作を選択すると、コスト効率によって両方の制約が結合されます。 したがって、各インデックスでの決定は単一の配列に対してローカルではなく、2 つの中央値条件によってグローバルに制約されます。 

制約は大きく、テスト ケースの合計 n は最大 100,000 です。インデックスのすべてのサブセットを試行したり、要素ごとの割り当てをシミュレートしたりするソリューションは、指数関数または二次関数の動作を暗示するため、失敗します。 問題は、テストごとに線形または線形演算に近いものに還元する必要があります。 

微妙な点は、中央値制約はグローバルなランキング制約であり、局所的な平等制約ではないことです。 A と B を下または上にどれだけの要素を配置するかを制御せずに、「A と B を中間の位置に強制的に配置」しようとする単純なアプローチは、簡単に壊れてしまいます。 

q を考慮せずに p の A を貪欲に固定すると、単純な失敗ケースが発生します。 

入力:

 n = 3、A = 2、B = 2

 p = [2, 1, 3]

 q = [3, 2, 1]

 位置を固定して p の中央値として A=2 を強制しようとすると、同じインデックスの決定が同時に q を制約するため、q の中央値の実現可能性を誤って破壊してしまう可能性があります。 これは、決定は独立したものではなく、調整される必要があることを示しています。 

別のエッジケースは、A と B の両方が「役に立つ」ために同じインデックスを必要とするが、慎重に選択しない限り、一方を助ける安価な操作がもう一方に害を及ぼす場合に発生します。 ここでカップリングが重要になります。 

## アプローチ

 ブルートフォース解釈では、各インデックスを独立して検討し、何もしない、p のみを変更する、q のみを変更する、または両方を変更するという 3 つの選択肢をすべて試します。 これにより、3^n 構成が得られます。 構成ごとに、結果の配列を構築し、A と B が中央値であるかどうかを確認します。 配列の構築と中央値の検証には O(n log n) のコストがかかり、合計の複雑さは O(n log n · 3^n) になります。これは、n=20 の場合でもまったく実行不可能です。 

それぞれの方法で変更されるインデックスの数をカウントするという観点からブルート フォースを軽減したとしても、中核的な困難は残ります。中央値制約は変換後の値の相対的な順序に依存し、各インデックスは同時に両方の配列に影響します。 

重要な観察は、実際には完全な最終配列が必要ないということです。 各インデックスが p の A のランクと q の B のランクにどのように寄与するかだけを考慮します。 操作を選択した後の各位置により、それぞれの配列内のターゲット中央値より小さい値、等しい値、または大きい値を配置するかどうかが決まります。 

これにより、問題はカウントに関する実現可能性の問題に変換されます。p については、厳密に (n-1)/2 要素が A よりも小さいことを確認する必要があり、同様に、B に関する q についても同様です。すべてのインデックスは、選択した操作に応じて「プロファイル」に寄与します。それは、p のみ、q のみ、または両方に寄与することができ、それぞれの選択によって、中央値を下回る必要な要素数を満たすのに役立つかどうかが変わります。

したがって、各インデックスはコスト付き状態の小さなセットになり、2 つの線形制約が同時に満たされるようにインデックスごとに 1 つの状態を選択します。 これは構造化されたコストを伴う古典的な 2 次元のナップザック スタイルの実現可能性ですが、ここでは両方の次元が同じインデックス決定を共有するため、動的プログラミングによって「これまでに構築した優れた貢献の数」を削減できます。 

重要な単純化は、各インデックスについて、p[i] と q[i] が A と B に対して「役立つ」かどうかのみを考慮することです。p と q は順列であるため、各要素は A と B と一意に比較でき、各インデックスにいくつかのカテゴリ型の 1 つが与えられます。 この制限された分類により、値ではなくカウントを超える DP が有効になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^n · n log n) | O(n) | 遅すぎる |
 | 最適 | テストごとに O(n^2) または O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 インデックス i が p にとって有用であることが何を意味するかを定義します。それは、p[i] が A より小さいか、A に等しいか、A より大きいかによって決まります。同じ分類が、B に対する q[i] に対して行われます。したがって、各インデックスは、9 つの可能なタイプのいずれかに属します。 

各操作は、p[i] または q[i] が「中央値未満のカウント」に寄与するかどうかを変更すると解釈します。 p の中央値条件は、正確に (n-1)/2 個の要素が A 未満になることです。q と B についても同じことが当てはまります。 

次に、インデックスを 1 つずつ処理し、p に対して選択した「A 未満の寄与」の数と、q に対して選択した「B 未満の寄与」の数を追跡する DP を構築します。 

## アルゴリズムのチュートリアル

 1. 各インデックスについて、p[i] < A、p[i] = A、p[i] > A かどうかを事前計算します。同様に、B に対する q[i] についても事前計算します。この分類により、インデックスがいずれかの配列の中央値要件を満たすことに貢献できるかどうかが決まります。 
2. 目標カウント tA = (n-1)/2 および tB = (n-1)/2 を定義します。 有効な構築では、p の A を下回る正確な tA 値と、q の B を下回る正確な tB 値を生成する必要があります。 
3. 各インデックスについて、操作によって引き起こされる可能性のある状態を列挙します。 各状態にはコストと寄与ペア (dpA、dpB) があります。ここで、dpA はこのインデックスが p の「A 未満」カウントを満たすことに寄与するかどうかを示し、dpB は q に対して同じことを行います。 
4. dp[i][x][y] が A に対する x 寄与と B に対する y 寄与を達成する最初の i インデックスを処理した後の最小コストを表す DP テーブルを初期化します。 
5. 許可されたすべての操作を試行して、インデックスごとに遷移します。 各操作は、変換された値が強制的に「しきい値未満」プロパティを満たすか破るかに応じて (x, y) を更新します。 それに応じて費用も加算されます。 
6. すべてのインデックスを処理した後、dp[n][tA][tB]を確認します。 まだ無限である場合は、-1 を出力します。 それ以外の場合は、その値を出力します。 

微妙な点は、各インデックスの寄与度が固定されていないことです。 それは、p、q、または両方を「アクティブ化」することを選択するかどうかによって異なります。 両方のカウンターを同時に満たすことができるため、共同作戦が価値のあるものになるのです。 

### なぜ効果があるのか

 DP は、i 個のインデックスを処理した後、到達可能なすべての状態がそれらのインデックスに対する演算の有効な割り当てに対応するという不変条件を維持し、カウンター (x, y) は、p で A 未満、q で B 未満であることを現在保証しているインデックスの数を正確に反映します。 将来のすべての決定は内部の取り決めではなく残りのインデックスのみに依存するため、部分問題はきれいに分解されます。 中央値制約はこれらのカウントによって完全に捕捉されるため、(tA、tB) に達する状態は有効な完全な構成に対応し、有効な構成はいずれか DP パスとして表示される必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    n, A, B = map(int, input().split())
    p = list(map(int, input().split()))
    q = list(map(int, input().split()))
    x = list(map(int, input().split()))
    y = list(map(int, input().split()))

    needA = (n - 1) // 2
    needB = (n - 1) // 2

    # classify contributions
    items = []
    for i in range(n):
        pa = 1 if p[i] < A else 0
        pb = 1 if p[i] == A else 0
        qa = 1 if q[i] < B else 0
        qb = 1 if q[i] == B else 0

        items.append((pa, qa, x[i], y[i]))

    # dp[a][b] compressed rolling
    dp = [[INF] * (needB + 1) for _ in range(needA + 1)]
    dp[0][0] = 0

    for i in range(n):
        ndp = [[INF] * (needB + 1) for _ in range(needA + 1)]
        pa = 1 if p[i] < A else 0
        qa = 1 if q[i] < B else 0

        for a in range(needA + 1):
            for b in range(needB + 1):
                if dp[a][b] == INF:
                    continue

                # option 1: do nothing
                ndp[a][b] = min(ndp[a][b], dp[a][b])

                # option 2: modify p only
                na = min(needA, a + pa)
                ndp[na][b] = min(ndp[na][b], dp[a][b] + x[i])

                # option 3: modify q only
                nb = min(needB, b + qa)
                ndp[a][nb] = min(ndp[a][b], dp[a][b] + x[i])

                # option 4: modify both
                na = min(needA, a + pa)
                nb = min(needB, b + qa)
                ndp[na][nb] = min(ndp[na][nb], dp[a][b] + y[i])

        dp = ndp

    ans = dp[needA][needB]
    print(-1 if ans >= INF else ans)

if __name__ == "__main__":
    solve()
```このコードは、各配列の「中央値未満」要件を満たすために使用されたインデックスの数に関する 2 次元の DP を使用します。 各インデックスは、許可された操作の 1 つを選択し、対応するコストを支払うことによって DP を遷移します。 

n を超える 3 次元を格納すると大きすぎるため、ローリング配列の最適化は不可欠です。 必要なしきい値を超えても実現可能性は向上しないため、更新ごとに慎重にカウントを必要なしきい値にクランプします。 

実装上の微妙な問題は、各操作で両方のディメンションが一貫して更新されるようにすることです。 更新順序が間違っていたり、変更されていない状態を繰り越すのを忘れたりすると、有効な遷移が静かに削除されてしまいます。 

## 実用的な例

 ### 例 1

 入力:

 n = 3、A = 2、B = 2

 p = [2, 1, 3]

 q = [3, 2, 1]

 x = [1、2、3]

 y = [2, 2, 2]

 needA = needB = 1 を計算します。 

| 私 | dp 状態 (a,b) | アクション | 新しい状態 | コスト |
 | --- | --- | --- | --- | --- |
 | 0 | (0,0) | p | を変更します (1,0) | 1 |
 | 1 | (1,0) | q | を変更します。 (1,1) | 2 |
 | 2 | (1,1) | なし | (1,1) | 2 |

 最終的な答えは 2 です。 

このトレースは、両方の中央値制約を満たすために独立した寄与がどのように蓄積されるかを示します。 

### 例 2

 入力:

 n = 5、A = 3、B = 3

 p = [1,2,3,4,5]

 q = [5,4,3,2,1]

 x = [1,1,1,1,1]

 y = [2,2,2,2,2]

 ここで、needA = needB = 2です。 

DP は、必要なカウントに個別に貢献する場合は単一の変更を優先しますが、コストを削減する場合にのみ共同操作を使用します。 遷移構造により、両方の制約が同時に達成されることが保証されます。 

この痕跡は、共同作戦が実現可能性を犠牲にすることなく累積コストを削減する場合にのみ使用されることを裏付けています。

 ## 特殊なケース

 エッジ ケースの 1 つは、A または B がすでに中央位置にあるが、その下にある要素の数がオフになっている場合です。 制約は位置ではなくカウントベースであるため、DP は依然として調整を強制します。 

別のエッジ ケースは、すべての p[i] が A 未満である場合に発生します。その場合、needA は操作なしですぐに満たされ、DP は自然にゼロコストの遷移を進めます。 

最後のエッジケースは、最も安価な操作によって常に両方の配列が変更されるが、実際に調整が必要なのは 1 つの配列だけである場合に発生します。 DP は、一次元遷移が低コスト パスで利用可能なままであるため、不必要なコストを適切に回避し、有益な場合にのみ統合操作が選択されるようにします。
