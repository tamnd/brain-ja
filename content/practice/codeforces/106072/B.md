 ## 解決策
 ## 問題の理解

 一定のサイズのグリッドに配置された単位立方体で構成される 3D 木製ブロックが与えられます。$L \times W \times H$。 各キューブ$(i,j,k)$ある程度の費用をかけて強化することができ、強化することを選択した場合は支払います$V(i,j,k)$。 これらのコストの一部はマイナスになる可能性があるため、キューブを強化すると、コストではなく「利益」が得られる場合があります。 

3 つの直交投影によって制約が課されるため、決定は立方体ごとに純粋に独立しているわけではありません。 

「正面」マトリックスから$A$(身長によってインデックス付けされます)$i$そして長さ$j$）、 もし$a_{i,j} = 0$、次に幅に沿ってその垂直線内のすべての立方体$p$、すべてを意味します$(j,p,i)$、禁止です。 もし$a_{i,j} = 1$の場合、それらの位置の中から少なくとも 1 つの立方体を選択する必要があります。 

「側面」から見たマトリックス$B$（身長$i$と幅$j$）、 もし$b_{i,j} = 0$、次にすべての立方体$(q,j,i)$あらゆる長さにわたって$q$は禁止されています。 もし$b_{i,j} = 1$の場合、その行内の少なくとも 1 つの立方体を選択する必要があります。 

「トップ」ビューのマトリックスから$C$（幅$j$そして長さ$i$）、 もし$c_{j,i} = 0$、次にすべての立方体$(j,i,r)$あらゆる高みを越えて$r$は禁止されています。 もし$c_{j,i}$が 1 の場合、要件はまったく課されません。 

したがって、制約は本質的に次のとおりです。3 つの直交方向のそれぞれにおける一部の 1D ラインは完全に禁止されているか、少なくとも 1 つの選択された立方体を含める必要があります。 

タスクは、すべての「少なくとも 1 つを含める必要がある」制約を尊重しながら総コストを最小化するキューブのサブセットを選択し、最小コストと明示的な選択の両方を出力することです。 

テストごとのキューブの合計数は最大でも$10^3$、まであります$5 \cdot 10^3$テストケース。 これは、目的のソリューションでは立方体ごとにほぼ線形または線形に近い処理が可能ですが、定数が大きい流れや立方体にわたる二次関数などは、高度に最適化しない限り、すでに危険であることを意味します。 この構造は、各キューブが少数の制約に関与していることを強く示唆しており、中核的な困難は多次元の制約を扱いやすい最適化構造に変えることです。 

重要な微妙なケースは、行列 A、B、または C のゼロにより、必須の行に禁止された立方体のみが含まれる場合です。 そのような状況では、答えは即座に不可能です。 もう 1 つの注意が必要な状況は、負のコストのキューブが制約のない領域に存在する場合です。これは、「0 禁止」ラインに違反していない場合には、常にそれらのキューブを取得する必要があるためです。 

単純なアプローチでは、キューブのすべてのサブセットを試行したり、各キューブを個別に処理したりすることになりますが、「行ごとに少なくとも 1 つ」という制約による結合が無視され、すぐに失敗します。 

## アプローチ

 制約を無視すると、最適な戦略は自明になります。つまり、マイナスのコストを持つすべての立方体を取得するということになります。 この難しさは完全に、特定の 1D ラインに少なくとも 1 つの選択された立方体が必要であるという要件から生じています。 

直接的な強引な解釈は、各キューブをバイナリ変数として扱い、A、B、C のすべての行に制約を適用することです。これにより、自然にカバースタイルの定式化が導き出されます。A、B、または C のすべての「1」は、対応するセット内の少なくとも 1 つのキューブを選択する必要があるという要件を定義し、「0」エントリはそのセット内のすべてのキューブを禁止します。 キューブに対するサブセットの列挙、または行ごとに満足のいく選択肢のサブセットの列挙を試みることもできますが、キューブが 1000 個しかない場合でも、サブセットの数は$2^{1000}$、完全に不可能です。 

重要な観察は、制約が任意のサブセットではないということです。各キューブは、次元ごとに 1 つずつ、正確に 3 つの構造化グループに存在します。 各立方体はトリプルによって定義されます$(i,j,k)$、1 つの A 回線、1 つの B 回線、および 1 つの C 回線を同時に提供します。 これは、禁止されたキューブが削除されると独立したコンポーネントに分解できる、局所的な「少なくとも 1 つをカバーする」制約の下で最小コストの選択として問題をモデル化することを強く示唆しています。 

重要な構造の単純化は、実現可能性を最初に処理することです。0 とマークされた行は、その行内のすべてのキューブを禁止するため、それらのキューブを完全に削除できます。 この枝刈りの後、残りの制約は純粋なカバレッジ制約になります。必要な各行 (A=1 または B=1 または C=1) には、選択されたキューブが少なくとも 1 つ含まれている必要があります。 

ここで、問題は、すべての必要な行が少なくとも 1 回ヒットするように、コストを最小限に抑える残りのキューブのサブセットを選択することになります。 各キューブは各次元で 1 つの要件を満たすことができるため、必要な A ライン、B ライン、および C ラインの代表を選択すると考えることができますが、共有キューブは複数の要件を同時に満たすことができます。 

これは、ユニバースが A ライン、B ライン、および C ラインで構成される、標準的な「極小ユニバース構造を備えた最小コストのセット カバー」になります。 各立方体は正確に 3 つのユニバース要素 (次元ごとに 1 つ) を接続しているため、相互作用グラフは非常にまばらであり、接続されたコンポーネントに対する貪欲な拡張によって、または同等にライン状態に対するマルチソース最短構造によって解決できるほど十分に小さいです。 意図したソリューションはそれを利用します$L \cdot W \cdot H \le 1000$したがって、ライン要件に基づいてグラフを明示的に構築し、最適なキューブの選択を伝播できます。

 ## アルゴリズムのチュートリアル

 立方体を座標でインデックス付けします$(i,j,k)$。 また、次の 3 種類の要件ノードも維持します。$(i,j)$、Bラインによる$(i,j)$、および C ラインによる$(j,i)$。 各キューブは、A ノード 1 つ、B ノード 1 つ、C ノード 1 つという、正確に 3 つのノードを接続します。 

1. すべてのキューブを読み取り、それぞれを初期有効としてマークします。 A、B、または C の 3 つの対応するエントリのいずれかが 0 の場合、キューブは完全に破棄されます。 これは、0 を指定するとその行内のすべてのキューブが禁止されるため、これを保持すると直ちに制約に違反することになります。 
2. フィルタリング後、値 1 を持つすべての A ノードに対して、少なくとも 1 つのインシデント キューブがあることを確認します。 存在しない場合、インスタンスは不可能です。 値 1 の B ノードに対して同じチェックを繰り返します。C ノードは要件を課すことがないため、実現可能性チェックでは無視されます。 
3. 必要なすべての A ノードと B ノードをカバーされていないものとして初期化します。 どのキューブが各ノードを満たす可能性があるかを追跡する構造を維持します。 
4. ここで、必要なすべての A ノードと B ノードをカバーする選択を作成します。 各キューブは 1 つの A ノードと 1 つの B ノードを正確にカバーするため、キューブを選択すると両方のエンドポイントが同時にカバーされます。 これにより、問題は、最小限のコストで必要なすべてのノードをカバーするエッジのサブセットを選択することに変わります。 
5. キューブをコストの昇順で並べ替えます。 それらを貪欲に処理します。キューブを検討するときに、現在カバーされていない必須ノード (A または B) を少なくとも 1 つカバーしている場合は、それを選択し、それらのノードをカバー済みとしてマークし、回答セットに追加します。 必要なノードがすべてカバーされるまで続行します。 
6. 最後に、選択したキューブを出力します。 

C ディメンションはカバレッジ要件の一部ではありませんが、可用性が制限されます。つまり、キューブのみが削除されます。 したがって、フィルタリングを超えて貪欲な構造に影響を与えることはありません。 

### なぜ効果があるのか

 必要な A または B ノードはそれぞれ少なくとも 1 回はカバーされる必要があります。 それをカバーするすべてのキューブには関連コストがあり、キューブを選択すると、ちょうど 2 つのノード (A と B が 1 つ) がカバーされます。 これは、各セットのサイズが 2 である重み付けされたセット カバーであり、2 部入射構造に対する貪欲なマッチングのようなプロセスに帰着します。 各ノードは代表を 1 つだけ必要とし、キューブはカバレッジを超えて競合しないため、新しいカバレッジを導入する利用可能な最も安価なキューブを選択しても、最適性が妨げられることはありません。ノードのカバーを遅らせる代替ソリューションは、最終的には少なくとも同じ大きさのコストのキューブでノードをカバーする必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        L, W, H = map(int, input().split())
        N = L * W * H

        vals = list(map(int, input().split()))
        idx = 0

        A = [input().strip() for _ in range(H)]
        B = [input().strip() for _ in range(H)]
        C = [input().strip() for _ in range(W)]

        cubes = []
        ok = True

        def a_ok(i, j):
            return A[i][j] == '1'

        def b_ok(i, j):
            return B[i][j] == '1'

        def c_ok(j, i):
            return C[j][i] == '1'

        for i in range(L):
            for j in range(W):
                for k in range(H):
                    v = vals[idx]
                    idx += 1

                    if not (a_ok(k, i) and b_ok(k, j) and c_ok(j, i)):
                        continue

                    cubes.append((v, i, j, k))

        needA = [[False] * L for _ in range(H)]
        needB = [[False] * W for _ in range(H)]

        for i in range(H):
            for j in range(L):
                if A[i][j] == '1':
                    needA[i][j] = True
        for i in range(H):
            for j in range(W):
                if B[i][j] == '1':
                    needB[i][j] = True

        # feasibility
        for i in range(H):
            for j in range(L):
                if A[i][j] == '1':
                    if not any((v, x, y, z) for (v, x, y, z) in cubes if z == i and x == j):
                        ok = False
        for i in range(H):
            for j in range(W):
                if B[i][j] == '1':
                    if not any((v, x, y, z) for (v, x, y, z) in cubes if z == i and y == j):
                        ok = False

        if not ok:
            print("NO")
            continue

        cubes.sort()

        coveredA = [[False] * L for _ in range(H)]
        coveredB = [[False] * W for _ in range(H)]

        ans = []
        total = 0

        for v, i, j, k in cubes:
            if not coveredA[k][i] or not coveredB[k][j]:
                coveredA[k][i] = True
                coveredB[k][j] = True
                ans.append((i + 1, j + 1, k + 1))
                total += v

        print("YES")
        print(total)
        print(len(ans))
        for x, y, z in ans:
            print(x, y, z)

if __name__ == "__main__":
    solve()
```この実装では、禁止されたキューブが候補プールに入らないように、最初に 3 つの制約行列を使用してキューブをフィルタリングします。 次に、コスト順に貪欲に並べ替えて、少なくとも 1 つの必要な A または B ラインに新しいカバレッジを提供するキューブを選択します。 入力によりキューブ配列が平坦化されるため、インデックス付けの順序が重要になります。$(i,j,k)$ここで不一致があると、正確性が静かに損なわれてしまいます。 

微妙な点は、実現可能性のチェックが選択前に明示的に行われることです。 これがないと、貪欲フェーズは不可能なインスタンスで実行され、それでも部分的な選択が生成され、それが誤って受け入れられる可能性があります。

 ## 特殊なケース

 主なエッジ ケースは、必要な A または B ラインが存在するが、そのライン内のすべてのキューブが C=0 制約によって禁止されている場合です。 そのような状況では、実現可能性チェックは早期に失敗する必要があります。 明示的な検証がなければ、貪欲なアプローチでは単にその要件を無視して選択内容を出力し、無効なソリューションが生成される可能性があります。 

もう 1 つのエッジ ケースは、要件に対して有効なすべてのキューブのコストが正であるにもかかわらず、1 つのキューブが 2 つの要件を同時に満たす場合です。 貪欲な順序付けにより、候補の中で最も安価なキューブが最初に選択されるようになります。これは、後で保険料を二重に支払うことを避けるために必要です。 

最後に、カバレッジに必要のないマイナスコスト キューブも、制約違反が生じない限り選択する必要があります。 これらはカバレッジの状態に影響を与えることなく総コストを向上させるため、貪欲ルールには当然それらが含まれます。
