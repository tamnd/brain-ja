 ## 解決策
 ## 問題の理解

 物理実験の測定結果のリストが与えられます。 Vasya はできるだけ多くの測定値を保持したいと考えていますが、残りのセットは 1 つの条件を満たす必要があります。それは、最大の残りの値が最小の残りの値の 2 倍を超えてはいけないということです。 

タスクは、残りの数値が次を満たすように、最小数の測定値を削除することです。$y \le 2x$どこ`x`は最小残存値であり、`y`残りの最大値です。 

この問題を考えるもう 1 つの方法は、最大値が最小値の 2 倍以下であるすべてのサブセットの中から、可能な最大のサブセットを見つけることです。 保持できる測定値の最大数がわかれば、答えは簡単です。`removed = n - kept`入力サイズが到達しました`10^5`、これは二次解を即座に除外します。 すべての境界のペアを個別にチェックし、配列全体を再度スキャンするアプローチは、次のようなパフォーマンスを発揮します。`10^10`最悪の場合、制限時間を大幅に超えて操作が行われる可能性があります。 周りに何かが必要です`O(n log n)`または`O(n)`並べ替え後。 

値自体はせいぜい小さいです`5000`、 しかし`n`は十分に大きいため、要素の数に応じて適切に拡張できるアルゴリズムに引き続き焦点を当てる必要があります。 

見落としやすいエッジケースがいくつかあります。 

すべての値がすでに有効である配列を考えてみましょう。```
5
2 2 3 4 4
```正しい答えは、`0`なぜなら最大の値は`4`そして最小のものは`2`、 それで`4 ≤ 2 * 2`。 

不注意な実装では、削除する必要がないにもかかわらず、常にウィンドウを不必要に縮小し、要素を削除しようとする可能性があります。 

もう 1 つの注意が必要なケースは、境界の周囲に重複が表示される場合です。```
6
1 2 2 2 4 4
```配列全体が無効であるため、`4 > 2 * 1`。 ただし、のみを削除した後、`1`の場合、残りの配列が有効になります。 正しい答えは、`1`。 

2 ポインタの実装が正しくないと、左ポインタが激しく移動しすぎて、最適なウィンドウを見逃す可能性があります。 

3 番目に重要なケースは、最小サイズの入力です。```
2
1 5000
```残りの有効なサブセットのみがサイズを持つ`1`、 以来`5000 > 2`。 答えは`1`。 

これにより、少なくとも 2 つの要素が残らなければならないと想定する実装が捕捉されます。 

## アプローチ

 配列がソートされれば、総当たりのアイデアは簡単です。 インデックスで残りの最小値を固定するとします。`i`。 次に、考えられるすべての終了インデックスを試してみます。`j ≥ i`そして、次のことを確認してください。$a_j \le 2a_i$条件が成立する場合、次の部分配列が`i`に`j`は、並べ替えにより、それらの間のすべての要素も同じ範囲内にあることが保証されるため、有効です。 

これが機能するのは、最適な解は常にソートされた順序で連続したセグメントとして表現できるためです。 価値観を守るなら`3`そして`7`、値を除外することはありません`5`並べ替えた後、それらの間に座っています。 

ブルートフォースメソッドはすべてをチェックします`O(n^2)`ペア`(i, j)`。 と`n = 10^5`、これはおおよそになります`10^10`チェックが遅すぎます。 

重要な観察は、配列がソートされると、固定された左端点の有効範囲が単調に拡大するということです。 窓なら`[l, r]`有効であり、その後増加します`r`最終的には状態が崩れるかもしれないが、減少する`r`決して傷つきません。 

この単調な構造は、まさに 2 つのポインターが設計されているものです。 

引き違い窓を維持しております`[l, r]`ソートされた配列に対して。 あらゆる人にとって`r`、私たちは移動します`l`条件に違反している間のみ前進します。 その時点で、現在のウィンドウは、次で終わる最大の有効なセグメントになります。`r`。 

各ポインターは前方にのみ移動するため、ソート後の合計作業量は直線的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力配列を読み取り、並べ替えます。 

並べ替えは、最大値が最小値の 2 倍以下である最長の連続セグメントを見つけるという問題に変換します。 
2. 2 つのポインタを初期化します。 

させて`l = 0`。 繰り返していきます`r`左から右へ。 
3. それぞれについて`r`、ウィンドウの右側を展開します。 

現在のウィンドウは`[l, r]`。 
4. ウィンドウが無効な間に移動します。`l`フォワード。 

次の場合、ウィンドウは無効になります。$a_r > 2a_l$配列はソートされているので、増加します`l`ウィンドウの最小値が増加し、条件が満たされやすくなります。 
5. 有効性を復元した後、ウィンドウ サイズを計算します。 

現在の有効なセグメント長は次のとおりです。```
r - l + 1
```これまでに確認された最大有効長を追跡してください。 
6. すべての位置を処理した後、次のように出力します。```
n - maximum_valid_length
```これは必要な削除の最小数です。 

### なぜ効果があるのか

 ソート後、すべての有効な解は連続した部分配列に対応します。 保持されている 2 つの要素が条件を満たしている場合、並べ替え順序によって範囲が保持されるため、それらの間のすべての値も自動的に条件を満たします。 

スライディング ウィンドウは、現在のセグメントの不変条件を維持します。`[l, r]`内側のループが終了した後は常に有効です。 右端ごとに`r`、アルゴリズムは可能な限り最小のものを見つけます`l`これによりセグメントが有効に保たれ、次で終わる最大の有効ウィンドウも得られます。`r`。 

スキャン中に考えられるすべての最適なセグメントが何らかのウィンドウとして表示されるため、アルゴリズムは最良の答えを見逃すことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    l = 0
    best = 0

    for r in range(n):
        while a[r] > 2 * a[l]:
            l += 1

        best = max(best, r - l + 1)

    print(n - best)

solve()
```最初のステップでは、測定値を並べ替えます。 ソートを行わないと、選択した要素の連続性を維持しながら、候補セグメントの最小値と最大値を維持する効率的な方法がありません。 

左のポインタ`l`前に進むだけです。 これは効率にとって重要です。 逆方向に移動できれば、ソート後の複雑さは線形ではなくなります。 

内部の状態は、`while`ループは厳密です:```
a[r] > 2 * a[l]
```使用する`>=`平等は許されるので、ここでは間違っています。 例えば、`[2, 4]`有効です。 

ウィンドウ サイズは次のように計算されます。```
r - l + 1
```クラシックなオフバイワンのディテールです。 両方のエンドポイントが現在のセグメントに含まれています。 

最終的な答えは、測定値の合計数から、保持されている最大の有効なセグメントを減算します。

# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    l = 0
    best = 0

    for r in range(n):
        while a[r] > 2 * a[l]:
            l += 1

        best = max(best, r - l + 1)

    print(n - best)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    return sys.stdout.getvalue()

# provided sample

# minimum size

assert run("4\n2 4 4 4\n") == "0\n", "equality allowed"

 ## 特殊なケース

 等価境界の場合を考えてみましょう。```
4
2 4 4 4
```ソート後も配列は変わりません。 いつ`r`最初に到達する`4`、チェックされた条件は次のとおりです。```
4 > 2 * 2
```これは次のようになります。```
4 > 4
```これは false なので、ウィンドウは有効なままです。 アルゴリズムはすべての要素と出力を正しく保持します`0`。 

次に、極端な不一致の場合を考えてみましょう。```
2
1 5000
```で`r = 1`、条件は次のようになります。```
5000 > 2
```それは本当なので、`l`に進みます`1`。 有効なウィンドウは次のようになります。`[5000]`サイズ付き`1`。 アルゴリズムの出力`2 - 1 = 1`。 

最後に、境界付近で繰り返される要素を考慮します。```
6
1 2 2 2 4 4
```いつ`r`最初に到達する`4`、現在の最小値`1`次の理由により動作しなくなりました。```
4 > 2
```アルゴリズムが進化する`l`一度、最小値を作成します`2`。 条件は次のようになります。```
4 > 4
```これは false なので、大きな有効ウィンドウが保持されます。 これにより、スライディング ウィンドウが必要なだけ縮小することが確認され、これは最適化にとって不可欠です。
