 ## 解決策
 ## 問題の理解

 時間の経過とともにタスクを受信するシングルスレッド プリンターをシミュレートしています。 各タスクは指定された時間に到着し、既知のページ数と、複数のタスクが待機しているときに処理される順序を決定する優先順位を持っています。 優先度の高いタスクは、優先度の低いタスクより優先されます。 問題は、ちょうど 1 つのタスクの優先順位が欠落していることです。 代わりに、このタスクの印刷がいつ終了するかを知ることができます。 

目標は 2 つあります。1 つ目は、不明な優先順位を推定すること、2 つ目は、優先順位が欠落しているタスクを含むすべてのタスクの正確な終了時間を決定することです。 プリンターは 1 秒あたり 1 ページを正確に印刷し、タスクは到着するとすぐにキューに入ります。 

制約はかなり大きい。 最大 50,000 個のタスクを含めることができ、各タスクは非常に大きくなる可能性があります (ページ数は最大 10^9、時間は最大 10^9、終了時間は最大 10^15)。 これにより、単純なアプローチでは最悪の場合、最大 10^15 秒繰り返してしまう可能性があるため、タイムライン全体にわたる強引な 1 秒ごとのシミュレーションが即座に除外されます。 代わりに、出力される合計秒数ではなく、タスクの数に複雑さが依存するアプローチが必要です。 

微妙な落とし穴があります。 たとえば、複数のタスクが同時に到着した場合、最も優先度の高いタスクが最初に選択される必要があります。 到着順序の管理を誤ると、終了時間が不正確になる可能性があります。 もう 1 つの罠は、未知のタスクが常に最後に完了すると想定していることです。 実際には、その優先度が一部の既知のタスクよりも低い場合、後から到着するタスクによって先取りされる可能性があります。 

## アプローチ

 ブルートフォース ソリューションでは、不足しているタスクに対して考えられるすべての優先順位を試し、プリンターを秒単位でシミュレートし、どの優先順位が観察された終了時間につながるかを確認します。 プリンタのシミュレートは簡単であるため、ブルート フォースが機能します。待機中のタスクの優先キューを保持し、毎秒最も優先度の高いタスクを選択し、残りのページを減分し、完了したときに記録します。 しかし、タイムラインが 10^15 秒に達する可能性があるため、これは失敗します。 一度に 1 秒ずつ繰り返すことは不可能です。 

重要な洞察は、プリンターの動作はタスクが到着したとき、またはタスクが終了したときなど、不連続な瞬間にのみ変化するということです。 その間の秒数をシミュレートする必要はありません。 待機中のタスクの優先キューを維持し、次の関連イベントまで時間を進めることで、終了時間を効率的に計算できます。 このシミュレーション関数が存在すると、未知のタスクの考えられる優先度の値に対して二分探索を実行できます。 候補の優先順位が未知のタスクの所定の終了時間をもたらすかどうかを確認し、それに応じて検索を調整します。 

これを高速化する秘訣は、優先順位の相対的な順序のみを考慮していることを認識することです。 したがって、他のタスクによってまだ取得されていない値の間でのみ検索できます。 優先キューにヒープを使用すると、挿入と抽出が対数的に維持され、全体として O(n log n log U) のソリューションが得られます。ここで、U は未知のタスクの可能な優先順位の数です。 これは、n = 50,000 および U が 10^9 までの場合に実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(T * n) | O(n) | 遅すぎると、T は 10^15 に達する可能性があります |
 | シミュレーション + 二分探索 | O(n log n log U) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべてのタスクをリストに読み込み、優先度が不明なタスクを分離します。 到着時刻、ページ数、既知の優先度または未知のタスクのプレースホルダーを保存します。 不明なタスクの目標終了時刻も記録します。 
2. すべての既知の優先順位のセットを構築します。 これにより、既存のタスクと衝突しない未知のタスクの優先順位の候補を選択することができます。 
3. シミュレーション機能を実装します。 プリンターが常にキューから最も優先度の高いタスクを選択できるように、優先度によってキー設定された最小ヒープ (または慣例に応じて最大ヒープ) を初期化します。 現在時刻へのポインタを保持します。 重要な最適化はイベント駆動型のシミュレーションです。次のタスクの到着または現在のタスクの次のページの完了までの時間を進めます。 
4. 不明なタスクの優先度の候補ごとに、それを割り当ててシミュレーションを実行します。 シミュレーション中、タスクが完了するたびに、その終了時間を記録します。 未知のタスクが目標時間に終了すれば、正しい優先度が見つかったことになります。 
5. 優先順位は 10^9 までの異なる整数であるため、まだ使用されていない優先順位の実行可能な範囲にわたって二分探索を実行します。 シミュレーションを実行するたびにブール値が得られます。この優先順位によって目標の終了時間が得られるかどうかを確認します。 それに応じて検索を絞り込みます。 
6. 正しい優先順位が特定されたら、シミュレーションを再実行して、すべてのタスクの正確な終了時間を取得します。 決定した優先度と終了時刻をタスクを入力した順に出力します。 

機能する理由: このアルゴリズムは、印刷を待機しているタスクの優先キューを維持します。 不変条件は、キュー内で最も優先度の高いタスクが常に印刷されるタスクであるということです。 離散イベント シミュレーションでは、タスクがスキップされず、ルールに従ってタスクが選択されることが保証されるため、計算された終了時間はプリンターが生成する時間と正確に一致します。 二分探索により、不足しているタスクの既知の終了時間を正確に満たす優先度が確実に見つかります。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

def simulate(tasks, unknown_idx, unknown_priority):
    n = len(tasks)
    events = sorted([(t, i) for i, (t, _, _) in enumerate(tasks)])
    finish_times = [0] * n
    waiting = []
    time = 0
    task_pages = [s for _, s, _ in tasks]
    
    if unknown_idx != -1:
        tasks[unknown_idx] = (tasks[unknown_idx][0], tasks[unknown_idx][1], unknown_priority)
    
    i = 0
    while i < n or waiting:
        if not waiting:
            time = max(time, events[i][0])
        
        while i < n and events[i][0] <= time:
            idx = events[i][1]
            _, _, prio = tasks[idx]
            heapq.heappush(waiting, (-prio, idx))
            i += 1
        
        prio, idx = heapq.heappop(waiting)
        task_pages[idx] -= 1
        time += 1
        if task_pages[idx] == 0:
            finish_times[idx] = time
    
    return finish_times

def main():
    n = int(input())
    tasks = []
    unknown_idx = -1
    used_priorities = set()
    
    for idx in range(n):
        t, s, p = map(int, input().split())
        tasks.append([t, s, p])
        if p == -1:
            unknown_idx = idx
        else:
            used_priorities.add(p)
    
    target_time = int(input())
    
    low, high = 1, 10**9
    result_priority = -1
    while low <= high:
        mid = (low + high) // 2
        if mid in used_priorities:
            if mid == 10**9:
                mid -= 1
            else:
                mid += 1
        finish_times = simulate([list(task) for task in tasks], unknown_idx, mid)
        if finish_times[unknown_idx] == target_time:
            result_priority = mid
            break
        elif finish_times[unknown_idx] < target_time:
            low = mid + 1
        else:
            high = mid - 1
    
    finish_times = simulate([list(task) for task in tasks], unknown_idx, result_priority)
    
    print(result_priority)
    print(' '.join(map(str, finish_times)))

if __name__ == "__main__":
    main()
```コードでは、アイドル状態の秒数を不必要にシミュレートしないように、イベント駆動型シミュレーションを慎重に処理します。 到着時間が同じタスクは、同じ反復でヒープにプッシュされます。 優先キューにより、不明なタスクが挿入された場合でも、常に正しいタスクが印刷されます。 二分探索は、まだ使用されていない値に制限されます。
