 ## 解決策
 ## 問題の理解

 文字の長方形グリッドが与えられ、各セルには小文字の英字が含まれています。 このタスクは、同時に 2 つのプロパティを持つ軸に沿った部分四角形がいくつあるかを数えるというものです。 

まず、選択した長方形の 4 隅を見ると、4 隅の文字がすべて同一である必要があります。 次に、その四角形内の文字が含まれるセルの数を数えると、`'a'`、この数は指定された制限を超えてはなりません`k`。 

部分四角形は、少なくとも 4 セルの領域を持つ空ではない四角形となるように、通常の順序制約を使用して上の行、下の行、左の列、および右の列を選択することによって完全に決定されます。 

制約`n, m ≤ 400`行に対する二次または三次の解は受け入れられるが、すべての四角形を直接試行するものは失敗することを即座に示唆します。 部分長方形の数だけでも、$n^2 m^2$、それは約です$400^4 = 2.56 \cdot 10^{10}$、大きすぎます。 

これにより、各四角形が独立して処理されないよう、問題の構造を縮小する必要があります。 代わりに、同じ行または列のペアを共有する多くの四角形にわたって計算を再利用する必要があります。 

素朴だが重要な観察は、「最大で k`'a'`「セル」条件は、プレフィックス合計を使用して効率的に行うことができます。さらに難しいのは、すべての四角形を明示的にチェックする必要がない方法で「四隅すべてが等しい」条件を強制することです。 

いくつかの特殊なケースは、落とし穴を明確にするのに役立ちます。 

グリッドが完全に埋まっている場合は、`'a'`そして`k = 0`の場合、すべての四角形には次の要素が含まれるため、面積が 1 を超える四角形は無効になります。`'a'`everywhere, so the answer is zero. A naive solution might still count many rectangles just because corners match, ignoring the interior constraint.

 もし`k`とても大きいです、と言うと`k = n*m`の場合、角が等しいすべての四角形が有効になるため、問題は角の文字が等しい四角形のみを数えるということになります。 をハードコーディングするソリューションは、`'a'`コーナーを個別に処理するのではなくフィルタリング コーナーに制約すると、正しく単純化できなくなります。 

もし`n = 2, m = 2`、長方形が 1 つだけ存在します。 4 つの文字がすべて等しく、次の数が等しい場合にのみ有効です。`'a'`cells is within the limit. これは、両方の制約が同じ四角形に対してグローバルであり、コーナーごとまたは行ごとに独立してチェックするのではなく、同時にチェックする必要があることを強調しています。 

## アプローチ

 直接的なブルート フォース ソリューションでは、上下の行と左右の列のすべての選択肢が列挙されます。 各長方形について、四隅の文字をチェックしてカウントします。`'a'`事前に計算されたプレフィックス合計行列を使用するセル。 これは正しく、プレフィックスの合計によって各四角形が O(1) チェックされます。 ただし、$O(n^2 m^2)$長方形なので、全体の複雑さは次のようになります。$O(n^2 m^2)$が遅すぎる$n = m = 400$。 

効率を高める重要な構造は、最初に上部と下部の行を固定することです。 これら 2 つの行が固定されると、すべての列を 2 つの情報で要約できます。これら 2 つの行の文字が一致するかどうか (これは、その列を使用する有効な四角形の角に必要です)、および文字の数です。`'a'`文字はその列の 2 つの行の間にあります。 これにより、2D 長方形の問題が列に関する 1D 問題に縮小されます。 

行の固定ペアの場合、有効な四角形は 2 つの列を選択することに対応します。$l < r$両端の文字が両方の行で等しく、合計数が`'a'`これらの行と列の間の部分行列内のセルは最大でも`k`。 2 番目の条件は、列の重みの 1 次元配列に対する古典的な 2 ポインターの問題になります。 

微妙なのは、コーナー均等制約が文字に依存することです。 長方形は、4 つの角すべてが同じ文字を共有する場合にのみ有効です。つまり、選択された両方の列が両方の固定行で同じ文字を持つ必要があります。 これにより、列が文字ごとに自然にグループに分割され、各グループ内でスライディング ウィンドウを使用して有効な部分配列がカウントされます。`'a'`貢献。 

これにより、長方形の列挙から処理までの問題が軽減されます。$O(n^2)$行ペア、それぞれ$O(m)$、許容可能な解決策が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 行ペア + グループ列 + 2 つのポインターを修正 | O(n²m) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッド全体でプレフィックスの数をカウントする 2D プレフィックスの合計を事前計算します。`'a'`文字は任意の下位四角形内にあります。 これにより、次の数を計算できます。`'a'`O(1) の固定列の任意の 2 行間のセル。 行ペア間の垂直セグメントを繰り返し評価するため、これは不可欠です。 
2. すべての行のペアを反復処理します。`(top, bottom)`。 これら 2 つの行を修正すると、有効な四角形の境界を形成する 2 つの列を選択するという問題が軽減されます。 
3. 現在の行のペアについて、各エントリにいくつの値が格納される列の配列を構築します。`'a'`文字はその列に表示されます。`top`そして`bottom`。 この配列は、その列を四角形に含めることによるコストの寄与を表します。 
4. 各列について、文字ペアも記録します。`(grid[top][col], grid[bottom][col])`。 これら 2 つの文字が等しい場合にのみ、列を四角形の境界として使用できます。 そうしないと、この行ペアの有効な四角形の隅の列として機能できません。 
5. 両方の行で表される文字によって列をグループ化します。 文字ごとに`'a'`に`'z'`、最上位行と最下位行の文字がその文字と一致するすべての列インデックスを収集します。 
6. このような列グループごとに、列に対して 2 ポインタ スイープを昇順に実行します。 スライディングウィンドウを維持する`[l, r]`の合計を追跡します`'a'`そのウィンドウでの貢献。 
7. 展開する`r`一歩ずつ。 合計が超えるたびに`k`、 動く`l`制約が再び満たされるまで前進します。 移動するたびに`r`、すべての有効な開始位置`l' ≤ l`有効なペアを形成しませんが、すべての位置が`[l, r)`する。 で終わる有効な長方形の数を数えます。`r`。 
8. すべての文字とすべての行ペアにわたる寄与を合計します。 これにより最終的な答えが得られます。 

重要な考え方は、行を固定して単一の文字グループに制限すると、すべての有効な四角形が列の部分配列に正確に対応し、`'a'`制約はその部分配列に対して加算的になります。 

### なぜ効果があるのか

 行の固定ペアの場合、すべての有効な四角形は 2 つの列によって決まります。 コーナー条件では、両方の端点が両方の行で一致する必要があるため、両方の列が同じ文字グループに属するように強制されます。 1 つのグループ内で残る唯一の制約は、グループの総数です。`'a'`四角形内のセル。列上で直線的です。 2 ポインター プロセスでは、この制約を満たすすべてのサブ配列が 1 回だけ列挙されるため、四角形が見逃されることはなく、異なるグループまたは行のペアにわたって二重にカウントされることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    # prefix sum for 'a'
    pref = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(n):
        row_sum = 0
        for j in range(m):
            row_sum += (g[i][j] == 'a')
            pref[i + 1][j + 1] = pref[i][j + 1] + row_sum

    def get_a(x1, y1, x2, y2):
        return pref[x2][y2] - pref[x1][y2] - pref[x2][y1] + pref[x1][y1]

    ans = 0

    for top in range(n):
        for bottom in range(top + 1, n):
            col_a = [0] * m
            col_letter = [''] * m

            for j in range(m):
                if g[top][j] == g[bottom][j]:
                    col_letter[j] = g[top][j]
                    col_a[j] = get_a(top, j, bottom + 1, j + 1)
                else:
                    col_letter[j] = '#'

            pos_by_letter = [[] for _ in range(26)]
            val_by_letter = [[] for _ in range(26)]

            for j in range(m):
                c = col_letter[j]
                if c != '#':
                    idx = ord(c) - 97
                    pos_by_letter[idx].append(j)
                    val_by_letter[idx].append(col_a[j])

            for idx in range(26):
                vals = val_by_letter[idx]
                if not vals:
                    continue

                l = 0
                s = 0
                for r in range(len(vals)):
                    s += vals[r]
                    while s > k:
                        s -= vals[l]
                        l += 1
                    ans += (r - l)

    print(ans)

if __name__ == "__main__":
    solve()
```プレフィックス合計構造により、垂直セグメントは必ず次のクエリを実行します。`'a'`カウントは定数時間です。 行ペア上のメインの二重ループは、ソリューションの構造的バックボーンです。 

各行ペア内で、2 つの行が一致しない列を無視して、列を文字グループに圧縮します。 このような列は有効な四角形の境界として表示されないため、これは重要です。 

各グループ内の 2 ポインター ロジックは、累積されたサブ配列をカウントします。`'a'`貢献は範囲内にとどまる`k`。 表現`(r - l)`各右エンドポイントに対して有効な左エンドポイントがいくつ存在するかをカウントします。

 ## 特殊なケース

 グリッドが均一な場合、すべての列は同じ文字グループに属するため、アルゴリズムはすべての列にわたる純粋な 2 ポインタ問題に帰着します。 この実装ではすべての四角形が正しく集計されますが、それでもフィルタリングされます。`'a'`制約。 

いつ`k = 0`、ゼロを含む長方形のみ`'a'`セルは許可されます。 プレフィックスベースの列の重みにより、単一の列でも含まれる四角形が保証されます。`'a'`スライディング ウィンドウの拡張中は直ちに除外されます。 

行が最大で列まで異なる場合、特定の行ペアに対して多くの列が無効になります。 アルゴリズムは、不一致の列をセンチネルでマークし、すべてのグループから除外することで、それらを自然にスキップし、無効な四角形の境界が考慮されないようにします。
