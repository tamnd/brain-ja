 ## 解決策
 ## 問題の理解

 無向重み付きグラフが与えられます。 すべてのエッジは 2 つの頂点を接続し、正のコストを持ちます。 タスクは頂点から開始することです`1`、頂点に到達`n`、最短パスを 1 つ出力します。 ルートが存在しない場合は、印刷します`-1`。 

グラフが大きいため、考えられるすべてのパスを探索することはできません。 まで`10^5`頂点と`10^5`エッジ、それに近いアルゴリズム`O(n^2)`Python ではすでにリスクがあり、指数関数的なものは不可能です。 エッジの数が頂点の数と同じオーダーであるため、グラフはまばらであり、隣接行列ではなく隣接リストを強く示唆しています。 

エッジの重みはすべて正です。 その詳細が問題を完全に変えます。 正の重みを使用すると、ノードまでの最短距離が決定されると、その後のパスでそれを改善することができないため、ダイクストラのアルゴリズムが機能します。 

この問題では、最小距離だけでなく、実際のパスも求められます。 つまり、リラックス中にどのようにして各頂点に到達したかを覚えておく必要があります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

グラフが切断される可能性があります。 

入力：```
3 1
1 2 5
```からの道はありません`1`に`3`したがって、正しい出力は次のようになります。```
-1
```不注意な実装では、ノードの親が存在しないためにパスを再構築しようとしてクラッシュする可能性があります。`3`。 

グラフには、同じ頂点ペアの間に複数のエッジが含まれる場合があります。 

入力：```
3 3
1 2 10
1 2 1
2 3 2
```最短のパスは次のとおりです。```
1 2 3
```総費用付き`3`。 エッジを上書きしたり、一意であると仮定したりすると、誤って重いエッジを保持してしまう可能性があります。 

グラフには自己ループが含まれる場合があります。 

入力：```
2 2
1 1 5
1 2 3
```ノード上のループ`1`リラックスプロセスでは自然に無視されるべきです。 古い状態が正しく処理されない場合、バグのある実装により誤って同じノードが永久に緩和され続ける可能性があります。 

最短パスには非常に長い距離が含まれる場合があります。 エッジの重みは最大です`10^6`、パスには多くのエッジが含まれる可能性があるため、合計距離は 32 ビット整数の範囲を超える可能性があります。 Python の整数はこれを自動的に処理しますが、C++ のような言語では次の処理が必要になります。`long long`。 

## アプローチ

 ブルートフォースのアイデアは、考えられるすべてのパスを列挙することです。`1`に`n`、コストを計算し、最小限に抑えます。 すべての有効なルートがチェックされるため、これは論理的に機能し、最適なルートを見逃すことはありません。 

問題は、グラフ内の単純なパスの数が指数関数的に増加する可能性があることです。 適度に接続されたグラフであっても、数百万または数十億のパスが含まれる可能性があります。 と`10^5`頂点では、強引な攻撃は完全に不可能です。 

もう少し良い単純なアプローチは、ベルマンフォードと同様に、BFS スタイルのリラクゼーションを繰り返し使用することです。 Bellman-Ford は、より短いパスが存在しなくなるまで距離を繰り返し改善するため、負の重みを指定しても正しく機能します。 その複雑さは、`O(n * m)`。 ここでおおよそのことになります`10^10`最悪の場合、制限時間を大幅に超えて操作が行われる可能性があります。 

重要な観察は、すべてのエッジの重みが正であるということです。 正の重みを指定すると、最短パスに単調な構造が与えられます。つまり、現在の最小の暫定距離を抽出すると、今後のパスでそれを改善することはできません。 この特性はまさにダイクストラのアルゴリズムが依存しているものです。 

ダイクストラは、すべてのノードへの既知の最良の距離を維持し、常に最も近い未処理のノードを最初に展開します。 優先キューを使用すると、抽出の効率が維持されます。 グラフがまばらであるため、隣接リストとヒープにより複雑さが増します。`O((n + m) log n)`、制約に簡単に適合します。 

また、`parent`配列。 ノードまでの最短距離を改善するたびに、どの前のノードがその改善をもたらしたかを記録します。 ディクストラが終わったら、そこから後ろ向きに歩いて道を再構築します。`n`に`1`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | Brute Force Path Enumeration | 指数 | O(n) | 遅すぎる |
 | ベルマン・フォード | O(nm) | O(n) | 遅すぎる |
 | ヒープのあるディクストラ | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. Build an adjacency list for the graph.

 Since the graph is undirected, every edge`(u, v, w)`両方向に追加する必要があります。 
2. 無限大で初期化された距離配列を作成します。`dist[x]`ノードから現在わかっている最短距離を保存します`1`ノードへ`x`。 最初だけ`dist[1] = 0`。 
3. で初期化された親配列を作成します。`-1`。`parent[x]`への最短パス上の前のノードを記憶します。`x`。 これにより、後でパスを再構築できるようになります。 
4.プッシュ`(0, 1)`最小ヒープに入れます。 

ヒープは常に、暫定的な距離が最小のノードを提供します。 
5. ヒープから最小の状態を繰り返しポップします。 

ポップしてみよう`(d, u)`。 もし`d`に等しくありません`dist[u]`、この状態は古いためスキップする必要があります。 

より短いルートが後で検出される可能性があるため、同じノードの複数のコピーがヒープ内に存在する可能性があります。 
6. エッジを残してリラックスします`u`。 

隣人ごとに`(v, w)`、次のことを確認します。```
dist[u] + w < dist[v]
```true の場合、より短いルートが見つかりました`v`。 
7. 距離配列と親配列を更新します。 

セット：```
dist[v] = dist[u] + w
parent[v] = u
```次に、更新された状態をヒープにプッシュします。 
8. ヒープが空になったら、次のことを確認します。`dist[n]`。 

まだ無限大の場合は、ノード`n`到達不可能なので印刷します`-1`。 
9. パスを再構築します。 

ノードから開始`n`そして繰り返し移動します`parent[cur]`到達するまで`1`。 印刷する前に、収集したシーケンスを逆にします。 

### なぜ効果があるのか

 ダイクストラのアルゴリズムは、すべてのエッジの重みが正であるという事実に基づいています。 ヒープがノードを抽出するとき`u`最小の暫定距離では、他の未処理のパスはすでに少なくとも同じくらい高価になっているはずです。 到達する代替ルート`u`後で、距離が小さくない別のノードを通過し、正のエッジの重みを追加する必要があるため、改善できません`dist[u]`。 

その特性により、ノードが現在の最適距離で処理されると、その値が最終的な値となります。 

親配列には、既知の最良の距離を生成したエッジが常に記録されます。 距離は真の最短値に向かってのみ改善されるため、最後の親チェーンは有効な最短パスを再構築します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

n, m = map(int, input().split())

graph = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v, w = map(int, input().split())
    graph[u].append((v, w))
    graph[v].append((u, w))

dist = [INF] * (n + 1)
parent = [-1] * (n + 1)

dist[1] = 0

pq = [(0, 1)]

while pq:
    d, u = heapq.heappop(pq)

    if d != dist[u]:
        continue

    for v, w in graph[u]:
        nd = d + w

        if nd < dist[v]:
            dist[v] = nd
            parent[v] = u
            heapq.heappush(pq, (nd, v))

if dist[n] == INF:
    print(-1)
else:
    path = []

    cur = n

    while cur != -1:
        path.append(cur)
        cur = parent[cur]

    path.reverse()

    print(*path)
```隣接リストにより、エッジの数に応じてメモリ使用量が線形に保たれます。 まで`10^5`エッジの場合、これは行列よりもはるかに効率的です。`10^10`細胞。 

ヒープにはペアが格納されます`(distance, node)`。 パイソンの`heapq`は最小ヒープを実装しているため、最小距離が常に最初に処理されます。 

古い状態のチェック:```
if d != dist[u]:
    continue
```が不可欠です。 仮定ノード`u`以前は距離を置いて押されていた`10`そしてその後、距離を置いてより良い道を見つけました`5`。 どちらの状態もヒープ内に残ります。 時代遅れのとき`(10, u)`最終的には表示されますが、無視する必要があります。 このチェックを行わないと、アルゴリズムは正しいままですが、不必要な緩和が実行され、遅くなりすぎる可能性があります。 

親の更新は、より短いパスが検出されたときに正確に行われます。 これにより、再構築されたチェーンが最終的な最短距離に対応することが保証されます。 

パス再構築は後ろ向きに歩きます`n`向かって`1`。 親は逆の順序を指しているため、印刷する前に収集された配列を逆にします。 

Using a large integer like`10**30`可能な最大最短距離はそれよりはるかに小さいため、無限大は安全です。

import sys
import io
import heapq

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    INF = 10**30

    n, m = map(int, input().split())

    graph = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v, w = map(int, input().split())
        graph[u].append((v, w))
        graph[v].append((u, w))

    dist = [INF] * (n + 1)
    parent = [-1] * (n + 1)

    dist[1] = 0

    pq = [(0, 1)]

    while pq:
        d, u = heapq.heappop(pq)

        if d != dist[u]:
            continue

        for v, w in graph[u]:
            nd = d + w

            if nd < dist[v]:
                dist[v] = nd
                parent[v] = u
                heapq.heappush(pq, (nd, v))

    if dist[n] == INF:
        return "-1"

    path = []

    cur = n

    while cur != -1:
        path.append(cur)
        cur = parent[cur]

    path.reverse()

    return " ".join(map(str, path))

 ## 特殊なケース

 切り離されたグラフを考えてみましょう。```
3 1
1 2 5
```アルゴリズムはノードから開始します`1`、ノードをリラックスします`2`、その後、ヒープは空になります。 ノード`3`には到達しないため、次のようになります。```
dist[3] = INF
```最終チェックでこれが検出され、次のように出力されます。```
-1
```パスの再構築は試行されないため、無効な親アクセスはありません。 

ここで複数のエッジを考えてみましょう。```
3 3
1 2 10
1 2 1
2 3 2
```ノード処理時`1`、両方のエッジからノードまで`2`検査されます。 最初のものは距離を与えます`10`、しかし2番目はそれを改善します`1`。 

最終的な距離は次のようになります。```
dist[2] = 1
dist[3] = 3
```親チェーンは以下を再構築します。```
1 → 2 → 3
```すべてのエッジが独立して緩和されるため、アルゴリズムは平行エッジを自然に処理します。 

最後に、自己ループについて考えてみましょう。```
2 2
1 1 5
1 2 3
```いつノード`1`が処理されると、ループ エッジは次のことを提案します。```
0 + 5 = 5
```ノード用`1`自体。 以来`dist[1]`すでに`0`、更新は行われません。 

通常のエッジからノードまで`2`与える:```
dist[2] = 3
```出力は次のようになります。```
1 2
```予想どおり、自己ループは効果がありません。
