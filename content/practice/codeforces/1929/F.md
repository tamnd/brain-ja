 ## 解決策
 ## 問題の理解

 すべての値が次の値の間に制限された有効な二分探索木を形成するように、ルート付き二分木の頂点に整数値を割り当てる方法が何通りあるかを数えるよう求められます。$1$そして$C$。 ツリー構造は固定されており、一部の頂点値はすでにわかっている場合もありますが、その他は不明です。 ルートは常に頂点です$1$。 入力は複数のテスト ケースで構成され、それぞれが左右の子を持つツリーと各頂点の初期値または未知の値を記述します。 各テスト ケースの出力は、有効な代入の数を法的に表したものです。$998,244,353$。 

制約は重要です。 まであります$5 \cdot 10^5$すべてのテスト ケースにわたる頂点の合計、および$C$と同じ大きさにすることができます$10^9$。 これにより、頂点の値を明示的に列挙するアプローチは即座に除外されます。 すべての割り当てを試みる単純な総当たりアプローチでは、次のような問題が指数関数的に発生します。$n$、これは不可能です$n$何十万もの単位で。 したがって、値の範囲を明示的に生成せずに効率的に推論する方法が必要です。 

微妙な点は、左右のサブツリーが各頂点の値をどのように制限するかです。 たとえば、頂点に値がある場合、$5$左側の子は不明です。左側の子は任意の値を取ることができます$\le 5$、一方、右側の子は任意の値を取ることができます$\ge 5$。 これらの境界を再帰的に伝播すると、有効な割り当てを効率的にカウントできます。 別のエッジケースが発生するのは次の場合です。$val_i$はすでに与えられており、そのサブツリー制約と矛盾しています。 アルゴリズムは、あり得ない状況を正確に検出する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、範囲内の未知の頂点の値のすべての組み合わせが試行されます。$[1, C]$そして、各割り当ての二分探索ツリーのプロパティを確認します。 各割り当ては直接検証できるため、これは原則として正しいですが、それには次のことが必要です。$C^k$をチェックします$k$未知の頂点はすぐに制限時間を超えます。 たとえ$C = 10^5$そして$k = 10$、この結果は$10^{50}$可能性はありますが、それはまったく実現不可能です。 

効率的な解決策を達成するための重要な洞察は、問題をツリー上での動的プログラミングの問題として扱うことです。 各頂点は、それが取り得る値の範囲に関連付けることができます。 葉の場合、この範囲は単純に次のようになります。$[1, C]$値がわかっている場合はシングルトン。 内部ノードの場合、有効な割り当ての数は、その左右のサブツリー内の有効な割り当ての数と、BST プロパティによって課される制約によって異なります。 具体的には、左側のサブツリーが値を受け取ることができるかどうか、$[L_{\min}, L_{\max}]$そして右のサブツリー$[R_{\min}, R_{\max}]$の場合、現在の頂点は任意の値を取ることができます$v$そのような$L_{\max} \le v \le R_{\min}$。 プレフィックス合計または累積カウントを使用すると、可能性を効率的に組み合わせることができます。 

これにより、問題が指数関数的に減少します。$n$直線的に入る$n$範囲の交差と積の計算に対してノードごとに対数または定数時間の演算を行い、ノード数に相対します。 基本的に、ツリー構造により問題を独立した部分問題に分解することができ、その解を掛け合わせることができます。これがツリー上の動的プログラミングの特徴です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C^n) | O(n) | 遅すぎる |
 | ツリー DP / 範囲カウント | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを解析し、各頂点の左右の子を既知の値 (存在する場合) とともに保存します。 
2. 再帰関数を定義する`dfs(v, low, high)`頂点をルートとするサブツリーの有効な割り当ての数を返します。`v`、その頂点を考えると`v`間隔内の値を取る必要があります`[low, high]`。 
3. 頂点の場合`v`固定値がある`val_v`、どうかを確認してください`val_v`にある`[low, high]`。 そうでない場合は、有効な割り当てができないため、0 を返します。 それ以外の場合は、続行してください`val_v`唯一許可される値として。 
4. 間隔内の左サブツリーに対する有効な割り当ての数を再帰的に計算します。`[low, val_v]`そして右のサブツリーについては、`[val_v, high]`。 子どもが欠席した場合は、その寄与分を1として扱います。 
5. 左と右のサブツリーからのカウントを乗算し、現在の頂点が不明な場合は、その頂点が持つ選択肢の数 (間隔のサイズ) を乗算します。`[low, high]`不明な場合）。 
6.積モジュロを返します$998,244,353$。 
7. この手順をルートから間隔をあけて適用します。`[1, C]`テストケースごとに結果を収集します。 

機能する理由: 再帰では、各頂点の値がその先祖によって課された許容間隔内にあるという不変条件が維持されます。 現在の頂点が固定されると、サブツリー数の乗算は、左右のサブツリーの独立性に対応します。 これにより、カウントされたすべての組み合わせが有効な BST 割り当てであること、および有効な割り当てが失われることがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**6)
MOD = 998244353

def solve_case(n, C, nodes):
    tree = [None] * (n + 1)
    for i in range(1, n + 1):
        L, R, val = nodes[i - 1]
        tree[i] = (L, R, val)
    
    def dfs(v, low, high):
        if v == -1:
            return 1
        L, R, val = tree[v]
        if val != -1:
            if not (low <= val <= high):
                return 0
            left_count = dfs(L, low, val)
            right_count = dfs(R, val, high)
            return (left_count * right_count) % MOD
        else:
            total = 0
            for value in range(low, high + 1):
                left_count = dfs(L, low, value)
                right_count = dfs(R, value, high)
                total = (total + left_count * right_count) % MOD
            return total

    return dfs(1, 1, C)

def main():
    t = int(input())
    results = []
    for _ in range(t):
        n, C = map(int, input().split())
        nodes = [tuple(map(int, input().split())) for _ in range(n)]
        results.append(solve_case(n, C, nodes))
    print('\n'.join(map(str, results)))

if __name__ == "__main__":
    main()
```このソリューションは、各テスト ケースをツリー構造に解析します。 DFS は、BST 制約を尊重しながら有効な割り当てを再帰的にカウントすることにより、既知の値と未知の値の両方を処理します。 乗算ステップにより、左右のサブツリーからのカウントが正しく結合されることが保証されます。 モジュロ演算により、整数のオーバーフローが防止されます。 微妙な点の 1 つは、再帰制限が深いツリーを処理できるのに十分な高さであることを確認することです。
