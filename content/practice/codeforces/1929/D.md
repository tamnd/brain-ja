 ## 解決策
 ## 問題の理解

 サブセット内の交差点を危険であると正確に宣言した場合、ツリー内の単純なパスに 3 つ以上の危険な交差点が含まれないように、ツリー内の交差点のサブセットの数を数えるように求められます。 入力は次のツリーです。$n$ノード、によって定義される$n-1$エッジ、および出力は「良好な」サブセットの数を法としたものです$998\,244\,353$。 複数のテストケースが与えられ、その合計は$n$すべての場合において、$3 \cdot 10^5$したがって、ツリーごとにほぼ線形または線形に近い時間で実行されるソリューションが必要です。 

素朴なアプローチは、すべてを生成することです$2^n$ノードのサブセットを調べて、ツリー内のすべてのパスの状態を確認します。 これは次の場合にはすぐに実行できなくなります。$n$20でもあるから$2^{20} = 10^6$サブセットとツリー内のすべてのパスをチェックするには、$O(n^2)$操作。 のために$n$まで$3 \cdot 10^5$、強引な行為はまったく問題外です。 

明らかではないエッジ ケースには、チェーンであるツリーが含まれます。 長さ 4 のチェーンでは、2 つの中間ノードと 1 つのエンドポイントを含むサブセットが、あるパス上の 3 つの危険な交差点を含むセットを形成します。 これは、ノードに危険な隣接ノードが複数ある場合に問題が発生することを示しており、ノードの次数とツリー内での位置がサブセットのカウント方法に影響を与えることを示唆しています。 

## アプローチ

 あらゆるサブセットをすべてのパスに対してチェックできるため、ブルート フォース ソリューションが機能します。 障害点は、二次パス チェックと組み合わせられたサブセットの指数関数的な増加です。 適切なサブセットを列挙せずにカウントする方法が必要です。 

重要な洞察は、ツリー構造を活用することです。 ツリーでは、パスはそのエンドポイントによって一意に決定されるため、パス上に 3 つの危険なノードがあるサブセットを数えると、少なくとも 3 つの長さのパスを形成するノードを数えることになります。 ノードに 2 つ以上の隣接ノードがあり、それらのノードも危険で、それを介して接続されている場合、危険な交差点が 3 つあるパスが作成されるため、危険な構成が発生する可能性があります。 この観察は、カウントをリーフから上に伝播する動的プログラミング ソリューションに自然につながります。 

各ノードに対して 3 つの状態を定義できます。危険ではない、危険ではあるがサブツリー内の他の危険なノードに隣接していない、または危険であり、危険なノードの「ペア」の一部を形成しています。 これらの状態を使用すると、各ノードをルートとするサブツリーの有効なサブセットの数を再帰的にカウントできます。 子からの寄与を乗算し、状態を正しく組み合わせることで、サブツリー内のパスに 3 つ以上の危険なノードが存在しないことが保証されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n^2) | O(n) | 遅すぎる |
 | ツリー状態の DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを隣接リストとして表します。 これにより、任意のノードからその子への効率的なトラバースが可能になります。 
2. 再帰的 DP 関数を定義する`dfs(node, parent)`3 つのカウントを返します。`dp0`ノードが危険ではないサブセットの場合、`dp1`ノードが危険だが孤立しているサブセットの場合、`dp2`ノードが危険な子とのペアの一部を形成するサブセットの場合。 
3. For a leaf node,`dp0 = 1`空集合は有効なので、`dp1 = 1`葉だけを危険なものとしてマークすることは有効であるため、`dp2 = 0`ペアを形成する子がないからです。 
4. 内部ノードの場合、初期化します。`dp0 = dp1 = 1`そして`dp2 = 0`。 各子を反復処理し、子の`dp0, dp1, dp2`。 次のようにカウントを更新します。`dp0`による`(child.dp0 + child.dp1 + child.dp2)`危険でないノードは有効な子サブセットを持つことができるため、乗算します。`dp1`による`(child.dp0 + child.dp1)`なぜなら、単一の危険なノードは、それに貢献する子を持つことができないからです。`dp2`、と乗算します`dp2`による`(child.dp0 + child.dp1)`組み合わせによる貢献も追加します`dp1`このノードの`dp1`ペアを形成するのに必要な子供の数。 
5. すべての子を処理した後、タプルを返します`(dp0, dp1, dp2)`ノード用。 グッドセットの総数は`dp0 + dp1 + dp2`根元にある。 
6. モジュロを適用する$998\,244\,353$オーバーフローを避けるために各操作で。 

機能する理由: 3 つの状態は、すべての有効なサブセットの完全なパーティションを形成します。 組み合わせロジックにより、サブツリー内のどのパスにも危険なノードが最大 2 つあることが保証されます。`dp2`危険なノードを含む長さ 2 のパスを形成する可能性のあるペアを正確に追跡します。 子からの貢献を乗算すると、二重にカウントされることなく、すべての有効な構成が正しくカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        edges = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            edges[u - 1].append(v - 1)
            edges[v - 1].append(u - 1)

        def dfs(u, parent):
            dp0, dp1, dp2 = 1, 1, 0
            for v in edges[u]:
                if v == parent:
                    continue
                c0, c1, c2 = dfs(v, u)
                new_dp2 = (dp2 * (c0 + c1 + c2) + dp1 * c1) % MOD
                dp1 = (dp1 * (c0 + c1)) % MOD
                dp0 = (dp0 * (c0 + c1 + c2)) % MOD
                dp2 = new_dp2
            return dp0, dp1, dp2

        result = sum(dfs(0, -1)) % MOD
        print(result)

solve()
```このコードは、テスト ケースの数を読み取ることから始まり、次に各ツリーの隣接リストを構築します。 再帰関数`dfs`ツリーを走査し、3 つの DP 状態を計算します。 アップデートでは、3 つの危険なノードを含むパスを回避するために組み合わせを注意深く追跡します。 ルートで DP 状態を合計して、良好なセットの合計数を取得し、結果を出力します。
