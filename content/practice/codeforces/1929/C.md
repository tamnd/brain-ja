 ## 解決策
 ## 問題の理解

 サーシャは、賭けごとに自分の賭け金を係数で増やすか、完全に失うかのどちらかの賭けゲームを繰り返します。 彼がコントロールできる唯一のコントロールは各ベットのサイズであり、過去の結果に基づいてそれを調整することが許可されています。 ただし、カジノは安全上の制約を課します。つまり、以下の金額以上を失うことはありません。$x$連続して何回も。 

問題は、期待利益を最大化することや、確率論的な意味での最適なベッティング戦略を見つけることではありません。 代わりに、それは最悪の場合の保証についてです。 私たちは、結果がどのように展開しても（連敗ルールを尊重する限り）、ある時点で彼の資本を任意に大きくできるような賭け戦略をサーシャが設計できるかどうかを判断する必要があります。 

入力は複数の独立したシナリオを記述します。 各シナリオには乗数が与えられます$k$、許容される連続損失の最大値$x$、および初期資本$a$。 出力は、単純な実現可能性の決定です。 

制約は十分に小さいため、各テスト ケースは一定時間内に処理する必要があります。 これにより、シミュレーションや戦略の探索が即座に除外されます。 その答えは、損失と利益がどのように相互作用するかという構造的特性から導き出されるはずです。 

微妙なエッジケースが現れるのは、$x = 1$。 この場合、サーシャは 2 回連続で負けることは決して許されず、力関係が劇的に変わります。 もう 1 つのエッジケースは次のような場合です$k$勝利あたりの成長は最小限であり、強制的な損失ブロックを補う必要があるため、 は 2 に近いです。 

## アプローチ

 ブルートフォースのアイデアでは、ベッティング戦略と敵対的な結果をシミュレートしようとします。 考えられるすべての賭け金サイズを調査し、すべての敵対的シーケンスが依然として無制限の成長を可能にするかどうかを追跡することを想像することもできます。 これはすぐに不可能になります。$x$、結果シーケンスの数は指数関数的に増加し、戦略スペースは賭け金サイズの選択において連続的です。 

重要な洞察は、個々の賭けの観点から考えるのをやめ、代わりにプロセスを損失とその後の勝利のサイクルに圧縮することです。 サーシャはこれ以上失うことはできないので、$x$連続して何回もプレイを続ける場合、プレーの最悪の場合のセグメントは最大でも$x$勝つ前に連敗する必要がある。 問題は、慎重に選択された単一の勝ちの賭けからの利益が、そのようなブロックでの累積的な最悪の場合の損失を支配できるかどうかに帰着します。 

これにより、問題は次のような決定論的な不等式に変換されます。$k$、$x$、 そして$a$。 重要なのは、資本の崩壊を防ぎながら最終的な乗数的成長を保証する戦略が存在するかどうかだけです。 この条件は、次のしきい値の比較に単純化されます。$k$対$x + 1$。 

いつ$k \ge x + 2$、勝利による成長は最悪の損失シーケンスを上回るほど強力であり、サーシャはいつでも資本を無限に回復して増幅できます。 いつ$k \le x + 1$、純指数関数的な成長を防ぐブロックに損失を配置することで、どのような戦略も無力化できます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に分析します。 

1.読む$k$、$x$、 そして$a$。 初期資本$a$この条件は無制限の成長が構造的に可能かどうかのみに依存するため、最終的な決定には影響しません。 
2. 比較する$k$と$x + 1$。 この比較は、勝利の乗数的利点が考えられる最悪の連敗を克服できるかどうかを捉えます。 
3. もし$k \ge x + 2$、「YES」を出力します。 これは、その後も$x$連続損失が発生した場合でも、1 回の勝利の賭けで累積損失を相殺し、成長の可能性を回復するのに十分な資本を増やすことができます。 
4. それ以外の場合は「NO」を出力します。 この体制では、敵対的な損失パターンにより、システムが際限のない成長を達成することが妨げられる可能性があります。 

### なぜ効果があるのか

 プロセスは、最大でも長さの損失ブロックに自然に分解されます。$x$、それぞれ勝利で終わります。 このようなブロックの最終的な効果は、次の乗算が行われるかどうかにのみ依存します。$k$引き算を上回る$x$ステップ。 しきい値$k = x + 1$サイクル当たりの成長率がプラスである体制とそうでない体制を区別します。 サイクルごとの成長がプラスになると、繰り返し適用することで無制限の資本が得られます。 そうしないと、戦略に関係なくプロセスが制限されてしまいます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    k, x, a = map(int, input().split())
    if k >= x + 2:
        print("YES")
    else:
        print("NO")
```実装は、導出されたしきい値条件から直接続きます。 各テスト ケースは一定時間内に独立して処理されます。 変数$a$は読み取られますが、決定には使用されません。これは、無制限の増加の可能性が次の関係にのみ依存するためです。$k$そして$x$、開始資金ではありません。 

よくある間違いは、$a$コンディションに入れるか、ベッティングシーケンスをシミュレートします。 どちらも不必要であり、誤った推論や非効率につながります。 

## 実用的な例

 場合を考えてみましょう$k = 2, x = 1, a = 7$。 以来$k = 2$そして$x + 1 = 2$、 我々は持っています$k \le x + 1$、したがって、答えは「NO」です。 損失が発生するとすぐにさらなる回復パターンが妨げられるため、システムは成長を保証できません。 

ここで考えてみましょう$k = 5, x = 4, a = 7$。 ここ$k = 5$そして$x + 1 = 5$、それではまたまた$k \le x + 1$、「いいえ」を与えます。 勝利が強力であっても、敵対者は時間の経過とともに成長を無効化する損失ブロックを強制する可能性があります。 

最後に、取ってください$k = 88, x = 4, a = 10^9$。 ここ$k \ge x + 2$, したがって、答えは「YES」です。 最大 4 回の損失が連続しても、十分に強力な勝利倍率によって補償され、資本を際限なく増やすことができます。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        k, x, a = map(int, input().split())
        out.append("YES" if k >= x + 2 else "NO")
    return "\n".join(out)

 ## 特殊なケース

 いつ$x = 1$、すべての損失の直後に勝利が必要となるため、システムは非常に制限的になります。 この場合、中程度の値であっても、$k$閾値を超えないと十分ではない可能性がある$x + 1 = 2$。 アルゴリズムはこれを同じ比較を通じて直接処理し、特別なケースを使用せずに正しい決定を行います。 

いつ$k = x + 1$、システムはまさに利益と損失が均衡する境界にあります。 アルゴリズムはこれを「いいえ」として分類します。これは、サイクルごとの正味の増加がないため、無制限の増加は保証できないことを反映しています。
