 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、その要素を任意の順序で並べ替えることができます。 

特定の配置の美しさは、連続する要素間の差異の合計として定義されます。$$(a_2-a_1)+(a_3-a_2)+\cdots+(a_n-a_{n-1})$$私たちの仕事は、可能な限り最大の美しさを生み出す順序を選択することです。 

入力には複数のテスト ケースが含まれています。 各テスト ケースでは、配列要素を受け取り、それらを再配置した後に達成可能な最大の美しさを出力する必要があります。 

制約は非常に小さいです。 配列の長さは最大 100 で、テスト ケースは最大 500 です。 たとえ$O(n^2)$解決策は簡単に十分に高速になります。 課題はパフォーマンスではなく、美しさの公式の中に隠された数学的単純化を認識することです。 

よくある間違いは、取り決め自体が複雑な意味で重要であると考えることです。 たとえば、小さな数字と大きな数字を交互に配置してみるとよいでしょう。```
1 100 2 99
```そして計算する$$(100-1)+(2-100)+(99-2)=98$$これは大きく見えますが、最適ではありません。 もっと簡単なアレンジメントとしては、```
1 2 99 100
```与える$$(2-1)+(99-2)+(100-99)=99$$すべての値が等しい場合、別のエッジ ケースが発生します。```
5 5 5
```すべての差はゼロであるため、答えは次のようになります。```
0
```答えが常に肯定的であると仮定する不注意な実装は、ここで失敗します。 

3 番目に重要なケースは、配列の最小サイズです。```
2
1 10
```美しさは単純に、$10-1=9$, 連続差が1つしかないためです。 

## アプローチ

 ブルートフォースソリューションでは、配列のあらゆる順列を生成し、その美しさを計算し、最大値を維持します。 

これが機能するのは、考えられるすべての配置を直接チェックするためです。 長さの配列の場合$n$、 がある$n!$順列。 たとえ$n=10$、これはすでに 3,628,800 の順列になります。 以来$n$100 になる可能性がありますが、ブルートフォースは完全に不可能です。 

重要な観察は、美しさの公式を拡張することから得られます。$$(a_2-a_1)+(a_3-a_2)+\cdots+(a_n-a_{n-1})$$すべての中間条件はキャンセルされます。$$-a_2+a_2,\quad -a_3+a_3,\quad \ldots$$最初と最後の要素のみが残ります。$$a_n-a_1$$これは、アレンジメントの美しさは最初と最後の要素によってのみ決まることを意味します。 

問題が最大化されるまで縮小されたら$$a_n-a_1,$$答えは明らかになります。 最小値を最初に配置し、最大値を最後に配置する必要があります。 そうすれば美しさは変わる$$\max(a)-\min(a).$$最小値よりも小さい要素も最大値よりも大きい要素も存在しないため、これより優れた配置は他にありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n! \cdot n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取ります。 
2. 配列の最小要素を見つけます。 
3. 配列の最大要素を見つけます。 
4. 最大値と最小値の差を出力します。 

これが機能する理由は、美しさの公式が常に以下の範囲に及ぶためです。$$a_n-a_1.$$その数量を最大化するために、最小値を先頭に配置し、最大値を末尾に配置します。 

### なぜ効果があるのか

 美しさの表現は伸縮自在の和です。 すべての内部要素は、正符号付きで 1 回、負符号付きで 1 回の合計 2 回出現します。 これらの寄与は互いに打ち消し合います。 

その結果、どんな配置でも美しさは、最後の要素から最初の要素を引いたものに等しくなります。 可能な最大値は、最後の要素としてグローバル最大値を選択し、最初の要素としてグローバル最小値を選択することによって取得されます。 彼らの違いはまさに$\max(a)-\min(a)$、これは達成可能な最大の美しさです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(max(a) - min(a))
```実装は数学的観察に直接従います。 

テスト ケースごとに、配列が 1 回読み取られます。 Pythonの組み込み`max()`そして`min()`関数は配列をスキャンし、最大値と最小値を返します。 彼らの違いが答えです。 

難しい境界条件はありません。 長さ 2 の配列は自然に機能します。答えは単純に大きい要素と小さい要素の差であるからです。 最大値と最小値が等しく、ゼロが生成されるため、同じ値を持つ配列も機能します。 

値は次のように大きくできます。$10^9$ですが、Python の整数はオーバーフローを心配することなく簡単に処理できます。 

## 実用的な例

 ### 例 1

 入力配列:```
2 1 3
```| ステップ | 値 |
 | --- | --- |
 | 最小 | 1 |
 | 最大 | 3 |
 | 答え | 3 - 1 = 2 |

 出力：```
2
```これは核となるアイデアを示しています。 いくつかの並べ替えが可能ですが、最大の美しさは単純に最大値と最小値の差です。 

### 例 2

 入力配列:```
100 54 80 43 90
```| ステップ | 値 |
 | --- | --- |
 | 最小 | 43 |
 | 最大 | 100 |
 | 答え | 100 - 43 = 57 |

 出力：```
57
```最適な配置の 1 つは次のとおりです。```
43 54 80 90 100
```誰の美しさは$$(54-43)+(80-54)+(90-80)+(100-90)=57.$$トレースでは、最小値と最大値のみが重要であることが確認されています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n)$| 最小値と最大値を 1 回スキャン |
 | スペース |$O(1)$| 入力配列以外の変数はわずか数個だけ |

 と$n \le 100$最大 500 のテスト ケースでは、このソリューションは制限内で快適に実行されます。 総作業量はわずか数万回です。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ans.append(str(max(a) - min(a)))

    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return out

 ## 特殊なケース

 ### すべての要素は等しい

 入力:```

```アルゴリズムは以下を計算します。 

| 数量 | 値 |
 | --- | --- |
 | 最小 | 5 |
 | 最大 | 5 |
 | 答え | 0 |

 出力：```
0
```可能な再配置はすべて同じ配列値を生成するため、連続するすべての差異は相殺されます。 

### 長さ 2 の配列

 入力:```
1
2
1 10
```アルゴリズムは以下を計算します。 

| 数量 | 値 |
 | --- | --- |
 | 最小 | 1 |
 | 最大 | 10 |
 | 答え | 9 |

 出力：```
9
```要素が 2 つだけあるため、美しさはちょうど 1 つの違いで構成され、小さい値を最初に置くことで最大化されます。

 入力:```

```アルゴリズムは以下を計算します。 

| 数量 | 値 |
 | --- | --- |
 | 最小 | 3 |
 | 最大 | 4 |

```値を繰り返しても引数は変わりません。 伸縮合計は依然として最後のマイナス最初に減少するため、グローバル最小値と最大値のみが問題となります。
