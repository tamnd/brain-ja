 ## 問題の理解

 1 から N までの数値の順列が与えられ、その順列を左から右にスキャンしてスコアを定義します。 値 P[i] を配置するたびに、以前のすべての値 P[j] を調べ、P[j] が P[i] を除算する場合は 1 を追加します。 順列のスコアは、除数が順列の最初に現れるすべての順序付きペアにわたるそのような約数関係の総数です。 

タスクは 1 つの順列のスコアを計算することではありません。 代わりに、サイズ N の考えられるすべての順列を考慮し、そのスコアを計算し、これらのスコアを合計する必要があります。 

入力は複数のテスト ケースで構成され、それぞれの値 N は最大 100000 になります。テスト ケースは最大 100000 個まで存在する可能性があるため、どのソリューションでも効率的に答えを事前計算し、一定時間内に各クエリに答える必要があります。 

この制約は、N! であるため、順列の列挙を伴うアプローチは不可能であることを意味します。 非常に早く成長します。 すべての順列のすべてのペアを反復するだけでも、実現可能な限界をはるかに超えてしまいます。 これにより、明示的に順列を構築することを避け、組み合わせ的な方法で寄与をカウントする方向に進みます。 

微妙なエッジケースは、順列の順序に応じた定義から生じます。 たとえば、N = 1 の場合、ペアが存在しないため、答えは自明に 0 になります。 N = 2 の場合、両方の順列は、すべての順列にわたって期待において異なる形で対称的に寄与し、最終的な合計は両方の順序を考慮する必要があります。 単一の順列を扱うアプローチや、固定された順序構造を前提とするアプローチは失敗します。 

## アプローチ

 強引な解釈は簡単です。 サイズ N のすべての順列を繰り返し、すべてのペア i < j をチェックし、P[i] が P[j] を除算するかどうかを検証することでスコアを計算します。 これは正しいですが、根本的には実行不可能です。 Nもいるよ！ それぞれの置換には O(N^2) 個のチェックが必要で、結果は O(N! · N^2) となり、N = 10 の場合でも天文学的に大きくなります。 

重要な観察は、スコアが a が b を割る場合のペア (a, b) の相対的な順序にのみ依存するということです。 順列を構築する代わりに、別の質問をします。分割 b を持つ値の固定順序ペア (a, b) の場合、a を b の前に配置する順列は何回ありますか?

 (a, b) のペアを固定したら、他の要素はすべて自由に配置できます。 中でもN! 順列では、ちょうど半分が a を b の前に置き、半分が b を a の前に置きます。 この対称性は、任意の順列で a と b の位置を交換すると、一意のパートナー順列が生成されるため当てはまります。 

したがって、各有効なペア (a, b) は、正確に (a が b の前に現れる順列の数) に寄与し、これは N! です。 /2を合計スコアに加算します。 その場合のスコアは次のようになります。 

すべてのペア a < b を a | で合計します。 Nのb! / 2.

 これを次のように書き換えることができます。 

F(N) = (N! / 2) * ペア (a, b) の数、1 ≤ a < b ≤ N、つまり a が b を割る。 

問題全体は、範囲 [1, N] にわたる約数の関係をカウントすることに帰着します。 

すべての a について、その上に a の倍数がいくつ存在するかを事前に計算できます。 各 a について、有効な b は、k ≥ 2 の k・a の倍数です。そのような b の数は、floor(N / a) - 1 です。すべての a を合計すると、有効な順序ペアの合計数が得られます。 

これにより、問題は除数にわたる調和和に変換され、標準の除数カウント累積を使用して O(N log N) または O(N) で計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 順列に対するブルートフォース | O(N! · N^2) | O(N) | 遅すぎる |
 | 組み合わせ + 除数のカウント | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、寄与するすべてのペアが、特定の順列における位置ではなく、値によってのみ定義されることがわかります。 これにより、順列カウントを除数構造から分離することができます。

1. 1 から N までの各値 a について、b が a の倍数であり、b > a となるように有効な b をすべて決定します。 これらは、まさに、後の順列で出現し、a との約数関係に寄与する可能性のある値です。 
2. 固定の a について、そのような b がいくつ存在するかを数えます。 これは、floor(N / a) - 1 です。厳密なペアの意味では、数値はそれ自体を除算するものとしてカウントされないため、減算によって自明なケース b = a が削除されます。 
3. これらのカウントをすべての a にわたって合計します。 これにより、a が b を割るような有効な順序ペア (a, b) の合計数が得られます。 
4. 合計ペア数を N 倍します。 / 2. これは、すべての順列の半分では a が b の前に現れ、残りの半分では a が b の後に現れるという事実を説明します。 
5. 階乗値は繰り返し必要になるため、テスト ケース全体で最大 N まで階乗を事前計算します。 すべての計算は 1e9 + 7 を法として行われるため、除算の代わりに 2 の逆剰余が使用されます。 
6. 各クエリ N について、事前計算された除数カウントを使用してペア数を計算し、factorial[N] で乗算し、inv2 で乗算します。 

重要な考え方は、順列構造は順序確率にのみ影響し、約数ペアの存在には影響しないということです。 

### なぜ効果があるのか

 別個の値のペア (a、b) を分割 b で修正します。 すべての順列にわたって、a が b の前に現れる順列と、b が a の前に現れる順列の間には、それらの位置を交換することによって得られる完全な全単射が存在します。 この対称性により、すべての順列のちょうど半分がこのペアのスコアに寄与することが保証されます。 寄与度は値のペアにわたって独立しているため、合計の線形性が適用され、合計スコアは独立したペアの寄与度の合計になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

MAXN = 100000

# precompute factorials
fact = [1] * (MAXN + 1)
for i in range(2, MAXN + 1):
    fact[i] = fact[i - 1] * i % MOD

inv2 = (MOD + 1) // 2

# precompute divisor-pair counts up to N
cnt = [0] * (MAXN + 1)
for a in range(1, MAXN + 1):
    for b in range(2 * a, MAXN + 1, a):
        cnt[b] += 1

# prefix sum of valid (a,b) pairs per N
pairs = [0] * (MAXN + 1)
for i in range(1, MAXN + 1):
    pairs[i] = pairs[i - 1] + cnt[i]

t = int(input())
out = []
for _ in range(t):
    n = int(input())
    ans = pairs[n] * fact[n] % MOD
    ans = ans * inv2 % MOD
    out.append(str(ans))

print("\n".join(out))
```階乗配列は N! の直接計算をサポートしています。 モジュロ演算の下で。 cnt 配列は、各数値が適切な約数から受け取る小さい約数の数をカウントするために使用され、b を合計することで有効な (a, b) ペアを効果的にカウントします。 プレフィックス sumpairs[n] には、数値 1 ～ n の除数エッジの総数が格納されます。 

次に、各クエリは前に導出した式、つまり合計スコアが有効なペアの数に N を掛けたものに等しいことを使用します。 / 2.

 inv2 による乗算は、モジュラー演算における 2 による除算を置き換えます。これは、順列のちょうど半分が各ペアに寄与するため必要です。 

## 実用的な例

 N = 4 を考えます。有効な約数のペア (a、b) を列挙します: (1,2)、(1,3)、(1,4)、(2,4)。 したがって、そのようなペアは 4 つあります。 

Nを計算します！ = 24 なので、各ペアは 24 / 2 = 12 に寄与します。合計は 4 * 12 = 48 です。

したがって、カウント = 5。N! = 120、ペアごとの貢献 = 60、合計 = 300。

## 複雑さの分析

 前処理は、最大 100000 までの N の制限内に快適に収まります。各クエリは一定時間内に応答されます。これは、最大 100000 のテスト ケースに必要です。 

## テストケース```python
import sys, io

MOD = 10**9 + 7

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MAXN = 100000

    fact = [1] * (MAXN + 1)
    for i in range(2, MAXN + 1):
        fact[i] = fact[i - 1] * i % MOD

    inv2 = (MOD + 1) // 2

    cnt = [0] * (MAXN + 1)
    for a in range(1, MAXN + 1):
        for b in range(2 * a, MAXN + 1, a):
            cnt[b] += 1

    pairs = [0] * (MAXN + 1)
    for i in range(1, MAXN + 1):
        pairs[i] = pairs[i - 1] + cnt[i]

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        ans = pairs[n] * fact[n] % MOD
        ans = ans * inv2 % MOD
        out.append(str(ans))

    return "\n".join(out)

# minimal cases
assert solve("1\n1\n") == "0"
assert solve("1\n2\n") == str((1 * 2 // 2) * 1 % MOD)

# small hand cases
assert solve("1\n3\n") is not None
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | N=1 | 0 | 空の置換エッジケース |
 | N=2 | 1 | 単一の約数ペア (1,2) |
 | N=3 | 3 | 複数の約数の寄与 |

 ## 特殊なケース

 N = 1 の場合、個別の要素がないため、除数ペアのカウントはゼロになります。 このアルゴリズムでは、pairs[1] = 0 および階乗 [1] = 1 が生成されるため、最終的な答えは 0 となり、定義と一致します。 

2 や 3 のような小さな N の場合、内側の除数ループは適切な倍数のみを正しく累積します。 N = 2 の場合、cnt[2] は a = 1 から 1 回増加して 1 つの有効なペア (1,2) を与え、式はそれに 2 を乗算します。 / 2 = 1。 

N が大きい場合、順列に関する対称性の仮定が重要になります。 このアルゴリズムは、任意のペア (a、b) を交換すると、順列が逆の順序でバイジェクトされ、正確に半分の寄与が保証されるという事実に基づいています。 実装はこのマッピングを明示的に構築することはありませんが、正確性についてはマッピングに依存し、算術演算では inv2 による乗算を通じて直接このマッピングが反映されます。
