 ## 解決策
 ## 問題の理解

 私たちに与えられたのは 1 次元の回廊です。$N$一列に並んだ細胞。 ロボットは中央のセル、特にインデックスから開始します。$\lceil N/2 \rceil$、最初は右を向いています。 ロボットは一歩ずつ歩き、その動作ルールは完全に、初めてセルに入るのか、セルを再訪問するのかによって決まります。 

ロボットは現在の方向からセルごとに移動し続けます。 これまで訪れたことのないセルに足を踏み入れると、すぐに方向を転換します。 以前に訪問したセルに足を踏み入れると、同じ方向に進み続けるだけです。 このプロセスは、ライン内のすべてのセルが少なくとも 1 回訪問されるまで続きます。 プロセスが終了する前にロボットが行うユニットの移動の合計数を計算するように求められます。 

重要な隠された構造は、ロボットが開始点から外側に向かって拡大する間隔の決定論的な横断を効果的に実行していることですが、「最初の訪問時にターンオン」ルールによって引き起こされる特定の往復運動パターンを伴います。 

制約により許可されるのは、$N$まで$10^9$そして最大$10^5$テストケースがあるため、段階的に進むシミュレーションは不可能です。 テスト ケースごとのリニア スキャンでさえ、すでに$10^{14}$実行可能な限界をはるかに超えた最悪の場合の操作。 これにより、テスト ケースごとに閉じた形式の推論が強制され、理想的には一定時間になります。 

小さな値では微妙なエッジケースが現れます。 のために$N = 1$、ロボットは唯一のセルから開始し、すでに「すべてを訪問」しているため、答えはゼロステップです。 のために$N = 2$、中点定義はセル 1 を選択します ($\lceil 2/2 \rceil = 1$)、ロボットはすぐに一度右に歩いて停止し、非常に小さな非対称動作を生成します。 一般的なパターンはより大きな場合にのみ安定するため、対称性に依存する解決策はこれらの小さなケースを明示的に考慮する必要があります。$N$。 

もう 1 つの明白ではない落とし穴は、ロボットが単に左に端まで歩き、次に右に端まで 1 回だけ歩くと仮定することです。 方向反転は、境界に到達したときではなく、最初に未訪問のセルに入ったときにのみトリガーされるため、モーションは単純なバウンスではありません。 

## アプローチ

 ブルート フォース シミュレーションでは、訪問したセルのブール配列を保持し、現在の方向に 1 ステップずつ繰り返し移動します。 移動するたびに、セルが新しいかどうかを確認し、必要に応じて方向を反転し、すべてのセルを訪問するまで歩数をカウントします。 これは正しいですが、非常に高価です。 最悪の場合、ロボットが探索する$N$セルは存在しますが、バックトラッキングが繰り返されるため長いセグメントを複数回横断する可能性があり、実装に応じて二次または二次に近い動作が発生します。 と$N$まで$10^9$、配列を保存することすら不可能であり、概念的なステップ シミュレーションですら問題外です。 

重要な観察は、ロボットが恣意的な再訪問を決して作成しないことです。 訪問セットは常に単一の連続セグメントです。 ロボットが一定の間隔を通過すると$[L, R]$、常にその端の 1 つまたはその内側に配置され、次の拡張では方向とパリティに応じて、常にこの間隔がどちらかの側でちょうど 1 セル分拡張されます。 各拡張ステップでは、新しい境界セルに到達する前に、現在の訪問セグメント内で予測可能な量の前後の移動が発生します。 

これにより、問題は、間隔が中央から外側に向かってどのように増加するかを追跡することに帰着します。 ロボットは、訪問範囲を 1 つの新しいセルだけ拡張するたびに、現在の訪問間隔のサイズに比例した決定的な量の移動を実行します。 これらの寄与を合計すると、次のもののみに基づく閉じた形式の式が得られます。$N$と初期位置を決定するため、シミュレーションの必要がなくなります。 

最後の単純化は、答えは開始セルの左右でどれだけの展開が発生するか、およびそれらが交互に発生するパターンにのみ依存するということです。 これにより、一定時間で評価できる線形算術構造が生成されます。

 ## アルゴリズムのチュートリアル

 中心となるアイデアは、プロセスを開始位置の周囲の訪問間隔を拡大するものとして再解釈することです。 

開始位置を次のようにします$s = \lceil N/2 \rceil$。 左側のセルの数を次のように定義します。$L = s - 1$、右に次のように$R = N - s$。 

訪問セグメントを一度に 1 セルずつ繰り返し拡張するプロセスをモデル化します。 各拡張は「最初の訪問」イベントに対応し、そのような各イベントは、拡張境界からの現在の距離の 2 倍に 1 つの移行ステップを加えたものに等しい予測可能な移動数に寄与します。 

## アルゴリズムのチュートリアル

 1. 開始インデックスを計算します。$s$そして導き出す$L$そして$R$。 これにより、問題はロボットが各方向にどこまで拡張する必要があるかに分割されます。 
2. ロボットは最終的にすべての場所を訪問する必要があることに注意してください。$L + R + 1 = N$セル、正確に存在することを意味します$N - 1$最初のセルからの拡張。 
3. 概念的な間隔を維持する$[l, r]$から始まる$[s, s]$。 各ステップは次のいずれかを展開します$l$または$r$外側に1つずつ。 
4. 横方向に拡張する場合、ロボットは現在の間隔全体を横断して新しい境界に到達します。 この走査には、現在の間隔の長さ (ステップ単位) が正確にかかります。 
5. 新しいセルに到達すると、ロボットは方向を反転し、次の移動では決定的なパターンで両側を交互に移動します。 
6. 交互をシミュレートする代わりに、算術寄与を別々に合計して、左右のシーケンスにグループ展開します。 
7. 各側面の拡張が一連の横断長の増加に寄与するという事実を使用して、総コストを合計します。$1, 2, 3, \dots$注文に応じて両側にあります。 

### なぜ効果があるのか

 あらゆる瞬間において、訪問したセルは連続したセグメントを形成しており、ロボットの唯一意味のある状態は、ロボットが次にどのエンドポイントに向かって拡張しているかということだけです。 「最初の訪問時に方向を反転」というルールにより、新しい境界に到達すると、ロボットは反対側に到達するために既知のセグメント全体を再度横断する必要があることが保証されます。 これにより、内部パスの履歴ではなく、開始点の左右にあるセルの数のみに依存する決定的な交代パターンが強制されます。 すべての移動はセグメントを拡張するかセグメントを完全に横断するため、合計作業量は拡張中のセグメントの長さの合計となり、単純な等差数列を形成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        if n == 1:
            print(0)
            continue

        s = (n + 1) // 2
        L = s - 1
        R = n - s

        # cost of expanding one side contributes triangular sums
        # total cost becomes sum of first L + R integers
        ans = (L + R) * (L + R + 1) // 2
        print(ans)

if __name__ == "__main__":
    solve()
```実装は、移動が必要ない単純な単一セルのケースを処理することから始まります。 中間点は、整数の天井除算を使用して計算されます。 そこから、各側にいくつのセルが存在するかを導き出します。 

コードで使用される重要な簡略化は、展開の総数が$N - 1$、各拡張は、ロボットがすでにどこまで進歩したかに応じてコストの増加に寄与します。 これは、次の三角数式に折りたたまれます。$N - 1$なぜなら、すべての新しいセルは、現在訪問しているサイズに厳密に増加する形で比例するトラバースを必要とするからです。 

唯一の微妙な点は、正しい中間点の計算を保証することです。 使用する$(n+1)//2$偶数と奇数の両方でオフバイワンエラーを回避します$N$。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())

 ## 特殊なケース

 のために$N = 1$、ロボットはすでに廊下全体をカバーし始めているため、移動は発生しません。 アルゴリズムは明示的にゼロを返します。これは、次の事実と一致します。$L = R = 0$。 

のために$N = 2$、中点はセル 1 であり、次のようになります。$L = 0$、$R = 1$。 式の結果は次のとおりです$(1 \cdot 2)/2 = 1$これは、すべてのセルにアクセスする前に右に 1 回移動することに相当します。 

非常に大きい場合$N$、 のような$10^9$、最大の整数の乗算のみが含まれるため、計算は安定したままになります。$10^9$、64ビットの制限内に十分収まります。 シミュレーションがないためパフォーマンスの低下はなく、算術構造により Python のオーバーフローの問題が完全に回避されます。
