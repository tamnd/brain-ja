 ## 解決策
 ## 問題の理解

 グリッド上に水平 2 行の点が与えられます。 1 つのチームがポジションの下端に立っています$(1,0)$を通して$(n,0)$、他のチームは真上に立っています$(1,n)$を通して$(n,n)$。 最下位のすべてのプレイヤーは、対応する列に向かって垂直レーザーを真上に発射します。 

これら 2 つの列の間には、水平の壁セグメントがあります。 各壁は一定の高さに固定されています$y$x 座標の間隔にまたがる$[x_1, x_2]$。 これらの壁は重ならず、互いに接触することはありません。 

重要な仕組みは、垂直レーザーが壁セグメントに当たったときに何が起こるかです。 ビームは単に止まるわけではありません。 代わりに、ヒット ポイントで切断され、セグメントの 2 つの端点から始まり、同じ垂直方向に上向きに続く 2 つの新しいビームに置き換えられます。 これにより、単一のビームが上の複数の壁と相互作用するときに複数のビームに分割されるカスケード効果が作成されます。 

目標は、すべての可能な分割イベントが最初のすべてのプレイヤーに適用された後、少なくとも 1 つのレーザー ビームが到達した最上列のプレイヤーの数を決定することです。$n$梁。 

制約は、合計が$n$テストケース全体で最大$2 \cdot 10^5$、壁の数は最大で$n$。 ビーム分割を明示的にシミュレートするソリューションは、1 つのビームが繰り返し分岐する可能性があり、密な構成では二次関数またはさらに悪い動作を引き起こす可能性があるため、非常に遅くなります。 目的のソリューションでは、繰り返しの分割の影響を、ほぼ直線的な時間で効率的に更新およびクエリできる構造に圧縮する必要があります。 

微妙なエッジ ケースは、梁が複数のレベルにわたって繰り返し分割されるように配置された壁から発生し、単一の柱から開始した場合でも上部の広い範囲をカバーする可能性があります。 単純なシミュレーションでは、各ビームがその柱内に留まるか、壁ごとに 1 回だけ分割されると誤って仮定する可能性があり、再帰的伝播を見逃してしまいます。 

## アプローチ

 直接シミュレーションは以下から始まります$n$垂直ビームを作成し、レベルごとに処理します。 梁が壁セグメントに当たるたびに、その梁を端点の 2 つの梁に置き換えます。 最悪の場合、単一のビームがすべての壁に当たる可能性があり、各ヒットごとにアクティブなビームの数が 2 倍になります。 と$q$これにより、ビームの数が指数関数的に増加し、総処理コストがすぐに実行不能になります。 

失敗点は、個々のビームを追跡しているのに、多くのビームが次にどこに行くかという点で冗長であることです。 連続した X 範囲内のすべてのビームは同じように動作します。ビームは常に次の同じ壁構造に当たり、同じ伝播パターンを生成します。 これは、ビームを個別に追跡するのをやめ、代わりに x 座標のどの間隔が「アクティブ」であるかを追跡する必要があることを示唆しています。 

重要な観察は、壁は隣接するアクティブなセグメント間の境界を作成または破壊するだけであるということです。 各壁はセグメントを最大 2 つの独立したセグメントに効果的に分割し、これらのセグメントはその後独立して進化します。 これは、X 軸のアクティブな間隔への動的な分割を維持し、高さによってソートされた壁を通してこれらの間隔がどのように変化するかをシミュレートできることを意味します。 

壁を昇順に処理します。$y$。 各壁で、その間隔内にアクティブなビームが何本存在するかを調べます。$[x_1, x_2]$。 その間隔内のすべてのアクティブなビームはエンドポイントで新しいビームを生成するため、その間隔が以前にアクティブであった場合、その効果はエンドポイントをアクティブにするのと同等です。 壁は重なったり端点を共有したりしないため、これらの更新があいまいな形で干渉することはありません。 

アクティブなセグメントを効率的に維持し、到達可能な上位の位置をカウントするには、差分配列またはセグメント アクティベーション構造を使用できます。 このプロセスは、範囲をマークし、エンドポイントのアクティベーションを上方に伝播することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(2^q) 最悪の場合 | O(n) | 遅すぎる |
 | インターバル伝播 (スイープ + DSU/アレイ) | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 このプロセスを、x 座標に沿った到達可能性の伝播として再解釈します。壁は、その端点に到達可能性の新しいソースを導入するだけです。 

1. すべての壁を Y 座標の増加順に並べ替えます。 

これにより、物理的に壁にぶつかるのと同じ順序で梁の上向きの動きが確実にシミュレートされます。 
2. 配列を維持する`reach[i]`位置かどうかを示す$i$一番下の行では、最終的に構造を通って上に到達するビームを生成できます。 

最初は、すべてのプレイヤーがビームを発射するため、すべての最下位ポジションがアクティブになります。 
3. 壁ごとに$[x_1, x_2]$、このセグメントが「アクティブ化」されているかどうか、つまり少なくとも 1 つのビームが現在そのセグメントを通過しているかどうかを判断します。 

ビームがこのセグメントに到達しない場合、システムに影響はありません。 
4. セグメントがアクティブ化されている場合は、両方のエンドポイントをマークします。$x_1$そして$x_2$アクティブなソースとして。 

これは分割ルールをモデル化します。セグメントに当たるビームは両方の端点で上向きに続くビームを生成します。 
5. 壁の処理を順番に続けて、新しくアクティブ化されたエンドポイントが後の壁に寄与できるようにします。 
6. 最後に、少なくとも 1 つのアクティブなソースから到達可能な上位の位置がいくつあるかを数えます。 

重要な削減点は、ビーム経路をシミュレートする代わりに、到達可能な壁セグメントによって引き起こされるエンドポイントの活性化のみを伝播することです。 

### なぜ効果があるのか

 システムは、どの x 位置がビームをより高いレベルに送信できるかによって完全に決定されます。 梁は壁に衝突したときにのみ動作を変更し、そのイベントはその X 座標が壁セグメントの内側にあるかどうかのみに依存します。 同じ x 位置にあるすべてのビームは同じように動作し、壁が重なり合うことがないため、プロセスは独立した間隔のアクティベーションに分解されます。 各分割ではエンドポイントのみが導入され、既存のセグメントを超えて新しい内部動作が作成されることはありません。 これにより、エンドポイントのアクティブ化を追跡するだけで将来のすべてのビーム経路を再構築できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    walls = []
    for _ in range(q):
        x1, x2, y = map(int, input().split())
        walls.append((y, x1, x2))
    
    walls.sort()
    
    active = [False] * (n + 1)
    for i in range(1, n + 1):
        active[i] = True
    
    changed = True
    
    while changed:
        changed = False
        for y, l, r in walls:
            # check if any active point exists in [l, r]
            if any(active[i] for i in range(l, r + 1)):
                if not active[l]:
                    active[l] = True
                    changed = True
                if not active[r]:
                    active[r] = True
                    changed = True
    
    print(sum(active[1:]))

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```この実装は、壁のエンドポイントを通じてアクティベーションを伝播するというアイデアに直接従っています。 配列`active`は、現在どの x 位置が上向きに継続できるビームを生成しているかを表します。 各壁について、その間隔をスキャンして、アクティブなビームが当たっているかどうかを確認します。 その場合は、両方のエンドポイントをアクティブ化します。 

繰り返された`changed`新しくアクティブ化されたエンドポイントにより、以前は非アクティブだった壁が関連するようになる可能性があるため、ループが必要です。 これは、問題で説明されているカスケード分割動作を反映しています。 

実装上の微妙な懸念事項は範囲チェックです。`any(active[i] for i in range(l, r + 1))`、これは壁ごとに線形であり、不注意に実装すると遅くなる可能性があります。 意図したソリューションでは、これをセグメント ツリーまたは差分構造に置き換えることになりますが、ロジックは同じであり、アクティブ セットと壁間隔の間の交差を検出します。 

## 実用的な例

 次のような小さなセットアップを考えてみましょう$n = 5$そして2つの壁：$[2,4]$で$y=1$そして$[4,5]$で$y=2$。 

各反復後にアクティブなポジションを追跡します。 

| ステップ | アクティブセット | 壁加工 | 効果 |
 | --- | --- | --- | --- |
 | 初期化 | {1,2,3,4,5} | - | すべてのビームがアクティブになります |
 | 1 | {1,2,3,4,5} | [2,4] | アクティブ化、2 と 4 を追加 (変更なし) |
 | 2 | {1,2,3,4,5} | [4,5] | アクティブ化、4 と 5 を追加 (変更なし) |

 これは、すべての位置が到達可能なままである場合を示しているため、最終的な答えは 5 になります。 

ここで考えてみましょう$n = 5$、壁$[2,3]$そして$[4,5]$, ただし初回起動は2時のみ。 

| ステップ | アクティブセット | 壁加工 | 効果 |
 | --- | --- | --- | --- |
 | 初期化 | {1,2,3,4,5} | - | フルスタート |
 | 1 | {1,2,3,4,5} | [2,3] | 2 と 3 を強化します |

 ここでの伝播は些細なものですが、この構造は、エンドポイントがどのように後のアクティブ化を促進するかを示しています。 

これらのトレースは、インターバルの交差によってトリガーされるエンドポイント拡張の下でシステムがクロージャとして動作することを確認します。

 ## 特殊なケース

 エッジ ケースの 1 つは、ほぼ全範囲にわたる単一の壁です。たとえば、$n = 5$、 壁$[1,5]$。 すべてのビームがこの壁に当たるため、両方のエンドポイントがアクティブになります。 この場合、エンドポイントはすでにアクティブであるため、変化は起こらず、答えは 5 のままです。分割を内部ビームの削除として扱う単純なシミュレーションでは、到達可能な位置が誤って減少する可能性があります。 

もう 1 つのエッジ ケースは、次のようなネストされた壁のチェーンです。$[1,3]$、$[2,4]$、$[3,5]$。 中央領域にビームが入ると、エンドポイントのアクティベーションが繰り返され、最終的にはすべての位置がアクティブになります。 伝播順序なしで壁を独立して処理するアプローチでは、この閉鎖効果を捉えることができません。 

3 番目のケースは、X 範囲で分離された孤立した壁です。 例えば$[1,2]$そして$[4,5]$。 これらは独立して動作し、アクティベーションを共有しないため、到達可能な最終セットは単にエンドポイント クロージャの結合になります。 正しい解決策では、グローバルな伝播の仮定により誤ってそれらをマージすることを回避する必要があります。
