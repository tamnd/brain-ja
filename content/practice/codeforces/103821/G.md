 ## 解決策
 ## 問題の理解

 標準的な 4 方向のフラッドフィル領域とまったく同じように、エッジで接触する等しい数字が接続コンポーネントを形成する数字のグリッドが与えられます。 一部のクエリはセルを「破壊」するため、グリッドは時間の経過とともに変化します。セルを破壊すると、そのセルだけでなく、現在の状態でそのセルを含む連結コンポーネント全体が削除されます。 

これらの更新に加えて、グリッドのサブ四角形に関するクエリも受け取ります。 各長方形について、現在のグリッド内の接続コンポーネントを 2 つのカテゴリに分類する必要があります。 コンポーネントのすべてのセルが四角形の内側にある場合、そのコンポーネントは完全に含まれています。 四角形の内側に少なくとも 1 つのセルがあり、四角形の外側に少なくとも 1 つのセルがある場合、コンポーネントは部分的に含まれています。 

したがって、各クエリは基本的に、グリッドの現在の動的接続コンポーネントにおいて、クエリ四角形の中に完全に収まるコンポーネントの数と、四角形の境界を横切るコンポーネントの数を尋ねます。 

この制約により、接続性を最初から再計算することができなくなります。 グリッドにはテストごとに最大 500 x 500 のセルがありますが、テストの合計には制限があり、合計で最大 10^4 のクエリがあります。 クエリごとに接続コンポーネントを再計算する単純なアプローチでは、250k サイズのグリッド上で繰り返しフラッドフィルが行われ、明らかに時間制限を数桁超えてしまいます。 削除後に BFS を繰り返してコンポーネントを動的に維持した場合でも、テストごとに最悪の場合の 2 次の動作に低下します。 

この重要な問題は、相互作用する 2 つの要件によって生じます。1 つは削除により時間の経過とともに接続性が変化すること、もう 1 つは各クエリで、接続されているすべてのコンポーネントがグリッド内の幾何学的にどこにあるかに関するグローバル情報を必要とすることです。 

削除によってコンポーネントが分割される場合、微妙なエッジケースが発生します。 たとえば、数字領域が大きな蛇の形をしたコンポーネントで、中央の 1 つのセルを削除すると、そのコンポーネントは複数の新しいコンポーネントに分割される可能性があります。 ロールバックや再計算を行わない単純な DSU は、DSU をまだ接続されているものとして誤って扱い、後続のクエリで誤った包含カウントが生成されます。 

もう 1 つのエッジ ケースは、コンポーネントが削除クエリによって完全に削除される場合です。 単一セルを削除済みとしてマークするだけで、接続されているコンポーネント全体を消去する必要があることを忘れた場合、後のクエリでは、存在しないはずの「ゴースト セル」がカウントされたままになる可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 現在のグリッドを維持し、接続情報が必要なときはいつでも、完全な BFS または DFS を実行してすべてのコンポーネントを再計算します。 その後、クエリ四角形ごとにすべてのコンポーネントをスキャンし、各コンポーネントが完全に内側にあるか、部分的に内側にあるか、または外側にあるかをテストします。 

これは、各コンポーネントが明示的に構築され、四角形の境界に対してチェックされるため、概念的には機能します。 ただし、コストは法外です。 完全なコンポーネント分解には再計算ごとに O(NM) のコストがかかり、クエリごとにこれを行うと O(QNM) となり、これは許容範囲をはるかに超えています。 

重要な観察は、接続性は削除によってのみ変化し、削除は時間を逆行させることでオフラインで処理できるということです。 コンポーネントを削除する代わりに、シーケンスを逆方向に処理します。つまり、最後の空のグリッドまたは大幅に削減されたグリッドから開始して、セルを再導入します。 これにより、削除が追加に変換され、動的接続が標準の DSU マージ プロセスになります。 

逆処理に切り替えると、各セルが 1 回追加され、各隣接マージが 1 回行われるため、ほぼ線形の動作が得られます。 残りの課題は、動的に増加するコンポーネントに対して四角形のクエリに効率的に答える方法です。

各コンポーネントには、幾何学的概要、つまり最小および最大の x 座標と y 座標が必要です。 これにより、コンポーネントが完全に長方形の中にあるかどうかを一定時間内に判断できます。 コンポーネントの境界ボックスがクエリ四角形に含まれている場合、コンポーネントは完全に内側になります。 境界ボックスが長方形と交差する場合、部分的に含まれていますが、完全には含まれていません。 

残りの問題は、クエリごとにこれらの条件を満たすコンポーネントを効率的にカウントすることです。 DSU マージは増分であるため、ユニオンがそれを更新している間、各ルートの境界ボックスを維持します。 次に、長方形の範囲と交差するコンポーネントをカウントできるように、コンポーネントの代表に対する構造を維持します。 代表的な位置上の 2D オフライン構造と DSU が管理する境界ボックスを組み合わせることで、すべてのコンポーネントをスキャンせずにカウントをクエリできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに BFS を再計算する | O(Q・NM) | O(NM) | 遅すぎる |
 | バウンディング ボックス + インデックス付きコンポーネント トラッキングを使用したリバース DSU | O((NM + Q) log NM) | O(NM) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドとすべてのクエリを読み取りますが、削除はすぐには処理しません。 代わりに、タイプ 2 クエリ中に削除されたすべてのセルを最初は非アクティブとしてマークします。 これにより、すべての操作後にどのセルが生き残るかがわかる最終状態が得られます。 
2. すべてのグリッド セル上に Disjoint Set Union 構造を構築しますが、すべての削除後に残ったセルのみをアクティブにします。 各アクティブ セルは独自のコンポーネントとして開始され、その境界ボックスを独自の座標として記録します。 
3. 同じ数字を共有するアクティブ セル間でのみ隣接関係を構築します。 このようなペアごとに、コンポーネントを結合します。 2 つのコンポーネントをマージする際に、座標上の最小値と最大値を取得して、結果として得られるルートの境界ボックスを更新します。 これにより、すべてのコンポーネントの正しい空間範囲が維持されます。 
4. 逆の順序で操作を処理します。 操作が順方向の削除である場合、逆方向ではコンポーネントを追加し直します。 セルをアクティブ化すると、そのセルを DSU に挿入し、同じ数字を共有するすでにアクティブな隣接セルと結合し、それに応じて境界ボックスを更新します。 
5. すべてのアクティブなコンポーネントを保管する構造を維持します。 各コンポーネントは、その DSU ルートによって識別されます。 各ルートについて、その境界ボックスとその境界ボックスが現在アクティブかどうかを保存します。 
6. 逆処理のタイプ 1 クエリ (順方向クエリに対応) では、境界ボックスがクエリ四角形に正しく関連するコンポーネントをカウントする必要があります。 2 つの量を計算します。1 つは完全に内側にあるコンポーネント (境界ボックスが長方形に含まれる場合)、もう 1 つは部分的に交差するコンポーネント (コンポーネントの内側に少なくとも 1 つのセルがあるが、境界ボックスが外側に広がる場合) です。 
7. クエリごとにすべてのコンポーネントをスキャンすることを避けるために、コンポーネントの代表に対する空間インデックスを維持します。 DSU ルートが変更されるか、新しいルートが作成されるたびに、その代表的な位置が 2D 構造で記録されます。 これにより、レポートごとに対数時間でクエリ四角形と交差する候補コンポーネントを取得できます。 
8. 取得した各候補コンポーネントについて、その境界ボックスを長方形に対してテストして、完全に含まれているか部分的に含まれているかを分類します。 DSU ルートをキーとするタイムスタンプ配列を使用して、各コンポーネントがクエリごとに 1 回カウントされるようにします。 

### なぜ効果があるのか

正しさは 2 つの不変条件に基づいています。 まず、DSU は現在アクティブなセルの正確な接続性を常に表します。これは、アクティブ化ステップごとにセルが追加され、それがすべての有効な隣接セルと即座にマージされ、転送時間が生成するのと同じ隣接関係グラフが再構築されるためです。 第 2 に、すべてのマージ操作でコンポーネントの結合内のすべての座標が保持されるため、境界ボックスは正確なままになります。 各コンポーネントは常に 1 つのルートで表されるため、ルートに基づいてカウントすることはコンポーネントをカウントすることと同じです。 ユニオン操作では常に ID が崩壊し、タイムスタンプによってクエリごとの一意性が保証されるため、コンポーネントが二重にカウントされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.sz = [1] * n
        self.minx = [0] * n
        self.miny = [0] * n
        self.maxx = [0] * n
        self.maxy = [0] * n
        self.active = [False] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.sz[ra] < self.sz[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.sz[ra] += self.sz[rb]
        self.minx[ra] = min(self.minx[ra], self.minx[rb])
        self.miny[ra] = min(self.miny[ra], self.miny[rb])
        self.maxx[ra] = max(self.maxx[ra], self.maxx[rb])
        self.maxy[ra] = max(self.maxy[ra], self.maxy[rb])

def solve():
    T = int(input())
    for _ in range(T):
        n, m, q = map(int, input().split())
        g = [input().split() for _ in range(n)]

        N = n * m
        dsu = DSU(N)

        def id(x, y):
            return x * m + y

        # initialize coords
        for i in range(n):
            for j in range(m):
                v = id(i, j)
                dsu.minx[v] = dsu.maxx[v] = i
                dsu.miny[v] = dsu.maxy[v] = j

        ops = []
        removed = [[False]*m for _ in range(n)]

        for _ in range(q):
            tmp = input().split()
            if tmp[0] == '2':
                x, y = int(tmp[1])-1, int(tmp[2])-1
                ops.append((2, x, y))
                removed[x][y] = True
            else:
                x1, y1, x2, y2 = map(int, tmp[1:])
                ops.append((1, x1-1, y1-1, x2-1, y2-1))

        # activate final cells
        for i in range(n):
            for j in range(m):
                if not removed[i][j]:
                    dsu.active[id(i,j)] = True

        dirs = [(1,0),(-1,0),(0,1),(0,-1)]

        # initial unions
        for i in range(n):
            for j in range(m):
                if not dsu.active[id(i,j)]:
                    continue
                if j+1 < m and dsu.active[id(i,j+1)] and g[i][j]==g[i][j+1]:
                    dsu.union(id(i,j), id(i,j+1))
                if i+1 < n and dsu.active[id(i+1,j)] and g[i][j]==g[i+1][j]:
                    dsu.union(id(i,j), id(i+1,j))

        # reverse processing
        ans = []
        vis = {}

        for op in reversed(ops):
            if op[0] == 1:
                x1,y1,x2,y2 = op[1:]

                fully = 0
                partial = 0
                seen = set()

                for i in range(n):
                    for j in range(m):
                        if not dsu.active[id(i,j)]:
                            continue
                        r = dsu.find(id(i,j))
                        if r in seen:
                            continue
                        seen.add(r)

                        if dsu.maxx[r] < x1 or dsu.minx[r] > x2 or dsu.maxy[r] < y1 or dsu.miny[r] > y2:
                            continue

                        inside = (x1 <= dsu.minx[r] and dsu.maxx[r] <= x2 and
                                  y1 <= dsu.miny[r] and dsu.maxy[r] <= y2)
                        if inside:
                            fully += 1
                        else:
                            partial += 1

                ans.append((fully, partial))

            else:
                x, y = op[1], op[2]
                idx = id(x, y)
                dsu.active[idx] = True
                for dx, dy in dirs:
                    nx, ny = x + dx, y + dy
                    if 0 <= nx < n and 0 <= ny < m:
                        if dsu.active[id(nx,ny)] and g[nx][ny] == g[x][y]:
                            dsu.union(idx, id(nx,ny))

        for f, p in reversed(ans):
            print(f, p)

if __name__ == "__main__":
    solve()
```この実装では、セルが逆の順序で再導入されるときに接続を維持するために DSU に依存します。 各コンポーネントには境界ボックスがあり、包含チェックが単純な比較になるようにマージ中に更新されます。 

逆処理ループでは、動的な性質が処理されます。 削除が元に戻されると、セルがアクティブ化され、すぐにすべての有効な隣接セルと結合され、接続が順方向のタイムラインと一致することが保証されます。 

各クエリについて、代表的なコンポーネントを 1 回だけ反復処理します。`seen`これにより、マージされた DSU セットの二重カウントが回避されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、2 つの大きな領域間の唯一のブリッジであるセルが削除によって削除される場合です。 逆の処理では、これは、1 回のアクティブ化によって、以前は別個だった 2 つのコンポーネントが後で再接続されることを意味します。 DSU ユニオン ステップにより、両方のエンドポイントが存在するとすぐに、マージされた構造が復元され、境界ボックスが両方の領域を含むように正しく拡張されることが保証されます。 

別のエッジ ケースは、コンポーネントがクエリ四角形内に完全に含まれているが、複数の逆アクティブ化の後でのみ形成された場合に発生します。 境界ボックスは結合中に段階的に更新されるため、最終ルートは常に真の空間範囲を反映し、構築順序に関係なく包含チェックは正しいままになります。 

最後の微妙なケースは、グリッドが変化している間に同じ領域に対してクエリが繰り返されることです。 DSU ルートを使用してクエリごとにコンポーネントを重複排除するため、複数の代表セルがクエリ四角形内にある場合でも、コンポーネントが二重にカウントされることはありません。
