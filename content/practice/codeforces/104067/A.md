 ## 問題の理解

 小さな整数範囲にわたる複数の独立したクエリが与えられます。 各クエリは間隔を提供します$[l, r]$そして数字$k$。 すべての整数に対して$x$、それを素因数分解し、その因数分解で素因数がいくつ現れるかを数え、多重度を数えます。 それで$12 = 2^2 \cdot 3$貢献する$3$要因、一方で$18 = 2 \cdot 3^2$も貢献します$3$。 

番号が呼ばれます$k$- この素因数の数が正確であれば「怖い」$k$。 クエリごとに、指定されたセグメント内の整数が正確にいくつあるかをカウントする必要があります。$k$素因数。 

入力制約によって、すでにソリューションが強力に形成されています。 の値$l$そして$r$せいぜい$10^5$したがって、数値の世界は十分に小さいため、すべての整数のプロパティを 1 回前処理できます。 ただし、クエリの数は多く、最大$10^5$そのため、クエリごとに因数分解を再計算すると時間がかかりすぎます。 すべてのクエリのすべての数値を因数分解する単純なアプローチでは、おおよその結果が得られます。$10^5 \times 10^5$これは許容範囲をはるかに超えています。 

パラメータ$k$も小さく、16 で区切られています。これは、素因数の数の分布が浅く、効率的に事前計算できることを示唆しています。 

1 のような小さな数字には、微妙なエッジ ケースが発生します。数字 1 には素因数がありません。 クエリで要求された場合$k = 0$、それはカウントされるべきですが、多くの単純な実装では、素数分解がないため 1 を完全に無視します。 もう 1 つの問題は、多重度を正しくカウントすることです。 たとえば、8 は 1 ではなく 3 を寄与する必要があります。$8 = 2^3$。 ここで間違いがあると、組織的な過小カウントにつながります。 

## アプローチ

 ブルート フォース ソリューションは、すべての数値を因数分解して各クエリを直接処理します。$[l, r]$トライアル分割を使用します。 これは概念的には簡単です。数値ごとに、素数で繰り返し割り、因数を数えます。 それは正しいですが、そのコストは因数分解の繰り返しによって決まります。 ふるいを使ってもこうすると$10^5$一定範囲のサイズで何倍にもなる$10^5$結果は約$10^{10}$最悪の場合、操作が不可能になる場合があります。 

重要な観察は、すべての数値が固定された小さな範囲内にあるため、その素因数の数を 1 回で事前計算できることです。 クエリごとに因数分解を再計算する代わりに、関数を計算します。$f[x]$の素因数の数に等しい$x$。 この配列が判明すると、各クエリは静的配列に対する範囲カウントの問題になります。 

多くのクエリにわたる範囲カウントは、プレフィックス合計を使用して効率的に処理されます。 可能なすべての値に対して、$k$、プレフィックス配列を構築します$pref[k][x]$最大何個の数値を保存します$x$まさに持っています$k$素因数。 その後、各クエリは定数時間の減算に帰着します。 

これにより、問題は繰り返しの数論計算から前処理ステップと高速検索に変換されます。

 ## アルゴリズムのチュートリアル

 までのすべての数値を前処理します。$N = 10^5$。 

1. アレイを構築する`spf`または、ふるいのような方法を使用して最小の素数を直接計算し、各数値をすばやく因数分解できます。 これにより、すべての数値について割り算チェックを最初から再計算する必要がなくなります。 
2. 各整数について$x$2から$N$、多重度を使用して素因数の合計数を計算します。 分裂を繰り返す$x$最小の素因数で計算し、カウントを累積します。 これにより値が生成されます`cnt[x]`。 
3.以来$k$最大でも 16 である場合、考えられるそれぞれのプレフィックスの合計を構築します。$k$。 保守します`pref[k][i]`に数値をいくつ保存するか$[1, i]$まさに持っています$k$素因数。 以前の値を伝播し、次の場合に 1 を追加することで、段階的に埋めていきます。`cnt[i] == k`。 
4. 各クエリについて$(l, r, k)$、次を使用して定数時間で応答します。$$pref[k][r] - pref[k][l-1]$$5. 各クエリの結果を出力します。 

実装上の主な関心事は、因数分解を線形または線形に近い状態に保つことです。 最小素因数前処理を使用すると、実際には各数値が対数時間で分解されます。 

### なぜ効果があるのか

 正確さは 2 つの不変条件に依存します。 初め、`cnt[x]`は正確に次の素因数の合計数です$x$というのは、除算の各ステップで正確に 1 つの素因数が削除され、すべての因数が最小の素数による繰り返し除算によって説明されるからです。 第 2 に、プレフィックス配列は、それぞれの出現回数の累積数を維持します。$k$-クラス。 各整数は独立して 1 つの整数に寄与するため、$k$、プレフィックスの違いにより、重複や省略がなく、あらゆるセグメントにわたるカウントが正確に分離されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

N = 100000

spf = list(range(N + 1))

for i in range(2, int(N ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, N + 1, i):
            if spf[j] == j:
                spf[j] = i

cnt = [0] * (N + 1)

for i in range(2, N + 1):
    x = i
    c = 0
    while x > 1:
        p = spf[x]
        while x % p == 0:
            x //= p
            c += 1
    cnt[i] = c

MAXK = 16
pref = [[0] * (N + 1) for _ in range(MAXK + 1)]

for i in range(1, N + 1):
    for k in range(MAXK + 1):
        pref[k][i] = pref[k][i - 1]
    k = cnt[i]
    if k <= MAXK:
        pref[k][i] += 1

q = int(input())
out = []

for _ in range(q):
    l, r, k = map(int, input().split())
    if k > MAXK:
        out.append("0")
    else:
        out.append(str(pref[k][r] - pref[k][l - 1]))

print("\n".join(out))
```このソリューションでは、まず最小の素因数を構築して、因数分解が決定的かつ高速になるようにします。 次に、各数値がその素数成分に還元され、単なる個別の素数ではなく多重度が正しく累積されます。 プレフィックス テーブルは、各行が固定の番号に対応するように構築されています。$k$したがって、クエリではスキャン範囲が必要ありません。 

実装でよくある落とし穴は、1 が寄与する要素が 0 であることを忘れることです。 ここでは自然に処理されますので、`cnt[1]`はゼロのままで、次のプレフィックスに含まれます。$k = 0$。 

もう 1 つの微妙な問題は、プレフィックス配列を効率的に更新することです。 すべてのフルカウントを再計算する$k$インデックスごとに独立して実行すると遅すぎます。 代わりに、以前のプレフィックス値をコピーし、関連する値のみを更新します。$k$インデックスごとのバケット。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from math import isclose

    N = 100000
    spf = list(range(N + 1))
    for i in range(2, int(N ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, N + 1, i):
                if spf[j] == j:
                    spf[j] = i

    cnt = [0] * (N + 1)
    for i in range(2, N + 1):
        x = i
        c = 0
        while x > 1:
            p = spf[x]
            while x % p == 0:
                x //= p
                c += 1
        cnt[i] = c

    MAXK = 16
    pref = [[0] * (N + 1) for _ in range(MAXK + 1)]

    for i in range(1, N + 1):
        for k in range(MAXK + 1):
            pref[k][i] = pref[k][i - 1]
        k = cnt[i]
        if k <= MAXK:

    q = int(_sys.stdin.readline())
    out = []
    for _ in range(q):

        if k > MAXK:
            out.append("0")
        else:
            out.append(str(pref[k][r] - pref[k][l - 1]))
    return "\n".join(out)

 ## 特殊なケース

 値 1 の場合、アルゴリズムは次の値を割り当てます。`cnt[1] = 0`初期化を通じて暗黙的に。 クエリが要求するとき$k = 0$、ゼロクラス バケットに 1 回だけ寄与するため、プレフィックス配列には正しく 1 が含まれます。 

大型用$k$15 や 16 などの値を指定すると、範囲内の多くの数値がその係数数に達しません。 これらのバケットは前処理を通じてゼロのままであるため、プレフィックス テーブルは引き続きそれらを安全に処理します。そのため、特別な場合のロジックを使用せずに減算するとゼロが得られます。 

によるクエリ$l = 1$アクセスに依存する`pref[k][0]`。 プレフィックス配列はインデックス 0 のゼロで初期化されるため、減算は`pref[k][r] - pref[k][0]`アンダーフローやインデックス作成エラーなしで、全範囲のカウントを正しく返します。
