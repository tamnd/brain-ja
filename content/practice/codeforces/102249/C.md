 ## 問題の理解

 1 つの変数を含む有効なブール式が与えられています。`x`、その否定`X`、定数`0`そして`1`、および二項演算子`&`、`|`、 そして`^`。 括弧は式ツリーを決定します。 

単一の文字を別の文字に置き換えることはできますが、文字の挿入や削除はできません。 すべての変更を行った後でも、結果は有効な式でなければなりません。 目標は、式全体の値を独立したものにすることです。`x`できるだけ少ない変更を加えます。 

ブール変数は 1 つだけであるため、すべての式は、可能な 4 つのブール関数のうちの 1 つを表します。`0`、これは常に false です。`1`、これは常に真実です。`x`、これは偽です`x = 0`そして真実です`x = 1`。`X`、これは当てはまります`x = 0`そして偽`x = 1`。 

これは、式を 2 回評価することを直ちに示唆します (1 回目は )。`x = 0`そして一度一緒に`x = 1`。 2 つの結果が等しい場合、式はすでに次から独立しています。`x`, したがって、答えはゼロです。 

興味深いのは、2 つの結果が異なる場合、常に 1 つの変更で十分であることを証明していることです。 この観察により、大規模な動的プログラムや変更の可能性を検索する必要がなくなりました。 

式の長さは最大 300 で、テスト ケースの数は最大 500 です。 テスト ケースごとのリニア スキャンは簡単に手頃な価格で実行できます。 通常、二次アルゴリズムでもこれらの範囲には十分小さいですが、問題の構造により、はるかに優れた処理が可能になります。 さらに重要なことは、変更された式に対する指数関数的な検索は完全に不可能であるということです。 式 alphabet には 9 つの可能な文字が含まれるため、長さ 300 の文字列をすべて列挙するには、最大 (9^{300})、およそ (3.4 \times 10^{286}) 個の候補を検討する必要があります。

 ## アプローチ

 直接的なブルート フォース アプローチでは、文字を変更して取得できるすべての文字列を試し、結果の文字列が有効な式であるかどうかを確認し、次の両方の値について評価します。`x`、変更される位置の最小数を維持します。 これは正しいです。許可されたすべての変更シーケンスが 1 つの候補文字列に対応するため、徹底的な検索によって最終的に最適な答えが考慮されます。 

問題は候補者の数だ。 式のアルファベットには 9 つの文字が使用できます。`x`、`X`、`0`、`1`、`|`、`&`、`^`、`(`、 そして`)`。 すべての位置にそれらのいずれかを含めることができる場合、長さ (n) の (9^n) 個の文字列が存在します。 最大長 (n=300) では、約 (3.4 \times 10^{286}) 個の文字列になります。 一定時間内に 1 つの候補をチェックすることさえ絶望的であり、実際に候補を検証して評価するのには (O(n)) のコストがかかり、合計の作業量はおおよそ (O(n9^n)) になります。 

答えが有効な定数式までの最小ハミング距離によって定義されるため、総当り攻撃は機能しますが、可能な文字列のスペースが膨大であるため失敗します。 重要な点は、実際には変更された式を構築する必要がないということです。 

元の式がすでに定数であると仮定します。 その場合、答えは明らかにゼロです。 

ここで、その値が次のものに依存すると仮定します。`x`。 構造上の可能性は 2 つだけです。 

式が単一の項で構成されている場合は、次のいずれかである必要があります。`x`または`X`、 なぜなら`0`そして`1`はすでに一定です。 その 1 文字を次のように変更すると、`0`または`1`定数式を生成します。 したがって、1 つの変更で十分です。 

式に二項演算が含まれている場合は、そのルートを考慮します。 根は次のような形をしています`(A op B)`、 どこ`A`そして`B`は有効な表現です。 各子は、前にリストした 4 つのブール関数の 1 つを表します。 

1 つの変数の 2 つのブール関数の場合、次の少なくとも 1 つ`&`、`|`、 そして`^`それらの組み合わせを一定にします。 これは可能な形式から直接見ることができます。 

いずれかのオペランドが定数の場合`0`、選択する`&`結果を生む`0`。 

いずれかのオペランドが定数の場合`1`、選択する`|`結果を生む`1`。 

2 つのオペランドが同じ非定数関数である場合、`^`キャンセルさせます。 例えば、`x^x = 0`そして`X^X = 0`。 

オペランドが`x`そして`X`、選択する`&`与える`0`、選択しながら`|`または`^`与える`1`。 

したがって、バイナリ式がまだ定数でない場合は、ルート演算子のみを変更するだけで定数にできます。 この問題では最小限の変更のみが求められるため、どの演算子を使用するかを見つける必要さえありません。 

その結果、問題全体は 1 つの質問に集約されます。元の式は次の場合と同じブール値に評価されますか?`x = 0`そして`x = 1`? 「はい」の場合は答えてください`0`。 それ以外の場合は答えてください`1`。

 ## アルゴリズムのチュートリアル

 1. 式を解析し、すべての部分式を両方の可能な値について評価します。`x`。 部分式の結果をペアとして表現します`(value_when_x_is_0, value_when_x_is_1)`。 例えば、`x`は`(0, 1)`、`X`は`(1, 0)`、`0`は`(0, 0)`、 そして`1`は`(1, 1)`。 
2. パーサーがバイナリ式に遭遇したとき`(A op B)`、次の 2 つの結果のペアを再帰的に取得します。`A`そして`B`。 同じブール演算子を 2 つの座標に個別に適用します。 これが機能するのは、式が独立して評価されるためです。`x = 0`そして`x = 1`。 
3. 完全な式を解析した後、結果のペアを検査します。 両方の座標が等しい場合、式は、可能な両方の値に対して同じ値を持ちます。`x`したがって、それはすでに定数であり、答えは次のようになります。`0`。 
4. 座標が異なる場合、式は不定になります。 式が 1 文字の場合は、次のようにする必要があります。`x`または`X`に変更します`0`または`1`1 回の編集で一定になります。 
5. 式がバイナリの場合は、ルート演算子のみを変更します。 2 つの子関数について、少なくとも 1 つ`&`、`|`、 そして`^`は定数関数を生成するため、1 回の編集で十分です。 
6. 非定数式では編集をゼロにすることはできず、常に 1 回の編集で十分であるため、出力`1`非定数の場合。 

### なぜ効果があるのか

 パーサーは、すべての部分式で表され、その値によってエンコードされた正確なブール関数を計算します。`x = 0`そして`x = 1`。 したがって、元の式が独立している場合、ルートのペアは正確に等しくなります。`x`。 

ペアが等しい場合、変更はゼロで十分かつ最適です。 異なる場合、ゼロの変更は機能しないため、少なくとも 1 つの変更が必要です。 1 文字の解決策が常に存在します。葉の場合は、replace`x`または`X`定数付き。 バイナリ式の場合は、ルート演算子を、2 つの子関数を結合して定数にする演算子に置き換えます。 したがって、すべての非定数式には、最小の答えが 1 つだけあります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def evaluate(expr):
    n = len(expr)
    pos = 0

    def parse():
        nonlocal pos

        c = expr[pos]

        if c == '0':
            pos += 1
            return (0, 0)

        if c == '1':
            pos += 1
            return (1, 1)

        if c == 'x':
            pos += 1
            return (0, 1)

        if c == 'X':
            pos += 1
            return (1, 0)

        # c == '('
        pos += 1

        left = parse()
        op = expr[pos]
        pos += 1
        right = parse()

        pos += 1  # ')'

        a0, a1 = left
        b0, b1 = right

        if op == '&':
            return (a0 & b0, a1 & b1)

        if op == '|':
            return (a0 | b0, a1 | b1)

        return (a0 ^ b0, a1 ^ b1)

    return parse()

def solve():
    t = int(input())
    out = []

    for case in range(1, t + 1):
        expr = input().strip()
        v0, v1 = evaluate(expr)

        if v0 == v1:
            ans = 0
        else:
            ans = 1

        out.append(f"Case #{case}: {ans}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`evaluate`関数は再帰降下パーサーです。 入力は有効な式であることが保証されているため、パーサーは不正な構文を回復する必要がありません。 

終端文字の場合、関数はグローバル位置を 1 つ進め、2 つのブール値を返します。 ペア表現により、`x`そして`X`特に便利:`x`になる`(0, 1)`そして`X`になる`(1, 0)`。 

パーサーが見るとき`(`、最初に左側の式を解析し、次に演算子を 1 つだけ読み取り、次に右側の式を解析し、最後に最後の式を消費します。`)`。 式の文法は正確であるため、順序は重要です。`(left operator right)`。 

2 つの子は座標ごとに結合されます。 たとえば、左の子が`(0, 1)`そして右の子は`(1, 0)`、次に彼らの`&`結果は`(0 & 1, 1 & 0) = (0, 0)`。 

仮説の変更後に式を明示的に構築する必要はありません。 上記の証明は、非定数式を 1 回の編集で常に定数にできることを保証します。 したがって、コードに必要なのは最後のペアのみであり、どの文字が実際に変更されるかを決定する必要はありません。 

ネストの最大の深さは式の長さによって制限され、最大でも 300 であるため、Python の再帰制限は問題なく十分です。 大きな整数の計算はないため、整数のオーバーフローは無関係です。
