 ## 解決策
 ## 問題の理解

 文字列で表されたスイレンの列があります。 最初の文字は常に`A`、アルファ カエルを表し、その後のすべての文字は次のいずれかです。`B`、ベータカエルを表す、または`.`、空のパッドを表します。 

アルファ フロッグは最初のパッドからスタートし、最後のパッドに到達したいと考えています。 ベータ フロッグは、隣接する空のパッドに 1 つの位置を移動できます。 アルファ フロッグは別の動きをします。1 つまたは複数のベータ フロッグの連続するブロックを飛び越えて、そのブロックの直後に最初の空のパッドに着地する場合があります。 最初の章とは異なり、アルファフロッグはどちらの方向にもジャンプできます。 我々が判断する必要があるのは、一連の協力的な動きによって最終的にアルファを最後のパッドに配置できるかどうかだけです。 

テスト ケースごとに、入力によりそのような文字列が 1 つ与えられます。 出力は`Y`アルファフロッグが右端のパッドに到達できれば、`N`さもないと。 

長さは最大 5,000 まで可能で、テスト ケースは最大 500 個まで存在できます。 可能な配置の数はパッドの数に応じて指数関数的に増加するため、構成に関するシミュレーションは完全に非現実的です。 テスト ケースごとに 2 次の作業量を実行するアルゴリズムであっても、不必要にコストがかかります。 すべてのケースが最大長である場合、すべてのテスト ケースにわたって最大 250 万文字が検査されるため、各文字列の線形スキャンは容易に十分に小さくなります。 

不注意な実装によって間違った答えが得られる小さなケースがいくつかあります。 のために`A.`、答えは`N`: アルファには飛び越えられるベータ フロッグがありません。ベータが存在しないため、ベータを移動することは不可能です。 のために`AB`、答えも`N`アルファのすぐ隣にベータ カエルがいるにもかかわらず、その後に空のパッドがないためです。 のために`AB.`、答えは`Y`: アルファは 1 匹のベータ フロッグを飛び越えて、最後のパッドに着地します。 ついに、`ABB`は`N`: アルファ以降の両方のパッドにはベータ フロッグが含まれているため、着陸パッドはありません。 よくある間違いは、着陸パッドの存在を確認せずに、ベータ フロッグが少なくとも 1 匹存在するかどうかだけを確認することです。 

アルファが両方向にジャンプできるようにする新しいルールは、別の微妙なケースを生み出します。 2 匹以上のベータ カエルがいる場合、答えは次のようになります。`Y`通常の一方向リープフロッグ条件に十分なベータ フロッグがない場合でも。 例えば、`A.B..BBB.`ベータ フロッグが 3 匹いて、到達可能です。 これを第 1 章とまったく同じように扱うと、誤って拒否されてしまいます。 

## アプローチ

 直接的な総当たりアプローチは、カエルのすべての完全な配置を状態として扱い、幅優先検索を実行することです。 状態から、すべての合法的なベータの動きとすべての合法的なアルファジャンプを列挙し、新しく発見されたすべての状態から続行できます。 これは正しいです。カエルの動きのすべての正当なシーケンスがこの状態グラフのパスに対応しているため、最後のパッドにアルファがある状態に到達することは、まさに望ましい状態です。 

問題は州の数です。 アルファがいずれかを占有できる場合`N`位置、および他のすべての位置には独立してベータ フロッグまたは空のパッドが含まれます。`N * 2^(N-1)`独特の構成。 まで検査中`O(N)`各構成からの可能な移動により、最悪の場合の移行検査カウントは次のようになります。`O(N^2 * 2^N)`。 のために`N = 5000`、これは遠隔的には実現可能ではありません。 

有益な観察は、ベータカエルの詳細な位置は最終的な決定には重要ではないということです。 重要なのはその数だけです。 させて`n = N - 1`、アルファの開始パッドの後のパッドの数、そして`b`ベータカエルの数になります。 

構造上の条件は3つあります。 

まず、もし`n = 1`, アルファは2番目のパッドに到達することはできません。 右側にパッドが 1 つしかない場合は、そこが空でアルファがジャンプできないか、ベータ カエルが含まれていて空の着陸パッドが存在しないかのどちらかです。 

第二に、アルファ以降のすべてのパッドがベータ カエルによって占有されている場合、`b = n`、空の着陸パッドはどこにもありません。 アルファは動けない。 

興味深いのは、次の場合に何が起こるかということです。`b < n`したがって、少なくとも 1 つの空のパッドが存在します。 ベータ フロッグが 1 つだけの場合、古いリープフロッグ制限が引き続き適用されます。 単一のベータ カエルはアルファが飛び越えるオブジェクトとして機能しますが、アルファが飛び越えた後、そのベータ カエルはアルファの後ろにいます。 別の有用なジャンプを作成するために使用できる 2 番目のベータ フロッグはありません。 のために`b = 1`、唯一成功したケースは`n = 2`、つまり`AB.`。 

少なくとも 2 つのベータ カエルが登場すると、第 2 章では状況が完全に変わります。 2 つのベータ フロッグは空のパッドと協力して、繰り返しのローカル パターンを作成できます。これにより、新しいベータ フロッグを目的地に向かって 1 つ移動する必要がなく、アルファが前進できるようになります。 代表的なローカル変換は次のとおりです。```
ABB.. -> AB.B. -> .BAB. -> .B.BA
```最初のベータ フロッグが利用可能な穴に移動し、アルファはそのすぐ右側のベータ フロッグを飛び越え、アルファは 2 番目のベータ フロッグを使用し続けることができます。 同じアイデアを行内で移動できます。 少なくとも 1 つの空のパッドと少なくとも 2 つのベータ カエルが存在する限り、カエルは自分自身を再配置できるため、この 2 ベータ メカニズムによってアルファは目的地に向かって進み続けることができます。 これは、第 2 章で紹介された追加の可能性です。この基準は、問題に対して確立された解決策の特徴付けと一致します。 

第 1 章のしきい値は次のように書くこともできます。`b >= ceil(n / 2)`。 第 2 章では、そのしきい値は 2 匹未満のベータ カエルの場合にのみ関連します。`b >= 2`空のパッドがある限り、すでに到達可能です。 したがって、便利な実装は次のようになります。```
n = N - 1
b = number of B characters

if n == 1: N
else if b == n: N
else if b >= ceil(n / 2): Y
else if b >= 2: Y
else: N
```の`ceil(n / 2)`条件は 1 ベータ版のケースを正確に処理しますが、`b >= 2`新しい第 2 章のメカニズムをキャプチャします。 これは、公開されたソリューションで使用されるコンパクトな特性評価でもあります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(N^2 2^N)`|`O(N 2^N)`| 遅すぎる |
 | 最適 |`O(N)`|`O(1)`入力文字列に加えて | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取って、`n = len(s) - 1`。 イニシャルは除きます`A`関連するすべての動きがその右側のパッド間で発生するためです。 
2. 数を数えます`b`の`B`文字。 上記の構造条件が分かれば、それらのベータカエルの正確な位置は不要になります。 
3. もし`n == 1`、すぐに答えます`N`。 アルファはベータ カエルを越えて合法的なジャンプを実行できず、それでもどこかに着陸します。 
4. もし`b == n`、 答え`N`。 Alpha 以降のすべてのパッドは占有されているため、空の着陸パッドはありません。 
5. コンピューティング`ceil(n / 2)`として`(n + 1) // 2`。 もし`b`少なくともこの値です、答えてください`Y`。 これは、ベータ フロッグが 1 つある唯一の有用なケースを含む、標準的なリープフロッグの配置をカバーしています。 
6. 前の条件が失敗した場合でも、`b >= 2`、 答え`Y`。 空のパッドが存在する場合、2 つのベータ フロッグが存在すると、新しい第 2 章のメカニズムがアクティブになります。 の`b == n`ケースはすでに拒否されているため、少なくとも 1 つの穴が利用可能です。 
7. 上記のいずれのケースにも当てはまらない場合は、次のように答えます。`N`。 これは、アルファが前進するにはベータ カエルが少なすぎるため、特別な 2 ベータ メカニズムが利用できないことを意味します。 

機能する理由: このアルゴリズムは、動作を妨げる構成を、有効な協調メカニズムを持つ構成から正確に分離します。 の`n == 1`この場合、アルファジャンプは不可能です。 の`b == n`ケースには着陸可能なパッドがありません。 利用可能なベータ フロッグが 2 つ未満の場合は、通常のリープフロッグ要件によって、アルファが最後まで到達するのに十分なサポートがあるかどうかが決まります。 2 つのベータ フロッグと少なくとも 1 つの空のパッドが存在すると、それらの動きが第 2 章の 2 ベータ パターンを作成し、アルファを前進させることができます。 したがって、受け入れられたすべてのケースには有効な一連の動きがありますが、拒否されたすべてのケースには必要な構造が欠けています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(s):
    n = len(s) - 1
    b = s.count('B')

    if n == 1:
        return 'N'

    if b == n:
        return 'N'

    if b >= (n + 1) // 2:
        return 'Y'

    if b >= 2:
        return 'Y'

    return 'N'

def main():
    t = int(input())
    out = []

    for case_id in range(1, t + 1):
        s = input().strip()
        answer = solve_case(s)
        out.append(f"Case #{case_id}: {answer}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```の`solve_case`関数はまず文字列の長さを次のように変換します。`n`、Alpha の右側のパッドの数。 これは数学的特徴付けと直接一致し、最初のアルファパッドをカエルの数を数える条件に混入することを避けます。`str.count('B')`決定に必要な文字列に関する唯一の情報を提供します。 配置を変更したり、ベータ フロッグの動きをシミュレートしたりする必要はありません。 

条件`b == n`肯定的な条件の前にチェックする必要があります。 例えば、`ABB`もっている`n = 2`そして`b = 2`、したがって、式は`b >= (n + 1) // 2`それは本当です。 それでも答えは`N`アルファには着陸する場所がないからです。 これらのチェックを逆にすると、間違った答えが生成されます。 

表現`(n + 1) // 2`の上限を計算します`n / 2`整数演算を使用します。 ここでは Python の整数にはオーバーフローの問題はなく、すべての値は言語の整数の範囲に比べて小さいです。 

外側のループは必要なものを追加します`Case #i: `プレフィックスを付けて、回答を一度書く前に収集します。 これにより、500 のテスト ケースすべてを快適に処理しながら、I/O がシンプルに保たれます。

 ## 特殊なケース

 The smallest possible input is`A.`。 ここ`n = 1`そして`b = 0`、したがってアルゴリズムは戻ります`N`他の条件を検討する前に。 これにより、空の 2 番目のパッドが通常の 1 ステップの移動で到達可能な目的地として誤って扱われることが回避されます。 

のために`AB`、 我々は持っています`n = 1`そして`b = 1`。 アルゴリズムは依然として戻ります`N`最初の条件から。 アルファにはジャンプできるベータ フロッグがありますが、そのベータ フロッグの後には空のパッドがないため、ジャンプには正当な着地位置がありません。 

のために`AB.`、 我々は持っています`n = 2`そして`b = 1`。 最初の条件が失敗し、サフィックスが完全に占有されていないため、`b >= ceil(2 / 2)`それは本当です。 アルゴリズムは戻ります`Y`からの直接移動に一致します。`A`以上`B`決勝へ`.`。 

のために`ABB`、 我々は持っています`n = 2`そして`b = 2`。 閾値テストはケースを受け入れるように見えます。`2 >= 1`、しかしアルゴリズムはチェックします`b == n`最初に戻ります`N`。 Alpha 以降のパッドはすべて占有されているため、着陸パッドはありません。 この順序付けは不可欠です。 

のために`A.B.`、 我々は持っています`n = 3`そして`b = 1`。 この長さの旅には、ベータ フロッグ 1 匹では不十分です。 上限の閾値は、`2`、 それで`b = 1`それに失敗して、`b >= 2`も失敗します。 答えは`N`。 

といったケースの場合、`A.BB`、 我々は持っています`n = 3`そして`b = 2`。 空いているパッドがあるので、`b != n`、そして2匹のベータフロッグが第2章のメカニズムをアクティブにします。 アルゴリズムは戻ります`Y`。 古い動作パターンのみに基づく第 1 章の解決策では、このより広範なルールを誤って処理する可能性があります。 

最後に、次で構成される最大サイズの文字列については、`A`続いて4,999`B`キャラクター、`n = 4,999`そして`b = 4,999`。 アルゴリズムは戻ります`N`サフィックス全体が占有されているため、すぐに実行されます。 以下で構成される最大サイズの文字列の場合`A`、 二`B`文字と 4,997 個の空のパッド、`b = 2 < n`、したがって、答えは次のとおりです`Y`。 これら 2 つのケースは、ベータ カエルの数と少なくとも 1 つの空の着陸パッドの存在の両方を考慮する必要がある理由を示しています。
