 ## 解決策
 ## 問題の理解

 (N) 個のスイレンの葉が並んでいます。 最初のパッドにはアルファ フロッグが含まれ、他のパッドにはベータ フロッグが含まれるか、何も含まれません。 アルファフロッグは右にしか移動できません。 移動するには、少なくとも 1 つの連続するベータ フロッグを飛び越え、それらのベータ フロッグの後の最初の空のパッドに着地する必要があります。 ベータ フロッグは、目的のパッドが空の場合は常に、独立して 1 つの位置を左右に移動できます。 

問題は、ベータ フロッグの動きとアルファ フロッグのジャンプのシーケンスによって、最終的にアルファ フロッグを最後のパッドに配置できるかどうかです。 

入力には最大 500 のテスト ケースが含まれており、各行の長さは最大 5000 です。各行を 1 回または一定の回数だけスキャンするソリューションは、十分に高速です。 (O(N^2)) ソリューションも単一のテスト ケースでは管理可能ですが、500 のケースと 5000 近くの長さでは、すでに数十億の操作が必要になる可能性があります。 数十個のパッドが並んでいる場合でも、膨大な数のカエル配列が存在する可能性があるため、指数関数的な検索は完全に実行不可能です。 

アルファフロッグが現在合法的なジャンプを持っているかどうかだけに焦点を当てていると、重要なエッジケースが見落とされやすくなります。 

のために`A.`、空の最終パッドがありますが、飛び越えられるベータフロッグがありません。 正しい答えは、`N`。 右側の空のパッドを十分なものとして扱う不注意な解決策は、誤った結果を返します。`Y`。 

のために`AB`、ベータフロッグはありますが、アルファフロッグが着地できる空のパッドはありません。 正しい答えは、`N`。 少なくとも 1 つのベータ カエルが存在することだけを確認するのは間違いです。 

のために`ABB`、ベータフロッグはありますが、空のパッドがまったくないため、アルファフロッグはどこにも着陸できません。 正しい答えは、`N`。 

のために`A.B`、ベータ フロッグが 1 つと空のパッドが 1 つあります。 ベータフロッグは左に移動して生産することができます`AB.`、その後、アルファフロッグはそれを飛び越えて最後のパッドに到達します。 正しい答えは、`Y`。 最初の手がすぐに利用可能かどうかだけをチェックするソリューションでは、このケースは誤って拒否されてしまいます。 

重要な違いは、ベータ カエルの最初の位置は、その総数ほど重要ではないということです。 ベータフロッグは空のパッドを移動することで協力できるため、の数だけを使用して問題を解決できます。`B`そして`.`。 

## アプローチ

 直接的な総当たりの解決策では、カエルのあらゆる可能な配置が状態として扱われます。 1 つの状態から、すべての正当なベータ フロッグの動きとすべての正当なアルファ フロッグのジャンプを生成し、アルファ フロッグが最後のパッドに到達するまで BFS または DFS を実行できます。 

これは正しいです。なぜなら、すべての正当な一連の動きは、この状態グラフを通るパスに対応しているからです。 問題はそのグラフのサイズです。 (b) ベータ カエルがある場合、アルファ カエルの位置を選択し、次に残りの (N-1) 個のパッドの中から (b) ベータ 位置を選択することによって、状態を記述することができます。 それはせいぜい

 [
 N\binom{N-1}{b}
 】

 州。 (b) のすべての可能な値にわたって、これは (N) で指数関数的になります。 すべての状態から最大 (O(N)) 個の手を生成すると、(O(N^2 2^N)) スタイルのワーストケースの上限が得られます。 (N=5000) では、このアプローチはリモートでは実用的ではありません。 

ブルートフォースはあらゆる可能な配置を明示的に追跡するため機能しますが、それはまさに不必要な部分です。 私たちは実際には、個々のベータカエルがどこにいるのかを気にしません。 空のパッドを通って移動できる彼らの能力は、合計で十分な数のベータ フロッグがある限り、アルファ フロッグがジャンプする必要があるときはいつでも、そのうちの 1 つをアルファ フロッグの隣に移動できることを意味します。 

(b) をベータ フロッグの数、(d) を空のパッドの数とします。 Alpha Frogは1つのパッドを占有しているため、

 [
 N = 1+b+d。 
】

 最初の必要条件は (d\geq 1) です。 アルファ フロッグは最終的には空のパッドに着陸する必要があるため、空のパッドがなければ最後のパッドに到達することは不可能です。 

2 番目の条件は (b\geq d) です。 アルファ フロッグのジャンプは必ず少なくとも 1 匹のベータ フロッグの上を通過する必要があります。 アルファフロッグのまだ前方にある列の一部にある空のパッドは、将来の着陸の機会であると考えてください。 このような空のパッドを越えて進むには、その直前に配置できる少なくとも 1 つのベータ フロッグが必要です。 ベータ フロッグよりも空のパッドの方が多い場合、最終的には最後に到達する前にベータ フロッグがなくなってしまいます。 

逆に、(1\leq d\leq b) の場合、カエルはいつでも協力できます。 次のパッドが既にベータ フロッグによって占有されている場合、アルファ フロッグは連続するベータ フロッグを飛び越えて、次の空のパッドに着地することができます。 次のパッドが空の場合、さらに右にある最も近いベータ フロッグは、アルファ フロッグに隣接するまで、空のパッドを通って左に移動できます。 アルファフロッグはそれを飛び越えることができます。 このようなジャンプはすべて、残りのサフィックスから少なくとも 1 つのベータ フロッグを消費すると同時に、そのサフィックスから 1 つの空のランディング パッドを削除するため、不等式 (b\geq d) は維持されます。 

したがって、問題全体は単純な条件に帰着します。 

[
 1\leq d\leq b.
 】

 同様に、(N=1+b+d) なので、これは次のように書くこともできます。 

[
 b+1\leq N-1\leq 2b.
 】

 同じ特徴付けはどちらの形式でも表現できますが、ドットを直接数えると推論がより明確になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^2 2^N)) 上限 | (O(N2^N)) | 遅すぎる |
 | カウント`B`そして`.`| (O(N)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ベータカエルの数を数えます。`b`、および空のパッドの数、`d`。 
2. もし`d == 0`、 戻る`N`。 たとえベータカエルがたくさんいたとしても、アルファカエルが着陸する場所はありません。 
3. もし`b >= d`、 戻る`Y`。 アルファ フロッグが通過しなければならない空の着地位置ごとに少なくとも 1 回のジャンプを提供できる十分なベータ フロッグが存在します。 
4.そうでない場合は戻る`N`。 ベータ フロッグよりも空のパッドが多いことは、アルファ フロッグが最終的にベータ フロッグが利用できないジャンプを必要とすることを意味します。 

カウントが十分である理由は、ベータ フロッグが空のパッドを通って移動できるためです。 ベータ カエルの総数が十分に大きくなれば、最初の正確な位置は最終的な戦略を制限しません。 

### なぜ効果があるのか

 不変条件は、アルファ フロッグよりもまだ前の行の部分では、利用可能なベータ フロッグの数が少なくともまだ通過する必要がある空のパッドの数であるということです。 最初はこれがまさに条件 (b\geq d) です。 アルファ フロッグが前進するたびに、空のパッドに着陸し、少なくとも 1 つのベータ フロッグと交差します。 残りのサフィックスと比較して、必要な空の着陸位置と利用可能なベータ フロッグの両方が少なくとも 1 つ減少するため、不等式は有効のままです。 次のパッドが空の場合は、その右側のベータ フロッグをアルファ フロッグに隣接するまで左に移動して、必要なジャンプが可能になります。 次のパッドがすでにベータ カエルによって占有されている場合、アルファ カエルはすぐにジャンプできます。 したがって、(1\leq d\leq b) は必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for case in range(1, t + 1):
        s = input().strip()

        b = s.count('B')
        d = s.count('.')

        answer = 'Y' if d >= 1 and b >= d else 'N'
        out.append(f"Case #{case}: {answer}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```入力ループは、テスト ケースごとに 1 行を読み取ります。 決定は文字列のカウントのみに依存するため、文字列の長さを個別に保存する必要はありません。`B`そして`.`。`b = s.count('B')`すべてのベータカエルを数えますが、`d = s.count('.')`空のパッドをすべてカウントします。 Alpha Frog は空のパッドとしてカウントされないため、`d`これは、最初に利用可能な着陸パッドの正確な数です。 

条件`d >= 1`最初を除くすべてのパッドが Beta Frog によって占有されている場合を処理します。 このような列にはたくさんのカエルが含まれていますが、着陸可能な位置はありません。 

条件`b >= d`が中心的な観察です。 シミュレーション、再帰、グラフ構築、文字列の変更はありません。 

また、最後のパッドに関係するインデックス操作もないため、0 ベースまたは 1 ベースの特別な境界計算で間違いが生じることもありません。 Python の整数には制限がありませんが、ここでのカウントはいずれにしても最大 5000 であるため、整数のオーバーフローは無関係です。 

## 実用的な例

 ### サンプル 1:`AB.`ここにはベータ フロッグが 1 つと空のパッドが 1 つあります。 (b=1) かつ (d=1) であるため、条件は満たされます。

 | 結果 | 3 | 0 | 0 | アルファが最後のパッドに到達 |

 アルファ フロッグはベータ フロッグを直接飛び越えて最後の空のパッドに着地できるため、答えは次のようになります。`Y`。 

これは、自明ではない成功した最小の構成です。 また、両方のリソースが必要な理由も示します。 飛び越えるためのベータフロッグと、着地するための空のパッドがなければなりません。

| ステップ | アルファ位置 | ベータ数 | 空のパッド | 決定 |

 アルファ フロッグは、その右側の唯一のパッドがベータ フロッグによって占有されており、その後に空のパッドがないため、ジャンプできません。 答えは`N`。 

このトレースは境界条件を適用します`d == 0`。 ベータカエルの数だけでは十分ではありません。
