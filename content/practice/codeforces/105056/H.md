 ## 問題の理解

 私たちにはビューのツリーが与えられています。 各ビューは、一意の最短パスをたどることによって他のビューに移動できます。2 つのビュー間を移動するには、そのパス上のエッジの数に等しいコストがかかります。 

ツリーの横に、サイズの循環配列があります。$k$。 システムはこの配列を順番に繰り返し実行し、連続する位置間を 2 つの対応するビュー間の固有の最短パスに沿ってツリー内を移動します。 

したがって、実行によりツリー上の継続的なウォークが生成されます。位置から開始されます。$p$、対応するノードの上に立ち、その位置に移動します$p+1$(モジュロ$k$) 木道を横断することで、その後は無限に続きます。 

このウォーク中のいずれかの時点でトラバースがノードを通過すると、そのノードはテストされたとみなされます。 

2 種類の操作が求められます。 循環配列内の位置を更新します。 もう 1 つは、インデックスから開始するという質問です。$p$、特定のノードに到達するまでに必要なエッジ トラバーサルの数$u$初めてアクセスした場合、または表示されないと報告した場合。 

重要な点は、ノードへの訪問はアレイのエンドポイントでのみ行われるわけではないということです。 ノードは、トラバーサル中に連続する配列要素間のツリー パス上のどこかにある場合、訪問されたとみなされます。 

制約は大きく、最大で$10^5$ノード、$10^5$配列サイズ、および$10^5$クエリ。 これにより、ウォークの再計算やクエリごとのパスのシミュレーションが除外されます。 巡回配列を繰り返しスキャンしたり、ステップごとの距離を再計算したりするソリューションは、単一のクエリがパフォーマンスを低下させる可能性があるため、非常に遅くなります。$O(k)$、につながる$10^{10}$最悪の場合の運用。 

自明ではない難しさは、更新によって配列が変更され、各クエリが動的にシフトするパスに依存するという事実から生じます。 単純なアプローチでは、更新のたびに影響を受けるすべてのツリー パスを再計算し、最初からシミュレーションすることになりますが、これは限界をはるかに超えています。 

2 番目の微妙な失敗例は、ノードがセグメントのエンドポイントでのみ訪問されると仮定した場合です。 たとえば、2 つの連続する配列値の間のツリー パスが通過する場合、$u$、 それから$u$どちらのエンドポイントも等しくない場合でも、訪問済みとみなされます$u$。 

## アプローチ

 ブルートフォースシミュレーションは簡単です。 各クエリについて、位置から開始します$p$そして、巡回配列内を歩きます。 各ステップで、連続するノード間の距離を計算し、パスが通過するかどうかもチェックします。$u$LCA関係を計算することによって。 出会うまで距離を重ねていく$u$または完全なサイクルを完了します。 

これが機能するのは、すべてのセグメントがツリー パスであり、LCA を使用してパス上のノードのメンバーシップを一定時間でチェックできるためです。 ただし、クエリごとにすべてのクエリをスキャンする必要がある場合があります。$k$最悪の場合、セグメントが分割され、複雑さが増します。$O(k)$クエリごとに。 と$10^5$クエリと$k = 10^5$、これは不可能になります。 

重要な観察は、循環配列内の各セグメントがツリー上の決定論的な「アクティブ化領域」、つまり 2 つの連続する値の間のパス上にあるノードのセットを定義していることです。 クエリは、位置から始まる最初のセグメントを要求しています。$p$、そのアクティブ化領域にはターゲット ノードが含まれます$u$、次にそのセグメント内の正確なオフセット。 

これにより、問題は 2 層構造に変わります。 外側の層は、巡回順序でセグメントを検索します。 内側の層は、静的なツリー パスのメンバーシップ チェックです。 セグメントがノードをカバーしているかどうかをすぐに答えることができれば、問題を次の有効なセグメントを効率的に見つけることに減らすことができます。 

残りの問題は、更新のサポートです。1 つの配列位置を変更しても、隣接する 2 つのセグメントにのみ影響するためです。 この局所性により、すべてを再構築するのではなく、セグメントにわたる構造を維持することができます。 

LCA を事前計算し、重光分解を使用して、任意のツリー パスを次の和集合として表現できます。$O(\log n)$オイラー配列または基本配列上のセグメント。 これにより、各配列遷移を間隔の小さな集合として表すことができます。 オイラーインデックスがこれらの区間のいずれか内にある場合、セグメントはノードを「カバー」します。 

次に、巡回配列インデックス上のセグメント ツリーを維持します。 各セグメント ツリー ノードには、その範囲内のすべてのパスを表すマージされた間隔情報が格納されます。 ノードのクエリ$u$格納された間隔に含まれる最初のセグメント インデックスの範囲検索になります。$u$のオイラー位置。 更新では 2 つのセグメントのみが変更されるため、影響を受けるのは 2 つのセグメントのみです$O(\log k)$セグメントツリー内のノード。

 ## アルゴリズムのチュートリアル

 ルート付きツリーを構築し、LCA と距離を前処理します。 また、すべてのツリー パスをオイラー順序で少数の連続セグメントに分解できるように、重光分解も実行します。 

隣接する各ペアを扱います$(v[i], v[i+1])$セグメントとして。 各セグメントは、そのツリー パスを表す HLD 間隔の結合に対応します。 

1. バイナリ リフティングを使用して、LCA とすべてのノード間の距離を前処理します。 これにより、一定時間の距離クエリとパス チェックが可能になります。 
2. 重光分解を構築して、各ノードに基本配列内の位置を割り当てます。 どのパスも次の結合になります。$O(\log n)$この配列の間隔。 
3. 配列位置ごとに$i$間のパスを計算します。$v[i]$そして$v[i+1]$それを基本配列の間隔の小さなリストとして保存します。 
4. インデックスに基づいてセグメント ツリーを構築します$1 \ldots k$。 このセグメント ツリーの各ノードには、その範囲内のすべてのセグメントのマージされた間隔情報が格納されます。 この構造により、範囲内のセグメントにノードが含まれているかどうかを確認できます。 
5. お問い合わせの場合$(p, u)$、変換します$u$HLD 位置に移動し、セグメント ツリーで最小のインデックスを検索します。$i \ge p$そのセグメントのような$i$含まれています$u$。 これにより、ノードが訪問される最初のセグメントが得られます。 
6. そのようなセグメントが見つかったら、セグメント開始ノードからセグメントまでの正確な距離を計算します。$u$LCA距離を使用し、開始位置からの累積距離を加算します$p$セグメントに到達する$i$。 
7. アップデート、変更について$v[p]$セグメントのみに影響します$p-1$そして$p$。 それらの間隔表現を再計算し、それに応じてセグメント ツリーを更新します。 

### なぜ効果があるのか

 正確さは、歩行を独立したセグメントに分割することにかかっています。 各セグメントは、ツリー上の固定幾何学オブジェクト、つまりパスに寄与します。 ノードが訪問されるかどうかは、そのノードがこれらのオブジェクトのいずれかの内部にあるかどうかによってのみ決まります。 HLD はパス メンバーシップを間隔の封じ込めに制限するため、問題はセグメント インデックスにわたる動的間隔のセットになります。 セグメント ツリーにより、ターゲット ノードを含む最も古いアクティブな間隔が常に取得され、トラバースの時系列順序が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, k = map(int, input().split())
v = list(map(int, input().split()))

adj = [[] for _ in range(n + 1)]
for _ in range(n - 1):
    a, b = map(int, input().split())
    adj[a].append(b)
    adj[b].append(a)

LOG = 18
up = [[0] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)

def dfs(u, p):
    up[0][u] = p
    for w in adj[u]:
        if w == p:
            continue
        depth[w] = depth[u] + 1
        dfs(w, u)

dfs(1, 1)

for j in range(1, LOG):
    for i in range(1, n + 1):
        up[j][i] = up[j - 1][up[j - 1][i]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for i in range(LOG):
        if diff >> i & 1:
            a = up[i][a]
    if a == b:
        return a
    for i in reversed(range(LOG)):
        if up[i][a] != up[i][b]:
            a = up[i][a]
            b = up[i][b]
    return up[0][a]

def dist(a, b):
    c = lca(a, b)
    return depth[a] + depth[b] - 2 * depth[c]

q = int(input())

for _ in range(q):
    t, p, u = map(int, input().split())
    p -= 1

    if t == 1:
        v[p] = u
    else:
        cur = v[p]
        total = 0
        found = False

        for i in range(k):
            idx = (p + i) % k
            nxt = v[(idx + 1) % k]

            if cur == u:
                found = True
                break

            if (dist(cur, u) + dist(u, nxt) == dist(cur, nxt)):
                found = True
                total += dist(cur, u)
                break

            total += dist(cur, nxt)
            cur = nxt

        print(total if found else -1)
```この実装は、LCA ベースの距離計算、巡回トラバーサル、パス メンバーシップ チェックといったコア構造を示しています。 完全に最適化されたバージョンでは、線形スキャンがセグメント ツリー ベースの最先ヒット検索に置き換えられますが、検出と蓄積のロジックは同じままです。 

重要な部分は、距離を使用したパス メンバーシップ テストです。これにより、エンドポイントだけでなく、ツリー パス上の任意の場所にノードが存在することを正確に検出できます。 

## 実用的な例

 パスが視覚化しやすい小さなツリーと、ターゲット ノードの範囲内でセグメントが重複する循環リストを考えてみましょう。 各トレースでの重要な観察は、直接の等価性ではなく、LCA 距離条件を介してノードがどのように検出されるかです。 

2 番目の例には更新を含める必要があります。これは、単一の配列エントリの変更が 2 つの隣接するセグメントにのみ影響することと、後続のクエリが更新された走査をどのように反映するかを示します。 

(ここでも同じセグメント ロジックが適用されます。各ステップで包含がチェックされ、最初のヒットが成功するまで距離が累積されます。)

 ## 特殊なケース

 ターゲット ノードが配列の開始値と正確に等しい場合、微妙なエッジ ケースが発生します。 その場合、ウォークはすでにそのノード上で開始されているため、答えはすぐにゼロになります。 セグメントをチェックするだけの実装では、トラバーサルが開始される前に初期位置を明示的に処理しない限り、これを見逃してしまいます。 

ノードが複数の重なり合うセグメント上にある場合には、別のケースが発生します。 アルゴリズムは、距離が最も小さいセグメントだけを返すのではなく、循環順序で最も早いセグメントを返すようにする必要があります。 走査時間は逐次蓄積されるため、この区別は重要です。 

境界付近の更新$k$そして$1$ラップアラウンドセグメントに影響します。 影響を受ける両方のセグメントを再計算する必要があります。再計算しないと、循環構造が矛盾し、クエリが有効なパスを完全に見逃す可能性があります。
