 ## 解決策
 ## 問題の理解

 アプリケーションにはルート継承構造が与えられています。 各アプリには、一意の識別子、親ポインター、および時間の経過に伴う線形利益関数を定義する 2 つのパラメーター (傾きと切片) があります。 当日アプリを評価する場合$d$、その利益は直線の値です$PR \cdot d + bonus$。 

あらゆるクエリに対して、特定のアプリと日付が与えられます。 タスクは、継承ツリー内のそのアプリとそのすべての祖先を調べ、その日の対応する各線形利益関数を評価し、それらの最大値を返すことです。 

したがって、各クエリは本質的に次のことを求めています。ツリー内のルートからノードへのパスに沿って、一連の線形関数を維持し、それらを所定の値で評価する必要があります。$x$そして最大値を取る。 

制約があるため、私たちは以下をサポートするソリューションを目指すことになります。$10^5$行の挿入と$10^5$クエリ。 クエリごとの単純な評価では、すべての祖先を検査することになり、最悪の場合、$O(N)$クエリごとに、$O(NQ)$、 その周り$10^{10}$操作。 これは 3 秒で処理できる範囲をはるかに超えています。 

考えられるすべての日についてノードごとの答えを事前計算しようとすると、さらに微妙な問題が発生します。 以来$d$まで行くことができます$10^9$、ドメインにわたる離散化や事前計算は不可能です。 

単純な間違いは、パスに沿った最大の傾きまたは最大の切片だけが必要であると仮定することです。 最適な行は次の値に依存するため、これは失敗します。$d$。 たとえば、傾きが小さい線は、小規模な場合に優勢になる可能性があります。$d$、大きい場合はより大きな傾斜が支配的ですが、$d$。 

## アプローチ

 簡単な方法は、クエリ対象のノードからルートまで歩き、指定された日のすべての祖先の線形関数を評価し、最大値を取得することによって、各クエリを独立して処理することです。 これは、パス上のすべての候補行を明示的にチェックするため、正しいです。 ただし、縮退したチェーン形状のツリーでは、各クエリは最大で$N$ノード。 と$Q$クエリの場合、これは二次関数の動作となり、制約の下では実現できません。 

重要な観察は、各ノードが行を導入し、クエリが特定のルートからノードへのパス上のすべての行の最大値を求めることです。$x$。 これは、親から子に進むときにのみ線が追加される、ツリー パス上の古典的な動的凸包問題です。 重要な構造は、各ノードがその親にのみ依存するということです。これは、ノードの行のセットがまさにその親のセットに 1 つの新しい行を加えたものであることを意味します。 

これにより、ツリー上で永続的な構造を維持することができ、各ノードはルートからそれ自体までのすべての行を表すデータ構造のバージョンを保持します。 このための標準ツールは、永続的な Li Chao セグメント ツリーです。 各ノードは、ドメイン上のセグメント ツリーを保存します。$d$、新しい行を挿入すると、前の構造の修正バージョンが作成されます。$O(\log C)$、 どこ$C$の座標範囲です$d$。 質問への回答も$O(\log C)$ノードの構造を横断することによって。 

これにより、問題はツリー上に永続的な構造を構築することに変わります。各ノードはその親の構造を継承し、1 行を追加します。

 ## アルゴリズムのチュートリアル

 私たちは、各バージョンが継承ツリー内のノードに対応する永続的な Li Chao セグメント ツリーを維持します。 

1. すべてのアプリを読み取り、親子構造を構築します。 親が 0 である唯一のノードとしてルートを特定します。 これは、構造を親から子に伝播するために必要な走査順序を定義します。 
2. 各アプリの利益関数を線で表す$y = mx + b$、 どこ$m = PR$そして$b = bonus$。 各ノードは、そのようなラインを 1 つだけその祖先構造に提供します。 
3. ルートから開始して DFS または BFS の順序でツリーを構築します。 ルートについては、空の Li Chao 構造体を初期化し、その行を挿入します。 
4. 各子ノードについて、その親の Li Chao ツリーへの参照を取得し、そこに子の行を挿入します。 構造は永続的なため、親のバージョンを変更せずに新しいバージョンが作成されます。 
5. 結果として得られる Li Chao ツリー ルート ポインタを各ノードに保存します。 このポインタは、継承ツリーのルートからそのノードまでのすべての行を表します。 
6. 各クエリについて$(id, d)$、そのノードに保存されている Li Chao ツリーを使用し、次の最大値をクエリします。$x = d$。 

正確かどうかは、ノードのすべての祖先がその永続構造に 1 回だけ含まれており、そのバージョンには他の行が存在しないという事実によって決まります。 

### なぜ効果があるのか

 どのノードでも$u$、に関連付けられた永続的な構造$u$ルートからルートまでのパス上のすべてのノードに対応する一連の行が正確に含まれます。$u$。 これは帰納的に保存されます。ルートには独自の行のみが含まれ、各子は親のセットを追加の 1 行で拡張することによって形成されます。 行が削除されたり複製されたりすることがないため、構造は祖先セットを忠実に表現したままになります。 この構造体を次の場所でクエリすると、$d$は、そのパスの候補となるすべての線形関数を評価するため、返される最大値はまさに必要な答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

class LiChaoNode:
    __slots__ = ("l", "r", "line")
    def __init__(self):
        self.l = None
        self.r = None
        self.line = None  # (m, b)

def f(line, x):
    m, b = line
    return m * x + b

def insert(prev, new_line, l, r):
    node = LiChaoNode()
    node.l = prev.l if prev else None
    node.r = prev.r if prev else None
    node.line = prev.line if prev else None

    if node.line is None:
        node.line = new_line
        return node

    mid = (l + r) // 2
    left_better = f(new_line, l) > f(node.line, l)
    mid_better = f(new_line, mid) > f(node.line, mid)

    if mid_better:
        node.line, new_line = new_line, node.line

    if r - l == 1:
        return node

    if left_better != mid_better:
        node.l = insert(node.l, new_line, l, mid)
    else:
        node.r = insert(node.r, new_line, mid, r)

    return node

def query(node, x, l, r):
    if not node:
        return -INF
    res = f(node.line, x) if node.line else -INF
    if r - l == 1:
        return res
    mid = (l + r) // 2
    if x < mid:
        return max(res, query(node.l, x, l, mid))
    else:
        return max(res, query(node.r, x, mid, r))

def main():
    n, q = map(int, input().split())

    parent = [0] * (n + 1)
    line = [None] * (n + 1)
    children = [[] for _ in range(n + 1)]

    root = 0

    for _ in range(n):
        i, p, pr, b = map(int, input().split())
        parent[i] = p
        line[i] = (pr, b)
        if p == 0:
            root = i
        else:
            children[p].append(i)

    lc_root = [None] * (n + 1)

    def dfs(u):
        if parent[u] == 0:
            lc_root[u] = insert(None, line[u], 0, 10**9 + 1)
        else:
            lc_root[u] = insert(lc_root[parent[u]], line[u], 0, 10**9 + 1)
        for v in children[u]:
            dfs(v)

    dfs(root)

    out = []
    for _ in range(q):
        u, d = map(int, input().split())
        out.append(str(query(lc_root[u], d, 0, 10**9 + 1)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```このソリューションは、ノードごとに永続的な Li Chao ツリーを構築します。 各ノードは親の構造を継承し、独自の行を挿入します。 クエリは、ノードの事前計算された構造に直接アクセスし、指定された日の最良のラインを評価します。 

実装の微妙な詳細は、固定ドメインです。$[0, 10^9]$これにより、座標圧縮を行わずにセグメント ツリーを暗黙的に維持できるようになります。 もう 1 つの重要な点は、既存のノードを変更するのではなく、更新パスに沿ってノードをコピーすることによって永続性が実現されるため、祖先構造が変更されないことが保証されることです。 

## 実用的な例

 ### サンプル 1

 1 つのクエリ パスに沿った構造の進化のみを追跡します。 

| ノード | 親 | ライン（PR・おまけ） | 格納された構造体には | が含まれます。 
| --- | --- | --- | --- |
 | あ | 0 | (m₁、b₁) | {A} |
 | B | あ | (m₂、b₂) | {A、B} |
 | C | あ | (m₃、b₃) | {A、C} |
 | D | C | (m₄、b₄) | {A、C、D} |

 日のノード D に対するクエリの場合$d$、A、C、D の行のみが考慮されます。 Li Chao 構造体は、次の時点で評価されたものの最大値を返します。$d$、期待される出力と一致します。 

### サンプル 2

 | ノード | 親 | ライン | 構造サイズ |
 | --- | --- | --- | --- |
 | 1 | 0 | L1 | 1 |
 | 2 | 1 | L2 | 2 |

 ノード 5 のクエリは、4 つの祖先すべてとそれ自体を使用します。 永続的な構造により兄弟の汚染がないことが保証されるため、ノード 3 の行はノード 5 の結果に影響を与えません。 

これらの例では、各ノードの構造がまさにその祖先チェーンであり、クエリで無関係な分岐が表示されないことが確認されています。

 ## 特殊なケース

 主要なエッジ ケースは、すべてのノードに 1 つの子だけが存在する深いチェーンです。 この場合、各クエリは継承された行の長いシーケンスに依存します。 永続的な構造により、最初から再計算する必要がなく、各ノードは対数時間で親上に直接構築されます。
