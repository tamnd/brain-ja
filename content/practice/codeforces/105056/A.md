 ## 解決策
 ## 問題の理解

 電子メールのような識別子を表す単一の文字列が与えられ、それが架空のアドレス グループで使用される非常に特殊なパターンに一致するかどうかを判断する必要があります。 

有効な文字列は、単一の「@」文字で区切られた 2 つの部分で構成されている必要があります。 「@」より前の部分は英小文字のみからなるユーザー名です。 「@」の後の部分はリテラルテキスト「odoo」でなければなりません。 そのドメインの後には、追加のサフィックス、余分なドット、文字は許可されません。 

したがって、タスクは構造と正確な内容の両方をチェックすることになります。つまり、1 つの「@」、空ではなく純粋にアルファベットの小文字である左側、および長さがちょうど 4 文字で「odoo」に等しい右側です。 

入力サイズは最大 50 文字であるため、単純なスキャンや分割であっても、パフォーマンスの点では簡単ではありません。 文字列に対して線形時間で実行されるアプローチであればどれでも十分です。 

最も一般的な失敗のケースは、微妙な書式違反が原因です。 文字列には複数の「@」記号が含まれている場合があり、その場合はただちに無効になります。 もう 1 つの一般的な問題は、「odoocom」や「odoo」など、「odoo」を含むだけで完全に一致しないドメインを受け入れることです。 または「odoo123」。 最後に、ユーザー名の大文字または数字は、他のすべてが一致する場合でも拒否される必要があります。 

これらの特殊なケースを例で明確にします。 

入力:`palm@odoocom`出力：`no`部分文字列「odoo」が表示されますが、ドメインは必要以上に長くなっています。 

入力：`im_not_an_email`出力：`no`「@」区切り文字がまったくないため、構造が無効です。 

## アプローチ

 これを解決する強引な方法は、すべての位置を潜在的な「@」分割点としてスキャンすることにより、文字列を電子メールとして解釈してみることです。 分割候補ごとに、左側の部分文字列が小文字であるかどうかを検証し、右側の部分文字列を「odoo」と比較します。 これは制約が小さいため機能しますが、セパレータを 1 つ見つけて直接検証するだけでよいため、不要なオーバーヘッドが生じます。 

より明確なアプローチは、最初に単一の「@」文字を見つけることです。 存在しない場合、または複数回出現する場合、その文字列は直ちに拒否されます。 分割点がわかったら、文字タイプをチェックして左側が空でないことを確認することで左側を検証します。 次に、右側が正確に「odoo」であり、他には何もないことを確認します。 

重要な洞察は、構造が十分に厳格であるため、後戻りや推測が必要ないということです。 文字列がまったく有効であれば、有効な分解は 1 つだけであるため、直接解析すれば十分です。

 ## アルゴリズムのチュートリアル

 1. 入力文字列 E を読み取ります。 
2. E に「@」が何回出現するかを数えます。1 回でない場合は、「no」を返します。 この形式では単一の区切り文字が必要なため、複数またはゼロが出現すると構造がすぐに壊れます。 
3. E を「@」の位置で左右の 2 つの部分に分割します。 
4. 左側の部分が空ではなく、「a」から「z」までの小文字の英字のみで構成されていることを確認します。 数字、大文字、またはアンダースコアを使用すると無効になります。 
5. 右側の部分が文字列「odoo」とまったく同じであることを確認します。 長さや文字内容に差異がある場合は無効となります。 
6. すべてのチェックに合格した場合は「yes」を出力し、そうでない場合は「no」を出力します。 

### なぜ効果があるのか

 検証では、文字列の一意の構造分解が強制されます。 '@' には有効な位置が 1 つだけあるため、その位置が固定されると、両方の部分は曖昧さなく独立して制約されます。 左側の条件により、不正な文字がユーザー名に漏れないことが保証され、右側の等価性チェックにより厳密なドメインの一致が強制されます。 すべての無効な形式はこれらの独立した制約の少なくとも 1 つに違反するため、無効な文字列がすべてのチェックに同時に合格することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

if s.count('@') != 1:
    print("no")
    sys.exit(0)

left, right = s.split('@')

if not left or right != "odoo":
    print("no")
    sys.exit(0)

for c in left:
    if not ('a' <= c <= 'z'):
        print("no")
        sys.exit(0)

print("yes")
```コードは文字列を読み取ることから始まり、ただちに単一の「@」制約を強制し、構造的に無効なケースをすべて早期に削除します。 

分割後、文字列の直接比較を使用して右側を検証します。これは、ターゲットが固定されているため、文字ごとのチェックよりも簡単かつ安全です。 

左側は 1 文字ずつ検証され、小文字のみが存在し、空でないことが確認されます。 この明示的なループにより、単純なプレフィックス チェックをすり抜けてしまう空のユーザー名や無効なシンボルなどの特殊なケースが回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        s = input().strip()
        if s.count('@') != 1:
            print("no")
        else:
            left, right = s.split('@')
            if not left or right != "odoo":
                print("no")
            else:
                ok = True
                for c in left:
                    if not ('a' <= c <= 'z'):
                        ok = False
                        break
                print("yes" if ok else "no")
    return out.getvalue().strip()

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、空のユーザー名です。 入力用`@odoo`、分割により空の左側部分が生成されます。 アルゴリズムは明示的にチェックします`if not left`なので、文字検証が試行される前に正しく拒否されます。 

もう 1 つの特殊なケースは、次のような複数の区切り文字です。`abc@odoo@odoo`。 初期チェックでは '@' が 1 つだけ必要なため、この入力は分割時に曖昧さなく即座に拒否され、不正な構造が誤って受け入れられるのを防ぎます。 

3 番目のケースは、ユーザー名の大文字と小文字の区別です。たとえば、`ABC@odoo`。 分割後、左側のループで範囲外の文字が検出されます。`'a'`に`'z'`、文字列は拒否されます。
