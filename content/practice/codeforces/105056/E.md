 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。各値は、バッチ中に保存されたレコードの正味の変化を表します。正の値は占有スペースを増加させ、負の値は空きスペースを増やします。 これらのバッチの連続セグメントについては、ストレージ 0 から順番に適用をシミュレートし、オーバーフローを回避するためにどれだけの追加容量が必要になるかを追跡します。 セグメントの機能は、そのセグメントのプレフィックスで到達する最高のストレージ レベルです。 

同様に、部分配列を見ると、ゼロから開始して段階的に値を累積します。 累計が増加するたびに、より多くの容量が必要になります。 減少するたびに、以前に使用されていたスペースのみが解放されます。 したがって、セグメントのコストは、そのセグメント内の最大プレフィックス合計になります。 

タスクは、考えられるすべてのサブ配列に対してこの値を計算し、すべてのサブ配列にわたってそれらを合計することです。 

制約は大きく、すべてのテスト ケースにわたる合計配列サイズは最大 200,000 です。 これにより、すべてのサブ配列を明示的に評価し、その中のプレフィックス最大値を再計算するアプローチは直ちに除外されます。これは、最悪の場合は 3 次になるためです。 テスト ケースごとに O(n^2) の解でも、すべてのテストを合計すると遅すぎます。 

「最大プレフィックス合計」についての素朴な考え方には、微妙な問題が生じます。 これを部分配列の合計の最大値として誤って扱ったり、エンドポイントのみに依存すると仮定したりすることがよくあります。 そうではありません。 セグメントの初期に小さな落ち込みがあり、その後に大きな増加が続くと、答えが大きく左右される可能性があり、その動作は境界だけでなく内部構造に依存します。 

たとえば、次のようなセグメントでは、`[2, 3, -4, 6]`、累計は次のとおりです。`2, 5, 1, 7`したがって、最終値が最大値でなくても、答えは 7 になります。 合計またはエンドポイントのみを考慮する方法は、ここでは失敗します。 

## アプローチ

 直接的な解決策は、すべてのペアを反復します。`(L, R)`、その部分配列内のプレフィックスの合計を計算し、最大値を追跡し、結果を累積します。 これは正しいですが、高価です。 各部分配列に対して O(長さ) の作業を実行し、全体で O(n^3) になります。 

グローバル プレフィックスの合計を事前に計算したとしても、各サブ配列のスライディング ウィンドウにわたる最大値が依然として必要であり、すべてのサブ配列にわたって評価するには二次関数のままです。 

重要な変換は、グローバル プレフィックスの合計を使用してサブ配列の動作を書き直すことです。 させて`P[i]`との接頭辞の合計になる`P[0] = 0`。 次に、部分配列内の累計`[L, R]`位置にある`i`等しい`P[i] - P[L-1]`。 部分配列の最大値は次のようになります。`f(L, R) = max(P[L], P[L+1], ..., P[R]) - P[L-1]`したがって、問題は 2 つの部分に分かれます。 最初の部分は、プレフィックス配列のサブ配列最大値の合計です。`P`。 2 番目の部分は、次のみに依存する線形項です。`P[L-1]`。 

2 番目の部分は簡単に集計できます。 最初の部分は古典的な問題です。すべてのサブ配列の最大要素の合計です。これは、単調スタックを使用して、各位置が最大値として寄与するサブ配列の数を数えることによって解決できます。 

これにより、問題全体が 2 つの線形計算に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テストごとに O(n^2) | お(1) | 遅すぎる |
 | 単調スタック + プレフィックス分解 | テストあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず問題をプレフィックスの合計に変換し、次にそれを「プレフィックス配列に対するサブ配列の最大値」部分と補正項に分離します。 

1. プレフィックス合計を構築する`P`どこ`P[0] = 0`そして`P[i] = A[1] + ... + A[i]`。 これにより、セグメントの合計を 2 つのプレフィックス値の差として表すことができます。 
2. セグメントのコストを書き換える`[L, R]`として`max(P[L..R]) - P[L-1]`。 減算項は左側のエンドポイントにのみ依存します。これは、後で独立した集計が可能になるため、非常に重要です。 
3. の合計寄与度を計算します。`-P[L-1]`すべてのサブ配列にわたる部分。 固定インデックスの場合`i = L-1`、で始まるすべての部分配列に表示されます。`L = i+1`、それで、`(n - i)`サブアレイ。 私たちは掛け算をします`P[i]`その数と合計によって`i`。 
4. 配列全体のサブ配列の最大値の合計を計算します。`P`。 ポジションごとに`i`、サブ配列の数を決定します`[L, R]`持っている`P[i]`最大の要素として。 これは、単調減少スタックを使用して、左右で最も近い大きい要素を見つけることによって行われます。 
5. 各インデックスについて`i`の最大値であれば、`count_left[i]`Lの選択肢と`count_right[i]`R の選択肢の場合、その寄与は`P[i] * count_left[i] * count_right[i]`。 これらの寄与を合計すると、すべてのサブアレイの最大値の合計が得られます。 
6. ステップ 3 から線形項を減算して、最終的な答えを取得します。 

### なぜ効果があるのか

 プレフィックス変換は、元の「セグメント内の最大累計合計」をプレフィックス値に対する静的範囲最大クエリに変換します。 これにより、動的蓄積への依存が解消されます。 この形式になると、すべての部分配列の値は、固定配列要素の最大値から決定論的なオフセットを差し引いた値にのみ依存します。 最大分解プロパティにより、各プレフィックス値が明確に定義されたサブ配列のセットに対して独立して寄与することが保証されます。これはまさに単調スタックがカウントするものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # prefix sums
    P = [0] * (n + 1)
    for i in range(1, n + 1):
        P[i] = P[i - 1] + a[i - 1]

    # We work on P[0..n]
    # Step 1: sum of subarray maximums over P
    arr = P

    nP = n + 1

    # previous greater (strict) and next greater (>= or > carefully handled)
    left = [0] * nP
    right = [0] * nP

    stack = []
    for i in range(nP):
        while stack and arr[stack[-1]] <= arr[i]:
            stack.pop()
        left[i] = stack[-1] if stack else -1
        stack.append(i)

    stack = []
    for i in range(nP - 1, -1, -1):
        while stack and arr[stack[-1]] < arr[i]:
            stack.pop()
        right[i] = stack[-1] if stack else nP
        stack.append(i)

    sum_max = 0
    for i in range(nP):
        l = i - left[i]
        r = right[i] - i
        sum_max += arr[i] * l * r

    # Step 2: subtract linear contribution
    sub = 0
    for i in range(nP - 1):
        sub += P[i] * (n - i)

    print(sum_max - sub)

if __name__ == "__main__":
    solve()
```コードは、すべてのセグメントの合計が 2 つのプレフィックス値の差になるようにプレフィックスの合計を構築することから始まります。 次に、プレフィックス配列のサブ配列の最大値を数えることとして問題を処理します。 

単調スタック セクションは、プレフィックス値ごとに、最大値を維持したまま左右にどこまで拡張できるかを計算します。 左側の境界は直前の厳密に大きい値で停止し、右側の境界は次に大きいか等しい値で停止し、各部分配列が正確に 1 回カウントされるようにします。 

最後に、減算項により固定オフセットが考慮されます。`P[L-1]`で始まるすべての部分配列に表示されます。`L`。 

## 実用的な例

 検討してください`A = [2, 3, -4]`。 プレフィックス配列は`P = [0, 2, 5, 1]`。 

部分配列の最大値を超える場合`P`、各間隔を調べます。 

| サブアレイ | マックスP |
 | --- | --- |
 | [0] | 0 |
 | [0,2] | 2 |
 | [0,2,5] | 5 |
 | [2,5] | 5 |
 | [2,5,1] | 5 |
 | [5] | 5 |
 | [5,1] | 5 |
 | [1] | 1 |

 合計すると、最大値からの合計寄与が得られます。 次に、開始プレフィックス値に基づいて線形項を減算します。 

ここで考えてみましょう`A = [3, -5]`、 それで`P = [0, 3, -2]`。 

すべてのサブ配列:

 | サブアレイ | マックスP |
 | --- | --- |
 | [0] | 0 |
 | [0,3] | 3 |
 | [3] | 3 |
 | [3,-2] | 3 |
 | [-2] | -2 |

 これは、負の接頭辞が周囲の構造に応じて最大値にどのように関与するかを示しています。 

これらの例は、変換によって構造が正しく分離されることを確認します。最大値は、元の符号ではなく、接頭辞値の相対的な順序にのみ依存します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        n = int(input())
        a = list(map(int, input().split()))

        P = [0] * (n + 1)
        for i in range(1, n + 1):
            P[i] = P[i - 1] + a[i - 1]

        arr = P
        nP = n + 1

        left = [0] * nP
        right = [0] * nP

        st = []
        for i in range(nP):
            while st and arr[st[-1]] <= arr[i]:
                st.pop()
            left[i] = st[-1] if st else -1
            st.append(i)

        st = []
        for i in range(nP - 1, -1, -1):
            while st and arr[st[-1]] < arr[i]:
                st.pop()
            right[i] = st[-1] if st else nP
            st.append(i)

        sum_max = 0
        for i in range(nP):
            sum_max += arr[i] * (i - left[i]) * (right[i] - i)

        sub = 0
        for i in range(nP - 1):
            sub += P[i] * (n - i)

        return str(sum_max - sub)

    return solve()

## 特殊なケース

 単一要素の配列は、アルゴリズムが正の場合は最大プレフィックスが単にその要素であり、それ以外の場合はゼロであると正しく解釈するかどうかをテストします。 プレフィックス変換により、サブ配列のオーバーカウントが発生しないことが保証されます。 

全負の配列では、累計がゼロより大きくならない場合でも、プレフィックス maxima が正しく動作することが保証されます。 単調スタックは引き続き寄与をカウントしますが、減算項が正しく優勢となり、すべてのサブアレイにわたって必要な合計容量がゼロになります。 

大きな正と負の値を交互に使用すると、最終的なプレフィックスが小さい場合でも中間ピークが捕捉されることが確認されます。これが、合計の代わりにプレフィックス最大値を使用することが不可欠な理由です。
