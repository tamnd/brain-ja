 ## 解決策
 # 問題の理解

 ボードには、オープン セル、ブロックされたセル、サイコロの開始位置、および 1 から 6 までのターゲット番号を含むいくつかのセルが含まれています。サイコロは固定された向きで始まります。上面は 6、北面は 4、西面は 2 です。移動すると、隣接するブロックされていないセルにサイコロが転がり、出目の方向に応じて方向が変わります。 

サイコロが番号の付いたセルの上にあり、その上面の値がそのセルに書かれた数字と等しい場合、そのセルは 1 ポイントを与えます。 各セルは、ダイスが何度も到達した場合でも、最大 1 回だけ貢献できます。 タスクは、収集できるポイントの最大数を見つけることです。 

ボードの寸法は最大 100 x 100 で、最大 10,000 個のセルが与えられます。 可能な歩行の数は移動の数とともに指数関数的に増加するため、パスを直接検索することは不可能です。 たとえ長さ 100 の方向の考えられるすべてのシーケンスだけを考慮したとしても、可能性の数はすでに探索できる数をはるかに超えています。 有用な観察は、ダイには可能な方向が 24 個しかないため、意味のある状態の総数は十分に少なく、最大でも 100 × 100 × 24 = 240,000 状態であるということです。 

微妙な点は、単一の最短パスや少ない移動数のパスを見つけることが目的ではないということです。 ダイはセルを再訪問し、自由に動き回ることができます。 セルを訪問済みとしてマークし、二度とそのセルに入らないソリューションでは、今後のスコアリングの機会が誤って削除されてしまいます。 

例えば：```
1 2
s1
..
```正しい答えは、`1`。 ダイスは、次のセルを含むセルに移動できます。`1`何らかのオリエンテーションでスコアを付けます。 方向を無視する通常のグリッド BFS は、最初の訪問ですべてが決まると想定し、異なるダイ面で同じ位置に到達できることを見逃してしまう可能性があります。 

もう 1 つのケースは、セルに到達できてもスコアを獲得できない場合です。```
1 2
s2
..
```答えは、番号が付けられたセルの数によって自動的に決まるわけではありません。 セルは、上面がその値と一致する場合にのみ寄与します。 到達可能なすべての番号付きセルをカウントする不用意なアプローチでは、次のエラーが返されます。`1`、ただし、正解は次のとおりです。`0`必要な向きが不可能な場合。 

最後のエッジ ケースは、開始セルがすぐにはカウントされないことです。 開始位置に数字が書かれていない場合、得点はありません。 問題により開始セルに数値が許可された場合でも、同じ状態グラフのアイデアで正しく処理されます。 

## アプローチ

 この問題を考える強引な方法は、考えられるすべてのロールのシーケンスを試し、得られた最良のスコアを記録し続けることです。 考えられるあらゆる移動戦略が考慮されているため、これは正しいです。 問題は、可能なパスの数が爆発的に増加することです。 どの状態からでも最大 4 つの移動が可能であるため、多数の移動の後、探索されるパスの数は指数関数的に増加します。 

私たちを救ってくれる構造は、ダイには無制限のメモリがないということです。 その将来の動作は、現在のボード セルとダイの現在の方向という 2 つのことだけに依存します。 同じ向きで同じセルに戻ると、まったく同じ将来の可能性が得られるため、移動の完全な履歴は無関係です。 

これにより、問題はグラフの到達可能性に変わります。 各状態はペアです`(row, column, orientation)`。 ダイを移動すると、これらの状態の間にエッジが作成されます。 すべてのロールはロールバックすることで元に戻すことができるため、BFS または DFS を使用して到達可能なすべての状態を調査できます。 

到達可能な状態をすべて見つけた後は、実際の最終ルートをシミュレートする必要はありません。 到達可能なすべての状態は、到達可能な状態グラフのウォーク中に訪問できます。 したがって、すべてのボード セルについて、少なくとも 1 つの到達可能な方向が正しい番号を上に配置していれば、そのセルを収集できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 手数の指数関数 | 指数 | 遅すぎる |
 | 状態グラフの検索 | O(nm × 24) | O(nm × 24) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. あらゆる可能なダイの向きを状態として表現します。 サイコロには 6 つの面がありますが、反対側の面は固定されているため、立方体には物理的に 24 の方向しかありません。 与えられた方向から開始して、4 方向にローリングすることで新しい方向を生成します。 
2. 開始セルと初期ダイ方向を含む状態から BFS を開始します。 位置とともに方向を保存する理由は、同じセルがどの面が上にあるかによって異なる動作をする可能性があるためです。 
3. 状態を探索するときは、可能な 4 つのロールをすべて試してください。 ボードから出る動きやブロックされたセルに入る動きは無視します。 有効な移動ごとに、新しい方向を計算し、以前に到達していない場合は新しい状態を追加します。 
4. BFS が完了したら、到達可能なすべての状態を検査します。 状態が番号付きセル上にあり、上面がそのセルの値と等しい場合、そのセルを収集可能としてマークします。 
5. マークされたセルを数えます。 すべての収集可能なセルは到達可能な状態に対応しており、到達可能な状態グラフではそのようなすべての状態を訪問できるため、このカウントは可能な最大スコアです。 

なぜ機能するのか: BFS は、ダイが到達できる状態を正確に調査します。 位置と方向がダイスを完全に記述するため、状態グラフには将来の手を決定するために必要なすべての情報が含まれています。 すべての得点機会は、一致する上面を持つ到達可能な状態によって表され、すべての到達可能な状態は何らかのウォークで横断できるため、そのようなすべてのセルを収集できます。 一致する到達可能な状態を持たないセルはポイントを与えることができません。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def roll(state, direction):
    top, bottom, north, south, west, east = state

    if direction == 0:  # east
        return (west, east, north, south, bottom, top)
    if direction == 1:  # west
        return (east, west, north, south, top, bottom)
    if direction == 2:  # north
        return (south, north, top, bottom, west, east)
    return (north, south, bottom, top, west, east)  # south

def solve():
    n, m = map(int, input().split())
    board = [input().strip() for _ in range(n)]

    sr = sc = -1
    for i in range(n):
        for j in range(m):
            if board[i][j] == 's':
                sr, sc = i, j

    start = (6, 1, 4, 3, 2, 5)

    orientations = []
    index = {}
    queue = deque([start])
    index[start] = 0

    while queue:
        cur = queue.popleft()
        orientations.append(cur)
        for d in range(4):
            nxt = roll(cur, d)
            if nxt not in index:
                index[nxt] = len(index)
                queue.append(nxt)

    dirs = [(-1, 0, 2), (1, 0, 3), (0, -1, 1), (0, 0, 0)]
    # The last entry is replaced below because east has no simple row/col pair.
    moves = [(-1, 0, 2), (1, 0, 3), (0, -1, 1), (0, 1, 0)]

    seen = [[[False] * 24 for _ in range(m)] for _ in range(n)]
    seen[sr][sc][index[start]] = True

    q = deque([(sr, sc, index[start])])

    while q:
        r, c, o = q.popleft()
        cur = orientations[o]

        for dr, dc, d in moves:
            nr = r + dr
            nc = c + dc

            if not (0 <= nr < n and 0 <= nc < m):
                continue
            if board[nr][nc] == 'x':
                continue

            no = index[roll(cur, d)]
            if not seen[nr][nc][no]:
                seen[nr][nc][no] = True
                q.append((nr, nc, no))

    ans = 0
    for i in range(n):
        for j in range(m):
            if board[i][j].isdigit():
                value = int(board[i][j])
                ok = False
                for o in range(24):
                    if seen[i][j][o] and orientations[o][0] == value:
                        ok = True
                        break
                if ok:
                    ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装の最初の部分では、24 個すべての立方体の方向が生成されます。 タプルの順序は`(top, bottom, north, south, west, east)`これにより、各ロール操作が面の単純な再割り当てになります。 

BFS は、行、列、方向 ID の 3 次元状態を保存します。 方向 ID は事前に計算されたリストから取得され、トラバーサル中にタプルの比較が繰り返されることを回避します。 

スコアリングフェーズはトラバーサルとは別のものです。 状態に到達することとセルを収集することは異なる概念であるため、これは意図的なものです。 セルには、正しい上面を露出する到達可能な方向が 1 つだけ必要です。 

境界チェックにより無効な移動が防止され、ブロックされたセルは新しい状態を追加する前にスキップされます。 状態の数は十分に少ないため、Python は訪問したすべての状態を安全に保存できます。 

## 実用的な例

 最初のサンプルの場合:```
3 4
.23s
4.2x
xx.1
```BFS とスコアリング フェーズの簡略化されたトレースは次のとおりです。 

| ポジション | オリエンテーショントップ | アクション |
 | --- | --- | --- |
 | (0,3) | 6 | BFS を開始する |
 | (0,2) | 2 | 2 | を含むセルを収集します。 
| (0,1) | 5 | スコアなし |
 | (1,1) | 3 | スコアなし |
 | (1,0) | 4 | 4 を含むセルを収集 |
 | (2,2) | 1 | 1 を含むセルを収集 |

 完全な到達可能な状態グラフには、示されているものよりも多くの方向が含まれており、これらの追加の状態により、ダイはすべての一致するセルを収集できます。 最終的なカウントは、`5`1 つを除くすべての番号付きセルは、到達可能な方向と一致する可能性があるためです。 

2 番目のサンプルの場合:```
2 2
4s
22
```トレースは次のとおりです。 

| ポジション | オリエンテーショントップ | アクション |
 | --- | --- | --- |
 | (0,1) | 6 | BFS を開始する |
 | (0,0) | 2 | スコアなし |
 | (1,1) | 3 | スコアなし |
 | (1,0) | 4 | スコアなし |

 含まれている 2 つのセル`2`到達可能ですが、上面が以下の場合はどちらも到達できません`2`。 答えは`1`を含むセルのみであるため、`4`合わせることができます。

 ## 特殊なケース

 番号付きセルが異なる方向でのみ到達可能なボードの場合、アルゴリズムは最初の訪問後に停止しません。 例えば：```
2 2
s1
..
```BFS は、セルへの最初の到着と、他のすべての到達可能な方向の両方を保存します。 を含むセルの場合、`1`がチェックされている場合、アルゴリズムは上面で到達可能な状態を見つけます。`1`そしてそれを数えます。 

次のような、一致する方向が存在しない、到達可能な番号付きセルの場合:```
2 2
s2
..
```BFS は引き続きセルを探索しますが、スコアリング フェーズでは、到達可能なすべての方向の上面をチェックします。 何も表示されない場合`2`、セルは無視されます。 

障害物のあるボードの場合:```
3 3
sxx
x1x
xx2
```BFS は有効なセル内の状態のみを展開します。 孤立した番号付きセルは決して到達可能な状態にはならないため、ポイントを提供することはできません。 特別な処理を行わなければ、答えはゼロのままです。
