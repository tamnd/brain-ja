 ## 解決策
 ## 問題の理解

 真珠の列を表すバイナリ文字列が与えられます。各真珠は白または黒です。 システムは、長期にわたって 2 つの操作をサポートします。 

1 回の操作で範囲内のすべての真珠の色が反転し、白が黒に、黒が白に変わります。 もう 1 つの操作は、サブセグメントについて質問し、かなり珍しい削除プロセスを定義します。セグメントから連続したチャンクを繰り返し削除します。削除される各チャンクは、それ自体が厳密に交互の色を持つ必要があります。つまり、そのチャンク内の隣接する 2 つのパールが同じ色を共有しないことを意味します。 チャンクを削除した後、残りのパーツを接着します。これはセグメント全体がなくなるまで続きます。 質問は、必要なそのような削除操作の最小限の数を尋ねることです。 

重要なのは、選択された各チャンクがすでに有効な代替文字列である必要があるため、再配置したり修正したりすることはできないということです。 交互条件をすでに満たしているセグメントのみを選択します。 

この制約は、文字列の長さと操作の数の両方が最大 100 万であることを示唆しており、クエリごとに部分文字列全体を再構築またはスキャンするアプローチは即座に除外されます。 クエリごとに最初から再計算するソリューションは、最悪の場合、二次関数の動作に低下し、失敗します。 

微妙な点は、範囲の反転によって文字列が時間の経過とともに変化するため、静的に回答を前処理できないことです。 もう 1 つの重要な点は、セグメントの削除は順番に独立しているため、最適な戦略は、削除間の動的な相互作用ではなく、元の部分文字列の構造にのみ依存することです。 

よくある間違いは、削除後の複雑なマージ動作について考えることです。 たとえば、削除をシミュレートし、隣接関係の変化が将来の選択に動的に影響を与えると考えるかもしれません。 実際には、元の部分文字列を有効な交互の部分に分割することだけを考慮しているため、マージのステップでは元の隣接関係を超える新しい構造は導入されません。 

## アプローチ

 ブルートフォースのアイデアは単純です。クエリごとに部分文字列を抽出し、それを最小数の交互セグメントに貪欲に分割します。 欲張りな観察としては、セグメント内では、隣接する文字が異なる限り延長でき、連続する 2 つの文字が等しい場合は常にカットする必要があるということです。 これが機能するのは、交互のセグメントには等しく隣接する境界を含めることができず、そのような境界ごとに新しい部分が強制的に作成されるためです。 

ただし、このアプローチでは、クエリごとに範囲全体をスキャンする必要があります。 最大 100 万のクエリと最大 100 万の長さの文字列では、最悪のケースは実行不可能になり、約 10¹² の文字チェックに達します。 

重要な観察は、答えは間隔内の隣接する等しい文字を持つ位置がいくつあるかによってのみ決まるということです。 s[i] が s[i+1] に等しい位置 i として境界を定義すると、各境界は新しいセグメントを強制します。 したがって、クエリ間隔 [L, R] の答えは、単純に 1 にその間隔内の境界の数を加えたものになります。 

これにより、問題は 1 から n-1 までの位置 i にわたって動的バイナリ配列を維持することになり、各位置は s[i] が s[i+1] に等しいかどうかを格納します。 範囲の反転は、等価関係が一貫性を保つかどうかにのみ影響します。 重要なのは、隣接するペアの両方の端点を反転すると等価性が維持されるため、各隣接するペアの等価性インジケーターはセグメント全体の反転の下では変化しません。 これは、更新の構造を簡単にする重要な簡素化です。 

必要なのは、これらの等価フラグを維持し、遅延伝播ブックキーピングによって派生された等価情報を正しく保持しながら、元の文字列の範囲反転をサポートするセグメント ツリーだけです。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース | O(nq) | O(n) | 遅すぎる |
 | 遅延反転を使用したセグメント ツリー | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 元の文字列に対するセグメント ツリーを維持します。 各ノードには、セグメント内の最初の文字、セグメント内の最後の文字、およびセグメント内の等隣接ペアの数という 3 つの情報が格納されます。 また、セグメントを反転する必要があるかどうかを示す遅延フラグも維持します。 

1. 初期文字列からセグメント ツリーを構築します。 各リーフ ノードの最初と最後は文字自体であり、内部隣接関係がないため、カウントは 0 です。 内部ノードの場合、子の数を合計し、左の子の最後の文字が右の子の最初の文字と等しい場合にさらに 1 つ追加することで子をマージします。 
2. [L, R] に関するクエリに答えるために、セグメント ツリーにクエリを実行して、その区間内の等隣接ペアの数を取得します。 答えは、その値に 1 を加えたものです。完全に交互になるセグメントはゼロの等隣接境界に対応し、したがって正確に 1 つの部分が必要となるためです。 
3. [L, R] に対する反転操作を処理するには、遅延範囲更新を適用します。 セグメントが完全にカバーされると、その遅延フラグを切り替え、保存されている最初と最後の文字を交換します。 
4. 遅延更新をツリーの下にプッシュするとき、遅延フラグを切り替えてエンドポイントを交換することによって、フリップを子に伝播します。 
5. 重要な特性は、等しい隣接ペアの数が反転しても変わらないため、更新中に再計算することはありません。 

なぜそれが機能するのかは、答えが隣接性の等価構造のみに依存するという観察から来ています。 2 つの隣接する文字が間隔内で等しい場合、有効な分解ではそれらを交互に異なるセグメントに分割する必要があります。 逆に、隣接する 2 つの文字が異なる場合、それらは安全に同じセグメントに留まることができます。 これにより、最小分割は等価境界の数に 1 を加えたものと正確に等しくなります。 セグメント ツリーはこれらの境界を暗黙的に維持し、その有効性を変更することなく更新をサポートします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, s):
        self.n = len(s)
        self.s = s
        self.first = [0] * (4 * self.n)
        self.last = [0] * (4 * self.n)
        self.cnt = [0] * (4 * self.n)
        self.lazy = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1)

    def build(self, idx, l, r):
        if l == r:
            v = self.s[l]
            self.first[idx] = v
            self.last[idx] = v
            self.cnt[idx] = 0
            return
        m = (l + r) // 2
        self.build(idx * 2, l, m)
        self.build(idx * 2 + 1, m + 1, r)
        self.pull(idx)

    def pull(self, idx):
        lc, rc = idx * 2, idx * 2 + 1
        self.first[idx] = self.first[lc]
        self.last[idx] = self.last[rc]
        self.cnt[idx] = self.cnt[lc] + self.cnt[rc]
        if self.last[lc] == self.first[rc]:
            self.cnt[idx] += 1

    def apply_flip(self, idx):
        self.lazy[idx] ^= 1
        self.first[idx] ^= 1
        self.last[idx] ^= 1

    def push(self, idx):
        if self.lazy[idx]:
            for child in (idx * 2, idx * 2 + 1):
                self.apply_flip(child)
            self.lazy[idx] = 0

    def update(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            self.apply_flip(idx)
            return
        self.push(idx)
        m = (l + r) // 2
        if ql <= m:
            self.update(idx * 2, l, m, ql, qr)
        if qr > m:
            self.update(idx * 2 + 1, m + 1, r, ql, qr)
        self.pull(idx)

    def query(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.cnt[idx]
        self.push(idx)
        m = (l + r) // 2
        res = 0
        if ql <= m:
            res += self.query(idx * 2, l, m, ql, qr)
        if qr > m:
            res += self.query(idx * 2 + 1, m + 1, r, ql, qr)
        return res

def main():
    n, q = map(int, input().split())
    s = list(map(int, list(input().strip())))
    st = SegTree(s)

    out = []
    for _ in range(q):
        tmp = input().split()
        t, l, r = tmp[0], int(tmp[1]) - 1, int(tmp[2]) - 1
        if t == 'M':
            st.update(1, 0, n - 1, l, r)
        else:
            if l == r:
                out.append("1")
            else:
                eq = st.query(1, 0, n - 1, l, r)
                out.append(str(eq + 1))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```セグメント ツリーには、文字列を再構築せずに隣接ベースのクエリに答えるのに十分な構造が格納されます。 唯一の微妙な点は、等価性カウントはフリップとは独立しているため、更新はエンドポイント文字にのみ影響することです。そのため、フリップ操作中に内部カウントには決して触れません。 

クエリ ロジックにより、問題全体が間隔にわたる単一の統計に還元され、セグメント ツリーにより、対数時間で取得できることが保証されます。

 ## 特殊なケース

 1 文字の間隔は最も単純なケースです。隣接するペアがないため、答えは常に 1 になります。 クエリでは等しいペアが 0 個返され、1 が加算されるため、アルゴリズムはこれを直接処理します。 

次のような完全に交互の文字列`010101`には等しく隣接する境界がないため、それに対するクエリは境界を返します。 セグメント ツリーは全体を通してゼロを格納し、フリップは各ペアの両方のエンドポイントを同時に反転するため、この構造を保存します。 

次のような均一な文字列`000000`隣接するペアはすべて等しいため、最大の境界が生成されます。 各クエリは完全な文字数を返し、更新によりそれが反転されます。`111111`、同じように動作します。 遅延反転はエンドポイントを切り替えるだけですが、等価性カウントは安定したままであり、更新全体での正確性が保証されます。
