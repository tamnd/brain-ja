 ## 解決策
 ## 問題の理解

 私たちは 3 つの回転コンポーネントからなるシステムを扱っています。 各コンポーネントには円形スケール上の位置があり、完全に回転するたびに、固定ステップ数の後に開始点に戻ります。 ここでの工夫は、各コンポーネントの回転量を直接選択しないことです。 代わりに、各操作で 3 つのコンポーネントのうち 2 つを 1 ステップずつ回転し、3 つ目は変更しないままにする操作を実行します。 

各コンポーネントには初期オフセットがあり、それぞれに独自の係数もあります。つまり、最終位置は独自のサイクル長を法として評価されます。 いくつかの操作を実行した後、3 つのコンポーネントすべてを固定の基準方向に揃える必要があります。 

簿記の観点からプロセスを見ると、各操作は 2 つのコンポーネントに寄与し、1 つはそのまま残ります。 多くの操作にわたって、これにより、コンポーネントごとに 1 つずつ、コンポーネントが選択されなかった回数を示す 3 つの非負の整数が生成されます。 これらの導出されたカウントは、3 つのモジュール制約を同時に満たさなければなりません。 目標は、操作の合計数を最小限に抑えることです。これは、これらの導出されたカウントの線形結合を最小限に抑えることと同じです。 

入力サイズの制約は非常に厳しいため、3 つの変数の自然状態空間にわたる三次探索は実行不可能です。 すべての変数ペアにわたる二次探索でも、各状態遷移が定数時間でない限り境界線になります。 これは、ソリューションが操作を直接シミュレートするのではなく、モジュール式システムの構造を利用する必要があることを示唆しています。 

3 つの合同式が独立して解けると仮定すると、微妙な失敗例が発生します。 たとえば、2 つの変数に有効な値を選択し、3 番目の変数を独立して強制すると、3 番目の変数が 3 つの方程式すべてに同時に関与するため、壊れます。 もう 1 つの一般的な落とし穴は、非負性を強制せずにシステムを純粋なモジュールとして扱うことです。これにより、負の操作数に対応する有効なモジュール ソリューションが得られます。 

## アプローチ

 ブルートフォースの観点は、操作上の定義から始まります。 各ステップは 3 つのコンポーネントの中からペアを選択するため、S ステップの後には、各ペアが何回選択されたかを示す 3 つのカウンターが表示されます。 これらから、各コンポーネントが選択されなかった回数を導き出し、これらはモジュラー制約に直接現れます。 単純な解決策では、3 つのペアにわたる演算の可能な分布をすべて合理的な限界まで列挙し、結果の構成がすべての制約を満たすかどうかをチェックします。 

自然探索空間は係数範囲の 3 乗のように増大するため、これはすぐに実行不可能になります。 各変数を最大 2000 に制限したとしても、トリプルの数は数十億のオーダーであり、各チェックにはモジュラー演算が含まれます。 

重要な構造的観察は、層の各ペアが選択される回数に関して書き換えられると、システムは 3 つの変数において線形であるということです。 (0,1)、(0,2)、(1,2) のペアを選択する回数を a、b、c とすると、各制約は a、b、c で​​線形合同になります。 これにより、問題は、a + b + c を最小化する目的で、モジュラー制約の下で小さな線形システムの非負の整数解を見つけることに変換されます。 

重要な削減点は、2 つの変数を固定すると、3 番目の変数は 3 つの同時合同のモジュラー システムまで決定されるということです。 すべてのトリプルを探索する代わりに、ペアのみを探索し、建設的な中国剰余計算を使用して 3 番目の変数の実現可能性と最小限の完了を計算します。

 ## アルゴリズムのチュートリアル

 この問題を、層の各ペアの選択に対応する操作数 a、b、c の観点から書き直します。 これにより、t 値による間接表現が削除され、直接線形システムが得られます。 

1. 各層に対する操作の効果を表現します。 各ペア演算は正確に 2 つのレイヤーに +1 を与えるため、各制約は、参加に応じて係数 2、1、および 1 を持つ a、b、および c の線形式になります。 このステップは、「選択された」層と「選択されていない」層の間の非対称性を取り除き、対称な線形システムを与えるため、不可欠です。 
2. 各モジュール条件を a、b、c の一次式の合同式に変換します。 各方程式は、対応するサイクル長を法とする線形剰余条件になります。 これにより、3 つの独立したモジュラー制約が生成されますが、すべて同じ変数が対象となります。 
3. a と b の値を固定します。 a と b が選択されると、各方程式は c に対する直接の制約になります。 各制約の形式は、c ≡ value modulo yi です。 これにより、問題は 3 つの自由度から 1 つに減りますが、同時に 3 つの合同式が発生します。 
4. 段階的な中国剰余構造を使用して c を解きます。 可能であれば、最初の 2 つの合同式を単一の剰余クラスに結合してから、3 番目の合同式とマージします。 各マージで、不一致を検出するか、関与するモジュライの最小公倍数を法とする一意の剰余クラスを取得します。 
5. c の有効な剰余クラスが見つかったら、最小の非負の代表を選択します。 これにより、固定 (a, b) ペアに対する最小の実現可能な c が得られます。これは、目的が c で単調であるために必要です。 
6. 総コスト a + b + c を計算し、すべてのペア (a、b) の最小値を追跡します。 a または b を大きく変更しても、実現可能性を有意義に向上させることはなく、目的が増加するだけであるため、検索範囲は最大係数によって安全に制限できます。 

### なぜ効果があるのか

 元の各ステップが 3 つの派生変数 a、b、c に線形的かつ独立して寄与するため、変換ではすべての実行可能な解が保存されます。 有効な演算シーケンスはすべて、正確に 1 つのトリプル (a、b、c) に対応し、その逆も同様です。 制約は純粋に線形合同であるため、実現可能性は剰余クラスのみに依存し、非負性要件を超える絶対大きさには依存しません。 2 つの変数を修正し、CRT を介して 3 番目の変数を再構築することにより、すべての残基一致構造を 1 回だけ列挙し、実行可能な解が見逃されたり、無効な解がカウントされなかったりすることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ext_gcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x, y = ext_gcd(b, a % b)
    return g, y, x - (a // b) * y

def mod_inv(a, mod):
    g, x, _ = ext_gcd(a, mod)
    if g != 1:
        return None
    return x % mod

def crt_pair(r1, m1, r2, m2):
    g, p, q = ext_gcd(m1, m2)
    diff = r2 - r1
    if diff % g != 0:
        return None, None
    lcm = m1 // g * m2
    step = m2 // g
    x = (diff // g) * p % (m2 // g)
    res = (r1 + m1 * x) % lcm
    return res, lcm

def solve_case(x, y):
    r = [(-x[i]) % y[i] for i in range(3)]
    ans = 10**30

    maxv = max(y)

    for a in range(maxv + 1):
        for b in range(maxv + 1):
            ok = True

            c1_r, c1_m = (r[0] - 2 * a - b) % y[0], y[0]
            c2_r, c2_m = (r[1] - a - 2 * b) % y[1], y[1]
            c3_r, c3_m = (r[2] - a - b) % y[2], y[2]

            c, m = c1_r, c1_m

            c, m2 = crt_pair(c, m, c2_r, c2_m)
            if c is None:
                continue
            c, m3 = crt_pair(c, m2, c3_r, c3_m)
            if c is None:
                continue

            if c < 0:
                c += ((-c) // m3 + 1) * m3

            ans = min(ans, a + b + c)

    return -1 if ans == 10**30 else ans

def main():
    t = int(input())
    for _ in range(t):
        x0, x1, x2, y0, y1, y2 = map(int, input().split())
        print(solve_case([x0, x1, x2], [y0, y1, y2]))

if __name__ == "__main__":
    main()
```実装では、まず各ターゲット アライメントを残基要件に変換します。 ネストされたループは、レイヤーの各ペアが何回選択されるかを表す a と b の可能な値を列挙します。 各ペアについて、c に対する暗黙の制約を導出し、標準の拡張ユークリッド ベースの CRT ルーチンを使用してそれらをマージします。 いずれかの時点でシステムに一貫性がなくなると、その (a, b) ペアは破棄されます。 

CRT ルーチンは最もデリケートな部分です。 これにより、2 つのモジュラー制約が重複する場合に、実現可能性と結合係数の両方が正しく計算されることが保証されます。 値が大きくなると目的が悪化するだけであるため、最後の正規化ステップでは c が最小の非負の代表として採用されることが保証されます。 

## 実用的な例

 すべての係数が等しく、初期オフセットが小さい小規模な構成を考えてみましょう。 これは、制約が 3 つの方程式にわたってどのように対称的に相互作用するかを示すのに役立ちます。 

y = [3, 3, 3]、x = [1, 2, 0] の場合を考えてみましょう。 剰余 r = [2, 1, 0] を計算します。 固定 (a, b) の場合、各方程式は c に対する線形制限を生成します。 CRT は 3 つの残基クラスすべてを整列させるか、そのペアを直ちに拒否します。 たとえば、a = 0、b = 0 は c ≡ 2 mod 3、c ≡ 1 mod 3 を生成しますが、これは矛盾しているため、破棄されます。 a = 1、b = 0 を試すと剰余がシフトされ、線形オフセットがどのように相互作用するかに応じて 3 つの制約すべてが整列する可能性があります。 

ここで、y = [2, 5, 7] など、1 つの係数が他の係数よりもはるかに小さい 2 番目のケースを考えてみましょう。 これにより、CRT マージ ロジックが強調されます。 各 (a, b) について、最初の 2 つの合同式は多くの場合、10 を法とする剰余にマージされ、その後、7 を法として調整されます。これは、中間係数がどのように増加するか、および非共素の場合を処理するために拡張 gcd が必要である理由を示しています。

 ## 特殊なケース

 主要なエッジ ケースは、モジュール制約が個別には満たされるが、結合すると一貫性がない場合に発生します。 たとえば、c の各合同式は独立して解を持つ可能性がありますが、それらを組み合わせた交差部分は空になります。 このような場合、CRT マージは早期に失敗し、アルゴリズムはその (a, b) ペアを正しくスキップします。 これにより、部分的な実現可能性を誤って有効な構成としてカウントすることが防止されます。 

もう 1 つの微妙なケースは、CRT から計算された c が負の場合です。 目的関数は剰余クラスだけでなく絶対大きさに依存するため、実装ではそれを最小の非負代表に明示的に正規化します。 

すべてのモジュライが等しく、初期オフセットが対称である場合、最後のエッジ ケースが表示されます。 ここで、多くの (a, b) ペアが c に同一の制約を生成します。 注意して最小化しないと、過大評価したり、真の最小値を見逃したりする可能性があります。 (a, b) の完全な列挙により、最適な対称構成が依然として到達可能であることが保証されます。
