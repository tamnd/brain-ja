 ## 解決策
 ## 問題の理解

 整数の配列と固定整数が与えられます。$K$。 各クエリについて、インデックスから配列のサブセグメントを調べます。$l$に$r$そして、XOR の制約の下で長さを最大化する、このセグメント内の連続したサブ配列を選択したいと考えています。 

制約は、選択した部分配列内のすべての要素の XOR が最大でも次の値でなければならないということです。$K$。 クエリ範囲に完全に含まれるすべての有効なサブ配列のうち、可能な最大長を返します。 条件を満たすサブ配列がない場合は、ゼロを返します。 

主な問題点は、すべてのクエリが異なる範囲を尋ねることであり、各範囲内では、プレフィックスやサフィックスだけでなく、すべてのサブ配列に対して最適化が行われることです。 単純な考えなら、すべてのペアを試してしまうだろう$(u, v)$、XOR を計算し、条件をチェックしますが、これでは遅すぎます。$O(n^2)$クエリごとのサブ配列。 

制約により、これがさらに鮮明になります。 と$n, q \le 2 \cdot 10^4$、$O(n^2)$クエリごとのアプローチでは、おおよその結果が得られます$10^{12}$最悪の場合の操作は遠隔からは実行不可能です。 たとえ$O(n \log n)$クエリが密集している場合、クエリ ソリューションごとにタイムアウトになる危険性があります。 

XOR 構造ではさらに微妙な問題が発生します。 XOR は部分配列に対して単調ではないため、和の単調性に依存する古典的なスライディング ウィンドウのトリックを直接適用することはできません。 

素朴な考えによる失敗の簡単な例は、ウィンドウを拡大すると常に XOR が増加すると仮定することです。 考慮する：```
a = [1, 2, 3], K = 2
```部分配列 [1,2] には無効な XOR 3 がありますが、[2] だけは有効です。 拡大または縮小は予測どおりに動作しないため、ローカル ウィンドウの更新ではなくプレフィックス XOR 推論に依存する必要があります。 

## アプローチ

 ブルート フォース ソリューションは、各クエリを個別に処理します。 固定クエリの場合$[l, r]$、すべてのペアを列挙します$(u, v)$、の XOR を計算します。$a_u \oplus \cdots \oplus a_v$、制約を満たす最大長を維持します。 プレフィックス XOR を使用しても、各クエリには依然としてコストがかかります$O(n^2)$最悪の場合、セグメントごとに二次関数的に多くのサブ配列が存在するためです。 まで$2 \cdot 10^4$クエリを実行すると、これは不可能になります。 

重要な点は、サブ配列に対する XOR はプレフィックス XOR を使用して表現できることです。$$a_u \oplus \cdots \oplus a_v = pref[v] \oplus pref[u-1]$$これにより、条件が 2 つのプレフィックス値間の関係に変換されます。 ただし、依然として問題は、クエリ範囲内で最長の有効なペアを見つけることです。これは、プレフィックス インデックスを線上の点として扱い、ビットごとの制約を満たすペアを検索する必要があることを示唆しています。 

この構造は自然にバイナリ トライ (ビットごとのトライ) によって処理され、動的ウィンドウ内でプレフィックス XOR が維持されます。 右のエンドポイントごとに、XOR 制約が成立する最も左のエンドポイントを知りたいと考えます。 これは 2 ポインター スタイルのグローバル計算になりますが、クエリによって範囲が制限されるため、オフライン処理とセグメントベースの集計で拡張する必要があります。 

あらゆるポジションについて事前計算します$i$、最も早い位置$j$そのようなサブ配列$[j, i]$すべての有効な選択肢について制約を満たします。 これは、プレフィックス XOR を追跡し、条件を強制するトライを備えたスライディング ウィンドウを使用して維持できます。 各右エンドポイントの最適な有効な左境界がわかったら、問題をこれらの事前計算された間隔にわたる範囲最大クエリに変換できます。 

最後に、各クエリは次のことを尋ねることになります。$v \in [l, r]$、最大値はいくらですか$v - L[v] + 1$どこ$L[v]$の最小の有効な開始値です$v$それはクエリの中にあります。 これは範囲クエリの問題となり、セグメント ツリーで解決できます。

 ## アルゴリズムのチュートリアル

 まず、配列をプレフィックス XOR 形式に変換して、サブ配列 XOR が 2 つのプレフィックス値間の XOR として表されるようにします。 これが必要なのは、範囲制約をビットごとのトライ問題の標準形式であるペア制約に変えるためです。 

次に、インデックスに対して 2 ポインター ウィンドウを使用しながら、プレフィックス XOR 値に対してバイナリ トライを維持します。 アイデアは窓を維持することです$[l, r]$したがって、その内部のプレフィックス XOR の有効なペアごとに、サブ配列制約が満たされます。 延長するにつれて$r$、移動することでウィンドウを有効に保とうとします。$l$必要に応じて前に進みます。 

それぞれのポジションで$r$有効なウィンドウが得られたら、次で終わる部分配列の最小の有効な開始インデックスを決定できます。$r$として保存します。$L[r]$。 

すべて前処理を行った後、$L[r]$、配列上にセグメント ツリーを構築します。$r$で終わる部分配列によって達成可能な最良の答えを格納します。$r$、つまり$r - L[r] + 1$。 

各クエリ$[l, r]$次に、間隔にわたるこのセグメント ツリーの最大値を取得することによって応答されます。$[l, r]$ただし、有効な開始位置が少なくとも次の位置にある位置のみを考慮します。$l$。 計算された場合$L[r]$未満です$l$の場合、その部分配列はクエリ範囲内に完全には入っていないため、クランプする必要があります。 

### ステップ

 1. プレフィックス XOR 配列を計算する$pref$、 どこ$pref[i] = a_1 \oplus \cdots \oplus a_i$。 これにより、任意の部分配列 XOR が 2 つのプレフィックス値間の単一の XOR 式になります。 
2. 現在、インデックス上のスライディング ウィンドウ内にあるプレフィックス XOR のバイナリ トライを維持します。 各トライ ノードは、左ポインタが移動したときに削除できるようにカウントを保存します。 この構造により、XOR 制約を効率的にテストできます。 
3. 右ポインタを配列上で左から右に移動します。 挿入された新しいプレフィックス XOR ごとに、関連するすべてのペアが XOR を満たす必要があるという条件にウィンドウが違反しているかどうかを確認します。$\le K$。 存在する場合は、有効性が復元されるまで、左ポインタを進めてトライからプレフィックス値を削除します。 これにより、各位置で終了する最大有効ウィンドウが維持されます。 
4. 各右端点について$r$、最小の有効な開始インデックスを記録します$L[r]$。 これは、ウィンドウの現在の左ポインタから導出されます。 
5. アレイを構築する$best[r] = r - L[r] + 1$。 これは、正確に次の位置で終わる最長の有効な部分配列を表します。$r$グローバルな妥当性制約の下で。 
6. セグメントツリーを構築する$best$範囲の最大値のクエリに答えます。 
7. 各クエリについて$[l, r]$、その範囲にわたるセグメントツリーの最大値を返します。 有効な部分配列が存在しない場合は、0 を返します。 

### なぜ効果があるのか

 トライを伴うスライディング ウィンドウは、すべての誘導されたサブ配列が XOR 制約を満たすように、プレフィックス XOR 状態の最大セットを維持します。 制約に違反した場合は常に、最適化に必要な候補を除外することなく、左端の要素を削除することで実現可能性が復元されます。 これにより、正しいエンドポイントごとに、そこで終了する有効なサブ配列に参加できる最小の実行可能な開始位置が保存されることが保証されます。 すべての有効な部分配列は次のように出現する必要があるため、$(L[r], r)$この構造では、クエリをこれらのエンドポイントの最大範囲に減らすだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Trie:
    def __init__(self):
        self.child = [[-1, -1]]
        self.cnt = [0]

    def new_node(self):
        self.child.append([-1, -1])
        self.cnt.append(0)
        return len(self.child) - 1

    def insert(self, x):
        node = 0
        self.cnt[node] += 1
        for b in range(30, -1, -1):
            bit = (x >> b) & 1
            if self.child[node][bit] == -1:
                self.child[node][bit] = self.new_node()
            node = self.child[node][bit]
            self.cnt[node] += 1

    def remove(self, x):
        node = 0
        self.cnt[node] -= 1
        for b in range(30, -1, -1):
            bit = (x >> b) & 1
            node = self.child[node][bit]
            self.cnt[node] -= 1

    def max_xor(self, x):
        node = 0
        res = 0
        for b in range(30, -1, -1):
            bit = (x >> b) & 1
            want = bit ^ 1
            if self.child[node][want] != -1 and self.cnt[self.child[node][want]] > 0:
                node = self.child[node][want]
                res |= (1 << b)
            else:
                node = self.child[node][bit]
        return res

class SegTree:
    def __init__(self, arr):
        n = len(arr)
        self.n = n
        self.seg = [0] * (4 * n)
        self.build(1, 0, n - 1, arr)

    def build(self, idx, l, r, arr):
        if l == r:
            self.seg[idx] = arr[l]
            return
        m = (l + r) // 2
        self.build(idx * 2, l, m, arr)
        self.build(idx * 2 + 1, m + 1, r, arr)
        self.seg[idx] = max(self.seg[idx * 2], self.seg[idx * 2 + 1])

    def query(self, idx, l, r, ql, qr):
        if ql > r or qr < l:
            return 0
        if ql <= l and r <= qr:
            return self.seg[idx]
        m = (l + r) // 2
        return max(
            self.query(idx * 2, l, m, ql, qr),
            self.query(idx * 2 + 1, m + 1, r, ql, qr)
        )

def solve():
    n, K = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] ^ a[i - 1]

    trie = Trie()
    l = 0
    L = [1] * (n + 1)

    for r in range(1, n + 1):
        trie.insert(pref[r - 1])

        while l < r:
            # check if window is valid
            # brute check via trie: if any pair exceeds K, shrink
            # we test by trying best xor in window
            if trie.max_xor(pref[r]) <= K:
                break
            trie.remove(pref[l])
            l += 1

        L[r] = l + 1

    best = [0] * (n + 1)
    for i in range(1, n + 1):
        best[i] = max(0, i - L[i] + 1)

    seg = SegTree(best)

    q = int(input())
    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        ans = seg.query(1, 0, n, l, r)
        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()

セグメント ツリーには適切なエンドポイントごとに最適な回答が保存され、各クエリに対数時間で回答できるようになります。 プレフィックス XOR が位置で行われるため、プレフィックス インデックスと配列インデックスの間の off-by-one の処理は重要です。$i$で終わるサブ配列に対応します$i$。

 ## 特殊なケース

 重大なエッジケースは次のような場合です。$K = 0$。 この場合、XOR が 0 に等しい部分配列のみが有効になります。 例えば：```
a = [1, 1, 1], K = 0
```プレフィックス XOR パリティが一致する偶数長のサブ配列のみが有効です。 このアルゴリズムは、XOR がゼロ以外になるたびに積極的に縮小し、有効なプレフィックス等価状態のみがウィンドウ内に残るようにします。 

もう 1 つのエッジ ケースは、クエリ範囲に対して有効なサブ配列が存在しない場合です。 例えば：```
a = [8, 16], K = 1
```空でないすべての部分配列の XOR は 1 より大きいため、正解は 0 です。前処理後もすべての最良の値が 0 のままであるため、セグメント ツリーは当然 0 を返します。 

最後の微妙なケースは、有効性がローカルな要素ではなく、離れた要素に依存する場合です。 例えば：```
a = [5, 6, 7, 4], K = 3
```一部のサブ配列は、右端の要素を追加した後でのみ無効になり、複数の縮小ステップが強制されます。 スライディング ウィンドウは、ローカル チェックに依存するのではなく、グローバルな妥当性を繰り返し適用することで正確性を保証します。
