 ## 解決策
 ## 問題の理解

 循環文字列が与えられているため、部分文字列を末尾から先頭に折り返すことができます。 この円内の各位置には、小文字とそれに関連付けられた整数値があります。 文字列の長さの候補については、その長さの可能なすべての循環部分文字列を調べ、円内でこの部分文字列が出現するすべての開始位置を考慮します。 

固定サブストリング長の場合、それぞれの個別の循環サブストリングが開始位置のセットを定義します。 ルールにより、このセットは正確であることが強制されます。位置は、そこから始まる部分文字列が候補文字列と一致する場合に限り、セットに属します。 したがって、任意の位置を選択しているのではなく、同一の巡回部分文字列によってインデックスをグループ化しています。 

このようなグループごとに、その開始位置に割り当てられた値の XOR を計算します。 少なくとも 1 つのグループに空ではない出現セットがあり、それらの出現位置にわたる値の XOR が 0 に等しい場合、部分文字列は有効であるとみなされます。 タスクは、有効な循環部分文字列の可能な最大長を見つけることです。 

制約は n = 100000 までであり、すべての部分文字列を明示的に検査するアプローチは即座に除外されます。 循環文字列内の部分文字列の数は O(n^2) であるため、すべての長さとすべての開始位置を直接反復する解は、時間制限を数桁超えてしまいます。 

微妙なエッジ ケースは、部分文字列が文字列の終わりに回り込む場合です。 たとえば、「abcde」のような文字列では、インデックス 4 で始まる長さ 3 の部分文字列は「eab」になります。 線形配列内の部分文字列のみを処理するソリューションでは、これらの有効な循環一致が失われます。 

もう 1 つの障害モードは、グループ化せずにオカレンスを独立して処理することで発生します。 2 つの位置が同じ部分文字列を生成する場合、それらは別々ではなく一緒に XOR に寄与する必要があります。 グループ化を無視すると、XOR 計算が正しく行われなくなります。 

## アプローチ

 直接的なブルート フォース アプローチでは、長さ L を固定し、すべての開始位置 p をチェックし、部分文字列を他のすべてと循環的に比較し、等しい部分文字列をグループ化し、それらのインデックスに対して XOR を計算します。 2 つの部分文字列の各比較には O(L) のコストがかかり、O(n^2) 個の部分文字列があるため、長さあたり約 O(n^3) の時間がかかります。これは、n = 100000 ではまったく実行不可能です。 

ハッシュを使用して部分文字列の比較を最適化したとしても、L ごとにグループ化を再計算する必要があるため、すべての長さにわたる状態の合計は O(n^2) となり、それでも大きすぎます。 

重要な構造的観察は、単純な方法で長さごとに部分文字列の等価性を個別に再計算する必要がないということです。 循環文字列のすべての部分文字列は、最初の n 文字の開始位置に制限された、2 倍の文字列 S + S の部分文字列に正確に対応します。 これにより、循環問題が線形部分文字列問題に変換されます。 

線形表現に移行した後も、等しい部分文字列をグループ化し、それらの開始位置に対する XOR を集約する必要があります。 これはまさに接尾辞オートマトンが設計されたものです。 オートマトンの各状態は、同じ正しいコンテキストを共有する部分文字列のセットを表し、さらに重要なことに、部分文字列のすべての出現をコンパクトに表します。 

反転した二重文字列に対してサフィックス オートマトンを構築します。 元の文字列の開始位置に関する情報が必要であるのに対し、接尾辞オートマトンは部分文字列の終了位置を自然に集約するため、逆転は非常に重要です。 反転すると、反転した文字列の終了位置が元の循環文字列の開始位置に対応します。

オートマトン内の各出現は、対応する元の開始インデックスの値 V に寄与します。 各状態が、それが表す部分文字列のすべての開始位置の XOR を蓄積するように、サフィックス リンクを通じて XOR 値を伝播します。 次に、単純にすべての状態をチェックし、XOR が 0 である最大長を取得します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース部分文字列グループ化 | O(n^3) | お(1) | 遅すぎる |
 | 長さごとのハッシュ | O(n^2 log n) | O(n^2) | 遅すぎる |
 | 逆二重化文字列のサフィックス オートマトン | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字列を複製することで循環構造を線形構造に変換し、それを反転して部分文字列の出現が接尾辞の出現になるようにします。これは接尾辞オートマトンによって自然に処理されます。 

### ステップ

 1. 文字列 T = reverse(S + S) を作成します。 

これにより、S のすべての循環部分文字列が T の通常の部分文字列に対応することが保証され、ラップアラウンドは 2 倍化によって自動的に処理されます。 
2. T 上に接尾辞オートマトンを構築します。 

各状態は、T のさまざまな位置で終わる部分文字列のセットを表します。 
3. オートマトンに文字を挿入するときに、T の各位置に対して S + S で元のインデックスを追跡します。 

T の位置 j が S + S の位置 k に対応する場合、k は元の配列の k mod n にマップされます。 
4. T 内の各位置 j について、終了位置 j に対応するオートマトン状態に V[k mod n] を追加します。 

これにより、各オカレンスが正しい XOR 寄与ソースで初期化されます。 
5. 構築後、サフィックス リンクを介して長い状態から短い状態に値を伝播します。 

これにより、各状態がその部分文字列のすべての出現に対して XOR を蓄積するように、寄与がマージされます。 
6. 各状態について、オートマトン構造からその部分文字列の長さを計算します。 

状態に格納されている XOR 値がゼロで、その状態が少なくとも 1 つの出現に対応する場合、答えを更新します。 

### なぜ効果があるのか

 すべての循環部分文字列は、S + S の部分文字列の 1 つの同値クラスに対応するため、T の部分文字列の 1 セットに正確に対応します。接尾辞オートマトンは、T のすべての部分文字列を状態に分割し、それぞれが一意の部分文字列を表します。 すべての出現は正確に 1 回挿入され、その後正しく伝播されるため、各状態は、元の循環文字列内でその部分文字列が出現するすべての開始位置の XOR を正確に蓄積します。 すべての有効な部分文字列は、その出現セット全体にわたって XOR = 0 を満たす必要があるため、オートマトン全体にわたって状態を徹底的にチェックすることで、重複や省略なしにすべての可能性がカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SAM:
    def __init__(self):
        self.next = []
        self.link = []
        self.length = []
        self.xorv = []
        self.last = 0

        self.next.append({})
        self.link.append(-1)
        self.length.append(0)
        self.xorv.append(0)

    def extend(self, c, val):
        cur = len(self.next)
        self.next.append({})
        self.length.append(self.length[self.last] + 1)
        self.link.append(0)
        self.xorv.append(0)

        p = self.last
        while p != -1 and c not in self.next[p]:
            self.next[p][c] = cur
            p = self.link[p]

        if p == -1:
            self.link[cur] = 0
        else:
            q = self.next[p][c]
            if self.length[p] + 1 == self.length[q]:
                self.link[cur] = q
            else:
                clone = len(self.next)
                self.next.append(self.next[q].copy())
                self.length.append(self.length[p] + 1)
                self.link.append(self.link[q])
                self.xorv.append(0)

                while p != -1 and self.next[p].get(c) == q:
                    self.next[p][c] = clone
                    p = self.link[p]

                self.link[q] = self.link[cur] = clone

        self.last = cur
        self.xorv[self.last] ^= val
        return self.last

def solve():
    S = input().strip()
    V = list(map(int, input().split()))
    n = len(S)

    T = (S + S)[::-1]

    sam = SAM()
    pos_state = []

    for j, ch in enumerate(T):
        orig = (2 * n - 1 - j) % n
        state = sam.extend(ch, V[orig])
        pos_state.append(state)

    cnt = [0] * len(sam.next)
    order = sorted(range(len(sam.next)), key=lambda i: sam.length[i], reverse=True)

    for i in range(len(sam.next)):
        cnt[i] = 1

    for i in order:
        p = sam.link[i]
        if p != -1:
            sam.xorv[p] ^= sam.xorv[i]

    ans = 0
    for i in range(len(sam.next)):
        if sam.xorv[i] == 0:
            ans = max(ans, sam.length[i])

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、すべての循環部分文字列が連続部分文字列になるように、反転した 2 倍の文字列を構築します。 接尾辞オートマトンに挿入された各文字は、元の位置から対応する値を運びます。 マッピング`(2*n - 1 - j) % n`反転された 2 倍の文字列内の位置を元の円内の正しい開始インデックスに変換します。 

XOR 集計はサフィックス リンクを通じてプッシュされ、各状態がその部分文字列のすべての出現からの寄与を蓄積します。 最後に、すべての状態をスキャンし、XOR が 0 に等しい最大長を選択します。 

よくある落とし穴は、循環部分文字列では文字列を 2 倍にする必要があることを忘れていることです。 これがないと、境界を越える部分文字列は表現されず、答えは不正確になります。 

## 実用的な例

 小さな円形の文字列を考えてみましょう`S = "aba"`価値観を持って`[1, 2, 1]`。 

私たちは構築します`S + S = "abaaba"`それを逆にして取得します`T = "abaa ba"`適切に反転した`"abaa ba"`。 

| ステップ | 処理された文字 | 元のインデックス | 状態の長さ | 状態 | での XOR
 | --- | --- | --- | --- | --- |
 | 1 | | 0 | 1 | 1 |
 | 2 | b | 1 | 2 | 2 |
 | 3 | | 2 | 3 | 1 |
 | ... | ... | ... | ... | ... |

 伝播後、表す部分文字列は、`"aba"`すべての出現を収集し、その XOR は次のようになります。`1 ^ 2 ^ 1 = 2`、ゼロではないため、無効です。 

ここで、値が次のような場合を考えてみましょう。`[1, 1, 0]`。 同じ部分文字列`"aba"`XOR が生成されます`1 ^ 1 ^ 0 = 0`、長さ 3 が有効になります。 

これらのトレースは、妥当性がグループ化の正確さと周期的な発生の正確な集計に完全に依存していることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、有効な部分文字列が循環文字列の境界を囲む場合です。 たとえば、`"abcde"`、インデックス 4 で始まり長さ 3 の部分文字列は次のようになります。`"eab"`。 を使った施工は`S + S`これは、二重化された文字列内の連続した部分文字列として表現されることを保証し、反転により開始インデックスへの正しいマッピングが保持されます。 

もう 1 つのケースは、すべての文字が同一であるが、XOR 構造が相殺される場合です。 多くの部分文字列が存在する場合でも、開始インデックスが 0 と XOR される部分文字列のみが受け入れられます。 サフィックス オートマトンは、すべての同一の部分文字列を 1 つの状態に正しくグループ化し、それらの XOR が正しく集計されることを保証します。 

最後の微妙なケースは、部分文字列が 1 回しか出現しない場合です。 次に、XOR 条件は、その単一の値が 0 であるかどうかをチェックすることになります。 シングルトン状態は追加の寄与を伝播しないため、オートマトンはこれを自然に処理します。
