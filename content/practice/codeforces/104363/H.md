 ## 解決策
 ## 問題の理解

 固定の 10×10 ボードが与えられ、各セルが戦場タイルを表します。 一部のセルは壁になっており、使用できません。 1 つおきのセルには最初に多数の軍隊が含まれており、コア、砦、芝生、中立地域などのカテゴリに属します。 時間の経過とともに、いくつかのラウンドを待機すると、タイプに応じて一部のセルの軍隊の数が増加します。 

待機が終了すると、セル間で軍隊を任意に何度でも移動できる単一の大規模な「実行ラウンド」を実行することが許可されますが、2 つの制限があります。順序付けられた各セルのペアは最大 1 回しか使用できないこと、および x 個の軍隊をあるセルから別のセルに移動することは、x が現在の軍隊に待機時間とマンハッタンの距離に基づく線形許容量を加えたものを超えない場合にのみ許可されます。 すべての移動の後、壁以外のすべてのセルは少なくとも 1 つの部隊を獲得する必要があり、その 1 回の実行フェーズでボード全体 (壁を除く) を占領できれば成功とみなされます。 

タスクは、これを可能にするために必要な待機ラウンドの最小数を計算することです。 300 を超える待機ラウンドが必要な場合、答えは不可能であると宣言され、-1 が出力されます。 

盤面は小さいとはいえ、待つことでローカルな供給（各セルの軍隊は異なる速度で成長する）とグローバルな実現可能性（距離と時間の制約の下で1ラウンドでどれだけ移動できるか）の両方が変化することを理解することから困難が生じます。 

この制約は、考えられるすべての移動計画の総当りシミュレーションが実行不可能であることを意味します。 1 つの構成だけをシミュレートする場合でも、移動フェーズ自体には最大 100 個のセル間の相互作用が含まれ、考えられるすべての転送を推論すると、組み合わせ爆発が発生します。 答えは 300 で制限されているため、一定の待機時間の実現可能性をチェックするソリューションは効率的である必要があり、理想的には O(100²) または O(100² log 300) 程度です。 

重要な微妙な点は、総兵員数を追跡するだけの単純なアプローチは失敗するということです。 たとえば、兵力の総量は十分であるが、距離の制約により 1 ラウンド内での再配分が妨げられている場合、1 つの角に集中している構成は依然として不可能である可能性があります。 同様に、ペアごとの「1 回使用」制限を無視すると、転送能力を過大評価することになります。 

## アプローチ

 この問題を考える最も直接的な方法は、r ラウンドの待機をシミュレートし、最終的な再分配を実行できるかどうかを確認することです。 固定 r の場合、各セルには強化後の部隊数が決定されます。 次に、エッジごとの容量制約を尊重しながら、すべての非壁セルが少なくとも 1 つの部隊で終了することを保証する有効な転送セットが存在するかどうかを判断する必要があります。 

強引な解釈では、再分配を明示的にモデル化しようとします。 各セルが他のすべてのセルに部隊を派遣できるフローのようなシステムを構築し、最大フローまたは制約を満たす定式化を使用して実現可能性を解決しようとすることを想像することもできます。 ただし、この小さなグリッドでも、潜在的な直接転送の数は 10,000 であり、最大 300 までの r ごとに実現可能性をチェックすると、このアプローチは非常に遅くなります。 

重要な観察は、移動フェーズは実際には、複雑な方法でグローバルに経路や流れの分布を最適化することではないということです。 代わりに、すべてのセルは、受信者として「満足」できるかどうかに関して独立して動作します。再分配後に必要なのは、少なくとも 1 つの部隊のみです。 転送ではラウンドごとの操作数に制限はありませんが、各順序ペアは最大 1 回しか使用されないため、ソースからターゲットへの各エッジには明確な容量があります。 これにより、問題は、r によって決定される容量を持つ固定された完全な有向グラフに対する実現可能性チェックに変換されます。

与えられた r について、強化によって強化された利用可能な供給を、すべてのターゲット ノードが少なくとも 1 つのユニットを受け取るように分配できるかどうかという質問を再解釈できます。 グラフは高密度で小さいため、実現可能性は、容量の制約に違反することなく、すべてのノードに何らかのソースからの受信ユニットを割り当てることができるかどうかを確認することになります。 この構造により、r の二分探索が可能になります。これは、r を増加しても容量が増加するだけであり、実現可能性が低下することはないためです。 

したがって、解は r に関する単調な実現可能性問題になり、各チェックは 100 ノードのグラフ上の多項式になります。

 ## アルゴリズムのチュートリアル

 この問題を待機ラウンド数 r にわたる単調決定問題として扱います。 

1. 候補値 r を固定し、r 回の増援後の各非壁セルの部隊数を計算します。 各セルの種類によって寄与が異なるため、カテゴリと初期値に基づいて各セルを個別に更新します。 このステップでは、時間を利用可能な供給量に変換します。 
2. すべてのセルが他のすべてのセルに部隊を派遣できる有向グラフを構築します。 各順序ペア (u, v) について、最終ラウンドで転送できる軍隊の最大数を計算します。これは、u での増援調整値と許容ボーナス r + ManhattanDistance(u, v) に依存します。 
3. 各セルを少なくとも 1 つのユニットを受信する必要があると解釈します。 問題は、エッジ容量を超えずにすべてのノードが少なくとも 1 つのユニットを受信できるように受信転送を割り当てることができるかどうかになります。 
4. フロー スタイルの構造を使用して実現可能性を確認します。スーパー ソースを、利用可能な供給と等しい容量ですべてのセルに接続し、各セルをデマンド 1 でスーパー シンクに接続します。セル間には、計算された転送容量を持つエッジを許可します。 最大流量がすべての要求を満たしている場合は、r で十分です。 
5. 0 ～ 300 の r を二分探索します。実行可能性チェックに合格した最小の r が答えになります。 どれも合格しなかった場合は、-1 を出力します。 

### なぜ効果があるのか

 重要な不変条件は、r を増加してもノードの供給容量またはエッジ容量のいずれかのみが増加し、決して減少しないことです。 これにより、実現可能条件が単調になります。 したがって、特定の r で完全占有が許可されると、それより大きな r でも完全占有が許可されます。 この単調性により、二分探索が正当化され、最小の実現可能な r が明確に定義されることが保証されます。 

フローの定式化では、供給制限、ペアごとの転送制限、ノードごとの需要など、すべての制約を同時に取得します。 ゲーム内の有効な戦略は、構築されたネットワーク内の実行可能な割り当てに対応し、実行可能なフローは有効な再分配計画に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

class Dinic:
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(n)]

    def add_edge(self, u, v, c):
        self.adj[u].append([v, c, len(self.adj[v])])
        self.adj[v].append([u, 0, len(self.adj[u]) - 1])

    def bfs(self, s, t):
        self.level = [-1] * self.n
        q = deque([s])
        self.level[s] = 0
        while q:
            u = q.popleft()
            for v, c, _ in self.adj[u]:
                if c > 0 and self.level[v] == -1:
                    self.level[v] = self.level[u] + 1
                    q.append(v)
        return self.level[t] != -1

    def dfs(self, u, t, f):
        if u == t:
            return f
        for i in range(self.it[u], len(self.adj[u])):
            self.it[u] = i
            v, c, rev = self.adj[u][i]
            if c > 0 and self.level[v] == self.level[u] + 1:
                ret = self.dfs(v, t, min(f, c))
                if ret:
                    self.adj[u][i][1] -= ret
                    self.adj[v][rev][1] += ret
                    return ret
        return 0

    def maxflow(self, s, t):
        flow = 0
        INF = 10**18
        while self.bfs(s, t):
            self.it = [0] * self.n
            while True:
                f = self.dfs(s, t, INF)
                if not f:
                    break
                flow += f
        return flow

def solve():
    a = []
    for _ in range(10):
        a.append(list(map(int, input().split())))
    c = []
    for _ in range(10):
        c.append(list(map(int, input().split())))

    cells = []
    for i in range(10):
        for j in range(10):
            if a[i][j] != -1:
                cells.append((i, j))

    n = len(cells)

    def gain(cell_type, r):
        if cell_type == 1:
            return 2 * r
        if cell_type in (2, 3, 6, 7):
            return r
        return 0

    def ok(r):
        S = n + n
        T = S + 1
        dinic = Dinic(T + 1)

        total_need = 0

        for i, (x, y) in enumerate(cells):
            cap = a[x][y] + gain(c[x][y], r)
            if cap < 0:
                cap = 0

            dinic.add_edge(S, i, cap)

            dinic.add_edge(i, i + n, 1)
            total_need += 1

        for i in range(n):
            xi, yi = cells[i]
            for j in range(n):
                xj, yj = cells[j]
                if i == j:
                    continue
                dist = abs(xi - xj) + abs(yi - yj)
                dinic.add_edge(i, j + n, a[xi][yi] + r + dist)

        flow = dinic.maxflow(S, T)
        return flow == total_need

    lo, hi = 0, 300
    ans = -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、候補待ち時間ごとにフロー ネットワークを構築します。 各セルは「アウト」ノードと「イン」ノードに分割されるため、すべてのセルが少なくとも 1 つのユニットを受信する必要があります。 ソースは、増援後に利用可能な軍隊に等しい容量で各セルに接続します。 セル間の有向エッジは、距離と待機ボーナスを考慮して転送できる軍隊の数をエンコードします。 最大フロー チェックでは、すべてのセルが 1 つのユニットを受信できるかどうかを確認します。 

二分探索により、この高価なチェックを対数回のみ実行することが保証されます。

 ## 特殊なケース

 いくつかの孤立した非壁セルを除いて、すべてのセルが壁である場合、重大なエッジ ケースが発生します。 その状況では、フロー グラフには有効な受信または送信構造を持たないノードが含まれており、それらのノードにはユニットを割り当てることができないため、実行可能性チェックは正常に失敗します。 

もう 1 つのエッジ ケースは、単一セルの初期兵力が非常に少ないにもかかわらず、能力の高い隣接セルに囲まれている場合です。 グローバルな供給が十分である場合でも、距離が遠い場合はエッジごとの制限によって再配布がブロックされる可能性があります。 フロー構造はこれらの制限を明示的にエンコードし、過大評価を防ぎます。 

最後に、r が 300 に近づくと、容量は均一に増加し、ネットワークは自明に実現可能になります。 二分探索により、この範囲を超えてシミュレーションを行わないことが保証されます。
