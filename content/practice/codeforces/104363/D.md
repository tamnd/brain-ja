 ## 問題の理解

 私たちは、奏が一連のサービスを提供している間に、どれだけの有効な「配布計画」に従うことができるかを数えるよう求められます。$n$一列に並んだ部屋。 プロセスは常に左から右に厳密に移動し、部屋を再訪問することはありません。 

単一のプランは、部屋を連続したブロックに分割することによって定義されます。 各操作で、奏はブロック長を選択します$k_i$、ここでそれぞれ$k_i$少なくとも 1、最大でも$K$。 その後、彼は正確にサービスを提供します$k_i$最初の空いている部屋から始まる連続した部屋。 これは全員が終わるまで続く$n$部屋は覆われているため、選択されたブロック サイズは次の構成を形成します。$n$。 

選択したサイズのブロックごとに$k_i$、奏は取る$4k_i$箱から出た箱入りの食事$m$食事の種類、それぞれの量に制限はありません。 社内での食事の順序は関係ありません。 重要なのは、それらの中に各タイプが何個出現するかだけです$4k_i$食事。 

操作の数、ブロック サイズのいずれかが異なる場合、2 つのプランは異なるものとみなされます。$k_i$、または任意の操作で取得された食事の種類のマルチセット数。 

したがって、問題は、すべての有効なセグメンテーションを数えるということになります。$n$、および各セグメントサイズについて$k$、サイズのマルチセットの数を数えます$4k$以上$m$タイプが存在します。 

サイズのマルチセット$4k$以上$m$type は非負の整数を選択することと同じです$x_1 + x_2 + \dots + x_m = 4k$、これは標準的な星とバーの数です。$$f(k) = \binom{4k + m - 1}{m - 1}.$$したがって、すべての有効な計画は、セグメント長の合計のシーケンスに対応します。$n$、重みは次の積に等しい$f(k_i)$。 

制約$n, m \le 10^5$そして$K \le n$何かを意味する$O(nK)$動的プログラミングは、最悪の場合、遅すぎます。$10^{10}$トランジション。 平$O(n \log n)$移行は不均一なカーネルに依存するため、メソッドは慎重に構造化する必要があります$f(k)$、定数係数ではありません。 

微妙なエッジケースが現れるのは、$K \ge n$。 その場合、すべての構成は、$n$が許可されており、ループする単純な DP 実装$K$静かに二次時間に劣化します。 

もう一つのエッジケースは、$n=1$。 ここにはセグメントが 1 つだけあり、答えは単純です。$f(1)$。 少なくとも 2 つのセグメントを想定する実装や、DP を誤って初期化する実装は、この境界で失敗する可能性があります。 

## アプローチ

 直接的なアプローチは、動的プログラミング状態を定義することです。$dp[i]$最初の部分をカバーする有効な方法の数を表します$i$部屋。 位置から$i$、次のセグメントの長さをすべて試します。$k$そしてそれを追加する場合$i+k \le n$。 それが再発につながる$$dp[i] = \sum_{k=1}^{K} dp[i-k] \cdot f(k).$$これは正しいです。すべての計画は次で終了します。$i$以前のカットポイントから来ている必要があります$i-k$、最後のセグメントは、その長さだけに依存する係数に独立して寄与します。 

ただし、この定式化には次のことが必要です$O(nK)$各位置について、すべてのセグメントの長さにわたって反復処理を行うためです。 と$n, K \le 10^5$、これは実現可能な限界をはるかに超えています。 

重要な構造は、これが畳み込みのような反復であるということです。$dp[i]$固定カーネルに依存する$f(k)$以前のすべての dp 値に適用されます。 問題は、カーネルが位置全体で一定ではないことですが、それでもシフト不変であるため、多項式畳み込みを使用した分割統治の最適化が可能です。 

DP 範囲を半分に分割します。 左半分を解くとき、すべての値が既知であるため、固定重み配列による畳み込みを介して右半分を更新するために使用できます。$f$。 各マージ ステップは、dp のセグメントとカーネルの乗算に帰着します。これは、NTT ベースの多項式乗算を使用して効率的に実行できます。 

これにより、$O(n \log n)$各レベルが互いに素なセグメントに対して畳み込みを実行する分割統治 DP。

 ## アルゴリズムのチュートリアル

 1. 階乗および逆階乗を最大で事前計算します。$4n + m$二項係数を効率的に評価します。 これによりコンピューティングが可能になります$f(k) = \binom{4k + m - 1}{m - 1}$一定時間あたり$k$。 
2. アレイを構築する$f[1..K]$、各エントリには、ある長さのセグメントの寄与が格納されます。$k$。 これにより、問題は重み付けされた組成をカウントするタスクに変換されます。 
3. DP 配列を定義します。$dp[i]$正確にカバーする有効な方法の数です$i$部屋。 
4.セット$dp[0] = 1$なぜなら、部屋をゼロにする方法が 1 つあるからです。それは何もしないことです。 
5. DP 範囲を解く$[1, n]$分割統治戦略を使用します。 セグメントの場合$[l, r]$、再帰的に解決します$[l, mid]$まず、左側のすべての dp 値が右側に影響を与える前に判明するようにします。 
6. 左半分が計算されたら、畳み込みを使用してその寄与を右半分に伝播します。 左側のインデックスごとに$i$とステップサイズ$k$、更新します:$$dp[i+k] \mathrel{+}= dp[i] \cdot f(k)$$これはまさに dp セグメントとカーネルの間の畳み込みです。$f$、有効な範囲に制限されます。 
7. 左側の dp セグメントと反転カーネルの間の NTT 乗算を使用してこの畳み込みを効率的に実行し、寄与が右半分の正しい位置に配置されるようにインデックスを調整します。 
8. 全範囲になるまで、すべてのセグメントに対して再帰的に繰り返します。$[1, n]$処理されます。 

### なぜ効果があるのか

 DP は、すべての有効なプランを最後のセグメントとプレフィックス プランに独自に分解することを定義します。 これにより、各 dp 値が以前の値にのみ依存する、インデックスに対するツリー状の依存構造が生じます。 分割統治戦略は、左側の間隔からのすべての寄与が右側の間隔の更新に使用される前に完全に処理されるようにすることで、この依存関係を尊重します。 

遷移は線形でシフト不変であるため、すべての区間間の寄与は畳み込みとして表現でき、畳み込みは区間分解に関して結合します。 これにより、DP 範囲を分割しても有効な構成が失われたり二重にカウントされたりしないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def ntt(a, invert=False):
    n = len(a)
    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            a[i], a[j] = a[j], a[i]

    length = 2
    while length <= n:
        wlen = pow(3, (MOD - 1) // length, MOD)
        if invert:
            wlen = modinv(wlen)
        i = 0
        while i < n:
            w = 1
            for j in range(i, i + length // 2):
                u = a[j]
                v = a[j + length // 2] * w % MOD
                a[j] = (u + v) % MOD
                a[j + length // 2] = (u - v) % MOD
                w = w * wlen % MOD
            i += length
        length <<= 1

    if invert:
        inv_n = modinv(n)
        for i in range(n):
            a[i] = a[i] * inv_n % MOD

def convolution(a, b):
    n = 1
    while n < len(a) + len(b) - 1:
        n <<= 1
    fa = a[:] + [0] * (n - len(a))
    fb = b[:] + [0] * (n - len(b))
    ntt(fa, False)
    ntt(fb, False)
    for i in range(n):
        fa[i] = fa[i] * fb[i] % MOD
    ntt(fa, True)
    return fa

def solve():
    n, m, K = map(int, input().split())

    max_k = K
    fact = [1] * (4 * max_k + m + 5)
    invfact = [1] * (4 * max_k + m + 5)

    for i in range(1, len(fact)):
        fact[i] = fact[i - 1] * i % MOD

    invfact[-1] = modinv(fact[-1])
    for i in range(len(fact) - 2, -1, -1):
        invfact[i] = invfact[i + 1] * (i + 1) % MOD

    def C(n, r):
        if r < 0 or r > n:
            return 0
        return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

    f = [0] * (K + 1)
    for k in range(1, K + 1):
        f[k] = C(4 * k + m - 1, m - 1)

    dp = [0] * (n + 1)
    dp[0] = 1

    def cdq(l, r):
        if l == r:
            return
        mid = (l + r) // 2
        cdq(l, mid)

        left = dp[l:mid + 1]
        trans = convolution(left, f)

        for i in range(mid + 1, r + 1):
            j = i - l
            if j < len(trans):
                dp[i] = (dp[i] + trans[j]) % MOD

        cdq(mid + 1, r)

    cdq(0, n)
    print(dp[n])

if __name__ == "__main__":
    solve()
```コードはまず階乗テーブルを構築して、各セグメント サイズの組み合わせカウントを評価します。 機能$f(k)$食事を配布するためのすべての可能な方法を 1 つのステップでエンコードします。 

コア DP は、CDQ 分割統治手順によって処理されます。 各再帰呼び出しは、右半分を更新するために使用する前に、左半分を完全に計算します。 畳み込みステップは、すべてのペアを個別に繰り返すのではなく、左の状態から右の状態への可能なすべての遷移を一括して伝播します。 

FFT ベースの畳み込みは二次遷移ループを置き換え、制約の下でソリューションを実行可能にします。 

畳み込み結果内のインデックス付けには注意が必要です。 セグメント開始間のオフセット$l$DP インデックスは正確に保存されなければなりません。 そうしないと、寄与が誤ってシフトされ、たとえ畳み込み自体が正しい場合でも、答えが外れてしまいます。

 ## 特殊なケース

 いつ$n=1$、CDQ 再帰はただちに単一の状態に解決されます。 唯一可能なセグメントは、$k=1$したがって、結果は正確に次のようになります$f(1)$。 基本ケースであるため、アルゴリズムはこれを正しく処理します。$dp[0]=1$再帰の深さの曖昧さなしに、単一の畳み込みステップを通じて伝播します。 

いつ$K \ge n$、のすべてのパーティション$n$有効です。 コンボリューション カーネルは DP 範囲全体に広がりますが、CDQ は依然として問題を分割して、各セグメントが個別に処理されるようにします。 更新は左から右にのみ流れるため、過剰カウントは発生しません。 

いつ$m=1$、すべてのセグメントで食事を選択する方法は 1 つだけです。$4k$アイテムは同じタイプである必要があります。 これにより、問題はすべての重みが 1 に等しい純粋な重み付けされた合成に縮小されます。アルゴリズムは標準の合成カウントに集約され、DP 初期化と畳み込み構造によって正しく処理されます。
