 ## 解決策

 ## 問題の理解

 一定の順序で到着する一連の候補者が与えられます。 各候補者には初期の積極性レベルと、候補者を採用するためのコストがあります。 それらのいくつかを選択することはできますが、すでに受け入れた最大の積極性と結びついた制約があります。特定の積極性を持つ候補を受け入れると、以前に受け入れたすべての積極性よりも厳密に大きい積極性を持つ後続の候補は受け入れることができなくなります。 

候補者のサブセットを選択した後、ステージ上の参加者としてインデックスの昇順で処理されます。 各参加者は最初に、積極性のレベルに基づいて収益を貢献します。 そして、2 人の参加者が同じ攻撃性レベルを共有するたびに、彼らは戦います。一方が削除され、もう一方は攻撃性が 1 増加し、これが繰り返しカスケードする可能性があります。 参加者のレベルが上がるたびに、新しいレベルに基づいて追加の収益が得られます。 このプロセスは、残りの参加者全員が明確な積極性の値を持つまで続きます。 

目標は、この進化するシステムによって生み出される総収益から採用コストを差し引いた額が最大になるように、採用する候補者を選択することです。 

制約は厳しく、n と m は両方とも最大 2000 です。これにより、およそ O(n^2) または O(n^2 log n) よりも悪いものは即座に排除されます。 戦闘後の最終的な攻撃性は n + m まで増加する可能性があるため、サブセットごとにプロセス全体を単純にシミュレーションすることは不可能です。 どのようなソリューションでも、候補者間の対話とカスケード的な「レベル バンプ」を構造化された動的プログラムに圧縮する必要があります。 

攻撃的な値が複雑なパターンで繰り返される場合、微妙なエッジケースが発生します。 たとえば、すべての候補の初期レベルが同じ場合、単純に考えて 1 つだけが生き残ると仮定するかもしれませんが、実際にはマージを繰り返すとレベルが上に伝播し、追加の収益が複数回発生します。 

もう 1 つの落とし穴は、候補の選択がより高いインデックスを持つ他の候補から独立していると仮定することです。 「すでに受け入れられたものよりも厳密に高い」という制約により、プレフィックス最大構造が導入されます。つまり、低価値の候補を早期に受け入れると、その後の高価値の候補がブロックされる可能性があり、これは元に戻すことはできません。 この依存関係により、すべての DP は選択された最大レベルでプレフィックス制約を追跡するようになります。 

## アプローチ

 強引なアイデアは、候補者のすべてのサブセットを試し、ステージプロセスをシミュレートし、すべての戦闘カスケードで収益を計算し、コストを差し引くことです。 この問題は選択されたサブセットに対する決定論的な結果を定義するため、これは概念的には正しいです。 ただし、これには 2^n のサブセットを評価する必要があり、各評価には最大 O(n + m) レベルまでカスケードできるマージを繰り返して最大 n 人の参加者をシミュレートする必要があります。 最適化を行ったとしても、これは実現可能な限界をはるかに超えています。 

重要な構造的洞察は、参加者の順序は固定されており、相互作用は各攻撃性レベルを現在占有している参加者の数にのみ依存するということです。 2 人の参加者が同じレベルを共有すると、1 人が事実上上に「押し上げ」られ、カウント システムを持ち込むような連鎖反応が生じます。 これは、個人を追跡するのではなく、レベル全体の分布を追跡する必要があることを示唆しています。 

2 番目の洞察は、採用順序の制約は、これまでに選ばれた候補者の最大の積極性レベルのみを考慮していることを意味しているということです。 最大許容レベルが L であると決定すると、選択されたすべての候補の初期レベルは最大でも L でなければなりません。これにより、選択プロセスは、レベルの制限された範囲内でサブセットを選択することに変換されます。

次に、プロセスを再解釈します。レベルごとに、採用した候補者の数と、上位レベルへのキャリーを通じて候補者がローカルでどのように相互作用するかを集計します。 これにより、当然のことながら、各レベルの境界に何人の「アクティブな」参加者が存在するかを表す状態を維持する、候補に対するプレフィックス処理と組み合わせたレベルにわたる DP が得られます。 

最終的な構造は、レベルごとの DP となり、各レベルで何人の候補者を採用するかを決定し、コストと直接的な収益貢献を考慮しながら、持ち越された超過参加者を通じてその効果を上方に伝播します。

 ## アルゴリズムのチュートリアル

 候補者は、初期の積極性レベルによってグループ化されて処理されます。 cnt[v] をレベル v の候補とそのコストのリストとする。 

当社は、現在マージにより上位レベルに移行している「アクティブな参加者」の数を州が説明するレベル全体の DP を維持しています。 

1. dp[v][k] が v までのすべてのレベルを考慮し、レベル v の k 人のアクティブな参加者を上方に運ぶ最大利益を表す DP テーブルを初期化します。 この k は、マージを通じて上位レベルに貢献する可能性がある未解決の参加者が何人残っているかを表します。 
2. 各レベル v について、まずレベル v で候補のサブセットを選択することによる正味の寄与を計算します。選択された各候補はすぐに c[v] に寄与しますが、コストも s[i] だけ増加します。 これにより、選択された要素のベースライン寄与合計が得られます。 
3. レベル v から選択する候補の数を繰り返します。コストで並べ替えることで、最も有益なものを最初に取得することができます。これは、固定レベル内では、マージが上方に伝播する前に相互作用が対称的であるためです。 
4. レベル v の t 個の候補の選択ごとに、内部衝突を解決した後にそれらが生成する効果的な「追加の活性化」の数を計算します。 t 人の参加者が同じレベルに入ると、t-1 個のマージが発生し、floor((t +Previous_carry) / 2) がレベル v+1 にキャリーされますが、残りはレベル v に留まります。 
5. レベル v から計算された収益とキャリー マージからの寄与を加算することにより、dp[v][k] を dp[v+1][k’] に変換します。 この移行では、参加者ごとの直接収益 c[v] と、マージ中の各増分による追加収益の両方が考慮されます。 
6. キャリーによって攻撃性が初期限界を超えて押し上げられる可能性があるため、n + m までのすべてのレベルに対してこれを繰り返します。 
7. 答えは、すべての可能なキャリー完了を考慮した、最終レベルでの最大 dp 値です。 

### なぜ効果があるのか

 重要な不変条件は、すべてのレベル v で、DP 状態が上位レベルに影響を与えるために必要な唯一の情報、つまり将来のマージを生成する未解決の参加者の数を完全に取得することです。 参加者の個人情報はもはや重要ではなく、各レベルでの参加者の数だけが重要になります。 マージは決定的であり、レベルの同等性にのみ依存するため、このカウントベースの表現で十分であり、損失がありません。 すべての遷移では実際のプロセスと DP 抽象化の間の等価性が維持されるため、利益貢献が二重にカウントされたり見逃されたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    l = list(map(int, input().split()))
    s = list(map(int, input().split()))
    c = list(map(int, input().split()))

    maxv = n + m

    groups = [[] for _ in range(maxv + 1)]
    for i in range(n):
        groups[l[i]].append(s[i])

    for v in range(maxv + 1):
        groups[v].sort()

    dp = [float('-inf')] * (maxv + 2)
    dp[0] = 0

    for v in range(maxv + 1):
        ndp = [float('-inf')] * (maxv + 2)
        for carry in range(maxv + 1):
            if dp[carry] < 0:
                continue

            cur = 0
            cost_sum = 0
            t = 0

            for cost in groups[v]:
                t += 1
                cost_sum += cost

                gain = t * c[v] - cost_sum

                total = carry + t
                next_carry = total // 2
                rem = total % 2

                val = dp[carry] + gain

                if val > ndp[next_carry]:
                    ndp[next_carry] = val

        dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```DP は積極性レベルを反復して、マージ後に残っている未解決の参加者の数を繰り越します。 各レベル内では、参加者ごとの収益貢献がレベル内で均一である一方、コストが唯一の差別化要因であるため、プレフィックスを取得することで固定サイズの最適なサブセットが得られるように、候補がコストによって並べ替えられます。 

プレフィックス サイズ t ごとに、ネット ゲインを t · c[v] から総コストを引いたものとして計算し、マージが t に受信キャリーを加えて次のレベルの新しいキャリーにどのように圧縮するかをシミュレートします。 遷移により、それに応じて DP が更新されます。 

共通の微妙な点は、各レベル内のプレフィックス選択のみを考慮するようにすることです。 寄与はカウントのみに依存するため、プレフィックス以外のサブセットは、高コストの候補を低コストの候補に置き換えることによって支配されます。

 ## 特殊なケース

 エッジケースの 1 つは、すべての候補者が同じ積極性レベルを共有する場合です。 その状況では、追加の候補ごとに、独立した寄与ではなく一連のマージが発生します。 DP は各プレフィックス サイズをキャリーの増加として正しく処理するため、すべての候補を選択すると、線形ゲインではなく上向き伝播が繰り返されます。 

もう 1 つのエッジ ケースは、コストが c[v] に比べて非常に大きい場合です。 最適な解決策には、候補をまったく選択しないことが含まれる場合があります。 すべての遷移で負のゲインが得られる場合は dp[0] = 0 が最適なオプションのままであるため、DP はこれを自然に処理します。したがって、空のセットは計算全体を通じて有効なままになります。
