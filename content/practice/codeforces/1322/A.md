 ## 解決策
 ## 問題の理解

 括弧のみで構成される文字列が与えられ、連続するセグメントを選択し、その文字を任意に並べ替える操作を使用して文字列を変更できます。 このような操作のコストは、選択したセグメントの長さに等しくなります。 目標は、最小の総コストで最初の文字列を正しい括弧シーケンスに変換するか、それが不可能であると判断することです。 

ここでの正しいシーケンスとは、通常の意味を持ちます。つまり、すべての接頭辞の閉じ括弧の数が開き括弧の数より多くなることはなく、開き括弧と閉じ括弧の合計数が等しい、有効な式のように動作します。 

重要な点は、文字を自由に変更することはできず、選択したセグメント内でのみ並べ替えることができ、コストは選択したセグメントの大きさによって異なるということです。 このため、根本的に問題となるのは、左括弧を必要な位置にいかに安価に「移動」できるかということです。 

までの制約$10^6$文字を使用すると、すべての部分文字列を試行したり、操作を明示的にシミュレートしたりするソリューションは直ちに除外されます。 有効なアプローチはすべて線形または線形に近いものでなければなりません。$O(n \log n)$定数によってはきついかもしれません。 

1 つ目の微妙なエッジ ケースは、文字列にプレフィックスの意味での閉じ括​​弧が多すぎて、グローバルに補正できない場合です。 たとえば、文字列が ")))((" で始まる場合、最初のプレフィックスはすでに無効であり、並べ替えが許可されていても、全体としてはまだ十分な左括弧が必要です。合計 '(' カウントが ')' 未満の場合、正しいシーケンスを形成することは不可能であるため、答えは -1 でなければなりません。

 もう 1 つの注意が必要な状況は、文字列全体では既にバランスが取れているものの、「))((」など、順序が大きく間違っている場合です。素朴な直感で局所的な修正を示唆するかもしれませんが、コスト モデルでは、長いセグメントにわたって有用な '(' を移動するのはコストがかかるため、括弧の位置が重要になります。

 ## アプローチ

 ブルートフォース戦略では、セグメントを繰り返し選択し、考えられるすべての並べ替えをシミュレートして、文字列を有効な構成に近づけようとします。 「有用な」並べ替えに限定したとしても、考えられるセグメントの選択肢の数は次のとおりです。$O(n^2)$、各操作で文字列の一部のスキャンまたは再構築が必要になる場合があり、実行可能な制限をはるかに超えています。 

重要な観察は、セグメント内の内部順序は実際にはまったく考慮しておらず、括弧を再配置する機能のみを考慮しているということです。 各操作は事実上、文字列の後半から一部の '(' を取り出して前に持ってきて、プレフィックスのバランスがマイナスになる点を修正する方法です。

 これは、現在のバランスを維持しながら文字列を左から右にスキャンすることを示唆しています。 閉じ括弧が開始括弧を超える不均衡に遭遇した場合は常に、将来から開始括弧を「インポート」する必要があります。 セグメントを取得するコストはその長さに比例するため、最も安価な有効なインポートは常に右側にある利用可能な '(' です。

 したがって、任意の順列の観点から考える代わりに、最も近い利用可能な '(' を使用して負のプレフィックス バランスを繰り返し修復することに問題を縮小します。

 | アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース並べ替え | 指数 | O(n) | 遅すぎる |
 | 貪欲に最も近い '(' を修正 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての左括弧の位置を維持し、文字列を左から右にスキャンして、通常の有効性チェックと同様に現在の残高を追跡します。 

1. '(' のすべてのインデックスを事前計算してリストに保存します。これにより、次に使用可能な開始括弧に順番に常にアクセスできるようになります。
 2. 以前の問題を修正するためにすでに消費した '(' の数を表す、このリストへのポインタを初期化します。
 3. バランス変数をゼロに初期化します。 これは、シミュレートされた修正後に現在のプレフィックス内で「(」よりも「(」)が何個多く見つかったかを追跡します。
 4. 文字列の各位置 i を左から右に繰り返します。 

文字が「(」の場合は残高が1増加し、「)」の場合は残高が1減少します。 

残高がマイナスになると、現在のプレフィックスは無効になります。 現時点では、次の未使用の '(' を将来から取得して状況を修正する必要があります。

 '(' が位置 j にあるとします。そのような位置が存在しない場合、余分な閉じ括弧を補正できないため、変換は不可能です。

 次に、セグメント [i, j] に概念的な操作を適用し、その '(' を位置 i に移動します。追加されるコストは (j - i + 1) です。

 この修正後は、現在の位置 i が '(' になったかのようにエフェクトを扱うため、残高は負のままではなく 1 になり、使用されている '(' の上にポインタを進めます。
 5. 文字列の終わりまでスキャンを続けます。 
6. 累計コストの合計が答えです。 

重要な不変条件は、いつでもすべてのプレフィックス不足が、可能な限り最も早い利用可能な開始括弧を使用して解決されるということです。 これにより、修正を延期しても必要な '(' が遠ざかり、コストが増加するだけなので、今後のステップが必要以上に高価になることはありません。

 不足が発生するたびに、有効な最終シーケンスではその位置またはそれより前の位置に '(' を割り当てる必要があり、そのような '(' に最も近いものを選択することで、その割り当てのコスト寄与が最小限に抑えられるため、アルゴリズムは最適な解を見つけることができません。

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    opens = [i for i, c in enumerate(s) if c == '(']
    total_opens = len(opens)
    if total_opens * 2 != n:
        print(-1)
        return

    ptr = 0
    bal = 0
    ans = 0

    opens = opens  # list of positions

    for i, c in enumerate(s):
        if c == '(':
            bal += 1
        else:
            bal -= 1

        if bal < 0:
            if ptr >= total_opens:
                print(-1)
                return
            j = opens[ptr]
            ptr += 1

            ans += (j - i + 1)
            bal = 1  # we effectively placed '(' at position i

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、最初に、開き括弧と閉じ括弧の合計数が一致するかどうかをチェックして、実現可能性を確認します。 この条件がなければ、再配置によって正しいシーケンスを生成することはできません。 

メイン ループは、標準の有効性チェックをシミュレートすると同時に、無効になったプレフィックスを修復します。 左括弧の上にポインタを置くと、各 '(' が修復ソースとして最大 1 回使用されることが保証されます。

 微妙な点は修理後にバランスが1にリセットされること。 これは、現在位置が左括弧内に事実上修正され、接頭辞が負ではなくなったことを反映しています。

 ## 特殊なケース

 最初の文字で負になるプレフィックスは、最初に使用可能な開始括弧を直ちに使用することによって処理されます。 このアルゴリズムではバッファを想定していないため、「)」で始まる文字列であっても、後に「(」が存在すれば正しく修復されます。

 すべての開始括弧が最後に集中している場合、初期の終了括弧ごとに修復がトリガーされます。 ポインターは、各開始括弧が順番に使用されることを保証します。また、大きなギャップを越えてキャラクターを移動する必要性を反映して、徐々に短いジャンプが不可能になるため、コストが累積します。 

開始括弧の数が不十分な場合は、シミュレーションが開始される前に最初の実行可能性チェックによってこれが検出され、誤った部分処理が回避されます。
