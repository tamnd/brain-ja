 ## 解決策

 ## 問題の理解

 整数の配列が与えられ、順序のない個別の要素のペアをすべて考慮します。 各ペアについて、それらの合計を計算します。 これらのペアごとの合計をすべて収集した後、それらを合計したり最小化したりする代わりに、ビットごとの XOR を使用して結合します。 タスクは、この最終的な XOR 値を効率的に計算することです。 

直接の解釈は簡単です。フォームのすべての値を生成します。$a_i + a_j$のために$i < j$、次にそれらを XOR します。 難しさは、そのようなペアの数に起因します。 要素が最大 400,000 個になると、ペアの数はおよそ 8 × 10^10 に達し、明示的な列挙で処理できる範囲をはるかに超えます。 これにより、ペアの反復処理やすべての合計の保存に依存するソリューションは即座に排除されます。 

主な課題は、加算と XOR の両方がビット レベルで、しかし異なる方法で相互作用することです。 加算ではビット間でキャリーが発生しますが、XOR はビットごとに独立して動作します。 この不一致により、素朴な推論が失敗する傾向があります。 

単純なアプローチを破る典型的なエッジケースは、多くの数値が同一である場合、またはキャリーが加算構造を支配する場合です。 たとえば、すべての要素が 2 の場合、すべてのペアの合計は 4 になり、XOR はペアの数が奇数か偶数かによってのみ決まります。 ブルートフォースアプローチでも概念的にはこれを処理できますが、キャリーを処理せずに要素ごとの集計によって合計を誤って圧縮しようとすると失敗します。これは、キャリーが個々の値ではなくペアの構造に依存するためです。 

もう 1 つの微妙なケースは、ペアの構造が最小限である小さな配列です。 たとえば、`[1, 2, 3]`、合計は`3, 4, 5`、XOR の動作は、これらの結果のバイナリの重複に依存します。 各要素の寄与を個別に XOR しようとするアプローチは、ペアごとの相互作用が分離できないため、失敗します。 

## アプローチ

 ブルートフォース手法では、すべてのペアを反復処理し、それらの合計を計算し、XOR を計算します。 これは正しいですが、すぐには実行できません。 n = 400,000 の場合、演算数は n² / 2 のオーダーになり、これは約 8 × 10^10 の加算と XOR となり、時間制限をはるかに超えます。 

これを改善するために、最終的な答えのビット単位の構造に焦点を当てます。 重要な観察は、XOR がビットごとに独立しているということです。つまり、最終的な答えの各ビットは、そのビットが設定されているペアの合計の数にのみ依存します。 

したがって、合計を直接計算する代わりに、固定ビット k について、k 番目のビットが 1 である合計を生成するペア (i, j) がいくつあるかを尋ねます。 そのカウントが奇数の場合、答えの k 番目のビットは 1 になります。 それ以外の場合は 0 です。 

ここで、問題は、ビットごとに、そのビットを設定するキャリー構造を生成するペアの数が奇数であるか偶数であるかを判断することに移ります。 直接のビットごとのペアのカウントはまだ 2 次のように見えますが、ビットの寄与を分離し、下位ビットに対するプレフィックス頻度のカウントを使用することにより、ペアの合計の再計算を回避できます。 

ビットを下位から上位に処理します。 各ビット k については、2^(k+1) を法とする値のみを考慮します。上位ビットは加算後にビット k が設定されるかどうかに影響を与えないからです。 これにより、数値を下位ビットごとに分類し、並べ替えと 2 ポインター形式のカウントまたは頻度マップを使用して有効なペアをカウントできるようになります。 

主な構造上のトリックは、固定 k の場合、(a[i] + a[j]) にビット k が設定されているという条件は (a[i] mod 2^(k+1)) と (a[j] mod 2^(k+1)) にのみ依存することです。 これにより、循環間隔でペアをカウントするという問題が軽減され、ビットあたり O(n log n) で実行するか、ソートと 2 ポインター スイープを使用してさらに最適化することができます。 

ビット数には制限がある (a[i] ≤ 10^7) ため、考慮する必要があるのは最大約 24 ビットだけであり、全体の複雑さは管理可能になります。

 ## アルゴリズムのチュートリアル

 1. 0 から 24 までの各ビット位置 k を反復します。各反復で、このビットが最終的な応答に設定されるかどうかが決定されます。 

ビットを分離する理由は、XOR がビットごとにきれいに分解されるためです。 
2. 固定 k の場合、すべての配列要素を 2^(k+1) を法とする値に削減します。 これにより、合計の k 番目のビットが 1 になるかどうかに影響を与える情報が正確に保持されます。 
3. この縮小された配列をソートします。 並べ替えにより、ネストされたループの代わりに 2 つのポインターを使用して、値ごとに有効なパートナー要素をカウントできます。 
4. k 番目のビットが 1 である合計を生成するペアの数を数えます。この条件は、[0, 2^(k+1)) 内の特定の範囲に入る合計に対応します。これは、合計がそのビットが切り替わる範囲にある場合にビット k が 1 になるためです。 
5. ソートされた縮小値を 2 つのポインターでスイープし、必要な間隔構造に該当する補数の数をカウントすることにより、そのようなペアの数を効率的に計算します。 
6. 有効なペアの合計数が奇数の場合、答えにビット k を設定します。 それ以外の場合は、未設定のままにしておきます。 

### なぜ効果があるのか

 各ビット k について、加算は下位ビットからのキャリーにのみ依存するため、上位ビットの寄与は加算後にビット k が設定されるかどうかには影響しません。 モジュロ 2^(k+1) を実行することにより、ビット k に関連するすべてのキャリー相互作用を完全にキャプチャします。 すべてのペアの XOR は寄与のパリティのみに依存するため、ビット k を設定するペアの合計の数を正確に数えると、答えのそのビットが完全に決定されます。 ビット間の独立性により、結果を結合する際の正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    MAXB = 25
    ans = 0
    
    for b in range(MAXB):
        mod = 1 << (b + 1)
        half = 1 << b
        
        vals = [x % mod for x in a]
        vals.sort()
        
        cnt = 0
        
        j1 = j2 = n
        
        for i in range(n):
            while j1 > i and vals[i] + vals[j1 - 1] >= half:
                j1 -= 1
            while j2 > i and vals[i] + vals[j2 - 1] >= mod:
                j2 -= 1
            
            cnt += (j2 - j1)
        
        if cnt % 2 == 1:
            ans |= (1 << b)
    
    print(ans)

if __name__ == "__main__":
    solve()
```コア実装は、関連する下位ビットのみが残るように、2 のべき乗を法として数値を繰り返し削減します。 ビットごとに、ペアの合計をビットが 1 になる範囲に分類します。2 ポインター構造によりこれらの範囲の境界が効率的に維持され、ソート後に有効なペアをビットごとに線形時間でカウントできるようになります。 

ポインタ更新の順序には注意が必要です。両方のポインタは i 全体で単調であるため、全体の複雑さがビットごとに線形に保たれます。

 ## 特殊なケース

 すべての値が同一である配列の場合、すべてのペアの合計は同一であるため、答えはペアの数が奇数かどうかによってのみ決まります。 たとえば、`[5, 5, 5, 5]`、ペアが 6 つあり、すべて合計すると 10 になるため、XOR は 0 になります。各ビットで寄与するペアの数が偶数であるため、アルゴリズムはこれを正しく処理します。 

n = 2 の小さな配列の場合、アルゴリズムは単一の合計を計算することになり、各ビットはその合計から直接決定されます。 モジュロベースのカウントでも、有効なペアが 1 つだけ生成され、正確さが保証されます。 

10^7 に近い最大値の場合、24 を超える上位ビットは全体を通してゼロのままであるため、ビット ループを制限しても寄与を見逃すことはありません。
