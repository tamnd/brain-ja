 ## 解決策
 ## 問題の理解

 3 つの非負の整数が与えられます`b`、`c`、 そして`d`。 負でない整数を構築する必要があります`a`そのような$$(a \mid b) - (a \& c) = d$$どこ`|`ビット単位の OR であり、`&`ビット単位の AND です。 

タスクは、ある値を最適化することではありません。`a`。 任意の有効な`a`許容されます。 そのような値が存在しない場合は、次のように出力します。`-1`。 

最初の観察は、数値の大きさから得られます。 各値は次のように大きくできます。$10^{18}$これは、最大約 60 バイナリ ビットが関連することを意味します。 いくつでもありえます$10^5$したがって、テスト ケースごとに数千回の操作を費やすソリューションでも問題ありませんが、数値自体の大きさによっては不可能です。 

可能な値に対する総当たり検索`a`はすぐに除外されます。 許容範囲は次のとおりです$2^{61}$、大まかに言うと$2.3 \times 10^{18}$。 

難しいのは引き算です。 ビットごとの問題の多くは独立してビットごとに解決できますが、減算では通常、隣接するビット間で借用が発生します。 借用を考慮せずにすべてのビットを独立して処理する不用意な解決策は、一般に間違っています。 

重要なエッジケースは、矛盾を強制するビットの組み合わせから生じます。 

考慮する：```
b = 0, c = 0, d = 1
```すると方程式は次のようになります$$a - 0 = 1$$だから答えは`a = 1`。 

ビットを正しく再構築しないソリューション`a`この些細なケースを見逃してしまうだろう。 

もう 1 つの重要なケースは次のとおりです。```
b = 1, c = 0, d = 0
```ビット0の場合、`(a|1)`いつもです`1`、 その間`(a&0)`いつもです`0`。 左側は常に少なくとも`1`、したがって解決策は存在しません。 正しい出力は次のとおりです`-1`。 

バグの 3 番目の原因は、減算によって借入が発生する可能性があることを忘れていることです。 

例えば：```
b = 0, c = 1, d = 1
```私たちが選ぶなら`a = 1`、その後

 (1|0) - (1&1) = 1 - 1 = 0

 そうではない`1`。 

ビット間の関係は、現在位置に入るボローに依存するため、それを明示的に追跡する必要があります。 

## アプローチ

 最も直接的なアイデアはブルートフォースです。 考えられるすべての値を試してください`a`、 評価する$$(a|b)-(a\&c)$$それが等しいかどうかを確認してください`d`。 

すべての候補者を検査するので、これは明らかに正しいです。 問題は検索スペースです。`a`と同じくらい大きいかもしれない$2^{61}$、したがって、最悪の場合は以上が必要になります$2 \times 10^{18}$評価。 1 秒あたり 10 億回の演算を行ったとしても、それには数十年かかります。 

式の構造は、ビット単位のアプローチを示唆しています。 OR と AND はどちらも各ビットで独立して動作します。 異なるビット位置を結合する唯一の演算は減算です。 

させて$$X = a|b$$そして$$Y = a\&c$$方程式は次のようになります$$X - Y = d.$$2 進減算を実行する場合、あるビットから次のビットに流れる情報は借用だけです。 つまり、受信した借用という単一の状態を維持しながら、最下位ビットから最上位ビットまで処理できるということです。 

各ビット位置について、次のことがわかります。 

- 少し`b`- 少し`c`- 少し`d`- 現在の借入

 未知のものはちょっとしたものです`a`。 

両方の可能性を試してみます (`0`または`1`）で十分です。 それぞれの選択肢について、対応するビットを計算できます。`X`そして`Y`、バイナリ減算の 1 ステップを実行し、生成されたビットがターゲット ビットと一致するかどうかを確認します。`d`。 

これにより、問題は 2 つの借用状態のみを持つ小さな動的プロセスに変わります。`0`そして`1`。 最大 61 ビットを処理するため、テスト ケースごとの作業量は一定です。

 | 最適 |$O(61)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`a = 0`そして`borrow = 0`。 
2. からのビット位置を処理します。`0`を通して`60`。 
3. 現在のビットを抽出します。$$b_i,\ c_i,\ d_i$$から`b`、`c`、 そして`d`。 
4. 現在のビットの可能な値を両方試してください。`a`、つまり`0`そして`1`。 
5. 候補ビットの場合`a_i`、次を計算します。$$x_i = a_i \mid b_i$$そして$$y_i = a_i \& c_i$$6. 2 進減算の 1 ステップをシミュレートします。$$x_i - y_i - borrow$$値が負でない場合、結果のビットはその値となり、次の借用は次のようになります。`0`。 

それ以外の場合は追加します`2`値を設定し、次の借入を次のように設定します。`1`。 
7. 結果のビットが次と等しいかどうかを確認します。`d_i`。 

一致する場合、この選択は`a_i`方程式と一致しています。 ビットを応答に保存し、借用を更新して、次の位置に進みます。 
8. どちらでもない場合`a_i = 0`または`a_i = 1`必要なビットが生成されますが、解決策は存在しません。 出力`-1`。 
9. すべてのビットが処理された後、最終的な借入がゼロであることを確認します。 借用が残っている場合は、減算結果が等しくないことを意味します。`d`。 
10. 構築された値を出力します。`a`。 

### なぜ効果があるのか

 すべてのビット位置で、2 進減算は 3 つの値 (被減数の現在のビット、減数の現在のビット、およびその位置に入るボロー) のみに依存します。 

このアルゴリズムは、未知のビットの可能性を 2 つだけ明示的に列挙します。`a_i`。 選択によって必要な部分が再現されるたびに、`d`、上位ビットに必要なすべての情報が発信ボローによって要約されるため、有効なグローバル解の可能性が維持されます。 

借用は、減算プロセスの完全な状態として機能します。 処理されたすべてのビットは対応するビットと一致するため、`d`、最後の借入がゼロである場合、再構成された数は次の条件を満たします。$$(a|b)-(a\&c)=d.$$ある立場にある場合、選択の余地はありません`a_i`必要なビットを生成できても、有効な継続が存在しないため、レポートが行われます。`-1`は正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        b, c, d = map(int, input().split())

        a = 0
        borrow = 0
        ok = True

        for i in range(61):
            bi = (b >> i) & 1
            ci = (c >> i) & 1
            di = (d >> i) & 1

            found = False

            for ai in (0, 1):
                xi = ai | bi
                yi = ai & ci

                cur = xi - yi - borrow

                if cur >= 0:
                    bit = cur
                    nb = 0
                else:
                    bit = cur + 2
                    nb = 1

                if bit == di:
                    found = True
                    borrow = nb

                    if ai:
                        a |= (1 << i)

                    break

            if not found:
                ok = False
                break

        if borrow:
            ok = False

        ans.append(str(a if ok else -1))

    sys.stdout.write("\n".join(ans))

solve()
```解は減算プロセスに正確に従います。 

変数`borrow`現在のビットに入るボローを保存します。 すべてのビット位置について、考えられる両方の値をテストします。`a_i`。 

表現```
xi = ai | bi
yi = ai & ci
```の対応するビットを表します`(a|b)`そして`(a&c)`。 

減算ステップは、2 進数演算とまったく同じように実行されます。 ローカル値が負になった場合は、次のビットから借用して追加します。`2`現在の位置への借入を記録し、`1`。 

微妙な点は加工範囲です。 この問題は、有効な答えがその中にあることを保証します。`[0, 2^61]`なので、ビットをチェックしています`0..60`で十分です。 すべての入力は以下にあります`2^60`、より高いビットを必要とするボロー伝播は、最後のビットによって検出されます。`borrow`チェック。 

もう 1 つの微妙な点は、最初の有効な選択を直ちにコミットすることです。 すべての州について`(bit position, incoming borrow)`必要な継続は最大 1 つです。 借用は以前のすべての決定を完全に要約するため、追加のバックトラックは必要ありません。
