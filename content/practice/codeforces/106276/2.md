 ## 解決策
 ## 問題の理解

 この問題は、2 つの皿と正確に 3 つの既知の重さを持つ天秤を記述します。 重りには質量があります`a`、`b`、 そして`c`、 と`a < b < c`。 大量の梨`p`はすでに正常に測定されているため、3 つの重りを何らかの配置でバランスさせることができることがわかります。 

あなたの仕事は、そのような配置を 1 つ出力することです。 梨は左側の皿に置く必要があります。 重りの一部は左側に取り付けられ、一部は右側に取り付けられ、一部は使用されない場合があります。 両方のパンの合計質量が等しくなる必要があります。 

左側の梨と一緒に置かれた重りの合計質量がある場合`x`、右側の重みは総質量を持ちます。`y`、条件は次のとおりです。`p + x = y`入力値は次のように大きくできます。`10^9`したがって、数値が小さいことに依存するアプローチは適切ではありません。 ただし、重みの数は 3 つに固定されています。 これにより、問題は完全に変わります。可能な配置の数は少なく、入力サイズとともに増加しません。 時間計算量が一定のソリューションで十分です。 

主なエッジケースは、分銅を未使用のままにしておくことができ、秤のどちらの側に配置してもよいということを忘れていることから生じます。 

たとえば、次のようになります。```
1
3
10
9
```有効な答えの 1 つは、梨と重りを置くことです。`1`左側と体重`10`右側に。 平等というのは、`9 + 1 = 10`。 検索するだけのいいかげんな解決策`p`1 つの重みからもう 1 つの重みを引くと、これを見逃してしまいます。これは、より小さい重みが梨側にも必要なためです。 

別のケースは次のとおりです。```
2
5
8
1
```梨を左側に置き、重りを置くことで梨のサイズを測ることができます`2`そして`5`右側に。 平等というのは、`1 + 2 + 5 = 8`。 両側で 1 つの重みを使用することのみを考慮したソリューションは失敗します。 

オブジェクトの固定数が重要な観察です。 質量制限が大きいため、探索空間は大きくなりません。 

## アプローチ

 直接的な強引なアプローチは、あらゆるウェイトのあらゆる可能な配置を試すことです。 各ウェイトには、左パン、右パン、または未使用の 3 つの選択肢があります。 3 つの重みがある場合、`3^3 = 27`可能な取り決め。 配置ごとに、両側の合計質量を計算し、秤のバランスが取れているかどうかを確認できます。 

考えられるすべての法的配置が検索に含まれるため、この方法は正しいです。 重みの数が増加する場合にのみ、状態の数が増加するため、非現実的になります。`3^n`。 現在の問題の場合、最悪の場合のチェック数はわずか 27 です。 

重要な観察は、問題は膨大な数の中から賢い算術分解を見つけることではないということです。 値は大きいですが、選択肢の数は非常に少ないです。 選択肢の徹底的な検索は事実上一定時間です。 

可能な構成のセットが完全で小さいため、ブルート フォースが機能します。 同じアイデアは何百もの重みを使用する場合には機能しませんが、ちょうど 3 つの重みを使用する場合は、最も単純で安全な解決策になります。

 ## アルゴリズムのチュートリアル

 1. 3 つの重量と梨の質量を読み取ります。 アルゴリズムは重みを対称的に扱うため、重みを配列に保存します。 
2. 3 つの重みの割り当てをすべて列挙します。 重量ごとに、左パン、右パン、未使用の 3 つの状態から 1 つを選択します。 これは、スケール ルールで許可されるすべての可能な配置をカバーします。 
3. 現在の割り当てでは、梨を除いた左側の皿の質量と、右側の皿の質量を計算します。 バランス条件は、右側が洋ナシと左側を足したものに等しくなければならないということです。 
4. 代入が式を満たす場合、左側に割り当てられた重みとともに洋ナシを出力し、右側に割り当てられた重みを出力します。 この問題では、そのような割り当てが少なくとも 1 つ存在することが保証されているため、最初の有効な割り当てで十分です。 

なぜ機能するのか: あらゆるウェイトのあらゆる可能な配置が検査されます。 梨の元の計量で使用される有効な配置は、これらの 27 状態の 1 つであるため、列挙は、等号が成立する少なくとも 1 つの状態に到達する必要があります。 このような状態が見つかると、生成された配置は正しい計量の定義を直接満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = int(input())
    b = int(input())
    c = int(input())
    p = int(input())

    weights = [a, b, c]

    for mask in range(27):
        x = mask
        left = []
        right = []

        for w in weights:
            state = x % 3
            x //= 3

            if state == 0:
                left.append(w)
            elif state == 1:
                right.append(w)

        if p + sum(left) == sum(right):
            print(*([p] + left))
            print(*right)
            return

solve()
```コードでは次の番号が使用されます。`0`に`26`プレースメントのコンパクトな表現として。 3 進数のすべての数字は、1 つの重りの状態を表します。 の数字`0`重りが梨と一緒に置かれていることを意味します。`1`は反対側の皿に置かれることを意味し、`2`未使用という意味です。 

変換ループは繰り返しかかります`x % 3`現在の重みの選択を抽出し、3 で割って次の重みに移動します。 ちょうど 3 つの重みがあるため、考えられるすべての 3 項の組み合わせがカバーされます。 

条件`p + sum(left) == sum(right)`バランス方程式と直接一致します。 出力形式で要求されているため、プログラムはまず左側に洋ナシを印刷します。 このステートメントでは空のリストが許可されているため、パンに洋ナシのみまたは重りのみが含まれている場合には特別な処理は必要ありません。 

Python では整数の精度が任意であるため、オーバーフローの心配はありません。 列挙サイズが小さいため、入力速度も無関係になりますが、必要な`sys.stdin.readline`インターフェイスが使用されます。

 ## 特殊なケース

 この場合の場合:```
1
3
10
9
```列挙は重みが次の状態に達します`1`梨の側面と重みにあります`10`反対側にあります。 小切手は、`9 + 1 == 10`, したがって、アルゴリズムはその配置を出力します。 探すだけの方法`p = y - x`と`x = 0`左側には追加の重みが必要なため、失敗します。 

この場合の場合:```
2
5
8
1
```有効な配置では、1 つの大きな重みに対して 2 つの重みを一緒に配置する必要があります。 検索では最終的に重みが割り当てられます`2`そして`5`左側と体重`8`右側へ。 平等はこうなる`1 + 2 + 5 = 8`, したがって、結果は受け入れられます。 

次のような非常に大きな値の場合:```

```このアルゴリズムは、小さい数値の場合とまったく同じ 27 個のチェックを実行します。 算術値は検索サイズに影響を与えないため、解は一定時間のままになります。
