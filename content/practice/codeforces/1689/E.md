 ## 解決策
 ## 問題の理解

 負ではない整数の配列が与えられます。 配列の各要素はグラフの頂点に対応します。 2 つの頂点は、それらの値のビット単位の AND が正の場合、エッジによって接続されます。 

グラフの接続は保証されません。 個々の配列要素を繰り返し 1 つずつ増減することができますが、減分は正の値の場合にのみ許可されます。 増加または減少するたびに 1 回の操作が必要になります。 

私たちのタスクは、グラフを接続するために必要な演算の最小数を見つけて、その最小値を達成する結果の配列を 1 つ出力することです。 

最も重要な観察は、グラフ構造が共有セット ビットによって完全に決定されるということです。 2 つの数値は、1 に等しい共通ビットが少なくとも 1 つある場合、隣接しています。したがって、接続性は、数値そのものではなく、ビットが配列全体にどのように分散されるかという特性になります。 

制約は驚くほど小さいです。 すべての合計$n$入力全体で最大 2000 です。これは、$O(n^2)$あるいは$O(n^2 \log A)$解決策は完全に受け入れられます。 値が以下なので$2^{30}$、関連するビット位置は 30 個だけです。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
2
0 0
```値 0 に対応する頂点にはビットが設定されていないため、すべてから分離されています。 接続されたグラフにはゼロが含まれていてはなりません。 ゼロ以外の頂点間の接続のみをチェックするソリューションでは、誤って成功したと主張されてしまいます。 

もう 1 つの注意が必要なケースは次のとおりです。```
2
3 12
```次の理由により、グラフが切断されています。```
3  = 0011
12 = 1100
```それらの AND はゼロです。 1 つのデクリメントにより次の結果が得られます。```
3  = 0011
11 = 1011
```そして今度は AND が正になります。 最小の答えは 1 です。 

最後の微妙なケースは次のとおりです。```
4
8 8 1 1
```ゼロを削除しても、グラフは切断されたままになります。 いくつかの建設的なアイデアは、それを 2 つの操作で結び付けますが、必ずしも 1 つで行う必要はありません。 ソリューションでは、回答 1 と 2 を正しく区別する必要があります。 

## アプローチ

 強引なアプローチでは、考えられるすべての変更シーケンスを検索し、すべての変更の後に接続性をテストします。 

これは原理的には明らかに正しいですが、完全に実行不可能です。 要素ごとに数回の増分と減分に制限するだけでも、すでに指数関数的な検索スペースが作成されます。 

重要な進歩は、答えが常に非常に小さいということです。 

まず、すべてのゼロを変更する必要があります。 ゼロはビットを提供せず、エッジを何とも共有できません。 すべてのゼロを 1 に変えることは、ゼロごとにちょうど 1 回の操作が必要であり、有用な値を生成するため、常に最適です。 

すべての 0 が 1 になったら、結果のグラフを調べます。 

すでに接続されている場合は完了です。 

それ以外の点では、編集上の観察は注目に値します。ゼロを削除した後、残りの最小追加コストが 2 を超えることはありません。 まず、可能なすべての単一の増分とすべての単一の減分を試して、追加の操作が 1 つだけで十分であるかどうかをテストできます。 以来$n \le 2000$、この総当たりチェックは安価です。 

これらの試みがどれもうまくいかない場合、答えは正確に 2 つである必要があります。 

最後のステップは、これら 2 つの操作を達成するための建設的な方法です。 させて```
lowbit(x) = x & (-x)
```そして、lowbit が最大であるすべての要素を考慮します。 

そのような要素が 1 つだけある場合は、1 ずつ減分します。 

このような要素が複数ある場合は、そのうちの 1 つをデクリメントし、別の要素をインクリメントします。 

この特別な変更により、常にグラフが接続されます。 その証明は、接続テストで使用されるビットコンポーネント構造から得られます。

 ## アルゴリズムのチュートリアル

 ### 接続チェック

 頂点上のグラフは大きくなる可能性がありますが、ビット位置は 30 しかありません。 

頂点グラフを直接構築する代わりに、ビットに基づいてグラフを構築します。 

すべての数値について、その数値内に表示されるすべての設定ビットを接続します。 数値にビット 1、4、および 7 が含まれる場合、その数値によってビットがリンクされるため、これらのビットは同じコンポーネントに属します。 

すべての数値を処理した後、どこにでも現れるすべてのビット位置は単一の連結成分に属している必要があります。 そうしないと、元の頂点グラフを接続できません。 

### ステップ

 1. 配列内のすべてのゼロを数えます。 
2. すべてのゼロを 1 に置き換え、置き換えた数を答えに加算します。 
3. グラフが接続されているかどうかを確認します。 
4. 接続されている場合は、現在の配列を出力します。 
5. それ以外の場合は、すべてのインデックスを試します。 

各インデックスの値が正の場合は、一時的に値を 1 減らして接続をテストします。 

接続が確立されたら、この配列を出力します。 
6. 値を元に戻し、一時的に 1 ずつ増やします。 
7. 接続を再度テストします。 
8. 接続が確立されたら、この配列を出力します。 
9. 単一の変更が機能しない場合は、次の最大値を見つけます。`lowbit(a[i])`。 
10. その最大ロービットを持つすべてのインデックスを収集します。 
11. そのようなインデックスが 1 つだけ存在する場合は、その要素を 1 つ減らします。 
12. それ以外の場合は、これらの要素の 1 つを 1 つ減らし、別の要素を 1 つ増やします。 
13. 答えに 2 を加算し、結果の配列を出力します。 

### なぜ効果があるのか

 すべての 0 を 1 に置き換えることは必須です。 ゼロには設定ビットが含まれないため、常に分離されます。 接続された最終グラフはすべてのゼロを削除する必要があります。 

ゼロが削除された後、最初に 1 回の追加操作が必要なすべての可能性をテストします。 すべての合法的な 1 操作ソリューションは、1 つの要素に対する 1 つの増分または 1 つの減分のいずれかである必要があるため、徹底的なチェックで十分です。 

残りの主張は、1 操作の解決策が存在しない場合、2 操作の解決策が常に存在するというものです。 公式編集によるロービット構造がこれを保証します。 最大のロービットを持つ要素は、すべての数値の中で最高の「ビット レベル」に位置します。 それらの 1 つまたは 2 つを 1 つずつ調整すると、最も低い設定ビットが変更され、切断されたビット コンポーネントがマージされます。 したがって、残りのすべてのケースは、正確に 2 つの追加操作で解決できます。 

答え 0 と 1 はすでに除外されているため、可能な最小の答えは 2 でなければなりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def connected(a):
    parent = list(range(30))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        ra = find(a)
        rb = find(b)
        if ra != rb:
            parent[ra] = rb

    used = []

    for x in a:
        bits = []
        for b in range(30):
            if (x >> b) & 1:
                bits.append(b)

        if bits:
            used.extend(bits)
            root = bits[0]
            for b in bits[1:]:
                union(root, b)

    used = list(set(used))

    if not used:
        return False

    r = find(used[0])
    for b in used:
        if find(b) != r:
            return False

    return True

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ops = 0

        for i in range(n):
            if a[i] == 0:
                a[i] = 1
                ops += 1

        if connected(a):
            print(ops)
            print(*a)
            continue

        found = False

        for i in range(n):
            if a[i] > 0:
                a[i] -= 1
                if connected(a):
                    print(ops + 1)
                    print(*a)
                    found = True
                    break
                a[i] += 1

            a[i] += 1
            if connected(a):
                print(ops + 1)
                print(*a)
                found = True
                break
            a[i] -= 1

        if found:
            continue

        best = max(x & -x for x in a)

        idx = [i for i in range(n) if (a[i] & -a[i]) == best]

        if len(idx) == 1:
            a[idx[0]] -= 1
        else:
            a[idx[0]] -= 1
            a[idx[1]] += 1

        print(ops + 2)
        print(*a)

solve()
```実装は以下を中心に展開します。`connected()`関数。 

配列の位置にグラフを構築する代わりに、30 ビットの位置に DSU を構築します。 すべての数値は、その設定ビットのすべてを 1 つの DSU コンポーネントにマージします。 最後に、グラフを接続するには、使用されるすべてのビットが 1 つの DSU コンポーネントに属している必要があります。 これはまさに公式ソリューションで使用される基準です。 

ワンオペレーション検索では、一時的な変更を行うたびに値を慎重に復元する必要があります。 要素の復元を忘れることは、間違った答えの一般的な原因です。 

低ビット計算では以下を使用します。```
x & -x
```これにより、設定された最下位ビットが分離されます。 すべての要素の中で、最大の低ビットを持つ要素を見つけて、建設的な 2 つの操作による修正を適用します。

 ## 特殊なケース

 次のことを考慮してください。```
2
0 2
```ゼロに対応する頂点にはエッジがありません。 アルゴリズムはゼロを即座に 1 に変換します。 その後、接続をチェックします`[1,2]`。 まだ切断されている場合は、後のステージで処理されます。 重要なのは、接続されたソリューションはゼロを維持できないということです。 

考慮する：```
2
3 12
```ゼロ処理後は何も変わりません。 グラフが切断されました。 ワンオペレーション検索では、すべての増分と減分をテストします。 変化`3`に`4`得られるもの:```
4 & 12 = 4
```したがって、グラフは接続され、アルゴリズムは正しく答え 1 を返します。 

次のことを考慮してください。```
4
8 8 1 1
```ワンオペレーションの変更は成功しません。 アルゴリズムは構築段階に達します。 最大ロービットは 8 で、8 の両方のコピーによって達成されます。1 つは減少し、もう 1 つは増加し、正確に 2 回の追加操作で接続が保証された構成が生成されます。 ワンオペレーションの可能性はすべてすでに使い尽くされているため、この答えが最適です。
