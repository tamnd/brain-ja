 ## 解決策
 ## 問題の理解

 頂点 1 をルートとする 2 分木が与えられています。各頂点には、最大 2 つを持つルートを除き、最大 3 つの近傍があります。 最初は根のみが感染します。 各ターン、ミーシャは感染していない頂点を 1 つ削除し、その頂点とそのすべてのエッジを削除することができます。その後、感染は隣接するすべての頂点に広がります。 目標は、プロセスの完了後に感染せずに残り、削除されない頂点の最大数を決定することです。 

入力は複数のテスト ケースを提供し、それぞれがツリーを次のように記述します。`n`頂点と`n-1`エッジ。 出力は、保存できる頂点の数を表すテスト ケースごとの 1 つの整数です。 

制約は重要です。 と`n`すべてのテスト ケースで最大 3×10^5、最大 5000 のテスト ケースでは、考えられるすべての欠失シーケンスを探索するアルゴリズムを用意する余裕はありません。 感染ステータスを更新し、ターンごとに削除する頂点を選択する単純なシミュレーションでは、テスト ケースごとに O(n^2) の操作が必要となり、タイムアウトになる可能性があります。 各ツリーをそのサイズに対して線形時間で処理するソリューションが必要です。 

エッジ ケースは、ツリーが小さいか、または大きく歪んでいる場合に発生します。 たとえば、2 つの頂点を持つツリーには、1 つを削除する以外に頂点を保存する余地がなく、保存される頂点は 0 になります。 ルートに 1 つの子があるノードのチェーンでは、保存された頂点を数えるために直接の子だけでなく、より深いサブツリーを考慮する必要があることがわかります。 

## アプローチ

 ブルートフォース手法では、毎日シミュレーションを行います。感染していない頂点ごとに、削除を試み、感染を伝播させ、将来のすべての動きを再帰的に評価します。 正しいのですが、これは組み合わせ的に爆発します。 n=20 の場合でも、欠失配列の数は天文学的な数になります。 

重要な点は、削除によって、ルートまたはより深いノードの子をルートとするサブツリー内の頂点のみが保存されるということです。 ノードに複数の子があると、すべての子を同時に削除することはできないため、一部のサブツリーを感染させることになります。 問題は、戦略的なポイントで 1 つの子を削除した場合、感染が時間内に到達してノードを破壊できないサブツリー内のノードを数えることに帰着することに気づきました。 これにより、当然のことながら、感染がそのノードに到達した場合に保存できる頂点の数をノードごとに計算する、深さ優先検索アプローチが得られます。 

具体的には、葉を保存する最小単位として扱う場合、サブツリー内で保存される頂点の最大数は、その子の最大保存値の合計から最大値を引いた値になります。 これは、感染がターンごとに 1 つのエッジに沿って広がるためであり、感染がより小さなサブツリーに広がるのを防ぐ方法で頂点を削除できますが、一度にすべてを削除することはできません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適な DFS + DP | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 隣接リストを使用してツリーを構築します。 ノードの再訪問を避けるために、DFS を実行するときに親を除く、各ノードがその近隣ノードを認識していることを確認します。 
2. 再帰関数を定義する`dfs(node, parent)`をルートとするサブツリーに保存できる頂点の最大数を返します。`node`感染が到達した場合`node`。 
3. ノードがリーフ (次数 1、ルートを除く) の場合は、感染がすぐにノードに到達し、保存する子が存在しないため、0 を返します。 
4. それ以外の場合は、現在のノードのすべての子 (親を除く) を反復処理します。 子ごとに再帰的に計算します`dfs(child, node)`。 
5. ノードに複数の子がある場合、すべての子の保存された値の合計からそれらの最大値を引いた値を保存できます。 これは、感染が常に最初に少なくとも 1 人の子供に到達し、他のサブツリーを保護できるのは戦略的な削除によってのみであることをモデル化しています。 子が 1 つだけの場合は、DFS がその子に対して返したものをすべて保存します。 
6. 現在のノードのこの計算値を返します。 
7. 電話をかける`dfs(1, 0)`根元に。 結果は、ツリーに保存できる頂点の最大数になります。 

機能する理由: DFS トラバーサルにより、各ノードが 1 回ずつアクセスされることが保証され、再発により、分岐ノードでは感染によって少なくとも 1 つのサブツリーが完全に消費される必要があるという重要な洞察が得られます。したがって、最良の戦略は小さいサブツリーを保存することです。 この不変式はすべてのノードに対して再帰的に当てはまります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        tree = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            tree[u].append(v)
            tree[v].append(u)
        
        def dfs(u, parent):
            children = [v for v in tree[u] if v != parent]
            if not children:
                return 0
            saved = [dfs(v, u) for v in children]
            if len(saved) == 1:
                return saved[0]
            return sum(saved) - max(saved)
        
        print(dfs(1, 0))

if __name__ == "__main__":
    solve()
```隣接リストの構築により、隣接リストを効率的に横断できるようになります。 の`dfs`関数は、循環を防ぐために親を慎重に除外します。これは、ツリーが無向であるため、非常に重要です。 再帰を使用するため、深いツリーのスタック オーバーフローを避けるために再帰制限を増やします。 保存されたサブツリーの最大値を減算すると、小さいサブツリーを保存しながら最大のサブツリーを感染させるという最適な戦略が実装されます。 

## 実用的な例

 サンプル入力`4 1 2`(2 つの頂点を持つツリー)`0`。 DFS はルートから開始され、1 つの子 (頂点 2) を参照します。これはリーフであるため、0 を返します。子は 1 つしかないため、ルートは 0 を返します。 

4 つの頂点が次のように接続されたサンプル入力`1-2-3`そして`2-4`:

 | ノード | 子どもたち | 保存された値 | 返されました |
 | --- | --- | --- | --- |
 | 3 | [] | [] | 0 |
 | 4 | [] | [] | 0 |
 | 2 | 3,4 | [0,0] | 0 |
 | 1 | 2 | [0] | 0 |

 ここで、感染が広がる前に頂点 2 を削除すると、頂点 3 と 4 を保存できることがわかります。DFS は、保存されたサブツリーを正しく計算し、複数の子が存在する場合に最大のものを減算します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | 各ノードは 1 回アクセスされ、すべての子はエッジごとに一定の時間で処理されます。 
| スペース | テスト ケースあたり O(n) | 隣接リストと傾斜ツリー内の深さ O(n) の再帰スタック |

 ## 特殊なケース

 2 つのノードからなるツリーの場合: 入力`2\n1 2\n`。 DFS はルート 1 から開始し、子 2 を参照します。子はリーフで、0 を返します。ルートは 0 を返します。出力`0`試合が予想されます。 最小限のツリーにもかかわらず、再帰エラーは発生しません。 

5 つのノードの斜めのラインの場合: 入力`5\n1 2\n2 3\n3 4\n4 5\n`。 DFS はリーフからルートに伝播します。ノード 5 と 4 はリーフで、0 を返します。ノード 3 は子 4 を参照し、0 を返します。ノード 2 は子 3 を参照し、0 を返します。ルート 1 は子 2 を参照し、2 を返します。
