 ## 解決策
 ## 問題の理解

 順列が与えられています$p$数字のうち$1$を通して$n$。 別の順列を構築したい$q$すべての位置が変わるように同じ番号を使用します。 あらゆるインデックスに対して$i$、に置かれた値$q_i$とは異なる必要があります$p_i$。 

このような有効な順列すべての中で、辞書編集的に最小のものを出力する必要があります。 有効な順列が存在しない場合は、次のように出力します。$-1$。 

制約は非常に小さいです。 すべての合計$n$値は最大でも$1000$。 これは、$O(n^2)$アルゴリズムは簡単に十分に高速です。 高度なデータ構造や高度な最適化は必要ありません。 本当の課題は、固定小数点を回避しながら、辞書編集的に最小の有効な順列を見つけることです。 

最も危険なエッジケースは、建設の終わり近くに発生します。 

考慮する：```
n = 1
p = [1]
```長さ 1 の順列は 1 つだけあります。 どの候補者も順位を付けるだろう$1$位置にある$1$、固定点を作成します。 正しい答えは次のとおりです。```
-1
```利用可能な最小値を常に選択する貪欲なアルゴリズムでは、誤った結果が生成されます。$[1]$。 

もう 1 つの注意が必要なケースは次のとおりです。```
p = [1, 2, 3]
```現在の位置の値と等しくない利用可能な最小値を貪欲に選択すると、次のようになります。```
q = [2, 1, ?]
```のみ$3$残っていますが、$q_3 = 3$は禁止されています。 不注意で貪欲なアプローチは、たとえ有効な答えであっても行き詰まってしまう```
[2, 3, 1]
```存在します。 

3 番目の重要なケースは、値が 1 つだけ残り、それが最後の位置の禁止値と等しい場合に発生します。 例えば：```
p = [2, 3, 1, 4]
```単純な構築では次のような結果が得られる可能性があります。```
q = [1, 2, 4, ?]
```だけで$4$残り。 以来$p_4=4$、配置すると要件に違反します。 正しい修正は、最後に選択した値を残りの値と交換して、次のようにすることです。```
[1, 2, 4, 3]
```これは有効であり、辞書編集上最小限です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 のすべての順列を生成します$1$を通して$n$と異なるかどうかを確認してください。$p$すべての位置で、辞書編集上最も小さい有効なものを保持します。 

これが機能するのは、神秘的な順列の定義が検証しやすいためです。 残念ながら、順列の数は$n!$。 たとえ$n=10$、これはすでに 300 万の可能性を超えています。 階乗増加により、ブルートフォースは使用できなくなります。 

重要な観察は、辞書編集上の最小性が貪欲な構造を示唆しているということです。 ポジションを決めるとき$i$、すぐには条件に違反しない、利用可能な最小の数値を配置する必要があります。$q_i \ne p_i$。 

ほとんどのポジションはこの方法で処理できます。 唯一の複雑な問題は最後に現れます。 貪欲に最初を埋めた後、$n-1$の位置では、1 つの値が残る場合があります。 その値が次と等しくない場合$p_n$、ただ置くだけです。 

残りの値が等しい場合$p_n$、建設を修復しなければなりません。 残りの値はまだ使用されていないため、以前の位置にすでに存在している必要があります。$p$。 これを前の位置に配置された値と交換すると、辞書編集上の最小性を維持しながら固定小数点が削除されます。 

この観察により、問題は単純な貪欲アルゴリズムに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n! \cdot n)$|$O(n)$| 遅すぎる |
 | 最適な貪欲さ |$O(n^2)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. もし$n=1$、出力$-1$。 神秘的な順列は存在しません。 
2. 未使用の番号のセットを維持します。 
3. 最後の位置を除き、位置を左から右に処理します。 
4. ポジションについて$i$に等しくない最小の未使用の数値を選択します。$p_i$。 
5. 未使用のセットからその番号を削除し、答えに追加します。 
6. 最初の項目を入力したら$n-1$位置、ちょうど 1 つの数字が残ります。 
7. 残数が異なる場合$p_n$、最後の位置に置きます。 
8. それ以外の場合は、一時的に最後の位置に配置し、構築された順列の最後の 2 つの要素を交換します。 
9. 結果の順列を出力します。 

最終的なスワップが機能する理由は簡単です。 残りの数は次のとおりです$p_n$, したがって、最後の位置に留まることはできません。 前の位置には別の値が含まれています。 これら 2 つの値を交換すると、最後の固定点が削除され、新しい固定点は作成されません。 

### なぜ効果があるのか

 辞書編集上の順序は 2 つの順列が異なる最も早い位置によって決定されるため、貪欲な選択は常に最適です。 位置で$i$、利用可能な最小の有効な数値を選択すると、すべての有効なソリューションの中で可能な限り最小のプレフィックスが生成されます。 

貪欲なプロセスが困難に遭遇するのは、最終位置に 1 つの禁止値が残っている場合だけです。 その状況では、これまでの選択肢はすべて、すでに辞書編集上最小限のものでした。 最後の 2 つの位置を交換すると、可能な限り遅く順列が変更され、最小の接頭辞が保存され、したがって辞書編集上の最小性が保存されます。 

したがって、アルゴリズムは、有効なミスティック順列が存在する場合には必ずそれを構築し、すべての有効な順列の中で辞書順列が最小になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    p = list(map(int, input().split()))

    if n == 1:
        print(-1)
        continue

    unused = set(range(1, n + 1))
    q = []

    for i in range(n - 1):
        for x in range(1, n + 1):
            if x in unused and x != p[i]:
                q.append(x)
                unused.remove(x)
                break

    last = next(iter(unused))
    q.append(last)

    if q[-1] == p[-1]:
        q[-1], q[-2] = q[-2], q[-1]

    print(*q)
```アルゴリズムは、未使用の値を明示的に維持します。 以来$n\le1000$からのすべての番号をスキャンします。$1$に$n$どの段階でも完全に受け入れられます。 

最初$n-1$ポジションは貪欲に埋められます。 各ステップで、禁止値とは異なる使用可能な最小の数値$p_i$が選択されます。 

最後に残った値が追加されます。 最終位置に固定点を作成すると、最後の 2 つの要素が交換されます。 

最も重要な実装の詳細は、すべてのポジションが埋まった後にのみスワップが実行されることです。 この状況を早期に処理しようとするとロジックが複雑になるため、その必要はありません。

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        if n == 1:
            out.append("-1")
            continue

        unused = set(range(1, n + 1))
        q = []

        for i in range(n - 1):
            for x in range(1, n + 1):
                if x in unused and x != p[i]:
                    q.append(x)
                    unused.remove(x)
                    break

        q.append(next(iter(unused)))

        if q[-1] == p[-1]:
            q[-1], q[-2] = q[-2], q[-1]

        out.append(" ".join(map(str, q)))

    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

assert run("4\n3\n1 2 3\n5\n2 3 4 5 1\n4\n2 3 1 4\n1\n1\n") == \
       "2 3 1\n1 2 3 4 5\n1 2 4 3\n-1"

assert run("1\n1\n1\n") == "-1"

assert run("1\n2\n1 2\n") == "2 1"

assert run("1\n3\n2 1 3\n") == "1 3 2"

assert run("1\n4\n1 2 3 4\n") == "2 3 4 1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |$n=1$|$-1$| 不可能なケース |
 | [1,2] | [2,1] | 最小の自明でない順列 |
 | [2,1,3] | [1,3,2] | 最終的な修復手順 |
 | [1,2,3,4] | [2,3,4,1] | サイクリックシフトスタイルのソリューション |

 ## 特殊なケース

 次のことを考慮してください。```
1
1
1
```長さ 1 の順列は 1 つだけあります。 候補地があれば$1$唯一の位置で固定点を作成します。 アルゴリズムは即座に検出します$n=1$そして出力$-1$。 

考慮する：```
1
3
1 2 3
```貪欲な選択により、次のような結果が得られます。```
[2,1,3]
```最終値は禁止値と等しい$3$。 アルゴリズムは最後の 2 つの位置を交換し、次を取得します。```
[2,3,1]
```すべての位置が元の順列とは異なります。 

考慮する：```
1
2
2 1
```貪欲なプロセスは以下を選択します。```
[1,2]
```どちらの位置も元の順列とは異なるため、修復する必要はありません。 これにより、アルゴリズムが解決可能な最小サイズを正しく処理していることが確認されます。 

考慮する：```
1
4
2 3 1 4
```最終ステップでの残りの値は、$3$に等しくない$4$。 アルゴリズムは単にそれを追加して以下を返します。```
[1,2,4,3]
```これにより、修復手順が必要な場合にのみ適用されることが検証されます。
