 ## 解決策
 ## 問題の理解

 個別のアイテムのシーケンスが与えられます。各アイテムは元々 1 から N までの固定位置にあります。それらを新しい順序に並べ替える必要があります。 制約は位置に関するものです。項目が位置 x で始まり、位置 y で終わる場合、絶対距離 |x − y| になります。 言い換えれば、アイテムは元の位置の近くにとどまることができず、最終的な置換では少なくとも K ステップ離れなければなりません。 

タスクは、このルールを満たす有効な順列を構築するか、そのような順列が存在しないことを判断することです。 

入力は単一の曲名のシーケンスですが、これらの名前は個別の要素のラベルにすぎません。 実際の構造は、インデックス位置 1 から N です。出力は、有効な並べ替えシーケンスか、それが実行できないというステートメントです。 

N が 10^5 までという制約は、線形または線形に近い構造が必要であることを意味します。 順列または検索構成をテストしようとするソリューションは、N! であるため、直ちに除外されます。 あるいは、N^2 アプローチでさえ、実現可能な限界をはるかに超えています。 唯一の実行可能な解決策は、直接的な建設的な置換または貪欲なシフトです。 

キーエッジケースは、小さい N または大きい K から生じます。K が N に対して大きい場合、移動は不可能になります。 

たとえば、N = 4 および K = 3 の場合、位置 1 は少なくとも位置 4 に移動する必要がありますが、位置 4 は最大でも位置 1 に移動する必要があり、すべての要素で同時に解決できない競合が発生します。 すべてを K 位置だけシフトするような単純な試みは、ラッピングによって小さな距離が生じるため失敗します。 

もう 1 つの微妙なエッジ ケースは、K = 0 の場合です。その場合、|x − x| であるため、元の順序はすでに条件を満たしています。 = 0 が許可されます。 

## アプローチ

 ブルートフォース解釈では、すべての順列を生成し、すべての要素が距離条件を満たすかどうかを確認しようとします。 これはルールを直接適用するため、原則的には正しいですが、N! をチェックする必要があります。 順列があり、各チェックのコストは O(N) であるため、N = 8 程度を超えると完全に実行不可能になります。 

より構造化されたブルートフォースの改善は、配置位置を位置ごとに交換またはバックトラックして、各割り当てがすでに配置されている要素の距離制約を確実に遵守するようにすることです。 初期の配置が後の配置を大きく制約し、分岐係数が依然として大きいため、これは依然として爆発的です。 

重要な観察は、制約が純粋に位置的かつ対称であるということです。各インデックス i は、その要素を区間 [i − (K − 1), i + (K − 1)] に配置することを禁止します。 これは、検索の代わりに、すべてのインデックスを禁止ゾーンの外側に均一な方法でシフトする順列を直接構築する必要があることを示唆しています。 

自然な試みは循環的なシフトです。 すべての要素を i から i + K に移動してラップアラウンドすると、各要素はインデックス空間内で正確に K 位置前方に移動します。 ただし、ラッピングによって、K より小さい可能性のある 2 番目の変位が導入されます。これによって制約が破られないのは、ラップアラウンド距離がまだ少なくとも K である場合であり、これは正確に N − K ≥ K、または同等の N ≥ 2K の場合に発生します。 

N ≥ 2K の場合、配列をサイズ K と N − K の 2 つの部分に安全に分割し、配列全体を K 位置だけ回転できます。 これにより、すべての要素が少なくとも K だけ前方または後方に移動することが保証されます。 

N < 2K の場合、利用可能な位置が密集しすぎるため、いかなる試みも失敗するはずです。 すべての要素は、それ自体の周囲にサイズ 2K − 1 の中央ウィンドウを避ける必要がありますが、利用可能な位置の総数はすべての制約を同時に満たすには不十分です。

 | ブルートフォース順列 | O(N!・N) | O(N) | 遅すぎる |
 | サイクリックシフト構築 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

最適な構築は、距離の制約に違反することなく、K 個の位置だけ配列を安全に回転できるかどうかによって決まります。 

1. K の値を確認します。K が 0 の場合、元の順序はすでに条件を満たしているため、配列を直接出力できます。 これにより、不必要な変換が回避され、縮退のケースがきれいに処理されます。 
2. N が 2K 未満かどうかを確認します。 そうである場合は、有効な順列が存在しないと直ちに結論付けます。 これは、有効な配置では、すべての要素がサイズ 2K − 1 の禁止された間隔の外側にマップされる必要があり、長さ N の行には収まらないという事実から導かれます。 
3. N が少なくとも 2K の場合、各インデックスを N を法として K 位置だけ前方にシフトすることによって新しい順列を構築します。具体的には、1 から N までの各 i について、それを位置 (i + K) に割り当て、N を超えると先頭に戻ります。 
4. 結果のシーケンスをこの新しい順序で出力します。 

この構造が選択される理由は、均一な変位パターンを作成するためです。 すべての要素は循環的に正確に K 位置前方に移動され、サイズ条件 N ≥ 2K により、折り返しによって K より小さいショートカット距離が生成されないことが保証されます。 

### なぜ効果があるのか

 このアルゴリズムは、もともと位置 i にあった各要素が、i からの循環距離が正確に K 前方の位置に移動されるという不変条件を維持します。 N ≥ 2K の場合、この周期的変位は K または N − K の線形変位に対応し、両方とも K 以上で​​す。したがって、すべての要素は |i − p[i]| を満たします。 ≥ K、制約がグローバルに保持されることを確認します。 すべての位置が 1 回だけ使用されるため、結果は有効な置換になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    arr = input().split()

    if k == 0:
        print("YES")
        print(*arr)
        return

    if n < 2 * k:
        print("NO")
        return

    res = [None] * n

    for i in range(n):
        res[(i + k) % n] = arr[i]

    print("YES")
    print(*res)

if __name__ == "__main__":
    solve()
```この実装では、アルゴリズムで説明されている巡回シフトを直接エンコードします。 配列`res`は最終的な順序を表し、元の各インデックス i は位置 (i + k) mod n に配置されます。 モジュロ演算はラップアラウンドが処理される唯一の場所であり、正確性は、このラップアラウンドによって K より小さい変位が生成されないことを保証する初期のチェックに依存します。 

よくある間違いは、N < 2K の場合に同じ巡回シフトが失敗することを忘れていることです。 このガードがないと、末尾から先頭に折り返された要素が元の位置に近づきすぎる可能性があります。 

## 実用的な例

 入力で N = 4 および K = 1 の場合を考えます。`[a, b, c, d]`。 

各要素を 1 位置ずつシフトします。 

| 私 | 元の位置 | 新しい位置 (i+1 mod 4) |
 | --- | --- | --- |
 | 1 | | 2 |
 | 2 | b | 3 |
 | 3 | c | 4 |
 | 4 | d | 1 |

 結果として得られる順列は、`[d, a, b, c]`。 すべての要素は循環的に 1 つの位置を正確に移動します。K = 1 であるため、これは有効です。 

ここで、入力を使用して N = 6 および K = 2 を考えます。`[1, 2, 3, 4, 5, 6]`。 

| 私 | 元の位置 | 新しいポジション |
 | --- | --- | --- |
 | 1 | 1 | 3 |
 | 2 | 2 | 4 |
 | 3 | 3 | 5 |
 | 4 | 4 | 6 |
 | 5 | 5 | 1 |
 | 6 | 6 | 2 |

 結果は`[5, 6, 1, 2, 3, 4]`。 すべての要素は元のインデックスから 2 または 4 位置離れた位置に移動され、両方とも K 以上です。 

これらのトレースは、シフトにより均一な変位パターンが維持され、禁止された近傍内に要素が留まることを回避していることを示しています。

 ## 特殊なケース

 K = 0 の場合、制約は制限を課しません。 アルゴリズムは直ちに元の配列を返します。これは、すべての要素が元の位置からの距離 0 に留まるため、条件を自明に満たします。 

N < 2K、たとえば N = 5、K = 3 の場合、シフトを試みるとラップアラウンド衝突が発生します。 位置 4 から 1 に移動した要素の距離は 3 ですが、境界付近の要素をすべて制約に違反せずに配置することはできず、構築は不可能です。 アルゴリズムはこれを正しく検出し、並べ替えを試みる前に NO を出力します。 

N ≥ 2K の場合、巡回シフトによって元の位置の周囲の禁止区間に要素がマッピングされることはなく、すべての要素が安全な距離に配置されるため、すべての可能なケースで構築が正しいことが確認されます。
