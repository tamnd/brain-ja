 ## 解決策
 ## 問題の理解

 私たちには一組の学生といくつかの学生団体が与えられています。 各組織は役員のグループで構成されており、イベントを実行するには、すべての役員が組織のプロムに実際に出席する必要があります。 

各組織のプロムは、土曜日または日曜日の 2 日のうちの 1 日にスケジュールする必要があります。 重要な制限は、学生は同じ日に予定されている 2 つの異なるプロムに参加できないことです。 学生は複数の組織に所属する可能性があるため、少なくとも 1 人の役員を共有するイベント間で競合が発生します。 

このタスクは、学生が同じ日に 2 つの組織に出席する必要がないように、各組織を土曜日または日曜日に割り当てることです。 それが不可能な場合は、失敗を報告する必要があります。 複数の有効なスケジュールが存在する場合は、土曜日に配置される組織の数を最大化するスケジュールがさらに優先されますが、有効な最大土曜日のソリューションであればどれでも受け入れられます。 

入力は当然、学生と組織間の二部構成の発生構造です。各組織はセットであり、セット間の重複が競合を定義します。 2 つの組織が少なくとも 1 人の学生を共有すると競合するため、同じ日に割り当てることはできません。 

注意すべき主な制約はスケールです。 すべての組織にわたるメンバーシップ エントリの総数は数十万に達する可能性があるため、組織のすべてのペアを明示的に比較するソリューションは不可能です。 組織に対する二次的なチェックはすぐに失敗します。 代わりに、問題を共有生徒から構築されたグラフ構造に落とし込み、ほぼ線形な時間で処理する必要があります。 

微妙なエッジケースは、学生が 3 つ以上の組織に所属しており、その組織すべてがその学生を通じて重複している場合に発生します。 たとえば、1 人の学生が 3 つの組織に属している場合、3 つの組織すべてがその共有メンバーを通じて相互に制約されます。 推移的伝播を考慮せずに組織ごとに単純に貪欲な割り当てを行うと、後で簡単に矛盾が生じる可能性があります。 

もう 1 つの特殊なケースは、競合グラフに奇数のサイクルが含まれている場合です。 たとえば、3 つの組織が異なる重なり合う学生をペアごとに共有すると、一貫して 2 色にすることができない制約のサイクルが強制され、スケジュール設定が不可能になります。 これを検出するには、ローカルなチェックではなく、グローバルな推論が必要です。 

## アプローチ

 各組織を独立して扱い、土曜日または日曜日のすべての割り当てを試すという強引なアイデアです。 M 個の組織の場合、これは 2^M の可能性をもたらします。 各課題について、すべての学生をチェックし、学生が所属するすべての組織の中で、最大 1 人が土曜日に割り当てられ、最大 1 人が日曜日に割り当てられていることを確認することで、妥当性を検証します。 単一の割り当ての構築と検証にはすでに O(メンバーシップの合計) が必要なので、合計は O(2^M · total_membership) になります。これは、数十万はおろか、数十の M であっても実現不可能です。 

重要な観察は、生徒が強制していることを理解すると、私たちは実際には生徒のことを直接気にしていないということです。 各学生は、所属するすべての組織間に制約を課します。これらの組織のうちの 2 つが同じ日を共有することはできません。 これは、各学生について、その学生を含む組織が対立グラフで徒党を形成していると言うのと同じです。 隣接する組織が異なるように 2 つの色 (日) のいずれかを割り当てる必要があるため、問題全体はこのグラフが 2 部構成であるかどうかを確認することに帰着します。 

一旦 2 部構成の検査として見なされると、問題は標準的なグラフの色付けになります。 問題は、グラフが明示的に与えられていないことです。 それは共有学生を通じて暗黙的に定義されます。 各学生を反復処理し、学生が所属するすべての組織を接続することで、隣接関係を構築する必要があります。

土曜日の割り当てを最大化するという要件は、実現可能性を変えるものではありません。 どの 2 部グラフでも、色の交換まで、連結成分ごとに 2 つの有効な色が存在します。 したがって、より多くのノードが土曜日の側に分類されるように、各コンポーネントの方向を選択できます。 このコンポーネントごとのローカルな反転により、グローバルな最大値が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース割り当て | O(2^M · 会員数合計) | O(会員数合計) | 遅すぎる |
 | グラフ構築 + 2 部カラーリング | O(N + 会員数合計) | O(N + M + 合計メンバーシップ) | 承認済み |

 ## アルゴリズムのチュートリアル

 各組織をグラフ内のノードとしてモデル化します。 少なくとも 1 人の学生を共有する 2 つのノードを接続します。 学生ごとにすべてのペアワイズ エッジを明示的に構築するとコストがかかる可能性があるため、代わりに、各学生を反復処理してメンバーシップ リスト内のすべての組織を接続するという標準的な手法を使用します。 

1. すべての組織の隣接リストを作成します。 すべての学生について、所属する組織のリストを収集し、そのリスト内の連続する組織を接続してエッジを形成します。 学生が k 個の組織に属している場合、それらをチェーンで接続すると、二部制約の推移性を通じてグループ全体に一貫性がすでに強制されるため、これで十分です。 
2. すべての組織に対してグラフの走査を実行します。 未訪問の組織ごとに、BFS または DFS を開始し、土曜日と日曜日を表す値 0 と 1 を使用して、接続されたコンポーネントを 2 色に着色しようとします。 任意の開始色を割り当てます。 
3. トラバース中に、組織 u から v へのエッジを訪問するとき、割り当てられていない場合は、v に u の反対の色を割り当てます。 すでに割り当てられていて、u の色と一致する場合は、構成が不可能であることがすぐにわかり、停止します。 
4. 接続コンポーネントが完成すると、最初の選択に応じて 2 つの有効な色が得られる場合があります。 土曜日の割り当てを最大化するために、カラー 0 とカラー 1 を取得したノードの数を数え、必要に応じてコンポーネント全体を反転して、カラー 0 がより大きなグループに対応するようにします。 
5. 最後に、最終的な色に基づいて各組織に割り当てられた日を出力します。 

正確さは、接続されている各コンポーネントを個別に扱うことから得られます。 コンポーネント内では、すべての制約がエッジによって強制され、二部構成により、奇数サイクルが存在しない場合に限り、すべての制約が満たされることが保証されます。 色を交換すると隣接性の制約が維持され、どちらの側が土曜日とラベル付けされるかだけが変更されるため、反転ステップによって有効性が損なわれることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict, deque

def solve():
    n, m = map(int, input().split())
    
    orgs = []
    student_map = defaultdict(list)
    
    # read input
    for i in range(m):
        r = int(input())
        names = input().split()
        orgs.append(names)
        for name in names:
            student_map[name].append(i)
    
    adj = [[] for _ in range(m)]
    
    # build graph: connect organizations sharing students
    for members in student_map.values():
        for i in range(len(members) - 1):
            u = members[i]
            v = members[i + 1]
            adj[u].append(v)
            adj[v].append(u)
    
    color = [-1] * m
    answer = [None] * m
    
    for i in range(m):
        if color[i] != -1:
            continue
        
        queue = deque([i])
        color[i] = 0
        comp = [i]
        
        ok = True
        
        while queue:
            u = queue.popleft()
            for v in adj[u]:
                if color[v] == -1:
                    color[v] = color[u] ^ 1
                    comp.append(v)
                    queue.append(v)
                elif color[v] == color[u]:
                    ok = False
        
        if not ok:
            print("NO")
            return
        
        cnt0 = sum(1 for x in comp if color[x] == 0)
        cnt1 = len(comp) - cnt0
        
        flip = cnt1 > cnt0
        
        for x in comp:
            final_color = color[x] ^ flip
            answer[x] = "Saturday" if final_color == 0 else "Sunday"
    
    print("YES")
    for x in answer:
        print(x)

if __name__ == "__main__":
    solve()
```コードはグラフ構築のアイデアに直接従っています。 隣接リストは共有学生メンバーシップを使用して構築され、BFS を使用して交互の日を割り当てます。 唯一の微妙な実装の詳細は、両方の色数がわかった後でそれを反転するかどうかを決定できるように、トラバーサル中に各接続コンポーネントを保存する必要があることです。 コンポーネント ノードを保存しないと、最適化ステップは実行できません。 

ここでよくある落とし穴は、学生が多くの組織に所属する可能性があることを忘れていることです。 生徒のリスト内のすべてのペアを接続しようとすると、生徒ごとに O(k^2) 個のエッジが発生する危険があります。 ここで使用される線形チェーン接続は、二部制約を維持しながらその爆発を回避します。 

## 実用的な例

 3 つの組織 A、B、C からなる小規模な構成を考えてみましょう。A と B は 1 人の学生を共有し、B と C は別の学生を共有しますが、A と C は誰とも直接共有しません。

 A にはアリスとボブが含まれます

 B にはボブとチャーリーが含まれます

 Cにはチャーリーが含まれています

 | ステップ | 処理されたノード | 色の割り当て | キューの状態 |

 | 開始 | あ | A=0 | [A] |

 走査後の色は A=0、B=1、C=0 になります。 

これは、2 つの組織が直接重複していない場合でも、推移的な制約が共有メンバーを通じてどのように正しく伝播されるかを示しています。

 これは、反転がコンポーネントごとに独立して適用され、実現可能性に影響を与えることなく土曜日への最大限の割り当てが保証されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N + 合計 r_i) | 学生から組織への各エッジは、グラフの構築および BFS の走査中に 1 回処理されます。 
| スペース | O(N + M + 合計 r_i) | 隣接リストとメンバーシップおよび BFS 状態のストレージ |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、学生が非常に多くの組織に所属している場合です。 その状況では、すべてのペアを明示的に接続するわけではありません。 代わりに、チェーン エッジを介した BFS 伝播に依存します。 接続により制約が推移的に広がるため、アルゴリズムは引き続き、その学生のグループ内のすべての組織に 2 つのパーティション間で交互に強制することを正しく強制します。 

もう 1 つのエッジ ケースは、他の学生と学生を共有しない、完全につながりのない組織です。 このようなノードは、サイズ 1 の孤立したコンポーネントを形成します。 アルゴリズムは最初にカラー 0 を割り当て、制約なしに「土曜日を最大化する」という目標に自然に貢献します。 

最後のエッジ ケースは、奇数サイクルのオーバーラップによって引き起こされる不一致です。 たとえば、A が B と生徒を共有し、B が C と生徒を共有し、C が A と生徒を共有する 3 つの組織があります。BFS の色付け中に、これにより最終的に矛盾が発生し、すでに色付けされたノードに隣接するノードと同じ色が割り当てられ、即座に拒否がトリガーされ、NO が出力されます。
