 ## 解決策
 ## 問題の理解

 2D 平面上には偶数の点が与えられます。 タスクは、すべてのポイントを正確に分割することです。$n/2$素のペア。 

ペアポイントの場合$(x_1,y_1)$そして$(x_2,y_2)$、その寄与はマンハッタン距離です$$|x_1-x_2| + |y_1-y_2|.$$考えられるすべての完全一致の中で、マンハッタン距離の合計を最大化する組み合わせを出力する必要があります。 

すべてのテスト ケースにわたるポイント数は最大で$2 \cdot 10^5$したがって、すべてのペアリングを検査する解決策は不可能です。 たとえ$n=20$、完全一致の数はすでに膨大です。 と$n$到達$2 \cdot 10^5$に近いものを期待する必要があります。$O(n \log n)$。 

厄介な点は、マンハッタン距離には 2 つの独立した座標が含まれていることです。 x 座標のみにとって最適であると思われるペアリングは、y 座標にとって最適であると思われるペアリングと互換性がないように見える場合があります。 重要な観察は、これら 2 つの最適化が実際には同時に実行できるということです。 

よくある間違いは、残っている最も遠いポイントを貪欲にペアにしてしまうことです。 考慮する：```
4
(0,0)
(1,100)
(100,1)
(101,101)
```ローカルで貪欲な選択を行うと、1 つの極端な点がすぐに消費されてしまい、グローバルに最適なマッチングが妨げられる可能性があります。 正しい解決策を得るには、すべての点の構造を一度に推論する必要があります。 

多くの点が同じ x または y 座標を共有する場合、別の微妙なケースが発生します。 例えば：```
4
(0,0)
(0,1)
(0,2)
(0,3)
```この問題では一意の一致は必要ありません。 複数の最適な答えが存在し、アルゴリズムは同点に関係なく機能する必要があります。 

## アプローチ

 ブルートフォース ソリューションでは、すべての完全なマッチングが生成され、その合計マンハッタン距離が計算され、最良のマッチングが維持されます。 

これは、すべての有効な回答を明示的にチェックするため、正しいです。 残念ながら、完全一致の数は$n$頂点は$$(n-1)(n-3)(n-5)\cdots 1,$$超指数関数的に成長します。 平$n=20$すでに実用的な限界をはるかに超えています。 

より迅速な解決策を見つけるには、まず y 座標のことを忘れて、x だけを調べます。 

数字があるとします$x_1,x_2,\dots,x_n$そして最大化したい$$\sum |x_a-x_b|$$すべてのペアリングにわたって。 

ソート後、最適な戦略は明らかです。最小の半分と最大の半分をペアにします。 1 つの次元に対するすべての最適解は、下半分の要素と上半分の要素を一致させます。 

驚くべきことは、同じアイデアを両方の座標に同時に適用できることです。 

点を x で並べ替えます。 最初にマークを付ける$n/2$としてポイント$X_L$そして最後$n/2$として$X_R$。 

点を y で並べ替えます。 最初にマークを付ける$n/2$としてポイント$Y_L$そして最後$n/2$として$Y_R$。 

各点は、次の 4 つのグループのいずれかに正確に属します。$$A=X_L\cap Y_L$$

$$B=X_R\cap Y_L$$

$$C=X_L\cap Y_R$$

$$D=X_R\cap Y_R$$すべてのポイントをペアリングできれば$A$からのポイント付き$D$、およびからのすべてのポイント$B$からのポイント付き$C$、その後、すべてのペアが x 分割と交差し、さらに y 分割とも交差します。 

x 分割を横切ると、最大の x 寄与が保証されます。 

y 分割を横切ると、可能な最大の y 寄与が保証されます。 

カウント引数は次のことを示します$$|A|=|D|$$そして$$|B|=|C|.$$したがって、そのような組み合わせは常に存在します。 これは、独立して最適な x 構造と y 構造が実際に互換性があることを意味します。

 ## アルゴリズムのチュートリアル

 1. すべてのポイントを元のインデックスと一緒に読み取ります。 
2. 点を x 座標で並べ替えます。 
3. 最初のマークを付けます$n/2$ポイントは下位 x 半分に属し、残りのポイントは上位 x 半分に属します。 
4. 点を Y 座標で並べ替えます。 
5. 最初のマークを付けます$n/2$点は y の下半分に属し、残りの点は y の上半分に属します。 
6. すべての点について、それが 4 つのグループのどれに属するかを決定します。$A$、$B$、$C$、 または$D$。 
7. ポイントのペアリング$A$からのポイント付き$D$勝手に。 
8. ポイントをペアにする$B$からのポイント付き$C$勝手に。 
9. 生成されたすべてのペアを出力します。 

グループのメンバーシップのみが重要であるため、各グループ内の任意のペアリングが機能します。 ペアが両方の座標の反対側の半分を接続すると、全体的な最適性の議論はすでに満たされています。 

### なぜ効果があるのか

 1 つの次元では、すべてのペアが下半分の要素を上半分の要素に接続した場合にのみ、可能な最大の寄与が達成されます。 

私たちの構造では、生成されたすべてのペアが x パーティションを通過することが保証されます。 したがって、合計 x 寄与は最大になります。 

同じ構造により、生成されたすべてのペアが y パーティションを通過することも保証されます。 したがって、合計 y 寄与は最大になります。 

マンハッタン距離は x 寄与と y 寄与の合計であるため、両方を独立して最大化すると、グローバルに最大のマンハッタン和が得られます。 等式$|A|=|D|$そして$|B|=|C|$必要なペアリングを常に完了できるようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n = int(input())

        pts = []
        for i in range(n):
            x, y = map(int, input().split())
            pts.append([x, y, i + 1])

        x_side = [0] * n
        y_side = [0] * n

        order_x = sorted(range(n), key=lambda i: (pts[i][0], pts[i][1]))
        for pos, idx in enumerate(order_x):
            if pos < n // 2:
                x_side[idx] = 0
            else:
                x_side[idx] = 1

        order_y = sorted(range(n), key=lambda i: (pts[i][1], pts[i][0]))
        for pos, idx in enumerate(order_y):
            if pos < n // 2:
                y_side[idx] = 0
            else:
                y_side[idx] = 1

        A, B, C, D = [], [], [], []

        for i in range(n):
            if x_side[i] == 0 and y_side[i] == 0:
                A.append(pts[i][2])
            elif x_side[i] == 1 and y_side[i] == 0:
                B.append(pts[i][2])
            elif x_side[i] == 0 and y_side[i] == 1:
                C.append(pts[i][2])
            else:
                D.append(pts[i][2])

        for a, d in zip(A, D):
            out.append(f"{a} {d}")

        for b, c in zip(B, C):
            out.append(f"{b} {c}")

    sys.stdout.write("\n".join(out))

solve()
```最初の並べ替えでは、各点が x に関して下半分に属するか上半分に属するかを決定します。 2 番目の並べ替えでは、y に対して同じ分類が実行されます。 

その後、すべてのポイントが 4 つのバケットのいずれかに割り当てられます。 証明は、バケット サイズが完全一致に必要な等式を満たしていることを示しています。したがって、対応する要素を`zip`安全です。 

出力にはソート後の位置ではなく、入力順序からのポイント識別子が必要であるため、元のインデックスを使用することが不可欠です。 

この実装ではマンハッタン距離は決して計算されません。 数学的構造だけで最適なマッチングが決まります。

# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    input_data = io.StringIO(inp)

    t = int(input_data.readline())
    ans = []

    for _ in range(t):
        n = int(input_data.readline())

        pts = []
        for i in range(n):
            x, y = map(int, input_data.readline().split())
            pts.append([x, y, i + 1])

        x_side = [0] * n
        y_side = [0] * n

        ox = sorted(range(n), key=lambda i: (pts[i][0], pts[i][1]))
        oy = sorted(range(n), key=lambda i: (pts[i][1], pts[i][0]))

        for p, idx in enumerate(ox):
            x_side[idx] = 0 if p < n // 2 else 1

        for p, idx in enumerate(oy):
            y_side[idx] = 0 if p < n // 2 else 1

        A, B, C, D = [], [], [], []

        for i in range(n):
            if x_side[i] == 0 and y_side[i] == 0:
                A.append(i + 1)
            elif x_side[i] == 1 and y_side[i] == 0:
                B.append(i + 1)
            elif x_side[i] == 0 and y_side[i] == 1:
                C.append(i + 1)
            else:
                D.append(i + 1)

        for a, d in zip(A, D):
            ans.append(f"{a} {d}")

        for b, c in zip(B, C):
            ans.append(f"{b} {c}")

    return "\n".join(ans)
