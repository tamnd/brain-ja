 ## 解決策
 ## 問題の理解

 うちにはいくつかのタイプの男の子がいます。 タイプは、そのタイプのすべての男子が好む 2 人の女子と、そのタイプに属する男子の数によって説明されます。 選ばれた男の子のグループは、選ばれた 2 人の男の子に少なくとも 1 人の好きな女の子がいる場合に有効です。 

入力は、ストーリー内に隠されたグラフを記述します。 各女の子は頂点であり、各男の子のタイプは、そのタイプが好む 2 人の女の子を接続するエッジです。 エッジの重みは、そのタイプの少年の数です。 タスクは、選択したエッジのすべてのペアが同じ頂点に接するエッジのセットを選択し、それらの重みの合計を最大化することです。 

すべてのテスト ケースにわたるboy タイプの合計数は 700,000 に達する可能性があります。これは、多くのサブセットまたは多くのタイプのペアを試行するアプローチは不可能であることを意味します。 二次解法では最悪の場合、約 4,900 億回の演算が必要になる可能性があり、これは通常のコンテストの制限時間内に収まる量をはるかに超えています。 型の数が線形に近いものが必要です。 

難しいのは、選択したエッジのセットがどのように見えるかを理解することです。 よくある間違いは、互換性のあるエッジの長いチェーンを検索することです。 ただし、互換性を確保するには、隣のペアだけでなく、すべてのペアが女の子を共有する必要があります。 たとえば、エッジ (1,2)、(2,3)、および (3,4) では、3 つのエッジすべてが連結コンポーネントを形成しますが、最初と 3 番目のエッジは女の子を共有していないため、すべてを選択することはできません。 

もう 1 つのエッジ ケースは、多くのエッジが同じ女の子を使用する場合です。 入力用```
3
1 2 5
1 3 7
1 4 4
```女の子 1 を介して 3 つのタイプすべてを一緒に選択できるため、答えは 16 です。男の子の数ではなくタイプの数だけを数える解決策は 3 を出力し、間違っています。 

2 番目のエッジ ケースは、パスが有望に見えても無効である場合です。 入力用```
3
1 2 10
2 3 10
3 4 10
```正しい出力は 20 です。中央のエッジはいずれかの外側のエッジと組み合わせることができますが、2 つの外側のエッジは共存できません。 接続性のみをチェックする方法では、誤って 30 人の少年全員を連れて行ってしまう可能性があります。 

## アプローチ

 この強引なアイデアは、男の子のタイプのすべての可能なサブセットを試し、選択されたすべてのペアが女の子を共有するかどうかを確認することです。 これは正しいグループの定義に直接従うためです。 ただし、n 型の場合は 2^n 個のサブセットがあり、これは中程度の n であってもすでに不可能です。 もう 1 つの自然な力技は、すべてのエッジのペアをチェックして互換性情報を構築することですが、これには O(n^2) の比較が必要であり、n が 700000 に達すると遅すぎます。 

重要な観察は、有効なエッジのセットの形状が非常に制限されているということです。 選択した 2 つのエッジが異なると仮定します。 彼らは女の子を共有しなければならないので、両方の辺に属するいくつかの頂点が存在します。 選択したセット内のいずれかのエッジを獲得します。 他のすべてのエッジは、その端点のいずれかに接触する必要があります。 一部のエッジが一方のエンドポイントに触れ、他のエッジがもう一方のエンドポイントに触れた場合、元のエッジのエンドポイントが同じでない限り、これら 2 つのグループは共通の女の子を共有しませんが、これは不可能です。 これは、選択されたすべてのエッジが 1 人の女の子で接触する必要があることを意味します。 

したがって、問題ははるかに単純になります。 すべての女の子について、その女の子にエッジが触れるすべてのタイプの男の子の合計数を計算します。 答えはそのような最大の合計です。 考えられるすべての有効なグループは、共通の集合場所として 1 人の女の子を選択することに対応します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) または O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. インデックスが女の子を表し、値がその女の子を好むタイプの男の子の総数を表す配列を作成します。 女の子は 2n 人いるので、配列のサイズは 2n + 1 になります。 
2. 好きな女の子が a と b で、カウントが c のすべての男の子のタイプについて、a と b の合計に c を加えます。 これが機能するのは、女の子を中心とする有効なグループには、その女の子に関するあらゆるエッジ インシデントを含めることができるためです。 
3. すべてのタイプを処理した後、totals 配列に格納されている最大値を見つけます。 この値は、可能な最大のグループ サイズです。 

効果がある理由: すべての有効な回答には、選択したすべてのタイプの男の子に好かれる女の子が 1 人含まれている必要があります。 アルゴリズムは、一般的な女の子のあらゆる選択肢をチェックし、その周りの互換性のある男の子をすべて合計します。 最大グループはこれらの合計の 1 つとして現れる必要があり、計算されたすべての合計は有効なグループであるため、最大値が正確に答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        total = [0] * (2 * n + 1)

        for _ in range(n):
            a, b, c = map(int, input().split())
            total[a] += c
            total[b] += c

        ans.append(str(max(total)))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```配列`total`各女の子に接触するすべてのエッジの累積重量を保存します。 女の子には1から2nまでの番号が振られているので、`2 * n + 1`位置を使用すると、女の子の番号をインデックスとして直接使用できます。 

すべての入力エッジについて、両方のエンドポイントは同じカウントを受け取ります。これは、そのタイプのすべての男の子が、どちらかの好きな女の子を中心とする可能性のあるグループに寄与しているためです。 決勝戦`max`動作では、考えられるすべてのセンターがチェックされます。 

並べ替えやグラフの作成は必要ありません。 グラフはインシデント エッジの重みの合計によってのみ重要となるため、隣接リストを保存するとメモリが追加されてしまいますが、役に立ちません。 Python 整数を使用すると、カウントが大きくなる可能性があるため、オーバーフローの問題も回避されます。 

## 実用的な例

 最初のサンプルの場合:```
2
1 2 3
3 4 5
```トレースは次のとおりです。 

| ステップ | 女の子の合計 |
 | --- | --- |
 | 開始 | [0, 0, 0, 0, 0] |
 | (1,2,3) を加算 | 女の子 1 = 3、女の子 2 = 3 |
 | (3,4,5) を追加 | 女の子 3 = 5、女の子 4 = 5 |
 | 最大 | 5 |

 最良の選択は、女の子 3 または女の子 4 のいずれかで、そのタイプの男の子を 5 人選ぶことです。 

3 番目のサンプルの場合:```
4
1 2 3
2 3 4
3 5 4
1 3 2
```トレースは次のとおりです。 

| ステップ | 更新された値 |
 | --- | --- |
 | 開始 | すべてゼロ |
 | (1,2,3) を加算 | 女の子 1 = 3、女の子 2 = 3 |
 | (2,3,4) を追加 | 女の子 2 = 7、女の子 3 = 4 |
 | (3,5,4) を追加 | 女の子 3 = 8、女の子 5 = 4 |
 | (1,3,2) を追加 | 女の子 1 = 5、女の子 3 = 10 |
 | 最大 | 10 |

 女の子 3 は、最適なグループの共通の女の子であり、それにタッチするすべてのタイプを選択できます。

## 特殊なケース

 多くのエッジが同じ女の子を共有する場合:```
1
3
1 2 5
1 3 7
1 4 4
```合計は、女の子 1 = 16、女の子 2 = 5、女の子 3 = 7、女の子 4 = 4 になります。女の子 1 はすべての有効な選択肢の共通点であるため、アルゴリズムは 16 を選択します。 

チェーンケースの場合：```
1
3
1 2 10
2 3 10
3 4 10
```合計は、女の子 1 = 10、女の子 2 = 20、女の子 3 = 20、女の子 4 = 10 です。アルゴリズムは 20 を出力します。これは、女の子 2 の周囲の 2 つのエッジまたは女の子 3 の周囲の 2 つのエッジのみを一緒に選択できるという事実と一致します。 

単一タイプの場合:```
1
1
1 2 100
```両方の女の子が合計 100 を受け取るため、最大値は 100 になります。これにより、実装が最小のグラフを正しく処理していることが確認されます。
