 ## 解決策
 # 問題の理解

 私たちに与えられているのは、`n × m`セルに色が含まれるグリッド。 利用可能な色は次のいずれかです`{R, G}`いつ`c = 2`、 または`{R, G, B}`いつ`c = 3`。 

目標はせいぜい変更することです`q`水平または垂直に隣接する 2 つのセルが同じ色にならないようにセルを調整します。 このステートメントは、許可された変更数の範囲内で解決策が常に存在することを保証します。 

グリッドはせいぜい小さいです`100 × 100`, したがって、最大でも`10,000`細胞。 これは特に攻撃的なものを排除するものではありませんが、問題は計算上のものではなく建設的なものです。 課題は、許可された変更回数内に確実に収まるカラーリングを見つけることです。 

重要な観察は、セルのパリティから得られます。 細胞`(row + column) % 2 = 0`チェッカーボードの片面を形成し、パリティのあるセル`1`もう一方を形成します。 隣接するセルは常に反対のパリティに属します。 

のために`c = 2`、有効なカラーリングはすべて、次の 2 つのチェッカーボード パターンのいずれかである必要があります。```
R G R G ...
G R G R ...
```または同じパターン`R`そして`G`交換した。 

のために`c = 3`、色を追加すると、さらに自由度が高まります。 一方のパリティのすべてのセルを変更せずに保持し、もう一方のパリティのセルのみを再色付けすることができます。 1 つのパリティには最大でも`⌊nm/2⌋`セルの場合、これにより、最も困難なサブタスクで使用される変更制限が自動的に尊重されます。 

1 つのパリティが固定されている場合、微妙なケースが発生します。 もう一方のパリティ内のセルの場合、その隣接セルは 1 つ、2 つ、または 3 つの異なる色を使用する可能性があります。 3 つの色すべてが隣接するセルに表示される場合、現在のセルには色が残っていないため、固定パリティの選択は機能しません。 解決策は、両方のパリティ クラスを固定側として試すことです。 問題が保証されるということは、これらの試行のうち少なくとも 1 つが成功することを意味します。 

次の例を考えてみましょう。```
3 3
3 4
RGB
GBR
BRG
```間違ったパリティを変更せずに維持することに固執すると、一部のセルがその周囲の 3 色すべてを認識してしまい、割り当てることができなくなる可能性があります。 両方のパリティを試行すると、この罠を回避できます。 

もう 1 つの簡単な間違いは、変更を誤って数えることです。`c = 2`。 例えば：```
1 4
2 2
RGRG
```グリッドは既に 1 つのチェッカーボード パターンに正確に一致しているため、正解は変更せずに出力することです。 常に次から始まる解決策`R`左上隅にあると、反対のパターンの方がよく一致する場合に、すべてのセルが誤って変更されてしまいます。 

# アプローチ

 強引なアイデアは、グリッドの考えられるすべての有効な色を検索し、最大でも必要な色を選択することです。`q`修正。 たった 3 色であっても、グリッドの`10,000`細胞は持っています`3^10000`可能な着色ですが、完全に実行不可能です。 

隣接グラフの構造により、問題が簡単になります。 グリッドは 2 部構成です。 すべてのエッジは反対側のパリティを接続します。 これは、2 つのパリティ クラスを独立して推論できることを意味します。 

いつ`c = 2`、1 つのセルの色が選択されると、接続されたチェッカーボード グラフのすべての適切な色が強制的に適用されます。 まさに 2 つの可能性があります。 単純に両方を元のグリッドと比較し、変更が少ない方を選択します。 

いつ`c = 3`では、変更する必要があるパリティ クラスが 1 つだけであるという事実を利用します。 すべてのパリティ 0 セルを変更しないままにするとします。 この場合、どのパリティ 1 セルも互いに隣接していないため、すべてのパリティ 1 セルを独立して選択できます。 このようなセルごとに、すべての固定隣接セルとは異なる色を選択します。 一部のセルに 3 色すべてを使用する隣接セルがある場合、この試みは失敗します。 次に、反対パリティを固定して構築を繰り返します。 

構築が成功するたびに 1 つのパリティ クラスのセルのみが変更されるため、変更の数がそのパリティ クラスのサイズを超えることはありません。

 # アルゴリズムのチュートリアル

 ### ケース 1:`c = 2`1. 左上のセルが次のようなチェッカーボード パターンを構築します。`R`。 
2. 左上のセルが次のようなチェッカーボード パターンを構築します。`G`。 
3. 各パターンの元のグリッドと異なるセルの数を数えます。 
4. 差分の数が少ないパターンを出力します。 

有効な 2 色のグリッドはすべて、これら 2 つのパターンのいずれかである必要があるため、より良い方が常に最適です。 

### ケース 2:`c = 3`1.すべてのセルをパリティで修正してみてください`0`。 
2. 元のグリッドを作業グリッドにコピーします。 
3. パリティのすべてのセルについて`1`、その隣人を見てください。 
4. しましょう`used`それらの近隣に現れる色のセットになります。 
5. 現在の色が入っていない場合`used`、変更しないでください。 
6. それ以外の場合は、次から任意の色を選択します。`{R, G, B}`それは入っていない`used`。 
7. そのような色が存在しない場合、この試みは失敗します。 
8. すべてのパリティ 1 セルが正常に割り当てられた場合は、結果のグリッドを出力します。 
9. それ以外の場合は、パリティを使用して同じ手順を繰り返します。`1`固定とパリティ`0`色を塗り直した。 

### なぜ効果があるのか

 1 つのパリティ クラスが固定されている場合、色変更される 2 つのセルは隣接しません。 色を変更した各セルは、固定された隣接セルの色を避けるだけで済みます。 

隣接するすべての固定セルとは異なる色が選択された場合、そのセルに付随するすべてのエッジが有効になります。 グリッドの各エッジには各パリティ クラスのエンドポイントが 1 つあるため、すべてのエッジが同時に有効になります。 

固定パリティの両方の選択肢を試すと、ステートメントで約束された構造が見つかることが保証されます。 成功すると、1 つのパリティ クラスのセルのみが変更されるため、変更の数はそのクラスのサイズによって制限されます。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
c, q = map(int, input().split())
a = [list(input().strip()) for _ in range(n)]

if c == 2:
    patterns = []

    for start in ['R', 'G']:
        grid = []
        diff = 0

        for i in range(n):
            row = []
            for j in range(m):
                if (i + j) % 2 == 0:
                    ch = start
                else:
                    ch = 'G' if start == 'R' else 'R'

                row.append(ch)
                if ch != a[i][j]:
                    diff += 1

            grid.append(row)

        patterns.append((diff, grid))

    ans = min(patterns, key=lambda x: x[0])[1]

    for row in ans:
        print(''.join(row))

else:
    colors = ['R', 'G', 'B']

    def build(fixed_parity):
        b = [row[:] for row in a]

        for i in range(n):
            for j in range(m):
                if (i + j) % 2 == fixed_parity:
                    continue

                used = set()

                for di, dj in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                    ni = i + di
                    nj = j + dj

                    if 0 <= ni < n and 0 <= nj < m:
                        used.add(b[ni][nj])

                if b[i][j] not in used:
                    continue

                found = False

                for col in colors:
                    if col not in used:
                        b[i][j] = col
                        found = True
                        break

                if not found:
                    return None

        return b

    ans = build(0)
    if ans is None:
        ans = build(1)

    for row in ans:
        print(''.join(row))
```の`c = 2`ブランチは単純に両方のチェッカーボードの色を評価し、近い方を選択します。 

の`c = 3`ブランチはパリティベースの構築を実行します。 作業グリッドは、オリジナルのコピーとして開始されます。 固定パリティに属するセルは決してタッチされません。 1 つおきのセルは独立して処理されます。 

ここでは実装の詳細が重要になります。 近傍を調べるときは、元のグリッドではなく、作業中のグリッドから読み取ります。 固定パリティのセルは変更されませんが、色を変更したセルは互いに隣接することがないため、以前に割り当てられた値が競合することはありません。 

失敗条件は、再色付けされたセルの隣接セルに 3 色すべてが表示される場合に発生します。 その場合、そのパリティの選択に有効な色は存在しないため、反対のパリティを試します。

### 固定パリティの間違った選択

 セルが固定された隣接セルの 3 色すべてを認識する構成を想像してください。 利用可能な色が残っていないため、そのパリティの選択は失敗します。 アルゴリズムは次の場合にこれを検出します`used = {R, G, B}`そしてその試行に対して失敗を返します。 次に、反対側のパリティを固定して再試行します。これは、`c = 3`場合。
