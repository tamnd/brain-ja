 ## 解決策
 ## 問題の理解

 要素が次のとおりである配列が与えられます。`1`そして`-1`。 

すべてのプレフィックスの合計が負でなく、すべてのサフィックスの合計も負でない場合、サブシーケンスは良好と呼ばれます。 部分配列のクエリごとに`[l, r]`、その部分配列内の適切な部分列の可能な最大長を見つけなければなりません。 単一の要素を反転する更新クエリもあります。`1`に`-1`またはその逆。 

配列の長さとクエリの数は両方とも次のとおりです。`5 · 10^5`。 クエリされた範囲全体をスキャンするソリューションは、すぐに遅すぎます。 たとえ`O(length of range)`最悪の場合、クエリは二次関数になります。 おおよその必要があります`O(log n)`更新ごとおよびクエリごとに。 

問題の微妙な部分は、適切なサブシーケンスが実際にどのようなものかを理解することです。 

サブシーケンスを取得します。```
1 -1 1
```そのプレフィックスの合計は次のとおりです。```
1, 0, 1
```どれもマイナスではありません。 

その接尾辞の合計は次のとおりです。```
1, 0, 1
```すべてが負ではないため、その後のシーケンスは良好です。 

次に、次のことを考えてみましょう。```
1 1 -1
```接頭辞の合計は負ではありませんが、接尾辞は次のもののみで構成されます。`-1`合計があります`-1`, そのため、その後の続きが良くありません。 

プレフィックスの合計をチェックするだけの単純なアプローチでは、誤って受け入れられてしまいます。 

もう 1 つの簡単な間違いは、すべてのことを次のように仮定することです。`-1`以前のものと一致する必要があります`1`。 例えば：```
1 1 1
```含まれていません`-1`まったく、それでも、それは有効な適切な長さの部分列です`3`。 

接尾辞の条件が構造を興味深いものにしています。 

## アプローチ

 ブルート フォース ソリューションでは、範囲のすべてのサブシーケンスを列挙し、それぞれがプレフィックスとサフィックスの制約を満たしているかどうかを確認します。 

さまざまな長さの場合`m`、 がある`2^m`後続。 たとえ`m = 50`、これは完全に不可能であり、実際の制限は数十万です。 

重要な観察は、条件を書き換えることから得られます。 

すべてのプレフィックスの合計がサブシーケンスの合計以下である場合に限り、サフィックスの合計は負ではありません。 したがって、適切なサブシーケンスとは、プレフィックスの合計が内部に留まるサブシーケンスです。```
0 ≤ prefix_sum ≤ total_sum
```範囲を左から右にスキャンし、下限のみを満たす最長のサブシーケンスを貪欲に構築するとします。`prefix_sum ≥ 0`。 

毎`1`はいつも便利なので、いつも利用しています。 

のために`-1`、現在の残高がプラスの場合にのみ受け取ります。 

させて```
c1 = number of chosen 1's
c2 = number of chosen -1's
```そしてさせてください```
mx = maximum balance ever reached during this greedy process
```結果のサブシーケンスはプレフィックス条件を満たしますが、上限に違反する可能性があります。`prefix_sum ≤ total_sum`。 

最終的なバランスは次のとおりです。```
c1 - c2
```サブシーケンスを有効にするには、最大残高を以下から減らすだけで済みます。`mx`せいぜいまで`c1 - c2`。 

It can be shown that deleting```
mx - (c1 - c2)
```選択された`-1`構築の最後からの値で常に十分です。 最終的な長さは次のようになります。```
(c1 + c2) - (mx - (c1 - c2))
= 2*c1 - mx
```したがって、答えは以下によってのみ決まります。```
c1 = number of 1's in the range
mx = maximum balance reached by the greedy process
```次の観察は、この貪欲なバランスが次のように進化することです。```
s = max(0, s + a[i])
```それはまさにカダネの再発です。 

値`mx`これまでに到達した最大値です`s`、これは正確に範囲のサブ配列の合計の最大値です。 

したがって：```
answer = 2 * (number of 1's in range) - (maximum subarray sum of range)
```ここで、問題は標準的なセグメント ツリー タスクになります。 以下の範囲クエリが必要です。```
number of 1's
maximum subarray sum
```ポイント更新付き。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとに O(2^m · m) | O(m) | 遅すぎる |
 | セグメントツリー | クエリ/更新ごとに O(log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. セグメントツリーを構築します。 
2. 各ノードストアについて:

 -`num`: の数`1`セグメント内の値。 
-`sum`: セグメントの合計。 
-`pre`: 最大プレフィックス合計。 
-`suf`: サフィックスの合計の最大値。 
-`mx`: 部分配列の合計の最大値。 
3. 葉の場合:

 - 値が`1`、 店：```
num=1, sum=1, pre=1, suf=1, mx=1
```- 値が`-1`、 店：```
num=0, sum=-1, pre=0, suf=0, mx=0
```Kadane スタイルの解釈では空の部分配列が許可されるため、負の値はゼロに寄与します。 
4. 標準の最大部分配列式を使用して 2 つの子をマージします。```
num = left.num + right.num
sum = left.sum + right.sum

pre = max(left.pre, left.sum + right.pre)
suf = max(right.suf, left.suf + right.sum)

mx = max(
    left.mx,
    right.mx,
    left.suf + right.pre
)
```5. フリップ更新の場合は、1 つのリーフを変更し、ルートへのパス上のすべてのノードを再計算します。 
6. 範囲クエリの場合、以下を記述するセグメント ツリー ノードを取得します。`[l, r]`。 
7. 答えは次のとおりです。```
2 * num - mx
```### なぜ効果があるのか

 貪欲な構造がすべてを維持します`1`そして、`-1`そうすることで残高がマイナスになることはありません。 これにより、プレフィックス条件を満たす最長のサブシーケンスが生成されます。 

残る唯一の障害はサフィックス条件です。これは、すべてのプレフィックスの合計が最終残高を下回るようにする必要があることと同じです。 残高が上限に達した場合は、`mx`そして最終的なバランスは`c1 - c2`、その差を縮めなければなりません`mx - (c1 - c2)`。 選択した数を正確に削除する`-1`値が十分であるため、最終的な長さは`2*c1 - mx`。 

貪欲なバランスのプロセスはカダネの再発と同じなので、`mx`範囲の最大サブ配列合計に等しい。 セグメント ツリーは、更新後にこの値を計算するために必要な数量を正確に維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("num", "sum", "pre", "suf", "mx")

    def __init__(self, num=0, sm=0, pre=0, suf=0, mx=0):
        self.num = num
        self.sum = sm
        self.pre = pre
        self.suf = suf
        self.mx = mx

def merge(a, b):
    res = Node()
    res.num = a.num + b.num
    res.sum = a.sum + b.sum
    res.pre = max(a.pre, a.sum + b.pre)
    res.suf = max(b.suf, a.suf + b.sum)
    res.mx = max(a.mx, b.mx, a.suf + b.pre)
    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.arr = arr
        self.st = [Node() for _ in range(4 * self.n)]
        self.build(1, 0, self.n - 1)

    def make_leaf(self, v):
        if v == 1:
            return Node(1, 1, 1, 1, 1)
        return Node(0, -1, 0, 0, 0)

    def build(self, p, l, r):
        if l == r:
            self.st[p] = self.make_leaf(self.arr[l])
            return

        m = (l + r) // 2
        self.build(p * 2, l, m)
        self.build(p * 2 + 1, m + 1, r)
        self.st[p] = merge(self.st[p * 2], self.st[p * 2 + 1])

    def update(self, p, l, r, idx):
        if l == r:
            self.arr[idx] *= -1
            self.st[p] = self.make_leaf(self.arr[idx])
            return

        m = (l + r) // 2
        if idx <= m:
            self.update(p * 2, l, m, idx)
        else:
            self.update(p * 2 + 1, m + 1, r, idx)

        self.st[p] = merge(self.st[p * 2], self.st[p * 2 + 1])

    def query(self, p, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.st[p]

        m = (l + r) // 2

        if qr <= m:
            return self.query(p * 2, l, m, ql, qr)

        if ql > m:
            return self.query(p * 2 + 1, m + 1, r, ql, qr)

        left = self.query(p * 2, l, m, ql, qr)
        right = self.query(p * 2 + 1, m + 1, r, ql, qr)
        return merge(left, right)

n, q = map(int, input().split())
a = list(map(int, input().split()))

seg = SegTree(a)

ans = []

for _ in range(q):
    parts = list(map(int, input().split()))

    if parts[0] == 1:
        pos = parts[1] - 1
        seg.update(1, 0, n - 1, pos)
    else:
        l, r = parts[1] - 1, parts[2] - 1
        node = seg.query(1, 0, n - 1, l, r)
        ans.append(str(2 * node.num - node.mx))

sys.stdout.write("\n".join(ans))
```The segment tree node is exactly the classic maximum-subarray node. 唯一の追加フィールドは、`num`、いくつ数えますか`1`値がセグメントに表示されます。 

マージ操作は、Kadane セグメント ツリーのマージと同じです。 最大の部分配列は、左側の子に完全に存在することも、右側の子に完全に存在することも、境界を越えることもできます。`left.suf + right.pre`。 

のための葉`-1`用途`pre = suf = mx = 0`。 これは、最適なサブ配列が空であってもよい標準的な定式化です。 この詳細が欠けていると、負の値のみを含む範囲の答えが変わります。 

最終的な式`2 * node.num - node.mx`クエリされたセグメントに直接適用されます。

 ## 特殊なケース

 次のことを考慮してください。```
1
-1
```唯一の空ではないサブシーケンスは、`[-1]`。 プレフィックスの合計が負であるため、無効です。 アルゴリズムは以下を保存します。```
num = 0
mx = 0
```そして次を返します:```
2 * 0 - 0 = 0
```これは正解と一致します。 

次に、次のことを考えてみましょう。```
3
1 1 -1
```プレフィックスの合計のみをチェックするソリューションでは、3 つの要素すべてが保持されます。 のみで構成されるサフィックス`-1`が負なので、その後のシーケンスは良くありません。 

範囲のセグメント データは次のようになります。```
num = 2
mx = 2
```答えは次のようになります。```
2 * 2 - 2 = 2
```それはまさに正しい美しさです。 

最後に、次のことを考慮してください。```
3
1 1 1
```ありません`-1`まったく価値観。 すべてのプレフィックスとサフィックスの合計は正です。 ツリーは次のように報告します。```
num = 3
mx = 3
```それで：```
2 * 3 - 3 = 3
```そして配列全体が選択されます。
