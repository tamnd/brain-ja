 ## 解決策
 ## 問題の理解

 すでにアルファベット順に書かれている、個別の小文字で構成される有限のアルファベットと、すべての文字がそのアルファベットに属するクエリ文字列が与えられます。 クエリ文字列からのレーベンシュタイン距離がちょうど 1 である、すべての個別の文字列を構築する必要があります。 

距離が 1 の場合は、基本的な編集が 1 つだけで十分であることを意味します。 任意の位置に 1 つのアルファベット文字を挿入したり、既存の 1 文字を削除したり、1 つの文字を別のアルファベット文字に置き換えたりすることができます。 元の文字列自体は、それ自体からの距離がゼロであるため、出力してはなりません。 結果の文字列は、重複を削除して辞書順に出力する必要があります。 

クエリ文字列の長さは 2 ～ 100 です。アルファベットには明確な小文字のみが含まれるため、最大 26 文字になります。 これらの境界は小さいです。 考えられるすべての編集を個別に生成したとしても、候補は数千しかありません。 すべての候補に対する二次アルゴリズムは不要ですが、候補数自体が十分に小さいため、直接構築することが自然な解決策となります。 

主なエッジケースは重複生成に起因します。 たとえば、入力の場合```
a
aa
```正しい出力は```
aaa
a
```挿入する`a`最初の文字の前、2 つの文字の間、または 2 番目の文字の後には常に次の文字が生成されます。`aaa`したがって、すべての操作を個別に出力する不注意な実装では、同じ文字列が 3 回出力されてしまいます。 いずれかの出現箇所を削除すると、`a`同じ文字列を生成します`a`、別の複製が作成されます。 

2 番目のケースは置換です。 と```
ab
aa
```どちらかを置き換える`a`による`b`生成する`ba`、2 番目の文字を置き換えると、次のような結果も生成されます。`ab`。 より一般的には、編集位置が異なっていても結果として同じ文字列が得られる可能性があるため、重複排除は使用された操作のみに基づくのではなく、候補を生成した後に実行する必要があります。 

アルファベットには 1 文字を含めることもできます。 例えば、```
a
aa
```使用できる別の文字がないため、置き換える可能性はまったくありません。 挿入と削除については引き続き考慮する必要があります。 すべての位置に置換があると想定する実装では、元の文字列を生成するか、存在しない代替文字にアクセスします。 

## アプローチ

 最も直接的なアプローチは、すべての正当な編集を列挙し、結果の文字列をコレクションに入れることです。 (n+1) 個の挿入位置のそれぞれについて、(k) 個のアルファベット文字をすべて試します。 (n) 個の位置ごとに、その文字を削除して得られる文字列を生成します。 最後に、すべての位置について、現在のアルファベットとは異なるすべてのアルファベット文字を試し、(n(k-1)) 個の置換候補を与えます。 

したがって、生成される候補の数は次のようになります。 

[
 (n+1)k+n+n(k-1)=2nk+k。 
]

 最大値 (n=100) および (k=26) では、これは単なる

 [
 2\cdot100\cdot26+26=5226
 ]

 候補者たち。 各候補の長さは最大 101 なので、すべての候補を構築するのに必要な文字数は数十万文字だけです。 

単純な実装では、すべての候補をリストに生成し、文字列を繰り返し比較して重複を削除できます。 それは正しいです。すべての可能な距離 1 の演算が明示的に考慮されますが、ペアごとの比較による重複の削除には (O(C^2 n)) がかかる可能性があります。ここで、(C) は生成される候補の数です。 (C) 約 5000 では、これはすでに何百万もの文字列比較を行うことになり、不必要にコストがかかります。 

重要な観察は、この問題では操作のカウントを求めていないということです。 結果として得られる一意の文字列を要求します。 ハッシュ セットは、まさにその要件に必要なデータ構造です。 すべての正当な結果を一度生成し、それをセットに挿入し、ハッシュによってすべての重複を自動的に折りたたむことができます。 生成後、セットをリストに変換して並べ替えると、必要な辞書順が得られます。 

したがって、強引なアイデアが解決策の基礎であり続けます。 改善点は、編集を列挙することを避けることではありません。これよりも複雑な編集を正当化するには編集が少なすぎるためです。 改善点は、重複排除を効率的に実行する方法で回答のコレクションを表現することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ペアごとの重複削除によるブルート フォース | (O(C^2 n + C\log C)) | (O(Cn)) | 正しいが不必要に遅い |
 | ハッシュ セットを使用して生成および重複排除する | (O(nk\cdot n + C\log C)) | (O(Cn)) | 承認済み |

 ここで (C=2nk+k)、(n\le100) と (k\le26) では、両方の境界は十分に小さいです。 

## アルゴリズムのチュートリアル

 1. アルファベットとクエリ文字列を読みます。 (n) をクエリの長​​さ、(k) をアルファベットのサイズとする。 挿入または置換されるすべての文字はこのアルファベットに由来する必要があるため、これら 2 つの文字列は利用可能な編集を完全に記述します。 
2. という空のセットを作成します。`answers`。 セットが使用されるのは、異なる編集によってまったく同じ文字列が生成される可能性があり、必要な出力には各文字列が 1 回だけ含まれるためです。 
3. あらゆるポジションについて、`0`を通して`n`、その位置にすべてのアルファベット文字を挿入します。 長さ (n) の文字列には、最初の文字の前のギャップと最後の文字の後のギャップを含む (n+1) 個のギャップがあります。 
4. すべての文字位置について、その文字を削除し、結果の文字列をセットに挿入します。 すべての削除には 1 コストがかかるため、これらはまさに考えられるすべての削除結果です。 
5. すべての文字位置について、現在のアルファベットを除くすべてのアルファベット文字を試し、その文字に置き換えます。 文字を単独で置換すると編集が行われず、元のクエリ文字列が誤って導入されてしまうため、現在の文字をスキップする必要があります。 
6. セットをリストに変換し、辞書順に並べ替えます。 アルファベット自体はすでに順序付けされていますが、生成される文字列の長さと編集位置は異なるため、最終的な順序を生成順序から確実に取得することはできません。 
7. ソートされたリスト内のすべての文字列をそれぞれの行に出力します。 2 つの編集シーケンスで同じ文字列が生成された場合、セットはすでに重複を削除しています。 

### なぜ効果があるのか

 距離がちょうど 1 のすべての文字列は、3 つの操作 (1 回の挿入、1 回の削除、または 1 回の置換) のいずれかによって取得可能でなければなりません。 このアルゴリズムは、3 つの操作すべてのすべての正当なインスタンスを明示的に列挙するため、有効な答えが見逃されることはありません。 

挿入ループでは、すべての可能な位置とすべてのアルファベット文字が考慮されます。 削除ループでは、既存のすべての文字が考慮されます。 置換ループでは、すべての位置とすべての異なるアルファベット文字が考慮されます。 したがって、生成された候補の中には、可能なすべての 1 編集変換が表示されます。 

このセットは、異なる文字列ではなく、等しい文字列のみを削除します。 元の文字列は有効な挿入または削除によって生成されることはなく、置換によって現在の文字が意図的に除外されるため、残りのすべての要素の距離は正確に 1 になります。 並べ替えによって変更されるのは表示順序のみであるため、最終出力は正確に辞書順の必要な文字列のセットになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(data: str) -> str:
    lines = data.splitlines()
    alphabet = lines[0].strip()
    s = lines[1].strip()

    n = len(s)
    answers = set()

    # Insert one alphabet character at every possible position.
    for i in range(n + 1):
        left = s[:i]
        right = s[i:]
        for ch in alphabet:
            answers.add(left + ch + right)

    # Delete one character.
    for i in range(n):
        answers.add(s[:i] + s[i + 1:])

    # Replace one character by a different alphabet character.
    for i in range(n):
        for ch in alphabet:
            if ch != s[i]:
                answers.add(s[:i] + ch + s[i + 1:])

    return "\n".join(sorted(answers))

def main():
    data = sys.stdin.read()
    sys.stdout.write(solve(data))

if __name__ == "__main__":
    main()
```最初の 2 つの入力行は、アルファベットとクエリ文字列として読み取られます。 テストケースの数がないため、入力全体を一度に使用できます。 

挿入ループは次を使用します。`range(n + 1)`長さ (n) の文字列には (n+1) 個の挿入ギャップがあるためです。 表現`s[:i] + ch + s[i:]`インサート`ch`元の文字列を変更せずに。 

削除式`s[:i] + s[i + 1:]`位置にある文字を正確に削除します`i`。 また、スライス エラーの一般的な原因である最初と最後の位置も自然に処理されます。 

置換の条件としては、`ch != s[i]`は不可欠です。 これがないと、元のクエリ文字列が`answers`たとえそれ自体からのレーベンシュタイン距離がゼロであっても。 

Python 文字列は不変であるため、操作ごとに新しい文字列が作成されます。 生成される候補は最大 5226 個で、各候補の長さは最大 101 であるため、ここではこれで完全に適切です。Python の整数は計算に関連しないため、オーバーフローの懸念はありません。 

決勝戦`sorted(answers)`問題が必要とする通常の辞書編集上の文字列順序を与えます。
