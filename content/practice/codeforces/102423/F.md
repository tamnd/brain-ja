 ## 解決策
 ## 問題の理解

 地球の周りには (N) 個の星があります。 各星 (i) について、3 つの値が宇宙船の移動距離への寄与を表します。 星は理想的には方向 (a_i) と整列しており、最大の寄与 (T_i) を与え、打ち上げ方向が (a_i) から遠ざかるラジアンごとに (s_i) 単位の移動距離を失います。 角距離は円形であるため、角度 (0) をわずかに超えて移動することは、(2\pi) のわずかに前に移動することと同じです。 

選択された発射方向が (x) の場合、星 (i) が寄与します

 [
 f_i(x)=\max(0,T_i-s_i\演算子名{距離}(a_i,x))。 
】

 合計距離はこれらすべての寄与の合計であり、1 回転にわたる最大距離が必要です。 入力には最大 (10^5) 個の星が含まれ、小数点以下最大 6 桁の実数値パラメータが含まれます。 必要な数値誤差は (10^{-6}) です。 

境界 (N\le 10^5) により、多くの候補方向を試したり、方向ごとにすべての星を評価したりすることが直ちに除外されます。 星ごとに 3 つの特別な方向だけを考慮したとしても、最悪の場合の評価はすでに約 (3N^2)、約 (3\cdot10^{10}) になることになります。 数十万のイベントを並べ替えることが作業の大半を占め、5 秒間のコンテスト制限に簡単に適合するため、(O(N\log N)) に関する解決策が適切です。 

直接実装では誤って処理される可能性のあるエッジケースがいくつかあります。 (s_i=0) の場合、星はあらゆる方向に (T_i) を寄与します。 例えば、```
1
5 0 1
```答えがあります```
5.000000
```(T_i/s_i) を常にゼロで割る計算を行う不注意な実装。 

2 番目の問題は、円形の境界です。 考慮する```
2
1 1 0
1 1 6.183185
```2 番目の角度は (2\pi-0.1) に近いため、2 つの有用な領域は (0/2\pi) の境界を越えてオー​​バーラップします。 最大値はおよそ```
1.900000
```角度間隔を通常の間隔として扱い、ラップしない実装では、この重複が見逃されます。 

3 番目の特殊なケースは、星が少なくとも半円活動し続けるときに発生します。 例えば、```
2
10 1 0
10 1 3.141593
```おおよその答えがあります```
16.858407
```半径 (T_i/s_i) は (\pi) より大きいため、円の周囲で寄与がゼロになることはありません。 アクティブ領域を半径 (T_i/s_i) の通常の三角形として扱うと、円の距離が方向を変える点を超えて誤って拡張されてしまいます。 

最後に、いくつかの星がまったく同じ優先角度を持つことができます。 例えば、```
3
5 1 1
5 1 1
5 1 1
```答えがあります```
15.000000
```すべての微分変化は同じ座標で発生します。 イベントを個別に処理するのは問題ありませんが、実装ではすべてのイベント座標が一意であると想定してはなりません。 

## アプローチ

 直接的なアプローチは、候補となる方向を特定し、それぞれの方向での合計の寄与を評価することです。 各星の寄与は、その優先方向とその寄与がゼロになる 2 つの方向で式を変更します。 これにより、(O(N)) 個の方向候補が得られます。 すべての候補で個別に合計貢献度を評価するには、(O(N)) 個の作業が必要となり、(O(N^2)) 個の時間がかかります。 (N=10^5) の場合、最悪の場合はおよそ (10^{10}) 個の星評価となり、5 秒の制限をはるかに超えます。 

すべての個々の寄与が区分的に線形であるため、ブルート フォースが機能します。 失敗の原因は、合計を最初から繰り返し再計算することです。 

重要な観察は、全体の合計も区分的に線形であるということです。 いくつかの星が傾きを変える 2 つの連続する点の間では、すべての星は固定された線形公式を持ち、したがって合計関数も同様に固定された傾きを持ちます。 ある区間の線形関数は、いずれかの端点で最大値に達します。 角度が回転するにつれて傾きがどのように変化するかを知る必要があるだけです。 

有効角半径が次のような星の場合、

 [
 d=\min\left(\pi,\frac{T_i}{s_i}\right),
 】

 その寄与は、(a_i-d) から (a_i) まで傾き (+s_i) で上昇し、その後、(a_i) から (a_i+d) まで傾き (-s_i) で低下します。 したがって、導関数は次のように変化します。 

[
 +s_i,\quad -2s_i,\quad +s_i
 】

 その3つの位置で。 

唯一の問題は、(0) と (2\pi) にある円形の境界です。 これを処理するには、ラップされたエンドポイントを区間 ([0,2\pi]) に戻し、それに応じて初期導関数を調整します。 これにより、非定常星ごとに 3 つのイベントのみが提供されます。 

結果として得られるアプローチは、傾斜変化イベントに対する標準的なスイープです。 まず角度 (0) での合計値を計算し、角度 (0) の直後の微分値の合計を計算し、すべての微分変化イベントを並べ替えてから、あるイベントから次のイベントへの現在の傾きを積分します。 

同じ区分的線形イベントのアイデアは、このコンテストの問題の受け入れられた解決策にも反映されており、各星をその左端点、ピーク、右端点で表し、(0) と (2\pi) と交差する区間を明示的に処理します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^2)) | (O(N)) | 遅すぎる |
 | 最適 | (O(N\log N)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (s_i=0) のすべての星について、(T_i) を現在の値に直接加算します。 その寄与は決して変化しないため、派生イベントは生成されません。 
2. 1 つおきの星について、計算します。 

[
 d_i=\min\left(\pi,\frac{T_i}{s_i}\right)。 
】

 (\pi) を使用した最小値は、円周距離を正しく処理します。 最短角距離は (\pi) を超えることはできないため、(T_i/s_i\ge\pi) になると、寄与はどこでも正のままとなり、関連する傾きの変化が優先方向とその対蹠点で発生します。 

1. 発射角 (0) でのこの星の寄与を計算し、実行値に追加します。 (a_i) から (0) までの円周距離は単純に (\min(a_i,2\pi-a_i)) です。 
2. 3 つのイベント位置を定義します

 [
 l=a_i-d_i、\qquad m=a_i、\qquad r=a_i+d_i。 
】

 (l) では、導関数は (+s_i) だけ変化します。 (m) では、導関数は (-2s_i) だけ変化します。 (r)では(+s_i)で変化します。 

1. (l<0) の場合、イベントがスイープ間隔内に収まるように (2\pi) を追加します。 この間隔は角度 (0) と交差するため、星は角度 (0) の直後にすでに上昇側にあるため、初期導関数に (s_i) を追加します。 
2. (r>2\pi) の場合、そこから (2\pi) を引きます。 寄与は角度 (0) の直後ですでに下降側にあるため、初期導関数から (s_i) を減算します。 

厳密な不平等が重要です。 エンドポイントが正確に (0) または (2\pi) である場合、それはすでに境界にあるイベントであり、ラップされた間隔を表しません。

1. すべてのイベントを角度ごとに並べ替えます。 2 つの連続するイベント間では、傾きが変化する星は存在しないため、合計関数は直線になります。 
2. 角度 (0) の合計値、初期導関数、および前の角度 (0) から開始します。 角度 (x) の各イベントについて、値を次のように進めます。 

[
 \text{値} \mathrel{+}= \text{傾き}\cdot(x-\text{前の角度})。 
】

 次に、イベントの派生変更を適用し、最適な値を更新します。 

1. 見つかった最大値を返します。 この関数は周期的であり、角度 (2\pi) は角度 (0) と同じ方向であるため、初期位置とすべての導関数変更位置をチェックすると円全体がカバーされます。 

### なぜ効果があるのか

 各星について、(T_i/s_i) を (\min(\pi,T_i/s_i)) に置き換えた後、その寄与は、その左側の境界、優先角度、および右側の境界の間のすべての間隔で線形になります。 したがって、その導関数はこれら 3 つのイベント間で一定です。 

すべてのスターの合計も、連続するグローバル イベント間では直線的です。 線形関数は厳密な内部最大値を持つことができないため、グローバル最大値は角度 (0) またはイベント座標で発生する必要があります。 スイープは、現在の合計傾きを積分し、微分変化を適用することにより、そのような座標ごとに正確な関数値を維持します。 したがって、スイープによって記録された最大値は、正確に最大移動距離となります。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

PI = math.pi
TWO_PI = 2.0 * math.pi

def solve():
    n = int(input())

    events = []
    cur = 0.0
    initial_slope = 0.0

    for _ in range(n):
        t, s, a = map(float, input().split())

        if s == 0.0:
            cur += t
            continue

        # The angular contribution can never depend on a distance
        # larger than pi.
        d = min(PI, t / s)

        # Contribution at angle 0.
        dist0 = min(a, TWO_PI - a)
        cur += max(0.0, t - s * dist0)

        left = a - d
        right = a + d

        # If the active interval crosses 0, its rising segment
        # is already active immediately after angle 0.
        if left < 0.0:
            left += TWO_PI
            initial_slope += s

        # If the active interval crosses 2*pi, its falling segment
        # is already active immediately after angle 0.
        if right > TWO_PI:
            right -= TWO_PI
            initial_slope -= s

        events.append((left, s))
        events.append((a, -2.0 * s))
        events.append((right, s))

    if not events:
        print(f"{cur:.6f}")
        return

    events.sort()

    best = cur
    slope = initial_slope
    previous = 0.0

    for angle, delta in events:
        cur += slope * (angle - previous)
        best = max(best, cur)

        slope += delta
        previous = angle

    print(f"{best:.6f}")

if __name__ == "__main__":
    solve()
```入力ループは、(T_i/s_i) を計算する前に (s_i=0) の場合を分離します。 このようなスターは定数 (T_i) を提供するため、イベントを保存しても時間の無駄になるだけです。 

非定常星の場合、`dist0 = min(a, TWO_PI - a)`方向 (0) からの最短角距離を計算します。 これにより、スイープの開始時に対物レンズ全体の正確な値が初期化されます。 

3 つのイベント エントリは、派生的な変更をエンコードします。 左の終点は上昇セグメントを開始し、優先角度は導関数を (+s_i) から (-s_i) に変更し、右の終点は導関数をゼロに戻します。 そのため、デルタは (+s_i)、(-2s_i)、および (+s_i) になります。 

ラッピングの調整は微妙な部分です。 左端点が負の場合、星の上昇セグメントは角度 (0) と交差するため、初期導関数にはすでに (+s_i) が含まれています。 右端点が (2\pi) を超える場合、下降セグメントは境界を越えるため、初期導関数には (-s_i) が含まれます。 

スイープでは、目的を再計算する代わりに導関数を積分します。 表現`cur += slope * (angle - previous)`は、まさにその区間にわたる一次関数の値の変化です。 派生的な変更はイベント座標に到達した後にのみ適用されるため、ブレークポイント自体での off-by-one スタイル エラーが回避されます。 

パイソンの`float`ここでは十分です。 入力の小数点以下の桁数は最大 6 桁で、必要な応答許容誤差は (10^{-6}) です。 最大合計寄与度は最大でも (10^8) ですが、通常の倍精度演算で十分な絶対精度が得られる精度の範囲内に十分収まります。 元のステートメントでは、同じ (10^{-6}) 出力許容誤差を指定しています。
