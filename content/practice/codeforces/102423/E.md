 ## 解決策
 ## 問題の理解

 サイズ n の順列により、数値 1、…、n が再配置され、すべての数値が 1 回だけ出現します。 位置 i は、そこに配置される値も i である場合、固定小数点です。 このタスクは、n、必要な固定点の数 m、およびランク k を与え、正確に m 個の固定点を持つすべての置換のうち、辞書編集順で k 番目の置換を要求します。 このような順列が k 個よりも少ない場合、次のように出力します。`-1`。 公式の制限は 1≤n≤50、0≤m≤n、1≤k≤10 18 で、制限時間は 1 秒です。 

n の小さな値は欺瞞的です。 n=50 であっても、50!≈3.04×10 64 個の順列が存在するため、順列を列挙することは完全に不可能です。 ランク k の上限は 10 18 です。これは、10 18 を超えるカウントを区別する必要がないことを意味します。O(n 3 ) 付近の解は簡単に十分に小さくなりますが、n の階乗または指数関数は除外されます。 

表面的に合理的な実装が失敗する可能性がある境界ケースがいくつかあります。 のために`1 1 1`、唯一の順列は`1`、したがって、答えは次のとおりです`1`。 再配置する位置が少なくとも 2 つ必要であると想定する実装では、このケースが誤って拒否される可能性があります。 

のために`3 2 1`、答えは`-1`。 2 つの固定点では 1 つの位置と 1 つの値だけが残るため、最終的な位置も強制的に固定されます。 したがって、n>1 の場合、正確に n-1 個の固定点は不可能です。 単純に m 個の固定位置を選​​択し、他のすべてを並べ替える式では、追加の固定点を含む配置を誤ってカウントする可能性があります。 

のために`3 0 3`、答えは`-1`。 3つの要素の2つの乱れは、`231`そして`312`したがって、ランク 3 を要求することは、利用可能なセットを超えています。 値を選択する前にブロック全体をカウントしない貪欲な構造は、無効な分岐に入り、要求されたランクが存在しなかったことを知らずに最終的に失敗する可能性があります。 

3つ目のサンプルは、`5 3 7`、もう 1 つの有用な境界ケースです。 その答えは、`2 1 3 4 5`。 最初の 6 つの有効な置換は次で始まります。`1`、7番目はで始まります`2`。 候補が完了した回数をカウントするのではなく、候補が完了できるかどうかのみをチェックする貪欲なアルゴリズムでは、このランクを正しく決定できません。 公式サンプルは、`3 1 1 -> 1 3 2`、`3 2 1 -> -1`、 そして`5 3 7 -> 2 1 3 4 5`。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 1、…、n のすべての順列を生成し、その固定小数点を数え、正確に m のものを保持し、辞書順に並べ替えて、k 番目のものを取得します。 これは正しいです。考えられるすべての順列が考慮され、最終的な順序がまさに必要な順序になるからです。 問題は順列の数です。 最悪の場合、それらの生成とチェックには約 n⋅n かかります。 基本的な位置チェック。 n=50 の場合、これはおよそ 50⋅50!≈1.52×10 66 チェックであり、実際的な制限をはるかに超えています。 

有益な観察は、有効な順列をすべて構築する必要はないということです。 答えの次の要素を決定するには、考えられる次の値のそれぞれに有効な補完がいくつあるかを知る必要があるだけです。 最小の候補が k 未満の有効な置換を占める場合、そのブロック全体をスキップして k を減らすことができます。 それ以外の場合は、その候補者が回答の一部である必要があります。 

残りの問題は、これらの完了を効率的にカウントする方法です。 プレフィックスが修正されると、残りの一部の位置は引き続き独自の値を受け取ることができますが、他の位置はその値がすでに使用されているために受け取ることができません。 q を残りの位置の数とし、r を独自の値もまだ利用可能な残りの位置の数とします。 これらの r 位置は、新しい固定点が発生できる唯一の場所です。 3 次元動的計画法の漸化式を使用して、この還元された状態の順列を数えることができます。 

繰り返しは、利用可能な独自の値をまだ持っている r 位置の 1 つを選択することに基づいています。 独自の値を受け取る場合は、1 つの固定点を作成します。 それ以外の場合、その値は他の場所から取得される必要があります。 その代替値は、別の特別な位置に属し、その位置が固定される可能性を破壊するか、または特別でない位置に属します。 

すべての順列をチェックすると最終的に答えが見つかるため、総当り攻撃は機能しますが、階乗数が多いため失敗します。 残りの位置と残りの可能な固定小数点のペアの数のみが重要であるという観察により、計数の問題は O(n 3 ) に削減され、その後、辞書編集的なアンランキングが別の O(n 2 ) 状態遷移をとります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん⋅ん!) | 保存された回答以外の O(n) | 遅すぎる |
 | 最適 | O(n 3 ) | O(n 3 ) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 定義する`dp[q][r][t]`q 個の位置と q 個の値が残っている場合に部分順列を完了する方法の数として、それらの位置のうち正確に r 個にはまだ利用可能な独自の値があり、残りの位置には正確に t 個の固定点が必要です。 

3 番目のパラメーターは、既に構築された合計数ではなく、まだ必要な固定点の数です。 これにより、DP が特定のプレフィックスから独立したものになります。 
2. 次のコマンドで空の状態を初期化します。`dp[0][0][0] = 1`。 ポジションが残っていない場合、あと 0 個の固定点が必要な場合、有効な完了は 1 つだけです。 
3. 状態を処理します。`r = 0`別に。 残りの位置は固定されないため、可能なターゲットは次のとおりです。`t = 0`。 残りの q 値のすべての順列は有効であり、次のようになります。`q!`完成品。 
4. の状態の場合`r > 0`、利用可能な独自の値がまだあるポジションの 1 つを選択します。 可能性は 3 つあります。 

その位置が独自の値を受け取ると、1 つの固定点が作成されます。 新しい状態は`(q-1, r-1, t-1)`。 

別の特別な位置の独自の値を受け取る場合は、`r-1`選択肢。 選択した値が消えるため、対応する位置を固定できなくなり、選択した位置自体も消えます。 新しい状態は`(q-1, r-2, t)`。 

特別でない値を受け取った場合は、`q-r`選択肢。 選択した特別な位置のみが消え、`(q-1, r-1, t)`。 

したがって、再発は、

 dp[q][r][t]=dp[q−1][r−1][t−1]+(r−1)dp[q−1][r−2][t]+(q−r)dp[q−1][r−1][t]。 
5. すべての DP 値の上限を 10 18 に設定します。最大値が 10 18 である k とカウントを比較するだけなので、10 18 とそれよりもはるかに大きな数を区別しても、答えには影響しません。 キャッピングにより、演算も小さく抑えられます。 
6. 位置 1 から答えの構築を開始します。最初はすべての値が未使用であるため、n 個の位置はすべて固定小数点位置として使用できます。 セット`r = n`そして`fixed = 0`。 
7. 現在の位置 i で、すべての未使用の値 v を昇順に試します。 この順序はまさに辞書編集に必要なものです。 
8. v を選択することを一時的に想像してください。v=i の場合、追加の固定点が 1 つ作成され、可能な固定ペアの数は 1 つ減少します。 

v  =i の場合、現在位置が消失するため、考えられる 1 つの固定ペアが失われます。 v>i の場合、値 v は将来の位置に属しており、これも削除され、別の可能な固定ペアが失われます。 したがって、

 r ' =r−1−[v>i]

 v  =i の場合、v=i の場合、r ' =r−1 となります。 
9. しましょう`need`v を選択した後にまだ必要な固定点の数です。残りの n-i 位置について DP 状態をクエリします。 そのカウントが k より小さい場合、この候補で始まるすべての順列は目的の答えの前に来るため、k からカウントを減算して次の値を試します。 
10. カウントが少なくとも k の場合、v にコミットし、使用される値セット、固定小数点カウント、および`r`、次の位置に進みます。 
11. 希望のランクを含む候補がない場合、出力`-1`。 実際には、これは初期段階からすでに検出できます。`dp[n][n][m]`カウント。 

重要な不変条件は、位置 i を処理する前に、`r`独自の値がまだ利用可能な残りの位置を正確にカウントするため、それらの位置だけが固定点になることができます。 DP は、1 つの特別な位置に割り当てられた値を考慮して、その縮小状態の完了を 1 回だけカウントします。 貪欲な構築中、スキップされたすべての候補は、サイズが正確にわかっている完全な辞書編集ブロックを表すため、そのサイズを減算すると、残りのサフィックス内の目的のランクとして k の解釈が保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LIMIT = 10**18

def solve_case(n, m, k):
    # dp[q][r][t]:
    # q remaining positions,
    # r positions whose own values are still available,
    # t fixed points still required.
    dp = [[[0] * (n + 1) for _ in range(n + 1)]
          for _ in range(n + 1)]

    dp[0][0][0] = 1

    # States with r = 0 have no possible fixed points.
    for q in range(1, n + 1):
        dp[q][0][0] = min(LIMIT, q * dp[q - 1][0][0])

    for q in range(1, n + 1):
        for r in range(1, q + 1):
            for t in range(0, q + 1):
                value = 0

                # The chosen special position becomes fixed.
                if t >= 1:
                    value += dp[q - 1][r - 1][t - 1]

                # It receives the own value of another special position.
                if r >= 2:
                    value += (r - 1) * dp[q - 1][r - 2][t]

                # It receives a value belonging to a nonspecial position.
                if q > r:
                    value += (q - r) * dp[q - 1][r - 1][t]

                dp[q][r][t] = min(LIMIT, value)

    if dp[n][n][m] < k:
        return "-1"

    used = [False] * (n + 1)
    answer = []

    r = n
    fixed = 0

    for i in range(1, n + 1):
        remaining = n - i

        for v in range(1, n + 1):
            if used[v]:
                continue

            is_fixed = (v == i)
            new_fixed = fixed + is_fixed

            if is_fixed:
                new_r = r - 1
            else:
                new_r = r - 1 - (v > i)

            need = m - new_fixed

            if need < 0 or need > remaining:
                ways = 0
            elif new_r < 0 or new_r > remaining:
                ways = 0
            else:
                ways = dp[remaining][new_r][need]

            if ways < k:
                k -= ways
                continue

            answer.append(v)
            used[v] = True
            fixed = new_fixed
            r = new_r
            break

    return " ".join(map(str, answer))

def main():
    n, m, k = map(int, input().split())
    print(solve_case(n, m, k))

if __name__ == "__main__":
    main()
```DP は順列が構築される前に構築されます。 の`r = 0`行は直接処理されます。これは、固定点が不可能な場合、それ以上の固定点が要求されない限り、残りのすべての置換が受け入れられ、階乗再帰が得られるためです。 

のために`r > 0`、3 つの項は再発の 3 つのケースに正確に対応します。 周囲の境界線`r - 2`、`t - 1`、残りの位置により、無効な状態へのアクセスやカウントが防止されます。 

工事中は、`used[v]`どの値がすでに出現しているかを記録します。 のアップデート`r`微妙です。 いつ`v == i`、現在の固定ペアは 1 回だけ消滅します。 いつ`v != i`、現在の位置が修正される可能性が失われ、`v > i`、その価値が消費されたばかりであるため、それ自体の将来のポジションもチャンスを失います。 だからこそこの表現は、`r - 1 - (v > i)`。 

Python の整数はオーバーフローしませんが、そのしきい値を超えるすべてのカウントはランク比較に等しいため、10 18 の上限は依然として役立ちます。 DP は残りの位置の数に 0 から始まるストレージを使用しますが、順列自体の位置は 1 から始まります。 これら 2 つの概念を分離しておくことで、このソリューションで最も一般的な off-by-one エラーを回避できます。

 |`3 0 3`|`-1`| ランクが有効な順列の数を超えています。 
|`50 50 1`|`1 2 ... 50`| 最大 n、すべての位置は固定 |
 |`5 4 1`|`-1`| 正確に n−1 個の固定点は不可能です。 

## 特殊なケース

 のために`1 1 1`、初期状態は`dp[1][1][1] = 1`。 唯一の候補は値です`1`、必要な固定点を作成し、状態を終了します。`(0,0,0)`。 DP は 1 つの完了を報告するため、答えは次のようになります。`1`。 正しい基本ケースを超えるシングルトンの置換には特別な処理は必要ありません。 

のために`3 2 1`、初期状態`dp[3][3][2]`はゼロです。 反復は構造的な理由を自動的に捉えます。2 つの固定点が作成されると、残りの位置には代替値がなく、同様に固定されます。 その結果、アルゴリズムは次のように出力します。`-1`順列を構築しようとする前に。 

のために`3 0 3`、初期の DP カウントは 2 で、これに対応します。`2 3 1`そして`3 1 2`。 要求されたランクは 3 であるため、`2 < 3`、アルゴリズムはすぐに報告します`-1`。 この境界は、比較が正しいかどうかを確認する場合に特に役立ちます。`count < k`、 ない`count <= k`。 

のために`5 3 7`、位置 1 の最初の候補は`1`。 その値で始まる有効な補完は 6 つあるため、アルゴリズムは k を 7 から 1 に変更し、プレフィックス全体を拒否します。 候補者`2`有効な補完が 1 つだけあるため、それが選択されます。 残りの州軍`1`2 番目の位置で、`3,4,5`それぞれの立場に就いて、`2 1 3 4 5`。 このケースでは、辞書編集ブロックのスキップと、将来の可能性のある固定小数点の数の更新の両方が実行されます。 

のために`50 50 1`、すべての位置を固定する必要があります。 DP には有効な補完が 1 つだけあり、貪欲なプロシージャはすべての位置で利用可能な最小値を受け入れます。 結果は次の恒等置換です。`1`を通して`50`、許可される最大の n が階乗サイズの動作を導入しないことを確認します。 

のために`5 4 1`、ちょうど 4 つの固定点が強制的に 5 番目の点も固定されます。 DP はこのターゲットに対して 0 を返すため、アルゴリズムは不正な最終配置を試行せずにターゲットを拒否します。 これは、n>1 ごとに m=n−1 が不可能な一般的なケースです。
