 ## 解決策
 ## 問題の理解

 平面内には n 個の異なる点があり、同じ線上に 3 つの点はありません。 風車は、ラインとそのライン上の現在のピボット ポイントで構成されます。 ラインは、最初に別の点に到達するまでピボットを中心に時計回りに回転し、その点が新しいピボットになります。 完全な 360 ° 回転中に、ある点ができるだけ多く昇格されるように、最初のピボットと開始方向を選択したいと考えています。 

主な難しさは、ピボットが変化することです。そのため、1 つの風車を直接シミュレートするには、回転線が次にどの点に到達するかを繰り返し尋ねる必要があります。 考えられるすべての開始状態に対してこれを実行すると、コストがかかりすぎます。 プロセスを確認する便利な方法は、カウントしたい点から見ることです。 そのポイントが昇格されるたびに、風車ラインはそのポイントと他の 1 つのポイントを通過します。 このようなイベントは、その線の両側にある点の数によって完全に特徴付けることができます。 

入力には、10 5 で区切られた座標を持つ最大 2000 個の点が含まれます。O(n 3 ) 解はすでにおおよその性能を発揮します。 

2000⋅1999⋅1998≈7.98×10 9

 幾何学的テストは、10 秒の制限の下では実用的ではありません。 O(n 2 logn) ソリューションは快適です。 この座標は、座標の差が最大 2⋅10 5 であり、積が約 4⋅10 10 になるため、通常の 64 ビット整数の外積で十分であることも意味します。 

重要な微妙なケースがいくつかあります。 

たった 2 点の場合、答えは 1 になります。たとえば、次のようになります。```
2
0 0
1 0
```出力があります```
1
```ピボットとして使用できるポイントは他に 1 つだけであるため、関連するサイクル中にポイントを複数回昇格させることはできません。 

公式サンプルのように、3 つの非共線点の場合、答えは 2 になります。```
3
-1 0
1 0
0 2
```不注意な実装が 1 を取得する可能性がある理由は、2 つの点を通る 1 本の幾何学的な線には 2 つの方向があるためです。 考えられる 2 つのサイド カウントが一致する場合、両方の方向が風車の同じ状態への昇格に寄与するため、寄与はマージされるのではなく 2 回カウントされる必要があります。 

他のすべての点がピボットを通る線の片側にある場合、別の境界ケースが発生します。 このような線は、片側のカウントがゼロである船体の接線構成に対応します。 各側の n/2 ポイントなどのバランスの取れた分割のみを考慮するソリューションでは、これらの風車が見逃され、誤った最大値が生成される可能性があります。 

## アプローチ

 直接的なアプローチは、ピボットを選択し、次のライン イベントを定義する別の点を選択し、そのラインの各側にある点の数を明示的にカウントすることです。 順序付きペアには O(n 2 ) の選択肢があり、両側の点を数えるには O(n) かかります。 これにより、n=2000 で O(n 3 ) 時間、約 8×10 9 の相互積評価が得られます。 考えられるすべての開始構成からすべての完全な風車をシミュレートすることはさらに悪いことになります。 

n の 3 番目の要素を取り除く観察は、点 p を固定すると、関連するすべての線が p を通過するということです。 p を原点に置き、他のすべての点を極角で並べ替えることができます。 p から別の点 q に向かう有向線の場合、その左側の点の数は、角度が次の開いた半円内にあるベクトルの数と正確に一致します。 同一線上にある 3 つの点はないため、その半円の境界上に正確に位置するベクトルは他にありません。 

これは、p を通るすべてのラインのすべてのサイド カウントが 1 回の角度ソートと 2 ポインター スイープで見つかることを意味します。 変化するピボットを明示的にシミュレートする必要はありません。 

有向光線 p→q の厳密に左側に L 個の点があると仮定します。 q と p がピボット ステータスを交換する瞬間、この同じ幾何学的な線の 2 つの可能な方向は、次のような風車の状態に対応します。 

k1 =L+1

 左側の点、または

 k 2 =n−L−2

 左側のポイント。 

風車のラインはスイープ中に指向性を持って回転するオブジェクトであるため、両方の方向が関係します。 k 1 =k 2 の場合、これらは同じ状態に属する 2 つの異なるプロモーション イベントであるため、両方を加算する必要があります。 

したがって、すべてのピボット p に対して、左側の点の数 k によってインデックス付けされた周波数配列を構築します。 1 つおきのポイントは、状態 L+1 に 1 つのプロモーションに寄与し、状態 n-L-2 にもう 1 つのプロモーションに寄与します。 すべての p と k の最大の周波数が、まさに必要な答えになります。 実際の風車への接続は、ピボットが変化しても、方向を向いた線の両側の点の数が固定されたままであるという不変条件です。 したがって、固定 k の場合、角度スイープはその風車状態の促進イベントを正確に列挙します。

 ## アルゴリズムのチュートリアル

1. 1 つの点 p を、現在プロモーションの数を測定している点として固定します。 p が原点となるように座標系を概念的に移動します。 1 つおきの点が p からのベクトルを与えます。 
2. すべてのベクトルの極角を計算し、これらの角度を徐々に並べ替えます。 3 つの入力点が同一線上にないため、同じピボットからの 2 つのベクトルが 180 ∘ を法として同じ方向を持つことはありません。 ここでは浮動小数点角度を安全に使用できますが、ジオメトリ自体は厳密な角度順序のみに基づいています。 
3. すべての要素に 2π を追加して、ソートされた角度配列を複製します。 これにより、循環シーケンスが線形シーケンスに変わります。 元の角度 θ i ごとに、角度が θ i ＋π に達するまでポインタを進めます。 これら 2 つの角度の間に厳密にある点の数は、有向線の左側にある点の数 L です。 
4. このイベントについて、考えられる 2 つの風車の状態を k 1 =L+1 および k 2 =n−L−2 として計算します。 両方の周波数カウンターをインクリメントします。 これらがたまたま等しい場合、同じカウンタを 2 回インクリメントすることは意図的です。これは、2 つの反対方向が完全な回転中の 2 つのプロモーション イベントを表すためです。 
5. 現在のピボットの 1 つおきのポイントを処理した後、そのピボットで得られた最大周波数を取得します。 すべてのポイントに対して同じ手順を繰り返し、グローバル最大値を維持します。 
6. その最大値を出力します。 固定点のすべての昇格は、上記でカウントされた順序付けされたライン イベントの 1 つに対応し、カウントされたすべてのイベントは、サイド カウントによって決定される 1 つの風車状態に正確に属します。 

### なぜ効果があるのか

 点を修正 p. 別の点 q と p が回転線上にあるイベントを考えてみましょう。 有向線 p→q の左側に残っている点の数を L とします。 

風車は、ピボットが変更されたときに、その方向を向いた線の各側の点の数を保持します。 昇格の瞬間に、1 つのポイントが古いピボットとしてラインから離れ、新しく昇格したポイントがその位置を占めるため、サイド カウントは変わりません。 

ラインの 1 つの方向では、プロモートされたポイントがピボット側のポイントを左のカウントに寄与し、L+1 が与えられます。 逆の方向の場合、同じイベントの左側に n-L-2 個の点があります。 これらはまさに、イベントに関連する考えられる 2 つの風車の状態です。 

逆に、p が昇格されるたびに、先行するピボットは q であるため、昇格はライン pq 上で発生します。 イベントは上記の 2 つの方向のいずれかによって表され、スイープによってカウントされます。 したがって、状態 k の頻度は、そのサイド カウントで風車が 1 回転する間に p が昇格する回数と正確に一致します。 すべての p と k の最大値を取ると、答えが得られます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n = int(input())
    points = [tuple(map(int, input().split())) for _ in range(n)]

    answer = 0
    two_pi = 2.0 * math.pi

    for p in range(n):
        px, py = points[p]

        angles = []
        for i in range(n):
            if i == p:
                continue
            x, y = points[i]
            angles.append(math.atan2(y - py, x - px))

        angles.sort()
        m = n - 1

        # Put every angle into [0, 2*pi).
        for i in range(m):
            if angles[i] < 0.0:
                angles[i] += two_pi

        angles.sort()

        extended = angles + [a + two_pi for a in angles]

        freq = [0] * n
        j = 1

        for i in range(m):
            if j <= i:
                j = i + 1

            limit = angles[i] + math.pi

            while j < i + m and extended[j] < limit:
                j += 1

            # Points strictly inside the counterclockwise semicircle.
            left = j - i - 1

            k1 = left + 1
            k2 = n - left - 2

            freq[k1] += 1
            freq[k2] += 1

        cur = max(freq)
        if cur > answer:
            answer = cur

    print(answer)

if __name__ == "__main__":
    solve()
```ピボットごとに、`angles`そのピボットから他のすべての点への方向が含まれています。 [0,2π) への正規化により、複製された配列の推論が容易になり、2 π だけシフトされた 2 番目のコピーは角度ゼロの境界を横切る半円を処理します。 

2 ポインター変数`j`前に進むだけです。 角度がソートされているので、`i`増加しても、半円の終点が後方に移動することはありません。 したがって、次のすべての n−1 値は、`left`はソート後に線形時間で見つかります。 

条件`extended[j] < limit`は厳しいです。 等しいとは、別の点が半円の境界上に正確に存在することを意味し、現在のピボットを通る 1 つの線上に 3 つの点が配置されます。 この問題は、このようなことが決して起こらないことを保証しますが、厳密な比較を使用すると、片側の点の定義とも厳密に一致します。 

表現`left + 1`そして`n - left - 2`プロモートされたポイントと、プロモート中にラインを占める古いピボットを考慮します。 2 つの式が等しい場合もあり、その場合、コードは意図的に同じ周波数を 2 回増加させます。 

角度を計算した後は、座標を含むすべての算術演算が回避されるため、整数のオーバーフローの問題は発生しません。 Python の浮動小数点精度は、2 つのベクトルが同一線上にない場合に整数座標ベクトルの角度を順序付けるのに十分です。

import io
import math

def solve_data(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        # Inline version of the submitted solution.
        n = int(sys.stdin.readline())
        points = [tuple(map(int, sys.stdin.readline().split()))
                  for _ in range(n)]

        answer = 0
        two_pi = 2.0 * math.pi

            angles = []

                if i == p:
                    continue

                angles.append(math.atan2(y - py, x - px))

            angles.sort()

            for i in range(len(angles)):
                if angles[i] < 0.0:
                    angles[i] += two_pi

            angles.sort()

                freq[k2] += 1

            answer = max(answer, max(freq))

        print(answer)
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

1 0
```各ピボットには他の点が 1 つだけあります。 その半円の数は L=0 で、k 1 =1 および k 2 =0 となります。 各状態は 1 つの昇格を受け取るため、答えは 1 になります。アルゴリズムの 2 ポインター スイープは、点を含まない半円に対する特別なケースを必要とせずにこれを処理します。 

3点サンプルの場合```
3
-1 0
1 0
0 2
```ピボット (0,2) には、L=0 のイベントが 1 つあります。 どちらの式も k=1 を生成するため、コードはインクリメントされます。`freq[1]`2回。 これはまさに、実装でプロモーション イベントをカウントするのではなく一連の状態を使用した場合に失われるケースです。 

ハル接線の状況では、一部のイベントは L=n−2 になる可能性があります。 次に、式は k 1 =n−1 および k 2 =0 を与えます。 これらの極端な状態は有効な風車であり、周波数配列に残る必要があります。 k≈n/2 などの中間値に検索を制限すると、凸包で発生する昇格が誤って破棄されてしまいます。 

最大サイズのテストでは、アルゴリズムはすべてのペアワイズ ライン関係を明示的に構築することはありません。 一度に 1 つのピボットを処理し、その n-1 個の角度のみを保存し、複製された角度配列を通じて 1 つのポインターを進めます。 総作業量は O(n 2 logn) のままです。これが、n=2000 のケースが実用的なままである理由です。
