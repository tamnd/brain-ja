 ## 解決策
 ## 問題の理解

 (n) 個の整数のシーケンス (X) があります。 すべての要素は (1) と (k) の間にあり、(1) から (k) までのすべての値はシーケンス内のどこかに出現します。 残っているすべての要素の相対的な順序を維持しながら、いくつかの要素を削除する必要があります。 

最終シーケンスにはすべての値が 1 回だけ含まれている必要があるため、その長さは正確に (k) になります。 このようなすべての部分列の中で、辞書編集的に最小の部分列が必要です。 言い換えれば、最初に最初に選択した値を最小化し、次に同じ最初の値を持つ選択肢の中から 2 番目に選択した値を最小化する、というようになります。 元の問題では (n) が (2\cdot10^5) までとなるため、シーケンスの大部分を繰り返しスキャンしたり、多くの可能なサブシーケンスを考慮したりする解決策は実行できません。 

線形解または (O(n\log n)) 解が自然なターゲットです。 (2\cdot10^5) 個の要素と 2 秒の制限がある場合、(O(n^2)) は、最悪の場合、約 (4\cdot10^{10}) 回の基本反復を意味し、競技プログラミングの実装で処理できる量をはるかに超えます。 この問題の構造は、各値の出現が 1 つだけ必要であり、後の出現により辞書編集上のより適切な選択肢が得られる場合は常に、重複した出現を破棄できるため、有利です。 

最初のエッジ ケースは (k=1) の場合であり、答え全体は単一の値で構成されます。 例えば、```
1 1
1
```出力があります```
1
```前の要素に関係するスタック操作が必要であると想定する不用意な実装は、前の要素がまったくないため、ここで失敗する可能性があります。 

もう 1 つのエッジ ケースは、シーケンスがすでに順列である場合です。 例えば、```
5 5
1
2
3
4
5
```出力があります```
1 2 3 4 5
```正確に (k) 個の要素があるため、すべての値を保持する必要があります。 現在の値が小さいという理由だけでスタック要素を削除する実装では、後で出現しない値を誤って削除する可能性があります。 

終わり近くの重複も、よくある間違いの原因です。 考慮する```
6 3
3
2
1
3
1
3
```答えは```
2 1 3
```最初`3`を選択するため、最適な答えの一部にはなり得ません。`2`next は最初の要素を小さくし、その後の要素を返します。`3`まだ利用可能です。 ただし、決勝は`3`選択した後は保持する必要があります`2`そして`1`、それ以降ではありません`3`存在します。 貪欲スタックでは、安全に削除できる要素と、削除すると残りのシーケンスが不完全になる要素を区別する必要があります。 

## アプローチ

 直接的な総当たりアプローチは、考えられる部分列を列挙し、(1) から (k) までのすべての値を含む部分列を 1 回だけ保持し、辞書編集的に最小のものを選択することです。 すべての有効な回答が明示的に考慮されるため、これは正しいです。 問題は部分列の数です。 部分列は全部で (2^n) 個あり、(k) が (n/2) 程度のとき、ちょうど長さ (k) の候補の数は次のようになります。 

[
 \binom{n}{\lfloor n/2\rfloor}、
 ]

 これはおよそ (2^n/\sqrt{n}) です。 (n=2\cdot10^5) の場合、これは完全に不可能です。 

それほど極端ではない総当たり戦略は、左から右に答えを構築することです。 各位置で、候補値を昇順に試し、すべての欠落値が利用可能な状態で残っている出現を検索します。 それぞれの実現可能性チェックが慎重に実装されたとしても、サフィックスを繰り返しスキャンすると、(O(nk)) 個の作業が必要になる可能性があります。 最悪の場合、これは約 (4\cdot10^{10}) 操作に達します。 

有益な観察は、辞書編集的最小化によって、すでに選択されている値を削除する非常に具体的な理由が得られるということです。 現在の答えが値 (a) で終わり、次のシーケンス値が (b<a) であるとします。 (a) が後で再び発生した場合、現在の (a) を維持することは決して最適ではありません。 これをより小さい (b) に置き換えると、答えは辞書編集的に小さくなりますが、(a) が後から出現しても必要なコピーを提供できます。 

これにより、単調スタック戦略が得られます。 シーケンスを左から右に処理します。 スタックは、現在構築できる最良のプレフィックスを表します。 より小さい値が到着すると、それらの値が後で再び出現する限り、スタックの最後からより大きな値を削除します。 値が後で出現しない場合、その値は所定の位置にロックされ、削除できません。 

もう一つ条件があります。 すべての値が 1 回だけ必要になるため、現在の値がすでにスタックにある場合は、単純にスキップします。 最初に出現したものが必ずしも必要なものであるとは限りませんが、それを一時的に保持しておくと、最後に出現する可能性がある前に小さい値が出現した場合に、スタック ルールによって後で置き換えることができます。 

したがって、重要なデータ構造は単なる`last`すべての値の最終位置を格納する配列。 スキャン中、スタックには重複は含まれず、すべてのポップは後で別の出現が存在することによって正当化されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^n)) 候補 | (O(n)) | 遅すぎる |
 | 貪欲なスキャンの繰り返し | (O(nk)) | (O(k)) | 遅すぎる |
 | 単調スタック | (O(n)) | (O(n+k)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. シーケンスを読み取り、計算します。`last[x]`、各値 (x) が表示される最後のインデックス。 現在の回答から値を削除できるのは、別のコピーが後で利用できることが保証されている場合のみであるため、この情報が必要です。 
2. 現在の最良のサブシーケンスプレフィックスを含むスタックを維持し、ブール配列を維持します。`used`どの値がすでにスタックにあるかを教えてくれます。 スタックには同じ値が 2 回含まれることはありません。これは、最終的な答えにすべての値が 1 回だけ含まれるという要件に直接一致します。 
3. すべての値 (x) を左から右に処理します。 もし`used[x]`はすでに true なので、(x) をスキップします。 別のコピーを保持すると、1 回限りの条件に違反します。また、既存のオカレンスがスタック内にすでに表されているため、そのコピーでは答えを改善できません。 
4. (x) が使用されていない場合は、スタック内の最後の値と比較します。 スタックが空ではありませんが、その最後の値が (x) より大きく、その最後の値が現在の位置の後に再び出現し、ポップして未使用のマークを付けます。 新しい (x) は小さいため、前に配置するとシーケンスが辞書編集的に小さくなりますが、ポップされた値が後から出現することで実現可能性が維持されます。 
5. スタックの最上位が (x) より小さくなるか、最上位の値がそれ以降出現しなくなったらすぐにポップを停止します。 最初のケースでは、それを置き換えるとシーケンスが大きくなります。 2 番目のケースでは、それを削除すると、その値の唯一残っているコピーが失われます。 
6. スタックに (x) を押して、使用済みとしてマークします。 すべての入力要素が処理されるまで続行します。 
7. スタックを印刷します。 (1) から (k) までのすべての値が入力に出現することが保証されており、別のコピーが残っている場合にのみ値を削除するため、最終スタックにはすべての (k) 値が 1 回だけ含まれます。 

### なぜ効果があるのか

 重要な不変条件は、入力の接頭辞を処理した後、スタックが辞書編集上最小の個別値のサブシーケンスであり、まだ永久に失われていないすべての値を含むように拡張できることです。 

新しい値 (x) がスタックのトップ (y) より小さい場合、(x) よりも前に (y) を保持すると、結果が辞書編集的に悪くなります。 (y) は、後で別のコピーが発生したときに正確に削除することができるため、削除しても有効な補完が不可能になることはありません。 このプロセスを繰り返すと、(x) より大きく置換可能なすべてのスタック サフィックスが削除されます。 

スタック値がその後出現しない場合、可能なすべての完了から消えるため、削除することはできません。 スタックトップが (x) より小さい場合は、小さい値を最初に保持することが辞書編集的にすでに最適です。 したがって、すべてのプッシュまたはポップは辞書編集上の最適性と実現可能性によって強制され、最終的なスタックが望ましいサブシーケンスであることが証明されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = [int(input()) for _ in range(n)]

    last = [0] * (k + 1)

    for i, x in enumerate(a):
        last[x] = i

    used = [False] * (k + 1)
    stack = []

    for i, x in enumerate(a):
        if used[x]:
            continue

        while stack:
            top = stack[-1]

            if top <= x:
                break

            if last[top] <= i:
                break

            stack.pop()
            used[top] = False

        stack.append(x)
        used[x] = True

    print(*stack)

if __name__ == "__main__":
    solve()
```最初のループは、すべての値の最後の出現を計算します。 インデックスは左から右に処理されるため、`last[x] = i`当然、配列内の最後の出現箇所が残ります。 

の`used`配列により、回答が重複して入力されるのを防ぎます。 これは別のものです`last`:`last`値を削除できるかどうかを答えます。`used`現在の回答にその値のコピーがすでに存在するかどうかを回答します。 

内側の`while`ループは単調スタック操作です。 条件`top > x`は辞書編集上の条件です。 条件`last[top] > i`が実現可能条件です。 どちらも必須です。 2 番目の条件を省略すると、残っている値の唯一の出現が削除される可能性があります。 

比較には、`last[top] <= i`それよりも`last[top] < i`現在のインデックスは後で出現するものではないため、`top`いつ`top`すでにスタックにありますが、使用しています`<=`境界を明確かつ安全なものにします。 実際には、現在のスタック値とは異なる個別のスタック値の場合、`x`、`last[top]`常に少なくとも`i + 1`まだ利用可能な場合。 

すべての値は、削除の間に最大 1 回プッシュされ、プッシュごとに最大 1 回ポップされます。 より正確には、各発生は一定の償却スタック作業のみを引き起こす可能性があるため、アルゴリズム全体は線形です。 

Python の整数では、アルゴリズムは (2\cdot10^5) で囲まれたインデックスと値のみを操作するため、オーバーフローの問題は発生しません。
