 ## 問題の理解

 入力は、壁が斜めに描かれた迷路を記述します。 ASCII 表現では、各文字位置は小さな四角形になります。 点は、その正方形に壁が含まれていないことを意味します。 スラッシュまたはバックスラッシュは、その正方形内の斜めの壁セグメントです。 スラッシュ方向のパリティ条件により、隣接する斜めの壁が一貫して接し、曖昧な交差が生じないことが保証されます。 タスクは、迷路のすべての領域に外側への道ができるように、できるだけ少ない壁セグメントを削除することです。 

迷路について考えるのに役立つのは、元のキャラクターの観点からではなく、自由空間の接続された領域の観点から考えることです。 現在の迷路に (k) 個の切断された領域があり、外側がそのうちの 1 つであると仮定します。 壁を削除すると最大 2 つの領域を接続できるため、少なくとも (k-1) 個の壁が必要です。 逆に、2 つの異なる領域を分離するすべての壁を削除して結合できるため、(k-1) 回の削除で十分です。 したがって、問題全体は、接続された領域をカウントすることに帰着します。 

公式問題には (1 \le r,c \le 1000) があるため、入力には最大 (10^6) 文字を含めることができます。 入力文字ごとに一定の作業量を調べるソリューションが適切です。 (O((rc)^2)) の処理を​​行うアルゴリズムは、最大サイズでおよそ (10^{12}) 回の演算に達するため、まったく適していません。 元のコンテストのステートメントでは、5 秒の制限時間と 512 MB のメモリが使用されます。 

単純なグリッド実装では間違ってしまう可能性のある幾何学的詳細がいくつかあります。 斜めの壁は、その対角線の 2 つの辺が異なる領域に属しているため、単純にブロックされた 1 つの文字セルとして扱うことはできません。 たとえば、最小の囲まれた迷路は次のとおりです。```
2 2
/\
\/
```そして答えは`1`。 各スラッシュを通常のブロックされたグリッド正方形として扱うと、対角線のジオメトリが失われ、囲まれた領域が存在しないと誤って報告される可能性があります。 

2 番目のエッジ ケースは、斜めの壁が外側の境界に接しているものの、閉じた領域を形成していない迷路です。 例えば、```
1 1
/
```答えがあります`0`。 単一の対角線セグメントは境界の角から別の角まで延びているため、両側は外側に接続されたままになります。 すべてのスラッシュを個別の囲まれたセルの作成としてカウントする不注意な実装では、間違った答えが返されます。 

逆の配置も重要です。```
2 2
\/
/\
```答えがあります`0`。 この向きでは、4 つの対角線セグメントは内部領域を囲みません。 すべてのスラッシュの密集したグループが閉じた領域を作成すると想定する実装では、誤って返される可能性があります。`1`。 

最後に、次のような完全にオープンな迷路```
1 1
.
```はすでに 1 つの領域、つまり外部接続された領域で構成されているため、答えは次のようになります。`0`。 これにより、接続されたコンポーネントの数ではなく、空きサブセルの数を誤ってカウントする実装が捕捉されます。 

## アプローチ

 直接的な総当たりアプローチでは、壁を取り除き、すべての領域が外側に到達できるかどうかを確認します。 候補の壁ごとに、それを一時的に取り除き、迷路の上に塗りつぶしを実行し、すべての空き領域が外部に接続されているかどうかをテストできます。 接続性チェックが (O(rc)) 個の迷路位置に接触している間に (rc) 壁が存在する可能性があるため、最悪のケースは (O((rc)^2)) になります。 (r=c=1000) では、(10^{12}) 回の演算のオーダーになります。 ブルート フォースは、変更の可能性があるたびに接続性を明示的にテストするため、正しいのですが、検索を繰り返すと使用できなくなります。 

重要な点は、どの特定の壁を取り除くかを決定する必要がないということです。 最初の迷路に (k) 個の接続された自由空間領域がある場合、正確に (k-1) 個の壁で十分です。 1 つの壁を削除すると 2 つの領域が結合され、コンポーネント数が 1 つ減少します。 外部に接続された領域のみが残るまでこれを繰り返すと、(k-1) 回の削除が必要になりますが、これより少ない削除を行うソリューションはありません。 

残っているのは、これらの領域を正確にカウントすることです。 斜めの表現では、動きが斜めの壁の周りで発生するため、元の (r \times c) 文字グリッド上では扱いにくくなります。 表現を両方向に 2 倍にスケーリングすることで、幾何学的な複雑さを取り除くことができます。 これはコンテスト分析で説明されている標準的な変換です。各入力文字は (2 \times 2) ブロックになり、対応する対角線に沿った 2 つのセルが壁としてマークされ、迷路全体の周囲に空の境界が追加されます。 

のために`/`の場合、ブロックされたセルは、(2 \times 2) ブロックの右上と左下のセルです。 のために`\`、左上と右下のセルです。 ドットは 4 つのセルすべてを解放します。 拡張されたグリッド内の移動は通常の 4 方向の移動であるため、斜めの壁は物理的なバリアとまったく同じように動作します。 

余分な空の境界は無限の外側を表します。 これにより、迷路から脱出できるすべての領域が 1 つの共通コンポーネントに接続されることが保証されます。 次に、拡張されたグリッドをフラッドフィルして、その接続されたコンポーネントをカウントします。 答えは、1 つのコンポーネントが外側であるため、コンポーネントの数から 1 を引いたものになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 拡張グリッド フラッド フィル | (O(rc)) | (O(rc)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (r \times c) 文字グリッドを読み取り、サイズ ((2r+2) \times (2c+2)) の拡張グリッドを作成します。 余分な 1 セルの境界線は、迷路の外側を表すように意図的に空のままにされています。 
2. すべての元の文字をその (2 \times 2) ブロックにマップします。 ドットの場合は、壁がないため、4 つの位置すべてを空のままにしておきます。 のために`/`、右上と左下の位置を壁としてマークします。 のために`\`、左上と右下の位置を壁としてマークします。 2 倍に拡大すると、通常の 4 方向の動きが斜めの壁を横切ることができないほどの厚みが対角線の壁に与えられます。 
3. 展開されたグリッドをスキャンします。 未訪問の空のポジションが見つかるたびに、そこからフラッドフィルを開始し、到達可能なすべての空のポジションを訪問済みとしてマークします。 新しい塗りつぶしごとにコンポーネント数を 1 回増加させます。 
4. 追加された境界を含むコンポーネントを外側領域として扱います。 他のすべてのコンポーネントは、外部に接続する必要がある囲まれた領域または切断された領域です。 
5. 印刷`components - 1`。 減算により、カウントから外側の成分が削除されます。 

### なぜ効果があるのか

 拡張されたグリッドは、元の迷路の接続性を正確に保持します。 元の迷路のパスは、拡張表示ではフリー セルを通る 4 方向のパスに対応しますが、すべての斜めの壁は、迷路を横切る通路をブロックするために必要な 2 つの位置を占めます。 空の境界線は、迷路から 1 つの外側のコンポーネントに抜けるすべての方法を接続します。 

展開されたグリッドに (k) 個の接続されたコンポーネントがあるとします。 そのうちの 1 つは外側であり、それに接続する必要がある (k-1) 個の領域が残ります。 1 つの壁の削除でマージできるコンポーネントは最大 2 つであるため、(k-1) 未満の削除では十分ではありません。 一方、外側にない各コンポーネントは壁によって残りのコンポーネントから分離されているため、適切な分離壁を削除すると、そのコンポーネントを別のコンポーネントとマージでき、この操作を繰り返すと、正確に (k-1) 回の削除を使用して、すべての (k) 個のコンポーネントが接続されます。 したがって、最小値はコンポーネントの数から 1 を引いたものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    r, c = map(int, input().split())
    maze = [input().strip() for _ in range(r)]

    h = 2 * r + 2
    w = 2 * c + 2

    # 0 = free, 1 = wall/visited
    grid = bytearray(h * w)

    # Convert every slash into two blocked cells in its 2x2 block.
    for i in range(r):
        row = maze[i]
        base = (2 * i + 1) * w + 1

        for j, ch in enumerate(row):
            p = base + 2 * j

            if ch == '/':
                grid[p + 1] = 1
                grid[p + w] = 1
            elif ch == '\\':
                grid[p] = 1
                grid[p + w + 1] = 1

    components = 0

    # The stack stores linear indices in the expanded grid.
    stack = []

    for i in range(h):
        start = i * w

        for j in range(w):
            pos = start + j

            if grid[pos]:
                continue

            components += 1
            grid[pos] = 1
            stack.append(pos)

            while stack:
                cur = stack.pop()

                nxt = cur - w
                if grid[nxt] == 0:
                    grid[nxt] = 1
                    stack.append(nxt)

                nxt = cur + w
                if grid[nxt] == 0:
                    grid[nxt] = 1
                    stack.append(nxt)

                nxt = cur - 1
                if grid[nxt] == 0:
                    grid[nxt] = 1
                    stack.append(nxt)

                nxt = cur + 1
                if grid[nxt] == 0:
                    grid[nxt] = 1
                    stack.append(nxt)

    print(components - 1)

if __name__ == "__main__":
    solve()
```実装の最初の部分では、元の行を保存し、拡張されたグリッドを 1 つの行として割り当てます。`bytearray`。 フラット バイト配列は、Python のリストのリストよりもメモリ効率が大幅に優れています。これは、両方の次元が 1000 の場合、展開されたグリッドには約 400 万の位置を含めることができるため、重要です。 

表現`p = base + 2 * j`元の文字に対応する (2 \times 2) ブロックの左上のセルを識別します。`(i, j)`。 のために`/`、ブロックされた位置は次のとおりです。`p + 1`そして`p + w`。 のために`\`、 彼らです`p`そして`p + w + 1`。 これらはまさに、適切な対角線上にある 2 つのセルです。 

境界が壁として明示的にマークされることは決してないため、外側のフレーム全体が自由空間として開始されます。 塗りつぶし時には外側のコンポーネントになります。 

フラッド フィルでは、代わりに線形インデックスが使用されます。`(row, column)`タプル。 垂直方向に移動するとインデックスが変化します`w`、水平方向に移動しながら 1 ずつ変化します。 展開されたグリッドには完全に空の境界線があるため、`cur - w`、`cur + w`、`cur - 1`、 そして`cur + 1`有効のままです。 1 セルの境界線は、外側の行境界でのフラット インデックスによって引き起こされる遷移でも、明示的に表された外側の領域内に残るため、水平方向の移動にも役立ちます。 

位置は、そのバイトを次から変更することによって訪問済みとしてマークされます。`0`に`1`。 壁と訪問セルには同じバイト値が使用されます。これは、どちらも塗りつぶしがその位置に再び入ってはいけないことを意味するためです。 セルをスタックにプッシュする前にセルにマークを付けると、同じセルが複数回挿入されるのを防ぎます。 

再帰は使用されません。 再帰的 DFS は、展開されたセルの数に比例した再帰の深さを必要とし、大きな開いた迷路では Python の再帰制限を超えます。
