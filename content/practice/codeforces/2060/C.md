 ## 解決策
 ## 問題の理解

 ボード上に書かれた整数の配列が与えられます。 ゲームはラウンドごとに 2 つの数字を繰り返し削除しますが、順序が重要です。アリスは、後でボブが適切なペアを形成できないようにする目的で、最初に 1 つの数字を削除します。一方、ボブは、削除された 2 つの値の合計が固定目標値に達する頻度を最大化するために、別の数字を削除して応答します。$k$。 ラウンド内で選択された 2 つの数字が合計されるたびに、$k$、スコアが 1 つ増加します。 

重要な問題は、プレイヤーが協力していないことです。 アリスは、ボブが合計が次のようなペアを作成するのを積極的に阻止しようとしています。$k$一方、ボブはそのようなペアを強制しようとしています。 最終的なスコアは、何ラウンドで相補的なペアが完成したかによってのみ決まります。$(x, k-x)$。 

入力サイズが大きく、最大$2 \cdot 10^5$テスト ケース全体の要素の合計。 これにより、考えられるすべてのゲーム状態のシミュレーションや再帰的なゲーム ツリー推論が除外されます。 ターンごとの選択肢を評価したり、分岐の結果を追跡しようとするものはすべて、二次的な動作に劣化し、合格しません。 

値がちょうど半分の場合、微妙なエッジケースが発生します。$k$、ペアリングには 2 つの同一の値が必要であるためです。 たとえば、次の場合$k=10$多くの 5 がある場合、成功した得点イベントごとに 5 が 2 つ消費されます。 頻度を追跡せずに値の任意の出現をペアにする素朴な貪欲性は、そのような場合に簡単に過大カウントまたは過小カウントする可能性があります。 

もう 1 つのエッジ ケースは、値が重複する相補的なチェーンを形成する場合です。 たとえば、$k=6$、1、2、4、5 のような値は、複数のペアが同じ出現をめぐって競合するように相互作用します。 単純な「カウントを独立して補う」アプローチは、各要素が 1 回消費されることを無視するため、失敗します。 

## アプローチ

 ゲームを強引に解釈すると、各ターンをシミュレートしようとします。 すべてのステップで、アリスが数字を選択し、ボブが最適に応答し、将来の結果を再帰的に評価します。 これにより、深みのある分岐ゲーム ツリーが生成されます。$n/2$、各ノードには最大で$O(n^2)$考えられる選択肢。 メモ化を行ったとしても、状態空間は残りの数値のマルチセットに依存し、そのサイズは指数関数的になります。 これは実現可能な限界をはるかに超えています。 

重要な観察は、採点において重要なのは、ボブがアリスが選択した値の補数を選択できるかどうかだけであるということです。 アリスの最善の防御策は、すでに「危険な」値の利用可能な補数の数を減らすことです。 ボブの最善の戦略は、利用可能な補数がまだある値を保存するかターゲットにすることです。 

この相互作用は周波数の問題に陥ります。 ターンをシミュレートする代わりに、素のペアがいくつあるかを考慮します。$(x, k-x)$最適な衝突の下で形成することができます。 アリスは常に、潜在的な一致を早期に破ることによってボブの機会を「無駄に」しようとします。これは事実上、それぞれの価値を意味します$x$その補完物とのみ競合します$k-x$そして最終的なスコアは、そのようなペアが最適な干渉に耐えられる数に依存します。 

これはきれいな削減につながります。すべての値の頻度をカウントし、次に各値についてカウントします。$x$と組み合わせます$k-x$。 有効な一致ごとに、両側の出現が 1 つずつ消費されます。 特別な注意が必要な場合$x = k-x$、ペアリングでは同じ数字が 2 つ出現することが使用されます。 

貪欲な実装は次のようになります。値を反復処理し、常に可能な限り多くの補数と一致し、各数値が最大 1 回使用されるようにします。

 ## アルゴリズムのチュートリアル

 私たちはゲームを、最適なプレイの下でマルチセットからいくつの相補的なペアを形成できるかを数えることに要約します。 

1. 配列内のすべての数値の頻度マップを作成します。 これにより、各値のコピーが何個存在するかを正確に知ることができます。これは、最適推論によってターン順序の複雑さが取り除かれた後の唯一の関連する状態です。 
2. それぞれの個別の値を反復処理します。$x$周波数マップで。 各値について、その補数を計算します$y = k - x$。 二重カウントを避けるために、各ペアは 1 回だけ処理されます。 
3. もし$x < y$の出現を照合しようとします。$x$の発生により$y$。 提供される有効なスコアリングペアの数は次のとおりです。$\min(freq[x], freq[y])$。 次に、これらの一致した要素を概念的に削除して、他の場所に参加できないようにします。 
4. もし$x = y$、私たちは自己補完のケースにいます。 有効な各ペアには、次の 2 つの出現が必要です。$x$、つまり貢献度は$\lfloor freq[x] / 2 \rfloor$。 
5. すべての寄与を最終スコアに累積し、テスト ケース用に出力します。 

注文条件$x < y$値の各ペアが 1 回だけ処理されることを保証し、対称の補数が二重にカウントされるのを防ぎます。 

### なぜ効果があるのか

 ゲームは組み合わせ要素に集約され、得点には補完的な値のみが重要となります。 アリスの最適な戦略は、せいぜいペアリングを遅らせたり再配置したりすることしかできませんが、形成できる互いに素な相補ペアの総数を変えることはできません。 成功したすべてのスコアは、合計が次のようになるちょうど 2 つの値を消費します。$k$、どの要素も複数のスコアに寄与することはできません。 周波数マッチング プロセスは、最適な敵対的プレイの下での結果と一致する、素の有効なペアの最大数を構築します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        arr = list(map(int, input().split()))
        
        freq = {}
        for v in arr:
            freq[v] = freq.get(v, 0) + 1
        
        used = set()
        ans = 0
        
        for x in freq:
            y = k - x
            if x in used:
                continue
            if y not in freq:
                continue
            
            if x == y:
                ans += freq[x] // 2
            else:
                ans += min(freq[x], freq[y])
            
            used.add(x)
            used.add(y)
        
        print(ans)

if __name__ == "__main__":
    solve()
```ペア構造について推論すると、個々の位置はもはや重要ではなくなるため、解決策は各値の出現を数えることから始まります。 の`used`set は両方を処理しないことを保証します$x$そして$k-x$別々に行うと、ペアのカウントが 2 倍になります。 

ケースは次の間で分割されました`x == y`そして`x != y`が不可欠です。 値がその補数に等しい場合、ペアリングは 1 つのバケットの内部で行われるため、2 で割ります。 それ以外の場合は、最小操作を使用して 2 つの周波数バケット間で照合します。

 ## 特殊なケース

 すべての値が同一で等しい場合$k/2$、すべての採点イベントは 2 つの同一の要素を消費します。 このアルゴリズムは、整数を 2 で除算することでこれを処理し、単一の要素を再利用できないことを正しく反映しています。 

値が次のような完全な対称セットを形成する場合$[1,2,3,4]$と$k=8$、各値にはちょうど 1 つの補数があり、重複は発生しません。 周波数ペアリングにより、各ペアが 1 回カウントされることが保証され、`used`set は重複を防ぎます。 

2 つの値の合計が一致しない場合$k$、周波数マップは引き続き正しく構築されますが、すべての補数ルックアップが失敗し、寄与がゼロになります。
