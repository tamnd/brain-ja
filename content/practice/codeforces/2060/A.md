 ## 解決策
 ## 問題の理解

 中央の要素が欠落している 5 つの整数の配列を表す 4 つの既知の値が与えられています。 欠落している位置は 3 番目であり、負数やゼロを含む任意の整数値を自由に選択できます。 その値が固定されると、3 つの「ローカル フィボナッチ チェック」が評価されます。各チェックでは、要素がその直前の 2 つの要素の合計と等しいかどうかが尋ねられます。 

具体的には、配列の 3、4、5 番目の位置にチェックが適用されます。 満たされた各チェックは、フィボナッチ性と呼ばれるスコアに 1 ポイントを与えます。 タスクは、このスコアができるだけ大きくなるように、欠落している中間値を選択することです。 

制約は小さく、テスト ケースは最大 500 個で、すべての数値は 100 で区切られます。これにより、テスト ケースごとの複雑な検索が即座に除外されますが、実際の簡素化は構造から来ています。唯一の自由は 1 つの変数にあり、各条件はその変数を含む直接方程式に変換されます。 これは、大きな状態空間を探索しているのではなく、いくつかの線形制約を調整しているだけであることを意味します。 

3 つの制約をすべて同時に考慮せずに、貪欲に中間値をシミュレートまたは推測しようとすると、微妙な失敗のケースが発生します。 たとえば、最初の関係を満たすために中央の値を選択すると、別の選択で 2 つの条件を同時に満たせる場合でも、後の両方の関係が崩れる可能性があります。 これは、各条件が同じ変数に対して異なる必須値を課し、これらの要件間の重複のみが問題となるために発生します。 

## アプローチ

 この問題を素朴に扱う場合は、欠落要素の考えられる値を反復処理して、3 つのフィボナッチ条件のうちいくつが当てはまるかを計算してみるかもしれません。 中間値が固定されるとすべての条件を評価できるため、これは概念的には正しいです。 ただし、欠損値は正または負の任意の整数になる可能性があるため、理論的には検索空間に制限がなく、この考えは実際には崩れます。 

検索を人為的に広い範囲 (-1000 から 1000 など) に制限したとしても、テスト ケースごとに何千ものチェックを実行することになりますが、構造を考えるとこれは不必要です。 重要な観察は、3 つの条件のそれぞれが独立して、その条件が成立する場合の中間値が何でなければならないかを正確に決定するということです。 

最初の条件は、最初の 2 つの要素から派生した中間要素の特定の値を強制します。 2 番目の条件は、3 番目の既知の要素と 2 番目の要素から派生した別の値を強制します。 3 番目の条件は、最後の 2 つの要素から派生したさらに別の値を強制します。 選択できる値は 1 つだけであるため、これらの制約の最大数を満たす値を選択するのが最善です。これにより、問題は 3 つの候補値の間で等しい値を数えるということになります。 

これにより、問題は整数の検索から 3 つの計算された数値の単純な頻度比較に変換されます。

 ## アルゴリズムのチュートリアル

1. 各フィボナッチ条件を未知の中間値の方程式に変換します。 位置 3 の条件は、最初の 2 つの既知の値に関して中央の要素を直接表現します。 
2. 位置 4 の条件に対しても同じことを行い、中央の要素が周囲の既知の値を使用して分離されるように書き換えます。 これにより、2 番目の候補値が生成されます。 
3. 位置 5 の条件に対して同じ手順を繰り返し、同じ中央要素の 3 番目の候補値を生成します。 
4. これら 3 つの候補値のうち、互いに等しいものがいくつあるかを数えます。 任意の値の頻度は、その値を選択することによって同時に満たされる条件の数を表します。 
5. 3 つの候補の中の最大の頻度を返します。これは、達成可能な最良のフィボナッチ性に対応するためです。 

重要な推論ステップは、すべての有効な構成がこれらの候補値の 1 つを選択することに正確に対応しており、満たされた各条件はこれらの制約の 1 つと一致することと同等であるということです。 

### なぜ効果があるのか

 3 つのフィボナッチ条件はそれぞれ、条件が強制された場合に中央の要素を一意に決定する線形方程式です。 すべての条件は同じ変数に依存するため、達成可能な最良のスコアは、単一の値に一致するこれらの方程式の最大のサブセットのサイズにすぎません。 どの条件も複数の未知の選択に依存しないため、他の隠れた相互作用は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a1, a2, a4, a5 = map(int, input().split())

        # each condition implies a specific value for a3
        c1 = a1 + a2
        c2 = a4 - a2
        c3 = a5 - a4

        # count how many conditions agree
        best = 0
        best = max(best, (c1 == c2) + (c1 == c3) + 1)
        best = max(best, (c2 == c1) + (c2 == c3) + 1)
        best = max(best, (c3 == c1) + (c3 == c2) + 1)

        print(best)

if __name__ == "__main__":
    solve()
```このコードは、各フィボナッチ条件によって引き起こされる欠落要素の 3 つの可能な値を計算します。 次に、他の候補と同等性を比較することにより、各候補が満たす条件の数を評価します。 最終的な答えは、同時に true にできる条件の最大数です。 

よくある実装の落とし穴は、中間要素を順番に「解決」しようとすることです。 このアプローチでは、前の選択が後の選択に影響を及ぼさないことを暗黙的に前提としていますが、ここではすべての制約が同じ変数に対して競合するため、導出された値間の一貫性のみが問題となります。

 ## 特殊なケース

 1 つのエッジ ケースは、導出された 3 つの値がすべて異なる場合に発生します。 たとえば、制約によって中央の要素に対して 3 つの異なる必須値が生成される場合、単一の選択肢が複数の条件を満たすことはありません。 アルゴリズムは、ペアごとの一致をカウントすることでこれを処理し、最大値は 1 になります。 

もう 1 つのケースは、すべての制約が一致する場合です。 のような入力の場合`5 5 10 15`、すべての導出値が等しくなり、すべての条件が同じ中間値によって同時に満たされるため、カウント ロジックは自然に 3 を生成します。
