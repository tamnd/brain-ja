 ## 解決策
 ## 問題の理解

 同じ頂点セット上に 2 つの無向グラフが与えられています。 作業グラフと呼ばれる 1 つのグラフは、変更が許可されている構造です。 2 番目のグラフは、接続性の観点から最終的に「一致」させる必要がある固定参照構造です。 

許可される操作は非常に強力です。作業中のグラフに欠落しているエッジを自由に挿入したり、既存のエッジを削除したりできます。 このような変更ごとに 1 回の操作が必要になります。 これらの一連の編集を実行した後は、正確なエッジは気にせず、接続されたコンポーネントのみを気にするようになります。 目標は、参照グラフ内で 2 つの頂点が接続されている場合にのみ、作業グラフ内で 2 つの頂点が接続されることです。 

したがって、このタスクは基本的に、頂点の 1 つのパーティションを別のパーティションに変換することであり、各パーティションはグラフの接続されたコンポーネントによって定義されます。 

制約は厳しく、すべてのテスト ケースにわたって頂点とエッジは最大 2×10^5 です。 これにより、エッジごとに接続性を繰り返し再計算したり、単純に変更をシミュレートしたりするアプローチは即座に除外されます。 どのソリューションも基本的に、通常は DSU または DFS を使用して、テスト ケースごとに問題を数回の線形またはほぼ線形のパスに減らす必要があります。 

2 つのグラフがすでに同一の接続性を定義しているにもかかわらず、非常に異なるエッジ セットを持っている場合、微妙なエッジ ケースが発生します。 たとえば、両方のグラフが接続されているが、一方がツリーであり、もう一方が密である場合、エッジ セットが大幅に異なっていても、接続性はすでに一致しているため、操作は必要ありません。 コンポーネントの代わりに「エッジを揃える」という単純なアプローチでは、不要な編集が誤ってカウントされてしまいます。 

もう 1 つのエッジ ケースは、両方のグラフが完全に接続されていないが、頂点の分割方法が異なる場合に発生します。 たとえば、F が 1 つのコンポーネントで、G がすべてをシングルトンに分割する場合、F のすべての頂点を分離するのに十分なエッジを削除する必要があります。コンポーネントの構造を考慮せずにエッジの違いのみに焦点を当てたアプローチは、このような場合に過大カウントまたは過少カウントになります。 

## アプローチ

 ブルートフォースパースペクティブは、F を、G と同じ接続コンポーネントを持つターゲット グラフに直接変換しようとします。頂点のペアを繰り返しチェックし、最終的に接続されるべきかどうかに応じて、エッジが必要か削除する必要があるかを判断することを想像できます。 ただし、各操作によって接続がグローバルに変更されるため、編集のたびに接続コンポーネントを再計算すると、コストのかかるグラフ走査の繰り返しが発生します。 エッジを慎重に選択したとしても、任意の追加や削除の下で動的な接続を維持すると、必要以上に重い構造に追い込まれることになります。 

重要な簡素化は、実際にエッジを一致させる必要はなく、接続されたコンポーネントのみを一致させる必要があることです。 これが認識されると、問題は頂点セットの 2 つのパーティション (F のコンポーネントと G のコンポーネント) を比較することになります。 

G の各接続コンポーネント内では、最終的にすべての頂点が最終的なグラフで接続される必要があります。 これは、各 G コンポーネント内で、最終状態が単一の連結コンポーネントでなければならないことを意味します。 逆に、異なる G コンポーネントからの頂点は最終的なグラフでは切り離される必要があるため、異なる G コンポーネント間を横切る F のエッジは基本的に「間違っている」ため、削除する必要があります。 

これで構造がきれいになりました。 まず、異なる G コンポーネントを接続する F 内のすべてのエッジを削除することで、F が G の分割を尊重するように強制します。 このクリーンアップの後、F の残りの各コンポーネントは完全に G のコンポーネント内に存在します。各 G コンポーネント内で、場合によっては複数の F コンポーネントを 1 つに接続する必要があります。 2 つのコンポーネントの各マージには、正確に 1 つのエッジの追加が必要であり、私たちができる最善のことはコンポーネントを貪欲に接続することなので、コストはコンポーネントの数から G コンポーネントごとに 1 を引いたものになります。

これは DSU ベースのソリューションにつながります。DSU for G を使用してグループを識別し、それらのグループ内で有効な F エッジをシミュレートし、グループごとに結果のコンポーネントをカウントし、必要なマージの数を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース再計算 | O(n・(m₁+m₂)) | O(n+m) | 遅すぎる |
 | DSU コンポーネントの結合 | O((n+m₁+m₂) α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 概念上、素セット共用体構造を 2 回使用していますが、実装に必要な DSU は 1 つだけです。 

1. グラフ G の DSU を構築して、その連結成分を計算します。 各頂点には、どの最終コンポーネントに属するかを識別する代表が割り当てられます。 このステップでは、問題をグラフベースからコンポーネントベースに変換します。 
2. 頂点に対して別の DSU を初期化しますが、同じ G コンポーネント内にある結合のみを許可します。 これにより、最終的な回答では分離されたままにしておく必要があるコンポーネント間で誤ってマージすることがなくなります。 
3. F のすべてのエッジを繰り返します。各エッジ (u、v) について、u と v が同じ G コンポーネントに属しているかどうかを確認します。 そうでない場合、このエッジは最終構造では無効となり、必要な削除が 1 つ発生します。 存在する場合、F の制限付き DSU 内の u と v を結合します。 
4. すべての有効なエッジを処理した後、各 G コンポーネントは、F の許可されたエッジによって形成されるいくつかの接続された部分に分割されます。 
5. 各 G コンポーネントについて、その頂点間に存在する DSU ルートの数を数えます。 コンポーネントにこのような部分が k 個ある場合、それらを 1 つの連結コンポーネントに接続するには、正確に k−1 回の操作が必要です。 
6. すべての G コンポーネントを合計して必要なマージを行い、コンポーネント間のエッジのすべての削除を追加します。 この合計が答えになります。 

### なぜ効果があるのか

 正確さは、問題を 2 つの独立した制約に分割することによって得られます。つまり、必要な切断に違反するエッジを削除することと、必要な各グループ内の接続を復元するためだけにエッジを追加することです。 コンポーネント間のエッジが削除されると、各 G コンポーネントは孤立した部分問題になります。 このような部分問題の内部では、k 個のコンポーネントを持つ接続された構造は少なくとも k−1 個のエッジが接続される必要があり、コンポーネント内の欠落しているエッジは追加できるため、常にそれを達成できます。 

これにより、下限と、それを達成するための建設的な方法の両方が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]

def solve():
    t = int(input())
    for _ in range(t):
        n, m1, m2 = map(int, input().split())

        g_dsu = DSU(n)

        edges_f = []
        for _ in range(m1):
            u, v = map(int, input().split())
            edges_f.append((u - 1, v - 1))

        for _ in range(m2):
            u, v = map(int, input().split())
            g_dsu.union(u - 1, v - 1)

        comp_vertices = [[] for _ in range(n)]
        for i in range(n):
            comp_vertices[g_dsu.find(i)].append(i)

        f_dsu = DSU(n)

        deletions = 0

        for u, v in edges_f:
            if g_dsu.find(u) != g_dsu.find(v):
                deletions += 1
            else:
                f_dsu.union(u, v)

        answer = deletions

        for comp in comp_vertices:
            roots = set()
            for v in comp:
                roots.add(f_dsu.find(v))
            if len(comp) > 0:
                answer += len(roots) - 1

        print(answer)

if __name__ == "__main__":
    solve()
```コードはまず、DSU を使用してグラフ G をコンポーネントに圧縮します。 次に、F のエッジがそれらのコンポーネントを尊重するかどうかに基づいてフィルタリングします。 エッジ交差コンポーネントは、必要な削除として直ちにカウントされます。 

有効な各 G コンポーネント内で、F の許可されたエッジが頂点をどのようにサブコンポーネントに分割するかを追跡します。 それぞれの個別の DSU ルートは 1 つの部分に対応し、それらを統合するために必要なマージの数を計算します。 

微妙な実装の詳細は、F でグローバル接続を維持しようとしないことです。コンポーネント間の構造はフィルタリングされると無関係になるため、代表的なラベルのみに依存します。 

## 実用的な例

 G が F とは異なる方法で頂点を分割する小さなケースをトレースします。 

n = 4 の場合を考えてみましょう。 

F エッジ: (1,2)、(2,3)

 G エッジ: (1,2)、(3,4)

 G コンポーネントは {1,2} と {3,4} です。 

### トレース

 | ステップ | アクション | DSU(G) コンポーネント | DSU(F制限) | 削除 |
 | --- | --- | --- | --- | --- |
 | 初期化 | ビルドG | {1,2}、{3,4} | すべて別々 | 0 |
 | プロセス (1,2) | 結合は許可されます | {1,2}、{3,4} | {1,2} | 0 |
 | プロセス (2,3) | クロスエッジ | {1,2}、{3,4} | {1}、{2}、{3}、{4} | 1 |

 G コンポーネント内では次のようになります。 

{1,2} の場合、F には 1 つのコンポーネントがあるため、コストは 0 です。 

{3,4} の場合、F には 2 つのシングルトンがあるため、コストは 1 になります。 

合計の答えは 2 です。 

このトレースは、アルゴリズムが制約の分解と一致させて、削除コストを内部マージ コストから明確に分離する方法を示しています。 

2 番目のケースは、完全に接続された G を示しています。 

Fエッジ：なし

 G エッジ: チェーンを形成する 1-2-3-4

 すべての頂点は 1 つの G コンポーネント内にあるため、F 内の接続性のみを計算します。すべての頂点は分離されているため、4 つのコンポーネントがあり、3 つのマージが必要です。 アルゴリズムは当然 3 を出力します。これは、単一グループ内にスパニング ツリーを構築するだけでよいという考えと一致します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m₁ + m₂) | DSU 操作とエッジと頂点上のシングルパス |
 | スペース | O(n) | DSU アレイとストレージのグループ化 |

 この制約では合計要素数が 2×10^5 まで許容されるため、線形または線形に近い DSU 操作は十分に制限内に収まり、特にサイズによるパス圧縮と結合により、操作ごとのほぼ一定の償却時間が保証されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    import sys

    input = sys.stdin.readline

    class DSU:
        def __init__(self, n):
            self.parent = list(range(n))
            self.size = [1] * n

        def find(self, x):
            while self.parent[x] != x:
                self.parent[x] = self.parent[self.parent[x]]
                x = self.parent[x]
            return x

        def union(self, a, b):
            a = self.find(a)
            b = self.find(b)
            if a == b:
                return
            if self.size[a] < self.size[b]:
                a, b = b, a
            self.parent[b] = a
            self.size[a] += self.size[b]

    t = int(input())
    out = []

    for _ in range(t):
        n, m1, m2 = map(int, input().split())

        g = DSU(n)

        edges = []
        for _ in range(m1):
            u, v = map(int, input().split())
            edges.append((u - 1, v - 1))

        for _ in range(m2):
            u, v = map(int, input().split())
            g.union(u - 1, v - 1)

        f = DSU(n)

        del_cost = 0

        for u, v in edges:
            if g.find(u) != g.find(v):
                del_cost += 1
            else:
                f.union(u, v)

        comp = {}
        for i in range(n):
            r = g.find(i)
            comp.setdefault(r, []).append(i)

        ans = del_cost
        for nodes in comp.values():
            roots = set(f.find(x) for x in nodes)
            ans += len(roots) - 1

        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 F が完全に接続されているが、G が頂点を多くのコンポーネントに分割しているケースは、削除カウントが重要である理由を示しています。 F のすべてのエッジが異なる G コンポーネントに接続している場合、そのようなエッジはすべて削除する必要があります。削除しないと、最終的なグラフで、分離したままにしておく必要があるコンポーネントが誤って接続されてしまいます。 

G が完全に接続されているが、F に複数のコンポーネントがある別のケースでは、逆の効果が示されます。 削除は必要ありませんが、F 内のすべての切断された部分は、その数より正確に 1 つ少ないエッジで接続する必要があります。 すべての頂点が 1 つの G グループに分類されるため、アルゴリズムはこれを自然に処理し、内部 DSU 構造のみが答えを決定します。
