 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 隣接する 2 つの要素を繰り返し選択して、「バランス減算」操作を実行することができます。つまり、ペアを調べ、両方のエントリから小さい方の値を減算し、続行します。 この操作では、選択した 2 つの要素のうちの少なくとも 1 つが常に強制的にゼロになり、値が増加することはありません。 

目的は、配列を完全に並べ替えることではなく、そのような操作を任意の数だけ使用して配列を非減少シーケンスに変換できるかどうかを判断することです。 

主な問題点は、操作がローカルであるにもかかわらず、その影響が伝播することです。ペアを変更すると、隣接するペアを調整する将来の機能に影響を与えます。 すべての操作は非負性を保持し、隣接するペアから質量のみを削除するため、システムは非常に制約されたルールの下で値を再分配および消去しているかのように動作します。 

制約は厳しいです: 合計$n$すべてのテストケースにわたって、$2 \cdot 10^5$。 各操作は隣接する操作と相互作用する可能性があり、可能な操作シーケンスの数は指数関数的に増加するため、操作をシミュレートしたり、配列の状態を調査しようとするアプローチはすべて、すぐに失敗します。 これにより、テスト ケースごとに線形または線形に近い貪欲な推論が求められます。 

ローカルな改善がグローバルな順序と矛盾する場合、微妙なエッジケースが発生します。 たとえば、次のような配列$[4, 5, 2, 3]$ほぼソート可能に見えますが、操作構造により、以前の構造を壊さずに中間ブロック間の反転を修正することができません。 もう 1 つの注意が必要なケースは、次のような高低パターンが交互に現れることです。$[4,5,4,5,4,5,\dots]$、キャンセルを繰り返すことでシーケンスが「スムーズ」になるかどうかは明らかではありません。 最後に、次のような配列を厳密に減少させます。$[4,3,2,1]$リダクションを繰り返すことで修正できるように見えますが、この操作では値を増やすことができないため、一部の反転は基本的に元に戻すことができません。 

## アプローチ

 ブルートフォースアプローチでは、可能なすべての操作を明示的にシミュレートします。 各操作では、関連する 2 つの要素のうち少なくとも 1 つがゼロになるため、最悪の場合、$O(n^2)$各ステップで、操作に最適なペアを検索する必要があります。 固定ペア選択戦略に限定したとしても、すべての減算が将来の有効な手を変更するため、状態空間は依然として大きく分岐します。 これは実際にはすぐに指数関数的に増加します。 

重要な観察は、実際には演算の正確な順序に興味があるのではなく、配列が減少しないようにするのに十分な「障害」を除去できるかどうかに興味があるということです。 各操作は隣接する 2 つの位置にのみ影響し、その唯一の効果は両方を同じ量だけ削減し、一方または両方をゼロにする可能性があります。 これは、値が非常に制御された方法でのみ「下方向に流れる」ことができ、恣意的に転送できないことを意味します。 

重要な洞察は、各位置の実現可能な最小限の「残存容量」を維持しながら、配列を左から右に処理することです。 プレフィックスを修正する場合、現在の値は、以前に調整された値でサポートできる値を超えてはなりません。 そうしないと、前の要素を増やして補償することができないため、一連の操作で反転を調整することができません。 

これは貪欲な構築につながります。各要素を前の要素と比較して可能な限り最善の削減をシミュレートし、各ステップで結果として得られるシーケンスが達成可能な形式で減少しないことを保証します。 この操作により、基本的に隣接する要素をまとめて削減できるため、有効な制約は生の値ではなく、調整されたプレフィックス状態間の比較になります。

 ## アルゴリズムのチュートリアル

 正しい見方は、左隣の位置とのすべての最適な操作の後に、各位置に何らかの「使用可能な値」が残っていると考えることです。 現在の位置を減らすことができる最小値を表す実行値を維持しながら、有効な非減少継続を許可します。 

1. 最初の要素の前に制約するものが何もないため、最初の要素を変更せずに開始します。 これは、プレフィックスの達成可能なベースライン値です。 
2. 次の各要素について、現在調整されている前の値と比較します。 現在の要素が既に大きいか等しい場合は、非減少要件に違反しないため、変更しないままにしておくことができます。 
3. 現在の要素が以前の調整値より小さい場合、強制的に増加させるのではなく、許可された操作効果を使用して前の要素を減少させようとします。 演算により両方の隣接する値が均等に減少するため、唯一の実行可能な調整は、現在の要素が強制的にそれを超えないようにするために、前の寄与を効果的に下げることです。 
4. 実現可能性の重要な条件は、以前の制約を破ることなく、以前の調整値を現在の値まで削減できるかどうかです。 そうでない場合は、直ちに不可能であると結論付けなければなりません。 
5. アレイ全体でこのプロセスを継続し、常に「有効な以前の値」を更新して、最も厳密な有効な構成を反映します。 

### なぜ効果があるのか

 不変条件は、インデックスを処理した後のものです。$i$、保存された値は、達成可能な最小値を表します。$a_i$プレフィックスを維持する有効な操作シーケンスの下で$[1..i]$減っていない。 すべての操作は隣接するペアを対称的に変更するだけなので、以前の位置に比べてプレフィックス要素を増やす新しい機能を導入することはできません。 したがって、いずれかの段階で調整できない場合は、$a_i$この不変条件を使用すると、今後の操作はすべて厳密にローカルであり、以前の制約を遡って増やすことができないため、今後の操作では違反を修正できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        cur = a[0]

        ok = True
        for i in range(1, n):
            if a[i] >= cur:
                cur = a[i]
            else:
                if cur < a[i]:
                    ok = False
                    break
                cur = a[i]

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```コードは単一の変数を維持します`cur`最後に処理された位置の実効値を表します。 次の要素が少なくとも`cur`、非減少シーケンスを自然に拡張します。 それが小さい場合、前の制約を「引き下げ」ようとしますが、何も増やすことができないため、構造が落下を吸収できないときにまさに破損が発生します。 

重要な実装の詳細は、操作を明示的にシミュレートしようとしないことです。 この操作の唯一の関連する効果は、隣接する値を均等に削減できることですが、これは進化するプレフィックス状態で単調な実現可能条件に崩壊します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))
            cur = a[0]
            ok = True
            for i in range(1, n):
                if a[i] >= cur:
                    cur = a[i]
                else:
                    ok = False
                    break
            out.append("YES" if ok else "NO")
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 重要なエッジ ケースは、次のような長時間増加するプレフィックスの後の急激な低下です。$[1, 2, 3, 100, 1]$。 維持されたプレフィックス制約が突然の減少と互換性がなくなるため、アルゴリズムは最後のステップでこれを拒否します。 この操作では、前の要素と比較して最後の要素を「リフト」することはできないため、一連のローカル リダクションによって反転を修復することはできません。 

もう 1 つのエッジ ケースは、次のような交互シーケンスです。$[4,5,4,5,4,5]$。 ローカル ペアを減らすことができても、グローバル構造により繰り返し制約違反が発生し、パターンが単調な実現可能性を破ると、アルゴリズムは早期に正常に失敗します。 

最後のエッジケースは、すでにソートされた入力です。 操作が必要ないため、不変式によって競合が引き起こされることはなく、アルゴリズムはシーケンスを即座に受け入れます。
