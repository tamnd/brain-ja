 ## 解決策
 ## 問題の理解

 このタスクでは、位置 1 から位置 N までステーションの 1 次元ルートに沿って移動する探査車を記述します。連続するステーションの各ペアの間には道路セグメントがあります。 各セグメントに対して、探査機は 2 つの方法でセグメントを横断します。 

歩くことができますが、時間がかかり、疲労が一定量増加します。 あるいは、バスを利用することもできますが、お金もかかり、所要時間も異なりますが、重要なことに、バスを利用するとすぐに疲労がゼロにリセットされます。 バスの料金はすべて区間ごとに支払われ、探査機には固定予算があります。 また、全行程には世界的な時間制限もあります。 

目的は単に時間やお金を最小限に抑えることではありません。 代わりに、総移動時間が制限を超えず、バスの総コストが予算を超えないようにしながら、移動中に探査機がこれまでに経験した最悪の疲労値を最小限に抑えたいと考えています。 

重要な解釈は、疲労は歩いているときだけ蓄積され、バスを利用するたびに完全にリセットされるというものです。 したがって、道はバスの乗車ごとに区切られた歩行ブロックに自然に分割されます。 答えは、そのようなブロック上の最大歩行累積であり、時間と予算の制約を尊重しながら、その最大値を最小限に抑えるためにリセットする場所を選択したいと考えています。 

制約は、N が最大 50 であることを示していますが、時間は大きくなり、バジェットは最大 1000 になる可能性があります。これは、構造がセグメントとバジェット状態にわたる動的プログラミングに十分小さいことをすぐに示唆しています。 セグメントごとに徒歩またはバスを単純に指数関数的に選択すると、2^(N−1) 通りの可能性が得られます。これは約 2^49 であり、あまりにも大きすぎます。 ローカルで貪欲な戦略を試したとしても、時間、コスト、疲労が絡み合うため、ローカルでの決定は信頼できなくなります。 

微妙なエッジケースは、徒歩の方がバスより常に速くて安いが、疲労が生じる場合に現れます。 単純な戦略では、コストと時間を最小限に抑えるためにバスを完全に避けようとするかもしれませんが、その場合、予算が未使用であるにもかかわらず、時間の制約に違反する可能性があります。 もう 1 つの失敗例は、現地では無駄に思えても、早めにバスに乗ったほうが疲れがリセットされるため、厳密には良い場合です。 たとえば、ウォーキングによって疲労が急激に高まり、制限時間内にその後の決断が不可能になる場合、一見安上がりに見えても、リセットを遅らせるのは間違いです。 

## アプローチ

 強引な見方では、すべてのセグメントを独立して検討し、歩くかバスに乗るかを決定します。 すべてのフルパスがカバーされているため、これは正しいですが、規模の点ですぐに失敗します。 N が最大 50 の場合、2^(N−1) 通りの可能性があり、それぞれについて合計時間、コスト、最大疲労を計算する必要があります。 効率的に評価したとしても、これは天文学的な規模です。 

重要な観察は、疲労がリセット間のセグメント最大値のように振る舞うことです。 バスに乗ると疲労がリセットされるため、問題はシーケンスを歩行ブロックに「分割」するブレークポイントの選択になります。 この構造は、状態がどれだけ進んだか、どれだけのお金を使ったか、どれだけの時間を費やしたか、そして前回のリセット以降の現在の疲労度を追跡する動的プログラミングを示唆しています。 

また、最大値を最小化する必要もありますが、これは通常、答えの二分探索によって処理されます。 候補疲労限界 F を修正すると、歩行セグメントが F を超えないようにして経路を横断できるかどうかを尋ねることができます。これにより、問題が実現可能性のチェックに変わります。 このチェックでは、X_i > F の区間は歩くことができないため、バスで移動する必要があり、予算と時間がかかりますが、疲労をリセットできます。 それ以外の場合、歩行は許可されますが、現在の疲労が増大するため、F を決して超えないようにする必要があります。

これにより、問題は、時間と予算の制約を満たす有効な一連の選択が存在するかどうかを確認することになります。 N が小さく、C が最大でも 1000 であるため、遷移が疲労制約の下での徒歩またはバスの決定を反映する場合、位置とバジェットを超える DP で十分です。

 ## アルゴリズムのチュートリアル

 最小可能な最大疲労を二分探索し、各候補の実現可能性をチェックすることによって問題を解決します。 

1. リセット間の任意の時点での最大許容疲労を表す候補値 F を決定します。 これにより、問題は「はい」または「いいえ」の質問に変換されます。 
2. この F では、各セグメントを前処理して、歩行が許可されるかどうかを決定します。 X_i が F より大きい場合、そのセグメントを歩くことは不可能なので、横断する場合はバスに乗らざるを得ません。 
3. DP 状態 dp[i][c] を、疲労制約 F を尊重しながら、正確に c のお金を費やしてステーション i に到着するのに必要な最小時間として定義します。 
4. コストも時間もかからずに最初のステーションから開始するため、dp[1][0] = 0 を初期化します。 
5. 1 から N-1 までの各セグメント i について、ステーション i から i+1 への遷移を考慮します。 到達可能な dp[i][c] ごとに、2 つの遷移を試みます。 
6. セグメント i で歩行が許可されている場合 (X_i ≤ F を意味する)、dp[i+1][c] を dp[i][c] + A_i で更新し、現在の疲労を暗黙的に更新します。 疲労は F によって制限されるため、このセグメント上の疲労の蓄積が F を超えない場合にのみ、この遷移を受け入れます。 
7. バスに乗る場合は、dp[i+1][c + Y_i] を dp[i][c] + B_i で更新します。 バスは疲労をリセットするので、次のセグメントは新鮮な状態で始まります。 
8. すべてのセグメントを処理した後、一部の c ≤ C に対して dp[N][c] が ≤ T であるかどうかを確認します。そのような状態が存在する場合、候補 F は実行可能です。 
9. F を 0 から max(X_i) まで二分探索して、実現可能な最小値を見つけます。 

正確さは、疲労が歩行セグメント内では単調であり、バスの使用時にリセットされるという事実に依存しているため、すべての有効な戦略はこの DP 状態空間内のパスに正確に対応します。 

### なぜ効果があるのか

 DP のどの時点でも、状態は関連するすべての履歴 (ステーション インデックス、使用済み資金、最後のリセット以降の暗黙的な疲労) を完全にキャプチャします。F を超えないように制御することで制御されます。将来の遷移は現在の位置と残りの制約にのみ依存するため、同じ値 (i, c) に達する 2 つの部分解は将来の決定に関して交換可能です。 これにより最適な下部構造が得られ、二分探索により、実現可能な最小の疲労限界が見つかるまで全体的な最大疲労限界を確実に厳しくすることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(F, N, C, T, A, X, B, Y):
    INF = 10**18
    dp = [[INF] * (C + 1) for _ in range(N + 1)]
    dp[1][0] = 0

    for i in range(1, N):
        for c in range(C + 1):
            if dp[i][c] == INF:
                continue

            # walk
            if X[i] <= F:
                if dp[i][c] + A[i] <= T:
                    dp[i + 1][c] = min(dp[i + 1][c], dp[i][c] + A[i])

            # bus
            if c + Y[i] <= C:
                if dp[i][c] + B[i] <= T:
                    dp[i + 1][c + Y[i]] = min(dp[i + 1][c + Y[i]], dp[i][c] + B[i])

    return min(dp[N]) <= T

def solve():
    N, C, T = map(int, input().split())
    A = [0] * N
    X = [0] * N
    B = [0] * N
    Y = [0] * N

    for i in range(1, N):
        a, x, b, y = map(int, input().split())
        A[i] = a
        X[i] = x
        B[i] = b
        Y[i] = y

    lo, hi = 0, max(X)
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, N, C, T, A, X, B, Y):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、実現可能性のチェックを最適化から分離します。 の`can`機能は固定疲労限界を強制し、ステーションと予算を超えて DP を実行します。 次に、二分探索ラッパーが実行可能な最小の制限を見つけます。 

実装の微妙な詳細はインデックス付けです。セグメントは 1 から N-1 まで格納され、ステーション i と i+1 の間で遷移がきれいに整列します。 もう 1 つの重要な点は、DP 遷移内で時間の枝刈りが必要であるということです。 これがないと、すでに T を超えている状態が後の遷移を不必要に汚染してしまいます。 DP は初期状態を積極的に枝刈りする代わりに大きなセンチネル値を使用するため、正確性がシンプルに保たれます。 

## 実用的な例

 3 つの駅と 2 つのセグメントがある小さなルートを考えてみましょう。 

N = 3、C = 3、T = 20 とします。 

セグメント 1 には A = 5、X = 4、B = 3、Y = 2 があります。 

セグメント 2 には、A = 6、X = 2、B = 4、Y = 1 があります。 

F = 4 をテストします。 

| 私 | c | dp[i][c] | アクション | 次の状態 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 開始 | (1,0) |
 | 1→2 | 0 | 0 | 歩く | 時間 = 5 |
 | 1→2 | 0 | 0 | バス | 時間 = 3、コスト = 2 |
 | 2→3 | 0 | 5 | 歩く | 時間 = 11 |
 | 2→3 | 2 | 3 | バス | 時間 = 7 |

 このトレースは、徒歩とバスの両方のトランジションが F のもとでも有効であり、複数の実行可能なパスが存在することを示しています。 DP は両方の可能性を捉え、予算内で実現可能な最小限の時間を確保します。 

次に、F = 2 について考えます。X1 = 4 が制限を超えているため、セグメント 1 は歩くことができず、バスが強制されます。 これにより、疲労のスパイクが即座に軽減され、移行が制限され、実現可能性チェックによって無効な戦略が早期に切り捨てられることがわかります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、たとえ 1 つのセグメントであっても、すべての歩行時間が合計制限時間を超える場合です。 その場合、実現可能な解決策はバスに依存する必要があります。 ウォーキング トランジションはすぐに時間制約に失敗し、バス トランジションのみがアクティブになるため、DP はこれを正しく処理します。 

もう一つのケースは、予算がゼロの場合です。 その場合、Y_i > 0 を必要とするすべての遷移が禁止されるため、DP は疲労限界 F の下で純粋な歩行実行可能性へと退化します。T の下で時間を維持するような F が存在しない場合、二分探索は正しく -1 を返します。 

最後のエッジケースは、局所的には歩くのが最適であっても、疲労をリセットするために早めにバスに乗る必要がある場合です。 DP は、両方の遷移を常に独立して考慮し、疲労蓄積の単調性を想定していないため、これを捉えています。
