 ## 解決策
 ## 問題の理解

 平面内に一連の点が与えられており、すべての点のペアがセグメントによって接続されていると考える必要があります。 このような各セグメントは、そのセグメントに沿った任意の位置に出現する可能性がある 1 つの「敵」に対応しますが、その正確な位置は事前に固定されていません。 

1 つのアクションは、平面内の任意の円を選択することで構成されます。 円の上または内側にある敵は排除されます。 敵はセグメントに沿った任意の点に現れる可能性があるため、エッジを確実に排除する唯一の方法は、セグメント全体が安全に円の内側にいることを確認することです。 エンドポイントが 1 つでも外側にあると、敵がそこに現れて生き残る可能性があります。 

したがって、点の各ペアはエッジに寄与し、セグメントの両方の端点が円の内側にある場合、そのエッジは円で「覆われている」と見なされます。 この問題は、考えられるエッジの数 m ごとに、円が少なくとも m 個のエッジをカバーする中心が存在するような円の最小半径はいくらかを尋ねます。 

点は最大でも n ≤ 100 なので、エッジの数は最大 4950 です。これにより、3 次またはわずかに劣る幾何学的な前処理を行う余裕があることがすぐにわかりますが、すべての円に対して動的に反復したり、指数関数的なサブセット検索を実行しようとすると、遅すぎます。 

微妙な点は、円が指定された点のいずれかを中心とする必要がなく、特定の構造を通過する必要もないことです。 これにより、ジオメトリは連続的になりますが、重要な円の極限構造は依然として少数の点によって決定されます。 

よくある落とし穴の 1 つは、セグメントの一部だけが円の内側にある場合に、エッジが覆われていると解釈されることです。 これは誤りです。敵はセグメントに沿ってどこにでも出現する可能性があるため、部分的にカバーしても保証はありません。 もう 1 つの間違いは、入力点を中心とする円だけを考慮すればよいと仮定していることです。最適な円は 2 つまたは 3 つの境界点によって定義されることが多いため、これは失敗します。 

## アプローチ

 この強引なアイデアは、考えられるすべての円を検討し、それぞれの円の内側に両方の端点を持つセグメントがいくつあるかを数えるというものです。 ただし、円は連続した空間を形成するため、直接数えることは不可能です。 

重要な構造上の観察は、固定円の場合、「両方の端点が内側にある」という条件は、セグメントの内部ではなく端点のみに依存するということです。 したがって、ディスク内にいくつの点があるかだけを考慮し、カバーされるエッジの数はその数によって完全に決まります。 ディスクに k 個の点が含まれる場合、その中の k(k−1)/2 個のエッジを正確にカバーします。 

これは問題を幾何学的パッキングの問題に変換します。つまり、k ごとに、少なくとも k 点を含むことができる円板の最小半径が必要になります。 

これで、ジオメトリが管理しやすくなりました。 選択された点のサブセットを囲む最小の円は、常に最大 3 つの境界点、つまり直径のペアまたは外接円が緊密な三角形のいずれかによって定義されます。 これは、一部のサブセットに対するすべての「最適ディスク」候補が O(n²) ペアと O(n³) トリプルから生成できることを意味します。 

このような円の候補をすべて列挙し、その半径を計算し、それらに含まれる点の数を計算します。 次に、円を半径で並べ替え、これまでに確認された含まれる点の最大数を追跡します。 半径が増加するにつれて、達成可能な最良のカウントは単調になるため、最初に k 点に到達すると、その k の最小半径が得られます。 

最後に、恒等式 m = k(k−1)/2 を使用して、「円盤内の k 点」から「カバーされる m 個のエッジ」に変換します。

 | サークル上の総当たり攻撃 | 無限 / 手に負えない | お(1) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: すべての候補円を生成する

2 つの方法で円を構築します。 まず、点のペアごとに、そのセグメントを直径とする円を形成します。 次に、同一線上にない点のトリプルごとに、それらを通過する一意の外接円を計算します。 サブセットを囲む最小の円は最大 3 つの境界点によって定義されるため、これらの円で十分です。 

### ステップ 2: 円の半径と範囲を計算する

 各円について、その中心と半径を計算します。 次に、この円の内側または境界上に入力ポイントがいくつあるかを数えます。 これにより、その円の値 k が得られます。 

これが機能する理由は、円に k 点が含まれている場合、それらの点の間で正確に k(k−1)/2 のエッジを自動的にカバーするためです。 

### ステップ 3: 円を半径で並べ替えます

 すべての候補円を半径の小さい順に並べ替えます。 これにより、許容される円のサイズを徐々に大きくするシミュレーションが可能になります。 

### ステップ 4: 達成可能な最高のポイント数を維持する

 ソートされた順序で円を反復処理し、これまでに確認された円でカバーされるポイントの最大数を維持します。 新しいサークルが以前のベストよりも多くのポイントをカバーしている場合、それを更新します。 

いつでも、この値は現在の半径のしきい値に対して可能な最良の k を表します。 

### ステップ 5: ポイント数をエッジ要件に変換する

 必要な m ごとに、k(k−1)/2 ≥ m となる最小の k を決定します。 m の答えは、スイープが少なくとも k 点に達する最初の半径です。 

### なぜ効果があるのか

 すべての有効な解は、点のサブセットを含むディスクに対応します。 そのサブセットには、最大 3 つの境界点によって定義される最小の包囲円が存在し、これが候補セットに含まれます。 したがって、実行可能なすべての k 点構成が列挙で表されます。 半径でソートすると、より大きな半径構成の前に、各 k を達成できる最小限の半径が確実に見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

EPS = 1e-10

def dist(a, b):
    return math.hypot(a[0] - b[0], a[1] - b[1])

def circle_two(a, b):
    cx = (a[0] + b[0]) / 2
    cy = (a[1] + b[1]) / 2
    r = dist(a, b) / 2
    return cx, cy, r

def circle_three(a, b, c):
    x1, y1 = a
    x2, y2 = b
    x3, y3 = c

    d = 2 * (x1*(y2 - y3) + x2*(y3 - y1) + x3*(y1 - y2))
    if abs(d) < EPS:
        return None

    ux = ((x1*x1 + y1*y1)*(y2 - y3) +
          (x2*x2 + y2*y2)*(y3 - y1) +
          (x3*x3 + y3*y3)*(y1 - y2)) / d

    uy = ((x1*x1 + y1*y1)*(x3 - x2) +
          (x2*x2 + y2*y2)*(x1 - x3) +
          (x3*x3 + y3*y3)*(x2 - x1)) / d

    r = dist((ux, uy), a)
    return ux, uy, r

def count_points(center, r, pts):
    cx, cy = center
    cnt = 0
    rr = r + 1e-9
    for x, y in pts:
        if (x - cx) ** 2 + (y - cy) ** 2 <= rr * rr:
            cnt += 1
    return cnt

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    circles = []

    for i in range(n):
        for j in range(i + 1, n):
            cx, cy, r = circle_two(pts[i], pts[j])
            cnt = count_points((cx, cy), r, pts)
            circles.append((r, cnt))

    for i in range(n):
        for j in range(i + 1, n):
            for k in range(j + 1, n):
                c = circle_three(pts[i], pts[j], pts[k])
                if c is None:
                    continue
                cx, cy, r = c
                cnt = count_points((cx, cy), r, pts)
                circles.append((r, cnt))

    circles.sort()

    best = 0
    max_k = [0] * (n + 1)

    idx = 0
    for r, cnt in circles:
        best = max(best, cnt)
        if best <= n:
            max_k[best] = r

    for i in range(1, n + 1):
        if max_k[i] == 0:
            max_k[i] = max_k[i - 1]

    total_edges = n * (n - 1) // 2
    k_needed = [0] * (total_edges + 1)

    k = 0
    for m in range(total_edges + 1):
        while k * (k - 1) // 2 < m:
            k += 1
        k_needed[m] = k

    out = []
    for m in range(1, total_edges + 1):
        out.append(str(max_k[k_needed[m]]))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、すべての直径円と外接円を明示的に構築し、それぞれがキャプチャする点の数を評価します。 重要な点は、ジオメトリ中にエッジを直接追跡しようとしないことです。 私たちは常に問題をディスク内のポイントをカウントすることに還元します。 

浮動小数点許容値は、共線性と包含性をチェックするときに小さなイプシロンによって処理されます。 これが必要なのは、点がほぼ同一線上にある場合、外接円の計算が数値的に敏感になるためです。 

エッジから必要な k へのマッピングは、幾何学的スイープ中に組み合わせ論が繰り返し再計算されるのを避けるために個別に行われます。 

## 実用的な例

 ### 例 1

 正方形を形成する 4 つの点を考えてみましょう。 2 つの点を含む円もあれば、3 つまたは 4 つの点を含む円もあります。 

| サークルタイプ | 半径 | 内部のポイント | これまでのベストk |
 | --- | --- | --- | --- |
 | ペアサークル | 小さい | 2 | 2 |
 | トリプルサークル | 大きい | 3 | 3 |
 | 囲み円 | 最大 | 4 | 4 |

 これは、半径を大きくすると、より大きなサブセットのロックが解除される様子を示しています。 

### 例 2

 3 つがほぼ同一線上にあり、1 つが遠くにある点を考えてみましょう。 

| サークルタイプ | 半径 | 内部のポイント | これまでのベストk |
 | --- | --- | --- | --- |
 | 任意のペア | 小さい | 2 | 2 |
 | 任意のトリプル (同一直線上が無効) | スキップしました | 2 | 2 |
 | 大きな円 | 大きい | 3 | 3 |

 これは、外接円が縮退トリプルを無視しなければならない理由と、直径円が不可欠である理由を示しています。

 ## 特殊なケース

 主なエッジケースは、3 つの点がほぼ同一線上にある場合です。 このような場合、外接円の式は、行列式がゼロに近いため、数値的に不安定になるか未定義になります。 アルゴリズムはこれらのトリプルを明示的にスキップし、直径円に依存しますが、直径円はそのような構成に最適なディスクを依然として正確に表します。 

もう 1 つのケースは、最適な円にちょうど 2 つの点が含まれる場合です。 これは、3 点円によってカバレッジが向上しない場合に発生します。 直径の構造により、これらのケースが引き続き考慮されることが保証されます。 

最後に、複数の円が同じ半径に達する場合は、最初に最大の範囲を取得することで自然に処理されます。 指定された k を達成する最初の出現のみが重要であるため、同点は正確さに影響しません。
