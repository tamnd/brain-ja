 ## 解決策
 ## 問題の理解

 配列で表されるネギの 1 次元フィールドが与えられます。 ワーカーは固定位置から開始し、このラインに沿って固定タイム ステップ数だけ移動します。 どの段階でも、すべてのネギが同じ量だけ均一に成長します。 この成長後、作業員は現在の位置でネギを収穫し、その位置がゼロにリセットされ、その後、必要に応じて左、右に移動するか、その場に留まります。 

重要な点は、成長はすべてのステップでグローバルに適用されるため、ある位置で収集される値は、その初期値だけでなく、最後に収集されてからの経過時間にも依存するということです。 時間が経つにつれて、すべてのポジションは増加し続けますが、収穫するたびにリセットされ、再びゼロから成長し始めます。 

タスクは、収集される合計価値を最大化するために、一定のステップ数にわたる移動戦略を選択することです。 

制約は非常に大きいです。 テスト ケースの数は最大 100,000 まで可能で、すべてのテスト ケースの合計配列サイズは最大 200,000 まで可能ですが、テストごとのステップ数は 10^6 まで可能です。 これにより、各ステップを明示的に処理するシミュレーションは即座に除外されます。 どのような解決策であっても、テストごとの n に主に依存する構造、理想的には線形または線形に近い構造に問題を削減する必要があります。 

微妙な難しさは、移動と繰り返しの収穫の間の相互作用から生じます。 素朴な直観としては、成長は蓄積されるため、ポジションを再検討することは有益であるかもしれないが、リセット操作はその蓄積を破壊するというものです。 これにより、明らかではないエッジ動作が発生します。 

いくつかの小さな例で落とし穴を明らかにします。 

移動せずに単一のセルに留まる場合、世界的な成長により増加する値を繰り返し収集しますが、同時に同じセルをリセットし続けることになります。これは、最初の訪問後に基本値の蓄積された利益をすべて失うことを意味します。 じっとしている素朴な貪欲さは明らかに最適ではありません。 

積極的に動きすぎると、収穫ではなく歩くことに費やし、潜在的な利益を失います。 最適なソリューションでは、移動距離と高価値セグメントの収集のバランスを取る必要があります。 

もう 1 つの注意が必要なエッジ ケースは、k が 0 の場合です。 その場合、値はまったく増加せず、問題は、利点を再考することなく、最初に訪問した値の合計を最大化するウォークを選択することになります。 これにより、ソリューションは静的ケースと動的ケースを均一に処理するようになります。 

## アプローチ

 最初のアプローチは、プロセスを段階的に直接シミュレートすることです。 各タイム ステップで、すべての値を増やし、現在の位置を答えに追加してリセットし、次の手を選択します。 これは正しいですが、まったく実行不可能です。 各ステップでは、配列全体を更新するか、遅延構造を維持する必要があり、テスト ケースごとに最大 10^6 のステップが必要となり、最悪の場合は 10^11 のオーダーの演算が発生します。 

重要な観察は、世界的な成長の要素が経路から独立しているということです。 すべてのステップは、位置に関係なく、現在のタイム ステップで乗算された同じ加法項 k に寄与します。 これは、成長への貢献全体を動きの最適化から切り離すことができることを意味します。 一度分離すると、残る問題は純粋に初期値と再訪問によって導入されるペナルティに関するものになります。 

均一な成長の寄与を除去した後、問題は、各位置がその初期値に一度だけ寄与するライン上の歩行を選択することになり、位置を再訪しても寄与は増加せず、移動予算を無駄にする可能性があります。 これにより、反復せずにノードを訪問する線上の最適な歩行はセグメント上に存在する必要があるため、連続セグメントを形成する個別の訪問位置のシーケンスを選択するという問題が軽減されます。

セグメントを訪問するコストは、最初の位置から開始してセグメントをどのように移動するかによって異なります。 固定開始点 p から区間 [l, r] をカバーするには、まず 1 つの終点まで歩いてから、区間全体をスイープする必要があります。 これにより、方向に応じて 2 つの可能な横断コストが生じます。 

これにより、問題は、幾何学的実現可能性制約を伴う最大合計部分配列に変換されます。つまり、t0 ステップ内で区間を完全に横断できるように、p を含む最良の区間が必要になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ステップシミュレーション | O(t0・n) | O(n) | 遅すぎる |
 | トラバーサル制約による間隔の最適化 | テストごとの O(n) (償却) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 許容移動回数内でセグメント内のすべての位置を訪問できるように、開始位置 p を含むセグメント [l, r] を選択することに問題を集約します。 セグメントのスコアは、そのセグメントにわたる v[i] の合計です。 

1. p を含むセグメント [l, r] を修正します。 再訪問しても収集される基本値は増加しないため、作業者はこのセグメント内の選択されたすべての位置を、繰り返し行わずに何らかの順序で訪問する必要があります。 
2. p から開始して [l, r] 内のすべての点を訪問するために必要な最小ステップ数を計算します。 自然な走査順序は 2 つあります。 最初に左に行く場合、p から l まで歩き、次に r までスイープし、コストは (p - l) + (r - l) になります。 最初に右に進む場合、p から r まで歩き、次に l に戻ります。コストは (r - p) + (r - l) になります。 
3. セグメントの実際のコストは、これら 2 つの値の最小値です。 セグメントが実現可能であるためには、このコストが最大でも t0 であることが必要です。 
4. 次に、p を含むすべての実行可能なセグメントにわたって v[i] の合計を最大化する必要があります。 これは、自明ではない実現可能性制約を伴う古典的な間隔最適化問題です。 
5. l と r に対して 2 ポインター手法を使用します。 固定された各 l について、実現可能性を維持しながら、r を可能な限り拡張します。 セグメントの合計を O(1) で計算できるように、プレフィックスの合計を維持します。 
6. 導出されたコスト式を使用して実現可能性をチェックすることにより、両方の走査ケースを暗黙的に評価し、各 (l, r) について有効な構成のみを考慮するようにします。 

### なぜ効果があるのか

 最適な戦略は、一連の異なる位置を訪問するウォークに対応します。 空のスペースを横切る無駄なステップを避けたい場合は、直線上でそのようなセットは連続した間隔を形成する必要があります。 固定間隔では、最適なトラバーサルは、p から始まる 2 つの単調スイープの 1 つに縮小されます。 ゲインは、どのポジションを訪問する順序ではなく、どのポジションを訪問するかによってのみ依存するため、間隔の実現可能性を確認し、その合計を最大化するだけで済みます。 これにより、動的な移動の問題が静的な間隔の選択の問題に変換されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, p = map(int, input().split())
    a = list(map(int, input().split()))
    k, t0 = map(int, input().split())

    p -= 1

    # prefix sums for interval queries
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    def seg_sum(l, r):
        return pref[r + 1] - pref[l]

    ans = 0
    r = p

    # two pointers over left endpoint
    for l in range(p, -1, -1):
        if r < l:
            r = l

        while r < n:
            # cost if go left first then right
            cost_left = (p - l) + (r - l)
            # cost if go right first then left
            cost_right = (r - p) + (r - l)
            if min(cost_left, cost_right) <= t0:
                r += 1
            else:
                break

        ans = max(ans, seg_sum(l, r - 1))

    print(ans)

if __name__ == "__main__":
    solve()
```実装では、プレフィックスの合計を事前計算して、一定時間で間隔の合計を評価します。 メイン ループは左のエンドポイントを固定し、トラバーサル制約が満たされたまま右のエンドポイントを貪欲に拡張します。 実現可能性チェックは、開始位置からの 2 つの可能なスイープ命令を直接エンコードします。 

よくある実装の落とし穴は、2 ポインター展開での off-by-one の処理です。 ポインタ r は排他的として維持されるため、すべての実現可能性チェックでは実際の間隔のエンドポイントとして r - 1 が使用されます。 もう 1 つの微妙な点は、開始位置が中心にない場合、一方の方向を無視すると最適なセグメントが失われることになるため、すべてのステップで両方のトラバース方向が考慮されるようにすることです。 

## 実用的な例

 n = 5、p = 3、値 [1、3、2、5、4] の小規模な構成を検討し、短いセグメントのみが実行可能であるように小さい t0 を想定します。 

間隔がどのように拡大するかを調べます。 

| l | r | セグメント | コストは左から順 | コストを右から優先 | 実現可能 | 合計 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 3 | 3 | [4] | 0 | 0 | はい | 5 |
 | 2 | 3 | [3,4] | 1 | 2 | はい | 7 |
 | 1 | 3 | [2,3,4] | 2 | 4 | おそらくt0によって異なります。 10 |

 これは、間隔を拡張すると合計が増加する一方で、走査コストも増加すること、および最適なソリューションは、純粋に値の密度ではなく、実行可能な最大の間隔によって決定されることを示しています。 

p が終点付近にある 2 番目の例は、非対称性を示しています。 

n = 4、p = 1、値を [10, 1, 1, 10] とします。 左端から開始して、最初に右に進むことが常に最適であるため、重要なトラバース方向は 1 つだけです。 コスト計算式では自動的に安価な方向が選択されるため、アルゴリズムはこれを自然に捉えます。

 ## 特殊なケース

 p が位置 1 にある場合、左への移動が存在しないため、アルゴリズムは左ファーストトラバーサルの使用を正しく回避する必要があります。 l が p に等しい場合は常に (p - l) がゼロになり、実行不可能な間隔は自然に除外されるため、コスト式は依然として正しく動作します。 

t0 が非常に大きい場合、配列全体が実行可能になり、2 ポインター ウィンドウが全範囲に拡張されるため、アルゴリズムは配列全体の合計を正しく返します。 

すべての値がゼロの場合、動きに関係なく結果はゼロになります。また、プレフィックスの合計はすべての候補にわたってゼロのままであるため、アルゴリズムが誤って長いセグメントを優先することはありません。
