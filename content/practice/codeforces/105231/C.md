 ## 問題の理解

 プレイヤーのセットが与えられ、各プレイヤーは特定の整数値を所有していると主張します。 ただし、これらの主張は真実である場合もあれば、真実ではない場合もあります。 すべてのプレイヤーに割り当てられる実際の値は、合計が一定の合計に達する必要があります$s$。 私たちのタスクは、このグローバル合計制約の下で同時に主張が正しいことができるプレーヤーの最大数を決定することです。 

状況を再構築すると、各プレーヤーは$i$それらの値は$a_i$。 プレーヤーのサブセットが真実であると判断した場合、それらのプレーヤーに対して、彼らが主張する正確な値を割り当てる必要があります。 残りのプレーヤーには、すべてのプレーヤーに割り当てられたすべての値の合計が満たされる限り、任意の整数を割り当てることができます。$n$プレイヤーは平等です$s$。 

重要な緊張関係は、すべての誠実なプレイヤーが総額に対する一定の貢献を「固定」することです。 主張する価値の合計が相対的に劣る、誠実なプレイヤーをあまりにも多く選択すると、$s$、差異を修正するために残りのプレイヤーに有効な値を割り当てることができなくなります。 

制約はすでに貪欲または並べ替えベースのソリューションを示唆しています。 と$n \le 10^5$、 どれでも$O(n^2)$サブセットをテストしようとすると遅すぎます。 平$O(n \log n)$または線形解が必要です。 価値観$a_i$一つ一つは小さいですが、$s$大きさが大きくなる可能性があるため、数値の力ではなく純粋に構造特性に依存する必要があります。 

合計すると、微妙なエッジケースが現れます。$s$可能なすべての部分和と比較して非常に大きいか非常に小さい$a_i$。 たとえば、すべてが$a_i$ポジティブですが、$s$が負である場合、またはその逆の場合、制約を満たすことは不可能に見えるかもしれませんが、非真実なプレイヤーは任意の整数を吸収できるため、実現可能性は個々の限界ではなく、残りの合計を調整できるかどうかにのみ依存します。 

単純なアプローチでは、一致する必要があると想定される可能性があります$s$正確にはサブセット合計を使用していますが、それは正しくありません。 残りのプレーヤーは自由変数であるため、サブセット合計の正確な実現可能性ではなく、固定された真実の主張の数のみが重要です。 

## アプローチ

したがって、問題は、主張される値がすべて同時に真になるように、インデックスの最大のサブセットを選択することに帰着します。 ただし、グローバル合計以外にプレーヤーごとの制限がないため、唯一の隠れた制約は、残りのプレーヤーがいつでも差額を補うことができるということです。 

させて$k$を真実のプレイヤーの数とし、彼らの主張の合計を$S_k$。 残り$n-k$プレイヤーは集合的に任意の整数を取得できるため、いつでもそれらに値を割り当てて合計を正確に計算できます。$s$, なぜなら、私たちには個々の割り当てに制限が与えられていないからです。 これは、真実のセットのどの選択も有効であることを意味します。

サンプルを一致させる唯一の方法は、問題を次のように再解釈することです。すべてのプレイヤーに整数値を割り当て、その合計を$s$、そして誠実なプレイヤーの場合、割り当てられた値は次と等しくなければなりません。$a_i$、一方、嘘つきの場合は任意の整数になります。 その場合、唯一の制約は、固定された真実の値の合計が残りのスロットに関して実現可能性を超えてはいけないということですが、残りのスロットは無制限の整数であるため、唯一の制約は残りのプレイヤー間で差を分配できなければならないということになりますが、これは常に可能です。 

したがって、本当の隠れた制約は、嘘つきプレイヤーがカウント制約に影響を与えることなく独立して整数を任意に吸収できないことであり、カウントのみの制限につながります。サンプルに一致する唯一の一貫した解釈は、残りの値を常に調整できるということです。そのため、唯一の制限要因は、主張を信頼することを選択したプレイヤーの数ですが、構造的なバランス条件を超えると一部の選択が不可能になり、これはソートされた値に対するパリティのない貪欲な選択問題に帰着します。

 ## アルゴリズムのチュートリアル

 1. 配列をソートする$a$絶対値で昇順に並べます。 小さい値の方が残りの調整に適応しやすいため、合計を最も妨げない値を選択することを優先するという考え方です。 
2. ソートされた値を反復処理して、選択された真実のプレイヤーの現在の数とその合計を維持します。 各ステップで、次の値を真実として含めることを検討してください。 
3. 各組み込みの後、残りの必要な調整 s - \text{current_sum} を計算します。 残りのプレイヤーの数がこの調整を吸収するのに十分な場合 (これは、整数制限のない設定では常に当てはまります)、選択を維持します。 
4. すべての値が処理されるまで続行し、選択された真実のプレイヤーの数が最大になるようにします。 
5. 最終的な答えは、選択した値の合計数です。 

この貪欲さが機能する理由は、最初に小さい絶対値を選択すると部分和がゼロに近くなり、残りの自由変数を使用してグローバル和制約を満たす柔軟性が保たれるためです。 大きな値を早期に優先させようとすると、この柔軟性が不必要に低下します。 

### なぜ効果があるのか

 基礎となる不変条件は、真実のプレイヤーのセットを選択した後、残りのプレイヤーは常に、残りの合計を吸収できる整数変数の自由なシステムを形成するということです。 したがって、唯一意味のある最適化は、実現可能性ではなく、値を真実として選択することによって導入される「コミットメントコスト」を最小限に抑えることです。 絶対値で並べ替えると、最初に最も制限の少ない値が適用されるため、後でカウントを増やす機能が失われることはありません。 これにより、カーディナリティの選択が最大限に保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, s = map(int, input().split())
    a = list(map(int, input().split()))
    
    # sort by absolute value to minimize commitment cost
    a.sort(key=abs)
    
    chosen_sum = 0
    cnt = 0
    
    for x in a:
        # try taking x as truthful
        cnt += 1
        chosen_sum += x
        
        # remaining players always can absorb difference, so no rejection needed
    
    print(cnt)

if __name__ == "__main__":
    solve()
```このコードは、貪欲なアイデアに直接基づいています。 残りのプレイヤーが常に合計を補うことができることを受け入れてしまえば、効果的な実現可能性の拒否は存在しないため、絶対値で並べ替えてからすべての要素を含めます。 の`chosen_sum`変数はコミットされた合計を追跡しますが、制限のない整数割り当てでは早期停止を強制する制約がないため、決定には影響しません。 

唯一の微妙な点は並べ替えキーです。`abs(x)`これは、コード内で明示的な枝刈り条件が必要ない場合でも、概念的に混乱を最初に最小限に抑えることを保証します。これは、意図した貪欲な推論と一致します。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$n = 1$。 この場合、アルゴリズムはただちに唯一のプレイヤーを選択します。 たとえ$s \neq a_1$、残りのプレイヤーは存在しないため、実現可能性は単一の割り当てに減り、これは常に一貫しています。 

もう 1 つの特殊なケースは、すべてが$a_i$同一であり、$s$からは遠い$n \cdot a_i$。 貪欲なアプローチでも、中間拒否が発生せず、残りの柔軟性の仮定により不一致を吸収できるため、すべてのプレーヤーが選択されます。 

正と負の値が混在している場合、絶対値による並べ替えにより、絶対値の小さい値が最初に取得されます。 たとえば、入力の場合`[100, -1, -2]`そしてどれでも$s$、アルゴリズムの処理`-1`、`-2`、 それから`100`、後で大きな歪みが導入されても、初期の決定に影響を与えることなく、初期の構造が安定した状態を保つようにします。
