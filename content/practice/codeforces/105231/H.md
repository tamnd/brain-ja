 ## 解決策
 ## 問題の理解

 大きな数値グリッドが与えられています。これを値の行列と考えてください。 また、次のサイズの小さな長方形の「フィルター」のサイズも修正します。$k \times l$。 このフィルターは、大きなグリッドのすべての有効な位置上でスライドされ、各位置で、カバーされた要素の加重合計を取得することによって 1 つの出力値を生成します。 プロセス全体の最終出力は、これらすべてのスライディング ウィンドウの結果を含む別の行列です。 

重要な自由は、フィルター自体が与えられていないことです。 代わりに、フィルターの各セルを個別に選択できますが、すべてのセルは次の 3 つの値のいずれかである必要があります。$-1$、$0$、 または$1$。 フィルターを選択した後、畳み込み出力行列を計算し、その出力内のすべての値を合計します。 タスクは、この最終的な合計を最大化することです。 

制約$n, m \le 1000$入力行列に最大 100 万個のセルを含めることができることを意味します。 カーネルの数が膨大であるため、考えられるすべてのカーネルを列挙しようとするソリューションは直ちに不可能です。$3^{k \cdot l}$、指数関数的に増加します。 単一のカーネルに対して単純に畳み込みを計算しても、それを繰り返すと非常に遅くなります。 

本当の制約圧力は、ほぼ線形または線形に近いものが必要であるということです。$nm$、次のようなものから$O(nm \cdot k \cdot l)$最大サイズではすでに境界線に達しているでしょう。 

単純な推論を打ち破る可能性がある微妙な問題は、カーネルの選択が複数の位置間で相互作用すると仮定することです。 たとえば、カーネルのセルが、全体的な最適化を必要とする複合的な方法で重複領域に影響を与えると誤って考える可能性があります。 もう 1 つの罠は、候補カーネル値ごとに畳み込みを明示的にシミュレートする必要があると仮定していることです。 どちらも不必要であり、過度の複雑さにつながります。 

## アプローチ

 この問題を直接考える方法は、カーネルを修正して畳み込み出力を計算し、すべてを合計することです。 それは簡単です。出力位置ごとに、$k \times l$カーネルと対応する部分行列と合計。 これをすべての出力位置に対して繰り返すと、総コストは次のようになります。$O((n-k+1)(m-l+1)kl)$、最悪の場合は約$10^{12}$実行可能な限界をはるかに超えた操作。 

主な単純化は、合計の順序を逆にすることによって実現されます。 「各出力セルはパッチに適用されたカーネルに依存する」と考えるのではなく、「各カーネル セルが多くの出力セルに寄与する」と考えます。 合計を交換すると、各カーネルの位置が$(x,y)$入力行列から完全に導出された固定量が乗算されます。 この量は他のカーネル セルには依存しません。 

この変換後、問題はスライディング ウィンドウに関するものではなくなり、単純なセルごとの最適化になります。つまり、カーネルの位置ごとに、$-1$、$0$、 または$1$線形式を最大化します。 最適な選択は、サインによって即座に決定されます。

 ## アルゴリズムのチュートリアル

 カーネルの選択を入力の集計から分離する方法で合計スコアを書き換えます。 

1. ヘルパー行列を計算する$S$サイズの$k \times l$、各エントリは$S[x][y]$カーネル位置に対する入力グリッドの合計寄与度を表します$(x,y)$すべての出力配置にわたって。 これは、カーネル セルが実行されたときに各入力セルがカバーされる回数を数えることによって取得されます。$(x,y)$畳み込みで使用されます。 
2. カーネル セルが固定されていることを確認します。$(x,y)$貢献する$K[x][y] \cdot S[x][y]$最終的な答えへ。 これは、合計スコアがカーネル セルの独立した寄与の合計であることを意味します。 
3. 各カーネル エントリは {-1, 0, 1} から独立して選択できるため、各項を個別に最大化します。 もし$S[x][y]$ポジティブです、選択してください$K[x][y] = 1$。 マイナスの場合は選択してください$K[x][y] = -1$。 ゼロの場合は選択してください$0$。 
4. 最終的な答えは、すべての絶対値の単純な合計です。$S[x][y]$。 

したがって、重要な計算タスクは、すべてを計算することです。$S[x][y]$効率的に。 それぞれ$S[x][y]$入力グリッドの固定部分行列の合計、具体的には で始まる四角形に対応します。$(x,y)$高さのある$n-k+1$と幅$m-l+1$。 これは、2D プレフィックス合計を使用してセルごとに一定時間で計算できます。 

### なぜ効果があるのか

 重要な特性は、畳み込み和の線形性です。 合計を交換した後、目的はカーネル行列と入力から導出された固定行列の間のドット積になります。 このフォームに入ると、各決定変数が$K[x][y]$和の中の 1 つの項にのみ影響し、他の項との結合はありません。 これにより、すべての組み合わせ構造が削除され、問題はセルごとに独立した符号の選択に減ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m, k, l = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    # prefix sum
    ps = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(n):
        row_sum = 0
        for j in range(m):
            row_sum += a[i][j]
            ps[i + 1][j + 1] = ps[i][j + 1] + row_sum

    def get(x1, y1, x2, y2):
        return ps[x2][y2] - ps[x1][y2] - ps[x2][y1] + ps[x1][y1]

    h = n - k + 1
    w = m - l + 1

    ans = 0
    for i in range(k):
        for j in range(l):
            x1, y1 = i, j
            x2, y2 = i + h, j + w
            s = get(x1, y1, x2, y2)
            if s > 0:
                ans += s
            else:
                ans -= s

    print(ans)

if __name__ == "__main__":
    main()
```プレフィックス合計の構築は、部分行列合計クエリを定数時間に圧縮します。これは、各カーネル位置にそのようなクエリが 1 つ必要なため、不可欠です。 長方形の境界は、カーネル セルが有効な畳み込み配置に参加する頻度に関する観察から直接得られます。 

よくある実装上の間違いは、プレフィックス合計での off-by-one の処理です。 ここで、プレフィックス配列のサイズが調整されます$(n+1) \times (m+1)$そのため、部分行列クエリがクリーンになり、特別なケーシング エッジが必要なくなります。

 ## 特殊なケース

 まれなケースは、特定のカーネル位置のすべての部分行列の合計がゼロになる場合です。 このような状況では、そのセルに対する最適な選択は、カーネル値をゼロに設定し、何も寄与しないことです。 アルゴリズムはこれを自然に処理します。$|0| = 0$, したがって、何も足したり引いたりすることはありません。 

もう一つのケースは次のような場合です。$k = n$そして$l = m$。 ここで、畳み込みの位置は 1 つだけであり、リダクションにおける長方形のサイズは次のようになります。$1 \times 1$。 このアルゴリズムは、対応する入力セルの符号に基づいて各カーネル セルを選択するもので、これは完全なオーバーラップの直接解釈と一致します。 

最後の微妙なケースは、入力値の大きさは大きいが、符号が混在している場合です。 このソリューションでは 64 ビット Python 整数が暗黙的に使用されるため、オーバーフローの心配はなく、制限された整数の加算のみを蓄積するため、プレフィックス合計は安定したままになります。
