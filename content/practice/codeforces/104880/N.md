 ## 解決策
 ## 問題の理解

 長さの隠し配列を操作しています$n$、各位置は衣類のアイテムを表し、色を格納します。$1$に$n$。 私たちの目標は、隠された順列のような構成全体を復元することです。ただし、繰り返しが許可されているため、順列であることが保証されません。 

実行できる唯一の操作は、長さの完全な推測配列を送信することです。$n$。 各推測の後、システムは正確に正しい位置の数、つまりインデックスの数を返します。$i$満足する$a_i = b_i$、 どこ$b$は隠し配列です。 すべての位置が正しい場合は、すぐに終了します。 それ以外の場合は、最大次数の厳格な上限を設けて続行します。$10n$クエリ。 

したがって、このタスクは、グローバルなハミング類似性スコアのみという非常に弱いフィードバックを伴う対話型の再構成問題です。 

制約$n \le 500$およびクエリ制限$10n$すべての値に対して位置ごとのブルートフォースを必要とするアプローチは限界に達していますが、それでも妥当であることを強く示しています。 直接的な単純な戦略は次のようになります。$O(n^2)$推測かそれ以上の場合は、慎重に構造化しないとクエリの予算を超過する危険があります。 

調整せずに独立した位置ごとの推測を試みると、微妙な失敗のケースが発生します。 たとえば、1 つを除くすべての位置を固定し、その位置をすべての値で循環させる場合、次のことが必要になる可能性があります。$n$インデックスごとのクエリの合計$n^2$、次の場合に制限に違反します。$n = 500$。 

主な課題は、フィードバックが集約されるため、単純に座標を分離するとコストが高すぎることです。 

## アプローチ

 強引な考え方では、それぞれの位置を独立して決定しようとします。 固定インデックスの場合$i$、他のすべての位置を一定に保ち、すべてを試すことができます$n$位置で可能な色$i$。 スコアが 1 つ増加するたびに、その位置の正しい値が見つかったことになります。 

これは正しいです。スコアの差により、単一の座標での正しさが分離されるからです。 ただし、このアプローチにはコストがかかります$n$ポジションごとのクエリの結果、$n^2$合計クエリ数。 のために$n = 500$、これは$250{,}000$許可をはるかに超えるクエリ$5000$。 

この改善は、ポジションを 1 つずつ分離する必要がないことに気づいたことから生まれました。 各クエリはグローバルな位置合わせ情報を提供するため、座標を個別に修正するのではなく、完全な候補配列を繰り返し改善するものとして問題を扱うことができます。 位置ごとに値をスキャンする代わりに、現在の推測を維持し、変更によって正確性が向上するという証拠がある場合にのみそれを変更します。 

重要なアイデアは、ハミング類似度を貪欲に山登りすることです。座標が間違っていると疑われるたびに、それを別の値に置き換えてみて、スコアが改善した場合にのみ変更を保持します。 各改善により正しい位置の数が厳密に増加し、スコアは次の制限を受けるため、$n$、最大でもお受けできます。$n$全体的に改善され、プロセスが効率化されます。$10n$クエリ。 

これにより、問題が座標方向の検索からグローバルな増分最適化に変換されます。

 ## アルゴリズムのチュートリアル

 たとえばすべて 1 など、任意に初期化された現在の推測配列を維持します。 また、隠し配列に対する現在のスコアも維持します。 

1. すべての位置を 1 に設定して推測配列を初期化し、クエリを実行して初期スコアを取得します。 これにより、構造を想定せずにベースラインの位置合わせが行われます。 
2. ポジションごとに$i$、現在の値が正しいかどうかを判断しようとします。 一時的にのみ変更します$a_i$、可能な値を順に循環します。$1$に$n$。 
3. 位置での各試行値について$i$、完全なクエリを発行します。 返されたスコアが現在の最高スコアと比較して増加した場合、この値を受け入れ、配列を永続的に更新します。 この増加により、この位置が正しくなった、または正しくなったことが保証されます。 
4. 変化がない場合、ポジションのスコアは向上します$i$、以前の値を復元します。 これにより、現在のソリューションの品質が低下することがなくなります。 
5. すべてのインデックスに対してこのプロセスを継続し、クエリが返されるまで配列を繰り返し調整します。$n$、完全な正しさを意味します。 

重要な設計上の選択は、グローバル スコアを厳密に改善する変更のみをコミットすることです。これにより、振動が防止され、着実な進歩が保証されます。 

### なぜ効果があるのか

 単一のインデックスの変更は、隠し配列との一致に関してそのインデックスでの正確さにのみ影響するため、受け入れられる変更ごとに正しい位置の数が 1 つずつ増加します。 スコアは上記に制限されているため、$n$、私たちは最大でも受け入れることができます$n$改善。 スコアを向上させないクエリはすべて破棄されるため、無駄なクエリも位置ごとに制限されます。 これにより、クエリの総数が線形予算内に収まるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(arr):
    print(*arr)
    sys.stdout.flush()
    x = int(input())
    if x == -1:
        sys.exit(0)
    return x

def solve():
    n = int(input())

    cur = [1] * n
    cur_score = ask(cur)

    for i in range(n):
        best_val = cur[i]
        best_score = cur_score

        for v in range(1, n + 1):
            if v == cur[i]:
                continue

            cur[i] = v
            score = ask(cur)

            if score > best_score:
                best_score = score
                best_val = v

            if score == n:
                return

            cur[i] = best_val

        cur[i] = best_val
        cur_score = best_score

    # final check
    ask(cur)

if __name__ == "__main__":
    solve()
```このコードは、現在の候補配列を維持し、その場で更新します。 ポジションごとに、考えられるすべての色を試し、全体的なスコアを向上させる色だけを保持します。 インタラクションプロトコルは即時の出力配信に依存しているため、すべてのクエリ後のフラッシュは不可欠です。 スコアに達した場合の早期終了$n$解決後の不要なクエリを防ぎます。 

微妙なディテールが復元中`cur[i]`失敗した試行の直後。 これがないと、後のクエリで誤った一時状態が蓄積され、スコアの解釈が破損します。

 ## 特殊なケース

 重要なエッジケースは、複数の値が同じスコアを与える場合です。 たとえば、現在の推測がすでに多くの位置と一致している場合、間違った位置を変更しても、他の場所でエラーが補正されるため、スコアがすぐに上がらない可能性があります。 このアルゴリズムは、厳密な改善が行われた場合にのみ変更をコミットするため、トラップされることを回避します。 

隠し配列を考慮する$[1,1,1,1]$そして現在の推測$[1,2,2,2]$。 スコアは 1 です。1 つの間違った位置を 2 から 1 に変更すると、スコアは 2 に増加するため、アルゴリズムは一度に 1 つの座標を正しく修復します。 変更によってスコアが改善されない場合、その変更はすぐに破棄され、ドリフトを防ぎます。 

これにより、アルゴリズムは有害な変更を決して受け入れず、受け入れられたすべての動きの正確性が厳密に向上し、正しい配列での最終的な終了が保証されます。
