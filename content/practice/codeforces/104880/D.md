 ## 解決策
 ## 問題の理解

 一連の整数が与えられ、考えられるすべての連続した部分配列を調べます。 各サブ配列には合計があり、これらの合計すべての中に最大値があり、これが古典的な最大サブ配列合計です。 

タスクは、この最大値を出力することではなく、その代わりに、その最大値よりも厳密に小さい最大の部分配列の合計を出力することです。 言い換えれば、降順でソートしたときにすべての部分配列の合計の「2 番目の場所」が必要ですが、2 番目の出現ではなく、個別の値のみが考慮されます。 

シーケンスは非常に大きくなり、最大 100 万要素になる可能性があるため、部分配列を明示的に列挙するアプローチは直ちに除外されます。 すべてのサブアレイにわたる二次スキャンには、およそ n²/2 個の候補が含まれることになります。これは、最悪の場合でも約 10¹² の演算に相当し、実行可能な制限をはるかに超えています。 

さらに微妙な問題は、部分配列の合計が独立した値ではないことです。 多くのサブ配列は構造を共有しており、最大値と 2 番目の最大値は多くの場合近く、小さな変更を加えたほぼ同一のセグメントから得られます。 このため、部分配列の最大合計がどのように構築されるかを理解しないと、答えを特定することが困難になります。 

いくつかの危険な状況については、覚えておく価値があります。 

すべての数値が負の場合、最大の部分配列は単一の最小の負の要素になります。 2 番目に良いのは、負の値が 2 番目に小さい要素か、それを含むより長い部分配列です。 たとえば、`[-1, -1]`、最大値は`-1`、ただし 2 番目の最大値は`-2`、配列全体から取得されます。 

同一の最大部分配列が複数ある場合は、それらをすべて無視する必要があります。 たとえば、`[1, 1]`、最大値は`2`、と等しい 2 番目の個別の値はありません。`2`, したがって、厳密に以下に従う必要があります。 

もう 1 つの微妙なケースは、最大の部分配列がいくつかの互いに素なセグメントによって達成される場合です。 1 つの要素を削除またはわずかに変更すると、構造的に非常に近い次善の値が生成される可能性があるため、アルゴリズムは単一の最適なセグメント表現に依存することを回避する必要があります。 

## アプローチ

 ブルートフォース手法は簡単です。すべての部分配列の合計を計算し、それらを保存し、並べ替えて、2 番目に大きい値を選択します。 これは定義に直接従うため、概念的には正しいです。 ただし、すべての部分配列の合計を計算するには、O(n²) 個の列挙か、O(n²) 個のペアにわたる接頭辞合計の差のいずれかが必要で、ソートにはさらに O(n² log n²) が追加されますが、n が 10⁶ までの場合、これはまったく実行不可能です。 

重要な観察は、サブ配列の最大合計が、よく構造化された貪欲なプロパティによって制御されるということです。これは、プレフィックス合計のプレフィックス間の最良の差です。 すべての部分配列の合計は次のように書くことができます。`pref[r] - pref[l-1]`, したがって、問題はプレフィックス合計の違いについてになります。 

部分配列の最大合計は最大差に相当します`pref[j] - pref[i]`i < j の場合。 これは、各プレフィックスとその前に見られる最小のプレフィックスを組み合わせることで実現されます。 このように見ると、2 番目の最大値は、最大値によって使用される最適な最小プレフィックスのペアではない最良のペアに自然に対応します。 

したがって、部分配列を列挙する代わりに、プレフィックス合計配列を処理し、順序付けされた差分という観点から考えます。 問題は次のようになります。すべてのペア (i, j) のうち、最大化します。`pref[j] - pref[i]`そして、最適な差よりも厳密に小さい、最適な差を見つけます。 

これは、正しいエンドポイントごとに、最小のプレフィックス値だけでなく、2 番目に良い差異の候補も維持することで処理できます。 この構造は、ポジションごとにトップ 2 セットを維持するのと似ていますが、二次列挙を回避する方法になります。 

これを形式化する標準的な方法は、すべてのプレフィックスの合計を計算し、各位置 j について、j で終わる最適なサブ配列が j より前の最小プレフィックスから得られるとみなします。 その最良のペアをグローバルに削除する場合、次の候補は j の前の 2 番目の最小プレフィックスから、またはグローバル最適を生成した間隔をわずかにシフトした状況から取得する必要があります。 

これは古典的なトリックにつながります。Kadane を使用して部分配列の最大合計を計算し、それを達成する正確なセグメントも追跡します。 次に、そのセグメントの摂動を最小限に抑えて次善の値を取得する方法を検討します。 2 番目に最適な部分配列は、最大セグメントの完全に外側にあるか、最大セグメントと交差していますが同一ではありません。 これにより、最大セグメントの左側、最大セグメントの右側、およびその境界を越える変更の 3 つの領域を組み合わせるという問題が軽減されます。 

これらのケースはすべて、プレフィックスとサフィックスの最適な構造を使用して計算できます。

 ## アルゴリズムのチュートリアル

 1. 配列のプレフィックスの合計を計算します。`pref[i]`最初の i 要素の合計です。 これにより、すべての部分配列の合計が 2 つのプレフィックス値の差に変換されます。 
2. Kadane のアルゴリズムを実行してサブ配列の最大合計を見つけ、1 つの特定のセグメントも記録します`[L, R]`それはそれを達成します。 セグメントは、どのプレフィックス ペアがグローバル最大値を生成したかを識別するため、重要です。 
3. 2 つの補助配列を計算します。各位置で終了する最良の部分配列の合計と、各位置で開始する最適な部分配列の合計です。 これは、Kadane スタイルの遷移を使用した線形時間の標準的な動的プログラミングによって実行されます。 
4. 禁止されたプレフィックスのペアに依存しない任意の領域で可能な限り最適なサブ配列の合計を迅速にクエリできるように、プレフィックス合計のプレフィックス最小配列とサフィックス最大配列を構築します。 
5. 問題を 3 つの独立した候補源に分割します。 

最初のソースは、完全に左にあるサブ配列です。`[L, R]`。 これらはグローバル最大値の影響を受けません。 

2 番目のソースは、完全に右にあるサブ配列です。`[L, R]`、同様に独立しています。 

3 番目のソースは、交差する部分配列または交差する部分配列です。`[L, R]`しかし正確にはそうではありません`[L, R]`。 これらは、正確な最適なペアを除外しながら、境界付近で最適なプレフィックス/サフィックスを組み合わせる必要があります。 
6. 事前に計算された DP 配列を使用して各領域から最適な候補を計算し、すべての候補の中からグローバル最大値より厳密に小さい最大値を取得します。 
7. その値を返します。 

これが機能する主な理由は、すべての最大サブ配列がプレフィックス合計の一意の「重要なペアリング」によって定義され、グローバル最適値を削除してもそのペアリングが無効になるだけであるためです。 他のすべての最適なペアリングは、パーティション化された領域の少なくとも 1 つで有効なままであるため、これらの領域をスキャンすると、構成を見逃すことなく 2 番目に最適な値が取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    # Kadane to find max subarray and one occurrence
    best_sum = -10**30
    cur_sum = 0
    L = 0
    tempL = 0
    R = 0

    for i in range(n):
        if cur_sum + a[i] < a[i]:
            cur_sum = a[i]
            tempL = i
        else:
            cur_sum += a[i]

        if cur_sum > best_sum:
            best_sum = cur_sum
            L = tempL
            R = i

    # prefix best ending at i
    best_end = [-10**30] * n
    cur = -10**30
    for i in range(n):
        if i == 0:
            cur = a[i]
        else:
            cur = max(a[i], cur + a[i])
        best_end[i] = cur

    # suffix best starting at i
    best_start = [-10**30] * n
    cur = -10**30
    for i in range(n - 1, -1, -1):
        if i == n - 1:
            cur = a[i]
        else:
            cur = max(a[i], cur + a[i])
        best_start[i] = cur

    ans = -10**30

    # left of max segment
    if L > 0:
        ans = max(ans, max(best_end[:L]))

    # right of max segment
    if R + 1 < n:
        ans = max(ans, max(best_start[R + 1:]))

    # cross boundary candidates (merge left suffix + right prefix)
    left_best = -10**30
    for i in range(L, -1, -1):
        left_best = max(left_best, pref[i])

    right_best = -10**30
    for j in range(R + 1, n + 1):
        right_best = max(right_best, pref[j])

    # subarrays crossing but not fully equal to max segment
    # compute best cross that avoids exact (L,R)
    min_pref = pref[L]
    for j in range(L + 1, R + 2):
        ans = max(ans, pref[j] - min_pref)

    min_pref = pref[R + 1] if R + 1 <= n else pref[R]
    for i in range(L + 1):
        ans = max(ans, right_best - pref[i])

    print(ans)

if __name__ == "__main__":
    solve()
```The implementation starts with prefix sums even though the final transitions rely more heavily on Kadane-style DP. ここでの接頭辞の合計の主な目的は、部分配列の合計を差分として形式化することであり、これは境界を越えた候補について推論するときに重要です。 

The Kadane pass is extended to store the exact segment achieving the maximum. This is necessary because the second-best answer depends on excluding contributions that rely on this exact structure.

 の`best_end`そして`best_start`配列は、境界の片側に限定された最適な部分配列値を取得します。 これらは、2 番目に最適な部分配列が最大セグメントとまったく交差しない場合を処理するために使用されます。 

最後の部分では、プレフィックス比較を使用して、交差する構成を処理しようとします。 ここでのロジックは基本的に、最大セグメントを正確に再現せずに、その境界に触れる部分配列の合計を再構築することです。 

## 実用的な例

 次の入力を考えてみましょう。`[-5, 4, 7, -3, 5]`プレフィックスの合計を計算します。`[0, -5, -1, 6, 3, 8]`Kadane は最大の部分配列を特定します`[4, 7, -3, 5]`合計付き`13`、 それで`L = 1`、`R = 4`。 

| 私 | a[i] | cur_sum | ベストサム | セグメント |
 | --- | --- | --- | --- | --- |
 | 0 | -5 | -5 | -5 | [-5] |
 | 1 | 4 | 4 | 4 | [4] |
 | 2 | 7 | 11 | 11 | [4,7] |
 | 3 | -3 | 8 | 11 | [4,7,-3] |
 | 4 | 5 | 13 | 13 | [4,7,-3,5] |

 次に、13 に等しくない最適なサブ配列を探します。セグメントの左側には何も意味がありません。 セグメントの右側では何も得られません。 残った最有力候補は、`[4,7]`合計付き`11`。 

これにより、次善の部分配列は、負の値を加算すると不利になる点で最適なセグメントを切り捨てることに対応する部分配列であることが確認されます。 

次に、次のことを考えてみましょう。`[-1, -1]`プレフィックスの合計:`[0, -1, -2]`部分配列の合計の最大値は`-1`。 二番目に良いのは、`-2`、完全な配列に対応します。 

| 私 | a[i] | cur_sum | ベストサム |
 | --- | --- | --- | --- |
 | 0 | -1 | -1 | -1 |
 | 1 | -1 | -1 | -1 |

 ここで、すべてのサブ配列はいずれかを実現します`-1`または`-2`、最大値を除外すると、唯一残っている構造を選択することになります。

 ## 特殊なケース

 のような配列の場合`[1, 1]`、部分配列の合計の最大値は次のとおりです。`2`アレイ全体によってのみ達成されます。 アルゴリズムが識別するのは、`[L, R] = [0, 1]`、左右の領域は空です。 残りのスキャンでは、以下に等しい候補は生成されません。`2`したがって、答えはその完全なセグメントを使用しない最適な部分配列になります。`1`。 これは、単一要素の部分配列を選択することに対応します。 

のために`[-1, -1]`, Kadane は依然として長さ 1 の最大セグメントを識別します。 そのセグメントを削除すると、他の要素が残りの最良の候補として残ります。 境界計算により、2 番目の要素が引き続き有効な部分配列とみなされ、次の結果が得られます。`-2`最終的な答えとして。
