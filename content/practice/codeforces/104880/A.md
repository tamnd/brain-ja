 ## 解決策
 ## 問題の理解

 長さ 24 のバイナリ文字列としてエンコードされた固定スケジュールが与えられます。各位置は、1 時間目から 24 時間目までの 1 日の 1 時間に対応します。`1`あなたがその時間中働いていることを意味しますが、`0`休んでいるという意味です。 

スケジュールを無効にする唯一の条件は、連続 6 時間の労働時間のブロックが存在することです。 1 日のどこかに、6 つだけで構成される連続した部分文字列が存在する場合`1`キャラクター、スケジュールは有害であると考えられます。 それ以外の場合は許容されます。 

タスクは、そのような禁止されたブロックが存在するかどうかを判断するだけです。 

入力サイズは 24 に固定されていますが、問題の構造は、短いシーケンスにわたる一般的なパターン認識タスクを示唆しています。 長さ 6 の考えられるすべての連続セグメントを検査するソリューションは、長さ 24 の文字列にはそのようなセグメントが 19 個しかないため、ここでは一定時間で実行されます。 

一般的なエッジ ケースは、オフバイワン スキャン ロジックから発生します。 たとえば、与えられた`111110111111`のような素なブロックのみをチェックする不用意な実装です。`[1..6], [7..12]`境界を越えるランを誤って見逃してしまう可能性があります。 もう 1 つの微妙な問題は、ランはどこにでも出現する可能性があり、必ずしも 6 の倍数に揃えられる必要はないということを忘れていることです。 

正しく処理するには、サイズ 6 の重なっているウィンドウをすべてチェックする必要があります。 

## アプローチ

 この問題を解決する総当りの方法は、長さ 6 の可能な連続する部分文字列をすべて調べて、その部分文字列内のすべての文字が正しいかどうかを確認することです。`1`。 文字列の長さは 24 なので、そのような部分文字列は 24 − 6 + 1 = 19 個あります。 各部分文字列の有効性をチェックするには 6 文字を検査する必要があるため、合計の作業量は一定であり、非常に少なくなります。 

入力サイズが固定されており小さいため、このブルートフォース手法はこの設定ではすでに最適です。 ただし、概念的には、文字列の長さが次のようなより一般的なバージョンを考えると便利です。`n`。 その場合、単純なアプローチではサイズ 6 のすべてのウィンドウが検査され、O(n) 個のウィンドウと O(6n) 個の合計チェックが行われ、O(n) に単純化されます。 

重要な点は、部分文字列に対して複雑な関数を計算しているのではなく、単に長さが 6 以上のランが存在するかどうかを検出しているだけであるということです。 これにより、問題は連続した電流の連続を追跡することと同等になります。`1`s. 部分文字列を繰り返し再スキャンする代わりに、実行中のカウンタを維持し、`0`に遭遇します。 カウンターが6になった瞬間にすぐに停止できます。 

これにより、ロジックがスライディング ウィンドウ チェックから定メモリを使用したシングル パスに削減されます。

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`run`ゼロに。 この変数は、連続する現在の長さを表します。`1`これまで見てきました。 
2. 文字列内の各文字を左から右に繰り返します。 
3. 現在のキャラクターが`1`、増分`run`連続記録が続いているため、1 ずつ増えます。 
4. 現在のキャラクターが`0`、リセット`run`連続したシーケンスは壊れているため、0 に設定されます。 
5.アップデート後`run`6 に達しているかどうかを確認します。6 に達している場合は、スケジュールが無効であると直ちに判断し、処理を停止します。 
6. 6 に到達することなくループが終了した場合、スケジュールは有効です。 

重要な考え方は、将来の有効なブロックは連続している必要があり、ブレークは以前の連続性を無効にするため、現在のストリーク以上を記憶する必要はないということです。 

### なぜ効果があるのか

 文字列内の任意のインデックスでの値は、`run`のみで構成されるその位置で終わる最長の接尾辞の長さと正確に等しくなります。`1`s. これは、可能なすべての連続ブロックを意味します。`1`s は暗黙的に次の値として表されます。`run`スキャン中のある時点で。 長さ 6 のブロックがどこかに存在する場合、その最後の文字に到達すると、`run`少なくとも 6 である必要があり、検出がトリガーされます。 逆に、そのようなブロックが存在しない場合は、`run`6 に達することはないため、アルゴリズムはスケジュールを正しく受け入れます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

run = 0
for ch in s:
    if ch == '1':
        run += 1
        if run >= 6:
            print("NO")
            break
    else:
        run = 0
else:
    print("YES")
```このソリューションは 24 文字のスケジュールを読み取り、単一の整数カウンターを維持します。 ループでは Python を使用します`for-else`早期ブレークが発生しない場合にのみ「YES」が出力される構造になっています。 有効な違反が見つかると、それ以上のスキャンは不要になるため、早期に終了することが重要です。 

よくある実装上の間違いは、次のような問題が発生したときにカウンターをリセットするのを忘れることです。`0`これにより、分割されたランが 1 つの連続セグメントに誤ってマージされてしまいます。 もう 1 つの微妙な問題は、反復中ではなくループ後にのみチェックすることです。これにより、早期終了は防止されますが、入力サイズが小さいため、依然として正しいままになります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

        s = input().strip()

                    break
            else:
                run_cnt = 0
        else:
            print("YES")
    return out.getvalue().strip()
