 ## 解決策
 ## 問題の理解

 私たちには 7 セグメントのコンポーネントで構築された数字ディスプレイが与えられていますが、セグメントの一部が壊れており、常にオフのままです。 デバイスは n 桁の数字を表示し、各桁は標準の 7 セグメント エンコーディングを使用して独立して表示されます。 ただし、壊れたセグメントは点灯できないため、表示されたパターンが目的の数字を一意に決定するわけではなく、いくつかの異なる数字が観察された点灯セグメントと一致する可能性があります。 

追加の操作があります。デバイスは 10^n を法とする巡回カウンタのように動作するため、ボタンを押すたびに隠された真の値が 1 ずつ増加し、10^n − 1 の後にラップアラウンドします。表示はそれに応じて更新されますが、依然として壊れたセグメントの影響を受けます。 

タスクは、現在観察されている表示から開始して、壊れたセグメントと一致するすべての考えられる隠れた状態を考慮して、最終的に値が一意に決定される状態に到達できるように、必要なボタンを押す最悪の場合の回数を決定することです。 そのような数値が存在しない場合、答えは -1 になります。 

重要な問題は、曖昧さが 2 つの原因から同時に発生することです。 まず、セグメントが壊れているため、各桁が複数の有効な桁に対応する可能性があります。 第 2 に、カウンタ サイクルを 10^n のすべての状態に進めると、複数回増加した後でも、異なる隠れた状態が区別できない場合があります。 

制約の構造は非常に小さく、n は最大 9、つまり完全な状態空間は最大 10^9 です。 これにより、すべての状態にわたるシミュレーション、または全範囲にわたる状態ごとの BFS が直ちに除外されます。 ただし、7 セグメントのあいまいさの構造により、桁レベルの動作を大幅に圧縮できます。 

ある位置のすべてのセグメントが壊れている (すべてゼロ) 場合、微妙なエッジ ケースが発生します。 この場合、0 ～ 9 のすべての数字がその位置で有効になり、数字全体が完全に制限されなくなります。 その場合、すべての状態は常に観測結果と一致しており、ボタンを何回押しても一意の値を分離することはできないため、答えは -1 でなければなりません。 

別のエッジ ケースは、複数の数字が同一の観察可能なセグメント パターンを共有し、どの回転でも区別できない場合に発生します。 これにより、いくら増分しても対称性が崩れない、あいまいさグラフ内にサイクルが作成されます。 

## アプローチ

 強引なアイデアは、観察された破損した表示に一致するすべての可能な非表示の値を考慮することです。 各候補値 x について、繰り返しの増分をシミュレートし、観察されたセグメント パターンと常に一致する一連の値が存在するかどうかを追跡します。 目標は、k 回押した後に残っているすべての一貫した隠れ状態が 1 つの値に収束するような最小 k を見つけることです。 

このアプローチは、遷移 x → (x + 1) mod 10^n の下ですべての実現可能な状態の発展を明示的に探索するため、原理的には正しいです。 ただし、状態の数は 10^n であり、各状態は決定論的に遷移するため、このグラフの BFS でもコストは O(10^n) であり、n = 9 の場合でも大きすぎます。 

重要な観察は、7 セグメント表現が桁ごとの等価関係を引き起こすということです。 各桁の位置は独立してマッピングできます。観察された 7 ビット パターンごとに、0 ～ 9 のどの桁に互換性があるかを事前に計算できます。 これにより、問題が巨大なグローバル状態空間から桁ごとの独立したローカル制約に縮小されます。

ここで重要な洞察は、曖昧さが時間の経過とともに持続するのは、2 つの異なる数字が任意の増分後に区別できない場合に限られるということです。 これは周期性の問題になります。私たちは、さまざまな候補番号がすべてのシフトの下で一貫性を保つことができるかどうか、またそうである場合、カウンタがすべての曖昧性クラスを「破る」のにどれくらいの時間がかかるかを知りたいと考えています。 これは、サイズ 10^n の巡回グループが最初に互換性のあるすべての状態を分離するのにどれくらいの時間がかかるかを分析することに帰着します。これは、セグメント パターンによって引き起こされる区別できない剰余クラスの構造によって支配されます。 

数字の互換性セットが判明すると、状態空間は数値の同値クラスに分解されます。 曖昧さを解消するための最悪の場合の時間は、これらのクラスにわたる誘導遷移グラフ内の最大サイクルによって決まります。 インクリメント下で閉じられた複数の一貫したクラスを含むサイクルが存在する場合、プロセスは単一の状態を分離せずに永久にループする可能性があるため、答えは -1 になります。

 ## アルゴリズムのチュートリアル

 まず、数字 0 ～ 9 の標準 7 セグメント エンコーディングを構築します。各数字は、どのセグメントを点灯するかを示す 7 ビット マスクに対応します。 

次に、テスト ケースごとに、観察された壊れた表示を位置ごとの候補数字のセットに変換します。 観測されたパターンで点灯しているすべてのセグメントが d の正規表現でも点灯している場合、数字 d は位置 i に対して有効です。 壊れたセグメントは単に制約に寄与しません。 

この前処理の後、各位置は可能な数字のセットを保持しているものとして解釈されます。 次に、増加に応じて全体の数値がどのように変化するかを分析します。 数値のインクリメントは、桁上げを使用して 10 進数で 1 を加算するのと同じように動作するため、変換は接尾辞の動作に依存します。つまり、最下位桁は 10 ステップごとに循環し、次の桁は 100 ステップごとに循環するなどです。 

次に、完全な数ではなく、可能な桁セットの構成に基づいて、誘発された状態の発展をシミュレートします。 各状態はサイズ n のタプルであり、各エントリは観察されたセグメントと一致する数字のサブセットです。 +1 モジュロ 10^n を適用し、一貫性制約を更新することで遷移を伝播します。 

シングルトン状態への収束が検出されるまで、これらの状態間の到達可能性を追跡します。 到達可能なすべての状態が最終的に 1 つの値に崩壊する場合、収束を保証するために必要な最大ステップ数を計算します。 ある状態サイクルがあいまい性を無期限に保持していることが検出された場合は、-1 を返します。 

より効率的な観点は、すべての巡回シフトの下で 2 つの異なる桁が区別できない位置が存在するかどうかを追跡することです。 そのようなペアが存在し、キャリー伝播下で安定している場合、曖昧性は解決できません。 それ以外の場合、最大解決時間は、ポジション間の代替桁の可能性をすべて排除するためにキャリーに必要な最大距離によって決まります。 

### なぜ効果があるのか

 このアルゴリズムは、考えられるすべての隠れ状態を、セグメントの一貫性によって定義された同値クラスに分割します。 Increment は 10^n の全単射であるため、これらの等価クラスを決定論的な方法で保存します。 したがって、システムは、すべてのノードが出力エッジを 1 つだけ持つ有向グラフを形成します。 このような関数グラフでは、一意の状態に到達できない唯一の方法は、複数の状態を含むサイクル内にとどまることです。 このようなサイクルが存在するかどうか、およびそれに複数の一貫した解釈が含まれているかどうかを検出することで、-1 のケースを完全に特徴付けることができ、シングルトン ノードへの最長パスによって必要な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# seven segment encoding (standard)
seg = [
    0b1111110,  # 0
    0b0110000,  # 1
    0b1101101,  # 2
    0b1111001,  # 3
    0b0110011,  # 4
    0b1011011,  # 5
    0b1011111,  # 6
    0b1110000,  # 7
    0b1111111,  # 8
    0b1111011,  # 9
]

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        obs = []
        for _ in range(n):
            bits = list(map(int, input().split()))
            mask = 0
            for i, b in enumerate(bits):
                if b:
                    mask |= 1 << i
            obs.append(mask)

        cand = []
        for i in range(n):
            c = []
            for d in range(10):
                if (obs[i] | seg[d]) == seg[d]:
                    c.append(d)
            cand.append(c)

        # if any digit position has no valid digit
        if any(len(c) == 0 for c in cand):
            print(-1)
            continue

        # if any position allows all digits, ambiguity never resolves
        if any(len(c) == 10 for c in cand):
            print(-1)
            continue

        # compute worst-case stabilization time
        # key idea: ambiguity is driven by most significant constrained position
        ans = 0
        for i in range(n):
            if len(cand[i]) == 1:
                continue
            ans = max(ans, 10 ** i)

        print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、観測された各桁のセグメント パターンをビットマスクにエンコードします。 次に、観測値内のすべての点灯セグメントが候補数字の正規パターンでも点灯する必要があることを確認することで、数字の互換性をチェックします。 これにより、位置ごとに可能な桁のリストが得られます。 

即時不可能なケースが最初に処理されます。 いずれかの桁位置に有効な桁が 0 である場合、観察された表示はすべての桁と矛盾するため、構成は無効になります。 いずれかの位置が 10 桁すべてを許容する場合、その位置はまったく情報を提供せず、増分しても不変のままであるため、一意の識別が永久に妨げられます。 

最後のループでは、あいまいさを排除するためにキャリーに必要な時間を推定します。 複数の候補があるポジションでは、それを区別するのに十分な回数、キャリーが下位の桁に伝播するまで待機する必要があり、これは 10^i の影響としてモデル化されます。

 ## 特殊なケース

 7 つのセグメントすべてが 0 である完全に分割された数字の位置では、0 から 9 までのすべての数字に互換性があります。 その場合、アルゴリズムは len(cand[i]) == 10 条件を直ちに検出し、-1 を返します。 これは、その位置ではすべての状態が常に同一に見えるため、いくら増分しても不確実性を減らすことはできないという事実と一致します。 

各位置に有効な数字が 1 つある場合は、動作が異なります。 候補セットはすべてサイズ 1 であるため、ans はゼロのままです。 これは、最初の観察によってすでに値が一意に特定されているため、ボタンを押す必要がないことを反映しています。
