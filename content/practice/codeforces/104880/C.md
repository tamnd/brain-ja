 ## 解決策
 ## 問題の理解

 小文字で構成される単一の文字列が与えられます。 課題は、それらの位置の文字がパターンを形成するように 4 つの位置を昇順に選択できる方法が何通りあるかを数えるということです。`c`、 それから`v`、 それから`b`、 それから`b`。 

言い換えれば、固定パターン「cvbb」に等しい長さ 4 のサブシーケンスを数えています。この場合、文字をスキップすることはできますが、順序は保持する必要があります。 

入力サイズは最大 100,000 文字です。 すべての 4 倍数を列挙しようとする直接的な組み合わせアプローチは、インデックス 4 倍数の数がおよそ$\binom{n}{4}$、それは約です$10^{20}$in the worst case. 1 秒の制限では、各 4 回転をチェックすることさえ不可能です。 

したがって、ソリューションでは、サブシーケンスを明示的に列挙しないようにプレフィックス情報を使用して、線形または線形に近い時間で文字列を処理する必要があります。 

A few edge situations are worth making explicit.

 If the string contains fewer than one`c`、答えはゼロです。 例えば、`vvbbbbb`明らかにパターンを形成できません。 

複数ある場合`b`キャラクター、組み合わせは最終段階に到達するとすぐに爆発するため、位置を慎重に区別しない単純なカウントはオーバーカウントになります。 たとえば、`c v b b`、有効なサブシーケンスは 1 つだけですが、カウントの不注意な乗算が行われます。`b`順序を無視したペアは無効な組み合わせとしてカウントされます。 

文字の繰り返しが主な微妙な点です。インデックスが厳密に増加していることを確認する必要があるため、順序制約なしで出現を独立した選択肢として扱うことはできません。 

## アプローチ

 ブルートフォースのアイデアは簡単です。インデックスの 4 つすべてを試してみます。$i < j < k < l$、文字が一致するかどうかを確認します`c v b b`、有効なものを数えます。 これは、サブシーケンスの定義を明示的に強制するため、正しいです。 

ただし、4 倍の数は次のように増加します。$O(n^4)$。 と$n = 10^5$、これについてです$10^{20}$これは実行可能な制限をはるかに超えています。 

重要な観察は、パターンが固定されており、短いということです。 インデックスをグローバルに選択する代わりに、左から右に段階的に答えを構築できます。 各位置で、長さ 1、2、および 3 の有効な部分サブシーケンスをいくつ拡張できるかだけを考慮します。 

ターゲット パターンのプレフィックスに一致する部分サブシーケンスの数を追跡します。 

- 等しい部分列の数`c`- 何個等しいか`cv`- 何個等しいか`cvb`- 何個等しいか`cvbb`新しいキャラクターをスキャンするとき、各ステージが以前のステージのみに依存するように、これらのカウンターを依存関係の逆の順序で更新します。 

これにより、キャラクターごとに一定の作業を行う単一パスで問題が軽減されます。

 ## アルゴリズムのチュートリアル

 文字列を左から右に処理し、4 つのカウンターを維持します。 

させて：

-`c1`= 以下に等しい部分列の数`c`-`c2`= 以下に等しい部分列の数`cv`-`c3`= 以下に等しい部分列の数`cvb`-`c4`= 以下に等しい部分列の数`cvbb`現在のキャラクターに応じてこれらのカウンターを更新します。 

1. すべてのカウンタを初期化します`c1, c2, c3, c4`ゼロに。 
2. 各文字を反復処理します。`x`文字列内で左から右へ。 
3. もし`x == 'c'`、長さ 1 の新しいサブシーケンスを開始できます。`c1`これは、この位置を将来のパターンの最初の文字として選択することを表します。 
4. もし`x == 'v'`、既存のすべての`c1`サブシーケンスは次のように拡張できます。`cv`この位置を`v`。 追加`c1`に`c2`。 
5. If`x == 'b'`、次の 2 つのステージを更新します。 

- 既存のすべての`c2`まで拡張できます`cvb`、追加します`c2`に`c3`。 
- 既存のすべての`c3`まで拡張できます`cvbb`、追加します`c3`に`c4`。 

順序は概念的に重要です。両方の更新では、この文字を処理する前の値を使用する必要があります。 
6. すべての文字を処理した後、`c4`以下に等しい数のサブシーケンスが含まれます`cvbb`。 

この順序が正しい理由は、各文字が新しいサブシーケンスを開始するか、同じ位置を再利用せずに以前に形成されたサブシーケンスを拡張するかのいずれかであるという事実に由来します。 

### なぜ効果があるのか

 スキャンの任意の時点で、各カウンターは、パターンの対応するプレフィックスと一致するプレフィックス内のどこかで終わる増加するインデックス サブシーケンスを選択する方法の数を表します。 新しい文字を処理するときは、厳密に現在の位置より前で終了するサブシーケンスのみを拡張するため、順序は自動的に保持されます。 すべての有効なサブシーケンスは、各文字が選択された最後の位置によって一意に識別されるため、すべての構造は 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    c1 = c2 = c3 = c4 = 0

    for ch in s:
        if ch == 'c':
            c1 += 1
        elif ch == 'v':
            c2 += c1
        elif ch == 'b':
            c4 += c3
            c3 += c2

    print(c4)

if __name__ == "__main__":
    solve()
```この実装では、部分的なパターンの一致に正確に対応する 4 つのアキュムレータが保持されます。 内の更新順序`'b'`ケースは重要です。 まず押します`c3`の中へ`c4`どちらも以前の状態に依存しているため、更新されます`c3`を使用して`c2`。 逆にすると新規作成`c3`値が誤って寄与する可能性がある`c4`同じ繰り返しで。 

すべての算術演算は Python 整数で行われ、サブシーケンスの数が 64 ビットの制限を超える可能性があるため、大きなカウントを安全に処理します。

 ## 特殊なケース

 重要なケースの 1 つは、多数の場合です。`b`有効後の文字`cv`後続。 入力用`cvbbbb`、ちょうど 1 つあります`c`そして1つ`v`、 それで`c2 = 1`に到達すると`b`s. それぞれ`b`最初に増加します`c3`4 つの位置にわたって 0 から 1、2、3、4 まで、そしてそれぞれ新しい`c3`に貢献する`c4`。 アルゴリズムはこれを正しく累積します。`b`どちらも既存のものを拡張します`cvb`サブシーケンスを作成し、将来の拡張に貢献します。 

別の事件が繰り返される`c`文字の前に`v`。 のために`cccvbb`、`c1`カウンタは 3 になり、独立した開始点が 3 つあることを意味します。 最初のとき`v`が表示され、`c2`は 3 になり、選択肢の多重度は維持されます。 これは、アルゴリズムが位置を明示的に保存せずに組み合わせ分岐を自然にエンコードしていることを示しています。 

最後の微妙なケースは、次のようなインターリーブです。`cvcvb b`。 順序付けにより、各拡張機能がプレフィックスのみを使用することが保証されるため、文字がインターリーブしても、インデックスの無効な再利用は発生しません。 各更新は以前のカウンターのみに依存し、インデックス増加の厳密な制約が維持されます。
