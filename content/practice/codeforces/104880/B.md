 ## 解決策
 ## 問題の理解

 私たちには、無限の直線に沿って移動する人々のセットが与えられています。 各人はそれぞれのポジションからスタートします$x_i$そして等速で移動します$v_i$。 すべての動きは同時に始まるので、時間は$t = 0$共有されています。 

二人が同時に同じ位置に到着すると、一緒に写真を撮ります。 のグループであれば、$k$人々は同時に同じ場所に集まり、そのグループ内のすべてのペアが写真を撮るので、それが貢献します$\frac{k(k-1)}{2}$その瞬間の写真。 常にそのようなペアごとの会議の合計数が必要です。 

重要な目的は動きそのものではなく、位置の同等性です。$$x_i + v_i t = x_j + v_j t$$これは、2 人がいつ出会うかを定義します。 

制約$n \le 1000$そして$|x_i|, |v_i| \le 10^4$すぐに提案する$O(n^2)$推論は安全です。 時間を継続的にシミュレートしたり、イベントを動的に追跡しようとするソリューションは、不必要であり、過度に複雑になる可能性があります。 

微妙な問題は、同時会議の処理です。 複数のペアがまったく同じ時間と場所で集まり、クラスターを形成することがあります。 たとえば、3 人全員が同じ交差点時間と位置を満たす場合、写真は 2 枚または 1 枚ではなく、3 枚と数えなければなりません。 

別のエッジケースは、同じ開始位置から発生します。 もし$x_i = x_j$、速度に関係なく時間 0 ですぐに会うため、最初に 1 枚の写真を投稿します。 正の時間を持つ交差点のみをチェックする単純な実装では、これらを見逃してしまいます。 

最後に、たとえば、速い人が先にスタートした場合など、2 つの軌道が前進時間中に交差しないため、2 つの軌道が交わらない場合があります。 

## アプローチ

 ブルートフォース手法では、すべての人のペアをチェックし、彼らの軌跡が交差するかどうかを計算します。 ペア用$(i, j)$、次のように解決します。$$x_i + v_i t = x_j + v_j t$$これは次のようになります:$$t = \frac{x_j - x_i}{v_i - v_j}$$もし$v_i = v_j$、次の場合にのみ会います。$x_i = x_j$、そうでない場合は決してありません。 もし$t \ge 0$、会議を 1 回と数えます。 

これが機能するのは、各有効なペアが 1 つの会議イベントに正確に対応するためです。 正確さは簡単ですが、グループ化された方法で複数人の衝突を明示的に処理しません。 ただし、各会議はペアごとに独立して貢献するため、ペアごとのカウントですでに十分です。 

問題は、イベントを時間で並べ替えたり、動きをシミュレートしたりするなど、ペアの列挙を超えた何かを試みた場合にのみパフォーマンスになります。 それには最大の処理が必要になります$O(n^2)$イベントを整理し、$O(n^2 \log n)$、これは不要です。 

重要な洞察は、時間をシミュレートする必要がまったくないということです。 すべての出会いは純粋にペアワイズ代数によって決定され、すべての有効なペアを直接数えることで、すでに正しい答えが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースペアチェック | O(n²) | お(1) | 承認済み |
 | イベントシミュレーション / 仕分け | O(n² log n) | O(n²) | 受け入れられるが不要 |

 ## アルゴリズムのチュートリアル

 1. 順序付けされていないすべての人のペアを反復処理します。$(i, j)$。 これにより、考えられるすべてのインタラクションが 1 回だけ考慮されることが保証されます。 
2. もし$v_i = v_j$、どうかを確認してください$x_i = x_j$。 だとすると、この二人は最初からいつも一緒にいるので、ちょうど1枚の写真を投稿していることになる。 そうでなければ、彼らは決して会うことはなく、何も貢献しません。 
3. もし$v_i \ne v_j$、次を使用して会議時間を計算します。$$t = \frac{x_j - x_i}{v_i - v_j}$$これは、時間の経過とともにそれらの位置を同等にすることから直接導き出されます。 
4. 次の場合にのみペアをカウントします。$t \ge 0$。 マイナスの時間は過去の会議に対応しますが、モーションが開始されるのは無関係です。$t = 0$。 
5. 有効なペアの総数を累積します。 

なぜ効果があるのか:

 各ペアの人々には、直線運動によって決定される固有の潜在的な集合時間があります。 その時間が存在し、負でない場合、ペアはちょうど 1 枚の写真を提供します。 複数の人が同じポイントで同時に出会った場合でも、そのグループ内の各ペアは独立してカウントされるため、ペアごとの累積により、特別な処理を行わずにグループの衝突が自然に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
people = [tuple(map(int, input().split())) for _ in range(n)]

ans = 0

for i in range(n):
    x1, v1 = people[i]
    for j in range(i + 1, n):
        x2, v2 = people[j]

        if v1 == v2:
            if x1 == x2:
                ans += 1
            continue

        num = x2 - x1
        den = v1 - v2

        if den == 0:
            continue

        # check if t >= 0 without floating point
        # t = num / den >= 0  <=> num and den have same sign
        if num * den >= 0:
            ans += 1

print(ans)
```この実装は、ペアごとの推論を直接反映しています。 ループ構造は、すべてのペアを列挙します。$O(n^2)$。 等速度の場合は分離されます。これは、そうでなければ分割が無効であり、概念的には永続的なオーバーラップまたは決して会合しないことに対応するためです。 

条件`num * den >= 0`明示的に計算するのではなく、分数の符号をチェックすることで浮動小数点の精度の問題を回避します。 位置と速度は整数ですが、除算によって微妙な浮動小数点誤差が生じる可能性があるため、これは重要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    people = [tuple(map(int, input().split())) for _ in range(n)]

    ans = 0
    for i in range(n):
        x1, v1 = people[i]
        for j in range(i + 1, n):
            x2, v2 = people[j]

            if v1 == v2:
                if x1 == x2:
                    ans += 1
                continue

            num = x2 - x1
            den = v1 - v2

            if num * den >= 0:
                ans += 1

    return str(ans)

# provided sample-style tests

 ## 特殊なケース

 複数の人が同じ位置からスタートした場合、その中のすべてのペアがすぐにカウントされます。 入力用`3 0 1 0 2 0 3`、アルゴリズムは 3 つのペアすべてを評価し、それぞれが次の条件を満たします。`x1 == x2`したがって、すべてのペアが時間 0 で一致するという事実と一致して、3 が返されます。 

速度は同じだが位置が異なる場合など`2 0 1 10 1`、条件`v1 == v2`カウントをトリガーしてスキップし、平行移動が決して交差しないことを正しく反映します。 

速い人が先にスタートしたとき、たとえば`0 2`そして`10 1`、計算された分子と分母は反対の符号を持つため、`num * den >= 0`失敗し、無効な「逆方向」会議がカウントされなくなります。
