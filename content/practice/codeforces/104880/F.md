 ## 解決策
 ## 問題の理解

 マッチ棒の数字を使用して形成された数式が次の形式で与えられます。$a + b = c$または$a - b = c$ここで、各数値は固定の 7 セグメント スタイルで書かれ、すべての数字は 0 ～ 999 の範囲内にあります。式は物理的にマッチ棒から構築されているため、すべての数字と演算子は、特定のパターンで配置された固定数の棒に対応します。 

許可される操作は最大でも移動です$k$式内のどこにでもマッチ棒を使用できます。 1 つのマッチ棒を移動するということは、それを 1 つのセグメントから取り出して、それを配置して、ある数字または演算子の別の有効なセグメントを形成することを意味します。 これらの移動後も、結果の式は同じ構造ルールに従う必要があります。つまり、正確に 3 つの数字と 1 つの演算子、数字は有効な 7 セグメント数字のままでなければならず、先頭のゼロは許可されず、3 つの数字のそれぞれは最初に指定されたものと同じ桁数を維持する必要があります。 演算子はプラスとマイナスの間で変更することもできますが、これ自体がマッチ棒の移動を必要とします。 

タスクは、最大でも有効な正しい方程式に到達できるかどうかを判断することです。$k$動きます。 

重要な制約は、$k \le 5$、非常に小さいです。 これは、考えられるすべての数字変換の空間は大きいものの、実行可能な解決策はすべての式を強引に探索するのではなく、制限された編集距離または数字遷移に対する事前計算を利用する必要があることを直ちに示唆しています。 

素朴な誤解は、これがローカルの数字の問題であると考えることから生じることがよくあります。 そうではない。 1 回の移動であらゆるセグメントがどこにでも変更される可能性があるため、問題はグローバルです。数字とオペレーターは共有の予算を通じて対話します。 

先頭のゼロからは微妙なエッジケースが発生します。 たとえば、変形する$100 + 2 = 102$のようなものに$001 + 2 = 003$桁レベルでは有効に見えるかもしれませんが、先行ゼロなしで桁幅を保持する必要があるため禁止されています。 

もう 1 つのよくある落とし穴は、オペレータの変更を無視することです。 7 セグメント表現では「+」と「-」は 1 セグメントだけ異なるため、多くの最適な変換では移動バジェットの一部として演算子を反転する必要があります。 

最後に、数字の同一性の変更は構造によって制限されます。数字間で任意に「数字をシャッフル」することはできません。 各桁の位置は個別に変換する必要があり、コストが累積します。 

## アプローチ

 直接的な総当たりアプローチでは、有効な式をすべて列挙しようとします。$a' \pm b' = c'$各数値は入力と同じ桁数を持ち、最大でも次の値を使用して元の式を各候補に変換できるかどうかを確認します。$k$動きます。 候補ごとに、すべての数字と演算子の変換コストを計算し、すべての可能性にわたる最小コストを取得します。 

ただし、999 までの数値に制限しても、最大$10^3 \times 10^3 \times 10^3$の組み合わせ$(a', b', c')$、それぞれについて、桁レベルの差を計算します。 これは最大では大きすぎます$T = 10^3$。 

重要な観察は、各桁が変換コストの点で独立していることです。 数値は単なる数字のシーケンスであり、7 セグメント表現で必要なセグメント変更の数に等しい固定コストで、各数字を別の数字に置き換えることができます。 同様に、演算子は既知のコストを持つ小さな定数セットを形成します。 

これにより、問題は小さな状態空間にわたる有限コスト変換に変わります。 任意の数字を他の数字に変更するコストと、「+」を「−」に、またはその逆に変更するコストを事前に計算できます。 次に、任意の候補式について、桁位置ごとに一定時間で総コストを計算できます。 

残りの課題は、すべてを列挙することを避ける方法です。$10^9$表現。 代わりに、数値が最大 3 桁であることを利用して、各数値を固定長の数値ベクトルとして扱うことができます。 有効な数値のトリプルをすべて列挙しますが、桁コストの累積を使用して早期にプルーニングし、それを超えるものはすべて破棄します。$k$。 以来$k \le 5$、ほとんどの遷移は厳しく制限されており、検索スペースは管理可能なままです。 

したがって、ソリューションは、数字トリプルにわたる制限された DFS または BFS、または同等に、事前計算されたコストを使用した枝刈りを伴う完全な列挙になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての式に対するブルートフォース |$O(10^9)$テストごと |$O(1)$| 遅すぎる |
 | 桁コストの事前計算 + 限定検索 |$O(T \cdot C_k)$どこ$C_k$は小さい定数検索空間です |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 すべての数値が最大 3 桁であるという事実に依存しているため、固定長の数値配列として扱うことができます。 

1. 0 ～ 9 の各桁のマッチ棒 (またはセグメントの状態) の数を事前計算し、桁を変換するコストも事前計算します。$x$数字に変換する$y$。 これは 7 セグメント表現を使用して 1 回実行されます。 コストは単に異なるセグメントの数です。 
2. 「+」と「-」の間の演算子の変換コストを事前計算します。 セグメントが 1 つだけ異なるため、このコストは表現に応じて 1 または 2 となり、ハードコーディングできます。 
3. 入力式を 3 つの固定長の数字配列に解析します。$A, B, C$そしてオペレーター$op$。 各数値は、先頭のゼロが構造的に保持された状態で 3 桁に正規化されます (長さを固定しておく必要があるため)。 
4. 1 つの候補式を変換するコストを計算する関数を定義します。$(A', B', C', op')$桁ごとの変換コストと演算子のコストを合計することにより、元の式から計算されます。 
5. 考えられるすべてのトリプルを列挙します$(A', B', C')$0 から 999 までですが、早めにプルーニングします。 

いずれかの桁位置で累積コストが超過した場合$k$、そのブランチの探索を直ちに中止してください。 
6. 有効なトリプル候補ごとに、算術的正しさをチェックします。$A' + B' = C'$または$A' - B' = C'$、先頭のゼロ違反がないことを確認します。 
7. 総コストを含む有効な候補が見つかった場合$\le k$、「はい」を返します。 
8. 完全な探索後に条件を満たす候補がない場合は、「いいえ」を返します。 

### なぜ効果があるのか

 正確性は、グローバル変換コストを独立した桁ごとの寄与に分解することに依存します。 許可されたすべての移動は 1 つのセグメントのみを変更し、各セグメントは 1 つの数字または演算子にのみ属します。 したがって、総コストはすべてのコンポーネントにわたって加算されます。 なぜなら$k$が非常に小さいため、実行可能なソリューションはすべて、このコスト メトリックにおいて元の構成の厳密に境界付けられた近傍内に留まる必要があります。 プルーニングにより、すでに予算を超えている構成を調査することがなくなるため、有効な最適なソリューションを途中で破棄することがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# 7-segment representation for digits 0-9
seg = [
    "1111110",  # 0
    "0110000",  # 1
    "1101101",  # 2
    "1111001",  # 3
    "0110011",  # 4
    "1011011",  # 5
    "1011111",  # 6
    "1110000",  # 7
    "1111111",  # 8
    "1111011"   # 9
]

# precompute digit transformation cost
cost = [[0] * 10 for _ in range(10)]
for i in range(10):
    for j in range(10):
        cost[i][j] = sum(seg[i][k] != seg[j][k] for k in range(7))

# operator cost: '+' <-> '-'
# represent '+' as 0, '-' as 1
op_cost = [[0, 1],
           [1, 0]]

def parse_number(x, length):
    s = str(x).rjust(length, '0')
    return list(map(int, s))

def value(digits):
    return digits[0] * 100 + digits[1] * 10 + digits[2]

def valid_no_leading_zero(d):
    return not (len(d) > 1 and d[0] == 0)

t = int(input())
for _ in range(t):
    expr = input().strip()
    k = int(input())

    # parse a op b = c
    left, c = expr.split('=')
    a_b = left.split('+') if '+' in left else left.split('-')
    a = list(map(int, a_b[0]))
    b = list(map(int, a_b[1]))
    c = list(map(int, c))

    orig_op = 0 if '+' in expr else 1

    # pad to 3 digits
    a = [0] * (3 - len(a)) + a
    b = [0] * (3 - len(b)) + b
    c = [0] * (3 - len(c)) + c

    ans = False

    # brute force all candidates with pruning
    for A in range(1000):
        A_digits = [A // 100, (A // 10) % 10, A % 10]
        if A_digits[0] == 0 and A >= 100:
            continue

        for B in range(1000):
            B_digits = [B // 100, (B // 10) % 10, B % 10]
            if B_digits[0] == 0 and B >= 100:
                continue

            for op in range(2):
                for C in range(1000):
                    C_digits = [C // 100, (C // 10) % 10, C % 10]
                    if C_digits[0] == 0 and C >= 100:
                        continue

                    # check arithmetic
                    if op == 0:
                        if A + B != C:
                            continue
                    else:
                        if A - B != C:
                            continue
                        if A < B:
                            continue

                    # compute cost
                    total = 0
                    for i in range(3):
                        total += cost[a[i]][A_digits[i]]
                        if total > k:
                            break
                        total += cost[b[i]][B_digits[i]]
                        if total > k:
                            break
                        total += cost[c[i]][C_digits[i]]
                        if total > k:
                            break
                    if total <= k:
                        ans = True
                        break
                if ans:
                    break
            if ans:
                break
        if ans:
            break

    print("Yes" if ans else "No")

算術チェックは、不必要な桁の比較を避けるためにコスト計算の前に行われます。 ほとんどのトリプルは無効な方程式であるため、この順序付けは非常に重要です。
