 ## 解決策
 ## 問題の理解

 複数の種類の石が与えられており、各種類には値と数量があります。 全体的には正確にあります$2n$したがって、ペアリングではすべての石を一度だけ使用する必要があります。 

価値のある2つの石をペアにするとき$x$そして$y$、それらは次のスコアに貢献します。$(x + y) \bmod k$。 目標は、すべての石をペアにして、これらのモジュールの貢献の合計が全体にわたって一致するようにすることです。$n$ペアが最大化されます。 

スコアを再解釈する便利な方法は、各ペアを 2 つのケースに分割することです。 もし$x + y < k$、貢献は単純に$x + y$。 もし$x + y \ge k$、貢献度は$x + y - k$。 あらゆる「溢れ出る過去」$k$” まさに費用がかかります$k$。 すべての石のすべての値の合計は固定されているため、最終的な答えを最大化することは、少なくとも合計が得られるペアの数を最大化することと同じです。$k$。 このような各ペアは、合計を正確に減らします。$k$したがって、これらの削減をできるだけ回避するか、どのペアがしきい値を超えることを強制されるかを同等に制御したいと考えています。 

入力サイズにより総当たり攻撃は不可能になります。 石の数は合計で非常に多くなる場合があります（最大約$2 \cdot 10^9$制約から最悪の解釈の要素)、個別の値の数は最大でも$2 \cdot 10^5$。 すべての石を明示的に列挙したり、すべての組み合わせを試行したりするアルゴリズムは実行不可能です。 平$O((2n)^2)$または$O(n \log n)$展開された要素では、メモリと時間のせいで失敗します。 

素朴な貪欲なアプローチの微妙な失敗例は、多重度を正しく考慮せずに、個々の石をソートし、極端な組み合わせを行うことが常に最適であると仮定することです。 拡張された配列に単純に実装すると、すぐにメモリ制限に達してしまいます。 もう 1 つの間違ったアプローチは、各石を可能な限り最大の有効なパートナーと個別に貪欲にペアリングすることです。これは、早期に大きな値を消費すると、将来のより良いペアリングが妨げられる可能性があることを無視するため、全体的な最適性を破壊する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべての石をリストに展開し、可能な限り完全に一致するものをすべて試し、それぞれのスコアを計算します。 これは解空間全体を探索するため正しいですが、一致の数は$(2n)! / (2^n n!)$、超指数関数的に成長します。 たとえ非常に小さなものであっても$n$、これはすでに実行不可能であり、与えられた制約ではまったく手の届かないものです。 

重要な観察は、スコアはペアがしきい値を超えるかどうかのみに依存するということです。$k$それ以外の場合は、正確なペアの合計ではありません。 書き直すと、問題は次のようになります。合計が少なくとも次のペアの数を最大化します。$k$。 残りのペアはすべて、ペナルティなしで全額を自動的に寄付します。 

これにより、問題はソートされたマルチセットでの構造化されたマッチング問題に変わります。 どのペアが「成功」するかだけを気にします (クロス$k$）とそうでないもの。 最適な戦略は古典的な貪欲原則から生まれます。この組み合わせはしきい値を超える可能性が最も高いため、常に利用可能な最小値を利用可能な最大値と一致させようとします。 このペアさえ届かないなら$k$の場合、最小要素は小さすぎて他のペアリングがしきい値に到達するのを助けることができないため、有益ではない方法でペアリングする必要があります。 

これにより、問題は頻度でソートされた値の配列に対する 2 ポインター プロセスに縮小され、リストを拡張するのではなくカウントが慎重に消費されます。

 ## アルゴリズムのチュートリアル

 入力を値と周波数のペアに圧縮し、値で並べ替えます。 

2 つのポインターを維持します。1 つは最小値クラスで、もう 1 つは最大値クラスです。 

1. ポインタの初期化$l = 0$、$r = m - 1$、および変数`success = 0`。 
2. その間$l \le r$、現在の値クラスを考慮します。$v_l$そして$v_r$。 
3. もし$l = r$、同じ値グループ内でペアリングしています。 形成できるペアの数は$\lfloor c_l / 2 \rfloor$。 かどうかを確認します$2v_l \ge k$。 「はい」の場合、これらのペアはすべて成功しています。 それ以外の場合は、最適なカウントに寄与するものはありません。 
4. もし$v_l + v_r \ge k$、次に、最小値と最大値の組み合わせが成功を保証します。 できるだけ多くのペアを組み合わせます。$\min(c_l, c_r)$。 このような各ペアリングは、1 つの成功したペアに貢献します。 それに応じて両方のカウントを減らし、使い果たされた側のポインタを移動します。 
5. もし$v_l + v_r < k$、その場合は最大のパートナーであっても、$v_l$到達できない$k$。 これはつまり$v_l$成功したペアには参加できません。 移転により検討から外します$l$前方に進み、その質量を効果的に不可避の非成功ペアに押し込みます。 
6. すべてのカウントが消費されるまで続けます。 

答えは、見つかった成功したペアの数です。 

### なぜ効果があるのか

 このアルゴリズムは構造的優位性の議論に依存しています。 値を並べ替える場合、残りのセット内の最大の要素が、より小さな要素にとって最適なパートナーとなります。 その最良のパートナーがまだしきい値に達するのに不十分な場合、その小さな要素がペアの成功に寄与するのに役立つ代替ペアリングはありません。 したがって、早期に削除しても、成功したペアの最適な数を減らすことはできません。 

最小値と最大値の間に成功したペアリングが存在する場合、どちらかのエンドポイントをより極端な代替物に置き換えることは不可能であるため、それらのペアリングは常に安全です。エンドポイントはすでに極端値です。 これにより、貪欲に摂取して潜在的な成功を失うことがなくなります。 

このプロセスでは、残りの不一致要素がすべて、現在の極値との潜在的な有効なペアを少なくとも 1 つ持っているという不変条件が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    v = list(map(int, input().split()))
    
    pairs = sorted(zip(v, a))
    
    l, r = 0, m - 1
    success = 0
    
    while l <= r:
        vl, cl = pairs[l]
        vr, cr = pairs[r]
        
        if l == r:
            # pair within same group
            if vl * 2 >= k:
                success += cl // 2
            break
        
        if vl + vr >= k:
            t = min(cl, cr)
            success += t
            pairs[l] = (vl, cl - t)
            pairs[r] = (vr, cr - t)
            if pairs[l][1] == 0:
                l += 1
            if pairs[r][1] == 0:
                r -= 1
        else:
            # vl cannot form success with any vr
            l += 1
    
    print(success)

if __name__ == "__main__":
    solve()
```コードは、マルチセットを値とカウントのペアに圧縮し、それらを並べ替えることから始まります。 次に、2 つのポインターは、これらのカウントを貪欲に消費することをシミュレートします。 ペアが有効な場合、そのような各ペアは独立して 1 つの成功結果に寄与するため、可能な限り多くの一致する質量を使い果たします。 ペアが無効な場合、他のペアでは救済できないため、小さい方の側を安全に破棄します。 

カウントを更新するときは注意が必要です。ポインターを適切にデクリメントまたは進めることに失敗すると、無限ループや二重カウントが発生します。 ペアリングは同じバケット内で行われるため、単一値の場合も個別に処理する必要があります。 

## 実用的な例

 ### 例 1

 入力:```
n = 3, k = 5
values: [1, 2, 3], counts: [2, 2, 2]
```値グループを追跡します。 

| l | r | (vl,cl) | (vr,cr) | アクション | 成功 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 2 | (1,2) | (3,2) | 1+3>=5、ペアを 2 回 | 2 |
 | 1 | 1 | (2,2) | - | 自己グループ、2+2>=5 false | 2 |

 最終的な答えは 2 つの成功したペアです。 

これは、アルゴリズムが極端な組み合わせを最初に優先し、使用可能な組み合わせを自然に使い果たす方法を示しています。
