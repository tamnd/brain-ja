 ## 解決策
 ## 問題の理解

 それぞれが同じ長さのバイナリ文字列のコレクションが与えられます。 各文字列は、固定ビット数で基数 2 で書かれた数値と考えることができます。 文字列のすべてのペアについて、ビットごとの XOR を計算し、結果のバイナリ文字列を整数として解釈して 2 乗し、インデックスを持つすべてのペアのこの値を合計します。$i \le j$。 

対角線のペアは次のとおりです。$i = j$数値とそれ自体の XOR はゼロであるため、何も寄与しません。 したがって、問題の実際の内容は、個別の文字列の順序付けされていないすべてのペアにわたる合計寄与分ですが、それでも XOR 結果の二乗値を尊重する方法で累積されます。 

制約は非常に具体的な意味で重要です。 すべての文字列にわたる入力ビットの合計数は最大で$5 \cdot 10^6$。 これが重要な制限です。すべてのビットの読み取りと処理が許可されますが、次のようなスケールのものはすべて許可されます。$n^2$または$m^2$注意しないとすぐに危険になります。 すべてのペアの XOR を明示的に計算してから 2 乗しようとするソリューションでは、約$O(n^2 m)$、両方の次元が適度に大きい場合でもすでに失敗します。 

単純なアプローチでは、より微妙な問題も見逃してしまいます。 XOR 値が効率的に計算されたとしても、XOR 値を 2 乗するとクロスビット相互作用が隠蔽されます。 これは、各ビットを個別に扱うだけでは十分ではないことを意味します。 ビット位置間の相互作用が最終的な答えに影響します。 

具体的な失敗例として、次のような 2 つの数字を考えてみましょう。`011`そして`101`。 彼らの XOR は`110`これは 6 であり、その 2 乗は 36 です。代わりに、ビットごとの寄与を個別に合計しようとすると、次のようになります。$2^2$各設定ビットからは得られますが、相互作用項を見逃します$2 \cdot 2^2 \cdot 2^1$。 このクロス項の欠落は、まさに単純なビットごとの合計が壊れる場所です。 

## アプローチ

 ブルートフォースの解決策は簡単です。 文字列のすべてのペアについて、XOR を計算し、それを整数に変換し、2 乗して、それを答えに加算します。 XOR自体にコストがかかる$O(m)$、そして、あります$O(n^2)$ペアなので、全体の複雑さは次のようになります。$O(n^2 m)$。 と$n m \le 5 \cdot 10^6$、両方が発生する最悪の場合、これは大きすぎます。$n$そして$m$およそ数千以上あります。 

重要な観察は、二乗 XOR がビット寄与に拡張できることです。 XOR の値を重み付きビットの合計として書き込む場合$2^k$の場合、二乗により 2 種類の項が生成されます。1 つのビット位置からの寄与と、ビット位置のペア間の相互作用です。 これにより、問題は、文字列のすべてのペアにわたって、1 つのビット位置でどのくらいの頻度で異なるか、また 2 つの位置で同時にどのくらい異なるかをカウントすることに変わります。 

シングルビット部分は取り扱いが容易です。 各ビット位置について、そのビットで異なる文字列のペアが何ペアあるかを知る必要があるだけです。 これは、その列内の 1 と 0 の数から計算できます。 

問題は、2 つの異なるビット位置間の相互作用です。 直接的な解決策には、ビット位置のすべてのペアを反復処理し、両方の位置で異なる文字列ペアの数をカウントする必要があります。 それは二次関数に見えます$m$、しかし制約$n \cdot m \le 5 \cdot 10^6$ビット行列が少なくとも 1 次元でスパースであることを保証します。 これにより、問題を転置し、ビットセットベースのカウントを使用できるようになり、ワードレベルの演算を使用してビット位置の各ペアを効率的に処理できるようになります。

 ## アルゴリズムのチュートリアル

 入力を$n \times m$行が数値、列がビット位置であるバイナリ行列。 

1. 各ビット位置が次のとおりになるように、入力の転置表現を構築します。$k$長さのビットセットを保存します$n$。 これにより、すべての数値にわたる 2 つのビット位置をすばやく比較できます。 
2. 各ビット位置について$k$、そのビットで異なる文字列のペアが何ペアあるかを計算します。 これは、その列内の 1 と 0 を数えることによって行われます。 あれば$c_1$ものと$c_0$ゼロの場合、異なるペアの数は次のようになります。$c_0 \cdot c_1$。 これは、次の方法を介して二乗 XOR に直接寄与します。$2^{2k}$重さ。 
3. ビット位置のペアごとに$(k, l)$と$k < l$、両方の位置で異なる文字列のペアが何組あるかを計算します。 ビットセットを使用して、ビットによって決定される 4 つのカテゴリのそれぞれに該当する文字列の数を数えます。$(k, l)$:`00`、`01`、`10`、 そして`11`。 
4. これらのカウントから、両方のビットが異なる文字列ペアの数を次のように計算します。$$\text{cnt}_{00} \cdot \text{cnt}_{11} + \text{cnt}_{01} \cdot \text{cnt}_{10}.$$この値は重みを伴う交差項に寄与します$2 \cdot 2^k \cdot 2^l$。 
5. シングルビットとクロスビットの両方の寄与を最終的な答えのモジュロに累積します。$998244353$。 

### なぜ効果があるのか

 2 乗 XOR 値は、ビット インジケーター上で 2 次形式に拡張されます。 すべての寄与は、2 つの文字列の各ビット位置が異なるかどうかのみに依存し、文字列の実際の同一性には依存しません。 これは、問題全体がビット間のペアごとの不一致パターンをカウントすることに帰着することを意味します。 シングルビットおよびペアワイズビットの不一致カウントがすべて判明すると、展開内のすべての項が 1 回だけ考慮され、高次の交互作用は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modpow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

n, m = map(int, input().split())
a = [input().strip() for _ in range(n)]

# store columns as bit arrays (as Python integers bitsets over rows)
col = [0] * m
for i in range(n):
    row = a[i]
    for j, ch in enumerate(row):
        if ch == '1':
            col[j] |= (1 << i)

ans = 0

# precompute powers of 2 up to 2m
pw = [1] * (m + m + 5)
for i in range(1, len(pw)):
    pw[i] = pw[i - 1] * 2 % MOD

# single-bit contributions
for k in range(m):
    ones = col[k].bit_count()
    zeros = n - ones
    cnt = ones * zeros
    w = pw[2 * k]
    ans = (ans + cnt * w) % MOD

# pair-bit contributions
for k in range(m):
    bk = col[k]
    for l in range(k + 1, m):
        bl = col[l]

        both_1 = (bk & bl).bit_count()
        only_k = (bk & ~bl).bit_count()
        only_l = (~bk & bl).bit_count()
        both_0 = n - both_1 - only_k - only_l

        cnt = both_0 * both_1 + only_k * only_l

        w = pw[k + l + 1]  # 2 * 2^k * 2^l = 2^(k+l+1)
        ans = (ans + cnt * w) % MOD

print(ans % MOD)
```実装は、各列を行のビットセットに変換することから始まり、これにより、ビットごとの演算を使用して後の交差カウントが高速になります。 最初のループは、そのビットで異なる 2 つの文字列の選択に基づく単純な組み合わせ引数を使用して、個々のビット位置からの寄与を計算します。 

2 番目のネストされたループは、ビット位置のペア間の相互作用を処理します。 ビットセットを使用すると、4 つの結合分布を計算できます。$(k, l)$AND 演算と補数を効率的に使用します。 これら 4 つのカウントから、両方のビットが異なるペアがいくつあるかを再構築し、バイナリ展開から導出された正しい重みを乗算します。 

指数$k + l + 1$重量は膨張によるものです$2 \cdot 2^k \cdot 2^l = 2^{k+l+1}$、浮動小数点演算を回避し、すべてをモジュラー演算に保ちます。

 ## 特殊なケース

 ペアがないため、単一の文字列を入力するとすぐにゼロになります。 すべてのペア カウンタがゼロのままであるため、アルゴリズムはこれを自然に処理します。 

すべての文字列が同一の場合、すべての列がすべて 0 またはすべて 1 になり、すべての寄与が 0 になります。 異なるペアが存在しないため、ビットセットの交差部分も正しく折りたたまれます。 

すべての文字列にわたって 1 つのビット位置のみが変化する場合、2 番目に変化する次元がないため、クロスビット ループは何も寄与せず、答えは単一列の組み合わせカウントに減ります。 

これらのケースでは、構造が縮退したときに、特別な処理を必要とせずに、シングル ビット部分とペア ビット部分の両方が正しく劣化することが確認されています。
