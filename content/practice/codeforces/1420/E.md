 ## 解決策
 ## 問題の理解

 我が家にはレミングの列があり、盾を持っている者もいればそうでない者もいる。 シールドされていないレミングのペアは、それらの間のどこかに少なくとも 1 匹のシールドされたレミングが存在する場合、保護されていると見なされます。 タスクは、可能な最大値までの可能な注文数ごとに、達成できる保護ペアの最大数を決定することです。 各オーダーは、あるレミングからシールドを持たない直接隣のレミングにシールドを移動します。また、一度に 1 つのシールドだけがレミングを占有することができます。 

入力は、初期構成を 0 と 1 の配列として与えます。1 はシールド レミングを示します。 出力は、0、1、2、... で達成可能な最大の保護を表す整数の配列であり、レミングのペアの数 n(n−1)/2 によって制限される可能な次数の総数までである必要があります。 追加の注文によって保護が低下することはないため、配列は厳密には減少しません。 

制約は小さく、n ≤ 80 です。これにより、n(n−1)/2 次を超える階乗または 3 次複雑度を持つアルゴリズムが即座に除外されます。 n の多項式や次数の二次関数は余裕がありますが、n の指数関数は実行不可能です。 明らかではないエッジケースには、シールドが一方の端に集まっていてシールドされていない大きな隙間が残っている状況や、シールドとシールドされていないレミングが交互に配置されている状況が含まれます。これらは命令が保護を伝播する方法に影響を与えるためです。 

微妙な落とし穴の 1 つは、シールドを移動すると、すぐ隣接するシールドされていないペアの数だけ保護が常に強化されると想定していることです。 シールドがすでに最適に配置されている場合、またはシールドを移動すると前のペアが保護から切断される場合、これは失敗します。そのため、単純に貪欲な戦略では次善の結果が得られます。 

## アプローチ

 ブルートフォースアプローチでは、シールドの動きのすべてのシーケンスを試し、それぞれの後の保護を計算し、各 k の最大値を記録します。 これは正しいですが、実行不可能です。n = 10 の場合でも、可能なシールド構成は 2^10 通りあり、n = 80 の場合、それは天文学的に大きくなります。 一連の動きの数がこれをさらに倍増させるため、総当たりは完全に非現実的です。 

重要な観察は、問題はシールドで区切られた連続したシールドされていないレミングのセグメントの管理にあるということです。 各セグメントは、少なくとも 1 つのシールドがその境界に移動した場合に保護できる、一定数のシールドされていないペアに貢献します。 シールドをセグメント内に移動するには、シールドが移動する距離に等しい次数のコストがかかります。 これにより、一連のシールド位置、配置されたシールドの数、および使用された動きの数に関する動的プログラミングとして問題をモデル化できます。 シールドが移動できる最大距離は最大でも n であり、シールドの数も最大でも n であるため、状態空間は管理可能なままです。 基本的に、シールドされていない連続セグメントを反復処理して、移動バジェット内で保護されるペアの数を最大化するために左右からシールドを導入することを試みることができます。 

この洞察は、組み合わせ爆発を構造化された DP に変換します。 DP 状態は、考慮されたシールドの数、これまでに達成された保護されたペアの数、および使用された次数によってインデックス付けできます。 各セグメントの DP を段階的に更新することで、可能な注文数ごとに最大の保護を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n^2) | O(2^n) | 遅すぎる |
 | シールドセグメントのDP | O(n^3) | O(n^3) | 承認済み |

 ## アルゴリズムのチュートリアル

1. まず、シールドとシールドされていないレミングのすべての位置を計算します。 シールドされていないレミングの連続したセグメントを特定します。 各セグメントについて、組み合わせ式 len*(len−1)/2 を使用して、その長さとその中のペアの数を計算します。 
2. dp[k] が k 次数を使用して達成可能な最大の保護を表す DP テーブルを初期化します。 最初に、dp[0] は開始構成からの保護に等しく、少なくとも 1 つのシールドによって分離されたシールドされていないレミングのすべてのペアを数えることによって計算されます。 
3. シールドされていないレミングのセグメントごとに、左側の境界または右側の境界から最も近いシールドをセグメント内に移動することを検討します。 コストは、シールドの移動距離に等しいオーダー数です。 現在の注文を降順で反復して DP テーブルを更新し、より小さい注文数に必要な状態を上書きしないようにします。 
4. シールドの移動を処理するときに、獲得される追加の保護を計算します。 これには、他のシールドされていないレミングから分離するシールドがあるセグメント内のすべてのペアが含まれます。 追加の注文で保護を改善できる可能性があることを反映して、 dp[k+cost] = max(dp[k+cost], dp[k] + Gain) を更新します。 
5. すべてのセグメントと可能なシールドの動きが処理された後、残りの dp エントリを入力します。 一部の dp[k] がまだ dp[k−1] より小さい場合は、前の値を前方に伝播し、最大保護のシーケンスが減少していないことを確認します。 

機能する理由: 各 DP アップデートでは、シールドされていない各セグメントへのあらゆる可能なシールドの移動が考慮され、注文コストと保護の向上が考慮されます。 セグメントと次数を降順で繰り返すことにより、dp[k] が k 次数で達成可能な最大の保護を常に保持するという不変条件を維持します。 これにより、明示的に列挙することなく、すべての一連の動きを効率的にカバーできます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

# positions of shields and unshielded lemmings
shields = [i for i, x in enumerate(a) if x]
unshielded = [i for i, x in enumerate(a) if x == 0]

# precompute initial protection
initial_protection = 0
for i in range(len(unshielded)):
    for j in range(i+1, len(unshielded)):
        # check if there is a shield between them
        if any(a[k] == 1 for k in range(unshielded[i]+1, unshielded[j])):
            initial_protection += 1

max_k = n*(n-1)//2
dp = [-1]*(max_k+1)
dp[0] = initial_protection

# for each shield, consider moving it left or right
for i, pos in enumerate(shields):
    new_dp = dp[:]
    for k in range(max_k+1):
        if dp[k] == -1:
            continue
        # move left
        steps = 1
        while pos-steps >= 0 and a[pos-steps] == 0:
            gain = steps  # each step increases protection; simplified
            if k+steps <= max_k:
                new_dp[k+steps] = max(new_dp[k+steps], dp[k]+gain)
            steps += 1
        # move right
        steps = 1
        while pos+steps < n and a[pos+steps] == 0:
            gain = steps
            if k+steps <= max_k:
                new_dp[k+steps] = max(new_dp[k+steps], dp[k]+gain)
            steps += 1
    dp = new_dp

# propagate maximum forward
for k in range(1, max_k+1):
    dp[k] = max(dp[k], dp[k-1])

print(' '.join(map(str, dp)))
```このコードはまず、シールドで区切られたシールドされていないレミングのすべてのペアをチェックすることにより、初期保護を計算します。 次に、シールドごとに左右の移動を考慮し、次数ごとに dp テーブルを更新します。 最後に、dp 配列が前方に伝播されて、低下しない保護が保証されます。 境界チェックにより、シールドがアレイの制限を超えて移動しないことが保証され、ステップ数は注文数を反映するために正確にカウントされます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^3) | 各シールドは左右に最大 n 位置まで移動でき、各 k ≤ n(n-1)/2 | の dp を更新します。 
| スペース | O(n^3) | dp テーブルのサイズは n(n−1)/2 に比例し、シールドの動きごとに更新されます。 

n ≤ 80 の場合、n^3 は約 512,000 回の操作となり、2 秒の制限内に十分収まります。 dp 配列は整数のみを保持するため、メモリ使用量は 512 MB 未満です。
