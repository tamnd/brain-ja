 ## 解決策
 ## 問題の理解

 一定時間ごとに点灯したり消灯したりするランプのコレクションがあります。 タスクは正確に選択することです$k$すべてのランプが同時に点灯する瞬間が存在するようなランプ。 言い換えれば、選択されたサブセットに対して、$k$ランプの場合、すべてのランプの中にある時点を少なくとも 1 つ見つける必要があります。$k$彼らの間隔。 出力は、そのようなものを選択する方法の数です。$k$-ランプのサブセット、モジュロ$998\,244\,353$。 

入力により得られるのは、$n$ランプ間隔。各間隔はその開始によって定義されます。$l_i$そして終わり$r_i$。 両方$n$そして$k$大きくなる可能性があります:$n$まで$3 \cdot 10^5$これは、すべてをチェックする単純なアプローチを意味します。$\binom{n}{k}$サブセットは絶望的です。 すべてのサブセットを保存することすら不可能です。 大きな時間値 (最大$10^9$) 可能なすべての時点を直接反復できないことを示します。 

エッジケースが発生するのは次の場合です$k = 1$、単一のランプが存在する場合はカウントされ、存在しない場合はカウントされます。$k$間隔が重なっているため、可能なセットはゼロになります。 重複する間隔は部分的に交差したり、他の間隔に完全に含まれたりする可能性があるため、アルゴリズムは同時に開始または終了する間隔を正しく処理する必要があります。 

たとえば、間隔のある 3 つのランプを考えてみましょう。$[1, 3], [2, 4], [5, 6]$そして$k = 2$。 最初の 2 つだけが重複します。 3 番目のランプを含むサブセットは有効なグループを形成しません。 部分的な重複を無視する不注意なアプローチでは、次のようなサブセットを誤ってカウントする可能性があります。$[1, 3]$そして$[5, 6]$。 

## アプローチ

 ブルートフォース手法では、すべてを反復処理することになります。$\binom{n}{k}$ランプのサブセットを調べ、それらの間隔の交差点が空でないかどうかを確認します。 各サブセットについて、開始時間の最大値と終了時間の最小値を計算することで、それらが重複するかどうかが決まります。 正しいとはいえ、このアプローチは指数関数的です。$\binom{300{,}000}{k}$制限時間をはるかに超えています。 小さくても$k$like 5 は何十億もの組み合わせを生成します。 

より迅速な解決策のための重要な洞察は、問題をサブセットではなくタイムライン上のイベントをカウントするものと考えることです。 点灯および消灯する各ランプはイベントとして表すことができます。$l_i$そして「削除」$r_i+1$。 小さいものから時間をかけて掃いてみると$l_i$最大まで$r_i$、アクティブなランプの実行数を維持できます。 少なくとも存在するときはいつでも、$k$アクティブランプ、任意のランプを選択できます$k$そのうち、貢献しているのは$\binom{\text{active}}{k}$合計数に。 

この観察により、問題は指数関数的な問題から次のような問題に変換されます。$O(n \log n)$イベントを並べ替えて順番に処理します。 私たちは問題をカウントの維持に落とし込み、組み合わせ数学 (事前に計算された階乗とモジュラー逆数) を利用して二項係数を効率的に計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n は k * k を選択します) | O(n) | 遅すぎる |
 | イベント スイープ + 組み合わせ論 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 間隔のエンドポイントを 2 つのリストに分割します。$[l_1, l_2, ..., l_n]$そして終わる$[r_1, r_2, ..., r_n]$。 両方のリストを並べ替えます。 並べ替えることにより、イベントを時系列に効率的に処理できるようになります。 
2. 階乗とモジュラー逆関数を最大で事前計算します。$n$モジュロ$998\,244\,353$。 これにより、任意の二項係数の定数時間計算が可能になります。$\binom{x}{k}$モジュロ$998\,244\,353$。 
3. アクティブなランプのカウンターをゼロに初期化し、有効なランプの合計数の変数を初期化します。$k$-ランプはゼロに設定されます。 
4. ソートされた開始点をスイープします。 時刻に開始する各ランプについて$l_i$、現在アクティブなランプの数は、その前またはその時点で開始されたランプの数と正確に一致します。$l_i$そしてまだ終わっていない。 二重カウントを避けるために、計算のみを行います$\binom{\text{active}}{k-1}$このランプが点灯した瞬間。 このランプは、$k$- 任意の組み合わせのランプセット$k-1$すでにアクティブなランプ。 処理後にアクティブなランプ数を増加させます。 
5. このランプに対して計算された二項係数によって有効なセットの総数を増加させます。 すべてのランプに対してこのプロセスを続けます。 
6. 合計カウントのモジュロを返します。$998\,244\,353$。 

機能する理由: 処理が順番に開始されることで、すべてのセットが確実に実行されます。$k$ランプは、セットの最後のランプが開始されたときに 1 回だけカウントされます。 アクティブなランプの稼働数により、他のすべてのランプが点灯することが保証されます。$k-1$ランプは現在のランプと重なっており、空でない交差点が保証されます。 階乗と逆乗を事前に計算すると、モジュロ演算での効率的な計算が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD-2, MOD)

def prepare_factorials(n):
    fact = [1] * (n+1)
    invfact = [1] * (n+1)
    for i in range(1, n+1):
        fact[i] = fact[i-1] * i % MOD
    invfact[n] = modinv(fact[n])
    for i in range(n-1, -1, -1):
        invfact[i] = invfact[i+1] * (i+1) % MOD
    return fact, invfact

def nCk(n, k, fact, invfact):
    if k < 0 or k > n:
        return 0
    return fact[n] * invfact[k] % MOD * invfact[n-k] % MOD

def main():
    n, k = map(int, input().split())
    intervals = [tuple(map(int, input().split())) for _ in range(n)]
    
    starts = sorted(l for l, r in intervals)
    ends = sorted(r for l, r in intervals)
    
    fact, invfact = prepare_factorials(n)
    
    ans = 0
    active = 0
    j = 0  # pointer for ended lamps
    for i in range(n):
        while j < n and ends[j] < starts[i]:
            active -= 1
            j += 1
        ans = (ans + nCk(active, k-1, fact, invfact)) % MOD
        active += 1
    
    print(ans)

if __name__ == "__main__":
    main()
```このソリューションでは、まず、高速二項計算のために階乗を事前計算します。 開始時間と終了時間を並べ替えることでスイープが有効になります。 ポインタ`j`現在の開始前に終了したランプはアクティブとみなされなくなります。 二項係数`nCk(active, k-1)`現在のランプが含まれるすべてのサブセットをカウントします。 モジュロ演算により、大きな数値の正確性が保証されます。
