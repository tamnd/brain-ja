 ## 解決策
 ## 問題の理解

 3 つの整数を作成するように求められます$a$、$b$、 そして$c$、それぞれは最大の広い範囲にあります$10^9$、ペアごとの XOR 値を含む特定の式が指定されたターゲット数値と一致するようにする$n$。 この式は、すべてのペアの XOR を合計します。$(a \oplus b) + (b \oplus c) + (a \oplus c)$。 

主な困難は、XOR を評価することではなく、これら 3 つのペアごとの XOR の合計が正確に一致する値を選択することです。$n$、またはそのようなトリプルが存在しないことを証明します。 

入力には複数の独立したクエリが含まれています。 それぞれについて、有効なトリプルを出力するか、$-1$無理なら。 以来$n$と同じ大きさにすることができます$10^9$まであります$10^4$テストケースでは、ケースごとに一定時間の構築が必要です。 

微妙なエッジケースが現れるのは、$n = 1$。 小さな値を試してみると、次の式がすぐにわかります。$(a \oplus b) + (b \oplus c) + (a \oplus c)$常に偶数を生成します。 たとえば、すべてのビットが独立して考慮される場合、各ビットは合計に 0 または 2 のいずれかを与えます。 これはすでに奇妙なことを暗示しています$n$表現することはできません。 単純な検索では、この構造上の制限を見逃して、誤って奇数の値を構築しようとします。 

もう 1 つの落とし穴は、2 つの変数を等しく設定するか、単純な等差数列を使用すると常に機能すると仮定することです。 一部の小さな値は手動でパッチできますが、ビットごとの独立性を尊重する一般的なパターンが必要です。 

## アプローチ

 強引なアイデアは、すべてのトリプルを試すことです$(a, b, c)$妥当な範囲で式を計算します。 値を数千のような小さな範囲に制限したとしても、最悪の場合でもこれは 3 次であり、数十億回の操作が必要になります。 それは実現可能性をはるかに超えています。 

重要な点は、値を検索するのではなく、ビット パターンを慎重に選択することで式を制御できることです。 XOR は各ビットで独立して動作するため、問題をビットごとに考えることができます。 

単純な構造のトリプルを調べると、重要な同一性が明らかになります。 直したら$a = 0$、式は次のように単純化されます。$$(a \oplus b) + (b \oplus c) + (a \oplus c) = b + (b \oplus c) + c$$次に、貢献度の合計が等しくなるように貢献度を整形したいと思います。$n$。 これを直接解決する代わりに、次のように表現しようとします。$n$XOR 構造が単純な 2 つの数値の組み合わせとして。 

あらゆる用途に対応する標準的な構造$n$分割することです$n$2 つの等しい半分に分割します。$$n = 2x$$そして次を選択してください:$$a = x,\quad b = 0,\quad c = x$$ここで次を計算します。$$a \oplus b = x,\quad b \oplus c = x,\quad a \oplus c = 0$$したがって、合計は次のようになります$x + x + 0 = 2x = n$。 

これはいつでも機能します$n$は均等です。 奇数の場合$n$、パリティ引数は不可能を示しているため、次のように出力します。$-1$。 

ブルートフォース手法は、XOR の構造を無視し、問題を数値検索として扱うため、失敗します。 XOR がビット全体で線形化され、寄与を制御した直接構築が可能になるため、最適なソリューションが機能します。

 ## アルゴリズムのチュートリアル

 1.読む$n$。 もし$n$奇数である場合、すぐに出力されます$-1$。 これは、ビット寄与のペアごとの対称性により、式が常に偶数に評価されるという事実からわかります。 
2. コンピューティング$x = n / 2$。 私たちは、合計貢献度を 2 つの等しい XOR 条件に均等に分配することを目指しています。 
3. トリプルを構築する$a = x$、$b = 0$、$c = x$。 この選択により、2 つの XOR ペアが正確に寄与することが保証されます$x$それぞれ、3 番目の寄与はゼロです。 
4. トリプルを出力します。 

### なぜ効果があるのか

 XOR の各ビット位置は独立して寄与します。 どこでも少しでも$a$そして$c$一致すると、XOR はゼロになります。 以来$b = 0$、とのXOR$b$の値を保存します$a$そして$c$。 これにより、次のようなまったく同じ寄与が 2 つ作成されます。$x$、合計すると$n$。 この構造は非負性を保証し、範囲内に留まります。$x \le 10^9 / 2$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    if n % 2 == 1:
        print(-1)
    else:
        x = n // 2
        print(x, 0, x)
```このソリューションは、上記で導出された構造を直接適用します。 パリティ チェックでは、不可能なケースが最初に処理されます。 一度$n$が均一であることが確認され、2 で割ると対称構造で使用される正確な値が得られます。 

選択$b = 0$これは、XOR で値を保持し、ビット間の意図しないキャンセルを回避するため、重要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        if n % 2 == 1:
            out.append("-1")
        else:
            x = n // 2
            out.append(f"{x} 0 {x}")
    return "\n".join(out)

# provided samples
assert run("5\n4\n1\n12\n2046\n194723326\n") == "2 0 2\n-1\n6 0 6\n1023 0 1023\n97361663 0 97361663"

# custom cases
assert run("1\n2\n") == "1 0 1", "minimum even"
assert run("1\n1\n") == "-1", "minimum odd"
assert run("1\n0\n") == "0 0 0", "zero edge"
assert run("1\n1000000000\n") == "500000000 0 500000000", "large even"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 のために$n = 1$、奇数パリティのため、アルゴリズムはすぐに拒否します。 入力によりチェックがトリガーされます$n \bmod 2 = 1$、それ以上の計算は行われず、$-1$。 

のために$n = 0$を考慮すると、同じ構築が得られます。$x = 0$、 その結果$(0, 0, 0)$、XOR 合計は次のようになります。$0$、これは一貫しています。 

次のような大きな偶数の値の場合、$n = 10^9$、計算セット$x = 5 \cdot 10^8$。 ビット パターンのみが重要であるため、すべての値は範囲内に残り、XOR 構造は大きさの影響を受けません。
