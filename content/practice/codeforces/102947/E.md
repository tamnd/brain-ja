 ## 解決策
 ## 問題の理解

 サイズの正方行列が与えられます。$n \times n$, ここで、各エントリは、特定の食品の種類に割り当てられた場合に、特定の生存者がどの程度の価値に貢献するかを説明します。 各生存者は正確に 1 つの食品タイプに割り当てられる必要があり、各食品タイプは正確に 1 つの生存者を受け取る必要があるため、割り当ては行と列の間で完全に一致します。 

目標は、選択された行列値の合計ができるだけ大きくなるように、この 1 対 1 の割り当てを選択することです。 

このステートメントでは生存者と食料の種類について説明していますが、その構造は純粋に割り当て問題です。つまり、各行と各列から要素を 1 つだけ選択し、合計を最大化します。 

制約$n \le 10$がキー信号です。 一般的な代入問題$n$500 まではハンガリーアルゴリズムまたは最小コスト最大フロー手法が必要ですが、ここでは検索スペースが十分に小さいため、すべての順列を列挙することが可能です。 

唯一意味のあるエッジ ケースは、すべての行が 1 回だけ使用され、すべての列が 1 回だけ使用される必要があることを理解することによって得られます。 ローカルで最適な選択がグローバルに最適なペアリングをブロックする可能性があるため、素朴な貪欲なアプローチはすぐに失敗します。 

たとえば、次のことを考えてみましょう。```
n = 3
matrix:
10 1 1
1 10 1
1 1 10
```ここでは行または列ごとに貪欲に機能しますが、少し変更します。```
n = 3
matrix:
10 9 1
9 10 1
1 1 100
```各行で最適なエントリを個別に選択すると、最後の行が値の低い列にトラップされ、最適なペア構造が失われる可能性があります。 

したがって、問題は基本的に、独立した選択ではなく、順列に関するものです。 

## アプローチ

 この強引なアイデアは、生存者を食料の種類に割り当てられる可能性があるすべてを試してみることです。 各割り当ては列の置換に対応するため、$n$行をすべて列挙できます$n!$順列を計算し、それぞれの合計を計算します。 

これは正しいです。すべての有効な割り当てが 1 つの順列に正確に対応し、すべての順列が有効な割り当てを表すからです。 

ただし、コストは要因的に増加します。 たとえ$n = 10$、私たちは得ます$10! = 3,628,800$順列。 それぞれの評価にかかる費用$O(n)$、大まかに言うと$3.6 \times 10^7$これは境界線にありますが、慎重に実装された場合にのみ Python で許容されます。 この構造は、総当たりを大幅に最適化しようとするよりも、より明確に実行できることを示唆しています。 

重要な観察は、単調性や貪欲な実現可能性のような追加の構造が存在しないということです。そのため、最も単純で正しい解決策は、バックトラッキングまたはバックトラッキングを使用した純粋な順列列挙です。`itertools.permutations`。 

これにより、問題は列の順序に基づいたクリーンな徹底的な検索に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 |$O(n! \cdot n)$|$O(n)$| 受け入れられました$n \le 10$|
 | DP / ハンガリー語 (ここはやりすぎ) |$O(n^3)$|$O(n^2)$| 受け入れられるが不要 |

 ## アルゴリズムのチュートリアル

 1. サイズの行列を読み取ります。$n \times n$、エントリは$(i, j)$生存者を割り当てる値です$i$食べ物の種類に合わせて$j$。 これにより、割り当てのコストが完全に定義されます。 
2. 数値のすべての順列を生成する$0$に$n-1$。 各順列は行の選択肢を表します。$i$列に割り当てられます`perm[i]`。 これにより、各列が 1 回だけ使用されることが保証されます。 
3. 各順列について、すべての行を反復して加算することにより合計を計算します。`matrix[i][perm[i]]`。 これにより、その割り当ての値が評価されます。 
4. すべての順列にわたって見られる最大合計を追跡します。 これは可能な限り最良の割り当てを表します。 
5. すべての順列をチェックした後、最大値を出力します。 

唯一の微妙な点は、順列を列の割り当てとして正しく解釈することです。 行と列のインデックス付けの間に不一致があると、正確性が損なわれます。 

### なぜ効果があるのか

 生存者の食料タイプへの有効な割り当てはすべて、行と列の間の全単射に対応し、すべての全単射は正確に列インデックスの順列です。 すべての順列を評価するため、有効な割り当てが失われることはありません。 各順列の合計を正確に計算するため、見つかった最大値が最適解になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from itertools import permutations

n = int(input())
a = [list(map(int, input().split())) for _ in range(n)]

best = 0

for perm in permutations(range(n)):
    total = 0
    for i in range(n):
        total += a[i][perm[i]]
    if total > best:
        best = total

print(best)
```この解決策は、割り当ての解釈を直接反映しています。 行列はそのまま保存され、各順列は各行の列選択として扱われます。 現在の最大値は、観察された最良の割り当てを維持します。 

ここでよくある間違いは、貪欲に行ごとに選択しようとすることですが、以前の選択により将来の列の可用性が制限されるため、失敗します。 順列アプローチでは、最初からグローバルな一貫性を強制することでこれを回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n! \cdot n)$| すべての順列を列挙し、合計を計算します。$n$それぞれの行 |
 | スペース |$O(n)$| 行列と現在の順列を保存します。 

と$n \le 10$、特に各演算が単純な加算であるため、階乗増加は時間制限内で実行できるほど十分に小さいままです。 

## テストケース```python
import sys, io
from itertools import permutations

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = [list(map(int, input().split())) for _ in range(n)]
    best = 0
    for p in permutations(range(n)):
        total = 0
        for i in range(n):
            total += a[i][p[i]]
        best = max(best, total)
    return str(best)

# provided sample
assert run("2\n3 4\n0 2\n") == "5", "sample 1"

# custom: all equal values
assert run("2\n1 1\n1 1\n") == "2", "uniform matrix"

# custom: diagonal dominant
assert run("3\n10 1 1\n1 10 1\n1 1 10\n") == "30", "diagonal best"

# custom: forcing permutation choice
assert run("3\n1 2 3\n3 2 1\n2 3 1\n") == "8", "mixed case"

# custom: minimum size
assert run("1\n7\n") == "7", "single element"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2x2 均一行列 | 2 | 対称性と平等な選択肢 |
 | 対角行列 | 30 | 最適な対角線の正しいマッチング |
 | 混合3x3 | 8 | 自明ではない順列選択 |
 | 単一要素 | 7 | 基本ケースの処理 |

 ## 特殊なケース

 単一の生存者の場合、唯一の順列が空であり、合計が単一の行列エントリに減少するため、アルゴリズムはすぐに唯一の利用可能な値を返します。 

すべてのエントリが等しい一様行列の場合、すべての順列は同じ合計を生成します。 このアルゴリズムは引き続きすべての順列を探索しますが、一貫して同じ最大値を追跡し、選択順序に偏りが存在しないことを確認します。 

高い値が分散している場合など、最適な割り当てに貪欲でないスワップが必要な行列の場合、順列列挙によって正確さが保証されます。 考えられる各組み合わせは明示的に評価されるため、中間の選択肢が最適ではないように見えても、割り当てが失われることはありません。
