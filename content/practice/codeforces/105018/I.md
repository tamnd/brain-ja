 ## 解決策
 ## 問題の理解

 ラベル付けされた面の円形配置が与えられます。 各位置には顔を説明する文字列ラベルが含まれており、正確に 1 つの位置がラベルでマークされます。`"Jaqen"`、旅行者の現在位置を表します。 

現在の面をその位置に戻した後、必要なターゲット ラベルを持つ別の面を検索する必要があります。 移動は円の周りの時計回りまたは反時計回りの両方向に許可されており、ターゲット ラベルの出現に到達する前に検査される面の数が最小限であることが必要です。 

重要な点は、検査コストが、検査結果から円に沿ったステップ数として測定されることです。`"Jaqen"`両方向を考慮して、ターゲット ラベルの最も近い位置に位置します。 

入力サイズでは最大 100 のテスト ケースが可能で、合計で最大 10^5 の面が許可されます。 これにより、テスト ケースごとの線形時間よりも悪いものは即座に排除されます。 すべての開始を試行して距離を再計算する 2 次アプローチは、最悪の場合、約 10^10 の演算にまで低下しますが、これは現実的ではありません。 

ターゲット ラベルが配列内にまったく存在しない場合、微妙なエッジ ケースが発生します。 その場合、正しい出力は次のとおりです。`-1`。 もう 1 つのエッジ ケースは、ターゲット ラベルが正確に`"Jaqen"`自体。 概念的には最初に現在の顔を「返す」ので、引き続き別の出現を検索します。存在しない場合、答えも次のようになります。`-1`。 

## アプローチ

 直接的なアプローチは、次のインデックスを見つけることです。`"Jaqen"`次に、円内のすべての位置について、このインデックスからの距離を確認し、ラベルがターゲットと一致するものの中で最小値を維持します。 配列は円形であるため、各距離では時計回りと反時計回りの両方のオフセットを計算して最小値を取得する必要があります。 

これは、考えられるすべての宛先を明示的に評価するため、正しく機能します。 ただし、ターゲットの一致候補ごとに距離を O(1) で再計算しますが、すべての位置をスキャンするには依然として O(n) のコストがかかります。 複数のテスト ケースに対してこれを実行することは、単独ではまだ許容されますが、特にモジュール式の演算を繰り返して単純に実装し、`"Jaqen"`毎回。 

重要な点は、ターゲットが出現するたびに、複雑な方法で個別に距離を再計算する必要がないということです。 位置がわかったら、`"Jaqen"`、他のすべての位置の距離は、純粋に円上のインデックス演算によって決定されます。 したがって、答えは、配列を 1 回スキャンし、ターゲット ラベルに一致する位置のみの円周距離を計算し、最小値を取得することになります。 

長さ n の配列内のインデックス i と j の間の円周距離は次のとおりです。 

min(|i - j|, n - |i - j|)

 目的のラベルが付いた位置のみを考慮するため、問題を 1 つのパスに縮小します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのペアを再計算) | O(n²) | お(1) | 遅すぎる |
 | 最適なシングルスキャン | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、ラベルが付いた特別な位置のインデックスを特定します。`"Jaqen"`。 これは、すべての距離が測定される基準点です。 
2. 検索しているターゲットラベルを読み取ります。 
3. ターゲットのラベルが配列のどこにも存在しない場合は、戻り値を返します。`-1`すぐに。 これにより、不必要な計算が回避されます。 
4. 変数を初期化する`best`大きな値にします。 これにより、これまでに見つかった最小の円周距離が追跡されます。 
5. 配列内のすべてのインデックス i をスキャンします。 各ポジションについて:

 1. i のラベルがターゲットと一致する場合、i とターゲット間の円周距離を計算します。`"Jaqen"`索引。 
2.アップデート`best`この距離が小さければ。 
6. トラバース終了後、出力します。`best`。 

重要な決定は、距離の計算を関連する位置のみに制限することです。 これにより、無関係なラベルを評価する時間を無駄にすることがなくなります。 

### なぜ効果があるのか

 すべての有効な答えは、ターゲット ラベルの出現を選択し、円に沿って歩くことに対応します。`"Jaqen"`その出来事に。 その歩行のコストは、サイクル上の相対的な位置にのみ依存します。 すべての出現を正確に 1 回検査し、開始位置からの真の最小円形距離を計算するため、それらすべての最小値が正確に大域的最適値となります。 直接循環トラバース以外のパスを短くすることはできないため、代替構造や複数ステップの推論は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        parts = input().split()
        n = int(parts[0])
        target = parts[1]

        arr = input().split()

        start = -1
        for i, x in enumerate(arr):
            if x == "Jaqen":
                start = i
                break

        # If target is not present at all
        if target not in arr:
            print(-1)
            continue

        best = float('inf')

        for i, x in enumerate(arr):
            if x == target:
                diff = abs(i - start)
                dist = min(diff, n - diff)
                if dist < best:
                    best = dist

        print(best if best != float('inf') else -1)

if __name__ == "__main__":
    solve()
```実装では、まず各テスト ケースを解析し、ターゲット ラベルと完全な循環リストの両方を抽出します。 次に、ラベル付きの開始位置を見つけます。`"Jaqen"`ワンパスで。 

2 回目のパスでは、ターゲットと一致する位置のみをチェックします。 円形距離の計算には標準のラップアラウンド式が使用されます。`min(|i - start|, n - |i - start|)`これにより、時計回りと反時計回りの両方の動きが正しく考慮されます。 

よくある落とし穴は、ラップアラウンド補正の適用を忘れて絶対差分だけを使用することです。 これにより、最適なパスが配列の境界を横切るときの距離が過大評価されてしまいます。 

もう 1 つの微妙な問題は、ターゲットが完全に欠落している場合の処理​​です。 明確なチェックがなければ、`best`無限大のままなので、次のように変換する必要があります。`-1`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        parts = input().split()
        n = int(parts[0])
        target = parts[1]
        arr = input().split()

        start = -1
        for i, x in enumerate(arr):
            if x == "Jaqen":
                start = i
                break

        if target not in arr:
            out.append("-1")
            continue

        best = float('inf')
        for i, x in enumerate(arr):
            if x == target:
                d = abs(i - start)
                best = min(best, min(d, n - d))

        out.append(str(best if best != float('inf') else -1))

    return "\n".join(out) + "\n"

# provided sample-like tests
assert run("1\n5 one-eyed\nred-haired Jaqen silver-haired one-eyed red-haired\n") == "2\n"
assert run("1\n3 thick-eyebrows\nJaqen brown-eyed long-nose\n") == "-1\n"

# custom cases
assert run("1\n1 a\nJaqen\n") == "-1\n"
assert run("1\n4 x\nx Jaqen x x\n") == "1\n"
assert run("1\n6 a\nb c Jaqen d e a\n") == "3\n"
assert run("1\n5 Jaqen\nJaqen Jaqen Jaqen Jaqen Jaqen\n") == "0\n"

 | --- | --- | --- |
 | 単一要素のみ | -1 | 到達可能なターゲットがありません |
 | 円の周りの複数のターゲット | 1 | 円形の最短経路 |
 | ラップを越えたターゲット | 3 | ラップアラウンドの正確性 |
 | すべてのラベルが同一 | 0 | 自明の最小ケース |

 ## 特殊なケース

 配列のサイズが 1 の場合、唯一の要素は`"Jaqen"`, したがって、他のターゲットは不可能です。 スキャンでは一致するものが見つからず、返されます`-1`、別の顔を見つけなければならないというルールと一致します。 

ターゲットが左右対称に複数回出現する場合`"Jaqen"`の場合、アルゴリズムは各候補を独立して正しく評価し、最小の円周距離を選択します。 各発生は 1 回処理されるため、対称性によってバイアスや重複エラーが発生することはありません。 

最も近いオカレンスが境界を囲む必要がある場合、`min(diff, n - diff)`計算では短い円弧が自動的に取得され、直線距離のみから生じる過大評価が防止されます。
