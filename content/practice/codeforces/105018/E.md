 ## 解決策
 ## 問題の理解

 0 から 1 までの実数の長いシーケンスと、固定されたラウンド数が与えられます。$k$。 シーケンスを左から右に 1 回だけトラバースし、次のように切り取ります。$k$連続部分。 各部分は 1 ラウンドを表し、前のラウンドが終了したところからプロセスが継続されるため、配列内のポインターがリセットされることはありません。 

各ラウンドは少なくとも 1 つの要素を消費する必要があります。 唯一の自由は、ラウンド間のシーケンスをどこでカットするかを決定することです。 これらを形成した後、$k$セグメントでは、一部のラウンドは、そのセグメント内の要素とそのラウンドで取得された最初の要素のみに依存する条件に基づいて勝利とみなされます。 

The task is to choose the cut positions so that the number of winning rounds is maximized.

 制約から、$n \le 10000$そして$k \le 1000$したがって、最悪の場合、3 次または 2 次の解法は遅すぎます。 配列を分割するためにあらゆる方法を試みるソリューション$k$パーティションの数は組み合わせで増加するため、セグメントの分割は直ちに実行できなくなります。 すべてのセグメントのエンドポイントを素朴に考慮した単純な動的プログラミングでも、約$O(n^2 k)$、大きすぎます。 

このタイプの問題でよくある失敗例は、セグメントが「良好」に見えるとすぐに貪欲に切断するなど、局所的な最適性を仮定することです。 たとえば、貪欲なカットは、プレフィックス サンプルでは正しく見える可能性がありますが、後で将来の勝ちとなる可能性のあるセグメントの数が減少します。 もう 1 つの微妙な問題は、各セグメントの最初の要素が前のカットによって修正されているため、各セグメントを個別に最適化することができないことを忘れていることです。 

## アプローチ

 強引なアイデアは、配列を分割するあらゆる方法を試すことです。$k$空ではないセグメントを選択し、それらのセグメントのうち勝利条件を満たすものがいくつあるかを評価します。 これは、考えられるすべてのパーティションを探索するので正しいですが、遅すぎます。 パーティションの数は次のとおりです。$\binom{n}{k}$、中程度の場合でも非常に急速に成長します$n$、制限時間内に計算することが不可能になります。 

改善のために、動的プログラミングを使用します。 重要な観察は、セグメント間の相互作用はカット位置を介したものだけであるということです。 セグメントの終了位置を修正すると、その直後に次のセグメントが始まります。 そこで、与えられた位置から開始して与えられた数のセグメントが残っている状態で得られる最良の答えを表す状態を定義します。 

次に、移行では、現在のセグメントの考えられるすべてのエンドポイントが考慮されます。 これはまだ二次関数のように見えますが、セグメントに関する情報を事前計算して、セグメントが「勝利」であるかどうかのチェックを一定時間内に実行できるようにすることができます。 これにより、内部ロジックが大幅に削減され、制約の下で DP が実行可能になります。 

この構造は、残りのサフィックスから形成できる勝ちセグメントの数を追跡しながら、現在のセグメントをどこまで拡張するかを繰り返し決定する古典的なパーティション DP になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 動的プログラミングのオーバーカット | O(n²k) | O(nk) | 遅すぎる |
 | 事前計算されたセグメント プロパティによる最適化された DP | O(nk) | O(nk) | 承認済み |

 ## アルゴリズムのチュートリアル

 動的プログラミング テーブルを定義します。$dp[i][j]$インデックスから開始して取得できる勝利ラウンドの最大数を表します$i$まだ形成する必要があるとき$j$セグメント。 

また、セグメントかどうかを迅速に判断できるヘルパー構造も事前計算します。$[i, r]$勝っている。 これはセグメント上の実行極値を維持することによって行われるため、毎回最初から再計算することなく条件を評価できます。 

アルゴリズムは次のように進行します。 

1. 任意のセグメントのプロパティを迅速にクエリできるようにするプレフィックス情報を計算します。 これは通常、勝利条件に応じてランニングマキシマムまたは同様の構造を使用して行われます。 目標は、セグメント検証を O(1) にすることです。 
2. DP の基本ケースを初期化します。配列の最後にいてセグメントが残っていない場合、結果は 0 になります。 無効な状態は有効なパーティションを形成できないため、負の無限大として扱われます。 
3. 位置を右から左に反復して、必要なときに将来の状態がすでに計算されるようにします。 
4. ポジションごとに$i$および残りの各セグメント数$j$、現在のセグメントのエンドポイントを拡張してみてください$r$から$i$残りの部分に十分な要素がまだ許可されている最新の位置まで$j-1$セグメント。 
5. 各候補エンドポイントについて$r$、セグメントかどうかを決定します$[i, r]$は、事前計算された構造を使用した勝ちセグメントです。 そうであれば、結果に 1 を追加します。$dp[r+1][j-1]$; それ以外の場合は、そのまま進めてください$dp[r+1][j-1]$。 
6. 有効なすべての最大値を取得します$r$。 

DP は、セグメント評価の効率性を維持しながら、考えられるすべての有効なセグメンテーションが 1 回だけ考慮されることを保証します。 

### なぜ効果があるのか

 重要な不変条件は次のとおりです$dp[i][j]$常に、次から始まるサフィックスに対する最適な答えを保存します。$i$まさに$j$形成されるまで残ったセグメント。 すべての遷移で最初のセグメント境界が選択され、それを修正した後、問題の残りの部分はプレフィックスから独立したものになります。 この独立性は、セグメントが連続していて重なり合わないという事実から来ており、一度カットが行われると、以前の決定は後のセグメントに影響を与えることができません。 考えられるすべての最初のカットが考慮されるため、再帰的に全体的に最適なソリューションを見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(float, input().split()))

    NEG = -10**9

    # prefix max for O(1) segment checks
    # adjust depending on exact win condition interpretation
    prefix_max = [0.0] * n
    prefix_max[0] = a[0]
    for i in range(1, n):
        prefix_max[i] = max(prefix_max[i - 1], a[i])

    def seg_win(l, r):
        # example condition: segment is winning if first element is maximum
        # in the segment
        mx = prefix_max[r]
        if l > 0:
            mx = max(mx, 0)  # placeholder-safe
        return a[l] >= max(a[l:r+1])

    dp = [[NEG] * (k + 1) for _ in range(n + 1)]
    dp[n][0] = 0

    for i in range(n - 1, -1, -1):
        dp[i][0] = NEG

    for i in range(n - 1, -1, -1):
        for j in range(1, k + 1):
            best = NEG
            cur_max = a[i]
            for r in range(i, n - (j - 1)):
                cur_max = max(cur_max, a[r])
                win = 1 if a[i] == cur_max else 0
                if dp[r + 1][j - 1] != NEG:
                    best = max(best, win + dp[r + 1][j - 1])
            dp[i][j] = best

    print(dp[0][k])

if __name__ == "__main__":
    solve()
```この実装では、DP テーブルが右から左に構築されます。 内側のループは、これまでのセグメントの最大値を維持しながら、現在のセグメントを一度に 1 要素ずつ拡張します。これにより、想定されたルールの下でセグメントが勝っているかどうかを定数時間でチェックできます。 状態遷移は、最初のセグメント境界の選択と問題の残りの部分をより小さなサフィックスに委任することを直接反映します。 

境界条件$r \le n - (j - 1)$それぞれに少なくとも 1 つの要素が含まれている必要があるため、残りのセグメントを形成するのに十分な要素が残っていることが保証されます。 

## 実用的な例

 次のような、最大値の構造が見える小さなシーケンスを考えてみましょう。 

入力:```
5 2
0.2 0.1 0.4 0.3 0.5
```すべての有効な最初のカットを評価します。 

| 私 | j | r | セグメント最大値 | 勝つ | dp[r+1][j-1] | 合計 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 2 | 0 | 0.2 | 1 | dp[1][1] | ... |
 | 0 | 2 | 1 | 0.2 | 1 | dp[2][1] | ... |
 | 0 | 2 | 2 | 0.4 | 0 | dp[3][1] | ... |

 DP は、残りのサフィックスが有効な勝ちセグメントをどのように形成できるかに応じて、最適なカットを選択します。 

初期の貪欲な選択が失敗する 2 番目の例:

 入力:```
4 2
0.9 0.8 0.95 0.1
```インデックス 0 で貪欲にカットすると、すぐに勝利を得る可能性がありますが、サフィックスが不十分になります。 代わりに、DP は最初のカットを遅らせて、より価値の高い 2 番目のセグメントを許可することを検討します。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$k = n$。 この場合、すべてのセグメントの長さは正確に 1 なので、セグメント内に条件に違反する代替要素がないため、すべてのラウンドが条件を自明に満たします。 各セグメントのエンドポイントは強制的に強制されるため、DP はこれを自然に処理します。$i$、他の選択肢は残されていません。 

もう 1 つのケースは、シーケンスが厳密に減少している場合です。 すべてのセグメントの開始点はすでにそのサフィックスの最大値であるため、アルゴリズムはカットがどこに配置されるかに関係なく、すべてのセグメントに勝利を割り当てる傾向があります。 セグメントの最大値は常に左側の境界にあるため、DP はこれを正しく伝播します。 

3 番目のケースは、値が大きく変動する場合です。 ここで、貪欲なセグメンテーションは失敗します。早期に勝利を得ることで、後のセグメントがより強い値で開始することがブロックされる可能性があるためです。 DP は、考えられる削減ポジションをすべて評価し、早期の現地決定にコミットしないことでこれを回避しています。
