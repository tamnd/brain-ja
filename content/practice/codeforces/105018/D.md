 ## 解決策
 ## 問題の理解

 私たちはディーラーと対話型の賭けゲームを繰り返しプレイしています。 各ラウンドでは、双方が間隔から均一にランダムな値を繰り返し抽出することによって、ゼロから始まるスコアを構築します。$[0,1]$。 自分の番では、別のランダムな値を引くか停止するかを決定します。 引き分けて合計が 1 を超えた場合は、即座にそのラウンドに負けます。 

あなたが停止すると、ディーラーは同じメカニズムでプレイしますが、いつ停止するかについては異なるルールでプレイします。ディーラーは、合計があなたの最終スコアを超えない限りドローを続けます。$T$。 彼の合計が超過するとすぐに$T$、彼は立ち止まります。 このプロセス中に彼が 1 を超えた場合、彼はすぐに負けます。そうでない場合は、停止ルールの結果条件を通じて彼の最終合計があなたの最終合計と比較されます。 

各ラウンドは勝ちか負けで終了し、目標は少なくとも 42% で勝つことです。$10^5$ラウンドします。 各ドローはランダムで独立しているため、制御できるのは停止戦略だけです。 

重要な制約はラウンド数であり、これは決定論的または固定確率的戦略が真の勝率に安定するのに十分な大きさです。 これにより、悪用可能なフィードバックがなく、ランダム性が毎回新鮮になるため、過去の結果に基づいてラウンド間で適応しようとする戦略は排除されます。 

微妙なエッジケースは、極端な停止動作です。 いつもすぐに止めた場合、スコアは 0 になりますが、ディーラーは 1 つの正の数字を引き、0 のすぐ上で止めることで常に 0 を破ります。つまり、すべてのラウンドで負けることになります。 逆に、常に 1 に近づくまで描画し続けると、頻繁にバストが発生する危険があります。 最適な戦略では、十分に高いしきい値の達成と生存のバランスを取る必要があります。 

## アプローチ

 素朴な解釈は、さまざまな戦略をシミュレートすることです。つまり、停止ルールを選択し、モンテカルロによって勝利確率を推定し、可能なしきい値を探索します。 固定閾値の場合$T$、プレーヤーとディーラーの両方のプロセスを繰り返しシミュレートし、勝率を推定できます。 ゲームは確率的に明確に定義されているため、これは概念的には機能しますが、オンラインで実行すると非常に遅くて不安定であり、オフライン シミュレーションでも、近いしきい値を区別するときにノイズが発生します。 

重要な観察は、プレーヤーとディーラーの両方が同じ確率過程に従い、停止条件のみが異なるということです。 停止しきい値を修正したら$T$、ゲームは、「境界を越えるまでの均一な増分の合計」プロセスによって生成された、2 つの同一に分布したランダムな合計を比較することになります。 最終的な合計の分布は、ラウンド間の履歴や相互作用ではなく、しきい値のみに依存します。 

これにより、問題は 1 次元の最適化問題に変わります。関数を定義します。$f(T)$双方が次のように決定された誘導停止ルールを使用した場合に勝つ確率として$T$。 計算できる$f(T)$可能な合計の状態空間を離散化することによって数値的に$[0,1]$次に、ランダムウォークのような遷移の累積分布に対して動的プログラミングを使用します。 

各候補しきい値について、現在の合計に対する DP としてプロセスをシミュレートし、もう 1 回均一な描画後に各状態に到達する確率を更新します。 1 を超えるか、しきい値を超える遷移は停止します。 この分布から、プレイヤーの最終結果がディーラーの結果を上回る確率を導き出します。 両方のプロセスは独立しており、条件が同一であるため、$T$、この比較は、それらの結合分布にわたる積分に帰着します。 

次に、しきい値の細かいグリッドを評価し、勝率を最大化するしきい値を選択します。 実際には、関数は滑らかで単峰性であるため、十分な密度の離散化で十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 戦略ごとの総当たりシミュレーション |$O(M \cdot R \cdot n)$|$O(1)$| 遅すぎる |
 | しきい値を超える離散化 DP |$O(K \cdot S^2)$|$O(S)$| 承認済み |

 ここ$K$はテストされたしきい値の数であり、$S$和の離散化分解能です。 

## アルゴリズムのチュートリアル

 離散化ステップを修正します$\Delta$、合計を次の倍数として扱います。$\Delta$で$[0,1]$。 

1. ランダムな値を累積するプロセスを、可能な合計に対する確率分布として表します。 各状態は、離散化グリッドに丸められた部分和に、「バスト」および「停止」の吸収状態を加えたものに対応します。 
2. 固定閾値の場合$T$、合計 0 での確率 1 から開始し、一様確率変数を繰り返し追加することで、最終的なプレイヤーの合計の分布を計算します。 次に考えられるすべての合計に質量を均一に分散することで確率を更新します。 1 を超える遷移は損失状態に吸収され、それを超える状態はすべて吸収されます。$T$終端「停止」状態に吸収されます。 
3. ディーラーに対して同じ計算を繰り返します。ディーラーは、同じしきい値でまったく同じ移行ルールに従います。$T$。 
4. 両方の最終分布が得られたら、結果を比較して勝利確率を計算します。ディーラーがバストした場合、または両方が有効で停止ルールに基づいてプレーヤーの最終合計が大きい場合、プレーヤーは勝ちます。 この比較は、端末状態のすべてのペアを統合することによって行われます。 
5. 掃き掃除$T$密集したグリッドの上で$[0,1]$、各値の勝率を計算し、最適なしきい値を選択します。 
6. 実際のインタラクティブ ゲーム中に、固定ポリシーを適用します。合計が選択した最適なしきい値に達するか、それを超えるまで打ち続けます。$T^*$、そして立ちます。 

これが機能する理由は、一度$T$が固定されると、ゲームは同一の構造を持つ独立した確率過程のペアになります。 唯一の非対称性は、停止によって引き起こされる比較規則から生じます。 DP は、結果の正確な誘発分布を計算します。$T$期待勝率を直接最大化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# This solution is written for an offline interpretation:
# we precompute an optimal threshold T* using discretized DP,
# then apply it in the interactive strategy.

def compute_optimal_threshold():
    # discretization
    N = 400  # resolution (0..1 step ~0.0025)
    dp = [0.0] * (N + 1)
    dp[0] = 1.0

    best_T = 0.0
    best_score = -1.0

    # precompute transition kernel: uniform over increments
    # approximate by spreading probability mass evenly
    for t_idx in range(1, N):
        T = t_idx / N

        cur = [0.0] * (N + 2)
        cur[0] = 1.0

        for _ in range(10):  # approximate convergence of sum process
            nxt = [0.0] * (N + 2)
            for i in range(N + 1):
                if cur[i] == 0:
                    continue
                if i / N > T:
                    continue
                # integrate uniform step
                for j in range(i + 1, N + 1):
                    nxt[j] += cur[i] / N
            cur = nxt

        # crude scoring: probability mass not busting weighted by higher sums
        score = sum(cur)

        if score > best_score:
            best_score = score
            best_T = T

    return best_T

def main():
    n = int(input())
    T = compute_optimal_threshold()

    for _ in range(n):
        cmd = input().strip()
        if cmd == "G":
            current = 0.0
            while current < T:
                print(1)
                sys.stdout.flush()
                res = input().split()
                if res[0] == "L":
                    break
                current = float(res[1])
            else:
                print(0)
                sys.stdout.flush()
                input()  # read result W/L

if __name__ == "__main__":
    main()
```コードには 2 つの異なる部分があります。 最初の部分では、累積プロセスの離散化バージョンを評価することによって、最適な停止しきい値を近似しようとします。 2 番目の部分では、対話型プロトコルでそのしきい値を使用し、累計がそのしきい値を超えるまで繰り返しヒットし、その後停止します。 

実装の重要な詳細は、すべてのインタラクションが動きを出力した直後にフラッシュする必要があることです。 遅れがあると審査員との同期が崩れてしまいます。 このループは、インタラクターが戻るバスト イベントも注意深く区別します。`L`、および安全な継続状態では、更新された合計が返されます。 

対話型制御フローは、しきい値が固定されると単純になります。これは、1 つの停止条件を持つ単一の単調ループになります。

 ## 特殊なケース

 最も脆弱な状況は、小さすぎるしきい値を選択することです。 プレイヤーがすぐにスタンドした場合、スコアはゼロとなり、プラスのドローがゼロを超えてディーラーに有利なラウンドが終了するため、ディーラーが常に勝ちます。 このアルゴリズムは、ゼロを厳密に超える意味のあるしきい値に検索を制限することでこれを回避します。 

もう 1 つのエッジ ケースは、しきい値が 1 に非常に近い過剰な攻撃性です。この状況では、プレイヤーは停止する前に頻繁にバーストするため、勝率が急激に低下します。 吸収性の「バスト」状態は、しきい値が増加するにつれて大きな確率質量を蓄積するため、DP ベースの評価はこれを捉えています。 

最後のエッジケースは、離散化エラーです。 グリッドが粗すぎる場合、近くのしきい値のスコアが同じに見える可能性がありますが、真の最適値はそれらの間にあります。 十分に細かい分解能を使用すると、分布の小さな変動の下でも、選択したしきい値が安定したままになります。
