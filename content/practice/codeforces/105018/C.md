 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$グリッドといくつかのルークが個別のセルに配置されます。 ルークは、その行のすべてのセルとその列のすべてのセルを制御します。 セルは、その行または列を共有するルークがない場合にのみ「安全」とみなされます。 

許可されている操作は、ルークをボードから削除することです。 目標は、あらゆる場所の安全性を最大化することではなく、除去後に少なくとも 1 つの安全なセルの存在を保証することだけです。 このようなセルを存在させるために削除するルークの数を最小限に抑えたいと考えています。 

別の言い方をすると、少なくとも 1 つのセルが必要になります。$(i, j)$削除後に次のように行を追加します。$i$ルークとコラムは含まれていません$j$ルークは含まれていません。 

制約は小さいです。$n \le 50$そして$k \le n^2 \le 2500$。 これにより、おおよその範囲を超えるものは即座に除外されます$O(n^3)$慎重に実装すればテストケースごとに実装されますが、それさえも必要ありません。 グリッド セルの直接列挙はすでに実現可能です。 

単純な間違いは、ルークのサブセットの削除をシミュレートする必要があると考えることです。 たとえば、削除するルークを選択しようとすると、サブセットの数は次のようになります。$2^k$でさえ巨大になります。$k = 2500$。 もう 1 つの間違った方向は、空の行または空の列だけを独立して考慮しているが、条件はペアに依存すると仮定することです。$(row, column)$、一次元だけではありません。 

ルークがまったく存在しない場合、微妙なエッジケースが発生します。 すべてのセルはすでに安全であるため、答えはゼロです。 もう 1 つは、すべての行と列が少なくとも 1 回は占有されるようにルークが分散される場合です。 その場合でも、慎重に選択した行と列の交点からルークを削除しても安全なセルを生成できますが、それは対象を絞った削除が行われた場合に限られます。 

## アプローチ

 強引なアイデアは、除去する可能性のあるすべてのルークのサブセットを試し、安全なセルが存在するかどうかを確認することです。 各サブセットについて、すべての行と列をスキャンして、ペアが存在するかどうかを確認します。$(i, j)$その行と列の両方に残りのルークがありません。 1 つのサブセットのコストを確認する$O(n^2 + k)$、そして、あります$2^k$これは、たとえ最小の非自明な入力であっても、実行可能な限界をはるかに超えています。 

重要な簡素化は視点の変更によるものです。どのルークを削除するかを決定する代わりに、最初にターゲットのセーフ セルを修正します。 安全なセルは次のとおりである必要があると決定したとします。$(i, j)$。 そのためには、漕いでください$i$空の列になる必要があります$j$最終的には空になるはずです。 つまり、並んでいるすべてのルークを除去する必要があるということです$i$そして縦列のすべてのルーク$j$。 そのセルを安全にする他の方法はありません。 

これにより、問題が直接コストの計算に変換されます。 各候補セルについて$(i, j)$、その行または列に何人のルークがあるかを計算します。 これらのルークを削除すると、次のことが保証されます。$(i, j)$が安全になり、そのコストはまさにその選択に必要な除去の数になります。 次に、すべてのセルの最小値を選択します。 

これが機能するのは、すべての有効な最終構成が行と列が完全にクリアされている少なくとも 1 つのセルに対応している必要があり、これを達成する唯一の方法がそれらの線と交差するすべてのルークを削除することであるためです。

 ## アルゴリズムのチュートリアル

 1. 各行と各列にルークの数を数えます。 これにより、すべてのルークを繰り返しスキャンすることなく、後で除去コストを計算することができます。 
2. ブール グリッドまたはセットを使用して、各セルにルークが存在するかどうかを記録します。 これは、ルークが選択した行と列の交点にあるときに二重カウントを避けるために必要です。 
3. すべてのセルについて$(i, j)$、安全にするためのコストを計算します。 コストは並んでいるルークの数です$i$列内のルークの数を加えたもの$j$、すでにルークがある場合はマイナス 1$(i, j)$。 
4. すべてのセルにわたる最小コストを追跡します。 これは、ボード上の任意の場所に少なくとも 1 つの安全なセルを作成するために必要な除去の最小数を表します。 
5. 各テスト ケースに対してこの最小値を出力します。 

### なぜ効果があるのか

 ターゲットセルの固定$(i, j)$削除後、その行と列の両方にルークが存在しない必要があるという厳しい要件が強制されます。 これらのラインの外側にあるルークはその特定のセルの安全性に影響を与えませんが、内側にあるルークは削除する必要があります。 したがって、各候補セルのコストは完全に決定され、他の場所での決定とは独立しています。 すべての有効な解は安全になる少なくとも 1 つのセルに対応する必要があるため、すべての候補を最小化することですべての可能性がカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        
        row = [0] * (n + 1)
        col = [0] * (n + 1)
        has = [[0] * (n + 1) for _ in range(n + 1)]
        
        for _ in range(k):
            x, y = map(int, input().split())
            row[x] += 1
            col[y] += 1
            has[x][y] = 1
        
        ans = k
        
        for i in range(1, n + 1):
            for j in range(1, n + 1):
                cost = row[i] + col[j] - has[i][j]
                if cost < ans:
                    ans = cost
        
        print(ans)

if __name__ == "__main__":
    solve()
```実装はその推論を直接反映しています。 行配列と列配列にはカウントが保存されるため、各候補セルを一定時間で評価できます。 グリッド`has`ルークが交差点に正確にある場合の二重減算を防ぎます。 答えは次から始まります$k$すべてのルークを削除すると、常に有効な構成が保証されるためです。 

すべてのセルにわたる二重ループは安全です。$n \le 50$、テスト ケースごとに最大 2500 の評価が与えられます。 

## 実用的な例

 ルークがいくつかの点在する位置を占める小さなボードを考えてみましょう。 

入力：```
1
3 3
1 1
1 2
2 3
```最初に行数と列数を計算します。 

| ステップ | 行1 | 行2 | 行3 | 列1 | 列2 | 列3 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 入力後 | 2 | 1 | 0 | 1 | 1 | 1 |

 次に、各セルのコストを評価します。 

| セル | 行 + 列 - オーバーラップ | 説明 |
 | --- | --- | --- |
 | (1,1) | 2 + 1 - 1 = 2 | 交差点のルーク | 写真 交差点のルーク
 | (1,2) | 2 + 1 - 1 = 2 | 再び交差点 |
 | (1,3) | 2 + 1 - 0 = 3 | (1,3) にルークはありません |
 | (2,1) | 1 + 1 - 0 = 2 | |
 | (2,2) | 1 + 1 - 0 = 2 | |
 | (2,3) | 1 + 1 - 1 = 1 | 最良の選択 |
 | (3,1) | 0 + 1 = 1 | |
 | (3,2) | 0 + 1 = 1 | |
 | (3,3) | 0 + 1 = 1 | |

 最小値は 1 です。つまり、安全なセルのロックを解除するにはルークを 1 つ取り除くだけで十分です。 

このトレースは、解がグローバル構造に依存せず、純粋にローカルな行と列の交差にどのように依存するかを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    import sys
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n, k = map(int, input().split())
            row = [0] * (n + 1)
            col = [0] * (n + 1)
            has = [[0] * (n + 1) for _ in range(n + 1)]

            for _ in range(k):
                x, y = map(int, input().split())
                row[x] += 1
                col[y] += 1
                has[x][y] = 1

            ans = k
            for i in range(1, n + 1):
                for j in range(1, n + 1):
                    ans = min(ans, row[i] + col[j] - has[i][j])
            out.append(str(ans))
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 ルークが存在しない場合、行数と列数はどこでもゼロのままであるため、すべてのセルはコストがゼロと評価され、最小値はゼロになります。 このアルゴリズムは、特別な処理を行わなくても、当然のことながらゼロを返します。 

すべてのルークが 1 つの行にある場合、その行のすべての候補セルは高いコストを生成しますが、他の行のセルは列数のみに依存します。 最小値は占有されている行の外側の行に正しく移動し、削除は必要ありません。 

ルークがほぼすべての行と列をカバーする場合、交差点の修正`-has[i][j]`が重要になります。 それがなければ、ルークは次の場所に置かれます。$(i, j)$2 回カウントされ、削除コストが膨らみ、不正確な回答が生成される可能性があります。
