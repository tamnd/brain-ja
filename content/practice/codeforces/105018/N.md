 ## 解決策
 ## 問題の理解

 この問題では、次のように表される火山ピットについて説明します。$n \times m$グリッド。各セルには、時刻 0 のマグマ レベルと比較してその点がどれだけ高いかが格納されます。 値がゼロのセルはすでにマグマレベルにあり、すぐに水没することを意味します。 

マグマは時間の経過とともに 1 ミリ秒あたり 1 ミリメートルの速度で均一に上昇し始めます。 時間が経過するにつれて、有効マグマ レベルが増加するため、現在のマグマ レベル以下の高さのセルはすべて水没します。 

ドラゴンの卵は特定のセルに配置されます$(x, y)$そして、マグマが最初にそのセルに到達する正確な瞬間を特定したいと考えています。 ただし、マグマは必ずしもその高さを通ってそのセルに直接到達する必要はありません。 周囲の岩石が障壁を形成している場合、マグマは外側の溶岩領域から卵の位置までの経路に沿って最も低い障壁を通って「オーバーフロー」する必要があります。 外側の境界はすでに溶岩であるため、マグマは常にそこから始まり、より低い制約を通って内側に伝播する可能性があります。 

重要な解釈は、卵に触れた時間は、境界 (最初の溶岩領域) から卵細胞までのあらゆる経路に沿った、可能な最小限の「最大高度バリア」によって決まるということです。 つまり、すべてのパスには、そのパスに沿った最大セル値によって定義される制限の高さがあり、この最大値を最小化するパスが必要になります。 

制約により、最大で次のことが許可されます。$10^3 \times 10^3$グリッド サイズ、つまり 100 万セルです。 これは、次のような解決策がすぐに示唆されます。$O(n^2 \log n)$または$O(n^2)$許容されますが、次のようなものは$O(n^2 \cdot n)$またはクエリごとに BFS/DFS を繰り返すと遅すぎます。 

単純なアプローチでは、マグマのミリ秒ごとの上昇や時間しきい値ごとの洪水の充填をシミュレートしようとする可能性があります。 それは不可能です、なぜなら答えは次のとおりです$10^9$、各シミュレーション ステップではグリッドをスキャンする必要があり、制限のない結果が発生します。$O(10^9 \cdot nm)$プロセス。 

2 番目の素朴なアイデアは、卵細胞について、境界からのすべてのパスを試し、各パスに沿った最大標高を計算することです。 ただし、すべてのパスを列挙することは指数関数的であり、たとえ小さなグリッドであっても実行不可能です。 

さらに微妙な間違ったアプローチは、卵細胞自体の高さのみが必要であると仮定することです。 これは失敗します。なぜなら、卵はより高い岩石の輪に囲まれている可能性があり、マグマはそこに到達する前にまずその輪の上に上昇する必要があるからです。 

具体的な失敗例は次のとおりです。```
0 2 0
2 1 2
0 2 0
```卵が中心にある場合、その値は 1 ですが、周囲の障壁がアクセスをブロックしているため、マグマは 2 に上昇するまで到達できません。 「単に a[x][y] を取るだけです」という素朴な答えは 1 を出力しますが、これは正しくありません。 正解は 2 です。 

## アプローチ

 ブルート フォース ビューポイントでは、グリッドを重み付けされた風景として扱い、隣接するセル間の各移動は、これまでに遭遇した最高標高によって制限されます。 任意の境界セルから、パスに沿った最大高度を追跡しながら卵細胞に到達しようとします。 すべての可能なパスの中で、この最大値を最小にするパスが必要です。 

これは古典的なミニマックス パスの問題です。 ブルート フォース ソリューションでは、境界からターゲットまでのすべてのパスを列挙し、各パスの最大セル値を計算し、これらの最大値の最小値を取得します。 グリッド内のパスの数は、おおよそ指数関数的に増加します。$O(4^{nm})$最悪の場合、これは完全に不可能になります。 

重要な洞察は、これが各ノードがグリッド セルであるグラフの最短パス問題と同等ですが、パス コストは加算されないということです。 代わりに、パスのコストは、そのパスに沿った最大のエッジの重み (セルの高さ) です。 これにより、問題は発生する最大重みを最小化する経路を見つけることに変換されます。これは、緩和が使用するダイクストラのアルゴリズムの変形を使用して自然に解決されます。`max(current_cost, next_cell_value)`追加の代わりに。 

マグマは外側から発生するため、すべての境界セルから同時に開始します。 各境界セルには、その高さに等しい初期コストがあります。 次に、内側に伝播し、常に最初に既知の最小電流の「フラッド レベル」でセルを拡張します。 これにより、最初に細胞に到達したときに、細胞を上昇するマグマにさらす最善の方法をすでに見つけていることが保証されます。 

これは事実上、グリッド グラフ上のミニマックス最短パスです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | ミニマックス・ディクストラ |$O(nm \log nm)$|$O(nm)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各グリッド セルをグラフ内のノードとして扱います。 隣接するセル間の移動には、従来の意味ではコストがかかりません。 代わりに、各ノードはその高さを制約として提供します。 

1. すべての境界セルを含む優先キューを初期化します。これは、これらのセルが時刻 0 ですでにマグマに隣接しているためです。 各境界セルは、その高さに等しいコストで挿入されます。 これは、マグマがその細胞に影響を与えた最も古い時期を表しています。 
2. 距離配列を維持する`dist[i][j]`ここで、各値には、境界からそのセルに到達するために必要な最小可能な最大標高が格納されます。 最初は、境界セルを除くすべての値が無限大です。 
3. 優先キューから現在のコストが最小のセルを繰り返し抽出します。 これにより、常に最も有望な「最も障壁の低い」領域を最初に拡張することが保証されます。 
4. 抽出された各セルについて、その 4 つの隣接セルをリラックスしてみます。 近傍の場合、候補コストを次のように計算します。`max(current_cost, grid[nx][ny])`。 これは、マグマがこのパスを介して隣のマグマに到達するために通過しなければならない最も高い岩を表します。 
5. この候補コストが近隣の既知のコストよりも小さい場合、それを更新し、優先キューにプッシュします。 
6. 到達可能なすべての細胞が処理されるまで、または卵細胞が完成するまで続けます。 
7. 答えは次のとおりです。`dist[x][y]`。 

正確さは、セルが優先キューからポップされるときはいつでも、境界からセルに到達するために必要な最小限の最大バリアがすでに見つかっているという不変条件から得られます。 代替パスは、同等以上の中間最大値を使用するため、結果を改善できません。 

これが機能するのは、プライオリティ キューが常にボトルネック値の増加順に状態を拡張し、確定後にノードへのより適切なパスが存在しないようにするためです。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    x, y = map(int, input().split())
    x -= 1
    y -= 1

    grid = [list(map(int, input().split())) for _ in range(n)]

    INF = 10**18
    dist = [[INF] * m for _ in range(n)]
    pq = []

    # all boundary cells start from outside lava
    for i in range(n):
        for j in range(m):
            if i == 0 or j == 0 or i == n - 1 or j == m - 1:
                dist[i][j] = grid[i][j]
                heapq.heappush(pq, (dist[i][j], i, j))

    dirs = [(1,0), (-1,0), (0,1), (0,-1)]

    while pq:
        cost, i, j = heapq.heappop(pq)

        if cost != dist[i][j]:
            continue

        if i == x and j == y:
            print(cost)
            return

        for di, dj in dirs:
            ni, nj = i + di, j + dj
            if 0 <= ni < n and 0 <= nj < m:
                nc = max(cost, grid[ni][nj])
                if nc < dist[ni][nj]:
                    dist[ni][nj] = nc
                    heapq.heappush(pq, (nc, ni, nj))

def main():
    solve()

if __name__ == "__main__":
    main()
```マグマは外層のどこからでも発生するため、このソリューションでは、すべての境界セルから複数ソースのダイクストラ初期化を使用します。 各緩和ステップでは、近隣に到達するための最もよく知られているボトルネック値が更新されます。 

実装の微妙な点は、移動コストを加算的なものとして決して扱わないことです。 使用する`max(cost, grid[nx][ny])`は不可欠です。 これを加算に置き換えると、高さは累積距離ではなくしきい値を表すため、モデルが完全に壊れてしまいます。 

もう 1 つの重要な点は、ターゲット セルがポップされたときの早期終了です。 ダイクストラはコストが非降下であることを保証しているため、初めて卵細胞を破砕した時点で、すでにその最適値が見つかっています。

2 2

 | --- | --- | --- | --- |
 | 1 | 境界セル | 0 | フロンティアを初期化する |

 アルゴリズムは、中心に到達するには少なくとも高さ 1 を通過する必要があることを発見したため、答えは 1 になります。 

これは、ほとんどの地形が平坦であっても、単一の高いセルでもボトルネックを決定することを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、高さ 0 の境界溶岩に隣接しているため、卵が時刻 0 で既に実質的に水没している場合です。 このような場合、アルゴリズムはすぐに境界伝播から開始され、卵細胞の計算コストがすでにゼロになっている可能性があります。 優先キューはそれを早期にポップし、追加の処理を行わずに正しい答えを生成します。 

もう 1 つのエッジ ケースは、卵が徐々に高くなる壁で囲まれる完全に囲まれた盆地です。 この状況では、アルゴリズムにより、各層を通過するにつれてコストが徐々に増加することが保証されます。 異なるバリア プロファイルを持つ複数のパスがある場合でも、ミニマックス伝播により、可能な限り低い最大値が選択されることが保証されます。 

最後の微妙なケースは、複数の境界パスが異なる中間最大値を持つ同じセルにつながる場合です。 ヒープは同じノードに複数のエントリをプッシュする可能性がありますが、`if cost != dist[i][j]`ガードは、古い状態が無視されることを保証し、誤った更新を防ぎ、緩和が繰り返されても正確さを維持します。
