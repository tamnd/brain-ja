 ## 解決策
 ## 問題の理解

 接頭辞の合計と接尾辞の合計が 4 つの極値条件を同時に満たすような整数配列を構築するように求められます。 

選択した配列について、ゼロから始まり左から右に要素を累積する実行中のプレフィックス合計シーケンスを考慮します。 このシーケンスには最高値と最低値があります。 これら 2 つの値が何でなければならないかがわかります。プレフィックスの合計は最大値に達する必要があります。`a`そして最低限の`b`。 

同時に、右側から見て、接尾辞の合計を各位置から最後までの要素の合計として定義すると、その接尾辞の合計シーケンスにも最大値と最小値が存在します。 これらは必ず`c`そして`d`。 

したがって、タスクはこれらの値を計算することではなく、これら 4 つの極値制約を正確に生成する配列を構築するか、不可能性を報告することです。 

制約の規模は大きくなりますが、出力配列のサイズは十分に小さい (最大 1000)。 これは、組み合わせや検索を試すのではなく、プレフィックス合計のパスを明示的に構築する建設的な解決策を強く示唆しています。 1 つの候補をチェックするだけでも接頭辞と接尾辞の線形計算が必要であり、配列の空間は原理的に無限であるため、配列を総当りで処理しようとする解決策は直ちに実行不可能になります。 

微妙だが重要な問題は、接頭辞と接尾辞の条件が独立していないことです。 単純なアプローチでは、プレフィックスと合計のパスのマッチングを個別に構築しようとする可能性があります。`(a, b)`そしてもう一つのマッチング`(c, d)`それらを連結しますが、サフィックスの合計はグローバル合計に依存するため、任意に連結すると一貫性が失われます。 

必要な極値に互換性がない場合、エッジ ケースが発生します。 たとえば、プレフィックスの合計がゼロを含まない範囲にあると想定されている場合、プレフィックスの合計は常に 0 から始まるため、構築は不可能になります。 したがって、有効な解決策は少なくともそれを尊重する必要があります`0`間にあります`b`そして`a`。 

## アプローチ

 強引なアイデアは、配列を段階的に構築し、プレフィックスとサフィックスの両方の制約を同時に維持しようとすることです。 各位置で値を選択し、プレフィックスとサフィックスの極値を再計算します。 すべての位置が多くの整数の選択肢に分岐し、制約はローカルで決定できない将来の接尾辞の動作に依存するため、これはすぐに指数関数的になります。 境界による枝刈りでも依然として指数関数的な状態空間が残ります。 

重要な簡素化は、すべてをプレフィックスの合計のみの観点から書き直すことで実現します。 させて`S[i]`との接頭辞の合計になります`S[0] = 0`そして`S[n]`合計に等しい。 すべての接尾辞の合計は次のように書くことができます。`total - S[i]`。 これは、接尾辞の極値が接頭辞の極値と最終合計によって完全に決定されることを意味します。 

この観察から、接尾語制約は新たな構造的自由を導入するものではなく、単に要素間の関係を固定するだけであることがわかります。`a, b, c, d`そしてその合計額。 これらが一貫していると、タスクは次のステップに戻ります。`0`一定期間内に収まる最終合計まで`[b, a]`そして実際には両方のエンドポイントに到達します。 

これにより、問題は、高さが制限された 1 次元格子パスの構築に変換され、決定論的に実行できます。

 | プレフィックス合計の削減 + 構築的なパス | O(a - b + c) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 プレフィックスの合計を次のように表します。`S`、 と`S[0] = 0`。 

### ステップ 1: サフィックス制約をプレフィックス形式に変換する

 接尾語の合計を総和で表現します`T = S[n]`。 位置の接尾辞の合計`i`等しい`T - S[i-1]`。 したがって、サフィックスの最大値はプレフィックスが最小のときに発生し、サフィックスの最小値はプレフィックスが最大のときに発生します。 これにより、次の関係が得られます。`c = T - b`そして`d = T - a`両方の方程式は同じ合計を表すため、次のようにする必要があります。`T = a + d = b + c`。 これは一貫性の要件です。 失敗すると、配列は存在できなくなります。 

### ステップ 2: プレフィックス合計の実現可能条件を導出する

 プレフィックスの合計は常にゼロから始まるため、間隔は`[b, a]`ゼロを含める必要があります。 最終的な金額も`T`この間隔内に存在する必要があります。そうでない場合、プレフィックス合計シーケンスは次で終了できません。`T`限界を侵さずに。 

したがって、私たちは次のようにしなければなりません`b ≤ 0 ≤ a`そして`b ≤ T ≤ a`。 

置き換える`T = b + c`を取得します。`0 ≤ c ≤ a - b`。 これが失敗すると建設が不可能になります。 

### ステップ 3: タスクを制約付きウォークとして再定式化する

 一連のステップが必要になります`+1`そして`-1`(またはより一般的には整数ステップ) で始まります。`0`、で終了します`T`、決して離れない`[b, a]`、両方のエンドポイントを達成します`a`そして`b`ある時点で。 

これを保証する最も簡単な方法は、両方の境界への訪問を明示的に強制することです。 

### ステップ 4: パスを構築する

 プレフィックス合計の軌道を 3 つのフェーズで構築します。 

まずはから移動します`0`まで`a`を使用して`+1`ステップ。 これは常に有効です。`0 ≤ a`。 

次に、から移動します`a`まで`b`を使用して`-1`ステップ。 これを下回ることがないため、これは範囲内に留まります`b`。 

最後に、から移動します`b`まで`T`を使用して`+1`ステップ。 これは有効です。`T ≤ a`。 

結果として得られるパスは連続的であり、範囲内に留まります。`[b, a]`、正しい合計で終了します。 

### なぜ効果があるのか

 構築されたプレフィックス和シーケンスは、各フェーズ内では単調ですが、全体的には単調ではありません。これは、最小値と最大値の両方を達成するために重要です。 各フェーズでは 1 つの極値に到達することが明示的に保証されるため、最終シーケンスでは両方の極値が達成されます。`a`そして`b`。 サフィックスの合計はプレフィックスの合計と最終合計によってのみ決定されるため、プレフィックス制約を照合して正しい合計を適用すると、サフィックスの極値が自動的に一致します。`c`そして`d`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c, d = map(int, input().split())

        T1 = a + d
        T2 = b + c

        if T1 != T2:
            print(-1)
            continue

        T = T1

        if not (b <= 0 <= a):
            print(-1)
            continue

        if not (b <= T <= a):
            print(-1)
            continue

        res = []

        # 0 -> a
        res.extend([1] * a)

        # a -> b
        res.extend([-1] * (a - b))

        # b -> T
        res.extend([1] * (T - b))

        print(len(res))
        print(*res)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず両方の合計計算方法が一致することを検証します。 これがないと、プレフィックス制約とサフィックス制約が互いに矛盾します。 

その後、プレフィックス合計間隔がゼロ付近で有効であること、および間隔内でターゲット合計に到達可能であることを確認します。 

構造自体は、接頭辞合計の軌跡を直接変換したものです。`+1`または`-1`実行合計の制御された変化に対応し、必要な合計で終了する前にパスが両方の境界に達するようにステップ数が選択されます。 

よくある落とし穴は、プレフィックスの合計には開始点としてゼロが含まれている必要があることを忘れていることです。 もう 1 つは、セグメントの順序は機能すると仮定していますが、実際には、その順序は内部のウォークを維持するために慎重に選択されています。`[b, a]`あらゆる段階で。 

## 実用的な例

 一貫したケースを考えてみましょう。 

入力:```
1
3 -2 4 -1
```私たちは計算します`T = a + d = 3 + (-1) = 2`、そしてまた`b + c = -2 + 4 = 2`, したがって、インスタンスは実行可能です。 間隔は`[-2, 3]`。 

| フェーズ | アクション | プレフィックス合計範囲 | 現在の合計 |
 | --- | --- | --- | --- |
 | 開始 | 0 | [0] | 0 |
 | 0 → a | +1 3 回 | [0,3] | 3 |
 | a → b | -1 5 回 | [3,-2] | -2 |
 | b→T | +1 4 回 | [-2,2] | 2 |

 これは、両方の極値が`3`そして`-2`に達し、最終的な合計が一致する`T`。 

次に、無効なケースを考えてみましょう。 

入力:```
1
2 1 3 0
```ここ`a + d = 2 + 0 = 2`しかし`b + c = 1 + 3 = 4`。 この不一致は、プレフィックスとサフィックスの両方の制約を同時に満たすことができない構造がないことを直ちに示しています。

 ## 特殊なケース

 エッジケースの 1 つは次の場合に発生します。`a = 0`または`b = 0`これは、プレフィックス合計間隔が 1 つの境界で開始点に正確に触れることを意味します。 その場合、第 1 フェーズは完全に消滅する可能性がありますが、次のフェーズから移行するため、建設はまだ機能します。`0`に`a`次の場合にステップは不要です`a = 0`。 

もう 1 つのケースは、目標の合計が`T`境界の 1 つに等しい。 もし`T = a`、最終フェーズは空になり、構築は制約に違反することなく最大プレフィックス値で正しく終了します。 

最後の微妙なケースは次のような場合です。`b`は負であり、大きさは大きい。 その後、第 2 フェーズは長くなりますが、パスが以下に低下することはないため、すべてのステップは有効なままです。`b`、そして我々は明示的にちょうどそこで停止します`b`再び上に移動する前に。
