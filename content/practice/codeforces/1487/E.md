 ## 解決策
 ## 問題の理解

 アイテムは 4 層あります。 

1段目は1品目、2段目は2品目、3段目はドリンク、4段目はデザートとなります。 すべてのアイテムにはコストがかかります。 

隣接するレイヤーの各ペアの間では、いくつかの組み合わせが禁止されています。 最初のコースは特定の 2 番目のコースと適合しない場合があり、2 番目のコースは特定のドリンクと適合しない場合があり、ドリンクは特定のデザートと適合しない場合があります。 

各レイヤーからアイテムを 1 つだけ選択する必要があります。 選択したシーケンス内のすべての隣接するペアを許可する必要があります。 すべての有効なディナーの中で、総コストを可能な限り最小限に抑えたいと考えています。 

問題を階層化したグラフとして表示するのが最も自然な方法です。 各項目は頂点です。 エッジは隣接するレイヤー間にのみ存在し、それらのエッジの一部は禁止されているため削除されます。 レイヤー 1 で始まりレイヤー 4 で終わる最も安価なパスが必要です。ここで、パスのコストは頂点のコストの合計です。 

制約は解決策の方向性を完全に決定します。 各レイヤーには最大 150,000 個の項目を含めることができますが、禁止されたペアの各セットには最大 200,000 個のエントリが含まれます。 層間の二次アルゴリズムは不可能です。 2 つのレイヤー間のすべてのペアをチェックする場合でも、大まかに必要になります。$150000^2$限界をはるかに超えた操作。 

有益な観察は、禁止されたペアの数が、可能なペアの数に比べて比較的少ないということです。 入力には、許可されているすべての接続が記述されているわけではありません。 代わりに、悪いものだけをリストします。 これは、考えられるすべてのエッジを中心とするのではなく、禁止されたセットを中心にソリューションを構築することを強く示唆しています。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

すべてのアイテムが到達不能になるレイヤーを考えてみましょう。```
Layer A costs: [1]
Layer B costs: [2]
Forbidden: (A1,B1)
```有効な遷移が存在しません。 レイヤー B のアイテムの正しい値は「不可能」です。 誤って元のコストを維持した場合、後の層がそれを介してソリューションを誤って構築する可能性があります。 

もう 1 つの微妙なケースは、最も安価な先行製品が禁止されているにもかかわらず、より高価な先行製品が利用可能である場合に発生します。```
Previous layer values: [1, 5]
Current item forbids predecessor 1
```このアイテムの答えは、無限ではなく、5 にそれ自身のコストを加えたものです。 世界的に最も安価な先行製品のみをチェックするソリューションは失敗します。 

3 番目に重要なケースは、アイテムの先行するすべてのアイテムが禁止されている場合です。```
Previous layer values: [3, 7]
Forbidden predecessors: {1, 2}
```アイテムは到達不能になるはずです。 この状況の検出を忘れた実装では、誤って無効な値を再利用する可能性があります。 

## アプローチ

 総当りのアプローチでは、可能な限りのディナーを試します。 

最初のコースごとに、2 番目のコースごとに試してください。 有効なペアごとに、すべての飲み物を試してください。 有効なトリプルごとに、すべてのデザートを試してください。 すべての隣接ペアが許可される場合は常に、合計コストを計算し、最小値を維持します。 

このアプローチは、すべての有効なディナーを明示的に検査するため、正しいです。 残念ながら、その複雑さは、$$O(n_1 n_2 n_3 n_4)$$これは次のように大きくすることができます$$150000^4$$そしてそれは完全に不可能です。 

問題の構造を利用する必要があります。 

1 つのレイヤー内のすべての項目について、達成可能な最低コストがすでにわかっているとします。 次の層のすべての項目について、達成可能な最も安いコストを計算したいと考えています。 

固定アイテムの場合$v$次の層では、$$dp[v] = cost[v] + \min(dp[u])$$すべての先人を超えて$u$禁止されていないもの$v$。 

難しいのは、その最小値を効率的に見つけることです。 

単純な実装では、すべての項目についてすべての先行処理をスキャンします。 それは再び二次関数になります。 

重要な観察は、各項目が全体として比較的少数の先行操作のみを禁止していることです。 すべての先行値をコストで並べ替える場合、特定のアイテムについて、並べ替えられたリストを最も安いものから最も高価なものまでたどって、禁止されていない最初の先行値を選択できます。 

なぜこれが効率的なのでしょうか?

 各アイテムには、その禁止された先行アイテムのみが保存されます。 禁止されたペアの数は最大 200,000 です。 ソートされた先行タスクのリストはすべてのアイテムで共有されるため、候補先行タスクが禁止されているかどうかを確認することは、単なるハッシュセットの検索です。 

すべての項目について、最初の許可された先行操作が見つかるまで、ソートされた先行操作リストを検索します。 禁止されたペアの総数が少ないため、このプロセスは十分に高速です。 

この変換を 3 回実行します。 

1.第1コース→第2コース。 
2. 2皿目→ドリンク。 
3.ドリンク→デザート。 

最後の変換後の答えは、デザート層で到達可能な最小値になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n_1 n_2 n_3 n_4)$|$O(1)$| 遅すぎる |
 | 最適 |$O((N+M)\log N)$|$O(N+M)$| 承認済み |

 ここ$N=n_1+n_2+n_3+n_4$そして$M=m_1+m_2+m_3$。 

## アルゴリズムのチュートリアル

 前のレイヤーのすべての項目について達成可能な最良のコストがわかっていると仮定します。 

次の層で達成可能な最良のコストを計算する手順が必要です。 

### 移行手順

 1. 前のレイヤーのすべてのアイテムを現在の DP 値で並べ替えます。 
2. 現在のレイヤー内のすべてのアイテムについて、禁止された先行アイテムのセットを保存します。 
3. 現在のレイヤーの各アイテムを個別に処理します。 
4. ソートされた先行製品リストを、最も安いものから最も高価なものまでスキャンします。 
5. 現在の項目の禁止されたセットにインデックスが存在しない最初の先行項目を見つけます。 
6. そのような先行品が存在する場合、その DP 値を現在のアイテム自体のコストに追加します。 
7. 先行者が存在しない場合は、非常に大きな値を使用して、現在の項目を到達不能としてマークします。 

### 完全なアルゴリズム

 1. 最初のレイヤーの DP 値をコストに初期化します。 
2. レイヤ 1 からレイヤ 2 への移行手順を適用します。 
3. レイヤ 2 からレイヤ 3 への移行手順を適用します。 
4. レイヤ 3 からレイヤ 4 への移行手順を適用します。 
5. 4 番目のレイヤーの最小 DP 値を取得します。 
6. 最小値が無限大の場合、出力`-1`。 それ以外の場合は、その最小値を出力します。 

### なぜ効果があるのか

 現在のレイヤー内のすべての項目について、その項目で終わるすべての有効なディナーは、許可された先行処理を経由する必要があります。 

ソートされた先行タスクのリストでは、DP の昇順で先行タスクが検査されます。 禁止されていない最初の先行操作は、まさに最小の DP 値を持つ許可された先行操作です。 

したがって、遷移は次のように計算されます。$$cost[v]+\min_{\text{allowed }u} dp[u]$$これはまさにアイテムの最適な値です$v$。 

すべてのレイヤーは前のレイヤーの正しい値から計算されるため、帰納法により、すべての DP 値が最適なままであることがわかります。 デザート ノードの最後の最小値は、まさに最も安価な有効なディナーです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

n1, n2, n3, n4 = map(int, input().split())

a = list(map(int, input().split()))
b = list(map(int, input().split()))
c = list(map(int, input().split()))
d = list(map(int, input().split()))

def build(prev_dp, cur_costs):
    m = int(input())

    bad = [set() for _ in range(len(cur_costs))]
    for _ in range(m):
        x, y = map(int, input().split())
        bad[y - 1].add(x - 1)

    order = sorted(range(len(prev_dp)), key=lambda i: prev_dp[i])

    res = [INF] * len(cur_costs)

    for i in range(len(cur_costs)):
        for p in order:
            if p not in bad[i]:
                if prev_dp[p] < INF:
                    res[i] = cur_costs[i] + prev_dp[p]
                break

    return res

dp2 = build(a, b)
dp3 = build(dp2, c)
dp4 = build(dp3, d)

ans = min(dp4)

print(-1 if ans >= INF else ans)
```実装は動的プログラミングの定式化に直接に従います。 

として渡される配列`prev_dp`には、前のレイヤーのすべてのアイテムの達成可能な最小コストがすでに含まれています。 の`build`関数は次の層の DP 値を計算します。 

現在のレイヤーの各アイテムは、その禁止された先行アイテムをハッシュ セットに保存します。 メンバーシップテストは、$O(1)$平均して。 

ソートされた配列`order`重要な最適化です。 前のインデックスを最小の DP 値から最大の DP 値までリストします。 現在の項目を処理するときは、禁止されていない先行項目が見つかるまでこのリストを検索します。 リストはソートされているため、その先行するものは自動的に許容される最も安価なものになります。 

小切手`prev_dp[p] < INF`到達不可能な状態が有効な先行状態として使用されるのを防ぎます。 

入力のインデックスは 1 から始まりますが、Python リストは 0 から始まります。 変換は、禁止されたペアを読み取るとすぐに実行されます。 

値`INF = 10**18`考えられるすべての有効な答えを安全に超えています。 最大の夕食費は最大です$4 \times 10^8$したがって、到達可能な状態と到達不可能な状態が混同される危険はありません。

 ## 特殊なケース

 アイテムがすべての先行アイテムを禁止する場合を考えてみましょう。```
Previous DP: [3, 7]
Forbidden predecessors: {1, 2}
```ソートされた先行順序は次のとおりです。`[3, 7]`。 アルゴリズムは両方のエントリをチェックし、両方の禁止されたエントリを検出し、結果を更新しません。 アイテムの価値は残ります`INF`、これは正しく到達不能としてマークされます。 

最も安価な先行処理が禁止されているが、別の有効な先行処理が存在する場合を考えてみましょう。```
Previous DP: [1, 5, 10]
Forbidden predecessors: {1}
```アルゴリズムはDP値をチェックします`1`、禁止されているため拒否し、DP 値を確認します`5`そしてそれを受け入れます。 結果として生じる移行にはコストがかかります`5`これは、許可されているすべての先行タスクの中でまさに最小値です。 

レイヤー全体のすべてのアイテムが到達不能になった場合を考えてみましょう。```
Layer 1: [1]
Layer 2: [2]
Forbidden: (1,1)
```レイヤ 2 の唯一の項目が値を受け取ります`INF`。 後の遷移が計算されるとき、条件は`prev_dp[p] < INF`この到達不可能なアイテムが使用されるのを防ぎます。 不可能性は最終的な答えに正しく伝播し、それは次のようになります。`-1`。
