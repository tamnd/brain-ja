 ## 問題の理解

 整数のトリプルを探しています$(a, b, c)$そのような$1 \le a \le b \le c \le n$。 2 つの条件が同時に成立する必要があります。 

最初の条件は標準的な幾何学的条件です。これら 3 つの数値は直角三角形の辺として機能する必要があるため、次のように順序付けした後、$a \le b \le c$、彼らは満足しなければなりません$a^2 + b^2 = c^2$。 

2 番目の条件は人為的であり、間違った式から来ています。3 番目の値も満たす必要があります。$c = a^2 - b$。 したがって、一般的なピタゴラス トリプルを検索するのではなく、この追加の 2 次制約にも当てはまるものだけを検索します。 

タスクは、クエリごとにそのようなトリプルがいくつ存在するかをカウントすることです。$n$、 どこ$n$と同じ大きさにすることができます$10^9$、最大で$10^4$テストケース。 

この制約は、考えられるすべてのペアを列挙することを直ちに意味します。$(a, b)$まで$n$不可能です。 ナイーブ$O(n^2)$テストケースごとのスキャンには最大で次のものが含まれます$10^{18}$実行可能な限界をはるかに超えた最悪の場合の操作。 

さらに微妙な観察は、有効な解決策は非常にまれであるということです。 制約により、両方の方程式が同時に成立するように強制されるため、通常、探索空間は少数の小さな構造化された候補のみに縮小されます。 

よくある落とし穴は、以下に多数のピタゴラス トリプルがあると仮定することです。$n$そして、ユークリッドの公式を使用してそれらを事前計算または生成しようとします。 このアプローチでは 2 番目の方程式が無視され、ほとんどすべての古典的なトリプルが削除されます。 もう一つの間違いは症状の治療です$c = a^2 - b$順序を確認せずに独立してそこから値を生成する$a \le b \le c$、無効なトリプルが生成される可能性があります。 

3 番目の微妙な問題は、オーバーフローのような推論です。$a^2$急速に成長するため、次のような限界を早まって想定してしまう可能性があります。$a \le \sqrt{n}$常に重要ですが、ここでは実現可能性は両方の方程式によって決まります。 

## アプローチ

 ブルートフォースソリューションでは、すべてのトリプルに対して反復処理が行われます。$(a, b, c)$と$1 \le a \le b \le c \le n$、両方の条件を確認し、一致するものをカウントします。 これは定義を直接検証するため、正しいです。 ただし、トリプルの数は次のとおりです。$n^3$、さらにペアに減らすこともできます$(a, b)$葉$O(n^2)$、これはまだ大きすぎます$n = 10^9$。 

重要な洞察は、2 つの方程式が一緒になって剛直な代数系を形成しているということです。 置き換える$c = a^2 - b$の中へ$a^2 + b^2 = c^2$2 つの変数で単一のディオファントス方程式を与えます。 拡張:$$a^2 + b^2 = (a^2 - b)^2$$これは、可能な整数解を大幅に制限する 4 次の関係に単純化されます。 重要な認識は、$a$大きくすることはできません。 以来$c = a^2 - b \le n$そして$b \ge 1$、すぐに得られます$a^2 \le n + b \le 2n$、 それで$a \le \sqrt{2n}$。 しかし、方程式自体の構造からより強力な制限が生じます。$a$固定されており、$b$は再配置によって一意に決定され、実現可能性は、結果として次の結果が得られるかどうかを確認することに帰着します。$b, c$範囲内の整数であり、順序を満たします。 

これにより、問題は可能な限り反復されるようになります。$a$、暗黙の計算$b$、構築されたトリプルが有効かどうかを検証します。 以来$a$まで上がるだけでいい$O(\sqrt{n})$、大規模な場合でもソリューションは効率的になります。$n$。 

この問題の驚くべき点は、有効なトリプルの実際の数が非常に少ないことです。 実際、両方の制約を乗り越えられる構造的な解決策はほんのわずかしかないため、テスト ケースごとの答えは、そのような解決策を数えることから導き出すことができます。$c \le n$。

 ## アルゴリズムのチュートリアル

 問題となるほど大きくなり得る唯一の変数を反復処理することで、解を導き出します。$a$。 

1. 反復する$a$1から上に進みますが、一度停止します$a^2 - 1 > n$。 これにより、すべての計算結果が保証されます。$c$制限を超えることはできません。 
2. 固定ごとに$a$、 扱う$b$不明で代替品として$c = a^2 - b$ピタゴラス方程式に当てはめます。 これにより、有効な整数かどうかを決定する二次制約が与えられます。$b$存在します。 
3. 並べ替えると、次のような状態が発生します。$b$以下を満たす必要があります:$$a^2 + b^2 = (a^2 - b)^2$$生産量の拡大と簡素化:$$0 = a^4 - 2a^2b - a^2 + 2b$$解決できるのは$b$:$$b = \frac{a^4 - a^2}{2(a^2 - 1)}$$のみ受け付けます$a$この式が整数である場合の値。 
4. そのような候補者については、次のように計算します。$b$、次に計算します$c = a^2 - b$。 注文内容を確認する$a \le b \le c$そして限界$c \le n$。 
5. 有効なトリプルをすべて数えます。 この式では有効な整数解しか得られないため、$a$、ループは非常に小さいです。 

### なぜ効果があるのか

 方程式系では、ほぼすべての自由度が削除されます。 2 つの独立変数の代わりに$a$そして$b$、2 番目の方程式は、それらの間に直接の関数依存関係を強制します。 その結果、検索空間は 2 次元グリッドから単一の代数曲線に沿ったまばらな候補点の集合に崩壊します。 反復処理$a$すべての有効なトリプルは一意のトリプルに対応する必要があるため、これで十分です。$a$、そしてすべての候補者$a$有効なトリプルが 1 つだけ生成されるか、まったく生成されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        ans = 0

        # a is small; derived constraint ensures only few candidates exist
        a = 1
        while a * a - 1 <= n:
            a2 = a * a

            denom = 2 * (a2 - 1)
            numer = a2 * (a2 - 1)

            # b = (a^4 - a^2) / (2(a^2 - 1))
            if denom != 0 and numer % denom == 0:
                b = numer // denom
                c = a2 - b

                if 1 <= b <= c <= n:
                    ans += 1

            a += 1

        print(ans)

if __name__ == "__main__":
    solve()
```実装は、派生した閉じた形式に従います。$b$。 ループオーバー$a$条件によって暗黙的に制限されます$a^2 - 1 \le n$、大きいので$a$強制するだろう$c = a^2 - b$関係なく限界を超える$b \ge 1$。 

整数の除算チェックには注意が必要です。 分子と分母は、浮動小数点エラーを避けるために慎重に構築されます。 注文チェック$b \le c$代数的導出によって自動的に保証されるわけではないため、これは不可欠です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())

        ans = 0
        a = 1
        while a * a - 1 <= n:
            a2 = a * a
            denom = 2 * (a2 - 1)
            numer = a2 * (a2 - 1)
            if denom and numer % denom == 0:
                b = numer // denom
                c = a2 - b
                if 1 <= b <= c <= n:
                    ans += 1
            a += 1

        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 のために$n < 5$、ループオーバー$a$まだ実行されますが、有効なトリプルが見つかりません。$c = 5$可能な最小の有効な斜辺です。 アルゴリズムは常に次のことを強制することでこれを処理します。$c \le n$したがって、無効なカウントは生成されません。 

のために$n$5 を少し超えると、反復は次の値に達します$a = 3$、計算します$b = 4$、生成します$c = 5$。 小切手$b \le c \le n$たとえ次のような場合でも正確性を保証します$n$かろうじて解決を可能にします。 

非常に大きい場合$n$、ループオーバー$a$ゆっくりと成長しますが、二次条件によって制限されたままになります。 後は新たな解決策が現れないので、$a = 3$の場合、アルゴリズムはすぐに終了し、正しく 1 を返します。
