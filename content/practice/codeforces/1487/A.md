 ## 解決策
 ## 問題の理解

 私たちには、初期の強さまたはレベルを持つヒーローのコレクションが与えられます。 彼らはペアで戦い、レベルの異なる 2 人のヒーローが出会うたびに、強い方が勝ち、さらに強くなります。 レベルが同じ場合、戦いは引き分けとなり、誰も何も得られません。 戦闘の順序を任意に選択できる場合、何人のヒーローが究極のチャンピオンになるチャンスがあるかを調べるように求められます。 言い換えれば、ヒーローが天文学的に多数の決闘で勝利する一連の戦いが存在する場合、そのヒーローは勝者の可能性があります。 

入力により、ヒーローの数とその初期レベルが提供されます。 出力は、一連の戦いの下で勝つ可能性のあるヒーローの数です。 と$n$まで$100$レベルの上限は$100$、各ヒーローを個別に検討し、相対的なレベルについて推論する余裕があります。 シーケンスの数が爆発的に増加するため、考えられるすべてのシーケンスの総当りシミュレーションは非現実的です。 

微妙なエッジケースは、すべてのヒーローが同じレベルを持つ場合です。 そのシナリオでは、すべての戦いは引き分けであるため、どのヒーローも勝利を重ねることはできません。 たとえば、レベルの場合`[5, 5]`、答えは`0`。 もう 1 つの特殊なケースは、他のヒーローよりも厳密に強いヒーローが 1 人だけである場合に発生します。 そのヒーローだけが勝つことができます。 のために`[3, 2, 2]`、最強のヒーローだけが勝者の可能性があります。 単純なアプローチでは、小規模な戦いに勝つ可能性があるため、レベルが 2 番目に高いヒーローを勝者として誤ってカウントする可能性がありますが、実際には、最終的な勝者に最適化されたシーケンスで最も強いヒーローを超えることはできません。 

## アプローチ

 ブルートフォースアプローチでは、戦闘のすべてのシーケンスをシミュレートしようとします。 ヒーローごとに、考えられるあらゆるペアの決闘を試し、勝利を追跡することができます。 これは原理的には正しいですが、必要な戦闘数は天文学的に膨大になります (`100^500`) なので、実際のシミュレーションは不可能です。 たとえ`n = 100`、実行不可能になります。 

重要な観察は、ヒーローのレベルが、最終的に自分を超える可能性のある潜在的なライバルの最小レベルよりも厳密に小さくない場合にのみ、勝者の可能性があるということです。 具体的には、最小レベルのヒーローは、より強力なヒーローの勝利を妨げることはできず、最大レベルより 1 つ低いレベルのヒーローは、最大レベルのヒーローの最終的な勝利を妨げることはできません。 したがって、最低限のレベルのヒーローのみを考慮する必要があります。 ヒーローのレベルが配列内の最小レベル以上の場合、ヒーローは勝者の可能性があります。 

この洞察により、問題は最小レベルを見つけて、それよりも高いレベルを持つヒーローを数えるというものに縮小されます。`min_level`。 すべてのヒーローが最低レベルで同点の場合、誰も勝つことができません。これは、上で説明したエッジケースと一致します。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 テスト ケースごとに、次の手順を実行します。 
2.読む`n`、ヒーローの数、およびそのレベルの配列`a`。 
3. すべてのヒーローの最低レベルを決定します。 このレベルは、勝利シーケンスに参加できる「最も弱い」ヒーローを表します。 
4. レベルがこの最小値よりも厳密に大きいヒーローをすべて数えます。 これらのヒーローは、常に最下位レベルのヒーローを最後まで支配できるため、候補となります。 
5. 現在のテスト ケースのカウントを出力します。 

それが機能する理由: 厳密に強力なヒーローが存在する場合、ヒーローは勝者になる可能性はありません。最終的には、そのヒーローが常に勝利で彼らを上回るからです。 逆に、レベルが最低値を超えているヒーローは、一連の戦いで、より弱いヒーローを排除または先んじて、必要な勝利を蓄積することができます。 これにより、問題は最小レベルとの単純な比較に集約されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    min_level = min(a)
    count = sum(1 for x in a if x > min_level)
    print(count)
```このソリューションは、まずテスト ケースの数を読み取ります。 テスト ケースごとに、ヒーロー レベルを読み取り、最小値を計算します。 次に、最小値よりも厳密に強いヒーローをカウントします。 ジェネレーター式を使用すると、不要な中間リストを回避できます。 これにより、テスト ケースごとに O(n) の処理が保証され、制約を考慮すると効率的になります。 

## 実用的な例

 ### 例 1

 入力:`[3, 2, 2]`| ヒーロー | レベル | レベル > min_level? |
 | --- | --- | --- |
 | 1 | 3 | はい |
 | 2 | 2 | いいえ |
 | 3 | 2 | いいえ |

 最低レベルは`2`。 レベルのある主人公のみ`3`がこの最小値を超えているため、勝者の可能性は 1 人です。 

### 例 2

 入力:`[5, 5]`| ヒーロー | レベル | レベル > min_level? |
 | --- | --- | --- |
 | 1 | 5 | いいえ |
 | 2 | 5 | いいえ |

 すべてのヒーローは同じレベルを持っています。 最小値は`5`厳密に言うとこれより強いヒーローはいないので、カウントは次のようになります。`0`。 

### 例 3

 入力:`[1, 3, 3, 7]`| ヒーロー | レベル | レベル > min_level? |
 | --- | --- | --- |
 | 1 | 1 | いいえ |
 | 2 | 3 | はい |
 | 3 | 3 | はい |
 | 4 | 7 | はい |

 最小値は`1`。 厳密には 3 人の英雄の方が強いので、答えは次のとおりです。`3`。 

これらのトレースは、アルゴリズムが最も弱いヒーローよりも厳密に強いヒーローを正しくカウントしていることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t * n) | 各テスト ケースは、n 個の要素を 2 回スキャンします (min と count)。 最大 t = 500、n = 100 → 50,000 操作。 |
 | スペース | O(n) | 各テスト ケースのレベルを配列に保存します。 |

 このソリューションは、1 秒の時間制限と 256 MB のメモリ制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        min_level = min(a)
        count = sum(1 for x in a if x > min_level)
        print(count)
    return output.getvalue().strip()

# provided samples
assert run("3\n3\n3 2 2\n2\n5 5\n4\n1 3 3 7\n") == "1\n0\n3", "sample 1"

# custom cases
assert run("1\n2\n1 100\n") == "1", "one very strong, one weak"
assert run("1\n5\n10 10 10 10 10\n") == "0", "all equal levels"
assert run("1\n4\n1 2 3 4\n") == "3", "all different levels"
assert run("1\n3\n2 2 3\n") == "1", "single winner above duplicates"
assert run("1\n2\n100 1\n") == "1", "max and min boundary values"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2\n1 100`|`1`| 一人の強い英雄が弱い英雄を支配する |
 |`5\n10 10 10 10 10`|`0`| すべて平等、勝者なし |
 |`4\n1 2 3 4`|`3`| 最低よりも強い複数のヒーロー |
 |`3\n2 2 3`|`1`| 重複の中で最も強いものだけが勝ちます |
 |`2\n100 1`|`1`| 境界値の処理 |

 ## 特殊なケース

 すべてのヒーローのレベルが同じ場合、最小値はすべてのレベルに等しく、厳密にはどのヒーローも強いことはありません。 アルゴリズムは正しく返します`0`。 1 人の非常に強いヒーローと数人の弱いヒーローがいるヒーローの場合、アルゴリズムは強いヒーローのみを勝者としてカウントします。 小さな配列の場合 (`n = 2`)、アルゴリズムは等しい値と等しくない値の両方を正しく処理します。 この実装は、最大許容レベルでも機能します (`100`) およびヒーローの最大数 (`100`) オーバーフローや非効率がありません。
