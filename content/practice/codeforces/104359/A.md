 ## 問題の理解

 私たちには秘密の言葉が与えられています`S`長さの`n`、すべての文字が区別され、カラー パターンが表示されます。`P`別の未知の推測単語がどのように説明されるか`T`に対して評価されました`S`Wordle ルールを使用します。 

評価はポジションごとに行われます。 もし`T[i]`等しい`S[i]`、結果は緑色になります。 もし`T[i]`位置が一致しません`i`でもその手紙はどこかに存在する`S`、黄色になります。 それ以外の場合は白です。 

私たちの任務は逆になります。 私たちは与えられています`S`そして結果として得られるパターン`P`そして、考えられる推測された単語を再構築する必要があります`T`長さの`n`すべての文字が`T`は区別されており、Wordle の評価は`S`正確に生成します`P`。 そのような言葉が存在しない場合は、不可能であると報告する必要があります。 

重要な構造的制約は次のとおりです。`n`は非常に小さく、最大でも 10 です。これにより、位置に関する指数関数構造は許容されるが、完全なアルファベットの順列に依存するものは許容されないことがすぐにわかります。 ソリューションでは、文字のサブセットにわたる割り当てを自由に探索したり、爆発の危険を冒さずにバックトラッキングを使用したりできます。 

微妙な制約は、推測された単語の「すべての文字が異なる」ルールから生じます。 これは、位置ごとに個別に色を一致させるだけではないことを意味します。 各文字はグローバルに 1 回しか使用できないため、1 つの位置での選択は他のすべての文字を制限します。 

よくある落とし穴は、各ポジションを独立して扱うことです。 たとえば、次の場合`S = ABC`パターンはすべて黄色なので、割り当ててみるとよいでしょう`BCA`ただし、緑と黄色のより複雑な混合の場合、ローカルでの貪欲な決定により、グローバルな一貫性が簡単に妨げられる可能性があります。 

別の失敗例は、白い位置がある場合に発生します。 白い位置には存在しない文字を使用する必要があります。`S`。 残った手紙を誤って再利用した場合`S`場合、評価では白ではなく誤って黄色が生成されます。 たとえば、次の場合`S = ABC`位置は白です。`A`there is invalid because it would become yellow.

 ## アプローチ

 強引なアイデアは、考えられるすべての推測単語を生成することです`T`からなる`n`アルファベットの文字を区別し、それぞれの文字が必要なカラー パターンを生成するかどうかを確認します。 それぞれのポジションについて、メンバーシップと平等性を計算します。`S`。 候補単語の数は、およそ 26 文字を並べたものです`n`一度に、次のオーダーです$26 \cdot 25 \cdot \dots$、すでに巨大な`n = 10`。 これにより、総当たり攻撃が不可能になります。 

問題の構造は、位置のタイプごとに制約を分割することを示唆しています。 緑の位置が完全に固定されている場合:`P[i] = G`、 それから`T[i]`等しい必要があります`S[i]`。 黄色の位置はより興味深いものです: から文字を取得する必要があります。`S`しかし、自分たちの立場の手紙ではありません。 白の位置は文字を外側に取らなければなりません`S`。 

緑の割り当てが修正されると、残りのタスクは、未使用の文字のサブセットを割り当てることになります。`S`位置と文字の等価性を回避して、位置を黄色にします。 これは、禁止された対角線を使用した制約付きマッチング問題であり、サイズが最大 10 であるため、代入をバックトラックするだけで十分です。 

すべての緑と黄色を配置した後、白の位置を、存在しない文字から任意に埋めることができます。`S`というのは、これらの文字は区別される以上にいかなる制約とも相互作用しないからです。

 ## アルゴリズムのチュートリアル

 強制的な配置とグローバルな一意性を尊重しながら、段階的に答えを構築します。 

1. パターンに基づいてインデックスを 3 つのグループ (緑の位置、黄色の位置、白の位置) に分類します。 緑色の位置では、文字とその配置の両方がすぐに修正されます。 
2. 緑の位置ごとに`i`、 セット`T[i] = S[i]`そしてその文字を使用済みとしてマークします。 これにより柔軟性は低下しますが、不確実性は排除されます。 
3. 残りの手紙のプールを構築します。`S`緑の位置によって固定されなかったもの。 これらは、黄色の位置で使用できる唯一の文字です。 
4. 各黄色の位置について`i`、私たちはそれを知っています`T[i]`の残りの文字から選択する必要があります`S`、しかしそれはできません`S[i]`。 これにより、ポジションごとに有効な候補者のセットが作成されます。 
5. 黄色の位置に対して深さ優先検索を実行し、未使用の文字を一度に 1 つずつ割り当てます。 各ステップで、まだ使用されておらず、位置制限に違反していない候補文字を選択します。 検索は、すべての黄色の位置が割り当てられるか、矛盾が見つかるまで続けられます。 
6. すべての黄色の位置を正常に割り当てられたら、白色の位置に進みます。 それぞれの白い位置について、ここにない文字を選択します。`S`そしてまだ使用されていません。 アルファベットのサイズは26なので、`n ≤ 10`、以前の制約によって構成がすでに不可能になっていない限り、常に十分な文字があります。 
7. いずれかのステージが失敗した場合は、有効な単語が存在しないことを報告します。 

### なぜ効果があるのか

 この構築では、グリーン割り当てを通じてすべての決定論的制約を直ちに強制し、その後、残りの問題を、単射性制約と禁止された固定点の下で固定セットから文字のサブセットを割り当てるという問題に減らします。 バックトラッキングでは、黄色の位置と残りの秘密文字の間で考えられるすべての一貫した全単射が調査されるため、有効な割り当てが存在する場合は、それが見つかります。 白色の位置は、文字の使用を「Sから」と「Sの外」に分けると独立するため、黄色の段階以降の実現可能性に影響を与えることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    p = input().strip()

    used = [False] * 26
    ans = [''] * n

    idx_s = {c: i for i, c in enumerate(s)}

    greens = []
    yellows = []
    whites = []

    for i in range(n):
        if p[i] == 'G':
            ans[i] = s[i]
            used[ord(s[i]) - 65] = True
        elif p[i] == 'Y':
            yellows.append(i)
        else:
            whites.append(i)

    # remaining letters from S for Y positions
    rem_letters = []
    for c in s:
        if not used[ord(c) - 65]:
            rem_letters.append(c)

    m = len(yellows)
    used_y = set()

    sys.setrecursionlimit(10000)

    def dfs(pos):
        if pos == m:
            return True

        i = yellows[pos]
        for c in rem_letters:
            if c in used_y:
                continue
            if c == s[i]:
                continue
            used_y.add(c)
            ans[i] = c
            if dfs(pos + 1):
                return True
            used_y.remove(c)
        return False

    if not dfs(0):
        print("No")
        return

    # fill whites with letters not in S
    available = []
    in_s = set(s)
    for i in range(26):
        c = chr(65 + i)
        if c not in in_s:
            available.append(c)

    ptr = 0
    for i in whites:
        ans[i] = available[ptr]
        ptr += 1

    print("Yes")
    print("".join(ans))

if __name__ == "__main__":
    solve()

黄色の割り当てが成功した後、残りの位置は白となり、十分な量が存在することが保証されている秘密の単語の外側の文字から貪欲に埋められます。 

微妙な点は、黄色の割り当てではローカルな有効性だけでなく、グローバルな一意性を強制する必要があるということです。 このため、共有`used_y`セットが必要です。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのポジションが緑の場合です。 その状況では、すべての位置が固定されているため、アルゴリズムは決してバックトラッキングに入らず、秘密の単語を直接出力します。 たとえば、`S = ABC`そして`P = GGG`の場合、割り当てステップはすべての位置を直ちに設定して終了します。 

もう 1 つのケースは、すべてのポジションが黄色の場合です。 ここで、アルゴリズムは、固定点のない秘密文字の完全な置換を保証する必要があります。 DFS は当然、次のような割り当てを拒否することでこれを強制します。`T[i] = S[i]`これにより、制限されたセットに対する混乱のような動作が保証されます。 

白を多く含む入力も重要です。 ほとんどの位置が白の場合でも、非秘密文字のプールが十分に大きいため、アルゴリズムは成功します。 アルファベットは26文字なので、`n ≤ 10`、以前の制約によってすでに誤って消費されていない限り、常に十分な供給が存在します。この構造では、S 文字と非 S 文字をきれいに分離することで回避します。
