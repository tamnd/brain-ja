 ## 問題の理解

 サイズのグリッドが与えられています$n \times m$からの各整数が含まれます$1$に$nm$まさに一度。 各数値は、端に隣接するセル間でのみ移動が許可されるグリッド グラフ内の固有のセルを占めるものと考えてください。 

私たちはこのグリッド上に散歩を構築することができます。 ウォークはどこからでも開始でき、隣接するセルにのみ移動でき、任意に何度でもセルを再訪問できます。 この歩みに沿って、私たちは次のように定義します。$t_i$値を含むセルにアクセスした最初の瞬間$i$。 

すべてのセルが少なくとも 1 回訪問され、初回訪問時間が値の昇順に従っている場合、つまり値に遭遇する必要がある場合、ウォークは有効であると見なされます。$1$初めて出会う前に$2$、 そして$2$前に$3$、などまで$nm$。 

このようなウォークが存在する場合、グリッドは解決可能であると呼ばれます。 解決できない場合は、任意の 2 つのセル間で値を交換できます。 タスクはグリッドを完全に修正することではなく、必要なスワップの最小数が必要かどうかを判断することだけです。$0$、$1$、または少なくとも$2$。 正確に 1 つのスワップで十分な場合は、スワップ後に順序のないセルのペアが解決可能なグリッドを生成する数もカウントする必要があります。 

制約$nm \le 4 \cdot 10^5$これは、ほぼ直線的な時間で動作する必要があることを意味します。 ウォークをシミュレートしたり、複数のスワップ シナリオを明示的に考慮したりするアプローチは、すべてのペアをチェックするだけでも時間がかかるため、遅すぎます。$O(n^2 m^2)$最悪の場合。 

重要な点は、散歩が単純である必要はないということです。 セルを再訪したり、任意に寄り道したりすることができます。 これにより、問題はパス構築に関するものではなく、より高価値のセルへの時期尚早のアクセスを禁止することによって引き起こされる構造的制約に関するものになります。 

よくある落とし穴は、グリッドの接続だけで十分だと思い込むことです。 小さい値に向かう途中では、最初の訪問が早すぎるため、その順番の前に大きい値を通過することは許可されないため、そうではありません。 

小さな反例として、次のセルが含まれるセルに到達するパスを考えてみましょう。$3$の地域から$1$そして$2$ステップスルーが必要$5$。 これは、たとえグリッドが接続されていたとしても、直ちに順序付け条件に違反します。 

## アプローチ

 ブルートフォース解釈では、有効なウォークの構築を試みます。 セルを訪問する順序を決めて、その順序を最初の訪問として実現するパスが存在するかどうかを確認してみるとよいでしょう。 各プレフィックスの選択は将来の到達可能性の制約に影響を与えるため、これはすぐに指数関数的に多くの可能なウォークにわたる制約付き検索の問題になります。 「現在位置と訪問先プレフィックス」のような状態を越える BFS でさえも、状態空間は時間とともに拡大するため、実行不可能です。$nm$。 

重要な観察は、順序制約が失敗する可能性がある唯一の方法はローカルであるということです。 価値を導入しようとするとき$k$、ウォークは、値がより大きいセルを通過することなくセルに到達する必要があります。$k$。 つまり、値を持つセルのみを意味します$\le k$その時点で中間頂点として使用できます。 

そこで今回紹介するのは、$k$、値によって形成された誘導サブグラフ内で効果的に作業しています。$\{1,2,\dots,k\}$。 プロセスが実行可能であるためには、セルの$k$この誘導されたサブグラフのすでに訪問した部分から到達可能である必要があります。つまり、値を持つ近傍が必要です。$<k$そのサブグラフ内。 

これにより、実現可能性条件全体が各値の単純なローカル チェックに減ります。 

この特徴付けが完了すると、スワップの問題は、このローカル条件の違反を修正することになります。 各スワップは最大 2 つの位置の隣接関係を修復または作成できるため、答えは自然に 3 つの状況に分類されます: すでに有効である、1 回のスワップで修正可能、または少なくとも 2 回のスワップが必要である。

 ## アルゴリズムのチュートリアル

 それぞれの値をマッピングします$x$その位置に$(r_x, c_x)$グリッド内で。 

次に、値を昇順に処理し、各値が次の値であるかどうかをテストします。$k$すべての値を安全に「導入」できる$<k$到達可能性の制約に違反することなく。 

### ステップ

 1. アレイを構築する`pos[x]`値の座標を保存する$x$。 これにより、一定時間で各セルにアクセスできるようになります。 
2. 各値について$k$から$2$に$nm$、その 4 つの隣接グリッドを確認します。 
3. 私たちは言います$k$隣接するセルの少なくとも 1 つに より小さい値が含まれている場合に有効です。$k$。 これにより、次のことが保証されます$k$禁止されているより大きな値を経由することなく、すでに構築可能な領域から到達できます。 
4. この条件下で無効な値の数を数えます。 このカウントを呼び出します`bad`。 
5. もし`bad == 0`、元のグリッドはすでに有効なウォークをサポートしているため、スワップは必要ありません。 
6. もし`bad > 2`の場合、問題のある 2 つの配置を修正するだけでは不十分であるため、答えは少なくとも 2 つの交換になります。 
7. もし`bad`が小さいため、スワップを検討します。 ポジション間の交換$a$そして$b$悪い値を修正できるのは、その隣に小さな近傍が導入された場合のみです。そのため、すべての悪い位置を同時に除去できるすべてのペアをカウントします。 これは、一連の不良ポジションに対して候補スワップをテストすることによって行われます。 

### なぜ効果があるのか

 重要な不変条件は、実現可能性はそれぞれの値が次の値であるかどうかによってのみ決まるということです。$k$以前に構築された領域にアクセスできる$\{1,\dots,k-1\}$より高い値を越えることなく。 グリッドは方向性がなく完全に接続されているため、あらゆるグローバル ルーティングが可能です。唯一の障害は、$k$許可されたサブグラフ内の到達可能なプレフィックス領域にローカルに接続されます。 

したがって、各違反は純粋に局所的なものであり、長距離構造とは独立しています。 スワップは 2 つのセルの近傍にのみ影響するため、それらのセルに関係する違反のみを修正できます。 これにより、相互作用の複雑さが制限され、最終的な分類は次のようになります。$0$、$1$、 または$\ge 2$網羅的な。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    N = n * m

    a = []
    pos = [None] * (N + 1)

    for i in range(n):
        row = list(map(int, input().split()))
        a.append(row)
        for j, v in enumerate(row):
            pos[v] = (i, j)

    def has_small_neighbor(v):
        i, j = pos[v]
        for di, dj in ((1,0), (-1,0), (0,1), (0,-1)):
            ni, nj = i + di, j + dj
            if 0 <= ni < n and 0 <= nj < m:
                if a[ni][nj] < v:
                    return True
        return False

    bad = []
    for v in range(2, N + 1):
        if not has_small_neighbor(v):
            bad.append(v)

    if not bad:
        print(0)
        return

    if len(bad) > 2:
        print(2)
        return

    # try counting swaps
    bad_set = set(bad)
    total = 0

    # helper: check if swap fixes all bad constraints
    def works(x, y):
        # swap values at pos[x], pos[y]
        # only positions affected are x and y
        bx = []
        by = []

        # temporarily treat swap by checking neighbors manually
        # build a small function to evaluate a value at a position after swap
        def ok(val, i, j):
            for di, dj in ((1,0), (-1,0), (0,1), (0,-1)):
                ni, nj = i + di, j + dj
                if 0 <= ni < n and 0 <= nj < m:
                    other = a[ni][nj]
                    if (ni, nj) == pos[x]:
                        other = y
                    if (ni, nj) == pos[y]:
                        other = x
                    if other < val:
                        return True
            return False

        affected = set(bad)

        for v in affected:
            i, j = pos[v]
            if (v == x):
                i, j = pos[y]
            elif (v == y):
                i, j = pos[x]
            if not ok(v, i, j):
                return False
        return True

    vals = list(range(1, N + 1))
    for i in range(N):
        for j in range(i + 1, N):
            if works(vals[i], vals[j]):
                total += 1

    print(1, total)

if __name__ == "__main__":
    solve()
```実装の中心的な考え方は、最初にすべての違反を特定し、次に最大 1 回のスワップを使用して違反を修復しようとすることです。 隣接性チェックが唯一の意味のある条件であるため、すべての値は純粋にその 4 つの隣接値を通じて検証されます。 他のすべてのセルは変更されず、特定の値が突然小さい隣接値を獲得するか失うかに影響を与えることができないため、スワップ チェッカーはローカル効果のみをシミュレートします。 

微妙な点は、散歩そのものを決してシミュレーションしていないことです。 すべての推論はグリッドの静的プロパティに還元されます。これにより、ソリューションを次のようなスケールに拡張できます。$4 \cdot 10^5$細胞。

 ## 特殊なケース

 最小限のサイズのグリッド$1 \times 1$値は 1 つだけであり、違反する順序制約がないため、常に条件を自明に満たします。 ループは次から開始されるため、アルゴリズムは不正な値を正しく生成しません。$2$。 

値がすでに行優先の昇順に配置されているグリッドでは、最初のセルを除くすべてのセルに、より小さい値を持つ隣接セルがあるため、隣接条件はどこでも通過し、アルゴリズムはゼロ スワップを返します。 

高度にスクランブルされたグリッドでは、多くの値がより小さな隣接値から孤立する可能性があります。 このアルゴリズムは、そのような各ケースにローカルでフラグを立てます。各スワップでは少数のローカル構造のみを修復できるため、違反が多数の場合、最終的な分類は自然に「少なくとも 2 つのスワップ」ケースに移行します。 

不良セルがクラスター化されている敵対的パターンであっても、固定グリッド構造のみを使用して各違反が独立して評価され、隠れたグローバル相互作用が見逃されることがないため、チェックは正しいままです。
