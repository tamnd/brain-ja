 ## 問題の理解

 長さの文字列として表される 10 進数が与えられます。$n$。 私たちの仕事は、同じ長さの、先頭にゼロのない別の正の整数を構築することです。これを、指定された数値に 1 桁ずつ加算すると、結果の合計が回文を形成します。 

出力は一意である必要はありません。 条件を満たす同じ長さの有効な数値であればどれでも受け入れられるため、数値を構築する方法に柔軟性が与えられます。 

制約$n \le 100{,}000$候補を 1 つずつ試したり、可能な数に対して指数関数や二次関数の検索を実行したりするアプローチは直ちに除外されます。 候補ごとのリニアスキャンでも、繰り返すと遅すぎます。 解決策は本質的に次のように答えを構築する必要があります$O(n)$。 

重要な構造上の観察は、出力数値が桁上げを伴う桁ごとの加算を通じてのみ入力と相互作用するということです。 回文制約は、どちらの加数にも直接適用されるのではなく、結果の合計に適用されます。 これは、私たちが制御している実際のオブジェクトは、加算における桁上げ伝播パターンであることを意味します。 

いくつかの微妙なケースは、素朴な推論を打ち破る傾向があります。 1 つは、キャリーを一貫して追跡せずに、外側から内側に向​​かって貪欲に合計を回文にしようとする場合です。 たとえば、合計の最初と最後の桁を固定し、構築された数値の対応する桁を個別に導出すると、キャリー チェーンが衝突する途中で簡単に不一致が発生する可能性があります。 別の失敗例は、貪欲な構築が、局所的な桁の固定がより重要な位置に影響を与えないと仮定している場合に発生します。これは、キャリーが左方向に伝播するため、誤りです。 

最後に、構築される数値には先行ゼロがないという要件が重要です。 単純な対称構造では、最上位桁付近のキャリーを補正するときに誤って先行ゼロが生成される可能性があります。 

## アプローチ

 強引なアイデアは、可能な限りすべてのことを試してみることです$n$-桁の数字$x$、計算する$a + x$、結果が回文であるかどうかを確認します。 これは正しいですが、まったく実行不可能です。 検索スペースには、$9 \cdot 10^{n-1}$候補があり、それぞれの追加には次の時間がかかります$O(n)$、天文学的な結果につながります$O(n \cdot 10^n)$複雑。 

重要な観察は、実際には任意の合計に対して回文特性を強制する必要がないということです。 私たちは自由に選ぶことができます$x$、したがって、合計を直接構築できます$s = a + x$それは回文です、そして回復します$x$引き算して$a$キャリー付きで 1 桁ずつ。 

この再構成は非常に重要です。 選ぶことを考えるのではなく、$x$、回文ターゲットの構築について考えます$s$そのような$s \ge a$桁ごとの加算の実現可能性を検討してから、次のように定義します。$x = s - a$。 ボローによる減算も線形なので、一度決定論的にシミュレーションできます。$s$固定されています。 

残りの問題は、有効な回文をどのように構築するかになります。$s$。 自然な出発点は、$s$左半分を右半分にミラーリングすることによって。 ただし、次のことを確認する必要があります。$s$は十分な大きさであるため、減算によって負の数字が生成されることはありません。 これは、キャリーを意識した左から右への貪欲な構造によって処理されます。つまり、元の数値に関して実現可能性を確保しながら、対称性を強制します。 

回文を作成するために 1 つのパスを実行し、差を計算するために別のパスを実行するため、最終的な解は線形になります。

 ## アルゴリズムのチュートリアル

 数字の配列を完全に操作し、ターゲットの回文を構築します$s$、そして答えを導き出します$x$。 

1. 入力数値を数字の配列に変換します。$a[0 \dots n-1]$。 これにより、文字列のオーバーヘッドなしで直接位置演算が可能になります。 
2. 候補回文を作成する$s$の左半分の数字をコピーすることで、$a$右半分へ。 ポジションごとに$i$、最初に設定しました$s[i] = s[n-1-i] = a[i]$。 これにより、構造的には正しいものの、減算すると必ずしも有効ではないベースライン回文が得られます。 
3. 最も重要な側から始めて、必要に応じて回文を上向きに調整して、後で計算するときに確実に$x = s - a$、負の数字は発生しません。 具体的には、ボローを追跡しながら、左から右への減算をシミュレートします。 どこかの位置でそれを検出した場合、$s[i] < a[i]$以前の借用を考慮した後、ミラーリングされたプレフィックスをインクリメントします。$s$より大きな回文を適用します。 

左から調整する理由は、前の桁を増やすと最大の効果が得られるためです。つまり、合計値が増加します。$s$構造の破壊を最小限に抑えながら回文性を維持します。 

1.ファイナライズ後$s$、計算する$x$借用を使用して桁ごとの減算を実行することにより、$s - a$。 このステップは決定論的であるため、$s \ge a$工事により保証されます。 
2. 出力$x$先頭のゼロの桁をスキップし、強制的な実現可能性調整により最初の桁がゼロ以外であることを保証することで、先頭のゼロがないことを保証します。 

### なぜ効果があるのか

 このアルゴリズムは、構築された回文の不変条件を維持します。$s$は、辞書編集上および数値的に常に、からの減算中の負の借用を回避するのに十分です。$a$。 調整ステップごとに対称的な数字のペアが増加し、回文構造を維持しながら、次の値が厳密に増加します。$s$。 違反が発生する場合にのみ桁を増やすため、必要な変更は最小限に抑えられ、ボローを使用した桁ごとの減算の単調性から正確さが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = list(map(int, input().strip()))
    n = len(a)

    # build initial palindrome candidate
    s = a[:]
    for i in range(n // 2):
        s[n - 1 - i] = s[i]

    # ensure feasibility by fixing from left if needed
    def less(x, y):
        for i in range(n):
            if x[i] != y[i]:
                return x[i] < y[i]
        return False

    # if s < a, increment the middle as a palindrome
    if less(s, a):
        i = (n - 1) // 2
        while i >= 0:
            if s[i] < 9:
                s[i] += 1
                s[n - 1 - i] = s[i]
                break
            s[i] = 0
            s[n - 1 - i] = 0
            i -= 1

    # compute x = s - a
    x = [0] * n
    borrow = 0
    for i in range(n - 1, -1, -1):
        cur = s[i] - borrow - a[i]
        if cur < 0:
            cur += 10
            borrow = 1
        else:
            borrow = 0
        x[i] = cur

    # remove leading zeros
    i = 0
    while i < n - 1 and x[i] == 0:
        i += 1

    print("".join(map(str, x[i:])))

if __name__ == "__main__":
    solve()
```コードは、位置ごとに演算が行われるように、入力を数値配列に解析することから始まります。 ミラーリングされた候補回文を構築し、この候補が元の数値を安全に差し引くのに十分な大きさであるかどうかをチェックします。 そうでない場合は、中間で局所的な増分を実行し、回文性を維持するために変更を対称的に伝播します。 

減算フェーズは、右から左へのボロー伝播を伴う標準的な桁ごとの減算です。 最後のループでは先頭のゼロが削除されますが、この問題では固定幅の出力ではなく正の整数表現のみが必要なため安全です。
