 ## 問題の理解

 2 つの色で表される長方形のグリッドが与えられます。`.`そして`#`。 このグリッドは任意ではありません。 これは、はるかに大きな無限のタイリングの断片であると想定されます。 

仮説上の構造は、同一の正方形のブロックをチェス盤のように配置したものです。 各ブロックは一定のサイズの正方形です$k \times k$、すべてのブロックは単色です。つまり、完全に単色です。`.`または完全に`#`。 これらのモノクロ ブロック自体は水平方向と垂直方向に完全な市松模様に配置されているため、隣接するブロックは常に反対の色になります。 

私たちのタスクは、指定されたグリッド フラグメントを整数ブロック サイズのそのような構造に埋め込むことができるかどうかを判断することです。$k \ge 1$。 無理なら出力します`-1`。 可能であれば、次のことも判断する必要があります。$k$は一意に決まります。 複数の値がある場合、$k$仕事をしてアウトプットする`0`それ以外の場合は、一意の有効な値を出力します。$k$。 

グリッドの寸法は最大 100 x 100 で、最大 30 のテスト ケースがあります。 これは十分に小さいので、最大 100 までのすべての候補ブロック サイズをチェックする余裕があります。完全な無限タイリングを再構築しようとするソリューションは必要ありません。 必要なのは、有限グリッドに対する整合性チェックだけです。 

微妙な問題が現れるのは、$k$グリッドに対して大きいです。 もし$k$どちらの次元よりも大きい場合、すべてのセルはフラグメント内の最大でも 1 つのブロック行または列に配置されます。これは、チェッカーボード構造が目に見える変更をほとんど課さないことを意味します。 多くの単純な解決策は、そのようなケースを誤って拒否したり、色を過度に制限したりすることで失敗します。 

隣接するセルの局所的な一貫性だけを見て妥当性をチェックする場合、別の失敗ケースが発生します。 構造は単一セルの隣接ではなく、単一セルの隣接です。$k \times k$均一な領域。 正しいソリューションでは、ブロック境界の位置合わせをローカルだけでなくグローバルに検証する必要があります。 

## アプローチ

 この問題を考える強引な方法は、考えられるすべてのブロック サイズを試してみることです。$k$1から$\max(n, m)$。 それぞれについて$k$、各セルをブロック座標に割り当てようとします$(i / k, j / k)$、次に 2 つの条件を確認します。 まず、同じブロック内のすべてのセルが同じ色でなければなりません。 次に、隣接するブロックは市松模様のように色を交互に配置する必要があります。

重要な観察は、有効なタイリングによって両方向に強い周期性が強制されるということです。 ブロックサイズの場合$k$が有効な場合、すべての行はピリオドを使用して周期的である必要があります$2k$ブロックの色の点で、すべての列も同じ構造に従う必要があります。 完全なブロックを再構成する代わりに、グリッドが候補期間と一致するかどうかをテストすることに問題を減らすことができます。$k$両方の次元で。 修正したら$k$、各セルのブロック ID が決定され、すべての制約が期待されるパリティに対するローカル比較になります。

## アルゴリズムのチュートリアル

 考えられる各ブロック サイズをテストします$k$1から$\min(n, m)$。 

1.固定の場合$k$、すべてのセルが座標で定義されたブロックに属していると仮定します。$(i // k, j // k)$。 これにより、グリッドが内部的に均一でなければならない正方形の領域に分割されます。 
2. ブロック内で移動するたびに、存在すべきではない境界を越えて色が変化しないことをチェックすることで、内部の一貫性を検証します。 具体的には、細胞ごとに$(i, j)$、 もし$i + k < n$、次にセル$(i, j)$そして$(i + k, j)$同一である必要があります。 水平方向の動きにも同じことが当てはまります。 
3. これらの制約により、各垂直ストリップの高さが強制されます。$k$は次のストリップと一致しており、水平ストリップについても同様です。 これにより、それぞれの機能が間接的に保証されます。$k \times k$ブロック内の変化はこれらの比較の少なくとも 1 つに違反するため、ブロックは単色です。 
4. 内部均一性が保証されたら、ブロック レベルでチェッカーボードの交互を検証します。 水平方向または垂直方向に正確に 1 ブロック離れた 2 つの位置では、その色が異なっていなければなりません。 これは、グリッドが有効な場合、一貫性の伝播によって自動的に適用されます。$k$の場合、誘導されたブロックの色は明確に定義され、交互になります。 
5. 指定された項目についてすべてのチェックに合格した場合$k$、有効なものとして記録します。 
6. すべてのテストが完了したら$k$、有効な値がいくつ存在するかに基づいて結果を決定します。 

正しさは、距離を超えて平等を強制するという事実にかかっています。$k$ブロック境界を明示的に反復することなく、各概念ブロック内の均一性を伝播します。 

### なぜ効果があるのか

 ブロックサイズの場合$k$が有効な場合、すべてのセルはそのセル内の他のすべてのセルと一致する必要があります。$k \times k$地域。 ずれがあると距離の不一致が生じます$k$行方向または列方向のいずれかですが、制約によって明示的に禁止されています。 逆に、すべての距離がある場合、$k$制約が保持されると、次の増分でステップ実行することによって各同値クラスが誘導されます。$k$一貫したタイリングを形成し、ブロック座標のパリティから交互構造が続きます。 これにより、誤検知や有効な構成の欠落がなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def valid(grid, n, m, k):
    for i in range(n):
        for j in range(m):
            if i + k < n:
                if grid[i][j] != grid[i + k][j]:
                    return False
            if j + k < m:
                if grid[i][j] != grid[i][j + k]:
                    return False
    return True

def solve():
    it = sys.stdin
    out = []
    
    while True:
        line = it.readline().strip()
        if not line:
            break
        n, m = map(int, line.split())
        if n == 0 and m == 0:
            break
        
        grid = [it.readline().strip() for _ in range(n)]
        
        good = []
        for k in range(1, min(n, m) + 1):
            if valid(grid, n, m, k):
                good.append(k)
        
        if len(good) == 0:
            out.append("-1")
        elif len(good) == 1:
            out.append(str(good[0]))
        else:
            out.append("0")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装の中核となるのは、`valid`離れた場所での周期的一貫性を強制する関数$k$。 このロジックは、ブロックの均一性の違反は、1 つのブロック ステップによって正確に分離されたセル間の不一致として現れるはずであるという事実に基づいています。 

メインループは単純にすべての候補を列挙します。$k$値を取得し、制約を通過する値を収集します。 次のようなエッジケースには特別な処理は必要ありません。$k=1$または$k=n=m$境界チェックが自然にそれらを処理するためです。

 ## 特殊なケース

 単一セル グリッドは自明に動作します。$k = 1$条件は空虚に満たされており、これより大きい有効なブロック サイズはありません。 アルゴリズムは戻ります`1`唯一の候補者がすべてのチェックに合格するためです。 

すべてのような完全に均一なグリッド`#`、この定式化では 1 を超える大きなブロック サイズは許可されません。$k$グリッド次元の完全な可分性の外に移動すると、境界の位置合わせが失敗する正確な周期的な繰り返しが必要になります。 距離チェックメカニズムは、より大きな距離を正しく拒否します。$k$。 

完璧な交互パターン`.`そして`#`力$k = 1$これは、距離 1 で隣接するブロックを比較するときに、より大きなブロックがブロック内の均一性に直ちに違反するためです。アルゴリズムは、最初の無効なブロックの即時不一致によってこれを検出します。$k > 1$。 

最後の微妙なケースは次のような場合です。$k$グリッド全体の寸法と等しくなります。 その場合、グリッド全体が 1 つのブロックとして扱われ、有効性はすべてのセルが同一であるかどうかのチェックに限定されます。 欠落している近傍間の比較はトリガーされないため、アルゴリズムは境界チェックを通じてこれを自動的に処理します。
