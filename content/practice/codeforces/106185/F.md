 ## 解決策
 ## 問題の理解

 私たちは皿の列を与えられ、それぞれの皿にはリンゴ（`a`) またはバナナ (`b`）。 初期構成から開始し、一連の操作を使用してそれをターゲット構成に変換したいと考えていますが、操作は任意の単一のスワップではありません。 代わりに、各操作は 2 匹の犬、エイミーまたはベッシーのいずれかによって実行される決定的な「実行」であり、各実行は制約された左から右へのトラバーサル内の複数の位置を変更します。 

各犬は果物を口に含んだ状態で開始し、一番左の皿からスキャンします。 スキャン中、現在保持しているプレートと一致するプレートは無視されます。 反対のフルーツが含まれる最初のプレートを見つけると、交換を実行します。つまり、保持しているものをそのプレートに置き、プレートのフルーツを拾い上げ、スキャンを続けます。 最終的に、次に遭遇した反対タイプのプレートに対して 2 回目のスワップを実行し、その後ホームに戻り、操作が終了します。 いずれかの時点で、そのような必要な反対の果実が存在しない場合、操作は失敗します。 

エイミーはバナナを持ち始め、ベッシーはリンゴを持ち始め、彼らはリンゴとバナナに関して対称的に行動します。 初期文字列をターゲット文字列に変換するために、エイミーとベッシーの呼び出しの順序を選択しながら、このような操作を最大 10000 回適用できるかどうかを決定する必要があります。 

重要な制約は、各操作が実質的にグローバルであり、ローカル スワップではなく、構造化された方法で 2 つのポジションに影響を与える可能性があることです。 これは、独立した位置を扱っているのではなく、スキャン プロセスによって引き起こされるグローバル パリティまたは順序付けの制約を扱っていることを直ちに示唆しています。 

n は最大でも 100 であるため、2^100 ですら限界をはるかに超えており、分岐係数は 10000 ステップまで実質的に 1 ステップあたり 2 であるため、一連の操作に対する単純な指数関数的検索は不可能です。 正しい解決策は、すべてのシーケンスのシミュレーションではなく、変換プロセスの構造的不変条件に依存する必要があります。 

問題の状態 s と t が異なっていても、初期構成がすでにターゲットと等しい場合、微妙なエッジ ケースが発生します。これは、推論中の中間状態が、同一性が到達不能または自明であると誤って仮定する可能性があるためです。 もう 1 つのエッジ ケースは、文字列の 1 つに文字の出現が非常に少なく、犬が走行中に 2 回目に必要な遭遇を実行できず、局所的な不一致が存在するにもかかわらず失敗する場合です。 

主な問題は、各操作が文字列全体にわたってグローバルな「ペアリング」動作を強制するため、実現可能性は、必要な再配置を 2 つの交互のスキャン ルールに基づいて有効なペアの相互作用に分解できるかどうかによって決まります。 

## アプローチ

 ブルート フォース アプローチでは、各操作が完全な文字列状態の遷移として扱われます。 どのような構成からでも、エイミーの操作またはベッシーの操作をシミュレートし、有効であれば次の状態を生成できます。 これにより、問題は、ノードがすべて 2^n 個の可能な文字列であり、エッジが 2 つの演算のいずれかの適用に対応するグラフ到達可能性の問題に変わります。 到達不可能な状態を無視したとしても、各ノードには最大 2 つの発信遷移があります。 

ただし、状態空間は n で指数関数的であるため、BFS であっても天文学的な数の構成を探索することになります。 主な失敗点は、n が最大 100 であるため、可能な状態の数が完全に実行不可能になってしまうことです。 

構造的なブレークスルーは、各操作が恣意的ではなく、不一致のシンボルに対する制御された 2 ポインター ペアリング プロセスのように動作することを観察したことから生まれました。 各操作は、固定された左から右の順序で反対の型の 2 つの出現を効果的に消費します。 これは、プロセスが文字列を自由に並べ替えないことを意味します。 代わりに、異なる文字の位置間に厳格なインターリーブ制約が適用されます。 

問題を再構成すると、各操作は、交互に現れる不一致の特定のパターンを修正するものとみなすことができ、システム全体は、2 つの位置のシーケンス間の一貫性を維持するように動作します。`a`そして`b`交互制約の下で一致する必要があります。 これにより、問題は、制限された数の構造化ペア操作を使用して s と t の間の不一致構造が解決できるかどうかをチェックすることに帰着します。これは、特定の誘導された不均衡イベントのシーケンスが 2 つの交互のスタック状変換の下で実行可能かどうかを検証するのと同等です。 

重要な観察は、完全な変換をシミュレートする必要がないということです。 代わりに、各タイプの不一致がいくつ存在するか、および各操作の強制的な左から右への貪欲な性質と一致する方法で不一致をペアにできるかどうかを追跡します。 これにより、有効なシーケンスを構築するか、不可能であることを証明する、建設的な貪欲チェックが行われます。

 ## アルゴリズムのチュートリアル

 中心的なアイデアは、各文字列の位置を、不一致のインデックス間の構造化されたペアリング プロセスによって満たされる必要がある要件として再解釈することです。 

s と t が異なる位置を定義し、それらを 2 つのカテゴリに分けます。`a`そして、それは`b`、および s が持つ位置`b`そして、それは`a`。 変換プロセスでは、制約された順序で 2 つの不一致をそれぞれ効果的に処理する操作を使用して、一方のマルチセットをもう一方のマルチセットに変換する必要があります。 

アルゴリズムは次のように進みます。 

1. s[i] が t[i] と異なるすべてのインデックス i を収集し、不一致の方向に基づいてそれらを 2 つの順序付きリストに分割します。 1 つのリストには必要なポジションが保存されます`a → b`、その他の店舗`b → a`。 順序は左から右のインデックス順です。 
2. 各操作が構造化された交互の方法で正確に 2 つの位置を反転することを観察します。これは、各操作が互換性のある順序で各リストからちょうど 1 つの不一致を消費することを意味します。 これにより、2 つのリスト間にペアリングの制約が生じます。 
3. 貪欲にマッチングをシミュレートすることを試みます。2 つの不一致リストに対する 2 つのポインターを維持します。 各ステップで、各リストから次に利用可能な不一致をペアにします。 一方のリストがもう一方のリストよりも先に枯渇した場合、または順序付けの制約により必要な順序でペアリングできない場合、変換は不可能です。 
4. 成功した各ペアリングは、シーケンス内の 1 つの操作に対応します。 操作のタイプ (エイミーまたはベッシー) は、現在どの不一致タイプが必要な修正パターンを開始しているかによって異なります。 これは、どのリストがペアリング シーケンスの先頭にあるかから推測できます。 
5. 各ペアに正しい文字を追加して、操作文字列を構築します。 合計操作数が 10000 を超えないようにしてください。 それ以外の場合は失敗を返します。 

この貪欲なペアリングが機能する理由は、各ドッグ操作内のスキャン順序により、利用可能な最も早い不一致が最初に相互作用するよう強制されるためです。 左から右へのスキャンで許可される範囲を超えて相互作用をスキップしたり並べ替えたりする自由はないため、有効なシーケンスは不一致位置の自然な順序を尊重する必要があります。 これにより、問題は、単調性を損なうことなく、2 つの順序付けされたシーケンスを有効な交互のペアにインターリーブできるかどうかを確認することに変わります。 

維持される不変条件は、k 回の操作を処理した後、最初の k 個のペアの不一致が両方のリストのインデックスの厳密に増加する順序で一致するということです。 これにより、今後の操作で以前のインデックスを再検討する必要がなくなり、各操作に組み込まれた左から右へのスキャン制約と矛盾することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, s, t):
    ab = []
    ba = []
    
    for i in range(n):
        if s[i] == t[i]:
            continue
        if s[i] == 'a' and t[i] == 'b':
            ab.append(i)
        else:
            ba.append(i)
    
    # If counts differ, impossible under symmetric pairing constraint
    if len(ab) != len(ba):
        return None
    
    ops = []
    
    i = j = 0
    turn = 0  # 0 means AB consumes next, 1 means BA consumes next
    
    while i < len(ab) and j < len(ba):
        # each operation pairs one ab and one ba mismatch
        if turn == 0:
            # try consume ab first
            if i >= len(ab):
                return None
            ops.append('A')
            i += 1
            j += 1
        else:
            if j >= len(ba):
                return None
            ops.append('B')
            i += 1
            j += 1
        
        turn ^= 1
    
    if i != len(ab) or j != len(ba):
        return None
    
    if len(ops) > 10000:
        return None
    
    return ''.join(ops)

def solve():
    out = []
    while True:
        line = input().strip()
        if not line:
            break
        n = int(line)
        if n == 0:
            break
        s = input().strip()
        t = input().strip()
        
        res = solve_case(n, s, t)
        if res is None:
            out.append("no")
        else:
            out.append("yes")
            out.append(res)
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、まず不一致位置が 2 つの単調リストに抽出されます。 両方の犬のスキャン動作では左から右の順序が維持されるため、この分離は不可欠であり、重要なのはインデックス順序のみです。 

ペアリング ループは、ロックステップで両方の不一致リストを消費しながら、操作タイプの厳密な変更を強制します。 変数`turn`各ペアの修正ステップでどの犬の構造アクションが最初に適用されるかをエンコードします。 すべての反復では、各不一致リストから正確に 1 つの要素が消費されます。これは、各有効な操作が正確に 2 つの不一致位置を修正するという事実を反映しています。 

重要な微妙な点は、エイミーやベッシーの内部スキャンをシミュレートしようとしていないことです。 代わりに、有効なグローバル変換はインデックス順序の不一致の一貫したペアに対応する必要があり、有効な操作シーケンスが存在する場合はそれを再構築するのに十分であるという事実に依存します。

 ## 特殊なケース

 重大なエッジケースは、一方向のみで不一致が存在する場合です。 たとえば、すべての異なる位置が`a`と`b`t の場合、対応するものはありません`b → a`ペアリングする位置。 2 つの不一致リストのサイズが等しくないため、アルゴリズムはそのようなケースを即座に拒否します。これは、一連のドッグ操作によって不均衡な変換を修正できないことが正しく反映されています。 

もう 1 つのエッジ ケースは、不一致が存在するものの、大量にインターリーブされている場合です。 それでも、アルゴリズムは隣接性に依存せず、ソートされたインデックスの順序のみに依存するため、インターリーブは正確さに影響しません。 ペアリングは、ソートされたインデックスに対してロックステップで続行され、左から右への制約が確実に尊重されます。 

最後のエッジ ケースは、必要な操作の数が 10000 の制限を超える場合です。n ≤ 100 であるため、実際にはこのようなことは起こりそうもありませんが、アルゴリズムはシーケンスを出力する前にこの境界を明示的にチェックし、縮退した構造であっても出力制約への準拠を保証します。
