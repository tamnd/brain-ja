 ## 解決策
 ## 問題の理解

 今日から始まるタイムラインが与えられており、今日は月曜日として固定されています。 カレンダーは日ごとに進み、次の日数を数えたいと思います。`m`日は営業日です。 

2 種類の制限により非稼働日が定義されます。 まず、週末は一定の周期パターンに従っており、毎週土曜日と日曜日は常に休日になります。 次に、追加の休日のリストがあり、今日を 1 日目として始まる絶対日インデックスとして指定されます。これらの追加の休日は繰り返される場合があり、週末と重なる場合があります。 その日が週末である場合、または追加休日リストに表示されている場合、その日は非稼働日です。 それ以外の場合は営業日となります。 

タスクは、1 日目から 1 日目までの期間に何営業日が表示されるかを計算することです。`m`、 どこ`m`最大 10^18 までの非常に大きな値になる可能性があります。 追加休日数`n`は小さくてせいぜい 300 ですが、当時の値は 10^18 までと大きいです。 

この制約の主な意味は、何日もかけて反復することができないということです。 10^18 までのスキャンすら不可能です。 どのような解決策も、週末の周期構造と範囲にわたる直接の算術推論に依存する必要があります。 追加の休日リストのサイズが小さいことから、通常の週末パターンを処理した後でそれらを個別に処理できることがわかります。 

単純な間違いは、これを直接のシミュレーション問題として扱い、すべてを反復処理することです。`m`毎日が週末か一連の休日かを確認しながら、日を確認します。 これは次の場合にすぐに失敗します`m`大きいです。 

もう 1 つの微妙な落とし穴は、週末は位置モジュロ 7 のみに依存しますが、マッピングは 1 日が月曜日であるという事実に依存することを忘れていることです。 不注意なモジュロ調整エラーにより、すべての週末が誤ってシフトされます。 

最後に、休日リストに重複があっても何も変わりませんが、重複を除外するのを忘れたり、重複を誤って 2 回数えたりすると、答えは間違ってしまいます。 

## アプローチ

 ブルートフォースアプローチは簡単です。毎日 1 日から 1 日まで`m`を使用して、土曜日か日曜日かを計算します。`(day % 7)`追加のホリデー セットに表示されるかどうかを確認します。 ハッシュ セットに格納されている場合、各チェックは O(1) であるため、合計の複雑さは O(m) になります。 これは正しいですが、実行不可能です。`m`最大 10^18 まで大きくなる可能性があり、これは計算上の限界をはるかに超えています。 

重要な観察は、週末が期間 7 で定期的であるため、長期にわたる週末の寄与を 1 日ごとではなくブロック単位で計算できることです。 繰り返す代わりに、丸何週間が含まれるかを数えます。`m`に 2 を掛けて、残りの日数を明示的に処理します。 

週末の日が考慮されると、残る唯一の複雑な問題は追加の休日リストです。 以来`n ≤ 300`、各休日を個別に処理できます。 休日ごとに`a_i`それは中にあります`[1, m]`、すでに週末であるかどうかを確認します。 そうでない場合は、合計から 1 営業日が削除されます。 

したがって、戦略は次のようになります。合計日数から開始します。`m`、算術によって計算された週末の日を減算し、次に平日に該当する固有の追加休日の数を減算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 間隔内に完全な週が何週間含まれるかを計算します。`[1, m]`分割することで`m`7 まで。丸 1 週間はちょうど 2 つの週末に相当します。 これにより、週末の日数の基本カウントは次のようになります。`weeks * 2`。 
2. 丸一週間後に何日残っているかを確認します。 これらは最初のものです`m % 7`最後の週から数日後。 1 日目は月曜日であるため、これらの残りの日は常に週次サイクルの同じプレフィックスに対応するため、これらのそれぞれの日が土曜日か日曜日かを明示的に確認して、週末のカウントに追加できます。 
3. 週末の合計日数を計算します。`[1, m]`丸一週間の週末と残りの週の週末を追加します。 
4. 営業日数を次のように初期化します。`m - weekend_count`、最初は週末以外の日はすべて稼働していると想定されるためです。 
5. 余分な祝日をすべてセットに挿入しますが、その日数だけをセット内に収めます。`[1, m]`。 これにより、無関係な大きな値の処理が回避されます。 
6. それぞれの固有の追加休日について、それが週末かどうかを確認します。 そうでない場合は、誤って労働日としてカウントされているため、回答から差し引く必要があります。 すでに週末である場合、週末はすでに除外されているため、効果はありません。 
7. 最終調整後の稼働日数を出力します。 

### なぜ効果があるのか

 正確さは、カレンダーを 2 つの独立した構造、つまり週末の固定された周期構造と不規則な除外のまばらなセットに分離することにかかっています。 7 日間の各セグメントは月曜日から始まる同一の構造を持っているため、週末の計算は正確です。 追加の休日の調整ステップは、周期構造によってすでに除外されていない限り、そのような日ごとに独立して稼働日を非稼働日に切り替えるため、機能します。 重複は 2 つの独立した除外システム間でのみ発生し、単純なセット メンバーシップを超えて二重カウントが発生することはないため、週末以外の休日のみを差し引くと、正確な稼働日数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_weekend(day: int) -> bool:
    # Day 1 is Monday:
    # 6 -> Saturday, 0 -> Sunday when (day-1) % 7 mapping
    r = (day - 1) % 7
    return r == 5 or r == 6

def solve():
    out = []
    while True:
        line = input().strip()
        if not line:
            continue
        n, m = map(int, line.split())
        if n == 0 and m == 0:
            break

        arr = list(map(int, input().split()))
        
        # weekends
        full_weeks = m // 7
        rem = m % 7

        weekend = full_weeks * 2
        for i in range(rem):
            if is_weekend(full_weeks * 7 + i + 1):
                weekend += 1

        working = m - weekend

        # extra holidays
        seen = set()
        for a in arr:
            if 1 <= a <= m:
                seen.add(a)

        for d in seen:
            if not is_weekend(d):
                working -= 1

        out.append(str(working))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に完全な週と残りのブロックを分離することにより、カレンダーをモジュール表現に変換します。 の`is_weekend`関数は、1 日目が月曜日である平日の配置をエンコードし、土曜日と日曜日が正しく分類されるようにします。 

週末のカウント ステップでは、残りのセグメントが常に月曜日に単独で始まると想定するのではなく、慎重に処理します。 表現`full_weeks * 7 + i + 1`は、平日の分類の一貫性が保たれるように、残った部分の絶対日インデックスを再構築します。 

セット`seen`入力リストに繰り返し休日が含まれる場合、重複した減算を防ぎます。 各休日は、クエリされた間隔内にある場合にのみ考慮されます。 

週末の日はすでに一括で削除されており、そうでない場合は二重の減算が発生するため、減算ステップは週末以外の休日にのみ適用されます。 

## 実用的な例

 ### 例 1

 入力:```
n=4, m=8
holidays = [1,2,3,4]
```丸一週間を計算します。`8 // 7 = 1`、残り`1`。 

| ステップ | 値 |
 | --- | --- |
 | まる一週間 | 1 |
 | 丸週からの週末 | 2 |
 | 残りの日 | 1 |
 | 週末合計 | 2 |
 | 基本営業日 | 8 - 2 = 6 |
 | 範囲内の休日 | {1,2,3,4} |

 次に、各休日を確認します。 1 日目のみが週末ではなく月曜日であるため、1 を引きます。最終的な答えは 5 です。 

これは、平日の休日が重なると、休日以外の日にのみ影響が及ぶことがわかります。 

### 例 2

 入力:```
n=2, m=10
holidays = [15, 3]
```3日目のみが範囲内です。 

| ステップ | 値 |
 | --- | --- |
 | まる一週間 | 1 |
 | 丸週からの週末 | 2 |
 | 残り日数 | 3日間 |
 | 週末合計 | 剰余を介して計算される |
 | 基本営業日 | m - 週末 |
 | 有効な休日 | {3} |

 3 日目は週末ではないため、1 を減算します。 

これは、範囲外の休日が正しくフィルタリングされていることを示しています。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。`m`この状況では完全な週がないため、すべての週末の計算は剰余ロジックから行われる必要があります。 アルゴリズムはこれを自然に処理します。`m // 7`ゼロになり、ループのみが終了します`rem`が使用されます。 

もう 1 つの特殊なケースは、週末に休日が発生する場合です。 たとえば、6 日目 (土曜日) が休日としてリストされている場合、最初から勤務としてカウントされていないため、その日を勤務日から差し引いてはなりません。 アルゴリズムはチェックすることでこれを処理します。`is_weekend(d)`減算の前に、二重カウントエラーが発生しないことを確認します。 

最後のエッジケースには、休日リストの重複が含まれます。 同じ日が複数回出現する場合、単純な減算では誤って答えが複数回減ってしまう可能性があります。 セットを使用すると、毎日が 1 回だけ処理され、繰り返し入力しても正確さが維持されます。
