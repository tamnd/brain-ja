 ## 解決策
 ## 問題の理解

 一連のポジションが与えられ、各ポジションには開き括弧または閉じ括弧のラベルが付いているスタンプが保持されます。 通常の意味では部分文字列は取りません。 代わりに、これらの位置に沿って歩いてシーケンスを構築します。 

まず、任意の位置を選択し、その文字を印刷します。 その後、次の各ステップは行上の隣接する位置 (左または右) に移動する必要があり、新しい位置に文字を印刷します。 私たちは何度もその位置を再訪することを許されていますが、その場にとどまることは許されないので、一歩ごとに隣の位置に移動しなければなりません。 

このウォークにより、括弧の文字列が生成されます。 開始位置と終了位置の順序付けされたペアが何組あるかを数えるように求められます。これにより、正しい括弧シーケンスを生成するようなウォークが少なくとも 1 回許可されます。これは、接頭辞のバランスがマイナスになることはなく、最終的なバランスがゼロになることを意味します。 

すべてのテスト ケースにわたって n が 2×10^5 までという制約は、テスト ケースごとに 2 次の動作を伴う解法は不可能であることを意味します。 合計入力サイズは大きいものの集約されるため、テスト ケースごとに O(n log n) または O(n) が必要になります。 

微妙な点は、散歩は単純である必要はないということです。 前後に移動できるため、シーケンスは部分文字列や単純なパスに制約されません。 これにより、「部分文字列のバランスをチェックするだけ」のような単純な解釈は正しくなくなります。 

典型的な失敗例は、部分文字列に同じ数の '(' と ')' が含まれているが、順序的にプレフィックスのバランスが取れた有効なシーケンスではない場合に発生します。 

たとえば、s = ")()(" を考慮し、部分文字列の有効性を誤って仮定した場合、i = 2、j = 3 を選択します。部分文字列 "()"" は有効ですが、")()(" のようなより複雑なケースでは、順序が固定されている場合、等しい数の一部の部分文字列は有効なシーケンスを形成できません。ただし、ウォーキングによって並べ替えることができるため、この直感が変わり、解決策の鍵になります。

 ## アプローチ

 直接的な総当たりアプローチでは、開始位置と終了位置のすべてのペアを試し、各ペアについて、それらの間のすべての可能なウォークをシミュレートして、有効な括弧シーケンスが生成できるかどうかを確認します。 たとえ妥当な歩行に限定したとしても、各ステップで左または右を選択でき、任意にノードを再訪問できるため、可能なパスの数は指数関数的に増加します。 これは、n が小さい場合でもすぐに実行不可能になります。 

重要な観察点は、行構造により、迂回路を介して文字を「再配置」できるということです。 エッジ上を前後に移動することで、印刷されたシーケンス内の隣接する要素を効果的に交換できます。 このアイデアを繰り返すと、接続された道を歩いていることを尊重する限り、選択した開始点と終了点の間で、訪問する登場人物のあらゆる順序を実現できることがわかります。 

この柔軟性が理解されると、問題はパスの構築に関するものではなくなり、複数の文字セットが有効な括弧シーケンスを形成できるセグメントを数えるという問題になります。 マルチセットは、「(」の数が「)」の数と等しく、すべての左括弧が最初に来るように配置できる場合に限り、有効なシーケンスを形成できます。 つまり、唯一の本当の制約はカウントの等しいことであり、セグメント内の順序ではありません。 

したがって、タスクは、エンドポイント間の合計残高がゼロになるようにエンドポイントのペアをカウントすることになります。 これは、ウォークがステップを交互に実行し、シーケンスの長さが基礎となるプレフィックス表現のエンドポイントのパリティと一致する必要があるという事実から生じる追加のパリティ制約を伴うプレフィックス合計カウント問題になります。

 ## アルゴリズムのチュートリアル

 各 '(' を +1 に、各 ')' を -1 に変換し、prefix[0] = 0 として配列全体のプレフィックスの合計を計算します。

次に、有効なエンドポイントのペアを 2 つのプレフィックス インデックス i および j として、それらの間の正味合計がゼロになるように再解釈します。 その条件は prefix[j] = prefix[i - 1] となります。 

考えられるすべての j を左から右に反復し、各 j について、同じプレフィックス値を持つ以前の位置 i - 1 の数を数えたいとします。 

ただし、ウォークの構造に起因する追加の制約が 1 つあります。エンドポイント間に印刷される文字の数は、交互の移動に必要なパリティと一致する必要があります。 これは、(j - (i - 1)) が偶数の長さであることを要求することを意味します。これは、i - 1 と j が同じパリティを持つことと同等です。 

プレフィックス合計値によってインデックス付けされた頻度テーブルを維持し、各プレフィックス値内でインデックスのパリティによってカウントを分離します。 

各位置 j について、j と同じパリティを持つ prefix[j] の以前の出現数を加算します。 

最後に、これをすべての j にわたって累積します。 

これが機能する理由は、ウォークの自由度をプレフィックスの合計に圧縮することにあります。 前後に移動できるため、固定された部分文字列に制限されなくなります。 代わりに、純残高のみが重要になります。 パリティ条件は、各ステップの位置が変更されるという事実をエンコードするため、印刷される文字の数はプレフィックス インデックス モデルのエンドポイント パリティと一致します。 このアルゴリズムは正しいです。なぜなら、すべての有効な構造がまさにそのような 1 つのプレフィックス ペアに対応しており、そのようなすべてのペアは適切なウォークによって実現できるからです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    while True:
        line = input().strip()
        if not line:
            continue
        n = int(line)
        if n == 0:
            return
        s = input().strip()

        pref = 0
        cnt = {}
        cnt.setdefault(0, [0, 0])
        cnt[0][0] = 1

        ans = 0

        for i in range(1, n + 1):
            c = s[i - 1]
            if c == '(':
                pref += 1
            else:
                pref -= 1

            p = i & 1
            if pref in cnt:
                ans += cnt[pref][p]

            if pref not in cnt:
                cnt[pref] = [0, 0]
            cnt[pref][p] += 1

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、その場でプレフィックスの合計を構築し、各プレフィックス値を偶数および奇数のインデックスでの出現回数にマッピングする辞書を維持します。 位置 i まで拡張するたびに、プレフィックス値とパリティ要件の両方に一致する有効な以前のエンドポイントをすぐにカウントし、構造を更新します。 

主な微妙な点は、0 ベースのインデックス付けと 1 ベースのインデックス付けを一貫して使用することです。 ここで、ループ内ではインデックス i は 1 から始まり、パリティは i から直接取得されます。これは、i - 1 と j の比較から得られる要件に一致します。 

## 実用的な例

 小さな例 s = "()()" を考えてみましょう。 プレフィックスの合計は 0、1、0、1、0 です。 

パリティを使用して各プレフィックス値の出現を追跡します。

 これは、繰り返されるプレフィックス値が有効なエンドポイント ペアにどのように直接対応するかを示しています。 

ここで、局所的に大きく不均衡な s = ")))(((" を考えます。プレフィックス値は大きく異なり、プレフィックスの合計が以前の値に戻る場合にのみ一致が発生します。これは、グローバルにバランスの取れたセグメントのみが寄与していることを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、プレフィックスの合計がすぐに繰り返されるが、パリティが一致しない場合です。 たとえば、「()()」のようなパターンでは、偶数位置と奇数位置の両方にプレフィックス値 0 が作成されます。 このアルゴリズムはパリティ バケットを分離するため、有効な遷移のみがカウントされます。 

もう 1 つのエッジ ケースは、"))))(((((" など) のような完全にアンバランスな接頭辞です。この場合、接頭辞の値はほとんど一致しないため、答えはゼロになり、辞書には衝突のない個別の値のみが格納されます。

 最後に、n = 2 の場合、パリティ処理の正確性が保証されます。 "()" の場合、接頭辞は i = 2 でゼロに戻り、パリティは i = 0 での以前の出現と一致するため、ペアは正確に 1 回カウントされ、予想される単一の有効な構造と一致します。
