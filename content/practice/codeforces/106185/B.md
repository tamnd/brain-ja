 ## 問題の理解

 文字列が与えられています$s$。 タスクは別の文字列を構築することです$t$2 つの条件が同時に成立するようにします。$t$文字列全体と一致します$s$、そして終わり$t$文字列全体とも一致します$s$。 このような文字列すべての中で、可能な限り短いものを出力する必要があります。 

これを解釈する別の方法は、次のコピーを「接着」したいということです。$s$より長い文字列に$s$プレフィックスとサフィックスの両方として表示されますが、プレフィックスのコピーとサフィックスのコピーの間の重複は許可されます。 目標は、元の文字列以外に必要な余分な素材の量を最小限に抑えることです。 

入力は複数のテスト ケースで構成され、それぞれが最大 50 個の長さの文字列を提供します。この小さな制約は、二次チェックや単純なプレフィックス比較を使用したソリューションでも十分であることをすぐに示唆しています。$O(n^3)$最大 50 ケースであれば、テスト ケースごとの安全性は依然として高いでしょう。$n \le 50$。 

主なエッジケースは、文字列の内部に強い繰り返しがある場合です。 たとえば、次の場合$s = \texttt{aaaa}$、その場合、重なり合うことができ、最も短い有効な文字列は単に文字列を盲目的に 2 倍にすることはありません。 常に完全な文字列を 2 回連結する単純なアプローチでは、次のようになります。$\texttt{aaaaaaa}$、一方、最適な答えは$\texttt{aaaa}$それ自体は最小限に拡張されるか、解釈に応じて部分的に重複する場合もあります。 もう 1 つのエッジ ケースは、プレフィックスとサフィックスの間に重要な重複がない場合です。 例えば、$s = \texttt{abc}$、答えは完全な連結になります。$\texttt{abcabc}$適切なオーバーラップが存在しないためです。 

最も難しいのは、プレフィックスのサフィックスがどのくらいの大きさの文字列全体と同時に一致できるかを検出することです。 

## アプローチ

 ブルートフォースアプローチは、次の 2 つのコピーを連結して候補文字列の構築を試みることです。$s$あらゆる可能な重なり長さで。 重ねたら$k$文字列を取得して候補文字列を形成します。$s$そして追加$s[k:]$。 次に、この構築された文字列が次の条件を満たすかどうかを検証します。$s$そして次で終わります$s$。 それぞれについて$k$、この検証には費用がかかります$O(n)$、そして、あります$O(n)$の選択肢$k$、与える$O(n^2)$テストケースごとに。 これはすでに簡単に終わっていますが、さらに単純化することができます。 

重要な観察は、実際にはすべての重複を個別にテストする必要はないということです。 必要な文字列は、次の最大の接頭辞によって決まります。$s$それも接尾辞です$s$。 接尾辞でもある最も長い適切な接頭辞、たとえば長さを見つけたら$L$、それらを安全に重ねることができます$L$の 2 つのコピーの間にある文字$s$。 これは、まさにプレフィックス関数の計算 (KMP など) で使用される構造であり、文字列の最長の境界を見つけます。 

最長の境界線がわかっている場合は、重複しない接尾辞を追加することで最短の有効な文字列が取得されます。$s$それ自体に対して：$s + s[L:]$。 この問題は一意性を保証しており、これは最長の境界構造の一意性と一致します。

 ## アルゴリズムのチュートリアル

 文字列の接頭辞関数を計算します$s$。 この関数は、位置ごとに、その位置で終わるサフィックスに一致する最長の適切なプレフィックスの長さを示します。 

1. アレイを構築する$\pi$どこ$\pi[i]$の最長プレフィックスの長さを格納します$s$インデックスで終わるサフィックスと一致する$i$。 これにより、文字列のすべての境界情報が取得されます。 
2. から始める$j = 0$。 インデックス 1 からインデックス 1 までの文字列を反復処理します。$n-1$。 キャラクターごとに、$j > 0$そして$s[i] \neq s[j]$、にフォールバックします$j = \pi[j-1]$。 このステップにより、最も長い有効な一致が常に維持されるようになります。 
3. もし$s[i] = s[j]$、増分$j$そして割り当てます$\pi[i] = j$。 これにより、現在一致するプレフィックスとサフィックスの長さが増加します。 
4. 文字列全体を処理した後、値は$\pi[n-1]$の最長の適切なプレフィックスの長さを返します$s$これは接尾辞でもあります$s$。 
5. 完全な文字列を取得して答えを作成します$s$そして追加$s[\pi[n-1]:]$。 これは、一致する最大のプレフィックスとサフィックスをオーバーラップし、最短の有効な内線番号を生成します。 

### なぜ効果があるのか

 prefix 関数は文字列のすべての境界をエンコードし、プレフィックスとサフィックスの間の有効な重複は境界に対応する必要があります。 境界線を最長にすると重なりが最大になり、追加される新しい文字の数が最小限になります。 境界線を短くすると、サフィックスのより多くの文字を複製する必要があるため、厳密に長く構築される文字列が強制されます。 これにより、プレフィックスとサフィックスの両方の制約を満たすすべての候補の中で、構築された文字列が最小限になることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_prefix_function(s):
    n = len(s)
    pi = [0] * n
    j = 0
    for i in range(1, n):
        while j > 0 and s[i] != s[j]:
            j = pi[j - 1]
        if s[i] == s[j]:
            j += 1
            pi[i] = j
    return pi

def solve():
    out = []
    while True:
        line = input().strip()
        if line == "0":
            break
        n = int(line)
        s = input().strip()
        pi = build_prefix_function(s)
        overlap = pi[-1]
        ans = s + s[overlap:]
        out.append(ans)
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、プレフィックス関数の計算を中心にしています。 機能`build_prefix_function`ポインタを維持します`j`現在一致しているプレフィックスの長さを追跡します。 不一致が発生した場合、ゼロから再開するのではなく、以前に計算された境界長を使用してジャンプバックするため、線形時間計算量が維持されます。 

プレフィックス関数が構築されると、最後の値はプレフィックスとサフィックス間の最長の重複を直接示します。 建設`s + s[overlap:]`文字列を拡張する唯一の場所であり、元の文字列の文字を最大限に再利用することが保証されます。 

微妙な点は、候補文字列を明示的にチェックしないことです。 すべての正確性は、考えられるすべての重複をコンパクトにエンコードするプレフィックス関数構造に委任されます。
