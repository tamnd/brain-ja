 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$惑星。 各惑星は 1 つの双方向宇宙ルートによってその親惑星に接続されており、各ルートには期限があります。 このルートは、横断を開始した時点で現在時間がその期限を超えていない場合にのみ使用できます。 どのルートでも移動には常に 1 単位時間がかかります。 

あなたは時間 0 の惑星 1 から開始します。タスクは他のすべての惑星を少なくとも 1 回訪問することですが、ひねりが加えられています。すでに訪問した惑星に即座にテレポートすることができます。 テレポートには時間はかかりませんが、以前に訪れた惑星にしかテレポートできないため、初めて惑星に到達するときも、ルートに沿った通常の移動を経由する必要があります。 

テレポーテーションにより、すでに探索されたツリーの部分を物理的に歩く必要がなくなるため、重要な実際の構造は、惑星を最初に訪問する順序です。 初めて新しい惑星に到達するたびに、時間はちょうど 1 ずつ増えます。 

目標は、新しいノードを発見するためにルートを横断するたびに、そのルートの有効期限がまだ切れていないような、すべての惑星を訪問する順序が存在するかどうかを判断することです。 このような順序が存在する場合、惑星 2 から 2 までの訪問の有効な順序を出力する必要があります。$n$。 

入力は根のある木: 惑星をエンコードします。$i$に接続されています$p_i$、その端には期限があります$e_i$。 以来$p_i < i$、構造はすでに暗黙的に 1 にルートされています。 

制約$n \le 1000$を許可します$O(n^2 \log n)$あるいは$O(n^2)$アプローチ。 ヒープを使用した線形貪欲なソリューションで十分です。 

微妙な失敗例は、期限が迫っている場合でも、親より先にノードにアクセスできないという事実を無視することで発生します。 

たとえば、子には早めの期限が設定されているが、親は遅れているとします。 

入力:```
3
1 0
1 0
```両方のエッジは時間 0 で期限切れになります。有効な訪問順序はすべて、`1, 2, 3`または`1, 3, 2`。 両方の子にはそれぞれ時間 1 と 2 でアクセスする必要がありますが、両方のエッジには時間 0 が必要なため、トラバースは不可能です。 親の制約を無視してノードごとの期限だけをチェックする単純なアプローチでは、この種の構造が誤って受け入れられてしまいます。 

## アプローチ

 期限を無視する場合、問題は簡単です。テレポートを使用すると、訪問したノードにジャンプして戻って別の場所で探索を続けることができるため、ノード 1 から開始して任意の DFS オーダーを実行できます。 

問題は、新しく検出されたノードごとに 1 単位の時間が消費され、ノードの検出に使用されるすべてのエッジがその時点でもまだ有効でなければならないことです。 これは、訪問順序が私たちが制御する真の変数であることを意味します。 

重要な観察点は、各ノードが$i$（のために$i > 1$) は、その一意の親エッジを介してのみ最初に到達されます。$(p_i, i)$。 If ノード$i$の位置に訪問されます$k$(ノード 1 の 1 から開始) の順序でエッジのトラバース$(p_i, i)$時間に起こる$k-1$。 したがって、制約は次のようになります。$$k - 1 \le e_i \quad \Rightarrow \quad k \le e_i + 1$$したがって、すべてのノードには、訪問順序におけるその位置に期限があります。 

また、ノードはその親の前にアクセスできないことにも注意する必要があります。 これにより、ルートツリーの優先順位制約が形成されます。つまり、親は子よりも前に出現する必要があります。 

したがって、問題は、各タスクに期限と前提条件 (その親) がある、単一のタイムライン上で単位時間タスクをスケジュールすることになります。 各タイム ステップで、使用可能なノード (親がすでに訪問されているノード) を 1 つ選択し、それを順序に永続的に固定します。 

強引なアイデアでは、親の制約と一致するすべての順列を試行し、毎回期限をチェックします。 それは最悪の場合は要因となり、すぐに実行不可能になります。$n=20$。 

最適な構造は、古典的な貪欲なスケジューリング原則に基づいています。つまり、現在利用可能なすべてのノードの中から、常に期限が最も短いノードを最初に選択します。 直観的には、期限が厳しいノードを遅らせても、将来のステップの実行可能性が低下するだけであり、早期に実行すれば、期限の厳しいノードの柔軟性が保たれるということです。 

「利用可能な」ノード、つまり親がすでにアクセスされているノードの優先キューを維持します。 最小の期限を持つノードを抽出するたびに、そのノードに訪問順序の次の位置を割り当て、その子をアクティブ化します。

 | --- | --- | --- | --- |
 | ブルートフォース順列 |$O(n!)$|$O(n)$| 遅すぎる |
 | ヒープに貪欲 (期限が早いものを優先) |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを 1 にルートします。各ノード$i > 1$親がいる$p_i$そして締め切り$e_i$、これは位置制約に変換されます。$pos[i] \le e_i + 1$。 

1. 位置 1 ですでに訪問しているノード 1 から開始します。他のすべてのノードがノード 1 に依存しているため、これが最初に利用可能な唯一のノードです。 
2. 期限をキーにして利用可能なノードの最小ヒープを維持する$e_i$。 最初に、ノード 1 のすべての子を挿入します。 
3. デッドラインが最小のノードをヒープから繰り返し抽出します。 このノードは現在到達可能なすべての選択肢の中で最も緊急であるため、これを遅らせることは最も危険です。 
4. これを訪問順序の次の位置に割り当てます。 期限に違反した場合、現在位置から 1 を引いた値が超過することを意味します。$e_i$、将来の再配置ではこれを修正できないため、構築はすぐに失敗します。 
5. このノードを訪問済みとしてマークし、そのすべての子をヒープにプッシュします。これは、このノードへのテレポート経由で到達可能になるためです。 
6. すべてのノードが処理されるまで続行します。 すべてのノードが正常に配置された場合、記録された順序が答えになります。 

### なぜ効果があるのか

 すべてのステップで、使用可能なノードのセットは、前提条件がすでに満たされているすべてのノードを表します。 これらの中で、最小の期限を選択することで、実行不能に近づいたノードがより柔軟な期限に延期されることがなくなります。 有効な順序が存在する場合、優先順位制約に違反することなく、ノードが減少しない期限順序で処理されるように順序を変換する方法が常にあります。これは、後の緩い期限ノードを以前の厳しい期限ノードと交換することは実現可能性を損なうことはなく、違反を修正できるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n = int(input())
    parent = [0] * (n + 1)
    deadline = [0] * (n + 1)
    g = [[] for _ in range(n + 1)]

    for i in range(2, n + 1):
        p, e = map(int, input().split())
        parent[i] = p
        deadline[i] = e
        g[p].append(i)

    visited = [False] * (n + 1)
    visited[1] = True

    heap = []
    order = []

    for v in g[1]:
        heapq.heappush(heap, (deadline[v], v))

    t = 1  # position index (node 1 is at time 0 / position 1)

    while heap:
        e, v = heapq.heappop(heap)

        # v will be visited at position t+1, so time is t
        if t > e:
            print("no")
            return

        order.append(v)
        visited[v] = True

        for to in g[v]:
            heapq.heappush(heap, (deadline[to], to))

        t += 1

    if len(order) != n - 1:
        print("no")
        return

    print("yes")
    print(*order)

if __name__ == "__main__":
    solve()
```この実装は貪欲なプロセスを正確に反映しています。 ヒープには、現在利用可能なすべてのノードが期限順に格納されます。 変数`t`ルートの後にすでに配置されているノードの数を追跡するため、次のノードの現在の訪問時間は次のようになります。`t`。 

よくある落とし穴は、時間と位置の処理が 1 つずつずれていることです。 ここで、ノード 1 は暗黙的に位置 1 を占有するため、次のノードを配置しようとしているとき、そのトラバース時間は正確に`t`、 ない`t+1`。 小切手`if t > e`条件をエンコードします$t \le e$。 

もう 1 つの微妙な点は、テレポートにより既に訪問したノードに常に到達できるため、親のアクティブ化を超えて接続を明示的に強制することは決してないことです。 唯一の構造要件は、子が親の処理後にのみプッシュされることです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ルートの複数の子が同じ期限を持つ場合です。 アルゴリズムはいずれかの順序を選択できますが、実現可能かどうかは、root にアクセスした後にのみ両方が使用可能であることを考慮するかどうかによって決まります。 タイは任意であるため、ヒープはこれを自然に処理します。 

もう 1 つのエッジ ケースは、パスに沿って期限が厳密に減少する長いチェーンです。 これは、各ノードが必要なときに正確に利用可能になり、貪欲なプロセスがチェーンの順序を反映するため、常に実現可能です。 

より微妙なケースは、深いノードのデッドラインが浅い兄弟サブツリーよりも早い場合です。 ヒープは、その親が使用可能になるとすぐに最初に処理されるようにし、無関係なブランチの背後で遅延するのを防ぎます。
