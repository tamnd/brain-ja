 ## 解決策
 ## 問題の理解

 指定された数値が 4 または 7 に等しい任意の数の整数の合計として表現できるかどうかを判断するように求められます。入力は単一の整数です。$a$1 から 99 までの値であり、そのような表現が存在する場合、出力は「YES」、そうでない場合は「NO」のいずれかになります。 概念的には、これは 2 つの硬貨の額面 (4 と 7) のみを使用する特殊な種類の「硬貨の変更」問題と考えることができます。 

重要な制約は、$a$この小さな上限は、パフォーマンスを懸念することなく 4 と 7 のすべての可能な組み合わせを検討できることを意味します。 すべてのペアを試す素朴なアプローチ$(x, y)$どこ$4x + 7y = a$どちらの金種でもコインの最大数は 25 枚未満であり、組み合わせの合計数が少ないため、これは実現可能です。 

エッジケースが現れるのは、$a$4 未満、または 4 から 7 の間ですが、4 または 7 には等しくありません。たとえば、次のような場合です。$a = 3$、4 と 7 の合計が 3 になる組み合わせはないため、正しい出力は「NO」です。 もし$a = 11$、数値は次のように表すことができます。$4 + 7$したがって、出力は「YES」になります。 不注意なアプローチでは、4 または 7 の倍数のみを個別に試行し、次のような組み合わせが欠落する可能性があります。$4 + 7$。 

## アプローチ

 ブルートフォース手法は、合計が超えない 4 と 7 のすべての非負のカウントを反復します。$a$。 4 の可能な数ごとに、残りが次のとおりであるかどうかを確認します。$a - 4x$は 7 で割り切れます。このアプローチは、反復の合計数が次のように制限されるため機能します。$\frac{a}{4} \approx 24$最悪の場合。 技術的には二重ループを使用することもできますが、4 の数が固定されれば、7 で割り切れるかどうかのチェックは定数時間であるため、4 秒にわたる単一ループで十分です。 

最適なアプローチは、考慮する必要がある洞察に依存します。$x$0から$\lfloor a / 4 \rfloor$。 それぞれについて$x$、 もし$(a - 4x) \% 7 == 0$、 それから$a$は 4 と 7 の合計で表すことができます。 これにより、7 の負の数や不可能な数の不要な探索が減り、解決策が存在する場合には必ず解決策が見つかるようになります。 入力範囲が狭いため、これより高速な方法は必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(a^2) | お(1) | 入力が少ないため承認されました |
 | シングルループチェック | O(a/4) = O(1) | お(1) | 受け入れられ、よりシンプル |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$a$入力から。 これが確認したい目標金額です。 
2. 反復する$x$0から$\lfloor a / 4 \rfloor$。 それぞれ$x$は使用された 4 の数を表します。 
3. それぞれについて$x$、剰余を計算します$r = a - 4x$。 これは7sでカバーしなければならない金額です。 
4. 次のことを確認します。$r$を使用すると 7 で割り切れます$r \% 7 == 0$。 trueの場合は「YES」を出力して停止します。 
5. いいえの場合$x$ループ後にこの条件を満たした場合、「NO」を出力します。 

なぜ機能するのか: 4 と 7 のあらゆる組み合わせは次のように表すことができます。$4x + 7y = a$。 可能なすべての 4 カウントを反復することにより、可能なすべての値をテストすることが保証されます。$y$それはマイナスではありません。 可算性チェックにより、次のことが保証されます。$y$は整数であり、元の方程式を満たします。 有効な組み合わせはスキップできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a = int(input())
for x in range(a // 4 + 1):
    if (a - 4 * x) % 7 == 0:
        print("YES")
        break
else:
    print("NO")
```コードは整数を読み取ります$a$そして反復します$x$0から$a // 4$。 表現$(a - 4 * x) \% 7$余りが完全に 7 で形成できるかどうかを直接チェックします。 を使用して`for`でループします`else`句により、有効な値がない場合にのみ「NO」が出力されることが保証されます。$x$が見つかりました。 よくある間違いは、ループ境界内での off-by-one エラーです。 ここ、`a // 4 + 1`正しくは、次の場合が含まれます$x = a // 4$。

## テストケース```python
import sys, io

 ## 特殊なケース

 のために`a = 1`の場合、ループは、7 で割り切れない x = 0、r = 1 で実行されます。出力は「NO」となり、下限が正しく処理されます。 のために`a = 28`, x = 0 の場合、r = 28 は 7 で割り切れるため、アルゴリズムはすぐに「YES」を出力し、7 のみを使用する解が正しく検出されたことを示します。 これらの例は、入力範囲内のすべての組み合わせが効率的にテストされることを確認します。
