 ## 解決策
 ## 問題の理解

 私たちは、各ノードがコストと栄養価という 2 つの属性を持つ果物を表す根付きの木を与えられています。 ツリーは、1 つのノードがルートとして指定され、他のすべてのノードがエッジを介して接続され、そのルートを介して暗黙的に親子関係を形成するように配置されます。 

「購入操作」は、ノードを親接続から切り離すように機能します。 顧客が果物を選択すると、売り手はその果物を親に直接接続するすべてのエッジを切断し、結果としてその果物をルートとする切断されたサブツリー全体が購入の一部となります。 そのカットによって下の追加コンポーネントが分離される場合、それらも自動的に追加されるため、各操作はカットポイントに接続されていた接続コンポーネント全体を効果的に購入します。 

顧客は、以前のカット後にツリーに残っているものに対して常に、このような操作を複数実行できます。 各操作は現在のフォレストからサブツリー状のコンポーネント全体を削除します。その操作のコストはそのコンポーネント内のすべての果物のコストの合計であり、利益は栄養価の合計です。 

この質問は、予算が与えられた場合に、そのようなカットのシーケンスを選択することによって達成できる最大の総栄養価はいくらか、選択された各成分は全額支払わなければならず、成分は一度除去されるともう入手できないためバラバラである、というものです。 

これにより、問題は、互いに素な接続されたサブツリー (ルート ツリーの意味で) のコレクションを選択することに変換され、各サブツリーのコストはノード コストの合計に等しく、値はノードの栄養素の合計に等しく、ナップザックの予算内で価値を最大化します。 主な制限は、有効な項目は任意のサブセットではなく、ルート付きツリー内の正確なサブツリーであることです。 

制約は次のことを示しています$n$そして$q$最大 3000 まで上がりますが、すべてのコストと予算も 3000 に制限されます。これはすぐに、擬似多項式のナップザック構造を示唆します。 ただし、ツリー構造ではすべてのノードを独立して扱うことができません。 妥当性は階層に依存するため、ノードを越えた単純なサブセット DP は不可能です。 

素朴な考えを打ち破るエッジケースには、次のようなものがあります。 

直線的なチェーンツリー。 すべてのノードを独立したアイテムとして扱う場合、重複するプレフィックスを 2 倍にカウントします。 たとえば、チェーンで$1 \to 2 \to 3$、ノード 2 でのサブツリーの選択にはすでにノード 3 が含まれているため、ノード 3 を個別に選択することは無効です。 

星の形をした木。 子ノードを切断すると、その子のサブツリーのみが削除されますが、複数の子の選択は許可されるため、独立性は兄弟間でのみ保持され、グローバルでは保持されません。 

小さな例:

 入力:```
3 2 1 1
1 1
2 2
3 3
1 2
1 3
3
```正しい推論: ノード 2 のサブツリー、ノード 3 のサブツリー、または両方を選択できますが、ノードが重複することはありません。 単純な「最適な比率のノードを選択する」アプローチは、構造が重要であるため失敗します。 

主な困難は、ノードの選択がその子のサブツリーの任意の組み合わせをオプションで取得することを意味することを正しくエンコードすることですが、子から何を取得するかを決定すると、そのノードは他の兄弟から独立します。 

## アプローチ

 ブルートフォース手法では、互いに素なサブツリーの有効なセットをすべて列挙します。 これを想像する 1 つの方法は、ノードごとにカット ルートとしてノードを「アクティブ化」するかどうかを決定し、アクティブ化されたノードが別のアクティブ化されたサブツリー内に存在しないようにすることです。 有効な選択ごとに、総コストと栄養を計算し、予算内で最良のものを採用します。 

このような構成の数は指数関数的に増加します。 サブツリーのルートに限定しても、各ノードには 2 つの選択肢があります。サブツリー全体を単位として取るか、選択を子に延期するかのどちらかです。 これは、各ノードで子の組み合わせ間で予算を分割する方法を決定するため、ツリー上に展開すると指数関数的な分岐につながります。 

重要な観察は、各サブツリーが内部構造を持つナップザック アイテムのように動作することです。ノードの場合、ノードのサブツリー全体を 1 つのアイテムとして選択するか、子サブツリー内の選択に分解するかの間でバジェットを分配しています。 これは古典的なツリー DP ナップサックのマージ問題です。 

各ノードで DP を定義し、ツリー構造を考慮してサブツリーのみを使用して達成可能なすべての (コスト、値) ペアを計算します。 各ノードについて、何も取らないオプションから開始し、最大 3000 のバジェットにわたってナップザック畳み込みを使用して子 DP 状態を繰り返しマージします。 

各ノードの DP は、DP 配列を予算を超えるナップサックとして扱い、子を 1 つずつマージすることによって計算されます。 子を含める場合、現在の累積状態とその子のサブツリー DP の間の予算の配分を組み合わせます。 すべての子を処理した後、オプションで現在のノード自体をサブツリー項目全体 (完全なサブツリーのコストと値) として含めるか、分解されたオプションを保持します。 

重要な単純化は、任意のコストと値のペアを追跡する必要がないことです。 予算には制限があるため、DP をコストでインデックス付けされた配列に圧縮します。

 ## アルゴリズムのチュートリアル

 私たちは木を次の場所に根付けます$r$。 DFS を使用してサブツリー DP をボトムアップで計算します。 

1. 各ノードについて$u$、DP配列を初期化します`dp[u]`どこ`dp[u][c]`のサブツリーから得られる最大の栄養です$u$総コストを正確に計算して$c$。 から始めます`dp[u][0] = 0`。 
2. の子に対して DFS を実行します。$u$。 それぞれの子どもたちにとって$v$、最初に計算します`dp[v]`。 
3. マージ`dp[v]`の中へ`dp[u]`ナップサックスタイルの畳み込みを使用します。 一時的な配列を作成し、現在の状態と子状態の間の予算分割ごとに値を結合します。 このステップにより、独立した子サブツリー全体に予算を配分するあらゆる方法が考慮されるようになります。 
4. すべての子をマージした後、サブツリー全体をルートとすることを検討します。$u$単品として。 そのコストはそのサブツリー内のコストの合計であり、その値はそのサブツリー内の栄養の合計です。 更新します`dp[u][cost[u]]`したがって、完全なサブツリー選択と比較することによって決定されます。 
5. 戻る`dp[u]`親に。 
6. ルートを処理した後、最大値を取得して各クエリに回答します。`dp[r][c]`みんなのために$c \leq \text{budget}$。 

「サブツリー全体を取得」オプションを明示的に許可する理由は、一部の最適なソリューションでは、サブツリーを子の決定に分解せず、単一の購入単位として選択することを好むためです。 

### なぜ効果があるのか

 すべてのノードで$u$、DP は、その子孫内の互いに素なサブツリーを選択するためのすべての実行可能な方法を列挙します。 不変条件というのは、`dp[u]`のノードのみを使用して、達成可能なすべてのコストと値の組み合わせを表します。$u$のサブツリーを素性を損なわずに作成できます。 子は互いに素であるため、マージ プロセスでは子サブツリー間の独立性が維持されます。 オプションの完全なサブツリーの選択では、サブツリーを 1 つの購入として取得するカット操作が考慮されます。 すべての有効なグローバル ソリューションは、各サブツリー境界で行われる選択に一意に分解できるため、有効な構成が失われることはなく、無効な重複が導入されることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        n, m, r, q = map(int, input().split())

        cost = [0] * (n + 1)
        val = [0] * (n + 1)

        for i in range(1, n + 1):
            cost[i], val[i] = map(int, input().split())

        g = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            a, b = map(int, input().split())
            g[a].append(b)
            g[b].append(a)

        queries = list(map(int, input().split()))
        maxW = max(queries)

        parent = [0] * (n + 1)
        order = []

        stack = [r]
        parent[r] = -1

        while stack:
            u = stack.pop()
            order.append(u)
            for v in g[u]:
                if v == parent[u]:
                    continue
                parent[v] = u
                stack.append(v)

        children = [[] for _ in range(n + 1)]
        for u in order:
            for v in g[u]:
                if v != parent[u]:
                    children[u].append(v)

        dp = [[-10**18] * (maxW + 1) for _ in range(n + 1)]

        for u in reversed(order):
            dp[u][0] = 0
            for v in children[u]:
                ndp = [-10**18] * (maxW + 1)
                for i in range(maxW + 1):
                    if dp[u][i] < 0:
                        continue
                    for j in range(maxW + 1 - i):
                        if dp[v][j] < 0:
                            continue
                        ndp[i + j] = max(ndp[i + j], dp[u][i] + dp[v][j])
                dp[u] = ndp

            if cost[u] <= maxW:
                for c in range(maxW, cost[u] - 1, -1):
                    dp[u][c] = max(dp[u][c], dp[u][c - cost[u]] + val[u])

        root_dp = dp[r]
        pref = [0] * (maxW + 1)
        best = 0
        for i in range(maxW + 1):
            best = max(best, root_dp[i])
            pref[i] = best

        print(f"Case {tc}:")
        for a in queries:
            print(pref[a])

if __name__ == "__main__":
    solve()
```このソリューションでは、まずツリーをルート化し、明示的な子のリストを構築します。 これにより、DP 中に親チェックが繰り返されることが回避されます。 DP はノードごとに完全なナップザック配列として保存され、ゼロコストを除いて負の無限大で初期化されます。 

マージ ステップでは、ノードとその子の間でトリプル ループ ナップザック畳み込みを使用し、すべての予算分割が確実に考慮されるようにします。 子をマージした後、ノード自体をアイテムとして取得し、同じ反復で必要な状態の上書きを避けるために DP を逆に更新することができます。 

最後に、各クエリが O(1) で回答できるように、プレフィックス最大配列が構築されます。

 ### 例 1

 根の生えた小さな木を考えてみましょう。```
1 is root
1 - 2
1 - 3
```コストと価値:

 | ノード | コスト | 値 |
 | --- | --- | --- |
 | 1 | 4 | 3 |
 | 2 | 2 | 2 |
 | 3 | 1 | 1 |

 予算 = 3

 最初に葉を処理します。 

ノード 2 の場合: dp では、{0 コスト、0 値} および {2 コスト、2 値} が許可されます。 

ノード 3 の場合: dp は {0,0} と {1,1} を許可します。 

ノード 1 で、子をマージします。 組み合わせが得られます。 

| コスト | 値 |
 | --- | --- |
 | 0 | 0 |
 | 1 | 1 |
 | 2 | 2 |
 | 3 | 3 |

 コストが 4 > 予算であるため、ノード 1 自体を使用することはできません。 

3の答えは3です。 

これは兄弟の独立性を示しています。子供たちはナップザックのアイテムのように結合します。

 ## 特殊なケース

 単一ノード ツリーは、ルートを唯一の使用可能な項目として取得することを DP が正しく許可しているかどうかをテストします。 アルゴリズムが初期化されます`dp[root][0] = 0`次に、予算が許せばノード自体を使用して、正しい出力をすぐに生成することを検討します。 

深いチェーンはマージ順序を強調します。 各ノードはその子に依存するため、DFS の順序を逆にすることで、親がマージする前に子の DP が完全に計算され、累積的なナップザック状態の正確さが維持されます。 

星型の木は、子供たちが自立していることを証明します。 各子 DP は個別にマージされ、畳み込みによって子間でバジェットが分割されるため、重複は発生しません。
