 ## 解決策
 ## 問題の理解

 学期には固定の週数があり、各週には限られた数の授業が含まれます。 すでに数週間が経過しており、完了した週にはすでに一定数のクラスに出席しています。 残りの週はまだ先なので、残りの各週に何回のクラスに出席するかを決定する必要があります。 

目標は、最終的な出席率が学期中の全授業の少なくとも 60% になるようにすることです。 ただし、1週間に実際に開催される授業数を超えて受講することはできないため、残りの週ごとに貢献できる授業数には上限があります。 

課題は、出席率 60% に達することが可能かどうかを判断するだけでなく、可能であれば残りの週の有効な計画を立てることでもあります。 すべての有効な計画のうち、週ごとの制限を尊重しながら残りの週に出席者数を分散する計画を出力する必要があります。 

重要な数量は簡単です。 学期中の総授業数は、週数×週あたりの授業数で決まります。 それらの週の一部はすでに終了しており、過去の出席状況は確定しています。 残りの決定は、週ごとの上限に基づいて、今後の週に追加の出席者をどのように配分するかです。 

制約は非常に小さいです。 週数は最大 14 で、週あたりのクラスは最大 5 です。これは、分布に関する強引な推論が完全に安全であり、線形または貪欲な構造でも十分すぎることを意味します。 問題はパフォーマンスに関するものではなく、実現可能性を正しく処理し、有効な割り当てを構築することにあります。 

主な失敗例は 2 つの原因から生じます。 1 つ目は、整数の除算を使用して必要な出席閾値を誤って計算しており、必要な出席クラス数を過小評価する可能性があります。 たとえば、クラスの合計が 50 の場合、60 パーセントは 30 ですが、次のように計算すると、`50 * 60 / 100`一部の言語では整数の切り捨てが行われるため、必要に応じて上限動作が正しく行われるように注意する必要があります。 

2 番目の問題は、実行可能性の制約を無視して残りの週を貪欲に埋めるだけでも常に機能すると仮定していることです。 たとえば、残りのキャパシティが必要な総出席者数に達するのに不十分な場合、配布を構築する前に不可能であることを正確に検出する必要があります。 

具体的なエッジケースは、必要な出席者数がすでに満たされている場合です。 その場合、不必要な出席を追加する必要はなく、「週当たりの最小数」の意図に違反する可能性があるため、残りの週はすべてゼロで埋められる必要があります。 

もう 1 つのエッジケースは、残りのクラスすべてに出席しても不十分な場合です。 たとえば、合計クラスが 20 で、必須が 12 で、すでに 11 を出席し、空いているクラスが 1 だけ残っている場合、非常に近くても不可能です。 

## アプローチ

 強引なアプローチでは、残りの週に参加者を分散する可能なすべての方法を列挙しようとします。 各週は 0 から Y までの値を取ることができるため、最大 14 週、Y が最大 5 であるため、構成の数は最大で$6^{14}$、これは直接列挙するには大きすぎます。 

ただし、問題の構造により、ブルートフォースは不要になります。 唯一のグローバル要件は、出席クラスの最小合計数に達することです。 毎週の値が Y を超えられないことを除いて、分布を優先することはありません。これにより、問題は単純な実現可能性と構築タスクに変わります。 

重要な点は、唯一意味のある数量は、まだ出席する必要がある追加のクラスの合計数であるということです。 その数を計算したら、残りの週にそれを分配することが境界充填問題になります。要件が満たされるまで、容量 Y まで週を埋めます。 

まず、学期内の合計クラス数と必要なしきい値 (60 パーセント) を計算します。 次に、すでに出席したクラスの数を差し引いて、さらに必要なクラスの数を求めます。 この数値がゼロ以下であれば、すでに要件を満たしています。 総残量を超えると作業が不可能になります。 それ以外の場合は、要件が満たされるまで、可能な限り多くのクラスを貪欲に各週に割り当てます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 最適 | O(W) | O(W) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 学期中の合計授業数を次のように計算します。$X \times Y$。 これは、全員出席の世界を表します。 
2. 必要な出席率を合計の 60% として計算します。 出席率は整数である必要があるため、これが上限とみなされます。$0.6 \times X \times Y$。 これにより、境界線にある不十分な値を決して受け入れることがなくなります。 
3. 残りの必要出席日数を次のように計算します。`need = required - N`。 この値がゼロ以下の場合、それ以上の出席は必要ありません。 
4. 残りの容量を次のように計算します。`(X - Z) * Y`。 これは、まだ蓄積できる最大出席者数です。 
5. もし`need > remaining capacity`、最大の努力でもしきい値に到達できないため、「いいえ」を出力します。 
6. それ以外の場合は、出席を残りの週に分散します。 残りの週ごとに、`min(Y, need)`そしてそれをから引きます`need`。 
7. 割り当て後に数週間が残っている場合は、それ以上は必要ないため、出席をゼロで記入します。 

### なぜ効果があるのか

 正しさは、週を結合する唯一の制約が出席者の全体的な合計であるという事実に依存します。 各週は上限を除いて独立しています。 私たちは常に残りの要件をできるだけ早く満たそうとするため、後で実現可能性を妨げる可能性のある方法で容量を無駄にすることはありません。 ソリューションが存在する場合、貪欲なフィルにより、単純なリニア スキャンで容量を消費してソリューションが構築されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    X, Y, Z, N = map(int, input().split())

    total = X * Y
    required = (total * 60 + 99) // 100

    need = required - N

    remaining_weeks = X - Z
    remaining_capacity = remaining_weeks * Y

    if need <= 0:
        print("Yes")
        print(" ".join("0" for _ in range(remaining_weeks)))
        return

    if need > remaining_capacity:
        print("No")
        return

    ans = []
    for _ in range(remaining_weeks):
        take = min(Y, need)
        ans.append(take)
        need -= take

    print("Yes")
    print(" ".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```このソリューションは、60 パーセントの要件を過少カウントしないように、上限区分を使用してクラスの合計数と必要なしきい値を計算することから始まります。 変数`need`追加で必要な受講クラスの数を把握します。 

次に、残りの週に受講できる可能性のあるクラスの数を計算します。 この実現可能性チェックがなければ、有効な完全なスケジュールが存在しない場合でも部分的なスケジュールを構築してしまう可能性があるため、この実現可能性チェックは非常に重要です。 

貪欲ループは、週ごとの制限や残りの要件を超えることなく、毎週できるだけ多くのクラスを割り当てます。 一度`need`ゼロになると、その後の週は自動的にゼロになります。

 ## 特殊なケース

 要件がすでに満たされている場合、アルゴリズムは残りの週にゼロの割り当てを即座に出力します。 たとえば、合計クラスが 20 で必須クラスが 12 であるが、すでに 15 クラスがある場合、次のようになります。`need`が負になり、出力はゼロ ベクトルとなり、不必要な割り当てを行わずに実現可能性が正しく維持されます。 

残容量が満杯でも足りない場合は、実現可能性チェックにより建設ができなくなります。 たとえば、残りの合計容量が 3 であるが、さらに 5 つのクラスが必要な場合、アルゴリズムは次のことを検出します。`need > remaining_capacity`配布を試みる前に「いいえ」を出力します。
