 ## 解決策
 ## 問題の理解

 無向ツリーが与えられているので、すべてのノードに小文字を割り当てる必要があります。 ラベル付け後、ツリー内のすべての単純なパスは、そのパスに沿ってノード ラベルを読み取って形成された文字列に対応します。 

2 つのグローバル制約を同時に保持する必要があります。 まず、両端が両方の葉であるパスを選択した場合、結果の文字列は回文になる必要があります。 第 2 に、エンドポイントがリーフ ノードと非リーフ ノードであるパスを選択する場合、その文字列は決して回文であってはなりません。 

したがって、ツリーのラベル付けは単一のパスに関するものではなく、葉から葉へのすべてのパスにわたって回文構造を強制すると同時に、葉から内部へのすべてのパスで回文を明示的に分割することを目的としています。 

入力サイズは最大 200,000 ノードに達するため、どのソリューションも頂点数が線形または線形に近い必要があります。 ツリーには 2 次の多くのパスがあるため、すべてのノードのペアまたはすべてのパスを個別に推論しようとすることは、直ちに実行不可能になります。 

微妙な点は、制約が選択されたペアだけではなく、_すべてのリーフ ペア_について話していることです。 これにより、ローカル割り当てトリックではなく、ツリー上にグローバル構造が強制されます。 

素朴な推論を打ち破る傾向のあるエッジケースは、ツリーが分岐するときに現れます。 

中心と多数の葉を持つ星を試してみると、任意の 2 枚の葉が長さ 3 のパスを形成します。 その文字列は回文でなければならず、これにより 2 つの葉が同じ文字を持つことが強制されます。 これをすべてのリーフ ペアに拡張すると、すぐに多くの等式が強制され、リーフ対非リーフの制約を満たすことができなくなります。 

たとえば、サイズ 4 の星について考えてみましょう。```
    2
    |
3 - 1 - 4
```すべての葉のペアは (2,3)、(2,4)、(3,4) です。 これらすべてのパスを回文にすることで強い対称性が強制されますが、ラベルが均一であれば 2 対 1 や 3 対 1 などのパスも回文になり、2 番目の条件に違反します。 

この種の競合は、分岐構造が危険であり、非常に制約されたツリーのみが機能できることを示唆しています。 

## アプローチ

 強引な考え方は、任意に文字を割り当て、葉から葉へのパスと葉から葉以外へのパスをすべて列挙することで両方の条件を検証することです。 ラベル付けが固定されている場合でも、ツリー内には Θ(n²) 個のパスが存在するため、すべてのパスをチェックするとコストがかかります。 各パス チェックにはパス長の線形時間がかかるため、最悪の場合、制限をはるかに超える Θ(n³) にまで爆発します。 

重要な構造観察は、条件によってツリー自体が単一の鎖のように動作するようになるということです。 

次数が少なくとも 3 のノードがある場合は、それぞれに葉が含まれる複数のサブツリーが接続されます。 さまざまな枝から葉を摘み取ると、分岐点を通過する複数の異なる葉から葉へのパスが作成されます。 これらのパスでは、各ブランチが分岐中心を介して他のすべてのブランチを同時にミラーリングする必要があるため、互換性のない対称制約が必要になります。 これは、固定された小さなアルファベットでは一定のラベル付けに崩壊することなく満たすことができず、リーフから非リーフへの制限に違反します。 

この制限により、ツリーが単一の単純なパスに折りたたまれます。 ツリーがパスになると、問題は 1 次元になります。つまり、2 つのエンドポイント間のすべてのサブパスが回文になるように、線に沿って文字を割り当てるだけで済みますが、エンドポイントから内部ノードまでの接頭辞は回文にならないようになります。 

パス上には、端点である葉が 2 つあります。 葉から葉へのパスはフル パスのみです。 その文字列は回文である必要があるため、ラベル付けはパスに沿って対称である必要があります。 

同時に、リーフから非リーフへのパス、つまりエンドポイントから開始してパス内のどこかで停止するパスについて考えてみましょう。 このプレフィックスが回文である場合、その中間点の周りでそれ自体をミラーリングすることになり、エンドポイントの直後に少なくとも 1 つの文字変更を導入しない限り、完全なパスの対称性と矛盾する強い繰り返しが強制されます。 

最も単純な構成は 2 つの文字を使用することです。 両方のエンドポイントに 1 つの文字を配置し、すべての内部ノードに別の文字を配置します。 これにより、フル パスは回文に保たれますが、エンドポイントで始まるプレフィックスは即座に回文を破ることが保証されます。

 ## アルゴリズムのチュートリアル

 1. ツリーを読み取り、すべてのノードの次数を計算します。 ツリーに次数 1 のノードが 3 つ以上ある場合、または次数が 2 より大きいノードがあれば、ツリーは拒否されます。 これにより、ツリーは単純なパスでなければならないことが強制されます。 
2. n = 1 の場合は個別に処理します。 リーフから非リーフへのパスが存在しないため、単一のノードは両方の条件を自明に満たします。 任意の文字を割り当てると、辞書編集的に最小の選択肢は次のようになります。`'a'`。 
3. 有効なパスの場合、その 2 つのエンドポイントを次数 1 のノードとして識別します。 
4. 1 つのエンドポイントから開始してパスをたどって、チェーンに沿ったノードの順序を生成します。 これは、隣接関係を使用し、前のノードに再度アクセスすることを回避する単純なウォークによって実行できます。 
5. 文字を割り当てる:与える`'a'`両方のエンドポイントに割り当て、`'b'`すべての内部ノードに送信されます。 
6. 結果の文字列を元のノードのインデックス付け順序で出力します。 

### なぜ効果があるのか

 葉から葉へのパスはチェーン全体だけです。 そのラベルは、`'a' + many 'b' + 'a'`、これは回文です。 エンドポイントから内部ノードへのパスはすべて次で始まります。`'a'`すぐに続いて`'b'`、最初と最後の文字が異なるため、すでに回文の対称性が破れています。 したがって、そのような接頭辞は回文になることはできません。 パス構造により、他のリーフ ペアが存在しないことが保証されるため、追加の制約は導入されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
adj = [[] for _ in range(n)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].append(v)
    adj[v].append(u)

if n == 1:
    print("a")
    sys.exit()

deg = [len(adj[i]) for i in range(n)]

# Tree must be a path
bad = False
leaves = 0
for i in range(n):
    if deg[i] > 2:
        bad = True
    if deg[i] == 1:
        leaves += 1

if bad or leaves != 2:
    print(-1)
    sys.exit()

# find one endpoint
start = 0
for i in range(n):
    if deg[i] == 1:
        start = i
        break

order = []
prev = -1
cur = start

while cur != -1:
    order.append(cur)
    nxt = -1
    for nei in adj[cur]:
        if nei != prev:
            nxt = nei
            break
    prev, cur = cur, nxt

res = [''] * n
for i, node in enumerate(order):
    if i == 0 or i == n - 1:
        res[node] = 'a'
    else:
        res[node] = 'b'

print("".join(res))
```コードはまず、次数をチェックすることでツリー構造が単一のチェーンであることを検証します。 これは、グローバル回文制約を満たすことができる唯一の構造的なケースです。 

検証後、以前のポインター技術を使用してリーフから別のリーフに移動することでパスを再構築します。これにより、完全な DFS の必要性が回避されます。 

割り当て手順は意図的に最小限に抑えられています。エンドポイントのみが内部ノードと異なります。 制約はエンドポイントと内部ノードのみを区別し、対称要件を超えるパス内の位置は区別しないため、これで十分です。

 ## 特殊なケース

 高次ノードを持つツリーは、必要なパス構造に違反するため、即座に拒否をトリガーします。 たとえば、3 つのリーフに接続されたノードは、一貫して満たすことができない複数の独立したリーフ間制約を強制しますが、アルゴリズムは次数チェックによってこれを正しく検出します。 

単一ノード ツリーは、矛盾するパス制約が存在しないため、すべての構造的推論をバイパスし、直接処理されます。 

2 ノード ツリーは最も単純な有効なパスであり、この構築により両方のエンドポイントに同じ文字が割り当てられ、内部ノード制約を完全に回避しながら有効な回文が生成されます。 

すべての場合において、アルゴリズムは問題を検証済みのパスまたは即時不可能のいずれかに絞り込み、あいまいな部分的な構成を防ぎます。
