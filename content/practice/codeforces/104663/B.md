 ## 解決策
 ## 問題の理解

 非負の整数の動的なセットを維持します。 時間の経過とともに、このセットは変化します。数値を挿入または削除できます。また、セットを降順に並べ替えるときに、現在特定の位置にランクされている要素を削除することもできます。 

この進化するセットに加えて、現在セット内のすべての数値にわたって各 10 進数の数字がどのくらいの頻度で出現するかを概念的に追跡します。 0 から 9 までの任意の数字について、すべてのアクティブな数字でその数字の合計出現数をカウントできます。 これにより、セットが変更されるたびに変更される固定頻度テーブルが得られます。 

クエリ番号 k に対して、この頻度テーブルのみに依存するスコア f(k) を定義します。 k に現れるすべての数字を調べ、出現するたびに、その数字の全体的な頻度を加算します。 k 内の繰り返される数字は複数回寄与します。 クエリはこのスコアを要求しますが、それは k が現在セット内にある場合に限られます。 それ以外の場合、答えは -1 です。 

主な問題点は、一連の数値とその桁統計の両方がオンラインで進化し、削除は値だけでなく順序統計によっても行われることです。 

制約は最大 300,000 操作に達します。 これにより、操作ごとにすべての数値をスキャンすると二次的な動作が発生するため、クエリごとに桁数を最初から再計算することが直ちに除外されます。 どのソリューションも、集約された情報を増分的に維持し、順序付けされた削除を効率的にサポートする必要があります。これは、バランスのとれたバイナリ インデックス付き構造や順序付きセットなどの対数更新を伴う構造を示唆しています。 

数値のオンとオフを複数回切り替えると、微妙なエッジケースが発生します。 桁頻度への寄与は、挿入時に完全に追加され、削除時に完全に削除されなければなりません。 数字の繰り返しでは、別の注意が必要な状況が発生します。たとえば、数字 111 には数字 1 が 3 回出現するため、頻度の更新では、存在だけでなく多重度も考慮する必要があります。 

2 番目の自明ではないエッジケースは、k 番目に大きい欠失です。 セットサイズが k より小さい場合、操作は完全に無視されなければなりません。 それ以外の場合は、値ではなくランクによって要素を正しく識別する必要があります。 

## アプローチ

 直接的なアプローチでは、アクティブな番号のセットを通常のコンテナに保存します。 各クエリ f(k) について、すべての数値をスキャンし、その場で桁の頻度を再計算します。 これは正しいですが、遅すぎます。クエリごとに O(n) 桁のスキャンにコストがかかる可能性があり、最大 3e5 クエリではこれは実行不可能になります。 

わずかに優れたブルート フォースでは、セットを維持し、必要に応じて桁数を再計算しますが、増分再計算でも、更新ごとにすべての数値のすべての桁に触れる必要があります。 各数値は最大 10 桁であるため、完全な再計算は 1 回の操作あたり O(n log10 n) であり、依然として制限をはるかに超えています。 

重要な観察は、桁数が数値に対して加算されるということです。 各数値は固定桁のヒストグラムに寄与します。 現在のセット全体で桁 d が何回出現するかを格納するグローバル配列 cnt[d] を維持する場合、f(k) は k の桁に対する単純な検索ベースの計算になります。 

これにより、問題は 2 つのことを効率的に維持することに移ります。1 つは高速な挿入、削除、k 次統計を備えた動的数値セット、もう 1 つは挿入または削除された数値ごとに O(桁) で更新できる実行桁ヒストグラムです。 

二分探索によるソートされたリストや圧縮された座標上のフェンウィックツリーなど、バランスの取れた構造で順序統計を解きます。 値は最大 2e9 で、最大 3e5 の異なる要素があるため、座標圧縮とフェンウィック ツリーまたは順序統計ツリーは O(log n) で機能します。 数値は最大 10 桁であるため、各更新では O(10) の桁数も調整されます。 

最終的な構造では、メンバーシップと数字の寄与の間の一貫性が維持されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq・d) | O(n) | 遅すぎる |
 | 最適 (順序セット + 桁頻度) | O(q log n + q · d) | O(n) | 承認済み |

 ここで、d は最大 10 です。 

## アルゴリズムのチュートリアル

 すべてのアクティブな数値をソートされた順序で保存するデータ構造と、グローバルな桁頻度配列 cnt[10] を維持します。 また、メンバーシップの切り替えとランクごとの削除もサポートする必要があります。 

1. まず、値をインデックスに圧縮できるように、すべての初期数値とトグル クエリに表示されるすべての数値を収集します。 これにより、固定範囲でフェンウィック ツリーを使用できるようになります。 値が 2e9 に達するため、圧縮が必要です。 
2. 圧縮されたインデックス上にフェンウィック ツリー (または BIT) を構築します。各位置には、番号が現在アクティブかどうかが格納されます。 これにより、プレフィックスの合計をクエリし、k 番目のアクティブな要素を見つけることができます。 
3. cnt[0..9] をゼロとして初期化します。 すべての初期数値について、それを構造に挿入し、その桁の寄与を cnt に追加します。 これにより、正しい開始状態が確立されます。 
4. クエリ「+ k」の場合、k が現在アクティブかどうかを確認します。 存在する場合は削除します。 それ以外の場合はそれを挿入します。 挿入するときは、k の桁を調べて、各桁の出現ごとに cnt[d] をインクリメントします。 削除する場合も同様にデクリメントします。 
5. クエリ「- k」の場合、まずアクティブ セットのサイズが少なくとも k であるかどうかを確認します。 そうでない場合は無視します。 それ以外の場合は、フェンウィック ツリーを使用して、k 番目に大きい要素のインデックスを見つけます。 Fenwick は自然に k 番目の最小値をサポートするため、size - k + 1 をクエリして変換します。次に、値を取得して削除し、桁の頻度を更新します。 
6. クエリ「? k」の場合、まず k がアクティブかどうかを確認します。 そうでない場合は、-1 を出力します。 それ以外の場合は、k の桁を反復し、各桁の出現ごとに cnt[d] を合計することによって f(k) を計算します。 

### なぜ効果があるのか

 常に、cnt[d] は、すべてのアクティブな数値にわたる数字 d の出現の合計数と正確に等しくなります。 挿入するたびに数値の桁ヒストグラムが追加され、削除するたびにまったく同じヒストグラムが削除されます。 セット上の各操作は cnt 上の対応する更新によってミラーリングされるため、不変条件は true のままです。 f(k) は純粋に k 桁にわたる cnt[d] の線形結合として定義されるため、メンバーシップが検証されると、計算された値は常に正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def find_kth(self, k):
        idx = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = idx + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                idx = nxt
            bitmask >>= 1
        return idx + 1

def digits(x):
    if x == 0:
        return [0]
    res = []
    while x:
        res.append(x % 10)
        x //= 10
    return res

n, q = map(int, input().split())
a = list(map(int, input().split()))

ops = []
vals = set(a)

for _ in range(q):
    line = input().split()
    ops.append(line)
    if len(line) == 2:
        vals.add(int(line[1]))

vals = sorted(vals)
idx = {v: i + 1 for i, v in enumerate(vals)}

fw = Fenwick(len(vals))
active = set()
cnt = [0] * 10

def add_num(x):
    if x in active:
        return
    active.add(x)
    fw.add(idx[x], 1)
    for d in digits(x):
        cnt[d] += 1

def remove_num(x):
    if x not in active:
        return
    active.remove(x)
    fw.add(idx[x], -1)
    for d in digits(x):
        cnt[d] -= 1

for x in a:
    add_num(x)

out = []

for op in ops:
    if op[0] == '+':
        x = int(op[1])
        if x in active:
            remove_num(x)
        else:
            add_num(x)

    elif op[0] == '-':
        k = int(op[1])
        size = fw.sum(len(vals))
        if k > size:
            continue
        target = size - k + 1
        idx_pos = fw.find_kth(target)
        x = vals[idx_pos - 1]
        remove_num(x)

    else:
        x = int(op[1])
        if x not in active:
            out.append("-1")
        else:
            res = 0
            for d in digits(x):
                res += cnt[d]
            out.append(str(res))

print("\n".join(out))
```フェンウィック ツリーは、純粋に順序統計のために使用されます。 アクティブ セットは同期を維持して、O(1) メンバーシップ チェックを可能にします。 桁数配列 cnt は、数値がアクティブ セットに出入りするときにのみ更新され、クエリ時間が k の桁長のみに依存することが保証されます。 

よくある間違いは、トグル クエリでは既存の番号がすでに存在する場合は削除する必要があることを忘れていることです。 もう 1 つは、実際の状態の変化だけではなく、クエリごとに桁数を更新することです。これにより、度数表が破損します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n + q · d) | Fenwick の更新と k 番目のクエリは対数的であり、桁の仕事は数値ごとに一定です。 
| スペース | O(n + 10) | 圧縮されたインデックスと数字の頻度配列 |

 log n は 3e5 要素の場合約 19 であり、数値処理は更新またはクエリごとに最大 10 操作に制限されるため、このソリューションは制限内に問題なく収まります。

 ## 特殊なケース

 微妙なケースとして、同じ番号を複数回切り替えることがあります。 たとえば、空から開始し、「+ 10」を 2 回適用すると、最初に挿入してから削除する必要があります。 実装では、追加するか削除するかを決定する前にメンバーシップを明示的にチェックし、状態が変化した場合にのみ桁数が変更されるようにします。 

もう 1 つのエッジ ケースは、セットが小さすぎる場合のランクによる削除です。 現在のセットのサイズが 2 で、「- 5」を受け取った場合、Fenwick クエリは実行されず、桁数も変更されず、cnt の正確性が維持されます。 

最後に、1111111111 のような桁の多い数値は、多重度の処理を強調します。 挿入ごとに cnt[1] が 10 ずつ更新され、削除によって同じ量が減算されます。 桁の反復は桁数が線形であるため、最悪の値であっても効率的なままです。
