 ## 解決策
 ## 問題の理解

 私たちは複数の針が見える円形の時計を与えられていますが、すべての針は同じに見えるため、どれが時、分、秒に対応しているかを直接知ることはできません。 各針は一定の周期で均一に回転するため、常に 3 つの針は真夜中からの基礎となる時間によって決まる 3 つの角度を形成します。 

入力は 3 つの角度に関して時計の 1 つのスナップショットを記述しますが、これらの角度にはラベルが付けられていません。 タスクは、これら 3 つの観測角度が真夜中以降の一貫した時刻に対応するように 3 つの実際の時計の針に有効に割り当てられているかどうかを判断し、存在する場合はその時刻を一意に再構築することです。 

これについて考えるのに役立つ方法は、時間は真夜中からナノ秒単位で測定される単一の隠れた整数値であり、各針の位置はその値の決定論的な関数であるということです。 時針は非常にゆっくりと動き、12 時間で 1 回転し、分針は 1 時間で 1 回転、秒針は 1 分で 1 回転します。 したがって、観察される状態は、同じ隠れた値の 3 つのモジュラー線形式です。 

この制約は非常に厳格であるため、観察された角度を実際の手に割り当てることができる可能性は 6 つありますが、そのほとんどは有効な時間に対応しません。 出力は、割り当てが機能しないこと、または構成の一貫性を保つ正確な時刻 (時、分、秒) のいずれかです。 

問題はナノ秒単位で定義されるため、隠れたスケールは非常に大きくなりますが、その構造は純粋に算術モジュラー制約です。 一般的な定式化では範囲が最大 10^18 スケールであるため、これにより、時間の経過に伴うシミュレーションやブルート フォースの可能性が即座に排除されます。 代わりに、解決策は時計の形状からの直接の再構築に依存する必要があります。 

キー エッジ ケースは、2 つ以上の手が一致したときに表示されます。 その状況では、割り当ての複数の置換によって同一の角度セットが生成されます。 たとえば、3 つの針すべてが 0 度を指している場合、どの割り当ても一貫していますが、再構築された時間は依然として有効であり、すべての制約と一貫している必要があります。 角度から手へのマッピングの一意性を仮定する単純な解決策は、有効なケースを過剰に制約したり拒否したりするため、ここでは失敗します。 

もう 1 つの微妙なケースは、浮動小数点精度またはモジュラー ラップアラウンドが正しく処理されない場合に発生します。 各針の位置は完全な回転を法として定義されるため、完全な 1 サイクルだけ異なる値は同一として扱われなければなりません。 モジュール正規化を行わない単純な角度比較では、手が完全に回転した有効な構成が誤って拒否される可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 針は 3 つしかなく、どの観察角度が実際のどの針に対応するかわからないため、3 つの観察角度のすべての順列を試し、それらを時針、分針、秒針に割り当てることができます。 割り当てごとに、基礎となる時間を再構築しようとします。 

割り当てが決定されると、時針は 12 時間を法とする時間を直接決定します。 そこから、ナノ秒単位の絶対時間の候補を導​​き出すことができます。 この候補を使用して、分針と秒針の位置を再計算し、モジュラー等価性の下でそれらが観察された角度と一致するかどうかを確認します。 それらが一致する場合、有効な解決策が見つかりました。 

これが機能するのは、時間から手の位置へのマッピングが決定的であるためです。そのため、正しい割り当ては 3 つの制約をすべて同時に満たさなければなりません。 ただし、総当たり法では順列が 6 つしか存在しないため、一定の作業が行われます。そのため、実際の困難は、この段階での組み合わせ爆発ではなく、モジュラー演算を高精度で正しく処理し、一貫性を確保することです。

重要な洞察は、フルタイムを再構築するには片手だけで十分であるということです。 時針は、対象範囲全体にわたって、大まかではあるが単射的な方法で時間をエンコードします。 その角度を細かく離散化された円上の位置として解釈すると、完全なタイムスタンプの一意の候補が得られます。 残りの 2 つの手は、曖昧さの原因ではなく、検証の制約として機能します。 

したがって、問題は、割り当ての反復、時針からの時刻の解読、残りの検証に帰着します。

 ## アルゴリズムのチュートリアル

 角度を大きな円上の整数の目盛りとして扱い、1 回転が固定定数に対応するようにスケーリングします。 これにより、浮動小数点演算を完全に回避できます。 

観察された 3 つの角度を時間、分、秒の役割に割り当てるあらゆる順列を試します。 

各割り当てでは、まず時針の位置を候補時刻を定義するものとして解釈します。 時針は 12 時間ごとに 1 つの完全なサイクルを完了するため、その角度を完全なサイクルを法とするナノ秒のタイムスタンプに直接マッピングできます。 このステップは、12 時間枠のどこまで進んでいるかを効果的に推測します。 

タイムスタンプの候補を取得したら、既知の周期性を使用して、その時点で分針と秒針がどこに位置するかを計算します。 これは、角度位置空間への時間の直接的なモジュール乗算です。 

次に、計算された位置と割り当てられた観測値を比較します。 モジュラー等価性の下で両方が正確に一致する場合、割り当ては有効であり、デコードされた時間を出力できます。 

どの順列も一貫した割り当てを生成しない場合、構成は不可能です。 

### なぜ効果があるのか

 この正しさは、各手の位置が 1 つの隠れた変数 (真夜中からの時間) の決定的な線形関数であるという事実から得られます。 この関数は、時針の完全な 12 時間間隔に制限されている場合は単射的です。つまり、問題の領域内の基礎となるタイムスタンプを一意に決定します。 タイムスタンプが固定されると、他の 2 つの針は独立変数ではなく派生値となるため、代替ソリューションを導入することはできません。 したがって、有効な解は少なくとも 1 つの順列の下で一貫している必要があり、検証に合格したすべての順列は真の基礎となる時間に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# constants based on full circle discretization
FULL = 12 * 60 * 60 * 10**9  # nanoseconds in 12 hours
HOUR = 60 * 60 * 10**9
MINUTE = 60 * 10**9
SECOND = 10**9

def check(h, m, s):
    # try interpreting h as hour hand
    # recover time from hour hand angle
    # scale assumption: h = t * (FULL / FULL) mod FULL in canonical form
    t = h % FULL

    mh = (t // MINUTE) % 60
    sh = (t // SECOND) % 60
    hh = (t // HOUR) % 12

    # convert observed m, s back to comparable scale
    # since all are modulo FULL, we compare normalized positions
    return (m % FULL == (t % FULL) * 60 // 1 % FULL) and (s % FULL == (t % FULL) * 3600 // 1 % FULL)

def solve():
    a = list(map(int, input().split()))

    for i in range(3):
        for j in range(3):
            if j == i:
                continue
            k = 3 - i - j

            h, m, s = a[i], a[j], a[k]
            if check(h, m, s):
                # reconstruct time in hh:mm:ss
                t = h % FULL
                hh = (t // HOUR) % 12
                mm = (t // MINUTE) % 60
                ss = (t // SECOND) % 60
                print(hh, mm, ss)
                return

    print("Impossible")

if __name__ == "__main__":
    solve()
```コードはまず、観測された 3 つの角度値を読み取ります。 次に、これらの値の 3 つの時計針へのすべての割り当てを繰り返します。 各割り当てでは、候補の時針が 12 時間を法とする絶対時間を修正すると仮定します。 

チェック機能は、残りの 2 つの針が導出された時刻と一致するかどうかを検証する役割を果たします。 再構築では精度の問題を回避するために整数演算が使用されます。 最後のステップでは、タイムスタンプを標準の時、分、秒の形式に変換します。 

実装の微妙な点は、すべての比較が同じモジュール ドメイン内に留まらなければならないことです。 一貫したスケーリングを行わずに生の角度と派生時間コンポーネントを混合することは、このタイプの問題で最も一般的な誤答の原因です。

 ## 特殊なケース

 観察された 3 つの角度がすべて同一の場合でも、アルゴリズムは通常どおり続行されます。 すべての順列は同じ再構築されたタイムスタンプをもたらすため、最初の有効なチェックがトリガーされ、ゼロ時間が返されます。 

2 本の手が同じ角度を共有している場合、複数の順列は区別できなくなりますが、正しいセマンティック マッピングのみが導出値と観測値の間の一貫性チェックに合格します。 これにより、曖昧さが正確さに影響を与えるのを防ぎます。 

完全な回転が完了する直前など、値がモジュラー境界に近い場合、modulo FULL による正規化により、同等の位置が同じように扱われることが保証されます。 すべての比較が同じ循環領域で行われるため、再構築された時間は安定したままになります。
