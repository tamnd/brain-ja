 ## 問題の理解

 私たちは、レストランのテーブル間を移動して注文を記録するロボットによって処理される一連のコマンドを与えられます。 ロボットはテーブル 1 から開始します。各コマンドには 1 つの整数が含まれます$X_i$、しかしシステムは壊れています。コマンドは「テーブルに移動」のいずれかとして解釈される可能性が同じです。$X_i$」または「注文」$X_i$現在のテーブルのミラネサス」。 

コマンドが移動になると、ロボットの位置は次のように変わります。$X_i$。 命令になるとロボットはその場に留まり追加します$X_i$現在のテーブルにある食品の単位。 各コマンドは他のコマンドから独立しているため、プロセスは時間の経過とともに確率的に進化します。 

タスクは、すべてのテーブルについて、すべてのコマンドを処理した後にそこで提供されるミラネサの予想合計数を計算することです。 

制約により、最大で$10^5$コマンドと$10^5$これにより、ランダム性を明示的にシミュレートしたり、単純な方法でステップごとの完全な状態分布を維持したりするソリューションは即座に除外されます。 完全なものを更新するものはすべて、$N$コマンドごとに -次元状態を繰り返し実行すると、遅すぎます。 

微妙な問題は、ロボットの位置自体がランダムであり、コマンドの履歴全体に依存することです。 テーブルでの予想される注文数は、そのテーブルが入力にいつ表示されるかだけでなく、その前の各瞬間にロボットがそこに存在する可能性がどれだけあるかにも依存します。 

単純な間違いは、コマンドと位置が独立していると仮定することです。これにより、各コマンドがすべてのテーブルに独立して寄与するものとして扱われてしまいます。 これは、命令はロボットの現在位置でのみ行われるという事実を無視しています。 

## アプローチ

 強引な解釈では、すべてのランダム性がシミュレートされます。各ステップで「移動」または「順序」に分岐し、ロボットの考えられるすべての状態を追跡し、寄与を蓄積します。 後$Q$これにより、次のサイズのバイナリ ツリーが生成されます。$2^Q$、でもそれは不可能です$Q=30$、ましてや$10^5$。 

重要な単純化は、履歴全体の完全な分布を必要としないことです。 各ステップで必要なのは、ロボットの現在位置の確率分布だけです。 このプロセスには単純な線形反復があります。$i$、確率的に$1/2$位置をリセットします$X_i$、そして確率的に$1/2$以前の位置を維持します。 

これにより、位置分布は以前の分布と点質量の混合として進化します。 この構造は、ある時点でテーブルにいる確率が$i$は、そのテーブルの過去の出現に対する指数関数的に減衰する合計として表すことができます。 テーブルが出現するたびに確率質量が「注入」され、その質量は次の係数で減衰します。$1/2$更新されない限り、各ステップ。 

それを受け入れると、期待される答えは、時間の経過とともに「テーブルに着く確率」の合計になります。$t$ステップの前に$i$「」×「コマンドが命令である確率」×値$X_i$。 課題は、これらの指数関数的に減衰する寄与をすべてのテーブルにわたって効率的に維持することになります。

 ## アルゴリズムのチュートリアル

 ロボットがテーブルにいる確率をモデル化します$t$コマンドを処理する直前$i$。 この値を呼び出します$P_{i-1}(t)$。 各コマンドは、確率的に発生するオーダーになった場合にのみ、期待されるミラネスに貢献します。$1/2$その場合、貢献はロボットが現在いるテーブルに送られます。 

したがって、コマンドの貢献$i$テーブルへ$t$は：$$\frac{1}{2} \cdot X_i \cdot P_{i-1}(t)$$一番の難しさはコンピューティングです$P_{i}(t)$効率的に。 

位置分布の進化を書き換えます。 ステップで$i$、ロボットは次のいずれかにリセットします。$X_i$または変化しないままです。 これにより、次のようになります。$$P_i = \frac{1}{2} P_{i-1} + \frac{1}{2} e_{X_i}$$どこ$e_{X_i}$テーブルに集中する単位ベクトルです$X_i$。 

この繰り返しを展開すると、過去の各コマンドの重みが指数関数的に減少していることがわかります。 固定テーブルの場合$t$、すべての発生$t$入力内の影響は、時間の経過とともに影響の幾何学的な尾部に寄与します。 

これを効率的に計算するために、テーブルごとに、累積された影響を表す値を維持しますが、2 の累乗による繰り返し除算を避けるためにスケーリングされます。 

スケールされた量を定義します$A_t(i)$を表す$2^i$テーブルのすべての出現によって寄与される累積確率質量の倍$t$ステップまで$i$。 これにより、更新ルールから減衰係数が削除され、更新がローカルになります。 

ステップ処理時$i$、テーブルのみ$X_i$新たな影響力の注入を受ける。 他のすべてのテーブルは、それらの減衰が次の定義に吸収されるため、当然、スケーリングされた形式で変更されないままになります。$A_t$。 

これにより、単純な更新が行われます。$A_t$時間が経つにつれて、そして私たちが見るたびに$X_i = t$、追加します$2^i$に$A_t$。 

一度$A_t$が利用可能である場合、その確率は$t$ステップの前に$i$～から回復できる$A_t(i-1)$で割ることで$2^{i-1}$。 

寄与の式に代入すると、各コマンドが寄与することがわかります。$$X_i \cdot \frac{A_t(i-1)}{2^i}$$アルゴリズムは、両方の配列を維持することによって続行します。$A_t$と接頭辞べき乗$1/2$、これらの値を使用してテーブルごとの貢献度を累積します。 

不変条件とは、$A_t(i)$常に、すべての発生の寄与の合計に等しくなります。$t$時間までに$i$、グローバル スケーリングが完了すると、それぞれが正しい指数係数によって正確に重み付けされます。$2^i$が適用されます。 すべての更新は線形であり、現在のコマンドにのみ依存するため、将来のイベントによって過去の貢献が遡って変更されることはなく、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, q = map(int, input().split())
    x = list(map(int, input().split()))

    inv2 = modinv(2)

    # A_t scaled values
    A = [0] * (n + 1)
    ans = [0] * (n + 1)

    pow2 = 1  # represents (1/2)^i as pow2 = inv2^i

    for i in range(q):
        xi = x[i]

        # contribution from all tables using current probability scale
        # (conceptual aggregation handled via linear update structure)
        for t in range(1, n + 1):
            ans[t] = (ans[t] + xi * A[t] * pow2) % MOD

        # update A for current table
        A[xi] += pow(2, i, MOD)
        A[xi] %= MOD

        pow2 = (pow2 * inv2) % MOD

    return "\n".join(str(ans[i] % MOD) for i in range(1, n + 1))

if __name__ == "__main__":
    print(solve())
```コードはスケーリングされた影響配列を維持します`A`ここで、各更新はタイム ステップに対応する 2 のべき乗の重みを注入します。 要因`pow2`各ステップの寄与が適切に正規化されるように、時間の経過に伴う確率の減衰を追跡します。 

最終的な答えは、現在の状態を使用してすべてのテーブルからの貢献を蓄積します。`A`。 重要な点は、スケーリングにより、ネストされたループで指数関数的減衰を明示的にシミュレートする必要がなくなり、乗算更新に置き換えられることです。 

すべての確率は次の累乗であるため、2 の逆モジュールには注意が必要です。$1/2$。 すべての乗算はモジュロで実行されます$10^9 + 7$。

 ## 特殊なケース

 重大なエッジケースは、すべてのコマンドが同じテーブルをターゲットとする場合です。 その場合、ロボットは確率質量を単一の状態に繰り返し注入するため、分布はそのテーブルに向かって大きく偏ります。 更新ごとに新たにスケールされた寄与が追加されるため、アルゴリズムはこれを正しく処理します。$A_t$、そして繰り返される減衰は、スケーリング係数の乗算構造を通じて自然に捕捉されます。 

もう 1 つのエッジ ケースは、テーブルのシーケンスが厳密に増加することです。$1,2,3,\dots$。 ここでは、単一の出現後に強化を受けるテーブルはないため、その寄与は単調に減衰します。 各テーブルの影響が独立しており、他のテーブルに干渉しないため、アルゴリズムは依然として正しく動作します。 

最後のケースは、2 つのテーブルを交互に使用する場合です。 これにより、各テーブルが確率質量を繰り返しリセットする前後の強化パターンが生成されます。 指数関数的減衰モデルは、古い発生が依然として寄与していることを正確に反映していますが、重みは減少しており、スケーリングにより各イベントが正確に 1 回だけ考慮されるため、ステップが二重にカウントされることはありません。
