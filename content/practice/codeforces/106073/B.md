 ## 解決策
 ## 問題の理解

 N ポジションのデッキから始めます。 各位置には最初に何らかの値を持つカードがあり、シャッフルを繰り返した後、各位置でどのような値が必要かを示すターゲット配置が与えられます。 使用可能な唯一の操作は、位置の固定順列です。各位置 i は、現在のカードを位置 P[i] に送信します。 この順列は繰り返し適用されるため、k 回シャッフルした後、順列を k 回適用することによってデッキが変形されます。 

重要なタスクは、順列を k 回適用することで初期配列がターゲット配列に変換されるように、最小の k を決定することです。 そのような k が存在しない場合、答えは「不可能」です。 そのような最小の k が 10^9 を超える場合、「DEMAIS」を出力する必要があります。 

重要な制約は、N が 10^6 まで大きくなり得るため、N において線形または線形に近い解でなければなりません。k ステップを明示的にシミュレートすることは直ちに不可能です。k 自体が大きくなる可能性があり、各ステップが O(N) であるため、最悪のケースでは 10^15 の演算が行われる可能性があります。 

微妙な問題は、配列 A と B で値が繰り返されることにあります。値は一意ではないため、値だけで個々のカードを追跡することはできません。 代わりに、アイデンティティは位置に関連付けられており、順列は値ではなく位置に作用します。 

いくつかの特殊なケースが自然に現れます。 A がすでに B に等しい場合、答えはゼロです。 順列が循環を形成し、値が位置全体で一貫して一致しない場合、答えは不可能です。 別の失敗ケースは、ある程度のサイクル長の後に順列が最終的に同一に戻ったとしても、必要な値の位置合わせが異なるサイクルにわたる異なるサイクル位相で発生し、同期が不可能になる場合に発生します。 

## アプローチ

 直接シミュレーションでは、配列に順列を繰り返し適用します。 各アプリケーションの後で、結果の配列を B と比較します。これは正しいですが、各シャッフルは O(N) であり、最悪の場合、順列のサイクル長までシミュレートする必要がある可能性があります。これは、O(N)、または 10^9 の制限を考慮するとさらに悪いことになる可能性があります。 これにより O(N^2) の動作が発生し、10^6 までの N には遅すぎます。 

順列が独立したサイクルに分解されることを観察すると、問題の構造がより明確になります。 サイクル内では、位置が決定論的に相互に回転します。 グローバルに考える代わりに、各サイクルを個別に分析して、より単純な質問をすることができます。特定のサイクルについて、どのシフト k でサイクル内のすべての位置がそのターゲット値に同時に一致するか?

 1 つのサイクルを固定すると、順列を k 回適用することは、サイクルを k ステップ回転することに相当します。 したがって、各サイクルは k に周期的な制約を生成します。 サイクル内の各位置について、k ステップ後にマップされる開始位置を計算できます。現在の位置の B と一致するには、A のその位置の値が必要です。 これは、サイクルに沿ったインデックスの一致から導出される、「k はサイクル長を法とする何らかの値に一致しなければならない」という形式の制約になります。 

各位置は必要なアライメントシフトを与えます。 同じサイクル内の複数の位置で異なるシフトが必要な場合、有効な k は存在しません。 それらが一致すると、サイクルごとに 1 つのモジュラー制約が得られます。 最後に、答えはすべてのサイクル制約を同時に満たす必要があるため、中国剰余定理を使用して合同系を解きます。 矛盾が出てくると答えられなくなります。 解が存在する場合は、最小の非負の k を取得し、それが 10^9 を超えているかどうかを確認します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N・K) | O(N) | 遅すぎる |
 | サイクル分解 + CRT | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

この順列を、各ノードが出ていくエッジを 1 つだけ持つ有向グラフとして解釈します。 これにより、グラフが互いに素なサイクルに分解されることが保証されます。 

1. 訪問されていない各位置から開始位置に戻るまで歩き、順列をサイクルに分解します。 各サイクルのノードを走査順序で記録します。 シャッフルが繰り返されるとポジションが相互作用するのはサイクル内のみであるため、この構造は不可欠です。 
2. 各サイクルに対して、サイクル順序に沿って 0 から L−1 までのインデックスを割り当てます。 1 つのシャッフルを移動することは、インデックスを 1 モジュロ L だけインクリメントすることに対応します。 
3. サイクル内のすべての位置について、A のある位置に元々あった値が B 内の必要な値と一致するように、必要なシフト数を決定します。具体的には、サイクル内のインデックス i の位置について、k シフト後にその値がどこから取得される必要があるかを特定します。 これにより、必要な合同式 k ≡ シフト mod L が得られます。 
4. サイクルの処理中に、その位置からのすべての制約を交差させます。 L を法として必要な 2 つの異なるシフトに遭遇した場合、システムは一貫性がなく、直ちに不可能であると結論付けられます。 
5. すべてのサイクルを処理した後、k ≡ r_i (mod m_i) の形式の合同式のセットを累積します。 拡張ユークリッド アルゴリズムを使用して、それらを繰り返しマージします。 いずれかの時点で解決策がない場合は、「IMPOSSIVEL」を出力します。 
6. 大域的な解 k が得られたら、最小の非負の代表を選択します。 k > 10^9 の場合、「DEMAIS」を出力します。 それ以外の場合は、k を出力します。 

これが機能する理由は、各サイクルが順列の繰り返しのもとで独立して進化するためです。 1 サイクル内では、k 回のシャッフルの効果は正確に回転であるため、すべての制約がモジュール式の位置合わせ条件になります。 グローバル構成は、すべてのサイクルが独立した回転要件を満たす単一の k に一致する場合にのみ正しいものとなります。 中国剰余定理はこれらの周期的制約の交差部分を正確に捉えており、故障は互換性のないサイクル要件に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def egcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x1, y1 = egcd(b, a % b)
    return g, y1, x1 - (a // b) * y1

def crt(a1, m1, a2, m2):
    # solve x ≡ a1 (mod m1), x ≡ a2 (mod m2)
    g, p, q = egcd(m1, m2)
    if (a2 - a1) % g != 0:
        return None, None
    lcm = m1 // g * m2
    t = ((a2 - a1) // g * p) % (m2 // g)
    x = (a1 + m1 * t) % lcm
    return x, lcm

def solve():
    n = int(input())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))
    P = list(map(int, input().split()))
    P = [p - 1 for p in P]

    visited = [False] * n
    INF = 10**18

    def get_shift(cycle):
        L = len(cycle)
        pos = {cycle[i]: i for i in range(L)}
        shift = None

        for i in cycle:
            target = B[i]
            found = False
            for j in cycle:
                if A[j] == target:
                    diff = (pos[i] - pos[j]) % L
                    if shift is None:
                        shift = diff
                    elif shift != diff:
                        return None
                    found = True
            if not found:
                return None
        return shift, L

    constraints = []

    for i in range(n):
        if not visited[i]:
            cur = i
            cycle = []
            while not visited[cur]:
                visited[cur] = True
                cycle.append(cur)
                cur = P[cur]
            if len(cycle) == 0:
                continue

            res = get_shift(cycle)
            if res is None:
                print("IMPOSSIVEL")
                return
            shift, L = res
            constraints.append((shift % L, L))

    k = 0
    m = 1

    for a2, m2 in constraints:
        k, m = crt(k, m, a2, m2)
        if k is None:
            print("IMPOSSIVEL")
            return

    if k > 10**9:
        print("DEMAIS")
    else:
        print(k)

if __name__ == "__main__":
    solve()
```実装では、まず順列のサイクルを構築します。 各サイクルは独立して分析され、そのサイクル内で必要な回転数を記述する単一のモジュール式条件が抽出されます。 ヘルパー関数`get_shift`B 内のすべての必要な値を、同じサイクル内の A 内の値と一致させて、一貫したオフセットを導出します。 複数のオフセットが現れると、いつでもサイクルを満たすことができなくなります。 

すべてのサイクル制約を抽出した後、ソリューションは標準の中国剰余定理ルーチンを使用してそれらをマージします。 の`crt`関数は、拡張ユークリッド アルゴリズムを使用して非共素係数を慎重に処理します。これは、サイクル長が因数を共有できるため必要です。 最後の k は最小の非負の代表値に減らされ、10^9 のしきい値と照合されます。 

## 実用的な例

 2 つのケースをトレースして、サイクル制約がどのように発生して結合されるかを確認します。 

### 例 1

 単一サイクルが一貫したシフトを生成する場合を考えます。 

| ステップ | サイクル | 派生シフト | 制約 |
 | --- | --- | --- | --- |
 | 1 | [0,1,2,3] | 2 | k ≡ 2 mod 4 |

 シフト 2 ではすべての位置が一致するため、サイクルによって 1 つの合同が得られます。 他にサイクルは存在しないため、最終的な答えは k = 2 になります。 

これにより、サイクル内で問題が単純な回転位置合わせに帰着することが確認されます。 

### 例 2

 A がすでに B に等しい場合を考えます。 

| ステップ | サイクル | 派生シフト | 制約 |
 | --- | --- | --- | --- |
 | 1 | 任意のサイクル | 0 | k ≡ 0 mod L |

 すべてのサイクルはシフト 0 で即座に整列し、すべての制約をマージした後に k = 0 が生成されます。 

これは、ゼロ シャッフル構成が一貫したモジュラー制約として自然に処理されることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、サイクルに A には繰り返し値が含まれるが、B には必要な値が 1 回しか出現しない場合です。その状況では、内部マッチング ループが同じターゲットに対して複数の候補ソースを見つけ、競合するシフトが生成される可能性があります。 アルゴリズムは、サイクル内のすべての位置を単一の回転オフセットに強制的に一致させるため、これを正しく拒否します。 重複によって曖昧さが生じると、整合性が即座に失われます。 

もう 1 つのケースは、異なるサイクルが個別に解を許容するものの、それらの係数に互換性がない場合です。 たとえば、あるサイクルは k ≡ 1 mod 2 を必要とし、別のサイクルは k ≡ 0 mod 2 を必要とする場合があります。各サイクルは局所的に一貫していますが、CRT ステップはグローバル k が存在しないことを検出し、正しい「IMPOSSIVEL」を生成します。 

最後のエッジ ケースは、CRT 再構成により計算された k が非常に大きくなる場合です。 解が存在する場合でも、結合係数を法として換算し、10^9 と照合して、値を出力するか「DEMAIS」を出力するかを決定する必要があります。
