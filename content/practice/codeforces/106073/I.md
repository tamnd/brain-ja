 ## 解決策
 ## 問題の理解

 平面内には、固定された順序で訪れる星を表す一連の点が与えられます。 連続する星は常に水平または垂直に整列するため、それぞれの星の間を移動します。$i$そしてスター$i+1$軸に平行な直線セグメントです。 

それぞれの星について$i$、整数の半径を割り当てる必要があります$R_i \ge 1$。 宇宙船は概念的には星を「周回」する$i$その半径で。 連続する星間の唯一の結合は幾何学的制約、つまり星の半径です。$i$星間のユークリッド距離より厳密に小さくなければなりません$i$そしてスター$i+1$。 

宇宙船は星から移行します$i$スターを付ける$i+1$の軌道上の点で$i$それは次の星に最も近いものですが、実現可能性に関して重要なのは不等式だけです$$R_i < d(i, i+1)$$どこ$d$はユークリッド距離です。 

すべての制約を満たす有効な半径のシーケンスを選択し、最大化するように求められます。$R_1$。 割り当てがまったく存在しない場合は、-1 を出力します。 

重要な点は、半径が独立していないことです。$R_i$が選択されると、それは初期の星で可能なことに影響を与えます。$R_1$、任意の実現可能性ではありません。 

制約は大きく、最大で$10^5$したがって、どの解も線形または線形に近いものでなければなりません。 数列上の二次関数はすぐに遅すぎます。 

いくつかの失敗例は自然に現れます。 

たとえば、連続する 2 つの星が非常に近い場合、$(0,0)$そして$(0,1)$、距離は 1 なので、$R_1$半径は少なくとも 1 でなければならないため、これは不可能です。これにより、構成全体が不可能になります。 

初期の 1 つのエッジが短い場合を除き、すべてのエッジが長い場合、より微妙な障害が発生します。 たとえば、最初のエッジの距離が 2 であるが、後のエッジが大きい場合は、次のことを選択できると考えるかもしれません。$R_1 = 1$、しかし実際には、半径がどのように伝播するかに応じて、後の制約によって矛盾が強制される可能性があるため、一貫したグローバルな構築が必要です。 

主な困難は、制約が最後から最初にどのように逆方向に伝播するかを理解することです。 

## アプローチ

 素朴な解釈は、半径を左から右に割り当てようとすることです。 それぞれについて$i$、私たちは選びます$R_i$できるだけ大きい下で$R_i < d(i, i+1)$、続けてください。 これにより、各ローカル値が最大化されますが、最大化というグローバルな目標は無視されます。$R_1$完全に実行可能な割り当てが存在する場合。 この貪欲な前進アプローチは最大化を保証するものではありません$R_1$なぜなら、早​​い段階で小さな半径を選択すると、より大きな半径を可能にする実現可能性パターンが不必要に制限される可能性があるからです。$R_1$別のディストリビューションの下にあります。 

もう一つの強引なアプローチは、$R_1$修正して実現可能性を確認します: 修正した場合$R_1 = x$、建設できますか？$R_2, \dots, R_N$? それから二分探索ができます$x$。 ただし、実現可能性を素朴にチェックする場合でも、各半径には範囲があるため、後続の半径の多くの選択肢を検討する必要があり、潜在的に指数関数的になる可能性があります。$[1, d(i,i+1)-1]$。 

重要な観察は、唯一の制約はローカルな上限であり、グローバル最小値を除いて、異なる半径間には直接的な下限の依存関係がないことです。$R_i \ge 1$。 これはそれぞれのことを意味します$R_i$独自のエッジ制約を遵守していることを確認すれば、いつでも独立して選択できます。 間の伝播制約はありません。$R_i$そして$R_{i+1}$。 

したがって、実現可能性は単純な条件に帰着します。つまり、すべてのエッジの距離が少なくとも 2 でなければなりません。$R_i \ge 1$そして$R_i < d(i,i+1)$、 それで$d(i,i+1) \ge 2$。 これが成立したら、いつでも設定できます$R_i = 1$みんなのために$i$、およびそれ以上の$R_1$はその出力エッジによってのみ制約されます。 

したがって、影響を与える唯一の実際の制約は、$R_1$は最初のエッジです:$R_1 < d(1,2)$。 以来$R_1$は整数で、最大値は$d(1,2) - 1$すべてのエッジが有効である場合 (距離が少なくとも 2)。 いずれかのエッジの距離が 1 であれば、答えは -1 になります。 

これにより、問題全体が、連続する点間のユークリッド距離の計算と妥当性のチェックに集約されます。

 ## アルゴリズムのチュートリアル

 1. すべてのポイントを順番に読み取り、連続するポイント間の二乗ユークリッド距離を計算します。 平方距離では、整数とのみ比較するため、順序を維持しながら浮動小数点の精度の問題が回避されます。 
2. 連続するペアごとに、二乗距離が少なくとも 4 であるかどうかを確認します。これは、実際の距離が少なくとも 2 である必要があることと同じであり、整数の半径が保証されます。$R_i \ge 1$満足できる$R_i < d(i,i+1)$。 
3. 連続するペアの二乗距離が 1 に等しい場合は、構成は不可能であると直ちに結論付けます。 これは 1 単位離れた 2 つの点に対応し、厳密に 1 より小さい整数半径は残りません。 
4. 最初のエッジ距離は直接境界にあるため、個別に追跡します。$R_1$。 させて$d_1$は星 1 と星 2 の間のユークリッド距離になります。 
5. すべてのエッジが有効な場合、答えを次のように計算します。$d_1 - 1$、二乗距離に基づく整数演算を使用します。 

### なぜ効果があるのか

 各半径$R_i$次の星によってのみ制約され、以前の選択には依存しません。 システムは、次のような連鎖制約を課しません。$R_i \le R_{i+1}$またはその逆。 したがって、実現可能性はエッジごとの独立した制約に分解され、最大化されます。$R_1$その直近のエッジのみに依存します。 すべてのエッジが少なくとも 1 つの有効な整数半径を許可すると、いつでも割り当てることができます。$R_i = 1$みんなのために$i \ge 2$、と設定します$R_1$下流の制約に影響を与えることなく、最大許容値で動作します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    x = []
    y = []
    for _ in range(n):
        xi, yi = map(int, input().split())
        x.append(xi)
        y.append(yi)

    def dist2(i):
        dx = x[i] - x[i+1]
        dy = y[i] - y[i+1]
        return dx*dx + dy*dy

    # check feasibility
    for i in range(n - 1):
        d2 = dist2(i)
        if d2 < 4:
            # distance < 2 means no integer radius >= 1 works
            if d2 == 1:
                print(-1)
                return

    # compute answer from first edge
    dx = x[0] - x[1]
    dy = y[0] - y[1]
    d2 = dx*dx + dy*dy

    # since d >= 2, sqrt(d2) is integer only in axis-aligned case
    # but we only need floor(sqrt(d2)) - 1
    # here distances are integer but can be sqrt(2), sqrt(5), etc.
    # radius must be integer < sqrt(d2)
    import math
    d = math.isqrt(d2)
    if d * d == d2:
        # perfect square distance
        d_exact = d
    else:
        # non-perfect square, actual sqrt is between d and d+1
        d_exact = math.sqrt(d2)

    # correct integer result is floor(sqrt(d2)) - 1
    print(math.isqrt(d2) - 1)

if __name__ == "__main__":
    solve()
```このソリューションはすべての座標を読み取り、連続するすべてのセグメントをチェックします。 実現可能条件は、距離が正確に 1 のセグメントがないことを保証することによって強制されます。これは、その頂点での整数半径が妨げられるため、唯一不可能なケースです。 

最終的な答えは最初のセグメントのみに依存します。 半径は距離よりも厳密に小さい整数であるため、最大整数は、最初の 2 点間のユークリッド距離を厳密に下回る最大の整数であり、整数の平方根を使用して計算されます。 

コードは使用します`math.isqrt`浮動小数点エラーを避けるため。 ドラフトの中間の浮動計算は実際には必要なく、概念的には平方根から 1 を引いた整数フロアに置き換えられます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isqrt

    def solve():
        n = int(input())
        x = []
        y = []
        for _ in range(n):
            xi, yi = map(int, input().split())
            x.append(xi)
            y.append(yi)

    solve()

 ## 特殊なケース

 最も脆弱なケースは、連続するペアの距離がちょうど 1 である場合です。入力の場合```
2
0 0
1 0
```二乗距離は 1 であり、すぐに失敗が引き起こされます。 アルゴリズムは、次の計算の前にこれを検出します。$R_1$、-1 を直接生成します。これは、整数の半径が満たされないという事実と一致します。$1 \le R_i < 1$。 

もう 1 つの特殊なケースは、最初のセグメントは長いが、後のセグメントが短い場合です。 例えば：```
3
0 0
100 0
100 1
```最初のエッジにより、大きな$R_1$, しかし、2 番目のエッジの距離は 1 であるため、実現可能性は失敗します。 スキャンはこれを 2 番目のセグメントで捕捉し、答えを計算する前にインスタンスを拒否することで、最初のエッジのみに基づいた誤った楽観的な出力を防ぎます。
