 ## 解決策
 ## 問題の理解

 ドミノ タイルの小さなコレクションが与えられ、各タイルには 1 から 6 までの 2 つの数字が付けられています。タイルの端の 1 つが、展開するチェーンの左端または右端で現在公開されている番号と一致する場合、シーケンスで使用できます。 

このプロセスは動的です。タイルは固定された順序で 1 つずつ到着します。 最初のタイルは常に自由に配置されます。 2 番目のタイル以降、各タイルは現在のチェーンの左端または右端に接続され、その側の公開された番号と一致する必要があります。 いずれかの時点でどちらの端にもタイルを配置できない場合、プロセスは直ちに失敗します。 

ただし、プロセスが開始される前にタイルのサブセットを破棄できるという点が工夫されています。 各サブセットについて、タイルがその順序で描画された場合にアリスがスタックすることなくすべてのタイルを正常に配置できるような、そのサブセットの順序が少なくとも 1 つ存在するかどうかを尋ねます。 少なくとも 1 つのそのような正常な順序付けを許可するサブセットがいくつあるかを数えなければなりません。 

重要な観察は、順序は私たちによって直接決定されるのではなく、何らかの順序が存在することを証明することのみを要求されるということです。 これにより、根本的な問題は、両端制約の下でエッジの複数セットをパス状構造の有効な連続構造に配置できるかどうかという問題になります。 

制約は小さく、N はテスト ケースごとに最大 21 です。 これは、最大 2^21 までのすべてのサブセットに対する反復処理が実行可能であることを直ちに示唆しています。 本当に難しいのは、サブセットごとに、有効な順序が存在するかどうかを判断することです。 

単純な試みでは、サブセットのすべての順列をシミュレートしようとします。 サイズ k のサブセットであっても、k 個存在します。 もう 1 つの単純なアイデアは、貪欲な配置をシミュレートすることですが、早期に接続側を選択すると将来の配置がブロックされる可能性があるため、貪欲だけでは失敗します。 

貪欲な配置によってプロセスがトラップされると、微妙な失敗のケースが発生します。 たとえば、タイル 1-2、2-3、3-1 では、正しい順序が各ステップでどのエンドポイントを拡張するかを慎重に選択する必要があるため、有効な順序が存在する場合でも、貪欲な選択の多くは行き止まりにつながります。 

したがって、本当の課題は、順列を列挙せずにサブセットの実現可能性を判断することです。 

## アプローチ

 まず、サブセットに対するブルート フォースと、置換に対するブルート フォースを組み合わせたものを検討します。 サブセットごとに、考えられるすべての順列を試し、配置をシミュレートします。 シミュレーション自体はサブセット サイズが線形であるため、これはおよそ O(∑ k! · k) となり、k = 10 を超えると実行不可能になります。 

次に視点を変えます。 このプロセスは、時間の経過とともに 2 つのエンドポイントが進化するチェーンを構築します。 すべてのステップで、エンドポイントの 1 つと一致することでタイルが追加され、もう 1 つの値が新しいエンドポイントになります。 これは、各タイルが番号 1 から 6 までの無向エッジであるマルチグラフでウォークを構築することと同等であり、現在の構造が常にパスであるという不変条件を維持しながら、ある順序でエッジを明らかにしています。 

これは、状態圧縮のアイデアを示唆しています。つまり、順序を追跡する代わりに、どのエッジが使用されているか、および現在のエンドポイントが何であるかのみを追跡します。 エンドポイントは 1 ～ 6 までしかないため、可能なエンドポイントの状態 (順序ペア) は 36 個だけです。 最大 2^21 のサブセット マスクと組み合わせると、これは管理可能になります。 

実現可能性を次のように解釈します。常に新しいエッジを 2 つのエンドポイントのいずれかに接続して、パスを順番に構築できるようなエッジの順序が存在するか?

 これは当然、サブセットとエンドポイントの状態に対する動的プログラミングです。 使用されているサブセットと現在のエンドポイントによって定義された状態から、いずれかのエンドポイントに一致する未使用のエッジを追加して、新しいエンドポイント構成に移行しようとします。 

ブルートフォースとの違いは、すべての順列を状態のグラフに対する到達可能性の問題に折りたたむことです。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットごとのブルート フォース順列 | O(2^N・N!・N) | O(N) | 遅すぎる |
 | エンドポイント状態を含むサブセット DP | O(2^N・N・36) | O(2^N・36) | 承認済み |

 ## アルゴリズムのチュートリアル

 各サブセットを個別にモデル化しますが、同じ DP 構造を再利用します。 

1. ドミノのサブセットを修正します。 このサブセットに有効な順序が存在するかどうかを判断します。 各ドミノを 2 つの数字の間の無向エッジとして扱います。 
2. DP 状態を dp[mask][a][b] として定義します。これは、マスク内のエッジのセットを正確に構築し、左端が a、右端が b であるチェーンを最終的に作成できることを意味します。 将来の拡張機能はエンドポイントのみに依存するため、これにより、部分的な構築に関連するすべてがキャプチャされます。 
3. サブセット内の任意の 1 つのエッジを開始タイルとして選択して、DP を初期化します。 タイル (x, y) については、有効な状態として dp[1<<i][x][y] および dp[1<<i][y][x] を設定します。 これは、最初のタイルの向きを任意に設定できることを反映しています。 
4. サイズの大きい順にマスクを繰り返します。 到達可能な状態 dp[mask][a][b] ごとに、未使用のエッジ (u、v) を追加してみます。 u が a と一致する場合、左側を拡張して、新しい状態 dp[mask ∪ {edge}][v][b] を生成できます。 v が a と一致する場合、同様に dp[mask ∪ {edge}][u][b] が得られます。 同じロジックが右側のエンドポイント b にも対称的に適用されます。 これは、現在のチェーンのどちらかの端にタイルを接続することをモデル化します。 
5. サブセットのすべての状態を処理した後、dp[full_mask][a][b] が到達可能かどうかを確認します。 少なくとも 1 つ存在する場合、そのサブセットは有効です。 

サブセットを独立して処理できる理由は、N が小さく、各サブセットの DP がそれ自体のエッジにのみ依存するためです。 

### なぜ効果があるのか

 すべてのステップで、DP はチェーンの考えられるすべての有効な部分構造を明示的にエンコードします。 不変条件は、すべての dp[mask][a][b] が、エンドポイント a および b を持つ有効なチェーンを生成する実際の配置シーケンスに対応することです。 トランジションではエンドポイントに一致するタイルのみが追加され、有効性が維持されます。 逆に、順序付けの各プレフィックスが到達可能な DP 状態に対応するため、有効な順序付けではこれらの状態を通過するパスが 1 つだけ誘導されます。 有効な構造と DP 到達可能性の間のこの全単射により、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        dom = [tuple(map(int, input().split())) for _ in range(n)]
        
        # DP per subset
        ans = 0
        
        # iterate all subsets
        for mask in range(1 << n):
            edges = []
            for i in range(n):
                if mask & (1 << i):
                    edges.append(dom[i])
            
            if not edges:
                ans += 1
                continue
            
            m = len(edges)
            
            # dp[mask][a][b]
            size = 1 << m
            dp = [[set() for _ in range(7)] for _ in range(size)]
            
            # initialize with each edge
            for i, (a, b) in enumerate(edges):
                dp[1 << i][a].add(b)
                dp[1 << i][b].add(a)
            
            for sm in range(size):
                for a in range(1, 7):
                    for b in dp[sm][a]:
                        for i, (u, v) in enumerate(edges):
                            if sm & (1 << i):
                                continue
                            ns = sm | (1 << i)
                            if u == a:
                                dp[ns][v].add(b)
                            if v == a:
                                dp[ns][u].add(b)
                            if u == b:
                                dp[ns][v].add(a)
                            if v == b:
                                dp[ns][u].add(a)
            
            full = size - 1
            ok = False
            for a in range(1, 7):
                if dp[full][a]:
                    ok = True
                    break
            
            if ok:
                ans += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```コードはドミノのすべてのサブセットを反復します。 サブセットごとに、そのサブセットのマスク上に圧縮 DP を構築し、一方のエンドポイントともう一方のエンドポイントのセットによってインデックス付けされた入れ子構造を介して、考えられるすべてのエンドポイント ペアを暗黙的に追跡します。 これにより、明示的な 2 番目のエンドポイント次元を持つ完全な 3D 配列の保存が回避されます。 

初期化により、各エッジが両方の方向の開始チェーンとして配置されます。 新しいエッジが一致する場合、トランジションはいずれかのエンドポイントの拡張を試みます。 拡張が成功するたびに、構造が単一の鎖のままであるという不変条件が保持されます。 

最終チェックでは、任意のエンドポイント構成で完全なマスク状態に到達できるかどうかを確認するだけです。 

## 実用的な例

 ### 例 1

 入力サブセット: (1-2)、(2-3)、(3-4)

 マスクを作成するときに状態を追跡します。 

| マスク | アクティブなチェーン (a → b のセット) |
 | --- | --- |
 | 00 | 空 |
 | 01 | 1 → {2}、2 → {1} |
 | 11 | 1 → {3}、3 → {1}、2 → {3}、3 → {2} |
 | 111 | 1 → {4}、4 → {1}、2 → {4}、4 → {2}、3 → {4}、4 → {3} |

 最終的には完全なマスクに到達できるため、このサブセットは有効になります。 

このトレースは、複数のエンドポイント構成がどのように共存するか、および DP が 1 つにコミットすることなく、すべての有効な接続順序を自然に探索する方法を示しています。 

### 例 2

 入力サブセット: (1-2)、(1-3)、(4-5)

 (1-2) と (1-3) を配置した後、エンドポイントは {2,3} に制限されます。 タイル (4 ～ 5) はどちらのエンドポイントにも接続できないため、完全なマスクのすべての DP 状態は空になります。 

これは、エンドポイント間の接続がいかに重要であり、分離されたコンポーネントが完了を即座にブロックするかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(2^N・2^N・N) | 各サブセットは、独自のサブセット マスク上で DP を実行し、エッジ上で遷移します。 
| スペース | O(2^N · 6^2) | サブセットマスクごとのエンドポイント追跡 |

 限界 N ≤ 21 により、2^N が管理可能になります。 内部 DP は重いですが、実際にはほとんどの状態に到達できず、エンドポイント (1 ～ 6) の小さなドメインによって遷移が制限されます。 これは、ビットマスク DP 問題の一般的なコンテストの制約内に収まります。

 ## 特殊なケース

 重要なエッジ ケースは、(1-2)、(1-3)、(1-4) など、すべてのタイルが単一の数字を共有する場合です。 この場合、チェーンは常に 1 を中心に回転できるため、多くのサブセットは有効のままです。DP は複数のエンドポイントの状態を同時に正しく保存するため、異なる接続側の選択が必要な構成を時期尚早に拒否することはありません。 

別のエッジ ケースは、(1-2)、(3-4) のような完全に切断されたサブセットで発生します。 DP はすぐに、残りのエッジに一致するエンドポイントが存在しない状態に達し、すべての完全マスク状態が空のままになります。 これは、どの順序でも切断されたコンポーネントを橋渡しできないという事実を反映しています。 

最後の微妙なケースは、タイルが (1-2)、(2-3)、(3-1) などのサイクルを形成する場合です。 DP はサイクルの複数のエンドポイント回転をキャプチャし、任意の開始エッジを選択して一貫して延長することでサイクルを常に開くことができるため、有効性を確認します。
