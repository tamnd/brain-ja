 ## 解決策
 ## 問題の理解

 無向単純グラフの最終状態が与えられます。$N$都市。 このグラフはもともとこの形式で作成されたものではないと言われています。 代わりに、それは同じ木として始まりました$N$頂点。 その後、変換が適用されます。元のツリーで 2 つの頂点に正確に 2 つのエッジのパスがある場合は常に、それらの 2 つの端点の間に新しい直接エッジが追加されます。 

したがって、追加されたすべてのエッジは、元のツリーの長さ 2 のパスに対応し、そのようなペアはすべて、最終的なグラフでは 1 つの新しいエッジによって接続されます。 元の木の端は決​​して削除されませんでした。 

タスクは、指定されたグラフがこの方法で生成されたかどうかを判断し、生成された場合は有効な元のツリーを再構築することです。 

制約により、最大で$10^5$頂点と$4 \cdot 10^5$エッジ。 すべての候補ツリーをテストしたり、ノードのペアに対して直接変換をシミュレートしたりするソリューションは、すべての頂点のペアをチェックするだけですでに問題が発生してしまうため、直ちに不可能です。$O(N^2)$、限界をはるかに超えています。 私たちは、「ツリーとすべての距離 2 の接続」として現れるグラフの構造的特徴付けを余儀なくされています。 

微妙な問題は、複数のツリーが同じ最終グラフを生成する可能性があることです。 オリジナルを一意に見つけることは求められていません。有効なオリジナルを見つけることだけが求められます。 

いくつかの特殊なケースが重要です。 

最終的なグラフがすでにツリーである場合は、正確に$N-1$エッジ。 その場合、距離 2 の加算はエッジ数を増加させるため、適用できませんでした。 したがって、考えられる唯一の元のツリーはグラフ自体です。 入力にそれ以上の値が含まれている場合、$N-1$エッジはあるものの、いくつかのエッジを削除した後でもツリー構造を形成します。「ツリーの意味が有効である」と仮定する素朴なアプローチは、余分なエッジが異なる構造的意味を持つ可能性があるため失敗します。 

最終的なグラフのノードの次数が 1 である場合、それは元のツリーの葉でもある必要があります。 それ以外の場合は、一意の近傍を介して距離 2 の接続が少なくとも 1 つ生成され、次数が 1 を超えて増加します。 

最後に、任意のグラフを選択して、それを「ツリーと距離 2 の閉包」として解釈しようとすると、ツリー構造と一致しないサイクルが発生すると、すぐに実現可能性が損なわれます。 たとえば、三角形$1-2-3-1$追加の構造がない場合は有効に見えるかもしれませんが、3 つのノードのツリーからは得られません。3 つのノード上のツリーは追加のエッジを 1 つだけ生成し、単一のサイクルではなく完全なグラフを生成するためです。 

## アプローチ

 強引なアイデアは、元のツリーを直接再構築してみることです。 スパニング ツリーを推測し、そのツリー内の距離 2 のペア間のすべてのエッジを追加すると、指定されたグラフが正確に得られるかどうかを確認することもできます。 これは概念的には簡単です。候補ツリーを選択し、距離 2 にあるすべてのペアを計算し、結果として得られるエッジを生成し、入力と比較します。 

問題は、可能な木の数です。 がある$N^{N-2}$ラベル付きの木なので列挙することは不可能です。 ルートを修正して親の割り当てを試みても、指数関数的な分岐が発生します。 さらに悪いことに、単一の候補を検証するには、すべての距離 2 ペアを計算する必要があります。$O(N)$密な隣接形式のノードごとに、$O(N^2)$合計で。 

重要な観察は、変換が非常に厳格な構造を持っているということです。 あらゆるオリジナルのエッジ$(u,v)$近傍の重なり方を除いて、最終的なグラフに直接信号は作成されません。 特に、最終的なグラフでは、2 つの頂点が元のツリーで隣接しているか、ツリー内で共通の隣接点を共有している場合にのみ隣接します。 

これはまさに樹形図の二乗です。 したがって、問題は、指定されたグラフが何らかのツリーの二乗であるかどうかを認識し、そのツリーを再構築することになります。 

よく知られている構造上の事実は、ツリー-スクエア グラフでは、慎重に選択された中心からの BFS 階層化を使用して、頂点を「コア構造」によってグループ化できることです。 ツリー内の葉は非常に特徴的な方法で動作します。つまり、それらはまさに頂点であり、その近傍は、その固有の隣接ツリーの近傍のサブセットに加えて、その近傍自体を加えたものになります。 

これは、貪欲なピーリング アプローチを示唆しています。つまり、元のツリーの葉と一致する近傍構造を持つ頂点を繰り返し識別し、それを削除し、エッジを逆方向に再構築します。 

有効な正方形グラフでは、最終グラフの閉じた近傍が元のツリーの単一の親に接続されていると「説明」できる頂点が常に存在するという考えを使用して、これを形式化できます。 

このような頂点を繰り返し削除することで、ツリーを逆に復元できます。

 ## アルゴリズムのチュートリアル

 最終的なグラフに完全に取り組み、それを生成した可能性のあるツリーを徐々に再構築します。 

## 1. 隣接関係セットを構築する

 近隣の包含を迅速にテストできるように、隣接関係リストをハッシュ セットとして保存します。 近傍間のサブセット関係を頻繁にチェックするため、これは重要です。 

## 2. 頂点次数を計算する

 進化するグラフ表現において現在の度数を維持します。 元のツリーの葉は、最終的なグラフの特殊な低構造頂点に対応します。 

## 3. 候補リーフノードを特定する

 近隣の頂点からそれ自体を差し引いた頂点が、他の 1 つの頂点で一貫した方法でカバーできる頂点を探します。 具体的には頂点$v$隣接するものが存在する場合、削除可能とみなされます$u$すべての隣人が$v$最終的なグラフは次のいずれかです$u$または隣接する$u$。 これは、次のような考えをコード化しています。$v$に付いていた葉っぱでした$u$元のツリーと、それに関係する他のすべてのエッジ内$v$距離から来る - 2 つの接続を介して$u$。 

このステップは、ツリーの誤った推測を防ぐための中核となるフィルタリング メカニズムです。 

## 4. 頂点を繰り返しピーリングします

 削除可能な頂点のキューを維持します。 キューが空ではない間に頂点を削除します$v$、その親を修正します$u$、およびレコードエッジ$(u, v)$再構築されたツリーの一部として。 

取り外し後$v$、隣接構造が変更されたため、影響を受ける近隣を更新します。 

## 5. 完了の検証

 最後に、正確に次のようにする必要があります。$N-1$記録されたエッジ。 そうしないと、再構築が失敗し、不可能が出力されます。 それ以外の場合は、記録された木のエッジを出力します。 

## なぜ機能するのか

 不変条件は、各ステップにおいて、有効な元のツリーの葉に対応する頂点が、正方形グラフの現在誘導されたサブグラフ内で識別可能なままであるということです。 正しいリーフを削除しても、残りの構造を完成させる可能性は失われません。これは、ツリーの正方形のプロパティがリーフの削除の下で遺伝するためです。ツリーからリーフを削除することは、正方形グラフ内の隣接関係がその親によって完全に決定される頂点を削除することに対応します。 したがって、グラフが有効であれば、常に少なくとも 1 つの削除可能な頂点が存在し、ピーリングがスタックすることはありません。 早期にスタックした場合、どのツリーもグラフを生成できなかった可能性があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [set() for _ in range(n)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].add(v)
        adj[v].add(u)

    deg = [len(adj[i]) for i in range(n)]
    alive = [True] * n

    from collections import deque
    q = deque()

    def is_removable(v):
        # try to find a parent u
        for u in adj[v]:
            if not alive[u]:
                continue
            ok = True
            for w in adj[v]:
                if w == u:
                    continue
                # w must be adjacent to u
                if u not in adj[w]:
                    ok = False
                    break
            if ok:
                return u
        return -1

    for i in range(n):
        u = is_removable(i)
        if u != -1:
            q.append(i)

    parent = [-1] * n
    order = []

    while q:
        v = q.popleft()
        if not alive[v]:
            continue
        u = is_removable(v)
        if u == -1:
            continue

        alive[v] = False
        parent[v] = u
        order.append((u, v))

        for w in adj[v]:
            if alive[w]:
                # structure changes conceptually; we keep adjacency static but rely on alive checks
                pass

    if len(order) != n - 1:
        print("*")
        return

    for u, v in order:
        print(u + 1, v + 1)

def main():
    solve()

if __name__ == "__main__":
    main()
```この実装では隣接構造が固定されたままになり、`alive`削除をシミュレートする配列。 キー操作は、`is_removable`、近傍包含条件をチェックして、元のツリーの親として機能できる近傍を検索します。 

よくある落とし穴は、削除時に隣接リストを更新することです。 これはここでは不要であり、ソリューションが大幅に複雑になります。 代わりに、チェック中に非アクティブなノードを単純に無視します。 

もう 1 つの微妙な点は、キューからポップするときに削除可能性を再チェックしていることです。 これにより、近傍が削除された後に頂点が有効でなくなる可能性があるため、古くなった候補が回避されます。

 ## 特殊なケース

 星型の元のツリーは、この変換下でも安定します。 中心はすべてのリーフに接続され、最終的なグラフではすべてのリーフがペアで接続されます。 すべての葉がすぐに削除できるため、アルゴリズムはこれを処理します。各葉には有効な親候補が 1 つあり、それらを 1 つずつ剥がすと中央が最後に残ります。 

縮退のケースは、グラフがすでに完成している場合に発生します。 その場合、すべての頂点は他のすべての頂点に隣接するため、多くの選択肢について近傍包含チェックが成功します。 削除可能性が有効なツリー構造に正しく折りたたまれ、通常は一貫した再構築としてスターが生成されるため、アルゴリズムは引き続き機能します。 

単一のツリー親構造ではすべてを説明できない一貫性のない三角形がグラフに含まれている場合、失敗ケースが発生します。 このような場合、削除可能条件は最終的にすべての頂点で失敗し、キューが早期に空になります。 これは、元のツリーが観察されたクロージャを生成できないことを示す信号です。
