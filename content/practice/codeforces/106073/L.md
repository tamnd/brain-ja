 ## 解決策
 ## 問題の理解

 与えられた要素は 3 つです。各単語が固定の 2D 整数ベクトルを持つ単語の辞書、参照コーパスとして機能する長いテキスト、および一連のクエリです。 各クエリは短い単語のシーケンスで終わり、簡略化された言語モデルを模倣したルールに従って次の単語を予測する必要があります。 

クエリの場合、その最後の K ワードをコンテキスト ウィンドウとして受け取ります。 ナレッジ ベースのテキスト全体をスキャンし、これらの K 個の単語が同じ順序で連続して出現するすべての位置を探します。 このような一致が見つかるたびに、その出現の直後に続く単語を記録します。 これらの記録された単語は複数の候補セットを形成します。 

少なくとも 1 つの候補が見つかった場合は、そのベクトルとすべての候補ベクトルの間の内積を合計することによって、各辞書単語 d にスコアを付けます。 辞書に存在しない候補単語はゼロ ベクトルとして扱われます。つまり、スコアにはまったく寄与しません。 次に、最大スコアを持つ辞書の単語を選択し、辞書の順序で前に出現する単語を優先して関係を解消します。 

微妙な点は、K が実際にはクエリごとに固定されていないことです。 K の長さのコンテキスト全体で一致が見つからない場合は、K を 1 つ減らして再試行し、少なくとも 1 つの一致が見つかるか K = 1 に達するまで繰り返します。K = 1 でも一致が得られない場合、予測は失敗し、アスタリスクが出力されます。 

制約は小さく、N、M は最大 1000、Q は最大 10 です。これは、サフィックス オートマトンや高度なインデックス構造などの漸近的な最適化手法を気にせずに、クエリごとにテキストを繰り返しスキャンし、それぞれの削減された K を実行できることをすぐに示唆しています。 総作業量はおよそ Q × K × M に制限されており、十分に小さいです。 

主な失敗例は、これらの動作の 1 つを忘れたことが原因です。 よくある間違いの 1 つは、K を減らすときに検索を再開しないことです。もう 1 つは、未知の候補単語をゼロ ベクトルとしてではなく、存在しないものとして誤って処理することです。これにより、スコアリングの動作が微妙に変化します。これは、単語はまだ収集されるべきであるものの、何も貢献しないためです。 3 番目の間違いは、タイブレークの処理を誤ることです。これは、単語の辞書順ではなく、辞書順が唯一のルールであるためです。 

## アプローチ

 直接的な解決策は、問題の説明を正確にシミュレートします。 

各クエリおよび考えられるコンテキスト長 K ごとに、ナレッジ ベースをスキャンし、すべての位置をチェックして、次の K 語がクエリ サフィックスと一致するかどうかを確認します。 一致するものが見つかった場合、次の単語を候補として記録します。 スキャン後、少なくとも 1 つの候補を収集した場合は、候補ベクトルに対する内積を合計することによってすべての辞書単語のスコアを計算し、最適なベクトルを選択します。 候補が存在しない場合は、K をデクリメントして繰り返します。 

構造がフラットであるため、この強引なアプローチはすでに十分です。知識ベースは単なるシーケンスであり、パターンは短く (K ≤ 5)、クエリの数は少ないです。 最悪のケースでは、クエリごとに最大 K 個の値をチェックし、毎回 M 単語をスキャンし、O(N) スコアリングを実行しますが、それでも十分に制限内です。 

重要な点は、前処理が必要ないということです。 この問題は、サフィックス構造を構築するよりも線形スキャンを繰り返す方が低コストになるように設計されており、スコアリングのステップは非常に小さな固定次元 (2D ベクトル) に対する線形代数であるため、定数が低く抑えられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シミュレーション | O(Q・K・M・K+Q・N・K) | O(N + M) | 承認済み |
 | 最適化されたインデックス作成 | 必要ありません | 必要ありません | やりすぎ |

 ## アルゴリズムのチュートリアル

 各クエリを個別に処理します。

1. クエリの最後の K ワードを抽出します。 これらは、ナレッジ ベースで照合しようとしているパターンを形成します。 
2. K から 1 までの現在のコンテキスト長 L を試します。L ごとに、クエリの最後の L ワードを取得し、ナレッジ ベースをスキャンします。 
3. ナレッジ ベースをスキャンしているときに、i + L が範囲内にあるようにすべてのインデックス i をチェックします。 Words[i : i+L] がコンテキストと正確に一致する場合、words[i+L] を候補として記録します。 
4. 固定 L のスキャンを終了した後、少なくとも 1 つの候補が見つかった場合は、L の減少を停止し、スコアリングに進みます。 候補が存在しない場合は、L を 1 つ減らして繰り返します。 
5. 候補が見つからずに L = 0 に達した場合は、元のクエリの後にアスタリスクが出力されます。 
6. それ以外の場合、すべての候補を反復処理して、すべての辞書単語 d のスコアを計算します。 各候補は、そのベクトルと d のベクトルの間の内積に寄与します。ただし、候補の単語が辞書にない場合、そのベクトルは (0, 0) として扱われ、何も寄与しません。 
7. 最大スコアを持つ辞書単語を選択します。 複数の単語が同点の場合は、辞書インデックスが最も小さい単語が選択されます。 

正確さは、考えられるすべての有効なコンテキストの出現が明示的に検査され、スコアリングが固定ベクトルの決定論的な集計であるという事実から得られます。 近似やヒューリスティックはなく、徹底的なマッチングと線形累積のみです。 タイブレーク ルールは、純粋に辞書を順番にスキャンし、これまでに見られた最良のものを維持することによって処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    idx = {}
    words = []
    vec = []

    for i in range(n):
        parts = input().split()
        w = parts[0]
        x = int(parts[1])
        y = int(parts[2])
        idx[w] = i
        words.append(w)
        vec.append((x, y))

    m = int(input())
    kb = []
    while len(kb) < m:
        kb.extend(input().split())
    kb = kb[:m]

    q, K = map(int, input().split())

    for _ in range(q):
        parts = input().split()
        F = int(parts[0])
        query = parts[1:]

        found_candidates = None
        used_L = 0

        for L in range(K, 0, -1):
            if F < L:
                continue

            pattern = query[F - L:]
            candidates = []

            for i in range(m - L):
                if kb[i:i+L] == pattern:
                    candidates.append(kb[i+L])

            if candidates:
                found_candidates = candidates
                used_L = L
                break

        if not found_candidates:
            print(" ".join(query + ["*"]))
            continue

        scores = [0] * n

        for c in found_candidates:
            if c in idx:
                cx, cy = vec[idx[c]]
                for i in range(n):
                    dx, dy = vec[i]
                    scores[i] += dx * cx + dy * cy

        best = 0
        for i in range(1, n):
            if scores[i] > scores[best]:
                best = i

        print(" ".join(query + [words[best]]))

solve()
```辞書は、順序付けのためのリストとして、また素早いベクトル検索のためのマップとして保存されます。 ナレッジ ベースは 1 つのリストにフラット化されているため、直接スキャンできます。 クエリごとに、コンテキストの長さを減らし、総当たりの部分文字列比較によって候補を収集します。これは、制約が小さい場合には十分に効率的です。 

スコアリング ステップでは、欠落している単語が辞書マップにない場合はスキップすることで、それらの単語を明示的にゼロ ベクトルとして扱います。 

タイブレークは、インデックスを左から右にスキャンし、厳密に大きいスコアが見つかった場合にのみ更新することによって自然に処理されます。 

## 実用的な例

 単純なベクトルと短いテキストを持つ辞書の単語を含む小さなシナリオを考えてみましょう。 ナレッジ ベース内に複数回出現する語句で終わるクエリについては、候補がどのように収集され、スコアがどのように蓄積されるかを調べます。 

| ステップ | アクション | 候補者 |
 | --- | --- | --- |
 | L = K | フルコンテキストをスキャン | なし |
 | L = K-1 | 縮小されたコンテキストをスキャン | ["単語A", "単語B"] |
 | スコア | 内積の合計 | 最適なものを選択してください |

 このトレースは、正確なコンテキストは失敗したが、より短いコンテキストは成功した場合のフォールバック メカニズムを示しています。 

正確なコンテキストが存在する別のケースでは、削減の必要性がわかりません。 

| ステップ | アクション | 候補者 |
 | --- | --- | --- |
 | L = K | 一致が見つかりました | ["x", "y", "z"] |
 | スコア | スコアをすぐに計算する | 最終予想 |

 これは、アルゴリズムが常に最も長く一致するコンテキストを優先することを確認します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、長さ K の部分文字列が知識ベースに存在しないが、より短い部分文字列は存在する場合です。 たとえば、K = 3 であるが、K = 2 の一致のみが存在する場合、アルゴリズムは、L = 2 のスキャンを正しく再開し、途中で中止してはなりません。 ループ構造は明示的に下方向に継続し、この動作を保証します。 

もう 1 つのケースは、候補単語が辞書にない場合です。 その状況でも、候補コレクションには参加しますが、ゼロ ベクトルを提供します。 これは、スコアにまったく影響を与えるべきではないことを意味し、実装では検索をスキップし、寄与を追加しないことで保証します。 

最後のエッジケースはタイブレークです。 2 つの辞書の単語が同じスコアで終わる場合は、前の辞書エントリのみを選択する必要があります。 これは、インデックスを順番にスキャンし、厳密に改善された場合にのみ更新し、最初に発生した最大スコアを保持することによって処理されます。
