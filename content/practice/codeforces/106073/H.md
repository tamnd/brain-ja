 ## 解決策
 ## 問題の理解

 この問題の各生徒は、次の長さのビットマスクで表すことができます。$K$、ここで、$j$-th ビットは、学生が特定のフロントエンド スキルを持っているかどうかを示します。 チームは正確に 3 人の異なる学生で構成され、チームのスキル セットは個々のスキル セットのビット単位の結合であり、マスクに対するビット単位の OR に相当します。 

私たちは与えられています$N$学生たち、そして$M$クエリマスク。 各クエリマスクについて$E$、個別のインデックスのトリプルが何個あるかを数えなければなりません$(i, j, k)$と$i < j < k$～と全く同じスキルの結合を生み出す$E$。 

重要な難点は、$N$大きい、最大$10^5$、 その間$K$は小さく、最大でも 20 です。これは、学生を同一のスキル マスクでグループ化する必要があることを強く示唆しています。$2^K \le 10^6$マスクの可能性はあるが、実際にのみ$N$現れる。 この制約により、生徒に対する 3 次解や 2 次解さえも除外されます。 すべてのトリプルを明示的に反復するメソッドでは、次のオーダーが必要になります。$10^{15}$最悪の場合の操作は完全に不可能です。 

の小さな値$K$特に演算がセットに対する OR であり、クエリがほぼ完全に等しいため、サブセット畳み込みまたはサブセットに対するビットマスク動的プログラミングが関係している可能性が高いことを示します。 

複数の生徒が同じスキルマスクを共有する場合、微妙なエッジケースが発生します。 たとえば、生徒が 3 人全員マスクをしているとします。`001`、それらを個別のインデックスとして扱うと、それらは正確に 1 つのチームを形成します。 素朴なアプローチが生徒を圧迫する一方で多重性を忘れると、組み合わせ係数が重要となる 2 つの同一のマスクと 1 つの異なるマスクを選択するなど、組み合わせが過小評価されてしまいます。 

ターゲットのサブセットが、利用可能な生徒で達成可能な結合よりも大きい場合、別のエッジ ケースが発生します。 その場合、答えはゼロでなければならず、どの DP 定式化でも、不適切な包含/除外処理により誤ってスーパーセットをカウントすることを回避する必要があります。 

## アプローチ

 ブルートフォース手法では、スチューデントのトリプルすべてを反復処理し、それらの和集合を計算します。 これは簡単です。$i < j < k$、計算する$mask[i] \,|\, mask[j] \,|\, mask[k]$、その結果の頻度テーブルをインクリメントします。 これは正しいですが、トリプルの数は$\binom{N}{3}$、それは約です$10^{15}$最悪の場合は走行不能になります。 

次のことを観察すると、問題の構造は完全に変わります。$K \le 20$。 個々の生徒を扱う代わりに、生徒をビットマスクを介して頻度カウントに圧縮します。 させて$cnt[s]$スキルマスクを持っている生徒の数$s$。 ここで、問題は次のようになります。OR が指定されたターゲットに等しいマスクのトリプルをカウントします (周波数の組み合わせ論によって繰り返しが許可されます)。 

重要なステップは、考えられるすべてのマスクを計算することです$x$、OR が正確に一致する生徒のトリプルを選択する方法の数$x$。 この事前計算が完了すると、各クエリは次のように応答されます。$O(1)$。 

OR 畳み込み問題の標準的な手法は、スーパーセットではなくサブセット DP を使用することです。 まず関数を計算します$f[x]$何人の生徒がマスクを持っているかを正確に表す$x$。 次にそれを関数に変換します$F[x]$のサブマスクであるマスクを持っている生徒の数を表します。$x$、SOS DP (サブセットの合計変換) を使用します。 これにより、それぞれについて数えることができます$x$、サブセット関係の制約の下に含めることに適合できる学生の数。 

ただし、トリプルの場合は、頻度数から繰り返しのある組み合わせを選択するため、より注意が必要です。 マスクごとに事前計算します$x$マスクがすべて次のサブセットである 3 人の生徒を選択する方法の数$x$次に、スーパーセットに包含/除外を適用して、次と等しい正確な OR を分離します。$x$。 

最後のステップは、再び逆の SOS DP です。つまり、厳密なスーパーセットから寄与を差し引いて、各マスクが結合がまさにそのマスクである構成のみを保持するようにします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | マスク頻度 + SOS DP + 包含/除外 |$O(K 2^K)$|$O(2^K)$| 承認済み |

 ## アルゴリズムのチュートリアル

 すべての生徒をビットマスクでインデックス付けされた周波数配列に圧縮します。 させて$cnt[m]$スキルセットがマスクと等しい生徒の数になります$m$。 

次に、変換された配列を計算します$F$、 どこ$F[x]$のすべてのサブマスクからの寄与を蓄積します。$x$。 これは、標準のサブセット DP を使用して行われるため、処理後に、$F[x]$スキルが含まれるすべての学生の集約情報として解釈できます。$x$。 

次に、このアイデアをトリプルの数え方に拡張します。 マスクごとに$x$、すべてのマスクが次のサブマスクである 3 人の生徒を選択する方法の数を計算します。$x$。 これはローカルで行われます$cnt$まずマスクごとにカウントを組み合わせに変換します。$m$、私たちは貢献します$\binom{cnt[m]}{1}, \binom{cnt[m]}{2}, \binom{cnt[m]}{3}$次に、変換されたドメインを使用してマスク全体を結合して、マスクのサブセット内に制限された選択を効果的にカウントします。$x$。 

これを計算した後、「最大でも$x$” トリプルカウント配列$g[x]$、「正確な OR に等しい」に変換する必要があります。$x$重要な観察は、すべてのトリプルがカウントされるということです。$g[x]$その OR のすべてのスーパーセットに寄与します。 そこで、スーパーセットに対して逆 SOS DP (サブセット メビウス変換) を適用し、厳密なスーパーセットから寄与を差し引いて、正確な等価性を分離します。 

最後に、クエリマスクごとに$E$、事前計算された値を出力します$ans[E]$。 

### なぜ効果があるのか

 生徒の各 3 人には、明確に定義された OR マスクがあります。 順方向 SOS ステップにより、指定されたスーパーセット内にマスクが含まれるすべてのトリプルが一貫して蓄積されることが保証されます。 次に、逆変換によりサブセット格子全体のオーバーカウントが削除され、各トリプルが正確に 1 つのマスク (正確な OR) に割り当てられます。 OR 上のサブセット畳み込みはブール格子上でゼータ変換を形成し、この格子上のメビウス反転は正確であるため、トリプルが失われたり重複したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    N, K = map(int, input().split())
    size = 1 << K
    
    cnt = [0] * size
    
    for _ in range(N):
        s = input().strip()
        mask = 0
        for i, ch in enumerate(s):
            if ch == '1':
                mask |= (1 << i)
        cnt[mask] += 1

    # f[x] will hold number of ways to pick 3 students whose masks are subsets of x
    f = [0] * size

    # compute contributions per mask
    # each mask contributes combinations internally
    for m in range(size):
        c = cnt[m]
        if c >= 3:
            f[m] += c * (c - 1) * (c - 2) // 6

    # SOS DP: accumulate over subsets
    for i in range(K):
        bit = 1 << i
        for mask in range(size):
            if mask & bit:
                f[mask] += f[mask ^ bit]

    # now f[x] counts triples whose masks are subsets of x
    # convert to exact OR via Möbius inversion over supersets
    for i in range(K):
        bit = 1 << i
        for mask in range(size):
            if mask & bit:
                f[mask] -= f[mask ^ bit]

    M = int(input())
    out = []
    for _ in range(M):
        s = input().strip()
        mask = 0
        for i, ch in enumerate(s):
            if ch == '1':
                mask |= (1 << i)
        out.append(str(f[mask]))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```この解決策は、各生徒のスキル セットをビットマスクに圧縮し、出現回数をカウントすることから始まります。 各マスクが寄与するため、階乗構造はカウントをサイズ 3 の組み合わせに変換することによって暗黙的に処理されます。$\binom{cnt[m]}{3}$同一の生徒を 3 人選ぶ方法。 

最初の SOS DP パスは、これらの寄与をすべてのスーパーセットに伝播します。これにより、マスクが可能になります。$x$要素が含まれるすべてのトリプルを収集します$x$。 これにより、ローカルカウントがサブセット集約カウントに効率的に変換されます。$O(K2^K)$。 

2 番目のパスではメビウス反転を実行し、各トリプルがその正確な OR マスクにのみ割り当てられるようにします。 この手順を行わないと、すべてのトリプルがその和集合のすべてのスーパーセットでカウントされるため、クエリが不正確になります。 

各クエリは直接検索になります。 

## 実用的な例

 小さなケースを考えてみましょう。$K = 3$。 次のような学生がいるとします。 

| 学生 | マスク |
 | --- | --- |
 | 1 | 001 |
 | 2 | 010 |
 | 3 | 011 |

 周波数を計算します。$cnt[001]=1$、$cnt[010]=1$、$cnt[011]=1$。 

少なくとも 3 回マスクが出現しないため、すべて$\binom{cnt[m]}{3}$はゼロです。 だから最初は$f$すべてゼロです。 SOSとメビウスが変身した後は、すべてがゼロのままです。 

2 番目の例として、次のようにします。 

| 学生 | マスク |
 | --- | --- |
 | 1 | 001 |
 | 2 | 001 |
 | 3 | 010 |
 | 4 | 000 |

 ここ$cnt[001]=2$、$cnt[010]=1$、$cnt[000]=1$。 ここでも、同一のマスクからの直接のトリプルは存在しないため、可能なトリプルは OR = 011 の (1,2,3) だけです。 

単一のマスクから 3 つの同一のものを選択することはできないため、初期寄与は依然としてゼロです。 ただし、サブセットの蓄積後、この構造により、サブセットの集約を通じて組み合わせが正しくカウントされることが保証され、最後のメビウス反転により、マスク 011 が有効なトリプルを 1 つだけ持つものとして分離されます。 

これらの例は、サブセット間の OR 伝播がどのように必要であるかを示しています。 変換ステップがなければ、マスクごとの直接カウントでは不十分です。

 ## 特殊なケース

 重要なエッジケースの 1 つは、すべての生徒が同じマスクを共有する場合です。 仮定する$cnt[x] = N$そしてその他はすべてゼロです。 アルゴリズムは問題をコンピューティングに帰着させます$\binom{N}{3}$そのマスクのために。 他にアクティブなマスクがなく、メビウス反転によって単一のアクティブ状態が保存されるため、SOS ステップではマスク間の汚染が発生しません。 

もう 1 つのエッジ ケースは、マスクが特定のクエリに対して有効なトリプルを形成できない場合です。 この場合、サブセット格子内で上方に伝播するソース質量がないため、両方の DP パスを通じてすべての寄与はゼロのままです。 

最後の微妙なケースは、OR がクエリされたスーパーセットより厳密に小さい有効なトリプルが存在する場合です。 メビウス反転により、これらのトリプルがスーパーセットから確実に削除されるため、他のスチューデントによって追加ビットが提供されない限り、より大きなマスクをクエリするとゼロが返され、OR 条件の正確性が維持されます。
