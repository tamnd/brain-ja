 ## 解決策
 ## 問題の理解

 すべての係数が 0 または 1 である多項式が与えられているため、多項式は x のべき乗のセットとして考えるのが最適です。 の係数が$x^k$が 1 の場合はその項を含めますが、それ以外の場合は含めません。 多項式は、定数項が存在するかどうかのみに応じて 2 つの演算のうち 1 つを繰り返し適用する決定論的なプロセスを通じて展開されます。 

定数項が存在する場合、多項式は次の値を乗算することによって変換されます。$x+1$、次に 1 を追加し、最後に 2 に等しい係数が削除されるように単純化します。 係数が 2 を超えることはないため、この単純化により、項が 2 回出現する衝突が効果的に解決されます。 定数項が存在しない場合、演算ははるかに単純になります。多項式を x で除算します。これは、すべての指数を 1 ずつ下にシフトすることに相当します。 

このプロセスは、多項式が正確に 1 になるまで繰り返されます。つまり、定数項のみが残り、高次の項は存在しません。 

主な難点は、各ステップで多項式の構造が非線形に変化することです。 乗算$x+1$どちらも既存の項をシフトおよび混合し、追加の「キャンセル付き +1」により定数項に相互作用が導入され、単純な単調性の引数が破壊されます。 

制約は小さく、初期次数は最大 20 であるため、多項式は最大 21 ビットにわたるビットマスクとして表現できます。 プロセスがすぐに縮小することは保証されていませんが、状態空間は十分小さいため、各ステップがビット操作を使用して効率的に実装されている限り、変換の直接シミュレーションが可能です。 

微妙なエッジ ケースは、多項式がすでに 1 である場合です。この場合は、演算を実行する必要はありません。 もう 1 つのエッジ ケースは、乗算を繰り返すと初期範囲よりも高次の項が作成される場合です。そのため、オーバーフロー処理なしで長さ 21 の固定サイズ配列を想定する実装では、暗黙のうちに項が削除されたり、不正なインデックスが付けられたりします。 3 番目の問題は、「係数 2 を破棄する」ルールの誤解です。このルールは、グローバルに 2 を法とする算術演算ではなく、乗算と加算による寄与を組み合わせた後でのみ事実上キャンセルされます。 

## アプローチ

 ブルート フォース アプローチはまさにこのステートメントで説明されているとおりです。多項式を明示的に表し、多項式の乗算を次のように実行します。$x+1$、1を追加し、すべての係数をスキャンして任意の2を0に戻すか、定数項がない場合は右にシフトします。 それぞれの操作にかかる費用$O(n)$どこ$n$現在の学位です。 変換の次数は増減する可能性があり、迅速な収束を保証する明らかな単調な可能性がないため、プロセスには多数のステップが必要になる場合があります。 最悪の場合、単純な多項式演算で実装すると、多くの中間構成を段階的にシミュレートすることが非効率になります。 

重要な点は、係数がバイナリであるため、多項式をビットマスクとして表現でき、すべての演算がビットごとの変換になるということです。 乗算$x$は左シフトであり、加算は XOR に相当します。 これにより、プロセス全体が整数上のステート マシンに変換されます。 このように書くと、各ステップは次のようになります。$O(1)$ビット演算を実行し、1 に達するまで単純にシミュレーションします。与えられた制約に対して、実際には多項式が数十ビットを超える意味のある大きさになることはないため、状態空間は小さく、シミュレーションでは収束がすぐに起こります。

 ## アルゴリズムのチュートリアル

 多項式を整数としてエンコードします。ビット i は次の存在を表します。$x^i$。 

1. 入力多項式を読み取り、そのビットマスク表現を構築します。 各係数 1 は対応するビットを設定します。 これにより、代数シフトがビット シフトになるコンパクトなエンコーディングが得られます。 
2. ビットマスクが 1 になるまで繰り返します。値 1 は、定数項のみを含む多項式に対応します。 
3. 現在のビットマスクに最下位ビットが設定されている場合は、「(x+1) を乗算して 1 を加算する」演算を適用します。 ビット用語で言えば、GF(2) のようなキャンセル動作に対する (x+1) の乗算は次のようになります。`mask XOR (mask << 1)`。 追加の「+1」は定数項を再度反転するので、1 と XOR します。この組み合わせは、項が 2 回出現したときにどのようにキャンセルされるかを正確に捕捉します。 
4. 最下位ビットが設定されていない場合は、x による除算を実行します。これは、ビットマスク全体を 1 つ右にシフトすることに相当します。 
5. 各変換を 1 つの操作としてカウントします。 

シミュレーションは、定数項のみが残るまで続行されます。 

### なぜ効果があるのか

 多項式の構造は項の有無によって完全に把握され、すべての変換は定数項が存在するかどうかのみに依存します。 これにより、有限の 2 値状態空間にわたって進化が決定的になります。 多項式をビットマスクとして表すと、明示的に処理される定数項の切り替えを除いて両方の演算がビット位置に対して線形であるため、将来のステップに必要なすべての情報が保存されます。 したがって、シミュレートされた各遷移は、元のプロセスの 1 つのステップと正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    coeffs = list(map(int, input().split()))
    
    mask = 0
    for i, a in enumerate(reversed(coeffs)):
        if a:
            mask |= 1 << i

    steps = 0

    while mask != 1:
        if mask & 1:
            # multiply by (x + 1) and add 1, with cancellation behavior
            mask = (mask ^ (mask << 1)) ^ 1
        else:
            # divide by x
            mask >>= 1
        steps += 1

    print(steps)

if __name__ == "__main__":
    solve()
```実装では、指数の昇順で係数配列からビットマスクを構築します。 コアループは次を使用して定数項をチェックします。`mask & 1`。 存在する場合、変換では左シフトと XOR を組み合わせて乗算をシミュレートします。$x+1$、続いて定数項を反転します。 それ以外の場合は、右シフトにより x による除算が実装されます。 ループ カウンタは操作の数を直接追跡します。 

実装の微妙な詳細は、入力が最高次数から定数項に与えられるため、ビットマスクを構築するときに係数の順序が確実に逆転するようにすることです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、多項式が 1 で始まる場合です。アルゴリズムは即座に検出します。`mask == 1`ゼロ反復を実行し、操作が必要ないという定義と正確に一致します。 

もう 1 つのケースは、多項式に定数項がない場合です。 例えば、$x^3$x による除算の繰り返しを即座にトリガーします。 マスクは 1 になるまで右にシフトされます。これは x のストリッピング パワーに 1 つずつ正確に対応します。 

最後のケースは、乗算を繰り返すことで高次の項が導入される場合です。 たとえば、小さな多項式から開始すると、元の次数を超えるビットを含むマスクが生成される可能性があります。 表現は無制限の整数であるため、オーバーフローや切り捨ては発生せず、シミュレーションの一貫性が保たれます。
