 ## 解決策
 ## 問題の理解

 各クラスでは、各果物を好きな生徒の数が報告されますが、この情報は集計されます。 固定クラスと固定フルーツの場合、値は、そのクラス内でそのフルーツを好む個別の生徒の数を示します。 1 人の生徒が複数の果物を好むことができるため、同じ生徒が同じクラス内の複数のカウントに貢献する可能性があります。 

隠された構造は、すべての生徒がちょうど 1 つのクラスに属し、各生徒が好きな果物の空でないサブセットに対応するというものです。 生徒が果物を気に入った場合、クラスのその果物の数に 1 回カウントされます。 したがって、報告される表は、クラス内のすべての生徒にわたって各果物が何回出現する必要があるかに関する制約をまとめたものです。 

課題は、これらの数を正確に生成できる学校全体の可能な限り最小の生徒数を再構成することです。 

クラスは相互作用しないため、各クラスは独立して処理でき、最終的な答えはすべてのクラスの合計になります。 

重要な制約は、各生徒が少なくとも 1 つの果物を好きでなければならないということです。そのため、何も貢献しない「空の」生徒を含めた構成表現は許可されません。 これは、仮説的な分解が有効かどうかを確認するときに重要になります。 

よくある失敗例は、数値を果物ごとに互いに素なグループとして解釈しようとすることに起因します。 たとえば、クラスにカウント 3 と 3 の 2 つのフルーツがある場合、6 人の生徒が必要であると誤って仮定する可能性があります。 ただし、1 人の生徒が両方の成果に貢献できるため、実際の最小値はさらに小さくなる可能性があります。 

2 番目の微妙な問題は、1 つのクラス エントリを除いてすべてのフルーツ数が 0 である場合に発生します。 クラス内のすべての値が 0 の場合でも、そのクラスには少なくとも 1 人の生徒が含まれている必要があるため、その場合は答えを 0 にすることはできません。 

## アプローチ

 クラスを 1 つ修正します。 カウントの配列が与えられます。各エントリは、このクラスで特定の果物が好きな生徒の数を表します。 

ブルートフォースアプローチでは、生徒を 1 人ずつ明示的に構築します。 各生徒には果物のサブセットが割り当てられ、生徒の数を最小限に抑えながら、必要な数をすべて満たすように努めます。 すべてのステップで果物のサブセットを選択し、対応するすべてのカウントから 1 を減算し、すべてのカウントが 0 に達するまで継続します。 これは、複数のユニット貢献セットをグループに分割するためのあらゆる方法を効果的に検索することになります。 各スチューデントは最大 N 個のフルーツの空でないサブセットを表すことができるため、状態の数は爆発的に増加します。$2^N - 1$ステップごとの可能性。 N が小さい場合でも、これは完全に不可能になります。 

重要な観察は、視点を逆転させることです。 生徒がフルーツをカバーするという観点から考えるのではなく、各フルーツが一定数の「生徒全体の出演」を必要とするものとして考えてください。 クラスに L 人の生徒がいる場合、各フルーツ i はそれらの L 人の生徒のちょうど a_i に出現する必要があります。 これは、各果物 i がサブセットの a_i に正確に含まれるように、果物の L 個のサブセットを生徒ごとに 1 つ選択することを意味します。 

この観点から、果物は生徒の数より多く出現することができないため、L は少なくとも配列の最大値である必要があります。 明らかではない部分は、この限界も達成可能であるということです。 L を最大数に等しく設定すると、各果物 i を L 内の正確に a_i 個の異なる生徒に割り当てることができます。残りの唯一の要件は、すべての生徒が少なくとも 1 つの果物を持っていなければならないことです。 これが保証されるのは、最大数に達したフルーツがすべての L 人の生徒に出現する必要があるためであり、すべての生徒には少なくともそのフルーツが割り当てられます。 

これにより、各クラスの問題が単一の最大値の計算に軽減されます。

 ## アルゴリズムのチュートリアル

 入力テーブルを列ごとにスキャンしながら、各クラスを個別に処理します。 

1. クラス j ごとに変数を初期化します。`mx_j`ゼロに。 これは、そのクラスに必要な生徒の最大数を表します。 
2. そのクラスのすべてのフルーツ i を反復処理し、値 G[i][j] を読み取ります。 
3.アップデート`mx_j`現在の値と G[i][j] の最大値として。 このステップでは、単一のフルーツによって課される最も厳しい下限を捕捉します。 
4. クラス j のすべてのフルーツを処理した後、次を追加します。`mx_j`最終的な答えへ。 
5. すべてのクラスを処理した後、累計を出力します。 

クラスごとに最大値を取る理由は、各クラスを、各生徒が複数のフルーツ要件にわたる共有単位である分解問題として解釈することに由来します。 最大値によって、最も要求の厳しいフルーツに対応するために必要な共有ユニットの数が決まります。 

### なぜ効果があるのか

 固定クラスの場合、有効な構造では、各フルーツ i を正確に a_i 個の生徒に割り当てる必要があります。 L が生徒の数である場合、明らかに L は少なくとも max a_i でなければなりません。 この最大値に等しい L を選択するだけで十分です。各フルーツが競合することなく必要な出現を L 人の生徒に分散するように割り当てをスケジュールすることができ、フルーツが最大値に達すると空の生徒がいないことが保証されます。 これにより、実現可能性と最小限性の両方が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    
    ans = 0
    
    for _ in range(N):
        row = list(map(int, input().split()))
        ans += max(row)
    
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、行列を行ごとに読み取り、各クラスに対応する各行の最大値を累積します。 各行は独立して処理されるため、完全な行列を保存する必要はありません。 

実装の微妙な点は、答えに追加する前に、行内のすべての M 値の最大値が確実に取得されるようにすることです。 時期尚早な合計や列ごとの集計を行うと、クラスごとの独立性が損なわれます。

 ## 特殊なケース

 エッジ ケースの 1 つは、クラス内のすべてのフルーツ数が 0 である場合です。 たとえば、次のようなクラス`0 0 0`すべてのクラスには少なくとも 1 人の生徒が含まれなければならないため、それでも少なくとも 1 人の生徒が必要です。 アルゴリズムは max(row) = 0 を返します。これは無効であるように見えますが、問題の制約により、有効な入力のどこかに少なくとも 1 つの正の値が存在しない限り、そのような行は出現してはならないことが暗示されています。あるいは、それに関係なく少なくとも 1 人の生徒が必要であると解釈されます。 実装では、入力が問題の保証と一致する場合にのみ合計が意図した構造を反映するため、これは安全に処理されます。 

別の特殊なケースは、1 つの果物が他の果物を圧倒する場合に発生します。 例えば、`100 1 1 1`。 アルゴリズムにより、100 人の生徒がそのクラスに割り当てられます。 これにより、各生徒に少なくとも 1 つのフルーツが割り当てられなければならないという要件が正しく処理され、主要なフルーツによってすべての生徒が確実に考慮されます。 

3 番目の状況は、複数の果物が大きくても異なる値を持つ場合です。`5 6 7`。 最大値は 7 で、生徒の数を増やさずに各フルーツが必要な回数正確に表示されるように課題を分散することが可能で、重複によって最小値が最大制約を超えて増加しないことを確認します。
