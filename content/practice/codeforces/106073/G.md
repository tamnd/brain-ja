 ## 問題の理解

 長さのターゲットバイナリ文字列が与えられます。$N$、同じ長さのすべてゼロの配列から開始します。 開始位置を選択する操作を実行できます$i$固定 8 ビット パターンの XOR を実行します$B$配列上に配置され、$B[j]$位置に影響を与える$i+j$その位置が配列内に存在する場合は常に。 各操作は最大 8 つの連続する位置のウィンドウ内のビットを反転し、重複するアプリケーションは XOR を介して蓄積されます。 

タスクは固定パターンをシミュレートすることではなく、8 ビット パターンを選択することです。$B$自体。 一度$B$が修正されているため、できるだけ少ない操作でターゲット文字列を生成したいと考えています。 最小の操作数を達成するすべてのパターンの中で、次のように解釈した場合、辞書編集的に最小のバイナリ パターンを出力する必要があります。$b_0$最上位ビットとして。 

制約$N \le 4096$は、次の二次方程式の解が存在することを意味します。$N$パターンごとにすでに遅すぎます。 しかないので、$2^8 = 256$考えられるパターン、$O(256 \cdot N)$または$O(256 \cdot N \cdot 8)$このアプローチは実現可能ですが、定数係数の作業を超える重い内部ループを伴う操作ごとまたは位置ごとの再計算を伴うものは、依然として快適に通過する可能性があります。 

微妙なエッジケースは境界効果から生じます。 この操作は次の位置で適用できます。$-7$に$N-1$つまり、初期ビットはインデックス 0 より前から始まる操作の影響を受ける可能性があります。プレフィックス ビットへの影響を考慮せずに負のシフトを無視する単純な実装では、初期ビットがそのような寄与を必要とする場合に、暗黙的に失敗します。 別の問題が発生するのは、$b_0 = 0$。 その場合、位置での操作は$i$直接反転しない$c_i$となり、システムをローカルで制御することが難しくなります。 適切に処理されない限り、どのようなソリューションでもこれを考慮するか、そのようなパターンを回避する必要があります。

 ## アルゴリズムのチュートリアル

 すべての 8 ビット パターンを評価します$B$独立して。 固定パターンごとに、操作を適用する場所を決定しながら、ターゲット文字列を左から右に構築することをシミュレートします。 

1.固定の場合$B$、配列を初期化します`x`各位置で演算を適用するかどうかを表します。 概念的には、すべてのポジションがゼロから始まり、まだ操作が適用されていないと仮定します。 
2. からの位置をスイープします$0$に$N-1$。 位置で$i$、配列の現在の値を計算します。$i$以前に選択されたすべての操作によって生成されます。 ポジションでの過去の各操作$j$貢献する$B[i-j]$もし$0 \le i-j < 8$。 
3. 計算値とターゲットビットを比較します。$C[i]$。 それらが一致する場合、アクションは必要ありません。 
4. それらが異なる場合、位置での操作を強制的に適用する必要があります。$i$影響を与える可能性がある限り$i$に依存します$b_0$。 もし$b_0 = 1$、この操作は反転します$C[i]$、ということで設定しました$x[i] = 1$。 もし$b_0 = 0$、不一致は以前の選択によってすでに解決されている必要があります。 それ以外の場合、このパターンは貪欲な構築には無効です。 
5. 申請する$x[i] = 1$ポジションに寄与するため、将来の効果を暗黙的に即座に更新します。$i$を通して$i+7$後の計算で。 
6. スイープ終了後の操作の合計数は、次の合計になります。$x[i]$。 
7. 操作数を最小限に抑え、辞書編集上最小のバイナリ値で関係を解消することで最適なパターンを追跡します。$B$。 

中心となる不変条件は、位置を処理する前の不変条件です。$i$、指数に影響を与えるすべての寄与$< i$完全に決まっている。 操作は前方位置にのみ影響するため、将来の決定によって過去の正しさが変更されることはありません。 したがって、不一致がある場合は、$i$、 そして$b_0 = 1$これを修正する唯一の方法は、次の場所に操作を配置することです。$i$、貪欲な選択はヒューリスティックではなく強制されます。

import sys
input = sys.stdin.readline

def simulate(B, C, N):
    # x[i] = whether we apply operation at i
    x = [0] * (N + 8)  # safe padding for window effects

    cur = [0] * N  # we maintain current constructed value implicitly via recomputation

    # Instead of recomputing full convolution each time, maintain incremental effect
    # We track active contributions using a sliding window
    active = [0] * (N + 8)

    res = 0

    for i in range(N):
        # compute current bit at i
        val = 0
        for j in range(8):
            if i - j >= 0:
                val ^= x[i - j] & ((B[j] == '1'))
        if val != C[i]:
            if B[0] == '0':
                return float('inf')
            x[i] = 1
            res += 1

    return res

def solve():
    N = int(input().strip())
    C = input().strip()

    best_B = None
    best_q = float('inf')

    for mask in range(256):
        B = format(mask, '08b')
        q = simulate(B, C, N)

    print(best_B, best_q)

小切手`B[0] == '0'`現在の位置を直接切り替えることができない場合、将来の操作のみを使用して位置を固定することが構造的に不可能であることを処理します。 これにより、貪欲な構築の一貫性が強制されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ターゲットがすべて 0 である場合です。 アルゴリズムはすべてのパターンを正しく評価し、空のパターンが$B = 00000000$有益な操作はなく、他のパターンは不要な反転を引き起こすだけであるため、操作は必要ありません。 

初期ビットが仮想的な負のインデックス演算に依存する場合、別のエッジ ケースが発生します。 貪欲シミュレーションは、そのような効果がすべて開始時に暗黙的にゼロであるという事実に依存することにより、負のインデックスの明示的な処理を回避します。 配列に影響を与える事前の操作がない状態から開始するため、これは一貫しています。 

最後のエッジケースは次のような場合です$b_0 = 0$。 そのシナリオでは、位置の不一致$i$から始まる操作では修正できません$i$、貪欲なプロセスは矛盾を即座に検出します。 これにより、使用できないパターンが正しく取り除かれ、操作が誤って過小カウントされるのを防ぎます。
