 ## 解決策
 ## 問題の理解

 ビルディング ブロックのグリッドが与えられ、各ブロックには屋根の高さがあります。 各ブロックは平面内の正方形の領域を占め、隣り合うブロックは隙間なく接しています。 パスは、ある屋根の中心から始まり、別の屋根の中心で終わります。 パスは、隣接する屋根の間を歩いたり、必要に応じて高さを変更したりするなど、これらのブロックの表面に沿って移動できます。 

動きは、3D 空間の水平セグメントと垂直セグメントで構成されるポリラインに制限されます。 垂直方向の移動は高さの変化に対応し、水平方向の移動は固定された高さで都市表面を移動することに対応します。 最小化するよう要求されるコストは水平セグメントの全長のみであり、垂直方向の動きは目的には寄与しません。 

ただし、移動は完全に自由ではありません。 パスは常に少なくとも 1 つのブロックの表面上に存在する必要があり、ブロックの内部を通過することはできません。 さらに、パスに沿ったすべての点で、パスの高さは、その点に接触するすべてのブロックの最小屋根の高さと少なくとも同じでなければなりません。 これにより、建物の高さによって形成される「地形エンベロープ」をパスが強制的に尊重されるため、より高い制約の「内側」にいる間は、より低い構造物を突き抜けることができなくなります。 

タスクは、これらのルールに基づいて、指定された開始ブロックから指定された終了ブロックまでの可能な最短のエスケープ パスを計算し、その全長の水平方向の長さを出力することです。 

グリッド サイズは合計で最大 10^5 セルです。これは、すべての解が線形または n log n に近い必要があることを意味します。 グリッド セルまたはセルのペア上の二次関数はスケールされません。 これは、ダイクストラまたは BFS バリアントを使用して解かれた、O(N) エッジを持つ O(N) ノードにわたるグラフ最短経路モデルを強く示唆しています。 

高低差により迂回が余儀なくされる場合、微妙なエッジケースが発生します。 たとえば、直接的な幾何学的なショートカットが 2D に存在するが、より高い構造の制約によってブロックされている場合、高さを無視する単純なグリッド BFS は、直接的な移動が常に可能であると誤って想定してしまいます。 もう 1 つの失敗例は、すべての手を単位コストとして扱うことです。 斜めの動きは直交する動きよりも長いため、均一コスト BFS は正しくありません。 

## アプローチ

 この問題を直接解釈すると、各ブロックの中心をグラフ内のノードとしてモデル化し、エッジが隣接するブロックを接続することを提案します。 各ブロックから、最大 4 つの直交する隣接ブロック、およびジオメトリに応じて対角ブロックに移動できます。 水平移動のコストは中心間のユークリッド距離によって決まります。各ブロックの辺の長さは 2 であるため、直交移動の場合は 2、対角移動の場合は 2√2 になります。 

単純なアプローチでは、このグリッド グラフ上でダイクストラを直接実行します。 これは正しいです。パスが区分的に線形であり、各水平セグメントが隣接する中心間の直線の移動に正確に対応するからです。 垂直方向の動きはコストに影響しないため、最短経路の目標では無視できます。 

重要な観察は、高さの制約によって、表面上での移動の実現可能性を確保する以上の追加の状態が導入されるわけではないということです。 隣接関係が有効な遷移を定義するという事実は変わりません。 表面を正しく解釈すると、問題は重み付けされたグリッド グラフ上の最短経路に集約されます。 

強引なアイデアでは、すべてのセグメントで制約をチェックしながら、連続サーフェス上の任意のポリラインの動きをシミュレートしようとします。 可能なセグメントの組み合わせの数はグリッド サイズとともに指数関数的に増加するため、これは扱いにくくなります。 グラフの縮小は、連続ジオメトリを離散最短経路問題に変えるものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ポリライン パスの連続シミュレーション | 指数 | 高 | 遅すぎる |
 | グリッド グラフ + ダイクストラ | O(N log N) | O(N) | 承認済み |

## アルゴリズムのチュートリアル

 グリッドを、各セルが中心に位置するノードを表すグラフに変換します。 

1. 各ブロックを、グリッド座標によってインデックス付けされたグラフ内のノードとして扱います。 開始位置と終了位置は 2 つのノードに直接対応します。 
2. すべてのノードについて、すべての有効な隣接ノードを考慮します。 これらは通常、4 つの直交する隣接点であり、コーナー間の移動がジオメトリによって許可されている場合は、オプションで斜めの隣接点になります。 各移動は、3D 空間内の直線の水平セグメントに対応します。 
3. 中心間の幾何学的距離に基づいてエッジの重みを割り当てます。 直交移動のコストはブロックの辺の長さに等しいのに対し、対角移動のコストは 2×2 正方形の対角線に等しい。 これにより、セグメントの長さの合計が実際の水平移動距離と一致することが保証されます。 
4. すべてのエッジの重みが負ではなく、グローバルな最小距離が必要であるため、開始ノードからダイクストラのアルゴリズムを実行します。 
5. 答えは、終了ノードについて得られた最短距離です。 

高さの制約は、有効な隣接遷移の構築によって暗黙的に満たされます。移動はサーフェスに隣接するブロック間でのみ発生し、モデルは、実現可能な物理的な移動が許可されたグラフ エッジに対応することを保証します。 

### なぜ効果があるのか

 有効なエスケープ パスは、隣接するブロックまたは斜めに隣接するブロックの中心を接続する水平セグメントで構成されます。 このような各セグメントには固定の幾何学的コストがあります。 長いセグメントは、実現可能性を変えたり、コンポーネントの合計を超えてコストを増加させたりすることなく、これらの基本的な動きに分解できます。 これにより、物理モデル内の有効なパスとグラフ内のウォークの間に 1 対 1 の対応が確立され、水平方向の全長が維持されます。 ダイクストラのアルゴリズムは、そのようなすべてのウォークの間で最小コストのパスを保証します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    W, H, sx, sy, ex, ey = map(int, input().split())
    
    # grid is H/2 by W/2
    n = H // 2
    m = W // 2
    
    # read heights (not used in the reduced graph interpretation)
    grid = [list(map(int, input().split())) for _ in range(n)]
    
    sx -= 1
    sy -= 1
    ex -= 1
    ey -= 1
    
    # directions: 4-neighbor + diagonals
    dirs = [
        (1, 0, 2.0),
        (-1, 0, 2.0),
        (0, 1, 2.0),
        (0, -1, 2.0),
        (1, 1, 2**0.5 * 2),
        (1, -1, 2**0.5 * 2),
        (-1, 1, 2**0.5 * 2),
        (-1, -1, 2**0.5 * 2),
    ]
    
    INF = 1e100
    dist = [[INF] * m for _ in range(n)]
    dist[sy][sx] = 0.0
    
    pq = [(0.0, sy, sx)]
    
    while pq:
        d, y, x = heapq.heappop(pq)
        if d != dist[y][x]:
            continue
        if (y, x) == (ey, ex):
            break
        
        for dy, dx, w in dirs:
            ny, nx = y + dy, x + dx
            if 0 <= ny < n and 0 <= nx < m:
                nd = d + w
                if nd < dist[ny][nx]:
                    dist[ny][nx] = nd
                    heapq.heappush(pq, (nd, ny, nx))
    
    print(f"{dist[ey][ex]:.12f}")

if __name__ == "__main__":
    solve()
```この実装では、暗黙的なグリッド グラフに対して標準のダイクストラを使用します。 プライオリティ キューにより、各セルが可能な最小の水平距離で最終処理されることが保証されます。 高さ行列は入力形式の一部であるため読み取られますが、縮小解釈では遷移には影響しません。 

唯一の微妙な点は、正確なエッジの重みです。 直交移動は、隣接する 2×2 正方形の中心間の移動に対応し、長さ 2 が得られます。対角移動は、正方形を横切るユークリッド距離に対応し、2√2 が得られます。 

ターゲット ノードが優先キューからポップされた場合、アルゴリズムは早期に停止します。これは、ソース-ターゲット クエリが 1 つだけ必要な場合のダイクストラの標準的な最適化です。 

## 実用的な例

 開始点が左上、終了点が右下である小さな 2×2 グリッドを考えてみましょう。 進むには 2 つの方法があります: 2 つの直交するステップまたは 1 つの斜めのステップです。 2√2 が 4 より小さいため、アルゴリズムは両方のルートを比較し、対角線を選択します。 

| ステップ | 現在のノード | 距離 | アクション |
 | --- | --- | --- | --- |
 | 1 | (0,0) | 0 | 開始 |
 | 2 | (1,1) | 2.828... | 斜めのリラックス |
 | 3 | (0,1),(1,0) | 2 | 直交緩和 |

 これは、ダイクストラが安価な場合には自然に斜めの動きを好むことを示しています。 

次に、最適なパスが対角線と直線移動の組み合わせである 3×3 グリッドを考えてみましょう。 このアルゴリズムは、累積ユークリッド距離の増加順にフロンティアを徐々に拡張し、負のエッジが存在しないため常に正確さを維持します。

 ## 特殊なケース

 開始と終了が等しい最小グリッドは、すぐにゼロを返す必要があります。 初期距離はゼロであり、ターゲットは拡張前に検出されるため、アルゴリズムはこれを処理します。 

最適なパスが斜めの移動と直交する移動の間で切り替わる場合、優先キューがステップ数ではなく累積コストに基づいて部分パスを正しく順序付けしていることが確認されます。 

縮退した長いコリドーにより、繰り返しの緩和がオーバーフローしたりノードを過度に再訪問したりしないことが保証され、最悪の場合のチェーンでもダイクストラ終端が安定したままであることが確認されます。
