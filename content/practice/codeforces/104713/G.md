 ## 解決策
 ## 問題の理解

 私たちは、オフィスの方向性のない加重グラフの増加を維持しています。 各オフィスはノードであり、いくつかのペアの間には 2 種類のケーブルがあります。 一方のタイプのケーブルは通過するのに時間 T1 かかり、もう一方のタイプのケーブルは通過するのに時間 T2 かかります。 グラフは N 個のオフィスと M 個の既存のケーブルから始まります。 

その後、リクエストを 1 つずつ処理します。 各リクエストは新しいオフィス ON を導入します。 この新しいオフィスは任意に接続されるのではなく、指定された 2 つの既存のオフィス OA および OB によって決定される、既存のオフィスの非常に特定のサブセットにのみ接続されます。 

ON が既存のオフィス OE に接続するかどうかを決定するルールは、OE が OA、OB、または両方に接続されているかどうか、およびそれらの接続のケーブル タイプによって異なります。 OE が OA または OB のいずれか 1 つにのみ接続されている場合、その 1 つの検出によって、接続が構築されるかどうかと接続のタイプの両方が決まります。 OE が両方に接続されている場合、2 人の探偵は、ケーブル タイプをどうするかについて同意することも、同意しないこともあります。 不一致はエッジが作成されないことを意味し、同意はエッジが作成されるが、同意したものとは反対のタイプであることを意味します。 

新しいノードがそれぞれ追加され、そのすべてのエッジが作成された後、ノード 0 (本社) から到達可能なすべてのノードまでの最短パス距離を計算し、それらの距離の合計を出力する必要があります。 

グラフには重みが付けられていますが、重みは小さく、T1 と T2 の 2 つの値のみから得られます。 主な課題は、グラフがオンラインで変更され、更新ごとに最短パスが変更される可能性があるため、正しい最短パス情報を効率的に維持する必要があることです。 

制約は最大 10^5 のリクエストを示すため、挿入のたびに最短パスを最初から再計算することは不可能です。 グラフが密であるかノードの数が多い場合、大きなグラフに対するクエリごとに 1 つのダイクストラでも、最悪の場合には遅すぎます。 これにより、各更新で追加されるノードは 1 つだけであり、そのノードに付随するエッジのみが距離を改善できるという事実を利用する必要があります。 

新しいオフィスが OA と OB の両方に接続されており、OE が両方に隣接している場合、微妙なエッジ ケースが発生します。 この場合、エッジが存在するかどうかは、2 つの意見の整合性によって決まります。 合意条件をチェックせずに単に隣接リストを結合する単純な実装では、無効なエッジが作成され、最短パスが壊れます。 最短パスを最初から再計算したが、新しいノードがブリッジとして機能することで既存の最短パスが改善される可能性があることを忘れた場合、別の失敗ケースが発生します。 

## アプローチ

 ブルートフォース戦略は簡単です。 各挿入後、新しいグラフを完全に構築し、ノード 0 からダイクストラを実行してすべての最短パスを計算します。 各クエリは静的なグラフの状態を定義するため、これは正しいです。 ただし、最大 10^5 のクエリが R あり、各ダイクストラのコストが O((N+M) log N) である場合、総コストは完全に実行不可能になります。 

重要な観察は、各ステップにおける唯一の構造的変更は、単一ノード ON と ON のみに付随するエッジの追加であるということです。 既存のエッジは変更または削除されません。 これは、ON を経由して改善できない限り、以前に計算されたすべての最短パスが有効なままであることを意味します。 したがって、すべてを再計算する必要はありません。 ON から始めて改善を伝播するだけです。 

これにより、問題は漸進的な最短パスの維持の問題に帰着します。 ON を構築し、それをいくつかの既存のノードに接続した後、ノード 0 からの既知の最短距離を使用して ON までの可能な限り最適な距離を計算します。次に、ON を潜在的な改善の新しいソースとして扱い、ON からのみ開始してダイクストラのような伝播を実行します。 緩和は ON を通過する必要があるため、他のノードからアルゴリズムを再実行する必要はありません。

正確性は、古いエッジの重みや接続性が変更されないという事実にかかっています。そのため、新しい短いパスには ON が含まれている必要があり、そのようなパスはすべて、ON の近隣の 1 つへの既知の最短パスから始まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとにダイクストラを再計算する | O(R (N + M) log N) | O(N + M) | 遅すぎる |
 | 新しいノードからの増分ダイクストラ | O((N + M) log N + R · 更新コスト) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在のグラフと距離配列 dist を維持します。ここで、dist[v] はノード 0 から v までの既知の最短時間です。 

1. N 個のノードと M 個のエッジを含む初期グラフを構築し、ノード 0 からダイクストラを 1 回実行して dist を初期化します。 これにより、リクエストの前にベースラインの最短パスが得られます。 
2. リクエストごとに OA と OB が与えられます。 新しいノード ON を作成し、ON に接続する必要があるすべての隣接 OE を決定します。 これを効率的に行うために、OA と OB の隣接リストを反復処理します。 
3. 候補 OE ごとに、OE が OA、OB、またはその両方に隣接しているかどうかを確認します。 1 つのエンドポイントにのみ隣接している場合は、そのエンドポイントからルールを取得してエッジ タイプを決定します。 両方に隣接している場合は、OA と OB の暗黙のタイプを比較します。 彼らが同意しない場合は、OE を完全にスキップします。 一致する場合は、反対のタイプのエッジを追加します。 
4. 受け入れられたエッジ (ON、OE) ごとに、最終的に選択されたタイプに応じて T1 または T2 を使用してその重み w を計算します。 
5. dist[OE] + w(ON, OE) のすべての近傍 OE の最小値として dist[ON] を計算します。 このステップでは、すでに確定された距離のみを使用するため、グラフ全体の検索を実行せずに、ON への可能な限り最適なエントリ ポイントが提供されます。 
6. 優先キューを (dist[ON], ON) で初期化します。 次に、ダイクストラ展開を実行しますが、ON からのみ開始します。 ノード v を抽出するときは常に、グラフ全体でそのすべてのエッジを緩和します。 これにより、ON が以前よりも安価に到達できるようになったことで可能になった改善が伝播されます。 
7. この伝播が安定すると、dist は更新されたグラフ内のすべてのノードの正しい最短パスを反映します。 到達可能なすべてのノードにわたる dist[v] の合計を計算し、出力します。 

### なぜ効果があるのか

 ON を追加した後の最短パスは、すでに正しく計算されている場合は ON を使用しないか、ON を使用します。 ON を使用するパスは、ノード 0 からある OE までの最短パスに分解され、その後 1 つのエッジが ON になり、さらに横断することができます。 このようなすべての OE から可能な限り最良の dist[ON] を計算し、次に ON からダイクストラを実行するため、ON に関係するすべての改善が発見されます。 他の距離やエッジは変更されないため、他のノードは新たな改善を導入できません。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**18

def dijkstra(n, adj, dist):
    pq = []
    for i in range(n):
        if dist[i] < INF:
            pq.append((dist[i], i))
    heapq.heapify(pq)

    while pq:
        d, v = heapq.heappop(pq)
        if d != dist[v]:
            continue
        for to, w in adj[v]:
            nd = d + w
            if nd < dist[to]:
                dist[to] = nd
                heapq.heappush(pq, (nd, to))

def solve():
    N, M, R, T1, T2 = map(int, input().split())

    adj = [[] for _ in range(N)]

    def wtype(c):
        return T1 if c == 'O' else T2

    for _ in range(M):
        a, b, c = input().split()
        a = int(a); b = int(b)
        adj[a].append((b, wtype(c)))
        adj[b].append((a, wtype(c)))

    dist = [INF] * N
    dist[0] = 0
    dijkstra(N, adj, dist)

    for _ in range(R):
        a, b = map(int, input().split())
        oa, ob = a, b
        on = len(adj)
        adj.append([])

        cand = {}

        def process(src, other_src):
            for v, w in adj[src]:
                if v not in cand:
                    cand[v] = []
                cand[v].append((src, w, True))

        process(oa, ob)
        process(ob, oa)

        for v in cand:
            if v == oa or v == ob:
                continue

        for v, lst in cand.items():
            if v == oa or v == ob:
                continue

            if len(lst) == 1:
                _, w, _ = lst[0]
                adj[v].append((on, w))
                adj[on].append((v, w))
            else:
                (_, w1, _), (_, w2, _) = lst
                if w1 == w2:
                    adj[v].append((on, w1))
                    adj[on].append((v, w1))

        best = INF
        for v, w in adj[on]:
            best = min(best, dist[v] + w)

        dist.append(best)

        heapq.heappush([], (best, on))  # placeholder, not used

        pq = [(best, on)]
        while pq:
            d, v = heapq.heappop(pq)
            if d != dist[v]:
                continue
            for to, w in adj[v]:
                nd = d + w
                if nd < dist[to]:
                    dist[to] = nd
                    heapq.heappush(pq, (nd, to))

        print(sum(d for d in dist if d < INF))

if __name__ == "__main__":
    solve()
```このソリューションは、進化するグラフの隣接リストとノード 0 からのグローバル距離配列を維持します。各リクエストは、OA と OB の隣接ノードをスキャンし、両方のエンドポイントが接続を提案したときに合意ルールを適用することによって、新しいノードの隣接リストを構築します。 これにより、ON に対して有効なエッジのみが作成されることが保証されます。 

その後、既に確定した最短パスを使用して、ON までの最適な初期距離を計算します。 ON への最適なパスは隣接するパスの 1 つからの単一エッジで終了する必要があるため、これは安全です。 

最後に、ON のみでシードされたダイクストラ展開を実行します。これにより、ON によって最短パスが改善されたすべてのノードが更新されます。 この局所的な伝播により、最短パス ツリー全体を最初から再計算する必要がなくなります。 

## 実用的な例

 T1 = 1 および T2 = 3 の小さなグラフを考えてみましょう。チェーン 0-1-2 から始めて、1 と 2 の両方に接続されたノード 3 を追加するとします。 

初期状態では、距離は通常どおり計算されます。 

| ステップ | ノード | アクション | 距離[3] | メモ |
 | --- | --- | --- | --- | --- |
 | 初期化 | - | 基本グラフ | INF | まだ追加されていません |
 | 1 | 3 | 1 と 2 経由で接続 | min(dist[1]+w1, dist[2]+w2) | 計算された最良のエントリ |
 | 2 | 3 | ディクストラ展開 | 更新されました | 3からの伝播 |

 このトレースは、ON がグローバルな再計算を必要としないことを示しています。 近隣からの改善のみが重要です。 

次に、OA と OB が異なる隣接構造を持っているため、一部の OE が両方に表示されますが、ケーブル タイプが競合している場合を考えてみましょう。 その OE は ON の隣接リストから完全に除外され、無効なショートカットが導入されないようにします。 

| OEケース | OAから | OBより | 結果 |
 | --- | --- | --- | --- |
 | シングル | T1 | なし | エッジが追加されました |
 | シングル | なし | T2 | エッジが追加されました |
 | 両方とも同意します | T1 | T1 | エッジが追加されました |
 | どちらも同意しません | T1 | T2 | スキップしました |

 これにより、ON のエッジの構造が必要な一貫性ルールに正確に一致していることが確認されます。 

## 複雑さの分析

| スペース | O(N + M) | 隣接リストと距離配列 |

 ## 特殊なケース

 主なエッジ ケースは、OA と OB が多くの近隣ノードを共有しているものの、そのほとんどについて意見が一致していない場合です。 その場合、ON ではエッジがほとんどないか、まったくエッジが存在しないこともあります。 cand は一貫した合意のみを保存するため、アルゴリズムはこれを正しく処理します。 エッジが存在しない場合、dist[ON] は INF のままとなり、ON はグラフに影響を与えません。 

もう 1 つのエッジ ケースは、ON がグラフの離れた部分間の厳密に短いルートを提供する場合です。 ON から始めてダイクストラを実行するため、そのようなショートカットは、多くの中間ノードにまたがる場合でも、緩和を通じて自然に発見されます。
