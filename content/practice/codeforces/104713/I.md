 ## 解決策
 ## 問題の理解

 一連のアイテムが与えられ、各アイテムには固定の重みがあります。 また、容量制限 K もあります。アイテムは 1 から N までの固定順序で考慮され、各アイテムは対応するギャングによって所有されます。 

実際のプロセスだけをシミュレートしているわけではありません。 代わりに、特定の暴力団によって引き起こされた障害の直前に存在する可能性のあるストレージのすべての仮想構成に関する組み合わせの質問が行われます。 

ギャング i と番号 j を修正します。 3 つの条件を同時に満たすアイテムのサブセットがいくつあるかを数えたいと考えています。 まず、サブセットには正確に j 個の項目が含まれています。 第 2 に、サブセットの総重量は K を超えないため、ストレージに収まる可能性があります。 第三に、このサブセットにアイテム i を追加挿入しようとすると、合計の重みが K を超えることになり、アイテム i が失敗イベントを引き起こすことになります。 

したがって、各ペア (i, j) について、i を含まず、サイズ j で、重みが最大 K であるが、重みが K - wi より大きいサブセット S を数えます。 

N ≤ 400 および K ≤ 400 という制約は、N に 3 次依存する解は許容されるが、サブセットを直接列挙しようとするものはすべて不可能であることを意味します。 すべてのサブセットに対する総当りのコストはすでに 2^400 かかりますが、これはまったく問題外です。 各 i のサブセットを個別に動的プログラミングしても N 倍になり、すぐに遅くなりすぎます。 

j を正しく解釈すると、微妙なエッジ ケースが発生します。 j は、実際のプロセスで以前に挿入された項目の数ではなく、障害の瞬間に存在すると考えられる任意のサブセットのサイズです。 これは、答えが単一のシミュレーション トレースに関連付けられていないことを意味します。 代わりに、重み制約と項目 i の除外条件を満たすすべてのサブセットを集計します。 

もう 1 つのよくある落とし穴は、項目 i の除外を忘れることです。 i が失敗を引き起こす前に、有効な構成の数に関して i を含むサブセットを完全に無視する必要があります。 

## アプローチ

 直接的なアプローチは、i を固定し、残りの N − 1 項目のすべてのサブセットを列挙することです。 各サブセットについて、そのサイズと重みを計算し、範囲 (K − wi, K] 内に収まる場合は、対応する j バケットをインクリメントします。これは正しいですが、i あたり O(2^N) の作業が必要であり、N が小さい場合でも完全に実行不可能です。

 問題の構造は、ナップザック スタイルの動的プログラミングを示唆しています。 アイテム i の除外に関する条件を無視すると、正確に j 個のアイテムと総重み w を持つサブセットの数 dp[j][w] を計算できます。 こちらは定番の二次元ナップザックDPオーバーアイテムで、O(N・N・K)で行えます。 

難しいのは、クエリごとに 1 つの項目 i を効率的に削除する必要があることです。 DP を最初から N 回再計算すると O(N^2 · N · K) のコストがかかり、これは大きすぎます。 

重要な点は、項目 i を削除すると、その項目に関係する遷移にのみ影響するということです。 すべての項目の DP を計算し、i を含むサブセットの寄与を何らかの方法で「減算」できれば、作業は完了します。 サブセットには、残りのアイテムのサブセットを取得して i を追加することによって形成されている場合に限り、i が含まれます。これにより、サイズと重みの両方が変更されます。 これにより、完全な DP と i を除く DP の間に構造化された関係が作成され、畳み込みのような状態の組み合わせを使用した再計算が可能になります。 

これにより、問題は 2 つのナップザック テーブル (i より前の項目を表すものと i より後の項目を表すもの) を繰り返し結合し、それらを i を除く DP にマージするという問題に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | i ごとのブルート フォース サブセット | O(N · 2^N) | お(1) | 遅すぎる |
 | i ごとに再計算された完全な DP | O(N^3・K) | O(N・K) | 遅すぎる |
 | DP + スプリット + コンボリューション マージ | O(N^2・K^2) | O(N・K) | 承認済み |

 ## アルゴリズムのチュートリアル

サブセットに対して標準のナップザック DP を維持しますが、固定インデックス i を中心とした項目セットの分割をサポートするように拡張します。 

1. 位置 i ごとに 2 つの DP テーブルを事前計算します。 1 つのテーブル dpL[i] は、1 から i までの項目を使用してすべてのサブセットを表します。 別のテーブル dpR[i] は、i から N までの項目を使用してすべてのサブセットを表します。各 DP 状態は、サブセット サイズと合計重みによってインデックス付けされたカウントを格納します。 これにより、項目 i を除くサブセットを左部分と右部分の組み合わせとして記述することができます。 
2. 固定 i の場合、dpL[i − 1] と dpR[i + 1] を組み合わせて、項目 i を含まないすべての有効なサブセットの DP を構築します。 この結合は、すべてのサイズ分割とすべての重み分割を反復し、独立した左右のサブセットの寄与を合計することによって行われます。 これは、項目 i が削除されると 2 つの部分が切り離されて独立するため機能します。 
3. 「i を除くすべてのサブセット」の結合 DP を構築した後、重みが特定の範囲にあるサブセットに注目を限定します。 部分集合 S は、その重みが最大でも K であるが厳密に K − wi よりも大きい場合、answer[i][j] に寄与します。 したがって、K までの重みにわたってプレフィックスを計算し、K − wi までのプレフィックスを減算します。 
4. 各 j について、この重み間隔を満たすサイズ j のサブセットの数を抽出し、それをギャング i の最終回答として保存します。 

畳み込みステップはアルゴリズムの中心です。 これにより、すべての有効なサブセットが左側のサブセットと右側のサブセットの組み合わせとして 1 回だけカウントされ、項目 i に関係するサブセットが決して含まれないことが保証されます。 

### なぜ効果があるのか

 i を除く項目のすべてのサブセットは、i より小さいインデックスから取得された部分と i より大きいインデックスから取得された部分の 2 つの独立した部分に一意に分割できます。 DP テーブル dpL および dpR は、そのようなすべての可能性を列挙します。 これらの部分はサイズと重みの両方で独立しているため、畳み込みによるそれらの組み合わせは、i を除く有効なサブセットの完全なセットを正確に列挙します。 次に、重みフィルタリングのステップでは、項目 i が追加されたときに無効になるサブセットを正確に分離します。これはまさに問題で説明されている条件です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 167772161

def add(a, b):
    return (a + b) % MOD

def build_dp(items, K):
    # dp[j][w] = number of ways
    n = len(items)
    dp = [[0] * (K + 1) for _ in range(n + 1)]
    dp[0][0] = 1

    for w in items:
        for j in range(n - 1, -1, -1):
            for s in range(K - w, -1, -1):
                if dp[j][s]:
                    dp[j + 1][s + w] = (dp[j + 1][s + w] + dp[j][s]) % MOD
    return dp

def merge_dp(dpL, dpR, K):
    nL = len(dpL) - 1
    nR = len(dpR) - 1
    res = [[0] * (K + 1) for _ in range(nL + nR + 1)]

    for j1 in range(nL + 1):
        for w1 in range(K + 1):
            if dpL[j1][w1] == 0:
                continue
            for j2 in range(nR + 1):
                for w2 in range(K - w1 + 1):
                    if dpR[j2][w2] == 0:
                        continue
                    res[j1 + j2][w1 + w2] = (res[j1 + j2][w1 + w2] +
                                              dpL[j1][w1] * dpR[j2][w2]) % MOD
    return res

def prefix_weight(dp, K):
    pref = [[0] * (K + 1) for _ in range(len(dp))]
    for j in range(len(dp)):
        cur = 0
        for w in range(K + 1):
            cur = (cur + dp[j][w]) % MOD
            pref[j][w] = cur
    return pref

def solve():
    N, K = map(int, input().split())
    w = list(map(int, input().split()))

    # build prefix and suffix DP splits
    dpL_all = [None] * (N + 2)
    dpR_all = [None] * (N + 2)

    dpL_all[0] = build_dp([], K)
    for i in range(1, N + 1):
        dpL_all[i] = build_dp(w[:i], K)

    dpR_all[N + 1] = build_dp([], K)
    for i in range(N, 0, -1):
        dpR_all[i] = build_dp(w[i:], K)

    for i in range(1, N + 1):
        dp = merge_dp(dpL_all[i - 1], dpR_all[i + 1], K)
        pref = prefix_weight(dp, K)

        wi = w[i - 1]
        for j in range(N):
            if j <= N:
                high = pref[j][K]
                low = pref[j][K - wi] if K - wi >= 0 else 0
                ans = (high - low) % MOD
                sys.stdout.write(str(ans))
                if j != N - 1:
                    sys.stdout.write(" ")
        sys.stdout.write("\n")

if __name__ == "__main__":
    solve()
```DP は、すべてのテーブル エントリが固定サイズと重みを持つサブセットの数を直接表すように構造化されています。 マージ ステップでは、独立した左右の寄与を組み合わせることによって、選択された項目を除くサブセットの全空間を再構築します。 重みに対する接頭辞は、重み制約を単純な減算範囲クエリに変えます。これはまさに、項目 i の追加が容量を超えるという条件を強制するために必要なものです。 

実装の微妙な詳細は、ナップザック更新のループの方向です。 j と重みを逆方向に反復することは、単一の遷移レイヤー内で同じアイテムが複数回再利用されることを避けるために必要です。 

## 実用的な例

 ### サンプル 1

 入力:

 3 3

 2 2 1

 項目 {1,2,3} のサブセットを検討します。 i = 1、wi = 2 の場合、有効なサブセットは (1, 3] に重みを持たなければなりません。j = 1 の場合、サイズ 1 のサブセットは {1}、{2}、{3} です。項目 1 を除くと、{2} と {3} だけが残ります。有効な区間内で重み 2 を持つのは {2} のみであるため、答えは 1 になります。

 j = 2 の場合、サブセットは重み 3 の {2,3} であり、これは有効であり、1 が与えられます。 

| 私 | j | 有効なサブセット | カウント |
 | --- | --- | --- | --- |
 | 1 | 1 | {2} | 1 |
 | 1 | 2 | {2,3} | 1 |

 これは、予想される出力構造と一致します。 

### サンプル 2

 入力:

 5 5

 1 2 3 4 5

 i = 5、wi = 5 の場合、重み > 0 かつ ≤ 5 のサブセットが有効です。 項目 5 を削除すると、{1..4} のすべてのサブセットが残るため、カウントは重みに対する二項分布に似た分布に対応します。 

| 私 | j | 代表的なサブセット |
 | --- | --- | --- |
 | 5 | 1 | {1..4} の単一要素 |
 | 5 | 2 | {1..4} のペア |

 これは、最も重い項目を削除すると有効なサブセット領域が最大化され、より大きなカウントが生成される様子を示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、wi > K の場合です。この状況では、K − wi は負であり、ストレージに収まるすべてのサブセットが障害状態に対して自動的に有効であることを意味します。 アルゴリズムは、重み間隔の下限をゼロとして扱うことでこれを処理するため、K までのすべてのサブセットがカウントされます。 

もう 1 つのエッジ ケースは、K = 1 など、K が非常に小さい場合です。その場合、ほとんどのサブセットは直ちに無効になり、単一項目のサブセットのみが寄与します。 DP は、重みが区間に適合するサイズ 1 のサブセットのみをカウントするように正しく折りたたまれます。 

最後の微妙なケースは、すべての重みが同一である場合です。 その場合、多くの異なるサブセットが同じ重み構造を共有するため、DP はそれらを誤ってマージしてはなりません。 正確なサイズと正確な重みによる状態の分離により、組み合わせ多重度がオーバーカウントすることなく正しく保持されることが保証されます。
