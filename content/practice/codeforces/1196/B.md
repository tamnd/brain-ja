 ## 解決策
 ## 問題の理解

 いくつかの独立した配列が与えられています。 それぞれについて、正確に k 個の連続する部分に切り分けなければなりません。各部分の合計は奇数になります。 配列の順序は固定されているため、自由なのはカット位置の選択だけです。 

部分配列は、要素のパリティの合計が 2 を法として 1 になるとき、正確に奇数の和になります。重要なのはパリティだけであるため、内部値は奇数か偶数かを詳細に追跡する必要はありません。 

出力はセグメント自体ではなく、セグメントを定義するカット位置です。 k 個のセグメントがインデックス r1、r2、...、rk で終了すると決定し、rk は n に等しくなければならないと判断した場合、効率的にパーティションを記述したことになります。 

この制約により、クエリごとの線形ソリューションが実現されます。 すべてのクエリにわたる配列の合計の長さは最大 2 × 10^5 であるため、各配列を 1 回または一定の回数スキャンするソリューションであればどれでも受け入れられます。 n が大きい場合、単一クエリ内の二次関数はすでに遅すぎます。 

主な問題は、セグメントの合計が範囲のグローバル プロパティであるにもかかわらず、すべてのセグメントに厳密なパリティ条件を同時に適用する必要があることです。 すべてのカット位置を試したり、セグメントの合計を繰り返しチェックしたりする単純な試みは、すぐに実行不可能になります。 

いくつかの微妙な失敗例が自然に現れます。 残りのセグメントの数を制御せずに、奇数のプレフィックス合計が表示されるたびに貪欲にカットすると、要素が不足するのが早すぎたり、遅すぎたりする可能性があります。 局所的な貪欲な選択が有効であるように見えても、奇数要素の総数が k 個の奇数和セグメントを形成するのに不十分な場合、別の失敗が発生します。 

## アプローチ

 ブルートフォース戦略では、n-1 個のギャップの中から k-1 個のカット位置を選択するすべての可能な方法を試し、結果として得られる各セグメントの合計が奇数かどうかを確認します。 パーティションの数は組み合わせによるもので、次のとおりです。$\binom{n}{k}$、最悪の場合、n は指数関数的になります。 単一のパーティションの検証でも線形であるため、このアプローチは実行可能な限界をはるかに超えています。 

重要な観察は、何がセグメントの合計を奇数にするかを考えることから得られます。 セグメント合計は、奇数の奇数要素が含まれている場合にのみ奇数になります。 偶数要素は、パリティにゼロを寄与する場合を除き、パリティに影響を与えません。 これにより、問題全体が配列内の奇数の位置の追跡に縮小されます。 

k 個のセグメントを固定する場合、それぞれのセグメントは奇数の奇数に寄与する必要があります。 これを保証する最も簡単な方法は、各セグメント境界構造に奇数要素を 1 つだけ割り当てることです。 これは、各カットは合計が奇数であるセグメントを終了する必要があるため、k−1 個の奇数要素を強制カット アンカーとして使用する必要があることを示唆しています。 

k-1 個の奇数要素が最初の k-1 セグメントの終点として選択されると、最後のセグメントには自動的に残りの要素が含まれます。 最後のセグメントの和も奇数になるようにするには、配列全体の奇数要素の総数が奇数である必要があり、k-1 個の奇数アンカーを消費した後でも、残りのサフィックスには奇数カウントの奇数が含まれている必要があります。 最後のセグメントは n で終了するため、全体で少なくとも k 個の奇数が必要であり、k 番目に選択された奇数位置が、最後のセグメントに少なくとも 1 つの奇数要素を残す最後の奇数セグメントのエンドポイント戦略でなければならないということになります。 

したがって、構築は貪欲なものになります。配列をスキャンし、奇数要素のインデックスを収集し、最初の k−1 個の奇数インデックスをカット ポイントとして使用します。 k 番目のセグメントは自動的に n で終了します。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 貪欲な奇妙なアンカー | クエリあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各クエリを個別に処理します。 

1. 配列をスキャンし、奇数のすべての要素の位置を記録します。 これらの位置は、奇数和セグメントを形成するために利用可能なすべてのパリティ「リソース」を表します。 
2. 奇数要素の数が k 未満の場合、直ちに不可能であると結論付けます。 各セグメントには、合計を奇数にするために少なくとも 1 つの奇数要素が含まれている必要があるため、k 個の有効なセグメントの構築を開始することさえできません。 
3. 奇数要素の数が少なくとも k である場合、最初の k-1 個の奇数位置を最初の k-1 セグメントの端点として選択します。 選択された各奇数インデックスは、セグメントに奇数の奇数要素が含まれており、境界が奇数の寄与で位置合わせされているため、そこで終了するセグメントの和が奇数であることを保証します。 
4. 最後のセグメントが n で終了するように設定します。 残りのサフィックスには必ず未使用の要素がすべて含まれており、少なくとも k 個の奇数要素から開始したため、残りのセグメントには依然として奇数の奇数が含まれており、その合計が奇数であることが保証されます。 
5. 収集したカット位置を出力します。 

重要な不変条件は、i 個のカット位置を選択した後、それぞれに少なくとも 1 つの奇数要素が含まれる i 個のセグメントを作成し、i 番目に選択された奇数インデックスまでのプレフィックスが完全に消費されていることです。 これにより、完成した各セグメントの合計が奇数になり、奇数のアンカーのないセグメントが残らないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    out = []
    
    for _ in range(q):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        odds = []
        for i, x in enumerate(a, start=1):
            if x % 2 == 1:
                odds.append(i)
        
        if len(odds) < k:
            out.append("NO")
            continue
        
        # we use first k-1 odd positions as cut points
        cuts = odds[:k-1]
        
        # last cut must be n
        cuts.append(n)
        
        out.append("YES")
        out.append(" ".join(map(str, cuts)))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは貪欲なアイデアを直接実装しています。 リスト`odds`すべての奇数値要素のインデックスを格納します。 実現可能性チェック`len(odds) < k`各セグメントに少なくとも 1 つの奇数要素が含まれている必要があるという最小要件を強制します。 

カット リストは、最初の k-1 個の奇数インデックスを取得することによって形成されます。 n を追加すると、出力形式で必要な最終的なセグメント境界条件が保証されます。 

微妙な点は、各セグメントの合計を明示的に検証していないことです。 各セグメントにはそのエンドポイントに選択された奇数アンカーが 1 つだけ含まれることが保証されており、セグメント合計パリティが強制的に奇数になるため、これは不要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    q = int(input())
    res = []
    for _ in range(q):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        odds = [i+1 for i,x in enumerate(a) if x % 2 == 1]
        if len(odds) < k:
            res.append("NO")
        else:
            cuts = odds[:k-1] + [n]
            res.append("YES")
            res.append(" ".join(map(str, cuts)))
    return "\n".join(res)

 ## 特殊なケース

 すべての要素が偶数の場合、1 つのエッジ ケースが発生します。 例えば`a = [2,4,6]`すべてのセグメントの合計は偶数であるため、有効なパーティションは存在しません。 奇数のインデックスのリストが空であるため、アルゴリズムはこれを正しく検出し、ただちに失敗します。`len(odds) < k`状態。 

もう 1 つのエッジ ケースは、k が奇数の要素の数に等しい場合です。 例えば`a = [1,2,3]`、k = 2。奇数の位置は [1,3] です。 アルゴリズムは 1 でカットを選択し、3 で最終カットを選択し、セグメントを生成します`[1]`そして`[2,3]`、どちらも奇数の合計です。 これは、最初の k-1 個の奇数位置を使用すると、後戻りや調整を必要とせずにセグメントが自然に位置合わせされることを確認します。
