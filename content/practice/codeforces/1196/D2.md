 ## 解決策
 ## 問題の理解

 R、G、B の文字のみで構成される文字列が与えられています。この文字列から、固定長 k の連続ブロックを選択し、このブロックが無限の繰り返しパターン「RGBRGBRGB...」の一部のセグメントと一致するように文字を変更したいと考えています。 

重要な自由は、文字列内の任意の長さ k のウィンドウを選択できることと、ターゲットとして周期パターンの任意のアラインメントを選択できることです。 各位置合わせは、「RGB」の 3 つの循環シフトの 1 つに対応します。 ターゲット パターンが固定されたら、選択したウィンドウ内で既にそれに一致する位置がいくつあるかを数えます。その他はすべて変更する必要があります。 

したがって、タスクは長さ k のウィンドウと不一致を最小限に抑えるパターンの位相を見つけることになります。 

制約は大きく、すべてのクエリの合計長は最大 200,000 です。これにより、単純な方法でウィンドウごとに不一致を個別に再計算することは直ちに不可能になります。 すべての部分文字列を試して比較を最初から再計算するソリューションは O(nk) のように動作し、両方が大きい場合は非常に遅くなります。 

k が n と等しい場合、微妙なエッジ ケースが発生します。 この場合、ウィンドウは 1 つだけですが、3 つの位相調整すべてを考慮する必要があります。 もう 1 つの特殊なケースは、文字列がすでにパターンと完全に一致しているものの、想定とは異なる位相で開始されるため、位相を誤って修正するアルゴリズムが最適な解決策を見逃す可能性がある場合です。 

## アプローチ

 直接的なアプローチは、長さ k のウィンドウを文字列全体にスライドさせることです。 各ウィンドウについて、繰り返しパターンの 3 つの可能な位置合わせをすべて試します。 固定ウィンドウと固定フェーズの場合、各文字を予想される文字と比較し、不一致をカウントします。 

答えはすべての選択肢にわたって正確に最小の不一致であるため、これは正しく機能します。 ただし、各ウィンドウのコストは O(k) で、ウィンドウが O(n) あり、クエリごとに O(nk) になります。 最悪の場合、k は n に比例するため、これはクエリごとに 2 次になりますが、グローバル制約の下では実現できません。 

重要な観察は、ターゲット パターンが周期 3 で周期的であるということです。これは、どの開始位置でも、期待される文字はインデックス モジュロ 3 と位相シフトのみに依存することを意味します。 ウィンドウごとに比較を再計算する代わりに、文字列全体にわたる 3 つのフェーズごとに不一致配列を事前計算できます。 次に、各ウィンドウ クエリは、これらの配列に対する範囲合計クエリになります。 

具体的には、{0, 1, 2} のフェーズ p ごとに、s[i] がフェーズ p のその位置で予期される文字と異なるかどうかを位置 i に格納する配列を構築します。 これらの配列のプレフィックス合計により、任意のウィンドウで不一致を定数時間で計算できます。 次に、ウィンドウを 1 回スライドさせて、すべての位置とフェーズにわたって最小値を取得します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとに O(nk) | O(1) おまけ | 遅すぎる |
 | フェーズごとのプレフィックスの不一致 | クエリあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. RGB サイクルの 3 つの可能な開始フェーズのそれぞれについて、文字列上に不一致配列を構築します。 インデックス i では、s[i] がそのフェーズで予期される文字と一致しない場合、この配列には 1 が格納され、それ以外の場合は 0 が格納されます。フェーズを分割する理由は、パターンの位置合わせがターゲット文字列の唯一のあいまいさであるためです。 
2. O(1) の任意の区間 [l, r] における不一致の数を計算できるように、各不一致配列をプレフィックス合計配列に変換します。 これにより、ウィンドウごとに文字比較を再計算する必要がなくなります。 
3. 長さ k のウィンドウを文字列内のすべての開始位置にスライドさせます。 開始インデックスごとに、プレフィックスの合計を使用して、3 つのフェーズごとにそのウィンドウ内の不一致数を計算します。 
4. すべてのウィンドウおよびすべてのフェーズにわたって実行最小値を維持します。 この値は、一部の部分文字列を有効な RGB 位置合わせパターン セグメントに一致させるために必要な変更の最小数を表します。 
5. すべてのウィンドウを処理した後の最小値を出力します。 

それが機能する理由: 考えられる有効なソリューションはそれぞれ、ウィンドウの選択とフェーズの選択によって一意に定義されます。 このアルゴリズムは、そのようなすべてのペアを明示的に評価しますが、プレフィックス合計を使用して各評価を O(1) に圧縮します。 不一致のカウントは構成ごとに正確であるため、すべての構成にわたるグローバル最小値が見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    base = "RGB"
    
    for _ in range(q):
        n, k = map(int, input().split())
        s = input().strip()

        # prefix sums for 3 phases
        pref = [[0] * (n + 1) for _ in range(3)]

        for p in range(3):
            for i, ch in enumerate(s):
                expected = base[(i + p) % 3]
                mismatch = 1 if ch != expected else 0
                pref[p][i + 1] = pref[p][i] + mismatch

        ans = k  # worst case: all mismatched

        for l in range(0, n - k + 1):
            r = l + k
            for p in range(3):
                cost = pref[p][r] - pref[p][l]
                if cost < ans:
                    ans = cost

        print(ans)

if __name__ == "__main__":
    solve()
```この実装では 3 つのプレフィックス配列が構築され、各エンコーディングは「RGB」の 1 つの巡回シフトに対して不一致になります。 重要な詳細はインデックス付けです。各フェーズがパターンの異なる配置に対応するように、予期される文字は (i + p) % 3 を使用して計算されます。 

次に、ウィンドウ コストはプレフィックスの差を使用して O(1) で抽出されます。 ウィンドウとフェーズにわたる二重ループは、状態ごとに定数時間の操作のみを実行するため、許容されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    def input():
        return sys.stdin.readline()
    
    q = int(sys.stdin.readline())
    base = "RGB"
    
    for _ in range(q):
        n, k = map(int, sys.stdin.readline().split())
        s = sys.stdin.readline().strip()

        pref = [[0] * (n + 1) for _ in range(3)]

        for p in range(3):
            for i, ch in enumerate(s):
                expected = base[(i + p) % 3]
                pref[p][i + 1] = pref[p][i] + (ch != expected)

        ans = k
        for l in range(n - k + 1):
            for p in range(3):
                ans = min(ans, pref[p][l + k] - pref[p][l])

        output.append(str(ans))
    
    return "\n".join(output)

# provided samples
assert run("3\n5 2\nBGGGG\n5 3\nRBRGR\n5 5\nBBBRR\n") == "1\n0\n3"

# all same char
assert run("1\n4 2\nBBBB\n") == "1"

# already perfect RGB
assert run("1\n3 3\nRGB\n") == "0"

# reverse pattern
assert run("1\n3 3\nGBR\n") == "0"

# k = n case
assert run("1\n5 5\nRGRGR\n") == "1"

 ## 特殊なケース

 最初のエッジ ケースは、文字列全体がシフトされた RGB パターンにすでに一致しているが、デフォルトの位相には一致していない場合です。 たとえば、k = 3 で「GBR」と入力します。アルゴリズムは 3 つのフェーズすべてを正しくチェックするため、そのうちの 1 つで不一致がゼロになります。 開始フェーズが固定されていると想定したソリューションでは、3 つの変更が誤って報告されてしまいます。 

もう 1 つのケースは、「BBBBB」など、すべての文字が同一である場合です。 アライメントを行わないと多くの一致が生成されますが、スライディング ウィンドウは依然として重要です。 プレフィックス配列により、各ウィンドウで不一致が正しく蓄積され、最小ウィンドウ コストが正しく識別されることが保証されます。 

最後に、k が 1 に等しい場合、すべての位置が独自のウィンドウになります。 このアルゴリズムは、どの単一文字が正しい位相位置で R、G、または B のいずれかに最も近いかをチェックすることに帰着します。 各ウィンドウは単一のプレフィックス差分範囲にすぎないため、プレフィックス手法では特別なロジックを使用せずにこれを自然に処理します。
