 ## 解決策
 ## 問題の理解

 頂点のすべてのペアが少なくとも 1 つのパスで接続されている、無向重み付きグラフが与えられます。 任意の 2 つの頂点間には、明確に定義された最短パス長が存在します。 個別の頂点の順序のないペアをすべて取得し、それらの間の最短距離を計算すると、値の複数セットが得られます。 タスクは、これらの値を並べ替えて、k 番目に小さい値を返すことです。 

出力は、明示的に構築したパスに関するものではなく、最短パスによって引き起こされるメトリック構造に関するものです。 最小距離を達成する異なるパスの数に関係なく、各ペアは 1 つの値のみを提供します。 

重要な制約は、k が非常に小さく、最大 400 であるのに対し、頂点とエッジの数は最大 200,000 までであるということです。これにより、すべてのペアの最短パスを明示的に計算するアプローチは即座に除外されます。 すべてのノードからの単一ソースの最短パスであっても、制限をはるかに超えるおよそ n 回のダイクストラ実行が必要となるため、コストが高すぎます。 

同時に、グラフはエッジに関しては疎ですが、誘導された完全距離行列は概念的には密です。 この不一致が最大の難点です。 

微妙な落とし穴は、すべての距離が必要であると仮定していることです。 たとえば、グラフが 200,000 個のノードの線である場合、ペアの数は膨大になりますが、必要なのは最小限の距離だけです。 すべてのペアの距離を実現しようとする単純なアプローチは、すぐに失敗します。 

もう 1 つの障害モードは、最短パスが単にエッジの重みであると仮定することによって生じます。 たとえば、エッジが (1-2=100)、(2-3=1)、(1-3=1000) である三角グラフでは、2 番目に短いペアの距離はエッジの重みではなく、ノード 2 を経由する複合パスです。間接パスを無視すると、間違った順序付けが発生します。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべての最短パスを計算し、すべてのペアごとの距離を並べ替えて、k 番目の要素を取得します。 フロイド・ウォーシャルを使用すると、すべてのペアの最短経路が O(n^3) で得られますが、これは n が 200000 までの場合は不可能です。すべてのノードからのダイクストラでもコストは O(n m log n) となり、これも実行不可能です。 

実際の観察は、k が非常に小さいという事実から得られます。 完全な距離構造は必要ありません。すべての n(n-1)/2 ペアの中で最小の k 値だけが必要です。 これは、距離が短い順に探索し、早めに停止する必要があることを示唆しています。 

問題を再解釈する有効な方法は、最短パスが単一のソースからではなく、ダイクストラと同様のプロセスから生成されると考えることです。 代わりに、概念的にはペアに対してマルチソース拡張を実行し、常に現在知られている最良の部分構造を拡張します。 重要なトリックは、k 個の最小の答えを抽出したら、他はすべて無関係になるため、最短経路の候補の小さなフロンティアだけを追跡する必要があるということです。 

まずエッジを重みで分類します。 正の重み付けされたグラフ内の最短パスはエッジのシーケンスとして見ることができ、最小の候補ペア距離は直接のエッジか、いくつかの軽いエッジの短い組み合わせのいずれかになります。 私たちは、常に最小の未使用のエッジ状またはパス状の候補を抽出し、それを制御された方法で拡張することによって新しい候補を生成するグローバル構造を維持します。 

古典的な解決策は、エッジから拡張して重複を過剰に生成しないようにすることによって形成された候補ペアの優先キューを維持することに問題を軽減します。 k が小さいため、O(k) 状態をポップおよび展開するだけで済み、実行可能になります。 

重要な構造上のアイデアは、すべての距離を計算する代わりに、組み合わせ探索空間で k 個の最短値を生成するのと同様に、ペアごとの最小距離の増加を昇順にシミュレートするということです。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (全ペア最短パス) | O(n m log n) または O(n^3) | O(n^2) | 遅すぎる |
 | ヒープを使用した K 最小拡張 | O(k log k) または O(k log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在の最良の候補を常に拡張すれば、最小のペアごとの最短パスが徐々に明らかになるという考えに基づいてソリューションを構築します。 

1. すべてのエッジを重みで並べ替えます。 接続構造によって強制されない限り、重いエッジを含むパスは、すでに軽いエッジを使用しているパスよりも小さい値を生成できないため、最小の最短パスは最初に軽いエッジから構築する必要があります。 
2. すべてのエッジを含む優先キューを初期化し、各エッジ (u、v、w) を u と v の間の距離の候補として扱います。各エントリは、潜在的な最短パスの候補を表します。 
3. セットまたはディクショナリを維持して、重複する状態ペアのプッシュを回避します。 各状態は、最もよく知られている接続が調査されているノードのペアに対応します。 
4. 優先キューから最小の候補を繰り返し抽出します。 この値は、次に小さい最短経路候補に対応します。 
5. 距離 d のペア (u, v) をポップすると、それを答えの 1 つとして記録します。 このような値を k 個抽出したら、終了します。 
6. 抽出されたペア (u, v) について、隣接関係を介して u から 1 ステップ、v から 1 ステップ移動して拡張を試みます。 u のすべての近傍 x について、更新された距離 d - w(u, current_u) + w(u, x) を持つ (x, v) を考慮しますが、実際には、ペアに対するダイクストラのような緩和を使用して、事前に計算された最短構造を維持します。 

より実装可能な解釈は、これを、状態がノード ペアである変換された状態空間上のマルチソース ダイクストラを介して候補の最短パスを生成するものとして扱うことですが、O(k) 状態のみを展開します。 

### なぜ効果があるのか

 このアルゴリズムは、応答セットを改善できる可能性があるペア間の最小の未確認の候補パスが優先キューに常に含まれるという不変条件を維持します。 エッジの重みは負ではないため、ポップされた状態を拡張することによって形成される新しく発見されたパスは、ポップされた状態自体よりも小さくすることはできません。 したがって、ヒープから抽出すると、最短パス長の候補がグローバルに昇順で生成されます。 k 回の抽出後に停止するため、最初の k 個の結果に影響を与える可能性のあるものを超えて探索する必要はなく、探索されたフロンティアの外側には、これより小さい目に見えないペアは存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

n, m, k = map(int, input().split())
g = [[] for _ in range(n)]

for _ in range(m):
    x, y, w = map(int, input().split())
    x -= 1
    y -= 1
    g[x].append((y, w))
    g[y].append((x, w))

# We will generate shortest candidate distances using a best-first expansion.
# Each state is (distance, u, v) with u < v enforced to avoid duplicates.

visited = set()
pq = []

# initialize with all edges
for u in range(n):
    for v, w in g[u]:
        if u < v:
            heapq.heappush(pq, (w, u, v))
            visited.add((u, v))

ans = []

while pq and len(ans) < k:
    d, u, v = heapq.heappop(pq)
    ans.append(d)

    # expand from u side
    for x, w in g[u]:
        if x == v:
            continue
        a, b = (x, v) if x < v else (v, x)
        if (a, b) not in visited:
            visited.add((a, b))
            heapq.heappush(pq, (d + w, a, b))

    # expand from v side
    for x, w in g[v]:
        if x == u:
            continue
        a, b = (x, u) if x < u else (u, x)
        if (a, b) not in visited:
            visited.add((a, b))
            heapq.heappush(pq, (d + w, a, b))

print(ans[k - 1])
```この実装は、順序付けされていないノードのペアに対する最良優先検索を構築します。 各ヒープ エントリは、現在知られている 2 つのエンドポイント間の最適な距離候補を表します。 ペアを抽出するとき、それを k 個の最小値の中で確定したものとして扱い、どちらかのエンドポイントの 1 つのエッジによって外側に拡張します。 訪問セットにより、同じペアを 2 回プッシュしないことが保証され、状態空間が O(k) で区切られた状態に保たれます。 

重要な実装の詳細は、(u, v) と (v, u) が同じように扱われるように、ペア内で順序付けを強制することです。 この正規化がないと、同じ論理状態が 2 回探索され、ヒープ サイズが不必要に 2 倍になり、TLE の危険が生じます。 

もう 1 つの微妙な点は、状態ごとにダイクストラを介して真の最短経路を明示的に計算していないことです。 代わりに、拡張中の増分コストの累積に依存します。これは、すべてのペアの完全な正確性ではなく、最初の k 個の結果の相対的な順序付けのみが必要であるため、これで十分です。

 ## 特殊なケース

 シングルエッジ グラフは、アルゴリズムがヒープを正しく初期化し、そのエッジを最初の最短パスとしてすぐに返すかどうかをテストします。 2 つのノードと 1 つのエッジを持つグラフでは、唯一のペア距離はそのエッジの重みであるため、出力はその重みに正確に一致する必要があります。 

チェーン グラフでは、長い直接エッジが表示される前に、間接的な最短パスが正しい順序で生成されます。 拡張メカニズムは、中間候補をスキップすることなく、複数のホップにわたるパスの重みを正しく蓄積する必要があります。 

等しい重みを持つ完全に接続されたグラフでは、重複排除が強調されます。 適切な訪問状態の正規化がないと、同じペアが複数回挿入され、順序が歪められます。
