 ## 解決策
 ## 問題の理解

 R、G、B の 3 文字のみからなる文字列が与えられています。この文字列から、固定長の連続したセグメントを見つけたいと考えています。`k`それは繰り返しパターンに可能な限り近いものです`RGBRGBRGB...`。 元の文字列内の文字を変更することができ、変更するたびに 1 つの文字が R、G、B の別の文字に変更されます。目標は、少なくとも 1 つの長さを変更することです。`k`substring は、元の文字列内の変更する文字をできるだけ少なくしながら、無限周期パターンの一部のセグメントに完全に一致します。 

重要なのは文字列全体ではなく、一定の長さのウィンドウが存在するかどうかです。`k`それは、繰り返しサイクルの完全に整列したスライスに変えることができます。 有効なターゲット部分文字列は、サイクル内の開始フェーズを選択すると完全に決定されます。 そのフェーズには、R から開始する、G から開始する、または B から開始するという 3 つの可能性しかありません。 

制約は小さいです。各クエリには次のような制約があります。`n ≤ 2000`、との合計`n`これにより、クエリごとの 3 次またはそれより悪い解は即座に排除されますが、`O(n^2)`気持ちよくアプローチします。 3 つのパターンの定数倍でも問題ありません。 

単純な間違いは、ターゲット パターンが固定されていると想定することです。 たとえば、常に比較すると、`RGBRGB...`R から開始すると、最適な位置合わせが G または B から始まるケースを見逃します。もう 1 つの微妙な問題は、単一の長さだけではなく文字列全体を変更する必要があると仮定していることです。`k`ウィンドウ。 最適なソリューションは、最適なウィンドウ位置と最適なフェーズの選択によって決まります。 

単純な調整による小さな失敗例を示します。 

入力:```
n = 3, k = 3
s = "GBR"
```単に比較してみると`RGB`、2 つの変更が必要です。 しかし、G から始まるパターンに合わせると (`GBRGBR...`)、部分文字列はすでに完全に一致しているため、答えは 0 です。1 つの位相のみを修正する解決策は、誤って過大評価することになります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。長さのすべての部分文字列に対して`k`、無限パターンの 3 つの可能な開始フェーズのそれぞれについて、そのパターンに正確に一致するために変更する必要がある文字の数を数えます。 各ウィンドウについて、不一致を計算します。`RGB...`、`GBR...`、 そして`BRG...`、そして最小限のものを取ります。 

固定ウィンドウの場合、不一致コストの計算には時間がかかります`O(k)`。 がある`O(n)`ウィンドウと 3 つのパターンがあるため、全体の複雑さは`O(3nk)`クエリごとに、最悪の場合は`O(n^3)`。 と`n = 2000`、これでは遅すぎます。 

重要な観察は、フェーズを選択すると、ターゲット パターンが完全に決定的になるということです。 各ウィンドウを個別に再計算する代わりに、各位置および各フェーズの不一致寄与を事前に計算できます。 それからすべての長さ-`k`ウィンドウはスライド範囲にわたる単純な合計になります。 

フェーズごとに問題を評価に変換します`p ∈ {0,1,2}`、位置が一致しない配列`i`性格を期待しています`(RGB)[(i + p) mod 3]`。 次に、各フェーズの不一致のプレフィックス合計を計算します。 各ウィンドウ コストは定数時間範囲クエリになります。 これにより問題は次のように縮小されます`O(3n)`クエリごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | お(1) | 遅すぎる |
 | プレフィックスの不一致 + スライディング ウィンドウ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 R、G、B をサイクル内のインデックス 0、1、2 として扱います。 

1. 文字列内の各文字をインデックス形式に変換して、比較が数値になるようにします。 これにより、周期的なパターン チェックが簡素化されます。 
2. フェーズごとに`p`で`{0, 1, 2}`、文字列全体にわたって不一致配列を構築します。 位置で`i`、期待される文字は`(i + p) % 3`。 実際のキャラクターと異なる場合はコスト 1 をマークします。 それ以外の場合は 0。これにより、パターン マッチングが数値コストの問題に変換されます。 
3. 各フェーズのこの不一致配列に対してプレフィックス合計配列を構築します。 プレフィックスの合計により、O(1) 内の任意の部分文字列の不一致数を計算できます。これは、重複するウィンドウを多数テストするため、非常に重要です。 
4. 一定の長さのウィンドウをスライドさせます`k`文字列を越えて。 スタートポジションごとに`i`、作成コストを計算します。`s[i:i+k]`プレフィックス合計を使用して 3 つのフェーズのそれぞれを照合します。 すべてのフェーズにわたって最小値を取得します。 
5. すべてのウィンドウにわたって最小値を追跡し、出力します。 

プレフィックスの合計が重要な理由は、隣接するウィンドウが重なり合うため、最初から再計算すると同じ作業を繰り返し行うことになるためです。 プレフィックス合計は、繰り返された作業を再利用可能な部分合計に圧縮します。 

### なぜ効果があるのか

 すべての有効なターゲット部分文字列は、文字列内の開始位置と繰り返しサイクル内の位相という 2 つの選択肢によって一意に決定されます。 アルゴリズムは、そのようなすべての組み合わせを暗黙的に評価します。 不一致配列は、各フェーズの各位置の正確な変換コストをエンコードします。 プレフィックス合計は範囲集約の正確さを維持するため、各ウィンドウ コストは近似や省略なしでフェーズごとに 1 回正確に計算されます。 

考えられるすべての候補部分文字列が評価され、各コストが正確に計算されるため、計算されたすべての値の最小値が真のグローバル最小値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    mp = {'R': 0, 'G': 1, 'B': 2}
    pattern = [0, 1, 2]

    for _ in range(q):
        n, k = map(int, input().split())
        s = input().strip()
        a = [mp[c] for c in s]

        best = 10**9

        for p in range(3):
            pref = [0] * (n + 1)

            for i in range(n):
                expected = (i + p) % 3
                pref[i + 1] = pref[i] + (a[i] != expected)

            for i in range(n - k + 1):
                cost = pref[i + k] - pref[i]
                if cost < best:
                    best = cost

        print(best)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に文字を整数にエンコードし、循環比較が 3 を法とする算術になります。各フェーズで、各エントリがそのインデックスまでの不一致をカウントするプレフィックスの合計を構築します。 次に、すべてのウィンドウ コストが 2 つのプレフィックス値の差として計算されるため、部分文字列全体を毎回再計算する必要がなくなります。 フェーズにわたる外側のループは一定のサイズであるため、漸近的な複雑さには影響しません。 

よくある実装の落とし穴は、各フェーズに独自のプレフィックス配列が必要であることを忘れていることです。 1 つの配列を再利用すると、互換性のない不一致の定義が混在し、不正確な結果が生成されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output

    input = sys.stdin.readline

    q = int(input())
    mp = {'R': 0, 'G': 1, 'B': 2}

    for _ in range(q):
        n, k = map(int, input().split())
        s = input().strip()
        a = [mp[c] for c in s]

        best = 10**9

        for p in range(3):
            pref = [0] * (n + 1)
            for i in range(n):
                expected = (i + p) % 3
                pref[i + 1] = pref[i] + (a[i] != expected)

            for i in range(n - k + 1):
                best = min(best, pref[i + k] - pref[i])

        print(best)

    return output.getvalue().strip()

 ## 特殊なケース

 単一文字の場合、たとえば、`s = "R", k = 1`、アルゴリズムは各フェーズの不一致を計算します。 フェーズ 0 では、期待値は R であるため、コストは 0 となり、単一要素ウィンドウに対するプレフィックスの減算は正しく 0 を返します。 他のフェーズではコスト 1 が生成されるため、最小値は正しく 0 になります。 

次のような完全に均一な文字列の場合`BBBBBB`と`k = 3`、すべてのウィンドウが 3 つのフェーズすべてに対して評価されます。 不一致配列は位置ごとの差異を正確にカウントし、プレフィックスの差により、各ウィンドウ コストが不一致文字の数を正確に反映することが保証されます。 すべてのウィンドウが重なり合っているにもかかわらず、それぞれがプレフィックス合計を通じて独立して評価され、二重にカウントされることなく正確性が維持されます。
