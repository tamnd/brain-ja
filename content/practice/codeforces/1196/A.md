 ## 解決策
 ## 問題の理解

 各クエリでは 3 つのキャンディーの山が得られます。 アリスは 1 つの山全体を取得し、ボブは残りの山の 1 つを取得する必要があり、最後の山は任意にそれらの間で分割できます。 

配布後、一方がもう一方よりも多くのキャンディーを持っている場合、余分なキャンディーは単に破棄することができます。 最終的な結果は、両方の人が同じ数のキャンディーを手に入れることになります。 私たちの目標は、その共通数を最大化することです。 

重要な観察は、廃棄されたキャンディーが許可されていることです。 すべてのキャンディーを使用する必要はありません。 必要なのは、アリスとボブの両方が保持できる量を最大化することだけです。 

クエリ数は最大でも 1000 件と非常に少ないです。 ただし、各パイルには最大で$10^{16}$キャンディーなので、山のサイズ自体に依存するアルゴリズムは不可能です。 クエリごとに一定時間で評価できる直接的な数式が必要です。 

よくある間違いは、答えが常にキャンディーの総数の半分であると想定することです。 杭を考慮してください$(1,1,100)$。 合計は$102$、つまり半分は$51$。 しかし、2つの小さな山には、$2$全部キャンディー。 1人で山を受け取ることができます$100$、でも相手は届かない$51$キャンディーだけだから$2$キャンディーは最大の山の外側に存在します。 正しい答えは、$2$。 

もう 1 つの簡単な間違いは、最大の山が答えを直接制限すると考えることです。 考慮する$(4,4,4)$。 最大の山にはサイズがあります$4$、それでも答えは$6$。 アリスが受け取れる$4$一つの山から、$2$残りの山からボブがもう一方を受け取ります$4$そしてもう一つは$2$。 

3 番目のエッジケースは、1 つの山が他の山を支配する場合に発生します。 のために$(1,10,100)$、合計は$111$したがって、理論上の上限は次のようになります。$\lfloor 111/2 \rfloor = 55$。 この値は達成可能であり、答えが得られます。$55$。 

## アプローチ

 ブルートフォースの観点は、考えられるすべての割り当てを試すことです。 アリスがどの山を取るか、ボブがどの山を取るかを選択し、残りの山を分割するためのあらゆる方法を検討することができます。 

すべての有効な分布が検査されるため、この推論は正しいです。 問題は、残りの山には最大で$10^{16}$したがって、考えられるすべての分割を列挙することは完全に不可能です。 

前進するには、実際に最終的な等価額を制限するものは何なのかを考える必要があります。 

パイルのサイズがソートされているとします。$$a \le b \le c.$$させて$$S = a+b+c.$$二人とも同じ金額で終わるので$x$、彼らは一緒に保ちます$2x$キャンディー。 彼らは存在する以上のキャンディーを保持することはできません。$$2x \le S,$$それは与える$$x \le \left\lfloor \frac{S}{2} \right\rfloor.$$これが最初の上限です。 

もう一つあります。 両方の人に与えるために$x$少なくともキャンディーは$x$最大の山は多くてもそのキャンディのすべてを片側に提供するため、キャンディは 2 つの小さな山を組み合わせたものでなければなりません。 最大の山の外側の合計金額は、$$a+b.$$したがって、$$x \le a+b.$$重要な制限はこれらのみです。 もし$$x \le \min\left(a+b,\left\lfloor \frac{S}{2}\right\rfloor\right),$$そうすれば、そのような分布はいつでも構築できます。 

したがって、答えは単純です$$\min\left(a+b,\left\lfloor \frac{a+b+c}{2}\right\rfloor\right),$$そうするように並べ替えた後$c$一番大きな山です。

 ## アルゴリズムのチュートリアル

 1. 3 つのパイルのサイズを読み取ります。 
2. 次のように並べ替えます。$a \le b \le c$。 
3. キャンディーの総数を計算します。$$S=a+b+c.$$4. 最初の上限を計算します。$$\left\lfloor \frac{S}{2} \right\rfloor.$$同じ量で終了する 2 人が一緒に存在する以上のキャンディーを保持することはできません。 
5. 2 番目の上限を計算します。$$a+b.$$2 つの小さな山には、$a+b$キャンディーの合計が含まれるため、最終的な同量がこの値を超えることはできません。 
6. 出力$$\min\left(a+b,\left\lfloor \frac{S}{2}\right\rfloor\right).$$### なぜ効果があるのか

 値$x$超えることはできません$\lfloor S/2 \rfloor$しかないから$S$キャンディーが入手可能。 それも超えることはできません$a+b$なぜなら、最大の山だけでは両方の参加者に十分なキャンディーを提供できないからです。 

これら 2 つの不等式により上限が決まります。$$x \le \min\left(a+b,\left\lfloor \frac{S}{2}\right\rfloor\right).$$この限界は常に達成可能です。 最大の山が非常に大きい場合、$a+b$が制限要因となります。 それ以外の場合は、キャンディーの総数が制限要因になります。 いずれの場合も、残りの山を適切に分割して、その値を正確に実現できます。 したがって、この式は上限であると同時に達成可能な値でもあり、正しさを証明しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

q = int(input())

for _ in range(q):
    a, b, c = map(int, input().split())
    a, b, c = sorted((a, b, c))

    total = a + b + c
    print(min(a + b, total // 2))
```実装は数式に直接に従います。 

3 つの値は、最大の山が常に次の場所に格納されるようにソートされます。`c`。 これにより数量を特定できるようになります`a + b`、これは最大の山の外側にあるキャンディーの総数です。 

値`total // 2`キャンディーの総数のみが重要な場合、 は可能な最大の均等シェアを表します。 

答えは、これら 2 つの限界の最小値です。 

Python の整数は、以下よりもはるかに大きな値を自動的に処理します。$10^{16}$なので、オーバーフローは心配ありません。 ソリューション全体では、クエリごとに数回の算術演算のみを使用します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    q = int(input())

    ans = []
    for _ in range(q):
        a, b, c = map(int, input().split())
        a, b, c = sorted((a, b, c))
        ans.append(str(min(a + b, (a + b + c) // 2)))

    return "\n".join(ans) + "\n"

 ## 特殊なケース

 次の入力を考えてみましょう。```
1
1 1 100
```並べ替えた後、$a=1$、$b=1$、$c=100$。 アルゴリズムは以下を計算します。$$a+b=2,$$

$$\left\lfloor \frac{102}{2} \right\rfloor = 51.$$答えは$\min(2,51)=2$。 

このケースは、全体の半分だけを使用することがなぜ間違っているのかを示しています。 ほとんどすべてのキャンディーが 1 つの山の中に閉じ込められています。 

次に、次のことを考えてみましょう。```
1
4 4 4
```アルゴリズムは以下を計算します。$$a+b=8,$$

$$\left\lfloor \frac{12}{2} \right\rfloor = 6.$$答えは$6$。 

最大の山だけを見る単純な戦略では、次のように予測される可能性があります。$4$、小さすぎます。 残りのパイルを分割すると、両方の参加者が個々のパイルのサイズを超えることができます。 

最後に、次のことを考慮してください。```
1
2 3 5
```アルゴリズムは以下を計算します。$$a+b=5,$$

$$\left\lfloor \frac{10}{2} \right\rfloor = 5.$$答えは$5$。 

この境界ケースは、両方の上限が等しい場合です。 アルゴリズムは特別なロジックを必要とせずに自然に処理します。
