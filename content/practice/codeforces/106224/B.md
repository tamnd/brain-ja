 ## 解決策
 ## 問題の理解

 左から右にインデックスが付けられたフィールドの行が与えられます。 このラインの上に、事前にプログラムされた散布ルートがいくつかあります。 各ルートは間隔であり、連続するセグメント内のすべての畑に肥料を与えることを意味します。$[L_i, R_i]$。 

クエリはすべてのルートについて尋ねるわけではありません。 代わりに、インデックスからルートの連続したブロックを選択します。$X$に$Y$、概念的にはそれらのスプレーのみを適用します。 選択された各ルートはその間隔を完全にカバーし、少なくとも 1 つの選択された間隔がフィールドをカバーする場合にその畑が肥沃であるとみなされることを除いて、重複するスプレーは特別な方法でスタックしません。 タスクは、クエリごとに、選択した間隔の少なくとも 1 つによって最終的にカバーされるフィールドの数を計算することです。 

重要な構造は、間隔の部分配列を繰り返し取得し、固定された座標軸上でそれらの和集合の全長を求めることです。 これは「間隔の範囲、部分範囲のクエリ結合の長さ」の問題であり、アクティブな間隔のセットがクエリごとに変化するため、標準の静的結合よりも困難です。 

この制約は、フィールドの数と間隔とクエリの数の両方が、次のオーダーで大きくなる可能性があることを意味します。$10^5$。 クエリごとにユニオンを最初から再計算するソリューションでは、最大でマージが必要になります。$10^5$クエリごとの間隔。これはすぐに時間制限を超えます。 たとえ$O(N)$クエリごとのアプローチにより、$10^{10}$最悪の場合は運用が不可能になります。 

間隔が重なり合うと、微妙なエッジケースが現れます。 たとえば、すべての間隔が$[1, F]$、どのクエリでも返されるはずです$F$選択された間隔の数に関係なく。 単純なソリューションでは、マージされた表現を明示的に維持しない場合、誤って重複を複数回カウントする可能性があります。 

別の失敗例は、間隔が互いに素であるが、クエリ範囲内でインターリーブされている場合に発生します。 たとえば、間隔$[1,2], [3,4], [5,6]$、およびそれらすべてを選択するクエリでは、慎重にマージする必要があります。 ここでは単純に長さを合計すると正しい答えが得られますが、それは重複がないためです。 混合オーバーラップ パターンでは、単純な合計が壊れます。 

## アプローチ

 ブルートフォースのアイデアは単純です。クエリごとに、すべての間隔を取得します。$[X, Y]$、それらを左側のエンドポイントで並べ替えて、結合にマージします。 現在のアクティブなセグメントを維持し、間隔が重なるたびにそれを拡張します。 これは正しいです。なぜなら、直線上の間隔の和集合は、ソートとマージによって常に計算できるからです。 

問題はコストです。 各クエリは次のような影響を受ける可能性があります$O(N)$間隔があり、それらを並べ替えるにはコストがかかります$O(N \log N)$クエリごとに。 グローバルに事前ソートすることでソートを回避したとしても、抽出してマージする必要があります。$O(N)$クエリごとの間隔、$O(NQ)$行動。 と$10^5$クエリを実行すると、これは完全に不可能になります。 

重要な観察は、間隔の形状を変更していないということです。 インデックスのどのサブセットがアクティブであるかを変更するだけです。 これは、間隔のインデックス空間上にデータ構造を構築することを示唆しています。 セグメント ツリーの各ノードは区間インデックスの連続ブロックを表し、そのブロックについて、すべての区間の和集合をフィールド軸上の互いに素なセグメントとして圧縮形式で保存します。 この構造が構築されると、クエリ$[X, Y]$組み合わせだけで答えられる$O(\log N)$範囲内のすべての間隔を反復する代わりに、ノードを実行します。 

これが機能するのは、労働組合の労働組合が依然として労働組合であるためです。 各ノードが、すでに素の区間にマージされた寄与を格納している場合、2 つのノードをマージするには、素のセグメントの 2 つのソートされたリストをマージするだけでよく、結合サイズは線形です。 各間隔が次の影響を受けるため、ツリー全体のすべてのセグメント リストの合計サイズは管理可能なままです。$O(\log N)$ノード。

 ## アルゴリズムのチュートリアル

 間隔のインデックス範囲にわたってセグメント ツリーを構築します。 

1. 各リーフノードは単一の間隔に対応します$[L_i, R_i]$、1 つのセグメントを含むリストとして保存されます。 単一の区間は自明のことながら 1 つのセグメントの結合であるため、このリストはすでに「圧縮」されています。 
2. 各内部ノードは間隔の範囲を表します。 その値は、その左の子のすべての間隔と右の子のすべての間隔の和集合であり、フィールド軸上の互いに素なセグメントの並べ替えられたリストとして表現されます。 これを構築するには、2 つの子のセグメント リストをマージします。 
3. 2 つのノードをマージするということは、両方のソートされたリストを調べて、重複または隣接するセグメントを単一の連続セグメントに結合することを意味します。 このステップは、2 つの間隔セットの和集合を計算することと同じです。 
4. 完全なセグメント ツリーを構築した後、各ノードはそのセグメント ブロックの完全な結合を格納します。 
5. 質問に答えるため$[X, Y]$、この範囲を次のように分解します。$O(\log N)$ツリー ノードをセグメント化し、それらの事前計算された間隔リストを収集し、それらを最終的な結合にマージします。 
6. 答えは、最終的に結合されたリスト内のすべての互いに素なセグメントの長さの合計です。 

正確さは、すべてのレベルで、各ノードがそのセグメント範囲内のすべての間隔の和集合を正確に表すという事実から得られます。 結合は結合であるため、ノードの結果を任意の順序で結合しても、選択したすべての間隔の結合が生成されます。 

不変条件は、すべてのセグメント ツリー ノードがそのサブツリー内のすべての間隔の正確な、完全にマージされた表現を格納することです。 2 つの正しい共用体表現をマージすると、別の正しい共用体表現が生成されるため、このプロパティはビルド全体にわたって保持されます。 クエリ分解では間隔が欠落したり重複したりすることはないため、最終的にマージされたリストは、すべての間隔の和集合と正確に一致します。$[X, Y]$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, intervals):
        self.n = len(intervals)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.data = [[] for _ in range(2 * self.size)]

        for i, (l, r) in enumerate(intervals):
            self.data[self.size + i] = [(l, r)]

        for i in range(self.size - 1, 0, -1):
            self.data[i] = self.merge(self.data[2 * i], self.data[2 * i + 1])

    def merge(self, a, b):
        if not a:
            return b
        if not b:
            return a

        res = []
        i = j = 0

        def add(seg):
            if not res:
                res.append(seg)
            else:
                l, r = res[-1]
                if seg[0] <= r:
                    res[-1] = (l, max(r, seg[1]))
                else:
                    res.append(seg)

        while i < len(a) and j < len(b):
            if a[i][0] < b[j][0]:
                add(a[i])
                i += 1
            else:
                add(b[j])
                j += 1

        while i < len(a):
            add(a[i])
            i += 1
        while j < len(b):
            add(b[j])
            j += 1

        return res

    def query(self, l, r):
        l += self.size
        r += self.size + 1

        left_res = []
        right_res = []

        def merge_into(res, segs):
            for seg in segs:
                if not res:
                    res.append(seg)
                else:
                    l0, r0 = res[-1]
                    if seg[0] <= r0:
                        res[-1] = (l0, max(r0, seg[1]))
                    else:
                        res.append(seg)

        while l < r:
            if l & 1:
                merge_into(left_res, self.data[l])
                l += 1
            if r & 1:
                r -= 1
                merge_into(right_res, self.data[r])
            l //= 2
            r //= 2

        total = left_res + right_res[::-1]
        if not total:
            return 0

        merged = []
        for seg in total:
            if not merged:
                merged.append(seg)
            else:
                l0, r0 = merged[-1]
                if seg[0] <= r0:
                    merged[-1] = (l0, max(r0, seg[1]))
                else:
                    merged.append(seg)

        return sum(r - l for l, r in merged)

def main():
    F = int(input())
    N = int(input())
    intervals = [tuple(map(int, input().split())) for _ in range(N)]
    seg = SegTree(intervals)

    Q = int(input())
    out = []
    for _ in range(Q):
        x, y = map(int, input().split())
        out.append(str(seg.query(x - 1, y - 1)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```セグメント ツリーはボトムアップで構築されるため、すべてのノードには正規化された間隔の結合がすでに格納されています。 これにより、クエリ中に繰り返し再計算が行われることがなくなります。 マージ ルーチンは、ソートされた互いに素なセグメントを慎重に維持します。これは、長さを効率的に計算する際の正確性のために不可欠です。 

よくある実装上の落とし穴は、境界に接する間隔をマージし忘れることです。 以来$[1,2]$そして$[3,4]$互いに素であるため、結合すべきではありませんが、$[1,2]$そして$[2,5]$にマージする必要があります$[1,5]$エンドポイントが包括的かどうかに応じて異なります。 ここではエンドポイントが包括的であるため、重複または隣接性を一貫して扱う必要があります。 

## 実用的な例

 次の小さな例を考えてみましょう$F = 6$と間隔$[1,3], [2,4], [5,6]$。 3 つすべてを選択してクエリを処理します。 

| ステップ | アクティブ構造 | マージされたセグメント |
 | --- | --- | --- |
 | リーフ マージ 1 | [1,3] | [1,3] |
 | リーフマージ2 | [1,3] + [2,4] | [1,4] |
 | 最終マージ | [1,4] + [5,6] | [1,4]、[5,6] |

 最終的な答えは、$4 + 2 = 6$、完全なカバレッジを示しています。 

次に、クエリのみを選択する場合を考えてみましょう。$[2,4]$そして$[5,6]$。 

| ステップ | アクティブ構造 | マージされたセグメント |
 | --- | --- | --- |
 | 最初の間隔 | [2,4] | [2,4] |
 | 2 番目の | を追加 [5,6] | [2,4]、[5,6] |

 結果は$3 + 2 = 5$、不連続なセグメントが誤ってマージされることなく処理されることを確認します。 

これらのトレースは、重複パターンに関係なく、構造が一貫して共用体のセマンティクスを保持していることを示しています。

 ## 特殊なケース

 一般的なエッジ ケースは、クエリ内のすべての間隔が同一である場合です。たとえば、すべての間隔が$[1, F]$。 セグメント ツリー ノードはすべて同じマージされたセグメントに折りたたまれるため、クエリは正しく返されます。$F$二重カウントなしで。 

別のエッジケースは、間隔が境界でのみ接触する場合に発生します。たとえば、$[1,2]$そして$[2,3]$。 エンドポイントは包括的であるため、マージ ステップではそれらを重複しているものとして扱う必要があります。そうしないと、答えが誤って次のようになります。$2 + 2 = 4$の代わりに$3$。 マージ ルーチンは明示的にチェックします`seg[0] <= r0`これにより、境界に接するセグメントが正しくマージされます。 

3 番目のケースは、クエリが単一の間隔を選択する場合です。 その状況では、クエリ分解により 1 つのリーフ ノードが返され、正規化以外のマージは必要ありません。 出力は単純な間隔の長さであり、意図した定義と直接一致します。
