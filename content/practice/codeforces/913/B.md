 ## 解決策
 ## 問題の理解

 1 から _n_ までの番号が付けられた頂点を持つルート ツリーが与えられます。 頂点 1 は常にルートです。 1 つおきの頂点について、入力によりその親がわかり、ツリー構造が完全に定義されます。 

頂点に子がなく、ルートではない場合、頂点はリーフとみなされます。 すべての葉以外の頂点に、それ自体が葉である少なくとも 3 つの子がある場合、その木はスプルースと呼ばれます。 

タスクは、指定されたツリーがこの条件を満たすかどうかを判断するだけです。 すべての非リーフ頂点に少なくとも 3 つのリーフの子がある場合は、次のように出力します。`"Yes"`。 それ以外の場合は印刷します`"No"`。 

制約は非常に小さいです。 ツリーには最大 1000 個の頂点が含まれます。 すべての頂点とそのすべての子を検査するアルゴリズムであっても、制限内で快適に実行できます。 高度なツリー アルゴリズム、再帰トリック、または重い前処理は必要ありません。 

主な課題は、状態を正しく解釈することです。 葉であるすべての子孫をカウントしているわけではありません。 葉である直接の子のみをカウントします。 

次の例を考えてみましょう。```
5
1
1
2
2
```ツリーは次のとおりです。```
1
├─2
│ ├─4
│ └─5
└─3
```頂点 1 には、頂点 3 というリーフの子が 1 つだけあります。頂点 4 と 5 はリーフですが、これらは 1 の孫であり、子ではありません。 正しい答えは次のとおりです。```
No
```リーフの子ではなくリーフの子孫をカウントする不用意な実装は、このツリーを誤って受け入れてしまいます。 

もう 1 つの微妙なケースは、内部頂点に多くの子があるが、それらの子のうちの十分な数が葉ではない場合です。```

```頂点 2 には 3 つのリーフの子があるため、有効です。 頂点 1 には、頂点 3 と 4 の 2 つのリーフの子しかありません。正解は次のとおりです。```
No
```不注意な解決策では、ルートのみをチェックしたり、リーフの子の代わりに子を合計でカウントしたりする可能性があります。

```ルートには 3 つの葉の子があるため、答えは次のようになります。```
Yes
```条件は「少なくとも 3 つ」なので、正確に 3 つを受け入れる必要があります。 

## アプローチ

 最も直接的なアプローチは、リーフではない頂点をすべて調べて、その子のうちのいくつがリーフであるかを数えることです。 

ブルートフォース バージョンでは、毎回すべての頂点をスキャンすることで、子がリーフであるかどうかを判断できます。 すべての頂点、すべての子について、ツリー全体を検索して、その子に独自の子があるかどうかを確認します。 _n_ 個の頂点がある場合、これはおよそ _O(n²)_ 個の作業につながります。 

_n = 1000_ の場合、_O(n²)_ であっても許容されます。 約 100 万回の操作は十分に制限内です。 

さらにクリーンなアプローチがあります。 入力を読み取りながら、すべての頂点の子を含む隣接リストを構築します。 この構造を取得すると、頂点が葉であるかどうかを判断するのは簡単になります。頂点は、子のリストが空の場合にまさに葉になります。 

重要な観察は、トウヒの状態が直接の子にのみ依存するということです。 サブツリーを走査したり、深さを計算したりする必要はありません。 各内部頂点について、独自の子を持たない子の数を単純に数えます。 

これにより、すべての隣接リストに対するソリューションが 1 回のパスに短縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 承認済み |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 頂点の数を読み取ります。 
2. すべての頂点の子リストを作成します。 頂点ごとに`i`2から`n`、その親を読み取ります`p`そして追加します`i`に`children[p]`。 
3. すべての頂点を反復処理します。 
4. 頂点に子がない場合、それはリーフです。 トウヒの条件は葉には適用されないため、スキップします。 
5. リーフ以外の頂点ごとに、その直接の子のうちのいくつがリーフであるかを数えます。 子は、それ自体の子リストが空の場合にのみリーフになります。 
6. リーフ以外の頂点のこの数が 3 未満の場合、次のように出力します。`"No"`そしてすぐにやめてください。 
7. すべての非リーフ頂点がチェックに合格した場合、出力します。`"Yes"`。 

### なぜ効果があるのか

 頂点がスプルースの定義に違反するのは、それが内部頂点であり、その直接の子の葉が 3 つ未満である場合に限ります。 

アルゴリズムは、すべての内部頂点についてこの条件を正確にチェックします。 定義ではリーフに制限が設けられていないため、すべてのリーフは無視されます。 すべての内部頂点が 1 回検査され、葉の子の数が定義に従って正確に計算されます。 

アルゴリズムが出力する場合`"No"`、一部の内部頂点が要件を満たしていないため、ツリーをトウヒにすることはできません。 アルゴリズムが出力する場合`"Yes"`、すべての内部頂点が要件を満たし、スプルースの定義と一致します。 したがって、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

children = [[] for _ in range(n + 1)]

for v in range(2, n + 1):
    p = int(input())
    children[p].append(v)

for v in range(1, n + 1):
    if not children[v]:
        continue

    leaf_children = 0

    for child in children[v]:
        if not children[child]:
            leaf_children += 1

    if leaf_children < 3:
        print("No")
        sys.exit()

print("Yes")
```最初の部分では、ルート付きツリーを隣接リストとして構築します。 入力によって各頂点の親が直接与えられるため、子のリストの構築は簡単です。 

2 番目の部分では、すべての頂点を反復処理します。 空の子リストを持つ頂点はリーフであるため、スキップされます。 

コードは内部頂点ごとに、空の子リストを持つ子の数をカウントします。 これらはまさに定義で必要とされるリーフの子です。 

頂点にある葉の子が 3 つ未満になった瞬間、答えは次のようになります。`"No"`, そのため、プログラムは早期に終了します。 ループが終了すると、すべての内部頂点が条件を満たし、答えは次のようになります。`"Yes"`。 

よくある間違いは、直接のリーフの子ではなく、すべてのリーフの子孫をカウントすることです。 実装では、頂点のみを検査することでこれを回避します。`children[v]`。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    children = [[] for _ in range(n + 1)]

    for v in range(2, n + 1):
        p = int(input())
        children[p].append(v)

    for v in range(1, n + 1):
        if not children[v]:
            continue

        cnt = 0
        for child in children[v]:
            if not children[child]:
                cnt += 1

        if cnt < 3:
            print("No")
            return

    print("Yes")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return out

# provided sample
assert run("4\n1\n1\n1\n") == "Yes", "sample 1"

# minimum valid tree
assert run("4\n1\n1\n1\n") == "Yes", "minimum spruce"

# root has only two leaf children
assert run("3\n1\n1\n") == "No", "root needs at least three leaf children"

# internal node valid, root invalid
assert run("7\n1\n1\n1\n2\n2\n2\n") == "No", "count only immediate leaf children"

# larger valid tree
assert run("8\n1\n1\n1\n2\n2\n2\n1\n") == "Yes", "all internal vertices satisfy condition"

# chain structure
assert run("4\n1\n2\n3\n") == "No", "every internal vertex fails"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`4 / 1 1 1`| はい | ちょうど 3 つの葉の子があれば十分です。 
|`3 / 1 1`| いいえ | 葉の子を 2 つだけ持つルート |
 |`7 / 1 1 1 2 2 2`| いいえ | リーフの子孫はカウントされません。 
|`8 / 1 1 1 2 2 2 1`| はい | 複数の内部頂点はすべてルールを満たすことができます |
