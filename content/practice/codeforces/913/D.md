 ## 解決策
 ## 問題の理解

 私たちには一連の試験問題が与えられており、それぞれに解答時間と、スコアに寄与するかどうかを制御する「厳密さの制限」が設定されています。 合計時間が試験時間を超えない限り、問題のサブセットを選択して解くことができます。 ただし、得点は単に解けた問題の数ではありません。 合計 k 個の問題を解決した場合、解決された問題は、それ自体の制限が少なくとも k である場合にのみポイントに貢献します。 したがって、スコアは、選択したセットの最終的なサイズと、選択した問題のうちのどれだけがそのサイズに「耐えられる」かによって決まります。 

目標は、合計時間 T に適合するサブセットを選択し、この k 依存の条件下で有効なまま選択された問題の数を最大化することです。 

入力サイズ n は最大 200,000 まで可能で、指数サブセット検索は除外されます。 O(n²) のアプローチでも、最悪の場合はすでに遅すぎます。 時間値は、並べ替えや貪欲な構造には十分小さいですが、すべてのサブセットにわたるネストされたシミュレーションには十分ではありません。 

速い問題を選択することだけに焦点を当てたり、カウントを最大化することだけに焦点を当てた場合、単純な落とし穴が発生します。 たとえば、k 個の最小時間問題を選択しても、それらの多くが十分に大きな aᵢ を持つことは保証されません。 同様に、高い aᵢ 値のみを選択すると、時間の実現可能性が無視されます。 サブセットのサイズと有効性のしきい値の間の相互作用が重要な問題です。 

微妙なエッジ ケースは、新しい問題を追加すると k が増加し、以前は有効だった選択肢が無効になる場合です。 たとえば、現在 k が 2 で、aᵢ = 2 の選択された問題があるとします。これは依然として有効です。 別の問題を追加すると、k は 3 になり、同じ問題は無効になります。 正しいアルゴリズムは、このフィードバック ループを予測する必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのサブセットを試し、合計時間を計算し、aᵢ ≥ k を満たす選択された問題の数を確認することでスコアを評価します。 これは定義に直接従うため正しいですが、2ⁿ のサブセットを調査します。 n が 200,000 に達すると、23⁰ さえも実行不可能になるため、このアプローチはすぐに破綻します。 

重要な観察は、視点を逆転させることです。 サブセットを選択して後で k を計算する代わりに、k を修正して尋ねることができます。合計時間が ≤ T で、そのうち少なくとも k 個が aᵢ ≥ k を満たすような k 個の問題を選択することは可能ですか? しかし、k 個の選択されたアイテムをすでに修正している場合、それらのすべてが aᵢ ≥ k を満たす必要があり、そうでない場合はスコアに貢献できません。 これにより、合計時間を最小限に抑えながら、aᵢ ≥ k を満たす問題から k 個の「適格な」問題を選択するように問題が変換されます。 

固定 k の場合、最適な方法は明らかです。aᵢ ≥ k のすべての問題の中で、最小の k 個の tᵢ 値を選択します。 それらの合計が ≤ T であれば、k は実行可能です。 各 k の実現可能性をテストし、最大値を取得できます。 これを効率的に行うために、問題を aᵢ で分類し、k が減少するにつれて適格な問題の中で最小時間を追跡する構造 (通常は最小ヒープまたはマルチセット) を維持します。 

k を n から 1 まで繰り返し、徐々により多くの問題をアクティブにします (k が減少すると aᵢ ≥ k が容易になるため)。 候補時間の最小ヒープを維持し、選択された k 個の最小時間の累計を保持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2ⁿ・n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 考えられるすべての最終サイズ k を最大から最小までチェックし、使用可能な問題のプールを維持するという問題を再構成します。

1. 問題を aᵢ の降順に並べ替えます。 これにより、k が大きくなるとより厳しい要件が課されるため、k が減少するにつれて問題が発生することが可能になります。 
2. 現在適格な問題の時間コストを保存する空の最小ヒープを初期化します。 また、選択した時間の合計を追跡する変数と、k 個の最小時間を維持するための 2 番目のヒープまたは構造も維持します。 
3. k = n から開始して 1 まで下方向に移動します。各 k で、aᵢ が k に等しいすべての問題をプールに追加します。 これらは、サイズ k 以下のあらゆるソリューションに適用できるようになりました。 
4. 現在のプールについて、最小の合計時間で k 個の問題を選択できるかどうかを知りたいと考えています。 対象項目の中から常に最小のk回を抽出できる仕組みを維持しています。 一般的なトリックは、適格な時間をすべてサイズ k の最大ヒープにプッシュし、大きい値を破棄して k 個の最小値のみを保持することです。 
5. この k の候補を挿入した後、ヒープ内に少なくとも k 個の要素がある場合は、それらの合計を計算します。 それが T を超えない場合、k を実行可能として記録し、現在の選択を保存します。 
6. k が減少するにつれて実現可能性が容易になるため、実現可能な最初の k (大きいものから小さいものまで) が最大の答えになります。 

### なぜ効果があるのか

 任意の固定 k の場合、有効な解は aᵢ ≥ k の問題のみで構成されなければなりません。 これらの中で、合計時間を最小化することは、k 個の最小の tᵢ 値を選択することと同じです。 このアルゴリズムにより、各 k について、この最適なサブセットが効果的に正確に維持されることが保証されます。 k を降順にチェックするため、最初に実現可能な k が最大となり、それより大きな k は実現可能ではありません。 

重要な不変条件は、各ステップ k において、これまでに検討された aᵢ ≥ k のすべての問題の中で最小の k 回の時間がヒープに含まれるということです。 これにより、実現可能性のチェックが近似的ではなく正確であることが保証されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, T = map(int, input().split())
    problems = [[] for _ in range(n + 1)]
    
    for i in range(n):
        a, t = map(int, input().split())
        problems[a].append((t, i + 1))
    
    heap = []
    total_time = 0
    best_k = 0
    best_set = []
    
    # We maintain a max-heap using negative values to keep k smallest times
    current = []
    
    for k in range(n, 0, -1):
        for t, idx in problems[k]:
            heapq.heappush(current, -t)
            total_time += t
            
            if len(current) > k:
                removed = -heapq.heappop(current)
                total_time -= removed
        
        if len(current) == k and total_time <= T:
            best_k = k
            best_set = [idx for _, idx in [( -x, -1) for x in current]]  # placeholder rebuild
    
    # Reconstruct properly for best_k
    heap = []
    total_time = 0
    res = []
    
    for k in range(n, 0, -1):
        for t, idx in problems[k]:
            heapq.heappush(heap, (t, idx))
        
        if len(heap) >= best_k:
            temp = heapq.nsmallest(best_k, heap)
            if sum(t for t, _ in temp) <= T:
                res = [idx for _, idx in temp]
                break
    
    print(best_k)
    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```最初のフェーズでは、aᵢ 値に基づいて問題のグループを構築し、制約を徐々にアクティブにできるようにします。 第 2 フェーズでは、候補時間のヒープを維持し、より大きな時間は実現可能性を損なうだけであるため、関連する最小のもののみを保持します。 

実装の微妙な詳細は、k ごとに個別に k サイズの構造を直接維持できないことです。 代わりに、最初から再計算することなく、すべての k 値の正確性を保証する増分挿入と枝刈りに依存します。 

k ごとに正確なメンバーシップを保存するとコストがかかるため、再構成ステップは分離されます。 代わりに、k がわかったら、実行可能な最良のセットを再計算します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from math import inf

    n, T = map(int, sys.stdin.readline().split())
    probs = []
    for i in range(n):
        a, t = map(int, sys.stdin.readline().split())
        probs.append((a, t, i + 1))

    best_k = 0
    best_set = []

    for k in range(n, 0, -1):
        cand = [t for a, t, i in probs if a >= k]
        cand.sort()
        if len(cand) >= k and sum(cand[:k]) <= T:

            break

    eligible.sort()

    return f"{best_k}\n{len(chosen)}\n" + " ".join(str(i) for _, i in chosen)

 ## 特殊なケース

 すべての問題の aᵢ が非常に小さい場合 (たとえば、すべて 1 に等しい場合)、クリティカルなエッジ ケースが発生します。この場合、選択されたすべての問題が k ≤ 1 である必要があるため、k ≥ 2 の解は時間に関係なく自動的に無効になります。より高い k 値の候補が存在しないため、アルゴリズムは k > 1 を実行可能とは決して考慮せず、これを正しく処理します。 

もう 1 つの特殊なケースは、時間が非常に長いにもかかわらず、aᵢ 値が制限されている場合に発生します。 すべての問題を時間内に解決できたとしても、スコアは選択した項目の中で最も小さい aᵢ によって制限されます。 実現可能性は常に aᵢ ≥ k によってゲートされ、スコアの過大評価を防ぐため、アルゴリズムはこれを自然に反映します。 

最後に、1 つの問題が非常に長い時間を持つが aᵢ が大きい場合、k が非常に小さい限り、その問題は決して選択されません。 常に最小の時間を最初に選択するため、必要な場合を除き、そのような外れ値は自動的に除外され、最適性が維持されます。
