 ## 解決策
 ## 問題の理解

 最低価格で少なくとも**Lリットルのレモネード**を購入するよう求められています。 この店では **n 種類のボトル**を提供しており、i 番目の種類の**容量は 2^(i-1) リットル**、**価格は c[i] ルーブル**で、各種類を無制限に購入できます。 タスクは、L リットルに達するか、それを超えるための **最小総コスト** を決定することです。 

制約から、**n ≤ 30** と小さいですが、**L は最大 10^9** になる可能性があるため、可能なすべてのリットルを反復する解決策は実行できません。 単に標準の DP をリットル単位で使用することはできません。これには O(L) 個のメモリと時間が必要となり、あまりにも大きすぎるからです。 代わりに、ボトル タイプの数が少ないということは、**ビットマスキング、貪欲な戦略、またはサブセット上の DP** を使用できることを示唆しています。 

明らかではないエッジケースには、**大きいボトルの方が小さいボトルよりも 1 リットルあたりのコストが高い**ため、大きいボトルだけを使用すると目標を不必要に超過する可能性があります。 たとえば、3 リットルが必要だが、8 リットルのボトルの方が 1 リットルのボトル ​​3 本より安い場合、最適な解決策は、たとえ L を超えていたとしても 8 リットルのボトルを購入することかもしれません。常に L 未満の最大容量フィッティングを使用して充填する単純な欲張りな考えは、ここでは失敗します。 

## アプローチ

 強引なアプローチは、**ボトルのすべての組み合わせ**を考慮し、総量とコストを計算し、L を満たすか超えるものの中から最小値を選択することです。各ボトル タイプには無限の供給があるため、組み合わせの数に制限はありません。 ボトルごとの選択肢を妥当な限界 (たとえば、L を超えるのに十分な量) に制限すると、複雑さはおよそ O((L/体積)^n) になります。これは、n = 30 および L が 10^9 までの場合には遅すぎます。 

重要な観察は、**各ボトルの体積は 2 の累乗である**ということです。 これは当然、**二項対立で考える**ことになります。つまり、ボリュームの各「ビット」を取得するか取得しないかを検討できます。 さらに、**コストを前処理**して、2 つの小さなボトルを購入した方が、2 倍の容量の 1 つの大きなボトルを購入するよりも決して安くならないようにすることができます。 正式には、1 から n-1 までの各 i について、次のように置き換えます。`c[i+1]`と`min(c[i+1], 2*c[i])`。 これにより、価格関数が **出来高に関して単調である**ことが保証され、次善の選択が防止されます。 

この前処理の後、問題は **ビットごとの貪欲な選択** に減ります。つまり、最大のボトルから下に向かって反復処理を行い、残りの L に基づいて取得する個数を決定します。また、大きなボトルによるオーバーシュートが、小さなボトルを組み合わせるよりも安くなる場合に備えて、最小コストを追跡する必要もあります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((L/体積)^n) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず、コストを前処理します。 2 番目から最後までの各ボトル タイプについて、そのコストを現在のコストの最小値と **前の小さいボトルのコストの 2 倍**に置き換えます。 これにより、大きなボトルが小さなボトルと比べて不釣り合いに高価になることがなくなります。 
2. 変数を初期化します。`ans`無限として (最小コストを追跡します)、`current_cost`0 (これまでに蓄積されたコスト) となります。 
3. ボトルのタイプを最大から最小まで繰り返します。 タイプごとに、残りのリットル L をカバーするために **このタイプのボトルを何本使用できるかを決定します**。整数の除算を使用して、現在の残りの L に達するか、それをわずかに超えるボトルの最小数を計算します。 
4. これらのボトルのコストを`current_cost`。 各手順の後に、**このタイプの追加のボトルを単独で購入した方が、小さいボトルを組み合わせるよりも安価な解決策になるかどうか** についても検討してください。 アップデート`ans`現在の値の最小値と`current_cost + c[i]`オーバーシュートした場合。 
5. すべての型が終了したら、変数`ans`最小限の総コストを維持します。 

**機能する理由:** 前処理により、容量あたりのコストでは、小さなボトルを組み合わせても大きなボトルに勝てないことが保証されるため、安全に欲張った選択をすることができます。 各ステップでのオーバーシュートを考慮すると、必要以上に大きなボトルを購入した方が、ぴったりフィットする小さなボトルを購入するよりも安くなるケースが確実に考慮されます。 不変条件は、各反復において、`current_cost`これは、少なくともこれまでに説明したリットルをカバーする最も安価な方法です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, L = map(int, input().split())
c = list(map(int, input().split()))

# Preprocess: ensure larger bottles are never more expensive than two smaller ones
for i in range(1, n):
    c[i] = min(c[i], 2 * c[i-1])

ans = float('inf')
current_cost = 0
remaining = L

for i in range(n-1, -1, -1):
    volume = 1 << i
    count = remaining // volume
    current_cost += count * c[i]
    remaining -= count * volume
    
    # consider buying one extra bottle of this type
    ans = min(ans, current_cost + (c[i] if remaining > 0 else 0))

# In case we have exactly covered L
ans = min(ans, current_cost)

print(ans)
```**説明:** 前処理ステップにより、非単調な価格設定が防止されます。 メインループは最大のボトルから最小のボトルに進みます。`count`このタイプのボトルをオーバーシュートすることなく安全に摂取できる数です。`remaining`まだ必要なリットルを追跡します。 追加後`count`ボトルの場合、重要なエッジケースに対処するために、オーバーシュートが安くなるかどうかを確認するために追加のボトルを購入することを常に検討しています。 最後に、オーバーシュートが必要ない場合、答えが少なくとも正確なコストであることを確認します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, L = map(int, input().split())
    c = list(map(int, input().split()))
    for i in range(1, n):
        c[i] = min(c[i], 2 * c[i-1])
    ans = float('inf')
    current_cost = 0
    remaining = L
    for i in range(n-1, -1, -1):
        volume = 1 << i
        count = remaining // volume
        current_cost += count * c[i]
        remaining -= count * volume
        ans = min(ans, current_cost + (c[i] if remaining > 0 else 0))
    ans = min(ans, current_cost)
    return str(ans)

# provided samples
assert run("4 12\n20 30 70 90\n") == "150", "sample 1"
assert run("3 3\n10 20 10\n") == "10", "sample 2"

# custom cases
assert run("1 1\n100\n") == "100", "minimum L and n"
