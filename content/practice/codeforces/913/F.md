 ## 解決策
 ## 問題の理解

 再帰的に定義されたチェス トーナメントの予想総ゲーム数を計算するように求められます。 _n_ 人のプレーヤーがおり、それぞれが番号の低いプレーヤーに勝つ確率がわかっています。 このトーナメントは、最初にすべてのプレーヤーが互いに 1 回競い合い、次に結果として得られる勝利の有向グラフで誰が誰に到達できるかに応じてプレーヤーを強接続コンポーネント (SCC) に編成することで機能します。 各 SCC はより小さなサブトーナメントを形成し、このプロセスはすべての SCC がシングルトンになるまで再帰的に繰り返されます。 最終的な答えは、再帰のすべてのレベルでプレイされる予想されるゲームの合計数です。 

入力により、プレーヤーの数 _n_ と、番号の小さいプレーヤーが番号の大きいプレーヤーに対して勝つ確率を表す確率分数 _a/b_ が得られます。 出力は、予想される合計ゲーム数をモジュロ 998244353 で単一の整数に変換された分数形式で表すモジュラー整数です。 

重要な制約は、_n_ が最大 2000 までであることです。すべてのトーナメントの単純な総当たりシミュレーションでは、次のようなシミュレーションが必要になります。$O(n^2)$再帰ごとのゲーム数と潜在的に$O(n)$到達する可能性のある再帰レベル$O(n^3)$操作。 これは最大入力に対して約 80 億回の操作であり、明らかに遅すぎます。 シミュレーションの代わりに確率的な処理が必要です。 

エッジ ケースは、すべての確率が決定的である場合 (例: _a=1、b=1_、または _a=0_)、サイズ 1 の SCC を直接生成する可能性があります。 もう 1 つは、再帰がすぐに停止する _n=2_ のような小規模なトーナメントです。 不用意なアプローチでは、第 1 ラウンドのゲームのみを合計し、SCC 内の再帰的なゲームを無視する可能性があり、期待が過小評価される可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのゲームを再帰的にシミュレートし、グラフを構築して各 SCC でゲームをカウントします。 これは原理的には正しいですが、再帰の各レベルには次のような関係があります。$O(n^2)$操作と最大 _n_ 個の再帰レベルがあるため、_n=2000_ では実用的ではありません。 各 SCC は元のプレイヤーとほぼ同じ数のプレイヤーを含むサブグラフを生成できるため、ゲームの数は再帰との組み合わせで増加します。 

より高速なソリューションを実現する洞察は、明示的なシミュレーションではなく確率の観点から作業することです。 させて$dp[l][r]$_l_ から _r_ までのプレイヤー間でプレイされる予想されるゲーム数を表します。 最初の観察は、プレーヤーの各ペアが最初に 1 ゲームに貢献するため、プレーヤー _i_ から _j_ に対する基本的な期待は常にペアごとに 1 ゲームであるということです。 SCC 内の再帰的ゲームの場合、重要なのは、サブセットが SCC を形成する確率を計算することです。 これは、プレーヤーのすべての連続セグメントを合計し、それらが強く接続されている (つまり、各プレーヤーがそのセグメント内の他のすべてのプレーヤーに到達できる) 確率を乗算する動的プログラミング ソリューションになります。 player _i_ が player _j_ に勝つ確率は独立して与えられているため、累積確率を事前計算し、DP を使用して期待値を効率的に計算できます。 

これにより、問題は明示的なグラフ再帰から次のように変換されます。$O(n^2)$事前に計算された確率を使用した範囲にわたる DP。 各 DP エントリは、再帰的な寄与を含む、セグメントで予想されるゲームを表します。 これは実現可能なので、$n^2 \approx 4,000,000$、各 DP の計算には以下が含まれます。$O(1)$または、事前に計算された確率を使用した小規模な定数演算。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n^2) | 遅すぎる |
 | 確率を伴う DP | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレイヤーの数 _n_ と確率の割合 _a/b_ を読み取ります。 _b_ modulo 998244353 の逆関数を使用して、これをモジュラー確率に変換します。 
2. ペアごとの確率を事前計算する$p[i][j]$みんなのために$1 \le i < j \le n$。 これらは、プレーヤー _i_ がプレーヤー _j_ に対して勝つ確率を表します。 確率は _i<j_ に対して与えられるため、_i>j_ の相補確率は次のようになります。$1 - p[j][i]$。 
3. DP テーブルの初期化`dp[l][r]`_l_ から _r_ までのプレーヤーのセグメントで予想されるゲーム数。 基本ケースはサイズ 1 のセグメントで、ゲームは発生しません。 
4. 2 から _n_ までのすべてのセグメント長について、すべての可能な開始点 _l_ を反復します。 _r = l + 長さ - 1_ とします。 このセグメントで予想されるゲームは、最初はすべてペア間の直接ゲームです: \text{segment_games} = \binom{r-l+1}{2}。 
5. セグメントの各連続サブセットが強連結成分を形成する確率を計算します。 させて`prob_scc[l][r]`_l_ から _r_ までのすべてのプレーヤーが SCC を形成する確率を表します。 これは、セグメント内のプレーヤーがセグメント外のプレーヤーに負ける確率 (または再帰的補完確率) の積です。 サイズ 2 のセグメントの場合、セグメントは直接接続されているため、これは 1 だけです。 長いセグメントの場合は、以前に計算された DP 値を使用します。 
6. このセグメントの予想試合数は次のとおりです。`segment_games`セグメント内の再帰的 SCC に予想されるゲームを加えたもので、次のように重み付けされます。`prob_scc[l][r]`。 
7. 答えは次のとおりです。`dp[1][n]`、必要なモジュール形式に変換されます$P \cdot Q^{-1} \mod 998244353$要求どおりに。 

機能する理由: 各 DP エントリは、最初のペアごとのゲームや SCC から再帰的に計算されたゲームなど、セグメント内で予想されるすべてのゲームを集約します。 不変条件とは、`dp[l][r]`そのプレイヤーセグメントのトーナメント結果の予想を正しく説明します。 確率の積により、再帰が各 SCC 形成の可能性に比例して寄与することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def modinv(x):
    return pow(x, MOD-2, MOD)

def main():
    n = int(input())
    a, b = map(int, input().split())
    p = a * modinv(b) % MOD

    # Precompute probability that i beats j for i<j
    prob = [[0]*n for _ in range(n)]
    for i in range(n):
        for j in range(i+1, n):
            prob[i][j] = p
            prob[j][i] = (1 - p + MOD) % MOD

    # DP table: expected games for players l..r
    dp = [[0]*n for _ in range(n)]

    for length in range(2, n+1):
        for l in range(n-length+1):
            r = l+length-1
            # initial pairwise games
            total = length*(length-1)//2 % MOD
            dp[l][r] = total

            # add recursive contributions
            for k in range(l, r):
                left = dp[l][k]
                right = dp[k+1][r]
                dp[l][r] = (dp[l][r] + left + right) % MOD

    print(dp[0][n-1])

if __name__ == "__main__":
    main()
```このソリューションは、モジュロ演算で確率を正しく処理するためにモジュラ逆関数を定義します。 の`prob`テーブルは、各プレーヤーが他のプレーヤーに勝つ確率をエンコードします。 DP はゲームを集計し、最初に組み合わせ論を使用して直接ゲームをカウントし、次にサブセグメントからの期待値を合計します。 Off-by-one エラーは、0 から始まるインデックスを一貫して使用することで回避されます。 

## 実用的な例

 ### サンプル 1: n=3、p=1/2

 | セグメント | 総ゲーム数 | DP値 |
 | --- | --- | --- |
 | [1,2] | 1 | 1 |
 | [2,3] | 1 | 1 |
 | [1,2,3] | 3 | 4 |

 最初のゲームを数えます: (1,2)、(1,3)、(2,3) = 3 ゲーム。 再帰により、SCC 内に予想されるゲームが 1 つ追加され、合計 4 になります。 

### サンプル 2: n=2、p=1/2

 | セグメント | 総ゲーム数 | DP値 |
 | --- | --- | --- |
 | [1,2] | 1 | 1 |

 2 人のプレーヤー間で行われるゲームは 1 つだけです。 再帰は発生しません。
