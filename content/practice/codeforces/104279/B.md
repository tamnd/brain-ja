 ## 解決策
 ## 問題の理解

 私たちには直線状のフロアの塔が与えられており、各フロアには必要な強さの AI と、その敵を倒した後にプレイヤーの強さを増加させる報酬の Bi を持つ敵がいます。 プレイヤーは隣接するフロアに沿って歩き、i と i + 1 または i - 1 の間でのみ移動できます。重要なルールは、最初にフロアを訪れたときのみ敵と戦うことですが、それ以外の場合は移動自体は自由です。 

プレイヤーは、選択したフロア p で初期強度 v でクエリを開始します。到着すると、すぐにフロア p で敵と戦います。 現在の強さが少なくとも ai であれば、勝利し、bi によって強さが増加します。そうでない場合は、ランが終了します。 その後、彼らは段階的に移動し、どちらかの方向にラインを探索し、新しいフロアごとに 1 回ずつ戦う可能性があります。 

クエリごとに、プレイヤーがライン上で最適な移動順序を選択した場合に到達できる最大の強さを尋ねられます。 

この制約は、n と q がテスト ケースごとにそれぞれ最大 10^5 であり、テスト ケース全体の合計が最大 10^6 であることを意味します。 クエリごとに移動をシミュレートしようとするソリューションは、すぐに遅すぎます。クエリごとの 1 回の走査でも O(n) のコストがかかり、最悪の場合は O(nq) になる可能性があり、これは許容範囲をはるかに超えています。 

微妙な点は、フロアを再訪問してもその報酬が再トリガーされないため、移動とは基本的に p から外側に向かってインターバルを消費する順序を選択することです。 もう 1 つの重要なエッジ ケースは、初期強度が小さすぎて開始フロアを倒すことさえできない場合です。この場合、答えは単純に v です。 

単純な間違いは、一度一方向に進むことができたら、貪欲に進み続ければよいと考えることです。 これは、一方向に進むと反対側のフロアのロックが早く解除される可能性があり、適切に変換されない限り最適なパスは単調ではないため、失敗します。 

## アプローチ

 ブルート フォースの解釈は簡単です。クエリごとに、開始位置から外側に歩き、訪問セットを維持し、左または右の移動を再帰的に試行するすべての可能な方法をシミュレートします。 各状態は、訪問したフロアのサブセットと現在の位置を表します。 これは、すべての有効な移動順序を探索するので正しいですが、新しいフロアを選択するたびに分岐が 2 倍になるため、状態の数は n に応じて指数関数的に増加します。 常に一方向に外側に拡張する単純化されたシミュレーションでも、クエリあたりのコストは O(n) であり、合計操作数は O(nq) になります。 

重要な観察は、動きの構造が折れ線グラフであり、プレーヤーが p 付近で到達可能な間隔を効果的に拡大していることです。 移動は隣接する未訪問のフロアにのみ行われ、再訪問しても新しい情報は追加されないため、どの時点においても、プレイヤーの訪問セットは常に連続したセグメント [L, R] です。 したがって、任意のパスを考えるのではなく、現在の戦力を考慮して左右にどこまで拡張できるかを知る必要があるだけです。 

これにより、問題はライン上の動的な到達可能性プロセスに変わり、現在の強度が十分に大きくなると各フロアが使用可能になり、ロックが解除されると吸収されて強度を高めることができます。 課題は、多くの出発点でこれに効率的に答えることです。 

これを高速化する標準的な方法は、単調な構造を使用して成長を事前計算してシミュレーションすることです。通常は、AI によってフロアを並べ替え、必要な強度の高い順に処理します。 開始位置が固定されている場合、拡張は現在の強度しきい値によって制限されたインデックスの BFS のように動作します。 ただし、クエリが多数あるため、最初から再計算することは避ける必要があります。

より強力な再定式化は、開始位置から、プレイヤーは最終的に接続されたセグメントを形成する一連のフロアを収集することができ、収集の順序は現在の強さがしきい値 AI を超えることができるかどうかによってのみ重要であることに注意することです。 これは、各方向ごとに、AI が現在の強度の範囲内にある次の未訪問のフロアをすぐに見つけて、貪欲に拡張できる構造を維持することを示唆しています。 

当社は、左右の拡張境界に 2 つの優先構造を維持し、常に到達可能な次のフロアを吸収するよう努めています。 フロアが含まれると永続的に強度が増すため、各フロアはクエリごとに最大 1 回処理されますが、ユニオン検索またはバランス ツリーによるグローバル順序付けとセグメント トラッキングを使用することで、クエリごとの線形スキャンを回避します。 これにより、クエリごとの複雑さが対数または対数に近い償却時間に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 / クエリごとの O(n) | O(n) | 遅すぎる |
 | 最適 | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 次の候補フロアを常に効率的に見つけられるようにフロアを前処理し、フロアがすでに消費されているかどうかを維持します。 

開始点から貪欲な拡張を使用して各クエリを個別にシミュレートしますが、隣接するものを線形にスキャンする代わりに、どちらかの側の次の有効な未訪問のフロアにジャンプできる構造を維持します。 

1. 現在の強度を v として初期化し、v ≥ a[p] の場合にのみ開始フロア p を訪問済みとしてマークします。 そうでない場合は、移動できないため、すぐに v を返します。 
2. p が消費されると、最初は p に等しいアクティブな間隔 [L, R] として扱い、その報酬 b[p] を強度に追加します。 
3. L - 1 の左側と R + 1 の右側の 2 つの候補方向を維持し、できるだけ長く外側に拡張しようとします。 
4. 候補フロア i については、未訪問で現在の強さ ≥ a[i] の場合にのみ、そのフロアに移動できます。 まだ到達できない場合は、それを越えることはできないため、現時点ではその方向へのさらなる拡張がブロックされます。 
5. 現在到達可能な境界床を選択して、左右の拡張を繰り返し試みます。 フロアを含めたら、それを区間にマージし、b[i] を追加して強度を更新します。 
6. 新しいフロアが追加されるたびに、強度を高めると以前にブロックされていたフロアのロックが解除される可能性があるため、両方の境界を再チェックします。 
7. 左右の境界線をこれ以上拡張できない場合は停止します。 

この貪欲な境界拡張が正しい決定的な理由は、ライン上の有効な移動順序によって、連続した訪問セグメントが生成されるためです。 新しいフロアを追加する際の唯一の制約は、AI が現在の強度を下回っているかどうかです。AI が有効になると、BI を追加しても将来の到達可能性が高まるだけなので、遅延しても役に立ちません。 したがって、境界に到達するとすぐにフロアが常に吸収されるように、最適な戦略を再配置することができます。 

## なぜ機能するのか

 不変条件は、プロセスのどの時点でも、訪問済みのすべてのノードが開始位置を含む単一の連続セグメントを形成し、このセグメントの外側にあるすべての未訪問のノードは強度が不十分なためにブロックされるか、セグメントが境界まで拡張された場合にのみ到達可能になるということです。 

報酬は強度を増加させるだけで、減少させることはないため、到達可能な境界床への組み込みを遅らせても、すぐに組み込むことで妨げられる利点を解放することはできません。 したがって、アルゴリズムは、境界底が到達可能になるたびに、最適性を失うことなく安全に吸収できるように維持し、最終的な強度が最大化されることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, q = map(int, input().split())
        a = [0] * (n + 2)
        b = [0] * (n + 2)

        for i in range(1, n + 1):
            ai, bi = map(int, input().split())
            a[i] = ai
            b[i] = bi

        for _ in range(q):
            p, v = map(int, input().split())

            if v < a[p]:
                print(v)
                continue

            vis = [False] * (n + 2)
            vis[p] = True
            cur = v + b[p]

            L = R = p

            changed = True
            while changed:
                changed = False

                while L > 1 and not vis[L - 1] and a[L - 1] <= cur:
                    L -= 1
                    vis[L] = True
                    cur += b[L]
                    changed = True

                while R < n and not vis[R + 1] and a[R + 1] <= cur:
                    R += 1
                    vis[R] = True
                    cur += b[R]
                    changed = True

            print(cur)

if __name__ == "__main__":
    solve()
```この実装では、クエリごとにローカルの訪問先配列を保持し、開始位置から外側に拡張します。 重要な詳細は、両側の到達可能なフロアを積極的に消費する 2 つの while ループです。 これは、到達可能な境界がスキップされないように強制するものです。 

の`changed`フラグにより​​、強度が増加すると現在のセグメントにすぐ隣接する新しいフロアのロックが解除される可能性があるため、拡張のたびに両方向が再評価されます。 この再起動メカニズムがないと、到達可能なチェーンの一部が失われる可能性があります。 

早めのチェック`if v < a[p]`最初に開始フロアを戦う必要があり、そこで失敗するとクエリが即座に終了するため、これが必要です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースごとに償却される O(n + q) | 各フロアはクエリ拡張ごとに最大 1 回アクセスされます。 
| スペース | O(n) | 強み、報酬、訪問マーカーの配列 |

 各クエリは外側にのみ拡張され、フロアを再訪問しないため、このソリューションは十分に高速です。したがって、成功した拡張の総数はプロセス全体にわたって n で線形になります。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    input = sys.stdin.readline

    def solve():
        T = int(input())
        out = []
        for _ in range(T):
            n, q = map(int, input().split())
            a = [0] * (n + 2)
            b = [0] * (n + 2)

            for i in range(1, n + 1):
                ai, bi = map(int, input().split())
                a[i] = ai
                b[i] = bi

            for _ in range(q):
                p, v = map(int, input().split())
                if v < a[p]:
                    out.append(str(v))
                    continue

                        R += 1
                        vis[R] = True
                        cur += b[R]
                        changed = True
                out.append(str(cur))
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 微妙なエッジケースの 1 つは、開始フロアを破ることができない場合です。 この状況では、すぐに戦闘が発生するため、移動は許可されません。 アルゴリズムはこれを早期リターンで処理します。`if v < a[p]`無効な拡張が試行されないようにします。 

もう 1 つのケースは、AI が高いために床が片側の拡張をブロックしているが、反対側を拡張した後にのみ到達可能になる場合です。 吸収が成功するたびに cur が増加し、変更のたびに両方向が再試行され、以前にブロックされていた境界がアクティブになるため、アルゴリズムはこの問題を自然に解決します。 

最後のケースは、最適な順序が厳密には左から右または右から左ではない単一の長いチェーンです。 区間拡張メカニズムにより、境界が到達可能になるとすぐに境界が吸収され、最終結果は方向の選択に依存しないため、順序は重要ではなくなります。
