 ## 解決策
 ## 問題の理解

 三角形の面のコレクションが与えられ、各三角形は 3 つの整数の頂点 ID によってのみ記述されます。 これらの ID は、ID を超える意味のある方法でジオメトリを表すことはありません。 2 つの三角形がエッジ全体を共有している場合、つまり 2 つの三角形が共通の頂点 ID を正確に 2 つ持っている場合、それらは隣接しているとみなされます。 この問題における「3D モデル」とは、単にこの三角形上の隣接関係にある連結成分のことです。 

タスクは、すべての三角形をそのような接続されたコンポーネントにグループ化し、接続性が三角形間の共有エッジによって定義され、存在するコンポーネントの数と各コンポーネントのサイズをレポートすることです。 

重要な抽象化の変化は、ジオメトリをまったく扱わなくなったことです。 私たちは、ノードが三角形であり、2 つの三角形が一対の頂点を共有するときにエッジが存在するグラフを扱っています。 

制約は厳しく、すべてのテスト ケースにわたる三角形の総数は最大 100,000 です。これにより、三角形間の二次比較は即座に除外されます。 単純なペアごとのチェックでは、三角形のすべてのペアを比較する必要があり、最悪の場合、制限をはるかに超える約 10^10 の演算が必要になります。 有効な解決策では、各三角形が少数の一定回数だけ処理されること、理想的には操作ごとに対数または償却定数で処理されることを保証する必要があります。 

微妙な落とし穴は、隣接性が頂点の完全な重なりや幾何学的一致に依存すると考えることです。 そうではありません。 正確な共有ペアのみが重要です。 もう 1 つの微妙な問題は、共有頂点が接続性を意味すると仮定していることです。 それは誤りです。三角形は単一の頂点だけでなく、エッジを共有する必要があります。 たとえば、三角形 (1,2,3) と (1,4,5) は頂点を共有していますが、接続されていません。 

最後に、グラフは必ずしも平面的または適切に構造化されているわけではありません。 1 つのエッジが多くの三角形に属することができ、高密度のローカル クラスターを形成します。 幾何学的直観に頼った解決策は失敗します。 

## アプローチ

 直接的なアプローチは、三角形のすべてのペアを比較し、それらが 2 つの頂点を共有しているかどうかを確認することです。 これは接続の定義を直接実装しているため、これは正しいです。 ただし、すべてのペアの隣接性をチェックすると O(n^2) 回の比較が必要になり、各比較ではセットの交差のチェックや比較の並べ替えが必要になるため、実際にはさらに遅くなります。 n が 100000 までの場合、これは不可能です。 

重要な洞察は、視点を逆転させることです。 2 つの三角形が接続されているかどうかを尋ねる代わりに、どの三角形が共有エッジを介して接続できるかを尋ねます。 すべての三角形には正確に 3 つのエッジが含まれており、各エッジは順序のない頂点 ID のペアとして表すことができます。 2 つの三角形がエッジを共有する場合、それらはそのエッジの同じ順序なしペア表現を共有します。 

したがって、三角形を相互に比較する代わりに、エッジをそれらを含む三角形にマッピングします。 すべてのエッジがキーになり、そのキーを共有するすべての三角形がそのエッジを介して接続されます。 これにより、接続グラフを暗黙的に構築できるようになります。 

このマッピングを取得したら、素の集合結合構造を使用して、エッジを共有する三角形をマージできます。 各エッジ グループは、それを含むすべての三角形を接続します。 すべてのエッジを処理した後、各 DSU コンポーネントは 1 つの接続された 3D モデルに正確に対応します。 

これにより、三角形のペアごとの比較から三角形エッジの線形処理に問題が軽減されます。

 ## アルゴリズムのチュートリアル

 各三角形を素集合和集合構造のノードとして扱います。 目標は、ノードがエッジを共有するたびにノードをマージすることです。

1. n 個の要素 (三角形ごとに 1 つ) を含む DSU 構造を初期化します。 最初は接続が不明であるため、各三角形は独自のコンポーネントで始まります。 
2. 各三角形について、その 3 つのエッジを列挙します。 各エッジは、ソートされたペア (min(u, v)、max(u, v)) として表されます。 エッジは無向であり、(u, v) は (v, u) と同じように扱う必要があるため、ソートが必要です。 
3. エッジから、このエッジで確認された最初の三角形インデックスまでのハッシュ マップを維持します。 初めてエッジに遭遇したとき、その三角形のインデックスを保存します。 
4. 別の三角形で同じエッジに再び遭遇すると、現在の三角形と以前に保存された三角形を結合します。 これにより、このエッジを共有するすべての三角形が同じ DSU コンポーネント内に収まることが保証されます。 
5. すべての三角形とエッジを処理した後、すべての三角形を反復処理して、その DSU ルートを見つけます。 各ルート コンポーネントのサイズを数えます。 
6. すべてのコンポーネント サイズを収集し、出力用に昇順に並べ替えます。 

重要な考え方は、すべての共有エッジが、それを含むすべての三角形間に推移的な接続を引き起こすということです。 最初の出現を結合することにより、各エッジ グループ内にスター構造が効果的に構築されます。これは接続には十分です。 

### なぜ効果があるのか

 各三角形は、共有エッジを介した到達可能性によって定義されるコンポーネントに属します。 2 つの三角形がエッジを共有するたびに、それらは直接接続されており、同じコンポーネントに属している必要があります。 DSU は、2 つのノードが結合されると、それらが同じセット内に残り、この接続関係が維持されることを保証します。 

逆に、2 つの三角形が共有エッジのチェーンを介して接続されている場合、DSU はそのチェーンに沿ってそれらを段階的にマージします。 したがって、最終的な各 DSU セットは、エッジ共有を通じて接続された三角形の最大セットに正確に対応し、問題の 3D モデルの定義と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        dsu = DSU(n)
        edge_map = {}

        for i in range(n):
            a, b, c = map(int, input().split())

            e1 = (a, b) if a < b else (b, a)
            e2 = (a, c) if a < c else (c, a)
            e3 = (b, c) if b < c else (c, b)

            for e in (e1, e2, e3):
                if e in edge_map:
                    dsu.union(i, edge_map[e])
                else:
                    edge_map[e] = i

        comp = {}
        for i in range(n):
            r = dsu.find(i)
            comp[r] = comp.get(r, 0) + 1

        sizes = sorted(comp.values())
        print(len(sizes))
        print(*sizes)

if __name__ == "__main__":
    solve()
```DSU は、三角形の接続されたコンポーネントを維持するために使用されます。 ユニオン操作は、繰り返しエッジが検出された場合にのみ実行され、冗長なマージを行わずに正確性が保証されます。 

各三角形は正確に 3 つのエッジを生成し、各エッジは、同一のエッジが同じキーにマップされるように端点を並べ替えることによって正規化されます。 ハッシュ マップには、エッジごとに代表的な三角形が 1 つだけ保存されます。接続性は推移的であるため、これで十分です。 

最後のループでは、DSU 代表を圧縮し、コンポーネントのサイズをカウントします。 出力仕様によりソートが必要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    class DSU:
        def __init__(self, n):
            self.p = list(range(n))
            self.s = [1]*n
        def f(self,x):
            while self.p[x]!=x:
                self.p[x]=self.p[self.p[x]]
                x=self.p[x]
            return x
        def u(self,a,b):
            a,b=self.f(a),self.f(b)
            if a==b:return
            if self.s[a]<self.s[b]:a,b=b,a
            self.p[b]=a
            self.s[a]+=self.s[b]

    T = int(input())
    out = []
    for _ in range(T):
        n = int(input())
        dsu = DSU(n)
        mp = {}
        for i in range(n):
            a,b,c = map(int,input().split())
            for e in [(min(a,b),max(a,b)),(min(a,c),max(a,c)),(min(b,c),max(b,c))]:
                if e in mp:
                    dsu.u(i, mp[e])
                else:
                    mp[e]=i
        comp = {}
        for i in range(n):
            r = dsu.f(i)
            comp[r]=comp.get(r,0)+1
        sizes = sorted(comp.values())
        out.append(str(len(sizes)))
        out.append(" ".join(map(str,sizes)))
    return "\n".join(out)

 ## 特殊なケース

 微妙なケースは、直接共有ではなく、共有エッジのチェーンを通じて接続が形成される場合です。 考慮する：```
1 2 3
1 2 4
4 2 3
```三角形 0 はエッジ (1,2) を介して 1 に接続されます。 三角形 1 はエッジ (2,4) を介して 2 に接続します。 三角形 0 と 2 はエッジを直接共有していませんが、三角形 1 を介して接続されます。DSU はそれらを段階的に正しくマージし、単一のコンポーネントを生成します。 

もう 1 つのエッジ ケースは、多くの三角形が同じエッジを共有する場合です。 例えば：```
1 2 3
1 2 4
1 2 5
1 2 6
```すべての三角形はエッジ (1,2) を共有するため、すべて 1 つのコンポーネント内に存在する必要があります。 ハッシュ マップには最初の三角形が格納され、後続のすべての三角形がその中に結合され、単一の接続されたセットが構築されます。 

最後のエッジ ケースは、エッジが繰り返されない完全な分離です。 その場合、すべての三角形は独自の DSU セットのままとなり、出力はそれぞれサイズ 1 の n 個のコンポーネントになります。
