 ## 問題の理解

 15 種類のアクションを持つゲーム システムが与えられ、各アクションはそのインデックスに応じて一定量のスタミナを消費します。 アクション 1 ～ 4 はそれぞれ 8 スタミナ、アクション 5 ～ 10 はそれぞれ 9 スタミナ、アクション 11 ～ 15 はそれぞれ 10 スタミナを消費します。 プレイヤーには合計スタミナ予算があります`n`、各タイプのアクションを任意の数だけ実行できます。 目標は、すべてを正確に費やすためのさまざまな方法が何通り存在するかを数えることです。`n`スタミナ。方法は、実行される順序ではなく、15 のアクションがそれぞれ何回使用されるかによって純粋に定義されます。 

形式的には、変数が同じ係数を持つ 3 つのグループに分割される線形方程式の非負の整数解の数を数えます。つまり、8 で重み付けされた 4 つの変数、9 で重み付けされた 6 つの変数、および 10 で重み付けされた 5 つの変数です。変数が異なる場合、2 つの解は異なります。 

制約は非常に大きいです。`n`最大 10^18 まで可能で、最大 10^4 のテスト ケースがあります。 これにより、反復処理を行うアプローチは即座に除外されます。`n`、またはパーティション化する方法の数を超えてさえも`n`素朴な多次元 DP の意味で。 どのような解法も、次の算術特性のみに依存する必要があります。`n`そして小さな固定構造。 

実現可能性について推論するときに、微妙な問題が現れます。すべてがそうなるわけではありません。`n`すべてのコストが 1 の倍数であるため、これは表現可能ですが、さらに重要なのは、この構造が多重度を持つ 8、9、10 のコインの組み合わせによってのみ制限されることです。 素朴な考えでは、各アクションを独立して扱うことになりますが、複数のアクションは同じコストを共有するため、組み合わせ論は単なる分割ではなく、繰り返しを伴う合成になります。 

小さなエッジケースは構造を明確に示しています。 もし`n = 8`、有効な解決策には、4 つの 8 コスト アクションのうちの 1 つを 1 回だけ使用することが含まれます。 これにより、すでに 4 つの異なる解決策が得られます。 多重性を無視してコストの組み合わせのみをカウントする不注意なアプローチでは、誤って 1 が返されます。 

もう一つのエッジケースは、`n = 9`。 9 コスト グループを使用した 6 つの個別のシングル アクション ソリューションがありますが、8 コスト アクション 1 つと不可能なもののような組み合わせもあり、これはカウントしてはなりません。 単純なナップザック スタイルの DP はこれに対処できますが、非常に遅すぎます。`10^18`。 

本当の難しさは、「どのグループが総コストにどれだけ貢献しているか」と「そのコストがグループ内の同一項目にどのように配分されているか」を区別することです。

 ## アルゴリズムのチュートリアル

 問題を制約付き線形方程式の計数解に変換し、組み合わせ分布を掛けます。 

1. 15 個の変数を 3 つの集計変数に変換します。`A, B, C`、それぞれコスト 8、9、10 のアクションの合計数を表します。 これにより、方程式は次のように簡略化されます。`8A + 9B + 10C = n`。 
2. 固定の場合`A`、残りの合計を計算します`rem = n - 8A`。 もし`rem < 0`、それより大きいと考えるのはやめてください`A`。 これにより、以降のすべての計算が有効なままになります。 
3.解決する`9B + 10C = rem`。 両方の変数を検索する代わりに、モジュラー算術を使用します。モジュロ 10 を減算して、次の可能な値を決定します。`B`。 以来`9 ≡ -1 (mod 10)`を制限する合同条件を導き出します。`B`10 を法とする単一の剰余クラスに変換します。 
4. 有効なものをすべて列挙します`B`値が残留条件と一致し、確実に`B ≥ 0`そして`9B ≤ rem`。 それぞれの有効な`B`、計算する`C = (rem - 9B) / 10`整数の非負の解のみを受け入れます。 モジュロ制約により、1 回あたりの候補数が非常に少なくなります。`A`。 
5. 有効なトリプルごとに`(A, B, C)`、分布の数を計算します。`ways(A) = C(A + 3, 3)`同一コスト8アイテム4個の場合、`ways(B) = C(B + 5, 5)`6コスト-9アイテムの場合、`ways(C) = C(C + 4, 4)`5コスト-10アイテムの場合。 
6. これら 3 つの値を乗算し、答えのモジュロを累積します。`1e9+7`。 

### なぜ効果があるのか

 重要な不変条件は、15 個の元の変数の有効な割り当てがすべてトリプルに一意に対応することです。`(A, B, C)`さらに、同一コスト グループ全体にわたる各集計数の独立した分布を追加します。 線形方程式により、合計を超えるグループ間の依存性が保証されず、組み合わせステップによりグループ内の順列が完全に考慮されます。 モジュラー削減により、それぞれの`A`、すべて実現可能`(B, C)`ペアは省略や重複なく 1 回だけ列挙されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

# precompute nCr up to needed range dynamically via memoized factorials
max_n = 200000  # safe upper bound for combinatorics within constraints

fact = [1] * (max_n + 1)
invfact = [1] * (max_n + 1)

for i in range(1, max_n + 1):
    fact[i] = fact[i - 1] * i % MOD

invfact[max_n] = pow(fact[max_n], MOD - 2, MOD)
for i in range(max_n, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def nCr(n, r):
    if n < 0 or r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

def solve_case(n):
    ans = 0

    maxA = n // 8
    for A in range(0, maxA + 1):
        rem = n - 8 * A
        if rem < 0:
            break

        # B mod 10 constraint from 9B + 10C = rem
        # 9B ≡ rem (mod 10) => -B ≡ rem (mod 10) => B ≡ -rem (mod 10)
        B0 = (-rem) % 10

        # try B = B0 + 10k
        B = B0
        while 9 * B <= rem:
            if B >= 0:
                rest = rem - 9 * B
                if rest % 10 == 0:
                    C = rest // 10
                    if C >= 0:
                        ways = nCr(A + 3, 3)
                        ways *= nCr(B + 5, 5)
                        ways %= MOD
                        ways *= nCr(C + 4, 4)
                        ways %= MOD
                        ans = (ans + ways) % MOD
            B += 10

    return ans

t = int(input())
for _ in range(t):
    n = int(input())
    print(solve_case(n))

重要な実装の詳細は、モジュール削減を使用して制限を行うことです。`B`これを使用しないと、ループがオーバーします。`B`では直線的になります`n`、これは特定の規模では不可能です。
