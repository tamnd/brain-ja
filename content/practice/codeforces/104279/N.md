 ## 解決策
 ## 問題の理解

 円上に配置されたバイナリ文字列を処理しています。 リング上に書かれた長さ n のバイナリ シーケンスを考えてください。位置 n が位置 1 に戻ります。このような 2 つのリングは、一方を回転して他方に入れることができる場合には同じオブジェクトとみなされます。そのため、巡回シフトによって新しい構成が生成されることはありません。 

この制約は、強力な局所規則性条件です。リング上の長さ k のすべての連続セグメントは、同じ合計を持たなければなりません。 値は 0 と 1 のみであるため、長さ k のすべてのウィンドウに同じ数の 1 が含まれることを意味します。 同様に、サイズ k のウィンドウを 1 位置ずつスライドしても、その中の 1 の数は変わりません。 

タスクは、長さ n の個別のバイナリ ネックレスがこの特性 (998244353 を法とする) を満たす数を数えることです。 

入力サイズは大きく、テスト ケースは最大 100,000、n は最大 10^6 です。 これにより、テスト ケースごとの n の二次関数や、テスト ケースごとの線形スキャンさえも即座に除外されます。 解決策では、算術推論の後、各クエリを一定時間またはほぼ一定の時間に短縮する必要があります。 

素朴な試みでは、2^n 個のバイナリ文字列をすべて生成し、ウィンドウ制約を満たすものをフィルタリングしてから、回転によって商を計算します。 有効性のチェックだけでも文字列あたり O(n) であるため、これは完全に不可能です。 

より巧妙ではあるが、依然として間違ったアプローチは、条件によって周期 k の周期性が強制されると仮定することです。 この条件はウィンドウの合計に関するものであり、個々の位置の等価性に関するものではないため、この形式では常に真であるとは限りません。 ただし、非常に剛性の高い構造が生成され、最終的には構成スペースが大幅に減少します。 

k = 1 の場合、重要なエッジ ケースが表示されます。その場合、すべての単一位置はサイズ 1 のウィンドウにわたって等しい合計を持たなければなりません。これは空であるため、長さ n のすべてのバイナリ ネックレスが有効になります。 この場合の答えは、単一のパターンではなく、長さ n のバイナリ ネックレスの数です。 

もう 1 つのエッジ ケースは、k = n − 1 です。この場合、すべての長さ n − 1 ウィンドウの合計は同じでなければなりません。 2 つの位置に差があると合計が異なる 2 つのウィンドウが作成されるため、すべてのビットが強制的に等しくなります。 

これらの極端な結果は、構造が gcd(n, k) に大きく依存していることをすでに示唆しており、ここからが本当の単純化になります。 

## アプローチ

 ブルート フォース ビューポイントは、バイナリ文字列を修正し、ウィンドウの状態をチェックすることから始まります。 回転ごとに、リング全体で k 個の長さのウィンドウの合計を再計算します。 これは、回転で商した後の候補オブジェクトあたり O(n^2) であり、実現可能な限界をはるかに超えています。 

重要な構造観察は、ウィンドウを 1 位置だけシフトしたときにウィンドウの合計がどのように動作するかを観察することです。 S_i が位置 i ～ i+k-1 の合計である場合、S_{i+1} は、a_i を a_{i+k} に置き換えるだけで S_i と異なります。 条件 S_i = S_{i+1} は、すべての i に対して a_i = a_{i+k} を意味します。 

これにより、問題は合計に関する制約から位置間の純粋な等価制約に変換されます。 すべてのインデックスは、円上で k ステップ先のインデックスと強制的に等しくなります。 これは、インデックスがマッピング i → i + k (mod n) に基づいてサイクルに分割されることを意味します。 すべてのサイクルは単色でなければなりません。 

独立したサイクルの数は正確に gcd(n, k) です。 各サイクルには独立して 0 または 1 を割り当てることができるため、回転を無視すると、2^{gcd(n,k)} 構成が得られます。 

最後の複雑さは、全長 n リングの回転下での循環等価性です。 これは標準的なネックレスのカウント問題ですが、円の周りに周期的に配置された gcd(n, k) の独立したブロック上のサイズ 2 の縮小アルファベットに適用されます。 

リング全体を回転させると、これらのサイクルが変わります。 誘発されたアクションは、gcd(n,k) サイクル表現の循環シフトです。 したがって、長さ g = gcd(n, k) のバイナリ ネックレスを数えることになります。 これにより、問題は古典的な結果に帰着します。つまり、長さ g のバイナリ ネックレスの数は次のようになります。

(1/g) * sum_{d | g} φ(d) * 2^{g/d}。 

これはクエリごとに計算されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | O(2^n · n) | O(n) | 遅すぎる |
 | サイクル削減 + ネックレス フォーミュラ | クエリあたり O(√g) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各クエリを小さな算術計算に変換して進めます。 

1. g = gcd(n, k) を計算します。 これは、インデックスが制約 a_i = a_{i+k} によってどのようにグループ化されるかをキャプチャします。 ステップ k を法とした n でのサイクル分解には、正確に g 個の独立したサイクルがあります。 
2. 各サイクルを単一のバイナリ変数として解釈します。 長さ n のリングは、サイクルが折りたたまれた後、長さ g のリングになります。 元の文字列の各構成は、長さ g のバイナリ文字列に一意に対応します。 
3. 元の長さ n のリングの回転がこれらの g ブロックの回転を引き起こすことを認識してください。 したがって、2 つの構成は、その長さ g 表現が互いの巡回シフトである場合には等価です。 
4. 問題を長さ g のバイナリネックレスを数えるというものに落とし込みます。 これは、サイズ g の巡回群に対する標準的なバーンサイド補題の適用です。 
5. バイナリネックレスの公式を適用します。g の約数 d ごとに、ステップ d の回転によって固定された構成をカウントします。 サイクル構造 d の回転には g/d の独立した位置があり、それぞれ 0 または 1 を指定でき、2^{g/d} 個の固定文字列が得られます。 
6. g のすべての約数 d をオイラーの合計関数 φ(d) で重み付けして合計し、g で割ります。 最終的な答えは、(1/g) * sum_{d|g} φ(d) * 2^{g/d} 法 998244353 です。 
7. 約数を事前計算するか、クエリごとに最大 sqrt(g) まで反復し、2 の累乗の剰余を計算します。 

### なぜ効果があるのか

 スライディング ウィンドウによって引き起こされる等式制約により、各等差数列モジュロ k 内のすべての位置が同一になるように強制されます。 これにより、リングが制約と回転の両方の下で不変である gcd(n, k) 等価クラスに分割されます。 元の組み合わせ構造は、長さ g のバイナリ ネックレスに正確に崩壊します。 次に、バーンサイドの補題は回転中の軌道をカウントし、それぞれの異なる周期構造が過大カウントまたは省略なしで正確に 1 回カウントされることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modpow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def phi_sieve(n):
    phi = list(range(n + 1))
    for i in range(2, n + 1):
        if phi[i] == i:
            for j in range(i, n + 1, i):
                phi[j] -= phi[j] // i
    return phi

def divisors(x):
    small, large = [], []
    i = 1
    while i * i <= x:
        if x % i == 0:
            small.append(i)
            if i * i != x:
                large.append(x // i)
        i += 1
    return small + large[::-1]

MAXN = 10**6
phi = phi_sieve(MAXN)

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    g = 0
    a, b = n, k
    while b:
        a, b = b, a % b
    g = a

    divs = divisors(g)
    ans = 0
    for d in divs:
        ans = (ans + phi[d] * modpow(2, g // d)) % MOD

    inv_g = pow(g, MOD - 2, MOD)
    ans = ans * inv_g % MOD
    print(ans)
```この実装では、算術構造を組み合わせ推論から分離します。 gcd ステップは、ウィンドウ制約を完全に削除する構造削減です。 除数の列挙は、バーンサイドの補題に直接組み込まれます。 べき乗剰余演算は、制約内で 2 の累乗を安全に処理します。 g のモジュラー逆関数は、回転に対する正規化を実行します。 

微妙な点は、φ を 10^6 まで事前計算していることです。 これは制約の下では安全であり、クエリごとに合計を再計算する必要がなくなります。 10^6 までのすべての数値の約数の合計は、実際には 10^5 クエリに対して十分小さいため、除数の列挙は依然として効率的です。 

## 実用的な例

 n = 4、k = 2 とします。次に、g = gcd(4,2) = 2 となります。 

長さ 2 のバイナリ ネックレスを計算します。 

| d | φ(d) | g/d | 2^{g/d} | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 2 | 4 | 4 |
 | 2 | 1 | 1 | 2 | 2 |

 合計 = 6、2 で割ると 3 になります。 

これは、長さ 2 の 3 つのバイナリ ネックレス、00、01、11 (01 と 10 が識別される) と一致します。 

ここで、n = 10、k = 6 を考えます。その後、再び g = 2 となります。 

制約構造が同じサイクル サイズに折りたたまれるため、結果は前のケースと同じになります。 これは、n と k を個別にではなく、gcd のみが重要であることを示しています。

 ## 特殊なケース

 k = 1 の場合、サイズ 1 のすべてのウィンドウは、すべてのビットが同一である場合にのみ、自明に等しい合計を持ちますが、回転では定数文字列が 2 つの異なる構成 (すべて 0 またはすべて 1) として扱われます。 g = n であり、長さ n にわたるネックレスの式は定数ネックレスを含むすべてのバイナリ ネックレスを正確にカウントするため、アルゴリズムはこれを処理します。 

k = n − 1 の場合、g = 1 になります。除数の合計は φ(1)·2^{1} / 1 = 2 となり、2 つの定数構成と一致します。 このアルゴリズムはすべてを 1 つのサイクルにまとめ、リング全体で均一性を正しく強制します。 

n と k が互いに素である場合、再び g = 1 となり、構造によりすべての位置が同じ同値クラスに属することが強制されます。 これは、スライディング等式がリング全体に制約を伝播するという直観と一致します。
