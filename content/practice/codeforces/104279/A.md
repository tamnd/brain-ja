 ## 問題の理解

 グリッドが与えられています$n$行と$m$列。 各セルには次のいずれかの文字が含まれます。$A$または$B$。 左上のセルから開始して、右下のセルに到達するまで右または下のみに移動します。 したがって、すべての有効なパスは、次のシーケンスに対応します。$n+m-1$細胞があり、$\binom{n+m-2}{n-1}$そういった道。 

パスを移動すると、訪問したすべてのセルから 1 単位のエネルギーが収集されます。 これらのエネルギーは、容量のある FIFO コンテナ (キュー) にプッシュされます。$k$。 新しいアイテムが追加され、保存されているアイテムの総数が超過したとき$k$、サイズが正確になるまで最も古いアイテムが削除されます$k$。 したがって、コンテナには常に最後のものだけが保存されます。$k$道に沿ってエネルギーを集めます。 

コンテナがいっぱいですべてが満たされると、スコアが与えられます。$k$蓄えられたエネルギーの種類は次のとおりです。$A$。 その時点で1点が追加されます。 その後、コンテナは正常に動作し続け、パスの後半で同じ状況が発生した場合には、さらなるポイントが再び与えられる可能性があります。 

タスクは、最初から最後まですべてのパスを考慮し、すべてのパスにわたって累積されたポイントの総数を法で計算することです。$998244353$。 

重要な構造上の制約は、$n, m \le 400$したがって、グリッドのパスあたりのステップ数は最大 800 です。 パスの数は指数関数的です$n+m$, したがって、パスを列挙することは不可能です。 有効なソリューションでは、グリッド上で動的プログラミングを使用してすべてのパスを同時に処理する必要があります。 

単純に解釈すると、各パスのキューを個別にシミュレートしようとする可能性があります。 パスの数が組み合わせ的に増加するため、これはすぐに失敗します。 もう 1 つの単純なアイデアは、最後のファイルを完全に保存することです。$k$シーケンスを DP 状態として表示します。 以来$k$最大 800 近くになる可能性があり、これは指数関数的、または少なくとも$O(2^k)$限界をはるかに超えた状態空間。 

微妙なエッジ ケースは、スコアがスライディング ウィンドウ条件に依存し、ウィンドウがいっぱいになったときに正確に保持される必要があることです。 これを「すべての部分文字列を数える」として誤って扱うと、$A^k$パス文字列内にあると、グリッド パス構造との相互作用が失われます。グリッド パス構造では、異なるパスが結合したり分岐したりするため、組み合わせてカウントする必要があります。 

## アプローチ

 ブルートフォースアプローチは、次からのすべてのパスを列挙することです。$(1,1)$に$(n,m)$、キューを段階的にシミュレートし、キューに正確に含まれている回数を数えます。$k$連続した$A$価値観。 これは正しいですが、パスの数は$\binom{n+m-2}{n-1}$これは大規模なグリッドではすでに数億のオーダーに達しており、各シミュレーションにコストがかかります$O(n+m)$、完全に実行不可能になります。 

重要な点は、キューには常に最後の行が正確に含まれていることです。$k$パスプレフィックスの文字。 得点条件は、最後に得点したかどうかのみに依存します。$k$キャラクターはすべて$A$。 これにより、キューの内容全体を追跡する必要がなくなります。 代わりに、現在の連続実行を追跡するだけで済みます。$A$はパスの終点にあり、上限は次のとおりです$k$、なぜなら、$B$実行をリセットします。 

これにより、問題は各状態が位置だけでなくグリッド DP に変換されます。$(i,j)$、だけでなく、連続何回も$A$はそのセルで終わります。 遷移はローカルであり、次のセルの文字にのみ依存します。 

状態ごとに 2 つの値、つまりその状態に到達する方法の数と、それらすべての方法で累積された合計スコアを維持します。 状態を拡張するときは、新しい実行が少なくとも次の値に達するたびに、両方のカウントを更新し、スコアに 1 を追加します。$k$、それは最後を意味するので、$k$キャラクターはすべて$A$。

 ## アルゴリズムのチュートリアル

 グリッドを行優先の順序で処理し、各状態がセルで終わるパスと現在の連続するサフィックスに関する情報を保存する DP テーブルを維持します。$A$さんの。 

1. すべてのセルについて$(i,j)$、 定義する$dp[i][j][r]$現在のサフィックスが正確にこのセルに到達する方法の数として$r$連続した$A$、どこで$r$で切り捨てられます$k$。 
2.初期化$dp[1][1][r]$開始セルが$A$または$B$。 もしそうなら$A$、 それから$r=1$、 さもないと$r=0$。 ここから始まるパスは 1 つだけなので、カウントは 1 です。 
3. 各セルについて、状態を次のセルに伝播します。$(i+1,j)$そして$(i,j+1)$。 移動するときは、ランレングスを更新します。 

次のセルが$A$、 増加$r$1まで$k$。 もしそうなら$B$、リセット$r$0にします。 
4. 移行中、並列 DP 配列も維持します$score[i][j][r]$この状態に到達するすべてのパスにわたって累積された合計スコアを保存します。 
5. の状態に移行すると、$r = k$、それは最後を意味します$k$キャラクターはすべて$A$。 このような到着はすべて、その状態に到達するパスごとに 1 ポイントを与えるため、対応するパスの数をスコアに追加します。 
6. グリッド全体を処理した後、すべての状態のすべてのスコアを合計します。$(n,m)$。 

重要な不変条件は、すべての DP 状態が、関連するサフィックス情報によってグループ化されたセルに到達するすべてのパスのすべてのプレフィックスを正確に表すことです。 ランレングス$r$パスを延長するときに新しいスコア イベントが発生するかどうかを完全に決定するため、最後のスコア以降の履歴情報はありません。$k$文字は常に必要とされます。 これにより、二重カウントや寄付の見逃しがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def add(a, b):
    a += b
    if a >= MOD:
        a -= MOD
    return a

n, m, k = map(int, input().split())
grid = [input().strip() for _ in range(n)]

# dp[j][r] for current row: number of ways
dp = [[0] * (k + 1) for _ in range(m)]
sc = [[0] * (k + 1) for _ in range(m)]

def trans_char(prev_cnt, prev_sc, ch, add_from_A):
    ndp = [0] * (k + 1)
    nsc = [0] * (k + 1)
    if ch == 'A':
        for r in range(k):
            if prev_cnt[r] == 0:
                continue
            nr = r + 1
            if nr > k:
                nr = k
            cnt = prev_cnt[r]
            ndp[nr] = add(ndp[nr], cnt)
            nsc[nr] = add(nsc[nr], prev_sc[r])
            if nr == k:
                nsc[nr] = add(nsc[nr], cnt)
    else:
        for r in range(k + 1):
            cnt = prev_cnt[r]
            if cnt == 0:
                continue
            ndp[0] = add(ndp[0], cnt)
            nsc[0] = add(nsc[0], prev_sc[r])
    return ndp, nsc

for i in range(n):
    ndp_row = [[0] * (k + 1) for _ in range(m)]
    nsc_row = [[0] * (k + 1) for _ in range(m)]

    for j in range(m):
        ch = grid[i][j]

        if i == 0 and j == 0:
            if ch == 'A':
                dp[0][1] = 1
            else:
                dp[0][0] = 1
            continue

        prev_cnt = [0] * (k + 1)
        prev_sc = [0] * (k + 1)

        if i > 0:
            for r in range(k + 1):
                prev_cnt[r] = add(prev_cnt[r], dp[j][r])
                prev_sc[r] = add(prev_sc[r], sc[j][r])

        if j > 0:
            for r in range(k + 1):
                prev_cnt[r] = add(prev_cnt[r], ndp_row[j - 1][r])
                prev_sc[r] = add(prev_sc[r], nsc_row[j - 1][r])

        ndp_cell, nsc_cell = trans_char(prev_cnt, prev_sc, ch, k)

        ndp_row[j] = ndp_cell
        nsc_row[j] = nsc_cell

    dp = ndp_row
    sc = nsc_row

ans = 0
for j in range(m):
    for r in range(k + 1):
        ans = add(ans, sc[j][r])

print(ans)
```この実装では、メモリを線形に保つために行ごとに DP を圧縮します。$m$。 各セルは上と左からの寄与をマージします。これは、そこに到達する唯一の方法であるためです。 トランジション関数はカウントの伝播とスコアの累積の両方を処理し、ランレングスに達したときに特別な増分を行います。$k$。 

よくある落とし穴は、スコアの蓄積は状態ごとに上書きされるのではなく、すべてのパスにわたって加算される必要があることを忘れていることです。 もう 1 つは、累積スコアを正しく伝播せずに、ランレングスのみを誤ってリセットすることです。
