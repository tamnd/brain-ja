 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースでは、第 1 象限のグリッドで作業しています。 各セグメントの端点が同じ値を満たすため、受信したすべてのセグメントは 45 度の単一の対角線上にあります。$x + y$。 これは、すべてのセグメントが点から移動するように制約されることを意味します$(x_1, y_1)$別の点へ$(x_2, y_2)$同じ対角線上に留まりながら、厳密に右と下に移動します。 

幾何学的には、このような各セグメントは、グリッド内の 1 本の固定対角線の一部をトレースします。 異なるセグメントは、そのセグメントに応じて異なる対角線上に存在する場合があります。$x + y$価値。 

各テスト ケースには 2 つのことが必要です。 まず、単位グリッド セルの対角線が複数回横断されているかどうかを判断する必要があります。 各単位セルは正確に 1 つの対角線セグメント (同じ傾斜方向) に寄与するため、この条件は、すべての固定対角線に沿って、線上の点が複数回覆われるような形で描画されたセグメントが重ならないことを保証するのと同じです。 

次に、描画されたすべてのセグメントの全長を計算する必要がありますが、この問題ではこの全長を 2 で割ることが求められます。垂直方向の変位は対角線の制約によって決まるため、各セグメントの寄与は水平方向の変位のみに依存します。 

制約により、最大で次のことが許可されます。$10^5$テスト ケースあたりのセグメント、最大 10 個のテスト ケース。 これにより、二次的なペアごとのオーバーラップ チェックが即座に除外されます。 たとえ$O(n \log^2 n)$重い定数を使用して実装すると、テスト ケースごとのアプローチは限界に達するため、次のことを目指す必要があります。$O(n \log n)$テストケースごとにそれ以上です。 

対角線によるグループ化を無視すると、微妙な失敗のケースが発生します。 たとえば、セグメントについて考えてみましょう。$(0,1)\to(1,0)$そして$(1,2)\to(2,1)$。 これらは異なる対角線上にあるため、相互作用することはなく、それらを横切る重複チェックは無意味です。 すべてのセグメントを次の基準でグローバルに並べ替える単純なアプローチ$x_1$それらを誤って比較し、誤った重複を報告する可能性があります。 

エンドポイントのみをチェックすると、別の失敗ケースが発生します。 同じ対角線上にある 2 つのセグメントは、端点を共有していないものの、セグメント内で部分的に重なっている可能性があり、条件に違反します。 

## アプローチ

 ブルートフォース手法では、同じ対角線上にあるセグメントのすべてのペアが比較されます。 各ペアについて、その線上の間隔が正の長さと交差するかどうかを確認します。 これには必要です$O(n^2)$最悪の場合の比較は非常に遅すぎます。$n = 10^5$。 対角線ごとに制限されている場合でも、1 つの対角線にほぼすべてのセグメントが含まれる可能性があります。 

重要な観察は、各セグメントは単に次の式で識別される 1 次元の直線上の間隔であるということです。$c = x + y$。 この値でセグメントをグループ化すると、問題はグループごとの古典的な区間重複検出問題になります。 各グループ内の間隔を並べ替えて、それらがエンドポイントを超えて交差していないことを確認するだけで済みます。 

2 番目のタスクは、描画された全長の半分を計算することで、すべてのセグメントがその水平スパンに正確に寄与するため、単純化されます。$(x_2 - x_1)$必要な答えに。 すべてのセグメントにわたるこれらの値を合計すると、最終結果が直接得られます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

まず、値によってセグメントをグループ化します。$c = x + y$。 これは、セグメントが配置されている対角線の正体です。 すべてのセグメントは、まさに 1 つのグループに属します。 

次に、各グループ内で、各セグメントを 1 次元の間隔として扱います。$[x_1, x_2]$、 以来$y$によって一意に決定されます$x + y = c$。 

次に、これらの間隔を左の端点で並べ替えます。$x_1$。 並べ替えにより、重複が存在する場合、それがこの順序で連続する間隔の間に現れることが保証されます。 

次に、ソートされた間隔をスキャンして、これまでに到達した右端の点を維持します。 開始位置が現在の右境界よりも厳密に小さい新しい間隔に遭遇した場合、直ちに重複を検出し、回答を無効としてマークします。 開始点が境界と等しい場合、エンドポイントが接触してもカバレッジが繰り返されることを意味しないため、これは許可されます。 

同時に、次の値を追加することで、最終回答に対する各セグメントの寄与度を累積します。$x_2 - x_1$。 

最後に、オーバーラップ条件に違反したかどうかと、計算された合計を出力します。 

正確さは、各対角線を 1 次元の線に減らすことで得られます。 このようなラインでは、繰り返されるカバレッジは、ソートされた順序で間隔の交差として表示される必要があります。 並べ替えでは重複する可能性のある間隔の隣接関係が維持されるため、すべての違反を検出するには 1 回のリニア スキャンで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        groups = defaultdict(list)
        total = 0
        ok = True

        for _ in range(n):
            x1, y1, x2, y2 = map(int, input().split())
            c = x1 + y1
            groups[c].append((x1, x2))
            total += (x2 - x1)

        for c, segs in groups.items():
            segs.sort()
            r = -1
            for l, rr in segs:
                if l < r:
                    ok = False
                    break
                r = max(r, rr)
            if not ok:
                break

        print("YES" if ok else "NO")
        print(total)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず対角識別子をキーとする辞書を構築します。$x+y$。 保存された各エントリは、次の間隔に縮小されます。$x$、対角制約により、$y$冗長です。 重複チェックはソート後の各バケット内でのみ実行されます。 

各セグメントが独立して寄与するため、累計は入力解析中に即座に蓄積されます。$x_2 - x_1$。 これにより、後でセグメントを再検討する必要がなくなります。 

微妙な点は、隣接する間隔を許可していることです。$l = r$。 これは、内部点を二重にカバーせずに端点で接触するセグメントに対応しており、問題の条件下では有効です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    def solve():
        T = int(input())
        out = []
        for _ in range(T):
            n = int(input())
            g = defaultdict(list)
            total = 0
            ok = True
            for _ in range(n):
                x1,y1,x2,y2 = map(int,input().split())
                c = x1+y1
                g[c].append((x1,x2))
                total += x2-x1

            for segs in g.values():
                segs.sort()
                r = -1
                for l,rr in segs:
                    if l < r:
                        ok = False
                        break
                    r = max(r, rr)
                if not ok:
                    break

            out.append(("YES" if ok else "NO") + "\n" + str(total))
        return "\n".join(out)

    return solve()

# simple non-overlap
assert run("1\n2\n0 1 1 0\n1 2 2 1\n") == "YES\n2", "no overlap"

# overlap on same diagonal
assert run("1\n2\n0 4 2 2\n1 3 3 1\n") == "NO\n4", "overlap case"

# single segment
assert run("1\n1\n0 0 5 5\n") == "YES\n5", "single segment"

# disjoint multiple diagonals
assert run("1\n3\n0 1 1 0\n1 2 2 1\n2 3 3 2\n") == "YES\n3", "separate diagonals"

 ## 特殊なケース

 厄介なケースは、セグメントが端点でのみ接触する場合です。 例えば、$[0,2]$そして$[2,5]$同じ対角線上にあるユニット ポイントは 2 回カバーされないため、条件に違反しません。 アルゴリズムは平等を可能にするため、これを処理します$l = r$失敗を引き起こすことなく、厳密に重複する場合にのみフラグを立てます。$l < r$。 

もう 1 つのケースは、すべてのセグメントが異なる対角線上にある場合です。 それらの射影がグローバルな x オーダーで重なっている場合でも、それらは独立しています。 グループ化$x+y$それらが決して干渉しないこと、およびスキャンで無関係な間隔が比較されることがないことを保証します。 

最後の微妙なケースは、すべてのセグメントが同じ対角線を共有する大きな入力です。 その状況では、アルゴリズムは単一のソートされた間隔スイープに縮退し、引き続き実行されます。$O(n \log n)$仕分けのため、制限内に留まります。
