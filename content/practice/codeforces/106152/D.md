 ## 解決策
 ## 問題の理解

 を構築する必要があります`r × c`マインスイーパーボード。 

各セルは地雷または空のセルのいずれかです。 

有効なボードは 2 つの条件を満たさなければなりません。 

すべての鉱山について、隣接するセルの少なくとも 1 つは空でなければなりません。 

空のセルごとに、隣接する鉱山の数が以下を超えてはなりません`M`。 

隣接するセルは通常のマインスイーパーの隣接セルであり、最大 8 つのセルが側面または角で接触します。 

すべての有効なボードの中で、可能な限り最大数の地雷が必要です。 

寸法は非常に小さく、`2 ≤ r, c ≤ 6`、 その間`1 ≤ M ≤ 8`。 ボードには最大 36 個のセルが含まれるため、すべての地雷の配置をブルート フォースで実行するには、最大 36 個のセルをチェックする必要があります。`2^36`完全に不可能な構成です。 

幅と高さが小さいことは、状態圧縮アプローチを示唆しています。 マインスイーパのすべての制約は距離 1 内のセルにのみ依存するため、セルの有効性はそのセル自体の列と隣接する 2 つの列にのみ依存します。 この場所が重要な観察です。 

微妙なエッジケースが境界線に現れます。 

最初の列の地雷について考えてみましょう。 ボードの外側のセルは空のセルではありません。 「ボードの外側」を空のセルとして扱う不注意な実装では、そのような地雷が空の隣接セルを持つという要件を満たすことを誤って許可してしまいます。 

例えば：```
**
**
```すべての細胞は地雷です。 どの鉱山にも空の隣人は存在しないため、このボードは無効です。 

もう 1 つの特殊なケースは、空のコーナー セルです。 隣接するものは 8 つではなく 3 つだけです。 

例えば：```
..
.*
```左上隅には隣接する鉱山が 1 つだけあります。 存在しないセルを隣接セルとしてカウントすると、間違った結果が生成されます。 

最後の重要なエッジ ケースは、両方の隣接する列がわかった後でのみセルを完全に検証できることです。 列を確認するのが早すぎると、次の列からの情報を見逃す可能性があります。 

## アプローチ

 ブルートフォースの解決策は簡単です。 のすべてのサブセットを列挙します。`r × c`セルを鉱山のセットとして使用し、両方の有効性条件をチェックします。 ボードには 36 個のセルを含めることができるため、これを検討する必要があります。`2^36 ≈ 6.8 × 10^10`これは現実的な制限をはるかに超えています。 

ブルート フォースが正しい理由は、考えられるすべてのボードを直接テストするためです。 失敗する理由は、膨大な検索スペースにあります。 

重要な観察は、すべての制約がローカルであるということです。 

列内のセルかどうかを判断するには`j`は有効です。列からの情報のみが必要です`j-1`、`j`、 そして`j+1`。 それより遠くにあるものはそのセルに影響を与えることはできません。 

以来`r ≤ 6`、列全体は最大 6 ビットのビットマスクとして表現できます。 あるのは`2^r ≤ 64`考えられる列の状態。 

これにより、問題はプロファイル動的プログラミングの問題に変わります。 

列マスクのトリプルごとに`(A, B, C)`、中央の列のすべてのセルかどうかを確認できます`B`列で囲まれた場合にルールを満たす`A`そして`C`。 

次に、列を左から右に処理します。 DP 状態には、最後の 2 つの列マスクが保存されます。 新しい列が追加されると、すぐに中央の列を確認できます。 

検索スペースが小さくなります。`64 × 64 × 64 = 262144`最悪の場合は3倍になる可能性もあります。 

それは簡単に管理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(r・c)・r・c) | お(1) | 遅すぎる |
 | 最適なプロファイル DP | O(c · 2^(3r)) | O(2^(2r)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各列を長さのビットマスクとして表現します。`r`。 
2. 考えられるすべての 3 つのマスクについて`(left, mid, right)`、中央の列のすべてのセルが問題の制約を満たしているかどうかを判断します。 
3. 空のセルの場合、既存の隣接セルの中で隣接する地雷をカウントします。 カウントは次を超えてはなりません`M`。 
4. 地雷セルの場合、少なくとも 1 つの隣接セルが空かどうかを確認します。 
5. すべての有効なトランジションを保存します。 中央の列のすべてのセルがテストに合格した場合、トリプルは有効です。 
6. マスクのセンチネル列を 2 つ追加します`0`1 つは最初の実列の前、もう 1 つは最後の実列の後にあります。 これらのセンチネルは、実際の空のセルではなく、「セルなし」を表します。 
7. 列に対して動的プログラミングを使用します。 状態を、すでに選択されている最後の 2 つの列マスクとします。 
8. 新しい列マスクを追加しようとするときは、対応する事前計算されたトリプルを使用して前の列が有効になることを確認します。 
9. DP 値は、これまでに設置された地雷の最大数です。 
10. すべての実列を処理した後、正しいセンチネルを追加し、最後の実列に対して最後の有効性チェックを 1 回実行します。 
11. 最大の DP 値が答えです。 

### なぜ効果があるのか

 セルは、それ自体の列および隣接する 2 つの列内のセルとのみ対話します。 アルゴリズムが列を検証するとき、その列に影響を与える可能性のあるすべての情報はすでにわかっています。 

DP は無効な中央列を決して受け入れません。すべての有効なボードは、DP によって処理される列マスクの 1 つのシーケンスに正確に対応します。 

すべての関連する隣接情報が利用可能になったときにすべての列が正確にチェックされるため、無効な構成が存続することはなく、有効な構成が破棄されることもありません。 DP はすべての有効なボードを調査し、ボード内の地雷の数を最大化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        r, c, M = map(int, input().split())

        S = 1 << r

        def bit(mask, row):
            return (mask >> row) & 1

        valid = [[[False] * S for _ in range(S)] for _ in range(S)]

        for left in range(S):
            for mid in range(S):
                for right in range(S):
                    ok = True

                    for row in range(r):
                        cur = bit(mid, row)

                        mines = 0
                        has_empty = False

                        for dc in (-1, 0, 1):
                            for dr in (-1, 0, 1):
                                if dc == 0 and dr == 0:
                                    continue

                                nr = row + dr
                                if not (0 <= nr < r):
                                    continue

                                if dc == -1:
                                    mine = bit(left, nr)
                                elif dc == 0:
                                    mine = bit(mid, nr)
                                else:
                                    mine = bit(right, nr)

                                if mine:
                                    mines += 1
                                else:
                                    has_empty = True

                        if cur == 0:
                            if mines > M:
                                ok = False
                                break
                        else:
                            if not has_empty:
                                ok = False
                                break

                    valid[left][mid][right] = ok

        NEG = -10**9

        dp = [[NEG] * S for _ in range(S)]
        dp[0][0] = 0

        for _col in range(c):
            ndp = [[NEG] * S for _ in range(S)]

            for a in range(S):
                for b in range(S):
                    cur_val = dp[a][b]
                    if cur_val == NEG:
                        continue

                    for nxt in range(S):
                        if valid[a][b][nxt]:
                            ndp[b][nxt] = max(
                                ndp[b][nxt],
                                cur_val + nxt.bit_count()
                            )

            dp = ndp

        ans = 0

        for a in range(S):
            for b in range(S):
                cur_val = dp[a][b]
                if cur_val == NEG:
                    continue

                if valid[a][b][0]:
                    ans = max(ans, cur_val)

        print(ans)

solve()
```実装の中核は、次の事前計算です。`valid[left][mid][right]`。 

中央の列のすべてのセルについて、8 つの隣接する可能性のある位置を調べます。 ボードの外側の行はスキップされます。 左右のマスクは、隣接する列に関する情報を自然に提供します。 

DP はマスクの 2 つのセンチネル列から始まります`0`。 これらのマスクはボードの一部としてカウントされません。 他のすべての列と同じ遷移ロジックを使用して、最初と最後の実際の列のみをチェックできます。 

よくある間違いの原因は、隣接する列が両方ともわかっている場合にのみ列を検証できるということを忘れていることです。 したがって、状態は 1 つではなく 2 つの連続した列マスクを保持します。 

もう 1 つの微妙な詳細は、地雷のカウントです。 新しい列が追加されると、新しい列の地雷のみがスコアに追加されます。 以前の列は、導入時にすでにカウントされていました。
