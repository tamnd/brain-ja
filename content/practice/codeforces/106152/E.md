 ## 解決策
 ## 問題の理解

 できるだけ多くの地雷タイルを使用して長方形のマインスイーパー ボードを構築する必要があります。 すべての地雷は少なくとも 1 つの空のタイルに触れなければならないため、地雷タイルを他の地雷で完全に囲むことはできません。 空のタイルはいくつかの地雷に接触する可能性がありますが、隣接する地雷の数が指定された制限を超えることはできません`M`。 ボードのサイズは 2 ～ 6 行と列と小さいため、可能な最大数の鉱山のみを出力する必要があります。 元の問題の制約と例は、ICPC Tishreen Collegiate Programming Contest の問題アーカイブからのものです。 

小さな寸法が鍵です。 ボードには最大でも 36 個のセルがあり、すべての完全なボードを試すことは不可能です。`2^(r*c)`可能性。 6 x 6 ボードの場合、これは次のようになります。`2^36`、それは数え切れないほどです。 ただし、1 行に含まれるセルは最大 6 個であるため、`2^6 = 64`考えられる行パターン。 これは、ボードを行ごとに処理し、将来の決定に影響を与える行のみを記憶することを示唆しています。 

困難なケースは、大きな入力ではなく、境界状況です。 端の行には隣接するセルが少ないため、すべてのセルを 8 つの隣接セルがあるかのように扱うと、誤った答えが生成される可能性があります。 

たとえば、次の入力を使用します。```
2 2 1
```ボード全体には 4 つのセルがあり、空のセルは最大 1 つの地雷に触れることができます。 2 つの地雷を斜めに配置することは無効です。各地雷は地雷のみに接触し、空のセルには接触しないためです。 空のセルのみをチェックする不注意な解決策では、誤って 2 つの地雷が許可されてしまいます。 

別のケースは次のとおりです。```
2 2 8
```答えは`3`、 ない`4`。 地雷でいっぱいのボードは、すべての地雷には空の隣がなければならないというルールに違反します。 空のセルの周囲の地雷の最大数のみをチェックするソリューションでは、無効なすべての地雷ボードが受け入れられます。 

3 番目のよくある間違いは、DP 内の単一行で発生します。 一番上の行の場合、セルの上には行がありません。 実装が誤って欠落している行を地雷が含まれているものとして扱った場合、境界付近の有効な構成が拒否されます。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべてのセルに「mine」または「empty」のいずれかを割り当てて、両方のルールを検証します。 ボードの場合`r*c`セル、これはチェックします`2^(r*c)`ボード。 最大のボードには 36 個のセルがあり、`68,719,476,736`可能性。 非常に迅速な検証ステップであっても、これを実現することはできません。 

有益な観察は、ルールがローカルであるということです。 セルが有効かどうかは、セル自体と隣接する 8 つのセルにのみ依存します。 新しい行を選択すると、完全に決定される唯一の行は、新しい行の 2 つ上の行です。 3 つの連続した行が得られたら、中央の行を確認することができ、それを再度確認する必要はありません。 

これは行ベースの動的プログラミングにつながります。 行はビットマスクとして保存されます。 ビット値 1 は、セルが地雷であることを意味します。 次の行を追加することで古い行を検証できるため、DP は最後の 2 行を記憶しています。 

総当たりは、考えられるすべてのボードを検査するため機能します。 同じ局所的な状況を何度も繰り返すため、失敗します。 DP は、最後の 2 行が同じであるすべての部分ボードを 1 つの状態にグループ化することで、この繰り返しを排除します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(r_c) * r_c) | O(r*c) | 遅すぎる |
 | 最適 | O(r * 2^(3*c)) | O(2^(2*c)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての行をビットマスクで表します。 との行の場合`c`コラム、あります`2^c`可能なマスク。 少し`1`私のものとビットを意味します`0`空という意味です。 
2. 行を上から下に処理します。 DP 状態には、前の 2 つの行と、これまでに配置された地雷の最良の数が保存されます。 新しい行を追加する場合、連続する 3 つの行を使用できます。 
3. これら 3 つの行の中央を確認します。 空のセルごとに、3 行の隣接する位置にある地雷の数を数えます。 カウントがより大きい場合`M`、トランジションは無効です。 
4. 中央の行にあるすべての地雷を確認します。 3 つの行内に隣接する空のセルがない場合、遷移は無効です。 
5. 中央の行が有効な場合は、ウィンドウを前方に移動します。 新しい状態では最後の 2 行が保持され、新しい行に地雷の数が追加されます。 
6. すべての行を選択した後、その下の空の空の行を使用して最後の行を検証します。 答えは、すべての完成状態の中で最も良い値です。 

これが機能する理由は、すべての隣接セルが既知の場合にすべてのセルが正確にチェックされるためです。 次の行が選択された後は、その行は以前の行に影響を与えることはできないため、その行を状態から破棄しても必要な情報は失われません。 DP の不変条件は、保存されているすべての状態が、最後の 2 行が同じであるすべての可能な有効な部分ボードと、それらの間の最大マイン数を表すということです。 

## Python ソリューション```python
import sys
from functools import lru_cache

input = sys.stdin.readline

def solve_case(r, c, limit):
    masks = list(range(1 << c))
    pop = [x.bit_count() for x in masks]

    def valid(upper, middle, lower):
        for col in range(c):
            cnt = 0
            if ((middle >> col) & 1) == 0:
                for row_mask in (upper, middle, lower):
                    for dc in (-1, 0, 1):
                        nc = col + dc
                        if 0 <= nc < c and ((row_mask >> nc) & 1):
                            cnt += 1
                if cnt > limit:
                    return False

            else:
                has_empty = False
                for row_mask in (upper, middle, lower):
                    for dc in (-1, 0, 1):
                        nc = col + dc
                        if 0 <= nc < c and ((row_mask >> nc) & 1) == 0:
                            has_empty = True
                if not has_empty:
                    return False
        return True

    @lru_cache(None)
    def dp(row, prev2, prev1):
        if row == r:
            return pop[prev1] if valid(prev2, prev1, 0) else -10**9

        ans = -10**9
        for cur in masks:
            if row == 0:
                ans = max(ans, dp(row + 1, 0, cur) + pop[cur])
            else:
                if valid(prev2, prev1, cur):
                    ans = max(ans, dp(row + 1, prev1, cur) + pop[cur])
        return ans

    return dp(0, 0, 0)

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        r, c, m = map(int, input().split())
        ans.append(str(solve_case(r, c, m)))
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```行マスクはテスト ケースごとに 1 回生成されます。 の`valid`機能はソリューションの中心です。 隣接する 3 つの行を受け取り、中央の行が両方のマインスイーパー ルールを満たすかどうかを判断します。 

再帰的 DP は次のように使用します。`(row, prev2, prev1)`その状態として。`prev2`そして`prev1`配置する次の行のすぐ上の 2 行です。 次の行が選択されると、古い中央の行が完全にチェック可能になります。 

下の境界線は、最後の行の後にゼロマスクを渡すことによって処理されます。 これは地雷のない行を表し、検証ロジック内の特別な処理を回避します。 

Python の整数には任意の精度があるため、オーバーフローの問題はありません。 インデックス作成の唯一の危険は、隣接する列をチェックすることです。そのため、すべての列へのアクセスが検証されます。`0 <= nc < c`。 

## 実用的な例

 サンプル入力の場合:```
4 5 3
```1 つの最適な配置には 12 個の地雷が含まれます。 

| ステップ | 前の行 | 新しい行 | 検証された行 | 最高の鉱山 |
 | --- | --- | --- | --- | --- |
 | 1 | なし | 選択された行 0 | なし | 行 0 鉱山 |
 | 2 | 行 0 | 選択した行 1 | 行 0 | 行 0 + 行 1 |
 | 3 | 行 0、行 1 | 選択した行 2 | 行 1 | 過去のベスト |
 | 4 | 行 1、行 2 | 選択した行 3 | 行 2 | 過去のベスト |
 | 5 | 行 2、行 3 | 終わり | 行 3 | 12 |

 このトレースは、すべての行がその隣接行がわかった後にのみチェックされることを示しています。 

サンプル入力の場合:```
3 3 4
```答えは6です。 

| ステップ | 前の行 | 新しい行 | 検証された行 | 最高の鉱山 |
 | --- | --- | --- | --- | --- |
 | 1 | なし | 行 0 | なし | 行 0 カウント |
 | 2 | 行 0 | 行 1 | 行 0 | 更新されました |
 | 3 | 行 0、行 1 | 行 2 | 行 1 | 更新されました |
 | 4 | 行 1、行 2 | 終わり | 行 2 | 6 |

 この事例は、DP がやみくもに地雷の数を最大化するわけではないことを示しています。 それは、鉱山に空きの隣がない州を拒否します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(r * 2^(3c)) | すべての遷移には 3 つの行マスクが関係します。 
| スペース | O(r * 2^(2c)) | メモ化は、行インデックスと 2 つのマスクによって形成された状態を保存します。 

最大幅が 6 の場合、行マスクは 64 個しかありません。 状態の数は少ないままであるため、解は制約に簡単に適合します。

 ## 特殊なケース

 のために`2 2 1`この場合、DP はボードの周りに空の仮想行から始まります。 各鉱山には隣接する空のセルがないため、完全な鉱山ボードは失敗します。 遷移バリデーターは、応答に貢献する前にそれを拒否します。 

のために`2 2 8`この場合、すべての空セルが 8 つの隣接セルすべてに接触する可能性があるため、空セルの制限はなくなります。 アルゴリズムは引き続き個別の地雷要件をチェックするため、誤って 4 つを返すのではなく、3 つの地雷を備えた最適なボードを見つけます。 

境界行の場合、仮想ゼロ マスクは欠落している外側の行を表します。 これは、コーナー地雷には実際のマインスイーパーの近隣ルールに一致する、ボード上に実際に存在する空の近隣地雷のみが必要であることを意味します。
