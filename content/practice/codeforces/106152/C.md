 ## 解決策
 ## 問題の理解

 食品のラインナップがあり、それぞれの項目には満足度が設定されています。 すべての項目について、取得することもスキップすることもできます。 

隣接する 2 つのアイテムを持ち込むことはできないという制限があります。 アイテムを選ぶなら`i`、次にアイテム`i+1`スキップする必要があります。 

課題は、このルールの下で得られる最大の合計の望ましさを見つけることです。 入力は、食品項目の数とその満足度の値で構成されます。 出力は 1 つの整数、つまり達成可能な最大の合計の望ましさです。 

制約`n ≤ 10000`十分に小さいので、`O(n²)`ソリューションは最悪の場合でもすでに約 1 億回の操作を実行することになり、不必要にコストがかかります。 この問題は隣接する位置のみを問うため、各位置が一定数の前の位置に依存する動的計画法による解決策を強く示唆しています。 アン`O(n)`解決策が自然な目標です。 

よくある間違いは、隣接するすべてのペアから貪欲に大きい値を取得することです。 ローカルな選択が必ずしもグローバルな最良の答えにつながるとは限りません。 

考慮する：```
3
2 1 2
```正しい答えは次のとおりです。```
4
```1番目と3番目の項目を取り上げます。 隣接する値のみを調べる貪欲な戦略では、この組み合わせを見逃す可能性があります。 

もう 1 つの特殊なケースは、項目が 1 つしかない場合です。```
1
42
```答えは次のとおりです。```
42
```盲目的にアクセスする DP 実装`dp[i-2]`小さなインデックスを処理しないと、ここで失敗する可能性があります。 

3 番目のエッジ ケースは、多くの値がゼロの場合に発生します。```
5
0 0 0 0 0
```答えは次のとおりです。```
0
```アルゴリズムは、何も取らないことが事実上最適である状況を正しく処理する必要があります。 

## アプローチ

 ブルートフォースアプローチは、食品のすべてのサブセットを調べ、隣接する選択された位置が含まれているかどうかを確認し、その満足度の合計を計算することです。 これは、すべての有効な選択肢を明示的に考慮するため、正しいです。 

問題は、`2^n`サブセット。 たとえ`n = 50`、これはすでに時間内に計算できる範囲をはるかに超えており、実際の制限は次のとおりです。`n = 10000`。 

重要な観察は、私たちが所定の位置に立つとき、`i`、意味のある可能性は 2 つだけです。 

項目をスキップするか`i`、この場合、ベストアンサーは次のとおりです。`i`まさにこれまでのベストアンサーです`i-1`。 

またはアイテムを受け取ります`i`、その場合の項目`i-1`は取れません。 達成可能な最良の値が、次の時点までの最良の答えになります。`i-2`アイテムの魅力に加えて`i`。 

これはポジションでの決定を意味します`i`は、以前に計算された 2 つの状態のみに依存します。 この構造はまさに動的プログラミングの設計対象です。 

させて`dp[i]`最初の条件を使用して得られる最大の望ましさを示します。`i`アイテム。 

それから：```
dp[i] = max(
    dp[i-1],
    dp[i-2] + value[i]
)
```すべての状態が 1 回計算され、線形時間の解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | お(1) | 遅すぎる |
 | 最適なDP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして望ましさの値。 
2. ベースケースを取り扱う`n = 1`唯一の値を返すことによって。 
3. DP 配列を作成します。`dp[i]`最初から得られる最大の好感度を格納します。`i`アイテム。 
4.セット`dp[0] = 0`、空のプレフィックスを表します。 
5.セット`dp[1] = value[0]`、アイテムが 1 つしかないため、最良の選択はそれを取ることです。 
6. ポジションごとに`i`から`2`に`n`、次を計算します。```
dp[i] = max(
    dp[i-1],
    dp[i-2] + value[i-1]
)
```最初のオプションは、現在の項目をスキップします。 2 番目のオプションは、それを取得し、少なくとも 1 つ前の位置で終了する最も有効なソリューションと組み合わせます。 
7. 出力`dp[n]`。 

### なぜ効果があるのか

 不変条件とは、`dp[i]`最初の最適な答えを常に保存します`i`アイテム。 

のために`i`- 番目の項目では、すべての有効なソリューションは 2 つのグループのうちの 1 つに正確に属します。 

アイテムが選択されていない、または値が付与されている`dp[i-1]`、または選択された場合、アイテムを強制します`i-1`排除され価値を与える`dp[i-2] + value[i]`。 

これらが唯一の可能性であり、そのうちの大きい方を採用するため、`dp[i]`が最適です。 帰納法により、最終的な答えを含むすべての状態が正しい`dp[n]`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

if n == 1:
    print(a[0])
else:
    dp = [0] * (n + 1)

    dp[0] = 0
    dp[1] = a[0]

    for i in range(2, n + 1):
        dp[i] = max(dp[i - 1], dp[i - 2] + a[i - 1])

    print(dp[n])
```DP 配列では、便宜上 1 から始まるインデックスを使用します。`dp[i]`最初のものを指します`i`元の配列は 0 ベースのままです。 

移行では、`a[i - 1]`なぜなら、`i`-th DP 状態は、インデックスに格納されている要素に対応します`i - 1`。 

最も一般的な実装上の間違いは、配列のインデックス付けシステムを混合し、誤って使用することです。`a[i]`これにより、すべての値が 1 位置ずつシフトされ、不正確な結果やインデックス エラーが発生します。 

初期化も重要です。`dp[0]`は空のプレフィックスから何も取得しないことを表しますが、`dp[1]`は最初の項目に対する最良の回答を表します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各 DP 状態は 1 回計算されます。 
| スペース | O(n) | DP 配列には次のものが格納されます。`n + 1`状態 |

 と`n ≤ 10000`, リニアタイムは非常に快適です。 メモリ使用量もわずかで、必要な整数は数千個だけです。 

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))

    if n == 1:
        return str(a[0])

    dp = [0] * (n + 1)
    dp[1] = a[0]

    for i in range(2, n + 1):
        dp[i] = max(dp[i - 1], dp[i - 2] + a[i - 1])

    return str(dp[n])

# provided samples
assert run("5\n3 8 10 2 0\n") == "13"
assert run("7\n0 9 10 2 0 0 0\n") == "11"
assert run("1\n42\n") == "42"

# custom cases
assert run("1\n0\n") == "0", "minimum size"
assert run("5\n0 0 0 0 0\n") == "0", "all zeros"
assert run("3\n2 1 2\n") == "4", "take first and third"
assert run("6\n5 5 5 5 5 5\n") == "15", "all equal values"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 0`|`0`| 最小入力サイズ |
 |`5 / 0 0 0 0 0`|`0`| すべての値がゼロ |
 |`3 / 2 1 2`|`4`| 隣接しない選択は貪欲な選択に勝ります |
 |`6 / 5 5 5 5 5 5`|`15`| 等しい値が繰り返される |

 ## 特殊なケース

 次のことを考慮してください。```
1
42
```アルゴリズムはすぐに基本ケースを使用して出力します。`42`。 DP 移行は必要ありません。 これにより、への無効なアクセスが回避されます。`dp[-1]`またはその他の範囲外の位置。 

考慮する：```
3
2 1 2
```DP 値は次のようになります。```
dp[1] = 2
dp[2] = 2
dp[3] = 4
```アルゴリズムは 1 番目と 3 番目の項目を正しく組み合わせて、`4`。 

考慮する：```
5
0 0 0 0 0
```DP テーブルはすべてゼロのままです。```
dp = [0, 0, 0, 0, 0, 0]
```出力は`0`、これは達成可能な最大の望ましい値です。 

これらのケースは、再帰処理が小さな入力、貪欲でない最適な選択、およびゼロ値の項目を正しく処理することを示しています。
