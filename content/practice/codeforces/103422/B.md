 ## 解決策
 ## 問題の理解

 値の配列が与えられます。各値は、ライン内の人物に割り当てられた「仕事の難易度」を表します。 この配列の任意の連続セグメントを選択し、そのセグメントに非常に特殊な変換を適用することができます。右から左にスイープし、各位置で現在の値をそのすぐ右の値との間の最小値に置き換えます。 これにはサフィックスの最小値を左方向に伝播する効果があるため、操作後、選択したセグメント内のすべての位置がそのセグメント内のサフィックスの最小値になります。 

タスクは、この変換を適用した後に得られるセグメントの合計ができるだけ大きくなるようなセグメントを選択することです。 セグメント境界と、その変換されたセグメントの結果の合計の両方を出力する必要があります。 

配列サイズは最大 100,000、値は最大 10^9 です。 これにより、最悪の場合 O(n^3) に達するため、すべての O(n^2) セグメントを試行し、それぞれ O(n) で単純に変換をシミュレートするアプローチは直ちに除外されます。 O(n^2) の総作業量であっても、一般的な 1 秒の制約の下では大きすぎるため、解決策では検索を線形または線形演算時間近くまで短縮する必要があります。 

微妙なエッジ ケースは、変換によって増大する構造が非常に方向性のある方法で破壊されるという事実から生じます。 たとえば、[1, 3, 5, 7] のような厳密に増加するセグメントを取得した場合、操作後は変更されずに [1, 3, 5, 7] になりますが、[7, 5, 3, 1] のような減少セグメントを取得した場合、繰り返し最小値に大きく崩壊します。 「長いセグメントは常に優れている」という単純な期待は失敗します。セグメントを拡張すると、伝播された最小値が減少し、以前の要素の寄与が大幅に減少する可能性があるためです。 

もう 1 つの特殊なケースは、等しい値が表示される場合です。 たとえば、[5, 1, 1, 10] では、大きな 10 を含むセグメントを選択すると、以前の要素が 1 に折りたたまれる可能性があるため、小さな値の後に高い値を含めることが必ずしも有益であるとは限りません。 

## アプローチ

 ブルートフォース戦略は、エンドポイント l と r のすべてのペアを考慮し、v[l..r] に対する gorbasort 演算をシミュレートし、その合計を計算することです。 右から左に 1 回スイープするため、1 つのセグメントのシミュレーションには O(r - l) 時間がかかります。 すべてのセグメントを合計すると、O(n^2) 個のセグメントがあり、それぞれに線形時間がかかるため、最悪の場合、O(n^3) 個の動作が発生します。 これは、10^5 までの n にとっては遅すぎます。 

重要な構造上の観察は、この操作により、変換後の各位置が、選択されたセグメント内のサフィックス最小値として定義されるということです。 右端点 r を固定すると、セグメントを左方向に拡張しながら要素の寄与を効果的に構築できます。 各要素は、セグメント内でその右側にあるすべての要素よりも小さい場合に独自の値を提供するか、これまでに確認された最小値に「固定」されます。 

これにより、変換された合計は、左の端点で区分的線形関数のように動作します。 左に移動すると、セグメントの値は新しい最小値に遭遇したときにのみ変更されます。これは、その最小値のみが将来の接尾辞最小値の伝播を変更するためです。 このような点の間では、ブロックの寄与は予測可能であり、現在の最小値と移動距離を使用して一定時間で計算できます。 

これにより、現在の最小値と累積寄与を維持しながら、右端点 r を固定し、左方向に拡張することができます。 新しい小さい値が見つかるたびに、最小値を更新し、それに応じて寄与を調整します。 各要素は固定 r に対して最大 1 回だけ新しい最小値になるため、すべての r にわたる合計仕事量は線形です。

 ## アルゴリズムのチュートリアル

すべての可能な右端点 r に対して反復処理を行います。 各 r について、セグメント [l, r] の最適な変換された合計を維持しながら、ポインター l を r から左に拡張します。 

1. r を固定して開始し、現在の最小値を v[r] に初期化し、現在の合計を v[r] に初期化します。 セグメント [r, r] は操作によって変更されないため、この基本ケースは正確です。 
2. 一度に 1 ステップずつ左に移動します。 v[l] を含めると、それを現在の最小値と比較します。 v[l] が現在の最小値以上の場合、その右側にあるすべてのものがすでにより小さなサフィックス最小値を強制しているため、変換後 v[l] はまさにその最小値になります。 これは、その寄与が単に現在の最小値であることを意味します。 
3. v[l] が現在の最小値より小さい場合、v[l] は新しい最小値になります。 この時点以降、別のより小さい要素が表示されるまで、l 以降のすべての位置はこの新しい値によって制限されます。 最小値を更新し、それに応じて累計を調整します。 
4. 各ステップで、[l, r] の計算された合計をこれまでの最良の答えと比較し、最大値が改善された場合にセグメントのエンドポイントを保存します。 

重要な効率の向上は、変換されたセグメント全体を再計算しないため、左に移動するたびに一定の作業のみが実行されることです。 代わりに、接尾辞の最小構造が変更を単純な状態更新に折りたたむという事実に依存します。 

これらのステップの後、最適な l、r、および対応する計算された合計を出力します。 

### なぜ効果があるのか

 固定セグメントの場合、位置 i の最終値は v[i]、v[i+1]、...、v[r] の最小値です。 これは、変換されたセグメントがサフィックス最小構造によって完全に決定されることを意味し、セグメントを左に拡張するにつれて単調に進化します。 アルゴリズムは正確にこの構造を増分的に維持するため、すべての更新は再計算せずに真の変換されたセグメントの合計を反映します。 サフィックス最小プロファイルのすべての変更は、新しい最小値が現れるとすぐにキャプチャされるため、セグメントの状態が誤って表現されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    v = list(map(int, input().split()))

    best_sum = -10**30
    best_l = best_r = 0

    for r in range(n):
        cur_min = v[r]
        cur_sum = v[r]

        if cur_sum > best_sum:
            best_sum = cur_sum
            best_l, best_r = r, r

        for l in range(r - 1, -1, -1):
            if v[l] < cur_min:
                cur_min = v[l]

            cur_sum += cur_min

            if cur_sum > best_sum:
                best_sum = cur_sum
                best_l, best_r = l, r

    print(best_l + 1, best_r + 1, best_sum)

if __name__ == "__main__":
    solve()
```コードは右のエンドポイント ループを実装し、実行最小値と変換された合計を維持しながら左に展開します。 重要な実装の詳細は次のとおりです。`cur_sum += cur_min`新しく追加された各要素は、操作を適用した後の現在のサフィックスの最小値に正確に寄与するため、これは有効です。 

インデックスは内部的に 0 ベースの形式で保存され、問題のインデックス付け規則に合わせて、出力時にのみ 1 ベースの形式に変換されます。

 ## 特殊なケース

 サイズ 1 の最小入力は、基本状態を直接示します。 アルゴリズムはその単一のインデックスでセグメントを初期化するため、拡張は発生せず、結果はすぐに正しいものになります。 

[1, 2, 3, 4] のような厳密に増加する配列では、左方向に拡張するときに新しい最小値が出現しないため、各要素がその完全な値に寄与します。 このアルゴリズムは、cur_min を変更せずに維持し、セグメント全体にわたる単純な算術合計を累積します。 

[5, 4, 3, 2, 1] のような厳密に減少する配列では、現在の最小値への更新が頻繁に行われます。 新しい要素はそれぞれ、支配的なサフィックスの最小値となり、以前の大きな値が繰り返しオーバーライドされる様子がトレースに示されます。 より小さい値が検出されるたびに各ステップで cur_min が更新され、suffix-minimum 構造が確実に保持されるため、実装ではこれが正しく反映されます。
