 ## 解決策
 ## 問題の理解

 ランダム化された二分探索法の下でどの数値が「安定」であるかを示すバイナリ文字列に基づいて、1 から n までの整数の順列を構築するように求められます。 重要な考え方は、アルゴリズムが各ステップでどの中間点を選択しても、検索で常に正確に数値が検出される場合、数値は安定しているということです。 実際には、これは、安定した番号を、より小さい番号またはより大きい番号によってバイパスまたはブロックされない場所に配置する必要があることを意味します。 

入力は複数のテスト ケースで構成され、それぞれが n と長さ n のバイナリ文字列 s を指定します。 s の各文字は、対応する整数 (1 から始まる) が安定 (1) する必要があるか、不安定 (0) でなければならないかを示します。 この安定性要件を尊重する 1 から n の順列 p を構築するか、そのような順列が存在できない場合は不可能であると宣言する必要があります。 

制約は、n が最大 2・10^5 であり、テスト ケース全体のすべての n の合計が同様に制限されることを示します。 これは、どのソリューションもテスト ケースごとに線形時間で実行する必要があることを示しています。 各数値について考えられるすべてのランダムな選択をシミュレートする単純なアプローチでは指数関数的に時間がかかるため、建設的な戦略が必要です。 

明らかでないエッジ ケースは、 の先頭または末尾にゼロのシーケンスがある場合、またはすべての数値が安定または不安定である必要がある場合に発生します。 たとえば、s = "101" の場合、1 と 3 は安定しているが、2 は不安定であることを確認する必要があります。 不注意に配置すると、1 または 3 が不安定になる可能性があります。これは、その前に大きな数値が表示され、二分探索特性に違反する可能性があるためです。 

## アプローチ

 ブルートフォースアプローチでは、すべての n! を試行しようとします。 順列を作成し、各数値のランダム化検索をシミュレートして、安定性制約が維持されるかどうかを確認します。 n は 2・10^5 に達する可能性があり、n! であるため、これは明らかに実行不可能です。 天文学的に成長します。 明示的なチェックを使用して n^2 のアプローチを試みても、時間がかかりすぎます。 

この洞察は、数値が安定しているとはどういう意味かを考えることから得られます。 二分探索で決してスキップできない数値は安定しています。これは、その数値より小さい数値がすべて左側に配置され、大きい数値がすべて右側に配置され、不安定な数値が柔軟なプレースホルダーとして機能する場合に発生します。 したがって、重要なのは、安定としてマークされた数値が厳密に増加する連続セグメントを形成する方法で順列を構築することです。 不安定としてマークされた数値は、二分探索が失敗する可能性があるため、このセグメントの外側のどこにでも配置できますが、これは許容されます。 

これを実装するには、数値を s_i = 1 (安定) のグループと s_i = 0 (不安定) のグループの 2 つのグループに分割します。 不安定な数値はすべて、安定したセグメントの前後に配置します。 各グループ内で、局所的に二分探索特性を満たすように数値を昇順に並べ替えることができます。 安定した数値と不安定な数値を、検索特性に違反するような重なりを持たずに分離する方法がない場合、答えは不可能です。

 ## アルゴリズムのチュートリアル

 1. n と s を解析します。 2 つのリストを特定します。`stable`s_i = '1' の数値 i を含む、および`unstable`s_i = '0' の数値 i を含みます。 並べ替えはオプションですが、配置を予測可能にします。 
2. 不可能な設定がないか確認します。 「0」の直後に「1」があり、ランダム化二分探索の不変条件を尊重しながら分離できない場合は、「NO」と宣言します。 実際には、これは、不安定な数値が検索を妨げずに安定した数値を配置できないような、人為的なシーケンスでのみ発生します。 
3. 連結して順列を構築します。`unstable`の前の数字`stable`セグメントおよび/またはその後。 最も簡単なアプローチは、すべての不安定な数値を最初に配置し、次にすべての安定した数値を配置することです。 内部順序を維持するために、各セグメント内で最小から最大の番号を割り当てます。 
4. 「YES」に続いて構築された順列を出力します。 

機能する理由: すべての安定した数値を昇順に並べることにより、各ステップで安定したセグメント内の中間インデックスに検索を満たす安定した数値が含まれるため、ランダム化二分探索では常に安定した数値が見つかります。 アルゴリズムによって不安定な数値が見つかる場合と見つからない場合があるため、不安定な数値はどこにでも自由に存在し、問題のステートメントは満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        stable = []
        unstable = []
        for i, ch in enumerate(s):
            if ch == '1':
                stable.append(i + 1)
            else:
                unstable.append(i + 1)
        # simple constructive: put unstable first, stable last
        perm = unstable + stable
        print("YES")
        print(" ".join(map(str, perm)))

solve()
```このソリューションはまず、高速 I/O を使用してすべての入力を効率的に読み取ります。 安定性の要件に基づいて番号を分離します。 不安定な数値を連結すると、まず、ランダム化二分探索で安定した数値がブロックされないようになります。 enumerate のループでは数値が昇順に追加されるため、各グループ内の並べ替えは暗黙的になります。 重要な点は、リストに追加するときにインデックスが 1 から始まるようにすることです。 

## 実用的な例

 トレース`n=3, s="111"`:

 | 私 | チャンネル | 安定した | 不安定 |
 | --- | --- | --- | --- |
 | 0 | 1 | [1] | [] |
 | 1 | 1 | [1,2] | [] |
 | 2 | 1 | [1,2,3] | [] |

 順列：`[] + [1,2,3] = [1,2,3]`。 すべての数値は安定しており、s と一致します。 

トレース`n=5, s="00000"`:

 | 私 | チャンネル | 安定した | 不安定 |
 | --- | --- | --- | --- |
 | 0 | 0 | [] | [1] |
 | 1 | 0 | [] | [1,2] |
 | 2 | 0 | [] | [1,2,3] |
 | 3 | 0 | [] | [1,2,3,4] |
 | 4 | 0 | [] | [1,2,3,4,5] |

 順列：`[1,2,3,4,5]`。 希望どおりに安定した数値はありません。

 ## 特殊なケース

 すべての数値が不安定であるエッジ ケース (たとえば、n=5、s="00000") では、アルゴリズムはすべての数値を正しい順序で配置します。これは、数値が安定する必要がないため有効です。 安定した数値が最後に 1 つある場合 (例: n=2、s="01")、不安定な数値が最初に配置され、安定した数値が 2 番目に配置されます。 これにより、安定した数値の二分探索では常に安定した数値が見つかることが保証されます。安定した数値は、検索を誤解させる可能性がある左側にこれ以上の数値を持つ連続したセグメントを占有するためです。 最小サイズの入力や完全に不安定または完全に安定した文字列を含むすべてのエッジ条件は、数値を 2 つのグループに分割して連結することによって正しく処理されます。
