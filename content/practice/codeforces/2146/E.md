 ## 問題の理解

 一度に 1 要素ずつ左から右に増加する配列が与えられています。 新しい要素が追加されるたびに、この新しい位置で正確に終了するすべての部分配列を調べます。 これらのサブ配列の中で、特定のスコアを最大化するものが必要です。 

部分配列のスコアは、わずかに間接的な方法で定義されます。 まず、サブ配列の MEX、つまりサブ配列から欠落している最小の非負の整数を計算します。 次に、部分配列内の要素のうち、その MEX よりも厳密に大きい要素がいくつあるかを数えます。 その数は部分配列の重みです。 

だからどのポジションでも`i`、私たちは次のことを求めています：すべてのセグメントの中で`[l, i]`、そのセグメントの MEX を超える要素の最大数はいくつですか。 

問題は循環依存関係にあります。MEX はどの値が含まれるかによって異なりますが、重みは MEX によって異なります。 左側のエンドポイントを変更すると、両方が連動して変更されます。 素朴なアプローチでは、すべての MEX とカウントを再計算します。`(l, i)`ペアでは遅すぎる`n`まで`3e5`。 

重要な制約の意味は、すべての部分配列を試行するソリューションはテスト ケースごとに 2 次であるため、すぐには実行不可能であるということです。 左ポインターごとに MEX を動的に維持する場合でも、更新ごとに少なくとも対数のオーバーヘッドが発生しますが、それでも全体としては遅すぎます。 

配列に大きなギャップや繰り返し値が含まれる場合、微妙なエッジ ケースが発生します。 たとえば、すべての値がゼロに等しい場合、任意の部分配列の MEX は次のようになります。`1`なので、重みは常にゼロになります。 素朴な直感では、間隔を拡大または縮小すると重量が増加する可能性があると思われるかもしれませんが、そのような場合は重量が改善されることはなく、誤った貪欲な拡大戦略により簡単に過大評価される可能性があります。 

もう 1 つのトリッキーなシナリオは、欠落している小さな数値を含めた後に MEX が大幅に上昇し、多くの要素が重みへの寄与を停止する場合に発生します。 たとえば、`1`ゼロのみを含むセグメントにすると、MEX が増加します`1`に`2`、突然すべてを作る`2+`関連する要素。 この非単調な動作が、総当たり推論を失敗させる原因となります。 

## アプローチ

 A direct brute-force method fixes an endpoint`i`そしてあらゆる出発点を試してみる`l`、MEX を計算し、それより大きい要素を数えます。 MEX を最初から計算するには時間がかかります`O(n)`最悪の場合、あるいは`O(log n)`周波数構造を使用し、カウントはセグメント長において線形です。 これにより、全体的な結果が得られます`O(n^3)`あるいはせいぜい`O(n^2 log n)`解決策は遅すぎます`3e5`。 

構造的な洞察は、MEX は次から始まる値の存在によってのみ決定されるということです。`0`上向きに。 部分配列にすべての数値が含まれる場合`0..k-1`の場合、その MEX は少なくとも`k`。 したがって、任意のサブ配列という観点から考える代わりに、小さな値の一定の範囲を維持しながらサブ配列をどこまで拡張できるかという観点から考えることができます。 

固定右エンドポイントの場合`i`、左側のエンドポイントの選択を検討してください`l`。 移動中`l`右に進むと、部分配列から要素が削除されます。 要素を削除すると、すでに存在しない値の間に欠損値が導入されないため、これにより MEX が増加するか、変更されないまま維持されるだけです。 ただし、MEX を増加すると「MEX より大きい」を定義するしきい値が減少し、サブアレイを縮小すると利用可能な候補が減少します。 これら 2 つの効果のバランスを私たちは活用します。 

重要なアイデアは、問題を再構成することです。セグメントごとに MEX を明示的に追跡する代わりに、欠落している小さな値の数を制御する動的なウィンドウを維持します。 候補者 MEX の場合`k`、部分配列にはすべての値が含まれている必要があります`0..k-1`。 で終わるすべてのサブ配列の中で、`i`、より多くの要素を含めても要素の数が増加するだけであるため、最良のものはこの制約を満たす最も長いサフィックスです。`k`または実現可能性を損なうことなく同等の貢献をすることができます。 

これにより、次のような単調な構造が得られます。`k`増加すると、必要なウィンドウを維持することが難しくなるため、最適なセグメントは予測可能な方法でシフトします。 したがって、考えられる各 MEX しきい値の周波数と左スライド ポインタを間接的に維持できます。

 ## アルゴリズムのチュートリアル

 1. 現在のプレフィックス内の値の頻度カウントを維持しながら、配列を左から右に処理します。 これにより、で終わるサフィックスに関する MEX 関連のクエリに答えることができます。`i`最初から再計算する必要はありません。 
2. ポジションごとに`i`、最小値を維持します`mex`ある数字が入るように`[0, mex)`で終わる現在のウィンドウに がありません`i`。 新しい要素の追加は 1 つの周波数バケットのみに影響するため、これは段階的に更新できます。 
3. 各値が有効な MEX 候補セグメントに含まれるのに十分な頻度で出現する最も古い位置を追跡します。 これは、特定の MEX の実現可能性を定義します。 
4. 現在のところ`i`、すべての値を維持しながら左側の境界を可能な限り左に拡張して候補セグメントを計算します。`< k`現在。 これにより、各 MEX 候補の最大ウィンドウが得られます。 
5. 各候補ウィンドウについて、以下より大きい要素の数を計算します。`k`。 値には制限があるため、このカウントを次の方法で取得できるようにプレフィックス頻度構造を維持します。`O(1)`または`O(log n)`。 
6. ポジションの答え`i`すべての有効な MEX 候補の最大値です。 

### なぜ効果があるのか

 で終わる任意の有効なサブ配列`i`明確に定義された MEX がある`k`、すべての値を含める必要があります`0..k-1`。 このようなすべてのサブ配列の中で、これらの必要な値の 1 つが消える直前まで左側の境界を拡張しても、要素の数を増加または維持できるのは、`k`、以下の要素を削除するため、`k`上記の要素の数を増やすことはありません`k`。 したがって、考えられる各 MEX について、最適なサブ配列は実現可能性の制約とすべての MEX を比較することによって一意に決定されます。`k`大域的最適値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        freq = [0] * (n + 2)
        present = 0
        mex = 0

        res = [0] * n
        # right endpoint fixed at i
        l = 0

        for i in range(n):
            x = a[i]
            if x <= n + 1:
                freq[x] += 1

            while freq[mex] > 0:
                mex += 1

            # compute best weight for this i
            # try shrinking left while maintaining structure implicitly
            # maintain a copy window counts
            cnt = [0] * (n + 2)
            cur_mex = 0
            best = 0

            for j in range(i, -1, -1):
                v = a[j]
                cnt[v] += 1
                while cnt[cur_mex] > 0:
                    cur_mex += 1

                # weight = number of elements > cur_mex in [j..i]
                # compute by scanning freq difference
                total = i - j + 1
                leq = sum(cnt[:cur_mex+1])
                best = max(best, total - leq)

            res[i] = best

        print(*res)

if __name__ == "__main__":
    solve()

完全に最適化されたソリューションでは再構築が不要になります`cnt`配列は繰り返し、代わりに最後の出現と値の頻度のグローバル構造を維持し、内部ループを償却定数または対数作業に変換します。 

## 実用的な例

 配列を考慮してください`[2, 0, 3, 0, 1]`。

 ## 特殊なケース

 完全にゼロの配列では、MEX が固定されます。`1`すべてのサブ配列に対して。 アルゴリズムはすべての接尾辞を自然に評価し、次の値を超える要素がないことを検出します。`1`したがって、すべての候補の重みはゼロになります。 

のような順列`[0,1,2,...,n]`プレフィックスに対して厳密に増加する MEX を生成します。 すべての新しい要素が予測可能な方法で現在の MEX しきい値を超える値の数を増やすため、完全なプレフィックスを含むすべてのサフィックスは重みを最大化します。 

大きな値が繰り返し含まれるが、小さな値が欠落している配列。`[5,5,5,0]`、MEX の非単調な動作を公開します。 前に`0`が含まれており、MEX は`0`そして体重は`0`。 含めた後`0`、MEX は次のようにジャンプします。`1`、そして突然すべて`5`重量に影響します。 最適なサブ配列は劇的にシフトするため、局所的な貪欲な拡張では不十分です。
