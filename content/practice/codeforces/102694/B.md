 ## 解決策
 ## 問題の理解

 問題は以下を含むツリーから始まります。`n`頂点。 新しい孤立した頂点がこのツリーの外側に存在します。 元の頂点ごとに`i`、その新しい頂点をに接続すると想像します。`i`エッジを 1 つ追加して、結果として得られる木の直径がどのくらいになるかを尋ねます。 タスクは、考えられるすべての接続点に対してこの値を出力することです。 入力には元の木のエッジのみが与えられ、出力には次のものが含まれます。`n`考えられる接続ごとに 1 つずつ答えます。 

到達できる頂点の数`300000`したがって、すべての頂点からツリーを探索するアプローチは遅すぎます。 ツリーの 1 回の走査には線形時間がかかり、この規模では許容範囲内ですが、それを繰り返すと`n`所要時間は約`n²`最大のケースでは約 900 億件の訪問が行われます。 ソリューションは次の点に近いものでなければなりません`O(n)`。 

厄介なケースのほとんどは、新しい葉が直径をどのように変化させるかについての誤解に関連しています。 新しい葉がすでにツリーの中央近くにある頂点に取り付けられている場合は、元の直径が答えのままになる可能性があります。 例えば：```
3
1 2
2 3
```元の直径は`2`。 新しい頂点をノードにアタッチする`2`長さのパスを作成します`2`新しい葉から両端まで、つまり答えは`2`。 古い直径に常に 1 を加算する不注意な解決策では、次の出力が出力されます。`3`。 

Another edge case is a single vertex:```
1
```入力にはエッジがありません。 新しい頂点を追加して唯一のノードに接続すると、ツリーには 1 つのエッジで接続された 2 つの頂点が存在するため、答えは次のようになります。`1`。 直径の端点が常に 2 つあると想定しているコードは、ここで失敗する可能性があります。 

最後のケースは、アタッチされた頂点が元の直径の端点である場合です。```
3
1 2
2 3
```新しい頂点をノードにアタッチする`1`パスを与える`new - 1 - 2 - 3`、長さは`3`。 答えは古い直径よりも大きいため、元の直径のみを出力する解決策は不正確です。 

## アプローチ

 直接的な解決策は、考えられるすべてのアタッチメント頂点を試してみることです。 選択した 1 つの頂点に対して`v`からトラバースを実行できます。`v`、その最も遠い頂点を見つけ、古い直径と新しいリーフからその最も遠い頂点までの距離の最大値として新しい直径を計算します。 これが機能するのは、新しい頂点を含むすべての最長パスが新しいエッジから始まり、そこから最も遠い元の頂点まで継続する必要があるためです。`v`。 

問題は、これがほぼ同じ作業を何度も繰り返すことです。 すべての要素からトラバースを実行する`n`頂点コスト`O(n²)`時間。 と`n = 300000`、これは可能性をはるかに超えています。 

重要な観察は、木の直径と最も遠い頂点の間に非常に特殊な関係があるということです。 もし`a`そして`b`任意の直径の 2 つの端点、つまりすべての頂点`v`、から最も遠い頂点`v`常に次のいずれかです`a`または`b`。 これは、すべての頂点から検索する必要がないことを意味します。 必要なのは、これら 2 つの端点までの距離だけです。 

元の直径の長さを次のようにします。`D`。 新しい葉が付く頃`v`の場合、新しいツリーの直径は古い直径か、新しいリーフから始まるパスのいずれかになります。 新しい葉から始まる最長のパスには長さがある`ecc(v) + 1`、 どこ`ecc(v)`からの最大距離です`v`任意の古い頂点に。 なぜなら`ecc(v) = max(dist(v, a), dist(v, b))`、すべての答えは次のようになります。```
max(D, max(dist(v, a), dist(v, b)) + 1)
```全体の問題は、2 つの直径端点と 2 つの距離配列を見つけることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 任意の頂点 (頂点など) からトラバースを開始します。`1`、そこから最も遠い頂点を見つけます。 この頂点を呼び出します`a`。 

ツリー内の任意の開始点から最も遠い頂点は、常に直径の終点になります。 

1. から別のトラバースを開始します。`a`から最も遠い頂点を見つけます`a`。 電話してください`b`。 からの距離`a`に`b`元の直径の長さです`D`。 
2. からツリーを 1 回トラバースします。`a`からの距離を保存します`a`あらゆる頂点に。 

これらの距離は、偏心計算の考えられる 1 つの側面を表します。 

1. からツリーを 1 回横断します。`b`からの距離を保存します`b`あらゆる頂点に。 

これで、すべての頂点が両方の直径の端点までの距離を認識できるようになりました。 

1. 頂点ごとに`v`、次を計算します。```
max(D, max(dist_a[v], dist_b[v]) + 1)
```最初の値は、新しいリーフを使用しない直径を処理します。 2 番目の値は、新しいリーフから始まるパスを処理します。 

なぜ効果があるのか:

 追加の頂点を追加した後に導入される新しいパスは、新しいエッジで始まるパスのみです。 このようなパスの長さは、選択したアタッチメント頂点から元の頂点までの距離に 1 を加えたものになります。 このような最長のパスは、接続点から最も遠い元の頂点を使用します。 ツリーでは、すべての頂点の最も遠い頂点は直径の 2 つの端点の 1 つであるため、保存された 2 つの距離配列には、すべての離心率を計算するために必要な情報が正確に含まれています。 古い直径で最大値を取得すると、考えられる両方のタイプの最長パスがカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get_dist(start, graph):
    n = len(graph) - 1
    dist = [-1] * (n + 1)
    stack = [start]
    dist[start] = 0

    while stack:
        v = stack.pop()
        for u in graph[v]:
            if dist[u] == -1:
                dist[u] = dist[v] + 1
                stack.append(u)

    return dist

def solve():
    n = int(input())
    graph = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        a, b = map(int, input().split())
        graph[a].append(b)
        graph[b].append(a)

    dist0 = get_dist(1, graph)
    a = max(range(1, n + 1), key=lambda x: dist0[x])

    dist_a = get_dist(a, graph)
    b = max(range(1, n + 1), key=lambda x: dist_a[x])

    dist_b = get_dist(b, graph)
    diameter = dist_a[b]

    ans = []
    for i in range(1, n + 1):
        ans.append(str(max(diameter, max(dist_a[i], dist_b[i]) + 1)))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```の`get_dist`関数は反復 DFS を実行します。 明示的なスタックを使用すると、ツリーは次のようなチェーンになるため、Python の再帰の深さの問題が回避されます。`300000`頂点。 

最初のトラバースでは、直径の端点が 1 つ見つかります。 2 番目のトラバーサルでは、もう一方のエンドポイントを検索し、最初のエンドポイントからのすべての距離を取得します。 3 番目のトラバースでは、もう一方のエンドポイントからの距離が得られます。 これら 2 つの配列は、すべての回答に必要な完全な情報です。 

直径の長さは、答えを計算する前に保存されます。 最後のループでは、各頂点について、古い直径を維持するか、新しくアタッチされた頂点を通るより長いパスを作成するかの両方の可能性をチェックします。 

Python では整数は自動的に増加するため、整数オーバーフローの懸念はありません。 回避すべき主な実装の詳細は、誤って再帰を使用することです。これは、パス形状のツリーでデフォルトの再帰制限を超える可能性があります。 

## 実用的な例

 入力の場合:```
3
3 2
2 1
```直径の端点はノードです`1`そして`3`。 

| 頂点 | 1 までの距離 | 3 までの距離 | 元の直径 | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 2 | 2 | 3 |
 | 2 | 1 | 1 | 2 | 2 |
 | 3 | 2 | 0 | 2 | 3 |

 これは、新しいリーフが端点に取り付けられた場合には直径が大きくなるが、中心近くに取り付けられた場合には直径が大きくならないことを示しています。 

入力の場合:```
5
4 2
1 4
5 4
3 4
```木には中心がある`4`葉の間の直径の端点。 

| 頂点 | 終点 A までの距離 | 終点 B までの距離 | 元の直径 | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 2 | 2 | 3 |
 | 2 | 2 | 0 | 2 | 3 |
 | 3 | 1 | 1 | 2 | 3 |
 | 4 | 1 | 1 | 2 | 2 |
 | 5 | 2 | 0 | 2 | 3 |

 中心頂点に新しいリーフを接続しても、既存のリーフ間のパスよりも長いパスは作成されないため、中心頂点は元の直径を維持します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 3 回のツリー トラバースとすべての頂点にわたる 1 回の最終パス |
 | スペース | O(n) | 隣接リストと距離配列は線形情報を格納します。 

このアルゴリズムは、頂点およびエッジごとに一定数の操作のみを実行します。 これは`300000`合計作業量はツリー サイズに比例して増加するため、頂点制限が制限されます。 

## テストケース```python
import sys
import io

def solve_io(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline

    n = int(data())
    graph = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        a, b = map(int, data().split())
        graph[a].append(b)
        graph[b].append(a)

    def dist(start):
        d = [-1] * (n + 1)
        d[start] = 0
        stack = [start]
        while stack:
            v = stack.pop()
            for u in graph[v]:
                if d[u] == -1:
                    d[u] = d[v] + 1
                    stack.append(u)
        return d

    d = dist(1)
    a = max(range(1, n + 1), key=lambda x: d[x])
    da = dist(a)
    b = max(range(1, n + 1), key=lambda x: da[x])
    db = dist(b)
    dia = da[b]

    result = "\n".join(
        str(max(dia, max(da[i], db[i]) + 1))
        for i in range(1, n + 1)
    )

    sys.stdin = old_stdin
    return result

assert solve_io("1\n") == "1", "single vertex"
assert solve_io("3\n3 2\n2 1\n") == "3\n2\n3", "path tree"
assert solve_io("5\n4 2\n1 4\n5 4\n3 4\n") == "3\n3\n3\n2\n3", "sample tree"
assert solve_io("4\n1 2\n2 3\n3 4\n") == "4\n3\n3\n4", "long chain"
assert solve_io("4\n1 2\n1 3\n1 4\n") == "3\n3\n3\n3", "star tree"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1`|`1`| 可能な限り最小のツリーを処理します。 
| 4 つの頂点のチェーン |`4 3 3 4`| 直径の端点をチェックします |
 | 1 つの頂点を中心とする星 |`3 3 3 3`| センターの動作をチェックします |
 | 提供されたサンプル | マッチングサンプル | 式を確認します |

 ## 特殊なケース

 単一の頂点の場合:```
1
```トラバースでは、両方の直径の端点として唯一の頂点が見つかります。 離心率はゼロなので、式は次のようになります。`max(0, 0 + 1)`、生産`1`。 直径エンドポイント ロジックは引き続き機能するため、アルゴリズムは特別な処理を必要としません。 

中間の接続点の場合:```
3
1 2
2 3
```直径は`2`。 頂点の場合`2`、両方のエンドポイントの距離は次のようになります。`1`、そのため、追加されたリーフを通る新しいパスには長さがあります`2`。 最大値が残る`2`これにより、すべての回答が誤って増加することを回避できます。 

エンドポイント接続ポイントの場合:```
3
1 2
2 3
```頂点の場合`1`、最大エンドポイント距離は次のとおりです。`2`。 新しいエッジを追加すると、一定の長さのパスが作成されます`3`、そして数式は戻ります`max(2, 2 + 1) = 3`。 同じ理由が反対側のエンドポイントにも当てはまります。
