 ## 解決策
 ## 問題の理解

 ルートがノードであるルート付きツリーがあります`1`。 各ノードには正の整数の金額が格納されます。 サブツリーによって生成される値は、そのサブツリー内のすべてのノードに格納されている値の積です。 

2 つの操作をオンラインで処理する必要があります。 更新により、1 つのノードの値が置き換えられます。 クエリでは、2 つのサブツリーの値間の比率が求められます。 製品が巨大になる可能性があるため、比率以上`10^9`正確に印刷する必要があります`1000000000`。 

この難しさは、1 つのノードを変更すると、そのノードを含むすべてのサブツリー、つまりその祖先すべてに影響を与えるという事実から生じます。 直接シミュレーションでは、ツリー内を上向きに繰り返し歩くことになるため、速度が遅すぎます。 

制限により許容される範囲`O((n+q) log n)`操作。 まで`3 * 10^5`ノードとクエリ、すべての操作でサブツリー全体またはルートからノードへのパス全体をスキャンするものであれば、おおよその範囲に到達できます。`9 * 10^10`操作が完了しません。 

主なエッジケースは、大規模な製品とツリー構造によって引き起こされます。 単一ノード ツリーが有効です。```
Input
1
1
1 1 1
```可能なサブツリーはルートのみであるため、答えは次のようになります。```
1.0000000000
```通常の乗算​​を使用した不注意な実装では、適度な入力でもオーバーフローが発生しますが、正しい解には対数のみが必要です。 

もう 1 つのケースは、ノードが何度も更新される場合です。```

3
1 2 10
1 2 100

```最終的な比率は、`100`古い値は乗算するのではなく、置き換える必要があるためです。 以前の貢献を削除するのを忘れると、不正確な答えが生成されます。 

3 番目のエッジ ケースは、分母サブツリーが大きい場合です。```

```サブツリーの値`1`は`5`、一方サブツリー`2`は`5`、したがって、答えは次のとおりです`1`。 サブツリーの値はすべての子孫に依存するため、祖先または深さのみを比較するソリューションは失敗します。 

## アプローチ

 簡単なアプローチは、すべてのノード値を維持し、必要に応じてサブツリー積を計算することです。 ノードに対するクエリの場合`x`のサブツリー全体を走査できます。`x`、すべての値を乗算し、繰り返します。`y`。 サブツリー値の定義はまさにその結果であるため、これは正しいです。 

ツリーが大きくなると問題が発生します。 星型のツリーと、`n = 300000`には、ほぼすべてのノードを含む 1 つのサブツリーがあります。 1 つのクエリには数十万の乗算が必要になる可能性があり、これを数十万のクエリに対して実行すると、`9 * 10^10`操作。 

最初の観察は、積を維持するのは難しいが、対数によって積が合計に変換されるということです。$$\log(a \times b)=\log(a)+\log(b)$$サブツリー積を保存する代わりに、各サブツリー内の対数の合計を保存します。 2 つのサブツリー値の比率は、2 つの合計の差になります。 

残りの課題はアップデートです。 If ノード`x`対数差による変化`d`、すべての祖先サブツリーの合計は次のように変化する必要があります。`d`。 これはまさに、ルートから次へのツリー パスの更新です。`x`、ノードに関連付けられた値を求めるクエリが続きます。 

オイラー ツアーは便利な変換を提供します。 ノードに値を保存し、そのオイラー区間にわたる合計をクエリすると、サブツリーの合計が得られます。 差分手法を備えたフェンウィック ツリーを使用すると、ルートからノードへの寄与をオイラー次数の範囲更新として表すことができ、すべての操作を対数時間で実行できるようになります。 

最後の方法では、各ノードの対数寄与を維持し、フェンウィック ツリーでオイラー順序付けを使用してサブツリーの合計を維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合、クエリ/更新ごとに O(n) | O(n) | 遅すぎる |
 | 最適 | 操作ごとに O(log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DFS をルートから実行して計算します。`tin[x]`そして`tout[x]`すべてのノードに対して。 のサブツリー`x`連続したオイラー線分になります`[tin[x], tout[x]]`。 
2. すべてのノードの対数値を保存します。 最初にすべてのノードには以下が含まれます`1`したがって、すべての対数は次のようになります。`0`。 
3. ノード値が変化したとき`old`に`new`、次を計算します。$$\Delta=\log(new)-\log(old)$$これは、このノードを含むすべてのサブツリーが獲得しなければならない量です。 

1.追加`\Delta`をノードのオイラー位置に加算し、サブツリー間隔が終了した後でフェンウィック ツリーを使用して減算します。 これにより、サブツリーのクエリはオイラー区間の合計と等しくなります。 
2. ノードを要求するクエリの場合`x`そして`y`、対数部分木の合計を取得します。`sx`そして`sy`。 望ましい比率は次のとおりです。$$e^{sx-sy}$$結果が到達するほど差が大きい場合`10^9`、すぐにキャップを印刷します。 

機能する理由: フェンウィック ツリーは、更新されたすべてのノードの累積された対数寄与を、それを含むすべてのサブツリーに正確に保存します。 すべてのノードの値はすべての祖先のオイラー区間に正確に寄与するため、サブツリーで維持される合計は常にその真の積の対数に等しくなります。 維持された 2 つの合計の差を取ると、要求された比率の対数が得られ、累乗後の答えが得られます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0.0] * (n + 3)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        res = 0.0
        while i:
            res += self.bit[i]
            i -= i & -i
        return res

    def range_add(self, l, r, v):
        self.add(l, v)
        if r + 1 <= self.n:
            self.add(r + 1, -v)

def solve():
    n = int(input())
    graph = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        a, b = map(int, input().split())
        graph[a].append(b)
        graph[b].append(a)

    tin = [0] * (n + 1)
    tout = [0] * (n + 1)
    order = 0

    sys.setrecursionlimit(1000000)

    def dfs(v, p):
        nonlocal order
        order += 1
        tin[v] = order
        for u in graph[v]:
            if u != p:
                dfs(u, v)
        tout[v] = order

    dfs(1, 0)

    bit = Fenwick(n)
    values = [1] * (n + 1)
    logs = [0.0] * (n + 1)

    q = int(input())
    ans = []

    for _ in range(q):
        t, x, y = map(int, input().split())

        if t == 1:
            delta = math.log(y) - logs[x]
            logs[x] = math.log(y)
            values[x] = y
            bit.range_add(tin[x], tout[x], delta)
        else:
            diff = bit.sum(tout[x]) - bit.sum(tin[x] - 1)
            diff -= bit.sum(tout[y]) - bit.sum(tin[y] - 1)

            if diff >= math.log(1e9):
                ans.append("1000000000")
            else:
                ans.append("{:.10f}".format(math.exp(diff)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```DFS は、各サブツリーに連続した間隔を割り当てます。 フェンウィック ツリーはサブツリーの合計を直接保存しません。 オイラー位置の差分配列を保存するため、サブツリー間隔への寄与の追加は 1 対のポイント更新になります。 

更新操作は継続されます`logs[x]`ノード値の現在の対数として。 新しい対数と古い対数の差は、すべての祖先サブツリーの合計を変更する必要がある量とまったく同じです。 

クエリは、次のプレフィックス合計を取得してサブツリー合計を再構築します。`tout[x]`前のプレフィックスの合計を引いたもの`tin[x]`。 2 つの対数サブツリーの合計を減算すると、要求された比率の対数が得られます。 

呼び出し前にキャップチェックが実行されます`exp`。 実際の製品比率は天文学的に大きくなる可能性があるため、これによりオーバーフローが回避されます。

 ## 特殊なケース

 単一ノード ツリーの場合、DFS は長さ 1 のオイラー区間を作成します。 フェンウィック ツリーには更新がなく、すべてのクエリが同じ単一の値を比較し、`1`。 

更新が繰り返される場合、保存された対数は累積されずに上書きされます。 たとえば、ノードを次から変更します。`4`に`5`追加します`log(5)-log(4)`、 ない`log(5)`。 これにより、維持されるサブツリー値の一貫性が保たれます。 

非常に大きな答えの場合、アルゴリズムはべき乗の前に対数を比較します。 少なくとも差がある場合`log(10^9)`、必要な出力がすでに固定されているため、正確な値は不要です。`1000000000`。
