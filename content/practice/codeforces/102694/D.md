 ## 解決策
 ## 問題の理解

 この問題のグラフは、接続された無向ツリーです。 各エッジには容量値があります。 すべてのクエリについて、特別なルールに基づいて、指定された 2 つの頂点間で送信できるフローの最大量が求められます。つまり、フローのすべての単位が完全なパスを通過し、そのパス上のすべてのエッジの容量が 1 ずつ減少する必要があります。 タスクは、クエリされた 2 つの頂点間でルーティングできるそのようなユニットの可能な最大数を見つけることです。 

入力はツリーのエッジを記述し、次に一連の頂点ペアを記述します。 各ペアの出力は 1 つの整数、つまりこれら 2 つの頂点間の最大可能フローです。 グラフにはサイクルがないため、任意の 2 つの頂点間にはパスが 1 つだけ存在します。 

この制限により、最大 300,000 個の頂点とエッジが許可され、エッジ容量は 10^9 に達します。 すべてのクエリのパス全体を探索するソリューションでは、クエリの数も多くなる可能性があるため、時間がかかりすぎる可能性があります。 クエリごとの線形スキャンは、最悪の場合、約 9 * 10^10 のエッジ チェックに達する可能性があり、これは実用的なレベルをはるかに超えています。 各クエリが対数時間で応答されるように、ソリューションには前処理が必要です。 

主なエッジ ケースは、ツリー構造とフローの定義から得られます。 1 つのエッジを持つパスは、そのエッジの容量を直接返す必要があります。 例えば：```
2 1
1 2 7
2
1 2
2 1
```正しい出力は次のとおりです。```
7
7
```番号の小さい頂点からのみ検索したり、方向が存在すると仮定したりする不用意な実装は、逆クエリで失敗する可能性があります。 

もう 1 つのケースは、最小容量エッジがどちらのエンドポイントにも近くない場合です。 考慮する：```
4 3
1 2 10
2 3 3
3 4 8
1
1 4
```答えは次のとおりです。```
3
```流れは中央のボトルネックエッジによって制限されます。 隣接するエッジのみをチェックするメソッドは、誤って 10 または 8 を返します。 

最後に重要なケースは、非常に大容量であることです。 例えば：```
2 1
1 2 1000000000
1
1 2
```答えは次のとおりです。```
1000000000
```実装では、Python 整数を使用して容量を保存する必要があります。 固定サイズの整数型を使用する言語では、ここで注意する必要があります。 

## アプローチ

 直接的なアプローチは、ある頂点から別の頂点まで歩き、一意のツリー パス上のすべてのエッジを見つけて、それらの間の最小容量を取得することによって各クエリに答えることです。 これは正しいです。フローの単位は、パス上のすべてのエッジから 1 単位の容量を消費するからです。 ユニットの総数は最小容量エッジを超えることはできず、同じパスを繰り返し使用することで常にその多くのユニットを送信できます。 

問題は、木が長い鎖を持つ可能性があることです。 すべてのクエリが 2 つの離れた頂点について質問する場合、各クエリはほぼすべてのエッジを検査する可能性があります。 頂点が 300,000 個あり、クエリが多い場合、最悪の場合、合計作業量は 2 次関数になります。 

重要な点は、グラフがツリーであるため、すべてのパス クエリが、一意のルートからノードへのパスに沿った集計値を要求していることです。 これにより、バイナリ リフティングを使用できるようになります。 前処理中に、すべての頂点および 2 の累乗ごとに、その距離にある祖先と、その祖先へのジャンプ時の最小エッジ キャパシティを保存します。 クエリに答える際に、両方の頂点を上に持ち上げ、保存されている最小値が一致するまで結合します。 

ブルート フォースは、答えが一意のパスのみに依存するため機能しますが、パスを繰り返し再構築するため失敗します。 同じ祖先とパス セグメントが再利用されているという観察により、考えられるすべての上向きの動きを対数のジャンプ数に圧縮することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) 前処理後のクエリごとに O(log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを頂点 1 にルートし、DFS を実行します。 走査中に、すべての頂点の深さ、その直接の親、およびその親に接続するエッジの容量を保存します。 これにより、すべてのパス クエリがルート化されたツリー内の移動問題に変換されます。 
2. バイナリリフティングテーブルを構築します。 すべての頂点とすべてのジャンプ長 2^k について、そのジャンプ後に到達した祖先と、そのジャンプ中に発生した最小エッジ容量を保存します。 最小値を保存する理由は、答えがボトルネック値であるため、2 つのパス セグメントを結合するには最小値を取得するだけで済みます。 
3. 頂点 a と b の間のクエリの場合、まず両方の頂点が同じ深さにあることを確認します。 各ジャンプで見られる最小容量で現在の答えを更新しながら、より深い頂点を 2 の累乗で上に持ち上げます。 
4. 深さを等化した後で頂点が異なる場合は、両方の頂点を一緒に最大ジャンプ サイズからゼロまで持ち上げます。 祖先が異なる場合は常に、そのジャンプを両方の頂点に適用し、保存されている両方の最小値で答えを更新します。 
5. 前のステップの後、両方の頂点は、最下位の共通祖先の直接の子になります。 各頂点からその親までの最終エッジを含め、プロセス中に収集された最小容量を出力します。 

なぜ効果があるのか:

 ツリーでは、すべてのクエリ パスを、最初の頂点から最下位の共通祖先までの上向きセグメントと、2 番目の頂点から同じ祖先までの上向きセグメントに分割できます。 バイナリ リフティングでは、両方のセグメントが 2 つの素の累乗ジャンプに分解されます。 保存されている各ジャンプ値は、まさにそのセグメントの最小容量です。 使用されているすべてのセグメントの最小値を取得すると、パス全体の最小容量が得られ、これがまさに可能な最大フローとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        graph[u].append((v, w))
        graph[v].append((u, w))

    LOG = n.bit_length()

    up = [[0] * (n + 1) for _ in range(LOG)]
    mn = [[10**18] * (n + 1) for _ in range(LOG)]
    depth = [0] * (n + 1)

    stack = [(1, 0, 10**18)]
    order = []
    while stack:
        v, p, w = stack.pop()
        up[0][v] = p
        mn[0][v] = w
        order.append(v)
        for to, weight in graph[v]:
            if to != p:
                depth[to] = depth[v] + 1
                stack.append((to, v, weight))

    for k in range(1, LOG):
        prev = up[k - 1]
        cur = up[k]
        prev_mn = mn[k - 1]
        cur_mn = mn[k]
        for v in range(1, n + 1):
            parent = prev[v]
            cur[v] = prev[parent]
            cur_mn[v] = min(prev_mn[v], prev_mn[parent])

    def query(a, b):
        ans = 10**18

        if depth[a] < depth[b]:
            a, b = b, a

        diff = depth[a] - depth[b]
        bit = 0
        while diff:
            if diff & 1:
                ans = min(ans, mn[bit][a])
                a = up[bit][a]
            diff >>= 1
            bit += 1

        if a == b:
            return ans

        for k in range(LOG - 1, -1, -1):
            if up[k][a] != up[k][b]:
                ans = min(ans, mn[k][a], mn[k][b])
                a = up[k][a]
                b = up[k][b]

        ans = min(ans, mn[0][a], mn[0][b])
        return ans

    q = int(input())
    out = []
    for _ in range(q):
        a, b = map(int, input().split())
        out.append(str(query(a, b)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```DFS セクションは、ツリーのルート表現を作成します。 ツリーには数十万の頂点が含まれる可能性があるため、反復スタックでは Python の再帰の深さの問題が回避されます。 

バイナリ リフティング構造により、前のレベルから各上位レベルが埋められます。 頂点が 2^(k-1) エッジを 2 回ジャンプできる場合、頂点は 2^k エッジをジャンプできます。 大きなジャンプの最小容量は、2 つの小さなジャンプの最小値です。 

2 つの頂点は比較可能なレベルに達した後でのみ、最も低い共通の祖先でしか出会うことができないため、クエリ関数は最初に深さを揃えます。 後で同時に持ち上げることで、誤って解答点を超えてしまうのを防ぎます。 ループの後、両方の頂点が共通の祖先の直下にあるため、最後の親エッジは個別に処理されます。 

Python の整数は、オーバーフローを心配することなく、最大 10^9 の容量を処理します。 すべての実際のエッジ容量が小さいため、初期値 10^18 は無限大として機能します。

import io

def run(inp: str) -> str:

    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().split()
    sys.stdin = old

    if not data:
        return ""

    it = iter(data)
    n = int(next(it))
    m = int(next(it))

    graph = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        w = int(next(it))
        graph[u].append((v, w))
        graph[v].append((u, w))

    LOG = n.bit_length()
    up = [[0] * (n + 1) for _ in range(LOG)]
    mn = [[10**18] * (n + 1) for _ in range(LOG)]
    depth = [0] * (n + 1)

    stack = [(1, 0, 10**18)]
    while stack:
        v, p, w = stack.pop()
        up[0][v] = p
        mn[0][v] = w
        for to, weight in graph[v]:
            if to != p:
                depth[to] = depth[v] + 1
                stack.append((to, v, weight))

    for k in range(1, LOG):
        for v in range(1, n + 1):
            up[k][v] = up[k - 1][up[k - 1][v]]
            mn[k][v] = min(mn[k - 1][v], mn[k - 1][up[k - 1][v]])

    def query(a, b):
        ans = 10**18
        if depth[a] < depth[b]:
            a, b = b, a
        d = depth[a] - depth[b]
        k = 0
        while d:
            if d & 1:
                ans = min(ans, mn[k][a])
                a = up[k][a]
            d >>= 1
            k += 1
        if a == b:
            return ans
        for k in range(LOG - 1, -1, -1):
            if up[k][a] != up[k][b]:

                a = up[k][a]
                b = up[k][b]

    q = int(next(it))
    ans = []
    for _ in range(q):
        ans.append(str(query(int(next(it)), int(next(it)))))
    return "\n".join(ans)
