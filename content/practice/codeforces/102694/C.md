 ## 解決策
 ## 問題の理解

 最大数十万のノードを持つツリーがあります。 ナマケモノはノードから始まります`a`ノードに到達したい`b`。 唯一の制限は、最大でも交差できることです`c`眠りにつく前のエッジ。 からのパスの場合`a`に`b`以下である`c`、ナマケモノが到着します`b`。 それ以外の場合は正確に停止します`c`出発後のエッジ`a`へのユニークな道を進んでいます`b`。 

すべてのクエリに対して、ナマケモノが停止するノードを出力する必要があります。 入力はツリーであり、その後に多数の独立した移動クエリが続きます。 ツリー構造は決して変更されないため、主な課題は、それぞれの動きに迅速に応答できるように十分な前処理を行うことです。 

制限により、最大で許可されます`n = 300000`ノードと`q = 300000`クエリ。 すべてのクエリに対してツリーをたどるソリューションには、次のような時間がかかります。`O(nq)`最悪の場合、可能性をはるかに超えて時間がかかります。 前処理フェーズ後の各クエリは対数時間程度になる必要があります。 木の深さも指定できるので、`O(n)`、より高速な祖先クエリを準備しない限り、単純な親ジャンプだけでは十分ではありません。 

厄介なケースは、移動の方向に起因します。 宛先は、ルート ツリーの開始ノードの上、その下、または別のブランチにある場合があります。 例えば：```
3
1 2
2 3
1
1 3 1
```正しい出力は次のとおりです。```
2
```不用意に実装すると、上方に移動するだけになる可能性があります。`a`パスは下向きに始まるので失敗します。 

もう 1 つのエッジ ケースは、ナマケモノがすでに十分なエネルギーを持っている場合です。```
3
1 2
2 3
1
1 3 5
```正しい出力は次のとおりです。```
3
```常に正確に実行する実装`c`ジャンプは目的地を越えて移動しようとします。 

3 番目のケースは、開始ノードと終了ノードが等しい場合です。```
1
1
1 1 10
```答えは次のとおりです。```
1
```パスの長さはゼロなので、動きは起こりません。 パスに少なくとも 1 つのエッジが含まれることを前提としたソリューションでは、無効なジャンプが発生する可能性があります。 

## アプローチ

 直接的な解決策は、次からパスを再構築することです。`a`に`b`、その後移動します`c`それに沿ったエッジ。 これは正しいです。ツリーにはノードの各ペア間に単純なパスが 1 つだけあるからです。 ただし、クエリごとにツリーを検索してパスを見つけると、多くのノードにアクセスする可能性があります。 鎖状のツリーと`300000`ノードとクエリの数が同じであれば、総作業量はほぼ同じになります。`90000000000`エッジ訪問は遅すぎます。 

重要な点は、実際にはパス全体が必要ないということです。 1 つのエンドポイントから一定の距離にあるノードを見つける必要があるだけです。 これは古典的な木飛び問題です。 

ツリーをルート化し、バイナリ リフティング テーブルを前処理します。 すべてのノードについて、その祖先を離れた場所に保存します`1, 2, 4, 8`、 等々。 これにより、任意の数のエッジだけ上に移動できます。`O(log n)`時間。 

任意のターゲットに向かう動きを処理するために、最も低い共通の祖先を使用します。 させて`l`～のLCAになる`a`そして`b`。 からのパス`a`に`b`は 2 つの部分に分かれています: からのパス`a`まで`l`、およびからのパス`l`まで`b`。 

ナマケモノが移動する必要があるエッジの数が、からの距離よりも少ない場合は、`a`に`l`、答えは単に の祖先です。`a`。 それ以外の場合は、LCA に到達し、その後下降を続けます。`b`。 下向きの動きは、パスの裏側を見ることで上向きの動きに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n)、合計 O(nq) | O(n) | 遅すぎる |
 | バイナリリフティング | 前処理後のクエリごとの O(log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノードでツリーをルート化します`1`そして深さ優先検索を実行します。 すべてのノードとその直接の親の深さを保存します。 これを実行しながら、バイナリリフティングテーブルを構築します。`up[node][j]`の祖先です`node`つまり`2^j`その上のエッジ。 

このテーブルを使用すると、端から端まで歩く代わりに、パスの大部分をスキップできます。 
2. クエリごとに`(a, b, c)`、最も低い共通祖先を見つけます。`l`の`a`そして`b`。 2 つのノード間の距離は次のとおりです。`depth[a] + depth[b] - 2 * depth[l]`。 

この距離が最大であれば`c`、ナマケモノが到着します`b`、したがって、答えは次のとおりです`b`。 
3. ナマケモノが LCA に到達する前に止まった場合、つまり`c <= depth[a] - depth[l]`、ジャンプ`c`から上への先祖`a`。 
4. それ以外の場合は、ナマケモノが最初に LCA に到達します。 残りの距離は次のとおりです。`remaining = c - (depth[a] - depth[l])`。 

パスのターゲット側には長さがあります`depth[b] - depth[l]`。 ノード`remaining`LCA の下のエッジを向かって`b`ノードと同じです`depth[b] - depth[l] - remaining`上のエッジ`b`。 から上にジャンプ`b`その金額で。 

機能する理由: すべてのクエリはツリー内の固有のパスを使用して回答されます。 LCA はこのパスを 2 つのセクションに分割し、1 つは上向きに進みます。`a`もう1つは下向きに向かっています`b`。 バイナリ リフティングでは、選択した数の上向きエッジの後に到達したノードが正確に返されるため、パスを再構築することなく、考えられる両方の移動方向が処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    graph = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        graph[u].append(v)
        graph[v].append(u)

    LOG = (n + 1).bit_length()
    up = [[0] * LOG for _ in range(n + 1)]
    depth = [0] * (n + 1)

    stack = [1]
    parent = [0] * (n + 1)
    parent[1] = 1

    while stack:
        u = stack.pop()
        up[u][0] = parent[u]
        for v in graph[u]:
            if v != parent[u]:
                parent[v] = u
                depth[v] = depth[u] + 1
                stack.append(v)

    for j in range(1, LOG):
        for i in range(1, n + 1):
            up[i][j] = up[up[i][j - 1]][j - 1]

    def jump(u, k):
        bit = 0
        while k:
            if k & 1:
                u = up[u][bit]
            k >>= 1
            bit += 1
        return u

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a

        a = jump(a, depth[a] - depth[b])

        if a == b:
            return a

        for j in range(LOG - 1, -1, -1):
            if up[a][j] != up[b][j]:
                a = up[a][j]
                b = up[b][j]

        return up[a][0]

    q = int(input())
    ans = []

    for _ in range(q):
        a, b, c = map(int, input().split())

        l = lca(a, b)
        dist = depth[a] + depth[b] - 2 * depth[l]

        if c >= dist:
            ans.append(str(b))
            continue

        up_from_a = depth[a] - depth[l]

        if c <= up_from_a:
            ans.append(str(jump(a, c)))
        else:
            remaining = c - up_from_a
            down_from_l = depth[b] - depth[l]
            ans.append(str(jump(b, down_from_l - remaining)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```前処理セクションでは、ルート付きツリー情報を一度構築します。 反復 DFS は、再帰 DFS が Python の再帰制限を超える可能性がある、チェーン形状のツリーでの再帰の深さの問題を回避します。 

の`jump`関数は、コアのバイナリ リフティング操作です。 それはビットを読み取ります`k`そして、祖先テーブルから対応する 2 のべき乗を適用します。 すべてのジャンプは同じパス上を上に移動するため、これらのジャンプの順序は重要ではありません。 

の`lca`関数は最初に 2 つのノードの深さを揃えます。 その後、親が一致するまで、両方のノードを 2 の大きなべき乗から小さなノードまで一緒に引き上げます。 返された親は、最下位の共通祖先です。 

クエリ ロジックは 4 つのアルゴリズム ステップに正確に従います。 唯一デリケートな部分はパスの後半です。 LCA に到達した後も移動が続く場合、直接下にジャンプすることは不可能であるため、コードは視点を反転し、LCA から上にジャンプします。`b`。 

Python の整数はすべての距離を安全に処理しますが、主な関心事はクエリ内での不必要な作業を回避することです。 すべてのクエリは、一定数のバイナリ リフティング操作のみを実行します。
