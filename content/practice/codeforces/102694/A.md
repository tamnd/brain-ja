 ## 解決策
 ## 問題の理解

 ツリーは、直径が 2 つのノード間の最長パスである幾何学オブジェクトのように扱われます。 この問題では、円周の珍しいバージョンが定義されています。円周率の実際の値の代わりに、円周率 = 3 を使用します。通常、円周率は直径に円周率を掛けたものであるため、必要な答えは木の直径の 3 倍になります。 入力は無向ツリーを次のように記述します。`n`頂点と`n - 1`エッジであり、出力はこの変更された定義に基づく円周値です。 

主なタスクは、ジオメトリをシミュレートすることではありません。 ツリー内の 2 つの頂点間の最長距離を見つけることです。 この制約により、最大で次のことが許可されます。`3 * 10^5`したがって、ツリーを一定回数探索するアルゴリズムが必要です。 すべての頂点のペアを試すアプローチでは、約`n^2 / 2`ペア、それは周りになります`4.5 * 10^10`最大の入力をチェックしますが、1 秒の制限でサポートできる入力をはるかに超えています。 

エッジケースはツリーの構造から生じます。 単一の頂点にはエッジがないため、その直径はゼロであり、答えもゼロでなければなりません。 例えば：```
Input:
1

Output:
0
```常に少なくとも 1 つのエッジが存在すると仮定する不用意な実装は、隣接リストの構築中、または存在しない隣接ノードからの検索の実行中に失敗する可能性があります。 

2 つの頂点を持つ木の直径は 2 ではなく 1 です。 例えば：```
Input:
2
1 2

Output:
3
```最長のパスには 1 つのエッジが含まれるため、円周は次のようになります。`1 * 3`。 よくある間違いは、エッジではなく頂点を数えて、`6`。 

星型のツリーも便利な例です。 例えば：```
Input:
5
1 2
1 3
1 4
1 5

Output:
6
```最長のパスは、1 つのリーフから中心を通って別のリーフに進み、2 つのエッジを含みます。 任意の 1 つのルートから最も深い子だけをチェックする実装では、2 つではなく 1 つが誤って返される可能性があります。 

## アプローチ

 直接的な解決策では、頂点の各ペア間の距離が計算され、最大値が維持されます。 開始頂点ごとに DFS または BFS を実行して、他のすべての頂点までの距離を見つけることができます。 直径はすべてのペア間の最大距離に正確に一致するため、これは正しいです。 ただし、これをすべての頂点から実行するとコストがかかります`O(n^2)`時間。 と`n = 300000`、これには数百億の操作が必要になります。 

ツリーの便利な特性は、2 回のトラバースのみを使用して直径を見つけることができることです。 任意の開始頂点を選択し、そこから最も遠い頂点を見つけます。 その頂点は、直径の 1 つの端点であることが保証されます。 次に、そのエンドポイントから別のトラバースを開始します。 2 回目の横断で見つかった最遠距離は直径の長さです。 

これが機能する理由は、木々の小道の形状にあります。 頂点の各ペアには、それらの間のパスが 1 つだけ存在します。 任意の点から開始した場合、できるだけ遠くに移動すると、ツリーの最端に向かって進みます。 その端からの 2 番目の検索は反対の端に到達し、可能な限り長いパスが得られます。 

エッジの数で直径を見つけた後、最終的な答えは単純です。`diameter * 3`なぜなら、この問題では pi が 3 と定義されているからです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーの隣接リストを作成します。 各エッジは 2 つの頂点を接続します。ツリーには方向がないため、両方の方向を保存する必要があります。 
2. 頂点などの任意の頂点から DFS または BFS を実行します。`1`、その頂点からの距離を記録します。 最大距離の頂点を見つけます。 

最初の走査は特別な頂点から開始する必要はありません。 見つかった最も遠い頂点は、実際の直径の検索を開始するのに十分です。 

1. 前の手順で見つかった頂点から 2 番目の DFS または BFS を実行します。 再度距離を記録し、到達した最大距離を取得します。 

この最大距離は、エッジで測定された木の直径です。 

1. 直径に次の値を掛けます。`3`そして結果を印刷します。 

このアルゴリズムが正しい理由は、ツリーには頂点の各ペア間に一意のパスがあるためです。 最初のトラバースは、最長パスの片側のリーフに到達します。 その終点から開始して、2 番目のトラバースは最長パスの反対側の終点に到達する必要があるため、求められる最大距離は正確に直径になります。 すべての有効な直径パスがこのエンドポイントを通過すると考慮されているため、これより大きな距離は存在できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def farthest(start, graph):
    stack = [(start, -1, 0)]
    best_node = start
    best_dist = 0

    while stack:
        node, parent, dist = stack.pop()

        if dist > best_dist:
            best_dist = dist
            best_node = node

        for nxt in graph[node]:
            if nxt != parent:
                stack.append((nxt, node, dist + 1))

    return best_node, best_dist

def solve():
    n = int(input())

    graph = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        a, b = map(int, input().split())
        graph[a].append(b)
        graph[b].append(a)

    if n == 1:
        print(0)
        return

    endpoint, _ = farthest(1, graph)
    _, diameter = farthest(endpoint, graph)

    print(diameter * 3)

if __name__ == "__main__":
    solve()
```隣接リストにはツリーが格納されます。`O(n)`すべてのエッジを訪問する必要があるため、メモリが必要になります。 ヘルパー関数`farthest`反復 DFS を実行します。 明示的なスタックを使用すると、長さのチェーンになる可能性があるツリーでの Python 再帰の深さの問題を回避できます。`300000`。 

最初の電話は`farthest`直径検索の適切な開始終点を特定するだけです。 返された距離は必ずしも最終的な直径ではないため、無視されます。 2 番目の呼び出しはそのエンドポイントから開始され、返される距離は実際の直径です。 

乗算は直径が見つかった後に実行されます。 直径はエッジをカウントするため、パスは次のようになります。`k`エッジには円周がある`3k`。 Python では整数は自動的に増加するため、整数オーバーフローの心配はありません。

## テストケース```python
import sys
import io

def solve(data):
    sys.stdin = io.StringIO(data)
    input = sys.stdin.readline

    n = int(input())
    graph = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        a, b = map(int, input().split())
        graph[a].append(b)
        graph[b].append(a)

    def farthest(start):
        stack = [(start, -1, 0)]
        node = start
        dist = 0

        while stack:
            cur, parent, d = stack.pop()
            if d > dist:
                node = cur
                dist = d
            for nxt in graph[cur]:
                if nxt != parent:
                    stack.append((nxt, cur, d + 1))
        return node, dist

    if n == 1:
        return "0"

    a, _ = farthest(1)
    _, d = farthest(a)
    return str(d * 3)

 ## 特殊なケース

 頂点が 1 つのツリーの場合:```
Input:
1
```アルゴリズムはトラバーサルをスキップし、直接ゼロを返します。 この条件がないと、2 番目のエンドポイントが存在すると想定するコードが無効なデータにアクセスする可能性があります。 

2 頂点ツリーの場合:```
Input:
2
1 2
```最初のトラバースでは、距離 1 にある他の頂点を見つけます。 2 番目の走査でも最大距離 1 が見つかるため、答えは次のようになります。`1 * 3 = 3`。 これにより、距離がエッジによって測定されることが確認されます。 

スターツリーの場合:```
Input:
5
1 2
1 3
1 4
1 5
```頂点から始める`1`、最も遠いノードは距離 1 の葉です。 これらのリーフの 1 つから開始して、2 番目のトラバースは距離 2 にある別のリーフに到達します。 このアルゴリズムは、直接の子だけを考慮するのではなく、中心を通るパスを正しく見つけます。
