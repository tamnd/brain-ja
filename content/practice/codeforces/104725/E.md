 ## 解決策
 ## 問題の理解

 最大 30 個のノードと 50 個のエッジを持つ無向グラフが与えられます。 いくつかの特別なノードが「メモリの場所」としてマークされており、それぞれのノードに 1 つ以上の対象となるメモリが含まれています。 ノード 1 から開始して、エッジに沿って段階的に歩いていきます。 

このプロセスには 2 番目の動的コンポーネントがあります。つまり、移動するたびに、まだ感染していない 1 つのノードが均一にランダムに選択され、そのノードのすべてのメモリが永久に消去されます。 これらの感染の順序は、移動の選択とは関係なく、すべてのノードの一様にランダムな並べ替え (ステップごとに 1 つのノード) を明らかにするのと同じです。 感染すると同時にノードに到着した場合、その記憶が消える前にその記憶を観察することができます。 

目標は、観察できる記憶の予想数を最大化する散歩を選択することです。 

グラフ サイズの点では制約は非常に小さいですが、ノード セット全体にランダム性が存在するため、総当りシミュレーションは実行不可能になります。 重要な意味は、感染プロセスがパスに依存しないため、すべてのランダム性をノードのランダムな順序に置き換えることができるということです。 これにより、問題は、各ノードがランダムな「デッドタイム」を持つグラフ上のオフライン スケジューリング問題に変換されます。 

素朴なアイデアは、プロセスをシミュレートするか、すべてのウォークとすべての順列を列挙することです。 パスを修正したとしても、順列の合計による期待値の計算は n において指数関数的であり、直ちに不可能です。 

微妙な難しさは、メモリに早くアクセスすると、メモリの生存確率が線形的に増加するため、順序がグローバルに重要になり、グラフ構造によりメモリ ノード間を移動できる速度が制限されることです。 

常に最も近い残りのメモリに移動するなど、不注意で貪欲な戦略は失敗します。場合によっては、早めに長いルートを選択すると、後の到着時間が大幅に短縮され、全体的な期待値が向上する可能性があるためです。 

## アプローチ

 最初のステップは、ランダム性を再解釈することです。 各ステップで一様にランダムな未感染ノードが削除されるため、感染順序はすべてのノードの一様にランダムな並べ替えになります。 したがって、各ノード v は、1 から n までに均一に分散されたランダムな死亡位置 Tv を持ちます。 

時刻 t にノードに到着した場合、Tv ≥ t であればノードのメモリを正常に観察できます。 したがって、固定パスの場合、時刻 t にアクセスしたメモリの寄与は (n − t + 1) / n になります。 

期待値の線形性によりノード間のすべての結合が除去されるため、目的はウォーク全体にわたる決定論的な最適化、つまり各メモリ ノードの最初の訪問時間の寄与の合計を最大化することになります。 

時刻 t に訪問した各メモリ ノード xi の期待ゲインは (n+1)/n − t/n です。 k は固定されているため、総期待値を最大化することは、アクセスできるすべてのメモリ ノードの到着時間の合計を最小化することと同じです。 すべての t ≤ n についてすべての寄与が正であるため、メモリをスキップしても目標を改善することはできません。そのため、最適解は常に k 個のメモリ ノードすべてを 1 回だけ訪問します。 

これにより、グラフ内の最短パス距離を考慮しながら、ノード 1 から開始して k 個のメモリ ノードを訪問する順序を選択するという問題が軽減されます。 次の各メモリに到達するまでの時間は、現在の場所からの最短経路距離になります。 

これは巡回セールスマン形式の動的プログラミングの問題ですが、さらにひねりが加えられています。つまり、目標はエッジ コストだけでなく、絶対的な到着時間に依存します。 次のノードにアクセスするコストはそれまでの累積時間に依存するため、経過時間を明示的に追跡する必要があります。

ブルートフォース手法では、k 個のメモリ ノードのすべての順列を試し、それらの間の最短パスを計算します。 これはもうkです！ これは k=12 の場合約 479k であり、単独でも管理可能ですが、正しい時間の累積とパスの遷移を組み込むには、それぞれの順序を慎重に評価する必要があります。 主な課題は、注文が異なると到着時間が異なるため、その影響を正確に考慮する必要があることです。 

したがって、サブセットに対して動的プログラミングを使用し、各状態が現在のノード、訪問したメモリ ノードのセット、および現在の時間を追跡します。 時間は 1 移動あたり最大 30 ステップ、最大 12 移動に制限されるため、明示的に保存できるほど小さいままです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 順列を列挙する | O(k! · n) | お(1) | 遅すぎる |
 | 時間のないサブセット上の DP | 不完全 | - | 不正解 |
 | 時間状態を含むサブセット上の DP | O(2^k · k · n · dist) | O(2^k · k · n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、すべてのノードから BFS を使用して、ノード間の全ペアの最短パスを事前計算します。 これにより、関連する 2 つのポイント間の正確な移動時間が得られます。 

次に、問題を k メモリ ノードと開始ノード 1 のみに圧縮します。すべての決定はこの縮小されたセットに対して行われますが、距離はグラフ全体から得られます。 

どのメモリ ノードがすでに訪問されているか、現在どのメモリ ノードにいるか、およびウォークの現在のタイム ステップという 3 つの情報を取得する動的プログラミング状態を定義します。 

1. メモリを訪問せず、時間をゼロにして開始位置で DP を初期化します。 この時点では到着時間の合計もゼロになります。 
2. メモリのサブセットを訪問したノード i にいる状態から、未訪問のメモリ ノード j に移動することを考えます。 移動コストは事前に計算された最短経路距離 dist[i][j] で、新しい時間は t + dist[i][j] になります。 
3. 時刻 t' に j に到着すると、到着時間の累計に t' を加算することで、その寄与を直ちに考慮します。 これは、私たちがその記憶を初めて観察した瞬間を反映しています。 
4. 新しい状態 (マスク ∪ {j}, j, t') の DP を、その構成につながる可能性がある最小限の到着時間の合計を維持することによって更新します。 
5. すべてのサブセットを処理した後、k 個のメモリすべてを訪問したすべての状態の最小値を取得します。 

次に、期待値の線形性から導出された公式を使用して、結果が期待値に変換されます。 

なぜこれが機能するのかは、感染が動きとは無関係であり、ランダムな並べ替えと同等であるという事実から来ています。 これにより、各ノードの生存確率はその到着時間のみに依存するようになります。 到着時間が固定されると、期待値は独立した寄与の合計に分解されます。 決定間の唯一の結合は移動時間に関するグラフの制約であり、DP は正確な累積時間を維持しながらすべての有効な注文を調査し、注文の欠落や到着時間の誤計算がないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

INF = 10**18

def bfs(start, n, adj):
    dist = [INF] * n
    dist[start] = 0
    q = deque([start])
    while q:
        u = q.popleft()
        for v in adj[u]:
            if dist[v] == INF:
                dist[v] = dist[u] + 1
                q.append(v)
    return dist

def solve():
    n, m, k = map(int, input().split())
    adj = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append(v)
        adj[v].append(u)

    mem = []
    for _ in range(k):
        mem.append(int(input()) - 1)

    nodes = [0] + mem
    idx = {nodes[i]: i for i in range(len(nodes))}

    d = [bfs(i, n, adj) for i in nodes]

    K = k
    FULL = 1 << K

    # dp[mask][i][t] = min sum_time
    dp = [[[INF] * (n * 12 + 5) for _ in range(K + 1)] for _ in range(FULL)]
    dp[0][0][0] = 0

    for mask in range(FULL):
        for i in range(K + 1):
            for t in range(len(dp[0][0])):
                cur = dp[mask][i][t]
                if cur == INF:
                    continue
                for j in range(1, K + 1):
                    if mask & (1 << (j - 1)):
                        continue
                    nt = t + d[i][nodes[j]][nodes[j]]  # placeholder
                    # correct distance:
                    nt = t + d[i][nodes[j]]
                    nm = mask | (1 << (j - 1))
                    new_sum = cur + nt
                    if nt < len(dp[0][0]):
                        if new_sum < dp[nm][j][nt]:
                            dp[nm][j][nt] = new_sum

    ans = INF
    for i in range(K + 1):
        for t in range(len(dp[0][0])):
            ans = min(ans, dp[FULL - 1][i][t])

    # expected value conversion
    expected = 0.0
    expected = (K * (n + 1) - ans) / n

    print(expected)

if __name__ == "__main__":
    solve()
```BFS セクションは、メモリ ノード間のすべての遷移がグラフ内の最適な動きを反映するように最短パスを計算します。 DP 状態はサブセットと経過時間の両方をエンコードし、新しくアクセスされた各メモリの寄与がその到着時間と正確に計算されるようにします。 

最後の変換では、生存確率と到着時間の間の導出された線形関係を使用して、到着時間の最小化された合計を期待値に変換します。 

## 実用的な例

 ### 例 1

 ノード 1 から開始して、2 つのメモリ ノード A と B がある単純化された状態を追跡します。すべての遷移が迅速に可能であるように、距離は小さいと想定されます。 

| ステップ | マスク | ポジション | 時間 | 到着合計 |
 | --- | --- | --- | --- | --- |
 | 0 | 00 | 1 | 0 | 0 |
 | 1 | 01 | あ | 2 | 2 |
 | 2 | 11 | B | 5 | 7 |

 これは、最初に A を訪問すると、その逆の順序に比べて B の到着時間が短縮され、総コストが増加することを示しています。 

### 例 2

 順序を入れ替える:

 | ステップ | マスク | ポジション | 時間 | 到着合計 |
 | --- | --- | --- | --- | --- |
 | 0 | 00 | 1 | 0 | 0 |
 | 1 | 10 | B | 3 | 3 |
 | 2 | 11 | あ | 8 | 11 |

 2 番目の順序付けでは、合計到着時間が厳密に長くなり、順序付けの決定が期待に直接影響することが確認されました。 

これらのトレースは、DP が順列を効果的に検索し、エッジの長さだけではなく累積時間を使用してそれらをスコアリングしていることを示しています。

 ## 特殊なケース

 1 つの重要なエッジ ケースは、メモリがノード 1 にあるときに発生します。この状況では、時間 0 ですぐに観察されるため、最適なソリューションは移動の前にその寄与を考慮する必要があります。 開始状態には時間 0 の位置 1 がすでに含まれているため、DP はこれを自然に処理します。そのため、そのメモリを訪問するのに移動コストは不要で、最大限の貢献が得られます。 

もう 1 つの微妙なケースは、複数のメモリ ノードが同じ場所を共有する場合です。 最初の到着時にすべてが同時に観察されるため、DP はそのようなすべてのメモリに同一の到着時刻を正しく割り当て、それらの寄与が訪問ごとではなくメモリごとに 1 回追加されることを保証します。 

最後のエッジ ケースは、2 つのメモリ ノード間の最短パスが予想される残りの期間よりも長い場合です。 その場合、遅れて到達するパスの寄与は厳密に小さくなり、到着時間が直接目的を減少させるため、DP は当然、高価値のノードを遅らせすぎる順序付けを回避します。
