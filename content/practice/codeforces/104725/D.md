 ## 解決策
 ## 問題の理解

 グリッドは、通過可能なセル内で 4 方向のみの移動が許可される都市地図を表します。 一部のセルはブロックされており、一部のセルはボーナスを提供し、他のすべてのセルは中立です。 まさにあります$k$スタートポジションと$k$終了位置。 有効な配送ルートは、任意の開始点から始まり、隣接する通行可能なセルまで段階的に歩き、最終的には終了セルで終了します。 すべてのセルは、異なるルートを含むすべてのルートにわたって最大 1 回使用できます。 

各ルートの基本スコアは 100 です。訪問したセルごとにスコアから 1 が減算されますが、セルにボーナスが含まれている場合は、代わりに 1 が加算されます。 合計スコアはすべてのルートの合計であり、目標は、合計スコアが最大になるように、任意の数のルートを選択し、開始点から終了点までを効果的にペアにし、連続しないパスを選択することです。 

制約は、グリッド上のグラフ アルゴリズムには十分小さいです。$n, m \le 30$最大で 900 個のセルが得られ、$k \le 10$パスの数を制限します。 この組み合わせは、ペアリングやパスを直接対象とした組み合わせ検索ではなく、容量制約のあるグラフを対象としたフローまたは状態空間の検索を強く示唆しています。$k=10$パスの選択のせいで。 

2 つのルートが高値セルまたはショートカット コリドーを共有したい場合、微妙な失敗例が発生します。 任意の開始点と終了点のペア間の最短パスの割り当てを貪欲に行うと、より優れたグローバル構成が簡単に妨げられる可能性があります。 

たとえば、単一のセルを通過すると +1 ボーナスが得られるが、それを使用すると、少し長いパスを通らなければならない別のルートがブロックされるセルの狭い廊下を考えてみましょう。 貪欲な方法では、コリドーが構築する最初のパスにコリドーを割り当て、2 番目のパスが多くのニュートラル セルを迂回し、利益以上の損失が発生する可能性があります。 

もう 1 つの失敗例は、ペアリングの曖昧さによって発生します。 開始点が固定された終了点に一致しないため、ローカルで間違ったペアを選択すると、長い迂回が余儀なくされる可能性があります。 任意のマッチングごとに最短パスを計算する単純なアプローチでは、パスの相互作用が個々の最短距離よりも重要であることが無視されます。 

主要な問題は、パスが頂点に共通でない必要があり、同時に 2 組の端末間で最適なペアリングを選択する必要があることです。 

## アプローチ

 強引なアイデアは、開始点と終了点がどのように一致するかを列挙し、一致するそれぞれについて、頂点が分離されたパスの最適なセットを計算することです。 マッチングを修正したとしても、グリッド上で複数の互いに素な最適なパスを見つけることは、すでに困難なフローの問題です。 すべてを列挙する$k!$マッチングはすでに不可能です$k=10$、そして各マッチングの内部では依然として複雑な最短非結合パスの計算が必要であり、直接実行した場合は最悪の場合指数関数的になる可能性があります。 

重要な構造的観察は、グリッドをフロー ネットワークに変えることができるということです。 各セルは最大 1 回しか使用できません。これはまさに頂点容量の制約になります。 各パスはローカル セルの寄与の合計に寄与し、障害物や容量を除けばセル間の移動は制限されません。 これは最小コストのフローの古典的な設定であり、フローの各単位が 1 つの配送ルートに対応します。 

開始と終了の間のペアリングを事前に固定する必要はありません。 スーパー ソースをすべての始点に接続し、スーパー シンクをすべての終点に接続すると、送信$k$フローの各単位は独自の宛先を選択するため、どの開始が使用されるか、およびそれらがどのように終了とペアになるかを自動的に決定します。 

残る唯一の問題は、各グリッド セルを最大 1 回使用することを強制することです。 これは、各セルを容量 1 の「入力」ノードと「出力」ノードに分割することで処理され、セルを通過するとその容量が 1 回だけ消費されます。 

変換すると、問題は正確に送信することになります。$k$最小コスト フローの単位。コストはルート スコアのマイナスをエンコードします。

 ## アルゴリズムのチュートリアル

 1. 各グリッド セルを 2 つのノードに変換し、1 つは入口を表し、もう 1 つは出口を表し、それらを容量 1 の有向エッジで接続します。これにより、各セルはすべてのパスにわたって最大 1 回使用できるようになります。 
2. セルを使用するペナルティと等しいコストを内部エッジに割り当てます。 ニュートラル セルはスコアに -1 を与えますが、ボーナス セルは 0 を与えます。そのため、最小コストの定式化ではニュートラル セルにはコスト 1、ボーナス セルには 0 を使用します。 
3. 非障害物セルの隣接するすべてのペアについて、一方の出口ノードを、容量 1、コスト 0 でもう一方の入口ノードに接続します。これにより、追加のスコアリングなしで移動がモデル化されます。 
4. スーパー ソースを作成し、容量 1、コスト 0 で各開始セルのエントリ ノードに接続します。 
5. 各エンドセルの出口ノードを容量 1、コスト 0 のスーパーシンクに接続します。 
6. 正確に送信する最小コストのフローを実行する$k$スーパーソースからスーパーシンクまでのユニット。 各ユニットは、開始点から終了点までの 1 つの完全なルートに対応します。 
7. 最終的な答えは次のとおりです。$100k$コストはセル寄与のマイナスとして定義されているため、フローによって返される総コストを差し引いたものです。 

この正しさは、頂点に分離されたパスの実行可能なすべての集合が等しい値のフローに正確に対応し、フローのすべての単位が開始から終了まで 1 つの有効なパスをエンコードしているという事実から得られます。 ノード分割により、異なるフロー単位間でセルが再利用されないことが保証され、これは素性制約と一致します。 コスト加法性により、フロー コストがすべてのルートに沿ったセルごとの寄与の正確な合計になることが保証されるため、コストを最小化することは合計スコアを最大化することと同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from heapq import heappush, heappop

class MinCostMaxFlow:
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(n)]

    def add_edge(self, u, v, cap, cost):
        self.adj[u].append([v, cap, cost, len(self.adj[v])])
        self.adj[v].append([u, 0, -cost, len(self.adj[u]) - 1])

    def flow(self, s, t, maxf):
        n = self.n
        res = 0
        INF = 10**18
        h = [0] * n

        while maxf:
            dist = [INF] * n
            prevv = [-1] * n
            preve = [-1] * n
            dist[s] = 0
            pq = [(0, s)]

            while pq:
                d, v = heappop(pq)
                if dist[v] < d:
                    continue
                for i, e in enumerate(self.adj[v]):
                    to, cap, cost, rev = e
                    if cap > 0 and dist[to] > dist[v] + cost + h[v] - h[to]:
                        dist[to] = dist[v] + cost + h[v] - h[to]
                        prevv[to] = v
                        preve[to] = i
                        heappush(pq, (dist[to], to))

            if dist[t] == INF:
                break

            for i in range(n):
                if dist[i] < INF:
                    h[i] += dist[i]

            d = maxf
            v = t
            while v != s:
                d = min(d, self.adj[prevv[v]][preve[v]][1])
                v = prevv[v]

            maxf -= d
            res += d * h[t]

            v = t
            while v != s:
                e = self.adj[prevv[v]][preve[v]]
                e[1] -= d
                self.adj[v][e[3]][1] += d
                v = prevv[v]

        return res

n, m, k = map(int, input().split())
grid = [list(map(int, input().split())) for _ in range(n)]

def id(i, j):
    return i * m + j

V = n * m * 2 + 2
S = V - 2
T = V - 1
mcmf = MinCostMaxFlow(V)

INF = 10**9

for i in range(n):
    for j in range(m):
        if grid[i][j] == -1:
            continue
        u = id(i, j)
        in_node = u
        out_node = u + n * m

        cost = 1 if grid[i][j] == 0 else 0
        mcmf.add_edge(in_node, out_node, 1, cost)

        for di, dj in [(1,0),(-1,0),(0,1),(0,-1)]:
            ni, nj = i + di, j + dj
            if 0 <= ni < n and 0 <= nj < m and grid[ni][nj] != -1:
                v = id(ni, nj)
                mcmf.add_edge(out_node, v, 1, 0)

starts = []
for _ in range(k):
    x, y = map(int, input().split())
    starts.append((x-1, y-1))

ends = []
for _ in range(k):
    x, y = map(int, input().split())
    ends.append((x-1, y-1))

for x, y in starts:
    u = id(x, y)
    mcmf.add_edge(S, u, 1, 0)

for x, y in ends:
    u = id(x, y)
    mcmf.add_edge(u + n * m, T, 1, 0)

cost = mcmf.flow(S, T, k)
print(100 * k - cost)
```グリッドはフロー ネットワークに拡張され、各セルが入口ノードと出口ノードに分割されます。 内部エッジは使い捨ての制約を強制しますが、隣接エッジはコストをかけずに移動できます。 min-cost フロー ルーチンは、ポテンシャルを使用して最短の拡張パスを効率的に処理し、すべてのフローが完了するまで 1 つのフロー単位を繰り返し送信します。$k$パスが形成されているか、それ以上の有効なルーティングが存在しません。 

よくある実装の落とし穴は、コストが移動エッジではなくノードに属することを忘れていることです。 コストがノード使用量ではなくグリッド遷移に配置されている場合、セルに出入りするときにパスが誤ってペナルティを蓄積したり重複したりする可能性があります。 

## 実用的な例

 ### 例 1 (小さなグリッドを構築)

 1 つの開始点が (1,1)、もう 1 つの終了点が (2,2) で、すべてのセルが中立である 2×2 グリッドを考えてみましょう。 

唯一の有効なパスは 2 つの中間状態を強制的に通過し、フローは次のように動作します。 

| ステップ | 拡張パス | これまでの費用 |
 | --- | --- | --- |
 | 1 | 開始 → (1,1) → (1,2) → (2,2) | 2 |
 | 2 | 送信フロー | 2 |

 代替ルーティングが存在しないため、アルゴリズムはこの一意のパスを選択します。 コストは、使用されるニュートラル セルの数に正確に対応します。 

これにより、ノード分割によってエッジ トラバーサルごとではなくセルごとの使用量が正しく課金されることが確認されます。 

### 例 2 (構築されたトレードオフ グリッド)

 ここで、中央のセルがボーナス セルであり、2 つの独立したルートがそれをめぐって競合する 3×3 グリッドを考えてみましょう。 1つのルートは少し長くなりますが、ボーナスセルを通過できます。 

| ステップ | ルート1の決定 | ルート2決定 | 総コスト |
 | --- | --- | --- | --- |
 | 1 | ボーナスセンターを取る | 迂回 | 下 |
 | 2 | フローロックセンターの使用法 | 残りのパスを調整 | 最適 |

 キャパシティー 1 は独占性を強制するため、フローは最大のグローバル利益を生み出すルートにボーナス セルを割り当てることを選択します。 

これは、ローカルの貪欲な割り当てが失敗する一方、グローバル フローによって共有された高価値セルの競合が自然に解決されることを示しています。

 ## 特殊なケース

 ボーナス セルが複数の最適なルート間のジャンクションにある場合、重大なエッジ ケースが発生します。 容量の制約がないと、複数のパスが誤って通過し、スコアが人為的に増大します。 ノード分割構造では、単一のトラバースを強制することでこれを防ぎます。 

別のエッジ ケースは、開始点が終了点に隣接しており、単一の最適な出口パスの近くに複数の開始点が集まっている場合に発生します。 貪欲な割り当てでは複数のフローが同じコリドーに送信される可能性がありますが、内部ノードのユニット容量によってこれがブロックされ、代替ノードが再ルーティングを開始するか、合計ゲインが低下する場合は未使用のままになります。 

最後のエッジ ケースは、すべての有益なパスの実効コストが 100 を超える場合です。 その状況では、フローを送信すると、パスごとの合計スコアがゼロゲインを下回る可能性があります。 フローの定式化では、フローの単位の送信には常にコストが発生し、アルゴリズムは目的を改善する場合にのみフローを送信するため、役に立たない場合は特定の開始を使用しないことが当然許可されます。
