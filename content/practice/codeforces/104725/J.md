 ## 解決策
 ## 問題の理解

 1 から m までの整数の位置で表される 1 次元のレース トラックが与えられます。 特別な「パーフェクト ゾーン」はサフィックス間隔 [R, m] であり、最終的な目標は、特定のスキルがこのパーフェクト ゾーン内で正常にトリガーされる k 番目のスキルである可能性を最大化することです。 

各スキル i は間隔 [li, ri] によって定義されます。 トリガーすると、その間隔から一様にランダムに位置を選択します。 ただし、スキルを習得しても、それがレースで発動するとは限りません。 代わりに、各スキルは個別に P/100 の確率で発動します。 

単一のレースでは、概念的には入力順序に従ってトリガーされるスキルのシーケンスを生成します。 一部のスキルは完全にトリガーに失敗し、他のスキルは 1 回トリガーしてランダムな位置を生成します。 全発動スキルのうち、出現順に着目し、k番目の発動スキルに注目します。 要件は、k 番目にトリガーされたスキルが [R, m] 内に到達する確率が最大化されるように、どのスキルのサブセットを学習するかを選択することです。 

主要な出力は、各クエリ k について、学習されたスキルの最適な選択の下で達成可能な最大確率です。 

制約は、m が最大 2400 までであるのに十分小さく、n と q は最大 5000 です。これは、どのソリューションでもスキルに対して 2 次または二次に近い前処理が可能であり、k および間隔エンドポイントを超える DP さえも妥当であることをすぐに示唆しています。 ただし、n と q を一緒にしても、クエリごとの再計算は除外されるため、すべてを 1 回事前計算する必要があります。 

素朴な解釈は巧妙な罠につながります。 単に独立したベルヌーイ試行のサブセットを選択して順序統計を調べているだけだと思う​​人もいるかもしれませんが、「k 番目の成功したトリガー」条件は、選択されたすべてのスキルを組み合わせ的な方法で結合します。 均一な位置分布により、イベント構造はさらに複雑になります。 

典型的な間違ったアプローチは、各スキルを独立して扱い、[R, m] に到達する個々の確率を最大化しようとすることですが、これはすべてのトリガーではなく、k 番目のトリガーのみが重要であるという事実を無視しています。 

P = 0 または P = 100 の場合、別の失敗ケースが発生します。P = 0 の場合、どのスキルもトリガーされないため、k ≥ 1 の場合 k 番目のトリガーは未定義であり、確率 0 として扱われます。P = 100 の場合、選択されたスキルはすべて 1 回だけトリガーされ、問題はランダム変数の固定シーケンスの順序に帰着します。ここでは、選択するスキルの数の組み合わせのみが問題となります。 アクティベーションのランダム性を前提とした解決策は、この境界を誤って複雑にしすぎてしまいます。 

## アプローチ

 最も直接的な解釈から始めます。 学習したスキルのセットを修正し、k を修正するとします。 すべてのサブセットとすべてのアクティベーション結果をシミュレートします。 各シナリオについて、少なくとも k 個のスキルがトリガーされたかどうかを判断し、k 番目にトリガーされたスキルを抽出し、それが [R, m] に到達する確率を計算します。 

すべてのサブセットとすべてのアクティベーション パターンを効果的に合計しているため、これはスキルの数において明らかに指数関数的です。 サブセットの選択を無視したとしても、1 つの構成を評価するには、2^n 個のアクティブ化結果すべてを推論する必要がありますが、これは不可能です。 

重要な観察は、k 番目にトリガーされたスキルの識別は、実際の位置ではなく、その前にトリガーされたスキルの数のみに依存するということです。 各スキルは、その前にアクティブなトリガーの数に独立して寄与しており、プロセスを一連のベルヌーイ試行として扱うことができます。 これにより、問題は順序統計に関する確率的な組み合わせの問題に変わります。 

スキルの固定選択の場合、特定のスキル i が k 番目にトリガーされるスキルになる確率は、その先行スキルのうちちょうど k−1 個のスキルがトリガーする確率に、i がトリガーする確率を乗算し、その位置が [R, m] にある確率を乗算したものになります。

空間成分は独立していて簡単です。区間 [li, ri] の場合、[R, m] に到達する確率は単純にオーバーラップの長さを区間の長さで割ったものになります。 

残りの難しさは、各 k について、ベルヌーイ数列で k 番目の成功になった場合にのみ各スキルが寄与する加重和を最大化するスキルのサブセットを選択する必要があることです。 これは古典的な「順序統計の重みを使用してアイテムを選択する」最適化であり、各スキ​​ルの前に配置する成功の数に関するナップザックのような DP に変換できます。 

スキルを順番に処理し、処理されたスキルのうち正確に j 個のスキルがシーケンス内の現在の位置より前にトリガーされるように設定されている場合に、 dp[j] が達成可能な最高の貢献を表す DP を維持します。 各スキル i は、その活性化確率と空間確率によって重み付けされた dp[j] に基づいて状態 j+1 に寄与します。 

遷移は k 内で線形であり、m は空間確率の事前計算の場合にのみ小さいため、メイン DP は O(nk) で実行されます。 

P/100 によって引き起こされるプレフィックス二項式のような確率を事前計算し、位置 i の前に正確に j 個のトリガーが発生する確率を高速に更新できるようにします。 これにより、サブセットごとに二項分布を再計算する必要がなくなります。 

最後に、完全な処理後に dp[k] を読み取ることで、各クエリ k に答えます。

 ## アルゴリズムのチュートリアル

 このプロセスを、スキルの最適な選択の下で各スキルが k 番目に成功したトリガーになる可能性をカウントすることに変換します。 

まず、すべてのスキル i について、それがトリガーされた場合にその位置がパーフェクト ゾーン [R, m] 内にある確率を事前計算します。 これは、[li, ri] と [R, m] 間のオーバーラップ長の (ri − li + 1) に対する比率として計算されます。 

また、活性化確率として p = P/100 を固定します。 

次に、これまで検討したスキルのうち正確に j 個のスキルがトリガーされるように、dp[j] が達成可能な最大確率量を表す動的プログラミング テーブルを構築しますが、どれが k 番目のターゲットになるかはまだ割り当てられていません。 

入力順にスキルを反復処理します。 

各スキル i について、2 つの可能性を考慮します。 k 番目のトリガーの形成に寄与しない (この場合、dp は変化しない) か、k 番目のトリガーになります。 それが k 番目のトリガーであるためには、正確に k−1 個の前のスキルがトリガーされている必要があり、これはシーケンスの i より前に発生する必要があります。 

i の選択は将来のカウントに影響するため、状態を j にわたって逆方向に伝播することによって dp を更新します。 i を k 番目のトリガー候補とみなす場合、dp[k−1] に p を乗算し、spatial_probability[i] を乗算したものに等しい項を追加します。 

すべてのスキルを処理した後、dp[k] にはクエリ k の最適確率が含まれます。 

この DP は、スキルの ID ではなく、k 番目の位置より前のトリガーされたスキルの数のみが重要であるという事実に依存しています。 これにより、サブセット構造がプレフィックスカウント構造に折りたたまれます。 

### なぜ効果があるのか

 核となる不変条件は、dp[j] がベルヌーイ活性化モデルの下で正確に j 個のトリガーが成功することを保証しながら、処理されたスキルを使用して達成可能な最適な確率を常に表すということです。 各スキルは独立してトリガーされ、空間的な結果はアクティベーションとは独立しているため、貢献度はアクティベーション確率、組み合わせ配置確率、および空間成功確率の積に明確に組み込まれます。 この分離性により、DP 状態への貪欲な割り当てによって最適な構成が失われないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, R, q, P = map(int, input().split())
    p = P / 100.0

    seg = []
    for _ in range(n):
        l, r = map(int, input().split())
        L = max(l, R)
        Rr = min(r, m)
        if Rr < L:
            seg.append(0.0)
        else:
            seg.append((Rr - L + 1) / (r - l + 1))

    # dp[j] = best probability that j skills trigger so far contributing optimally
    dp = [0.0] * (n + 1)
    dp[0] = 1.0

    for i in range(n):
        ndp = dp[:]
        for j in range(n - 1, -1, -1):
            if dp[j] == 0:
                continue
            # skill i triggers and contributes
            ndp[j + 1] = max(ndp[j + 1], dp[j] * p)
        dp = ndp

    # answer for each k: choose k-th trigger landing in zone
    # each skill contributes independently in expectation-style DP
    contrib = [0.0] * (n + 1)

    dp2 = [0.0] * (n + 1)
    dp2[0] = 1.0

    for i in range(n):
        for j in range(i, -1, -1):
            dp2[j + 1] += dp2[j] * p

    for k in range(1, n + 1):
        contrib[k] = dp2[k - 1] * p

    # best k-th skill selection reduces to picking max spatial probability
    ans = [0.0] * (n + 1)
    best = 0.0
    for i in range(n):
        best = max(best, seg[i])
        for k in range(1, n + 1):
            ans[k] = max(ans[k], contrib[k] * best)

    for _ in range(q):
        k = int(input())
        print("%.9f" % ans[k])

if __name__ == "__main__":
    solve()
```この実装では、問題を 2 つの独立した要素、つまりスキルが k 番目のトリガーになる確率と、スキルがパーフェクト ゾーンに到達する確率に分割します。 配列`seg`間隔の重複を使用して、各スキルの空間的成功確率を計算します。 

2 番目の部分の構築`contrib[k]`これは、正確に k−1 個の前のトリガーがあり、その後に別のトリガーが続く確率質量をモデル化します。 これは、独立したベルヌーイ試行に対する標準の二項スタイルの DP を使用して行われます。 

最後に、各 k について、このトリガー位置の確率をこれまでに確認された最良の空間確率と組み合わせます。これは、最適な戦略は、その k の重複寄与が最大となるスキルを選択することであるためです。 

微妙な点は、サブセットを明示的に選択していないことです。 代わりに、DP は暗黙的にすべてのスキルが適格であると想定し、独立性がトリガーの順序を制御します。 逆方向反復により、ベルヌーイ畳み込みの正確さが保証されます。 

## 実用的な例

 ### 例 1

 スキルが 3 つだけ存在し、k = 2 である小さなインスタンスを考えてみましょう。 

| 私 | dp2[j] 前 | 遷移 | dp2[j] 後 |
 | --- | --- | --- | --- |
 | 1 | [1, 0, 0] | p | でトリガー [1、p、0] |
 | 2 | [1、p、0] | p | でトリガー [1, 2p, p^2] |
 | 3 | [1, 2p, p^2] | p | でトリガー [1, 3p, 3p^2, p^3] |

 k = 2 の場合、dp2[1] = 3p を取得します。これは、2 番目のトリガー イベントの前の正確に 1 つのトリガーに対応します。 pを掛けると、選択したスキルが2番目のトリガーとなる貢献確率が得られます。 

これにより、dp2 が独立したアクティベーションにわたって二項確率を正しく蓄積していることが確認されます。 

### 例 2

 すべてのスキルがパーフェクト ゾーンに完全に重なる場合を考えてみましょう。したがって、すべての i に対して seg[i] = 1 になります。 

どのスキルが選択されたかに関係なく、最初のトリガーが最適であるため、k = 1 の答えは単純に p になります。 

k = 2 の場合、確率は分布形式で dp2[1] * p = (n p (1−p)^{n−1}) * p となり、特定のスキルが 2 番目に成功したトリガーである確率と一致します。 

これは、すべての間隔が同一である場合、空間構造が消失し、純粋な順序統計が残ることを示しています。

 ## 特殊なケース

 P = 0 の場合、スキルはトリガーされないため、k ≥ 1 の確率は 0 になります。すべての遷移に p が乗算され、より上位の状態がすべて 0 になるため、DP は正しく折りたたまれます。 

P = 100 の場合、すべてのスキルが常にトリガーされるため、dp2 はシーケンス内の位置にわたる決定的な二項分布になります。 このアルゴリズムは、以前のスキルの組み合わせをカウントすることに帰着し、空間確率が唯一の差別化要因になります。 

すべての間隔が [R, m] の完全に外側にある場合、seg[i] はすべての i に対してゼロになり、最終的な答えは k に関係なくゼロになります。 DP は引き続き実行されますが、空間寄与が蓄積されることはありません。 

間隔に [R, m] が完全に含まれる場合、seg[i] は 1 になり、問題は純粋に k 番目のトリガー確率を選択することになり、空間成分と時間成分がきれいに分離されることが確認されます。
