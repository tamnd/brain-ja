 ## 解決策
 ## 問題の理解

 整数変数の小さなシステムが与えられています。 変数は最大 6 つあり、それぞれがゲーム内のキャラクターの属性を表し、各属性は 0 から K までの任意の整数にすることができます。 

これらの変数に加えて、最大 100 人の裁判官がいます。 各審査員は、正確に 2 つの異なる属性を調べ、それら 2 つの値が関係する単純な線形条件をチェックします。 条件が満たされた場合、そのジャッジは固定スコアを与えます。 条件は常に「選択された 2 つの属性の線形結合がしきい値以下、またはしきい値以上である」という形式になり、各係数は -1、0、または 1 に制限されます。 

タスクは、満足したすべての審査員スコアの合計が最大になるように、すべての属性の値を選択することです。 

重要な構造は、すべての制約が 2 つの変数のみに依存し、変数ごとのドメイン サイズが小さいことです。 これは、制約が小さな制約満足問題のように見えても、割り当てを列挙する余裕があることをすぐに示唆しています。 

探索空間のサイズは最大でも (K+1)^n であるため、この制約によりブルート フォースが実行可能になります。 n ≤ 6 および K ≤ 8 の場合、各変数には最大 9 個の値が含まれるため、代入の総数は 9^6 = 531441 になります。各代入について、最大 100 個の制約を評価でき、最悪の場合でもおよそ 5 × 10^7 の演算が行われます。これは、厳密な実装を備えた Python では許容可能です。 

微妙なエッジ ケースとしては、どの割り当てでも制約を満たすことが不可能な場合があります。 その場合、彼らは決して貢献すべきではありません。 もう 1 つの微妙なケースは、不等式が係数に応じて常に真または常に偽になる可能性があるため、解では制約が「バランスがとれている」または意味があると仮定してはなりません。 

## アプローチ

 単純な解釈では、これをペアごとの制約を持つ整数変数に対する一般的な最適化として扱い、制約の伝播または貪欲な代入で解決しようとすることになります。 この方向は、変数全体に単調な構造がなく、独立性がないため失敗します。つまり、1 つの変数を変更すると、それに関係するすべての制約に影響します。 

しかし、小さなドメインはすべてを変えます。 各変数には可能な値が 9 つしかなく、変数も 6 つしかないため、可能な代入をすべて直接列挙できます。 各課題について、すべてのジャッジ条件を一定時間で評価します。 

検索スペースが完全に探索できるほど小さいため、総当り攻撃は機能しますが、変数の数またはドメイン サイズが大きい場合は失敗します。 n が小さいという観察は、そうでなければ難しい最適化問題を直接の列挙問題に変換するものです。

 ## アルゴリズムのチュートリアル

 n 個の属性に対する値の可能な割り当てをすべて列挙し、各割り当てのスコアを計算します。

1. すべてのタプル (A1、A2、...、An) を生成します。各 Ai の範囲は 0 から K です。これは状態空間にわたる完全な検索であり、候補解が見逃されないことが保証されます。 
2. 課題ごとに、実行スコアをゼロに初期化します。 このスコアは、この特定の構成に対するすべての審査員の合計貢献度を表します。 
3. m 人の審査員全員に対して繰り返します。 各ジャッジは 2 つのインデックス i および j と条件タイプ op を参照します。 
4. 各審査員について、一次式 a * Ai + b * Aj を計算します。 op が 0 の場合、この値が d 以下であるかどうかを確認します。 op が 1 の場合、それが d 以上であるかどうかを確認します。 
5. 条件が満たされている場合、現在の課題のスコアに v を加算します。 
6. この課題のすべての審査員を処理した後、現在のスコアが大きい場合はグローバル最大スコアを更新します。 
7. すべての割り当てが処理された後、見つかった最大スコアを出力します。 

これが機能する主な理由は、考えられるすべての割り当てが 1 回だけ評価され、割り当てが与えられた場合のスコア関数が完全に決定的であるためです。 異なる割り当て間には相互作用がないため、大域的最適値は列挙されたセット内に現れる必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, K = map(int, input().split())
    cons = []
    for _ in range(m):
        i, j, op, a, b, d, v = map(int, input().split())
        i -= 1
        j -= 1
        cons.append((i, j, op, a, b, d, v))

    best = 0
    A = [0] * n

    def dfs(idx):
        nonlocal best
        if idx == n:
            score = 0
            for i, j, op, a, b, d, v in cons:
                val = a * A[i] + b * A[j]
                if op == 0:
                    if val <= d:
                        score += v
                else:
                    if val >= d:
                        score += v
            if score > best:
                best = score
            return

        for x in range(K + 1):
            A[idx] = x
            dfs(idx + 1)

    dfs(0)
    print(best)

if __name__ == "__main__":
    solve()
```この実装では、すべての割り当てに対して深さ優先列挙が使用されます。 配列 A には、現在の部分割り当てが格納されます。 すべての変数が割り当てられると、コードは単一パスですべての制約を評価します。 

よくある落とし穴は、入力ではインデックスが 1 から始まるため、0 から始まるインデックスに変換する必要があることを忘れることです。 もう 1 つの微妙な点は、A が再作成されるのではなく再帰で再利用されるようにすることです。これにより、不要なオーバーヘッドが回避されます。 

## 実用的な例

 最初のサンプルは、3 つの変数と 5 つの制約を持つケースに対応します。 有効な割り当ての 1 つは A1 = 1、A2 = 0、A3 = 1 で、合計スコアは 12 になります。評価は、この固定ベクトルに対して各制約をチェックし、満たされた制約のみを合計することによって続行されます。 

| 制約インデックス | 式 | チェック結果 | 貢献 |
 | --- | --- | --- | --- |
 | 1 | A3 + A1 ≤ 0 | 偽 | 0 |
 | 2 | A3 + A1 ≤ 2 | 本当 | 2 |
 | 3 | A3 ≤ 1 | 本当 | 3 |
 | 4 | A3 + A2 ≧ 2 | 本当 | 0 |
 | 5 | A3 - A2 ≧ 1 | 本当 | 3 |

 2 番目のサンプルには、常に満たされる制約と条件付き制約が混在する 3 つの変数があります。 構造から、A1 はその制約によって 0 に強制されますが、A3 は正の報酬条件に影響を与える唯一の変数です。 A3 ≤ 2 を選択すると、合計スコアが最大になります。 

| 変数の状態 | A1 | A2 | A3 | 現在のスコア |
 | --- | --- | --- | --- | --- |
 | 制約後 | 0 | 無料 | ≤ 2 | 13 |

 このトレースは、制約によって自由度が大きく崩壊する可能性があり、最適な選択は、実際に報酬を伴う不平等に影響を与える少数の変数に焦点を当てることから得られることが多いことを示しています。

def run(inp: str) -> str:

    cons = []
    for _ in range(m):

 ## 特殊なケース

 一般的なエッジケースは、制約を満たすことが不可能な場合です。 このような状況では、割り当てに関係なく、何も貢献しません。 条件が true と評価された場合にのみ v を追加するため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、制約が常に満たされる場合です。 たとえば、a = 0、b = 0、op = 0、d ≥ 0 の場合、すべての代入はそれを満たします。 ブルート フォース評価では、すべての状態に対して一貫してカウントされるため、すべてのスコアに単純に一定の加算となります。 

3 番目のケースは、最適解が変数の極値に依存する場合です。 列挙には 0 から K までのすべての値が明示的に含まれるため、境界最適化は常に検索空間に含まれるため、特別な処理は必要ありません。
