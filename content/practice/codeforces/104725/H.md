 ## 問題の理解

 1 人のプレイヤーが所有する文字列のコレクションと、クエリの生成に使用される文字列の 2 番目のコレクションが与えられます。 各クエリ文字列について、その部分文字列のすべてを個別のゲーム インスタンスとみなします。 このような各部分文字列に対して、特別な操作が適用されます。つまり、部分文字列が 3 つの連続する部分に分割され、操作の結果として中央の部分が選択されます。 

選択した中間部分が最初のコレクションの指定された参照文字列の 1 つと一致すると、勝利となります。 必要な重要な量は、勝利が可能かどうかだけではなく、クエリ文字列のすべての部分文字列にわたる有効な操作の合計数 (部分文字列が選択されるすべての方法で合計されたもの) です。 

したがって、各クエリ文字列の出力は、部分文字列を選択し、その部分文字列を 3 つの部分に分割して、中央の部分が参照文字列のいずれかに等しくなるように選択できる方法の合計数になります。 

この制約は、すべての部分文字列に対する単純な列挙が不可能であることを強く示唆しています。 単一のクエリ文字列の長さは最大 100 万に達する可能性があり、すでに 10^12 程度の部分文字列が含まれています。 各部分文字列をすべてのパターンに対してテストするだけだったとしても、制限時間を超えてしまいます。 すべての参照文字列の合計の長さは 2×10^5 で制限されており、高速なマルチパターン マッチングをサポートする構造にそれらを前処理する必要があることを示唆しています。 

微妙なエッジケースは、一致が重なっていることです。 パターンがクエリ文字列内に複数回出現する場合 (重複する出現を含む)、各出現は独立して影響を及ぼします。 もう 1 つのエッジ ケースは、クエリ文字列の境界付近でパターンが発生する場合です。この場合、有効な囲み部分文字列の数が少なくなり、左または右への拡張子をカウントする際の 1 つずつの間違いが容易に発生します。 

## アプローチ

 直接的なアプローチは、各クエリ文字列のすべての部分文字列を生成し、各部分文字列について考えられるすべての分割点を試し、中央のセグメントが参照文字列と一致するかどうかを確認することです。 これは爆発につながります。長さ L のクエリ文字列には O(L²) 個の部分文字列があり、各部分文字列には最大 O(L) 個の分割があり、結果としてクエリごとに O(L³) 個の動作が発生しますが、これは完全に実行不可能です。 

重要な点は、分割の中央のセグメントが単にクエリ文字列の連続した部分文字列であるということです。 部分文字列の部分文字列について推論する代わりに、プロセスを再解釈することができます。すべての有効な操作は、クエリ文字列内の参照文字列の 1 つの出現と、外側の部分文字列が両側にどれだけ広がるかの選択によって完全に決定されます。 

これにより、問題は、テキスト内の複数のパターンの重み付けされた出現をカウントすることに変換されます。 最大 2×10^5 の合計パターン長と最大 10^6 の合計テキスト長を持つマルチパターン マッチングは、トライベースのオートマトンの使用を強く示唆します。 Aho-Corasick オートマトンを使用すると、各クエリ文字列を 1 回スキャンして、発生したすべてのパターンを線形時間でレポートできます。 

長さ k のパターンが発生し、位置 r で終わることがわかると、その開始位置は r−k+1 になります。 この場合、中央のセグメントは固定されており、それを含む部分文字列の数は、クエリ文字列内で左右にどこまで拡張できるかによってのみ決まります。 これにより、出現ごとに直接寄与の式が得られ、部分文字列を明示的に列挙する必要がなくなります。

 ## アルゴリズムのチュートリアル

 すべての参照文字列を単一の Aho-Corasick オートマトンに処理して、各クエリ文字列をスキャンしながらすべてのパターンを同時に照合できるようにします。

### 1. オートマトンを構築する

 すべての参照文字列をトライに挿入し、エラー リンクを計算することで、クエリ文字列のスキャン中に 1 文字あたり O(1) の償却時間で遷移できるようにします。 各終端ノードは、そこで終了するパターンとその長さを格納します。 

### 2. 各クエリ文字列をスキャンします。 

オートマトンを通じてクエリ文字列を 1 文字ずつ調べます。 各位置 r では、直接または障害リンクを介して、この位置で終了するすべてのパターンを表すノードにいます。 

### 3. 一致したパターンの出現をすべて処理する

 位置 r で終了する長さ k のすべてのパターンについて、その開始位置 l = r−k+1 を計算します。 これにより、具体的な出現間隔 [l, r] が得られます。 

### 4. この出現箇所が含まれる部分文字列の数を数えます。 

この出現を含む部分文字列は、l またはその前で始まり、r またはその後で終了する必要があります。 有効な選択肢の数は、左側の境界では l 個の選択肢、右側の境界では (n-r+1) 個の選択肢です。ここで、n はクエリ文字列の長さです。 このような各選択は個別の部分文字列に対応するため、個別の操作コンテキストになります。 

### 5. 寄付を蓄積する

 すべてのパターンとすべての位置で一致するすべての出現の答えに l × (n−r+1) を加算します。 

### なぜ効果があるのか

 有効な各操作は、分割の中間セグメントとしてパターンの出現を選択し、周囲の部分文字列の境界を選択することによって一意に決定されます。 オートマトンはすべての出現を正確に 1 回列挙し、境界カウントではその出現を含むすべての部分文字列を正確にカウントします。 各ペア (部分文字列、その内部の出現) が固有の有効な操作に対応するため、部分文字列が欠落したり、構成が二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class Node:
    __slots__ = ("next", "link", "out")
    def __init__(self):
        self.next = {}
        self.link = 0
        self.out = []

def build_ac(patterns):
    trie = [Node()]

    # build trie
    for idx, s in enumerate(patterns):
        v = 0
        for ch in s:
            if ch not in trie[v].next:
                trie[v].next[ch] = len(trie)
                trie.append(Node())
            v = trie[v].next[ch]
        trie[v].out.append(len(s))

    # build failure links
    from collections import deque
    q = deque()

    for c, v in trie[0].next.items():
        q.append(v)
        trie[v].link = 0

    while q:
        v = q.popleft()
        for c, u in trie[v].next.items():
            q.append(u)
            f = trie[v].link
            while f and c not in trie[f].next:
                f = trie[f].link
            trie[u].link = trie[f].next[c] if c in trie[f].next else 0
            trie[u].out += trie[trie[u].link].out

    return trie

def solve():
    n, m = map(int, input().split())
    patterns = [input().strip() for _ in range(n)]
    texts = [input().strip() for _ in range(m)]

    ac = build_ac(patterns)

    for t in texts:
        v = 0
        nlen = len(t)
        ans = 0

        for i, ch in enumerate(t, start=1):
            while v and ch not in ac[v].next:
                v = ac[v].link
            if ch in ac[v].next:
                v = ac[v].next[ch]
            else:
                v = 0

            for k in ac[v].out:
                l = i - k + 1
                ans += l * (nlen - i + 1)

        print(ans % MOD)

if __name__ == "__main__":
    solve()
```このソリューションは、すべての参照文字列に対してマルチパターン オートマトンを構築します。 スキャン中、ノードに到達するたびに、伝播された出力リストを通じて、そこで終了するすべてのパターンを収集します。 一致ごとに、その終了位置と保存された長さを使用して寄与度を計算します。 

よくある落とし穴は、障害リンクが出力を伝播する必要があることを忘れていることです。そうしないと、終端ノードのみが一致を報告し、多くの発生が見逃されてしまいます。 もう 1 つの微妙な点は、左側の境界式 l = i − k + 1 がオフバイ 1 エラーなしで一貫性を保つように、現在位置に 1 ベースのインデックスを使用していることです。

 ## 特殊なケース

 重要なエッジ ケースは、クエリ文字列内でパターンが何度も重なり合って出現する場合です。 たとえば、パターン`"aa"`内部`"aaaa"`オートマトンは各発生を独立して報告し、それぞれが独自の境界に基づいて貢献します。 各終了位置は個別に処理され、重複排除は発生しないため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、パターンがクエリ文字列全体と一致する場合です。 この場合、l = 1 および r = n であるため、寄与率は 1 × 1 になります。これは、有効な囲み部分文字列が 1 つだけ、つまり文字列自体であることを意味します。 この数式は特別なケースを使用しなくても正しく動作し、境界処理が両極端にわたって一貫していることを確認します。
