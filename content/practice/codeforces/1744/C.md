 ## 解決策
 ## 問題の理解

 信号機は、文字列で記述された周期的なパターンに従います。 文字列が`"rggry"`、最後に到達すると、再び最初から開始され、無限シーケンスが生成されます。 

現在の色がわかります`c`, しかし、サイクル内で現在その色のどの出現が見られているかはわかりません。 信号が青になったときにのみ横断できるため、サイクル内の色が青になっているすべての位置を考慮する必要があります。`c`。 

そのような位置ごとに、次の位置まで何秒経過する必要があるかを尋ねることができます。`'g'`現れますか？ 実際の現在の瞬間は、次のようなあらゆる出来事に対応する可能性があるため、`c`、これらすべてのポジションの中で最悪の待ち時間が必要です。 その最大待ち時間が答えです。 

文字列の長さは次のようになります。`2 · 10^5`すべてのテスト ケースを組み合わせたものです。 これにより、高価なネストされたスキャンが即座に排除されます。 アン`O(n²)`解決策には約が必要です`4 · 10^10`限界をはるかに超えた最悪の場合の動作。 線形または線形に近いソリューションが必要です。 

信号機の円形の性質が、微妙なバグの主な原因です。 文字列の終わりに近い位置では、先頭に戻った後に緑色のライトが表示されるまで待つ必要がある場合があります。 

考慮する：```
n = 3
c = r
s = "rrg"
```最初`'r'`緑になるまで 2 秒待ちます。`'r'`1秒待ちます。 答えは 2 です。元の文字列の内側のみを検索する解決策では、他の例のラップアラウンド ケースを誤って見逃してしまいます。 

別の簡単な間違いが現れるのは、`c = 'g'`。```
n = 1
c = g
s = "g"
```すでに青信号に到達しているため、答えは 0 です。将来の青信号をまだ見つけようとする一般的な検索ロジックは、正の値を返す可能性があります。 

より興味深いラップアラウンドの例は次のとおりです。```
n = 5
c = y
s = "yrrgy"
```最後`'y'`次の緑は残りのサフィックスの中にありません。 次のサイクルの先頭までラップして、ポジション 3 のグリーンに到達する必要があります。所要時間は 4 秒です。 循環構造を無視すると、間違った答えが得られます。 

## アプローチ

 直接的なブルートフォースソリューションは説明が簡単です。 ターゲットカラーを含むすべての位置について`c`、緑色の信号が見つかるまで、周期的な文字列を一度に 1 歩ずつ前進することを繰り返します。 その待ち時間を記録し、最大値を取得します。 

これが機能するのは、問題の定義を明示的にシミュレートするためです。 問題はパフォーマンスです。 あれば`O(n)`の発生`c`、それぞれがスキャンすることができます`O(n)`青信号に到達する前の位置の場合、全体の複雑さは次のようになります。`O(n²)`。 と`n = 2 · 10^5`、それは遅すぎます。 

重要な観察は、すべての位置が、無限循環シーケンス内でその右側に最も近い緑色の光のみを考慮しているということです。 発生するすべての情報を個別に検索するのではなく、`c`、これらの最も近い緑の距離を簡単に取得できるように、文字列を前処理できます。 

循環文字列の便利なテクニックは複製です。 文字列をそれ自体と連結すると、元のサイクル内のすべての回り込みパスは、二重化された文字列内の通常の右方向のパスになります。 

例えば：```
s      = yrrgy
s + s  = yrrgyyrrgy
```これで、最初のコピーのすべての位置が、折り返しを気にすることなく、次の青信号を右に安全に検索できるようになりました。 

を含む最新の位置を記憶しながら、2 倍になった文字列を右から左にスキャンします。`'g'`。 すべてのキャラクターについて、次の青信号までの距離がすぐにわかります。 文字が等しいときはいつでも`c`、その距離を使用して答えを更新します。 

これにより、問題は 1 回のリニア スキャンに軽減されます。

 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. もし`c`は`'g'`、出力`0`今すぐ渡れるのですぐに。 
2. 二重化された文字列を作成する`t = s + s`。 これにより、円運動が通常の右への運動に変換されます。 
3.スキャン`t`これまでに確認された最も近い青信号の位置を維持しながら、右から左へ。 
4. 現在のキャラクターがいるたびに、`'g'`、保存された緑色の位置を現在のインデックスに更新します。 
5. 現在の文字が次の値に等しいときはいつでも`c`、この位置から保存された緑色の位置までの距離を計算します。 
6. 文字列の最初のコピーに属する位置のみが重要です。 答えは、そのようなすべての位置間の最大距離です。 
7. その最大距離を出力します。 

### なぜ効果があるのか

 文字列を 2 倍にすると、元のサイクル内の位置から次の青信号までのすべてのパスが、単純な右方向のセグメントとして 2 倍になった文字列の内側に完全に表示されます。 右から左にスキャンしている間、保存された緑色の位置は常に現在のインデックス以降の最も近い緑色のライトになります。 したがって、次のことが起こるたびに、`c`、計算された距離は、まさに次の青信号までの待ち時間です。 すべての発生の最大値を取る`c`これは、考えられる限り最悪の現在の立場に備える必要があるという要件に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, c = input().split()
    n = int(n)
    s = input().strip()

    if c == 'g':
        print(0)
        continue

    doubled = s + s

    next_green = -1
    ans = 0

    for i in range(2 * n - 1, -1, -1):
        if doubled[i] == 'g':
            next_green = i

        if i < n and doubled[i] == c:
            ans = max(ans, next_green - i)

    print(ans)
```最初の特殊ケースハンドル`c = 'g'`。 現在の信号はすでに青になっているため、待つ必要はありません。 

その後、文字列が複製されます。 通常はサイクルの終わりにラップするあらゆる待機が、二重化された文字列内の右への通常の移動として表現されるようになりました。 

逆スキャンでは、`next_green`、現在のインデックスの右側に最も近い緑色の位置。 インデックスは右から左に処理されるため、この値は必要なときにいつでも利用できます。 

条件`i < n`重要です。 元の文字列からの出現のみが必要です。 2 番目のコピーは、純粋にラップアラウンド距離の計算を容易にするために存在します。 

よくある間違いは、両方のコピーの出現に対する回答を更新することです。 そうすると、元のサイクルの実際の開始位置に対応しない状態がカウントされます。

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    t = int(input())

    out = []

    for _ in range(t):
        n, c = input().split()
        n = int(n)
        s = input().strip()

        if c == 'g':
            out.append("0")
            continue

        doubled = s + s
        next_green = -1
        ans = 0

        for i in range(2 * n - 1, -1, -1):
            if doubled[i] == 'g':
                next_green = i

            if i < n and doubled[i] == c:
                ans = max(ans, next_green - i)

        out.append(str(ans))

    print("\n".join(out))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    solve()
    return sys.stdout.getvalue()

 ## 特殊なケース

 次のことを考慮してください。```
1
1 g
g
```現在の色はすでに緑色なので、答えは次のようになります。`0`。 アルゴリズムは、スキャンが開始される前にこれを処理します。 この特別なケースがなければ、ソリューションは将来の青信号を不必要に検索し、ゼロ以外の値を生成する可能性があります。 

考慮する：```
1
5 y
yrrgy
```の発生`'y'`インデックス 4 には、元の文字列の右側に緑色のライトがありません。 2 倍後の文字列は次のようになります。`yrrgyyrrgy`、次のグリーンはインデックス 8 に表示されます。距離は次のとおりです。`8 - 4 = 4`、正しくカウントされます。 これはまさに、サイクルの循環を忘れた実装が壊れる状況です。 

考慮する：```
1
6 r
rrrrrg
```すべての赤の位置は、最後に単一の緑を待ちます。 距離は`5, 4, 3, 2, 1`。 最大値は`5`。 逆スキャン中に、`next_green`は緑の位置に固定されたままになるため、各赤はすぐに正しい距離を取得します。 

考慮する：```
1
3 r
rrg
```最初の赤は 2 秒待機し、2 番目の赤は 1 秒待機します。 アルゴリズムは両方の距離を計算し、最大値を維持します。 これにより、発生した中で最短の待機を見つけるのではなく、最悪の場合の保証問題を解決していることが検証されます。
