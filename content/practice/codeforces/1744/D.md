 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられているので、すべての要素の積を次で割り切れるようにする必要があります。$2^n$、 どこ$n$配列の長さです。 要素を乗算することができます$a_i$独自のインデックスによる$i$インデックスごとに 1 回だけ。 目標は、これらの乗算の数を最小限に抑えるか、それが不可能であると報告することです。 

実際には、各数値は積に 2 の特定の数の因数を与えます。 これらの貢献の合計が少なくとも$n$。 乗算する$a_i$による$i$によって寄与される 2 の数が増加する可能性があります$a_i$インデックス自体の因数分解に 2 が含まれる可能性があるためです。 

制約により許可されるのは、$n$到達する$2 \cdot 10^5$すべてのテスト ケースの合計は同じ数に制限されます。 インデックスのサブセットの数が指数関数的に増加するため、操作のすべての組み合わせを試みる総当り的なアプローチでは、時間がかかりすぎます。 代わりに、必要な 2 の数を効率的に達成するために操作に優先順位を付ける方法が必要です。 

微妙なエッジ ケースは、すべての数値が奇数でインデックスが小さいため、許可された演算を組み合わせても十分な 2 を達成できない場合です。 たとえば、次の場合$a = [1, 1, 1, 1]$、任意の数値にそのインデックスを乗算すると、数値ごとに 2 の因数が 1 つしか得られないため、積は次の値に達することはできません。$2^4 = 16$であり、正しい出力は -1 です。 常に最初の数値を選択する単純な貪欲なアプローチでは、解決策が存在すると誤って報告される可能性があります。 

## アプローチ

 素朴な総当たりアプローチでは、インデックスのすべてのサブセットを考慮し、各サブセットに演算を適用し、結果の積を計算し、それが次で割り切れるかどうかを確認します。$2^n$。 サイズの配列の場合$n$、これは確認が必要です$2^n$サブセット。 たとえ$n = 20$、これはすでに 100 万以上の組み合わせであり、$n$まで$2 \cdot 10^5$、それはまったく不可能です。 

重要な洞察は、数値そのものではなく、各数値の因数分解における 2 の数のみを考慮しているということです。 定義しましょう`twos(a_i)`回数としては$a_i$は 2 で割り切れます。同様に、インデックスを掛けます。$i$追加します`twos(i)`その要素のカウントに。 次に、問題は単純な選択問題に帰着します。つまり、次のようなインデックスを選択する必要があります。`twos(i)`貢献により、合計に達するのに十分な追加の 2 が得られます。$n$。 

したがって、最初に次の合計を計算します。`twos(a_i)`すべての要素にわたって。 すでに少なくとも$n$、操作は必要ありません。 それ以外の場合は、インデックスを乗算することで得られる可能性のあるゲインのリストを計算します。$i$、降順に並べ替え、必要な合計に達するまで最大の利益を貪欲に選択します。 到達する前に利益を使い果たした場合$n$、答えは-1です。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取る$a$そしてその長さ$n$。 初期化する`current_twos`ゼロに。 
2. 各要素について$a_i$、除算を繰り返してそれに含まれる 2 の因数の数を計算し、それに加算します。`current_twos`。 
3. もし`current_twos >= n`、0を出力して戻ります。 操作は必要ありません。 
4. それ以外の場合はリストを計算します`index_twos`各エントリはどこにありますか`twos(i)`のために$i = 1$に$n$。 これは、乗算した場合の潜在的なゲインを表します$a_i$による$i$。 
5. 並べ替え`index_twos`降順で、追加の 2 に最も貢献するインデックスを優先します。 
6.初期化`operations`0まで繰り返します。`index_twos`に各値を加算します。`current_twos`そして増加する`operations`それまで`current_twos >= n`。 
7. 可能なすべてのゲインを使用した後、`current_twos < n`、-1 を出力します。 それ以外の場合は、印刷します`operations`。 

**なぜ効果があるのか**

 不変条件は、次の合計です。`current_twos`は積の 2 の合計累乗を表します。 2 の降順でインデックスを乗算すると、最小限の操作で必要なしきい値に到達することが保証されます。 ゲインが小さくても合計にそれほど寄与しないため、代替のインデックス セットではより少ない操作で目標を達成することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_twos(x):
    cnt = 0
    while x % 2 == 0:
        x //= 2
        cnt += 1
    return cnt

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        current_twos = sum(count_twos(x) for x in a)
        if current_twos >= n:
            print(0)
            continue
        
        index_twos = [count_twos(i) for i in range(1, n + 1)]
        index_twos.sort(reverse=True)
        
        operations = 0
        for gain in index_twos:
            current_twos += gain
            operations += 1
            if current_twos >= n:
                break
        
        if current_twos < n:
            print(-1)
        else:
            print(operations)

if __name__ == "__main__":
    solve()
```この解決策では、まず各数値の 2 の因数を数えて、初期積の割り算を決定します。 潜在的な利益を並べ替えると、最大の寄与が最初に使用されるようになります。 最初の 2 がない配列などのエッジ ケースは、ループ オーバーによって自然に処理されます。`index_twos`。 Python は整数オーバーフローを自動的に処理するため、大きなプロダクトでも問題は発生しません。
