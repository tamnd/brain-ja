 ## 解決策
 ## 問題の理解

 3 つの正の整数が与えられており、それらが 3 つの隠れた正の整数を含む非常に特殊な構造から来たものであるかどうかを確認したいと考えています。$a$、$b$、 そして$c$。 これらの未知の値から、3 つの観測値を定義します。1 つは次の最大値です。$a$そして$b$、もう一つは最大値です$a$そして$c$、最後は最大値です$b$そして$c$。 タスクは、特定のトリプルかどうかを判断することです。$x, y, z$このように解釈できます。そうであれば、少なくとも 1 つの有効なトリプルを再構築します。$(a, b, c)$。 

重要な問題は、各入力数値が独立していないことです。 それらのそれぞれは、同じ 3 つの隠れた値の間のペアの関係をエンコードするため、システムは厳密に制約されます。 単純な試みでは、3 つの制約すべてを同時に尊重せずに貪欲に値を割り当てようとする可能性があり、これにより簡単に矛盾が生じる可能性があります。 

制約により、最大で$2 \cdot 10^4$テスト ケース、最大値$10^9$。 これは、どのような解もテスト ケースごとに一定時間である必要があることを直ちに示唆しています。 候補の列挙や範囲にわたる検索を伴うものはすべて不可能です。$10^9$is far beyond limits.

 一般的な微妙な失敗のケースは、次の 2 つ以上の場合に発生します。$x, y, z$は等しいですが、構造は依然として有効な分解を許可しません。 たとえば、2 つの最大値が大きいにもかかわらず、3 番目の変数に一貫性のない下限が強制されている場合、単純に等しい値を割り当てる単純な構造では、たとえ算術チェックに合格したとしても、静かに論理制約に失敗する可能性があります。 

もう 1 つの注意が必要なケースは、3 つの値がすべて異なる場合です。 それでも、ペアごとの最大関係は単一の順序付けと一致する必要があるため、隠れ変数を割り当てることが常に可能であるとは限りません。$a, b, c$。 

## アプローチ

 強引なアイデアは、可能なすべての割り当てを試してみることです。$a, b, c$指定された範囲まで調べて、結果の最大値がターゲットのトリプルと一致するかどうかを確認します。 これは理論的には簡単です。すべてのトリプルを反復処理して条件を検証します。 ただし、これを探索すると、$10^9$変数ごとに選択肢があり、$10^{27}$完全に不可能な組み合わせです。 

各方程式が次の相対的な順序を直接制約していることを観察することで、問題を大幅に減らすことができます。$a$、$b$、 そして$c$。 それぞれの最大値は、ペア内のどの変数が大きいかを示します。 たとえば、次の場合$x = \max(a, b)$、その後両方$a \le x$そして$b \le x$、そしてそれらの少なくとも 1 つは等しい$x$。 他の 2 つのペアについても同じ構造が繰り返されます。 

重要な洞察は、$x, y, z$、最大値は特別な役割を果たす必要があります。 そのうちの 1 つが他の 2 つよりも厳密に大きいと仮定します。 その値は 2 つの最大方程式に出現する必要があり、これにより最大の隠れ変数が一貫して配置されます。 最大の制約が修正されると、残りの変数は直接チェックできる少数の可能性に分解されます。 

これは、次の直接構築戦略につながります。つまり、次の値のうちの最大値を扱います。$x, y, z$の一つの候補として$a, b, c$、次に、最大値によって暗示される一貫性条件に基づいて残りの 2 つを割り当てます。 矛盾が生じた場合、解決策は存在しません。

 ## アルゴリズムのチュートリアル

 私たちは与えられています$x, y, z$。 私たちが構築したいのは$a, b, c$ペアごとの最大値が正確に一致するようにします。 

1. 次の中で最大の値を特定します。$x, y, z$。 電話してください$M$。 この値は、次の少なくとも 1 つとして表示される必要があります。$a, b, c$、それはあるペアの最大値であるためです。 
2. 仮定する$a = M$一般性を失うことなく。 これは、トリプルを任意の順序で出力できるため、変数のラベルを自由に変更できるため有効です。 
3. から$x = \max(a, b)$、 以来$a = M \ge x$、これは強制的に$M = x$または$b = x$。 もし$x < M$、次に設定する必要があります$b = x$。 
4. 他の 2 つの式にも同じロジックを適用します。 各方程式は、すでに固定されている値を確認するか、残りの変数を割り当てます。 
5.割り当て後$b$そして$c$、3 つの最大条件がすべて正確に満たされていることを確認します。 不一致が発生した場合、その構築は無効になります。 

同じロジックを確認する簡単な方法は、次の 2 つの値を確認することです。$x, y, z$最大のものと等しくなければなりません。そうでない場合、制約によりペアごとの最大値構造に矛盾が生じます。 

### なぜ効果があるのか

 このシステムは、ペアごとの支配関係によって完全に決定されます。 形の各方程式$\max(u, v)$少なくとも 1 つのエンドポイントの上限と強制等価の両方をエンコードします。 の 1 つ以来、$x, y, z$グローバル最大値でなければなりません$a, b, c$、その値が構築を固定します。 一度アンカーされると、残りのすべての変数は不等式の一貫性によって強制され、隠れた矛盾に対する自由がなくなります。 これにより、有効なトリプルが存在する場合、最大要素から導出された構成によってそれが回復され、構成が失敗した場合には、3 つの方程式すべてを同時に満たす代替代入ができないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x, y, z = map(int, input().split())

        M = max(x, y, z)

        # try to interpret M as one of a, b, c
        # we construct a candidate triple
        a = b = c = M

        # enforce constraints from each pair
        if x != M:
            b = x
        if y != M:
            c = y
        if z != M:
            # z = max(b, c)
            if b == M and c == M:
                b = z  # arbitrary assignment
            elif b == M:
                b = z
            elif c == M:
                c = z

        # validate
        if max(a, b) == x and max(a, c) == y and max(b, c) == z:
            print("YES")
            print(a, b, c)
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを独立して処理するため、ループはクエリの数において線形になります。 それぞれのケースで、最大値を特定することから始めます。これは、最大値が少なくとも 1 つの隠れ変数に対応する必要があるためです。 次に、その最大値を 3 つの位置すべてに強制し、指定されたペアごとの最大値がグローバル最大値よりも厳密に小さい場合に制約を徐々に緩和することによって、暫定的なトリプルを構築します。 

複数の中間割り当てが可能であり、すべてが 3 つのペア制約すべてにわたって同時に一貫性を維持できるわけではないため、検証ステップは不可欠です。 この最終チェックを行わないと、依存関係が競合する場合に、誤った貪欲な割り当てがすり抜けてしまう可能性があります。 

## 実用的な例

 インプットを考慮する$3, 2, 3$。 ここでの最大値は、$3$。 から始めます$a = b = c = 3$。 以来$y = 2$、私たちは執行します$\max(a, c) = 2$、強制的に$c = 2$。 他の制約はすでに一貫しています。 得ます$(a, b, c) = (3, 3, 2)$、すべての方程式を満たします。 

| ステップ | | b | c | 最大(a,b) | 最大(a,c) | 最大(b,c) |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初期化 | 3 | 3 | 3 | 3 | 3 | 3 |
 | yを調整 | 3 | 3 | 2 | 3 | 2 | 3 |

 これにより、より小さい最大値に関係する変数のみを削減すると正確さが維持されることが確認されます。 

ここで考えてみましょう$10, 30, 20$。 最大値は$30$したがって、すべての変数を 30 に設定して開始します。$x = 10$、私たちは強制します$b = 10$。 以来$z = 20$、間の一貫性を強制します。$b$そして$c$、検証時に矛盾が生じます$y = 30$。 

| ステップ | | b | c | 最大(a,b) | 最大(a,c) | 最大(b,c) |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初期化 | 30 | 30 | 30 | 30 | 30 | 30 |
 | ×修正 | 30 | 10 | 30 | 30 | 30 | 30 |
 | 修正 | 30 | 10 | 20 | 30 | 30 | 20 |

 構造がすべてのペアごとの最大値を同時に満たすことができないため、最終チェックは失敗します。 これは、局所的な制約が満たされるように見えても、すべてのトリプルが表現可能であるわけではないことを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、3 つの入力がすべて等しい場合です。 この場合の設定は、$a = b = c = x$すべてのペアごとの最大値は同じ値に等しいため、すべての最大条件を自明に満たします。 平等性を損なうような調整は行われないため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、正確に 2 つの値が等しく、厳密に 3 番目の値よりも大きい場合に発生します。 例えば$x = y = 100, z = 50$。 から始まる$a = b = c = 100$、からの制約$z$次のうちの 1 つを強制します$b$または$c$50 まで下がりますが、これはすぐに他の最大条件の 1 つを破り、検証で正しく拒否されます。 

最後の微妙なケースは、最大値が次の値のうち 1 回だけ現れる場合です。$x, y, z$。 このような場合、一貫性のために最大値は少なくとも 2 つの最大値で共有される必要があるため、代入によってペア間で矛盾する等価性が強制されます。 3 つのペアごとの最大制約をすべて同時に満たす代入はできないため、アルゴリズムは最終検証中にこれらのケースを拒否します。
