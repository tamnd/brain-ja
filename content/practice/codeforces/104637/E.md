 ## 解決策
 ## 問題の理解

 ドアが開く順序を説明するシーケンスが与えられます。 各ドアは、家の 2 つの出口 (左の出口または右の出口) のいずれかに属します。 このシーケンスは幾何学や構造を説明するものではなく、次に開かれるドアが左側に属するか右側に属するかを段階的に示すだけです。 

このシーケンスのいくつかのプレフィックスを開いた後は常に、各側のドアの一部が開かれています。 1 つの出口全体が完全に開いている場合、ブラックさんは家を出ることができます。つまり、その出口に属するすべてのドアがすでに開いているプレフィックスに表示されています。 

タスクは、2 つの出口のうちの少なくとも 1 つでこの条件が true になる最も早いプレフィックス長を見つけることです。 

最大 200,000 ドアという制約は、プレフィックスに対する二次シミュレーションが遅すぎることを意味します。 どのドアが完全に開いているかを再計算して各プレフィックスをチェックするアプローチでは、最悪の場合、およそ n² 回の操作が必要となり、これは 1 秒の制限で処理できる範囲をはるかに超えています。 ソリューションは、単一のリニア スキャン、または要素ごとの一定量の追加作業に依存する必要があります。 

1 つの出口の最後のドアがシーケンスの非常に早いのに、もう 1 つの出口がずっと遅く終了する場合、微妙なエッジ ケースが発生します。 たとえば、すべての右側のドアが先頭近くに表示され、最後の右側のドアが位置 3 にあるが、左側のドアが位置 n まで続く場合、たとえ左側のシーケンスの大部分がまだ不完全であっても、答えは 3 になります。 単純なプレフィックス シミュレーションでは、両側が完全にオープンされるまで誤って待機する可能性がありますが、これは必須ではありません。 

## アプローチ

 強引な方法は、すべてのプレフィックスの長さ k を調べて、左側の出口のすべてのドアまたは右側の出口のすべてのドアがそのプレフィックス内に出現したかどうかを確認することです。 これを直接行うには、各側のドアの合計数を知り、これまでに見たドアの数を数える必要があります。 単純な実装では、k ごとにプレフィックスをスキャンして完全性を検証するか、セットを維持して合計と比較します。 

この条件は純粋に、ある型のすべての出現をカバーするものであるため、これは正しく機能します。 ただし、各プレフィックスのカバレッジを再計算すると、作業を繰り返すことになります。 n 個の要素の場合、プレフィックスをスキャンすると、約 1 + 2 + ... + n 回の操作が行われ、これはおよそ n² になります。 

重要な観察は、実際には中間カウントは気にしておらず、各側がプレフィックスに完全に含まれる時期だけを気にしているということです。 シーケンス内の最後の出現に遭遇した瞬間に、側面が完全に開きます。 その瞬間まで、少なくとも 1 つのドアは開かれていません。 その瞬間以降、それは永遠に全開のままになります。 

これにより、シーケンス内の各値の最後の位置を見つける問題が軽減されます。 どちらかの側が完了するとすぐに終了が可能になるため、答えは単にこれらの完了ポイントの中で最も早いものになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 (最後の発生スキャン) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. シーケンスを 1 回スキャンし、左のドアが表示される最後の位置と右のドアが表示される最後の位置を記録します。 サイドの完成は、中間構造ではなく、その最終出現にのみ依存するため、これで十分です。 
2. 両方の最後の位置がわかったら、それらを比較します。 より早く終了した側が、最も早く終了する機会を決定します。 
3. 最後の 2 つの出現インデックスの最小値を出力します。 

重要な考え方は、プロセスをシミュレーションしているのではなく、双方が完全に満足する正確な瞬間を特定しているということです。 

### なぜ効果があるのか

各出口について、それが使用可能になる瞬間は、シーケンス内の最後の出現によって決まります。 その位置の前では、少なくとも 1 つの必要なドアがまだ開いていません。 その位置の後、その側の必要なすべてのドアがプレフィックスに表示されることが保証されます。 したがって、各側は単一のしきい値インデックスを提供し、答えはこれらのしきい値の最小値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_str(data: str) -> str:
    it = iter(data.strip().split())
    n = int(next(it))
    last0 = last1 = 0

    for i in range(1, n + 1):
        x = int(next(it))
        if x == 0:
            last0 = i
        else:
            last1 = i

    return str(min(last0, last1))

def solve():
    data = sys.stdin.read()
    sys.stdout.write(solve_str(data))

if __name__ == "__main__":
    solve()
```この実装は、2 つの整数、つまり各タイプの最後に検出されたインデックスのみの追跡に依存しています。 ループには、概念上のプレフィックス長に直接一致するように 1 のインデックスが付けられ、最後での 1 ずつずれた調整が回避されます。 最終的な答えは、スキャン後の一定時間内に計算されます。 

よくある間違いは、実行カウントを維持しようとして、カウントが合計と一致するかどうかを確認することです。 このアプローチは機能しますが、合計数を明示的に把握する必要があり、非効率的に実装すると追加のオーバーヘッドが発生するリスクがあります。 最終出現メソッドはこれを完全に回避します。

 ## 特殊なケース

 1 つのタイプのすべてのドアが非常に早い段階で出現するケースは、完了瞬間のみを追跡することがなぜ機能するのかを示しています。 入力用`1 1 1 0 0 0`、最後の右ドアは位置 3 にあるため、左ドアがその後に続いても、プレフィックス 3 ですでに出口が可能です。 このアルゴリズムは、プレフィックスをシミュレートするのではなく、各タイプの最終的な出現を記録するため、これを正確に捕捉します。 

のような逆の状況では、`0 1 0 1 0 1`、両方のサイドがインターリーブされますが、各サイドの最後の出現により、いつ独立して完了するかが決まります。 これらの最終位置の最小値により、すべてのステップをシミュレートする必要がなく、最も早い使用可能なプレフィックスが正しく識別されます。
