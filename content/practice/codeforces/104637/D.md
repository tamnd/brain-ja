 ## 解決策
 ## 問題の理解

 1 から n までの範囲の整数が、完全正方形または完全立方体の 2 つの特別な形式の少なくとも 1 つで記述できる数を数えるよう求められます。 数値が両方の方法で記述できる場合でも、カウントされるのは 1 回のみです。 

したがって、クエリ n ごとに、基本的に 2 つの集合の和集合のサイズを数えます。つまり、i² 形式のすべての数値と j³ 形式のすべての数値で、最大 n に制限されます。 

テスト ケースの数という点では入力サイズは小さく、最大 20 ですが、n の値は最大 10⁹ と大きくなります。 これにより、n までのすべての整数を反復処理するアプローチは即座に除外されます。 テスト ケースごとのリニア スキャンには最大 10⁹ の操作が必要ですが、これは 1 秒に収まる量をはるかに超えています。 

より微妙な制約の意味は、答え自体が整数べき乗によって駆動されることです。 正方形と立方体は両方とも急速に成長するため、n までのカウントは約 n^(1/2) と n^(1/3) になります。n が 10⁹ の場合、最大でそれぞれ約 31623 と 1000 になります。 これは、ルートに対する反復処理が実行可能であることを示唆しています。 

単純な間違いは、平方と立方体の両方の数を二重に数えることです。 たとえば、64 は 8² と 4³ の両方であるため、両方のシーケンスに表示されます。 単純に正方形と立方体の数を加算するアプローチでは、そのような数が過剰にカウントされてしまいます。 

2 番目の微妙なエッジ ケースは、最小値です。 n = 1 では、正方形シーケンスと立方体シーケンスの両方に 1 が含まれますが、それでも寄与するのは 1 回だけです。 

## アプローチ

 強引な解釈では、1 から n までのすべての整数 x を反復処理し、それが完全な正方形であるか完全な立方体であるかを確認します。 x が正方形か立方体かをチェックするには、整数の根を計算して検証する必要があり、チェックごとに O(1) になります。 これにより、テスト ケースあたり O(n) となり、n = 10⁹ ではクエリあたり約 10 億チェックとなり、複数のテスト ケースを考慮する前でさえ遅すぎます。 

重要な構造的観察は、各整数を調べる必要はなく、平方と立方体の生成子だけを調べる必要があるということです。 すべての正方形は、i² ≤ n の整数 i によって生成され、すべての立方体は、j³ ≤ n の整数 j によって生成されます。 これにより、問題は有効なインデックス i と j をカウントすることになり、sqrt(n) と cbrt(n) に関する問題になります。 

ただし、sqrt(n) + cbrt(n) を単純に計算すると、平方と立方体の両方の数値が過剰にカウントされます。 lcm(2,3) = 6 であるため、数値は正確に 6 乗の場合、正方形でも立方体でもあります。したがって、k⁶ の形式の数値は両方のリストに表示され、1 回減算する必要があります。 

これにより、問題は古典的な累乗集合に対する包含/除外カウント、つまり平方数を数え、立方体を数え、6 乗を減算する問題に変わります。

 ## アルゴリズムのチュートリアル

 ## 累乗による最適なカウント

 1. 与えられた n に対して、i² ≤ n を満たす整数 i がいくつあるかを計算します。 これは、floor(sqrt(n)) と同等です。 これにより、n までのすべての正方形がカウントされます。 
2. j3 ≤ n を満たす整数 j がいくつあるかを計算します。これは、floor(cbrt(n)) です。 これにより、n までのすべての立方体がカウントされます。 
3. k⁶ ≤ n を満たす整数 k がいくつあるかを計算します。これは、floor(n^(1/6)) です。 これは、正方形と立方体の両方の数値を数えます。これらは正確に 6 乗であるためです。 
4. 正方形と立方体の数を加算し、6 乗の数を引きます。 これにより、正方形セットと立方体セットの両方でカウントされた重複が削除されます。 
5. 各テスト ケースの結果の値を出力します。 

各ステップが機能する理由は、数値を直接反復処理しているのではなく、その固有の生成指数を反復処理しているためであり、各変換は生成変数内で単調であるためです。 

### なぜ効果があるのか

正方形であるすべての整数 x ≤ n は、整数 i に対して一意の表現 x = i² を持ち、同様に、すべての立方体は一意の表現 x = j³ を持ちます。 これにより、整数 i と j から有効な数値のセットへの 2 つの単射マッピングが作成されます。 唯一の重複が発生するのは、数値を i² と j³ として同時に書き込むことができる場合であり、これは x が完全な 6 乗であることを意味します。 6 乗は各セットで 1 回カウントされるため、そのカウントを減算すると、オーバーラップする要素ごとに 1 回だけオーバーカウントが修正されます。 指数表現は素因数分解の項で一意であるため、他の重複は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def isqrt(n: int) -> int:
    lo, hi = 0, 10**9
    while lo <= hi:
        mid = (lo + hi) // 2
        if mid * mid <= n:
            lo = mid + 1
        else:
            hi = mid - 1
    return hi

def icbrt(n: int) -> int:
    lo, hi = 0, 10**6
    while lo <= hi:
        mid = (lo + hi) // 2
        if mid * mid * mid <= n:
            lo = mid + 1
        else:
            hi = mid - 1
    return hi

def i6th(n: int) -> int:
    lo, hi = 0, 10**3
    while lo <= hi:
        mid = (lo + hi) // 2
        p = mid * mid
        p = p * p * p
        if p <= n:
            lo = mid + 1
        else:
            hi = mid - 1
    return hi

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = isqrt(n)
        b = icbrt(n)
        c = i6th(n)
        print(a + b - c)

if __name__ == "__main__":
    solve()
```この実装では、3 つの計数タスクが整数ルートの計算に分割されます。 各ヘルパー関数は浮動小数点演算ではなく二分探索を使用し、10⁹ などの大きな境界での精度の問題を回避します。 

平方根関数は、sqrt(10⁹) が約 31623 で安全な範囲内であるため、10⁹ まで検索します。 立方根の探索空間の上限は 10⁶ で、これはすでに cbrt(10⁹) ≈ 1000 をはるかに上回っています。 (10³)⁶ = 10¹⁸ であるため、6 根の上限は 10⁶ であり、すべての可能な入力を余裕で超えています。 

最終的な式は、中間セットを保存せずに、包含と除外を直接適用します。 

## 実用的な例

 ### 例 1: n = 10

 2 乗、3 乗、6 乗を計算します。 

| ステップ | 値 |
 | --- | --- |
 | フロア(sqrt(10)) | 3 (1、4、9) |
 | 床(cbrt(10)) | 2 (1, 8) |
 | 床(n^(1/6)) | 1 (1) |
 | 結果 | 3 + 2 - 1 = 4 |

 この結果、1、4、8、9 がそれぞれ 1 回カウントされることが確認されます。 

### 例 2: n = 100

 | ステップ | 値 |
 | --- | --- |
 | フロア(sqrt(100)) | 10 |
 | 床(cbrt(100)) | 4 |
 | 床(n^(1/6)) | 2 |
 | 結果 | 10 + 4 - 2 = 12 |

 これには、100 までのすべての正方形と 100 までのすべての立方体が含まれますが、6 乗は二重カウントから除外されます。 

これらのトレースは、オーバーラップ補正により、両方のシーケンスに出現する数値が一貫して正確に削除されることを示しています。

 ## 特殊なケース

 n = 1 の場合、平方数と立方体の数は両方とも 1 に等しく、6 乗の数も 1 になります。この式は 1 + 1 − 1 = 1 を生成し、二重カウントを正しく回避します。 

n = 10⁹ の場合、平方根は 31622、立方根は 1000、6 乗根は 10 です。減算により、10 の 6 乗が 2 回カウントされなくなります。 このアルゴリズムは、オーバーフローや精度の問題を発生させることなく、純粋に整数ルートの計算を通じてこれを処理します。
