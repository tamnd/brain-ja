 ## 解決策
 ## 問題の理解

 アラームを繰り返す非常に特殊な睡眠サイクルをシミュレートしています。 Polycarp は眠りに落ち、最初のアラームが鳴るまで一定の分待機します。 その後、目が覚めるたびに、総睡眠時間が十分に蓄積されているかどうかを確認します。 それでも必要な量に達していない場合は、アラームがリセットされる別のサイクルを経て、再び眠りにつくのにしばらく時間を費やします。実際の睡眠に寄与するのは次のアラーム間隔の一部だけです。 

重要な考え方は、時間が交互のフェーズに分割されるということです。睡眠フェーズは睡眠の蓄積に寄与しますが、「入眠」フェーズは時間を消費しますが、睡眠は増加しません。 アラームは、最初の間隔が異なることを除いて、一定の間隔でこのプロセスを繰り返し中断します。 

蓄積された睡眠が最初に少なくとも所定のしきい値に達する正確な時間を計算するように求められます。 プロセスの構造により十分なスリープを蓄積することが不可能な場合、プロセスは永久に実行され、-1 を出力する必要があります。 

制約では最大 1000 個のテスト ケースが許可され、各パラメーターは 10^9 までの大きさにすることができます。 これにより、分ごとまたはイベントごとの進行をシミュレートすることが直ちに排除されます。 アラームごとの線形シミュレーションでも、値が大きくプロセスに最大数十億サイクルかかる最悪のケースでは遅すぎます。 

微妙な失敗例は、睡眠の蓄積が「眠りに落ちるオーバーヘッド」に比べてあまりにもゆっくりと成長する場合に現れます。 このような場合、アラームが無限に鳴り続けても、サイクルごとに得られる有効な睡眠がゼロになるか不十分になり、無限ループが発生する可能性があります。 

たとえば、c ≤ d の場合、入眠中にアラームが鳴るたびに、Polycarp はアラームをリセットし、最初の中断以降は意味のある睡眠段階に到達することはありません。 これにより、蓄積された睡眠が進まなくなる可能性があります。 

もう 1 つのエッジ ケースは、b がすでに a を超えるか等しい場合です。これは、Polycarp が最初のアラームの直後に十分な睡眠を取ることを意味します。 その場合、それ以上のサイクルは発生せず、答えは単純に b になります。 

最後に、繰り返しパターンで睡眠が蓄積する場合があるため、すべてのサイクルを明示的にシミュレートすることを避け、代わりにサイクルごとの純利益について推論する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、各アラームサイクルをシミュレートします。 現在の時刻と蓄積された睡眠を追跡し、アラームが鳴るまで待機し、その間隔で得られた睡眠を加算し、その後入眠時間を差し引いて続行するという処理を繰り返します。 各サイクルは O(1) ですが、サイクル数は a/b または a/c に比例する可能性があり、最悪の場合は 10^9 に達します。 これにより、直接シミュレーションが不可能になります。 

重要な観察は、最初のアラームの後、プロセスが周期的になるということです。 各サイクルは固定量の睡眠獲得に寄与し、固定量のリアルタイムを消費します。 すべての起床をシミュレートするのではなく、全サイクルごとにどれだけの睡眠が得られるかを理解することだけが必要です。 

時間 b で最初に目覚めた後、Polycarp はこれまでの睡眠が十分であるかどうかを確認します。 そうでない場合、彼は繰り返しパターンに入ります。各サイクルは、d 分間眠りに落ち、リセットから c 分後に次のアラームを待つことから構成され、その間、重複構造に応じて最後の部分のみが睡眠に寄与します。 重要な削減点は、全サイクルごとに合計時間が c 増加し、重複に応じて c または max(0, c - d) の有効睡眠に寄与することです。 

これにより、問題は線形累積問題に変わり、最初のステップの後に早期終了する可能性があります。 

プロセスはすぐに終了するか、同じ増分を数回行った後に終了するか、サイクルごとの正味のスリープゲインがゼロであるため進行しないかのいずれかです。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 最初のアラーム直後に、Polycarp がすでに必要な睡眠を満たしているかどうかを確認します。 最初のセグメント b で得られた睡眠が少なくとも a であれば、それ以上待つ必要はないため、答えは単純に b になります。 
2. 満足できない場合は、最初の起床後にどれだけ追加の睡眠が効果的に得られるかを計算します。 最初のサイクルでは既知の初期寄与が与えられ、その後は各繰り返しが同様に動作します。 
3. 目が覚めた後、Polycarp が d 分間かけて眠りにつくのを観察してください。 この間、次のアラーム間隔 c が「入眠を超えて重複」するほど大きくない場合、その後のサイクルで追加の睡眠は得られません。 
4. c ≤ d の場合、アラームが何か役立つ前に、すべてのサイクルが眠りにつくことによって完全に消費されてしまいます。 これは、最初の目覚めの後はそれ以上の睡眠は蓄積されないことを意味するため、b < a の場合は答えは不可能です。 
5. それ以外の場合、c > d の場合、各サイクルは最初の起床を超えて正確に (c - d) 分の追加の有効睡眠量に寄与します。 これを直線的な進行として扱うことができます。 
6. 合計睡眠時間が少なくとも a に達するまでに、このようなサイクルが何回必要かを計算します。 これは、最初のアラーム後の残りの必要な睡眠時間の単純な上限分割です。 
7. 最初の b を加算し、次にサイクルごとに c を加算して、サイクル数を合計時間に変換します。 

### なぜ効果があるのか

 最初のアラームの後、プロセスは決定論的な線形反復になります。 各サイクルは同一の構造を持ち、時間と蓄積された睡眠の両方に一定の増加をもたらします。または、c ≤ d の場合は睡眠にはまったく寄与しません。 これは、各ウェイクアップ後のシステムの状態が、これまでの総睡眠時間によって完全に特徴づけられ、その値が直線的に変化することを意味します。 後のサイクルには分岐やランダム性がないため、増分が正かゼロかを分類すると、結果は固定されます。有限の等差数列がしきい値に達するか、シーケンスがまったく進行しないかのどちらかです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c, d = map(int, input().split())

        # first alarm
        if b >= a:
            print(b)
            continue

        # if no progress possible after first cycle
        if c <= d:
            print(-1)
            continue

        # remaining sleep needed
        need = a - b

        gain = c - d

        # number of full useful cycles needed
        cycles = (need + gain - 1) // gain

        # total time: initial b + cycles * c
        ans = b + cycles * c
        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、シミュレーション問題から等差数列へのリダクションを直接エンコードします。 早期終了は、最初のアラームがすでに要件を満たしている場合を処理します。 条件`c <= d`システムがそれ以上スリープを蓄積できないという縮退ケースを捉えています。 最後の式は、同じサイズの増分の数を計算します。`gain`残りの赤字を補うために必要であり、それを時間に換算します。 

よくある落とし穴は、最初のセグメントの寄与が残りのセグメントとは異なることを忘れることです。 コードは処理によってそれを分離します`b`均一サイクルロジックに入る前に個別に実行してください。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

| スペース | お(1) | テスト ケースごとに使用される変数はわずかです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            a, b, c, d = map(int, input().split())

            if b >= a:
                out.append(str(b))
                continue

            if c <= d:
                out.append(str(-1))
                continue

            need = a - b
            gain = c - d
            cycles = (need + gain - 1) // gain
            out.append(str(b + cycles * c))

        return "\n".join(out)

    return solve()

 ## 特殊なケース

 いつ`b >= a`、アルゴリズムはすぐに戻ります`b`サイクルロジックを入力せずに。 これは、最初のアラームがすでに十分な休息を提供しており、その後の構造が重要であるという仮定が存在しない状況に対応します。 

いつ`c <= d`、システムは最初のウェイクアップ後に追加のスリープを蓄積できません。 この場合、アルゴリズムは -1 で終了します。 次の有効な睡眠間隔に到達しようとする試みはすべて、入眠時間によって完全に消費されるため、この推論は実際のプロセスと一致します。 

いつ`c > d`ただし、必要なスリープは非常に小さいため、上限分割後に計算されたサイクル数がゼロになる可能性があります。 式`(need + gain - 1) // gain`は、必要な場合にのみ少なくとも 1 サイクルを確保することでこれを適切に処理し、早期終了でのオフバイワン エラーを回避します。
