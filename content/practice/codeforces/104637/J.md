 ## 解決策
 ## 問題の理解

 Tanya が階段を上るときに言ったことを表す単一の整数シーケンスが与えられます。 新しい階段に入るたびに、1 から数え始め、その階段が終わるまで 1 段ずつ上に登り続けます。 それから彼女はすぐに別の階段を続け、再び 1 から始めます。 

したがって、シーケンスはいくつかの連続した実行を連結することによって形成されます。各実行は、正の整数 k に対して 1、2、3、...、k の形式になります。 私たちのタスクは、シーケンスをこれらの最大有効ランに分割し、そのようなランが存在する数とその長さを出力することです。 

この構造は非常に厳格です。すべての階段は 1 から始まり、次の要素はすべて 1 ずつ増加し、このパターンが崩れた瞬間に新しい階段が開始されなければなりません。 

n ≤ 1000 という制約は十分小さいため、O(n²) アプローチでも許容されますが、構造は直接線形スキャンで十分であることを示唆しています。 

いくつかの特殊なケースが重要です。 シーケンスは 1 つの階段で構成されている場合があります (例: 1 2 3 4 5)。この場合、答えは長さ 5 の 1 つのブロックになります。また、シーケンスは多数の 1 段の階段で構成されている場合もあります (例: 1 1 1 1)。この場合、各 1 は前方に拡張できないため、すべての要素が独自の階段になります。 もう 1 つの微妙なケースは、1 2 3 1 2 3 4 など、休憩後にシーケンスがきれいに再開される場合です。この場合、誤ってリセット ポイントを越えてマージしてはなりません。 

単純な間違いは、シーケンスが減少するか同じままになるたびに、新しい階段が始まると想定することです。 これは近いものですが、正しいルールはより厳密です。次の期待値が違反されたときに新しい階段が開始され、その期待値は 1 にリセットされます。 

## アプローチ

 ブルートフォース解釈では、シーケンスの考えられるすべてのセグメントをセグメントに分割して、各セグメントが有効な 1 から k の進行を形成しているかどうかを確認します。 候補セグメンテーションごとに、妥当性の検証にはセグメント長に直線的な時間がかかり、パーティションの数は n とともに指数関数的に増加するため、計算量が爆発的に増加します。 すべての位置でカットを試みる、より抑制されたアプローチであっても、チェックの実装方法によっては、二次関数またはそれより悪い動作が発生する危険性があります。 

重要な観察は、妥当性条件が局所的で決定的であるということです。 階段の中に入ると、次に期待される数値は常に current_index_in_stairway + 1 になります。これは、階段がどこで終わるかを推測する必要がなく、パターンが崩れたらすぐに貪欲に検出できることを意味します。 

現在の階段で期待される次の値を維持しながら、単純に左から右にスキャンします。 現在の数値が予想と一致する場合は、続行します。 そうでない場合は、前の階段が終了し、この位置から新しい階段が始まります。 

これにより、問題全体がアレイ上の 1 回のパスに軽減されます。

 ## アルゴリズムのチュートリアル

1. シーケンスのスキャンを左から右に開始し、連続する有効な増加ランを 1 つの階段として扱います。 これらの階段の長さを発見次第、保存します。 
2. 有効なシーケンスでは最初の要素は常に 1 でなければならないため、最初の階段の長さを 1 として初期化します。 この問題によって妥当性が保証されるため、これをグローバルに検証する必要はありませんが、それでも構造を固定するためにそれを使用します。 
3. シーケンス内の次の各要素について、前の要素に 1 を加えたものと比較します。 これは現在の階段の継続と予想されます。 一致する場合、現在の階段の長さを 1 だけ延長します。 
4. 値が期待と一致しない場合は、前の階段が終了したことを意味します。 その長さを保存し、新しい階段を開始し、新しいセグメントの期待値をリセットします。 新しいセグメントは、シーケンス構造と一致する 1 で始まる必要があります。 
5. すべての要素を処理した後、不一致によって階段が閉じられないため、最後の階段の長さが記録されていることを確認します。 

### なぜ効果があるのか

 すべてのインデックスで、アルゴリズムは有効な階段に対して唯一可能な継続ルールを強制します。次の番号は正確に前の + 1 である必要があります。すべての階段は独立しており、常に 1 から始まるため、この条件が満たされない瞬間に、その境界を越えて有効な階段を生成できる代替セグメンテーションは存在しません。 これにより、各カットが選択されるのではなく強制されるため、貪欲なパーティションは一意に決定され、シーケンスの元の構造と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    res = []
    current_len = 0
    prev = None
    
    for x in a:
        if current_len == 0:
            current_len = 1
        else:
            if x == prev + 1:
                current_len += 1
            else:
                res.append(current_len)
                current_len = 1
        prev = x
    
    res.append(current_len)
    
    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```この実装では、現在の階段の走行長が維持されます。 連続する +1 パターンが途切れると、現在のセグメントが結果リストにプッシュされ、新しいセグメントが始まります。 変数`prev`要素ごとに O(1) 時間で効率的に連続性条件をチェックする必要があります。 

唯一の微妙な点は、終了によって自然にブレーク条件がトリガーされるわけではないため、最終セグメントがループの後に追加されるようにすることです。

 ## 特殊なケース

 主なエッジケースは、シーケンスが頻繁に切り替わる場合です。`1 1 1 1`。 アルゴリズムは、予想される増分との不一致をすべて強制カットとして扱います。 最初の要素で、新しいセグメントが開始されます。 2 番目の要素では、期待値は 2 ですが、1 と表示されるため、最初のセグメントをすぐに閉じて、新しいセグメントを開始します。 これが要素ごとに繰り返され、唯一の有効な解釈と一致する長さ 1 の 4 つのセグメントが生成されます。 

もう一つのケースは、次のような完璧な連続登りです。`1 2 3 4 5`。 ここで、期待値は常に実際の値と一致するため、スキャン中にカットはトリガーされません。 結果は単一のセグメントであり、アルゴリズムはそれを最後に追加するだけで、不一致がないことが単一の階段に対応することを確認します。 

のような混合構造`1 2 3 1 2`境界での正しさを示します。 最初の不一致は 4 番目の要素で発生します。期待値は 4 ですが、1 と表示され、長さ 3 の直後で分割が強制されます。次に 2 番目のセグメントはそのリセット ポイントからきれいに進み、元の構造と一意に一致する最終的なセグメンテーションが生成されます。
