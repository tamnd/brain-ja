 ## 解決策
 ## 問題の理解

 平面内に 3 つの点が与えられますが、それらは任意ではなく、隠れた元の点の三角形を形成する 3 つのセグメントの中点を表します。 

より具体的には、3 つの未知の整数点 A、B、C が存在します。AB、BC、CA の中点が与えられます。 各中間点は整数座標で正確にわかっており、タスクは元の 3 点を復元することです。 

各中点は通常の幾何学的な方法で定義されます。A が (ax, ay) で B が (bx, by) の場合、AB の中点は ((ax + bx)/2, (ay + by)/2) になります。 他の 2 つの側面についても同様です。 

入力ではこれら 3 つの中点座標が任意の順序で提供され、A、B、および C の座標を出力する必要があります。 

重要な制約は、元の点のすべての座標が整数であることが保証されていることです。 これは、すべての中点座標が 2 つの整数の整数算術平均に対応することを直ちに意味します。そのため、中点の各座標は一般に整数または半整数のいずれかですが、この問題では常に整数です。 

境界は小さく、座標はおおよそ ±100 以内であるため、テスト ケースごとに O(1) の算術再構成で十分です。 検索やジオメトリの列挙に関係するものは必要ありません。 

中間点にラベルが付いていると仮定すると、素朴な誤解が生じます。 この問題では、どの中点がどのエッジに対応するかがわかりません。そのため、主な困難はラベルのないシステムを解くことです。 

いくつかのエッジの状況が重要です。 

3 つの中点がすべて同一である場合、たとえばすべてが (0, 0) である場合、すべての元の点は (0, 0) で一致する必要があります。 個別の頂点を想定した不注意な試みは失敗する可能性があります。 

2 つの中点が交換されているか、誤って解釈されている場合、点間で直接ペアリングを試みると、矛盾した頂点や分数の頂点が生成される可能性があります。 たとえば、一貫性を強制せずに任意の中点の差をペアリングすると、無効な非整数の頂点候補が生成されます。 

## アプローチ

 強引な解釈では、与えられた 3 つの点を 6 つの順列すべてでエッジ AB、BC、CA に割り当ててから、毎回 A、B、C を再構築して一貫性をチェックすることになります。 これはすでに小さいですが、概念的には必要以上に重いです。 

重要な観察は、中点方程式が線形システムを形成しているということです。 中点を M_AB、M_BC、M_CA と表すと、次のようになります。 

A + B = 2M_AB

 B + C = 2 M_BC

 C + A = 2 M_CA

 3 つの方程式をすべて加算すると、次のようになります。 

2(A + B + C) = 2(M_AB + M_BC + M_CA)

 それで:

 A + B + C = M_AB + M_BC + M_CA

 合計 S = A + B + C がわかったら、各頂点を分離できます。 

A = S − (B + C) = S − 2 M_BC

 B = S − 2 M_CA

 C = S − 2 M_AB

 これにより、順列検索を行わずに解が完全に決定されます。 残る唯一の問題は、どの中間点がどのペアに対応するかがわからないことです。 したがって、ラベルを正しく割り当てる必要があります。 

ただし、3 つの役割はすべて対称であるため、指定された 3 つの点 (M_AB、M_BC、M_CA) へのすべての割り当てを単純に試行できます。 割り当てごとに、上記の式を使用して A、B、C を計算し、中間点を再計算して一貫性を確認します。 

順列は 6 つしかないため、これは継続的な作業です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート順列 + 再計算 | お(1) | お(1) | 承認済み |
 | 固定ラベルを使用した線形システム | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 3 つの中間点 M1、M2、M3 を読み取ります。 

これらは未知のエッジに対応しますが、順序は想定されません。 
2. これらの点を M_AB、M_BC、M_CA に割り当てるすべての順列を繰り返します。 

これにより、入力が三角形のエッジにマッピングされる可能性のあるすべての方法を確実にカバーできます。 
3. 各割り当てについて、S = M_AB + M_BC + M_CA を座標方向に計算します。 
4. 以下を使用して候補頂点を再構築します。 

A = S − 2 * M_BC

 B = S − 2 * M_CA

C = S − 2 * M_AB

 これは、中点方程式を代数的に解くことから直接得られます。 
5. 次のことを確認して、正確さを検証します。 

中点(A, B) == M_AB

 中点(B, C) == M_BC

 中点(C, A) == M_CA

 このステップにより、間違った順列により、見た目は正しいが間違った再構成が生成されるのを防ぎます。 
6. 有効な構成が見つかったら、A、B、および C を出力します。 

### なぜ効果があるのか

 中点方程式は、中点とエッジの間の対応が固定されると、一意の解を持つ線形システムを定義します。 再構成の式は、これらの方程式の合計と減算から直接得られるため、有効な割り当てによって正確な元の頂点が生成されることが保証されます。 正しいラベル付けは 6 つの順列の中にあるため、アルゴリズムは必ずそのラベル付けに遭遇します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def midpoint(p, q):
    return ((p[0] + q[0]) // 2, (p[1] + q[1]) // 2)

def ok(A, B, C, MAB, MBC, MCA):
    return (midpoint(A, B) == MAB and
            midpoint(B, C) == MBC and
            midpoint(C, A) == MCA)

def solve():
    mids = [tuple(map(int, input().split())) for _ in range(3)]

    from itertools import permutations

    for MAB, MBC, MCA in permutations(mids):
        Sx = MAB[0] + MBC[0] + MCA[0]
        Sy = MAB[1] + MBC[1] + MCA[1]

        A = (Sx - 2 * MBC[0], Sy - 2 * MBC[1])
        B = (Sx - 2 * MCA[0], Sy - 2 * MCA[1])
        C = (Sx - 2 * MAB[0], Sy - 2 * MAB[1])

        if ok(A, B, C, MAB, MBC, MCA):
            print(*A)
            print(*B)
            print(*C)
            return

solve()
```コードは、指定された 3 つの中点座標を読み取り、三角形のエッジへの可能なすべての割り当てを試みます。 割り当てごとに、導出された線形恒等式を使用して頂点が再構築されます。 検証関数は中点を再計算して、再構成された三角形が一貫していることを確認し、誤った順列が受け入れられるのを防ぎます。 

実装の微妙な詳細は、中間点チェックでの整数の除算です。 この問題では元の点の整数座標が保証されているため、再構築された中点は浮動小数点演算なしで正確に一致します。 整数タプルを使用すると、精度の問題が完全に回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from itertools import permutations

    mids = [tuple(map(int, sys.stdin.readline().split())) for _ in range(3)]

    def midpoint(p, q):
        return ((p[0] + q[0]) // 2, (p[1] + q[1]) // 2)

    def ok(A, B, C, MAB, MBC, MCA):
        return (midpoint(A, B) == MAB and
                midpoint(B, C) == MBC and
                midpoint(C, A) == MCA)

    for MAB, MBC, MCA in permutations(mids):
        Sx = MAB[0] + MBC[0] + MCA[0]
        Sy = MAB[1] + MBC[1] + MCA[1]

        A = (Sx - 2 * MBC[0], Sy - 2 * MBC[1])
        B = (Sx - 2 * MCA[0], Sy - 2 * MCA[1])
        C = (Sx - 2 * MAB[0], Sy - 2 * MAB[1])

        if ok(A, B, C, MAB, MBC, MCA):
            return f"{A[0]} {A[1]}\n{B[0]} {B[1]}\n{C[0]} {C[1]}\n"

    return ""

 ## 特殊なケース

 3 つの中点がすべて同一である場合、すべての置換により同じ再構築された頂点が生成され、アルゴリズムはすべての元の点が一致する折りたたまれた三角形を正しく返します。 すべてのペアごとの中点が変更されないため、中点検証ステップは引き続き合格します。 

入力の順序が任意の場合、最初の入力を AB に、2 番目を BC に、3 番目を CA にマッピングすると、矛盾した頂点が静かに生成される可能性があります。 置換ループは、すべてのラベルを明示的にチェックすることでこれを防ぎます。 

座標が負または混合の場合、再構成式での減算により大きな中間値が生成される可能性がありますが、問題の保証により、すべての演算は整数の範囲内に留まります。 中間点の検証により、算術的不一致が即座に拒否されることが保証されます。
