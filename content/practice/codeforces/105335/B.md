 ## 解決策
 ## 問題の理解

 入力は、古いマルチタップ電話キーパッドからの 2 から 9 までの一連の数字です。 各数字は文字のグループに対応し、その数字を連続して複数回押すと文字が生成されます。 たとえば、2 を 1 回押すと 1 つの文字が表示され、2 を 2 回押すとグループ内の次の文字が表示されます。 

記録されたデータに欠けている重要な部分は、文字間の休止部分です。 単語を入力するとき、話者は異なる文字の間で一時停止しますが、記録された文字列はすべてを 1 つの連続したキー入力の流れにマージします。 タスクは、観察されたキー押下ストリームを生成した可能性がある文字シーケンスを復元することです。 

キーパッドは標準の電話マッピングと同様に動作します。2 は abc に、3 は def、4 は ghi、5 は jkl、6 は mno、7 は pqrs、8 は tuv、9 は wxyz にマップされます。 同じ数字を繰り返し押すと、その文字が循環しますが、この問題により、タイピストがキー上の文字数を決して超えないことが保証されるため、ラップアラウンドは発生しません。 

出力は有効なデコードされた文字列ですが、すべての有効な解釈の中で最も短い解釈を優先する必要があり、まだあいまいさがある場合は辞書編集的に最小の解釈を選択する必要があります。 

制約から、入力の長さは最大 200 です。これは、O(n) または O(n log n) までの解は自明であることを意味します。 O(n²) でさえ通過する可能性がありますが、構造は線形スキャンを強く示唆しています。 

単純な解釈では、一時停止を任意に挿入し、文字列のすべてのセグメント化をテストして実行しようとする可能性があります。 すべての数字のペアの間には、壊れるかどうかという二分の一の決定があるため、この値はすぐに指数関数的になります。 長さ 200 の場合、すでに 2¹⁹⁹ の可能性があり、これは実現不可能です。 

さらに微妙な間違いは、1 つの数字が常に 1 つの文字に対応すると想定していることです。 これは、数字が繰り返される場合など、マッピング内の後の文字に到達するために複数回押す必要がある場合には失敗します。 

数字が何度も繰り返される場合、エッジケースが発生します。 たとえば、7777 のようなセグメントは、7 の完全なマッピングを使用して 4 文字の単語にマッピングする必要があります。もう 1 つのケースは、2323 のような交互の数字で、数字が変更されるたびに新しい文字の境界が強制されます。 

## アプローチ

 この強引なアイデアは、数字列をセグメントに分割するあらゆる可能な方法を検討することであり、各セグメントは 1 つのキーの繰り返しの押下を表します。 セグメント化ごとに、長さと対応するキーパッド マッピングに基づいて、すべてのセグメントを文字に変換します。 これが機能するのは、明示的に一時停止して入力プロセスを直接シミュレートするためです。 

失敗点は組み合わせ爆発です。 長さ n の文字列の場合、n−1 個のギャップがあり、各ギャップは分割である場合とそうでない場合があります。 これにより、2^(n−1) 個のセグメント化が行われます。 n = 50 の場合でも、これはすでに大きすぎるため、制約により最大 200 が許容されます。 

重要な観察は、一度型付けモデルを強制すると、有効な解釈において一時停止が恣意的ではなくなるということです。 同じ数字が連続して繰り返される場合、それらのキーは同じ文字に属している必要があります。 一時停止は、桁が変更された場合にのみ発生します。そうでない場合は、同じキーを押し続けている間にリセットを意味し、押し続ける解釈と矛盾するためです。 これにより、一意のセグメンテーション、つまり同一の数字の最大の連続ブロックが強制されます。 

文字列がランに分割されると、その長さをキーが押された回数として解釈することにより、各ランが独立して正確に 1 つの文字にマップされます。 

したがって、余分な分割を導入しても文字数が増えるだけであるため、この最大実行解釈によって可能な限り最短の出力が常に実現されます。 有効性を維持する代替のセグメント化がないため、辞書編集上の最小値も固定されます。

 ## アルゴリズムのチュートリアル

 文字列を 1 パスで処理し、連続する同一の数字をブロックにグループ化します。 

1. 現在の桁とその連続の長さを維持しながら、文字列を左から右にスキャンします。 これは、数字の変更が新しい文字の唯一の有効な境界であるため、最大の連続する同一の数字をグループ化します。 
2. 長さ k の完成した数字 d のそれぞれについて、位置 k を使用して d のマッピングにインデックスを付けることによって、それを文字に変換します。 これは、キーを k 回押すことを直接シミュレートします。 
3. 結果の文字を出力文字列に追加します。 
4. 文字列全体が処理されるまで続行し、最後の実行も確実に変換されます。 

この正確性は、各実行が同じボタンを連続して中断なく押すキー操作に対応しているという事実から得られます。 この問題ではキーの文字数を超えてオーバーフローしないことが保証されているため、各ランレングスは常に曖昧さなく有効な文字にマップされます。 

### なぜ効果があるのか

 重要な不変条件は、スキャンのすべての点で、現在の実行が元の入力プロセスの 1 文字だけを表すということです。 ラン内で分割しようとすると、同じキーを押したまま一時停止が挿入されることになり、別の文字を生成できず、出力の文字数が増えるだけです。 したがって、最大ラン分解により、最小長の有効なデコードが生成されます。 各実行は決定論的に 1 つの文字にマッピングされるため、代替のデコードでは辞書編集的に小さいまたは短い文字列を生成することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

KEYS = {
    '2': "abc",
    '3': "def",
    '4': "ghi",
    '5': "jkl",
    '6': "mno",
    '7': "pqrs",
    '8': "tuv",
    '9': "wxyz"
}

def solve():
    s = input().strip()
    n = len(s)
    
    res = []
    i = 0
    
    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1
        
        digit = s[i]
        length = j - i
        
        res.append(KEYS[digit][length - 1])
        
        i = j
    
    print("".join(res))

if __name__ == "__main__":
    solve()
```実装は実行分解を直接反映します。 内側のループは、同一の数字の各最大ブロックを展開します。 表現`length - 1`キーパッド文字列へのインデックス付けは 0 から始まり、押された回数は 1 から始まるため、これは非常に重要です。 

よくある間違いは、桁が変わったときに適切にリセットせずにカウントを蓄積しようとすることです。 ポインターベースのアプローチでは、次のセグメントを開始する前に各セグメントを明示的に閉じることでこれを回避します。

 ## 特殊なケース

 重要なエッジ ケースは、連続する数字がそのキーパッド グループの長さと正確に一致する場合です。 4 つの文字にマップされる数字 7 の場合、7777 のような入力は最後の文字「s」にマップされる必要があります。 ランレングスはマッピングへのインデックスとして直接使用されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つの特殊なケースは、1 桁の入力です。 実行は 1 回だけであるため、アルゴリズムはそのキーのマッピングの最初の文字をすぐに返し、境界ロジックはトリガーされません。 

232323 などの交互の数字は、複数の単一長のランを形成します。 各実行は独立して処理されるため、桁変更時に誤ってマージが発生することはありません。
