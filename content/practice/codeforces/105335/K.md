 ## 解決策
 ## 問題の理解

 地図は`N × M`格子点のグリッド。 各ポイントには次のようなスコアがあります。`0`そして`9`。 

アリスは左上隅から開始します`(1,1)`そしてボブは右上隅から開始します`(1,M)`。 移動は厳密に大きな行番号に進む必要があり、すべての移動は直線セグメントになります。 パスのスコアは、そのパスが訪問するすべての格子点の合計です。 

2 つのパスが交差することはできません。 どちらの子供もいつでも立ち止まってラリーを終えることができます。 

最終的な答えは、$$(\text{Alice score}) \times (\text{Bob score})$$そして可能な限り最大の値が必要です。 

グリッドの寸法は最大でも`1000 × 1000`, ただし、すべてのセル値は 1 桁のみです。 この小さなスコア範囲が重要な観察結果であることがわかります。 

最初の幾何学的事実は、最適なパスが行を飛び越えることは決してないということです。 パスが行から移動する場合`r`直接漕ぐ`r+2`、すべてのスコアは負ではないため、行に中間点を挿入します。`r+1`スコアを上げることしかできません。 コンテストのチュートリアルでは、最適解では行座標が移動するたびにちょうど 1 ずつ増加することが明示されています。 

両方のプレーヤーがまだ移動している場合、プレーヤーはすべての列に表示され、アリスはその列のボブの左側に厳密に留まらなければなりません。 

1 人のプレイヤーが早めにストップした場合、微妙なエッジケースが発生します。 

考慮する```
2 2
9 1
9 0
```両方とも 2 行目まで続く場合、最良の製品は次のとおりです。`18 × 1 = 18`。 

より良い解決策は、アリスがすぐに停止することです。 アリスはスコアを記録します`9`、ボブが移動する間、`(2,1)`そして得ます`1 + 9 = 10`。 答えは次のようになります`90`。 公式チュートリアルではまさにこの状況を指摘しています。 

両方のプレイヤーが常に列まで続行することを前提としたソリューション`N`このテストでは失敗します。 

## アプローチ

 強引な定式化は説明するのが簡単です。 すべての行について、アリスが左側になるようにアリスの列とボブの列を選択します。 次に、両方のスコアを計算して積を最大化します。 

問題は、各行がおおよそ`M²`可能性。 と`N,M ≤ 1000`、構成の数は天文学的に多くなります。 

重要な観察は、アリスの列が連続してわかったら、ボブは厳密にその右側の最良の値のみを気にするということです。 

行を処理しているとします。`r`。 

アリスがコラムをとったら`i`、彼女は得をする$$S[r][i]$$ボブは右側の最適な列を選択でき、$$\max_{j>i} S[r][j].$$この行にはペアのみが必要です$$(a,b).$$すべてのセル値が間にあるため、`0`そして`9`、 両方`a`そして`b`は数字です。 

固定アリスゲインの場合`a`、達成可能な最大のボブゲインのみが重要です。 つまり、各行は、各桁に 1 つずつ、最大 10 個の有用な遷移を提供します。`0..9`。 

次に合計スコアを見てみましょう。 

開始セルを超えたアリスの追加スコアは最大で$$9(N-1) \le 8991.$$つまり、状態がアリスの累積スコアであるナップザック スタイルの DP を実行できます。 

させて$$dp[x]$$両方のプレイヤーがまだアクティブで、アリスが追加スコアを蓄積している間に取得できる最大のボブ スコアになります。`x`。 

状態空間は約`9000`、十分小さいです。 

残りの合併症は早期停止です。 行の一部のプレフィックスを処理した後、アリスが停止してボブが制限されなくなる場合や、ボブが停止してアリスが制限されなくなる場合があります。 すべての行境界で両方の可能性を評価します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | アリスのスコアのDP | O(N・9000) | O(9000) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取ります。 
2. しましょう`baseA = S[1][1]`そして`baseB = S[1][M]`。 
3. 行ごとに`r ≥ 2`、次を計算します。`rowMax[r]`= その行の最大値。 

すべての桁について`a`から`0`に`9`、計算する`best[a] = max value to the right of some column whose value equals a`。 

これは、両方のプレーヤーがまだアクティブである間のすべての有用なトランジションを表します。 
4. サフィックス配列を構築する$$suf[r] = \sum_{k=r}^{N} rowMax[k]$$これは、他のプレイヤーが停止した後、唯一残ったプレイヤーがまだ何ポイントを獲得できるかを示します。 
5.初期化```
dp[0] = 0
```他のすべての状態は不可能です。 
6. 行の処理前`r`、行の後に停止して評価します`r-1`。 

アリスが立ち止まると:```
Alice = baseA + x
Bob   = baseB + dp[x] + suf[r]
```ボブが止まったら:```
Alice = baseA + x + suf[r]
Bob   = baseB + dp[x]
```両方の製品の回答を更新します。 
7. プロセス行`r`。 

到達可能なすべての状態について`x`およびすべての有効な数字の遷移`(a,b)`その行から:```
ndp[x + a] =
    max(ndp[x + a], dp[x] + b)
```8. 交換する`dp`と`ndp`そして続けます。 
9. すべての行が処理された後、両方のプレーヤーが最後の行までアクティブなままである場合を評価します。```
(baseA + x) * (baseB + dp[x])
```10. 最大積を出力します。 

### なぜ効果があるのか

 両プレイヤーが移動している間、各列は独立して貢献します。 

アリスが値を持つ列を選択した場合`a`, 同じ行におけるボブの最適な選択は、厳密に右側の最適な値にのみ依存します。 行に関するその他の情報は重要ではありません。 

DP には、考えられるすべてのアリスの合計スコアと、それに対応する最大のボブ スコアが保存されます。 今後の行は累積合計にのみ依存するため、この状態で十分です。 

1 人のプレーヤーが停止すると、残りのプレーヤーは制約がなくなり、残りのすべての行から独立して最大値を取得できます。 接尾辞の合計は、将来の利益を正確に表します。 

DP は、実行可能なすべてのアクティブ プレフィックス構成とすべての可能な停止位置を調査して、最大の積を見つけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [list(map(int, input().split())) for _ in range(n)]

    baseA = g[0][0]
    baseB = g[0][m - 1]

    row_max = [0] * n
    row_opts = []

    for r in range(1, n):
        row = g[r]
        row_max[r] = max(row)

        suf_right = [-1] * m
        cur = -1
        for c in range(m - 1, -1, -1):
            suf_right[c] = cur
            cur = max(cur, row[c])

        best = [-1] * 10

        for c in range(m - 1):
            a = row[c]
            b = suf_right[c]
            if b >= 0:
                best[a] = max(best[a], b)

        opts = []
        for a in range(10):
            if best[a] >= 0:
                opts.append((a, best[a]))

        row_opts.append(opts)

    suf = [0] * (n + 2)
    for r in range(n - 1, 0, -1):
        suf[r] = suf[r + 1] + row_max[r]

    MAXS = 9 * (n - 1)

    NEG = -10**18
    dp = [NEG] * (MAXS + 1)
    dp[0] = 0

    ans = baseA * baseB

    for idx in range(n - 1):
        r = idx + 2

        rem = suf[r]

        for x in range(MAXS + 1):
            if dp[x] == NEG:
                continue

            bob_now = dp[x]

            ans = max(
                ans,
                (baseA + x) * (baseB + bob_now + rem)
            )

            ans = max(
                ans,
                (baseA + x + rem) * (baseB + bob_now)
            )

        ndp = [NEG] * (MAXS + 1)

        for x in range(MAXS + 1):
            if dp[x] == NEG:
                continue

            cur_b = dp[x]

            for a, b in row_opts[idx]:
                nx = x + a
                if cur_b + b > ndp[nx]:
                    ndp[nx] = cur_b + b

        dp = ndp

    for x in range(MAXS + 1):
        if dp[x] == NEG:
            continue

        ans = max(
            ans,
            (baseA + x) * (baseB + dp[x])
        )

    print(ans)

solve()
```グリッドを読み取った後、コードは各行を前処理してコンパクトな遷移セットを作成します。 すべての桁について`a`、アリスがゲインする間、ボブは最大のゲインのみが達成可能です`a`保管されています。 これはまさに、行ごとの作業を軽減する圧縮です。`O(M²)`最大 10 個の遷移の可能性があります。 

DP 配列には、アリスの累積スコアによってインデックスが付けられます。 すべてのスコアは数字であるため、最大のインデックスは次のとおりです。`9(N-1)`。 

サフィックス配列は早期停止の場合を処理します。 アリスまたはボブが停止すると、他のプレイヤーは残りの各行の最大値を自由に収集できるため、単純なサフィックスの合計で十分です。 

最も一般的な実装上の間違いは、最後の行の前で停止するケースを忘れることです。 公式チュートリアルの`2 × 2`この例が存在するのは、最適化では 1 人のプレイヤーがすぐに停止する必要があるためです。

    input = data.readline

    g = [list(map(int, input().split())) for _ in range(n)]

    baseB = g[0][m - 1]

    row_opts = []

    for r in range(1, n):
        row = g[r]
        row_max[r] = max(row)

            a = row[c]
            b = suf_right[c]
            if b >= 0:

        opts = []
        for a in range(10):
            if best[a] >= 0:
                opts.append((a, best[a]))

        row_opts.append(opts)

    suf = [0] * (n + 2)
    for r in range(n - 1, 0, -1):

        rem = suf[r]

            if dp[x] == NEG:

            ans = max(ans, (baseA + x) * (baseB + dp[x] + rem))

        if dp[x] != NEG:

    return str(ans) + "\n"

 ## 特殊なケース

 もう一度考えてみましょう:```
2 2
9 1
9 0
```初期状態:```
Alice = 9
Bob = 1
```行 2 が処理される前に、アルゴリズムは停止を評価します。 

残りの最大行サフィックスは次のとおりです。```
9
```アリスが停止すると、次の結果が得られます。```
9 × (1 + 9) = 90
```それが現在の答えになります。 

続行する場合の DP 遷移では、以下のみが生成されます。```
18 × 1 = 18
```最終的な答えは残っています`90`。 

次に、次のことを考えてみましょう。```
2 2
0 0
0 0
```すべての遷移の寄与はゼロです。 DP には到達可能な状態が 1 つだけ含まれており、すべての停止評価でもゼロが生成されます。 アルゴリズムの出力`0`、それは正しいです。 

最後に次のことを考慮してください。```
3 2
9 9
9 9
9 9
```唯一可能な順序は、列 1 にアリス、列 2 にボブです。両方とも 3 行すべてを収集します。```
27 × 27 = 729
```どちらかが早く止まると製品が小さくなります。 DP は継続と停止の両方を評価し、正しい最大値を維持します。
