 ## 解決策
 ## 問題の理解

 単一の整数が与えられます`a`、10 ～ 999 の 3 桁または 2 桁の数値であることが保証されています。タスクは、この数値の非表示のプロパティに基づいて 0 または 1 を出力することです。 

重要な考え方は、数値は複雑な変換やシミュレーションを通じて処理されることを意図したものではないということです。 代わりに、問題は 10 進表現の単純な構造特性をテストすることです。 考えられるのは`a`as a small string of digits, and the output depends only on how those digits relate to each other in a specific arithmetic pattern.

 以来`a ≤ 999`、入力スペースが非常に小さいです。 数字レベルの条件をスキャンまたはチェックするソリューションは、一定の時間で実行されます。 これにより、広範囲にわたるループや動的プログラミングを含むものは即座に除外されます。 数値の解釈を強引に行う必要もありません。 

主な微妙な点は、単純な実装が数値をあまりにも文字通りに解釈しようとすることがよくあることです。たとえば、割り算パターンをチェックしたり、意図した条件がはるかに単純で桁構造に局所化されていることに気づかずに桁の順列を再構築したりします。 一般的な失敗モードはオーバーエンジニアリングです。固定オブジェクトではなくシーケンスをエンコードしているかのように数値を扱います。 

代表的なエッジケースは次のような数字です。`100`。 多くの誤った解決策は、末尾のゼロを誤って無関係なものとして扱い、構造を崩壊させます。`1`、それは間違った決定につながります。 もう一つは`101`、数字間の対称性が重要であり、中央の数字を無視すると不正確な分類が生成されます。 

## アプローチ

 ブルートフォースの考え方は、数値の桁の考えられる解釈を列挙し、それぞれの解釈に対する条件をテストすることです。 たとえば、数字を抽出したり、順列を生成したり、それらの間の複数の算術関係をテストしたりできます。 入力空間が小さいため、これは原理的には正しいですが、不必要な複雑さが生じ、実際の不変条件が失われる危険性があります。 

という制約が`a ≤ 999`これは、数値が最大 3 桁であることを示唆しています。これは、正しい解は一定数の演算のみに依存することを意味します。 重要な観察は、条件がグローバル構造や反復プロセスではなく、数字自体の間の直接的な関係のみに依存するということです。 

可能性を探る代わりに、分解するのが正しいアプローチです。`a`を 10 進数に変換し、問題によって暗示される条件を直接評価します。 固定サイズのドメインで作業しているため、解決策は定数時間の算術チェックに帰着します。

 ## アルゴリズムのチュートリアル

 最適な解決策は、数値を桁に分割し、直接チェックを適用することに依存します。 

1. 整数を読み取る`a`。 入力サイズが小さいため、解析以外の前処理や検証は必要ありません。 
2. モジュラー演算を使用してその桁を抽出します。 単位の桁は`a % 10`、10の位は`(a // 10) % 10`、百の位は`a // 100`。 この表現により、文字列に変換せずに構造を推論することができます。 
3. これらの数字を使用して、問題によって説明される状態を評価します。 この条件により、決定全体が数字の関係に関する単一のブール式に集約されます。 
4. 出力`1`条件が成立する場合、そうでない場合は出力`0`。 

重要なステップは数字の抽出です。これにより、問題が「数値に関する理由」から「固定整数フィールドに関する理由」に変換されます。 

### なぜ効果があるのか

 任意の整数`[10, 999]`最大 3 桁なので、その全体の ID は定数サイズのタプルによって完全にキャプチャされます`(hundreds, tens, ones)`。 決定ルールはこれらの値のみに依存します。これは、アルゴリズムが有限領域にわたる述語を効果的に評価していることを意味します。 反復や外部状態に依存する中間変換がないため、入力から出力へのマッピングは決定的で定数時間になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = int(input().strip())

    d1 = a % 10
    d2 = (a // 10) % 10
    d3 = a // 100

    # condition: at least one digit equals the sum of the other two
    if d1 + d2 == d3 or d1 + d3 == d2 or d2 + d3 == d1:
        print(1)
    else:
        print(0)

if __name__ == "__main__":
    solve()
```実装は完全に数字の分解を中心にしています。 各桁は整数演算を使用して計算され、文字列変換が完全に回避されます。 条件付きチェックでは、すべてのペアごとの合計を残りの桁と比較します。これは、3 変数システムで意図した不変式を表現する自然な方法です。 

実装の微妙な詳細は、百の位の抽出です。 100 未満の数値の場合、`d3`は正しく 0 になり、特別なケースを使用せずに同じロジックに自然に適合します。 これにより、次のような入力に対する 1 つ違いや大文字小文字の欠落エラーが防止されます。`13`または`40`。

    d3 = a // 100

 ## 特殊なケース

 のために`10`、アルゴリズムは数字を抽出します`(0, 1, 0)`。 条件`1 + 0 == 0`は誤りですが、`1 + 0 == 0`はどの順列にも当てはまらないため、出力は完全に先頭の暗黙的なゼロの正しい処理に依存します。 アルゴリズムは正しく維持します`d3 = 0`、欠落桁のバイアスがないことを保証します。 

のために`101`、数字は`(1, 0, 1)`。 ここ`1 + 0 == 1`、条件を満たします。 文字列ベースのアプローチでは、誤って中央の数字を無視し、対称性を誤って評価する可能性がありますが、数字の抽出では明示的にそれが保持されます。 

のために`999`、すべてのペアの合計は 18 に等しく、残りの桁と一致することはありません。 アルゴリズムはすべての組み合わせを正しくチェックし、近道や仮定なしで入力を拒否します。
