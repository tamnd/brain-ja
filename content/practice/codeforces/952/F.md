 ## 解決策
 ## 問題の理解

 入力は、負でない小さな整数と、加算と減算の 2 つの演算のみを含む短い算術式です。 通常の中置記法を超える括弧、乗算、および隠れた書式設定規則はありません。 

タスクは、抽象的な意味で数学的に正しい値を計算することではなく、既知のバグのあるリファレンス実装が同じ式に対して出力するものを正確に再現することです。 これは、元の評価者が式を処理する方法を事実上リバース エンジニアリングしていることを意味します。 

オペランドの数は最大 10 で、各オペランドは最大 255 であるため、式の長さは非常に小さくなります。 文字列を 1 回または数回スキャンするソリューションであれば、すでに十分です。 二次関数の動作でさえ無関係ですが、構造は単一の線形パスが意図された方向であることを示唆しています。 

ここでの単純な間違いは、標準の演算子の優先順位ルールを仮定したり、完全な式パーサーを実装しようとしたりすることです。 これでも正しい数学的結果が得られますが、優先順位を無視したり、トークンを異なる方法で処理したりすると、バグのある評価器と一致しない可能性があります。 

微妙な失敗例の 1 つは、式を一般的な算術文法として解釈することに起因します。 たとえば、操車場またはスタックの評価が必要なものとして扱うことは不必要な複雑さであり、誤って実装された場合、意図したモデルには存在しない優先順位のバグが簡単に発生する可能性があります。 

もう 1 つのエッジ ケースは、負の値を考えすぎることです。 オペランドは 0 ～ 255 であることが保証されており、単項マイナスがないため、すべての数値は常にスタンドアロン トークンであるため、解析では数値、演算子、数値などの厳密な交互パターンを安全に想定できます。 

## アプローチ

 ブルート フォース解釈では、式を完全に解析してトークンにし、標準の式エバリュエーターを使用して評価します。 これには通常、後置表記に変換するか、値と演算子に 2 つのスタックを使用する必要があります。 これは一般的な算術式では正しいですが、ここでは不要な機構が導入されています。 オーバーヘッドは概念的には O(n) ですが、大きな定数係数があり、さらに重要なことに、優先順位ルールが誤って処理されると、実際の評価順序から逸脱する危険性があります。 

重要な点は、式には、意図した評価モデルで同じ優先順位を持つ演算子が 2 つだけ含まれているということです。 式は短く、すべてのオペランドが演算子で明示的に区切られているため、トークンが左から右に折り畳まれることが強く示唆されます。 これにより、アキュムレータを維持し、各演算を表示どおりに適用するという問題が軽減されます。 

参照ソリューションの「バグ」は、優先順位を考慮せずに式を厳密に左から右に扱うことと一致しており、これはこの文法にとって最も単純なインタプリタでもあります。

 ## アルゴリズムのチュートリアル

 式を一連の数値と演算子として処理し、常に次の演算を即座に累計に適用します。

1. 文字列から最初の数値を読み取り、それを結果の初期値として設定します。 これにより、折り曲げの開始点が確立されます。 
2. 文字列を左から右にスキャンします。 演算子に遭遇するたびに、次のトークンが数字であることがわかります。 
3. 次の整数を完全に解析します (複数の桁がある場合があります)。 これにより、数字を個別に処理するのではなく、オペランド全体が正しく消費されることが保証されます。 
4. 演算子を実行結果に直ちに適用します。 演算子が「+」の場合は、数値を加算します。 「-」の場合は減算します。 
5. 文字列の終わりに達するまで続けます。 その時点で、アキュムレータは参照評価器によって生成された最終値を保持します。 

### なぜ効果があるのか

 正確さは入力の構造によって決まります。すべての演算子は 2 つの完全なオペランドを直接接続しており、意図した評価モデルではどの演算子も他の演算子よりも高い優先順位を持ちません。 バグのある実装では評価は厳密に逐次的に行われるため、単一の実行中のアキュムレータを維持すると、まったく同じ中間状態が保存されます。 すべてのステップで、アキュムレータは式のプレフィックスを処理した後の参照解の値と等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    
    i = 0
    
    # read first number
    cur = 0
    while i < n and s[i].isdigit():
        cur = cur * 10 + (ord(s[i]) - 48)
        i += 1
    
    # process remaining operators and numbers
    while i < n:
        op = s[i]
        i += 1
        
        num = 0
        while i < n and s[i].isdigit():
            num = num * 10 + (ord(s[i]) - 48)
            i += 1
        
        if op == '+':
            cur += num
        else:
            cur -= num
    
    print(cur)

if __name__ == "__main__":
    solve()
```解決策は単一のリニア スキャンです。 最初のループは初期オペランドを分離し、演算が適用される前にアキュムレータが正しく初期化されるようにします。 2 番目のループでは、演算子の読み取りと次の数値の解析を交互に行い、式の構造を厳密に遵守します。 

解析では、代わりに手動の数字の累積を使用します。`split`これにより、書式設定に関する特殊なケースが回避され、トークン境界を完全に制御できます。

## 特殊なケース

 最初のエッジ ケースは、ゼロで始まる 1 桁の式です。 例えば、`0+0`。 このアルゴリズムはアキュムレータを最初の数値から直接初期化するため、特別なケースを必要とせずにゼロを正しく処理します。 

2 番目のエッジ ケースには、次のような最大値のオペランドが含まれます。`255-255+255`。 解析ループは、Python でのオーバーフローを心配することなく数字を安全に整数に累積し、各操作が即座に適用されるため、中間値は正しいままになります。 

3 番目のエッジ ケースは、次のような長い交互減算チェーンです。`1-2-3-4-5`。 アルゴリズムは減算を順番に繰り返し適用し、参照エバリュエーターの左から右への動作と正確に一致させます。 各中間結果はアキュムレータに保存されるため、優先順位の曖昧さは生じません。
