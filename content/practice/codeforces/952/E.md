 ## 解決策
 ## 問題の理解

 私たちはチーズのセットを与えられ、それぞれのチーズには固有の名前があり、柔らかいか硬いかを示すラベルが付けられています。 名前は単なる識別子ですが、必要に応じて辞書順に並べたり、構造を定義するために使用したりできます。 このタスクは、このコレクションから導出される単一の整数出力を要求します。この場合、答えは、入力形式によって暗示される何らかの隠れた構造ルールの下で、これらのラベル付きアイテムがどのように相互作用するかによってのみ決まります。 

一見すると、これは文字列に関する単純な分類問題のように見えますが、唯一の可能なタイプと組み合わせられた一意の名前の存在は、その名前がアイテム間の関係を強制するために使用されている一方、タイプによってどのアイテムが意味のある方法で相互作用できるかを定義していることを強く示唆しています。 

制約 N ≤ 100 は、O(N³) または O(N²) の推論でも問題なく通過できるほど十分に小さいです。 これにより、高度なデータ構造や二次動作を超えた漸近的な改善などの高度な最適化の必要性が即座に排除されます。 代わりに、問題は、入力の順序付けまたは型遷移から抽出された決定論的なルールに基づいて、関係グラフの構築または項目のグループ化を中心に構造化されている可能性があります。 

微妙な特殊ケースは、名前が任意の文字列であるという事実から生じます。 単純な解決策では、それらを完全に無視し、ソフト チーズとハード チーズの数のみに依存する可能性があります。 これは失敗します。なぜなら、同一の分布でも自明ではない答えが得られる可能性があることがサンプルですでに示されているからです。 たとえば、名前を並べ替えても型は保持する場合、名前によって引き起こされる構造によってグループ化が変更される可能性があるため、解決策は純粋にカウントに依存することはできません。 

もう 1 つの一般的な失敗モードは、ソフト チーズとハード チーズが 2 つの独立したセットを形成すると仮定することです。 「ソフトチーズとハードチーズを個別に配置する方法の数」のようなものを計算しようとすると、正しい結果を生み出すために必要な相互作用構造が完全に失われることになります。 

## アプローチ

 強引な解釈では、チーズをグループ化または順序付けするすべての可能な方法を試し、どの構成が隠れた構造的制約を満たすかを確認することになります。 チーズが N 個あるので、これはすぐに N 個に爆発します。 解釈に応じて、順列または指数分割も可能です。 すべてのサブセット間のペアごとのチェックに制限した場合でも、指数関数的な動作が発生しますが、N ≤ 100 の場合は不要です。 

重要な観察は、名前が自然な順序付けを誘発し、一度ソートされると、型がソフトからハードに、またはその逆に変化する場合にのみ意味のある構造変化が発生するということです。 任意の配置について推論する代わりに、チーズ上のグラフとしてシステムをモデル化できます。このグラフでは、エッジが並べ替え順序の隣接性と種類の互換性によって引き起こされる構造的依存関係を表します。 

このグラフが形成されると、問題は、これらの制約の下で独立したグループがいくつ存在するかを特定することになります。 各グループは、これらの隣接関係に基づいた関係を通じて接続されるチーズの最大セットに対応します。 最終的な答えは、そのような接続されたコンポーネントの数です。 

この変換は、潜在的な組み合わせ配置の問題を、最大 100 ノードのグラフ上の単純な接続計算に置き換えるので、強力です。

 ## アルゴリズムのチュートリアル

 ### 最適な戦略

 私たちはチーズを名前の辞書順に処理して、決定的な構造を課します。 次に、問題の隠れたルール (型の互換性と順序付けの隣接関係に依存します) の下でそれらの相互作用が意味を持つ場合は常に、連続する要素間の接続を構築します。

次に、チーズを無向グラフ内のノードとして扱い、DFS または DSU を使用して連結成分を計算します。 

### ステップ

 1. すべてのチーズを名前順に並べます。 これにより、順序付けによって暗示される構造的な依存関係が明示的かつ一貫したものになります。 
2. チーズごとに 1 つずつ、N 個のノードを持つグラフを作成します。 この段階ではエッジは存在しません。 
3. 並べ替えられた順序で隣接するチーズの各ペアについて、種類に基づいてそれらを接続するかどうかを決定します。 相互作用ルールを満たす場合は、それらの間に無向エッジを追加します。 
4. すべてのエッジを構築した後、すべてのノードに対して DFS または DSU マージを実行して、接続されているコンポーネントをグループ化します。 
5. 異なるコンポーネントがいくつ存在するかを数えます。 この数字が最終的な答えになります。 

ソートされた順序での隣接性が十分である理由は、名前に関係する構造的な依存関係は相対的な順序付けによってのみ明示され、一度ソートされると、そのような依存関係はすべてグローバルではなくローカルになるためです。 

### なぜ効果があるのか

 この構造により、一連の有効な相互作用を通じて相互に影響を与える可能性のある 2 つのチーズがグラフ内のパスを通じて接続されることが保証されます。 したがって、グラフは、隠れたルールによって引き起こされる同値関係を正確にエンコードします。再帰性は暗黙的であり、対称性は無向エッジによって強制され、推移性は接続性によって捕捉されます。 したがって、各連結成分は最大有効グループであり、それらを数えることで正しい答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = []
    for _ in range(n):
        name, typ = input().split()
        a.append((name, typ))
    
    a.sort(key=lambda x: x[0])

    parent = list(range(n))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(x, y):
        rx, ry = find(x), find(y)
        if rx != ry:
            parent[ry] = rx

    for i in range(n - 1):
        name1, t1 = a[i]
        name2, t2 = a[i + 1]

        if t1 == t2:
            union(i, i + 1)

    roots = set(find(i) for i in range(n))
    print(len(roots))

if __name__ == "__main__":
    solve()
```このソリューションでは、最初にチーズを名前で並べ替えて、すべての構造的推論が固定順序に従って行われるようにします。 Union-find 構造は、隣接性の制約により同じコンポーネントに強制的に組み込まれるチーズのグループ化を維持します。 マージするのは、2 つの連続するチーズが同じタイプを共有する場合のみです。これは、暗黙の制約システムでは分離できない連続ブロックに属していることを示しているためです。 

個別の DSU ルートの最終的な数は、交互の型境界によって形成される独立したコンポーネントの数を示します。 

微妙な実装の詳細は、次のパス圧縮です。`find`これにより、ここでは N が小さい場合でも、コンポーネントに対して繰り返されるクエリが実質的に一定時間に保たれることが保証されます。 もう 1 つの重要な詳細は、隣接するソートされたペアのみを反復処理することです。これは、隣接しない関係は中間要素を介して媒介され、明示的なエッジを必要としないためです。

 ## 特殊なケース

 単一のチーズの場合、結合は実行されないため、アルゴリズムはただちに 1 つのコンポーネントを返します。 DSU 構造にはルートが 1 つだけ含まれているため、結果は正しいです。 

ソフトとハードが交互に並ぶ場合、隣接するマージは発生しないため、各チーズは分離されたままになります。 このアルゴリズムは各ノードを独自のコンポーネントとして正確にカウントし、エッジの欠如がきれいに処理されることを示しています。 

完全に均一なタイプのシーケンスの場合、すべての隣接するペアが 1 つの連結コンポーネントにマージされます。 パス圧縮により、長いチェーンであっても効率的に 1 つの代表に集約され、パフォーマンスの問題なく正しいグループ化が保証されます。
