 ## 解決策

 ## 問題の理解

 非常に小さな正の整数の配列が与えられ、各値は「ラビオリ」部分の垂直方向の積み重ねとして想像されます。 スタックは配列と同じ順序で一列に配置されます。 

このプロセスは、相互作用する 2 つの方法でこの行を繰り返し変更します。 まず、隣接する 2 つのスタックの高さが少なくとも 2 異なる場合は常に、高さの 1 単位が高い方のスタックから低い方のスタックに「スライド」します。 これは、隣接するペアが 1 を超える差がなくなるまで繰り返し発生します。 この平滑化が安定したら、最も高いスタックを特定し (同点の場合は左端を選択)、それを削除し、その高さを記録します。 残りのスタックは一緒に移動し、すべてが削除されるまで同じプロセスが繰り返されます。 

最終出力は、削除された一連の高さです。 タスクは、このシーケンスが常に非降順でソートされるかどうか、つまりアルゴリズムが事実上正しいソート手順のように動作するかどうかを判断することです。 

制約は非常に小さく、要素数は最大 10 個、値は最大 100 です。これにより、通常の意味での漸近効率に関する懸念がなくなりました。 内部ダイナミクスが迅速に収束する限り、3 次以上のシミュレーションでも許容されます。 本当の課題はパフォーマンスではなく、再分配プロセスと最大値の繰り返し抽出を忠実にモデル化することです。 

素朴な間違いは、このプロセスを単に「最大の要素を繰り返し取得する」と解釈することです。 これは再配布ルールを完全に無視します。 

たとえば、次のことを考えてみましょう。```
1
3
```平滑化後は平滑化するものが何もないので、3 を出力します。これは簡単です。 

ただし、次の場合:```
2
1 3
```差は 2 なので、1 つのユニットが 3 から 1 にスライドし、配列になります。`[2, 2]`。 これで両方のスタックが等しくなり、最大値を取り除くと 2 が生成されます。出力は次のようになります。`[2, 2]`、 ない`[1, 3]`または`[3, 1]`。 単純な「並べ替えチェック」では、この再配布効果を完全に見逃してしまいます。 

もう 1 つの微妙な失敗例は、平滑化によって将来の最大値が変更されるときに発生します。 構造は各抽出の前に進化するため、すべての中間状態を正しくシミュレートしない限り、元の並べ替えられた配列と比較するだけでは十分ではありません。 

## アプローチ

 ブルートフォース解釈は、物理プロセスを直接シミュレートします。 2つのフェーズを繰り返し実行します。 まず、配列を「緩和」します。隣接するペアをスキャンし、隣接するユニットを少なくとも 2 上回るユニットをスタックから 1 つ移動します。 安定するまでこれを何度も繰り返す必要がある場合があります。 次に、最大要素を削除して続行します。 

各緩和ステップではエッジを越えて高さ 1 単位しか移動せず、合計の高さは全体で最大 1000 に制限されるため、システムは有限回数の移動後に安定する必要があります。 最大で 10 のポジションを使用すると、各動作で不均衡が軽減されるため、リラクゼーション操作の総数は管理可能なままになります。 

重要な点は、巧妙なデータ構造は必要ないということです。 システム全体は十分小さいため、安定化と繰り返しの削除を直接シミュレーションするだけで十分です。 この構造は局所拡散プロセスのように動作し、最終的な答えは、この拡散駆動の最大値シーケンスがソートされたシーケンスと一致するかどうかによってのみ決まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n · A · ステップ) | O(n) | 承認済み |
 | 最適なシミュレーション (同じ考え方、慎重な実装) | O(n · A · ステップ) | O(n) | 承認済み |

 ここで、「ステップ」は小さくなります。これは、各ユニットの動きが制限された不均衡を軽減し、n と A の両方が小さいためです。 

## アルゴリズムのチュートリアル

 システムを正確にシミュレーションします。 

1. スタックの高さを表す現在の配列から始めます。 これは、ラビオリ スタックの現在の物理的な状態です。 
2. アレイが安定するまで繰り返し「リラックス」します。 安定性とは、隣接するペアが 2 以上異なっていないことを意味します。 各緩和スキャンは左から右に進み、ルールが適用されます。a[i] > a[i+1] + 1 の場合、i から i+1 に 1 ユニット移動し、a[i+1] > a[i] + 1 の場合、対称的に 1 ユニットを反対方向に移動します。 これは、問題で説明されているスライド動作をモデル化します。 
3. 安定化後、配列内の最大値を見つけます。同点の場合は左端の値を選択します。 これは、どのスタックを削除するかを選択するためのルールと一致します。 
4. この値を出力シーケンスに記録し、配列から削除します。 これは、そのスタックを物理的に取り除くことを表します。 
5. アレイが空になるまでプロセスを繰り返します。 

重要な点は、削除によって隣接関係が変化するため、以前の安定性が引き継がれると仮定するのではなく、削除のたびに完全に再安定化する必要があることです。 

### なぜ効果があるのか

 緩和プロセスでは、局所的な制約が強制されます。削除前のすべての最終構成は、隣接する差が最大 1 であることを満たさなければなりません。 この制約は、隣接するスタック間で質量がどのように流れるかを一意に決定します。これは、ギャップが大きいと、ギャップが消えるまで決定的な単位の移動が強制されるためです。 各除去は常に完全に安定化された構成から取得されるため、進化は明確に定義され、緩和ループ内の任意の順序選択とは独立しています。 これにより、シミュレートされたシーケンスが物理プロセスによって定義されたシーケンスとまったく同じであることが保証されます。 

生成されたシーケンスが非降順でソートされている場合、プロセスは有効であると見なされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def stabilize(a):
    n = len(a)
    changed = True
    while changed:
        changed = False
        for i in range(n - 1):
            if a[i] > a[i + 1] + 1:
                a[i] -= 1
                a[i + 1] += 1
                changed = True
            elif a[i + 1] > a[i] + 1:
                a[i + 1] -= 1
                a[i] += 1
                changed = True
    return a

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    out = []
    
    while a:
        a = stabilize(a)
        
        mx = max(a)
        idx = 0
        for i in range(len(a)):
            if a[i] == mx:
                idx = i
                break
        
        out.append(mx)
        a.pop(idx)
    
    print("YES" if out == sorted(out) else "NO")

if __name__ == "__main__":
    solve()
```安定化機能は実装の中核です。 隣接するペアが「差は最大 1」ルールに違反しなくなるまで、ローカル調整が繰り返し適用されます。 転送により配列の前半で新しい違反が作成される可能性があるため、単一のパスでは十分ではありません。したがって、外側のループによって確実に収束します。 

安定化後、最大値を計算し、その左端にあるものを削除します。 複数の等しい最大値は位置に応じて異なる方法で処理されるため、左端のタイブレークは不可欠です。 

最後に、生成された削除シーケンスをソートされたバージョンと比較します。 プロセスが問題のダイナミクスの下で正しい並べ替えメカニズムのように動作する場合、削除順序はすでに非減少になっているはずです。

 ## 特殊なケース

 1 つのエッジ ケースは単一のスタックです。 配列はすでに安定しているため、出力はその値のみです。 順序の曖昧さがないため、シーケンスは自明にソートされます。 

もう 1 つの特殊なケースは、次のような均一な配列です。`[2,2,2]`。 No relaxation occurs, and each removal picks the same value repeatedly, producing a constant sequence.

 A more interesting case is when large gaps exist initially, such as`[1,100]`。 安定化により、両側が等しいか最大 1 の差になるまで、中間ステップで繰り返し値が押し上げられ、最終的には削除前にほぼ均一な構成に平坦化されます。 これは、このプロセスが長距離構造を破壊し、出力が初期順序付けではなく総質量に主に依存する理由を示しています。
