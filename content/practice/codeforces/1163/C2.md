 ## 解決策
 ## 問題の理解

 平面上に点のセットが与えられ、それぞれが電柱を表します。 すべての極のペアは無限の直線を定義し、その線は「ワイヤ」と見なされます。 3 つ以上の極が同じ線上にある場合、複数のワイヤは作成されず、その方向に一意のワイヤが 1 つだけ提供されます。 

タスクは、これらの異なるワイヤが何対交差するかを数えることです。 2 本のワイヤは、対応する線が平面内で交差する場合に交差します。これは、それらが平行または同一でない限り、常に当てはまります。 同一のワイヤは同一線上の点セットによって定義されるため、それらを数えすぎないように注意する必要があります。 

重要な問題は、ワイヤの数が単にポイントのペアの数ではないことです。 多くのトリプル (またはより大きなセット) が単一の線に折りたたまれ、多くの潜在的なワイヤーが削除され、交差構造が大幅に変更されます。 

n が 1000 までという制約は、O(n^2) または O(n^2 log n) の前処理が適切であることを示唆しています。 立方体以上のものは遅すぎます。 ポイントペアの数は約 5×10^5 であるため、ソートまたはハッシュを使用したペアごとまたはポイントごとの推論は許容されます。 

点の各ペアを別個のワイヤとして扱う場合、単純な間違いが発生します。 たとえば、3 つの点が同一線上にある場合、たとえば (0,0)、(1,1)、(2,2) の場合、単純なアプローチでは 3 本のワイヤが作成されますが、正しいモデルには 1 本しかありません。 これらの重複した「並列コピー」によりラインのセットが人為的に膨らむため、交差部分のカウントが過剰になる可能性があります。 

もう 1 つの微妙な問題は、線の表現の処理です。 勾配を使用すると、浮動小数点精度エラーが直接発​​生します。 たとえば、1/3 と 2/6 のような勾配は同一として扱う必要がありますが、浮動小数点表現は若干異なる場合があります。 

## アプローチ

 ブルートフォースアプローチでは、まず、点のペアによって決定されるすべてのラインを構築します。 これにより、O(n^2) 個の候補行が得られます。 次に、正規化された傾きと切片、または削減された方向ベクトルとオフセットなどの正規表現を保存することによって、それらを重複排除します。 固有のワイヤのセットを構築した後、ワイヤのすべてのペアをチェックして、それらが交差しているかどうかを確認できます。 これには O(m^2) のコストがかかります。m は一意の行の数ですが、最悪の場合でも O(n^2) です。 これにより、制限をはるかに超えた O(n^4) の動作が発生します。 

重要な点は、実際には線間の交差を明示的にテストする必要がないということです。 2 本の異なる非平行線は常に 1 回だけ交差します。 したがって、交差するペアの数は、ワイヤの合計ペアから平行なワイヤのペアを引いたものに等しくなります。 これにより、同じ方向を共有するワイヤの数を数えるという問題が軽減されます。 

したがって、タスクは次のようになります。すべての一意のラインを計算し、方向ごとにグループ化し、各グループ内のペアの数を減算します。 ペアの総数は C(m,2) で、方向グループごとに C(k,2) を減算すると答えが得られます。 

主な技術的困難は、(平行なグループ化のため) 方向と (非平行な線の間で一意性を確保するため) 位置を分離する方法で線を表現することです。 各ラインは、正規化された方向ベクトルと、点の 1 つから計算されたオフセット キーを使用して表現できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^4) | O(n^2) | 遅すぎる |
 | 最適 | O(n^2 log n) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 任意の点のペアによって決定されるすべての個別の線の正規表現を構築します。

1. i < j のすべての点のペア (i, j) を反復処理し、それらを通過する直線を計算します。 これにより、考えられるすべての配線候補が捕捉され、配線の欠落がなくなります。 
2. 線の方向を、gcd と符号によって正規化された縮小ベクトル (dx、dy) として表します。 平行線には比例した方向ベクトルがあるため、これによりすべての平行線がグループ化されます。 
3. 方向だけでなく特定の行を一意に識別する完全な行キーを作成します。 安定した方法は、正規化された方向と 1 つの端点から計算された符号付きオフセットを組み合わせて、異なる平行線が確実に区別されるようにすることです。 
4. 各回線キーをセットに挿入して、すべての一意のワイヤを取得します。 各一意のキーは、問題定義内の 1 つのワイヤーに正確に対応します。 
5. 方向ベクトルからその方向を共有する一意のラインの数までのマップを構築します。 
6. ワイヤの合計ペアを m(m−1)/2 として計算します。ここで、m は一意のラインの数です。 
7. サイズ k の各方向グループについて、これらのペアは平行で交差しないため、k(k-1)/2 を減算します。 

最終的な答えは、すべてのペアの数から交差しない平行ペアの合計を引いたものになります。 

### なぜ効果があるのか

 平面内の 2 つの異なる線が平行でない場合にのみ交差します。 この構造により、多くの点ペアでワイヤが定義されている場合でも、各ワイヤが一度だけ一意に表現されることが保証されます。 正規化された方向によるグループ化により、線のセットが平行線の同値クラスに分割されます。 すべてのペアを数えてクラス内のペアを削除すると、交差する線のペアが正確に残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd
from collections import defaultdict

def norm(dx, dy):
    if dx == 0:
        return (0, 1)
    if dy == 0:
        return (1, 0)
    g = gcd(dx, dy)
    dx //= g
    dy //= g
    if dx < 0:
        dx = -dx
        dy = -dy
    elif dx == 0 and dy < 0:
        dy = -dy
    return (dx, dy)

def line_key(x1, y1, x2, y2):
    dx = x2 - x1
    dy = y2 - y1
    dxn, dyn = norm(dx, dy)

    # compute a perpendicular-based offset (stable line id)
    # line: dx*(y - y1) - dy*(x - x1) = 0
    # use c = dx*y1 - dy*x1
    c = dxn * y1 - dyn * x1
    return (dxn, dyn, c)

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    lines = set()
    dir_count = defaultdict(int)

    for i in range(n):
        x1, y1 = pts[i]
        for j in range(i + 1, n):
            x2, y2 = pts[j]
            key = line_key(x1, y1, x2, y2)
            if key not in lines:
                lines.add(key)
                dx = key[0]
                dy = key[1]
                dir_count[(dx, dy)] += 1

    m = len(lines)
    total = m * (m - 1) // 2

    bad = 0
    for k in dir_count.values():
        bad += k * (k - 1) // 2

    print(total - bad)

if __name__ == "__main__":
    solve()
```コードは、点のすべてのペアを列挙し、それらが定義する線の正規表現を構築します。 方向は正規化され、すべての平行線が同じ (dx、dy) にマッピングされます。 オフセット項 c は、異なる平行線がマージされないことを保証します。 

微妙な点は、方向正規化では符号を一貫して修正する必要があるということです。 そうしないと、同じ線が反対方向のベクトルで 2 回出現する可能性があります。 選択されたルールは、可能な限り dx を強制的に正にします。 

セット`lines`多くの点のペアが生成された場合でも、各幾何学的な線が 1 回カウントされるようにします。 辞書`dir_count`次に、方向ごとに存在する一意のラインの数を集計します。これは、まさに交差しないペアを減算するために必要なものです。 

## 実用的な例

 ### 例 1

 入力:```
4
0 0
1 1
0 3
1 2
```すべてのペアをリストし、それらの回線キーを計算します。 

| ペア | 方向 | ユニークな行が追加されました | ディレクショングループ |
 | --- | --- | --- | --- |
 | (0,0)-(1,1) | (1,1) | はい | (1,1) |
 | (0,0)-(0,3) | (0,1) | はい | (0,1) |
 | (0,0)-(1,2) | (1,2) | はい | (1,2) |
 | (1,1)-(0,3) | (-1,2) | はい | (1,2) |
 | (1,1)-(1,2) | (0,1) | はい | (0,1) |
 | (0,3)-(1,2) | (1,-1) | はい | (1,-1) |

 固有の行 m = 6。 

合計ペア = 15。 

並列グループ:

 - (1,2): 2 行 → 1 を減算します。 
- (0,1): 2 行 → 1 を減算

 最終的な答え = 15 − 2 = 13。 

このトレースは、複数の点のペアがどのようにして共有の幾何学的な線に崩壊するのか、また交差の過多を避けるためにグループ化が必要な理由を示しています。

```すべての点が同一線上にあるため、どのペアでも同じ線が生成されます。 

| ペア | 方向 | ユニークな行が追加されました | ディレクショングループ |
 | --- | --- | --- | --- |
 | (0,0)-(1,1) | (1,1) | はい | (1,1) |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | すべての点のペアが 1 回列挙されます。 
| スペース | O(n^2) | 最悪の場合、ペアごとに最大 1 つの一意の行。 

10^6 演算は十分制限内にあり、ハッシュ オーバーヘッドは管理可能なままであるため、二次関数の動作は n が 1000 まで許容されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math
    from collections import defaultdict

    def solve():
        n = int(input())
        pts = [tuple(map(int, input().split())) for _ in range(n)]

        def gcd(a, b):
            while b:
                a, b = b, a % b
            return abs(a)

        def norm(dx, dy):
            if dx == 0:
                return (0, 1)
            if dy == 0:
                return (1, 0)
            g = gcd(dx, dy)
            dx //= g
            dy //= g
            if dx < 0:
                dx = -dx
                dy = -dy
            return (dx, dy)

        def key(x1, y1, x2, y2):
            dx, dy = x2 - x1, y2 - y1
            dx, dy = norm(dx, dy)
            c = dx * y1 - dy * x1
            return (dx, dy, c)

        lines = set()
        dirc = defaultdict(int)

        for i in range(n):
            for j in range(i + 1, n):
                k = key(*pts[i], *pts[j])
                if k not in lines:
                    lines.add(k)
                    dirc[(k[0], k[1])] += 1

        m = len(lines)
        total = m * (m - 1) // 2
        bad = sum(v * (v - 1) // 2 for v in dirc.values())
        print(total - bad)

    solve()
    return sys.stdout.getvalue().strip()

 ## 特殊なケース

 主なエッジケースは、多数の点が 1 つの線上にある場合です。 (0,0)、(1,1)、(2,2)、(3,3) のような入力の場合、すべての O(n^2) ペアが同じ幾何学的ワイヤに対応します。 このアルゴリズムはすべてのペアを 1 つのキーにまとめて、サイズ 1 の単一方向のグループを生成します。カウント中に並列減算は発生せず、ワイヤーが 1 本しかないため、答えは正しく 0 になります。 

もう 1 つのエッジ ケースは、y = 0、y = 1、y = 2 など、複数の異なる平行線が存在し、それぞれが複数の点で定義されている場合です。 ここでは、方向グループ化によってそれらが 1 つのクラスにマージされ、減算項によってそれらの間のすべての交差が削除されます。 各グループは内部的に交差を提供しませんが、並列関係のみが除外されるため、グループ間のペアは正しくカウントされたままになります。
