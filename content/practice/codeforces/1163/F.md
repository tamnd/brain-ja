 ## 解決策
 ## 問題の理解

 最大 200,000 の頂点とエッジを持つ重み付き無向グラフが与えられます。 各エッジには固定の重みがあり、エッジの重みの合計を使用してノード 1 からノード n までの最短パスを計算します。 

問題は、最短経路の問題を 1 つだけ解決しているわけではないということです。 代わりに、最大 200,000 の独立した変更が許可されます。 各変更により、正確に 1 つのエッジの重みが変更されますが、他のすべてのエッジは変更されないため、変更されたグラフのバージョンごとに 1 から n までの新しい最短パス距離を報告する必要があります。 

直接解釈すると、クエリごとに、1 つの変更されたエッジの重みを使用してグラフを一時的に再構築し、最短パスを再計算します。 

制約があるため、単純にこれを実行することは不可能です。 各クエリに対してダイクストラを最初から実行すると、約 O(q · m log n) のコストがかかりますが、これは 2 × 10^5 のクエリとエッジでは実現不可能です。 

微妙な点は、クエリごとに 1 つのエッジの重みが変更されることを除いて、グラフが無向で静的であることです。 この構造は、重い前処理を再利用する必要があることを示唆しています。 

単純なアプローチは、あまり目立たない形で失敗する可能性もあります。 ノード 1 から単一の最短パス ツリーを事前計算しようとして、それが安定していると仮定すると、変更されたエッジが元の最短パス ツリーの一部ではなく、より安価な代替パスが作成されると、即座に壊れます。 たとえば、元の最短パス上の 2 点間のショートカットを形成する非ツリー エッジの重みを減らすと、たとえそのエッジが元の解では無関係であったとしても、答えが変わる可能性があります。 

## アプローチ

 ブルートフォース手法は簡単です。 クエリごとに、エッジの重みを更新し、ノード 1 からノード n までダイクストラを実行します。 ダイクストラは任意の正の重みを処理するため、これは正しいですが、基本的に同じ計算を最大 200,000 回繰り返すことになります。 各実行のコストは O(m log n) で、最悪の場合はおよそ 4 × 10^10 の操作が必要になりますが、これは実際的な制限をはるかに超えています。 

重要な観察は、各クエリが 1 つのエッジのみを変更するということです。 これは、すべてを再計算するのではなく、単一のエッジの重みの変更に最短パスがどのように反応するかを理解する必要があることを示唆しています。 

まず、元のグラフを使用してノード 1 からすべてのノードまでの最短距離を計算し、元のグラフを反転して使用してノード n からすべてのノードまでの最短距離を計算します。 これらの配列を dist1 と distn とします。 

ここで、エッジ e = (u, v) を重み w から x に変更するクエリを考えてみましょう。 この変更による最短パスには 2 つのタイプがあります。 このエッジをまったく使用しない場合、そのコストは変更されず、元の最短パス距離 dist1[n] に等しくなります。 または、このエッジを少なくとも 1 回使用します。 すべての重みが正であるため、最適なパスでは変更されたエッジが 1 回しか使用されないため、1 から u に進み、エッジを横断し、v から n に進むパス、またはその逆のパスのみを考慮する必要があります。 

これにより、各クエリが dist1 と distn から導出された一定数の候補値をチェックすることになります。 

残りの微妙な点は、最短パスでも反対方向の変更されたエッジを使用する可能性があるため、両方の方向をテストする必要があることです。 

また、代替ルートと相互作用する方法で、最短パス構造上にエッジが現れる場合も処理する必要があります。 dist1 および distn の前処理は、必要なグローバル構造をすべてすでにキャプチャしています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース ダイクストラ | O(q · m log n) | O(n + m) | 遅すぎる |
 | dist + クエリごとに事前計算 O(1) | O((n + m) log n + q) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 事前に計算された最短パス情報を使用して、問題を各クエリに答えるように変換します。

1. 元のグラフのノード 1 からダイクストラを実行し、1 からすべてのノード v までの最短距離 dist1[v] を保存します。これにより、すべての順方向移動コストのベースラインが得られます。 
2. 同じグラフ上のノード n からダイクストラを実行し、すべてのノード v から n までの最短距離である distn[v] を保存します。 この逆の観点を使用すると、n で終わるパスのサフィックス コストを迅速に評価できます。 
3. エンドポイント (u, v) と重み w を持つすべてのエッジを配列に保存し、インデックスによってアクセスして変更できるようにします。 
4. 各クエリ (t, x) について、エッジ t = (u, v, w) を重み x で一時的に置き換えるものとして解釈します。 
5. エッジ t を使用しない最適なパスを計算します。 これは単に dist1[n] です。 
6. エッジ t を u → v 方向に 1 回だけ使用する最適パスを計算します。コストは dist1[u] + x + distn[v] になります。 これは、変更されたエッジを使用して u までの最短ルートをとり、その後 n まで最適に終了することに対応します。 
7. 対称ケース v → u を dist1[v] + x + distn[u] として計算します。 
8. クエリの答えは、これら 3 つの値の最小値です。 

これらの候補に限定できる理由は、変更されたエッジを使用するパスはすべて、1 から 1 つのエンドポイントまでのプレフィックス、エッジ自体、およびもう一方のエンドポイントから n までのサフィックスに分解できるためです。 パスがエッジを複数回使用する場合、すべての重みが正であるため、サイクルを削除するとコストが厳密に削減されるため、最適化することはできません。 

### なぜ効果があるのか

 前処理では、両端からのグローバルに最適な距離が計算されます。 変更されたエッジを使用する候補パスについては、コストを増加させることなく、そのエッジ以外のすべてを最短パスに置き換えることができます。 これは、最短パスが最適な部分構造を満たすため、有効です。つまり、最短パスのサブパスはそれ自体が最短になります。 したがって、クエリによって導入される唯一の自由度は、変更されたエッジが使用されるかどうか、およびどの方向に使用されるかということです。 他のすべての構造は、すでに dist1 と distn に最適に圧縮されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

INF = 10**30

def dijkstra(n, adj, start):
    dist = [INF] * (n + 1)
    dist[start] = 0
    pq = [(0, start)]
    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

n, m, q = map(int, input().split())

adj = [[] for _ in range(n + 1)]
edges = [None] * (m + 1)

for i in range(1, m + 1):
    u, v, w = map(int, input().split())
    adj[u].append((v, w))
    adj[v].append((u, w))
    edges[i] = (u, v, w)

dist1 = dijkstra(n, adj, 1)
distn = dijkstra(n, adj, n)

out = []
for _ in range(q):
    t, x = map(int, input().split())
    u, v, w = edges[t]

    ans = dist1[n]
    ans = min(ans, dist1[u] + x + distn[v])
    ans = min(ans, dist1[v] + x + distn[u])

    out.append(str(ans))

print("\n".join(out))
```コードは、隣接リストを構築し、クエリ内のインデックスによってエッジを参照できるようにエッジを保存することから始まります。 2 つのダイクストラ実行により、ノード 1 とノード n からの距離配列が計算されます。 

各クエリは、3 つの候補パス タイプを評価することによって一定時間内に応答されます。 元の最短パスは有効なままであり、2 つの式は、いずれかの方向の変更されたエッジを含む最短パスを考慮します。 

よくある実装の落とし穴は、同じグラフ上のノード n からダイクストラを実行するのを忘れることです。 2 番目のパスは、宛先へのすべてのサフィックス最短パスをエンコードするため、不可欠です。 

もう 1 つの微妙な点は、64 ビット安全な値を使用することです。 距離は最大 2 × 10^14 まで累積できるため、Python では自然に処理されますが、型付き言語ではオーバーフローを回避する必要があります。

### トレースの例

 dist1 と distn を 1 回事前計算してから、クエリを処理します。 

クエリごとに候補を評価します。 

| クエリ | 距離1[n] | dist1[u] + x + distn[v] | dist1[v] + x + distn[u] | 答え |
 | --- | --- | --- | --- | --- |
 | (3,4) | 4 | 5 | 6 | 4 |
 | (5,1) | 4 | 2 | 6 | 2 |
 | (3,8) | 4 | 5 | 7 | 5 |

 これは、元の最短パスがフォールバック オプションのままである一方で、さまざまなクエリがさまざまなエッジを潜在的なショートカットとしてアクティブにする方法を示しています。 

トレースは、アルゴリズムがグローバル構造を再計算することなく、単一のエッジ変更の影響を正しく分離していることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n + q) | 2 つのダイクストラ実行が前処理を支配し、各クエリは O(1) |
 | スペース | O(n + m) | 隣接リスト、エッジ ストレージ、距離配列 |

 バイナリ ヒープ ダイクストラを使用した 2 × 10^5 エッジが標準であるため、前処理は制約の下で快適にフィットします。 クエリ処理は定数時間であるため、クエリの最大数さえも重要ではありません。 

## テストケース```python
import sys, io

INF = 10**18

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    import heapq

    n, m, q = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    edges = [None] * (m + 1)

    for i in range(1, m + 1):
        u, v, w = map(int, input().split())
        adj[u].append((v, w))
        adj[v].append((u, w))
        edges[i] = (u, v, w)

    def dijkstra(s):
        dist = [INF] * (n + 1)
        dist[s] = 0
        pq = [(0, s)]
        while pq:
            d, u = heapq.heappop(pq)
            if d != dist[u]:
                continue
            for v, w in adj[u]:
                nd = d + w
                if nd < dist[v]:
                    dist[v] = nd
                    heapq.heappush(pq, (nd, v))
        return dist

    dist1 = dijkstra(1)
    distn = dijkstra(n)

    out = []
    for _ in range(q):
        t, x = map(int, input().split())
        u, v, w = edges[t]
        ans = min(
            dist1[n],
            dist1[u] + x + distn[v],
            dist1[v] + x + distn[u]
        )
        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 微妙なケースの 1 つは、変更されたエッジが元の最短パスの一部ではないが、縮小後にクリティカルになる場合です。 たとえば、長い迂回は、単一のエッジが安くなった後にのみ最適になる可能性があります。 dist1[u] + x + distn[v] は、以前に使用されたかどうかに関係なく、エッジが最適なプレフィックスとサフィックスを接続できるあらゆる可能な方法を評価するため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、元の最短パスがすでに変更されたエッジを使用している場合です。 重みが増加すると、最適な代替パスがまったく別のルートに切り替わる可能性があります。 dist1[n] という用語は、エッジを完全に回避するすべてのパスをすでにカバーしているため、最小値は特別なケースを使用せずに、使用する場合と使用しない場合の間で正しく遷移します。
