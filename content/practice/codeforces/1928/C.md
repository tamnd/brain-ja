 ## 解決策
 ## 問題の理解

 私たちには、生徒たちが「最初に～」という繰り返しに従って整列するというシナリオが与えられています。$k$-th" パターン。シーケンスは数字で始まります$1$に$k$、から反転します。$k-1$まで$2$、このブロック全体が毎回繰り返されます$2k-2$ポジション。 ヴァシャは戦列内での自分の位置を知っている、$n$、そして彼が受け取った番号、$x$、しかし忘れてしまった$k$。 私たちのタスクは、可能な値がいくつあるかを決定することです。$k$はこの情報と一致しています。 

主な制約は、$k$より大きくなければなりません$1$とのシーケンス以来、$k = 1$意味がありません。 ポジションは非常に大きくなる可能性があり、最大で$10^9$したがって、ラインを明示的にシミュレートしようとするアプローチは遅すぎます。 についての推論を可能にする数学的定式化が必要です$k$シーケンス全体を生成することなく。 

エッジケースが発生するのは次の場合です$x = 1$または$x = n-1$、これらは増加/減少ブロックの境界にある数値に対応しているためです。 不用意に実装すると、次の値が失われる可能性があります。$k$より大きいもの$n/2$または、周囲のシーケンスの対​​称性を処理できません。$k$正しく。 たとえば、$n = 10$そして$x = 2$、$k = 2$シーケンスが交互に [1,2,1,2,...] になるため機能しますが、$k = 9$たとえその位置に到達するのに十分な大きさに見えても、そうではないだろう$n$。 

## アプローチ

 単純なブルートフォースソリューションでは、すべてのことを試みることになります。$k$から$2$まで$n$位置までのシーケンスをシミュレートします$n$、その位置の数字が一致するかどうかを確認します$x$。 これは原理的には正しいですが、$n$まで$10^9$、単一のシーケンスをシミュレートするだけでも遅すぎます。シミュレーションには最大で$O(n)$テストケースごとの操作。 まで$100$テストケースでは、これはまったく実行不可能です。 

重要な観察は、このシーケンスが毎回繰り返されるということです。$2k-2$ポジション。 したがって、位置$n$ある長さのブロックに分類される$2k-2$、および位置の番号$n$長さの最初の増加セグメントのいずれかの部分です$k$または長さの減少するセグメント$k-2$。 これら 2 つのケースを代数的に分析すると、次のように表現できます。$k$の関数として$n$そして$x$。 これにより、検索が減少します。$O(n)$の約数を反復するまで$n-x$または$n-1$、はるかに小さなセット。 

特に、与えられた$k$、繰り返しブロック内のゼロベースのオフセットを次のように定義します。`pos_in_block = (n-1) % (2*k-2)`。 このオフセットが以下の場合$k$、 それから`x`等しい必要があります`pos_in_block + 1`。 それ以外の場合は、次と等しくなければなりません`2*k - pos_in_block - 1`。 これらの単純な一次方程式を解くと、$k$整数の割り算をチェックすると、すべての候補が得られます$k$。 数の約数の数は$O(sqrt(n))$、これにより実現可能な解決策が得られます。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`各テスト ケースを繰り返します。 
2. 各テストケースについて、Vasya の立場を読み取ります。`n`と番号`x`。 
3. Initialize a counter for valid`k`。 
4. 2 種類の候補者を検討する`k`Vasya の位置が繰り返しブロックのどのセグメントに該当するかに基づいて決定されます。 最初のタイプは、ブロック内のオフセットが増加部分にある場合に発生し、次の方程式が導かれます。`n - x = m*(2k-2)`ある整数に対して`m >= 0`。 2 番目のタイプは、オフセットが減少部分にある場合に発生します。`n + x - 2 = m*(2k-2)`ある整数に対して`m >= 0`。 
5. すべての約数を反復します。`n-x`そして`n+x-2`ゼロより大きく、各約数について候補を計算します`k`数式を使用すると、次のようになります。`k = (divisor + 2) // 2`。 それを確認してください`k > 1`そしてそれが元の方程式を満たしていることを確認します。 
6. 有効なそれぞれについて`k`、カウンターをインクリメントします。 
7. 現在のテスト ケースのカウンターを出力します。 

これが機能する理由は、すべての有効な位置が`n`番号の場合`x`繰り返しブロックの長さの整数倍にブロック内のオフセットを加えたものとして表すことができます。 上記の式はブロックの算術演算から正確に導出されており、有効な計算式が存在しないことが保証されています。`k`が見逃され、無効な候補は破棄されます。 各約数は、配置できるブロック長の潜在的な倍数に対応します。`x`位置にある`n`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_valid_k(n, x):
    res = 0
    # Check first type: n - x = m*(2k-2)
    for d in range(1, int((n-x)**0.5) + 1):
        if (n - x) % d == 0:
            for m in [d, (n-x)//d]:
                k = (m + 2) // 2
                if k > 1 and (n - x) % (2*k - 2) == 0:
                    res += 1
    # Check second type: n + x - 2 = m*(2k-2)
    for d in range(1, int((n+x-2)**0.5) + 1):
        if (n + x - 2) % d == 0:
            for m in [d, (n+x-2)//d]:
                k = (m + 2) // 2
                if k > 1 and (n + x - 2) % (2*k - 2) == 0:
                    res += 1
    return res

t = int(input())
for _ in range(t):
    n, x = map(int, input().split())
    print(count_valid_k(n, x))
```最初のループでは、次のすべての約数を検索します。`n-x`2 番目のループはセグメントの減少条件に対して同じことを行いますが、セグメントの増加条件を満たします。 約数ごとに、次のように計算します。`k`そしてそれが正確な方程式を満たしていることを確認します。 両方のループを使用すると、考えられるすべての配置を確実にキャプチャできます。`x`そのブロック内で。 数式内のオフバイワンエラーと、`k > 1`状態。 

## 実用的な例

 入力用`n = 10, x = 2`、候補者は次のとおりです。`n-x = 8`そして`n+x-2 = 10`。 8 の約数は 1、2、4、8 です。公式を適用すると、次のような可能性が得られます。`k = 2, 3, 5, 6`。 すべてが位置条件を満たしており、有効な値は 4 つです`k`。 

| 除数 | k | 方程式をチェック | 有効 |
 | --- | --- | --- | --- |
 | 1 | 1 | 失敗します k>1 | いいえ |
 | 2 | 2 | (10-2) % (2*2-2) = 8 % 2 = 0 | はい |
 | 4 | 3 | 8 % 4 = 0 | はい |
 | 8 | 5 | 8 % 8 = 0 | はい |
 | 8 (n+x-2 から) | 6 | 10 % 10 = 0 | はい |

 のために`n = 3, x = 1`、 のみ`k = 2`動作します。 ここ`n-x = 2`約2を与える`k = 2`。 もう一人の候補者は、`n+x-2 = 2`も与えます`k = 2`。 有効なのは 1 つだけ`k`。
