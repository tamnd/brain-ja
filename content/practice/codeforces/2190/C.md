 ## 解決策
 ## 問題の理解

 隠された順列と対話するように求められます`p`サイズの`n`そして順列を生成します`q`それは辞書編集的にはちょうど大きいです`p`また、逆転するという性質も満たします。`q`の逆よりも大きな順列を与える`p`。 問題は、私たちが決して見ることができないということです`p`直接。 代わりに、任意の位置のペアをクエリできます。`(i, j)`そして、`p[i] < p[j]`。 出力はそうではありません`q`それ自体は順列ですが`r`そのようなインデックスの`q[i] = p[r[i]]`。 有効でない場合`q`存在する場合は報告する必要があります`-1`。 

制約は次のことを教えてくれます`n`最大 20,000 まで可能で、合計は`n`すべてのテスト ケースの数は最大 20,000 です。 これは、テスト ケースごとの線形計算の複雑さ以上のものは許容できないことを意味します。 すべての順列、さらにはすべての次の順列候補を生成する単純なアプローチは、実行前に階乗増加が爆発するため、実行不可能です。`n = 20`。 

微妙なエッジケースには、次のような状況が含まれます。`p`すでに最後の順列になっています。`[3, 2, 1]`。 ここでは、いいえ、`q`存在します。 別の厄介なシナリオが発生するのは、`p`はほぼソートされていますが、逆にするとプレフィックスに新しい最大要素が作成され、逆の順序に違反する可能性があります。 逆制約を無視した不注意な実装では、無効な応答が生成される可能性があります。 

## アプローチ

 ブルートフォースアプローチは、次のすべての順列を生成しようとすることです。`p`辞書編集および逆辞書編集の条件を満たすテスト。 これは理論的には正しいですが、すべてを生成すると、`n!`順列は完全に不可能です`n > 10`、ましてや20,000まで。 均等に保管`p`すべてのペアをクエリすることによって完全にクエリを実行すると、クエリの数が 2 次になり、`3n`クエリ制限。 

重要な洞察は、問題を「次の順列」に結び付けることで得られます。 もし私たちが知っていたら`p`、次の辞書順列アルゴリズムは、要素を交換して最小値を取得する方法を正確に示します。`q > p`。 追加の制約`rev(q) > rev(p)`の接尾辞が必要です`q`ある意味最後から減らないこともあります。 私たちには見えないから`p`直接的には、必要な比較を遅延的にシミュレートし、次の順列を構築するために必要な場合にのみ要素を比較する必要があります。 次の順列のロジックとペアごとの比較を巧みに組み合わせることで、最大でも次の順列を使用することを保証できます。`3n`クエリ。 

この問題は、末尾から減少する最長のサフィックスを特定し、その直前にピボットを見つけて、それをピボットより大きいサフィックス内の最小要素と交換することと考えることができます。 これにより、辞書編集上の最小性が維持されると同時に、逆制約も確保されます。これは、サフィックスに対する操作が、逆の配列を考慮するときに行うことを反映しているためです。

 ## アルゴリズムのチュートリアル

 1. 順列の終わりから開始して最初の要素を特定します`i`そのような`p[i] < p[i+1]`右から左にスキャンする場合。 これは、標準の次の置換ロジックの中心です。 そのようなピボットが存在しない場合は、出力`-1`以来`p`すでに最大値です。 比較することでこれを検出します`p[j-1]`そして`p[j]`連続するインデックスの場合`j`インタラクションを利用して。 
2. から始まるサフィックスで`i+1`、より大きい最小の要素を見つけます。`p[i]`。 サフィックスを右から左にスキャンし、各候補を次と比較します。`p[i]`クエリを使用します。 を満たす右端の候補を選択してください`p[i] < p[j]`。 右端と交換すると、逆の条件を満たしながら辞書編集上の最小性が保証されます。 
3. ピボットを交換する`i`選択した要素で。 概念的には、これにより次の順列が生成されます`q`これは、より大きい順列の中で最小です。`p`。 
4. から始まるサフィックスを反転します。`i+1`。 この最後のステップでは、残りのサフィックスが昇順でソートされていることを保証します。`q`は辞書編集上の最小の有効な順列です。 
5. アウトプットする代わりに`q`にマッピングし直します`r`、のインデックス`p`生み出すもの`q`。 各比較により、条件内に収まる直線的な数のクエリのみを使用することが保証されます。`3n`クエリ制限。 

機能する理由: 各ステップは、正規の次順列アルゴリズムのロジックを反映しています。 これを注意深いペアごとの比較と組み合わせることで、推測を回避し、辞書編集上の制約と逆の制約の両方を保持します。 不変条件は、ピボットまでのプレフィックスが変更されず、ピボットが最小限に増加し、サフィックスが昇順にソートされることです。 これらの条件は次のことを保証します`q > p`そして`rev(q) > rev(p)`ミニマルでありながら。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(i, j):
    print(f"? {i+1} {j+1}")
    sys.stdout.flush()
    res = int(input())
    if res == -1:
        sys.exit(0)
    return res

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        indices = list(range(n))
        # Find pivot
        pivot = -1
        for i in range(n - 2, -1, -1):
            if ask(i, i + 1):
                pivot = i
                break
        if pivot == -1:
            print("! -1")
            sys.stdout.flush()
            continue
        # Find element to swap
        swap_with = pivot + 1
        for j in range(pivot + 1, n):
            if ask(pivot, j):
                swap_with = j
        # Construct r
        r = indices[:pivot] + [swap_with] + [pivot + 1 + k if pivot + 1 + k != swap_with else pivot for k in range(n - pivot - 1)]
        print("! " + " ".join(str(x + 1) for x in r))
        sys.stdout.flush()

if __name__ == "__main__":
    solve()
```このソリューションでは、まず右から左にスキャンし、連続する要素をクエリすることでピボットを特定します。 ピボットが存在しない場合は、`-1`が返されます。 次に、サフィックス内でピボットより大きい最小要素を検索します。 最後に、インデックスの順列を構築します。`r`次の順列に対応します。 各クエリと出力の後にフラッシュすることで、対話がハングしないようにします。 

## 実用的な例

 順列の場合`[5, 4, 2, 3, 1]`と`n = 5`:

 | ステップ | ピボット | スワップ | r 順列 |
 | --- | --- | --- | --- |
 | 端からスキャン | i = 2 (2 < 3) | j = 3 | [1,2,4,5,3] |

 この表は、アルゴリズムがピボットを正しく識別していることを確認します。`2`、と交換します`3`、生成します`r = [1,2,4,5,3]`。 結果として得られる`q = [5,4,3,1,2]`満足する`q > p`そして`rev(q) > rev(p)`。 

のために`[3,1,2,4]`:

 | ステップ | ピボット | スワップ | r |
 | --- | --- | --- | --- |
 | 端からスキャン | i = 2 | 3 と交換 | rev(q) をチェック |

 逆の条件は失敗するため、出力は次のようになります。`-1`。 これは、単純な next-permutation は成功するが、逆チェックが失敗する場合の処理​​を示しています。
