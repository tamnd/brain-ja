 ## 問題の理解

 まずは森から始めます。 グラフ全体が単一のツリーになるまで、接続されたコンポーネント間にエッジを追加することがあります。 

結果として得られるすべてのツリーに対して、標準の Prüfer コード削除プロセスを実行します。頂点が 2 つだけ残るまで、最も小さい番号の葉を繰り返し削除します。 それらの頂点の 1 つは常に頂点になります$n$。 もう 1 つの生き残った頂点はプリューファー頂点と呼ばれます$P(T)$。 

タスクは、すべての完了ツリーを数えることではありません。 代わりに、すべての$v<n$、森林を接続する方法が何通りあるかを数えなければなりません。プリューファー頂点が次の値に等しい木が生成されます。$v$。 

すべてのテスト ケースの頂点の合計数は最大で$2\cdot 10^5$。 完了ツリーの数に比例して作業を実行するソリューションは絶望的です。空のフォレストであっても、$n$頂点には$n^{n-2}$可能性のある木。 プリューファー頂点の構造的特徴付けと、コンポーネントのサイズといくつかのサブツリーのサイズのみに依存するカウント式が必要です。 

驚くほど危険なエッジケースは次のような場合です。$n$そして$n-1$すでに同じ接続コンポーネントに属しています。```
4 3
1 2
2 3
3 4
```森はすでに木になっています。 完了は 1 つだけです。 答えは単一の頂点、つまり、からのパス上の 2 番目の頂点に集中しています。$4$に$3$。 を仮定するあらゆる計数式$n$そして$n-1$最初に接続されていない場合は、ここで失敗します。 

もう 1 つの微妙なケースは、フォレストが孤立した頂点のみで構成されている場合です。```
3 0
```完了ツリーは 3 つあります。 答えは対称的ではありません。 頂点$2$頂点より大きい$1$したがって、葉を削除する順序が重要です。 ラベルのないツリーのみに基づいた議論は、間違った分布を与えます。 

3 番目の落とし穴は、次のコンポーネントが含まれていることです。$n$。 そのコンポーネント内の頂点が答えになる可能性は同じではありません。 重要なのは、子の下にぶら下がっているルート化されたサブツリーのサイズです。$n$コンポーネントのサイズだけではありません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 フォレストをツリーに接続するすべての方法を列挙し、プリューファー プロセスをシミュレートし、対応する答えを増分します。 

これは定義に直接従うため、正しいです。 残念ながら、完了ツリーの数は$$n^{k-2}\prod s_i,$$最悪の場合は指数関数的になります。 控えめな値であっても、$n$、木の数は天文学的に多いです。 

重要な観察は、プリューファープロセス自体を理解することから得られます。 

最後に生き残ったペアを考えてみましょう。 頂点$n$常に存在します。 いつ頂点を設定できるか$n-1$最後まで消える？ 

少なくとも 2 つの頂点を持つ木には、常に少なくとも 2 つの葉があります。 したがって$n-1$最後の近くの葉だけが残っている場合にのみ、最後まで生き残ることができます。$n-1$そして$n$。 つまり、からのユニークなパスは$n$に$n-1$残りの頂点がすべて含まれます。 そのパス上の 2 番目の頂点は、まさに一緒に生き残る頂点です。$n$。 これは、プリューファーの頂点を完全に特徴づけています。 

この特徴が分かると、問題は連結成分の計数問題になります。 古典的な公式$$n^{k-2}\prod s_i$$コンポーネントの接続方法を数えるためには、コンポーネント内のすべての頂点が対称であるという事実を組み合わせることができます。 結果の数はコンポーネントのサイズと、コンポーネント内の頂点にのみ依存します。$n$、ルート化されたサブツリーのサイズについて。

 ## アルゴリズムのチュートリアル

 ### 1. 連結成分を見つける

 フォレストで DFS または DSU を実行します。 

すべての頂点について、そのコンポーネント ID とそのコンポーネントのサイズを保存します。 

すべてのコンポーネントをその最大番号の頂点でルートします。 特に、以下を含む成分は、$n$に根付く$n$。 

### 2. コンポーネント内のサブツリーのサイズを計算します。$n$DFS 中に計算します$$dp[v]=1+\sum dp[\text{child}].$$子供のために$v$の$n$、この値は、下にぶら下がっている枝のサイズとまったく同じです。$v$。 

### 3. 次のような場合に対処します。$n$そして$n-1$すでに接続されています

 プリューファー頂点は永久に固定されます。 

から徒歩$n-1$～の子に届くまで上向きに$n$～からの道に横たわっている$n$に$n-1$。 

この頂点を呼び出します$x$。 

すべての完了ツリーには次のものがあります。$P(T)=x$、 それで$$ans[x] = \Big(\prod s_i\Big)\, n^{k-2}.$$他のすべての答えはゼロです。 

### 4. 候補頂点を検討する$v$仮定する$n$そして$n-1$異なるコンポーネントにあります。 

状況は 3 つあります。 

#### 4.1$v$の成分にあります$n$それから$v$～の直接の子でなければなりません$n$。 

残りのコンポーネントを接続するすべての方法の中で、次のコンポーネントが含まれています。$n-1$最終的にはブランチ内に到達する必要があります$v$。 

なぜなら、コンポーネントの頂点は$n$が対称である場合、その分岐に到達する確率は$$\frac{dp[v]}{|C_n|}.$$完了ツリーの総数を掛けると答えが得られます。 

#### 4.2$v$の成分にあります$n-1$まず、次のコンポーネントを接続します。$n$そして$n-1$。 

次に、目的のブランチサイズは次のようになります。$$|C_n|+|C_{n-1}|.$$カウント式に代入すると寄与率が得られます。 

#### 4.3$v$他のコンポーネントに存在する

 そのコンポーネントは、最初に次のコンポーネントにアタッチする必要があります。$n$。 

コンポーネント内のすべての頂点は対称であるため、コンポーネントのサイズのみが問題になります。 

### 5. モジュラー逆数とべき乗を事前計算する

 すべての式には、コンポーネントのサイズによる除算が含まれています。 係数は素数なので、逆剰余を使用します。 

事前計算も行う$$n^0,n^1,\dots,n^k.$$### なぜ効果があるのか

 重要な特性は、プリューファー頂点がちょうど 2 番目の頂点であるということです。$n$に$n-1$。 これが分かれば、問題は詳細な削除順序には依存しなくなります。 

確定候補者の場合$v$を含むコンポーネントが含まれる完了ツリーをカウントするだけで済みます。$n-1$の支店内に行き着きます$v$木が根を張るとき$n$。 同じ接続コンポーネント内の頂点は、古典的なコンポーネント結合のカウント式では区別できないため、カウントは関連するブランチのサイズに比例します。 アルゴリズムで使用されるすべての式は、正確に、完了ツリーの総数に、配置される完了ツリーの割合を乗算したものです。$n-1$その支店で。 したがって、すべての完了は 1 つの頂点に対して 1 回だけカウントされます。$v$、結果として得られる答えは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())

    inv = [0] * 200001
    inv[1] = 1
    for i in range(2, 200001):
        inv[i] = MOD - (MOD // i) * inv[MOD % i] % MOD

    for _ in range(t):
        n, m = map(int, input().split())

        g = [[] for _ in range(n + 1)]
        for _ in range(m):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        comp = [-1] * (n + 1)
        parent = [0] * (n + 1)
        sub = [1] * (n + 1)
        sizes = []

        sys.setrecursionlimit(1 << 20)

        def dfs(v, p, cid):
            comp[v] = cid
            sizes[cid] += 1
            parent[v] = p

            for to in g[v]:
                if to == p:
                    continue
                dfs(to, v, cid)
                sub[v] += sub[to]

        cid = 0
        for v in range(n, 0, -1):
            if comp[v] == -1:
                sizes.append(0)
                dfs(v, 0, cid)
                cid += 1

        k = cid

        sz = [0] * (n + 1)
        for v in range(1, n + 1):
            sz[v] = sizes[comp[v]]

        p = 1
        for s in sizes:
            p = p * s % MOD

        pw = [1] * (k + 1)
        for i in range(1, k + 1):
            pw[i] = pw[i - 1] * n % MOD

        def npow(e):
            if e >= 0:
                return pw[e]
            return inv[n]

        ans = [0] * n

        if comp[n] == comp[n - 1]:
            v = n - 1
            while parent[v] != n:
                v = parent[v]

            ans[v] = p * npow(k - 2) % MOD
        else:
            comp_n = comp[n]
            comp_nm1 = comp[n - 1]

            for v in range(1, n):
                if comp[v] == comp_n:
                    if parent[v] != n:
                        continue

                    ans[v] = (
                        sub[v]
                        * p
                        % MOD
                        * inv[sz[n]]
                        % MOD
                        * npow(k - 2)
                    ) % MOD

                elif comp[v] == comp_nm1:
                    ans[v] = (
                        p
                        * inv[sz[n]]
                        % MOD
                        * inv[sz[n - 1]]
                        % MOD
                        * (sz[n] + sz[n - 1])
                        % MOD
                        * npow(k - 3)
                    ) % MOD

                else:
                    ans[v] = (
                        sz[v]
                        * p
                        % MOD
                        * inv[sz[n]]
                        % MOD
                        * inv[sz[v]]
                        % MOD
                        * npow(k - 3)
                    ) % MOD

        print(*ans[1:])

solve()
```DFS は、コンポーネント ID、コンポーネント サイズ、親ポインター、サブツリー サイズを同時に計算します。 各コンポーネントの最大頂点でのルートは、カウントの証明で使用される引数と一致します。 含まれているコンポーネント$n$は自動的にルート化されます$n$これにより、関連するすべてのブランチのサイズがサブツリーのサイズと等しくなります。 

機能`npow`特殊指数を処理します$-1$。 これは次の場合に発生します。$k=1$または$k=2$、編集上の式は次のように置き換えられます。$n^{-1}$モジュラー逆関数により$n$。 

最も一般的な実装上の間違いは、次の直接の子のみを忘れることです。$n$いつ答えられるか$v$のコンポーネントに属します$n$。 小切手`parent[v] == n`が不可欠です。
