 ## 解決策
 ## 問題の理解

 中央値について直接考えるよりも、値の増加順に明らかになる順列について考える方がはるかに有益です。 

次の順列の値を処理するとします。`1`に`n`。 値がいつ`x`が処理されると、その位置は「アクティブ」になります。 どのポジションでも、その状態は次のようになります。`0`= 値はまだ処理されていません。`X`= 現在処理中の値、`1`= 値はすでに処理されています。 

長さ 3 のウィンドウのすべての中央値が明確であるという条件は、次にどの位置をアクティブ化できるかについての強力な制限になります。 禁止された局所パターンを単純化した後、純粋に位置的なプロセスが得られます。 ポジションは非常に特別な順序でアクティブ化する必要があります。 

入力により、最終的な順列が部分的に修正されます。 一部の位置にはすでに特定の値が含まれていますが、ゼロは未知の値を表します。 固定エントリと個別中央値条件の両方を満たす完全な順列の数を数えなければなりません。 

の合計額`n`すべてのテストケースにわたって、`2 · 10^5`、これはすぐに次のことを示唆しています。`O(n)`または`O(n log n)`テスト ファイルごとのソリューションが必要です。 二次関数はすべて絶望的です。`n^2`すでにそこら中にあるだろう`4 · 10^10`操作。 

微妙な点は、このステートメントが両方のことを保証していることです。`1`そして`n`部分的に既知の配列に現れます。 これら 2 つの値はランダムではありません。 それらの位置は、すべての有効な起動順序の幾何学的構造を一意に決定します。 カウントに関する議論全体がそれらを中心に構築されています。 

簡単な間違いの 1 つは、未知の値を独立して扱うことです。 考慮する：```
n = 5
0 5 4 1 0
```互換性のある順列は 2 つだけですが、どちらも反復中央値を作成するため、答えは次のようになります。`0`。 固定値の局所的な一貫性だけを見ると、これを完全に見逃してしまいます。 

もう 1 つの簡単な間違いは、ポジションが の位置から任意の左右の展開でアクティブ化される可能性があると想定することです。`1`。 例えば：```
n = 7
0 0 1 0 0 7 0
```一見すると、多くの拡張オーダーが可能であるように見えます。 実際には、個別中央値制約によって 2 つの固定位置チェーンのみが残り、残りの自由は単にそれらのチェーンがどのようにインターリーブされるかだけです。 

## アプローチ

 ブルートフォースソリューションでは、すべてのゼロを考えられるすべての欠損値で埋め、すべての互換性のある順列を生成し、隣接するトリプルのすべての中央値を計算し、結果のシーケンスに重複が含まれているかどうかを確認します。 

未知の位置が 20 個しかないとしても、これはすでに大まかに意味します。`20!`可能性。 探索空間はすぐに爆発します。 

重要な観察は、中央値の状態が最初に見えるよりもはるかに強いということです。 

値を昇順に処理すると、各値は 1 つの位置だけをアクティブにします。 禁止された中央値の繰り返しは、州の禁止されたローカル パターンに変換できます。`0`、`X`、 そして`1`。 これらのパターンを単純化すると、アクティブ化プロセスはほぼ決定的になります。 価値の位置`1`が出発点です。 From there, valid positions split into two chains. One chain walks through positions reachable by repeatedly moving two steps in one direction and bouncing at the borders. もう一方のチェーンは対称的に構築されています。 両方の鎖は次の位置で終了します。`n`。 

からのすべての値`2`に`n-1`これら 2 つのチェーンのいずれかに属している必要があります。 各チェーン内では、相対的な順序は固定されています。 残された唯一の自由は、2 つのチェーンをどのようにインターリーブするかです。 

部分的に既知の配列により、これらのチェーン内の特定の値がどこに出現する必要があるかについて制約が課されます。 これらの制約がチェーンの位置に変換されると、答えは有効なインターリーブをカウントする一連の二項係数計算になります。

 ## アルゴリズムのチュートリアル

 1. 位置を見つける`st`値を含む`1`そしてその位置`ed`値を含む`n`。 
2. 次から始まる最初のチェーンを構築します。`st`。 

移動`-2`繰り返し。 チェーンが到達する前に境界線にぶつかった場合`ed`に達するまで、適切なパリティの位置を左から右、次に右から左に続けます。`ed`。 
3. 2 番目のチェーンを対称的に構築します。 

移動`+2`繰り返し。 境界に到達した後、境界に到達するまで同様のパリティ ウォークを実行します。`ed`。 
4. を除くすべてのポジション`st`そして`ed`2 つのチェーンのうちの 1 つに正確に属します。 
5. 固定値ごとに`v`と`2 ≤ v ≤ n-1`、記録:

 - どのチェーンにその位置が含まれているか、
 - そのチェーン内のランク。 
6. 値を次から昇順に処理します。`2`に`n-1`。 

各チェーンの要素がすでに消費されている数を維持します。 
7. 固定値の場合`v`が発生すると、そのチェーン ランクが強制されます。 

前進しなければならないとします`dt[0]`チェーン上の要素`0`そして`dt[1]`チェーン上の要素`1`置く前に`v`。 

どちらの金額も不可能な場合、答えは次のとおりです。`0`。 
8. 各チェーン内の内部順序を維持しながら、これらの新しく消費されたチェーン要素をインターリーブする方法の数を数えます。 

カウントは$$\binom{dt[0]+dt[1]-1}{dt[c]-1},$$どこ`c`含まれているチェーンです`v`。 
9. 答えにこの二項係数を乗算し、消費された長さを更新します。 
10. すべての固定値を処理した後、2 つのチェーンの残りのサフィックスをインターリーブします。$$\binom{rem_0+rem_1}{rem_0}.$$1. 結果のモジュロを出力します`998244353`。 

### なぜ効果があるのか

 禁止されたローカル パターンにより、すべての有効なアクティベーション注文は、`1`そして`n`。 チェーン内では順序が固定されています。 有効な置換は、これらのチェーンのインターリーブの選択に対応します。 

入力の固定エントリにより、特定のチェーン ランクに特定の値が強制的に表示されます。 値を昇順に処理する際、固定値ごとにインターリーブが独立したセグメントに分割されます。 セグメント内では、各チェーン内の相対的な順序のみが重要であり、有効なマージをカウントすることはまさに二項係数になります。 

セグメント数を乗算すると、グローバルに有効なインターリーブの数、つまり有効な順列の数が求められます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAXN = 400000

fac = [1] * (MAXN + 1)
for i in range(1, MAXN + 1):
    fac[i] = fac[i - 1] * i % MOD

invfac = [1] * (MAXN + 1)
invfac[MAXN] = pow(fac[MAXN], MOD - 2, MOD)
for i in range(MAXN, 0, -1):
    invfac[i - 1] = invfac[i] * i % MOD

def C(n, r):
    if r < 0 or r > n:
        return 0
    return fac[n] * invfac[r] % MOD * invfac[n - r] % MOD

def solve_case():
    n = int(input())
    a = list(map(int, input().split()))

    st = ed = -1
    for i, x in enumerate(a, start=1):
        if x == 1:
            st = i
        if x == n:
            ed = i

    used = [False] * (n + 1)
    used[st] = True

    chains = [[], []]

    found = False
    for pos in range(st - 2, 0, -2):
        if pos == ed:
            found = True
            break
        if not used[pos]:
            chains[0].append(pos)
            used[pos] = True

    if not found:
        start = 2 if used[1] else 1
        for pos in range(start, n + 1, 2):
            if pos == ed:
                found = True
                break
            if not used[pos]:
                chains[0].append(pos)
                used[pos] = True

    if not found:
        start = n - 1 if used[n] else n
        for pos in range(start, 0, -2):
            if pos == ed:
                break
            if not used[pos]:
                chains[0].append(pos)
                used[pos] = True

    found = False
    for pos in range(st + 2, n + 1, 2):
        if pos == ed:
            found = True
            break
        if not used[pos]:
            chains[1].append(pos)
            used[pos] = True

    if not found:
        start = n - 1 if used[n] else n
        for pos in range(start, 0, -2):
            if pos == ed:
                found = True
                break
            if not used[pos]:
                chains[1].append(pos)
                used[pos] = True

    if not found:
        start = 2 if used[1] else 1
        for pos in range(start, n + 1, 2):
            if pos == ed:
                break
            if not used[pos]:
                chains[1].append(pos)
                used[pos] = True

    len0 = len(chains[0])
    len1 = len(chains[1])

    chain_id = [-1] * (n + 1)
    rank_in_chain = [-1] * (n + 1)

    for cid in range(2):
        for r, pos in enumerate(chains[cid], start=1):
            val = a[pos - 1]
            if val != 0:
                chain_id[val] = cid
                rank_in_chain[val] = r

    cur = [0, 0]
    ans = 1

    for v in range(2, n):
        if chain_id[v] == -1:
            continue

        cid = chain_id[v]

        if rank_in_chain[v] <= cur[cid]:
            return 0

        dt = [0, 0]
        dt[cid] = rank_in_chain[v] - cur[cid]
        dt[cid ^ 1] = (v - 1) - (cur[0] + cur[1]) - dt[cid]

        if dt[cid ^ 1] < 0:
            return 0

        limit = len0 if (cid ^ 1) == 0 else len1
        if cur[cid ^ 1] + dt[cid ^ 1] > limit:
            return 0

        ans = ans * C(dt[0] + dt[1] - 1, dt[cid] - 1) % MOD

        cur[0] += dt[0]
        cur[1] += dt[1]

    rem0 = len0 - cur[0]
    rem1 = len1 - cur[1]

    ans = ans * C(rem0 + rem1, rem0) % MOD
    return ans

t = int(input())
out = []
for _ in range(t):
    out.append(str(solve_case()))

sys.stdout.write("\n".join(out))
```前処理では階乗と逆階乗が 1 回計算され、すべての二項係数を定数時間で評価できるようになります。 

2 つのチェーン構築ブロックがソリューションの中心です。 それらは、個別中央条件によって強制される独特の位置構造を再現します。 各位置は正確に 1 つのチェーンに割り当てられます。 

すべての固定値について、そのチェーンとランクのみを保存します。 これにより、元の順列問題が 2 つの順序付けられたシーケンスの制約されたマージに変換されます。 

変数`cur`各チェーンの要素の数が、以前に処理された値によってすでに消費されているかを追跡します。 の`dt`値は、マージする必要がある次のセグメントを示します。 二項係数は、内部チェーンの順序を維持しながらセグメントをマージするためのすべての有効な方法をカウントします。 

最後の二項係数は、最後の固定値の後の接尾辞を処理します。

 ## 特殊なケース

 次のことを考慮してください。```
5
0 5 4 1 0
```チェーン構造が価値を強制する`4`互換性のあるすべての補完において 2 つの異なるトリプルの中央値として表示されます。 処理中に、固定値制約が利用可能なチェーン ランクと矛盾し、アルゴリズムがリターンする原因となります。`0`。 

考慮する：```
7
0 0 1 0 0 7 0
```中間値は固定されていません。 このアルゴリズムは制約処理ブランチに入ることはなく、2 つのチェーンのすべての有効なインターリーブを直接カウントします。 結果は`10`。 

考慮する：```
10
1 10 0 0 0 0 0 0 0 0
```の位置`1`そして`10`両方のチェーンを完全に押し込みます。 すべての中間値は、一意の相対順序に従う必要があります。 すべての二項因子が等しい`1`、したがって、答えは次のとおりです`1`。 

すべての条件が特殊な場合のメディアン ロジックとしてではなく、チェーン ランクおよびチェーン マージの制約として表現されるため、アルゴリズムはこれらすべてのケースを均一に処理します。
