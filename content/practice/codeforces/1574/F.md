 ## 問題の理解

## アプローチ

 直接的な総当たりアプローチでは、すべての配列が列挙されます。`a`長さの`m`、そしてそれぞれについて、すべてのサブ配列の出現を 1 回カウントします。`A_i`。 内部のパターンの出現を数える`a`パターンごとにすでに線形になっているため、これはおおよそ次のようになります`O(k * m * total_length_of_patterns)`それは天文学的な大きさです。 パターン マッチングを KMP に減らしても、依然として指数関数的に多くの候補配列をチェックする必要があるため、私たちは救われません。 

重要な観察は、制約が各パターンに対して個別にローカルではなく、グローバルであるということです。重要なのは、パターンがどのように重なり合うかということです。`a`特定の「原子」を連結したように動作します。 これらのアトムは、パターンの接頭辞と接尾辞の間の境界関係によって引き起こされる同値クラスに対応します。 実際、有効な配列の構造は、パターンの重複に関する障害リンク スタイルのオートマトンによって制御されます。 

これは当然、すべてのパターンに対して Aho-Corasick スタイルのオートマトンを構築することになります。 各状態は、あるパターンの接尾辞でもある接頭辞に対応します。 出現に関する制約は、構築中の遷移と許可される状態に対する制限に変換されます。`a`。

 ## アルゴリズムのチュートリアル

 1. 指定されたすべての配列のトライを構築します`A_i`。 各ノードは、何らかのパターンのプレフィックスを表します。 この構造は、すべてのパターンのオーバーラップを明示的にエンコードします。 
2. トライ上の BFS を使用して障害リンクを構築します。 これらのリンクにより、すべてのノードが、何らかのパターンのプレフィックスでもあるその文字列の最長の適切なサフィックスを認識できるようになります。 これは、Aho-Corasick オートマトンの構築で使用されるのと同じ構造です。 
3. 各ノードについて、そこで終了するパターンの数を計算します。 パターンの終了は出現の登録に相当するため、この値は後で間接的にカウント制約に寄与します。 
4. 事前計算遷移関数`go[v][c]`、ノードにいる場合、次のオートマトンの状態がわかります。`v`そして文字を追加します`c`。 これは、トライ エッジと障害リンクをたどることによって取得されます。 
5. DP 状態を定義する`dp[i][v]`長さのプレフィックスを構築する方法の数として`i`配列の`a`オートマトンが次の状態になる`v`加工後`i`文字。 初期状態は root です。`dp[0][root] = 1`。 
6. 各ポジションについて`i`から`0`に`m-1`、すべての状態を遷移: すべての状態に対して`v`そしてどのキャラクターも`c`から`1`に`k`、 アップデート`dp[i+1][go[v][c]] += dp[i][v]`。 これは、パターン一致の追跡中に配列を 1 要素ずつ拡張するすべての方法をカウントします。 
7. 答えは次の合計です。`dp[m][v]`すべての州にわたって`v`なぜなら、最終的なオートマトンの状態は有効な構築された配列に対応するからです。 

### なぜ効果があるのか

 オートマトンは、配列を左から右に構築するときに、出現するすべてのパターンをエンコードします。 ある状態に到達するたびに、パターンの終わりに対応するすべてのサフィックスが暗黙的に登録されます。 障害リンクは、重複する発生が見逃されたり、誤って二重にカウントされたりしないことを保証します。 このオートマトンではすべての有効な配列が 1 つのパスに正確に対応し、すべてのパスが 1 つの配列に正確に対応するため、長さのパスを数えます。`m`有効な配列を正確にカウントします。 

パターンの出現とサブパターンの間の制約は構造的に強制されます。サブパターンの出現はオートマトンの中間ノードに対応し、パターンの出現は終端ノードに対応します。 サフィックス リンクは必要な情報をすべて伝播するため、DP 中に追加の制約チェックは必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

class Node:
    __slots__ = ("next", "link", "out")
    def __init__(self):
        self.next = {}
        self.link = 0
        self.out = 0

def build_aho(patterns, k):
    nodes = [Node()]

    for pat in patterns:
        v = 0
        for x in pat:
            if x not in nodes[v].next:
                nodes[v].next[x] = len(nodes)
                nodes.append(Node())
            v = nodes[v].next[x]
        nodes[v].out += 1

    from collections import deque
    q = deque()

    for c, u in nodes[0].next.items():
        q.append(u)
        nodes[u].link = 0

    while q:
        v = q.popleft()
        for c, u in nodes[v].next.items():
            q.append(u)
            j = nodes[v].link
            while j and c not in nodes[j].next:
                j = nodes[j].link
            nodes[u].link = nodes[j].next.get(c, 0) if j or c in nodes[j].next else 0
        nodes[v].out += nodes[nodes[v].link].out

    # build transitions
    go = [{} for _ in nodes]
    for v in range(len(nodes)):
        for c in range(1, k + 1):
            cur = v
            while cur and c not in nodes[cur].next:
                cur = nodes[cur].link
            if c in nodes[cur].next:
                go[v][c] = nodes[cur].next[c]
            else:
                go[v][c] = 0

    return go, nodes

def solve():
    n, m, k = map(int, input().split())
    patterns = []
    for _ in range(n):
        tmp = list(map(int, input().split()))
        patterns.append(tmp[1:])

    go, nodes = build_aho(patterns, k)

    dp = [0] * len(nodes)
    dp[0] = 1

    for _ in range(m):
        ndp = [0] * len(nodes)
        for v in range(len(nodes)):
            if dp[v]:
                for c in go[v]:
                    ndp[go[v][c]] = (ndp[go[v][c]] + dp[v]) % MOD
        dp = ndp

    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```この実装では、すべてのパターンに対してトライを構築し、すべてのノードが拡張下でサフィックスがどのように動作するかを認識できるように障害リンクを構築します。 DP 層は、このオートマトン上の標準的な状態遷移です。 微妙な実装の詳細は、失敗リンクを介して出力カウントをマージすることです。これにより、重複するパターンの終わりが正しく蓄積されることが保証されます。 遷移表`go`DP がメイン ループ中に障害チェーンを繰り返し通過しないように、事前に計算されます。 

よくある落とし穴の 1 つは、直接エッジが存在しない場合でも、遷移は障害リンクをたどる必要があることを忘れていることです。 別のものは誤って伝播しています`out`これにより、他のパターンのサフィックスであるパターンからの寄与が失われることになります。

 ## 特殊なケース

 主なエッジケースは、あるパターンが別のパターンの接尾辞である場合です。`[1,2]`そして`[1,2,1,2]`。 この場合、障害リンクにより、より長いパターン状態に到達すると、より短いパターン状態も暗黙的に登録されます。 伝播せずに`out`接尾辞リンクを介して値を使用すると、短いパターンの出現は少なくカウントされます。 

もう 1 つのエッジ ケースは、すべてのパターンが単一要素の配列である場合です。 次に、オートマトンはすべてのキャラクターの自己ループを持つ単一のルートに折りたたまれ、DP は単純にカウントされます。`k^m`。 より深い構造を追跡しようとするソリューションは、このケースを複雑にしすぎますが、オートマトンは自然に処理します。
