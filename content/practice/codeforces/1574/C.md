 ## 解決策
 ## 問題の理解

 私たちにはヒーローのチームがあり、それぞれが固定された強さを持っています。 ドラゴンごとに、それと戦うヒーローを 1 人だけ選択し、残りのヒーローはすべて城を守るために残ります。 

ドラゴンには 2 つの要件があります。 選ばれた攻撃者は少なくとも力を持っている必要があります`x`、すべてのディフェンダーの合計戦力は少なくとも`y`。 

ヒーローの強さを高めるためにコインを使うことができます。 各強さのポイントには 1 コインがかかり、各ドラゴンは個別に処理されるため、アップグレードは一時的なものです。 

ドラゴンごとに、一部のヒーローが攻撃要件を満たし、残りのヒーローが防御要件を満たすことができるように、必要なコインの最小数を決定する必要があります。 

この制約により、すべてのドラゴンのすべてのヒーローを検査するソリューションは即座に除外されます。 両方`n`そして`m`到達できる`2 · 10^5`、だから、`O(nm)`アルゴリズムは大まかに実行します`4 · 10^10`これは 2 秒の制限をはるかに超えています。 

ヒーローの強さは次のように大きくなります。`10^12`、防御要件は次のように大きくなる可能性があります。`10^18`。 これは、64 ビット整数演算を使用する必要があることを意味します。 Python はこれを自動的に処理します。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
Heroes: [10]
Dragon: x = 5, y = 100
```攻撃者はすでに攻撃要件を満たしていますが、その英雄が去ると防御者が力を持ちます`0`。 答えは`100`、 ない`0`。 攻撃するヒーローだけに焦点を当てると、間違った結果が生じます。 

考慮する：```
Heroes: [5, 100]
Dragon: x = 50, y = 5
```攻撃力のアップグレードが必要ないため、最強のヒーローを選択するのは魅力的に思えます。 でもディフェンダーには力がある`5`、これで十分です。 コストは`0`。 

代わりにヒーローを選択した場合`5`、必要です`45`攻撃力に達するまでのコイン`50`。 攻撃者の選択は重要です。 

もう一つの微妙なケース:```
Heroes: [4, 8]
Dragon: x = 6, y = 100
```ヒーローの選択`8`費用:```
attack = 0
defense = 100 - 4 = 96
total = 96
```ヒーローの選択`4`費用:```
attack = 6 - 4 = 2
defense = 100 - 8 = 92
total = 94
```一番近くにいる主人公`x`常に最適であるとは限りません。 場合によっては、攻撃者により多くの費用を支払うことで防御者が強化され、総コストが削減されることがあります。 

これらの例は、どのヒーローが攻撃者になるかを慎重に評価する必要があることを示唆しています。 

## アプローチ

 ブルートフォースのアイデアは単純です。 ドラゴンごとに、すべてのヒーローを攻撃者として試してください。 

ヒーローの強さがあるとします。`a[i]`そしてすべての英雄の強さの合計は`S`。 

このヒーローが攻撃すると、防御側が貢献します`S - a[i]`。 

攻撃要件には次のコストがかかります。```
max(0, x - a[i])
```防衛要件には次のコストがかかります。```
max(0, y - (S - a[i]))
```合計コストは、これら 2 つの値の合計です。 

すべてのヒーローをチェックすると、考えられるすべての攻撃者を明示的に評価し、最小限のものを取得するため、正しい答えが得られます。 残念ながら、各クエリには`O(n)`仕事。 と`2 · 10^5`英雄と`2 · 10^5`ドラゴン、これはおおよそになります`4 · 10^10`評価。 

重要な観察は、コスト関数が非常に構造化された方法で変化するということです。 

英雄に力を持たせよう`h`。 

The attack contribution is:```
max(0, x - h)
```として`h`増加すると、この量は減少します。 

守備貢献度は以下の通りです。```
max(0, y - (S - h))
```これは次と同等です。```
max(0, y - S + h)
```として`h`増加すると、この量が増加します。 

ある部分はより大きなヒーローを好み、もう 1 つは小さなヒーローを好みます。 

これは、攻撃要件が満たされていない状態から満たされた状態に変化する点の近く、つまり強度の付近で最適化が発生することを意味します。`x`。 

ヒーローを並べ替えた後、少なくとも次の強さを持つ最初のヒーローを二分探索できます。`x`。 

よりもはるかに小さいヒーローは、`x`追加の攻撃コインが必要です。 よりもはるかに大きなヒーローは、`x`守備側を不必要に弱体化させます。 最小値は、最も近いヒーローの間でのみ発生します。`x`。 

具体的には、以下を確認するだけで済みます。 

1. 少なくとも強さを持った最初のヒーロー`x`。 
2.その直前の主人公。 

他のすべての候補者に勝つことができるのはこれらの候補者だけです。 

各クエリは 1 つのバイナリ検索と 2 つの評価になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | 最適 | O(n log n + m log n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのヒーローの強さを読み取り、合計の強さを計算します`S`。 
2. ヒーローの強みを並べ替えます。 

並べ替えにより、ヒーローの強さの二分探索が可能になります。 
3. ドラゴンごとに`(x, y)`、少なくとも次の強さを持つ最初のヒーローを見つけます`x`。 

二分探索を使用する (`bisect_left`）。 
4. そのようなヒーローが存在する場合、そのヒーローをアタッカーとして評価します。 

攻撃要件はすでに満たされているため、攻撃コストはゼロになる可能性があります。 防御コストは次のとおりです。```
max(0, y - (S - hero))
```5. 二分探索位置の直前にヒーローがいる場合は、そのヒーローも評価します。 

この英雄は以下の最強の英雄です`x`。 攻撃のアップグレードが必要な場合があります。```
max(0, x - hero)
```さらに防御力のアップグレードも。 
6. 評価された候補の中から最小コストを取得します。 
7. クエリに対する回答を出力します。 

### なぜ効果があるのか

 攻撃するヒーローに力を持たせる`h`。 

費用は```
f(h) =
max(0, x - h)
+
max(0, y - (S - h))
```最初の項は次のように減少します`h`が増加します。 第 2 項は次のように増加します`h`が増加します。 

以下のヒーローについては`x`、より大きなヒーローに移動しても、第 1 項は増加せず、第 2 項は徐々にしか増加しません。 以下の最高のヒーロー`x`以下の中で一番大きいのは`x`。 

少なくとも英雄にとっては`x`、最初の項はゼロになります。 このようなヒーローの中で、より大きなヒーローを選択すると、防御側が弱くなるだけで、決して役に立ちません。 少なくとも最高のヒーロー`x`少なくとも最小のものです`x`。 

分類してみると、この 2 人の英雄はまさに先代と後継者です。`x`ソートされた配列内。 他のすべてのヒーローはこれらの候補のいずれかによって支配されているため、これら 2 つの可能性のみをチェックすると、常に最適なものが見つかります。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

a.sort()
total = sum(a)

m = int(input())

for _ in range(m):
    x, y = map(int, input().split())

    pos = bisect_left(a, x)
    ans = 10**30

    if pos < n:
        hero = a[pos]
        cost = max(0, y - (total - hero))
        ans = min(ans, cost)

    if pos > 0:
        hero = a[pos - 1]
        cost = max(0, x - hero) + max(0, y - (total - hero))
        ans = min(ans, cost)

    print(ans)
```最初の部分ではヒーローを分類し、彼らの総力を計算します。 合計はクエリごとに再利用されるため、防御側の強さを次のように即座に計算できます。`total - hero`。 

ドラゴンごとに、`bisect_left`必要な攻撃値以上の強さを持つ最初のヒーローを見つけます。 そのヒーローは、攻撃アップグレードなしで戦うことができる最小のヒーローです。 

敷居以下の最強ヒーローなので前作もチェックしてます。 弱いヒーローはさらに攻撃のアップグレードが必要になりますが、それを補う利点はありません。 

最初の答えは非常に大きな数値に設定されています。 有効な候補者はすべて更新します。 

よくある間違いは、守備側の戦力には攻撃側のヒーローが含まれていないことを忘れていることです。 正しいディフェンダーの強さは、`total - hero`、 ない`total`。 

もう 1 つのよくある間違いは、バイナリ検索の結果のみをチェックし、前の結果を無視することです。 いくつかの最適な解決策では、ヒーローをわずかに下回って選択する必要があります。`x`because the stronger defenders save more coins overall.

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + m log n) | 並べ替えを 1 回実行し、その後クエリごとに 1 回のバイナリ検索を実行します。 
| スペース | O(1) おまけ | ヒーロー配列自体は別として |

 仕分けフェーズのコスト`O(n log n)`。 各ドラゴン クエリは二分探索を実行し、最大 2 つの候補を評価するため、コストがかかります`O(log n)`。 

と`n, m ≤ 2 · 10^5`、これは簡単に制限内に収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
from bisect import bisect_left

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))

    a.sort()
    total = sum(a)

    m = int(sys.stdin.readline())

    out = []

    for _ in range(m):
        x, y = map(int, sys.stdin.readline().split())

        pos = bisect_left(a, x)
        ans = 10**30

        if pos < n:
            hero = a[pos]
            ans = min(ans, max(0, y - (total - hero)))

        if pos > 0:
            hero = a[pos - 1]
            ans = min(
                ans,
                max(0, x - hero) +
                max(0, y - (total - hero))
            )

        out.append(str(ans))

    return "\n".join(out) + "\n"

7 9
4 14

8 7
"""
