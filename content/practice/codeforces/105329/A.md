 ## 問題の理解

 キャンディーの山は 3 つ与えられ、各山は独立して変更しないままにすることも、1 回だけ 2 倍にすることもできます。 これらの操作を選択すると、3 つの山すべてのキャンディーの合計数が固定されます。 問題は、この最終的な合計を 3 人で均等に割り切れる、つまり合計が 3 で割り切れるようにすることができるかどうかです。 

したがって、実際の決定は、山をどのように分割するかではなく、結果の合計が可算条件を満たすように、2 倍にする山のサブセットを選択できるかどうかです。 

各山には元の状態または倍増された状態の 2 つの状態しかないため、最終的な合計は少数の組み合わせから形成できます。 目的は、少なくとも 1 つの組み合わせの合計が 3 で割り切れるかどうかを確認することです。 

制約は小さく、各値は最大 1000 であるため、すべての組み合わせを列挙する推論は実質的に定数時間になります。 8 つの可能性すべてを単純にチェックするだけでも、時間制限があれば簡単です。 重要なのは、その構造が 3 つの独立した要素に対する二者択一であることを認識することです。 

よくある間違いは、合計が 3 で割り切れる場合にのみ分配が可能であることに気づかず、最後にキャンディーを均等に分配することに重点を置くことです。もう 1 つの間違いは、各山を個別に局所的に推論しようとすることですが、割り切れる可能性は全体的な合計にのみ依存します。 

微妙なエッジ ケースは、元の合計がすでに 3 で割り切れる場合です。この場合、答えは何も操作せずにすぐに YES になります。 もう 1 つのエッジ ケースは、1 つの特定の 2 倍の組み合わせだけで可分性が修正される場合です。たとえば、大きさが小さくてもパリティの変化が重要な小さな入力などです。

 ## アルゴリズムのチュートリアル

 選択肢を 2 倍に割り当てた結果、合計が 3 で割り切れるかどうかを判断したいと考えています。 

1. 初期の山を表す 3 つの整数を読み取ります。 
2. 倍増する杭のすべてのサブセットを列挙します。 各サブセットは、0 から 7 までのバイナリ マスクを表します。 
3. サブセットごとに、杭が選択されているかどうかに応じて、元の値または 2 倍の値を加算して合計を計算します。 
4. この合計が 3 で割り切れるかどうかを確認します。 
5. いずれかの構成が条件を満たす場合は、すぐに YES を返します。 
6. 何もない場合は、NO を返します。 

この手順で十分である理由は、すべての有効な操作シーケンスが杭の 1 つのサブセットに正確に対応するためです。 他に許可される操作がないため、列挙は完了します。 

### なぜ効果があるのか

各パイルは x または 2x に貢献します。 これは、達成可能なすべての最終合計が、x + y + z に x、y、z の一部を再度加算したものになることを意味します。 アルゴリズムは、そのような線形結合をすべて暗黙的にチェックします。 3 で割り切れるかどうかは最終合計にのみ依存し、考えられるすべての最終合計がテストされるため、有効な解が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

x = int(input())
y = int(input())
z = int(input())

vals = [x, y, z]

for mask in range(8):
    total = 0
    for i in range(3):
        if mask & (1 << i):
            total += 2 * vals[i]
        else:
            total += vals[i]
    if total % 3 == 0:
        print("YES")
        sys.exit()

print("NO")
```実装では、ビットマスクを使用してサブセット列挙を直接エンコードします。 各ビットは、山が 2 倍になるかどうかを示します。 0 から 7 までのループは、構成を見逃すことなくすべての可能性をカバーします。 

有効な構成が見つかると、他のサブセットのチェックを続ける必要がないため、早期に終了することが重要です。 これにより、定数係数がすでに小さい場合でも、ソリューションがクリーンな状態に保たれ、不必要な計算が回避されます。

    import sys

    y = int(input())

# custom cases

 ## 特殊なケース

 1 1 1 のような最小の場合は、常に割り切れる合計 3 が生成されるため、アルゴリズムは最初のマスクですぐに YES を返します。 たとえそれ以降のマスクがすべて不要であっても、列挙により正確さが確認されます。 

1 1 2 のようなケースは失敗を示しています。 元の合計は 4 で、サブセットを 2 倍すると、合計は 4、5、6、7、6、7、8、9 になります。 3 で割り切れるのは 6 と 9 だけですが、慎重に確認すると、演算の解釈によっては、列挙で有効な構成が存在するかどうかがキャプチャされることがわかります。 このアルゴリズムは、少なくとも 1 つのマスクが機能するかどうかを正確に識別します。 

1000 1000 1000 などの大きな等しい値は、すべての計算が小さな定数範囲内に留まるため、動作は変わりません。 可分性チェックは大きさには影響を受けず、列挙によって保持されるモジュール構造にのみ影響されます。
