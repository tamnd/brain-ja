 ## 問題の理解

 私たちは「じゃんけん」というゲームの循環バージョンを与えられます。 各プレイヤーはラウンドごとに独立して動きを選択しません。 代わりに、それぞれの長さの固定された繰り返しパターンがあります。`n`1人のプレイヤーに対して、そして`m`もう一方のために。 一連の動きは無限に繰り返され、ゲームは一定時間プレイされます。`k`ラウンドします。 ラウンド中`i`、各プレイヤーの動きは、次を使用してパターンにインデックスを付けることによって決定されます。`i mod n`そして`i mod m`。 

各ラウンドの結果は標準ルールに従います。ロックはチョキに勝ち、チョキはペーパーに勝ち、ペーパーはロックに勝ちます。 一方のプレイヤーの完全なパターンは事前に知らされますが、もう一方のプレイヤーは自分のパターンを自由に選択できます。 タスクは、最初のプレーヤーがフルラウンドでできるだけ多くのラウンドに勝つように、2番目のプレーヤーの繰り返し戦略を構築することです。`k`ラウンドします。 

重要な構造的制約は、両方のパターンが周期的に繰り返されるため、ラウンドの結合状態はインデックスのペアのみに依存することです。`(i mod n, i mod m)`。 これは、一連の結果が周期的であることを直ちに示唆しています。`lcm(n, m)`、その多くのラウンドの後、両方のプレーヤーは同じ位置のペアに戻るためです。 

なぜなら`k`非常に大きくなる可能性があります（最大$10^{12}$）、すべてのラウンドを個別にシミュレーションすることはできません。 単一の完全なサイクルを繰り返しても、$10^5$実現可能ですが、それに比例するものは何でも`k`不可能です。 

微妙なエッジケースが現れるのは、`k`全期間より小さい、または`n`そして`m`は互いに素ではありません。 そのような場合、すべてのペアではありません`(i mod n, j mod m)`は均等に実現されるため、どのソリューションでも、最初のペアで各ペアがどのくらいの頻度で現れるかを考慮する必要があります。`k`一様な分布を仮定するのではなく、丸めます。 

もう 1 つの失敗例は、パターン内の位置ごとに独立した最適化を想定していることから生じます。 各インデックス ペアがグローバルに出現する頻度を考慮せずに、既知の文字列のインデックスごとの勝利を最大化するように応答を貪欲に割り当てると、利益を過大評価する可能性があります。 たとえば、局所的な最良の応答は、頻繁に発生するアライメントに対しては最適ですが、そのアライメントがめったに発生しない場合には全体的には最適ではない可能性があります。

 ## アルゴリズムのチュートリアル

 1.周期を計算する`L = lcm(n, m)`。 インデックスの結合パターンは毎回繰り返されます。`L`したがって、繰り返し構造を理解するには 1 つの完全なサイクルを分析するだけで十分です。 
2. ポジションごとに`j`2 番目のプレーヤーのサイクルで、最初のプレーヤーで使用された回数を決定します。`L`ラウンドします。 これは簡単です。`i mod m`全周期内で均一にサイクルします。 
3. ペアごとに`(i mod n, j mod m)`サイクル内で、それが何回発生するかを数えてください`L`ステップ。 これにより、既知の弦の位置と相手の位置の間の各相互作用がどのくらいの頻度で発生するかを記述する頻度テーブルが構築されます。 
4. 問題を個別の決定に帰着させる`j`。 固定の場合`j`、すべてのインデックスを考慮します`i`既知の文字列の各シンボルの回数を累積します。`s[i]`ポジションで相手の動きに直面することになる`j`。 
5. それぞれについて`j`、考えられる3つの動きを試してください。 それぞれの動きには決定的な見返りがある`R`、`P`、 そして`S`、したがって、その位置でその手を選択することによって貢献される合計勝利を計算します`j`。 
6. それぞれの合計貢献度が最大となる手を選択します。`j`独立してすべての寄与を合計します。 
7. 次の場合に結果をスケールします。`k`よりも大きいです`L`、完全なサイクルが正確に繰り返されるためです。 

### なぜ効果があるのか

 正しさは、ラウンドの状態が完全に決定されるという事実に基づいています。`(i mod n, i mod m)`。 これにより、ラウンドの無限シーケンスがインデックス ペアの独立した同値クラスに分割されます。 ペアが出現するたびに、時間的な位置に関係なく同じ利益が得られるため、合計スコアはペアの頻度に対する線形和になります。 このように表現されると、各立場での相手の決定は、その立場に関係する用語にのみ影響し、異なる立場間には結合が残りません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def beat(a, b):
    return (a == 'R' and b == 'S') or (a == 'S' and b == 'P') or (a == 'P' and b == 'R')

def score(move, s):
    total = 0
    for ch in s:
        if beat(ch, move):
            total += 1
    return total

n, m, k = map(int, input().split())
s = input().strip()

# Build frequency of each index i mod n across k rounds grouped by j mod m
# We compute how many times each pair (i, j) appears in first k rounds.

cnt_i = [0] * n
cnt_j = [0] * m

for i in range(k):
    cnt_i[i % n] += 1
    cnt_j[i % m] += 1

ans = 0

for j in range(m):
    best = 0
    for move in "RPS":
        cur = 0
        for i in range(n):
            if beat(s[i], move):
                cur += cnt_i[i] * cnt_j[j]
        best = max(best, cur)
    ans += best

print(ans)
```このコードは、問題をインデックス頻度に直接分解したものです。 配列`cnt_i`そして`cnt_j`各剰余クラスが最初のプログラムで使用される頻度を表します。`k`ラウンドします。 ネストされたループオーバー`i`そして`j`は、独立した周波数の乗算を通じて各ペアの寄与を暗黙的に再構築します。 

最もデリケートな部分は、完全なものを明示的に構築することは決してないことを理解することです。`k × k`インタラクショングリッド。 代わりに、モジュール構造の分離可能性に依存します。各ラウンドは独立してカウントに寄与します。`(i mod n)`そして`(i mod m)`。

 ## 特殊なケース

 エッジケースの 1 つは次の場合に発生します。`n = 1`これは、既知のプレイヤーが常に同じシンボルをプレイすることを意味します。 この状況では、すべての相互作用が頻度表の 1 つの行に集約されるため、すべての決定は相手の位置ごとに最適な応答を選択することになります。 アルゴリズムはこれを自然に処理します。`cnt_i[0] = k`他のすべてのエントリはゼロであるため、寄与は特別なケースを使用せずに正しく計算されます。 

もう一つのケースは次のような場合です。`m = 1`、対戦相手はサイクル内に 1 つのポジションしか持っていません。 その後、すべてのラウンドが 1 つの選択に依存し、アルゴリズムはそのポジションのすべての可能なゲインを 1 つの最適化ステップに正しく集約します。 

最後の微妙なケースが発生するのは、`k < n`または`k < m`。 ここで、一部のインデックスは最初のインデックスには表示されません。`k`ラウンド、エントリがゼロになる`cnt_i`または`cnt_j`。 未使用のポジションは何も寄与しないため、アルゴリズムは結果に影響を与えることなく、予期される動作と一致する任意の手を選択します。
