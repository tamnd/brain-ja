 ## 解決策
 ## 問題の理解

 各生徒は、0 から n までの線分上の固定整数の位置から開始します。 時間 0 で、すべての生徒は方向を独立して選択します。0 に向かって左方向、または n に向かって右方向のいずれかです。それぞれの方向は 2 分の 1 の確率で選択されます。 その後、選択した方向に 1 秒あたり 1 歩ずつ移動します。 2 人の学生が出会うと、即座に方向を交換します。これは、ラベルのない粒子としての軌道だけを考慮する場合、学生がお互いを通過するのと同じです。 

私たちが実際に気にするのは、指定された制限時間 t 以内に生徒が境界線 (位置 0 または位置 n) に到達するかどうかだけです。 各クエリ時間 t について、その時間までに誰もセグメントから離れていない確率が必要です。 この問題では、この確率が 0 または 2 の逆乗のいずれかであることが保証されているため、答えは確率が 2^{-m} になるような指数 m 、またはイベントが不可能な場合は -1 になるだけです。 

衝突ルールは、簡略化の重要なポイントです。 衝突ではアイデンティティが交換されるだけであるため、各生徒は退出するまで、選択した方向に独立して移動しているかのように動作します。 したがって、プロセス全体は生徒ごとに独立したランダムな決定に帰着し、各選択が t 秒以内に終了につながるかどうかを推論するだけで済みます。 

この制約により、クエリごとの単純なシミュレーションは不可能になります。 最大 10^5 の学生と 10^5 のクエリを使用する場合、クエリごとにすべての学生を再計算するソリューションでは、最悪の場合でも約 10^10 の演算が必要になりますが、これは制限をはるかに超えています。 

素朴な推論による微妙な失敗のケースは、生徒がエンドポイントに近づいたときに現れます。 たとえば、生徒が位置 1 にいて t が 1 の場合、左を選択するとすぐに終了するため、有効な方向は 1 つだけです。 真ん中の遠くにいる別の生徒は、どちらの方向でも安全である可能性があります。 安全な方向が全く分からない生徒がいる場合、たとえ他の生徒が大丈夫だったとしても、答えは即座に確率ゼロでなければなりません。 この全体的な不可能条件を欠くと、不正確な非ゼロ出力が発生します。 

## アプローチ

 効率を無視する場合、直接的なアプローチは、各クエリを個別にシミュレートすることです。 すべての生徒について、左に進むと t 秒以内に 0 に到達するかどうか、右に進むと t 秒以内に n に到達するかどうかを確認します。 両方の方向で終了が発生する場合、確率はゼロです。 それ以外の場合は、特定の方向を選択することを余儀なくされた生徒の数を数えます。 強制された選択はそれぞれ 2 分の 1 の係数を与えるため、指数 m はまさに強制された生徒の数になります。 

このアプローチは正しいですが、q 個のクエリごとに O(n) スキャンを繰り返すため、合計の複雑さは O(nq) になります。 最大の制約がある場合、これは実行不可能になります。 

重要な観察は、各生徒の行動が 2 つの固定値 (左端点までの距離と右端点までの距離) のみに依存するということです。 固定時間 t について、これら 2 つの値の t との比較を使用して各生徒を分類します。 これにより、問題は静的配列に対する範囲カウントのクエリに応答することに変わります。 

これを認識すると、問題は前処理タスクになります。 すべての左の距離と右の距離を保存し、それらを並べ替えて、二分探索でしきい値のクエリに答えることができます。 残りの微妙な点は、両方の方向が同時に無効であることを検出することです。これは、両方の距離が最大 t であるかどうかによって決まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース | O(nq) | お(1) | 遅すぎる |
 | ソート + 二分検索 | O(n log n + q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各生徒について、左に行く場合は出るまでにかかる時間、右に行く場合は出るまでにかかる時間の 2 つの値を計算します。 左側の終了時間はその位置に等しく、右側の終了時間は n からその位置を引いたものです。 これらの値は、特定のクエリ時間に対して方向が安全かどうかを完全に決定します。 
2. 学生に対して 3 つの配列を定義します。A は左退室時刻を格納し、B は右退室時刻を格納します。C は各学生の 2 つの退室時刻のうち良い方を格納します。これは、C[i] がその学生が可能な限り最適な方向の選択の下で退校するまでの最小時間であることを意味します。 この C は、不可能なケースを検出するのに役立ちます。 
3. クエリ時間 t に対して、A[i] と B[i] を t と比較することによって生徒を分類します。 2 つの方向のうちの 1 つだけが安全である場合、つまり A[i] > t および B[i] > t のいずれかが正確に成立する場合、スチューデントは強制されます。 
4. 強制された選択肢を数える前に、A[i] <= t および B[i] <= t を持つ生徒がいるかどうかを確認します。 このような生徒には有効な方向性がまったくないため、イベントは不可能であり、答えは -1 です。 
5. これらの量を効率的に計算するには、A、B、C を別々に並べ替えます。 クエリごとに、二分探索を使用して、各配列内に最大 t の要素がいくつあるかを数えます。 これらのカウントにより、必要なすべてのカテゴリを再構築できます。 
6. A[i] <= t の生徒の数を cntA、B[i] <= t の場合は cntB、C[i] <= t の場合は cntC とします。 すると、cntC はまさに不可能な生徒の数になります。 cntC がゼロ以外の場合、-1 を出力します。 
7. それ以外の場合は、強制生徒を、A[i] <= t または B[i] <= t のいずれかが false である生徒として計算します。 これは、(cntB - cntC) + (cntA - cntC) に等しくなります。 最後の指数 m は、この強制カウントです。 

### なぜ効果があるのか

 各学生は、時間 t までに退出を回避するという制約の下で、方向が固定であるか自由であるかに応じて、1 または 1/2 の係数を個別に寄与します。 独立性は、終了時間の観点から相互作用を効果的に除去する衝突ルールから得られます。 確率がゼロになる唯一の方法は、一部の生徒が有効な指示を持っていない場合であり、これは両方の退出時間が最大 t であることで正確に把握されます。 他のすべての生徒は乗算的に貢献するため、指数は単に強制された決定の数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
a = list(map(int, input().split()))

A = a
B = [n - x for x in a]
C = [min(A[i], B[i]) for i in range(n)]

A.sort()
B.sort()
C.sort()

def count_leq(arr, x):
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] <= x:
            lo = mid + 1
        else:
            hi = mid
    return lo

out = []
for _ in range(q):
    t = int(input())

    cntA = count_leq(A, t)
    cntB = count_leq(B, t)
    cntC = count_leq(C, t)

    if cntC > 0:
        out.append("-1")
        continue

    forced = (cntA + cntB)
    out.append(str(forced))

print("\n".join(out))
```配列 A と B は、各生徒の 2 つの独立した退室クロックをエンコードします。 並べ替えにより、各クエリを完全スキャンではなく 2 分検索のペアにすることができます。 

アレイ C は、無効な構成に対する重要な防御手段です。 両方の退出時間が t 以内の学生がいる場合、その学生には退出を回避する有効な初期方向の選択がないため、確率はゼロになります。 

最終的な式は、cntC が 0 に等しい条件下でのみ機能します。 その場合、すべての生徒には少なくとも 1 つの安全な方向があり、ちょうど 1 つの方向が安全でないたびに、指数に 1 つの強制ビットが寄与します。 

よくある実装上の間違いは、cntC を 2 回誤って減算したり、C が別個のカテゴリではなく 2 つのしきい値の共通部分を表すことを忘れたりすることです。 

## 実用的な例

 n が 7 で、生徒が 2、3、5 番目の位置にある小規模な構成を考えてみましょう。 

### 例 1

 A は [2, 3, 5]、B は [5, 4, 2]、C は [2, 3, 2] として計算します。 

クエリ t = 2 の場合、しきい値カウントは次のとおりです。 

| 配列 | ≤ t カウント |
 | --- | --- |
 | あ | 1 |
 | B | 1 |
 | C | 2 |

 cntC がゼロではないため、少なくとも 1 人の生徒が時間 2 以内に両方向に退出する可能性があり、イベントは不可能になります。 出力は -1 です。 これは、交差条件が実行可能性を即座に無効にする方法を示しています。 

### 例 2

 t = 1 の場合、次のようになります。 

| 配列 | ≤ t カウント |
 | --- | --- |
 | あ | 0 |
 | B | 0 |
 | C | 0 |

 生徒が不可能な状況に追い込まれることはなく、どの方向を選択しても時間 1 以内に脱出することはありません。 すべての学生は双方向に安全であるため、強制カウントは 0、確率は 1、つまり m は 0 に等しいことになります。 

この例では、すべての終了時間が t を超えると、システムは確率減衰のない完全な自由状態に退化することが確認されています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + q log n) | 3 つの配列のソートが前処理の大半を占め、各クエリはソートされた配列の二分検索によって回答されます。 
| スペース | O(n) | 3 つの補助配列には終了時刻が格納されます。 

前処理コストは n の線形であり、各クエリは対数です。 n と q が最大 10^5 であるため、これは一般的な時間制限内に問題なく収まります。

 ## 特殊なケース

 すべての生徒が両端に非常に近い位置に座っている場合、すべての生徒が小さな t に対して両方向が危険になる可能性があります。 その状況では、アルゴリズムは直ちに cntC をトリガーし、-1 を出力します。これは、少なくとも 1 人の生徒が退学する必要があるという事実と一致します。 

すべての生徒が中心付近にいる場合、小さい t に対して A と B の両方が大きいため、cntC はゼロのままで、強制カウントはゼロになります。 m が 0 に等しい場合、確率は 1 になります。 

位置が片側に大きく偏ると、A と B の分布が非対称になります。 各カテゴリは順序や形状とは無関係に、純粋にしきい値の比較によって定義されるため、二分探索分離は依然として強制生徒を正しくカウントします。
