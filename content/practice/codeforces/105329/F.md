 ## 解決策
 ## 問題の理解

 1 から n マイナス 1 までの位置のラインが与えられ、最初に数人の生徒がこれらの整数の点に配置されます。 各生徒は、位置 0 に向かって左に移動するか、位置 n に向かって右に移動するかの初期方向を個別に選択します。 その後、各生徒は毎秒ごとに選択した方向に 1 歩ずつ移動し、2 人の生徒が同じ位置で出会うと、あたかも速度を交換したかのように瞬時に方向を逆転させます。 

重要な物理的観察は、同一性を無視した場合、直線上の同一の移動エージェント間の衝突は、相互に通過するものとして解釈できるということです。衝突後の方向の交換は、ラベルを交換して直進を続けることと同等であるためです。 ただし、私たちが気にするのは衝突そのものではなく、学生が所定の時間範囲 t 内に位置 0 または位置 n に到達するかどうかです。 

各クエリ時間 t について、時間 t までに生徒がセグメント [0, n] から出ていない確率を計算するように求められます。 答えはゼロか正確な 2 分の 1 乗であることが保証されているため、確率の代わりに、確率が 2 の乗から m を引いた値、または確率が 0 の場合はマイナス 1 に等しくなるような指数 m を出力します。 

n が 100000 まで、q が 100000 までという制約は、動きをシミュレートしたり、ペアごとの相互作用を明示的に処理したりするソリューションは不可能であることを意味します。 クエリあたり O(n log n) でも遅すぎるため、目的のソリューションでは、およそ O(n log n) または O(n) で 1 回前処理し、O(1) または O(log n) で各クエリに応答する必要があります。 

複数の生徒が同じ位置から始めると、微妙な特殊なケースが発生します。 複数の生徒が 1 つの座標を占有する場合、生徒の相対運動は方向の選択のみに依存します。 それらの間の衝突は終了イベント構造を変更しませんが、即時終了が可能かどうかに影響を与える可能性があります。 もう 1 つのデリケートな状況は、生徒が境界線の非常に近くからスタートする場合です。これは、たった 1 つの不利な方向の選択でも、数秒以内に即時に終了する可能性があり、t が十分に大きい場合、確率がゼロに低下する可能性があるためです。 

素朴な誤解は、学生が出口に関して独立して行動すると仮定することですが、衝突によって軌道が結合されるため、これは失敗します。 もう 1 つの間違ったアプローチは、それらを相互作用しない粒子として扱い、各生徒の生存確率を個別にカウントすることです。 衝突後の交換により、到達するエンドポイントが変わるため、これは失敗します。 

## アプローチ

 ブルートフォース手法では、すべての 2^k 方向の課題 (k は生徒の数) を列挙し、各課題の動作をシミュレートし、時間 t 以内に退出する生徒がいるかどうかを確認します。 k は最大 100000 になる可能性があり、2^k は天文学的に大きいため、中程度の k の場合でもこれは不可能です。 割り当てごとのシミュレーションに削減するだけでもすでに O(n t) のコストがかかりますが、これは限界をはるかに超えています。 

重要な洞察は、同一速度の一次元線上での衝突は、時間の経過とともに複数の位置セットに影響を与えないということです。 アイデンティティを並べ替えるだけです。 生徒が退出するかどうかという観点から見ると、衝突は無関係です。なぜなら、退出は最初のパスが t ステップ以内の境界につながるかどうかのみに依存し、これは生徒の相対的な順序と境界までの距離にのみ依存するからです。

問題を再構成すると、各生徒は制約を与えます。左向きの場合、a_i ステップで 0 に達します。 右を向いている場合は、n から a_i を引いたステップで n に到達します。 問題は、衝突によって学生がリダイレクトされ、事実上、ローカル グループ内の別の学生と同じように動作する可能性があることです。 重要な観察は、占有ポジションの最大連続ブロック内では、可能な出口イベントのセットはそのブロック内の極端なポジションにのみ依存するということです。これは、内部スワップでは可能な限り最も早い出口イベントを防ぐことはできず、それをトリガーする人物を並べ替えるだけであるためです。 

したがって、問題は、方向の割り当てに関係なく、位置ごとに t 内に決定論的な強制終了が存在するかどうかを識別することに帰着します。 このような強制終了が存在する場合、その可能性はゼロです。 それ以外の場合、ランダム性は特定の「重要な」境界選択での独立した選択に減少し、各制約は事実上 1 つの独立したビットを固定し、2 の乗から m を引いた確率が生成されます。ここで、m は独立した必要な方向制約の数を数えます。 

最終的な構造は、各位置が最大 1 つの独立した 2 値制約に寄与し、t 内での終了を防ぐために必要な「ブロッキング条件」の数に応じて、答えがプレフィックスで計算可能な値になります。

 | ブルートフォースシミュレーション | O(2^n · n) | O(n) | 遅すぎる |
 | 最適な間隔制約のカウント | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 学生のポジションの配列を処理し、ソートされたポジションのマルチセットに変換します。 衝突ではスワップを除いて相対的な順序が維持されるため、順序が重要となるため、隣接情報のみが必要になります。 

生徒の位置 x ごとに、2 つの潜在的な退出時間を計算します。左側の境界までの x ステップと、右側の境界までの n マイナス x ステップです。 対応する退出時間が最大 t である方向が割り当てられた場合、生徒は時間 t 以内に退室します。 

次に、時間 t までに退場を避けるためには、最小退場時間が最大でも t であるすべての生徒が、より安全な方向を選択する必要があることがわかります。 これにより、そのような生徒ごとに制約が生じます。 

ただし、複数の生徒が同じ位置を共有する場合、または強制構造で間隔が重なる場合、制約は独立していません。 これを解決するために、位置によって学生を分類し、左から右にスイープして、連続する「危険な」学生、つまり少なくとも 1 つの方向が t 以内に退出する学生をグループ化します。 

各グループ内で、両方の境界制約が同時にアクティブであるかどうかを追跡します。 学生の両方の方向が t 以内に退出する場合、その学生は方向に関係なく常に退出するため、確率は直ちにゼロになり、出力は 1 減ります。 

それ以外の場合、各危険グループは、独立した 2 つの決定を 1 つだけ提供します。つまり、必要なすべての左寄りの選択が行われるか、または必要なすべての右寄りの選択が衝突構造と一致して行われるかのいずれかです。 指数 m は、そのような独立したグループの数です。 

しきい値 t に対するそのようなグループの数を再計算することで、各クエリに答えます。 

### なぜ効果があるのか

 不変条件は、時間 t までに出口を引き起こす可能性のある位置の最大の連続セグメント内では、衝突によるすべての内部再配置は出口が発生するかどうかに関わらず変わらないということです。 どの生徒が境界に到達するかを変更するだけです。 したがって、生存に影響を与える唯一の自由度は、セグメント全体が逃げる軌道を生成するのを防ぐ選択であり、そのような各セグメントは、正確に 1 つの独立した 2 値制約に寄与します。 これにより、セグメントに避けられない出口が含まれない限り、確率空間が 2 の乗からセグメント数を引いたものに因数分解されることが保証されます。この場合、確率はゼロに崩壊します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    a.sort()

    # Precompute left and right exit times
    left = a
    right = [n - x for x in a]

    for _ in range(q):
        t = int(input())

        # check impossible case: any student must exit regardless of direction
        impossible = False
        for i in range(len(a)):
            if min(left[i], right[i]) <= t:
                # if both directions lead to exit within t, forced exit
                if left[i] <= t and right[i] <= t:
                    impossible = True
                    break

        if impossible:
            print(-1)
            continue

        # count independent constraints
        m = 0
        i = 0
        while i < len(a):
            if min(left[i], right[i]) > t:
                i += 1
                continue

            # start a constrained segment
            m += 1
            j = i
            while j < len(a) and min(left[j], right[j]) <= t:
                j += 1
            i = j

        print(m)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、隣接関係が衝突時の潜在的な相互作用構造を反映するように位置を並べ替えます。 各生徒について、どちらかの境界にどれくらいの速さで到達できるかを事前に計算します。 各クエリについて、まず、両方向とも時間 t 以内に退出するため、必然的に退出する学生が存在するかどうかを検出します。 その場合、すぐにマイナス 1 を出力します。 

それ以外の場合は、ソートされた位置をスキャンして、可能な最小退出時間が最大 t である連続する生徒をグループ化します。 このような各最大グループは、m として数えられる 1 つの独立した 2 値制約に寄与します。 

共通の微妙な点は、別々のグループ間で制約を二重にカウントしないようにすることです。 これは、カウントされたらグループ全体を超えてポインタを進めることによって処理されます。 

## 実用的な例

 n = 7、位置 [2、2、3] の小規模な構成を考えてみましょう。 左側の終了時間は [2、2、3]、右側の終了時間は [5、5、4] です。 

t = 1の場合:

 | 私 | 位置 | 左 | 右 | 分(左,右) | 強制的に？ |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 2 | 2 | 5 | 2 | いいえ |
 | 1 | 2 | 2 | 5 | 2 | いいえ |
 | 2 | 3 | 3 | 4 | 3 | いいえ |

 生徒が退学を強制されることはないため、制約されたセグメントはなく、m = 0、つまり確率は 1 です。 

t = 2の場合:

 | 私 | 位置 | 左 | 右 | 分(左,右) | 強制セグメント |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 2 | 2 | 5 | 2 | はい |
 | 1 | 2 | 2 | 5 | 2 | はい |
 | 2 | 3 | 3 | 4 | 3 | いいえ |

 インデックス 0 から 1 までの 1 つの連続した制約付きセグメントを取得するため、m = 1 となります。 

これは、t がいくつかの位置の境界しきい値を超えると、制約が生徒ごとに独立して動作するのではなく、連続したブロックにマージされることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | この単純な形式での O(n + qn) 最悪のケース | 各クエリは配列をスキャンし、セグメントをグループ化します。 
| スペース | O(n) | 位置と派生配列のストレージ |

 このソリューションは構造を説明するために設計されていますが、厳密な設定での最適化が必要になります。 min(left[i], right[i]) が t に関連して順序を変更するブレークポイントを適切に前処理すると、クエリ時間を O(1) または O(log n) に短縮でき、最大 100000 までの n と q の制約内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()
    left = a
    right = [n - x for x in a]

    out = []
    for _ in range(q):
        t = int(input())
        impossible = False
        for i in range(len(a)):
            if left[i] <= t and right[i] <= t:
                impossible = True
                break
        if impossible:
            out.append("-1")
            continue

        m = 0
        i = 0
        while i < len(a):
            if min(left[i], right[i]) > t:
                i += 1
                continue
            m += 1
            j = i
            while j < len(a) and min(left[j], right[j]) <= t:
                j += 1
            i = j
        out.append(str(m))

    return "\n".join(out)

# custom cases
assert run("7 2\n2 2 3\n1\n2\n") == "0\n1", "basic grouping"
assert run("5 1\n1 2 3\n10\n") == "-1", "forced exit"
assert run("6 1\n2 4 2\n1\n") == "0", "no constraints early"

 | 強制終了 | -1 | 避けられない出口の検出 |
 | 大きい t は効果なし | 0 | 安全な構成の処理 |

 ## 特殊なケース

 重大なエッジケースは、すべての生徒が境界線に非常に近づいている場合です。 たとえば、位置 [1, 1, 1] と小さい n では、t = 1 で両方向が一部の生徒の退場につながり、不可能な条件が引き起こされる可能性があります。 これらの位置では左右の終了時間が最大でも t であるため、アルゴリズムはこれを正しく識別し、すぐに答えをマイナス 1 に設定します。 

もう 1 つのケースは、生徒全員が両方の境界線から遠く離れた内部にいる場合です。 たとえば、すべての位置が t より大きい min(x, n － x) を満たす場合、スキャンでは制約されたセグメントが生成されないため、m = 0 となります。どの方向を選択しても時間ウィンドウ内で終了する可能性がないため、アルゴリズムは確率 1 を正しく返します。
