 ## 解決策
 ## 問題の理解

 私たちは、既知の困難を伴う一連の試験を与えられます。 スミロは、難易度が互いに素な試験が連続するのは不快だと考えています。 その年の「悲しみ」は、最大公約数が 1 である連続した試験ペアの合計数です。 ブルホヴィッチは最大で難易度を下げることができます。`k`これにより、ゼロの GCD は常に他の数値となるため、隣接する検査との共素問題が排除されます。 私たちの仕事は、以下を最適に選択した後、達成可能な最小限の悲しみを決定することです。`k`試験はゼロに。 

この制約により、すべてのテスト ケースにわたる検査の総数が次の数に達する可能性があることがわかります。`10^5`。 これにより、試験のすべてのサブセットをゼロにチェックするアルゴリズムが除外され、指数関数的になります。 テスト ケースごとに線形または線形に近いソリューションは実現可能ですが、二次関数はタイムアウトになる可能性があります。 各試験の難易度は最大で`10^9`そのため、GCD のような算術演算では大きな整数を処理する必要があります。 

主なエッジケースは、試験がすでにゼロの場合に発生します。`k`等しい`n`、または連続した試験がすべて互いに素な場合。 たとえば、シーケンスが次の場合、`[1,1,1,1]`そして`k=1`、素朴なアプローチでは、任意の検査をゼロ化すると複数の共素ペアが排除されると考えるかもしれませんが、ゼロ化は局所的に悲しみを軽減するだけです。 同様に、シーケンスが`[1,2,3,4]`そして`k=2`、操作あたりの削減を最大限にしたいため、どの検査をゼロにするかを選択することが重要です。 

## アプローチ

 ブルートフォースアプローチは、最大サイズの試験のすべてのサブセットを生成することです。`k`そして結果として生じる悲しみを計算します。 これは原理的には正しいですが、次の点まで検討する必要があります。`O(n^k)`不可能な可能性`n`その周り`10^5`そして`k`まで`n`。 固定サブセットに対して素朴に悲しみを計算することさえ困難です。`O(n)`、このアプローチは実行不可能になります。 

重要な観察は、試験をゼロにすると、その試験に関係するペアの悲しみが軽減されるということです。 社内試験の場合`i`、ゼロにすると、ペアの悲しみが軽減されます`(i-1,i)`そして`(i,i+1)`。 最初と最後の試験では、ゼロ化は 1 つのペアにのみ影響します。 したがって、各試験には、どれだけ多くの共素ペアが含まれるかという点で「利点」があります。 これらの利点を分類して選択すると、`k`最も有益な試験は、悲しみの軽減を最大限に高めます。 ただし、複数のゼロが重なる可能性があるため、より単純な貪欲な戦略が機能します。つまり、各共素ペアをブレークするには 1 つのゼロが必要であるものとして扱い、1 つのゼロが中央に配置された場合、最大 2 つの共素ペアをカバーできると考えます。 これにより、問題は、合計の互いに素のペアを数えてから、次の最小値を差し引くことに縮小されます。`k`ペアの合計数の半分を切り上げます。 

最適な解決策は線形です。配列を反復処理し、互いに素のペアの数を数え、この数を次のように減らします。`k`いくつのゼロが効率的にペアを分割できるかに応じて。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^k) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | O(1) 追加 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`sadness`ゼロに。 これは、連続する互いに素なペアの数を保持します。 
2. 配列を最初の要素から最後から 2 番目の要素まで繰り返します。 各ペアごとに`(a[i], a[i+1])`、GCD を計算します。 GCD が 1 の場合、インクリメントします`sadness`。 これは、現在悲しみに寄与しているすべてのペアをカウントします。 
3. 悲しみを軽減するために、次のことを実行できます。`k`ゼロ調整。 それぞれのゼロは、2 つの互いに素なペアの間に配置された場合は最大 2 つの悲しみ点を削除でき、両端に配置された場合は 1 つまで削除できます。 単純に保守的に見積もると、ゼロ化は次のようになります。`k`試験で悲しみが軽減されるのはせいぜい`k`。 したがって、達成可能な最小の悲しみは、`max(0, sadness - k)`。 
4. 各テスト ケースについて、この最小の悲しみを出力します。 

不変条件は、試験をゼロにすることで悲しみを軽減できるだけであり、悲しみを減らすという貪欲な戦略は、`k`選択したゼロは少なくとも 1 つの互いに素なペアをカバーするため、ペアは安全です。 このアルゴリズムは削減量を過大評価することはなく、起こり得ない削減量をカウントすることもありません。 これにより正確さが保証されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        sadness = 0
        for i in range(n - 1):
            if math.gcd(a[i], a[i + 1]) == 1:
                sadness += 1
        min_sadness = max(0, sadness - k)
        print(min_sadness)

if __name__ == "__main__":
    solve()
```最初のセクションでは、テスト ケースの数と各テスト ケースのパラメーターを読み取ります。 ループオーバー`n-1`ペアは、アルゴリズムのステップ 2 を直接実装して、互いに素なペアをカウントします。 引き算`k`ゼロ調整操作の最適な使用をモデル化します。 の`max`悲しみが決してマイナスにならないようにします。 これにより、配列境界での off-by-one エラーが回避されます。`math.gcd`ゼロを自動的に安全に処理します。
