 ## 解決策
 ## 問題の理解

 私たちは、成長する根付きの木に対する一連の操作を処理するように求められます。 ツリーは 1 という番号が付けられた単一のノードから始まり、各ノードには最初は 0 の数値が設定されます。クエリは、既存のノードに新しい子を追加するか、指定されたノードのサブツリー内のすべての値を指定された量だけ増分します。 すべてのクエリの後、ツリー内のすべてのノードの最終値を出力する必要があります。 

入力は複数のテスト ケースで構成され、各テスト ケースには最大 500,000 のクエリが含まれます。 すべてのテスト ケースにわたるクエリの合計が 500,000 を超えないことが保証されます。 値は次のように大きくできます。$10^9$または同じくらい小さい$-10^9$。 これらの制約は、アルゴリズムが以下よりも悪いものであることを意味します。$O(q \log q)$テストケースごとの効率が十分である可能性は低いです。 クエリごとにサブツリー内のすべてのノードを更新する単純なソリューションでは、次のような時間がかかります。$O(nq)$最悪の場合、到達する可能性のある時間$2.5 \cdot 10^{11}$操作が遅すぎます。 

明らかではないエッジ ケースには、それ自体が大きなサブツリーを持つノードに子を追加することや、複数の重複するサブツリーの増分が含まれます。 たとえば、ノード 1 ～ 3 を持つツリーがあり、ノード 1 でインクリメントを実行し、続いてノード 2 でインクリメントを実行する場合、毎回サブツリーを走査する単純なアプローチでは、正しく実装されていない場合、カウントが 2 倍になったり、更新が失われる可能性があります。 もう 1 つのエッジ ケースは、新しいノードを追加し、そのノードに対してサブツリーの増分を即座に実行することです。 アルゴリズムは、将来の増分で新しく追加されたノードを正しく考慮する必要があります。 

## アプローチ

 ブルートフォース手法は簡単です。ツリーの隣接リストを維持し、各ノードの値を保存し、クエリごとにサブツリーを走査して増分を適用します。 これは正しいですが、時間計算量は$O(qn)$各タイプ 2 クエリはサブツリー内のすべてのノードにアクセスする可能性があるためです。 最悪のケースでは、ツリーがスターまたはチェーンであり、すべてのクエリがルートの増分である場合、テスト ケースごとに 5 億回の操作に達しますが、これは非現実的です。 

重要な観察は、サブツリーの増分とツリーの成長が連続した構造を持っていることです。 各ノードは 1 回だけ追加され、ノードが追加されると、その親は決して変更されません。 ツリーは、各ノードの「親」ポインターを持つ配列として表すことができます。 その後、すべてのクエリの後の 1 回の走査で、親から子に値を伝播できます。 サブツリー内のすべてのノードをすぐに更新する代わりに、親で増分を記録し、後でプッシュダウンすることができます。 これは本質的に DFS ベースのプレフィックス伝播です。各ノードはその祖先からの増分を蓄積します。 

各サブツリーを直接更新すると正しい値が得られるため、ブルート フォースは機能しますが、サブツリーが大きく、クエリが多数ある場合は失敗します。 DFS 内で増分を 1 回伝播するだけでよいという観察により、複雑さを軽減できます。$O(nq)$に$O(n+q)$テスト ケースごとに実行されます。これは、指定された範囲に対して効率的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 親ポインター + DFS の伝播 | O(n+q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`parent`どこ`parent[i]`ノードの親を格納します`i`。 配列を初期化する`value`ノード値のゼロ。 セット`children`各ノードの子を追跡するためのリストのリストとして。 
2. タイプ 1 のクエリごとに (頂点に子を追加)`v`)、ツリーのサイズを増やします`sz`1つずつセット`parent[sz] = v`、追加します`sz`に`children[v]`。 これにより、メモリ内のツリー構造が効率的に維持されます。 
3. タイプ 2 (頂点のサブツリーの増分) の各クエリについて`v`による`x`）、 アップデート`value[v] += x`。 まだサブツリーを走査しないでください。 増分を目的のサブツリーのルートに保存します。 
4. すべてのクエリを処理した後、ルート (ノード 1) から開始して DFS を実行します。 各ノードで`u`、すべての子供たちに`c`で`children[u]`、累積された値を伝播します。`value[c] += value[u]`。 次に、子を再帰的に処理します`c`。 これにより、すべてのサブツリーの増分が正しく適用されることが保証されます。 
5. DFS 後、`value`配列にはすべてのノードの正しい値が含まれています。 1から順に出力します。`sz`。 

正確さを保証する不変条件は、各ノードの値が、そのノードまたはその祖先のいずれかに適用されるすべての増分の合計である必要があるということです。 増分をルートに保存し、DFS で一度伝播することで、このプロパティを正確に維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

def solve():
    T = int(input())
    for _ in range(T):
        q = int(input())
        parent = [0]  # 1-indexed, parent[1] unused
        children = [[] for _ in range(q + 2)]
        value = [0] * (q + 2)
        sz = 1

        for _ in range(q):
            line = input().split()
            if line[0] == '1':
                v = int(line[1])
                sz += 1
                parent.append(v)
                children[v].append(sz)
            else:
                v, x = int(line[1]), int(line[2])
                value[v] += x

        def dfs(u):
            for c in children[u]:
                value[c] += value[u]
                dfs(c)

        dfs(1)
        print(' '.join(str(value[i]) for i in range(1, sz + 1)))

if __name__ == "__main__":
    solve()
```このソリューションでは、`parent`子を正しく追加するために維持されますが、子を直接追跡するため、DFS 伝播では使用されません。 事前に割り当てます`children`そして`value`配列を使用してクエリ中の動的なサイズ変更を回避し、パフォーマンスを向上させます。 再帰的 DFS は、増分を親から子に 1 回だけ伝播し、重複するサブツリーの増分を正しく処理します。
