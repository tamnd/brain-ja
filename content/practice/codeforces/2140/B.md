 ## 解決策
 ## 問題の理解

 私たちには番号が与えられています$x$そして、別の正の整数を構築する必要があります$y$特定の割り切り条件が成立するように。 この構造は、次の 10 進表現を連結して新しい数値を形成することに依存します。$x$すぐに続いて$y$。 の桁数で表すと$y$による$k$の場合、この連結された値は次のように書くことができます。$x \cdot 10^k + y$。 

要件は、この連結された数値が合計で割り切れることです。$x + y$。 したがって、条件を強制する必要があります$$x \cdot 10^k + y \equiv 0 \pmod{x + y}.$$有効なデータを生成する以上の最適化は求められていません。$y < 10^9$。 制約により、最大で次のことが許可されます。$10^4$テストケースとそれぞれの$x$以下です$10^8$したがって、あらゆる構築はテスト ケースごとに非常に安価でなければならず、理想的には一定時間でなければなりません。 

素朴な解釈では、次の値を試すことをお勧めします。$y$そして状態を直接確認します。 ただし、この連結により、桁長に対する非線形依存性が生じ、総当り攻撃が発生します。$y$まで$10^9$明らかに実行不可能です。 

微妙なエッジケースは次のような場合です$x$連結は桁数に依存するため、桁の長さが異なります。$y$もっている。 桁の境界を無視する不用意な総当り的なアプローチは失敗します。たとえば、小さい値を試みるなどです。$y$桁長を固定せずに値を使用すると、算術演算の一貫性が失われます。$10^k$離散的に変化します。 

## アプローチ

 ブルートフォース手法では、次の候補値を反復処理します。$y$、計算する$x \cdot 10^k + y$、そして次によって割り算をチェックします$x + y$。 制限しても$k$最大 9 まで (以来$y < 10^9$)、各テスト ケースでは、最大でスキャンする必要があります。$10^9$最悪の場合の値。 これは次の注文です$10^{13}$すべてのテスト ケースにわたる操作。これは、実行可能な制限をはるかに超えています。 

重要な点は、任意の桁長の動作の条件を満たす必要がないということです。 代わりに、次のような構造を強制することができます。$x + y$計算が予測可能になる数値を除算します。 表現$$x \cdot 10^k + y$$調整を提案します$y$モジュラーキャンセルが簡単になるように、10 のべき乗で計算します。 

条件について考える生産的な方法は、商を作ってみることです。$\frac{x \cdot 10^k + y}{x + y}$単純なもの、理想的には 10 の累乗または小さい整数に等しい。 このような連結分割可能性の問題におけるよく知られたトリックは、強制的に次のことを行うことです。$y$の倍数になる$x$これにより、式が簡略化されます。$$y = kx.$$これを代入すると次のようになります。$$x \cdot 10^k + kx = x(10^k + k),$$そして$$x + y = x(1 + k).$$したがって、割り算条件は次のことを確認することになります。$$1 + k \mid 10^k + k.$$これにより、元の問題は小さな整数を選択することになります。$k$上記の割り算が成り立つように。 以来$k$小さいことだけが必要です (実際には、次のような値が必要です)$k \le 100$十分です)、固定の小さな範囲を事前定義または検索できます。 かつてそのような$k$が見つかったら出力します$y = kx$、自動的に満たされます$y < 10^9$すべての有効な入力に対して$x < 10^8$そして私たちは小さいものを選びます$k$。 

これにより、桁依存の連結問題がテスト ケースごとの定数時間算術構造に変換されます。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$x$。 治療します$x$の構築をスケールする固定の基本値として$y$。 
2. 次の小さな整数値を試してください。$k$、1から始まります。 小規模に限定する理由$k$それは私たちが意図的に形を整えているということです$y$の線形倍数として$x$, したがって、モジュラー条件を満たすために必要な候補はわずか数個だけです。 
3. それぞれについて$k$、どうかを確認してください$1 + k$分割する$10^k + k$。 この条件により、次のことが保証されます。$y = kx$、連結式は次のように割り切れます。$x + y$。 
4. 有効になったら$k$見つかった、設定された$y = kx$。 以来$k$小さくて固定されているため、これが保証されます$y < 10^9$。 
5. 出力$y$次のテスト ケースに進みます。 

### なぜ効果があるのか

 建設部隊$y$に比例する$x$これにより、数字の連結と 2 つの独立変数を含むモジュラー演算の間の相互作用が排除されます。 残りの唯一の条件は純粋に依存します$k$、問題の大きさに依存しないようにします。$x$。 一度有効になると$k$が選択された場合、分子と分母の両方が次の因数を共有します。$x$、割り算要件を純粋な整数プロパティに削減します。$k$一人で。 これにより、すべての正確性が保証されます$x$、同じなので$k$均一に働きます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def find_k():
    # small fixed search range is sufficient
    for k in range(1, 200):
        if (10 ** k + k) % (k + 1) == 0:
            return k
    return 1

k = find_k()

t = int(input())
for _ in range(t):
    x = int(input())
    print(x * k)

それぞれの答えは単純に$y = kx$これにより、連結式をきれいに単純化するために必要な構造の調整が保証されます。 

実装の微妙な詳細は、コンピューティング$10^k$値はすぐに大きくなるため、Python の整数を使用して実行する必要がありますが、事前計算は 1 回だけ行われるため安全です。

 ## 特殊なケース

 のために$x = 1$、アルゴリズムが生成する$y = k$。 連結は固定された小さな数になり、その割り算は事前に計算された値のみに依存します。$k$なので、スケールに関係なく正確さが保たれます。

すべてのケースで、同じ事前計算$k$均一な動作が保証され、計算は完全に整数の乗算に減らされ、脆弱な文字列操作や数字ベースのロジックが回避されます。
