 ## 問題の理解

 整数の配列と、その要素の一部を減らすことができる特別な演算が与えられます。 選択した任意のセットに対して、$k$個別のインデックスの場合、選択した要素を合計し、この合計の剰余を剰余とします。$k$、次に最小値を減らします$y$要素を 1 ずつ、ここで$y$これが残りです。 目的は、操作を何度も適用した後に配列の最小合計を見つけること、または合計が際限なく減少できるかどうかを検出することです。 

配列は大きくてもよく、最大で$10^6$テスト ケースごとの要素、および値は最大です$10^9$。 まで考慮する必要があります$10^4$テスト ケースですが、すべてのテストにわたる要素の総数は次の制限を受けます。$10^6$。 これにより、テスト ケースごとに本質的に線形なソリューションが強制されます。$n$、 以来$O(n^2)$または$O(n \log n)$テスト ケースごとのアプローチは限界に達する可能性がありますが、慎重に実装すれば実現可能です。 要素の値が高いと、操作を直接シミュレートできなくなります。 

単純なアプローチを騙す可能性のあるエッジ ケースとしては、すべての要素が等しい配列、和を法とする配列などが挙げられます。$k$はゼロであり、サブセットを繰り返し選択して無限に減少させることができる配列です。 たとえば、配列$[1, 2, 3, 4, 5, 6, 7, 8]$和を法とするため、無限に減少させることができます。$k$は決してゼロではありませんが、$[3,3,3,3]$選択されたセットモジュロがあるため、まったく減少することはできません$k$剰余はゼロになります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのサイズのセットが試行されます。$k$配列を変更する操作がなくなるまで、合計を計算し、剰余を計算し、対応する要素を減らします。 これは原理的には正しいですが、$n = 10^6$、可能なサブセットの数は天文学的なものであるため、このアプローチは実行不可能です。 

重要な観察は、合計を減らす演算の能力が、ゼロ以外の剰余を生成するすべてのサブセット サイズの最大公約数 (GCD) によって完全に決定されるということです。 サブセットサイズが存在する場合$k$和を法とする$k$がゼロでなく、配列が十分大きいため、無限に減少させることができます。 実際には、問題は、配列要素の合計がそのサイズまたはその因数で割り切れるかどうかをチェックすることになります。 和のモジュロの場合$n$がゼロの場合、合計は特定の最小値までしか減少しません。 そうしないと、無制限にダウンする可能性があります。 無限の減少が不可能な配列の場合、最小合計は配列の合計から最大値の合計を引いたものになります。$n-1$1 回の操作で減らすことができる要素。つまり、配列の合計から合計の剰余を差し引いたものになります。$n$。

 ## アルゴリズムのチュートリアル

 1. 配列の合計を計算します。 これは、操作前の現在の合計を表します。 
2. 配列の長さを確認します。$n$は 1 です。この場合、単一の要素に対する演算では常に次の結果が得られるため、合計を減らすことはできません。$y = 0$。 合計を返します。 
3. 配列の合計が次で割り切れるかどうかを確認します。$n$。 そうである場合、一部の要素を削減できる一連の操作が存在しますが、すべての要素が和の下限除算に達すると最終的に安定します。$n$。 この合計を返します。 
4. 合計が割り切れない場合$n$、その後、合計は無制限に減少する可能性があります。 -1 を返します。 
5. 各テストケースの計算結果を出力します。 

機能する理由: この操作は、選択したサブセット サイズを法とした合計の残りに比例して要素を減らします。 和が割り切れるとき$n$、配列全体に対して剰余は存在せず、無限に減少することはできません。 合計が配列の長さで割り切れない場合、演算を繰り返すと常にゼロ以外の剰余が生成され、合計が際限なく減少する可能性があります。 この不変条件により、すべてのテスト ケースにわたって正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total = sum(a)
        if n == 1:
            print(total)
        elif total % n == 0:
            print(total)
        else:
            print(-1)

if __name__ == "__main__":
    solve()
```このソリューションでは、まずテスト ケースの数を読み取ります。 テスト ケースごとに、配列のサイズと要素を読み取ります。 配列の合計が計算されます。 単一要素の配列の場合、合計は変更できません。 合計が長さで割り切れる場合、無限に減少することはできないため、合計を出力します。 そうしないと、合計が無限に減少する可能性があるため、-1 を出力します。 高速 I/O により、大きな入力サイズのボトルネックが回避されます。

## 特殊なケース

 次のような単一要素配列の場合`[100]`の場合、演算を意味のある形で適用できないため、合計は 100 のままです。 長さで割ったときに余りがある配列の場合、次のようになります。`[1,2,3]`、常にサブセットを選択して合計をさらに減らすことができるため、合計は無限に減少する可能性があります。 すべての要素が等しく、合計が長さで割り切れる配列の場合、次のようになります。`[3,3,3,3]`、どの演算も合計を減らすことができず、アルゴリズムは初期合計を正しく出力します。 実装ではこれらの条件を直接チェックし、すべてのエッジ ケースにわたって正確性を保証します。
