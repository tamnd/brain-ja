 ## 解決策
 ## 問題の理解

 一連のシーケンスがあります`n`山。 各山の石の数は次のいずれかの整数になります。`1`に`m`。 

ゲーム自体は、移動中の石の値には依存しません。 プレイヤーは削除するポジションを選択するだけです。 ターンごとに、現在のシーケンスのインデックスが再作成され、プレーヤーは、インデックスが良好なインデックスの固定セットに属しているポジションのみを削除できます。 アリスが最初に動き、最後に残った山にできるだけ多くの石を配置したいと考えています。 ボブはその逆を望んでいます。 

パイル値の特定の構成の 1 つでは、最適なプレイによって 1 つの生き残る元の位置が決定されます。 その値を次のようにします`x`。 

課題は 1 つのゲームを解決することではありません。 合計しなければなりません`x`パイル値のすべての可能な割り当てにわたって、すべてのパイルが独立して値を選択します。`[1,m]`。 

The first thing that stands out is that`n ≤ 20`。 サイズの状態空間`2^n`は現実的であり、この声明では、次の合計が保証されることさえ保証されています。`2^n`すべてのテストケースで次を超えない`2^20`。 

2 番目に重要な境界は、`m ≤ 10^6`。 すべての値またはすべての構成を列挙することは不可能です。 がある`m^n`この構成は、中程度の入力であっても天文学的に大きくなります。 

ゲームの構造も独特です。 動きは実際のパイル値に依存しません。 これらは現在存在するポジションにのみ依存します。 これは、ゲームを数値とは独立して分析し、カウント引数と組み合わせることができることを示唆しています。 

よくある間違いは、どの元の位置が残っているかを判断し、その位置の構成を数えようとすることです。 値の割り当てが異なると、ゲーム中の最適な決定が変わる可能性があります。 

考慮する：```
n = 2
good = {1}
```唯一の正当な手は最初の山を削除するので、2 番目の山は常に残ります。 答えは簡単です。 

ここで、アリスがいくつかの削除の中から選択する、より大きなゲームを考えてみましょう。 どの動きが最適であるかは、値によって異なります。 生存位置はあらかじめ決まっているわけではありません。 

もう一つの微妙なケースは次のような場合です。`m = 1`。```
n = 20
m = 1
```すべての山には、正確に 1 つの石が含まれています。 すべての構成には最終的な値があります`1`、ゲームとは関係なく。 答えは単純です`1`。 

しきい値カウントを使用しようとするソリューションでも、この境界を適切に処理する必要があります。 

## アプローチ

 まず総当たり的な解決策を想像してみましょう。 

パイル値のすべての構成について、ミニマックス ゲームをシミュレートし、最終値を取得します。 次に、すべての構成を合計します。 

がある`m^n`構成。 たとえ`n = 20`そして`m = 2`、それはすでに100万州を超えています。 ハードバージョンの場合は、`m`100万人に達するので、総当たりは完全に絶望的です。 

重要な観察は、ゲームの仕組みは値間の比較のみに依存しているということです。 

しきい値を固定するとします`T`。 すべてのパイル値をビットに置き換えます。```
0 if value < T
1 if value ≥ T
```次に、別の質問をしてください。```
Can Alice force the final surviving pile to have bit 1?
```これはもはや数値最適化の問題ではありません。 バイナリ シーケンス上の純粋な勝ち負けのゲームになります。 

以来`n ≤ 20`、長さのすべてのバイナリ シーケンス`n`ビットマスクとして表すことができます。 マスク上にミニマックス DP を構築できます。 

どのマスクがアリスにとって有利であるかがわかったら、元の問題に戻ります。 

固定閾値の場合`T`、すべての山は独立して次のいずれかに寄与します。```
value < T      : T - 1 choices
value ≥ T      : m - T + 1 choices
```したがって、次を含むバイナリマスクの場合、`j`1、そのマスクを生成する元の構成の数は次となります。```
(T-1)^(n-j) · (m-T+1)^j
```アリスが最後の力を加えることができたら`1`そのマスクから、対応するすべての構成が、最終値が少なくとも`T`。 

これにより、元の最適化問題が、少なくとも最終値を持つカウント構成に変換されます。`T`。 

計算後```
F(T) = number of configurations whose final value is at least T
```標準恒等式を使用して最終値の合計を回復します```
count(value = T) = F(T) - F(T+1)
```そして```
answer = Σ T · count(value = T).
```指数部分は以下にのみ依存します。`n`の値が大きい一方で、`m`組み合わせカウントによって処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m^n・ゲーム) | 巨大な | 遅すぎる |
 | 最適 | O(nk2^n + nm) | O(2^n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### バイナリマスクの DP

 バイナリ シーケンスの場合は、次のように定義します。```
dp[len][mask][0]
```アリスが最後のビットを強制できるかどうか`1`。 

同様に、```
dp[len][mask][1]
```ボブの番になったときに、同じ質問を表します。 

で表される配列は、`mask`長さがある`len`。 

### Transition

If we delete the`p`- 番目の位置では、より短いマスクが得られます。 

この操作を呼び出します。```
delete(mask, p)
```アリスは成功につながる少なくとも 1 つの手を必要としています。```
dp[len][mask][0]
    = OR over legal deletions
      dp[len-1][new_mask][1]
```ボブは、アリスにとってすべての結果が失敗することを望んでいます。そのため、次のようになります。```
dp[len][mask][1]
    = AND over legal deletions
      dp[len-1][new_mask][0]
```同様に、ボブの状態を次のように初期化します。`1`そして最小値を繰り返します。 

### 基本ケース

 山が 1 つだけ残っている場合:```
dp[1][0][0] = dp[1][0][1] = 0
dp[1][1][0] = dp[1][1][1] = 1
```残りのビット自体が答えです。 

### 優勝マスクを数えています

 長さの DP を構築した後`n`、すべてのマスクに```
dp[n][mask][0] = 1
```は勝利のしきい値設定です。 

させて```
cnt(mask) = number of ones in mask.
```私たちが気にするのは、マスクに何枚含まれているかだけです。 

作成する：```
sum[j]
```= 正確に一致する勝利マスクの数`j`もの。 

### F(T) の計算

 しきい値の場合`T`:

 勝利のマスク`j`に対応するもの```
(T-1)^(n-j) · (m-T+1)^j
```オリジナルの構成。 

したがって、```
F(T)
=
Σ sum[j]
  · (T-1)^(n-j)
  · (m-T+1)^j
```### 正確な値を回復する

 私たちは次のことを知っています:```
F(T) = count(final value ≥ T)
```したがって：```
count(final value = T)
=
F(T) - F(T+1)
```ついに：```
answer
=
Σ T · (F(T)-F(T+1))
```剰余を取得`10^9+7`。 

### なぜ効果があるのか

 しきい値変換では、最終値が少なくとも次の値になるかどうかを決定するために必要な情報が正確に保存されます。`T`。 

値をビットに置き換えた後、最後のビット`1`最終的なパイル値が少なくとも`T`。 ミニマックス ゲームは、正確な大きさではなく、それらのビットのみに依存します。 

DP は、アリスが生存者を強制できるかどうかを正しく計算します。`1`なぜなら、各州はすべての法的削除を考慮し、誰の順番に応じて OR と AND を交互に選択するからです。 

勝利マスクが判明すると、すべての元の構成が`F(T)`まさにそのしきい値マスクが勝っているときです。 各マスクの割り当ての数は、ラベルが付けられている位置の数にのみ依存します。`1`、上記の組み合わせ式が得られます。 

したがって`F(T)`少なくとも最終値を持つ構成の正確な数です`T`、伸縮変換によって最終値の合計が再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7
MAXN = 20

popcount = [0] * (1 << MAXN)
for i in range(1, 1 << MAXN):
    popcount[i] = popcount[i >> 1] + (i & 1)

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())
        k = int(input())
        good = [x - 1 for x in map(int, input().split())]

        if m == 1:
            print(1)
            continue

        dp_prev_a = [0, 1]
        dp_prev_b = [0, 1]

        for length in range(2, n + 1):
            size = 1 << length

            dp_a = [0] * size
            dp_b = [1] * size

            for mask in range(size):
                alice = 0
                bob = 1

                for p in good:
                    if p >= length:
                        break

                    low = mask & ((1 << p) - 1)
                    high = mask >> (p + 1)
                    nxt = low | (high << p)

                    alice |= dp_prev_b[nxt]
                    bob &= dp_prev_a[nxt]

                dp_a[mask] = alice
                dp_b[mask] = bob

            dp_prev_a = dp_a
            dp_prev_b = dp_b

        win_count = [0] * (n + 1)

        for mask in range(1 << n):
            if dp_prev_a[mask]:
                win_count[popcount[mask]] += 1

        ans_ge = [0] * (m + 2)

        for tval in range(1, m + 1):
            a = tval - 1
            b = m - tval + 1

            cur = 0
            for ones in range(n + 1):
                cur += (
                    pow(a, n - ones, MOD)
                    * pow(b, ones, MOD)
                    % MOD
                    * win_count[ones]
                )
                cur %= MOD

            ans_ge[tval] = cur

        answer = 0

        for tval in range(1, m + 1):
            exact = (ans_ge[tval] - ans_ge[tval + 1]) % MOD
            answer = (answer + tval * exact) % MOD

        print(answer)

solve()
```DP はシーケンスの長さを増やすことによって構築されます。 トランジションは、1 つの正当な位置を削除し、残りのビットをより短いマスクに圧縮します。 

2 つの配列は誰の順番に対応します。 アリスは 1 回の成功する必要があるため、論理 OR を使用します。 ボブが選択したすべての手が依然として成功につながる場合にのみアリスが成功するため、ボブは論理 AND を使用します。 

ゲーム DP が終了すると、実際の値は問題から消えます。 必要なのは、指定された数の勝利マスクの数だけです。 この圧縮により、ハード バージョンが実現可能になります。 

最後の計数段階では、すべてのしきい値を評価します。`T`組み合わせカウントには高速のべき乗剰余演算を使用します。
