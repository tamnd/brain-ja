 ## 解決策
 ## 問題の理解

 整数の配列でプレイされるゲームが与えられます。このゲームでは、2 人のプレイヤーが順番に 1 つのアクション (ゲームをすぐに終了するか、2 つの要素の位置を交換する) を実行します。$l$そして$r$、追加します$r-l$ランニングコストに。 最適化しようとしている関数は次のとおりです$$f(a) = \text{cost} + a_1 - a_2 + a_3 - a_4 + \dots + (-1)^{n+1} a_n$$アリスはこの値を最大化することを目指しており、ボブはこの値を最小化することを目指しています。 最後のタスクは計算することです$f(a)$両方が最適にプレイされている場合。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは配列サイズを示します$n$そして配列要素。 各テスト ケースの出力は単一の整数であり、最終的な値は$f(a)$最適なプレイのもとで。 

与えられた$n$と同じ大きさにすることができます$2 \cdot 10^5$と合計$n$すべてのテスト ケースでは、次の制限もあります。$2 \cdot 10^5$、線形より悪いアルゴリズム$n$テストケースごとにタイムアウトになる可能性があります。 可能なスワップの数は二次関数的に増加するため、ネストされたループやすべてのスワップの列挙は直ちに除外されます。 

微妙な部分は、いつスワップする価値があるかを理解することです。 2 つの要素の配列を考えてみましょう$[1000, 1]$。 素朴な考えは、それらを交換してコスト 1 を追加することかもしれません。しかし、交互の合計は交換せずにすでに最大化されています。$1000 - 1 = 999$。 アリスが入れ替わる場合、コストは 1 増加しますが、交互の合計は同じ量だけ減少します (数値が交互のパターンで入れ替わります)。ボブが最適に応答できた場合、アリスの状況は悪化します。 したがって、小さなアレイや明確に優勢な交互パターンを持つアレイでは、ゲームを即座に終了することが最善の策となる可能性があります。 

エッジ ケースには、要素が 1 つまたは 2 つだけある配列、すべての要素が等しい配列、最大値または最小値が交互の合計を最大化する位置にすでに存在する配列が含まれます。 常に要素を交換しようとする不用意なアルゴリズムはここで失敗します。 

## アプローチ

 ブルートフォースアプローチは、スワップとゲーム終了の動きのあらゆる可能なシーケンスをシミュレートすることです。 考えられる各ペアについて$l, r$、結果を交換して再帰的に計算できます。 これは理論的には正しいですが、考えられるゲーム シーケンスの数が天文学的ではるかに多いため、扱いが困難です。$10^{100}$。 深さを制限しても$n^2$スワップが多すぎる$n$まで$2 \cdot 10^5$。 

重要な観察は、最適なプレイのどのシーケンスにおいても、プレイヤーはコストを上回る正味交互合計を改善するスワップのみを考慮するということです。 そのようなスワップが存在しない場合、最適な措置はゲームを直ちに終了することです。 さらに、交互の合計に影響を与えることができる唯一の位置は、配列内の最初と最後の位置です。 これは、配列内の 2 つの要素を交換すると、対戦相手が対抗できる形で合計に影響を与えるためです。 その結果、ゲーム全体は 1 つの決定に集約されます。つまり、スワップの可能性がある最初と最後の要素のみを考慮し、交互合計のゲインがスワップ コストを超えるかどうかに基づいて、ゲームを終了するかスワップするかを選択します。 長さが 1 または 2 の配列の場合、ほとんどの場合、ゲームはすぐに終了します。

 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. スワップを実行せずに、配列の最初の交互合計を計算します。 これは、配列を反復処理し、その位置に応じて各要素を加算または減算することによって行われます。 
2. 最初の要素と最後の要素を交換することで得られる最大のゲインを特定します。 この交換にかかる費用は、$n-1$。 それらを交換する場合は、新しい交互の合計を計算します。 この合計とスワップ コストが最初の代替合計よりも優れている場合は、スワップを実行する価値があります。 それ以外の場合、最適な行動はゲームを直ちに終了することです。 
3. 対戦相手はすぐにゲームを終了するか、アドバンテージを取り消すことができるため、ゲームは最大 1 回のスワップ後に終了します。 追加のスワップはそれぞれ打ち消される可能性があるため、複数のスワップを順番に実行するインセンティブはありません。そのため、1 つのスワップのみを考慮すれば十分です。 
4. すぐに終了するか、最適なスワップを実行することで得られる最大値を出力します。 

それが機能する理由: 不変条件は、対戦相手がいつでも元に戻したり無力化できるため、最初と最後のポジションを超えて交換しても結果は改善されないということです。 両端に焦点を当てることで、すぐにキャンセルできない方法で交互の合計に影響を与える唯一のスワップをキャプチャします。 このアルゴリズムは、アリスの最適な先手意思決定とボブの即時カウンターを効果的にシミュレートします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        alt_sum = sum(a[i] if i % 2 == 0 else -a[i] for i in range(n))
        if n == 1:
            print(a[0])
            continue
        # potential swap of first and last
        swapped_sum = (-a[0] + sum(a[1:-1][i] if i % 2 == 0 else -a[1:-1][i] for i in range(len(a[1:-1])))) + a[-1] * (1 if (n-1) % 2 == 0 else -1)
        gain_with_swap = swapped_sum + (n - 1)
        print(max(alt_sum, gain_with_swap))

if __name__ == "__main__":
    solve()
```コードは最初にテスト ケースの数を読み取ります。 配列ごとに、交互の合計が計算されます。 長さが 1 の配列の場合、値は自明です。 長い配列の場合、最初と最後の要素を交換することを考慮し、交互の合計への影響を計算し、スワップ コストを追加します。 すぐに終了するか、スワップを実行するかの最大値が結果を与えます。 

微妙な選択には、スワップされた合計を計算するときの中間部分の処理が含まれます。 インデックス作成では、最初と最後の要素を削除した後も交互のパターンを正しく維持する必要があります。 スワップコストの追加を忘れたり、インデックスの位置がずれていると、不正確な結果が生成されます。
