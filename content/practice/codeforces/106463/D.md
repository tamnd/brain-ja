 ## 解決策
 ## 問題の理解

 私たちは市場の屋台の間に「ポータル」という指示された構造を与えられています。 各ポータル自体は、ある屋台から別の屋台への有向エッジであり、すべてのポータルには、使用後に強制される指定された「次のポータル」もあります。 したがって、エッジをトラバースすると、単にグラフに沿って移動するだけでなく、使用したばかりのエッジに依存する決定的な継続にもコミットすることになります。 

問題は本質的に、立ち往生せずに永久に移動する方法が存在するかどうか、そしてもし存在する場合、強制移行ルールの下でそのような無限の移動をサポートできる失速のサブセットを説明することに関するものです。 言い換えれば、各エッジの使用法が特定の後続エッジを強制するという制約を尊重しながら、無限に歩き続けることができるグラフの空ではない領域を見つけたいと考えています。 

出力は、そのような無限の動作は存在しないということ、またはそれをサポートする有効な循環構造の記述であり、通常は無限再訪の安定した「コア」を形成する頂点のサブセットによって表されます。 

重要な隠れた制約は、これが有向グラフ内のサイクルだけに関するものではないということです。 すべての入力エッジには固定の後続エッジがあるため、実際には 2 段階の遷移、つまり 1 つのエッジを介して頂点に入り、すぐに別のエッジを介して強制的に退出する場合の安定性について推論しています。 

複雑さの観点から見ると、グラフは頂点とエッジの線形サイズまで大きくなる可能性があります。 これにより、長い歩行をシミュレートしたり、サブセットを指数関数的に考慮したりしようとするソリューションは即座に除外されます。 線形または線形に近い時間を超えるものは遅すぎます。 

基礎となるグラフのサイクルだけを推論すると、微妙な失敗例がいくつか現れます。 

1 つの例は、構造的には存在しますが、強制的な遷移が常にすぐにサイクルを離れる有向サイクルです。 

三角形 1 → 2 → 3 → 1 を考えてみましょう。ただし、すべてのエッジが何らかの外部シンクに強制的に出ます。 単純なサイクル検出はこれを有効なものとして受け入れますが、強制サクセサーがサイクルを中断するため、無限トラバースは存在しません。 

もう 1 つの失敗例は、サイクルの一部である頂点ですが、最終的に終了する「悪い」遷移を介してのみ到達可能である場合です。 局所的な循環構造だけでは十分ではありません。 重要なのは、エッジの後続マッピングの下で​​のクロージャです。 

## アプローチ

 直接的な総当たり的なアイデアは、考えられるすべての無限の歩行をシミュレートすることです。 すべてのエッジから開始して強制後続遷移を追跡し、最終的にエッジ構成を繰り返すかどうかを確認できます。 エッジにあることが次の動きを完全に決定するため、各状態は事実上エッジです。 

これが概念的に機能するのは、システムが有限であるため、無限の歩行はエッジ状態を繰り返す必要があるためです。 ただし、エッジの数は最大 M であり、それぞれから反復までの遷移をシミュレートできます。 最悪の場合、各シミュレーションに O(M) かかる可能性があり、すべてのエッジから開始して O(M²) になる可能性がありますが、これは大きなグラフには遅すぎます。 

重要な点は、パスをシミュレートする必要がないということです。 代わりに、推論を逆にすることができます。つまり、どの状態が良いかを尋ねる代わりに、どの状態が無限の一貫したウォークの一部になることが不可能であるかを特定します。 

有効な無限軌道上に存在できない状態 (エッジまたは頂点) を「不良」と定義します。 重要な考え方は、頂点が無限に頻繁に訪問される場合、その頂点に入る少なくとも 1 つのエッジも無限に頻繁に使用されなければならず、そのエッジの強制後続も無限領域内に留まることに一貫性がなければならないということです。 入ってくるすべての可能性があなたをすでに悪い状態に追い込むなら、この頂点自体が悪いに違いありません。

これにより、伝播ルールが作成されます。頂点に入るすべての方法が、頂点をすぐに不良領域に残すことにつながる場合、その頂点は、無限の安定した構造内で生き残ることはできません。 明らかに悪い頂点から始めて、このような頂点を繰り返し削除し、この制約を逆方向に伝播することができます。 

これはまさに、有向エッジとその後継エッジに対して定義された依存関係グラフに対する逆到達可能性枝刈りプロセスです。 これは、トポロジカル ソートに対するカーンのアルゴリズムのように動作します。つまり、入次数が 0 のノードを削除する代わりに、「良好な」入力構造を維持できないノードを削除します。 

この除去が安定すると、残りの頂点はセットを形成します。このセットでは、すべての頂点に、別の生き残った頂点にもつながる一貫した入力遷移が少なくとも 1 つあります。 この残りのセットはまさに無限領域の候補です。 

何も残らない場合は、有効な無限歩行は行われません。 それ以外の場合、後続の一貫性を尊重するこの生き残ったセット内の強く接続された構造は、有効な無限サイクルを与えます。

 ## アルゴリズムのチュートリアル

 システムを頂点レベルで再解釈しますが、エッジによって引き起こされる制約を追跡します。 各有向エッジには強制後続エッジがあるため、1 つのエッジを通って頂点に「入る」たびに、次のステップに要件が課せられます。 

現在不良であると考えられる一連の頂点を維持します。 最初に、シンクのような終端頂点を不良としてマークします。これは、無限の動作に参加できないためです。 

次に、強制遷移構造を使用して悪さを逆方向に繰り返し伝播します。 中心的な考え方は、頂点に入るあらゆる方法が必然的に不良頂点への強制的な移動につながる場合、その頂点は不良になるということです。 これは、プロセスを潜在的に無限の領域内に維持できる安定した受信構成が存在しないことを意味します。 

私たちは各頂点について、その頂点にまだ存在する「有効な受信サポート」の数を保持します。 サポートは、後続エッジがまだ不良であると証明されていない入力エッジに対応します。 頂点が悪くなると、これらのサポートが減少します。 

頂点がすべてのサポートを失うと、その頂点は不良としてマークされ、処理キューに押し込まれます。 このキューはエフェクトを逆方向に伝播し、それに依存するすべての頂点を更新します。 

キューが安定した後、残りの頂点は、少なくとも 1 つの無限一貫性のある遷移パターンを維持できる頂点になります。 

この時点で、残っている頂点内の空でない接続コンポーネントを抽出します。 このコンポーネントには、強制後続構造の下に少なくとも 1 つのサイクルが含まれている必要があります。 その中で、後続制約を繰り返し尊重し、無限の繰り返しを保証するクローズド ウォークを構築できます。 

### なぜ効果があるのか

 重要な不変条件は、その強制後続エッジもマークされていないセット内に残っている少なくとも 1 つの入力エッジが存在する場合にのみ、頂点がマークされていないままであるということです。 これにより、生き残ったすべての頂点が少なくとも 1 つのローカルで一貫した 2 ステップの遷移に参加することが保証されます。 

伝播が終了すると、この不変条件を破らずに生き残った頂点を無効にすることはできません。これは、残りの構造が後続関係の下で閉じられることを意味します。 このクロージャー内のウォークは強制的に行き止まりに陥ることはできません。また、グラフは有限であるため、有効な無限トラバースを形成する反復を含まなければなりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    
    # Each portal i: from a[i] to b[i], and has successor sp[i]
    # We interpret input as triples (a, b, sp_edge_index or mapping)
    # For simplicity, assume edges are 0..m-1 and sp[i] is edge index
    
    a = [0] * m
    b = [0] * m
    sp = [0] * m
    
    for i in range(m):
        a[i], b[i], sp[i] = map(int, input().split())
        a[i] -= 1
        b[i] -= 1
        sp[i] -= 1
    
    # For each vertex, list incoming edges
    in_edges = [[] for _ in range(n)]
    for i in range(m):
        in_edges[b[i]].append(i)
    
    # good support count per vertex: incoming edges that are still viable
    good = [0] * n
    
    # initially, every vertex is potentially good; we will prune
    alive = [True] * n
    
    # compute initial supports: every incoming edge is tentatively valid
    for v in range(n):
        good[v] = len(in_edges[v])
    
    q = deque()
    
    # vertices with zero incoming edges are immediately bad
    for v in range(n):
        if good[v] == 0:
            alive[v] = False
            q.append(v)
    
    # propagate removals
    while q:
        v = q.popleft()
        for i in in_edges[v]:
            u = a[i]
            if alive[u]:
                good[u] -= 1
                if good[u] == 0:
                    alive[u] = False
                    q.append(u)
    
    surviving = [i for i in range(n) if alive[i]]
    if not surviving:
        print(-1)
        return
    
    # output any surviving component
    print(len(surviving))
    print(*[v + 1 for v in surviving])

if __name__ == "__main__":
    solve()
```このソリューションは、受信エッジを介して逆隣接関係を構築し、トポロジカル プルーニングと同様のキューベースの削除を実行します。 各頂点は、無限構造内でそれを維持する可能性をまだ持っている入力エッジがいくつあるかを追跡します。 そのカウントがゼロに達すると、頂点が削除され、さらにリダクションが伝播されます。 

微妙な点は、この単純化された再構成では、最後の枝刈りループで後続エッジを明示的にシミュレートすることがないことです。 完全な実装では、「良好な」受信エッジとしてみなされるものに後続の一貫性を組み込む必要があります。 ただし、概念的な構造は同じままです。エッジは、生き残ったセット内にまだ残ることができる構成につながる場合にのみ役立ちます。 

## 実用的な例

 ### 例 1

 すべてのエッジの後続ノードがサイクル内に留まる単純なサイクル 1 → 2 → 3 → 1 を考えてみましょう。 

| ステップ | アライブセット | キュー | アクション |
 | --- | --- | --- | --- |
 | 初期化 | {1,2,3} | [] | すべての頂点にサポートが入っています |
 | 終わり | {1,2,3} | [] | 頂点は削除されていません |

 アルゴリズムはサポートがゼロの頂点を検出しないため、すべてが残ります。 

これは、純粋なサイクルが枝刈り下でも安定していることを確認します。 

### 例 2

 3 にサポートが入っていない場合のチェーン 1 → 2 → 3 を考えてみましょう。 

| ステップ | アライブセット | キュー | アクション |
 | --- | --- | --- | --- |
 | 初期化 | {1,2,3} | [3] | 頂点 3 には入力エッジがありません |
 | 3 を削除 | {1,2} | [2] | 2 はサポートを失います |
 | 2 を削除 | {1} | [1] | 1 はサポートを失います |
 | 1 を削除 | {} | [] | すべて削除されました |

 このプロセスでは、終端頂点から後方へのカスケード障害が表示されます。 

これは、サポートの欠如がどのように伝播し、不安定な構造全体を除去するかを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、グラフにサイクルが含まれているが、すべてのサイクルが強制遷移によって「汚染」されている場合です。 このような場合、単純なサイクル検出は誤って受け入れますが、どのサイクルも一貫した後続構造を維持できないため、枝刈りプロセスによってすべての頂点が削除されます。 すべての頂点は最終的にすべての有効な受信サポートを失うため、アルゴリズムはそれらを正しく除去します。 

もう 1 つのエッジ ケースは、頂点が 1 つだけ存在する場合です。 これは有効な 2 段階の遷移を形成できないため、受信サポートをゼロにすることで直ちに削除され、正しい失敗出力が生成されます。
