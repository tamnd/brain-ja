 ## 問題の理解

 私たちに回覧板が渡されました。$N$からラベル付けされた位置$0$に$N-1$。 プレーヤーはあるポジションからスタートします$Y$。 長さの一連の動きもあります$K$、各移動が値を追加します$a_i$現在の位置に戻りますが、すべての位置は剰余として取得されます$N$, そのため、プレイヤーは常にサークル上に留まります。 

ひねりを加えると、その特定の正方形が$X$ポータルのように動作します。 プレイヤーが着地するたびに$X$移動を実行した後、通常の方法ではそこに留まりません。 代わりに、彼らはすぐに「テレポート」します。$Y$、その後、今後の動きを適用し続けます。$Y$また。 

タスクは、開始マスごとに決定することです。$z$、すべてを適用した後にプレイヤーが行き着く場所$K$このテレポート ルールがアクティブな状態で移動します。 

素朴な解釈は単純なシミュレーションです。すべてのことから始めてみてください。$z$、すべての動きをいつでもシミュレート$X$に到達したら、ジャンプして戻ります$Y$。 問題は、同じプレフィックスの合計とテレポート サイクルが開始位置ごとに再計算されるため、直接シミュレーションの反復処理が非常に重くなることです。 

制約が意味するのは、$N$そして$K$十分に大きいので、$O(NK)$シミュレーションが遅すぎる。 平$O(K)$クエリごとの開始位置は、全体にわたって繰り返されると実行不可能になります。$N$州。 

を繰り返し訪問すると、微妙な問題が発生します。$X$。 たとえば、プレフィックスの合計によりウォークがヒットする場合、$X$複数回実行した場合、最初のヒット後のその後の動作は、完全なパスではなく、次のヒットの時間のみに依存します。 繰り返し構造を再利用しない単純なアプローチでは、同じ接尾辞の動作が何度も再計算されます。 

もう 1 つのエッジケースは次のような場合です$X$与えられたスタートからはまったく到達しません。 この場合、テレポーテーションは行われず、結果は単純なモジュール式プレフィックス合計シフトだけになります。 どのようなソリューションでも、これら 2 つのケースを明確に分離する必要があります。 

## アプローチ

 ブルートフォース手法では、各開始位置を個別にシミュレートします。 それぞれについて$z$、すべてを繰り返します$K$移動、現在の位置の維持、および着地するたびに$X$にリセットします$Y$。 これはルールに正確に従っているため、これは正しいです。 ただし、同じプレフィックス合計が再計算されます。$N$につながる$O(NK)$時間の複雑さは、両方の場合には遅すぎます。$N$そして$K$大きいです。 

重要な観察は、円上の動きはプレフィックスの和を法としてのみ依存するということです。$N$。 定義すると$p_i = (a_1 + \dots + a_i) \bmod N$、その後の位置$i$最初から動く$z$は$z + p_i$テレポートによってプロセスがリセットされない限り。 

重要な構造は、$X$モジュラー条件の解決のみに依存します。$$z + p_i \equiv X \pmod N$$これは以下と同等です$$p_i \equiv X - z \pmod N$$したがって、各残基について$d$、一番早い時間を知りたいです。$i$どこ$p_i \equiv d$。 最初の発生がわかれば、テレポートが発生するかどうか、発生する場合はプロセスがどのように継続するかを判断できます。$Y$。 

2 番目の重要な洞察は、いったん着地すると、$X$どこかのインデックスで$i$、最終的な結果はその後に何が起こるかによってのみ決まります。$i$からやり直します$Y$。 これにより、プレフィックス インデックス上に「ジャンプ テーブル」が作成されます。各最初のヒットは、後の再帰ヒットにつながるか、きれいに終了します。 

接頭辞の合計を右から左に前処理し、各残基の最も古いインデックスを保存します。 これにより、クエリごとに一定時間で、次のテレポートがどこで発生するか、または何も発生しないかを計算できます。

 ## アルゴリズムのチュートリアル

 移動配列モジュロのプレフィックス合計を使用します。$N$。 させて$p_i$インデックスまでのプレフィックスの合計を示します$i$、 と$p_0 = 0$。 

次に、残基クラスごとに、それが現れる最も早い位置を計算します。 これにより、「次にいつ着陸するか」に直接答えることができます。$X$」を、ずれた出発点からでも。 

## アルゴリズムのチュートリアル

 1. プレフィックスの合計を計算する$p_i = (a_1 + \dots + a_i) \bmod N$。 これにより、移動がモジュール形式の位置に圧縮されるため、将来のすべての位置はプレフィックス値の単純な追加として書き込むことができます。 
2. アレイを構築する`idx[d]`最小のインデックスを格納する$i$そのような$p_i \equiv d \pmod N$。 これを最後からスキャンして埋めていくので、前のインデックスが後のインデックスを上書きします。 これにより、常に最初の出現が保存されることが保証されます。 
3. 開始点が固定の場合$z$、着陸の条件$X$ステップで$i$になる$p_i \equiv X - z$。 これを次のルックアップに変換します。`idx[(X - z) mod N]`。 
4. このインデックスが存在しない場合、テレポートは発生しません。 最終的な位置は単純に$z + p_K \bmod N$。 
5. インデックスが存在する場合、最初のヒットが次の場所にあると仮定します。$i$。 その瞬間から私たちはリセットしました$Y$したがって、問題は次から始まる最終位置の計算に帰着します。$Y$ただし、その後のサフィックスの動作のみを考慮します$i$。 事前計算します`end[i]`、最初にヒットした場合の最終結果を保存します。$X$移動後$i$。 
6. 計算するには`end[i]`、次に同じ残留条件が再び発生する時間を見つけるか、それ以上のテレポートは発生しないと結論付けるかのいずれかです。 これは同じものを使用して行われます`idx`構造を維持し、常に次の関連イベントにジャンプできるようにします。 
7. 最後に、各開始位置について$z$、最初のヒット インデックスからのサフィックス結果、またはヒットが存在しない場合は単純な線形結果のいずれかを出力します。 

これが機能する理由は、テレポートのたびにシステムが固定状態にリセットされるためです。$Y$、その後重要になるのは、プレフィックス合計の残りのサフィックスだけです。 プレフィックス合計の構造により、将来のヒットはモジュラー等価性にのみ依存します。モジュラー等価性はすでに完全にエンコードされています。`idx`テーブル。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, K, X, Y = map(int, input().split())
    a = list(map(int, input().split()))

    p = [0] * (K + 1)
    for i in range(1, K + 1):
        p[i] = (p[i - 1] + a[i - 1]) % N

    INF = K + 5
    idx = [INF] * N

    for i in range(K, -1, -1):
        idx[p[i]] = i

    end = [0] * (K + 1)

    for i in range(K, -1, -1):
        d = p[i]
        nxt = idx[d]
        if nxt == INF:
            end[i] = (Y + p[K] - p[i]) % N
        else:
            if nxt == i:
                end[i] = (Y + p[K] - p[i]) % N
            else:
                end[i] = end[nxt]

    res = [0] * N

    for z in range(N):
        d = (X - z) % N
        i = idx[d]
        if i == INF:
            res[z] = (z + p[K]) % N
        else:
            res[z] = end[i]

    print(*res)

if __name__ == "__main__":
    solve()
```この解決策は、プレフィックス合計のモジュロを構築することから始まります。$N$、すべての動きを固定サイクルのモジュラー演算に変換します。 の`idx`配列は後ろから構築され、各残基が出現する最も早い時刻を格納します。 

の`end`次に、配列はインデックスに対して逆方向に計算されます。 それぞれ`end[i]`最初に着陸した場合の最終結果を表します$X$移動直後に起こる$i$。 同じ残基がそれ以上出現しない場合、プロセスは単純に次からの直接の接尾辞のシフトで終了します。$Y$。 それ以外の場合は、すでに計算された結果を再利用するため、複雑さが線形に保たれます。 

最後に、それぞれのスタート位置$z$必要な残基にマッピングされます$X - z$、そして我々は事前に計算されたものにジャンプします`end`状態にするか、純粋なプレフィックスサム変換にフォールバックします。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$X$どの開始位置からでも到達することはできません。 その状況では、すべてのエントリが`idx[X - z]`が存在しないため、すべての結果は単純なモジュラー和に戻ります。$z + p_K$。 ルックアップはすぐに非テレポートの場合に分岐するため、アルゴリズムはこれをきれいに処理します。 

もう 1 つのエッジ ケースは、接頭辞の合計が剰余を繰り返さない場合です。 それから`idx[d]`常に一意のインデックスを指し、`end[i]`別の状態を介して連鎖することはありません。 これにより、システムは独立した線形接尾辞の計算に減らされ、意図した動作と一致します。 

3 番目のエッジケースは次のような場合です。$K = 0$。 それから$p_0 = 0$、`idx`インデックス 0 の残基 0 のみが含まれており、すべての開始位置は次のいずれかに直接マッピングされます。$X$または変化しないままです。 すべてのロジックがプレフィックス構造での定数時間の検索に帰着するため、アルゴリズムは引き続き機能します。
