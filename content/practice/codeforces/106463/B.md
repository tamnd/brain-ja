 ## 解決策
 ## 問題の理解

 階層的に接続された屋台のセットを表すルート付きツリーが与えられます。 これらの屋台を「訪問」する方法は、DFS のようなトラバーサルによって固定され、最初に各サブツリーに入る順序によって、各屋台を 2 つのチームのいずれかに割り当てる方法が決まります。 

重要なルールは、屋台のチームは独自に選ばれないということです。 代わりに、グローバル トラバース順序における最初の訪問位置の同等性に依存します。 ノードのサブツリーに入ると、その子をある順序でたどります。各子サブツリーは、そのサイズがその後に来るすべてのパリティ シフトに影響を与える訪問ノードのブロックに寄与します。 

このタスクは、ルートが Team Potato に固定されているという制約の下で、子サブツリーの順序選択の有効なグローバル割り当てがツリー全体にわたって一貫したチーム割り当てにつながる数をカウントすることです。 

入力はルート付きツリーを記述し、出力はすべての誘導されたチーム割り当てが一貫性を持つようにトラバーサルの選択肢を配置する有効な方法の数 (大きな素数を法とする) です。 

制約スケール (この種のツリー DP 問題では一般的) は、線形または線形に近い動作が必要であることを意味します。 子を明示的に並べ替えたり、すべてのサブツリーの順序をシミュレートしようとするものはすべて、階乗的に爆発します。 各ノードの子はさまざまな方法で並べ替えられる可能性があり、それぞれの順序がパリティの伝播にグローバルに影響を与えるため、中程度の分岐であっても指数関数的な爆発につながる可能性があります。 

ノードにサブツリー サイズがすべて等しい子がある場合、微妙なエッジ ケースが発生します。 この状況では、子サブツリーの走査によってパリティが反転されないため、相対的な順序によって将来の割り当てが変更されることはなくなります。 すべての子が対称的に動作すると仮定する単純なアプローチでは、カウントが過剰になります。 奇数サイズのサブツリーが複数存在する場合、別のエッジ ケースが発生します。サブツリーを交換するとパリティ代替構造が変更されますが、サブツリーごとに独立して変更されるわけではないため、子を個別に扱う場合に見落としやすい組み合わせ制約が生じます。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのノードで子のすべての置換を列挙し、各置換に対する完全な DFS トラバーサルをシミュレートし、誘導パリティ割り当てを計算しようとします。 これは、問題で説明されている走査プロセスを直接モデル化しているため、概念的には正しいです。 ただし、ノードに k 個の子がある場合、その数は k! になります。 これはツリー全体で急速に増加します。 k が約 10 の場合でも、階乗増加によりこれは実行不可能になり、最大 n ノードでは構成の総数は天文学的に大きくなります。 

重要な観察は、実際にはすべての子の正確な順序は気にしておらず、サブツリーのサイズがパリティ遷移にどのような影響を与えるかだけを気にしているということです。 各サブツリーはブロックに寄与し、そのサイズによって後続のサブツリーのパリティを反転するかどうかが決まります。 これにより、構造全体の順列の問題が、偶数と奇数のサブツリー サイズに基づいて制御された組み合わせ効果にまで軽減されます。 

DP を定義します。ノード x ごとに、x が固定チームに割り当てられていると仮定して、そのサブツリーの有効な構成の数を計算します。 子サブツリーが処理されると、各子 y は 2 つの情報を提供します。それは、有効な内部構成 DP[y] の数と、そのサブツリーのサイズが偶数か奇数かであり、これにより、走査時にパリティを反転するかどうかが決まります。 

すべての子サブツリーのサイズが偶数であれば、どれもパリティの伝播に影響しません。 これにより、すべての子ルートが一貫して整列することが強制され、唯一自由になるのは各サブツリーの内部配置です。 したがって、結果は子に対する単純な積になります。

少なくとも 1 つの奇数サイズのサブツリーが存在する場合、奇数の子を選択した順序で移動するときにパリティが交互に行われます。 偶数サイズのサブツリーは異なる動作をします。パリティを反転しないので、奇数のサブツリー間の交互構造に影響を与えることなく、柔軟に挿入できます。 組み合わせ構造は、各パリティ クラスに入る奇数のサブツリーの数を選択することに帰着します。これにより、奇数のサブツリーが交互の役割間でどのように分割されるかに基づいて二項係数が得られます。 

各ノードがその子を 1 回処理し、結果を O(deg(x)) 時間で結合するため、DP は線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (子を並べ替え + DFS をシミュレート) | O(n!) 最悪の場合 | O(n) | 遅すぎる |
 | パリティ グループ化を使用したツリー DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーをノード 1 にルートし、事後探索でサブツリーのサイズと DP 値を計算します。 

1. 最初にサブツリーのサイズを計算します。 各ノード x について、sz[x] を 1 にすべての子のサイズを加えたものとして累積します。 これが必要なのは、パリティの動作がサブツリーのサイズが偶数か奇数かに完全に依存するためです。 
2. x 自体が Team Potato に割り当てられているという仮定の下で、DP[x] を x をルートとするサブツリーの有効な構成の数として定義します。 この正規化により、絶対的なパリティ状態をグローバルに追跡することを回避できます。 
3. 各ノード x について、最初にすべての子 y を処理し、DP[y] と sz[y] を計算します。 この時点で、各子サブツリーは、寄与数とパリティを反転するかどうかという 2 つの値に完全に要約されます。 
4. x の子を 2 つのグループに分割します。偶数の sz[y] を持つグループと、奇数の sz[y] を持つグループです。 カウントをそれぞれ q と p とします。 
5. p が 0 に等しい場合、つまりすべての子のサイズが偶数である場合、スキャン時にパリティを反転するサブツリーはありません。 この場合、各子ルートは一貫して位置合わせする必要があり、サブツリー間に組み合わせによるインターリーブ効果はありません。 すべての子 y にわたる DP[y] の積として DP[x] を計算します。 
6. p が 0 より大きい場合、奇数のサブツリーをトラバースするたびにパリティが交互に切り替わります。 偶数サブツリーは、この交互パターンに影響を与えることなく配置できます。つまり、偶数サブツリーは独立したブロックとして乗算的に寄与します。 
7. 奇数サイズのサブツリーの場合、ルート チームは走査順序の位置に応じて交代します。 奇数サブツリーを交互のパリティ ロールに分散することのみが重要であり、内部順序は重要ではありません。 p 個の奇数サブツリー間のパリティの役割の有効な割り当ての数は、二項係数 C(p, ⌊p/2⌋) です。 
8. DP[x] = C(p, ⌊p/2⌋) にすべての子にわたる DP[y] の積を乗じて寄与を結合します。 
9. 階乗および逆階乗を法 10^9+7 で事前計算し、二項係数を定数時間で評価します。 

これが機能する理由は、サブツリー サイズによって引き起こされるパリティ フリップのみを追跡することにあります。 すべてのサブツリーは、パリティ フリップ (奇数サイズ) またはフリップなし (偶数サイズ) のいずれかに寄与します。 走査順序は累積的なパリティの変化によってのみ問題となるため、この構造は、奇数の貢献者に交互の役割を割り当て、偶数の貢献者は中立の乗数を維持する方法が何通りあるかを数えることに崩壊します。 パリティの寄与が固定されると各サブツリーは完全に独立し、素のサブツリー間の相互作用はこのパリティ状態を超えて内部構造に影響を与えないため、DP は正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

# factorial precomputation up to n
def build_fact(n):
    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)

    for i in range(2, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n - 1, -1, -1):
        invfact[i] = invfact[i + 1] * (i + 1) % MOD

    return fact, invfact

def C(n, r, fact, invfact):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

fact, invfact = build_fact(n)

sz = [0] * n
dp = [1] * n

def dfs(x, p):
    sz[x] = 1
    odd = 0
    even = 0

    for y in g[x]:
        if y == p:
            continue
        dfs(y, x)
        sz[x] += sz[y]

        if sz[y] % 2 == 0:
            even += 1
        else:
            odd += 1

    prod = 1
    for y in g[x]:
        if y == p:
            continue
        prod = prod * dp[y] % MOD

    if odd == 0:
        dp[x] = prod
    else:
        dp[x] = prod * C(odd, odd // 2, fact, invfact) % MOD

dfs(0, -1)

print(dp[0])
```DFS は、1 回の走査でサブツリー サイズと DP 値の両方を計算します。 奇数のサブツリーのみがパリティ フリップを導入するため、奇数の子と偶数の子の分離が不可欠です。 積の蓄積により、独立した内部構成が正しく乗算されることが保証されます。 

二項係数は階乗事前計算を使用して計算され、対数剰余べき乗呼び出しの繰り返しを回避します。 よくある間違いは、キャッシュを使用せずにノードごとの組み合わせを再計算することです。これにより、複雑さが O(n log n) に達します。 もう 1 つの微妙な問題は、DFS 中に親エッジを分離するのを忘れることです。これにより、サブツリーのサイズが誤って拡大されてしまいます。 

## 実用的な例

 ### 例 1

 ルート 1 に 2 つの葉の子 2 と 3 がある小さなツリーを考えてみましょう。 

| ノード | サイズ | 奇妙な子供たち | 子供でも | DP |
 | --- | --- | --- | --- | --- |
 | 2 | 1 | 0 | 0 | 1 |
 | 3 | 1 | 0 | 0 | 1 |
 | 1 | 3 | 2 | 0 | C(2,1)=2 |

 リーフでは、DP は自明に 1 です。ルートでは、両方の子のサブツリー サイズが奇数であるため、p = 2。交互のパリティ ロールを割り当てる方法の数は C(2,1)=2 で、DP[1]=2 となります。 

これは、奇数のサブツリーが複数存在する場合、それらが走査順序でどのように交互するかを答えが反映していることを確認します。 

### 例 2

 ここで、ルート 1 に 1 つの子 2 があり、ノード 2 に 1 つの子 3 があるとします。 

| ノード | サイズ | 奇妙な子供たち | 子供でも | DP |
 | --- | --- | --- | --- | --- |
 | 3 | 1 | 0 | 0 | 1 |
 | 2 | 2 | 0 | 1 | 1 |
 | 1 | 3 | 1 | 0 | 1 |

 ノード 2 のサブツリー サイズは均等であるため、パリティ フリップアップには寄与しません。 ノード 1 では、奇数サイズの子が 1 つだけあるため、p = 1 および C(1,0)=1 となり、DP[1]=1 となります。 

これは、偶数サイズのサブツリーがどのようにパリティの変更を抑制し、組み合わせ分岐を排除するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ノードとエッジは DFS で 1 回処理され、すべての DP 遷移は事前計算された階乗を使用して O(1) になります。 
| スペース | O(n) | 隣接リスト、サブツリー サイズ、DP 配列、および再帰スタック |

MOD = 10**9 + 7

    n = int(input())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)
    for i in range(2, n + 1):
        fact[i] = fact[i - 1] * i % MOD
    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n - 1, -1, -1):
        invfact[i] = invfact[i + 1] * (i + 1) % MOD

    def C(n, r):
        if r < 0 or r > n:
            return 0
        return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

    sys.setrecursionlimit(10**7)

    sz = [0] * n
    dp = [1] * n

    def dfs(x, p):
        sz[x] = 1
        odd = 0
        even = 0

            dp[x] = prod
        else:

    dfs(0, -1)

 ## 特殊なケース

 単一ノード ツリーは、最も明確な境界ケースです。 DFS は sz[1]=1 を割り当て、子を割り当てないため、odd=0 および DP[1]=1 になります。 アルゴリズムは、可能な唯一の割り当てに一致する 1 を直接返します。 

連鎖構造は、組み合わせ選択の抑制を示します。 ルートを除くすべてのノードには子が 1 つだけあり、サブツリー サイズは代替パリティです。 各ステップで、奇数は 0 または 1 であるため、二項係数は 1 に評価され、全体として単一の有効な構成が生成されます。 

星型のツリーは、組み合わせのコアが現れる場所です。 すべての子が葉の場合、すべての子サブツリーのサイズは 1 になり、すべてが奇数になります。 ルートでは、p は子の数に等しく、DP は C(p, ⌊p/2⌋) になります。 この実装では、すべての子が同一の奇数寄与者として正しくグループ化され、内部構造の順列を過剰にカウントすることなく、交互のパリティ割り当てがカウントされます。
