 ## 解決策
 # 問題の理解

 タスクは、年からカレンダーの日付ごとに書くのにかかる鉛筆の総コストを計算することです。`A`年間を通じて`B`。 日付は、年を除いて、月番号と日番号を結合することによって表されます。 たとえば、3 月 7 日は次のようになります。`37`、12月24日は`1224`。 日付を書き込むコストは、その表現自体の数値です。 

答えに影響を与える一年の唯一の部分は、2 月が 28 日か 29 日かどうかです。 入力では 2 年が得られ、おそらく次のようになります。`10^18`、出力は、それらのすべての年にわたるすべての日付値の合計を剰余として換算したものです。`104206969`。 

年の大きさにより、年または日付を繰り返すことは直ちに除外されます。 を含む範囲`10^18`おおよそ何年もかかります`10^18 * 365`日付の計算は、プログラムが妥当な時間内に実行できる量をはるかに超えています。 この解決策では、ほとんどの年は同一であり、閏年の数のみが問題となるという事実を利用する必要があります。 

直接実装が失敗する可能性がある場所がいくつかあります。 年`0`もその1つです。 400 で割り切れるため、うるう年の規則を満たします。したがって、入力`0 0`2月を29日で使用する必要があり、次のようになります。`180987`。 閏年を数え始めるソリューション`1`誤って通常の年として扱われてしまいます。 

もう一つの罠は世紀の法則です。 入力`1900 1900`は、4 で割り切れますが、400 ではなく 100 で割り切れるため、通常の年です。その答えは次のとおりです。`180758`。 4 で割り切れる値のみを使用する解は、閏年の値を返します。 

反対側の境界が次の位置に表示されます。`2000 2000`。 今年は 400 で割り切れるため、うるう年となり、答えは次のようになります。`180987`。 すべての世紀をうるう年ではないとして拒否する解決策は、ここでは失敗します。 

# アプローチ

 ブルート フォース ソリューションでは、間隔内の毎年を処理し、それが閏年であるかどうかを判断し、その 12 か月とそれらの月内のすべての日をループします。 毎日、日付値を作成し、それを回答に追加します。 これは定義に直接従うため、正しいです。 

ただし、可能な最大の間隔には約`10^18`年。 年に 1 回の定時操作でもすでに遅すぎ、完全な日付シミュレーションには約`3.65 * 10^20`日中の操作。 カレンダーの繰り返し構造は、この必要性を取り除く重要な観察です。 

月の長さは決して変わらないため、通常の年はまったく同じ金額を寄付します。 各うるう年もまったく同じ金額を寄付します。 個々の年を合計する代わりに、範囲内に含まれる平年と閏年の数を数えるだけで済みます。 

一ヶ月間`m`と`L`日、最初の 9 日間は次の形式の値に寄与します`10m + day`、残りの日数は次の形式の値に寄与します。`100m + day`。 これら 2 つの部分を組み合わせると、直接式が得られます。`month_sum = m * (100L - 810) + L(L+1)/2`これをすべての月に使用すると、通常の年とうるう年の固定寄与率が得られます。 

残る問題は、閏年を数えることです。`0`特定の年に。 で割り切れる年数`k`から`0`を通して`n`は`n//k + 1`、ゼロ年が含まれているためです。 包含-排他により飛躍数が得られます。`multiples of 4 - multiples of 100 + multiples of 400`プレフィックス関数を何年も使用している`0..n`任意の区間を引き算で答えてみましょう。

 # アルゴリズムのチュートリアル

 1. 1 つの通常年と 1 つのうるう年の寄与を事前計算します。 月ごとに、その月のすべてのエンコードされた日付の合計の計算式を適用します。 これにより、同じカレンダー パターンを繰り返し再計算することが回避されます。 
2. プレフィックス関数を作成する`pref(x)`すべての年の貢献度の合計を返します。`0`を通して`x`。 もし`x`が負の場合、ゼロより前の年はないため、接頭辞はゼロになります。 
3. 4、100、および 400 で割り切れる数を使用して、プレフィックス範囲内の閏年をカウントします。残りの年は通常の年であるため、2 つのカウントにそれぞれの年間寄与率を乗算します。 
4. プレフィックスを減算して、要求された間隔を計算します。`pref(B) - pref(A-1)`。 結果を正の値に保つために、減算後に係数を適用します。 

これが機能する理由: すべての年は、通常または閏年の 2 つのカテゴリのいずれかに正確に属します。 通常の年はすべて同じ 12 か月の長さであるため、同じ金額を拠出します。 うるう年も同様です。 プレフィックス関数は、各タイプが何年存在するかを正確にカウントします。つまり、合計はこれら 2 つの固定拠出金の正確な組み合わせになります。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 104206969

def year_value(leap):
    days = [31, 29 if leap else 28, 31, 30, 31, 30,
            31, 31, 30, 31, 30, 31]

    total = 0
    for month, length in enumerate(days, 1):
        total += month * (100 * length - 810)
        total += length * (length + 1) // 2
    return total % MOD

NORMAL_YEAR = year_value(False)
LEAP_YEAR = year_value(True)

def leap_count(x):
    if x < 0:
        return 0
    return (x // 4 + 1) - (x // 100 + 1) + (x // 400 + 1)

def prefix(x):
    if x < 0:
        return 0

    leaps = leap_count(x)
    years = x + 1
    normal = years - leaps

    return (normal * NORMAL_YEAR + leaps * LEAP_YEAR) % MOD

def solve():
    A, B = map(int, input().split())
    print((prefix(B) - prefix(A - 1)) % MOD)

solve()
```

`year_value`12 か月すべてを 1 つの計算に圧縮します。 この数式は 1 桁の日と 2 桁の日をまとめて処理するため、個々の日付をループすることがなくなります。`leap_count`意図的に使用する`x//k + 1`だけではなく`x//k`。 余分な 1 はゼロ年を表し、他の年と同じ割り算ルールに従います。 

プレフィックスの計算には次のものを使用します。`x + 1`間隔はゼロから始まり、両方のエンドポイントが含まれるため、年になります。 最後の減算には次のものを使用します`A - 1`、つまり年`A`それ自体は含まれたままになります。 

Python の整数はオーバーフローしませんが、中間値が大きくなる可能性があります。 プレフィックス値を返すときに係数が適用され、最終的な答えも次のように正規化されます。`% MOD`減算がマイナスになる可能性があるからです。

# テストケース```python
import sys
import io

MOD = 104206969

def year_value(leap):
    days = [31, 29 if leap else 28, 31, 30, 31, 30,
            31, 31, 30, 31, 30, 31]
    total = 0
    for month, length in enumerate(days, 1):
        total += month * (100 * length - 810)
        total += length * (length + 1) // 2
    return total % MOD

NORMAL_YEAR = year_value(False)
LEAP_YEAR = year_value(True)

def leap_count(x):
    if x < 0:
        return 0
    return (x // 4 + 1) - (x // 100 + 1) + (x // 400 + 1)

def prefix(x):
    if x < 0:
        return 0
    l = leap_count(x)
    return ((x + 1 - l) * NORMAL_YEAR + l * LEAP_YEAR) % MOD

def solve_case(inp):
    a, b = map(int, inp.split())
    return str((prefix(b) - prefix(a - 1)) % MOD)

assert solve_case("1 3") == "542274", "sample"
assert solve_case("0 0") == "180987", "year zero leap"
assert solve_case("1 1") == "180758", "single normal year"
assert solve_case("1900 1900") == "180758", "century non leap"
assert solve_case("2000 2000") == "180987", "century leap"
assert solve_case("1000000000000000000 1000000000000000000") == "180987", "maximum year"

 # エッジケース

 入力用`0 0`、アルゴリズムは次のように計算します。`leap_count(0)`として`1//?`式を通して`(0//4+1) - (0//100+1) + (0//400+1)`、それは与える`1`。 その年は閏年として分類され、寄与します`180987`。 

入力用`1900 1900`、4 カウントで割り切れる場合は年が含まれますが、100 カウントで割り切れる場合は年が削除されます。 1900 は 400 で割り切れないため、加算されません。 結果には平年の寄与率が使用されます。 

入力用`2000 2000`、年は 100 で割り切れるルールによって削除され、400 で割り切れるルールによって復元されます。 閏年寄与分を受け取ります。 

などの広大な範囲の場合、`1 10^18`、アルゴリズムが何年もループすることはありません。 閏年と平年の年数を整数除算で評価するだけなので、最大制約でも実行時間は一定のままです。
