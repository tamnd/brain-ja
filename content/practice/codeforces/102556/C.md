 ## 解決策
 ## 問題の理解

 Riana は、左から右に番号が付けられたブロックがある 1 次元の通りを移動しています。 彼女はブロック 1 からスタートし、ブロック A に到達したいと考えています。歩いている間、彼女はどちらの方向を選択しても構いませんが、バス停によって移動ルールが変わります。バス停に到着すると、すぐにそこのバスに乗らなければならず、バスは彼女を 1 つの固定された目的地ブロックに送ります。 すべてのバスはより大きなブロック番号に移動するため、バスの乗車だけでサイクルを形成することはできません。 

入力は、道路の長さ、目的地のブロック、およびバス停のセットを記述します。 各バス停は、その位置からより大きな位置への有向ジャンプです。 タスクは、最終的にリアナをブロック A に配置する一連の歩行選択が存在するかどうかを判断することです。出力は次のようになります。`YES`彼女がそこに到達できれば、そして`NO`さもないと。 

制約は小さく、ブロック数は最大 100、バス停数は最大 50 です。 これは、考えられるすべての有用な状態を探索するアルゴリズムで十分であることを意味します。 多くの異なるパスが同じブロックにつながる可能性があるため、すべての可能な歩行パスを指数関数的に探索するソリューションは不要です。 代わりに、どのブロックがすでに到達したかを保存し、それぞれを 1 回処理することができます。 

主なエッジケースは、バスの強制的な性質に起因します。 よくある間違いは、バスをオプションのジャンプとして扱うことです。 例えば：```
5 4 1
2 5
```正しい答えは、`NO`。 ブロック 1 から右に歩くとブロック 2 に到達し、リアナはバスに乗ってブロック 5 に移動することになります。その後、彼女は左に歩いてブロック 4 に到達できるため、この例では実際に次のようになります。`YES`。 危険な部分は最終的な答えではなく、仮定です。ソリューションが強制バスを無視し、ブロック 2 を通常の位置として扱う場合、無効なパスを探索する可能性があります。 

より直接的な例は次のとおりです。```
6 3 1
2 6
```正しい答えは、`NO`。 ブロック 1 から右に歩くと、ブロック 2 の停留所に到達し、すぐにリアナはブロック 6 に送られます。リアナはそこから左に歩くことしかできませんが、ブロック 3 はブロック 2 のバス停の手前にあり、送られなければその停留所を越えることができないため、再び到達することはできません。 隣接するすべてのブロックを通過する移動を許可する不用意な最短パスの解釈は、パスを誤って検出する可能性があります。 

別のエッジケースが宛先で始まります。```
5 1 1
1 5
```正しい答えは、`YES`。 リアナはすでにアテネオにいるため、移動する必要はありません。 目的地を確認する前に常にバス トランジションを適用する実装では、彼女を誤って遠ざけてしまう可能性があります。 

## アプローチ

 簡単なアプローチは、考えられるあらゆる歩行判断をシミュレートすることです。 リアナは、ブロックから 1 ブロックずつ左または右に繰り返し歩いてみることができ、バス停に着くたびに目的地にジャンプします。 これは運動の規則に直接従うため、これは正しいです。 ただし、訪問したブロックを記憶せずにパスの検索として実装すると、同じ状況を何度も再訪する可能性があります。 ここの通りは小さいにもかかわらず、特にリアナがバスを起動する前に前後にさまようことができるため、自然な強引なビューでは、歩くことを膨大な数の可能なシーケンスとして扱います。 

重要な観察は、すべての強制バス チェーンが終了した後は、Riana の現在のブロックのみが重要になるということです。 彼女のこれまでの歩行歴は将来の選択に影響しません。 可能なブロックは N 個だけなので、到達可能なブロックに対してグラフ検索を実行できます。 

残りの問題は、グラフのエッジをどのように作成するかです。 Riana は、到達可能なブロックから、アテネオに到着するか、その方向の最初のバス停に遭遇するまで、どちらの方向にも歩くことができます。 バスはすぐに到着するため、彼女は最初のバス停を通過できません。 その方向にバス停がない場合は、その方向のすべてのブロックに徒歩で到達できます。 バス停がある場合、その停留所から強制的にバスをすべて追跡した後の目的地のみが結果として得られます。 

ブロックの数が十分に少ないため、トランジションを生成するときに、ある位置の周囲のすべてのブロックをチェックできます。 これにより、単純な幅優先検索ソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 移動の選択肢の数が指数関数的に増加する可能性 | O(N) | メモ化しないと遅すぎる |
 | 最適 | O(N² + B) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのバス停を読み取り、各停留所の行き先をブロック番号で保存します。 エントリが欠落している場合は、そのブロックがバス停ではないことを意味します。 
2. スターティングブロックがすでにアテネオの場合は、すぐに答えます`YES`。 目的地にいるだけで十分であり、移動する必要はありません。 
3. ブロック 1 から開始する幅優先検索を使用します。各キュー エントリは、すべての強制バス乗車が終了した後に Riana が存在できるブロックを表します。 
4. ブロックを処理するときは、バス停にぶつかる前に左に歩いてアテネオに到達できるかどうかを確認します。 左側にバス停がない場合は、より小さなブロックごとにアクセスできます。 左側に最も近いバス停が存在する場合、徒歩で到達できるのは現在のブロックとそのバス停の間のブロックのみです。 
5. 右に歩きながら同じチェックを実行します。 最初にバス停に遭遇した場合、次に到達可能な状態はそのバスの目的地となり、その後にその目的地でトリガーされる追加のバスが続きます。 
6. 新しい到達可能なブロックが見つかるたびに、それをキューに追加します。 ブロックがすでに処理されている場合は、ブロックを再度探索しても新しいことは何も明らかにできないため、そのブロックをスキップします。 
7. A に到達せずに検索が終了した場合、出力`NO`。 

なぜ効果があるのか:

 検索によって維持される不変条件は、キューに配置されたすべてのブロックが、すべての強制バス乗車に従った後に Riana が実際に占有できるブロックであるということです。 ブロックを拡張するとき、アルゴリズムは、左または右に歩くことを選択した場合の正当な結果を正確に考慮します。 それは彼女がバスに乗らずにバス停を通過することを決して許さないし、不可能な移動を生み出すこともない。 すべての有効な決定シーケンスはこれらの遷移のシーケンスに対応するため、到達可能な宛先は最終的に発見されます。 検索で A が見つからない場合、有効な一連の選択肢は A に到達できません。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    N, A, B = map(int, input().split())

    bus = [-1] * (N + 1)
    for _ in range(B):
        x, y = map(int, input().split())
        bus[x] = y

    if A == 1:
        print("YES")
        return

    def follow_bus(pos):
        while bus[pos] != -1:
            pos = bus[pos]
        return pos

    start = follow_bus(1)

    visited = [False] * (N + 1)
    visited[start] = True
    q = deque([start])

    while q:
        pos = q.popleft()

        if pos == A:
            print("YES")
            return

        left_stop = -1
        for x in range(pos - 1, 0, -1):
            if bus[x] != -1:
                left_stop = x
                break

        if left_stop == -1:
            for x in range(1, pos):
                if not visited[x]:
                    if x == A:
                        print("YES")
                        return
                    visited[x] = True
                    q.append(x)
        else:
            for x in range(left_stop + 1, pos):
                if not visited[x]:
                    if x == A:
                        print("YES")
                        return
                    visited[x] = True
                    q.append(x)
            nxt = follow_bus(left_stop)
            if not visited[nxt]:
                visited[nxt] = True
                q.append(nxt)

        right_stop = -1
        for x in range(pos + 1, N + 1):
            if bus[x] != -1:
                right_stop = x
                break

        if right_stop == -1:
            for x in range(pos + 1, N + 1):
                if not visited[x]:
                    if x == A:
                        print("YES")
                        return
                    visited[x] = True
                    q.append(x)
        else:
            for x in range(pos + 1, right_stop):
                if not visited[x]:
                    if x == A:
                        print("YES")
                        return
                    visited[x] = True
                    q.append(x)
            nxt = follow_bus(right_stop)
            if not visited[nxt]:
                visited[nxt] = True
                q.append(nxt)

    print("NO")

solve()
```バス配列には、各バス停からの可能な遷移のみが保存されます。 の`follow_bus`この関数は、バスの目的地が別のバス停である場合を処理します。 バスごとにブロック番号が増加するため、このループは常に終了します。 

BFS キューには、すべての自動バス乗車がすでに行われた後に可能な位置のみが含まれています。 これが、初期位置が次のように正規化される理由です。`follow_bus(1)`。 特別なチェックは、`A == 1`目的地に到着するためにバスに乗る必要がないため、その前に起こります。 

トランジションを生成するとき、コードは各方向で最も近いバス停を検索します。 その停留所より前のブロックは、有効な徒歩目的地です。 停留所に到達するとすぐにバスの乗車がトリガーされるため、停留所自体は歩行状態として追加されません。 停留所から作成される唯一の状態は、バスの最終目的地です。 

すべての値が最大 100 であるため、整数のオーバーフローの問題はありません。ループには、現在位置と次の停留所の間のブロックのみが意図的に含まれており、Riana がバスに乗らずに停留所に立ってしまうという 1 つずれた間違いを回避します。

## テストケース```python
import sys
import io
from collections import deque

def solve_case(inp):
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    N, A, B = map(int, input().split())
    bus = [-1] * (N + 1)

    for _ in range(B):
        x, y = map(int, input().split())
        bus[x] = y

    if A == 1:
        return "YES\n"

    def follow_bus(pos):
        while bus[pos] != -1:
            pos = bus[pos]
        return pos

    start = follow_bus(1)
    visited = [False] * (N + 1)
    visited[start] = True
    q = deque([start])

    while q:
        pos = q.popleft()
        if pos == A:
            return "YES\n"

        for direction in (-1, 1):
            x = pos + direction
            while 1 <= x <= N:
                if bus[x] != -1:
                    nxt = follow_bus(x)
                    if not visited[nxt]:
                        visited[nxt] = True
                        q.append(nxt)
                    break
                if not visited[x]:
                    if x == A:
                        return "YES\n"
                    visited[x] = True
                    q.append(x)
                x += direction

    return "NO\n"

 ## 特殊なケース

 Riana が目的地から開始する場合:```
5 1 1
1 5
```アルゴリズムチェック`A == 1`バスを追いかける前に。 出力します`YES`、強制的な移動が発生する前に、到着を完了したものとして正しく処理します。 

バスが下位ブロックへのアクセスをブロックする場合:```
6 3 1
2 6
```検索はブロック 1 から始まります。右に移動するとバス停であるブロック 2 に到達するため、結果として得られる状態はブロック 6 だけです。ブロック 6 から左に歩くとブロック 4 に到達しますが、再びブロック 2 に足を踏み入れるとバスがトリガーされます。 ブロック 3 は決して生成されないため、アルゴリズムは次のように出力します。`NO`。 

複数のバスの乗車がすぐに発生する場合:```
10 5 2
1 3
3 8
```開始ブロックは、1 のバスに続いてブロック 3 まで進み、次に 3 のバスの直後にブロック 8 まで続きます。検索はブロック 8 から開始され、通常どおり続行されます。 バスの目的地が増加しているため、このチェーンが永久にループすることはありません。
