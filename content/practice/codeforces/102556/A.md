## アプローチ

 簡単なアプローチは、空の位置のサブセットを埋めることを検討し、結果として得られる円に敵コンポーネントが 1 つだけあるかどうかを確認することです。 考えられるすべてのドットのサブセットについて、円をシミュレートし、接続されている敵グループの数を数えることができます。 これは、考えられるすべての最終的な配置を検討するため正しいですが、サブセットの数は指数関数的に増加します。 100 個のポジションがある場合、最悪の場合には 100 個の空のポジションが含まれ、次のようになります。$2^{100}$処理することが不可能な可能性。 

重要な観察は、敵ではなく何もない空間を見ることから始まります。 既存の敵は、点の円形の隙間によって分離されます。 ドットの隙間を完全に埋めると、その隙間を通して両側の敵グループがつながります。 円全体を 1 つの接続された敵グループにするには、おそらく 1 つを除くすべてのドット ギャップを削除する必要があります。 

なぜ 1 つのギャップが残るのでしょうか? 連続した空のセグメントを 1 つ残すことを想像してください。 他のすべてのギャップは埋められるため、埋められたギャップを通って円を周回するとすべての敵に到達します。 残りの空のセグメントは、同じ接続された敵のチェーンの終わりと始まりの間の未使用のブレークになります。 

ギャップを維持するとドットを埋める手間が省けるため、最大のドット ギャップを維持し、他のすべてのドット ギャップを埋める必要があります。 答えは、ドットの総数から敵グループ間の最大の円形のギャップの長さを引いたものです。

 ## アルゴリズムのチュートリアル

 1. 円内の敵の数を数えます。 敵がいない場合は接続するものが何もないため、答えはゼロになります。 
2. 空の位置の連続したシーケンスをすべて検索します。 文字列は循環しているため、最初と最後の位置が同じ空のシーケンスに属している可能性があるため、スキャンでは境界を慎重に処理する必要があります。 
3. 最大の空シーケンスの長さを記録します。 これは、最後の円形チェーンの切れ目を表すため、空のままにすることができる唯一のギャップです。 
4. 空のポジションの総数を数えます。 最大のギャップの外側にあるすべての空いているポジションは敵に変えなければなりません。 
5. 空の位置の合計数から最大ギャップ長を引いた値を返します。 

最大のギャップをそのままにしておくのが最善である理由は、敵グループを結び付けるためには他のすべてのギャップをなくす必要があるためです。 ギャップを小さく保つと、必要以上に多くのポジションを埋める必要が生じます。 

なぜ効果があるのか:

 円の周りに存在する敵グループを考えてみましょう。 空のギャップはすべて、2 つの隣接するグループを分離します。 2 つ以上のギャップが空のままの場合、円には複数の切断された敵セクションが含まれます。 したがって、最大でも 1 つのギャップが生き残ることができます。 最大のギャップを選択すると、最大数のドットを埋めることが回避されるため、埋める位置の数が最小限に抑えられます。 アルゴリズムはすべてのギャップを検査し、まさにこの最適なギャップを選択するため、戻り値は最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    if 'X' not in s:
        print(0)
        return

    total_dots = s.count('.')

    doubled = s + s
    first_x = doubled.find('X')

    max_gap = 0
    current = 0

    for i in range(first_x, first_x + n):
        if doubled[i] == '.':
            current += 1
            max_gap = max(max_gap, current)
        else:
            current = 0

    if max_gap > total_dots:
        max_gap = total_dots

    print(total_dots - max_gap)

solve()
```この解決策では、接続する敵グループが存在しないため、最初に空の円のケースが処理されます。 その後、少なくとも 1 つ`X`が存在するため、敵の位置でスキャンを開始して円のビューを回転させます。 これにより、ドット シーケンスが入力文字列の末尾と交差する部分のあいまいさがなくなります。 

二重化された文字列により、モジュール式インデックスを使用せずに循環近傍にアクセスできるようになります。 正確にスキャンするだけです`n`最初の敵の後ろに位置するため、終わりと始まりからの点のシーケンスは 1 つの連続したギャップとしてカウントされます。 

変数`current`現在の空のセグメントの長さを格納します。 敵が出現するたびにセグメントが終了し、`max_gap`これまでに見られた最高のギャップがすでに含まれています。 可能な最大のギャップはドットの総数を超えることはできないため、最終的な答えは単にその保存されたギャップに含まれないドットの数になります。 

Python では、入力の長さが 100 のみであるため、整数オーバーフローの懸念はありません。主な境界条件は、開始点を正しく選択することです。 任意の位置から開始すると、円形のドット ギャップを 2 つの小さな部分に分割できます。

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    s = sys.stdin.readline().strip()
    n = len(s)

    if 'X' not in s:
        ans = 0
    else:
        total_dots = s.count('.')
        doubled = s + s
        start = doubled.find('X')

        best = 0
        cur = 0
        for i in range(start, start + n):
            if doubled[i] == '.':
                cur += 1
                best = max(best, cur)
            else:
                cur = 0

        ans = total_dots - min(best, total_dots)

    sys.stdin = old_stdin
    return str(ans)

assert solution("XX..XX.X....") == "4", "sample 1"
assert solution("X..XX.X..X") == "3", "sample 2"

assert solution("X") == "0", "single enemy"
assert solution(".....") == "0", "no enemies"
assert solution("XXXXX") == "0", "already connected"
assert solution("XX..XX") == "0", "circular connection"
assert solution("X.X.X") == "2", "alternating enemies"
