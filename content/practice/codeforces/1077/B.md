 ## 解決策
 ## 問題の理解

 私たちは一列のアパートを与えられ、それぞれのアパートに明かりがついたり消えたりしています。 構成はバイナリ配列で、1 は点灯、0 は暗いことを意味します。 位置 i の居住者は、現在、両方の隣人が照明をオンにし、自分の照明がオフになっているパターンの真っ只中にいる場合、不安を感じます。 

より正確には、トリプル (a[i-1], a[i], a[i+1]) が (1, 0, 1) に等しい場合、インデックス i で障害が発生します。 目標は、これらの妨害を直接カウントすることではなく、そのようなパターンが配列内のどこにも存在しないように、居住者が電気を消さなければならないアパートの最小数を決定することです。 

操作には制約があります。正確に k 個の異なる位置を選択し、それらの位置を強制的に 0 にすることができます。他のすべての位置は変更されません。 タスクは、パターン 1,0,1 のすべての出現を排除する最小の k を見つけることです。 

制約は小さく、n は最大 100 です。これは、3 次または 2 次の解でも十分に高速であることを意味します。 ただし、問題の構造から、最適な解決策は、インデックスのサブセットを強引に列挙するよりもはるかに単純であることがわかります。 

複数の外乱が重なると、微妙なエッジケースが発生します。 たとえば、配列 1 0 1 0 1 では、位置 3 の中央のゼロをオフにすると、位置 2 と 4 を中心とする 2 つの重複する潜在的なパターンが固定されます。各外乱を個別に処理する単純なアプローチでは、必要な演算が過剰にカウントされる可能性があります。 

障害がまったくない場合には、別の特殊なケースが発生します。 その場合、答えはゼロであり、貪欲またはシミュレーションのアプローチでは、不必要な変更を誤って導入することなく、これを正しく保存する必要があります。 

## アプローチ

 直接的な総当たり戦略では、位置のすべてのサブセットをオフにして、結果の配列をシミュレートし、インデックス i がまだパターン 1,0,1 を満たすかどうかを確認します。 サブセットごとに、配列を変更して 1 回スキャンします。これには O(n) のコストがかかります。 2^n 個のサブセットがあるため、これは O(n・2^n) となり、n = 100 の場合にはすでに大きくなります。 

重要な観察は、外乱は局所的であり、非常に構造化された方法で独立しているということです。 位置 i での外乱は、連続する 3 つの要素のみに依存します。 これを排除するには、最終構成で 3 つの位置 i-1、i、i+1 の少なくとも 1 つが 0 になるようにする必要があります。 

ただし、重要な点は、中間位置 i をオフにしても、1 つの乱れが修正されるだけではないということです。 隣接するインデックスを中心とする重複するパターンを同時に除去することができます。 これは、貪欲な左から右への構築を示唆しています。パターン 1,0,1 を検出したら、可能な限り最も効率的な方法で直ちに修正する必要があります。 

左から右にスキャンすると、i を中心とする外乱が見つかるたびに、最適な動きは位置 i+1 をオフにすることです。 この選択は、現在の乱れを解決し、右側を変更しないままにすることで将来生じる重複を防ぐため、非常に重要です。 代わりに i または i−1 をオフにすると、後で追加の操作を強制する残留構造が残る可能性があります。 

この貪欲な決定は、各外乱がその中心に固定されており、インデックス i を通過すると、その後の決定が以前のインデックスに影響を与えることができないため、安全です。 したがって、単一のリニア スキャン中にすべての発生が正確に 1 回処理されることを確認するだけで済みます。

 ## アルゴリズムのチュートリアル

1. 1 から n-2 までのインデックス i を使用して、配列を左から右にスキャンします。 外乱には連続する 3 つの位置が必要であるため、エンドポイントを避けます。 
2. 各位置 i で、a[i−1] = 1、a[i] = 0、および a[i+1] = 1 かどうかを確認します。これにより、i を中心とする乱れた構成が特定されます。 
3. そのようなパターンが見つかった場合は、この乱れを 1 回の操作で修正する必要があるため、答えを 1 増やします。 
4. i での外乱を修正した後、a[i+1] = 0 を設定して、位置 i+1 をオフにするシミュレーションを行います。これは、i+1 に関係する重複パターンが後で再度カウントされないようにするため、重要です。 
5. 後退せずに前方にスキャンを続けます。 たとえ配列を変更したとしても、以前のインデックスに関係する障害はすでに解決されているか、将来の変更の影響を受けることがないため、以前のインデックスを再検討することはありません。 
6. スキャンが終了したら、実行された操作の合計数を返します。 

### なぜ効果があるのか

 正確性は、各外乱がその中心インデックス i に一意に固定されているという事実に依存しており、a[i+1] = 0 を強制することでそれを解決すると、以前の決定との干渉を最小限に抑えながら、それを維持できる唯一の構成が破壊されます。 インデックス i を越えると、要素を 1 から 0 に変えるだけで変更を元に戻さないため、以降の操作では i を中心とする有効な 1,0,1 を再導入することはできません。 これにより、各外乱が最大 1 回だけカウントされることが保証され、貪欲な選択によってより安価なソリューションが妨げられることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    k = 0
    i = 1
    
    while i < n - 1:
        if a[i - 1] == 1 and a[i] == 0 and a[i + 1] == 1:
            k += 1
            a[i + 1] = 0
            i += 2
        else:
            i += 1
    
    print(k)

if __name__ == "__main__":
    solve()
```このソリューションは配列を読み取り、修正の数を表す単一のカウンターを維持します。 左隣が必要なため、スキャンはインデックス 1 から開始され、同じ理由で最後のインデックスの前で停止します。 

障害が見つかった場合は、すぐに右隣の電源をオフにしてそれを「修正」します。 この選択は設定によってエンコードされます`a[i+1] = 0`。 次に、この操作ですでに無効化されている重複する構造の再検討を避けるために、ポインタは 2 だけ前にジャンプします。 

ロジックの残りの部分は単純な線形トラバースであり、各位置が最大 1 回処理されることが保証されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    
    def solve():
        n = int(input())
        a = list(map(int, input().split()))
        k = 0
        i = 1
        while i < n - 1:
            if a[i - 1] == 1 and a[i] == 0 and a[i + 1] == 1:
                k += 1
                a[i + 1] = 0
                i += 2
            else:
                i += 1
        print(k)

    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

# provided sample
assert run("""10
1 1 0 1 1 0 1 0 1 0
""") == "2"

# minimum size, no disturbance
assert run("""3
1 1 1
""") == "0"

# single disturbance
assert run("""3
1 0 1
""") == "1"

# alternating chain
assert run("""5
1 0 1 0 1
""") == "2"

# all zeros
assert run("""6
0 0 0 0 0 0
""") == "0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1 1 | 0 | 妨害はありません |
 | 1 0 1 | 1 | 単一修正のケース |
 | 1 0 1 0 1 | 2 | 重なり合うパターン |
 | すべてゼロ | 0 | 境界の安全性 |

 ## 特殊なケース

 のような入力の場合`1 0 1 0 1`、アルゴリズムはインデックス 1 で外乱に遭遇し、すぐに右隣を反転し、前方にシフトします。 これにより、同じ領域が二重にカウントされるのを防ぎます。 その後インデックス 3 に達すると、更新された配列に以前の変更が反映され、真に残っている外乱のみが処理されるようになります。 

次のような完全に均一な配列では`0 0 0 0`、スキャンによって条件がトリガーされることはないため、カウンターはゼロのままであり、不要な操作は導入されません。
