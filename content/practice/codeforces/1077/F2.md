 ## 解決策
 ## 問題の理解

 私たちには、一列に並べられた一連の写真が与えられており、それぞれに美しさの価値があります。 正確に選択する必要があります`x`これらの写真のうち再投稿するものを選択できますが、その選択はカバレッジ ルールによって制限されます。少なくとも一定の長さの連続したブロック`k`選択した画像を少なくとも 1 つ含める必要があります。 

この制約により、選択されたインデックスが配列全体で十分な頻度になることが強制されます。 行列に沿って歩くことを想像したら、決して行くことは許されません`k`少なくとも 1 つの要素を選択せず​​に連続した位置を指定します。 同時に、正確に選択したいと考えています`x`elements and maximize the sum of their beauty values.

 重要な張力は、間隔と値の間にあります。 Choosing high-value elements is good, but skipping too much creates gaps that violate the coverage rule. So the solution is fundamentally about balancing “how many we pick so far” with “where the last pick happened”.

 制約`n ≤ 5000`そして`x ≤ n`指数関数的なサブセットの列挙を除外します。 立体的またはそれ以上の解決策`(position, picks, last pick)`最適化された形式ではかろうじて合格する可能性がありますが、すべてのサブセットを試すことは不可能です。 この構造は、選択が行われた回数を追跡する追加の状態を備えたプレフィックスに対する動的プログラミングを強く示唆しています。 

微妙なエッジケースが現れるのは、`k = 1`。 その場合、長さ 1 のすべてのセグメントには選択された要素が含まれている必要があり、すべての要素が強制的に選択されます。 スキップする自由を前提とした解決策はすぐに失敗します。 別のエッジケースが発生するのは次の場合です。`x`に比べて小さすぎます`n / k`、必要な密度でアレイをカバーすることが不可能になります。 たとえば、次の場合`n = 10, k = 3`、配列をカバーするには少なくとも 4 つのピックが必要です。 もし`x < 4`、最適に選択したとしても答えは不可能です。 

## アプローチ

 ブルートフォースアプローチでは、サイズのすべてのサブセットを選択しようとします。`x`間隔の制約が維持されるかどうかを確認します。 有効性は、選択したインデックスをスキャンし、連続する選択したポジション間のギャップが超過していないことを確認することでテストできます。`k - 1`。 これにはすでに費用がかかります`O(n choose x)`サブセット、そして各サブセットのチェックにも時間がかかります`O(n)`、小さな入力を超えると完全に実行不可能になります。 

制約の構造は、別の視点を示唆しています。サブセットについてグローバルに考える代わりに、最後に選択した位置についてローカルに考えます。 最後に選択したインデックスがわかれば、ルールに違反せずにどこまで移動できるかを判断できます。 これは当然、配列を左から右に処理し、これまでに選択された要素の数を維持する DP につながります。 

重要な観察点は、それぞれの位置で`i`、それを選択する場合は、前の選択が以下を超えていないことを確認するだけで済みます。`k`離れた位置にあります。 それより遠い場合、状態は無効です。 これにより、問題は、遷移が境界のあるギャップに依存する制約付き選択 DP に縮小され、最大まで後方にのみスキャンすることで、最良の前の状態を効率的に計算できます。`k`ポジション。 

私たちは定義します`dp[i][j]`最初の値を使用して最大合計として`i`要素と正確な選択`j`要素 (最後に選択された要素がその位置にある)`i`。 カバレッジ制約により、前の状態からの遷移が次の位置からのみ発生することが保証されます。`[i-k, i-1]`そうしないと、少なくとも次のギャップが生じてしまうためです。`k`選択なしで。 

これにより、問題は、最後のスライディング ウィンドウ最適化による構造化 DP に縮小されます。`k`ポジション。

 ## アルゴリズムのチュートリアル

 各状態が、指定された数の選択された画像と特定の位置で終了する場合に達成可能な最良の合計を追跡する動的プログラミング テーブルを構築します。 

1. DP 配列を初期化する`dp[i][j]`j 番目に選択されたピクチャが位置 i にあるときの最大の美しさの合計を表します。 シングルピックを除き、すべての状態は無効として開始されます。 
2. ポジションごとに`i`、この要素のみを最初の選択として選択することで、新しいシーケンスを開始できるようになります。`dp[i][1] = a[i]`。 これにより、DP に有効な単一要素のサブシーケンスがシードされます。 
3. ポジションごとに`i`そして数えます`j > 1`、j 番目に選択された要素を次の場所に配置しようとします。`i`。 制約を維持するには、前に選択した要素が次の場所にある必要があります。`[i-k, i-1]`。 
4. 計算します`dp[i][j]`すべての有効な以前のポジションの中から最良の値を取得することによって`p`で`[i-k, i-1]`使用して`dp[p][j-1] + a[i]`。 これにより、カウントの正確さと間隔の有効性の両方が保証されます。 
5. 前回の最大値の再計算を避けるため`k`あらゆる状態のポジションに応じて、各状態のスライド最大構造を維持します。`j-1`レイヤー、移動に応じて更新します`i`。 
6. DP を埋めると、答えは全体の最大値になります。`dp[i][x]`すべての有効な終了位置に対して`i`。 
7. 状態がない場合は、`x`選択内容は有効なので出力します`-1`。 

スライディング ウィンドウの最適化により、これが実現可能になります。スライディング ウィンドウの最適化がないと、各遷移がスキャンされてしまいます。`k`満員につながるポジション`O(n^2 x)`アプローチ。 

### なぜ効果があるのか

 どの時点においても、この問題によって課される唯一の制限は、選択された連続する要素間の最大許容ギャップです。 このプロパティは、完全な履歴ではなく、最後に選択されたインデックスのみに依存します。 したがって、すべての有効な選択は、連続する選択された位置間の遷移に一意に分解でき、それぞれが距離内にあるように制約されます。`k`。 DP はこれらの遷移を正確にキャプチャし、すべての有効なシーケンスはこの状態グラフを通る 1 つのパスに正確に対応します。 すべての遷移では実現可能性が維持され、すべての有効な先行遷移が考慮されるため、最大の DP 状態が最適な解決策となる必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, x = map(int, input().split())
    a = list(map(int, input().split()))

    INF = -10**18

    # dp[j][i]: best sum using j picks, last pick at i
    dp_prev = [INF] * n
    dp_cur = [INF] * n

    # initialize: 1 pick
    for i in range(n):
        dp_prev[i] = a[i]

    if x == 1:
        print(max(dp_prev))
        return

    for j in range(2, x + 1):
        dp_cur = [INF] * n
        best = INF

        for i in range(n):
            # maintain window [i-k, i-1]
            if i - 1 >= 0:
                best = max(best, dp_prev[i - 1])

            if i - k - 1 >= 0:
                best = max(best, dp_prev[i - k - 1])

            if best != INF:
                dp_cur[i] = best + a[i]

        dp_prev = dp_cur

    ans = max(dp_prev)
    print(ans if ans > INF else -1)

if __name__ == "__main__":
    solve()
```この実装では、DP を 2 つの層 (以前のピック数と現在のピック数) に圧縮します。 各反復では、次に選択された要素を各位置に配置するための最適な値が構築されます。 変数`best`前回のスライド最大値として機能します`k`適格なポジションを確保し、有効な前任者のみを考慮するようにします。 

よくある落とし穴は、ウィンドウが存在することを忘れることです。`[i-k, i-1]`、 ない`[i-k+1, i]`。 もう 1 つの微妙な問題は、不可能な状態の処理です。`-inf`したがって、無効な遷移が加算によって誤って有効になることはありません。 

## 実用的な例

 ### 例 1

 入力:```
5 2 3
5 1 3 10 1
```DP レイヤーをピック数によって追跡します。 

| j (ピック) | i=0 | i=1 | i=2 | i=3 | i=4 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 5 | 1 | 3 | 10 | 1 |
 | 2 | - | 6 | 8 | 13 | 11 |
 | 3 | - | - | 9 | 18 | 19 |

 最終的な答えは 18 です。これは、遷移に応じてインデックス (0, 2, 3) または (0, 2, 3) を選択することで得られますが、ギャップが 1 を超えることはありません。 

このトレースは、DP がローカル制約を維持しながら、より長い有効なシーケンスを徐々に構築する方法を示しています。 

### 例 2

 入力:```
4 3 2
1 100 1 100
```ここで、長さ 3 のセグメントにはピックが含まれている必要があるため、連続する 3 つのポジションをスキップすることはできません。 

| j | i=0 | i=1 | i=2 | i=3 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 100 | 1 | 100 |
 | 2 | - | 101 | 200 | 201 |

 ベストアンサーは、位置 1 と 3 を選択して 201 です。 

これは、制約がどのようにスプレッドアウト選択を強制しながら、高い値を貪欲に優先するかを示しています。

 ## 特殊なケース

 いつ`k = 1`、すべての単一要素セグメントには選択した要素が含まれている必要があるため、すべての位置を選択する必要があります。 アルゴリズムは、すべての値を合計し、正確に選択することになります。`n`項目、および遷移をスキップする DP は、明示的に処理されない場合、正確性に違反します。 

いつ`x`小さすぎてカバレッジを満たすことができません。たとえば、`n = 10, k = 4, x = 2`, どのような配置でも、4 つの連続する選択されていない要素のブロックを避けることはできません。 すべての状態が無効になり、到達可能なものがなくなるため、DP には当然これが反映されます。`dp[n][x]`。 

値が非常に偏っている場合 (中央に 1 つの非常に大きな要素がある場合など)、DP はそれを取得することと、将来の実現可能性を失うことのバランスを正しくとる必要があります。 ウィンドウ制約により、最適なローカル値を取得した場合でも、状態遷移を通じて間隔を強制することでグローバルな妥当性が維持されることが保証されます。
