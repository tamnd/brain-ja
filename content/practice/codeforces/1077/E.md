 ## 解決策
 ## 問題の理解

 それぞれの問題がトピックに属する複数の問題セットが与えられます。 同じトピックが何度も登場する可能性があります。 このプールからいくつかのコンテストを作成したいと考えています。 各コンテストでは単一のトピックの問題のみを使用する必要があるため、均質です。 コンテストごとに異なるトピックを使用する必要があるため、各トピックは最大 1 つのコンテストに参加できます。 

これらのコンテストは順番に並べられています。 最初のコンテストで使用すると判断した場合$x$問題がある場合は、次は使用する必要があります$2x$、次$4x$、など、厳密な二重連鎖を形成します。 作成するコンテストの数は自由に選択でき、開始サイズも自由に選択できます。$x$。 目的は、コンテストの数を最大化することではなく、選択したすべてのコンテストで使用される問題の総数を最大化することです。 

主要な構造は、各コンテストが問題の固定予算を消費し、予算が指数関数的に増加するということです。 トピックは繰り返すことができないため、シーケンスの各ステップには異なるトピックを割り当てる必要があり、そのトピックには、そのステージ サイズをサポートするのに十分な問題が含まれている必要があります。 

制約$n \le 2 \cdot 10^5$が必要であることを意味します$O(n \log n)$または$O(n)$アプローチ。 すべての可能な開始サイズとトピックの割り当てを明示的にシミュレートしようとすると、特に各トピックが何度も出現する可能性があり、単純なマッチングでは大きな頻度リストを繰り返しスキャンすることになるため、遅すぎます。 

周波数が不均一な場合、微妙な障害が発生することがあります。 たとえば、1 つのトピックのカウントが膨大で、他の多くのトピックのカウントが小さい場合、2 倍の順序を無視して単純に最大の周波数を最初に取得する貪欲な割り当てでは、初期段階で大きなカウントが無駄になったり、より適切な配置が存在するにもかかわらずチェーンの拡張に失敗したりする可能性があります。 

もう 1 つの特殊なケースは、複数のトピックが同じ頻度を持つ場合です。 素朴なアプローチではこれらを同じ意味で扱うかもしれませんが、初期段階では後の段階よりも消費する問題がはるかに少なく、順序を間違えると実行可能な拡張が妨げられる可能性があるため、代入順序が重要になります。 

## アプローチ

 強引なアイデアは、考えられるすべての開始トピックとすべての開始サイズを考慮することです。 固定開始サイズの場合$x$、チェーンを構築しようとします。少なくとも次の条件を備えたトピックを選択します。$x$問題、次に少なくとも以下の内容の他のトピック$2x$、 それから$4x$、 等々。 選択肢ごとに、使用した問題の合計を計算し、最大値を取得します。 

これはすべての有効なシーケンスを探索するため、原則として正しいです。 ただし、試行のたびに、トピック間で実行可能な次の頻度を繰り返し検索します。 まで$2 \cdot 10^5$問題があるため、異なる周波数の数が多く、可能なチェーンの数も多くなります。 周波数を圧縮したとしても、すべてのチェーンをチェックすると、実際には 2 次またはそれ以上の結果が得られます。 

重要な観察は、問題の構造は個々の問題ではなく、トピックの頻度のみに依存するということです。 トピックごとに存在する問題の数を計算すると、各トピックを「容量」値として考えることができます。 次に、これらの容量を等比級数のレベルに割り当てます。 

スタートを選択して順方向にシミュレーションする代わりに、視点を逆転させます。たとえば、コンテストの数を固定します。$k$、レベルへのトピックの可能な限り最適な割り当てを確認してください。$1, 2, 4, \dots, 2^{k-1}$。 固定の場合$k$使用量を最大化するには、利用可能な最大の周波数を必要な最大のレベルに割り当てます。 これは、頻度を並べ替えて、最大の要件から最大の容量まで貪欲に一致させることを示唆しています。 

残りの問題は、最適なものをどのように決定するかです。$k$。 レベルが追加されるたびに要件が 2 倍になるため、必要な合計は指数関数的に増加します。$k$せいぜい周りにいる$\log n$。 これにより、すべてを試すことが可能になります$k$価値観を持ち、貪欲に評価します。

 ## アルゴリズムのチュートリアル

 1. 各トピックの頻度を数えます。 

各トピックは、そこから割り当てることができる問題の数を表す単一の数字になります。 
2. 周波数を降順に並べ替えます。 

大きなトピックは柔軟性が高いため、可能な限り大きな要件にも対応できるようにしたいと考えています。 
3. 頻度のプレフィックス合計を構築して、選択した上位トピックのサブセットに対して利用可能な問題の数を迅速に計算します。 
4. 可能な限りすべてのコンテストを試してください$k$。 

要件は成長するにつれて増加するため、$1, 2, 4, \dots$、必要な合計が利用可能な問題を超えると停止します。 
5.固定の場合$k$、必要なサイズを計算します。$1, 2, 4, \dots, 2^{k-1}$。 
6. 最大の要件から最小の要件まで実行可能性を貪欲にチェックします。頻度の最も高いトピックを最初に最大の要件に割り当てます。 

これが機能するのは、要件が大きくなるほど満たすことが難しくなるため、最も柔軟なリソースを消費する必要があるためです。 
7. 可能であれば、割り当てられたすべてのコンテスト サイズの合計として合計貢献度を計算し、回答を更新します。 

### なぜ効果があるのか

 重要な不変条件は、コンテストの数が固定されている場合、より大きな周波数が利用可能な場合に、より小さな周波数に大きな要件を与えることによって最適な割り当てが得られることは決してないということです。 より大きな周波数をより大きな要件に移動するスワップは、制約が単調であるため、実現可能性を維持または向上させることしかできません。 これにより、問題はソートされた需要とソートされたキャパシティの一致に軽減され、割り当ての組み合わせの急増が排除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    freq = {}
    for x in a:
        freq[x] = freq.get(x, 0) + 1
    
    vals = sorted(freq.values(), reverse=True)
    
    best = 0
    
    # try number of contests k
    for k in range(1, len(vals) + 1):
        need = []
        x = 1
        total_need = 0
        
        for i in range(k):
            need.append(x)
            total_need += x
            x *= 2
        
        # prune if even total requirement exceeds sum of all problems
        if total_need > n:
            break
        
        # check feasibility: assign largest needs to largest frequencies
        ok = True
        for i in range(k):
            if vals[i] < need[k - 1 - i]:
                ok = False
                break
        
        if ok:
            best = max(best, total_need)
    
    print(best)

if __name__ == "__main__":
    solve()
```コードはまず入力をトピックの頻度に圧縮します。 次に、これらの頻度を並べ替えて、常に最も強力なトピックを最初に割り当てることを推論できるようにします。 考えられるコンテストの数ごとに、必要な幾何学的シーケンスを構築し、最大の周波数が最大の要件を満たすことができるかどうかをチェックします。 逆比較により、最も有利な方法で制約が一致することが保証されます。 

必要な合計を使用したプルーニング ステップにより、要件が利用可能な問題を超えた場合の不必要なチェックが防止されます。

 ## 特殊なケース

 重要なエッジケースは、1 つのトピックが頻度分布を支配する場合です。 例えば：```
8
1 1 1 1 1 1 1 1
```ここではコンテストを 1 つだけ形成できますが、2 番目のトピックが存在しないため、アルゴリズムは正しく 1 を出力します。 

もう 1 つのケースは、多くの小さな同等のトピックです。```
6
1 2 3 4 5 6
```各トピックの頻度は 1 です。$k = 1$動作します、以来$k = 2$すでに 2 番目のトピックが必要です。 ソートされた周波数が要件チェックに失敗するため、アルゴリズムは過剰拡張を正しく防止します。 

最後のケースは、大きなトピックは存在するが、深いチェーンをサポートできない場合です。 このアルゴリズムにより、たとえ合計が大きくても、指数関数的な要件により早期停止が強制され、無効な長いシーケンスが防止されます。
