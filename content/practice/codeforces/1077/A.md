 ## 解決策
 ## 問題の理解

 カエルは位置 0 から始まる数直線に沿って移動します。 その動きは厳密に交互です。最初に一定距離だけ右にジャンプします。`a`、次に左に`b`、そしてまたすぐに`a`、 等々。 各クエリはそのようなカエル 1 つを独立して記述し、正確に実行した後にどこに到達するかを尋ねます。`k`ジャンプします。 

入力は複数の独立したシナリオで構成されます。 各シナリオでは、2 つのステップ サイズとジャンプの数が提供されます。 各シナリオの出力は、この交互の動きをシミュレートした後の最終座標です。 

制約に関する重要な観察事項は次のとおりです。`k`は 10^9 まで大きくなるため、各ジャンプを直接シミュレートすることは不可能です。 単純なシミュレーションではクエリごとに O(k) 時間がかかり、最悪の場合、クエリごとに 10^9 の操作が必要になり、すぐに時間制限を超えます。 最大 1000 個のクエリでは、これは完全に不可能です。 ソリューションでは、クエリごとに一定時間で最終位置を計算する必要があります。 

次の場合、微妙なエッジケースが発生します。`k = 1`。 右ジャンプは 1 回だけなので、答えは正確に次のようになります。`a`。 もう 1 つの重要なケースは次のような場合です。`k`は均等であり、`a`等しい`b`なぜなら、すべての動きがキャンセルされ、カエルはゼロに戻るからです。 パリティが正しく処理されない場合、これらのキャンセルにより段階的な実装が誤解される可能性があります。 

## アプローチ

 直接的なアプローチは、各ジャンプを順番にシミュレートすることです。 ゼロから始めて交互に加算していきます`a`そして引き算`b`。 これは定義に正確に従っているため、正しいです。 ただし、大型の場合は、`k`、これには、同じ 2 つの操作をクエリごとに最大 10^9 回繰り返す必要があります。 たとえ効率的な演算を行ったとしても、このアプローチは遅すぎます。 

楽章の構造は第 2 期で周期的です。 すべてのジャンプのペアは、次の正味の動きで構成されます。`a - b`。 この観察により、シーケンス全体を 2 つのジャンプのブロックに折りたたむことができます。 ジャンプをペアにグループ化したら、追加の最後のジャンプがあるかどうかを処理するだけで済みます。`k`奇数です。 

もし`k`は偶数です、正確にあります`k/2`それぞれが貢献する完全なペア`a - b`、結果は次のようになります`(k/2) * (a - b)`。 もし`k`奇妙です、あります`(k//2)`完全なペアと追加の 1 つの右方向ジャンプ`a`。 

これにより、問題は線形シミュレーションからクエリごとの定数時間演算に軽減されます。

 | ペア圧縮 | クエリごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各クエリを個別に処理します。 

1.読む`a`、`b`、 そして`k`。 これらは、交互のステップ サイズと適用する移動の数を定義します。 
2. どれだけ満たされているかを計算します`(right, left)`整数除算を使用してペアが存在します`k // 2`。 このような各ペアは、正味変位に寄与します。`a - b`カエルが最初にすぐ近くを移動するからです`a`そして去った`b`。 
3. 完全なペアの数に次の値を掛けます。`(a - b)`すべての完全なサイクルの寄与を蓄積します。 これにより、おそらく最後のジャンプを除くすべてのジャンプがキャプチャされます。`k`奇数です。 
4. もし`k`奇数です。サイズの右方向へのジャンプを 1 つ追加します。`a`というのは、シーケンスは常に右ジャンプで始まり、奇数長のシーケンスは右移動で終わるからです。 
5. 計算された位置を出力します。 

### なぜ効果があるのか

 一連の動きは、独立した 2 つのステップのブロックに分解されます。 各ブロックは常に同じ構造状態から始まり、右ジャンプの後に左ジャンプが続きます。 ライン上の加算は結合的であるため、最終的な位置は、これらのブロックの合計と、次の場合に残った 1 つの最初のステップ ジャンプの存在にのみ依存します。`k`奇数です。 中間位置は将来のステップ サイズや方向に影響を与えないため、ペアに折りたたむと合計変位が正確に保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, k = map(int, input().split())

    pairs = k // 2
    res = pairs * (a - b)

    if k % 2 == 1:
        res += a

    print(res)
```この実装は、アルゴリズムで導出された分解を直接反映しています。 整数除算は完全な 2 ステップ サイクルを分離し、パリティ チェックは最後の一致しない右ジャンプを処理します。 算術演算では Python 整数が使用されるため、値が 10^18 スケールに達してもオーバーフローは問題になりません。 

## 実用的な例

 2 つのクエリをトレースして、分解がどのように動作するかを確認します。

 | 1 | 開始 | 2 | 2 × (1 - 10) = -18 | |
 | 2 | 奇数 k | 2 | -18 | +1 |

 最終結果は-17。 

これにより、ペアからのマイナスの純移動が最後の右ジャンプによって修正されることが確認されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        a, b, k = map(int, input().split())
        pairs = k // 2
        res = pairs * (a - b)
        if k % 2 == 1:
            res += a
        out.append(str(res))
    return "\n".join(out)

# provided samples
assert run("6\n5 2 3\n100 1 4\n1 10 5\n1000000000 1 6\n1 1 1000000000\n1 1 999999999\n") == "8\n198\n-17\n2999999997\n0\n1"

# custom cases
assert run("1\n1 1 1\n") == "1"
assert run("1\n10 10 2\n") == "0"
assert run("1\n3 5 1\n") == "3"
assert run("1\n3 5 2\n") == "-2"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`1 1 1`| 1 | シングル右ジャンプ |
 |`10 10 2`| 0 | ペアで完璧なキャンセル |

 ## 特殊なケース

 いつ`k = 1`、アルゴリズムは正しく計算します`k//2 = 0`したがって、ペアの寄与は追加されず、最後の奇数ステップで追加されます。`a`。 右ジャンプが 1 回だけ発生するため、これは定義と一致します。 

いつ`k = 2`、アルゴリズムは正確に生成します`a - b`、完全なペアが 1 つあり、ジャンプの残りがないためです。 これは動きに直接一致します`0 → a → a - b`。 

いつ`a = b`、すべてのペアはゼロに寄与するため、奇数の残りのジャンプのみがゼロ以外の結果を生成できます。 偶数の場合`k`、結果は常にゼロになり、奇数の場合は`k`、まさにその通りです`a`。
