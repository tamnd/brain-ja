 ## 問題の理解

 整数の複数セットが与えられており、固定長のパターン配列を構築したいと考えています。$k$。 このパターンを選択すると、元のマルチセットからそのパターンを繰り返し「抽出」しようとします。抽出ごとに、パターン内のすべての値が 1 回出現し、完全に抽出されるたびに、消費された要素がプールから永久に消えます。 

目標は、完全な抽出の数ができるだけ多くなるようにパターンを選択することです。 パターンを並べ替えたり、パターン内の値を繰り返したりすることは自由ですが、すべてのコピーは元の配列で使用可能な周波数によって完全にサポートされている必要があります。 

重要な観点は、順番は実現可能性とは無関係であるため、答えは最終パターンに各値が何回出現するかによってのみ決まるということです。 値が表示された場合$x$パターン内で 回抽出すると、完全な抽出ごとに消費されます。$x$配列からのその値のコピー。 

制約により、最大で$2 \cdot 10^5$そのため、すべての候補パターンを試したり、多くの選択肢の抽出をシミュレートしたりするソリューションは遅すぎます。 二次関数の何か$n$または、値のすべてのサブセットの列挙に依存するものは直ちに除外されます。 

周波数が極端に偏っている場合、微妙なエッジケースが発生します。 1 つの数値が非常に頻繁に出現し、他の数値がまれな場合、単純に貪欲な選択を行うと、パターン内で頻繁に出現する数値が過剰に使用され、パターン全体のバランスをとる可能性がブロックされる可能性があります。$k$ポジション。 Another tricky case is when$k$は個別の要素の数に比べて大きいため、直感ではなく頻度の制約によって慎重に制御する必要がある繰り返しを強いられます。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのサイズのマルチセットを構築しようとします。$k$の個別の値から$s$, 次に何回抽出できるかをシミュレーションします。 存在する値だけに限定したとしても、$s$、可能なパターンの数は指数関数的に増加します。$k$そして、候補ごとに限界周波数比を計算する必要があります。これにはコストがかかります。$O(n)$。 これはすぐに実行不可能になります。 

中心的な観察は、候補パターンを修正した場合、それを抽出できる回数は純粋に頻度によって決まるということです。$v$表示されます$c_v$パターン内で何度も出現し、$f_v$配列内に 回含まれる場合、最大でパターンを抽出できます$\min_v \lfloor f_v / c_v \rfloor$回。 

これは、逆の視点を示唆しています。パターンを選択してそのスコアを計算する代わりに、抽出されたすべてのコピーにわたって各値が占める合計「スロット」の数を決定します。 私たちが目指すなら$x$コピーの場合、値ごとの合計需要が利用可能な周波数を超えないパターンが必要になります。 つまり、すべてのコピーにわたる各値の合計使用量は、最大でも$f_v$、したがって、各コピーは最大でも使用できます$\lfloor f_v / x \rfloor$値の出現$v$。 

これにより、固定数のコピーに対してキー変換が行われます。$x$までを考慮して、可能な限り最良のパターンを貪欲に構築できます。$\lfloor f_v / x \rfloor$各値の出現数 (合計サイズまで)$k$。 サイズに到達できれば$k$、 それから$x$コピーは可能です。 

ここで問題は最大値を見つけることになります$x$。 実現可能性は単調なので、$x$(抽出できれば$x$コピー数が少ない場合、抽出できる数は少なくなります)、二分探索が可能です$x$。 候補者ごとに$x$、実現可能性をテストし、貪欲にパターンを構築します。 

最後に、最大値になったら、$x$がわかっている場合、その制約の下で構築された有効なパターンを出力します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 二分探索 + 貪欲な構築 |$O(n \log n)$| O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列内の各値の頻度を数えます。 これにより、考えられるすべてのパターン要素に対して最大供給制約が与えられます。 
2. 少なくともサポートするパターンを構築できるかどうかをチェックする関数を定義します。$x$完全な抽出。 それぞれの値について$v$、単一のコピーで何回出現できるかを計算します。$\lfloor f_v / x \rfloor$。 これは、値を使い果たさないコピーごとの最大許容量です。$x$繰り返し。 
3. これらの値ごとの容量をすべて合計します。 合計が以下の場合$k$そうすると、最も寛大なパターンでも長さに達することができなくなります。$k$、 それで$x$コピーは不可能です。 
4. 可能であれば、値を反復処理し、各値を合計してパターンを構築します。$\lfloor f_v / x \rfloor$パターンの長さに達するまでの回数$k$。 
5. 二分探索を使用します。$x$1との間$n$、実現可能性のテストと限界の調整を繰り返します。 
6. 実現可能な最大値を見つけた後$x$、同じ貪欲な構造を使用して最終パターンを再構築します。 

これが機能する理由は、コピー数が固定されているためです。$x$、各値をコピーごとの制限まで完全に飽和させることで、可能な限り最良のパターンが常に得られます。 偏差があると、全体のサイズが小さくなるか、利用可能な周波数容量が無駄になります。 二分探索により、最大のものを確実に見つけることができます。$x$これでも、同じサイズの全長パターンを構築できます。$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(x, freq, k):
    total = 0
    for v in freq:
        total += freq[v] // x
        if total >= k:
            return True
    return total >= k

def build(x, freq, k):
    res = []
    for v in freq:
        cnt = freq[v] // x
        take = min(cnt, k - len(res))
        res.extend([v] * take)
        if len(res) == k:
            break
    return res

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))

    freq = {}
    for v in arr:
        freq[v] = freq.get(v, 0) + 1

    lo, hi = 1, n
    best = 1

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, freq, k):
            best = mid
            lo = mid + 1
        else:
            hi = mid - 1

    ans = build(best, freq, k)
    print(*ans)

if __name__ == "__main__":
    solve()
```実装では、実現可能性のチェックと再構築が分離されます。 の`can`関数は、実際のパターンを構築せずに、指定されたコピー数が達成可能かどうかを計算します。これにより、二分探索の効率が維持されます。 の`build`次に、関数は同じロジックを使用してパターンを貪欲に再構築し、実現可能性テストとの一貫性を確保します。 

微妙な点は、再構築では、`can`。 2 つの間に不一致があると、実現可能性テストが正しくても、不正確なパターンが生成されます。 

## 実用的な例

 次の入力を考えてみましょう。```
7 3
1 2 3 2 4 3 1
```まず周波数を計算します。 

| 値 | 周波数 |
 | --- | --- |
 | 1 | 2 |
 | 2 | 2 |
 | 3 | 2 |
 | 4 | 1 |

 実現可能性をテストします。 のために$x = 2$、それぞれの値が寄与します$\lfloor f_v / 2 \rfloor$:

 | 値 | 貢献 |
 | --- | --- |
 | 1 | 1 |
 | 2 | 1 |
 | 3 | 1 |
 | 4 | 0 |

 合計は 3 で十分です$k = 3$, なので2枚コピーが可能です。 のために$x = 3$, 貢献度は3要素到達不可能以外は全てゼロになるので失敗します。 したがって、最高の$x = 2$。 

再構築は 1、2、3 からそれぞれ 1 つを選択し、`[1, 2, 3]`。 

ここで、歪んだケースを考えてみましょう。```
6 4
1 1 1 1 2 2
```周波数:

 | 値 | 周波数 |
 | --- | --- |
 | 1 | 4 |
 | 2 | 2 |

 試す$x = 2$: 貢献度は値 1 に 2、値 2 に 1、合計 3 です。$k = 4$。 だからそれだけ$x = 1$動作します。 最大 4 つの 1 と 2 つの 2 を使用できますが、必要な要素は 4 つだけなので、有効なパターンは次のとおりです。`[1, 1, 1, 2]`または同様のもの。 

このトレースは、アルゴリズムが順序付けについて明示的に推論することなく、頻繁に使用される要素とまれな要素のバランスを自然にとっていることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 複雑さは制限内に問題なく収まります。$n \le 2 \cdot 10^5$、約 18 ～ 20 の実現可能性チェックが実行されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    arr = list(map(int, input().split()))

    freq = {}
    for v in arr:
        freq[v] = freq.get(v, 0) + 1

    def can(x):
        total = 0
        for v in freq:
            total += freq[v] // x
        return total >= k

    lo, hi = 1, n
    best = 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid):
            best = mid
            lo = mid + 1
        else:
            hi = mid - 1

    res = []
    for v in freq:
        cnt = freq[v] // best
        res.extend([v] * min(cnt, k - len(res)))
        if len(res) == k:
            break

    return " ".join(map(str, res))

# provided sample
assert run("7 3\n1 2 3 2 4 3 1\n") in {"1 2 3", "1 3 2", "2 1 3"}

# all equal
assert len(run("5 2\n1 1 1 1 1\n").split()) == 2

# k = n
assert len(run("4 4\n1 2 3 4\n").split()) == 4

# skewed frequencies
assert len(run("6 3\n1 1 1 2 2 3\n").split()) == 3

# minimum case
assert run("1 1\n7\n") == "7"

 | k = n | 完全再構築 | 境界彩度 |

 ## 特殊なケース

 すべての要素が同一である入力の場合、次のようになります。`5 3`と`[7 7 7 7 7]`、アルゴリズムは各コピーに 1 つの値のみを含めることができると計算し、二分探索では最大でも 1 つの値しか含めることができません。$\lfloor 5/3 \rfloor = 1$完全抽出が可能です。 再構築では、実行可能性の制約に一致する任意の 3 つの 7 が出力されるだけです。 

場合については、$k = n$、アルゴリズムは事実上、繰り返し制約なしで完全なマルチセットを選択することになりますが、バイナリ検索は依然として有効な最大コピー数 (多くの場合 1) を返します。再構築により、配列全体が次の値まで埋められます。$n$、これは正しさを自明に満たします。 

次のような非常に不均衡な入力の場合`[1,1,1,1,2]`大きい$k$、実現可能性チェックにより、レア要素が過剰に割り当てられないことが保証され、抽出中に失敗する可能性のある過度に楽観的なパターンが防止されます。
