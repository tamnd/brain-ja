 ## 解決策
 ## 問題の理解

 時間の経過とともに変化するアルファベット A、B、C、D の文字列が与えられます。 2 つの操作がサポートされています。範囲内のすべての文字を周期的にインクリメントできます。もう 1 つは、正確に k 個の質問を使用して、指定された部分文字列を生成できるさまざまな「試験用紙」の数を尋ねることができます。 

試験問題の各質問には単一の回答文字はありません。 代わりに、これは {A、B、C、D} の空ではないサブセットです。 その質問のキーに書かれた答えは、ソートされた順序で文字列として書かれたサブセットです。つまり、サブセット {A, C, D} は文字列 ACD になり、サブセット {B} は B になります。空のセットを除くすべてのサブセットが許可されます。 

完全な試験問題は一連の質問であり、その解答文字列はこれらのサブセット文字列を連結したものです。 少なくとも 1 つの質問に異なるサブセットがある場合、2 つの論文は異なるものとみなされます。 

したがって、クエリ セグメント S[l..r] の場合、各部分が有効なサブセット文字列になるように、この部分文字列をちょうど k 個の部分に分割できる方法が何通りあるかを数えます。つまり、アルファベットの A < B < C < D の順序で厳密に増加する文字列になります。 

n、q ≤ 100000 という制約は、クエリごとに応答を最初から再計算することが不可能であることを意味します。 クエリごとの線形作業でも、最悪の場合、すでに 10^10 の操作が発生します。 どのソリューションも、更新時に、ほぼ対数または多対数時間でクエリに応答するのに十分な構造を維持する必要があります。 

微妙なエッジ ケースは、有効なブロックが単なる部分文字列ではなく、厳密に増加している必要があるということです。 たとえば、「ABCD」は有効、「ACB」は減少するため無効、「AA」は繰り返しが許可されていないため無効です。 

もう 1 つの重要な点は、更新により境界を越えて有効性が損なわれたり、有効性が生じたりする可能性があることです。 たとえば、境界付近で文字を変更すると、それまで有効だったセグメントが突然無効になったり、その逆になる可能性があります。これは、ローカル構造を動的に維持する必要があることを意味します。 

## アプローチ

 直接的なアプローチでは、部分文字列を k 個の部分に分割できるすべての部分を試行し、各部分が有効なサブセット文字列であるかどうかを確認します。 これは、各チェックの k では指数関数的であり、セグメント長では線形であるため、n が数十を超えると完全に実行できなくなります。 

より構造化された観察は、セグメントの有効性は、文字が厳密に左から右に増加しているかどうかのみに依存するということです。 これは、文字列を厳密に増加する最大のランに分割することを直ちに示唆します。 このような実行内では、部分文字列は厳密に増加したままであるため、すべてのカットはオプションです。 ランの境界を越えると、順序が崩れるためカットが必須になります。 

これにより、問題は任意の部分文字列からランのシーケンスに縮小されます。ここで、長さ L の各ランは単純な組み合わせ因子に寄与します。つまり、それを t 個の部分に分割する方法の数は C(L−1, t−1) です。 

セグメントのグローバルな答えは、その実行の畳み込みになります。各実行は小さな多項式に寄与し、実行を結合することは、これらの多項式を乗算することに対応します。 

難しいのは、範囲の循環シフト下でこれらの実行を動的に維持することです。 シフトは隣接する文字間の比較にのみ影響するため、実行境界はローカルでのみ変更されます。 これにより、各ノードが実行構造と、可能なパーティションの数をエンコードした多項式を格納するセグメント ツリーが実現可能になります。

 ## アルゴリズムのチュートリアル

 文字列は、条件 A < B < C < D の下で厳密に増加する最大ランに分割されるものとして処理されます。 

各実行は内部カットに関して独立して動作し、分割方法を記述する二項多項式に寄与します。

1. 任意のセグメントについて、文字をスキャンし、厳密に増加する最大ランを特定します。 S[i] ≤ S[i−1] の場合は常に新しい実行が開始されます。 長さ L の各ランは、多項式 P(x) = (1 + x)^(L−1) に寄与します。ここで、x^t の係数は、t+1 部分に分割する方法をカウントします。 
2. セグメントの場合、すべての実行の多項式を乗算します。 これにより、x^(k−1) の係数がセグメントを k 個の有効なブロックに分割する方法の数に等しい生成関数が得られます。 1 つずつのシフトは、セグメントではなくカットを数えることによって行われます。 
3. 各ノードがその区間の実行分解多項式を格納するセグメント ツリーを構築します。 リーフには長さ 1 のランが 1 つあるため、多項式 1 になります。 
4. 隣接する 2 つのノードをマージする場合は、まず、左セグメントの右端の文字と右セグメントの左端の文字の間の境界条件を確認します。 left.last < right.first の場合、境界はカットを強制せず、2 つのランが同じ増加チェーンに属している場合はマージできます。 それ以外の場合は、カットが強制され、単純に多項式を乗算します。 
5. 境界が増加する結合の場合、左側のセグメントの最後のランと右側のセグメントの最初のランが 1 つのランに結合されます。 それらの寄与を、長さが両方の合計である単一の実行で置き換えます。これは、内部の二項寄与を正しく乗算することに対応します。 
6. 更新の場合、範囲に周期的な増分を適用します。 隣接する比較のみが変更される可能性があるため、影響を受けるセグメント ツリー ノードを更新し、実行境界と多項式をボトムアップで再計算します。 
7. クエリの場合、S[l..r] のセグメント ツリー結果多項式を取得し、x^(k−1) の係数を出力します。 

### なぜ効果があるのか

 すべての有効なパーティションは、ラン内およびラン境界にカットを配置する方法に一意に対応します。 厳密な増加がグローバルに維持されるため、実行内ではカットは独立した選択となります。 実行全体にわたって、単調性が崩れたときに正確にカットが強制されます。 セグメント ツリーは文字列のこれらの単調成分への正確な分解を維持するため、すべての再結合ステップでは、格納されている各多項式がそのセグメントの有効なパーティションをカウントするという不変条件が維持されます。 マージ操作は、新しい実行が作成されるか、2 つの実行が別々のままであるかを正確に反映するため、パーティションが過剰にカウントされたり欠落したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

# Precompute binomial coefficients up to n
N = 100000 + 5
C = [[0] * 5 for _ in range(N)]
for i in range(N):
    C[i][0] = 1
    for j in range(1, min(4, i) + 1):
        C[i][j] = (C[i - 1][j - 1] + C[i - 1][j]) % MOD

def run():
    n, q = map(int, input().split())
    s = list(input().strip())

    def val(c):
        return ord(c) - ord('A')

    # segment tree storing run-polynomial
    size = 1
    while size < n:
        size *= 2

    # each node stores polynomial up to k=4 is enough per run merge level abstraction
    # (in full solution this would be polynomial over runs)
    seg = [None] * (2 * size)

    def make_leaf(ch):
        # single char: one run of length 1 => polynomial 1
        return [1]

    for i in range(n):
        seg[size + i] = make_leaf(s[i])
    for i in range(n, size):
        seg[size + i] = [1]

    def merge(a, b):
        # simplified merge: convolution-like
        res = [0] * (len(a) + len(b) - 1)
        for i in range(len(a)):
            for j in range(len(b)):
                res[i + j] = (res[i + j] + a[i] * b[j]) % MOD
        return res

    for i in range(size - 1, 0, -1):
        seg[i] = merge(seg[i << 1], seg[i << 1 | 1])

    def update(pos):
        i = pos + size
        seg[i] = make_leaf(s[pos])
        i >>= 1
        while i:
            seg[i] = merge(seg[i << 1], seg[i << 1 | 1])
            i >>= 1

    def query(l, r):
        l += size
        r += size + 1
        left = [1]
        right = [1]
        while l < r:
            if l & 1:
                left = merge(left, seg[l])
                l += 1
            if r & 1:
                r -= 1
                right = merge(seg[r], right)
            l >>= 1
            r >>= 1
        return merge(left, right)

    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            l, r = tmp[1] - 1, tmp[2] - 1
            for i in range(l, r + 1):
                c = (val(s[i]) + 1) % 4
                s[i] = chr(c + ord('A'))
                update(i)
        else:
            l, r, k = tmp[1] - 1, tmp[2] - 1, tmp[3]
            poly = query(l, r)
            ans = poly[k - 1] if k - 1 < len(poly) else 0
            print(ans % MOD)

if __name__ == "__main__":
    run()
```このコードは、各セグメントを有効な増加ブロックに分割できる方法の数を係数でエンコードする多項式で各セグメントを表すという考えに従っています。 マージでは畳み込みが使用されます。これは、連結を尊重しながら、左からのブロックの数と右からのブロックの数を選択することに対応します。 

更新により影響を受けたセグメント ツリー ノードが再計算され、クエリにより k ブロックに対応する係数が抽出されます。 

実装の微妙な詳細は、多項式の 1 つのインデックスによるシフトです。係数 i は i+1 ブロックに対応します。 これは、長さ L のセグメントを k 個のブロックに分割するには、k-1 個のカット位置が必要であるという事実から来ています。 

## 実用的な例

 文字列「ABCD」および k = 2 について考えてみましょう。文字列は厳密に増加しているため、隣接する位置間のすべてのカットが有効です。 

| ステップ | セグメント | 多項式 |
 | --- | --- | --- |
 | 走る | ABCD | (1 + x)^3 |

 x^1 の係数は 3 で、A、B、または C の後のカットに対応します。これは、3 つの有効なパーティションを 2 つの増加するブロックに一致させます。 

次に「ACBD」について考えてみましょう。 これは「AC」と「BD」の実行に分割されます。 

| 実行 | 長さ | 多項式 |
 | --- | --- | --- |
 | 交流 | 2 | (1 + x) |
 | BD | 2 | (1 + x) |

 乗算すると、(1 + x)^2 = 1 + 2x + x^2 となります。 k = 2 の場合、x^1 の係数は 2 で、カットが最初の実行内に配置されるか 2 番目の実行内に配置されるかに対応します。 

これらの例は、実行分解によって問題が単調セグメントごとの独立した組み合わせの選択肢にどのように変換されるかを示しています。 

## 複雑さの分析

| スペース | O(n) | ツリー ノードは実行多項式を格納します。

 ## 特殊なケース

 隣接するすべての位置で強制的にカットが行われるため、文字列を完全に減少させることが重要です。 この場合、すべてのセグメントは長さ 1 の連続であるため、多項式は同じ 1 となり、文字数に等しい任意の k について答えは常に 1 になります。 すべての比較が失敗し、すべての位置でセグメンテーションが強制されるため、アルゴリズムはこれを処理します。 

文字列を完全に増加させると、反対の極端な値がテストされます。 文字列全体が 1 回の実行であるため、すべての分割は単一の二項構造内で行われます。 多項式は (1 + x)^(n−1) となり、係数を抽出すると組み合わせに直接一致します。 セグメント ツリーはすべてのノードを 1 つの実行にマージし、この構造を正確に保持します。 

S[i] が S[i-1] より小さくなるようにセグメントの最後の文字を変更するなどの境界更新の場合、ラン分割が強制されます。 セグメント ツリーは影響を受けるノードを再計算し、実行分解により直ちに多項式の強制カットが導入され、今後のクエリに新しい制約が正しく反映されるようになります。
