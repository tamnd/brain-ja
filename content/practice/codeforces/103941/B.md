 ## 解決策
 ## 問題の理解

 それぞれが小さな整数の重みにマップされた 4 文字のみで構成される循環文字列が与えられます。 文字列はリング状に配置されているため、最後の文字の後で最初の文字に戻ります。 この円上でいくつかのカット位置を選択することができ、それによって円がいくつかの連続する円セグメントに分割されます。 

各セグメントは通常の文字列 (もはや循環ではありません) として扱われ、多項式ハッシュが割り当てられます。この場合、前の文字は 31 の小さい累乗に寄与し、後の文字はより大きな累乗に寄与します。 パーティションの合計スコアは、すべてのセグメントのハッシュの合計です。 目標は、この合計スコアが最大になるようにカットを選択することです。 

文字列が循環的であるという制約が重要な問題です。 セグメントは端の周りを囲む場合があり、パーティションは本質的に、円を正確に 1 回覆う、切り離された円弧の選択です。 

n が最大 200,000 である場合、カットを選択する方法の数は指数関数的に増加するため、すべてのカットの組み合わせを試すソリューションは不可能です。 区間全体の二次 DP でも遅すぎます。 文字列上で少数の定数のパスしか許容できないため、O(n) または O(n log n) の解が期待されます。 

微妙な問題は、循環構造とハッシュ内の指数関数的な重みの間の相互作用から発生します。 単純な間違いは、文字列を線形として扱い、ラップアラウンド相互作用を無視してローカルで貪欲に切り取ることです。 もう 1 つのよくある失敗は、セグメントごとのハッシュを正しく計算するものの、1 つのカットを変更すると境界だけでなくセグメント全体の指数構造に影響を与えることを見逃すことです。 

具体的な失敗例は、丸の上に「へはん」のような文字列が表示されます。 ローテーションを考慮せずに値の低下が見られるたびに貪欲にカットすると、高価値のキャラクターがパワーウェイトの低いセグメントに早い段階で着地するような不適切な開始点を選択し、合計スコアが大幅に低下する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、円内の連続する文字間のエッジのすべてのサブセットを潜在的なカットポイントとして列挙することです。 選択ごとに、すべてのセグメント ハッシュを個別に計算し、それらを合計します。 これは問題の定義に直接従うため、正しいです。カットが修正されると、セグメント ハッシュは決定的になります。 ただし、n 個のエッジがあるため、2^n 通りの分割が可能となり、O(n) で各分割を計算しても、実行不可能な O(n・2^n) の複雑さになります。 

改善するには、カットがハッシュ構造にどのような影響を与えるかを理解する必要があります。 セグメント内では、右に近い文字ほど 31 の累乗が大きくなります。これは、同じセグメント内で後の位置が前の位置を支配することを意味します。 したがって、どのセグメント内でも、値の大きい文字を右端に配置することが有益です。 

この観察は、パーティションの品質が、シーケンスの値が「低下」する位置でカットするかどうかに大きく依存することを示唆しています。 このようなドロップでのカットを回避すると、セグメント内の低重みの位置に大きな値が強制的に配置される可能性があり、これは最適ではありません。 逆に、下降ごとにカットすると、各セグメントが局所的に減少しないことが保証され、そのセグメント内で小さな値が小さなべき乗に、大きな値が大きなべき乗に揃えられます。 

重要な考え方は、次の文字が現在の文字より厳密に小さい位置で正確にカットすることによって最適なパーティションが得られるということです (循環隣接性を考慮して)。 これにより、円が最大の非減少セグメントに分割され、この構造は各セグメント内の 31 乗の単調増加と完全に一致します。

 | --- | --- | --- | --- |
 | すべてのカットを列挙する | O(2^n · n) | O(n) | 遅すぎる |
 | 下り坂での貪欲なカット | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

各文字を指定された数値にマッピングします (a は 1、e は 2、h は 3、n は 4)。 

次に円形の紐を一度加工し、カットを入れる位置を決めます。 

1. 文字列を循環順序でたどり、各文字を次の文字と比較します。 

現在の値が次の値より大きい場合、それらの間のカットをマークします。 

これにより、すべての減少する遷移を確実に破ることができます。 
2. これらのカットポイントを使用して、円をセグメントに分割します。 各セグメントは、マップされた値に関して最大​​の非減少シーケンスになります。 

この構造により、セグメント内では、先に進むにつれて値が下がらないことが保証されます。 
3. 各セグメントについて、定義を使用してそのハッシュを直接計算します。 

セグメントは互いに素であり、円を 1 回だけカバーするため、それらのハッシュを安全に蓄積できます。 
4. すべてのセグメントのハッシュを合計して、最終的な答えを取得します。 

### なぜ効果があるのか

 セグメント内では、右に行くにつれて 31 の指数が増加するため、各位置は前の位置よりも指数関数的に重要になります。 大きい値が先に現れ、小さい値が後に現れる場合、大きい値には 31 の小さいべき乗が乗算されるため、寄与は最適ではありません。下降時に正確にカットすると、セグメントに沿って値が減少しないことが保証されるため、この不整合が防止されます。そのため、大きい値は自然に重みの高い位置に向かって移動します。 2 つの隣接する非減少セグメントをマージすると、境界で降下が生じ、少なくとも 1 組の要素の加重合計の寄与が厳密に減少するため、そのようなマージでは答えを改善できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
BASE = 31

val = {'a': 1, 'e': 2, 'h': 3, 'n': 4}

def solve():
    s = input().strip()
    n = len(s)
    a = [val[ch] for ch in s]

    # find cut positions on circular boundary
    cuts = [False] * n
    for i in range(n):
        if a[i] > a[(i + 1) % n]:
            cuts[i] = True

    # build segments
    ans = 0
    i = 0
    while i < n:
        j = i
        seg = []
        while True:
            seg.append(a[j])
            if cuts[j]:
                break
            j = (j + 1) % n
        i = (j + 1) % n

        # compute hash of segment
        h = 0
        for x in seg:
            h = (h * BASE + x) % MOD
        ans = (ans + h) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まず文字が数値の重みに変換され、次に循環順序で厳密な降下が発生するすべての位置が特定されます。 これらの位置はセグメントの境界を定義します。 

その後、円を 1 回歩き、カットに到達するまでエッジをたどって各セグメントを構築します。 各セグメントは独立して処理され、そのハッシュは標準の多項式形式で計算されます。 

微妙な点は、文字列を明示的に回転する必要がないことです。 カット セットによってサイクル上のパーティションが完全に決定されるため、インデックス 0 から開始してその後のカットで十分です。 

## 実用的な例

 サンプル文字列を考えてみましょう`henan`、次のようにマッピングされます`h=3, e=2, n=4, a=1, n=4`。 

循環遷移を調べます。 

| 私 | a[i] | a[i+1] | カット？ |
 | --- | --- | --- | --- |
 | 0 | 3 | 2 | はい |
 | 1 | 2 | 4 | いいえ |
 | 2 | 4 | 1 | はい |
 | 3 | 1 | 4 | いいえ |
 | 4 | 4 | 3 | はい |

 したがって、カットは 0、2、4 に配置され、円をこれらの境界に沿ったセグメントに分割します。 

次に、各セグメントのハッシュを個別に計算し、それらを合計します。 

これは、線形ビューでは最適なカットが視覚的に明らかでない場合でも、円形降下によってどのようにセグメンテーションが強制されるかを示しています。 

ここで考えてみましょう`aenhan`、次のようにマッピングされます`1 2 4 3 1 3`。 唯一の下り坂は、`4->3`そして`3->1`、セグメントの正しい端で高価値の要素を分離するセグメントを生成し、ハッシュ計算においてそれらの要素がより大きな力を受け取れるようにします。

 ## 特殊なケース

 次のような単一文字列の場合`a`、円には 1 つの頂点と 1 つの自己ループ遷移があります。 このアルゴリズムでは厳密な降下は見られず、文字列全体を含む単一のセグメントが生成され、ハッシュ値 1 が正しく生成されます。 

次のような完全に減少するサイクルの場合`n h e a n`、すべてのトランジションは下降であるため、すべての文字は独自のセグメントになります。 各セグメント ハッシュは単一のマップされた値に減少し、合計は単純にすべての重みの合計になります。これは最適な構成と一致します。これは、マージでは 31 の累乗が増加して、より大きな値がより小さな値の前に配置され、より大きな値の寄与が減少するためです。 

次のような完全に増加するサイクルの場合`a e h n a`、ラップアラウンドエッジにはちょうど 1 つの下りがあり、文字列全体に等しい 1 つのセグメントが生成されます。 これにより、大きな値がその重みが最大となるセグメントの右側に残ることが保証され、これは指数関数的な重み付け構造の下で最適です。
