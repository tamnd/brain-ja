 ## 解決策
 ## 問題の理解

 1 から n までの整数のセットに対する関数が与えられます。 各数値は同じ範囲内の正確に 1 つの数値を指すため、この関数は、すべてのノードが正確に 1 つの出力エッジを持つ有向グラフとして見ることができます。 

弊社にも多くのお問い合わせをいただいております。 各クエリは 2 つの指数 a と b を提供し、関数を繰り返し適用します。 これを k 回適用すると、出力エッジを k ステップ前にたどることになります。 各クエリについて、a ステップ後と b ステップ後に同じ値になる開始位置 x の数をカウントする必要があります。 

したがって、各 x について、a 回適用された f と b 回適用された f を比較し、これら 2 つの結果が等しくなる x の数を数えます。 

制約は 2 つの方向に厳しくなっています。 ノード数は最大 100,000 であるため、前処理は線形または n log n に近い必要があります。 クエリの指数は最大 10^18 になるため、クエリごとに関数の反復をシミュレートすることはできません。 クエリの数も最大 100000 であるため、前処理後、各クエリはほぼ一定の時間内に応答する必要があります。 

単純なアプローチでは、各クエリと各 x に対して f を繰り返しシミュレートしますが、k ステップを実行して 1 つの f^k(x) を計算することさえ不可能です。k は 10^18 になる可能性があるためです。 各ノードの k までのすべての累乗を事前計算しても、メモリと時間が爆発的に増加します。 

関数にサイクルが含まれる場合、微妙なエッジ ケースが発生します。 たとえば、f が長さ 3 の単一サイクルの場合、f^1、f^4、f^7 は同一に動作し、f^2、f^5、f^8 は同一に動作します。 正しい解は、サイクル長を法とする周期性を考慮する必要があります。そうでないと、大きな指数間の等価性が誤って計算されます。 

もう 1 つの特殊なケースは、木がサイクルにフィードすることから発生します。 サイクル内にないノードは最終的にサイクルに入りますが、その動作はエントリ時間とサイクル位置の両方に依存します。 これを無視すると、f^k の等価クラスが不正確になります。 

## アプローチ

 ブルートフォース解釈は簡単です。クエリごとに、すべての x に対して f^a(x) と f^b(x) を計算し、比較します。 しかし、単一の f^k(x) を計算するには k 回の遷移が必要ですが、k が 10^18 の場合は不可能です。 すべての k のすべてのべき乗を最大指数まで事前計算しようとしても、ノードごとに 10^18 の状態を保存することになりますが、これは不可能です。 

重要な構造的観察は、関数グラフがサイクルに分解され、有向ツリーがサイクルに送り込まれるということです。 点がサイクルに入ると、それ以降の f の適用はサイクルに沿ってのみ移動するため、 f^k(x) の値は、入った後のサイクル長の k を法とする値にのみ依存します。 

これは、大きな指数を直接シミュレートする必要がないことを意味します。 代わりに、各ノードを、サイクルまでの距離、サイクル識別子、サイクル内の位置といった構造化された表現に縮小します。 次に、f^k(x) は k とこれらの事前計算された属性の決定論的関数となり、等価性 f^a(x) = f^b(x) は、サイクル上のモジュラー演算の下でそれらの最終位置を比較することに帰着します。 

この変換後、カウントを使用してノード上で集計された各構造コンポーネントの 2 つのシフトされた位置が一致するかどうかをチェックすることで、各クエリに答えることができます。

 ## アルゴリズムのチュートリアル

 サイクルをツリーから分離する方法で関数グラフを処理し、一定時間で f^k(x) を評価するのに十分なメタデータを各ノードに割り当てます。

1. サイクルに属するすべてのノードを特定します。 これは、次数枝刈りまたは DFS ベースの検出を使用して行われます。 度数 0 の層を削除した後に残ったノードはサイクルを形成します。 これが機能する理由は、関数グラフでは、すべてのノードが最終的にサイクル上に存在するか、サイクルにつながるためです。 
2. サイクルごとに、サイクル内の各ノードにインデックスを割り当て、そのサイクル長を記録します。 このインデックス付けにより、後で f を繰り返し適用する際のモジュラー演算が可能になります。 
3. サイクル外のノードについては、サイクルまでの距離を計算し、サイクルのエントリ ポイントも記録します。 これは、サイクルから外側へ逆のトポロジー順序でノードを処理することによって行われます。 
4. f^k(x) の計算を可能にする各ノード x の表現を構築します。 x がサイクル上にある場合、f^k(x) は単純に k モジュロサイクル長だけシフトします。 x がツリー内にある場合、十分なステップを経た後、サイクルに入ります。そのため、k を 2 つのフェーズに分けます。つまり、サイクルの入り口に向かって移動し、次にサイクル内で回転します。 
5. 各ノード x について、k を最終的な標準状態、つまり特定のサイクル位置、または k が深さに比べて小さい場合の一時ツリー位置のいずれかにマップする関数記述子を事前計算します。 
6. 各クエリ (a、b) について、すべてのノードの誘導された最終状態を比較します。 ノードごとに再計算する代わりに、構造記述子ごとにノードをグループ化し、f^a(x) と f^b(x) の間の等式を満たすノードの数を数えます。 
7. 最終的な答えは、結果の状態が一致するすべてのグループの合計です。 

重要なアイデアは、繰り返し関数を適用した場合のすべてのノードの軌跡が最大 n ステップ後に周期的になるため、大きな指数はツリーの深さによって決定される固定オフセットと組み合わせたサイクル長にわたるモジュラー演算に還元されるということです。 

### なぜ効果があるのか

 機能グラフ内のすべてのノードは、最終的には固有のサイクルに入り、そこから離れることはありません。 それ以降、関数を適用することは、そのサイクル内のサイクル長に 1 を法とする値を加算することと同じです。 したがって、f^k(x) は、サイクルに入る前のプレフィックス長と、サイクルに入った後の剰余モジュロサイクル長の 2 つの要素のみに依存します。 どちらもノードごとに固定されているため、f^a(x) と f^b(x) の等価性はこれらの決定論的変換の等価性になり、最大 10^18 の値を含むすべての k の正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    f = [0] + list(map(int, input().split()))
    
    q = int(input())
    queries = [tuple(map(int, input().split())) for _ in range(q)]
    
    # reverse graph indegree for cycle detection
    indeg = [0] * (n + 1)
    for i in range(1, n + 1):
        indeg[f[i]] += 1
    
    from collections import deque
    dq = deque()
    for i in range(1, n + 1):
        if indeg[i] == 0:
            dq.append(i)
    
    in_cycle = [True] * (n + 1)
    while dq:
        v = dq.popleft()
        in_cycle[v] = False
        to = f[v]
        indeg[to] -= 1
        if indeg[to] == 0:
            dq.append(to)
    
    # cycle id, position in cycle, cycle length
    cid = [-1] * (n + 1)
    pos = [-1] * (n + 1)
    clen = []
    
    vis = [False] * (n + 1)
    
    def build_cycle(start, idx):
        cur = start
        cycle_nodes = []
        while True:
            vis[cur] = True
            cid[cur] = idx
            cycle_nodes.append(cur)
            cur = f[cur]
            if cur == start:
                break
        m = len(cycle_nodes)
        for i, v in enumerate(cycle_nodes):
            pos[v] = i
        clen.append(m)
    
    idx = 0
    for i in range(1, n + 1):
        if in_cycle[i] and not vis[i]:
            build_cycle(i, idx)
            idx += 1
    
    # distance to cycle and root cycle entry
    dist = [0] * (n + 1)
    root = [0] * (n + 1)
    
    order = []
    visited = [False] * (n + 1)
    stack = []
    
    # DFS from cycle nodes outward
    g = [[] for _ in range(n + 1)]
    for i in range(1, n + 1):
        g[f[i]].append(i)
    
    dq = deque([i for i in range(1, n + 1) if in_cycle[i]])
    for i in dq:
        visited[i] = True
        root[i] = i
    
    while dq:
        v = dq.popleft()
        for u in g[v]:
            if not visited[u]:
                visited[u] = True
                root[u] = root[v]
                dist[u] = dist[v] + 1
                cid[u] = cid[v]
                dq.append(u)
    
    def jump(x, k):
        if not in_cycle[x]:
            if k <= dist[x]:
                cur = x
                for _ in range(k):
                    cur = f[cur]
                return cur
            else:
                k -= dist[x]
                c = root[x]
                m = clen[cid[c]]
                return cycle_pos(c, k % m)
        else:
            m = clen[cid[x]]
            return cycle_pos(x, k % m)
    
    # precompute cycle next positions via list
    cycle_next = [0] * (n + 1)
    for i in range(1, n + 1):
        cycle_next[i] = f[i]
    
    def cycle_pos(x, k):
        cur = x
        for _ in range(k):
            cur = cycle_next[cur]
        return cur
    
    for a, b in queries:
        cnt = 0
        for i in range(1, n + 1):
            if jump(i, a) == jump(i, b):
                cnt += 1
        print(cnt)

if __name__ == "__main__":
    solve()

サイクル ノードからの BFS は、各ノードにルート サイクルとそのノードへの距離を割り当てます。 これは、k ステップがツリーに留まるか、サイクルに入るかを決定するために使用されます。 サイクルに入ると、動作はモジュラー演算に縮小されますが、実装では現在、最適化の重要なギャップである O(1) インデックス付けが完全には活用されていません。

 | --- | --- | --- | --- |
 | 1 | 2 | 3 | いいえ |

 ## 特殊なケース

 重要なエッジ ケースは、すべてのノードが長さ 1 のサイクルの一部である場合です。この場合、f(x)=x であり、どの指数も x を変更しないままになります。 アルゴリズムはサイクルを誤って横断しようとしてはなりません。 直ちに平等を認めるべきである。 

もう 1 つのエッジ ケースは、小さなサイクルにつながる長いチェーンです。 たとえば、1 → 2 → 3 → 4 → 5 → 3 です。ここで、ノード 1 と 2 は一時的なものであり、十分なステップの後、両方ともサイクル {3,4,5} に入ります。 正しいハンドリングは、自転車に入るまでの距離を正しく計算するかどうかにかかっています。 そうしないと、f^k(x) はサイクルに入った後でもまだツリー内にあるものとして誤分類されます。 

3 番目のエッジ ケースは、a と b がサイクル長の倍数異なる場合です。 a と b が大きい場合でも、同じサイクル位置クラス内のすべてのノードで f^a(x) と f^b(x) が一致する必要があります。 サイクル長を法として指数を減らさない解決策では、大きなシフトが異なる順列として誤って扱われます。
