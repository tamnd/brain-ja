 ## 解決策
 ## 問題の理解

 英語の小文字で構成される単一の長い文字列が与えられます。 この文字列から文字を削除し、残りの文字を順番に保持してサブシーケンスを形成することができます。 

目標は、非常に厳密なパターンを形成する 17 文字を正確に選択できるかどうかを判断することです。最初の 5 文字はすべて同一で、次の 7 文字もすべて同一 (おそらく別の文字)、最後の 5 文字もすべて同一 (おそらく 3 番目の文字) です。 3 つのブロックは、各ブロックが一定であるという意味で独立していますが、異なるブロックの文字は互いに一致する場合もあれば、一致しない場合もあります。 

そのようなサブシーケンスが存在する場合は、有効なサブシーケンスを 1 つ出力する必要があります。 存在しない場合は出力します`none`。 

入力サイズは最大 100 万文字です。 これにより、すべてのサブシーケンス、さらには位置のすべての組み合わせを構築しようとするアプローチは即座に除外されます。 位置のペアにわたって大きな定数を持つ二次関数や線形に近い関数は遅すぎます。 文字列を有用な構造に圧縮するか、検索を少数の一定数の候補に減らすかのいずれかが必要です。 

微妙な問題は、3 つのセグメントが同じ文字を再利用できることです。 たとえば、次のような文字列`aaaaaaaaaaaaaaaaa`3 つのセグメントはすべて同じ文字にすることができるため、これは有効です。 セグメントが異なるはずだと仮定する不注意なアプローチは、このような場合には失敗します。 

もう 1 つのエッジ ケースは、文字の出現が十分にあるにもかかわらず、それらがインターリーブされすぎて必要なブロックを順番に形成できない場合です。 たとえば、ある文字が 20 回出現する可能性がありますが、最初のブロックで初期の出現を貪欲に取得すると、順序を明示的にチェックしない限り、後のブロックの実現可能性が損なわれる可能性があります。 

## アプローチ

 強引なアイデアとしては、3 つのブロックのそれぞれに文字を選択し、5 つの出現箇所を検索し、その後 7 つの出現箇所を検索し、さらに 5 つの出現箇所を検索してみるというものです。 各ブロックには 26 の選択肢があるため、26 の可能性があります。 各トリプルについて、文字列をスキャンするか、ポインタを使用して有効なサブシーケンスを見つけます。 各試行の単純なスキャンには O(n) のコストがかかり、約 263 · n 回の操作が必要になります。これは、10⁶ までの n には大きすぎます。 

キャラクターごとに、それが出現する位置のリストを事前計算することで改善できます。 次に、指定されたインデックスの後に k 個の出現のブロックを配置できるかどうかを確認するには、リスト内を前に進むか、二分探索を使用するかが問題になります。 これにより、文字の固定トリプルのチェックが非常に小さくなり、事実上定数または対数になります。 

重要な観察は、順序制約を除いて、構造が文字間で完全に独立していることです。 ブロック内で文字を混在させる必要はありません。そのため、各ブロックは、事前に計算された単一のリストからの出現の選択にすぎません。 これにより、問題は 3 つのシーケンスで注文されたピックの実現可能性をテストすることに変わります。 

アルファベットのサイズは 26 に固定されているため、各チェックが効率的であれば、すべてのトリプルの反復処理が許容されます。

 ## アルゴリズムのチュートリアル

 文字ごとに、文字列内でその文字が出現するすべてのインデックスの並べ替えられたリストを保存します。 これにより、指定された位置の次に有効な文字の出現位置に直接ジャンプできます。 

1. アレイを構築する`pos[c]`キャラクターごとに`c`、発生するすべてのインデックスが昇順に含まれます。 この前処理は、任意の位置の後の k 番目の出現箇所を迅速に特定できるようにするために必要です。 
2. 順序付けられたすべての文字のトリプルを反復処理します。`(a, b, c)`から`'a'`に`'z'`。 各トリプルは、3 つのブロックの候補パターンを表します。 
3. 固定トリプルの場合は、部分シーケンスを左から右に貪欲に構築しようとします。 ポインタを維持します`cur`これは、次に使用できる最小インデックスを表します。 
4. 登場するキャラクターを 5 つ選んでみてください`a`から`pos[a]`、毎回、厳密にその後に最初の出現を選択します。`cur`。 いずれかの時点でそのような発生が 5 件未満である場合、このトリプルは直ちに失敗します。 
5. 最初のブロックを正常に選択した後、更新します`cur`最後に選択した位置へ`a`。 
6. 同じプロセスを繰り返して、出現する文字を 7 つ選択します`b`後`cur`、更新中`cur`再び最後に選択した位置に戻ります。 
7. 最後に、出現する文字を 5 つ選択してみます。`c`後`cur`。 これが成功すると、有効なサブシーケンスが構築され、対応する文字を出力できます。 

貪欲な選択が固定トリプル内で機能する理由は、ブロック内の選択を遅らせると将来の可用性が低下するだけで、増加することはないためです。 ブロック内のすべての文字は同一であるため、最も古い有効な位置を選択すると、最大限の柔軟性が維持されます。 

### なぜ効果があるのか

 固定トリプルの場合`(a, b, c)`の場合、アルゴリズムは常に、位置に関して辞書編集上最も古い有効なサブシーケンスを構築します。 このトリプルに対して有効なサブシーケンスが存在する場合、順序制約を破ることなく、選択された各出現が可能な限り最も早い有効な出現に置き換えられるサブシーケンスが存在します。 この交換引数により、貪欲な選択により、同じトリプルに対して存在する可能性のある解決策が排除されないことが保証されます。 考えられるすべてのトリプルがテストされるため、有効なパターンを発見する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    pos = [[] for _ in range(26)]
    for i, ch in enumerate(s):
        pos[ord(ch) - 97].append(i)

    def take(lst, start, k):
        res = []
        cur = start
        for _ in range(k):
            # find first index > cur
            # binary search
            lo, hi = 0, len(lst)
            while lo < hi:
                mid = (lo + hi) // 2
                if lst[mid] > cur:
                    hi = mid
                else:
                    lo = mid + 1
            if lo == len(lst):
                return None, start
            cur = lst[lo]
            res.append(cur)
        return res, cur

    for a in range(26):
        for b in range(26):
            for c in range(26):
                cur = -1

                res_a, cur_a = take(pos[a], cur, 5)
                if res_a is None:
                    continue

                res_b, cur_b = take(pos[b], cur_a, 7)
                if res_b is None:
                    continue

                res_c, cur_c = take(pos[c], cur_b, 5)
                if res_c is None:
                    continue

                idxs = res_a + res_b + res_c
                out = [''] * 17
                for i, p in enumerate(idxs):
                    out[i] = s[p]
                print(''.join(out))
                return

    print("none")

if __name__ == "__main__":
    solve()
```解決策は、文字ごとにインデックスをグループ化することから始まります。これは、効率的なジャンプを可能にする核となる構造です。 ヘルパー関数`take`指定された位置の後の次の k 個の出現を抽出する責任があります。 事前に計算されたリストに対して二分検索を使用して、次の有効なインデックスを見つけます。これにより、各ステップが文字の頻度において対数的になることが保証されます。 

トリプル ループは、3 つのブロックに対する文字の可能な割り当てをすべて列挙します。 大きく見えますが、定数係数は 26³ に固定されており、各実現可能性チェックが効率的であれば、厳しい時間制限の下では十分小さい値です。 

有効なトリプルが見つかるとすぐに構築が行われるため、ほとんどの場合、プログラムは早期に停止します。 

## 実用的な例

 入力文字列を考慮してください`aaaaacccccccaaaaa`。 

トリプルの成功した試みを追跡できます`(a, c, a)`。 

| ステップ | ブロック | キャラクター | 選択されたポジション | 現在のポインタ |
 | --- | --- | --- | --- | --- |
 | 1 | 最初の 5 | | 0、1、2、3、4 | 4 |
 | 2 | 次の 7 | c | 5,6,7,8,9,10,11 | 11 |
 | 3 | 最新5件 | | 12,13,14,15,16 | 16 |

 これらのインデックスを構築した後、対応する文字を直接出力して、有効なサブシーケンスを形成します。 

このトレースは、アルゴリズムがブロック全体の順序制約を正しく尊重し、以前の位置を再利用しないことを示しています。 

ここで、次のような早期に障害が発生する場合を考えてみましょう。`ababa`何度も繰り返されましたが、単一の文字が連続して利用できるのが不十分でした。 トリプルの場合`(a, a, a)`の場合、最初のブロックは成功する可能性がありますが、最初の選択後に十分なオカレンスが残っていないため、2 番目のブロックは失敗する可能性があり、これにより無効な出力が正しく防止されます。

 ## 特殊なケース

 特殊なケースの 1 つは、3 つのセグメントすべてが同じ文字を使用する場合です。 その状況でも、同じリストが 3 回再利用されるため、アルゴリズムは引き続き機能します。 最初の 5 つのピックでは使用可能なサフィックスが減りますが、リストは前方にスキャンされるため、後のピックでは順序が自動的に尊重されます。 

もう 1 つのケースは、文字がグローバルに十分な回数出現するものの、以前に選択した後に使用可能なシーケンスに含まれない場合です。 たとえば、最初はオカレンスが密で、後でまばらになる可能性があります。 内部の二分探索`take`常に厳密な順序を尊重するため、以前の位置を誤って再利用することはありません。 

最後のエッジケースは、複数の有効なトリプルが存在する場合です。 アルゴリズムは最初に成功した構築で停止しますが、この問題では有効なサブシーケンスが許容されるため、これは問題ありません。
