 ## 解決策
 ## 問題の理解

 私たちには、白バラと赤バラの 2 種類の花が咲く庭が与えられました。 この庭園から、任意の数の花 (すべての色を選択するか、まったく色を選択しないことも可能) を選択して花束​​を作りたいと考えています。 

花束は 2 つの制約を同時に満たさなければなりません。 まず、選択した花の総数が少なくとも所定のしきい値以上である必要があります。 次に、選択した花のうち、赤いバラの数が奇数である必要があります。 

各テスト ケースでは、そのような花のサブセットを選択できるかどうかのみが問われ、それを構築する方法は問われません。 

重要な点は、何も並べ替えたり、順序付けられた構造を選択したりせず、可用性の制限内で赤いバラを何本、白いバラを何本含めるかという数だけを決定することです。 

この制約により、各色最大 10^18 個の花が許可されます。 これにより、可能性を列挙したり、選択肢をシミュレートしようとするアプローチは即座に排除されます。 正しい解決策では、問題をテスト ケースごとの算術チェックの数を一定に減らす必要があります。 

微妙な失敗例は、最小サイズに到達することだけを貪欲に考えることから発生します。 たとえば、必要な合計に達するのに十分な花があるが、しきい値に達するか超えるには偶数の赤いバラが必要であるとします。 このような状況では、単純な「できるだけ多くのデータを取得する」というアプローチは、誤って成功を結論付けてしまいます。 

もう 1 つの例外的なケースは、赤いバラがまったくない場合です。 たとえば、w が大きく、r がゼロの場合、どの花束にも赤いバラは 0 本あり、これは偶数であるため、合計サイズに関係なく自動的にパリティ要件を満たしません。 

同様に、赤いバラが 1 つまたは 2 つしかない場合、パリティにより、サイズ要件を達成するのに役立つ場合でも、1 つを未使用のままにしなければならない可能性があります。 

これらの観察結果は、問題が合計サイズの下限と 1 つのコンポーネントのパリティ制約の組み合わせにあることをすでに示唆しています。 

## アプローチ

 この強引なアイデアは、花束内の赤いバラの可能な数を 0 から r まですべて試し、それぞれの選択肢について、最小サイズの制約を尊重しながら白いバラを使用して花束の残りを埋めることができるかどうかを決定することです。 一定の数の赤いバラ x について、x が奇数であるかどうか、および x といくつかの数の白いバラ y が x + y ≥ k (y ≤ w) を満たすかどうかを確認します。 

これは問題の定義を直接反映しているため機能しますが、遅すぎます。 最悪の場合、r は最大 10^18 になる可能性があるため、すべての可能性を反復処理することは不可能です。 

重要な観察は、構造が非常に単純であるということです。重要なのは赤数の同等性だけであり、白いバラは必要な合計サイズに達するための柔軟な充填材にすぎません。 奇数の赤いバラが必要かどうかを決定したら、最適な戦略は常に、各種類の有効な花をできるだけ多く撮ることです。 

固定パリティを選択する場合、制約を尊重しながら合計数を最大化することが最善です。 これにより、問題は 2 つのケースのうち少なくとも 1 つの実現可能性をチェックすることになります。つまり、奇数の赤を選択するか、制限内にそのような奇妙な選択が存在しないために失敗するかです。 

k − x ≤ w および k − x ≥ 0 となるような奇数の x ≤ r が存在するかどうかだけを知る必要があります。パリティにおいて常に最小の有効な調整が必要であることがわかれば、これは単純な区間の実行可能性チェックになります。

 ## アルゴリズムのチュートリアル

 赤と白のカウントを別々に扱い、合計とパリティの観点からのみ推論します。

1. まず、合計で k 個の花を摘むことが可能かどうかを確認します。 最大で w + r 個の花を取得できるため、w + r < k の場合、パリティに関係なくサイズ制約を満たす選択は存在しないため、答えは直ちに否定になります。 
2. 次に、奇数赤の要件を満たすことに焦点を当てます。 x が奇数、x ≤ r となるような赤い花の数 x が存在するかどうかを知りたいのですが、それでも白を使用して合計 k 個の花に到達できるかどうかを知りたいのです。 
3. x 個の赤い花を摘む場合、合計 k − x 個の白と赤を一緒に摘まなければならないため、必要な白い花の数は k − x − x_red_pa​​rt となり、単純化すると k − x ≤ w となります。 これは、x が k − w ≤ x ≤ r を満たす必要があることを意味します。 
4. したがって、区間 [max(0, k − w), r] 内で少なくとも 1 つの奇数の整数 x を探します。 
5. このような奇数が存在する場合、有効な花束を作成できます。 そうでない場合、答えは否定的です。 
6. 区間内に奇数が存在するかどうかをテストするには、エンドポイントをチェックします。下限が偶数の場合、それが ≤ r であればそれを使用できます。 それ以外の場合は、次の奇数を試します。 

なぜそれが機能するのかは、結局のところ制約を分離することにあります。 合計サイズの制約は、合計 w + r のみを制限しますが、白で塗りつぶすことが可能かどうかは、x を連続した間隔に制限します。 整数区間内では、パリティ制約は、その中に少なくとも 1 つの奇数の整数が存在するかどうかをチェックすることになります。 白い花は完全に柔軟であるため、これ以上の構造がこの間隔の推論を妨げることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        w = int(input())
        r = int(input())
        k = int(input())
        
        if w + r < k:
            out.append("No")
            continue
        
        # we try to find an odd number of red flowers x
        # such that k - x <= w and 0 <= x <= r
        L = max(0, k - w)
        R = r
        
        # find first odd >= L
        if L % 2 == 0:
            x = L + 1
        else:
            x = L
        
        if x <= R:
            out.append("Yes")
        else:
            out.append("No")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードでは、まず、すべての花を採取しても不十分であるという不可能なケースを排除します。 次に、計算された実行可能な範囲内に奇数の整数が存在するかどうかを見つけることに問題を落とし込みます。 重要な唯一の実装詳細は、下限を最初の奇数候補に正しく位置合わせすることです。このステップをスキップすると、間隔が偶数で始まるが直後に奇数が含まれる有効なケースが誤って拒否されるためです。 

## 実用的な例

 ### 例 1

 入力:

 w = 4、r = 3、k = 7

 まず、合計可用性: 4 + 3 = 7 を確認します。これは要件を正確に満たしています。 

赤カウントの実行可能な間隔は [max(0, 7 − 4), 3] = [3, 3] です。 候補は 3 だけですが、これは奇数です。 

| ステップ | Ｌ | R | 最初の奇数 x | 有効？ |
 | --- | --- | --- | --- | --- |
 | 境界を計算する | 3 | 3 | 3 | はい |

 これにより、赤が 3 つあるすべての花を取得できることが確認されました。 

### 例 2

 入力:

 w = 5、r = 4、k = 9

 合計可用性は 9 なので、サイズは実行可能です。 

間隔は [max(0, 9 − 5), 4] = [4, 4] となります。 可能な赤のカウントは偶数の 4 だけであるため、要件に違反します。 

| ステップ | Ｌ | R | 最初の奇数 x | 有効？ |
 | --- | --- | --- | --- | --- |
 | 境界を計算する | 4 | 4 | 5 | いいえ |

 合計 9 個の花に到達できますが、フルサイズの選択ごとに偶数の赤いバラが必要となるため、有効な花束は存在しません。

 ## 特殊なケース

 赤い花がない場合、r = 0 により、すべての花束の赤の数が強制的にゼロ (偶数) になります。 実行可能な区間 [max(0, k − w), 0] に奇数が含まれていないため、アルゴリズムはこれを正しく処理し、すぐに「いいえ」を返します。 

白い花が多く赤い花が少ない場合、たとえば w = 10^18、r = 1、k = 10^18 の場合、間隔は [0, 1] になります。 最初の奇数の候補は 1 であり、範囲内にあるため、解は正しく受け入れられます。 

k = w + r など、最小要件が厳しい場合、アルゴリズムは、r 自体が奇数であるかどうか、または実行可能性を満たしながら赤カウントの 1 単位で調整できるかどうかをチェックすることになり、これは区間ロジックと正確に一致します。
