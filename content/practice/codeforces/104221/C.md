 ## 解決策
 ## 問題の理解

 クズヤは誕生日パーティーの準備をしていますが、招待できるゲストの数は、未知のパン屋でケーキがどのようにスライスされるかによって決まります。 彼の街にはパン屋がいくつかあり、各パン屋は常にケーキを一定の数のスライスにカットします。 Kuzya は、母親がどのパン屋を選ぶかを事前には知りません。 

彼は、どのベーカリーを使用しても、クズヤ自身を含むパーティーの参加者全員でケーキを均等に分割できるように、ゲストの数を選択したいと考えています。 すべての人がまったく同じ数のスライスを受け取る必要があり、未使用のままにすることはできません。 

これをより具体的に再構成すると、いくつかの数値が与えられ、それぞれの数値はケーキを何等分にカットできるかを表します。 考えられるすべてのケーキのサイズに対して、そのケーキがグループ内で均等に分割できるように、グループのサイズを選択する必要があります。 

出力は、この制約の下で可能なゲストの最大数です。 Kuzya本人も参加しているので、合計人数は出力より1人多くなります。 

ケーキ サイズが 10^9 までのベーカリーが 100,000 軒までという制約により、考えられるすべてのグループ サイズを試し、素朴な方法で個別にチェックするソリューションは即座に除外されます。 各候補の直接の割り算チェックでは、最悪の場合、およそ 10^14 の演算が必要になりますが、これは実行可能な制限をはるかに超えています。 

よくある微妙な失敗例は、数値に意味のある共通構造がない場合に発生します。 たとえば、パン屋が 2、3、5 個のスライスを生産する場合、ゲスト数が 0 より大きいグループ サイズを選択する方法はありません。1 より大きい整数ですべてを割ることはできないからです。 もう 1 つの注意が必要なケースは、すべての値が同一である場合です。この場合、ケーキ全体のサイズ自体が制限要因となるため、答えは単純にその値から 1 を引いたものになります。 

## アプローチ

 強引なアプローチは、パーティーに参加できるすべての人数を試し、その人数がすべてのケーキのサイズを割り切れるかどうかを確認することです。 具体的には、候補グループのサイズを 1 から配列の最小値まで反復し、各候補についてすべてのベーカリーに対する割り算をチェックします。 これは、すべてのケーキを選択した人数で均等に分割できるという条件を直接強制するため、正しいです。 

ただし、このアプローチは遅すぎます。 最悪の場合、最大 10^9 の値と 100,000 のベーカリーが存在する可能性があります。 候補を最小限の要素に制限したとしても、最大 10^9 のチェックに直面し、各チェックで 100,000 の要素がスキャンされるため、約 10^14 の操作が必要になります。 

重要な観察は、「グループのサイズがすべてのパン屋に適用される」という条件は、すべての a_i を人数で分割する必要があることを意味するということです。 これはまさに配列全体の公約数の定義です。 すべての候補をテストするのではなく、すべての要素を分割する最大の整数、つまり最大公約数だけが必要です。 

すべての値の gcd を計算したら、有効なグループ サイズでこの gcd を除算する必要があり、考えられる最大の選択肢は gcd 自体です。 Kuzya 自身もカウントに含まれるため、ゲストの数はグループの人数より 1 人減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n · min(a_i)) | お(1) | 遅すぎる |
 | 最適 (GCD) | O(n log A) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは問題を、すべてのケーキのサイズの最大公約数を見つけることに縮小します。 

1. 最初のパン屋のケーキ サイズを最初の候補 gcd 値として開始します。 
2. 残りのすべてのベーカリー値を反復処理し、それぞれの新しい数値で gcd を更新します。

更新のたびに、現在の gcd が gcd(gcd, a_i) に置き換えられ、縮小または変更されないまま維持されます。 
3. すべての値を処理した後の最終的な gcd は、すべてのベーカリーに均等に分配できるケーキ スライスの最大数を表します。 
4. gcd は合計人数 (ゲストと Kuzya) を表すため、これを 1 減算してゲストの数に変換します。 

1 を引く理由は構造的なものです。ケーキを d 等分に分割できる場合、パーティーにはちょうど d 人がいるということになり、ゲストは d から 1 を引いたものになります。 

### なぜ効果があるのか

 すべてのステップで、実行中の gcd は、これまでに処理されたすべての要素を分割する最大の整数です。 新しい要素を含める場合、gcd で更新すると公約数のセットが正確に保持されます。 この不変条件により、最終要素の後の結果はすべての a_i を分割する最大の数になるため、これより大きな有効なグループ サイズは存在できなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd

n = int(input())
a = list(map(int, input().split()))

g = a[0]
for x in a[1:]:
    g = gcd(g, x)

print(g - 1)
```このソリューションは、すべてのベーカリー ケーキのサイズを読み取り、実行中の gcd を維持します。 の`math.gcd`関数は、呼び出しごとの対数時間で最大公約数を効率的に計算します。これは、境界が大きい場合に重要です。 

最後の 1 の減算は、gcd がゲストだけではなく参加者全体をカウントしていることを直接反映しています。 

よくある実装の落とし穴は、最初の要素で gcd を初期化するのを忘れ、代わりにゼロから開始することです。 数学的には gcd(0, x) = x ですが、これは安全ですが、明示的ではありません。 で初期化しています`a[0]`混乱を避け、不変の記述とより明確に一致します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log A) | 各 gcd 計算は値のサイズが対数であり、n 個の要素に適用されます。 
| スペース | お(1) | 単一の実行中の gcd 値のみが保存されます。 

この制約では最大 100,000 個の値が許可され、各値は最大 10^9 であるため、対数 gcd 演算は時間制限内に問題なく収まります。 

## テストケース```python
import sys, io
from math import gcd

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    g = a[0]
    for x in a[1:]:
        g = gcd(g, x)

    return str(g - 1)

def run(inp: str) -> str:
    return solve(inp)

# provided samples
assert run("2\n5 10\n") == "4"
assert run("5\n2 7 8 10 5\n") == "0"

# custom tests
assert run("1\n7\n") == "6", "single bakery"
assert run("3\n6 12 18\n") == "5", "clear gcd structure"
assert run("4\n1 1 1 1\n") == "0", "all ones edge"
assert run("2\n1000000000 500000000\n") == "499999999", "large values"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 つの数字 | 単一の値から 1 を引いた値 | 最小限の入力処理 |
 | 6 12 18 | 5 | マルチステップ GCD の安定性 |
 | すべてのもの | 0 | 最小の gcd ケース |

 ## 特殊なケース

 ベーカリーが 1 つだけある場合、gcd は単にその値であるため、答えは a_i - 1 になります。残りの要素に対するループがスキップされ、初期値がそのまま残されるため、アルゴリズムはこれを自然に処理します。 

7 のような入力の場合、実行中の gcd は 7 であるため、出力は 6 になり、6 人のゲストと Kuzya を意味します。 

10 10 10 など、すべての値が等しい場合、gcd は全体を通して 10 のままです。 つまり、パーティーには合計 10 人が参加できるので、ゲストは 9 人になります。 gcd(a, a) は常に a であるため、アルゴリズムはこれを保持します。 

配列に 1 が含まれる場合、gcd はすぐに 1 になり、それ以降の更新ではそれを変更できません。 これにより、1 人を超えるグループは形成できないため、答えはゲスト 0 人に正しく強制されます。
