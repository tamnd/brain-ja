 ## 解決策
 ## 問題の理解

 次のような無向の単純なグラフが与えられます。$n$交差点と$m$道路。 各道路は 2 つの異なる交差点を接続しており、交差点のペアの間に存在する道路は最大でも 1 つです。 タスクは、すべての道路に方向を割り当て、方向を指定した後、ある交差点からスタートして、サイクル内で指示された道路を永遠にたどることが不可能になるようにすることです。 

グラフの用語では、無向グラフを有向サイクルを持たない有向グラフに変換する必要があります。 各エッジの方向は独立して自由に選択できますが、最終的な有向構造は非環状でなければなりません。 有効な方向が複数存在する場合は、そのうちのいずれかを印刷できます。 

制約は大きく、最大で$2 \cdot 10^5$頂点とエッジ。 これにより、頂点のすべての順列を試したり、サイクル形成を繰り返しシミュレートしたりするような二次関数は直ちに除外されます。 必要なのは$O(n + m)$または$O(m \log n)$工事。 

微妙な点は、入力グラフ自体にサイクルが含まれる可能性があり、さらにその多くが含まれる可能性があることです。 「まずサイクルを断ち切らなければならない」という素朴な思い込みは、不必要な複雑さをもたらします。 実際のタスクは、エッジの削除や構造の変更ではなく、純粋に方向を割り当てることです。 

典型的な失敗例は、グローバル ルールを使用せずにローカルで貪欲な方向付けを試みた場合に発生します。 たとえば、三角形の場合$1-2-3-1$、向きを変えると$1 \to 2$、$2 \to 3$、 そして$3 \to 1$、すぐに有向サイクルを作成します。 ローカルな一貫性のみに基づいた貪欲なルールは、グローバルな順序付けを強制しない場合、簡単にこのような矛盾に陥る可能性があります。 

もう 1 つの落とし穴は、最初に無向グラフ内のサイクルを検出する必要があると仮定していることです。 サイクルでいっぱいのグラフでも DAG に方向付けることができるため、これは無関係です。 

## アプローチ

 ブルートフォースの考え方は、エッジを 1 つずつ方向付けして、各割り当ての後に有向サイクルが現れるかどうかを確認しようとすることです。 各チェックでは、有向グラフでのサイクル検出が必要です。$O(n + m)$、そして私たちはそれをします$m$につながる$O(m(n + m))$。 と$m$まで$2 \cdot 10^5$、これでは遅すぎます。 

重要な構造的洞察は、すべてのエッジがその順序で前方を指すような頂点のグローバルな順序が存在する場合に、有向グラフが非巡回であるということです。 これにより、問題は「サイクルを動的に回避する」という問題から「一貫した頂点のランキングを選択する」という問題に変換されます。 

完全な注文だけが必要であることを受け入れてしまえば、構築は簡単になります。 ラベルなどの厳密な順序を頂点に割り当てます。$1 < 2 < \dots < n$。 次に、すべての無向エッジについて$(u, v)$、小さいラベルから大きいラベルの方向に配置します。 有向サイクルは、ラベルのシーケンスが厳密に増加し、最終的には先頭に戻ることを意味しますが、これは不可能です。 

これは、元のグラフの密度や周期に関係なく機能します。方向付けは構造を無視し、グローバルな順序付けのみに依存するためです。

 ## アルゴリズムのチュートリアル

 一貫した頂点順序を強制することにより、有向非巡回グラフを構築します。 

1. 各頂点にそのインデックスに等しい固定ランクを割り当てます。$1$に$n$。 これにより、すべての頂点にわたって厳密な合計順序が作成されます。 この順序を導入する理由は、非巡回方向は何らかの順序と互換性がなければならないため、非巡回方向を直接構築します。 
2. 入力で指定されたすべてのエッジを反復処理します。 各エッジについて$(u, v)$の順位を比較します。$u$そして$v$。 
3. もし$u < v$、エッジの向きを次のようにします$u \to v$。 それ以外の場合は、次のように配置します$v \to u$。 これにより、すべてのエッジがランクの小さい頂点からランクの大きい頂点に向かうようになります。 
4. すべての向きのエッジを、読み取られたのと同じ順序で出力します。 

### なぜ効果があるのか

 矛盾のために、配向後に有向サイクルが存在すると仮定します。 このサイクルに沿って、構築ルールにより、すべてのエッジは小さいインデックスから大きいインデックスに移行する必要があります。 これは、サイクルをトラバースすると、頂点インデックスがステップごとに厳密に増加することを意味します。 厳密に増加させると開始頂点に戻ることはできません。これは、開始インデックスがサイクル内で同時に最小と最大の両方である必要があるためです。 したがって、有向サイクルは存在できず、グラフは DAG になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    edges = []
    for _ in range(m):
        u, v = map(int, input().split())
        if u < v:
            edges.append((u, v))
        else:
            edges.append((v, u))

    out = []
    for u, v in edges:
        out.append(f"{u} {v}")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装は順序付けのアイデアを直接エンコードします。 各エッジは、その方向が頂点の自然な数値順序に従うように直ちに正規化されます。 構築自体が非周期性を保証するため、隣接リスト、DFS、または周期検出は必要ありません。 

よくある間違いは、エッジを保存し、後で方向を一貫性なく決定することです。 重要な特性は、同じグローバルな順序付けが例外なくすべてのエッジに均一に適用されることです。

 ## 特殊なケース

 完全なグラフなどの密な循環グラフは、すべてのエッジが依然として同じグローバルな数値順序に従って方向付けられているため、正しく処理されます。 たとえば、完全に接続されたトリプルでは、​​すべてのエッジが以下と一致します。$1 < 2 < 3$、サイクルではなく厳密な階層を生成します。 

単一エッジのグラフは、他のエッジに依存せずに比較によって方向が即座に割り当てられるため、簡単に機能します。 この最小限のケースでも、すべてのエッジが同じ順序を尊重するという不変条件は有効のままです。 

入力エッジが任意の順序で与えられるグラフは、方向が入力シーケンスから独立しているため、正確さに影響しません。 各エッジは個別に処理されますが、常に同じグローバル ルールの下で処理されます。
