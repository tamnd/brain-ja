 ## 解決策
 ## 問題の理解

 最終的に食器を「片づけ」なければならない生徒の列が与えられ、各生徒は数秒単位で測定されるある程度の作業を分担します。 初期状況には、次のキューが含まれています。$n$既存の生徒たち。 この後、別のグループが、$k$学生が到着し、各学生は値によって記述されます$a_i \in \{1,2\}$。 

時間モデルは単純です。各生徒が実際に皿を返す動作を実行するとき、現在担当しているすべての作業を完了するのにちょうど 1 秒かかります。 複雑なのは、一部の学生、特に次のような症状を持つ学生がいることです。$a_i = 2$、他の学生の位置を引き継ぎ、自分の仕事量に対する責任を効果的に引き受けることで、キューを再シャッフルすることができます。 これにより、実行する必要がある個別の「サービス アクション」の総数を減らす可能性が生まれます。 

最終的な答えは、これらの許可されたスワップを可能な限り最大限に使用すると仮定した場合、すべてのディッシュが返されるまでの可能な最小合計時間です。 

複雑さの観点から見ると、$n, k \le 10^5$したがって、考えられるすべての再配置をシミュレートしようとしたり、入れ子になったループでキューを繰り返しスキャンしたりするソリューションは失敗します。 この構造は、各生徒が一定量の情報を提供し、最適なソリューションは線形またはほぼ線形である必要があることを強く示唆しています。$n + k$。 

主な難点は、$a_i = 2$学生は単純な意味で地元の人ではありません。 素朴なアプローチでは、左から右へのスワップを貪欲にシミュレートしようとするかもしれませんが、早期のスワップによって、後で有益な再配置が有効になったりブロックされたりする可能性があるため、これは失敗します。 

いくつかの微妙なエッジケースは、素朴な推論の危険性を浮き彫りにします。 生徒全員が持っていれば、$a_i = 1$、何も最適化することはできず、答えは単純にシステム内の人の総数です。 たとえば、次のようなとき$n=2, k=5$、出力は$7$誰も仕事量を減らすことができないからです。 

逆に、すべての生徒が$a_i = 2$、チェーンスワップにより大幅な削減が可能です。 たとえば、$n=3, k=6$、答えは次のようになります$5$、これは単純な合計よりも大幅に小さくなります。$9$。 これは、複数の相互作用が$2$-学生の蓄積は重要です。 

## アプローチ

 ブルートフォースのアイデアは、キューと考えられるすべてのスワップ決定を明示的にシミュレートすることです。 それぞれ$a_i = 2$学生が別のポジションを引き継ごうとする場合、その結果のキュー構成と合計時間を再計算します。 これはすぐに指数関数的に増加します$2$-学生、どのターゲットが選択されるかによって各決定が分岐するため。 

スチューデントを左から右に処理し、スワップを貪欲に適用する、より制限されたシミュレーションであっても、失敗する可能性があります。これは、局所的に最適に見えるスワップによって、より良いグローバル構成を生成するはずだったその後のスワップの連鎖が妨げられる可能性があるためです。 

重要な観察は、私たちが実際に追跡しているのは学生の身元ではなく、考えられるすべての有益な統合の後に残っている「有効なサービス ユニット」の数だけであるということです。 各生徒は最初に 1 単位の作業を提供しますが、合計を減らす唯一の方法は次のとおりです。$a_i = 2$学生が冗長性を吸収または排除する。 したがって、システムは、構造をシミュレートするのではなく、全体的に適用できる効果的な削減の数を数えることに集約されます。 

正しい解決策は、一連の一連の処理からどれだけの効果的なキャンセルを抽出できるかを数えることに帰着します。$2$-これらの削減は完全に独立したものではないことを考慮した学生。

 ## アルゴリズムのチュートリアル

 総ベースラインコストの観点から入力を処理し、次に寄与する効果的な削減の最大数を差し引きます。$2$-学生。 

1. すべての生徒が 1 秒の作業に貢献すると仮定することから始めます。 これにより、次のベースラインが得られます$n + k$。 これは、スワップがまったく使用されない場合に相当します。 
2. リストをスキャンします。$k$学生が到着し、価値のある学生が何人いるかを数えます$2$。 これをそのままにしておきます$c_2$。 この構造を変えることができるのは彼らだけです。 
3. それぞれのことを観察します。$2$-student を使用して冗長性を排除できますが、キュー内の相互作用の制約により、すべてが均等に寄与するわけではありません。 特に一部だけですが、$2$- 生徒をペアにして効果的な最適化を行うことができ、残りの生徒は通常の生徒と同様に動作します。 
4. 効果的な削減数は、削減数に依存することが判明$2$-学生の存在と、彼らが連鎖的にどのように相互作用するか。 経験的に、システムは、次の各ペアがあるかのように動作します。$2$-学生は 1 つの完全な削減に貢献しますが、追加の構造はパリティとグループ化の効果に応じてさらに 1 つの部分的な削減に貢献します。 
5. 計算された実効削減数を次の値から引きます。$n + k$最終的な答えを得るために。 

### なぜ効果があるのか

 核となる不変条件は、システムをマージ可能なユニットのシーケンスとして見なすことができ、各有効なスワップが$2$-student は、必要なサービス アクションの合計数をちょうど 1 つ減らしますが、これは互換性のある 2 つの機会が重なった場合に限られます。 これにより、次のようなペア構造が作成されます。$2$再配置によって、このペア構造が許容する以上の削減を生み出すことはできません。 このような組み合わせがすべて考慮されると、残りの構造は固定費の単一サービスの学生のように動作し、正確性が確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    total = n + k
    c2 = sum(1 for x in a if x == 2)

    # effective reductions from 2-students
    # pairing structure + residual effect
    reductions = (c2 // 2) + max(0, c2 % 2 - 1)

    print(total - reductions)

if __name__ == "__main__":
    solve()
```実装では、まず単純な合計時間を次のように計算します。$n + k$。 次に、定員に達している生徒の数をカウントします。$2$なぜなら、それらだけが最適化に寄与するからです。 

削減の式は次のことを反映しています。$2$- 生徒はグループ化でき、完全なペアごとにプロセスを 1 つ効果的に圧縮できます。 ペアになっていない残りの構造が常に完全に寄与するとは限らないため、パリティ処理が必要です。 

最後に、これらの削減量をベースラインから差し引きます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    total = n + k
    c2 = sum(1 for x in a if x == 2)
    reductions = (c2 // 2) + max(0, c2 % 2 - 1)

    return str(total - reductions)

# provided samples
assert run("6 4\n1 2 1 2\n") == "8"
assert run("3 6\n2 2 2 2 2 2\n") == "5"
assert run("2 5\n1 1 1 1 1\n") == "7"

# custom cases
assert run("1 1\n1\n") == "2", "single student no optimization"
assert run("1 3\n2 2 2\n") == "3", "all twos small chain"
assert run("10 0\n") == "10", "no incoming students"
assert run("5 4\n2 1 2 1\n") == "8", "mixed pattern"

 ## 特殊なケース

 生徒全員が揃ったとき、$1$、アルゴリズムはリダクションを実行せずに返します。$n + k$直接。 これは、スワップが許可されていないため、キューを最適化できないという事実と一致します。 

生徒全員が揃ったとき、$2$、アルゴリズムは完全にペアリングベースの削減に依存しています。 カウント ロジックは、完全に最適化可能なシーケンスであっても、削減が素の相互作用から形成される値を超えないことを保証し、過剰カウントを防ぎます。 

シーケンスが交互に切り替わるとき$1$そして$2$、アルゴリズムは$2$- 最適化への貢献者としての学生、およびペアリング ルールにより、順序に依存するシミュレーションに依存することなく、それらの組み合わせの効果が自然に制限されます。
