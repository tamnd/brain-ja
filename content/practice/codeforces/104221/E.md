 ## 解決策
 ## 問題の理解

 直線に沿った店舗の可能な位置がいくつか与えられ、顧客のセットが与えられます。各顧客は固定点に住んでおり、個人的な許容範囲があります。 店舗の場所を 1 つ選択し、お茶の単位ごとに単一の価格を設定した場合、各顧客は、店舗までの交通費と価格の合計がしきい値を超えない場合に限り、最大でも 1 単位を購入します。 

固定店舗ポジションの場合$x_i$そして価格$c$、 お客様$j$もしそうなら買うつもりです$|x_i - y_j| + c \le a_j$。 これを整理すると条件はこうなる$c \le a_j - |x_i - y_j|$。 したがって、各顧客は、店舗の場所ごとに最大許容価格を提供します。 

店舗の場所と価格を 1 つ選択する必要があります$c$少なくともそうなるように$k$顧客は条件を満たしているため、それぞれ 1 ユニットずつ購入します。 すべての顧客が購入できるのは最大 1 ユニットであるため、満足した顧客の数は単に制約が満たされた顧客の数です。 目標は最大化することです$c$、または有効な構成が存在しないことを報告します。 

制約$n, m \le 10^5$顧客と店舗の位置のすべての組み合わせを直接チェックすることは直ちに除外されます。$10^{10}$最悪の場合の運用。 どのソリューションでも、すべてのペアを明示的に評価することは避けなければなりません。 

微妙な点は、実現可能性が価格的に単調であることです。 価格なら$c$売るために働く$k$アイテムの場合は、それより低い価格でも機能します。$c$より多くの顧客が不等式を満たすだけです。 この単調性は、答えの二分探索を強く示唆しています。 

単純な間違いは、各ショップのすべての顧客に対して反復処理を行うことにより、条件を満たす顧客の数を各ショップで計算することです。 これでは作業が繰り返され、遅すぎます。 

もう一つの間違いは、貪欲に独自の店舗に顧客をアサインしようとすることです。 この制約は顧客ごとではなく、選択したショップごとにグローバルであるため、ローカルな決定は構成されません。 

注目に値するエッジケースには、どの店もプラスの価格で 1 人の顧客さえも満足させることができない状況、または次のような状況が含まれます。$k$たとえ価格がゼロであっても、あらゆる場所でサービスを提供できる顧客の数よりも多くなります。 

## アプローチ

 ブルートフォース手法は簡単です。 店舗のポジションごとに、どれだけの顧客が満足しているかを確認することで、暗黙のうちにあらゆる可能な価格を試します。$a_j - |x_i - y_j| \ge c$。 候補価格を固定した場合、固定ショップの満足顧客を数えるには時間がかかります。$O(n)$。 これをすべてのショップに対して繰り返すと、$O(mn)$最適化がなければ、多くの価格を検索したり、カウントを繰り返し再計算したりする必要があり、これは許容範囲をはるかに超えています。 

重要な観察は、店舗の場所が固定されている場合、各顧客が価格に独立した上限を設定していることです。 価格で購入できる顧客の数$c$まさにその数です$j$そのような$a_j - |x_i - y_j| \ge c$。 こちらはモノトーンです$c$, したがって、実現可能な最大価格を二分探索できます。 残りの問題は、与えられた条件について実現可能性を効率的に評価することです。$c$。 

固定の場合$c$、各顧客は、受け入れられる店舗ポジションの間隔を誘導します。$$|x_i - y_j| \le a_j - c$$つまり$$x_i \in [y_j - (a_j - c),\; y_j + (a_j - c)]$$したがって、各顧客は店舗の場所に対して間隔となり、ポイントを選択する必要があります$x_i$少なくともカバーされる$k$間隔。 これは、間隔に関する古典的なスイープ ライン/座標圧縮問題であり、少なくともいずれかの位置がカバーされているかどうかを確認します。$k$。 

店舗の位置を並べ替えて圧縮し、差分配列またはバイナリ インデックス付きツリーを使用して、各店舗の位置をカバーする間隔の数をカウントできます。 各実現可能性チェックが実行されます$O(n + m)$、そしてその答えに対して二分探索を実行します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(mn)$小切手ごと |$O(1)$| 遅すぎる |
 | 最適 |$O((n + m)\log A)$|$O(n + m)$| 承認済み |

 ここ$A$は可能な最大価格であり、次の制限があります$10^9$。 

## アルゴリズムのチュートリアル

 この問題を、指定された価格が正しいかどうかを確認することに変換します。$c$が実現可能である場合は、実現可能な最大値を二分探索します。 

### 固定価格の実現可能性チェック$c$1. お客様ごとに$j$、計算する$r_j = a_j - c$。 もし$r_j < 0$、この顧客はまったく購入できず、無視されます。 
2.店舗ごとのポジション$x_i$、すべての顧客が満足していると解釈します$|x_i - y_j| \le r_j$そのポジションに +1 カバレッジに貢献するとみなします。 
3. 各顧客を間隔に変換する$[y_j - r_j, y_j + r_j]$。 実際の店舗の位置との重複のみを考慮します。 
4. ショップの位置をソートし、プレフィックスの合計を使用して、各ショップをカバーする間隔の数をカウントします。 
5. ショップのポジションが少なくとも以下の条件に該当する場合$k$間隔、価格$c$実現可能です。 

重要な技術的ステップは、間隔範囲を個別の工場位置に効率的にマッピングすることです。 店舗をソートし、二分探索を使用して圧縮配列内の間隔の終点を見つけてから、差分配列を適用します。つまり、最初にカバーされたショップのインデックスに +1 を追加し、最後にカバーされたインデックスの後に -1 を追加します。 

### 価格よりも二分探索

 範囲内で検索します$[0, \max a_j]$。 中間値ごとに、実現可能性チェックを実行します。 可能であれば、より高い価格を試します。 それ以外の場合は削減します。 

### なぜ効果があるのか

 固定店舗の場合、価格を上げても満足する顧客の数が減るだけです$a_j - |x_i - y_j| \ge c$。 この単調性により、実現可能性が単調であることが保証されます。$c$。 各顧客が価格で購入したい一連の店舗ポジションを個別に定義するため、実現可能性条件自体はインターバル カバレッジによって正しく捕捉されます。$c$。 有効なソリューションは、少なくとも以下の条件でカバーされる店舗位置がある場合に存在します。$k$そういった間隔。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(c, n, m, k, y, a, x):
    events = []
    for j in range(n):
        r = a[j] - c
        if r < 0:
            continue
        l = y[j] - r
        rgt = y[j] + r
        events.append((l, rgt))

    if not events:
        return False

    xs = sorted(x)
    m = len(xs)

    diff = [0] * (m + 1)

    import bisect
    for l, r in events:
        i = bisect.bisect_left(xs, l)
        j = bisect.bisect_right(xs, r) - 1
        if i <= j:
            diff[i] += 1
            diff[j + 1] -= 1

    cur = 0
    for i in range(m):
        cur += diff[i]
        if cur >= k:
            return True

    return False

def solve():
    n, m, k = map(int, input().split())
    y = []
    a = []
    for _ in range(n):
        yi, ai = map(int, input().split())
        y.append(yi)
        a.append(ai)

    x = list(map(int, input().split()))

    lo, hi = 0, max(a)
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, n, m, k, y, a, x):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、問題を二分探索ドライバーと実現可能性チェッカーに分離します。 チェッカーは、各顧客を購入希望の店舗位置の範囲に変換し、ソートされた店舗座標の差分配列を使用して重複をカウントします。 二等分演算により、各間隔が対数時間でマッピングされます。 

よくある落とし穴は、実際のライン全体ではなく、店舗の位置だけを気にしていることを忘れていることです。 そのため、間隔は連続的に処理されるのではなく、ソートされたショップ配列のインデックスに投影されます。 

もう 1 つの微妙な点は、空の実現可能性を処理することです。すべての顧客が$a_j < c$の場合、関数はすぐに false を返し、誤った蓄積を防ぎます。

 ## 特殊なケース

 すべての場合に 1 つのエッジケースが発生します。$a_j < c$。 その状況では毎回$r_j$は負になり、間隔リストは空になります。 実現可能性チェックはすぐに false を返します。これは、その価格では何も購入できない顧客が存在しないという事実と一致します。 

もう 1 つの特殊なケースは、間隔が店舗の境界に正確に接する場合です。 私たちが使っているので、`bisect_left`そして`bisect_right`、間隔が店舗の位置で正確に終了する顧客は、その店舗をカバレッジに正しく含めます。 たとえば、顧客間隔が$[2, 5]$店舗には 5 が含まれており、右側の境界にはその店舗が含まれています。`bisect_right`カバーされたセグメント内に配置します。 

最後のエッジケースは、複数の店舗が同じ座標を共有する場合です。 ソートにより重複が保存され、差分配列によりすべての同一位置にわたるカバレッジが正しく集約されるため、各重複ショップはプレフィックス スキャンで独立して、しかし一貫して処理されます。
