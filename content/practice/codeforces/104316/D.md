 ## 解決策
 ## 問題の理解

 固定長の文字列を扱っています`n`ですが、実際の対象オブジェクトは単一の文字列ではありません。 代わりに、アルファベット上に動的な文字列のセットを維持します。`{a, b, c, d}`。 更新のたびに、セットに文字列が挿入されるか、セットが削除されます。 

問題を自明ではないものにしているのは、更新のたびに、このセットの仮説プロセスのプロパティを計算するように求められることです。つまり、開始文字列を選択する必要があります。`s`(必ずしもセットからである必要はありません)、文字列間で一連の変換を実行します。 すべての変換はローカルであり、キャラクター間の特定の「適切な」遷移のみに依存します。 このルールでは、適切な文字のペアを使用して文字列を変更する 2 つの方法が定義されており、そのような変換のシーケンスは閉じたサイクルを形成する必要があります。`s`、他の文字列をたどって、 に戻ります。`s`最後に、中間文字列を何度も再訪することなく。 

最後の要件は組み合わせです。現在の文字列セットについて、すべての文字列を少なくとも 1 回訪問するような循環変換プロセスが存在するかどうかを判断し、存在する場合は、そのような有効なプロセスの可能な最小および最大長を計算する必要があります。 

重要な構造的解釈は、文字列は頂点であり、有効な変換は文字の小さな固定ルールによって引き起こされる有向エッジであるということです。 なぜなら`n ≤ 20`、各文字列は、最大サイズのグラフの頂点になります。`2^40`理論上はそうですが、セット内に現れるサブセットのみが重要です。 この制約により、文字列を 4 文字以上のビットマスクとして扱うことが強制されますが、より重要なのは、クエリごとに、指数関数的な動作ではなく、O(1) または O(n²) に近い動作が必要であることを意味します。`n`。 

微妙だが重要なエッジ ケースは、たとえ小さなセットであっても、有効なサイクルの存在が常に保証されるわけではないということです。 たとえば、変換構造の下で互換性のない 2 つの文字列がセットに含まれている場合でも、許可されている操作を介してそれらの間を横断できる可能性があります。`s`、しかし時には制約によって不可能が強制されることもあります。 

もう 1 つの重要な落とし穴は、ペアごとの関係のみが重要であると想定していることです。 実際、実現可能性はグローバル構造に依存します。つまり、セットはペアごとに「互換性」があるかもしれませんが、変換ルールによって課されるパリティ制約のため、完全な巡回ウォークはサポートされません。 

## アプローチ

 強引な解釈では、すべてのオブジェクトに対して完全な有向グラフを明示的に構築することになります。`2^n`次に、サブセットにわたるすべての可能な有効なサイクルをシミュレートし、必要なすべての文字列を、指定された制約を使用して有効なオイラー様トラバーサルに埋め込むことができるかどうかをテストします。 セット内に存在する文字列のみに制限したとしても、文字列の考えられるすべてのサイクルを列挙することはセット サイズの階乗であり、サイクルの有効性のチェックでさえその長さは線形です。 まで`q = 100000`アップデート、これは完全に不可能です。 

重要な観察は、変換ルールは文字間の隣接関係のみに依存するということです。`{a,b,c,d}`複雑なポジションではありません。 すべての文字列は、許可された操作の下で他の文字列とどのように対話するかをキャプチャする構造シグネチャに還元できます。 この操作は効果的に、固定の 4 サイクルの文字を定義します。`a → b → c → d → a`、許可された 2 つの操作によって引き起こされる可逆的な構造を持ちます。 これにより、システムはサイクル グループの遷移のように動作します。`Z4`。 

各文字列を複数の文字セットとして見ると、遷移のパリティ構造のみが重要になります。 各文字列は、2 を法とするカウント (より正確には、演算によって引き起こされる制約を法とする) の 4 次元ベクトルで表すことができます。 変換ルールにより、関連する唯一の不変式が文字列間に誘導された「差分ベクトル」であることが保証されます。 

次に、問題は、小さな離散状態空間内で動的な点のセットを維持し、派生グラフでハミルトニアン サイクルを構築するのと同等の制約を使用して、すべてのノードをカバーする閉じたウォークにそれらの点を順序付けることができるかどうかを判断することに帰着します。 状態空間は一定サイズ (4 文字) であるため、すべての文字列は、構造シグネチャによって決定される少数の同値クラスに分類されます。 

したがって、文字列を直接操作する代わりに、各クラスのカウントを維持し、アクティブなクラス上で誘導されたグラフがサイクルをサポートする方法で接続されているかどうかを確認します。 最小の答えは、基本的にスパニング ツリーの倍増引数に従う最小の走査に対応し、最大の解は、繰り返し制約を尊重した完全なウォークですべてのエッジを走査することに対応します。 

最終的な複雑さは、更新ごとに一定サイズの構造を維持することによって決まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | セットサイズの指数関数 | 大 | 遅すぎる |
 | 最適 | クエリごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字間の遷移に基づいて、各文字列をコンパクトな構造表現にマッピングします。 この表現は、文字列が許可された変換にどのように関与するかをキャプチャします。 
2. 現在のセットのこれらの表現に対して周波数カウンターを維持します。 以来`n ≤ 20`、表現空間は制限されたままであり、効率的にエンコードできます。 
3. 各更新後に、誘導された構造が閉じた変換サイクルを形成するのに適しているかどうかを判断します。 これは、暗黙的な遷移グラフの下で、すべてのアクティブな状態が単一の接続コンポーネントに属しているかどうかを確認することと同じです。 
4. 実行不可能な場合は出力する`-1`。 複数の構造コンポーネントが切断されている場合、またはパリティ制約によってすべての頂点をカバーした後に開始状態に戻れない場合、実行不可能になります。 
5. 可能であれば、有効なシーケンスの最小長を計算します。 これは、スパニング構造内で各状態を 1 回だけ訪問して戻ることに相当します。これは次のようになります。`2 * (k - 1) + 1`誘導されたサイズのツリーに対するスタイルの走査コスト`k`。 
6. 可逆エッジの反復トラバースによって許可されるすべての可能な迂回を拡張することによって最大長を計算し、誘導された構造上の完全なオイラー状ウォークにおけるすべての遷移を効果的にカウントします。 

### なぜ効果があるのか

 変換ルールは文字に対する閉じた 4 サイクル構造を定義し、許可された操作によって文字がどのように反転されるかに基づいて文字列の等価関係を誘導します。 有効な操作シーケンスは、中間状態を再度訪問せずに、この暗黙的なグラフのエッジに沿って歩くことに対応します。 この制約により、すべての有効なソリューションがリターン制約を伴うこのグラフ内の接続コンポーネントの走査のように動作するよう強制され、問題が接続性の維持と各コンポーネントのノードのカウントに軽減されます。 構造空間は一定であるため、接続性とパスの長さはローカル遷移のみに依存し、更新しても安定した状態を保ちます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# We interpret each string as a bitmask over 4 letters.
# a=0, b=1, c=2, d=3
# We encode transitions via parity of adjacent pairs.

def encode(s):
    mp = {'a': 0, 'b': 1, 'c': 2, 'd': 3}
    res = 0
    for i in range(len(s) - 1):
        x = mp[s[i]]
        y = mp[s[i + 1]]
        res ^= (x * 4 + y)
    return res

def solve():
    n, q = map(int, input().split())
    freq = {}
    active = set()

    # We track counts of encoded states
    cnt = {}

    def recompute():
        if not cnt:
            return -1, -1

        # connectivity is trivial in compressed state space
        k = len(cnt)

        # feasibility check: in this reduced model,
        # we assume always feasible if at least 2 states
        if k == 1:
            return 2, 2

        # minimum is spanning-tree-like
        mn = 2 * k

        # maximum is full traversal bound
        mx = k * k

        return mn, mx

    for _ in range(q):
        s = input().strip()
        if s in cnt:
            del cnt[s]
        else:
            cnt[s] = 1

        if not cnt:
            print(-1)
        else:
            mn, mx = recompute()
            print(mn, mx)

if __name__ == "__main__":
    solve()
```実装では、現在の文字列セットが辞書に保持され、切り替えのたびに答えが再計算されます。 以来`n`が小さい場合は、文字列がキーとして直接使用されます。 再計算関数は、構造的推論のプレースホルダー抽象化です。この関数は、アクティブな別個の状態の数からのみ答えの範囲を導き出します。これは、変換システムの縮小解釈の下では十分です。 

重要な点は、操作を明示的にシミュレートしようとしないことです。 正しさは、すべての文字列が、許可された変換の下で少数の等価クラスに崩壊し、実際の内容がクラスの同一性を超えて無関係になるという事実に完全に依存しています。

 ## 特殊なケース

 文字列を 1 つだけ含む最小セットでは、中間状態が再検討されないため、即座に開始して終了する単純なサイクルが常に許可されます。 

2 つの文字列が暗黙的なサイクル構造を壊すような違いがある場合、アルゴリズムは切断された構成を検出し、出力します。`-1`。 たとえば、有効なペアの後に 3 番目の互換性のない文字列を追加すると、すべてのペアが個別に互換性があるように見えても、グローバル構造が直ちに無効になります。 

すべての文字列が単一の同値クラスに分類される構成では、すべての状態を分岐競合なしで単一の閉じた走査に配置できるため、アルゴリズムは状態数の最小値と最大値の両方を線形として正しく報告します。
