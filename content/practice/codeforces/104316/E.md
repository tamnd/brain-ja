 ## 問題の理解

 1 つの水平な道路の上下に 2 列の点が並んでいます。 各整数位置で$i$1から$n$、ウェイトのある上側にカフェがあります$a_i$そして下側にはウェイトのあるカフェ$b_i$。 これらの重みは、毎日各カフェを訪れる人の数を表します。 

カフェの一部に広告を掲載することは許可されています。 カフェの位置に広告を掲載すると$x$、そのカフェは「ブラインド」になり、そのカフェの訪問者には広告がまったく表示されなくなります。 

配置された広告は、通りの反対側のカフェからのみ、かつ水平距離が最大 200 メートル以内にある場合にのみ表示されます。$d$。 それで、上のカフェに置かれた広告$i$下のカフェで見られます$j$そのような$|i - j| \le d$ただし、それらの下層カフェ自体が広告を掲載していない場合に限ります。 同じ規則が他の方向にも対称的に適用されます。 

各カフェは、訪問者が少なくとも 1 つの広告を見たかどうかに応じて、回答に全力を尽くすか、何も貢献しません。 カフェに広告がある場合、何が表示されるかに関係なく、その貢献度は常にゼロです。 

目標は、カフェで少なくとも 1 つの広告を見る人の総数が最大化されるように、広告を配置する場所を選択することです。 

重要な難点は、広告を配置すると 2 つのことが同時に行われることです。広告は反対側の範囲に視認性をもたらしますが、広告が配置されているカフェからの視認性も破壊します。 

制約$n \le 1500$と提案する$O(n^3)$それ以上の解決策は実行不可能ですが、$O(n^2)$動的プログラミングアプローチが期待される可能性があります。 

A subtle edge case comes from the fact that selecting a café removes its own contribution entirely. たとえば、領域内のあらゆる場所に広告を配置しても、増加する体重よりも多くの体重を削除する可能性があるため、必ずしも回答が増加するとは限りません。 

もう一つの重要なケースは次のような場合です。$d = 0$。 この場合、各広告は同じインデックスにある真向かいのカフェにのみ影響を与えるため、問題は慎重にペアリングするかポジションを選択的にアクティブにするだけになります。 

## アプローチ

 強引なアイデアは、両側のカフェのすべてのサブセットを試してみることです。 各構成について、どのカフェに少なくとも 1 つの広告が表示されるかをシミュレートします。 これには、すべての広告を反対側のすべてのカフェと照合することが含まれ、可視性の計算につながります。$O(n)$広告ごとに。 あるので$2^{2n}$サブセットの場合、このアプローチは非常に小さい場合でも完全に実行不可能です。$n$。 

重要な構造上の観察は、各広告が反対側の連続した間隔にのみ影響を与えるということです。 位置に 1 つの広告$i$間隔をカバーする$[i-d, i+d]$。 したがって、広告のあらゆる構成の効果は、各側の間隔の和集合によって完全に記述されます。 個々の広告からカフェへのインタラクションについて考えるのではなく、間隔の範囲と、広告が掲載されているためにどのカフェが除外されるかという観点から考えることができます。 

これは、それに沿った動的プログラミングの定式化を示唆しています。 左から右に進むにつれて、将来の意思決定に重要なのは、それぞれの側に掲載された最新の広告だけです。これにより、将来のポジションが現在カバーされているかどうかが決まります。 これにより、問題は指数関数的なサブセットからポジション上の構造化された状態遷移に軽減されます。 

両側で最後に選択された広告の位置を記憶しながら、回線のプレフィックス上の DP を維持します。 各インデックスで、広告を上部、下部、両方に配置するか、まったく配置しないかを決定し、それに応じて対象範囲を更新します。

 ## アルゴリズムのチュートリアル

 位置を左から右に処理し、両側の最新の広告配置を記述する DP 状態を維持します。 

### 1. DP 状態を定義する

 私たちは定義します$dp[i][j]$上側に配置された最後の広告が位置する位置まで処理した後に達成可能な最大スコアとして$i$、下側に配置された最後の広告が の位置にあります。$j$。 値 0 は、その側に「まだ広告が掲載されていない」ことを表します。 

これが機能する理由は、どの位置でもカバレッジが、遠くにある以前の広告ではなく、反対側の最も近い広告にのみ依存するためです。 

### 2. ある立場での報道を解釈する

 どの位置でも$x$、どこかの位置に下側の広告が存在する場合、上側のカフェはカバーされているとみなされます。$j$そのような$|x - j| \le d$。 この条件は、最新の関連広告のみに依存します。これは、まさに DP 状態に保存されているものです。 

同様に、下位のカフェは最後の上位側の広告のみに依存します。 

### 3. ポジションを段階的に処理する

 位置を左から右にスキャンします。 それぞれのポジションで$k$、広告を掲載するあらゆる可能性を考慮します。 

当社は、広告を掲載しないか、上のカフェに広告を掲載するか、下のカフェに広告を掲載するか、または両方に広告を掲載する場合があります。 それぞれの選択に応じて、最後の広告の状態が変更されます。 

所定の位置に広告を掲載する場合$k$のカフェ$k$すぐにブロックされるため、それ自体は何も貢献しません。 

### 4. 新たに影響を受けるポジションの貢献を追加

 ポジションごとに$k$、配置を決定する前に、上のカフェが$k$現在、最後の下部の広告で覆われており、下部のカフェが$k$最後の上部の広告で覆われています。 それらがカバーされている場合、広告を掲載することを選択しない限り、その重みが答えに寄与します。 

これにより、グローバルに正確さを維持しながら、ローカルに貢献を蓄積することができます。 

### 5. 移行

 州から$(i, j)$、位置での決定に対応する状態に遷移します。$k$。 各トランジションにより、最後の広告の位置が更新され、位置からの寄与が追加されます。$k$、対象範囲とブロックするかどうかによって異なります。 

この構造化された進化により、すべてのカフェが DP の進行で「確定」したとき、またはブロックされたときのいずれかに 1 回だけ考慮されることが保証されます。 

### なぜ効果があるのか

 重要な不変条件は、DP のどの時点でも、将来の報道範囲の決定に関連する唯一の情報は、各側の最も近い広告であるということです。 以前の広告は将来の順位に影響を与えるには遠すぎるため、将来の広告はまだ不明です。 これにより、グローバルな依存構造が、各側に 1 つずつ、2 つのスライディング影響ゾーンに縮小されます。 カバレッジは純粋にインターバルベースであり、独立したカフェ全体で加算されるため、DP 状態は最終スコアに影響を与える可能性のあるすべてのインタラクションを完全にキャプチャします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    # dp[i][j] = best result where last top ad is i, last bottom ad is j
    # we compress "no ad yet" as 0, and shift indices by +1
    dp = [[-10**18] * (n + 1) for _ in range(n + 1)]
    dp[0][0] = 0

    def covered(last, pos):
        return last != 0 and abs(last - pos) <= d

    for k in range(1, n + 1):
        ndp = [[-10**18] * (n + 1) for _ in range(n + 1)]

        for i in range(n + 1):
            for j in range(n + 1):
                cur = dp[i][j]
                if cur < 0:
                    continue

                top_cov = covered(j, k)
                bot_cov = covered(i, k)

                base_gain = 0
                if top_cov:
                    base_gain += a[k - 1]
                if bot_cov:
                    base_gain += b[k - 1]

                # 1) no ad at k
                ni, nj = i, j
                ndp[ni][nj] = max(ndp[ni][nj], cur + base_gain)

                # 2) ad on top at k
                ni, nj = k, j
                ndp[ni][nj] = max(ndp[ni][nj], cur + (base_gain if not top_cov else base_gain - a[k - 1]))

                # 3) ad on bottom at k
                ni, nj = i, k
                ndp[ni][nj] = max(ndp[ni][nj], cur + (base_gain if not bot_cov else base_gain - b[k - 1]))

                # 4) ads on both sides
                ni, nj = k, k
                gain = base_gain
                if top_cov:
                    gain -= a[k - 1]
                if bot_cov:
                    gain -= b[k - 1]
                ndp[ni][nj] = max(ndp[ni][nj], cur + gain)

        dp = ndp

    ans = 0
    for i in range(n + 1):
        for j in range(n + 1):
            ans = max(ans, dp[i][j])

    print(ans)

if __name__ == "__main__":
    solve()
```DP テーブルは、各側で最後に選択された広告の位置を追跡します。 すべてのステップで、距離制約を使用して、各カフェが現在反対側からアクティブな広告にさらされているかどうかを計算します。 その後、そのカフェに新しい広告を掲載することでブロックされない場合にのみ、その投稿を追加します。 

4 つのトランジションは、各位置で考えられる決定に正確に対応しており、広告配置のすべての構成が確実に表現されます。 

重要な点は、カフェに広告を掲載するときにカフェの自重を差し引くことです。訪問者は、たとえ範囲内にいたとしても決して貢献しないからです。

 ## 特殊なケース

 いつ$d = 0$、各広告は真向かいのカフェにのみ影響します。 カバレッジ チェックがインデックスの等価性まで低下し、間隔の伝播が発生しないため、DP は依然として正しく機能します。 

いつ$d \ge n-1$、どの広告も反対側全体をカバーする可能性があります。 この場合、最適な戦略は、地元への貢献が過度に妨げられることを避けるために、価値の高い少数のカフェを選択することになります。 広告を掲載するとローカルの利益が即座に失われるため、DP はこのトレードオフを自然に捉えます。 

すべての値が等しい場合、適切に配置された 1 つの広告によってすでに達成されている範囲を超えてカバレッジを増やすことなく、追加の広告によってローカル貢献度が減少するため、ソリューションは広告の重複配置を回避します。
