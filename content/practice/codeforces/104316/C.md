 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、行がすべてその文字列の巡回シフトである正方行列を構築します。 行 0 は文字列そのもので、行 1 は 1 位置右にシフトされ、行 2 は 2 位置右にシフトされ、行 n から 1 を引くまで同様に続きます。 

この構造により、非常に構造化されたマトリックスが生成されます。各行には、回転されただけの同じ文字が含まれます。 タスクは、四角形内のすべてのセルが 1 になるように、この行列内で軸が整列した最大の四角形を見つけることです。 

ここでの四角形は、連続した行のブロックと連続した列のブロックです。 したがって、完全に 1 で構成され、その面積を最大化する部分行列を探します。 

制約が十分に大きいため、n × n 行列を明示的に構築しようとするソリューションは直ちに実行不可能になります。 すべてのテスト ケースの合計の長さが 200 万に達すると、それを保存するだけでもコストがかかりすぎます。 このため、グリッドを具体化するのではなく、循環シフトの構造を直接推論する必要があります。 

重要なエッジ ケースは、文字列に含まれる文字列が非常に少ない場合、またはまったく含まれない場合に発生します。 1 がない場合、長方形は存在できないため、答えはゼロになります。 文字列がすべて 1 の場合、行列全体が 1 で埋められ、答えは n 倍の n になります。 

複数のブロックを形成する場合、より微妙な状況が発生します。 たとえば、次のような文字列では`110011`、最長の連続ブロックは長さ 2 ですが、そのようなブロックは複数あります。 1 の合計数だけを数えるという単純な考えでは、1 はシフト全体でグローバルに調整されていないため、答えが誤って過大評価されてしまいます。 

素朴な考え方によるもう 1 つの失敗例は、各行が独立して寄与していると仮定することです。 各行に 1 の長いセグメントがある場合でも、巡回シフトによりそれらのセグメントが異なる行にまたがって整列しない可能性があり、これがまさに問題を自明ではないものにしています。 

## アプローチ

 ブルートフォース手法では、完全な n × n 行列を構築し、バイナリ行列アルゴリズムで最大の四角形を実行します。 行列の構築にはすでに O(n²) のコストがかかりますが、テスト全体で合計 2・10⁶ までの n については不可能です。 n = 200000 の 1 回のテストでも、メモリの制限をはるかに超えます。 

たとえ明示的な構築を避けたとしても、すべての O(n²) 個の長方形を評価する必要がありますが、これは根本的に大きすぎます。 

重要な観察は、循環シフトが構造にどのような影響を与えるかを理解することから得られます。 すべての行は回転するまで同一です。つまり、1 のパターンは保持されますが、移動されます。 これは、適切な長方形はグリッド内の任意の局所構造によって作成されるのではなく、一貫したオフセットに沿った単一パターンの繰り返しの位置合わせによって作成されることを意味します。 

重要な単純化は、制限要因が元の巡回文字列内の 1 の最も長く連続するブロックであることです。 循環的な意味での連続するものの最大長を識別し、それを L と呼ぶ場合、それらのブロックを連続したシフトにわたって整列させることによって、行列内に常に L × L の正方形を構築できます。 同時に、L より長い行セグメントまたは列セグメントには、存在しない文字列のシフトされたバージョンで 1 が長く続く必要があるため、どの次元でも L を超える四角形は存在できません。 

これにより、問題は文字列内の 1 の最長の循環ランを見つけてその 2 乗を返すという問題に縮小されます。

 ## アルゴリズムのチュートリアル

 ## 1. 循環処理用に文字列を拡張します。 

文字列をそれ自体と連結して、周期的な動作を線形にシミュレートします。 これにより、元の文字列のラップアラウンド セグメントが通常の部分文字列として表示されるようになります。 

このステップが必要なのは、最長の 1 が文字列の終わりに回り込む可能性があるためです。 

## 2. 2 倍になった文字列内の 1 の最も長い連続セグメントを見つけます。 

連続する文字列を追跡しながら、2 倍になった文字列をスキャンしますが、循環実行は元の長さを超えることができないため、長さ n までの実行のみを考慮します。 

ゼロに遭遇するたびに、現在のランレングスをリセットします。 検出された最大値は、最長の周期実行 L です。 

この値は、適切な回転後に行列の任意の行に一貫して配置できる 1 のブロックの最大長を表します。 

## 3. 正方形形成の推論

 L が既知になると、どの行でも、ある巡回位置に L 個の連続セグメントが存在することがわかります。 行は巡回シフトであるため、これらのセグメントを連続する L 行にわたって整列させて、一貫した列セット内で重複するようにすることができます。 

これにより、L × L のすべて 1 の長方形が生成されます。 

## 4. 出力 L の 2 乗

 答えは、この最大正方形の面積です。 

### なぜ効果があるのか

 各行は同じバイナリ パターンの回転であるため、1 の長方形を維持する唯一の方法は、選択した行ごとに 1 の連続内に完全に収まる列間隔を選択することです。 巡回アライメントにおけるそのようなランの最大値は、正確に L です。どのアライメントにおいても、連続する行が L 個を超えることはできません。そのため、有効な長方形のどの次元も L を超えることはできません。最大のランをアライメントすることで L × L ブロックを構築できるため、L² は達成可能かつ最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)
        if n == 0:
            print(0)
            continue
        
        # double string for circular handling
        ss = s + s
        
        best = 0
        cur = 0
        
        # we only need to scan at most 2n characters
        for i, ch in enumerate(ss):
            if ch == '1':
                cur += 1
                # cap because cyclic window cannot exceed n
                if cur > n:
                    cur = n
            else:
                cur = 0
            best = max(best, cur)
        
        print(best * best)

if __name__ == "__main__":
    solve()
```この解決策は、二重化された文字列をスキャンして周期的な実行をキャプチャすることに依存しています。 n のキャップは重要です。これがないと、2 倍の文字列内の「111...111」のような実行が有効な巡回解釈を誤って超える可能性があるからです。 

最後の二乗ステップは、行と列にわたって最大に位置合わせされたブロックを形成することに直接対応します。 

## 実用的な例

 ### 例 1

 検討してください`s = 00111`。 

私たちは構築します`s + s = 0011100111`。 

1 の実行をスキャンします。 

- 最も長く実行されるものは`111`したがって、L = 3です。 

9を出力します。 

これは、1 が表示される 3 つの連続する列を選択し、それらを適切にシフトされた 3 つの行にわたって配置することに対応します。 

| ポジション | シャア | 現在の実行 | ベスト |
 | --- | --- | --- | --- |
 | 0 | 0 | 0 | 0 |
 | 1 | 0 | 0 | 0 |
 | 2 | 1 | 1 | 1 |
 | 3 | 1 | 2 | 2 |
 | 4 | 1 | 3 | 3 |
 | 5 | 0 | 0 | 3 |

 トレースは、最大実行が 3 でどのように安定するかを示しています。 

### 例 2

 検討してください`s = 10101`。 

それから`s + s = 1010110101`。 

1 つは孤立しているため、連続する最長の値は 1 です。 

したがって、L = 1 となり、答えは 1 になります。 

これは、多数の長方形があっても、隣接性がないため、より大きな長方形を形成できないことを示しています。

 ## 特殊なケース

 ゼロのみを含む文字列は有効な実行を生成しないため、スキャンによって現在のカウンターが増加することはなく、最適な値はゼロのままです。 アルゴリズムは正しく 0 を出力し、1 からなる四角形は存在できないという事実と一致します。 

境界を越える実行をラップする文字列。たとえば、`1100011`、文字列を 2 倍にすることで正しく処理されます。 ランニング`11`最後に接続します`11`2 倍化された表現の先頭で、正しい巡回最大値が生成されます。 

実装では完全に 1 の文字列は n でキャップされ、倍増表現によって実際の循環構造よりも長い実行が誤って生成されないようにします。 これにより、L = n と n × n の長方形が得られます。
