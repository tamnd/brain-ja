 ## 解決策
 ## 問題の理解

 いくつかの独立したシナリオが与えられています。 各シナリオでは、n 個の店が順番に訪問され、リンゴの種類は m 個あります。 各ショップには、いくつかの種類のリンゴのサブセットが含まれている場合があります。 ダニアは店を訪れると、そこで売られているすべての種類のリンゴを 1 つだけ取り出し、バックパックに入れます。 

面白いのは、バックパックにはキャンセルルールがあるということです。 店を出た後、同じ種類のリンゴが 2 つバックパックに入ってしまうと、バックパック内のすべてのリンゴがすぐに消えてしまいます。 これは、これまでに各型が追加された回数のパリティのみが重要であり、型が 2 回出現した瞬間にすべてがゼロにリセットされることを意味します。 

不明なお店もございます。 これらのショップについては、空にするか、リンゴの種類のサブセットを含めるかなど、その内容を任意に選択できます。 私たちの目標は、最後の店を訪れた後にバックパックに残るリンゴの数を最大にする方法で、これらの未知の店を選択することです。 

各シナリオの出力は、未知の店に最適な選択肢が与えられた場合、n 個の店すべての後のリンゴの最終的な最大数になります。 

この制約は、すべてのテスト ケースにわたるショップ エントリの総数が最大 200,000 であることを意味します。これにより、未知のショップのすべてのサブセットを列挙したり、選択肢を徹底的にシミュレートしようとするソリューションは除外されます。 テスト ケースごとに線形または線形に近いアプローチが必要で、理想的には各ショップを O(1) または償却 O(1) の作業で 1 回処理します。 

未知の各ショップを個別に最適化できると想定した単純なアプローチでは、微妙な失敗例が発生します。 たとえば、ローカルで衝突を回避しようと貪欲に試みても、将来的にリセットが強制される可能性があります。 型が繰り返されると、それがいつ発生したかに関係なく、すべてが失われるため、相互作用はグローバルです。 

もう 1 つの微妙なケースは、すべての店舗が不明な場合です。 単純な考えでは、あらゆる場所にすべてのタイプを含めることが考えられますが、そうすると 2 番目のショップの後にはすぐに崩壊が余儀なくされます。 代わりに最適な戦略は、衝突が発生するタイミングを正確に制御することです。理想的には、繰り返されるタイプをできるだけ長く遅らせるか、繰り返しを完全に回避します。 

## アプローチ

 未知のショップの柔軟性を無視すると、プロセスは決定論的になります。 各ショップをシミュレートし、アクティブなリンゴの種類のセットまたはビットマスクを維持し、重複が出現するたびにキャンセル ルールを適用するだけです。 これは O(合計リンゴ) 個で機能しますが、未知の店を選択するのには役立ちません。 

難しいのは、未知のショップではサブセットを完全に制御できるものの、キャンセル ルールにより最初の繰り返しですべてが破棄されることです。 これは、最終的な構築のどこかに 2 回出現するタイプは、蓄積されたすべての進行状況を消去するため、本質的に有害であることを示唆しています。 

重要な観察は、成功した構築では、実際に「アクティブ化」することを選択したすべてのショップで、各種類のリンゴが最大 1 回しか表示されないということです。 選択した 2 つの異なるショップでタイプが 2 回出現した場合、2 回目の出現以降は構築全体が役に立たなくなるため、最終的な答えはその瞬間にゼロに崩壊します。 

これにより、問題は、選択されたショップ全体でリンゴの種類が 2 回使用されないようにショップ オカレンスのセットを選択するという問題に軽減されます。 各ショップはタイプのセットを提供するため、できるだけ多くのショップを含めたいと考えていますが、使用されるタイプの点でタイプ セットがバラバラである場合に限ります。 未知のショップは任意に作成できるため、意図的に新しいタイプを導入しない限り、競合を避けるためにいつでも調整できます。

最適な戦略はショップに対して貪欲になります。どのタイプがすでに使用されているかを維持します。 各ショップについて、それがわかっている場合は、その固定セットを考慮する必要があります。 未知の場合は、そのセットを最適に選択できます。答えを増やしたい場合は、新しい未使用の型を 1 つだけ選択し、そうでない場合は空のままにしておく必要があります。 未知のショップで複数の新しいタイプを選択しようとしても無意味です。複数の新鮮なリソースを消費することになりますが、それでも連続して 1 つのショップ ステップしか提供されないからです。 

したがって、このプロセスは、m 個のタイプをすべて使い果たすか、強制的な競合が発生する前に、未使用のタイプを少なくとも 1 つ提供できるショップの数を追跡することに帰着します。 

より洗練された解釈は、重要なのはタイムライン全体で型の「最初の出現」を何回導入できるかだけであるということです。 これまでに出現したことのないタイプを割り当てるたびに、強制的な繰り返しによって以前に崩壊が引き起こされない限り、最終的なカウントでちょうど 1 つのリンゴが得られます。 崩壊は壊滅的なものであるため、どのタイプも 2 度出現することは望ましくありません。 

したがって、答えは、達成できる個別のリンゴの導入の最大数になります。これは、m と、競合することなく新しいタイプを導入できるショップ スロットの数によって制限されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (不明なショップのサブセットを選択) | 指数 | O(m) | 遅すぎる |
 | 最適 (最初の出現を貪欲に追跡) | O(n + 合計 ki) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. リンゴの種類が加工ショップにすでに導入されているかどうかを追跡するブール配列 used[1..m] を維持します。 これは、再度追加するとグローバル折りたたみルールが直ちにトリガーされるかどうかを表します。 
2. カウンタの答えを 0 に初期化して保持します。これは、リセットをトリガーせずに最後にバックパック内に安全に存在できるリンゴの数を表します。 
3. 1 から n までのショップを順番に繰り返します。 各ショップについて、既知のタイプのリストを調べます。 
4. ショップが不明 (ki = 0) の場合、新しい種類のリンゴが存在する場合はそれを紹介する機会として扱います。 まだ使用されていないタイプがないかスキャンします。 1 つ見つかった場合は、それを使用済みとしてマークし、回答を 1 つ増やします。複数のタイプを導入しても、最終的な安全カウントを増やすことなく、将来避けられない繰り返しが発生する危険性があるだけであるため、複数のタイプを導入しません。 
5. 販売店がわかっている場合は、その種類を検査します。 このショップのいずれかのタイプがすでに中古としてマークされている場合、このショップを完全に導入すると衝突が繰り返され、すべての進歩が台無しになります。 そのような状況では、最良の戦略は、このショップからリンゴを取得しないで、実質的に貢献度 0 にすることです。そうでない場合、そのすべてのタイプが未使用の場合は、すべてのリンゴを安全に取得できます。各タイプを使用済みとしてマークし、ショップのサイズに応じて答えを増やします。 
6. すべての店舗が処理されるまでこのプロセスを継続し、最大数の安全な紹介を蓄積します。 

重要な点は、型の再利用を決して許可しないことです。 型が一度使用されると、それを将来含めることは永久に禁止されます。 

### なぜ効果があるのか

 どの時点でも、バックパック履歴にタイプが 2 回出現すると、すべてがリセットされ、以前のすべての利益は無関係になります。 これにより、最終的に残るリンゴを最大化することを目的とした有効な構築では、選択された追加シーケンス全体にわたってすべてのタイプが最大 1 回グローバルに導入されることが保証されます。 

アルゴリズムはこの不変条件を厳密に維持します。つまり、型は初めて導入されたときに使用済みとしてマークされ、再度導入されることはありません。 この不変条件に違反するショップは、部分的に無視されるかスキップされます。 未知のショップは自由に選択できるため、追加のタイプは冗長であるか、将来の競合の観点から直ちに危険であるため、多くても 1 つの新しいタイプに制限しても最適性が失われることはありません。

したがって、アルゴリズムは常に、非反復型導入の最大セットを時系列順に構築します。これは、可能な最終的に生き残るリンゴの最大数に直接対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        used = [False] * (m + 1)
        ans = 0

        for _ in range(n):
            arr = list(map(int, input().split()))
            k = arr[0]
            if k == 0:
                # unknown shop: try to introduce one new type if possible
                added = False
                for x in range(1, m + 1):
                    if not used[x]:
                        used[x] = True
                        ans += 1
                        added = True
                        break
                continue

            types = arr[1:]
            conflict = False
            for x in types:
                if used[x]:
                    conflict = True
                    break

            if conflict:
                continue

            for x in types:
                if not used[x]:
                    used[x] = True
                    ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、各型が一度だけ貢献できるという不変条件に従います。 既知のショップについては、まず型を再利用することでルールに違反するかどうかを確認します。 安全な場合にのみ、その店にあるすべての新鮮な種類を消費します。 未知のお店のために、貪欲に新しいタイプを1つだけ導入します。 

微妙な点は、未知のショップが m にわたって線形にスキャンして自由なタイプを見つけることですが、これは m が小さい場合にのみ許容されます。 より厳密な最適化設定では、これは次の未使用の型または優先順位構造体へのポインターに置き換えられます。

 ## 特殊なケース

 すべてのショップが不明な場合、アルゴリズムは、タイプがなくなるまで、ショップごとに 1 つの新しいタイプを貪欲に割り当てます。 各タイプは 1 回しか使用できないため、答えは m によって制限され、アルゴリズムは競合を引き起こすことなく自然にその値で飽和します。 

既知のショップに以前に使用された型が含まれている場合、アルゴリズムはそれを完全にスキップします。 これは、これを含めると繰り返しが強制され、最適性が破壊されるという事実をモデル化しています。 重複が存在すると、既知のショップ内の部分選択は重複を回避できないため、スキップは安全です。 

ショップが空か不明で、未使用のタイプが残っていない場合、何も貢献しません。 これは、使用可能な個別のタイプをすべて使い果たした後は、繰り返し禁止制約に違反しない限り、それ以上のゲインは不可能であることを正確に捉えています。
