 ## 解決策
 ## 問題の理解

 非負の整数の配列が与えられます。 実行できる操作は 1 つだけです。配列の連続したセグメントを選択し、そのセグメント内のすべての要素を、選択した 1 つの非負の値で上書きします。 

目的は、この操作の後に配列の mex をちょうど 1 だけ増やすことができるかどうかを判断することです。 mex は、配列に現れない最小の非負の整数です。 

したがって、初期 mex が m の場合、0 から m−1 までのすべての数値が少なくとも 1 回出現する必要があり、m はどこにも出現しません。 演算後、mex が m+1 になるようにします。これは、2 つのことが同時に成立する必要があることを意味します。0 から m までのすべての数値が出現する必要があることと、m+1 が存在しなければならないことです。 

この操作は、1 つの連続セグメントを 1 つの値で上書きするだけであるため、非常に制限的です。 これは、同じ間隔構造内にない限り、異なる場所にある複数の欠損値を個別に修正できないことを意味します。 

制約は大きく、すべてのテスト ケースで配列の合計長は最大 200,000 です。 これにより、テスト ソリューションごとに O(n) が強制されます。 二次関数は、テスト ケースごとであっても、すぐに失敗します。 

mex が 0 の場合、微妙なエッジ ケースが発生します。この場合、最初は 0 が欠落しているため、その後 1 が欠落したままであることを確認しながら 0 を作成する必要があります。 たとえば、配列が [2,2,2] の場合、mex は 0 です。任意のセグメントを 0 に設定すると、配列には 0 が含まれますが、1 は含まれないため、答えは「はい」になります。 単純なアプローチでは、欠損値の周囲の構造を保持する必要があると誤って考える可能性がありますが、ここでは配列全体を安全に上書きできます。 

もう 1 つの注意が必要な状況は、mex が正であるにもかかわらず、必要な数 m+1 が複数回出現する場合です。 m を修正しようとして誤って m+1 を導入すると失敗するため、選択したセグメントは、その外部への値の制御されない伝播を回避する必要があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。配列の mex m を計算し、考えられるすべてのセグメント [l, r] とすべての考えられる値 k を試し、上書きをシミュレートし、mex を再計算し、それが m+1 になるかどうかを確認します。 これはすぐに実行不可能になります。 原則として k には O(n^2) 個のセグメントと最大 O(n) 個の選択肢があり、毎回 mex を再計算すると O(n) となり、単純な解釈では O(n^4) になるか、最適化を行ってもせいぜい O(n^3) になります。 mex の再計算を O(1) に減らすことさえ、任意の更新では現実的ではありません。 

重要な観察は、mex は小さな整数の有無のみに依存するということです。 mex を m から m+1 に増やすには、m が最終配列に現れる一方、m+1 が完全に消えることを確認する必要があります。 制御された方法で「導入」できる唯一の数値は、セグメント内で選択された k であり、外側のすべては変更されません。 

したがって、唯一の意味のある候補は、欠損値 m を修正する操作を使用することです。 最初は m が存在しないため、それを表示させる唯一の方法は、一部のセグメントを m に設定することです。 ただし、そうすると、そのセグメント内の他の必要な値が破壊される可能性があります。 重要な構造は、各値 x < m について、少なくとも 1 つの出現が選択したセグメントの外側に残ることを確認する必要があるということです。そうしないと、mex が m を下回り、直ちに失敗します。 

これにより、問題は、すべての値 0..m−1 がセグメントの外側に少なくとも 1 つ出現するように、m で上書きできるセグメントを見つけることになります。さらに、セグメントはどこにも m+1 を強制的に出現させてはなりません (m+1 ではなく m のみを記述するので、これはすでに安全です)。 

したがって、0..m−1 内の各値の最後と最初の出現位置を考慮するだけで済みます。 セグメントは、必要な値のすべての出現を完全にカバーしていない場合に有効です。 同様に、すべての x < m について、セグメントでは少なくとも 1 つの x の出現を除外する必要があります。

各 x について間隔 [first[x], last[x]] を計算できます。 セグメント [l, r] は、すべての x < m について、first[x] ≥ l および last[x] ≤ r が同時に成立するわけではない場合に有効です。 この状態は、これらの間隔のうちどれだけが完全にカバーされているかを追跡することで効率的にチェックできます。 

条件をスイープに変換できます。r を展開するときに、完全にカバーされる値の数を維持し、すべてがカバーされないように l を選択できるようにします。 これにより、テスト ケースごとに O(n) 個のソリューションが得られます。

 ## アルゴリズムのチュートリアル

 1. 出現する値をマークして、配列の mex m を計算します。 すべての推論はどの数値を保存する必要があるかによって決まるため、これが必要です。 
2. m が 0 の場合は、すぐに Yes を返します。 0 は欠落しているため、任意のセグメントを選択して 0 に設定することで、いつでもこれを導入できます。1 がすでに存在していないか、明示的に存在しない限り存在しないため、 mex は 1 になります。 
3. 0 から m-1 までのすべての値の最初と最後の出現を記録します。 mex はこれらの値によってのみ定義されるため、これらの値のみを考慮します。 
4. セグメント [l, r] が、x < m の出現をすべて完全にカバーする場合は無効であることに注意してください。その場合、操作後に x が配列から消えるからです。 
5. 各 x < m について、その出現範囲を間隔 [first[x], last[x]] として表します。 私たちの目標は、そのようなすべてのスパンを同時に完全には含まないセグメントを選択することです。 
6. すべての x < m の少なくとも 1 つの出現を完全にカバーすることを避けるセグメントを検索します。 これは、これらの完全な出現間隔のいずれのスーパーセットでもないセグメントを集合的に見つけることと同等です。 
7. 各 x が少なくとも 1 つ外側に残るようにセグメント境界を配置して、実現可能性を確認します。 そのようなセグメントが存在する場合は、必要な値を破壊することなく m を導入して、それを m で安全に上書きできます。 

### なぜ効果があるのか

 このアルゴリズムは、極端な発生を使用して、すべての値 x < m の生存条件をエンコードします。 値が失われるのは、すべての出現が選択したセグメント内にある場合のみです。これは、まさにセグメントに出現間隔全体が含まれている場合に発生します。 有効なセグメントにそのようなすべての間隔が同時に含まれていないことを確認すると、選択された値 m が必要な場所に正確に導入されながら、必要なすべての値が少なくとも 1 回は存続することが保証されます。 これにより、mex m+1 を定義するすべての制約が保存され、より小さい値が誤って失われることが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        seen = set(a)
        m = 0
        while m in seen:
            m += 1
        
        if m == 0:
            out.append("Yes")
            continue
        
        first = {}
        last = {}
        for i, x in enumerate(a):
            if 0 <= x < m:
                if x not in first:
                    first[x] = i
                last[x] = i
        
        # if any value < m is missing entirely, mex wouldn't be m
        # so all 0..m-1 exist
        
        intervals = []
        for x in range(m):
            intervals.append((first[x], last[x]))
        
        intervals.sort()
        
        # We try to see if there exists a segment [l,r]
        # such that for every x, not (first[x] >= l and last[x] <= r)
        # equivalently, segment is not covering all occurrences of all values
        
        # key simplification:
        # if we choose l as min first[x], we only need to ensure
        # we don't fully cover every interval simultaneously.
        
        min_l = min(l for l, r in intervals)
        max_r = max(r for l, r in intervals)
        
        # If there is a value whose interval spans the whole range,
        # then any segment covering that range kills it.
        # We need at least one value that "sticks out" on each side.
        
        leftmost = min_l
        rightmost = max_r
        
        # We check if there exists a split point where some interval
        # starts before it and ends after it, enabling a valid cut.
        
        # simpler condition: if m > 1 and all intervals overlap in a single core region,
        # it's impossible to avoid destroying some value when inserting m.
        
        # compute max of left ends except last, min of right ends except first
        max_left = max(first[x] for x in range(m))
        min_right = min(last[x] for x in range(m))
        
        if max_left < min_right:
            out.append("Yes")
        else:
            out.append("No")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```mex は値が大きくても構造が小さいため、コードは集合から直接 mex を計算することから始まります。 m を特定した後、自明な m = 0 の場合を直ちに処理します。 

m 未満の値の場合、最初と最後の出現を計算し、値がセグメント全体のカバーによっていつ破棄されるかを正確にエンコードします。 最後の条件は、安全なセグメントの選択を可能にする空ではない交差構造がこれらの間隔の間に存在するかどうかに実現可能性チェックを縮小します。 表現`max(first) < min(last)`少なくとも 1 つの出現ウィンドウの外側に点が存在するかどうかをキャプチャし、必要なすべての値を同時に削除しないセグメントを有効にします。 

よくある実装の落とし穴は、「値がセグメント内に表示される」ことと「値が完全に削除される」ことを混同することです。 すべての出現を完全に包含する場合のみ値が削除されるため、単一の出現のみを追跡するだけでは不十分です。

 ## 特殊なケース

 mex が 0 の場合、配列には 0 は含まれません。セグメントを上書きすることで常に 0 を導入できるため、アルゴリズムはすぐに Yes を返します。これは現実と一致します。 配列全体の選択を妨げる制約はなく、保存する必要のある値もありません。 

すべての値が厳密にインターリーブされ、すべての候補セグメントが少なくとも 1 つの必要な値を完全に削除する場合、条件 max(first) < min(last) は失敗します。 その状況では、欠落している mex 値を導入しようとするセグメントは、既存の必要な数値の 1 つを完全に破壊し、mex の増加を妨げます。 

出現間隔が部分的にのみ重なるように値が分散している場合、どの間隔も完全にカバーせずにセグメントを選択できる「ギャップ」が存在します。 このギャップはまさに不等式によって検出されるものであり、欠落している mex 値を安全に導入するために必要な構成的自由度に対応します。
