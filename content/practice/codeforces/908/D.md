 ## 問題の理解

 一度に 1 文字ずつ文字列を構築します。 各ステップで追加します`'a'`確率的に$$\frac{p_a}{p_a+p_b}$$そして追加します`'b'`確率的に$$\frac{p_b}{p_a+p_b}.$$固定文字列の場合、サブシーケンスの数は次のとおりです。`"ab"`説明するのは簡単です。 毎`'b'`できるだけ多くのことに貢献します`"ab"`後続もあり`'a'`その前の文字。 現在ある場合$i$手紙`'a'`、次に 1 つ追加します`'b'`の数が増えます`"ab"`正確にサブシーケンス$i$。 

プロセスは、合計数に達するとすぐに停止します。`"ab"`サブシーケンスは少なくとも到達します$k$。 最終的な予想数を尋ねられます。`"ab"`後続。 期待値は有理数であるため、それを剰余として出力します。$10^9+7$。 

制約$k\le1000$が重要な観察です。 二次動的計画法テーブルは次のようになります。$10^6$状態は 2 秒以内に完全に管理できます。 文字列を列挙したり、ランダムなプロセスをシミュレートしようとするアプローチは、可能性のあるシーケンスの数が長さに応じて指数関数的に増加するため、絶望的です。 

多くの場合、1 つの微妙なケースが発生します。`'a'`文字は最初の前に収集されます`'b'`。 たとえば、```
1 1000000 1
```多数の`'a'`文字は前に蓄積されます`'b'`が表示されます。 一度最初の`'b'`到着、の数`"ab"`サブシーケンスははるかに超えてジャンプする可能性があります$k$。 常に正確に停止すると仮定した DP$k$それは不正確でしょう。 

もう一つ厄介な状況が発生するのは、$i+j\ge k$、 どこ$i$の数です`'a'`キャラクターと$j$現在の数です`"ab"`後続。 もう一つ終わったら`'b'`、新しい合計が次になるため、プロセスはすぐに終了します。$i+j\ge k$。 この移行を個別に処理することが重要です。 

例えば、```
1 1 1
```答えは 2 です。シーケンスは次の時点で終了する可能性があります。`"ab"`、となるかもしれませんが、`"aab"`、`"aaab"`、 等々。 オーバーシュートの可能性があるため、期待値は 1 を超えます。 

## アプローチ

 ブルートフォース手法では、考えられるすべての文字列をその確率とともに生成し、文字列の数が増えるたびに停止します。`"ab"`サブシーケンスが到達する$k$。 期待値は合計して得られます。$$\Pr(\text{string})\times(\text{final number of }ab).$$これは数学的には正しいですが、実際には役に立ちません。 適度な長さの文字列でも、すでに指数関数的に多くの可能性が生まれています。 

重要な観察は、重要な量は 2 つだけであるということです。 

最初の数量は次の数です。`'a'`これまで見てきたキャラクターたち。 等しいと仮定します$i$。 

2 番目の数量は現在の数です。`"ab"`後続、言う$j$。 

文字の順序については他に何も関係ありません。 別のものを追加するたびに、`'a'`の状態になります。$(i+1,j)$。 を追加するたびに、`'b'`、の数`"ab"`サブシーケンスは次のように増加します$i$、生産状態$(i,j+i)$。 

これは当然、状態に関する動的プログラミングにつながります。$(i,j)$。 以来$j<k$、くらいしかありません。$k^2$関連する州。 

さらなる最適化により、$i\le k$。 もし$i\ge k$、次に 1 つ追加します`'b'`すぐにプロセスを終了します。 より大きな値を保存する代わりに、$i$、最初のステップの前に予想される追加ステップ数を直接説明できます。`'b'`が表示されます。 これにより、無限に多くの状態が削除されます。

 ## アルゴリズムのチュートリアル

 1.確率を法的に正規化する$10^9+7$。 

させて$$A=\frac{p_a}{p_a+p_b},\qquad B=\frac{p_b}{p_a+p_b}.$$2. 定義する$dp[i][j]$の状態から始まる予想される最終的な答えとして$i$手紙`'a'`そして現在$j$サブシーケンス`"ab"`。 

のある州のみ$j<k$が必要です。 
3. プロセス状態の逆順$i+j$。 

より大きな値$i+j$はさらに大きな値にのみ依存するため、逆走査では、必要なすべての状態がすでに計算されていることを保証します。 
4. もし$i+j\ge k$、もう一つ`'b'`プロセスを終了します。 

その前に`'b'`到着、追加でいくつか`'a'`の文字が表示される場合があります。 予想される追加枚数`'a'`最初の前の文字`'b'`は$$\frac{A}{B}.$$したがって、予想される数は、`'a'`終了時の文字数`'b'`等しいように見える$$i+\frac{A}{B}.$$最後の部分を追加すると`'b'`はこの金額に貢献するため、答えは次のようになります。$$j+i+\frac{A}{B}+1.$$5. それ以外の場合は、トランジションが 1 つ追加されます。`'a'`そしてもう一人は付け加えます`'b'`。 

確率で$A$の状態になります。$(i+1,j)$。 

確率で$B$の状態になります。$(i,j+i)$。 
6. 期待方程式を整理すると次のようになります。$$dp[i][j] = A\cdot dp[i+1][j] + B\cdot dp[i][j+i].$$1. 出力$dp[1][0]$。 

最初は、すでに仮想が 1 つあると想像できます。`'a'`。 この標準的なトリックで厄介な状態が解消されます$i=0$、ここで追加`'b'`何も変わりません。 

### なぜ効果があるのか

 州$(i,j)$将来に必要な情報が正確に含まれています。 同じ数を持つ任意の 2 つの文字列`'a'`文字と同じ数`"ab"`その時点以降、サブシーケンスは同じように動作します。 

再帰方程式は、次の文字の条件付けから直接得られます。 考えられるすべての継続はその確率でカウントされ、最終状態は正確に予想される寄与に置き換えられます。 逆順序では、依存状態がすでに既知であることが保証されるため、すべての状態が正しい期待値を受け取ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

k, pa, pb = map(int, input().split())

inv_sum = pow(pa + pb, MOD - 2, MOD)
A = pa * inv_sum % MOD
B = pb * inv_sum % MOD
inv_B = pow(B, MOD - 2, MOD)

dp = [[0] * (k + 1) for _ in range(k + 2)]

for s in range(2 * k - 1, -1, -1):
    for i in range(min(k, s), 1 - 1, -1):
        j = s - i
        if j < 0 or j >= k:
            continue

        if i + j >= k:
            dp[i][j] = (i + j + 1) % MOD
            dp[i][j] = (dp[i][j] + A * inv_B) % MOD
        else:
            dp[i][j] = (
                A * dp[i + 1][j] +
                B * dp[i][j + i]
            ) % MOD

print(dp[1][0])
```最初のステップでは、確率をモジュール数に変換します。 除算は逆モジュラーを使用して実装されます。 

テーブルには、すべての州の予想される回答が保存されます$(i,j)$。 逆走査$i+j$状態を計算するときに、両方の後続関数がすでに利用可能であることを保証します。 

条件`i + j >= k`次の状態を表します`'b'`必然的にプロセスが終了します。 用語`A * inv_B`等しい$$\frac{A}{B},$$これは予想される追加の数です`'a'`最初の前の文字`'b'`。 

移行```
A * dp[i + 1][j] + B * dp[i][j + i]
```それは単なる完全期待の法則です。 

最も一般的な間違いは、終了することを忘れることです。`'b'`それ自体がもう 1 つのバッチに貢献します$i$後続。 もう 1 つの頻繁なエラーは、任意に大きな値を保存しようとすることです。$i$、それは無限に多くの状態をもたらします。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    k, pa, pb = map(int, input().split())

    inv_sum = pow(pa + pb, MOD - 2, MOD)
    A = pa * inv_sum % MOD
    B = pb * inv_sum % MOD
    inv_B = pow(B, MOD - 2, MOD)

    dp = [[0] * (k + 1) for _ in range(k + 2)]

    for s in range(2 * k - 1, -1, -1):
        for i in range(min(k, s), -1, -1):
            j = s - i
            if j < 0 or j >= k:
                continue

            if i + j >= k:
                dp[i][j] = (i + j + 1 + A * inv_B) % MOD
            else:
                dp[i][j] = (
                    A * dp[i + 1][j] +
                    B * dp[i][j + i]
                ) % MOD

    return str(dp[1][0])

# provided sample
assert run("1 1 1\n") == "2", "sample 1"

# minimum input
assert run("1 5 5\n") == "2", "minimum case"

# highly biased toward a
run("1 1000000 1\n")

# highly biased toward b
run("1 1 1000000\n")

# boundary k=1000
run("1000 1 1\n")
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1 1`|`2`| サンプルケース |
 |`1 5 5`|`2`| k の最小値 |
 |`1 1000000 1`| 大きな値 | のロングラン`'a'`|
 |`1 1 1000000`| 1 に近い | 頻繁`'b'`|
 |`1000 1 1`| 有効な出力 | 最大状態数 |
