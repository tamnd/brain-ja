 ## 問題の理解

 非常に大きな整数が与えられました$X$、10 進数で最大 700 桁になる可能性があります。 この数値はメモリ内で標準の整数として扱えるものではないため、解決策はその数値表現を直接処理する必要があります。 

For any positive integer$n$、変換を定義します$S(n)$それは次の数字を取ります$n$、それらを降順でない順序で並べ替え、結果を数値として再度解釈します。 結果を整数として解釈する場合、先行ゼロは自然に破棄されますが、桁のマルチセットに影響を与えるため、ソート時には依然として重要です。 

タスクはすべての値の合計を計算することです$S(i)$すべての整数に対して$i$から$1$に$X$、モジュロを取った$10^9 + 7$。 

重要な難点は、$X$は非常に大きいため、次の値までのすべての数値を反復処理することはできません。$X$。 1000万でも機能は$S(i)$自明ではない。 10^{700} の場合、ブルート フォースは不可能です。 

この制約により、数値ごとの処理が即座に除外されます。 範囲にわたる線形スキャンでも意味がありません。 唯一の実行可能なアプローチは、個々の整数ではなく桁構造によって寄与を集計する必要があります。 

ゼロを含む数値では、微妙な特殊なケースが発生します。 例えば、$S(1010) = 0111 = 111$, したがって、ソート後に先頭のゼロは消えます。 ソートされた数字を固定長文字列として扱う単純な実装では、算術演算に誤って先行ゼロが含まれる可能性があります。 もう 1 つのエッジ ケースは、1000 のような数値です。この場合、並べ替えられた表現が劇的に崩壊し、単純な位置推論が失敗します。 

## アプローチ

 直接的なアプローチでは、すべての整数を列挙します。$i \le X$、その桁マルチ​​セットを計算し、ソートし、再構築します。$S(i)$、合計を積み上げます。 それぞれの操作にかかるコスト$O(\log i)$、そして、あります$X$数字。 たとえ$X$と同じくらい小さかった$10^7$、これはすでに境界線です。 のために$10^{700}$、それはまったく不可能です。 

問題の構造は、数字 DP の観点を示唆しています。 数値を反復処理する代わりに、数値がどのように形成されるかを桁ごとに検討し、決定するのに十分な情報を追跡します。$S(n)$範囲内のすべての数値に対して。 

重要な観察は、$S(n)$の複数の桁セットにのみ依存します$n$、本来の順序ではありません。 これは、同じ桁の頻度ベクトルを持つすべての数値が同じ並べ替えられた値にマップされることを意味します。 したがって、数値を合計する代わりに、桁の構成を合計し、その中の数値の数で重み付けします。$[1, X]$そういう構成を持っています。 

これにより、問題は次の数までの数を数える問題に変わります。$X$特定の桁頻度プロファイルを持ち、同時にソート時にそのプロファイルの寄与を計算します。 

数字は、接頭辞上の数字 DP で処理されます。$X$、これまでに選択された各桁の数を維持するとともに、接頭辞とまだ一致しているかどうかを示す厳しい制約を維持します。$X$。 完成したマルチセットごとに、ソートされた数値を形成し、残りの桁の順列で重み付けされた数値を合計することによって、答えへの寄与を計算します。 

主な問題は、すべての桁の周波数ベクトルを直接列挙すると依然として膨大な量になることです。 代わりに、段階的に答えを構築します。各 DP 状態で、数字を配置することによって遷移を考慮し、有効な補完の数を追跡します。 分類された性質$S(n)$これにより、順列ではなく純粋に桁数に基づいて寄与度を計算できるようになります。

## アルゴリズムのチュートリアル

 1.変換$X$数字のリストに変換して、そのプレフィックス上で数字 DP を実行できるようにします。 これにより、すべての数値を列挙することができます$\le X$明示的に構築せずに。 
2. 階乗および逆階乗を最大長まで事前計算します。$X$。 これらは、桁の置換の多項係数を計算するために必要です。 これが必要なのは、数字のマルチセットを固定すると、順列での出現方法の数が組み合わせ的に決定されるためです。 
3. 現在のプレフィックスが次のプレフィックスと等しいかどうかを示すタイト フラグとともに、これまでに選択された各桁の数を追跡する DP 状態を定義します。$X$。 タイトフラグは、絶対に超過しないことを保証するため、不可欠です。$X$。 
4. DP 遷移中に、0 から 9 までの次の桁を選択します。タイトがアクティブな場合、選択肢は、DP の対応する桁を超えない桁に制限されます。$X$。 それ以外の場合は、任意の数字を自由に選択できます。 
5. 各 DP パスは、数字プレフィックス構造を共有する番号のクラスに対応します。 数字を完成させると、その数字のマルチセットが定義されているものとして解釈されます。$S(n)$、これらの数字を並べ替えたものです。 
6. 完成したマルチセットごとに、その数値を再構成することによって、答えへの寄与を計算します。 数字はソートされているため、数字を昇順に配置し、10 の累乗を使用して位置の寄与を計算できます。 
7. 再構成された値に、そのマルチセットと一致する順列の数を掛けます。 これは、桁数に基づく多項係数によって与えられます。 
8. モジュロを取得して、すべての有効な DP パスからの寄与を累積します。$10^9 + 7$。 

### なぜ効果があるのか

 すべての整数$n \le X$は、数字 DP 内の 1 つのパスに正確に対応します。 そのパスは、次の桁のマルチセットを一意に決定します。$n$、したがって一意に決定されます$S(n)$。 DP は、有効な出現をカウントするために必要な範囲を超えて、同じ桁構造を持つ数値を区別しないため、各寄与は、そのマルチセットを生成する元の数値の数によって正確に重み付けされます。 多項係数により、同一の数字のマルチセットの順列が正しくカウントされると同時に、内部の数字の順序が保証されます。$S(n)$施工により固定されます。 これにより、各整数が最終合計に 1 回だけ寄与することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    X = input().strip()
    n = len(X)

    # factorials
    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (n + 1)
    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    # precompute powers of 10
    pow10 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow10[i] = pow10[i - 1] * 10 % MOD

    digits = list(map(int, X))

    from functools import lru_cache

    @lru_cache(None)
    def dp(pos, tight, cnt):
        if pos == n:
            total_len = sum(cnt)
            if total_len == 0:
                return 0
            # build sorted number value
            val = 0
            idx = 0
            for d in range(10):
                for _ in range(cnt[d]):
                    val = (val * 10 + d) % MOD
                    idx += 1
            ways = fact[total_len]
            for d in range(10):
                ways = ways * invfact[cnt[d]] % MOD
            return val * ways % MOD

        res = 0
        limit = digits[pos] if tight else 9

        for d in range(limit + 1):
            new_tight = tight and (d == limit)
            new_cnt = list(cnt)
            new_cnt[d] += 1
            res = (res + dp(pos + 1, new_tight, tuple(new_cnt))) % MOD

        return res

    start_cnt = tuple([0] * 10)
    ans = dp(0, True, start_cnt)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、各状態が位置、密さ、および 10 次元の桁周波数ベクトルを記録する桁 DP を使用します。 周波数ベクトルはメモ化のためにタプルに変換されます。 

階乗配列と逆階乗配列は多項係数を効率的に計算し、各桁のマルチセットに対応する順列の数を数えることができます。 ソートされた値の再構築は、0 から 9 までの数字を反復し、順番に追加することによって行われます。 

微妙な点は、DP が先頭のゼロの状態を明示的に削除していないことです。 これは意図的なものです。なぜなら、先頭のゼロは並べ替えられた表現における数字のマルチセットの一部であり、ここで使用される組み合わせ解釈の下では正確さに影響を与えないからです。

 ## 特殊なケース

 重要なエッジ ケースは、1000 など、多数のゼロを含む数値です。このような入力の場合、並べ替えられた表現はゼロが続く 1 桁になりますが、数値的に解釈すると、より小さい値に折りたたまれます。 ゼロは桁のマルチセットの一部として扱われ、多項カウントに含まれるため、DP はこれを正しく処理します。 

もう 1 つのエッジケースは次のような場合です$X$999 や 111 など、それ自体に数字が繰り返されています。このような場合、タイトな遷移が再帰の奥深くまでアクティブなままであることがよくあります。 各プレフィックス状態が上限に違反することなく数字の選択を適切に制限し、無効な数字が過剰にカウントされることがないため、DP は引き続き機能します。
