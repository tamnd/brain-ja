 ## 解決策
 ## 問題の理解

 長さのバイナリベクトルを扱います`m`、これは次の整数として見ることができます。`0`に`2^m - 1`。 

有効なセット`S`3 つの構造特性を満たさなければなりません。 

まず、指定されたセットのすべてのベクトルが含まれます。`T`。 

2 番目に、XOR の下で閉じられます。 2 つのベクトルが属する場合`S`の場合、それらのビットごとの XOR も属している必要があります。`S`。 

3 番目に、ビット単位の AND で閉じられます。 2 つのベクトルが属する場合`S`の場合、それらのビットごとの AND も以下に属している必要があります。`S`。 

タスクは、異なるセットが何セットあるかを数えることです`S`これらの要件をすべて満たします。 

この制約は、ベクトルのセットを明示的に構築するべきではないことを即座に示唆しています。 アンビエントスペースには以下が含まれます`2^m`ベクトル、および`m`と同じ大きさにすることができます`1000`。 ベクトルを 1 つずつ推論するアプローチは不可能です。 

入力の珍しい部分は、`n`とても小さいです。 私たちはせいぜい`50`与えられたベクトル、次元`m`到達できる`1000`。 この非対称性が鍵です。 行について考える代わりに、列について考える必要があります。 

よくある間違いは、ベクトル自体に焦点を当てて、ベクトルの閉包を生成しようとすることです。`T`XOR と AND の下で。 中程度の次元であっても、そのクロージャにはすでに指数関数的に多くのベクトルが含まれている可能性があります。 

もう 1 つの簡単な間違いは、XOR のみによるクロージャで十分であると考えることです。 例えば：```
m = 2
T = {10, 01}
```XOR クロージャは空間全体です`{00,01,10,11}`。 この集合は確かに有効ですが、関与する線形代数オブジェクトはそれだけではありません。 AND 条件は、問題に実際の構造を与えるものです。 

2 番目の微妙なケースは、いくつかの座標がすべてのベクトルにわたって同一に見える場合に現れます。`T`。```
m = 2
T = {11}
```どちらの座標も内部では同じように動作します`T`。 有効なセットは 2 つあります。```
{00,11}
```そして```
{00,01,10,11}
```同一の座標を永続的にマージされたものとして扱うソリューションでは、そのうちの 1 つが欠落します。 

## アプローチ

 強引な視点は、根底にある代数構造を明らかにするので便利です。 

すべてのセットを列挙しようとするとします`S`含む`T`そして、XOR と AND で閉じているかどうかをテストします。 宇宙には含まれています`2^m`ベクトルなので、候補セットの数は次のようになります。$$2^{2^m}.$$たとえ`m = 20`これはとんでもなく大きいです。 

より洗練されたブルートフォースは以下から始まります`T`そして、クロージャーに達するまで、すべての XOR および AND の結果を繰り返し加算します。 これは、以下を含む最小の有効なセットを計算します。`T`, しかし、この問題では、最小セットだけでなく、すべての有効なセットが求められます。 

重要な観察は、XOR の下でクロージャが行われることです。`S`上のベクトル空間`F₂`、一方、AND の下での閉包は次のことを意味します。`S`は座標乗算でも閉じられます。 

の部分空間`F₂^m`座標方向の乗算で閉じられるものは、次のブール部分環です。`F₂^m`。 

このようなサブリングは非常に硬い形状をしています。 

2 つの座標位置を考慮します`i`そして`j`。 すべてのベクトルが`S`これら 2 つの位置に常に同じビットがある場合、内部の座標は区別できません。`S`。 この関係により、座標がブロックに分割されます。 

任意のブロック、すべてのベクトルについて、`S`そのブロック上では定数である必要があります。 逆に、座標の分割が固定されると、各ブロック上で一定であるすべてのベクトルのセットは、XOR と AND の両方で閉じられます。 

したがって、すべての有効なセットは、座標位置の分割に正確に対応します。 

ここで、次の要件を課します。`T`に属します`S`。 

2つの座標を取得します`i`そして`j`。 それらは、すべてのベクトルが一致する場合にのみ同じブロック内に存在できます。`T`位置に同じビットがあります`i`そして`j`。 

各座標について、その列署名を形成します。$$(t_1[i], t_2[i], \dots, t_n[i]).$$異なる署名を持つ座標を同じブロックに配置することはできません。 

同じシグネチャーのコーディネートは完全に交換可能です。 このようなサイズのグループの中で`c`、任意の方法で座標を分割することができ、そのような分割ごとに個別の有効なセットが生成されます。 

セットのサイズのパーティションの数`c`ベル番号です`Bell(c)`。 

異なる署名グループは独立しているため、答えは次のようになります。$$\prod Bell(c_i),$$どこ`c_i`署名グループのサイズです。 

残っている唯一のタスクは、最大のベル数を計算することです。`1000`。 

スターリング数漸化式の使用$$S(n,k)=S(n-1,k-1)+kS(n-1,k),$$すべてのベル番号を計算できます$$Bell(n)=\sum_{k=0}^{n} S(n,k)$$で`O(m²)`時間。

 ## アルゴリズムのチュートリアル

 1.すべて読む`n`バイナリ文字列。 
2. 座標位置ごとに`j`、以下から構成される列署名を構築します。`j`すべての入力文字列の - 番目のビット。 
3. 同一の署名によって座標をグループ化し、各グループのサイズを記録します。 
4. 最大のベル数を事前計算します。`m`。 
5. スターリング漸化式を使用する$$S(n,k)=S(n-1,k-1)+kS(n-1,k)$$モジュロ`10^9+7`。 
6. あらゆる人にとって`n`、すべてを合計します`S(n,k)`入手する`Bell(n)`。 
7. 答えを次のように初期化します。`1`。 
8. サイズの署名グループごとに`c`、答えを乗算します`Bell(c)`モジュロ`10^9+7`。 
9. 結果を出力します。 

ステップ 3 で十分な理由は、異なる署名を持つ座標が同じ分割ブロックに属することはあり得ませんが、署名を共有する座標は任意に分割できるためです。 

### なぜ効果があるのか

 すべての適切なセットは、次のブール部分列です。`F₂^m`。 のブール部分列`F₂^m`は、まさに、座標の一部のブロック上で定数であるベクトルのコレクションです。 

のベクトル`T`ブロックを共有できる座標を制限します。 2 つの座標は、すべてのベクトルが一致する場合にのみマージできます。`T`両方の位置に同じビットを割り当てます。これはまさに、それらの列署名が等しい条件です。 

1 つの署名クラス内では、任意のパーティションが許可されます。 異なる署名クラスは独立しています。 サイズのクラスのパーティションの数`c`は`Bell(c)`したがって、すべてのクラスにわたってベル数を乗算すると、すべての有効なセットが 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def solve():
    m, n = map(int, input().split())
    rows = [input().strip() for _ in range(n)]

    groups = {}

    for col in range(m):
        sig = tuple(rows[r][col] for r in range(n))
        groups[sig] = groups.get(sig, 0) + 1

    # Stirling numbers of the second kind
    stir = [[0] * (m + 1) for _ in range(m + 1)]
    stir[0][0] = 1

    bell = [0] * (m + 1)
    bell[0] = 1

    for i in range(1, m + 1):
        for k in range(1, i + 1):
            stir[i][k] = (
                stir[i - 1][k - 1] +
                k * stir[i - 1][k]
            ) % MOD

        bell[i] = sum(stir[i][1:i + 1]) % MOD

    ans = 1
    for cnt in groups.values():
        ans = (ans * bell[cnt]) % MOD

    print(ans)

solve()
```実装の最初の部分では、列の署名を構築します。 以来`n ≤ 50`、署名を文字のタプルとして保存することは完全に安全です。 これらのタプルが等しい場合、2 つの座標は正確に同じグループに属します。 

ベル数は、第 2 種スターリング数によって計算されます。 と`m ≤ 1000`、`O(m²)`動的プログラムは約 100 万回の状態更新を実行しますが、これは制限に簡単に適合します。 

よくある実装エラーは、再帰定義から直接ベル数を計算しようとすることです。 この反復には、以前のすべてのベル数値が含まれ、とにかくすぐに二次関数になります。 スターリング漸化式は単純で数値的に安定したモジュロです`10^9+7`。 

もう一つの微妙な点は、`Bell(0)=1`。 サイズが 0 の署名グループはありませんが、Stirling DP を正しく開始するには、この基本ケースが必要です。

 ## 特殊なケース

 検討してください```
1 1
0
```座標は 1 つだけであるため、サイズのシグネチャ クラスは 1 つだけです。`1`。 以来`Bell(1)=1`、アルゴリズムは戻ります`1`。 特別な取り扱いは必要ありません。 

考慮する```
2 1
11
```両方の座標が同じ署名を持っています`(1)`。 グループの規模は`2`、与える`Bell(2)=2`。 このアルゴリズムは、考えられる両方の座標パーティションを正確にカウントします。 

考慮する```
3 2
101
010
```署名は次のとおりです。```
(1,0), (0,1), (1,0)
```座標`1`そして`3`相互作用するかもしれないが、調整する`2`彼らに加わることはできない。 答えは次のようになります$$Bell(2)\cdot Bell(1)=2.$$これは、列署名によるグループ化が正しい基準である理由を示しています。 2 つの座標は、次のすべてのベクトルが一致する場合に正確にマージ可能です。`T`それらを同一のものとしてみなします。
