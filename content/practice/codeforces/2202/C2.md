 ## 解決策
 ## 問題の理解

 一連の整数が与えられ、その課題は古代文明で使用された生成手順を理解することを中心に展開します。 プロシージャは長さのシーケンスから始まります`m`そして、既存の要素の後に新しい要素を繰り返し挿入します。新しい要素は、その後に続く要素より 1 つ大きくなります。 正確に実行した後`k`挿入すると、長さのシーケンスが得られます。`m+k`。 問題は、任意のシーケンスが与えられた場合に、このプロセスを使用して生成された可能性のある元のシーケンスの長さの最小値を計算したいことです。 その最小の長さは次のように定義されます。`f(sequence)`。 

単一のシーケンスではなく、次のシーケンスの合計が求められます。`f(c)`隣接するすべてのサブセグメントにわたって`c`入力シーケンスの`a`。 本質的に、次の質問に答えなければなりません。`a`、挿入ルールに基づいて初期シーケンスを生成し、これらの最小長をすべて合計するには、初期シーケンスがどれほど小さくなる可能性がありますか。 

制約は重要です。 各テスト ケースには最大 300,000 個の要素を含めることができ、テスト ケースは最大 10,000 個まで含めることができ、すべてのテストにわたる要素の合計数は 300,000 に制限されます。 これは、すべてのサブセグメントを明示的に検査する単純な解決策は不可能であることを意味します。 素朴な解決策には、O(n²) 個のサブセグメントが含まれ、各サブセグメントの計算が必要になります。`f`直線的な時間がかかる可能性があり、テスト ケースあたりの作業量が O(n³) となり、制限時間には遅すぎます。 このため、線形または線形に近い計算方法を見つける必要があります。`f`すべてのサブ配列に対して効率的に実行されます。 

明らかではないエッジ ケースには、最小シーケンスの長さがサブ配列ごとに 1 になる厳密に増加するシーケンス、値がランダムに変動するシーケンス、要素が繰り返されるシーケンスが含まれます。 たとえば、入力の場合`[1, 2, 3, 4, 5]`、すべての部分配列は元のシーケンスから生成できます。`[1]`、それでそれぞれ`f`は 1. を前提とした不用意な解決策`f(c)`は常に次の長さです`c`間違った合計が出力されます。 

## アプローチ

 ブルートフォースアプローチでは、すべてのサブセグメントを反復処理します。`a`そして、サブセグメントごとに、挿入手順の逆をシミュレートして計算します。`f(c)`。 これには、最小の元のシーケンスを再構築するために O(n²) のサブセグメントが必要となり、潜在的にセグメントごとに O(n) が必要になります。 のために`n`最大 300,000 の場合、約 10¹⁶ の操作が必要となり、まったく現実的ではありません。 

重要な洞察は、挿入操作の性質から得られます。 このプロセスによって生成される有効なシーケンスは、各要素が挿入された前の要素と等しいか 1 つ大きいチェーンです。 より正式には、セグメントを左から右にトラバースすると、シーケンスを「ブロック」に分割できます。各ブロックは、連続した整数を含む厳密に増加する連続したものです。 最小の元のシーケンスは、新しい実行を開始する要素の数、つまり位置の数になります。`i`どこ`a[i]`から続かない`a[i-1]`これは、1 回スキャンして現在の実行の長さを維持し、連続するプロパティが切れるたびにリセットすることと同じです。 

この観察により、コンピューティングは`f(c)`要素ごとに O(1) で実行開始を識別することになります。 すべてのサブセグメントを効率的に合計するには、各位置について次のようにすることに注意してください。`i`、から始まる実行の長さに基づいて、それが属するすべてのサブ配列への寄与を計算できます。`i`。 スライディング ウィンドウまたは 2 ポインター アプローチを使用すると、実行ごとに影響を受けるサブ配列の数を数え、線形時間で寄与を合計できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を反復処理する`a`左から右へ。 変数を維持する`current_run_start`最新の連続実行がどこから始まったかを追跡します。 ゼロに初期化します。 
2. 各要素について`a[i]`からの連続パターンが続いているかどうかを確認します。`a[i-1]`。 もし`a[i]`に等しくありません`a[i-1] + 1`、 マーク`i`更新による新しい実行の開始として`current_run_start`。 
3. ポジションごとに`i`で終わる部分配列の数を計算します。`i`以降に始まるもの`current_run_start`。 この番号は`i - current_run_start + 1`、これらの各部分配列は、次の合計に 1 を与えます。`f(c)`最小限のシーケンスには現在の実行の開始が含まれている必要があるためです。 
4. 繰り返しながら、貢献度の累計を維持します。 配列が完全に処理されると、合計は次の合計を表します。`f(c)`すべてのサブ配列にわたって。 
5. この手順をテスト ケースごとに個別に繰り返します。 

機能する理由: 重要な不変条件は、セグメントを生成する最小シーケンスには、常にセグメントの最初の要素と、前の要素から連続していないすべての要素が含まれるということです。 現在の連続実行の開始を追跡することにより、すべてのサブ配列が次で終了することを保証します。`i`実行の最初の要素の貢献を 1 つだけ継承します。 これにより、カウント実行開始の貪欲な選択が生成プロセス定義と完全に一致するため、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total = 0
        run_start = 0
        for i in range(n):
            if i > 0 and a[i] != a[i-1] + 1:
                run_start = i
            total += i - run_start + 1
        print(total)

solve()
```コードは、テスト ケースの数を読み取ることから始まります。 テスト ケースごとに、シーケンスの長さとシーケンス自体を読み取ります。 変数`run_start`現在の連続実行の開始を追跡します。 シーケンスを反復処理する際、現在の要素が前の要素の継続でない場合は常に、更新します。`run_start`。 それぞれのポジションが貢献する`i - run_start + 1`これは、その位置で終了し、実行開始以降に開始するすべてのサブ配列を考慮した合計になります。 このコードは、各テスト ケースの累積合計を出力します。
