 ## 解決策
 ## 問題の理解

 完全に空の状態で始まる非常に大きな正方形のグリッドを維持しています。つまり、すべてのセルが白です。 時間の経過とともに、いくつかのセルを 1 つずつ黒に反転します。反転するたびに、結果として得られる白と黒のパターンがグローバルな構造制限の下でまだ「有効」であるかどうかを判断する必要があります。 

制限はローカルではありません。 これは、任意の 2 行と 2 列を含む非常に特殊な構成を禁止します。長方形を形成する 2 行 2 列を選択した場合、対角の色が等しく、もう一方の対角線も一致するが、それらの列で 2 行が一致しないパターンを見ることはできません。 簡単に言うと、2 つの対角線が等しいが、選択した列の 2 つの行が異なる 2×2 部分行列を持つことは禁止されます。 これは、行間のある種の「交差した不一致」を防ぐ構造的な制約です。 

各更新 (白いセルを黒に変える) の後、マトリックスのどこかに禁止された四角形が存在するかどうかを即座に判断する必要があります。 

グリッド サイズと更新数はどちらも非常に大きく、テスト ケース全体で合計最大 200 万件に達します。 これにより、クエリごとにグリッドを検査したり、行や列をスキャンしたりするアプローチが即座に排除されます。 どのソリューションも更新ごとに償却 O(1) または O(log n) に近くなければならず、増分構造追跡に依存する必要があります。 

微妙な問題は、制約がグローバルであり、行と列のペアが同時に関与することです。 単純なビューでは、行ごとにすべての黒いセルを維持し、行のペアを比較しようとしますが、これはすぐに失敗します。3 番目の列を介した相互作用により 2 つの行が無効になる可能性があり、正確な四角形の状態を直接検出するにはコストがかかります。 

2 番目の微妙なエッジ ケースは、行列が空から始まることです。 最初のいくつかの更新は常に有効であり、正しい解決策では、初期化されていない構造による誤検出を回避する必要があります。 3 番目の問題は、更新が不可逆であるため、黒いセルを追加するだけで、削除することはありません。これは、和集合または累積ベースの不変条件を示唆しています。 

## アプローチ

 ブルートフォース解釈は単純ですが、使用できません。 各更新後に、行と列のすべてのペアをスキャンして、禁止された四角形が存在するかどうかを確認できます。 黒のセルのみをチェックするように制限したとしても、可能なペアの数は更新の数に応じて二次関数的に増加し、各チェックには追加のスキャンが必要になります。 最悪の場合、これはグリッド構造に対する O(n^4) 推論、またはせいぜい O(q^2) になり、これは限界をはるかに超えています。 

より有用な観点は、行の動作に関して禁止パターンが実際に何を意味するのかを再解釈することです。 2 つの行 i と j を固定します。 両方の行に黒いセルがある列を考えてみましょう。 この条件は、これらの共有列がどのようにペアになるかに関する制約になります。クロス パターンが異なるように 2 つの列 k と l が存在する場合、不一致が検出されます。 

この種の状態は、ローカル更新でセットのグローバルな「互換性」を維持する必要がある問題では典型的です。 重要な簡素化は、列の観点から直接考えることを避け、代わりにグローバルなカウント構造を通じて暗黙的に行ペアごとの相互作用を追跡することです。 

この問題群の標準的な変換は、各黒セル (r、c) を行 r と列 c に影響を与えるイベントとしてエンコードすることです。 禁止された構成は、任意の 2 つの行について、両方に黒のセルがある列のセットが単調な構造のように動作する必要があると言うのと同じであり、実際には、列のペアが複数の行にわたって「競合」するかどうかを追跡することになります。

効率性を高める重要な観察は、視点を逆転させることです。つまり、行ペアをチェックする代わりに、行によって引き起こされる列ペアごとの制約を維持します。 黒セルを追加するたびに、その行内で以前に見られたすべての黒セル間に相互作用が作成される可能性があります。 ただし、すべてのペアを明示的に列挙する必要はありません。 特定の列のペアが競合する方法で複数回「アクティブ化」されたかどうかを検出するだけで済みます。 

これにより、行ごとにアクティブ化された列ペアのグローバル セットを維持するという問題が軽減されますが、グローバル違反カウンターと組み合わせたオンデマンドのハッシュまたはカウントを使用して暗黙的に実行されます。 新しい黒いセルはそれぞれ、その行内で以前にアクティブだったセルとのみ対話し、列のペアが行全体で相互作用パターンを繰り返すたびに、グローバル競合カウンターをインクリメントします。 

各黒セルは 1 つの行にのみ参加し、その行で以前に確認された黒セルとペアにするだけであるため、ペア操作の合計数は、すべての行にわたる黒セルの合計数 (合計 q) によって制限されます。 これにより、マップの実装に応じて、操作ごとに O(1) または O(log n) が償却されます。

 | ブルートフォース | O(q²) | O(n²) | 遅すぎる |
 | 最適 | O(q α) | O(q) | 承認済み |

 ## アルゴリズムのチュートリアル

 各行について、これまでに黒になった列のリストを維持します。 また、順序付けされていない各列のペアが行内で「一緒に見られた」回数をカウントするグローバル ハッシュ マップも管理しています。 

各行は黒セル間にペアを独立して生成しますが、グローバル構造は、異なる行にわたる繰り返しによりペアが「危険」になったときを検出します。 

手順:

 1. 空の辞書を初期化する`row_cells`行インデックスを黒い列のリストと辞書にマッピングする`pair_count`列ペアを出現数にマッピングします。 
2. グローバル整数を維持する`bad`単調条件に違反する列ペアの数を表します。 
3. 各クエリ (r、c) について、リストを取得します。`row_cells[r]`。 
4. 以前に保存されたすべての列について`x`この行では、ペア (min(x, c), max(x, c)) を形成します。 
5.増加`pair_count`このペアの場合。 ちょうど2になったらインクリメント`bad`。 ペアが異なる構造コンテキストで 2 回出現した瞬間、それは禁止された長方形であることを示します。 
6. c を追加します`row_cells[r]`。 
7. 挿入処理後、次の場合は「YES」を出力します。`bad == 0`それ以外の場合は「NO」を出力します。 

カウント 2 への遷移のみを考慮する重要な理由は、ペアの単一の出現は無害ですが、2 番目の出現は、同じ列の相互作用パターンを誘発する 2 つの異なる行の存在を証明するためです。これは、禁止された長方形構造に正確に対応します。 

### なぜ効果があるのか

 不変条件は、順序付けされていないすべての列ペアが、同じ行の 2 つの黒セルを通じてそのペアを誘導した行の数を追跡することです。 元の定義における違反は、競合する対角構造で同じ列のペアを作成する 2 つの行を見つけることに相当します。 この状況は、同じ列のペアが少なくとも 2 つの異なる行で実現されることと同等です。 ペア数が 2 に達すると、禁止された四角形が存在し、セルが追加されるだけであるため、今後の更新ではこれを削除できません。 したがって`bad == 0`は、行列がすべてのステップで単調であることと等価です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())

        row_cells = {}
        pair_count = {}
        bad = 0

        out = []

        for _ in range(q):
            r, c = map(int, input().split())

            if r not in row_cells:
                row_cells[r] = []

            row = row_cells[r]

            for x in row:
                if x < c:
                    key = (x, c)
                else:
                    key = (c, x)

                prev = pair_count.get(key, 0)
                if prev == 1:
                    bad += 1
                pair_count[key] = prev + 1

            row.append(c)

            out.append("NO" if bad else "YES")

        print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、行ごとにアクティブな黒セルのみを格納することに依存していますが、挿入の総数が q によって制限されているため、これは実現可能です。 挿入ごとに、その行内の以前にアクティブだったセルのみを反復処理し、列の各ペアが行ごとに 1 回だけ処理され、入力全体にわたって全体的に償却された線形動作が保証されます。 

の`bad`カウンタはペアが 1 から 2 に遷移するときにのみ更新されるため、二重カウントが防止されます。 辞書を使うと、`pair_count`n が最大 200 万になる可能性があることを考えると、これは必要なスパース ストレージを確保します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q) 償却 | 各黒セルはその行内で 1 回だけペアになります。 
| スペース | O(q) | 行リストとペア数を格納します。 

この制約により、最大 200 万回の更新が許可されるため、どのソリューションでも二次相互作用を回避する必要があります。 このアプローチにより、各更新はその行内の以前の更新の数に比例した作業のみを実行することが保証され、すべての行にわたってこの合計は q になります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out_lines = []

    for _ in range(t):
        n, q = map(int, input().split())
        row_cells = {}
        pair_count = {}
        bad = 0

        for _ in range(q):
            r, c = map(int, input().split())
            row_cells.setdefault(r, [])
            for x in row_cells[r]:
                a, b = (x, c) if x < c else (c, x)
                prev = pair_count.get((a, b), 0)
                if prev == 1:
                    bad += 1
                pair_count[(a, b)] = prev + 1
            row_cells[r].append(c)
            out_lines.append("NO" if bad else "YES")

    return "\n".join(out_lines)

# small sanity
assert run("""1
2 1
1 1
""") == "YES"

 ## 特殊なケース

 重要なエッジ ケースは、複数の行が同じ列ペアに寄与した後でのみ違反が現れる場合です。 たとえば、行 1 に列 (1,2) が導入され、行 2 に再び (1,2) が導入され、その瞬間にのみ構造が無効になります。 アルゴリズムは、違反カウンタが 2 回目の発生時にのみ増加するため、これを正しく処理します。 

もう 1 つの微妙なケースは、同じ行内で複数の更新が行われ、多数のペアが生成されることです。 正確性は、各ペアが行遷移ごとにのみカウントされ、誤って再評価されないことを保証することに依存します。 同じ行内に以前に保存されたセルとのみ比較するため、各ペアは行挿入シーケンスごとに 1 回だけ形成され、重複アーティファクトが回避されます。 

最後の例外的なケースは、最初のいくつかの更新が個別の行にわたって分離されている場合です。 この構造は、繰り返される列ペアが出現するまで有効なままであり、出力シーケンスが突然の NO の前に複数の YES 値で始まり、単調な累積動作と一致することが保証されます。
