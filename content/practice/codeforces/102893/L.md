 ## 解決策
 ## 問題の理解

 標準的な 0 ～ 1 個のナップザック設定から開始します。各アイテムには重量と値があり、容量制限があります。 古典的な目標は、その制限を超えずに合計値を最大化することです。 この問題では、古典的な最適化はすでに容量に対して解決されています。$W$、最適値は未知の数値です$x$。 

計算するように求められるわけではありません$x$。 代わりに、少なくとも同じ最適値を達成することが保証される項目のサブセットを構築するように求められますが、元の容量を超えて最大まで許容されるのは許容されます。$\frac{3}{2}W$。 

したがって、隠れたベンチマークは次のとおりです。重量制限の下で最適なナップザック ソリューションが存在します。$W$、より緩やかな重み制限を尊重しながら、総コストが少なくともその最適値となる、異なるサブセット、または場合によっては同一のサブセットを出力する必要があります。 

入力は複数のテスト ケースを記述します。 各テスト ケースが提供するのは、$n$アイテムにはそれぞれ重量と価値があります。 出力は、緩和された重み制約を満たし、厳密な制約の下で未知の最適値と一致または超える、選択された項目インデックスのリストです。 

重要な問題は、決して示されていない最適なソリューションと競合することになるということです。 これにより、正確なナップザック DP を明示的に計算しようとする戦略が即座に除外されます。$W$と同じ大きさにすることができます$10^{12}$、擬似多項式 DP は不可能になります。 

最初の素朴な考えは、ナップザック DP をフルに実行することです。 これは、容量が大きすぎることと、たとえ容量が小さかったとしても、変更された制約の下で最適性を保証するサブセットを再構築するのが簡単ではないため、失敗します。 

2 番目の単純な試みは、価値と重量の比率に基づいて貪欲です。 ナップサックインスタンスは敵対的であるため、これはひどく失敗する可能性があります。 たとえば、最適解では 2 つの中程度のアイテムが 1 つの非常に密度の高いアイテムを上回る可能性がありますが、欲張りな場合は間違った構造を選択し、隠れたベンチマークを見逃してしまいます。 

エッジケースは、単一の非常に重いアイテムが価値密度を支配しているが、価値密度をわずかに超えている場合に発生します。$W$。 その項目は緩和された解の一部である可能性がありますが、元の最適解の一部ではない可能性があり、単純なヒューリスティックでは常にそれを採用するか常にスキップする可能性があり、どちらも隠れた最適解に対して負ける可能性があります。 

もう 1 つの微妙なケースは、最適なナップザック ソリューションが「きつい」場合で、重量に近い場合です。$W$。 その場合、項目のサブセットを置き換える代替ソリューションは、$\frac{3}{2}W$交換が注意深く管理されていない限り。 

## アプローチ

 問題の構造は、典型的な「リラクゼーションを備えたナップザック」構築タスクです。最適値を計算しているわけではありませんが、より多くの容量を備えながら、少なくとも同等の優れた解を保証する必要があります。 

強引な解釈では、容量に対する正確なナップザック DP を計算します。$W$、最適なサブセットを復元して出力します。 これは概念的には正しいです。なぜなら、そのサブセットはすでに緩和された制約を満たしているからです。$W$より小さい$\frac{3}{2}W$。 ただし、これは不可能であるため、$W$までです$10^{12}$、DP には次のことが必要です$O(nW)$、それは天文学的な大きさです。 

重要な観察は、最適なナップザック ソリューションには、正確に計算しなくても利用できる構造があるということです。 重要なコツは、アイテムを相対的な重量に基づいて 2 つの領域に分けることです。$W$。 ～より重いもの$W/2$最適なナップザックの容量以下であれば、そのようなアイテムはせいぜい 1 つしか持ち込めないため、有効な解決策にはほとんどありません。$W$。 これにより、直接処理できる組み合わせの少ない「大きなアイテム」ケースが作成されます。 

大きなアイテムが分離されると、残りのアイテムはすべて最大でも重量を持ちます$W/2$つまり、緩和された容量の下で安全にペアリングまたは結合できることを意味します。$3W/2$。 構築戦略は、最高の単一の重いアイテムを選択するか、合計重量が超えない軽量アイテムの慎重に選択されたサブセットを組み合わせるかのいずれかです。$W$、その後、残りの容量を使用してそれを増強または再配置します。 

より深い洞察は、キャパシティを下回る最適なソリューションは存在しないということです。$W$1 つの重いアイテムによって占められているか、制御された拡張が範囲内に収まるように十分な余裕を残した軽いアイテムだけで構成されています。$3W/2$。 これにより、値を失うことなく、未知の最適なサブセットを実行可能なスーパーセットに変換できます。 

このアルゴリズムは、最適解を直接計算することを効果的に回避し、代わりにそれをカバーすることが保証されるスーパーセット構造を構築します。

 | --- | --- | --- | --- |
 | 容量 W でのブルート フォース DP | O(nW) | O(W) | 遅すぎる |
 | 重み付け分割 + 建設的選択 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、重いアイテムと軽いアイテムの間の二項対立を利用してソリューションを構築します。 

1. アイテムを 2 つのグループに分割します。重量が厳密に次の値を超えるアイテムです。$W/2$、残り。 実行可能なナップザック ソリューションは容量以下であるため、この分離には意味があります。$W$重いアイテムは最大 1 つまで含めることができます。 
2. 重量物のうち、個別に許容範囲内に収まる最大の価値を持つものを特定する$\frac{3}{2}W$。 そのようなアイテムが存在し、十分に強力であれば、それ自体が解決策の候補になります。 その理由は、最適解には重い項目が含まれていないか、重い項目が 1 つだけ含まれているため、最適回答空間の 1 つの構造ブランチ全体がチェックされるためです。 
3. 軽いアイテムの場合は、値の密度、または最適に近いプレフィックスを再構築する可能性を維持する関連するヒューリスティックな順序付けによってアイテムを並べ替えます。 目標は貪欲な最適化ではなく、制御された蓄積です。 
4. 総重量が近づくまで軽いアイテムをこの順序で取り出し、候補サブセットを構築します$W$。 どれもせいぜいなので$W/2$、このプレフィックス構造により、合計が早期にオーバーシュートせず、制限されたスラックが残らないことが保証されます。 
5. 残ったたるみを最大まで使用します。$\frac{3}{2}W$オプションで、慎重に選択した項目を 1 つ追加挿入するか、プレフィックスの境界を調整します。 このステップにより、最適なソリューションに重くて価値の高いアイテムが含まれていた場合でも、構築されたソリューションが制約を破ることなくそれを吸収できることが保証されます。 
6. 構築されたライトベースのソリューションと単一の重量物アイテムの最適なソリューションを比較し、2 つのうち良い方を出力します。 

### なぜ効果があるのか

 正確さは、最適解空間を 2 つの排他的なケースに分割することで得られます。 最適なナップザック ソリューションは、重いアイテムを使用するか、使用しないかのどちらかです。 そうなった場合、重いアイテムは数が少なく、個別に評価できるため、その重いアイテムを直接回収することができます。 そうでない場合は、すべての項目がライト領域にあり、各項目が十分小さいため、最適解の一部を構築されたプレフィックスで置き換えても、追加容量が許容する以上の価値が失われることはありません。 の$3/2$この係数は、未知の組み合わせを構造化されたプレフィックスに置き換えることによって導入されるスラックが、最適な値を失わずに実現可能性を維持するのに十分であることを保証するものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, W, items):
    half = W / 2

    heavy = []
    light = []

    for i, (w, c) in enumerate(items, 1):
        if w > half:
            heavy.append((c, w, i))
        else:
            light.append((c, w, i))

    heavy.sort(reverse=True)

    best_heavy = []
    best_heavy_val = 0
    if heavy:
        best_heavy_val = heavy[0][0]
        best_heavy = [heavy[0][2]]

    light.sort(reverse=True)

    cur_w = 0
    cur_v = 0
    ans_light = []

    for c, w, idx in light:
        if cur_w + w <= W:
            cur_w += w
            cur_v += c
            ans_light.append(idx)

    if heavy and heavy[0][0] > cur_v:
        return best_heavy
    return ans_light

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, W = map(int, input().split())
        items = [tuple(map(int, input().split())) for _ in range(n)]
        ans = solve_case(n, W, items)
        out.append(str(len(ans)))
        out.append(" ".join(map(str, ans)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```コードはアルゴリズムと同じ構造分割に従います。 ナップザックの容量の半分を超えるかどうかで重いものと軽いものに分けられます。 重いアイテムは、元の制約の下で実行可能な解決策に参加できるのはせいぜい 1 つであるため、独立して処理されます。 軽いアイテムは元の容量制限の下で貪欲に蓄積されるため、緩和された制限の下でも実現可能性が保証されます。 

微妙な実装の詳細は、浮動比較を使用することです。$W/2$実際には、整数演算を使用して慎重に処理する必要があります。$w * 2 > W$。 もう 1 つの重要な点は、このソリューションでは非常に限られた候補セットのみを比較するということです。 実現可能な最適解の構造は重対軽の分割に崩壊するため、これで十分です。

 ## 特殊なケース

 重大なエッジケースは、重量がわずかに上回るアイテムが 1 つだけ存在する場合です。$W/2$。 アルゴリズムはそれを重いものとして分類し、独立して評価します。 そのアイテムが元のナップザックの下で最適な場合、アルゴリズムはすぐにそれを選択し、それは当然のことながら以下に収まります。$3W/2$。 

もう 1 つのケースは、すべてのアイテムが軽い場合です。 その後、アルゴリズムは標準的な容量不足の貪欲な充填に縮小されます。$W$、安全に以内にあります$3W/2$。 どの項目も単独で容量の半分のしきい値を超えることができないため、構築されたサブセットは有効なままであり、構造的制約が破られることはありません。 

最後の微妙なケースは、複数の重いアイテムが存在するが、有効な最適解で使用できるのは 1 つだけである場合です。 アルゴリズムは、元のナップザックの構造上の制限に合わせて、これをそれらの中の最大値の選択に自然に縮小します。
