 ## 解決策
 ## 問題の理解

 この問題は、次のグループについて説明します。`n`ちょうど 1 人のプレイヤーが隠れた詐欺師である場合。 私たちは、タスクを完了するのが見られたプレーヤーの観察を与えられます。 観察リストに登場するプレイヤーが偽者であることはできません。 誰かが複数のタスクを実行しているのを見ても追加情報は得られないため、リストには同じプレイヤーが複数含まれる場合があります。 

目標は、観察結果から詐欺師の可能性が 1 つだけ残されているかどうかを判断することです。 タスクを実行しているところを一度も見たことがないプレイヤーが 1 人だけいる場合、答えは次のようになります。`YES`。 詐欺師の可能性がある人が 2 人以上いる場合、乗組員は確信が持てず、答えは次のようになります。`NO`。 特殊なケースが 1 つあります。すべてのプレイヤーがリストに含まれている場合、偽者がタスクを偽造したに違いないため、情報に一貫性がありません。問題により、そのようなことが起こったと仮定することはできません。 答えもまた、`NO`。 

制約は小さく、プレーヤーの数と観測の数は両方とも最大です。`1000`。 これは、単純なリニア スキャンを使用したソリューションでも十分に高速であることを意味します。 解決策`O(n + k)`実行される操作はわずか数千件です。 複数回ソートしたり、すべてのプレイヤーを繰り返しチェックしたりするような、より複雑なアプローチは不要ですが、これらの制限を満たしている可能性は依然として高くなります。 

主なエッジケースは、ユニークなプレーヤーの紛らわしい外観から生じます。 観察が重複しても、詐欺師の可能性の数は減りません。10 回観察されたプレイヤーは、依然として非詐欺師であることが確認された 1 人にすぎないからです。 

例えば：```
3 3
1 2 2
```正しい出力は次のとおりです。```
YES
```選手`1`そして`2`安全が確認されているのでプレイヤーのみ`3`詐欺師になる可能性があります。 個別のプレイヤーではなく観測値をカウントする不注意な実装では、3 人のプレイヤーが見つかったと考えて誤った回答をする可能性があります。`NO`。 

もう 1 つのケースは、すべてのプレイヤーが登場する場合です。```
3 5
2 1 1 3 3
```正しい出力は次のとおりです。```
NO
```3人のプレーヤー全員がタスクを実行しているのが見られました。 偽者は通常タスクを完了できないため、確実に特定できるプレイヤーは存在しません。 

最後の境界ケースは、プレーヤーがちょうど 2 人の場合です。```
2 2
2 2
```正しい出力は次のとおりです。```
YES
```プレイヤーのみ`2`詐欺師から除外され、プレイヤーから退場します`1`ユニークな可能性として。 

## アプローチ

 簡単な強引な方法では、すべてのプレイヤーを詐欺師の可能性があるとして試すことになります。 候補者ごとに、そのプレーヤーがタスク リストに表示されるかどうかを確認できます。 選手が出てきたら無理です。 それ以外の場合は、回答の可能性があるものとしてカウントされます。 これは正しいです。なぜなら、私たちが持っている唯一の情報は、プレイヤーが観察されたかどうかだけだからです。 

このアプローチの問題は、スキャンが繰り返されることです。 まであります`1000`選手たちと`1000`観測結果なので、最悪の場合のパフォーマンスは約`1,000,000`小切手。 これでもここでは問題ありませんが、必要以上に一般的な問題を解決しています。 

重要な観察は、プレイヤーが何回登場するかは気にしないということです。 どのプレイヤーが少なくとも 1 回登場したかを知る必要があるだけです。 それらのプレーヤーがマークされると、答えはマークされていないプレーヤーの数によって単純に決まります。 

強引なアプローチが機能するのは、「このプレイヤーに可能性があるかどうか」を問うためです。 すべてのプレイヤーに対して個別に回答しますが、すべてのプレイヤーが独立しているという観察により、すべての候補者に一度に回答することができます。 ブール配列は各プレーヤーが見られたかどうかを記録し、問題を未見のプレーヤーのカウントに軽減します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nk) | お(1) | ここでは受け入れられますが、不要です |
 | 最適 | O(n + k) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各プレーヤーがタスクを実行しているのが見られたかどうかを記録する配列を作成します。 最初は、すべてのプレイヤーは見えないとみなされます。 
2. 観察されたすべてのプレーヤーを読み取り、そのプレーヤーを見たものとしてマークします。 プレーヤーが少なくとも 1 回出現したかどうかのみを考慮するため、繰り返し出現しても何も変わりません。 
3. まだ見えていないプレイヤーを数えます。 これらの選手たちはまさに詐欺師の可能性がある候補者たちだ。 
4. 詐欺師の可能性がある人の数がちょうど 1 人の場合、次のように出力します。`YES`。 それ以外の場合は印刷します`NO`。 

これが機能する理由は、目に見えるプレーヤーはすべて考慮から除外され、見えないプレーヤーはすべて可能性を維持できるためです。 乗組員は、残りのセットにプレイヤーが 1 人だけ含まれている場合にのみ、詐欺師を特定できます。 

なぜ効果があるのか:

 このアルゴリズムは、観察リストの任意のプレフィックスを処理した後、マークされたプレーヤーがまさにそのプレフィックスに登場したプレーヤーであるという不変条件を維持します。 最後に、詐欺師になれなかったすべてのプレイヤーがマークされます。 残っているのは、すべての観察結果と一致するプレイヤーだけです。 そのようなプレイヤーが 1 人いる場合、偽者は一意に決定されます。 候補者がゼロまたは複数の場合、確実性はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    seen = [False] * (n + 1)

    for _ in range(k):
        x = int(input().strip()) if False else None

    # Re-read input handling the second line containing all values
    data = list(map(int, input().split()))
    for x in data:
        seen[x] = True

    possible = 0
    for i in range(1, n + 1):
        if not seen[i]:
            possible += 1

    print("YES" if possible == 1 else "NO")

if __name__ == "__main__":
    solve()
```この実装では、プレイヤー番号でインデックス付けされたブール配列を使用します。 プレイヤー番号は から始まるので、`1`、配列にはサイズがあります`n + 1`そのため、インデックスはプレーヤー識別子と直接一致します。 

観察結果を読んだ後、リスト内の各プレーヤーにマークが付けられます。 重複する値には特別な処理は必要ありません。`True`複数回割り当てても、1 回割り当てたのと同じ効果があります。 

最後のループでは、マークされていないプレーヤーがカウントされます。 との比較`1`候補者がゼロの場合でも候補者が複数の場合でも、偽者を特定できないことを意味するため、これが必要な唯一の条件です。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    n, k = map(int, sys.stdin.readline().split())
    seen = [False] * (n + 1)
    for x in map(int, sys.stdin.readline().split()):
        seen[x] = True

    cnt = sum(1 for i in range(1, n + 1) if not seen[i])
    print("YES" if cnt == 1 else "NO")

    result = sys.stdout.getvalue()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return result

assert run("3 3\n1 2 2\n") == "YES\n", "sample 1"
assert run("4 2\n3 1\n") == "NO\n", "sample 2"
assert run("3 5\n2 1 1 3 3\n") == "NO\n", "sample 3"
assert run("2 2\n2 2\n") == "YES\n", "sample 4"

assert run("2 1\n1\n") == "YES\n", "minimum observations"
assert run("5 5\n1 2 3 4 4\n") == "YES\n", "duplicate values"

assert run("10 1\n7\n") == "NO\n", "many possible impostors"
