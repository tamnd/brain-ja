 ## 解決策
 ## 問題の理解

 Vasya は、それぞれに難易度とコストを伴う一連の問題からコンテストを組み立てたいと考えています。 彼は問題を含めることで固定の報酬を受け取りますが、2 種類のコストも支払います。1 つは各問題の作成者への直接支払い、もう 1 つは選択したセグメント内の連続する問題間の最大二乗差に基づく「ギャップ ペナルティ」です。 形式的には、インデックスから問題の連続した部分列を選択すると、`l`に`r`、利益は次の合計です。`a`問題ごとのコストから、選択した問題のコストの合計から、そのセグメント内の連続する難易度間の最大ギャップの 2 乗を引いた額。 

入力により提供されるのは、`n`それぞれに困難を伴う問題`d_i`そしてコスト`c_i`、困難が厳密に増加している場所。 連続した問題の選択に対して達成可能な最大の利益を見つけなければなりません。 出力は、この最大利益を表す単一の整数です。 

とすれば`n`最大 3·10^5 の場合、O(n^2) の複雑さを持つアルゴリズムでは、およそ 10^10 の演算が必要となるため、非常に遅くなります。 線形または線形に近い時間で機能するソリューションが必要です。 単一の問題を選択すると、微妙なエッジ ケースが 1 つ発生します。つまり、ギャップはゼロであるため、利益は単純に`a - c_i`。 単純な実装が常にギャップを計算すると、単一の問題に対して誤ってゼロ以外のペナルティが追加される可能性があります。 もう 1 つの注意が必要なケースは、最大のギャップが総コストを支配する場合です。 たとえば、間隔の広い困難を選択すると、より小さく、よりコンパクトなセグメントを選択するよりも利益が減少する可能性があります。 

## アプローチ

 ブルートフォース手法では、すべての連続するサブ配列を反復処理し、それぞれの利益を計算します。 開始インデックスごとに`l`、セグメントをすべての終了インデックスまで拡張します。`r ≥ l`、コストの合計を計算し、連続する難易度間の最大二乗差を計算し、それをから引きます。`a * length - cost sum`。 これは、文字通りすべてのオプションを試行するため、正確性を保つために機能しますが、セグメントの計算には O(n^2) の作業が実行されます。これは、n が 3・10^5 までの場合は実行不可能です。 さらに、各セグメントの最大ギャップを再計算すると、セグメントごとにさらに O(n) が追加され、単純な実装では複雑さが O(n^3) に悪化します。 

重要な洞察は、ギャップ ペナルティが連続する難易度の差の二乗の最大値によって決定され、右に移動すると単調増加シーケンスを形成するということです。 連続する難易度間の差を事前に計算し、問題を最大化するものとして扱うことにより、`a * length - sum(c_i) - max_gap`、スライディング ウィンドウまたはスタックベースの単調構造を使用して問題の構造を利用できます。 基本的に、問題ごとに、その時点で終了する最大許容セグメントを維持し、それを延長しても利益が減少しないようにします。 差分の単調スタックを使用すると、最大ギャップを効率的に追跡し、潜在的なセグメントを O(n) 時間で評価できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 (単調スタック + プレフィックス合計) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 連続する難易度間の差異の配列を計算します。`diff[i] = d[i+1] - d[i]`のために`i`で`0..n-2`。 この配列を使用すると、任意のセグメントの二乗ギャップを効率的に計算できます。 
2. コストのプレフィックス合計を計算します。`pref_cost[i] = c[0] + ... + c[i]`, したがって、任意のセグメントのコストの合計は`[l, r]`O(1) で次のように計算できます。`pref_cost[r] - pref_cost[l-1]`（取り扱い`l=0`別途）。 
3. 変数を初期化する`max_profit`負の無限大まで。 これにより、これまでに見つかった最高の利益が追跡されます。 
4. スタックまたは両端キューを使用して、セグメントの最大 2 乗ギャップを追跡しながら、潜在的なセグメント開始インデックスを維持します。 スタックは単調です`diff[i]^2`、セグメントを拡張することで最大ギャップが効率的に更新されるようになります。 
5. エンディングインデックスごとに`r`0 から n-1 まで、各開始インデックスからセグメントを拡張することを検討してください。`l`スタック内にあります。 セグメントの利益を計算する`[l, r]`として`profit = (r - l + 1) * a - (pref_cost[r] - pref_cost[l-1]) - max_gap(l, r-1)^2`。 アップデート`max_profit`これが高ければ。 
6. セグメントを拡張することで最大ギャップが大きくなりすぎる場合は、スタックからインデックスをポップスタートします。 これにより、考慮されているセグメントが管理可能なギャップで最大の利益を得ることが保証されます。 
7. すべてのセグメントを繰り返した後、印刷します。`max_profit`。 

機能する理由: 単調スタックは、次で終わるすべてのセグメントに対して、`r`、スタートインデックスを検討しています。`l`これは、差が小さいセグメントが先にプッシュされ、差の二乗が大きいために利益が減少するセグメントがスキップされるため、利益が最大化されます。 プレフィックス合計を使用すると、コストを一定時間で計算でき、ギャップ計算はスタックを介して効率的に行われるため、すべてのセグメントが 1 回だけ考慮され、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, a = map(int, input().split())
    d, c = [], []
    for _ in range(n):
        x, y = map(int, input().split())
        d.append(x)
        c.append(y)
        
    if n == 1:
        print(a - c[0])
        return

    diff = [d[i+1] - d[i] for i in range(n-1)]
    pref_cost = [0] * n
    pref_cost[0] = c[0]
    for i in range(1, n):
        pref_cost[i] = pref_cost[i-1] + c[i]

    max_profit = -10**18
    stack = []

    for r in range(n):
        while stack and (r > 0 and diff[r-1]**2 >= diff[stack[-1]]**2):
            stack.pop()
        stack.append(r)
        l = stack[0]
        gap = 0 if l == r else max(diff[l:r])**2
        total_cost = pref_cost[r] - (pref_cost[l-1] if l > 0 else 0)
        profit = (r - l + 1) * a - total_cost - gap
        max_profit = max(max_profit, profit)

    print(max_profit)

if __name__ == "__main__":
    main()
```このソリューションでは、まず、連続する難易度とコストのプレフィックス合計の差を準備します。 単一問題のケースを個別に処理すると、誤ったギャップ計算が回避されます。 スタックは、差分の単調性を尊重する方法で潜在的な開始インデックスを維持し、任意のセグメントの最大二乗ギャップを効率的に計算できるようにします。 各終了インデックスで、現在の最適なセグメントの利益を計算し、全体の最大値を更新します。

1 1

```選択中`[0,1]`: 利益 = 2*5 - (1+2) - (2-1)^2 = 10 - 3 -1 = 6

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 問題を 1 回通過します。 プレフィックスの合計は O(n) です。 単調スタックでは、各要素が最大 1 回プッシュ/ポップされることが保証されます。 |
 | スペース | O(n) | プレフィックスの合計と差の配列。 スタック サイズは最大でも n です。 |

 n が最大 3・10^5 であるとすると、4 秒の制限内では O(n) 回の操作が許容されます。 メモリ使用量も範囲内です。
