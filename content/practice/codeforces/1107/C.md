 ## 解決策
 ## 問題の理解

 ヒットの固定シーケンスが与えられており、各ヒットにはダメージ値があり、特定のボタン (小文字) に関連付けられています。 残りのヒットは元の順序を維持したまま、シーケンスからヒットを削除することができます。 合計ダメージは継続したヒットの合計です。 

制約は、同じボタンが 2 回以上押されると、`k`結果のシーケンスで何度も連続してゲームパッドが壊れます。 したがって、最終的に選択されたサブシーケンスでは、同一文字の最大ブロックはすべて最大でも長さでなければなりません。`k`。 

課題は、この制約の下で総ダメージを最大化するサブシーケンスを選択することです。 

入力サイズは最大です`2 · 10^5`、つまり、次式の解はすべて`n`すぐに遅すぎます。 平`O(n log n)`これは受け入れられますが、問題の構造は、決定がグローバルな相互作用ではなく等しい文字のローカル ブロックにのみ依存するため、線形または線形に近い貪欲なアプローチが必要であることを強く示唆しています。 

すべてのサブシーケンスを考慮するという素朴な考えがありますが、単一の文字に限定した場合でも、同じ文字の各ブロック内の組み合わせサブセットを考慮する必要があり、これは最悪の場合指数関数的になります。 

ロングランの途中で大ダメージの要素が発生すると、さらに微妙な問題が発生します。 たとえば、ある文字が何度も繰り返され、その 1 つの出現で非常に大きなダメージがある場合、以前の選択肢が割り当てを満たしたという理由だけでその文字が除外されないようにする必要があるかもしれません。`k`。 

もう 1 つの特殊なケースは、同じ文字の複数の長いブロックが他の文字によって分離されている場合です。 元の文字列では連続していなくても、削除後に単一のブロックにマージできるため、以前のセグメントでの決定をスキップすると、後の実現可能性に影響します。 

## アプローチ

 強引な解釈は次のようになります。インデックスのすべてのサブセットを試し、結果のシーケンスを計算し、同じ文字の連続が長さを超えているかどうかを確認します。`k`。 有効なサブセットについては、損害額を合計して最大値を取得します。 これは明らかに指数関数的です`n`、あるので`2^n`サブセット、そして各サブセットのチェックにも時間がかかります`O(n)`。 

重要な観察は、実現可能性は_結果のサブシーケンス_内の同一文字の連続にのみ依存し、要素を自由にスキップしてそれらの連続の長さを制御できるということです。 元の文字列内の同一文字の連続セグメント内では、どの要素を保持するかを効果的に選択していますが、その順序は固定されています。 

今度は 1 つの文字に注目してください`c`。 すべての位置が次のようになると仮定します。`s[i] = c`が考慮されます。 これらの出現のサブシーケンスを選択したいと考えていますが、最終的なシーケンスでは次のシーケンスが実行されないという制限があります。`c`を超える`k`。 ただし、間に他の文字がブレークするため、実際の結合は、元の文字列内の連続する同一文字の最大ブロックごとに発生します。 

そこで、文字列を等しい文字のセグメントに分解します。 各セグメント内では、単一の文字を処理する必要があります。 制約は次のようになります。各セグメントでは、以下の値を超えてはなりません。`k`項目は連続していますが、すべてが同一であるため、これは単純に最適なサブセットを選択することになりますが、それ以上の項目を決して選択しないようにします。`k`そのセグメント内の連続したピック。 したがって、セグメント内の最適な戦略は簡単です。`k`セグメントが完全に独立している場合の最大値。 

ただし、セグメントは、同じキャラクターの新しい実行を開始するかどうかによってのみ相互作用します。 正しいグローバルな観点はもっと単純です。文字ごとに、その出現を順番に処理し、決してそれ以上のものを取得しないようにします。`k`その文字の連続して選択された要素。 到達したら`k`連続して選択された出現がある場合、別の文字に切り替えて「リセット」しない限り、それ以降の出現はスキップする必要があります。これは、グローバルに順番に処理しているときに自然に発生します。 

これは、貪欲な構造につながります。つまり、インデックスを順番に処理し、文字ブロックごとに保持される連続文字のカウンターを維持し、超過する必要がある場合には常に維持されます。`k`、現在の連続した同じ文字の選択の中で最も価値の低い要素を削除する必要があります。 これは当然、優先キューのような調整になりますが、さらに単純な解釈もあります。 

動的に考える代わりに、各ブロックを独立して処理できます。 同一の文字のブロックで、その長さが次のようになると仮定します。`m`。 以上を保つことはできません`k`最終シーケンスではそのうちの 1 つが連続しているため、そのブロック内で選択できるのは最大でも`k`ブロック自体は元の文字列内ですでに連続しており、内部で分離できないためです。 したがって、各ブロックでの最適な選択は、`k`そのブロックの最大値。 

これにより問題が完全に分離されます。ブロックごとに小さな選択範囲を並べ替えたり維持したりするのです。

 ## アルゴリズムのチュートリアル

 文字列を、同一の文字の最大の連続セグメントに分割することによって処理します。 

1. 配列を左から右にスキャンし、連続する等しい文字をセグメントにグループ化します。 このようなセグメント内でのみ、連続したプレスが蓄積される可能性があるため、これが必要です。 
2. セグメントごとに、そのセグメントに属するすべてのダメージ値を収集します。 内部の文字はすべて同じであるため、このセグメントから選択されたサブセットは最終シーケンスに連続して表示されます。 
3. セグメント内では、制約が許容する範囲を超えて事実上「オーバーコミット」しないようにしながら、合計を最大化したいと考えています。 最適な戦略は、`min(k, length of segment)`最大のダメージ値。 その理由は、このセグメント内で選択されたアイテムは連続したブロックを形成するため、許可された制限内で最も価値のあるアイテムのみが必要になるためです。 
4. セグメント内の値を降順に並べ替え、最初の値を取得します。`k`。 
5. これらの選択した値を回答に追加し、次のセグメントに進みます。 

重要な考え方は、要素をスキップしても異なる文字をマージすることは決してできず、異なる文字が介在するため、異なるセグメント間で同一の文字をマージすることは不可能であるため、セグメントは独立しているということです。 

### なぜ効果があるのか

 同一文字の連続ブロック内では、最終シーケンスは選択されたサブセットの連続性を保持します。 そのブロック内のすべての要素が 1 回の実行に寄与するため、意味のある唯一の制約は保持する要素の数です。 以上を維持する`k`そのブロックからの数は直ちにルールに違反します。また、より価値の高いものに置き換える場合、保持する数を少なくすることは常に次善の策となります。 したがって、トップを選択すると、`k`各セグメントの値は、他の場所でより長く有効な実行を危険にさらすことなく、貢献を最大化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    s = input().strip()

    ans = 0
    i = 0

    while i < n:
        j = i
        vals = []

        while j < n and s[j] == s[i]:
            vals.append(a[j])
            j += 1

        vals.sort(reverse=True)
        for t in range(min(k, len(vals))):
            ans += vals[t]

        i = j

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは入力を読み取り、同一の連続文字をグループ化しながら文字列を反復処理します。 グループごとに、対応するすべてのダメージ値をリストに収集します。 降順に並べ替えると、最も価値のあるヒットを最初に選択できるようになり、必要なのは`k`それ以上取得すると、そのブロック内の制約に違反するためです。 

ポインタ`i`セグメント全体を一度にスキップすることで進み、文字列の線形トラバースが保証されます。 唯一の非線形コストは、各セグメント内の並べ替えによって発生します。

    input = sys.stdin.readline

    i = 0

 ## 特殊なケース

 微妙なケースは、文字列全体が 1 文字である場合です。 その場合、アルゴリズムは単一のセグメントを処理し、単純に最上位を選択します。`k`価値観。 たとえば:

 入力:```
6 2
1 100 2 90 3 80
aaaaaa
```セグメントは収集します`[1, 100, 2, 90, 3, 80]`、並べ替えると`[100, 90, 80, 3, 2, 1]`、そしてかかります`100 + 90 = 190`。 制約は完全にローカルであるため、他のセグメントとの相互作用は存在しません。 

もう 1 つのエッジケースは次のような場合です`k = 1`。 各セグメントはその最大要素のみを提供します。これは、同じ文字を 2 つ連続して使用することはできないという直観と一致します。そのため、すべてのブロックをその最適な代表値に縮小する必要があります。
