 ## 解決策
 ## 問題の理解

 サイズの正方行列が与えられます。$n \times n$ただし、明示的にビットとして書き込まれるのではなく、各行は 16 進文字にパックされます。 各 16 進数は 4 つのバイナリ セルを表すため、入力はバイナリ行列のコンパクトなエンコードにすぎません。 

タスクは最大のブロック サイズを見つけることです$x$マトリックスをより小さいサイズのグリッドに「圧縮」できるようにする$\frac{n}{x} \times \frac{n}{x}$。 圧縮とは、行列を重複しないように分割することを意味します。$x \times x$ブロックの場合、単一ブロック内のすべてのセルがまったく同じ値を持つ必要があります。 異なるブロックは異なることが許可されますが、1 つのブロック内では変化はありません。 

したがって、条件はグローバルな繰り返しに関するものではなく、グリッドの固定パーティション内のローカルな均一性に関するものです。 

制約は私たちを$O(n^2)$または近くの$O(n^2 \log n)$解決。 以来$n \le 5200$、$O(n^2)$パスはもう近づいています$2.7 \times 10^7$細胞、それは問題ありません。 受け入れられないのは、多数の候補値に対して完全な行列スキャンを繰り返すことです。$x$なぜなら、約数の数はまだ数十億もの演算を必要とするほど十分に大きい可能性があるからです。 

素朴なアプローチでは、すべての約数を試してしまうでしょう$x$の$n$すべてのブロックをスキャンして各ブロックを検証します$x^2$細胞。 各チェックにコストがかかるため、時間がかかります$O(n^2)$、それを何度も行うと、そのコストは倍増します。 

ブロックの独立性ではなく周期的な繰り返しを仮定すると、微妙な失敗のケースが発生します。 たとえば、各$4 \times 4$ブロックは一定ですが、異なるブロックは変化するため、完全に周期的なグリッドとして扱うと、有効な圧縮が誤って拒否されます。 

もう 1 つの失敗例は、16 進数のデコードを慎重に処理しないことに起因します。 各文字は 4 ビットに拡張され、ビットをセルにマッピングする際に 1 つずれると構造がシフトされ、ブロック アラインメント チェックが中断されます。 

## アプローチ

 ブルートフォース戦略は定義から始まります。 候補者ごとに$x$、行列を次のように分割します。$x \times x$ブロックを作成し、すべてのブロックに個別の値が 1 つだけ含まれていることを確認します。 ブロックごとに、そのすべてのセルをスキャンします。 これは、圧縮条件を直接強制するため、正しいです。 

問題は繰り返しです。 各チェックはすでにすべてに影響しています$n^2$多数のセルに対してこれを行うと、合計の作業量が大きくなりすぎます。 

重要な点は、すべてのブロック内のすべてのセルを繰り返し再スキャンする必要がないということです。 ブロックは、そのすべての値が同一である場合に有効です。これは、バイナリ行列の場合、そのブロック内の値の合計が次のいずれかであると言うのと同じです。$0$または$x^2$。 これにより、2D プレフィックス合計を維持する場合、各ブロック チェックが定数時間クエリに変換されます。 

プレフィックスの合計が利用可能になると、各候補は$x$を反復することで検証できます$\left(\frac{n}{x}\right)^2$ブロックと各ブロックの合計をチェックする$O(1)$。 これにより、各候補チェックがセルの数ではなくブロックの数に比例するように減少します。 

約数だけをテストするので、$n$、すべての約数にわたる合計作業量は、ブロック数にわたる調和のような合計を形成し、合計の複雑さは に近いままになります。$O(n^2)$。

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 入力をバイナリ行列にデコードする

 各 16 進文字は 4 ビットに拡張されます。 私たちは完全な$n \times n$マトリックス$A$0 と 1 のみを含みます。以降の推論はすべて直接セル アクセスに依存するため、このステップが必要です。 

### ステップ 2: 2D プレフィックス合計配列を構築する

 各エントリが四角形内の左上隅からその位置までの 1 の数を格納するプレフィックス合計テーブルを構築します。 これにより、任意の部分行列の合計を一定時間でクエリできるようになります。 これは、繰り返しスキャンに代わるメカニズムです。 

### ステップ 3: すべての約数を列挙する$n$すべての有効なブロック サイズを生成します$x$そのような$n \bmod x = 0$。 グリッドは等しいブロックに分割可能である必要があるため、これらの値のみが意味を持ちます。 

### ステップ 4: 各候補者について$x$、すべてのブロックを検証します

 行列を次のように分割します。$x \times x$ブロック。 各ブロックについて、プレフィックスの合計を使用して 1 の数を計算します。 合計がどちらでもない場合$0$または$x^2$の場合、ブロックには混合値と候補が含まれます。$x$は無効です。 

### ステップ 5: 有効な最大値を追跡する$x$すべての候補を反復処理し、検証に合格した最大の候補を保存します。 これが最終的な答えです。 

### なぜ効果があるのか

 各ブロックは、圧縮行列内の単一の値に対応する必要があります。 バイナリ行列の場合、有効なブロックは定数であることと同等であり、これは合計が 0 またはフルであることと同等です。 プレフィックスの合計により、各ブロックを曖昧さなく正確に 1 回チェックすることが保証されます。 すべてのセルは固定の 1 つのブロックに属するため、$x$、検証は正確さを完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_matrix(n):
    A = [[0] * n for _ in range(n)]
    for i in range(n):
        row = input().strip()
        col = 0
        for ch in row:
            v = int(ch, 16)
            for k in range(3, -1, -1):
                if col < n:
                    A[i][col] = (v >> k) & 1
                    col += 1
    return A

def build_prefix(A, n):
    ps = [[0] * (n + 1) for _ in range(n + 1)]
    for i in range(n):
        row_sum = 0
        for j in range(n):
            row_sum += A[i][j]
            ps[i + 1][j + 1] = ps[i][j + 1] + row_sum
    return ps

def rect_sum(ps, x1, y1, x2, y2):
    return ps[x2][y2] - ps[x1][y2] - ps[x2][y1] + ps[x1][y1]

def solve():
    n = int(input())
    A = build_matrix(n)
    ps = build_prefix(A, n)

    def ok(x):
        for i in range(0, n, x):
            for j in range(0, n, x):
                total = rect_sum(ps, i, j, i + x, j + x)
                if total != 0 and total != x * x:
                    return False
        return True

    best = 1
    for x in range(1, n + 1):
        if n % x == 0 and ok(x):
            best = x

    print(best)

if __name__ == "__main__":
    solve()
```デコードステップでは、各 16 進数を正しい順序で 4 ビットに注意深く処理し、ビットの配置が元のマトリックス レイアウトと一致することを確認します。 接頭辞の合計は 1 から始まるインデックスを使用して構築されるため、部分行列クエリでは境界チェックが必要ありません。 

検証機能は、個々のセルではなくブロック起点のみをスキャンすることによって、各候補ブロック サイズをチェックします。 長方形の合計クエリはそれぞれを分離します。$x \times x$領域を一定時間で処理します。これが最適化の核心です。 

全体にわたるループ$x$約数の数が制限されており、プレフィックスの合計により各チェックが効率的であるため安全です。

 ## 特殊なケース

 完全に均一な行列が最も単純なケースです。 すべての候補者$x$すべてのブロック合計は常に$x^2$。 プレフィックスの合計は常に各ブロックの完全なカバレッジを返すため、アルゴリズムはこれを自然に処理します。 

市松模様のパターンはすべての場合に失敗します$x > 1$。 このような場合、ブロック合計は常に混合され、最初に失敗したチェックは最初の無効なブロックのすぐ内側で発生し、不要な領域をスキャンすることなく早期に拒否されます。 

大きな連続領域でのみ均一であるが、ブロック境界で位置がずれているマトリックスは、位置合わせが重要である理由を示しています。 大きな領域が値を共有している場合でも、それらが誤ってブロック境界を越える場合、合計条件は境界ブロックでの不一致を正確に検出します。
