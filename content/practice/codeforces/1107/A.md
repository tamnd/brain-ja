 ## 解決策
 ## 問題の理解

 それぞれ 1 から 9 までの数字の文字列が与えられます。タスクは、この文字列を少なくとも 2 つの連続するセグメントに分割し、各セグメントを整数として解釈したときに結果のシーケンスが厳密に増加するようにすることです。 区切り記号はどこにでも配置できますが、各桁は 1 つのセグメントに正確に属している必要があります。 出力は、有効な分割が存在しない場合は「NO」、または「YES」の後にセグメント数とセグメント自体が続くかのいずれかになります。 

制約は控えめで、クエリはそれぞれ最大 300 桁の文字列で最大 300 件までです。 これは、文字列の長さがほぼ 2 次である任意の解が実現可能であることを意味します。$300 \cdot 300 = 90,000$クエリごとの操作は制限時間内に収まります。 Python では整数オーバーフローのリスクはありませんが、複数桁になる可能性のある数値間の比較を処理する必要があります。大きな整数の変換を避けたい場合は、文字列比較として慎重に行う必要があります。 

見落としやすいエッジケースには、次のような数字が繰り返されるシーケンスが含まれます。`33`、次のように厳密に減少するシーケンス`654321`、および複数の分割が可能であるが、特定の分割のみが厳密な昇順を満たすシーケンス。 例えば、`654`次のように分割できます`6 | 54`しかし、そうではありません`65 | 4`。 もう 1 つの微妙なケースは、文字列の桁がすべて等しい場合です。`11`厳密に増加するセグメントに分割することはできません。 

## アプローチ

 ブルートフォースアプローチは、文字列に区切り文字を配置するあらゆる方法を試し、結果の各シーケンスが厳密に増加しているかどうかを確認することです。 各桁は現在のセグメントの継続であることも、新しいセグメントの開始であることもあるため、次のようになります。$2^{n-1}$分割の可能性。 のために$n = 300$、これは天文学的に大きく、実行不可能です。 このアプローチは原理的には正しいですが、現実的ではありません。 

重要な洞察は、**有効な増加分割** を見つけるだけでよく、必ずしも最短または最適である必要はないということです。 各桁は少なくとも 1 であるため、単純な貪欲なアプローチが機能します。つまり、文字列を左から右にスキャンして、最後のセグメント値を維持できます。 桁数を追加して現在のセグメントを拡張しようとしますが、新しいセグメントが前のセグメントより厳密に大きくなるとすぐに区切り文字を配置します。 終端に到達する前にそのような延長が不可能な場合は、有効な分割が見つかるまで、現在の位置からより短いセグメントを試行します。 セグメントは先頭にゼロのない数値であり、1 ～ 9 の数字のみで構成されるため、複数の数字がある限り、有効な分割が見つかることが保証されます。 

貪欲なアプローチが機能するのは、任意の数字のシーケンスがある時点で分割して、増加するシーケンスを作成できるためです。最初の数字だけでは、残りの数字で形成される十分に長い数字よりも常に小さくなります。 失敗する唯一のシーケンスは、次のような同じ数字の繰り返しで完全に構成されるシーケンスです。`33`または次のような同一の数字を持つ減少シーケンス`11`、厳密に増加する 2 つの数を生成することはできません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 貪欲な分割 | クエリあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. クエリの数を読み取ります。 クエリごとに、数字の文字列を読み取ります。 
2. すべての数字が同一であるかどうかを確認します。 その場合、厳密に増加する分割は不可能であるため、「NO」を出力します。 
3.初期化`last_segment`最後に選択した数値を表す空の文字列として。 
4. 左から文字列のスキャンを開始します。 ポジションごとに`i`、現在のセグメントを一度に 1 桁ずつ拡張して形成してみてください。`current_segment`。 
5. 1回`current_segment`厳密にはより大きくなる`last_segment`、セグメントを終了します。セグメントのリストに追加し、更新します。`last_segment`に`current_segment`、次の位置から新しいセグメントを開始します。 
6. すべての桁が処理されるまで続行します。 最後のセグメントが空の場合 (つまり、最後のセグメントが前のセグメントよりも大きくなったことがない場合)、厳密に昇順を維持するために、そのセグメントを前のセグメントとマージします。 
7. 少なくとも 2 つのセグメントが形成されている場合は、「YES」とセグメントを出力します。 それ以外の場合は「NO」を出力します。 

これが機能する理由: 不変条件は、セグメントを配置した後、そのセグメントが常に前のセグメントよりも厳密に大きくなるということです。 各桁は少なくとも 1 であるため、残りの桁が前のセグメントよりも大きな数値を形成する点が常に存在します。 これにより、アルゴリズムが減少シーケンスを生成しないことが保証されます。 同一の数字のエッジケースは別個に処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        s = input().strip()
        
        if s[0] == s[-1] and s.count(s[0]) == n:
            print("NO")
            continue
        
        segments = []
        last_segment = ""
        i = 0
        while i < n:
            j = i + 1
            while j <= n and (last_segment == "" or int(s[i:j]) <= int(last_segment)):
                j += 1
            if j > n:
                # If we reached the end without finding a larger segment, take the rest
                current_segment = s[i:n]
                segments.append(current_segment)
                break
            current_segment = s[i:j]
            segments.append(current_segment)
            last_segment = current_segment
            i = j
        
        if len(segments) < 2:
            print("NO")
        else:
            print("YES")
            print(len(segments))
            print(" ".join(segments))

if __name__ == "__main__":
    solve()
```このソリューションでは、すべての桁が同じである場合に、自明な不可能性がないかどうかが最初にチェックされます。 次に、前のセグメントより厳密に大きくなるまで各セグメントを拡張して、貪欲にセグメントを構築します。 これ以上分割できない文字列の端は慎重に処理してください。 有効な分割が存在する場合は、セグメントのリストを出力します。 

## 実用的な例

 ### 例 1:`654321`| 私 | 現在のセグメント | 最後のセグメント | セグメント |
 | --- | --- | --- | --- |
 | 0 | 6 | "" | [] |
 | 1 | 6 | "" | ["6"] |
 | 1 | 5 | 「6」 | ["6"] |
 | 1 | 54 | 「6」 | ["6","54"] |
 | 3 | 3 | 「54」 | ["6","54"] |
 | 3 | 321 | 「54」 | ["6","54","321"] |

 アルゴリズムは 3 つのセグメントに正しく分割され、それぞれが厳密に増加します。 

### 例 2:`33`すべての数字が同一です。 アルゴリズムは即座に「NO」を出力します。

## 特殊なケース

 ケース`33`は、同一の数字のシーケンスを分割できないことを示しています。 アルゴリズムは、最初の桁のカウントをチェックすることでこれを検出します。 シーケンス`654321`は、貪欲なアプローチが、前のセグメントを超えるまで数字をより大きな数にグループ化することによって、減少シーケンスであっても複数のセグメントを正しく形成することを示しています。 このソリューションは文字列末尾のマージを正しく処理し、たとえ単独で大きな数値を形成できなかったとしても、最後のセグメントが確実に含まれるようにします。
