 ## 解決策
 ## 問題の理解

 それぞれのサイズが異なる小さなバイナリ グリッドのコレクションが与えられます。$m \times m$, ここで、各セルは空か塗りつぶされています。 キー操作は「グリッド置換」の一種です: 2 つのグリッドを構成する場合$T_1$そして$T_2$、すべての塗りつぶされたセル$T_1$の完全コピーに置き換えられます$T_2$、空のセルはすべて$m \times m$空のセルのブロック。 結果として、グリッドのサイズが大幅に大きくなります。$m^2 \times m^2$。 

タスクは、この操作の下で何組の入力グリッドが交換されるかをカウントすることです。これは、入力グリッドをどちらの順序で構成しても、まったく同じ結果の大きなグリッドが生成されることを意味します。 

入力サイズは大きくなる可能性がありますが、最大$10^5$グリッド、各グリッドは非常に小さく、$m \le 5$。 これは、各グリッドを小さなオブジェクトとして扱い、それらをハッシュまたは比較する解決策は実行可能であるが、構成を明示的にシミュレートしようとするアプローチは不可能であることをすぐに示唆しています。 単一のコンポジションはすでにサイズが拡大しています$m^2 \times m^2$、多くのペアに対してそれを行うと、計算量が爆発的に増加します。 

見落としがちな主なエッジケースは、構成下の平等が見た目よりもはるかに厳しいということです。 たとえば、置換操作は塗りつぶされたセルの正確な配置に依存するため、「対称的に見える」2 つの異なるグリッドは一般に交換されません。 単一の塗りつぶされたセルでも、構造がどのように複製されるかを完全に決定できます。 

異なる位置のフルグリッドまたはスパースグリッドなどの構造化パターンに対して可換性が成立すると仮定すると、微妙な失敗例が発生します。 たとえば、あるグリッドに 1 つの塗りつぶされたセルがあり、もう 1 つのグリッドに複数の塗りつぶされたセルがある場合、それらを異なる順序で構成すると異なる数の複製ブロックが生成されるため、等価性は維持できません。 これにより、ほとんどの「構造的対称性」の推測が除外され、操作下で 2 つのグリッドが事実上区別できないオブジェクトになる場合を特定する方向にソリューションが推進されます。 

すべての構造的制約を生き残る唯一の堅牢な等価性は、グリッドの文字通りの等価性です。 

## アプローチ

 ブルートフォース手法では、すべてのペアの合成グリッドを計算します。$(T_i, T_j)$両方の順序で実行し、結果を比較します。 各コンポジションは、$m \times m$グリッドに$m^2 \times m^2$グリッドなので、単一の構成にコストがかかります$O(m^4)$。 と$n^2$ペアの場合、これは次のようになります$O(n^2 m^4)$、これは実現不可能です。$n = 10^5$。 

重要な単純化は、どのような構造が合成後にも残るかを理解することです。 この操作では、異なるセル間の情報が混合されません。 ブロック全体を複製するだけです。 これにより、結果は塗りつぶされたセルのパターンによって完全に決定され、それらのパターンの不一致は出力全体に乗算的に伝播します。 

重要な観察は、2 つのグリッドが交換できる場合、それらをいずれかの順序で構成すると、すべてのレベルで同一のブロック構造が生成される必要があるということです。 これにより、厳格な位置合わせ条件が強制されます。塗りつぶされたセルの配置に違いがあると、ブロックが展開される場所の不一致が直ちに生じます。 これを回避する唯一の方法は、両方のグリッドでまったく同じ複製パターンを誘発することです。これは、グリッドが同一である場合にのみ発生します。 

したがって、問題は、入力マルチセット内の同一のグリッドのペアをカウントすることに帰着します。 

各グリッドをサイズの固定長文字列 (またはビットマスク) として表すことができます。$m^2$、それらをハッシュし、頻度を数え、組み合わせを合計します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース構成 |$O(n^2 m^4)$|$O(m^4)$| 遅すぎる |
 | ハッシュ + 頻度カウント |$O(n m^2)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各グリッドをコンパクトな表現として扱い、同一の出現をカウントします。 

1. それぞれを読む$m \times m$グリッドにして単一の文字列またはビットマスクに平坦化します。 

完全に等しいことのみを比較するため、平坦化の順序は一貫性がある限り問題になりません。 
2. 各グリッド表現のハッシュを計算します。 

ローリング ハッシュまたは文字列の Python タプルで十分です。$m \le 5$したがって、衝突は実際的な問題ではありません。 
3. グリッド表現から出現数までの頻度マップを維持します。 

それぞれの同一のグリッドは同じバケットに貢献します。 
4. すべてのグリッドを処理した後、各バケット内の順序なしペアの数を次のように計算します。$f \cdot (f - 1) / 2$、すべてのバケットを合計します。 
5. 合計を出力します。 

### なぜ効果があるのか

 合成操作では、2 つの異なるグリッドが少なくとも 1 つの合成順序で異なるレプリケーション レイアウトを生成できるように、構造が厳密に保存されます。 これにより、可換性が基礎となるグリッドの等価性と等価になります。 この等価性が確立されると、問題はマルチセット内の等しい要素をカウントすることになります。これはまさに周波数集約が計算することです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    freq = {}
    
    for _ in range(n):
        rows = []
        for _ in range(m):
            rows.append(input().strip())
        key = ''.join(rows)
        freq[key] = freq.get(key, 0) + 1
    
    ans = 0
    for c in freq.values():
        ans += c * (c - 1) // 2
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、各グリッドを単一の連結された長さの文字列に縮小します。$m^2$。 これにより、明示的な 2 次元の処理が不要になります。 周波数マップは、同一のグリッドを自動的にグループ化します。 

唯一の微妙な点は、改行が正しく処理されるようにすることです。 各グリッドは正確に読み取られます$m$行を削除し、連結前に改行文字を削除します。 

## 実用的な例

 ### 例 1

 2 つが同一で 1 つが異なる 3 つのグリッドを考えてみましょう。 

平坦化された表現のみを追跡します。 

| ステップ | グリッドキー | 周波数マップ |
 | --- | --- | --- |
 | 1 | あ | {A: 1} |
 | 2 | B | {A: 1、B: 1} |
 | 3 | あ | {A: 2、B: 1} |

 最終的な答えは次のように計算されます。$C(2,2) + C(1,2) = 1 + 0 = 1$これは、同一のグリッドのみが可換ペアに寄与することを示しています。 

### 例 2

 すべてのグリッドが同一の場合:

 | ステップ | グリッドキー | 周波数マップ |
 | --- | --- | --- |
 | 1 | あ | {A: 1} |
 | 2 | あ | {A: 2} |
 | 3 | あ | {A: 3} |

 答えは次のようになります。$3 \cdot 2 / 2 = 3$どのペアも同一であるため、すべてのペアが通勤します。

 ## 特殊なケース

 2 つの同一のグリッドを持つ最小入力は、寄与がゼロでない唯一のケースを示しています。 アルゴリズムは両方を読み取り、同じキーを 2 回生成し、計算します。$2 \cdot 1 / 2 = 1$、単一の有効なペアと一致します。 

すべてのグリッドが異なる場合、各キーの頻度は 1 になります。すべての項があるため、式の結果はゼロになります。$1 \cdot 0 / 2$は消え、ペアはカウントされません。 

多数の同一のグリッドが表示される場合、ハッシュ テーブルは入力順序に関係なくそれらを 1 つのバケットにグループ化し、順序が結果に影響しないことを示します。 ペアの数はそのバケット内で二次関数的に増加します。これは、2 つの同一の要素を選択する組み合わせ構造と一致します。
