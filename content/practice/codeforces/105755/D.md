 ## 問題の理解

 左から右にラベルが付けられたロボットの列が与えられます。 ロボット$i$位置から始まります$x = i$、すべてのロボットは時間 0 で左に移動し始めます。 「スローモーションショット」が発射されるたびに、まだラインのプラス側にあるすべてのロボットの速度が半分に低下するため、単純な方法では、動きは時間の経過とともに均一ではありません。 これらのショットはゼロより大きい整数倍でのみ発射でき、そのような時点で複数のショットを発射する可能性があります。これは、その正確な時間にすべてのアクティブなロボットが攻撃される回数を増やすことと同等です。 

各ロボットには必要なヒット数があります。 ロボット$i$正確に叩かなければならない$a_i$回、ここでシーケンスは$a_1 \le a_2 \le \dots \le a_n$減っていない。 プロセスは正確に終了します$a_n$合計ショットが発射されており、整数の時間に発射されるショットの数が異なる場合、異なるスケジュールは異なるものとみなされます。 

このタスクは、有効な起動スケジュールがいくつ存在するかを数えることです (剰余 998244353)。 

制約$n \le 100$そして$a_i \le 100$ロボットの数と起動「レイヤー」の最大数の両方が少ないことがわかります。 これは、次の値の範囲にわたる動的プログラミングまたは組み合わせ構築を強く示唆しています。$a_i$、実際の連続運動シミュレーションに依存するものではありません。 モーションの詳細は制約を定義するために存在しますが、解決策は最終的には整数タイム ステップ全体にイベントを分散するための構造化された方法をカウントすることに帰着する必要があります。 

重要な微妙な点は、物理学の素朴な解釈は誤解を招くということです。 ロボットの正確な連続位置は、スケジュールのカウントには無関係です。 重要なのは、各ロボットが将来のショットの影響を受けなくなる時期だけであり、これは正確なタイミングではなく、すでに命中された回数のみに依存します。 

よくある失敗例は、速度を変更するたびに動きをシミュレートしたり、正確な位置を追跡しようとしたりすることに起因します。 たとえば、半減が繰り返される中で各ロボットの正確な衝突時間を計算しようとすると、浮遊動作が発生し、有効なショット スケジュールの組み合わせ構造に対応しません。

重要な観察は、次の単調性であるということです。$a_i$階層構造を意味します。 を考えた現時点では、$k$- 番目のショット、まさにロボットです$a_i \ge k$将来のヒットをまだ必要としているという意味で、まだ「アクティブ」です。 以来$a_i$が減少しない場合、これらのアクティブ セットはロボットのプレフィックスを形成します。 これにより、問題はショット レベルごとに一連のタイム スロットを構築することに変換されます。各レベルには、そのレベルをまだ必要とする最後のロボットによって決定される上限があります。

 ## アルゴリズムのチュートリアル

 We process the problem level by level, where level$k$に対応します$k$システム全体の - 番目のショット。

4. すべてのレベルで選択肢の数を増やす$k = 1 \dots a_n$、プレフィックス境界が固定されると、さまざまなレベルでの選択は独立するためです。 
5. 積モジュロ 998244353 を返します。

### なぜ効果があるのか

 核となる不変条件は、レベルでの$k$重要な唯一の制約は、どのロボットが少なくとも必要とするかということです。$k$ヒットします。 これらのロボットは、許可される配置に上限を強制します。$k$-回目の起動時間ですが、ロボットは次の起動時間を必要とします$k$ヒットはすでに将来の決定から「切り離され」ています。 関連するロボットのセットは次のように単調に縮小するため、$k$、制約は時間インデックスのネストされた間隔を形成します。 このネストにより、各レベルが、以前の配置を考慮した後に残っている有効な整数スロットの数に等しい独立した乗算係数に寄与することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    a.sort()
    max_k = a[-1]
    
    # p[k] = largest index i such that a[i] >= k
    p = [0] * (max_k + 1)
    
    j = n - 1
    for k in range(1, max_k + 1):
        while j >= 0 and a[j] >= k:
            j -= 1
        p[k] = n - 1 - j
    
    ans = 1
    for k in range(1, max_k + 1):
        choices = p[k] - (k - 1)
        ans = (ans * choices) % MOD
    
    print(ans)

if __name__ == "__main__":
    solve()

各レベルは、そのレベルの有効な位置の数に等しい乗算係数を提供します。$k$- すでに配置されている以前の時間を考慮した後の th の起動時間。 最終製品には、これらの独立した選択が集約されます。 

微妙な実装の詳細により、$p[k]$はインデックスではなくカウントとして解釈され、減算は$(k-1)$厳密に増加する時点の構造を正しく説明しています。

 ## 特殊なケース

 ミニマルなケース付き$n = 1$そして$a_1 = 1$起動時間は 1 つだけであり、ロボット間の相互作用がないため、有効なスケジュールは 1 つだけ生成されます。 アルゴリズムは計算します$p_1 = 1$、選択肢は 1 つだけです。 

のような場合には$a = [1,1,1,1]$、各レベルにはアクティブなロボットが 1 つだけあるため、各ステップは 1 つの配置に寄与します。 アルゴリズムは維持します$p_k = n$みんなのために$k = 1$、積はずっと 1 のままです。 

いつ$a_n$大きいですが、初期のロボットの多くは小さいです$a_i$、プレフィックス サイズは次のように急速に縮小します。$k$が増加します。 アルゴリズムはこれをモノトーン ポインターを通じてキャプチャし、一度$p_k < k$の場合、有効な厳密な増加スケジュールを形成できないため、積は正しくゼロになります。
