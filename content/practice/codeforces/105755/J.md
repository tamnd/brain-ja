 ## 解決策
 ## 問題の理解

 それぞれの建物の高さと開始位置が与えられています。 プレイヤーは最初の建物から、最終的にはすべての建物を少なくとも 1 回は踏みたいと考えています。 移動は隣接する建物間でのみ許可されます。 面白いのは、上り坂に移動すると上向きの変化量に等しいエネルギーを消費するのに対し、平地または下り坂に移動するとコストはかからないということです。 プレイヤーがエネルギーを使い果たすと、それ以上上り坂に移動できなくなります。 

線路の両端にも専用出口があります。 どちらの端からでも、プレイヤーは自由に飛び出すことができ、すぐに元のエネルギーを回復して最初の建物に戻ることができます。 これは、完全なトラバースを複数の独立した「実行」に分割することができ、常に開始位置で開始し、終点の 1 つで終了できることを意味します。 

可能な開始位置ごとに、これらのリセット可能な実行を任意の数だけ使用してすべての建物を訪問できるように、最小の初期エネルギーを決定する必要があります。 

この制約は、テスト ケースごとに線形時間に近いアルゴリズムを意味します。 すべてのテスト ケースにわたる建物の合計数は最大 100,000 であるため、インデックスごとに一定量を超える作業を実行するソリューションは遅すぎます。 すべてのパスの二次探索やエネルギー状態のシミュレーションは直ちに除外されます。 

単純な推論による微妙な失敗のケースは、プレーヤーが 1 回の連続トラバースを実行する必要があると仮定した場合です。 例えば、最初から両端に向かって高さが高くなっている場合、一度歩くのに大きなエネルギーが必要になります。 ただし、テレポートを使用すると、両端に向かって 1 つずつ、2 つの独立した移動に分割できます。 

もう 1 つのよくある落とし穴は、エネルギーが距離や歩数に依存すると仮定することです。 たとえば、高さの場合`[1, 100, 2]`位置 2 から開始して、左右に移動すると、たとえ両側が一歩離れていたとしても、コストは大きく異なります。 

## アプローチ

 直接的なアプローチでは、すべての建物を訪問するためのすべての可能な方法をシミュレートします。 開始位置から、エネルギーと訪れた状態を追跡しながら、左右の動きのすべてのシーケンスを試すことができます。 各ステップが分岐し、状態を再訪するのは位置と残りのエネルギーの両方に依存するため、これはすぐに指数関数的になります。 エネルギーの変化はパスに依存し、最大 100,000 のサイズのラインでは考えられるパスの数が膨大になるため、枝刈りを行ってもあまり役に立ちません。 

重要な簡素化は、タスクを開始位置から独立した行程に分割することで実現します。 エンドポイントに到達するたびにエネルギーがリセットされるため、他のランと相互作用することはありません。 これは、すべてをカバーする 1 つのグローバル パスは必要ないことを意味します。 代わりに、2 つの独立した要件の観点から考えることができます。1 つは最初から左端に到達するための要件、もう 1 つは最初から右端に到達するための要件です。 別々のランで両端に到達できると、左のランは 1 と s の間のすべての建物を訪問し、右のランは s と n の間のすべての建物を訪問するため、すべての建物がカバーされます。 

したがって、問題は、非対称エッジ コストの下で、単一パスで開始点から各終了点まで移動するのに必要な最小エネルギーを計算することに帰着します。 i から i+1 への移動では、高さが増加する場合にのみエネルギーがかかります。逆方向の場合も同様です。 全方向のコストは、単純にそのパスに沿ったすべての上り坂の移行の合計です。 

したがって、開始位置の答えは、左端に到達するまでのコストと右端に到達するまでのコストの最大値になります。

 ## アルゴリズムのチュートリアル

 目標は、開始インデックスごとに、各方向への最適な動きで両端に到達するのに必要なエネルギーを計算することです。 

1. 各位置について、右に一歩ずつ歩いて右端に到達するまでのコストを計算します。 

i から i+1 に移動する場合、h[i+1] - h[i] が正の場合のみ加算します。 それ以外の場合は何も追加しません。 これにより、その方向への上り坂の移動に費やされる正確なエネルギーが捕捉されます。 
2. これらの累積コストを配列に格納して、各開始位置が正しい境界に到達するために必要な総エネルギーを表す値を持つようにします。 
3. 左方向については、i から i-1 に移動すること以外は同様の累積を計算します。 

左に移動する場合、左に移動するときの上り坂のステップを表すため、h[i-1] - h[i] が正の場合にのみ加算します。 
4. これらの左方向のコストを、開始位置に合わせて別の配列に格納します。 
5. 各開始位置について、左のコストと右のコストの最大値を取得します。 これは、左右の探査がリセット可能な別々の実行で行われるため、エネルギーが 2 つのうちより高価な方に十分である必要があるという事実を表しています。 

この分解が有効である理由は、左端に向かうすべての動きが最初から左にのみ進む実行で発生し、右端に向かうすべての動きが最初から右にのみ進む実行で発生するように、すべての有効な戦略を再配置できるためです。 方向を切り替える混合パスは、いずれの方向にも必要な最大エネルギーを削減することなく、追加の上り坂遷移のみを導入する可能性があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        h = list(map(int, input().split()))

        # cost to reach right from each position
        right = [0] * n
        for i in range(1, n):
            gain = h[i] - h[i - 1]
            if gain > 0:
                right[i] = right[i - 1] + gain
            else:
                right[i] = right[i - 1]

        # cost to reach left from each position
        left = [0] * n
        for i in range(n - 2, -1, -1):
            gain = h[i] - h[i + 1]
            if gain > 0:
                left[i] = left[i + 1] + gain
            else:
                left[i] = left[i + 1]

        res = []
        for i in range(n):
            res.append(str(max(left[i], right[i])))

        print(" ".join(res))

if __name__ == "__main__":
    solve()
```このソリューションは 2 つの蓄積を構築します。 の`right`配列には、開始位置から右端に向かって歩くときの累積上り坂コストが格納されます。 各ステップは、次の建物がより高い場合にのみ寄与します。 の`left`アレイはこのロジックを逆方向にミラーリングします。 

各位置の答えは、その 2 つの方向コストのうち大きい方を取ることによって独立して計算されます。これは、これらのコストが、両方が成功する必要がある別々のエクスカーションに対応しているためです。 

よくある間違いは、両方向を単一の走査コストに結合しようとすることです。 これはテレポートのリセットを無視します。これにより、移動が独立したセグメントに分割され、左右の動きの間の結合が削除されます。 

## 実用的な例

 高さが次のような単純なケースを考えてみましょう。`[1, 2, 3, 4]`。 すべてのステップが上り坂であるため、コストは右に移動する場合にのみ蓄積されます。 

| 私 | 身長 | 適切なコスト | 残りのコスト | 答え |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 0 | 3 | 3 |
 | 1 | 2 | 0 | 2 | 2 |
 | 2 | 3 | 0 | 1 | 1 |
 | 3 | 4 | 0 | 0 | 0 |

 これは、左に移動すると逆トラバースで上り坂の遷移に繰り返し遭遇するため、位置に応じて左側のコストがどのように支配的になるかを示しています。 

ここで考えてみましょう`[5, 1, 4, 2]`。 

| 私 | 身長 | 適切なコスト | 残りのコスト | 答え |
 | --- | --- | --- | --- | --- |
 | 0 | 5 | 0 | 3 | 3 |
 | 1 | 1 | 3 | 4 | 4 |
 | 2 | 4 | 0 | 1 | 1 |
 | 3 | 2 | 0 | 0 | 0 |

 これは、高さの非対称性により、開始点に応じて異なる支配的な方向が生じることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        t = int(input())
        for _ in range(t):
            n = int(input())
            h = list(map(int, input().split()))

            right = [0] * n
            for i in range(1, n):
                gain = h[i] - h[i - 1]
                right[i] = right[i - 1] + (gain if gain > 0 else 0)

            left = [0] * n
            for i in range(n - 2, -1, -1):
                gain = h[i] - h[i + 1]
                left[i] = left[i + 1] + (gain if gain > 0 else 0)

            res = [str(max(left[i], right[i])) for i in range(n)]
            print(" ".join(res))

    solve()
    return sys.stdout.getvalue().strip()

 ## 特殊なケース

 次のような完全にフラットな配列の場合`1 5 7 7 7 7 7`、すべてのトランジションの高さの増加はゼロです。 このアルゴリズムは、左と右の両方の累積に対してゼロを生成し、上り坂の移動はまったく必要ないため、すべての開始位置は正確にゼロのエネルギーを返します。 

開始位置のピークの場合、`1 5 3 2 4 1`指標3から左側は、帰りに盛り上がる谷に降りるためエネルギーを必要とする可能性があります。 累積では上り坂の遷移のみが正確にキャプチャされるため、答えは移動距離ではなく、2 つの方向の上り坂のうち大きい方を反映します。 

次のような厳密に交互のパターンの場合`1 100 2 100 1`、各方向に複数の上りジャンプがあります。 プレフィックスとサフィックスの累積はこれらのスパイクを個別に捕捉し、最大値を取得することで、リセットなしの 1 回の実行では横断できないパスを混合することなく、開始位置が最悪の方向を考慮することが保証されます。
