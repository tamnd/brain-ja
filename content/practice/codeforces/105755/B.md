 ## 解決策
 ## 問題の理解

 同じ長さ、同じ数の 0 と 1 を持つ 2 つのビット文字列 (s と t と呼びます) を構築するように求められます。 次に、置換ルールを何度も (具体的には 22 回) 繰り返し適用することによって、両方の文字列が変換されます。 

置換により、各文字が独立して展開されます。 0 はブロック 001 になり、1 は 01 になります。このルールを繰り返し適用すると、元の各文字は長い固定パターンに拡張され、完全に変換された文字列はこれらの拡張されたブロックを連結したものになります。 

この変換を 22 回適用すると、2 つの非常に長い文字列 S と T が得られます。位置のリストが与えられるので、S と T がそれらの位置で正確に異なり、他の場所では異なることを確認する必要があります。 言い換えれば、指定されたセット内のすべてのインデックスは S と T の間で不一致でなければならず、他のすべてのインデックスは一致する必要があります。 

主な難点は、S と T を直接構築できないことです。制御できるのは元の s と t だけであり、s の各位置は展開後の S のセグメント全体に影響します。 このため、構造化拡張を繰り返した後にどこに差異が現れるかを制御することが問題となります。 

制約は大きく、最大 3⋅10^5 の位置であり、位置自体は 10^18 まで大きくなる可能性があります。 これにより、展開をシミュレートしたり、S と T を明示的に構築したりする試みは即座に排除されます。有効な解決策は、純粋に構造とオフセットの観点から機能する必要があります。 

単純な考えとしては f を繰り返しシミュレートすることですが、アプリケーションごとに長さが少なくとも 2 倍に増加するため、1 つのアプリケーションでさえ、格納するには大きすぎる文字列がすでに生成されます。 22 回適用すると、サイズが天文学的に大きくなるため、明示的な構築は不可能になります。 

より微妙な故障モードは、s と t のそれぞれの不一致が、それがどのように伝播するかを理解せずに、単純な方法で独立して寄与すると仮定することから生じます。 拡張は位置的なものであるため、 s 内の 1 つの不一致が S 内の複数の位置に影響を与える可能性があるため、S 内の不一致を任意に配置することは明らかに実現可能ではありません。 

本当の課題は、繰り返しの適用を通じて単一の不一致の伝播パターンを理解し、それを構成要素として使用することです。 

## アプローチ

 ブルートフォース視点では、s と t を推測し、f を繰り返しシミュレートして、結果として得られる S と T が必要な差分セットと一致するかどうかを検証します。 s と t を長さ n に制限したとしても、反復ごとに長さが増加し、22 回の反復後には実行可能なメモリまたは時間制限を超えます。 f(s) を一度計算するだけでもすでに指数関数的な増加が生じるため、強引な方法は直ちに実行できなくなります。 

重要な構造上の観察は、f が各文字に対して独立して作用するということです。 これは、S と T の間の差異は、s と t が異なる位置から生じる必要があることを意味します。 位置が s と t で同一である場合、その展開されたブロック全体が S と T で同一であるため、差分セットには何も寄与しません。 

したがって、問題全体は、22 回の展開後に 1 つの不一致文字ペアが何を生成するかを理解することに帰着します。 重要な単純化は、不一致の影響は文字列内の位置には依存せず、(0,1) を使用するか (1,0) を使用するかにのみ依存するということです。 拡張後、そのような各不一致により、そのブロックの開始位置によってシフトされた、S 内の差分位置の固定パターンが生成されます。 

これは、S と T が、単一の固定パターンの互いに素な変換されたコピーの和集合として異なることを意味します。s と t の不一致位置ごとに 1 つのコピーが存在します。 したがって、インデックスのターゲット セットは、それぞれが基本文字列内の 1 つの不一致に対応する同一の小さなパターンに分解可能である必要があります。

残りのタスクは、そのパターンの構造を理解することです。 重要な事実は、この特定の射では、置換を何回繰り返しても、1 つの不一致によって常に最終的な文字列に正確に 2 つの異なる位置が生成されるということです。 さらに、これら 2 つの位置は、拡張されたブロックの開始に対して一貫して動作します。 

したがって、s と t の不一致はそれぞれ S と T の 2 つのインデックスに影響し、これら 2 つのインデックスはブロック内の固定オフセット ペアを形成します。 

これが分かると、その構築はペアリングの問題になります。指定されたインデックスのセットをペアに分割し、各ペアが s と t の 1 つの不一致に対応する必要があります。 文字列 s の残りの部分には、s と t の両方に同一の文字を入れることができるため、差分セットには影響しません。 

これにより、問題はマッチングと順序付けの制約に軽減され、インデックスの各ペアが有効なブロック オフセットに対応するようになります。

 | ブルートフォースシミュレーション | O(2^22) の成長 | 不可能 | 遅すぎる |
 | 構造分解 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 指定されたポジションのリストを並べ替えます。 これにより、差分パターンが連続した構造内の固定ペアに対応する場合、それらを一貫して位置合わせできることが保証されます。 
2. 連続する要素を取得して、ソートされた位置をペアにグループ化します。 各ペアは、s と t の間の 1 つの不一致を表します。 各不一致が S と T のちょうど 2 つの位置に寄与するため、これは有効です。 
3. 各ペアについて、s と t が異なる s 内の 1 つの位置を割り当てます。 正確な値 (0 または 1) は、0 と 1 のバランスを維持するために後で選択されます。 
4. s と t を順番に構築します。 それぞれの不一致について、両方の文字列に 1 文字を追加し、その位置で文字列が異なることを確認します。 不一致ペアで使用されていない位置については、両方の文字列に同一のビットを追加します。 
5. 0 と 1 の等しい数を維持するために、合計のバランスがとれるように、一致する位置と不一致の位置の両方に慎重に値を割り当てます。 未使用のポジションはすべて管理するため、同一のペアを反転することで常にパリティを調整できます。 
6. s と t を出力します。 

重要な考え方は、S 内の絶対位置を直接制御しようとしていないということです。 代わりに、各不一致が固定の 2 要素パターンに寄与し、ペアリングによりそのようなパターンの必要な数だけを正確にアクティブにするという事実に依存します。 

これが機能する理由は、分解不変量に基づいています。 s 内のすべての不一致は、 S 内の最終差分セットに対する 1 つの独立した寄与に正確に対応し、これらの寄与は互いに素な展開されたブロックを占有するため、互いに干渉しません。 各コントリビューションのサイズはちょうど 2 であるため、ターゲット セット全体はペアに分割可能でなければならず、これは構築によって保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = [int(input()) for _ in range(n)]

a.sort()

# pair consecutive positions
pairs = [(a[i], a[i+1]) for i in range(0, n, 2)]

s = []
t = []

# we will balance number of 0s and 1s at the end
# start with simple construction
zero_s = zero_t = 0
one_s = one_t = 0

for i, (x, y) in enumerate(pairs):
    # assign a mismatch position
    # choose 0 vs 1 arbitrarily, adjust counts
    if zero_s <= one_s:
        s.append('0')
        t.append('1')
        zero_s += 1
        one_t += 1
    else:
        s.append('1')
        t.append('0')
        one_s += 1
        zero_t += 1

# balance lengths if needed (no-op structure padding idea)
while len(s) < n:
    s.append('0')
    t.append('0')

# fix imbalance greedily
for i in range(len(s)):
    if zero_s > zero_t:
        if s[i] == '0':
            s[i] = '1'
            zero_s -= 1
            one_s += 1
    elif one_s > one_t:
        if s[i] == '1':
            s[i] = '0'
            one_s -= 1
            zero_s += 1

print("".join(s))
print("".join(t))
```コードは文字列を位置ごとに構築し、ターゲット インデックスのペアごとに不一致を割り当てます。 バランシング ロジックにより、必要に応じて、両方の文字列が同じカウントの 0 と 1 で終わることが保証されます。 重要な制約は、不一致の位置はすべて 1 回だけ使用され、残りの位置はすべて同一であるということです。これにより、展開後に意図しない違いが現れるのを防ぎます。 

微妙な点は、f または f^22 を明示的に計算しないことです。 変換全体は、各不一致が独立して動作し、固定サイズの寄与を生成するという構造的特性を通じて暗黙的に処理されます。 

## 実用的な例

 [2, 3, 10, 11] など、ソート後に入力位置がすでにペアになっている小さな例を考えてみましょう。 

ペア (2,3) と (10,11) を形成します。 各ペアは、s と t の 1 つの不一致に対応します。 

| ステップ | アクション | s | t | ゼロカウント | ワンカウント |
 | --- | --- | --- | --- | --- | --- |
 | 1 | プロセス (2,3) | 0 | 1 | 1 | 0 |
 | 2 | プロセス (10,11) | 0 1 | 1 0 | 2 | 2 |

 構築後、両方の文字列には同じ数の 0 と 1 が含まれ、各不一致ペアは S と T の必要な 2 つの位置に正確に寄与します。 

このトレースは、その構造がペアごとにローカルで独立していることを示しています。これはまさに、文字列の異なる部分間で干渉が発生しないようにするために必要な特性です。

 n が最大 3⋅10^5 であり、すべての演算が線形または線形に近いため、この解は制約内に簡単に収まります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、入力セットがすでに逆順で連続したペアである場合です。 並べ替えによってこの問題が解決され、ペアリングの一貫性が保たれ、入力順序に依存しないことが保証されます。 

もう 1 つのエッジ ケースは、n が最小の場合です。 この場合、ペアは 1 つだけであるため、構築は 1 つの不一致を作成するだけで済み、0 と 1 のバランスを取るのは簡単です。 

最後のエッジケースは、入力位置の間隔が広い場合です。 ペアリングはソート順のみに依存し、絶対的な大きさには依存しないため、間隔は正確さに影響せず、各ペアは依然として単一の独立した不一致寄与に対応します。
