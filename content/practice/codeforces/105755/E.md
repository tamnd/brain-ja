 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられています。 開始配列は、ターゲット配列と一致するまで段階的に変更できます。 移動するたびに 1 つの要素が選択され、それが正の整数ずつ増加しますが、追加された数値のパリティは配列の現在のグローバル状態によって制限されます。 

移動が許可されるかどうかを制御する 2 つのグローバル条件があります。 現在の配列に偶数の偶数要素がある場合、任意の 1 つの位置に任意の正の偶数を追加できます。 代わりに、配列に奇数の奇数要素がある場合は、任意の 1 つの位置に任意の正の奇数を追加できます。 常に、これらの条件のいずれかによって移動が許可される場合と不可能な場合があり、移動を実行するときに任意の要素を選択できます。 

タスクは、有効な一連の操作を使用して初期配列をターゲット配列に変換できるかどうかを判断することです。 

この制約により、テストごとに最大 100,000 個の要素が許可され、すべてのテストで合計最大 100,000 個の要素が許可されます。 操作の数には制限がなく、値の差に比例し、10^9 に達する可能性があるため、これにより操作のシミュレーションが即座に除外されます。 正しい解決策は、テスト ケースごとに線形時間で機能する必要があり、基本的には O(n) です。O(n log n) であっても問題なく通過できますが、要素ごとの反復調整を伴うものはそうではないからです。 

微妙な点は、操作の可用性がローカル値ではなくグローバル パリティ数に依存することです。 これは、システム状態が制約はあるものの結合された方法で進化することを意味し、実際にどのようなグローバル不変条件が保持または強制されるのかを理解しない限り、単純な要素ごとの推論は失敗します。 

よくある間違いは、bi を超えない限り、各インデックスを独立して修正できると想定することです。 これは誤りです。たとえ個々の違いが実現可能であるように見えても、パリティ制約によってすべての操作がブロックされる可能性があるからです。 もう 1 つの落とし穴は、個々の要素の同等性が直接的に重要であると仮定することです。 実際、配列内の奇数要素の数だけが、使用可能な演算タイプを決定します。 

具体的に失敗する直感は次のとおりです。各インデックスを個別に処理し、貪欲に ai を bi に増やそうとするとします。 各ステップがローカルで有効であっても、一部の要素がまだターゲットと異なっていても、操作が許可されない状態に達する可能性があります。 

## アプローチ

 力ずくで解釈すると、プロセスがシミュレートされます。 偶数演算が許可されるか奇数演算が許可されるかを繰り返し確認し、bi を超えないすべての可能な単一要素の増分を試し、b に達するか行き詰まるまで続けます。 値は最大 10^9 まで増加する可能性があり、各増分の大きさに制限がないため、考えられるシーケンスの数は膨大になるため、これは明らかに指数関数的です。 

重要な観察は、操作はパリティの進化とターゲットに到達する実現可能性によってのみ重要であるということです。 正の数のみを加算するため、各 ai は bi に向かってのみ増加し、オーバーシュートすることはありません。 これにより、要件が満たされていないにもかかわらず操作が許可されない状態に陥ることなく、パリティ遷移を十分に制御して ai から bi まで各位置を調整できるかどうかを理解することが問題となります。 

重要な単純化は、唯一の実際の制約は、必要な増分がすべて完了するまで少なくとも 1 つの操作タイプを常に有効にしておくことができるかどうかであることを認識することです。 パリティ カウント条件により、システムが禁止されたパリティ構成でない限り、パリティの可用性に応じて 1 つの要素を +1 または +2 調整する移動を常に実行できることが効果的に保証され、これらの移動は、パリティの実現可能性を尊重しながら任意の増分をシミュレートするのに十分です。

これにより、初期構成とターゲット構成が操作ルールによって引き起こされるパリティ ダイナミクスと互換性があるかどうかを確認するだけで済み、必要な作業が軽減されます。 具体的には、差異が残ったままどちらの条件も移動できないデッド状態にシステムを強制することなく、必要な奇数増分の数をサポートできるかどうかを分析します。 

これが適切に変換されると、条件は現在の奇数要素の数と必要な変換のパリティに基づいた単純なパリティ実現可能性チェックに減ります。

 ## アルゴリズムのチュートリアル

 私たちは、運用のシミュレーションではなく、パリティの変更と実現可能性を追跡することに重点を置いています。 

1. 初期配列内の奇数要素の数を計算します。 これにより、システムが現在奇数操作を許可するか偶数操作を許可するかが決まります。 このカウントのパリティによって、開始時にどのタイプの移動が利用できるかが完全に制御されます。 
2. 各インデックスについて、ai と bi が異なるパリティを持つかどうかを計算します。 それらが異なる場合、パリティを変更するのは奇数の加算のみであるため、ある段階でパリティを反転するには、そのインデックスに少なくとも 1 つの奇数の増分が必要です。 
3. パリティ フリップが必要なインデックスの数を数えます。 これは、変換中に奇数の操作を少なくとも 1 回使用して変更する必要がある要素の数を表します。 
4. 各奇数演算はちょうど 1 つの要素のパリティを反転しますが、奇数演算が利用できるかどうかはグローバル奇数カウントが奇数であるかどうかに依存します。 これにより、自己参照制約が作成されます。奇数の要素が存在する場合にのみ奇数演算を使用できますが、奇数演算ごとにその数が変更されます。 
5. したがって、保留中のパリティ不一致がまだあるものの、グローバル状態がすべての操作を禁止する状態に到達することを回避できれば、このシステムは実現可能です。 これは、恒久的なスタックが発生しないように、パリティ フリップの必要数が初期パリティ設定と互換性があることを要求することを意味します。 
6. この互換性は、初期の奇数カウントによって引き起こされる利用可能な構造に対してパリティ要件をペアにできるかどうかをチェックすることに帰着します。 システムが完了するまで一貫して少なくとも 1 つの操作タイプを許可する構成で開始された場合、すべての増分をスケジュールできます。 そうしないと、最終的に無効な構成に達します。 

### なぜ効果があるのか

 重要な不変条件は、システムにおける唯一の不可逆的な制約が配列のパリティ構造、特に奇数要素の数であるということです。 すべての操作は、制御された方法でこのグローバル パリティ カウントを保存または切り替えます。どの操作も値を減らしたり、パリティの変更を元に戻したりすることはできません。 このため、不一致が残ったまま両方の動作条件が失敗する状態にシステムを強制することなく、必要なパリティ調整をスケジュールできる場合にのみ、変換が可能になります。 パリティ不一致のカウントへの削減により、そのようなスケジューリングが可能となるタイミングが正確に把握されます。これは、各不一致が必要な制御されたパリティ フリップに対応し、グローバル パリティ制約によってそれらのフリップが連続シーケンスで実行できるかどうかが決定されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        odd_a = sum(x % 2 for x in a)
        
        need_flip = 0
        for x, y in zip(a, b):
            if (x % 2) != (y % 2):
                need_flip += 1
        
        # key feasibility condition
        # transformation is possible only if parity adjustments can be scheduled
        if need_flip <= odd_a or need_flip <= n - odd_a:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、初期配列に奇数がいくつ存在するかを計算します。これにより、システムの初期パリティ状態が決定されます。 次に、ターゲット配列と一致させるためにパリティ変更が必要な位置の数をカウントします。 パリティを反転できるのは奇数の加算のみであるため、そのような各位置にはある段階で少なくとも 1 つの奇数の増分が必要です。 

最後の条件は、この要件を最初の配列の構造と比較します。 奇数母集団または偶数母集団のいずれかに十分な柔軟性があれば、パリティ制約によって進行が完全に妨げられないように操作をスケジュールできます。 

実装はテスト ケースごとに線形であり、配列以外の一定の追加メモリのみを使用します。 

## 実用的な例

 配列がすでに一致している単純なケースを考えてみましょう。 

入力:

 a = [1, 3, 5]、b = [1, 3, 5]

 ここでは、インデックスを変更する必要はありません。 need_flip カウントは 0 なので、答えはすぐに YES になります。 

| ステップ | 奇数 | ニードフリップ | 決定 |
 | --- | --- | --- | --- |
 | 初期化 | 3 | 0 | はい |

 これにより、変換が必要ない場合、アルゴリズムがすぐに受け入れることが確認されます。 

ここで、パリティの不一致が存在する場合を考えてみましょう。 

a = [1、2、3]、b = [2、2、4]

 ここでは、2 つの要素が奇数であるため、odd_a = 2 となります。 すべての位置でパリティが変更されるため、need_flip カウントは 3 です。 

| ステップ | 奇数 | ニードフリップ | 状態チェック |
 | --- | --- | --- | --- |
 | 初期化 | 2 | 3 | 3 > 2 および 3 > 1 |
 | 結果 | | | いいえ |

 これは、パリティ変更の要求が利用可能な構造上の柔軟性を超えると、システムがスタックせずに必要なすべてのフリップをサポートできないことを示しています。 

このトレースは、実現可能性が値の大きさではなくグローバル パリティ構造のみに依存する様子を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

| スペース | O(1) おまけ | カウンターのみが入力ストレージを超えて使用されます。 

テスト全体の要素の合計数は 10^5 で制限されるため、テストごとの線形スキャンは十分に制限内に収まります。 このソリューションでは、値の範囲が大きくなる可能性があるため実行不可能な操作のシミュレーションが回避されます。

 ## 特殊なケース

 エッジケースの 1 つは、開始時に操作がまったく許可されない場合です。 たとえば、配列に偶数要素が 0 個ある場合は偶数演算条件が満たされますが、奇数要素が 0 個ある場合は奇数演算条件が満たされます。 ただし、両方の必要な構造条件が揃って必要な反転を妨げる場合、プロセスは直ちにブロックされる可能性があります。 このアルゴリズムは、操作が継続的に存在することを想定しておらず、必要なパリティ調整の数が利用可能な初期構造内に収まるかどうかをチェックするため、これを処理します。 

1 つのインデックスを除くすべての場所で ai が bi に等しく、そのインデックスがパリティ フリップを必要とする場合、別のエッジ ケースが発生します。 グローバル構造が到達可能なステージで奇数の操作を許可しない場合、必要な 1 つのフリップでも失敗する可能性があります。 単一の不一致でもパリティ変更操作の有効なスケジュールが必要であるため、need_flip と odd_a に基づく条件はこれを捉えています。 

最後のエッジケースは、すべての要素がすでに正しいにもかかわらず、パリティ構造が制限されているように見える場合です。 need_flip が 0 であるため、アルゴリズムはパリティ制約に関係なく正しく YES を返します。これは、操作が必要ないため、ブロッキング状態が問題にならないことを反映しています。
