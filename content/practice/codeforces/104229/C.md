 ## 解決策
 ## 問題の理解

 頂点が人々を表し、エッジが友情を表す、接続された無向グラフが与えられます。 2 人のプレーヤーが交代でエッジに沿って移動し、グラフ内を効果的に歩き回りますが、各エッジはプレイ全体を通して最大 1 回しか使用できないという厳格なルールが適用されます。 ウォークは頂点 1 (マリア) から始まり、すべての移動は、現在の頂点から隣接する頂点まで未使用のエッジをトラバースすることで構成されます。 

重要な点は、これがインタラクティブなゲームであるということです。 Maria の番になったら、関数を呼び出して彼女の手を取得するか、彼女が有効な手を持っておらず、放棄したことを検出する必要があります。 マリアの番ではない場合、私たちは未使用のエッジを使用して合法的な手を選択することで対応します。 プレイヤーが移動を強いられたものの、未使用のインシデント エッジがなくなった場合、ゲームは終了します。 

目的は、任意のプレーをシミュレートすることではなく、他のプレーを調整することです。$n-1$頂点を調整することで、マリアは最終的に自分のターンで未使用のエッジがなくなる位置に到達します。 言い換えれば、マリアの番で散歩を強制的に終了させ、マリアを負けさせようとしているのです。 

制約$n \le 2 \cdot 10^5$そして$m \le 4 \cdot 10^5$は、どの戦略もエッジの数が線形またはほぼ線形でなければならないことをすぐに示します。 状態空間には現在の頂点だけでなく、どのエッジが使用されているかも含まれており、指数関数的であるため、考えられるすべてのゲーム状態について明示的に推論することは不可能です。 

この問題の微妙な点は、エッジがプレーヤーごとではなくグローバルに消費されることです。 これは、ゲームが事実上、敵対的に構築されるオイラー トレイルであることを意味し、両方のプレイヤーがエッジを再利用せずに交互に同じパスを延長します。 

素朴な失敗事例がサイクル付きのグラフで表示されます。 たとえば、1-2-3-1 のトライアングルで、パリティを考慮せずにマリアの動きを恣意的に「ミラーリング」すると、彼女に有利なエッジが使い果たされるまで永久にプレイできるサイクルへのアクセスを彼女に与えることになるかもしれません。 もう 1 つの失敗例は、頂点 1 がカット頂点ではなく、複数の互いに素な枝を持つグラフです。 素朴な貪欲な遊びによって、マリアがサブツリーを使い果たし、別のサブツリーに逃げ込み、代わりに私たちに行き止まりを残してしまう可能性があります。 

これらの問題は、ローカルでの貪欲な決定が不十分であることを示しています。 正しい解決策は、エッジのグローバル ペアリング構造について推論する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、ゲームを明示的にシミュレートし、未使用のエッジのセットを維持し、各動きで可能なすべての応答を試行します。 各ステップで、Maria は隣接する未使用のエッジを選択することができ、私たちも同様に応答します。 これにより、各状態が現在の頂点、ターン、使用エッジ セットによって定義されるゲーム ツリーが形成されます。 私たちの側からの分岐を無視したとしても、マリアは学位の中から選択することができ、州の数は段階的に増加します。$O(2^m)$エッジ使用の組み合わせによるものです。 これは直ちに実行不可能です。 

重要な構造上の観察は、トラバースの順序は重要ではなく、各頂点でのエッジの使用のパリティのみが重要であるということです。 すべてのエッジが 1 回だけ使用されるかまったく使用されず、グラフが接続されているため、このプロセスは、行き詰まるまで頂点間を交互に繰り返すトレイルを構築することに似ています。 勝者は、マリアのターンで未使用のインシデント エッジが残っていない頂点でトラップされるのがマリアであることを保証できるかどうかにかかっています。 

これは古典的なアイデアになります。各頂点でエッジをペアにして、マリアが頂点に入るたびに強制退出戦略を立てることができれば、常に決定論的に対応できるようになります。 基本的な構造は、頂点に付随するエッジのペアを維持することで、トラバースが常に制御されたペアのエッジを消費するようにすることです。 これは、エッジをオイラー トレイル応答システムをシミュレートする戦略に分解することに密接に関連しています。 

各頂点に、ペアで一致させる必要があるインシデント エッジがあるとみなしたら、問題を隣接リストに基づいて一貫したペアリング戦略を構築することに集約できます。 私たちは常に、未使用のエッジを取得してマークすることで対応し、Maria の順番で強制されない限り、頂点を「アンバランスな」状態のままにしないようにします。 

最適なソリューションは、ウォークのスタックのようなシミュレーションを維持し、常に入力エッジと出力エッジを貪欲かつ一貫してペアリングし、応答するたびに、すべての非開始頂点が均等な使用状態のままになるという不変条件を確実に保持します。

 ## アルゴリズムのチュートリアル

 重要なアイデアは、動的なトレイルを維持し、現在の頂点の未使用のエッジを消費することで常に応答することです。 また、使用済みのエッジも追跡するため、再利用することはありません。 

1. グラフの隣接リストを構築し、各エッジが使用されているかどうかをマークするブール配列を維持します。 これが必要なのは、制約によってエッジの再利用が禁止されており、正確さがこのルールの厳密な適用に依存するためです。 
2. GetMove() を呼び出して、Maria の最初の動きを待ちます。 これにより、最初の現在の頂点が確立されます。 マリアが動いた瞬間、私たちは彼女が選んだ頂点に位置し、順番が来ます。 
3. 現在の頂点から、未使用の入射エッジを選択します。 次に、MakeMove(v) を呼び出してそれを走査します (v は近傍です)。 これにより、エッジが 1 回使用されるというルールを尊重しながら、常にウォークを延長することが保証されます。 
4. 各移動後、すぐに GetMove() を呼び出して Maria の応答を取得します。 この交代は厳密なターン構造を維持します。 
5. いずれかの時点で GetMove() が 0 を返した場合、Maria には有効な移動がありません。 ゲームはマリアの負けで終了するため、直ちに終了して成功を返します。 
6. 時期尚早にスタックしないように、頂点にいるときは常に、利用可能な未使用のエッジを優先します。 Maria はエッジのみを消費することができ、私たちは常に即時に応答するため、強制されない限り、未使用のエッジを放置することはありません。 

基本的なメカニズムは、ウォークが継続的にエッジを消費することであり、私たちは常に Maria の位置からすぐに伸びるため、彼女に最後の動きを与える方法で頂点を孤立させることを防ぎます。 

### なぜ効果があるのか

 維持される不変条件は、ゲームが自分たちの番である頂点にあるときはいつでも、未使用のエッジが存在する場合は、すぐにそれを消費するということです。 これにより、マリアが最初に頂点を使い果たす孤立した奇数過剰状況を決して制御できなくなることが保証されます。 すべてのエッジは 1 回だけ使用され、グラフは有限であるため、プロセスは終了する必要があり、即時応答の構造により、可能な限り Maria のターンで終了が行われることが保証されます。 交互の消費は、Maria からパリティの利点を強制的に引き離す方法で、エッジの使用を効果的に組み合わせます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def SocialEngineering(n, m, edges):
    from collections import defaultdict, deque

    adj = [[] for _ in range(n + 1)]
    used = [False] * m

    for i, (u, v) in enumerate(edges):
        adj[u].append((v, i))
        adj[v].append((u, i))

    ptr = [0] * (n + 1)

    def get_unused(u):
        while ptr[u] < len(adj[u]) and used[adj[u][ptr[u]][1]]:
            ptr[u] += 1
        if ptr[u] < len(adj[u]):
            v, eid = adj[u][ptr[u]]
            ptr[u] += 1
            return v, eid
        return None, None

    cur = GetMove()
    if cur == 0:
        return

    while True:
        v, eid = get_unused(cur)
        if eid is None:
            return
        used[eid] = True
        MakeMove(v)

        cur = GetMove()
        if cur == 0:
            return
```このソリューションは隣接リストを構築し、既に使用されているエッジを効率的にスキップする頂点ごとのポインターを維持します。 各エッジは 1 回だけ使用されるとマークされ、各隣接エントリは最大 1 回スキャンされるため、線形的な複雑さが保証されます。 

インタラクション ループは、マリアの動きと私たちの反応を交互に繰り返します。 私たちは常に、彼女の現在の位置から次に利用可能な未使用のエッジで貪欲に応答します。 ポインタの最適化により、すでに使用されているエッジを繰り返しスキャンすることがなくなります。 

実装の微妙な詳細は、MakeMove を呼び出す前に常に枯渇をチェックする必要があることです。 未使用のエッジが存在しない場合は、マリアが次のチェックで必ず負けるか、ゲームが一貫して終了するため、すぐに戻らなければなりません。

 ## 特殊なケース

 シングルエッジ グラフ 1-2 は、最も直接的な終了シナリオです。 Maria は 1 から開始し、2 に移動しますが、その後続行できなくなります。 アルゴリズムは、エッジが消費されると利用可能なエッジがなくなり、マリアのターンで負けます。 

1-2-3-1 のようなサイクルでは、マリアの観点から、素朴で貪欲なプレイによってサイクルが永久に存続する可能性があることが懸念されます。 ただし、すべての移動がエッジを消費し、常に即座に応答するため、最大 3 ペアの移動でサイクルが使い果たされ、その後 Maria には残りの隣接関係がなくなり、GetMove は 0 を返します。 

1 を中心とする高次の星では、マリアには最初は多くの選択肢があります。 このアルゴリズムにより、彼女の選択のそれぞれが、別のエッジを消費する応答と即座にペアになり、中心にあるすべてのインシデント エッジが急速に枯渇し、すでに消費された接続に再度アクセスできないことが保証されます。
