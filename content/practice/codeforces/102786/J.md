 # 問題の理解

 私たちには方向性のない道路網があります。 各家は頂点、各道路はエッジであり、すべての道路には整数のラベルが付いています。 指定された家から別の家まで移動する必要がありますが、ルートのコストは道路の長さの合計ではありません。 コストは、そのルートで使用されるすべての道路値のビット単位の OR です。 タスクは、すべてのルートの中で可能な限り最小のそのような値を見つけること、または 2 つの家が接続されていないことを報告することです。 

入力は、最大 100,000 個の頂点と 100,000 個のエッジを持つグラフを記述します。 重みは 10^9 まで大きくなるため、出現できるバイナリ位置は約 30 個だけです。 このサイズのグラフでは、パスを列挙したり、考えられるすべてのルートの組み合わせに対して検索を実行したりするアルゴリズムは直ちに排除されます。 ダイクストラなどの通常の最短経路アルゴリズムでさえ、OR には必要な加法特性がないため、直接適用できません。 

主な難点は、エッジが多いルートの方が、エッジが少ないルートよりも優れている可能性があることです。 たとえば、重み 8 と 1 のパスの値は 9 ですが、重み 10 の単一エッジの値は 10 です。エッジの数は無関係で、ルートに現れるビットのセットのみが重要です。 

単純な実装を壊すエッジケースがいくつかあります。 グラフが切断されている場合、答えは大きな初期値ではなく -1 でなければなりません。 例えば：```
3 1
1 2 7
1 3
```正しい出力は次のとおりです。```
-1
```答えをゼロに初期化するか、既存のエッジのみをチェックする不注意な解決策では、家 3 に到達できない場合でも、誤った値が返される可能性があります。 

2 番目のトラップは、道路の数が最も少ないパスが最適であると仮定することです。 考慮する：```
3 3
1 2 6
2 3 1
1 3 7
1 3
```正しい出力は次のとおりです。```
7
```直接道路では 7 が得られ、2 本の道路があるルートでは 6 OR 1 が得られ、これも 7 になります。エッジ数に基づく方法では、実際の最適化問題は解決されません。 

もう 1 つのよくある間違いは、ビットを間違った方向に処理することです。 上位ビットのバイナリ値がすべての下位ビットを支配するため、上位ビットの削除は、上位ビットなしでも接続が可能かどうかを確認した後にのみ実行できます。 たとえば、削除できたはずのビットをソリューションが誤って保持してしまった場合、後から下位ビットを最適化しても結果を修正できません。 

# アプローチ

 直接的な総当たりアプローチでは、2 つの頂点間のすべての可能なパスを探索し、すべてのパスの OR を計算しようとします。 これは正しいです。考えられるすべての答えは何らかのパスから得られますが、密なグラフ内のパスの数は指数関数的に増加する可能性があります。 100,000 のエッジを持つグラフであっても、膨大な数の異なるルートが含まれる可能性があるため、列挙することは不可能です。 

もう少し構造化されたアイデアは、最短パス アルゴリズムを使用し、頂点ごとにこれまでに見つかった最良の OR 値を保存することです。 頂点から隣接頂点への遷移は次のようになります。```
new_value = current_value | edge_weight
```問題は、頂点に到達できるさまざまな OR 値の数が、自然には 1 に制限されないことです。 通常のダイクストラ引数は、パス長と加算の組み合わせに依存しますが、OR を使用すると、以前は見栄えが悪かった状態が後で役立つようになります。 通常の最短パス フレームワークは、OR 値の特別な構造を利用しません。 

重要な点は、OR 結果には、選択したルートの少なくとも 1 つのエッジに現れるビットのみが含まれるということです。 ルートを直接構築しようとする代わりに、少しずつ答えを構築できます。 

現在、応答に含めることがまだ許可されているビットのセットがあるとします。 1 ビットを削除しても、残りのマスク内に収まるエッジのみを使用して 2 つのターゲット頂点がまだ接続されている場合、そのビットは不要であり、永久に破棄できます。 これを削除するとグラフが切断される場合は、すべての有効なルートでそのビットが必要になるため、それを保持する必要があります。 

これにより、問題は接続チェックが繰り返されることになります。 エッジの重みには関連するビットが約 30 個しかないため、必要なチェックは約 30 回だけです。 各チェックは、素のセット共用体構造を使用して実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | パス数の指数関数 | O(n + m) | 遅すぎる |
 | 最適 | O(B(n + m) α(n)) ここで、B はビット数 | O(n) | 承認済み |

 # アルゴリズムのチュートリアル

 1. グラフ内のすべてのエッジの重みの OR を含むマスクを計算します。 有効なルートには、このマスクに存在するビットのみを含めることができるため、これが考えられる最大の答えになります。 
2. 最上位ビットから最下位ビットまでビットを処理します。 現在のビットについては、一時的にマスクから削除し、設定ビットがすべてこの小さなマスクに含まれるエッジのみを使用して、開始頂点が目的地に到達できるかどうかをテストします。 
3. 接続テスト中に、素の集合結合構造を構築します。 すべてのエッジについて、重みが満たされる場合はその端点をマージします。`(weight & mask) == weight`。 この条件は、エッジに禁止ビットが導入されていないことを意味します。 
4. ビットを削除した後、2 つの頂点が同じコンポーネント内にある場合は、ビットを削除したままにしておきます。 接続が切断されている場合は、考えられるすべてのルートでビットが必要となるため、ビットを復元します。 
5. すべてのビットが処理された後、残りのマスクは可能な最小の OR 値になります。 元のグラフで接続が許可されなかった場合、最終マスクではそのケースを区別するのに十分ではないため、最終接続チェックを実行し、宛先に到達できない場合は -1 を出力します。 

この貪欲なプロセスが正しい理由は、2 進数が辞書編集的に最大の異なるビットによって順序付けされているためです。 少し考えてみると、ルートがなくても有効なルートがまだ存在する場合は、ルートを維持するよりも削除する方が常に優れています。 その後の決定は下位ビットにのみ影響し、不必要に上位ビットを保持することを補償することはできません。 不変条件は、ビットのプレフィックスを処理した後、現在のマスクが有効なルートを許可する、すでに考慮された上位ビットの可能な最小のセットであるということです。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    edges = []
    mask = 0

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v, w))
        mask |= w

    a, b = map(int, input().split())
    a -= 1
    b -= 1

    def connected(cur_mask):
        parent = list(range(n))
        size = [1] * n

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def union(x, y):
            x = find(x)
            y = find(y)
            if x == y:
                return
            if size[x] < size[y]:
                x, y = y, x
            parent[y] = x
            size[x] += size[y]

        for u, v, w in edges:
            if (w & cur_mask) == w:
                union(u, v)

        return find(a) == find(b)

    if not connected(mask):
        print(-1)
        return

    for bit in range(30, -1, -1):
        candidate = mask & ~(1 << bit)
        if connected(candidate):
            mask = candidate

    print(mask)

if __name__ == "__main__":
    solve()
```変数`mask`は、不要なビットを削除した後でも可能な最良の答えを表します。 グラフのどこにも現れないビットをルートに含めることはできないため、すべてのエッジの OR として開始されます。 

の`connected`繰り返しグラフテストを実行する関数です。 新しいグラフを構築する必要はありません。 代わりに、現在のマスクと互換性のある重みを持つエッジを正確に結合します。 表現`(w & cur_mask) == w`エッジで使用されるすべてのビットが許可されていることを確認します。 

素セット結合の実装では、サイズによるパス圧縮と結合を使用して、すべての接続チェックを線形時間に近づけます。 重みは最大 10^9 であるため、ビット 30 から 0 までをチェックすると、設定可能なすべてのビットがカバーされます。 

最終マスクだけでは、到達不可能なグラフと、応答が 0 の到達可能なグラフとの違いを表すことができないため、最初の接続性チェックが必要です。 重みゼロのエッジのみを含むパスは有効であり、ゼロを返す必要があります。

 # エッジケース

 グラフが切断された場合は、ビットの削除が開始される前に処理されます。 入力の場合:```
3 1
1 2 7
1 3
```初期マスクは 7 です。最初の接続チェックでは、頂点 3 が頂点 1 と同じ DSU コンポーネントにないことが判明したため、アルゴリズムはすぐに -1 を返します。 存在しないルートを最小化しようとすることはありません。 

このアルゴリズムは、重みがゼロのエッジを持つルートも正しく処理します。 のために：```
2 1
1 2 0
1 2
```初期マスクはゼロです。 接続チェックではエッジのみが受け入れられます。`(0 & 0) == 0`。 どのビットも削除できず、答えはゼロのままです。 

多くのエッジを持つルートは直接エッジよりも優れている可能性があり、アルゴリズムはどちらも優先しません。 のために：```
4 4
1 2 8
2 3 4
3 4 2
1 4 15
1 4
```直接エッジの場合は 15 になります。より長いパスの場合は 15 になります。`8 | 4 | 2 = 14`。 貪欲な削除では各上位ビットをチェックし、頂点が接続されたままビット 0 が消え、最小値として 14 が残る可能性があることを発見します。 

最後のエッジケースには上位ビットが含まれます。 このアルゴリズムは 30 から 0 までのすべての可能なビットを処理するため、1073741823 などの重みはオーバーフローや重要な位置の欠落なしに処理されます。 

この社説は、必要に応じて、より短く、よりコンテスト風に、またはより証明に重点を置くように調整できます。
