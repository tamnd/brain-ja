 # 問題の理解

 並んでいます`n`商品。重みの配列で表されます。 行は時間の経過とともに変化します。各クエリは 2 つの位置で要素を交換します。 スワップのたびに、配列全体が非降順でソートされているかどうかを判断する必要があります。 

答えは、配列がどのようにして現在の状態になったかには依存しません。 スワップ後の各瞬間において、すべての要素がその直後の要素より大きくないかどうかだけを知る必要があります。 

この制限により、クエリのたびに配列全体をチェックすることを避ける必要があります。 と`n`そして`q`どちらも到達`100000`、すべてをスキャンするソリューション`n`各スワップのポジションは最大で実行されます`10^10`これは 2 秒の制限をはるかに超えています。 各クエリによって、保持されている少量の情報のみが変更されるソリューションが必要です。 

主なエッジケースは、スワップが必ずしもスワップされた 2 つのポジションのみに影響を与えるわけではないという事実から生じます。 隣接する要素との関係も変化する可能性があります。 例えば：```
Input
3 1
1 3 2
2 3
```交換後の配列は次のようになります`[1, 2, 3]`したがって、出力は次のようになります。```
Sorted!
```スワップされた値自体が正しい順序であるかどうかだけをチェックするソリューションでは、位置での隣接関係が次のとおりであるという事実を見落とします。`1`も変わりました。 

もう 1 つの重要なケースは、値が等しい場合です。```
Input
3 1
5 5 5
1 3
```出力は次のとおりです。```
Sorted!
```次のような厳密な比較`a[i] < a[i+1]`隣接する等しい値が許可されるため、この配列は誤って未ソートとしてマークされます。

```最初のスワップの後、配列はソートされますが、2 回目のスワップで再びソートされます。 最初に成功した時点で停止するのではなく、現在の状態とは独立してすべてのクエリに回答する必要があります。 

# アプローチ

 簡単なアプローチは、すべてのスワップをシミュレートし、配列全体をスキャンして、すべての隣接するペアが順序付けされているかどうかを確認することです。 非減少配列は、すべての隣接する比較が満たされる配列であるため、これは正しいです。`a[i] <= a[i+1]`。 

問題はコストです。 それぞれの`q`クエリには最大で`n-1`比較の結果、`O(nq)`仕事。 最悪の場合はこれくらいです`10^10`動作が遅すぎます。 

問題の構造から、より小さなターゲットが得られます。 スワップでは 2 つの位置の値のみが変更されるため、ほとんどの隣接するペアはまったく同じ順序を維持します。 現在間違っている隣接するペアの数を維持する場合、1 回のスワップでは、スワップされた位置に接するペアを更新するだけで済みます。 

このカウントが 0 の場合、配列は正確にソートされます。 スワップの前に、影響を受ける隣接ペアの寄与を削除し、スワップを実行してから、それらの新しい寄与を追加します。 各位置には隣接する位置が 2 つしかないため、クエリごとに一定数のペアが変更されます。

 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | 最適 | O(n+q) | O(n) | 承認済み |

 # アルゴリズムのチュートリアル

 1. 不正な隣接ペアのカウンターを構築します。 あらゆるインデックスに対して`i`、どうかを確認してください`a[i] > a[i+1]`。 これが真の場合、そのペアはソート順序に違反しており、カウンターが増加します。 
2. 各交換クエリについて、交換される 2 つのポジションを特定します。 変更できる隣接ペアは、交換された位置を含むペアのみであるため、変更を行う前にそれらのインデックスを収集してください。 
3. 影響を受けるすべての隣接ペアの古い寄与をカウンターから削除します。 現在の値がこれらの位置から消えようとしているため、この手順が必要です。 
4. 2 つの配列値を交換します。 
5. スワップ後に、影響を受けるすべての隣接ペアの新しい寄与を追加します。 カウンタは現在の配列を再度説明します。 
6. カウンタがゼロの場合は、次のように出力します。`Sorted!`。 それ以外の場合は、印刷します`Unsorted!`。 

これが機能する理由は、非減少配列内で考えられるすべての無秩序が不良な隣接ペアとして現れるためです。 隣接するペアが減少していない場合、すべての要素は最大でも次の要素になります。これは、配列全体がソートされていることを意味します。 スワップ操作では、スワップされた位置のいずれかに隣接しないペアを変更することはできないため、それらのペアのみを更新すると、違反の正確な数が保持されます。 

# Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    bad = 0
    for i in range(n - 1):
        if a[i] > a[i + 1]:
            bad += 1

    ans = []

    def value_bad(i):
        return i >= 0 and i + 1 < n and a[i] > a[i + 1]

    for _ in range(q):
        x, y = map(int, input().split())
        x -= 1
        y -= 1

        affected = set()

        for pos in (x, y):
            affected.add(pos - 1)
            affected.add(pos)

        for pos in affected:
            if value_bad(pos):
                bad -= 1

        a[x], a[y] = a[y], a[x]

        for pos in affected:
            if value_bad(pos):
                bad += 1

        if bad == 0:
            ans.append("Sorted!")
        else:
            ans.append("Unsorted!")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```変数`bad`隣接する反転の数を格納します。 ヘルパー関数は、配列の外側の位置は決してカウントされるべきではないため、境界も処理しながら、特定の隣接ペアが無効かどうかをチェックします。 

交換された位置が隣り合っている場合、影響を受けるセットに重複が含まれる可能性があります。 セットを使用すると、同じ隣接するペアを 2 回削除または追加することが回避されます。 これはポジションなどのスワップの場合に重要です`2`そして`3`、両方の位置が隣接するペアを共有します。 

このコードは、次で始まる入力形式から位置を変換します。`1`、で始まる Python インデックスに変換します。`0`。 以前の状態を削除せずに変更された配列をカウントすると、配列の 2 つの異なるバージョンが混在することになるため、交換は古い寄与が削除された後にのみ発生します。

 # エッジケース

 値が等しい場合、アルゴリズムは次を使用します。`>`それよりも`>=`不良ペアを数えるとき。 入力あり:```
3 1
5 5 5
1 3
```影響を受ける隣接ペアは交換後にチェックされますが、両方の比較は有効なままです。`5 <= 5`。 カウンタはゼロのままで、答えは`Sorted!`。 

配列全体を修正するスワップの場合、アルゴリズムは交換前に古い不良ペアを削除してから、新しいペアを追加します。 と：```

2 つの隣接する位置を変更するスワップの場合、影響を受ける重複したインデックスを 2 回処理してはなりません。 で：```
