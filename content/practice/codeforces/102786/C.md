 ## 解決策
 ## 問題の理解

 このタスクは、対話型のグラフ再構成問題です。 ホールからスタート`0`、そして最初のホールで`0`を通して`N`すでに到達可能です。 その後、ドローンは発見されたトンネルの破片を繰り返し送信します。 各フラグメントには、ホール番号の間にいくつかの方向のないエッジが含まれています。 フラグメントを受信するたびに、収集した情報が現在の到達可能なエリアからホールまでの経路を構築するのに十分であるかどうかを直ちに判断する必要があります。`9999`。 その場合は印刷します`ATTACK`; それ以外の場合は印刷します`WAIT`そしてドローンの飛行を続行させます。 

入力はオンラインで行われるため、通常とは異なります。 最初の行は最初に利用可能なセットのサイズを示し、その後のすべての行は検出されたエッジの新しい部分です。 出力は固定入力に対する最終的な答えではなく、各更新後の一連の決定です。 

ほぼあり得る`100000`ホール。 これにより、ドローン メッセージが送信されるたびにグラフ検索を最初から再構築することが直ちに排除されます。 更新のたびにすべての既知のエッジにわたる完全な BFS または DFS を実行すると、同じエッジを何千回も処理する可能性があり、5 秒の制限の下ではコストが高すぎます。 接続性を段階的に更新できる構造が必要です。 

主なエッジケースは、入力のオンラインの性質によって引き起こされます。 パスは新しいフラグメントを処理した直後に表示される可能性があるため、フラグメントを読み取る前にのみチェックすると、必要な攻撃の瞬間を逃してしまいます。 

たとえば、最初の行が次のようになっているとします。```
0
```唯一のドローンメッセージは次のとおりです。```
1 0 9999
```正しい出力は次のとおりです。```
ATTACK
```印刷するソリューション`WAIT`新しいエッジを適用する前に、許可された攻撃の瞬間をすでに逃したかどうかを後でチェックするだけです。 

もう 1 つの微妙なケースは、クイーンが間接的に接続されている場合です。```
0
2 0 5 5 9999
```正しい出力は次のとおりです。```
ATTACK
```エッジ`0-5`ホールを直接含まない`9999`ですが、2 つのエッジが一緒になってルートを形成します。 直接隣接するものだけをチェックする`0`失敗するだろう。 

3 番目のよくある間違いは、最初のホールがすでにアクセス可能であることを忘れることです。 入力が次で始まる場合:```
3
```それからホール`0`、`1`、`2`、 そして`3`最初のドローン応答前にすべてが利用可能になります。 正しいソリューションでは、最初からこれらを 1 つの到達可能なコンポーネントとして扱う必要があります。 

## アプローチ

 簡単な解決策は、発見されたすべてのトンネルを保存し、ドローン メッセージごとに現在到達可能なホールからグラフ検索を実行することです。 これは正しいです。なぜなら、答える必要がある唯一の質問は、`9999`は開始位置を含むコンポーネントに属します。 ただし、同じ古​​いエッジが何度もスキャンされます。 まで`100000`ホールや多くの更新があり、グラフ全体を繰り返し走査すると、数十億のエッジ チェックに到達する可能性があります。 

問題の構造から、より簡単な見方が得られます。 正確なルート、距離、ツリー構造は必要ありません。 2 つのホールが同じ接続コンポーネント内にあるかどうかを知る必要があるだけです。 トンネルを追加すると、2 つのコンポーネントがマージされるだけで、分離されることはありません。 これはまさに、素のセット共用体構造が当てはまる状況です。 

当初は全ホール`0`を通して`N`到達可能なコンポーネントに属します。 すべてのドローン メッセージについて、受信した各エッジの 2 つのエンドポイントを結合します。 メッセージ内のすべてのエッジが処理された後、ホールかどうかを確認します。`9999`ホールと同じ代表者がいる`0`。 「はい」の場合、パスは存在します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(U * (V + E)) | O(V + E) | 遅すぎる |
 | 最適 | O((V + E) α(V)) | O(V) | 承認済み |

 ここ`U`はドローンのアップデートの数であり、`α(V)`は逆アッカーマン関数であり、非常にゆっくりと増加するため、事実上一定です。 

## アルゴリズムのチュートリアル

 1. 考えられるすべてのホールに対して素のセット和集合構造を作成します。 ホール番号は最大まで上がる可能性があるため、`99999`、考えられるすべての頂点に十分なスペースを準備します。 

最初に到達可能なホールは次のとおりです。`0`を通して`N`、したがって、それらはすでに開始位置に接続されている必要があります。 それぞれをホールと一体化させます`0`。 
2. 次のドローンメッセージを読みます。 最初の数値は検出されたトランジションの数で、その後にその数のホール番号のペアが続きます。 

各ペアは無向トンネルを表します。 トンネルは両方のホールが相互に到達可能になることを意味するため、それらのコンポーネントをマージします。 
3. メッセージ全体を処理した後、ホールのコンポーネントを比較します。`0`そしてホール`9999`。 

それらが等しい場合、収集された情報にはすでに女王へのルートが含まれているため、次のように出力します。`ATTACK`そして終了します。 それ以外の場合は印刷します`WAIT`、出力をフラッシュし、次のフラグメントを待ちます。 

なぜ効果があるのか:

 不変条件は、任意の数のドローン メッセージを処理した後、発見されたトンネルによって 2 つのホール間にルートが存在することが証明された時点で、2 つのホールは同じ素のセット結合コンポーネント内にあるということです。 最初は、アクセス可能なホールが統合されるため、これは当てはまります。 新しい各トンネルは 2 つのコンポーネント間の可能な接続を作成するだけであり、ユニオン操作はまさにそのマージを実行します。 すべてのエッジが対応するコンポーネントに接続されていない限り、有効なルートは存在できません。そのため、ホールかどうかをチェックします。`9999`ホールと同じコンポーネントに属します`0`攻撃経路が存在するかどうかを確認することに相当します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]

def main():
    n = int(input())
    dsu = DSU(100000)

    for i in range(1, n + 1):
        dsu.union(0, i)

    for line in sys.stdin:
        if not line.strip():
            continue

        data = list(map(int, line.split()))
        k = data[0]

        idx = 1
        for _ in range(k):
            u = data[idx]
            v = data[idx + 1]
            idx += 2
            dsu.union(u, v)

        if dsu.find(0) == dsu.find(9999):
            print("ATTACK")
            sys.stdout.flush()
            return
        else:
            print("WAIT")
            sys.stdout.flush()

if __name__ == "__main__":
    main()
```の`DSU`クラスには、すべてのホールを表す接続コンポーネントが格納されます。 パス圧縮`find`サイズによるユニオンは内部ツリーを浅く保ちながら、将来の検索を非常に高速にします。 

初期化ループは、最初に利用可能なすべてのホールをホールに接続します。`0`。 入力ではこれらのエッジが明示的にリストされていないため、これは見落とされやすい部分です。 ドローンはプログラムの開始後にのみ追加のトンネルを提供します。 

受信フラグメントごとに、コードは最初にすべての新しいトンネルを適用し、その後でのみ答えをチェックします。 必要な攻撃の瞬間が最新のフラグメントが到着した直後になる可能性があるため、順序は重要です。 

これは対話型タスクであるため、すべての応答後のフラッシュが必要です。 これがないと、ジャッジはプログラムの決定を待っているため、次のフラグメントを送信できない可能性があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((N + E) α(100000)) | すべての最初のマージと検出されたすべてのエッジは、ほぼ一定の償却作業を実行します。 
| スペース | O(100000) | DSU は、考えられるホールごとに 1 つの親値と 1 つのサイズ値を保存します。 

ホールの最大数は、固定 DSU アレイには十分小さいです。 このソリューションは、エッジを受信した後にすべてのエッジを再度スキャンすることはないため、ドローンが多数更新されても効率が維持されます。 

## テストケース```python
import sys
import io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    class DSU:
        def __init__(self, n):
            self.p = list(range(n))

        def find(self, x):
            if self.p[x] != x:
                self.p[x] = self.find(self.p[x])
            return self.p[x]

        def union(self, a, b):
            a = self.find(a)
            b = self.find(b)
            if a != b:
                self.p[b] = a

    out = []
    n = int(input())
    dsu = DSU(100000)

    for i in range(1, n + 1):
        dsu.union(0, i)

    for line in sys.stdin:
        if not line.strip():
            continue
        a = list(map(int, line.split()))
        k = a[0]
        ptr = 1
        for _ in range(k):
            dsu.union(a[ptr], a[ptr + 1])
            ptr += 2
        if dsu.find(0) == dsu.find(9999):
            out.append("ATTACK")
            break
        out.append("WAIT")

    return "\n".join(out)

assert solve("""3

""") == "WAIT\nATTACK", "sample 2"

assert solve("""0

""") == "ATTACK", "direct connection"

""") == "ATTACK", "indirect connection"

""") == "WAIT\nWAIT\nATTACK", "late merge"

 ## 特殊なケース

 クイーンが最初のドローン メッセージによって接続されている場合でも、チェックする前に受信したすべてのエッジを処理するため、アルゴリズムは引き続き機能します。 のために：```
0
1 0 9999
```ユニオン操作がマージされる`0`そして`9999`、したがって代表者は一致し、答えは次のようになります。`ATTACK`。 

ルートに複数の中間ホールがある場合、特別な処理は必要ありません。 のために：```
0
2 0 5 5 9999
```最初の共用体はコンポーネントを作成します`{0,5}`2番目はそれを次のように展開します`{0,5,9999}`。 最終的な比較ではルートが正しく検出されます。 

開始アクセスエリアにホール以外のホールが含まれる場合`0`、これらのホールは最初に統合する必要があります。 のために：```
3
1 3 8
1 8 9999
```ホール`3`はすでに到達可能であるため、検出されたチェーンは 2 回目の更新後にクイーンに到達します。 頂点からのみ開始するソリューション`0`ホールを初期化せずに`1`を通して`N`誤って攻撃を遅らせたり見逃したりする可能性があります。
