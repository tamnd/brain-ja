 ## 解決策
 ## 問題の理解

 入力は、資産価格の毎日の変化率を表します。 各値はベーシス ポイントで与えられるため、次の値が得られます。`100`の変化を意味します`1%`、`-250`の減少を意味します`2.5%`、 等々。 価格変更は次々に適用されます。つまり、追加ではなく増加します。 一連の変化`+10%`、 それから`-10%`2 番目の変更はすでに変更された値に影響を与えるため、元の価格には戻りません。 

連続した範囲の日を選択する必要があります。 レンジの開始日は資産を購入する日、終了日は資産を売却する日です。 目標は、この範囲内のすべての変更を適用した後の最終値を最大化することです。 複数の範囲でまったく同じリターンが得られる場合は、開始日が最も新しいものが優先されます。 開始日が等しい場合は、より長い範囲が優先されます。 

変更の数は 300,000 に達する場合があります。 二次解法では、最悪の場合でも約 450 億の間隔を調べる必要がありますが、これは一般的な競技プログラミングの制限時間よりはるかに長くなります。 ソリューションは、線形または線形に近い時間で配列を処理する必要があります。 メモリの量も入力サイズに比例する必要があるため、間隔結果の大きなテーブルを保存するのは現実的ではありません。 

単純な実装が失敗する可能性があるエッジケースがいくつかあります。 1 つ目は、パーセントを乗算するのではなく加算すると、間違った答えが得られるということです。 例えば：```
4
5000 -4000 100 100
```正しい答えは、`1 4`、なぜなら乗数は`1.5 * 0.6 * 1.01 * 1.01`、これは個人の利益よりも大きいです。 変化を合計するソリューションでは、次のようになります。`50 - 40 + 1 + 1 = 12%`また、それを個々の日と誤って比較する可能性があります。 

もう 1 つの問題は、ネガティブな変更の処理です。 大幅な低下によりセグメントの拡張が悪化する可能性がありますが、後で増加するとセグメント全体が最適化される可能性があります。 例えば：```
5
-1000 5000 -1000 5000 -1000
```最適な間隔は全範囲です`1 5`2 つの強い増加が乗算を通じて損失を補うためです。 連続する正の値のみを検索するソリューションでは、これが欠けています。 

タイブレークも微妙なポイントです。 考慮する：```
4
100 0 100 0
```間隔`1 4`そして`3 4`ゼロの変更は価格に影響を与えないため、同じリターンが得られます。 正しい答えは、`3 4`, 後から始まるので。 最初に見つかった最大値を維持する実装は失敗します。 

## アプローチ

 直接的なアプローチは、可能な限りすべての開始日を試し、一度に 1 日ずつ間隔を延長することです。 間隔ごとに、現在の乗数を維持し、これまでに見つかった最良の乗数と比較できます。 考えられるすべての期間がチェックされるため、これは正しいです。 

ただし、`N * (N + 1) / 2`可能な間隔。 と`N = 300000`、つまり約 450 億間隔です。 定期的な更新を行ったとしても、これは遅すぎます。 

重要な観察は、毎日の乗数がすべてプラスであるということです。 の変更`p`ベーシス ポイントは次の乗数に対応します。```
1 + p / 10000
```すべての乗数は正であるため、積を最大化することは、それらの対数の合計を最大化することと同じです。```
log(a * b * c) = log(a) + log(b) + log(c)
```この問題は、変換された値に対する最大部分配列合計問題になります。 これはまさに Kadane のアルゴリズムで処理される構造です。 

ブルートフォース手法はすべての製品を明示的に評価するため機能しますが、間隔が長すぎるため失敗します。 乗算を加算に変換すると、左から右にスキャンしながら、可能な限り最良の以前の状態のみを維持できます。 

アプローチ間の比較は次のとおりです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) | お(1) | 遅すぎる |
 | 最適 | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 日々の変化を対数値に変換します。 気分転換に`p`、 店：```
log(1 + p / 10000)
```一定期間にわたるこれらの値の合計は総収益の対数を表すため、合計を比較することは実際の収益を比較することと同じです。 

1. 変換された値のプレフィックスの合計を維持します。 もし`pref[i]`最初の合計です`i`変換された値、次に間隔の値`(l, r)`は：```
pref[r] - pref[l - 1]
```1. 終了位置をスキャンしながら`r`、すべての位置の中で最小のプレフィックス合計を保持します。`r`。 前の最小のプレフィックスを減算すると、次で終わる可能な最大の間隔が得られます。`r`。 
2. 複数のプレフィックス位置が同じ最小値を持つ場合は、最新のものを保持します。 問題のタイブレーク ルールでは、開始位置が遅い方が優先されます。 
3. 現在の間隔を、これまでに見つかった最良の回答と比較します。 リターンが大きい場合は、答えを置き換えます。 リターンが等しい場合は、より大きな開始インデックスを持つ間隔を選択し、それらも等しい場合は、より長い間隔を選択します。 
4. 加工後の位置`r`、 入れる`pref[r]`保存された最小プレフィックス情報に組み込まれるため、将来の間隔はその後開始できます。`r`。 

なぜ効果があるのか:

 プレフィックスの合計表現は、現在のプレフィックスから差し引く前のプレフィックスを 1 つ選択することによって、すべての間隔値が決定されることを意味します。 終了位置が固定されている場合、最適な間隔は前の最小のプレフィックス値の直後から開始する必要があります。 アルゴリズムは、等しいプレフィックス値の間での正しいタイブレークの選択など、この必要な情報を常に正確に保存します。 考えられるすべての終了位置がチェックされ、各終了位置に対する最適な開始点が考慮されるため、全体的な最適値が見つかります。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    logs = [math.log1p(x / 10000.0) for x in p]

    eps = 1e-12

    pref = 0.0
    min_pref = 0.0
    min_pos = 0

    best_value = -float("inf")
    best_l = 1
    best_r = 1

    for i, value in enumerate(logs, start=1):
        pref += value

        current = pref - min_pref
        l = min_pos + 1
        r = i

        length = r - l + 1
        best_length = best_r - best_l + 1

        if (
            current > best_value + eps
            or (
                abs(current - best_value) <= eps
                and (l > best_l or (l == best_l and length > best_length))
            )
        ):
            best_value = current
            best_l = l
            best_r = r

        if pref < min_pref - eps or (abs(pref - min_pref) <= eps and i > min_pos):
            min_pref = pref
            min_pos = i

    print(best_l, best_r)

if __name__ == "__main__":
    solve()
```この解では、まずすべてのパーセンテージの変化が対数に変換されます。`log1p`直接計算する代わりに使用されます`log(1 + x)`ゼロに近い値の方が正確であるためです。 

変数`pref`現在のプレフィックスの合計を保存します。`min_pref`現在の位置より前に確認された最小のプレフィックス合計です。`min_pos`はそのプレフィックスのインデックスです。 現在の位置が期間の終わりとして使用される場合、この最小プレフィックスを減算すると、ここで終了する最良の間隔が生成されます。 

答えの比較には、タイブレーク ロジックが含まれています。 対数リターンが大きいほど常に優れています。 2 つの戻り値が浮動小数点精度内で等しい場合、左端の大きい方の端点を持つ区間が選択されます。 両方の左側のエンドポイントが一致する場合、後の右側のエンドポイントの方が長い間隔になります。 

のアップデート`min_pref`これは、現在の回答を確認した後に発生します。これは、プレフィックスの定式化において、同じ日に終了する間隔の開始点として現在の日を使用できないためです。 順序を正しく保つことで、1 つずつずれたエラーを回避できます。 

累積対数間の比較のみが必要なため、ここでは Python 浮動小数点数で十分です。 元の積は極端に小さくなったり大きくなったりする可能性がありますが、対数形式によりすべての値が管理可能な範囲内に収まります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | 毎日の変更はそれぞれ 1 回変換され、処理されます。 |
 | スペース | お(1) | 少数の実行変数のみが保存されます。 |

 このアルゴリズムは、最大 300,000 の入力値のそれぞれに対して一定量の作業を実行します。 すべての間隔またはプレフィックス配列を保存する必要がないため、メモリ制限内に快適に収まります。 

## テストケース```python
import sys
import io
import math

def solve_data(data):
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(data)
    input = sys.stdin.readline

    n = int(input())
    p = list(map(int, input().split()))

    pref = 0.0
    min_pref = 0.0
    min_pos = 0
    eps = 1e-12

    best = -float("inf")
    bl = br = 1

    for i, x in enumerate(p, 1):
        pref += math.log1p(x / 10000.0)

        cur = pref - min_pref
        l = min_pos + 1

        if (
            cur > best + eps
            or (
                abs(cur - best) <= eps
                and (l > bl or (l == bl and i - l + 1 > br - bl + 1))
            )
        ):
            best = cur
            bl = l
            br = i

        if pref < min_pref - eps or (abs(pref - min_pref) <= eps and i > min_pos):
            min_pref = pref
            min_pos = i

    sys.stdin = old_stdin
    return f"{bl} {br}"

assert solve_data("4\n1000 2000 -3000 4000\n") == "4 4"
assert solve_data("4\n10 20 -25 40\n") == "1 4"

assert solve_data("3\n100 100 100\n") == "1 3"
assert solve_data("3\n-9999 5000 5000\n") == "2 3"
assert solve_data("5\n100 0 100 0 0\n") == "3 5"

assert solve_data("2\n-10000 100\n") == "2 2"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`3 / 100 100 100`|`1 3`| 収益性の高いシーケンスが拡張されていることを確認します。 |
 |`3 / -9999 5000 5000`|`2 3`| 初期の大きな損失が破棄されていることを確認します。 |
 |`5 / 100 0 100 0 0`|`3 5`| 最新スタートのタイブレークをチェックします。 |

 ## 特殊なケース

 非常に大きな損失とそれに続くゲインを含むシーケンスは、最小のプレフィックス ロジックによって処理されます。 のために：```
3
-9999 5000 5000
```最初の乗数は`0.0001`, したがって、これを含めると投資がほぼ破壊されます。 1 日目以降のプレフィックスの合計は非常に負になり、これが最小のプレフィックスになります。 2 日目が処理されると、2 日目からの開始が改善され、そこからアルゴリズムが継続されます。 最終的な答えは次のとおりです。```
2 3
```間隔間のタイでは、最も遅い開始を優先する必要があります。 のために：```
5
100 0 100 0 0
```ゼロを変更しても戻り値は変わりません。 間隔`1 5`そして`3 5`同じ製品を持っています。 このアルゴリズムは、等しい最小プレフィックス間の最新の位置を保存するため、3 日目から始まる候補が以前の候補と置き換えられます。 出力は次のとおりです。```
3 5
```1 日が最良の答えになる可能性があります。 のために：```
4
1000 2000 -3000 4000
```最初の 3 日間を一緒に過ごすのは、最後の 1 日だけで過ごすよりも弱いです。 4 日目以前のプレフィックスの最小値は損失後に更新され、アルゴリズムは 4 日目のみを考慮できるようになります。出力は次のようになります。```
4 4
```これらのケースは、正の連続が最適であると仮定したり、タイブレーク ルールを無視したりするパーセンテージの加算に基づいたアプローチが失敗する傾向にあるケースです。
