 ## 解決策
 ## 問題の理解

 正の整数の配列を使用してプレイされる 2 人用ゲームの勝者を決定するように求められます。 アリスが先に動きます。 各ターンで、プレイヤーは配列の最初の要素を検査します。 ゼロの場合、プレイヤーは即座に負けます。 それ以外の場合、プレイヤーは配列内の 2 番目の要素以降の位置を選択し、最初の要素を 1 つ減らして、選択した要素と交換します。 ゲームは、プレイヤーが行動できなくなるまで交互に続きます。これは、まさに最初の要素がゼロになったときに起こります。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、配列のサイズと配列要素が提供されます。 両方のプレイヤーが最適にプレイした場合、出力は各ゲームの勝者となります。 

制約により許可されるのは、`n`100,000 に達するまでの合計と`n`すべてのテスト ケースで 200,000 に達します。 個々の動きをシミュレートしようとするソリューションはどれも、次のオーダーで簡単に実行できます。`10^9`配列要素が大きい場合の最悪の場合の演算。 これにより、単純なシミュレーションが除外されます。 テスト ケースごとに少数の操作、理想的には O(n) を使用して勝者を直接計算するアプローチが必要です。 

最初の要素が最大でない配列では、重要な微妙な点が発生します。 たとえば、次のように考えてみましょう`[1, 10]`。 素朴なアプローチでは、`a_1`by one は常に最初のプレイヤーに有利ですが、ここでは大きな 2 番目の要素により、間違って処理された場合、最初のプレイヤーが負ける立場を作ることができます。 すべての要素が等しい配列、最初の要素が最小または最大である配列、サイズ 2 の配列はすべて、一貫して処理する必要があるわずかに異なるダイナミクスを持っています。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる動きをシミュレートします。 各ターンで、可能なすべてのインデックスを反復処理します。`i >= 2`、最初の要素をデクリメントして交換し、再帰的に勝者を決定します。 このアプローチは正しいですが、実行不可能です。 サイズの配列の場合`n = 10^5`と`a_1 = 10^9`の場合、シミュレーションには許可されているよりもはるかに多くの操作が必要になります。 

重要な洞察は、最初の要素の役割を観察することで得られます。 どのターンでも必ず減少します`a_1`1つずつ。 他の要素の位置は、それらが最終的に前面に移動する場合にのみ重要になります。 もし`a_1`が配列内の最小の要素である場合、移動するプレイヤーはまずそれをゼロに減らすことを強制され、次のプレイヤーが勝ちの位置に残ります。 逆に、もし`a_1`が最小ではない場合、プレーヤーはより大きな要素を前面に交換して、最初の要素の「負担を効果的に相手に渡す」ことができます。 

このことから、結果は主に配列の最初の要素と残りの要素の比較に依存することがわかります。 もし`a_1`が残りの合計よりも厳密に大きい場合、最初のプレーヤーが強制的に勝利することができます。 もし`a_1`最小の場合、最初のプレイヤーが負けます。 サイズ 2 の配列の場合、勝者は 2 つの要素の差のパリティによって単純に決定されます。 すべてのケースを捉える正確な定式化は、最初の要素が残りの要素の最大値よりも厳密に大きいかどうかをチェックすることです。 そうであれば、アリスは即座に勝ちます。 それ以外の場合、勝者は、すべての要素をゼロにするのに必要な合計手数の同等性によって決定されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(a_1 * n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。`n`そして配列`a`。 
2. すべての配列要素の合計を計算し、最大要素を特定します。 
3. 最大要素が最初の要素と等しいかどうかを確認します。 もし`a_1`は厳密には最大の要素ですが、アリスはいつでもそれをより小さな要素と交換し、戦略的に削減して勝利を強制することができます。 そうしないと、移動するプレイヤーは最小限の要素が前面にあり、最初にそれをゼロに減らさなければならない状況に直面します。 
4. 移動の合計数を数えます。これはすべての要素の合計に等しくなります。 この合計が奇数であれば、アリスが勝ちます。 互角ならボブが勝ちます。 これが機能するのは、各手ごとに合計がちょうど 1 減り、パリティによって誰が最後の手を打つかが決まるためです。 
5. テストケースの勝者を出力します。 

機能する理由: このアルゴリズムは、移動するたびに配列の合計が 1 ずつ厳密に減少するという不変式に依存しています。 最後の非ゼロ要素をゼロに減らすことを強制されたプレイヤーが負けます。 スワップは最初の要素が最終的に削減されるのを防ぐことができないため、合計パリティを追跡することによって個々のスワップを抽象化します。 比較する`a_1`配列の残りの部分を使用すると、最初の要素が優勢でゲームの戦略的なコントロールが可能になるエッジ ケースを確実に捕捉できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total = sum(a)
        max_val = max(a)
        if max_val > total - max_val:
            print("Alice")
        elif total % 2 == 1:
            print("Alice")
        else:
            print("Bob")

if __name__ == "__main__":
    main()
```このソリューションでは、まず配列の合計を計算し、最大要素を特定します。 最大の要素が残りの要素の合計より厳密に大きい場合、アリスは自分のターンで最初の要素が決してゼロにならないことを常に保証し、勝利を保証します。 それ以外の場合、手数の合計のパリティに依存します。合計が奇数の場合はアリスが最後の手となり、合計が偶数の場合はボブが最後の手となります。 これにより、任意の長さと値の配列が処理され、直接のシミュレーションが回避されます。

 これらのトレースは、最初の要素の優位性または合計パリティのいずれかを考慮すると、勝者を正しく予測できることを確認します。

 ## 特殊なケース

 アレイの場合`[1,1]`, アリスはボブのために最後の非ゼロ要素を残すことを避けることができません。 合計は 2 なので、ボブが勝ちます。 のために`[1000000000,1]`、最初の要素が合計を支配するため、アリスはそれを減らして交換し、常にボブが勝ち手を持たないようにすることができます。 すべての要素が等しい配列ではパリティ ロジックがテストされます。合計が奇数の場合はアリスが勝ちます。 互角ならボブが勝ちます。 これらのエッジ ケースは、最大比較と合計パリティの両方がゲーム内のシナリオの完全なセットを捉えていることを確認します。
