 ## 問題の理解

 私たちに与えられているのは、$n \times n$グリッドでは、各セルが 3 つの地形タイプ (使用可能な植林地、水源、または使用できない封鎖された土地) のいずれかを表します。 正確に 2 列の高さの水平ストリップが「有効なガーデニング ストリップ」としていくつあるかを数えるように求められます。 

ストリップは、連続する 2 つの行を選択し、それらの 2 つの行内の列の連続したセグメントを選択することによって定義されます。 その長方形内では、植栽地と水源のみが許可されているため、ブロックされたセルは表示されません。 さらに、ストリップ内のすべての植栽セルは最大でもマンハッタンの距離内にある必要があります$k$グリッド全体の少なくとも 1 つの水源セルから（必ずしもストリップ内にある必要はありません）。 距離はフルグリッドで測定されます。 

重要な構造上の制限は、2 つの水セルが垂直方向に隣接しないことです。 これにより、カラムに 2 つの連続したウェルが含まれることがなくなります。これは、後で伝播と範囲カバレッジについて推論するときに重要になります。 

タスクは、両方の制約を満たす、高さ 2 の有効な長方形をすべて数えることです。 

制約$n \le 2000$おおよそより悪いものはすぐに除外します$O(n^2)$または$O(n^2 \log n)$。 すべての四角形を素朴に列挙し、セルごとに距離をチェックするソリューションは、非常に遅すぎます。$O(n^3)$可能な長方形と各チェックは$O(n)$、につながる$O(n^4)$。 

より微妙な制約は、距離がストリップ内だけでなくグリッド内の任意の場所のウェルに依存することです。 ストリップの有効性はグローバル近接情報に依存するため、単純なサブグリッド推論は危険になります。 

いくつかの特殊なケースでは、よくある間違いが明らかになります。 

ストリップのグリッドのどこにも水セルが含まれていないが、植栽地がまだある場合、それらの植栽セルには距離を設定できないため、無効になります。$\le k$あらゆる水源に。 たとえば、グリッドにウェルがまったくなく、$k \ge 1$、すべてのストリップは距離要件を満たしていないため、答えはゼロです。 

植栽セルがストリップの外側の井戸に近い場合、別の故障モードが発生します。 選択した長方形内のウェルのみをチェックする単純なアプローチでは、有効なストリップが誤って拒否されてしまいます。 

最後に、たとえ距離条件が成立するとしても、ブロックされたセルを含むストリップは直ちに無効になります。 

## アプローチ

 ブルート フォース アプローチでは、隣接する行のすべてのペアを列挙し、次に考えられるすべての左右の境界を列挙することから始めます。 各候補の長方形について、そのすべてのセルをスキャンして、ブロックされた土地が存在しないこと、およびすべての植栽セルにマンハッタン距離内に少なくとも 1 つの水セルがあることを確認します。$k$。 

これは正しいですが、高価です。 がある$O(n^2)$行ペアの選択と$O(n^2)$列セグメント、生成$O(n^4)$長方形。 各長方形には最大で次のものが含まれます$O(n^2)$最悪の場合、距離を確認するには、すべての水セルをスキャンするか、クエリごとに BFS 距離を計算する必要があります。 これは、実行可能な実行時間をすぐに超えます。 

重要な観察は、距離制約がグローバルに事前計算できることです。 各セルについて、マルチソース BFS を使用して任意の水源までの最小距離を計算できます。 この前処理により、「植栽セルが距離内にある」という状態になります。$k$” は定数時間の検索になります。

 これで、すべてのセルが安全か安全でないかのラベルが付けられます。 有効なストリップは 2 つの独立した条件を満たさなければなりません。つまり、ブロックされたセルが含まれていないこと、およびすべての植栽セルが安全であることです。 

これにより、問題は、行のペアごとにバイナリ行列内のすべて 1 の部分四角形をカウントすることに変換されます。ここで、「1」は、セルが許可される (ブロックされておらず、水または安全な植栽のいずれか) ことを意味します。 

行のペアごとに、有効性を示すバイナリ配列に列を圧縮し、すべてのエントリが有効である連続セグメントをカウントします。 これらのセグメント内では、内部の植栽セルが安全であることを確認する必要もありますが、安全性はセルごとに事前に計算されているため、これは単純な妥当性チェックにとどまります。 

残りの構造は標準です。行のペアごとに、列全体をスイープし、最大の連続した有効なセグメントをカウントし、各セグメント内のサブ配列の数を加算します。

 ## アルゴリズムのチュートリアル

 まず、グリッドを距離制約がすでに解決されている形式に変換します。 

1. すべての水セルから開始するマルチソース BFS を使用して、すべてのセルから最も近い水源までの最小マンハッタン距離を計算します。 各水セルは距離 0 で初期化され、BFS は 4 方向に広がります。 これが機能するのは、マンハッタン距離がユニット エッジを持つグリッド グラフの最短経路長に正確に対応するためです。 
2. 水であるか、BFS 距離が最大である植栽地である場合、すべてのセルを「安全」としてマークします。$k$。 より長い距離を持つ植栽セル$k$有効なストリップでは使用できないものとして扱われます。 
3. 次に、行のすべてのペアを検討します。$(r1, r2)$どこ$r2 = r1 + 1$、ストリップは正確に 2 行の高さでなければならないためです。 このようなペアごとに、列を左から右に処理します。 
4. 各列について$c$、両方のセルがあるかどうかを確認します。$(r1, c)$そして$(r2, c)$使用可能 (ブロックされていない) で安全です。 いずれかがブロックされているか安全でない場合は、この列を現在の行ペアに対して無効としてマークします。 
5. これで、どの列がこの行ペアの有効なストリップに参加できるかを示す列上のバイナリ配列が得られました。 この配列をスキャンして、有効な列の最大の連続セグメントを見つけます。 
6. 長さの各セグメントについて$L$、 追加$L \cdot (L+1) / 2$答えは、どのサブセグメントも有効な水平ストリップに対応するためです。 
7. すべての行ペアに対して繰り返し、合計を累積します。 

重要な考え方は、行のペアが固定されると列が独立し、妥当性は単純な連続セグメントのカウント問題になるということです。 

なぜ効果があるのか:

 BFS 前処理により、すべての植栽セルがグローバルな距離制約を満たしているかどうかをすでに認識していることが保証されます。 この変換後の有効性は、ローカル セルのプロパティとブロックされたセルの有無のみに依存します。 各ストリップは高さ 2 の連続した長方形であり、行が固定されると列制約は独立するため、有効なストリップはすべて、すべてのセルが許可される列の部分配列に正確に対応します。 最大の有効なセグメントにわたってサブ配列をカウントすると、各有効なストリップが正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, k = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]
    
    INF = 10**9
    dist = [[INF] * n for _ in range(n)]
    q = deque()
    
    for i in range(n):
        for j in range(n):
            if grid[i][j] == 2:
                dist[i][j] = 0
                q.append((i, j))
    
    dirs = [(1,0), (-1,0), (0,1), (0,-1)]
    
    while q:
        x, y = q.popleft()
        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < n:
                if dist[nx][ny] > dist[x][y] + 1:
                    dist[nx][ny] = dist[x][y] + 1
                    q.append((nx, ny))
    
    safe = [[False] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            if grid[i][j] == 2:
                safe[i][j] = True
            elif grid[i][j] == 1 and dist[i][j] <= k:
                safe[i][j] = True
    
    ans = 0
    
    for r1 in range(n - 1):
        r2 = r1 + 1
        ok = [True] * n
        
        for c in range(n):
            if grid[r1][c] == 3 or grid[r2][c] == 3:
                ok[c] = False
            elif not safe[r1][c] or not safe[r2][c]:
                ok[c] = False
        
        c = 0
        while c < n:
            if not ok[c]:
                c += 1
                continue
            start = c
            while c < n and ok[c]:
                c += 1
            length = c - start
            ans += length * (length + 1) // 2
    
    print(ans)

if __name__ == "__main__":
    solve()
```BFS セクションは、すべてのウェルからグローバル距離フィールドを同時に構築するため、ストリップごとの距離の再計算が不要になります。 の`safe`行列は、距離制約をブール条件に圧縮します。これは、問題を 2D 計数に削減するために重要です。 

行ペア ループはストリップ高さの制約を強制します。 その中には、`ok`配列は、両方の行が使用可能であり、安全制約を満たすことを強制します。 最終スキャンは古典的な連続セグメントの累積であり、各最大セグメントがすべてのサブセグメントに寄与します。 

微妙な点は、水セルは有効性の源であるため、距離に関係なく常に安全であると考えられることです。 もう 1 つは、ブロックされたセルが個別に処理され、列を即座に無効にすることです。

 ## 特殊なケース

 ウェルのないグリッドは、全体的な距離の依存性を示しています。 すべての植栽セルは距離要件を満たしていないため、すべてのストリップは無効になります。 BFS の初期化では到達可能なソースが生成されず、すべての距離が無限のままになります。`safe`行列はウェルを除くすべての場所で false になります。 ウェルが存在しないため、有効なセグメントは形成されず、答えは正しくゼロになります。 

単一のブロックされたセルによってすべての有効性が損なわれたストリップは、セグメンテーションがどのように機能するかを示しています。 このアルゴリズムは前処理後に各列を独立して処理するため、単一の無効な列によってセグメントが 2 つの独立した計数問題にきれいに分割されます。 これにより、過剰なカウントが防止され、ブロックされたセルがまばらに分布している場合でも正確さが保証されます。
