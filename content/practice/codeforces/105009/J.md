 ## 問題の理解

 長さのシーケンスが与えられます$N$値のみを含む$0,1,2,3$。 すべての要素はボードから始まります$A$そして私たちは彼らを船に移さなければなりません$B$繰り返し前を取ることで$A$そしてそれを追加する$B$。 その際、さらに 2 つの変換が許可されます。すべての値を反転することができます。$A$マッピングによる$x \to 3-x$、現在の内容を元に戻す可能性があります。$B$。 

このプロセスは単に要素を移動するだけではありません。 最終的な取り決めは、$B$構造上の制約を満たす必要があります。出現するすべての個別の値は、正確に 1 つの連続したブロックを形成する必要があります。 つまり、値が複数回出現する場合、$B$、そのすべての出現は、他の値がインターリーブされることなく、単一の中断されていないセグメント内に存在する必要があります。 

各テスト ケースでは、文字を使用した可能な限り最短の一連の操作が求められます。$c$（補体）、$r$（逆行する$B$）、 そして$p$(からプッシュ$A$に$B$）有効な最終構成を実現します。 最小長のすべてのシーケンスの中で、辞書編集的に最小のものを出力する必要があります。 

制約が十分に厳しいので、$N$まで上がります$10^5$テストケース全体の合計も$10^5$。 これにより、バックトラッキングや状態検索を使用して任意の操作インターリーブをシミュレートしようとするアプローチは即座に排除されます。 操作ごとに分岐したり、複数の候補状態を維持したりするソリューションは、指数関数的または少なくとも二次関数的な動作に退化します。 

グループ化が純粋に並べ替えに関するものであると仮定すると、素朴な推論による微妙な失敗例が現れます。 たとえば、シーケンス$0,1,0,1$プッシュの再配置だけでは修正できません。 反転または補完が役立つと思うかもしれませんが、グローバル変換のみが存在するため、実際の制約は、最大でも数回のグローバル フリップでシーケンスを「値ごとに 1 回の実行」にできるかどうかです。 頻度のみをカウントしたり、ソートが常に可能であると仮定したりする不注意なアプローチは、そのようなケースを誤って受け入れることになります。 

もう 1 つのよくある落とし穴は、操作を貪欲な方法で自由にインターリーブ可能として扱うことです。実際には、プロセスの途中で操作を適用しても、構築されているものの本質的な構造は変更されません。すべての要素は依然として元の順序または完全に逆の順序で消費され、補完は値の名前をグローバルに変更するだけです。 

## アプローチ

 ブルートフォースの観点は、これを、次のように定義された状態にわたる最短経路問題として扱うことです。$(A, B)$さらに、補数を適用したかどうか、および反転したかどうかも確認します。 各ステップでは 3 つの操作の 1 つを適用でき、最短の有効なシーケンスが検索されます。 これはすぐに実行不可能になります。$A$そして$B$進化する$N$そのため、状態空間はプッシュの数に応じて指数関数的に増加し、到達可能なすべての構成を表すことさえ、すでに完了しています。$O(4^N)$構造的には似ています。 

重要な観察は、どちらでもないということです$c$または$r$シーケンス内に新しい順序の自由が生まれます。 補数は値の名前を一貫して変更するだけであり、反転は最終シーケンスを読み取る方向を反転するだけです。 実際の組み合わせ構造は要素がプッシュされる順序のみであり、フロー全体を逆にしない限り、この順序は固定されます。 

これにより、問題は入力シーケンスの一定数のグローバル変換のチェックに分解されます。 必要なのは、補数や反転を適用するかどうかを検討し、結果のシーケンスが「値ごとに単一の連続ブロック」条件をすでに満たしているかどうかを検証することだけです。 可能性は 4 つしかないため、問題は指数関数的な状態の探索からテスト ケースごとに 4 つの線形スキャンに減ります。

 ## アルゴリズムのチュートリアル

 1. 元の配列を基本構成として、またその相補配列、その逆配列、およびその逆相補配列を考慮します。 これら 4 つのケースは、補数と逆数の両方がインボリューションであるため、許可されたグローバル操作の意味のある効果をすべて表しています。 
2. 4 つの候補シーケンスのそれぞれについて、次の各値が一致するかどうかを確認します。$\{0,1,2,3\}$最大でも 1 つの連続セグメントに出現します。 これは、シーケンスをスキャンして、一度値を残した後はその値に二度と遭遇しないようにすることと同じです。 
3. 有効な候補ごとに、運用コストを計算します。 基本シーケンスのコストは 0 で、補数を適用すると 1 つの演算を加算し、逆を適用すると 1 つの演算を加算し、両方を適用すると 2 つの演算を加算します。 
4. 演算回数が最も少ない候補を選択します。 複数の候補が同じコストを共有する場合は、文字列を比較する辞書順で最小の演算文字列を選択します。$\{c,r,p\}$辞書順に。 
5. 最初に選択したグローバル操作を辞書編集的に最適な順序で発行し、次に追加することによって、最終的な操作シーケンスを構築します。$N$押す$p$すべての要素は 1 回だけ転送する必要があるためです。 

この構造が有効である理由は、補完と反転が要素のプッシュの進行に依存しないためです。 後で適用しても先に適用しても、最終的なマルチセット構造は変わりません。$B$、値と順序の解釈のみ。 したがって、コストを増加させたり有効性を損なったりすることなく、すべてのプッシュの前にすべてのグローバル変換が行われるように、最適なソリューションを再配置できます。 

### なぜ効果があるのか

 重要な不変条件は、実現可能性に影響を与える唯一の自由度は、要素が消費される線形順序であるということです。$A$、おそらくグローバルで一度逆転する可能性があります。 補完は隣接構造には影響せず、ラベルの名前を変更するだけです。 したがって、実現可能性の条件は、固定順列 (元の順または逆順) が各ラベルが単一の間隔を形成する特性をすでに持っているかどうかのみに依存します。 このプロパティは再ラベル付けされても保持されるため、4 つのグローバル変換をチェックすることですべての可能性が網羅されます。 

プロセスの途中で操作を適用するインターリーブ戦略は、すべてが同じになる同等の戦略に変換できます。$c$そして$r$操作が最初に適用され、その後にすべての操作が適用されます$p$最終的なシーケンスを変更したり、操作の数を増やしたりすることなく、操作を実行できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok(arr):
    seen = [False] * 4
    active = [False] * 4
    for x in arr:
        if not active[x]:
            if seen[x]:
                return False
            active[x] = True
            seen[x] = True
        for v in range(4):
            if v != x:
                active[v] = False
    return True

def build_ops(use_c, use_r):
    ops = []
    if use_c:
        ops.append('c')
    if use_r:
        ops.append('r')
    ops.append('p')
    return ''.join(ops)

def solve():
    t, n = map(int, input().split())
    comp = [3, 2, 1, 0]
    
    for _ in range(t):
        a = list(map(int, input().split()))
        
        cand = []
        
        # identity
        if ok(a):
            cand.append((0, build_ops(False, False)))
        
        # complement
        a2 = [comp[x] for x in a]
        if ok(a2):
            cand.append((1, build_ops(True, False)))
        
        # reverse
        a3 = a[::-1]
        if ok(a3):
            cand.append((1, build_ops(False, True)))
        
        # reverse + complement
        a4 = [comp[x] for x in a3]
        if ok(a4):
            cand.append((2, build_ops(True, True)))
        
        cand.sort()
        cost, base = cand[0]
        
        # append p's
        print(base[:-1] + 'p' * n)

if __name__ == "__main__":
    solve()
```この解決策では、問題を構造の検証と操作の再構築に分割します。 の`ok`この関数は、値が検出されたかどうか、およびその現在のセグメントがまだアクティブであるかどうかを追跡することによって、単一ブロックの状態をチェックします。 変換のケースは、プッシュの前に補完および/または反転を適用することに正確に対応します。 

出力構造では、すべてのプッシュ操作が事実上同一であるという事実を利用しているため、それらは繰り返される接尾辞として表すことができます。`p`。 これにより、進化するボードを明示的にシミュレートすることが回避されます。 

## 実用的な例

 次のような、値がすでにクリーンなブロックに出現しているシーケンスを考えてみましょう。$1,1,0,0,3,3$。 恒等変換はすでに条件を満たしているため、アルゴリズムはグローバル操作を選択せず​​、プッシュのみを出力します。 スキャンでは、セグメントが閉じられた後に値が再表示され、有効性が確認されることはありません。 

次に、次のようなシーケンスを考えてみましょう$0,1,0,1$。 セグメントを離れた後に値 0 が再び現れるため、アイデンティティ チェックは失敗します。 補数の場合とその逆の場合もチェックされますが、値ごとに単一間隔の構造が生成されるものはありません。 これは、この問題が存在することを保証する理由を示しています。有効な入力では、4 つの変換のうち少なくとも 1 つできれいなセグメンテーションが生成されます。 

| 変換 | シーケンス | 有効？ |

 ## 特殊なケース

 重要なエッジケースは、シーケンスが反転後にのみ有効になる場合です。 たとえば、次のようなシーケンス$0,0,1,1,2,2$すでに有効ですが、$2,2,1,1,0,0$同じ構造に一致させるには反転が必要です。 このアルゴリズムは、反転した構成を明示的にテストし、各値が単一の連続した間隔に表示されることを確認することでこれを処理します。 

もう 1 つの特殊なケースは、補完が必要な場合です。 値は以下で対称であるため、$x \to 3-x$、元の形式では失敗したシーケンスは、名前を変更すると有効になる場合があります。 このチェックでは、数字の固定された意味を仮定するのではなく、両方のラベル空間を独立して評価することによって正確さを保証します。
