 ## 解決策
 ## 問題の理解

 単一行に配置された整数のシーケンスが与えられ、最大 3 つの異なる値を使用する、このシーケンスの連続するセグメントを、できるだけ長く見つけるように求められます。 

配列を Numerica での取引のタイムラインと考えてください。 それぞれの数字は、その時点で取引されているアイテムの種類です。 市場で最大 3 種類のアイテムのみが扱われる継続的な期間を選択したいと考えています。 このようなすべての有効なストレッチの中で、最大の長さを持つストレッチが必要です。 

出力されるのは、可能な限り最適なストレッチの長さを表す 1 つの数値だけです。 

配列サイズは最大 100000 まで可能で、すべてのサブ配列を明示的に検査しようとするソリューションは即座に除外されます。 二次または三次アプローチでは、最悪の場合でも 10¹⁰ 程度の演算が必要になりますが、これは 1 秒で実行できる演算をはるかに超えています。 これにより、通常はスライディング ウィンドウまたは 2 つのポインターを使用する、線形または線形に近い手法が推進されます。 

貪欲な拡張を考えると、微妙な問題が生じます。 制約に違反するまでセグメントを拡張する場合は、セグメントを縮小する方法に注意する必要があります。 違反が発生するたびに最初からやり直す単純なアプローチでは、最適なウィンドウを逃したり、速度が遅すぎたりする可能性があります。 

たとえば、次のような配列を考えてみましょう。`[1, 2, 3, 4, 1, 2, 3]`。 最適なセグメントは、次のような 3 つの異なる値のみを含むウィンドウです。`[1, 2, 3, 4]`無効ですが、`[2, 3, 4, 1]`4 つの異なる値があるため、これも無効です。 正解は次のようなセグメントから 3 です。`[1, 2, 3]`。 4 番目の個別の値が表示されるたびに誤って再起動すると、有用な重複が繰り返し破棄され、不必要に再計算される可能性があります。 

## アプローチ

 ブルートフォース手法は簡単です。 すべての開始インデックスを考慮し、出現する個別の数値の数を追跡しながら部分配列を右に拡張します。 開始ごとに、4 つの個別の値に達するまで拡張し、その点より前に確認された最良の有効な長さを記録します。 

これは、すべての候補セグメントを明示的にチェックするため機能します。 問題はそのコストです。 N 個の開始位置のそれぞれについて、最大 N 個の要素をスキャンする可能性があり、単純な方法で個別のカウントを維持するとオーバーヘッドが追加されます。 ハッシュを使用した場合でも、最悪の場合の複雑さは O(N²) であり、N = 10⁵ の場合、約 10¹⁰ の演算が必要になり、明らかに遅すぎます。 

重要な点は、実際には各インデックスからスキャンを再開する必要がないということです。 右ポインタを前方に移動すると、左ポインタも同様に前方に移動するだけで、最大 3 つの異なる値の制約が復元されます。 値がウィンドウから完全に外に出ると、その値は周波数構造から削除されます。 両方のポインターのこの単調な動きにより、各要素がウィンドウに出入りするのは最大 1 回であることが保証されます。 

これはまさにスライディング ウィンドウ手法です。常に有効なウィンドウ (最大 3 つの異なる値) を維持し、左から縮小することで違反を修正しながら貪欲にウィンドウを拡張します。

 | 最適な引き違い窓 | O(N) | O(1) から O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 窓口を整備しております`[l, r]`そしてその中の値の周波数マップ。 

1.初期化`l = 0`、`best = 0`、および空の周波数マップ。 

これにより、空のスライディング ウィンドウが設定されます。 
2.右ポインタを移動します`r`配列全体で左から右へ。 

各ステップでは、現在のウィンドウに 1 つの新しい要素が追加され、次で終わるすべてのサブ配列が徐々に探索されます。`r`。 
3.追加する場合`A[r]`、マップ内の頻度を増やします。 

これにより、現在のウィンドウ内で各値が何回出現したかの正確なカウントが保持されます。 
4. マップ内の個別のキーの数が 3 を超える場合は、ウィンドウを左から縮小します。 

繰り返し頻度を減らしていきます。`A[l]`そして移動します`l`ウィンドウに再び最大 3 つの異なる値が含まれるまで、前方に進みます。 無効なウィンドウは回答に寄与できないため、これが必要です。 
5. 有効性を復元した後、次のように回答を更新します。`best = max(best, r - l + 1)`。 

この時点で、`[l, r]`で終わる最長の有効なサブ配列です。`r`, そのため、グローバル最大値として考慮するのが安全です。 
6. まで続けます`r`配列の最後に到達します。 

### なぜ効果があるのか

 このアルゴリズムは、次のキーの不変式に依存します。`r`、窓`[l, r]`最大 3 つの異なる値が含まれ、かつ`l`現在のこのプロパティを維持する最小のインデックスです。`r`。 動くだけだから`l`必要に応じて前方に進み、次で終わる潜在的により良いウィンドウを破棄することはありません。`r`。 すべての有効なサブ配列はある時点でウィンドウ エンドポイントとして表され、これらの最大値がグローバルな答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    freq = {}
    l = 0
    best = 0
    
    for r in range(n):
        freq[a[r]] = freq.get(a[r], 0) + 1
        
        while len(freq) > 3:
            freq[a[l]] -= 1
            if freq[a[l]] == 0:
                del freq[a[l]]
            l += 1
        
        best = max(best, r - l + 1)
    
    print(best)

if __name__ == "__main__":
    solve()
```このソリューションは、スライディング ウィンドウの不変条件を中心に直接構築されます。 辞書`freq`多重度と条件を追跡します`len(freq) > 3`ウィンドウが制約に違反したときを検出します。 

内部の while ループは非常に重要です。違反の直後にウィンドウが常に修復されるようにします。 頻度がゼロになったときにキーを削除せずに、`len(freq)`これはバグの一般的な原因です。 

表現`r - l + 1`現在のウィンドウ サイズを計算し、次で終わる最適な有効なサブ配列を表します。`r`。

 ## 特殊なケース

 次のような最小限の入力`1`アルゴリズムがループに入らずに答えを正しく初期化するかどうかをテストします。 ウィンドウは単一の要素で開始および終了し、周波数マップには 1 つのキーが含まれており、出力 1 が即座に生成されます。 

次のような完全に均一な配列`5 5 5 5 5`収縮状態を引き起こすことはありません。 周波数マップのサイズは常に 1 であるため、ウィンドウは全長まで単調に増加します。 これにより、アルゴリズムが有効なウィンドウを人為的に縮小しないことが確認されます。 

次のような厳密に交互のパターン`1 2 3 4 5 6`強制的に収縮を繰り返します。 4 番目の個別の値が表示されると、3 つだけが残るまで左ポインタが進みます。 これにより、頻度がゼロに低下したときに削除ロジックの正確性がテストされ、実行全体を通して個別カウントのチェックが正確であることが保証されます。
