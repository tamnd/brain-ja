 ## 解決策
 ## 問題の理解

 整数の固定配列と多くの独立した範囲クエリが与えられます。 各クエリはインデックスから連続したセグメントを選択します。$l$に$r$、およびモジュラス値$x$。 そのクエリでは、選択したセグメントのすべての要素を法的に削減することによって得られる剰余の合計を計算します。$x$、その合計を出力します。 

主な難点は、範囲と係数の両方がクエリごとに変化し、関係するすべての値が 200,000 に達する可能性があることです。 これにより、クエリごとにすべての要素の残りを再計算するアプローチが除外されます。 最大 200,000 のクエリと最大 200,000 の配列長を使用して、セグメントをクエリごとに直接スキャンすると、およそ$O(NQ)$実行可能な限界をはるかに超えた最悪の場合の操作。 

微妙な側面は、モジュロ演算自体の動作から生じます。 小型用$x$、配列内のほとんどの値は、その完全な値またはそれに近い値を提供します。 大型用$x$、ほとんどの値は変更されません。 移行はスムーズではなく、次の倍数によって決まります。$x$各値の下にあります。 

素朴なアプローチを打ち破るエッジケースは、通常、次のような移行から生じます。 

すべての要素が以下より小さい場合$x$、答えは単純にセグメントの合計です。 たとえば、配列の場合$[1,2,3]$そして$x=10$、値が折り返されないため、範囲の答えは単なる合計になります。 

もし$x=1$、配列に関係なく、すべての剰余はゼロになるため、すべてのクエリはゼロを返します。 このケースを明示的に単純化しない単純な実装でも機能しますが、モジュロの計算を繰り返して時間を無駄にする可能性があります。 

もし$x$とても小さいです、と言う$x=2$、値はパリティに応じて 0 と 1 の間で切り替わり、計算を慎重に構造化しない限り、寄与はプレフィックスの合計だけでは一致しなくなります。 

本当の課題は、これらすべての体制を統一された方法で効率的に処理することです。 

## アプローチ

 ブルートフォース手法は簡単です。 クエリごとに、以下を繰り返します。$l$に$r$、計算する$A_i \bmod x$、合計を積み上げます。 これはクエリの定義に直接従うため、正解です。 ただし、各クエリにはコストがかかります$O(r-l+1)$、そして最悪の場合、これは$O(N)$。 と$Q$クエリの合計の複雑さは次のようになります$O(NQ)$、到達できる$4 \cdot 10^{10}$動作し、使用できません。 

重要な観察は、構造を公開する方法でモジュロ演算を書き直すことができるということです。 あらゆる値に対して$a$、 我々は持っています$$a \bmod x = a - x \cdot \left\lfloor \frac{a}{x} \right\rfloor.$$したがって、クエリは次のようになります。$$\sum a_i - x \cdot \sum \left\lfloor \frac{a_i}{x} \right\rfloor.$$最初の部分は単なる範囲の合計であり、次のように答えることができます。$O(1)$プレフィックス合計を使用します。 難しいのは 2 番目の部分です。商の合計が必要です。$\lfloor a_i / x \rfloor$ある範囲にわたって。 

ここで、制約の構造が重要になります。 価値観$a_i$は最大 200,000 であるため、値によって位置を前処理できます。 固定の場合$x$、各学期$\lfloor a_i / x \rfloor$はステップ関数です。次の場合にのみ変化します。$x$の約数を交差します$a_i$。 これは、貢献を値ごとにグループ化し、複数の値を反復処理することを示唆しています。$x$。 

より直接的で強力な視点は、$x$すべての要素が間隔で定義された値ブロック内で同じ剰余に寄与していることを観察します。$[k x, (k+1)x)$。 固定クエリ範囲の場合、値インデックスに対して事前に計算された周波数プレフィックス構造を使用して、各ブロックに含まれる要素の数をカウントできます。 

これを効率的に利用するために、値領域全体で周波数プレフィックスの合計を維持します。 それぞれの値について$v$、配列の任意のプレフィックスに何回出現したかを保存します。 それからクエリについては$(l,r,x)$の倍数にわたって繰り返します。$x$: ブロックごとに$[kx, (k+1)x - 1]$、その範囲内にある範囲内の要素の数を数え、対応する剰余の寄与を乗算して合計します。 

値は最大 200,000 までしかないため、特定のブロックの数は$x$は$O(\frac{MAXA}{x})$。 すべてのクエリにわたって、これは十分に償却されます。$x$ブロック数が少なく、小さい$x$周波数構造によって効率的に処理されます。 

小さい係数と大きい係数の間のこの二重性がソリューションを効率的にします。要素ごとの計算を値ブロックごとの集計に変換します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(NQ)$|$O(1)$| 遅すぎる |
 | 値ブロック + プレフィックス周波数 |$O((N + Q)\sqrt{MAXA})$償却済み |$O(N + MAXA)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレフィックス合計配列を構築します$A$。 これにより回答が可能になります$\sum_{i=l}^r A_i$一定時間で、これがすべてのクエリのベースになります。 
2. 値に対して周波数プレフィックス構造を構築します。各値は次のようになります。$v$、セグメント内で何回出現するかをすぐに判断できます。$[l,r]$。 これは、位置を値ごとにグループ化して保存するか、プレフィックス数を維持することによって行われます。 
3. クエリごとに$(l,r,x)$、プレフィックス合計を使用してセグメントの生の合計を計算します。 これは、モジュロ リダクションを適用する前の合計を表します。 
4. の倍数にわたって繰り返します。$x$から始まる$k=0$。 インターバルごとに$[kx, (k+1)x - 1]$、要素の数を数えます$[l,r]$この値の範囲に収まります。 
5. 各値ブロックについて、剰余合計に対するその寄与を計算します。 あらゆる要素$a$このブロックでは貢献します$a - kx$、まさにその通りなので$a \bmod x$いつ$a$その隙間にあります。 
6. すべてのブロックにわたる寄与を累積し、結果を出力します。 

重要な設計上の選択は、配列インデックスを反復するのではなく、値ブロックを反復することです。 これにより、複雑さはクエリごとの要素ごとからクエリごとの値の範囲ごとに移行します。 

### なぜ効果があるのか

 すべての整数$a$フォームの 1 つの区間にのみ属します$[kx, (k+1)x)$、その間隔内での値は$a \bmod x$一次式に簡略化します$a - kx$。 これにより、値ドメイン全体が、寄与ルールが均一な互いに素なセグメントに分割されます。 パーティションはのみに依存するため、$x$、個々の位置を繰り返し検査することなく、セグメントごとの寄与を集計することができ、正確性は、これらの間隔がすべての可能な値の完全で重複しないカバーを形成するという事実から得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXA = 200000

def build_prefix(a):
    n = len(a)
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]
    return pref

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    pref = build_prefix(a)

    pos = [[] for _ in range(MAXA + 1)]
    for i, v in enumerate(a):
        pos[v].append(i + 1)

    def count_in_range(l, r, v):
        arr = pos[v]
        # binary search manually
        lo, hi = 0, len(arr)
        while lo < hi:
            mid = (lo + hi) // 2
            if arr[mid] < l:
                lo = mid + 1
            else:
                hi = mid
        left = lo

        lo, hi = 0, len(arr)
        while lo < hi:
            mid = (lo + hi) // 2
            if arr[mid] <= r:
                lo = mid + 1
            else:
                hi = mid
        right = lo
        return right - left

    out = []

    for _ in range(q):
        l, r, x = map(int, input().split())

        total = pref[r] - pref[l - 1]
        res = 0

        if x == 1:
            out.append("0")
            continue

        if x > MAXA:
            out.append(str(total))
            continue

        k = 0
        while k * x <= MAXA:
            L = k * x
            R = min(MAXA, (k + 1) * x - 1)

            for v in range(L, R + 1):
                cnt = count_in_range(l, r, v)
                if cnt:
                    res += cnt * (v - k * x)

            k += 1

        out.append(str(res))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、高速範囲合計クエリ用のプレフィックス合計を構築することから始まります。 また、二分検索を使用してクエリ範囲内の出現をカウントできるように、各値の位置も事前に計算されます。 

クエリごとに、値をサイズのブロックで処理します。$x$。 各ブロックは線形剰余式に寄与し、ブロック内の値を反復処理することでこれらの寄与を蓄積します。 特別な取り扱い$x=1$そして$x > MAXA$不必要な作業を回避します。 

微妙な実装の詳細は、位置配列の 1 ベースのインデックス付けであり、これにより範囲カウント ロジックが簡素化されます。 もう 1 つは、境界内に含まれるインデックスの数を計算する際の慎重な境界処理です。$[l,r]$。 

## 実用的な例

 ### サンプル 1

 1 つのクエリを考えます。$l=2$、$r=6$、$x=5$、配列を使用$[14,16,9,6,9,10,16]$。 

サイズ 5 の値ブロックを処理します。 

| ブロック k | 値の範囲 | 範囲内の要素 | 要素ごとの貢献度 | カウント | 部分合計 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0-4 | なし | 0 | 0 | 0 |
 | 1 | 5-9 | 9,6,9 | (v - 5) | 3 | 4+1+4 = 9 |
 | 2 | 10-14 | 10 | (v - 10) | 1 | 0 |
 | 3 | 15-19 | 16,16 | (v - 15) | 2 | 1+1 = 2 |

 最終的な答えは、$9 + 0 + 2 = 11$、セグメントの計算された剰余合計と一致します。 

このトレースは、値の間隔によるグループ化によって要素ごとのモジュロ計算が構造化された集計にどのように置き換えられるかを示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(Q \cdot \frac{MAXA}{x} \log N)$償却済み | 各クエリは値ブロックを反復します。 カウントには二分探索が使用されます。 
| スペース |$O(N + MAXA)$| 値およびプレフィックス配列ごとの位置 |

 制約$A_i \le 2 \cdot 10^5$値ドメインがブロック分解に十分小さいことを保証します。 大規模なクエリ$x$生成するブロックが少なく、合計実行時間を制限内に抑えることができるため、自動的にコストが安くなります。

 ## 特殊なケース

 のために$x=1$、すべての値は剰余ゼロにマップされます。 アルゴリズムはこのケースを明示的に短絡するため、ブロック ロジックに入らずにすぐに 0 を返します。 これにより、すべての値グループに対する不必要な反復が回避されます。 

のために$x > MAXA$、次のブロック境界に到達する値はないため、$a_i < x$。 ブロック ループはこれを検出します。$k=0$は有効であり、すべての寄与がゼロ調整に減少するため、答えは単純な範囲の合計になります。 

値が繰り返される配列の場合、位置リストにより範囲内での正確なカウントが保証されます。 たとえば、値 5 がインデックスに表示される場合、$[2, 10, 20]$、クエリ$[1, 15]$バイナリ検索境界を介して 2 つの出現を正しくカウントし、ブロック ロジックは、二重にカウントすることなく、このカウントに値ごとの正しい寄与を乗算します。
