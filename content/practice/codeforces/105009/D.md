 ## 解決策
 ## 問題の理解

 各テスト ケースでは、同じ長さの 2 つの配列が与えられます。 位置を左から右に処理します。 位置で`i`、値から始めます`a[i]`オプションで、以前の値のサブセットを乗算することもできます。`a[1] ... a[i-1]`。 以前の各値は最大 1 回使用できますが、まったく使用しないことも選択できます。 

このサブセットを選択し、すべてを掛け合わせた後は、結果の積の最後の桁だけを気にする必要があります。 問題は、その数字を正確に取得できるかどうかです。`b[i]`単位の桁として。 

難しいのは、製品自体が非常に大きくなる可能性があるにもかかわらず、重要なのは最後の桁だけであることです。 これは、すべての計算を 10 を法とする算術演算に削減でき、最後の桁を正規化することで負の値を処理できることをすぐに示唆します。 

制約は私たちを`O(n)`または`O(n log n)`テストケースごとのソリューション。 テスト ケース全体の要素の総数は次のとおりです。`5 * 10^5`、サブセットを明示的に試したり、指数関数的な組み合わせを探索したりするソリューションは、すぐに失敗します。 テスト ケースごとの 2 次アプローチでも、最悪の場合には時間がかかりすぎます。 

微妙な点は、ゼロを乗算すると、以前のすべての寄与が破壊されることです。 前の要素が 0 の場合、他の要素に関係なく、到達可能な最後の桁のセットは単一の値に折りたたまれます。 もう 1 つの微妙な点は、前の要素の異なるサブセットがさまざまな方法で同じ最後の桁を生成する可能性があるため、実際にはサブセットにわたる組み合わせ論ではなく、小さな有限状態空間での到達可能性を扱っていることです。 

単純な間違いは、前の要素のすべてのサブセットを試行することで各インデックスを独立して解決できると考えることです。 のために`n = 2000`、それはすでに実行不可能になっています`2^n`サブセット。 もう 1 つの間違った単純化は、数字が以前に表示されたかどうかだけを追跡することです。`a[i] % 10`、乗法相互作用を無視します。 たとえば、数字がある場合`2`そして`5`にアクセスできるようにする`0`（なぜなら`2 * 5 = 10`)、プレゼンスのみのモデルではこれが見逃されます。 

## アプローチ

 ブルートフォース解釈は簡単です。インデックスごとに、前の要素のすべてのサブセットを列挙し、乗算します。`a[i]`各サブセットごとに最後の桁を計算し、等しいものがあるかどうかを確認します。`b[i]`。 これは定義に直接従うため、正しいです。 ただし、それぞれのポジションには、`i - 1`前の要素なので、これは`O(2^(i-1))`インデックスごとの作業量が爆発的に増加し、実現可能な制限を超えます。 

重要な観察は、完全な値は決して必要ではなく、10 を法とする乗算だけが必要であるということです。これにより、問題は桁の乗法半群の処理に軽減されます。`{0..9}`。 基本数字を繰り返し乗算しています`a[i] % 10`以前に確認された数字のサブセット積によって計算されます。 

サブセットの観点から考えるのではなく、プロセスを動的に再解釈します。 各ステップで、前の要素のサブセットを使用して形成できるすべての可能な積 (mod 10) を維持します。 新しい要素が到着すると、既存の到達可能な数字はすべて変更されないままになるか、新しい数字で乗算されます。 これは古典的な「小さな状態空間上のサブセット閉包」であり、状態空間には 10 個の要素しかありません。 

これにより、問題は、処理された要素のサブセットからどの最後の桁が取得可能かを表すサイズ 10 のビットマスクを維持することに変換されます。 新しい数字ごとに、古い州とその積を新しい数字とマージすることでこのマスクが更新されます。 

次に、次のことを確認することで各クエリに答えることができます。`b[i]`乗算することで達成可能です`a[i] % 10`プレフィックスから到達可能なサブセット製品を使用します。

 ## アルゴリズムのチュートリアル

 各プレフィックスをセットを維持するものとして扱います`S`前の要素のサブセットを使用して形成できる 10 を法とする可能な乗算結果。 

1.初期化`S = {1}`。 これは、積 1 を生成する空のサブセットを表します。何も乗算しても値が変更されるべきではないため、恒等式が必要です。 
2. 各インデックスについて`i`、計算する`x = a[i] % 10`。 もし`x`が負である場合は、次のように正規化します`[0, 9]`を使用して`(x + 10) % 10`。 これにより、一貫したモジュラー乗算が保証されます。 
3. 状態を更新する前に、次のことを確認してください。`b[i]`現在のプレフィックスを使用して実現できます。 これは、`s ∈ S`そのような`(s * x) % 10 == b[i]`。 「はい」の場合は出力します`Y`、それ以外の場合は出力`N`。 
4. を使用するかどうかを考慮して、到達可能なセットを更新します。`a[i]`将来のサブセットでは。 既存のすべての状態に対して`s`を維持することも、次の値を乗算して拡張することもできます。`x`。 そこで新しいセットを構築します`S' = S ∪ { (s * x) % 10 for all s in S }`。 
5.割り当て`S = S'`そして続けます。 

確認後に更新する理由は、`a[i]`はそれ自体の決定では許可されず、前の要素のみが許可されます。 

### なぜ効果があるのか

 不変条件は、インデックスを処理した後のものです。`i - 1`、セット`S`のサブセットによって形成される積の考えられるすべての最後の桁が正確に含まれます。`a[1..i-1]`。 更新ステップでは、すべてのサブセットが正しいため、正確さが維持されます。`a[1..i]`どちらかを除外します`a[i]`(すでに入っています`S`) またはそれを含みます (乗算によって捕捉されます)`x`のあらゆる要素で`S`）。 乗算のモジュロ 10 が閉じているため、他の値は現れません。 これにより、メンバーシップのクエリが確実に行われます。`S`プレフィックス サブセット製品の到達可能性を正解します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        # reachable last digits from subsets of processed prefix
        S = set([1])

        ans = []

        for i in range(n):
            x = a[i] % 10
            if x < 0:
                x += 10

            # query before updating with a[i]
            ok = False
            for s in S:
                if (s * x) % 10 == b[i]:
                    ok = True
                    break

            ans.append('Y' if ok else 'N')

            # update reachable set
            newS = set(S)
            for s in S:
                newS.add((s * x) % 10)

            S = newS

        out.append(''.join(ans))

    print('\n'.join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、達成可能な最後の桁のセットを維持します。 重要な実装の詳細は、挿入する前に現在のプレフィックス状態を使用して実現可能性をチェックすることです。`a[i]`なぜなら、この問題では厳密に前の要素の使用のみが許可されているからです。 次に、更新ステップにより、将来のインデックスの状態空間が拡張されます。 

状態空間は 10 桁の可能な桁で制限されるため、Python セットの使用は許容されます。そのため、すべてのセット演算は実質的に定数時間になります。

 ## 特殊なケース

 重要なエッジケースは、ゼロが早く現れる場合です。 仮定する`a = [2, 0, 7]`。 加工後`2`、到達可能なセットは`{1, 2}`。 後`0`、以下を含むサブセットの選択肢を含むすべての製品`0`になる`0`、したがってセットは次のようになります`{0, 1, 2}`しかし事実上、将来の乗算には常に次のものが含まれます。`0`支配的な吸収状態として。 アルゴリズムはこれを正しく処理します。`0`挿入のみ`0`、以前の状態はすべて有効なままです。 

もう 1 つの特殊なケースは負の数です。 もし`a[i] = -19`、その桁は`9`。 モジュロ正規化を使用すると、次のことが保証されます。`-19 % 10`として扱われます`9`、最後の桁の演算では符号の方向が無視されるため、正確さが維持されます。 

最後に、たくさんの数字を繰り返しました`5`このアルゴリズムは、サブセットを明示的に追跡することはなく、到達可能な残基のみを追跡するため、組み合わせ解釈が爆発的に増加した場合でも安定したままになります。
