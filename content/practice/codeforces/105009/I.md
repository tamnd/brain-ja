 ## 解決策
 ## 問題の理解

 数直線上の線分の集合が与えられます。 重要な構造上の制約は、任意の 2 つのセグメントが互いに素であるか、一方が他方を完全に含んでいるかのいずれかであるということです。 部分的な重複は存在せず、すべてのエンドポイントは個別です。これは、セグメントが任意の間隔グラフではなく、きれいな入れ子構造を形成していると考えることができることを意味します。 

ホリは「バイト」を実行してセグメントを削除します。 彼女は一口で 1 つのセグメントを選択すると、そのセグメントはその内部のすべてのセグメントとともに消えます。 目標は、このようなバイトを一連にしてすべてのセグメントを除去することです。 どのセグメントをどの順序で噛ませるかの選択が異なると、たとえ封じ込めのために複数のセグメントが一度に削除されたとしても、異なる有効なシーケンスが定義されます。 

各テスト ケースの出力は、1e9+7 を法として取得された、すべてのセグメントを削除する個別の有効なシーケンスの数です。 

すべてのテスト ケースの合計 N が最大 5000 であるという制約が、重要な構造上のヒントです。 これは、テストごとの 2 次または 3 次 DP には十分小さいですが、シーケンスやサブセットの指数関数的な列挙には大きすぎます。 考えられるすべての削除順序、または選択した「代表セグメント」のすべてのサブセットを明示的にシミュレートするソリューションは、各セグメントが含まれる構造に応じて複数の選択肢に分岐する可能性があるため、爆発的な影響を及ぼします。 

微妙なエッジの動作は、一口で複数のセグメントを除去できるという事実から生じます。 たとえば、外側のセグメント [1, 10] と内側のセグメント [2, 3] および [4, 5] がある場合、[1, 10] を選択するとすぐにすべてが削除されます。 ただし、最初に内側のセグメントを選択すると、シーケンスが異なります。 正確性の条件は、選択されたセグメントのセットだけではなく、順序付けられた削除戦略のカウントに依存します。 

隠れた主な落とし穴は、セグメントを削除するとそのサブツリー全体が一度にどのように折りたたまれるかを注意深くモデル化せずに、これを単純なツリー数の問題として扱うことです。 もう 1 つの落とし穴は、セグメントの選択がそのノードのみの削除に相当すると想定しており、強制的なカスケード削除を見逃してしまいます。 

## アプローチ

 入れ子プロパティは、各セグメントをノードとして解釈し、各セグメントをそれを含む最小のセグメントに接続すると、セグメントがフォレストを形成することを意味します。 エンドポイントは個別であり、交差は包含を意味するため、この構造は明確に定義され、すべてをカバーする仮想ルートを追加すると、ルートのあるフォレストが形成されます。 

この包含ツリーを構築すると、問題は、ノードを選択するとそのサブツリー全体が 1 回の操作で削除される、ルート化されたツリーに対するカウントの問題になります。 ただし、シーケンスは重要であるため、依存関係を伴うサブツリーの崩壊の順列をカウントしています。 

強引なアイデアは、すべての有効なシーケンスをシミュレートすることです。各ステップで、残りのセグメントを選択し、そのサブツリー全体を削除して、再帰します。 これにより、最初は最大 N の分岐係数が探索され、その後徐々に縮小していきます。 最悪の場合、たとえばネストされたセグメントのチェーンでは、シーケンスの数は階乗サイズの選択肢の並べ替えのように増加しますが、これは実現不可能です。 

重要な観察は、包含ツリーを修正すると、セグメントを削除するプロセスが残りのコンポーネントのルートを繰り返し選択することに相当するということです。 各コンポーネントは、包含によって引き起こされる順序付けの制約を除いて、独立して動作します。 これにより、各ノードがその子がどのようにインターリーブまたは選択されるかに応じて組み合わせ因子に寄与するツリー上の DP が得られます。 

正しい構造は、各ノードが多項インターリーブを介してその子を結合すると同時に、ノードを選択するとそのサブツリー全体が 1 回のアクションで削除されるという事実も考慮したものであることが判明しました。 これにより、ツリーの折りたたみ操作によって引き起こされる半順序の有効な線形拡張をカウントするのと同様の反復が作成されます。

各ノードについて、サブツリーを削除する方法の数とサブツリーのサイズを計算し、サブツリーの削除の順序が重要な場合には DP を使用して子を結合します。

 | 組み合わせ論を使用したツリー DP | テストあたり O(N^2) (合計 N ≤ 5000) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 包含ツリーを分類して構築する

 セグメントを左端点の昇順で並べ替え、等しい場合は右端点の降順で並べ替えます。 次に、スタックを使用して親子関係を決定します。セグメントの親とは、セグメントを完全に含む最小のセグメントです。 

これが機能するのは、ネスト プロパティにより、ソート順にスキャンしたときにコンテナーがスタックのような構造を形成することが保証されるためです。 

### ステップ 2: 隣接リストを作成する

 各セグメントはツリー (またはフォレスト) 内のノードになります。 各ノードを、包含構造によって決定される直接の子に接続します。 

また、複数の最上位コンポーネントを均一に処理できるように、すべてのセグメントを含む仮想ルートも導入します。 

### ステップ 3: DP 状態を定義する

 各ノードについて`u`、2 つの値を計算します。`sz[u]`はサブツリー内のセグメントの数です。`u`、それ自体も含めて。`dp[u]`をルートとするサブツリー内のすべてのセグメントを完全に削除するための有効なシーケンスの数です。`u`。 

直感というのは、`dp[u]`このコンポーネントに限定されるすべての有効な「バイト シーケンス」をカウントします。 

### ステップ 4: 基本ケース

 ノードに子がない場合、そのノードは単一のセグメントを表します。 それを取り除く方法は一つしかないので、`dp[u] = 1`そして`sz[u] = 1`。 

### ステップ 5: 子を結合する

 ノードの場合`u`子供たちと一緒に`c1, c2, ..., ck`、最初にすべての子の DP 値を再帰的に計算します。 

次に、異なるサブツリーの削除は任意の順序でインターリーブできるが、サブツリーの整合性を尊重する必要があるという考えを使用して、それらを結合します。 

実行中の畳み込みを維持します。 

サイズ 0 および dp 1 の「現在のシーケンス」から始めます。 

それぞれの子どもたちにとって`c`、サブツリー全体の削除イベントがすでに処理された子の間にインターリーブできる位置を選択して、それをマージします。 インタリーブの数は、サブツリーのサイズに基づいた二項係数によって与えられます。 

具体的には、合計サイズ S の構造体を既に処理しており、サイズ s の子サブツリーを追加した場合、dp[c] を乗算し、C(S + s, s) を乗算して S を更新します。 

### ステップ 6: ノード自体を処理する

 子の処理後、ノード自体も有効な削除アクションになります。 ノードを選択すると、サブツリー全体が 1 ステップで削除されるため、サブツリー全体が即座に折りたたまれる代替シーケンスが生成されます。 

したがって、ノードごとに「ルート選択」ケースを 1 つ追加します。`dp[u] += 1`これは、内部構造を完全にスキップして、セグメント全体を一度に噛むという選択を反映しています。 

### ステップ 7: 最終的な答え

 答えは`dp[root]`ここで、ルートは他のすべてを含む仮想セグメントです。 

### なぜ効果があるのか

 包含構造は、すべての有効なシーケンスがサブツリー削除のシーケンスの選択に対応するツリー分解を保証します。 各サブツリーは順序付けの制約を除いて独立して動作し、すべての有効なインターリーブはサブツリー削除イベントの順列に一意に対応します。 DP は、サブツリー インターリーブの各組み合わせが折りたたみ操作の一意のグローバル順序に対応するため、すべてのシーケンスが 1 回だけカウントされることを保証します。一方、「ノード全体を取得」オプションはすべての内部構造をバイパスするショートカット削除パスをキャプチャします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    seg = []
    coords = set()

    for _ in range(n):
        l, r = map(int, input().split())
        seg.append((l, r))
        coords.add(l)
        coords.add(r)

    # sort by left asc, right desc for nesting
    seg.sort(key=lambda x: (x[0], -x[1]))

    # build tree using stack
    parent = [-1] * n
    stack = []

    for i, (l, r) in enumerate(seg):
        while stack and seg[stack[-1]][1] < r:
            stack.pop()
        if stack:
            parent[i] = stack[-1]
        stack.append(i)

    children = [[] for _ in range(n)]
    roots = []

    for i in range(n):
        if parent[i] == -1:
            roots.append(i)
        else:
            children[parent[i]].append(i)

    # add virtual root
    root_children = roots

    # factorials for binomial coefficients
    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)

    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(a, b):
        if b < 0 or b > a:
            return 0
        return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

    sys.setrecursionlimit(10**7)

    def dfs(u):
        sz = 1
        dp = 1

        for v in children[u]:
            csz, cdp = dfs(v)
            dp = dp * cdp % MOD
            dp = dp * C(sz + csz, csz) % MOD
            sz += csz

        dp = (dp + 1) % MOD
        return sz, dp

    res = 0
    for r in root_children:
        _, val = dfs(r)
        res = (res + val) % MOD

    print(res)

t = int(input())
for _ in range(t):
    solve()
```実装は、ネストされたセグメントがスタック順序で処理されるようにセグメントを並べ替えることから始まります。これにより、テスト ケースごとに線形時間で包含ツリーを再構築できるようになります。 

階乗事前計算は、二項係数の高速計算をサポートします。インターリーブは、すでに配置されたイベントの中から 1 つのサブツリーの位置を選択することに対応するため、子サブツリーをマージするときに必要となります。 

DFS はサブツリーのサイズと DP 値を同時に計算します。 各子について、最初にその DP 値を乗算し、次に組み合わせを使用して以前に処理されたノード間でそのサブツリーをインターリーブする方法の数を乗算します。 

決勝戦`+1`各ノードで、サブツリー全体を 1 バイトで削除するオプションをエンコードします。これは、そのセグメントをルート削除アクションとして直接選択することに対応します。 

## 実用的な例

 ### 例 1

 セグメントを考慮してください。```
[1,6], [2,5], [3,4]
```| ノード | 子どもたち | サイズ | DP |
 | --- | --- | --- | --- |
 | [3,4] | なし | 1 | 1 |
 | [2,5] | [3,4] | 2 | (1 * C(1,1)) + 1 = 2 |
 | [1,6] | [2,5] | 3 | (2 * C(1,2)) + 1 = 3 |

 最終的な答えは 3 です。 

このトレースは、完全な折りたたみオプションを引き続き許可しながら、ネストされた構造がどのように組み合わせインターリーブを蓄積するかを示しています。 

### 例 2

 セグメント:```
[1,4], [2,3]
```| ノード | 子どもたち | サイズ | DP |
 | --- | --- | --- | --- |
 | [2,3] | なし | 1 | 1 |

 答えは 2 です。これは、内側を削除してから外側を削除するか、外側を直接削除するかのいずれかに対応します。 

これは、「直接崩壊」の選択と構造化ピーリングの比較を示しています。

 ## 特殊なケース

 単一セグメントのケースは、可能な限り最も単純な構造を示しています。包含ツリーには 1 つのノードが含まれているため、唯一の有効なシーケンスは、それを即座に削除する単一のバイトです。 アルゴリズムは次のように割り当てます。`dp = 1`リーフでそれを変更せずに返し、期待される出力と一致します。 

次のような完全にネストされたチェーン`[1,6], [2,5], [3,4]`演習はマージを繰り返します。 各レベルではサブツリーのサイズが増加し、二項インターリーブ ロジックが強制的にアクティブになります。 DP は組み合わせを正しく蓄積しながら、すべてのノードで直接折りたたみを許可し、構造化削除とショートカット削除の両方が確実にカウントされるようにします。 

複数のルートは、ルート コンポーネント全体の DP 値を合計することによって処理されます。 ルートはセグメントが重複していないため独立しているため、それらのシーケンスは干渉しません。 このアルゴリズムは各ルートを個別に処理して集約するため、ツリー間の組み合わせを必要とせずに正確性が維持されます。
