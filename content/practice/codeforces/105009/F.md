 ## 解決策
 ## 問題の理解

 都市間の道路網を表す有向重み付きグラフが与えられます。 固定の開始都市から$s$、目標の都市に到達したい$t$。 グラフにはすでに含まれています$M$道路、さらには$K$オプションの道路。 これらのオプションの道路のうち最大 1 つを選択し、それをグラフに永続的に追加することができます。 どの 1 本の道路を追加するか (またはまったく追加しない) を決定した後、そこからの最短距離を調べます。$s$に$t$。 

タスクは、次の間の最小達成可能な最短経路距離を計算することです。$s$そして$t$この選択の後。 

この制約により、最短経路の前処理が求められます。 と$N \le 10^4$そして$M \le 10^5$、ダイクストラのアルゴリズムを実行することは可能ですが、それぞれの最短経路を最初から再計算するようなことは可能です。$K \le 10^4$候補エッジが遅すぎる可能性があります。 候補エッジごとに完全な最短パス アルゴリズムを実行する単純なアプローチでは、最大で$K$ディクストラの実行、それぞれ$O(M \log N)$、それは限界をはるかに超えています。 

最適なパスで候補エッジが使用されているが、その両側の距離の再計算も必要な場合、微妙な問題が発生します。 両方向からの距離を事前に計算しないと、二重にカウントされたり、パスの有効な分解が欠落したりする危険があります。 

いくつかの特殊なケースが重要です。 

パスを改善する候補エッジがない場合、答えは単純にベース グラフ内の元の最短パスになります。 少なくとも 1 つのエッジが有用であると想定する単純なソリューションでは、誤って無限大を返したり、「何も使用しない」オプションを考慮しなかったりする可能性があります。 

もし$s = t$の場合、空のパスが有効であるため、追加されたエッジに関係なく、答えは常に 0 になります。 

グラフが最初に切断されている場合は、いくつかの候補エッジが接続する唯一の方法である可能性があります。$s$に$t$したがって、マルチソース構造を無視すると失敗します。 

## アプローチ

 強引なアイデアは簡単です。 それぞれについて、$K$候補道路を一時的にグラフに追加し、そこから最短経路を再計算します。$s$に$t$。 何も追加しない場合も考えます。 各最短経路の計算コスト$O(M \log N)$ダイクストラを使用するため、全体の複雑さは次のようになります。$O(K M \log N)$。 と$K = 10^4$そして$M = 10^5$、これは実現可能な限界をはるかに超えています。 

重要な点は、最短パスを繰り返し再計算する必要がないということです。 代わりに、候補エッジの寄与を 2 つの独立した部分に分けることができます。つまり、その開始点からどこまで到達できるかです。$s$、そしてその終わりからどこまで行くことができるか$t$。 これは、2 方向の最短パスを事前に計算することを示唆しています。 

からディクストラを1回実行します$s$計算する$dist_s[x]$からの最短距離$s$すべてのノードに。 次に、すべてのエッジを反転して、ダイクストラを実行します。$t$計算する$dist_t[x]$、すべてのノードからノードまでの最短距離が得られます。$t$。 

これで、各候補エッジが$u \to v$重さで$w$フルパスを形成できる$s \to u \to v \to t$費用がかかる$dist_s[u] + w + dist_t[v]$。 すべての候補の最小値を取得し、元の候補と比較します。$dist_s[t]$。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(K M \log N)$|$O(N + M)$| 遅すぎる |
 | 最適 (ダイクストラ実行 2 回) |$O((N + M)\log N + K)$|$O(N + M)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 最適なソリューション

 1. 元のグラフの有向隣接リストを作成します。 また、すべてのエッジが含まれる逆隣接リストも作成します。$u \to v$になる$v \to u$。 ソースからだけでなくターゲットまでの距離も必要なので、反転したグラフが必要です。 
2. から始めてダイクストラを実行します。$s$元のグラフ上で計算します$dist_s[x]$からの最短距離$s$すべてのノードに。 これにより、オプションのエッジを使用する前に、中間ノードに到達するための最適な方法がすべてキャプチャされます。 
3. から始めてダイクストラを実行します。$t$反転したグラフで計算します$dist_t[x]$、からの最短距離に相当します。$x$に$t$元のグラフでは。 これにより、候補エッジを使用した後にサフィックス パスを評価できるようになります。 
4. 答えを次のように初期化します。$dist_s[t]$これは、追加のエッジをまったく使用しないことに相当します。 
5. 候補道路ごとに$u \to v$費用がかかる$w$、パス値を計算します$dist_s[u] + w + dist_t[v]$。 これは、新しい道路に 1 回だけ入り、その後目的地まで最適に進む経路を表します。 
6. 現在の値と計算されたすべての候補パス コストの最小値を使用して、答えを更新します。 
7. 最終的な答えを出力します。 

### なぜ効果があるのか

 からの任意の有効なパス$s$に$t$追加エッジを 1 つまで使用するものは 3 つのセグメントに分解できます。$s$どこかのノードに$u$、次に選択した新しいエッジ$u \to v$、次に、からの最短の継続$v$に$t$。 すべてのエッジの重みは負ではないため、これらのエンドポイントへの最短パスとエンドポイントからの最短パスは独立しており、最適性を失うことなく事前計算できます。 これにより、各候補エッジが次のように評価されることが保証されます。$dist_s[u] + w + dist_t[v]$そのエッジのあらゆる可能な最適な使用法を捉えます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline
INF = 10**18

def dijkstra(start, adj, n):
    dist = [INF] * (n + 1)
    dist[start] = 0
    pq = [(0, start)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    return dist

def solve():
    n, m, k, s, t = map(int, input().split())

    adj = [[] for _ in range(n + 1)]
    radj = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v, w = map(int, input().split())
        adj[u].append((v, w))
        radj[v].append((u, w))

    candidates = []
    for _ in range(k):
        u, v, w = map(int, input().split())
        candidates.append((u, v, w))

    dist_s = dijkstra(s, adj, n)
    dist_t = dijkstra(t, radj, n)

    ans = dist_s[t]

    for u, v, w in candidates:
        if dist_s[u] < INF and dist_t[v] < INF:
            ans = min(ans, dist_s[u] + w + dist_t[v])

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は 2 つの標準ダイクストラ実行に依存しています。 最初のものは前方距離を計算します$s$、2 番目は反転したグラフを使用して距離を計算します。$t$。 反転グラフは、すべてのノードからダイクストラを実行する必要がないため、不可欠です。 次に、各候補エッジは、事前に計算された値を使用して一定時間で評価されます。 

よくある間違いは、「新しいエッジを使用しない」という基本的な回答を含めるのを忘れることです。 もう 1 つは、ダイクストラ内の候補エッジを緩和しようとしていますが、パス緩和ステップごとではなく、グローバルに 1 つの候補エッジのみが許可されるため、問題が発生します。

 ## 特殊なケース

 エッジケースの 1 つは、元のグラフが接続されていない場合です。$s$に$t$。 たとえば、パスがない場合、$dist_s[t]$は無限大です。 その状況では、候補エッジが最初の有効なルートを作成する可能性があります。 アルゴリズムはこれを自然に処理します。$dist_s[u]$そして$dist_t[v]$引き続き使用可能であり、有効な組み合わせのみが有限の値に影響します。 

もう一つのケースは次のような場合です。$s = t$。 ダイクストラはすぐにゼロを返し、すべての候補式は正の値を加算するため、最小値はゼロのままになります。 

最後の微妙なケースは、複数の候補エッジがエンドポイントを共有する場合です。 アルゴリズムはそれぞれを独立して処理し、距離をグローバルに事前計算するため、重複する構造は正確さに影響しません。
