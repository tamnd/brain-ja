 ## 解決策
 ## 問題の理解

 最初は (1, 1) の正の整数の順序付きペアで記述される単一の状態から開始します。 各移動は、非常に構造化された方法で状態を変更します。最初のコンポーネントが 2 番目のコンポーネントを吸収するか、2 番目のコンポーネントが最初のコンポーネントを吸収します。 多くの移動の後、状態の成長バイナリ ツリーが得られます。このツリーでは、すべてのノードがこれら 2 つの操作によって 2 つの子に分割されます。 

一連の演算は、線形式 ax + by がしきい値 c より厳密に大きくなる瞬間まで有効であるとみなされます。 その境界を越えると、そのシーケンスのプロセスは停止します。 異なるシーケンスは、その長さ、または任意のステップで左または右の操作が選択されたかどうかによって区別されるため、この無限二分木内のすべての個別のパスが個別に答えに寄与しますが、それは線形制約が満たされる点までに限られます。 

タスクは、クエリ (a、b、c) ごとに、すべての中間状態で制約 ax + by ≤ c 内に留まり、制約に違反したときに正確に終了する個別の操作シーケンスの数をカウントすることです。 

この制約は、最大 200,000 という非常に多くのクエリを示唆していますが、すべての c 値の合計は最大 1,000,000 です。 これが重要なシグナルです。c のクエリごとに線形時間を費やすソリューションはいずれも潜在的に許容されますが、クエリごとの c の二次関数は不可能です。 同様に、ツリーのサイズは深さとともに指数関数的に増大するため、クエリごとの操作ツリーの完全な走査は直ちに除外されます。 

ax + by が c を超えるまで、到達可能なすべての状態を明示的に生成する単純なシミュレーションでは、中程度の値ではすでに爆発します。 c が小さい場合でも、分岐はステップごとに 2 倍になるため、状態の数は指数関数的に深くなります。 たとえば、(1,1) から開始すると、わずか 20 回の操作の後、すでに 2^20 の状態が存在し、実現可能な限界をはるかに超えています。 

x + y の値によって単純に状態を追跡できると仮定すると、さらに微妙な問題が生じます。 異なるシーケンスが同じペアにつながる可能性がありますが、プロセスがマージされることはないため、ここでは重複状態の追跡は意味がありません。 構造はグラフではなくツリーです。 

## アプローチ

 直接的な総当たりアプローチは、(1, 1) をルートとするバイナリ ツリーを探索し、各ノードを 2 つの子に拡張し、ax + by ≤ c を満たすノードの数を数えることです。 すべての有効なシーケンスが 1 つのノードに正確に対応するため、これは概念的には正しいです。 ただし、ノードの数は深さとともに指数関数的に増加し、制約 ax + by ≤ c は、ツリーの幅ではなく線形方向の増加のみを制限します。 中程度の c の場合でも、ツリーにはトラバースするには多すぎるノードが含まれています。 

重要な構造的洞察は、このツリーが任意のものではないということです。 これは Calkin-Wilf ツリーであり、すべてのノード (x, y) が縮小分数 x/y の一意の表現であり、すべての正の互いに素のペアが 1 回だけ出現することを意味します。 2 つの操作により、繰り返されることなくすべての互いに素のペアが生成されます。 

これにより問題が変わります。 ツリー内のパスを数える代わりに、線形制約 ax + by ≤ c の下で gcd(x, y) = 1 で格子点 (x, y) を数えます。 これは、メビウス関数による包含排他を使用して解決できる古典的な数理論の計数問題です。 

まず、不等式を満たすすべての整数ペア (x, y) をカウントし、次に、縮小されたグリッドから寄与を差し引くことによって、gcd(x, y) > 1 となる整数ペアを削除します。

 ## アルゴリズムのチュートリアル

1. 可能な最大 c 値までメビウス関数を事前計算します。 これにより、gcd 制約に対する高速な包含/除外が可能になります。 メビウス関数は、互いに素のペアを数えるときに倍数の部分集合がどのようにキャンセルされるかをエンコードします。 
2. 各クエリ (a、b、c) について、ax + by ≤ c および gcd(x, y) = 1 となるような格子点 (x, y) のカウントとして問題を再解釈します。これにより、ツリー トラバースの観点が整数座標に関するカウント問題に置き換えられます。 
3. gcd に対して包含/除外を適用します。 互いに素な解を直接数えるのではなく、すべての解を考慮し、x と y の両方が何らかの整数 d で割り切れる解を減算します。 これにより、寄与がμ(d) によって重み付けされる分解が行われます。 
4. 各除数スケール d について、制約を a(dx) + b(dy) ≤ c に削減します。これは、a x + b y ≤ ⌊c / d⌋ と同等です。 このような各項は、効率的に計算できる無制限の整数解をカウントします。 
5. a x + b y ≤ N に対する整数解の数を計算するには、可能な x 値を反復処理します。 それぞれの固定 x について、最大 y は (N − a x) // b です。 これらをすべての有効な x で合計すると、解の総数が得られます。 
6. μ(d) = 0 の値をスキップして、μ(d) を使用してすべての d にわたる寄与を累積します。最終的な答えは、1e9 + 7 を法とする加重和です。 

### なぜ効果があるのか

 すべての有効な演算シーケンスは一意の互いに素のペア (x, y) に対応し、そのようなすべてのペアは生成された構造内に 1 回だけ現れます。 線形制約は、どのノードがカウントされるかを制限するだけです。 ツリーを格子点問題に変換し、メビウス反転によって互いに素な点を分離することで、有効な状態がそれぞれ 1 回だけカウントされ、無効な多重度が代数的に相殺されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

MAXC = 200000

# Möbius function
mu = [1] * (MAXC + 1)
is_prime = [True] * (MAXC + 1)
primes = []

mu[0] = 0
for i in range(2, MAXC + 1):
    if is_prime[i]:
        primes.append(i)
        for j in range(i, MAXC + 1, i):
            is_prime[j] = False

# recompute mu properly
mu = [1] * (MAXC + 1)
mu[0] = 0
for p in primes:
    for i in range(p, MAXC + 1, p):
        mu[i] *= -1
    p2 = p * p
    for i in range(p2, MAXC + 1, p2):
        mu[i] = 0

def count_leq(a, b, n):
    if n <= 0:
        return 0
    res = 0
    max_x = n // a
    for x in range(1, max_x + 1):
        rem = n - a * x
        res += rem // b
    return res

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c = map(int, input().split())

        ans = 0
        d = 1
        while d <= c:
            if mu[d] != 0:
                ans += mu[d] * count_leq(a, b, c // d)
            d += 1

        print(ans % MOD)

if __name__ == "__main__":
    solve()
```メビウスの事前計算はグローバルに 1 回実行され、各クエリで同じ算術構造を再利用できるようになります。 機能`count_leq`は幾何学的なコアであり、x を合計し、線形境界の下に収まる y 値の数を計算します。 

d に対する外側のループは、包含と除外を適用します。 c まで反復されますが、クエリ全体の c の合計には制限があるため、集計作業は管理可能に保たれます。 

よくある落とし穴は、x と y が少なくとも 1 でなければならないことを忘れることです。これは、x を 1 から開始し、正の解のみを数えることで処理されます。 

## 実用的な例

 a = 1、b = 1、c = 5 の小さなクエリを考えてみましょう。x + y ≤ 5 および gcd(x, y) = 1 のペア (x, y) が必要です。 

d からの貢献を調べます。 

| d | μ(d) | c//d | count_leq(1,1,c//d) | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 5 | 10 | 10 |
 | 2 | -1 | 2 | 3 | -3 |
 | 3 | -1 | 1 | 1 | -1 |
 | 4 | 0 | 1 | 1 | 0 |
 | 5 | -1 | 1 | 1 | -1 |

 最終的な答えは 10 − 3 − 1 − 1 = 5 です。 

これは、すべての整数点ではなく、三角形の下のプリミティブ格子点を数えているという直観と一致します。 

ここで、a = 2、b = 3、c = 10 の場合を考えてみましょう。 

最初に 2x + 3y ≤ 10 までの整数解を数えてから、包含排除を通じて互いに素のペアに制限します。 この構造は、線形制約がどのように有限領域を切り分け、メビウス反転がその領域をプリミティブ点のみにフィルタリングするかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(∑ c + max c log max c) | 各クエリは d を c まで反復しますが、c の合計には制限があり、内部のカウントは c/a | で線形です。 
| スペース | O(最大 c) | Möbius 関数と補助配列のストレージ |

 この制約は償却に大きく依存しています。c では単一のクエリが線形になる可能性がありますが、すべてのクエリにわたる合計作業量は 10^6 の範囲にとどまります。 これにより、Python での実行が制限内に保たれます。

 ## 特殊なケース

 c が非常に小さい場合、特に c = 1 または c = 2 の場合、微妙なエッジ ケースが発生します。このような場合、考えられる唯一の候補はルート状態 (1,1) ですが、それでも a と b に応じて ax + by ≤ c を満たす場合と満たさない場合があります。 境界が正でない場合は count_leq がゼロを返し、包含と排他が自然に崩壊するため、アルゴリズムはこれをきれいに処理します。 

別のケースは、a と b が c に比べて大きい場合です。 たとえば、a = 100000、b = 100000、c = 1。制約により、すべての状態が直ちに除外されます。 c // d はすべての d に対してゼロになり、count_leq からゼロが生成されるため、内部のカウント ループは何も寄与しません。 

最後に、a と b が等しい場合は、対称性を強調します。 格子領域の構造は x = y に沿って対称になりますが、メビウス反転では依然として原始点が正しくフィルタリングされ、二重カウントや省略が発生しないことが保証されます。
