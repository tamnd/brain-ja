 ## 解決策
 ## 問題の理解

 私たちは一列の牛を与えられ、それぞれに体重が付けられています。 「RAID」は、開始位置とステップ サイズの 2 つの整数によって定義されます。 a の位置から開始して、b の位置ずつ前進を繰り返し、着地した牛をすべて回収し、ラインの終端を通過したら停止します。 各クエリでは、その特定の襲撃パターンによって収集されたすべての牛の合計重量が求められます。 

言い換えれば、各クエリは配列内のインデックスの等差数列を定義し、それらのインデックスの値を合計する必要があります。 

制約は大きく、最大 3×10^5 の牛と 3×10^5 のクエリです。 これにより、段階的に進行をたどることによって各クエリの合計を再計算するアプローチは即座に除外されます。 最悪の場合、b = 1 の 1 つのクエリが O(n) 要素に触れると、許容範囲をはるかに超える O(n·q) になります。 

b が大きい場合と小さい場合には、微妙なエッジ ケースが発生します。 b が大きい場合、各クエリはほとんど要素に触れず、コストがかかります。 b が小さい場合、多くのインデックスがクエリ間で重複し、単純な反復では同じ作業が何度も繰り返されます。 もう 1 つの問題は、a = 1 および b = 1 の場合です。これは配列全体を合計することになり、総当たりで繰り返し再計算される状況になります。 

単純な改善では、(a, b) ごとに結果をキャッシュしようとするかもしれませんが、最大 3×10^5 の個別のペアが存在する可能性があるため、これは最悪の場合役に立ちません。 

## アプローチ

 ブルート フォースのアイデアは簡単です。クエリごとにインデックス a から開始し、w[a]、w[a + b]、w[a + 2b] などを n を超えるまで繰り返し追加します。 これは、RAID の定義に正確に従っているため、正しいです。 問題はコストです。 b = 1 の最悪のケースでは、各クエリは n 個の要素を処理し、n と q が両方とも 3×10^5 の場合、全体で約 9×10^10 の演算が行われます。 

重要な観察は、ジャンプ サイズ b によって動作が 2 つの根本的に異なる領域に分割されるということです。 b が大きいということは、クエリあたりの訪問位置が少ないことを意味します。 b が小さいということは、多くのクエリが b を法とする同様の剰余クラスを共有することを意味するため、事前計算された情報を再利用できます。 私たちが利用する構造は、固定ステップ b によって訪問されるインデックスが独立した算術シーケンスを形成し、b が小さい場合、そのようなシーケンスは全体でわずかしか存在しないというものです。 

これはハイブリッド ソリューションにつながります。 √n 付近のしきい値 B を選択します。 b が B より大きい場合、クエリは最大でも n / B 個の要素のみを訪問するため、各クエリを直接計算します。 b 以下の場合、右から左へ動的計画法を使用してすべての可能な (b, 剰余) ペアの答えを事前計算するため、各クエリは O(1) になります。 

重要な遷移は反復を書き直すことです。固定 b に対して、dp[i] = w[i] + dp[i + b] を定義します。 これにより、特定の b に対するすべての答えを 1 回のパスで計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | ステップ サイズの Sqrt 分解 | O(n√n + q√n) | O(n√n) | 承認済み |

 ## アルゴリズムのチュートリアル

 しきい値 B ≈ √n を使用して、ステップ サイズ b に基づいてクエリを分離します。

1. 小さなステップ サイズの答えを保存するために構造体を初期化します。 1 から B までの各 b について、dp 配列を計算します。ここで、dp[i] は、i から開始して配列を出るまで b ずつジャンプする合計を表します。 
2. 1 から B までの各 b について、n から 1 まで逆の順序で dp を計算します。位置 i で、i + b ≤ n の場合は dp[i] = w[i] + dp[i + b] を設定し、それ以外の場合は dp[i] = w[i] を設定します。 これは、同じ等差数列内で次に訪問する位置が正確に i + b であるため機能します。 
3. 固定 b の dp を計算した後、dp[a] を返すことで、その b を使用するクエリに O(1) 時間で答えることができます。 
4. b > B のクエリの場合は、i = a、a + b、a + 2b を繰り返し、n を超えるまで重みを合計することで直接答えます。 b が大きいため、訪問する要素の数は少なくなります。 
5. 小さなステップには事前計算された dp を使用し、大きなステップには直接シミュレーションを使用して、すべてのクエリを処理します。 

これが機能する理由は、固定配列上の算術数列の構造に関係しています。 小さなステップの場合、配列は重複するチェーンで繰り返し再利用されるため、事前計算はすべてのクエリにわたって償却されます。 大きなステップの場合、チェーンは十分にまばらであるため、直接の走査は安価です。 すべてのクエリはこれら 2 つのレジームのいずれかによって処理され、どちらも重複または省略することなく、考えられるすべての (a、b) ケースをカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
w = list(map(int, input().split()))
q = int(input())

B = int(n ** 0.5) + 1

# store answers for small b
dp = [[0] * n for _ in range(B + 1)]

# precompute for all b up to B
for b in range(1, B + 1):
    for i in range(n - 1, -1, -1):
        if i + b < n:
            dp[b][i] = w[i] + dp[b][i + b]
        else:
            dp[b][i] = w[i]

for _ in range(q):
    a, b = map(int, input().split())
    a -= 1

    if b <= B:
        print(dp[b][a])
    else:
        s = 0
        i = a
        while i < n:
            s += w[i]
            i += b
        print(s)
```dp テーブルは最適化の中核です。 各行は固定ステップ サイズ b に対応し、各エントリは等差数列全体を 1 つの事前計算値にまとめます。 直接ループは、進行が短くて前処理の価値がない場合にのみ使用されます。 

唯一の微妙な実装の詳細はインデックス作成です。 dp 配列は 0 から始まるインデックスに基づいて構築されているため、すべてのクエリは検索前に a を - 1 に変換します。 もう 1 つの詳細は、有効な将来のインデックスのみを参照することを保証する境界チェック i + b < n です。 

## 実用的な例

 ### 例 1

 入力:```
n = 3
w = [1, 2, 3]
queries = (1,1), (1,2)
```b = 1 の場合、dp[1][i] はサフィックスの合計です。 

| 私 | dp[1][i] |
 | --- | --- |
 | 3 | 3 |
 | 2 | 5 |
 | 1 | 6 |

 クエリ (1,1) は dp[1][1] = 6 を返します。 

(1,2) の場合、インデックス 1 と 3 を直接参照します。 

合計 = 1 + 3 = 4。 

これは、dp が完全な走査を O(1) に圧縮する方法を示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n√n + q√n) | 小さなステップ b ごとに O(n) の dp 配列が構築され、そのような b 値は √n 個あります。 大きなステップでは、クエリごとに最大 √n 個の要素を処理します。 
| スペース | O(n√n) | DP テーブルには、各 b に対して最大 √n | n 個のエントリが格納されます。 

組み合わせた複雑さは、√n ≈ 550 であるため、最大 3×10^5 の n、q の制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import sqrt
    n = int(input())
    w = list(map(int, input().split()))
    q = int(input())

    B = int(n ** 0.5) + 1
    dp = [[0] * n for _ in range(B + 1)]

    for b in range(1, B + 1):
        for i in range(n - 1, -1, -1):
            if i + b < n:
                dp[b][i] = w[i] + dp[b][i + b]
            else:
                dp[b][i] = w[i]

    out = []
    for _ in range(q):
        a, b = map(int, input().split())
        a -= 1
        if b <= B:
            out.append(str(dp[b][a]))
        else:
            s = 0
            i = a
            while i < n:
                s += w[i]
                i += b
            out.append(str(s))
    return "\n".join(out)

# sample-like
assert run("3\n1 2 3\n2\n1 1\n1 2") == "6\n4"

# minimum
assert run("1\n5\n1\n1 1") == "5"

# all equal
assert run("5\n1 1 1 1 1\n2\n1 1\n1 2") == "5\n3"

# large step
assert run("6\n1 2 3 4 5 6\n1\n2 5") == "7"

 | --- | --- | --- |
 | 単一要素 | 5 | 基本ケースの正確性 |
 | 一様な配列 | 5、3 | ステップ サイズ間の一貫性 |
 | 大ジャンプ | 7 | スパーストラバーサルの正確性 |

 ## 特殊なケース

 重要なエッジ ケースは、b = 1 の場合です。その状況では、すべてのクエリは a からの完全な接尾辞の合計になり、単純なソリューションでは長いセグメントが繰り返し再計算されます。 dp[1][i] は自然にサフィックス合計チェーンになるため、dp 再帰はこれをきれいに処理します。 

もう 1 つの特殊なケースは、a が終わりに近く、b が大きい場合です。 たとえば、n = 6、a = 5、b = 10 です。ループには w[5] のみを含めて、すぐに停止する必要があります。 直接シミュレーションでは、各加算の前に条件 i < n がチェックされるため、これが正しく処理されます。 

最後の微妙なケースは、複数のクエリが同じ (a、b) を共有する場合です。 このソリューションはクエリごとのキャッシュに依存しません。 代わりに、dp ルックアップまたは決定論的トラバーサルのいずれかを介して、クエリごとに独立して正確性を保証します。
