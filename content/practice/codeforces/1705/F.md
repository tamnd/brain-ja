 ## 問題の理解

 オンライン正誤試験の解答キーを回復するように求められます。$n$質問。 各質問には、正の場合は「T」、偽の場合は「F」のいずれかの正解が 1 つだけあります。 解答キーについて学ぶ唯一の方法は、採点システムを利用することです。長さの候補解答を提出します。$n$正解数を返します。 私たちの目標は、最大 675 個のクエリを使用して完全なキーを決定することです。 

まず最初に気づくことは、$n$これは、すべてを試すという単純なアプローチを即座に排除します。$2^n$考えられる組み合わせは天文学的に膨大です。 675 というクエリ制限は、$n$しかし、私たちは依然としてランダムな推測や指数関数的なものを許容することはできません。$n$。 各クエリはグローバルな尺度 (正解の数) を提供するため、この信号を利用してキーを少しずつ復元する必要があります。 

微妙な点は、どれが正しいかではなく、正解の数だけが表示されることです。 これは情報理論上の課題です。各クエリから得られる情報は次のとおりです。$\log_2(n+1)$情報はせいぜいビットなので、各ビットを確実に抽出するにはクエリを注意深く構成する必要があります。 エッジケースには以下が含まれます$n=1$1 つのクエリで問題が即座に解決される場合、$n=2$単一の回答を反転することで、曖昧さを完全に解決できます。 

## アプローチ

 ブルートフォース手法では、考えられるすべてのキーをテストします。 それぞれが前の質問と 1 つずつ異なる一連の推測を提出し、正解数の変化を観察することができます。 これは原理的には機能しますが、最大で次のことが必要です。$2^n$クエリ。 のために$n=1000$、これは不可能です。 

重要な洞察は、_フリップ テスト_を使用して各質問に対する答えを個別に決定できるということです。 最初の推測 (すべて「T」とします) から始めると、正解の数がわかります。 次に、質問ごとにその値を反転し、変更されたシーケンスを送信します。 正解数が増えれば、反転によって誤った推測が修正されたことになり、反転した値は正しいことになります。 正解数が減れば、反転した値が間違っていたので、元の値が正しかったことになります。 これにより、各ビットを正確に決定できます$n$最初のベースラインの後のクエリ。 

さらなる最適化は、バイナリ検索やビットマスキングと同様の手法を使用して複数のビットを一度に処理することです。$n \le 1000$675 個のクエリが許可されているため、単純なフリップ テストはすでに制限内に十分適合しています。 総当たりアプローチは、解空間が指数関数的に増大するため失敗しますが、独立したフリップ手法により、問題はクエリの線形数に減少します。

 ## アルゴリズムのチュートリアル

 1. まず、一定の長さのシーケンスを送信します。$n$「T」で埋められています。 正解数を記録し、$c_0$。 これにより、フリップを比較するためのベースラインが得られます。 
2. 各質問を繰り返す$i$0から$n-1$。 質問ごとに、ベースライン シーケンスのコピーを作成し、$i$- 'T' から 'F' までの (またはその逆) 番目の答え。 この新しいシーケンスを送信し、正解の数を読み取ります$c_i$。 
3. もし$c_i > c_0$、反転により間違った答えが修正されたため、反転された値が正しい値になります。 回答キーを更新し、ベースラインをインクリメントします$c_0 = c_i$。 
4. もし$c_i < c_0$、フリップが正解を壊したので、元の値が正解でした。 答えはそのままにしておいて、$c_0$は変わらないままです。 
5. すべての質問を処理した後、シーケンスは実際の回答キーと一致します。 送信して完了します。 

機能する理由: このアルゴリズムは、次の不変条件に依存しています。$c_0$正しく識別された回答の数を常に追跡します。 反転するたびに変更される答えの正しさは 1 つだけであるため、新しいカウントをベースラインと比較することで、反転されたビットが正しかったかどうかが直接わかります。 各質問は 1 回だけ検討されるため、すべての答えは最大でも 1 回以内に発見されます。$n+1$クエリ。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
flush = sys.stdout.flush

n = int(input())
# Start with all True
seq = ['T'] * n
print("".join(seq))
flush()
c0 = int(input())

for i in range(n):
    # Flip current bit
    seq[i] = 'F' if seq[i] == 'T' else 'T'
    print("".join(seq))
    flush()
    c_new = int(input())
    
    if c_new > c0:
        # Flip was correct, update baseline
        c0 = c_new
    else:
        # Flip was wrong, revert
        seq[i] = 'F' if seq[i] == 'T' else 'T'

# Submit final answer
print("".join(seq))
flush()
```解決策は次のようになります$n$そして、すべての「T」の最初の推測から始まります。 フリップ テストでは、クエリごとに 1 ビットのみが変更されるという不変条件が使用されます。 丁寧なアップデートで、$c_0$すでに発見されている答えの正確な数を常に知ることができます。 最初の質問、最後の質問、単一要素シーケンスなどの境界条件は、ループによって自然に処理されます。

 ## 特殊なケース

 のために$n=1$の場合、アルゴリズムは「T」を送信します。 答えが「F」の場合、最初のフリップですぐにそれが検出されます。 クエリ数は 2 で、675 を大きく下回ります。 

最初にすべての答えが間違っていると推測されるシーケンス (すべて「T」だがキーはすべて「F」) では、フリップするたびに正解数が増加します。 後$n$反転すると、シーケンスがキーと一致します。 アルゴリズムは一度に 1 ビットのみを反転し、カウントを直接比較するため、オフバイワン エラーは発生しません。 

最大サイズについては$n=1000$の場合でも、ループは依然として 1001 クエリのみを実行し、サイズ 1000 の線形配列を使用します。これにより効率が維持され、整数のオーバーフローやバッファーの問題が回避されます。
