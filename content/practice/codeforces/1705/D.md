 ## 解決策
 ## 問題の理解

 バイナリ文字列として表される、点灯または消灯の電球の列が与えられます。`s`。 マークは、この初期構成をターゲット構成に変換したいと考えています`t`制限された操作の下で電球を繰り返し切り替えることで、任意の電球を選択できます`i`これは最初でも最後でもありません。つまり、そのすぐ左と右の電球が異なり、その状態が反転します。 タスクは、必要なそのような操作の最小数を見つけるか、それが不可能であると判断することです。 

重要な制約は、最初と最後の電球を直接切り替えることはできず、中央の電球は隣接する電球が異なる場合にのみ切り替えることができるということです。 と`n`最大 200,000 および最大 10,000 のテスト ケースでは、すべてのテスト ケースにわたる電球の総数が本質的に線形であるアルゴリズムが必要です。 考えられるすべての操作シーケンスをシミュレートしようとする単純な試みは、組み合わせ論的に爆発することになります。これは、各中央のバルブにはステップごとに最大 1 つのトグル オプションしかありませんが、シーケンスの順序が重要であるためです。 

エッジケースは、最初または最後の電球が異なる場合に発生します。`s`そして`t`なぜなら、直接変更することはできないからです。 例えば、`s = 010`そして`t = 110`不可能だから`s[0]`とは異なります`t[0]`。 もう 1 つの微妙なケースは、中央にある連続する同一の電球のシーケンスを反転する必要がある場合に発生します。 操作の制限とは、次のような特定のパターンが発生することを意味します。`000`なる必要がある`111`、最初は中間のバルブに異なる隣接バルブが存在しないため、これは不可能です。 

## アプローチ

 ブルート フォース アプローチでは、ターゲット設定に到達するまで、有効な切り替えのすべてのシーケンスを試行します。 これは原理的には正しいですが、分岐係数が大きいため、異なる隣接バルブを持つ中央のバルブごとに、切り替えるかどうかを選択する必要があります。 シーケンスの数は次のように指数関数的に増加します。`n`、これは不可能になります`n`最大 2*10^5。 

重要な洞察は、隣の電球が異なる場合にのみ、この操作で電球を反転できるということです。 これは、有用なトグルが「01」または「10」パターンでのみ発生することを意味します。 したがって、個々の電球について考える代わりに、等しい電球の連続したセグメントという観点から考えることができます。 問題は、エンドポイントが既に正しいことを確認しながら (エンドポイントは変更できないため)、最終的にターゲットと一致するために各交互セグメントに適用できるトグルの数を数えることに帰着します。 

これをより単純な線形スキャンに変換できます。`s`そして`t`文字ごとに位置を数えます。`s[i] != t[i]`そして操作は可能です。 エンドポイントで不一致があると、ケースは即座に不可能になります。 この貪欲なアプローチは最適であり、O(n) 時間で実現可能です。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 貪欲なリニアスキャン | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、まずエンドポイントを確認します。 もし`s[0] != t[0]`または`s[n-1] != t[n-1]`、すぐに戻ります`-1`最初と最後の電球は変更できないためです。 
2. カウンタの初期化`ops = 0`操作の数に応じて。 
3. 位置を反復処理する`i`1 から n-2 (中央の電球):

 ａ． もし`s[i] != t[i]`そして`s[i-1] != s[i+1]`、増分`ops`そして概念的に反転します`s[i]`。 実際に変更する必要はありません`s`必要なのはカウントだけだからです。 

b. もし`s[i] != t[i]`しかし`s[i-1] == s[i+1]`、現在電球を反転することはできません。 そのような位置を追跡してください。 隣接するポジションでフリップすると新たなチャンスが得られるので、それらを再検討するかもしれません。 
4. 中央のバルブをすべてスキャンした後、許可された操作では解決できない不一致が残っているかどうかを確認します。 だったら返して`-1`。 それ以外の場合は戻ります`ops`。 

これが機能する理由: 不変条件は、電球は隣接する電球が異なる場合にのみ切り替えることができるということです。 可能な限り線形にスキャンし、貪欲に反転することで、将来の反転をブロックしない方法で各反転が不一致の総数を減らすことを保証します。 エンドポイントチェックにより、不可能なことを試みないようにすることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        s = input().strip()
        t = input().strip()
        
        if s[0] != t[0] or s[-1] != t[-1]:
            print(-1)
            continue
        
        ops = 0
        # Track positions where flips are possible
        s = list(s)
        for i in range(1, n-1):
            if s[i] != t[i] and s[i-1] != s[i+1]:
                ops += 1
                s[i] = t[i]  # Conceptually flip to match t
        
        # After greedy flips, check if s matches t
        if ''.join(s) != t:
            print(-1)
        else:
            print(ops)

if __name__ == "__main__":
    solve()
```このソリューションは、エンドポイントをチェックして、不可能なケースを迅速に破棄することから始まります。 次に、中央のすべてのバルブを反復処理し、操作が有効な場合は常に概念的な反転を実行します。 最終的な比較により、不可能な位置が一致しないままになることはありません。 リストの使用`s`文字列の不変性に影響を与えることなく、その場で概念的な反転が可能になります。 

## 実用的な例

 サンプル 1:

 | 私 | s[i] | t[i] | s[i-1] | s[i+1] | アクション | 作戦 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 0 | 0 | 反転できません | 0 |
 | 2 | 0 | 1 | 1 | 0 | フリップ | 1 |
 | 3 | 0 | 0 | 0 | 0 | 反転できません | 1 |

 ポジション 2 で貪欲に反転すると、最終的には一致が可能になります。 残りの位置はすでに一致しているか、反転できません。 合計操作 2.

 サンプル 2:

 | 私 | s[i] | t[i] | s[i-1] | s[i+1] | アクション | 作戦 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 1 | 0 | 反転できません | 0 |
 | 2 | 1 | 0 | 0 | 1 | フリップ | 1 |

 エンドポイントのチェックが失敗します (`s[0] != t[0]`)、戻ります`-1`すぐに。 

これらのトレースは、アルゴリズムが実行可能なケースと不可能なケースの両方を処理していることを確認します。

 ## 特殊なケース

 エンドポイントの不一致は、返すことによって直ちに処理されます。`-1`。 例えば、`s=101`そして`t=001`失敗する理由`s[0] != t[0]`。 同一の電球の長いシーケンス、例:`s=00000`そして`t=00100`、隣接するものが異なる場合にのみ反転を許可します。 等しい隣接位置を持つ中央の位置は反転不可能なままであり、正しく返されます。`-1`。 最小限の入力`n=3`正しく動作します。操作ルールに従って、中央の電球のみを切り替えることができます。 アルゴリズムは正しくインクリメントします`ops`フリップが可能な場合のみなので、不正な操作はカウントされません。
