 ## 解決策
 ## 問題の理解

 私たちは一列に並んだ部屋を与えられましたが、それぞれの部屋にはある程度の塵が積もっていました。 マークは、前の部屋から後の部屋に 1 単位の塵を移動する特別な操作を使用して、最後の部屋を除くすべての部屋を掃除したいと考えています。ただし、その間のすべての部屋がゼロでない場合に限ります。 具体的には、2 つのインデックスを選択できます$i < j$すべての部屋から$i$に$j-1$少なくとも 1 ユニットの塵がある、減少する$a_i$1ずつ増加します$a_j$by 1. タスクは、最後の部屋を除くすべての部屋を完全に埃のない状態にするために必要な最小操作数を決定することです。 

重要な入力制約は次のとおりです。$n$まで行くことができます$2 \cdot 10^5$と合計$n$テストケース全体でも次を超えない$2 \cdot 10^5$。 粉塵レベルは次のような高さになる可能性があります$10^9$したがって、個々の操作を直接シミュレートしようとするアルゴリズムは遅すぎます。$10^9$最悪の場合の運用。 

一部の部屋ですでに塵がゼロの場合、微妙な特殊なケースが発生します。 たとえば、最初の部屋がゼロの場合、そこから塵を移動することはできず、代わりに後の部屋に依存する必要があります。 もう 1 つの注意が必要なケースは、塵が最後の部屋から遠く離れたところに集中している場合で、塵を複数の部屋に (場合によっては複数回) 「押し出す」必要があります。 

すべての操作を段階的に実行しようとする単純な実装は、中間ゼロをチェックせずにすべての移動が常に可能であると仮定すると、時間的にも、場合によってはロジック的にも失敗します。 

## アプローチ

 ブルートフォースアプローチは簡単です。ダストがゼロでないすべての部屋に対して、右側にある考えられるすべての目的地を試し、操作を適用し、最後の部屋を除くすべての部屋がゼロになるまで繰り返します。 これは、操作ごとに一部の部屋の塵が減少するため機能しますが、操作の数はすべての塵の値の合計に達する可能性があります。$O(n \cdot 10^9)$、明らかに遅すぎます。 

重要な洞察は、個別の操作をそれぞれシミュレートする必要がないということです。 操作がどのように機能するかを考えてみましょう: 室内の各単位の塵$i$最終的には右に移動し、どこかの部屋の埃を増やしなければなりません$j > i$。 目標は、最後の部屋を除くすべての部屋を掃除することなので、部屋のあらゆる単位の塵を取り除くことです。$i$少なくとも貢献する$1$それ自体の操作に加えて、それを蓄積できる部屋に到達するために移動しなければならない距離に等しい追加の操作数が加算されます。 具体的には各部屋ごとに$i < n$、その部屋によって寄与される合計操作は、その部屋の塵にゼロを押し上げた塵からの「オーバーフロー」を加えたものに等しくなります。 これを部屋ごとに合計すると、最小の操作数が得られます。 

これを実装する簡単で正しい方法は、必要な操作の累計を維持しながら、左から右に繰り返すことです。部屋に埃がある場合$a_i$、貢献します$a_i$それをゼロにする操作を行ってから、この塵を前方に「移動」させ、隣の部屋の塵を増やすことを想像できます。 事実上、操作の数は次のように累積できます。$a_i + \text{running\_sum}$どこ$\text{running\_sum}$余分な粉塵を前方に運びます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(すべての塵の合計) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`ops`ゼロに。 これにより、必要な操作の合計数がカウントされます。 
2. 最初の部屋から最後から 2 番目の部屋まで部屋を繰り返します。 各部屋ごとに$i$、次の操作を行います。 

- 粉塵レベルを追加します`a[i]`に`ops`。 この部屋からあらゆる塵埃を除去する必要があるため、少なくともこれだけの作業が必要です。 
- 次の部屋が存在する場合、現在の部屋のダストを次の部屋に追加します。 必要な動作をカウントしながらダストを前方に押し出すモデルです。 これにより、各部屋の塵がさらに右に移動する必要があるユニットを表すという不変条件が維持されます。 
3. ループ後、`ops`最後の部屋を除くすべての部屋をゼロにするために必要な最小限の操作が含まれています。 

**機能する理由:** 各部屋の塵は右方向にしか移動できませんが、この操作により、一度に 1 つのユニットを、場合によっては複数の部屋にまたがって移動させることができます。 ダストを前方に蓄積することで、すべてのユニットが移動ごとに 1 回カウントされるようになります。 中間の部屋では操作によってダストをゼロ以下に減らすことができないため、この左から右への累積により、個々の移動を実行することなく最小カウントが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    ops = 0
    for i in range(n-1):
        ops += a[i]
        a[i+1] += a[i]
    
    print(ops)
```このコードは、高速 I/O を使用して複数のテスト ケースを効率的に読み取ります。 テスト ケースごとに、最初のテスト ケースを繰り返します。$n-1$部屋ごとに必要なすべての操作をカウントし、塵を前方に押し出します。 ループは正しい合計操作で終了します。 主な微妙な点は、最後の部屋以降のダストを決して移動させないようにすることと、すべての中間移動をモデル化するために次の部屋のダストを正しく更新することです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(input())
    res = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ops = 0
        for i in range(n-1):
            ops += a[i]
            a[i+1] += a[i]
        res.append(str(ops))
    return "\n".join(res)

# provided samples
assert run("4\n3\n2 0 0\n5\n0 2 0 2 0\n6\n2 0 3 0 4 6\n4\n0 0 0 10\n") == "3\n5\n11\n0"

# custom cases
assert run("3\n2\n0 0\n3\n1 0 1\n5\n5 0 0 0 0\n") == "0\n2\n5"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2 0 0 | 0 | すでにゼロなので、操作は必要ありません |
 | 3 1 0 1 | 2 | 塵はゼロを正しく移動する必要があります。 
| 5 5 0 0 0 0 | 5 | 開始時にすべてのダストが正しく蓄積されます。 

## 特殊なケース

 最初の部屋がゼロの場合、次のように`0 5 0 0`、アルゴリズムは単純にゼロを追加することでそれを処理します。`ops`そして何も前進させません。 2 番目の部屋からの塵は、必要に応じて右に移動します。 同様に、最初に最後の部屋に塵があった場合、最初の部屋のみであるため、運用にはカウントされません。$n-1$部屋はゼロでなければなりません。 これにより、アルゴリズムが演算を過少カウントしたり過大カウントしたりすることがなくなります。 

単一の演算が複数の中間ゼロにまたがる場合、次のようになります。`2 0 0 1`の場合、アルゴリズムは演算を 2+0+0 = 2 として正しく累積し、すべての中間ステップをシミュレートすることなく、合計演算の計算に進みます。 この抽象化により、正確性と効率性が保証されます。
