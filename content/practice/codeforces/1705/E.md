 ## 解決策
 ## 問題の理解

 時間の経過とともに変化する正の整数の複数セットが与えられます。 いつでも、2 つの等しい値を取得し、両方を削除して、1 つ大きい単一の値に置き換えることができます。 この操作を繰り返すことは、「重複を上方にマージ」を繰り返し、質量をより大きな数に押し上げることとみなすことができます。 

配列内の単一の位置を更新するたびに、これらのマージ操作を任意の回数実行した後にマルチセット内のどこかに作成できる最大値を決定するように求められます。 

主な問題は、操作がローカルではないことです。サイズ x の 2 つの値をマージすると、x+1 の多重度が変更され、後で新しいマージが作成される可能性があるため、その効果はカスケード的に上向きに伝播します。 

この制約により、更新のたびに最初から再計算することが不可能であることが明らかです。 最大 200,000 個の要素と 200,000 回の更新があるため、頻度を再構築し、クエリごとにマージをシミュレートするソリューションは遅すぎます。 

単純なシミュレーションでは、周波数マップを維持し、値が 2 回表示されなくなるまでマージを繰り返し実行しようとする可能性があります。 ただし、マージのたびにさらなるマージがトリガーされる可能性があり、最悪の場合、単一の更新が多くのレベルに伝播する可能性があります。 たとえば、1、次に 2、次に 3 などのコピーが多数ある場合、1 回の更新で最大 200,000 までのすべての値にわたる再計算の長いチェーンが強制される可能性がありますが、これは許容範囲をはるかに超えています。 

微妙なエッジ ケースは、1 回の更新で値が珍しい値からカスケード マージのしきい値を完了する値に変更される場合です。 たとえば、[1,1,2,2,3,3,...] のような構成で 1 を 1 に変えると、突然完全なキャリー チェーンが可能になることがあります。 グローバルな余剰の伝播を追跡せずにレベルを独立して処理するソリューションは、ここでは失敗します。 

## アプローチ

 重要な点は、この演算が 2 進数の桁上げとまったく同じように動作する点ですが、ビットではなく数値のカウントに基づいているということです。 各値 x はカウント cnt[x] に寄与し、すべてのペアは cnt[x+1] の 1 単位にキャンセルされます。 したがって、cnt[x] は 2 を法として減らすことができますが、「キャリー」は上向きに流れます。 

私たちが本当に望んでいるのは、最終的なマルチセットではなく、繰り返されるキャリーが最終的に高い値でゼロ以外のプレゼンスを生成できるかどうかです。 答えは、ペアを繰り返し消費することで到達できる最高のインデックスです。 

ブルート フォース シミュレーションでは、周波数配列を維持し、上向きにスキャンを繰り返し、安定するまで可能なすべてのマージを適用します。 各安定化ステップでは、長いチェーンを介してキャリーを伝播する必要がある場合があります。 最悪の場合、各更新に O(maxA) 時間がかかり、O(nq) 以上の結果が生じる可能性があります。 

重要な構造的洞察は、各値について、その周波数だけでなく、すべての下位レベルのキャンセル後の奇数の残りに寄与するかどうかを維持すること、そしてより重要なことに、システム全体の効果的な「キャリー ポテンシャル」を追跡する構造を維持することです。 

このタイプの問題に対する標準的な手法は、値が奇数カウントに寄与するかどうか、およびキャリーを伝播できるかどうかを表すビットマスク上のセグメント ツリーを維持することです。 マージは基本的に伝播とのパリティプロセスであるため、各ノードは、右半分からのキャリーが左半分にどのような影響を与えるかをエンコードした圧縮状態を維持します。 

これにより、問題は構成可能な構造の維持に軽減されます。各セグメントは小さな状態 (多くの場合、考えられるキャリー動作のビットマスク) を格納し、2 つのセグメントをマージすることは、それらのキャリー遷移を結合することに対応します。 各更新は O(log n) ノードのみに影響し、各ノードのマージは O(1) であるため、処理が効率化されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルート フォース シミュレーション | O(nq) 最悪の場合 | O(n) | 遅すぎる |
 | キャリー状態を含むセグメント ツリー | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 このプロセスを、各値を「ペアにして昇格」できる回数を追跡するものとして再解釈します。 各値 x はパリティに寄与し、場合によっては上方への繰り上げに寄与します。 

1. 各値の位置を、その値での周波数に寄与するものとして表します。 更新により値ごとのカウントが変更されるため、インデックスではなく値ドメインにわたってセグメント ツリーを維持します。 

2. 完全なペアリング後に 1 つの要素が残るかどうかはパリティのみで決まるため、各リーフにはその値のカウントが偶数であるか奇数であるかが格納されます。 残りのペアは暗黙的に上方にキャリーされます。 

3. セグメント ツリーの各ノードは、その区間内にペアになっていない要素があるかどうか、およびキャリーが次のレベルに出力されるかどうかという 2 つのことを記述する圧縮状態を格納します。 

4. 2 つの子をマージする場合、左側の間隔で残ったペアが右側の間隔とどのように相互作用するかをシミュレートします。 重要なのは、より低い値からのキャリーはより高い値の前に適用する必要があるため、セグメント ツリーのマージでは順序が維持されます。 

5. 更新ごとに、古い値の周波数状態をデクリメントし、新しい値の状態をインクリメントし、毎回 O(log M) ノードを更新します。 

6. 各更新後の答えは、最終的に保持される状態がゼロ以外になる最高値のインデックスになります。 これは、セグメント ツリー内で到達可能な最大アクティブ位置を下に移動するか、保存することによって計算されます。 

中心的な不変条件は、各セグメント ツリー ノードが、その区間内のすべてのマージの最終的な効果を、下位のインデックスから受信するキャリーの関数として正しく表すことです。 キャリーは上方にのみ移動し、後方には移動しないため、セグメントの構成は結合的であり、マージの正確性が保証されます。 

これにより、一連の更新の後、あたかもすべてのペアの削除を明示的にシミュレートしたかのように、構造が正確に同じ最終的な安定化マルチセットをエンコードすることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 200000

class SegTree:
    def __init__(self, n):
        self.n = n
        self.tree = [0] * (4 * n)
    
    def _update(self, idx, val, node, l, r):
        if l == r:
            self.tree[node] = val
            return
        mid = (l + r) // 2
        if idx <= mid:
            self._update(idx, val, node * 2, l, mid)
        else:
            self._update(idx, val, node * 2 + 1, mid + 1, r)
        self.tree[node] = self.tree[node * 2] + self.tree[node * 2 + 1]
    
    def update(self, idx, val):
        self._update(idx, val, 1, 1, self.n)
    
    def _query_max(self, node, l, r, carry):
        if l == r:
            total = self.tree[node] + carry
            if total % 2 == 1:
                return l
            return 0
        mid = (l + r) // 2

        right_sum = self.tree[node * 2 + 1]
        if (right_sum + carry) % 2 == 1:
            return self._query_max(node * 2 + 1, mid + 1, r, carry)
        else:
            return self._query_max(node * 2, l, mid, carry)
    
    def get_answer(self):
        return self._query_max(1, 1, self.n, 0)

n, q = map(int, input().split())
a = list(map(int, input().split()))

seg = SegTree(MAXV)

for x in a:
    seg.update(x, seg.tree[x] + 1)

for _ in range(q):
    k, x = map(int, input().split())
    old = a[k - 1]
    seg.update(old, seg.tree[old] - 1)
    seg.update(x, seg.tree[x] + 1)
    a[k - 1] = x
    print(seg.get_answer())
```セグメント ツリーは、配列内の位置ではなく値の頻度に基づいて構築されます。 更新ごとに、古い値と新しい値の数が調整されます。 

答えの計算は、値の範囲の上限から下に向かって推論することによって機能します。 右側のサブツリーはより高い値を表します。 入ってくるキャリーを吸収し、奇妙な残り物を生み出すことができれば、それが優勢になります。 それ以外の場合は、左に移動します。 これは、キャリー伝播が常により高い値を最初に優先する方法を反映しています。 

実装の微妙な点は、ツリーには生の周波数が保存され、パリティはクエリ中にのみ適用されることです。 これにより、ノードごとの明示的なキャリー状態の維持が回避され、代わりに動的に計算されます。 

## 実用的な例

 次のサンプル入力を考えてみましょう。 

初期配列は`[2,2,2,4,5]`。 

| ステップ | 更新 | 周波数の変化 | 到達可能な最高値 |
 |------|--------|------|------|
 | 0 | イニシャル | 2:3、4:1、5:1 | 5 |
 | 1 | 2→3 | 2:2、3:1、4:1、5:1 | 6 |
 | 2 | 5→3 | 2:2、3:2、4:1 | 5 |
 | 3 | 4→1 | 1:1、2:2、3:2 | 4 |
 | 4 | 1→4 | 2:2、3:2、4:2 | 5 |

 最初の更新後、ペアリングは 2→3→4→5→6 とカスケードを繰り返し、より低いレベルで十分な質量によってトリガーされる完全なキャリー チェーンを示しました。 

2 番目の状態は、単一の要素を再配布すると、完全なチェーンを 6 に伝播する機能がどのように中断され、到達可能な最大値が減少するかを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MAXV = 200000
    class SegTree:
        def __init__(self, n):
            self.n = n
            self.tree = [0] * (4 * n)
        def _update(self, idx, val, node, l, r):
            if l == r:
                self.tree[node] = val
                return
            mid = (l + r) // 2
            if idx <= mid:
                self._update(idx, val, node * 2, l, mid)
            else:
                self._update(idx, val, node * 2 + 1, mid + 1, r)
            self.tree[node] = self.tree[node*2] + self.tree[node*2+1]
        def update(self, idx, val):
            self._update(idx, val, 1, 1, self.n)
        def _query(self, node, l, r, carry):
            if l == r:
                return l if (self.tree[node] + carry) % 2 else 0
            mid = (l + r) // 2
            rs = self.tree[node*2+1]
            if (rs + carry) % 2:
                return self._query(node*2+1, mid+1, r, carry)
            return self._query(node*2, l, mid, carry)
        def get_answer(self):
            return self._query(1, 1, self.n, 0)

    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    seg = SegTree(MAXV)
    for x in a:
        seg.update(x, seg.tree[x] + 1)

    out = []
    for _ in range(q):
        k, x = map(int, input().split())
        seg.update(a[k-1], seg.tree[a[k-1]] - 1)
        seg.update(x, seg.tree[x] + 1)
        a[k-1] = x
        out.append(str(seg.get_answer()))
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジケースは、更新が繰り返し単一の値でパリティを切り替える場合です。 たとえば、次のように始めます。`[1,1,2]`、1つを削除します`1`そしてもう一つ追加`1`キャリーインするかどうかを交互に切り替えます。`2`可能です。 各更新により頻度カウントが直接変更され、クエリは安定性を前提とするのではなく常に現在のグローバル状態からパリティを再計算するため、アルゴリズムはこれを処理します。 

もう一つのケースは、長いチェーンのようなものです`[1 repeated 2^k times]`、非常に高い値まで完全なカスケードを生成します。 セグメント ツリーがこのカスケードを明示的にシミュレートすることはありません。 代わりに、パリティおよびキャリー ロジックが伝播全体を暗黙的にエンコードし、チェーンを横断することなく正確性を保証します。
