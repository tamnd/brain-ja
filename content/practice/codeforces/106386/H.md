 ## 解決策
 ## 問題の理解

 重み付けされたノードを持つ有向グラフが与えられます。 各ノードはスケート要素を表し、各要素にはスコアがあります。 からの有向エッジ$x$に$y$要素の実行が許可されていることを意味します$y$要素の直後$x$。 パフォーマンスはこのグラフ上のウォークであり、各ステップは有向エッジに従い、ウォークは任意のノードから開始できます。 

重要な点は、同じ要素を繰り返しても、最初に出現した後はスコアが追加されないことです。 したがって、ノードを複数回訪問した場合、最初の訪問のみがその値に寄与します。 それ以降の訪問はすべてゼロになります。 

タスクは、ウォーク中に発生する個別のノード値の合計を最大化する有効なウォークを選択することです。 

グラフは大きくなる場合があり、最大で$10^5$ノードと$2 \cdot 10^5$エッジ。 パスを列挙したり、ウォーク全体で指数関数的な探索を実行しようとしたソリューションは、すぐに失敗します。 平$O(n^2)$グラフが高密度になり、トラバース パターンが頻繁に繰り返される可能性があるため、最悪の場合、アプローチが大きすぎます。 

微妙な問題は、サイクルが許可されており、実際にはサイクルがノードを「再訪」する唯一の方法であることです。 ただし、ノードの再訪問は、まだ収集されていない新しいノードに到達するのに役立つ場合にのみ役立ちます。 リージョン内の到達可能な価値のあるノードがすべて収集されると、ループを継続してもメリットはありません。 

簡単な間違いは、これが最長パスの問題または DAG DP の問題であると想定することです。 サイクルが許可されていて便利であるため、これは失敗します。 もう 1 つのよくある間違いは、強く接続されたコンポーネントを圧縮し、結果として得られるグラフを間違って扱うことです。特に、SCC 内ではすべてのノードが相互に到達可能であり、再訪問することなく任意の順序で収集できることを忘れた場合に、コストがかかります。 

たとえば、サイクルがあるとします。$1 \to 2 \to 3 \to 1$、正しい動作は、このサイクルのどこからでも開始して 3 つの値すべてを収集できることです。 単純なパス DP では、一方向のトラバースのみがカウントされ、コンポーネント全体が事実上自由にトラバースできることを見逃してしまう可能性があります。 

## アプローチ

 ブルートフォースのアイデアは、値がすでに収集されている訪問済みのノードのセットを維持しながら、すべてのノードから開始して可能なすべてのウォークをシミュレートすることです。 各ステップで、出力エッジに沿って移動し、ノードの値がまだ見られていない場合は追加します。 これはプロセスの定義と直接一致するため、正しいです。 

障害点は状態空間です。 訪問セットのみのサイズがあります$2^n$、各状態には最大で$n$考えられる次の動き。 到達可能な状態に限定しても、ウォークは進行を決定する前に任意に何度もループできるため、サイクルを含むグラフ内の個別のパスの数に制限はありません。 これにより、直接シミュレーションが不可能になります。 

重要な観察は、グラフ内のサイクルは内部的には重要ではないということです。 強く接続されたコンポーネントに入ると、そのコンポーネント内を自由に移動して、順序を気にせずにそのコンポーネント内のすべてのノードを収集できます。 唯一意味のある構造は、これらのコンポーネントがどのように相互に接続されているかです。 

これにより、問題は強く接続されたコンポーネントの有向非巡回グラフに帰着します。 各コンポーネント内では、入力するとその中のすべてを収集できるため、すべてのノード値を合計できます。 コンポーネント間では、凝縮 DAG によって制限されるため、コンポーネントの重みの合計を最大化するこの DAG 内のパスを効果的に選択します。 

これにより、この問題は、ノードの重みが SCC 値の合計となる DAG 上の最長パス問題に変換されます。

 ## アルゴリズムのチュートリアル

 1. グラフの強接続成分を計算します。 各ノードにはコンポーネント ID が割り当てられます。 このステップでは、相互に到達可能なノードをグループ化します。これは、そのようなグループ内では順序制約によってコレクション全体が制限されなくなるため、重要です。 
2. 各コンポーネントについて、そのコンポーネント内のすべてのノードの重みを合計することによって、その合計値を計算します。 これは、ウォークがコンポーネントに入ると内部を横断し、最終的にはすべてのノードにアクセスできるため、有効です。 
3. 各 SCC が単一ノードとなる凝縮グラフを構築します。 あらゆるオリジナルのエッジに$u \to v$、コンポーネントが異なる場合は、コンポーネントの代表間に有向エッジを追加します。 
4. SCC 凝縮は常に有向非巡回グラフを生成するため、コンポーネントの位相順序を計算します。 
5. DAG 上で動的プログラミングを実行します。 させて$dp[c]$コンポーネントで終了する達成可能な最大合計値になります。$c$。 全て初期化する$dp[c]$どこからでも始められるので、コンポーネント自体の合計を使用します。 
6. トポロジ順にコンポーネントを調べます。 各エッジについて$c \to d$、 アップデート$dp[d]$として$dp[d] = \max(dp[d], dp[c] + value[d])$。 この遷移は、相互に到達可能なノードのある領域から別の領域に移動し、到着時に宛先コンポーネント内のすべてのノードを収集することを表します。 
7. 答えは、すべての dp 状態の最大値です。 

正確性は、コンポーネントが入力されると、そのすべてのノードがペナルティなしで収集でき、コンポーネントから離れると、出力エッジを経由する場合を除いて追加の値を提供できないという事実に依存します。 SCC 短縮によりすべての内部順序制約が削除されるため、すべての有効なウォークは DAG 内のパスに正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    val = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    gr = [[] for _ in range(n)]
    
    for _ in range(m):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        g[x].append(y)
        gr[y].append(x)

    # Kosaraju: first pass order
    vis = [False] * n
    order = []

    def dfs1(u):
        vis[u] = True
        for v in g[u]:
            if not vis[v]:
                dfs1(v)
        order.append(u)

    for i in range(n):
        if not vis[i]:
            dfs1(i)

    # second pass: assign components
    comp = [-1] * n
    comps = []

    def dfs2(u, idx):
        comp[u] = idx
        comps[idx].append(u)
        for v in gr[u]:
            if comp[v] == -1:
                dfs2(v, idx)

    for u in reversed(order):
        if comp[u] == -1:
            comps.append([])
            dfs2(u, len(comps) - 1)

    k = len(comps)

    comp_sum = [0] * k
    for c in range(k):
        s = 0
        for u in comps[c]:
            s += val[u]
        comp_sum[c] = s

    dag = [set() for _ in range(k)]
    indeg = [0] * k

    for u in range(n):
        for v in g[u]:
            cu, cv = comp[u], comp[v]
            if cu != cv and cv not in dag[cu]:
                dag[cu].add(cv)
                indeg[cv] += 1

    topo = []
    stack = [i for i in range(k) if indeg[i] == 0]
    while stack:
        u = stack.pop()
        topo.append(u)
        for v in dag[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                stack.append(v)

    dp = comp_sum[:]

    for u in topo:
        for v in dag[u]:
            if dp[v] < dp[u] + comp_sum[v]:
                dp[v] = dp[u] + comp_sum[v]

    print(max(dp))

if __name__ == "__main__":
    solve()
```コードの前半では、Kosaraju のアルゴリズムを実行して、強く接続されたコンポーネントを識別します。 順方向 DFS は終了順序を生成し、逆方向グラフ DFS はコンポーネントを割り当てます。 これが必要なのは、SCC 内の到達可能性の対称性によってサイクルの安全な崩壊が可能になるためです。 

後半では凝縮グラフを作成します。 複数の元のエッジがコンポーネントの同じペアに接続できるため、エッジの重複を避けるためにコンポーネントごとにセットが使用されます。 重複排除がなければ、入次数および DP 遷移は引き続き機能しますが、時間を無駄にし、冗長な更新の危険性があります。 

DP ステージは、DAG 上の最長パスの計算であり、各コンポーネントが開始点として自給自足しているため、コンポーネントの合計で初期化されます。 これを入力すると完全な収集が可能になるため、トランジションにより完全な宛先コンポーネント値が追加されます。 

## 実用的な例

 サイクルとテールを持つ小さなグラフを考えてみましょう。 

入力:```
5 5
1 10 100 1 50
1 2
2 3
3 1
3 4
4 5
```SCC 分解により 1 つの成分が得られる$\{1,2,3\}$合計は 111、シングルトンは 4 と 5 です。 

| ステップ | コンポーネント | 前の dp | 移行 | |後の dp
 | --- | --- | --- | --- | --- |
 | 初期化 | {1,2,3} | 111 | 開始 | 111 |
 | プロセス | 4 | 0 | 111+1 | 112 |
 | プロセス | 5 | 0 | 112 + 50 | 162 |

 これは、サイクルに入ると、そのすべてのノードがすぐに収集され、外側の構造のみが重要であることを示しています。 

次に、分岐グラフを考えてみましょう。 

入力:```
4 3
5 1 10 2
1 2
1 3
3 4
```各ノードは独自の SCC です。 

| ステップ | ノード | 前の dp | 移行 | |後の dp
 | --- | --- | --- | --- | --- |
 | 開始 | 1 | 5 | 初期化 | 5 |
 | 1→2 | 2 | 1 | 5 + 1 | 6 |
 | 1→3 | 3 | 10 | 5 + 10 | 15 |
 | 3→4 | 4 | 2 | 15 + 2 | 17 |

 最適なパスは 1 → 3 → 4 であり、DP が最上位ノードだけではなく、DAG 内の最適なルートを選択していることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n + m)$| Kosaraju は線形時間で実行され、SCC 圧縮と DP も各エッジを 1 回処理します。 
| スペース |$O(n + m)$| 隣接リスト、リバース グラフ、SCC ストレージ、および DP アレイ |

 ## 特殊なケース

 完全に循環するグラフは最も重要なコーナーケースです。 すべてのノードが相互に到達可能な場合、アルゴリズムはすべてを 1 つの SCC に圧縮し、すべての値の合計を返します。 SCC を圧縮しないパスベースの DP は、再訪問を誤って無効として扱うか、不適切に二重カウントとして扱います。 

もう 1 つのエッジ ケースは、複数の切り離されたコンポーネントを含むグラフです。 各コンポーネントは独自の SCC になり、DP は各コンポーネントを個別に初期化するため、アルゴリズムにより人為的なソース ノードを必要とせずにどこからでも開始できるようになります。 

最後の微妙なケースは、最適なパスが遅れてサイクルに入り、別のノードを通って終了する場合です。 SCC 短縮により、サイクルに入るとすぐにすべての値が付与されるため、部分的な走査をシミュレートするメリットはありません。 DP は、コンポーネント全体をアトミックに処理することにより、過小カウントを正しく回避します。
