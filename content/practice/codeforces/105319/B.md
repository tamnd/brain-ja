 ## 解決策
 ## 問題の理解

 10 進数で構成される文字列が与えられます。 唯一許可される操作は、位置を選択し、その桁を 0 ～ 9 の範囲内で 1 ステップ上下に移動することです。この操作を何度でも繰り返し、前後に同じように読めるように文字列を変換します。 コストは、すべてのポジションにわたって実行される 1 ステップの増加または減少の合計数であり、タスクはこのコストを最小限に抑えることです。 

入力の構造は単純ですが厳密に重要です。各位置は、文字列の他端からのミラー位置とのみ相互作用します。 すべてのテスト ケースの合計の長さが最大 ​​1000 であるという制約は、テスト ケースごとに 2 次量の追加作業を実行するソリューションはすでに安全ですが、ネストされた大量の再計算を伴うものは合格しますが、不要であることを意味します。 

操作を段階的にシミュレーションしようとすると、素朴な誤解が発生します。 たとえば、次のようなペアを取ると、`1`そして`9`、大きい桁と一致するまで小さい桁を繰り返しインクリメントする場合があり、8 回の操作が必要になります。 これは局所的には正しいですが、考えられるすべての中間ターゲットに対して順番に実行すると、推論時間が無駄になり、実装が過度に複雑になります。 

両方の桁を独立して固定方向に向けて変更する必要があると仮定すると、別の微妙な故障モードが現れます。 たとえば、両方の数字を 0 または 9 の方向に回すと対称的に見えるかもしれませんが、常に最適であるとは限りません。 最適な集合場所は世界的に固定されているわけではありません。 

## アプローチ

 ブルート フォース パースペクティブでは、各位置を独立して扱いますが、ミラーリングされたキャラクターを等しくするために考えられるすべての方法をシミュレートします。 数字のペアの場合`a`そして`b`、ターゲットの数字を選択してみることができます`d`0 から 9 までを計算し、両辺を次のように変換するコストを計算します。`d`。 それには次のコストがかかります`|a - d| + |b - d|`、そして全体の最小値を取る`d`正しい答えが得られます。 これは正しいです。最後の等しい数字は 0 から 9 までの整数線上のどこかになければなりません。 

ただし、これにより、ペアごとに 10 個の可能なターゲットにわたる不必要なループが発生し、大まかに次のような結果が得られます。`O(10n)`テストケースごとに作業します。 まだ線形ではありますが、式が閉じた形式の簡略化を行っているという事実が隠蔽されます。 

重要な観察は、手続き的なものではなく、幾何学的なものです。 数直線上では、共通の会合点がそれらの間にある場合、両方の点を共通の会合点に移動することは最小限に抑えられます。 その場合、合計距離は端点間の直接距離に縮小されます。 したがって、一致する数字を検索する代わりに、2 つの数字間の絶対差としてコストを直接計算できます。 

これにより、問題全体が、ミラーリングされた位置にわたるこれらのペアごとの差を合計することに帰着します。

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、その文字列の最小コストを計算します。 

1. 文字列を読み取り、各文字を数字として解釈します。 文字列の長さは、存在するミラーリングされたペアの数を定義します。 
2. 総コストのアキュムレータをゼロに初期化します。 これにより、すべての対称ペアにわたって必要な最小限の操作が収集されます。 
3. インデックスごとに`i`文字列の先頭から中間点までをインデックスと組み合わせます`n - i - 1`。 これにより、すべての位置が 1 回だけ一致することが保証されます。 
4. ペアの 2 つの数字間の絶対差を計算します。 この値は、それらを等しくするために必要な単一ステップ操作の最小数を表します。 
5. この差をアキュムレータに加算します。 各ペアは独立しているため、これらのコストは直接合計されます。 
6. すべてのペアを処理した後、累積和を出力します。 

### なぜ効果があるのか

 ある位置での操作が別の位置に影響を与えることはないため、ミラーリングされた各ペアは他のペアから独立しています。 任意の 2 桁の場合、それらを等しくするための最小コストは、両方を整数直線に沿って互いに近づけることによって達成され、そのプロセスでカバーされる合計距離は、正確にそれらの間の絶対差になります。 すべての有効な回文はすべてのミラーリングされたペアに平等を強制する必要があるため、全体的な最適値は独立して最適なペアのコストの合計になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)
        ans = 0

        for i in range(n // 2):
            a = ord(s[i]) - ord('0')
            b = ord(s[n - i - 1]) - ord('0')
            ans += abs(a - b)

        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、対称インデックスをペアにして絶対差を累積する構造に従います。 を使用した変換`ord`直接的なものではありますが、繰り返しの整数解析のオーバーヘッドを回避します。`int()`制約を考慮すると許容される可能性もあります。 

ループは最大までしか実行されません`n // 2`、各ペアが正確に 1 回カウントされるようにします。 中央の文字はそれ自体で回文条件をすでに満たしており、コストがゼロであるため、奇数長の文字列には特別な処理は必要ありません。

 ## 特殊なケース

 単一文字の文字列は、満たすべきミラー化された制約がないため、すでに回文です。 アルゴリズムはゼロ ペアを処理するため、累積コストはゼロのままで、期待される結果と一致します。 

のような入力の場合`19`、アルゴリズムは 2 つの数字を組み合わせて計算します。`|1 - 9| = 8`。 中間ディジットを介してルーティングを試みても、正確に 8 単位ステップが蓄積され、直接計算はシミュレーションなしでその最小限のパスを反映します。 

次のようなすでに回文になっている文字列の場合、`1221`、ミラー化された各ペアは同一の数字で構成され、ペアごとの寄与はゼロになります。 各絶対差はゼロと評価されるため、アルゴリズムはこれを自然に保存します。 

次のような奇数長の文字列の場合`12321`、中央の数字が何かとペアになることはありません。 ループは意図的に半分の長さで停止し、中心が結果に影響を与えず、誤ったペアリングが発生しないようにします。
