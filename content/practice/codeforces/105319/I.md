 ## 解決策
 ## 問題の理解

 最初に 1 から n までの整数がソートされた順序で含まれる配列から始めます。 このプロセスは正確に n 回繰り返され、各繰り返しは現在の配列に対して実行される 2 つのアクションで構成されます。 

まず、配列の中央値要素を削除します。 中央値は、現在の配列のサイズが m の場合、位置 ⌈m/2⌉ の要素として定義されます。 配列は概念的に常に残りの値と同じ順序で並べ替えられるため、中央値は常に残りのセットの中央の要素になります。 

次に、中央値を削除した後、残りの配列の MEX を計算し、実行スコアに追加します。 ここでの MEX は、現在の配列に現れない最小の正の整数です。 

重要な出力は、n 回すべての除去にわたって蓄積された合計スコアです。 

制約は大きく、n は最大 10^9、テスト ケースは最大 10^5 です。 これにより、配列のシミュレーションや中央値抽出の繰り返しが即座に除外されます。 テスト ケースごとに n 回の削除を行うことになるため、バランスの取れた構造を維持するだけでも時間がかかりすぎます。 

微妙なエッジ ケースは、縮小プレフィックスに関する MEX を理解することから生まれます。 たとえば、配列が [1] の場合、中央値を削除すると空の配列が残り、空の MEX は 1 になります。別の小さなケースは n = 2 です。[1,2] から始まり、中央値が 1、残りが [2]、MEX が 1、次に中央値 2 が空のままになり、MEX が再び 1 になります。 最終スコアは 2 です。削除後に MEX がどのように進化するかについての誤った直感は、ここで壊れます。 

本当の難しさは、中央値の削除はグローバルであるが、MEX は欠落している最小の整数のみに依存しており、これが初期の小さな数値の削除方法と強く相互作用することです。 

## アプローチ

 ブルート フォース シミュレーションでは、配列がソートされた順序で維持されます。 各ステップでは中央値要素を削除し、1 から上方向にスキャンして MEX を見つけます。 中央値の削除は、単純な配列で実行すると O(n) になります。最悪の場合、MEX の検出も O(n) になります。 これを n 回繰り返すと、テスト ケースあたり O(n^2) になりますが、これは、1 回のテストでも n が 10^9 までは不可能です。 

バランスの取れた BST または順序統計ツリーを使用しても、中央値の除去は O(log n) に削減できますが、MEX を計算するには、欠落している最小の正の整数を追跡する必要があります。 単純に実行すると、別の構造を維持しない限り、MEX クエリは高価なままになります。 それでも、実際にはすべての削除をシミュレートする必要はないという、より深い問題が残ります。 

重要な観察は、プロセスが決定論的であり、配列の完全な構造ではなく、削除の相対的な順序のみに依存するということです。 常に残りのセット {1, 2, ..., k} の中央値を削除するため、削除された要素の順序は、縮小する連続セットの中央を繰り返し取得することによって完全に決定されます。 これにより、元の数値が削除の順序に予測可能な分割が生成されます。 

同時に、MEX は常に、最小の整数がすでに削除されている数に依存します。 各整数が削除されるまでにどのくらいの期間存続するかを追跡すると、それがいつ MEX 値の累積に寄与するかを正確に判断できます。 

重要な単純化は、視点を逆転させることです。 削除をシミュレートする代わりに、[1, n] の各整数 i がどのステップで削除されるかを決定します。 すべての値の除去時間がわかれば、MEX がどのように発展するかを再構築できます。ステップ t では、MEX は除去時間が ≥ t である最小の数です。 

これにより、問題は、古典的な分割統治パターンである、連続するセグメントから中央値を繰り返し取得する消去順序を理解することになります。

 ## アルゴリズムのチュートリアル

セット {1, 2, ..., n} の削除プロセスをモデル化します。 各ステップで、現在のセグメントの中央値を削除します。 これは、ルートが中央値であり、左のサブツリーが左半分の同じプロセスであり、右のサブツリーが右半分の同じプロセスであるインデックス上にバイナリ ツリーを構築することと同じです。 削除順序は、まさにこの暗黙的なセグメント ツリーの事前順序トラバーサルです。 

1. 区間にわたる分割統治分割をシミュレートすることによって、各値をその削除ステップに割り当てる関数を定義します。 区間 [l, r] について、mid = (l + r) // 2 (中央位置に対する適切なセル処理を使用) を計算し、次に利用可能な除去時間を割り当てます。 
2. 左側の間隔 [l, mid - 1] と右側の間隔 [mid + 1, r] を再帰的に処理し、進むにつれて深さを増やします。 これにより、繰り返される中央値の削除と一致する削除の完全な順序が構築されます。 
3. 各値の削除時間がわかったら、値を削除時間で並べ替えます。 これにより、要素が配列から消える正確な順序が得られます。 
4. 時間の経過に伴う MEX 寄与を計算します。 まだ削除されていない最小の数値を追跡するポインタ mx を維持しながら、1 から n までのタイム ステップをスイープします。 各ステップ t で mx を答えに追加し、時刻 t で要素 mx が削除された場合は、まだ存在する値が見つかるまで mx を前方にインクリメントします。 
5. これらの貢献を最終スコアに累積します。 

重要な考え方は、時刻 t における MEX は、時刻 t までにまだ削除されていない最小のインデックスのみに依存するということです。 削除時間がわかっているため、値が存続しているかどうかを簡単に比較できます。 

### なぜ効果があるのか

 中央値除去プロセスでは、アクティブな間隔の中央の要素が常に選択されるように配列が分割されます。 これにより、すべての要素の削除時間が再帰的中央値分割ツリー内の位置によってのみ決定されることが保証されます。 どのステップの MEX も、1 から始まる値のプレフィックスの存続のみに依存するため、まだ削除されていない最も古い整数を追跡するだけで十分です。 削除回数は厳密な順序を定義するため、現在の最小の生存数が削除される場合を除き、MEX は単調に進化し、MEX が上方にシフトします。 これにより、除去時間が判明したら、各ステップを一定の償却時間で計算できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def build(l, r, t, order):
    if l > r:
        return
    mid = (l + r) // 2
    order[mid] = t
    build(l, mid - 1, t + 1, order)
    build(l, mid + 1, r, t + 1, order)

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())

        order = [0] * (n + 1)
        build(1, n, 1, order)

        # bucket elements by removal time
        # we will invert into time -> value mapping
        pos = [[] for _ in range(n + 2)]
        for i in range(1, n + 1):
            pos[order[i]].append(i)

        removed = [False] * (n + 2)
        mex = 1
        ans = 0

        for time in range(1, n + 1):
            for v in pos[time]:
                removed[v] = True

            while removed[mex]:
                mex += 1

            ans += mex

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```再帰関数`build`は、分割構造の中央値に基づいて各数値に除去時間を割り当てます。 各ノードはその子の前に割り当てられ、中央値が削除される正確な順序がエンコードされます。 

の`pos`配列はこのマッピングを反転するので、特定のタイム ステップで発生するすべての削除を効率的に処理できます。 これにより、反復ごとにすべての要素をスキャンする必要がなくなります。 

の`mex`ポインタは単調に維持されます。 前に進むだけなので、ループが n 回実行されても、各値は最大 1 回アクセスされるため、テスト ケースごとの合計作業量は線形に保たれます。 

微妙な点は、分割ごとに間隔が半分になるため、再帰の深さが O(log n) に相当することです。 n は大きくなる可能性がありますが、削除回数の格納を超えてそのサイズの明示的な配列をメモリ内に構築することはありません。
