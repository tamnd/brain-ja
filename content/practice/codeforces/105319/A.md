 ## 解決策
 ## 問題の理解

 私たちは皿のコレクションを与えられ、それぞれの皿には重さと幅があります。 これらのプレートから、いくつかのサブセットを選択し、その選択したサブセットを、バーベルの左側と右側を表す 2 つの互いに素なグループに分割することができます。 選択されなかったプレートは単に無視されます。 

構成の「バランス」は幅のみに依存します。 選択した左右のグループへの分割について、左側の幅の合計と右側の幅の合計の間の絶対差を計算します。 次に、コーチはクエリ間隔ごとに複数のクエリを尋ねます。$[L, R]$、結果として得られるバランス値がその範囲内に収まるように、選択したプレートの可能な最大総重量を知りたいと考えています。 

主な困難は、1 つの固定分割を構築する必要がないことです。 各クエリは独立しているため、総重量を最大化しながらバランス制約を満たすために、どのプレートを取得するか、どのように分割するかを決定する必要があります。 

制約は、すべてのサブセットに対するブルートフォースが不可能であることをすでに示しています。 まで$10^5$テスト ケースごとにプレート数を指定すると、指数関数的なサブセットの列挙は直ちに除外されます。 プレートとバランス値に対する二次動的計画法であっても、幅の合計は最大で$10^5$これは、ナップザック スタイルの状態空間が使用できる可能性があることを示唆しています。 

どの構成もクエリ範囲内のバランス値を達成できない場合、微妙なエッジ ケースが発生します。 その場合、答えは「最良の終値」や空の選択解釈ではなく、ゼロである必要があります。 もう 1 つの重要なケースは、すべてのプレートの幅が同じである場合です。この場合、バランス構造が崩れ、パリティに応じて多くのクエリが簡単に達成可能または不可能になります。 

## アプローチ

 この強引なアイデアは簡単です。プレートのサブセットを選択し、あらゆる方法でそれを左右に分割し、バランスを計算し、総重量を追跡します。 これは正しいですが、すぐに爆発します。 分割を無視して、各プレートを左、右、または未使用に割り当てるという観点から考えたとしても、プレートごとにすでに 3 つの選択肢があり、$3^n$構成。 これは計算上の限界をはるかに超えています。 

最初の単純化は、関心事を分離することです。 総重量は、選択したプレートのみに依存し、分割方法には依存しません。 サブセットが固定されると、プレートが左に行くか右に行くかに関係なく、常にその全重量が含まれます。 分割の唯一の役割は、幅の差の制約を満たすことができるかどうかを判断することです。 

これにより、問題は到達可能性の問題に変換されます。 選択した幅に符号を割り当てることでどのようなバランス値が生成されるかを知りたいと考えています。 選択された各プレートは、次のいずれかに貢献します。$+b_i$または$-b_i$バランスの差に。 選択したすべての幅の合計を次のように表すと、$S$、片側に割り当てられた幅の合計は次のようになります。$x$、残高は次のようになります。$S - 2x$。 これは、達成可能なすべてのバランスが、幅のサブセットの合計によって完全に決定されることを意味します。 

ここからが重要な観察です。 重みは常に正であり、分割とは独立しているため、プレートのサブセットが選択されたら、常にそれを完全に含めることを好みます。 バランス値が達成できるかどうかを除いて、重量とバランスの実現可能性の間にトレードオフはありません。 したがって、クエリに対する最適な答えは、すべての重みの合計 (範囲内に少なくとも 1 つの有効な分割が存在する場合)、そうでない場合はゼロになります。 

したがって、問題は、達成可能なすべての幅のサブセット合計を計算し、それらからすべての達成可能なバランス値を導き出すことに帰着します。 これは、幅配列に関する古典的なナップザックの到達可能性の問題です。 

可能な幅のサブセット合計に対してブール DP を計算します。 到達可能な合計ごとに$x$、バランス値を導き出すことができます$S - 2x$、 どこ$S$すべての幅の合計です。 このようなバランス値はすべて達成可能としてマークされます。 最後に、達成可能なバランスがあるかどうかを尋ねる質問に答えることができる構造を構築します。$[L, R]$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットと分割に対するブルート フォース | 指数 | 指数 | 遅すぎる |
 | 幅全体のサブセット合計 DP + 派生バランス |$O(n \cdot \sum b)$|$O(\sum b)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### ## アルゴリズムのチュートリアル

 1. すべての幅の合計を計算します。$S$。 この値は、サブセットの合計が最終的な残高値にどのように変換されるかを決定します。 
2. 幅に対してナップザック スタイルの動的プログラミングを実行します。ここで、配列の達成可能なすべてのサブセットの合計を計算します。$b$。 ブール配列を維持します`dp[x]`プレートの一部のサブセットが選択された合計幅を正確に持つことを意味します$x$。 遷移は標準のサブセット合計です: 各プレート幅について$b_i$、各プレートが最大 1 回使用されるように、到達可能な合計を逆の順序で更新します。 
3. 到達可能なすべてのサブセットの合計を計算した後$x$、変換を使用してバランス値に変換します。$d = S - 2x$。 到達可能な各サブセット合計により、1 つの達成可能なバランス値が生成されます。 
4. 到達可能なすべての残高値をブール配列に保存します`can[d]`。 これにより、考えられるすべての残高に対する直接の到達可能性情報が得られます。 
5. プレフィックス構造を構築する`can`したがって、どのクエリ間隔でも$[L, R]$を使用すると、その範囲内に達成可能なバランスが少なくとも 1 つ存在するかどうかをすぐに判断できます。 
6. クエリごとに、プレフィックス構造を使用して間隔のエンドポイントをスキャンします。 値があれば、$[L, R]$達成可能な場合は、すべてのプレートの重量の合計を出力します。 それ以外の場合はゼロを出力します。 

### なぜ効果があるのか

 すべての有効な構成は、プレートのサブセットを選択し、それを 2 つの側面に分割することに正確に対応します。これは、選択した幅に符号を割り当てることと同じです。 この符号の割り当ては、幅のサブセット合計によって完全に捕捉されます。 DP はすべての可能なサブセットの合計を列挙するため、すべての実現可能なバランス値は派生セット内で 1 回だけ表されます。 重みは分割とは独立しており、選択されたプレートにのみ依存するため、実行可能なバランスであれば、そのサブセット内のすべてのプレートを取り込むことができ、総重量が最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        S = sum(b)
        total_weight = sum(a)

        # subset sum DP for widths
        dp = [False] * (S + 1)
        dp[0] = True

        for w in b:
            for s in range(S, w - 1, -1):
                if dp[s - w]:
                    dp[s] = True

        # reachable balance values
        can = set()
        for x in range(S + 1):
            if dp[x]:
                can.add(S - 2 * x)

        # convert to sorted list for range queries
        can = sorted(can)

        # answer queries by binary search
        import bisect
        for _ in range(q):
            L, R = map(int, input().split())
            i = bisect.bisect_left(can, L)
            if i < len(can) and can[i] <= R:
                print(total_weight)
            else:
                print(0)

if __name__ == "__main__":
    solve()
```DPセクションは標準的な0/1幅のナップザックです。 各プレートが一度だけ寄与するように、逆方向に反復します。 その後、符号付き合計とサブセット合計の間の代数関係を使用して、サブセット合計を達成可能なバランス値に変換します。 

クエリ処理は、達成可能なすべての残高を並べ替え、二分検索を使用してクエリ間隔内に値があるかどうかを確認することに依存しています。 

## 実用的な例

 幅が小さいケースを考えてみましょう$[1, 2]$と重み$[5, 3]$。 幅のサブセットの合計は次のとおりです。$0, 1, 2, 3$。 これらは次のように計算されたバランス値を生成します。$S - 2x = 3 - 2x$、{3, 1, -1, -3} が得られます。 ソート後の到達可能な残高は次のとおりです。$[-3, -1, 1, 3]$。 

| ステップ | 選択されたサブセットの合計$x$| バランス$S - 2x$| 到達可能なセット |
 | --- | --- | --- | --- |
 | 0 | 0 | 3 | {3} |
 | 1 | 1 | 1 | {3, 1} |
 | 2 | 2 | -1 | {3、1、-1} |
 | 3 | 3 | -3 | {3、1、-1、-3} |

 のようなクエリ$[0, 2]$区間内の値 1 を見つけるので、答えは総重量になります$8$。 のようなクエリ$[4, 10]$何も見つからないため、答えは 0 になります。 

このトレースは、私たちがもはや個々の割り当てについて推論しているのではなく、誘導されたバランス値のセットについて推論していることを裏付けています。

 ## 特殊なケース

 重要なエッジ ケースは、クエリ間隔内でサブセットの合計がまったくバランスを生み出さない場合です。 たとえば、すべての幅が 1 に等しく、偶数の残高のみに到達できる場合、奇数の間隔を要求するクエリは常に失敗します。 サブセットの合計が結果のバランスセットのパリティ制約を決定し、二分探索が決定されるため、DP はこれを正確に反映します。`can`交差点は見つかりません。 

もう 1 つのケースは、次のようにクエリ間隔が非常に広い場合です。$[1, 10^5]$。 この状況では、少なくとも 1 つのサブセット合計が存在する限り、通常、少なくとも 1 つの残高が区間内に収まり、答えは重みの完全な合計になります。 アルゴリズムはこれを自然に処理します。これは、間隔のサイズには依存せず、存在のみに依存するためです。
