 ## 解決策
 ## 問題の理解

 一意の名前が付けられたファイルのコレクションが与えられます。 現在、それらの一部はステージと呼ばれる特別な領域に配置されており、残りはワークスペースに配置されています。 また、Stage の外にある他のすべてのファイルとともに、最終的に Stage 内に正確に収まる必要があるファイルのターゲット セットも与えられます。 

許可される操作は 4 種類あります。1 つのファイルをステージとワークスペースの間でいずれかの方向に移動するか、または 1 回の操作ですべてのファイルを一方の側からもう一方の側に移動することです。 各操作には 1 回の移動がかかり、初期ステージ構成を目的の最終構成に正確に変換するために必要な移動の総数を最小限に抑えたいと考えています。 

主な難点は、一括操作は多くの不一致を一度に修正できる可能性がある一方で、正しいかどうかに関係なくすべてを移動するため、破壊的でもあることです。 ソリューションでは、要素を個別に修正する価値がある場合と、完全なリセットが有益な場合を判断する必要があります。 

構造的な意味での制約は小さいです。 テストごとのファイルの合計数は最大 100 で、名前は一意です。 これにより、大量の組み合わせ最適化やグラフ検索の必要性が即座に排除されます。 初期セットとターゲット セットの間のすべての関係をテストごとに線形時間または二次時間でチェックするソリューションで十分です。 

最初のステージがすでにターゲットと正確に一致している場合、微妙なエッジ ケースが表示されます。 単純なソリューションでは不要な操作が実行される可能性がありますが、正解はゼロです。 もう 1 つの特殊なケースは、ステージとターゲットが完全に切り離されている場合です。 その場合、すべてを個別に移動するか、完全なリセットを実行してから選択的に挿入するかを決定する必要があります。 

## アプローチ

 ブルートフォースの観点は、州の観点から考えることです。 各ファイルはステージまたはワークスペースにあるため、構成は最大 2^n です。 どの構成からでも 4 つの操作のいずれかを適用して、別の状態に遷移できます。 BFS などの最短パス検索では、最小限の操作数が見つかります。 すべての操作のコストは等しく、状態空間は有限であるため、これは正しいです。 

ただし、n が小さいとはいえ、2^100 はまったく実行できません。 状態を保存することさえ不可能になります。 操作の構造は、中間構成は気にせず、ファイルがターゲットに対して正しく配置されるかどうかだけを気にするため、ほとんどの状態空間は無関係であることを示唆しています。 

重要な観察点は、初期ステージ メンバーシップと必要な最終ステージ メンバーシップを比較したときに、すべてのファイルが 4 つのカテゴリのいずれかに分類されるということです。 ファイルはすでに正しい場合があります。つまり、ステージで開始して終了するか、ワークスペースで開始して終了する必要があります。 また、間違っている可能性もあります。つまり、現在ステージにあるがステージにあるべきではない、または現在ワークスペースにあるがステージにあるべきであることを意味します。 重要な操作は、まさにこれらの不一致を修正する操作です。 

単一ファイルの移動では 1 つの不一致が修正されますが、完全な移動では構成全体がリセットされ、多くの不一致を一度に削減できる可能性がありますが、その代償として正しい配置も元に戻ります。 これにより、間違ったファイルをそれぞれ直接修正するか、グローバル リセットを実行してから正しいステージを再構築するかのトレードオフが生じます。 

この解決策は、初期構成ですでに正しいファイルの数と間違っているファイルの数を数えて、グローバル リセットが有益かどうかを判断することになります。 完全な移動はステージ全体を空にするか埋めるので、そのような操作の後、必要なファイルを個別に挿入することでターゲットを再構築できます。 

最適な戦略は、最初にステージにすでに正しく配置されているファイルの数にのみ依存することがわかります。 多くのターゲット ファイルがすでにステージにある場合は、グローバルな移動を回避し、不一致のみをローカルで調整します。 正しいものがほとんどないか、まったくない場合は、最初に Stage をリセットする方がコストが安くなります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての構成にわたる BFS の状態 | O(2^n · n) | O(2^n) | 遅すぎる |
 | 交差カウントを設定する | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在のステージ リストをセットに変換して、メンバーシップ チェックが一定時間になるようにします。 これにより、ファイルが現在 Stage 内にあるかどうかをすばやく判断できます。 
2. ターゲットリストを別のセットに変換します。 問題は、ファイル全体に関してこれら 2 つのセットを比較することに帰着します。 
3. 初期ステージ セットにすでに存在するターゲット ファイルの数を数えます。 これは、破壊的な完全操作を実行しない場合、アクションを必要としないファイルを表します。 
4. ステージから欠落しているターゲット ファイルの数を計算します。 これらのファイルは、最初にすべてをリセットすることにしない限り、最終的には単一ファイル操作を使用して挿入する必要があります。 
5. 現在ステージ内にあるがターゲット セットには存在しない追加ファイルの数を計算します。 完全なリセット操作を使用しない限り、これらは削除する必要があります。 
6. 2 つの戦略を評価します。 最初の戦略は、単一ファイルの移動のみを使用することです。不足しているターゲット ファイルをすべてステージに挿入し、余分なファイルをすべて削除する必要があります。 この戦略のコストは、まさに初期ステージとターゲット ステージ間の不一致の数です。 
7. 2 番目の戦略は、ステージ全体のリセットを 1 回実行し、すべてをワークスペースに移動してから、必要なすべてのターゲット ファイルを個別に挿入することです。 これには 1 回の操作と k 回の挿入がかかります。 
8. これら 2 つの計算されたコストの最小値を返します。 

### なぜ効果があるのか

 重要な不変点は、完全リセットを使用するかどうかを決定した後、残りのすべての操作がファイルごとに独立していることです。 単一ファイルの移動では、メンバーシップの不一致が 1 つだけ解決され、他のファイルと対話することはありません。 完全なリセットでは、以前の正確性情報がすべて削除されるため、不一致の数が十分に大きく、個別に修復するよりも最初から再構築する方が安価である場合にのみ役立ちます。 大規模な正確性を部分的に維持する中間操作がないため、これら 2 つの戦略はすべての最適なパスを完全にカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m, k = map(int, input().split())
    s = input().split()
    stage = set(input().split())
    target = set(input().split())

    # count mismatches relative to final target
    missing_in_stage = 0
    extra_in_stage = 0

    for x in target:
        if x not in stage:
            missing_in_stage += 1

    for x in stage:
        if x not in target:
            extra_in_stage += 1

    # cost if we only do single-file moves
    cost_direct = missing_in_stage + extra_in_stage

    # cost if we reset stage then build target
    cost_reset = 1 + k

    print(min(cost_direct, cost_reset))
```コードは、各テスト ケースを読み取り、ステージとターゲット コレクションをセットに変換することから始まります。これにより、O(1) メンバーシップ チェックが可能になります。 次に、ステージに存在しないターゲット ファイルの数と、現在ステージに存在する無関係なファイルの数を計算します。 これら 2 つの数値は、単一ファイル操作のみを使用して構成を修復するコストを完全に表します。 

代替コストは、完全なリセットを実行することを想定しており、これには 1 回の操作が必要で、その後、必要なすべてのターゲット ファイルを個別に挿入します。これには k 回の操作が必要です。 これら 2 つの戦略の間で最小値を取ることで、最適性が保証されます。 

実装の微妙な点は、計算にすべてのファイルの初期リストが必要ないことです。 入力には表示されますが、操作はステージ メンバーシップの遷移にのみ依存するため、コスト構造には影響しません。 

## 実用的な例

 ### 例 1

 入力:

 ステージ = {dp}

 ターゲット = {貪欲、実装}

 欠損セットと追加セットを計算します。 

| ステップ | ステージ | ターゲット | 欠落しています | 番外編 | 直接コスト | コストをリセット |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初期化 | {dp} | {g、i} | 2 | 1 | 3 | 3 |

 直接戦略では dp が削除され、2 つのターゲット ファイルが追加され、3 回の操作が必要になります。 リセット戦略には 1 + 2 = 3 回の操作がかかります。 両方とも同点なので、どちらかが最適です。 

これは、グローバル リセットも同様に優れていますが、厳密には優れているわけではないケースを示しています。 

### 例 2

 入力:

 ステージ = {地理、木、数学}

 ターゲット = {数学、BS}

 | ステップ | ステージ | ターゲット | 欠落しています | 番外編 | 直接コスト | コストをリセット |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初期化 | {g、t、m} | {m,bs} | 1 | 2 | 3 | 3 |

 直接コストでは、2 つの追加ファイルが削除され、1 つの不足ファイルが挿入され、合計 3 になります。リセット コストは 1 + 2 = 3 です。ここでも両方の戦略が一致します。 

これは、k が不一致に比べて小さいため、等式のケースが一般的であり、両方の戦略が同様の線形式に崩壊することを強調しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テストあたり O(n) | ステージとターゲットのセットは 1 回だけスキャンします |
 | スペース | O(n) | ストア ファイル名を最大サイズ n | に設定します。 

制約はテスト全体の合計 n を 100 に制限しているため、この線形ソリューションは容易に十分に高速です。 少数の小さな文字列セットのみを保存するため、メモリの使用量は無視できます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, m, k = map(int, input().split())
        s = input().split()
        stage = set(input().split())
        target = set(input().split())

        missing = sum(1 for x in target if x not in stage)
        extra = sum(1 for x in stage if x not in target)

        out.append(str(min(missing + extra, 1 + k)))

    return "\n".join(out)

assert run("3\n3 1 2\n3\nimplementation\ndp\ngreedy implementation\n4 3 2\ngeo trees math bs\ngeo trees math\nmath bs\n1 0 0\na\n\n\n") == "3\n3\n0"

# all correct already
assert run("1\n3 2 2\na b c\na b\na b\n") == "0"

# all wrong, reset is optimal
assert run("1\n3 2 2\na b c\na b\nx y\n") == "3"

# k large, stage empty
assert run("1\n3 0 3\na b c\n\na b c\n") == "3"

 | --- | --- | --- |
 | すべて正しい | 0 | 身元事件 |
 | すべて間違っています | 3 | リセットか修復かの決定 |
 | 空のステージ | k | ゼロから構築 |
 | 混合 | 計算された | 不一致のカウント |

 ## 特殊なケース

 エッジ ケースの 1 つは、Stage がすでに Target と等しい場合です。 Stage = {a, b} および Target = {a, b} のような入力の場合、欠落カウントと余分なカウントは両方ともゼロであるため、直接コストはゼロで、リセット コストは 1 + k であり、これは厳密には大きくなります。 アルゴリズムは、何も操作を実行しなくても、正しくゼロを返します。 

もう 1 つのエッジケースは、Stage と Target が互いに素である場合です。 Stage = {a, b} および Target = {c, d} の場合、missing は 2、extra は 2 であるため、直接コストは 4 です。リセット コストは 1 + 2 = 3 であるため、アルゴリズムは正しくリセットを優先します。これは、すべての不一致を個別に修正するよりも 1 回のグローバル ワイプの方が安価であることを反映しています。 

最後のエッジ ケースは、Stage が空で Target も空の場合に発生します。 どちらのコストもそれぞれ 0 と 1 と評価されるため、答えは 0 であり、操作が必要ないという事実と一致します。
