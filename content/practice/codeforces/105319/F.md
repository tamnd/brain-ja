 ## 解決策
 ## 問題の理解

 一連の短いテキスト メッセージが与えられ、それぞれのメッセージに対して 1 つの特別なフレーズに基づいて応答方法を決定する必要があります。 受信するすべての文字列は単なる文字の行であり、そのタスクは、大文字小文字と文字を含めて、それが 1 つの固定ターゲット単語に正確に一致するかどうかを確認することです。 

メッセージが文字列と正確に等しい場合`BdnaDars`、応答は次のようになります。`Enough!`。 他のすべての可能な文字列に対する応答は次のようになります。`OK`。 

入力サイズは小さく、最大 1000 個の文字列で、各文字列の長さは最大 100 文字です。 これは、各文字列を直接比較するだけで十分であることを意味します。 単純な文字ごとのスキャンでも、全体で約 100,000 文字のチェックに制限されますが、これは一般的な制限時間としてはわずかです。 

唯一の微妙な障害モードは、文字列比較ロジックが正しくないことに起因します。 何が問題となるかをいくつかの例で説明します。 ソリューションが大文字と小文字を正規化するか文字をトリミングする場合、`bdnadars`または`BdnaDars `一致すべきではないにもかかわらず、誤って一致として扱われてしまいます。 ソリューションがプレフィックスのみを比較する場合、`BdnaDarsX`誤って受け入れられる可能性があります。 正しい動作には、完全に正確な平等性が必要です。 

## アプローチ

 この問題では、総当たりアプローチも最適です。 受信文字列ごとに、ターゲット文字列と文字ごとに比較します。`BdnaDars`。 不一致が見つかった場合は、すぐに次のように分類されます。`OK`。 不一致が見つからずに比較が終了し、長さが同じ場合は、次のように出力されます。`Enough!`。 

これで十分である理由は、この問題では検出​​する単一の正確なパターンが定義されているためです。 等価性チェック以外に悪用できる構造はなく、前処理やハッシュも必要ありません。 最悪の場合の作業は、すべての文字列の各文字を 1 回比較することであり、最大でも 1000 個の文字列×100 文字となり、比較はわずか 100,000 回になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (直接比較) | O(n・L) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各入力文字列を個別に処理し、ターゲット フレーズとの直接の等価性チェックに基づいて出力を決定します。 

1. 文字列の数 n を読み取ります。 これにより、どれだけの独立した決定を下すかが決まります。 
2. ターゲット文字列を次のように修正します`BdnaDars`なぜなら、すべての比較はこの一定の参照に対して行われるからです。 
3. 各入力文字列について、ターゲット文字列と直接比較します。 比較では、長さと文字ごとの同等性の両方を考慮する必要があります。 
4. s がターゲット文字列と正確に等しい場合、出力`Enough!`、禁止フレーズに一致するため。 
5. それ以外の場合は出力`OK`一致しない文字列はすべて均一に扱われるためです。 

重要な設計上の選択は、等価性を単一の原子条件として扱うことです。 これにより、プレフィックスや大文字と小文字の違いを誤って受け入れる可能性のある部分一致ロジックが回避されます。 

### なぜ効果があるのか

 出力は入力文字列が 1 つの固定参照文字列と同一かどうかのみに依存するため、このアルゴリズムは正しいです。 文字列が等しいかどうかは、すべてのインデックスで長さが一致し、文字が一致するかどうかによって完全に判断されます。 アルゴリズムはその条件を正確にチェックするため、すべての文字列が正しく分類され、2 つの異なる文字列が同じ誤った一致結果を生成することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

TARGET = "BdnaDars"

def solve():
    n = int(input().strip())
    for _ in range(n):
        s = input().strip()
        if s == TARGET:
            print("Enough!")
        else:
            print("OK")

if __name__ == "__main__":
    solve()
```このソリューションは、高速入力を使用してすべての文字列を読み取り、それぞれを固定定数と比較します。 の`.strip()`これは、等価性チェックの妨げとなる末尾の改行文字を削除するため、重要です。 

比較`s == TARGET`は Python で効率的に実装されており、最初の不一致で内部で短絡するため、この問題のサイズに最適です。 手動で文字ループやハッシュを行う必要はありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n・L) | n 個の文字列のそれぞれが、長さ L | まで文字ごとに比較されます。 
| スペース | お(1) | 固定ターゲット文字列と単一の入力バッファのみが使用されます。 

この制約では、長さ 100 の文字列を最大 1000 個許可するため、文字操作の総数は 100,000 に制限されます。 これは、単純な文字列比較であっても、Python の制限内に十分収まります。 

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline
    TARGET = "BdnaDars"
    n = int(input().strip())
    for _ in range(n):
        s = input().strip()
        if s == TARGET:
            print("Enough!")
        else:
            print("OK")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# provided sample
assert run("2\nHi\nBdnaDars\n") == "OK\nEnough!", "sample 1"

# custom cases

# minimum size
assert run("1\nBdnaDars\n") == "Enough!", "exact match single case"

# all different
assert run("3\nA\nB\nC\n") == "OK\nOK\nOK", "no matches"

# case sensitivity check
assert run("2\nbdnaDars\nBdnaDars\n") == "OK\nEnough!", "case sensitivity"

# near match with extra character
assert run("1\nBdnaDarsX\n") == "OK", "extra suffix"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1\nBdnaDars | 十分！ | 単一要素と完全一致 |
 | 3\nA\nB\nC | OK OK OK | 均一な拒否 |
 | bdnaダース / bdnaダース | わかりました/もう十分です! | 大文字と小文字の区別の処理 |
 | BdnaダースX | OK | プレフィックスの受け入れを禁止します。 

## 特殊なケース

 重要なエッジ ケースの 1 つは大文字と小文字の区別です。 文字列`bdnadars`たとえ視覚的にターゲットに似ていたとしても、決して受け入れられるべきではありません。 Python の文字列の等価性には、大文字と小文字の違いを含む文字の正確な一致が必要であるため、アルゴリズムはこれを正しく拒否します。 

もう 1 つの特殊なケースは、追加の末尾文字です。 例えば、`BdnaDarsX`ターゲットとプレフィックスを共有しますが、長さは長くなります。 文字列の長さが異なるため等価性チェックは失敗するため、安全に次のように分類されます。`OK`。 

3 番目のエッジ ケースは、入力がターゲットと同一である場合の正確な境界一致です。 この場合、比較はすべての文字を検証した後でのみ成功し、出力は次のようになります。`Enough!`これは、この問題で定義される唯一の特殊なケースです。
