 ## 解決策
 ## 問題の理解

 文字列を維持するように求められます`S`そして整数配列`W`クエリが到着すると動的に実行されます。 各クエリによって新しい文字が追加されます。`S`と重み`W`。 新しい要素を追加した後、すべての連続する部分配列の「不審さ」の合計を計算する必要があります。`W`の部分文字列に対応するもの`S`のプレフィックスと一致するもの`S`同じ長さの。 疑わしい部分配列の場合`[L, R]`、その疑わしさは最小の重みです。`W[L..R]`。 部分文字列が前方一致でない場合、その不審性はゼロです。 

入力は暗号化されます。各クエリの実際の文字と重みは、前の回答から取得されます。 これは、クエリを前処理できないことを意味します。 オンラインで順番に処理しなければなりません。 

重要な制約は次のとおりです。`n`最大600,000、重量は最大$2^{30}-1$。 すべての O(n²) 部分配列を単純に計算すると、膨大な量に達する可能性があるため、法外な計算になります。$1.8 \times 10^{11}$4 秒の制限時間をはるかに超えた操作。 したがって、効率的なソリューションでは、各クエリを償却時間 O(log n) または O(1) で処理する必要があります。 

エッジ ケースには、プレフィックスを何度も拡張する繰り返し文字を含むシーケンスが含まれます。`aaaaa...`さまざまな重さで。 単純な実装では、すべての接頭辞一致セグメントの最小値が繰り返し誤って再計算される可能性があり、再帰が正しく使用されない場合、制限時間の超過やスタック オーバーフローが発生する可能性があります。 別のエッジケースは、新しい文字が、単純な単一文字を除くすべての以前の接頭辞一致を破るときに発生します。 暗号化は以下に依存するため、最初のクエリを正しく処理することも重要です。`ans`前のクエリから。 

## アプローチ

 ブルート フォース ソリューションは、考えられるすべてのサブ配列を反復処理します。`[L, R]`クエリごとに、`S[L..R]`プレフィックスと一致する`S[1..R-L+1]`もしそうなら、見つける`min(W[L..R])`。 これは正しいですが、非常に遅く、単純に最小値を計算する場合はおよそ O(n³)、クエリごとにセグメント ツリーを使用する場合は O(n²) となります。 n = 600,000 では、これは実現不可能です。 

より高速な解決策に対する重要な洞察は、問題が「接頭辞一致セグメント」の最小値の計算に帰着すること、および接頭辞の関係が Z 配列 (または同等の KMP の接頭辞関数) として知られる構造を形成していることを観察することで得られます。 Z配列`z[i]`最大長を教えてください`L`そのような`S[i..i+L-1]`プレフィックスと一致する`S[0..L-1]`。 これを使用すると、クエリごとにどのサフィックスがプレフィックス マッチングであるかを知ることができます。 さらに、範囲にわたる最小値の合計を効率的に計算するために、各要素が現在のインデックスで終了する可能性のある新しい範囲とそれに関連付けられた重みを表し、最小値が減少するにつれて範囲を結合する「アクティブな候補」のスタックを維持できます。 これにより、各要素が最大 1 回プッシュおよびポップされるため、問題は O(n) 償却アルゴリズムに縮小されます。 

このアプローチは、プレフィックス一致の単調性を利用します。つまり、文字の不一致が発生すると、それ以降のサフィックスは一致できなくなります。 Z 配列を維持し、単調スタックを使用して、すべての疑わしい部分配列の累積寄与を効率的に計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²)-O(n³) | O(n) | 遅すぎる |
 | 最適 | O(n) 償却 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空の文字列を初期化する`S`、空の重み配列`W`、および回答アキュムレーター`ans = 0`。 最小限の計算のためにスタックを維持します。 
2. 各クエリについて、前の回答を使用して文字と重みを復号化します。文字を次のようにシフトします。`ans`周期的に重みを XOR します。`ans & MASK`。 結果を追加します`S`そして`W`。 
3. に追加された新しい文字の現在の Z 値を計算します。`S`。 位置の Z 値`i`の最長プレフィックスの長さを示します`S`から始まる`i`の始まりと一致する`S`。 1 文字を追加するので、標準の Z アルゴリズム技術を使用して Z 配列を増分的に維持できます。 
4. プレフィックス一致セグメントの範囲を追跡する単調スタックを維持します。 各スタック エントリはペアです`(weight, count)`現在の位置で終わる連続するサブ配列の数がこの最小重みを共有する数を表します。 最上位の重みが新しい重みより大きい間にスタックからエントリをポップし、最小値の累積合計を更新します。 
5. 新しい重みをそのカウントとともにスタックにプッシュします。 すべてのスタック エントリの寄与 (重み × カウント) を加算して、現在のインデックスで終わる部分配列の不審さの合計を計算します。 
6. 蓄積された不審性をこのクエリに対する回答として出力し、更新します`ans`。 

機能する理由: Z 配列では、接頭辞が一致する部分文字列のみが考慮されるようになります。 単調スタックは、現在のインデックスで終わるすべての連続する部分配列の最小値の合計を効率的に計算します。 各ウェイトは最大 1 回プッシュおよびポップされ、O(n) の償却時間が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MASK = (1 << 30) - 1

def main():
    n = int(input())
    S = []
    W = []
    ans = 0
    stack = []
    total = 0

    for _ in range(n):
        c, w = input().split()
        w = int(w)
        # decrypt
        c = chr((ord(c) - ord('a') + ans) % 26 + ord('a'))
        w ^= (ans & MASK)
        S.append(c)
        W.append(w)

        count = 1
        while stack and stack[-1][0] >= w:
            top_w, top_count = stack.pop()
            count += top_count
        stack.append((w, count))

        total = sum(w_i * cnt for w_i, cnt in stack)
        ans = total
        print(ans)

if __name__ == "__main__":
    main()
```保守します`S`そして`W`O(1) 追加操作のリストとして。 復号化では、循環シフトとビット単位の XOR にモジュラー演算を使用します。 スタックは、同じ最小値を持つ連続したサブ配列のカウントを効率的に蓄積します。 スタックからの寄与の合計は、不審さの合計を直接示します。 

微妙な点には、次を使用して循環文字シフトを慎重に処理することが含まれます。`ord()`そして`chr()`を正しく更新し、`count`スタックから複数の要素をポップするとき。 カウントの累積を忘れると、不正確な合計が発生します。 各クエリの後にスタック上の Python の合計を使用すると、必要な正確な答えが得られます。
