 ## 解決策
 ## 問題の理解

 すべてのノードが非表示の整数値を持つ、ルート化されたツリーが与えられます。 私たちが知っているのは、ツリー構造と各ノードの番号です。`c_i`。 この数値は、サブツリーにローカルなもの、つまりサブツリー内のすべてのノード間で何かを示します。`i`、 その通り`c_i`そのうちの値は、次の値よりも厳密に小さいです。`i`。 

タスクは、これらすべてのサブツリー制約と一貫性のあるノードへの整数の割り当てを再構築することです。 複数の割り当てが機能する場合は、どれも許容されます。すべての制約を満たす割り当てがない場合は、不可能であることを報告する必要があります。 

主な問題点は、すべてのノードがそのサブツリー内の比較に依存する制約を課すことですが、それらの比較は事前にわからない値のグローバルな順序に依存することです。 ツリーはこれらの制約をさまざまなレベルにわたって結合するため、ノードの単純な独立した処理は失敗します。 

この制約により、最大 2000 ノードが許可されます。 これは、3 次または 2 次の因数を使用した解が通過できるほど十分に小さいですが、すべての値の割り当てを明示的に推論したり、値の順列をシミュレートしたりすることは実行できません。 代わりに、一貫性を維持しながら値を段階的に割り当てる建設的なプロセスを期待する必要があります。 

一般的な失敗モードは、サブツリー構造を考慮せずに貪欲に値を割り当てようとしたときに発生します。 たとえば、BFS 順序で、または子の前に親によって値を割り当てると、その値は無視されます。`c_i`隣接するものだけでなく、サブツリー全体に依存します。 ノードの並べ替えのみに基づいて値を割り当てようとすると、別の微妙な失敗が発生します。`c_i`、 なぜなら`c_i`はグローバル ランクではなく、サブツリー相対ランクのみを表します。 

小さな具体的な問題: を持つ親を考えてみましょう。`c = 0`そして子供と`c = 1`。 より小さくなるように貪欲に値を割り当てると、`c`値が小さいことを意味する場合、親制約は両方の子が個別にではなく同時に順序付けされることに依存するため、サブツリー内に矛盾を強制する可能性があります。 

## アプローチ

 強引なアイデアは、次の順列から値を割り当てようとすることです。`1..n`ノードに接続し、すべての制約が満たされているかどうかを確認します。 割り当てごとに条件を検証するにはサブツリー数を計算する必要があり、これ自体がノードごとの DFS またはマージされたトラバーサルを必要とします。 たとえ一つの課題の確認に時間がかかっても`O(n^2)`、すべての順列を試してみると、`O(n!)`、それは限界をはるかに超えています。 

問題の構造は、相対的な順序を徐々に固定しながら、ローカルでサブツリー制約を尊重する方法で値を構築する必要があることを示唆しています。 重要な観察は、`c_i`ノードの前にサブツリー内のノードをいくつ配置する必要があるかを説明します。`i`値の順序付けではありますが、そのサブツリー内でまだ「利用可能な」ノードを基準としている場合に限ります。 

これは建設的なアイデアにつながります。つまり、ツリーを葉から上に向かって処理し、各ノードでサブツリー内のノード間の相対的なランクを決定します。 子のサブツリーの順序がすでにわかっている場合は、それらをマージし、次と一致する位置に親を挿入できます。`c_i`。 サブツリーは互いに素であるため、マージはソートされたリストをマージするのと同じように動作し、制約は正しい挿入ポイントの選択に減ります。 

各ノードについて、各配置候補よりも小さい要素の数を表す位置のリストを維持します。 子を結合するときは、これらのリストを結合してから、現在のノードを正確に次の位置に配置します。`c_i`そのサブツリー内の要素は小さくなります。 

これにより、問題はツリー DP に縮小され、各ノードがそのサブツリー内に考えられるランクのソートされた構造を構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列チェック | O(n! · n^2) | O(n) | 遅すぎる |
 | 順序付けされたマージを使用したツリー DP | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 次のノードでツリーをルートします。`p_i = 0`。 各サブツリー内の有効な相対順序を計算します。 
2. 各ノードについて、そのサブツリー内のノードの最終的な順序を表すリストを定義します。 実際の値を保存する代わりに、概念的に並べ替えられた順序で位置を保存します。 
3. ルートから DFS を実行します。 リーフ ノードの場合、違反する内部制約がないため、そのリストにはそれ自体のみが含まれます。 これは基本ケースとして機能します。 
4. 内部ノードの場合、最初にすべての子のリストを再帰的に計算します。 各子は、そのサブツリーの一貫した順序付けをすでに表しています。 
5. すべての子リストを 1 つのリストにマージします。 このマージは、連結して結果を単一の複数の位置セットとして扱うことによって行われます。 この段階では、サブツリー内の相対的なサイズのみを考慮します。 
6. 子をマージした後、現在のノードをこのマージされたリストに挿入する必要があります。`c_i`そのサブツリー内の要素はそれよりも小さいです。 これはインデックスに配置することを意味します`c_i`マージされたリストのゼロベースの順序付け。 
7. もし`c_i`マージされたリストのサイズより大きい場合、配置は不可能であり、構築はすぐに失敗します。 
8. 完全な DFS が完了すると、最小値から最大値までのノードの有効な順序が得られます。 増加する整数を割り当てる`1..n`この順番に従って。 

### なぜ効果があるのか

 各サブツリーは結合される前に個別に処理されるため、すべてのサブツリー リストは有効な内部順序を正確に表します。 位置にノードを挿入すると`c_i`、サブツリー内の小さい要素の数を正確に強制しています。 子のサブツリーは互いに素であるため、マージによって以前に満たされていた制約が破られることはありません。 DFS の不変条件は、すべてのサブツリー リストを違反することなく上方に拡張できるということです。`c_i`したがって、最終的なルート構造は、グローバルに一貫した順序付けをエンコードします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
children = [[] for _ in range(n)]
c = [0] * n
root = -1

for i in range(n):
    p, ci = map(int, input().split())
    c[i] = ci
    if p == 0:
        root = i
    else:
        children[p - 1].append(i)

# Each node returns a list of nodes in increasing order of final value
def dfs(u):
    cur = [u]
    for v in children[u]:
        sub = dfs(v)
        cur.extend(sub)

    # We need to place u so that exactly c[u] elements in its subtree are smaller
    # but cur currently includes u at front; we will reposition it.
    cur.remove(u)

    if c[u] > len(cur):
        raise ValueError("impossible")

    cur.insert(c[u], u)
    return cur

try:
    order = dfs(root)
    ans = [0] * n
    for i, node in enumerate(order):
        ans[node] = i + 1

    print("YES")
    print(*ans)
except ValueError:
    print("NO")
```実装は文字通り DFS の構築に従います。 各再帰呼び出しにより、サブツリーの順序が構築されます。 ノード自体を一時的に含めてから、ノードを削除して、指定された正しいインデックスに再挿入します。`c_i`。 これにより、挿入位置によってそのサブツリーの順序に存在する小さな要素の数が直接強制されるため、複雑なカウント ロジックが回避されます。 

最後の割り当てステップでは、構築されたグローバル順序を値にマッピングします。`1..n`、相対的な順序のみが重要であるため、これは常に有効です。 

ツリーはチェーンに縮退する可能性があるため、実装の微妙な点は再帰の深さです。 再帰制限を増やすと、Python でのスタック オーバーフローが防止されます。 

## 実用的な例

 ### 例 1

 入力:```
3
2 0
0 2
2 0
```ツリー構造: ノード 2 がルート、ノード 1 と 3 が子です。 

ノード 2 で DFS を開始します。 

| ステップ | ノード | 子の結果 | マージされたリスト | 挿入位置 | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | [] | [1] | c1 = 0 | [1] |
 | 2 | 3 | [] | [3] | c3 = 0 | [3] |
 | 3 | 2 | [1,3] | [1,3] | c2 = 2 | [1,3,2] |

 最終的な注文は、`[1, 3, 2]`。 値の割り当て`1,2,3`したがって、次のような有効な再構成が得られます。`1 3 2`または同等の一貫したラベル。 

このトレースは、ルートがグローバル制約を課す前に、各サブツリーがどのように独立して構築されるかを示しています。 

### 例 2

 入力:```
4
2 0
0 1
2 0
2 1
```ノード 2 はルートであり、子 1、3、4 があります。 

| ステップ | ノード | 子の結果 | マージされたリスト | 挿入位置 | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | [] | [1] | c1 = 0 | [1] |
 | 2 | 3 | [] | [3] | c3 = 0 | [3] |
 | 3 | 4 | [] | [4] | c4 = 1 | [4] |
 | 4 | 2 | [1,3,4] | [1,3,4] | c2 = 0 | [2,1,3,4] |

 これは、root がどのようにして`c = 0`自身をそのサブツリー内で強制的に最小にし、すべての子を上に移動します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | 各 DFS マージにはサブツリー サイズに対するリスト操作が含まれ、各ノードは最大 n | のサイズのリストに挿入される可能性があります。 
| スペース | O(n^2) | 各サブツリーには、そのノードの明示的なリストが格納されます。 

制約により許可されるのは、`n ≤ 2000`、だから、`O(n^2)`建設は許容されます。 操作は単純なリスト操作であり、Python はこれを制限内で快適に処理します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    children = [[] for _ in range(n)]
    c = [0] * n
    root = -1

    for i in range(n):
        p, ci = map(int, input().split())
        c[i] = ci
        if p == 0:
            root = i
        else:
            children[p - 1].append(i)

    sys.setrecursionlimit(10**7)

    def dfs(u):
        cur = [u]
        for v in children[u]:
            cur.extend(dfs(v))
        cur.remove(u)
        if c[u] > len(cur):
            raise ValueError
        cur.insert(c[u], u)
        return cur

    try:
        order = dfs(root)
        ans = [0] * n
        for i, v in enumerate(order):
            ans[v] = i + 1
        return "YES\n" + " ".join(map(str, ans))
    except:
        return "NO"

# sample
assert run("""3
2 0
0 2
2 0
""").split()[0] == "YES"

# chain
assert run("""1
0 0
""").startswith("YES")

# simple invalid
assert run("""2
2 1
0 0
""").startswith("NO")

# star
assert run("""4
2 0
0 1
2 0
2 1
""").split()[0] == "YES"

 ## 特殊なケース

 単一ノード ツリーは常に機能します。`c_1`ゼロでなければならず、唯一の有効な代入は自明です。 DFS はシングルトン リストを返し、位置 0 に挿入すると正確さが保たれます。 

ノード`c_i`サブツリーのサイズを超えると、すぐに構築が不可能になります。 アルゴリズムでは、これは挿入時に検出されます。`c_i > len(cur)`配置前に、不正な順序を生成するのではなく、早期に拒否されるようにします。 

星型ツリーでは、多くの独立した子サブツリーのマージが強調されます。 各子は互いに素な順序付けに寄与するため、連結によって有効性が維持され、ルートの挿入位置によって最終的な構造が曖昧さなく制御されます。
