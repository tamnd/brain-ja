 ## 解決策
 ## 問題の理解

 ラテン文字の大文字で書かれた単一の文字列が与えられます。 この文字列は有効な単語であることが保証されていません。 これは単に、通常の文字と特殊文字「ß」を含む可能性のある未知の小文字文字列にドイツ語の大文字化ルールを適用した結果です。 

問題は、古い表記法では「ß」に標準的な大文字の形式がないことです。 歴史的には、大文字の場合は「SS」に置き換えられます。 そのため、プロセスを逆にしようとすると曖昧さが生じます。 大文字の文字列に「SS」がある場合、それがもともと 2 つの別々の小文字「s」から来たのか、それとも大文字で「SS」になった 1 つの小文字「ß」から来たのかわかりません。 S 以外の大文字はすべて 1 つの小文字に対応するため、他のすべての文字は明確です。 

タスクは、このルールに基づいて指定された大文字の文字列を生成する可能性のあるすべての小文字の文字列を再構築することです。 特殊文字の場合、出力では「ß」を直接使用せず、代わりに文字「B」を使用する必要があります。 

入力の長さは最大 20 であるため、分岐係数が制御されている限り、指数関数的な分岐ソリューションでも許容されます。 これは、あいまいさが連続する「S」文字の実行の周囲に局所的にのみ存在し、そのような実行の総数がすべての可能性を列挙するには十分に小さいことを直ちに示唆しています。 

文字列に孤立した S ブロックまたは繰り返しの S ブロックが含まれている場合は、微妙なケースが発生します。 例えば「SSS」には独自の解釈はありません。 グループ化に応じて、「s + ss」、「ss + s」、または「ß + s」、または「s + ß」として分割できます。 すべての「SS」を貪欲に「ß」または「ss」に変換する単純なアプローチでは、有効な分解を見逃したり、早期にオーバーコミットしたりする可能性があります。 

もう 1 つの特殊なケースは、単一の「S」です。 「ß」は常に大文字の 2 つの S 文字を構成するため、1 つの大文字の S は小文字の「s」からのみ得られます。 したがって、ラン内の単一の文字がタイリングを制約します。 

## アプローチ

 ブルートフォース手法では、文字と「ß」を使用して長さ 20 までの小文字の文字列をすべて生成し、それぞれを大文字にして入力と比較します。 アルファベットのサイズが少なくとも 27 で、検索スペースが 27^20 となり、実現可能な制限をはるかに超えているため、これはすぐに爆発します。 

重要な点は、小文字から大文字への変換では、大文字の文字列内の S の連続セグメント内に曖昧性が生じるだけであるということです。 S 以外の文字はすべて固定されており、区切り文字として機能します。 k 個の連続する S 文字のブロックを分離すると、問題はブロックごとに独立したものになります。 

長さ k のブロック内で、サイズ 1 と 2 のタイルを使用して長さ k のシーケンスを効果的にタイリングしています。サイズ 1 のタイルは小文字の「s」に対応し、サイズ 2 のタイルは小文字の「ß」に対応します (出力では「B」として表されます)。 これにより、問題は 1 と 2 を使用して k のすべての合成を生成することになり、これは古典的なフィボナッチ構造の再帰です。 

k は全体で最大 20、S の出現数は最大 3 であるため、組み合わせの総数はわずかなままです。 各ブロックに対してすべての有効な解釈を生成し、非 S 文字で区切られたブロック全体のデカルト積を取得できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての小文字文字列に対するブルート フォース | O(27^n) | O(n) | 遅すぎる |
 | S ブロック タイリングに分割して結合 | O(F(k) · n) | O(F(k) · n) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字列をブロックごとに解釈して答えを構築します。

1. 文字列を左から右にスキャンし、連続する「S」文字の最大セグメントと単一文字の非 S セグメントに分割します。 この分離が機能するのは、S のみがあいまいさを生み出すためであり、他のすべては固定されており、直接小文字に変換できます。 
2. S 以外のすべての文字を直ちに小文字に変換し、固定セグメントとして保存します。 出力のこの部分は決して分岐しないため、すべての最終回答で同一になります。 
3. k 個の連続する S 文字のブロックごとに、k をサイズ 1 または 2 のセグメントに分割するすべての可能な方法を生成します。各分割は「s」と「B」で構成される文字列に対応します。1 は「s」に、2 は「B」にマッピングされます。 これが機能する理由は、「s」と「ß」の両方がそれぞれ 1 つまたは 2 つの大文字の S 文字を生成するためです。 
4. 空の文字列で始まる部分的な結果のリストを保持します。 ブロックごとに、そのブロックの考えられるすべての解釈を既存のすべての部分文字列に追加して、現在のリストを拡張します。 これにより、独立した S ブロックにわたるデカルト積が作成されます。 
5. すべてのセグメントを処理した後、構築されたすべての文字列を出力します。 

### なぜ効果があるのか

 各小文字文字列は、大文字文字列内のすべての最大 S-run が 1 長さと 2 長さの寄与にどのように分割されるかによって一意に決定されます。 非 S 文字はこの選択と相互作用しないため、独立したブロックへの分解は完了します。 このアルゴリズムは、すべてのブロックのすべての有効なタイリングを 1 回だけ列挙し、すべてのタイリングは有効な小文字のプリイメージに対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    
    # Parse into segments: either fixed chars or S-blocks
    blocks = []
    i = 0
    n = len(s)
    
    while i < n:
        if s[i] != 'S':
            blocks.append([s[i].lower()])
            i += 1
        else:
            j = i
            while j < n and s[j] == 'S':
                j += 1
            length = j - i
            
            # generate all decompositions of length using 1 and 2
            options = []
            
            def dfs(pos, cur):
                if pos == length:
                    options.append("".join(cur))
                    return
                if pos + 1 <= length:
                    cur.append('s')
                    dfs(pos + 1, cur)
                    cur.pop()
                if pos + 2 <= length:
                    cur.append('B')
                    dfs(pos + 2, cur)
                    cur.pop()
            
            dfs(0, [])
            blocks.append(options)
            i = j
    
    # combine all blocks
    res = [""]
    for b in blocks:
        new_res = []
        for prefix in res:
            for add in b:
                new_res.append(prefix + add)
        res = new_res
    
    # remove duplicates if any (safety, though not needed)
    res = sorted(set(res))
    
    sys.stdout.write("\n".join(res))

if __name__ == "__main__":
    solve()
```実装では、まず文字列を独立したセグメントに分解します。 S 以外のすべての文字は、固定の単一オプション ブロックになります。 すべての S-run は、サイズ 1 および 2 のステップでタイリングをシミュレートする深さ優先検索によって生成される、すべての有効な解釈のリストになります。 

最後の結合ステップでは部分文字列を繰り返し展開し、すべてのブロック解釈のデカルト積を効果的に構築します。 

少し微妙な点は、重複排除が最後に適用されることです。 理論的には、この構造によってすでに一意性が保証されていますが、ソートとセット変換により、同様の実装における異なる再帰パスからの偶発的な重複に対する堅牢性が保証されます。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(F(k) · n) | 各 S ブロックはフィボナッチ数タイリングを生成し、ブロックを結合すると合計出力サイズは線形になります。

 ## 特殊なケース

 単一の S 文字は決定論的に動作します。 アルゴリズムは長さ 1 のブロックを作成しますが、DFS はサイズ 1 の 1 つのステップのみを許可し、正確に 1 つの解釈 (「s」) を生成します。 

SSS のような長い S ランが分岐の唯一のソースです。 DFS は、すべての有効なタイリング (1+1+1、1+2、2+1) を調べます。2+2 は長さ 3 に対して無効であるため、境界チェックによって自動的に除外されます。 各パスは個別の小文字の再構成に対応するため、有効な出力が失われることはありません。 

非 S セパレータはブロック間の独立性を保証します。 たとえば、ASST では、文字列は A、SS、および T に分割されます。アルゴリズムは SS を独立して処理するため、その内部の組み合わせは A または T に干渉せず、文字列全体にわたって正確さが維持されます。
