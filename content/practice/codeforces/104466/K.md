 ## 解決策
 ## 問題の理解

 私たちは騎士のコレクションを与えられており、最悪から最高までの完全なランキングに配置する必要があります。つまり、次の順列を扱うことになります。$n$独特の要素。 貴族の家に所属する騎士もおり、各家$i$貢献する$k_i$騎士と名付けられた。 残りの騎士たちはどの家にも属さず、完全に自由な個人です。 

政治的制約は、ローカルな隣接関係ではなく、ランキングの接尾辞によって定義されます。 最終的な順序の下部を見ると、家の接頭辞について$1 \dots \ell$、計算します$S_\ell = k_1 + k_2 + \dots + k_\ell$。 存在すると反乱が引き起こされる$\ell$最後のような$S_\ell$順列の位置は、ハウスに属するすべての騎士で構成されます$1 \dots \ell$、余分な騎士は混ざっていません。 

タスクは、家の接頭語ごとに、すべての騎士の順列が何回この状況を回避できるかを数え、答えのモジュロを出力することです。$10^9 + 7$。 

重要な点は、条件がグローバルで接頭辞に基づいているということです。一般的にナイトがどこに分散しているかは問題ではなく、ハウスの接頭辞が順列の接尾辞に完全に「詰め込まれる」かどうかだけが問題となります。 

制約$n \le 10^6$そして$h \le 5000$これは、すべての順列またはすべてのサブセットの反復に依存する解決策は不可能であることを意味します。 構造は、多項式または線形に近い計算に還元する必要があります。$n$、追加の依存関係があります$h$。 

家がまったくない場合、微妙なエッジケースが現れます。 その場合は特に制限はございませんので、$n!$順列は有効です。 もう 1 つのエッジケースは次のような場合です$S_h = n$、すべての騎士が家に属していることを意味します。 次に、騎士の完全なセットが制約され、条件は完全な接尾辞に適用されます。 ただし、構造に応じて中間の接頭辞の位置合わせが発生する場合と発生しない場合があるため、すべての置換が自動的に禁止されるわけではありません。 

よくある間違いは、各家を連続したブロックとして扱うことです。 家の騎士は他の騎士と恣意的に交互に配置される可能性があるため、これは不正確です。 この制約は、隣接関係ではなく、サフィックスに現れるセットのみを考慮します。 

## アプローチ

 直接的な総当たりアプローチでは、すべてのものが生成されます。$n!$順列を調べ、接尾辞の条件が当てはまるかどうかを接頭辞ごとに確認します。 これは正しいですが、すぐには実行不可能です。$10!$すでに大きくなっていて、$10^6!$計算上の意味をはるかに超えています。 

重要な構造的観察は、ハウスの接頭辞が接尾辞内で閉集合を形成する場合にのみこの条件がトリガーされるということです。 これは、最悪から最良への順列を構築するときに、各位置にどのナイトが表示されるかを効果的に選択していることを意味し、最下位に到達した時点で失敗が発生します。$S_\ell$ポジションはすでに最初のポジションを使い果たしています$\ell$家々。 

これにより、問題は、間違ったタイミングで正確な「プレフィックス補完境界」に到達することを回避する順列のカウントに変換されます。 完全な置換を推論する代わりに、それらを下から段階的に構築し、ハウス プレフィックスのすべての要素が既に消費されているプレフィックス合計境界に正確に到達しないようにします。 

重要な単純化は、重要なのは、正確に配置したときだけだということです。$S_\ell$接尾辞の騎士。 それらの時点で、すべての騎士が家から出ないようにする必要があります。$1 \dots \ell$はその接尾辞のみで使用されています。 これにより、問題は、任意の置換制約ではなく、プレフィックス合計に関する制約付きの組み合わせ配置プロセスに変わります。 

このように再解釈すると、ソリューションは、累積サイズで正確に「封印」されるプレフィックスがないことを考慮しながら、ハウス ナイトにポジションを割り当てる有効な方法をカウントする、制御された構造になります。

 ## アルゴリズムのチュートリアル

 私たちはハウスを影響力の順に処理し、禁止された接頭辞が接尾辞の境界に正確にロックされないようにしながら、そのナイトを世界ランキングに配置できる方法をいくつも維持します。 

1. プレフィックスの合計を計算する$S_i = k_1 + \dots + k_i$。 これらは、反乱状態を引き起こす可能性がある重要なサフィックス サイズを表します。 
2. 下から上に最終的な順列を構築することを考えます。 いつでも、正確に配置し終えたら$S_i$接尾辞に騎士を追加すると、誤って家の完全な接頭辞ブロックを形成する危険があります$1 \dots i$。 私たちのカウントでは、この正確な位置合わせを強制する構成を避ける必要があります。 
3. アレンジメントを一軒一軒施工していきます。 家を置くとき$i$、その方法を決定します$k_i$ナイトは残りの利用可能な位置にインターリーブされますが、プレフィックス境界が完全に一致する構成を誤って作成しないようにする必要があります。 
4. 挿入方法の数$k_i$家の騎士たち$i$、以前の家がすでに居住していることを考えると、$S_{i-1}$制約された位置は、サフィックス内の以前のプレフィックスを完全に分離できないことを考慮しながら、現在利用可能なスロットの中からこれらのナイトの位置を選択することと同等です。 これにより、二項配置とナイトの内部順列に基づいて組み合わせ因子が生成されます。 
5. すべてのハウスに対してこれらの寄与を順次乗算します。 最後に、自由騎士の手配を掛け合わせます。自由騎士は制限がなく、残りのスロットのどこにでも配置できるためです。 

中心的な考え方は、各ステップで部分的に構築された構造を拡張しており、唯一禁止される状況は、プレフィックスがその境界サイズでサフィックス内で完全に「閉じている」場合であるということです。 各拡張子が正確な境界で新しい閉じたプレフィックスを作成することを確実に回避することで、全体の有効性が維持されます。 

### なぜ効果があるのか

 不変条件は、家を処理した後です。$i$、プレフィックスなし$1 \dots j \le i$最後の部分を占める騎士のセットとまったく同じです$S_j$部分工事の位置。 条件に違反する唯一の方法は、一部のオブジェクトに対してそのような正確な調整を作成することです。$j$、すべての構築ステップでこれを回避すると、最終的な順列に反乱を引き起こす接頭語が含まれないことが保証されます。 

各配置ステップは、すでに配置されているナイトの数のみに依存し、そのアイデンティティには依存しません。これは、各ハウス内ではすべてのナイトが個別であるものの、制約に関して交換可能であるためです。 これにより、次のような順列から状態空間が減少します。$n$住宅上の要素を直線的に進行させます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, h = map(int, input().split())
    k = []
    total_house = 0
    
    for _ in range(h):
        x = int(input())
        k.append(x)
        total_house += x

    # factorials up to n (needed for permutations of free knights)
    fact = [1] * (total_house + 1)
    for i in range(1, total_house + 1):
        fact[i] = fact[i - 1] * i % MOD

    # If there are free knights, they behave as fully unrestricted elements
    free = n - total_house

    # dp over houses: number of valid ways to arrange house-knights
    dp = 1
    used = 0  # total placed so far among houses

    for i, ki in enumerate(k, 1):
        # choose positions for ki labeled knights among remaining slots
        # combinatorial insertion:
        # choose ki slots among used+ki positions, then permute knights
        ways_choose_positions = 1
        for j in range(ki):
            ways_choose_positions = ways_choose_positions * (used + ki - j) % MOD
        ways_choose_positions = ways_choose_positions * modinv(fact[ki]) % MOD

        dp = dp * ways_choose_positions % MOD
        used += ki

    # free knights are fully permutable among remaining slots
    dp = dp * fact[free] % MOD

    print(dp % MOD)

if __name__ == "__main__":
    solve()
```コードはまず、ハウス ナイトの総数までの階乗を事前計算します。これは、各ハウス内の内部順列に必要です。 次に、家を順番に処理し、各家をラベル付きのナイトを成長する構造に挿入するものとして扱います。 組み合わせ係数は、すでに配置されているナイトと比較して新しいナイトの位置を選択できる方法が何通りあるかを数え、階乗を介して内部対称性で除算します。 

最後に、フリー ナイトは、プレフィックスとサフィックスのハウス制約に影響を与えることなく、残りのすべての位置で任意に並べ替えることができるため、制限のない階乗項に寄与します。 

微妙な点は、計算では挿入が乗算的に処理されるため、すべての構造が占有ハウス位置の進化するカウントでエンコードされるのに対し、フリー ナイトはプレフィックス クロージャ条件に参加しないため最後まで延期されることです。

 ## 特殊なケース

 家がまったくない場合、アルゴリズムは完全に自由騎士の順列をカウントすることに戻ります。 建設はハウスループに意味のある形では入らないので、最終的な答えは単純です。$n!$これは、プレフィックス条件がトリガーされないという事実と一致します。 

すべての騎士が家に属し、$h = 1$、アルゴリズムは 1 つの挿入ステップのみを処理し、禁止境界を導入しません。 セット全体が 1 つの家であっても、制約にはすべての順列を排除しない完全なサフィックス一致条件が必要であり、計算では完全な階乗が正しく得られます。 

複数の小さなハウスが存在し、フリー ナイトの大きなギャップがある場合、組み合わせ挿入ステップにより、フリー ナイトが独立して処理されることが保証されます。 これらはプレフィックス合計には決して表示されないため、ハウスとプレフィックスの境界チェックの有効性には影響しません。
