 ## 解決策
 ## 問題の理解

 銀河は、2 つのメカニズムによって運動が起こる惑星のグラフです。 基本構造は、接続されたグラフを形成する一連の双方向ライトトレイン接続です。 各惑星はノードであり、各列車は無向エッジです。 これに加えて、いくつかの特殊な惑星にはワームホールが存在します。 すべてのワームホール惑星は完全なテレポート ネットワークで接続されています。つまり、どのワームホール惑星からでもテレポートを試みて、均一にランダムな「異なる」ワームホール惑星に着陸することができます。 このテレポートは、旅行全体で最大 1 回使用できます。 

課題は、選択した地点で 1 つのテレポートをオプションで使用できることを前提として、通過するライトトレインのエッジの予想数を最小限に抑えながら、惑星 1 から惑星 n まで移動することです。 テレポート自体は列車としてカウントされませんが、ワームホール ノード間で位置をランダムに変更する可能性があり、目的地までの残りの最短経路が増減する可能性があります。 

重要な量は、静的グラフの最短経路ではなく、決定論的なウォークに挿入された単一の確率的ジャンプに対する最適な期待値です。 

この制約では、最大 200,000 個のノードと最大 1,000,000 個のエッジが許可されます。 最短パスを繰り返し再計算したり、状態ごとの決定をシミュレートしたりするアプローチでは、時間がかかりすぎます。 すべてのペアの距離を保存することさえ不可能です。 

微妙な問題は、テレポートが決定論的な意味で直接「有益」ではないということです。 目的地に近づいたり遠ざかったりする可能性があるため、解決策は最悪の場合や最良の場合ではなく、期待に基づいて判断する必要があります。 

素朴だが間違った考えは、テレポートを無視して最短パスを計算するか、テレポートをすべてのワームホール ノードへのゼロコスト エッジとして扱うことです。 テレポートは確率的であり、ソース以外のワームホールに着陸する可能性があるため、これは失敗します。 

## アプローチ

 テレポーテーションがなければ、問題はノード 1 からすべてのノード、特にノード n への標準的な単一ソースの最短パスに帰着します。 エッジは重み付けされていないため、BFS では距離が O(n + m) で与えられます。 

テレポートが導入されると複雑さが現れます。 ワームホール ノード u にテレポートすると、ランダムなワームホール v ≠ u に置き換えられ、v から n まで最適に歩き続けます。 これは、テレポート後のコストが、最初のノードを除いた、一様にランダムなワームホール ノードから n までの予想される最短距離であることを意味します。 

これは、すべてのワームホール ノード u について、元のグラフの n までの距離を知る必要があることを示唆しています。 すべての距離 dist[x] がわかったら、ワームホール ノードの平均を計算できます。 ただし、最適な戦略は単に「すぐにテレポートする」ということではありません。 まず 1 から選択したワームホール u まで歩き、次にテレポートして続行します。 

したがって、構造は次のようになります。ワームホール u を選択し、dist[1][u] を支払い、その後、オプションでテレポートし、ランダムなワームホールから予想される残りのコストを支払います。 

重要な観察は、テレポート後、どこから来たかに関係なく、一様にランダムなワームホール ノードにいるため、予想される残りのコストはどのテレポート アクションでも同じ一定であるということです。 したがって、決定はテレポートするかどうかを選択することと、テレポートする場合は最適な侵入ワームホールを選択することになります。 

これにより、問題は 3 つの配列 (1 からの距離、n からの距離、および n までのワームホール距離に対する総期待値) の計算に変換されます。 

ブルート フォースでは、可能なテレポート エントリをすべて試行し、予想をシミュレートし、コストは O(k²) になります。 kが大きい場合にはそれは不可能です。 

代わりに、BFS を使用して dist1[x] と distn[x] を事前計算します。 次に、次のように計算します。 

テレポート後の予想距離は、元のノードを除くすべてのワームホール ノードの distn の平均に等しくなります。 これにより、エントリ ノードにわずかな依存関係が生じますが、ワームホール距離にわたるプレフィックスの合計で処理できます。 

次に、各ワームホール u を評価します。

コスト(u) = dist1[u] + 1 + Expected_after_teleport(u)

 +1 は、テレポート操作の数が列車の数とは無関係であることを説明していますが、移行ステップは概念的なものです。 列車の端だけが重要です。 

答えは、ダイレクト パス dist1[n] と bestcost(u) の間の最小値です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | BFS のみ (テレポート モデリングなし) | O(n + m) | O(n) | 不正解 |
 | テレポートごとの最短パスを再計算する | O(k(n + m)) | O(n) | 遅すぎる |
 | ワームホール上の BFS + プレフィックスの合計 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ライトトレイン グラフに対してノード 1 から BFS を実行し、すべてのノードの dist1[x] を計算します。 これにより、自宅からすべての惑星に到達するために必要な列車の端の最小数が得られます。 
2. ノード n から BFS を実行し、すべてのノードの distn[x] を計算します。 これにより、すべての惑星から職場までの残りの列車コストが最小になります。 
3. ワームホール ノードのリストを抽出し、それらすべての distn の合計を計算します。 これは「テレポート先のコスト質量」の合計を表します。 
4. 各ワームホール ノード u について、u でテレポートが使用された場合に予想される残りのコストを計算します。 これは、u 自体を除くすべてのワームホールの平均 distn であり、(total_sum - distn[u]) / (k - 1) として計算できます。 
5. 各ワームホール u について、候補の答えを dist1[u] + Expected_after_teleport(u) として計算します。 これは、スタートから U まで歩き、テレポートし、期待に応じて最適に継続することを表します。 
6. このようなすべての候補を直接ルート dist1[n] と比較し、テレポートをまったく使用しないことに対応し、最小値を取得します。 

### なぜ効果があるのか

 BFS 距離は、最適な決定論的な移動コストをエンコードします。 テレポートは最大 1 回のみ発生し、すべての履歴が削除されるため、テレポート後の状態は、入口ワームホールではなく、着陸ノードのみに依存します。 これにより、確率的プロセスがエンドポイントの固定分布に対する単一の期待に崩壊します。 プレフィックスサムの調整により、エントリ ノードの除外が正確に処理され、条件付きの期待値の正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(start, n, adj):
    dist = [-1] * (n + 1)
    q = deque([start])
    dist[start] = 0
    while q:
        v = q.popleft()
        for to in adj[v]:
            if dist[to] == -1:
                dist[to] = dist[v] + 1
                q.append(to)
    return dist

def main():
    n, m, k = map(int, input().split())
    wormholes = list(map(int, input().split()))

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        a, b = map(int, input().split())
        adj[a].append(b)
        adj[b].append(a)

    dist1 = bfs(1, n, adj)
    distn = bfs(n, n, adj)

    direct = dist1[n]

    total = 0
    for x in wormholes:
        total += distn[x]

    INF = 10**30
    ans = direct

    if k > 1:
        for u in wormholes:
            expected = (total - distn[u]) / (k - 1)
            cand = dist1[u] + expected
            if cand < ans:
                ans = cand

    # output as reduced fraction
    from fractions import Fraction
    ans_frac = Fraction(ans).limit_denominator()
    print(f"{ans_frac.numerator}/{ans_frac.denominator}")

if __name__ == "__main__":
    main()
```実装は 2 つの BFS 実行から始まり、基礎となるトレイン グラフの最短パス構造を完全に決定します。 ワームホール集約ステップでは、すべてのテレポート着陸点から目的地までの合計距離が計算され、すべての候補に対して再利用されます。 

ワームホール上のループは、テレポート システムへの可能な各エントリ ポイントを評価します。 主要な実装の詳細は、平均化から現在のワームホールを除外することです。これは、合計から distn[u] を減算し、k-1 で割ることによって処理されます。 

最終的な答えは有理数であるため、浮動小数点の精度の問題を避けるために Python の分数を使用して正規化されます。

```まず 1 からの最短距離を計算します。 

| ノード | 距離 1 |
 | --- | --- |
 | 1 | 0 |
 | 2 | 1 |
 | 3 | 1 |
 | 4 | 2 |
 | 5 | 3 |

 5から：

 | ノード | 距離 |
 | --- | --- |
 | 5 | 0 |
 | 4 | 1 |
 | 2 | 2 |
 | 3 | 2 |
 | 1 | 3 |

 直接ルートのコストは 3 です。 

ワームホールは 2、3、4 であるため、距離の合計は 2 + 2 + 1 = 5 となります。 

u = 2 の場合: テレポート後の予想値 = (5 - 2) / 2 = 1.5、合計 = dist1[2] + 1.5 = 2.5

 u = 3 の場合: 同じ = 1 + 1.5 = 2.5

 u = 4 の場合: 期待値 = (5 - 1) / 2 = 2、合計 = 2 + 2 = 4

 最小値は 2.5 です。 

これは、ノード 2 または 3 を介したテレポートが最適であり、3 から 5/2 への予想される削減をもたらすことを示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m + k) | グラフ上の 2 つの BFS トラバーサルと、ワームホール ノード上の 1 つの線形パス |
 | スペース | O(n + m) | 隣接リストと距離の配列 |

 この制約により、最大 2×10^5 のノードと 10^6 のエッジが許可されるため、BFS ベースの線形トラバーサルが唯一の実行可能なアプローチになります。 追加のワームホールの凝集は無視できる程度です。

import sys, io
from fractions import Fraction

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    from collections import deque

    def bfs(start, n, adj):
        dist = [-1] * (n + 1)
        q = deque([start])
        dist[start] = 0
        while q:
            v = q.popleft()
            for to in adj[v]:
                if dist[to] == -1:
                    dist[to] = dist[v] + 1
                    q.append(to)
        return dist

    n, m, k = map(int, input().split())
    wormholes = list(map(int, input().split()))

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        a, b = map(int, input().split())
        adj[a].append(b)
        adj[b].append(a)

    dist1 = bfs(1, n, adj)
    distn = bfs(n, n, adj)

    direct = dist1[n]
    total = sum(distn[x] for x in wormholes)

    ans = direct
    if k > 1:
        for u in wormholes:
            cand = dist1[u] + (total - distn[u]) / (k - 1)
            ans = min(ans, cand)

    ans_frac = Fraction(ans).limit_denominator()
    return f"{ans_frac.numerator}/{ans_frac.denominator}"

## 特殊なケース

 特殊なケースの 1 つは、ワームホールが 1 つだけ存在する場合です。 その場合、他の場所に着陸することができないため、テレポートは使用できません。 このアルゴリズムは、k = 1 の場合にテレポート ループをスキップし、直接の最短パスを返すことによってこれを処理します。 

別のエッジ ケースは、開始ノードまたは終了ノード自体がワームホールである場合に発生します。 ワームホールのステータスはトラバーサルに影響しないため、BFS 距離は有効なままです。 テレポート動作のみがメンバーシップに依存します。 期待される計算には、平均化にこれらのノードが正しく含まれています。 

最後の微妙なケースは、複数のワームホールが目的地までの距離が同じである場合です。 除外項 (total - distn[u])/(k-1) により、すべての distn 値が等しい場合でも、期待値がすべてのエントリ選択肢にわたって一貫したままとなり、特定のワームホールへの偏りを防ぐことができます。
