 ## 解決策
 ## 問題の理解

 標準的な DnD ダイスのコレクションを振ります。 入力により、d4、d6、d8、d12、および d20 のサイコロがいくつ含まれているかがわかります。 すべてのサイコロは公正であり、各面には 1 から面の数までの番号が付けられます。 

完全なロールごとに 1 つの合計が生成されます。 額面の多くの異なる組み合わせによって同じ合計が生成される可能性があるため、異なる合計が等しく発生する可能性は高くありません。 このタスクは、可能性のあるすべての合計を、最高確率から最低確率の順に出力することです。 2 つの合計の確率がまったく同じである場合、どちらの順序も受け入れられます。 

最大の入力には、各タイプのサイコロが 10 個、合計 50 個のサイコロが含まれます。 すべての結果を強引に列挙することは直ちに不可能です。 d20 サイコロを 10 個振っただけでも、すでに$20^{10}$実際の最大入力はそれよりもはるかに大きくなります。 アルゴリズムは、個々のロールを列挙することを回避する必要があります。 

有益な観察は、結果の数は膨大であるが、可能な合計の数は少ないということです。 すべてのサイコロは少なくとも 1 を寄与するため、最小可能合計はサイコロの数になります。最大可能合計は次のとおりです。$$40 + 60 + 80 + 120 + 200 = 500.$$存在できる異なる合計は 451 個だけであり、これは非常に小さいです。 これは、合計よりも動的計画法を強く示唆しています。 

簡単な間違いの 1 つは、確率が浮動小数点値を使用して比較できると想定していることです。 浮動小数点の丸めでは、確率が等しいか非常に近い合計を誤って交換する可能性があります。 例えば、```
1 0 0 0 0
```は、それぞれ同じ確率で合計 1、2、3、および 4 を生成します。 正しい出力では、これらを任意の順序でリストできますが、丸められた浮動小数点値に基づく比較は不要です。 すべての合計に到達する方法の数を数えることにより、この問題は完全に回避されます。 

もう 1 つの微妙なケースは、ダイスが 1 つだけ存在する場合です。```
0 0 0 0 1
```すべての顔は 1 回だけ出現するため、すべての合計の確率は同じになります。 1 ～ 20 の任意の順列が有効です。 常に一意の順序があると想定するソリューションでは、有効な出力が誤って拒否されてしまいます。 

最後のエッジケースは、多数のサイコロが存在する場合です。```
10 10 10 10 10
```可能な出目の数は天文学的に多いため、確率を保存したり結果を列挙したりすることは不可能です。 動的プログラミングでは、達成可能な各合計を取得する方法の数のみが保存され、その最大インデックスが 500 を超えることはありません。 

## アプローチ

 最も直接的な解決策は、考えられるすべてのロールを再帰的に生成し、その合計を計算し、各合計が何回出現するかをカウントします。 すべての結果が 1 回だけ検査されるため、これは正しいです。 残念ながら、その実行時間は結果の総数に等しく、最悪の場合は次のようになります。$$4^{10} \cdot 6^{10} \cdot 8^{10} \cdot 12^{10} \cdot 20^{10},$$コンピューターが処理できるものをはるかに超えています。 

この問題が依然として簡単である理由は、どの一連のロールが合計を生成するかを実際には気にしていないからです。 それぞれの合計を取得する方法の数だけが必要です。 最大で 451 の異なる合計があるため、サイコロを 1 つずつ追加しながら合計の分布を繰り返し更新できます。 

いくつかのサイコロを処理した後にそれぞれの合計が何通り発生するかをすでに知っているとします。 他の人が一緒に死ぬとき$k$辺が追加されると、既存のすべての合計が正確に寄与します$k$新しい金額。 その数をそれらの新しい合計に単純に分配します。 これはまさに分布の畳み込みですが、可能な合計が数百しかないため、単純な動的プログラミングの実装はすでに十分に高速です。 

すべてのサイコロが処理された後、すべての完全な結果の可能性は等しいため、各合計の方法の数は確率に比例します。 これらのカウントによって合計を並べ替えると、必要な順序が直接生成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(\prod s_i)$|$O(\text{number of sums})$| 遅すぎる |
 | 最適 |$O(D \times S \times 20)$|$O(S)$| 承認済み |

 ここ、$D \le 50$はサイコロの数であり、$S \le 500$可能な最大の合計です。 

## アルゴリズムのチュートリアル

 1. 各金型の番号を読み取ります。 
2. 入力を、サイコロごとに 1 つのエントリを含むリストに展開します。各エントリには、その面の数が格納されます。 たとえば、1 つの d4 と 2 つの d8 がリストになります。`[4, 8, 8]`。 
3. 動的プログラミング配列を作成します。`dp[x]`合計を求める方法の数です`x`これまでに加工したダイスを使用します。 最初は合計 0 のみが可能であるため、`dp[0] = 1`。 
4. サイコロを一度に 1 つずつ処理します。 ダイスごとに`k`側面、新しい配列を作成します`ndp`。 
5. 到達可能なすべての合計と 1 から 1 までのすべての額面に対して`k`、現在のウェイ数を対応する新しい合計に加算します。 既存の各結果は、額面ごとに 1 つの結果に拡張されます。 
6. 交換する`dp`と`ndp`すべてのダイが処理されるまで続けます。 
7. サイコロの数とその面の数から、達成可能な最小および最大の合計を計算します。 
8. 達成可能なすべての合計を降順に並べ替えます。`dp[sum]`。 2 つのカウントが等しい場合は、どのような相対順序も受け入れられるため、2 次キーは無関係です。 
9. 合計をソートされた順序で出力します。 

### なぜ効果があるのか

 サイコロの接頭辞を処理した後、動的プログラミング テーブルは個別のロールの数を正確にカウントし、可能なすべての合計を生成します。 サイコロを振らずに合計 0 のみが達成できるため、この不変式は最初は真です。 以前のすべてのロールは新しいサイコロのすべての面と独立して拡張され、結果として得られるロールはすべて 1 回だけカウントされるため、すべての更新で不変条件が保持されます。 すべてのサイコロが処理された後、`dp[s]`合計が次の結果の合計数に等しい`s`。 すべての完全なロールの可能性は等しいため、これらのカウントによる並べ替えは、確率による並べ替えとまったく同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t, c, o, d, i = map(int, input().split())

    dice = (
        [4] * t +
        [6] * c +
        [8] * o +
        [12] * d +
        [20] * i
    )

    max_sum = sum(dice)
    dp = [0] * (max_sum + 1)
    dp[0] = 1

    current_max = 0

    for sides in dice:
        ndp = [0] * (max_sum + 1)
        for s in range(current_max + 1):
            if dp[s] == 0:
                continue
            ways = dp[s]
            for face in range(1, sides + 1):
                ndp[s + face] += ways
        dp = ndp
        current_max += sides

    min_sum = len(dice)

    ans = list(range(min_sum, max_sum + 1))
    ans.sort(key=lambda x: dp[x], reverse=True)

    print(*ans)

if __name__ == "__main__":
    solve()
```この解決策は、圧縮された入力をダイごとに 1 つのリスト エントリに拡張することから始まります。 これにより、ダイの種類に関係なく、すべての更新が同一になります。 

動的計画法配列は常に、特定の数のサイコロを処理した後の分布を表します。 各遷移では前のステージからの値のみを使用する必要があるため、すべてのダイに新しい配列が割り当てられます。 配列を適切に更新すると、新しく作成された状態が誤って再利用され、多くの合計が過剰にカウントされてしまいます。`current_max`サイコロの処理後に到達可能な最大の合計を追跡します。 この値までのみ反復すると、未使用のエントリのスキャンが回避されます。 

Python の整数は任意の精度まで自動的に拡張されるため、最大のテストで考えられる膨大な数のロールであっても、オーバーフローすることなく適合します。 

最後に、達成可能な合計がその数によって並べ替えられます。 確率は結果の総数に等しい共通分母だけ異なるため、カウントを比較するだけで十分です。

この例は、畳み込みを繰り返すことで、よく知られた釣鐘型の分布がどのように自然に作成されるかを示しています。この分布では、中間和には極値和よりもはるかに多くの組み合わせがあります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(D \times S \times 20)$| すべてのサイコロは、最大 20 個の面を使用して、到達可能なすべての合計を更新します。 |
 | スペース |$O(S)$| 現在と次回の分布のみが保存されます。 |

 サイコロの数は最大 50 個で、可能な最大合計はわずか 500 個であるため、アルゴリズムは 100 万回未満の遷移操作を十分に実行します。 これは問題の制限を簡単に満たします。 

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    t, c, o, d, i = map(int, input().split())

    dice = [4] * t + [6] * c + [8] * o + [12] * d + [20] * i
    max_sum = sum(dice)

    dp = [0] * (max_sum + 1)
    dp[0] = 1
    cur = 0

    for sides in dice:
        ndp = [0] * (max_sum + 1)
        for s in range(cur + 1):
            if dp[s]:
                for f in range(1, sides + 1):
                    ndp[s + f] += dp[s]
        dp = ndp
        cur += sides

    mn = len(dice)
    ans = list(range(mn, max_sum + 1))
    ans.sort(key=lambda x: dp[x], reverse=True)
    return " ".join(map(str, ans))

 ## 特殊なケース

 インプットを考慮する```
1 0 0 0 0
```動的プログラミング テーブルは次で始まります。`dp[0] = 1`。 d4 を処理した後、合計 1 ～ 4 はそれぞれ 1 つの寄与を受け取ります。 すべてのカウントは同一であるため、すべての順序が有効です。 このアルゴリズムは、特別な処理を行わなくても、自然に等しい周波数を生成します。 

ここで考えてみましょう```
0 0 0 0 1
```d20は1つだけです。 すべての面が 1 回だけ寄与するため、20 の合計はすべてカウント 1 を受け取ります。頻度でソートすると、すべての合計が同順位のままになり、同順位が任意の順序で表示される仕様と一致します。 

最後に考えてみましょう```
10 10 10 10 10
```達成可能な最小の合計は 50 で、最大は 500 です。可能なロールの総数は想像を絶するほど大きくなりますが、動的プログラミング テーブルにはまだ 501 エントリしか含まれていません。 各ダイは、可能な合計ごとに最大 20 回の遷移を実行するため、実行時間は個々の結果の数ではなく、合計の範囲のみに依存します。
