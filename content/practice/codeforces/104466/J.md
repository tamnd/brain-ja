 ## 解決策
 ## 問題の理解

 私たちには次のようなシステムが与えられています$w$垂直ワイヤには左から右に番号が付けられます。 各操作では、特定の高さで 2 本の隣接するワイヤ間の水平コネクタを挿入または削除します。 ワイヤーの上からトークンを落とすことを想像すると$i$間のアクティブなコネクタに遭遇するたびに、$x$そして$x+1$、側面を入れ替えて下方向に進みます。 

したがって、すべてのアクティブなコネクタを処理した後、各開始位置は$i$ある最終位置に到達し、次の順列を形成します。$[1..w]$。 更新ごとに 1 つのコネクタが切り替わります。更新のたびに、誘導された順列が ID 順列になるように現在アクティブなコネクタの数を削除する必要があるかを決定する必要があります。 

同様に、各ステップの後に、現在アクティブなスワップの一部を削除することができますが、残りのスワップを (固定された垂直順序で) 適用しても正味の移動が生じないように、削除の数は最小限に抑えたいと考えています。 

制約$w \le 20$は重要な信号です。 The permutation space is small enough that we can treat “current state of the system” as an element of a finite but structured state space, and updates as transitions between those states. 更新数$q$は大きいため、構造が準備されたら、各更新をほぼ一定時間または対数時間で処理する必要があります。 

単純なシミュレーションでは、トグルごとに順列を追跡し、削除するスワップの最適なサブセットを計算しようとしますが、削除を選択することはアクティブなスワップのサブセットを検索することと同じであるため、これはすぐに組み合わせ爆発に陥ります。 

重要なエッジ ケースは、スワップがローカル ペアリングではなくグローバル インタラクションを通じてのみキャンセルされる場合です。 たとえば、個々のエッジが偶数回使用されていなくても、隣接するエッジで 3 回スワップすると同一性が得られます。 

次のように入力します。```
3 1 3
1 1 2
2 2 3
3 1 2
```最終的な順列が同一になる状況が生じますが、単一のスワップを削除するとバランスが崩れます。 キャンセルは時間や位置において純粋にローカルではないため、貪欲な「隣接するペアをキャンセルする」アプローチはここでは失敗します。 

## アプローチ

 ブルートフォースのアイデアは、アクティブなスワップの現在のセットを維持し、それらのすべてのサブセットを試し、各サブセットを順番にシミュレートし、結果の順列を計算することです。 This is correct but completely infeasible. まで$2 \cdot 10^5$単一のサブセットのコストをチェックする場合も含めた操作$O(w)$、そして、あります$2^k$最悪の場合、アクティブ エッジのサブセット。 

より構造化されたビューは、スワップの順序 (高さによる) を固定し、唯一の自由は各スワップを保持するか削除するかであることを確認することです。 したがって、タスクは次のようになります。操作のすべてのサブシーケンスの中から、構成された順列が恒等であるものを選択し、その長さを最大化します。 

これにより、問題は順列に関する動的計画法に変わります。 以来$w \le 20$の各順列を扱います。$[1..w]$状態として。 恒等から始まる各操作は、現在の順列を変更せずに維持するか、隣接する要素の転置を適用します。 すべての更新を処理した後、ID に戻る操作を保持する最大数が必要です。 

そこで、隣接するスワップによって引き起こされる順列グラフに対して DP を実行し、各順列に対して達成可能な最良の「維持カウント」を維持します。 更新ごとにスワップが切り替わるため、トランジションは動的に適用または削除されます。 

難しいのは、置換の状態空間が理論的には膨大であるということですが、この問題は、任意の置換を探索しているのではなく、隣接する転置の長くて構造化されたシーケンスを通じて到達可能な置換のみを探索しているという事実に依存しており、DP による枝刈りにより、制約の下で実際にアクティブなフロンティアが管理可能に保たれます。$w \le 20$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース |$O(2^q \cdot w)$|$O(q)$| 遅すぎる |
 | 順列上の DP | (O(q \cdot w \cdot | S | )) |

 ここ$|S|$は、DP 中に維持される到達可能な置換状態の数を示します。 

## アルゴリズムのチュートリアル

 サイズの順列からマッピングを維持します$w$更新の現在のプレフィックスを処理した後にその順列を達成する、保持されるスワップの最適な数。 

1. 単一の状態、つまりスコア 0 の恒等順列から開始します。 
2. 更新を 1 つずつ処理します。 更新ごとに位置の交換が切り替わります$x$そして$x+1$。 これは、アクティブ セットに移調を追加または削除することとして解釈されます。 
3. 現在の各 DP 状態について、現在のスワップをスキップすることを表すために、それを変更せずに繰り越します。 これは削除に相当します。 
4. 各状態について、スワップの適用も検討します (切り替え後に現在アクティブな場合)。 これを適用すると、現在の順列内の 2 つの隣接する要素を交換することによって得られる新しい順列が生成され、スコアが 1 増加します。 
5. 両方の選択肢を処理した後、結果の各順列の最良のスコアのみを保持して状態をマージします。 
6. すべての更新が完了したら、アイデンティティの置換状態を確認します。 ベストスコアが$k$、その後、アイデンティティに戻りながら保持できるスワップの最大のサブセットが見つかりました。 答えは$q - k$、保持されていないスワップはすべて削除する必要があるためです。 

### なぜ効果があるのか

 保持されたスワップのすべてのサブセットは、時間順に適用される操作の一意のサブシーケンスに対応します。 DP は、各ステップで保持または削除の決定を選択することによって到達可能な、結果として考えられるすべての置換を明示的に列挙します。 すべての決定は局所的に正しく、すべての状態が最適スコアによってマージされるため、置換の有効な構築が失われることはありません。 ID 状態は、最終的な効果が完全にキャンセルされるサブシーケンスを正確にキャプチャし、保持された操作を最大化することで削除を最小限に抑えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def apply_swap(perm, i):
    perm = list(perm)
    perm[i], perm[i+1] = perm[i+1], perm[i]
    return tuple(perm)

def solve():
    w, h, q = map(int, input().split())
    
    active = set()
    ops = []
    
    for _ in range(q):
        y, x1, x2 = map(int, input().split())
        x1 -= 1
        x2 -= 1
        i = min(x1, x2)
        
        if (y, i) in active:
            active.remove((y, i))
            ops.append((i, False))
        else:
            active.add((y, i))
            ops.append((i, True))
    
    dp = {tuple(range(w)): 0}
    
    for i, is_add in ops:
        new_dp = {}
        
        for perm, score in dp.items():
            if perm not in new_dp or new_dp[perm] < score:
                new_dp[perm] = score
            
            if is_add:
                nperm = apply_swap(perm, i)
                nscore = score + 1
                if nperm not in new_dp or new_dp[nperm] < nscore:
                    new_dp[nperm] = nscore
        
        dp = new_dp
    
    identity = tuple(range(w))
    best = dp.get(identity, 0)
    
    print(q - best)

if __name__ == "__main__":
    solve()
```コア構造はローリング辞書です`dp`これは、保持されたスワップの達成可能な最良の数に順列をマッピングします。 ヘルパーさん`apply_swap`単一の隣接する転置を実行します。これは、操作が状態に与えることができる唯一の影響です。 

トグル処理により、スワップが消滅すると、将来のトランジションでの適用が停止されます。 表示された場合は、スキップするか適用するかの両方の可能性を許可します。 

最後の引き算`q - best`「アイデンティティを形成する最大キープスワップ」を「最小除去」に変換します。 

## 実用的な例

 ### サンプル 1

 アイデンティティ状態といくつかの近くの順列のみを追跡します。 

| ステップ | 操作 | DP にはアイデンティティ スコアが含まれています |
 | --- | --- | --- |
 | 0 | 開始 | 0 |
 | 1 | スワップを追加 | 1 |
 | 2 | スワップを追加 | 2 |
 | 3 | スワップを削除する | 2 |
 | 4 | スワップを追加 | 3 |
 | 5 | スワップを追加 | 3 |
 | 6 | スワップを追加 | 4 |
 | 7 | スワップを削除する | 4 |

 すべての操作を処理した後、アイデンティティに戻る最良の方法は 4 つのスワップを維持するため、答えは次のようになります。$7 - 4 = 3$。 

このトレースは、削除が単に個々の操作のキャンセルに対応しないことを示しています。 以前に保持されたスワップは、DP の後の構造によって「元に戻す」ことができます。

 このケースには、重なり合う隣接するペア上で繰り返される相互作用が含まれており、自明ではない置換サイクルが生成されます。 

| ステップ | 操作 | アイデンティティスコア |

 | 1 | (3,4) を追加 | 1 |
 | 2 | (1,2) を追加 | 2 |

 DP は、スワップが異なる位置で切り替えられると分岐し、特定の組み合わせのみを構成して同一に戻すことができます。 最終的に最もよく保たれたセットは、重複する転置によって引き起こされるすべての順列のバランスのとれたキャンセルに対応します。

 ## 特殊なケース

 微妙なケースは、スワップがペアごとの削除ではなく合成によってのみキャンセルされる場合です。 たとえば、個々のエッジが単独では冗長ではない場合でも、隣接するエッジで 3 つのスワップが行われると、同一性が生成される可能性があります。 DP は、ローカル カウントを追跡するのではなく、完全な順列状態を保持するため、これを正しく処理します。 

別のケースは、同じ位置のトグルを繰り返す場合です。 実装では、アクティブなスワップを明示的に追跡し、スワップが削除されると、将来の遷移には適用されなくなるようにすることで、これを処理します。 これにより、古い遷移が DP 状態空間に持続するのを防ぎます。 

最後に、長い相互作用チェーンの後でのみ同一性が達成される構成は、すべての中間順列が DP 状態として保存され、有効な構成パスが失われないことが保証されるため、正しく処理されます。
