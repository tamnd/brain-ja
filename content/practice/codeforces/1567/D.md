 ## 解決策
 ## 問題の理解

 ボブが、合計が固定されている一連の正の整数を書き留める状況が与えられます。 彼が持つ唯一の自由は、この合計額を正確に分割する方法です。`n`部品。 次に、アリスはこれらの数値をそれぞれ読み取りますが、10 進数で解釈する代わりに、11 進数で解釈して合計します。 

重要な点は、ボブの制約は純粋に 10 進法で加法的であるのに対し、アリスの評価も加法的ですが、数値体系の変更後であるということです。 基数変換により桁位置の数値が変更されるため、ボブは特定の 10 進表現の数値を選択することで、基数 11 の上位桁の値を「隠す」ことができます。 

出力は、次の有効な分解です。`s`の中へ`n`11 進解釈の合計を最大化する正の整数。 

制約は十分に厳しいため、テスト ケースごとに O(n) または O(n log s) の構築が必要です。 以来`n ≤ 100`そして`t ≤ 100`、O(t・n) の解法であっても自明ですが、パーティションを列挙したり、数値ごとに数字の割り当てをシミュレートしようとすると、次の条件に依存する場合は遅すぎます。`s`直接検索するか、構成の検索を試みます。 

すべての数値が小さい場合、微妙なエッジケースが発生します。 ボブが別れたら`s`多くの 1 にすると、アリスはすべての位置にわたって最大の桁キャリー効果を得ます。`1`基数 11 で独立して寄与します。基数 11 の桁上げ構造を考慮せずに、基数 10 の個々の数値を最大化しようとする素朴な貪欲性は、次のような場合には失敗します。`10 9`ここで、均等に分散することは、値を集中することよりも優れています。 

別の失敗例は、1 つの数値が非常に大きくなった場合に発生します。 例えば、`100 2`次のような貪欲な分割を誘惑するかもしれません`99 1`, しかし、これにより基数 11 の寄与する項の数が減り、桁の広がりが失われます。 

## アプローチ

 ブルートフォースアプローチでは、分割するためのあらゆる方法が列挙されます。`s`の中へ`n`正の整数。 そのような構成の数は`C(s-1, n-1)`、これは中程度の場合でも天文学的に大きくなります。`s`。 ステップごとの小さな分岐選択肢に制限しても、分割された各決定が後の構造に影響を与えるため、依然として指数関数的な爆発につながります。 

重要な観察は、アリスの評価が基数 11 の数字に対して線形であるため、各数字が桁の位置ごとに独立して寄与することです。 基数 11 で数値を書くと、基数 10 の制約のキャリーインが基数 11 の表現とあまり相互作用しないことがわかります。9 より大きい数字は異なる動作をし、数値を分割すると独立した桁拡張の数が増加し、11 のべき乗が大きくなります。 

重要な洞察は、できるだけ多くの数値を小さな値に等しくすると、下位 11 進数に寄与する項の数が増加し、質量を集中させるよりも効果的に集約できるということです。 同時に、すべての数値がプラスのままであることを確認する必要があります。 

最適な構造は非常に単純であることがわかります。1 の数を最大化し、残りの合計を 1 つの追加の数値に集中させます。 これにより、定数に寄与する 11 進数の項の数が最大化されます。`1`、合計額を維持しながら。 

問題は構築に帰着します`n-1`1 を取り出し、残りを最後の位置に置きます。

 ## アルゴリズムのチュートリアル

 1. 可能な最小値を割り当てることから始めます`1`に`n-1`数字。 これにより、すべての数値が正になることが保証され、アリスの合計における個別の貢献者の数が最大化されます。 
2. 残りの値を次のように計算します。`s - (n - 1)`。 この残りにより、総和制約が正確に満たされることが保証されます。 
3. この余りをシーケンスの最後の数値に割り当てます。 これにより、過剰な質量を 1 つの項に集中させながら有効性が維持されます。 
4. 作成したリストを出力します。 

この構造の背後にある理由は、より多くの数値に分割すると、最終的な合計に寄与する独立した基数 11 の拡張の数が増加するためです。 各正の整数は少なくとも寄与するため、`1`基数 11 で、値を持つ項の数を最大化します。`1`残りの部分の柔軟性を維持しながら、アリスの総貢献ベースラインを最大化します。 

### なぜ効果があるのか

 不変条件は、すべてのステップで有効なパーティションを維持することです。`s`11 進数の最下位桁の非ゼロ寄与の数を最大化します。 追加の各数値は少なくとも寄与します`1`アリスの合計を計算し、それより大きい値を分割します。`1`2 つの正の整数に変換すると、合計を減らすことなく、独立した単位に寄与する基数 11 の表現の数が厳密に増加します。 したがって、1 の数をグローバルに最大化しながら質量を 1 つの剰余項に押し込むと、基数 11 での桁方向の展開合計が最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s, n = map(int, input().split())
        
        # n-1 ones
        res = [1] * (n - 1)
        
        # last element absorbs remainder
        res.append(s - (n - 1))
        
        print(*res)

if __name__ == "__main__":
    solve()
```この構造は、1 つの数値を除くすべての数値を最小化する必要があるという貪欲なアイデアを直接エンコードしています。 最後の数値は残りの合計を吸収し、パーティションの正確性を保証します。 

実装では常に正確に減算するように注意しています。`n-1`から`s`これにより、数値がゼロになることはなくなります。 制約が保証されているため、`n ≤ s`、残りは常に少なくとも`1`。

 ## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(sys.stdin.readline())
    out = []
    for _ in range(t):
        s, n = map(int, sys.stdin.readline().split())
        res = [1] * (n - 1) + [s - (n - 1)]
        out.append(" ".join(map(str, res)))
    return "\n".join(out)

 ## 特殊なケース

 いつ`n = 1`、アルゴリズムは以下に等しい単一の数値を生成します。`s`。 建設`[1] * 0 + [s]`自然に崩壊する`[s]`、特別な処理を行わずに正確さを維持します。 

いつ`n = s`、すべての数字は次のようになります`1`。 残りは`1`したがって、出力は次のようになります`n`もの。 これは最も制限された分割であり、最大用語数を通じてアリスの合計が最大化されることが保証されます。 

いつ`s`大きくて、`n`が小さい場合、残りは単一の位置を占めます。 この構造により、他のすべての位置が最小限の基数 11 単位に寄与することが保証され、構造が最適に保たれます。
