 ## 解決策
 ## 問題の理解

 火星時間を表す文字列が「a:b」形式で与えられます。`a`は時間の要素であり、`b`微量成分です。 10 進数の地球時間とは異なり、これらの文字列は 1 より大きい基数を持つ任意の記数系の数値を表すことができます。私たちのタスクは、指定された文字列が有効な地球時間を表すことができるすべての基数を特定することです。 有効な時間とは、次の数値を意味します。`a`は 0 ～ 23 の数値であり、`b`0 ～ 59 の範囲です。 

入力文字列は、数字「0」～「9」と大文字「A」～「Z」で構成されます。 各文字は標準の位置表記に従って数字を表します。数字 0 ～ 9 は整数値にマップされ、文字 A ～ Z は 10 ～ 35 にマップされます。 文字列の先頭にゼロを付けることができますが、数値には影響しません。 長さ`a`そして`b`は最大 5 文字まで指定できます。これは、大きな基数で解釈すると、表現できる最大の数値がかなり大きくなる可能性があることを意味しますが、値を有効な時間と分の範囲内に保つ基数のみを考慮する必要があります。 

考慮すべきエッジ ケースには、最大の桁が 10 より大きい最小の有効な基数を決定する文字列が含まれます。たとえば、「1A:2」には少なくとも 11 の基数が必要です。それ以外の場合、「A」は有効な桁ではありません。 文字列が "00:01" などの場合、別のエッジ ケースが発生します。すべての桁が十分に小さいため、無限に多くの数値体系が機能する可能性があります。 このような状況では、小さな塩基のみをチェックする単純なアプローチでは、有効な塩基がないと誤って報告される可能性があります。 

## アプローチ

 ブルートフォースアプローチは変換を試みます`a`そして`b`2 から始まるすべての基数の整数に変換します。 各塩基について、両方の数値が有効な範囲内にあるかどうかを確認します。 考えられるすべての有効な基数は 1 より大きい整数であり、文字列の長さは有限であるため、これは原理的には正しいです。 ただし、このアプローチは素朴に実装すると非効率になる可能性があります。最大の桁が小さく文字列の値が小さい場合、理論的には考慮すべき最大基数に制限がなく、多数の不必要なチェックが発生する可能性があるためです。 

最適なソリューションを実現するための重要な洞察は、文字列内の最大の桁が可能な基数に厳密な下限を課すことを認識することです。 の最大の桁の場合、`a`は`max_a`そしてで`b`は`max_b`、考慮すべき最小のベースは次のとおりです。`max(max_a, max_b) + 1`。 これより小さい基数があると、少なくとも 1 文字が無効になります。 さらに、変換された数値が時間で 23 を超えるか、分で 59 を超えると、塩基のチェックを停止できます。これは、塩基が大きくなると値が増加するだけであるためです。 最小基数で時間の値が最大 23、分の値が最大 59 である場合、より大きな基数でもこれらの制約を満たすため、無限に多くの解が得られます。 それ以外の場合は、2 つの値のうち大きい方がそれぞれの境界を超えるベースまでをチェックするだけで済みます。 

このアプローチにより、チェックするベースの範囲が無制限の範囲から、時間と分の制約によって決定される小さな有限セットに減り、ソリューションが効率的で実装が簡単になります。

 ## アルゴリズムのチュートリアル

 1. 入力文字列をコロンで分割して時間を区切ります (`a`) と分 (`b`）。 
2. '0' ～ '9' を 0 ～ 9 にマッピングし、'A' ～ 'Z' を 10 ～ 35 にマッピングして、文字を整数値に変換するヘルパー関数を定義します。 
3. の最大の桁を特定します。`a`そしてで`b`。 考慮する必要がある最小基数は、これら 2 桁の最大値より 1 大きい値です。これより小さい数値体系では文字列を正しく表現できないためです。 
4. 最小基数が 60 より大きい場合、有効な基数は存在しません。これは、可能な最小基数であっても、`b`59 を超える場合があります。0 を出力して終了します。 
5. 最小基数から 60 までの基数については、変換します。`a`そして`b`その底の整数に変換します。 結果の値が時間と分の制約 (0 ≤ 時間 ≤ 23、0 ≤ 分 ≤ 59) を満たしているかどうかを確認します。 有効な塩基を記録します。 
6. 最小の基数がすでに時と分の制限内の数値を生成している場合、より大きな基数もすべて有効になり、無限に多くの解が得られます。 -1 を出力して終了します。 
7. 有効な塩基のリストが空の場合は、0 を出力します。そうでない場合は、塩基を昇順に出力します。 

これが機能する理由は、文字列から整数への変換が基数に関して単調増加しているためです。 変換された値がその境界を超えると、常に境界内に収まる非常に小さな文字列の場合を除いて、より大きな基数は制約を満たすことができません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def char_to_val(c):
    if '0' <= c <= '9':
        return ord(c) - ord('0')
    return ord(c) - ord('A') + 10

def str_to_int(s, base):
    val = 0
    for c in s:
        val = val * base + char_to_val(c)
    return val

time_str = input().strip()
a_str, b_str = time_str.split(':')

max_digit_a = max(char_to_val(c) for c in a_str)
max_digit_b = max(char_to_val(c) for c in b_str)
min_base = max(max_digit_a, max_digit_b) + 1

if min_base > 60:
    print(0)
    sys.exit()

hours = str_to_int(a_str, min_base)
minutes = str_to_int(b_str, min_base)

if hours <= 23 and minutes <= 59:
    print(-1)
else:
    valid_bases = []
    for base in range(min_base, 61):
        h_val = str_to_int(a_str, base)
        m_val = str_to_int(b_str, base)
        if h_val <= 23 and m_val <= 59:
            valid_bases.append(base)
    if not valid_bases:
        print(0)
    else:
        print(" ".join(map(str, valid_bases)))
```最初の部分では、文字を数値に変換し、最小の基数を見つけます。 2 番目の部分では、最小ベースがすでに有効な時間値を生成しているかどうかをチェックします。これは、無限に多くのベースが機能することを意味します。 それ以外の場合は、時間は 23 を超えることができず、分は 59 を超えることができないため、可能な基数を 60 まで反復します。各変換は文字列の長さにおいて線形ですが、長さは最大 5 であるため、これは高速です。
