 ## 解決策
 ## 問題の理解

 声明内の図は、パスとブロックされた領域の再帰的な三角形の配置を説明しています。 黒いセグメントは平面グラフを形成し、灰色の三角形は立ち入り禁止の森林エリアを表します。 Peter は、家から出発して、このグラフの端に沿って歩き、開始点に戻って、単純なサイクルを生成したいと考えています。 サイクルは自己交差してはならず、灰色の領域を囲んでもなりません。 

入力には単一の偶数整数が含まれています`n`、構造内のレベルの数を表します。 タスクは、すべての有効な指向性サイクルを剰余としてカウントすることです。`1000000009`。 

重要な問題は、グラフのサイズが時間とともに直線的に増大することです。`n`ただし、可能なサイクルの数は指数関数的に増加します。 以来`n`到達できる`10^6`、二次関数はすでに不可能です。 たとえ`O(n log n)`解は受け入れられますが、意図した解は実際には行列のべき乗を伴う線形または対数です。 

ジオメトリは実際の組み合わせ構造を隠します。 有効なルートは禁止された三角形を囲むことができないため、すべてのサイクルは、許可された小さな領域の接続されたコレクションの境界のように動作します。 これが再帰的なカウント プロセスに変換されると、問題は動的プログラミングの反復になります。 

危険なエッジケースは、最小の入力ですぐに現れます。 

のために`n = 2`、答えは次のとおりです。```
10
```方向性のないサイクルのみをカウントする不注意な実装では、次の出力が出力されます。`5`なぜなら、すべてのサイクルは時計回りまたは反時計回りに移動できるからです。 

もう 1 つの微妙な問題は、自己接触構造を過剰にカウントすることです。 単純さを強制せずにパスを再帰的に生成しようとするとします。 頂点を共有する 2 つのサブサイクルは、ルート自体が交差しているにもかかわらず、誤って有効なより大きなサイクルとして扱われる可能性があります。 繰り返しでは、1 つの単純な境界に対応する構成のみをカウントする必要があります。 

大きな値もバグの原因となります。 のために`n = 10^6`の場合、答えは天文学的に大きいため、すべての算術演算で係数を即座に適用する必要があります。 Python の整数はオーバーフローしませんが、モジュロ演算が遅れるとプログラムが不必要に遅くなります。 

## アプローチ

 強引な解釈では、平面グラフを明示的に構築し、家から始まるすべての単純なサイクルを列挙します。 中程度のサイズではこれはすでに絶望的です。 サイクル数は指数関数的に増加するため、サイクルが禁止領域を囲んでいるかどうかを検出するには、追加の幾何学的チェックが必要です。 たとえグラフが`O(n)`頂点では、単純なサイクルの数は指数関数的になります。`n`。 

この構造は、その構造がいかに強力な再帰的であるかに気づいた後でのみ管理可能になります。 

有効なサイクルは、カタロニア語スタイルの分解と同様に動作します。 サイクルが分岐レベルに達すると、その継続はより小さな独立したサブ問題に強制的に入れられます。 ジオメトリにより任意の交差が防止されるため、すべての有効なルートをより小さい有効なルートの組み合わせに一意に分解できます。 

いくつかの小さな値を処理した後、シーケンスは線形再帰を満たします。$f_n = 4f_{n-2} - f_{n-4}$基本値を使用すると:$f_0 = 1,\quad f_2 = 10$偶数のインデックスのみが存在するため、次のように定義すると便利です。$g_k = f_{2k}$すると、再発は次のようになります。$g_k = 4g_{k-1} - g_{k-2}$これは次数 2 の標準的な線形反復です。 以来`n`と同じくらい大きいです`10^6`、単純な線形 DP はすでに快適に通過します。 行列のべき乗も機能しますが、再帰処理は十分に単純であるため、反復 DP の方がクリーンです。

 ## アルゴリズムのチュートリアル

 1. 構造内に偶数レベルのみが存在することに注意して、圧縮シーケンスを定義します。`g[k] = answer for n = 2k`。 
2. 有効なサイクルの再帰構造から再帰関係を導き出します。 

レベルのすべての有効なサイクル`k`レベルで有効なサイクルから延長できます`k-1`4 つの異なる構造方法で。 一部の構成は 2 回カウントされます。これは、重複する分解によって同じ境界が作成され、減算項が生成されるためです。 

結果の再発は次のようになります。$g_k = 4g_{k-1} - g_{k-2}$3. 基本ケースを初期化します。 

空の構造体の場合:```
g[0] = 1
```最小の自明ではない構造の場合:```
g[1] = 10
```4. 反復処理`2`まで`n / 2`。 

各ステップで次を計算します。```
g[i] = (4 * g[i-1] - g[i-2]) mod MOD
```係数を適用する前に減算が負になる可能性があるため、加算します。`MOD`服用する前に`% MOD`。 
5. 出力`g[n / 2]`。 

### なぜ効果があるのか

 再帰は、三角形構造の 1 つの追加層によって有効な単純なサイクルを拡張するためのすべての可能な方法を捕捉します。 

用語`4g[k-1]`前のレベルからのすべての拡張子をカウントします。 一部の大きなサイクルでは、2 つの異なる分解をより小さな部分に許可するため、過剰カウントが発生します。 それらの重複した構成は、正確に、によって数えられる構造です。`g[k-2]`, したがって、それらを減算すると、1 対 1 の対応が復元されます。 

すべての有効なサイクルは、包含と除外の後に残る 1 つのクラスに正確に属するため、繰り返しではすべてのルートが 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000009

def solve():
    n = int(input())
    
    k = n // 2
    
    if k == 0:
        print(1)
        return
    
    if k == 1:
        print(10)
        return
    
    prev2 = 1
    prev1 = 10
    
    for _ in range(2, k + 1):
        cur = (4 * prev1 - prev2) % MOD
        prev2 = prev1
        prev1 = cur
    
    print(prev1)

solve()
```実装は繰り返しの後に直接続きます。 

変数`k`の偶数値から問題を圧縮します。`n`連続したインデックスに変換します。 これにより、コード全体で不必要な 2 の因数のオフセットを運ぶことがなくなります。`prev2`店舗`g[i-2]`そして`prev1`店舗`g[i-1]`。 繰り返しは前の 2 つの状態のみに依存するため、DP 配列全体を割り当てる理由はありません。 これにより、メモリ使用量が一定のスペースに削減されます。 

減算ステップは、一部の言語では通知なく失敗する可能性がある主要な実装の詳細です。 Pythonでは、`% MOD`すでに非負の結果が生成されているため、次のようになります。```
(4 * prev1 - prev2) % MOD
```直接的には安全です。 

再帰は非常に急速に増大するため、正確さとパフォーマンスの両方のために、反復ごとにモジュロを適用することが必要です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各レベルに 1 つの繰り返し遷移 |
 | スペース | お(1) | 以前の 2 つの状態のみが保存されます。 

以来`n ≤ 10^6`、ループは最大で実行されます`500000`繰り返し。 これは Python の制限時間内に簡単に収まります。 一定のメモリ使用量も制限を快適に下回っています。
