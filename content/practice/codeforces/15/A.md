 ## 解決策
 ## 問題の理解

 すべての家が _x_ 軸に沿って並んでいる村の 1 次元の地図が与えられました。 各家は正方形で、中心座標と辺の長さによって指定されます。 2 つの家が重なり合うことはありませんが、端に触れることはできます。 このタスクは、辺の長さが _t_ の新しい正方形の家を、その中心が _x_ 軸上にあり、少なくとも 1 つの既存の家に接し、既存の家に重ならないように配置できる個別の位置の数を数えるというものです。 

入力は、既存の住宅の数 _n_、新しい住宅の辺の長さ _t_、および各住宅の中心座標と辺の長さを表す _n_ 組の整数で構成されます。 出力は単一の整数、つまり新しい家の有効な位置の数です。 

_n_ と _t_ が最大 1000 までの制約は十分小さいため、O(n log n) または O(n²) アルゴリズムが実行可能です。 すべての可能なポジションに対して O(n³) の総当りアプローチを行う余裕はありませんが、パフォーマンスを心配することなく、すべてのハウスのペア間の相互作用を考慮することはできます。 エッジケースには、すべての家が大きくて接しており、有効な配置オプションが端に 2 つだけ残っている場合や、新しい家が 2 つの既存の家の間にぴったりと収まる場合などのシナリオが含まれます。 

たとえば、x=0 に辺 4 の家が 1 つだけあり、新しい家が辺 2 にある場合、左端または右端のいずれかに接触することができ、x=-3 と x=3 にちょうど 2 つの有効な位置が与えられます。 タッチを無視する単純なアプローチでは、_t_ より大きいギャップのみがカウントされ、誤ってゼロが返されてしまいます。 

## アプローチ

 強引なアプローチは、線に沿って考えられるすべての _x_ 座標をチェックし、既存の家と重なり合ったり、少なくとも 1 つに触れたりすることなく、辺 _t_ の正方形をそこに配置できるかどうかを確認することです。 これは正しいですが、座標を実数として扱うと位置の数が非常に多くなる可能性があるため、現実的ではありません。 各ポイントをチェックするのは不必要かつ非効率的です。 

重要な観察事項は、新しい家は既存の家に触れなければならないということです。 家は軸に沿って配置された正方形であるため、可能な位置は各家のすぐ左または右だけです。 具体的には、既存住宅の辺が_a_、中心が_x_の場合、左端が_x - a/2_、右端が_x + a/2_にあります。 _t_ 側の新しい家は、この家の左端または右端のどちらかに触れることができます。 左側に配置すると、新しい家の右端が既存の家の左端と一致し、中心が _(x - a/2) - t/2_ になることを意味します。 右に配置すると、中心は _(x + a/2) + t/2_ になります。 これにより、既存の家ごとに最大 2 つの候補地が生成されます。 

これらの候補が見つかったら、既存の住宅と重複するものがないことを確認する必要があります。 これにより、問題は最大 2n 個の候補位置を反復処理し、それぞれを n 個のハウスすべてと照合することになります。これは O(n²) アルゴリズムであり、n ≤ 1000 で実現可能です。この洞察により、問題は無限の検索空間から正確な候補の有限セットに変換され、管理しやすく実装が簡単になります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(範囲 × n) | お(1) | 遅すぎる |

 ## アルゴリズムのチュートリアル

1. 既存のすべての家の左端と右端を計算します。 中心が x で辺が a の家の場合、左 = x - a/2、右 = x + a/2 となります。 これにより、接触位置を確認するために必要な正確な境界が得られます。 
2. 各家について、新しい家の 2 つの候補位置を生成します。1 つは左端に触れ、もう 1 つは右端に触れます。 既存の家の左端に接する新しい家の中心は _left - t/2_、右端の中心は _right + t/2_ です。 
3. 候補センターのセットまたはリストを維持します。 セットを使用すると、複数の家が同じ位置を生成する場合、重複が自動的に削除されます。 
4. 候補中心ごとに、それが占める間隔を計算します: [中心 - t/2、中心 + t/2]。 この間隔をすべての既存住宅と比較して確認してください。 重複しない場合はそのままにしておきます。 それ以外の場合は破棄します。 
5. セット内に残っている有効な中心候補の数を数えます。 これが答えです。 

機能する理由: 既存の家の端でのみ候補を生成するため、各候補は少なくとも 1 つの家に触れることが保証されます。 重なりをチェックすることで、2 つの家が交差していないことが保証されます。 既存のどの家にも接していない家は問題の制約を満たさず、他の場所に配置された家は重なっているか、候補エッジの 1 つによってすでに表されているため、他に可能な位置はありません。 したがって、アルゴリズムはすべての有効な位置を 1 回だけ見つけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, t = map(int, input().split())
houses = []

for _ in range(n):
    x, a = map(int, input().split())
    left = x - a / 2
    right = x + a / 2
    houses.append((left, right))

candidates = set()

for left, right in houses:
    candidates.add(left - t / 2)
    candidates.add(right + t / 2)

valid_positions = 0

for center in candidates:
    new_left = center - t / 2
    new_right = center + t / 2
    overlap = False
    for h_left, h_right in houses:
        if not (new_right <= h_left or new_left >= h_right):
            overlap = True
            break
    if not overlap:
        valid_positions += 1

print(valid_positions)
```最初の部分は入力を読み取り、各ハウスを左右の間隔に変換します。 候補位置はこれらの間隔から直接導出され、正確なエッジベースの位置のみが必要なため、浮動小数点の丸めの問題が回避されます。 各候補者をすべての議院と照合することで、重複がないことが保証されます。 セットを使用すると、同じポジションが二重にカウントされなくなります。 

## 実用的な例

 ### サンプル 1

 入力:```
2 2
0 4
6 2
```エッジの計算: house1 [-2, 2]、house2 [5, 7]

 候補センター: -2-1=-3、2+1=3、5-1=4、7+1=8 → {-3, 3, 4, 8}

 重複を確認します。 

-3: 間隔 [-4, -2]、重複なし → 有効

 3: 間隔 [2, 4]、重複なし → 有効

 4: 区間 [3, 5]、house2 [5,7] と重複しますか? 3-5は5で終了、タッチ可→有効

 8: 間隔 [7, 9]、重複なし → 有効

 出力: 4

 このトレースは、単一点でのタッチが有効としてカウントされていることを示しており、エッジの状態が確認されています。 

### カスタム例

 入力:```
1 2
0 4
```エッジ: [-2、2]

 候補センター: -2-1=-3, 2+1=3 → {-3, 3}

 重複を確認します。 

-3: [-4, -2] 重複なし → 有効

 3: [2,4] 重複なし → 有効

 出力: 2

 これにより、アルゴリズムが最小限の入力ケースを正しく処理することが検証されます。
