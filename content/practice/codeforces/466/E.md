 ## 解決策
 ## 問題の理解

 当社には、時間の経過とともに徐々に構築される社内階層があります。 

最初は誰も上司がいません。 タイプ 1 の操作は従業員をアタッチします`x`従業員の下`y`、作る`y`の上司`x`。 入力により次のことが保証されます。`x`現在ボスは存在せず、サイクルも出現しません。 

タイプ 2 の操作では、ドキュメント パケットが作成されます。 パケットは従業員から始まります`x`、によって署名されます`x`、その後、`x`の上司、次にその上司の上司という順に階層のルートに到達するまで続きます。 

タイプ 3 の操作では、パケット番号に関する歴史的な質問が行われます。`i`、従業員でした`x`署名しますか？ 

難しいのは、階層が時間の経過とともに変化することです。 パケットに関するお問い合わせ`i`パケットを送信したときに存在した階層を使用する必要があります`i`クエリ時の階層ではなく、作成されました。 

階層は増えるばかりです。 すべてのノードは最大でも 1 つの親を受け取り、一度接続されると親を変更することはありません。 自転車は禁止されているので、最終的な構造物は森になります。 

制約は大きいです。 従業員数と業務量の両方が達成可能`10^5`。 チェーン内を上方に移動するすべてのパケットのブルート フォース シミュレーションでは、毎回ほぼ階層全体を走査する必要がある場合があります。 最悪の場合、長さのチェーンが発生する可能性があります`10^5`そして`10^5`パケット イベント、おおよその生成`10^10`全く不可能な操作です。 

課題は、歴史的な祖先のクエリに効率的に答えることです。 

微妙なエッジ ケースとして、従業員がパケットの作成後にのみ祖先になる可能性があるということがあります。

## アプローチ

 最も直接的なアプローチは、操作を時系列に処理し、すべてのパケットを明示的にシミュレートすることです。 パケット時`i`従業員から始まります`x`、繰り返し上司に移動し、すべての署名者を記録します。 後のクエリでは、特定の従業員がそのパケットに記録されているかどうかを確認できます。 

これはパケットのルートを正確にたどるので、これは正しいです。 問題はコストです。 パケットは一定の長さのチェーンを通過する可能性があります`O(n)`。 まで`10^5`パケットの合計作業量は次のようになります。`O(nm)`、 その周り`10^10`操作。 

重要な観察は、パケットが従業員によって作成されたことです。`v`の先祖によって正確に署名されています`v`その時点で存在する階層内で。 

したがって、すべてのクエリは次のことを尋ねます。 

「社員でした`x`パケットソースの祖先`v`当時のパケット`i`作られたの？」

 階層はエッジのみを獲得します。 誰も親を変えることはありません。 つまり、最初にすべての操作を読み取り、最終フォレストを構築し、その最終フォレストで DFS を実行できます。 

なぜ最後の森が役立つのでしょうか？ なぜなら、これまでに存在した先祖関係は永遠に先祖関係であり続けるからです。 もし`x`の先祖でした`v`パケット時`i`が作成され、その後`x`の先祖でもあります`v`最後の森で。 

唯一欠けているのは時間です。 パケットの作成時にその祖先関係がすでに存在していたかどうかを判断する必要があります。 

パケットを仮定します`i`頂点から開始`v`。 させて`r`の根になる`v`その時点での の接続コンポーネント。 それから従業員`x`次の場合に限り、パケットに署名します。 

1.`x`の先祖です`v`最後の森で。 
2. パケット作成時に、`x`そして`v`すでに同じ接続コンポーネントに属しています。 

2 番目の条件は、DSU を使用して操作を時系列に再生しながらチェックできます。 パケットが作成されると、そのソース頂点を表す現在のコンポーネントが保存されます。 後で、問い合わせのために`(x, packet)`保存されている代表値が次の代表値と等しいことを確認するだけです。`x`最後の森で。 

最終フォレスト内の祖先チェックは、DFS の開始時刻と終了時刻で回答されます。 

これにより、問題はオフラインの祖先クエリと DSU スナップショットに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(nm) | 遅すぎる |
 | 最適 | O((n + m) α(n)) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての操作を読み取り、保存します。 
2. 読みながら、最終的な森を構築します。 

あらゆる操作に対して`1 x y`、エッジを追加します`y -> x`。 
3. DSU を使用して操作を再生します。 

加工時`1 x y`を含むコンポーネントを結合します。`x`そして`y`。 
4. パケット作成処理時`2 x`、次のパケット ID を割り当てます。 

ストア:

 - ソース従業員`x`- 現在の DSU 代表者`x`この代表は、パケットの作成時に存在した接続コンポーネントを識別します。 
5. すべての操作が読み取られた後、最終フォレストのすべてのルートで DFS を実行します。 
6. オイラーツアーの時間を記録します。 

-`tin[v]`ノードに入るとき
 -`tout[v]`ノードを離れるとき
 7. オイラー時間を使用して、従業員`a`従業員のご先祖様です`b`最後のフォレストでは、次のようなときに実行されます。```
tin[a] <= tin[b] <= tout[a]
```8. すべてのパケットについて、最終フォレスト内のソース従業員のルートを計算します。 

これは DFS 中に取得できます。 
9. お問い合わせの場合`(x, packet_id)`：

させて`v`パケットソースになります。 

させて`comp`パケットの作成時に保存された DSU 代表になります。 

次の場合は「はい」と答えてください。 

-`x`の先祖です`v`最後の森で。 
- 最終ツリーのルート`x`で表される最終ツリーのルートと等しい`comp`。 

それ以外の場合は「NO」と答えてください。 

### なぜ効果があるのか

 従業員で作成されたパケットを考えてみましょう`v`。 

パケットは、からのパス上の頂点によって正確に署名されます。`v`その時点で存在していたコンポーネントのルートに移動します。 

エッジは追加されるだけで変更されないため、エッジの祖先は`v`パケット作成時には、パケットの祖先が残ります。`v`最後の森で。 したがって、最終的な DFS は、署名可能なすべての署名者を正確に識別します。 

ただし、一部の頂点は後で祖先になります。 それらの頂点は接続されていませんでした`v`パケットが作成されたとき。 パケットとともに保存された DSU スナップショットには、その時点でどのコンポーネントが存在していたのかが正確に記録されます。 クエリされた従業員がそのコンポーネントに属していることを要求すると、後でのみ表示されたすべての祖先が削除されます。 

2 つの条件は共に必要かつ十分であるため、すべてのクエリは正しく回答されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(300000)

n, m = map(int, input().split())

ops = []

children = [[] for _ in range(n + 1)]
has_parent = [False] * (n + 1)

class DSU:
    def __init__(self, n):
        self.p = list(range(n + 1))
        self.sz = [1] * (n + 1)

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]

dsu = DSU(n)

packet_source = [0]
packet_component = [0]

for _ in range(m):
    data = list(map(int, input().split()))
    t = data[0]

    if t == 1:
        x, y = data[1], data[2]

        children[y].append(x)
        has_parent[x] = True

        dsu.union(x, y)

        ops.append((1, x, y))

    elif t == 2:
        x = data[1]

        packet_source.append(x)
        packet_component.append(dsu.find(x))

        pid = len(packet_source) - 1
        ops.append((2, pid))

    else:
        x, i = data[1], data[2]
        ops.append((3, x, i))

tin = [0] * (n + 1)
tout = [0] * (n + 1)
root = [0] * (n + 1)

timer = 0

def dfs(start_root):
    global timer

    stack = [(start_root, 0)]

    while stack:
        v, state = stack.pop()

        if state == 0:
            timer += 1
            tin[v] = timer
            root[v] = start_root

            stack.append((v, 1))

            for to in reversed(children[v]):
                stack.append((to, 0))
        else:
            tout[v] = timer

for v in range(1, n + 1):
    if not has_parent[v]:
        dfs(v)

answers = []

for op in ops:
    if op[0] != 3:
        continue

    x, pid = op[1], op[2]

    source = packet_source[pid]
    comp_rep = packet_component[pid]

    comp_root = root[comp_rep]

    is_ancestor = tin[x] <= tin[source] <= tout[x]

    if is_ancestor and root[x] == comp_root:
        answers.append("YES")
    else:
        answers.append("NO")

print("\n".join(answers))
```最初のパスは 2 つの目的を同時に果たします。 最終的なフォレストを構築し、パケット作成ごとに DSU の状態を記録します。 DSU の状態は、後で再構築できない履歴情報です。 

DFS は、最終フォレストに対して 1 回だけ実行されます。 オイラー ツアー間隔により、一定時間の祖先チェックが可能になります。 ノードは、その DFS 間隔に他のノードのエントリ時間が含まれている場合に、別のノードの祖先になります。 

微妙な部分は、保存されている DSU の代表です。 コンポーネント全体のスナップショットは必要ありません。 作成時にパケットのコンポーネントに属することが保証されている頂点が 1 つだけ必要です。 最終的なフォレストが構築された後は、すべての DSU 代表者が 1 つのツリーに属することになるため、ツリーのルートを比較することで、クエリされた従業員がパケットが表示されたときにすでに接続されていたかどうかがわかります。 

もう 1 つの実装の詳細は、反復 DFS です。 一定の長さのチェーン上の再帰的 DFS`10^5`スタックオーバーフローの危険があります。 反復バージョンではその問題が回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) α(n)) | DSU の動作はほぼ一定で、DFS は線形です。 
| スペース | O(n + m) | フォレスト、操作リスト、パケット データ、DFS 配列 |

 このアルゴリズムは、操作を通じて 1 回のパス、最終フォレスト上で 1 回の DFS、およびクエリごとの定数処理を実行します。 と`n, m ≤ 100000`、これは簡単に制限内に収まります。

import sys, io

def run(inp: str) -> str:
    from collections import deque

    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n, m = map(int, input().split())

    children = [[] for _ in range(n + 1)]
    has_parent = [False] * (n + 1)

    class DSU:
        def __init__(self, n):
            self.p = list(range(n + 1))

        def find(self, x):
            while self.p[x] != x:
                self.p[x] = self.p[self.p[x]]
                x = self.p[x]
            return x

        def union(self, a, b):
            a = self.find(a)
            b = self.find(b)
            if a != b:
                self.p[b] = a

    dsu = DSU(n)

    ops = []
    src = [0]
    comp = [0]

    for _ in range(m):
        arr = list(map(int, input().split()))
        if arr[0] == 1:
            x, y = arr[1], arr[2]
            children[y].append(x)
            has_parent[x] = True
            dsu.union(x, y)
            ops.append((1,))
        elif arr[0] == 2:
            x = arr[1]
            src.append(x)
            comp.append(dsu.find(x))
            ops.append((2,))
        else:
            ops.append(tuple(arr))

    return ""
