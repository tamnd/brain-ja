 ## 解決策
 ## 問題の理解

 アンは合計 _n_ 回地下鉄を使って通勤する必要があります。 彼女は、_a_ ルーブルの料金で各乗り物を個別に支払うことも、_m_ 回の乗り物を正確にカバーし、_b_ ルーブルの特別な複数乗り物チケットを購入することもできます。 この問題では、すべての _n_ 回の乗り物をカバーするために支払わなければならない最小総費用を、おそらく個別のチケットと複数の乗り物チケットを組み合わせて決定するように求められます。 

入力整数は次の数量を表します。_n_ は乗車の合計数、_m_ は複数乗車券がカバーする乗車数、_a_ は 1 回の乗車料金、_b_ は 1 枚の複数乗車券の料金です。 出力は単一の整数で、すべての乗車を完了するために必要な最小ルーブル額です。 

制約は小さく、すべての値の上限は 1000 です。これは、複数乗車チケットの可能な数をループする単純なソリューションでも実現可能であることを意味します。 ただし、この問題は単純な算術で直接解くことができます。 主なエッジケースは、乗り物の数が複数の乗り物チケットよりも少ない場合、または複数の乗り物チケットが個別の乗り物を購入するよりも高価な場合に発生します。 たとえば、_n = 1_、_m = 5_、_a = 1_、および _b = 10_ の場合、5 回乗車券ではなく 1 ルーブルで 1 回乗車券を購入するのが最も安いオプションであることは明らかです。 

## アプローチ

 ブルートフォース手法では、0 から ⌈_n/m_⌉ までの可能なすべての回数の乗り物チケットを反復処理し、1 枚のチケットでカバーする残りの乗り物を計算し、最小総コストを追跡します。 このアプローチは、考えられるすべての組み合わせを検討するため正しいものですが、ここではやりすぎです。 最悪の場合、このループは最大 1000 回実行されますが、これは問題の制約では許容範囲内ですが、直接演算を使用するとより良い結果が得られます。 

重要な観察は、問題は、可能な限り多くの完全な乗り物チケットを購入した後の残りの乗り物に対する 2 つの戦略の単純な比較に帰着するということです。つまり、残りの乗り物の正確な数を個別に購入するか、それらを補うためにもう 1 枚の複数乗り物チケットを購入するかのいずれかです。 完全な複数乗車チケットの場合は、次のように計算します。`full_sets = n // m`。 残りは`remainder = n % m`。 最小コストは次の合計です。`full_sets * b`さらに安価なオプションとしては、`remainder * a`または`b`。 このロジックは、反復を必要とせずに、すべての最適な組み合わせを取得します。

 ## アルゴリズムのチュートリアル

 1. アンが購入できる完全な複数乗車チケットの枚数を整数除算で計算します。`full_sets = n // m`。 これは、必要な乗り物を超えない複数の乗り物チケットの最大数を表します。 
2. 複数の乗り物チケットをすべて購入した後、カバーされない乗り物の数を計算します。`remainder = n % m`。 
3. アンが残りの乗り物を 1 回分のチケットとして正確に購入した場合のコストを計算します。`cost_single_remainder = remainder * a`。 
4. アンが残りの乗り物をカバーするために追加の複数乗車券を 1 枚購入した場合のコストを計算します。`cost_extra_ticket = b`。 
5. 残りの乗り物について 2 つのオプションの最小値を選択し、それを複数の乗り物チケット全体の料金に追加します。`total_cost = full_sets * b + min(cost_single_remainder, cost_extra_ticket)`。 
6. 印刷`total_cost`。 

機能する理由: このアルゴリズムが機能するのは、複数乗車チケットと単一チケットの任意の組み合わせを、フルセットと残りの選択肢として表すことができるためです。 残りの乗り物について 2 つのオプションを比較することで、アンは最後の乗り物に必要以上に支払うことがなくなり、以前に対象となった乗り物の正規のチケットを追加で購入してもコストが削減されることはありません。 この問題は乗車回数に関しては線形ですが、コストの構造により定数時間の演算に帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, a, b = map(int, input().split())

full_sets = n // m
remainder = n % m

# cheapest way to cover remaining rides
remainder_cost = min(remainder * a, b)

total_cost = full_sets * b + remainder_cost
print(total_cost)
```コードは最初に 4 つの整数を読み取り、すぐに完全な複数乗車券と残りの乗車券の数を計算します。 次に、残りの乗り物を 1 枚のチケットまたは 1 枚の追加の複数乗りチケットでカバーするための安価なオプションを計算します。 最後に、コストを合計し、結果を出力します。 整数の除算と剰余を使用すると、フルセットと剰余の乗りを計算する際の off-by-one エラーが回避されます。 min 関数は、乗り残しの正しい決定を保証します。

 入力:`7 3 2 5`| フルセット | 残り | 残りのコスト | 合計コスト |

 説明: 複数乗車券を 2 枚購入すると、6 回の乗車がカバーされます。 乗り物は残り1台。 1 枚のチケットを 2 ルーブルで購入すると、3 回分のチケットを 5 ルーブルで購入するよりも安くなります。 合計コスト = 2 * 5 + 2 = 12。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m, a, b = map(int, input().split())
    full_sets = n // m
    remainder = n % m
    remainder_cost = min(remainder * a, b)
    total_cost = full_sets * b + remainder_cost
    return str(total_cost)

# Provided sample
assert run("6 2 1 2\n") == "6", "sample 1"

# Minimum-size input
assert run("1 1 1 1\n") == "1", "minimum rides equal ticket"

# Single ticket cheaper than multi
assert run("1 5 1 10\n") == "1", "single ticket cheaper than multi"

# Multi-ticket cheaper than single multiple
assert run("10 3 4 10\n") == "34", "mixed multi and single optimal"

# Rides exactly divisible by multi-ride ticket
assert run("6 3 2 5\n") == "10", "rides divisible by multi-ride ticket"

# Rides smaller than multi-ride ticket, multi-ride cheaper
assert run("2 5 3 5\n") == "5", "multi-ride ticket cheaper than 2 singles"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1 1 1 | 1 | 最小入力 |
 | 1 5 1 10 | 1 | マルチチケットよりも安いシングルチケット |
 | 10 3 4 10 | 34 | マルチとシングルの最適な組み合わせ |
 | 6 3 2 5 | 10 | マルチチケットによる正確な分割 |
 | 2 5 3 5 | 5 | シングルチケットよりも安いマルチチケット |

 ## 特殊なケース

 のために`n = 1, m = 5, a = 1, b = 10`、剰余は 1 です。アルゴリズムは 1 * 1 = 1 と 10 を比較し、1 を選択し、正しい最小コストを与えます。 のために`n = 6, m = 2, a = 1, b = 2`、剰余 = 0 であるため、追加コストは追加されません。 のために`n`で割り切れる`m`、アルゴリズムは過剰購入を行わず、未使用の乗り物に対する支払いを回避します。 それぞれのケースで、min 関数と整数の除算が小さい剰余と大きい剰余の両方を正しく処理できることが確認されます。
