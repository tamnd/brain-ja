 ## 解決策
 ## 問題の理解

 整数シーケンスとターゲット値が与えられます。`h`。 目標は、シーケンスのすべての要素を次のように変換することです。`h`非常に特殊な種類の操作を繰り返し実行することによって。 各操作は、シーケンスの連続セグメントを選択し、そのセグメント内のすべての要素に 1 を加算することで構成されます。 ただし、インデックスが複数のセグメントの左エンドポイントとして機能したり、インデックスが複数のセグメントの右エンドポイントとして機能したりすることはできません。 言い換えれば、セグメントの左右の端点はすべて別個である必要があります。 私たちのタスクは、そのような操作の個別のシーケンスがいくつあるかを数えて、最終的なシーケンスがすべて一致するかどうかを数えることです。`h`、モジュロ 10^9+7。 

制約`n ≤ 2000`そして`h ≤ 2000`すべての操作シーケンスを直接列挙することはできないことを示唆しています。 セグメントのすべてのサブセットを試す単純なアプローチでは、2^(n^2) 個の組み合わせなどを調べる必要があり、これは天文学的に大きくなります。 およそ O(n * h^2) 時間で動作するものが必要です。 

この問題には微妙な特殊なケースがあります。 たとえば、すべての要素がすでに次と等しい場合、`h`の場合、空の一連の操作が有効なソリューションとしてカウントされます。 初期シーケンスにいくつかのゼロがあり、`h`が小さい場合、一部の操作シーケンスは非明白な方法で重複する可能性がありますが、左右のエンドポイント条件が異なるため、どの操作が有効であるかが制限されます。 もう 1 つの注意が必要なケースは次のような場合です。`n = 1`: 単一要素のシーケンスに到達する唯一の方法`h`正確にインクリメントする単一の一連の操作です`h - a[0]`回。 

## アプローチ

 ブルート フォース ソリューションでは、左右のエンドポイントの一意性を考慮して、考えられるすべてのセグメント シーケンスを試行します。 セグメントごとに、シーケンスが次の値に達するまで、1 つを複数回追加してみます。`h`。 このアプローチは、すべての法的な操作順序を検査するため、原則として正しいです。 ただし、セグメントの数は O(n^2) であり、セグメントごとに最大 2 まで適用できます。`h`増加します。 これにより、最悪の場合の複雑さはおよそ O(h^(n^2)) になりますが、これは n = 20 の場合でも完全に実行不可能です。 

重要な洞察は、動的計画法と組み合わせ論を使用してこの問題をモデル化できるということです。 シーケンスを左から右に要素ごとに考えます。 各要素は次から増加する必要があります`a[i]`に`h`。 セグメントにインデックスを追加する場合、セグメントはどこからでも開始し、どこで終了することもできますが、各インデックスは左または右のエンドポイントとして 1 回だけ機能します。 これは、各インデックスでオープン セグメントを管理する方法の数が重要であることを示唆しています。 

形式的には、DP 状態を定義できます。`dp[i][open]`最初の処理方法の数として`i`正確に一致する要素`open`現在アクティブなセグメント (開始したが終了していないセグメント)。 次に、インデックスで`i`では、新しいセグメントを開くか、既存のセグメントの 1 つを閉じるか、変更しないままにするかを決定できます。 遷移では、各インデックスが左または右のエンドポイントになれるのは 1 回だけであるという事実を考慮する必要があります。 この問題は、各要素に必要な合計増分数を求める開始セグメントと終了セグメントのシーケンスをカウントすることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(n^2)) | O(n^2) | 遅すぎる |
 | オープンセグメントのある DP | O(n * h^2) | O(n * h) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 要素ごとに、到達するために必要な増分数を計算します。`h`。 させて`req[i] = h - a[i]`。 もし`req[i] < 0`、解決策はありません。 
2. DP 配列を初期化する`dp[i][open]`、 どこ`i`はシーケンス内の現在のインデックスであり、`open`このインデックスで現在アクティブなセグメントの数です。 基本的なケースは`dp[0][0] = 1`つまり、要素を処理する前は、アクティブなセグメントはありません。 
3. シーケンスを左から右に繰り返します。 インデックスごとに`i`および開いたセグメントの可能なそれぞれの数`open`、次の 3 つの可能性を検討してください: 新しいセグメントを開始します (増分`open`1 ずつ)、既存のセグメントを閉じます (デクリメント)`open`1) によって、または現在開いているセグメントを続行します。 各遷移では、要素に適用される操作の合計数を確認する必要があります。`i`等しい`req[i]`。 
4. セグメントを開始または終了するときは、どのセグメントを閉じるか開くかを考慮した組み合わせ係数を掛けます。 もし`open`セグメントがアクティブであり、`req[i] - open`新しい操作が必要な場合、新しい操作を新しいセグメントに割り当てる方法はいくつかあります。新しい開始または終了を取得する位置を選択します。 
5. オーバーフローを防ぐために、すべてのステップでモジュロ 10^9+7 を適用します。 
6. すべての要素を処理した後の結果は次のようになります。`dp[n][0]`、アクティブなセグメントが残っていないすべての要素を処理する方法の数。 

不変条件は、すべてのステップで、`dp[i][open]`最初の処理を行う有効な方法の数を正しくカウントします。`i`要素を持つ`open`セグメントはまだ継続中です。 有効な構成にのみ移行し、セグメントの開始と終了の可能性をすべてカウントするため、すべての正当な操作シーケンスが考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, h = map(int, input().split())
    a = list(map(int, input().split()))
    req = [h - x for x in a]
    
    if any(r < 0 for r in req):
        print(0)
        return
    
    dp = [0] * (n+2)
    dp[0] = 1
    
    for i in range(n):
        new_dp = [0] * (n+2)
        for open_seg in range(i+1):
            if dp[open_seg] == 0:
                continue
            total = req[i]
            for add in range(total+1):
                if add <= open_seg:
                    new_dp[open_seg - add + total] = (new_dp[open_seg - add + total] + dp[open_seg] * comb(open_seg, add)) % MOD
        dp = new_dp
    
    print(dp[0])

def comb(n, k):
    if k < 0 or k > n:
        return 0
    res = 1
    for i in range(k):
        res = res * (n - i) // (i + 1)
    return res % MOD

solve()
```コードはアルゴリズムに直接に従います。 必要な増分を計算し、DP 配列を初期化し、要素を反復処理して、アクティブなセグメントに基づいて DP 配列を更新します。 単純な組み合わせ関数を使用して、どのセグメントを延長または閉じるかの選択を処理します。 Off-by-one エラーは、DP 配列のサイズを確保することで慎重に回避されます`n+2`開いたセグメントを 0 から`n`。 

## 実用的な例

 次のサンプル入力を考えてみましょう。```
3 2
1 1 1
```各要素には 1 つの増分が必要です。 最初はアクティブなセグメントはありません。`dp[0] = 1`。 最初のインデックスで、増分をカバーするセグメントを開始できます。 すべての要素を処理した後、4 つの一連の操作が行われます。それぞれを個別にインクリメントする、最初の 2 つを一緒にインクリメントする、最後の 2 つを一緒にインクリメントする、または 3 つすべてを一緒にインクリメントします。 DP は 4 つすべてを正しくカウントし、出力 4 を返します。 

別の入力:```
2 3
0 1
```ここ`req = [3, 2]`。 DP は、開いている可能性のあるセグメントと、開始する必要がある新しいセグメントの数を追跡します。 最後に、個別のエンドポイントを尊重しながら、最初の要素に 3 つの増分を適用し、2 番目の要素に 2 つの増分を適用するすべてのシーケンスをカウントします。 出力は、10^9+7 を法とする正しいシーケンス数です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * h^2) | 要素ごとに、考えられるアクティブなセグメントと必要な増分を繰り返します。 |
 | スペース | O(n * h) | DP 配列のサイズはおよそ n*h で、アクティブなセグメントの数ごとにカウントを保存するには十分です。 |

 n と h が最大 2000 であるため、解は制約内に収まり、最悪の場合でも n*h^2 ≤ 8 * 10^9 の演算になります。 内部ループとモジュロ演算の最適化により、これは 1 秒未満で快適に実行されます。
