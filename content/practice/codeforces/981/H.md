 ## 問題の理解

 ツリーが与えられ、順序付けられたリストを選択します。$k$単純なパス。各パスはツリー内の 2 つのエンドポイントによって定義されます。 パスはツリー上にあるため、頂点の各ペアによって一意の単純なパスが決定されます。 

ツリーのすべてのエッジについて、$k$パスの場合、そのエッジは 3 つのカテゴリのいずれかに当てはまります。すべてのパスで使用されていない、選択されたパスの 1 つだけで使用されている、またはすべてのパスで使用されています。$k$パス。 主要な構造上の制約は、最後のカテゴリを空にすることはできないということです。つまり、すべてのカテゴリに少なくとも 1 つのエッジが存在する必要があります。$k$パスを同時に実行します。 

注文した数を数えるのが仕事です$k$-この条件を満たすパスのタプル。 

制約により、最大で次のことが許可されます。$10^5$頂点と$10^5$パス。 どのソリューションも線形に近いか、$O(n \log n)$パスを列挙したり、エンドポイントのペアを直接考慮したりすると、すでに$O(n^2)$オブジェクトを作成し、それを$k$選択は完全に不可能です。 

最初の微妙な落とし穴は、「すべてのパスにエッジが含まれている」という構造上の意味を誤解していることです。 単一のエッジが選択されたすべてのパスに属する場合、それらのパスはすべて、そのエッジを含むツリーの共通の接続領域を通過する必要があります。 これにより、任意の独立したパスの選択が即座に排除されます。 

2 番目の微妙な問題は、構造は共有しているものの方向やエンドポイントの順序が異なるパスを二重にカウントすることです。 パスには順序があり、エンドポイントにも順序があるため、$u \to v$そして$v \to u$パスとしては同一ですが、選択されたパスの異なるペアが同じ基礎となるパスを複数回繰り返すことができます。

 ## アルゴリズムのチュートリアル

 1. 任意のノード (通常は 1) でツリーをルート化し、DFS を使用してサブツリー サイズを計算します。 これにより、各サブツリーの頂点の数が得られ、エッジを削除するときに形成される各コンポーネントのサイズが暗黙的に得られます。 
2. 親間のすべてのエッジに対して$u$そして子供$v$、そのエッジの削除を、ツリーを次のサイズのサブツリーに分割すると解釈します。$sz[v]$そして残りのサイズ$n - sz[v]$。 
3. このエッジを使用する単純なパスは、分割の各側で 1 つのエンドポイントを選択し、正確に指定する必要があることに注意してください。$sz[v] \cdot (n - sz[v])$このエッジを含む可能なパス。 
4. 固定刃の場合、発注数は$k$-そのエッジをすべて含むパスのタプルは$(sz[v] \cdot (n - sz[v]))^k$、各パスの選択は独立しており、繰り返しが許可されているためです。 
5. すべてのエッジにわたってこの値を合計して、最終的な答えのモジュロを取得します。$998244353$。 

この合計が機能する理由は、それぞれの有効な構成が$k$パスには、交差部分の「最も深い」共通エッジである固有のエッジがあります。 そのエッジは合計で 1 回だけカウントされます。$k$パスには必ずそれが含まれており、他のエッジは構成を一意に表すものとしては認められません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    g = [[] for _ in range(n)]
    edges = []
    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append(b)
        g[b].append(a)
        edges.append((a, b))

    parent = [-1] * n
    order = [0]
    parent[0] = -2

    for v in order:
        for to in g[v]:
            if parent[to] == -1:
                parent[to] = v
                order.append(to)

    sz = [1] * n
    for v in reversed(order):
        for to in g[v]:
            if parent[to] == v:
                sz[v] += sz[to]

    ans = 0
    for v in range(1, n):
        p = parent[v]
        comp1 = sz[v]
        comp2 = n - sz[v]
        cnt = comp1 * comp2 % MOD
        ans = (ans + pow(cnt, k, MOD)) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初にツリーを構築し、BFS スタイルのトラバーサルを実行して親を割り当て、サブツリーのサイズをボトムアップで計算するために使用できる順序付けを生成します。 これにより、再帰の深さの問題が回避されます。$10^5$。 

重要な実装の詳細は、子ノードを反復処理することによって各エッジを 1 回だけ処理することです。$v$そして使用して$(v, parent[v])$エッジとして。 これにより二重カウントが防止されます。 

私たちは計算します$sz[v]$ルートとなるサブツリーのサイズとして$v$したがって、パスがそのエッジを横切る端点のペアの数は、$sz[v] \cdot (n - sz[v])$。 これを$k$すべての順序の - 乗数$k$-そのようなパスのタプル。

 ## 特殊なケース

 重要なエッジケースは、選択されたパスがすべて同一である場合です。 チェーンツリーの中で同じ道を選ぶ$k$回では、そのパス上のすべてのエッジがすべてのパスに含まれる有効な構成が生成されます。 そのパス上のすべてのエッジが独立してエンドポイント ペアの数に寄与し、繰り返しは自然にべき乗によって処理されるため、アルゴリズムはこれを考慮します。 

別の特殊なケースが発生するのは、$k=1$。 この場合、すべての単純なパスが有効であり、交差に関する条件は自明に満たされます。 この式は頂点のすべてのペアをカウントすることになります。各エッジベースの分解では、誘導されたカット構造を通じて各パスが 1 回だけカウントされるため、これは一貫しています。 

3 番目のエッジケースは、ツリーがスターである場合です。 すべてのパスは中心を通過するか単一のエッジであり、サブツリー サイズの式により各寄与が次のように明確に区別されます。$1 \cdot (n-1)$、すべてのパス タイプの均一な処理が保証されます。
