選択されたサブセットについて、各配列位置は、セグメントがその位置をカバーする選択されたすべての演算の合計を累積します。 したがって、ある位置の値は、選択された値のサブセットの合計になります。$x_i$ただし、サブセットは、どの操作がその位置をカバーするかによって異なります。 サブセットの最終スコアは、これらの加算を適用した後のすべてのポジションの最大値です。 

タスクはすべての整数を決定することです$y$結果の配列が正確に最大値を持つ演算のサブセットが少なくとも 1 つ存在する$y$。

主な問題点は、サブセットの効果が一律にグローバルではないことです。 演算の同じサブセットは、オーバーラップ構造に応じて、異なるインデックスで異なる合計を生成する可能性があります。

## アプローチ

 直接的なブルート フォース アプローチでは、操作のすべてのサブセットが列挙され、結果の配列が計算されます。$O(n)$、その最大値を抽出します。 これにより、$O(n \cdot 2^q)$ですぐに失敗します。$q = 20$、ましてや$10^4$。 

重要な構造的観察は、固定サブセットの場合です。$S$、最大値は常にある位置で達成されます。$i$、その位置では操作のみをカバーします$i$案件。 ポジションを固定すれば$i$、の値$i$は、セグメントに次の内容が含まれる一連の操作のサブセット合計です。$i$。 したがって、達成可能なすべての答えは、すべてのポジションを独立して検討し、そのポジションでの「アクティブ セット」のすべてのサブセットの合計を取ることで得られます。 

これにより、あらゆる立場で問題がコンピューティングに変換されます。$i$、マルチセットのサブセット合計のセット$A_i = \{x_j \mid l_j \le i \le r_j\}$そして労働組合をすべて支配する$i$。 課題は、すべてのサブセットの合計をゼロから再計算することです。$i$遅すぎます。 

構造を利用するために、ポジション上のセグメント ツリーを使用してセグメント構造ごとに操作をグループ化します。 各操作は、その間隔を完全にカバーするすべてのセグメント ツリー ノードに保存されます。 各ノードについて、ビットセット ナップザックを使用して、そのノードに割り当てられたすべての操作のサブセット合計 DP を計算します。 次に、どの位置でも、アクティブな操作はルートからリーフへのパスに沿って保存されたものとまったく同じであるため、ビットセット畳み込みを介してそのパスに沿ったノードの寄与を結合することによって、最終的なサブセット合計セットが取得されます。 

これは、ノードごとにサブセット合計ビットセットを事前計算し、ツリー全体に伝播して結合するという解決策につながります。

 ## アルゴリズムのチュートリアル

 1. インデックス範囲にわたってセグメント ツリーを構築します。$[1, n]$ここで、各ノードは位置のセグメントを表します。

3. すべてのノードに対して、ビットセット DP を計算します。`dp[s] = true`そのノードに保存されている値のサブセットの合計が$s$。 これは、マルチセットの標準的なナップザックです。$x$- ノードに割り当てられた値。 ビットセットは、値を反復処理し、シフト OR 遷移を適用することによって更新されます。 
4. ルートから DFS を実行します。 実行中のビットセットを維持する`cur`祖先から蓄積されたすべてのサブセットの合計を表します。 
5. 各ノードで、サブセット合計セットの畳み込みを使用して、その DP ビットセットを現在の状態にマージします。 異なるノードからの操作は独立した選択であるため、このステップでは、異なるツリー レベルから独立してサブセットを選択することが考慮されます。 
6. 位置に対応する葉に到達したとき$i$、現在のビットセットは、その位置で達成可能なすべての値を表します。 すべてのインデックスを追加$s$そのような`cur[s] = true`グローバルな回答セットに追加します。 
7. DFS が完了したら、収集されたすべての値を昇順に出力します。 

### なぜ効果があるのか

 各操作は、その操作がセグメントを完全にカバーするセグメント ツリー ノードに正確に割り当てられます。 どのポジションでも$i$、ルートからリーフへのパス上のノードは、影響を与えるすべての操作のパーティションを形成します。$i$。 各ノードの DP は、そのセグメント全体で均一な演算のすべてのサブセット合計を正しくエンコードします。 異なるノードでの演算は独立しているため、サブセットの合計は畳み込みによって結合され、DFS はすべての位置が正確に正しい組み合わせを認識することを保証します。 したがって、すべての位置での実行可能なすべてのサブセット合計が、トラバーサルのどこかで 1 回だけ生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class BitsetDP:
    def __init__(self, n):
        self.n = n
        self.bits = 1  # bit 0 set

    def add(self, x):
        self.bits |= (self.bits << x)
        self.bits &= (1 << (self.n + 1)) - 1

def merge(a, b, n):
    res = [False] * (n + 1)
    for i in range(n + 1):
        if a[i]:
            for j in range(n + 1 - i):
                if b[j]:
                    res[i + j] = True
    return res

def solve():
    n, q = map(int, input().split())
    seg = [[] for _ in range(4 * n)]

    def add(node, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            seg[node].append(val)
            return
        mid = (l + r) // 2
        if ql <= mid:
            add(node * 2, l, mid, ql, qr, val)
        if qr > mid:
            add(node * 2 + 1, mid + 1, r, ql, qr, val)

    for _ in range(q):
        l, r, x = map(int, input().split())
        add(1, 1, n, l, r, x)

    def build(node):
        dp = BitsetDP(n)
        for x in seg[node]:
            dp.add(x)
        seg[node] = dp.bits
        if node * 2 < len(seg):
            build(node * 2)
            build(node * 2 + 1)

    build(1)

    ans = set()

    def dfs(node, l, r, cur):
        cur_bits = cur
        node_bits = seg[node]

        new = 0
        for i in range(n + 1):
            if cur_bits >> i & 1:
                shifted = node_bits << i
                new |= shifted

        cur_bits |= new

        if l == r:
            for i in range(n + 1):
                if cur_bits >> i & 1:
                    ans.add(i)
            return

        mid = (l + r) // 2
        dfs(node * 2, l, mid, cur_bits)
        dfs(node * 2 + 1, mid + 1, r, cur_bits)

    dfs(1, 1, n, 0)

    ans.discard(0)
    ans = sorted(ans)
    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()

微妙な点は、ビットセットの畳み込みがシフト累積によって近似されることです。 ここで、多くの誤った実装が正確さを失います。 このロジックは、独立したグループからのサブセットの合計が、達成可能な合計のペアごとの加算によって結合されるという事実に基づいています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての操作が配列全体をカバーする場合です。 この状況では、すべての位置に同一のアクティブ セットがあるため、アルゴリズムはグローバル サブセット合計 DP とまったく同じように動作するはずです。 セグメント ツリーはすべての操作をルートに割り当て、DFS は単一の DP 状態を一貫してすべてのリーフに伝播し、正しく均一な結果を生成します。 

もう 1 つのケースは、すべてのセグメントが互いに素である場合です。 各位置は最大でも 1 つの操作を受け取るため、各位置でのサブセットの合計は自明です。 DFS は、各リーフが自身のノードの寄与のみを認識し、位置間で相互汚染が発生しないことを保証します。 

3 番目の微妙なケースは、操作が入れ子状に重複する場合に発生します。 セグメント ツリーの分解により、ネストされた間隔が複数のノードに分散されますが、各ノードの DP はその構造内部のすべての組み合わせを正確にキャプチャします。 DFS はこれらを二重にカウントせずにマージし、重複する寄与の正確さを維持します。
