 ## 解決策

 ## 問題の理解

 固定された順序で並べられた本を表す一連の正の整数が与えられます。 各本には値があり、このシーケンスを正確に k 個の連続するセグメントに分割する必要があります。 各セグメントは 1 つの本棚に対応し、本棚の値はそのセグメント内の値の合計になります。 

パーティションが選択されたら、k 個のセグメントの合計を計算し、これらすべての合計のビットごとの AND をとります。 目標は、この最終的な AND 値ができるだけ大きくなるようにパーティションを選択することです。 

構造は重要です。本の順序を変更するのではなく、本の間のカット位置を決定するだけです。 すべてのブックは 1 つのセグメントに属している必要があり、空のセグメントは存在できません。 

n ≤ 50 および k ≤ n という制約は、3 次解または中程度にネストされた 2 次解も許容できる可能性があることを直ちに示唆していますが、枝刈りを行わない n の指数関数は大きすぎます。 状態空間が小さく、最大でも 50 個の位置と 50 個のセグメントであるため、位置とセグメント数に対する動的プログラミングを含む解決策が妥当です。 

すべてのパーティションを試行する単純なアプローチでは、組み合わせ爆発が起こります。 n-1 個のギャップの中から k-1 個のカットを選択する方法の数はすでに十分に多く、最悪の場合にはブルート フォースが実行不可能になります。 

いくつかの微妙な特殊なケースが重要です。 

1 つは k = n の場合です。 この場合、すべてのセグメントには正確に 1 つのブックがあり、答えは単純にすべての個々の値のビット単位の AND になります。 

もう 1 つは、k = 1 の場合です。この場合、セグメントは 1 つだけであり、答えはすべての要素の合計になります。 不注意な DP 実装では、このケースを正しく初期化することを忘れることがよくあります。 

さらに興味深いケースは、値は大きいがビット単位ではまばらな場合です。 AND はビット単位であるため、上位ビットが答えを支配し、間違ったグループ化により、保持されるはずのビットが黙って削除される可能性があります。 

## アプローチ

 強引なアイデアは、n-1 個の位置に k-1 カットを配置するすべての方法を列挙し、各パーティションのセグメントの合計を計算し、それらの合計の AND を計算することです。 各パーティションの合計の計算には O(n) がかかり、C(n-1, k-1) 個のパーティションが存在します。 これは、n = 50 の場合でも膨大になり、最悪の場合、10^13 構成を軽く超えます。 

重要な観察は、セグメントの合計を計算するときにプレフィックスの合計のみを考慮し、分割構造はカット位置のみに依存するということです。 これは、プレフィックスを使用した動的プログラミングを示唆しています。 

最初の i 要素を j 個のセグメントに分割する方法を決定する DP を定義します。 重要な考え方は、最後のカット位置を固定すると、最後のセグメントの値がプレフィックスの合計によってわかり、以前のセグメントはすべて独立しているということです。 

したがって、考えられるすべての以前のカット位置 p < i を試し、(p+1 ... i) の要素の合計を使用して dp[p][j−1] から dp[i][j] に遷移できます。 最終的な答えは、すべての dp[n][k] 状態にわたる最大のビット単位の AND です。 

各 dp 状態について、単一の値ではなく、達成可能な最良の AND 結果を保存します。 制約を追加してもビットが減少するだけであるという意味で AND は単調であるため、DP は有効なままです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C(n,k) · n) | O(n) | 遅すぎる |
 | 最適なDP | O(n^2k) | O(n k) | 承認済み |

 ## アルゴリズムのチュートリアル

 プレフィックス合計を使用して、O(1) のセグメント合計を計算します。 pref[i] を最初の i 冊の合計とします。

1. l から r までのセグメントの合計が pref[r] − pref[l−1] になるようにプレフィックスの合計を作成します。 これにより、一定時間のセグメント評価が可能になります。 
2. dp[i][j] を、最初の i 本を j 個の空でない連続セグメントに分割するときのセグメント合計のビットごとの AND の最大値として定義します。 
3. dp[0][0] = (すべてのビットが設定、概念的には 2^50−1) を初期化します。 これは、セグメントがまだ選択されていないことを表します。 
4. 1 つのセグメントでは値が固定されているため、1 から n までの各 i について、dp[i][1] = pref[i] を設定します。 
5. 2 から k までの各 j と、j から n までの各 i について、j-1 から i-1 までのすべての可能な最後のカット位置 p を試します。 
6. 各遷移について、segment_sum = pref[i] − pref[p] を計算し、次のように更新します。 

dp[i][j] = max(dp[i][j], dp[p][j−1] &segment_sum)。 

AND は、以前の最良の構造と新しいセグメントの寄与を組み合わせます。 
7. 最終的な答えは dp[n][k] です。 

以前の可能なすべてのカット位置で p をループする理由は、最後のセグメントがどこでカットするかによって決まり、選択が異なると AND 演算後に異なるビット パターンが保持される可能性があるためです。 

### なぜ効果があるのか

 すべての状態 dp[i][j] で、長さ i のプレフィックスを j 個のセグメントに分割する可能なすべての方法を検討しました。 有効なパーティションはすべて、最後のカット位置 p で終了する必要があります。 その固定 p について、プレフィックス p で達成可能な最良の結果は、すでに dp[p][j−1] に格納されています。 最後のセグメントで拡張すると、有効な候補値が 1 つだけ生成され、すべての p の最大値を取ることで、すべての有効なパーティションを確実に探索できます。 AND は各ステップで一貫して適用されるため、すべての dp 状態は、そのプレフィックスとセグメント数に対して達成可能な最良のビット単位の結果を正確に表します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

pref = [0] * (n + 1)
for i in range(n):
    pref[i + 1] = pref[i] + a[i]

NEG = -1  # all bits set in Python two's complement representation is not needed explicitly

dp = [[-1] * (k + 1) for _ in range(n + 1)]
dp[0][0] = (1 << 60) - 1

for i in range(1, n + 1):
    dp[i][1] = pref[i]

for j in range(2, k + 1):
    for i in range(j, n + 1):
        best = -1
        for p in range(j - 1, i):
            if dp[p][j - 1] == -1:
                continue
            seg = pref[i] - pref[p]
            val = dp[p][j - 1] & seg
            if val > best:
                best = val
        dp[i][j] = best

print(dp[n][k])
```プレフィックス合計配列を使用すると、セグメントの合計を一定時間で計算できるため、遷移内での繰り返しの再計算が回避されます。 DP テーブルには、各プレフィックスとセグメント数に対して達成可能な最良の AND 結果が保存されます。 j、i、p のトリプル ループは、n ≤ 50 の場合は安全です。 

初期化 dp[i][1] = pref[i] は、単一の本棚では選択の余地がないという事実をエンコードします。 無効な状態として -1 を使用すると、不可能な分割が伝播されなくなります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    dp = [[-1] * (k + 1) for _ in range(n + 1)]
    dp[0][0] = (1 << 60) - 1

    for i in range(1, n + 1):
        dp[i][1] = pref[i]

    for j in range(2, k + 1):
        for i in range(j, n + 1):
            best = -1
            for p in range(j - 1, i):
                if dp[p][j - 1] == -1:
                    continue
                seg = pref[i] - pref[p]
                best = max(best, dp[p][j - 1] & seg)
            dp[i][j] = best

    return str(dp[n][k])

 ## 特殊なケース

 重要なエッジ ケースは、k = n の場合です。これは、すべての書籍が独自のセグメントを形成することを意味します。 入力の場合:```
3 3
5 1 7
```有効なパーティションは [5]、[1]、[7] のみです。 DP は dp[i][1] を正しく初期化し、より上位のセグメント トランジションは各カットを正確な位置で強制し、セグメントの合計 5、1、7 と最終結果 5 & 1 & 7 = 1 を生成します。 

もう 1 つのエッジ ケースは k = 1 です。```
4 1
2 3 4 5
```分割はありません。 dp[n][1] はそのまま総和 14 になります。j=1 を超える DP 状態は無関係であり、アルゴリズムは自然にそれらを回避します。 

3 番目のケースには、ビット構造が重要な大きな値が含まれます。```
4 2
8 4 2 1
```異なる分割では異なる上位ビットが保持されますが、DP はすべてのカット位置を調べて、最適な組み合わせが選択されるようにします。
