 ## 解決策

 ## 問題の理解

 2 つの会社がそれぞれ化学元素のコレクションを所有しており、すべての元素は大きな整数キーによって識別されます。 要素が出現するたびに、企業が展示会でその要素を発表することを決定した場合に得られる利益価値も伴います。 企業は総利益を最大化するために独自の要素のサブセットを選択したいと考えていますが、選択した両方のサブセットで同じ要素キーを提示することは禁止されています。 

より構造的な観点から見ると、すべての要素キーは一方の会社、他方の会社、またはその両方に存在する可能性があります。 それが両方に表示される場合、競合により、多くてもどちらかの側でそれを使用することを許可するかを決定する必要があります。 1 つの企業にのみ表示される場合、その企業は、有益かどうかに応じて、自由にそれを含めたり除外したりできます。 

目標は、選択した利益の合計を最大化する方法で、共有キー間のすべての競合を解決することです。 

制約は合計要素数が 200,000 までであり、一方のセットのすべての要素をもう一方のセットのすべての要素と比較するソリューションは除外されます。 二次ペアリング手法では、最悪の場合でも 10¹⁰ 程度の操作が必要になりますが、これは制限時間を大幅に超えます。 重要な構造上のヒントは、2 つのセット間の相互作用はキーが等しい場合にのみ発生するため、すべての推論を一意の要素インデックスごとに局所化できるということです。 

キーごとに 2 つの競合する値のうち大きい方を常に選択するという素朴で貪欲なアイデアは有望に見えますが、最初にキーごとにグループ化せずに実装すると、誤って適用される可能性があります。 たとえば、同じキーの重複が集約されずに独立して処理された場合、同じ要素 ID に対して複数の寄与を誤って選択する可能性があり、問題の条件に違反します。 

もう 1 つの微妙な失敗例は、キーが 1 社のみに出現した場合に発生します。 交差するキーのみを処理する不注意な実装では、それらの一意の要素を完全に含めることを忘れて、保証された利益を失う可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、各要素キーを個別に検討し、考えられるすべての割り当てについて、それが ChemForces に送信されるか、TopChemist に送信されるか、またはどちらにも送信されないかを決定しようとします。 k 個の共有キーを想像すると、これはキーごとに 3 つの決定となり、3ᵏ の可能性が生じます。 中程度の k であっても、これは組み合わせ的に爆発し、実行不可能です。 

重要な観察は、決定間の結合は同一の要素インデックスごとにのみ行われるということです。 すべての出現をキーごとにグループ化すると、各キーは独立した決定単位になります。 特定のキーについて、ChemForces の寄与、TopChemist の寄与、または両方が存在する場合は 2 つの最大値を取得します。 

これにより、問題全体が単純な集計タスクに短縮されます。つまり、個別のキーごとに、達成可能な最良の寄与を計算し、それを合計します。 

ブルートフォースは相互作用をグローバルに扱うため失敗しますが、問題は実際には独立したキーごとの選択肢に完全に分解されます。 最適な解決策は、この分解を直接利用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^k) | O(k) | 遅すぎる |
 | 最適 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 両社からすべての要素を読み取り、インデックス値ごとにグループ化します。 キーごとに、ChemForces から得られた最高の利益と TopChemist から得られた最高の利益を保存します。 これが必要なのは、各企業が内部で個別のキーを保証しているため、各企業のキーごとに存在する値は最大でも 1 つだけです。 
2. 両社のキーを結合したすべてのキーについて、最終的な答えへの寄与を決定します。 キーが 1 つの会社にのみ存在する場合は、その値を直接取得します。 両方に存在する場合は、2 つの値の大きい方を採用します。 
3. すべてのキーに対するこれらの選択された寄与を合計します。

重要な決定は、キーごとの最大値です。これにより、競合するキーが 2 回カウントされず、可能な限り最善の選択が維持されます。 

### なぜ効果があるのか

 唯一の制約は、同じキーを両方の会社から同時に選択できないことであるため、各キーは他のキーから独立しています。 十字キーの制限はありません。 キーを分離すると、そのキーに対する最適な決定は他のキーに影響を与えなくなり、局所的に最適な選択がグローバルに最適なソリューションに結合されることが保証されます。 これは古典的な分離可能性の特性です。目的関数はキーに対して加算的であり、制約は異なるキーを結合しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
best = {}

for _ in range(n):
    a, x = map(int, input().split())
    best[a] = x  # ChemForces values

m = int(input())
for _ in range(m):
    b, y = map(int, input().split())
    if b in best:
        best[b] = max(best[b], y)
    else:
        best[b] = y

print(sum(best.values()))
```最初のループでは、ChemForces の値を使用して辞書を初期化します。 2 番目のループでは、TopChemist 専用の要素に新しいキーを挿入するか、最大値を取得して既存のキーを更新します。これにより、競合が正しく解決されます。 

最終的な合計は、キーごとの最適な寄与を集計します。 

実装によくある落とし穴は、各企業の入力によってすでに社内のキーの一意性が保証されていることを忘れていることです。 これにより、さらに集計することなく、会社ごとにキーごとに 1 つの値を保存できます。 もう 1 つの微妙な点は、両方の値を加算することで共有キーを二重にカウントしないようにすることです。 代わりに、上書きまたは比較します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    best = {}

    for _ in range(n):
        a, x = map(int, input().split())
        best[a] = x

    m = int(input())
    for _ in range(m):
        b, y = map(int, input().split())
        if b in best:
            best[b] = max(best[b], y)
        else:
            best[b] = y

    return str(sum(best.values()))

 ## 特殊なケース

 主なエッジケースは、1 つの会社に要素がまったくない場合です。 その場合、答えは単純に他社の価値の合計になります。 すべてのキーは片側からのみ取得され、直接追加されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、すべてのキーが重なっている場合です。 入力の場合:```
2
1 5
2 3
2
1 4
2 10
```辞書はキー 1 が max(5,4)=5 になり、キー 2 が max(3,10)=10 になり、15 になります。これにより、更新によって両方の値が蓄積されることがないことが確認されます。 

最後のエッジ ケースは、n と m の値がそれぞれ最大 100,000 という非常に大きな値です。 辞書ベースの集計により、要素ごとに定数時間の処理が保証されるため、完全に重複した入力であっても線形時間が維持され、劣化しません。
