 ## 解決策
 ## 問題の理解

 サイズのグリッドが与えられています$n \times m$黒と白のタイルで埋め尽くされました。 各タイルは「B」(黒) または「W」(白) のいずれかです。 ここでのタスクは、一連の四角形の塗りつぶし操作を使用して、グリッド内のすべてのタイルを同じ色にすることが可能かどうかを判断することです。 操作は、同じ色の任意の 2 つのタイルを選択し、それらの間にある長方形全体をその色で塗りつぶすことで構成されます。 各テスト ケースの出力は、均一なグリッドが達成可能な場合は「YES」、そうでない場合は「NO」になります。 

制約が示すのは、$n$そして$m$最大 500 まで可能で、すべてのテスト ケースにわたるタイルの合計数は超えません$3 \cdot 10^5$。 これにより、考えられるすべての操作を明示的にシミュレートしようとするアルゴリズムが排除されます。これは、潜在的な四角形操作の数がタイルの数に応じて二次関数的に増加するためです。 代わりに、実際にすべての塗りつぶしを実行せずに、色の位置を分析して実現可能性を判断する方法が必要です。 

明らかではないエッジ ケースは、タイルが他の同じ色のタイルから隔離されており、四角形操作でそのタイルを他のタイルに含めることができない場合に発生します。 たとえば、$2 \times 1$1 つの「W」と 1 つの「B」を持つグリッドを統合することはできません。これは、どの操作も 1 つのタイルを拡張して他のタイルを覆うことができないためです。 同じ色の 2 つのタイルの間に常に四角形を描画できると想定する単純な実装では、ここで誤った「YES」が生成されます。 

## アプローチ

 ブルートフォース手法では、グリッドが均一になるか、それ以上の変更が不可能になるまで、考えられるすべての四角形の塗りつぶし操作をシミュレートしようとします。 これには、同じ色のタイルのすべてのペアを反復処理し、それらの間の四角形を更新することが含まれる場合があります。 最悪の場合、$500 \times 500$グリッド、あるかもしれない$(500 \cdot 500)^2 / 2 \approx 3 \cdot 10^{10}$まったく実行不可能な操作です。 

問題を単純化する重要な観察は、四角形の操作では、常に下端または右端に達する四角形をカバーする色のタイルを拡張できるということです。 基本的に、右下のタイル (または角のタイル) が他のすべてのタイルの最終色として機能する場合に限り、どのグリッドも統一できます。 一番下の行または一番右の列のタイルが既に右下の色と一致している場合は、一連の四角形操作でタイルを拡張して、最終的にグリッド全体をカバーすることができます。 逆に、最下行または最右列に右下のタイルと異なるタイルが存在する場合は、右下で終わるいかなる四角形操作によっても変更できないため、統合は不可能です。 

この観察により、シミュレーションを完全に回避することができ、問題は、タイルの数が線形である他の重要なタイルと比較して右下のタイルの色をチェックすることに限定されます。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースの寸法を読み取ります。$n$そして$m$を読んでから、$n$グリッドの行。 
2. 右下のタイルの色を特定します。$(n-1, m-1)$。 これがグリッド全体のターゲットカラーになります。 
3. 一番下の行（行）のタイルを調べます。$n-1$) と右端の列 (列$m-1$)、右下のタイル自体を除きます。 
4. 最下行または最右列のタイルが目的の色と異なる場合は、「NO」を出力します。 これは、これらのタイルを、異なる色のタイルを含まずに右下で終了する四角形操作に含めることができないためです。 
5. 最下行および右端列のすべてのタイルがターゲット色と互換性がある場合は、「YES」を出力します。 グリッドの残りの部分は、これらの端から左上に向かって四角形操作を開始して再帰的に塗りつぶすことができます。 
6. すべてのテスト ケースに対して手順 1 ～ 5 を繰り返します。 

機能する理由: このアルゴリズムは、右下のタイルはその色を上または左に拡張するためにのみ使用できるという不変式に依存しています。 最下行または右端の列に沿った不一致があると、この伝播が妨げられ、グリッドを統一することができなくなります。 他のすべてのタイルは、互換性のあるエッジから開始して徐々に大きくなる長方形で覆うことができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        grid = [input().strip() for _ in range(n)]
        target = grid[-1][-1]
        possible = True
        # Check bottom row
        for j in range(m-1):
            if grid[-1][j] != target:
                possible = False
                break
        # Check rightmost column
        if possible:
            for i in range(n-1):
                if grid[i][-1] != target:
                    possible = False
                    break
        print("YES" if possible else "NO")

if __name__ == "__main__":
    solve()
```このソリューションでは、まずすべての入力を効率的にキャプチャし、右下のタイルを基準色として決定します。 一番下の行と右端の列をチェックすると、必要な四角形操作が実行可能であることが保証されます。 の使用`break`不可能なシナリオが検出されたらすぐに終了するようにします。 右下のタイルはそれ自体と自明の互換性があるため、これらのチェックから右下のタイルを除外することで、オフバイワン エラーが回避されます。

 右端の列の (0,0) のタイルはターゲットとは異なります。 アルゴリズムは NO を出力します。 四角形操作では単一の列を W から B に変更できないため、これは予想される動作と一致します。

 一番下の行には W とは異なるタイルがあります。右端の列にも W とは異なるタイルがありますが、最初のチェックは失敗し、YES が出力されます。 これは、長方形がエッジ内の他の互換性のあるタイルから開始して右下の色を伝播できることをアルゴリズムが正しく識別していることを示しています。

## 特殊なケース

 のために$1 \times 1$グリッドの場合、単一タイルは自明に均一であるため、アルゴリズムは YES を出力します。 右下のタイルのみが残りのタイルと異なるグリッドの場合、他のすべてのタイルは右下のタイルと一致するように変換できるため、アルゴリズムは引き続き YES を出力します。 サイズの市松模様で$2 \times 2$の場合、最下行も右端の列も競合するタイルなしでは統合できないため、アルゴリズムは NO を出力します。 これらのエッジケースは、アルゴリズムが最小サイズ、均一なグリッド、不可能な構成を正しく処理していることを確認します。
