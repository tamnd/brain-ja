 ## 解決策
 ## 問題の理解

 配列の連続する要素間の関係記号のシーケンスが与えられ、最初の要素と最後の要素の間の関係を一意に推測できるかどうかを判断するように求められます。 より具体的には、配列自体はわかりませんが、隣接する各ペアについて、最初の要素が 2 番目の要素より小さいか、等しいか、大きいかはわかります。 タスクは、これらの比較が最初の要素が最後の要素より小さいか、等しいか、または大きいかを判断するのに十分であるかどうかを判断することです。 曖昧な点がある場合は、疑問符を付けて報告する必要があります。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは、これらのペアごとの比較を表す最大 100 文字の文字列です。 テスト ケースは最大 500 個あり、操作の合計数は最大 500 × 100 = 50,000 であり、2 秒の制限時間内に十分収まるため、テスト ケースごとに文字列を反復処理するソリューションでも実現可能です。 これにより、より複雑なデータ構造や高度なアルゴリズムが必要になるという懸念が排除されます。 課題は効率ではなく、比較の伝播を理解することです。 

微妙な点は、等号によって引き起こされる曖昧さにあります。 たとえば、次のような文字列`<=<`複数の一貫した数値シーケンスのための余地を残します。 想像できる`[1, 2, 2, 1]`または`[2, 2, 3, 1]`。 このような場合、最初と最後の要素を一意に比較することはできません。 もう 1 つの特殊なケースは、次のような等号のみの文字列です。`===`これは、すべての要素が等しいこと、つまり最初と最後の要素も等しいことを直接意味します。 

## アプローチ

 単純なアプローチは、指定された関係と一致する一連の数値を再構築して、最初と最後の要素の比較が変化するかどうかを確認することです。 これは、考えられるすべての整数の代入を試みることによって行うことができますが、長さが 100 の場合でも、これは組み合わせ的に爆発的に発生します。 概念的には、シーケンスのペアが最初と最後の要素に対して異なる結果を生成する場合、比較があいまいになるため、これは機能します。 ブルート フォースの問題は、実際の値は必要なく、相対的な変更のみが必要なため、数値を列挙するのは過剰であることです。 

最適なアプローチでは、重要な比較は左端と右端の不等号だけであることがわかります。 最初の不等号が小なりの場合、最初の要素は次の要素よりも小さい可能性があります。 同様に、最後の等号以外の記号が「より大きい」場合は、終わりに向かって減少していることを示します。 文字列にのみが含まれている場合`<`、 のみ`>`、または方向が矛盾しない組み合わせであれば、最初と最後の要素の関係を直接判断できます。 あいまいさは、シーケンスに両方が含まれる場合に正確に発生します。`<`そして`>`記号は 0 個以上の等号で区切られます。 間にある等号は順序に影響を与えないため、問題は両方の存在を確認することになります。`<`そして`>`文字列の中で。 両方が存在する場合、答えは次のようになります。`?`。 それ以外の場合、答えは単一の方向が存在するか、または`=`等号のみが存在する場合。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、比較文字列を調べます。 少なくとも 1 つあるかどうかを数える`<`そして少なくとも1つ`>`文字列の中で。 等号は、相対的な順序を変更せず、どちらの方向にもマージできるため、無視されます。 
2. 両方の場合`<`そして`>`存在する、戻る`?`。 これは曖昧さを捉えています。つまり、最初の要素を最後の要素よりも小さくしたり大きくしたりする文字列と一致するシーケンスが存在します。 
3. もしそうなら`<`兆候がある、戻る`<`すべての遷移は、最後の要素が最初の要素と少なくとも同じ大きさになる非減少順序を示すためです。 同様に、`>`兆候がある、戻る`>`。 
4. ある場合`=`標識、戻る`=`すべての要素が等しいからです。 

機能する理由: 重要な特性は、最も外側の方向の変更のみが最初と最後の要素の可能な順序を決定するということです。 等号は曖昧さを生じさせず、両方の記号が存在しても問題ありません。`<`そして`>`シーケンス内のどこにでも、最初と最後の要素が互いより小さいか大きい場合がある、複数の一貫したシーケンスを構築できます。 この不変条件により、値を明示的に再構築しなくても正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    has_less = '<' in s
    has_greater = '>' in s
    if has_less and has_greater:
        print('?')
    elif has_less:
        print('<')
    elif has_greater:
        print('>')
    else:
        print('=')
```このソリューションはテスト ケースの数を読み取り、各比較文字列を反復処理します。 重要な決定は、次の存在を検出することによって行われます。`<`そして`>`文字列の中で。 これにより、実際の数値を配列の位置に割り当てる不必要な試みが回避されます。 文字列を処理する`strip()`末尾の改行文字が包含チェックに干渉しないようにします。 条件チェックの順序も重要です。あいまいなケースが最初にテストされ、次に単一方向のケースがテストされ、最後にすべてが等しいケースがテストされます。 

## 実用的な例

 ### サンプル 1:`>>>`| ステップ | 持っていない | 大きい | 出力 |
 | --- | --- | --- | --- |
 | '>>>' | 偽 | 本当 | '>' |

 すべての兆候は、`>`したがって、最初の要素は最後の要素よりも大きくなります。 

### サンプル 2:`<><=<`| ステップ | 持っていない | 大きい | 出力 |
 | --- | --- | --- | --- |
 | '<><=<' | 本当 | 本当 | 「？」 |

 両方`<`そして`>`が存在するため、最初から最後までの比較があいまいになります。 

これらのトレースは、アルゴリズムが曖昧さの原因として両方向の存在を正確に識別し、一方向のみまたはすべてが等号のシーケンスが一意の決定につながることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        has_less = '<' in s
        has_greater = '>' in s
        if has_less and has_greater:
            out.append('?')
        elif has_less:
            out.append('<')
        elif has_greater:
            out.append('>')
        else:
            out.append('=')
    return '\n'.join(out)

# provided samples
assert run("4\n>>>\n<><=<\n=\n<<==") == ">\n?\n=\n<", "sample 1"

# custom cases
assert run("1\n<") == "<", "single less"
assert run("1\n>") == ">", "single greater"
assert run("1\n=") == "=", "single equal"
assert run("1\n<<<<<") == "<", "all less"
assert run("1\n>>>>>") == ">", "all greater"
assert run("1\n<><><>") == "?", "alternating ambiguity"
assert run("1\n=====") == "=", "all equal signs"
assert run("1\n<==>") == "?", "equal signs in between both directions"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`<`|`<`| 単一の比較、単純なケース |
 |`>`|`>`| 単一の比較、単純なケース |
 |`=`|`=`| 単一の比較が等しい |
 |`<<<<<`|`<`| 複数の小なり記号のみ |
 |`>>>>>`|`>`| 複数の不等号のみ |
 |`<><><>`|`?`| 交互の方向、曖昧さ |

 ## 特殊なケース

 インプットを考慮する`<==>`。 アルゴリズムセット`has_less = True`そして`has_greater = True`したがって、出力は次のようになります`?`。 次のようなシーケンスを構築できるため、これは正しいです。`[1, 2, 2, 0]`作る`a_1 > a_n`、 または`[0, 1, 1, 2]`作る`a_1 < a_n`。 等号は曖昧さを防ぐものではありません。 これにより、競合を判断する際に等号が適切に無視されることが確認されます。 

のために`====`、`has_less = False`そして`has_greater = False`、アウトプットにつながる`=`。 これにより、最小長 2 の配列を含め、すべての要素が等しいというエッジ ケースが正しく処理されます。
