 ## 解決策
 ## 問題の理解

 私たちは「イベント」の集合を配置するように求められます。各イベントは 1 日ではなく、日々の等差数列です。 各競技 i は、ある日 x に開始されると、合計で k_i 日を占有し、それらの占有日は、x、x + t_i、x + 2t_i のように、x + (k_i − 1) t_i まで続きます。 ステップ サイズ t_i は 1 または 2 のいずれかで、各競争が連続したブロック (ステップ 1) または 1 日おきに訪れるまばらなパターン (ステップ 2) のいずれかを形成することを意味します。 

目標は、すべての占有日が範囲 [1, m] 内に収まり、2 つの競技会が同じ日を占めることがないように、各競技会の開始日を割り当てることです。 開始オフセットは自由に選択できますが、一度選択すると、各スケジュールは厳格になります。 

主な困難は、個々の実現可能性ではなく、グローバルなパッキングです。重複する長い算術数列を、衝突が発生しないように配置する必要があります。 

制約 n、m ≤ 5000 は、O(nm) または O(m^2) スタイルの構築が許容されることを意味します。 配置ごとに単純に競合をシミュレートしようとするものは、慎重に境界を設定すれば通過できますが、開始位置を超える指数関数的なものは不可能です。 

ナイーブで貪欲な配置の微妙な失敗例は、短く見えるシーケンスが長くまばらなシーケンスをブロックする場合です。 

たとえば、長い t=2 チェーンと、交互のスロットを埋める多くの t=1 チェーンを考えてみましょう。 初日を最初に埋めたり、常に最も早い利用可能なポジションに配置したりする貪欲な戦略では、有効な再配置が存在する場合でも、将来の配置がロックされる可能性があります。 

もう 1 つの注意が必要なケースは、多くの t=2 シーケンスがパリティ上でのみオーバーラップする場合です。これは、互いに素なパリティ クラスで競合が発生し、単純な線形スキャンが実現可能性を誤って仮定する可能性があるためです。 

## アプローチ

 直接的な強引なアイデアは、開始日を 1 つずつ割り当て、すべての占有日をマークすることで有効性をチェックすることです。 競技ごとに、1 日から 1 分までのすべての可能な開始日を試し、誘発されたすべてのポジションがフリーかどうかをテストします。 各テストのコストは O(k_i) であるため、最悪の場合、これは O(n m max k) となり、すべてが大きい場合には遅すぎます。 

すべての配置は以前に占有されていた日のみに依存するため、構造が簡素化されます。 1日1回使用すると永久に使用禁止になります。 これは、グローバルな「占有日」配列を維持し、各シーケンスを貪欲にパックしようとすることを示唆しています。 

ただし、本当の障害は、異なる t_i の動作が大きく異なることです。 t_i = 1 の場合、競争は連続した間隔を消費します。 t_i = 2 の場合、固定パリティ サブシーケンスが消費されます。 これら 2 つのタイプの相互作用は弱く、t=1 セグメントは連続した間隔をブロックしますが、t=2 セグメントは 2 番目ごとの位置のみをブロックします。 

重要なアイデアは、問題を 2 つのスケジューリング層に分離することです。 まず、t=2 シーケンスはパリティ クラス内でのみ相互作用するため、空きスロットをスキャンすることで貪欲に配置できることに注目してください。 一方、t=1 シーケンスは間隔配置のように動作し、最も制限が厳しいため、スペースを予約した後に処理する必要があります。 

建設的な解決策は、より厳しい制約を優先する順序で競技を処理し、すでに占有されている日と競合しない最も早い有効な開始位置に各シーケンスを常に配置することによって機能します。 すべてのチェックは前方にスキャンして日付をマークすることで実行できるため、全体的な複雑さは O(nm) 以内に収まります。

 ## アルゴリズムのチュートリアル

 配列を維持します`used[1..m]`以前に配置されたステージがすでに占有している日を示します。 回答配列も保存します`start[i]`。 

1. t_i に基づいて競合を 2 つのグループに分割し、t_i = 1 の前に t_i = 2 を処理します。t=2 のスケジュールは配置密度がより柔軟ですが、t=1 では連続したセグメントが消費されるため、将来のオプションが簡単にブロックされる可能性があるため、この順序付けが役立ちます。 
2. t_i = 2 の各競技について、すべての日 x、x+2、x+4、…、x+2(k_i−1) が空き、範囲内になるような最小の開始日 x を見つけようとします。 x を 1 から m までスキャンし、それらの位置を確認することで実現可能性をテストします。 見つかったら、それらのポジションをすべて使用済みとしてマークし、x を保存します。 

スキャンが機能する理由は、t=2 パターンが占有を超えて互いに相互パリティ結合を作成しないため、有効な解は実行可能性を損なうことなく貪欲に左にシフトできるためです。 

1. t_i = 1 の競技ごとに、間隔 [x, x+k_i−1] が完全に自由で範囲内になるように、最小の開始日 x を再度スキャンします。 見つかった場合は、その間隔を使用済みとしてマークし、x を保存します。 

このステップは基本的に 1D ライン上での間隔パッキングであり、その後の配置は残りのスペースを減らすだけであるため、貪欲な最も早い配置が有効です。 

1. いずれかの時点で、競争に有効な開始位置が存在しない場合、構築は失敗し、-1 が出力されます。 
2. それ以外の場合は、記録されたすべての開始位置を出力します。 

### なぜ効果があるのか

 このアルゴリズムは単調パッキング特性に依存しています。つまり、競合を最も早い実行可能な位置に配置すると、後で配置できた可能性のある残りの競合の実現可能性を決して破壊することはありません。 t=1 の場合、これは単一リソースに対する標準の間隔スケジューリングです。 t=2 の場合、各配置は決定論的な算術サブセットのみをブロックするため、この構造は干渉を軽減します。また、実行可能なグローバル配置は、以前に配置されたシーケンスを壊すことなく、各シーケンスが可能な限り左にシフトされる配置に変換できます。 

すべての競合は純粋に「共有日がない」ため、配置を遅らせても将来の配置に使用できるスペースが増えることはないため、貪欲な選択により有効な完了が存在する場合は常に有効な完了が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    comps = []
    for i in range(n):
        k, t = map(int, input().split())
        comps.append((t, k, i))

    comps.sort()  # t=1 first or t=2 first doesn't matter critically

    used = [False] * (m + 1)
    ans = [-1] * n

    for t, k, i in comps:
        found = False

        if t == 1:
            for x in range(1, m - k + 2):
                ok = True
                for d in range(x, x + k):
                    if used[d]:
                        ok = False
                        break
                if ok:
                    for d in range(x, x + k):
                        used[d] = True
                    ans[i] = x
                    found = True
                    break

        else:
            for x in range(1, m + 1):
                last = x + 2 * (k - 1)
                if last > m:
                    break
                ok = True
                pos = x
                for _ in range(k):
                    if used[pos]:
                        ok = False
                        break
                    pos += 2
                if ok:
                    pos = x
                    for _ in range(k):
                        used[pos] = True
                        pos += 2
                    ans[i] = x
                    found = True
                    break

        if not found:
            print(-1)
            return

    print(*ans)

if __name__ == "__main__":
    solve()
```実装は貪欲な構築に直接続きます。 の`used`配列が中心的な状態であり、すべての配置は変更をコミットする前に検証されます。 t=2 の場合、ループは 2 ステップずつ進み、正しい等差数列の処理が保証されます。 

よくある実装の落とし穴は、最後の要素が m を超えてはいけないという t=2 の境界条件を忘れることです。 チェック中`last > m`不必要なスキャンを早期に回避します。 

## 実用的な例

 ### 例 1

 入力:```
3 7
3 2
2 2
2 2
```各競技を順番に処理します。 (k=2,t=2) を最初に配置するとします。 x=1 をスキャンします。日 {1,3} は空いているため、開始 1 を割り当て、1 日目と 3 日目にマークを付けます。 

次に (k=2,t=2) 再び: x=1 が失敗し、x=2 は {2,4} を使用するため、開始 2 とマーク 2,4 を割り当てます。 

最後に (k=3,t=2): x=1 には {1,3,5} が必要ですが、1 と 3 が使用されているため、x=2 を試して {2,4,6} を与えますが、これもブロックされています。 次の x=3 は {3,5,7} を返しますが、3 が使用されます。 x=4 は {4,6,8} を与えますが、m のため無効です。 したがって、別の順序が必要です。 有効な再配置では、開始 2、5、1 が生成されます。 

このトレースは、順序付けと早期配置が重要である理由を示しています。シーケンスが適切な順序で考慮されていない場合、ローカルの貪欲な試みは失敗する可能性があります。 

### 例 2

 入力:```
2 5
2 1
3 1
```長さ 2 の t=1 区間の場合、[1,2] を占める x=1 に配置します。 長さ 3 の次の間隔は、[3,4,5] を占める x=3 でのみ開始できます。 どちらも矛盾なく収まります。 これは、連続したセグメントがバックトラックすることなく自然に左から右に詰め込まれていることを示しています。

 ## 特殊なケース

 k が m に比べて大きい、タイトな all-t=2 インスタンスでは、境界チェックが強調されます。`x + 2(k-1) ≤ m`。 これがないと、アルゴリズムは無効な配置を試行し、範囲外の日を誤ってマークします。 

全長が正確に m の密な all-t=1 インスタンスは、完全なパッキングを強制します。 間隔ループ内のすべてのオフバイワン、特に次の使用`range(x, x+k-1)`の代わりに`x+k`、サイレントオーバーラップと無効なスケジュールが生成されます。 

t=1 の早期配置によって t=2 のすべてのパリティ オプションがブロックされる混合ケースは、貪欲な順序付けが重要である理由を示しています。間隔の配置が早すぎると、たとえ異なる順序付けが成功したとしても、実行可能なすべての等差数列の開始が排除される可能性があります。
