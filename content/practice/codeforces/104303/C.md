 ## 解決策
 ## 問題の理解

 サイズ A、B、C の 3 つの従業員グループが与えられています。すべての従業員をペアに配置する必要があります。つまり、各従業員は他の 1 人の従業員と正確に一致し、一致しない人は一人もいないことになります。 有効なペアは 2 つの状況で形成されます。つまり、両方の従業員が同じ部門に所属しているか、または異なる部門に所属しており、2 つの部門の規模の合計が素数であるかのいずれかです。 

これについて考えるのに役立つ方法は、最初は個人を直接マッチングするのではなく、各部門内で何組のペアを採用し、何組の部門間のペアを使用するかを決定するということです。 すべてのペアリングには正確に 2 人が必要となるため、従業員 A + B + C の合計数は偶数でなければなりません。そうでない場合、全員をすぐにペアリングすることは不可能です。 

制約はテスト ケースの数という点で非常に大きく、最大 200,000 です。各テスト ケースは 100,000 までの 3 つの整数だけであるため、解はテスト ケースごとに O(1) か、最悪でも O(log n) でなければなりません。 ペアリングをシミュレートしたり、組み合わせを検索したりするアプローチは遅すぎます。 

合計が奇数の場合、微妙なエッジケースが発生します。 たとえば、A = 1、B = 1、C = 1 の場合、合計は 3 になります。どのようなペアリング ルールを使用しても、1 人は一致しないままなので、答えは P でなければなりません。もう 1 つの興味深いエッジ ケースは、A = 0、B = 2、C = 2 など、2 つのグループがゼロの場合です。ペアリングはグループ内およびグループ間で可能ですが、実現可能性は、残りのパリティ制約とグループ間の制約が一致するかどうかによって決まります。 

主な問題は、グループ間のペアリングが、個々の従業員ではなく、グループ サイズの合計が素数を形成するかどうかのみに依存することです。 これにより、問題は 3 つの整数にわたる小さな組み合わせの実行可能性チェックに縮小されます。 

## アプローチ

 この問題を直接的に考える方法は、各従業員をノードとして扱い、制約の下で完全なマッチングを構築しようとすることです。 個人間で考えられるすべての組み合わせを試し、部門の状況に基づいて妥当性をチェックすることもできます。 n 個の項目をペアにする方法の数は階乗であるため、これはすぐに指数関数的になります。 

より構造化された強引な方法は、各部門内で何組のペアを採用し、何組の部門間ペアを形成するかを決定することです。 それでも、構成ごとに実現可能性をチェックする必要があり、A、B、C と構成の数が増えるため、大規模な入力では実行できなくなります。 

重要な観察は、部門内のアイデンティティは気にしておらず、カウントだけを気にしているということです。 各部門は同一の要素の山を提供します。 有効な解決策は、制約の下で 3 つの山をペアに分割することと同じです。 グループが 3 つしかないため、有効なマッチング パターンは、使用される交差エッジの数に応じて、構造的なケースの小さなセットに減ります。 

もう 1 つの重要な簡素化はパリティによってもたらされます。 すべての組み合わせで 2 人が削除されるため、A + B + C は偶数でなければなりません。 それ以上に、唯一の問題は、許可されたグループ間条件を尊重してすべての要素をペアにできるように 3 つのグループ間の分布を調整できるかどうかです。 グループ間の妥当性は合計が素数であるかどうかのみに依存し、関係する合計は A+B、B+C、および A+C だけであるため、一定数の構成をチェックするだけで済みます。 

したがって、問題は、3 つのグループ サイズ間のパリティと素数有効隣接関係から導出されるいくつかの構造化パターンをチェックすることに帰着します。

 ## アルゴリズムのチュートリアル

 問題をすべての人がペアにできるかどうかを確認することに落とし込みます。そのため、最初に人の合計数が均等であることを確認します。 そうでない場合は、有効なペアリングが存在しません。

次に、許可されたクロスペアリングの構造を分析します。 部門のペアごとに、そのサイズの合計が素数になるかどうかを確認します。 これにより、最大 3 つのブール条件 (AB 許可、BC 許可、および AC 許可) が与えられます。 

ここで、ペアリングによってすべての要素を完全に削除できるかどうかを検討します。 3 つのクロスペアがすべて禁止されている場合、可能なペアは各部門内のみとなるため、A、B、C はそれぞれ個別に均等である必要があります。 

正確に 1 つまたは 2 つのクロスペアが許可されている場合、グループ間でパリティを転送できる可能性があります。 重要な考え方は、2 つのグループ間のクロスペアが、パリティのバランスをとるために使用可能なカウントをマージするように機能するということです。 これは、許可されたエッジの下にある接続されたコンポーネントが、合計パリティのみが重要となる単一のプールのように動作することを意味します。 

そこで、3 つのノード A、B、C からなるグラフを構築し、合計が素数となるエッジを接続し、連結成分を考慮します。 接続コンポーネント内では、すべてがペアになるまで、許可されたクロスペアを使用してカウントを再配置できるため、各接続コンポーネントについて、その内部の人の合計数は偶数である必要があります。 

最後に、許可されたエッジによって引き起こされる各連結成分をチェックし、その合計が偶数であることを確認します。 すべてのコンポーネントがこの条件を満たしていれば、ペアリングが可能です。 

これが機能する理由は、接続されたコンポーネント内では、許可されたクロスエッジにより、制約に違反することなくグループ間で個体を再分配できるため、そのコンポーネント内の総質量のパリティのみが重要となるためです。 ペアリングでは常に 2 人が削除されるため、局所的に均等であることが必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_prime(x):
    if x < 2:
        return False
    if x % 2 == 0:
        return x == 2
    i = 3
    while i * i <= x:
        if x % i == 0:
            return False
        i += 2
    return True

def solve(a, b, c):
    if (a + b + c) % 2:
        return "P"
    
    ab = is_prime(a + b)
    bc = is_prime(b + c)
    ac = is_prime(a + c)

    # components: 0=A, 1=B, 2=C
    visited = [False] * 3
    arr = [a, b, c]

    edges = [[] for _ in range(3)]
    if ab:
        edges[0].append(1)
        edges[1].append(0)
    if bc:
        edges[1].append(2)
        edges[2].append(1)
    if ac:
        edges[0].append(2)
        edges[2].append(0)

    for i in range(3):
        if not visited[i]:
            stack = [i]
            visited[i] = True
            comp_sum = 0
            while stack:
                u = stack.pop()
                comp_sum += arr[u]
                for v in edges[u]:
                    if not visited[v]:
                        visited[v] = True
                        stack.append(v)
            if comp_sum % 2:
                return "P"
    
    return "R"

t = int(input())
out = []
for _ in range(t):
    a, b, c = map(int, input().split())
    out.append(solve(a, b, c))

print("\n".join(out))
```ペアリングには要素の合計数が偶数である必要があるため、実装では最初にグローバル パリティがチェックされます。 次に、考えられる 3 つのグループ間の合計の素数を計算します。 これらの結果に基づいて、3 つのノードからなる小さなグラフを構築し、接続されたコンポーネントをグループ化します。 各コンポーネントの合計サイズは累積され、いずれかのコンポーネントの合計が奇数の場合、許可された変換ではそのコンポーネント内で完全にペアにすることは不可能です。 

3 つのノードにわたる DFS はテスト ケースごとに一定の作業であり、素数チェックは境界が小さいため十分に高速です。

 ## 特殊なケース

 すべての値がゼロの場合、アルゴリズムは効果的に寄与するノードがないグラフを構築し、合計はゼロ、つまり偶数になります。 各コンポーネントの合計はゼロであるため、ペアリング制約に違反していないため、正しく R が返されます。 

A = B = C = 1 の場合、すべてのクロスサムは 2 (素数) に等しいため、すべてのノードが接続されます。 ただし、合計は 3 で奇数であるため、アルゴリズムはすぐに拒否します。 これは、接続だけではパリティの不均衡を補償できないことを示しています。 

A = 2、B = 2、C = 2 の場合、ペアの合計はすべて 4 であり、素数ではないため、エッジは存在しません。 各コンポーネントは分離されており、合計が偶数であるため、アルゴリズムは受け入れます。 これにより、クロスペアリングが許可されない場合には、分離されたパリティ チェックで十分であることが確認されます。
