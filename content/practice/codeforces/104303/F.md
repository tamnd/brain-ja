 ## 解決策
 ## 問題の理解

 私たちには、人々の有向ネットワークが与えられており、各人は他の何人かの住所を知っています。 誰かがメッセージを受信すると、すぐに知り合い全員に転送します。 このプロセスは特定の人から始まり、無限に繰り返されます。 転送は無条件であり、受信者によって常に転送が再トリガーされるため、メッセージはサイクル内を循環し、ネットワークの到達可能な部分を介して永久に伝播する可能性があります。 

課題は、メッセージのコピーを無限に受信する可能性があるという意味で、どの人が「危険」であるかを判断することです。 これは、最初の送信者から到達可能な転送サイクルにその人が参加している場合、またはそのようなサイクルに入った後に到達できる場合にまさに発生します。 メッセージがサイクルに入ると循環し続け、そのサイクル内のすべてのノード、またはそのサイクルから到達可能なすべてのノードが無限に多くのメッセージを受信します。 

各テスト ケースでは、人数、名前、最初の送信者のインデックス、および誰が誰にメッセージを転送するかを説明する有向隣接リストが得られます。 無限に頻繁に影響を受ける可能性のあるすべての人々を、元の入力順序で出力する必要があります。 

制約は小さく、テスト ケースあたり最大 100 人、テスト ケース最大 1000 件です。 これはすぐに次のことを示唆しています。$O(n^3)$または、最悪のケースが発生するため、テスト ケースごとに複数のグラフを走査することさえも許容されます。$10^5$ノードの合計はありますが、各グラフは小さいです。 

微妙なエッジ ケースは、ソースからは直接到達できないが、別のサイクルに入った後に到達可能になるサイクルから発生します。 たとえば、A が B に到達し、B が C に到達し、C が B に戻る場合、B と C は循環を形成し、両方とも無限になります。 B または C から到達可能なノードも無限になります。 

もう 1 つのエッジ ケースは自己ループです。 ユーザーが自分自身にメッセージを転送すると、他のサイクルが存在しない場合でも、すぐに無限ループが作成されます。 サイクルを明示的に考慮しない単純な到達可能性のみのアプローチでは、この動作が見逃されます。 

最後に、接続されていないコンポーネントも重要です。 開始者から到達可能なコンポーネントのみが問題となりますが、到達可能なコンポーネントに入ると、最初の DFS パス上に直接存在しない場合でも、そのコンポーネント内のすべてのサイクルが考慮される必要があります。 

## アプローチ

 ブルート フォース シミュレーションでは、文字通り段階的にメッセージを伝播し、各ノードがメッセージを受信した回数をカウントします。 サイクルが存在するため、シミュレーションは決して終了しないため、次のようなカットオフを課す必要があります。$n$または$n^2$ノードごとのステップ数。 正しい条件は有限の伝播深さに関するものではなく、有向グラフ内の構造サイクルに関するものであるため、この考えは基本的に不安定です。 シミュレーションに上限を設けたとしても、「無限受信」の検出は信頼性が低くなります。ノードはサイクルに属さずに多くのメッセージを受信する場合や、サイクルに含まれていてもカットオフ後にのみ検出される場合があります。 

正しい観点は、問題をグラフ到達可能性とサイクル検出の問題として再構成することです。 ノードは、ソースから到達可能な有向サイクルに到達できる場合に限り、無限に多くのメッセージを受信します。 メッセージがサイズが 1 を超える強接続コンポーネントまたは自己ループに入ると、そのコンポーネント内のすべてのノードが無限になります。 さらに、転送が無限に続くため、そのようなコンポーネントから到達可能なすべてのノードも無限になります。 

これにより、標準的な分解が行われます。つまり、強接続コンポーネント (SCC) を計算し、グラフをコンポーネントの DAG に折りたたみ、どの SCC が循環であるかを特定し、到達可能なすべての循環コンポーネントとその下流のすべてをマークしながら、ソース SCC からこの凝縮されたグラフを通じて到達可能性を伝播します。 

Tarjan または Kosaraju のアルゴリズムはここに完全に適合します。$n \le 100$により、SCC の計算が簡単になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 素朴なシミュレーション | 無制限/指数関数的な動作 | O(n^2) | 不正確/非実用的 |
 | SCC + 伝播 | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ノードが人物であり、エッジが転送関係を表す有向グラフを構築します。 これにより、メッセージのフローが説明どおりに正確にエンコードされます。 
2. グラフに対して強連結成分分解を実行します。 各 SCC は、相互に到達できるノードをグループ化します。これが、無限のメッセージ循環の背後にある重要な構造特性です。 
3. SCC に複数のノードが含まれている場合、または単一ノードに自己ループがある場合、SCC を周期的としてマークします。 どのサイクルでも繰り返しの再訪問が保証されるため、これによりすべての内部無限受信ソースがキャプチャされます。 
4. 各 SCC がノードになり、元のグラフのメンバー間にエッジがある場合は SCC 間にエッジが存在する、凝縮されたグラフを構築します。 これにより、有向非巡回グラフが生成されます。 
5. 開始者が含まれる SCC を特定します。 これはメッセージ伝播のエントリ ポイントです。 
6. ソース SCC から開始して、圧縮されたグラフに対して DFS または BFS を実行します。 SCC に入るたびに、それが到達可能であるとマークされます。 
7. このトラバース中に、周期的な SCC に到達した場合、それを「無限に感染」としてマークします。 SCC が無限とマークされると、そこから到達可能なすべての SCC も無限になるため、伝播は継続しますが、すべての下流ノードは無限セット内に残ります。 
8. ソース SCC から到達可能なサイクリック SCC に属する、または圧縮されたグラフ内のそのような SCC から到達可能な元のノードをすべて収集します。 

### なぜ効果があるのか

 重要な不変条件は、SCC がグラフの相互到達可能性構造を正確に圧縮することです。 単一の SCC 内では、すべてのノードが他のすべてのノードに到達できるため、すべてのサイクルが 1 つの SCC に完全に含まれます。 周期的な SCC に入ると、再訪問を制限する方法がないため、その SCC 内のすべてのノードは無限に多くのメッセージを受信します。 凝縮されたグラフは DAG であるため、SCC 間の伝播では新しいサイクルを作成できません。そのため、無限大は SCC レベルでのみ発生し、前方に広がります。 これにより、サイクリック SCC から到達可能なすべての SCC をマークすることで、無限に多くのメッセージを受信するノードだけを正確にキャプチャし、それ以外は何も受信しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    T = int(input())
    
    for _ in range(T):
        n, m = map(int, input().split())
        names = input().split()

        g = [[] for _ in range(n)]
        for i in range(n):
            parts = list(map(int, input().split()))
            k = parts[0]
            for v in parts[1:]:
                g[i].append(v - 1)

        # Tarjan SCC
        idx = 0
        stack = []
        onstack = [False] * n
        disc = [-1] * n
        low = [0] * n
        comp_id = [-1] * n
        comps = []
        
        def dfs(u):
            nonlocal idx
            disc[u] = low[u] = idx
            idx += 1
            stack.append(u)
            onstack[u] = True

            for v in g[u]:
                if disc[v] == -1:
                    dfs(v)
                    low[u] = min(low[u], low[v])
                elif onstack[v]:
                    low[u] = min(low[u], disc[v])

            if low[u] == disc[u]:
                comp = []
                while True:
                    x = stack.pop()
                    onstack[x] = False
                    comp_id[x] = len(comps)
                    comp.append(x)
                    if x == u:
                        break
                comps.append(comp)

        for i in range(n):
            if disc[i] == -1:
                dfs(i)

        c = len(comps)
        comp_has_cycle = [False] * c

        for i, comp in enumerate(comps):
            if len(comp) > 1:
                comp_has_cycle[i] = True
            else:
                u = comp[0]
                if u in g[u]:
                    comp_has_cycle[i] = True

        cg = [[] for _ in range(c)]
        for u in range(n):
            for v in g[u]:
                if comp_id[u] != comp_id[v]:
                    cg[comp_id[u]].append(comp_id[v])

        start = comp_id[m - 1]

        from collections import deque
        q = deque([start])
        vis = [False] * c
        vis[start] = True

        bad = [False] * c
        while q:
            u = q.popleft()
            if comp_has_cycle[u]:
                bad[u] = True

            for v in cg[u]:
                if not vis[v]:
                    vis[v] = True
                    bad[v] = bad[u]
                    q.append(v)
                else:
                    if bad[u]:
                        bad[v] = True

        res = []
        for i in range(n):
            if bad[comp_id[i]]:
                res.append(names[i])

        if res:
            print(len(res))
            print(*res)
        else:
            print("No one is disturbed!")

if __name__ == "__main__":
    solve()
```実装は、グラフを読み取り、隣接リストを構築することから始まります。 SCC ステップでは Tarjan のアルゴリズムが使用され、検出時間と低リンク値によってコンポーネント ルートが特定されます。 各ノードにはコンポーネント ID が割り当てられており、これによりグラフを折りたたむことができます。 

SCC 分解後、循環コンポーネントを明示的にマークします。 単一ノード SCC は自動的に安全ではなく、自己ループをチェックする必要があるため、この手順は不可欠です。 

次に、圧縮されたグラフが構築され、最初の送信者を含む SCC から BFS が開始されます。 の`bad`配列はコンポーネントがサイクルの影響を受けるかどうかを追跡します。 コンポーネントが不良とマークされると、そのコンポーネントは下流のすべての伝播に対して不良のままになります。 

最後に、コンポーネント レベルの結果を入力順に個々の人々にマッピングします。

 ## 特殊なケース

 自己ループは SCC マーキング内で処理されます。単一ノード コンポーネントは検証によってチェックされます。`u in g[u]`。 これにより、SCC サイズが 1 であっても、それ自体に転送するノードは確実にサイクリックとして扱われます。 

切断されたグラフでは、開始 SCC から到達可能なノードのみが考慮されます。 BFS はソース SCC から開始するため、到達不能なコンポーネントが訪問セットに入ることはなく、誤ってマークされることはありません。 

サイクルのない純粋なチェーンは、到達可能性だけでは無限のメッセージを意味しないことを示しています。 SCC が周期的とマークされていないため、`bad`伝播はトリガーされず、出力は空のままです。
