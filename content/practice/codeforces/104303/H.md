 ## 解決策
 ## 問題の理解

 文字だけからなる文字列が与えられます`X`、`T`、 そして`U`。 各テスト ケースについて、次のプロパティを持つ部分文字列の数を数える必要があります。`X`、`T`、 そして`U`その部分文字列内の文字はすべて等しいです。 

ここでの部分文字列は元の文字列の連続したセグメントであるため、可能なすべての間隔を効果的にスキャンし、3 つの文字タイプにわたるバランス状態をチェックしています。 出力は、そのようなバランスのとれた部分文字列がいくつ存在するかを表す、テスト ケースごとに 1 つの整数です。 

制約`len(S) ≤ 10^4`テストケースごとに最大`T = 100`ケースは合計入力サイズを示唆しています`10^6`最悪の場合の文字。 これにより、テスト ケースごとに 2 次的な解はすでに除外されています。`O(n^2)`約につながるだろう`10^8`ケースごとの操作と最大`10^{10}`全体的に大きすぎます。 

微妙なエッジケースは、文字列が非常に歪んでいる場合です。たとえば、`"XXXXXXXXXX"`。 長さ 3 の部分文字列は有効になりません。`T`または`U`全然キャラクター。 部分文字列の長さが 3 で割り切れるかどうかだけをチェックする単純なアプローチでは、文字の分布を無視すると、多くの部分文字列が誤ってカウントされてしまいます。 

もう 1 つのエッジ ケースは、文字がパターン内に均等に分散されているが、固定ブロックに整列していない場合です。`"XTUXTU"`。 有効な部分文字列がいくつか存在しますが、それらは必ずしも周期構造と一致しているわけではないため、プレフィックスベースの変換が使用されない場合はブルート チェックが必要です。 

## アプローチ

 直接的なアプローチは、すべての部分文字列を列挙し、各部分文字列について次の出現回数をカウントすることです。`X`、`T`、 そして`U`。 3 つのカウントがすべて等しい場合、答えが増加します。 これは定義を直接チェックするので正しいです。 

ただし、各部分文字列の頻度を個別にカウントすると、再計算が必要になります。 各文字の接頭辞の合計を維持したとしても、`O(1)`部分文字列ごとにチェックしますが、すべての部分文字列の生成は残ります`O(n^2)`。 と`n = 10^4`、これは約になります`10^8`テスト ケースごとに部分文字列が必要になるため、遅すぎます。 

重要な観察は、3 つのカウントの等価性が 2 つの差の等価性に変換できるということです。 カウント間のプレフィックスの違いを追跡すると、変換された座標系でその端点が同じ「状態」を共有する場合に限り、部分文字列のカウントは等しいことがわかります。 

プレフィックス数を定義する`cx[i]`、`ct[i]`、`cu[i]`。 部分文字列の場合`(l, r]`、平等とは次のことを意味します。`cx[r] - cx[l] = ct[r] - ct[l] = cu[r] - cu[l]`。 

並べ替えると次のようになります。`cx[r] - ct[r] = cx[l] - ct[l]`そして`cx[r] - cu[r] = cx[l] - cu[l]`。 

したがって、各プレフィックス位置は値のペアにマッピングでき、有効な部分文字列は等しい状態のペアに対応します。 部分文字列をカウントすることは、等しいプレフィックス状態のペアをカウントすることになり、これは周波数マップを使用して実行できます。 

文字列を反復処理し、プレフィックス数を維持し、各状態が出現する頻度を保存します。 ある状態を再訪するたびに、その前の頻度を答えに追加します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(1) または O(n²) | 遅すぎる |
 | プレフィックス状態ハッシュ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、等しいプレフィックス状態を数えるという問題に変換します。 

1. 3 つの実行カウンターを維持する`cx`、`ct`、`cu`、最初はゼロです。 これらは、現在の位置までに見た各キャラクターの数を表します。 
2. 各プレフィックス インデックスの状態を次のように定義します。`(cx - ct, cx - cu)`。 これにより、3 カウントの等しい条件が 2 つの値に圧縮されます。 
3. 辞書を使う`freq`これまでに各状態が発生した回数を保存します。 状態で初期化します`(0, 0)`頻度 1 を持ち、文字列が始まる前の空のプレフィックスを表します。 
4. 文字列を左から右にスキャンします。 文字ごとに、対応するカウンターを更新します。 
5. 位置更新後`i`、現在の状態を計算します`(cx - ct, cx - cu)`。 
6.追加`freq[state]`答えは、同じ状態が以前に出現するたびに、次で終わる有効な部分文字列が形成されるためです。`i`。 
7. インクリメント`freq[state]`1までに。 

重要な推論ステップは、2 つの接頭辞の状態が一致するときはいつでも、それらの間の部分文字列には等しい数の文字列が含まれるということです。`X`、`T`、 そして`U`。 部分文字列を明示的にチェックしているのではなく、代わりに、プレフィックス空間内でバランス条件が一致する頻度をカウントしています。 

### なぜ効果があるのか

 このアルゴリズムは、各プレフィックス状態が文字数間の相対的な違いを一意にエンコードするという不変式に依存しています。 2 つのインデックスが同じ状態を共有する場合、それらのプレフィックス数を減算するとすべての差異がなくなり、それらの間の部分文字列内の 3 文字すべてのカウントが等しくなります。 逆に、有効な部分文字列はそのエンドポイントで同一のプレフィックス状態を生成する必要があるため、すべての有効な部分文字列は等しい状態のペアとして 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []
    
    for _ in range(T):
        s = input().strip()
        
        cx = ct = cu = 0
        freq = {(0, 0): 1}
        ans = 0
        
        for ch in s:
            if ch == 'X':
                cx += 1
            elif ch == 'T':
                ct += 1
            else:
                cu += 1
            
            state = (cx - ct, cx - cu)
            ans += freq.get(state, 0)
            freq[state] = freq.get(state, 0) + 1
        
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、接頭辞状態の考え方に直接準拠しています。 カウンタは累積頻度を維持し、辞書は`freq`各状態が出現した回数を格納します。 決定的なラインは、`ans += freq.get(state, 0)`、等価条件を満たす、現在の位置で終わるすべての部分文字列をカウントします。 

初期化`freq = {(0, 0): 1}`空のプレフィックスが有効な開始参照として扱われるため、インデックス 0 で始まる部分文字列が正しくカウントされるようになります。 

現在の状態の頻度を増やす前に、回答を更新するように注意する必要があります。 逆にすると、同じ位置にある空の部分文字列が複数回誤ってカウントされてしまいます。

 ## 特殊なケース

 重要なエッジ ケースは、文字列に 1 つまたは 2 つの異なる文字しか含まれていない場合です。 たとえば、入力`"XXTTXX"`決して含まない`U`したがって、等しい数を満たす部分文字列はありません。 状態が次のとおりであるため、アルゴリズムはこれを自然に処理します。`(cx - ct, cx - cu)`些細なケースを超えて、3 つのカウンタすべてのバランスを同時に取るような方法で繰り返されることはありません。`ans`ゼロのままです。 

もう 1 つのエッジ ケースは、次のような完全にバランスの取れた連結です。`"XTUXTU"`。 ここでは、複数の部分文字列が重複し、同じプレフィックス状態を再利用します。 状態の各繰り返しは、それまでのすべての発生に対してカウントされるため、重複する有効な部分文字列は追加のロジックなしで自然に含まれます。 

最後に、次のような単一文字列`"X"`または`"T"`初期状態なので正しく初期化してください`(0,0)`完全なバランスが達成された場合にのみ一致しますが、完全なバランスが達成されることは決してないため、出力はゼロになります。
