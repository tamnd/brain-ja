 ## 解決策
 ## 問題の理解

 私たちには学生のプールが与えられ、各学生は最大 60 のトピックのサブセットを知っています。 有効なチームとは、2 つの条件が同時に満たされる学生のサブセットです。1 から p までのすべてのトピックが少なくとも 1 人のチーム メンバーによってカバーされ、各トピックについて最大 1 人のチーム メンバーがそれを知ることが許可されます。 言い換えれば、すべてのトピックについて、選択したサブセットを見ると、そのトピックは 0 人または 1 人の知識セットに現れることができますが、複数人になることはできませんが、それでもすべてのトピックがチーム内のどこかに現れることが必要です。 

課題は、これらの制約を満たす生徒のサブセットが何人いるかを数えることです。 

最も重要な構造的結果は、すべてのトピックが、そのトピックを両方とも含む 2 人の生徒のペアを禁止する制約のように動作すると同時に、そのトピックが全体で少なくとも 1 回は表示されるように強制することです。 各生徒は最大 60 ビットのサブセットで表され、n は最大 42 であるため、自然検索空間は生徒のすべてのサブセット (2^42) であり、すでに約 4.4 兆個の可能性があります。 サブセットを直接列挙するソリューションは実行不可能です。 

生徒の中に何らかのトピックが存在しない場合、微妙なエッジケースが現れます。 その場合、カバレッジ要件を満たすことができないため、有効なチームは存在しません。 たとえば、p = 3 でトピック 2 を誰も知らない場合、すべての学生を選択したとしても、トピック 2 はまだ明らかにされていないため、答えはゼロでなければなりません。 

別の失敗モードは、2 人の生徒がトピックを共有するときに現れます。 単純なサブセット数には両方が含まれますが、そのようなサブセットは他のトピックに関係なく無効であるため、最後だけをチェックするのではなく、枝刈りが必要です。 

## アプローチ

 ブルート フォース ソリューションでは、生徒のすべてのサブセットを反復し、サブセット内のトピックの和集合を計算し、和集合には p 個のトピックがすべて含まれている必要があり、トピックが 2 回出現してはいけないという 2 つの条件をチェックします。 2 番目の条件は、サブセットごとに周波数配列を維持するか、構築中に重複を追跡することによってチェックできます。 ビットマスクを使用した場合でも、これには依然として 2^42 のサブセットを反復処理する必要があり、サブセットごとに最大 42 人の生徒または 60 ビットをスキャンする必要があり、実行可能な制限をはるかに超える複雑さになります。 

重要な観察は、「選ばれた 2 人の学生にはトピックが表示されない」という制約により、有効な各チームが、選ばれた学生が互いに素なビットマスクを持つ必要がある構造になってしまうということです。 これは、和集合がすべての p ビットをカバーする、ペアごとに共通でない集合のサブセットを数えていることを意味します。 これは典型的な素集合パッキング問題です。 

n はわずか 42 ですが、p は最大 60 であるため、学生に対する直接部分集合 DP は大きすぎます。 この体制における標準的な手口は中間者合わせです。 学生を最大 21 人のサイズの 2 つの半分に分割します。各半分は独立して列挙でき、サブセットごとに 2 つの情報を記録します。それは、カバーするトピックのビットマスクと、それが内部的に有効かどうか (半分内で重複はありません) です。 

半分ごとに、すべての有効なサブセットを生成し、カバレッジ マスクごとにグループ化します。 半分にまたがる素の条件は単純なビット単位の AND 制約になります。マスク L を持つ左のサブセットとマスク R を持つ右のサブセットは、L & R = 0 の場合にのみ結合できます。カバレッジ要件は L | になります。 R = フルマスク。 

その後、カウントは、補数マスクを使用して、すべての有効な左の状態を反復し、互換性のある右の状態を照合することになります。 適切なマスクの頻度を事前に計算すると、高速な集約が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 真ん中で会う | O(2^(n/2) · 2^(n/2)) | O(2^(n/2)) | 承認済み |

 ## アルゴリズムのチュートリアル

 学生を左右の 2 つのグループに分け、それぞれのグループに約 n/2 人ずつ参加させました。

1. 各生徒の知識セットを p ビットのビットマスクに変換します。 これにより、トピックごとのループではなくビット操作を使用して、結合および交差チェックを高速に行うことができます。 
2. 左半分のすべてのサブセットを列挙します。 各サブセットについて、その共用体マスクを構築し、同時にサブセット内にトピックが 2 回出現しないことを検証します。 私たちはマスクを実行し、「これまでのところ有効」な状態を維持します。 新しい生徒が現在のマスクと重なる場合、そのサブセットは破棄されます。 
3. すべての有効な左サブセット マスクを頻度テーブルに保存します。 複数のサブセットが同じマスクを生成する場合、後で照合するためにそれらを区別できないため、それらをまとめてカウントします。 
4. 右半分に対して同じプロセスを繰り返し、有効な右マスクの度数表を作成します。 
5. マスクのペア (L、R) ごとに、L は左側のテーブルから、R は右側のテーブルから取得されます。次の 2 つの条件をチェックします。L と R はゼロである必要があり、L | R である必要があります。 R はトピックの完全なセットに等しくなければなりません。 両方が成立する場合、答えへの寄与は freqL[L] × freqR[R] となります。 
6. すべての寄与を合計し、結果を出力します。 

半分を独立して組み合わせることができる理由は、各半分の内部の妥当性がすでにその半分内での素性を強制しているためです。 クロスハーフの競合はビット単位の AND を使用して明示的に処理されるため、無効なオーバーラップはマージ ステップで生き残ることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gen_half(arr, p):
    n = len(arr)
    res = {}
    for mask in range(1 << n):
        ok = True
        cur = 0
        for i in range(n):
            if mask >> i & 1:
                x = arr[i]
                if cur & x:
                    ok = False
                    break
                cur |= x
        if ok:
            res[cur] = res.get(cur, 0) + 1
    return res

def solve():
    T = int(input())
    for _ in range(T):
        n, p = map(int, input().split())
        full = (1 << p) - 1
        a = []
        for _ in range(n):
            tmp = list(map(int, input().split()))
            k = tmp[0]
            mask = 0
            for x in tmp[1:]:
                mask |= 1 << (x - 1)
            a.append(mask)

        mid = n // 2
        left = a[:mid]
        right = a[mid:]

        L = gen_half(left, p)
        R = gen_half(right, p)

        ans = 0
        for lm, lv in L.items():
            for rm, rv in R.items():
                if (lm & rm) == 0 and (lm | rm) == full:
                    ans += lv * rv

        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、各生徒の知識をビットマスクとしてエンコードすることから始まります。 これにより、すべてのトピック操作が O(1) ビット単位の操作に削減されます。 

機能`gen_half`学生の半数のすべてのサブセットを列挙します。 各サブセット マスクについて、トピックの結合を構築し、サブセット内で重複が発生しないようにします。 小切手`cur & x`新入生がサブセット内にすでに存在するトピックを共有しているかどうかを検出します。 

複数のサブセットが同じカバレッジを生成する可能性があるため、各有効なサブセットは、結果として得られるカバレッジ マスクを周波数辞書に提供します。 

両方の半分を生成した後、最後のステップで互換性をチェックします。 条件`(lm & rm) == 0`半分全体に非結合性を強制し、`(lm | rm) == full`すべてのトピックを完全にカバーします。 

各半分には最大 2^21 のサブセットがあるため、マスクに対するネストされた反復は許容されます。 

## 実用的な例

 p = 3 と 4 人の生徒の小さなケースを考えてみましょう。 

学生 1 = {1}、学生 2 = {2}、学生 3 = {3}、学生 4 = {1,2} は、ペアリングに応じた重複制約のため、1 または 2 のみのサブセットでは無効です。 

左の {1,2} と右の {3,4} に分割します。 

### 左半分の列挙

 | サブセット | マスクマスク 有効 |
 | --- | --- | --- |
 | ∅ | 000 | はい |
 | {1} | 001 | はい |
 | {2} | 010 | はい |
 | {1,2} | 011 | はい |
 | {4} | 011 | はい（単品） |

 これにより、マスク 011 が 2 回出現するような頻度カウントが生成されます。 

### 右半分の列挙

 | subset | マスクマスク 有効 |
 | --- | --- | --- |
 | ∅ | 000 | はい |
 | {3} | 100 | はい |
 | {4} | 011 | はい |

 では、組み合わせてみましょう。 結合が 111 で交差が 0 であるペアのみを受け入れます。 したがって、左マスク 011 は右マスク 100 とのみペアリングできます。 

このトレースは、有効性が半分の内側で完全にローカルであり、グローバル制約がマージ時にのみ適用されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(2^(n/2) · 2^(n/2)) | 両方の半分のすべてのサブセットを列挙し、マスクを照合します。 
| スペース | O(2^(n/2)) | サブセットマスクの周波数マップを保存する |

 n ≤ 42 の場合、各半分には最大 2^21 ≈ 200 万のサブセットがあります。 このアプローチは、ビット操作と辞書集約を使用して実装された場合、Python の制限内に収まります。

 ## 特殊なケース

 すべての学生が少なくとも 1 つの共通のトピックを共有する場合、少なくとも 2 のサイズのサブセットが「トピックの繰り返し禁止」ルールに違反するため、答えは直ちにゼロになります。 サブセットの列挙中に、両方の生徒を含むペアがトリガーされるため、アルゴリズムはこれを自然に処理します。`cur & x != 0`、すべての複数要素のサブセットを削除します。 

トピックが欠落しているケースの結果は次のとおりです。`full`決して到達できない。 左右のマスクが重ならないように組み合わせても、`(lm | rm) == full`は決して成り立たないので、累積された答えはゼロのままです。 

同一の生徒が多数いるケースは、マスク マップの頻度集約によって処理されます。 サブセットは組み合わせ的に異なりますが、同一のマスクにまとめられるため、最終的なマージ ステップで乗算によって正しくカウントされます。
