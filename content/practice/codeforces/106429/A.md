 ## 解決策
 ## 問題の理解

 要素の円形配置を表す文字列と、ターゲット パターンを表す別の文字列が与えられます。 タスクは、元の円形配置を回転することによってターゲット パターンが得られるかどうかを判断することです。 

円運動の観点から考える代わりに、元の文字列を取得し、それを一定の位置だけ左にシフトし、最後に巻き付ける操作として再解釈する方が簡単です。 すべての有効な構成は、これらのローテーションの 1 つにすぎません。 目標は、少なくとも 1 つの回転がターゲットと正確に一致するかどうかを判断することです。 

入力は同じ長さの 2 つの文字列を記述します。1 つは基本構成として機能し、もう 1 つは回転後に照合するパターンとして機能します。 出力は、そのような回転が存在するかどうかに応じて、単純に「はい」または「いいえ」の決定を行います。 

制約構造は、文字列が大きくなる可能性があることを意味しており、通常は最大約 10^5 文字になります。 すべての回転を試行し、文字ごとに比較する 2 次解では、最悪の場合、N^2 程度の比較が必要になりますが、標準の制限の下では遅すぎます。 これにより、すべての回転を線形時間でテストできるアプローチにすぐに進むことができます。 

ここではいくつかの特殊なケースが重要です。 両方の文字列が同一の場合、ゼロ回転が機能するため、答えは自明に「はい」になります。 文字列に異なる文字マルチセットがある場合、たとえば`abac`そして`zzzz`、回転によってその不一致を修正することはできず、単純な回転チェックは依然として早い段階で失敗します。 別の微妙なケースは、次のような繰り返しパターンが存在する場合に発生します。`aaaaa`そして`aaaaa`、すべての回転が有効です。 不注意な実装では、複数の冗長な比較が誤って試行される可能性がありますが、正確さには影響がありません。 

## アプローチ

 ブルートフォースのアイデアは単純です。元の文字列の可能なすべての回転を生成し、それをターゲットと比較します。 各ローテーションは、文字列を位置 k でスライスし、サフィックスをプレフィックスと連結することによって構築できます。 このような各候補について、文字ごとにターゲットと比較します。 

これは、サーチ スペース内のすべての設定を明示的にチェックするため機能します。 ただし、コストが高い。 各回転の構築と比較には O(N) がかかり、N 回の回転があるため、合計操作は O(N^2) になります。 N が約 100,000 の場合、これは実行不可能になります。 

重要な観察は、文字列のすべての回転がそれ自体の 2 倍化されたバージョンの中に含まれていることです。 文字列をそれ自体と連結すると、すべての巡回シフトは、この 2 倍になった文字列の連続した部分文字列として表示されます。 たとえば、次の回転`abcd`は`abcd`、`bcda`、`cdab`、`dabc`、それらすべてが中に表示されます`abcdabcd`。 

これにより、問題は部分文字列検索に集約されます。必要なのは、ターゲット文字列が`S + S`。 回転を明示的に生成する代わりに、線形部分文字列検索を使用して 1 回スキャンします。 単純な実装では直接スライス比較を使用しますが、各開始位置が最大 1 回チェックされ、比較がすぐに短絡されるため、全体としては依然として O(N) です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^2) | O(N) | 遅すぎる |
 | ダブルストリングスキャン | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの文字列を読み取り、それらを S および T と呼びます。長さが異なる場合は、回転によって長さが維持されるため、解は存在しないと直ちに結論付けます。 これにより、不正な入力またはエッジ入力での不必要な作業が回避されます。 
2. S をそれ自体と連結して、新しい文字列 U を構築します。 このステップでは、S のすべての循環回転を U の部分文字列としてエンコードします。 
3. 0 から len(S) - 1 までのすべての開始位置 i を繰り返します。各位置は回転の候補を表します。 
4. 各 i について、部分文字列 U[i : i + len(S)] と T を比較します。それらが完全に一致する場合は、すぐに肯定的な答えを返します。 
5. 一致する位置がない場合は、否定的な応答を返します。 

比較ステップはアルゴリズムの中核です。 すべてのローテーションが 2 倍の文字列内の 1 つの開始インデックスに正確に対応するため、有効な設定がスキップされないため、安全です。 

### なぜ効果があるのか

 正確かどうかは、循環回転によって文字の相対的な順序が保持され、開始点が移動するだけであるという事実に依存します。 S + S を形成すると、S のインデックス i から始まる回転は、S + S の i から始まる長さ len(S) の部分文字列に対応します。 これにより、回転と 2 倍化された文字列内の固定長の部分文字列との間に 1 対 1 のマッピングが確立されます。 したがって、これらの部分文字列の中から T を検索することは、すべての回転をチェックすることと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    S = input().strip()
    T = input().strip()

    if len(S) != len(T):
        print("NO")
        return

    n = len(S)
    U = S + S

    for i in range(n):
        if U[i:i+n] == T:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```実装は、部分文字列検索への削減の直後に続きます。 2 倍の文字列 U が一度構築され、それからサイズ n のウィンドウをスライドさせます。 Python は不一致の場合の比較を短縮し、一般的な入力に対する平均動作を線形に保つため、スライス比較は安全です。 

さりげないディテールはループ綴じです。 インデックス n を超えて開始すると、以前の位置ですでにカバーされていた回転が繰り返されるため、2n ではなく n までのみ反復します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    S = input().strip()
    T = input().strip()

    if len(S) != len(T):
        return "NO"

    U = S + S
    n = len(S)

    for i in range(n):
        if U[i:i+n] == T:

assert run("abcd\nacbd\n") == "NO"
assert run("aaaa\naaaa\n") == "YES"

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての文字が同一である場合です。 S の場合 =`aaaaa`そしてT =`aaaaa`、すべての回転は同一です。 アルゴリズムは U = を形成します。`aaaaaaaaaa`、すべてのウィンドウが T に一致します。最初の反復ではすでに YES が返され、最大の繰り返しが正しく処理されます。 

もう 1 つのケースは、文字数が異なるためにどの回転も一致しない場合です。 S の場合 =`abc`そしてT =`abd`、U =`abcabc`。 すべてのウィンドウには文字 a、b、c のみが含まれるため、T との比較はすぐに失敗し、ループはすべての位置を使い果たし、正しく NO を返します。 

最後の微妙なケースは、二重化された文字列の境界で一致が発生する場合です。 S の場合 =`bcda`、T =`dabc`、U =`bcdabcda`。 有効な一致はインデックス 3 から始まり、元の境界を越えます。 S + S はラップアラウンドの連続性を正確に保持するため、スライディング ウィンドウは依然としてそれをキャプチャします。
