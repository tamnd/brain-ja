 ## 問題の理解

 整数のマルチセットが与えられ、それぞれが固定ビット数を使用してバイナリで表現されます。 任意の整数候補に対して$x$、そのスコアをすべての配列要素の合計として定義します。$a_i$、間の一致する最下位ビットの数$x$そして$a_i$。 同様に、それぞれについて、$a_i$、最長のサフィックス (最下位ビットから開始) を調べます。$x$そして$a_i$同意するので、その長さを答えに追加します。 

各クエリは、特定の構造を選択する変更された状況を考慮するように求めます。$x$(サブタスクで説明されている配列構造に応じて)、暗黙の制約の下で達成可能な最大スコアを計算する必要があります。$x$形成することができる。 

この問題に隠された重要な構造は、類似性がバイナリ表現の共有サフィックスによって定義されるということです。 このことから、上位ビットに関する決定は、下位ビットが要素をどのようにグループ化するかに大きく依存していることがすぐにわかります。これは、下位ビットで 2 つの数値が発散すると、上位ビットはその寄与を回復できないためです。 

この制約は、すべてのペアのすべてのビットを繰り返し調べる必要があるため、すべてのペアについて二次時間ですべてのクエリのペアごとのビット一致を再計算できないことを意味します。 と$n$一般的な Codeforce の制限とビット長まで$K$20～30歳くらいの純朴な$O(n^2 K)$このアプローチは遅すぎるため、クエリごとにリニア スキャンを繰り返しても、クエリが多数ある場合は拡張できません。 

微妙なエッジケースは、最適な設定がどの程度厳密であるかによって発生します。$x$制約されている。 ビットを独立して扱うか、各ビットを貪欲に選択すると、寄与は独立したビットの一致ではなく、最も長い共有サフィックスに依存するため、相互作用を簡単にカウントしすぎてしまう可能性があります。 たとえば、次の場合$a = 0101$そして$b = 0111$、そして私たちは選びます$x = 0111$からの寄稿$a$そして$b$個々のビットの一致だけではなく、最初に分岐する場所によって決まります。 

別の失敗例は、複数の候補が存在する場合に発生します。$x$上位ビットのみが異なり、下位ビットでは非常に異なるグループ化が引き起こされるものが存在します。 単純な「1 つの要素とできるだけ多くのビットを一致させる」戦略は、集計の寄与を無視するため、ここで破綻します。 

## アプローチ

 強引なアイデアは簡単です。すべての候補の構築を試してください。$x$、すべてと比較してスコアを計算します。$a_i$、そして最高のものを手に入れましょう。 候補者を問題の構造からインスピレーションを得た形式に制限したとしても、それでも少なくとも次のような結果が得られます。$O(n^2 K)$の各評価以来、最悪の場合の動作$x$すべての配列要素をスキャンし、ビットごとの一致を計算する必要があります。 

重要な観察は、類似性は基本的に共有サフィックスに関するものであるということです。これは、最下位ビットから上に向かって構築されたバイナリ トライで数値を編成することを示唆しています。 このようなトライでは、各ノードは反転したバイナリ表現のプレフィックスを表し、元の数値の共有サフィックスを意味します。 これにより、スコアリング関数は、要素をトライ サブツリーに分割する方法に依存するものに変わります。 

このように問題を捉えると、ペアごとの比較について考えるのをやめ、代わりにサブツリーの寄与という観点から考えるようになります。 各サブツリーは、固定接尾辞を共有する要素をグループ化し、次の値を選択します。$x$この構造を通るパスを選択することに対応します。 サブツリーからの寄与は、そこに存在する要素の数と、それらを分割する前にどれだけ深く調査するかによってのみ決まります。 

これは自然にトライでの動的プログラミングにつながります。 各ノードについて、最適かどうかを決定します。$x$完全に左側のサブツリーまたは右側のサブツリーに存在します。 それがサブツリー内にある場合、そのビットは以下のすべての要素で共有されるため、そのサブツリーからの完全な寄与に加えて、サブツリーのサイズに等しい追加のビット寄与が得られます。

 ## アルゴリズムのチュートリアル

 最下位から最上位のビットを使用して各数値が挿入されるバイナリ トライを構築します。 各ノードは、元の数値の接尾辞に対応する、反転されたビットの接頭辞を表します。 

すべてのノードについて、そのサブツリー内の要素の数を維持します。 このカウントは、そのサブツリー内のすべての要素にわたってビットを整列するときにどれだけの寄与が得られるかを直接決定するため、非常に重要です。 

また、各ノードの DP 値も定義します。これは、選択に限定した場合に達成可能な最高のスコアを表します。$x$そのサブツリー内で。 

これらの DP 値は、トライの最も深いレベルから始めてボトムアップで計算されます。 

ノードでは 2 つの可能性を検討します。 私たちはどちらかを選択します$x$完全に左側の子サブツリーに存在するか、完全に右側の子サブツリーに存在します。 左側のサブツリーを選択した場合、このビットはすべての要素に一致するため、そのサブツリー内のすべての要素が現在のビットの追加単位に寄与します。 同じロジックが右側のサブツリーにも対称的に適用されます。 

これにより、DP 値が 2 つのサブツリー選択肢の最大値となる遷移が得られます。各選択肢は、子 DP にそのサブツリーのサイズを加えたもので構成されます。 

ルートに到達するまでこの計算を上向きに繰り返します。ルートの DP 値によって完全なセットの答えが得られます。 

(問題の完全版で) 更新が発生すると、更新された要素の挿入パスに沿ったノードのみを変更し、サブツリーのサイズまたは構造が変更されたのはそれらのノードのみであるため、DP 値を上方に再計算します。 

### なぜ効果があるのか

 各ノードの DP 状態は、固定サフィックス グループに制約された達成可能な最良のスコアを取得します。 有効な選択肢はどれか$x$トライの降順に対応する必要があり、各レベルでの決定は、正確にどの子サブツリーが次のビットを定義するかによって決まります。$x$。 より深いビットからの寄与は、すでにグループ化されている要素にのみ依存するため、問題をサブツリーで分割すると、すべての相互作用が保存されます。 最適な構造では、両方の子からの寄与を同じレベルで混合する必要はありません。これは、単一のバイナリ選択のプレフィックスの一貫性に違反するためです。$x$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("ch", "cnt", "dp")
    def __init__(self):
        self.ch = [None, None]
        self.cnt = 0
        self.dp = 0

def insert(root, x, K):
    cur = root
    cur.cnt += 1
    for i in range(K):
        b = (x >> i) & 1
        if cur.ch[b] is None:
            cur.ch[b] = Node()
        cur = cur.ch[b]
        cur.cnt += 1

def dfs(node):
    if node is None:
        return 0
    for b in (0, 1):
        if node.ch[b] is not None:
            dfs(node.ch[b])

    if node.ch[0] is None and node.ch[1] is None:
        node.dp = 0
        return node.dp

    best = 0
    for b in (0, 1):
        if node.ch[b] is not None:
            best = max(best, node.ch[b].dp + node.ch[b].cnt)
    node.dp = best
    return node.dp

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    K = max(a).bit_length() if a else 1

    root = Node()
    for x in a:
        insert(root, x, K)

    dfs(root)
    print(root.dp)

if __name__ == "__main__":
    solve()
```この実装では、サフィックス アラインメントがトライ内でプレフィックス トラバーサルになるように、最下位ビットの最初の順序を使用してバイナリ トライを構築します。 各ノードはサブツリー数を保存します。これは挿入中に更新され、DP 遷移中に使用されます。 

DFS は子の処理後に DP 値を計算し、ボトムアップの正確性を保証します。 それ以上の拡張は不可能であるため、リーフ ノードの寄与はゼロです。 内部ノードは両方の子を評価し、より適切なサブツリーを選択し、そのサブツリーのサイズを、その下のすべての要素にわたる現在のビットの一致から得られるゲインとして追加します。 

実装の微妙な詳細は、行方不明の子の処理です。 これらは空のサブツリーとして扱われ、寄与はゼロなので、存在しないブランチに誤ってアクセスすることがなくなります。

 ## 特殊なケース

 重要なエッジケースは、すべての数値が同一である場合です。 その場合、トライは単一のパスに縮退します。 DP はすべてのレベルで完全なサブツリー サイズを伝播する必要があり、すべてのビットがすべての要素にわたって寄与するため、答えは最大になります。 すべてのノードには 1 つの子があり、DP はフル カウントを蓄積しながら常にそのブランチを選択するため、アルゴリズムはこれを処理します。 

もう 1 つの特殊なケースは、すべての数値の最初のビットが異なる場合です。 この場合、ルートには、より深い構造のない 2 つのバランスのとれたサブツリーがあります。 DP は、存在しない共有サフィックスを強制しようとすることなく、両側を独立して正しく評価し、最大サブツリー サイズの寄与を返します。 

最後のエッジ ケースは、トライにまばらな分岐が含まれている場合に発生します。 多くのノードが欠落している場合でも、DP は null の子を寄与ゼロとして扱い、構造の欠落によって無効な遷移や負の値が導入されないようにします。
