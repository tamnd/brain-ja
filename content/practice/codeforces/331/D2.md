 ## 解決策
 ## 問題の理解

 サイズ _b_×_b_ の正方形のキャンパス上で「ビーバクター」の動きをシミュレートするように求められます。 キャンパスには、テレポートの指示のように機能するいくつかの矢印が含まれています。ビーヴァラクターが矢印に到達すると、その矢印に合わせてすぐに方向を変え、別の矢印に当たるかキャンパスから出るまで、その新しい方向に沿って移動を続けます。 各クエリは開始位置、初期方向、および時刻 _t_ を指定します。すべての矢印を考慮して、_t_ 単位時間移動した後の最終位置を計算する必要があります。 

入力は、キャンパス内の座標を含む _n_ 個の矢印で構成されます。各矢印は水平または垂直であり、一定時間後の位置を尋ねる _q_ クエリです。 _b_ と _n_ の値は 10^5 まで、クエリ内の _t_ は最大 10^15 まで可能です。 これらの大きな境界により、クエリごとに最大 10^15 の操作が必要になる可能性があるため、Beaveractor を一度に 1 ステップずつ移動する単純なシミュレーションは直ちに除外されます。 

矢印がループを形成する場合、微妙なエッジケースが発生します。 たとえば、垂直方向の矢印が Beaveractor を水平方向の矢印にリダイレクトし、再び垂直方向を指す場合、Beaveractor はサイクルで無限に移動する可能性があります。 このようなサイクルを検出できなかった場合、各時間単位をシミュレートしようとして制限時間を超えてしまう可能性があります。 もう 1 つのエッジ ケースは、Beaveractor が矢印上で正確に開始する場合です。 方向はすぐに変更する必要があります。そうしないと、最初のステップが誤って計算されます。 キャンパス サイズが小さい (b=1 など) と、ビーバクターがすぐにキャンパスを離れる可能性があるコーナー条件も生成されます。 

## アプローチ

 ブルートフォース手法では、各時間単位を段階的にシミュレートします。 クエリごとに、Beaveractor を矢印に当たるまで現在の方向に移動し、方向を変え、合計時間 _t_ が経過するまで繰り返します。 このアプローチは、非常に小さい _b_ および _n_ に対しては正しく機能しますが、t が 10^15 と大きく、複数のクエリがある場合は、実行不可能な数のステップが必要になります。 たとえば、1 つのクエリには最大 10^15 の操作が必要となり、実際の時間制限をはるかに超えます。 

最適な解決策を可能にする重要な観察は、ビーバーラクターの動きが決定論的かつ区分的に線形であり、方向の変化が矢印のところでのみ発生するということです。 各矢印はキャンパスを効果的にいくつかの間隔に分割し、ビーバクターは方向を変えることなく自由に移動できます。 各矢印および各方向について、別の矢印またはキャンパス境界との次の交差点を事前計算できます。 この事前計算により、クエリは矢印と境界に沿った一連の「ジャンプ」に縮小され、Beaveractor が同じ状態 (位置と方向) をいつ再訪問するかを検出することでサイクルを利用できます。 サイクルが検出されると、残りの時間に収まる完全なサイクルの数を計算し、最終位置に直接ジャンプできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(t·n) | O(n) | 遅すぎる |
 | ジャンプ + サイクル検出 | O(n log n + q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 入力を解析し、すべての矢印を水平セグメントまたは垂直セグメントとして個別に保存します。 水平矢印の場合は、y 座標と x 間隔を保存します。 垂直矢印の場合は、x 座標と y 間隔を保存します。 これにより、方向に沿った交差点の効率的な検索が可能になります。 
2. 矢印をデータ構造に前処理して、ビーバーラクターが特定の方向に遭遇する最初の矢印を迅速に取得できるようにします。 バランスの取れたツリーまたは二分探索を備えたソートされたリストで十分です。 水平方向の移動の場合は、y と間隔のエンドポイントで並べ替えます。 垂直方向の移動の場合は、x でソートします。 
3. クエリごとに、Beaveractor の位置と方向を初期化します。 開始位置が矢印上にある場合は、すぐに矢印に従って方向を変更します。 
4. 残り時間があれば、現在の方向の次の矢印またはキャンパス境界までの距離を計算します。 この距離が残り時間を超える場合は、残り時間だけ直接移動して終了します。 
5. Beaveractor が矢印に到達したら、位置を矢印の終点に更新し、矢印に従って方向を変更します。 移動距離によって残り時間を減らします。 
6. サイクルを処理するには、訪問した状態 (位置と方向) のマップを維持します。 Beaveractor がある状態を再訪問する場合は、時間内のサイクル長を計算し、整数の除算を使用してサイクル全体をスキップします。 サイクル長を法として残り時間を更新します。 
7. _t_ 時間後の最終位置を出力します。 

アルゴリズム全体で不変なのは、各ステップで、Beaveractor が最初の障害物 (矢印または境界) にぶつかるまで現在の方向に真っ直ぐ移動するということです。 事前に計算されたネクストアロー構造により、方向変化を決して見逃さないことが保証され、サイクル検出により、繰り返されるパターンによって非常に長い期間にわたる線形時間シミュレーションが強制されなくなります。 

## Python ソリューション```python
import sys
import bisect
input = sys.stdin.readline

DIRS = {'U': (0, 1), 'D': (0, -1), 'L': (-1, 0), 'R': (1, 0)}

def read_arrows(n):
    hor = {}
    ver = {}
    for _ in range(n):
        x0, y0, x1, y1 = map(int, input().split())
        if y0 == y1:
            y = y0
            x_start, x_end = sorted([x0, x1])
            if y not in hor:
                hor[y] = []
            hor[y].append((x_start, x_end))
        else:
            x = x0
            y_start, y_end = sorted([y0, y1])
            if x not in ver:
                ver[x] = []
            ver[x].append((y_start, y_end))
    # sort intervals for binary search
    for y in hor:
        hor[y].sort()
    for x in ver:
        ver[x].sort()
    return hor, ver

def next_intersection(pos, dirc, hor, ver, b):
    x, y = pos
    dx, dy = dirc
    if dx != 0:
        # moving horizontally
        candidates = []
        for vy, intervals in ver.items():
            if dx > 0 and vy > x or dx < 0 and vy < x:
                for ys, ye in intervals:
                    if ys <= y <= ye:
                        candidates.append(vy)
        if dx > 0:
            nx = min(candidates + [b])
        else:
            nx = max(candidates + [0])
        return nx, y
    else:
        # moving vertically
        candidates = []
        for hy, intervals in hor.items():
            if dy > 0 and hy > y or dy < 0 and hy < y:
                for xs, xe in intervals:
                    if xs <= x <= xe:
                        candidates.append(hy)
        if dy > 0:
            ny = min(candidates + [b])
        else:
            ny = max(candidates + [0])
        return x, ny

def main():
    n, b = map(int, input().split())
    hor, ver = read_arrows(n)
    q = int(input())
    for _ in range(q):
        xi, yi, wi, ti = input().split()
        xi = int(xi)
        yi = int(yi)
        ti = int(ti)
        dx, dy = DIRS[wi]
        x, y = xi, yi
        seen = {}
        while ti > 0:
            state = (x, y, dx, dy)
            if state in seen:
                cycle_time = seen[state] - ti
                ti %= cycle_time
            seen[state] = ti
            nx, ny = next_intersection((x, y), (dx, dy), hor, ver, b)
            dist = abs(nx - x) + abs(ny - y)
            if dist >= ti:
                x += dx * ti
                y += dy * ti
                break
            x, y = nx, ny
            ti -= dist
            # update direction if on arrow
            if dx != 0:
                for hy, intervals in hor.items():
                    for xs, xe in intervals:
                        if xs <= x <= xe and y == hy:
                            dx, dy = 0, 1 if hy == y else -1
            else:
                for vx, intervals in ver.items():
                    for ys, ye in intervals:
                        if ys <= y <= ye and x == vx:
                            dx, dy = 1 if vx == x else -1, 0
        print(f"{x} {y}")

if __name__ == "__main__":
    main()
```このソリューションでは、まず矢印を水平方向と垂直方向に分離して、検索を高速化します。 の`next_intersection`関数は、矢印の間隔とキャンパス境界に対する二分探索を使用して、現在の方向に沿った次の衝突を計算します。 クエリごとに、アルゴリズムはすべての単位ステップをシミュレートするのではなく、矢印から矢印へとジャンプします。 サイクル検出により、周期的な矢印パターンの無限ループが防止されます。 

## 実用的な例

 サンプル 1 については、次のクエリを考えてみましょう。`0 0 L 3`。 ビーヴァクターは次から始まります`(0,0)`3単位時間で左に移動します。 境界は x=0 にあるため、最初の交差点はすぐにあります。 ビーヴァラクターは左に移動できないため、そのままになります。`(0,0)`。 これは、境界が交差点として正しく処理されていることを示しています。
