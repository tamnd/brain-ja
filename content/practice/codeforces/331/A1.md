 ## 解決策
 ## 問題の理解

 木の線形シーケンスが与えられ、それぞれがその木がどれほど美しいかを表す整数値を保持します。 これらのツリーのサブセットを削除しても、残りのツリーは元の順序を維持できます。 伐採後は少なくとも2本の木を残さなければなりません。 

ツリーを削除する有効な方法の中で、残りの値の合計を最大化したいと考えています。 ただし、追加の構造上の制約があります。最終シーケンスでは、最初と最後に残ったツリーは同じ値を持つ必要があります。 

したがって、このタスクは単なる最大部分列和問題ではありません。 私たちは実質的に値の選択を迫られています`x`、少なくとも 2 回の出現を維持します。`x`で始まり、で終わるサブシーケンスのみを考慮します。`x`、それらの間のすべてとこれら 2 つのエンドポイントの合計を最大化します。 

出力は、この制約の下で達成可能な最大合計、削除されたツリーの数、および削除されたツリーのインデックスです。 

制約は即座に重要になります。 最大 3 · 10^5 の要素を使用して、等しい値のすべてのペアを試し、それらの間をスキャンするソリューションは、単純に最悪の場合、O(n²) の動作を引き起こす危険があります。 2秒にしては遅すぎます。 発生間の寄与を効率的に、理想的には線形時間または線形に近い時間で処理する方法が必要です。 

等しい値の最適なペアを個別に選択しようとして、それらの間のすべてが常に取得されると仮定すると、単純な間違いが発生します。 たとえば、値が次の場合、`[5, -100, 5]`、最良のエンドポイントは 2 つの 5 ですが、中央を含めることは有害であるため、考慮する必要があります。 もう 1 つの微妙な失敗例は、値が何度も出現する場合です。最適なペアを選択するには、距離やエンドポイントだけではなく、出現回数を含めるか、何を除外するかが重要になります。 

本当の難しさは、すべての潜在的なエンドポイント値が異なる候補サブシーケンスを定義しており、それらすべてを効率的に評価する必要があることです。 

## アプローチ

 ブルートフォースアプローチは値を固定することから始まります`x`そして 2 つの出現を選択します`i < j`そのような`a[i] = a[j] = x`。 次に、それらの間にあるすべての要素を保持することを検討し、合計を計算します。 すべてのペアに対してこれを繰り返すと正確性が得られますが、値が O(n) 回出現する可能性があるため、最悪の場合、複雑さは 2 次になります。 

重要な観察は、エンドポイントを固定すると、区間内の最適な選択は複雑な方法ではオプションではないということです。エンドポイント間のすべての要素が取得されるか取得されないかのいずれかであり、合計を最大化する必要があるため、常に両端間のすべての要素が取得されます。 これにより、各候補が単純な式 (合計) に縮小されます。`[i, j]`プラスエンドポイント制約。 

ただし、すべてのペアを列挙するのは依然としてコストがかかりすぎます。 次の単純化は、配列をプレフィックスの合計として扱うことです。 固定値の場合`x`、その出現が位置にあると仮定します。`p1, p2, ..., pk`。 選ぶとしたら`pi`そして`pj`、スコアは次のようになります。`prefix[pj] - prefix[pi - 1]`。 

したがって、各値について、少なくとも 2 つの出現を使用するという制限付きで、その出現における 2 つのプレフィックス状態間の最大の差が必要になります。 

これにより、値ごとにグループ化された位置をスキャンし、各値についてこれまでに確認された最小のプレフィックスを維持するという問題が軽減されます。 

どのインデックスが削除されたのかを再構築する必要もあります。 最適なペアを選択したら`(i, j)`ある値の場合、最適な保持セットは、次の範囲にあるすべてのインデックスです。`i`そして`j`包括的な。 外側のものはすべて取り除かれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ペアに対するブルートフォース | O(n²) | O(n) | 遅すぎる |
 | プレフィックス + 値ごとのスイープ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 連続するセグメントの合計を O(1) で計算できるように、問題をプレフィックスの合計に再定式化します。 

1. プレフィックスの合計を計算する`pref`、 どこ`pref[i]`最初の合計を格納します`i`要素。 これにより、セグメントの合計を次のように迅速に計算できます。`pref[r] - pref[l-1]`。 
2. インデックスを値ごとにグループ化します。 個別の値ごとに`x`、すべての位置を調べます。`x`が発生します。 
3. 各値について`x`、その出現リストを左から右にスキャンし、以前の出現でこれまでに確認された最小のプレフィックス値を維持します。 ある位置で`j`で終わる最適なセグメントを計算します。`j`として`pref[j] - min_pref_so_far`これは、最も早い時期に発生したものを左のエンドポイントとして選択することに対応します。 
4. すべての値および出現のすべてのペアにわたるグローバル最良セグメントを追跡します。 最高のものを保存する`(l, r)`間隔。 
5. 最適な間隔が見つかったら、すべてのインデックスを維持して答えを作成します。`[l, r]`そして外側のすべてを削除します。 
6. その間隔の合計、削除された要素の数、および削除された要素のインデックスを出力します。 

### なぜ効果があるのか

 重要な不変条件は、すべての有効な解は、その左端と右端に保持されている値の出現によって完全に決定されるということです。`x`。 最適な解は等しい値で始まり、終わる必要があるため、等しい要素のペアに対応します。 固定ペアの場合、内部要素を削除するとエンドポイントの制約を満たすことができずに合計が減少するため、それらの間のすべてを取得することが常に最適です。 プレフィックス合計変換により、各候補ペアの評価が一定時間の差に減少することが保証され、スキャンの発生により、すべての有効なペアが繰り返しなしで考慮されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    pos = {}
    for i, v in enumerate(a, 1):
        pos.setdefault(v, []).append(i)

    best_sum = None
    best_l = best_r = None

    for v, lst in pos.items():
        min_pref = pref[lst[0] - 1]
        min_idx = lst[0]

        for j in lst[1:]:
            cur = pref[j] - min_pref
            if best_sum is None or cur > best_sum:
                best_sum = cur
                best_l = min_idx
                best_r = j

            if pref[j - 1] < min_pref:
                min_pref = pref[j - 1]
                min_idx = j

    kept = [0] * (n + 1)
    for i in range(best_l, best_r + 1):
        kept[i] = 1

    removed = []
    for i in range(1, n + 1):
        if not kept[i]:
            removed.append(i)

    print(best_sum, len(removed))
    print(*removed)

if __name__ == "__main__":
    solve()
```コードは、セグメントの合計を一定時間内に計算できるように、プレフィックスの合計を構築することから始まります。 次に、有効なエンドポイントが一致する必要があるため、同じ値の出現のみを比較するようにインデックスを値でグループ化します。 

各値リストについて、出現する前に最小のプレフィックス値を追跡します。 これは、これまでに確認された最良の左端点を表しています。 新しい出現ごとにセグメントを拡張し、最良の回答を更新しようとします。 

最適なセグメント境界を見つけた後、内部のすべてのものを保持としてマークし、他のすべてのインデックスを削除として出力します。 

微妙な点は、プレフィックスを注意深く追跡する必要があることです。`i-1`左側のエンドポイントの場合、セグメントの合計は、選択した開始点より前のすべてを除外することに依存するためです。

価値のために`2`で`[2, 5]`、セグメント合計は`pref[5] - pref[1] = 8 - 1 = 7`。 

価値のために`3`1 回のみ発生し、無視されます。 

最良は価値です`2`間隔あり`[2, 5]`。 

| 値 | 左 | 右 | 合計 |

 | 1 | 1 | 4 | 7 |
 | 2 | 2 | 5 | 7 |

 私たちが選ぶ`[2,5]`。 インデックスの削除`1`出力の合計を与える`8`。 

これは、複数の候補間隔が結合する可能性があり、有効な最大値が許容されることを示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、値の最初と最後の出現によって最良の間隔が形成される場合です。 のような入力の場合`4 -1 4`、有効な間隔は次のとおりです。`[1,3]`。 このアルゴリズムはプレフィックスの差を正確に計算し、それがより小さなセグメントよりも優先されるため、それを選択します。 

もう 1 つのケースは、値が何度も出現するが、中央のペアのみが最適である場合です。 例えば`5, -10, 5, -10, 5`、最適なセグメントはポジション間です`1`そして`5`, 中間カットは合計を減らすためです。 プレフィックス スイープにより、すべてのペアを列挙することなく暗黙的に比較できるようになります。 

最後のケースは、すべての値が等しい場合です。 この場合、最適な解決策は、すべてのエンドポイントが有効であり、要素を削除しても合計が減少するだけであるため、配列全体を保持することです。 プレフィックスの差は出現するたびに単調に増加し続けるため、アルゴリズムは自然に全範囲を選択します。
