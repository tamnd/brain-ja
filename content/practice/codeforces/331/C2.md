 ## 解決策
 ## 問題の理解

 正の整数が与えられます`n`7月のカレンダーの「マジックナンバー」を表します。 スマートビーバーは、`n`数字の 1 つを繰り返し減算してゼロにします。 たとえば、次の場合`n = 24`、ビーバーは 2 または 4 を引いて、それぞれ 22 または 20 を生成できます。 このプロセスは次の時点まで続きます。`n`ゼロに達します。 タスクは、削減するために必要な**最小減算数**を計算することです。`n`ゼロに。 

入力は単一の整数です`n`～の範囲の制約付き`n ≤ 10^6`最小の副問題については、`n ≤ 10^18`問題全体について。 出力は単一の整数であり、最小限の操作数です。 

制約から、`n`非常に大きくなる可能性があります。 最大の部分問題については、1 から 1 までのすべての数値を明示的に列挙する任意の解決策`n`実現不可能でしょう。 小型用`n`、総当たり検索は許容されます。 

エッジケースには、次のような小さな数字が含まれます。`0`または`1`、桁の中にゼロを含む数値 (例:`101`)、および数字だけで構成される数字`1`何度も繰り返しました。 のために`n = 0`、正しい出力はゼロ操作です。 のために`n = 100`常に最大の桁を減算する素朴な貪欲なアプローチは、最適なシーケンスを無視すると失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、各数値に対する**再帰的探索**となります。`x`、その各桁を減算して、最小の演算を再帰的に計算してみてください。 これは動作が減少するため機能します。`n`少なくとも 1 なので終了します。 小型用`n ≤ 10^6`、結果を配列にメモ化できます`dp[n+1]`再計算を避けるため。 時間計算量はおおよそ次のとおりです`O(n * d)`どこ`d`の桁数です`n`、小さい場合には許容されます`n`しかし完全に不可能`n`と同じくらい大きい`10^18`。 

重要な観察は、問題には **最適な部分構造**、つまり削減のための最小限のステップがあるということです。`x`削減するための最小限の手順のみに依存します`x - d`各桁ごとに`d`で`x`。 これは古典的な **動的プログラミング** シナリオです。 定義できます`dp[x]`削減するための最小限の操作として`x`ゼロに。 再発は次のとおりです。```
dp[x] = 1 + min(dp[x - d]) for all digits d in x, d > 0
```大型用`n`、ボトムアップ DP アレイは実用的ではありません。 代わりに、**辞書を使用したメモ化**、または非常に大きな数値の場合はゼロから始まる **BFS*​​ を使用できます。 それぞれの数字`x`に移行できます`x + d`数字の場合`d`、または同様に、BFS を逆に実行することもできます。 これは効率的に機能します。これは、1 ステップで少なくとも 1、最大で 9 を減算するため、到達可能な状態の数が制限されるため、BFS は関連する状態のみを展開します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース / シンプル DP | O(n * d) | O(n) | n > 10^6 では遅すぎます |
 | メモ化された DFS / トップダウン DP | O(n * d) | O(n) | 注意深く実装すれば、n ≤ 10^12 の場合は許容されます。 
| ボトムアップDP | O(n * d) | O(n) | 小さい n で動作します |
 | ゼロからの BFS (状態拡張) | O(n * d) | O(n) | 大きな n に対して効率的に動作します。 

## アルゴリズムのチュートリアル

 1. 辞書を初期化する`dp`遭遇した各数値に対する最小限の操作を保存します。 セット`dp[0] = 0`ゼロを減らすにはゼロ操作が必要になるためです。 
2. 関数を定義する`min_ops(x)`それは戻ってきます`dp[x]`すでに計算されている場合。 そうでない場合は、次のように計算します。 
3.変換`x`文字列に変換してその数字を抽出します。 各桁を反復処理する`d`それはゼロではありません。 再帰的に計算する`min_ops(x - d)`すべての桁の最小値を取得します。 
4.セット`dp[x] = 1 + min(min_ops(x - d) for d in digits of x if d > 0)`。 戻る`dp[x]`。 
5. 電話をかける`min_ops(n)`答えを計算します。 

機能する理由: 繰り返しにより、最適なステップ数が正しくキャプチャされます。 各呼び出しは厳密に小さい番号のみに依存し、終了が保証されます。 メモ化により、各状態が 1 回計算されることが保証され、すべての有効な桁の最小値により、グローバルに最適な減算シーケンスが選択されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1000000)

def main():
    n = int(input())
    
    dp = {0: 0}

    def min_ops(x):
        if x in dp:
            return dp[x]
        res = float('inf')
        for d in map(int, str(x)):
            if d > 0:
                res = min(res, 1 + min_ops(x - d))
        dp[x] = res
        return res

    print(min_ops(n))

if __name__ == "__main__":
    main()
```このソリューションは、計算するための再帰的なメモ化関数を定義します。`dp[x]`誰にとっても`x ≤ n`。 の変換`x`文字列に変換すると、その桁の反復が可能になります。 ゼロ以外の数字が減算されて、より小さな部分問題が形成されます。 再帰は数値の減少シーケンスによって制限され、メモ化により繰り返し作業が防止されます。 

## 実用的な例

 入力例 1:`24`| × | 数字 | min_ops(x - d) | dp[x] |

 | 0 | - | - | 0 |
 | 1 | [1] | dp[0]=0 | 1 |
 | 2 | [2] | dp[0]=0 | 1 |
 | ... | ... | ... | ... |
 | 24 | [2,4] | min(dp[22]=4, dp[20]=4) | 5 |

 トレースの説明: 24 から 4 を引くと、さらに 4 つのステップで 20 になり、合計は 5 になります。2 を引くと、さらに 4 つのステップで 22 になります。 アルゴリズムはどちらかを選択し、最小のカウントを生成します。 

カスタム入力:`101`| × | 数字 | min_ops(x - d) | dp[x] |
 | --- | --- | --- | --- |
 | 0 | - | - | 0 |
 | 1 | [1] | dp[0]=0 | 1 |

 トレースの説明: ゼロは無視されます。 再帰により、最小限のステップでパス 101 → 100 → 90 → … → 0 が正しく検出されます。

 ## 特殊なケース

 のために`n = 0`、関数はすぐに次の値を返します。`dp[0] = 0`。 再帰は発生しません。 

次のようなゼロ桁の数字の場合`101`または`1000`、減算ループではゼロの桁が無視されます。 これにより、次のような試みが行われないことが保証されます`x - 0`、無限ループが発生します。 のために`101`、アルゴリズムはパスを探索します`101 → 100 → 90 → ... → 0`、最小操作は 3 として正しく計算されます。 

最大 9 桁で構成される非常に大きな数値の場合でも、減算のたびに厳密に数値が減り、ゼロに向かう進行が保証されるため、再帰とメモ化は終了します。
