 ## 解決策
 ## 問題の理解

 の順列が与えられています`n`ビーバーにはそれぞれ 1 から 1 までの一意の ID が付いています。`n`。 ハイテク機械は連続した ID 間隔でビーバーを剃ることができますが、その並べ替えにその間隔内のすべての ID が昇順で含まれている場合に限り、位置が連続している必要はありません。 つまり、連続する ID 範囲を選択すると、`[x, y]`、ID の厳密に昇順の順列でそれらを見つけることができれば、マシンは 1 回のセッションでそれらを削ることができます。 

2 種類のクエリを処理する必要があります。1 つ目は、指定された ID 間隔ですべてのビーバーをシェービングするための最小セッション数を要求し、2 つ目は、指定された 2 つの位置でビーバーを交換します。 各出力クエリでは、以前のスワップの後であっても、セッションを効率的に計算する必要があります。 

制約は厳しいです:`n`最大 300,000 件、最大 100,000 件のクエリが存在する可能性があります。 毎回順列をスキャンする総当り的なアプローチでは、次のような時間がかかります。`O(n)`クエリごとに、`3*10^10`最悪の場合、動作が非常に遅くなります。 高速なセッション クエリとスワップ後の効率的な更新の両方を可能にする何らかのデータ構造または表現を維持する必要があります。 

エッジ ケースには、ID がすでに増加しているシーケンス、逆の順序のシーケンス、または以前は 1 つのセッションであったものを複数のセッションに分割するシングル スワップ シナリオが含まれます。 たとえば、順列が次の場合、`[1, 3, 2, 4]`、IDを剃る`[2, 3]`順列では 3 が 2 の前に出現するため、2 つのセッションが必要です。 単純なスキャンでは、境界のみをチェックする場合、誤って 1 セッションとしてカウントされる可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 お問い合わせの場合`[x, y]`、ID の位置をスキャンします。`x`に`y`順列で次の ID が前の ID の前に出現する回数を数えます。 「ブレーク」ごとに昇順でセッション数が増加します。 スワップには、順列配列の更新のみが必要です。 このアプローチは次の場合に有効です`n ≤ 100`しかし明らかに遅すぎる`n = 3*10^5`各クエリは最大でスキャンできるため、`n`要素。 

重要な観察は、セッションの最小数は完全に連続する ID の相対的な順序によって決定されるということです。 もし`pos[id + 1] > pos[id]`ID用`id`で`[x, y)`、マシンは 1 回のセッションでそれらを剃ることができます。 それ以外の場合は、新しいセッションが必要です。 したがって、「ブレーク」の配列を事前に計算できます。`pos[id + 1] < pos[id]`。 セッションの合計数`[x, y]`は、その間隔内の休憩の数に 1 を加えたものです。 

スワップを効率的に行うために、位置配列を維持します。`pos[id] = index`ブレーク セットはバイナリ インデックス付きツリーまたはセットとして設定されます。 2 つの要素を交換すると、少数の連続するペア (交換された ID とその隣接要素) のみに影響します。 これにより、更新の複雑さが軽減されます。`O(n)`に`O(1)`関連するペアごとに、アルゴリズム全体を完全な制約に対して十分な速度に保ちます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * q) | O(n) | n ~ 3*10^5 | には遅すぎます。 
| 位置配列 + ブレークを使用するのが最適 | O(q * log n) または O(q) with set) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列を読み取る`a`そして位置配列を構築します`pos`そのような`pos[id]`ビーバーの現在のインデックスを ID とともに返します`id`。 
2. 初期ブレークを事前計算します: ID ごとに`i`1から`n-1`、 もし`pos[i + 1] < pos[i]`、休憩としてマークします。 これらをセットまたはブール配列に格納します`breaks[i] = True`。 
3. タイプ 1 のクエリの場合`[x, y]`、最小セッション数は次のとおりです。`1 +`休憩の回数`[x, y-1]`。 ブレークのプレフィックス合計を維持する場合、このクエリは O(1) で答えることができます。 
4. タイプ 2 のクエリの場合、位置を交換する`i`そして`j`順列ではペアのみに影響します`(a[i]-1, a[i])`、`(a[i], a[i]+1)`、`(a[j]-1, a[j])`、`(a[j], a[j]+1)`。 スワップ後にこれらの ID のブレークを再計算し、ブレーク セット/プレフィックスの合計を更新します。 
5. を更新します。`pos`スワップを反映する配列。 
6. すべてのクエリに対して繰り返します。 

**機能する理由**: 不変条件は、ブレークが連続する ID の順序が正しくない場所を正確に表すことです。 休憩するたびにセッション数が 1 つずつ増えます。 スワップは、スワップされた ID とその近傍に関係するブレークにのみ影響するため、それらのみを更新すれば十分です。 ブレークを見逃したり、二重にカウントしたりすることはなく、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
pos = [0] * (n + 2)  # 1-indexed

for idx, val in enumerate(a):
    pos[val] = idx

# Compute initial breaks
breaks = [0] * (n + 2)
total_breaks = 0
for i in range(1, n):
    if pos[i + 1] < pos[i]:
        breaks[i] = 1
        total_breaks += 1

q = int(input())
for _ in range(q):
    query = list(map(int, input().split()))
    if query[0] == 1:
        x, y = query[1], query[2]
        # count breaks in [x, y-1]
        session_count = 1
        for i in range(x, y):
            session_count += breaks[i]
        print(session_count)
    else:
        i, j = query[1]-1, query[2]-1
        val_i, val_j = a[i], a[j]

        # remove old breaks affected by val_i and val_j
        for v in [val_i, val_i-1, val_j, val_j-1]:
            if 1 <= v <= n-1:
                total_breaks -= breaks[v]
        # swap in array and pos
        a[i], a[j] = a[j], a[i]
        pos[val_i], pos[val_j] = pos[val_j], pos[val_i]
        # recompute affected breaks
        for v in [val_i, val_i-1, val_j, val_j-1]:
            if 1 <= v <= n-1:
                breaks[v] = 1 if pos[v + 1] < pos[v] else 0
                total_breaks += breaks[v]
```**説明**: 位置配列とブール値ブレーク配列を維持します。 各セッション クエリでは、範囲内の区切りをカウントします。 スワップでは最大 4 ペアのブレークを更新するだけでよいため、アルゴリズムは高速なままです。 端の ID などの境界条件は、ブレーク更新を制限することで処理されます。`[1, n-1]`。
