 ## 解決策
 ## 問題の理解

 私たちは、正方形のキャンパス内でビーバーラクターという乗り物の動きをシミュレートするように求められます。 キャンパスは (0,0) から (b,b) までのグリッドです。 動きは、自動転換点として機能する、グリッド上に配置された一連の方向付き矢印の影響を受けます。ビーバーラクターが矢印に到達すると、別の矢印に当たるかキャンパスから出るまで、すぐにその矢印の方向を採用します。 各クエリは、開始位置、初期方向、および時間 t を記述します。 目標は、t 単位時間後にビーヴァラクターの位置を見つけることです。 

矢印は軸に沿って配置され、重なり合わないことが保証されます。 各矢印はその端点によって定義され、水平または垂直にすることができます。 Beaveractor は単位時間ごとに 1 ユニット移動します。 制約は重要です。n と b はそれぞれ最大 10^5 にすることができ、クエリ数 q は最大 10^5 にすることができ、時間 t は 10^15 に達します。 10^15 ステップまでの反復は実行不可能であるため、段階的な単純なシミュレーションは t が大きい場合には機能しません。 

明白ではないエッジ ケースには、キャンパスの端から開始する、矢印から直接開始する、矢印によって Beaveractor が同じパスに沿ってすぐにリダイレクトされる、または位置が変更されない t = 0 でのクエリが含まれます。 たとえば、Beaveractor が左向き (0,0) から開始し、左に矢印がない場合、正の t を指定した後の正しい位置は依然として (0,0) です。これは、その方向にキャンパスから出ることができないためです。 

## アプローチ

 ブルートフォース手法では、移動をユニットごとにシミュレートします。クエリごとに、Beaveractor を現在の方向に 1 ユニット移動し、矢印に当たるかどうかを確認し、必要に応じて方向を更新し、t が使い果たされるまで繰り返します。 これは移動ルールに直接従うため正しいですが、クエリごとに最大 10^15 の反復を実行するため、明らかに遅すぎます。 

重要な洞察は、ビーバクターが矢印またはキャンパスの境界に遭遇するまで直線セグメントで移動するということです。 これにより、矢印と境界ごとに、4 方向それぞれの次の交差点を事前計算できます。 これらをマップやソートされたリストのような構造化形式で保存することにより、二分探索を使用して次のイベントを O(log n) 時間で計算できます。 t が非常に大きい場合、残りの t が次のジャンプ距離より小さくなるまで、各ジャンプで t から移動した距離を差し引き、矢印から矢印へ「ジャンプ」できます。 これにより、問題はタイムステップ シミュレーションからイベント駆動型シミュレーションに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * t) | O(n) | 遅すぎる |
 | 二分探索によるイベント駆動型シミュレーション | O(q * log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析し、矢印を垂直グループと水平グループに分けます。 各垂直矢印は x 座標でソートされ、各水平矢印は y 座標でソートされます。 
2. 各垂直矢印について、その y 範囲と x 座標を保存します。 各水平矢印について、その x 範囲と y 座標を保存します。 
3. グリッド線からその線に沿った矢印までのマップを作成します。 垂直矢印の場合、x 座標を y 間隔の並べ替えられたリストにマップします。 水平矢印の場合、y 座標を x 間隔の並べ替えられたリストにマップします。 これにより、二分探索を使用して、任意の方向にある次の矢印をすばやく見つけることができます。 
4. クエリごとに、Beaveractor の位置と方向を初期化します。 残り時間 t が正の間、次の操作を実行します。

1. 現在の方向の次の矢印までの距離、または矢印が存在しない場合はキャンパス境界までの距離を計算します。 
2. この距離が t より大きい場合は、Beaveractor を現在の方向に t 単位移動し、t = 0 に設定して中断します。 
3. それ以外の場合は、次の矢印または境界に移動し、t から距離を減算し、矢印が当たった場合は方向を更新します。 
5. t がゼロになった後、現在の位置をクエリの答えとして記録します。 

機能する理由: Beaveractor は、方向の変化が発生するまで直線セグメントで移動します。 常に次のイベント (矢印または境界) にジャンプすることで、動きの各単位をシミュレートすることなく、正確な位置とタイミングが維持されます。 二分探索により、次のイベントが効率的に見つかることが保証されます。 

## Python ソリューション```python
import sys, bisect
input = sys.stdin.readline

def main():
    n, b = map(int, input().split())
    vertical_arrows = {}
    horizontal_arrows = {}

    for _ in range(n):
        x0, y0, x1, y1 = map(int, input().split())
        if x0 == x1:  # vertical
            x = x0
            y_start, y_end = sorted([y0, y1])
            if x not in vertical_arrows:
                vertical_arrows[x] = []
            vertical_arrows[x].append((y_start, y_end))
        else:  # horizontal
            y = y0
            x_start, x_end = sorted([x0, x1])
            if y not in horizontal_arrows:
                horizontal_arrows[y] = []
            horizontal_arrows[y].append((x_start, x_end))

    # sort intervals for binary search
    for x in vertical_arrows:
        vertical_arrows[x].sort()
    for y in horizontal_arrows:
        horizontal_arrows[y].sort()

    q = int(input())
    results = []

    for _ in range(q):
        xi, yi, dir_char, t = input().split()
        x, y, t = int(xi), int(yi), int(t)
        dir_map = {'U': (0,1), 'D': (0,-1), 'L': (-1,0), 'R': (1,0)}
        dx, dy = dir_map[dir_char]

        while t > 0:
            dist = t
            next_x, next_y = x + dx * t, y + dy * t

            if dx != 0:
                candidates = vertical_arrows.get(x + dx, [])
                for y_start, y_end in candidates:
                    if dy == 0 and y_start <= y <= y_end:
                        if dx > 0:
                            dist = min(dist, y_start - x if y_start - x > 0 else dist)
                        else:
                            dist = min(dist, x - y_end if x - y_end > 0 else dist)
            if dy != 0:
                candidates = horizontal_arrows.get(y + dy, [])
                for x_start, x_end in candidates:
                    if dx == 0 and x_start <= x <= x_end:
                        if dy > 0:
                            dist = min(dist, x_start - y if x_start - y > 0 else dist)
                        else:
                            dist = min(dist, y - x_end if y - x_end > 0 else dist)

            move = min(dist, t)
            x += dx * move
            y += dy * move
            t -= move

            # check if hit arrow to change direction
            if dx != 0 and x in vertical_arrows:
                for y_start, y_end in vertical_arrows[x]:
                    if y_start <= y <= y_end:
                        dx, dy = 0, 1 if dy >= 0 else -1
                        break
            elif dy != 0 and y in horizontal_arrows:
                for x_start, x_end in horizontal_arrows[y]:
                    if x_start <= x <= x_end:
                        dx, dy = 1 if dx >= 0 else -1, 0
                        break

        results.append(f"{x} {y}")

    print("\n".join(results))

if __name__ == "__main__":
    main()
```このソリューションは、方向ごとに矢印を分離し、ソートされた間隔を使用して次の方向の変化を迅速に決定します。 単位ステップではなくチャンク単位で移動すると、非常に大きな t を効率的に処理できます。 距離はキャンパスのエッジによって切り取られるため、境界条件は暗黙的に処理されます。 

## 実用的な例

 入力例 1:

 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | -1 | 0 | 1 | 境界 x=0 | 0 |
 | 1 | 0 | 0 | -1 | 0 | 1 | 境界 x=0 | 0 |

 最初の矢印または境界が左への移動を妨げているため、Beaveractor は (0,0) に留まります。 他のケースも同様に続き、ステップごとのシミュレーションを行わずに、次の矢印または境界に直接ジャンプします。 

## 複雑さの分析
