 ## 解決策
 ## 問題の理解

 正の整数のいずれかの桁を繰り返し減算して、その整数をゼロにするように求められます。 各ステップで、現在の数値に存在する任意の桁を選択し、それを減算する必要があります。 目標は、ゼロに到達するために必要な減算演算の数を最小限に抑えることです。 入力は単一の整数です`n`開始の「マジックナンバー」を表し、出力は減算の最小数を表す単一の整数です。 

制約は次から始まります`n ≤ 10^6`に`n ≤ 10^18`これは、単純なシミュレーション アプローチは最小のサブタスクでは機能する可能性がありますが、最大のサブタスクでは完全に実行不可能であることを示しています。 単純な方法では、すべてのステップで可能なすべての桁の減算を試行する必要があります。 付きの番号の場合`d`桁まで分岐できます`d`ステップごとの可能性。 もし`n`が 10^18 までの場合、この分岐は組み合わせ爆発につながります。 つまり、すべての減算シーケンスを明示的に調査しない方法が必要です。 

微妙な点の 1 つは、入力にゼロが含まれる可能性があることです。 数値にゼロの桁がある場合、ゼロを引くことはできません。 正の数字のみが数値を減らします。 例えば、`105`数字がある`1,0,5`。 引き算ができます`1`または`5`しかしそうではありません`0`。 不用意に実装すると、ゼロを減算しようとして無限ループに陥る可能性があります。 

もう 1 つの自明ではないケースは、次のような 1 桁で構成される数値です。`7`。 最小ステップ数は 7 ではなく 1 です。 アルゴリズムは、演算の総数を減らすために、整数を考慮し、各ステップで利用可能な最大の桁を動的に選択する必要があります。 

## アプローチ

 ブルートフォースソリューションは概念的には単純です。 それぞれの番号について`x`から`n`ゼロまで下げると、その桁の 1 つを減算して、到達可能なすべての数値を計算します。 最小ステップ数をゼロに戻す再帰関数を管理します。 再帰は、考えられるすべての減算シーケンスを探索するので正しいですが、非常に時間がかかります。`n = 10^6`おおよそあるかもしれない`10^6`州に分かれており、各州は次のように分岐します。`d`可能な数字。 のために`n = 10^18`、このアプローチはまったく実行不可能です。 

重要な洞察は、問題には重複する部分問題と最適な部分構造があり、これが動的プログラミングの特徴であるということです。 定義すると`dp[x]`削減する最小ステップ数として`x`ゼロまで、数値ごとに繰り返し計算できます。`x`、`dp[x] = 1 + min(dp[x - d] for each non-zero digit d of x)`。 これにより、問題はサイズの配列を埋めるという問題に軽減されます。`n+1`小さいもの用`n`、または大規模な場合はメモ化を使用する`n`。 10^18 までの非常に大きな数値の場合は、保存できません。`dp[x]`あらゆる人にとって`x`。 その場合、貪欲なアプローチと桁抽出を組み合わせて使用​​できます。つまり、常に現在の数値の最大桁を減算します。 最大の桁を減算すると各ステップでの削減が最大化され、減算が小さくなると全体的により多くのステップが必要になるため、これが最適であることが証明されています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n*d) | O(n) | n が大きいと遅すぎます |
 | 動的プログラミング | O(n*d) | O(n) | n ≤ 10^6 | の場合は受け入れられます。 
| 貪欲な最大桁 | O(log n * d) | お(1) | すべての制約に対して受け入れられます |

 ## アルゴリズムのチュートリアル

 1. 入力された番号を読み取ります`n`整数として。 
2. カウンタの初期化`steps`ゼロに。 これにより、実行された減算の回数が追跡されます。 
3. その間`n`がゼロより大きい場合は、次の手順を実行します。 

1. のすべての桁を抽出します。`n`。 
2. 最大の桁を選択します`max_digit`。 
3. 減算`max_digit`から`n`。 
4. インクリメント`steps`1つずつ。 
4. 1回`n`ゼロに達すると出力`steps`。 

これが機能する理由は、各ステップで、使用可能な最大の桁を減算することで数値が可能な限り減少するためです。 これより小さい桁では、残りを削除するために追加の操作が必要になるため、貪欲な選択が常に最適です。 これは事実上「桁ベースの削減」ヒューリスティックであり、各ステップが可能な限り最大の方法で残りの数を削減し、減算後の残りの数が同じタイプの部分問題を形成するため、最小であることが証明されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
steps = 0

while n > 0:
    digits = [int(d) for d in str(n)]
    max_digit = max(digits)
    n -= max_digit
    steps += 1

print(steps)
```このコードは入力数値を読み取り、カウンターを初期化します。 の`while`ループは数値がゼロになるまで継続します。 ループ内で、次を使用して数字が抽出されます。`str(n)`そして`int(d)`変換。 最大桁が減算されます`n`、歩数カウンターが増加します。 これは次まで続きます`n`がゼロになり、その時点で最小ステップ数に達します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    steps = 0
    while n > 0:
        digits = [int(d) for d in str(n)]
        n -= max(digits)
        steps += 1
    return str(steps)

# Provided samples
assert run("24\n") == "5", "sample 1"

# Custom cases
assert run("7\n") == "1", "single digit"
assert run("1000000\n") == "7", "power of ten"
assert run("123456789\n") == "9", "all digits"
assert run("0\n") == "0", "zero input"
assert run("19\n") == "3", "small two-digit number"
```| テスト入力 | 期待される出力 | 検証内容 |
