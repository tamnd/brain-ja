 ## 解決策
 ## 問題の理解

 1 から n までの数字の順列が与えられていますが、その順列は単なるデータではなく、「一列に並ぶビーバー」の固定順序を定義します。 各数値は 1 回だけ表示されますが、各値の位置は入れ替えにより時間の経過とともに変化します。 

タイプ 1 のクエリは、値の間隔 [x, y] について尋ねます。 x から y までのすべての値をカバーするには、連続した「シェービング セッション」が何回必要であるかを知りたいと考えています。 単一のセッションで値のグループを処理できるのは、順列内で x、x+1、x+2、…、y の位置がそのグループに限定されている場合にインデックスの昇順で表示される場合、つまり値の順序を尊重して部分列を形成する場合です。 これが全体的に失敗した場合は、値の範囲を複数の連続するセグメントに分割し、各セグメントの順列で「順序の一貫性」が保たれるようにします。 

タイプ 2 のクエリは、順列内の 2 つの位置を交換するため、クエリの構造を動的に変更します。 

隠れた中心的な構造は、実際には通常の意味でサブシーケンスをチェックしているのではなく、x から y までの値の位置シーケンスが「単調性を破った」回数を数えているということです。 

この制約により、操作ごとに対数更新またはほぼ一定の更新が行われます。 最大 10^5 のクエリと最大 3×10^5 の n を使用すると、クエリごとに [x, y] をスキャンするソリューションはすぐに遅すぎます。これは、最悪の場合の合計作業量が O(nq) となり、これは 10^10 の演算のオーダーに相当するためです。 

順列がすでに完全に順序付けされているか、またはほぼ順序付けられている場合、微妙なエッジ ケースが発生します。 たとえば、配列が [1, 2, 3, 4, 5] の場合、すべてのクエリは 1 を返します。単純な実装では、依然として間隔をスキャンして位置を不必要に再計算し、小さなテストには合格しますが、完全な制約には失敗する可能性があります。 

別の障害モードは、スワップによってローカルな反転が作成され、グローバル構造には直ちに影響を与えないものの、セグメント数が増加する場合に発生します。 たとえば、[1,2,3,4,5] の 2 と 3 を交換すると、位置シーケンスに 1 つのブレークが作成され、両方の値をカバーするすべての範囲の答えが変わります。 グローバル構造を維持せずに「ローカルで修正」しようとするソリューションは、この伝播を見逃してしまいます。 

## アプローチ

 ブルートフォースアプローチは簡単です。 各クエリ [x, y] について、値 x から y までの位置を値の昇順に収集し、x から x+1 に移動するときに位置シーケンスが何回減少するかを数えます。 それぞれの減少は、新しいセグメントが必要であることを示します。 これは正しいです。セグメントは、位置が増加している値の最大の連続ブロックに正確に対応するからです。 

ただし、これにはクエリごとに最大 O(n) 個の値を繰り返す必要があり、最悪の場合、合計の複雑さは O(nq) になります。 10^5 クエリでは、これは遅すぎます。 

重要な洞察は、答えは範囲内の隣接する値が置換順序で「壊れている」かどうかのみに依存するということです。 pos[v] を順列内の値 v の位置として定義します。 次に、固定間隔 [x, y] のセッション数は次のようになります。 

1 + [x, y-1] のインデックス i の数 (pos[i] > pos[i+1])。 

したがって、問題は、任意の部分列について推論するのではなく、動的配列 pos[v] を使用して、値空間内の隣接する値の反転をカウントすることに帰着します。 

2 つの操作をサポートする必要があります。1 つは位置のポイント更新 (要素を交換するとき)、もう 1 つは値の間隔内で条件を満たす隣接するペア (i, i+1) の数をカウントする範囲クエリです。 これは値軸上のセグメント ツリーの古典的な設定で、隣接する各ペアが「不良」かどうかを保存します。 

各リーフは値 i を表し、pos[i] > pos[i+1] かどうかを示す 0/1 インジケータを格納します。 2 つの要素を交換すると、交換された値のローカル比較のみに影響するため、O(1) または O(log n) の位置を更新します。 範囲合計クエリでは、ブレークの数が得られます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 隣接比較のセグメント ツリー | O(q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 順列内の値 v の位置である pos[v] と、位置 p の値である arr[p] の 2 つの配列を維持します。 

また、インデックス 1 から n-1 にわたるセグメント ツリーも維持します。ここで、各インデックス i は、pos[i] > pos[i+1] かどうかを格納します。 

1. 入力順列から初期配列 pos および arr を構築します。 その際、1 から n-1 までの i の各比較指標を計算します。 このステップでは、今後のすべてのクエリの回答を取得する構造を初期化します。 
2. これらのインジケーター上にセグメント ツリーを構築します。 各ノードは、その値間隔内の「ブレーク」の数を表すセグメントの合計を格納します。 
3. タイプ 1 クエリ [x, y] に答えるには、インデックス [x, y-1] の合計をセグメント ツリーにクエリします。 結果は休憩の数なので、答えはその合計に 1 を加えたものになります。 これが機能するのは、ブレークごとに連続した値の増加チェーンが新しいセグメントに分割されるためです。 
4. 位置 x と y でのスワップを処理するには、関係する値を a = arr[x] および b = arr[y] とします。 arr[x] と arr[y] を交換した後、pos[a]、pos[b]、および arr[x]、arr[y] を更新します。 
5. スワップ後は、a または b を含む比較のみが変更できます。 これは、インデックス a-1、a、b-1、および b (範囲内の場合) に影響します。 影響を受けるインデックス i ごとに、pos[i] > pos[i+1] かどうかを再計算し、その時点でセグメント ツリーを更新します。 
6. すべてのクエリを順番に処理し続けます。 

正しさは、値空間内の隣接関係のみが重要であり、スワップは 2 つの値の位置を変更するだけであるため、それらの値を含む比較のみが変更できるという事実に依存します。 

## なぜ機能するのか

 重要な不変条件は、すべての隣接するペア (i、i+1) について、順列におけるこれら 2 つの値の相対順序が反転するかどうかをセグメント ツリーが正確に格納することです。 すべての有効なシェービング セグメントは、そのような反転が発生しない最大の連続する値の範囲に対応します。 したがって、セグメントのカウントは、このバイナリ配列内のラン間の境界をカウントすることになります。 スワップは 2 つの値の位置にのみ影響するため、それらの値を含む比較のみを変更でき、構造の一貫性が保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.t = [0] * (4 * n)

    def build(self, v, l, r, arr):
        if l == r:
            self.t[v] = arr[l]
            return
        m = (l + r) // 2
        self.build(v*2, l, m, arr)
        self.build(v*2+1, m+1, r, arr)
        self.t[v] = self.t[v*2] + self.t[v*2+1]

    def update(self, v, l, r, i, val):
        if l == r:
            self.t[v] = val
            return
        m = (l + r) // 2
        if i <= m:
            self.update(v*2, l, m, i, val)
        else:
            self.update(v*2+1, m+1, r, i, val)
        self.t[v] = self.t[v*2] + self.t[v*2+1]

    def query(self, v, l, r, ql, qr):
        if ql > r or qr < l:
            return 0
        if ql <= l and r <= qr:
            return self.t[v]
        m = (l + r) // 2
        return self.query(v*2, l, m, ql, qr) + self.query(v*2+1, m+1, r, ql, qr)

n = int(input())
arr = [0] + list(map(int, input().split()))

pos = [0] * (n + 1)
for i in range(1, n + 1):
    pos[arr[i]] = i

if n == 1:
    q = int(input())
    for _ in range(q):
        input()
        print(1)
    sys.exit()

diff = [0] * (n)  # 1..n-1 used
for i in range(1, n):
    diff[i] = 1 if pos[i] > pos[i+1] else 0

st = SegTree(n-1)
st.build(1, 1, n-1, diff)

q = int(input())
for _ in range(q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 1:
        x, y = tmp[1], tmp[2]
        if x == y:
            print(1)
            continue
        res = st.query(1, 1, n-1, x, y-1)
        print(res + 1)
    else:
        x, y = tmp[1], tmp[2]
        a, b = arr[x], arr[y]

        if a == b:
            continue

        # swap in array
        arr[x], arr[y] = arr[y], arr[x]
        pos[a], pos[b] = y, x

        def fix(i):
            if 1 <= i <= n-1:
                val = 1 if pos[i] > pos[i+1] else 0
                st.update(1, 1, n-1, i, val)

        fix(a-1)
        fix(a)
        fix(b-1)
        fix(b)
```この実装では、値空間の構造が位置の更新から分離されます。 セグメント ツリーは、生の位置を格納することはなく、値の順序での隣接関係のみを格納します。これにより、クエリが範囲サイズに依存しなくなります。 

よくある落とし穴は、値ではなく位置に基づいてセグメント構造を維持しようとすることです。 これにより、スワップ時に中断される複雑な間隔マージが発生します。 正しい見方は、位置ではなく価値が安定の軸を定義するということです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    class SegTree:
        def __init__(self, n):
            self.n = n
            self.t = [0] * (4 * n)

        def build(self, v, l, r, arr):
            if l == r:
                self.t[v] = arr[l]
                return
            m = (l + r) // 2
            self.build(v*2, l, m, arr)
            self.build(v*2+1, m+1, r, arr)
            self.t[v] = self.t[v*2] + self.t[v*2+1]

        def update(self, v, l, r, i, val):
            if l == r:
                self.t[v] = val
                return
            m = (l + r) // 2
            if i <= m:
                self.update(v*2, l, m, i, val)
            else:
                self.update(v*2+1, m+1, r, i, val)
            self.t[v] = self.t[v*2] + self.t[v*2+1]

        def query(self, v, l, r, ql, qr):
            if ql > r or qr < l:
                return 0
            if ql <= l and r <= qr:
                return self.t[v]
            m = (l + r) // 2
            return self.query(v*2, l, m, ql, qr) + self.query(v*2+1, m+1, r, ql, qr)

    n = int(input())
    arr = [0] + list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i in range(1, n + 1):
        pos[arr[i]] = i

    diff = [0] * (n)
    for i in range(1, n):
        diff[i] = 1 if pos[i] > pos[i+1] else 0

    st = SegTree(n-1)
    st.build(1, 1, n-1, diff)

    q = int(input())
    out = []
    for _ in range(q):
        t = list(map(int, input().split()))
        if t[0] == 1:
            x, y = t[1], t[2]
            out.append(str(st.query(1, 1, n-1, x, y-1) + 1))
        else:
            x, y = t[1], t[2]
            a, b = arr[x], arr[y]
            arr[x], arr[y] = arr[y], arr[x]
            pos[a], pos[b] = y, x

            def fix(i):
                if 1 <= i <= n-1:
                    val = 1 if pos[i] > pos[i+1] else 0
                    st.update(1, 1, n-1, i, val)

            fix(a-1); fix(a); fix(b-1); fix(b)

    return "\n".join(out)

 ## 特殊なケース

 配列が完全にソートされている場合、重要なエッジ ケースが発生します。 その場合、すべての差分値は 0 になり、すべてのクエリは 1 を返します。セグメント ツリーは常に sum 0 を返すため、アルゴリズムはこれを自然に処理し、出力は 1 になります。 

もう 1 つのケースは、スワップに値空間内の隣接する値が含まれる場合です。 たとえば、値 i と i+1 の位置を交換すると、新しい位置に基づいて diff[i] が直接切り替わり、位置が重なっている場合は隣接する比較にも影響します。 更新ロジックは、交換された両方の値の周囲の i-1 および i+1 境界を明示的に再計算し、正確さを保証します。 

最後に、同じペアの繰り返しのスワップにより、古いセグメント ツリーの値が存続するかどうかがテストされます。 各スワップは pos[] からの影響を受けるすべての比較を再計算するため、履歴的な依存関係は残らず、操作履歴に関係なく構造の一貫性が保たれます。
