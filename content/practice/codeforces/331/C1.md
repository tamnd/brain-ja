 ## 問題の理解

 負ではない整数から始めます`n`。 

1 回の操作で、現在の数値の 10 進数表現を調べ、そこに表示される任意の桁を選択し、数値からその桁を減算します。 選択した数字はゼロにすることもできますが、ゼロを減算しても役に立ちません。そのため、有用な手では常に現在の数値に発生する正の数字を減算します。 

目標は、できるだけ少ない操作で正確にゼロに到達することです。 

たとえば、現在の値が`24`、使用可能な数字は次のとおりです。`2`そして`4`。 どちらかを減算してもよいでしょう。 最適なシーケンスの 1 つは次のとおりです。`24 → 20 → 18 → 10 → 9 → 0`これには 5 つの演算が使用されます。 

C1 バージョンの問題の場合、`n ≤ 10^6`。 この境界は、次のすべての値を考慮できるほど小さいです。`0`に`n`。 数値ごとに 1 つの状態を持つ動的プログラミング ソリューションには、およそ 100 万個の状態が必要ですが、これは時間とメモリの制限内で簡単に管理できます。 考えられるすべての減算シーケンスを繰り返し探索するアプローチは指数関数的に増大し、上限に達するずっと前に実行不可能になります。 

注目に値するいくつかの特殊なケースがあります。 

もし`n = 0`、操作はまったく必要ありません。 

入力：```
0
```出力：```
0
```すべての応答を大きな値に初期化し、開始状態を適切に処理しない不注意な実装では、別の何かが誤って報告される可能性があります。 

ゼロを含む数字も間違いのよくある原因です。 

入力：```
10
```利用可能な数字は次のとおりです`1`そして`0`。 引き算`0`数値を変更しないままにし、無駄な自己遷移を作成します。 正しい最適なシーケンスは次のとおりです。`10 → 9 → 0`したがって、答えは次のとおりです。```
2
```数字を盲目的に処理する実装`0`注意しないと、再帰的ソリューションで誤って無限ループが作成される可能性があります。 

1 桁の数字はすぐに答えが得られます。 

入力：```
7
```出力：```
1
```桁以降`7`数値に「」が表示されている場合は、それを直接減算して 1 回の操作でゼロに到達することができます。 

## アプローチ

 最も直接的な考え方は、すべての減算シーケンスをパスとして考えることです。 数字から`x`に移動できます`x - d`すべての桁ごとに`d`に登場する`x`。 あらゆる可能性を再帰的に試し、最小限のステップを踏めば、最終的には正しい答えが得られます。 

問題は、同じ中間値が繰り返し現れることです。 たとえば、多くの異なるパスが次の番号に到達する可能性があります。`137`毎回その答えを再計算すると、作業量が爆発的に増加します。 可能な減算シーケンスの数は指数関数的に増加します。 

重要な観察は、数値の答えはより小さい数値の答えにのみ依存するということです。 以下のすべての値に必要な最小限の操作がすでにわかっている場合`x`、その後、次の答えを計算できます。`x`に表示されるすべての数字を試してみることで、`x`。 

させて`dp[x]`削減するために必要な最小操作数を示します。`x`ゼロに。 

数字と仮定します`d`に登場する`x`そして`d > 0`。 差し引いた後`d`に到着します。`x - d`。 最初の移動には 1 回の操作が必要で、その後は`dp[x - d]`さらに多くの操作。 それがトランジションを与える`dp[x] = min(dp[x], dp[x - d] + 1)`。 

すべての遷移はより小さい数値に進むため、値を次から昇順に処理できます。`1`に`n`。 計算するとき`dp[x]`、必要な状態はすべてすでに計算されています。 

これにより、この問題は、整数ごとに 1 つの状態をもつ単純な動的プログラミング ソリューションに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数再帰ツリー | 遅すぎる |
 | 最適なDP | O(n log n) | O(n) | 承認済み |

 の`log n`係数は、各数値の桁を抽出して得られます。 

## アルゴリズムのチュートリアル

 1. 入力値を読み取る`n`。 
2. 配列を作成する`dp`サイズの`n + 1`。 
3.セット`dp[0] = 0`ゼロはすでに操作を必要としないためです。 
4. すべての数字について`x`から`1`に`n`、初期化します`dp[x]`大きな値にします。 
5. のすべての桁を抽出します。`x`繰り返し摂取することで`x % 10`で割る`10`。 
6. ゼロ以外のすべての数字について`d`に登場する`x`、最初の動きとしてその減算を行うことを検討してください。 
7.アップデート`dp[x] = min(dp[x], dp[x - d] + 1)`。 

値`dp[x - d]`すでに知られているので、`x - d < x`。 
8. すべての桁を処理した後、`x`、`dp[x]`その数値に対する最適な答えを保存します。 
9. 出力`dp[n]`。 

### なぜ効果があるのか

 動的プログラミングの状態は、特定の値からゼロに到達するために必要な真の最小操作数を表します。 

からのすべての有効な最初の動き`x`その数字の 1 つを減算する必要があります。 数字を選択した後`d`、残りの作業はまさに次の最適解です。`x - d`。 したがって、有効な戦略には必ずコストがかかります`1 + dp[x - d]`ある桁について`d`に登場する`x`。 

アルゴリズムはそのようなすべての最初の手をチェックし、最小限を維持します。 より小さい状態はすべてすでに正しく計算されているため、選択された最小値は、次の場合の真の最適値と等しくなります。`x`。 値の増加に関する帰納法により、`x`、すべての状態が正しく計算されます。`dp[n]`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    dp = [0] * (n + 1)

    for x in range(1, n + 1):
        dp[x] = 10**9

        t = x
        while t > 0:
            d = t % 10
            if d != 0:
                dp[x] = min(dp[x], dp[x - d] + 1)
            t //= 10

    print(dp[n])

if __name__ == "__main__":
    solve()
```配列`dp`すべての値の最小操作数を最大で保存します。`n`。 

外側のループは数値を昇順に処理します。 すべての遷移は次から始まるため、この順序は不可欠です。`x`に`x - d`、常に厳密に小さくなります`d > 0`。 計算する頃には`dp[x]`、必要なすべての先行状態がすでに使用可能です。 

数字の抽出は、係数と除算を繰り返して直接実行されます。 これにより、あらゆる数値を文字列に変換することがなくなり、実装がシンプルかつ効率的に保たれます。 

数字を無視する`0`重要です。 ゼロを減算しても数値は変化せず、ある状態からそれ自体への遷移が作成されます。 このような動きは決して答えを改善することはできません。 

基本的なケース`dp[0] = 0`繰り返し全体を固定します。 1 桁の数値は、その桁の 1 つが数値そのものに等しいため、自然に機能し、ゼロへの直接遷移が可能になります。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())

    dp = [0] * (n + 1)

    for x in range(1, n + 1):
        dp[x] = 10**9
        t = x

        while t > 0:
            d = t % 10
            if d:
                dp[x] = min(dp[x], dp[x - d] + 1)
            t //= 10

    print(dp[n])

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("24\n") == "5\n", "sample 1"

# minimum value
assert run("0\n") == "0\n", "n = 0"

# single digit
assert run("7\n") == "1\n", "single digit reaches zero directly"

# contains zero digit
assert run("10\n") == "2\n", "must ignore digit 0"

# another small boundary case
assert run("1\n") == "1\n", "smallest positive number"

 ## 特殊なケース

 次の入力を考えてみましょう。```
0
```アルゴリズムが初期化されます`dp[0] = 0`そしてトランジションは実行されません。 出力はすぐに行われます`0`。 これは、数値がすでにゼロであるという事実と一致します。 

次の入力を考えてみましょう。```
10
```加工時`10`、抽出された数字は次のとおりです。`1`そして`0`。 アルゴリズムは無視します`0`数字による遷移のみを使用します`1`:`dp[10] = dp[9] + 1 = 2`。 

結果のシーケンスは次のとおりです`10 → 9 → 0`、これが最適です。 

次の入力を考えてみましょう。```
7
```唯一ゼロ以外の数字は、`7`。 遷移は次のようになります。`dp[7] = dp[0] + 1 = 1`。 

アルゴリズムは、1 回の減算がゼロに達することを正しく認識します。 

次の入力を考えてみましょう。```
100
```数字は`1`、`0`、 そして`0`。 アルゴリズムは両方のゼロを無視し、減算のみを考慮します。`1`への移行を生成します。`99`。 無効な自己遷移は導入されず、DP は正常に続行されます。 これはまさに問題で必要な動作です。
