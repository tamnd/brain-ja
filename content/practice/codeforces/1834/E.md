 ## 解決策
 ## 問題の理解

 与えられた配列の連続する部分配列の最小公倍数として現れない最小の正の整数を見つけるように求められます。 入力は複数のテスト ケースで構成されます。 各テスト ケースに対して、整数の配列が与えられ、出力は、一部のサブセグメントの LCM として「欠落している」最小の整数になります。 

重要な観察は、問題は連続要素に対する LCM 演算による数値の構築に関するものであるということです。 単一要素のサブセグメントは、配列内に存在するすべての数値を即座に返します。 より大きなサブセグメントは倍数または組み合わせを生成する可能性がありますが、配列に必要な要素が不足しているため、一部の整数は形成されません。 タスクは、そのような最小の整数を効率的に識別することです。 

制約は、すべてのサブ配列の単純な列挙が実行不可能であることを示唆しています。 配列の長さは最大 3×10^5 に達する可能性があり、すべてのサブセグメントを反復処理すると O(n^2) かそれ以上になり、遅すぎます。 このため、到達可能な LCM を明示的に計算するのではなく、動的に推論する必要があります。 エッジ ケースには、長さ 1 の配列、繰り返しの数値を含む配列、大きな素数を含む配列、および連続する小さな整数で構成される配列が含まれます。 たとえば、配列`[2,3]`のサブセグメント最小公倍数が即座に得られます。`2`、`3`、 そして`6`。 ここでの最小の適切な整数は次のとおりです。`1`、サブセグメントが生成しないため、`1`。 小さな整数を系統的にチェックしないと、不正確な答えが生じる可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、すべての連続するサブセグメントが生成され、それらの LCM が計算されます。 これは、定義上、考えられるすべてのサブセグメントをチェックするため、原則的には正しいです。 問題は、サブセグメントの数が n とともに二次関数的に増加し、各サブセグメントの最小公倍数を単純に計算すると、大きな整数の場合にコストが高くなり、最適化されていない場合、最悪のケースでは O(n^3) になる可能性があることです。 問題の制約を考慮すると、これでは明らかに遅すぎます。 

最適なアプローチでは、LCM が急速に成長し、その素因数で表すことができることが認識されます。 すべてのサブセグメントを個別に考慮するのではなく、配列内の各位置で終わるすべての可能な LCM のセットを維持します。 配列を反復処理し、現在の要素と以前の各 LCM を組み合わせて、到達可能な LCM のセットを更新します。 セットの爆発を避けるために、妥当な範囲を超える最小公倍数は、より小さい適切な整数に寄与できないため、それらをプルーニングします。 配列全体を処理したら、1 から上に向かって反復して、到達可能な LCM セットにない最小の整数を見つけます。 これにより、冗長な大規模な LCM を保存したり計算したりすることがなく、LCM の単調増加を利用して候補を効率的にプルーニングするため、複雑さが大幅に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n^2) | 遅すぎる |
 | 最適 | O(n log a_max) | O(n log a_max) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、配列のサイズと要素を読み取ります。 
2. 空のセットを初期化する`current_lcms`これには、前の要素で終わるサブセグメントのすべての LCM が保存されます。 
3. 配列を反復処理します。 要素ごとに`a[i]`、新しいセットを作成します`next_lcms`そして挿入します`a[i]`。 これは、この位置で終わる長さ 1 のサブセグメントの LCM を表します。 
4. 各 LCM について`x`で`current_lcms`、計算する`lcm(x, a[i])`そしてそれを追加します`next_lcms`。 これにより、以前のすべてのサブセグメントが拡張され、現在の要素が含まれます。 特定のしきい値を超える LCM をスキップします。欠落している最小の整数を探しているため、大きな数値は無関係です。 
5.アップデート`current_lcms`なる`next_lcms`。 配列全体を処理した後、`current_lcms`可能なすべてのサブセグメントのすべての LCM が含まれます。 
6. 変数を初期化する`mex = 1`存在しなくなるまで増加させます`current_lcms`。 これは、サブセグメントの最小公倍数ではない最小の正の整数です。 

機能する理由: 各ステップで次のことが保証されます。`current_lcms`現在のインデックスで終わるすべてのサブセグメントの LCM が正確に含まれます。 LCM を前方に伝播し、現在の要素を長さ 1 のサブセグメントとして含めることにより、考えられるすべての連続 LCM をキャプチャします。 不変条件は、位置 i を処理した後、`current_lcms`は、i で終わるサブセグメントの最小公倍数の正確なセットです。 MEX を見つけるための最後の反復では、1 から始まるすべての整数が体系的にチェックされるため、正確さが保証されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        current_lcms = set()
        for num in a:
            next_lcms = {num}
            for x in current_lcms:
                l = x * num // math.gcd(x, num)
                if l <= 10**9 + 5:  # threshold to avoid unnecessary large numbers
                    next_lcms.add(l)
            current_lcms = next_lcms
        mex = 1
        while mex in current_lcms:
            mex += 1
        print(mex)

if __name__ == "__main__":
    solve()
```コードは入力を効率的に読み取ります。`sys.stdin.readline`そして、セットを使用して、各位置で終わるすべてのサブセグメントの最小公倍数を動的に維持します。 GCD ベースの LCM 計算は精度を確保し、次の式を使用して整数のオーバーフローを防ぎます。`x * y // gcd(x, y)`。 しきい値により、適切な整数を最小限に抑えることができない巨大な LCM の保存が防止され、メモリと計算が管理可能に保たれます。 

## 実用的な例

 入力のトレース`[1, 2, 3]`:

 | 私 | 番号 | 現在の_lcms | 次の_lcms |
 | --- | --- | --- | --- |
 | 0 | 1 | {} | {1} |
 | 1 | 2 | {1} | {2, 2*1/gcd(2,1)=2} = {2,2} → {2} |
 | 2 | 3 | {2} | {3, lcm(2,3)=6} → {3,6} |

 反復後、すべてのセットを結合します: {1,2,3,6}。 MEXは4です。 

入力のトレース`[2, 3]`:

 | 私 | 番号 | 現在の_lcms | 次の_lcms |
 | --- | --- | --- | --- |
 | 0 | 2 | {} | {2} |
 | 1 | 3 | {2} | {3, lcm(2,3)=6} → {3,6} |

 すべてのセットを結合します: {2,3,6}。 MEXは1です。 

これらのトレースは、単一要素のサブセグメントと拡張サブセグメントが到達可能なすべての LCM を生成し、アルゴリズムが欠落している最小の整数を正しく検出することを確認します。
