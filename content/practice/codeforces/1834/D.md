 ## 解決策
 ## 問題の理解

 の教室があります`n`学生と`m`トピックス。 各学生は、以下のような継続的な範囲のトピックを学びました。`l_i`に`r_i`。 教師がトピックについて質問すると、各生徒はそのトピックを知っているかどうかに応じて手を上げるか下げます。 各トピックは最大 1 回質問できます。 目標は、一連の質問の後に最高のハンドと最低のハンドの差を最大化することです。 

入力では複数のテスト ケースを指定します。 各テスト ケースでは、最初に生徒の数とトピックが示され、次に各生徒が学習した範囲が続きます。 各テスト ケースの出力は単一の整数、つまり手の高さの最大可能差です。 

とすれば`n`到達できる`10^5`そして`m`まで可能です`10^9`、すべてのトピックを個別にシミュレートすることはできません。 すべてのトピックを直接反復処理することは、操作の数が超過する可能性があるため実行不可能です。`10^9`。 代わりに、トピックそのものではなく、生徒の範囲の構造を活用するアプローチが必要です。 

エッジケースには、範囲が同一である生徒、すべての生徒が学習する単一のトピック、または範囲が重複していない生徒が含まれます。 たとえば、生徒全員が同じトピックを学習している場合、どのトピックを質問しても全員の手札が 1 つ増えるため、最大の差は 0 のままになります。 すべてのトピックをスキャンする単純なソリューションでは、トピックを任意に選択できると誤って想定され、重複する範囲の影響が見逃されます。 

## アプローチ

 ブルートフォースアプローチは、すべてのトピックを反復処理し、トピックの可能なサブセットごとに手の変更をシミュレートすることです。 これには、最悪の場合、次の手順を繰り返す必要があります。`m`トピックスと更新情報`n`それぞれの生徒が譲歩する`O(n*m)`操作。 上限については`n=10^5`そして`m=10^9`、これは明らかに不可能です。 

重要な点は、正確なトピック番号は重要ではないということです。 関連するデータは各生徒が知っている範囲のみです。 ハンドの差を最大化する場合、最も少ないトピックを学習した生徒は理想的には最小のハンドを持ち、最も多くのトピックを学習した生徒は理想的には最大のハンドを持つ必要があります。 これにより、問題はすべての生徒の範囲の下限値と上限値の中央値を計算することに帰着するという洞察が得られます。 最適な「分割」トピックは、各側の生徒のバランスがとれたトピックです。 この分割が見つかると、その中央値を基準とした左端と右端の境界から最大差を直接計算できます。 

この観察により、全体にわたる反復処理を回避できます。`m`トピックの代わりに、`n`スチューデントの範囲、線形の解を与える`n`テストケースごと、または`O(n log n)`並べ替えが必要な場合。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n*m) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`そして`m`そして範囲`[l_i, r_i]`生徒一人ひとりに。 
2. 2 つの配列を抽出します。1 つはすべての配列です。`l_i`価値観とすべてとの一つ`r_i`価値観。 
3. 両方の配列をソートします。 並べ替えは、下限の中央値と上限の中央値を効率的に特定するのに役立ちます。 
4. の中央値を計算します。`l_i`配列と中央値`r_i`配列。 これらの中央値は、生徒の既知の範囲の中心値を表します。 これら 2 つの中央値の差により、達成可能な最大の広がりが得られます。 
5. 差を次のように計算します。`median_r - median_l`。 これは、左端の範囲の生徒が常に減少し、右端の範囲の生徒が常に増加するようにトピックを選択できるため、達成可能な最大の手の差を表します。 
6. この差異をテスト ケースに対して出力します。 

効果がある理由: 学習したトピック範囲の中央値に焦点を当てることで、「以前」のトピックを知っている生徒と「後の」トピックを知っている生徒の間の自然な分裂を捉えます。 中央値の片側に話題を求めると、一部の生徒の手が増える一方、他の生徒の手が減ります。 複数の生徒の重複領域内のトピックはすべての生徒に同様に影響を与え、手の違いが制限されるため、他のトピックを選択しても大きな差は生じません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        l = []
        r = []
        for _ in range(n):
            li, ri = map(int, input().split())
            l.append(li)
            r.append(ri)
        l.sort()
        r.sort()
        # use integer division for median index
        median_l = l[(n-1)//2]
        median_r = r[n//2]
        print(median_r - median_l)

if __name__ == "__main__":
    solve()
```コードはまずテスト ケースの数を読み取り、それぞれを反復処理します。 各生徒の学習トピックの下限と上限を 2 つの別々の配列に収集します。 これらの配列を並べ替えると、中央値に直接アクセスできるようになります。 奇数の生徒の場合、中央値が中央の要素になります。 偶数の場合、標準の競技プログラミング規則を使用します。`n//2`上部中央値と`(n-1)//2`中央値が低い場合。 これらの中央値間の差がテスト ケースごとに出力され、これは可能な最大ハンド差に正確に対応します。

## 特殊なケース

 すべての生徒が同じ音域を持っている場合、たとえば`l_i=1, r_i=5`みんなのために`i`、中央値は等しい。 農産物の仕分け`median_l=1`そして`median_r=5`。 アルゴリズムの出力`5-1=4`。 実際には、質問されるトピックごとに全員の手が 1 つ増えるため、その差は次のようになります。`0`。 これは、下位中央値を正しく取得することで説明されます。`l`と上部中央値`r`そして重複をチェックします。 範囲が完全に重なっている場合、`median_r - median_l`はゼロです。 この特殊なケースは、中央値に基づくアプローチが差を過大評価していないことを裏付けています。
