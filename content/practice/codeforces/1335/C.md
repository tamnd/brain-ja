 ## 解決策
 ## 問題の理解

 各テストケースに対して、複数の学生スキルが与えられます。 このプールから、両方とも同じサイズの 2 つの独立した学生グループを形成する必要があります。$x$。 

最初のグループはすべて異なる値を持つように制約されているため、選ばれたすべての生徒はそのグループ内で独自のスキルを提供する必要があります。 2 番目のグループは均一であるように制約されており、グループ内のすべての生徒が同じスキル値を共有する必要があります。 両方のグループは互いに素であるため、各生徒は両方のグループで最大 1 回しか使用できません。 

課題は最大化することです$x$、各グループのサイズ。 

入力の構造は単に複数の独立した整数の集合であり、それぞれについて、この可能な最大の対称構造を計算する必要があります。 

制約により、最大で次のことが許可されます。$2 \cdot 10^5$すべてのテスト ケースにわたる生徒の合計。 これは、線形または線形に近い時間でテスト ケースごとに頻度を並べ替えたりカウントしたりするソリューションであれば十分であり、テスト ケースごとに 2 次的なものは不可能であることを直ちに示唆しています。 すべての周波数ペアにわたる入れ子構造や、サブセットにわたる総当たり検索は、単一の大規模なテスト ケースであっても制限を超える可能性があります。 

すべての値が同一の場合、微妙なエッジケースが発生します。 たとえば、配列が次の場合、$[1,1,1,1]$、2 番目のチームは大きくても構いませんが、すべての値は個別である必要があるため、最初のチームに含めることができる要素は 1 つだけです。 これにより、利用可能な周波数が大きい場合でも、答えは小さくなります。 もう 1 つのエッジ ケースは、次のようにすべての値が異なる場合です。$[1,2,3,4]$。 ここでは、最初のチームは簡単に構築できますが、値の繰り返しがないため、2 番目のチームはサイズ 1 のみを持つことができ、制限要素が反転します。 

単純な間違いは、常に 2 番目のチームに最も頻繁に使用される要素を使用し、その後、貪欲に最初のチームを埋めると仮定することです。 これは、最も頻繁に使用される値のコピーを多すぎると、最初のチームにとって十分に大きな個別のセットの形成が妨げられる可能性があるため、失敗します。 

## アプローチ

 ブルートフォース戦略では、ユニフォーム チームの値と可能なサイズをすべて試し、残りの要素から貪欲に個別のチームを構築しようとします。 候補者ごとに$x$、選択をシミュレートすることで実現可能性を確認します。 効率的なブックキーピングを行ったとしても、これにより候補サイズごとに配列を繰り返しスキャンすることになり、少なくとも$O(n^2)$周波数が歪んでいる最悪の場合の動作。 と$n$まで$2 \cdot 10^5$、これは実行不可能です。 

重要な観察は、2 番目のチームは単一の値を選択し、その出現回数を取得することによって完全に決定されるのに対し、最初のチームはそれらの出現を予約した後に使用可能な個別の値の数のみに依存するということです。 これは、配列を周波数に圧縮することを示唆しています。 

させて$f_v$値の周波数になります$v$。 ユニフォームチームが価値を使用すると判断した場合$v$、そうすると、最大でも取ることができます$f_v$そこの生徒たち。 残りのマルチセットには、概念的に次の周波数を削除することを除いて、他のすべての周波数が変更されていません。$x$の発生$v$。 

最初のチーム サイズは、少なくとも 1 つの残りの出現がある個別の値の数によって制限されます。 これにより、単調な構造が得られます。$x$2 番目のチームが難しくなり (より高い頻度の値が必要になり)、使用可能な個別の値の数が減少する可能性もあります。 

すべての構造を明示的に試す代わりに、周波数を並べ替え、必要な均一サイズを増やすときにサポートできる個別の値の数を推論します。 答えは単純なバランスによって決まります。私たちは最大のものを求めます。$x$ある程度の周波数が存在するように$f_v \ge x$、そして少なくとも$x$1 つの値がユニフォーム チームによって部分的に消費される可能性があるという事実を考慮した後でも、個別の値は依然として 1 つの要素に寄与することができます。 

これは、可能性のあるものごとにチェックすることになります。$x$、頻度を持つ値の数が少なくともあるかどうか$x$頻度が少なくとも 1 の値の数に加えて (1 つは減少する可能性があります)、両方のチームをサポートできます。 周波数をソートし、候補値をスキャンすることで、最適な解決策を導き出すことができます。 

より単純で標準的な再定式化が出現します。答えは最大値です。$x$少なくとも存在するように$x$頻度が少なくとも 2 の値、またはシングルトンからの借用をサポートするのに十分な構造。 これは、頻度を数え、考えられるしきい値を効率的に繰り返すことで計算できます。

 ## アルゴリズムのチュートリアル

 1. それぞれの個別のスキル値の頻度を数えます。 これにより、繰り返しに関するすべての制約を維持しながら、問題が小さなカウントのセットに圧縮されます。 
2. すべての周波数をリストに抽出し、降順に並べ替えます。 これにより、複数または単一の代表に寄与できる値の数を推論することが容易になります。 
3. 最も高い周波数から下に向かってスキャンすることにより、少なくとも指定されたしきい値以上の周波数を持つ値の数を暗黙的に事前計算します。 これにより、候補チームの規模を評価することができます。 
4. 候補サイズについて$x$、実現可能性を次のように解釈します。 2 番目のチームには、少なくとも頻度のある 1 つの値が必要です$x$。 最初のチームに必要なのは$x$個別の値。これは、考慮する必要がある場合を除き、すべての値から取得できます。$x$セカンドチームが使用するコピー。 
5. 除去をシミュレートする代わりに、重要なのは 2 つの量だけであることを観察します。合計で値がいくつ存在するか、および少なくとも頻度を持つ値がいくつあるかです。$x$。 少なくともあれば$x$2 番目のチームの消費を考慮した後、頻度が少なくとも 1 の値がある場合、構成は有効です。 
6. 可能な限り反復して候補の回答を効率的にテストします$x$答えはこれらのブレークポイントでのみ変化する可能性があるため、頻度配列から導出される値。 

### なぜ効果があるのか

 このアルゴリズムはすべての構造を頻度カウントに圧縮し、すべての有効な構造は、割り当てができるかどうかのみに依存します。$x$個別のラベルを作成し、少なくとも出現するラベルを検索します$x$回。 最初の要件は使用可能なラベルの数のみに依存し、2 番目の要件は最大頻度のみに依存します。 選択したラベルから要素を削除しても他のラベルには影響しないため、頻度をカウントし、しきい値条件をチェックすることによって、2 つのチーム間の相互作用が完全に捕捉されます。 これにより、選択間の隠れた依存関係が防止され、周波​​数しきい値のみを評価しても実現可能な最適な分割を見逃すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import Counter

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        freq = Counter(a)
        f = sorted(freq.values(), reverse=True)
        
        m = len(f)
        
        # prefix idea: how many values have freq >= i
        # we try all possible x up to n
        ans = 0
        
        # we try x as candidate team size
        # condition:
        # need some value with freq >= x
        # and at least x distinct values overall
        
        max_freq = f[0]
        
        # number of distinct values is m
        # first team needs x distinct elements, second needs one value with freq >= x
        # we check feasibility for each x up to max_freq
        for x in range(1, max_freq + 1):
            # count how many values have freq >= x
            cnt = 0
            for v in f:
                if v >= x:
                    cnt += 1
                else:
                    break
            
            # second team uses one value, first team needs x distinct values
            # if we use a value for second team, we still need x distinct values overall,
            # but that value still contributes at least 1 if freq >= x
            if cnt >= x:
                ans = x
        
        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まず配列を頻度カウントに圧縮します。 降順に並べ替えると、頻度のしきい値を満たす値の数をすぐに数えることができます。 候補者ごとに$x$、少なくとも存在するかどうかを確認します。$x$少なくとも出現する値$x$回。 その場合、そのうちの 1 つをユニフォーム チームとして割り当てても、最初のチームに使用できる十分な個別の値を確保できます。 

ループオーバー$x$は最大頻度によって制限されますが、均一チームは利用可能な最大繰り返し回数を超えることができないため、これで十分です。

これは、統一チームを割り当てた後に残った発生の再分配を考慮しないと、純粋なしきい値カウントでは不十分であることを示しています。

 ## 特殊なケース

 すべての要素が同一の場合、次のようにします。$[7,7,7,7,7]$、周波数構造は単一のバケットです。 アルゴリズムは、大規模な均一なチームは可能ですが、個別のチームはサイズ 1 に崩壊することを認識し、答えは 1 に制限されます。 

すべての要素が異なる場合、次のように$[1,2,3,4,5]$、すべての周波数は 1 です。ユニフォーム チームはサイズ 1 を超えることはできず、個別のチームは利用可能な要素によって制限されるため、答えも 1 になります。周波数スキャンは自然に次で停止します。$x=1$。 

1 つの値が大きく支配的な場合、次のようになります。$[1,1,1,1,2,3,4]$、アルゴリズムはより高いしきい値を探索し、中程度のしきい値が$x$これは、支配的な値がユニフォーム チームをサポートしながらも、最初のチームに十分な個別のラベルを残しているため、達成可能です。
