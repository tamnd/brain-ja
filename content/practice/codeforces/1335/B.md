 ## 問題の理解

 テストケースごとに、次の長さの小文字の文字列を構築する必要があります。`n`。 条件は、長さのすべての連続セグメントが`a`正確に含まれている必要があります`b`違う文字。 任意の有効な文字列を使用できます。 

数値はスライディング ウィンドウの状態を表します。 ポジション別に見てみると`1...a`、 それから`2...a+1`、 それから`3...a+2`、そのようなすべてのウィンドウには、同じ数の個別の文字が含まれている必要があります。 文字自体を自由に選択できます。 

すべての値の合計`n`は最大でも 2000 なので、二次アルゴリズムでも問題なく適合します。 課題はパフォーマンスではなく、シンプルな構造を見つけることです。 アルファベットは小文字が26文字しかないので、`b ≤ a`、有効な答えは常に存在します。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

仮定する`a = 1`そして`b = 1`。```
1
6 1 1
```長さ 1 のすべての部分文字列には、異なる文字が 1 つだけ含まれるため、どの文字列でも機能します。 正しい出力は```
aaaaaa
```複数の文字を循環させようとする不注意な解決策でも機能する可能性がありますが、必要な文字は 1 つだけであるという事実が見落とされます。 

もう一つの興味深いケースは次のような場合です。`a = b`。```
1
5 5 5
```長さ 5 の唯一の部分文字列には、5 つの異なる文字が含まれている必要があります。 考えられる答えの 1 つは、```

```5 文字未満を使用すると要件に違反します。 

より微妙な例は次のとおりです```

```次のような文字列```

```長さ 5 の各ウィンドウには文字のみが含まれるため、機能します。`a`、`b`、 そして`c`。 代わりに使用した場合```

```最初のウィンドウには 5 つの異なる文字が含まれますが、これは正しくありません。 

## アプローチ

 ブルートフォース戦略では、文字列を 1 文字ずつ構築しようとします。 新しい位置ごとに、26 文字すべてをテストし、影響を受ける長さの部分文字列がすべてあるかどうかを確認できます。`a`まだ正確にあります`b`個性的なキャラクター。 それぞれの検証は まで調べますので、`a`キャラクターが増えると、仕事の量はすぐに増えます。 問題のより大きなバージョンでは、探索空間自体が膨大になるため、このアプローチは魅力的ではなくなります。 

重要な点は、すべてのウィンドウを独立して満たす必要はないということです。 文字セットにすでに正確な内容が含まれる繰り返しパターンを作成すると、`b`異なる文字、その後、あらゆる長さ -`a`ウィンドウは同じセットを継承します。 

最初を取る`b`アルファベットの文字を順番に繰り返します。```
abcabcabc...
```以来`b ≤ a`、任意の長さの連続したブロック`a`それらだけを見る`b`ピリオドが正確に一致するため、各文字はブロック内のどこかに表示されます。`b`。 スライディング ウィンドウは自動的に条件を満たします。 

ブルート フォースは要件を直接チェックするため機能しますが、不必要に検索するため失敗します。 答えが周期的である可能性があるという観察により、問題は単純な構造に帰着します。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、最初のテスト ケースを準備します。`b`小文字:`"abc..."`。 
2. 一度に 1 つの位置ずつ答えを作成します。 
3. 位置で`i`、インデックスが次の文字を配置します。`i mod b`。 

これにより、長さの繰り返しパターンが作成されます`b`。 
4. 文字列が長さに達するまで続けます`n`。 
5. 構築された文字列を出力します。 

### なぜ効果があるのか

 繰り返しブロックには正確に次の内容が含まれます`b`はっきりとした文字。 その期間も`b`、すべてのグループ`b`連続した位置にはこれらすべての文字が含まれます。 長さのある窓`a`少なくとも以下の長さである`b`したがって、そのようなウィンドウにはそれぞれ、`b`少なくとも一度は手紙を送ります。 最初の文字のみが表示されるため、追加の文字は表示されません。`b`文字が使われています。 したがって、長さのすべての部分文字列`a`正確に含まれています`b`個性的なキャラクター。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
ans = []

for _ in range(t):
    n, a, b = map(int, input().split())
    cur = []

    for i in range(n):
        cur.append(chr(ord('a') + (i % b)))

    ans.append("".join(cur))

print("\n".join(ans))
```このソリューションはテスト ケースを個別に処理します。 

表現`i % b`繰り返しブロックのどの文字を使用するかを決定します。 位置`0`取得します`'a'`、 位置`1`取得します`'b'`、 等々。 に到達した後、`b`- 番目の文字で、パターンが再び始まります。 

変数`a`コードには現れません。 最初は疑わしいように見えるかもしれませんが、上記の証明は、なぜ唯一の要件が以下であるかを説明しています。`b ≤ a`。 期間が過ぎたら`b`、長さのすべてのウィンドウ`a`自動的にすべてが含まれます`b`手紙。 

リストを使用して、`"".join()`文字列の連結の繰り返しを回避し、実装の効率を維持します。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        n, a, b = map(int, input().split())
        cur = []

        for i in range(n):
            cur.append(chr(ord('a') + (i % b)))

        ans.append("".join(cur))

    return "\n".join(ans)

# provided sample
assert run(
"""4
7 5 3
6 1 1
6 6 1
5 2 2
"""
) == "abcabca\naaaaaa\naaaaaa\nababa"

# minimum size
assert run(
"""1
1 1 1
"""
) == "a"

# all values equal
assert run(
"""1
5 5 5
"""
) == "abcde"

# single distinct letter
assert run(
"""1
8 4 1
"""
) == "aaaaaaaa"

# maximum length pattern
assert run(
"""1
10 10 3
"""
) == "abcabcabca"
