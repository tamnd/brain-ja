 ## 問題の理解

 それぞれに整数の明るさの値を割り当てることができる方法が何通りあるかを数えています。$n$星。 各スターには独自の許容間隔があるため、$i$- 番目の星は間になければなりません$l_i$そして$r_i$。 このようなすべての割り当ての中で、選択されたすべての値の合計が以下を超えないものだけが保持されます。$m$、選択されたすべての値の最大公約数は正確に 1 です。 

したがって、私たちは効果的に取り組んでいます$n$-次元の有界整数ボックス。グローバル合計制約と交差し、すべての座標で乗算条件によってフィルター処理されます。 

ここでは制約が実際の信号です。 変数の数は最大 50 ですが、値は最大 50 です。$10^5$。 この組み合わせは、通常、変数ごとの選択肢に対する直接的な指数列挙は不可能であることを示しますが、各次元を小さく保つことができれば、変数ごとの畳み込みまたはナップザック スタイルの動的プログラミングが実現可能であることも示します。 タプルに対する gcd 制約はほとんどの場合、割り算制約に変換されるため、gcd 条件の存在はメビウス反転を強く示唆しています。 

単純なアプローチでは、すべての有効なタプルを列挙しようとしますが、gcd を無視しても、組み合わせの数はおよそ$\prod (r_i - l_i + 1)$、それは天文学的に大きくなる可能性があります。 合計制約はすべての次元を結合するため、星のサブセットにわたる DP であっても、ここでは意味がありません。 

2 番目の単純なアイデアは、gcd を状態として追跡しながら、合計に対してナップザック DP を実行することです。 gcd 値は大きく変化し、以前のすべての要素に依存する可能性があるため、これはすぐに失敗し、状態空間が管理不能になる可能性があります。 

DP 状態をフィルタリングすることで最後に gcd 条件を強制しようとすると、より微妙な障害モードが表示されます。有効な和限定割り当てをすべてカウントし、割り当てごとに gcd をチェックしようとしますが、個別に再検討するには割り当てが多すぎます。 

主な問題点は、gcd 条件がグローバルかつ乗算的であるのに対し、sum 制約は加算的であることです。 これら 2 つの構造は通常、メビウス反転によってきれいに分離されます。 

## アプローチ

 gcd 要件を少し無視すると、問題は、個々の間隔とグローバル合計制限を考慮して、星ごとに 1 つの値を選択する方法の数を数えることになります。 これは制約付き多次元ナップザック問題です。 なぜなら$n$が小さい場合は、星を 1 つずつ処理して合計に対して DP を構築しようとするかもしれません。 星ごとに、許容値を使用して 0 ～ 1 のような小さな畳み込みを追加します。 これはすでに多項式乗算構造を示唆しています。各スターは多項式に寄与し、係数の位置は総和への可能な寄与に対応します。 

総当たりの DP オーバーサムは機能しますが、値が小さく固定されている場合に限ります。 ここで問題となるのは、間隔が星ごとに異なることです。また、問題をさまざまな gcd 仮定に変換した後、この計算を何度も繰り返す必要があります。 

gcd 制約が転換点となります。 gcd を 1 に直接強制しようとする代わりに、視点を反転します。gcd がいくつかの値で割り切れるすべての構成をカウントします。$d$次に、メビウス反転を使用して、1 つのケースに等しい正確な gcd を分離します。 具体的に関数を定義すると、$F(d)$選択されたすべての値が次で割り切れる有効な構成の数として$d$、合計すると答えが得られます$F(d)$メビウス関数で重み付け$\mu(d)$。 

約数を固定したら$d$、すべての有効な構成にはすべてが含まれている必要があります。$a_i$形の$a_i = d \cdot b_i$。 これにより各間隔が変換されます$[l_i, r_i]$圧縮された間隔に$[\lceil l_i/d \rceil, \lfloor r_i/d \rfloor]$。 合計制約は次のようになります。$\sum b_i \le \lfloor m/d \rfloor$。 さて、問題は純粋に加算的なものです。

これらの多項式を直接乗算するのは、すべてに対して素朴に実行すると遅すぎます。$d$。 節約できる観察結果は、すべてのサイズの合計が$d$の調和系列のように動作します。$m/d$、各畳み込みは数論的変換で実行でき、合計の複雑さは次のようになります。$m \log^2 m$によって拡大縮小される$n$、制約としては許容されます。

 ## アルゴリズムのチュートリアル

 1. メビウス関数を次まで事前計算します。$m$、すべての約数が gcd 値の包含/除外に寄与するためです。 これにより、gcd の割り切れる数から 1 に等しい gcd を分離するために必要な係数が得られます。 
2. 可能なすべての約数を反復処理します。$d$1から$m$。 それぞれについて$d$、何も貢献しない場合はスキップします。つまり、変換されたすべての区間が空になります。 
3. 現在のところ$d$、各区間を変換します$[l_i, r_i]$の中へ$[L_i, R_i]$どこ$L_i = \lceil l_i/d \rceil$そして$R_i = \lfloor r_i/d \rfloor$。 何かあれば$i$、$L_i > R_i$の場合、これに対する設定はできません$d$。 
4. 目標合計限度額を次のように設定します。$S = \lfloor m/d \rfloor$。 選択する方法の数を数えます$b_i \in [L_i, R_i]$合計が最大で$S$。 
5. DP 多項式の初期化$f$どこ$f[0] = 1$。 これは、スターを処理するまでの方法の数を表します。 
6. それぞれの星について$i$、多項式を構築します$g$どこ$g[x] = 1$もし$x \in [L_i, R_i]$。 現在の多項式を乗算します$f$による$g$、上記のすべての次数を切り捨てます$S$。 このステップでは、合計を追跡しながら、処理された星間で値を分散するためのすべての方法を蓄積します。 
7. すべての星を処理した後、すべての係数を合計します。$f[0] + f[1] + \dots + f[S]$。 この値は$F(d)$、すべての値が次の値で割り切れる有効な構成の数。$d$。 
8. メビウス反転を使用して最終的な答えを累積します。$\mu(d) \cdot F(d)$結果に反映されます。 

### なぜ効果があるのか

 メビウス反転ステップでは、すべての構成がその正確な gcd に対して 1 回だけカウントされることが保証されます。 gcd が次と等しい任意の構成$g$全部に登場する$F(d)$どこ$d\mid g$、および交互のメビウスの重みは、次の場合を除き、すべての寄与をキャンセルします。$g=1$。 多項式 DP は、畳み込みを通じてグローバルな合計を強制しながら、スターごとの独立した選択をエンコードするため、固定された可分性レベルに対するすべての制約された割り当てを正確にカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def mobius_sieve(n):
    mu = list(range(n + 1))
    is_prime = [True] * (n + 1)
    primes = []
    mu[0] = 0
    mu[1] = 1

    for i in range(2, n + 1):
        if is_prime[i]:
            primes.append(i)
            mu[i] = -1
        for p in primes:
            if i * p > n:
                break
            is_prime[i * p] = False
            if i % p == 0:
                mu[i * p] = 0
                break
            else:
                mu[i * p] = -mu[i]
    return mu

def add_poly(a, b, S):
    res = [0] * (S + 1)
    for i, ai in enumerate(a):
        if ai == 0:
            continue
        for j, bj in enumerate(b):
            if i + j <= S:
                res[i + j] = (res[i + j] + ai * bj) % MOD
    return res

def solve():
    n, m = map(int, input().split())
    lr = [tuple(map(int, input().split())) for _ in range(n)]

    mu = mobius_sieve(m)

    ans = 0

    for d in range(1, m + 1):
        if mu[d] == 0:
            continue

        S = m // d
        dp = [1] + [0] * S

        ok = True

        for l, r in lr:
            L = (l + d - 1) // d
            R = r // d
            if L > R:
                ok = False
                break

            g = [0] * (S + 1)
            for x in range(L, R + 1):
                if x <= S:
                    g[x] = 1

            dp = add_poly(dp, g, S)

        if not ok:
            continue

        ans = (ans + mu[d] * sum(dp)) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```実装は、gcd 値に対する包含/除外をサポートするメビウス計算から始まります。 メインループは各約数を処理します$d$、それに応じてすべての範囲を圧縮し、和が制約された DP 多項式を構築します。 畳み込みは、切り捨てられた 2 次マージとして直接実装されます。これは、小規模な場合には十分です。$n$そして全体の償却構造$d$。 DP 状態の最終的な合計は、制限までの合計を許可することに正確に対応します。 

最もデリケートな部分は区間の変換です。 整数の割り算制約を正確にマッピングしているため、左境界には天井を使用し、右境界には下限を使用することが不可欠です。 そこに間違いがあると、実現可能性が誤って変更され、メビウスのキャンセルが中断されます。

 ## 特殊なケース

 すべての間隔で値が 1 より大きい整数の倍数になるように強制する場合、その整数を除くすべての約数は空の変換された範囲を生成します。 DP はすぐにゼロに崩壊し、メビウス重み付けの下では何も寄与しません。これは、どの構成も gcd 1 を達成できないという事実と一致します。 

合計制限が非常に小さい場合、変数ごとに局所的に有効な多くの構成は、最終の多項式切り捨て段階でのみ削除されます。 DP は依然として部分和を正しく考慮しており、係数の最終的な累積により、すべての有効なプレフィックスが二重にカウントされることなく含まれることが保証されます。
