 ## 解決策
 ## 問題の理解

 1 から n までのラベル付きノードの同じセット上に 2 つのフォレストが与えられています。 各フォレストは単にエッジの集合であり、サイクルを形成することはありませんが、各フォレストは切り離されて複数のツリーで構成されている場合があります。 

実行できる操作は、順序のない個別の頂点のペアを選択し、そのエッジを両方のフォレストに同時に追加することです。 制約は厳しく、エッジを追加するたびに、両方のグラフがフォレストのままでなければなりません。 これは、選択したエッジが 2 つの構造のどちらにもサイクルを作成してはいけないことを意味します。 

タスクは、追加できるそのようなエッジの数を最大化し、その最大値を達成する有効なエッジのセットを 1 つ出力することです。 

n ≤ 1000 という制約により、O(n^2) の構築が快適に行えます。 効率的な接続構造を備えたノードのすべてのペアをチェックすることを伴うものはすべて実行可能です。 実行不可能なのは、各候補エッジの接続性を最初から再計算する試みです。これは、O(n^3) に向かって進むことになるためです。 

単純なアプローチの微妙な失敗例は、フォレストの 1 つだけで接続性を誤って追跡したり、エッジが両方で同時に有効である必要があることを忘れたりした場合に発生します。 たとえば、一方のフォレストではノード 1 と 2 が接続されているが、もう一方のフォレストでは接続されていない場合、単一フォレストの観点からは安全に見えても、(1,2) を追加することはすでに違法です。 1 つの DSU のみをチェックするアプローチでは、エッジが過剰にカウントされます。 

あるフォレスト内のコンポーネントを、他のフォレストの進化する構造を尊重せずに貪欲に接続すると、別の問題が発生します。 現時点では安全な移動でも、将来の多くの接続がブロックされる可能性があるため、グローバル戦略を持たないローカルの貪欲なマージは、2 つのフォレスト間でコンポーネント構造が大きく異なる構成では失敗します。 

## アプローチ

 直接的な総当りのアイデアは、すべてのペア (u、v) を繰り返し試行し、そのエッジを追加することでいずれかのフォレストにサイクルが作成されるかどうかを確認することです。 両方のフォレストの接続構造を維持し、両方の DSU の異なるコンポーネントを接続するエッジのみを受け入れることができます。 エッジを追加した後、両方の DSU を更新し、ペアのスキャンを続行します。 

受け入れられたすべてのエッジが両方のフォレストで非周期性を維持するため、これは正しく機能します。 ただし、ブルート フォース プロセスは候補者の検索方法が非効率的です。 最悪の場合、O(n) の成功したエッジごとに O(n^2) のペアをスキャンし、O(n^3) のチェックが行われる可能性があります。 DSU を最適化しても、フル再スキャンを繰り返す必要はありません。 

重要な観察は、重要なのは各フォレスト内の正確なエッジ構造ではなく、それらの接続されたコンポーネントのみであるということです。 各フォレストはノードをコンポーネントに分割し、追加されたエッジは、そのエンドポイントが両方のフォレストの異なるコンポーネントにある場合に正確に有効になります。 

そこで、各フォレストを DSU コンポーネントに圧縮します。 ここで問題が発生します。両方の DSU の異なるコンポーネントにあるノードを接続し、同時に両方のコンポーネントを徐々にマージしたいと考えています。 これを確実に行う方法は、常に 1 つの DSU をプライマリ グループとして維持し、2 番目の DSU でまだ分離されている代表者のみを接続するようにすることです。 コンポーネントを反復処理し、互換性のあるコンポーネントを貪欲にマージすることで、有効なエッジの最大数を体系的に構築できます。 

単純な建設的な戦略は、最初のフォレストの各コンポーネントの代表ノードを選択することです。 次に、これらの代表をチェーンで接続しようとします。ただし、それらが 2 番目のフォレスト内の異なるコンポーネントにある場合に限ります。 2 番目のフォレストですでに接続されている場合はスキップします。 これにより、両方のパーティションの交差部分にまたがる構造が効果的に構築されます。 

DSU 操作により、サイクルが発生しないことが保証され、貪欲なマージにより、フォレストの 1 つがさらなるマージをブロックするまで接続が最大化されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適なDSU構築 | O(n α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、各フォレストに 1 つずつ、合計 2 つの DSU を維持しています。 

1. 最初のフォレストのすべてのエッジを使用して DSU1 を初期化します。 これにより、モカの森の接続されたコンポーネントが得られます。 
2. 2 番目のフォレストのすべてのエッジを使用して DSU2 を初期化します。 これにより、ダイアナの森の接続されたコンポーネントが得られます。 
3. すべてのノードを反復処理し、DSU1 コンポーネントの代表リストを維持します。 接続の決定には内部ノードが同等であるため、コンポーネントごとに必要なノードは 1 つだけです。 
4. これらの代表の上にポインタを維持し、連続する代表を接続しようとします。 
5. 連続する代表の各ペア (u、v) について、それらが DSU2 の異なるコンポーネントに属しているかどうかを確認します。 
6. DSU2 がそれらが異なるコンポーネントにあると言う場合、エッジ (u, v) を追加し、DSU1 と DSU2 の両方でそれらを結合します。 これにより、両方のフォレストでエッジが安全であることが保証され、コンポーネントが同時にマージされます。 
7. DSU2 がすでに接続されていると言う場合、エッジを追加すると Diana の森にサイクルが形成されるため、このペアをスキップします。 
8. 残りのコンポーネント間で有効なマージができなくなるまで続行します。 

### なぜ効果があるのか

 追加された各エッジは両方の DSU の 2 つのコンポーネントを同時にマージするため、どちらのフォレストもサイクルを取得することはありません。 有効なソリューションはどれも、2 つのパーティションの交差構造全体でコンポーネントをマージすることに対応します。 このアルゴリズムは、可能な限り多くの個別の相互互換性のあるコンポーネントを貪欲に接続します。スキップされた接続は、DSU2 に違反せずにその時点で追加することは不可能です。つまり、フォレスト条件を最初に破らない限り、有効な補完に表示することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n + 1))
        self.r = [0] * (n + 1)

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1
        return True

n, m1, m2 = map(int, input().split())

dsu1 = DSU(n)
dsu2 = DSU(n)

for _ in range(m1):
    u, v = map(int, input().split())
    dsu1.union(u, v)

for _ in range(m2):
    u, v = map(int, input().split())
    dsu2.union(u, v)

rep = []
seen = set()

for i in range(1, n + 1):
    root = dsu1.find(i)
    if root not in seen:
        seen.add(root)
        rep.append(i)

ans = []

for i in range(1, len(rep)):
    u = rep[i - 1]
    v = rep[i]
    if dsu2.find(u) != dsu2.find(v):
        ans.append((u, v))
        dsu1.union(u, v)
        dsu2.union(u, v)

print(len(ans))
for u, v in ans:
    print(u, v)
```このソリューションは、接続クエリが一定時間償却操作になるように、両方のフォレストの DSU 構造を構築することから始まります。 DSU1 のコンポーネント内のエッジは冗長であることが保証されているため、代表的な抽出ステップでは、最初のフォレストの個別のコンポーネントの接続のみを試みることが保証されます。 

貪欲ループでは、連続する代表のみが考慮されます。 この順序は任意ですが、マージが成功するたびに DSU1 コンポーネントの数が減り、すべてのマージは DSU2 に対してチェックされて循環が防止されるため、十分です。 エッジが承認されるたびに両方の DSU を更新することで、将来の決定全体にわたる一貫性が確保されます。 

よくある実装ミスは、エッジを追加した後に両方の DSU でユニオンを忘れることです。 これにより、DSU2 は更新された構造を反映しなくなるため、後のチェックが不正確になります。 もう 1 つの微妙な問題は、DSU1 の変更後に古い代表を使用することです。 ここでは、初期代表のみを使用しながらも DSU ユニオンを動的に実行することで、これを回避します。

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(n α(n)) | DSU 操作は、最大でも O(n) 個の結合と検索を支配します。 
| スペース | O(n) | 2 つの DSU と出力ストレージの親配列とランク配列 |

 n ≤ 1000 という制約により、これは十分に高速になります。 O(n^2) 実装でも問題はありませんが、DSU ベースの構築では実際には線形動作が保証されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    class DSU:
        def __init__(self, n):
            self.p = list(range(n + 1))
            self.r = [0] * (n + 1)

        def find(self, x):
            while self.p[x] != x:
                self.p[x] = self.p[self.p[x]]
                x = self.p[x]
            return x

        def union(self, a, b):
            a = self.find(a)
            b = self.find(b)
            if a == b:
                return False
            if self.r[a] < self.r[b]:
                a, b = b, a
            self.p[b] = a
            if self.r[a] == self.r[b]:
                self.r[a] += 1
            return True

    n, m1, m2 = map(int, sys.stdin.readline().split())
    d1, d2 = DSU(n), DSU(n)

    for _ in range(m1):
        u, v = map(int, sys.stdin.readline().split())
        d1.union(u, v)

    for _ in range(m2):
        u, v = map(int, sys.stdin.readline().split())
        d2.union(u, v)

    rep = []
    seen = set()
    for i in range(1, n + 1):
        r = d1.find(i)
        if r not in seen:
            seen.add(r)
            rep.append(i)

    ans = []
    for i in range(1, len(rep)):
        u, v = rep[i - 1], rep[i]
        if d2.find(u) != d2.find(v):
            ans.append((u, v))
            d1.union(u, v)
            d2.union(u, v)

    out = [str(len(ans))]
    out += [f"{u} {v}" for u, v in ans]
    return "\n".join(out)

""") in ["2\n1 2\n2 3", "2\n2 3\n1 2", "2\n1 3\n1 2", "2\n1 2\n1 3"]

# custom: already fully connected
assert run("""4 3 3

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、両方のフォレストがすでに接続されている場合です。 両方のグラフで単一のツリーを形成するエッジを持つ n = 4 のような入力の場合、考えられるすべての余分なエッジが両方の構造でサイクルを作成します。 このアルゴリズムは DSU1 と DSU2 を構築し、代表を 1 つだけ検出するため、候補ペアは生成されません。 出力は正しくゼロです。 

もう 1 つのケースは、一方のフォレストが高度に断片化されているのに、もう一方のフォレストがすでに 1 本のツリーである場合です。 DSU1 にコンポーネント {1,2}、{3,4} があり、DSU2 が完全に接続されているとします。 代表的なリストは [1,3] ですが、試行された接続はすべて DSU2 接続チェックに失敗します。 このアルゴリズムはエッジを生成しません。これは、エッジを追加すると、すでに接続されているフォレスト内にサイクルが直ちに作成されるという制約と一致します。 

最後の微妙なケースは、早期にマージすることが後の選択に影響を与える場合に発生します。 受け入れられた各エッジは両方の DSU を結合するため、後のチェックでは更新された接続が反映されます。 たとえば、初期の代表値が [1,2,3,4] で、(1,2) と (2,3) を追加すると、最初は有効に見えたとしても (1,3) が無効になるように DSU 状態が進化します。 すべての決定は初期状態ではなく現在の DSU 状態に基づいて行われるため、アルゴリズムはこれを自然に処理します。
