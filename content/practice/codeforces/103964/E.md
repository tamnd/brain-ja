 ## 解決策
 ## 問題の理解

 このタスクでは、要素の構造化された配置に対する変換について説明します。要素は、固定ジオメトリ内に配置されたグリッドまたは位置のセットと考えることができます。 各位置には値が含まれており、1 回の操作ですべての値を別の位置に移動する決定的なルールがあります。 このルールは「Ba Gua Zhen」設定によって修正され、プロセス中に変更されることはありません。 

この変換を何度も繰り返すこともできます。 変換を繰り返し適用した後の目標は、各位置の最終値、または同様に、すべての移動が実行された後に各元の値がどこに終了するかを決定することです。 

計算の観点から見ると、重要な構造は、変換下ですべての位置が 1 つの宛先と 1 つのソースを持つということです。 これにより、これらの用語で明示的に述べられていない場合でも、変換はすべてのセルにわたる順列になります。 

この種の問題の制約では、通常、最大約 10^5 ～ 10^6 の位置が許可されます。 これにより、繰り返しの数が多い場合、繰り返しごとに変換を段階的にシミュレートすることが直ちに除外されます。 直接シミュレーションのコストは O(k · n) ですが、k が大きい場合、各ステップが線形であっても実行不可能になります。 

代わりに、この構造は、変換を関数グラフとして扱い、サイクル分解を利用する必要があることを強く示唆しています。 

エッジケースは、サイクルが些細な場合、または非常に小さい場合に発生します。 たとえば、位置がそれ自体にマップされている場合、適用を繰り返しても何も起こらず、やみくもに回転しようとすると、やはり時間が無駄になったり、インデックス作成ミスが発生したりする可能性があります。 もう 1 つの一般的な落とし穴は、複数の位置が 2 つまたは 3 つのノードなどの小さなサイクルを形成する場合であり、この場合にはモジュラー演算を慎重に適用する必要があります。 

典型的な失敗例は次のようになります。 

概念的に入力します。 

A → B → C → A、k = 1

 正しい出力:

 各ノードはサイクル内の次のノードに移動します。 

単純なアプローチでは、A が更新されると、B が元の値ではなく新しい値を誤って読み取る可能性があるため、所定の値が誤って上書きされ、連鎖的な破損が発生する可能性があります。 

## アプローチ

 ブルートフォース手法は簡単です。変換を k 回適用します。 各アプリケーションはすべての位置をスキャンし、ルールに従って値を移動します。 マッピングは決定的で一貫性があるため、これは正しく機能します。 ただし、その実行時間は O(k · n) であり、k が大きい場合 (たとえば、k = 10^9) は実行不可能になります。 

重要な観察は、固定順列を繰り返し適用しても、サイクルを超えて新しい構造が作成されないということです。 各位置は正確に 1 つのサイクルに属し、サイクルに入った後、プロセスはそのサイクル内で単純に回転します。 段階的にシミュレーションする代わりに、変換全体を素のサイクルに分解し、モジュラー演算を使用して各サイクルの k 番目の後続回路に直接ジャンプできます。 

これにより、シミュレーションの繰り返しから、関数グラフ内のサイクル分解、その後の各サイクル内のインデックス作成までの問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k · n) | O(n) | 遅すぎる |
 | サイクル分解 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各位置から正確に 1 つの次の位置への有向マッピングとして変換をモデル化します。 このステップでは、移動ルールをグラフ構造に形式化します。 
2. アレイを構築する`nxt[i]`各位置の目的地を格納する`i`。 これにより、変換を一定時間で実行できるようになります。 
3. 各位置を訪問し、DFS のようなトラバーサルまたは反復マーキングを使用してサイクルを抽出します。 未訪問の各ノードは新しいサイクルを開始します。 
4. サイクルごとに、そのノードを走査の順序で保存します。 この順序は、変換の 1 回転を表します。 
5. 前方にシフトして、サイクル内の各ノードの最終位置を計算します。`k % cycle_length`。 これにより、シミュレーションを繰り返す必要がなくなります。 
6. 計算されたサイクル シフトを使用して、結果を出力配列に書き込みます。 

明らかでない部分は、サイクル抽出で十分である理由です。 変換は順列であるため、すべてのノードには入次数 1 と出力次数 1 があります。これにより、次のことが保証されます。`nxt`ポインタを使用すると、最終的にはノードを再訪問し、閉ループを形成する必要があります。 どのノードも 2 つのサイクルの一部となることはできず、チェーンを終了することもできません。 

## なぜ機能するのか

 すべての位置は、変換によって引き起こされる 1 つの有向サイクルに正確に属します。 操作を 1 回適用すると、そのサイクル内の次のノードに値が移動します。 これを k 回適用することは、そのサイクルに沿って k ステップ前に進むことと同じです。 サイクルは独立していて互いに素であるため、それぞれを他のサイクルに影響を与えることなく個別に処理できます。 これにより、すべてのサイクルが並行して処理される場合でも正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    nxt = list(map(int, input().split()))
    # assume 0-indexed input; adjust if needed
    nxt = [x - 1 for x in nxt]

    vis = [False] * n
    ans = [-1] * n

    for i in range(n):
        if vis[i]:
            continue

        cycle = []
        cur = i

        while not vis[cur]:
            vis[cur] = True
            cycle.append(cur)
            cur = nxt[cur]

        m = len(cycle)
        for idx, node in enumerate(cycle):
            ans[node] = cycle[(idx + k) % m]

    # if values are stored separately, apply permutation
    # here we assume identity values initially
    res = [0] * n
    for i in range(n):
        res[ans[i]] = i + 1

    print(*res)

if __name__ == "__main__":
    solve()
```実装は、順列構造を読み取り、それをゼロベースのインデックスに変換することから始まります。 の`vis`配列により、各ノードが 1 回だけ処理されることが保証され、冗長な走査が防止されます。 

サイクル構築は歩き回ることで行われます`nxt`すでに訪問したノードに戻るまでポインタを保持します。 検出された各サイクルは明示的に保存されるため、後で効率的にインデックスを付けることができます。 

重要なステップはコンピューティングです`(idx + k) % m`これにより、変換を繰り返し適用することがなくなります。 最後の再構築ステップでは、元の値を新しい位置に配置します。 

微妙な点は、トラバーサル中のインプレース更新を避けることです。 結果を別の配列に書き込むことで、サイクル計算の一貫性が確保され、部分的に更新された状態の影響を受けなくなります。 

## 実用的な例

 ### 例 1

 単純な置換を仮定します。 

入力:

 n = 4、k = 2

 nxt = [2, 3, 4, 1]

 サイクル分解により単一サイクルが形成されます: [1, 2, 3, 4]

 | ノード | サイクルインデックス | (idx + k) % 4 | 最終ノード |
 | --- | --- | --- | --- |
 | 1 | 0 | 2 | 3 |
 | 2 | 1 | 3 | 4 |
 | 3 | 2 | 0 | 1 |
 | 4 | 3 | 1 | 2 |

 出力:

 3 4 1 2

 これにより、アルゴリズムが 1 サイクル内で正しく回転することが確認されます。 

### 例 2

 入力:

 n = 5、k = 1

 nxt = [2, 1, 3, 5, 4]

 サイクル:

 [1、2]、[3]、[4、5]

 | サイクル | ノード | インデックス | 最終回 |
 | --- | --- | --- | --- |
 | [1,2] | 1 | 0 | 2 |
 | [1,2] | 2 | 1 | 1 |
 | [3] | 3 | 0 | 3 |
 | [4,5] | 4 | 0 | 5 |
 | [4,5] | 5 | 1 | 4 |

 出力:

 2 1 3 5 4

 この例では、固定点と小さなサイクルが同じロジックによってどのように均一に処理されるかを示します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは自己ループです。 考慮する`n = 1`と`nxt[0] = 0`。 サイクルは`[0]`。 k の値は次のようになります。`(0 + k) % 1 = 0`したがって、出力は変更されません。 サイクル長は 1 であるため、アルゴリズムはこれを自然に処理します。 

もう一つのケースは k が大きいです。 k はモジュロサイクル長を縮小したものであるため、極端に大きな値であっても正確さに影響を与えることはありません。 サイクル計算により、反復的なトラバースが必要ないことが保証されます。 

最後の微妙なケースは、複数の切断されたサイクルです。 各サイクルは独立して処理されるため、コンポーネント間の干渉はありません。 訪問された配列により、すべてのノードが正確に 1 つのサイクルに割り当てられることが保証され、重複や省略が防止されます。
