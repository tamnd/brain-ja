 ## 解決策
 ## 問題の理解

 部分的に埋められた 9 × 9 の数独グリッドが与えられます。 各セルには、1 から 9 までの数字がすでに含まれているか、空です。 タスクは、すべての行に各数字が 1 回ずつ含まれるように、すべての列に各数字が 1 回ずつ含まれるように、また 3 × 3 のサブグリッドごとに各数字が 1 回ずつ含まれるようにグリッドを完成させることです。 

入力は制約のある固定ボードの状態と考えることができ、出力は数独ルールに違反することなくこの状態を拡張する有効な完成したボードと考えることができます。 複数の補完が存在する場合、有効な補完は 1 つだけ受け入れられます。 

問題の構造は、各空セルが最大 9 つの値を取ることができるため、最悪の場合の指数関数的な検索スペースを即座に示唆します。 ただし、グリッド サイズは 81 セルに固定されているため、実際の困難は入力サイズの増加ではなく、制約の相互作用です。 これにより、問題は「大規模な計算」から「小さな組み合わせ空間の慎重な枝刈り」に変わります。 

枝刈りをせずに空のセルごとにすべての数字を試す単純な再帰的塗りつぶしは、分岐係数が最大 9 で深さが最大 81 であるため、多くの空白を含む 1 つのパズルでも爆発的に発生します。 

典型的な隠れた障害モードは、3 つの制約すべてを一貫して適用しないことから発生します。 たとえば、実装が 1 つの次元のみを検証する場合、行では有効でも列またはボックスでは無効な数字を配置しても、部分的なチェックに合格する可能性があります。 

バックトラッキング中に更新が適切にロールバックされない場合、別の微妙な問題が発生します。 よくある間違った実装では、行または列で使用されている数字をマークしますが、バックトラック時にそのマークを解除するのを忘れ、誤った枝刈りや誤った「解決策なし」の結論につながります。 

## アプローチ

 ブルートフォースアプローチでは、数独を空のセルに対する純粋な検索問題として扱います。 グリッドをスキャンし、最初の空のセルを選択し、1 から 9 までの数字を試し、再帰的に続行します。 これは、前の選択と一致するすべての可能な割り当てを調査するため、正しいです。 

ただし、最悪の場合の複雑さは次のとおりです。$9^k$、 どこ$k$空のセルの数です。 妥当性チェックから中程度の枝刈りを行ったとしても、ブランクが多いケースでは分岐係数が大きすぎるままになります。 

Sudoku を実際に解決できるようにする主な観察は、制約チェックが非常に安価で、高度に構造化されているということです。 各配置は、1 つの行、1 つの列、および 1 つの 3 x 3 ブロックの 3 つのセットに影響します。 これにより、有効性チェックが O(1) になるように増分状態を維持できるようになり、無効なブランチを即座に積極的に削除できます。 

次のセルをよりインテリジェントに選択することで、さらなる改善が得られます。 固定された順序でセルを埋めるのではなく、有効な候補が最も少ない空のセルを常に選択します。 これにより、制約されたセルによって検索ツリーが早期に崩壊するため、一般的なパズルにおける分岐が大幅に減少します。 

行、列、ボックスの 3 つのブール制約テーブルを維持し、再帰中にそれらを更新できます。 これにより、ソリューションは、移動ごとに一定時間の有効性チェックを行うガイド付きバックトラッキング検索に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(9^k) | お(81) | 遅すぎる |
 | 制約付きの最適化されたバックトラッキング | O(小さい指数関数、大幅に枝刈り) | お(81) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 9 × 9 グリッドを解析し、空の位置をすべて記録します。 その際、各行、各列、および各 3 x 3 サブグリッドでどの桁がすでに使用されているかを示す 3 つの制約トラッカーを構築します。 これにより、「ここに数字 d を配置できますか?」と定数時間で答えることができます。 
2. 座標の整数除算を使用してセルの 3 x 3 ボックス インデックスを計算する関数を定義します。 Sudoku の制約は固定ブロックに分割されているため、これが必要になります。 
3. グリッドを埋める再帰的ソルバーを実装します。 呼び出しごとに、次の空のセルを選択します。 任意に選択するのではなく、現在の制約に従って有効な桁数が最も少ないものを選択します。 これにより、早期の分岐が減少し、最大の大幅な節約がもたらされます。 
4. 選択したセルについて、1 ～ 9 の数字を繰り返します。各数字について、その行、列、およびボックスにその数字が存在しないかどうかを確認します。 有効な場合は、それを配置し、3 つの制約構造すべてで使用されるようにマークします。 
5. 残りのグリッドを再帰的に解決します。 再帰が成功した場合は、成功をすぐに上方に伝播します。 
6. 解決策につながる数字がない場合は、配置を元に戻して元に戻します。 これにより、すべての制約構造が復元され、以前の決定の一貫性が保たれます。 
7. すべてのセルが埋まっている場合は成功を返し、ボードが完成します。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは、すべての塗りつぶされたセルが数独の制約を満たすという不変条件を維持します。 制約テーブルにより、無効な数字が決して配置されないことが保証され、バックトラッキングにより部分的な割り当てが元に戻せることが保証されます。 すべての再帰的状態は、これまでの制約と一致する構成のみを探索するため、検索空間には無効な分岐は含まれず、潜在的に完全なソリューションのみが含まれます。 グリッドは有限であり、各ステップで空のセルの数が厳密に削減されるため、再帰は最終的に有効な完全な割り当てを見つけるか、すべての可能性を使い果たすことによって終了する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_sudoku(board):
    rows = [[False]*10 for _ in range(9)]
    cols = [[False]*10 for _ in range(9)]
    boxes = [[False]*10 for _ in range(9)]
    empties = []

    def box_id(r, c):
        return (r // 3) * 3 + (c // 3)

    for r in range(9):
        for c in range(9):
            if board[r][c] == 0:
                empties.append((r, c))
            else:
                d = board[r][c]
                rows[r][d] = True
                cols[c][d] = True
                boxes[box_id(r, c)][d] = True

    def get_candidates(r, c):
        b = box_id(r, c)
        return [d for d in range(1, 10)
                if not rows[r][d] and not cols[c][d] and not boxes[b][d]]

    def dfs():
        if not empties:
            return True

        best_idx = -1
        best_cands = None

        for i, (r, c) in enumerate(empties):
            cands = get_candidates(r, c)
            if not cands:
                return False
            if best_cands is None or len(cands) < len(best_cands):
                best_cands = cands
                best_idx = i

        r, c = empties.pop(best_idx)
        b = box_id(r, c)

        for d in best_cands:
            if not rows[r][d] and not cols[c][d] and not boxes[b][d]:
                board[r][c] = d
                rows[r][d] = cols[c][d] = boxes[b][d] = True

                if dfs():
                    return True

                rows[r][d] = cols[c][d] = boxes[b][d] = False
                board[r][c] = 0

        empties.append((r, c))
        return False

    dfs()
    return board

def main():
    board = []
    for _ in range(9):
        line = input().strip()
        row = []
        for ch in line:
            if ch in "0.":
                row.append(0)
            else:
                row.append(int(ch))
        board.append(row)

    solve_sudoku(board)

    for r in range(9):
        print("".join(str(x) for x in board[r]))

if __name__ == "__main__":
    main()
```ソルバーは、行、列、およびボックスの一定時間制約テーブルを構築します。 DFS ルーチンは常に、最も制限された空のセルを最初に選択します。これは、異常な分岐を防ぐ重要なヒューリスティックです。 元に戻すロジックは配置ロジックと対称的であり、バックトラック中の正確性が保証されます。 実装の微妙な点は、選択したセルが空のリストから一時的に削除され、分岐が失敗した場合にのみ復元されるため、同じ決定状態を再度訪問することが回避されることです。

 ## 特殊なケース

 ### 完全に空のグリッド

 入力はすべてゼロのグリッドです。 このアルゴリズムは最大分岐から始まりますが、最初の数個の配置が発生するとすぐに制約伝播の恩恵を受けます。 ヒューリスティックな選択により、均一な分岐の爆発が防止されます。 

### すでに解決されたグリッド

 空のリストは最初から空です。 基本条件が満たされるため、DFS はただちに終了し、元のグリッドが変更されずに返されます。 

### 単一の強制セル

 欠損値が 1 つあるほぼ完全なグリッドは、制約テーブルが唯一の有効な桁を正しく識別するかどうかをテストします。 アルゴリズムはそのセルの候補を計算し、バックトラックせずに直接そのセルを埋めます。 

### 高度に制約された中央セル

 最も制約されたセルがグリッドの中央にある場合、ヒューリスティックは最初にそのセルを正しく選択します。 これにより、無関係な周辺選択肢の探索が回避され、再帰が浅くなります。
