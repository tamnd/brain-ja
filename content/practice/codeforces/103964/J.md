 ## 解決策
 ## 問題の理解

 このタスクは幾何学的用語で理解できます。 グリッド上に描かれたキャンプ場を想像してください。一部のセルはテントや構造物で占められており、残りは空き地です。 人は占有領域の外側の境界に沿って歩き、常に占有領域と空き領域の間の端に正確に留まります。 目標は、グリッドのエッジに沿った単位ステップで測定した、この歩行の長さを計算することです。 

入力は長方形のグリッドを表します。 各セルは、その位置がキャンプ場に属しているか、何もない地形であるかを示します。 出力は、占有されているすべてのセルを囲む外側境界の全長を表す単一の整数です。 

複雑さの観点から、グリッド サイズは通常、テスト ケース全体で合計約 10^5 セル、または各次元で最大数千セルに達します。 これにより、境界の周りを一歩ずつ歩くことをシミュレートしたり、セルごとに繰り返し塗りつぶしを実行したりするソリューションは即座に排除されます。 セル数 O(nm)、または同等の O(総セル数) が線形である解決策が、唯一実行可能な方向です。 

占有されている 1 つのセルから開始し、方向ルールを使用してその周囲を歩き回ることで境界を明示的にトレースしようとすると、単純な間違いが発生します。 キャンプ場に複数の接続されていないコンポーネントがある状況を考えてみましょう。 

入力:```
1 0 1
0 0 0
1 0 1
```最初に占有されているセルから開始して「エッジをたどる」ことを試みる単純なウォーカーは、領域ごとに慎重に再起動しない限り、他のコンポーネントを完全に見逃してしまいます。 形状に穴がある場合、別の微妙な失敗が発生します。 

入力:```
1 1 1
1 0 1
1 1 1
```正しい出力では、外側の境界と内側のキャビティ境界の両方がカウントされます。 外側の輪郭のみをたどる単純な周囲トレースでは、内部の穴の寄与が無視されるため、答えが過小評価されてしまいます。 

これらのケースは、局所的な境界の通過が脆弱であることを示しています。 正しいアプローチはグローバルであり、露出したすべてのエッジを体系的に考慮する必要があります。 

## アプローチ

 この強引なアイデアは、占有されている各セルを独立した正方形として扱い、その境界がどの程度最終的な境界に寄与するかを判断することです。 各セルについて、その 4 つの隣接セルを検査します。 隣接する側がグリッドの外にある場合、または空の場合、その側は境界に 1 ユニットを貢献します。 これをすべての占有セルで合計すると、境界長の合計が得られます。 

すべてのセルのすべての露出したエッジが 1 回だけカウントされるため、このアプローチは正しいです。 ただし、実装が非効率的であると、パフォーマンスを過大評価しやすくなります。 サイズ n × m の完全なグリッドの最悪のケースでは、セルごとに 4 つのチェックが実行され、4nm の動作が行われます。 これはまだ線形ですが、共有エッジを繰り返し再歩行すると、歩行をシミュレートしたり、明示的な境界パスを構築しようとする試みは、異常なレイアウトで O((nm)^2) に低下する可能性があります。 

重要な洞察は、境界はパスの問題ではなく、ローカルの隣接関係の問題であるということです。 各セルは、そのすぐ隣のセルのみに基づいて独立して寄与します。 これにより、トラバースの必要性が完全になくなり、問題は単純なカウントに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース境界トレース | O((nm)^2) 最悪の場合 | O(nm) | 遅すぎる |
 | セルごとの隣接カウント | O(nm) | O(1) または O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取り、占有されているすべてのセルを特定します。 占有されている各セルは、潜在的な境界エッジに寄与する単位正方形として扱われます。 

2. 占有されているすべてのセルについて、隣接する 4 つの方向 (上、下、左、右) を調べます。 各方向は、考えられる境界の寄与を表します。 

3. 特定の方向について、隣接するセルがグリッドの外側にあるか空であるかを確認します。 その場合は、周長カウントを 1 つ増やします。 これは、隣接するものが欠けているとエッジが露出していることを意味するため、機能します。 

4. 次のセルに移動する前に、現在のセルの 4 つの方向すべてからの寄与を蓄積します。 これにより、各セルがすべての露出したエッジを独立して提供できるようになります。 

5. グリッド全体の寄与を合計し、最終的な合計を出力します。 

境界を構築する代わりに隣接セルをチェックする理由は、すべての境界セグメントが 1 つの占有セルと 1 つの非占有隣接セルで構成されるペアに一意に対応するためです。 これにより、セル間で共有されるエッジの二重トラバースが回避されます。 

### なぜ効果があるのか

 最終的な境界の各エッジは、正確に 1 つの占有セルと、正確に 1 つの隣接する空の位置または境界外の位置によって一意に決定されます。 エッジは常にその隣接の占有側に起因するため、エッジを 2 回カウントすることはできません。 逆に、露出した面は占有スペースから空きスペースへの移行を表すため、すべての露出面をカウントする必要があります。 この 1 対 1 マッピングにより正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]
    
    dirs = [(1,0), (-1,0), (0,1), (0,-1)]
    perimeter = 0

    for i in range(n):
        for j in range(m):
            if grid[i][j] != '1':
                continue
            for di, dj in dirs:
                ni, nj = i + di, j + dj
                if ni < 0 or ni >= n or nj < 0 or nj >= m or grid[ni][nj] == '0':
                    perimeter += 1

    print(perimeter)

if __name__ == "__main__":
    solve()
```実装は隣接性の原則に従います。 グリッドは 1 回スキャンされ、占有されているセルごとに 4 つの隣接セルが検査されます。 境界チェックにより、グリッドのエッジが露出した周囲として正しく処理されることが保証されます。 よくある間違いは、境界外の隣接エッジを寄与エッジとして扱うことを忘れることで、これにより外側の境界に沿ったカウントが過少にカウントされてしまいます。 

もう 1 つの微妙な問題は入力処理です。グリッドを整数として扱うか、文字列として扱うかは一貫している必要があります。 ここでは文字を比較するので、条件は明示的にチェックされます。`'1'`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 |---|---|---|
 | 時間 | O(nm) | 各セルは 1 回訪問され、4 つの定数時間近隣チェックがあります。 
| スペース | お(1) | 入力グリッドを超えて使用されるのは固定方向の配列のみです。 

最大 10^6 セルのグリッドであっても、演算は非常に小さな定数係数で線形のままであるため、アルゴリズムは制限内で快適に実行されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    import sys

    input = sys.stdin.readline

    def solve():
        n, m = map(int, input().split())
        grid = [list(input().strip()) for _ in range(n)]
        dirs = [(1,0), (-1,0), (0,1), (0,-1)]

                    if ni < 0 or ni >= n or nj < 0 or nj >= m or grid[ni][nj] == '0':
                        ans += 1
        print(ans)

    solve()
    return ""

 ## 特殊なケース

 単一の占有セルの場合、4 方向すべてがグリッドの外側にあるため、アルゴリズムは 4 つの露出したエッジを正確にカウントします。 

入力：```
1 1
1
```ループは唯一のセルを訪問し、4 つの隣接セルをチェックし、すべての失敗境界をチェックして、境界を 4 に増分します。 

完全に空のグリッドの場合、どのセルも寄与をトリガーしないため、出力はゼロのままになります。 

入力：```
2 2
00
00
```状態からして`grid[i][j] != '1'`どこでも失敗し、近隣チェックは行われず、アルゴリズムはゼロで終了します。 

完全に満たされたブロックの場合、占有されている 2 つのセル間の各隣接は境界としてカウントされないため、内部共有エッジはキャンセルされます。 外側のエッジのみが寄与し、長方形ブロックの予想外周長は 2(n + m) になります。
