 ## 解決策
 ## 問題の理解

 囲碁に似た長方形の盤が与えられます。 各セルは空であるか、2 色のいずれかに属する石が含まれています。 直角に接触する石は、接続されたグループを形成します。 グループに少なくとも 1 つの隣接する空のセルがあり、自由として機能する場合、そのグループは安定していると見なされます。 グループにまったく自由がない場合、グループ全体が理事会から削除されます。 

タスクは、このルールをシミュレートし、すべての不安定なグループが除去された後の最終状態を決定すること、または同様に、このルールの下で捕捉される石の数を計算することです。 あるグループを削除すると、別のグループに新しい自由が生まれる可能性があるため、グループ間の相互作用が重要ですが、この問題構造では、初期構成を 1 回評価し、自由がゼロのグループをすべて削除するだけで済みます。 

入力はボードの寸法を記述し、その後にグリッド自体が続きます。 各文字は空のセルまたは石の色のいずれかをエンコードします。 通常、出力は除去された石の数またはバリエーションに応じた最終的な安定化構成ですが、コアの計算では 4 方向の隣接関係にある接続コンポーネントを特定し、各コンポーネントが空のセルに接触しているかどうかを確認します。 

この制約は、最大 n 倍の m ノードを持つグラフを意味します。 一般的な制限は約 2×10^5 セルで、O(nm) の走査が必要です。 グループごとにスキャンを繰り返したり、セルごとに接続を最初から再計算したりするソリューションは、O(n^2 m^2) の動作に劣化し、すぐに失敗します。 

グループがボードの境界に触れると、微妙な問題が発生します。 問題が外側を空として明示的に扱わない限り、エッジにあるグループには自動的には自由がありません。 ほとんどの Go に似た定式化では、内側の空のセルのみがカウントされるため、石や境界線に囲まれたグループは、たとえエッジに触れたとしても無効になります。 もう 1 つのエッジ ケースは、敵の石に完全に囲まれた単一の石で、自由度がゼロのサイズ 1 のコンポーネントを形成しているため、除去する必要があります。 

## アプローチ

 問題を解決する直接的な方法は、各石を開始点として扱い、フラッド フィルを実行してその接続されたグループを検出し、次に隣接する石をスキャンして隣接する空のセルが存在するかどうかを確認することです。 そうでない場合は、そのグループ内のすべてのセルを削除済みとしてマークします。 訪問したノードをキャッシュせずにすべての石に対してこれを繰り返すと、同じコンポーネントの走査が繰り返されることになります。 ボードが石でいっぱいの最悪の場合、各セルはほぼグリッド全体のトラバースをトリガーし、結果として O((nm)^2) の操作が発生します。 

重要な観察は、各セルが正確に 1 つの接続コンポーネントに属しており、自由条件はそのコンポーネント内のいずれかのセルが空のセルに接触しているかどうかのみに依存するということです。 これにより、グリッド グラフ上で標準の BFS または DFS を使用して、すべてのコンポーネントを一度に計算できます。 コンポーネントを探索しているときに、少なくとも 1 つの隣接する空のセルがあるかどうかを同時に記録します。 トラバースが終了したら、コンポーネント全体を削除するか保持するかを決定します。 

これにより、セルごとの繰り返しの探索の問題が、グリッド上の単一の線形スキャンに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | セルごとのブルート フォース フラッド | O((nm)^2) | O(nm) | 遅すぎる |
 | コンポーネントごとに単一の BFS/DFS | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 各セルがノードであり、直交して隣接する同じ色の石の間にエッジが存在するグラフとしてグリッドをモデル化します。

1. グリッド内のすべてのセルを反復処理します。 まだ訪問されていない石に遭遇すると、そこから BFS または DFS を開始して、その接続されたコンポーネント全体を検出します。 これにより、各コンポーネントが正確に 1 回処理されることが保証されます。 
2. コンポーネントのトラバース中に、コンポーネントが少なくとも 1 つの自由を持っているかどうかを示すフラグを維持します。 訪問した石室ごとに、その隣の 4 つの石室を検査します。 隣接するセルが空のセルである場合、自由フラグを true に設定します。 これが機能するのは、自由が隣接関係でローカルに定義されているためです。 
3. また、現在のコンポーネントに属するすべてのセルを一時リストに収集します。 これは、コンポーネント全体の探索が完了するまで、石を削除するかどうかをすぐに決定できないため、必要です。 
4. コンポーネントのトラバースが終了したら、自由フラグをチェックします。 false のままの場合、出力要件に応じて、収集されたすべてのセルを削除済みとしてマークするか、キャプチャ済みとしてカウントします。 
5. グリッド内のすべてのセルが 1 回だけ訪問されるまで、このプロセスを続けます。 

完全な走査が完了するまで決定を遅らせる理由は、探索の後半で自由が発見される可能性があり、部分的な探索ではコンポーネントの運命を安全に決定できないためです。 

### なぜ効果があるのか

 正確性は、BFS または DFS が 4 方向の隣接関係の下で接続されたコンポーネントを 1 つだけ探索するという不変条件に基づいています。 自由度はグローバル構造ではなく、空のセルへの隣接性にのみ依存するため、自由度プロパティはコンポーネント全体で一定です。 コンポーネント内のいずれかのセルに隣接する空のセルがある場合、コンポーネント全体は有効です。 そうしないと、すべての細胞が死んでしまいます。 したがって、プロパティをコンポーネントごとに 1 回評価するだけで十分であり、一貫性があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]
    
    visited = [[False] * m for _ in range(n)]
    
    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]
    
    def inside(x, y):
        return 0 <= x < n and 0 <= y < m
    
    def bfs(i, j):
        stack = [(i, j)]
        visited[i][j] = True
        comp = [(i, j)]
        has_liberty = False
        
        color = grid[i][j]
        
        while stack:
            x, y = stack.pop()
            
            for dx, dy in dirs:
                nx, ny = x + dx, y + dy
                
                if not inside(nx, ny):
                    continue
                
                if grid[nx][ny] == '.':
                    has_liberty = True
                elif grid[nx][ny] == color and not visited[nx][ny]:
                    visited[nx][ny] = True
                    stack.append((nx, ny))
                    comp.append((nx, ny))
        
        if not has_liberty:
            for x, y in comp:
                grid[x][y] = '.'
            return len(comp)
        return 0
    
    captured = 0
    
    for i in range(n):
        for j in range(m):
            if grid[i][j] != '.' and not visited[i][j]:
                captured += bfs(i, j)
    
    print(captured)

if __name__ == "__main__":
    solve()
```このソリューションでは、明示的なスタックベースの DFS を使用して再帰制限を回避します。 各コンポーネントは一度検出され、メンバーシップと自由のステータスの両方を同時に追跡します。 グリッドは、コンポーネントのデッドが確認された後にのみその場で変更されるため、トラバースの干渉が防止されます。 

よくある落とし穴は、訪問したセルをスタックにプッシュするときにすぐにマークするのを忘れることで、指数関数的な再訪問につながる可能性があります。 もう 1 つの微妙な問題は、範囲外を自由として扱うことです。 ここでは、グリッド内の空のセルのみがカウントされるため、境界外を明示的に無視します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、境界線には接しているが内部に空のセルがないコンポーネントです。 たとえば、ボードの端に沿った石の列は、境界内に隣接する空のセルがない限り、生きているとは見なされません。 BFS は、インバウンド '.' のみを明示的にチェックします。 したがって、国境接触だけでは自由は生まれません。 

もう 1 つのエッジ ケースは、すべての石が分離されたチェッカーボード パターンです。 各石はサイズ 1 のコンポーネントを形成します。 アルゴリズムはそれぞれを独立して正しく処理し、囲まれている場合はすべてを捕捉済みとしてマークします。 

最後の微妙なケースは、単一の自由セルを持つ大きくて高密度のコンポーネントです。 トラバーサル中、最初の空の近傍が見つかるとすぐに自由フラグが true になり、コンポーネントの残りの部分では true のままとなり、すべての自由を明示的にカウントする必要がなくても正しい存続が保証されます。
