 ## 問題の理解

 廊下でつながった部屋のグラフが与えられました。 この構造は特別です。どの部屋も他のすべての部屋からアクセス可能で、部屋のペアの間には最大でも 1 つの廊下があり、同じ経路を前後に移動することによって強制されるサイクルを除いてサイクルはありません。 これは、グラフが次のツリーであることを意味します。$n+1$頂点と$n$エッジ。 

人は部屋から始まる$b_1$、その後、指定されたルームのリストにアクセスする必要があります$b_2, \dots, b_m$任意の順序で、最後に戻ります$b_1$。 廊下に沿って移動するには 1 単位の時間がかかります。 課題は、総移動時間を最小限に抑えることです。 

重要な点は、必要な部屋を訪れる順序は固定されていないということです。 私たちは、木の中を歩く合計距離を最小限に抑えるために、最適な訪問順序を自由に選択できます。 

制約は次のとおりです$n \le 10^5$したがって、訪問命令のすべての順列をシミュレートしようとするアプローチは不可能です。 すべてのペアのペアごとの最短経路を計算し、順列を試みても、時間がかかりすぎます。$m$大きくすることもできます。 ツリー上の直線または直線に近い時間が必要です。 

単純な考えは、これをツリー上の TSP として扱い、すべての訪問順序を試してみることです。$m$ノード。 それはすでに失敗しています$m!$、ただし、サブセットに対する動的プログラミングでも、$O(m^2 2^m)$、完全に不可能です。 

2 番目の単純なアイデアは、必要なすべてのノード間の最短経路を計算し、誘導計量空間で最短のハミルトニアン サイクルを解くというものです。 それは依然として組み合わせ爆発につながります。 

より微妙な失敗のケースは、あるトラバーサルで DFS 順序またはソートされた順序でノードにアクセスすることが常に機能すると仮定することから生じます。 ツリーでは、空間的な順序は線形ではありません。 間違った注文を選択すると、不必要に後戻りする可能性があります。 

## アプローチ

 グラフがツリーであることを認識すると、問題の構造を管理できるようになります。 ツリー上では、距離は一意の最短パスであり、ノード間の移動はこれらのパスに沿ったエッジの横断に対応します。 

ブルートフォースメンタルモデルは、必要なノードのすべての順列を試行し、毎回 LCA クエリまたは BFS を使用してパス長を計算します。 これは正しいです。最適なルートは、連続する訪問ノード間の一連の最短パスに開始点への戻りを加えたものであるためです。 問題は、$m!$可能な注文。 

重要な洞察は、ツリー上では、選択したノード間のパスの結合により、より小さなサブツリーが形成されるということです。 1 つのノードで開始し、他のすべてのノードを訪問し、最初に戻るトラバーサルは、リトレースを最小限に抑える選択されたトラバーサル戦略に沿った場合を除き、この誘導されたサブツリーの各エッジを少なくとも 2 回トラバースする必要があります。 これは、ターミナル ノードの「シュタイナー ツリー」の考え方と密接に関連しています。 

より正確には、必要なすべてのノードを接続する最小限のサブツリーを取る場合、すべての最適なツアーは、このサブツリーのすべてのエッジをカバーするウォークに対応します。 最小の合計歩行距離は次のようになります。$$2 \cdot (\text{number of edges in the induced subtree}) - \text{saving from choosing start point optimally}$$ただし、次で開始して終了する必要があるため、$b_1$より直接的に考えることができます。セット内のすべてのノードを含む最小のサブツリーのサイズを計算するだけで済みます。$\{b_1, b_2, \dots, b_m\}$、そのサブツリー内のエッジの数を 2 倍にします。 

したがって、問題は、マークされたノードによって引き起こされる仮想ツリーを構築し、そのエッジをカウントすることに帰着します。 

これを効率的に構築するために、LCA 前処理を使用します。 DFS 順序でノードをソートし、連続するノードの LCA を挿入し、必要な分岐点のみを含む圧縮ツリーを構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 |$O(m! \cdot n)$|$O(n)$| 遅すぎる |
 | ペアごとの最短パス DP |$O(m^2)$それより悪い |$O(m^2)$| 遅すぎる |
 | 仮想ツリー + LCA |$O((n + m)\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、ツリーをノード 1 (または任意の固定ノード) にルートし、LCA クエリの深さと祖先を前処理します。 

次に、次のように進めます。 

1. 任意のルートから DFS を実行して、各ノードのエントリ時間と深さを計算します。 これにより、サブツリー構造が適切に動作するノードの線形順序付けが得られます。 この順序付けにより、後でターミナル ノードを並べ替えることができるようになり、その LCA 構造をローカルで再構築できるようになります。 
2. LCA クエリ用のバイナリ リフティング テーブルを構築します。 これにより、任意の 2 つのノードの最小共通祖先を対数時間で計算できます。 仮想ツリーを構築するときに LCA を繰り返し挿入する必要があるため、これが必要になります。 
3. 開始ノードを含む必要なノードのセットを取得します。$b_1$。 入力リストに重複がある場合、ノードを複数回訪問しても最小サブツリーは変更されないため、重複は無視されます。 
4. これらのノードを DFS エントリ時間で並べ替えます。 この順序付けにより、リスト内の連続するノードがツリーの DFS ツアーに沿った走査順序に対応することが保証されます。 
5. このソートされたリスト内の隣接するペアごとに、LCA を計算し、それをノードのセットに追加します。 このステップが必要なのは、端末を接続する最小サブツリーが元のセットにないノードで分岐する可能性があるためです。 LCA を挿入しないと、内部接続点を見逃してしまいます。 
6. 拡張セットを DFS 順序で再度並べ替えます。 これにより、必要なすべての分岐点が一貫した走査順序に確実に含まれるようになります。 
7. スタックベースの仮想ツリーを構築します。 ソートされた順序でノードを反復処理し、仮想ツリー内の現在のパスを表すスタックを維持します。 新しいノードごとに、LCA 深さ関係に基づいて正しい親が見つかるまでポップを繰り返し、それを接続します。 各接続は、仮想ツリー内の 1 つのエッジに対応します。 
8. 仮想ツリーが構築されたら、そのエッジを数えます。 答えは、この仮想ツリーのエッジの数のちょうど 2 倍です。同じノードで開始し終了すると仮定すると、各エッジは 1 度奥に進み、1 度戻る必要があるためです。 

### なぜ効果があるのか

 このアルゴリズムは、必要なすべてのノードを含む最小限のサブツリーを再構築します。これは、ノード間のすべての単純なパスを正確に結合したものです。 必要なすべてのノードを訪問するウォークは、同じルートで開始および終了する場合、このサブツリー内のすべてのエッジを各方向に少なくとも 1 回横断する必要があります。 仮想ツリーにより不必要なノードが含まれないことが保証されるため、エッジ数は最小限に抑えられます。 したがって、この数を 2 倍にすると、最適な移動時間が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n + 2)]

for _ in range(n):
    a, b = map(int, input().split())
    g[a].append(b)
    g[b].append(a)

LOG = 18

up = [[0] * (n + 2) for _ in range(LOG)]
depth = [0] * (n + 2)
tin = [0] * (n + 2)
timer = 0

def dfs(v, p):
    global timer
    timer += 1
    tin[v] = timer
    up[0][v] = p
    for i in range(1, LOG):
        up[i][v] = up[i - 1][up[i - 1][v]]
    for to in g[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        dfs(to, v)

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for i in range(LOG):
        if diff >> i & 1:
            a = up[i][a]
    if a == b:
        return a
    for i in reversed(range(LOG)):
        if up[i][a] != up[i][b]:
            a = up[i][a]
            b = up[i][b]
    return up[0][a]

dfs(1, 1)

m = int(input())
b = list(map(int, input().split()))
b = list(set(b))
b.append(1)

b.sort(key=lambda x: tin[x])

nodes = b[:]
for i in range(len(b) - 1):
    nodes.append(lca(b[i], b[i + 1]))

nodes = list(set(nodes))
nodes.sort(key=lambda x: tin[x])

stack = []
adj = {v: [] for v in nodes}

def add_edge(u, v):
    adj[u].append(v)
    adj[v].append(u)

for v in nodes:
    while stack and not (tin[stack[-1]] <= tin[v] < tin[stack[-1]] + (1 << 30)):
        stack.pop()
    if stack:
        add_edge(stack[-1], v)
    stack.append(v)

edges = 0
visited_edges = set()

def dfs2(v, p):
    global edges
    for to in adj[v]:
        if to == p:
            continue
        edges += 1
        dfs2(to, v)

root = 1
dfs2(root, -1)

print(2 * edges)
```このソリューションでは、まずバイナリ リフティングを使用して標準の LCA 構造を構築します。 DFS 番号付けは、関与するノードの数に応じて仮想ツリーの構築が線形になるようにノードをソートできる DFS 順序を課すために使用されます。 

必要なルームを読み取った後、重複が削除され、開始ノードが明示的に追加されます。 これにより、ツアーが正しい開始点に固定されることが保証されます。 

LCA 挿入ステップは、最小接続サブツリーのすべての分岐点が含まれることが保証されるため、不可欠です。 

仮想ツリー上の最終的な DFS ではエッジがカウントされ、各エッジは閉じたウォークで両方向にトラバースする必要があるため、答えは 2 倍になります。 

微妙な点の 1 つは、仮想ツリーの構築が DFS の順序と LCA の一貫性に依存していることです。 スタック ロジックにより、圧縮ツリー内の有効な祖先と子孫の関係に沿ってのみノードが接続されることが保証されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、必要なすべてのノードが単一のルートからリーフへのパス上にある場合です。 その状況では、仮想ツリーは単純なチェーンに縮退します。 このアルゴリズムでは、連続するノード間に LCA が挿入されますが、すべての LCA は既存のノードに集約されるため、追加の分岐は導入されません。 エッジ数はチェーンの長さから 1 を引いたものになり、2 倍にしても正しい往復コストが生成されます。 

もう 1 つのケースは、開始ノードが$b_1$最も深い分岐領域の一部ではありません。 これを明示的に追加すると、仮想ツリーに正しいルート アンカーが確実に含まれるようになります。 これを行わないと、計算されたサブツリーが実際の開始点から切り離され、不正確な走査コストが発生する可能性があります。
