 ## 解決策
 ## 問題の理解

 私たちには固定された基底セットが与えられています$p_i$および関連する重み$c_i$。 各クエリは短い数字の文字列を返します。$s$、そしてそれをいくつかの連続した部分に分割することができます。 各部分は、先行ゼロのない有効な 10 進数である必要があります。 

セグメントごとに$t$、与えられた基底の 1 つの完全累乗として解釈しようとします。インデックスが存在する必要があります。$i$と指数$x \ge 1$そのような$t = p_i^x$。 これが可能であれば、セグメントは価値に貢献します$c_i \cdot x$、そうでない場合は寄与はゼロです。 パーティションの品質は、そのすべてのセグメントの中での最小の寄与です。 タスクは、すべての可能なパーティションにわたってこの最小値を最大化し、また、この最適値を達成するパーティションの数をカウントすることです。 

主な問題点は、文字列の長さが最大 ​​18 であるため、すべてのクエリは小さいですが、ベースとクエリの数が多いことです。 これにより、このソリューションは、基本セットおよび文字列ごとの動的プログラミングでの大量の前処理が必要になります。 

単純なアプローチでは、すでに指数関数的な長さになっている文字列を分割するためにあらゆる方法を試みることになります。 各セグメントについて、それがいくつかの累乗であるかどうかもチェックしようとします。$p_i$、コストがさらに追加されます。 18 は小さいとはいえ、構造を持たずにクエリごとに独立して実行すると、指数パーティションと高価なチェックの組み合わせは非常に遅くなります。 

また、累乗として複数の表現を持つ数値を含む微妙な特殊なケースもあります。 たとえば、次のような値$64$そうかもしれない$2^6$または$4^3$または$8^2$。 すべての有効な表現を事前計算しないと、異なる基数と指数のペアの選択に依存する最適なセグメンテーションが失われる可能性があります。 

もう 1 つの注意が必要な状況は、先頭のゼロに起因します。 「01」のようなセグメントは、たとえ数値的には 1 に等しいとしても、有効なものとして扱われてはなりません。部分文字列を整数に変換するのが早すぎて数値的に比較するアプローチは、そのようなケースを誤って受け入れてしまいます。 

最後に、セグメント全体の最小値を最大化するため、貪欲な選択は失敗します。 局所的に強い分割を行うと、後で弱いセグメントが強制され、グローバル スコアが低下する可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、最大 18 個の長さの文字列を分割する可能なすべての方法を列挙します。分割の数は次のとおりです。$2^{17}$、約130k。 パーティションごとにすべてのセグメントをチェックし、セグメントごとにそれが等しいかどうかをテストします。$p_i^x$誰にとっても$i$そして$x$。 事前計算を使用した場合でも、セグメントごとに多くの塩基にわたる部分文字列のべき乗チェックを行うと、すべてのパーティションとクエリにわたって大きな定数係数が乗算されるため、コストが高くなります。 

重要な構造上の観察は、文字列の長さが小さいため、すべての部分文字列を候補セグメントとして扱い、クエリごとに 1 回その「値」を事前計算できることです。 各部分文字列について、達成可能な最良のものを知る必要があります$c_i \cdot x$と等しくなるように$p_i^x$。 以来$s$が短い場合は、すべての部分文字列を列挙し、事前に計算された検出力値と照合できます。 

すべての部分文字列に重みが付けられると、問題は古典的なパーティション DP になります。最小セグメントの重みを最大化するセグメントにプレフィックスを分割し、その最良の最小値を達成する方法が何通りあるのかを数えたいと考えます。 これは本質的に、最適なボトルネックを維持するカウント パスと組み合わせた、間隔にわたる最大 DP です。 

移行は簡単です。プレフィックスを dp し、以前のすべてのカット位置を試し、最小スコアを伝播します。 唯一重要な部分は、複数の遷移が同じ最適値を生成する場合にカウントを正しく処理することです。

 ## アルゴリズムのチュートリアル

 ソリューションを 2 つのフェーズに分けます。基本セットの前処理と各クエリ文字列への応答です。 

1. ペアごとに$(p_i, c_i)$、すべての力を生成します$p_i^x$18 桁以内に収まるもの。 生成された数値ごとに、最適な値を保存します$c_i \cdot x$。 これにより、数値文字列を達成可能な最高の美しさにマッピングする辞書が作成されます。 後で部分文字列をチェックする代わりにべき乗を生成する理由は、べき乗パターンが疎であるのに対し、部分文字列は密であるためです。 
2. 各クエリ文字列について$s$、すべての部分文字列を列挙します$s[l:r]$。 各部分文字列について、先行ゼロがなく、事前計算されたマップに表示される場合は、保存されている美しさと等しい重みを割り当てます。 それ以外の場合はゼロを割り当てます。 このステップでは、問題を加重セグメンテーション問題に変換します。 
3. DP を定義します。$dp[i]$ペアを保管する$(best\_value, ways)$プレフィックスの場合$s[0:i]$。 最良の値は、達成可能な最小セグメントの重みの最大値であり、その値を達成するパーティションの数が数えられます。 
4.初期化$dp[0] = (+\infty, 1)$空のプレフィックスには制限セグメントがないためです。 
5. ポジションごとに$i$、以前のすべてのカット位置を反復します。$j < i$。 セグメントを考慮する$s[j:i]$そしてその重さ$w$。 と組み合わせる$dp[j]$取ることによって$min(dp[j].best, w)$。 これにより、次の候補スコアが生成されます。$dp[i]$。 これらの候補の最大値を追跡し、同点になる方法を合計します。 
6. 複数の遷移が同じ最小値を生成する場合、それらのカウントを加算します。 遷移によって最良の値が改善されると、カウントが上書きされます。 
7. 各クエリの最終的な答えは次のとおりです。$dp[n]$。 

正確さは、最適なパーティションが最後のカットによって完全に決定されるという事実に依存します。 すべてのプレフィックス状態はすでにすべての最適な方法を集約しているため、1 つのセグメントで拡張すると最適な部分構造が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

# Precompute all valid powers up to 18 digits
pow_map = {}

def limit_len(x):
    return len(str(x)) <= 18

# build power dictionary
# store best c_i * x per numeric value as string
n = int(input())
bases = []

for _ in range(n):
    p, c = input().split()
    p = int(p)
    c = int(c)

    cur = p
    exp = 1
    while cur <= 10**18:
        s = str(cur)
        if len(s) > 18:
            break
        if s not in pow_map or pow_map[s] < c * exp:
            pow_map[s] = c * exp

        if cur > 10**18 // p:
            break
        cur *= p
        exp += 1

q = int(input())

INF = 10**30

for _ in range(q):
    s = input().strip()
    m = len(s)

    # compute substring weights
    w = [[0] * m for _ in range(m)]

    for i in range(m):
        if s[i] == '0':
            continue
        val = 0
        for j in range(i, m):
            val = val * 10 + (ord(s[j]) - 48)
            if j - i + 1 > 18:
                break
            key = str(val)
            if key in pow_map:
                w[i][j] = pow_map[key]

    dp_val = [-1] * (m + 1)
    dp_cnt = [0] * (m + 1)

    dp_val[0] = 10**30
    dp_cnt[0] = 1

    for i in range(1, m + 1):
        best = -1
        cnt = 0
        for j in range(i):
            if dp_val[j] < 0:
                continue
            cur = min(dp_val[j], w[j][i - 1])
            if cur > best:
                best = cur
                cnt = dp_cnt[j]
            elif cur == best:
                cnt += dp_cnt[j]
        dp_val[i] = best
        dp_cnt[i] = cnt

    print(dp_val[m], dp_cnt[m])
```前処理ステップでは、数値文字列からすべての基底指数表現の中で達成可能な最高のスコアへのマップを構築します。 これにより、すべての部分文字列に対する指数チェックの再計算が回避されます。 

クエリごとに、すべての部分文字列値を段階的に事前計算します。 より長い部分文字列は有効な累乗に一致できないため、長さ 18 での初期のブレークは重要です。 先頭ゼロの処理は、開始位置をスキップすることによって強制されます。`s[i] == '0'`。 

次に、DP は各部分文字列を潜在的なセグメントの重みとして扱います。 の`dp_val`配列には達成可能な最小値が格納され、`dp_cnt`それを達成する方法がいくつあるかを追跡します。 初期化セット`dp_val[0]`最初のセグメントが人為的に最小値を下げないように、非常に大きな値に設定します。 

微妙な点は、同じ最適スコアを達成するトランジションに対してのみカウントを行う必要があるということです。 そうしないと、カウントしすぎたり、有効な分解が失われたりすることになります。

 ## 特殊なケース

 重大なエッジ ケースは、部分文字列が数値的に累乗に等しいが、先行ゼロがある場合です。`"09"`。 アルゴリズムはそのような開始を明示的にスキップするため、部分文字列マップに入ることはなく、無効な高スコアのセグメントが発生するのを防ぎます。 

もう 1 つのケースは、次のような累乗表現が重なっていることです。`"64"`、両方の可能性があります$2^6$そして$4^3$。 前処理では最大値が保存されます。$c_i \cdot x$したがって、DP は、代表者に関係なく、常に可能な限り最高の貢献を考慮します。 

最後のケースは、有効なセグメントがまったくない文字列です。 この場合、すべての部分文字列の重みが 0 になり、すべての分割が同一の最小値 0 を持つため、DP は依然として正しく動作し、考えられるすべての分割に等しいカウントで 0 を返します。
