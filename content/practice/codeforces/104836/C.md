 ## 解決策
 ## 問題の理解

 上映開始時間が複数ある 2 つの映画シリーズが与えられています。 各上映時間は固定されているため、すべての開始時刻が時間軸上の完全な間隔を暗黙的に定義します。 有効な計画は、最初の映画の 1 回の上映と 2 番目の映画の 1 回の上映を、選択した 2 つの間隔が時間的に重ならないように選択することで構成されます。つまり、一方が開始される前に一方が厳密に終了する必要があります。 

有効なペアが選択されたら、前のスクリーニングの開始から後のスクリーニングの終了までの合計時間を測定します。 目標は、この合計スパンを最小化する、各映画から 1 つずつ、重複しない 2 つの上映を選択することです。 

入力サイズは映画ごとに最大 200,000 回の上映に対応します。 これにより、すべてのスクリーニング ペアをチェックするソリューションは即座に除外されます。これは、最悪の場合、最大 4e10 の比較が必要となり、これは実現可能な限界をはるかに超えているからです。 スケジュールの順序と構造を活用する必要があります。 

微妙な点は、同じ映画内の上映が任意に重複する可能性があることです。 つまり、1 つのリスト内で互いに素な間隔を仮定することはできないため、1 つのリスト内のローカルな順序のみに基づいた貪欲な仮定は安全ではありません。 

素朴なソリューションをつまづかせる可能性のあるいくつかの特殊なケース:

 1 つの映画に 1 つの上映がある場合、答えは、他のリストから最適な互換性のある上映を選択することになります。 たとえば、2 番目の映画のすべての上映が非常に早い段階で行われる場合、有効な順序は 2 番目、最初の順序だけになる可能性があります。 

最適解が一方のリストから可能な最新の開始を選択し、もう一方のリストから互換性のある最も早い開始を選択する必要がある場合、単純な「最も近い開始時間」ヒューリスティックは間隔の重複制約を無視するため失敗します。 

## アプローチ

 強引なアプローチは簡単です。すべての上映をインターバルとして解釈し、各映画の 1 つのインターバルで構成されるすべてのペアを試します。 各ペアについて、両方の可能な次数をチェックし、それらが重複していないかどうかを判断し、結果のスパンを計算します。 これが機能するのは、すべての有効な組み合わせを明示的に評価するため、最適な組み合わせを見逃すことがないためです。 

ただし、1 つの映画に n 回の上映があり、もう 1 つの映画に m 回の上映がある場合、このアプローチでは O(nm) 回のチェックが実行されます。 両方とも 2e5 までの場合、これは 4e10 の操作となり、非常に遅すぎます。 

重要な観察は、順序が固定されると、目的の構造は間隔の極端な終点にのみ依存するということです。 最初の映画から 1 つの上映を修正した場合、2 番目の映画から可能な限り最適な互換性のある上映のみが必要になります。 各間隔は開始時間に固定期間を加えたものによって決定されるため、互換性は開始時間のしきい値条件まで低下します。 

したがって、すべてをペアにする代わりに、1 つのリストを前処理して、任意の時間しきい値に対して二分探索を使用して他のリスト内の最適な候補をすばやく見つけることができます。 2 次元のペアリングの問題を、一方の配列をスキャンし、対数時間でもう一方の配列をクエリすることに還元します。 

これにより、実装に応じて O(n log m + m log n) または O((n + m) log (n + m)) の解が得られます。

 ## アルゴリズムのチュートリアル

 各上映をインターバルとして扱います。 b_i から始まるボルビ上映は b_i + t_b に終了し、o_j から始まる Oпергеймер 上映は o_j + t_o に終了します。 

両方の可能な順序を考慮したいので、Borbi が 1 番目、Oпергеймер が 2 番目の場合の最良の答えを計算し、役割を交換します。 

### 1. 終了時刻を暗黙的に事前計算する

 間隔は明示的に保存しません。 代わりに、開始配列に依存し、その場で終了時間を計算します。 これにより、メモリがシンプルに保たれ、不必要な構造が回避されます。

### 2. 両方の配列をソートします

 入力はすでに開始時間によってソートされていますが、制約が変更されたり、入力の保証が弱かったりした場合、ソートによって正確さが保証されます。 さらに重要なのは、二分探索推論が有効になることです。 

### 3. 2 番目のムービー用のヘルパーを構築する

 Borbi の次に Oпергеймер という固定順序の場合、各 Borbi 間隔について、Borbi の終了後に開始する最も早い Oпергеймер 間隔が必要になります。 

このために、o_j >= b_i + t_b となるように、Oпергеймер 開始配列内で最初のインデックス j をバイナリ検索します。 

そのような j が見つかると、その間隔が、この最初の映画上映における最も早い有効な 2 番目の映画の選択肢となります。 後で開始しても合計スパンが増加するだけなので、実行可能な最も早いものが常に最適です。 

### 4. この方向に対する候補の答えを計算します

 それぞれの i:

 スパン = (o_j + t_o) - b_i を計算します。 

すべての有効な i の最小値を追跡します。 

### 5. 逆の役割で繰り返します

 ここで、最初に Oпергеймер、2 番目に Borbi を想定し、同じプロセスを対称的に繰り返します。 

最終的な答えは、両方向の最小値です。 

### なぜ効果があるのか

 重要な不変条件は、最初のスクリーニングが固定されている場合、最適な 2 番目のスクリーニングは常に最初のスクリーニングが終了した後に開始される最も早いものであるということです。 後の候補は、左のエンドポイントを固定またはさらに悪化させたまま、右のエンドポイントを増加させるだけであるため、スパンを改善することはできません。 これにより、互換性のあるすべての間隔から開始間隔ごとに 1 つのバイナリ検索結果に検索スペースが削減されます。 両方の可能な順序を評価するため、すべての有効な重複しないペアを最適な形式で 1 ​​回だけカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_direction(a_start, a_dur, b_start, b_dur):
    n = len(a_start)
    m = len(b_start)

    ans = float('inf')

    for i in range(n):
        a_l = a_start[i]
        a_r = a_l + a_dur

        # binary search first b_start[j] >= a_r
        lo, hi = 0, m
        while lo < hi:
            mid = (lo + hi) // 2
            if b_start[mid] < a_r:
                lo = mid + 1
            else:
                hi = mid

        j = lo
        if j < m:
            span = (b_start[j] + b_dur) - a_l
            if span < ans:
                ans = span

    return ans

def solve():
    tb, to = map(int, input().split())

    n = int(input())
    b = list(map(int, input().split()))

    m = int(input())
    o = list(map(int, input().split()))

    # Borbi then Oppenheimer
    ans1 = solve_direction(b, tb, o, to)
    # Oppenheimer then Borbi
    ans2 = solve_direction(o, to, b, tb)

    print(min(ans1, ans2))

if __name__ == "__main__":
    solve()
```このソリューションは、単一方向のルーチンを中心に構成されています。 最初のリストの各スクリーニングについて、終了時刻を計算し、二分探索によって 2 番目のリストで最も古い互換性のあるスクリーニングを見つけます。 二分探索により、重複しない有効なペアのみが考慮されることが保証されます。 

実装でよくある落とし穴は、厳密な非オーバーラップとは、2 番目の開始点が最初の終了点と厳密に大きいわけではなく、少なくとも同じである必要があることを意味することを忘れていることです。 二分探索の条件は次のようになります。`< a_r`、厳密な分離を正しく強制します。 

もう 1 つの微妙な問題は対称性です。 Borbi-first のみをチェックすると、最適な順序付けが Oпергеймер-first であるケースを見逃してしまうため、明示的に両方の方向を評価します。

 ## 特殊なケース

 重要なエッジケースは、1 つの順序だけで実現可能性が得られる場合です。 たとえば、すべての Oпергеймер の上映が非常に早く終了し、Borbi の上映が遅く開始される場合、Oпергеймер の上映のみが機能します。 逆方向の二分探索では可能な場合にのみ有効な候補が見つかり、逆方向では単純に無限大が生成されるため、アルゴリズムはこれを処理します。 

もう 1 つのエッジケースは、複数の上映が同時に開始される場合です。 二分探索によって常に最も早い実行可能な 2 番目のスクリーニングを選択するため、重複は正確さに影響しません。 

最後に、可能な限り最新の最初のスクリーニングによって最適なペアが決定されると、すべての候補開始が独自の最良の一致で独立して評価されるため、すべての i にわたるスキャンにより、そのペアを見逃さないことが保証されます。
