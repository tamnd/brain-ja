 ## 解決策
 ## 問題の理解

 この問題では、写真家のボブがすべてのスポーツ選手の写真を撮るために直線の競馬場に沿ってどこまで移動しなければならないかを決定するよう求められます。 各スポーツマンは、2 つのポジションによって定義される、レーストラックの固定セグメントに沿って前後に走ります。`ai`そして`bi`。 ボブはその位置から開始します`x0`そして、彼がスポーツマンのセグメント内のどこかに立っている場合にのみ、スポーツマンを写真に撮ることができます。 ボブがスポーツ選手全員を撮影できる位置に到達するために移動しなければならない最小距離を見つけるように求められました。 そのような位置が存在しない場合は、-1 を返さなければなりません。 

入力はスポーツ選手の数で構成されます`n`(最大 100)、ボブの開始位置`x0`(0 ～ 1000)、および`n`整数のペアによって定義されるセグメント`ai`そして`bi`(0 ～ 1000)。 各セグメントはどちらの順序でも指定できるため、小さい番号が最初になるとは限りません。 出力は単一の整数、つまりボブが移動しなければならない最小距離です。 

と`n`最大 100 人でも、パフォーマンスの限界に達することなく、すべてのスポーツ選手を個別に処理できます。 問題は主に、範囲を正しく処理し、重複を判断することです。 エッジ ケースには、すべてのセグメントがまったく重ならない状況が含まれます。この場合、有効な位置は存在しません。 たとえば、セグメントが`[0, 2]`、`[5, 6]`、 そして`[8, 10]`の場合、ボブが立ってすべてのランナーを撮影できる単一の位置はないため、正しい出力は -1 です。 不注意なアプローチでは、交差を計算せずに最初のセグメントを参照として選択しようとし、間違った答えが得られる可能性があります。 

## アプローチ

 素朴なアプローチは、0 から 1000 までのすべての位置を調べ、各位置がすべてのセグメント内にあるかどうかを確認し、ボブの開始点からの最小距離を追跡することです。 この総当たり法が機能するのは、位置範囲が小さく (最大 1001 位置)、`n`も小さいです。 最悪の場合、約 100,000 回のチェックが実行されることになりますが、これは 2 秒の制限内で実現可能です。 欠点は、不必要に遅く、問題の構造を活用していないことです。 

最適化するための重要な洞察は、ボブはすべてのセグメントの交点内に立つだけでよいということです。 すべての左端点の最大値とすべての右端点の最小値を取得して交点を計算すると、すべてのスポーツ選手を満足させるポジションの範囲がすぐに見つかります。 この交差が空の場合 (左の最大端点が右の最小端点より大きい)、位置は機能せず、答えは -1 になります。 それ以外の場合、ボブが移動しなければならない最小距離は、`x0`この交差点の最も近い地点まで。 

すべての整数をチェックすると最小距離が見つかることが保証されているため、総当り攻撃は機能しますが、すべてのセグメントの交差が実行可能領域を定義するという単純な特性を利用できません。 交差だけで有効な位置が決定されるという観察により、簡単な算術で問題が O(n * 1000) から O(n) に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * 1000) | O(n) | 受け入れられるが不要 |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 小さい値が最初になるように各セグメントを正規化します。 For a segment`[ai, bi]`、割り当てます`left = min(ai, bi)`そして`right = max(ai, bi)`。 これにより、交差点を見つけるときに一貫した比較が保証されます。 
2. 2 つの変数を初期化します。`max_left`0に、そして`min_right`これらには、すべてのセグメントの交差の端点が保存されます。 
3. 各セグメントを繰り返し処理します。 アップデート`max_left`現在の最大値として`max_left`そしてセグメントの`left`。 アップデート`min_right`現在の最小値として`min_right`そしてセグメントの`right`。 このループの後、`[max_left, min_right]`すべてのセグメントの交差を表します。 
4. 比較して交差点が空かどうかを確認します`max_left`そして`min_right`。 もし`max_left > min_right`、-1を出力します。 これは、すべてのスポーツ選手を満足させる単一のポジションはないことを示しています。 
5. それ以外の場合は、ボブの開始位置からの距離を計算します`x0`交差点へ。 もし`x0`内にあります`[max_left, min_right]`、距離は 0 です。`x0 < max_left`、距離は`max_left - x0`。 もし`x0 > min_right`、距離は`x0 - min_right`。 この距離を返します。 

機能する理由: 交差ステップは、内部のあらゆる位置を保証します。`[max_left, min_right]`ボブはあらゆるスポーツ選手の写真を撮ることができます。 相対的に最も近いエンドポイントを取得することにより、`x0`、最小限の距離を確保しております。 交差点の外側に移動すると距離が増加するか、制約に違反するため、他の位置ではこれより短い距離は得られません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, x0 = map(int, input().split())

max_left = 0
min_right = 1000

for _ in range(n):
    a, b = map(int, input().split())
    left = min(a, b)
    right = max(a, b)
    max_left = max(max_left, left)
    min_right = min(min_right, right)

if max_left > min_right:
    print(-1)
else:
    if x0 < max_left:
        print(max_left - x0)
    elif x0 > min_right:
        print(x0 - min_right)
    else:
        print(0)
```最初のセクションでは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 各セグメントは次を使用して正規化されます。`min`そして`max`交差点の計算が適切に行われるようにするためです。 変数`max_left`そして`min_right`交差点の端点を蓄積します。 最後の条件は 3 つのケースを処理します。ボブはすでに交差点の内側にいる、ボブは交差点の左側、またはボブは右側です。 これにより、off-by-one エラーや不要なループが回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, x0 = map(int, input().split())
    max_left = 0
    min_right = 1000
    for _ in range(n):
        a, b = map(int, input().split())
        left = min(a, b)
        right = max(a, b)
        max_left = max(max_left, left)
        min_right = min(min_right, right)
    if max_left > min_right:
        return str(-1)
    if x0 < max_left:
        return str(max_left - x0)
    elif x0 > min_right:
        return str(x0 - min_right)
    return str(0)

# Provided sample
assert run("3 3\n0 7\n14 2\n4 6\n") == "1", "sample 1"

# Custom cases
assert run("2 5\n0 4\n6 10\n") == "-1", "no intersection"
assert run("1 0\n0 0\n") == "0", "single segment, already there"
assert run("2 0\n0 5\n2 4\n") == "0", "x0 inside intersection"
assert run("3 1000\n0 1000\n500 1000\n600 900\n") == "100", "x0 beyond intersection"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2 5\n0 4\n6 10 | -1 | 交差点が空 |
 | 1 0\n0 0 | 0 | 単一セグメント、正しい位置に x0 |
 | 2 0\n0 5\n2 4 | 0 | x0 はすでに交差点の内側にあります |
 | 3 1000\n0 1000\n500 1000\n600 900 | 100 | x0 交差点の右側 |
