 ## 解決策
 ## 問題の理解

 ポリラインを表す一連の高さを数えています。 x 座標は次のように固定されます。`1, 2, ..., n`したがって、全体の形状は順序によってのみ決定されます。`y1, y2, ..., yn`。 

各高さは次の整数でなければなりません`1`に`4`、水平セグメントは禁止されているため、隣接する高さは異なる必要があります。 「こぶ」は単なる極大値です。 位置で`i`、こぶがある場合`y[i-1] < y[i] > y[i+1]`。 同様に、極小値は次の場合に現れます。`y[i-1] > y[i] < y[i+1]`。 

この問題は、正確に含まれるシーケンスの数を求めます。`t`極大値と正確な`t-1`極小値。 

制約は、ある次元では非常に小さく、別の次元では一見大きく見えます。 シーケンスの長さは最大でも`20`これは、指数関数的な検索が可能である可能性があることを示唆しています。 ただし、各ポジションには 4 つの選択肢があるため、総当たりで調べることになります。`4^20 ≈ 10^12`2秒以内ではまったく不可能です。 

わずかな高さの範囲が本当の手がかりです。 それぞれの値が属するので、`{1,2,3,4}`、最近の要素を含む個別の状態の数は非常に少ないです。 これは、最後のいくつかの値とすでに形成されているこぶの数に対する動的計画法を強く示唆しています。 

微妙な点は、極大値と極小値は 3 つの連続した値を確認した後でのみ決定されることです。 新しい値を追加すると、最後の 3 つの位置の中央の要素は、山、谷、またはそのどちらにも分類されません。 ポジションを分類するのが早すぎる不注意な実装では、間違ったカウントが行われます。 

もう 1 つの簡単な間違いは、同じ高さの隣接が禁止されていることを忘れていることです。 例えば：```
n = 3, t = 1
```シーケンス`1 2 2`視覚的には横ばいから増加しているように見えても、無効です。 等しい隣接要素は水平セグメントを作成するため、このシーケンスはカウントしないでください。 

最大値と最小値の間には交互特性もあります。 シーケンスが上向きに動き始めると、次の転換点は最大値、次に最小値、というようになります。 最大値と最小値を個別にカウントするバグのあるソリューションでは、誤って不可能なパターンが許可される可能性があります。 

例えば：```
1 3 2 4
```ここの位置`2`は最大値と位置です`3`は最小限です。 パターンが正しく交互に表示されます。 

ただし、シーケンスには、間に最小値がない 2 つの連続する最大値を含めることはできません。 ジオメトリがそれを禁止しています。 

もう 1 つの特殊なケースが境界近くに現れます。 ポジション`1`そして`n`隣接する 2 つのものがないため、山または谷とは決して見なされません。 すべての位置を均一にチェックする単純な実装では、エンドポイントが誤ってカウントされる可能性があります。 

例えば：```
1 3 2
```この位置には 1 つのこぶがあります`2`。 

しかし：```
3 1 2
```位置にこぶがない`1`、 それでも`3`唯一の隣接するものよりも大きいです。 

## アプローチ

 ブルート フォース ソリューションでは、長さのすべてのシーケンスが生成されます。`n`値を超える`{1,2,3,4}`そして有効なものをフィルタリングします。 

生成されたすべてのシーケンスについて、いくつかの隣接する値が等しい場合、まずそのシーケンスを拒否します。 次に、すべての内部位置をスキャンし、極大値と極小値をカウントします。 

これが機能するのは、定義が直接的であり、検証が簡単であるためです。 残念ながら、検索スペースは膨大です。```
4^20 = 1,099,511,627,776
```たとえ 1 つのシーケンスのチェックに必要な CPU 命令がわずか数個だったとしても、これは依然として絶望的です。 

重要な観察は、位置が`i`山か谷になるかは、連続する 3 つの値のみに依存します。```
y[i-1], y[i], y[i+1]
```左から右にシーケンスを構築する場合、最後の 2 つの高さがわかったら、新しい高さを追加することで中央の高さの役割が完全に決まります。 

つまり、将来はプレフィックス全体を気にしないことになります。 必要なのは以下だけです:```
current length
last two heights
number of maxima so far
number of minima so far
```これは古典的な動的プログラミング圧縮です。 高さの範囲が 4 つの値のみであるため、状態空間は小さくなります。 

最大でも次のものがあります。```
20 * 4 * 4 * 11 * 11
```州はわずか数千人です。 

移行は簡単です。 現在の最後の 2 つの値が次であると仮定します。`(a, b)`そして追加します`c`。 

もし：```
a < b > c
```それから`b`は極大値です。 

もし：```
a > b < c
```それから`b`は極小値です。 

そうしないと、新しいものは何も作成されません。 

このようにしてすべての状態を拡張し、カウントを蓄積します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(4^n · n) | O(n) | 遅すぎる |
 | 最適なDP | O(n · 4 · t · ²) | O(4² · t²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DP 状態を次のように定義します。```
dp[pos][a][b][mx][mn]
```ここで:

 1.`pos`は現在のシーケンスの長さです。 
2.`a`そして`b`最後の 2 つの高さです。 
3.`mx`すでに形成されている極大値の数です。 
4.`mn`はすでに形成された極小値の数です。 

状態には、この構成を生成するシーケンスの数が格納されます。 

1. 長さのすべてのシーケンスを初期化します。`2`。 

すべてのペアについて`(a, b)`と`a != b`、 セット：```
dp[2][a][b][0][0] = 1
```長さ 2 ではまだ内部位置が存在しないため、山も谷も表示されません。 

1. シーケンスを一度に 1 位置ずつ拡張します。 

現在の状態が次で終わるとします。`(a, b)`。 新しい値をすべて試してみる`c`から`1`に`4`と`c != b`。 

これにより、隣接する高さを等しくすることはできないというルールが維持されます。 

1. 次のことを判断します。`b`転換点となる。 

もし：```
a < b > c
```最大値の数を増やします。 

もし：```
a > b < c
```最小値の数を増やします。 

それ以外の場合、カウントは変化しません。 

中間の値`b`両方の近傍が既知であるため、 は完全に決定されます。 

1. 遷移結果を次の DP 状態に追加します。 

新しい状態は次のようになります。```
(pos + 1, b, c, new_mx, new_mn)
```最後の 2 つの値が前方にシフトするためです。 

1. シーケンスの長さに達するまで続けます`n`。 
2. すべての状態を正確に合計します。`t`マキシマと`t-1`ミニマ。 

最後の 2 つの高さはもう重要ではないので、すべての終了ペアを合計します。 

### なぜ効果があるのか

 DP の不変式は次のとおりです。```
dp[pos][a][b][mx][mn]
```有効な長さのシーケンスの数に等しい`pos`高さで終わる`(a,b)`正確に含まれるもの`mx`極大値と`mn`完全に決定されたすべての内部位置の中での極小値。 

新しい値を追加するたびに`c`、中間値のみ`b`新たに山や谷になる可能性があります。 以前の位置はすでに固定されており、隣接する位置が両方とも既知であるため、これ以上変更することはできません。 これは、すべての遷移でカウントが正確に 1 回更新されることを意味します。 

すべての有効なシーケンスは、次の値を繰り返し追加することで一意に構築できるため、DP はすべての有効なシーケンスを重複または省略することなく列挙します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, t = map(int, input().split())

    # dp[a][b][mx][mn]
    dp = [[[[0] * (t + 1) for _ in range(t + 1)] for _ in range(5)] for _ in range(5)]

    for a in range(1, 5):
        for b in range(1, 5):
            if a != b:
                dp[a][b][0][0] = 1

    for pos in range(2, n):
        ndp = [[[[0] * (t + 1) for _ in range(t + 1)] for _ in range(5)] for _ in range(5)]

        for a in range(1, 5):
            for b in range(1, 5):
                for mx in range(t + 1):
                    for mn in range(t + 1):
                        cur = dp[a][b][mx][mn]

                        if cur == 0:
                            continue

                        for c in range(1, 5):
                            if c == b:
                                continue

                            nmx = mx
                            nmn = mn

                            if a < b > c:
                                nmx += 1
                            elif a > b < c:
                                nmn += 1

                            if nmx > t or nmn > t:
                                continue

                            ndp[b][c][nmx][nmn] += cur

        dp = ndp

    ans = 0

    for a in range(1, 5):
        for b in range(1, 5):
            ans += dp[a][b][t][t - 1]

    print(ans)

solve()
```実装は DP 定義に直接準拠します。 

初期化により、長さ 2 の有効なプレフィックスがすべて作成されます。 長さ 1 から開始すると、転換点には 3 つの値が必要となるため、遷移ロジックが複雑になります。 

外側のループは以下から実行されます。`2`に`n-1`。 反復ごとに 1 つの新しい値が追加され、シーケンスの長さが 1 ずつ増加します。 

トランジションはトリプルを検査します`(a, b, c)`。 これが問題の中心的な考え方です。 真ん中の要素のみ`b`現時点では山にも谷にもなる可能性があります。 

条件の順序付けが重要です。```
if a < b > c:
```以下とは別にチェックする必要があります。```
elif a > b < c:
```なぜなら、ポジションは同時に両方になることはできないからです。 

剪定:```
if nmx > t or nmn > t:
    continue
```DP を小さく保ち、不要な状態を回避します。 

最後に、状態を正確に合計します。`t`マキシマと`t-1`ミニマ。 最後のペア`(a,b)`すべての内部ポジションがすでに分類されているため、これは無関係です。 

Python の整数は大きな応答を自動的に処理するため、オーバーフローは問題になりません。

 次のことを考慮してください。```
3 1
```可能な唯一の構造は次のとおりです。```
low high low
```DP はすべての有効なペアで始まります`(a,b)`そして追加します`c`。 ピークは次の場合にのみカウントされます。```
a < b > c
```有効なシーケンスは次のとおりです。```
1 2 1
1 3 1
1 4 1
2 3 2
...
```最終的な答えは次のようになります`4`高さ制限と明確な隣接ルールを尊重した上で。 

次に、次のことを考えてみましょう。```
3 2
```長さ 3 のシーケンスには、内部位置が 1 つだけあります。 二つのピークを作ることは不可能です。 遷移中、DP は最大 1 回だけピーク カウントを増やすことができるため、次のような状態になります。`2`ピークに達することはありません。 アルゴリズムは正しく返します`0`。 

もう 1 つの注意が必要なケースは、隣接する値が等しい場合です。```
4 1
```不注意な解決策では、次のことが受け入れられる可能性があります。```
1 3 3 1
```ただし、遷移は明示的にスキップされます。```
if c == b:
    continue
```したがって、水平セグメントは自動的に禁止されます。 

最後にエンドポイントの処理を検討します。```
3 1
```順序：```
3 1 2
```最初の値`3`はトリプルの中央の要素のみが分類されるため、ピークとしてカウントされません。 DP は以下の条件のみをチェックします。`(3,1,2)`、これにより、`1`谷ではなく、`3`ピーク。 これは問題の定義と正確に一致します。
