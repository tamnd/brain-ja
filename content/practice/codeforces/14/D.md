 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、`n`都市とは、2 つの都市間に 1 つの単純な経路が存在するように各都市が接続されていることを意味します。 道路には方向がなく、各道路の長さは 1 です。タスクは、長さの積が最大になるように、重なり合わない 2 つの経路を選択することです。 「重なり合わない」ということは、この問題は 2 つのパスが 1 つの都市を共有できないことを意味します。 

入力は、都市の数に続いて構造化されています。`n-1`都市を結ぶ道路を表す整数のペア。 出力は単一の整数、つまり 2 つの有効なパスの長さの最大積です。 

制約は小さいです。`n ≤ 200`。 これは木なので、可能なパスの数は次のとおりです。`O(n^2)`。 すべてのパスのペアの交差をテストする素朴な総当たりには、以下が含まれます。`O(n^4)`操作は明らかに大きすぎます`n=200`。 ツリー構造を活用した、よりスマートなアプローチが必要です。 

考慮すべきエッジ ケースには、ライン ツリー (1-2-3-4 など)、スター ツリー (1 つの中央ノードが他のすべてのノードに接続されている)、および 2 つまたは 3 つのノードのみを持つ最小のツリーが含まれます。 ライン ツリーでは、重複しない 2 つの最も長いパスは単一のエッジのみである可能性があります。 スター ツリーでは、最長のパスは中心を通過する必要があるため、重なり合わない 2 つのパスは別々のリーフ エッジのみを使用できます。 

## アプローチ

 ブルートフォース手法では、考えられるすべての単純なパスを列挙します。 パスごとに、その長さを計算できます。 次に、すべてのパスを他のすべてのパスとペアにして、ノードを共有しているかどうかを確認します。 パスペアの総数は次のとおりです。`O(n^4)`最悪の場合、`O(n^2)`パスと各パスのペアの比較には時間がかかります`O(n)`時間。 これは正しいですが、遅すぎます`n=200`。 

重要な洞察は、ツリー内では 2 つのノード間の距離が一意であるという観察から得られます。 各ノードの単純な BFS または DFS を使用して、すべてのノード ペア間の距離を事前計算できます。 距離がわかったら、問題を再定式化できます。ツリーの各エッジについて、ツリーを 2 つのサブツリーに分割する「カット」とみなします。 最初のサブツリー内のパスは、2 番目のサブツリー内のパスと交差することはできません。 これにより、エッジの削除後にサブツリー内の最長パスを計算し、すべてのエッジの結果を結合するという問題が軽減されます。 

動的プログラミングを使用すると、すべてのサブツリー内の最長パスを効率的に事前計算できます。 具体的には、`dp[u][v]`から始まる最長のパスです`u`をルートとするサブツリーに制約されます`v`再帰的 DFS を使用して計算し、冗長な再計算を回避できます。 一度`dp`が満たされている場合、(エッジで分割された) 重複しないサブツリーのすべてのペアを反復処理して、最大の積を計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^4) | O(n^2) | 遅すぎる |
 | 最適な DP + ツリー分解 | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力からツリーの隣接リストを構築します。 各都市は近隣都市を保存します。 
2. 2D 配列を初期化する`dist[u][v]`すべてのノードのペア間の距離を保存します。 
3. 各ノードについて`u`、DFS または BFS を実行して、他のすべてのノードまでの距離を埋めます。 これにより、`dist[u][v]`で計算されます`O(n^2)`合計時間。 
4. 3D DP 配列を初期化する`dp[u][v]`ノードから始まる最大パス長を表す`u`ノードをルートとするサブツリーに制約されます`v`(または同等に、エッジを通過するパスを考慮すると、`(u, v)`からの方向に`u`に`v`）。 
5. DFS を使用して埋める`dp[u][v]`再帰的に。 ノード用`v`そして隣人`u`、`dp[u][v]`は`1 + max(dp[v][w] for all w ≠ u)`。 
6. すべてのエッジのペアを反復処理します。`(u1, v1)`そして`(u2, v2)`。 これらを、各エッジを削除して形成された 2 つの別個の「サブツリー」として扱います。 次の式を使用して、各サブツリーの最大パス長を計算します。`dp`テーブル。 
7. 発生した 2 つのパス長の最大積を記録します。 
8. 最大積を出力します。 

なぜ機能するのか: DP 不変条件により次のことが保証されます。`dp[u][v]`で始まる最長パスの長さを常に格納します。`v`しかし、向かっては戻りません`u`。 エッジを削除するとツリーが 2 つの交差しないセットに一意に分割されるため、エッジのすべてのペアを考慮することで、考えられる重複しないパスの組み合わせをすべて効果的に列挙することになります。 各パーティションの最大パスを計算するので、それらの積は可能な最大値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1000)

n = int(input())
adj = [[] for _ in range(n)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].append(v)
    adj[v].append(u)

dp = [[0]*n for _ in range(n)]

def dfs(u, parent):
    for v in adj[u]:
        if v == parent:
            continue
        dfs(v, u)
        dp[u][v] = 1 + max((dp[v][w] for w in adj[v] if w != u), default=0)

for u in range(n):
    dfs(u, -1)

ans = 0
for u in range(n):
    for v in adj[u]:
        if u < v:
            for x in range(n):
                for y in adj[x]:
                    if x < y:
                        # Ensure edges do not share nodes
                        if len({u, v, x, y}) == 4:
                            ans = max(ans, dp[u][v] * dp[x][y])

print(ans)
```ソリューションは慎重に構築します。`dp`各エッジを「カット」として扱い、結果のサブツリー内の最長パスを計算することにより、テーブルを作成します。 エッジの二重カウントを避ける必要があるため、次のように繰り返します。`u < v`各エッジを 1 回だけ考慮します。 の`max(..., default=0)`リーフノードを正しく処理します。 

## 実用的な例

 **サンプル入力 1**```
4
1 2
2 3
3 4
```| ステップ | dp テーブル エントリが更新されました | 考慮される最大の製品 |
 | --- | --- | --- |
 | dfs(0) | dp[0][1] = 3 | - |
 | dfs(1) | dp[1][2] = 2 | - |
 | dfs(2) | dp[2][3] = 1 | - |
 | エッジを反復する | ペア (0,1)-(2,3) | 1*1 = 1 |

 説明: ツリーは線です。 最も長い 2 つの重複しないパスは単一エッジであり、それぞれ長さは 1 です。 製品 = 1。

 **カスタム入力**```
5
1 2
1 3
3 4
3 5
```カット後のサブツリーの最長パス: (1,2) → 長さ 1、(3,4) → 長さ 1。積 = 1。別のペア (1,3)-(4,5) → 積 = 2*1 = 2。最大値は 2。

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(n^3) | すべてのノードの BFS/DFS: O(n^2)。 エッジと隣接するエッジに対する DP 計算: O(n^3)。 |
 | スペース | O(n^2) |`dp`テーブルには、両方向の各エッジのパスが格納されます。 |
