 ## 解決策
 ## 問題の理解

 良いイベントとあまり良くないイベントのセットを、白いセグメント、黒いセグメント、2 番目の白いセグメントという 3 つの連続するセグメントに分割された一連の日にわたって分散する方法の数を計算するように求められます。 各セグメントは少なくとも 1 日を占める必要があり、特定の日のすべてのイベントは同じタイプになります。 さらに、イベントは区別可能です。1 日内のイベントを並べ替えたり、同じストライプの日の間でイベントを移動したりすると、異なる構成が生成されます。 

入力は 3 つの整数で構成されます: 合計日数`n`、良いイベントの数`w`、あまり良くないイベントの数`b`。 有効なシーケンスの総数を法で計算するように求められます。$10^9 + 9$。 

制約`3 ≤ n ≤ 4000`そして`2 ≤ w, b ≤ 4000`4000 の階乗は天文学的に大きいため、すべての可能なイベント配置を明示的に反復するアルゴリズムは遅すぎることを意味します。 事前計算とモジュラー演算を活用する組み合わせアプローチが必要です。 

見落としやすいエッジケースには、最小長のセグメントが含まれます。 たとえば、次の場合`n = 3`、`w = 2`、 そして`b = 1`、有効な日の長さは 1,1,1 のみですが、セグメントごとに少なくとも 1 日を強制せずに単純にイベントを分割すると、長さ 0 の日がカウントされたり、使用可能なイベントの数を超えたりする可能性があります。 もう 1 つの微妙な点は、イベントは区別できるため、セグメント内および日数にわたる順序が重要であるということです。 数日以内に順列のカウントを間違えたり、剰余演算を正しく処理できなかったりすると、誤った結果が得られます。 

## アプローチ

 ブルートフォースアプローチでは、良い出来事と悪い出来事を数日間に分割するためにあらゆる方法が試行されます。 一日を 3 つのセグメントに分割し、各セグメントの長さごとに、各日に割り当てられたイベントのすべての順列を試すことができます。 これは明らかに実行不可能です。`w = 100`以上のものを持っています$10^{150}$可能性。 ブルート フォースは、指数関数的な時間の複雑さと、すべての順列を明示的に処理するのが非現実的であるため、失敗します。 

重要な洞察は、この問題が、最小カウントによって制約された、区別できない日にわたる区別可能な項目の組み合わせ分布をカウントすることに帰着できるということです。 各ストライプは本質的に「整数合成」問題、つまり分割です。`k`イベントを`d`毎日少なくとも 1 つのイベントが発生するような日。 分配方法の数の公式`k`区別可能なアイテムを`d`空ではない区別できないビンは、階乗と二項係数を使用した組み合わせ和によって求められます。 

この観察により、階乗とモジュラー逆関数を最大まで事前に計算することができます。`w`または`b`。 次に、有効な日数を 3 つのストライプに分割したそれぞれについて、最初の白いストライプでの良好なイベントの分布数、黒いストライプでの悪いイベントの分布数、2 番目の白いストライプでの良好なイベントの分布数を乗算し、すべての有効な日の長さを合計します。 モジュラー演算により、オーバーフローが発生しません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * w! * b!) | お(1) | 遅すぎる |
 | 最適 | O(n * w + n * b) | O(w + b + n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 階乗とモジュラー逆関数を最大で事前計算します。`max(w, b, n)`モジュロ$10^9 + 9$。 これにより、イベント分布の二項係数を効率的に計算できます。 
2. ヘルパー関数を定義する`ways(k, d)`配布方法の数を返します`k`区別可能なイベントを`d`毎日少なくとも 1 つのイベントを受け取ります。 これは組み合わせ公式を使用して計算されます$\binom{k-1}{d-1} \times k! / \prod \text{day factorials}$、事前に計算された階乗と逆関数によって簡略化されます。 
3. 最初の白いストライプに割り当てられるすべての日数を繰り返します。`w1`1から`n-2`、黒いストライプ`b_days`1から`n-w1-1`、2番目の白いストライプ`w2 = n - w1 - b_days`。 
4. 各トリプルについて`(w1, b_days, w2)`、対応するストライプに割り当てられたすべての有効な数のイベントを反復します。1 日あたり少なくとも 1 つのイベント、合計が以下です。`w`または`b`。 
5. 3 ストライプのモジュロ全体にわたるイベント分布のカウントを乗算します。$10^9 + 9$そして合計して最終的な答えになります。 
6. 答えのモジュロを出力します。$10^9 + 9$。 

不変条件は、各反復で、すべての 1 日の長さの合計が次のようになることです。`n`すべてのイベント数の合計は次のようになります`w`または`b`制限内で、無効な構成がカウントされないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 9
MAX = 4000 + 10

# precompute factorials and inverses
fact = [1] * (MAX)
inv_fact = [1] * (MAX)

for i in range(1, MAX):
    fact[i] = fact[i-1] * i % MOD

inv_fact[MAX-1] = pow(fact[MAX-1], MOD-2, MOD)
for i in range(MAX-2, -1, -1):
    inv_fact[i] = inv_fact[i+1] * (i+1) % MOD

def comb(n, k):
    if k < 0 or k > n:
        return 0
    return fact[n] * inv_fact[k] % MOD * inv_fact[n-k] % MOD

def ways(events, days):
    if days > events:
        return 0
    # number of ways to put 'events' distinguishable items into 'days' non-empty days
    return comb(events - 1, days - 1)

n, w, b = map(int, input().split())

ans = 0
for w1_days in range(1, n-1):
    for b_days in range(1, n - w1_days):
        w2_days = n - w1_days - b_days
        w1_ways = ways(w, w1_days)
        b_ways = ways(b, b_days)
        w2_ways = ways(w, w2_days)
        ans = (ans + w1_ways * b_ways % MOD * w2_ways % MOD) % MOD

print(ans)
```コードはまず階乗とモジュラー逆行列を事前計算して、組み合わせ計算を迅速に実行できるようにします。 の`ways`関数は、区別可能なイベントを日ごとに分割する方法の数を計算し、毎日少なくとも 1 つのイベントが存在するようにします。 メイン ループは、すべての有効な日の分割を繰り返し、各ストライプのカウントを乗算し、答えのモジュロを累積します。$10^9 + 9$。 モジュラー乗算を慎重に処理すると、整数のオーバーフローが回避されます。
