 ## 解決策
 ## 問題の理解

 (n \times n) グリッドがあり、セル ((a,b)) にジョーカーがいます。 ジョーカーからのマンハッタン距離が正確に (d) であるグリッド内のセルを数える必要があります。 

セル ((x,y)) の場合、条件は次のようになります。 

[
 |x-a|+|y-b|=d。 
]

 グリッド境界がなければ、これらのセルは ((a,b)) の周囲にひし形を形成します。 ダイヤモンドには 4 つの対角線の側面があり、制限のない無限グリッド上に正確に (4d) のセルが含まれています。 難しいのは、このダイヤモンドの一部の部分が (n \times n) 部屋の外にある可能性があることです。 

入力には (n,a,b,d) が含まれます。(n) は (10^{18}) と同じ大きさです。 答え自体も順序 (10^{18}) になる可能性があるため、実装には 32 ビット整数よりも大きい値を快適に処理できる整数演算が必要です。 Python 整数はこれに直接適しています。 

(n) のサイズにより、グリッド上の反復処理が除外されます。 すべての (n^2) 個のセルをスキャンする場合でも、最大の場合は最大 (10^{36}) 個のチェックが必要になります。 (d) は独立して (10^{18}) に達する可能性があるため、(d) に比例するアプローチも不可能です。 (n) と (d) の両方に関係なく、一定量の作業が必要です。 

(4d) のような単純な式が失敗する境界ケースがいくつかあります。 たとえば、入力の場合`5 1 1 2`、制限されていないダイヤモンドには 8 つのセルがありますが、部屋内に収まるのは ((1,3))、((2,2))、および ((3,1)) の 3 つだけです。 正しい答えは、`3`したがって、盲目的に戻る (4d) と、部屋の外のセルがカウントされます。 

もう 1 つの微妙なケースは、ダイヤモンドのコーナーです。 のために`3 2 2 1`, all four cells at distance one are inside the room, so the answer is `4`。 4 つの対角辺を個別に数えると、各辺に 2 つの端点が含まれ、合計は 8 になります。 4 つのひし形の頂点はそれぞれ 2 つの隣接する辺に属しているため、4 つの辺の長さを単純に加算すると、すべての頂点が 2 倍にカウントされ、`8`の代わりに`4`。 

3 番目のケースは、ダイヤモンド全体が部屋の外にある場合に発生します。 のために`3 2 2 10`、グリッド内の最大可能距離は 4 であるため、どのセルも中心からマンハッタンまでの距離が 10 になることはありません。 正しい答えは、`0`。 理論上のダイヤモンドの少なくとも 1 つの点が生き残ることを前提とした解決策は、ここでは失敗します。 

## アプローチ

 直接的なアプローチは、部屋のすべてのセル ((x,y)) を検査し、(|x-a|+|y-b|=d) かどうかをテストすることです。 これは、考えられるすべてのセルを正確に 1 回検査し、マンハッタン距離の定義を直接適用するため、正しいです。 最悪の場合の実行時間は (O(n^2)) で、(n=10^{18}) の場合は (10^{36}) 個のセル チェックになります。 メモリ使用量は残る可能性がありますが (O(1))、実行時間の関係でこのアプローチは使用できなくなります。 

個々のセルではなく、方程式の形状に注目することで、より良い結果を得ることができます。 方程式

 [
 |x-a|+|y-b|=d
 ]

 は 4 つの対角線セグメントを示します。 彼らのエンドポイントは

 [
 (a-d,b)、\quad (a,b+d)、\quad (a+d,b)、\quad (a,b-d)。 
]

 たとえば、((a-d,b)) から ((a,b+d)) までのセグメントは次のようにパラメータ化できます。 

[
 (x,y)=(a-d+k,b+k),\qquad 0\le k\le d。 
]

 すべての整数 (k) は、ひし形のその側に 1 つのグリッド セルを与えます。 他の 3 つの辺も同じ構造を持ち、それに応じて座標変化の符号が調整されます。 

ブルートフォース手法は、すべてのセルを独立して考慮するため機能しますが、セルが多すぎるため失敗します。 目的のセットが 4 つの単調な対角線セグメントのみで構成されているという観察により、膨大な 2 次元の検索を 4 つの 1 次元の間隔に置き換えることができます。 

このようなセグメントの 1 つについては、(k=0,1,\ldots,d) を反復する必要はありません。 (k) のどの値が両方の座標を ([1,n]) 内に保持するかを決定するだけで済みます。 (k) が増加すると、各座標は正確に (+1) または (-1) だけ変化するため、各座標制限は単に許容される (k) 値の間隔になります。 これらの間隔を交差させると、一定時間内のセグメント上の有効なセルの正確な数が得られます。 

最後にもう 1 つ詳細があります。 隣接するダイヤモンド セグメントは終点を共有するため、クリップされた 4 つのセグメントを合計すると、頂点自体が部屋の中にある場合は常に、すべてのダイヤモンドの頂点が 2 回カウントされます。 このような頂点ごとに 1 を減算します。 2 つのセグメントはその頂点でのみ交わるため、部屋の外側の頂点は部屋の内側に複製を作成できません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) | (O(1)) | 遅すぎる |
 | 最適 | (O(1)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. マンハッタン距離のひし形の 4 つの辺をそれぞれパラメータ化されたセグメントとして表します。 4 つの開始点は ((a-d,b))、((a,b+d))、((a+d,b))、および ((a,b-d)) であり、各セグメントは 4 つの対角方向のいずれかに正確に (d) 単位ステップ移動します。 これにより、部屋の境界を適用する前に、マンハッタン距離にあるすべてのセルが正確にカバーされます (d)。 
2. 1 つのセグメントに対して、(0\le k\le d) の整数パラメータ (k) を導入します。 その座標は次の形式になります。 

[
 x=x_0+s_xk,\qquad y=y_0+s_yk,
 ]

 ここで、(s_x,s_y) はそれぞれ (1) または (-1) のいずれかです。 すべての有効な整数 (k) は、その側の 1 つのセルに対応します。 
3. 条件 (1\le x\le n) を (k) の区間に変換します。 (s_x=1) の場合、

 [
 1-x_0\le k\le n-x_0。 
]

 (s_x=-1) の場合、

 [
 x_0-n\le k\le x_0-1.
 ]

 (y) 座標についても同じことを行います。 両方の座標間隔を元の間隔 ([0,d]) と交差させます。 
4. 結果の下限が (L)、上限が (R) の場合、セグメントは、(L\le R) の場合は (R-L+1) 個のセルを提供し、それ以外の場合はゼロを提供します。 これは、完全に外側のセグメントと部分的にクリップされたセグメントをまったく同じ計算で処理します。 
5. 4 つのセグメントすべての寄与を合計します。 4 つのセグメントはマンハッタン距離のダイヤモンド全体をカバーしますが、各ダイヤモンドの頂点は 2 つのセグメントに属します。 
6. 4 つの頂点 ((a-d,b))、((a,b+d))、((a+d,b))、および ((a,b-d)) を確認します。 2 つの座標が ([1,n]) 内にあるすべての頂点について、合計から 1 を減算します。 これにより、2 つの隣接するセグメントによって作成された重複箇所が正確に削除されます。 

### なぜ効果があるのか

マンハッタン距離 (d) にあるすべてのセルは、隣接する 2 つの辺にある 4 つのひし形の頂点を除き、ひし形の 4 つの対角線の辺のうちの 1 つに正確に位置します。 各サイドのパラメータ化により、そのサイドのすべての整数セルが 1 回だけ生成されます。 間隔の交差は、その部屋に属する座標を持つ生成されたセルを正確に保持します。 したがって、クリップされた 4 つのセグメントを合計すると、すべての有効なセルが 1 回カウントされ、すべての有効なひし形の頂点が 2 回カウントされます。 部屋内の頂点ごとに 1 を減算すると、重複したカウントが正確に削除され、必要なすべてのセルが 1 回だけカウントされたままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def segment_count(x0, y0, sx, sy, d, n):
    lo = 0
    hi = d

    if sx == 1:
        lo = max(lo, 1 - x0)
        hi = min(hi, n - x0)
    else:
        lo = max(lo, x0 - n)
        hi = min(hi, x0 - 1)

    if sy == 1:
        lo = max(lo, 1 - y0)
        hi = min(hi, n - y0)
    else:
        lo = max(lo, y0 - n)
        hi = min(hi, y0 - 1)

    if lo > hi:
        return 0
    return hi - lo + 1

def solve():
    n, a, b, d = map(int, input().split())

    segments = [
        (a - d, b, 1, 1),
        (a, b + d, 1, -1),
        (a + d, b, -1, -1),
        (a, b - d, -1, 1),
    ]

    answer = 0

    for x0, y0, sx, sy in segments:
        answer += segment_count(x0, y0, sx, sy, d, n)

    vertices = [
        (a - d, b),
        (a, b + d),
        (a + d, b),
        (a, b - d),
    ]

    for x, y in vertices:
        if 1 <= x <= n and 1 <= y <= n:
            answer -= 1

    print(answer)

if __name__ == "__main__":
    solve()
```の`segment_count`機能はソリューションの中核です。 これは、完全なダイヤモンドの側面を表す自然パラメータ範囲 (0\le k\le d) から始まります。 次に、各座標がグリッドの境界に従ってこの範囲を狭めます。 

(x=x_0+k) などの正の方向の場合、下限 (x\ge1) は (k\ge1-x_0) を与え、上限 (x\le n) は (k\le n-x_0) を与えます。 負の方向 (x=x_0-k) の場合、不等式は逆転し、(k\ge x_0-n) および (k\le x_0-1) になります。 これらの不等式を直接処理すると、ジョーカーが部屋の特定の側の近くにいるかどうかに基づく特殊なケースが回避されます。 

4 つのセグメントの説明では、連続するひし形の頂点が使用されます。 方向のペアは ((1,1))、((1,-1))、((-1,-1))、および ((-1,1)) であるため、各辺は 1 回ずつ横断されます。 

頂点の減算は、4 つのセグメント数がすべて計算された後に行われます。 頂点は、その頂点自体がルーム内にある場合にのみ複製されます。 隣接するセグメントの長さから座標を推測するよりも、その座標を明示的に確認する方が安全です。 

Python では整数の精度が任意であるため、オーバーフローの問題は発生しません。 固定幅の整数型を使用する言語では、入力座標と答えには 64 ビットの符号付き整数で十分です。答えは部屋内のセルの数 (10^{36}) を超えることはできませんが、実際には距離リング上の数値は最大 (4\cdot10^{18}) であり、実際には最大 (4\cdot10^{18}) であるため、言語に応じて符号なし 64 ビット型または十分な幅の符号付き型が必要です。

### サンプル 2

 のために`5 2 3 4`、理論上のダイヤモンドは部屋よりもはるかに大きいです。 グリッドに到達するのは、向かい合う 2 つの辺の小さな破片だけです。 

| セグメント | 開始 | 方向 | 有効 (k) | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | ((-2,3)) | ((1,1)) | (3..4) | 2 |
 | 2 | ((2,7)) | ((1,-1)) | なし | 0 |

 | 4 | ((2,-1)) | ((-1,1)) | なし | 0 |

このトレースは、各辺を個別にクリップすることで、特別な幾何学的ケースを必要とせずに、大部分が部屋の外側にあるダイヤモンドを処理できる理由を示しています。

import sys
import io

def segment_count(x0, y0, sx, sy, d, n):
    lo = 0
    hi = d

    if sx == 1:
        lo = max(lo, 1 - x0)
        hi = min(hi, n - x0)
    else:
        lo = max(lo, x0 - n)
        hi = min(hi, x0 - 1)

    if sy == 1:
        lo = max(lo, 1 - y0)
        hi = min(hi, n - y0)
    else:
        lo = max(lo, y0 - n)
        hi = min(hi, y0 - 1)

    return max(0, hi - lo + 1)

def solution(inp: str) -> str:
    n, a, b, d = map(int, inp.split())

    segments = [
        (a - d, b, 1, 1),
        (a, b + d, 1, -1),
        (a + d, b, -1, -1),
        (a, b - d, -1, 1),
    ]

    answer = sum(
        segment_count(x0, y0, sx, sy, d, n)
        for x0, y0, sx, sy in segments
    )

    vertices = [
        (a - d, b),
        (a, b + d),
        (a + d, b),
        (a, b - d),
    ]

    for x, y in vertices:
        if 1 <= x <= n and 1 <= y <= n:
            answer -= 1

    return str(answer)

def run(inp: str) -> str:
    return solution(inp).strip()
