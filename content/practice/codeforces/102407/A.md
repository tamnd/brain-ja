 ## 問題の理解

 ソートされた税表があります。 各行には馬力境界が含まれています`b_i`そして税率`t_i`。 最初の境界は常にゼロであり、境界は厳密に増加します。 パワーのある車の場合`q`、適用されるレートは、境界が厳密に よりも小さいテーブルの最後の行からのレートです。`q`。 最後に特別なケースが 1 つあります。`q`最大境界より大きい場合は、最後のレートが使用されます。 

間隔の表現が少し特殊なので、正確なエンドポイントが重要です。 一行`i`を満たす力に適用されます`b_i < q <= b_{i+1}`。 したがって、`q`境界と正確に等しい`b_i`、行からのレート`i - 1`行に書かれたレートではなく、適用されます`i`。 すべてのクエリされたパワーは少なくとも`1`そして`b_1 = 0`、正確な正の境界の前の行が常に存在します。 

クエリされるすべての車両パワーに対して`q_j`、出力する必要があります`q_j * t`、 どこ`t`は、これらのルールによって選択されるレートです。 まで`100000`テーブルの行と`100000`クエリごとにすべてのテーブル行をチェックするには、最大で`10^10`比較。 これは、一般的なコンテストの制限時間でサポートできる範囲をはるかに超えています。 境界がすでに厳密に分類されているという事実を利用する必要があります。 

レートも減少しませんが、そのプロパティは実際には二分探索には必要ありません。 重要な特性は、境界配列がソートされていることです。 これにより、対数時間で関連する間隔を見つけることができます。 

一見合理的な実装が間違っている可能性がある境界ケースがいくつかあります。

## アプローチ

 直接的な解決策は、税表を最初からスキャンして各クエリを個別に処理することです。 力のために`q`、少なくとも次の最初の境界を探します。`q`。 その境界線があれば`b_i`、適用されるレートは`t_{i-1}`。 そのような境界が存在しない場合は、最後のレートが使用されます。 

表には連続した間隔が記述されているため、このアプローチは正しいです。 最小の境界から開始して上に移動し、最初の境界が次の条件を満たす`b_i >= q`は、正確に以下を含む区間の上端点です。`q`。 したがって、前の行は正しいレートを提供します。 

問題は繰り返し作業の量です。 クエリによってすべての検査が強制される可能性があります`n`これは行ごとに発生する可能性があります。`m`クエリ。 と`n = m = 100000`、最悪の場合は`100000 * 100000 = 10^10`テーブル検査。 個々のスキャンは単純であっても、100 億個の操作を実行するのは現実的ではありません。 

重要な観察は、テーブルから必要な唯一の情報は、次を満たす最初の境界の位置であるということです。`b_i >= q`。 だって全部`b_i`は厳密に増加しており、これはまさに二分探索が解決するタイプの検索です。 潜在的にすべての行をチェックする代わりに、残りの境界範囲の半分を繰り返し破棄します。 

パイソンの`bisect_left`必要な検索を直接表現します。 最初のインデックスを返します`i`そのような`b_i >= q`。 そのインデックスが存在する場合、正しいレートは次のようになります。`t_i`そのときだけ`q`厳密には次より大きいです`b_i`、それは私たちが望んでいることではありません。 さらに便利なことに、結果を次の挿入位置として解釈できます。`q`等しい境界の前で、前の行を使用します。つまり、`t[i - 1]`。 挿入位置が 0 の場合、クエリは最初の境界より前になりますが、クエリは正の値であり、最初の境界が 0 であるため、そのようなことは起こり得ません。 

すべての境界よりも大きいクエリの場合、`bisect_left`返品`n`、つまり、前の行は`n - 1`、まさに最後のレートです。 したがって、別の特別なケースを必要とせずに、同じ式で最終間隔を処理します。 

このブルート フォース手法は、各クエリを含む間隔を明示的に検出するため機能しますが、すべての車について同じ順序付けされたテーブルを最初から検索すると失敗します。 境界がソートされているという観察により、各線形スキャンを 1 つの二分探索に置き換えることができます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n) | 遅すぎる |
 | 二分探索 | O(n + m log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. を読んでください。`n`テーブルの行を抽出し、境界を 1 つの配列に保存し、対応するレートを別の配列に保存します。 入力により、境界配列がすでに厳密に増加していることが保証されるため、並べ替えは必要ありません。 
2.各車両のパワーについて`q`、 実行する`bisect_left(boundaries, q)`。 これにより、次の値以上の最初の境界が見つかります。`q`。 
3. 返された位置を次のようにします。`i`。 正しいレートは`rates[i - 1]`。 もし`q`と全く同じです`boundaries[i]`、その境界で終了する間隔は前の行に属します。これがまさにこれを使用する理由です。`i - 1`。 
4. もし`q`あらゆる境界を超えて、`bisect_left`返品`n`。 表現`rates[i - 1]`となる`rates[n - 1]`、必要に応じて最終レートを選択します。 
5. 乗算`q`選択したレートで計算し、結果を出力に追加します。 すべての回答を蓄積してまとめて印刷することで、無駄な出力操作を回避できます。 

### なぜ効果があるのか

 あらゆるクエリに対して`q`、 させて`i`その最初のインデックスになります`b_i >= q`。 このようなインデックスが存在する場合、以前のすべての境界は次の値よりも小さくなります。`q`、 それで`q`で終了する間隔に属します`b_i`。 その間隔には行からのレートが割り当てられます`i - 1`、与える`rates[i - 1]`。 そのようなインデックスが存在しない場合、すべてのテーブル境界は次の値よりも小さくなります。`q`したがって、問題は最終レートを明示的に割り当てます。`rates[n - 1]`二分探索で返されるため`n`。 したがって、すべてのクエリはテーブルで規定されたレートを正確に受け取り、そのレートにべき乗を乗じることで必要な税金が得られます。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def solve():
    n = int(input())

    boundaries = [0] * n
    rates = [0] * n

    for i in range(n):
        boundaries[i], rates[i] = map(int, input().split())

    m = int(input())
    answers = []

    for _ in range(m):
        q = int(input())

        i = bisect_left(boundaries, q)
        rate = rates[i - 1]

        answers.append(str(q * rate))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```2 つの配列は、入力に表示されるとおりにテーブルを正確に保持します。 ステートメントではすでに境界の増加が保証されているため、ペアを保存して並べ替える必要はありません。`bisect_left`実装上の重要な選択です。 次のような境界配列の場合、`[0, 100, 150, 200]`そしてクエリ`150`、インデックスを返します`2`、インデックスなので`2`以上の最初の値が含まれています`150`。 使用する`rates[1]`間隔に関連付けられたレートを選択します`(100, 150]`、まさにその通りです。 

使用する`bisect_right`1 つずれたエラーになります。 同じクエリに対して`150`、インデックスを返します`3`、アルゴリズムによってレートが選択されます。`(150, 200]`、 それでも`150`それ自体は前の間隔に属します。 

いつ`q`最終境界より大きい、`bisect_left`返品`n`。 アクセスする`rates[n - 1]`その後、自然に最大レートが選択されるため、特別な分岐は必要ありません。 

Python の整数には任意の精度があるため、乗算のべき乗と乗算率は次のとおりです。`10^9`オーバーフローすることはできません。 考えられる最大の製品は、`10^18`、これは Python によって直接処理されます。
