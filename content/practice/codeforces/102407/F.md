 ## 解決策
 ## 問題の理解

 非負の値 a 1 、…、a n の配列があり、観客ごとに 1 つの値があります。 各警察官は 1 つの連続した間隔 [li ,ri ] を監視します。 その役員の注意力はその間隔内の現在の値の合計であるため、すべての役員の注意力の合計はすべての間隔の合計の合計になります。 

アーサーは観客の価値を下げるかもしれない。 観客 j が d j だけ減少すると、0≤d j ≤a j となり、減少の総量は次を満たします。 

j=1 ∑ n d j ≤k。 

目標は、これらが減少した後のすべての警察官の注意力の合計を最小限に抑えることです。 

重要なのは、一人の観客を独立して見ることです。 観客 j が正確に c j 警察間隔に属していると仮定します。 a j を 1 つ減らすと、c j の役員全員が 1 単位の注意を失うため、合計の注意力は正確に c j だけ減少します。 したがって、アーサーの予算の各単位は、c j にのみ依存して異なる値を持ちます。 

まずすべての c j が必要です。 最大 m=10 6 個の間隔が存在する可能性があるため、すべての間隔のすべての位置に 1 を追加すると、コストが高くなりすぎます。 差分配列を使用すると、各間隔を定数時間で処理し、1 つのプレフィックス合計ですべてのカバー カウントを回復できます。 

境界 n ≤ 10 5 は、O(n 2 ) メソッドがすでに大きすぎて、基本演算が最大 10 10 であることを意味します。 役員の数は 10 6 に達する可能性があるため、各間隔を 1 回処理するのが適切な規模です。 値 k は 10 12 に達する可能性があるため、n が小さい場合でも、減少単位ごとに 1 回の反復を実行するアルゴリズムは不可能です。 Python では、100 万間隔の読み取りと処理が実行時間の大半を占めるため、慎重な入力処理も必要です。 

実装を静かに破壊する可能性のある境界ケースがいくつかあります。 k=0 の場合は何も変更できません。 例えば、```
1 1 0
5
1 1
```答えは 5 です。常に予算全体を費やすソリューションでは、許容値を下回る値を誤って減らそうとします。 

k がすべての a j の合計を超える場合、アーサーはすべての観客をゼロにすることができます。 例えば、```
2 1 100
3 4
1 2
```の答えは 0 であり、負の値ではありません。 ポジションの減少は元の値によって制限されます。 

エンドポイントが 1 つだけ含まれる区間にも、正しい差分配列境界が必要です。 のために```
2 1 1
5 7
2 2
```唯一カバーされる位置は 2 番目の位置なので、k=1 の場合の答えは 11 になります。r+1 ではなく r で差分配列を更新したり、0 ベースと 1 ベースのインデックスを混合したりすると、誤って最初の位置もカバーされてしまう可能性があります。 

最後に、ある観客を多数の警察官がカバーする一方で、別の観客を 1 人だけでカバーすることもできます。 のために```
3 2 5
4 4 4
1 3
2 2
```カバレッジ数は 1、2、1 です。 アーサーは、最初に観客 2 に 4 つの可能なユニットすべてを費やす必要があります。これは、そこにある各ユニットが合計 2 ユニットの注意を取り除くためです。 単純に最大の a j を選択したり、観客を元の順序で処理したりする戦略は、実際の目的を逃します。 

## アプローチ

 直接総当たり戦略では、アーサーの予算を一度に 1 単位ずつ考えることができます。 各ユニットについて、n 人の観客全員を検査し、現在のカバレッジ カウントが最大で値がまだ正であるものを見つけて、それを 1 つ減らし、これを繰り返します。 これは正しいです。観客 j から取り除かれるすべてのユニットは目標を正確に c j だけ減少させるため、利用可能な最良のユニットは常に最大 c j を持つユニットになります。 

問題は、k が 10 12 になる可能性があることです。たとえ最適な観客を見つけるのに O(n) しかかからなかったとしても、その手順には次のことが必要になる可能性があります。 

O(nk)=O(10 17 )

 操作。 観客が多くの単位で減少する可能性があるという事実は、単位ごとに同じカバー数を再検討する理由がないことを意味します。 

これを修正する観察は、同じ観客に属するすべてのユニットがまったく同じ値を持つということです。 観客 j がカバレッジ c j を持っている場合、そこで利用可能なすべての a j ユニットはそれぞれ正確に c j を保存します。 その結果、個々のユニットごとではなく、カバレッジ数ごとに予算をグループ化できます。 

すべての c j を計算した後、c j を減らすことで観客を並べ替えます。 Arthur は、最初に最高カバレッジの観客を完全に減らしてから、次のカバレッジ値を続行する必要があります。 残りの予算が 1 人の観客の価値の範囲内に収まる場合、その数のユニットだけが削除されます。 これは総当たり法と同じ貪欲な決定ですが、すべての同等の決定が 1 つの操作に圧縮されます。 

初期の総注意は次のように直接書くこともできます。 

j=1 ∑ n a j c j 。 

観客 j を d j だけ減らすと、目的も d j c j だけ減少します。 すべての d j には 1 単位の予算がかかり、c j の利益が得られるため、降順で利益を得るのが最適です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nk+m) | O(n) | 遅すぎる |
 | 最適 | O(m+nlogn) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 差分配列を作成する`diff`長さは n+1 です。 すべての警察間隔 [l,r] について、l で 1 を加算し、r+1 で 1 を減算します。 これは、区間が l で寄与を開始し、r の直後に寄与を停止するという事実を表しています。 
2. プレフィックスの合計を取得します`diff`。 位置 j での結果の値は正確に c j 、つまり観客 j を監視している警察官の数です。 
3. 初期の総注意を ∑a j c j として計算します。 これはすべての警察官の間隔を合計するのと同じですが、カバレッジ数がわかった後は O(n) で実行できます。 
4. すべての観客のカバレッジ c j と利用可能な金額 a j をペアにし、これらのペアをカバレッジごとに降順に並べ替えます。 カバレッジ c j で観客からユニットが削除されると、c j ユニットの注意が節約されるため、カバレッジが大きいほど常に予算を有効に活用できます。 
5. 分類された観客を横断します。 観客 j の場合、削除します。 

x=min(a j ,k 残り )

 単位。 答えから xc j を引き、残りの予算から x を引きます。 予算がゼロになったらやめる。 

1. 結果の合計を出力します。 予算がすべての観客の価値の合計よりも大きい場合、すべての価値は最終的にゼロになるため、答えは当然ゼロになります。 

### なぜ効果があるのか

 目的は ∑ j a j c j として書き換えることができます。ここで、 c j は位置 j を含む間隔の数です。 観客 j を 1 人減らすと、アーサーの予算が 1 単位かかり、目標が正確に c j だけ減少します。 したがって、利用可能なすべての削減単位は値 c j を持つ独立した項目であり、観客 j はまさにそのような項目 j を提供します。 これらの項目を値の降順で取得すると、予算の合計減少額が最大化されます。これは、最終的な注意を最小限に抑えることとまったく同じです。 したがって、貪欲なトラバーサルによって最適なソリューションが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))

    diff = [0] * (n + 1)

    for _ in range(m):
        l, r = map(int, input().split())
        diff[l - 1] += 1
        diff[r] -= 1

    coverage = [0] * n
    cur = 0
    for i in range(n):
        cur += diff[i]
        coverage[i] = cur

    total = 0
    items = []

    for value, cnt in zip(a, coverage):
        total += value * cnt
        items.append((cnt, value))

    items.sort(reverse=True)

    for cnt, value in items:
        if k == 0:
            break

        take = min(value, k)
        total -= take * cnt
        k -= take

    print(total)

if __name__ == "__main__":
    solve()
```値はカバレッジカウントが再構築された後にのみ必要となるため、入力配列は間隔の前に読み取られます。 差分配列はゼロから始まる位置を使用します。元の区間 [l,r] は次の加算になります。`l - 1`そして減算`r`。 以来`r`が最後の 0 から始まるカバーされたインデックスの 1 つ後の位置である場合、プレフィックスの合計は正しい位置で間隔を停止します。 

プレフィックス ループは次のことを維持します。`cur`現在アクティブな間隔の数として。 その結果、`coverage[i]`間隔に観客 i+1 が含まれる役員の数です。 

表現`value * cnt`最初の答えに対する観客の貢献度全体です。 Python の整数には任意の精度があり、合計が 32 ビット整数よりもはるかに大きくなる可能性があるため、これはここで役立ちます。 実際、a j は 10 7 であり、10 6 もの役員が同じ観客をカバーできます。 

仕分け`(cnt, value)`逆の順序では、より広い範囲が最初に配置されます。 二次発注による`value`同じカバレッジを持つ観客は同じ価値の減少を提供するため、正しさには影響しません。 の`take`式は、通常の場合と、残りの予算が現在の観客の価値よりも小さい場合を同時に処理します。 

コードは、k の単位ごとに 1 回の反復を実行することはありません。 k が 10 12 になる可能性があるため、これは不可欠です。各観客はソート後に 1 回処理されます。
