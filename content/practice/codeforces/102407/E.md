 ## 解決策
 ## 問題の理解

 ボードは方向のない単純なグラフです。 移動では頂点は削除されず、エッジが削除されます。次の移動では、直前に削除されたエッジとエンドポイントを共有するエッジを使用する必要があります。 エッジは選択すると消えるため、一度しか使用できません。 

ゲームを再解釈する便利な方法は、元の頂点をしばらく忘れることです。 元のエッジを頂点とする新しいグラフを作成します。 対応する元のエッジが端点を共有する場合、2 つの新しい頂点を正確に接続します。 これは元のグラフの**折れ線グラフ**です。 ゲームは次のようになります。最初のプレーヤーは折れ線グラフの任意の頂点を選択し、その後のすべての動きは未使用の隣接する頂点を選択します。 これは、Geography の無向頂点バージョンです。 最初のプレーヤーが最初の頂点を選択できれば勝ちとなり、最適なプレイが最終的に 2 番目のプレーヤーを動かさずに残すことができます。 このゲームのマッチングの特徴は、折れ線グラフが完全にマッチングした場合に、2 番目のプレーヤーがすべての可能な開始頂点から勝利することを示しています。 

入力には、最大で (10^4) 個の元の頂点と (10^4) 個の元のエッジが含まれます。 公式の制限は 2 秒および 512 MB です。 元のグラフの単一の高次頂点がそのすべての入射エッジを含むクリークを作成するため、折れ線グラフを直接構築することはすでに疑わしいです。 (10^4) 個のエッジを使用すると、そのクリークにはほぼ (10^4) 個の頂点と、(5\cdot10^7) 個前後の隣接ペアが含まれる可能性があります。 さらに重要なことは、ブルート フォース ゲーム検索は指数関数的かそれより悪いため、目的のソリューションではゲームの状態を列挙するのではなく、折れ線グラフの構造を利用する必要があるということです。 

一般的な誤った解釈を明らかにするいくつかの特殊なケースがあります。 まず、**合計**のエッジ数のパリティが十分ではありません。 考慮する```
4 2
1 2
3 4
```エッジの総数は 2 ですが、各接続コンポーネントには 1 つのエッジが含まれます。 2 つのエッジは隣接していないため、最初のプレーヤーがどちらかを選択した後、2 番目のプレーヤーは移動できません。 答えは`YES`。 ソリューションチェックのみ`m % 2`間違って印刷されてしまう`NO`。 

次に、孤立した頂点には効果がありません。 のために```
4 1
1 2
```頂点 3 と 4 は移動に参加できません。 唯一のエッジが折れ線グラフの 1 つの頂点コンポーネントを形成するため、Arthur が即座に勝ち、答えは次のようになります。`YES`。 エッジの代わりに頂点を数えたり、すべての元の頂点が自明ではないコンポーネントに属することを要求したりすると、間違った結果が得られます。 

3 番目に、偶数のエッジを持つ連結コンポーネントは逆の結果をもたらします。 のために```
4 3
1 2
1 3
1 4
```元の 3 つのエッジはすべて相互に隣接しているため、折れ線グラフは (K_3) になります。 アーサーは 1 つのエッジを選択し、対戦相手は別のエッジを選択し、アーサーが最後のエッジを選択するため、アーサーが勝ちます。 答えは`YES`。 すべての接続コンポーネントが接続されているという事実のみに基づいた不注意な議論は、エッジ数のパリティを逃すことになります。 

## アプローチ

 ブルートフォースアプローチは、現在消去されているエッジとすでに消去されているエッジのセットを完全なゲーム状態として扱うことです。 すべての正当な次のエッジについて、対戦相手が勝つことができるかどうかを再帰的に判断し、少なくとも 1 つの手が対戦相手の負け状態につながる場合は、現在の状態が勝利であると宣言します。 ゲームは有限であり、あらゆる継続が考慮されるため、これは正しいです。 

問題は継続回数です。 (m) 個のエッジを持つ元の星を取ります。 星のすべての 2 つのエッジはその中心を共有しているため、その折れ線グラフは (K_m) になります。 最初のエッジが選択された後は、残りのエッジが有効になり、その後も残りのエッジが有効になります。 再帰により、結果的に (m!) 個の異なる再生シーケンスを調べることができます。 (m) が (10^4) に近い場合、これは完全に不可能です。 状態は本質的に、現在のエッジとともに使用されるエッジのサブセットであり、(O(m2^m)) 個の可能な状態を与えるため、メモ化しても一般状態空間は実用的ではありません。 

重要な観察は、この特定の方向性のないゲームには一致する特徴があるということです。 無向頂点地理では、完全に一致するグラフにより、2 番目のプレーヤーにシンプルな応答戦略が与えられます。 最初のプレーヤーが頂点に入るたびに、2 番目のプレーヤーは固定の完全一致でそのパートナーに移動します。 逆に、最大のマッチングにより一部の頂点が一致しないままになった場合、最初のプレーヤーはそこから開始して、一致するエッジを応答戦略として使用できます。 一致しない頂点が間違ったタイミングで到達可能になったために戦略が失敗した場合、交互のパスは拡張パスとなり、マッチングの最大値に矛盾します。 これは、無向頂点地理の標準的なマッチング特性です。 

最初のプレイヤーは開始頂点を自由に選択できます。 したがって、折れ線グラフは、完全に一致した場合に、最初のプレーヤーが負けていることになります。 したがって、指定されたグラフの折れ線グラフが完全に一致するかどうかを判断するだけで済みます。 

もう一つの構造の単純化があります。 (k) 個のエッジを含む元のグラフの 1 つの連結コンポーネントを考えます。 その折れ線グラフは接続されており、正確に (k) 個の頂点があります。 偶数の頂点を持つ接続された折れ線グラフは常に完全に一致します。 同様に、偶数のエッジを持つすべての接続されたグラフのエッジは、各ペアの 2 つのエッジが頂点を共有するようにペアに分割できます。 これは折れ線グラフの標準プロパティです。 

完全な一致は頂点の数が偶数のグラフでのみ存在できるため、その逆は即時に行われます。 したがって、元のエッジの数が偶数である場合、元のグラフの連結コンポーネントは、正確に折れ線グラフの完全に一致可能なコンポーネントを生成します。 

したがって、ゲーム全体は非常に単純な条件になります。**元のグラフのすべての接続コンポーネントに偶数のエッジが含まれている**場合に、アーサーは正確に負けます。 少なくとも 1 つの連結コンポーネントに奇数のエッジがある場合、その折れ線グラフ コンポーネントのサイズは奇数で、完全に一致するものはなく、Arthur に勝利の開始エッジが与えられます。

 | --- | --- | --- | --- |
 | ブルートフォース | (O(m!)) | (O(m)) 再帰の深さ | 遅すぎる |

 最適なアルゴリズムでは、折れ線グラフを作成する必要はなく、消去されたエッジの実際の勝利シーケンスを知る必要もありません。 必要なのは、各接続コンポーネント内のエッジの数のパリティだけです。 

## アルゴリズムのチュートリアル

1. Disjoint Set Union 構造を使用して、元のグラフの連結コンポーネントを構築します。 すべての入力エッジ ((u,v)) について、(u) と (v) を結合します。 コンポーネント構造から必要な情報は、どのコンポーネントに各エッジが含まれるかということだけです。 
2. すべての結合が完了したら、元のエッジをもう一度スキャンします。 エッジ ((u,v)) については、(v) の代表でもある (u) の代表を見つけ、そのコンポーネントのエッジ数を増分します。 すべての結合の後にエッジをカウントすると、入力エッジが出現した順序に依存することがなくなります。 
3. 少なくとも 1 つのエッジを含むすべてのコンポーネントをチェックします。 エッジ数が奇数の場合は印刷します`YES`。 このようなコンポーネントは、奇数の頂点を持つ折れ線グラフ コンポーネントを生成するため、そのコンポーネントは完全に一致することができません。 アーサーはそこから優位にスタートでき、勝利の戦略を持っています。 
4. すべての空でないコンポーネントに偶数のエッジがある場合、次のように出力します。`NO`。 対応する各折れ線グラフ コンポーネントには偶数の頂点があるため、完全に一致します。 これらの完全な一致の素結合は折れ線グラフ全体の完全な一致であるため、2 番目のプレーヤーは一致戦略を使用してすべての最初の選択肢に答えることができます。 

### なぜ効果があるのか

 中心不変量は、元のグラフの連結成分と折れ線グラフの連結成分の間の対応関係です。 2 つのオリジナル エッジは、それらが同じ接続されたコンポーネントに属している場合に、隣接するオリジナル エッジのシーケンスを通じて正確に接続できるため、ゲームの動きが 1 つのオリジナル コンポーネントから別のオリジナル コンポーネントに交差することはありません。 

(k) 個のエッジを持つ 1 つの連結コンポーネント内に、折れ線グラフには (k) 個の頂点があります。 (k) が奇数の場合、完全に一致することはできないため、そのコンポーネント上のフリースタートの方向なし地理ゲームは最初のプレーヤーの勝ちとなります。 (k) が偶数の場合、折れ線グラフは完全に一致しているため、2 番目のプレーヤーは常に一致するエッジに沿って応答できます。 全体的な折れ線グラフは、空ではない元のコンポーネントのエッジ数が偶数である場合に正確に完全に一致します。 したがって、アルゴリズムは次のように出力します`YES`まさにアーサーが勝利の要素を持ってスタートしたときだ。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    parent = list(range(n))
    size = [1] * n
    edges = []

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a = find(a)
        b = find(b)
        if a == b:
            return

        if size[a] < size[b]:
            a, b = b, a

        parent[b] = a
        size[a] += size[b]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v))
        union(u, v)

    edge_count = [0] * n

    for u, _ in edges:
        root = find(u)
        edge_count[root] += 1

    for v in range(n):
        if edge_count[v] % 2 == 1:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```最初のループはすべてのエッジを保存し、そのエンドポイントを DSU に結合します。 パス圧縮`find`コンポーネント サイズによる結合により、DSU 全体がこれらの制約に対して効果的に線形に機能します。 

2 番目のループでは、最終コンポーネントの代表によってエッジをカウントします。 すべてのエッジがすでに結合されているため、両方のエンドポイントが同じ DSU コンポーネントに属しているため、最初のエンドポイントを使用するだけで十分です。 このカウントはすべての結合の後に意図的に実行されます。 入力の読み取り中にこれが行われた場合、最初にエッジが代表に割り当てられ、後で別のコンポーネントにマージされる可能性があります。 

最後のループでは、カウントがゼロ以外の DSU 代表でのみパリティをチェックします。 すべてのエッジは最終代表を使用して割り当てられるため、非代表のカウントはゼロになります。 孤立した頂点もカウント 0 になり、ゲームとは正しく無関係になります。 

Python には整数オーバーフローの問題はなく、可能な最大コンポーネント数は (10^4) のみです。 インデックス付けは、問題の 1 から始まる頂点から 0 から始まる Python 配列に即座に変換されるため、DSU には正確に (n) 個の要素が含まれます。

    size = [1] * n
    edges = []

            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

        a = find(a)
        b = find(b)

        edge_count[find(u)] += 1

    for count in edge_count:

    try:
        return solve()
    finally:
        sys.stdin = old_stdin

4 1
1 2
```DSU は、1 つのエッジを持つ頂点 1 と 2 を含む 1 つのコンポーネントを作成しますが、頂点 3 と 4 はエッジ カウント 0 で分離されたままになります。 ゼロ以外のコンポーネントのサイズが奇数であるため、アルゴリズムは次のように出力します。`YES`。 ゼロエッジ コンポーネントは、そこから選択するエッジがなく、したがってそれらに関連付けられたゲーム ポジションがないため、重要ではありません。 

奇妙な星のために```
4 3
1 2
1 3
1 4
```3 つのエッジはすべて 1 つのコンポーネント内にあるため、エッジ数は 3 です。折れ線グラフは (K_3) です。 アーサーは最初に任意のエッジを消去でき、対戦相手は残り 2 つのエッジのうち 1 つを消去でき、アーサーは最後のエッジを消去します。 アルゴリズムは出力します`YES`その三角形を構築することはありません。 

偶数の星のために```
5 4
1 2
1 3
1 4
1 5
```コンポーネントには 4 つのエッジが含まれており、それらのエッジのすべてのペアが隣接しています。 折れ線グラフは (K_4) で、完全に一致すると 4 つの頂点を 2 つのペアにできます。 2 番目のプレーヤーは、最初のプレーヤーが選択したエッジに対して、対応するパートナーを使って常に答えることができるため、アーサーは負け、アルゴリズムは次のように出力します。`NO`。 

最も危険な実装上の間違いは、DSU がコンポーネントのマージを完了する前にエッジをカウントしてしまうことです。 例えば、```
4 2
1 2
2 3
```最初に 1 と 2 を結合し、次に 2 と 3 を結合します。最終的に両方のエッジは 1 つのコンポーネントに属し、その数は 2 となるため、答えは次のようになります。`NO`。 入力処理中に古い代表に対してカウントすると、一時的なコンポーネント ID 間でこれら 2 つのエッジが分割され、間違ったパリティが生成される可能性があります。 このソリューションでは、エッジを保存し、すべての結合が完了した後にのみエッジをカウントすることで、これを回避します。 

最後の境界ケースは、(10^4) 個の頂点と (10^4) 個のエッジを持つグラフです。 接続された構造はパスから取得されます```
1-2-3-...-10000
```余分なエッジが 1 つある`1 3`。 ちょうど 10000 個のエッジがあり、すべてが 1 つの連結コンポーネントになっているため、コンポーネントのパリティは偶数であり、答えは次のようになります。`NO`。 DSU は、小さなグラフと同じ線形構造でインスタンス全体を処理します。これが、解が上限でも高速に保たれる理由です。
