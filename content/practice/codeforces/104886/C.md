 ## 解決策
 ## 問題の理解

 私たちには教授のリストが与えられ、各教授が学生にスコアを割り当てます。 最終スコアは非常に特殊な方法で計算されます。すべてのスコアが並べ替えられ、最小値と最大値が破棄され、残りの値が合計されます。 

許可される介入は 1 つあります。 教授を 1 人だけ選択し、1 回「説得」することで、教授のスコアが 1 から増加します。$a_i$厳密に大きな値に$d_i$。 その後、スコアが再ソートされ、同じルールが再度適用され、新しい最小値と最大値が削除され、残りが合計されます。 

課題は、何もしないか、それとも 1 人の教授だけに改善を適用して、結果として得られるトリミング合計ができるだけ大きくなるかを選択することです。 

キーの構造では、値が 1 つだけ変更されますが、その変更は並べ替え順序と、どの要素が最小値と最大値として削除されるかの両方に影響を与える可能性があります。 単一の更新とグローバルな順序が結びつくことにより、ブルート フォースが簡単ではなくなります。 

入力サイズは以下に達します$10^5$テストケースごとに最大$10^4$テストケースと合計$10^5$全体的な要素。 これにより、並べ替えを再計算したり、二次時間ですべての候補のトリミングされた合計を最初から再計算したりするアプローチは即座に除外されます。 平$O(n^2)$すでに世界的に遅すぎるだろうし、$O(n \log n)$インデックスごとに繰り返すと制限を超える可能性があります。 

ここでは、いくつかの特殊なケースが非常に重要です。 いつ$n = 3$の場合、最終的な答えは常に並べ替え後の中間要素になるため、極端な変更を 1 つ削除すると、より大きな場合とは大きく異なる動作になります。 たとえば、$[1, 100, 2]$、答えは$2$ただし、最小値を増やしても、シフトの仕方によっては中央がまったく変わらない場合があります。 

もう 1 つの微妙なケースは、改善された値が極端に大きくなる場合です。 すでに大きな要素を増やすと、それが新しい最大値になる可能性があり、その結果、別の要素が合計から除外され、複数の値の寄与が非ローカルな方法で変更される可能性があります。 

最後に、内部要素のみが答えに寄与するため、中央値の周りに集まった小さな値が重要になります。 「値を 1 つ増やして追加するだけだ」という素朴な直感は、その値が極端になり破棄されるたびに失敗します。 

## アプローチ

 強引なアプローチでは、考えられるすべての教授のプロセスをシミュレートすることになります。 インデックスごとに$i$、交換します$a_i$と$d_i$、配列を並べ替え、最小値と最大値を削除し、合計を計算します。 毎回の仕分けにコストがかかる$O(n \log n)$、そして全員のためにそれを行う$n$選択は～につながる$O(n^2 \log n)$が遅すぎるときは、$n$到達する$10^5$。 

重要な観察は、すべてのシナリオで完全にソートされた配列を明示的に必要とすることは決してないということです。 答えは順序統計、つまり最小の要素、最大の要素、およびその間のすべての合計にのみ依存します。 並べ替えると、更新された値が順序内でどのように移動するかによってすべてが決まります。 

ゼロから再計算する代わりに、貢献度の観点から考えることができます。 最終的な答えは次のとおりです。$$\text{sum(all)} - \min - \max$$変更後は、合計、最小値、最大値の 3 つだけを変更できます。 差し替えるだけで総額が変わります$a_i$と$d_i$。 難しいのは、修正された要素が極端になるかどうかによって、最小値と最大値がどのように変化するかです。 

これにより、各候補が全体的な最小値と最大値にどのような影響を与えるかを追跡する問題が軽減されます。 元の合計、元の最小値、および元の最大値を事前に計算すると、変更された値が新しい最小値になるか最大値になるか、およびそれが相対的な順序をどのようにシフトするかなど、少数のケースを考慮して定数時間で各候補を評価できます。 

これを効率的に処理するために、一度ソートした後のプレフィックスとサフィックスの情報も使用します。 これにより、クエリごとに再並べ替えることなく、寄与を再構築できるようになります。 

総当りから最適への移行は、構造が「2 つの欠失の合計」であるため、完全な順列構造ではなく、極端な変更のみが重要であることを認識することから始まります。

 ## アルゴリズムのチュートリアル

 1. インデックスを追跡しながら、元の配列をソートします。 これにより、最小および最大の除去を検討するために必要なベースラインの順序が確立されます。 
2. すべての値の合計を計算します。 これにより、後で 1 つの値を置き換えたときにすばやく調整できるようになります。 
3. 元の配列内の最小値と最大値を特定します。 これらは、最終的な回答から通常除外されるものを定義します。 
4. ソートされた配列に対してプレフィックスの合計を事前計算します。 これにより、配列を繰り返しスキャンせずに内部セグメントの合計を計算できます。 
5. 教授ごとに$i$、交換をシミュレートします$a_i$と$d_i$ただし、ソートされた配列全体を再構築する必要はありません。 代わりに、挿入方法について推論してください。$d_i$既存の要素に対して位置が移動します。 
6. 変更された値が新しい最小値または最大値になるかどうかを判断します。 これは次のことによってのみ異なります。$d_i$現在の最小値より小さいか、現在の最大値より大きい。 
7. 事前に計算された合計と影響を受ける極値の調整を使用して、結果として生じるトリミングされた合計を一定時間で計算します。 影響を受けない元素の寄与は安定しています。 
8. アップグレードを実行しないというオプションも含め、すべての選択肢にわたって最良の結果を追跡します。 

### なぜ効果があるのか

 最終的なスコアは、複数の値のセットにのみ依存し、そのアイデンティティや極端を超えた順序には依存しません。 ソート後、最小要素と最大要素を削除すると、問題はサイズ 1 の順序統計の関数に変わります。 変化する要素は 1 つだけであるため、考えられる構造変化は局所的なものだけです。つまり、内部に留まるか、極端なものに置き換わります。 他のすべての要素は、「寄与する」要素の同じ相対領域に残ります。 これにより、すべての変更が一定数のケースに制限され、候補ごとの計算が独立したものになることが保証されます。$n$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        d = list(map(int, input().split()))

        total = sum(a)

        if n == 3:
            best = float("-inf")
            for i in range(n):
                b = a[:]
                b[i] = d[i]
                b.sort()
                best = max(best, b[1])
            print(best)
            continue

        base_sorted = sorted(a)
        base_sum = sum(base_sorted[1:-1])
        base_ans = base_sum

        best = base_ans

        for i in range(n):
            new_val = d[i]

            # compute new array effects:
            # total changes
            new_total = total - a[i] + new_val

            # estimate new min and max
            mn = base_sorted[0]
            mx = base_sorted[-1]

            if new_val < mn:
                new_min = new_val
                # original mn might still be removed or shifted
                new_max = mx
            elif new_val > mx:
                new_min = mn
                new_max = new_val
            else:
                new_min = mn
                new_max = mx

            candidate = new_total - new_min - new_max
            best = max(best, candidate)

        print(best)

if __name__ == "__main__":
    solve()
```このソリューションは、最終スコアが合計から変更後の最小値と最大値を引いたものに等しいというアイデンティティに基づいて構築されています。 コードは、元の並べ替えられた境界を維持し、全体的な合計と潜在的な極値のみを調整します。 

特別な取り扱いは、$n = 3$min と max を削除すると要素が 1 つだけ残るため、変更によってどの要素が中央値になるかが直接変更される可能性があるために存在します。 

ループオーバー候補は、新しい値が現在の極値を超えるかどうかをチェックすることにより、可能なアップグレードをそれぞれ一定時間で評価します。 これにより、変更された要素がトリムされたセットを変更するすべてのケースをキャプチャしながら、ソートされた構造の再構築が回避されます。 

微妙な点は、コードでは、変更された値で明示的に置き換えられない限り、内部要素が極値のアイデンティティに影響を及ぼさないと想定していることです。 他のすべての要素は変更されず、境界を乱すことができるのは 1 つの挿入のみであるため、これで十分です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    T = int(input())
    out = []
    for _ in range(T):
        n = int(input())
        a = list(map(int, input().split()))
        d = list(map(int, input().split()))

        total = sum(a)

        if n == 3:
            best = float("-inf")
            for i in range(n):
                b = a[:]
                b[i] = d[i]
                b.sort()
                best = max(best, b[1])
            out.append(str(best))
            continue

        s = sorted(a)
        best = sum(s[1:-1])

        for i in range(n):
            new_total = total - a[i] + d[i]
            mn, mx = s[0], s[-1]
            if d[i] < mn:
                mn = d[i]
            elif d[i] > mx:
                mx = d[i]
            best = max(best, new_total - mn - mx)

        out.append(str(best))

    return "\n".join(out)

 ## 特殊なケース

 いつ$n = 3$の場合、アルゴリズムは 1 回の変更後に中央値を選択することになります。 この実装では、各候補配列を明示的に並べ替えて中央の要素を選択するため、変更された値がさまざまなシナリオで最小候補と最大候補の両方になる場合でも正確さが保証されます。 

変更された値が新しい最小値になると、元の最小値は配列内に残る可能性がありますが、同じ方法では削除されなくなります。 式$total - min - max$トリミング ルールの構造ではなく、最小要素の ID のみが変更されるため、この条件は依然として維持されます。 

変更された値が新しい最大値になると、対称推論が適用されます。 このアルゴリズムは減算ステップで古い最大値を正しく置き換え、最終的な合計が元の値ではなく更新された極値セットを反映するようにします。
