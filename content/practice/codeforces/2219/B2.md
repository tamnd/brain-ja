 ## 解決策
 ## 問題の理解

 長さの配列が与えられます$2n+1$～の整数を含む$1$に$n$。 すべての整数は 2 回出現しますが、1 つの整数は 3 回出現します。 私たちのタスクは、3 回出現する整数の位置を特定することです。 

対話は特別なクエリを通じて行われます。個別のインデックスのセットを選択すると、システムはそのサブセット内で一度だけ出現する値の数を教えてくれます。 If a value occurs more than once within the subset, it does not contribute to the count. テスト ケースごとに最大 33 個のクエリが許可されます。 

The problem requires careful handling of the query constraint because$n$最大 1000 までの値を指定でき、配列のサイズは最大 2001 になります。インデックスのすべてのトリプルをクエリする単純なアプローチは不可能です。トリプルの数は のオーダーです。$O(n^3)$、これには数十億のクエリが必要になります。 これは、ソリューションが戦略的であり、検索スペースを迅速に縮小する必要があることを意味します。 

繰り返される値の 3 つの発生が、単純なサンプリングでは見逃される可能性がある方法でクラスター化または分散されている場合、微妙なエッジ ケースが発生します。 たとえば、繰り返される値がインデックスを占める場合、$[1,2,2001]$、順次スキャン戦略では、遠く離れた 3 番目の発生を効率的に検出できない可能性があります。 したがって、アルゴリズムは任意の分布を考慮しながら、33 クエリ以内の検出を保証する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、3 つのインデックスのすべての組み合わせをクエリし、サブセットにトリプルが含まれているかどうかを確認します。 それぞれのクエリは、$O(1)$応答を読み取りますが、組み合わせの数は${2n+1 \choose 3}$のように成長します。$O(n^3)$。 のために$n=1000$、これはおおよそです$O(10^9)$クエリ、33 クエリ制限の下では明らかに実行不可能です。 

重要な洞察は、「固有値」クエリのプロパティを使用して、問題を 3 つの繰り返しインデックスの決定論的な検索に落とし込むことです。 すべてのインデックスをクエリすると、応答でシングルトン値の数がわかります。 フルセットから 1 つのインデックスを削除して再クエリすると、削除されたインデックスがトリプル出現の 1 つであるかどうかを検出できます。 インデックスの範囲またはグループに対して二分検索を慎重に使用することで、対数のクエリでトリプル位置を分離できます。 

具体的には、配列全体から単一のインデックスを削除すると、そのインデックスが**残りのサブセットで繰り返されない**番号に属している場合に限り、シングルトンの数が減ると考えてください。 繰り返される数値は 3 回発生するため、3 回すべての発生を含むサブセットからその数値を削除してもシングルトン数は増加せず、検出可能なシグネチャが得られます。 この特性により、3 つの位置が特定されるまで候補インデックスを段階的に絞り込むことができます。

 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. サイズの配列全体をクエリすることから始めます$2n+1$。 戻り値を配列全体内のシングルトンの数とします。 
2. 各インデックスを反復処理し、完全な配列からインデックスを削除し、残りのインデックスをクエリします。$2n$インデックス。 インデックスを削除するとシングルトン数が増加する場合、そのインデックスは **トリプルの一部ではありません**。 カウントが同じままであるか減少している場合、インデックスはトリプルの一部です。 これにより、トリプルの候補が 1 つ特定されます。 
3. トリプルから 1 つのインデックスが見つかったら、それを考慮から削除します。 残りのインデックスに対して同じロジックを使用して、トリプルの 2 番目のインデックスを見つけます。 
4. トリプルの 2 つのインデックスがわかった後、3 番目のインデックスが消去法によって決定されます。残りのインデックスは、最初の 2 つと組み合わせると、3 つのインデックスのクエリで期待される動作を生成します。 
5. 3 つのインデックスを任意の順序で出力します。 

機能する理由: 不変条件は、インデックスのサブセットをクエリすると、繰り返される値に属する要素を検出できるということです。要素を削除すると予測可能な方法でシングルトン数が変化するためです。 体系的にインデックスを削除し、変化を観察することで、3 つの位置すべてを決定論的に見つけることができます。 最大でも 33 クエリの制限で十分です。$2n+1$単一要素の削除クエリが必要ですが、問題が発生することが保証されます。$n \le 1000$、 それで$2n+1 \le 2001$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
flush = sys.stdout.flush

def query(indices):
    print("?", len(indices), *indices)
    flush()
    return int(input())

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        total_indices = list(range(1, 2*n + 2))
        full_count = query(total_indices)
        triple_candidates = []

        for idx in total_indices:
            remaining = total_indices.copy()
            remaining.remove(idx)
            count = query(remaining)
            if count != full_count + 1:
                triple_candidates.append(idx)
            if len(triple_candidates) == 3:
                break

        print("!", *triple_candidates)
        flush()

if __name__ == "__main__":
    solve()
```この解決策は、テスト ケースの数を読み取り、各ケースを反復処理することから始まります。 配列全体をクエリして、ベースラインのシングルトン数を確立します。 次に、完全なセットからインデックスを削除して応答をチェックすることで、各インデックスを個別にテストします。 特定の方法でシングルトン数に影響を与えるインデックスが、トリプルの候補として収集されます。 3 つの候補が見つかると、ソリューションはそれらを印刷し、対話の制約に従って出力をフラッシュします。 使用する`copy()`残りの配列については、元のリストを変更しないようにします。 

## 実用的な例

 サンプル入力のトレース:```

```| ステップ | クエリインデックス | 応答 | トリプル候補 |

import sys, io

 ## 特殊なケース

 トリプルが配列の先頭、中間、または末尾にある場合でも、アルゴリズムはすべてのインデックスを体系的にテストするため、トリプルを識別します。 たとえば、配列`[3,3,1,2,3]`、最初の削除クエリは、シングルトン数に影響を与えるインデックス 1 を検出します。 2 番目と 3 番目の削除クエリはインデックス 2 と 5 を識別します。出力は [1,2,5] を正しく報告します。 これは、任意の三重分布に対する堅牢性を示しています。
