 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、`n`頂点をルートとする頂点`1`。 各頂点間には一意の整数の重みがあります。`0`そして`n-1`。 任意の頂点に対して`v`と定義します。`S_v`ルートからルートまでのパスに沿った重みのセットとして`v`、包括的。 それから`f(v)`には存在しない最小の非負の整数 (MEX) です。`S_v`。 

単一の操作を最大 1 回実行できます: 頂点を選択します`v`そしてその重りを交換します`p_v`と`f(v)`。 私たちの目標は、次の合計を最大化することです。`f(v)`演算を適用した後にすべての頂点に適用するか、より高い合計が得られる場合は適用せずに実行します。 

入力には最大で次のものを含めることができます`2 * 10^5`複数のテスト ケースにわたる頂点。 ブルートフォース再計算`f(v)`すべての頂点で操作を試みると、すべてのパスに沿った MEX の再計算には頂点ごとに線形時間がかかるため、遅すぎます。`O(n^2)`テストケースごとに。 したがって、初期 MEX 値を効率的に計算し、許可される 1 つの演算が合計にどのような影響を与えるかを判断し、それを適用する最適な頂点を見つけることができるアルゴリズムが必要です。 

主要なエッジ ケースは、ツリーがチェーンであり、重みが次から始まる場合に発生します。`0`。 そのような場合には、`f(v)`は単に各頂点の深さです。 中央の頂点に対して操作を実行すると、どの頂点を選択するかに応じて合計が増加する場合と増加しない場合があり、常にルートまたはリーフを選択する単純なアプローチが間違っていることがわかります。 

## アプローチ

 ブルートフォースアプローチは、すべての頂点を反復処理し、割り当てをシミュレートすることです。`f(v)`に`p_v`、すべてを再計算します`f(u)`パスに沿った値を計算し、それらを合計します。 これは正しいですが、パスに沿って MEX を更新するには時間がかかるため、実行できません。`O(n)`頂点ごとに、降伏`O(n^2)`テストケースごとに。 と`n`まで`2 * 10^5`、これでは制限時間内に収まりません。 

重要な観察は次のとおりです`f(v)`ルートからルートへのパスに沿った重みのセットによって決定されます。`v`。 MEX がすでにパス内にある場合は、置き換えます`p_v`と`f(v)`先祖には影響しませんが、子孫には影響する可能性があります。 それぞれの数字なので`0`に`n-1`が 1 回だけ発生すると、ルートからリーフまでの MEX 値のシーケンスが、欠損値が発生するまで増加します。 したがって、最適な操作は、それをまったく適用しないこと、または現在の重みが次の MEX の子孫への伝播をブロックする頂点に適用することです。 最初に MEX 値の合計を計算し、ルート パスに沿って最初に欠落している整数を特定し、その値がブロックする頂点での演算の適用を検討できます。 これにより、複雑さが 1 回の DFS トラバーサルに加えて、いくつかの定数更新に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析し、ツリーを表す隣接リストを作成します。 これにより、任意の頂点の子への O(1) アクセスが許可されます。 
2. 配列を初期化する`f`サイズの`n`各頂点の MEX とブール配列を保存します`seen`サイズの`n+1`現在のパスにどの整数が現れるかを追跡します。 
3. ルートから DFS を実行して、初期 MEX 値を計算します。 

1. 現在の頂点の重みを表示どおりにマークします。 
2. から増分して現在の MEX を計算します。`0`既知としてマークされていない値が見つかるまで。 
3. この値を次の場所に保存します。`f[v]`。 
4. 子を再帰的に処理します。 
5. バックトラック: 表示されているように、現在の頂点のウェイトのマークを外します。 
4. すべての合計を追跡する`f(v)`の値`sum_f`。 
5. 合計を最大化するには、頂点の重みを次のように変更することに注意してください。`f(v)`サブツリー内の MEX のみを増加させることができます。 ルートから最初の欠落整数までのパスに沿った頂点を特定します (最初の MEX がパスに沿ったインデックスと等しくありません)。 その重みを置き換えることで、MEX 値をさらに伝播できるようになります。 
6. 合計が増加する場合はその頂点に操作を適用し、そうでない場合はツリーを変更しないままにします。 
7. 最大合計を出力します。 

**機能する理由:** 各頂点は、その MEX を合計に正確に反映します。 重みは一意であり、MEX はパスに沿った最小の欠落数値であるため、ブロックされた数値を解放する 1 回の操作のみで子孫の MEX を増やすことができます。 したがって、最初に欠落している整数を追跡することで、操作が最適に適用されることが保証されます。 DFS により、MEX を O(n) で効率的に計算できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        tree = [[] for _ in range(n)]
        for _ in range(n - 1):
            x, y = map(int, input().split())
            x -= 1
            y -= 1
            tree[x].append(y)
            tree[y].append(x)

        f = [0] * n
        seen = [False] * (n + 2)

        def dfs(v, parent):
            seen[p[v]] = True
            mex = 0
            while seen[mex]:
                mex += 1
            f[v] = mex
            for u in tree[v]:
                if u != parent:
                    dfs(u, v)
            seen[p[v]] = False

        dfs(0, -1)
        sum_f = sum(f)
        max_sum = sum_f

        # Find first vertex along the path from root whose weight blocks next MEX
        path_seen = [False] * (n + 2)
        vertex_to_change = None
        def dfs_find(v, parent):
            nonlocal vertex_to_change
            path_seen[p[v]] = True
            mex = 0
            while path_seen[mex]:
                mex += 1
            if vertex_to_change is None and p[v] != mex:
                vertex_to_change = v
            for u in tree[v]:
                if u != parent:
                    dfs_find(u, v)
            path_seen[p[v]] = False

        dfs_find(0, -1)

        if vertex_to_change is not None:
            p[vertex_to_change] = f[vertex_to_change]
            dfs(0, -1)
            max_sum = max(max_sum, sum(f))

        print(max_sum)

if __name__ == "__main__":
    solve()
```最初の DFS 計算`f(v)`を効率的に使用して、`seen`配列を使用することで、頂点ごとに最初から再計算する必要がなくなります。 2 番目の DFS は、各頂点の重みをルート パスに沿った予想される MEX と比較することにより、操作に最適な頂点を特定します。 再計算中`f`1 つの重みを変更した後は、完全な DFS が 1 つだけ必要なため、効率を維持しながら正確性が保証されます。 の選択`vertex_to_change`合計が増加する場合にのみ操作が実行されるようにします。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | 各 DFS はすべての頂点を 1 回横断します。 MEX 計算の頂点ごとの追加の定数作業 |
 | スペース | O(n) | 隣接リスト、配列`f`、`seen`、 そして`path_seen`|

 合計すると`n`すべてのテスト ケース ≤ 2 * 10^5 で、合計操作は 10^6 未満に留まり、4 秒の制限内に十分収まります。 メモリ使用量は 256 MB 未満のままです。
