 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、`n`各ノードは、バイナリ文字列に従って最初は赤または黒のいずれかに色付けされます。 赤いノードがマークされています`1`そして黒いノード`0`。 タスクは、確率的操作を繰り返し実行することによって、すべてのノードを赤に変えることです。つまり、任意のノードを選択し、均一にランダムに選択された隣接するノードの 1 つの色に再着色します。 私たちの目標は、ツリー全体を赤にするために予想されるこのような操作の最小数を計算することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは、次の方法でツリー構造を提供します。`n-1`エッジと初期カラー文字列。 この制約により、すべてのテスト ケースで合計最大 200,000 個のノードが許可され、線形演算よりも悪いソリューションは除外されます (`O(n log n)`) テストケースごと。 考えられるすべての操作シーケンスをシミュレートする単純なアプローチでは、組み合わせが爆発的に増加するため、ツリー構造と確率ダイナミクスを効率的に活用する戦略が必要です。 

明らかではないエッジ ケースには、すべてのノードが既に赤色であるツリー、単一の黒いノードに複数の赤色の隣接ノードがあるツリー、赤色のノードが分離されているチェーンが含まれます。 不注意なアプローチでは、期待値を考慮せずに黒ノードごとに 1 つの近傍のみをシミュレートする可能性があり、複数の赤の近傍がある場合に誤った推定値が生成される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、予想される値を再帰的に合計して、考えられるすべての操作シーケンスをモデル化しようとします。 単一ノードの場合、1 回の操作で色が変わる確率に基づいて、予想される操作数を計算できます。 しかし、これはすぐに手に負えなくなります。黒ノードごとにその隣接ノードを再帰的に考慮する必要があり、可能性の数が指数関数的に増加するからです。 

重要な洞察は、ツリー上の動的プログラミング アプローチを通じて問題を解決できるということです。 各サブツリーを独立して考慮すると、サブツリーのルートに応じて、そのサブツリーを完全に赤にするために必要な操作の予想数を計算できます。 ノードに対して期待される操作は、その黒の隣接ノードの数のみに依存し、サブツリーをボトムアップで結合できます。 ツリー構造によりサイクルが発生しないため、DFS を実行して期待値を効率的に計算できます。 

これにより、問題は組み合わせ爆発から各ノードでの単純な算術演算による線形トラバースに軽減されます。 ノードの期待される操作は、次の操作で赤に変わる確率の逆数であり、これは赤の近傍ノードの数に比例するため、確率的側面はきれいに崩れます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 木の上のDP | 写真 O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析し、ツリーの隣接リスト表現を構築します。 
2. 各ノードの値を初期化します。`E[node]`これには、このノードをルートとするサブツリーを完全に赤色にするために予想される操作の数が保存されます。 
3. 任意の赤いノードから開始して深さ優先検索を実行します (少なくとも 1 つ存在するため、それがルートとして機能します)。 
4. 各ノードについて`u`アクセスすると、最初にその子の期待される操作を再帰的に計算します。 黒のノードの場合は、赤の隣接ノードの数を数えます。`r`。 このノードで期待される操作は次のとおりです。`1 / (r / degree)`子の予想される操作の合計を加えたものです。 これは、確率を伴うベルヌーイ過程で成功するまでの予想試行回数という性質から来ています。`p`は`1/p`。 
5. DFS が完了すると、ツリー全体の予想される操作数がルート ノードに保存されます。 この値を十分な精度で出力します。 

機能する理由: 各演算を独立したベルヌーイ試行として扱うため、各ノードの期待値は確率演算を正しく考慮しており、ツリー トラバーサルにより、サブツリーからのすべての寄与が二重にカウントされることなく確実にカウントされます。 このボトムアップ計算により、葉から根まで確率が正しく伝播されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        adj = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            adj[v].append(u)

        red = [int(c) for c in s]
        visited = [False] * n

        def dfs(u):
            visited[u] = True
            if red[u]:
                exp = 0
            else:
                exp = 1
            total = 0
            cnt_red_neighbors = sum(1 for v in adj[u] if red[v])
            deg = len(adj[u])
            for v in adj[u]:
                if not visited[v]:
                    total += dfs(v)
            if not red[u]:
                # expected operations = 1 / (probability to turn red in one operation)
                if cnt_red_neighbors == 0:
                    # cannot turn red directly, wait for children
                    exp += total
                else:
                    exp += total / cnt_red_neighbors
            else:
                exp += total
            return exp

        # find any red node to start
        root = next(i for i, x in enumerate(red) if x)
        ans = dfs(root)
        print(f"{ans:.12f}")

if __name__ == "__main__":
    solve()
```コードはまず入力を解析し、隣接リストを構築します。 赤色のノードと訪問ステータスを初期化します。 DFS 関数は、予想される操作をボトムアップで計算します。 黒のノードの場合、赤の近傍に基づいて赤に変わる確率が計算され、サブツリーの予想される操作が追加されます。 赤いノードは即時の操作を必要としませんが、その子からの貢献を蓄積します。 赤色のノードから DFS を開始すると、最終的にはすべての黒色のノードが処理されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | DFS では各ノードが 1 回訪問され、ノードとエッジの合計が線形になるように、その隣接ノードを反復処理します。 |

 ## 特殊なケース

 すべてのノードがすでに赤色の場合、操作は必要ないため、DFS は正しくゼロを返します。 黒のノードに赤の隣接ノードがない場合、ノードが赤になるまで子からの期待される操作を蓄積し、相互確率が安全に計算されることを保証します。 複数の分岐した黒いノードを持つツリーの場合、ボトムアップ集計により、各ノードの期待値が確実に考慮されます。
