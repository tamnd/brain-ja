 ## 解決策
 ## 問題の理解

 同じ長さの複数の配列が与えられており、特別なスコアを最大化するためにそれらを何らかの順序でマージしたいと考えています。 単一の配列のスコアは、そのすべてのプレフィックスの合計を合計することによって計算されます。 たとえば、配列が`[a, b, c]`、そのスコアは`a + (a+b) + (a+b+c) = 3a + 2b + c`。 複数の配列を連結する場合、プレフィックスは配列全体にまたがるため、配列を連結する順序が合計スコアに影響します。 

入力により提供されるのは、`t`テストケース。 各テスト ケースが提供するのは、`n`長さの配列`m`。 タスクは、連結された配列のすべてのプレフィックスの合計として定義される最終スコアが最大化されるように、これらの配列を連結する順序を選択することです。 

制約は、最大で次のものを持つことができることを意味します。`2*10^5`すべてのテスト ケースにわたる要素の合計なので、ソリューションはこれよりも遅くなります。`O(n*m log n)`テストケースごとにタイムアウトになる可能性があります。 これにより、すべてをブルートフォースで列挙することが排除されます。`n!`順列。 エッジ ケースには、同一の要素を持つ配列、非常に大きいまたは非常に小さい要素を持つ配列、要素の合計が負である配列 (ただし、この問題ではすべての要素が正です) が含まれます。 

単純な実装では、単純に配列スコアを個別に合計し、順序を無視することができます。 配列が早く出現するほど、後続のプレフィックス合計からその要素の重みが大きくなるため、これは失敗します。 たとえば、大きな配列を最後に配置すると、最初に配置した場合に比べてその寄与が大幅に減少します。 

## アプローチ

 ブルート フォース アプローチは概念的に単純です。配列のすべての順列を列挙し、各順列を連結し、連結された各配列のスコアを計算して、最大値を選択します。 のために`n`長さの配列`m`、1 つの順列のスコアを計算するには次の時間がかかります`O(n*m)`そしてそこにあります`n!`順列。 これは小規模でも不可能になります`n`8とか10とか。 

重要な洞察は、配列のスコア寄与は、その内部プレフィックスの合計と、他の配列との相対的な位置の両方に依存するということです。 各配列に対して 2 つの値、つまりその合計の合計とそのプレフィックスの合計の合計を事前計算できます。 させて`S`配列内の要素の合計であり、`PS`はそのプレフィックスの合計の合計になります。 配列が位置に現れた場合`k`、その貢献度は`PS + S * (sum of all elements of arrays before it)`。 これは重み付きスケジューリング問題と同等です。各配列の内部プレフィックスの合計と、その合計に既に配置されている要素の合計を乗算した合計が最大になるように配列を順序付けしたいと考えています。 

数学的には、これは配列を合計でソートすることと同じです。`S`降順で。 合計が大きい配列は、後続の配列によって要素に大きな重みが乗算されるため、より早く出現する必要があります。 並べ替え順`S`連結全体にわたる重み付けされた寄与を最大化します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n * m) | O(n*m) | 遅すぎる |
 | 最適 | O(n*m + n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`そして`m`そしてそれを読んでください`n`長さの配列`m`。 
2. 各配列について、次の 2 つの値を計算します。その要素の合計 (`S`) とその接頭辞の合計の合計 (`PS`）。`S`は、その後に配置された配列に影響を与える場合の、この配列の合計の重みを表します。`PS`はそのスタンドアロンの貢献です。 
3. 配列を降順に並べ替えます。`S`。 これにより、より大きな合計を持つ配列が最初に表示され、後続の配列への重み付けされた寄与が最大化されます。 
4.初期化`total_sum`ゼロに、そして`result`ゼロに。 ソートされた配列を反復処理します。 配列ごとに、次の値を追加します。`PS + total_sum * S`に`result`、次に増加します`total_sum`による`S`。 これにより、実行スコアが正しく累積され、前の配列が後の配列の重みをどのように増加させるかを考慮します。 
5. すべての配列を処理した後、`result`このテスト ケースの最大スコアを保持します。 印刷してください。 

機能する理由: このアルゴリズムは、各ステップで、それまでに配置された要素の累計が次の配列の合計に乗算されるという不変条件を維持します。 配列を合計でソートすることで、最大の配列が早期に寄与し、その重みが最大化されるようにします。 各配列の内部プレフィックス合計も 1 回だけ加算されます。 他の順序では、より高いスコアを得ることができません。これは、小さい合計配列を大きい配列の前に配置すると、大きい配列の乗算の寄与が減り、貪欲な並べ替えによって防止されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        arrays = []
        for _ in range(n):
            arr = list(map(int, input().split()))
            total = sum(arr)
            prefix_sum = 0
            running = 0
            for x in arr:
                running += x
                prefix_sum += running
            arrays.append((total, prefix_sum))
        arrays.sort(reverse=True)  # sort by total sum descending
        total_sum = 0
        result = 0
        for total, prefix_sum in arrays:
            result += prefix_sum + total_sum * total
            total_sum += total
        print(result)

if __name__ == "__main__":
    main()
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`そして、各配列の合計とプレフィックスの合計をタプルとして保存します。 ソートはその場で降順に実行され、合計が大きい配列が優先されます。 最終結果は単一パスで計算され、現在の合計が維持されます。 主な微妙な点には、配列ごとにプレフィックスの合計を正しく計算することと、前の配列からの乗算寄与を加算することが含まれます。

## 特殊なケース

 合計が等しい配列の場合、配列の順序は最大スコアに影響しません。 たとえば、2 つの配列`[1,2]`そして`[2,1]`両方の合計は 3 です。並べ替えでは元の順序または任意の順序が保持され、アルゴリズムは引き続き正しいスコアを生成します。`1+2+3+1+2=9`順列とは関係なく。 

単一要素配列の場合、スコアは単純な合計です。
