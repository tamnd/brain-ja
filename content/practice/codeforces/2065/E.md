 ## 問題の理解

 このタスクでは、固定数の文字列を含む指定された長さのバイナリ文字列を構築するように求められます。`0`と`1`のカウント間の最大差が`0`と`1`部分文字列内の s は正確に`k`。 言い換えれば、文字列のすべての可能な連続セグメントの中で、次のセグメントの数の間の最大の絶対差が、`0`とその数`1`は正確でなければなりません`k`。 そのような文字列の構築が不可能な場合は、次のように出力する必要があります。`-1`。 

入力は複数のテスト ケースを提供し、それぞれに 3 つの整数が含まれます。`n`のカウントのために`0`さん、`m`のカウントのために`1`、そして`k`希望する最大残高値を求めます。 すべての合計`n`そして`m`すべてのテストケースで次を超えない`2*10^5`、という意味です`O(n+m)`テストケースごとのソリューションは許容されます。 すべての部分文字列を反復処理するアプローチは、単純な部分文字列の評価が非常に遅いため、非常に遅くなります。`O((n+m)^2)`を超えることになります`10^10`最悪の場合の運用。 

微妙なエッジケースには、次のような状況が含まれます。`k`両方を超える`n`そして`m`、 例えば`n = 3, m = 2, k = 4`。 バランスが 4 の部分文字列を作成することは不可能です。なぜなら、`0`と`1`■ いずれかの文字の合計数を超えることはできません。 もう 1 つの注意が必要なシナリオは、カウントの 1 つがゼロの場合です。 例えば、`n = 5, m = 0, k = 5`繰り返すだけで達成できる`0`ですが、`k = 4`も達成可能ですが、`k = 6`不可能です。 不用意にアプローチすると、これらの制限をチェックできない可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての順列が生成されます。`n` `0`と`m` `1`s、すべての部分文字列のバランス値を計算し、順列が正確に達成されるかどうかを確認します。`k`。 これは原理的には機能しますが、順列の数が階乗的に増加するため、非常に遅すぎます (`O((n+m)!)`)、すべての部分文字列を評価すると二次係数が追加されるため、指定された制約では完全に実行不可能になります。 

より高速なソリューションに対する重要な洞察は、最大のバランス値が連続する同一文字によって達成されるということです。 バランスのある部分文字列が必要な場合`k`、少なくとも必要です`k`連続した`0`または`1`s. 逆に、もし`k`を超える`n`または`m`、そんな走りは作れませんから無理です。 これから、最大で次のサイズのブロックを作成することで文字列を構築できます。`k`、交互に`0`と`1`■ 他の部分文字列のバランスを超えないようにするため。 常に正確なサイズで最大のブロックを最初に配置することによって`k`、すべての部分文字列間の最大バランスが以下であることを保証します。`k`。 残りの文字は、大きなバランスが作成されるのを避けるために、小さなブロックとして追加されます。

 ## アルゴリズムのチュートリアル

 1. 最初に単純な不可能なケースを確認します。 もし`k > max(n, m)`、出力`-1`。 これは、どの部分文字列も 1 文字の合計数を超えることができないためです。`k`達成できない。 
2. Initialize an empty result string and track the remaining`0`と`1`として`n_rem`そして`m_rem`。 
3. どちらか一方の間`n_rem`または`m_rem`が正の場合、次に配置する文字を決定します。 一定のサイズのブロックを配置することから始めます`k`残数が多いキャラ種の場合。 これにより、ストリングの初期段階で最大限のバランスが実現されます。 
4. サイズのブロックを配置したら`k`、そのキャラクターの残りカウントを減らす`k`。 
5. 次のブロックが次のブロックより大きいバランスを持つ部分文字列を作成しないように、反対のタイプの 1 文字を配置します。`k`。 この交互のパターンにより、バランスを超えることが回避されます。 
6. すべての文字が使用されるまで手順 3 ～ 5 を繰り返します。 他のキャラクターの残り数がブロックサイズ未満の場合は、すべてを一度に配置してください。 
7. ブロックを最終的な文字列に結合して出力します。 

機能する理由: このアルゴリズムは、部分文字列が次の値を超えることはできないという不変条件を維持します。`k`ブレークの前に同じ文字が連続すること。 常に正確なサイズのブロックを配置することで、`k`まず残高値`k`を達成し、その後交互に行うことで超過を防止します`k`。 これにより、すべての部分文字列間の最大バランスが正確に保証されます。`k`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        if k > max(n, m):
            print(-1)
            continue
        
        n_rem, m_rem = n, m
        res = []
        flip = 0 if n >= m else 1
        
        while n_rem > 0 or m_rem > 0:
            if flip == 0:
                block = min(k, n_rem)
                res.append('0' * block)
                n_rem -= block
                if m_rem > 0:
                    res.append('1')
                    m_rem -= 1
            else:
                block = min(k, m_rem)
                res.append('1' * block)
                m_rem -= block
                if n_rem > 0:
                    res.append('0')
                    n_rem -= 1
        print(''.join(res))

if __name__ == "__main__":
    solve()
```解決策は、要求された残高が不可能かどうかを確認することから始まります。 次に、どちらの残りカウントが多いかに基づいて、どのキャラクターを優先するかを選択します。 サイズのブロックを構築します`k`先頭のキャラクターの場合は、バランスのオーバーフローを防ぐために、他のキャラクターの単一ユニットをインターリーブします。 すべての文字が使用されるまで、交互のパターンが続きます。
