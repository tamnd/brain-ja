 ## 解決策
 ## 問題の理解

 この問題では、バイナリ文字列と個々のビットを反転するクエリを操作する必要があります。 文字列の場合$t$、 定義する$f(t)$文字列を分割する同一文字の連続ブロックの最小数として。 たとえば、`00110001`、ブロックは`[00][11][000][1]`そして$f(t) = 4$。 各フリップの後、次の合計を計算するように求められます。$f(b)$空ではないすべてのサブシーケンスにわたって$b$現在の文字列の$s$。 最終合計はモジュロで報告する必要があります$998244353$。 

入力により複数のテスト ケースが提供されます。 各テスト ケースは文字列とフリップのシーケンスを提供します。 各反転は累積されるため、1 つのクエリ後の文字列の状態は次のクエリに影響します。 文字列の長さとクエリの数はそれぞれ次の範囲に達します。$2 \cdot 10^5$、すべてのテスト ケースの合計は同じ数値によって制限されます。 これは、サブシーケンスの数が少ないため、サブシーケンスを列挙する単純な解決策では遅すぎることを意味します。$2^n$これは天文学的な数字です$n$近く$10^5$。 

明らかではないエッジ ケースには、すべての文字が同じである文字列が含まれます。 そのような場合には、$f(t) = 1$すべてのサブシーケンスは依然として均一であり、合計に非常に規則的なパターンが生成されます。 もう 1 つの微妙なケースは、1 回のフリップでブロックが分割または結合され、劇的に変化するときに発生します。$f(t)$多くのサブシーケンスに対して。 各クエリの後に合計を最初から再計算する単純なアプローチは非効率的であり、制限時間内に失敗します。 

## アプローチ

 ブルートフォースアプローチは、次のすべてのサブシーケンスを列挙することです。$s$、計算する$f(b)$それぞれを合計してください。 このアプローチは原理的には機能しますが、次のことが必要です。$O(2^n)$クエリごとの操作。次の場合は不可能です。$n$到達できる$2 \cdot 10^5$。 たとえ小さな例であっても、各サブシーケンスを個別に扱うことができないため、これは非現実的になります。 

重要な洞察は、次の観察から得られます。$f(b)$サブシーケンスに 0 から 1、または 1 から 0 への「文字の変化」が含まれる場合にのみ増加します。定義しましょう。$dp[i]$の合計として$f(b)$位置で終わるすべてのサブシーケンスにわたって$i$。 組み合わせ推論を使用すると、それぞれの立場が次のようになります。$i$前のブロックから拡張されるサブシーケンスの数に比例して合計に寄与します。 もし$s[i]$に等しい$s[i-1]$、それを前のサブシーケンスに追加しても、新しいブロックは導入されません。 違う場合は増える$f(b)$前の文字を含むすべてのサブシーケンスに対して 1 ずつ加算されます。 これにより、次の問題が軽減されます。$O(2^n)$に$O(n)$文字列ごとの評価。 

更新の場合、単一の文字を反転すると、隣接する文字との境界にのみ影響します。 させて$cnt$すべてのサブシーケンスの合計を表します。 ひっくり返すと$s[i]$、マージまたは分割の可能性を調整する必要があるだけです。$s[i-1]$そして$s[i+1]$。 2 の累乗を使用して位置を含むサブシーケンスの数を計算すると、クエリごとに一定時間で新しい合計を計算できます。 これにより、問題は、初期計算と組み合わせ恒等を使用した更新の両方を処理する効率的なアルゴリズムに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | 最適 | テスト ケースごとに O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 のべき乗モジュロを事前計算する$998244353$最大文字列長まで。 これらは、特定の位置を含むサブシーケンスの数を表します。 事前計算により、$O(1)$後でアクセスしてください。 
2. 次の最初の合計を計算します。$f(b)$入力文字列の空ではないすべての部分列にわたって$s$。 隣接する文字のペアごとに、異なる場合は次の値を追加します。$2^{i-1}$両方の位置を含むすべてのサブシーケンスが追加のブロックに寄与するため、累計に加算されます。 単一文字のサブシーケンスの場合は、合計を次のように初期化します。$n$各文字だけで 1 つのブロックを形成するためです。 
3. クエリごとに文字を反転する$s[v_i]$、その左右の隣を確認してください。 キャラクターが反転した場合は、影響を受ける境界の寄与を再計算します。 反転によって以前に異なる 2 つの隣接要素がマージされる場合は、対応する 2 のべき乗を減算します。 反転によって同一の近傍が分割される場合は、寄与分を加算し直します。 各更新は 2 つの境界に触れるだけであり、一定時間で実行できます。 
4. フリップを調整した後、新しい総和モジュロを保存します。$998244353$その質問に対する答えとして。 更新された文字列状態を使用して次のクエリの処理を続行します。 

ここで不変なのは、どの瞬間においても、`total`の合計を保持します$f(b)$現在の文字列のすべてのサブシーケンスにわたって。 各フリップは境界にのみ影響し、2 のべき乗の組み合わせカウントは影響を受けるサブシーケンスの数を正確にモデル化するため、アルゴリズムはすべての更新を通じて正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def solve():
    t = int(input())
    max_n = 2 * 10**5
    pow2 = [1] * (max_n + 2)
    for i in range(1, max_n + 2):
        pow2[i] = (pow2[i-1] * 2) % MOD

    for _ in range(t):
        s = list(input().strip())
        n = len(s)
        q = int(input())
        queries = list(map(lambda x: int(x)-1, input().split()))

        total = n  # sum of f(b) for subsequences of length 1
        for i in range(1, n):
            if s[i] != s[i-1]:
                total = (total + pow2[i-1]) % MOD

        res = []
        for idx in queries:
            for j in [idx-1, idx]:
                if 0 <= j < n-1:
                    if s[j] != s[j+1]:
                        total = (total - pow2[j] + MOD) % MOD
            s[idx] = '1' if s[idx] == '0' else '0'
            for j in [idx-1, idx]:
                if 0 <= j < n-1:
                    if s[j] != s[j+1]:
                        total = (total + pow2[j]) % MOD
            res.append(total)
        print(*res)

if __name__ == "__main__":
    solve()
```2 のべき乗の最初の事前計算により、境界からの寄与の定数時間計算が可能になります。 最初の合計では、1 文字を含むすべてのサブシーケンスが考慮され、隣接する文字の差からの寄与が追加されます。 各クエリの更新では、まず変更される境界で古い寄与を削除し、文字を反転してから、新しい寄与を追加します。 Off-by-one エラーは、近傍にアクセスする前に配列の境界を注意深くチェックすることで回避されます。 すべてのモジュロ演算により、合計が範囲内に収まることが保証されます。 

## 実用的な例

 最初のサンプルを使用すると、次のようになります。 

| ステップ | s | 合計 | アクション |
 | --- | --- | --- | --- |
 | イニシャル | 101 | 3 + 2^0 + 2^1 = 10 | 初期合計を計算する |
 | クエリ 1 (フリップ 1) | 001 | 10→7 | 位置 0 と 1 の境界を調整する |
 | クエリ 2 (フリップ 3) | 000 | 7→7 | 右側の境界のみが影響を受けます。合計を更新します |

 これは、隣接する位置のみをチェックする必要があるという不変条件と、2 のべき乗寄与がサブシーケンスの数を正しくモデル化することを裏付けます。 

2 番目のサンプルを使用すると、次のようになります。 

| ステップ | s | 合計 | アクション |
 | --- | --- | --- | --- |
 | イニシャル | 10110 | 5 + 貢献 = 61 | 初期計算 |
 | クエリ 1 (フリップ 1) | 00110 | 61 → 59 | 左境界が処理され、合計が更新されました |
 | クエリ 2 (フリップ 2) | 01110 | 59 → 67 | 境界が更新されました |
 | クエリ 3 (フリップ 3) | 01010 | 67 → 59 | 境界が更新されました |

 このトレースは複数のフリップを順番に表示し、増分更新が正しいことを確認します。 

## 複雑さの分析

| スペース | O(n) | 文字列と 2 のべき乗の配列を格納する |
