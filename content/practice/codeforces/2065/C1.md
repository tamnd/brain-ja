 ## 解決策
 ## 問題の理解

 各位置に最初は固定値が含まれる配列が与えられます。 すべての位置に対して、1 つのオプションの変換が許可されています。つまり、その位置の値を、単一の固定数から減算した結果で置き換えることができます。 これは簡単なバージョンであり、その固定数値が 2 番目の配列の唯一の要素であるため、変換されたすべての値は、各位置に個別に適用された同じ式から得られます。 

ここでのタスクは、インデックスごとに元の値を保持するか、変換された値に置き換えるかを選択した後、結果の配列を左から右に減少しないように配置できるかどうかを決定することです。 

重要な点は、各インデックスには 2 つの可能な最終値があり、インデックスごとに独立して選択できますが、その選択は並べ替え要件を通じて相互作用するということです。 したがって、この構造は要素を再配置することではなく、アレイ全体で一貫した構成を選択することを意味します。 

入力サイズは大きく、テスト ケース全体の配列長の合計は最大 200,000 です。 これにより、すべての組み合わせを試したり、部分的な割り当てごとに実行可能性を繰り返し確認したりする二次アプローチは除外されます。 複数の候補配列のテストケースごとの並べ替えでも問題ありませんが、両方の選択に対する指数関数的または要素ごとのバックトラックは失敗します。 

局所的に「適切な」選択が将来の柔軟性を妨げる場合、微妙な失敗例が発生します。 たとえば、あるインデックスで 2 つの値のうち小さい方を選択すると、後で不可能な制約が強制される可能性があります。 

次のような状況を考えてみましょう。```
a = [5, 1, 4], b = [10]
```各要素はそれ自体になるか、または`10 - a[i]`。 インデックス 0 での貪欲な選択では 5 または 5 が選択される可能性がありますが、初期の別の選択が成功したとしても、後の選択ではシーケンスが不可能になる可能性があります。 これは、以前の決定との互換性を追跡せずに、局所的に最小化または最大化するだけでは各位置を決定できないことを示しています。 

## アプローチ

 ブルートフォースソリューションはすべてを試します$2^n$各要素を変換するかどうかを選択する方法。 構成ごとに、結果の配列がソートされているかどうかを確認します。 これはすべての可能性を列挙しているため、明らかに正しいですが、指数関数的に爆発的に増加し、$n = 30$。 

重要な観察は、各要素には候補値が 2 つだけあり、グローバルな順序制約を維持することのみを考慮しているということです。 これにより、問題は逐次的な実現可能性プロセスに変わります。つまり、各インデックスで、以前に選択した値と少なくとも同じ大きさの値を選択する必要があります。 

各位置では最大 2 つのオプションが提供されるため、各ステップで設定できる最小有効値を貪欲に維持できます。 インデックス時$i$、両方の候補を検討し、それらを並べ替えて、以前に選択した値以上である最小のものを選択します。 どちらも機能しない場合、構成は失敗します。 

これが機能するのは、選択を遅らせても将来の要素に対する制約が増えるだけであり、常に最小の実現可能な値を選択することで、後の位置に最大の余地が残されるからです。

 | 貪欲な選択 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.各要素について$a_i$、その 2 つの可能な値を計算します: 元の値$a_i$、および変換された値$b_1 - a_i$。 

This gives a local choice set of size 2 per position.
 2. Sort these two values so that we can always try the smaller option first.

 This ordering matters because we want to preserve flexibility for later indices.
 3. 変数を維持する`prev`、最終的な配列の前のインデックスとして選択された値を表します。 非常に小さな数値に初期化します。 
4. 配列を左から右に繰り返します。 各インデックスで、2 つの候補値を昇順にチェックします。 
5. ≥ である最小の候補を選択します。`prev`。 

その理由は、ここでより大きな値を使用する有効なソリューションは、将来の実現可能性を損なうことなく、より小さな実現可能なソリューションに置き換えることができるということです。 
6. どちらの候補も≧でない場合`prev`、その場合、非減少順序を維持することは不可能なので、停止して失敗を返します。 
7. すべてのインデックスに値を割り当てることができた場合、配列は許可された操作でソート可能になります。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは次の不変条件を維持します。`prev`プレフィックスを有効に保ちながら、その位置で達成可能な最小値です。 各位置は単一の不等式制約によって次の位置を制限するだけであるため、実現可能な最小値を選択しても、将来のインデックスの解空間が減少することはありません。 ある位置でより大きな有効な値を選択するソリューションは、後の制約をより難しくするか同等にするだけであり、決して簡単にすることはできないため、より小さな有効な値に置き換えることで実現可能性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        x = b[0]

        prev = -10**30
        ok = True

        for v in a:
            c1 = v
            c2 = x - v

            if c1 > c2:
                c1, c2 = c2, c1

            if c1 >= prev:
                prev = c1
            elif c2 >= prev:
                prev = c2
            else:
                ok = False
                break

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```このソリューションは各テスト ケースを個別に処理し、常に単一の値を読み取ります。`b`変換定数として。 要素ごとに、考えられる結果の両方を計算し、実行中のメソッドを使用して非減少条件を強制します。`prev`しきい値。 

微妙な実装の詳細が初期化中です`prev`変換された値が負になる可能性があるため、ゼロではなく非常に小さな数に設定します。 もう 1 つの重要な点は、常に 2 つの候補を並べ替えて、実行可能な最小値を最初に試すことです。

 ## 特殊なケース

 エッジ ケースの 1 つは、変換されたすべての値が元の値より小さくなる場合です。 たとえば、次の場合$b_1$小さいし、$a_i$が大きい場合、変換された値の多くは負になります。 常に比較するため、アルゴリズムはこれを処理します。`prev`、これまでの手順の後ですでにマイナスになっている可能性があります。 

もう 1 つのケースは、早い段階で小さい値を選択すると、後で失敗する場合です。 たとえば、初期のインデックスに変換された値が非常に小さく、元の値がわずかに大きい場合、小さい方を選択すると有効な継続が残らない可能性があります。 貪欲ルールは、将来の制約をブロックする場合ではなく、まだ実現可能な場合にのみ小さい値を選択するため、これを回避します。 

最後のエッジケースは、両方の選択肢が等しい場合です。 その状況では、どちらの分岐も有効であり、順序は実現可能性にとって重要ではないため、アルゴリズムは当然それらを同じように扱います。
