 ## 解決策
 ## 問題の理解

 配列が与えられています`a`そして別の配列`b`。 あらゆるポジションに対して、`a`、私たちには二者択一のような選択肢があります。どちらかが去ることができます。`a[i]`変更しないか、何らかの要素を選択して取得した変換された値に置き換えます`b[j]`とコンピューティング`b[j] - a[i]`。 この決定に関しては、各インデックスは独立していますが、すべての選択肢を選択した後の最終シーケンスは、降順でない順序で並べ替える必要があります。 

重要な問題は、各ポジションには選択肢が 1 つだけではなく、最大で 2 つあることです。`m + 1`可能性: 元の値、および`m`変換された値。 両方なので`n`そして`m`まで可能です`2⋅10^5`複数のテストケースにわたって、位置ごとにすべての可能性を列挙することは不可能です。 すべてのペアを考慮したとしても、限界をはるかに超えた二次関数の動作につながります。 

変換された値が負になるか、元の値より大幅に小さくなる場合、微妙なエッジ ケースが発生します。 各位置で可能な限り最小の値を常に選択するような素朴な貪欲な戦略は、局所的に最適な選択が将来の実現可能性を破壊する可能性があるため、順序付けの制約を破ります。 

たとえば、次の場合`a = [5, 4]`そして`b = [10, 1]`、次に、`a[1] = 5`、選択する`1 - 5 = -4`魅力的に見えますが、有効な変換がブロックされる可能性があります。`a[2]`。 依存関係はローカルではなくグローバルです。 

中心的な課題は、結果のシーケンスが非減少になるように、位置ごとに元の値を選択するか、変換された値を選択するかを決定することです。 

## アプローチ

 ブルートフォースアプローチでは、それぞれを処理します`a[i]`持っているとして`m + 1`候補値を選択し、すべての組み合わせを試します。 指数関数的な性質を無視しても、すべての候補を生成するにはすでにコストがかかります`O(nm)`時間もかかるため、すべての組み合わせを確認することは不可能です。 

より構造化された観察が必要です。変換された値は次の形式になります。`b[j] - a[i]`、これは次のように線形に依存します。`a[i]`の要素ごとにシフトします`b`。 インデックスごとの選択という観点から考えるのではなく、以前に選択した値の実現可能性を維持するという観点から考える必要があります。 

配列を左から右に処理し、シーケンスを非減少に保ちながら、現在の位置に割り当てることができる最小値を追跡するとします。 それぞれについて`a[i]`、値を選択できるかどうかを知る必要があります。`>= prev`。 

位置で`i`、候補者には次の 2 種類があります。 

1. 元の値`a[i]`少なくともそうであれば`prev`。 
2. 変換された値`b[j] - a[i]`、これも少なくとも`prev`、 意味`b[j] >= prev + a[i]`。 

これにより、問題は、存在するかどうかを見つけることに帰着します。`b[j]`不等式を満たすのに十分な大きさです。 並べ替えると`b`、有効な最小値を二分探索できます。`b[j]`。 

各位置で、2 つのオプションの中から実行可能な最小値を選択します。 この貪欲な選択が機能するのは、実行値を可能な限り小さく保つことで、将来の制約を満たす可能性が最大化されるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(nm) | 遅すぎる |
 | 貪欲 + 二分探索 | O(n log m) | O(1) 追加 (並べ替え以外) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列のソート`b`。 適切かどうかを効率的にクエリできるように、並べ替えが必要です。`b[j]`指定されたしきい値に対して存在します。 
2. 変数を初期化する`prev`結果のシーケンス内で最後に選択された最小値を表す、非常に小さな値に設定されます。 
3. 各要素を反復処理する`a[i]`左から右へ。 
4. 維持しようとする`a[i]`満たしていれば変更されない`a[i] >= prev`。 これにより、元の値が保存され、不必要な変換が回避されます。 
5. 変形できるか確認する`a[i]`。 私たちには、`b[j]`そのような`b[j] - a[i] >= prev`、これは以下と同等です`b[j] >= prev + a[i]`。 
6. 二分探索を使用します。`b`最小のインデックスを見つけるには、`b[j] >= prev + a[i]`。 そのようなインデックスが存在する場合は、変換された値を計算します`b[j] - a[i]`。 
7. 両方のオプションが存在する場合は、将来の要素のための余地がより多く残るため、結果として小さい方の値を選択します。 
8. どちらのオプションも有効でない場合は、並べ替えられた制約を満たす継続がないため、すぐに失敗を返します。 
9. アップデート`prev`選択した値に変更して続行します。 

重要な考え方は、各ステップで可能な限り最小の有効なプレフィックス終了値を維持するということです。 

### なぜ効果があるのか

 どのインデックスでも`i`、アルゴリズムは次の不変条件を維持します。`prev`プレフィックスの有効な変換で達成可能な最小値です。`a[1..i-1]`。 すべての制約は「次の値は少なくとも前の値である必要がある」という形式であるため、どのステップでもより大きな値を選択しても、将来の実現可能性が制限されるだけです。 したがって、有効な解決策が存在する場合、常にその解決策が存在します。`prev`あらゆるステップで最小限に。 これにより、貪欲な選択が最適化されます。`prev`できるのは将来のオプションを削減または削除することだけであり、決して拡張することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        b.sort()
        prev = -10**30
        
        ok = True
        
        for x in a:
            best = None
            
            # option 1: keep original
            if x >= prev:
                best = x
            
            # option 2: transform
            # need b[j] >= prev + x
            import bisect
            idx = bisect.bisect_left(b, prev + x)
            if idx < m:
                cand = b[idx] - x
                if best is None or cand < best:
                    best = cand
            
            if best is None:
                ok = False
                break
            
            prev = best
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```実装は並べ替えから始まります`b`二分検索を有効にします。 変数`prev`構築されたシーケンス内で最後に選択された値を追跡します。 の各要素について`a`、有効な値を形成するために考えられる両方の方法、つまり値を変更しないで維持するか、可能な最小値を使用して変換するかを評価します。`b[j]`。 

二分探索ステップは重要な最適化です。 これにより、すべての要素をスキャンしないことが保証されます。`b`あらゆるポジションに。 より小さい有効な候補を選択することで、後の要素の柔軟性が保たれます。 

微妙な実装の詳細が初期化されています`prev`最初の要素が常に制限なく考慮されるように、非常に小さな数に設定します。 もう 1 つは、有効な変換が存在しない場合を慎重に処理することであり、テスト ケースを直ちに終了する必要があります。

 ## 特殊なケース

 最初のエッジケースは次のような場合です。`a`すでに並べ替えられています。 この状況では、各ステップで有効であることが保証されているため、アルゴリズムは常に元の値を維持することを優先します。 以来`prev`増加するか等しくなるだけで、不必要な変換はトリガーされません。 

すべての要素を変換する必要がある場合、別のエッジ ケースが発生します。 たとえば、次のようなとき`a`厳密に減少しており、`b`十分に大きな値が含まれている場合、実現可能性は完全にバイナリ検索の正確さに依存します。 アルゴリズムは、常に最小の有効な変換値を選択することでこれを処理し、単調な構築を保証します。 

最後の重要なケースは、`b[j]`あるインデックスで必要なしきい値を満たします。 その状況では、二分検索は次の位置を返します。`m`、アルゴリズムは正しく早期に終了します。 これにより、すでに不可能なプレフィックスにもかかわらず、後の要素が処理される誤った継続が防止されます。
