 ## 解決策
 ## 問題の理解

 配列内の数値のペアの最小公倍数が準素数となるペアを数えるように求められます。 半素数とは、同じである可能性がある、正確に 2 つの素数の積として表現できる任意の数です。 配列は 2 から 2 までの整数で構成されます。$n$、複数のテスト ケースが提供されます。 テストケースごとに、ペアの数を返す必要があります。$(i, j)$と$i \le j$そのような$\text{lcm}(a_i, a_j)$セミプライムです。 

制約が教えてくれる$n$と同じ大きさにすることができます$2 \cdot 10^5$、との合計$n$すべてのテスト ケースの上限も次のとおりです。$2 \cdot 10^5$。 すべてのペアを単純にチェックするような解決策はすぐに除外されます。$O(n^2)$最悪の場合の運用 - まで$4 \cdot 10^{10}$計算では 2 秒の制限をはるかに超えています。 代わりに、数値の構造と半素数の特性を利用する方法が必要です。 

配列に繰り返しの要素または非常に小さな値が含まれる場合、エッジ ケースが発生します。 たとえば、次のようにすべての値が同じ素数である場合、$[2, 2, 2]$の場合、どのペアの lcm も 2 となり、これは準素数ではありません。 すべてのペアが貢献すると仮定する不用意なアルゴリズムは、過剰にカウントしてしまいます。 もう 1 つの注意が必要なケースは、2 つの異なる数値の lcm の結果が (3, 3) の 9 のように素数の 2 乗になる場合です。これは準素数ですが、実装が異なる素数のみを考慮している場合は見逃しやすいです。 

## アプローチ

 ブルートフォース手法では、考えられるすべてのペアを反復処理します。$(i, j)$、 lcm を計算し、それが準素数であるかどうかを確認し、準素数である場合はそれをカウントします。 これは正しく動作しますが、時間計算量は次のとおりです。$O(n^2)$テストケースごとに、これは実行不可能です$n \sim 2 \cdot 10^5$。 

重要な洞察は、次のことを認識することで得られます。$\text{lcm}(a_i, a_j)$までの値しか取ることができません$n$なぜならそれぞれ$a_i \le n$。 これにより、以下のすべての準素数を事前計算することができます。$n$改良されたエラトステネスのふるいを効率的に使用します。 どの数値が準素数であるかがわかれば、配列要素を度数表にマッピングし、ふるいと多重度カウントの組み合わせを使用して有効なペアをカウントし、明示的なペアごとの lcm 計算を回避できます。 具体的には、どの数値が準素数であるかを事前に計算すると、配列を反復処理して、準素数 lcm を形成できる値のみを考慮することができます。 ペアの寄与は、ネストされたループではなくカウント式を介して計算できます。

 ## アルゴリズムのチュートリアル

 1. すべての素数を可能な最大値まで事前計算します。$n$ふるいを使って。 このステップは$O(n \log \log n)$。 素数のリストが得られ、素数チェックを高速に行うことができます。 
2. までのすべての準素数を生成します。$n$。 すべての素数を反復処理する$p \le \sqrt{n}$、それぞれについて$p$、素数を掛けます$q \ge p$そのような$p \cdot q \le n$。 これらの数値をブール配列に保存するか、O(1) メンバーシップ クエリ用に設定します。 これにより、lcm の結果が準プライムかどうかをすぐに確認できるようになります。 
3. テスト ケースごとに、周波数配列を構築します。`count[x]`各数値が何回あるかを記録します$x$入力配列に表示されます。 これにより、ペアのインデックス作成から多重度による値のペアのカウントまでの問題が軽減されます。 
4. すべての数値のペアを反復処理します。$(u, v)$どこ$u \le v$そして両方が配列に現れます。 次を使用して lcm を計算します。$\text{lcm}(u, v) = u \cdot v // \gcd(u, v)$。 この lcm が準素数の場合 (事前計算されたセットを確認してください)、ペア数の寄与を追加します。 もし$u = v$、貢献度は$\text{count}[u] \cdot (\text{count}[u] + 1) // 2$; それ以外の場合は、$\text{count}[u] \cdot \text{count}[v]$。 
5. テスト ケースの合計数を出力します。 

不変条件は、準素数を事前計算し、頻度カウントを使用することで、各インデックス ペアを反復することなく、すべての有効なペアが 1 回だけカウントされることを保証し、効率を達成しながら正確さを維持することです。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

MAX_N = 2 * 10**5 + 5

# Sieve to find primes up to MAX_N
is_prime = [True] * MAX_N
is_prime[0] = is_prime[1] = False
for i in range(2, int(MAX_N**0.5) + 1):
    if is_prime[i]:
        for j in range(i*i, MAX_N, i):
            is_prime[j] = False
primes = [i for i, val in enumerate(is_prime) if val]

# Precompute semi-primes
is_semi_prime = [False] * MAX_N
for i, p in enumerate(primes):
    for q in primes[i:]:
        val = p * q
        if val >= MAX_N:
            break
        is_semi_prime[val] = True

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    count = [0] * MAX_N
    for x in a:
        count[x] += 1
    
    nums = [i for i in range(2, n+1) if count[i] > 0]
    res = 0
    for i, u in enumerate(nums):
        for v in nums[i:]:
            lcm = u * v // math.gcd(u, v)
            if lcm < MAX_N and is_semi_prime[lcm]:
                if u == v:
                    res += count[u] * (count[u] - 1) // 2 + count[u]  # i <= j
                else:
                    res += count[u] * count[v]
    print(res)
```このソリューションでは、まず素数と準素数を事前計算して、定数時間のメンバーシップ チェックを可能にします。 頻度配列により、ペアごとの比較の繰り返しが回避され、一意の配列値に対するネストされたループにより、各 lcm が 1 回だけチェックされることが保証されます。 取り扱っております$i = j$組み合わせとセルフペアリングを計算することで正しく認識されます。
