 ## 問題の理解

 正の整数の配列が与えられ、すべての連続するサブ配列は、そのサブ配列内のすべての要素の最小公倍数とそのエンドポイント インデックスの積という 2 つの要素に基づく値を提供します。 タスクは、単一のグローバル値を計算することではなく、サブ配列間隔に制限される多くのクエリに答えることです。 クエリ間隔ごとに$[l, r]$、その中のすべてのサブサブ配列を考慮し、その最小公倍数を計算し、インデックスエンドポイントで乗算し、すべてを合計する必要があります。 

したがって、各クエリは全体の合計を要求します$[L, R]$完全に含まれている$[l, r]$、ここで、セグメントの寄与は$\text{LCM}(a_L, \dots, a_R) \cdot L \cdot R$、大きな素数を法として計算されます。 

構造が緻密です。 クエリごとに合計を行っています$\Theta((r-l+1)^2)$各サブ配列には、潜在的に長いセグメントにわたる LCM 計算が含まれます。 と$n, Q \le 10^5$、セグメントごとまたはクエリごとに LCM を再計算するアプローチは、すぐに遅すぎます。 

LCM の動作から、いくつかの微妙なエッジ ケースがすぐに現れます。 まず、サブ配列の小さな変更でも LCM が大幅に増加する可能性があります。 たとえば、$[2, 3, 4]$、セグメントを拡張するときに LCM が 2 から 12 にジャンプするため、単純なプレフィックス集約は線形に動作しません。 第 2 に、LCM は等式パターンではなく最大素指数に敏感であるため、値を繰り返しても問題は単純化されません。 第三に、答えはインデックスの乗算によって決まります。$L \cdot R$つまり、位置を追跡せずに純粋に値ベースの寄与を事前計算することはできません。 

## アプローチ

 ブルートフォースアプローチは文字通り定義に従います。 クエリごとに、すべてのサブ配列を列挙します。$[L, R]$、要素を反復処理してセグメントの LCM を計算し、次の値を乗算します。$L \cdot R$、蓄積していきます。 LCM が前のエンドポイントから増分的に維持される場合でも、各拡張機能には gcd 操作により少なくとも対数係数のコストがかかるため、各クエリは大まかになります$O((r-l)^2 \cdot \text{cost of LCM update})$。 最悪の場合こうなります$O(n^3)$、これは許容範囲をはるかに超えています。 

重要な観察は、LCM が非常に構造化された方法で単調であるということです。セグメントを右に拡張すると、LCM は変わらないか、より高い素数べき乗を組み込むことによって増加します。 各拡張は、新しい要素が現在の LCM にまだ存在していない素数パワーに寄与する場合にのみ LCM を変更できます。 

これは、古典的なオフライン変換を示唆しています。サブ配列ごとに LCM を再計算する代わりに、開始インデックスごとに維持します。$L$拡張したときの現在の LCM の値$R$ただし、それぞれの個別の LCM 値が最大間隔に関連付けられるように更新を圧縮します。$R$。 これにより、問題は、LCM が一定である範囲にわたる寄与の集計に変わります。 

範囲クエリを効率的に管理するために、右のエンドポイントをスイープしてすべてのサブ配列の寄与を事前計算します。 それぞれについて$R$で終わる部分配列のすべての個別の LCM 値を維持します。$R$、開始位置ごとにグループ化されています。 LCM は素数指数の最大値が変化する場合にのみ変化するため、それぞれの「ブレークポイント」の構造を維持できます。$R$これは、貢献ドメインを減少させてセグメントのスタックを維持するのと同様です。 

次に、貢献度をグローバル構造に蓄積し、次のようにインデックス付けします。$(L, R)$ただし、LCM によって重み付けされます。 クエリでは部分行列の合計が求められるため、$L \cdot R \cdot \text{LCM}$、コンポーネントを分離します。各更新が四角形の加算に対応するインデックス上の 2D 寄与グリッドを維持し、プレフィックスの合計を介してクエリに答えます。 

これは、それぞれのメンテナンスに基づいた解決策につながります。$R$セグメントのリスト$[L_1, L_2)$、$[L_2, L_3)$, ... ここで、各セグメントは、で終わる部分配列に対して同じ LCM を共有します。$R$。 各セグメントは定数値の倍に寄与します$L$、プレフィックスの蓄積が可能$L$。

 ## アルゴリズムのチュートリアル

 右端点を固定し、そこで終了するサブ配列のすべての可能な LCM 状態を維持し、左端点の互いに素なセグメントに圧縮することによって、寄与を処理します。 

1. 反復する$R$1から$n$、それを現在検討している部分配列の正しい境界として扱います。 これにより、すべてのサブ配列がその正しいエンドポイントが処理されるときに正確に 1 回カウントされるようになります。 
2. ペアのリストを維持する$(\ell, \text{lcm})$すべてが左端点のセグメントで始まり、部分配列の最小公倍数が次で終わることを表します。$R$は一定です。 当初、このリストには次のものだけが含まれています$(R, a_R)$これは、長さ 1 の部分配列の LCM がその要素と等しいためです。 
3. 以前の状態を次から拡張します$R-1$に$R$組み合わせることで$a_R$既存のすべての LCM 値を使用して$\text{lcm}(x, a_R)$。 これらの新しい値を計算するときに、等しい LCM で隣接するセグメントをマージし、リストが圧縮されたままになるようにします。 
4. マージ中、2 つのセグメントが同じ LCM を生成する場合は常に、それらを 1 つのより大きな間隔に統合します。 LCM が等しいということは、この正しいエンドポイントに対してすべての中間開始が同じように動作することを意味するため、これは非常に重要です。 
5. セグメントごとに$[\ell_i, \ell_{i+1})$LCM値あり$v_i$、固定に対するその合計寄与度を計算します。$R$として$$v_i \cdot R \cdot \sum_{L=\ell_i}^{\ell_{i+1}-1} L$$内部和は等差数列の公式を使用して計算されます。 

1. 貢献をプレフィックス構造に保存します。$L, R$, そのため、クエリ四角形は$[l, r]$の部分行列の合計として答えることができます。$O(1)$または$O(\log n)$実装に応じて。 
2. 事前に計算された 2D プレフィックス合計を使用して各クエリに答えます。 

重要なアイデアは、すべてのサブ配列を明示的に追跡するのではなく、サブ配列が各サブ配列でどのように終了するかを追跡することです。$R$左側の境界空間を同一の LCM 値で分割します。 

### なぜ効果があるのか

 固定右エンドポイントの場合$R$、で終わるすべてのサブ配列$R$開始インデックスによってのみ決定されます。 左に移動すると、最小指数が新しい最大値を導入する要素に遭遇した場合にのみ最小公倍数が変化します。 これは、LCM のオーバー スタートが連続セグメントにわたって区分的に一定であることを意味します。$L$。 これらのセグメントは互いに素であり、すべての有効な開始部分をカバーしているため、これらを合計すると、次で終了するすべてのサブ配列の寄与が正確に再構築されます。$R$。 全体を集約して$R$すべてのサブ配列を 1 回だけカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def lcm(x, y):
    import math
    return x // math.gcd(x, y) * y

n = int(input())
a = list(map(int, input().split()))
q = int(input())
queries = [tuple(map(int, input().split())) for _ in range(q)]

# 2D prefix over contributions
pref = [[0] * (n + 2) for _ in range(n + 2)]

for r in range(1, n + 1):
    cur = []
    cur.append((r, a[r - 1]))

    for l, val in prev:
        nv = lcm(val, a[r - 1])
        if cur and cur[-1][1] == nv:
            cur[-1] = (cur[-1][0], nv)
        else:
            cur.append((l, nv))

    prev = cur

    for i in range(len(cur)):
        l1 = cur[i][0]
        l2 = cur[i + 1][0] if i + 1 < len(cur) else r + 1
        v = cur[i][1]

        add = v * r % MOD

        pref[r][l1] = (pref[r][l1] + add * (l1 + l2 - 1) * (l2 - l1) // 2) % MOD

# build 2D prefix
for i in range(1, n + 1):
    for j in range(1, n + 1):
        pref[i][j] = (pref[i][j] + pref[i - 1][j] + pref[i][j - 1] - pref[i - 1][j - 1]) % MOD

for l, r in queries:
    ans = (pref[r][r] - pref[l - 1][r] - pref[r][l - 1] + pref[l - 1][l - 1]) % MOD
    print(ans)
```このコードは、右側のエンドポイントごとに寄与を構築し、左側のエンドポイントにわたって LCM 状態を圧縮するという考えに従っています。 の`prev`構造体には、前のインデックスで終わるサブ配列の LCM 値のセグメンテーションが格納されます。 新しい位置ごとに、新しい要素で LCM を計算し、等しい値を結合することによって、以前のすべてのセグメントを拡張します。 

の`pref`テーブルは、各セルが$(l, r)$右端が$r$そしてその左端点が少なくとも$l$。 最終的なクエリ抽出では、この 2D 構造に対して包含/除外を使用します。 

左セグメントの合計は連続する整数の合計の公式を使用して計算されるため、算術合計を計算するときは整数の除算に注意する必要があります。
