 ## 解決策
 ## 問題の理解

 各集団農場が生産するのは、`k[i]`穀物の袋。 お問い合わせの場合`(l, r, x, m)`の農場のみを考慮します。`l`を通して`r`。 農場が供給する場合`m`すべての家族に同じ整数のバッグを与えた後に残るバッグの数は正確に`k[i] mod m`。 

クエリは、その間隔内で正確にいくつのファームが残っているかを尋ねます。`x`。 以来`0 <= x < m`、これはインデックスをカウントすることに相当します。`i`で`[l, r]`満足のいく`k[i] mod m = x`。 

公式の制約は次のとおりです`n, q <= 5 * 10^4`、`k[i] <= 5 * 10^4`、 そして`m <= 5 * 10^4 + 1`、制限時間は1.5秒です。 境界は、クエリごとにすべての要素を処理することを排除できるように、意図的に十分な大きさに設定されています。`2.5 * 10^9`残りの演算。 同時に、価値観は、`k[i]`のみに制限されます`5 * 10^4`そして、その 2 番目の境界が、より高速な解決策への鍵となります。 

直接実装では誤って処理される可能性のあるエッジケースがいくつかあります。 まず、生産ゼロが有効です。 例えば、```
1 1
0
1 1 0 1
```答えがあります`1`、 なぜなら`0 mod 1 = 0`。 すべての生産値が正であると想定する実装では、ファームが誤って除外されてしまいます。 

ケース`m = 1`も特別です。 すべての整数には 1 を法とした余りが 0 あります。 したがって```
3 1
4 7 0
1 3 0 1
```生産しなければならない```
3
```よくある間違いは、可能な値を反復処理することです`x, x + m, ...`そして、ゼロを見逃したり、単一の剰余を誤って処理したりして、誤って上限を排他的なものとして扱ってしまいます。 

もう 1 つの境界ケースは、可能な最大値自体が剰余クラスのメンバーである場合です。 のために```
3 1
2 5 10
1 3 0 5
```答えは`1`、なぜなら、`5`そして`10`5 を法とした余りが 0 なので、実際の正しい出力は次のようになります。`2`。 などの不注意な進行ループ`range(x, max_value, m)`その前に止まるだろう`max_value`そして戻る`1`。 

## アプローチ

 ブルート フォース ソリューションは、定義に直接準拠します。 すべてのクエリに対して、次のことを繰り返します。`k[l-1:r]`、計算します`k[i] % m`と等しい場合、答えをインクリメントします。`x`。 すべてのファームが 1 回だけ検査され、条件がクエリの条件と正確に一致するため、これは明らかに正しいです。 

問題は最悪の場合の操作数です。 と`n = q = 50000`、クエリは配列全体をカバーできるため、アルゴリズムは大まかに実行できます。`50000 * 50000 = 2.5 * 10^9`残りのチェック。 これは 1.5 秒の制限が許容する値をはるかに超えています。 

有益な観察は、`k[i]`それ自体は小さいです。 クエリではファームの正確な値はあまり考慮されず、その値が等差数列に属しているかどうかのみが考慮されます。`x, x + m, x + 2m, ...`。 

もし`m`が大きい場合、この数列には少数の値しか含まれていないため、`k[i]`せいぜい`50000`。 すべての正確な値の位置を保存し、二分探索を使用して、各値が何回出現するかを数えることができます。`[l, r]`。 

たとえば、`m = 1000`そして`x = 7`、可能な唯一の生産値は次のとおりです。`7, 1007, 2007, ...`。 せいぜい約`50000 / 1000 = 50`彼らのうち。 したがって、係数が大きいと、候補値の短いリストが得られます。 

小さい`m`逆の動作をします。 のために`m = 2`、進行には多くの値が含まれているため、すべてをチェックするとコストがかかります。 しかし、明確な小さな係数は少数しか存在しません。 あらゆる小さなものを処理できます`m`配列全体を 1 回スキャンし、各剰余モジュロの位置リストを構築することで、一緒に`m`。 その後、これを含むすべてのクエリは、`m`二分探索で答えることができます。 

これにより、係数に基づいて平方根分解が行われます。 しきい値を選択してください`B`その周り`sqrt(50000)`、 だいたい`224`。 のために`m <= B`、配列の 1 回のスキャンでそのモジュラスを処理します。 のために`m > B`、各クエリを処理するには、その可能な値を列挙します。 双方とも大まかなパフォーマンス`O(sqrt(50000))`クエリまたはモジュラス グループごとに動作します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(nq)`|`O(1)`入力のほかに | 遅すぎる |
 | 最適 |`O(nB + q(K/B) log n)`|`O(n + K)`| 承認済み |

 ここ`K = max(k[i])`、 そして`B`近くで選ばれます`sqrt(K)`。 与えられた制限を考慮すると、両方の主な項はおよそ数千万の単純な操作になります。 

## アルゴリズムのチュートリアル

 1. 配列を読み取ってビルドする`positions[v]`、すべてのインデックスが含まれます。`k[i] = v`。 配列は左から右にスキャンされるため、インデックスを昇順で格納します。 
2. 係数に基づいてクエリをグループ化します。`m`小さいか大きいかです。 しきい値を使用する`B = 224`。 小さい係数はまとめて処理され、大きい係数は個別に応答されます。 
3. クエリで実際に発生する小さなモジュラスごとに、配列を 1 回スキャンし、各インデックスを対応するバケットに配置します。`k[i] % m`。 結果のバケット`buckets[x]`剰余を剰余とするインデックスが正確に含まれます`m`は`x`。 
4. 係数が小さいすべてのクエリについて、対応する剰余バケットを取得し、2 つのバイナリ検索を使用してインデックスをカウントします。`[l, r]`。`bisect_left`少なくとも最初の位置を見つける`l`、 その間`bisect_right`より大きい最初の位置を見つけます`r`。 その違いはまさに一致する農場の数です。 
5. 係数が大きいすべてのクエリについて、考えられる生成値を列挙します。`x, x + m, x + 2m, ...`まで`max(k)`。 それぞれの値について`v`、 使用`positions[v]`およびその出現を数える 2 つの二分探索`[l, r]`、それらの数を合計します。 
6. 元のクエリの順序で回答を出力します。 小さいモジュールと大きいモジュールの処理は異なるグループで発生するため、クエリ インデックスを保持することが必要です。 

### なぜ効果があるのか

 固定モジュラスの場合`m`、農場はまさに`x`生産価値がセットに属する場合に限り、残りのバッグ`{x + tm | t >= 0}`。 小型用`m`の場合、残りのバケットにはこの条件を満たすすべてのインデックスが明示的に含まれるため、バケットの範囲カウントによってクエリの答えが正確に得られます。 大型用`m`、同じ等差数列内のすべての値を列挙すると、考えられるすべての生成値がカバーされますが、他の値はカバーされません。 正確な値の位置リストは、要求された間隔内の一致するインデックスを正確にカウントします。 したがって、両方のブランチは同じ数学的セットをカウントしますが、表現方法が異なるだけです。 

## Python ソリューション```python
import sys
from bisect import bisect_left, bisect_right

input = sys.stdin.readline

MAX_K = 50000
B = 224

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    positions = [[] for _ in range(MAX_K + 1)]
    for i, value in enumerate(a, 1):
        positions[value].append(i)

    queries = []
    small_mods = set()

    for qi in range(q):
        l, r, x, m = map(int, input().split())
        queries.append((l, r, x, m))
        if m <= B:
            small_mods.add(m)

    answers = [0] * q

    small_queries = [[] for _ in range(B + 1)]
    large_queries = []

    for qi, (l, r, x, m) in enumerate(queries):
        if m <= B:
            small_queries[m].append((qi, l, r, x))
        else:
            large_queries.append((qi, l, r, x, m))

    # Process every small modulus that occurs in the input.
    for m in small_mods:
        buckets = [[] for _ in range(m)]

        for i, value in enumerate(a, 1):
            buckets[value % m].append(i)

        for qi, l, r, x in small_queries[m]:
            bucket = buckets[x]
            left = bisect_left(bucket, l)
            right = bisect_right(bucket, r)
            answers[qi] = right - left

    # Process large moduli query by query.
    max_value = max(a) if a else 0

    for qi, l, r, x, m in large_queries:
        total = 0
        value = x

        while value <= max_value:
            pos = positions[value]
            left = bisect_left(pos, l)
            right = bisect_right(pos, r)
            total += right - left
            value += m

        answers[qi] = total

    sys.stdout.write("\n".join(map(str, answers)))

if __name__ == "__main__":
    solve()
```の`positions`この構造は、アルゴリズムの大きな係数の部分に対応します。`positions[v]`元の配列を左から右にスキャンするときにインデックスが追加されるため、自動的にソートされます。 

クエリのグループ化により、2 つの複雑さの領域が分離されます。 小さな係数は、クエリで使用される回数に関係なく 1 回処理されますが、大きな係数では完全な剰余構造を構築することが正当化されないため、これらのクエリは可能な実稼働値のみを列挙します。 

小さな弾性率のループにより、`m`バケットを作成し、配列を 1 回スキャンします。 各インデックスは正確に 1 つのバケットに入ります。`value % m`。 なぜなら`x < m`入力、アクセスによって保証されます`buckets[x]`は常に有効です。 

2 つのバイナリ検索は意図的に異なっています。`bisect_left(bucket, l)`少なくとも次の位置に格納されている最初のインデックスを返します。`l`、 その間`bisect_right(bucket, r)`より厳密に大きい最初の位置を返します`r`。 彼らの差は満足できる順位を数えます`l <= position <= r`、包括的なクエリ間隔と一致します。 

大きな係数の場合、進行は次から始まります。`x`ではありません`0`。 剰余を含めることができる値`x`まさに`x + tm`。 ループは使用します`<= max_value`、 それよりも`< max_value`、そのため、配列の最大値に等しい実稼働値が誤ってスキップされることはありません。 

Python の整数はオーバーフローせず、保存されているすべてのインデックスは最大でも`50000`。 実装上の主な懸念事項は実行時間です。そのため、しきい値により、大きな係数を求めて配列全体を繰り返しスキャンすることが回避されます。

## 複雑さの分析

 しましょう`K = max(k[i])`、 と`K <= 50000`、そしてさせてください`B = 224`。 

| 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(nB + q(K/B) log n)`| それぞれの小さなモジュラスは配列を 1 回スキャンしますが、大きなクエリは最大で 1 回しかチェックしません。`K/B + 1`候補値 |

 多くてもあります`B`係数が小さいため、係数の小さいスキャンのコストは最大でも約`224 * 50000 = 11.2 million`アレイの訪問。 大きな弾性率は、`224`、したがって、クエリは約よりも少ないものを調べます`224`候補値。 と`50000`クエリ、これもまた次の順序です`11 million`それぞれ二分探索を使用した候補チェック。 これは、指定された境界と互換性があります。`2.5 * 10^9`ブルートフォースによるチェックが必要です。

    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    positions = [[] for _ in range(MAX_K + 1)]
    for i, value in enumerate(a, 1):
        positions[value].append(i)

    queries = []
    small_mods = set()

    for qi in range(q):
        l, r, x, m = map(int, input().split())
        queries.append((l, r, x, m))
        if m <= B:
            small_mods.add(m)

    answers = [0] * q
    small_queries = [[] for _ in range(B + 1)]
    large_queries = []

    for qi, (l, r, x, m) in enumerate(queries):
        if m <= B:
            small_queries[m].append((qi, l, r, x))
        else:
            large_queries.append((qi, l, r, x, m))

    for m in small_mods:

        for i, value in enumerate(a, 1):
            buckets[value % m].append(i)

                bisect_right(bucket, r) -
                bisect_left(bucket, l)

        value = x

            total += (
                bisect_right(pos, r) -
                bisect_left(pos, l)
            )
            value += m

        answers[qi] = total

 ## 特殊なケース

 ゼロ生産の場合は、次のことを考慮してください。```
1 1
0
1 1 0 1
```アルゴリズムは分類します`m = 1`小さな係数として、1 つの剰余バケットを作成し、位置を配置します。`1`バケツに`0`なぜなら`0 % 1 = 0`。 クエリはポジション間のバケットを検索します`1`そして`1`、1 つの位置を見つけるので、出力は次のようになります。`1`。 

のために`m = 1`、 考慮する```
3 1
4 7 0
1 3 0 1
```唯一可能な残りはゼロです。 前処理中に、位置が`1`、`2`、 そして`3`全員が同じバケットに入ります。 バイナリ検索は完全な間隔をカバーし、次の結果を返します。`3`。 これにより、モジュロ 1 の特殊なコードが回避されます。 

等差数列の正しい終点については、次のように考えます。```
3 1
2 5 10
1 3 0 5
```関連する生産値は次のとおりです。`0, 5, 10, ...`。 ここでは大きな係数の分岐は使用されません。`m = 5`ただし、同じ包括的累進原則が小係数バケットにも適用されます。`2`そして`3`どちらも剰余が 0 なので、結果は次のようになります。`2`。 排他的な上限を使用する実装では、誤って値が失われる可能性があります。`10`。 

弾性率が大きい場合は、次のことを考慮してください。```
5 1
