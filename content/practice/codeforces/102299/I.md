 ## 解決策
 ## 問題の理解

 (N) 個のペア ((p_i,f_i)) があります。 ペアに到達すると、プレーヤーは (p_i) ルーブルを受け取り、すぐに停止して (f_i) ルーブルを支払うことができます。 (f_i) が負の場合、それを支払うことは追加のお金を受け取ることを意味します。 プレーヤーが最後のペアに到達した場合は、そこで停止することが必須です。 

カジノはゲームの開始前にすべてのペアの順序を選択します。 次に、プレーヤーは可能な限り最適な停止ポイントを選択します。 私たちのタスクは、プレーヤーの最適な最終ゲインを可能な限り小さくする順序を選択し、その最小ゲインを出力することです。 

固定順序の場合、最初の (i) ペアがプレイされたと仮定します。 プレイヤーが正確にそこで停止した場合、彼女の利益は次のとおりです。 

[
 p_1+p_2+\cdots+p_i-f_i。 
]

 プレーヤーは、最後の停止位置も含め、任意の停止位置を選択できます。 したがって、固定順列の場合、プレーヤーの最適ゲインは次のようになります。 

[
 \max_{1\le i\le N}\left(\sum_{j=1}^{i}p_j-f_i\right)。 
]

 したがって、問題は純粋な順序付けの問題になります。これらの接頭辞式の最大値が最小になるようにペアを配置します。 

(N) が (10^5) までの場合、順列を列挙することは不可能です。 二次アルゴリズムでさえ、最大のケースではすでに約 (10^{10}) 個の演算を実行しており、利用可能な時間をはるかに超えています。 (O(N\log N)) を与えるソートベースのソリューションが必要です。 

誤った解決策を引き起こしやすい特殊なケースがいくつかあります。 負の値 (f_i) は文字通りに処理する必要があります。 例えば、```
1
1 -2
```プレイヤーは (1) を受け取り、次に別の (2) を受け取ります。したがって、答えは (1) や (-1) ではなく (3) になります。 料金が常に負ではないことを前提とした解決策は、これを誤ります。 

最後のペアもゲームの説明では特別ですが、公式では別個に扱う必要はありません。 例えば、```
1
0 1
```プレイヤーに (1) の支払いを強制するので、答えは (-1) になります。 式 (0-1=-1) はすでにこれを捉えています。 最後のペアを、プレイヤーが手数料を単に無視できるかのように扱うと、間違った答えが生成されます。 

(p_i) のゼロ値は許可されます。 のために```
2
0 1
3 4
```示されている順序ではプレフィックス値 (-1) と (-1) が与えられるため、答えは (-1) になります。 すべてのラウンドで蓄積量を厳密に増加させることに依存する証明や実装は無効になります。 

最後に、等しい (f_i) 値には特別なタイブレーク ルールは必要ありません。 等しい (f_i) 値間の任意の順序が最適です。 例えば、```
3
2 5
1 5
3 5
```にはプレフィックス値 (-3、-2、1) が任意の順序で含まれているため、答えは (1) になります。 

## アプローチ

 直接的なアプローチは、(N) 個のペアのすべての順列を試すことです。 各順列について、左から右にスキャンし、累積された (p) を維持し、(prefix-f_i) の最大値を計算します。 これは、考えられるすべての停止位置に対して最適なプレーヤーが利用できるゲインを正確に評価し、最適なゲインを採用するため、正しいです。 ただし、(N!) 個の順列があり、それぞれの評価に (O(N)) 時間がかかり、(O(N\cdot N!)) 個の演算が行われます。 (N=10) の時点でも、検査対象の基本ポジションはすでに約 3,600 万件あり、(N=11) ではこれが約 4 億 4,000 万件に増加します。 (N=10^5) では、このアプローチは遠隔的には実現可能ではありません。 

有益な観察は、プレーヤーの利益がまさにスケジュール目標の形をしているということです。 (p_i) をジョブ (i) の処理時間、(f_i) をその期限と考えてください。 最初の (i) ジョブを処理した後の完了時間は (p) のプレフィックスの合計であり、遅延は

 [
 C_i-f_i。 
]

 最大遅延を最小限に抑える必要があります。 古典的な交換の議論では、ジョブは期日の降順でない順序で処理されるべきであると言われています。これは、(f_i) を増加させることによってペアをソートすることを意味します。 

理由は、スケジューリング用語に依存せずに直接導き出すことができます。 2 つの隣接するペア (a) と (b) の順序が現在間違っていると仮定します (f_a>f_b)。 (S) をこれら 2 つのペアの前に累積した (p) とします。 (a,b) の順序で、関連する 2 つの値は次のとおりです。 

[
 S+p_a-f_a
 ]

 そして

 [
 S+p_a+p_b-f_b。 
]

 (f_a>f_b) および (p_b\ge0) であるため、2 番目の値は常に少なくとも最初の値になります。 したがって、このペアは貢献します

 [
 S+p_a+p_b-f_b
 ]

 最大限に。 

次に、それらを (b,a) の順序に入れ替えます。 2 つの値は次のようになります。 

[
 S+p_b-f_b
 ]

 そして

 [
 S+p_b+p_a-f_a。 
]

 (p_a\ge0) ため、最初の値は古い最大値より大きくありません。 (f_a>f_b) であるため、2 番目の値は大きくなりません。したがって、(f_a) を減算しても、(f_b) を減算した場合よりも小さくなるだけです。 したがって、反転を交換しても、プレーヤーの最適なゲインを増やすことはできません。 

すべての反転を繰り返し削除すると、(f_i) の増加によってソートされたペアが残り、答えが悪化することはありません。 したがって、この並べ替え順序は最適です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N\cdot N!)) | (O(N)) | 遅すぎる |
 | 最適 | (O(N\log N)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのペア ((p_i,f_i)) を読み取ります。 相対的な順序を決定する唯一のプロパティは (f_i) であるため、各ペアをそのまま保持し、2 番目のコンポーネントで並べ替えることができます。 
2. (f_i) を増加させてペアをソートします。 交換引数は、大きい (f) が小さい (f) の前に出現する場合は常に、これら 2 つのペアを交換しても、プレーヤーが利用できる最大ゲインを増やすことはできないことを示しています。 このプロセスを繰り返すことで、正確にソートされた順序が得られます。 
3. ソートされたペアを左から右にスキャンし、維持します。`prefix`, これまでに受け取った合計金額。 ペア ((p,f)) を追加した後、プレーヤーはこのペアで停止し、`prefix - f`。 
4. すべての値の最大値を維持する`prefix - f`。 あらゆる可能な停止位置が考慮されているため、この最大値は、選択した順序に対するプレーヤーの最適なゲインです。 
5. 最大値を出力します。 順序が最適に選択されているため、これは最適なプレーヤーがどの順序でも得られる最小の利益です。 

### なぜ効果があるのか

 固定順序の場合、プレーヤーは正確に 1 つの位置で停止でき、位置 (i) で停止すると値 (prefix_i-f_i) が得られます。 したがって、プレーヤーの最適なゲインは、まさにこれらの値の最大値になります。 

(f_a>f_b) の隣接する反転を考慮します。 2 つのペアを (a,b) として順序付けすると、影響を受ける 2 つの停止値のうち大きい方が (S+p_a+p_b-f_b) になります。 それらを交換すると、影響を受ける 2 つの値は (S+p_b-f_b) と (S+p_a+p_b-f_a) になります。 (p_a\ge0) と (f_a>f_b) であるため、どちらも最大でも古い最大値です。 他のすべての停止位置はまったく同じプレフィックス合計を持ち、変更されません。 したがって、反転を削除しても目的は決して増加しません。 

すべての順列は、反転を繰り返し除去することによって非減少 (f) 次数に変換できます。 これらのスワップのいずれも目標を増加させないため、ソートされた順序の目標値は他の順序よりも大きくなりません。 したがって、それは最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pairs = [tuple(map(int, input().split())) for _ in range(n)]

    pairs.sort(key=lambda x: x[1])

    prefix = 0
    answer = None

    for p, f in pairs:
        prefix += p
        value = prefix - f
        if answer is None or value > answer:
            answer = value

    print(answer)

if __name__ == "__main__":
    solve()
```入力はペアとして保存されるため、ソートによって (p_i) が対応する (f_i) から分離されることはありません。 ソートキーは 2 番目のコンポーネントであり、増加する (f_i) を与えます。`prefix`計算前に更新される`value`。 これは、プレーヤーがそのラウンドで退出するかどうかを決定する前に (p_i) を受け取ることに対応します。 計算中`prefix - f`(p_i) を追加する前に、別のゲームを表し、off-by-one エラーが発生します。`answer`として始まります`None`ハードコードされた大きな数値の代わりに。 サンプル 3 のように、正解が負の値になる可能性があるため、これは特に便利です。Python の整数は、可能な最大の接頭辞も自動的に処理します。 すべての (p_i) の合計は (10^{14}) に達する可能性があり、Python には任意精度の整数がありますが、C++ などの言語では 32 ビット整数がオーバーフローします。 

最後のペアには個別の分岐はありません。 スキャンが到達したときにその値が含まれます。プレイヤーはそこで停止する必要があるため、式は`prefix - f`まさに必要な最終的な見返りです。 

## 実用的な例

 サンプル 1 の入力ペアは ((1,2))、((3,3))、および ((2,1)) です。 (f) でソートすると ((2,1))、((1,2))、((3,3)) が得られます。 

| ペア | プレフィックス | 接頭辞 - f | 現在の答え |
 | --- | --- | --- | --- |
 | ((2,1)) | 2 | 1 | 1 |
 | ((1,2)) | 3 | 1 | 1 |
 | ((3,3)) | 6 | 3 | 3 |

 プレイヤーが考えられるストップゲインは (1)、(1)、(3) の 3 つです。 彼女は最大のもの、つまり (3) を選択します。 (f) 次数が増加することが最適であるため、他の置換によってより小さな最適ゲインを強制することはできません。 

サンプル 2 には、ペア ((1,-2)) が 1 つだけあります。 

| ペア | プレフィックス | 接頭語 - f | 現在の答え |
 | --- | --- | --- | --- |
 | ((1,-2)) | 1 | 3 | 3 |

 マイナスの手数料はプレイヤーの利益を増加させ、(1-(-2)=3) となります。 最終的な支払いの強制も同様の表現で自然に処理されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(N\log N)) | ソートはリニア スキャンよりも優先されます。 
| スペース | (O(N)) | (N) 個のペアは並べ替えのために保存されます。 

(N=10^5) の場合、ソートには大まかに (N\log N) の比較が必要となり、実用的です。 その後のスキャンは線形であり、メモリ使用量は入力ペアの数に比例します。 累積合計は (10^{14}) に達する可能性があり、Python の整数で安全に表現できます。

import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())
    pairs = [tuple(map(int, input().split())) for _ in range(n)]

    pairs.sort(key=lambda x: x[1])

    prefix = 0
    answer = None

    for p, f in pairs:
        prefix += p
        value = prefix - f
        if answer is None or value > answer:
            answer = value

    return str(answer)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    try:
        sys.stdin = io.StringIO(inp)
        return solve()
    finally:
        sys.stdin = old_stdin

# Provided samples
assert run("""3
1 2
3 3
2 1
""") == "3", "sample 1"

assert run("""1
1 -2
""") == "3", "sample 2"

assert run("""2
0 1
3 4
""") == "-1", "sample 3"

# Minimum-size input
assert run("""1
0 0
""") == "0", "single zero pair"

# Equal f values, any internal order is optimal
assert run("""4
2 5
2 5
2 5
2 5
""") == "3", "equal f values"

# Negative f and ordering direction
assert run("""2
1 -1
1 1
""") == "2", "negative f and increasing f order"

# Maximum-size input, also checks large prefix sums
max_case = "100000\n" + "1 0\n" * 100000
assert run(max_case) == "100000", "maximum n"

 ## 特殊なケース

 単一のマイナス手数料ペア```
1
1 -2
```1 要素の配列をソートして計算することで処理されます。`prefix = 1`、 に続く`prefix - f = 1 - (-2) = 3`。 このアルゴリズムは、停止にコストがかかることを想定していません。 マイナス (f) は、プレイヤーが退場したときの単なるボーナスです。 

強制的な最終ペアには特別なケースは必要ありません。 のために```
1
0 1
```スキャンで取得される`prefix = 0`そして計算します`0 - 1 = -1`。 これが可能な唯一の停止位置であるため、答えは正確に (-1) です。 より一般的には、最後の位置は、それ以前のすべての位置と同じ停止式に含まれます。 

ゼロ (p_i) 値も直接処理されます。 で```
2
0 1
3 4
```ペアはすでに (f) によってソートされています。 最初のプレフィックスは (0) で (-1)、2 番目のプレフィックスは (3) で (3-4=-1) になります。 最大値は (-1) です。 交換証明では (p_i\ge0) が使用されるため、処理時間がゼロであっても完全に有効です。 

等しい (f_i) 値は貪欲引数には影響しません。 のために```
4
2 5
2 5
2 5
2 5
```すべての手数料が同一であるため、可能な注文はすべて同等です。 プレフィックス値は (2,4,6,8) であるため、停止ゲインは (-3,-1,1,3) となり、答えは (3) になります。 ここでの並べ替えは、結果に影響を与えることなく安定または不安定になります。 

否定的な回答も有効であり、利益がないことと混同してはなりません。 サンプル 3 では、利用可能な停止位置ごとに 1 ルーブルが失われるため、(-1) が生成されます。 答えをゼロに初期化すると、これが誤って (0) になってしまうため、実装では最初に計算された値から初期化します。 

最大の累積量は (10^5\cdot10^9=10^{14}) になります。 Python の整数表現はこれを正確に処理しますが、32 ビット実装ではオーバーフローが発生します。 アルゴリズムはこのスケールより大きい値の演算を実行しないため、Python では数値上の問題は発生しません。
