 ## 解決策
 ## 問題の理解

 この問題では、使用したいパラメータを表す点 (p=(p_t,p_i)) を、(t) の可能な最小値とともに選択するように求められます。 与えられたすべての点 (c=(c_t,c_i)) について、問題は量 (T(c,p)) と内積項 (I(c,p)) を定義し、次のことを要求します。 

[
 T(c,p)-I(c,p)\let t.
 】

 目標は、適切な (p_t,p_i) と可能な最小値 (t) を出力することです。 

関連する定義は次のように記述できます。 

[
 T(c,p)=\frac{s(c)+d(p)}{2}、
 】

 どこで

 [
 s(c)=c_t^2+c_i^2,\qquad d(p)=p_t^2+p_i^2,
 】

 そして

 [
 I(c,p)=c_t p_t+c_i p_i。 
】

 一見すると、これは複数の代数式を含む最適化問題のように見えます。 有益なステップは、アルゴリズムについて考える前にそれらを拡張することです。 

定義を置き換えると、

 \frac{c_t^2+c_i^2+p_t^2+p_i^2}{2}
 -c_t p_t-c_i p_i。 
】

 2 を掛けて項をグループ化すると、次のようになります。 

[
 (c_t-p_t)^2+(c_i-p_i)^2\le 2t。 
】

 したがって、(p) を固定的に選択する場合、重要な量は単に (p) からすべての入力点までのユークリッド距離の 2 乗です。 

したがって、元の最適化は、指定されたすべての点までの最大距離を最小にする中心 (p) を選択することと同じになります。 最小の外接円が半径 (R) の場合、その中心はまさに最適 (p) であり、

 [
 t=\frac{R^2}{2}。 
】

 コンテストバージョンは制限時間が3秒で、大量のポイントを獲得できます。 受け入れられた実装では、ランダム化された最小包囲円アルゴリズムが使用され、その予想実行時間は線形です。 トリプルに対する 3 次探索は実行不可能であり、(n) が大きい場合は一般的な (O(n^2)) 幾何学的アルゴリズムでも問題が発生します。 最適な中心と半径は一般に整数ではないため、実装には浮動小数点演算も必要です。 

最初のエッジ ケースは単一ポイントです。 例えば、```
1
3 7
```は最適な中心 ((3,7))、半径 (0)、したがって (t=0) を持ちます。 円が 2 つまたは 3 つの点によって決定されると想定する実装は、この場合不必要に失敗します。 

2 番目のエッジケースは 2 点です。 のために```
2
0 0
4 0
```最適な中心は ((2,0))、半径は (2)、(t) の答えは (2) です。 3 点の外接円のみを考慮する不注意な実装では、答えを構築するための三角形がありません。 

3 番目のエッジ ケースは、3 つの同一線上にある点です。 のために```
3
0 0
2 0
5 0
```最小の囲み円は中心 ((2.5,0)) と半径 (2.5) を持つため、(t=3.125) になります。 3 点が同一線上にある場合、3 点の外接円公式は定義されません。 正しい円は 2 つの極点によって決定されるため、実装では共線性を個別に処理する必要があります。 

4 番目のエッジ ケースは、現在の円の境界上に正確に位置する点です。 点の二乗距離が現在の二乗半径と正確に等しい場合、その点はすでにカバーされており、円が再構築されることはありません。 不必要に大きい浮動小数点許容値を使用したり、不適切に選択された浮動小数点許容値を使用すると、このような境界ケースが不安定になる可能性があります。 

## アプローチ

 直接的なアプローチでは、入力ジオメトリによって決定される可能な中心を試します。 一連の点の場合、最小の囲み円は、中点が中心となる 2 つの境界点、または外中心が中心となる 3 つの境界点によって決まります。 すべてのペアとすべてのトリプルを列挙し、対応する円を構築し、それに対してすべての点をチェックし、最小の有効な点を保持することができます。 

これは正しいです。最適な外接円の境界には最大でも 3 つの点が存在します。 正確に 2 つの境界点が必要な場合、それらの中点によってそれら 2 つの点の最小円が決まります。 3 つ必要な場合は、その外接円によって一意の円が決まります。 すべての候補をチェックすると、最終的には最適な候補が検討されます。 

問題は動作回数です。 (O(n^3)) 個のトリプルがあり、各候補のすべての (n) 点をチェックすると、単純なバージョン (O(n^4)) が作成されます。 たとえ余分なチェックを避け、幾何学的構造を利用して (O(n^3)) の実装を取得したとしても、(n) が大きい場合には依然として多大な作業が必要です。 (n=10^5) の場合、(n^2) であってもすでにおおよそ (10^{10}) 個のペア演算を意味するため、3 次アルゴリズムや 4 次アルゴリズムは完全に範囲外になります。 

問題を変える観察は、考えられるすべての境界セットを列挙する必要がないということです。 代数変換後のタスクは、まさに最小外接円問題になります。 ランダム化された増分アルゴリズムにより、これまでに処理されたポイントの最小円を維持できます。 

現在の円には以前に処理されたすべての点がすでに含まれており、新しい点がその中にあるとします。 何も変わりません。 新しい点が外側にある場合は、処理されたプレフィックスの新しい最適な円の境界上にある必要があります。 その点を境界上に固定して建設を再開できます。 前の別の点が結果の円の外側にある場合、その 2 番目の点も境界上にある必要があります。 その段階では、候補円は境界点のペアによって決定されます。 3 つ前の点がまだ外側にある場合は、3 つの点すべてが境界点である必要があるため、その外接円が答えを決定します。 

ポイントをランダムにシャッフルするため、そのような再構築の予想数が少なくなります。 結果として得られるアルゴリズムでは、(O(n)) 個の実行時間と、ポイントを保存するための (O(n)) 個のスペースが予想されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 候補サークルを列挙する | (O(n^3)) またはそれ以上 | (O(n)) | 遅すぎる |
 | ランダム化された増分最小包囲円 | 期待される (O(n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての入力ポイントを読み取り、その順序をランダムにシャッフルします。 ランダム化は、予想される線形実行時間を取得するための鍵となります。これは、敵対的な入力順序により、増分アルゴリズムにより多くの再構築が実行される可能性があるためです。 
2. 最初の点を中心とする半径 0 の円から始めます。 単一の点は常にこのような円で囲まれる可能性があるため、これは最初のプレフィックスとして有効な最小円となります。 
3. ランダムな順序で左から右にポイントを処理します。 現在の点がすでに現在の円の内側にある場合は、円を変更しないでください。 既存の円は、新しい点を含め、これまでに処理されたすべての点をすでに囲んでいます。 
4. 現在の点 (p_i) が外側にある場合は、(p_i) をその境界に強制的に配置して円を再構築します。 (p_i) を中心とする半径ゼロの円から始めます。 古い円は (p_i) を含まないため、最適な状態を維持できません。 
5. これまでのすべてのポイントを再確認します。 以前の点が新しい円の内側にある場合は、円を変更しないままにしておきます。 外側にある場合、新しい最適な円には (p_i) とこの以前の点 (p_j) の両方が境界上になければなりません。 
6. (p_i) と (p_j) を対向する境界点として円を作成します。 その中心はそれらの中点であり、その半径は距離の半分です。 これは、これら 2 つの境界点を含む最小の円です。 
7. (p_j) より前のすべてのポイントを再確認します。 すべてがカバーされている場合は、2 点の円で十分です。 点 (p_k) が外側にある場合、このプレフィックスの最適な円の境界には (p_i,p_j,p_k) がなければなりません。 
8. 3 点の外接円を作成します。 3 点が同一線上にない場合、この円は一意に決定されます。 それらが同一線上にある場合、外接円は存在せず、代わりに、正しい円は、最も遠い 2 つの点によって決定される、3 つの点を含む最小の円になります。 
9. すべての点が処理された後、維持される円は入力セット全体の最小の囲み円になります。 元のパラメータ (t) は外接円の半径の 2 乗の半分に等しいため、その中心座標と (R^2/2) を出力します。 

不変条件は、最初の (i) 個のランダム化された点を処理した後、維持される円が正確にそれら (i) 個の点を囲む最小の円であるということです。 次の点がすでにカバーされている場合、不変条件は変更されずに残ります。 外側にある場合、拡大されたプレフィックスの有効な円にはその点が含まれている必要があるため、境界上に固定しても最適な解は失われません。 2 番目、さらに 3 番目の点が外側で見つかった場合にも、同じ議論が当てはまります。 3 つの同一線上にない境界点は必要な円を一意に決定しますが、3 つの同一線上にある境界点は 2 つの極点によって決定される円に縮小されます。 したがって、すべての再構築では最小円の不変条件が維持されます。 

## Python ソリューション```python
import sys
import math
import random

input = sys.stdin.readline

EPS = 1e-12

def dist2(a, b):
    dx = a[0] - b[0]
    dy = a[1] - b[1]
    return dx * dx + dy * dy

def inside(circle, p):
    cx, cy, r2 = circle
    dx = p[0] - cx
    dy = p[1] - cy
    return dx * dx + dy * dy <= r2 + EPS * max(1.0, r2)

def circle_two(a, b):
    cx = (a[0] + b[0]) * 0.5
    cy = (a[1] + b[1]) * 0.5
    r2 = dist2(a, b) * 0.25
    return cx, cy, r2

def circle_three(a, b, c):
    ax, ay = a
    bx, by = b
    cx, cy = c

    abx = bx - ax
    aby = by - ay
    acx = cx - ax
    acy = cy - ay

    cross = abx * acy - aby * acx

    scale = max(
        1.0,
        abs(abx * acy),
        abs(aby * acx)
    )

    if abs(cross) <= EPS * scale:
        ab = dist2(a, b)
        ac = dist2(a, c)
        bc = dist2(b, c)

        if ab >= ac and ab >= bc:
            return circle_two(a, b)
        if ac >= ab and ac >= bc:
            return circle_two(a, c)
        return circle_two(b, c)

    # Circumcenter formula.
    d = 2.0 * (ax * (by - cy) +
               bx * (cy - ay) +
               cx * (ay - by))

    a2 = ax * ax + ay * ay
    b2 = bx * bx + by * by
    c2 = cx * cx + cy * cy

    ux = (
        a2 * (by - cy) +
        b2 * (cy - ay) +
        c2 * (ay - by)
    ) / d

    uy = (
        a2 * (cx - bx) +
        b2 * (ax - cx) +
        c2 * (bx - ax)
    ) / d

    r2 = (ux - ax) * (ux - ax) + (uy - ay) * (uy - ay)

    return ux, uy, r2

def minimum_enclosing_circle(points):
    random.shuffle(points)

    n = len(points)

    if n == 0:
        return 0.0, 0.0, 0.0

    circle = (points[0][0], points[0][1], 0.0)

    for i in range(1, n):
        p = points[i]

        if inside(circle, p):
            continue

        circle = (p[0], p[1], 0.0)

        for j in range(i):
            q = points[j]

            if inside(circle, q):
                continue

            circle = circle_two(p, q)

            for k in range(j):
                r = points[k]

                if inside(circle, r):
                    continue

                circle = circle_three(p, q, r)

    return circle

def solve():
    n = int(input())
    points = [tuple(map(float, input().split())) for _ in range(n)]

    cx, cy, r2 = minimum_enclosing_circle(points)

    # The original inequality becomes distance^2 <= 2t.
    t = r2 * 0.5

    print(f"{cx:.10f} {cy:.10f} {t:.10f}")

if __name__ == "__main__":
    solve()
```の`dist2`関数は二乗距離を意図的に計算します。 このアルゴリズムでは距離と半径を比較するだけでよいため、平方根を取ると不必要な浮動小数点演算が追加されます。 

の`inside`関数は、距離の二乗と半径の二乗を比較します。 小さな許容誤差は半径のスケールに関連しており、数学的には正確に境界上にあるものの、わずかな浮動小数点誤差で表される点に役立ちます。`circle_two`2 つの境界点のケースを直接実装します。 中点が中心で、点間の二乗距離の 4 分の 1 が二乗半径です。`circle_three`3 つの境界点の場合を処理します。 で表される行列式`cross`共線性を検出します。 同一線上にある点の場合、外接円は定義されていませんが、最小の囲み円は、単に最も遠い 2 つの点を結ぶ直径を持つ円になります。 

ネストされたループ`minimum_enclosing_circle`境界引数に直接対応します。 外側のループは、現在の円に違反する点を特定します。 次のループでは、その点を修正し、2 番目の境界点を検索します。 最も内側のループは 3 番目の境界点を検索します。 点が現在の円に違反すると、その点はそのプレフィックスの新しい最適な円の境界に属さなければならないため、順序が重要になります。 

アルゴリズムが使用するのは、`random.shuffle`加工前。 ランダム化がなければ、期待される線形時間の保証は失われます。 ジオメトリ自体は順序に依存しないため、シャッフルしても安全です。 

Python の浮動小数点型は C の double であり、ここで使用される幾何学的計算にはこれで十分です。 最終値は小数点以下 10 桁で出力され、通常の絶対または相対浮動小数点チェッカーに十分な精度が得られます。

# helper: run solution on input string, return output string
import sys
import io
import math

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return out

def parse(out: str):
    return list(map(float, out.split()))

def close(a, b, eps=1e-7):
    return abs(a - b) <= eps * max(1.0, abs(a), abs(b))

# Minimum-size input.
out = parse(run("""1
3 7
"""))
assert close(out[0], 3.0)
assert close(out[1], 7.0)
assert close(out[2], 0.0)

# Two points, so the answer is determined by their midpoint.
out = parse(run("""2
0 0
4 0
"""))
assert close(out[0], 2.0)
assert close(out[1], 0.0)
assert close(out[2], 2.0)

# Three non-collinear points.
out = parse(run("""3
0 0
4 0
0 3
"""))
assert close(out[0], 2.0)
assert close(out[1], 1.5)
assert close(out[2], 3.125)

# Collinear points, where the two extreme points determine the circle.
out = parse(run("""3
0 0
2 0
5 0
"""))
assert close(out[0], 2.5)
assert close(out[1], 0.0)
assert close(out[2], 3.125)

# All points equal.
out = parse(run("""5
7 7
7 7
7 7
7 7
7 7
"""))
assert close(out[0], 7.0)
assert close(out[1], 7.0)
assert close(out[2], 0.0)

# A square. Any minimum enclosing circle has center (1,1) and radius sqrt(2).
out = parse(run("""4
0 0
2 0
2 2
0 2
"""))
assert close(out[0], 1.0)
assert close(out[1], 1.0)

```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 3 7`|`3 7 0`| シングルポイント初期化 |
 |`2 / 0 0 / 4 0`|`2 0 2`| 2点境界円 |
 |`3 / 0 0 / 4 0 / 0 3`|`2 1.5 3.125`| 三点外接円 |
 |`3 / 0 0 / 2 0 / 5 0`|`2.5 0 3.125`| 共線点の処理 |
 | 5部`(7,7)`|`7 7 0`| 重複したすべての等しい点 |
 | 正方形の四隅 | 写真 正方形の四隅`1 1 1`| 対称点と境界点 |

 中心は浮動小数点演算を使用して表現されるため、正確なテキスト出力は異なる場合があります。そのため、アサーションでは特定の 10 進形式を必要とせずに数値を比較します。 

## 特殊なケース

 ワンポイントの場合```
1
3 7
```外側のループは、半径 0 の ((3,7)) の円を初期化し、違反点は検出されません。 最終的な二乗半径はゼロであるため、アルゴリズムは (t=0) と出力します。 ここで重要な特性は、最小の囲み円の半径がゼロであることが許可されるということです。 

2点の場合```
2
0 0
4 0
```最初の点は半径ゼロの円を作成します。 2 番目の点はその外側にあるため、強制境界点になります。 最初の点も半径ゼロ円の外側にあるため、2 点円が作成されます。 その中心は ((2,0))、二乗半径は (4)、報告される値は (4/2=2) です。 3 点計算は試行されません。 

同一線上の点の場合```
3
0 0
2 0
5 0
```3 つの点すべてが境界候補になると、外積はゼロになります。 3 つの異なる同一線上の点を通過する有限円は存在しないため、同一線上の点から外心を計算することはできません。 代わりに、実装では 3 つのペアごとの二乗距離を比較し、ペア ((0,0),(5,0)) を選択し、それらの中点円を構築します。 中心は((2.5,0))、二乗半径は(6.25)、答えは(3.125)です。 

すでに境界上にある点の場合、`inside`テストでは小さな許容誤差が使用されます。 考慮する```
2
0 0
4 0
```2 番目の点が ((2,0)) を中心とし、半径 2 乗 (4) の円を作成した後、元の点は両方とも正確に 2 乗距離 (4) になります。 浮動小数点計算では (4) よりも無限に大きな値が生成される可能性があるため、厳密な計算と比較すると、`<`サークルを誤って再構築する可能性があります。 許容差は、数学的に境界点をカバーされたものとして扱います。 

重複したポイントについては、```
5
7 7
7 7
7 7
7 7
7 7
```どの点も最初の点からの距離はゼロです。 円を変更する必要はなく、答えは ((7,7,0)) のままです。 点が重複しても、最小の囲み円は変更されません。 

次のような対称構成の場合、```
4
0 0
2 0
2 2
0 2
```最適な中心は ((1,1)) です。 4 つの角すべての二乗距離は (2) であるため、半径の二乗は (2) で、必要な (t) は (1) です。 このケースは、すべての点が境界上に存在する可能性があり、アルゴリズムが一意の極値点である特定の 1 つの点に依存していないことを確認するため便利です。
