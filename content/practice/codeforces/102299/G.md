 ## 解決策
 ## 問題の理解

 私たちは持っています`n`レーシー、それぞれが固定された力を持っています。 初めは、すべてのレーシーが独自の階層のルートであるため、`n`別々の木。 

会議の運営`+ i j`レーシーは言う`j`レーシーに従属するようになる`i`。 階層にはサイクルが含まれないことが保証されているため、この操作は、以前は別々だった 2 つの階層ツリーを結合します。 正確な親子方向はレポート作成には重要ですが、クエリに答えるためにはどのレーシーが同じツリーに属しているかを知るだけで十分です。 

脅迫作戦`? i`レーシーから始まります`i`そして、その階層のリーダーに到達するまで上向きに移動します。 階層全体が脅威を認識すると、そのツリー全体で最も力の弱いリーシーがその脅威に対処するために割り当てられます。 したがって、クエリは、以下を含む接続コンポーネント内のすべてのレーシー間の最小電力を求めます。`i`。 

制約により、意図された表現がかなり明確になります。 まであります`10^5`レーシーと同じくらいたくさん`5 * 10^5`制限時間は 1 秒です。 すべてのクエリに対して階層全体をスキャンするアルゴリズムは、次のことを実行できます。`10^5 * 5 * 10^5 = 5 * 10^10`制限時間をはるかに超えた最悪の場合の操作。 操作ごとにほぼ一定の償却作業が必要です。 

権限は次のように大きくすることができます`10^9`, ただし、比較して保存するだけなので、Python の整数で十分です。 階層が非循環であることが保証されているという事実は、会議が成功するたびに 2 つの異なるツリーがマージされることを意味します。これはまさに、素集合の共用体構造が適用される設定です。 

最初のエッジケースは単一のリーシーです。```
1 1
7
? 1
```答えは`7`。 すべてのクエリに従うべき親があると想定するソリューションは、クエリされた leshy がすでにリーダーであるため、ここで失敗する可能性があります。 

もう 1 つの特殊なケースは、電力値が等しい場合です。```
2 2
5 5
+ 1 2
? 2
```答えは`5`。 誰がリーダーであるかは階層によって決まりますが、誰が脅威に対処するかは権力によって決まります。 実装が権力に基づいてリーダーを選択しようとする場合、これら 2 つの概念を混同すると、誤った結果が生じる可能性があります。 

3 番目の有用なケースは、新しい従属が非ルート leshy の下に接続される場合です。```
3 3
10 4 7
+ 1 2
+ 2 3
? 3
```結果として得られる階層は、`1 -> 2 -> 3`、そして答えは`4`。 コンポーネントは`{1, 2, 3}`したがって、答えはコンポーネント全体の最小電力であり、単にコンポーネントからの経路上の最小電力ではありません。`3`根元まで。 親チェーンのみをたどり、訪問した頂点を検査しようとするソリューションはここでも機能しますが、答えはツリー全体に依存するため、依然として不必要な作業が行われることになります。 

## アプローチ

 直接的なアプローチは、すべての leshy の親を明示的に維持することです。 お問い合わせの場合`? i`、から歩いて行けます`i`リーダーに到達するまでその親を経由して、その階層のメンバーを集めて、その最小パワーを見つけます。 これは正しいです。なぜなら、同じ階層内のすべてのレーシーは最終的には同じリーダーに直属し、割り当てられたレーシーは単にその階層の最小権限メンバーに過ぎないからです。 

問題は仕事量です。 階層にはすべてを含めることができます`n`leshys であり、クエリではそれらすべてを調べる必要がある場合があります。 と`m`オペレーションでは、最悪の場合のシーケンスが必要となる場合があります。`O(nm)`仕事、それは最大です`5 * 10^10`指定された範囲の基本的な訪問数。 親の走査を最適化したとしても、最小値を見つけるために階層を繰り返しスキャンするのはコストが高すぎるままです。 

有益な観察は、クエリに対する答えが階層の形状や方向に依存しないということです。 それは、同じ階層に属するレーシーのセットにのみ依存します。 会議ではそのような 2 つのセットが結合され、クエリでは 1 つのセットに保存される最小電力が求められます。 

これはまさに、素セット共用体 (DSU) によって処理される抽象化です。 各階層は 1 つの DSU コンポーネントによって表されます。 すべてのコンポーネントに対して、最小限の電力が保存されます。 いつ`+ i j`が発生した場合、以下を含むコンポーネントをマージします。`i`そして`j`、新しいコンポーネントの最小値は、単に 2 つの古い最小値の最小値です。 いつ`? i`が発生すると、次のような代表者が見つかります。`i`そして、その代表に対して保存されている最小値を返します。 

ブルート フォース手法は、クエリごとに階層を再構築するため機能しますが、同じ大規模な階層を繰り返しクエリすると失敗します。 コンポーネントのメンバーシップとコンポーネントの最小限のみが重要であるという観察により、階層構造を完全に破棄し、クエリが必要とする情報を正確に維持することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(nm)`最悪の場合 |`O(n)`| 遅すぎる |
 | 最適 |`O((n + m) α(n))`|`O(n)`| 承認済み |

 ここ`α(n)`は逆アッカーマン関数であり、成長が非常に遅いため、実際のすべての競合プログラミング制約に対して小さな定数のように動作します。 

## アルゴリズムのチュートリアル

 1. すべての leshy のパワーを読み取り、その leshy のみを含む DSU コンポーネントを初期化します。 他のレーシーがまだそれに属していないため、その構成要素の最小値はそれ自体のパワーです。 
2. のために`+ i j`操作を行うには、DSU の代表者を見つけます。`i`そして`j`。 会議は 2 つの階層を結合するため、それらのコンポーネントをマージする必要があります。 

そう言う方向性`j`～に従属するようになる`i`今後の回答には関係ありません。 どちらのレーシーが正式な親であるかに関係なく、両方のセットが 1 つの階層に属します。 
3. 2 つのコンポーネントをマージするときは、DSU ツリーが浅いままになるように、サイズまたはランクによるユニオンを使用します。 2 つのコンポーネントの最小値のうち小さい方を、マージされたコンポーネントの最小値として保存します。 
4.`? i`作戦、代表者を見つける`i`そして、その代表に対して保存されている最小値を出力します。 そのコンポーネント内のすべてのリーシーは同じ階層に属しているため、この値はまさに脅威を処理するリーシーのパワーとなります。 
5. パス圧縮を使用する`find`。 代表者が検出されるたびに、クエリされた leshy からその代表者に直接向かうパスを圧縮します。 その後の操作では、コンポーネントをより速く見つけることができます。 

### なぜ効果があるのか

 不変条件は、すべての DSU コンポーネントが正確に 1 つの現在の階層を表し、その代表に保存されている最小値がその階層内のすべての leshys の最小電力であるということです。 

最初はすべての階層が 1 つのレーシーで構成されているため、不変式が成り立ちます。 会議は、2 つの異なる階層を 1 つに結合します。 DSU はそのマージを正確に実行し、保存されている 2 つの最小値の最小値を取得すると、結合された階層全体の最小値が得られます。 クエリでは階層は変更されないため、`i`そして、保存された最小値を返すと、まさに脅威に気づいた人々の中で最も強力なリーシーが与えられます。 すべての操作ではこの不変条件が維持されるため、すべてのクエリは必要な検出力を返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    power = list(map(int, input().split()))

    parent = list(range(n))
    size = [1] * n
    minimum = power[:]

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    out = []

    for _ in range(m):
        op = input().split()

        if op[0] == '+':
            a = int(op[1]) - 1
            b = int(op[2]) - 1

            a = find(a)
            b = find(b)

            if a == b:
                continue

            if size[a] < size[b]:
                a, b = b, a

            parent[b] = a
            size[a] += size[b]
            minimum[a] = min(minimum[a], minimum[b])

        else:
            x = int(op[1]) - 1
            root = find(x)
            out.append(str(minimum[root]))

    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```の`parent`配列は DSU フォレストです。 最初は`parent[i] = i`なぜなら、すべてのレーシーは、自身の階層の代表として始まるからです。 の`size`配列はサイズによる結合をサポートし、DSU 構造が長いチェーンに縮退するのを防ぎます。 

の`minimum`配列には、各コンポーネントの代表に対する最小電力が格納されます。 すべてのクエリが最初に呼び出すため、非代表に属する値を更新する必要はありません。`find`そして現在の代表者から値を読み取ります。 

の`find`実装では反復パスの半分化が使用されます。 課題`parent[x] = parent[parent[x]]`上向きに歩きながらパスを短縮し、再帰なしの通常のパス圧縮と同じ漸近的な動作を与えます。 これにより、Python の再帰の深さの問題も回避されます。 

入力のインデックスは 1 から始まりますが、Python 配列は 0 から始まるため、すべての入力インデックスはすぐに 1 減ります。 和集合演算では、2 つの代表がすでに等しいかどうかがチェックされます。 この問題により、階層が循環的にならないことが保証されるため、有効な入力ではそのようなマージが発生しないはずですが、チェックを維持することで DSU が堅牢になり、コンポーネント サイズや最小値の破損が回避されます。 

Python には整数オーバーフローの問題はなく、とにかく最大のべき乗が Python 整数に収まります。 出力はリストに蓄積され、最後に一度書き込まれるため、クエリごとに個別の出力操作を実行するオーバーヘッドが回避されます。

 ## 特殊なケース

 シングルトン階層のケースは、DSU の初期状態によって処理されます。 のために```
1 1
7
? 1
```

`find(1)`唯一の代表者をただちに返送し、`minimum[0]`は`7`したがって、出力は次のようになります`7`。 1 要素階層はすでに有効な DSU コンポーネントであるため、特別な場合のコードは必要ありません。 

等しい力も自然に処理されます。 のために```
2 2
5 5
+ 1 2
? 2
```マージは計算します`min(5, 5)`、つまり`5`。 このアルゴリズムでは、Leshy インデックスや階層リーダーをパワーの代わりに使用することはありません。そのため、値が同じであっても曖昧さは生じません。 

マージでは、それ自体の代表ではない leshy の下に階層を接続できます。 例えば、```
3 3
10 4 7
+ 1 2
+ 2 3
? 3
```最初のマージの後、`{1,2}`最低限のものがある`4`。 2 番目のマージは leshy に結合します`3`そのコンポーネントを使用して、最小値を与える`4`また。 クエリでは、次の代表者が見つかります。`3`そして戻ってきます`4`。 DSU は、正式な階層が次のとおりであることを知る必要はありません。`1 -> 2 -> 3`、セット全体が答えを決定するものだからです。 

最大電力値もチェックする価値のある境界です。 次のような値`1000000000`に直接保存されます`minimum`、 そして`min()`普通に比べてみます。 Python には任意精度の整数があるため、後で他の派生整数値を格納するように実装が適応されたとしても、オーバーフローのリスクはありません。 

最後に、クエリは、クエリされた leshy が関与するマージの直前に到着する可能性があります。 例えば、```
3 2
8 3 5
? 3
? 1
```どちらのクエリもシングルトン コンポーネントで動作し、`5`そして`8`。 DSU 表現は最初の操作から有効であるため、クエリには事前の構築フェーズは必要ありません。
