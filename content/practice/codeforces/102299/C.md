 ## 解決策
 ## 問題の理解

 私たちはマトリョーシカのコレクションを保管しています。 すべての人形には、正の整数の重みと一意の識別子があります。 人形には複数の小さな人形を含めることができますが、外側の人形の中に直接的または間接的に含まれるすべての総重量が外側の人形の重量を超えてはなりません。 

お問い合わせの場合`? ID`、特定のネストを構築するように求められることはありません。 指定された人形をその内部のどこかに含む、1 つの有効なネストに可能な最大数の人形が必要です。 クエリされる人形は、最も外側の人形である必要はありません。 

コレクションは時間とともに変化します。 手術`+ W ID`重りを付けた新しい人形を挿入します`W`、`- ID`既存の人形を削除し、`? ID`その識別子を含む最大ネスト サイズを尋ねます。 公式の制約は次のとおりです`N <= 10^5`、`Q <= 5 * 10^5`、すべての重みと識別子は最大でも`10^9`。 コンテストでは、この問題に 3 秒の制限と 256 MB のメモリが与えられます。 

大きな値`Q`が重要な制約です。 クエリごとに現在利用可能なすべての人形を検査するアルゴリズムは、あまりにも高価すぎます。 最初だけ考えたとしても`10^5`人形、`5 * 10^5`クエリによってすでに発生している可能性がある`5 * 10^10`候補者のチェック。 動的な挿入と削除により、直接スキャンの魅力はさらに低下します。 

誤って対処しやすい特殊なケースがいくつかあります。 まず、平等が認められます。 例えば、```
2 1
1 1
? 1
```答えがあります```
2
```体重の人形が1つあるから`1`別の体重の人形を入れることができます`1`。 厳密な方法を使用した解決策`<`比較が誤って返される`1`。 

重みの重複も重要です。 で```
3 1
1 1 2
? 3
```答えは`3`、ネストを使用して`1, 1, 2`。 多重性を考慮せずに値による重みを削除すると、クエリされた人形や間違った重複が誤って削除される可能性があります。 

クエリされた人形は、ネストの途中にある可能性があります。 のために```
4 1
3 1 2 1
? 3
```答えは`3`、重みを使用して`1, 1, 2`、重さで`2`doll をクエリされた人形として指定します。 クエリの対象外の人形のみを検索する戦略では、有効な解決策が失われます。 

最後に、不合格となった候補者は引き続き利用可能でなければなりません。 考慮する```
3 1
1 3 10
? 2
```クエリされた人形の重量はどこですか`3`。 重量`1`人形を中に入れることができ、サイズが与えられます`2`、しかし重量`10`現在の合計は次のようになるため、人形はフォローできません`13`追加した後。 適合するかどうかを確認する前に最初の候補を削除する不注意な実装は、コレクションを破損する可能性があります。 

## アプローチ

 直接的なアプローチは、クエリされた人形を一時的に削除し、残りの重みを並べ替え、その周りにネストできる人形を繰り返し選択することです。 すべての段階で実行可能な最小の人形を使用する場合、これは正しいですが、ソートにはコストがかかります`O(N log N)`スキャンには費用がかかる場合があります`O(N)`1 つのクエリに対して。 まで`5 * 10^5`クエリ、これは必要なスケールには程遠いです。 

問題を 2 つの観察に分けることで、より良い結果を得ることができます。 1つ目は貪欲です。 片側にすでに配置されている人形の現在の合計が`S`。 次の人形には少なくとも重量が必要です`S`なぜなら、すでにその中にすべての人形が含まれている必要があるからです。 すべての可能な選択肢の中で、そのような最小の人形は常に、少なくとも大きな人形と同じくらい優れています。 より小さな人形を選択すると、その後のすべての選択に対して少なくとも同程度の容量が残るため、より大きな選択肢を実現可能な最小の人形に置き換えても、達成可能な人形の最大数を減らすことはできません。 

クエリされた人形内の人形については、世界的に最小の利用可能な重量から開始します。 クエリされた重量以下の場合にのみ使用できます`X`。 それを選択した後、新しい合計が最大でも次の値にとどまることを条件として、現在の内部合計と少なくとも等しい最小の利用可能な重みを繰り返し取得します。`X`。 

クエリされた人形が追加されると、同じ貪欲なプロセスが外側に向けて継続されます。 次の人形は少なくとも現在の総重量以上の重量を持つ必要があり、ここでも利用可能な最小の人形を選択します。 

2 番目の観察により、この貪欲なシミュレーションが高速になります。 最初に選択した内部人形に重みがついた後`y`、その後選択された人形はすべて、少なくとも現在の合計の重量を持ちます。 したがって、選択が成功するたびに合計は少なくとも 2 倍になります。 クエリされた人形が追加された後の外側でも同じことが当てはまります。 すべての重みが最大であるため、`10^9`、クエリで選択できるのは`O(log 10^9)`、およそ30、人形。 コレクションには何十万もの人形が含まれている可能性がありますが、クエリに必要な順序セット操作は少数だけです。 

C++ では、自然な実装は次のようになります。`multiset`、挿入、削除、最小値、および`lower_bound`で`O(log N)`。 公開されたソリューションは、順序付けられたマルチセットを使用したこの貪欲な戦略に従っています。 

Python にはバランスのとれたマルチセットが組み込まれていないため、以下の実装では座標圧縮と階層ビットセットを使用します。 それぞれの個別の重みにインデックスが付けられます。 count 配列には各重量を持つアクティブな人形の数が格納され、いくつかのレベルの 64 ビット ビットセットが現在どの重量インデックスが存在するかを示します。 圧縮されたインデックスまたはその後の最初のアクティブな重みを見つけるには、数回の階層操作のみが必要です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(QN) 候補チェック、および必要に応じて並べ替え | O(N) | 遅すぎる |
 | 最適な順序集合 | O(Q log W log N) | O(N + Q) | 承認済み |
 | Python 階層ビットセット | O((N + Q) log(N + Q) + Q log W log N) | O(N + Q) | 承認済み |

 ここ`W`は可能な最大重量を示します。 Python 実装における余分な対数は、バイナリ検索で圧縮されたインデックスを見つけることで得られます。 実際のアクティブウェイト ルックアップは、従来のツリーではなく 64 項階層を使用して実装されます。 

## アルゴリズムのチュートリアル

 1. 初期の人形とすべての操作を読み取り、出現する可能性のあるすべての重量を収集します。 座標圧縮では、動的操作を処理する前に、考えられるすべての重みを知る必要があります。 
2. 個別の重みをソートし、それぞれに圧縮インデックスを割り当てます。 すべてのアクティブな識別子からその圧縮された重みインデックスまでの辞書を維持します。 
3. 階層ビットセットを構築します。 レベル 0 では、ビット`i`少なくとも 1 つのアクティブな人形の重量が圧縮されたときに正確に設定されます`i`。 より高いレベルには、前のレベルのどの単語が空ではないかが格納されます。 これにより、非アクティブなインデックスをスキャンすることなく、次のアクティブな重みを見つけることができます。 
4. 挿入の場合、対応する圧縮ウェイトのカウントを増やします。 そのカウントが 0 から 1 に変化した場合、対応するビットを設定し、新しく空ではないワードを階層全体に伝播します。 
5. 削除する場合は、カウントを減らします。 カウントがゼロになると、そのビットをクリアし、新しく空になったワードを上方に伝播します。 
6. クエリの場合は、クエリ対象の人形を一時的に取り外します。 これにより、アルゴリズムが同じ物理的な人形を自身のコンテナまたはコンテンツの 1 つとして選択するのを防ぎます。 
7. しましょう`X`クエリされた人形の体重になり、答えを次のように設定します。`1`。 最小のアクティブな体重を見つける`y`。 もし`y <= X`、それを削除し、答えを増やし、現在の内和を次のように設定します。`y`。 最小の重みがすでに次の値を超えている場合`X`、クエリされた人形の中に可能な人形はありません。 
8. 可能な限り、最小のアクティブウェイトを見つけます。`y >= current_sum`。 もし`current_sum + y <= X`、削除して更新します`current_sum += y`。 それ以外の場合は停止してください。 より大きな候補はすべて、クエリされた人形の容量と少なくとも同じ量を消費するため、最小の候補を選択することが最適です。 
9.追加`X`現在の合計に。 クエリされた人形は、内部で選択されたすべてを含む現在のスタック全体になります。 
10. 現在の合計と少なくとも等しい最小のアクティブな重みを繰り返し見つけます。 存在する場合は、それを削除し、答えを増やし、その重みを現在の合計に追加します。 存在しない場合、ネストをさらに拡張することはできません。 
11. クエリされた人形と、一時的に選択されたすべての人形を復元します。 クエリは単なる計算であるため、コレクションはクエリの前とまったく同じである必要があります。 
12. 回答を印刷し、次の操作に進みます。 

これが機能する理由: 不変条件は、どの段階でも、同じ数の人形を持つすべての部分ネストの中で、現在の部分ネストの総重みが可能な限り最小であるということです。 内側の部分については、使用可能な最小の人形を選択することで、内部の残りの容量を最大限に維持できます。`X`。 外側の部分では、現在のスタックを含めることができる最小の人形を選択すると、可能な限り最小の新しい合計が保持されます。 代替的な選択には少なくとも同程度の重みがあるため、貪欲な選択よりも多くの将来の人形を許可することはできません。 選択されたすべての重みは少なくとも前の合計であるため、選択が成功すると現在の合計も 2 倍になり、反復回数が制限されます。 

## Python ソリューション```python
import sys
from bisect import bisect_left
from array import array

input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())

    initial = list(map(int, input().split()))
    while len(initial) < n:
        initial.extend(map(int, input().split()))

    # Store operations compactly.
    # typ: 0 = query, 1 = add, 2 = delete
    typ = bytearray()
    a = array('q')
    b = array('q')

    all_weights = array('q', initial)

    for _ in range(q):
        parts = input().split()
        op = parts[0]

        if op == b'+':
            w = int(parts[1])
            ident = int(parts[2])
            typ.append(1)
            a.append(w)
            b.append(ident)
            all_weights.append(w)
        elif op == b'-':
            ident = int(parts[1])
            typ.append(2)
            a.append(ident)
            b.append(0)
        else:
            ident = int(parts[1])
            typ.append(0)
            a.append(ident)
            b.append(0)

    weights = sorted(set(all_weights))
    m = len(weights)
    weight_to_index = {w: i for i, w in enumerate(weights)}

    del all_weights

    # id -> compressed weight index
    ids = {}

    counts = [0] * m

    # levels[0] has one bit per compressed weight.
    # A bit is set iff that weight currently exists.
    levels = []
    size = (m + 63) >> 6
    levels.append([0] * size)

    while size > 1:
        size = (size + 63) >> 6
        levels.append([0] * size)

    def activate(idx):
        counts[idx] += 1
        if counts[idx] != 1:
            return

        pos = idx

        for level in range(len(levels)):
            word = pos >> 6
            bit = 1 << (pos & 63)

            old = levels[level][word]
            if old & bit:
                break

            levels[level][word] = old | bit

            if old != 0:
                break

            pos = word

    def deactivate(idx):
        counts[idx] -= 1
        if counts[idx] != 0:
            return

        pos = idx

        for level in range(len(levels)):
            word = pos >> 6
            bit = 1 << (pos & 63)

            old = levels[level][word]
            new = old & ~bit
            levels[level][word] = new

            if new != 0:
                break

            pos = word

    def next_active(pos):
        """Return the first active compressed index >= pos, or -1."""
        if pos >= m:
            return -1

        level = 0
        p = pos

        while level < len(levels):
            word = p >> 6
            if word >= len(levels[level]):
                return -1

            mask = -1 << (p & 63)
            value = levels[level][word] & mask

            if value:
                bit = (value & -value).bit_length() - 1
                index = (word << 6) + bit

                if level == 0:
                    return index

                # We found a nonempty word in a higher level.
                # Descend to the actual weight index.
                current = index

                for lower in range(level - 1, -1, -1):
                    value = levels[lower][current]
                    bit = (value & -value).bit_length() - 1
                    current = (current << 6) + bit

                return current

            # No set bit remains in this word. The next possible
            # bit in the next hierarchy level represents word + 1.
            p = word + 1
            level += 1

        return -1

    # Insert the initial collection.
    for ident, w in enumerate(initial, 1):
        idx = weight_to_index[w]
        ids[ident] = idx
        activate(idx)

    out = []

    for k in range(q):
        operation = typ[k]

        if operation == 1:
            w = a[k]
            ident = b[k]

            idx = weight_to_index[w]
            ids[ident] = idx
            activate(idx)

        elif operation == 2:
            ident = a[k]

            idx = ids.pop(ident)
            deactivate(idx)

        else:
            ident = a[k]

            target_idx = ids[ident]
            x = weights[target_idx]

            # Temporarily remove the queried physical doll.
            deactivate(target_idx)

            chosen = [target_idx]
            answer = 1

            # Build the part strictly inside the queried doll.
            first = next_active(0)

            if first != -1:
                y = weights[first]

                if y <= x:
                    deactivate(first)
                    chosen.append(first)
                    answer += 1
                    current = y

                    while True:
                        need = bisect_left(weights, current)
                        nxt = next_active(need)

                        if nxt == -1:
                            break

                        y = weights[nxt]

                        if current + y > x:
                            break

                        deactivate(nxt)
                        chosen.append(nxt)
                        answer += 1
                        current += y
                else:
                    current = x
            else:
                current = x

            # The queried doll becomes part of the current stack.
            if chosen[-1] != target_idx:
                current += x
            else:
                current = x

            # Extend outward.
            while True:
                need = bisect_left(weights, current)
                nxt = next_active(need)

                if nxt == -1:
                    break

                y = weights[nxt]
                deactivate(nxt)
                chosen.append(nxt)

                answer += 1
                current += y

            out.append(str(answer))

            # Restore exactly the dolls temporarily removed for this query.
            for idx in chosen:
                activate(idx)

    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```初期コレクションは圧縮構造に 1 回だけ挿入されます。 識別子辞書には、元の重みではなく圧縮された重みインデックスが格納されるため、識別子の重みを繰り返し検索する必要がなくなります。 

の`activate`そして`deactivate`関数は多重度と階層の両方を維持します。 複数の異なる人形が同じ重量を持つ可能性があるため、多重性が必要です。 重みは、カウントが 0 に達するまでビットセット内でアクティブなままになります。`next_active`Python の代替品です`multiset.lower_bound`。 レベル 0 では、関連する 64 ビット ワード内の最初の設定ビットが検索されます。 その単語が空の場合は、より高いレベルに上がってどの単語にアクティブな重みが含まれているかを記録し、その後再び下降して正確な重みインデックスを回復します。 各レベルは 64 のエントリをグループ化するため、最大でも少数のレベルしか存在しません。`6 * 10^5`可能な重み。 

クエリされた人形は、貪欲なプロセスの前に削除され、その後復元されます。 の`chosen`配列は圧縮された重みインデックスを記録しますが、クエリでは ID から重みへのマッピングが変更されないため、識別子ではなくインデックスを復元するだけで十分です。 

すべての合計には Python 整数が使用されるため、オーバーフローの心配はありません。 固定幅の整数演算を行う言語では、ネストされた合計が超過する可能性があるため、64 ビット整数が必要です。`10^9`大きな要因によって。 

二人`bisect_left`呼び出しは、ソートされた個別の重みに対して意図的に実行されます。 必要な重量を次のように変換します。`current`実際の重みが少なくともその値である最初の圧縮インデックスに変換されます。 次に、ビット階層は、そのインデックスの後のすべての非アクティブな重みをスキップします。

 |`? 2`| 9 | 9 |`9`| 1 |
 | 内なる選択 | 9 | 4 |`9, 4`| 2 |
 | 次の内部候補 | 9 | 4 |`9, 4`| 2 |
 | 外側の検索 | 9 | 13 |`9, 4`| 2 |

 重量`10`内部では使用できません`9`なぜなら`4 + 10 > 9`。 クエリされた人形を追加した後の合計は、`13`、 それで`10`また、その外側に配置することもできません。 答えは次のようになります。`2`、サンプルと一致します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((N + Q) log(N + Q) + Q log W log(N + Q)) | 圧縮には並べ替えのコストがかかり、すべてのクエリは順序付けされた重み検索を使用して O(log W) の貪欲な選択を実行します。 
| スペース | O(N + Q) | 考えられるすべての重み、演算、識別子、カウント、階層レベルには線形空間が必要です。 

ここ`W <= 10^9`、 それで`log W`重要な実際的な事実は、クエリがコレクション全体をスキャンすることは決してないということです。 貪欲な合計は、選択が成功するたびに少なくとも 2 倍になり、潜在的に線形のクエリのように見えるクエリが、対数の順序付けされたルックアップに減ります。 元のコンテスト制限は 256 MB で 3 秒であり、同じ貪欲な制限が、目的の順序セット ソリューションが実行可能な理由です。

 ## 特殊なケース

 等価境界については、次のように考慮します。```
2 1
1 1
? 1
```クエリーされた人形は一時的に削除され、重みが 1 つ残されます。`1`。 以来`1 <= 1`、インナードールとして選ばれています。 現在の合計は次のようになります`1`、そして別の候補者が合計を計算します`2`、クエリされた人形には大きすぎます。 外側の人形は利用できないので、答えは次のとおりです。`2`。 アルゴリズムが使用するのは、`<=`容量チェックで境界を正確に処理します。 

重みが重複する場合は、次の点を考慮してください。```
3 1
1 1 2
? 3
```問い合わせた体重は、`2`。 最初のアクティブな体重は`1`が選択されます。 もう一人のアクティブな`1`も選択されているため、`1 + 1 = 2`。 次に、クエリされた人形が組み込まれ、3 つの人形のネストが生成されます。 count 配列は重みを保持します`1`両方のコピーが削除されるまでアクティブであるため、2 つの物理的な人形は別々に処理されます。 

最外側ではないクエリ対象の人形については、次のことを考慮してください。```
4 1
3 1 2 1
? 3
```一時的に体重を減らした後`2`、貪欲な内相が選択します`1`そしてもう一つ`1`、内部合計に達します`2`。 その後、クエリされた人形自体が追加されますが、外側の重みには結果の合計を含めることはできません。`4`。 答えは`3`。 このアルゴリズムは、クエリされた人形がスタック内の最初または最後の人形である必要があるとは決して想定しません。 

正確に塗りつぶす境界については、次のことを考慮してください。```
3 1
1 1 2
? 3
```二つの重み`1`人形には総重量が正確にあります`2`、したがって両方ともクエリされた重みの中に属します`2`人形。 答えは`3`。 厳密な不等号は最初の後に停止します。`1`そして間違った答えを返す`2`。 

動的な状態変化については、次の点を考慮してください。```
2 5
1 4
? 2
- 1
? 2
+ 2 3
? 2
```もともと体重は`1`ウェイトの中に入れることができる`4`、与える`2`。 識別子の後`1`は削除され、クエリされた重量のみが削除されます`4`が残っているので、答えは次のようになります`1`。 新しいウェイトの挿入`2`2 つの人形の入れ子の可能性を回復し、`2`また。 識別子辞書と多重度構造は独立して更新されるため、識別子を削除したり後で再利用したりしても、古い重みが残ることはありません。
