 ## 解決策
 ## 問題の理解

 ポジティブなチャプター価格を多数ご用意しております。 借金の期限が来るたびに、ドストエフスキーはすでに書かれた章のサブセットを売却することができ、その価値がそのサブセットの合計と等しくなったときに借金を正確に支払うことができます。 1 つの負債に対して同じ章を 2 回売却することはできないため、関連する質問はサブセット合計の質問になります。 

指定された価格の一部の合計として形成できない最小の正の整数が必要です。 答えは必ずしも各章の価格よりも大きいとは限りません。 たとえば、価格の場合`2, 5`、借金`1`すでに不可能なので、答えは`1`。 

配列には最大で次のものを含めることができます`5 * 10^5`各章の価格は次のとおりです。`10^12`。 これにより、サブセットの列挙が即座に除外されます。`2^n`彼らのうち。 多くの章のペアまたは間隔を考慮したアプローチでも、この規模では遅すぎます。 に近いアルゴリズムが必要です`O(n log n)`これは、2 秒の制限内で 50 万個の要素に対して実用的です。 

各価格の値が大きいということは、合計によってインデックス付けされた固定サイズの動的プログラミング配列が実行不可能であることも意味します。 総額に達する可能性があります`5 * 10^17`、合計ベースの DP が割り当てることができる量をはるかに超えています。 幸いなことに、この解には実行値が 1 つしか必要ないため、Python の任意精度の整数は潜在的に大きな答えを直接処理します。 

実装が静かに失敗する可能性があるいくつかのエッジケースがあります。 最小価格がそれより大きい場合`1`なら答えはすぐに出ます`1`。 たとえば、入力の場合`1`そして価格`2`、出力は`1`, なぜなら、どの部分集合も1ルーブルを生み出すことはできないからです。 最初の価格から開始し、それ以下のすべての値を構築できると想定する不注意な実装は、このケースを誤って見逃してしまいます。 

2 番目のエッジ ケースは、ある時点までのすべての値が構築可能であるにもかかわらず、次の価格でギャップが生じる場合に発生します。 たとえば、価格の場合`1 2`、私たちは作ることができます`1`、`2`、 そして`3`、しかしそうではありません`4`、したがって、答えは次のとおりです`4`。 連続的に到達可能な間隔全体を追跡するのではなく、現在の値自体がサブセット合計であるかどうかのみをチェックする実装では、このギャップを見逃す可能性があります。 

3 番目のケースは、次の価格が現在到達可能なすべての価格よりちょうど 1 大きい場合です。 価格付き`1 1 3`、最初の 2 つの値を使用して、次からすべての合計を構築できます。`0`を通して`2`。 値`3`これを次のように拡張します`5`、したがって、答えは次のとおりです`6`。 境界条件は次のようにする必要があります。`price <= reachable + 1`、 ない`price < reachable + 1`。 

## アプローチ

 直接的なアプローチは、章のすべてのサブセットを生成し、その合計を計算し、どの合計が可能かを記録することです。 がある`2^n`サブセット。 たとえ各サブセットの合計が効率的に維持されたとしても、依然として必要になります。`O(2^n)`仕事。 すべてのサブセットをすべて調べて構築された場合`n`要素の場合、操作数は次のようになります。`O(n * 2^n)`、これは完全に不可能です`n = 5 * 10^5`。 平`2^60`制限時間内に実行できるものをすでにはるかに超えています。 

より一般的な代替方法は、サブセット合計動的プログラミングです。 到達可能な金額をマークし、価格ごとに更新することができます。 問題は、合計額が次のように大きくなる可能性があることです。`5 * 10^17`したがって、理論的には効率的であっても、`O(n * sum)`DP はメモリや時間に収まりません。 

この便利な構造は、すべての価格がプラスであるという事実から生まれます。 すでにいくつかの章を処理しており、すべての値を次から構築できると仮定します。`1`を通して`R`。 次の価格を考えてみましょう`x`、すべての価格をさらにソートした後。 

もし`x <= R + 1`、古い章ではすべての値が次から作成されます。`0`を通して`R`、追加しながら`x`からすべての値を作成しましょう`x`を通して`x + R`。 なぜなら`x <= R + 1`、これら 2 つの間隔は接触または重なり合います。 したがって、それらの結合は次のすべての値になります。`0`を通して`R + x`。 

代わりに`x > R + 1`、 それから`R + 1`形成できません。 すでに処理された各章は最大でも`R`、および使用するすべてのサブセット`x`またはそれ以降、さらに大きな章には少なくとも合計が必要です`x`より大きい`R + 1`。 それで`R + 1`は明らかに最小の不可能な値です。 

これにより貪欲なアルゴリズムが得られます。 価格を並べ替え、完全に構築可能であることが知られている正の合計の最大のプレフィックスを維持し、次の価格がギャップを残さないときはいつでもその範囲を拡張します。 ブルートフォース手法では、どの合計が存在することが保証されているかについての情報がないため、すべてのサブセットを明示的に探索します。 上記の観察により、すべての情報が 1 つの整数に圧縮されます。`R`。 

結果として生じる複雑さは次のとおりです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n * 2^n)`|`O(2^n)`| 遅すぎる |
 | サブセット合計 DP |`O(n * S)`|`O(S)`| 遅すぎてメモリが多すぎる |
 | 最適な貪欲さ |`O(n log n)`|`O(n)`| 承認済み |

 ここ`S`は、すべてのチャプターの価格の合計を示します。 最適な方法では、配列のソートにほぼすべての時間を費やします。 

## アルゴリズムのチュートリアル

 1. すべての章の価格を読み取り、降順でない順に並べ替えます。 並べ替えにより、未処理の価格が少なくとも現在の価格と同じくらい大きいかどうかを推論できるようになります。 
2.初期化`reachable = 0`。 これは、章を使用せずに合計を構築できることを意味します。`0`、この時点での間隔内のすべての値`1`を通して`reachable`真空で構築可能です。 
3. ソートされた価格を最小値から最大値の順に処理します。 現在の価格の場合`x`と比較してください`reachable + 1`、構築可能であることがまだ保証されていない最小の正の量。 
4. もし`x > reachable + 1`、 戻る`reachable + 1`。 前の章では、以下の合計しか形成できません。`reachable`、一方、以下を含むサブセットは`x`少なくとも価値がある`x`。 したがって`reachable + 1`本当のギャップにあり、それが答えです。 
5. それ以外の場合は、`x <= reachable + 1`ので、追加します`x`に`reachable`。 追加する前に`x`、からのすべての合計`0`を通して`reachable`可能でした。 使用する`x`これらの同じサブセットを組み合わせると、以下のすべての合計が得られます。`x`を通して`x + reachable`。 以来`x <= reachable + 1`、2 つの間隔の間にギャップはないため、からのすべての値は`0`を通して`reachable + x`が可能になります。 
6. ギャップが見つからずにすべての価格が処理された場合は、リターンします。`reachable + 1`。 その時点で、からのすべての値`0`合計を超える合計は構築できますが、合計を超える合計は不可能です。 最初のそのような値は正確に`reachable + 1`。 

### なぜ効果があるのか

 不変条件は、現在の価格より前のすべての価格を処理した後、次のとおりです。`0`を通して`reachable`形成することができる。 次の価格を超えた場合`reachable + 1`、 それから`reachable + 1`形成できません: その価格のないサブセットは最大でも`reachable`、そしてそれを含むサブセットは少なくとも次の価格です。 価格が最大であれば`reachable + 1`、それを除いた合計`[0, reachable]`、およびそれを使用した合計はカバーします`[x, x + reachable]`。 これらの間隔は重なったり接触したりするため、一緒にカバーされます。`[0, reachable + x]`。 したがって、不変式は保存され、最初に検出されたギャップは正確に最小のありえない正の和になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    prices = list(map(int, input().split()))

    prices.sort()

    reachable = 0

    for x in prices:
        if x > reachable + 1:
            print(reachable + 1)
            return
        reachable += x

    print(reachable + 1)

if __name__ == "__main__":
    solve()
```最初の 2 行には、章数とその価格が表示されます。 入力には正確に含まれているため、`n`2 行目の価格、1 回の呼び出し`input()`指定された形式には十分です。 

並べ替えステップでは、価格が昇順に並べられます。 現在の価格が次の欠損値を埋めるには大きすぎると判断した後、残りのすべての価格が少なくとも同じ大きさであるため、そのギャップを埋めることもできないため、貪欲な証明はこの順序に依存します。`reachable`は、以下のすべての値が成立する最大の整数を表します。`0`を通して`reachable`施工可能です。 小切手`x > reachable + 1`が重要な境界です。 平等が許可される理由は、`x == reachable + 1`、新しい章自体が次の欠損値を埋め、連続範囲を拡張します。 

現在の価格でご利用いただける場合は、`reachable += x`新しくカバーされる間隔のエンドポイントを更新します。 不変式では、区間内のすべての値が使用可能であることを知るだけでよいため、どのサブセットが合計を生成するかを保存する必要はありません。 

合計が次の値に達する可能性があるため、ここでは Python 整数が適切です。`5 * 10^17`。 固定幅の整数型を使用する言語では、この値に 64 ビットの整数が必要ですが、Python では必要に応じて整数表現が自動的に拡大されます。

import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    prices = list(map(int, input().split()))
    prices.sort()

    reachable = 0

    for x in prices:
        if x > reachable + 1:
            print(reachable + 1)
            return
        reachable += x

    print(reachable + 1)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("3\n2 1 10000000000\n") == "4", "sample 1"
assert run("1\n2\n") == "1", "sample 2"

# Minimum-size input, cheapest possible chapter
assert run("1\n1\n") == "2", "single chapter worth 1"

# All equal values
assert run("5\n1 1 1 1 1\n") == "6", "all equal values"

# Boundary case: x == reachable + 1 must extend the range
assert run("3\n1 1 3\n") == "6", "exact boundary"

# Gap after several constructible values
assert run("4\n1 2 2 10\n") == "6", "gap after continuous range"

# Large values must not cause fixed-range DP assumptions
assert run("3\n1000000000000 1000000000000 1000000000000\n") == "1", "large prices"

# Maximum-size case, all values equal to 1
n = 500000
assert run(f"{n}\n" + " ".join(["1"] * n) + "\n") == "500001", "maximum n"

 ## 特殊なケース

 最も安い章の価格が 1 ルーブル以上である場合、答えは次のようになります。`1`。 入力用```
1
2
```最初の`reachable`は`0`、 それで`reachable + 1`は`1`。 ソート価格なので`2`より大きい`1`、アルゴリズムは戻ります`1`章を追加する前に。 これにより、答えが少なくとも最小の章の価格でなければならないと仮定するというよくある間違いを防ぐことができます。 

すでに完了した間隔の後のギャップについては、次のことを考慮してください。```
4
1 2 2 10
```仕分け後の最初の価格`1`変化`reachable`から`0`に`1`。 価格`2`満足する`2 <= 2`、 それで`reachable`になる`3`。 次は`2`満足する`2 <= 4`、範囲を拡張します`5`。 最終価格`10`より大きい`6`、 それで`6`形成できずに返されます。 の 2 つの小さいコピー`2`demonstrate why the algorithm must consider the entire already reachable interval rather than only individual subset sums.

 等価境界は次のように処理されます。```
3
1 1 3
```最初`1`与える`reachable = 1`、そして2番目は与えます`reachable = 2`。 次の価格はまさに`3`に等しい`reachable + 1`, したがって、それは受け入れられる必要があります。 到達可能な間隔は次のように拡張されます。`5`、そして答えは次のようになります`6`。 次のような厳密な比較を使用する`x >= reachable + 1`間違って戻ってきます`3`。 

非常に大きなチャプタ値には特別な処理は必要ありません。 のために```
3
1000000000000 1000000000000 1000000000000
```最初に並べ替えられた価格はすでに次の値を超えています`reachable + 1 = 1`、したがってアルゴリズムは戻ります`1`。 これは、考えられる金額によってインデックス付けされた DP が間違った抽象化である理由も示しています。実際の答えが小さい場合でも、数値が巨大になる可能性があります。
