 ## 解決策
 ## 問題の理解

 単一の山の石に適用される一連の操作が与えられています。 各操作は、石を 1 つ追加するか、石を 1 つ削除することです。 重要な制約は、除去が行われるたびに、その操作の前に山に少なくとも 1 つの石が含まれていることが保証されるということです。つまり、実際のプロセスで無効な除去が観察されることはありません。 

ただし、最初の石の数は教えられません。 目標は、空のパイルから削除しようとせずにシーケンス全体を実行できるように、可能な限り小さい開始値を選択し、すべての操作を適用した後の最終的なパイル サイズを計算することです。 

難しいのは、開始値が実現可能性に影響を与えることです。 開始値が低すぎると、一部のプレフィックスの除去が不可能になります。 開始値が高すぎると、最終的な値も必要以上に高くなります。 無効な状態を回避する最小の開始値が必要であり、その結果の終了値を計算します。 

制約$n \le 100$十分小さいため、リニア スキャンまたはプレフィックス シミュレーションで十分です。 可能な開始値に対する二次関数の総当たり攻撃も許容されますが、その必要はありません。 

シーケンスが除去で始まるとき、微妙なエッジケースが現れます。 たとえば、入力`---`初期パイルを少なくとも 3 にするように強制します。そうでない場合、最初の操作はすでに失敗します。 別のケースは、次のような混合シーケンスです。`-+--`ここで、初期の増分は、初期オフセットに応じて、後の低下を相殺する場合も、相殺しない場合もあります。 ゼロから開始し、無効な状態をローカルで「修正」するだけの単純なシミュレーションでは、必要な初期値が過小評価される可能性があります。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての初期パイル サイズが試行されます。 各候補の開始値について$x$、シーケンスをシミュレートします: に 1 を追加します。`+`そして1を減算します`-`、山がマイナスになるシミュレーションを拒否します。 有効なうち$x$、最小のものを選択して、最終結果を計算します。 

これは状態空間が小さいため機能しますが、最大でシミュレートする可能性があるため、精神的には非効率です。$n$各候補者に対する操作$x$、 そして$x$それ自体は最大まで行くことができます$n$。 これにより、$O(n^2)$シミュレーションは、ここではまだ問題ありませんが、実際の構造を隠します。 

重要な観察は、重要なのは、ゼロから開始した場合に演算のプレフィックス合計がどれだけ低くなるかだけであるということです。 それぞれ`-`それぞれ残高が減ります`+`それを増やします。 ゼロから始まるランニングバランスを定義すると、それが到達する最小値によって、マイナスにならないようにプロセス全体をどれだけ上方にシフトする必要があるかがわかります。 

最小プレフィックス合計が$m$、それでは少なくとも以下から始める必要があります$-m$有効性を保証するための石。 このシフト後の最終結果は、すべての演算の合計にこのオフセットを加えたものになりますが、必要なのは最終的な最小パイル サイズのみであるため、直接計算に集約されます。

 ## アルゴリズムのチュートリアル

 私たちは解釈します`+`+1として、そして`-`-1 として、最初の山がゼロであるかのように実行中のプレフィックスの合計を追跡します。 

1. 変数を初期化する`balance = 0`、未知のベースラインに対する現在の石を表します。 これはゼロからのスタートをシミュレートします。 
2.初期化`min_balance = 0`、スキャン中に検出された最小のプレフィックス値を記録します。 これは、シーケンスがゼロよりどれだけ下に行こうとするかを捕捉します。 
3. 文字列を左から右にスキャンします。 各キャラクターについて:

 そうであれば`+`、増分`balance`1によって。`-`、デクリメント`balance`1までに。 
4. アップデート後`balance`、 アップデート`min_balance = min(min_balance, balance)`。 これは、ゼロから開始した場合にシーケンスによって引き起こされる最も深い欠損を追跡します。 
5. すべての操作を処理した後、必要な最小の開始石は次のとおりです。`-min_balance`。 これにより、最下点がゼロになるように軌道全体がシフトされます。 
6. 最終的なパイル サイズは、単に調整された最終バランスであり、合計に必要なオフセットを加えたものに等しくなります。 ゼロからの最終残高は既知であるため、次のように直接計算します。`balance - min_balance`。 

### なぜ効果があるのか

 接頭辞の合計は、ゼロから開始した場合に山がどのように発展するかを表します。 負のプレフィックス値は、不可能な中間状態に対応します。 初期パイルに一定のオフセットを追加すると、状態間の相対的な差を変えることなく、プレフィックス カーブ全体が上にシフトします。 すべてのプレフィックスを非負にする最小のオフセットは、正確に最小プレフィックス合計の絶対値です。 シフトされると、最終状態は一意に決定されるため、この構築により、有効な最小の開始構成が得られ、したがって、可能な最小の最終杭サイズが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

balance = 0
min_balance = 0

for ch in s:
    if ch == '+':
        balance += 1
    else:
        balance -= 1
    if balance < min_balance:
        min_balance = balance

# minimal initial stones needed
start = -min_balance

# final stones after all operations
print(balance + start)
```このコードは、アルゴリズムで説明されているのと同じプレフィックス プロセスを追跡します。 の`balance`変数は操作の正味の効果を表しますが、`min_balance`最悪の赤字を計上。 計算された`start`中間の負のパイル サイズを防止する最小の安全なオフセットです。 それを最終バランスに追加すると、達成可能な最小の終了パイルが得られます。 

実装でよくある落とし穴は、最終的な答えが合計バランスと最小プレフィックスの両方に依存することを忘れていることです。 合計のみを使用すると、次のようなシーケンスでは失敗します。`--+`、最終的な結果よりも中間状態の方が重要です。 

## 実用的な例

 ### 例 1:`---`| ステップ | 操作 | バランス | 最小残高 |
 | --- | --- | --- | --- |
 | 1 | - | -1 | -1 |
 | 2 | - | -2 | -2 |
 | 3 | - | -3 | -3 |

 ここでは最小の接頭辞は -3 なので、3 つの石から始める必要があります。 ゼロからの最終残高は -3 なので、調整結果は -3 + 3 = 0 となります。 

これは、各ステップで新しい最小値が強制されるケースを示しており、答えは完全にプレフィックスの深さによって決まります。 

### 例 2:`-+-+`| ステップ | 操作 | バランス | 最小残高 |
 | --- | --- | --- | --- |
 | 1 | - | -1 | -1 |
 | 2 | + | 0 | -1 |
 | 3 | - | -1 | -1 |
 | 4 | + | 0 | -1 |

 最小の接頭辞は -1 なので、1 つの石から始めます。 最終残高は0なので、答えは1です。 

これは、正味合計がゼロの場合でも、初期のディップが必要な初期オフセットを決定することを示しています。

## テストケース```python

def solve(inp: str) -> str:
    import sys
    sys.stdin = io.StringIO(inp)
    s = sys.stdin.readline().strip()

    balance = 0
    min_balance = 0

    for ch in s:
        if ch == '+':
            balance += 1
        else:
            balance -= 1
        if balance < min_balance:
            min_balance = balance

    start = -min_balance
    return str(balance + start)

 ## 特殊なケース

 次のようなシーケンスの場合`---`、プレフィックスのシミュレーションは -1、-2、-3 になります。 アルゴリズムの記録`min_balance = -3`したがって、必要な開始値は 3 です。完全なシーケンスを適用した後、調整された最終結果はゼロになり、すべての初期石が正確に消費されるという直感と一致します。 

次のようなシーケンスの場合`-+-+`、プレフィックスは最初の操作で -1 に下がり、それより下がることはありません。 アルゴリズムセット`min_balance = -1`したがって、開始値は 1 です。ゼロからの最終残高は 0 であるため、出力は 1 となり、最初の除去を生き残るために 1 つの初期石が必要であることが正しく反映されています。 

次のようなシーケンスの場合`+-+-`、バランスはマイナスになることなく 0 と 1 の間を振動します。 最小プレフィックスは 0 のままであるため、初期石は必要ありません。 最終結果も 0 であり、追加と削除が実行可能性の問題なく相殺されるという事実と一致します。
