 ## 解決策
 ## 問題の理解

 ダンス フロアは長方形のグリッドで、各セルには通常の向きまたは反転した人が含まれています。 特定の操作を何度でも適用して、グリッド全体をすべてゼロに変換したいと考えています。 

位置のセルを選択することで 1 つの操作が選択されます$(R, C)$。 この操作により、サブ四角形内のすべてのセルが左上隅から切り替わります。$(1,1)$まで$(R,C)$。 その四角形内のすべてのセルの状態が反転します。0 は 1 になり、1 は 0 になります。タスクは、グリッド全体がゼロになるように必要なこのような接頭辞と四角形の切り替えの数を最小限に抑えることです。 

重要な制約は、最大のグリッド サイズです。$3000 \times 3000$これは最大 900 万個のセルを意味します。 完全な部分行列に対して各操作を素朴にシミュレートしようとするソリューションは、非常に遅すぎます。 平$O(NM\min(N,M))$は境界線にあるため、ソリューションは本質的に線形時間でグリッドを処理する必要があります。 

グリッドがすでにすべてゼロである場合、微妙なエッジ ケースが発生します。 ゼロ以外のセルごとに少なくとも 1 つの操作を常に実行する不注意なアプローチでは、誤って肯定的な応答が返される可能性があります。 もう 1 つの注意が必要なケースは、単一の行または列で貪欲な選択が連鎖的に相互作用する場合です。次に例を示します。 

入力:```
1 4
1 0 1 0
```正解は 2 です。単純なローカル反転戦略では、各セルを個別に修正し、各操作が以前のすべての位置に影響を与えるため、操作を過剰にカウントしようとする可能性があります。 

主な課題は、各操作が両方の次元のプレフィックスに影響を与えるため、セルごとに独立していない 2D 依存構造が作成されることです。 

## アプローチ

 強引なアイデアは、プロセスを直接シミュレートすることです。 各ステップで、グリッドをスキャンして現在 1 であるセルを見つけ、そのセルに演算を適用して、プレフィックスの四角形全体を反転します。 これは正しいです。最終的には、選択したプレフィックスに含まれるすべての 1 を削除する必要があるからです。 ただし、各操作で次の点に到達する可能性があります。$O(NM)$まで適用できます。$O(NM)$最悪の場合の運用。 これは次のことにつながります$O(N^2 M^2)$、それは完全に不可能です。 

重要な観察は、視点を逆転させることです。 操作について考えるのではなく、さまざまな位置で選択された操作が各セルにどのような影響を与えるかを考えてください。 細胞$(i,j)$位置で選択されたすべての操作によって正確に切り替わります$(R,C)$そのような$R \ge i$そして$C \ge j$。 これは、古典的な 2D プレフィックス支配構造です。 

グリッドを右下から左上に処理する場合、セルの値を決定するときに、セルに影響を与える下または右からのすべての操作がすでに決定されています。 これにより、次の時点で新しい操作が必要かどうかを貪欲に決定できるようになります。$(i,j)$すでに適用されているフリップのパリティに基づきます。 

2D パリティ構造は維持されますが、それを完全なグリッドとして明示的に保存することはありません。 代わりに、逆プレフィックス蓄積のアイデアを使用して影響を伝播します。 本質的な単純化は、私たちがセルにいるとき、$(i,j)$、最終値を修正する唯一の方法は、操作を次の場所に配置するかどうかを決定することです。$(i,j)$それ自体が、それに対して左上のセルにのみ影響する最小のプレフィックスであるためです。 

したがって、逆の順序で処理し、各位置にすでに影響を与えたフリップの数を累積し、以前の寄与を考慮した後、現在のセルがまだ 1 であるときはいつでも新しい演算を貪欲に適用します。

 ## アルゴリズムのチュートリアル

 ## 1. 操作をパリティ寄与として解釈する

 選択された各操作は、$(i,j)$長方形内のすべてのセルを反転します$[1..i] \times [1..j]$。 つまり、すべてのセルの最終状態は、行インデックスと列インデックスの両方で選択された操作の数がセルを支配するかどうかによってのみ決まります。 

## 2. グリッドを右下から左上に処理します

 繰り返します$i$から$N$まで$1$、 そして$j$から$M$まで$1$。 この時点で、影響を与える可能性のあるすべての細胞が$(i,j)$将来の決定（すなわち、$(i',j')$と$i' \ge i, j' \ge j$）はすでに決まっています。 

この方向が重要である理由は、$(i,j)$影響を与える最小の長方形です$(i,j)$したがって、これは、すでに固定されたより大きなインデックスを再破壊することなく、それを修正できる唯一のローカル決定です。 

## 3. 2D フリップ パリティ構造を維持する

 2D 差分配列を使用して、これまでに各セルが何回反転されたかを追跡します。 四角形内のすべてのセルを直接更新する代わりに、標準の包含/除外更新を適用して、プレフィックスの合計が任意のセルのフリップ カウントを回復するようにします。 

で操作を「アクティブ化」すると、$(i,j)$、長方形に 1 を加えます。$[1..i] \times [1..j]$差分配列で。 

## 4. 各セルの現在のパリティを問い合わせる

 で決める前に$(i,j)$、現在何回のフリップがそれに影響を与えているかを計算します。 現在の値 XOR 累積フリップが 1 の場合、次の時点で新しい演算を適用する必要があります。$(i,j)$。 

これが強制されるのは、既に処理された構造の正確性を損なうことなく、今後の操作 (辞書編集的に小さい座標での) がこのセルに影響を与えることができないためです。 

## 5. 回答を蓄積し、構造を更新する

 以前の反転を考慮した後でセルがまだ 1 である場合、答えをインクリメントし、新しい操作を反映するために差分構造を更新します。 

## なぜ機能するのか

 重要な不変条件は、セルを処理するときの条件です。$(i,j)$、厳密に下または右のセルに影響を与えるすべての決定はすでに修正されており、それらの寄与はパリティ構造で完全に考慮されます。 したがって、現在計算されたパリティは、$(i,j)$以前に決定されたすべての操作に関して最終的なものとなります。 

新しい操作は次のとおりです$(i,j)$細胞のみに影響を与える$(1..i, 1..j)$、すでに処理されているか、現在のセルが含まれています。 今後のステップはより小さいプレフィックスに対してのみ動作するため、時点での間違いを遡及的に修正することはできません。$(i,j)$。 これにより、貪欲な決定がローカルに最適化され、グローバルに一貫性のあるものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]

    # 2D difference array for prefix toggles
    diff = [[0] * (m + 2) for _ in range(n + 2)]

    def get(i, j):
        return (diff[i][j]
                + diff[i - 1][j]
                + diff[i][j - 1]
                - diff[i - 1][j - 1])

    ans = 0

    for i in range(n, 0, -1):
        row_acc = 0
        for j in range(m, 0, -1):
            cur = (diff[i][j]
                   + diff[i + 1][j]
                   + diff[i][j + 1]
                   - diff[i + 1][j + 1])

            val = grid[i - 1][j - 1]
            cur %= 2

            if (val + cur) % 2 == 1:
                ans += 1
                diff[i][j] += 1
                diff[i][j + 1] -= 1
                diff[i + 1][j] -= 1
                diff[i + 1][j + 1] += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、2D 差分配列を使用してプレフィックスの反転を表します。 それぞれの操作は、$(i,j)$は、四隅の包含/除外を使用した四角形の更新としてエンコードされます。 

現在のフリップ パリティのクエリ$(i,j)$は、差分配列に対する標準の 2D プレフィックス再構成式を使用して計算されます。 グリッドは右下から左上に処理されるため、セルで決定するときに、選択した順序でセルに論理的に影響を与えるすべての操作の効果がすでにわかります。 

よくある間違いは、差分配列のインデックスがグリッドを 1 ステップ超えて拡張されていることを忘れることです。 実装は安全に割り当てます$n+2 \times m+2$更新を適用する際の境界の問題を回避するため$i+1$または$j+1$。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すでにクリーンなグリッドです。 この状況では、すべてのセルがパリティ 0 と評価されるため、アルゴリズムは更新をトリガーしません。そのため、答えは 0 のままです。 これにより、最初のセルの解釈を誤ったために少なくとも 1 つの操作を強制するというよくある間違いを回避できます。 

もう 1 つの特殊なケースは単一行です。 すべての操作がプレフィックス セグメントになるため、アルゴリズムは右から左への 1D 貪欲スキャンに縮小されます。 右下から左上へのトラバースは自然にその動作に縮退し、各反転はすでに解決された位置に影響を与えることなく将来の不一致を正しくキャンセルします。 

最後のエッジ ケースは、完全に密な 1 のグリッドです。 このアルゴリズムは、(1,1) で 1 つの操作を正確に適用します。これは、すべてのセルを処理した後、累積されたパリティが、単一のグローバル プレフィックス フリップが 1 回の移動でグリッド全体を解決し、すべてのトグルを 1 つの操作に最適に圧縮することを示しているためです。
