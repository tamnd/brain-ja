 ## 解決策
 ## 問題の理解

 エビをのせていきます$n \times m$グリッド。各セルにはエビを含めることも、空にすることもできます。 各構成は単なるバイナリ行列です。 

グリルには、毎回ローカルでのみ有効になるルールがあります。$2 \times 2$サブグリッド。 そのようなものの中にある場合$2 \times 2$ブロックのエビの数が奇数の場合、そのブロックは火傷イベントを引き起こします。 問題は書き込みをシミュレートすることではなく、グリッド構成全体に少なくとも 1 つが含まれる数を数えることです。$2 \times 2$奇数パリティを持つサブグリッド。 

したがって、タスクは純粋に組み合わせです。サイズのバイナリ グリッドをすべて数えます。$n \times m$少なくとも 1 つの点でパリティ条件に違反している$2 \times 2$四角。 

入力サイズは最大です$2000 \times 2000$, したがって、グリッドには最大 400 万個のセルを含めることができます。 すべてのグリッドに対する総当りの列挙には、次のことが含まれます。$2^{4 \cdot 10^6}$という状態ですが、それは全く不可能です。 単一の構成コストを確認するだけでも$O(nm)$したがって、すべてのグリッドを反復するアプローチは直ちに除外されます。 

もう少し微妙な失敗例は、それぞれを処理しようとした場合に発生します。$2 \times 2$独立して。 これらのサブグリッドは重なり合う部分が多いため、ローカルで有効なパターンを選択しても、グローバルな一貫性は保証されません。 

たとえば、$2 \times 3$グリッドでは、列 1-2 および 2-3 の制約が中央の列を共有します。 貪欲またはローカルなカウント手法では、共有構造が 2 倍にカウントされるため、過剰にカウントされます。 

正しいアプローチでは、代わりにグリッドのグローバル構造を特徴付ける必要があります。$2 \times 2$サブグリッドには偶数パリティがあり、全空間から減算されます。 

## アプローチ

 私たちは最も直接的なアイデアから始めます。 がある$2^{nm}$グリッドを埋める方法。 それぞれについて、すべてをスキャンできます$(n-1)(m-1)$サブグリッドを調べて、合計が奇数のものがあるかどうかを確認します。 これは正しいですが、遅すぎます。すべてのグリッドを生成するにはすでに指数関数的な時間がかかり、単一のチェックですら二次的です。 

したがって、「悪い」グリッドを直接カウントする代わりに、問題を逆転させます。 補数を数えます: グリッドがない場合$2 \times 2$サブグリッドの合計が奇数です。 これらはまさに、あらゆるものが必要となる構成です。$2 \times 2$ブロックは偶数パリティを持ちます。 

この条件は非常に厳しいです。 どれでも取ってください$2 \times 2$ブロック：$$a_{i,j} \oplus a_{i,j+1} \oplus a_{i+1,j} \oplus a_{i+1,j+1} = 0$$並べ替えると次のようになります。$$a_{i+1,j+1} = a_{i,j} \oplus a_{i,j+1} \oplus a_{i+1,j}$$これは、最初の行と最初の列を修正すると、グリッド全体が強制されることを意味します。 1 つおきのセルは段階的に計算できます。 

これをより構造的に理解するには、グリッドが XOR 上の線形システムを満たす必要があるということです。 解空間は正確に$n + m - 1$自由度: 最初の行と最初の列のすべての値を選択します。$a_{1,1}$共有されました。 

したがって、「安全な」グリッドの数 (奇数ではありません)$2 \times 2$） は$2^{n+m-1}$。 それ以外はすべて有効な答えです。 

したがって、必要な数は次のようになります。$$2^{nm} - 2^{n+m-1}$$計算されたモジュロ$998244353$。

 ## アルゴリズムのチュートリアル

 1. サイズのバイナリ グリッドの総数を計算します。$n \times m$、つまり$2^{nm}$。 これは、制限のないすべての可能なエビの配置を表します。 
2. すべてのグリッドの数を計算します。$2 \times 2$サブグリッドは偶数パリティを持ちます。$2^{n+m-1}$。 これは、最初の行と最初の列が選択されると、他のすべてのセルが XOR 制約によって一意に決定されるという事実から来ています。 
3. 合計数から制約された数を減算して、少なくとも 1 つの違反を含む構成を分離します。$2 \times 2$サブグリッド。 これにより、$2^{nm} - 2^{n+m-1}$。 
4. すべてのべき乗モジュロを実行します。$998244353$数値は指数関数的に増加するため、計算中に減らす必要があるためです。 

どちらの指数も 400 万にも達する可能性があるため、重要な計算ツールは高速累乗です。 

### なぜ効果があるのか

 あらゆる制約$2 \times 2$ブロックは、グリッド全体に伝播する XOR に対する線形関係を強制します。 最初の行と列が固定されると、残りのすべてのセルが以前に決定された値によって強制されます。 これにより、以下を除くすべての自由が剥奪されます。$n + m - 1$独立したビットなので、有効なグリッドの空間は正確にその次元のベクトル空間になります。 構成のカウントは、これらの自由変数へのバイナリ割り当てのカウントになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modpow(a, e):
    res = 1
    a %= MOD
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def solve():
    n, m = map(int, input().split())
    
    total = modpow(2, n * m)
    safe = modpow(2, n + m - 1)
    
    ans = (total - safe) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```実装は完全にべき乗剰余演算に依存しています。 最初の呼び出しでは完全な構成空間が計算され、2 番目の呼び出しでは XOR 一貫性によって定義された構造化された部分空間が計算されます。 減算はモジュロで計算されます$998244353$, そのため、最終調整により非負性が保証されます。 

よくある間違いは、グリッドを反復処理したり、制約をローカルでシミュレートしようとしたりすることです。 正しい視点は、ローカルなチェックではなく、グローバルな線形構造です。

 ## 特殊なケース

 重要なエッジケースは最小の有効なグリッドです$2 \times 2$。 この場合、ちょうど 1 つあります$2 \times 2$したがって、問題は、4 つのセルすべての XOR が奇数であるバイナリ行列をカウントすることに帰着します。 式は次のようになります$16 - 8 = 8$、直接列挙に一致します。 

のために$2 \times m$グリッドでは、構造は簡素化されていますが、同じルールに従います。 列を追加するたびに、完全な空間では 1 つの自由度が追加されますが、安全な空間では 1 つの制約のみが追加されます。 指数演算のみに依存するため、この数式は一貫してこれを処理します。 

ような大きなグリッドの場合$2000 \times 2000$、指数$nm$は非常に大きくなりますが、べき乗剰余演算は対数時間で処理します。 正確さは大きさには依存せず、制約空間の代数構造にのみ依存します。
