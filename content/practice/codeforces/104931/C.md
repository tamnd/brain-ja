 ## 解決策
 ## 問題の理解

 私たちにはいくつかのスロット マシンが与えられており、それぞれを引くとランダムな報酬が得られます。 各マシンには、考えられる報酬値の小さなセットに対して独自の固定確率分布があります。 正確に実行することが許可されています`n`合計でプル数があり、各プルをいずれかのマシンに割り当てることができます。 さまざまなプルは独立しており、マシンの分布は時間の経過とともに変化しません。 

目標は、配布方法を決定することです。`n`期待される合計報酬ができるだけ大きくなるように、マシン全体を引っ張ります。 すべてのプルが完了した後は、実際の結果のシーケンスではなく、この可能な最大の期待値のみが求められます。 

制約は小さいです:両方とも`n`そして`k`最大 100 ですが、各分布には最大 1000 の結果を含めることができます。 これは、マシンとプルに関する 2 次または 3 次の解法でも受け入れられることをすでに示唆していますが、プルごとの分布に対する組み合わせ割り当てを伴うものは不要です。 各マシンの期待値を慎重に再計算するソリューションは、十分に高速です。 

多くの誤ったアプローチにおける微妙な失敗モードは、複数のプルにわたる合計報酬の完全な確率分布をモデル化しようとすることです。 たとえば、各プルの後に可能な合計に対して動的プログラミングを試みる場合があります。 この問題では分散や分布形状ではなく期待値のみが求められるため、これは不要です。 もう 1 つのよくある間違いは、賢いパターンでマシン間でプルをインターリーブする必要があると仮定することです。 実際には、各プルは独立しており、期待値に追加的に寄与するため、順序付けは影響しません。 

間違った方向の具体例として、2 台のマシンの期待値は同じだが、スプレッドが異なるとします。 分散追跡ソリューションは、期待値が分散に依存していないにもかかわらず、誤って「より安全な」マシンを優先しようとする可能性があります。 正しい答えは、リスクではなく、平均報酬のみに依存します。 

## アプローチ

 この問題を素朴に解釈すると、次のように割り当てなければなりません。`n`個別のアクション (プル)、それぞれが次のいずれかを選択します。`k`それぞれのアクションはランダムな結果をもたらします。 すべての可能な割り当てを列挙する総当り的なソリューションを想像することもできます。`n`マシン間でプルし、各割り当ての期待値を評価します。 

各割り当てについて、期待を適切にシミュレートした場合でも、分布からのプルごとに期待される報酬を計算する必要があります。 マシンごとの期待値が事前に計算されている場合でも、割り当ての数は`k^n`、それぞれの`n`プルは次のいずれかを独立して選択できます`k`機械。 と`n = 100`、これは天文学的に大きくなり、完全に実行不可能になります。 

重要な観察は、期待は線形であるということです。 複数の独立したプルの期待される合計報酬は、マシンの選択間の依存関係に関係なく、各プルの期待される報酬の合計にすぎません。 これは、各プルが使用するマシンのみに基づいて独立して寄与することを意味します。 最適なマシンを繰り返し選択するよりも優れた混合戦略を実現できるプル間の相互作用はありません。 

線形性を受け入れると、構造が崩壊します。各マシンにはプルごとに固定の期待報酬があり、すべてのプルは最大の期待値を持つマシンに送られる必要があります。 これ以上複雑な割り当ては必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | プルのブルート フォース割り当て | O(k^n) | O(n) | 遅すぎる |
 | 期待値を計算して最大値を選択する | O(k * m_i) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各マシンの確率分布を 1 つの数値、つまりプルごとに期待される報酬に変換し、最適なマシンを選択するという手順で進めます。 

1. 各マシンについて、考えられる報酬と対応する確率のリストを読みます。 

このマシンからの 1 回のプルの期待値は、結果の加重合計です。 
2. 期待値を計算する`E_i = sum(r_j * p_j)`各マシンごとに`i`。 

これにより、分布全体が長期平均ゲインを表す 1 つのスカラーに分解されます。 
3. すべてのマシンの最大期待値を追跡します。 
4. この最大期待値に次の値を掛けます。`n`、すべてから`n`プルはその最高のマシンに割り当てられる必要があります。 

最終的な答えは、`n * max(E_i)`。 

### なぜ効果があるのか

 各プルは独立した確率変数に寄与し、その期待値は選択したマシンにのみ依存します。 期待される報酬の合計は、個々のプルの期待値の合計です。 期待は加算的なものであるため、マシン間でプルを再配置しても、期間を超えた効果や相乗効果は生まれません。 期待値が小さいマシンを使用する割り当ては、そのプルを期待値が大きいマシンに移動し、期待値の合計を厳密に増加させることで改善できます。 これは、最適なソリューションでは、すべてのプルが常に最大の期待値を持つ単一のマシンに割り当てられることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    
    best = 0.0
    
    for _ in range(k):
        m = int(input())
        rewards = list(map(int, input().split()))
        probs = list(map(float, input().split()))
        
        exp = 0.0
        for r, p in zip(rewards, probs):
            exp += r * p
        
        if exp > best:
            best = exp
    
    print(n * best)

if __name__ == "__main__":
    solve()
```実装は、期待値の最大化への削減の直後に行われます。 各マシンは独立して処理され、その期待値は報酬と確率の内積として計算されます。 維持される唯一のグローバル状態は、これまでに見られた最大の期待値です。 

よくある落とし穴は、動的プログラミングを使用してプルを複数のマシンに分散しようとすることです。 プル間の収益逓減や依存関係がないため、これは不要です。 

値には制限があり、必要な精度は次のとおりであるため、浮動小数点精度で十分です。`1e-6`。 標準の倍精度は、マシンごとに最大 1000 語の蓄積を快適に処理します。 

## 実用的な例

 2 台のマシンと合計 3 つのプルがある小規模なインスタンスを考えてみましょう。 

マシン 1 は、確率 0.5 で報酬 10 を与え、確率 0.5 で報酬 0 を与えます。 期待値は5.0です。 

マシン 2 は確率 1.0 で報酬 3 を与えます。 期待値は 3.0 です。 

| 機械 | 期待値 |
 | --- | --- |
 | 1 | 5.0 |
 | 2 | 3.0 |

 | ステップ | これまでで最高 |
 | --- | --- |
 | マシン 1 以降 | 5.0 |
 | マシン2以降 | 5.0 |

 結果は`3 * 5.0 = 15.0`。 

ここで、マシンが多くの結果をもたらすが、平均値が低い場合を考えてみましょう。 マシン A に結果があると仮定します。`[0, 100]`確率的に`[0.99, 0.01]`、マシン B は常に 1 を返します。マシン A の期待値は 1.0、マシン B の期待値も 1.0 です。 どの割り当てでも同じ期待値が得られるため、すべてのプルをいずれかのマシンに割り当てるのが最適です。 

これにより、分散は重要ではなく、平均だけが解を導くことがわかります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k・m_i) | 各マシンの期待値は、その分布に対する 1 回のパスによって計算されます。 
| スペース | お(1) | 入力バッファリングを超えて保存されるスカラーはわずかです。 

この制約により、それぞれ最大 1000 個の結果を持つ最大 100 台のマシンが許可されるため、最大 100,000 回の乗算が実行されます。 これは容易に制限内に収まり、メモリ使用量は入力ストレージを除けば一定です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from math import isclose

    best = 0.0
    for _ in range(k):
        m = int(input())
        r = list(map(int, input().split()))
        p = list(map(float, input().split()))
        exp = sum(ri * pi for ri, pi in zip(r, p))
        best = max(best, exp)
    return str(best * n)

 ## 特殊なケース

 重要なエッジケースは、複数のマシンの期待値がまったく同じである場合です。 その状況では、それらの間でのプルの割り当てが最適です。 アルゴリズムは最大期待値のみを追跡し、どのマシンがそれを達成するかに依存しないため、これを自然に処理します。 

もう 1 つのケースは、すべてのマシンの期待値がゼロの場合です。 それでも、計算された期待値はゼロのままであり、次のように乗算します。`n`正しさを保ちます。 最大値はゼロのままであるため、特別な処理は必要ありません。 

最後の微妙なケースは、確率が非常に小さい場合、または値が上限に近い場合の数値精度です。 すべての報酬は 100 で制限されており、マシンごとに最大 1000 の用語があるため、蓄積された浮動小数点誤差は必要な値を大幅に下回ったままになります。`1e-6`許容範囲。
