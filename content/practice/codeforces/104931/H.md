 ## 解決策
 ## 問題の理解

 長さのシーケンスを数えています$N$カードランクの固定セットから形成されます。 ランクは全体の順序のように動作します。エースが最小で、次に 2 からキングまでです。 重要な制限は、連続するカードの変更がどのように許可されるかです。 

シーケンスの最初のカードは任意のランクにすることができます。 その後、新しいカードはそれぞれエースになるか、前のカードよりも厳密に高いランクを持つ必要があります。 これにより、Ace が一種のリセット値としてどこにでも出現する可能性があることを除いて、主にランクが上昇するシーケンスが作成されます。 

入力により得られるのは、$N$、シーケンスの長さ、そして有効なシーケンスがいくつ存在するかを計算する必要があります。ここで、少なくとも 1 つの位置のランクが異なる場合、2 つのシーケンスは異なるものとみなされます。 

制約$N \le 20$は十分に小さいため、位置ごとに一定数の状態を使用して動的プログラミングを行うことができます。 ランク数も固定 (13) なので、多項式の解はすべて$N$ランクも十分に速くなります。 これにより、すべてのシーケンスの指数関数的な列挙が即座に除外されます。$13^N$、中程度の場合でも巨大になります$N$。 

すべてのシーケンスを生成して妥当性をチェックする単純なアプローチも失敗します。これは、分岐係数が各ステップで 13 であるため、合計作業量は次のとおりです。$13^{20}$、これは実行可能な計算をはるかに超えています。 

微妙な点はエースの役割だ。 エースは以前のランクに関係なく常に許可されるため、他のランクとは異なる動作をし、トランジションでは個別に処理する必要があります。 この非対称性を無視すると、特に次のような小さな場合に、誤ったカウントが発生します。$N=2$ここでは、Ace トランジションの寄与が有効なペアの大部分を占めています。 

## アプローチ

 ブルート フォース ソリューションでは、シーケンスが段階的に構築されます。 各ポジションで、13 の可能なランクすべてを試し、前のランクからの移行が有効かどうかを確認します。 これはルールを直接適用するため正しいですが、実行時間は次のようなものに応じて指数関数的に増加します。$N$。 具体的には大まかに調べます$13^N$シーケンスは、たとえ$N=20$、という順番なので、$10^{22}$可能性。 

制約の構造により、より高速なアプローチが可能になります。 シーケンスの各状態は前のランクのみに依存し、遷移は次のランクが前のランクより大きいかエースであるかのみに依存します。 これは、同じ長さのすべての部分シーケンスを、終了ランクごとにグループ化されたカウントに圧縮できることを意味します。 

シーケンスを最後のカードごとにグループ化すると、動的プログラミングを使用してシステムを記述することができます。 個々のシーケンスを追跡する代わりに、長さの有効なシーケンスの数を追跡します。$i$各ランクで終了します。 状態間の遷移は単純なプレフィックスの合計になります。高いランクへの移動は、すべての小さな終了ランクに依存しますが、Ace への移動は、前のランクに関係なくすべての状態に依存します。 

これにより、問題は指数関数的な列挙から、繰り返される 13 の状態にわたる小さな DP に軽減されます。$N$回。

 ## アルゴリズムのチュートリアル

 シーケンスの長さと終了ランクにわたる DP としてプロセスをモデル化します。 

1. DP 配列を定義します。$dp[i][r]$有効な長さのシーケンスの数です$i$ランクで終わる$r$。 ランク$r=1$エースを表し、$r=13$キングを表します。 
2.初期化$dp[1][r] = 1$ランクごとに$r$1 枚のカード シーケンスはランクの選択に関係なく常に有効であるためです。 
3. ポジションごとに$i$2から$N$、すべてのランクの遷移を計算します$r$。 
4. ランクについて$r = 1$(エース)、以前のすべてのシーケンスはエースに移行できるため、$dp[i][1]$すべての合計です$dp[i-1][r]$。 これはエースが常に許可されるという特別なルールを表しています。 
5. ランクについて$r > 1$、シーケンスは次で終了できます。$r$前のランクが厳密に小さい場合のみ$r$。 これはつまり$dp[i][r]$すべての合計に等しい$dp[i-1][k]$のために$k < r$。 
6. DP テーブルを長さまで埋めた後$N$、答えはすべての合計です$dp[N][r]$すべてのランクにわたって。 

重要な最適化は、前の DP 行に対するプレフィックスの合計を計算することです。これにより、すべての小さなランクを繰り返しスキャンするのではなく、各遷移を一定時間で計算できるようになります。 

### なぜ効果があるのか

 すべてのステップで、同じランクで終了する同じ長さのすべてのシーケンスは、将来の拡張に関して交換可能です。これは、将来の有効性が最後のランクにのみ依存するためです。 DP 状態はこの最終ランクの依存関係を正確に捕捉し、遷移ルール​​は元のシーケンス定義で許可されている動きと正確に一致します。 これにより、有効なシーケンスが見逃されたり、無効なシーケンスがカウントされたりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input().strip())
    R = 13  # Ace to King

    dp = [1] * R  # dp for length 1

    for _ in range(2, n + 1):
        new_dp = [0] * R

        total = sum(dp) % MOD
        new_dp[0] = total  # Ace

        prefix = 0
        for r in range(1, R):
            prefix = (prefix + dp[r - 1]) % MOD
            new_dp[r] = prefix

        dp = new_dp

    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```DP アレイ`dp[r]`ランクで終わるシーケンスのカウントを保存します$r$。 各反復で、`new_dp[0]`Ace は普遍的に到達可能であるため、以前のすべての状態を集約します。 より高いランクの場合、ループはプレフィックスの合計を構築します。`new_dp[r]`より小さいランクで終わるすべてのシーケンスを正しくキャプチャします。 

Python の整数は大きさを安全に処理しますが、オーバーフローを防ぐためにモジュロが全体に適用されます。

 ## 特殊なケース

 のために$N=1$の場合、すべての単一ランクがスタンドアロン シーケンスとして有効であるため、答えは単純に 13 になります。 DP はランクごとに 1 つのシーケンスで正確に初期化されるため、結果はすぐに一致します。 

のために$N=2$、構造が表示されます。すべてのシーケンスはエースで終わるか、前のランクから増加します。 DP はエースのグローバル貢献と、より高いランクのプレフィックスベースの貢献に正しく分割され、正しい合計 91 が生成されます。 

最大限に$N=20$、DP は依然としてステップごとに一定の状態サイズで実行され、固定の 13 ランク構造によりオーバーフローやパフォーマンスの問題は発生しません。
