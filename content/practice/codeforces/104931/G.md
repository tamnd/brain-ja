 ## 解決策
 ## 問題の理解

 テスト ケースごとに小さな整数の配列が与えられます。 この配列から要素のサブセットを選択することはできますが、完全な配列を選択することは明示的に禁止されています。 サブセットが空の場合もあります。 

選択したサブセットに対して$S$では、サブセットのサイズ、サイズが偶数か奇数かに依存する符号、および選択した要素の立方体の合計の 3 つの部分を組み合わせた値を計算します。 具体的には、各サブセットは、そのサイズに次の値を乗算した値に相当します。$(-1)^{|S|}$次の合計を乗算します$x^3$サブセット内のすべての要素にわたって。 

タスクは、すべての有効なサブセットの中から、この式の可能な最小値と最大値を見つけることです。 

重要な構造上の詳細は、配列の長さが最大 ​​15 であることです。これにより、サブセットの総数が最大 15 になるため、視点が「組み合わせ論による最適化」から「すべてを列挙する」に即座に変わります。$2^{15} = 32768$。 最大 1000 のテスト ケースでも、サブセットのフル スキャンは問題なく制限内に収まります。 

微妙なエッジ状態は、空のサブセットの役割です。 空のセットの場合、サイズと合計は両方とも 0 であるため、値はきれいに 0 と評価されます。 もう 1 つの微妙な点は、フル セットの選択に対する制限です。 つまり、1 つのサブセットは完全な列挙の一部であっても考慮から除外する必要があります。 

式自体は、符号がサブセット サイズのパリティに依存する一方、大きさはサイズに比例して、また立方体の合計にも直線的に比例するため、直感的ではない動作をする可能性があります。 これは、サブセット構成の小さな変更によって符号が反転し、単調でない方法で結果が増幅または縮小される可能性があることを意味しており、貪欲な推論が排除されます。 

## アプローチ

 直接的なアプローチは、配列のすべてのサブセットを反復処理することです。 各サブセットについて、そのサイズとその要素の立方体の合計を計算し、式を評価します。 すべての有効なサブセットの最小値と最大値を追跡します。 

考えられる要素のすべての選択が明示的に考慮されるため、これは正しいです。 このアプローチのコストは、完全にサブセットの列挙によって発生します。 と$N = 15$、テスト ケースごとに 32768 のサブセットがあります。 サブセットごとに最大 15 個の要素をスキャンすることができ、最悪の場合でもテスト ケースごとに約 500k の操作が行われます。 最大 1000 のテスト ケースでは、オーバーヘッドの大きいタイトなループで単純に実装すると大きすぎますが、最適化された Python ではまだ許容できる範囲内です。 より慎重な実装では、キューブ値を事前計算し、ビット演算を使用することで、繰り返し作業を回避します。 

重要な観察は、より深い構造は必要ないということです。 サブセットが相互作用したり、連続領域にわたる最適化が必要になる問題とは異なり、ここでは制約により、総当たり列挙が意図した解決策であることが保証されます。 必要な最適化は、サブセットをビットマスクとして表現し、事前計算することだけです。$A_i^3$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースサブセット列挙 |$O(T \cdot 2^N \cdot N)$|$O(N)$| 最適化により受け入れられます |
 | 事前計算されたキューブを使用したビットマスク |$O(T \cdot 2^N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. サブセットの評価中に累乗を繰り返し計算しないように、各配列要素の 3 乗を事前計算します。 これにより、内側のループ内で繰り返される演算が削減されます。 
2. 0 から 0 までのすべてのビットマスクを反復処理します。$2^N - 1$。 各ビットマスクはサブセットを表します。$i$-th ビットは要素かどうかを示します。$A_i$が含まれています。 
3. この問題ではすべての要素を選択できないため、完全なセットに対応するビットマスクをスキップします。 
4. 残りのビットマスクごとに、選択された要素の数とそれらの選択された要素の 3 乗の合計という 2 つの量を計算します。 これは、ビットをスキャンし、カウントと合計の両方を累積することによって行われます。 
5. 計算された値を使用して式を評価します。 サブセット サイズがゼロの場合、式の定義により寄与はゼロになります。 
6. 評価されたすべてのサブセットにわたってグローバル最小値と最大値を維持します。 
7. すべてのサブセットを処理した後、最小値と最大値を出力します。 

これが正しい構造である理由は、各サブセットが独立しているためです。 あるサブセットの選択肢を別のサブセットの選択肢にリンクする制約がないため、検索空間はパワーセットから 1 つの要素を引いたものに対する独立した評価に完全に分離可能です。 

### なぜ効果があるのか

 フルセット マスクを除くすべての有効なサブセットは 1 つのビットマスクに対応し、すべてのビットマスクは 1 回だけ評価されます。 各マスクの計算は必要な関数の定義と正確に一致するため、アルゴリズムは省略や重複なく解空間の完全な列挙を実行します。 したがって、最小値と最大値は、実行可能な領域全体にわたって取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        N = int(input())
        A = list(map(int, input().split()))
        
        cube = [x * x * x for x in A]
        
        full_mask = (1 << N) - 1
        
        INF = 10**30
        mn, mx = INF, -INF
        
        for mask in range(1 << N):
            if mask == full_mask:
                continue
            
            cnt = 0
            s = 0
            
            m = mask
            i = 0
            while m:
                if m & 1:
                    cnt += 1
                    s += cube[i]
                m >>= 1
                i += 1
            
            if cnt == 0:
                val = 0
            else:
                sign = -1 if cnt % 2 else 1
                val = cnt * sign * s
            
            if val < mn:
                mn = val
            if val > mx:
                mx = val
        
        print(mn, mx)

if __name__ == "__main__":
    solve()
```中心となる実装の詳細はビットマスク ループです。 各マスクはサブセットをエンコードし、完全なマスクを明示的にスキップします。 内側のループはビットを 1 つずつデコードし、立方体の数と合計の両方を維持します。 その後、式は指定どおりに正確に評価されます。 

よくある間違いは、空のサブセットが有効であり、考慮する必要があることを忘れることです。 もう 1 つは、サブセット サイズが 0 のときに符号を誤って処理することですが、この場合、実装では当然 0 が返されます。 キューブを事前計算すると、サブセット ループ内で累乗が繰り返されることが回避されます。これは、1000 テスト ケースでのパフォーマンスにとって重要です。 

## 実用的な例

 配列を考えてみましょう$[1, -2, 3]$。 フルセットを除くすべてのサブセットを列挙します。 

| マスク | サブセット | |S| | 立方体の和 | 値 |

 |------|--------|------|--------------|------|

 | 000 | {} | 0 | 0 | 0 |

 | 001 | {1} | 1 | 1 | -1 |

 | 010 | {-2} | 1 | -8 | 8 |

 | 100 | {3} | 1 | 27 | -27 |

 | 011 | {1,-2} | 2 | -7 | -14 |

 | 101 | {1,3} | 2 | 28 | 56 |

 | 110 | {-2,3} | 2 | 19 | 38 |

 フルセットは対象外となります。 最小値は -27、最大値は 56 です。 

このトレースは、立方体の合計が大きくなった場合でも、パリティ ベースの符号がどのように値を反転させ、非単調な動作を生成するかを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        T = int(input())
        out = []
        for _ in range(T):
            N = int(input())
            A = list(map(int, input().split()))
            cube = [x*x*x for x in A]
            full = (1<<N)-1
            INF = 10**30
            mn, mx = INF, -INF
            for mask in range(1<<N):
                if mask == full:
                    continue
                cnt = 0
                s = 0
                m = mask
                i = 0
                while m:
                    if m & 1:
                        cnt += 1
                        s += cube[i]
                    m >>= 1
                    i += 1
                if cnt == 0:
                    val = 0
                else:
                    val = cnt * (-1 if cnt%2 else 1) * s
                mn = min(mn, val)
                mx = max(mx, val)
            out.append(str(mn) + " " + str(mx))
        return "\n".join(out)

    return solve()

# custom cases

assert run("1\n2\n1 2\n") is not None, "small sanity"
assert run("1\n3\n-1 -2 -3\n") is not None, "all negative"
assert run("2\n2\n1 2\n1\n7\n") is not None, "multiple cases"

 ## 特殊なケース

 空のサブセットは、式の両方のコンポーネントがゼロであっても有効な値を生成するため、最もデリケートなケースです。 アルゴリズムには当然マスク 0 を通じてこれが含まれており、フルセットのマスクと一致しないため、正しくゼロとして評価されます。 

フルセットの除外はマスクをスキップすることで明示的に処理されます。$2^N - 1$。 この条件がないと、解には誤って余分な候補が 1 つ含まれ、入力分布に応じて最大値または最小値を支配する可能性があります。 

すべての要素がゼロの場合、別のエッジ動作が発生します。 その後、すべてのサブセットはサイズや符号に関係なく 0 と評価され、評価された値はすべて同じ定数に折りたたまれるため、アルゴリズムは最小値と最大値の両方に対して正しく 0 を返します。
