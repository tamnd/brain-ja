 ## 問題の理解

 長さの非表示の円形配列と対話しています。$N$、 どこ$1 \le N \le 2 \cdot 10^5$。 円上の各位置には整数値が含まれており、これらの値は円の周りを順番に移動するにつれて厳密に増加します。$s_1 < s_2 < \dots < s_N$。 複雑なのは、配列が循環的であるため、インデックスをクエリすることです。$q$直接返さない$s_q$。 代わりに、それは返されます$s_{((q-1) \bmod N) + 1}$、シーケンスが毎回繰り返されることを意味します$N$要素。 

最大 50 件のクエリが許可されます。 各クエリでは、この隠れた周期シーケンスから値が得られます。 いくつかのクエリの後、期間の長さを決定する必要があります$N$。 

主な困難は、インデックスを直接観察することはなく、増加する繰り返しシーケンスの値のみを観察することです。 繰り返しの境界は不明であり、利用できる唯一の構造は 1 周期内の厳密な単調性です。 

制約$N \le 2 \cdot 10^5$また、わずか 50 個のクエリでは、配列全体を再構築したり、長距離を直接シミュレートしようとする戦略が即座に除外されます。 どのソリューションでも、列挙ではなく周期性と成長挙動から情報を抽出する必要があります。 

「繰り返しを素早く検出する」という観点だけで考えると、微妙な失敗例が現れます。 たとえば、値が非常に急速に増加する場合、次のような単純なサンプリングが行われます。 

クエリ 1、2、3、4、…

 まだ 1 サイクル内にあるため、たとえ期間が短くても、長期間厳密に増加する値を示す可能性があります。 逆に、ラップアラウンドすると、突然、はるかに小さい値に下がりますが、慎重に構造化されていない限り、少数のサンプルから正確な境界を検出することは信頼できません。 

中心的な課題は、モジュール式インデックス作成を通じて観察される厳密に増加するシーケンスの周期を推測することです。 

## アプローチ

 ブルート フォース アプローチでは、連続する位置をクエリし、前のクエリと比較して値が減少する最初のインデックスを検索することで、繰り返しを検出しようとします。 この点は折り返しを示しているため、次のように推測できます。$N$ドロップの位置として。 

これは、高密度でサンプリングし、既知の位置合わせから開始する場合にのみ機能します。 ただし、サイクルの開始段階はわかりません。 クエリを実行する$1, 2, 3, \dots$ラップするまで増加するシーケンスが得られますが、ラップ ポイントは隠れたサイクルの未知のオフセットに依存します。 サイクルが「途中」で始まる場合、最初のクエリがすでにサイクルの終わりに近づいている可能性があり、観察された低下はすぐに、または非常に少数のステップの後に発生します。 さらに悪いことに、アライメントが分からないと、1 回のラップだけでは位置にいるかどうかを区別するのに十分ではありません。$k$または$k + N$。 

重要な観察は、インデックスがラップしている間、値自体は 1 つの期間内で厳密に増加しているため、観察できる唯一の非単調な動作はモジュラー ラップによるものであるということです。 大きなジャンプをクエリして応答を比較すると、2 つのインデックスが同じサイクル セグメント内にあるかどうかを検出できます。 これにより、ラップ境界までの距離に対してダブリング スタイルの検索を使用できるようになります。 

より具体的には、位置ごとのクエリを比較すると、$x$そして$x + d$、両方が同じサイクルセグメント内にある場合、値は増加します。 一度$x + d$の倍数を横切る$N$、ソートされたサイクルの先頭に戻るため、値は大幅に減少します。 これにより、距離に関する二項述語が作成されます。$d$同じサイクルに留まるかどうか？」

 この単調な構造により、最大の二分探索が可能になります。$d$ラップが発生しないようにします。 それ$d$に直接対応します$N$なぜなら、サイクル長は正確に反復前の最大オフセットだからです。 

したがって、我々は問題を、ラップを引き起こす最小距離を見つけること、または同等の距離に対する二分探索による周期長を見つけることに帰着します。

 ## アルゴリズムのチュートリアル

 インデックスのクエリが実行されるという事実を利用します。$i$決定的な周期シーケンスを与えます。 唯一の信号は、$N$2 つのクエリがサイクルの異なる「回転」を参照する場合です。 

1.ベースクエリの位置を修正します$x = 1$、そして記録する$a = query(1)$。 これにより、サイクル内で安定した基準点が得られます。 
2. 候補距離に対して二分探索を実行します$d$範囲内で$[1, 2 \cdot 10^5]$。 の意味$d$クエリ インデックス空間でどれだけ前進するかです。 
3. 各中間点について$mid$、比較します$query(1)$と$query(1 + mid)$。 両方のインデックスがラップなしで同じサイクル セグメントにマップされる場合、値は循環構造と一貫性を保つ必要があります。 
4. シーケンスが基準値に対して「リセット」されるかどうかをチェックすることで、折り返しを検出します。 もし$query(1 + mid) < query(1)$の場合、ラップはその前または離れた場所で発生した必要があります。$mid$、 意味$mid \ge N$。 
5. ラップが検出されない場合は、期間を大きくする必要があるため、下限を上に移動します。 
6. それ以外の場合は、上限を減らします。 
7. 二分探索が収束した後、ラップを引き起こす最小距離は次のようになります。$N$を出力します。 

重要な実装の詳細は、絶対的なインデックスの正確さに依存せず、サイクル内の単調性と境界での厳密なリセット動作のみに依存することです。 

### なぜ効果があるのか

 単一サイクル内では、値のシーケンスは厳密に増加しています。 減少を確認する唯一の方法は、モジュールの境界を越えて最初からやり直すことです。$s_1$。 したがって、述語「query(i) < query(1)」は、「i は 1 とは異なるサイクル アライメントにある」と同等です。 この述語は単調です$i$: 一度 true になると、より大きなすべてに対して true のままになります。$i$。 この単調性によりバイナリ検索の正確さが保証され、正確な遷移点を確実に回復できます。$N$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(q):
    print(f"? {q}", flush=True)
    v = int(input().strip())
    if v == -1:
        sys.exit()
    return v

def solve():
    base = ask(1)

    lo, hi = 1, 200000
    ans = 200000

    while lo <= hi:
        mid = (lo + hi) // 2
        v = ask(1 + mid)

        if v < base:
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(f"! {ans}", flush=True)

if __name__ == "__main__":
    solve()
```このソリューションでは、固定参照クエリを位置 1 に保持し、それをサイクル ラップを検出するためのアンカーとして使用します。 他のすべてのクエリはこのアンカーと比較して、境界を越えたかどうかを判断します。 

二分探索は単一の比較ルールのみに依存するため、シーケンスを再構築したり、複数のオフセットを追跡したりする必要がなくなります。 唯一の微妙な要件は、対話が厳密であるため、クエリごとにフラッシュすることです。 

## 実用的な例

 ここで、インデックス 5 を超えてクエリを実行すると、シーケンスはラップされ、ベースよりも小さい値が返されます。 この急激な低下は、サイクルの境界を越えたことを示しています。

 ## 特殊なケース

 エッジケースの 1 つは、$N = 1$。 すべてのクエリは同じ値を返します。 条件$query(1+mid) < query(1)$決してトリガーされないため、二分探索により答えは正しく 1 にプッシュされます。 

もう 1 つのエッジケースは次のような場合です$N$が大きく、最初のラップは検索スペースの上限に近いです。 ラップが検出されると、すべての大きなインデックスもラップされた動作を示し、単調性が維持されるため、バイナリ検索は依然として収束します。 

最後の微妙なケースは、最初にクエリされた値がすでにサイクルの終わりに近づいている場合です。 それでも最初の数個は$1 + mid$クエリはすぐに折り返しを明らかにし、検索範囲をすばやく縮小し、それでも正しい境界に収束します。
