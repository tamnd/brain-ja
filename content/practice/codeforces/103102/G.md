 ## 解決策
 ## 問題の理解

 この問題は 2D 平面内の点の集合を記述し、これらの点の「単純なハル」を構築するように求めます。 ここでの「単純な包」という表現は、一連の平面点の標準的な凸包、つまり、直線セグメント上にある境界点が一貫した方法で処理される、すべての所定の点を含む最小の凸多角形に対応します。 

入力は座標のリストとして解釈できます。 各点は平面内の位置に寄与し、出力は反時計回りの順序で凸包の境界を形成する頂点のシーケンスになります。 このスタイルの Codeforces タスクで使用される正確な規則に応じて、境界上の同一線上のポイントが含まれるか除外されますが、ポリゴンが内側に凹むことなくポイント セットの周りをしっかりと包み込む必要があるという定義要件は変わりません。 

複雑さの観点から見ると、点の数が十分に大きいため、O(n log n) よりも悪い解は安全でなくなります。 すべての点のペアに対する二次スキャンまたは増分幾何学的チェックでは、n が 10^5 の場合、最悪のケースで約 10^10 の演算が発生しますが、これは妥当な時間制限を超えています。 これにより、すぐにソートと線形スキャンに基づいた古典的な凸包の構築に向かうことになります。 

単純な実装によく見られる失敗例がいくつかあります。 

1 つは、同一線上の境界点を正しく処理していないことです。 3 つの点が直線上にあるとします: (0,0)、(1,0)、(2,0)。 すべてのターンを非負に保つ単純なハルには 3 つの点がすべて含まれる可能性がありますが、必要な厳密な凸性に応じて、通常は中間点をハルの頂点から除外する必要があります。 

もう 1 つは、ポイントを並べ替えるときの方向の処理が正しくないことです。 Y 座標ではなく X 座標のみで並べ替えるなど、一貫して関係を解除することを忘れると、縮退した垂直方向の配置によって単調な構築ロジックが壊れる可能性があります。 

3 番目の問題は、重複ポイントを慎重に扱っていないことです。 重複が存在する場合、スタックベースのハルは長さ 0 のエッジまたは繰り返しの頂点を生成する可能性があり、出力形式の期待を裏切る可能性があります。 

## アプローチ

 ブルート フォースのアイデアは概念的には単純です。ポリゴンの境界を形成する可能性のある点のすべてのサブセットを試し、他のすべての点が境界の内側または上にあるかどうかを確認し、最小の有効なポリゴンを保持します。 候補サブセットごとに有効性をチェックするには、すべての点をスキャンし、各エッジに対して方向テストを実行する必要があります。 サイズ k のサブセットに限定したとしても、そのようなサブセットの数は組み合わせ的に増加し、各検証のコストは O(nk) になります。 これは、最大 10^5 の n に対して直ちに爆発します。 

重要な構造的観察は、凸包の境界が局所的な方向制約によって完全に決定されるということです。 点を辞書順に並べ替えてからそれらをスイープする場合、部分ハルを延長するたびに、最後の 2 つのエッジが左折特性を維持しているかどうかを確認するだけで済みます。 違反がある場合は、中央の頂点が凸境界に属せないことを意味します。 これにより、グローバルな幾何学的制約がローカルなスタック メンテナンス ルールに変わります。 

これはまさに、モノトーン チェーン アルゴリズムを適用できる理由です。 ソートによりグローバルな順序付けが行われ、スタックはソート後に線形時間で局所的に凸性を強制します。

 ## アルゴリズムのチュートリアル

 船体は下部船体と上部船体を別々に建造し連結するモノトーンチェーン工法で建造します。

1. すべての点を x 座標で辞書順に並べ替え、y 座標で分けます。 この順序により、ポイントが左から右に処理されるようになり、境界チェーンを構築するための自然な方向が得られます。 
2. ソートされたポイントを左から右に繰り返して、船体下部を構築します。 各ポイントについて、現在のチェーンを延長しようとしますが、最後のポイントを削除しますが、最後の 2 つのポイントと現在のポイントは反時計回りの回転を形成しません。 これにより、チェーンが内側に曲がることがなくなります。 
3. 同じ方法で上部船体を構築しますが、右から左に繰り返します。 これにより、同じ局所凸ルールを使用して凸包の上​​部境界が構築されます。 
4. 端点の重複を避けるために、各半分の最後の点を削除して、下部ハルと上部ハルを連結します。 
5. 結果として得られる頂点のシーケンスを順番に出力します。 

### なぜ効果があるのか

 重要な不変条件は、建設中のどの時点においても、部分船体が凸面を維持していることです。スタック上の連続する 3 つのポイントがすべて左折を形成します (厳密さによっては同一直線上になります)。 新しい点がこの特性に違反する場合、内側へのへこみが生じるため、最後のトリプルの中点を凸状境界の一部にすることはできません。 このような点を繰り返し削除すると、極端な点だけが残ります。 ソートはグローバルな順序でポイントを処理するため、有効なハル頂点が永続的にスキップされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(o, a, b):
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

def convex_hull(points):
    points = sorted(set(points))
    if len(points) <= 1:
        return points

    lower = []
    for p in points:
        while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
            lower.pop()
        lower.append(p)

    upper = []
    for p in reversed(points):
        while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)

    return lower[:-1] + upper[:-1]

def main():
    n = int(input())
    points = [tuple(map(int, input().split())) for _ in range(n)]
    hull = convex_hull(points)
    print(len(hull))
    for x, y in hull:
        print(x, y)

if __name__ == "__main__":
    main()
```外積関数は方向をエンコードします。 正でない値は、シーケンスが厳密に左折しないことを意味するため、中間点は凸性に寄与せず、削除されます。 の使用`set(points)`重複を早期に削除し、スタック構築の縮退を防ぎます。 

下部ハルと上部ハルに分離することで、底部と上部の両方の境界が対称的に処理されるようになります。 これらの端点は回転の両端で重なるため、連結では各半分の最後の要素が省略されます。 

## 実用的な例

 内部点を持つ単純な多角形を形成する小さな点のセットを考えてみましょう。 

入力:

 (0,0)、(2,0)、(1,1)、(0,2)、(2,2)

 ### 船体下部構造

 | ステップ | ポイント | スタック (下) |
 | --- | --- | --- |
 | 1 | (0,0) | (0,0) |
 | 2 | (2,0) | (0,0)、(2,0) |
 | 3 | (1,1) | (0,0)、(1,1) |
 | 4 | (0,2) | (0,0)、(1,1)、(0,2) |
 | 5 | (2,2) | (0,0)、(1,1)、(2,2) |

 中間点 (2,0) は、(1,1) が導入されたときに非左折が作成されるため、削除されます。 

### 船体上部構造

 | ステップ | ポイント | スタック（上） |
 | --- | --- | --- |
 | 1 | (2,2) | (2,2) |
 | 2 | (0,2) | (2,2)、(0,2) |
 | 3 | (1,1) | (2,2)、(1,1) |
 | 4 | (2,0) | (2,2)、(1,1)、(2,0) |
 | 5 | (0,0) | (2,2)、(1,1)、(0,0) |

 ### 最終船体

 重複をマージして削除すると、ハルは (0,0)、(0,2)、(2,2)、(2,0) になります。 

このトレースは、内部点 (1,1) が極端な頂点になることがないため、両方のスイープで削除されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | ソートが優先され、各ポイントは最大 1 回プッシュ/ポップされます。 
| スペース | O(n) | ポイントとハルスタックを保存する |

 ソートコストが計算全体の大半を占めますが、下部ハルと上部ハルの線形スキャンは O(n) で償却されます。 これは、最大 10^5 の n の一般的な制約内に問題なく適合します。

 ## 特殊なケース

 (5,5) などの単一点で構成される縮退入力は、下位と上位の構築ループの両方が意味のあるポップを実行しないため、同じ点を返す凸包ルーチンによって直ちに処理されます。 

(0,0)、(1,1)、(2,2)、(3,3) などの完全に共線的なセットは、外積条件で使用される理由を示しています。`<= 0`。 船体下部のスイープ中にすべての中間点が削除され、船体の境界を正しく形成する端点 (0,0) と (3,3) だけが残ります。 

繰り返しの (1,1) エントリなどの重複ポイントは、`set(points)`処理前に変換することで、スタック ロジックがゼロエリア ターンや不要なポップを作成する可能性がある冗長な頂点を認識しないようにします。
