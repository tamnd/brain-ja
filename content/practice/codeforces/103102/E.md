 ## 解決策
 ## 問題の理解

 整数の配列が与えられているので、3 で割り切れる特定の「ペアごとの積和」を持つ連続した部分配列がいくつあるかを数える必要があります。 

より正確には、任意の部分配列を取得します。 その値は、その内部の要素のペアのすべての積の合計として定義されます。 サブ配列が$[x_1, x_2, \dots, x_k]$、次に計算します$$x_1x_2 + x_1x_3 + \dots + x_{k-1}x_k.$$3 で割り切れる値を生成する部分配列の数を数えなければなりません。 

重要な制約は、最大の配列サイズです。$5 \cdot 10^5$したがって、部分配列に対する二次列挙はすぐに遅すぎます。 たとえ$O(n^2)$解決策は約を意味します$10^{11}$最悪の場合、2 秒の制限をはるかに超える操作が行われなくなります。 これにより、私たちは次の方向に向かうことになります。$O(n)$または$O(n \log n)$アプローチ。 

ここでは、いくつかの微妙な特殊なケースが重要です。 

すべての要素が 0 の場合、すべての部分配列の重みは 0 になるため、答えはすべての部分配列になります。$\frac{n(n+1)}{2}$。 積を再計算する単純なアプローチでは、誤ってオーバーフローしたり時間を無駄にしたりする可能性がありますが、それでも概念的には処理できるはずです。 

すべての要素が 3 の倍数である場合、すべての積も 3 の倍数であるため、ここでもすべての部分配列が有効になります。 これは、正しさの健全性チェックに適しています。 

値が大きい場合、次のように$10^9$、他の言語ではオーバーフローの懸念があるため、直接積の計算は不要であり危険ですが、ここで実際に観察されるのは、3 で割り切れる値は 3 を法とする値にのみ依存するため、3 を法とする剰余だけが重要であるということです。 

隠れた重要な問題は、部分配列の条件にペアごとの積が含まれており、これが標準の接頭辞の合計ではないことです。 不注意な試みにより、モジュラー推論のない単純な代数的縮約を前提として、合計と平方和を誤って維持しようとする可能性があります。 

## アプローチ

 まずは強引なアイデアからスタートします。 すべてのサブ配列について、その内部のすべてのペアを反復処理することにより、その重みを直接計算します。 つまり、それぞれについて、$l, r$、すべてを合計します$i < j$で$[l, r]$。 これにはかかります$O(n)$サブ配列ごとに、$O(n^2)$部分配列の場合、全体の複雑さは次のようになります。$O(n^3)$、これは完全に不可能です$n = 5 \cdot 10^5$。 

重みの式を簡略化する必要があります。 重要な代数恒等式は、任意の部分配列の合計に対する代数恒等式です。$S = \sum x_i$、 我々は持っています：$$\sum_{i<j} x_i x_j = \frac{S^2 - \sum x_i^2}{2}.$$これにより、ペアワイズ構造がプレフィックス和とプレフィックス二乗和に変換されます。 

ここで重要な観察です。この値が 3 で割り切れるかどうかだけを気にします。3 を法として処理しているため、2 の逆法 3 があるため、2 で除算することは安全です (なぜなら、$2 \equiv -1 \pmod 3$）。 

したがって、条件は純粋にプレフィックスベースのモジュール条件になります。 以下を維持できます。$$S_r = \sum_{i \le r} a_i,\quad Q_r = \sum_{i \le r} a_i^2.$$次にサブアレイ$[l, r]$違いだけに依存する$S_r - S_{l-1}$そして$Q_r - Q_{l-1}$。 モジュロ 3 を拡張および単純化すると、条件がプレフィックス状態の関数に減ります。 

これにより、問題は、特定のモジュラー関係に一致するプレフィックス状態のペアを数えることに変換され、小さな状態空間 (すべてが mod 3 であるため、状態空間は一定です) にわたる頻度を数えることで処理できます。 

したがって、サブ配列に対するブルート フォースは、プレフィックス構成のカウントに集約されます。$O(n)$。

 ## アルゴリズムのチュートリアル

 1. 3 で割り切れるには剰余のみが重要であるため、すべての配列要素を 3 を法として削減します。加算と乗算の両方が合同を維持するため、これは有効です。 
2. プレフィックスの合計を維持する$S$と接頭辞の二乗和$Q$、両方とも配列を反復処理するときにモジュロ 3 を取得します。 
3. 各プレフィックス位置について$r$、以下から構成されるコンパクトな状態表現を計算します。$(S_r \bmod 3, Q_r \bmod 3)$。 これは、次で終わるサブ配列を完全に特徴づけます。$r$ターゲットの表現に関して。 
4. ハッシュ マップまたはサイズ 9 の配列 (各コンポーネントの選択肢が 3 つしかないため) を使用して、各プレフィックス状態がこれまでに出現した回数を保存します。 
5. 新しいプレフィックス状態ごとに、代数的に導出されたゼロ モジュロ 3 の互換性条件をチェックすることにより、現在のインデックスで終わる有効なサブ配列を形成する前のプレフィックス状態の数を決定します。 
6. その周波数を応答に追加し、マップ内の現在のプレフィックス状態を増分します。 
7. 配列の最後まで継続し、累積されたカウントを出力します。 

### なぜ効果があるのか

 核となる不変条件は、すべてのサブ配列が$[l, r]$でのプレフィックス状態のペアに一意に対応します。$l-1$そして$r$。 部分配列の重みはこれらの接頭辞状態の差にのみ依存し、ペアごとの積和を​​接頭辞合計と接頭辞二乗和に変換した後、条件はこれら 2 つの状態に対する固定モジュラー制約になります。 すべての操作はモジュロ 3 で実行されるため、プレフィックス状態空間は有限であり、必要な情報をすべて完全に取得します。 したがって、有効なサブ配列をカウントすることは、正確にプレフィックス状態の有効なペアをカウントすることになり、サブ配列に関する追加の構造情報は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # prefix sums and prefix squared sums mod 3
    s = 0
    q = 0

    # frequency of (s, q)
    freq = [[0] * 3 for _ in range(3)]

    # empty prefix
    freq[0][0] = 1

    ans = 0

    for x in a:
        x %= 3
        s = (s + x) % 3
        q = (q + x * x) % 3

        # derived condition: we want subarray weight % 3 == 0
        # which translates into a fixed constraint on prefix states
        # we check all previous states that satisfy it
        for ps in range(3):
            for pq in range(3):
                # difference-based constraint encoded directly
                ds = (s - ps) % 3
                dq = (q - pq) % 3

                # compute subarray weight mod 3 using identity:
                # (S^2 - Q)/2 mod 3, and 2^{-1} = 2 mod 3
                val = ((ds * ds - dq) % 3) * 2 % 3

                if val == 0:
                    ans += freq[ps][pq]

        freq[s][q] += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、プレフィックス状態のアイデアを直接反映しています。 3 x 3 の状態にわたるネストされたループは要素ごとに一定の作業であるため、全体の複雑さは線形のままです。 

微妙な点は、2 による剰余除算です。剰余 3 の算術演算では、2 による除算は 2 による乗算に置き換えられます。$2 \cdot 2 \equiv 1 \pmod 3$。 だからこそこの表現は`* 2 % 3`正規化を正しく処理します。 

見落としがちなもう 1 つの点は、空のプレフィックス状態が含まれていることです。$(0,0)$これにより、インデックス 1 から始まるサブ配列を自然にカウントできるようになります。

 ## 特殊なケース

 次のような単一要素配列の場合`[0]`、プレフィックスの状態はすでに$(0,0)$, そのため、アルゴリズムはすぐにそれを有効なものとしてカウントします。 度数表はこの状態から始まるので、特別な処理をしなくても答えは 1 になります。 

すべてゼロの配列の場合、更新のたびに状態が維持されます。$(0,0)$。 それぞれの新しい位置は以前のすべてのプレフィックスと一致するため、アルゴリズムはすべてのプレフィックスを正しく累積します。$\frac{n(n+1)}{2}$周波数の累積を繰り返してサブアレイを生成します。 

すべての要素が 1 である配列の場合、プレフィックス状態は mod 3 状態の小さなサブセットを循環し、アルゴリズムはどのプレフィックス ペアが重み 0 をもたらすかを正確に識別します。 定数状態表現では、各ペアがプレフィックス遷移を通じて正確に 1 回評価されるため、サブ配列が二重にカウントされたり欠落したりすることがなくなります。
