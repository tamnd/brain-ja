 ## 解決策
 ## 問題の理解

 整数のマルチセットが与えられ、全体で各値のコピーが何個存在するかを変更することなく、その要素を 2 つのグループ (A と B と呼ぶ) に再分配することができます。 すべての要素は 2 つのグループのいずれかに正確に配置される必要がありますが、重複は任意に分割できます。 

任意のグループについて、そのグループに現れない最小の非負の整数である mex を計算します。 タスクは、mex(A) + mex(B) の合計ができるだけ大きくなるように要素を A と B に割り当てることです。 

重要な構造は、mex が 0 から始まるシーケンスを「カバー」できるかどうかのみに依存するということです。セット内に数値が欠落している場合、それ以降のすべてはその mex にとって無関係になります。 

制約は小さく、テスト ケースは最大 100 個、各配列のサイズは最大 100 です。これにより、テスト ケースごとに線形推論または二次推論を超えるものは即座に排除されます。 O(n³) でも合格する可能性がありますが、それに近いものは必要ありません。 この問題は、貪欲なカウント引数を対象としています。 

いくつかの小さな数値が完全に欠落している場合、微妙なエッジケースが発生します。 0 が欠落している場合、他に何も関係なく、両方のセットは直ちに mex 0 を持ちます。 もう 1 つは、数値が 1 回だけ出現する場合です。これは、2 つのセットのうち最大でも 1 つの連続プレフィックスを拡張する能力に寄与する可能性があり、両方の mex 値が同時に大きくなることが直接制限されます。 

## アプローチ

 ブルートフォース ソリューションでは、各要素を A または B に割り当てるあらゆる方法が試行されます。そのような割り当ては 2^n 個あり、それぞれについて 2 つの mex 値を計算するコストは O(n) です。 これは O(n・2^n) となり、n = 100 の場合でも大きすぎます。 

重要な観察は、mex(A) = k が A に 0 から k−1 までのすべての数値を少なくとも 1 回含まなければならないことを意味するということです。 同じことが B にも当てはまります。したがって、問題は、各番号の限られたコピーを使用して、0 から始まる完全なプレフィックスを 2 つのグループに同時に「供給」できる数についてになります。 

完全な割り当てという観点から考える代わりに、これらのプレフィックスを構築するために各値が提供する使用可能なコピーの数を知るだけで済みます。 各数値 x は、2 つの mex 計算に対して全体で最大 2 回寄与できますが、それは少なくとも 2 回出現する場合に限られます。 一度出現すると片方しか助けられません。 出現回数が 0 回である場合は、両方のプレフィックスが即座に破壊されます。 

これにより、問題は値を 0 から上にスキャンし、最初と 2 番目の mex を同時に構築し続けることができるかどうかを追跡するようになります。 頻度が少なくとも 2 の値に遭遇するたびに、A と B の両方にその値が含まれる可能性があります。 頻度がちょうど 1 の場合、延長できるのは 1 つだけであるため、割り当てを慎重に管理しないと、一方の「チェーン」が継続する一方で、もう一方の「チェーン」が強制的に停止される可能性があります。 この貪欲な追跡により、両方の mex 値をどこまで拡張できるかが直接計算されます。

 ## アルゴリズムのチュートリアル

 入力を周波数配列に圧縮します。ここで、cnt[x] には x が出現する回数が格納されます。 

次に、2 つの mex シーケンスを並行して構築するシミュレーションを行います。

1. A と B が 0 から始まる連続したプレフィックスの構築を継続できるかどうかを示す 2 つのフラグを維持します。最初は両方ともアクティブです。 
2. x を 0 から上に向かって繰り返します。 
3. cnt[x] == 0 の場合、どちらのセットにも x を含めることはできないため、両方のシーケンスは x で強制的に停止され、両方の mex 値は最大でも x になります。 
4. cnt[x] == 1 の場合、2 つのセットのうちの 1 つだけが x を受け取ることができます。 これは、x を超えて継続できるのは 1 つのプレフィックスのみであり、もう 1 つは x で停止する必要があることを意味します。 この単一のオカレンスを貪欲に割り当てて、小さい側または現在「飽和度が低い」側を拡張しますが、長さのみを考慮しているため、両方の mex 計算にわたって合計 1 つの拡張に寄与します。 
5. cnt[x] >= 2 の場合、両方のセットに x を含めることができるため、両方のプレフィックスを安全に続行できます。 
6. 貢献を蓄積します。セットに x が含まれるたびに、潜在的な mex 境界が増加します。 
7. 両方のシーケンスを延長できなくなると、プロセスは停止します。 

最終的な答えは、A と B がどこまで進んだかを合計したものです。 

これが機能する理由は、mex が 0 から始まる最長の連続プレフィックスによって完全に決定されるという事実に根ざしています。各値 x は、より小さい値がすべてすでにサポートされている場合にのみ関連します。 各ステップでの唯一の制限要因は、両方のプレフィックスを供給するのに十分な x のコピーがあるかどうかです。 そうする場合、両方とも続行します。 1 つある場合は、1 つだけが継続されます。 何も持っていない場合は、両方が終了します。 失われた以前の値を後の値で修復することはできないため、プロセスは元に戻すことができず、貪欲な決定は安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        cnt = [0] * 105
        for x in a:
            cnt[x] += 1
        
        ans = 0
        
        for x in range(0, 105):
            if cnt[x] == 0:
                break
            elif cnt[x] == 1:
                ans += 1
            else:
                ans += 2
        
        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、マルチセットを頻度テーブルに圧縮し、値を昇順にスキャンします。 答えは直接蓄積されます。2 つ以上のコピーを持つ値は 2 つの「使用」に寄与します。つまり、両方のセットがその値をプレフィックス チェーンに含めることができます。 1 つのコピーを持つ値は 1 つのみを提供します。 どちらのセットもその点を超えて mex を達成できないため、値が欠落している場合は両方のチェーンが直ちに終了します。 

実装の重要な詳細は、cnt[x] == 0 での早期ブレークです。これがないと、不足しているプレフィックス要素を後の値で補うことができると誤って想定してしまいますが、これは mex の定義では不可能です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        cnt = [0] * 105
        for x in a:
            cnt[x] += 1
        ans = 0
        for x in range(105):
            if cnt[x] == 0:
                break
            ans += min(2, cnt[x])
        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 配列に 0 がまったく含まれていない場合、A も B も有効なプレフィックスの構築を開始できないため、両方の mex 値が強制的に 0 になります。 アルゴリズムは、cnt[0] == 0 の最初の反復を通じてこれを処理し、すぐに中断して 0 を返します。 

値が 1 回だけ出現すると、両方の mex チェーンを合わせた合計の増加が制限されます。 たとえば、cnt[0] = 1 の場合、有効なプレフィックスの構築を開始できるセットは 1 つだけであるため、合計貢献量の上限は 1 になります。スキャンはユニットを 1 つだけ正しく追加し、アクティブ チェーンに対してのみ暗黙的に継続します。 

すべての値が k まで少なくとも 2 回現れる場合、両方の mex 値は最初の欠損数までロックステップで増加します。 アルゴリズムは、両方のセットにその数値を個別に含めることができることを反映して、そのような値ごとに 2 を加算し、プレフィックスが壊れたときに正確に停止します。
