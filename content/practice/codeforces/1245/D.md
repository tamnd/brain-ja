 ## 解決策
 ## 問題の理解

 平面上に配置された一連の都市が与えられます。 各都市は 2 つの方法のいずれかで「電力を供給」できます。1 つは都市に直接発電所を建設するか、すでに発電所がある都市に (直接的または他の都市を介して間接的に) 接続するかのいずれかです。 

市内に駅を建設する$i$固定費がある$c_i$。 Connecting two cities$i$そして$j$グリッドに沿ってワイヤーを敷設する必要があり、ワイヤーの長さはマンハッタン距離になります$|x_i - x_j| + |y_i - y_j|$。 この接続のコストは、その長さに、両方のエンドポイントに依存するユニットあたりのコストを乗算したものになります。$k_i + k_j$。 

最終的な目標は、選択したステーションと接続の総コストを最小限に抑えながら、すべての都市に電力を供給できるようにすることです。 出力は最小コストだけでなく、ソリューションの構造、つまりどの都市が駅を取得し、どの都市のペアが接続されているかも表します。 

この制約により、最大 2000 の都市が許可されます。 単純な全ペア グラフには約 400 万のエッジがあり、これはすでに境界線に達していますが、次のように注意深く処理すればまだ実現可能です。$O(n^2)$アルゴリズム。 関わるものなら何でも$O(n^2 \log n)$テストごとにそれ以上のテストは合格しますが、三次関数や最短経路の計算を繰り返すものは合格しません。 

すべての接続コストがステーションのコストと比較して非常に高い場合、微妙なエッジ ケースが発生します。 その場合、最適なソリューションはどこにでもステーションを構築し、エッジを使用しません。 逆に、ステーションのコストが大きく、接続コストが小さい場合、最適なソリューションは単一のステーションとすべての都市にわたるスパニング ツリーになります。 グローバル構造を持たずにローカルでエッジを貪欲に選択する単純なアプローチは、決定がグラフ全体にわたって相互作用するため、両極端で失敗する可能性があります。 

2 つの都市が同じ座標を共有する場合、別の障害モードが発生します。 それらのマンハッタン距離はゼロであるため、それらを接続するコストはゼロです。 エッジの重みが厳密に正であることを前提としたり、長さ 0 のエッジをスキップしたりする誤った実装は、誤った動作をする可能性があります。 

## アプローチ

 問題は当然ながら、すべてのノードを「アクティブ化」するための最小コストの方法です。アクティブ化は、ノード コストを支払うか、アクティブ化を伝播するエッジ コストを支払うことで発生する可能性があります。 これは、局所的な貪欲な選択ではなく、グラフ最適化構造を示唆しています。 

強引な解釈では、都市のすべてのサブセットを潜在的なステーションの場所として考慮し、誘導グラフ上の最小スパニング構造を使用して残りのノードを接続する最適な方法を計算します。 これはすぐに不可能になります。$2^n$サブセットと各評価には少なくとも次のものが必要になります。$O(n^2)$処理が進み、指数関数的な時間が発生します。 

重要な観察は、問題を単一のグラフの問題として再解釈できるということです。 「電源」を表す追加の仮想ノードを導入します。 つながる街$i$この仮想ノードに直接接続するとコストがかかります$c_i$。 これにより、ステーションの構築がエッジの選択に変換されます。 これで、すべての都市が仮想ノードに接続されるか、他の都市を介して接続され、最小スパニング ツリーを選択します。$n+1$ノード。 

2 つの都市間のコストは重み付きエッジになります。$$w(i, j) = (k_i + k_j)\cdot (|x_i - x_j| + |y_i - y_j|)$$仮想ノードへのエッジは次のとおりです。$$w(i, 0) = c_i$$したがって、完全な解決策は、次の完全なグラフ上の最小スパニング ツリー問題です。$n+1$ノード。 以来$n \le 2000$、Prim のアルゴリズム$O(n^2)$すべてのエッジを明示的に保存する必要がなく、実装だけで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n²) | 遅すぎる |
 | 仮想ノードを使用して MST をプリムする | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 概念的なグラフを構築します$n$都市に加えて、グローバルな電力源を表す追加のノードが 1 つあります。 

1. 配列を初期化する`min_cost[i]`都市を接続する最も安価な既知の方法として$i$成長する構造へ。 もともとこれは$c_i$つまり、駅を建設することが最良の選択肢であると想定されます。 

これは、各都市を仮想ノードに直接接続することに相当します。 
2. どの都市が最終構造に既に含まれているかを示す訪問済み配列を維持します。 何も含まれていない状態から始めます。 
3. 最小の未訪問の都市を繰り返し選択します。`min_cost`。 この選択は貪欲ではありますが、現在のツリーを延長する利用可能な最良のエッジが安全である必要がある Prim のアルゴリズムを効果的に実行しているため、有効です。 
4. この都市を訪問済みとしてマークし、その費用を答えに追加します。 最適な接続が仮想ノードである場合、ステーションを記録します。 それ以外の場合は、この改善をもたらした都市に対する優位性を記録します。 
5. 都市を追加した後、新しく追加された都市からのエッジを考慮して、残りの未訪問のすべての都市の接続コストの改善を試みます。 各ペアごとに$i, j$、マンハッタンの距離を計算して更新します。$$\text{cost} = (k_i + k_j)\cdot(|x_i - x_j| + |y_i - y_j|)$$これが現在最もよく知られているコストよりも小さい場合、$j$、それを更新し、記録します$i$の親です$j$。 
6. すべての都市が含まれるまで続行します。 

このプロセスでは、各ノードが仮想ノード (ステーション) に接続されるか、既知の最も安価なエッジを介して別の都市に接続されるスパニング ツリーが構築されます。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムはすでに完成したノードのセットと、残りの各ノードをこのセットに接続する最も安価な方法を維持します。 これはまさに、Prim のアルゴリズムで使用される不変式です。 仮想ノードにより、「ステーションの開始」が単なるエッジとして均一に扱われるようになります。 すべての更新では既存の構造への可能な限り最適な接続が常に考慮されるため、ノードが完成したら、より安価なグローバル構成を見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    x = [0] * n
    y = [0] * n
    for i in range(n):
        x[i], y[i] = map(int, input().split())

    c = list(map(int, input().split()))
    k = list(map(int, input().split()))

    INF = 10**18

    min_cost = c[:]
    parent = [-1] * n
    used = [False] * n

    total = 0
    stations = []
    edges = []

    for _ in range(n):
        v = -1
        for i in range(n):
            if not used[i] and (v == -1 or min_cost[i] < min_cost[v]):
                v = i

        used[v] = True
        total += min_cost[v]

        if parent[v] == -1:
            stations.append(v + 1)
        else:
            edges.append((v + 1, parent[v] + 1))

        for to in range(n):
            if not used[to]:
                dist = abs(x[v] - x[to]) + abs(y[v] - y[to])
                cost = (k[v] + k[to]) * dist
                if cost < min_cost[to]:
                    min_cost[to] = cost
                    parent[to] = v

    print(total)
    print(len(stations))
    print(*stations)
    print(len(edges))
    for a, b in edges:
        print(a, b)

if __name__ == "__main__":
    solve()
```この実装は、優先キューのない直接的な Prim のアルゴリズムですが、これは受け入れられます。$n \le 2000$。 の`min_cost`アレイは、ステーションまたはエッジを介して各都市を接続する最も安価な既知の方法を追跡します。 の`parent`配列は、その最も安いオプションが別の都市からのものなのか、仮想ステーションからのものなのかをエンコードします。 もし`parent[v]`は`-1`、駅を建設すると解釈します。 

よくある間違いは、ステーションのコストがプロセス全体を通じてエッジと競合することを忘れることです。 ここでは初期化することで最初から組み込まれています`min_cost[i] = c[i]`。 もう 1 つの微妙な問題は、ノードを選択した後でのみ距離を更新することです。 それより早く実行すると、Prim の不変条件が壊れてしまいます。

 ## 特殊なケース

 すべての都市の座標が同じ場合、マンハッタンの距離はゼロになります。 その場合、アルゴリズムは当然のことながら、駅を建設するよりも都市を接続することを優先します。$k_i + k_j > 0$エッジコストがゼロになるので問題ありません。 Prim プロセスは最初にゼロコストのエッジを選択し、ステーションの選択が必要になる前にすべてのノードをマージします。 

ステーションコストが非常に大きい場合、初期化`min_cost = c`ステーションを開くよりもコストがかかる場合に、アルゴリズムが初期エッジに誤ってコミットしないようにします。 各都市はプロセス全体を通じて両方のオプションを個別に比較するため、時期尚早な構造が修正されることはありません。 

都市が格安接続の点で完全に孤立すると、`min_cost`はステーションコストのままであり、最終的にステーションノードとして選択されます。 これは、アルゴリズムが切断された最適な構造を適切に処理することを確認します。
