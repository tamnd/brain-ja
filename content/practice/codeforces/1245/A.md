 ## 解決策
 ## 問題の理解

 2 つのステップ サイズが与えられています。`a`そして`b`。 ゼロから始めて、すべての非負の整数を昇順にペイントしますが、数値が白になるかどうかは、次のいずれかを繰り返し加算することによって、すでに白い数値から到達できるかどうかによって決まります。`a`または`b`。 

正式には、ゼロは白から始まります。 任意の番号に対して`i`、引くと白になります。`a`または`b`すでに白の番号に着地します。 どちらの前任者も機能しない場合、番号は黒のままです。 

このプロセスは、次のように形成できるすべての数値を構築することと同じです。`i = x·a + y·b`非負の整数の場合`x`そして`y`、すべての白い数字は繰り返し加算することで到達できるため、`a`または`b`ゼロからのスタート。 

問題は色を列挙することではなく、黒の数が無限に存在するかどうかを判断することです。 それは、到達可能な (白い) 数値のセットが、最終的に十分に大きな整数をすべてカバーできるほど十分な密度になるかどうかに完全に依存します。 

制約は小さく、`t ≤ 100`そして`a, b ≤ 10^4`。 これは、広範囲の整数にわたってプロセスをシミュレートしていないことを示唆しています。 遷移構造は局所的な伝播深さではなく数論に依存するため、ある大きなカットオフまでの値に対する単純なシミュレーションは恣意的で信頼性が低くなります。 

主なエッジケースは次のような場合です`a`そして`b`等しいです。 たとえば、次の場合`a = b = 10`、10の倍数のみが白です。 他のすべての整数は永久に黒であり、その数は無限にあります。 もう 1 つのエッジケースは、そのうちの 1 つが次のような場合です。`1`、 のような`a = 1, b = 10`, ここで、+1 ステップを繰り返すことですべての数字に到達できるため、黒い数字はまったくありません。 

## アプローチ

 ブルートフォース解釈では、次の順序でカラーリングをシミュレートしようとします。 配列をある大きな制限まで維持します。`N`、 マーク`0`白として、そしてそれぞれについて`i`の場合は白にマークします。`i-a`または`i-b`白いです。 次に黒い数字を数えます。 これは固定限界については正しいですが、問題は、それを超えると動作が安定する理論的限界が分からない限り、固定カットオフから「無限の黒」を決定できないことです。 限界値を上げても正確性は保証できません。病的なケースでは、後で黒い数字が現れても、最初の長い数字がすべて白になる可能性があるからです。 

重要な洞察は、白い数が次の式で生成される加法半群を形成するということです。`a`そして`b`。 これは古典的な数理論の構造です。すべての白い数字は線形結合です。`x·a + y·b`。 問題は、この半群が最終的に十分に大きな整数をすべてカバーするかどうかになります。 それはまさにそのときに起こります`gcd(a, b) = 1`, なぜなら、半群は共有限であるため、有限個の整数のみが到達不可能であることを意味します。 もし`gcd(a, b) > 1`、すべての白い数値は gcd の倍数であり、構造体の外側に無限に多くの整数が残るため、無限に多くの黒い数値が残ります。 

これにより、動的プロセス全体が 1 つの演算条件に縮小されます。

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り`a`そして`b`テストケースごとに。 目標は、加算プロセスが最終的にすべての大きな整数に到達できるか、それとも無限に多くの到達不能な値を残すかを判断することです。 
2. コンピューティング`g = gcd(a, b)`。 これにより、到達可能なすべての数値の基本的な周期構造が捕捉されます。これは、到達可能なすべての値が次の数で割り切れる必要があるためです。`g`。 
3. もし`g == 1`、有限個の整数のみが欠落しているという意味で、到達可能な集合は密であるため、黒の数は無限に存続することはできないと結論付けています。 
4. それ以外の場合、`g > 1`、到達可能なすべての数値は次の倍数であると結論付けられます。`g`、で割り切れないすべての整数を意味します。`g`永久にアクセスできなくなります。 このような整数は無限に存在するため、黒の数は無限になります。 

### なぜ効果があるのか

 すべての白い数字は繰り返し加算することによって構築されます。`a`そして`b`、したがってセット内にある必要があります`{x·a + y·b}`。 このような組み合わせはすべて次のように割り切れます。`g = gcd(a, b)`したがって、この剰余クラスの外にある数値は決して白にはなりません。 いつ`g = 1`、フロベニウスのコイン問題に関する古典的な結果は、すべての十分に大きな整数が表現可能であることを保証しており、有限個の黒数のみを強制します。 いつ`g > 1`、到達不可能な剰余クラスは無限に繰り返され、無限に多くの黒数が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

t = int(input())
for _ in range(t):
    a, b = map(int, input().split())
    g = math.gcd(a, b)
    if g == 1:
        print("Finite")
    else:
        print("Infinite")
```このソリューションでは、Python の組み込み gcd 関数を使用して、主要な構造的不変条件を抽出します。 各テスト ケースは独立しているため、同じチェックを繰り返し適用するだけです。 

決定ロジックは数理論的特徴付けを直接変換したものです。gcd が 1 に等しい場合は最終的にカバーされることを意味し、それ以外の場合は周期的な障害が残ることを意味します。 

## 実用的な例

 2 つの入力をトレースして、gcd 条件が結果をどのように決定するかを確認します。 

### 例 1:`a = 10, b = 10`| ステップ | | b | gcd(a,b) | 決定 |
 | --- | --- | --- | --- | --- |
 | 1 | 10 | 10 | 10 | 無限 |

 gcd は 10 であるため、すべての白い数字は 10 の倍数でなければなりません。1、2、3 のような数字は決して白にはならず、このパターンは無限に繰り返されます。 これにより、無限に多くの黒数が確認されます。 

### 例 2:`a = 6, b = 9`| ステップ | | b | gcd(a,b) | 決定 |
 | --- | --- | --- | --- | --- |
 | 1 | 6 | 9 | 3 | 無限 |

 ここで、すべての白い数字は 3 で割り切れます。3 で割り切れないすべての整数は永遠に黒のままであり、そのような整数は無限に存在します。 

これは、到達可能なセットが増大しても、固定されたモジュラー クラスから決して逃れられないことを示しています。

## テストケース```python
import sys, io
import math

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        a, b = map(int, input().split())
        out.append("Finite" if math.gcd(a, b) == 1 else "Infinite")
    return "\n".join(out)

# provided samples
assert solve("4\n10 10\n1 10\n6 9\n7 3\n") == "Infinite\nFinite\nInfinite\nFinite"

# custom cases
assert solve("1\n1 1\n") == "Infinite"
assert solve("1\n1 2\n") == "Finite"
assert solve("1\n4 6\n") == "Infinite"
assert solve("1\n5 10\n") == "Infinite"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1 | 無限 | 同一の手順、完全な制限 |
 | 1 2 | 有限 | gcd = 1 件 |
 | 4 6 | 無限 | gcd > 1 複合構造 |
 | 5 10 | 無限 | 複数ステップの周期性 |

 ## 特殊なケース

 いつ`a = b`、プロセスは単一ステップの到達可能性システムに退化します。 のために`a = b = 10`、到達可能なすべての数値は 10 の倍数です。アルゴリズムは次のように計算します。`gcd(10, 10) = 10`、すぐにそれを無限の黒数として分類し、10 の倍数以外のすべては決して到達できないという事実と一致します。 

1 つの値が`1`、 のような`a = 1, b = 10`、私たちは得ます`gcd = 1`。 アルゴリズムは有限の黒数を返します。 実際のプロセスでは、加算を繰り返すことですべての数値に到達します。`1`, したがって、黒い数字はまったく表示されません。 gcd チェックは、伝播をシミュレートせずにこれをキャプチャします。 

値がより大きな gcd を共有する場合、次のようになります。`a = 12, b = 18`の場合、アルゴリズムは無限に出力します。 到達可能な集合は 6 の倍数に制限され、この剰余クラスの外に無限に多くの整数が残り、それらは永久に黒として存続します。
