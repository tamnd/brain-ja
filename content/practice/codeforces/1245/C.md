 ## 解決策
 ## 問題の理解

 少し壊れた書き込み機によって生成されたと主張される文字列を受け取りました。 マシンは通常、各音声文字をそれ自体として印刷しますが、2 つの特殊な文字は異なる動作をします。`w`、機械は書きます`uu`、そしてユーザーが言った場合`m`と書いてあります。`nn`。 他のすべての文字は変更されずに印刷されます。 

私たちは最終的に書かれた文字列を与えられ、これらのルールの下で元の音声文字列が何個生成されるかを数えるよう求められます。 

言い換えると、指定された文字列をセグメントに分解しようとしています。`u`現実のどちらかに由来する可能性があります`u`または隠れたところから`w`、そしてすべての`n`現実のどちらかに由来する可能性があります`n`または隠れたところから`m`。 タスクは、有効な分解をすべてカウントすることです。 

入力長は最大 100,000 です。 すべての解釈を列挙しようとしたり、指数関数的な分岐を実行しようとしたソリューションは、次のような繰り返し文字が少しでも含まれるため、すぐに失敗します。`uuuuuu...`指数関数的な組み合わせが爆発的に発生します。 これにより、線形または線形に近い動的プログラミング アプローチが強制されます。 

微妙なエッジ ケースは、ラン内の無効な文字がすべての可能性を壊すことです。 たとえば、文字列に 以外の文字が含まれている場合、`u`、`n`、`w`、 または`m`、それらの文字は固定されているためまだ問題はありませんが、解釈によって誤って分割が強制されると、一部のセグメントが不可能になる可能性があります。 より具体的に考えてみると、`"amanda"`。 The letter`m`元の言語では常に生成されます`"nn"`、つまり単一のスタンドアロン`m`出力には決して存在できません。 あらゆる発生`m`出力文字列では、ソース文字が単一の文字列を生成しないため、すべての有効な解釈が即座に無効になります。`m`。 

もう 1 つの重要なケースは短期取引です。 例えば`"u"`解釈はまさに 1 つですが、`"uu"`2 つあります: どちらか`u u`または`w`。 のために`"uuu"`配置が重複しているため、すでに繰り返しが必要です。`w`依存関係を作成します。 

## アプローチ

 ブルートフォース解釈では、すべての位置が通常の文字から来たもの、またはマージされた変換の一部として扱われようとします。 これはすぐに後戻りの問題になり、同じ文字が実行されるたびに問題が発生します。`u`または`n`各ステップでの決断力が倍増します。 長いランの場合`k`、セグメンテーションの数はフィボナッチのような増加に対応しますが、単純な列挙では依然として明示的に分岐するため、指数関数的な複雑さが生じます。 

重要な観察は、曖昧さをもたらすのは 2 文字だけであり、両方の曖昧さはローカルであるということです。`w → uu`そして`m → nn`。 これは、あいまいさが連続して実行される場合にのみ現れることを意味します。`u`または`n`。 それ以外はすべて 1 対 1 で固定されます。 

したがって、文字列を線形に処理して、最大の連続実行に圧縮できます。 あらゆる実行に対して、`u`長さの`k`、各部分はリテラルのいずれかに対応するため、サイズ 1 または 2 の部分に分割できる方法が何通りあるかを数えます。`u`または隠された`w`。 同じことが次の実行にも当てはまります`n`。 

これはまさに、各ランレングスにわたるフィボナッチ DP を独立したセグメントにわたって乗算したものです。

 ## アルゴリズムのチュートリアル

 文字列を処理し、同じ文字の連続したブロックに圧縮します。 

1. 文字列を左から右にスキャンし、同一文字の最大のランを特定します。 異なる文字境界を越える変換はないため、各実行は独立して処理されます。 
2. キャラクターに遭遇したら`m`または`w`最後の文字列では、すぐに 0 を返します。これは、どちらでもないためです。`m`または`w`出力では単一の印刷文字として表示される場合があります。 これらは常に 2 文字のシーケンスに展開されます。 
3. 実行ごとに`u`長さのある`k`、サイズ 1 または 2 のセグメントに分割する方法の数を計算します。サイズ 1 のセグメントはリテラルに対応します。`u`、サイズ 2 のセグメントは非表示のセグメントに対応します。`w`。 
4. 実行ごとに`n`長さのある`k`、同じタイプのパーティション数を計算します。`n`どちらからでも来ることができます`n`またはから`m`。 
5. 各実行の寄与を乗算してグローバルな答えのモジュロを計算します$10^9+7$。 
6. フィボナッチ スタイルの DP を使用します。`dp[i]`一連の長さをカバーする方法の数を表します`i`。 移行は、`dp[i] = dp[i-1] + dp[i-2]`、最後のセグメントがサイズ 1 またはサイズ 2 であるためです。 

### なぜ効果があるのか

 それぞれの有効な解釈は、すべての最大値のタイリングに一意に対応します。`u`または`n`異なる文字は解釈時に重複できないため、これらのタイリングはセグメント間で独立しています。 繰り返しでは、隣接する文字を分割またはマージするバイナリの選択肢がすべて正確にカウントされます。すべてのタイリングが 1 つの分解に正確に対応するため、構成は 2 回カウントされません。`u`そして`w`（または`n`そして`m`）。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

s = input().strip()

# invalid characters that cannot appear in output
# since m and w are always expanded, they never appear alone
for ch in s:
    if ch == 'm' or ch == 'w':
        print(0)
        sys.exit(0)

n = len(s)

# precompute fibonacci up to n
dp = [0] * (n + 1)
dp[0] = 1
if n >= 1:
    dp[1] = 1

for i in range(2, n + 1):
    dp[i] = (dp[i - 1] + dp[i - 2]) % MOD

ans = 1

i = 0
while i < n:
    j = i
    while j < n and s[j] == s[i]:
        j += 1
    length = j - i

    if s[i] == 'u' or s[i] == 'n':
        ans = (ans * dp[length]) % MOD

    i = j

print(ans)
```コードはまず、次のような不可能なケースを拒否します。`m`または`w`。 次に、長さのランごとにフィボナッチ数を事前計算します。`k`タイリング数まで減少します`dp[k]`。 文字列は実行を抽出するために 1 回スキャンされ、各実行は乗算的に答えに寄与します。 

よくある実装の落とし穴は、実行が独立していることを忘れていることです。 もう 1 つは、どの文字が有効なシングルトンであるかを混同していることです。 のみ`u`そして`n`曖昧です。 他のものはすべて一方向に貢献します。

## テストケース```python
import sys, io

MOD = 10**9 + 7

def solve():
    s = input().strip()
    for ch in s:
        if ch == 'm' or ch == 'w':
            print(0)
            return

    n = len(s)
    dp = [0] * (n + 1)
    dp[0] = 1
    if n >= 1:
        dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = (dp[i-1] + dp[i-2]) % MOD

    ans = 1
    i = 0
    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1
        length = j - i
        if s[i] in ('u', 'n'):
            ans = (ans * dp[length]) % MOD
        i = j

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    solve()
    return sys.stdout.getvalue().strip()

# provided samples
assert run("ouuokarinn\n") == "4"

# custom cases
assert run("banana\n") == "1"
assert run("u\n") == "1"
assert run("uu\n") == "2"
assert run("m\n") == "0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | あなた | 1 | 単一のあいまいさの基本ケース |
 | うー | 2 | 分割とマージの選択 |
 | メートル | 0 | 無効な出力文字 |
 | バナナ | 1 | 曖昧さのないチェーン |

 ## 特殊なケース

 シングル`m`または`w`有効な元の文字列がスタンドアロンを生成できないため、入力では即座に答えが強制的にゼロになります。`m`または`w`。 アルゴリズムは、DP が動作する前に早期終了することでこれを処理します。 

長期にわたる`u`のような`"uuuuuu"`フィボナッチ前処理が分割の組み合わせを正しくスケールアップするかどうかをテストします。 DP では、文字が追加されるたびに複雑さが直線的に増加するだけであることが保証されます。 

混合文字列のような`"uunnnnuu"`実行の独立性をテストします。 各ブロックは個別に処理され、乗算ステップにより、相互作用することなくブロック間の組み合わせが正しくカウントされることが保証されます。
