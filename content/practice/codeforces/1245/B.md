 ## 解決策
 ## 問題の理解

 ボブが行うジャンケンの一連の動きを私たちは与えられます。 これに加えて、アリスには固定の動きのリストがあります。彼女はすべてのラウンドにわたって、指定された数のじゃんけんを正確にプレイしなければなりません。 

目標は、ボブのシーケンス全体を事前に知っているとして、アリスがラウンドの少なくとも半分 (切り上げ) で勝つように自分の動きを調整できるかどうかを決定することです。 1 ラウンドでの勝利は、標準的な RPS ルールによって決まります。ロックはチョキに勝ち、チョキはペーパーに勝ち、ペーパーはロックに勝ちます。 

そのような戦略が存在する場合、各手の正確なカウントを尊重しながら必要な勝利数を達成する、アリスの一連の有効な動きを 1 つ構築する必要もあります。 

制約は小さく、テスト ケースは最大 100 個、各ゲームのラウンドは最大 100 個です。 これは、テスト ケースごとに線形または二次よりも重いものを即座に除外しますが、より重要なのは、貪欲な構築またはカウントを超える単純な動的プログラミングで十分であることを示唆していることです。 状態空間は小さいですが構造化されているため、指数関数的な検索やバックトラッキングは必要ありません。 

素朴な戦略がリソースの枯渇を考慮せずに「局所的に勝利を最大化」しようとした場合、微妙な失敗例が発生します。 たとえば、アリスがロックスを倒すために早い段階ですべての紙の動きを貪欲に使用した場合、後でシザーズと対戦することになりますが、シザーズが残っていないため、別の分布によって保持できた可能性のある勝利を失う可能性があります。 もう 1 つの失敗モードは、いくつかの勝利を達成した後に任意に手を埋めたり、誤って正確なカウント要件を破ったり、勝利を不必要に減らしたりすることです。 

主な課題は、既知のシーケンスに対する勝利を最大化することと、各手のタイプの固定割り当てを尊重することという 2 つの制約を同時にバランスさせることです。 

## アプローチ

 ブルートフォースソリューションでは、アリスの複数の動きの可能な順列をすべて試し、それぞれの配置でボブに対する勝利を数えます。 単一のテスト ケースであっても、これは次のとおりです。$\frac{n!}{a!b!c!}$であっても天文学的に大きくなります。$n = 20$。 これはまったく実現不可能です。 

重要な観察は、供給される手が限られている点を除いて、各ポジションが独立しているということです。 置換をグローバルに考慮する必要はありません。 その代わりに、そこで勝ち手を使えるかどうかを基準に、貪欲に各ポジションを決定することができます。 

各インデックスで、ボブの動きは、勝利をもたらす最良の対抗手を正確に 1 つ決定します。 クォータ内に利用可能な手がまだある場合は、それを使用することが常に最適です。なぜなら、勝ち手を使用しても、限られたリソースを消費することを除いて、将来の機会を減らすことはないからです。 各手は 1 つのポジションにのみ貢献するため、この貪欲な割り当てにより、全体で達成可能な勝利の数が最大化されます。 

すべての勝利の機会が使い果たされたら、カウントを維持しながら残りの手を使用して残りのポジションを任意に埋めることができます。 

これにより、問題は、容量制約の下で最大勝利の割り当てを構築し、その最大値が必要なしきい値を満たしているかどうかを確認するという問題に軽減されます。

 ## アルゴリズムのチュートリアル

 しましょう$k = \lceil n/2 \rceil$、必要な最小勝利数。 

1. 各テスト ケースについて、次の内容を読んでください。$n$、カウントします$a, b, c$、ボブの文字列。 

結果の配列を保持します`ans`最初は空で、残りのカウントを追跡します。 
2. 最初のパス: 可能な限り勝利の手を割り当てるようにしてください。 

ポジションごとに$i$:

 - ボブが「R」をプレイした場合、アリスは「P」をプレイして勝ちます (P が残っている場合)。 
- ボブが「P」をプレイした場合、アリスは「S」をプレイして勝ちます (S が残っている場合)。 
- ボブが「S」をプレイした場合、アリスは「R」をプレイして勝ちます (R が残っている場合)。 

これらの勝ち手を貪欲にすぐに割り当て、対応する割り当てを減らします。 

その理由は、そのような割り当てはそれぞれ厳密に有益であるため、それを遅らせると機会を無駄にする危険があるだけであるということです。 
3. このパスの後、何回勝利が達成されたかを数えます。 
4. 勝利がすでに少なくともある場合$k$、残りの動きを使用して、残りの空のポジションをすべて任意に埋めていきます。$a, b, c$。 
5. 勝ち数が以下の場合$k$、最適な貪欲戦略でもしきい値に到達できないため、すぐに「NO」を出力します。 
6. それ以外の場合は、「YES」に続いて構築されたシーケンスを出力します。 

### なぜ効果があるのか

 各ポジションには、勝利を保証する手が最大 1 つあります。 このような動きを貪欲に割り当てても、他のポジションと競合することはありません。これは、動きは位置の依存性ではなく、グローバルなカウントによってのみ制限されるためです。 すべての勝利割り当ては合計スコアを厳密に増加させ、限られたリソースをちょうど 1 ユニット消費するため、勝利を延期しても最終的な勝利数を増やすことはできません。 したがって、この貪欲な手順により、達成可能な最大の勝利数が生成されます。 この最大値さえもしきい値を下回っている場合、有効な再配置は成功しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a, b, c = map(int, input().split())
        s = input().strip()

        ans = [''] * n
        wins = 0

        # First pass: take all guaranteed wins
        for i, ch in enumerate(s):
            if ch == 'R' and b > 0:
                ans[i] = 'P'
                b -= 1
                wins += 1
            elif ch == 'P' and c > 0:
                ans[i] = 'S'
                c -= 1
                wins += 1
            elif ch == 'S' and a > 0:
                ans[i] = 'R'
                a -= 1
                wins += 1

        need = (n + 1) // 2
        if wins < need:
            print("NO")
            continue

        # Fill remaining slots
        for i in range(n):
            if ans[i] == '':
                if a > 0:
                    ans[i] = 'R'
                    a -= 1
                elif b > 0:
                    ans[i] = 'P'
                    b -= 1
                else:
                    ans[i] = 'S'
                    c -= 1

        print("YES")
        print("".join(ans))

if __name__ == "__main__":
    solve()
```最初のループは、勝利が保証されている場合にのみ、移動リソースを積極的に消費します。 勝敗が決まるのはここだけだ。 2 番目のループは純粋にフィラー ステージであり、既に固定されている結果に影響を与えることなく、残りのクォータを尊重します。 

よくある間違いは、最初のパスで 3 つの移動タイプすべてのバランスを同時に取ろうとすることです。 実現可能性のチェックは、損失を均等に分配することではなく、十分な勝利の機会を獲得できるかどうかのみに依存するため、これは不要です。 

## 実用的な例

 ### 例 1

 入力:```
n = 3
a,b,c = 1,1,1
s = RPS
```| 私 | ボブ | 決定 | 残り (a,b,c) | 勝利 |

 | 0 | R | P | 1,0,1 | 1 |
 | 1 | P | S | 1,0,0 | 2 |
 | 2 | S | R | 0,0,0 | 3 |

 すべての手を使って勝利を確実にし、3勝を超えます。$\lceil 3/2 \rceil = 2$。 アルゴリズムは、完全に勝利した割り当てで YES を出力します。 

### 例 2

 入力:```
n = 3
a,b,c = 3,0,0
s = RPS
```| 私 | ボブ | 決定 | 残り (a,b,c) | 勝利 |

 | 0 | R | - | 3,0,0 | 0 |
 | 1 | P | - | 3,0,0 | 0 |
 | 2 | S | R | 2,0,0 | 1 |

 勝つことができる手は 1 つだけです。 必要な勝利数は 2 であるため、アルゴリズムは正しく拒否します。

 ## 特殊なケース

 エッジケースの 1 つは、ボブのシーケンスが 1 つの技タイプに大きく有利であるにもかかわらず、アリスには対応する勝ちの応答に十分なカウンターが欠けている場合です。 たとえば、ボブが多くの「R」を演奏する一方、アリスが「P」をほとんど演奏しない場合、貪欲ループは単純にそれらの位置をスキップし、後で埋めるためにそれらの位置を残します。 アルゴリズムは、使用できない勝ち手を強制することがないため、カウントを壊すことなくこれを自然に処理します。 

もう 1 つのケースは、アリスが正確に正しいカウントを持っているにもかかわらず、勝利のチャンスが分散している場合です。 たとえ勝利の可能性があるとしても、ストリングの早い段階では出現しない可能性があります。 貪欲スキャンは、線形トラバースを超える位置順序に依存せず、すべての機会が独立して評価されるため、依然としてそれらを捕捉します。 

最後のケースは、必要な勝利数が達成可能な最大勝利数と正確に等しい場合です。 このアルゴリズムは、最初に完全な最大勝利代入を構築し、その最大値ですら不十分な厳密には実行不可能なケースのみを拒否するため、引き続き機能します。
