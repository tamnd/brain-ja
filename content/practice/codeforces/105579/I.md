 ## 解決策
 ## 問題の理解

 n 個の頂点と m 個のエッジを持つ接続された無向グラフが与えられます。 頂点には、1 から n までの「新しい」番号が付けられており、入力で固定されています。 各エッジは 2 つの頂点 a と b を (この新しいラベルを使用して) 接続しますが、元の頂点識別子を保存する代わりに、エッジに書かれた値 s が与えられます。これは、その 2 つの端点の元のラベルの合計であることが知られています。 

私たちのタスクは、1 から n までの数値の順列 p を再構築することです。ここで、p[i] は、現在新しいラベル i を持つ頂点の元のラベルです。 すべてのエッジ (a、b、s) について、p[a] + p[b] = s でなければなりません。 複数の順列がすべての制約を満たす場合は、それらのいずれかを出力でき、何も存在しない場合は 0 を出力します。 

主な課題は、制約が順列にわたる線形方程式系を定義しているのに、グラフ構造が変数を結合していることです。 各エッジは 2 つの未知数間の合計制約を与えるため、これは独立した割り当てではなく、グラフに制約された割り当て問題になります。 

n ≤ 10^5 および m ≤ 3・10^5 という制約は、どの解もグラフ サイズにおいて本質的に線形またはほぼ線形でなければならないことを意味します。 順列のバックトラックや指数関数的な検索などは、直ちに不可能になります。 O(n^2) の伝播でもすでに大きすぎます。 

微妙な問題は、グラフにサイクルが含まれる可能性があることです。 ツリー上では、値をルートから伝播し、一貫してチェックできます。 サイクル中、システムは解を過度に制約したり、一貫性条件を強制したりして、多くの割り当てを拒否する可能性があります。 もう 1 つの微妙な問題は、たとえローカルな一貫性が保たれているとしても、結果の値が単なる整数の代入ではなく、1 から n の順列を形成することを保証する必要があることです。 

たとえば、順列制約を無視した場合、合計が p1 + p2 = 5 および p2 + p3 = 5 となるパス 1-2-3 のようなシステムは、複数の連続解を生成する可能性がありますが、[1, n] で有効な整数となるのはその一部だけであり、すべて別個です。 

重要なエッジケースは、サイクル内の接続されていない一貫性の矛盾、およびシステムが局所的に解決可能であるが、繰り返し値または 1 から n の範囲外の値を強制するケースです。 

## アプローチ

 ブルートフォース解釈では、各頂点を変数として扱い、値 1 から n を何らかの順序で割り当て、すべてのエッジをチェックしようとします。 これは、サイズ n (n!) のすべての順列を試行することと同等であり、n = 10^5 の場合でも実現可能性をはるかに超えています。 制約の伝播を使用してバックトラックに制限しても、各割り当てが複数の近傍に影響を及ぼし、分岐係数が大きいままであるため、爆発的な影響が出る可能性があります。 

より構造化されたビューは、各エッジ方程式 p[a] + p[b] = s を線形制約として解釈することです。 1 つの頂点値を固定すると、エッジに沿って値を伝播できます: p[b] = s - p[a]。 これは、各連結コンポーネント内で、単一の開始値を選択するまでにすべての値が決定されることを示唆しています。 これが重要な削減点です。システムは任意ではなく、コンポーネントごとに 1 つの自由度を持つ線形依存関係のグラフです。 

問題は、同じ頂点への異なるパスが一貫した値を生成する必要があることです。 これは、サイクルが開始値に制約を課すことを直ちに意味します。 コンポーネントにサイクルが含まれている場合、伝播される方程式はサイクル全体で一貫していなければなりません。そうでない場合、解は存在しません。 一貫性がある場合、サイクルは追加の自由度を導入せず、検証制約のみを導入します。 

すべての頂点値を +x または -x にルートから導出された定数を加えたものとして表現できると、構造は 2 部のような線形システムになります。 各頂点に式 p[i] =sign[i] * X + offset[i] を割り当てることができます。 次に、すべてのエッジが X を固定する制約を生成します。複数のエッジが X の競合を意味する場合、コンポーネントは無効です。 一致していれば、X は決定されます。

候補値を決定した後も、すべての p[i] が正確に 1 から n の順列であることを強制する必要があります。 これが最終的な検証ステップになります。 

したがって、最適解は、各連結成分を 1 つの変数の小さな線形システムに還元し、一貫性をチェックし、値を計算し、置換の妥当性を検証します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 制約の伝播に関してエッジがコンポーネント間で接続されることはないため、コンポーネントごとに作業します。 

1. (neighbor, sum) として保存された制約を使用してグラフの隣接リストを作成します。 これにより、方程式を効率的に伝播することができます。 
2. 未訪問の頂点ごとに、BFS または DFS を開始し、それにシンボリック形式 p[v] = 0 + X を割り当てます。これは、任意のベース参照を選択すると解釈します。 
3. トラバーサル中に、各エッジ (u、v、s) について、p[v] = s - p[u] を導出します。 v が未訪問の場合は、この派生値を割り当てて伝播を続行します。 
4. v がすでに訪問されている場合は、一貫性をチェックします。計算された値は、以前に割り当てられた値と一致する必要があります。 そうでない場合、システムは矛盾しており、このコンポーネントに対する解決策は存在しません。 
5. トラバース後、このコンポーネント内のすべての値が、最初の任意の選択に対する具体的な値として表現されます。 ただし、X を明示的に修正したことがないため、システムを別の方法で解釈します。伝播によって実際に線形関係が生成され、コンポーネントごとに 1 つの未知数に減ります。 任意の頂点をベースとして選択してこれを再計算し、他のすべての頂点を基準として表現します。 
6. X を抽出するには、コンポーネント内の頂点を 1 つ選択し、他のすべての値を p[i] = a[i] * X + b[i] として表します。ここで、a[i] は、パス制約のパリティに応じて +1 または -1 のいずれかになります。 次に、各エッジが X に当てはまらなければならない方程式を与えるので、任意のエッジから候補 X を計算し、他のすべてのエッジが一致することを確認します。 
7. X が固定されたら、すべての p[i] を計算します。 すべての p[i] が [1, n] の整数であることを確認します。 
8. すべてのコンポーネントにわたるすべての値を収集し、それらが 1 から n の順列を形成していることを確認します。 重複が発生したり、値が範囲外の場合、その解決策は無効になります。 
9. すべてのチェックに合格した場合は、1 と順列を出力します。 

中心的な考え方は、すべてのコンポーネントが単一の自由度に減少し、エッジが一貫性を確認するか、その自由度を決定するというものです。 

### なぜ効果があるのか

 連結コンポーネント内では、p[v] = s - p[u] を繰り返し適用することで、選択したルートからすべての頂点値が決定されます。 これは、パスに沿って符号を交互に配置します。つまり、各頂点値は、ルートの選択によって決定される単一の未知数のアフィン関数になります。 どのサイクルでも、このアフィン構造を検証するか、不可能にする制約が生成されます。 

不変条件は、任意のエッジを処理した後、割り当てられたすべての値が以前に処理されたすべての制約と一貫性を保つことです。これは、探索されたサブグラフ上で方程式系が常に満たされることを意味します。 矛盾が現れるとき、それはまさに矛盾した線形システムに対応します。 矛盾が現れない場合、システムは有効なアフィン解を定義します。このアフィン解は、コンポーネントごとに 1 つのグローバル パラメーターに至るまで一意である必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
g = [[] for _ in range(n)]

for _ in range(m):
    a, b, s = map(int, input().split())
    a -= 1
    b -= 1
    g[a].append((b, s))
    g[b].append((a, s))

visited = [False] * n
val = [0] * n
comp = []

def dfs(u):
    stack = [u]
    visited[u] = True
    comp_nodes = [u]
    val[u] = 0
    ok = True

    while stack:
        x = stack.pop()
        for y, s in g[x]:
            if not visited[y]:
                val[y] = s - val[x]
                visited[y] = True
                stack.append(y)
                comp_nodes.append(y)
            else:
                if val[y] != s - val[x]:
                    ok = False

    return comp_nodes, ok

res = [0] * n
used = set()

for i in range(n):
    if not visited[i]:
        nodes, ok = dfs(i)
        if not ok:
            print(0)
            sys.exit()

        # try to shift values so they become permutation candidates
        # pick a root offset so all values become positive
        mn = min(val[v] for v in nodes)

        shift = 1 - mn
        for v in nodes:
            val[v] += shift
            if not (1 <= val[v] <= n):
                print(0)
                sys.exit()
            if val[v] in used:
                print(0)
                sys.exit()
            used.add(val[v])
            res[v] = val[v]

print(1)
print(*res)
```DFS は、合計方程式を使用してエッジに沿って伝播することにより、すべてのエッジ制約と一致する値を各頂点に割り当てます。 以前に割り当てられた頂点が再び見つかった場合は、暗黙の値が一致するかどうかが検証され、サイクルの一貫性が強制されます。 

各コンポーネントが割り当てられた後、任意のルートから開始すると参照原点が効果的に固定されるため、値は加算シフトまでしか決定されません。 すべての値が有効範囲内に収まるように、コンポーネントの最小値が 1 にシフトされます。 このシフトにより、コンポーネント内のすべての値が一様に変換されるため、すべてのエッジ方程式が保存されます。 

最後に、最終出力は 1 から n の順列になる必要があるため、セットを使用してグローバルな一意性を保証します。 

微妙な実装の詳細は、有効性が最終的な調整値に依存するため、検証はシフトの前ではなく直後に行われる必要があることです。 もう 1 つの微妙な点は、整合性チェックでは格納された値の同一性だけでなく、派生関係 val[y] = s - val[x] と比較する必要があることです。そうしないと、サイクル内の未訪問の伝播エラーが検出されません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各頂点とエッジは、DFS の伝播と検証中に 1 回処理されます。 
| スペース | O(n + m) | 隣接リストと配列はグラフと値を保存します。 

線形複雑さは、n が 10^5 まで、m が 3・10^5 までであれば十分であり、反復 DFS と高速 I/O を使用して実装した場合、Python の一般的な 2 秒の制限内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    for _ in range(m):
        a, b, s = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append((b, s))
        g[b].append((a, s))

    visited = [False] * n
    val = [0] * n
    used = set()
    res = [0] * n

    def dfs(u):
        stack = [u]
        visited[u] = True
        comp = [u]
        val[u] = 0
        ok = True

        while stack:
            x = stack.pop()
            for y, s in g[x]:
                if not visited[y]:
                    val[y] = s - val[x]
                    visited[y] = True
                    stack.append(y)
                    comp.append(y)
                else:
                    if val[y] != s - val[x]:
                        ok = False
        return comp, ok

    for i in range(n):
        if not visited[i]:
            comp, ok = dfs(i)
            if not ok:
                return "0\n"
            mn = min(val[v] for v in comp)
            shift = 1 - mn
            for v in comp:
                val[v] += shift
                if not (1 <= val[v] <= n):
                    return "0\n"
                if val[v] in used:
                    return "0\n"
                used.add(val[v])
                res[v] = val[v]

    return "1\n" + " ".join(map(str, res)) + "\n"

 ## 特殊なケース

 最小の単一ノード グラフには制約がありません。 DFS は値 0 を割り当て、それを 1 にシフトして、有効な順列を即座に生成します。 これにより、孤立した頂点が正規化下で正しく動作することが確認されます。 

コンポーネントが重複するシフト範囲を生成する切断されたグラフは、グローバル`used`セット。 各コンポーネントは独立してシフトされ、衝突が発生した場合、アルゴリズムは構成を正しく拒否します。 これにより、順列要件に違反する、2 つの独立したコンポーネントが同じ元のラベル空間にマッピングされることが防止されます。 

循環矛盾は、DFS 中にノードを再訪問したときに、すでに割り当てられている値とは異なる値が得られたときに検出されます。 たとえば、エッジの合計が一致しない三角形では、サイクルの周りの伝播により最終的に不一致が強制され、即座に拒否が発生します。
