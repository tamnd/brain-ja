 ## 解決策
 ## 問題の理解

 直線道路での単純な運転シナリオをシミュレーションしています。 車は交差点から少し離れたところから発進し、一定の速度で交差点に向かって進みます。 未来の特定の時刻に、交差点の信号機が一定時間赤になります。 私たちの仕事は、赤の区間中に車が交差点内に進入するかどうかを判断することです。 そうなった場合、ドライバーはブレーキをかけなければなりません。 それ以外の場合、車は介入なしで続行できます。 

入力は 4 つの量を記述します。 距離`s`時間ゼロの時点で車が交差点からどのくらい離れているかを示します。 スピード`v`は一定であるため、交差点に到達するまでに必要な時間は完全に決定されます。 値`t`信号が赤に変わるまでの遅延です。`T`開始後に赤色が続く時間です。 

重要な導出量は、車の交差点への到着時間です。`s / v`。 時間間隔中はライトが赤になります`[t, t + T]`。 問題は、これら 2 つの時間間隔が赤信号の間に車が交差点に進入するような形で交差しているかどうかを確認することになります。 

制約は小さく、すべての値は最大 100 です。これにより、テスト ケースごとの定数時間演算を超える最適化の必要性が直ちに排除されます。 除算を完全に避けて整数比較を行う場合、浮動小数点精度は不要です。 

到着時間が端数になると、微妙な問題が発生します。 計算してみると`s / v`浮動小数点数を直接使用すると、境界例では精度誤差が発生する可能性があります。 例えば、`s = 9, v = 2`与える`4.5`これは、真の値よりわずかに下または上で表される可能性があります。 これは、次のような整数のしきい値と比較するときに重要です。`t`そして`t + T`。 より安全なアプローチは、分割を完全に避けることです。 

もう 1 つのエッジ ケースは、信号が赤に変わった瞬間、または信号が再び青に変わったまさにその瞬間に車が到着する場合です。 このステートメントは、自動車が切り替えの瞬間に正確に到着しないことを保証するため、厳密な不等式で十分であり、平等性を慎重に扱う必要はありません。 

## アプローチ

 直接シミュレーションのアプローチでは、到着時間を計算します。`s / v`そしてそれが赤い間隔内にあるかどうかを確認します`[t, t + T]`。 時間の関数としての自動車の位置は決定的であり、単一のイベントのみを考慮するため、これは原理的には正しいです。 ただし、浮動小数点の除算と整数の境界との比較が必要となり、不必要な精度のリスクが生じます。 

代わりに、条件を整数の不等式に変換することで、時間を完全に排除できます。 車は時間どおりに交差点に到着します`s / v`。 信号が赤になっても交差点の手前にいるという条件は、`s / v < t + T`、赤が有害な影響を及ぼし始めるまではまだ経過していません。`s / v > t`。 より正確に言うと、車は次の場合に影響を受けます。`t <= s / v <= t + T`。 

すべての部分を乗算すると、`v`(これは正であるため、不等号の方向は保持されます) は同等の整数条件を生成します。`t * v <= s <= (t + T) * v`。 これにより、浮動小数点演算が完全に削除され、問題は定数時間の算術チェックに軽減されます。

 ## アルゴリズムのチュートリアル

 この問題を完全に整数演算の観点から再定式化します。 

1. 両方のエンドポイントに速度を乗じて、信号が赤である時間間隔を「距離単位」で計算します。`v`。 これにより範囲が生成されます`[t * v, (t + T) * v]`これは、信号が赤のときに車が移動した可能性のあるすべての距離に相当します。 
2. 車の距離を比較する`s`この間隔に対して。 もし`s`この範囲内にある場合、車は信号が赤のときに交差点に到着することを意味します。 
3. もし`s`間隔内にある場合、出力`"Yes"`ブレーキが必要になるからです。 それ以外の場合は出力`"No"`。 

乗算が機能する理由は、時間の比較と距離の比較が正の定数係数によって線形に関係しているためです。`v`したがって、イベントの順序は保持されます。 

### なぜ効果があるのか

 車は時間通りに交差点に到着します`s / v`が経過します。 赤信号の間隔は時間で定義されますが、すべてに次の値を掛けます。`v`車の到着時間と赤色の間隔の両方を、順序を変更せずに同じスケールに変換します。 以来`v > 0`、変換は単調であるため、時間内のオーバーラップは、変換された整数空間内のオーバーラップに正確に対応します。 これにより、チェックが保証されます。`t * v <= s <= (t + T) * v`これは、赤の段階で車が交差点にあるかどうかを確認することに相当します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s, v, t, T = map(int, input().split())
    
    start = t * v
    end = (t + T) * v
    
    if start <= s <= end:
        print("Yes")
    else:
        print("No")

if __name__ == "__main__":
    solve()
```このソリューションは 4 つの整数を読み取り、次のようにスケーリングすることで赤信号の時間間隔を同等の距離間隔に即座に変換します。`v`。 との比較`s`純粋に整数ベースになるため、浮動小数点の問題が完全に回避されます。 

よくある間違いは計算です`s / v`それを直接比較すると、`t`そして`t + T`。 論理的には正しいですが、精度のエラーや不必要な複雑さのリスクがあります。 もう 1 つの微妙な問題は、両方の境界が包括的であることを忘れていることです。 この問題では、到着時に正確な切り替えの瞬間が発生しないことが保証されているため、包括性によって曖昧さが生じることはありません。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、赤色の間隔が時間 0 の直後に始まる場合です。 入力用`10 2 0 3`、間隔は`[0, 6]`。 車は時間どおりに到着します`10 / 2 = 5`、区間内にあります。 アルゴリズムは計算します`start = 0`そして`end = 6`、そして正しく報告します`"Yes"`以来`5`範囲内です。 

もう 1 つのケースは、赤色の間隔の遅延がゼロであるが継続時間もゼロであり、実質的に赤色になることがない場合です。 のために`1 1 0 0`、間隔は`[0, 0]`。 車は時間どおりに到着します`1`、これは外側にあり、整数チェックの結果は次のようになります。`start = 0`、`end = 0`、 それで`1`は内部になく、出力は`"No"`または`"Yes"`解釈次第。 このステートメントは、正確な切り替え衝突がないことを保証するため、この縮退ケースは不等式モデルと一貫して動作します。 

最後の微妙なシナリオは、車が非常に速い場合です。 のために`100 10 5 2`、到着時間は`10`、赤い間隔は`[50, 70]`。 変換されたチェックは次のようになります。`50 <= 100 <= 70`これは誤りで、信号が赤になる前に車が安全に通過することを確認しています。
