 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$タイル張りの壁を表すグリッド。 各セルには、次のように書かれた金のタイルが含まれています。`G`、または銀のタイル、と書かれています。`S`。 整数も与えられます$k$、連続したものを選択したいと思います。$k \times k$このグリッドのサブスクエア。 そのサブ正方形を選択した後、正方形全体が均一になるように、つまりすべてのタイルが同じタイプになるように、その中のいくつかのタイルを再ペイントすることができます。 

選ばれたものに対して$k \times k$地域、私たちはすべてを作ることを決定することができます`G`あるいはすべて`S`。 コストは、選択したターゲット タイプと一致しないセルの数です。 タスクは、可能なすべての再塗装コストの最小値を計算することです。$k \times k$サブスクエアと両方とも均一な色をターゲットとしています。 

グリッドのサイズ$n$最大1000であり、$k$この分離は非常に重要です。 可能な正方形の数はおおよそ次のとおりです$(n-k+1)^2$、それは約です$10^6$最悪の場合。 各正方形には最大で次のものが含まれます$k^2 \le 10^4$細胞。 平方当たりの単純な再計算は約$10^{10}$操作は 2 秒には大きすぎます。 有効な解決策は、正方形あたりのコストを一定またはほぼ一定の時間に削減する必要があります。 

微妙な問題は、両方のターゲット色を考慮する必要があることです。 正方形を均一にしようとするだけの単純な実装`G`またはのみに`S`計算を再利用せずにウィンドウごとに独立して実行すると、作業が重複して効率が失われる危険があります。 

もう 1 つのエッジケースは次のような場合です$k = n$。 その場合、候補となる正方形は 1 つだけあり、答えはグリッド全体を均一にするための最小限の反転だけです。 正しいソリューションでは、複数のウィンドウが存在することを前提としてはいけません。 

## アプローチ

 ブルートフォースアプローチは簡単です。 可能なすべての左上隅について$k \times k$正方形、すべてスキャンします$k^2$セルを数えて何個あるか数えます`G`そして何人ですか`S`。 そのマスのコストは$\min(\#G, \#S)$。 すべてのポジションで最小値を採用します。 

これは、近似を行わずにすべての候補領域を直接評価するため、正しいです。 障害点は実行時です。 がある$O(n^2)$ポジションと各コスト$O(k^2)$、につながる$O(n^2 k^2)$。 と$n = 1000$そして$k = 100$、これについてです$10^{10}$動作が遅すぎます。 

重要な点は、各正方形のカウントを最初から再計算する必要がないことです。 代わりに、グリッド全体で 2D プレフィックスの合計を事前計算し、その数を個別にカウントすることができます。`G`セルは任意の四角形内に表示されます。 数をクエリできるようになると、`G`あらゆる細胞$k \times k$の地域$O(1)$、の数`S`細胞はただ$k^2 - G$, そのため、費用がすぐにわかります。 

これにより、定数時間クエリで固定サイズのウィンドウをすべての位置にスライドさせるという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2 k^2)$|$O(1)$| 遅すぎる |
 | プレフィックスの合計 |$O(n^2)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 グリッドを数値行列に変換します。`G`1とそれぞれになります`S`次に、2D プレフィックス合計配列を構築します。 

1. プレフィックス合計配列を構築する`ps`どこ`ps[i][j]`の数を保存します`G`長方形内のセル`(0,0)`に`(i-1,j-1)`。 このシフトにより、境界の処理が簡素化されます。 
2. 各セルについて`(i,j)`元のグリッドで次を計算します。$$ps[i+1][j+1] = ps[i+1][j] + ps[i][j+1] - ps[i][j] + (grid[i][j] == 'G')$$これにより、各プレフィックス セルがすべてのセルをカウントするようになります。`G`s を上と左に 1 回だけ入力します。 
3. 可能なすべての左上隅を反復処理します。`(i,j)`の$k \times k$四角。 有効な範囲は次のとおりです。`0 ≤ i ≤ n-k`、`0 ≤ j ≤ n-k`。 
4. 各位置について、次の数を計算します。`G`包含/除外式を使用して正方形の内側にタイルを配置します。$$G = ps[i+k][j+k] - ps[i][j+k] - ps[i+k][j] + ps[i][j]$$これにより、一定時間でのカウントが得られます。 
5. コンピューティング`S = k*k - G`。 正方形を均一にするコストは`min(G, S)`。 
6. すべてのポジションにわたる最小コストを追跡し、出力します。 

### なぜ効果があるのか

 プレフィックス合計配列は、すべてのエントリにプレフィックスの正確な数が格納されるという不変式を維持します。`G`対応するサブ長方形内のタイル。 長方形の合計は包含と除外に対して線形であるため、$k \times k$クエリは、重複または省略することなく 4 つのプレフィックス値に分解できます。 これにより、各ウィンドウが正しいカウントで 1 回だけ評価されることが保証され、すべての有効な配置が考慮されるため、グローバル最小値が見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    ps = [[0] * (n + 1) for _ in range(n + 1)]

    for i in range(n):
        row_sum = 0
        for j in range(n):
            val = 1 if grid[i][j] == 'G' else 0
            ps[i+1][j+1] = ps[i][j+1] + ps[i+1][j] - ps[i][j] + val

    best = k * k

    for i in range(n - k + 1):
        for j in range(n - k + 1):
            g = ps[i+k][j+k] - ps[i][j+k] - ps[i+k][j] + ps[i][j]
            s = k * k - g
            best = min(best, g, s)

    print(best)

if __name__ == "__main__":
    solve()
```このソリューションでは、まずゴールド タイルのみに対して 2D プレフィックス合計を構築します。 これは、定数時間の四角形クエリをサポートするために必要な唯一の前処理ステップです。 ネストされたループは、有効なものをすべて列挙します。$k \times k$各クエリは 4 つのプレフィックス アクセスを使用するため、正方形の内部スキャンは必要ありません。 

重要な実装の詳細は、1 から始まるインデックス付けです。`ps`これにより、包含/除外を適用する際の境界チェックが回避されます。 このシフトがなければ、すべての四角形クエリのエッジで条件付きロジックが必要となり、エラーのリスクが高まります。 

の初期化`best`として`k*k`すべてのタイルがすでに 1 つの色である場合、これが最悪の場合の再描画コストであるため、機能します。 有効な構成はこれを超えることはできません。

 ## 特殊なケース

 いつ$k = 1$、すべてのセルは有効な正方形です。 このアルゴリズムはプレフィックス合計を使用して各セルを独立して評価しますが、各クエリはセル自体に帰着します。 単一セルはすでに均一であるため、最小コストは常に 0 です。 

いつ$k = n$、窓は1つだけです。 プレフィックス合計クエリはグリッド全体をカバーし、アルゴリズムはすべてを次のように変換するかどうかを正しく計算します。`G`または`S`のほうが安いです。 

チェッカーボードなどの交互パターンを持つグリッドの場合でも、プレフィックス合計は各ウィンドウのカウントを正しく集計します。 地域のパターンは大きく異なりますが、それぞれ$k \times k$領域は独立して評価され、包含と除外により正確な長方形の合計が保証されるため、寄与を見逃すウィンドウはありません。
