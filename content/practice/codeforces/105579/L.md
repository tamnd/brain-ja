 ## 問題の理解

 一連の牛乳バッチが与えられ、各バッチには 2 つの属性があります。 一つ目は係数です$b_i$これは、加熱温度の単位当たりに Vova がどの程度の風味を得るかを表します。 2つ目は限界です$t_i$これは、泡を生成せずにこのバッチを加熱できる最高温度を表します。 選択したグローバル加熱温度が$T$、次にバッチ$i$以下の場合にのみ飲めます$T \le t_i$。 飲みやすいものであれば、まさに貢献します$b_i \cdot T$トータルな楽しみ方へ。 もし$T > t_i$、バッチは使用できず、何も貢献しません。 

タスクは単一の整数温度を選択することです$T$これはすべてのバッチに適用され、泡のない状態を維持するすべてのバッチにわたる寄与の合計が最大化されます。 

重要な構造は次のとおりです$T$グローバルです。 各バッチを個別に最適化するのではなく、一部の項目の寄与を同時に線形に増加させ、同時に他の項目を除外する 1 つの値を選択します。 

入力サイズ$n$最大 100000 まで指定でき、値は$t_i$と同じ大きさにすることができます$10^9$。 これにより、考えられるすべての温度を試すアプローチは即座に除外されます。 ブルートフォースオーバー$T$までの確認が必要になります$10^9$候補者、それは不可能です。 すべてのペアまたはサブセットを反復処理することさえ、指数関数的な増加のため実行不可能です。 

素朴な観察では、答えは値によって定義された「ブレークポイント」にのみ依存します。$t_i$、増えているので$T$これらのしきい値のいずれかを超えた場合にのみ、アクティブなバッチのセットが変更されます。 

素朴な推論による微妙な失敗例は、$T = \max t_i$常に最適です。 たとえば、1 つのバッチに非常に大きなデータが含まれている場合、$b_i$でも小さい$t_i$、増加しています$T$そのしきい値を超えると完全に削除され、合計が減少する可能性があります。 

別の障害モードがそれぞれを評価しようとしています$T$計算を再利用せずに独立して実行できるため、$O(n \cdot \max t_i)$または同様の不可能な複雑さ。 

## アプローチ

 ブルートフォースのアイデアは単純です。 あらゆる可能な整数の温度に対して$T$、すべての合計を計算します$b_i \cdot T$そのような$t_i \ge T$。 候補者ごとに$T$、すべてスキャンします$n$項目を選択し、実現可能性を確認し、貢献を蓄積します。 これは問題の定義を直接シミュレートするため、これは正しいです。 

ただし、このアプローチは遅すぎるため、$T$までの範囲で可能$10^9$。 候補者をユニークに限定したとしても$t_i$価値観、私たちはまだ$n$候補者とそれぞれの要件$O(n)$仕事、につながる$O(n^2)$、これは大きすぎます$10^5$。 

重要な洞察は、視点を逆転させることです。 温度を固定してどのバッチが生き残るかを確認する代わりに、バッチを固定し、それがどの温度に寄与しているかを尋ねます。 バッチ$i$すべての人に貢献します$T \le t_i$、その寄与は次のように線形です。$T$。 これは、合計関数は線形関数の合計ですが、それぞれが独自のカットオフで切り捨てられることを意味します。 

並べ替えることができます$t_i$。 増えるにつれて$T$、バッチはまさに次の場合に無効になります。$T$閾値を超えています。 これは可能性を一掃することを示唆しています$T$値の降順$t_i$、どのバッチがまだアクティブであるかを維持します。 

よりクリーンな変革は、貢献の関数として考えることです。$T$:$$f(T) = T \cdot \sum_{i: t_i \ge T} b_i$$したがって、問題は次の最大値を見つけることになります。$T \cdot S(T)$、 どこ$S(T)$の合計です$b_i$すべての中で$t_i \ge T$。 として$T$増加し、$S(T)$減少するだけですが、$T$が増加します。 最適化は、すべての項目を正確に含めた時点で発生します。$t_i \ge T$、これはしきい値の並べ替えと候補ブレークポイントのチェックに対応します。 

ペアを並べ替えます$(t_i, b_i)$昇順に$t_i$。 次に、最大のものから処理します$t_i$下向きに、現在までの合計を維持します$b_i$。 各閾値で$t_i$を選択することを検討します。$T = t_i$2 つの隣接するしきい値の間では、アクティブ セットは変化せず、増加するためです。$T$アクティブ セットを境界まで固定したままにして、乗算係数のみを改善します。 

したがって、評価する必要があるのは、$T \cdot (\text{sum of } b_i \text{ with } t_i \ge T)$これらの重要なポイントで。

 ## アルゴリズムのチュートリアル

 この問題を、制約から導出された少数の意味のある候補点での関数の評価に変換します。 

1. 各バッチを次のようにペアリングします$(t_i, b_i)$リストを次の基準で並べ替えます$t_i$昇順で。 これにより、温度が上昇したときにバッチが有効でなくなる瞬間に基づいてバッチが整理されます。 
2. すべての合計を計算します。$b_i$。 これは、の初期値を表します$S(T)$非常に小さいため$T$、すべてのバッチが有効です。 
3. ソートされた配列を小さい順に走査します。$t_i$最大まで。 それぞれのポジションで$i$、私たちは治療します$t_i$候補温度として。 
4. 現在のサフィックスの合計を維持します。$b_i$ですが、先に進むにつれて減算することで暗黙的に計算されます。 しきい値のあるバッチを渡すとき$t_i$、それ以上の温度では有効ではなくなるため、削除します。$b_i$アクティブな合計から。 
5. それぞれの異なるしきい値で$t_i$、候補の答えを次のように計算します。$t_i \times (\text{current active sum})$。 正確に境界に到達したとき、またはアクティブ セットの更新直後にのみ評価します。 
6. このようなすべての候補評価にわたる最大値を追跡します。 

これらの点に限定できる理由は、2 つの連続するしきい値の間で、アクティブ セットが$S(T)$は一定です。 そんな隙間の中で、$f(T) = T \cdot S$は次の一次関数です$T$したがって、間隔内の最大値は常に正しい端点になります。 

### なぜ効果があるのか

 最適化されている関数は区分的に線形であり、ブレークポイントは値に正確に発生します。$t_i$。 アクティブなバッチのセットは固定されたままであるため、ブレークポイント間では傾きは変わりません。 以来$f(T)$は各間隔で線形であるため、その間隔にわたる最大値はエンドポイントになければなりません。 したがって、評価をエンドポイントに制限する$t_i$グローバル最大値を捕捉するには十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    b = list(map(int, input().split()))
    t = list(map(int, input().split()))
    
    pairs = list(zip(t, b))
    pairs.sort()
    
    total_b = sum(b)
    best = 0
    
    i = 0
    n = len(pairs)
    
    while i < n:
        j = i
        # group equal t values
        while j < n and pairs[j][0] == pairs[i][0]:
            j += 1
        
        # temperature candidate is pairs[i][0]
        T = pairs[i][0]
        
        # remove all elements with t == T from active set
        for k in range(i, j):
            total_b -= pairs[k][1]
        
        # now active set is all with t > T
        best = max(best, T * total_b)
        
        i = j
    
    print(best)

if __name__ == "__main__":
    solve()
```この実装は、しきい値によるペアのソートに依存しています。 変数`total_b`はすべての係数の合計として始まり、各しきい値グループを通過するにつれて徐々に寄与を失います。 現在のしきい値を持つすべてのバッチを削除した後、その正確な温度での寄与を計算します。これは、この点を超えて増加した場合、それらのバッチは有効ではなくなるためです。 

等しいグループ化$t_i$値が重要なのは、そのしきい値を超えるとすべての値が同時に無効になるためであり、そのレベルで候補を評価する前にそれらの値が削除されていることを確認する必要があります。

 ## 特殊なケース

 重要なエッジ ケースは、最適温度が最小のしきい値である場合です。 入力を考慮してください。```
2
100 1
1 100
```私たちが選ぶなら$T = 1$、両方のバッチが寄与し、$101$。 私たちが選ぶなら$T = 100$、2番目のバッチのみが寄与し、$100$。 アルゴリズムは両方のブレークポイントを評価します。 で$T = 1$、まだ削除は行われていないため、スコアは$1 \cdot 101$。 で$T = 100$、最初のバッチはすでに削除されているため、$1 \cdot 1$残り、生産$100$。 最大値は正しく識別されます。 

もう 1 つの特殊なケースは、すべてが$t_i$は同一です。 その後、すべてのバッチが一度に削除され、その単一のしきい値でのみ意味のある評価が行われます。 アルゴリズムはグループを 1 回処理し、すべてを減算します。$b_i$、それを超えると寄与がゼロであると評価され、特別なケースを使用せずに正確性が保証されます。
