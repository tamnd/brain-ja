 ## 解決策
 ## 問題の理解

 私たちには、100 × 100 のグリッド上に配置された複数のキングの位置が与えられます。 1 回のアクションで、単一のキングを選択し、それを 8 方向のいずれかに段階的に移動し始めます。つまり、移動するたびに、そのセルが対角線を含む隣接する正方形の 1 つに変更されます。 この移動キングが既に別のキングを含むセルに入るたびに、そのキングはボードから削除され、この選択されたキングの移動プロセスは、そのようなキャプチャが実行されるまで継続されます。 キャプチャが行われた後、このアクションを停止し、残りのキングを選択してプロセスを繰り返すことができます。 

目標は、キングのセットを正確に 1 つに減らし、すべてのアクションにわたるシングル ステップ キングの動きの総数を最小限に抑えることです。 

制約から分かる重要な点は、キングの数は最大でも 100 人であるということです。 これは、100 ノードにわたる完全なグラフには 4950 個のエッジしかないため、キングのすべてのペア間の関係を考慮しようとするあらゆるソリューションが実行可能であるほど十分に小さいです。 これは、ペアごとの距離と、完全に接続された構造にわたる全体的な最適化が関与している可能性が高いことを直ちに示唆しています。 

微妙な問題は、「移動」コストが実際に何を意味するのかを理解することです。 キャプチャは無料ではありません。 開始キングからターゲットキングまで移動するのに必要なキングステップ数がかかります。 これは、グラフの意味での単なる隣接ではなく、8 接続グリッド上の幾何学的最短経路であり、2 点間の正確なチェビシェフ距離です。 

素朴な誤解があると、各キャプチャーをコスト 1 として扱うことになりますが、ボード全体を移動するには多くの手順が必要となるため、これは間違いです。 もう 1 つの失敗モードは、貪欲に最近傍だけを考えることです。これは、複数のキングを効率的にマージする長期的な構造を考慮していません。 

## アプローチ

 ブルート フォース ビューでは、どのキングを移動し、どのターゲットを捕捉するかを繰り返し選択するプロセス全体をシミュレートし、考えられるシーケンスごとに総コストを計算します。 これは、k 個のオブジェクトをマージするすべての可能な順序を探索し、各ステップで、正確なパス コストでマージするためにすべての可能なペアを試行することと同じです。 パスの再計算を無視したとしても、シーケンスの数は k の階乗になります。これは、100 はおろか、k = 20 の場合でもまったく実行不可能です。 

重要な構造的洞察は、プロセスを再解釈することです。 別のキングを捕らえるためにキングを移動するたびに、事実上 2 つのコンポーネントが 1 つにマージされ、そのマージのコストはその時点での位置にのみ依存します。 最終結果は 1 人のキングが残るため、1 人を除くすべてのキングは 1 回だけ吸収されなければなりません。 これはまさに、初期の点セット上にスパニング ツリーを構築する構造です。各エッジは 1 つのキャプチャ操作に対応し、重みはその時点でマージされている 2 つのキング間の移動コストです。 

マージの宛先は常に元の 2 つのエンドポイントのうちの 1 つの位置であるため、2 つのキング (i, j) 間の距離はマージの順序に関係なく固定されます。 これにより、問題はキングの完全なグラフ上で最小スパニング ツリーを見つけることに変わります。ここで、各エッジの重みは座標間のチェビシェフ距離です。 

このように理解すると、問題は最大 100 ノードでの標準的な MST 計算に帰着し、Kruskal のアルゴリズムを使用して効率的に解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースマージシミュレーション | k の指数 | O(k) | 遅すぎる |
 | 完全なグラフ上の最小スパニング ツリー | O(k^2 log k) | O(k^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 各キングをグラフ内のノードとして扱い、任意の 2 つのキング間のコストを、空のボード上で一方から他方に移動するのに必要なキングの移動数として定義します。 

1. チェビシェフ距離を使用して、キングの各ペア間のコストを計算します。 これは`max(|r1 - r2|, |c1 - c2|)`なぜなら、キングは斜めに移動して、行と列の両方の差を同時に減らすことができるからです。 これにより、完全な重み付きグラフが定義されます。 
2. 計算された重みを使用してすべてのエッジ (i, j) を構築します。 k は最大 100 なので、エッジの数は管理可能です。 
3. すべてのエッジを重みで降順でない順に並べ替えます。 これにより、マージ構造内でサイクルが発生しない、使用可能な最小の接続を貪欲に選択できるようになります。 
4. k ノード上で Disjoint Set Union 構造を実行します。 最初は、各キングは独自のコンポーネントです。 
5. ソートされたエッジを反復処理します。 各エッジ (i, j) について、i と j が異なるコンポーネントにある場合は、それらをマージし、エッジの重みを答えに追加します。 すべてのキングが 1 つのコンポーネントに接続されるまで続けます。これには正確に k − 1 個のマージが必要です。 

各マージは元のプロセスの 1 つのキャプチャ操作に対応し、累積されたエッジの重みは、必要なシングルステップ キングの移動の合計数を表します。 

### なぜ効果があるのか

 キャプチャの有効な各シーケンスは、元のキングにわたるスパニング ツリーを定義します。各エッジは、以前は別個だった 2 つのコンポーネント間の 1 つのキャプチャ ステップに対応します。 そのステップのコストは、マージ時に選択されたペア間の正確なチェビシェフ距離であり、完全なグラフ内の固定エッジの重みと一致します。 残りのキングが 1 つになる戦略は、正確に k − 1 個のマージを実行する必要があるため、あるスパニング ツリーに対応します。 

逆に、ルートを選択し、そのエッジに沿ってマージをシミュレートし、各エッジが 1 回だけ支払われるようにすることで、スパニング ツリーを実現できます。 したがって、総移動コストを最小化することは、このグラフの最小スパニング ツリーを見つけることと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        return True

def solve():
    k = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(k)]

    edges = []
    for i in range(k):
        r1, c1 = pts[i]
        for j in range(i + 1, k):
            r2, c2 = pts[j]
            w = max(abs(r1 - r2), abs(c1 - c2))
            edges.append((w, i, j))

    edges.sort()
    dsu = DSU(k)

    ans = 0
    used = 0

    for w, a, b in edges:
        if dsu.union(a, b):
            ans += w
            used += 1
            if used == k - 1:
                break

    print(ans)

if __name__ == "__main__":
    solve()
```DSU は、選択されたマージを通じてどのキングがすでに接続されているかを維持し、サイクルが形成されないようにします。 結合が成功するたびに、以前は別個だった 2 つのグループ間で 1 つのキャプチャ操作を選択することに対応します。 ソートされたエッジにより、利用可能な最も安価な接続が常に最初に選択されることが保証されます。これはまさに最小スパニング ツリーを定義する貪欲なプロパティです。 

チェビシェフ距離の計算は、空のグリッド内でのキングの真の最小数をモデル化するため、非常に重要です。 他の距離を定義すると、最短移動コストとの等価性が崩れてしまいます。 

## 実用的な例

 3 つのキングの小さな構成を考えてみましょう。 

入力:```
3
1 1
1 3
3 2
```ペアごとの距離を計算します。 

| ペア | 距離 |
 | --- | --- |
 | (1,2) | 2 |
 | (1,3) | 2 |
 | (2,3) | 2 |

 すべてのエッジの重みは等しいため、すべてのエッジを誤って合計した場合に限り、スパニング ツリーの合計コストは 4 になりますが、MST は 2 つのエッジのみを選択します。 

| ステップ | 選択されたエッジ | コンポーネント | コスト |
 | --- | --- | --- | --- |
 | 開始 | - | {1}、{2}、{3} | 0 |
 | 1 | (1,2) | {1,2}、{3} | 2 |
 | 2 | (2,3) | {1,2,3} | 2 |

 合計コストは4です。 

このトレースは、正確に k − 1 個のマージが実行されていること、および DSU が冗長接続を正しく防止していることを確認します。 

ここで、一人の王が遠く離れている場合を考えてみましょう。```
3
1 1
1 2
100 100
```距離:

 | ペア | 距離 |
 | --- | --- |
 | (1,2) | 1 |
 | (1,3) | 99 |
 | (2,3) | 99 |

 | ステップ | 選択されたエッジ | コンポーネント | コスト |
 | --- | --- | --- | --- |
 | 開始 | - | {1}、{2}、{3} | 0 |
 | 1 | (1,2) | {1,2}、{3} | 1 |
 | 2 | (1,3) または (2,3) | {1,2,3} | 99 |

 合計コストは 100 で、アルゴリズムがコストのかかるマージを必要になるまで適切に遅らせていることがわかります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k^2 log k) | すべてのペアワイズ エッジは O(k^2) で生成され、ソートが優先されます。 
| スペース | O(k^2) | すべてのエッジの保管 |

 ## 特殊なケース

 最小限のエッジケースは、キングがちょうど 2 人いる場合です。 このアルゴリズムは、チェビシェフ距離に等しい重みを持つ単一のエッジを構築し、それをすぐに出力します。 これは可能な唯一の移動シーケンスと一致するため、正しさはすぐにわかります。 

退化した幾何学的構成とは、すべてのキングが一直線上に並んでいるか、密集して詰め込まれている場合です。 このような場合、多くのエッジの重みは等しいか、ほぼ同じになります。 DSU は、複数の等しい重みのエッジが存在する場合でも、k − 1 のみが選択されるようにして、オーバーカウントを回避します。 

遠い外れ値のケースは、貪欲なクラスタリングがなぜ重要なのかを示しています。 1 つのキングが遠く離れている場合、MST 構造は、より近いマージがすべて使い果たされるまで接続を遅らせ、高価なエッジが 1 回だけ使用されるようにします。これは、その孤立したキングを最終的に吸収する必要性に一致します。
