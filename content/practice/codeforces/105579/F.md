 ## 解決策
 ## 問題の理解

 数字の 1 から始めて、複数の小さな算術演算が与えられます。 各演算は、4 つの記号の 1 つと 1 から 9 までの数字で構成されるペアです。これらの演算をある順序で配置し、現在の値に順番に適用して、最終結果を生成する必要があります。 タスクは、この最終値をできるだけ大きくする順序を選択し、並べ替えられたリストを出力することです。 

各演算は現在の値を非常に直接的な方法で変換します。加算では一定量増加し、減算では一定量減少し、乗算ではスケールし、除算では縮小します。 主な難点は、後の操作はすでに変更された値に作用するため、操作の効果がそれがいつ適用されるかに大きく依存することです。 

n ≤ 100 という制約は、O(n²) 個の推論またはソートベースの戦略を快適に考慮できることを意味します。 n! 以降、順列にわたって指数関数的なことは不可能です。 n = 10 の場合でも成長が速すぎます。この構造は、解決策がすべての順列を試すのではなく、操作の種類を順序付けることであることを示唆しています。 

スケーリングと加算操作の間の相互作用から、微妙な問題が発生します。 たとえば、初期に適用された小さな加算は、後の乗算後に大きくなる可能性がありますが、後で適用された同じ加算は、生の値のみに寄与します。 同様に、早期に適用された減算は、後で乗算されると、より大きな損失に増幅される可能性があります。 

単純な戦略を露呈するエッジ ケースには、位置効果を考慮せずにさまざまなタイプの操作を混合することが含まれます。 たとえば、すべての加算を最初に配置し、その後に乗算を配置すると、乗算は加算を増幅する必要があるという事実を見逃してしまうため、逆の順序の方が適切です。 もう 1 つの失敗例は、すべての操作を順序とは無関係に処理し、すぐに中断してしまうことです。 たとえば、`+ 5`そして`* 2`、申請中`+ 5`最初に 7、次に 14 が生成されますが、逆にすると 2、次に 7 と、より小さい結果が生成されます。 

最後のコーナーケースは除算です。 除算は値を減らすため、それを早めに配置すると、その後に続くすべてが永久に縮小されます。 除算を任意に組み合わせる単純なアプローチでは、以前の乗算や加算によって得られた大きな利益が簡単に失われる可能性があります。 

## アプローチ

 強引なアプローチでは、n 枚のカードのすべての順列を試し、各順序のプロセスをシミュレートし、最大の結果を追跡します。 これは、考えられるすべてのシーケンスを直接評価するため、正しいです。 ただし、n が必要です。 各評価には O(n) のコストがかかり、O(n · n!) 時間がかかり、n = 10 の場合でも実行不可能になります。 

重要な観察は、実際には操作を恣意的に並べ替える必要がないということです。 各操作は現在の値をスケーリングするかシフトします。スケーリングはその後に続くすべてのものの大きさを変更するため、より強力な構造効果を持ちます。 これは、演算をその定性的効果によってグループ化する必要があることを意味します。乗算器はすべてを増幅するために最初に来るべきであり、加算演算は中間にあるべきであり、除数は以前の利益の縮小を避けるために最後に来るべきです。 

乗算器内では、係数が大きいほど、後続の乗数とそれに続くすべての相加効果も増幅されるため、早い段階でより有益になります。 除算は乗算で構成されるため、除算内では順序は重要ではありませんが、すべての除算は可能な限り遅らせる必要があります。 加算と減算は、すでに増幅されているように乗算器の後、減算されないように除算の前に配置するのが最適です。 

これにより、問題は操作を少数のカテゴリに分類し、そのカテゴリ内で適切に順序付けすることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・n!) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各操作がスケーリング効果とどのように相互作用するかを利用して、最適な順序を構築します。 

1. すべてのカードを掛け算、割り算、足し算、引き算の 4 つのグループに分けます。 これが必要なのは、各タイプが根本的に異なる方法で値に影響を与え、それらを任意に混合すると構造が失われるためです。 
2. 乗算カードを数値の降順に並べ替えます。 大きな乗算器は、他の乗算器やすべての加算寄与を含む、その後に続くすべてのものを増幅するため、より早い段階で適用する必要があります。 
3. すべての乗算カードをシーケンスの先頭に置きます。 この時点で、付加的な歪みを導入する前にスケーリング効果を最大化しました。 
4. すべての加算カードと減算カードを中央のセグメントにまとめます。 この段階では、乗算の後にそれ以上の乗算は発生しないため、乗算器による後でのスケーリング方法に内部順序が影響することはありません。 
5. すべての部門カードを最後に追加します。 除算は累積結果全体を減らすため、除算を遅らせると、以前に取得したすべての値ができるだけ長く保存されます。 
6. 連結されたシーケンス (ソートされた乗算、加算と減算、除算) を出力します。 

重要な構造上の決定は、スケーリング操作を追加的な操作から分離することです。 乗数が最初に固定されると、すべての加算効果は線形寄与になり、除算が最後に固定されると、最終的な均一なスケーリングになります。 

### なぜ効果があるのか

 不変条件は、乗算器を先頭に配置した後は、そのブロックの後にそれ以上のスケーリングが導入されないため、残りの演算が前の乗算器と後の乗算器の間の相対的な増幅に影響を与えないことです。 同様に、分割が最後に配置されると、結果全体に均一の係数が適用され、中央のブロック内の順序とは相互作用しません。

これは、増幅は乗算器ブロックによってすでに完全に決定されているため、加算ブロック内の再配置によって増幅の程度が改善または悪化することはないことを意味します。 同じロジックが分割にも適用され、最終的なグローバル縮小のみが適用されます。 順序が重要になるのは乗算器だけです。乗算器では、降順の係数で並べ替えることで、成長の最大の伝播が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
mul = []
add = []
sub = []
div = []

for _ in range(n):
    op, val = input().split()
    val = int(val)
    if op == '*':
        mul.append((val, op, val))
    elif op == '/':
        div.append((val, op, val))
    elif op == '+':
        add.append((val, op, val))
    else:
        sub.append((val, op, val))

# sort multiplications descending
mul.sort(key=lambda x: x[0], reverse=True)

res = []

for _, op, val in mul:
    res.append((op, val))
for _, op, val in add:
    res.append((op, val))
for _, op, val in sub:
    res.append((op, val))
for _, op, val in div:
    res.append((op, val))

for op, val in res:
    print(op, val)
```この実装は理論的な分解を直接反映しています。 乗算グループは式全体の増幅構造を定義するため、強度によってソートされ、最初に配置されます。 加算と減算は、乗数が固定されると、相対的な順序によって最終的なスケーリング パターンが変更されないため、内部ソートなしで追加されます。 部門が最後に配置されるのは、内部の配置に関係なく最終結果を一律に削減するためです。 

よくある実装の落とし穴は、加算ブロック内の順序を考えすぎることです。 その段階の後にはそれ以上の乗算は存在しないため、2 つの加算または 2 つの減算を交換しても、最終結果は変わりません。 

## 実用的な例

 次のサンプル入力を考えてみましょう。 

| ステップ | 乗数 | 追加/サブブロック | 部門 |
 | --- | --- | --- | --- |
 | イニシャル | 2、4 | +1、+5、-1、-2 | /2、/3 |
 | 並べ替え後 | 4、2 | +1、+5、-1、-2 | /2、/3 |

 アルゴリズムを適用すると、出力は最初に乗算になり、次に加算演算、最後に除算になります。 ここで示されている重要な動作は次のとおりです。`* 4`前に置かれます`* 2`後続のすべての追加効果が最大限に増幅されるようにします。 

ここでカスタムケースを考えてみましょう。 

入力:```

```| ステップ | 乗数 | 追加/サブブロック | 部門 |

 ここでの結果は、`+10`両方の乗数から恩恵を受ける一方で、`-5`不必要に増幅されることなく安全に配置されます。 除算は最後に適用され、すべてのゲインが累積された後でのみ最終結果が縮小されます。 

これらの例は、アルゴリズムが、縮小操作が適用される前にすべての成長が最大化される一貫した増幅構造を強制することを示しています。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    n = int(input())
    mul, add, sub, div = [], [], [], []

    for _ in range(n):
        op, val = input().split()
        val = int(val)
        if op == '*':
            mul.append((val, op, val))
        elif op == '/':
            div.append((val, op, val))
        elif op == '+':
            add.append((val, op, val))
        else:
            sub.append((val, op, val))

    mul.sort(reverse=True)

    for _, op, val in mul:
        print(op, val)
    for _, op, val in add:
        print(op, val)
    for _, op, val in sub:
        print(op, val)
    for _, op, val in div:
        print(op, val)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    solve()
    return out.getvalue().strip()

# sample-like test
assert run("""8
+ 1
+ 5
- 1
- 2
* 2
* 4
/ 2
/ 3
""") == """* 4
* 2
+ 1
+ 5
- 1
- 2

/ 3"""

# minimum case
assert run("""1

""") == """+ 9"""

# only multipliers
assert run("""3
* 1
* 5
* 2
""") == """* 5
* 2
* 1"""

# divisions only
assert run("""2
/ 2
/ 3
""") == """/ 2
/ 3"""

 | --- | --- | --- |
 | サンプル | 並べ替えられたグループ | 完全な構造の正確さ |
 | シングルオペレーション | 同じ操作 | 最小限の境界処理 |

 ## 特殊なケース

 単一の操作入力が最も単純な境界です。 アルゴリズムはそれをカテゴリに入れて直接出力します。これにより、相対的な順序付けの決定が存在しないため、正確さが保たれます。 

すべての演算が乗算である場合、降順で並べ替えることにより、より大きな乗算器が最初に表示され、後続の乗算器に対するカスケード効果が最大化されます。 例えば、`* 5, * 2, * 1`早期増幅を正確に保証します。 

除算のみが存在する場合、すべての除算は乗算的に可換であるため、どのような順序付けも有効です。 このアルゴリズムは一貫した順序を出力し、正確さを維持します。 

乗算器を使用せずに加算と減算を混合する場合、グループ化ステップの後にスケーリングの違いが導入されないため、それらの順序は問題になりません。 アルゴリズムのグループ化により、それらが安定したブロック内に留まり、有効な最適な配置が生成されます。
