 ## 解決策
 ## 問題の理解

 迷宮は次のように見ることができます。$N \times N$各セルが一意の整数の温度を持つグリッド。 ミノタウロスは、希望に応じて、どのセルからでも隣接する 4 つのセルの 1 つに移動できます。 その移動ルールは決定的です。常に 4 つの隣接セルを調べて、厳密に最小の温度を持つセルに移動しますが、その隣接セルが現在のセルよりも低い場合に限ります。 隣接するセルが厳密に低温である場合、セルは現在の位置で永久に停止します。 

各クエリは開始セルを与え、タスクはこのルールを繰り返し適用した後にミノタウロスが最終的に停止するセルの温度を決定することです。 

制約の重要な意味は次のとおりです。$N \le 500$したがって、グリッドには最大 250,000 個のセルが含まれますが、クエリの数は最大 20,000 個になる可能性があります。 クエリごとの単純なシミュレーションでは、複数のセルを繰り返し通過する可能性があり、最悪の場合、パスがグリッドのほぼ全体を横断する可能性があります。 そのため、クエリごとのトラバーサル アプローチを個別に繰り返すと、潜在的に遅すぎる可能性があります。 

微妙だが重要な特性は、すべての温度が異なるということです。 これにより、次の動作を選択する際の曖昧さがなくなり、すべての動作が厳密に温度を下げることが保証されます。 

メモ化せずに各クエリを個別にシミュレートすると、単純な間違いが発生します。 たとえば、下降スパイラルのような形状のグリッドでは、単一のクエリが横断する可能性があります。$O(N^2)$細胞。 これを 20,000 クエリに対して繰り返すと、実行不可能になります。$O(N^2 Q)$最悪の場合。 

極小値がまれであると仮定したり、完全な伝播を行わずに貪欲なショートカットを試みたりすると、別の失敗ケースが発生します。 局所極小ではないが、長い下降チェーンにつながるセルを考えてみましょう。 貪欲な「半径 1 以内でより高い値に囲まれている場合は早期に停止する」ルールは、誤って終了します。 

正しいモデルは、すべてのセルが近傍グラフの意味で極小値に達するまで、厳密に減少するパスに沿って決定論的に流れるというものです。 

## アプローチ

 ブルート フォース アプローチでは、各クエリが個別に処理されます。 指定されたセルから開始して、その 4 つの隣接セルを繰り返し検査し、現在のセルより温度が低い場合は最も小さい温度を持つセルを選択し、そこに移動します。 それぞれの移動により厳密に温度が低下し、すべての値が異なるため、経路の長さは次のように制限されます。$N^2$最悪の場合。 

このアプローチはルールを直接シミュレートするため、正しいです。 ただし、同じ降下パスを繰り返し再計算します。 多くの開始点は最終的に同じシンク セルに流入します。これは、グリッドの大部分が繰り返し横断されることを意味します。 

重要な観察は、局所最小値でない場合、すべてのセルには決定的な「次のステップ」が 1 つだけあるということです。 これにより、各ノードがその最良の隣接ノードを指すセル上に関数グラフが生成されます。 すべてのエッジが高温から低温に変化するため、サイクルは不可能であり、すべての接続されたコンポーネントは極小値を根とするツリーを形成します。 したがって、各クエリは「このノードはどのルートに属しているか?」と尋ねます。 

これにより、問題は、ローカル降下ポインタによって定義された有向フォレスト内で接続されたコンポーネントを見つけることに変わります。 すべてのセルの最終宛先 (ルート) を計算すると、各クエリは次のようになります。$O(1)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース シミュレーション |$O(N^2 Q)$最悪の場合 |$O(1)$番外編 | 遅すぎる |
 | 事前計算シンク (DFS / DP / Union スタイルの伝播) |$O(N^2)$|$O(N^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 動きを厳密に冷たい隣接セルへの有向エッジとして扱うことで、すべてのセルが最終的にどこに到達するかを事前計算します。 

1. 各セルについて、4 つの隣接する位置をスキャンし、現在のセルよりも厳密に小さい位置の中で最も温度が低い位置を選択することにより、次のセルを決定します。 そのような近隣が存在しない場合は、それをシンクとしてマークします。 このステップでは、各セルの決定的な「次のポインター」を構築します。 
2. 各セルが最終シンク (最終的に到達する極小値) を格納するメモ化構造を作成します。 最初は、すべてのエントリは計算されません。 
3. グリッド内の各セルに対して、DFS スタイルの解決を実行します。最終的なシンクがすでにわかっている場合は、すぐにそれを返します。 それ以外の場合は、シンクに到達するまで次のポインターを再帰的にたどり、その結果を再帰パスに沿って伝播させます。 これにより、各降下チェーンがシンクへの直接ポインターに効果的に圧縮されます。 
4. 前処理後、クエリされたセルに保存されているシンク値を返すだけで、各クエリに応答します。 

単純な走査ではなくメモ化を明示的に使用する理由は、多くのパスが重なり合うためです。 セルの宛先が判明すると、セルに入るすべてのパスが同じ結果を継承します。 

### なぜ効果があるのか

 移動するたびに温度が低下し、すべての値が異なるため、各セルには厳密に減少するパスがあります。 これにより、再帰が一意の局所最小値で終了することが保証されます。 メモ化により、各セルのシンクが 1 回だけ計算されることが保証されます。 「次のポインタ」は決定的であるため、構造は極小値をルートとする有向ツリーのフォレストを形成し、アルゴリズムはそのフォレスト内の各ノードのルートを計算します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

N = int(input())
grid = [list(map(int, input().split())) for _ in range(N)]

# directions
dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

# next pointer: where each cell would move
nxt = [[None] * N for _ in range(N)]
for i in range(N):
    for j in range(N):
        best = (grid[i][j], i, j)
        for di, dj in dirs:
            ni, nj = i + di, j + dj
            if 0 <= ni < N and 0 <= nj < N:
                if grid[ni][nj] < best[0]:
                    best = (grid[ni][nj], ni, nj)
        if best[1] == i and best[2] == j:
            nxt[i][j] = (i, j)
        else:
            nxt[i][j] = (best[1], best[2])

# memoized sink
sink = [[None] * N for _ in range(N)]

def find(i, j):
    if sink[i][j] is not None:
        return sink[i][j]
    ni, nj = nxt[i][j]
    if (ni, nj) == (i, j):
        sink[i][j] = (i, j)
        return (i, j)
    sink[i][j] = find(ni, nj)
    return sink[i][j]

for i in range(N):
    for j in range(N):
        find(i, j)

Q = int(input())
out = []
for _ in range(Q):
    x, y = map(int, input().split())
    x -= 1
    y -= 1
    i, j = sink[x][y]
    out.append(str(grid[i][j]))

print("\n".join(out))
```グリッドはメモリに直接読み取られ、セルごとに、その 4 つの隣接セルをスキャンすることで最適な出力エッジを計算します。 これにより、決定論的な降下グラフが確立されます。 

の`find`関数はメモ化された再帰を実行します。 セルは、すでに計算されている場合はすぐに解決されるか、次のセルを再帰的に解決して結果を保存します。 これにより、前処理中にすべてのセルが 1 回アクセスされることが保証されます。 

クエリは、事前に計算されたシンク テーブルにインデックスを付け、保存されている温度を返すだけです。 入力解析で 1 を引くと、問題の 1 から始まるインデックスが Python の 0 から始まる配列と一致します。 

## 実用的な例

 ### トレース例 1

 単純な 2×2 グリッドを考えてみましょう。$$\begin{matrix}
4 & 3 \\
2 & 1
\end{matrix}$$クエリ: (1,1)、(1,2)、(2,1)、(2,2)

 | 開始 | 次のステップ | パス | シンク |
 | --- | --- | --- | --- |
 | (1,1)=4 | (1,2)=3 | 4→3→1 | (2,2) |
 | (1,2)=3 | (2,2)=1 | 3→1 | (2,2) |
 | (2,1)=2 | (2,2)=1 | 2→1 | (2,2) |
 | (2,2)=1 | 停止 | 1 | (2,2) |

 これは、すべてのパスが単一の極小値に崩壊し、メモ化によりすべての中間ノードの結果が再利用されることを示しています。

 ## 特殊なケース

 1×1 グリッドは最も単純なケースです。 隣接セルが存在しないため、アルゴリズムは唯一のセルを独自のシンクとしてマークします。 クエリは、再帰せずにそのセルの温度を即座に返します。 

パスに沿って厳密に減少するグリッドは、長いチェーンをテストします。 このアルゴリズムは、DFS メモ化中に各セルを 1 回解決するため、パスの長さが長くても再計算は行われません。 

多くのセルが同じ極小値に集中するケースは、キャッシュの重要性を示しています。 メモ化がなければ、各クエリは同じパスを繰り返したどることになりますが、ここではすべての中間ノードが計算されたシンクを再利用するため、繰り返されるクエリは一定時間のままになります。
