 ## 解決策
 ## 問題の理解

 Minecraft の世界の垂直断面図が与えられています。$h \times w$グリッド。 各セルは空、土ブロック、または金ブロックのいずれかです。 底部は溶岩であり、初期構成は固体のスタックを形成します。「浮遊」ブロックがないため、占有されているすべてのセルはその下までずっと支えられています。 

プレーヤーは、左端の関連領域の最も高い空でないセルのすぐ上から開始し、上部近くの空のスペースを自由に移動できます。 移動は主な困難ではありません。 実際のコストは、ブロックの採掘や土ブロックの配置といった世界の変更から発生します。 

マイニングは下方向または右方向に行うことができます。 マイニングによりブロックが削除され、重力によってその上にあるものが崩壊する可能性があります。 土を置くとブロックが挿入され、サポートに着地するまで落下します。 タスクは、ブロックの作成と破壊のアクションの数を最小限に抑えながら、正しい境界に到達しながらすべてのゴールド ブロックを削除することです。 

これを解釈するのに便利な方法は、空きスペースが存在するとトラバースは基本的に無料になるということです。 コストがかかるアクションは、ブロックの削除や新しいブロックの配置など、構造を永続的に変更するアクションだけです。 これは、問題は基本的に、移動計画に関するものではなく、すべてのゴールドにアクセスできるようにするにはどのブロックを削除する必要があるかということであることを意味します。 

金ブロックが柱の中に埋め込まれている場合、微妙な問題が発生します。 上からそれらに到達しようとすると、最初にそれらの上にあるすべてのブロックを削除する必要があります。 これは、コストが各列内の垂直方向の依存関係によって決定されることをすぐに示しています。 

グリッドのグローバルな再構築を強制するような病的な水平方向の障害物はありません。 一番上の行は全幅にわたって空であるため、プレイヤーは操作を費やすことなくすべての建造物の上を水平に移動できます。 これにより、「迷路」の側面の大部分が削除され、問題が列ごとの推論に縮小されます。 

単純な間違いは、金ブロックのみが重要であり、答えは単に金セルの数であると想定することです。 金が列の上部にない場合、これは失敗します。 

たとえば、単一の列について考えてみましょう。```
#
G
#
```金セルのみを採掘しようとしても、金セルに直接到達することはできません。 まず上部の汚れブロックを除去する必要があります。 正しいコストは 1 ではなく 2 です。 

別の失敗例は、列全体をクリアする必要があると仮定した場合です。 金が上部付近にしか現れない場合、これは過大評価されることになります。 

主な課題は、各柱をどのくらい下方まで掘削する必要があるかを正確に特定することです。 

## アプローチ

 ブルートフォース戦略では、プレイヤーの動きと考えられるすべての操作シーケンスをシミュレートします。 すべての採掘アクションにより重力でブロックが移動し、すべての配置が将来のアクセシビリティを変更する可能性があるため、状態にはグリッド構成全体が含まれる必要があります。 たとえ$h, w \le 100$、構成の数は爆発的に増加します。 各操作は複数の可能な次の状態に分岐します。プレイヤーはさまざまな列とさまざまなアクション順序を選択できるため、分岐要素は大きくなります。 これはすぐに実行不可能になります。 

重要な構造の簡素化は、水平方向の動きが事実上自由であり、上部の空きスペースを通じて常に可能であることです。 これは、上からのアクセスに関して各列を独立して処理できることを意味します。 柱の上に立ったら、問題は、その柱にあるすべての金を除去する前に、どれだけのブロックを除去しなければならないかということだけです。 

単一のカラム内では、重力により、上のブロックを削除しても、コストに影響を与える複雑な内部再配置が発生しないことが保証されます。 列は常に連続したスタックのままであるため、上から下への垂直スキャンの観点から考えることができます。 

ここで重要な観察は、列内の最下位の金ブロックを下回る必要が決してないということです。 その下の土や構造物は、他の場所や出口への残りの金へのアクセスを妨げないため、手つかずのままにすることができます。 したがって、各列は独立して貢献します。必要なのは、その列の一番上から最も低いゴールドまですべてをクリアすることだけです。 

これにより、問題は、列ごとに、その金セルの中で最も高い深さ (底に最も近い) を計算し、その点より上およびその点を含むすべてのブロックを合計することになります。

 ## アルゴリズムのチュートリアル

 1. 各列を上から下にスキャンし、ゴールド ブロックを含む最も低い (最も深い) 行インデックスを記録します。 

これは、そのポイントより下にあるものは列内のすべてのゴールドの完成とは無関係であるため、重要です。 
2. カラムに金が含まれていない場合、カラムを変更する必要がないため、コストはゼロになります。 
3. それ以外の場合は、列の上部からその最も低い金の位置まで何個のセルがあるかを計算します。 

その列内のすべての金にアクセスして採掘するには、そのようなすべてのセルをある時点で削除する必要があります。 
4. すべての列のこの値を合計して、最終的な答えを取得します。 

### なぜ効果があるのか

 重要な不変条件は、ゴールド ブロックを削除するには、その上にある同じ列内のすべてのブロックを最初に破壊する必要があり、別の列での操作ではこの要件を排除できないことです。 上部の移動は自由であるため、列間の依存関係はありません。 カラムを特定の深さまでクリアすると決めたら、そのプロセスは直線的であり、他のカラムとは独立しています。 したがって、各柱で最も深い金を選択することで、その柱に必要な最小限の掘削が定義され、これらの独立した最小値を組み合わせることで全体的な最適値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    h, w = map(int, input().split())
    grid = [input().strip() for _ in range(h)]

    ans = 0

    for j in range(w):
        lowest_gold = -1
        for i in range(h):
            if grid[i][j] == 'G':
                lowest_gold = i

        if lowest_gold == -1:
            continue

        # we must clear from top down to lowest_gold inclusive
        ans += lowest_gold + 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装はそのアイデアに直接従っており、列ごとに最も深い金のセルを識別します。 その列で必要な破壊操作の数は、上からその位置までの正確なセルの数です。 

問題の構造により、空の上部領域を無制限に横断することが保証されるため、動きのシミュレーションを完全に回避します。 唯一意味のある作業は、垂直方向の依存関係をカウントすることです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    h, w = map(int, sys.stdin.readline().split())
    grid = [sys.stdin.readline().strip() for _ in range(h)]

    ans = 0
    for j in range(w):
        lowest = -1
        for i in range(h):
            if grid[i][j] == 'G':
                lowest = i
        if lowest != -1:
            ans += lowest + 1

    return str(ans)

 ## 特殊なケース

 ゴールドのない列は、更新されないため、クリーンに処理されます。`lowest_gold`マーカー、寄与はゼロです。 これにより、無関係な土の構造物を誤って強制的に掘削することが回避されます。 

金が一番上にある列では、その金のセル自体を削除するには 1 回の破壊を実行する必要があるため、アルゴリズムは確実に 1 を返します。 スキャンでは正しく識別されます`lowest_gold = 0`、コスト1につながります。 

複数の金のブロックが存在する列は、最も深いものだけが重要である理由を裏付けています。 最下位の金まで掘削すると、上位の金ブロックはすべて自動的に除去パスに含まれるため、その深さを超えて追加の柱コストが発生することはありません。
