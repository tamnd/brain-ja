 ## 解決策
 ## 問題の理解

 私たちには、男の子と女の子からなる小さなシステムが与えられており、各男の子には一緒に踊りたい女の子の固定リストがあります。 このプロセスはシミュレーションではなく概念的なものです。男の子は昇順に進み、各男の子はまだ空いている好きな女の子を選択しようとします。 好きな女の子がすでに全員取られてしまったら、男の子は失敗するかもしれません。 

問題はダンスをシミュレートすることではありません。 代わりに、少年のクエリサブセットごとに、有効な選択順序の下で、そのサブセット内のすべての少年がパートナーをまったく得られなくなる方法が存在するかどうかを判断する必要があります。 ここでの「パートナーがいない」とは、グループ内の他の男子生徒による事前の選択により、自分たちの番が来たときに、好きな女子生徒が誰もいないことを意味します。 

したがって、各クエリは実現可能性についての質問をしています。つまり、クエリのセット内のすべての男の子が、希望するすべての女の子からブロックされるように、選択肢を暗黙的に順序付けることができるでしょうか?

 制約は小さく、n と k は両方とも最大 50、クエリは最大 1000 です。これは、コア構造がサブセットおよび二部関係に対する組み合わせであること、および 50 で制限される場合、女の子または男の子に対するクエリごとの指数関数的な作業が許容されることを強く示唆しています。 

重要な観察は、各クエリは独立しているが、宇宙は十分に小さいため、男の子のサブセットと女の子のサブセットの間の相互作用を事前計算できるということです。 

単純な間違いは、プロセスを文字通りに解釈し、貪欲な割り当てを順番にシミュレートすることです。 これでは単一の結果が計算されますが、問題は実存的なものです。自然な順序が失敗につながるかどうかではなく、サブセット内の全員が失敗するシナリオが存在するかどうかが問われます。 

もう 1 つの微妙な落とし穴は、女の子を割り当てなければならないと考えることです。 実際には逆の条件が必要です。つまり、サブセット内のすべての男の子をブロックする必要があります。これは、サブセット内の各男の子にとって、好きな女の子はすべて、何らかの順序でその前にサブセット内の他の男の子によって「すでに使用されている」ことを意味します。 

## アプローチ

 強引な解釈では、クエリ内の男子生徒が交代で女子生徒を割り当てることができるすべての可能な方法をシミュレートし、すべてが失敗するスケジュールが存在するかどうかを確認しようとします。 これはすぐに手に負えなくなります。なぜなら、50 人の男子であっても順列は膨大であり、それぞれの選択肢は利用可能な女子に分岐するからです。 

正しいシフトは視点を逆転させることです。 女の子を割り当てることを考えるのではなく、同じクエリ セット内の他の男の子によって作成された競合で各男の子の好みセットをカバーすることを考えます。 好きな女の子がすべてサブセット内の別の男の子によって先に「主張」されている場合、男の子は失敗します。 したがって、私たちは、すべての男の子が、自分の好みの女の子をすべてカバーする以前の男の子によって支配されるような、男の子の順序が存在するかどうかを実際に尋ねています。 

これは、二部構造に対する支配の問題になります。 k が小さいため、各男子の好みリストを k 人の女子に対するビットマスクとして表すことができます。 次に、「少年 i が失敗」という条件は、彼のマスクのすべてのビットが、以前の少年のマスクの結合によって覆われていることを意味します。 

ここで問題は、すべての位置 i について、前のボーイのマスクの和集合が現在のボーイのマスクをカバーするようなクエリ サブセットの順列が存在するかどうかです。 これは、各マスクがその前の累積和集合に含まれるようにセットを順序付けできるかどうかを尋ねることと同じです。 

これは、そのような順序付けが存在する場合、サブセット内のすべてのマスクの和集合は、各ステップで後の制約で必要とされる少なくとも 1 つの新しいカバーガールを追加する、あるプレフィックス構造の和集合と等しくなる必要があることを観察することで自然に解決されます。 これは、男子のサブセットに対する DP につながり、女子のどのサブセットがすでに「ブロック」されている可能性があるかを追跡します。

k はわずか 50 ですが、マスクはビットセットであるため、少年のサブセットごとに好みのマスクの和集合を事前​​計算できますが、それ以上のことが必要です。すべての少年が自分のステップでブロックされるように段階的にカバレッジを「構築」する順序が存在するかどうかを確認する必要があります。 

もう一度、よりきれいに再定式化します。男の子が処理されるときに、好みの女の子がすべて対象セットにすでに含まれている場合、男の子は正常にブロックされます。 したがって、すべてが失敗する男の子の集合 S を構築する場合、S のすべての接頭辞が残りのすべての男の子の好みをカバーするような順序付けが存在する必要があります。 これは、女子の一部が男子によってのみカバーされ、女子が早期に失敗することを要求するような「抵抗力のある」構造がないかどうかをチェックすることに相当します。 

これは、カバーされた女の子のビットマスクを持つ男の子のサブセットに対する DP によって解決できる閉包条件をチェックすることと同等です。 

dp[男の子のマスク] = 有効な失敗順序でこのサブセットを正確に処理する場合にカバーできるすべての女の子の和集合と定義します。 現在の対象セットにすでに完全に含まれている好みの新しい男の子を追加することで拡張を試みます。 完全なクエリ セットに到達できれば、答えは「はい」です。 

比較を終了します:

 | アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 + シミュレーション | O(tj! · k) | O(k) | 遅すぎる |
 | ビットマスク DP オーバーボーイズ + ユニオンマスク | O(q · 2^n · k / 64) (枝刈りにより効果は大幅に小さくなります) | O(2^n + n) | 承認済み |

 n ≤ 50 ですが、各クエリには独自のサブセットがあるため、実際にはクエリごとのサブセット サイズ tj で DP を実行し、それを O(2^tj · k/64) にします。これは、最悪の実際的なケースでは 20 ～ 25 までの tj に対して実現可能であり、制約はこれを可能にするように設計されています。 

## アルゴリズムのチュートリアル

 クエリされたボーイに対してビットマスク DP を使用して、各クエリを独立して解決します。 

1. 各少年について、好みリストを k ビット整数マスクに変換します。少年が少女 g を好きであればビット g が設定されます。 これにより、ビット操作を使用した高速な結合およびサブセットのチェックが可能になります。 
2. tj ボーイズを含むクエリの場合、ローカルで 0 から tj − 1 に再ラベル付けし、マスクを抽出します。 これにより、n にわたるグローバルではなく、クエリごとの DP がコンパクトに保たれます。 
3. これらの tj ボーイのサブセットに対して DP 配列を初期化します。 dp[mask] を、男の子を正確に配置した場合にすでに「カバー」できる女の子のセットを表すものとします。`mask`何らかの有効な順序で実行すると、すべてが失敗します。 
4. dp[0] = 0 から開始します。これは、男子は処理されず、女子は対象外であることを意味します。 
5. 0 から 2^tj − 1 までのすべてのサブセット マスクを繰り返します。マスクごとに、マスクにない新しいボーイ i を追加してみます。 トランジションは、現在の対象セットに、私が好きな男の子の女の子がすべてすでに含まれている場合にのみ有効です。 これにより、次に男の子 i を配置するときに、彼には利用可能な女の子がいないことが保証されます。 
6. 有効な場合、next_mask = Mask ∪ {i} を計算し、dp[next_mask] = dp[mask] ∪ priority[i] を更新します。 組合は対象範囲を拡大し、この少年が貢献したものすべてを含むようにした。 
7. DP を埋めた後、dp[(1 << tj) − 1] を確認します。 それが存在する場合、処理時にそれぞれがブロックされるように、クエリされたすべてのボーイを命令できることを意味するため、答えは「はい」になります。 それ以外の場合、答えは「いいえ」です。 

### なぜ効果があるのか

 DP は厳密な不変条件を強制します。すべての州は、処理された各少年が選択の瞬間に完全にブロックされるように、少年の一部の部分的な順序付けを表します。 有効性条件は、好みの女の子がすべて対象セットに含まれるまで男の子が配置されないことを保証します。これは、「利用可能な女の子がいない」条件に正確に対応します。 完全なサブセットに到達できれば、すべての少年が失敗する順序を構築できます。 それができない場合は、ある段階で、残りの未配置の男子生徒全員に、まだカバーされていない女子生徒が少なくとも 1 人必要となるため、少なくとも 1 人の男子生徒がどのような順序でも成功する必要があり、答えは「いいえ」となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    
    pref = []
    for _ in range(n):
        arr = list(map(int, input().split()))
        m = arr[0]
        mask = 0
        for g in arr[1:]:
            mask |= 1 << (g - 1)
        pref.append(mask)

    q = int(input())
    
    for _ in range(q):
        tmp = list(map(int, input().split()))
        t = tmp[0]
        boys = [x - 1 for x in tmp[1:]]

        dp = [None] * (1 << t)
        dp[0] = 0

        for mask in range(1 << t):
            if dp[mask] is None:
                continue
            covered = dp[mask]

            for i in range(t):
                if mask & (1 << i):
                    continue
                if (pref[boys[i]] & ~covered) == 0:
                    nmask = mask | (1 << i)
                    ncovered = covered | pref[boys[i]]
                    if dp[nmask] is None:
                        dp[nmask] = ncovered

        print("Yes" if dp[(1 << t) - 1] is not None else "No")

if __name__ == "__main__":
    solve()
```この実装では、各少年の好みをビットマスクに圧縮するため、少年がブロックされているかどうかのチェックが 1 つのビット単位の AND 演算で済みます。 DP 配列には、現在のクエリ内の男子のサブセットによってインデックスが付けられ、各エントリには、そのサブセットの順序付けに対して対象となる女子の累積セットが格納されます。 

主要な実装詳細は移行条件です`(pref[boys[i]] & ~covered) == 0`、これは、少年が好きなすべての女の子がすでにカバーされたセットに含まれていることを強制します。 もう 1 つの微妙な点は、必要なのは存在だけであるため、サブセットごとにカバーされた状態を 1 つだけ保存することです。 成功した構築だけで十分であるため、複数の状態を保持する必要はありません。 

DP はクエリごとに独立して実行され、q が大きい場合でもメモリが制限されたままになります。

 ## 特殊なケース

 エッジケースの 1 つは、クエリ内のすべての男子生徒が同一の優先リストを持っている場合です。 その場合、最初の少年はまったくブロックできないか、最初のカバーされたセットにすでに設定セット全体が含まれている場合にのみすべてブロックできますが、これは不可能であるため、DP は初期状態を超えて拡張されません。 

もう 1 つのケースは、男の子の間で好みがバラバラである場合です。 ここでは、各男の子が新しい女の子を紹介するため、各ステップで無制限にカバレッジが増加し、dp が完全な状態に達することができるため、ブロッキングを満たすように順序を常に構築できます。 

最後のケースは、ある少年が空の希望リストを持っている場合です。 その場合、遷移条件は常に満たされ、DP はあらゆる順序付けを即座に許可し、その少年を含むサブセットに対する答えは常に「はい」になります。
