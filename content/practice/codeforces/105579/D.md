 ## 解決策
 ## 問題の理解

 私たちに与えられた一行は、$n$1 から 1 までのインデックスが付けられた人物$n$。 このプロセスでは、インデックスがフィボナッチ数であるすべての位置を選択することによって、現在の行からグループを繰り返し形成します。 選択された人々はラインから削除され、残りの人々はクローズされ、同じルールが短縮されたラインに再度適用されます。 タスクは、誰もいなくなるまでそのようなラウンドが何回発生するかを決定することです。 

重要な点は、フィボナッチ ポジションが常に元のインデックスではなく現在のラインナップを基準にして定義されていることです。 削除するたびに、残りの人々のインデックスが 1 から再作成されるため、フィボナッチ セットは新しい長さで再計算されます。 

制約$n \le 10^{18}$個人に対するあらゆるシミュレーションを即座に除外します。 単一のパスはすでに$O(n)$。 実行可能なソリューションはどれも、明示的な要素ではなく、配列の進化するサイズに純粋に対応する必要があります。 

次のような場合には、明らかではない例外的なケースが発生します。$n$小さいです。 例えば、$n = 1$位置 1 がフィボナッチであるため、ただちに単一のグループが生成されます。 のために$n = 2$、ポジション 1 と 2 は両方ともフィボナッチであるため、プロセスも 1 つのステップで終了します。 位置 1 のみがフィボナッチであるという単純な仮定では、ここですでに誤った結果が得られます。 

もう 1 つの微妙な落とし穴は、削除される要素の数がラウンド全体で一定であると仮定していることです。 実際には、配列の縮小に伴ってフィボナッチ カットオフが移動すると、変化します。 

## アプローチ

 直接シミュレーションではサイズの配列が保持されます。$n$は、現在の長さに設定されたフィボナッチ インデックスを繰り返し構築し、それらの要素を削除して、反復回数をカウントします。 これは、説明したとおりのプロセスに正確に従うため、概念的には単純で正しいものです。 ただし、計算的には不可能です。 各ラウンドで要素の一部が削除されたとしても、最悪のケースは依然として次から始まります。$10^{18}$要素が存在するため、要素ごとの操作は不可能になります。 

重要な観察は、プロセスが現在の長さだけに依存するということです。$m$要素の実際の値やアイデンティティではありません。 各ラウンドで、削除される要素の数は、以下のフィボナッチ数の数と等しくなります。$m$。 この値を$F(m)$。 遷移は整数に対する純粋な反復になります。$$m \rightarrow m - F(m)$$フィボナッチ数は指数関数的に増加するため、カウントは$F(m)$だけです$O(\log m)$。 これは、各ラウンドで現在のサイズに対して対数の要素が削除されることを意味します。 これは最初はラウンド数が多いことを示唆しているかもしれませんが、フィボナッチ分布の構造により、カットオフ ポイントが次のように非線形に下方にシフトするため、実際には状態がすぐに崩壊します。$m$減少します。 

したがって、問題は繰り返し評価することに帰着します。$F(m)$そして更新$m$ゼロになるまで。

 ## アルゴリズムのチュートリアル

 プロセス全体を削減して、ラインナップの現在の長さのみを追跡します。 

1. 以下のすべてのフィボナッチ数を事前計算します。$10^{18}$、この境界は考えられるすべての中間状態をカバーするためです。 これにより、フィボナッチ数の数に定時アクセスできるようになります。$\le m$。 
2.初期化$m = n$そしてカウンター$ans = 0$。 変数$m$は各ラウンド後の残り人数を表します。 
3. 各ラウンドで、以下のフィボナッチ数がいくつあるかを判断します。$m$。 これは、事前に計算されたフィボナッチ リストをバイナリ検索することで実行できます。 
4. このカウントを次から減算します。$m$、正確にそれらのポジションが現在のラウンドで削除されるためです。 
5. ラウンドごとに 1 つのグループが形成されるため、答えに 1 を加えます。 
6. まで繰り返します。$m = 0$。 

正しさは、各ラウンドの後、残りのラインナップの構成がその規模を超えて無関係であるという事実にかかっています。 重要なのは、現在の範囲にフィボナッチ インデックスがいくつ存在するかだけです。これらのポジションは常に削除されるためです。 

### なぜ効果があるのか

 どの段階でも、システムは単一の整数で完全に記述されます。$m$。 選択ルールは、最大のフィボナッチ インデックスのセットにのみ依存します。$m$、これは特定の場合に固定されています$m$。 これらのポジションを削除すると、その構造が新しいサイズを超えて将来のフィボナッチのメンバーシップに影響を与えない、より小さなラインナップが生成されます。 これにより、整数に対して明確に定義された決定論的な繰り返しが作成され、プロセスが終了するまで常に一貫して進行することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Precompute Fibonacci numbers up to 1e18
F = [1, 2]
while True:
    nxt = F[-1] + F[-2]
    if nxt > 10**18:
        break
    F.append(nxt)

def count_fib_leq(x):
    # binary search
    lo, hi = 0, len(F)
    while lo < hi:
        mid = (lo + hi) // 2
        if F[mid] <= x:
            lo = mid + 1
        else:
            hi = mid
    return lo

def solve():
    n = int(input())
    m = n
    ans = 0

    while m > 0:
        cnt = count_fib_leq(m)
        m -= cnt
        ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```フィボナッチ リストは一度作成されると、すべてのクエリで再利用されます。 値は指数関数的に増加するため、リストのサイズは小さいままです (約 90 要素)。 二分探索では、現在の範囲内にフィボナッチ インデックスがいくつあるかを分離します。 

ループは整数の状態のみを更新します$m$、個人のシミュレーションを避けます。 答えは、この減少ステップが枯渇するまで何回適用されるかを数えます。 

よくある実装上の間違いは、更新のたびにシーケンスを再構築することによってフィボナッチ数が誤って再計算されることです。 このソリューションでは、事前計算を 1 回行うことで、それを完全に回避します。

 ## 特殊なケース

 のために$n = 1$、フィボナッチ セットには位置 1 のみが含まれます。アルゴリズムは次のように計算します。$F(1) = 1$、減少します$m$0になって1ラウンド戻ります。 トレースにより、即時終了が確認されます。 

のために$n = 2$, フィボナッチの位置は 1 と 2 なので、$F(2) = 2$。 アルゴリズムは両方を 1 ステップで削除し、再び 1 つのラウンドを生成します。 

のために$n = 3$, フィボナッチの位置は 1、2、3 であるため、配列全体がすぐに削除されます。 繰り返しはこれを自然に処理します。$F(3) = 3$、プロセスを 1 回の反復で折りたたみます。
