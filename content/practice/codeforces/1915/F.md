 ## 解決策
 ## 問題の理解

 私たちは一次元の数直線上に人々の集合を与えられています。 人にはそれぞれ出発点と目的地があり、出発点と終点はすべて異なります。 全員が同時に目的地に向かって 1 秒あたり 1 単位の一定速度で移動を開始します。 二人の人が同時に同じ位置に着くと、必ずお互いに挨拶します。 タスクは挨拶の総数を数える事です。 

入力により複数のテスト ケースが提供されます。 各テスト ケースでは、人数とそれぞれの開始位置と終了位置を指定します。 出力は、各テスト ケースの挨拶の数である必要があります。 

制約は非常に重要です。 各テスト ケースには最大 200,000 人が含まれる可能性があり、合計で 10,000 のテスト ケースが存在する可能性があります。`n`200,000 を超えないすべてのテスト ケースにわたって。 これは、次の二次方程式の解を意味します。`n`O(n²) は 4×10¹⁰ 演算に達する可能性があるため、遅すぎます。 したがって、アルゴリズムは線形に近いか、最悪でも O(n log n) でなければなりません。 

微妙な点は、一方または両方がすでに目的地に到着している場合でも、挨拶が行われる可能性があることです。 また、すべてのポジションは個別であるため、複数の人が同じポイントで開始または終了する場合に対処する必要はありません。 不注意なアプローチでは、動きを秒ごとにシミュレートしようとする可能性がありますが、大規模な場合は失敗します。`n`。 

小さなエッジケースの 1 つは、すべての人々が厳密に重ならない間隔で移動する場合です。 たとえば、次の場合`a_i = 1, 3, 5`そして`b_i = 2, 4, 6`、2 つの間隔が重なることはないため、挨拶はゼロです。 1 秒ごとにチェックする単純なスイープ ラインまたはシミュレーションのアプローチでは、間隔の重複を正しく処理しないと、誤ってカウントをオーバーカウントする可能性があります。 

## アプローチ

 ブルートフォースアプローチは、秒ごとに移動するすべての人物をシミュレートし、各位置での衝突をチェックすることです。 挨拶は人々が一致した場合にのみカウントされるため、これは原理的には正しいですが、あまりにも遅すぎます。 最大の場合`b_i - a_i`は 10⁹ であり、毎秒シミュレートすることは不可能であり、すべてのペアをチェックすることは不可能です。`n`各タイム ステップでの時間計算量は O(n² × max_ distance) になりますが、これは許容できません。 

重要な洞察は、ある時点で数直線上の間隔が交差する場合にのみ、2 人が出会うということです。 すべての人は同じ速度で移動するため、各人の動きを 1 つの数値、つまり出発時刻と目的地に対する数直線上の「有効間隔」に変換できます。 人々を開始位置と終了位置で分類すると、問題はペアの数を数えるということになります。`(i, j)`そのような`a_i < a_j`そして`b_i > b_j`。 これは、開始位置がソートされるときの終了位置のシーケンスにおける反転の数とまったく同じです。 

マージ ソートに似た分割統治アルゴリズムを使用してこの構造を利用し、テスト ケースごとに O(n log n) 時間で反転を効率的にカウントできます。 ソートにより、重複するパスに対応する反転のみがカウントされることが保証され、これは挨拶条件に正確に一致します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n² × 最大距離) | O(n) | 遅すぎる |
 | ソート + 反転回数 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての入力値を読み取り、テスト ケースを保存します。 
2. テスト ケースごとに、ペアのリストを作成します。`(a_i, b_i)`。 
3. リストを並べ替える`a_i`。 これにより、開始位置の昇順で人々を処理することが保証されます。 
4. のシーケンスを抽出します。`b_i`このソート順で。 次にペアを数える必要があります`(i, j)`と`i < j`そして`b_i > b_j`。 
5. 変更した結合並べ替えを`b_i`マージ中に反転をカウントするシーケンス。 それぞれの反転は挨拶に対応します。`a_i`開始は早くなりますが、終了は遅くなります。つまり、パスが重複します。 
6. 合計反転回数を挨拶回数として出力します。 

正確さを保証する不変条件は、次の基準で並べ替えることです。`a_i`パスが重複する場合に会う可能性のある人々のみを比較するようにします。 反転を数える`b_i`は、早い開始者が後の開始者の後に到達する重複する間隔の数を正確に捕捉し、挨拶を作成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_inversions(arr):
    def merge_sort(nums):
        if len(nums) <= 1:
            return nums, 0
        mid = len(nums) // 2
        left, inv_left = merge_sort(nums[:mid])
        right, inv_right = merge_sort(nums[mid:])
        merged = []
        i = j = 0
        inv_count = inv_left + inv_right
        while i < len(left) and j < len(right):
            if left[i] <= right[j]:
                merged.append(left[i])
                i += 1
            else:
                merged.append(right[j])
                j += 1
                inv_count += len(left) - i
        merged.extend(left[i:])
        merged.extend(right[j:])
        return merged, inv_count
    _, total_inv = merge_sort(arr)
    return total_inv

t = int(input())
for _ in range(t):
    n = int(input())
    people = [tuple(map(int, input().split())) for _ in range(n)]
    people.sort(key=lambda x: x[0])
    b_seq = [b for _, b in people]
    print(count_inversions(b_seq))
```の`merge_sort`右半分の要素が最初に配置されるたびに、左半分の残りの要素の数を合計することによって反転をカウントします。 開始位置によって人を並べ替えることで、有効な挨拶のみがカウントされるようになります。 抽出中`b_i`並べ替え後は、最初から最後まで正しいマッピングが保持されます。

```開始位置で並べ替えます:`[(1,4), (2,3)]`。 のシーケンス`b_i`は`[4,3]`。 反転を数える:`4 > 3`→反転1回→挨拶1回。

トレースでは、並べ替えによって開始順序が保持され、反転によって重複するパスの数が正確にカウントされることが確認されます。

 ## 特殊なケース

 一人の人の場合、`b_i`シーケンスの長さは 1 であるため、マージ ソートは 0 の反転 → 0 の挨拶を返し、正しく処理されます。 次のような隣接する間隔の場合`[1 2],[2 3]`、並べ替え後`b_i = [2,3]`、倒置法が存在しない→挨拶が0。 マージ ソートは O(n log n) であるため、最大 2×105 人までの大規模な入力が処理され、時間制限内に収まります。 相対的な順序のみが重要であるため、負の座標でも問題ありません。
