 ## 解決策
 ## 問題の理解

 私たちには、非常に小さな独立したタスクが次々と与えられます。 各タスクは正確に 3 つの数字で構成されており、特定の構造が約束されています。3 つの値のうち、2 つは同一で、1 つは異なります。 私たちの仕事は、外れ値、つまりそのトリプルの中で 1 回だけ現れる数字を特定することです。 

テスト ケースごとの入力サイズは小さいですが、この問題は、大量の計算ではなく、等価パターンに関する明確な推論をテストするように設計されています。 各テスト ケースは独立しているため、利用できる共有状態や累積構造はありません。 

制約は十分小さいため、テスト ソリューションごとに任意の定数時間で十分です。 最大 270 のテスト ケースとケースあたりの整数が 3 つだけであるため、複数の比較を行ったり、単純なカウント構造を使用したりするアプローチであっても、制限時間内であればわずかに高速です。 実際の制約圧力は存在しません。 代わりに、等価パターンの正確さと処理が重要です。 

唯一の微妙な点は、構造が常に有効であると仮定することによって生じます。 不注意な実装では、ロジックの安定性を考慮せずに一般化や並べ替えを試みる可能性がありますが、厳密に 1 つの値が一意であることが保証されているため、その不変式を直接信頼できます。 

エッジケースは、ほとんどが同じパターンの退化した形式です。 たとえば、次のような入力`5 5 6`、`6 5 5`、 または`5 6 5`すべてが同じ出力を必要としますが、一意の値が常に固定位置にあると仮定すると、単純な位置推論が失敗する可能性があります。 

## アプローチ

 ブルートフォース解釈は、辞書やサイズ 10 の配列などの頻度構造を使用して、トリプル内の各桁の出現をカウントすることです。 3 つの値のそれぞれのカウントをインクリメントし、頻度が 1 に等しい値をスキャンします。 これは正しく、テスト ケースごとに一定時間で実行されます。 270 を超えるテスト ケースがあり、総作業量はごくわずかです。 

ただし、入力の構造が高度に制約されているため、このアプローチでは不必要な作業が行われます。 実際には完全な頻度表は必要ありません。 3 つの位置のどれが他の位置と異なるかを区別するだけで済みます。 重要な観察は、異なる要素が 1 つだけ存在する 3 つの要素が等しいということは、その異なる要素が他の 2 つの要素のうちの少なくとも 1 つと異なっていなければならない一方、等しいペアは互いに一致する必要があることを意味します。 

これにより、直接論理抽出、つまりペアの比較が可能になります。 もし`a == b`、 それから`c`が答えです。 それ以外の場合は、`a == c`、 それから`b`が答えです。 さもないと、`a`ユニークなものでなければなりません。 これにより、補助記憶装置を使用しない一定数の比較に問題が軽減されます。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 これにより、処理する独立したトリプルの数が決まります。 
2. 各テスト ケースについて、3 桁の数字を読み取ります。`a`、`b`、 そして`c`。 
3. 比較する`a`そして`b`。 それらが等しい場合、繰り返されるペアはすでに識別されているため、3 番目の値`c`ユニークなものでなければなりません。 
4. もし`a`そして`b`等しくない、比較する`a`そして`c`。 これらが等しい場合、`b`はそのペアと一致しない唯一の値であるため、一意の数字です。 
5. 上記のどちらの条件も当てはまらない場合、`b`等しい必要があります`c`、 そして`a`は一意の数字です。 

### なぜ効果があるのか

 正確に 2 つの値が等しいという保証により、3 つの要素が 1 つのペアと 1 つのシングルトンに厳密に分割されます。 すべての比較により、ペアが直接識別されるか、候補が除外されます。 等価性は推移的であるため、一致するペアが見つかると、残りの要素はそれらと等しくなることができないため、一意の要素でなければなりません。 条件付きチェーンの正確性を保証する、入力制約と一致する代替構成はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, c = map(int, input().split())
    
    if a == b:
        print(c)
    elif a == c:
        print(b)
    else:
        print(a)
```この解決策は完全に直接比較に依存しています。 最初の条件は、最初の 2 つの値がすでに繰り返されるペアを形成しているかどうかをチェックし、答えを即座に特定します。 2 番目の条件は、最初の比較が失敗した場合にのみ到達するため、次のことがわかります。`a != b`。 その時点で確認すると、`a == c`かどうかを決定します`a`繰り返されるペアの一部です。 どちらの条件も満たされない場合、唯一残る一貫した構造は次のとおりです。`b == c`、作る`a`ユニークな要素。 

入力解析以外にループやデータ構造は必要ありません。 チェックの順序は、冗長な比較を回避し、常に正しいシングルトンを識別することを保証するため、重要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        a, b, c = map(int, input().split())
        if a == b:
            out.append(str(c))
        elif a == c:
            out.append(str(b))
        else:
            out.append(str(a))
    return "\n".join(out)

 ## 特殊なケース

 主なエッジ ケースは、等しいペアが入力順序で隣接していない場合です。 たとえば、`4 7 4`、ペア`(4, 4)`真ん中の位置を中心に分割されます。 アルゴリズムは最初にチェックすることでこれを処理します。`a == b`、失敗した場合はチェックします`a == c`成功し、正しく識別されます`b`ユニークな要素として。 

もう 1 つのケースは、等しいペアが最初の 2 つの位置に現れる場合です。たとえば、`9 9 1`。 ここで最初の条件`a == b`すぐにトリガーされ、アルゴリズムが出力します`c`それ以上のチェックは必要ありません。 これにより、早期終了動作が安全であり、必要な推論が省略されないことが確認されます。 

最後に、`7 7 5`、構造は同じですが、値が異なります。 同じ不変式が成り立ちます。つまり、等価ペアが 1 つだけ存在するため、最初に一致する比較で常にトリプルの正しいパーティションが特定され、一意の要素が一貫して返されることが保証されます。
