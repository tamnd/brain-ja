 ## 解決策
 ## 問題の理解

 私たちは道路で結ばれた都市の地図を与えられます。各道路の距離は一定です。 スラブは都市 1 から開始し、都市 n に到達したいと考えています。 面白いのは、彼は最初は自転車を所有していないのですが、どの都市にも、特定の速度低下要因を備えた自転車が 1 台だけあるということです。 自転車を使用して道路を移動するには、その道路の距離に使用する自転車の速度を乗じた時間がかかります。 スラブは訪れたどの都市でも自転車を購入することができ、自転車を販売している都市に着くと自由に自転車を乗り換えることができます。 目標は、都市 1 から開始して都市 n に到達するまでの最小合計時間を決定することです。 

グラフには最大 1000 の都市と 1000 の道路が含まれていますが、これは比較的小規模です。 これにより、複雑なアルゴリズムを考慮できるようになります。$O(n^2)$または$O(m \log n)$テスト ケース全体のすべての都市と道路の合計がそれぞれ 1000 に制限されているため、最短パスの場合。 

明らかではないエッジ ケースは、最適な経路として、遅い自転車を早めに購入して後で短い距離を利用すること、または複数の道路が異なる長さで同じ都市を接続している場合などのシナリオから生じます。 常にローカルで最速のバイクを選択するような単純なアプローチは失敗する可能性があります。 たとえば、都市 1 の自転車が非常に遅いのに、都市 2 の自転車が非常に速い場合、最初の一歩が遅くても、最初に都市 2 に到着する方が良い場合があります。 

## アプローチ

 強引なアプローチは、考えられるすべての経路に沿って自転車購入のすべてのシーケンスを列挙することです。 これには、指数関数的に多くのパスを調べる必要がありますが、これは実行不可能です。 たとえエッジに関して最短経路のみに制限したとしても、各都市で異なる自転車を選択することによる爆発的な増加に依然として直面します。 

重要な観察は、どの都市においても、これまでに見られた速度の低下要因を最小限に抑えた自転車を常に使用することが最適な戦略であるということです。 これは、エッジ長に大きな低速係数を掛けても決して有益ではないためです。 各都市で使用できる最適な自転車がわかれば、問題は修正された最短経路問題に帰着します。エッジの重みは現在の都市の最小速度に依存します。 

これを、各ノードが到達時に最速のバイクを維持するグラフとしてエンコードできます。 次に、ダイクストラのようなアルゴリズムを実行し、これまでに入手可能な最良の自転車で各都市に到着するまでの最短時間を追跡します。 全体の複雑さは次のとおりです。$O(m \log n)$制約を考慮すると、これはテスト ケースごとに効率的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * m) | O(n*m) | 遅すぎる |
 | 最適 (修正されたダイクストラ追跡ミニバイク) | O(m log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 各テスト ケースについて、都市の数を読み取ります。$n$、道路の数$m$、道路の説明、各都市の自転車の速度。 グラフの隣接リストを作成します。 
2. 距離配列を初期化する`dist`どこ`dist[i]`都市に到達するまでの最小の総移動時間を保存します$i$。 セット`dist[1] = 0`都市 1 からスタートするので、自転車なしでは移動できません。 
3. タプルを含む最小優先度キュー (ヒープ) を初期化します。`(time, city, best_slowness)`。 から始める`(0, 1, s[0])`、最初に購入できる唯一の自転車は都市1にあるためです。 
4. 優先キューが空でない間に、次の操作を行います。 

ａ． タプルをポップする`(curr_time, u, min_s)`到達都市を表す$u$現在の最小限の自転車速度で$min_s$。 

b. もし`curr_time`すでにより大きいです`dist[u]`、このノードをスキップします。 

c. アップデート`dist[u] = curr_time`。 

d. アップデート`min_s = min(min_s, s[u-1])`速ければ市の自転車が買えるからです。 

e. 隣人ごとに$v$長さのエッジで接続されています`w`、 押す`(curr_time + w * min_s, v, min_s)`優先キューに入れます。 
5.加工後、`dist[n]`都市に到達するまでの最小の総移動時間が含まれます$n$。 

**機能する理由:** 重要な不変条件は、各都市で計算される最小時間は、通過する経路に沿って入手可能な最高の速度の自転車を使用した場合に相当するということです。 ダイクストラのアルゴリズムは常に最小時間を最初に拡張するため、都市が確定した後は、都市にとってこれより良い時間は見つからず、正確性が保証されます。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        adj = [[] for _ in range(n)]
        for _ in range(m):
            u, v, w = map(int, input().split())
            adj[u-1].append((v-1, w))
            adj[v-1].append((u-1, w))
        s = list(map(int, input().split()))
        
        dist = [float('inf')] * n
        heap = [(0, 0, s[0])]  # (time, city, best_slowness)
        
        while heap:
            curr_time, u, min_s = heapq.heappop(heap)
            if dist[u] <= curr_time:
                continue
            dist[u] = curr_time
            min_s = min(min_s, s[u])
            for v, w in adj[u]:
                if dist[v] > curr_time + w * min_s:
                    heapq.heappush(heap, (curr_time + w * min_s, v, min_s))
        
        print(dist[n-1])

if __name__ == "__main__":
    solve()
```**説明:** 現在の最小合計時間を常に拡張するためにヒープを使用します。 の`min_s`変数を使用すると、各パスに沿って入手可能な最良のバイクを追跡できます。 小切手`if dist[u] <= curr_time`最悪の状況の都市を再び訪れることを避けられます。 更新中`min_s`ポップ後は、現在の都市での自転車の購入がその後の移動の際に考慮されるようになります。
