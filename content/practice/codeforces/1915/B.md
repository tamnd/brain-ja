 ## 解決策
 ## 問題の理解

 文字 A、B、C を含む 3 × 3 の固定グリッドが与えられ、1 つの欠落セルを除いてラテン方陣の構造を持ちます。 ここで有効なラテン方陣とは、各行に A、B、C の各文字が 1 つだけ含まれていることを意味し、同じことが各列にも当てはまります。 

各テスト ケースでは、ちょうど 1 つのセルが疑問符に置き換えられます。 他の 8 つのセルはすべて正しく入力されているため、ラテン方陣を完成させると欠落している文字が一意に決定されます。 タスクは、失われた文字を回復することだけです。 

入力サイズはテスト ケースの数の点で大きく、最大で$10^8$。 各テスト ケースは一定の作業、つまり 3 x 3 のグリッドです。 これは、あらゆるソリューションがテスト ケースごとに一定時間で実行され、バックトラッキングや順列上のシミュレーションなどの不必要なオーバーヘッドを回避する必要があることを直ちに意味します。 

グリッド サイズは固定されているため、ディメンションに関連する意味のあるアルゴリズムのエッジ ケースはありません。 唯一のエッジ条件は、欠落している文字の位置であり、グリッド内のどこにでも配置できます。 素朴な間違いは、疑問符の位置が固定されていると想定し、その位置のみを確認することです。 たとえば、常に中央の行または列にあると仮定すると、次のような入力では失敗します。```
?AB
BCA
CAB
```正しい答えは、ローカルな位置ではなく、行と列のグローバルな制約によって決まります。 

もう 1 つの微妙な落とし穴は、行のみまたは列のみをチェックして欠落した文字を再構築しようとすることです。 各行と列は同時に置換制約を満たす必要があるため、どちらか一方だけでは不十分です。 

## アプローチ

 この問題を考える強引な方法は、疑問符として考えられるすべての文字を試し、結果のグリッドがラテン方陣の制約を満たすかどうかを検証することです。 使用可能な文字は 3 つだけであるため、これはテスト ケースごとにすでに一定の作業ですが、より一般的な総当たり的な意味で説明できます。欠落しているセルを A、B、または C で埋め、すべての行と列をチェックします。 

6 行だけをチェックするため、完全な 3 x 3 グリッドの検証には一定の時間がかかります。 したがって、この強引なアプローチでも、制約に対しては事実上最適化されます。 

ただし、構造特性を利用することでさらに単純化できます。つまり、ラテン方陣の有効な行ごとに、A、B、C の 3 つの文字が 1 回だけ出現します。 したがって、連続する 2 つの文字がわかっていれば、3 番目の文字は一意に決まります。 列についても同様です。 

これは、すべての可能性をテストする必要がないことを意味します。 疑問符を含む行または列を直接見つけて、欠落している文字をその行 (または列) に存在しない文字として計算できます。 各行には全体として欠落要素が 1 つだけ含まれることが保証されているため、どちらのアプローチでも機能し、行ベースのリカバリが最も簡単です。 

完全なセット {A, B, C} を計算し、「?」を含む行から既知の 2 つの文字を削除し、残りの要素が答えになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (A、B、C を試して検証) | テストごとに O(1) | お(1) | 承認済み |
 | 最適 (行/列の差を設定) | テストごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースの 3 × 3 グリッドを読み取ります。 グリッドが小さいため、前処理なしで直接処理できます。 
2. 疑問符の位置を見つけます。 これを行うには、9 つ​​のセルすべてをスキャンします。 グリッドのサイズは一定であるため、このスキャンは一定時間になります。 
3. 疑問符が含まれる行を特定します。 この行には、既知の文字が 2 つと、欠落している位置が 1 つだけ含まれます。 
4. その行の文字を収集し、セット {A、B、C} と比較します。 
5. 欠落している文字は、その行に存在しない文字です。 
6. 復元した文字を出力します。 

重要な決定は、行と列の情報を結合するのではなく、疑問符を含む行を使用することです。 有効な補完では各行に 3 文字すべてが 1 回だけ含まれている必要があるため、欠損値を再構築するにはその行だけで十分です。 

### なぜ効果があるのか

 ラテン方陣の各行は、{A、B、C} の順列です。 1 つのエントリを削除すると、正確に 2 つの異なる文字が残ります。 残りの文字は、そのペアの補文字として一意に決定されます。 入力は、正確に 1 つの位置で有効なラテン方陣と異なることが保証されているため、欠損値を含む行は、この構造を完全な形式で保持します。 したがって、欠落している要素を特定すると、決定論的な集合の補数を計算することになり、曖昧さが生じません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

ALL = {"A", "B", "C"}

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        grid = [input().strip() for _ in range(3)]

        ans = None

        for r in range(3):
            if "?" in grid[r]:
                s = set(grid[r])
                s.discard("?")
                ans = (ALL - s).pop()
                break

        out.append(ans)

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```ソリューションは各行をスキャンして疑問符を含む行を見つけます。 見つかったら、その行をセットに変換し、プレースホルダーを削除し、{A, B, C} とのセットの差を介して欠落文字を計算します。 の`.pop()`セットの差分には常に 1 つの要素が含まれるため、安全です。 

この実装は、欠落文字が含まれる行が 1 行のみであるという事実に依存しているため、処理後すぐに中断できます。 これにより、不必要なチェックが回避されます。

 ## 特殊なケース

 特殊なケースの 1 つは、欠落している文字が行の最初の位置に現れる場合です。 例えば：```
?BC
CAB
ABC
```アルゴリズムは、最初の行に疑問符が含まれていると識別します。 既知の文字は B と C であるため、{A, B, C} とのセットの差は A になります。セットのメンバーシップは順序を完全に無視するため、欠落しているセルの位置は計算に影響しません。 

もう 1 つのケースは、欠落している文字が最後の列にある場合です。```
ABC
BCA
CA?
```2 行目には疑問符が含まれており、既知の文字は C と A です。補数は B です。アルゴリズムはインデックス演算に依存しないため、列の位置は影響しません。 

最後の構造上のエッジ ケースは、1 行を除くすべての行が完全な順列であることです。 このアルゴリズムは依然として不完全な行のみを検査するため、他の場所で完全に有効な行からあいまいさが生じることはありません。
