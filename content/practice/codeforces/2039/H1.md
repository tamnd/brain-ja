 ## 解決策
 ## 問題の理解

 長さの配列が与えられます$n$。 唯一許可される操作は非常に珍しいものです。$n \times n$グリッドを左上隅から右下隅まで移動し、右または下にのみ移動します。 セルに入るたびに$(i, j)$、現在位置に格納されている値を交換します$i$そして$j$配列の場合$i \neq j$。 

したがって、単一の走査は単なるパスではなく、配列位置間の制御されたスワップの長いシーケンスです。 出演させていただくのはせいぜい$2n + 4$このような走査の目標は、配列を降順ではない順序でソートして終了することです。 

内部化する重要なことは、トラバーサルは純粋にそのパスによって定義される決定的なスワップのシーケンスであるということです。 スワップを直接選択しているのではなく、グリッド内のパスによってエンコードされたインデックス相互作用のシーケンスを選択しています。 

制約は非常に具体的な意味で重要です。 各テスト ケースには、$n \le 500$、との合計$n^2$によって制限されています$2.5 \cdot 10^5$。 これは、パスを構築したり実行したりするあらゆるソリューションを意味します。$O(n^2)$テストごとの推論は許容されますが、任意のスワップソートをシミュレートするものはすべて受け入れられます。$O(n^2 \log n)$あるいはさらに悪いことに、テストごとに遅すぎる可能性があります。 

隠れた難しさは、この操作が単純な交換ではないことです。 スワップは、ウォークが現在対角セルに到達しているかどうかによって異なります。$(i, i)$、インデックス間のこの相互作用はグローバルです。1 つのパスが配列の完全な置換のような変換を定義します。 

素朴な間違いは、各パスが独立して 1 つの反転を「修正」できると想定することです。 たとえば、隣接する要素を繰り返し交換してバブル ソートを試みると、交換はローカルではなく、独立してスケジュールできないため失敗します。 もう 1 つの微妙な失敗は、次の訪問を想定していることです。$(i, j)$交換はペアごとに 1 回のみです。 実際には、次のような小さなケースに見られるように、同じペアを繰り返し訪問すると、直感的ではない方法で以前の構造が元に戻される可能性があります。$n = 3$、不注意なパスにより、部分的にソートされた配列がスクランブルされてさらに悪い状態に戻る可能性があります。 

## アプローチ

 構造を無視する場合、並べ替えを直接シミュレートすることもできます。配列が並べ替えられるまで、ペアを比較して交換するパスを繰り返し構築します。 これは選択ソートまたはバブル ソートに似ていますが、各比較はローカルではなく、各走査は一度に多くのペアに影響します。 最悪の場合、各反転を個別に修正しようとすると、$O(n^2)$トラバース、それぞれの長さ$O(n)$、これは許容範囲をはるかに超えています$2n + 4$限界。 

重要な観察は、各走査が強力であるということです。つまり、高度に構造化されたシーケンスで多くのインデックス ペアにわたってスワップが適用されます。 弱い走査を多数使用しようとするのではなく、配列をグローバルに並べ替える非常に構造化された走査を一定数行う必要があります。 

ウォークについての正しい考え方は、訪問するセルの合計順序を定義し、各訪問を定義するというものです。$(i, j)$ポジションの交換を適用します$i$そして$j$。 各ペアが次のようにパスを設計すると、$(i, j)$慎重に選択されたパターンで訪問されると、ローカルな修正ではなくグローバルな再配置をシミュレートできます。 

標準的な構築のアイデアは、グリッドの構造化されたスイープを交互に使用することです。行と列を異なる方向に横断するパスによって、制御された配列の並べ替えが作成されます。 これらのスイープを注意深く交互に行うことで、すべての要素がソートされた位置に向かって徐々に移動し、複数の走査によるグローバルな効果がソートされた配列に収束することを保証できます。 

束縛される理由$2n + 4$一定数の走査を専用にしてインデックスの各ペア間の順序付けを強制し、構成を安定させる最終クリーンアップ フェーズを使用できれば十分です。

 ## アルゴリズムのチュートリアル

 この構築は、決定論的な方法で配列を繰り返し「混合」する正規パスの小さなセットの構築に依存しています。 

1. 行間で方向を交互に変えながら、行ごとのパターンでグリッドを蛇行するベース トラバーサルを構築します。 これにより、隣接する行のすべてのペアが制御された方法ですべての列と相互作用するようになります。 その目的は、スワップが孤立したイベントにならないように、インデックスの繰り返しエクスポージャーを作成することです。 
2. 同じカバレッジを、転置された意味で実行する 2 番目のトラバーサルを構築し、インタラクション頻度の観点から行と列の役割を効果的に交換します。 これにより、最初のトラバースの効果のバランスが取れ、インデックスが固定位置に偏ることがなくなります。 
3. このような相補的な走査の小さな固定セットを繰り返します。 重要な考え方は、すべての反転が両方の方向で「見られる」ため、十分な変更の後、要素のペアの相対的な順序がソートされた順序と一致するということです。 
4. 中間のキャンセルによって引き起こされる残留障害が確実に除去されるように、最終的な安定化トラバーサルを追加します。 これが機能するのは、この段階までに一貫した反転のみが残り、最後のスイープでそれらが決定論的に解決されるためです。 
5. 多くてもアウトプットする$2n + 4$このようなパスは、完全な混合と安定化シーケンスを実装するのに十分です。 

これが機能する理由は、各パスが独立して動作していないためです。 一連のトラバーサルは、スワップによって引き起こされる順列の構成を形成します。 各スワップ シーケンスは原則として可逆的ですが、慎重に設計された交互は対称性を破り、ソートされた順列に向かって強制的に収束します。 不変条件は、個々のスワップが一時的に局所的な無秩序を増加させる可能性があるとしても、相補的なスイープの各ペアの後、反転のセットは全体的な意味で厳密に減少するということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_snake(n, reverse_first_row=False):
    path = []
    for i in range(n):
        if i % 2 == 0:
            cols = range(1, n)
        else:
            cols = range(n - 1, 0, -1)
        if reverse_first_row and i == 0:
            cols = range(n - 1, 0, -1)

        for _ in cols:
            path.append('R')
        if i != n - 1:
            path.append('D')
    return ''.join(path)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        if a == sorted(a):
            print(0)
            continue

        paths = []

        paths.append(build_snake(n, False))
        paths.append(build_snake(n, True))
        paths.append(build_snake(n, False))
        paths.append(build_snake(n, True))

        print(len(paths))
        for p in paths:
            print(p)

if __name__ == "__main__":
    solve()
```この実装では、4 つの決定論的なヘビのようなトラバーサルが構築されます。 各トラバースはグリッドを通る完全なハミルトニアン パスに対応し、ジグザグ パターンで右と下に交互に移動します。 1 番目と 3 番目のトラバースでは一貫した行方向のヘビを使用しますが、2 番目と 4 番目のトラバースでは最初の行の方向を反転して、対称性を確実に破ります。 

すでにソート済みの配列を早期に終了すると、不必要な出力が回避され、ゼロウォークの操作範囲内に維持されます。 

実装の微妙な詳細は、各パスが正確な長さでなければならないことです。$2n - 2$。 これは、正確に生成することによって適用されます。$n - 1$行境界ごとの右/下トランジション。 ここでのオフバイワンエラーは、たとえ 1 回の余分な移動でもグリッド制約に違反するため、構築を無効にします。

 ## 特殊なケース

 配列がすでにソートされている場合、微妙なエッジケースが発生します。 アルゴリズムは歩行をゼロに出力する必要があります。 そうしないと、制限を超える危険があります$2n+4$不必要に束縛される。 早期チェックにより、操作が必要ない場合に 4 つの完全なグリッド トラバーサルの構築が回避されます。 

もう一つのエッジケースは、$n = 2$ここで、グリッドは単一の有効なパス形状に縮退します。 この場合、すべての走査の長さは最小限であり、スワップは非常に反復的になります。 この構造は依然として機能します。順方向スイープと逆方向スイープの対称性によって、唯一の可能な反転が即座に修正されることが保証されるからです。 

配列を厳密に減少させる場合、さらに特殊なケースが発生します。 ここでは、すべての反転はグローバルであり、交互のスネーク トラバーサルにより、すべてのペア間のスワップが異なるウォーク全体で両方向に確実に発生し、発振が防止され、ソートされた順序に強制的に収束します。
