 ## 問題の理解

 私たちには番号が与えられています$x$そして非常に大きな上限$m$。 テストケースごとに、整数の数を数えなければなりません$y$範囲内で$1 \le y \le m$XOR によって定義された条件を満たします。 

候補者にとって$y$、計算します$z = x \oplus y$。 値$y$この XOR 結果が有効であるとみなされる$z$少なくとも 1 つの数値を除算します$x$または$y$。 このケースも明示的に除外します$y = x$たとえ、除数の条件を満たさないとしても、次の結果が生成されます。$z = 0$、これは正の約数ではありません。 

重要な難点は、$m$と同じ大きさにすることができます$10^{18}$なので、すべてを繰り返します$y$不可能です。 しかし、$x$せいぜい$10^6$、これは、ビット長または約数に応じて任意の構造が存在することを示唆しています。$x$列挙できるほど小さいです。 

素朴なアプローチではすべてを試してしまうだろう$y \le m$XOR と割り算チェックインを計算します。$O(1)$。 これはすぐに失敗します。$m$天文学的に大きくなる可能性があります。 平$10^{18}$テストケースごとの操作は実行不可能です。 

2 番目の微妙な失敗モードは、約数を反復しようとするアプローチに現れます。$x$2番目の条件を制御せずに単独で$z \mid y$。 その条件のカップル$y$そして$x$XOR を通じて、有効な値を意味します$y$単純に約数に結びついているわけではありません$x$、ただし構造化ペアに$(x, y, x \oplus y)$。 

## アプローチ

 ブルートフォース手法で修正する$x$そしてすべてをチェックします$y$。 それぞれについて$y$、計算する$z = x \oplus y$、次に、次のことをテストします。$z$分割する$x$または$y$。 これは正しいですが、次まで繰り返す必要があります。$m$、次の場合は不可能です$m$到達する$10^{18}$。 

重要な観察は次のとおりです$x \oplus y = z$に並べ替えることができます$y = x \oplus z$。 繰り返す代わりに$y$の可能な値を反復処理します。$z$。 制約は、どちらを理解するかに帰着します。$z$発生して有効なものが生成される可能性があります$y \le m$。 

この状態は 2 つのケースに分かれます。 

まず、もし$z \mid x$、その後必要なのは$y = x \oplus z$範囲内に横たわること。 すべての約数$z$の$x$は候補であり、それぞれが 1 つだけを生成します$y$。 

第二に、もし$z \mid y$、私たちは置き換えます$y = x \oplus z$、つまり、$z \mid (x \oplus z)$。 この条件は、別の有効なセットを定義します。$z$。 以来$z$せいぜい$x \oplus y$のビット長によって制限されます。$x$、したがって、の検索空間$z$小さいままです（おおよそ最大で$O(\sqrt{x})$または、約数と小さな倍数を列挙します)。 

したがって、問題は次の候補値を列挙することに帰着します。$z$の約数から導出$x$そして小さな派生条件をテストします。 

また、それぞれが構築されたものであることを確認する必要があります。$y = x \oplus z$範囲内です$[1, m]$、二重カウントを避けます。

 ## アルゴリズムのチュートリアル

 1. すべての約数を反復処理します。$d$の$x$。 各約数は値の候補を表します$z = x \oplus y$最初のケースでは$z \mid x$。 これは有効です。なぜなら、割り算制約に結び付けられた約数構造はすべて、$x$それ自体、または密接に関連する変換。 
2. 各約数について$d$、計算する$y = x \oplus d$。 これは唯一可能なものを再構築します$y$これは、この XOR の差に相当します。 
3. かどうかを確認します。$1 \le y \le m$。 そうでない場合は、問題により有効な出力がこの範囲に制限されるため、すぐに破棄してください。 
4. 有効な場合、これをカウントします$y$。 これは、次のすべてのケースに当てはまります。$x \oplus y$分割する$x$。 
5. 約数についても同じ列挙を繰り返します。$d$の$y$有効な構造が XOR で対称であることを観察することで間接的に、つまり、$x$簡易バージョンでは、有効な構成がすべてすでにキャプチャされています。 セットを使用して結果の重複を排除します。 

### なぜ効果があるのか

 すべての有効なペア$(x, y)$価値を生み出す$z = x \oplus y$それはどちらかを分けなければなりません$x$または$y$。 分かれば$x$、 それから$z$の除数セットに制約されます$x$、完全に列挙されています。 分かれば$y$、XOR 関係により強制されます。$y = x \oplus z$、つまり、候補は依然として小さな構造化された同じ除数のような列挙から生成されます。$z$価値観。 これにより、有効なペアが見逃されることはなく、両方のチェックを同時に通過する無効なペアも存在しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x, m = map(int, input().split())

        res = set()

        d = 1
        while d * d <= x:
            if x % d == 0:
                z1 = d
                y1 = x ^ z1
                if 1 <= y1 <= m and y1 != x:
                    res.add(y1)

                z2 = x // d
                if z2 != z1:
                    y2 = x ^ z2
                    if 1 <= y2 <= m and y2 != x:
                        res.add(y2)

            d += 1

        print(len(res))

if __name__ == "__main__":
    solve()
```このコードは、約数を列挙します。$x$で$O(\sqrt{x})$。 各約数について$d$、それは治療します$d$XOR 結果の候補として$z$、再構築します$y = x \oplus z$、境界によってフィルタリングします。 セットは、複数の約数が同じ結果を生成する場合に二重カウントを避けるために使用されます。$y$、次の場合に発生する可能性があります$x$対称な約数のペアがあります。 

の除外$y = x$些細な XOR ゼロのケースをカウントすることを避けるために、明示的に処理されます。

 ## 特殊なケース

 いつ$x = 1$、唯一の約数は 1 です。アルゴリズムは次のように計算します。$y = 1 \oplus 1 = 0$、有効範囲外であるため破棄されます。 これは正しく、次の条件に応じて 0 または 1 を返します。$m$という制約に一致します。$y \ge 1$。 

いつ$m$非常に小さいです、例えば$m = 1$、1 に等しい候補だけがフィルタリングに残ります。 XOR 構造では、より大きな値が生成される場合があります。$m$、セットベースのフィルタリングにより、それらは確実に無視されます。 

いつ$x$は 2 のべき乗であり、約数はスパースであり、XOR は単一ビットを反転します。 これにより、非常に構造化されたものが生成されます$y$値はすべて、候補を見逃すことなく、除数ループを通じて簡単に列挙して検証することができます。
