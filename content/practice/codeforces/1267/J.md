 ## 問題の理解

 それぞれがカテゴリに属する複数のアプリケーションセットが与えられています。 カテゴリに関して重要なのは、そのカテゴリに含まれるアプリの数だけであるため、入力は各カテゴリの頻度に圧縮できます。 

すべてのアプリを「画面」に配置する必要があります。 各画面には、ソリューション全体の固定サイズがあり、次のように示されます。$s$ただし、使用できるのは 2 種類の画面のみです: サイズが完全に満たされた画面$s$、ほぼいっぱいのサイズの画面$s-1$。 重要な制限は、画面には 1 つのカテゴリのアプリのみを含めることができますが、異なる画面では同じカテゴリを自由に再利用できることです。 

固定的な選択の場合、$s$、すべてのカテゴリと頻度$x$サイズが次のいずれかのグループに分割する必要があります。$s$または$s-1$。 このようなグループの数は、そのカテゴリによって提供された画面の数です。 目標は選択することです$s$画面の総数が最小限に抑えられるように、すべてのカテゴリに有効なパーティションを設定します。 

入力サイズはテスト ケース全体で合計 200 万要素に達するため、グループ化を明示的にシミュレートしようとしたり、カテゴリごとのパーティションを検索しようとしたソリューションは遅すぎます。 ソリューションでは、理想的には少数の候補値を使用して、各テスト ケースを本質的に周波数の線形処理に削減する必要があります。$s$。 

カテゴリーごとに欲張って考えると微妙な問題が見えてきます。 固定の場合は次のように仮定したくなります。$s$、各カテゴリは常に使用します$\lceil x/s \rceil$スクリーン。 これは、次の理由により常に有効であるとは限りません。$s-1$」 柔軟性があり、異なる数の画面を強制したり、画面数を選択したりすることもできます。$s$無効。 

簡単な例でその複雑さを示します。 仮定する$s = 3$カテゴリには$x = 1$。 単一の画面サイズ$s-1 = 2$すでに間違った方向に容量制約を超えています。どの分解でも画面のサイズは少なくとも 2 でなければならないため、1 を表すことはまったくできません。 すべてではありません$s$世界的に実現可能です。 

もう 1 つの微妙な失敗は、貪欲な天井が局所的に機能するものの、$s-1$スクリーン。 これにより、パーティション化だけでなく、選択されたかどうかの検証にも問題が生じます。$s$すべてのカテゴリにわたって構造的に一貫しています。 

## アプローチ

 強引なアイデアは、可能な値をすべて試してみることです。$s$2 から最大周波数まで、およびそれぞれについて$s$、考えられるすべての組み合わせを試して、カテゴリごとの最小画面数を計算します。$s$そして$s-1$グループ。 サイズのカテゴリーごとに$x$、これには、小さな整数の実現可能性問題を解決するか、可能な数のグループを反復処理する必要があります。 すべてのカテゴリとすべてを合計したもの$s$、これは簡単に到達します$O(n^2)$最悪の場合、限界をはるかに超えてしまいます。 

重要な構造的観察は、カテゴリは、共通の選択を介さない限り相互作用しないということです。$s$。 一度$s$が固定されると、各カテゴリは独立した 1 次元の充填問題になります。 唯一のグローバルな制約は、同じであるということです。$s$すべてのカテゴリで機能する必要があります。 

固定の場合$s$で表すと、$k(x)$サイズのカテゴリに使用される画面の数$x$、それからそれら$k(x)$画面は合計容量間隔を満たす必要があります$[k(x)(s-1), ks]$含まれています$x$。 可能な限り最小の画面数は当然ながら次の値に近づきます。$\lceil x/s \rceil$ただし、実現可能かどうかは、残った構造を次の方法で調整できるかどうかによって異なります。$s-1$ビン。 

これは重要な単純化につながります。$s$、最適解は常に使用します$k(x) = \lceil x/s \rceil$カテゴリーごとに。 この割り当てが下限に違反している場合$k(x)(s-1) \le x$任意のカテゴリの場合、その値は$s$完全に無効です。 増やしてもメリットがない$k(x)$なぜなら、そうすることで総画面数が増えるだけで、下限が厳しくなるからです。 

したがって、タスクは次の候補値を評価することになります。$s$、コンピューティング$\sum \lceil x_i / s \rceil$、実現可能性を確認します。 

残りの問題は、次の値はどれかということです。$s$テストする必要があります。 制約の構造は、意味のあるブレークポイントのみが周波数自体から導出された値で発生することを意味します。$\lceil x/s \rceil$変更されるのは次の場合のみです$s$の約数を交差します$x$。 これにより、各候補の周囲の少数の候補者に注意を限定することができます。$x$、すべての整数ではなく。

 ## アルゴリズムのチュートリアル

 1. 各カテゴリの頻度を数えます。 配列を正の整数のリストに置き換えます。$x_1, x_2, \dots, x_k$。 これにより、問題のサイズが軽減され、無関係な順序が削除されます。 
2. 候補値のセットを構築します。$s$。 周波数ごとに$x$、 含む$x$そして$x+1$潜在的な候補者として。 これらの点は、あらゆる構造的変化を捉えています。$\lceil x/s \rceil$振る舞います。 
3. 各候補者について$s$、暫定的な画面数を計算します。$$m(s) = \sum_i \left\lceil \frac{x_i}{s} \right\rceil.$$4. 同じように$s$、制約を使用してすべてのカテゴリの実現可能性を検証します。$$m_i(s) \cdot (s-1) \le x_i,$$どこ$m_i(s) = \lceil x_i / s \rceil$。 いずれかのカテゴリがこの不等式に違反する場合、これを破棄します$s$。 
5. 最低限のものを守る$m(s)$すべての実現可能な候補者の中に。 

重要な推論ステップは、$s$が修正されているため、カテゴリごとの画面数を増やしても、グローバル制約を満たすのに役立たない形で容量効率が低下するだけです。 したがって、天井割り当てはテストする価値のある唯一の候補です。 

### なぜ効果があるのか

 固定の場合$s$、各カテゴリはサイズのグループに分割する必要があります$s$または$s-1$。 任意の有効なパーティション$k$グループは満たさなければなりません$k(s-1) \le x \le ks$。 可能な限り最小の$k$上限を満たすことができるのは、$\lceil x/s \rceil$、およびそれ以上の$k$左側が増加するだけで、解は悪化します。 

したがって、実現可能性は、自然な貪欲な割り当てかどうかをチェックすることに帰着します。$k = \lceil x/s \rceil$下限も満たします。 そうであれば、それが最適です$s$; そうでない場合は、調整しても修正できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))

        freq = {}
        for x in arr:
            freq[x] = freq.get(x, 0) + 1

        xs = list(freq.values())

        candidates = set()
        for x in xs:
            candidates.add(x)
            candidates.add(x + 1)

        best = n

        for s in candidates:
            if s <= 1:
                continue

            ok = True
            total = 0

            for x in xs:
                k = (x + s - 1) // s
                if k * (s - 1) > x:
                    ok = False
                    break
                total += k

            if ok:
                best = min(best, total)

        print(best)

if __name__ == "__main__":
    solve()
```このソリューションでは、カウントのみが重要であるため、最初にカテゴリを頻度に圧縮します。 候補生成ステップでは、最適な遷移が各周波数値の近くで発生するという観察を使用します。 

の計算$k = \lceil x/s \rceil$これは、固定画面サイズに対する自然な貪欲な割り当てです。 実現可能性チェックでは、許可されている最小の画面でも、下限制約に違反することなくカテゴリをパックできることが強制されます。$s-1$スクリーン。 

最終的な最小値は有効なすべての値に適用されます$s$。
