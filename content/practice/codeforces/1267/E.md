 ## 解決策
 ## 問題の理解

 私たちには複数の候補者と複数の投票所による投票システムが与えられています。 各局は各候補者が何票獲得したかを報告する。 候補者の最終スコアは、有効なすべてのステーションの投票の合計です。 

野党を代表する特別な候補者、最後の候補者がいます。 与党は投票所全体を無効にすることが認められている。 いくつかのステーションが削除されると、残りの投票総数によって勝者が決まります。 野党候補の合計が他のすべての候補の合計を厳密に上回る場合、野党候補は当選したとみなされます。 

タスクは、削除後に野党候補が厳密に他の候補よりも先にならないように、できるだけ少ないステーションを削除することです。 同様に、少なくとも 1 つの他の候補が最終スコアが反対派以上になるように、破棄するステーションの数を最小限に抑えたいと考えています。 

制約は小さく、候補者は最大 100 名、投票所は 100 か所までです。 これにより、最大 2^100 のサブセットが存在する可能性があるため、ステーションのサブセットに対する指数関数的な検索が即座に排除されます。 ステーション数の 2 次または 3 次の解は許容されますが、完全なサブセットの列挙を伴うものは許容されません。 

貪欲に推論すると、微妙な点が現れます。野党の支持が最も大きい局を削除するのは自然なことのように思えますが、これは正しくありません。 野党を支援する局は別の候補者も強く支持している可能性があり、その局を排除すると、実際には野党よりもその候補者に大きなダメージを与える可能性がある。 決定では、絶対的な反対票ではなく、相対的な優位性を考慮する必要があります。 

もう 1 つの特殊なケースはネクタイに由来します。 条件は厳格です。反対は厳密に他のすべてより大きくてはなりません。 野党が誰かと結託すれば、すでに選挙は妨げられる。 多くの誤った貪欲な戦略は、誤って必要以上に強い条件を強制します。 

## アプローチ

 強引なアプローチでは、投票所のすべてのサブセットを試し、すべての候補者の合計を計算し、反対派が厳密に最大値でないかどうかを確認します。 これは、考えられるすべての結果を評価するため正しいですが、サブセットが 2^m あり、各評価のコストが O(nm) となり、天文学的な実行時間につながるため、実行不可能です。 

重要な洞察は、視点を逆転させることです。 削除するステーションを選択する代わりに、ステーションを維持するという観点から考えることができます。 局のサブセットを保持する場合、他の候補者に対する野党の票差は、野党の票と各競合他社の票の合計の差にのみ依存します。 

競合候補ｊを固定する。 各ステーション i で、値を定義します。 

di = a[i][n] - a[i][j]

 これは、候補者 j と比較して、ステーション i を維持することが野党にとってどれだけ役立つかを測定します。 di が大きくて正の場合、そのステーションを維持すると、j に対する相手のリードが強化されます。 di が負の場合、ステーションは実際に j がギャップを埋めるか反転するのを支援します。 

相手が j に勝てないことを保証するために、維持されたステーションの di の合計が非正になるようにします。 プラスになれば反対派がjよりも先行する。 

さて、問題は次のとおりです。各競合相手 j について、残りのステーションに対する di の合計が ≤ 0 になるように、削除するステーションの最小数を選択する必要があります。これは、対戦相手に過度の相対ゲインを与えないように保持するステーションを選択することと同じです。 

固定 j の場合、最適な戦略は貪欲です。ステーションを di で降順に並べ替えます。 最初はすべてのステーションを維持すると仮定し、次に最大の正の di を持つステーションを最初に徐々に削除します。これらのステーションが相手の優位性を最も高めるためです。 残りの合計が正でなくなったら停止します。 

すべての候補 j に対してこのプロセスを繰り返し、最良の結果を取得します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m・n・m) | O(m) | 遅すぎる |
 | 候補ごとの貪欲な削除 | O(n · m log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての非野党候補 j を反復処理し、野党が j に勝たないようにするために削除する必要があるステーションの数を計算します。 

1. di = a[i][n] - a[i][j] を合計することにより、すべてのステーションにおける候補者 j に対する野党の合計優位性を計算します。 これは、削除される前に野党がどれだけリードしているかを表します。 
2. 各ステーション i について、di を計算します。 駅を di の降順に並べ替えます。 大きな正の di を持つステーションは、反対派のマージンを最も大きくするため、最も有害です。 
3. すべてのステーションを含めて開始し、現在の di の合計を維持します。 この合計がすでに ≤ 0 である場合、この候補を削除する必要はありません。 
4. それ以外の場合は、最大の di を持つステーションを繰り返し削除します。 ステーションを削除した後、その di を現在の合計から減算します。 それぞれの除去は、そのステップで相手のアドバンテージを可能な限り減らします。 
5. 累計が 0 以下になったら停止します。削除されたステーションの数と削除されたステーションを記録します。 
6. 1 から n-1 までのすべての候補 j について繰り返し、すべての j にわたる最小の除去セットを取得します。 

出力は、最良の候補 j に対応する削除されたステーションのセットです。 

### なぜ効果があるのか

 固定候補者 j の場合、値 di は、j に対する野党のリードへの貢献度を測定します。 有効な解決策では、維持されたステーションの di の合計が正でないことを保証する必要があります。 ステーションを削除することは、合計からその di を減算することと同じです。 

最大の di を持つステーションを最初に削除することを選択するのが最適です。各削除により、アクションごとの合計が最大限に減少するためです。 より大きな di を残しながらより小さな di を除去する最適解は、厳密には劣っているか同等ですが、同じ数の除去で合計を減らすという点では決して良くありません。 

したがって、貪欲なプロセスは、合計を非プラスにするために必要な最小限の除去数を生成します。これは、野党が候補者 j に厳密に勝つのを防ぐことに正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(m)]

    best_k = m + 1
    best_remove = None

    for j in range(n - 1):
        diffs = []
        total = 0

        for i in range(m):
            d = a[i][n - 1] - a[i][j]
            diffs.append((d, i))
            total += d

        diffs.sort(reverse=True)

        removed = []
        cur = total

        for d, i in diffs:
            if cur <= 0:
                break
            cur -= d
            removed.append(i + 1)

        if len(removed) < best_k:
            best_k = len(removed)
            best_remove = removed

    print(best_k)
    print(*best_remove)

if __name__ == "__main__":
    solve()
```コードは最初にすべてのステーションの結果を読み取ります。 野党を除く各候補について、その候補に対するステーションごとのアドバンテージの差を構築します。 これらの違いを分類すると、その比較において反対派に最も強く有利なステーションを優先的に削除することができます。 

構築されるループ`removed`反対派が選択した候補者に対して厳密な優位性を持たなくなるまで、有害な局を段階的に排除するシミュレーションを行います。 初めての状態`cur <= 0`が満たされている場合、並べ替えられた順序により、その候補の削除数が最小限に抑えられています。 

最後に、全体的に最小のキャンセル数に対応する最適な候補を選択します。 

よくある落とし穴は、比較が厳密であるため、平等であればすでに十分であることを忘れることです。 もう 1 つの微妙な点は、正しい候補インデックス付けを使用することです。`n-1`は反対であり、差は常にそれに対して計算されます。 

## 実用的な例

 サンプル入力を使用します。 

入力：```
5 3
6 3 4 2 8
3 7 5 6 7
5 2 4 7 9
```候補 1 (インデックス 0) について計算します。 ステーションごとの違い di = 野党 - 候補者 1 は次のとおりです。 

| 駅 | ディ |
 | --- | --- |
 | 1 | 8 - 6 = 2 |
 | 2 | 7 - 3 = 4 |
 | 3 | 9 - 5 = 4 |

 合計は 10 です。最初に最大の di を削除します。ステーション 2 または 3 (両方とも 4)、次にステーション 3 または 2、次にステーション 1 です。2 つのステーションを削除した後、残りの合計は ≤ 0 になるため、答えは 2 になります。 

候補 2 (インデックス 1) の場合、次のようになります。 

| 駅 | ディ |
 | --- | --- |
 | 1 | 8 - 3 = 5 |
 | 2 | 7 - 7 = 0 |
 | 3 | 9 - 2 = 7 |

 まずステーション 3 と 1 を削除します。 こちらも除去は2枚で十分です。 

これにより、複数の候補が同じ最適な答えを導き出すことができ、アルゴリズムが最小値を正しく選択することが確認されます。

n、m ≤ 100 の場合、総作業量は少なく、サイズ 100 で最大 100 種類であり、制限内では簡単です。

 ## 特殊なケース

 重要なエッジケースの 1 つは、野党が最初はどの候補者もリードしていない場合です。 その状況では、すべての候補者の合計の差はすでに非プラスになっているか、何も削除せずにマイナスにすることができます。 アルゴリズムはこれを処理します。`cur`は合計から開始され、削除の前にチェックされるため、ゼロの削除はすぐに受け入れられます。 

もう 1 つのケースは、複数のステーションが同じ di 値を持つ場合です。 並べ替えでは、それらを等しいものの間で任意に配置しますが、アルゴリズムは利用可能な最大の di を最初に削除することのみに依存するため、同順位の間で順序付けを行うと、同じ数の削除が行われます。 正しさはソートの安定性には依存しません。 

最後の微妙なケースは、di = 0 のステーションを削除する場合です。これによって実行中の合計は変更されませんが、一部の構成では厳密な不等号を破る必要がある場合には選択される可能性があります。 アルゴリズムは、cur ≤ 0 になるとすぐにループが停止するため、不必要な削除を自然に回避します。そのため、ゼロインパクトの削除は、そのしきい値に正確に到達する一部でない限り決して実行されません。
