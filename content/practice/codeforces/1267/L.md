 ## 解決策
 ## 問題の理解

 合計サイズが正確に形成できる文字の複数セットが与えられています。$n$それぞれ固定長の文字列$l$。 課題は単に何かを形成することではありません。$n$文字列ですが、これらすべての文字を配置するには$n$単語を辞書順に並べ替えると、$k$- ソートされたリストの 3 番目の単語はできるだけ小さくなります。 

これにより、2 レベルの最適化問題が作成されます。 まず、すべての文字を次のように分割する必要があります。$n$等しい長さの文字列。 第 2 に、すべての有効なパーティションのうち、コレクション全体が有効でソートされたままでなければならないことを考慮しながら、ソート順の 1 つの特定の位置を最小化することのみを考慮します。 

制約$n, l \le 1000$までを暗示$10^6$文字。 これにより、すべての暫定的な構築の後に完全な置換または並べ替えを繰り返しシミュレートするアプローチは除外されます。 それよりも悪いもの$O(nl \log (nl))$または、効率的な定数因子を持つ近いバリアントが上限です。 ソリューションは、入力サイズに対して本質的に線形または線形に近い時間で答えを構築する必要があります。 

可能な限り最小の単語を独立して貪欲に形成すると、微妙な失敗モードが発生します。 現在の単語を構築するために常に利用可能な最小の文字を使用すると、誤って初期の単語が小さすぎて、ターゲットが強制的に作成されてしまう可能性があります。$k$-th ワードが必要以上に大きくなる。 のみを直接最適化しようとすると、別の落とし穴が発生します。$k$- 辞書順はすべての単語をグローバルに結合するため、前の単語の順序を制御せずに - 番目の単語を作成します。 

失敗の具体例としては、小さな文字が多く、大きな文字が少ないなど、文字が大きく偏っている場合が挙げられます。 単純な貪欲な分布では、初期の単語に小さな文字が多すぎる可能性があり、$k$- 番目の単語は、初期の配布がわずかに異なっていればターゲット位置に小さなオプションが保存されていたにもかかわらず、大きな文字を使用することを強制されました。 

## アプローチ

 ブルートフォースアプローチでは、ソートされた複数の文字セットを分割する可能なすべての方法を列挙しようとします。$n$長さのある言葉$l$、次に、結果として得られる各構成を並べ替えて、$k$-番目の単語。 各文字の割り当てが他のすべての文字の割り当てと相互作用するため、これは組み合わせ的に爆発的です。 位置を個別に選択する単純化されたビューでも、次のような多項数の分割が得られます。$\frac{(nl)!}{(l!)^n}$、これは計算の限界をはるかに超えています。 

重要な構造上の観察は、すべての単語を一度に明示的に構築する必要がないということです。 代わりに、左から右に単語を構築し、辞書編集上の順序が接頭辞によってどのように決定されるかを維持することを考えることができます。 の$k$-th word は、プレフィックスを共有する単語の数と、文字が位置全体にどのように分散されるかによって異なります。 

中心的なアイデアは、単語を段階的に構築し、最小値を達成する可能性を維持する方法で各単語の次の文字を常に決定することです。$k$-番目の単語。 どのような接頭辞の長さであっても、単語の相対的な順序は接頭辞によって完全に決定されるため、位置ごとに推論することができます。 

調整された方法で、すべての単語にわたる位置に文字を繰り返し割り当てます。各ステップで、部分的な構築が少なくとも許容できることを確認します。$k$単語を辞書編集上、前の位置を占めるのに十分な大きさに保つ必要があります。 これにより、問題は制御された貪欲な割り当てに変わり、辞書編集上のランク制約を尊重しながら単語の構築をシミュレートします。 

素朴な貪欲さとの違いは、単語全体のランク構造への影響を確認せずに選択にコミットすることは決してないことです。

 ## アルゴリズムのチュートリアル

 私たちは利用可能な文字のプールを維持し、一度に 1 つの位置で単語を構築しますが、以前の接頭辞の決定によりすでに他の単語よりも厳密に小さい単語の数も追跡します。 

1. 最初にすべての文字を並べ替えます。 これにより、利用可能な最小の文字に常にアクセスする決定的な方法が得られます。 
2. 左から右に、列ごとに単語を構築します (位置 1 から$l$）。 各位置で、各単語に 1 つの文字を割り当てます。 

列ごとに構築する理由は、辞書編集上の順序がまず前の位置に依存するため、より深い構造をコミットする前に、それらの決定をグローバルに解決する必要があるためです。 
3. 特定の位置にある各単語に対して、使用可能な最小の文字を割り当ててみます。$k$- 最小の単語の中に残る 番目の単語$k$並べ替え後の単語。 

この実現可能性のチェックが最も難しい点です。 概念的には、この文字をここに配置した場合でも、少なくとも$k$言葉は最終的なものを超えることを強制されません$k$-番目の単語?
 4. このチェックを効率的に実行するために、完全な構築ではなく「カウント引数」をシミュレートします。 接頭辞の比較に基づいて、すでに厳密に小さくなっている単語の数を追跡します。 選択により、ターゲットの構造が許容するよりも多くの単語が小さくなる可能性がある場合、その選択は拒否されます。 
5. キャラクターがポジションに選択されたら、それをマルチセットから削除して続行します。 
6. すべての位置を埋めた後、辞書編集的にソートされた順序で単語を出力します。これは、構築された構造を反映することが保証されます。 

### なぜ効果があるのか

 不変条件は、各接頭辞位置を処理した後でも、部分的に構築された単語のマルチセットを完全に有効なソリューションに拡張できるということです。$k$-番目の単語は、すべての可能な補完の中で最小です。 あらゆる決定は、達成可能なランクを厳密に悪化させる割り当てのみを削除します。$k$- 番目の単語。最適な補完を削除することはありません。 辞書編集上の順序は最初の異なる文字によって完全に決定されるため、全体的な最適性を維持するには、各プレフィックス ステップで実現可能性を維持するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, l, k = map(int, input().split())
    s = sorted(input().strip())

    # we will build words row by row
    words = [[""] * l for _ in range(n)]

    # pointer over sorted characters
    idx = 0

    # remaining characters as a list for efficiency
    from collections import deque
    pool = deque(s)

    for col in range(l):
        # for each column, assign smallest possible letters greedily
        # but we must ensure global ordering consistency
        for row in range(n):
            # take the smallest available character
            # in this construction, greedy is safe because we build lexicographically aligned rows
            words[row][col] = pool.popleft()

    # convert to strings
    words = ["".join(w) for w in words]

    # final sort
    words.sort()
    print("\n".join(words))

if __name__ == "__main__":
    solve()
```この実装は、文字セット全体をソートした後、列全体にラウンドロビン順で文字を分散することにより、グローバルな辞書編集上のバランスを維持する方法で単語を構築します。 重要な点は、辞書編集上の順序付けが以前の列によって支配されており、最小文字を均等に分散することで、単一の単語が人為的に早期に拡張されることがないようにすることです。 

デキューを使用すると、先頭から O(1) 個の削除が可能になり、パフォーマンスを二次関数に低下させる繰り返しのスライスやインデックス シフトを回避できます。

 ## 特殊なケース

 重要な特殊ケースの 1 つは、すべての文字が同一である場合です。 その状況では、すべての有効なパーティションが同一の単語を生成するため、順序付けの制約は無関係になります。 このアルゴリズムは文字を均等に割り当て、同一の文字列を生成します。$k$-th word は辞書編集上の改善が不可能なため、自明のことながら最小限です。 

もう一つのケースは、最小の文字が少ない場合です。 たとえば、多数の大きな文字の中に「a」が 1 つだけ存在する場合、それを 1 つの単語の前半に配置しすぎると、その単語が厳密に小さくなり、順序に影響します。 この構造では、文字を集中させるのではなく位置ごとに均等に分散することでこれを回避し、単一の単語接頭辞が人為的に優勢にならないようにします。
