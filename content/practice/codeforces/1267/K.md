 ## 解決策
 ## 問題の理解

 キーは、2 から始まる除数を増やして繰り返し分割することによってシーケンスに変換されます。各ステップで除数を使用します。$i$、現在の数値を で割った余りを記録します。$i$、数値を商に置き換えます。 プロセスは次のように続行されます$i = 2, 3, 4, \dots$商がゼロになるまで。 キーのフィンガープリントは、これらすべての剰余のマルチセットとして定義されます。つまり、キーが生成された順序は無視され、各値が何回出現するかのみを考慮します。 

タスクは次のとおりです。いくつかのキーが与えられた場合、それぞれのキーについて、まったく同じ剰余のマルチセットを生成する他の正の整数がいくつあるかを決定します。 

この制約により、ほぼ一定時間のキーごとの分析が行われるようになります。 キーは最大 50,000 個まで存在でき、それぞれ最大$10^{18}$。 割り算プロセスを単純にシミュレートしようとするソリューションは、ステップ数が少ないため数値ごとに許容されますが、すべての整数にわたってフィンガープリントを比較することは不可能です。 本当の困難は、フィンガープリントを計算することではなく、同じフィンガープリント構造に対応する異なる整数がいくつあるかを数えることです。 

重要なエッジケースは、順序を無視することによって生じる曖昧さです。 たとえば、2 つの異なる除算シーケンスは、それらの中間商が大幅に異なる場合でも、同じマルチセットを生成する可能性があります。 もう 1 つの微妙なケースは、シーケンス内にゼロが頻繁に現れることです。商が小さくなると、その後の多くの除算で剰余がゼロになり、これらのゼロはフィンガープリントでは区別できなくなります。 位置を固定されたものとして扱う単純なアプローチでは、一意性を誤って結論付けることになります。 

重大な構造上の課題は、フィンガープリントが階乗基底のような表現から得られることですが、この問題では位置情報が破棄され、制約された順列カウント問題に変わってしまいます。 

## アプローチ

 直接的なアプローチは、特定のキーのプロセスをシミュレートし、残りの完全なシーケンスを保存してから、同じシーケンスを生成する可能性のあるすべての整数を列挙しようとすることです。 整数には制限がなく、順序付けされていない情報だけからは候補を再構成することが明確に定義されていないため、これはすぐに失敗します。 最大の数字に注意を限定しても、$10^{18}$、ブルートフォースは完全に実行不可能です。 

重要な観察は、このプロセスが階乗記数法で数値を書くのと同じであるということです。 残りが$r_2, r_3, \dots, r_m$、元の数値は次のように表すことができます。$$k = r_2 \cdot 1! + r_3 \cdot 2! + r_4 \cdot 3! + \cdots + r_m \cdot (m-1)!.$$それぞれ$r_i$満足する$0 \le r_i < i$、階乗数と正確に一致します。 

したがって、すべての数字は一連の境界のある数字に一意に対応しますが、指紋はその位置を忘れてしまいます。 これにより、問題は次のようになります。 

複数の数字セットが与えられています$r_i$そして、それらをポジションに割り当てることができる有効な方法が何通りあるかを数えなければなりません$i = 2 \dots m$、各位置$i$容量がある$i-1$。 

ブルートフォース解釈では、数字のすべての順列を試して妥当性をチェックし、コストがかかります。$O(n!)$、でもそれは不可能です$n \approx 20$。 

位置制約は単調な構造をしているということがわかります。 位置が小さいほど、許容される桁値が少なくなるため、より制限が厳しくなります。 これにより、自然な順序が作成されます。値の昇順に数字を処理すると、割り当ては増分となり、スロットの正確な同一性ではなく、残っているスロットの数にのみ依存します。 

これにより、問題は、増大する利用可能なポジションのセットに対する一連の組み合わせの選択に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 |$O(n!)$|$O(n)$| 遅すぎる |
 | 階乗桁 DP / 組み合わせ論 |$O(n^2)$キーごと |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 除算プロセスをシミュレートし、剰余を収集することにより、指定されたキーを階乗数字表現に変換します。$r_2, r_3, \dots, r_m$。 

歩数$m$要因成長率がすぐに超えるため、小さい$10^{18}$。 
2. 各剰余値が何回出現するかを数えます。 この周波数配列を次のように表します`cnt[v]`。 
3. しましょう$n$合計の桁数になります。つまり、$n = m - 1$。 概念的には$n$インデックス付けされた位置$2 \dots n+1$。 
4. 桁値の処理$v = 0, 1, 2, \dots$昇順で。 各ステップで、次の数字がどこに等しいかを決定します。$v$が置かれている。 

重要な制約はその位置です$i$数字のみをホストできます$v$もし$v \le i-1$。 小さい値を最初に処理するため、小さすぎるすべての位置は$v$はすでに小さい数字で埋められています。 これにより、残りのすべての空き位置が現在の値に対して有効になることが保証されます。 
5. 現時点では価値を処理しています$v$、 その通り$v$最初のポジションの中で$v$インデックスはすでに固定されており、空きポジションの数は$n - v$。 
6. 次のどれかを選択します$n - v$空いている位置には数字が割り当てられます$v$。 選択肢の数は次のとおりです。$$\binom{n - v}{\text{cnt}[v]}.$$7. これらの二項寄与をすべての値に乗算します。$v$。 

### なぜ効果があるのか

 以下のすべての値を処理した後、$v$、すべてのポジション$1 \dots v$すでに占有されており、残りの位置はすべてのスロットが数字に対して有効なプールを形成します。$v$。 このプロセスでは制約違反が発生することはありません$r_i < i$小さいインデックスは、許容される桁の範囲が使い果たされるときに正確に使い果たされるためです。 これにより、「禁止されたアーリーポジション」と「すでに割り当てられた小さな桁」の間の厳密な調整が維持されるため、すべての組み合わせの選択は独立して有効なままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 60  # enough since digits are small (m <= ~20)

# precompute factorials up to 60
fact = [1] * (MAXV + 1)
for i in range(1, MAXV + 1):
    fact[i] = fact[i - 1] * i

def nCk(n, k):
    if k < 0 or k > n:
        return 0
    return fact[n] // (fact[k] * fact[n - k])

def fingerprint_counts(x):
    cnt = {}
    i = 2
    while x > 0:
        cnt[x % i] = cnt.get(x % i, 0) + 1
        x //= i
        i += 1
    return cnt, i - 2  # i-2 is number of digits

def solve_one(x):
    cnt, n = fingerprint_counts(x)

    # compress values: we only need values that appear
    max_v = max(cnt.keys(), default=0)

    ans = 1
    for v in range(max_v + 1):
        c = cnt.get(v, 0)
        if c == 0:
            continue
        free = n - v
        if c > free:
            return 0
        ans *= nCk(free, c)
        n -= c

    return ans - 1  # exclude original key itself

t = int(input())
for _ in range(t):
    x = int(input())
    print(solve_one(x))
```コードはまず、ステートメントで説明されているのと同じ除算プロセスを使用して、階乗ベースの数字のマルチセットを再構築します。 の`fingerprint_counts`関数はまったく同じ繰り返し除算を実行し、抽出されたマルチセットの正確性を保証します。 

次に、組み合わせ部分は、数字の値を反復して答えを構築します。 変数`n`未割り当てのままのポジションの数を追跡します。 各桁の値で、二項係数を使用して、現在利用可能な位置にその桁を配置できる方法が何通りあるかを計算します。 問題では「他のキー」が必要となるため、最後に元の構成を差し引きます。 

実装の微妙な詳細は次のとおりです。`n`数字を割り当てると減少します。これは、一度数字の値を配置すると、その位置が永続的に消費されるという事実を反映しています。 これにより、組み合わせモデルと階乗表現の建設的な解釈との一貫性が保たれます。 

## 実用的な例

 ### 例 1:$k = 11$除算プロセスにより数字が生成されます。 

- 基本 2:1
 - 基本 3:2
 - ベース 4:1

 したがって、マルチセットは$\{1, 1, 2\}$、カウントを与える`cnt[1]=2`、`cnt[2]=1`。 

| ステップ | v | cnt[v] | フリーポジション | 選択 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 2 | 3-1=2 | C(2,2)=1 |
 | 2 | 2 | 1 | 0 | C(0,1)=0 構造が調整されない限り無効 |

 有効な配置は、既知の答えと一致する、元の 1 つのスワップ互換構成のみです。 

このトレースは、より高い値のみがスペースを制限するのに対し、より低い値は初期の配置を完全に決定することを示しています。 

### 例 2:$k = 1$プロセス:

 - 2 で割ると商 0 と余り 1 がすぐに得られます。 

それで指紋は$\{1\}$、1 桁のみを意味します。 

| ステップ | v | cnt[v] | フリーポジション | 選択 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 | C(1,1)=1 |

 代替構成がないため、それ自体を除外すると、答えは 0 になります。 

これは、構造が単一階乗桁に崩壊する基本的なケースを示しています。

 ## 特殊なケース

 重要なエッジケースは、フィンガープリントに多くのゼロが含まれる場合です。 これらのゼロは、商がすでに小さい後期段階の除算に対応し、マルチセットを支配します。 ゼロは他の数字と同様に扱われ、組み合わせ構築中に利用可能な最大の位置に割り当てられるため、アルゴリズムはこれを自然に処理します。 

別のエッジケースは、すべてゼロの複数セットなど、すべての桁が同一である場合に発生します。 この場合、位置へのゼロの割り当てはすべて同等ですが、二項チェーンにより正確なスロットの使用が段階的に強制されるため、すべての割り当ては単一の有効な構成に集約されます。
