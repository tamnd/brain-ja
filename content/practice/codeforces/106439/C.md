 ## 問題の理解

 ゲームは整数の配列でプレイされます。 有効な移動により、等しい値の 1 つのブロック全体が削除されます。 ブロックとは、すべての要素が同じである最大の連続グループを意味するため、プレイヤーはブロックの一部を削除することはできません。 アリスが最初に動きますが、ゲームが始まる前に、好きなように配列を並べ替えることができます。 タスクは、アリスがボブに対して勝つ戦略を持つように値を調整できるかどうかを判断することです。 

入力は複数の配列を記述します。 各配列について、アリスが可能な限り最良の順序を選択した後の最適な再生では、出力が勝者となります。 アリスとボブのどちらが勝つかを出力するだけで済みます。 

重要な観察は、アリスが初期配置を制御するため、元の位置は重要ではないということです。 複数の値セットのみが重要です。 値がグループ化されると、Alice は同じ値を一緒に配置できるため、それぞれの個別の値が 1 つの削除可能なブロックに寄与します。 次に、ゲームは、ブロックがいくつ存在するか、そしてプレイヤーがそれらのブロックを削除する際にどのように操作するかという問題になります。 

制約が大きいため、ゲームのシミュレーションは現実的ではありません。 要素の総数が約 200,000 に達すると、すべての順列、すべてのグループ化、またはすべての動きのシーケンスを試行するアプローチは爆発的に増加します。 ソリューションは配列を線形時間またはそれに近い時間で処理する必要があります。 

主なエッジ ケースは、同じ頻度の値から得られます。 不注意な解決策では、個別の値をカウントし、移動数が常にそのカウントであると想定する可能性がありますが、ブロック サイズのパリティによって結果が変わります。 

たとえば、次のことを考えてみましょう。```
1
3
5 5 5
```アリスは次のようにアレンジできます`[5,5,5]`。 ブロックは 1 つしかないので、アリスがそれを削除して勝ちます。 出力は次のとおりです。```
Alice
```すべての出現を独立した手として扱うソリューションでは、3 つの手が存在すると誤って認識してしまいます。 

別のケース:```
1
4
1 1 2 2
```アリスは配列を次のように配置できます。`[1,1,2,2]`。 ブロックは 2 つあり、アリスは最初に 1 つのブロックを削除します。 ボブが残りのブロックを削除したため、アリスは負けます。 出力は次のとおりです。```
Bob
```よくある間違いは、アリスは等しい値をグループ化することで常に利益を得られるが、グループ化によって決定されるのはブロックの数だけであると考えることです。 プレイヤーは引き続きそれらのブロックを交互に削除します。 

## アプローチ

 最初のアイデアは、ゲームを直接シミュレートすることです。 アリスは配列を並べ替えることができるので、さまざまな配列を試して、それぞれの配列でゲームをプレイすることができます。 可能な順列の数は非常に急速に増加するため、これは明らかに不可能です。 

もっと良い強引なアイデアは、同じ値のグループの長さのみが重要であることに気づくことです。 周波数を連続ブロックに分割し、勝者を計算する可能な方法を列挙できます。 これも失敗します。周波数は多くの可能性に分割される可能性があり、パーティションの総数が大きすぎるためです。 

重要な観察は、アリスが同じ値の出現を常に隣り合わせに配置できるということです。 値を複数のグループに分割することは、Bob に余分な動きを与えるため、決して役に立ちません。 表示される値について`cnt`場合によっては、最良の配置では、すべてを含む 1 つのブロックが得られます。`cnt`コピー。 

これで、ゲームはブロックのコレクションに縮小されました。 それぞれの個別の数字が 1 つのブロックを作成します。 プレイヤーは順番にブロックを削除するだけです。 すべての動きで正確に 1 つのブロックが削除されるため、最後の動きをしたプレイヤーが勝ちます。 

つまり、重要なのは、最適なグループ化後の個別の値の数だけです。 ブロックの数が奇数の場合は、アリスが最後の動きをします。 ブロックの数が偶数であれば、ボブはそうします。 

問題全体は、配列内に出現する異なる値の数を数えるということになります。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、表示されるすべての値を保存します。 

アリスはゲームが始まる前にすべてを並べ替えることができるため、元の順序は関係ありません。 
2. 一意の値の数を数えます。 

すべての等しい値を一緒に配置することで、それぞれの一意の値を正確に 1 つの最大ブロックに変えることができます。 
3. 一意の値の数のパリティをチェックします。 

カウントが奇数の場合、アリスは最後に残ったブロックを削除して勝ちます。 カウントが偶数の場合、ボブが最後の動きを獲得して勝ちます。 

### なぜ効果があるのか

 アリスが配列を再配置すると、すべての等しい値を連続して配置できるようになります。 これにより、個別の値ごとに 1 つのブロックが作成されます。 同じ値から複数のブロックを作成しても、手数が増えるだけであり、両方のプレイヤーがターンごとに 1 つのブロックを正確に削除するため、アリスを助けることはできません。 

したがって、このゲームは、個別の値ごとに 1 つのオブジェクトを使用する通常の交互除去ゲームと同じです。 オブジェクトの数が奇数の場合、アリスは奇数の手をすべて開始して実行するため、正確に勝ちます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        seen = set(a)

        if len(seen) % 2 == 1:
            ans.append("Alice")
        else:
            ans.append("Bob")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```このセットが使用されるのは、個別の値のみを保存するためです。 セットのサイズは、アリスが再配置後に作成できるブロックの数です。 

入力サイズが大きくなる可能性があるため、ソリューションでは次を使用します。`sys.stdin.readline`一度印刷する前に出力を収集します。 値とカウントのみを保存するため、ここでは Python 整数はオーバーフローしません。 

唯一の微妙な点は、元の位置への依存を避けることです。 アリスはゲームの開始前に配置を変更するため、配列を並べ替えたり、隣接する要素をチェックしたりすると、別の問題が解決されます。
