 # 問題の理解

 この問題は、重み付き無向グラフを通過する過程を記述します。 頂点は場所、エッジは道路であり、すべての道路には移動時間があります。 ある場所から始めて、別の場所に到達したいとします。 場所によっては避難所を設けているところもあります。 避難所に到着すると、雨の中の移動に費やした累積時間はゼロになります。 

制限は総旅行距離に関するものではありません。 それは休憩間の連続した移動のすべてについてです。 有効なルートには、開始点または避難所から次の避難所または目的地までの各部分の合計エッジ ウェイトが最大以下である限り、長い部分が多数含まれていてもかまいません。`k`。 

入力には複数のグラフ インスタンスが含まれています。 インスタンスごとに、頂点とエッジの数、降雨制限、開始頂点と目的地の頂点、避難所の頂点のセット、および重み付けされたエッジを受け取ります。 出力では、許容連続移動時間を超えずに目的地に到達できるかどうかが尋ねられます。 

すべてのテスト ケースの頂点とエッジの合計数は最大で`2 * 10^5`。 これにより、すべての避難所から最短経路アルゴリズムを繰り返し実行したり、避難所のペアを列挙したりするソリューションは除外されます。 解決策`O((n + m) log n)`頂点とエッジごとに少量の対数量の作業を実行するため、これは適切です。

# アプローチ

 直接的なアプローチは、まず重要な頂点間のペアごとの最短距離を見つけることです。重要な頂点は出発地、目的地、避難場所です。 次に、2 つの重要な頂点間の最短距離が最大で 2 つの頂点が接続されている別のグラフを作成できます。`k`。 最後に、この小さなグラフで到達可能性を確認します。 

ある重要な頂点から別の頂点への移動は、まさに 1 つの連続した雨のセグメントを表すため、この考えは正しいです。 問題は、次のようなことが考えられることです。`n`避難所。 ディクストラをすべての避難所から追い出すには、`O(n(n+m)log n)`最悪の場合、制限を大幅に超えてしまう可能性があります。 

重要な観察は、シェルター グラフを明示的に構築する必要がないということです。 現在の連続移動時間を追跡しながら、どの頂点に到達できるかを知る必要があるだけです。 避難所に到着すると、すぐに値は再びゼロになります。 

これにより、修正されたダイクストラ探索が行われます。 頂点に対して保存される距離は、開始点からの総移動距離ではありません。 これは、その頂点に立つために必要な中断のない雨の最小時間です。 値が小さいほど常に優れています。 現在の値を持つ頂点から`d`、重量のエッジを横切ることができます`w`場合のみ`d + w <= k`。 そのエッジの宛先頂点がシェルターの場合、新しい値はゼロになります。 それ以外の場合、新しい値は次のようになります。`d + w`。 

ブルート フォース手法では、検索前に考えられるすべての安全な遷移を計算します。 最適な方法では、1 回のグラフ走査中に重要な遷移を正確に検出します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 最適 |`O((n+m)log n)`|`O(n+m)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての避難所の頂点をマークして、頂点に到着すると降雨タイマーがリセットされるかどうかをアルゴリズムが即座に認識できるようにします。 重要な違いは、通常の頂点に立つことと避難所に立つことの違いです。 
2. 距離配列を初期化します。`dist[v]`頂点に到達するまでに必要な継続的な雨の最小時間を表します。`v`。 まだ移動が発生していないため、開始頂点をゼロに設定します。 優先キューに入れます。 
3. 現在の降雨時間が最小である頂点を優先キューから繰り返し取得します。 このエントリが古い場合は、無視してください。 これは、ダイクストラで使用される標準的な遅延削除手法です。 
4. すべての出力エッジについて、それを横切った後の時間を計算します。 値を超えた場合`k`、旅行者は雨の中を長時間続ける必要があるため、この移動は不可能です。 
5. エッジの宛先がシェルターの場合は、新しい値をゼロに置き換えます。 避難所に到達すると、それまでの連続移動時間が完全に削除されます。 
6. 新しい値によってネイバーの保存された値が改善される場合は、それを更新し、ネイバーを優先キューにプッシュします。 最終的に目的の頂点に到達すれば、答えは得られます。 

なぜ効果があるのか:

 不変条件というのは、`dist[v]`到達するまでに必要な可能な限り最良の残りの雨時間を常に保存します。`v`最初から。 より大きな値で頂点に到達するルートは、より小さな値で頂点に到達するルートよりも有用であることはありません。これは、将来のすべてのエッジが同じ量を追加し、シェルターが累積値を消去するためです。 優先キューはこの値の昇順に状態を処理するため、すべての緩和では最も有望な部分ルートが最初に考慮されます。 すべての遷移は降雨制限を尊重し、すべての有効な遷移が検索に利用できるため、アルゴリズムはパスが存在する場合に正確にパスを見つけます。 

# Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, m, k = map(int, input().split())
        a, b = map(int, input().split())

        s = int(input())
        shelters = []
        if s:
            shelters = list(map(int, input().split()))

        is_shelter = [False] * (n + 1)
        for x in shelters:
            is_shelter[x] = True

        graph = [[] for _ in range(n + 1)]
        for _ in range(m):
            u, v, w = map(int, input().split())
            graph[u].append((v, w))
            graph[v].append((u, w))

        inf = 10**30
        dist = [inf] * (n + 1)
        dist[a] = 0

        pq = [(0, a)]

        while pq:
            cur, u = heapq.heappop(pq)
            if cur != dist[u]:
                continue

            if u == b:
                break

            for v, w in graph[u]:
                nxt = cur + w
                if nxt > k:
                    continue

                if is_shelter[v]:
                    nxt = 0

                if nxt < dist[v]:
                    dist[v] = nxt
                    heapq.heappush(pq, (nxt, v))

        ans.append("YES" if dist[b] != inf else "NO")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```シェルター配列は、頂点の特殊なプロパティをリラクゼーション中の定数時間の検索に変換します。 これがなければ、すべてのエッジトラバーサルでシェルターリストを検索する必要があります。 

の`dist`配列には、経路の合計長ではなく、連続移動時間が格納されます。 これが主な実装の詳細です。 避難所に入るときに値をリセットすることで、通常のダイクストラのフレームワークが問題に適合します。 

条件`nxt > k`リセット前にチェックされます。 旅行者は、すでに越えることが不可能だった端にあるシェルターを魔法のように使うことはできません。 リセットは、その頂点に正常に到達した後にのみ適用されます。 

Python の整数はオーバーフローしませんが、エッジの重みが大きいと通常の 32 ビット範囲よりもはるかに大きな値が作成される可能性があるため、実装では無限大の大きな整数センチネルを使用します。
