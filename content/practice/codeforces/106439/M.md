 ## 問題の理解

 順序ペアを数えるように求められます$(a, b)$整数の長方形の内側、ここで$a$からの範囲$1$に$n$そして$b$からの範囲$1$に$m$、モジュラー算術演算とビット単位の演算を組み合わせた非常に特殊な代数条件を満たします。 

各ペアについて、2 つの剰余を計算します。$a \bmod b$そして$b \bmod a$それらを加算し、結果をビットごとの OR 値と比較します。$a \,|\, b$。 タスクは、この等式が真になるペアの数を数えることです。 

この式は対称的に見えますが、そうではありません。 の動作$a \bmod b$かどうかに大きく依存します。$a < b$または$a \ge b$、他の用語についても同様です。 ビットごとの OR はまったく異なる領域で動作し、算術構造ではなくバイナリ表現で動作します。 解決策は、構造的なケースに分けてこれら 2 つの観点を調和させることによって得られます。 

制約は大きいです。各テストには次のような制約があります。$n, m$まで$10^6$、まであります$10^4$合計が含まれるテスト ケース$n$そして$m$以下の範囲のテスト全体で$10^6$。 これにより、テストごとにすべてのペア、さらにはすべてのペアを反復するソリューションは即座に除外されます。 ナイーブ$O(nm)$スキャンには最大で$10^{12}$実行可能な限界をはるかに超えた最悪の場合の操作。 たとえ$O(n \log n)$慎重に償却しない限り、テストごとのアプローチは危険です。 

順序を考慮せずにモジュロ項を独立して処理しようとすると、微妙な障害モードが発生します。 例えば交換とか$a$そして$b$両方のモジュロ項を変更し、OR 構造も変更するため、慎重に正当化しない限り、対称ベースのショートカットは壊れることがよくあります。

重要な単純化は、どのような値を分析するかによって決まります。$a \bmod b + b \bmod a$実際に取ることができます。 モジュロ項はどちらの数値が大きいかによって異なります。 もし$a \ge b$、 それから$a \bmod b < b$そして$b \bmod a = b$。 もし$a < b$、役割が逆転します。 これにより、すぐに合計の構造が制限されます。一方の項は小さい数そのものになりますが、もう一方の項は厳密に小さい数よりも小さくなります。

### なぜ効果があるのか

 重要な不変条件は、有効なペアがモジュロ項の 1 つを強制的に消滅させることです。 これは仮定ではなく、境界引数の結果です。両方の剰余が 0 以外の場合、それらの合計は少なくとも 1 つのバイナリ位置でのビット単位の OR よりも厳密に小さくなります。これは、モジュロ演算は高次構造を消去し、OR は高次構造を保持または作成するためです。 この不一致により、一方の数値が他方の数値を割って新しいビットが導入されない退化した場合を除いて、等価性が妨げられます。 このアルゴリズムは、無効な領域を探索することなく、これらの制約されたケースを体系的に正確に列挙します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        if n > m:
            n, m = m, n

        ans = 0

        for b in range(1, m + 1):
            # count a < b where a divides b
            # divisors of b strictly less than b
            a = 1
            while a * a <= b:
                if b % a == 0:
                    d1 = a
                    d2 = b // a
                    if d1 < b and d1 <= n:
                        ans += 1
                    if d2 != d1 and d2 < b and d2 <= n:
                        ans += 1
                a += 1

            # count multiples a = k*b up to n
            k = 2
            while k * b <= n:
                a = k * b
                # bit condition: a has no bits outside b
                if (a | b) == b:
                    ans += 1
                k += 1

        print(ans)

if __name__ == "__main__":
    solve()
```実装は分割によるものに従います。$b$戦略。 除数ループは、$a < b$約数を列挙することによる体制$b$、モジュロがきれいに崩れる値のみをカウントするようにします。 複数のループハンドル$a \ge b$、ビットごとの包含条件を明示的にチェックします。 

微妙な点は、ループの順序です。$b$externalmost は、各テスト ケースの約数を個別に再計算することを回避します。 もう 1 つは、ビットごとのチェックにおける安全条件です。 たとえ数学的議論が有効なケースを強く制限しているとしても、明示的な`(a | b) == b`ガードは、乗算により禁止ビットが導入されるケースが誤って含まれることを防ぎます。

 ## 特殊なケース

 のために$n = 1$または$m = 1$、すべてのペアは単一の算術構成に崩壊し、モジュロ項は消滅します。 1 の除数の列挙は自明な除数のみを返すため、アルゴリズムはこれを正しく処理します。 

いつ$a = b$、両方のモジュロ項がゼロであるため、等式は次のようになります。$0 = a \,|\, a$、そうでない限り false です。$a = 0$、ドメインの外にあります。 ビット単位の条件が失敗するため、実装では当然これは除外されます。 

大きな素数値の場合、$a$そして$b$、除数構造は最小限であるため、有効なペアは些細な位置合わせを除いてほとんど消えます。 このアルゴリズムは、除数ループが 1 と数値自体でのみトリガーされ、後者は厳密な不等式条件によって除外されるため、寄与をほとんど生成することによってこれを反映します。
