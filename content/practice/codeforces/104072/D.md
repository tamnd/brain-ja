 ## 解決策
 ## 問題の理解

 次のサイズの正方形グリッドが与えられます。$N \times N$、各セルには 0 または 1 が含まれます。値 1 のセルは「良い」花を表し、0 は悪い花を表します。 このタスクは、境界上のすべてのセルが 1 であるという特性を持つ正方形部分行列がいくつあるかを数えるということです。正方形の内部セルはまったく問題ではありません。選択した正方形の外側の境界だけが完全に 1 である必要があります。 

正方形は、左上隅と辺の長さを選択することによって定義されます。 このような選択ごとに、その正方形の周囲のセルを検査し、それらがすべて 1 であるかどうかを確認します。答えは、すべての位置とサイズにわたる有効な正方形の合計数です。 

制約$N \le 3000$グリッドには最大 900 万個のセルがあることを意味します。 すべての四角形を明示的にチェックするソリューションは、大まかに考慮します。$O(N^2)$ポジションと最大$O(N)$辺の長さ、与える$O(N^3)$チェックが遅すぎます。 平$O(N^2 \log N)$各小切手が非常に安価でない限り、アプローチは境界線に達する可能性があります。 問題の構造は、境界チェックが一定時間またはほぼ一定時間になるようにグリッドを前処理する必要があることを強く示唆しています。 

一般的な失敗例は、これを境界のみの問題ではなく完全な部分行列の問題として扱うことから発生します。 たとえば、単純な 2D プレフィックス合計アプローチでは、正方形内のすべてのセルが 1 であることが誤って要求される可能性があります。 

次の入力を考えてみましょう。```
1 1 1
1 0 1
1 1 1
```境界線に中央のセルが含まれているため、3×3の正方形は無効ですか? 実際には、中心は境界上にないので、すべての境界セルが 1 であるため、3×3 正方形は有効です。単純な完全部分行列チェックでは、中心がゼロであるため、誤って拒否されます。 

もう 1 つの微妙なケースは、正方形がサイズ 1 に縮退する場合です。1 × 1 正方形は、その単一セルが 1 の場合、周囲がまさにそのセルであるため、常に有効です。 

このような特殊なケースでは、「内部」条件と「境界」条件を混在させると危険になります。 

## アプローチ

 ブルートフォース手法では、考えられるすべての正方形を列挙し、その周囲を直接チェックします。 左上隅ごとに$(i, j)$可能な各辺の長さ$k$、正方形の 4 つのエッジをスキャンし、すべての値が 1 であることを確認します。単一の正方形のコストをチェックする$O(k)$したがって、全体の複雑さは次のようになります。$O(N^4)$最悪の解釈で、あるいは$O(N^3)$部分スキャンを再利用することでわずかに最適化された場合。 いずれにしても、$N = 3000$、これは実現可能な限界をはるかに超えています。 

The key observation is that perimeter validity can be decomposed into directional consecutive-ones information. Instead of repeatedly scanning edges, we precompute how many consecutive 1s extend to the right from each cell, and how many extend downward. Once these are known, any horizontal or vertical segment of 1s can be validated in constant time. 正方形の大きさ$k$から始まる$(i, j)$上端、下端、左端、右端のすべてに少なくとも次の要素が含まれている場合に有効です。$k$それぞれのエンドポイントから始まる連続した 1。 これにより、境界チェックが候補正方形ごとに 4 つの定数時間ルックアップに変換されます。 

これにより、すべての正方形の位置を反復処理し、事前計算された実行を使用して各サイズをテストして、チェックを行うという問題が軽減されます。$O(1)$そして完全な解決策$O(N^3)$早期の停止と剪定によっては、それ以上の効果が得られます。 セルごとの実現可能な最大正方形サイズを慎重に処理することで、チェックの数を効果的に大幅に削減します。

 | ブルートフォース境界スキャン |$O(N^4)$|$O(1)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 まず 2 つの補助テーブルを計算します。 セルごとに、そのセルから右に連続する 1 の数が格納されます。 2 番目は、下に伸びる連続 1 の数を格納します。 これらはグリッドを右下から左上に走査することによって計算されるため、各状態は以前に計算された近傍のみに依存します。 

前処理の後、すべてのセルを正方形の左上隅の可能性として反復処理します。 このようなセルごとに、正方形の辺の長さを拡張しようとします。$k$。 正方形のサイズの場合$k$有効であるためには、次の 4 つの条件が満たされている必要があります。上端には少なくとも$k$右に 1 が連続する場合、下端にも少なくとも 1 が必要です。$k$右に 1 が連続し、同様に左端と右端にも少なくとも 1 が必要です。$k$連続した 1 が下向きになります。 

増やします$k$徐々に拡大し、境界条件が満たされなくなるとすぐに指定された原点からの拡大を停止します。これは、正方形が大きくなるとこれらの制約が厳しくなるだけであるためです。 

最後に、これらの拡張中に見つかったすべての有効な正方形の数を累積します。 

重要な不変条件は、事前に計算された右配列と下配列が各セルで始まる最大の連続 1 セグメントを正確に表すことです。 すべての周囲チェックは、対応するセグメントの長さが少なくとも正方形の辺の長さであるかどうかを確認することに帰着します。 すべての正方形の境界はそのようなセグメントで正確に構成されているため、有効な正方形が見逃されることも、無効な正方形がカウントされることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [list(map(int, input().split())) for _ in range(n)]

    right = [[0] * n for _ in range(n)]
    down = [[0] * n for _ in range(n)]

    for i in range(n - 1, -1, -1):
        for j in range(n - 1, -1, -1):
            if g[i][j] == 1:
                right[i][j] = 1 + (right[i][j + 1] if j + 1 < n else 0)
                down[i][j] = 1 + (down[i + 1][j] if i + 1 < n else 0)

    ans = 0

    for i in range(n):
        for j in range(n):
            max_k = min(right[i][j], down[i][j])
            k = 1
            while k <= max_k:
                if i + k - 1 >= n or j + k - 1 >= n:
                    break

                if right[i + k - 1][j] >= k and down[i][j + k - 1] >= k:
                    ans += 1
                    k += 1
                else:
                    break

    print(ans)

if __name__ == "__main__":
    solve()
```前処理ループは、1 の最大の水平および垂直ランを計算します。 各セルの反復では、これらの実行を使用して、可能な最大正方形サイズを即座に制限し、無駄なチェックを回避します。 上端と左端は開始セルの事前計算値によって暗黙的に保証されているため、展開ループは下端と右端のみを明示的に検証します。 

実装の微妙な詳細は、while ループ内の停止条件です。 正方形のサイズに一度$k$失敗すると、同じ原点からのより大きな正方形も失敗します。これは、少なくとも 1 つのすでに無効な境界を拡張しているためです。 この単調性により、早期停止が安全になります。

 ## 特殊なケース

 0 を含む 1×1 グリッドの場合、両方の方向配列が 0 であるため、アルゴリズムは正しく 0 を生成し、正方形は有効とはみなされません。 

中空の正方形など、1 が細い境界線のみを形成するグリッドの場合、アルゴリズムは内部密度ではなく境界の連続性にのみ依存するため、依然として大きな有効な正方形をカウントします。 DP 配列は、エッジに沿った中断のない実行を正確に反映するため、内部がゼロで埋められている場合でも、周囲のチェックは正確なままです。
