 ## 解決策
 ## 問題の理解

 いくつかのボールが異なる位置に配置されたラインが与えられます。 各ボールは既知の座標から始まり、数直線に沿って左または右に一定の速度で移動します。 すべてのボールが同時に動き始めます。 おもしろいのは、2 つのボールが出会うたびに、複雑な物理的な方法で相互作用するのではなく、速度を交換することによって相互に通過することです。これにより、アイデンティティを無視すると、システムは自由に移動する粒子と同等になります。 

一定の時間 T に、すべてのボールがどこにあるかを判断するように求められます。 衝突によりボール間の速度が効果的に変更されるため、最終的な出力は元のアイデンティティに関連付けられません。 代わりに、時刻 T 以降のすべてのボールの位置のマルチセットに興味があり、非降順で出力されます。 

重要な制約は、N が最大 100000、座標と速度の大きさが最大 ​​10^9、時間は最大 10^9 です。 これは、時間を段階的に進めたり、衝突を明示的に処理したりするシミュレーションは不可能であることを直ちに意味します。 衝突の単純なシミュレーションでは、ボールのすべてのペアがスワップのチェーンを通じて間接的に相互作用する可能性があるため、最悪の場合、潜在的に O(N^2) 個の相互作用イベントを処理する必要があります。 衝突イベントの数は二次関数になる可能性があるため、イベント駆動型シミュレーションであっても遅すぎる可能性があります。 

複数のボールが同じ初期位置を共有する場合、または速度が異なるために同時に同じ点に到着する場合、より単純ですが微妙なエッジ ケースが発生します。 衝突は瞬間的な交換として定義されるため、これらの状況は最終的な位置セットに曖昧さを生じさせませんが、動きの数学的変換を扱うのではなく明示的に順序付けをシミュレートしようとする単純な実装を壊します。 

たとえば、位置 0 と 10 にある 2 つのボールが速度 1 と -1 で互いに向かって移動しているとします。 T = 5 の後、それらは位置 5 で衝突し、速度が交換されるため、左側のボールは右側で終了し、その逆も同様です。 アイデンティティを追跡する単純なシミュレーションでは、衝突順序を正確に処理する必要がありますが、最終的な位置は、ボールが互いに通過した場合と同じになります。 

モデリングの核となる洞察は、衝突時に速度を交換することで、システムがボールを相互作用せずに相互に通過させ、その後順序に基づいて ID を再割り当てするのと同等になるということです。 

## アプローチ

 ブルート フォース ビューでは、モーションをシミュレートし、衝突を明示的に処理します。 すべてのボールを位置別に並べ替えて維持し、次の衝突イベントを繰り返し見つけ、そのイベントまで時間を進め、衝突しているペアの速度を交換し、時間 T まで継続します。各衝突はイベントであり、最悪の場合、隣接するボールのすべてのペアが速度に応じて複数回衝突する可能性があります。 イベントの数は O(N^2) に達する可能性があり、各イベントには優先キューの更新またはリスト スキャンが必要なため、N = 100000 ではソリューションが遅すぎます。 

重要な観察は、衝突中に速度を交換するということは、ボールのアイデンティティを無視した場合、ボールが変化せずに相互に通過するように動作すると言っているのと同じであるということです。 これは、各ボールが独立して動いた場合にどこにあるかを計算できることを意味します。時間 T での位置は、単純に p_i + s_i * T です。 

残る唯一の問題は、衝突によってアイデンティティが入れ替わることですが、出力には非降順でソートされた位置のみが必要であるため、アイデンティティは無関係です。 すべての最終位置を個別に計算した後、それらを並べ替えることで正しい構成が得られます。 半径 R は、軌道交換の数学的等価性ではなく、衝突が発生した場合にのみ影響するため、最終的な位置とは無関係です。 

したがって、問題は、各ボールの線形変換を計算し、結果をソートすることに帰着します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N^2) 以上 | O(N) | 遅すぎる |
 | 独立したモーション + ソート | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ボールについて、衝突がまったく起こらなかったかのようにその位置を計算します。 これは、一定速度の下での均一な動きを表す p_i + s_i * T を使用して行われます。 衝突では速度が交換されるだけで、一連の軌道は変更されないため、このステップは有効です。 
2. 計算されたすべての位置を配列に保存します。 この時点で、各エントリはボールの最終的な可能な位置を表しますが、アイデンティティはもはや意味を持ちません。 
3. 位置の配列を降順でない順序で並べ替えます。 衝突ではどのボールがどの軌道を占めるかが変更されるだけで、最終的な座標のセットは変更されないため、ソートが必要です。 
4. ソートされたリストを最終構成として出力します。 

なぜ効果があるのか

 重要な不変条件は、衝突によってボール間の速度のみが変更されるということです。これは、複数の軌道セットが保存されることを意味します。 各速度をトークンとしてラベル付けし、それを自由に移動させることを想像すると、各トークンは直線のパスをたどります。 スワッピングメカニズムにより、ボールが出会ったときにこれらのトークンを簡単に交換できます。 したがって、任意の時間 T において、ボールが占める位置のセットは、衝突を考慮せずに各初期ボールを独立して前進させることによって得られる位置のセットとなります。 唯一の違いは、どのボールがどの位置に配置されるかということですが、出力はソートされているため、これは無関係です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, r, t = map(int, input().split())
    pos = []
    
    for _ in range(n):
        p, s = map(int, input().split())
        pos.append(p + s * t)
    
    pos.sort()
    print(*pos)

if __name__ == "__main__":
    solve()
```この実装は、衝突が最終位置のマルチセットに影響を与えないという観察に直接基づいています。 各ボールの軌道は個別に計算され、結果が並べ替えられます。 

唯一の微妙な点は、64 ビットの安全な演算を使用していることです。 Python ではこれは自動的に行われますが、他の言語では p_i と s_i * T が 10^18 に達する可能性があるため注意が必要です。

 入力:

| ボール | p | s | p + sT |
 | --- | --- | --- | --- |
 | 1 | 3 | -1 | -2 |
 | 2 | 8 | -2 | -2 |
 | 3 | 1 | 3 | 16 |

 並べ替えると、-2、-2、16 が得られます。 

これは、速度と初期配置に応じて 2 つのボールが最終的に同じ最終座標値を共有する可能性があるが、順序は最後にのみ決定されるという考えと一致します。 

このトレースは、直接評価によってすでに正しい最終セットが得られているため、衝突が計算に無関係であることを示しています。

 ## 特殊なケース

 微妙な状況の 1 つは、2 つのボールが計算上のまったく同じ位置に来る場合です。 たとえば、異なる点から始まった 2 つのボールは、速度が反対であるため、時間 T 後に同じ座標に着地する可能性があります。 ソートでは自然に等しい値が扱われ、元のプロセスでの衝突でも、最終的な位置セットを変更せずに一時的なオーバーラップが許可されるため、このアルゴリズムは引き続き機能します。 

もう 1 つのエッジ ケースは T = 0 です。この場合、計算された位置は初期位置 p_i に減り、ソートは単純に座標による初期順序を返します。これは、動きが発生しないため要件と一致します。 

さらに特殊なケースとしては、負の速度と大きな T の組み合わせがあり、位置が負の数に押し込まれる可能性があります。 式 p_i + s_i * T はこれを直接処理し、Python の整数演算により、固定幅整数言語で発生するオーバーフローの問題を防ぎます。
