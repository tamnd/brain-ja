 ## 解決策
 ## 問題の理解

 宇宙船が固定された開始点から固定された目的地まで移動する平面内での幾何学的なルーティングの問題が与えられます。 その動きは継続的ですが、重要な制限が 1 つあります。左に移動することはできません。つまり、その x 座標はパスに沿って常に減少しません。 

開始点と終了点の間には、X 座標に関して厳密に左から右にソートされたいくつかの線分があります。 各セグメントは壁または魔法のゲートのいずれかです。 壁は幾何学的な障害物として機能します。宇宙船はその内部を通過することはできませんが、端点やセグメント自体に触れたり、それに沿ってスライドしたりすることは許可されます。 マジック ゲートの動作は異なります。パスがそのようなセグメント (エンドポイントを含む) を横切るたびに、プレイヤーは固定の報酬を獲得し、各ゲートは何回横切ったとしても 1 回だけカウントされます。 

選択したパスのコストは、移動したユークリッド長の合計からマジック ゲートから収集した報酬の合計を差し引いたものになります。 タスクは、この値を最小化する開始から終了までのパスを見つけることです。 

入力の順序によって課せられる構造がキー制約となります。 すべてのセグメントは左から右にソートされており、同一線上にある 3 つの入力点がないため、ジオメトリは、意味のあるパスの変更がセグメントの終点または開始点と終了点でのみ発生する構造を形成します。 これは、最適なパスがこれらの特別な点の間の直線移動で構成されていると想定できることを強く示唆しています。 

主な問題は、報酬がセグメントごとにグローバルであり、コストから差し引かれるのは 1 回だけであるため、パスが静的グラフ内の単純な最短パスではないことです。 単純な最短経路の解釈は、セグメントの交差がどのようにボーナスに寄与するかを正しくモデル化しない限り失敗します。 

エッジ ケースは、直接の直線パスが複数のゲートまたは壁と交差する場合に発生します。 たとえば、直接のセグメントは 2 つのマジック ゲートを通過する可能性がありますが、そのうちの 1 つを迂回すると、報酬のスキップが最適になるほど十分な距離が増加する可能性があります。 もう 1 つの微妙なケースは、投影順序でエンドポイントが一致する、またはほぼ一致する場合です。この場合、次に表示されるポイントを貪欲に選択すると失敗する可能性があります。これは、パスが少し長いと後で高い報酬が得られる可能性があるためです。 

制約は最大数千のセグメントを示唆しているため、二次または二次に近い幾何学的グラフの構築は妥当ですが、セグメントの交点を超える三次関数は遅すぎます。 

## アプローチ

 直接的な強引なアプローチでは、障害と報酬を含む連続した最短経路として問題をモデル化しようとします。 セグメントの端点の周りで曲がるすべての可能な多角形パスをシミュレートし、収集されたマジック ゲートのすべてのサブセットをチェックすることを想像できます。 頂点をセグメントの端点に制限しても爆発が発生します。N 個のセグメントの場合、目に見える点のすべてのペアがエッジを定義する可能性があり、各エッジは妥当性と報酬の寄与についてすべてのセグメントに対してテストする必要があります。 これは、慎重に実行するとおよそ O(N³) の動作につながりますが、パスが明示的に列挙されている場合はさらに悪化します。 

重要な観察は、ジオメトリは本質的に、左から右に順序付けされた環境における可視性グラフの問題であるということです。 X 座標はすべてのセグメントの端点にわたって厳密に増加しているため、中間の任意の曲率を必要とせずに、最適なパスを端点のサブセット (および開始点と終了点) 間の直線ジャンプに分解できます。 このような各セグメントはユークリッド距離コストに寄与し、壁を横切るかどうか、およびどのゲートと交差するかを事前に計算できます。

これにより、問題は、すべてのエンドポイントに開始点と終了点を加えたノードを持つグラフ上の最短パスに変換されます。 エッジは、壁の内部と交差しない有効な直線セグメントを表します。 各エッジの重みは、ユークリッド距離から交差するすべてのゲートの報酬の合計を引いたものです。 各ゲートの報酬は最終パスで 1 回だけカウントされるため、状態は技術的に拡張されますが、各ゲートは左から右の固定順序にある​​ため、同じセグメント構造を再利用する遷移内で二重にカウントしないようにすることで、制御された方法で交差エッジごとの報酬寄与を組み込むことができます。 結果として得られる構造は、通常、幾何学的チェックによって構築された密ではあるが管理しやすいグラフに対してダイクストラを使用して、最短パスの計算をサポートします。 

効率の向上は、連続的な移動を O(N) ポイント間の組み合わせの可視性遷移に置き換えることによって得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース連続パス列挙 | 指数関数 / O(N³) 以上 | O(N) | 遅すぎる |
 | 可視性グラフ + 最短パス | O(N² log N) | O(N²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 平面内のすべての重要な点、つまりセグメントの始点、終点、およびすべての終点を収集します。 セグメント上のどの内部点も新しい組み合わせの可視性動作を導入しないため、これらは最適なパスの転換点の唯一の候補です。 
2. 点のペアごとに、それらの間の直線セグメントが有効かどうかを検討します。 壁セグメントの内部を通過するセグメントは無効です。 これをチェックするには標準のセグメント交差テストが必要ですが、エンドポイントは許可されるため、厳密な内部交差を慎重に適用する必要があります。 
3. 有効な点のペアごとに、そのユークリッド長を計算します。 これは、これら 2 点間を直接移動するための基本移動コストを形成します。 
4. マジック ゲート セグメントごとに、2 点間の直線セグメントが交差するかどうかを判断します。 存在する場合、その報酬値を減算としてエッジの重みに追加します。 このステップでは、各エッジを複数のゲート報酬を収集する可能性があるものとして扱います。 
5. ノードがすべて点であり、重み付けされたエッジがすべて上記で計算された有効な遷移であるグラフを構築します。 
6. 開始ノードからダイクストラのアルゴリズムを実行し、変更されたエッジの重みを使用して、他のすべてのノードに到達するための最小コストを計算します。 
7. 終了ノードまでの最短距離の値を返します。 

重要な点はステップ 4 にあります。交差点検出では、内部交差点が正しく識別されることを保証しながら、エンドポイントを有効な交差点として扱う必要があります。 浮動小数点または精度のエラーを回避するには、堅牢な幾何学的配向テストが必要です。 

### なぜ効果があるのか

 この正しさは、壁の制約に違反しない限り、コストを増加させることなく、イベント ポイント間で実行可能なパスを継続的に「直線化」できるという事実から得られます。 壁は内部をブロックするだけで、端点の周囲を除いて曲線の迂回を強制しないため、最適なパスは端点間の一連の直線の可視エッジに変換できます。 この削減された構造内で、ダイクストラは、距離から報酬を差し引いた全体的に最適な累積を正確に捕捉します。これは、すべての報酬が、選択したエッジによって完全に決定されるセグメント交差イベントに関連付けられており、各エッジのコストがすでにその寄与を正確に 1 回エンコードしているためです。 

## Python ソリューション```python
import sys
import math
import heapq

input = sys.stdin.readline

def orient(ax, ay, bx, by, cx, cy):
    return (bx - ax) * (cy - ay) - (by - ay) * (cx - ax)

def on_segment(ax, ay, bx, by, cx, cy):
    return min(ax, bx) <= cx <= max(ax, bx) and min(ay, by) <= cy <= max(ay, by)

def seg_intersect(a, b, c, d):
    ax, ay = a
    bx, by = b
    cx, cy = c
    dx, dy = d

    o1 = orient(ax, ay, bx, by, cx, cy)
    o2 = orient(ax, ay, bx, by, dx, dy)
    o3 = orient(cx, cy, dx, dy, ax, ay)
    o4 = orient(cx, cy, dx, dy, bx, by)

    if o1 == 0 and on_segment(ax, ay, bx, by, cx, cy):
        return True
    if o2 == 0 and on_segment(ax, ay, bx, by, dx, dy):
        return True
    if o3 == 0 and on_segment(cx, cy, dx, dy, ax, ay):
        return True
    if o4 == 0 and on_segment(cx, cy, dx, dy, bx, by):
        return True

    return (o1 > 0) != (o2 > 0) and (o3 > 0) != (o4 > 0)

n = int(input())
segs = []
gates = []

points = []

for _ in range(n):
    tmp = list(map(int, input().split()))
    if tmp[0] == 0:
        _, x1, y1, x2, y2 = tmp
        segs.append(((x1, y1), (x2, y2), 0))
    else:
        _, p, x1, y1, x2, y2 = tmp
        segs.append(((x1, y1), (x2, y2), p))
        gates.append(len(segs) - 1)

sx, sy, tx, ty = map(int, input().split())

points.append((sx, sy))
points.append((tx, ty))

for a, b, _ in segs:
    points.append(a)
    points.append(b)

m = len(points)

def edge_cost(i, j):
    a = points[i]
    b = points[j]

    for (u, v, typ) in segs:
        if typ == 0:
            if seg_intersect(a, b, u, v):
                if not (a == u or a == v or b == u or b == v):
                    return None

    cost = math.hypot(a[0] - b[0], a[1] - b[1])

    for (u, v, typ) in segs:
        if typ == 1:
            if seg_intersect(a, b, u, v):
                cost -= typ

    return cost

adj = [[] for _ in range(m)]

for i in range(m):
    for j in range(i + 1, m):
        c = edge_cost(i, j)
        if c is not None:
            adj[i].append((j, c))
            adj[j].append((i, c))

dist = [float('inf')] * m
dist[0] = 0
pq = [(0, 0)]

while pq:
    d, u = heapq.heappop(pq)
    if d != dist[u]:
        continue
    for v, w in adj[u]:
        nd = d + w
        if nd < dist[v]:
            dist[v] = nd
            heapq.heappush(pq, (nd, v))

print(dist[1])
```この実装では、すべての端点と開始点と終了点にわたる可視性グラフを構築し、各エッジに壁に対する幾何学的実現可能性チェックを割り当てます。 マジック ゲートは、セグメントが各ゲートと交差するかどうかを確認し、エッジの重みから対応する報酬を減算することによって処理されます。 

微妙な点は、壁には厳密な内部除外が必要なため、交差テストでは端点の接触は許可されますが、内部の交差は拒否されることです。 もう 1 つのデリケートな側面は、浮動小数点距離がダイクストラで累積されるため、必要な精度を考慮すると Python 浮動小数点数を使用するだけで十分であることです。

 ## 特殊なケース

 重要なエッジ ケースは、最適なパスが壁の終点に正確に接触する場合に発生します。 このような場合、端点接触を無効として扱う単純な交差テストでは、有効なエッジが誤って削除されてしまいます。 アルゴリズムは、交差チェックでエンドポイントの等価性を明示的に許可することでこれを処理します。 

もう 1 つのケースは、直線セグメントが複数のゲートを通過するが、共線性によりそれらの一部のみが幾何学的に交差する場合です。 方向ベースのセグメント交差により、単なる境界ボックスの重なりではなく、真の交差のみがカウントされることが保証されます。 

3 番目のケースは、最適なパスが直接的ではないものの、開始点と終了点と同一線上にある中間エンドポイントを使用する場合です。 入力ではエンドポイント間に 3 つの共線点がないことが保証されるため、グラフは悪化した曖昧さを回避し、ダイクストラでは特別なタイブレークが必要ありません。
