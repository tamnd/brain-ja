 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、根を張った木です。$n$頂点。各エッジには空ではない文字列がラベル付けされます。 ツリーのルートは頂点 1 です。ルート以外の各頂点$v$親がいる$p_v$そして文字列$s_v$端から$p_v$に$v$。 「位置」は、エッジ文字列上の特定の文字として定義され、ペアで示されます。$(v, x)$、 どこ$x$は 0 から始まるインデックスです$s_v$。 

この問題では、位置のペアの数を数えるように求められます。$(v, x)$そして$(u, y)$最初の位置から 2 番目の位置まで常に下方向に移動するツリー パスをたどると、このパスに沿って連結された文字が特定のターゲット文字列を形成します。$t$。 

ツリーには最大で次のものを含めることができます$10^5$頂点の数を超えず、すべてのエッジの文字の合計数が次を超えないこと$3 \cdot 10^5$。 すべての位置のペアを試す単純なアプローチでは、すべてのエッジ文字列のすべての位置を反復処理する必要があります。 位置の数は文字の総数に比例します。$3 \cdot 10^5$、各パスを確認するには、追加の文字をスキャンする必要があります。 これにより、最悪の場合の時間計算量が近づきます。$O(10^{11})$、これは 1 秒の制限には大きすぎます。 

エッジ ケースには、エッジ上の非常に短い文字列、異なるエッジにわたって繰り返される部分文字列、およびターゲット文字列が複数のエッジにまたがる状況が含まれます。 たとえば、次の場合$t = "aba"$「aba」というラベルが付いた単一のエッジがある場合、インデックス 0 で始まりインデックス 2 で終わる位置のペアがカウントされる必要があります。 単純なエッジのみの比較では、親子エッジにまたがる一致を見逃す可能性があります。 

## アプローチ

 ブルート フォース アプローチはシンプルです。すべての可能な開始位置を反復処理します。$(v, x)$、木の端の文字列に沿って下方向にトラバースし、連結された文字が一致するかどうかを確認します。$t$。 このアプローチは正しいのですが、文字の合計数が多く、パスに多くの連結された文字列が含まれる可能性があるため、大きなツリーでは失敗します。 までを想定すると$3 \cdot 10^5$位置と各パスに必要な場合があります$O(|t|)$文字の比較、演算は簡単に超えます$10^{10}$。 

重要な観察は、問題がツリー パスに沿った文字列の一致に帰着できるということです。 ノードから下への各パスは、一連の文字として見ることができます。 ローリング ハッシュまたはプレフィックス オートマトンを使用して、各パスを効率的に表すことができます。 深さ優先検索でツリーを走査することにより、ルートから現在の位置までの現在のパスのローリング ハッシュを維持できます。 各位置で、現在の位置で終わる部分文字列が一致するかどうかを確認できます。$t$ハッシュ値を比較することによって。 これにより、すべての候補部分文字列をチェックできるようになります。$O(1)$各部分文字列を明示的にスキャンするのではなく、ハッシュ テーブルを使用して位置ごとに実行します。 

さらに、DFS を再帰的に適用し、ハッシュ値を段階的に更新しながら、文字列をエッジごと、文字ごとに処理する必要があります。 これにより、時間の複雑さが軽減されます。$O(\text{total characters})$、問題の制約の下では許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n \cdot | t | \cdot \text{平均パス長})) |
 | DFS + ローリング ハッシュ |$O(\text{total characters})$|$O(\text{total characters})$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 木構造、エッジ文字列、対象文字列を読み取る$t$。 各エッジに親ラベルと文字列ラベルを割り当てます。 長さを計算します$t$ローリングハッシュの累乗を一度計算します。 
2. DFS をルートから初期化します。 各エッジ文字列の各文字について、ルートからその文字までのパスを表すローリング ハッシュを拡張します。 ハッシュ値からそのカウントまでのマップを維持して、定数時間の部分文字列検索を可能にします。 
3. 各ポジションで$(v, x)$エッジ内の文字に対応し、この長さの位置で終わる部分文字列のハッシュを計算します。$|t|$。 ハッシュが事前に計算されたハッシュと一致する場合、$t$、答えを増やします。 
4. DFS を子頂点まで再帰的に続行し、そのエッジ文字列をローリング ハッシュ パスに追加します。 子を終了した後、その文字列をパスから削除し、兄弟との干渉を避けるためにローリング ハッシュを調整してバックトラックします。 
5. DFS が完了したら、一致したペアの合計数を出力します。 重要なのは、ローリング ハッシュにより、下向きのパスに沿った定数時間の部分文字列の一致が可能になるため、文字列を明示的に連結することなく、すべての候補位置が効率的に考慮されることです。 

機能する理由: すべての下向きのパスに沿ったすべての文字で、アルゴリズムはルートからその文字までのパスの正確なローリング ハッシュを維持します。 大きな素数係数と適切な基数があれば、ハッシュの衝突は非常にまれであるため、すべての有効な部分文字列が一致します。$t$は 1 回だけカウントされます。 バックトラッキングにより、兄弟パスが独立していることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
BASE = 31

def solve():
    n = int(input())
    tree = [[] for _ in range(n)]
    strings = [''] * n
    for i in range(1, n):
        p, s = input().split()
        p = int(p) - 1
        tree[p].append(i)
        strings[i] = s
    t = input().strip()
    len_t = len(t)

    # Precompute rolling hash of target string t
    t_hash = 0
    power = 1
    for ch in reversed(t):
        t_hash = (t_hash + (ord(ch) - ord('a') + 1) * power) % MOD
        power = (power * BASE) % MOD

    ans = 0

    def dfs(node, path_hash, path_powers):
        nonlocal ans
        current_hash = path_hash[:]
        current_powers = path_powers[:]
        for i, ch in enumerate(strings[node]):
            val = ord(ch) - ord('a') + 1
            h = (current_hash[-1] * BASE + val) % MOD
            current_hash.append(h)
            current_powers.append(current_powers[-1] * BASE % MOD)
            if len(current_hash) > len_t:
                start_h = (h - current_hash[-len_t - 1] * current_powers[len_t]) % MOD
                if start_h < 0:
                    start_h += MOD
            else:
                start_h = h if len(current_hash) == len_t else -1
            if start_h == t_hash:
                ans += 1
        for child in tree[node]:
            dfs(child, current_hash, current_powers)

    dfs(0, [0], [1])
    print(ans)

if __name__ == "__main__":
    solve()
```このコードはツリーを初期化し、ターゲット文字列のローリング ハッシュを計算し、各文字へのパスのハッシュを維持しながら DFS を実行します。 長さの部分文字列の場合$|t|$ハッシュと一致すると、答えがインクリメントされます。 エッジ文字列は文字ごとに処理され、DFS はすべての下向きのパスが考慮されるようにします。
