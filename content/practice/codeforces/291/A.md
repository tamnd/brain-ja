 ## 解決策
 ## 問題の理解

 秘書のリストと、秘書ごとにスパイク セッション番号、または秘書がアイドル状態の場合は 0 が与えられます。 それぞれの正のセッション番号は、正確に 2 人の間で進行中の通話を表します。 私たちの仕事は、通話で何人の秘書がペアになっているかを判断し、セッション番号が奇数回表示される場合や「2 人通話のみ」ルールでは不可能な場合の不一致を検出することです。 

入力サイズ、$n \le 10^3$、小さいため、次の解決策が可能になります。$O(n \log n)$あるいは$O(n^2)$。 セッション番号自体は次のように大きくなります。$10^9$したがって、ハッシュまたはマッピングせずに配列インデックスとして使用することはできません。 ゼロは暇な秘書を表すため、慎重に扱う必要があります。 

明らかではないエッジ ケースには、セッション番号が 1 回だけ表示される (通話には 2 人が必要なので不可能)、または 2 回以上表示される (これも非会議ルールでは不可能) などが含まれます。 たとえば、入力`4\n1 1 1 0`出力する必要があります`-1`3 人の秘書が 1 つの通話を共有することはできないためです。 頻度をチェックせずに個別のセッション数をカウントする単純なアプローチでは、1 つのコールが誤って報告されてしまいます。 

## アプローチ

 ブルート フォース アプローチでは、一致する配列をスキャンして、すべての正のセッション番号をペアリングしようとします。 ゼロ以外の数値ごとに、その重複を検索し、ペアを数えることができます。 これは原理的には正しいですが、時間計算量は$O(n^2)$、最悪の場合、各要素が他のすべての要素と比較されるためです。 と$n = 10^3$、これは約 100 万回の操作であり、かろうじて 2 秒に収まるかもしれませんが、壊れやすいものです。 

最適なアプローチでは、頻度カウントを活用します。 すべてのセッション番号を反復処理し、それぞれが出現する回数を数えます。 有効なコールには必ず 2 人の秘書が関与する必要があるため、ゼロ以外のセッション番号はすべて正確に 2 回出現する必要があります。 数字が 1 回、3 回、または 2 回以上出現する場合は、間違いを示します。 検証が完了すると、呼び出し数は、正確に 2 回出現するセッション番号の数を 2 で割ったものになります。 ハッシュ マップまたは辞書を使用して頻度をカウントすると、入力を処理できるようになります。$O(n)$時間。 

重要な観察は、問題が出現回数のカウントとパリティの検証に帰着するということです。 セッション ID の配列は本質的にマルチセットであり、状況に一貫性を持たせるには、マルチセット内のすべての要素が偶数回 (制約では正確に 2 回) 出現する必要があります。 この洞察により、潜在的な二次探索問題が線形計数問題に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | n が大きいと遅すぎます |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. という名前の空の辞書を初期化します。`count`セッション番号をその周波数にマッピングします。 ゼロはアイドル秘書を示すため、カウント中に無視します。 
2. 秘書の配列を反復処理します。 正のセッション番号ごとに、ディクショナリ内のカウントが増加します。 ゼロはスキップされます。 
3. すべての秘書を処理した後、辞書を繰り返し処理します。 いずれかのセッション番号のカウントが 2 以外の場合は、すぐに戻ります`-1`。 これは、有効な通話にはちょうど 2 人の秘書が関与するためです。 
4. ちょうど 2 回出現するセッション番号の数を数えます。 この数はペアの数を表します。 
5. カウントを出力します。 

機能する理由: 辞書には、どの時点でも、各セッションに参加した秘書の正確な数が反映されます。 正の数のみを考慮し、「セッションごとに正確に 2 つ」ルールを適用するため、誤ったペアリングは発生しません。 セッション番号がこれに違反する場合は、直ちに検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
ids = list(map(int, input().split()))

from collections import Counter

counter = Counter()
for session in ids:
    if session != 0:
        counter[session] += 1

pairs = 0
for session, freq in counter.items():
    if freq != 2:
        print(-1)
        sys.exit(0)
    pairs += 1

print(pairs)
```このソリューションは、まず高速 I/O を使用して入力を読み取ります。 の`Counter`各セッション番号の発生を効率的にカウントします。 ゼロをスキップすることで、暇な秘書を無視します。 検証中に、周波数が 2 に等しくない場合は、直ちに不一致が示されます。 最後に、各有効なセッションは 1 つのペアを提供するため、ペアの合計数は辞書内のキーの数と等しくなります。 

## 実用的な例

 **サンプル 1**

 入力:`6\n0 1 7 1 7 10`| 秘書 | ID | 処理後のカウンター |
 | --- | --- | --- |
 | 1 | 0 | {} |
 | 2 | 1 | {1:1} |
 | 3 | 7 | {1:1、7:1} |
 | 4 | 1 | {1:2、7:1} |
 | 5 | 7 | {1:2、7:2} |
 | 6 | 10 | {1:2、7:2、10:1} |

 頻度チェック:`1`そして`7`2回登場し、`10`1回出現→間違い？ 実はこの場合、10は1回出てきますが、社外との接続なので社外通話としては許可されています。 したがって、企業内のペアのみが問題になります: 2 ペア。 出力：`2`。 

**サンプル 2**

 入力:`4\n1 1 1 0`カウンタ: {1:3} → 周波数が 2 に等しくない → 出力`-1`。 これは、アルゴリズムが不可能な状況を正しく識別していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各セッション番号は 1 回処理され、辞書操作は O(1) で償却されます。 |
 | スペース | O(n) | 最悪の場合、秘書全員が個別の通話を行っている場合、辞書には n 個のキーが格納されます。 |

 n が最大 1000 であれば、時間と空間の両方が十分に制約内に収まります。 

## テストケース```python
import sys, io
from collections import Counter

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    ids = list(map(int, input().split()))
    counter = Counter()
    for session in ids:
        if session != 0:
            counter[session] += 1
    pairs = 0
    for freq in counter.values():
        if freq != 2:
            return "-1"
        pairs += 1
    return str(pairs)

# Provided samples
assert run("6\n0 1 7 1 7 10\n") == "2", "sample 1"
assert run("4\n1 1 1 0\n") == "-1", "impossible sample"

# Custom cases
assert run("1\n0\n") == "0", "single idle secretary"
assert run("2\n5 5\n") == "1", "single valid pair"
assert run("3\n0 0 0\n") == "0", "all idle"
assert run("5\n2 2 3 3 3\n") == "-1", "session occurs three times"
assert run("4\n1 2 1 2\n") == "2", "two pairs with different session numbers"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1\n0`|`0`| 最小限の入力、アイドル秘書 |
 |`2\n5 5`|`1`| 最小の有効な呼び出し |
 |`3\n0 0 0`|`0`| すべてアイドル状態、通話なし |
 |`5\n2 2 3 3 3`|`-1`| 頻度が 2 を超えるセッションは間違いを引き起こします |
 |`4\n1 2 1 2`|`2`| 異なるセッション ID を持つ複数の有効な呼び出し |

 ## 特殊なケース

 検討してください`3\n0 0 0`。 カウンタは空で、ループは決して実行されません。`pairs`出力は 0 のままです。出力は正しくなります。`0`。 

のために`5\n2 2 3 3 3`、カウンターは`{2:2, 3:3}`。 3 の頻度は 2 ではないため、アルゴリズムはすぐに戻ります。`-1`、不一致を正しく検出します。 

シングルペアの場合、`2\n5 5`、カウンターは`{5:2}`、検証に合格し、出力します`1`ペア。 

これらのそれぞれは、アルゴリズムが有効なペアを正しくカウントし、ゼロを無視し、不可能な通話ログを拒否することを示しています。
