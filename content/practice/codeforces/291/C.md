 ## 問題の理解

 各 IP アドレスは実際には、ドット付き 10 進数形式で書かれた 32 ビットの整数です。 サブネット マスクも 32 ビット値ですが、非常に特殊な形状を持つ必要があります。つまり、先頭にいくつかの`1`ビットの後にいくつかの末尾が続く`0`ビット。 

IP アドレスとサブネット マスクの AND 演算の結果がネットワーク アドレスになります。 マスクを適用した後に同じ結果が得られる場合、2 つの IP は同じネットワークに属します。 

最大 100,000 個の個別の IP アドレスとターゲット番号が与えられます`k`。 指定されたアドレスが正確に属するようなサブネット マスクを見つける必要があります。`k`異なるネットワーク。 複数のマスクが機能する場合は、最も少ないマスクを出力する必要があります。`1`ビット。 サブネット マスクは先頭のマスクで構成されているため、すべての有効なマスクの中で可能な限り短いプレフィックス長が必要であることを意味します。 マスクが正確に生成されない場合`k`ネットワーク、私たちは出力します`-1`。 

制約`n ≤ 100000`アドレスのすべてのペアを比較するものはすべて即座に除外されます。 アン`O(n²)`解決策には大まかに必要になります`10^10`最悪の場合の運用。 に近いものが必要です`O(n log n)`または`O(32n)`。

## アプローチ

 ブルートフォースのアイデアは単純です。 サブネット マスクは、完全にプレフィックス長によって決まります。 少なくとも 1 つ必要な場合、有効なマスクは 31 個のみです`1`ビットと少なくとも 1 つ`0`ビット、または先頭ビットを 0 ～ 32 の間に保つという観点から考えると、33 個の可能性があります。 マスクごとに、すべてのネットワーク アドレスを計算し、表示される個別の結果の数を数えます。 

マスク1枚あたりの費用は`O(n)`。 考えられるすべてのプレフィックス長に対してこれを繰り返すとコストがかかります`O(32n)`、これは約 320 万回の操作に相当します。`n = 100000`。 驚くべきことに、これでもすでに十分に高速です。 

重要な観察は、検索スペースが小さいということです。 入力には最大 10 万のアドレスが含まれますが、サブネット マスクの数は IP アドレスのビット幅、つまり 32 によって制限されます。 

2 番目の観察により、ソリューションはさらにきれいになります。 プレフィックスの長さが増加すると、各アドレスのより多くのビットが保存されます。 ネットワークは分割のみ可能であり、結合はできません。 したがって、個別のネットワーク アドレスの数はプレフィックス長に対して単調になります。 

次のように定義すると、`f(p) = number of distinct networks using the first p bits`それから`f(p)`決して減らない`p`成長します。 

この単調性により二分探索が可能になります。 33 個すべてのプレフィックス長をチェックする代わりに、ネットワーク数が少なくとも`k`。 

プレフィックスの長さが判明したら、カウントが正確であるかどうかを単純に検証します。`k`。 そうでない場合、解決策は存在しません。

 ## アルゴリズムのチュートリアル

 1. すべてのドット付き IP アドレスを 32 ビット整数に変換します。 

ビット単位の演算は、文字列よりも整数の方がはるかに簡単です。 
2. 関数を定義する`count_networks(p)`。 

この関数は最初のものだけを保持します`p`すべてのアドレスのビットを調べて、個別の結果がいくつ残っているかをカウントします。 
3. プレフィックス長の場合`p`、対応するマスクを構築します。 

もし`p = 0`、マスクはすべてゼロです。 

さもないと：`mask = ((1 << p) - 1) << (32 - p)`4. すべてのアドレスにマスクを適用し、結果をセットに挿入します。 

セットのサイズは、個別のネットワークの数と等しくなります。 
5.二分探索`p`から`0`に`32`。 

より多くのビットが保存されるため、ネットワークの数は決して減らないため、述語`count_networks(p) >= k`単調です。 
6. 最小のプレフィックス長を見つける`p`誰のために`count_networks(p) >= k`。 

これは、最も少ない 1 ビットを生成する候補です。 
7. コンピューティング`count_networks(p)`もう一度。 

結果が正確でない場合`k`、有効なサブネット マスクが存在しないため、出力します。`-1`。 
8. それ以外の場合は、対応するマスクを変換します。`p`ドット 10 進表記に戻して印刷します。 

### なぜ効果があるのか

 任意のプレフィックス長の場合`p`、2 つの IP アドレスが最初に割り当てられたときとまったく同じネットワークに属します。`p`ビットは同一です。 増加中`p`は追加ビットを使用してアドレスを区別するため、既存のグループは分割できますが、結合することはできません。 したがって、個別のネットワークの数は単調です。 

二分探索により、ネットワーク数が少なくとも次の値に達する最小のプレフィックス長が見つかります。`k`。 そのカウントが等しい場合`k`、プレフィックスの長さが小さくなるたびに生成されるマスクの数が 1 ビットよりも少なくなるため、最小の 1 ビットを持つ有効なマスクが見つかりました。`k`ネットワーク。 カウントがより大きい場合`k`、単調性はプレフィックス長が正確に生成できないことを意味します。`k`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ip_to_int(s):
    a, b, c, d = map(int, s.strip().split('.'))
    return (a << 24) | (b << 16) | (c << 8) | d

def mask_from_prefix(p):
    if p == 0:
        return 0
    return ((1 << p) - 1) << (32 - p)

def count_networks(ips, p):
    mask = mask_from_prefix(p)
    return len({ip & mask for ip in ips})

def int_to_ip(x):
    return ".".join(str((x >> shift) & 255) for shift in (24, 16, 8, 0))

def solve():
    n, k = map(int, input().split())

    ips = [ip_to_int(input()) for _ in range(n)]

    left, right = 0, 32

    while left < right:
        mid = (left + right) // 2

        if count_networks(ips, mid) >= k:
            right = mid
        else:
            left = mid + 1

    p = left

    if count_networks(ips, p) != k:
        print(-1)
        return

    print(int_to_ip(mask_from_prefix(p)))

solve()
```最初のヘルパーは、ドット表記を単一の 32 ビット整数に変換します。 これにより、文字列を操作する代わりにビット マスクを直接使用できるようになります。`mask_from_prefix`プレフィックス長に対応するサブネット マスクを構築します。 特別な場合`p = 0`そうでない場合、32 ビットによるシフトには特別な注意が必要になるため、これが必要です。`count_networks`すべてのアドレスにマスクを適用し、結果をセットに保存します。 そのセットのサイズは、まさに個別のネットワークの数です。 

二分探索では、ネットワーク数の単調性を利用します。 プレフィックス長がすでに少なくとも`k`ネットワークでは、プレフィックス長が長くても、少なくとも`k`, そこで左に移動します。 それ以外の場合は、右に進みます。 

二分探索が終了すると、カウントが次の値に達する最小のプレフィックス長が得られます。`k`。 カウントが未満からジャンプする可能性があるため、依然として等しいことを検証する必要があります。`k`直接より大きな値に`k`。 

最後に、マスクは 4 バイトを抽出することによってドット表記に変換されます。
