 ## 解決策
 ## 問題の理解

 各芝生には、個別の正の整数が含まれています。 2 つの芝生は、その数が原始的なピタゴラス トリプルで一緒に現れる場合、つながっているとみなされます。 

原始ピタゴラス トリプルは、以下を満たすペアごとに互いに素な整数のトリプルです。$x^2+y^2=z^2$「プリミティブ」という言葉が重要なのは、数値もペアごとに互いに素でなければならないためです。 

芝生なら`i`笑いを芝生に移すことができる`j`の場合、2 つの数値は 3 番目の整数とともに少なくとも 1 つのプリミティブ トリプルに属します。 笑いはそのような転移の連鎖によって広がるため、問題全体がグラフの問題になります。 

各芝生は頂点です。 

2 つの数値が原始ピタゴラス トリプルで一緒に出現できる場合は、それらの間にエッジを追加します。 

すべての芝生が最終的に笑いを得ることができるように、最初は笑われる芝生の数を最小限にする必要があります。 

これは、まさにこのグラフの連結成分の数です。 

制約こそが本当の課題なのです。 数値は最大 100 万個まで存在でき、値自体は 1,000 万個に達する場合があります。 すべてのペアをチェックするアルゴリズムはすぐに失敗します。 すべてのペアを 1 回繰り返すだけでも、おおよそ次のことが必要になります。$10^6 \cdot 10^6 = 10^{12}$4秒ではまったく不可能な操作です。 

グラフ自体も暗黙的です。 可能性が多すぎるため、単純に最大 1,000 万個のプリミティブ トリプルをすべて生成することはできません。 この解決策では、原始ピタゴラス トリプルの構造を非常に積極的に利用する必要があります。 

見落としやすいエッジケースがいくつかあります。 

単一の数字を考えてみましょう。```
1
2
```答えは`1`。 たとえその数値が、入力に存在しない数値を持つプリミティブ トリプルに参加できるとしても、それを別の既存の芝生に接続するのには役立ちません。 

もう 1 つの微妙なケースは、2 つの数値が両方とも偶数である場合です。```
2
6 8
```原始トリプルはペアごとに互いに素であるため、原始ピタゴラス トリプルには 2 つの偶数が含まれません。 正しい答えは、`2`。 

さらに危険な間違いは、すべての奇数が他のすべての奇数に接続されていると仮定することです。 例えば：```
3
3 5 15
```

`3`そして`5`つながっているので`(3,4,5)`原始的です。`15`どちらにも接続されていません。 すべての原始トリプルはペアごとの共素性を必要とし、`15`両方と要素を共有します`3`そして`5`。 正しい答えは、`2`。 

最後の重要な観察は、グラフが最初に見えるよりもはるかに密になっているということです。 大きな接続領域は、中間の数を介してすぐに現れます。 ペアごとの直接の特徴付けは困難ですが、プリミティブ トリプルの構造からは、非常に少数のグローバル コンポーネントが得られることがわかります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 入力数値のすべてのペアについて、それらが何らかの原始的なピタゴラス トリプルに一緒に現れることができるかどうかをテストします。 「はい」の場合は、DSU に接続します。 

問題はそれを効率的に決定することです。 

プリミティブ トリプルは Euclid の公式によって生成されます。$a=m^2-n^2,\quad b=2mn,\quad c=m^2+n^2$どこ`m > n`、`gcd(m,n)=1`、 そして`m-n`奇数です。 

ブルートフォース実装では、有効なものをすべて列挙する可能性があります。`(m,n)`ペアを作成し、トリプルを生成し、一緒に現れる入力数値を接続します。 これは、すべてのペアを直接チェックするよりもはるかに優れています。 

問題は規模だ。 値は 1,000 万に達するため、`m`それ自体はおおよそ次のようになります。$\sqrt{10^7} \approx 3162$すべての共素を列挙する`(m,n)`ペアは管理可能ですが、入力サイズが 100 万になると、生成されたすべてのトリプルを入力に接続するのに依然としてコストがかかります。 さらに重要なことは、グラフ理論の構造には、より強力な単純化が隠されていることです。 

重要な洞察は、プリミティブ トリプルが誘導する接続されたクラスはほんの一握りであるということです。 

任意の奇数を取得します`x`。 これは常にプリミティブ トリプルに現れます。$x^2+\left(\frac{x^2-1}{2}\right)^2=\left(\frac{x^2+1}{2}\right)^2$奇数の場合`x`、原始的な形式に書き換えられます。 特に、すべての奇数は何らかの偶数に接続されます。 

同様に、割り切れないすべての数は、`4`プリミティブトリプルに参加できます。 割り切れる数`4`追加のパリティ制約が成立しない限り、プリミティブ プリミティブ トリプルの脚として表示することはできません。 

生成されたグラフを注意深く観察すると、無限グラフ全体がちょうど 3 つの連結成分に分解されます。 

1. 割り切れる数`4`。 
2. 合同な数`2 mod 4`。 
3. 奇数。 

プリミティブ トリプルには常に 1 つの偶数と 2 つの奇数が含まれます。 偶数は次でなければなりません`2 mod 4`、決して割り切れない`4`。 つまり:

 - 奇数は、共有プリミティブ トリプルを通じて奇数と接続されます。 
- 数字`2 mod 4`奇数に接続します。 
- 割り切れる数`4`プリミティブ トリプルにはまったく参加しません。 

つまり、すべての奇数とすべての`2 mod 4`数値は 1 つの巨大なコンポーネントに属し、それぞれの倍数は`4`孤立している。 

これにより問題は完全に変わります。 グラフを明示的に構築する必要はなくなりました。 

答えは次のようになります。 

- 割り切れるすべての数値`4`1 つの独立したコンポーネントに寄与します。 
- 少なくとも 1 つのそのような数値が存在する場合、残りの数値はすべて一緒になって 1 つの追加コンポーネントに寄与します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(生成されたトリプルの数) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての数字を読みます。 
2. カウンタの初期化`isolated = 0`。 
3. ブール値を初期化する`has_non_isolated = False`。 
4. すべての数字について`x`:

 1. もし`x % 4 == 0`、増分`isolated`。 
2. それ以外の場合は設定します`has_non_isolated = True`。 

で割り切れる数`4`原始ピタゴラスの三重項に属することはできません。 そのような芝生は他の芝生から笑いを受け取ることができないため、それ自体が接続されたコンポーネントを形成します。 

他のすべての数値は同じ巨大コンポーネントに属します。 原始トリプルには常に、以下に一致する 1 つの数値が含まれます。`2 mod 4`そして 2 つの奇数。これにより、そのようなすべての値をチェーンで接続できるようになります。 

1. 最終的な答えは次のとおりです。```
isolated + (1 if has_non_isolated else 0)
```孤立していない番号が少なくとも 1 つある場合、それらのすべてに 1 つの開始芝生からアクセスできます。 

### なぜ効果があるのか

 原始ピタゴラス トリプルは厳密なパリティ構造を持っています。 

Euclid の構造を使用すると、次のようになります。$a=m^2-n^2,\quad b=2mn,\quad c=m^2+n^2$素数と`m,n`逆パリティの:

 -`a`そして`c`奇数です。 
-`b`で割り切れます`2`しかし、それによってではありません`4`。 

したがって、プリミティブ トリプルには、次で割り切れる数値が含まれることはありません。`4`。 

それはすぐに次の倍数になります`4`孤立した。 

次に、残りのすべての数値を検討します。 

- すべての奇数はいくつかの数字につながります`2 mod 4`プリミティブトリプルを介した数値。 
- 毎`2 mod 4`数字は奇数にもつながります。 
- 奇数のチェーンでセット全体を接続します。 

したがって、グラフには、自明ではない連結成分が 1 つだけ含まれているほか、孤立した複数の連結成分が含まれています。`4`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    isolated = 0
    has_other = False

    for x in a:
        if x % 4 == 0:
            isolated += 1
        else:
            has_other = True

    print(isolated + (1 if has_other else 0))

if __name__ == "__main__":
    solve()
```この実装は数学的特性を直接反映しています。 

ループは数値を 2 つのクラスに分割します。 

割り切れる数`4`孤立した頂点です。 原始的なトリプルにはそれらを含めることができないため、それぞれに独自の最初の笑いが必要です。 

1 つおきの数値は同じ連結成分に属します。 グループ全体で最初の笑いは 1 回だけ必要なので、コードは個別にカウントするのではなく、ブール値を使用してこれを追跡します。 

最後の式:```
isolated + (1 if has_other else 0)
```すべての数値が次で割り切れる場合を含め、すべてのケースを正しく処理します。`4`。 

よくある間違いは、数値をパリティだけで分類しようとすることです。 割り切れる数`4`～に一致する数とは根本的に異なる動作をする`2 mod 4`。 

もう 1 つの簡単なバグは、入力された数値が異なるものであることを忘れることです。 この証明は、位置間ではなく、値間のグラフの接続性に依存します。

# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    isolated = 0
    has_other = False

    for x in a:
        if x % 4 == 0:
            isolated += 1
        else:
            has_other = True

    print(isolated + (1 if has_other else 0))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# all multiples of 4
