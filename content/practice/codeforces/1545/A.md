[CF 1545A - AquaMoon と奇妙な並べ替え](https://codeforces.com/problemset/problem/1545/A)

 **評価:** 1500
 **タグ:** 並べ替え
 **解決時間:** 6分1秒
 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 私たちは友人の列を与えられ、それぞれが番号の付いたTシャツを着ています。 最初は友達全員が右を向いています。 AquaMoon は、隣接する 2 人の友達を交換することができ、そのたびに、両方の友達の向きが変わります。 目標は、一連の交換によって、T シャツの番号を降順でない順序に並べ替え、すべての友達が最終的に右を向くかどうかを判断することです。 

入力は複数のテスト ケースで構成されます。 それぞれについて、友達の数と、T シャツの番号のリストを受け取ります。 私たちの出力は、それぞれの場合において単純に「YES」または「NO」です。 

制約は重要です。`n`は最大 10^5 であり、合計は`n`すべてのテスト ケースにわたる は 10^5 です。 これは、テスト ケースごとに O(n log n) よりも悪いアルゴリズムは遅すぎる可能性があることを意味します。 二次解は問題外です。 また、スワップごとに方向が反転することも考慮する必要があるため、スワップのパリティを考慮せずに、通常の並べ替え規則を使用して配列が並べ替え可能かどうかを単純にチェックすることはできません。 

配列に繰り返し番号がある場合、微妙なエッジケースが発生します。 例えば、`[3, 3, 2, 2]`は最初はソートされていませんが、スワップには同じ値の数値が含まれる可能性があり、パリティ制約を満たすことができるため、ソートすることは可能です。 もう 1 つの注意が必要なケースは、最後の要素が他のすべての要素よりも小さいことを除いて、配列がほぼソートされている場合です。`[1, 2, 3, 5, 4]`。 このような場合、パリティと隣接性により並べ替えが成功しないため、答えは「いいえ」になります。 指示を無視する単純なアプローチでは、誤って「YES」が出力されてしまいます。 

## アプローチ

 ブルートフォースアプローチでは、方向を追跡しながら、すべての有効なスワップをシミュレートしようとします。 概念的には、バブルソートのような操作を実行できますが、スワップごとに方向を反転し、配列がソートされるまで繰り返すこともできます。 これは正しいですが、非常に非効率的です。 のために`n = 10^5`、バブル ソートでは、最悪の場合、最大約 10^10 の操作が必要になる可能性があり、これは実現可能性をはるかに超えています。 

重要な洞察は、スワップが両方向に反転することに気づくことです。 すべての友達が右を向いている状態で開始し、1 回交換した後、交換した 2 人の友達は左を向きます。 どちらかが関与する 2 回目の交換の後、方向は右に戻ります。 これは、方向が各要素が参加するスワップ数のパリティによって完全に決定されることを意味します。すべての要素が最終的に右を向くためには、各要素が偶数のスワップに参加する必要があります。 

値のパリティによって配列要素を分類できます。より具体的には、要素がすでに完全にソートされた配列に対して「偶数インデックス」位置にあるか「奇数インデックス」位置にあるかによって、配列要素を分類できます。 重要な点は、配列を奇数のインデックスの数値と偶数のインデックスの数値に分割でき、奇数の位置にある数値が、元々偶数の位置にあり、それらを通過する必要がある数値より決して小さくならない場合、ソートが可能であるということです。 より単純な実際的な観察は、パリティ制約はスワップによって修正できないため、最終位置で左側の大きい数値の直後に右側の小さい数値が続くという局所的な反転が存在しない限り、ソートは常に可能であるということです (特に最後の要素に影響します)。 

実際には、これは単純なチェックになります。最小の数値が最大の数値より小さく、奇数の距離を移動しないと解決できない場合、並べ替えは不可能です。 具体的には、配列に偶数と奇数の両方が含まれているかどうかを確認することで取得されます。 配列に偶数のみまたは奇数のみが含まれている場合、一部の反転は偶数スワップでは修正できず、「いいえ」になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テストケースについて、友人の数を読み取ります。`n`そしてTシャツの番号の配列。 
2. 参照用に配列のソートされたコピーを作成します。 
3. 元の配列に少なくとも 1 つの偶数と 1 つの奇数が含まれているかどうかを確認します。 これにより、パリティ スワップが可能かどうかが決まります。 
4. 偶数と奇数の両方が存在する場合は、「YES」を出力します。 それ以外の場合は、「NO」を出力します。 

その理由は、スワップは常に方向を反転させるということです。 偶数と奇数が混在している場合は、配列がソートされるときに最終的にすべての要素が右を向くように、常にスワップを整理できます。 すべて偶数またはすべて奇数の配列は、パリティ制約により特定の位置で失敗する可能性があり、ソート後に一部の要素が正しい方向に戻らなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        even = any(x % 2 == 0 for x in a)
        odd = any(x % 2 == 1 for x in a)
        if even and odd:
            print("YES")
        else:
            sorted_a = sorted(a)
            if a == sorted_a:
                print("YES")
            else:
                print("NO")

if __name__ == "__main__":
    main()
```この解決策では、まず偶数と奇数の両方が存在するかどうかを判断します。 そうであれば、いつでも並べ替えが可能です。 そうでない場合は、配列がすでにソートされているかどうかをチェックします。 これにより、次のような特殊なケースが捕捉されます`[2, 2, 2]`スワップが必要ない場合。 よくある間違いは、均一パリティでソート済みの配列のチェックを省略することです。これにより、誤って「NO」が返されます。

 ## 特殊なケース

 のような配列の場合`[2,2,2]`、アルゴリズムは、すべての数値が偶数であるが、すでに並べ替えられていると識別します。 ソートされた配列のチェックは正しく「YES」を返します。 のために`[3,1,5]`、すべての数値は奇数であり、並べ替えられていません。 パリティ制約によりスワップによる全方向の修正が妨げられ、正確性が確認されるため、アルゴリズムは「NO」を返します。 のために`[1,2,3,5,4]`、偶数と奇数の組み合わせにより、配列をソートし、すべての方向を右に戻す一連のスワップが確実に存在します。 このソリューションでは、「YES」が正しく出力されます。
