 ## 解決策
 ## 問題の理解

 長さのバイナリ文字列が与えられます$n$、各ポジションにはポーンが含まれるか空のいずれかです。 ボードはラインであり、ポーンは非常に制限された方法でのみ移動できます。ポーンは 2 つのセルを左右に「ジャンプ」できますが、これは中間のセルが占有されており、目的地のセルが空の場合に限られます。 

この制限により、移動はローカルで隣接関係に依存するため、ポーンは独立して移動しません。 代わりに、これらは、非常に特殊な意味で接続を維持する必要があるグループのように動作します。つまり、移動では、常に 3 つの連続するセルの小さなウィンドウ内で交互に占有されるパターンが維持されます。 

タスクは、動きをシミュレートすることではなく、有効な動きのシーケンスの下で、初期構成から開始して、ポーンの異なる構成が何回出現するかをカウントすることです。 占有セルが異なる場合、2 つの構成は異なるものとみなされます。 

制約が非常に厳しいため、状態グラフの探索は不可能です。 合計あり$n$まで$10^5$テスト ケース全体では、テスト ケースごとの線形 BFS でさえすでに境界線に達しており、ポーンや構成の数が指数関数的に増加することは直ちに実行不可能になります。 

微妙な点は、この動きは弱い意味で可逆的であるということです。対称的な構成では、左ジャンプを右ジャンプで元に戻すことができますが、常に直接元に戻せるわけではありません。 これにより、構成グラフ内に任意ではなく高度に構造化された接続コンポーネントが作成されます。 

典型的な間違いは、ポーンを独立して扱ったり、ローカルな再配置が可能であると想定したりすることです。 たとえば、から始めて、`0110`、隣接する 2 つの順列がすべて到達可能であると誤って考える人もいるかもしれませんが、実際にはパリティを保持する特定の構成のみが有効です。 

2 番目によくある失敗は、状態を動的に拡張して、動きの貪欲なシミュレーションを試みることです。 小さいものでも$n$、到達可能な状態の数は 1 のクラスター領域で組み合わせ的に増加するため、これはすぐに爆発します。 

## アプローチ

 ブルート フォース アプローチでは、ビットマスク上の BFS または DFS を使用して、到達可能なすべての構成を明示的にシミュレートします。 それぞれの状態は、$n$-ビット文字列であり、各状態はローカル移動を通じて複数の近傍を生成する可能性があります。 最悪の場合、州の数が指数関数的に増加する可能性があります。$n$というのは、それぞれの動きによって分岐構成が作成される可能性があり、単純な方法で成長を制限する単調ポテンシャル関数がないためです。 それぞれの状態がただ生成したとしても$O(n)$遷移が起こるずっと前に、状態空間自体がボトルネックになります。$n=100$。 

重要な観察は、移動ルールが実際には恣意的な再配置を作成しないということです。 ポーンの動きは、3 つの連続するセルのローカル パターンにのみ依存し、重要なことに、すべての動きはポーンの数を保存し、隠された構造も保存します。構成は、ゼロで区切られた独立したセグメントに分解できますが、連続したブロックという単純な意味では分解できません。 代わりに、関連する構造は、連続するセグメントの最大セグメント内のパリティとペアリングに基づいています。 

連続するセグメントの最大セグメントの内部で、重要なのは、隣接するセグメントの互いに素な「ペア」がいくつ存在するかです。 各移動は、そのようなペア間でポーンを効果的にシフトします。つまり、内部自由度は、どのペアが「シフト」に参加し、どのペアが固定のままかを選択することに対応します。 これにより、各セグメントがその長さと内部構造に基づいて二項タイプの因子に寄与する組み合わせ計数問題が発生します。 

より正確には、連続した長さのブロックの各最大ブロック$L$contributes a number of reachable configurations equal to a Fibonacci-like count that arises from choosing which adjacent pairs can be “activated” without overlap. The independence between blocks follows from zeros acting as hard separators: no move can cross a zero, so blocks evolve independently and their contributions multiply.

 これにより、状態にわたるグラフの到達可能性の問題から、既知の組み合わせ量のセグメントにわたる積までの問題が軽減されます。

 ## アルゴリズムのチュートリアル

 1. 文字列をスキャンし、次のもののみで構成される最大の連続セグメントに分割します。`'1'`。 ゼロはセグメント間の相互作用をブロックするため、このような各セグメントは独立しています。 これにより、問題は各セグメントを個別に解決することになります。 
2. 長さの各セグメントについて$L$、事前に計算された動的反復を使用して、答えへの寄与を計算します。 反復は、最初の 2 つが「固定ペア」を形成しているのか、それとも可能性のある動きによって引き起こされるギャップのような構成で構造が始まっているのかを検討することで生じます。 
3. 定義する$dp[i]$ある長さのセグメント内で到達可能な構成の数として$i$。 のために$i < 2$、移動が不可能なため、値は自明です。 大型の場合$i$、遷移は、移動が境界で効果的に使用されるかどうかに応じて、左端の構造が最初のペアをロックするか、前方にスキップするかのいずれかを反映します。 これは、フィボナッチの成長と同じ線形回帰をもたらします。 
4. 事前計算$dp[i]$最大まで$n$すべてのテスト ケースにわたって、各セグメントを一定時間で評価できるようにします。 
5. すべてのセグメントの寄与を剰余で乗算します。$998244353$テストケースの最終的な答えを得るために。 

### なぜ効果があるのか

 重要な不変条件は、移動がゼロで区切られた異なるセグメントを決して混合しないこと、およびセグメント内では、到達可能な構成はチェーン状に伝播するローカル隣接パターンのみに依存することです。 セグメントから到達可能なすべての設定は、各内部隣接がスワップ チェーンに参加するか、固定されたままであるかの選択によって一意に記述することができます。 これにより、到達可能な状態と線形構造に沿った有効な二値決定の間の全単射が誘発されます。これはまさにフィボナッチ回帰がカウントするものです。 

どの移動もセグメントを分割したり 2 つのセグメントをマージしたりできないため、分解はすべての操作にわたって安定しており、独立性により乗法性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def build_dp(n):
    if n == 0:
        return []
    dp = [0] * (n + 1)
    dp[0] = 1
    if n >= 1:
        dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = (dp[i - 1] + dp[i - 2]) % MOD
    return dp

def solve():
    t = int(input())
    arr = []
    strings = []

    max_n = 0
    for _ in range(t):
        n = int(input())
        s = input().strip()
        strings.append(s)
        max_n = max(max_n, n)

    dp = build_dp(max_n)

    for s in strings:
        ans = 1
        n = len(s)
        i = 0
        while i < n:
            if s[i] == '0':
                i += 1
                continue
            j = i
            while j < n and s[j] == '1':
                j += 1
            length = j - i
            ans = (ans * dp[length]) % MOD
            i = j
        print(ans)

if __name__ == "__main__":
    solve()
```すべてのセグメントがクエリを実行するため、コードは最初に最大入力サイズまでフィボナッチ スタイル テーブルを構築します。 これにより、テスト ケースごとに動的値を再計算する必要がなくなります。 

次に、テスト ケースごとに文字列をスキャンし、連続するブロックの最大のブロックを抽出します。 各ブロックは事前計算された値にマッピングされ、最終的な答えはすべてのブロックの寄与の積になります。 

重要な実装の詳細は正しいセグメンテーションです。ゼロはブロック境界を完全にリセットする必要があります。そうしないと、2 つの独立した構造が計算で誤って相互作用します。 

## 実用的な例

 ### 例 1:`0110`文字列を単一のブロックに分解します`11`長さ 2 で、ゼロで囲まれています。 

| ステップ | セグメント | 長さ | dp[長さ] | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | 「11」 | 2 | 2 | 2 |

 最終的な答えは 2 です。 

これは、2 つの隣接するポーン内に、元の配置と、許可された移動制約によって引き起こされる交換された構造という、到達可能な安定した構成が 2 つだけ存在するという事実と一致します。 

### 例 2:`01010`これは、2 つの独立したシングルポーン セグメントに分解されます。`"1"`そして`"1"`。 

| ステップ | セグメント | 長さ | dp[長さ] | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | "1" | 1 | 1 | 1 |
 | 2 | "1" | 1 | 1 | 1 |

 最終的な答えは、$1 \cdot 1 = 1$。 

隣接するペアがないため移動はできず、構成は固定されます。 

これらの例では、ゼロで区切られたセグメント間の独立性と実行内のローカルな組み合わせ構造の両方が正しくキャプチャされていることを確認します。

def solve():
    input = sys.stdin.readline

        n = int(input())
        s = input().strip()
        ns.append(n)
        ss.append(s)

    dp = [0] * (max_n + 1)
    dp[0] = 1
    if max_n >= 1:
        dp[1] = 1
    for i in range(2, max_n + 1):
        dp[i] = (dp[i-1] + dp[i-2]) % MOD

            if s[i] == '0':

 ## 特殊なケース

 完全に空のボードのような`0000`はセグメントを生成しないため、積は 1 のままです。スキャンは決してセグメントに入らないため、アルゴリズムはこれを自然に処理します。`'1'`ブロックし、最初の答えを変更せずに返します。 

次のような単一の長いブロック`111111`再発を直接テストします。 DP はセグメント化を行わずに完全なフィボナッチ スタイルの成長を評価し、結果は完全に次から取得されます。`dp[n]`。 スキャンは 1 つのセグメントを識別し、正確に 1 つの係数を乗算します。 

次のような高度に断片化された入力`1010101`セグメント間の独立性が確実に保たれるようにします。 それぞれ`'1'`は長さ 1、値 1 のセグメントになるため、乗算しても答えは変わりません。 各ゼロは実行を直ちに終了するため、アルゴリズムはゼロをまたぐマージを正しく回避します。 

これらのケースでは、完全な分離と完全な接続という両極端が、特別なケースを使用せずに同じセグメント化メカニズムによって均一に処理されることが確認されています。
