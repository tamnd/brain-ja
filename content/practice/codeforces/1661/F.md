 ## 解決策
 ## 問題の理解

 数直線上のソートされた点のシーケンスが与えられます。位置 0 から始まり、その後に位置が続きます。$a_1, a_2, \dots, a_n$、 どこ$a_n$最終目的地です。 これらの位置はテレポート ステーションとして機能します。 どのステーションからでも他のステーションに直接ジャンプできます。また、そこからのジャンプのコストは$x$に$y$は距離の二乗、$(x-y)^2$。 

選択した整数座標に追加のテレポーテーション ステーションを追加することができます。 それらを追加した後は、0 から$a_n$合計コストが以下の一連のテレポーテーションを使用する$m$。 目標は、追加するステーションの数を最小限に抑えることです。 

重要な構造は、すべての元のステーションが固定およびソートされており、大きなギャップをより小さなギャップに分割することでジャンプ コストを削減するために、中間の整数点のみを挿入できるということです。 コストは距離に応じて二次関数的に増加するため、ロングジャンプはいくつかの小さなジャンプに比べて非常に高価です。 

制約は大きく、最大で$2 \cdot 10^5$ポイントと値は最大$10^9$、までのエネルギーで$10^{18}$。 これにより、パスをシミュレートしたり、すべての点のペアを考慮したりするソリューションは即座に除外されます。 二次関数の動作でも、$n$それは不可能であるため、正しい解決策は、問題を、連続する指定された点の間のセグメントにわたる推論に圧縮する必要があります。 

単純な考えでは、すべてのギャップにポイントを挿入するすべての方法を検討し、可能な限り最適なパスを再計算することになりますが、挿入された各ポイントによって将来のすべての移行コストが変化するため、これは爆発的に発生します。 もう 1 つの誤解を招きやすい方向は、各ギャップを個別に最小化することを貪欲に行うことです。これは失敗します。最適なパスは、ローカルの最適化ではなく、セグメント長のグローバルな分布に依存するためです。 

1 つの大きなギャップが総コストを支配する場合、微妙なエッジ ケースが発生します。 たとえば、ポイントがある場合$[0, 10^9]$そして小さい$m$、セグメントが 1 つしかなく、そこに挿入するポイントの数を決定する必要があるため、中間の小さなギャップについてはどれだけの推論も当てはまりません。 逆もまた厄介です。多くの小さなギャップは個別には安く見えますが、適切にバランスが取れていないと、集合的には長く高価なジャンプを強いられることになります。 

## アプローチ

 挿入された点の制約を無視すると、問題は 0 から 0 までの最も安価なパスを評価することになります。$a_n$ここでは、指定されたノードのみを使用できます。 それは簡単なことです。0 から 2 まで直接進みます。$a_n$費用がかかる$a_n^2$。 この二次関数のコストを削減するために中間ノードを挿入できるため、この問題はさらに興味深いものになります。 

ブルートフォース解釈では、連続する指定されたポイント間の各ギャップに挿入するポイントの数を決定し、その結果の最適なパス コストを計算します。 長さのギャップがある場合$d$に分かれています$k+1$二乗コストを最小限に抑える最善の方法は、ポイントを均等に分散し、各セグメントの長さを約$d/(k+1)$。 そのギャップのコスト寄与はおよそ次のようになります。$(k+1) \cdot (d/(k+1))^2 = d^2/(k+1)$。 これはすでに構造を示唆しています。ポイントを挿入すると、作成するセグメントの数に反比例してコストが削減されます。 

ただし、挿入されたポイントのブルートフォース割り当ては、$n$ギャップは不可能です。 たとえそれぞれのギャップに選択肢がわずかしかなかったとしても、組み合わせが爆発的に広がります。$2 \cdot 10^5$ギャップは不可能です。 

重要な観察は、コスト関数が分割数に関してスムーズに動作するということです。 追加の挿入ポイントごとにわずかな利点が得られますが、ギャップがより細かくなると利点は減少します。 これにより、各ギャップに値するポイント数の貪欲な割り当てと組み合わせて、挿入されたポイントの数またはコストしきい値を超えるグローバル バイナリ サーチが可能になります。 

追加するポイントの数を直接決定する代わりに、問題を逆にします。セグメントあたりの目標最大コストを仮定し、すべてのギャップがこの制約を確実に遵守するために必要な挿入ポイントの数を計算します。 総エネルギーが範囲内に収まる場合$m$、その推測は実現可能です。 

これにより、問題は単調な実現可能性チェックに変換され、まさに二分探索が利用するものになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ギャップごとのブルートフォース割り当て | 指数関数 | O(n) | 遅すぎる |
 | セグメントごとのコスト + 欲張り分割の二分探索 |$O(n \log 10^{18})$| お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 パスを、0 と 0 を含む、連続する元の点の間のセグメントのシーケンスとして再解釈します。$a_n$。 各セグメントの長さ$d$点を挿入することで分割できます。 

1. 配列をエンドポイントで拡張し、次のように扱います。$p_0 = 0, p_1 = a_1, \dots, p_n = a_n$。 分割が最適化されれば、最適なパスは中間点を不必要にスキップすることがないため、連続した差分のみを考慮します。 
2. 挿入ポイントの候補数については、それらをセグメント全体に分散します。 問題は、総コストが範囲内に収まるように各セグメントを何回分割する必要があるかになります。$m$。 

長さのセグメント$d$に分割する$k+1$等しい部分がコストに比例して寄与する$d^2/(k+1)$。 スプリットを追加する利点は減少するため、最大のセグメントにスプリットを貪欲に割り当てることが最適です。 
3. セグメントごとの最大許容貢献しきい値で二分検索を実行します。$T$。 固定の場合$T$、コストが最大で以下になるように、各セグメントで必要な分割の数を計算します。$T$。 

ある長さのセグメントの場合$d$、次のものが必要です。$$\frac{d^2}{k+1} \le T \Rightarrow k+1 \ge \frac{d^2}{T}$$したがって、挿入されたポイントの数は$\max(0, \lceil d^2/T \rceil - 1)$。 
4. すべてのセグメントにわたって必要な挿入ポイントを合計します。 合計額が、暗示される許容予算の範囲内である場合、$m$、 それから$T$実現可能です。 
5. 実行可能な最小値を二分探索します$T$を計算し、そこから必要な挿入テレポーターの最小数を推定します。 

なぜこれが機能するかというと、実行可能条件と必要な分割数の両方が単調であるためです。$T$。 増加中$T$制約を緩和し、必要な挿入を増やすことはありません。 

### なぜ効果があるのか

 不変条件は、均一なコストしきい値を固定すると、各セグメントが独立して最適化されるということです。 二乗距離は凸であるため、セグメントを均等に分割すると、固定数の挿入ポイントの総コストが最小限に抑えられます。 これによりセグメント間の相互作用が排除され、異なるギャップ間でインサートを再配置する必要がないため、総分割数を変えることなく総コストを向上させることができます。 次に、二分探索では単調性が利用されます。つまり、許容コストが高くなると常に制約が弱くなり、決して強化されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def required_inserts(length, max_cost):
    # need (k+1) segments so that length^2/(k+1) <= max_cost
    # => k+1 >= length^2 / max_cost
    # => k >= ceil(length^2 / max_cost) - 1
    if length == 0:
        return 0
    need_segments = (length * length + max_cost - 1) // max_cost
    return max(0, need_segments - 1)

n = int(input())
a = list(map(int, input().split()))
m = int(input())

p = [0] + a

def can(max_cost):
    total = 0
    for i in range(1, len(p)):
        d = p[i] - p[i - 1]
        total += required_inserts(d, max_cost)
        if total > m:
            return False
    return True

lo, hi = 1, (p[-1] * p[-1])  # upper bound on cost per segment
ans_cost = hi

while lo <= hi:
    mid = (lo + hi) // 2
    if can(mid):
        ans_cost = mid
        hi = mid - 1
    else:
        lo = mid + 1

print(ans_cost)
```コードはまず、開始点として 0 を含む連続したギャップを処理するように問題を変換します。 ヘルパー関数は、セグメントが特定のコストしきい値を確実に遵守するために必要なポイント数を計算します。これは不等式から直接導出されます。$d^2/(k+1) \le T$。 

実現可能性チェックでは、すべてのセグメントにわたって必要な挿入が蓄積され、テレポーターの許容数を超えないことが保証されます。 次に、二分探索により、達成可能な最小のセグメントごとのコスト限界が見つかります。 

微妙な点は、上限を計算するときに浮動小数点エラーを避けるために整数演算を慎重に使用することです。 表現`(length * length + max_cost - 1) // max_cost`これを安全に処理します。 

## 実用的な例

 ### サンプル 1

 入力:```
n = 2
a = [1, 5]
m = 7
```ポイントを構築します:$0, 1, 5$。 セグメントの長さは 1 と 4 です。 

コスト閾値で二分探索を行います$T$。 候補者をテストするとします$T$:

 | セグメント | 長さ d | d² | 必要なセグメント | インサート |
 | --- | --- | --- | --- | --- |
 | 0→1 | 1 | 1 | 1 | 0 |
 | 1→5 | 4 | 16 | T に依存します | さまざまです |

 のために$T = 8$:

 | セグメント | d²/T | セグメント | インサート |
 | --- | --- | --- | --- |
 | 1 | 0.125 | 1 | 0 |
 | 4 | 2 | 2 | 1 |

 総挿入数 = 1 ≤ 7、実現可能。 

小さめの場合$T$、さらに多くの分割が必要です。 二分探索により、実行可能な最小しきい値が見つかります。 

これは、大きなギャップが分割割り当てをどのように支配するかを示しています。

 入力:```
n = 3
a = [2, 3, 10]
m = 3
```ポイント: 0、2、3、10、ギャップ 2、1、7。 

のために$T = 10$:

 | セグメント | d | d² | 必要なセグメント | インサート |
 | --- | --- | --- | --- | --- |
 | 2 | 2 | 4 | 1 | 0 |

 | セグメント | d | d² | 必要なセグメント | インサート |

 合計挿入数 = 2 ≤ 3、実現可能。 

二分探索はそのような最小のものに収束します$T$。

def run(inp: str) -> str:

def main():

    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    m = int(input())

    p = [0] + a

    def required_inserts(length, max_cost):
        if length == 0:
            return 0
        need_segments = (length * length + max_cost - 1) // max_cost
        return max(0, need_segments - 1)

            total += required_inserts(d, max_cost)

            hi = mid - 1

 ## 特殊なケース

 重大なエッジケースは、入力などの大きなギャップが 1 つだけある場合です。```
n = 1
a = [10^9]
m small
```ここで問題全体は、単一セグメントの分割に帰着します。 このアルゴリズムは、ループが 1 つの差異のみを処理し、二分探索によってそのセグメントのみに必要な分割の数を決定するため、これをきれいに処理します。 

もう 1 つのケースは、次のようなすべてのポイントが連続している場合です。```
a = [1,2,3,4,5]
```すべてのギャップは 1 であるため、インサートがなくてもコストはすでに最小限です。 機能`required_inserts`小さなセグメントの場合はゼロを返します。$d^2$二分探索中にすでに妥当なしきい値を下回っています。 

最後に、いつ$m$が非常に大きい場合、二分探索は挿入が不要な自明な解にすぐに収束します。これは、非常に大きい場合でも実現可能性チェックに合格するためです。$T$結果として、すべてのセグメントにわたって必要な分割はゼロになります。
