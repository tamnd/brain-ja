 ## 解決策
 ## 問題の理解

 あらゆるポジションで`i`、値のペアがあります`(a[i], b[i])`。 許可される唯一の操作は、同じペア内の 2 つの値を交換することです。 これはどのポジションに対しても独立して行うことができます。 

どのペアを交換するかを選択した後、最終的な配列を取得します`a`そして`b`。 コストは、最初の配列内の隣接する要素間の絶対差と 2 番目の配列内の同じ数量の合計です。$$\sum_{i=1}^{n-1} \left(|a_i-a_{i+1}| + |b_i-b_{i+1}|\right)$$課題は、このコストを最小限に抑えることです。 

重要な観察は、位置の交換が行われていることです。`i`ペアにのみ影響します`(a[i], b[i])`。 他のインデックスの値を変更することはありません。 目的には隣接するインデックスのペアのみが含まれるため、位置の寄与は`i`そして`i+1`配列の残りの部分から独立して分析できます。 

制約は驚くほど小さいです。 各配列の長さは最大 25 ですが、テスト ケースは最大 4000 個存在する可能性があります。 各ポジションには 2 つの選択肢があるため、すべてのスワップ構成に対するブルート フォース検索は依然として不可能です。`2^n`構成。 のために`n = 25`つまり、テスト ケースごとに 3,300 万以上の可能性があります。 

よくある間違いは、さまざまな立場での意思決定がグローバルに相互作用し、動的プログラミングが必要であると考えることです。 彼らは相互作用しますが、その相互作用は非常にローカルなものです。 コスト関数の構造を理解すると、隣接する各ペアを個別に最適化できます。 

考慮する：```
a = [1, 10]
b = [10, 1]
```スワップなしの場合のコストは、$$|1-10|+|10-1|=18.$$1 つの位置を交換すると、```
a = [1,1]
b = [10,10]
```費用がかかる`0`。 

「いつでも交換」などの貪欲なルール`a[i] > b[i]`」は、目的が個々のペア自体ではなく隣接する位置に依存するため、多くの例で失敗します。 

値がすでに順序付けされている場合には、別の微妙なケースが発生します。```
a = [1,2,3]
b = [6,7,8]
```どのような交換でも、小さな数字と大きな数字が混合されるだけであり、隣接する差分が増加します。 何もせずに最適な答えが得られます。 実際の寄与をチェックせずに常にペアを正規化するアルゴリズムでは、より大きなコストが発生する可能性があります。 

## アプローチ

 最も直接的な解決策は、すべてのスワップ構成を試してみることです。 各位置は変更しないままにすることも、交換することもできます。`2^n`可能性。 構成ごとに、結果として生じるコストを次のように計算できます。`O(n)`時間。 

ブルートフォース方式は、考えられるすべての最終状態を明示的にチェックするため、正しい方法です。 問題は探索空間のサイズです。 のために`n = 25`、おおよそ必要になります$$2^{25} \approx 3.3 \times 10^7$$単一のテスト ケースの構成は、制限時間の範囲をはるかに超えています。 

より良いものを見つけるには、目標の 1 つの用語に注目してください。$$|a_i-a_{i+1}| + |b_i-b_{i+1}|.$$ポジションのみ`i`そして`i+1`この表現に出てきます。 ペアを所定の位置に配置する`i`なれ`(x,y)`そしてその位置のペア`i+1`なれ`(u,v)`。 

これら 2 つの位置については、次のいずれかの方向を選択できます。```
(x,y) or (y,x)
(u,v) or (v,u)
```常に小さい値が最初になるように各ペアを並べ替えるとします。$$l_i = \min(a_i,b_i), \qquad r_i = \max(a_i,b_i).$$次に、隣接する位置の寄与を考慮します。$$|l_i-l_{i+1}| + |r_i-r_{i+1}|.$$他の方向性の方が良いでしょうか?

 2 つのペアの場合、可能性があるのは次のとおりです。$$|x-u|+|y-v|$$または$$|x-v|+|y-u|.$$この行の標準的な不等式は、小さい値を一緒に一致させたり、大きい値を一緒に一致させたりすることは、接続を交差させることより悪いことは決してないことを示しています。$$|x-u|+|y-v| \le |x-v|+|y-u|$$いつでも$x \le y$そして$u \le v$。 

各ペアを内部でソートした後、隣接するすべての寄与が個別に最小化されます。 合計の目的は隣接するすべての寄与の単純な合計であるため、すべてのペアを 1 回ソートすることが全体的に最適です。 

解決策は非常に簡単になります。すべてのペアを次のように置き換えます。`(min, max)`、最終的なコストを計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・2^n) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ポジションごとに`i`、ペアを交換します`(a[i], b[i])`と`(min(a[i], b[i]), max(a[i], b[i]))`。 

これにより、この位置に関係する今後のすべての隣接寄与を最小化する方向が修正されます。 
2. に対する答えを初期化します。`0`。 
3. 隣接するインデックスのペアごとに`i`そして`i+1`、 追加$$|a_i-a_{i+1}| + |b_i-b_{i+1}|$$答えに。 

ステップ 1 の後、これらの配列はすでにすべてのペアの最適な方向を表しています。 
4. 累計を出力します。 

### なぜ効果があるのか

 隣接するインデックスについては、$$x=\min(a_i,b_i), \quad y=\max(a_i,b_i),$$そして$$u=\min(a_{i+1},b_{i+1}), \quad v=\max(a_{i+1},b_{i+1}).$$これら 2 つの立場の貢献度は次のいずれかです。$$|x-u|+|y-v|$$または$$|x-v|+|y-u|.$$以来$x \le y$そして$u \le v$、小さい値同士や大きい値同士のペアは、交差ペアよりも大きくなることはありません。 したがって、ソートされた方向により、この隣接するペアの寄与が最小限に抑えられます。 

合計の目標は、そのような隣接する貢献の合計です。 各項は同じローカル選択、つまりすべてのペアの小さい要素を最初の配列に配置し、大きい要素を 2 番目の配列に配置することによって最小化されます。 すべての項が同時に最小化されるため、全体の合計が最小化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        for i in range(n):
            if a[i] > b[i]:
                a[i], b[i] = b[i], a[i]

        ans = 0
        for i in range(n - 1):
            ans += abs(a[i] - a[i + 1])
            ans += abs(b[i] - b[i + 1])

        print(ans)

solve()
```最初のループはすべてのペアを正規化します。`a[i] <= b[i]`。 これが重要な貪欲なステップです。 その変換後、隣接するすべての寄与はすでに最適な形になっています。 

2 番目のループでは、定義どおりに目的を正確に計算します。 答えは 32 ビット整数の制限を超える可能性があるため、Python 整数を使用すると、オーバーフローの問題が自動的に回避されます。 

よくある実装上の間違いは、すべてのスワップを実行する前に答えを計算してしまうことです。 証明は、すべてのペアが最初に正規化されることに依存します。 もう 1 つの間違いは、コントリビューションに一方だけではなく両方の配列が含まれていることを忘れていることです。
