 ## 解決策
 ## 問題の理解

 配列が与えられています`b`長さの`n`、各要素は、対応する配列内で到達するか超える必要がある目標値を表します。`a`。 当初は、`a`すべてゼロで構成されます。 次の操作は何度でも実行できます。次の長さの連続した部分配列を選択します。`k`そして増加シーケンスを追加します`1, 2, ..., k`そのサブ配列に。 目標は、必要な操作の最小数を決定して、すべての要素が`a`少なくとも対応する要素です`b`。 

制約は次のことを教えてくれます`n`と同じ大きさにすることができます`3 * 10^5`そしてそれぞれ`b_i`まで到達できます`10^12`。 これにより、単純なアプローチでは潜在的に何兆もの操作が必要となるため、各操作を個別にシミュレートしたり、多数の操作を反復したりするアルゴリズムは即座に除外されます。 

ここでのエッジケースは微妙です。 もし`k = 1`、各操作では 1 つの要素のみが増分されます。`1`したがって、答えは単純です。`max(b)`。 もし`k = n`の場合、各操作はすべての要素に影響しますが、増分は重み付けされます (`1, 2, ..., n`)、したがって、末端から貪欲に操作を分散することが最適である可能性があります。 もう 1 つの注意が必要なケースは、必要なデータとデータの間に大きなギャップが生じた場合に発生します。`b_i`値 - 不注意なアプローチでは、等差数列の重複を無視して演算を過小評価する可能性があります。 

たとえば、次のように考えてみましょう`n=3`、`k=2`、`b=[3,1,2]`。 単純なアプローチでは、位置 2 から始まる進行を追加することが 3 番目の要素にも影響することを考慮せずに、各要素を個別に上げようとする可能性があります。 

## アプローチ

 ブルートフォース手法では、配列を左から右に反復処理します。 それぞれのポジションで`i`かどうかを確認します`a[i] < b[i]`。 そうであれば、次から始まる十分な操作を適用します。`i`満足させる`b[i]`。 各操作が更新されます`k`要素、追加`1, 2, ..., k`。 このアプローチは論理的には機能しますが、操作ごとに配列を明示的に更新すると時間がかかりすぎます。 最悪の場合、`n = 3*10^5`そして`b_i`まで`10^{12}`、操作の数に制限がないため、明示的なシミュレーションは実行できません。 

重要な洞察は、配列を要素ごとに更新する必要がないということです。 「差分配列」を維持することも、遅延伝播のようなアプローチを使用することもできます。つまり、ローリング方式で以前の操作の累積効果を追跡します。 各演算は等差数列であるため、将来の要素への影響は増分と傾きとして表現できます。 各インデックスでの傾きの変化と現在の累積効果を保存するだけでよいため、実際にすべてを更新しなくても、各ステップで必要な追加操作の数を計算できます。`k`要素を明示的に。 

配列を左から右に処理することで、前の操作の累積的な影響を維持します。`current_add`そしてその斜面は`slope_add`。 いつでも`a[i] + current_add`未満です`b[i]`、位置に適用する新しい操作の数を計算します。`i`満足させる`b[i]`。 これにより、後の操作は前の操作と重複するため、最小限の操作が保証され、不足分は常に最適にカバーされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * b_max) | O(n) | 遅すぎる |
 | 最適 (プレフィックスの違いで貪欲) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`slope`長さの`n+1`ゼロ付き。 この配列は、以前の操作からの勾配の累積効果を追跡します。 初期化もする`current_add = 0`そして`operations = 0`。 
2. 各インデックスを反復処理します。`i`から`0`に`n-1`。 位置での実効値を計算します`i`として`effective = current_add`。 もし`effective < b[i]`、必要な新しい操作の数を次のように計算します。`needed = b[i] - effective`。 
3. インクリメント`operations`による`needed`。 
4.アップデート`current_add`追加することで`needed`。 
5. もし`i + k < n`、デクリメント`current_add`による`needed * k`位置にある`i+k`勾配配列内。 これにより、スロープ効果が持続するのは次のとおりです。`k`ポジション。 
6. を追加して傾きも伝播します。`needed`に`slope[i+1]`次のインデックスのために。 傾斜配列により、現在のウィンドウ内の位置の増分加算が正しく適用されることが保証されます。 
7. 次のインデックスに移動して更新します`current_add`追加することで`slope[i]`進行中の傾斜の寄与を考慮するため。 

なぜ機能するのか: 不変条件は各インデックスで`i`、`current_add`影響を与えるすべての操作の合計貢献度を反映します`a[i]`。 現在の合計が到達するには不十分な場合にのみ操作を追加します。`b[i]`, そして最小限にします。 差分配列で傾きを追跡することにより、各要素を明示的に更新することなく、等差数列の効果を後続の要素に正しく伝播します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())
    b = list(map(int, input().split()))
    
    slope = [0] * (n + 1)
    current_add = 0
    operations = 0
    
    for i in range(n):
        current_add += slope[i]
        if current_add < b[i]:
            needed = b[i] - current_add
            operations += needed
            current_add += needed
            if i + k < n:
                slope[i + k] -= needed
            if i + 1 < n:
                slope[i + 1] += needed
    
    print(operations)

if __name__ == "__main__":
    main()
```ソリューションは維持します`current_add`以前の操作の累積効果として。 の`slope`配列は、等差数列の増分効果を将来の位置に伝播します。 境界の処理は非常に重要です。更新のみを行います。`slope[i+k]`もし`i+k < n`インデックスのオーバーフローを避けるため、増分加算は次の時点で開始されます。`i+1`。
