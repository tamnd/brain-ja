 ## 問題の理解

 ブラックボードには、最初は次のすべての整数が含まれています。`0`に`n - 1`。 

ラウンドには常に 2 つの動きがあります。 最初のアリスはいくつかの番号を削除します`a`。 その場合、ボブは別の番号を削除する必要があります`b`そのような$$a+b \equiv 3 \pmod 4.$$ボブがそのような数字を見つけられなかった場合、ゲームは直ちに終了し、ボブは負けます。 ボブが番号を削除すると、次のラウンドが始まります。 プレイヤーは誰かが必要な行動をとれなくなるまで続けます。 

いくつかの値が与えられます`n`そして、それぞれについて、両方が完璧にプレイしたと仮定して、どちらのプレイヤーが勝つかを決定する必要があります。 

制約は小さいです。 テスト ケースは最大 100 個あり、`n ≤ 100`。 総当たりのゲーム検索はすでに実現可能ですが、本当の目標は、ゲームの背後にある数学的構造を発見することです。 その構造を理解すると、各テスト ケースの答えを一定時間で計算できます。 

微妙な点は、ボブが任意の番号を選択しないことです。 彼の選択は、アリスの 4 を法とする数の剰余クラスによって完全に決まります。 

有効なペアリングは次のとおりです。$$0 \leftrightarrow 3$$そして$$1 \leftrightarrow 2.$$～に一致する任意の数`0 (mod 4)`に一致する数値と一致する必要があります`3 (mod 4)`、およびそれに一致する任意の数`1 (mod 4)`に一致する数値と一致する必要があります`2 (mod 4)`。 

よくある間違いは、4 を法とした剰余ではなく、正確な値に注目することです。たとえば、次のような場合です。`n = 5`、数字は次のとおりです。$$0,1,2,3,4.$$番号`4`まったく同じように動作します`0`両方が合同なので、`0 (mod 4)`。 

もう 1 つの簡単な間違いは、整数の合計が偶数であれば自動的にボブに有利であると仮定することです。 のために`n = 2`、数字は 2 つありますが、セットは`{0,1}`。 どちらの選択にも有効なパートナーは存在しないため、アリスが即座に勝ちます。 

入力：```
1
2
```出力：```
Alice
```ボブは最初の一手で負けます。 

## アプローチ

 ブルートフォースアプローチでは、現在の残りの数値セットをモデル化し、すべての正当な手を再帰的に試みます。 アリスは勝利状態に到達しようとする一方、ボブは負けを避けようとします。 

これが機能するのは、次の場合には状態空間が小さいためです。`n ≤ 100`, しかし、ゲームの構造を完全に無視しています。 中程度の場合でも`n`、可能なゲーム状態の数は指数関数的に増加します。 

重要な観察は、4 を法とする剰余のみが重要であるということです。 

すべての数値は、次の 4 つのグループのいずれかに属します。$$0,\ 1,\ 2,\ 3 \pmod 4.$$ボブの応答は、特定の補完的なグループからのものでなければなりません。 

| アリスが選ぶ | ボブは選択しなければなりません |
 | --- | --- |
 | 0 モッド 4 | 3 モッド 4 |
 | 3 モッド 4 | 0 モッド 4 |
 | 1 モッド 4 | 2 モッド 4 |
 | 2 モッド 4 | 1 モッド 4 |

 これは、ゲームが 2 つの完全に独立したプールに分割されることを意味します。 

1. 残留物`0`そして`3`。 
2. 残留物`1`そして`2`。 

させて$$c_0,c_1,c_2,c_3$$は各剰余を持つ数値のカウントになります。 

最初のプール内で移動すると、常に 1 つの要素がプールから削除されます。`c_0`そしてからの1つ`c_3`。 

2 番目のプール内で移動すると、常に 1 つの要素がプールから削除されます。`c_1`そしてからの1つ`c_2`。 

ボブは、選択したプール内の両方のカウントがプラスのままである限り、応答を続けることができます。 

数字については`0`を通して`n-1`、残差カウントの違いは最大でも 1 です。 最初のいくつかの値を確認すると、パターンが明らかになります。 

| n | 勝者 |
 | --- | --- |
 | 1 | アリス |
 | 2 | アリス |
 | 3 | アリス |
 | 4 | ボブ |
 | 5 | アリス |
 | 6 | アリス |
 | 7 | アリス |
 | 8 | ボブ |

 4 つの数字の各ブロックは、正確に 1 つの完全なものに寄与します。`(0,3)`ペアと 1 つが完成`(1,2)`ペア。 

いつ`n`が 4 の倍数である場合、すべての剰余クラスは同じ頻度で現れます。 すべての数値は有効なペアに分割できます。 アリスが何をしても、ボブは常に反応します。 すべての数字が削除された後、移動できなくなった最初のプレイヤーはアリスなので、ボブが勝ちます。 

いつ`n`が 4 の倍数ではない場合、1 つ以上の剰余クラスに追加の要素があります。 アリスは最終的に、一致しない残基から選択し、法的対応なしでボブを離れることができます。 初期位置にアンバランスがすでに存在するため、ボブはこれを防ぐことができません。 

勝者は単純に次のとおりです。 

- ボブなら`n % 4 == 0`- そうでなければアリス

 ## アルゴリズムのチュートリアル

 1.読む`n`。 
2. コンピューティング`n % 4`。 
3. 余りがあれば`0`、出力`"Bob"`。 

この場合、すべての剰余クラスは同じ頻度で出現するため、すべての数値は何らかの有効な一致ペアに属します。 
4. それ以外の場合は出力`"Alice"`。 

少なくとも 1 つの残基クラスが一致しません。 アリスはこの不均衡を利用して、最終的にはボブを法的対応のない立場に追い込むことができます。 

### なぜ効果があるのか

 ゲームは完全に 4 を法とする残基の数によって決定されます。有効な手は常に残基クラスの相補的なペアから 1 つの数値を消費します。`(0,3)`または`(1,2)`。 

いつ`n`が 4 で割り切れる場合、4 つの剰余クラスのカウントはすべて等しい。 すべての要素を一致させることができるため、ボードが空になるまで、ボブは常にアリスの動きに応答できます。 その後、アリスは正当な手なしで最初のポジションに直面し、負けます。 

いつ`n`が 4 で割り切れない場合、少なくとも 1 つの剰余クラスには、その補数クラスよりも多くの要素が含まれます。 これらの追加要素は決して一致しません。 アリスは、一致しない要素だけが残るまで強制的に再生できますが、その時点でボブは応答できません。 したがって、アリスの勝ちです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    print("Bob" if n % 4 == 0 else "Alice")
```実装は数学的特徴付けに直接従います。 

重要な唯一の値は、`n % 4`。 剰余がゼロの場合、剰余クラスは完全にバランスが取れており、ボブが勝ちます。 残りが 1 つおきになると、アリスに有利な不均衡が生じます。 

シミュレーションは必要ありません。 ゲーム状態を保存する必要はありません。 各テスト ケースは一定時間内に独立して処理されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline
    t = int(input())
    ans = []
    for _ in range(t):
        n = int(input())
        ans.append("Bob" if n % 4 == 0 else "Alice")
    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return out

# provided sample
assert run("5\n2\n4\n5\n7\n100\n") == \
       "Alice\nBob\nAlice\nAlice\nBob"

# minimum n
assert run("1\n1\n") == "Alice"

# first Bob position
assert run("1\n4\n") == "Bob"

# just above multiple of 4
assert run("1\n9\n") == "Alice"

# maximum constraint
assert run("1\n100\n") == "Bob"
