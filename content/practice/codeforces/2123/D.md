 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられます。 2 人のプレイヤーが交互に動き、アリスが最初に動きます。 ゲームは文字列の一部を繰り返し書き換えることで進化します。 

アリスは、移動中に、任意のコレクションを正確に選択できます。`k`文字列内の任意の位置に配置されますが、必ずしも連続している必要はなく、それらのすべての位置が強制的に`0`。 ボブは移動中に、任意の連続した長さのブロックを選択できます。`k`そしてそのブロック内のすべての文字を強制的に`1`。 

ボブが次のターンを得る前であっても、文字列がすべてゼロになった瞬間に、アリスは即座に勝ちます。 

問題は、両方のプレイヤーが最適にプレイすると仮定して、アリスが有限の手数ですべてゼロの文字列に到達することを保証できるかどうかです。 

制約`n ≤ 2·10^5`すべてのテスト ケースにわたって、すべてのソリューションがテスト ケースごとに線形またはほぼ線形である必要があることを意味します。 二次関数の何か`n`テスト全体のサイズの合計が 200,000 に達するため、すでに遅すぎます。 これは、答えがゲームをシミュレートするのではなく、文字列の少数のグローバル プロパティに依存する必要があることを強く示唆しています。 

微妙な点は、アリスはサブシーケンスを完全に自由に選択できるのに対し、ボブは連続したセグメントに制限されているということです。 この非対称性が問題の核心です。アリスは分散した位置を制御し、ボブは構造を制御します。 

いくつかのコーナー シナリオで構造が明らかになります。 

もし`k = 1`, アリスはターンごとに任意の 1 つの位置を 0 に反転できますが、ボブは任意の 1 つの位置を反転して 1 に戻すことができます。 一つでもあれば`1`, アリスが削除した後、ボブはいつでもそれを復元できます。つまり、アリスが勝つことができるのは、文字列がすでにすべてゼロである場合だけです。 

もし`k`大きい、特に近い`n`1 回の動きですべての 1 を除去するアリスの能力は非常に強力になりますが、ボブの 1 つのインターバルは依然として広い連続領域を「毒」する可能性があります。 

もう 1 つの重要なエッジ ケースは、`1`はすでにある長さのセグメント内に集中しています`k`。 そうすれば、ボブはそれらを簡単に維持できますが、それらが分散している場合、アリスはそれらを同時に削除できます。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのゲーム状態をシミュレートしようとします。 各状態はバイナリ文字列であり、アリスは各状態から次のサイズの部分列の組み合わせを持ちます。`k`、一方、ボブには次のサイズの部分文字列がすべてあります。`k`。 分岐要素は膨大です。アリスだけが`O(n choose k)`選択肢。 到達可能な状態に制限したとしても、ゲーム グラフは指数関数的になり、このアプローチは完全に実行不可能になります。 

重要な観察は、正確な構成を追跡する必要はなく、ボブがアリスの目標達成を無期限に阻止できるかどうかだけを追跡する必要があるということです。 ボブの唯一の意味のある力は、一定のサイズのスライディング ウィンドウ内にそれらを継続的に再導入することです。`k`。 これは、唯一の永続的な障害は、アリスが世界的に領域を排除するよりも早くボブが「汚染」し続けることができる領域が存在するかどうかであることを示唆しています。 

アリスは正確に削除するので、`k`移動ごとに 1 つ (サブシーケンスを選択)、ボブは 1 つのブロックを作成します。`k`唯一の実際の制約は、サイズの固定ウィンドウの外側にいくつ存在するかです。`k`。 

文字列に一定の長さのウィンドウがある場合`k`すでにすべての 1 が含まれている場合、ボブはいつでもその領域を強化できますが、アリスは内部で再作成される前にその外側のすべての 1 を完全に削除することはできません。 逆に、そのようなウィンドウにすべての 1 が含まれていない場合、ボブは既存のすべてを 1 つの保護されたセグメントに集中させることができないため、アリスは散在するものを繰り返しターゲットにすることで最終的にそれらを削除できます。 

したがって、ゲーム全体は、すべての 1 が一定の長さの部分文字列に含まれているかどうかをチェックすることになります。`k`。

 ## アルゴリズムのチュートリアル

 1. 文字列に文字が含まれるすべてのインデックスを見つけます。`1`。 1 がない場合は、文字列がすでにすべて 0 であるため、アリスがすぐに勝ちます。 
2. の左端の位置を見つけます。`1`そして、の右端の位置`1`。 これら 2 つのエンドポイントは、文字列内のすべての 1 を含む最小間隔をキャプチャします。 
3. この間隔の長さを次のように計算します。`rightmost - leftmost + 1`。 これは、すべての領域をカバーする最小の連続セグメントを表します。`1`。 
4. この長さを次のものと比較します。`k`。 以下の場合`k`の場合、次のサイズのウィンドウが存在します。`k`すべての 1 をカバーするということは、ボブは常にその領域をターゲットにして、少なくとも 1 つを維持できることを意味します。`1`アリスの移動サイクル後。 
5. 間隔の長さが次の値より大きい場合`k`, アリスには、ボブが 1 つのウィンドウ内にそれらを再導入するよりも早く、複数の領域にわたってそれらを排除する十分な自由があり、最終的にすべてのそれらを確実に消滅させることができます。 
6. 出力`"Alice"`間隔の長さが超えた場合`k`、それ以外の場合は出力`"Bob"`。 

### なぜ効果があるのか

 不変条件は、残りすべての範囲です。`1`s. アリスの動きは任意の位置を消去することで全体的に 1 の数を減らしますが、ボブの動きは単一の連続したブロック内でのみ 1 を復元できます。 すべて 1 を含む最小間隔がすでに長さの範囲内にある場合`k`, ボブはいつでも同じ間隔を選択して再導入することができ、ゼロになるのを防ぎます。 それより大きい場合`k`, ボブはすべてのアクティブ領域を同時にカバーすることはできませんが、アリスは占有スパンが消えるまで徐々に縮小することができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()

        ones = [i for i, c in enumerate(s) if c == '1']

        if not ones:
            print("Alice")
            continue

        span = ones[-1] - ones[0] + 1

        if span <= k:
            print("Bob")
        else:
            print("Alice")

if __name__ == "__main__":
    solve()
```このコードは、最初に 1 のすべての位置を抽出し、1 が存在しない自明な勝利ケースを直ちに処理します。 次に、最初と最後の出現を使用して、すべての 1 の境界間隔を計算します。 ゲームの結果にとって重要なのは、インターバルの長さだけです。 最終的な比較`k`上記で導き出された重要な構造条件を実装します。 

実装の微妙な詳細は、インデックス付けがゼロベースであるため、スパンの計算は調整なしですでに正しい長さに一致していることです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        ones = [i for i, c in enumerate(s) if c == '1']
        if not ones:
            output.append("Alice")
        else:
            span = ones[-1] - ones[0] + 1
            output.append("Bob" if span <= k else "Alice")
    
    return "\n".join(output)
