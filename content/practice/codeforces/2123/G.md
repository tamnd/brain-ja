 ## 問題の理解

 私たちは時間の経過とともに変化する配列を維持しており、2 種類のクエリに答えるように求められます。 1 つのタイプは、配列内の単一の位置を永続的に更新します。 もう 1 つのタイプは独立しており、実現可能性について疑問を投げかけます。個別の要素に特別な演算を繰り返し適用できる場合、現在の配列を非減少シーケンスに変換できるでしょうか。 

タイプ 2 のクエリで許可される操作は非常に限定的です。 固定ステップサイズの場合$k$、各要素$a_i$によって増やすことができます$k$モジュロ$m$インデックスごとに独立して、何度でも。 言い換えれば、各値は独自の等差数列モジュロに沿って移動できます。$m$、そして、結果の配列がソートされるように、各進行から最終的な代表を選択できるかどうかを確認しようとしています。 

この難しさは、モジュロ演算と順序付けの間の相互作用に起因します。 各値は直線的に前進するだけでなく、循環するため、各インデックスには事実上、一定の間隔で到達可能な一連の循環的な値が含まれます。$k$。 

この制約により、高度に最適化されたソリューションが求められます。 すべての配列とクエリの合計サイズは最大でも$10^5$、各クエリは、理想的には対数時間またはほぼ一定の時間で、迅速に処理される必要があります。 クエリごとに実現可能性を最初から再計算するアプローチは、すぐに失敗します。$O(n)$クエリごとに、$10^{10}$最悪の場合の運用。 

素朴だが重要なエッジ ケースは、配列がすでに非減少であるにもかかわらず、モジュロ演算により互換性のある構成に到達できない場合です。 たとえば、次のようなとき$m = 6$、$k = 3$、配列には、次のような互いに素なサイクルに分割される両方の残基が含まれます。$\{0,3\}, \{1,4\}, \{2,5\}$の場合、操作ではこれらのクラスを混合できないため、ローカルな調整が妥当であるように見えても、グローバルな並べ替えが不可能になる可能性があります。

## アプローチ

 直接シミュレートしようとすると、クエリごとに、位置ごとに計算を試みることになります。$i$、から到達可能なすべての値$a_i$繰り返し添加すると$k \bmod m$。 これはサイズのサイクルです$m / \gcd(k, m)$。 次に、左から右へ貪欲に値を割り当て、少なくとも以前に選択した値以上の実現可能な最小値を常に選択します。 

この強引な考えは原理的には正しいです。 各要素には制約された値のセットがあり、並べ替えは互換性のある代表的なシーケンスを選択することになります。 ただし、到達可能なセットを構築し、クエリごとにスキャンするにはコストがかかります。 各クエリにはコストがかかります$O(n \cdot \frac{m}{\gcd(m,k)})$に退化します。$O(nm)$最悪の場合。 

重要な構造上の観察は、各要素の到達可能な値が任意のサブセットではないということです。 それらはモジュロの等差数列を形成します$m$。 さらに重要なのは、これらの進行が次のように調整されていることです。$\gcd(m,k)$、値を独立した剰余クラスに分割します。 各クラス内では、動きは周期的かつ均一です。 

これにより、問題は剰余クラスに対する実行可能性チェックに変換されます。 正確な値を追跡する代わりに、要素がモジュール層全体にどのように分布するかを追跡します。$d = \gcd(m, k)$。 各クラス内で、到達可能な値は長さの循環順序付けを形成します。$m/d$したがって、ソート条件は、これらのサイクルを左から右にどのように移動するかに関する制約になります。 

このように考えると、問題は固定された循環構造にわたる制約伝播タスクになり、各要素が開始点に寄与し、単調な走査が可能かどうかを判断する必要があります。 

更新とクエリを効率的にサポートするために、剰余クラスごとの頻度情報を維持し、循環シフトの下で有効な非減少選択が存在するかどうかを推論します。 最後の条件は、隣接する要素間で必要な「ラップアラウンド ブレーク」が強制されないよう、代表を選択できるかどうかを確認することになります。

 ## アルゴリズムのチュートリアル

 中心となるアイデアは、タイプ 2 の各クエリを、クエリによって引き起こされる構造を分析することによって処理することです。$d = \gcd(k, m)$。 すべての値は次のように分割されます$d$それぞれの長さの独立したサイクル$m/d$。 各配列要素は 1 つのサイクル内に存在し、そのサイクル内でのみ移動できます。 

各位置について、その剰余クラスのモジュロを維持します。$d$、およびそのサイクル内のオフセット。 

1. お問い合わせの場合$k$、計算する$d = \gcd(k, m)$。 これにより、値空間の独立したサイクルへの分解が決まります。 重要な理由は、繰り返し追加されることです。$k$合同クラスの剰余を決して出ない$d$。 
2. 各要素について$a_i$、そのクラスを計算します$c_i = a_i \bmod d$。 同じ要素のみ$c_i$異なるクラスの値は循環的にインターリーブされますが、ラップ制約がなければ比較できないため、順序付けに関して相互作用することができます。 
3. 各クラス内で、値を長さのサイクルにマッピングします。$m/d$。 概念的には各値を次のように正規化します。$(a_i - c_i)/d$、これによりサイクルが線形インデックスに平坦化されます。 
4. 並べ替えの問題は、それぞれを選択できるかどうかを決定することになります。$i$、結果として得られるリフト値が循環順序で比較したときに非減少シーケンスを形成するように、そのサイクル内の位置。 
5. サイクル内で実行可能な最小電流値を維持しながら、左から右にスキャンします。 各位置について、そのサイクル内で到達可能な最小値 (少なくとも以前に選択した値) を選択します。 何も存在しない場合は失敗します。 
6. サイクルの独立した性質により、クラスを混合する必要がありません。 それぞれの実現可能性チェックは、以下によって引き起こされる構造に対してローカルです。$d$。 

### なぜ効果があるのか

 不変条件は、各ステップで$i$、プレフィックスの実現可能性を維持しながら、達成可能な最小のリフト値を維持します。 各インデックスはそれ自身の等差数列サイクルのみをトラバースすることができ、これらのサイクルは線形化されると完全に順序付けされるため、有効な解はすべてこのリフト空間内の単調選択に対応する必要があります。 現在のサイクルのどの時点でも、以前に選択した値を超える値がない場合は、残りの到達可能なすべての値が循環順序で厳密に小さいか、単調性を破るラップが必要になるため、操作を再配置しても違反を修復できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd

def can_sort(a, m, k):
    d = gcd(k, m)
    # cycle length
    L = m // d

    # normalize values into (class, position in cycle)
    # class = a % d, pos = a // d
    # within each class, values behave like modulo L

    # we process greedily in lifted space
    prev = 0

    for x in a:
        c = x % d
        v = (x - c) // d  # position in cycle

        # we need smallest v' >= prev such that v' ≡ v (mod L)
        # i.e., v + t*L >= prev
        if v >= prev:
            cand = v
        else:
            t = (prev - v + L - 1) // L
            cand = v + t * L

        # cannot exceed cycle bounds (wrap makes it impossible to stay monotone)
        if cand >= L + v:
            return False

        prev = cand

    return True

def solve():
    t = int(input())
    for _ in range(t):
        n, m, q = map(int, input().split())
        a = list(map(int, input().split()))

        for _ in range(q):
            tmp = input().split()
            if tmp[0] == '1':
                i = int(tmp[1]) - 1
                x = int(tmp[2])
                a[i] = x
            else:
                k = int(tmp[1])
                print("YES" if can_sort(a, m, k) else "NO")

if __name__ == "__main__":
    solve()
```このソリューションは、モジュラー サイクル内の各値のリフト表現に対する貪欲なスキャンに問題を縮小することにより、タイプ 2 の各クエリを処理します。 gcd 分解は重要なステップです。なぜなら、gcd 分解により、$k$値空間を独立したコンポーネントに分割します。 

貪欲な変数`prev`これまでに選択された最小の実現可能なリフト値を追跡します。 各要素について、次の値以上の最初に到達可能な値を計算します。`prev`。 サイクル構造内でそのような値が見つからない場合は、直ちに不可能であると結論付けます。 

微妙なポイントは昇降ステップです`(x - c) // d`これにより、一貫した線形座標系で値を比較できるようになります。 この正規化がなければ、異なる残基間の比較は不正確になります。 

## 実用的な例

 次の小さな例を考えてみましょう$m = 6$、 配列$a = [4, 5, 2]$、 そして$k = 4$。 

我々は持っています$d = \gcd(4, 6) = 2$、 それで$L = 3$。 

値を正規化します。 

| 私 | a[i] | v = (a[i]-a[i]%d)/d | 前へ | 選ばれた |

次に、失敗したケースを考えてみましょう。$m = 6$、$a = [3, 2]$、$k = 3$。

 ## 特殊なケース

 主なエッジケースは次の場合に発生します。$k$大きな gcd を共有する$m$、非常に短いサイクルが生成されます。 このような場合、各要素には到達可能な値が 2 つまたは 3 つしかないため、小さな配列であっても並べ替えが不可能になる可能性があります。 リフトされた表現はサイクルごとに崩壊し、貪欲なステップは有効な後継者の不在を即座に検出するため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジケースは次のような場合です$k = 1$。 ここ$d = 1$したがって、値空間全体が 1 つのサイクルになります。 すべての要素はすべての値に到達することができ、貪欲なプロシージャは常に成功し、配列の長さの制約によって矛盾が強制されない限り、正しく YES を返しますが、このモデルでは矛盾が生じません。 

最後の微妙なケースは、更新によりクエリ間で値が変更される場合です。 各クエリは独立しているため、以前の実現可能性チェックの状態を再利用せず、更新が将来の計算にのみ影響し、過去のクエリ推論が破損しないようにします。
