 ## 解決策
 ## 問題の理解

 とのトーナメントがあります`n`選手たち。 プレーヤー`i`力がある`a[i]`。 生き残った2人のプレイヤーが選択され、弱い方が脱落することを繰り返します。 両方の強さが等しい場合は、どちらか一方を排除することができます。 

プロセスは正確に停止します`k`選手たちは残る。 特定のプレイヤーに興味があります`j`。 問題は、プレーヤーが可能にするペアの選択と引き分けの結果のシーケンスが存在するかどうかです。`j`決勝戦でまだ生き残るには`k`選手たち。 

キーワードは「何か方法はありますか？」です。 私たちは確率を求められるわけではありませんし、トーナメントで起こり得るすべての結果の下でプレイヤーが生き残る必要もありません。 必要なシーケンスは 1 つだけです。 

制約が十分に大きいため、トーナメントの状態をシミュレーションすることは不可能です。 すべてのテスト ケースで、プレーヤーの総数は次のとおりです。`2 · 10^5`したがって、次のことを期待する必要があります。`O(n)`または`O(n log n)`解決。 トーナメントの枠、生存者のサブセット、または状態空間の遷移を調査するものはすべて、指数関数的に成長し、すぐに失敗します。 

この問題の微妙な側面は、ペアリングの存在を確認する際に、ペアリングが完全に制御下にあることです。 最初に他の試合を選択することでプレーヤーを保護できる場合、それは許可されます。 

場合を考えてみましょう```
n = 4, j = 1, k = 1
strengths = [1, 2, 3, 4]
```プレイヤー 1 が最弱です。 唯一の生き残りになるには、プレイヤー 1 は最終的により強いプレイヤーを倒さなければなりませんが、これは不可能です。 正しい答えは、`NO`。 

ここで考えてみましょう```
n = 4, j = 1, k = 2
strengths = [1, 2, 3, 4]
```より強力な 2 人のプレイヤーを互いに排除できます。```
2 vs 3 -> 2 eliminated
4 vs winner -> another player eliminated
```プレイヤーが 2 人だけ残っている場合、プレイヤー 1 はまだ生きている可能性があります。 正しい答えは、`YES`。 

よくある間違いは、プレイヤーの相対的なランクを次のように考えることです。`j`すべての強みの中で常に重要です。 重要なのは選手が必要なときだけ`j`唯一無二のチャンピオンになるために。 

## アプローチ

 ブルートフォースアプローチでは、トーナメントプロセス全体がモデル化されます。 各ステージで、生き残ったプレイヤーのペアを選択し、エリミネーションを実行し、再帰的に続行します。 可能なトーナメント州の数は爆発的に増加します。 プレイヤーが 20 人であっても、考えられる除去シーケンスの数は膨大であり、これは完全に不可能です。 

ブルート フォースが正しい理由は、すべての有効なトーナメントを明示的に調査するためです。 失敗する理由は、各ステップでペアの選択肢の数がほぼ 2 次であり、指数関数的な検索ツリーが作成されるためです。 

より簡単に特徴を説明するには、消去法が実際に何を行うかに注目してください。 

2人のプレイヤーが出会うたびに、1人のプレイヤーが消えます。 自分より強いプレイヤーが2人以上いる場合`j`、それらのより強力なプレイヤーを互いにマッチングし続けることができます。 このような試合ごとに、強力なプレイヤーが 1 人削除されます。 これを繰り返すと、最終的には最大でも 1 人のプレイヤーより強いプレイヤーが残ります。`j`。 

トーナメントが中止になった場合`k > 1`生き残った人は、より強いプレイヤーが 1 人残ってもまったく問題ありません。 プレーヤー`j`生存者の中に存在する必要があるだけであり、必ずしも最も強い生存者である必要はありません。 

唯一難しいケースは、`k = 1`。 それからプレイヤー`j`チャンピオンに違いない。 チャンピオンは、トーナメントに厳密に強いプレイヤーを置くことはできません。遅かれ早かれ、より強いプレイヤーがプレイヤーを倒すことになるからです。`j`または、決勝に進出した相手を倒します。 

したがって:

 もし`k > 1`、すべてのプレイヤーは決勝まで生き残ることができます`k`生存者。 

もし`k = 1`、プレーヤー`j`彼らの強さがアレイ全体の最大の強さと等しい場合にのみ勝つことができます。 

これにより、問題全体が単一の最大チェックに減ります。

 ## アルゴリズムのチュートリアル

 1. プレイヤーの強さを読み取る`j`、つまり`a[j-1]`。 
2. もし`k > 1`、すぐに答えます`"YES"`。 

複数の生存者が許可されている場合、いつでも他のプレイヤー間で試合を手配し、プレイヤーの排除を避けることができます。`j`までだけ`k`選手たちは残る。 
3. もし`k = 1`、配列内の最大強度を計算します。 
4. 比較する`a[j-1]`その最大値で。 

等しい場合は答えてください`"YES"`。 

それ以外の場合は回答してください`"NO"`。 
5. すべてのテスト ケースに対して繰り返します。 

### なぜ効果があるのか

 いつ`k > 1`、プレイヤーだけが必要です`j`チャンピオンになることではなく、生き残るためです。 いつでもそれ以上のものがあります`k`残りのプレイヤーは、異なる 2 人のプレイヤーを選択できます`j`可能な限り。 他のプレイヤーの間で排除すると、プレイヤーを維持しながらフィールドが減少します`j`。 結局のところだけ`k`プレイヤーは残り、プレイヤーは`j`まだ生きています。 

いつ`k = 1`、プレーヤー`j`最後の生存者でなければなりません。 厳密に優れた強さを持つプレイヤーは、決してプレイヤーに負けることはありません`j`、したがって、そのようなプレーヤーはプレーヤーを妨げます`j`チャンピオンになってから。 逆に、プレイヤーの場合、`j`最大の強さを持っていますが、残りの敵はすべてそれより強くありません。 試合を適切にアレンジし、強さが等しい場合に有利な引き分け結果を利用することで、プレーヤーは`j`チャンピオンになれる。 

これら 2 つの観察結果は、考えられるすべてのケースを完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n, j, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        if k > 1:
            print("YES")
        else:
            print("YES" if a[j - 1] == max(a) else "NO")

solve()
```実装は証明に直接続きます。 

各テストケースについて、最初に次のことを確認します。`k`を超える`1`。 その状況での答えはいつも`"YES"`なので、それ以上の作業は必要ありません。 

のみ`k = 1`ケースは分析が必要です。 プレイヤーの力を取り戻す`j`を使用して`j - 1`これは、Python 配列のインデックスが 0 であるのに対し、問題ではインデックスが 1 のプレイヤー番号付けが使用されているためです。 

比較は、より強いプレイヤーの数ではなく、世界の最大強さと比較する必要があります。 同点はプレイヤーにとって有利な方法で解決できるため、最大値が同じであれば十分です。`j`。 

このコードは単一パスを実行して最大値を計算し、テスト ケースごとに線形時間を与えます。
