 ## 問題の理解

 非負の整数の配列が与えられ、正確に削除した後、最小除外値 (MEX) の可能な個別の値の数を計算するように求められます。$k$配列の要素ごとに$k$0から$n$。 配列の MEX は、配列内に存在しない最小の非負の整数です。 

テストケースごとに、出力する必要があります。$n+1$数値: 0 要素、1 要素、... を削除した後の可能な MEX 値の数 (最大)$n$要素。 

入力制約は重要です。 各配列の大きさは次のとおりです。$2 \cdot 10^5$、すべてのテスト ケースの合計が次を超えません。$2 \cdot 10^5$。 これは、これよりも悪い解決策は存在しないことを意味します。$O(n \log n)$テストケースごとにタイムアウトになる可能性があります。 削除された要素のあらゆる組み合わせをシミュレートする素朴な解決策は、サイズのサブセットの数が制限されるため、絶望的です。$k$組み合わせです。 

いくつかの特殊なケースは微妙です。 次のような、すべての要素が等しい配列を考えてみましょう。`[0,0,0,0]`。 MEX は 1 から始まりますが、ゼロのサブセットを削除しても、配列が空になるまで MEX に 1 以外の値を生成することはできません。 別のエッジ ケースは、配列の先頭から 0 が欠落している場合です。たとえば、`[1,2,3]`; この場合、MEX は 0 となり、要素を削除しても小さくすることはできず、大きくなるだけです。 不注意な実装では、要素を削除すると常に MEX が増加すると想定する可能性がありますが、これは誤りです。 

## アプローチ

 ブルートフォースアプローチでは、サイズのすべてのサブセットが試行されます$k$それぞれに$k$0から$n$、MEX を計算し、個別の値をカウントします。 これは論理的には正しいですが、まったく現実的ではありません。 のために$n = 10^5$、サイズ 1 のサブセットでも$O(n)$、サイズ 2 のサブセットは次のとおりです。$O(n^2)$、 等々。 明らかに、組み合わせ爆発がこれを排除します。 

重要な洞察は、要素を削除したときに MEX がどのように変化するかを理解することから得られます。 MEX は、候補 MEX よりも小さい数がすべて存在する場合にのみ増加します。 数字の場合$x < MEX$がありません。MEX はすでにあります$x$。 数値を削除する場合、MEX の増加を妨げる数値を削除することによってのみ MEX を増加させることができます。 逆に、現在の MEX 以上の数値を削除することでいつでも MEX を減らすことができますが、欠落している最小の数値よりも小さい MEX を作成することはできません。 

具体的には、0 から 0 までの各数値の出現を数えることができます。$n$。 と表しましょう`cnt[x]`の数として$x$配列内で。 その後、MEX を段階的に増加させるシミュレーションを行うことができます。 MEX = 0 では、0 が存在する必要があります。 MEX = 1 に達するには、十分な 0 を削除して配列サイズを小さくするか、他の数値を調整する必要があります。 継続的な「追加撤去予算」を維持することで、ターゲット MEX ごとに、それぞれのターゲット MEX ごとに何通りの方法でそれを達成できるかを決定できます。$k$。 プレフィックスの合計または除去の貪欲な割り当てを使用すると、効率的に答えを計算できます。 

これにより、複雑さが軽減されます。$O(n)$テスト ケースごとに、数値をカウントするために配列を 1 回スキャンするだけなので、その後はカウントを順次スキャンして MEX の増加をシミュレートします。

 ## アルゴリズムのチュートリアル

 1. 配列サイズを読み取る$n$そして配列`a`。 
2. 配列を初期化する`cnt`長さの$n+2$各数値の出現をカウントします。 反復処理`a`そして増加します`cnt[x]`要素ごとに`x`。 
3.初期化`removed = 0`特定の MEX に到達するために使用された総削除を追跡します。 空のリストを初期化する`ans`長さの$n+1$それぞれの可能な MEX 値の数を保存します。$k$。 
4. 潜在的な MEX 値を反復処理します。`mex`0から始まります。それぞれについて`mex`、 チェック`cnt[mex]`。 もし`cnt[mex]`が 0 の場合、余分な要素を削除しないと MEX に到達できないため、ブレークします。 それ以外の場合は蓄積します`removed += cnt[mex] - 1`。 これは、それぞれの小さい数を 1 つ確保した後に利用できる追加の除去を表します。 
5. それぞれについて`k`0から`n`、到達可能な MEX 値の数を次のように計算します。`min(n - k + removed, mex + 1)`。 これは、除去バジェットを貪欲に使用して、可能な MEX 値の数を拡張します。 
6. 反復が完了したら、または`mex`を超える`n`、残りを埋める`ans[k]`すべての要素を削除すると、MEX = 0 の空の配列だけが残るため、値は 1 になります。 
7. 出力`ans`現在のテストケースの場合。 

不変条件は、各ステップで、`removed`現在の MEX を減らさずに削除できる要素の余剰をカウントします。 これにより、到達可能な MEX 値の数がそれぞれについて正しく計算されることが保証されます。`k`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        cnt = [0] * (n + 2)
        for x in a:
            if x <= n:
                cnt[x] += 1

        ans = [0] * (n + 1)
        removed = 0
        mex = 0
        for mex in range(n + 1):
            if cnt[mex] == 0:
                break
            removed += cnt[mex] - 1

        # fill in number of possible MEX for each k
        for k in range(n + 1):
            ans[k] = min(k + 1, mex + removed)
            if k > removed + mex:
                ans[k] = mex

        print(' '.join(map(str, ans)))

if __name__ == "__main__":
    solve()
```の`cnt`配列は各整数の出現を最大でカウントします。`n`。`removed`MEX の増大を妨げることなく、削除可能な追加要素を追跡します。 最初のループは、要素が削除されない場合に達成可能な最大の MEX を特定します。 2 番目のループは除去を貪欲に分散します。`k`可能な MEX 値の数を計算します。 の`min`可能な最大 MEX を決して超えないようにします。 すべての要素が同じ場合にエッジ条件が発生します。これは、`cnt[mex] == 0`チェック。
