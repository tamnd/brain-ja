 ## 解決策
 ## 問題の理解

 接続された非巡回グラフが与えられているため、任意の 2 つの頂点間には単純なパスが 1 つだけ存在します。 このツリーでは、最初は均一なエッジの可変条件を維持し、次に 2 種類の操作を処理します。 1 つのタイプは 2 つの頂点間の一意のパスに沿った情報を要求し、もう 1 つはそのパス上のすべてのエッジの状態を変更し、操作定義によってはそのパスに隣接するエッジにも影響を与える可能性があります。 

各クエリはパスベースです。つまり、ツリーの構造により、個々のエッジではなく、ルートからノードへのパスまたは重いセグメントと軽いセグメントへの分解という観点から考える必要があります。 出力はクエリ操作に対してのみ定義されており、多くの更新後にパスに沿って何らかの集計値を計算する必要があります。 

制約は大きく、最大数十万の頂点とクエリがあります。 これにより、クエリごとに明示的にパスをたどるアプローチは即座に除外されます。これは、単一のパスが O(n) 回長くなる可能性があり、O(n) 回繰り返されると二次的な動作が生じるためです。 

この種の問題の主なエッジケースは、長いチェーンに起因します。 たとえば、直線 1-2-3-…-n のツリーでは、すべてのクエリが完全な配列範囲の演算に縮退します。 クエリごとの単純な DFS では、同じエッジに対して繰り返し再計算が行われ、時間内に終了しません。 更新が重なり合うと、別の微妙なエッジ ケースが発生します。これは、同じエッジに対する繰り返しの変更により、操作の独立性に関する仮定が無効になる可能性があるためです。 

## アプローチ

 ブルート フォース アプローチは簡単です。クエリごとに、一方のエンドポイントからもう一方のエンドポイントまで DFS または BFS を実行して、パス上のすべてのエッジを列挙し、それらを 1 つずつカウントまたは更新します。 これは正しいです。ツリーが一意のパスを保証するため、トラバーサルでは常に関連するエッジが正確に識別されます。 

ただし、このアプローチは遅すぎます。 最悪の場合、各パス クエリのコストは O(n) になる可能性があり、Q が最大 3×10^5 の場合、合計の複雑さは O(nQ) になり、これはまったく実行不可能です。 

重要な観察は、ツリー構造を適切に前処理すれば、あらゆるパスを少数の正規セグメントに分解できるということです。 「道を歩く」という観点から考えるのではなく、重光分解またはバイナリ リフティングを使用して、ツリーをルートからノードへのチェーンのセットとして扱います。 これにより、任意のパスが O(log n) セグメントに変換され、各セグメントはツリーの線形化表現の連続範囲に対応します。 

ツリーが線形化されると、パス クエリはセグメント クエリになります。 その後、範囲の割り当てが必要か範囲の追加が必要かに応じて、遅延伝播を備えたセグメント ツリーまたはフェンウィック ツリーを使用して更新を処理できます。 本質的な変換は、グラフの問題から配列の範囲クエリの問題に移行することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DFS | O(nQ) | O(n) | 遅すぎる |
 | 重光分解 + セグメントツリー | O((n + Q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 頂点 1 にルートがあると仮定し、ツリーのヘビーライト分解を構築して、すべてのノードがチェーンに属し、ルートからノードへの各パスが O(log n) セグメントに分解されるようにします。

1. まず、DFS を使用してサブツリーのサイズを計算します。 これにより、各ノードの重い子を最大のサブツリー サイズを持つ子として識別できるようになります。 この選択により、重いエッジをたどるときに長いチェーンに留まり、パスごとに O(log n) 回のみチェーンを切り替えることが保証されます。 
2. ツリーを重いパスに分解します。 各ノードには、チェーンが形成される順序に従って線形配列内の位置が割り当てられます。 このマッピングは、木のエッジを配列上の間隔に変換します。 
3. この線形配列上にセグメント ツリーを構築します。 セグメント ツリーは、問題がエッジまたは頂点のどちらの状態を定義しているかに応じて、エッジまたはノードの現在の状態を維持します。 更新がセグメント全体に影響を与える場合は、遅延伝播が使用されます。 
4. ノード u と v の間のクエリの場合、両方のノードが同じ重いパス上になるまで、より深いノードをそのチェーンの上に繰り返し移動します。 各ジャンプはセグメント ツリー内の連続セグメントに対応し、O(log n) 時間で処理できます。 
5. 更新クエリの場合、パス分解の各セグメントに必要な操作を適用します。 これには、クエリの種類に応じて、値の設定、状態の反転、またはカウントの累積が含まれる場合があります。 
6. 回答クエリの場合、パスに沿って訪問したすべてのセグメントからの結果を集約し、セグメント ツリーのマージ操作を使用してそれらを結合します。 

これが機能する理由は、重光分解では、ルートからノードへのパスが最大 O(log n) 個の重セグメントを通過することが保証されるという事実に基づいています。 各セグメントはオイラーのような順序付けにおける連続した間隔に対応し、セグメント ツリーは更新時に間隔の集計を正しく維持します。 これにより、すべてのエッジまたはノードが正確に 1 つのセグメント位置に属するため、ツリーのどの部分も欠落したり二重にカウントされたりすることがないため、正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, n):
        self.n = n
        self.t = [0] * (4 * n)
        self.lazy = [0] * (4 * n)

    def push(self, v, l, r):
        if self.lazy[v]:
            self.t[v] = (r - l + 1)
            if l != r:
                self.lazy[v*2] = 1
                self.lazy[v*2+1] = 1
            self.lazy[v] = 0

    def update(self, v, l, r, ql, qr):
        self.push(v, l, r)
        if ql > r or qr < l:
            return
        if ql <= l and r <= qr:
            self.lazy[v] = 1
            self.push(v, l, r)
            return
        m = (l + r) // 2
        self.update(v*2, l, m, ql, qr)
        self.update(v*2+1, m+1, r, ql, qr)
        self.t[v] = self.t[v*2] + self.t[v*2+1]

    def query(self, v, l, r, ql, qr):
        self.push(v, l, r)
        if ql > r or qr < l:
            return 0
        if ql <= l and r <= qr:
            return self.t[v]
        m = (l + r) // 2
        return self.query(v*2, l, m, ql, qr) + self.query(v*2+1, m+1, r, ql, qr)

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append(b)
        g[b].append(a)

    parent = [-1] * n
    depth = [0] * n
    size = [0] * n
    heavy = [-1] * n

    def dfs(u, p):
        size[u] = 1
        for v in g[u]:
            if v == p:
                continue
            parent[v] = u
            depth[v] = depth[u] + 1
            dfs(v, u)
            size[u] += size[v]
            if heavy[u] == -1 or size[v] > size[heavy[u]]:
                heavy[u] = v

    dfs(0, -1)

    head = [0] * n
    pos = [0] * n
    cur = 0

    def decompose(u, h):
        nonlocal cur
        head[u] = h
        pos[u] = cur
        cur += 1
        if heavy[u] != -1:
            decompose(heavy[u], h)
        for v in g[u]:
            if v != parent[u] and v != heavy[u]:
                decompose(v, v)

    decompose(0, 0)

    seg = SegTree(n)

    def path_update(u, v):
        while head[u] != head[v]:
            if depth[head[u]] < depth[head[v]]:
                u, v = v, u
            seg.update(1, 0, n - 1, pos[head[u]], pos[u])
            u = parent[head[u]]
        if depth[u] > depth[v]:
            u, v = v, u
        seg.update(1, 0, n - 1, pos[u], pos[v])

    def path_query(u, v):
        res = 0
        while head[u] != head[v]:
            if depth[head[u]] < depth[head[v]]:
                u, v = v, u
            res += seg.query(1, 0, n - 1, pos[head[u]], pos[u])
            u = parent[head[u]]
        if depth[u] > depth[v]:
            u, v = v, u
        res += seg.query(1, 0, n - 1, pos[u], pos[v])
        return res

    q = int(input())
    for _ in range(q):
        t, a, b = map(int, input().split())
        a -= 1
        b -= 1
        if t == 0:
            print(path_query(a, b))
        else:
            path_update(a, b)

if __name__ == "__main__":
    solve()
```DFS はサブツリー サイズを構築し、重いエッジを識別することで、長いチェーンが分解時に保存されます。 分解ステップでは、各ノードに平坦化された配列内の位置を割り当てます。これがセグメント ツリーの操作対象となります。 

更新関数とクエリ関数はどちらもクライミング チェーンに依存しています。 ノードからチェーンヘッドに移動するたびに、連続したセグメントが処理されます。 ここで、対数的な複雑さが現れます。これは、各ジャンプが、重光構造に関して残りのパス長の少なくとも半分を破棄するためです。 

セグメント ツリーは遅延伝播を使用して、範囲の割り当てを効率的にサポートします。 不変条件は、分解配列内のすべての位置が、ツリー内の対応するノードまたはエッジの現在の状態を正確に反映するということです。

```更新がパスにどのような影響を与えるかを追跡します。 

| ステップ | 操作 | パス | アクションの概要 |
 | --- | --- | --- | --- |
 | 1 | アップデート 2-4 | 2-1-3-4 | パス上のすべてのセグメントをマーク |
 | 2 | クエリ 2-5 | 2-1-3-5 | アクティブエッジの合計 |
 | 3 | クエリ 4-5 | 4-3-5 | アクティブエッジの合計 |

 最初のクエリは、後の両方のクエリと交差するパスをアクティブ化します。 分解により、各セグメントが 1 回更新されることが保証され、後続のクエリでは格納されたセグメント ツリーの状態が再利用されます。 

これは、セグメント ツリーがクエリごとに再計算するのではなくグローバルな状態を保存するため、重複するパスの更新が一貫して処理されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | 各パスは O(log n) セグメントに分解され、各セグメント ツリーの演算は O(log n) |
 | スペース | O(n) | 隣接リスト、HLD 配列、セグメント ツリー |

 各クエリは完全なパスではなく少数のセグメントのみに触れるため、対数係数により、300,000 クエリでも解が制限内に保たれます。

 ## 特殊なケース

 縮退チェーンは、重光分解の全深度をテストし、ツリーの高さが O(n) であっても、すべてのクエリが O(log n) セグメントを横断することを強制します。 分解により線形走査が妨げられるため、アルゴリズムは引き続き各クエリを効率的に処理します。 

星型ツリーは、すべてのパスの長さが 2 である反対の極端なテストを行います。ここでは、セグメント ツリーは主に互いに素な小さな間隔で実行され、更新がパスの長さに依存しないことが確認されます。 

同じパス上で更新を繰り返すと、遅延伝播により、再計算やセグメントの欠落が発生することなく、複数の範囲の割り当てが正しくマージされることが確認されます。
