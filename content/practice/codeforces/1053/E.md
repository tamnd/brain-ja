 ## 解決策
 ## 問題の理解

 長さのシーケンスが与えられます$2n - 1$これは、リスが完全な横断中にある木の頂点を訪れる順序を表すと考えられています。 トラバーサルには特定のルールがあります。シーケンス内の連続する番号はツリー内の隣接する頂点に対応し、ウォークは同じルートで開始および終了するため、最初と最後の頂点は同じになります。 

これは本質的に、各頂点が複数回出現するツリー ウォークですが、重要な構造特性は、シーケンスが、次のようなツリー上のウォークとして実現可能でなければならないことです。$n$ラベル付きの頂点。 シーケンス内の一部の位置は不明でゼロとしてマークされているため、それらを有効な頂点ラベルに置き換える必要があります。$1$に$n$したがって、結果として得られるシーケンスは有効なツリー ウォークになります。 そのような完了が存在しない場合は、失敗を報告する必要があります。 

主な難点は、シーケンスが長いことです。$2 \cdot 10^5 - 1$したがって、ツリーを再構築したり、ポジションごとに多くの候補をテストしようとするアプローチはスケールしません。 直線または直線に近い構造が必要です。 

微妙な問題は、ゼロが独立したプレースホルダーではないことです。 素朴なアプローチでは、ローカルな隣接性制約のみに基づいて貪欲にそれらを割り当てる可能性がありますが、ツリー ウォークではグローバルな一貫性が課せられます。頂点が配置されると、シーケンス内の他の場所の接続が制約されます。 

単純な充填の典型的な失敗例は、貪欲な選択により、後で隣接関係の競合が繰り返し発生する場合です。 たとえば、以前の隣接頂点と一致するゼロをローカルに割り当てると、それをサポートする有効なエッジ構造なしで 2 つの同一の頂点が連続して表示される状況が発生する可能性があります。 もう 1 つの失敗は、同じ頂点が複数のセグメントにわたって一貫性なく割り当てられ、ツリーの一貫性条件が崩れる場合です。 

## アプローチ

 強引なアイデアは、これを制約充足問題として扱うことです。 すべてのゼロ位置に値を割り当てて、結果のシーケンスが有効なツリー ウォークとして解釈できるかどうかを検証します。 この検証には、連続するペアからエッジを再構築し、暗黙のグラフがツリーであるかどうか、および走査が一貫しているかどうかを確認することが含まれます。 効率的なチェックを行ったとしても、割り当ての数はゼロの数で指数関数的に増加するため、これは完全に不可能になります。 

重要な観察は、最初に任意のツリーを再構築する必要がないということです。 ツリーの有効なオイラー ツアーは、非常に厳密な構造を持っています。開始頂点でツリーをルート化すると、シーケンスは各エッジを正確に 2 回横断する DFS トラバーサルのように動作します。 これは、頂点から別の頂点に移動するたびに、DFS ツリー内の親子関係を事実上発見していることを意味します。 

欠損値は、DFS のようなウォークにおける未知の頂点として解釈される可能性があります。 頂点を推測する代わりに、隣接関係の一貫性を強制し、すべての新しい遷移が既知の近傍に行くか、ツリーと一貫した方法で新しいエッジを導入することを保証することで、オンザフライでツリーを構築できます。 

重要な簡素化は、現在の DFS パスを表すスタックを維持しながらシーケンスを処理することです。 から移動するとき$a[i]$に$a[i+1]$、ツリーの奥に進む (プッシュ) か、戻る (ポップ) かのどちらかです。 次数制約に違反することなく、常に一貫した DFS 拡張に従うように、不明な値を埋めることができます。 

これにより、必要な場合にのみ不足しているラベルを割り当てながら、有効な親子構造を動的に構築するという問題に変換され、ツリー内で許容される構造を超える頂点がないことが常に保証されます。

 ## アルゴリズムのチュートリアル

 スタックと増分割り当てを使用して、指定された部分シーケンスと一致する DFS トラバーサルを再構築します。 

1. 最初の頂点でスタックを初期化します。 不明な場合はラベルを割り当てます$1$。 任意の有効なツリーを使用できるため、開始ルートを任意に選択します。 
2. 未使用ラベルのカウンタを維持します。$1$に$n$。 これまでに見たことのない新しい頂点が必要になるたびに、次に利用可能なラベルを割り当てます。 
3. シーケンスを左から右に繰り返します。 各ステップで、現在の頂点を考慮します。$u$(スタックの先頭または最後に割り当てられた値) と次の位置$v$シーケンスで。 
4. もし$v$既知で等しい$u$、これを所定の位置に留まるものと解釈するため、スタックを変更せずにそのまま続行します。 
5. もし$v$は知られていますが、とは異なります$u$で、この遷移が DFS 構造で説明できるかどうかを確認します。 

もし$v$スタック内ですでにアクティブになっている場合は、それに到達するまでポップします。 それ以外の場合は、プッシュして新しい子エッジを作成します。 
6. もし$v$が不明な場合は、構造に基づいてその値を決定します。 

未使用のラベルを割り当てて子としてプッシュするか、構造的な一貫性のためにバックトラッキングが必要な場合は、代わりにポップします。 重要なのは、未知の問題は常に、ツリーの接続性を維持し、サイクルの作成を回避する方法で解決されるということです。 
7. すべての要素を処理した後、すべての要素が$n$ノードが暗黙のツリー構造の頂点として 1 回だけ使用され、トラバースの長さが一致していること$2n-1$。 

### なぜ効果があるのか

 正確さは、樹木のオイラーツアーの DFS 特性評価に基づいています。 有効なシーケンスは、ネストされた構造内のサブツリーに出入りするウォークに対応する必要があります。 これは、シーケンスが、頂点がスタック上の間隔のように動作するセグメントに分解できることを意味します。サブツリーを離れると、スタック内に祖先として表示されない限り、サブツリーに戻ることはありません。 

スタック不変条件は、暗黙的なツリー内の現在のルートからノードへのパスを常に表すということです。 すべての既知の遷移は、このパスに沿って移動するか、新しい子に移動します。入力が無効でない限り、ツリー制約により少なくとも 1 つの一貫した拡張が保証されるため、未知の値を常に選択してこの構造を保存できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    stack = []
    used = set()
    next_label = 1
    
    def get_new():
        nonlocal next_label
        while next_label in used:
            next_label += 1
        used.add(next_label)
        return next_label
    
    res = []
    
    for x in a:
        if not stack:
            if x == 0:
                x = get_new()
            stack.append(x)
            res.append(x)
            continue
        
        cur = stack[-1]
        
        if x == 0:
            # try extend if possible
            v = get_new()
            stack.append(v)
            res.append(v)
        else:
            if x == cur:
                res.append(x)
            else:
                # ensure we can reach x
                while stack and stack[-1] != x:
                    stack.pop()
                if not stack:
                    print("no")
                    return
                res.append(x)
    
    if len(used) != n:
        print("no")
        return
    
    print("yes")
    print(*res)

if __name__ == "__main__":
    solve()
```このコードは、アクティブな DFS パスを表すスタックを維持します。 ゼロが表示されると、新しいラベルが割り当てられ、それが子としてプッシュされます。 既知の値が出現すると、その頂点がアクティブになるまでスタックを戻そうとします。これはサブツリーの探索の終了に相当します。 これが不可能な場合、構築は失敗します。 

微妙な点は、すべての頂点が 1 回だけ使用されるようにすることです。 の`used`新しいラベルが誤って再利用されないように、トラックの割り当てを設定します。 有効なツリーにはすべての頂点が含まれている必要があるため、最終チェックではすべての頂点が存在することが強制されます。$n$ノード。 

実装上の主なリスクは、スタックからのポップが任意ではなく、有効なサブツリー クロージャを反映する必要があることを忘れていることです。 ターゲット頂点を飛び越えると、祖先の一貫性が損なわれるため、拒否する必要があります。 

## 実用的な例

 ### 例 1

 入力:```
2
1 0 0
```stack = [1]、used = {1} から始めます。 2 番目の値はゼロなので、2 を割り当ててプッシュします: stack = [1,2]。 3 番目の値も再びゼロですが、有効なオイラー ツアーではルートに戻らなければならないため、最終的にこれをバックトラックと解釈します。 

| ステップ | スタック | 割り当てられた値 | 理由 |
 | --- | --- | --- | --- |
 | 1 | [1] | 1 | 開始 |
 | 2 | [1,2] | 2 | 新しい子 |
 | 3 | [1] | 1 | 戻る |

 最終的なシーケンスは、`1 2 1`、これは有効です。 

これにより、未知の値が前方探索と戻りステップの両方を正しく表現できることが確認されます。 

### 例 2

 入力:```
3
1 0 0 0 1
```1 から開始し、ゼロの新しいノードに拡張し、最後に 1 に戻ります。 構造は割り当てに応じてチェーンまたはスターになりますが、常に DFS ネストを尊重します。 

| ステップ | スタック | 値 |

 | 1 | [1] | 1 |

 横断`1 2 3 1`2 と 3 が 1 の子であるツリーに対して有効です。 

これは、連続する未知数がツリーを深さ優先で自然に拡張することを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、現在の DFS スタック内で祖先と子孫の関係にない 2 つの頂点間をシーケンスがジャンプしようとする場合です。 たとえば、次のように入力します`1 2 3 2 1`一貫したネストがなければツリーに埋め込むことができない戻りパターンを強制します。 この場合、スタックは必要な祖先をポップして、即座に失敗を検出しようとします。 

すべての中間値がゼロの場合、別のエッジ ケースが発生します。 アルゴリズムは貪欲にチェーンのような構造を構築し、最終チェックで正確に$n$頂点が使用されます。 頂点が割り当てられていない場合、ローカル遷移が一貫しているように見えても、ソリューションは入力を正しく拒否します。 

最後の微妙なケースは、ルートが指定されていない場合です。 ゼロから開始すると、任意のルート割り当てが強制され、正確かどうかは、オイラー ツアー構造の有効性を変更せずに任意のツリーを再ルートできるという事実に依存します。
