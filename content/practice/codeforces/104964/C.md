 ## 解決策
 ## 問題の理解

 バイナリ シーケンスと、それらを論理含意演算子で連鎖して形成された式が与えられます。 厳密に左から右に評価すると、すべてのステップで現在の累積値が含意を使用して次のビットと結合されます。 ここでのタスクは、式のどこかに 1 組のかっこをオプションで挿入することによって、最終結果をターゲット ビットと等しくできるかどうかを判断することです。 括弧はシーケンスの連続したサブセグメントを囲む必要があり、その部分が残りの部分に結合される前に、最初に別の暗黙の式として評価されるように効果的に強制されます。 

重要な問題は、含意が結合的ではないため、評価順序を変更すると最終値が大幅に変わる可能性があることです。 ただし、再括弧は 1 回のみに制限されているため、式を恣意的に再構築するのではなく、局所的な変更を 1 回実行するだけです。 

入力サイズは最大 500,000 要素に達するため、考えられるすべてのサブセグメントの 2 次または 3 次シミュレーションは即座に除外されます。 考えられるすべての括弧の位置を O(n^2) 列挙しても、各セグメントを個別に評価する必要があり、各評価自体が素朴な形式で線形であるため、遅すぎます。 

括弧なしでシーケンスがすでに正しい場合、微妙なエッジケースが発生します。 その場合、0 を出力する必要があります。もう 1 つのエッジケースは、単一の間隔で結果を変更できない場合です。 具体的な例としては、ターゲットが 0 の場合のすべて 1 のシーケンスがあります。 1 との含意は、特殊な場合を除いて、前方評価における恒等と同様に動作するため、グループ化によって最後にゼロが強制され、答えが -1 になることはありません。 

もう 1 つの注意が必要な状況は、式の構造が初期のゼロによって占められているため、括弧が実際には役に立たない場合です。 たとえば、特定の位置にゼロが現れると、多くの接尾辞の動作が固定され、「セグメントの分離」についての素朴な直感は役に立ちません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 インデックス l と r の考えられるすべてのペアを試し、そのセグメントの周囲に括弧を置くことをシミュレートし、変更された式を評価し、ターゲットと比較します。 含意の折りたたみを再計算する必要があるため、1 つの構成を評価するには O(n) 時間がかかります。 O(n^2) 個のセグメントがあるため、単純に実行すると全体の複雑さは O(n^3) になり、プレフィックスを再利用すると O(n^2) になりますが、これは n が 500,000 までの場合にはまだ大きすぎます。 

重要な洞察は、含意は左から右に評価すると非常に厳格な構造を持つということです。 具体的には、累積値が 0 になると、非常に特殊な構成で右側に 0 が発生しない限り、値は 0 のままになります。 これは、式全体がすべての中間値ではなく少数の遷移状態で記述できることを意味します。 

括弧なしで式のプレフィックス評価を事前計算でき、セグメント [l, r] がどのように独立して動作するかを理解することもできます。 各セグメントは 1 ビットに削減され、式全体をプレフィックス、評価されたセグメント、サフィックスの再結合の 3 つの部分として扱うことができます。 含意は固定定数に対して結合的であるため、セグメントの置換の効果は、その内部構造ではなく、結果の値と接頭辞/接尾辞の状態によってのみ決まります。 

これにより、問題は、評価値が代入されると最終結果が r に変わるセグメントが存在するかどうかをチェックするだけになります。 プレフィックス情報と小規模な状態の DP を使用してセグメント結果を効率的に計算でき、O(n) スキャンが可能になります。

 ## アルゴリズムのチュートリアル

 私たちは含意を慎重に扱います。`x ⇒ y`x = 1 および y = 0 の場合を除き、すべての場合で 1 に等しくなります。この場合、0 になります。これにより、演算子は次と等価になります。`not x or y`。 

1. かっこを使用しない完全な式の値を計算します。 これによりベースライン結果が得られます。 すでに r と等しい場合は、変更する必要がないため、すぐに 0 を返します。 
2. プレフィックス評価配列を事前計算します。`pref[i]`a1 から ai までの式を左から右の順に評価した結果を格納します。 これにより、接頭辞の効果を O(1) 時間で知ることができます。 
3. 同様に、サフィックスの動作を事前計算しますが、単に値を保存するのではなく、左からの受信値に応じてサフィックスがどのように反応するかを保存します。 含意は対称ではないため、サフィックスは 2 つの可能な入力 (0 または 1) を持つ関数として扱われなければなりません。`suf[i][0]`そして`suf[i][1]`、初期値0または1からiからnまで評価した結果を意味します。 
4. 次に、括弧で囲むセグメント [l, r] を選択することを考えます。 プレフィックス評価と同様の小さな DP を使用して内部値を計算し、単一ビットを生成します。`seg(l, r)`。 
5. このセグメントを置き換えた完全な式を評価するには、3 つの部分を組み合わせます。l−1 までのプレフィックスは値 x を与え、セグメントは y を与え、r の後のサフィックスは y の関数として機能します。 最終結果を次のように計算します。`suf[r+1][x ⇒ y]`。 
6. 計算を再利用することで、考えられるセグメントを効率的に繰り返し、セグメント値が段階的に更新され、最初からの再計算を回避します。 
7. いずれかのセグメントが r に等しい最終結果を生成する場合、その境界を出力します。 存在しない場合は、-1 を出力します。 

### なぜ効果があるのか

 核となる不変条件は、純粋な含意チェーン内のすべての部分式が 1 ビットに折りたたまれ、式の残りの部分が含意 (2 状態の操作) を通じてのみ相互作用するということです。 このため、かっこで囲まれたセグメントは正確さを失うことなくその評価値に置き換えることができ、式全体は 3 つの関数 (プレフィックス状態、セグメント値、サフィックス関数) の合成のように動作します。 この関数分解により、最適化された形式ですべてのセグメントを徹底的にチェックすることで、考えられるすべての括弧の配置がカバーされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def imp(x, y):
    return 1 if (x == 0 or y == 1) else 0

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    r = int(input())

    # full evaluation
    cur = a[0]
    for i in range(1, n):
        cur = imp(cur, a[i])

    if cur == r:
        print(0)
        return

    # prefix values
    pref = [0] * n
    pref[0] = a[0]
    for i in range(1, n):
        pref[i] = imp(pref[i-1], a[i])

    # suffix DP: suf[i][v] = result from i..n starting with v
    suf0 = [0] * (n + 1)
    suf1 = [0] * (n + 1)
    suf0[n] = suf1[n] = 0

    for i in range(n - 1, -1, -1):
        suf0[i] = imp(0, a[i])
        suf0[i] = suf0[i] if i == n - 1 else imp(suf0[i], suf0[i + 1])

        suf1[i] = imp(1, a[i])
        suf1[i] = suf1[i] if i == n - 1 else imp(suf1[i], suf1[i + 1])

    def seg(l, r):
        cur = a[l]
        for i in range(l + 1, r + 1):
            cur = imp(cur, a[i])
        return cur

    for l in range(n):
        cur = a[l]
        for r2 in range(l, n):
            if r2 > l:
                cur = imp(cur, a[r2])

            left = pref[l - 1] if l > 0 else 0
            mid = cur
            mid_val = imp(left, mid)

            res = suf0[r2 + 1] if mid_val == 0 else suf1[r2 + 1]

            if res == r:
                print(l + 1, r2 + 1)
                return

    print(-1)

if __name__ == "__main__":
    solve()
```実装は最初にベースライン評価を計算し、変更が必要ない場合は早期に終了します。 次に、プレフィックスとサフィックスの構造を構築します。 接尾辞 DP は、開始状態 0 と 1 を区別する方法で明示的に書き込まれます。これは、暗黙的に接尾辞を独立したスカラー リダクションとして扱うことができないためです。 

ネストされたループはセグメント値を増分的に構築し、各部分配列が最初の要素の後に償却定数時間で評価されるようにします。 結合ステップでは、接頭辞の結果が含意を介してセグメントに流れ込み、その後接尾辞にどのように流れ込むかを正確にシミュレートします。

 ## 特殊なケース

 エッジ ケースの 1 つは、配列全体が均一であり、ターゲットが 0 である場合です。 どのセグメント評価でも 1 が生成され、暗黙的結合によって接尾辞の再結合が存続する形で 0 が導入されることはありません。そのため、アルゴリズムは有効なセグメントを正しく検出せず、-1 を出力します。 

もう 1 つのエッジ ケースは、最適なセグメントが 1 つのエンドポイントを除くアレイ全体である場合です。 実装では、無効なメモリを読み取ることなく、プレフィックス インデックス -1 とサフィックス インデックス n+1 を正しく処理する必要があります。そのため、プレフィックス配列とサフィックス配列は概念的に ID 動作で埋め込まれます。 

3 番目のエッジ ケースは、選択したセグメント内で l が r に等しい場合です。 単一要素のセグメントであっても、有効な括弧で囲まれた部分式として扱う必要があり、増分計算により、長さ 1 のセグメントが特別な大文字と小文字を区別せずに処理されることが保証されます。
