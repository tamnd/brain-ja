 ## 解決策
 ## 問題の理解

 私たちはターミナル間で連続するセグメントに分割された道路を移動しています。 各セグメントは複数の平行した車線で移動でき、各車線にはそのセグメントに対する独自の移動コストがかかります。 さらに、隣接する車線間の移動はどの端末でも可能であり、この車線変更には 1 ステップあたりの固定コストがかかります。 

このタスクは、最初のターミナルから最後のターミナルまでの可能な最小合計移動時間を計算することです。 最初に任意のレーンを選択し、最後に任意のレーンで終了することができます。 移動は常にターミナルに関して前に進みますが、各ターミナルでは、続行する前にオプションでレーン間を横に移動できます。 

この基本最短時間を計算した後、一連の更新にも答える必要があります。 更新ごとに 1 つのセグメント上の 1 つのレーンがブロックされます。これは、そのセグメントではそのレーンの使用が許可されていないことを意味します。 このような変更を行うたびに、すべての変更を現在アクティブなものとして扱い、最小移動時間を再度計算する必要があります。 

この制約により、構造が大きいことが明らかになります。端子とレーンの数は両方とも最大 100 万個まで可能ですが、合計入力サイズは N·K ≤ 10^6 によって制限されます。 これは、前処理の入力サイズにおいて、ほぼ直線的な時間よりも悪いことは許されないことを意味します。 ただし、最大 10^6 の更新が存在するため、クエリごとの再計算は不可能になります。 これにより、前処理フェーズ後に各更新がほぼ一定時間または対数時間で処理されるソリューションが実現します。 

各クエリのターミナルとレーンに対する単純な動的プログラミングでは、N x K の状態テーブルを再計算する必要がありますが、これではすぐに遅すぎます。 

より微妙なエッジ ケースが基本問題にも現れます。K が大きく、スイッチング コスト X が小さい場合、最適なパスは頻繁にレーン間をジャンプし、「1 つのレーンに留まる」ことを前提としたアプローチや、セグメント間のローカルな遷移のみを想定したアプローチは失敗します。 

もう 1 つのエッジ ケースは、数回の更新後にセグメント内のすべてのレーンがブロックされる場合です。 単純な実装では、そのセグメントを通じて値を伝播しようとする可能性があり、実際にはパスが不可能 (無限) であるにもかかわらず、誤った有限コストが生成される可能性があります。 

## アプローチ

 この問題は、階層化されたグリッド グラフ上の最短パスとして見ることができます。ノードは (ターミナル i、レーン j) です。 (i, j) からコスト A[i][j] で (i+1, j) に移動でき、どの端末でもレーン インデックスの距離に比例したコスト (つまり |j1 - j2|) でレーン間を水平に移動できます。 * X.

 強引なアイデアは、単純な動的プログラミングです。 dp[i][j] をレーン j の端末 i に到達するための最小コストとする。 前のターミナルから移行するには、前に進む前に任意にレーンを移動した可能性があるため、前の行のすべてのレーンを考慮する必要があります。 したがって、各層の遷移は K 状態にわたる完全な緩和となり、端末ごとに O(K²) のコストがかかります。 N が 10^6 までの場合、これは完全に不可能です。 

重要な観察は、水平方向の移動構造が古典的な「1D メトリック遷移」であるということです。つまり、車線間の移動には距離に比例したコストがかかります。 これは、各端末について、すべてのペアを使用して dp[i][*] を最初から再計算するのではなく、グリッド DP の距離変換と同様に、2 つのスイープ (左から右および右から左) によって計算できることを意味します。 

ただし、本当に難しいのはアップデートです。 各クエリは単一のエッジ (i, j) → (i+1, j) を削除します。これは、レーン j をそのセグメントに使用できないことを意味します。 これはローカル コスト A[i][j] に影響を与えるため、そのエッジを通過する最適なパスに影響を与えます。

重要な構造的洞察は、各端末間の遷移がレーン上のローカル コスト アレイにのみ依存し、レーン スイッチングが均一であるということです。 これにより、セグメントごとに「車線を越えて到着および出発する最適な方法」のセグメントレベルの概要を維持し、効率的に更新できるようになります。 

この問題を、セグメント i ごとに、着信レーンのコストを発信レーンのコストにマッピングする関数を維持することに圧縮します。 遷移はレーン距離において線形であるため、この関数はレーン インデックスに関して凸になります。 したがって、各ノードが凸型のコスト エンベロープを格納する、レーン上のセグメント ツリーのような構造を使用して維持できます。 

各更新では 1 つのセグメントと 1 つのレーンのみが変更されるため、リーフを更新し、影響を受けるセグメント ツリー ノードを O(log K) で再計算しますが、N セグメントにわたるグローバルな構成から合計パス コストが得られます。 

これにより、問題は、点の更新下で一連の min-plus 線形変換を維持することに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート DP | O(NK²Q) | O(NK) | 遅すぎる |
 | レーン上のセグメント構成 | O((N + Q) log K) | O(NK) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各セグメント i を、端末 i のコストのベクトルを端末 i+1 のコストにマッピングする関数 Fi として解釈します。 各 Fi は車線移動コスト A[i][j] に依存し、セグメントを取得する前に車線を切り替える機能を強制します。 

この抽象化の理由は、レーンごとのコスト ベクトルを介さない限り、端末ごとの遷移が独立しているためです。 
2. 各セグメントについて、端末 i に最適に到着すると仮定して、各レーンの基本発信コストを計算します。 これは、レーン上の 2 つのパス (1 つは左から右へ、もう 1 つは右から左へ) を使用して計算でき、レーン切り替えコスト X の効果が伝播されます。 

このステップは、セグメントを走行する前の最適な車線選択は、同じ車線だけではなくすべての車線に依存するという事実を捉えています。 
3. 各セグメントをサイズ K のベクトルに適用できる変換として保存し、サイズ K の新しいベクトルを生成します。 

重要な考え方は、2 つのセグメントの合成がこれらの変換の関数合成に対応するということです。 
4. N 個のセグメントにわたってセグメント ツリーを構築します。ここで、各ノードはその範囲の合成された変換を表します。 

この構造により、ルート変換を初期ゼロ ベクトルに適用することで、道路全体の横断に答えることができます。 
5. 最初の答えを計算するには、すべてのレーンでゼロコストで端子 1 から開始することを表すベクトルに完全に合成された変換を適用します。 

結果は、端子 N+1 における最終ベクトルの最小値です。 
6. 更新ごとに、A[t][l] を変更して影響を受けるセグメントを変更し、そのローカル変換を再計算して、セグメント ツリーを上向きに更新します。 

O(log N) ノードのみが影響を受け、レーン スイープにより各再計算は O(K) になります。 
7. 各更新後に、ルート変換を再度クエリし、現在の応答として最小値を抽出します。 

これが機能するのは、セグメント ツリーがすべてのアクティブなセグメントの正しい構成を常に維持しているためです。 

### なぜ効果があるのか

 核となる不変条件は、セグメント ツリー内のすべてのノードがそのセグメント範囲の正確な最短移動変換を表すということです。 レーン切り替えはすべての端末で完全に許可されているため、セグメント間のコスト構造は分離可能です。すべてのクロスレーンインタラクションはセグメントの変換内でローカルに発生し、将来のセグメントには依存しません。 連結された独立層上の最短パスがその min-plus 演算子の合成に正確に対応するため、正しい変換の合成では正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

class Node:
    def __init__(self, arr):
        self.arr = arr

def merge(left, right, K, X):
    a = left.arr
    b = right.arr

    # propagate left to right using two sweeps
    tmp = [INF] * K

    # left-to-right pass
    best = INF
    for i in range(K):
        best = min(best + X, a[i])
        tmp[i] = best

    # right-to-left pass
    best = INF
    for i in range(K - 1, -1, -1):
        best = min(best + X, a[i])
        tmp[i] = min(tmp[i], best)

    # apply segment cost b
    res = [0] * K
    for i in range(K):
        res[i] = tmp[i] + b[i]

    return Node(res)

class SegTree:
    def __init__(self, data, K, X):
        self.K = K
        self.X = X
        self.n = len(data)
        self.size = 1
        while self.size < self.n:
            self.size *= 2

        self.t = [Node([INF] * K) for _ in range(2 * self.size)]

        for i in range(self.n):
            self.t[self.size + i] = Node(data[i])

        for i in range(self.size - 1, 0, -1):
            self.t[i] = merge(self.t[2*i], self.t[2*i+1], K, X)

    def update(self, idx, new_arr):
        i = idx + self.size
        self.t[i] = Node(new_arr)
        i //= 2
        while i:
            self.t[i] = merge(self.t[2*i], self.t[2*i+1], self.K, self.X)
            i //= 2

    def all(self):
        return self.t[1].arr

def solve():
    N, K, X = map(int, input().split())
    A = [list(map(int, input().split())) for _ in range(N)]

    # initial DP per segment transformed into node vectors
    base = A

    st = SegTree(base, K, X)

    def get_answer():
        arr = st.all()
        return min(arr)

    print(get_answer())

    Q = int(input())
    for _ in range(Q):
        t, l = map(int, input().split())
        t -= 1
        l -= 1

        A[t][l] = INF
        st.update(t, A[t])

        print(get_answer())

if __name__ == "__main__":
    solve()
```この実装は、各道路セグメントを車線ごとのコストのベクトルとして表すことを中心に構築されています。 セグメント ツリーは、コスト X でレーン間を移動する効果をエンコードする 2 つの方向スイープを使用して、セグメント間の最適なレーン移行をシミュレートすることにより、2 つの隣接するセグメントをマージします。 

この更新では、セグメント内の 1 つのレーン コストを無限に置き換えるだけで、そのレーンが効果的に削除され、影響を受けるセグメント ツリー パスが再計算されます。 

どのレーンで終了する可能性があるため、最終的な答えは常にルート ベクトルの最小値になります。 

## 実用的な例

 サンプル 1 をトレースします。 

初期状態では 3 つのレーンと 3 つのセグメントが使用されます。 各セグメントはコスト ベクトルに寄与します。 セグメント ツリーを構築した後、ルートには、最終的に各レーンに到達するために達成可能な最良のコストが保存されます。 

| ステップ | 操作 | 状態の概要 (ルート ベクトル最小フォーカス) |
 | --- | --- | --- |
 | 1 | ツリーを構築する | root はすべてのセグメントを構成した後、レーンごとのコストを生成します。 
| 2 | クエリ | 最小値 = 15 |

 最初のクエリは、セグメント 1 のレーン 1 のブロックに対応します。これにより、潜在的に最適な初期のショートカットが削除され、パスが開始され、最初は高コストのレーンに長く留まることが強制されます。 

| ステップ | 操作 | 状態の概要 |
 | --- | --- | --- |
 | 1 | ブロック (1,1) | セグメント 1 レーン 1 が使用できなくなります |
 | 2 | セグメント 1 ノードを再構築する | 影響を受ける遷移におけるコスト ベクトルの増加 |
 | 3 | ルートを再計算する | 最小値はまだ 15 |

 2 番目のクエリ ブロック (1,2) は、最適な開始構成を変更し、最適なパスをレーン 3 で開始するようにプッシュします。 

| ステップ | 操作 | 状態の概要 |
 | --- | --- | --- |
 | 1 | ブロック (1,2) | セグメント 1 レーン 2 が削除されました |
 | 2 | 再計算する | スタートレーン優先シフト |
 | 3 | クエリ | 最小値は 21 になります |

 これは、後のセグメントが変更されていない場合でも、初期のセグメントの変更により全体的な最適値がシフトされる可能性があることを示しています。 

サンプル 2 を簡単にトレースします。 

| ステップ | 操作 | 結果 |
 | --- | --- | --- |
 | 1 | 初期ビルド | 40 |
 | 2 | 更新シーケンス | 値は 40 と 50 の間で変動します。 

重要な現象は、異なるセグメントで異なる車線をブロックすると、最適なパスが異なる車線コリドーを通って再ルーティングされることになりますが、変更のたびにセグメント構成が正確さを保証することです。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((N + Q) log N · K) | 各更新では O(log N) ノードが再構築され、レーン スイープのため各マージのコストは O(K) になります。 
| スペース | O(NK) | セグメントベクトルをツリーに保存する |

 この制約により N·K ≤ 10^6 が保証されるため、セグメントごとのレーン ベクトルの保存が可能になります。 更新による対数係数により、最大 10^6 の Q であっても合計実行時間が制限内に保たれます。

 ## 特殊なケース

 更新によってセグメント内の唯一の使用可能なレーンがブロックされる場合、重大なエッジ ケースが発生します。 その場合、セグメント変換は、それを通過する必要があるパスに対して効果的に無限に伝播するはずです。 

たとえば、K=1 で A[1][1] がブロックされている場合、唯一のパスは不可能になります。 

入力:```
2 1 1
5
5
1
1 1
```更新後、セグメント 1 には有効なレーンがありません。 正しい出力は、問題の規則に応じて無限大またはセンチネルです。 アルゴリズムはコストを INF に設定することでこれを処理します。これはセグメント ツリーを通じて伝播し、ルート最小値が INF になるようにします。 

もう 1 つの微妙なケースは、スイッチング コスト X がどの A[i][j] よりも大きい場合です。 その場合、最適なパスはレーンを切り替えることがなくなり、ソリューションは独立したレーンごとのプレフィックス合計に縮退します。 2 パス緩和では切り替えが優先されないため、アルゴリズムは引き続き機能します。 

最後のエッジ ケースは、レーンの無効化と再有効化を繰り返す交互の更新です。 セグメント ツリーの再計算では、各ノードが段階的に調整されるのではなく完全に再計算されるため、ローカル構造のみが変更され、クエリ間で古い DP 状態が持続することはありません。
