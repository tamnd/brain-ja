 ## 問題の理解

 3 つの点を表す、数直線上の 3 つの整数位置が与えられます。 1 回の操作で、これらの点の順序付きペアを選択し、2 番目に選択した点から最初に選択した点に 1 単位の値を移動します。 具体的に、値を持つ点を選択すると、$u$そして$v$、彼らはなる$u+1$そして$v-1$。 

主な効果は、すべての操作で 3 つの値すべての合計が保持されることです。 したがって、3 つの点すべてが最終的に等しくなる唯一の方法は、最終状態が次の場合です。$(x, x, x)$どこ$3x = a+b+c$。 これは、合計が 3 で割り切れる必要があるという必要条件を直ちに暗示します。 

タスクは、そのような変換が可能かどうかを判断し、可能であれば最小操作数を計算することです。 必要に応じて、明示的な一連の操作も出力する必要があります。 

制約により、問題は 2 つの領域に分割されます。 実現可能性のみが必要な場合、値は次の値に達する可能性があります。$10^9$これにより、純粋な算術または不変式ベースの解決策が求められます。 操作を構築する必要がある場合、値は次のように縮小されます。$10^5$これは、演算数が線形である限り、建設的なシミュレーションが許容されることを示唆しています。 

単純なアプローチでは、任意の転送をシミュレートするか、可能な中間状態を検索しようとします。 状態空間は継続的に増大し、操作は任意にインターリーブされる可能性があるため、これはすぐに失敗します。 

より微妙な失敗例は、合計が 3 で割り切れる場合、常に割り切れる可能性があると仮定することです。 これは真実ですが、それは点間の不均衡をどのように再配分できるかを正しく理解している場合に限られます。 

具体的なエッジケースは、2 つの値がすでに等しいが、3 番目の値が遠く離れている場合です。$a=1, b=1, c=100$。 ペアごとに均等化しようとする不用意な戦略は、正しい答えが存在する場合でも、発振したり、効率的に収束できなかったりする可能性があります。 

もう 1 つの特殊なケースは、3 つの値がすべてすでに等しい場合です。 その場合、操作は必要なく、アルゴリズムはこれを早期に検出する必要があります。 

## アプローチ

 ブルートフォースのアイデアは、各状態をグラフ内のノードとして扱い、各操作が状態間を遷移するというものです。 州を超えた BFS は最終的に平等への道を見つけるでしょう。 ただし、座標は無制限の整数であるため、状態空間は両方向に無限です。 到達可能な合計に制限しても巨大な暗黙的なグラフが生成されるため、このアプローチは実行不可能になります。 

重要な観察は、この操作により 1 つの単位が 1 つの座標から別の座標に移動されるため、システムは合計質量を 3 つのビンに分配するように動作するということです。 最終状態は正確に各ビンの平均値である必要があるため、各座標は次の値に向けて調整する必要があります。$(a+b+c)/3$。 

グローバルに検索する代わりに、いつでも貪欲に不均衡を修正できます。 1 つの値が目標を下回っている場合は、目標を上回る任意の値を取得してその値を増やす必要があります。 これにより、黒字から赤字へのユニットの決定的な流れが生まれます。 各操作は、ターゲット構成からの絶対偏差の合計を厳密に削減します。 

これにより、すべてのバランスがとれるまで不足要素と余剰要素を繰り返しペアにするという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 1. 合計を計算する$S = a+b+c$。 もし$S \not\equiv 0 \pmod 3$、すぐに不可能と結論付けます。 すべての操作で合計が保持されるため、これが必要になります。 
2. 目標値を計算する$x = S / 3$。 これが唯一可能な最終状態です。 
3. 3 つのポジションをそれぞれ、上、同等、下に応じて黒字、中立、赤字に分類します。$x$。 これにより転送の方向が決まります。 
4. すべての値が等しいわけではありませんが、$x$、任意のインデックスを選択します$i$以下の値を持つ$x$そして任意のインデックス$j$上記の値を持つ$x$から 1 つのユニットを移動する 1 つの操作を実行します。$j$に$i$。 これにより、目標状態からの全体的な偏差が直接減少します。 
5. 各操作を順序付きペアとして記録する$(i, j)$選択した転送に対応します。 
6. 3 つの値がすべて正確になるまで繰り返します。$x$。 各操作により少なくとも 1 単位の不均衡が軽減されるため、プロセスは終了する必要があります。 

### なぜ効果があるのか

 不変条件は、合計が一定のままであり、すべての操作で達成可能性が維持されることです。$(x, x, x)$。 各ステップで量を厳密に減らします$|a-x| + |b-x| + |c-x|$, 黒字要素から赤字要素に 1 単位を移動するためです。 この量は負ではなく、操作ごとに 2 ずつ減少します (余剰から 1 が削除され、不足に 1 が追加されます)。そのため、最終的にはゼロに達する必要があり、その時点ですべての座標が等しくなります。$x$。 これにより、終了と移動数の最適性の両方が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input().strip())
    a, b, c = map(int, input().split())

    arr = [a, b, c]
    s = sum(arr)

    if s % 3 != 0:
        print("No")
        return

    x = s // 3

    ops = []

    def take(i, j):
        arr[i] += 1
        arr[j] -= 1
        ops.append((i + 1, j + 1))

    for _ in range(10**5):
        if arr[0] == arr[1] == arr[2]:
            break

        hi = max(range(3), key=lambda i: arr[i])
        lo = min(range(3), key=lambda i: arr[i])

        if arr[hi] == arr[lo]:
            break

        take(lo, hi)

    if arr[0] == arr[1] == arr[2]:
        print("Yes")
        print(len(ops))
        if t == 1:
            for u, v in ops:
                print(u, v)
    else:
        print("No")

def main():
    solve()

if __name__ == "__main__":
    main()
```実装では、最初に割り算条件をチェックし、ターゲットを暗黙的に計算します。 の`take`関数は、有向ペアの記録を含め、定義どおりに操作を適用します。 

ループは常にグローバル最小値とグローバル最大値を選択し、ステップごとの不均衡の最大限の削減を保証します。 これにより、赤字セットと剰余セットの明示的な簿記が不要になります。 

人為的な反復上限は、各操作が全体の不均衡を軽減し、建設的な場合に制限された整数値を使用すると、初期の広がりに対して線形時間で収束が起こるため、安全です。 

微妙な点は、正確なターゲット値に向けて移動を明示的に強制するのではなく、常に最小値と最大値の間であることです。 均一ではない構成には少なくとも 1 つの厳密な最小値と最大値が必要であるため、これで十分です。

 ## 特殊なケース

 重要な特殊ケースの 1 つは、3 つの数値がすべて等しい場合です。 アルゴリズムは、操作を実行せずに直ちに終了する必要があります。 入力用`0 0 0`、状態はすでに条件を満たしているため、出力は次のようになります。`Yes`操作はゼロです。 

もう 1 つのケースは、2 つの値が等しく、3 番目の値が 3 の倍数だけオフセットされている場合です。たとえば、`1 1 4`。 アルゴリズムは 4 から 1 に向かって繰り返し移行し、各ステップの後、すべての値が一致するまでスプレッドが減少します。 min-max 戦略により、発振が発生しないことが保証されます。 

3 番目のケースは、値がすでに緊密にクラスター化されているが等しくない場合です。`10 11 12`。 12 から 10 への 1 回の移行により範囲が減少し、もう 1 回のバランス調整ステップの後にすぐに均一性が得られます。
