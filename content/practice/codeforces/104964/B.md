 ## 解決策
 ## 問題の理解

 建物の列が与えられ、各建物はある整数の高さに配置されたセンサーを受信する必要があります。 建築用$i$、選択した高さ$d_i$独自の間隔内に限定されます$[a_i, b_i]$。 すべての高さを選択すると、構成のコストは、隣接するセンサー間の絶対差の合計をラインに沿って合計したものになります。$|d_1-d_2| + |d_2-d_3| + \dots + |d_{n-1}-d_n|$。 タスクは、この合計を最小化する有効な高さを選択することです。 

構造は逐次的です。各決定は、絶対的な差を通じてのみ隣接する決定と相互作用します。 隣接しない位置をリンクするグローバルな制約はありませんが、ある位置での選択は、次の間隔からの距離に影響するため、将来のすべてのコストに間接的に影響します。 

入力サイズにより、テストごとに線形または線形に近い動作が行われます。 の合計$n$すべてのテストの上限は$10^6$したがって、それ以上の解決策はありません。$O(n \log n)$テストごとに、重い遷移が繰り返されることでタイムアウトになるリスクがあります。 サイズの配列だけが必要なのでメモリは簡単です$n$。 

素朴な落とし穴は、私たちが独立して選択できると仮定していることです$d_i$内部の任意の値として$[a_i, b_i]$左から右へ貪欲に局所的な差異を最小限に抑えます。 これは、局所的に最適な選択により後で大きなジャンプが強制される場合には失敗します。 

たとえば、間隔について考えてみましょう。$$[0, 10], [5, 5], [0, 10]$$貪欲に選んでみたら$d_1 = 0$、 それから$d_2 = 5$、 それから$d_3 = 0$、コストがかかります$5 + 5 = 10$。 しかし、もし私たちが選択するなら$d_1 = 5$、 それから$d_2 = 5$、 それから$d_3 = 5$、費用は$0$。 最初のステップの選択によって、将来の遷移をフラット化できるかどうかが決まります。 

したがって、重要な問題は、各ポジションが以前の選択と独自の許容インターバルの両方に近いバランスをとる必要があることです。 

## アプローチ

 強引な見方では、各位置で次のことを考慮します。$i$で任意の整数を選択できます。$[a_i, b_i]$、そしてペアごとのコストのグローバル合計を最小限に抑えたいと考えています。 これは動的プログラミングの定義を示唆しています。$dp[i][x]$ポジションまでの最小コストになる$i$value で終了する場合$x$。 あらゆる以前の状態からの移行$x$あらゆる可能性のある流れに$y$につながる$$dp[i][y] = \min_{x \in [a_{i-1}, b_{i-1}]} dp[i-1][x] + |x-y|.$$値を離散化したとしても、間隔のサイズは最大で大きくなる可能性があります。$10^9$、これを明示的に計算することは不可能になります。 値を圧縮したとしても、最悪の場合、遷移は 2 次になります。 

重要な観察は、完全な関数は決して必要ないということです。$dp[i][x]$。 重要なのは、絶対値コストを伴う前の間隔から新しい間隔への移行が、_最良の代表点を前方に押し出す_ ことで要約できることです。 どの段階でもプレフィックスの最適な構成を実現$1..i-1$単一の値として要約できる$d_{i-1}$なぜなら、最終的に選択した値を位置で固定すると、$i-1$、未来はそのエンドポイントにのみ依存し、どのようにしてそこに到達したかには依存しません。 

これは一見しただけでは明らかではありませんが、コストは独立したエッジの寄与の合計であるという事実からわかります。 固定の場合$d_{i-1}$、最適な$d_i$は単に次の値に最も近い値です$d_{i-1}$内部$[a_i, b_i]$、 なぜなら$|d_{i-1}-d_i|$今後のステップとは関係なく最小化されます。 

したがって、グローバル問題は、前の値を次の区間に繰り返し投影することに分解されます。

 ## アルゴリズムのチュートリアル

 前の建物で選択した高さを維持しながら、建物を左から右に処理します。 

1. 最初の建物から始めます。 の任意の値$[a_1, b_1]$有効です。 私たちが選ぶ$d_1 = a_1$なぜなら、事前に考慮すべきコストがないからです。 
2. 次の建物ごとに$i$、以前に選択した高さを比較します$d_{i-1}$間隔を置いて$[a_i, b_i]$。 
3. もし$d_{i-1}$間隔の内側にあるので、設定します$d_i = d_{i-1}$。 これにより移行コストがゼロになり、今後のステップに役立たないため、移行する理由がありません。 
4. もし$d_{i-1} < a_i$、設定しました$d_i = a_i$。 これは、左側の境界に最も近い実行可能な点であり、$|d_{i-1}-d_i|$。 
5. もし$d_{i-1} > b_i$、設定しました$d_i = b_i$。 これにより、上からの間隔までの距離が対称的に最小化されます。 
6. コストを蓄積する$|d_{i-1} - d_i|$各ステップで。 

このアルゴリズムは、常に前の値に最も近い実現可能な値を選択しながら、有効なシーケンスを構築します。 

### なぜ効果があるのか

 各ステップで唯一関与するのは、$d_i$それは未来次第です、それが次の違いです$|d_i - d_{i+1}|$。 ただし、ステップに到達すると、$i$、間隔内の値はすべて将来のステップで同様に利用可能であり、将来の間隔では現在の位置のみが考慮され、どのようにしてそこに到着したかは考慮されません。 したがって、即時の遷移距離を最小限にしても、将来の最適性が犠牲になることはありません。 最適な構造は、前の値を次の許容間隔に繰り返し投影することになります。これは、逸脱しても、将来のステップの実現可能性や柔軟性が向上することなく、現在のコストが増加するだけであるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        d = [0] * n
        d[0] = a[0]
        total = 0

        for i in range(1, n):
            if d[i - 1] < a[i]:
                d[i] = a[i]
            elif d[i - 1] > b[i]:
                d[i] = b[i]
            else:
                d[i] = d[i - 1]

            total += abs(d[i] - d[i - 1])

        print(total)
        print(*d)

if __name__ == "__main__":
    solve()
```このソリューションは、実行中の選択された値を保持し、現在の間隔を超えた場合にのみ調整します。 コストは段階的に蓄積されます。 重要な微妙な点は、等しい場合が重要であるということです。前の値が正確に区間内にある場合、コストゼロの遷移を維持するために、それを変更しないようにする必要があります。

            n = int(input())
            a = list(map(int, input().split()))
            b = list(map(int, input().split()))

            out.append(str(total))
            out.append(" ".join(map(str, d)))
        return "\n".join(out)

    return solve()

 エッジ ケースの 1 つは、すべての間隔が 1 つの点で重なる場合です。 例えば：```
n = 4
a = [5, 5, 5, 5]
b = [5, 5, 5, 5]
```一歩ごとに力がかかる$d_i = 5$。 このアルゴリズムは、唯一の実現可能な値を即座にロックし、遷移ごとにゼロコストを蓄積します。 投影では常に同じ点が返されるため、あいまいさはありません。 

もう 1 つのケースは、間隔が厳密に減少しているため、各ステップで境界ジャンプが強制される場合です。```
a = [0, 10, 20]
b = [0, 10, 20]
```ここで、前の値は常に右側の次の間隔の外側にあるため、各間隔の右側の端点に向かって繰り返し下向きに投影し、確定的なステップ コストを累積します。 貪欲ルールでは常に最も近い境界が選択されるため、中間の選択肢が後の距離を短縮できないため、各遷移コストは隣接する間隔間の正確なギャップに等しく、最適解と一致します。
