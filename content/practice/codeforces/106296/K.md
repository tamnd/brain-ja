 ## 解決策
 ## 問題の理解

 この問題では、隠れた 10 進数のシーケンスが得られます。 非対話形式では、数字列全体を入力として使用できます。 この文字列の中に、数値が 3 で割り切れる連続部分が少なくとも 1 つ存在するかどうかを判断する必要があります。出力は次のようになります。`1`そのような部分文字列が存在する場合、および`0`さもないと。 

重要な特性は、3 で割り切れるかどうかは桁の合計にのみ依存するということです。 部分文字列が 3 で割り切れるのは、その桁の合計が 3 で除算した後に 0 が残る場合です。 

元のステートメントの文字列の長さは短いですが、意図したアイデアは拡張できるはずです。 長さがこのくらいだったら`10^5`、すべての部分文字列をチェックするソリューションではすでに遅すぎます。 くらいあります`n^2`可能な部分文字列、および`n = 10^5`これはおおよその意味になります`10^10`通常の制限時間をはるかに超えたチェック。 文字列を一度処理するソリューションが必要です。 

厄介なケースは、明らかな 1 桁ではない部分文字列から発生します。 例えば：```
Input
2
12

Output
1
```数字`1`単独では 3 で割り切れず、`2`単独では 3 で割り切れませんが、部分文字列`12`桁の合計があります`3`、それでうまくいきます。 個々の数字だけをチェックするソリューションは失敗します。 

別のケースは次のとおりです。```
Input
3
111

Output
1
```単一の数字は機能しませんが、文字列全体には合計があります`3`。 1 桁の答えが見つからずに停止する方法は間違っています。 

境界ケースは次のとおりです。```
Input
3
124

Output
0
```3 を法とする接頭辞の合計はすべての位置で異なり、接頭辞自体に残り 0 があるものはないため、有効な部分文字列は存在しません。 

## アプローチ

 ブルートフォースアプローチは、考えられるすべての部分文字列を試し、その桁の合計を計算し、その合計が 3 で割り切れるかどうかを確認することです。考えられるすべての候補が検査されるため、これは正しいです。 プレフィックス合計配列を使用すると、各部分文字列のチェックを定数時間で実行できますが、それでも`O(n^2)`部分文字列。 入力が大きい場合、これは遅くなりすぎます。 

重要な観察は、実際の合計は必要なく、3 を法とした剰余だけが必要であるということです。`pref[i]`最初の合計になる`i`3 を法とする数字。次の部分文字列の合計。`l`に`r`は：`pref[r] - pref[l - 1]`2 つの接頭辞の合計の余りが同じ場合、その差は 3 で割り切れます。その差は、桁の合計が 3 で割り切れる部分文字列に対応します。 

これにより、問題は、左から右にスキャンしながら、以前にそれぞれの残りを見たかどうかの追跡に変わります。 剰余が繰り返される場合、2 つの位置の間のセクションが有効な部分文字列となります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 大きな入力には遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 数字列を読み取り、プレフィックスの残りから開始します。`0`。 これは、文字列が始まる前の空のプレフィックスを表します。 
2. 出現したプレフィックスの残りを含む配列またはセットを保持します。 最初は残りだけ`0`空のプレフィックスの桁合計が 0 であるため、「」が表示されます。 
3. 文字列を左から右にトラバースします。 現在の数字を累計に加算し、それを剰余として減算します。`3`。 
4. この剰余が以前にすでに出現している場合、前の出現位置と現在の位置との間の部分文字列は、次の数で割り切れる桁の合計を持ちます。`3`、したがって、答えは次のとおりです`1`。 
5. それ以外の場合は、この残りを記録し、スキャンを続行します。 
6. 繰り返しの残りが見つからずに文字列全体が処理された場合は、次のように出力されます。`0`。 

なぜ効果があるのか:

 実行剰余は、現在の位置で終わるプレフィックスの桁の合計を表します。 同じ剰余が 2 回出現するたびに、2 つのプレフィックスの合計を減算すると共通部分が削除され、合計が 3 で割り切れる部分文字列が残ります。スキャン中に考えられるすべての終了位置がチェックされるため、アルゴリズムは有効な部分文字列が存在する場合はそれを見つけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = sys.stdin.read().split()
    if not data:
        return

    if len(data) == 1:
        s = data[0]
    else:
        s = data[1]

    seen = [False, False, False]
    seen[0] = True
    cur = 0

    for ch in s:
        cur = (cur + ord(ch) - ord('0')) % 3
        if seen[cur]:
            print(1)
            return
        seen[cur] = True

    print(0)

if __name__ == "__main__":
    solve()
```このコードは、考えられる 3 つのプレフィックスの残りのみを保存するため、プレフィックス配列は必要ありません。 の`seen`剰余がどこに出現したかではなく、剰余が出現したかどうかだけを気にするので、配列で十分です。 

による初期化`seen[0] = True`最初の桁から始まる部分文字列を処理します。 これがないと、桁の合計がすでに 3 で割り切れるプレフィックスは失われます。 

モジュロ演算はすべての桁が加算された後に実行され、実行中の値が小さく保たれ、不必要な整数の増加が回避されます。

## テストケース```python
import sys
import io

def solve_case(inp: str) -> str:
    data = inp.split()
    s = data[1] if len(data) > 1 else data[0]

    seen[0] = True
    cur = 0

        if seen[cur]:

 ## 特殊なケース

 部分文字列の場合`12`、アルゴリズムは剰余から始まります`0`、プロセス`1`そして残りを保管します`1`、その後、プロセス`2`そして残りを取得します`0`また。 残りなので`0`はすでに見られており、2 つの位置間の部分文字列は有効であり、答えは次のとおりです。`1`。 

文字列の場合`111`、実行中の剰余は`1`、`2`、 そして`0`。 最後の位置は剰余 0 に達します。これは、文字列全体が桁の合計を持つことを意味します。`3`。 初期に保存されたゼロの剰余により、アルゴリズムがこれを検出できるようになります。 

のような文字列の場合`124`、アルゴリズムは最初の 2 桁を読み取った後、繰り返されるゼロの残りを検出します。`1 + 2 = 3`。 これは、プレフィックスの残りが 1 桁ではない部分文字列を捕捉する理由を示しています。
