 ## 解決策
 ## 問題の理解

 重み付けされたツリーがあります。 各エッジはパスの一部を表し、コストがあります。 2 つの頂点間の移動は、頂点間の固有のパスに従い、その距離はそのパス上のエッジ コストの合計になります。 一部のパズルでは、一連のエッジから情報を収集する必要があります。 ジャーニーは、ジャーニー上に必要なエッジが少なくとも 1 つあるすべてのパズルについて、そのパズルの必要なエッジがすべてジャーニー上にある場合に成功します。 目標は、成功したすべての移動の距離を合計することです。 

入力によりツリーが生成され、その後に多くのパズルが続きます。 すべてのパズルにわたるエッジ参照の総数は制限されており、これが重要な制限です。 ノードとパズルの数はそれぞれ 100 万に達する可能性がありますが、パズル データの総量も 100 万にすぎないため、どのソリューションでも各エッジ参照を少数回処理するだけで済みます。 すべての頂点のペアをチェックするアプローチでは、最大のツリーに対してすでに約 10^12 の操作が必要になりますが、これは不可能です。 すべての頂点から開始する走査でも、二次関数になるためコストがかかりすぎます。 

中心的な問題は、パズルが単一のエッジを禁止していないことです。 必要なセットの一部だけを取得することを禁止します。 たとえば、パズルに 2 つのエッジが必要で、パスにそのうち 1 つしか含まれていない場合、そのパスは失敗します。 隠された構造は、強制的に一緒に表示されるエッジをグループ化することで得られます。 

よくある間違いは、すべてのパズルを個別に処理し、危険に見えるエッジを削除してしまうことです。 制約が結合する可能性があるため、これは失敗します。 1 つのパズルにエッジ 1 と 2 が含まれ、別のパズルにエッジ 2 と 3 が含まれているとします。この場合、3 つすべてを含むパズルは 1 つもありませんが、エッジ 1、2、3 はすべて強制的に結合されます。 

次の入力を考えてみましょう。```
4 1
1 2 1
2 3 1
3 4 1
2 1 2
```パズルには 2 番目と 3 番目のエッジが必要です。 成功する旅は、どちらか 1 つだけを使用することはできません。 有効な答えは、これらのエッジのどちらも使用しないパスと両方を使用するパスの合計です。 2 番目のエッジのみを削除するソリューションでは、ノード 2 からノード 3 へのパスが誤って許可されてしまいます。 

もう 1 つのエッジ ケースは、強制エッジが分岐する場合です。 例えば：```
4 1
1 2 1
1 3 1
1 4 1
3 1 2 3
```必要なエッジは単純なパスではなくフォークを形成します。 木道は決して分岐しないため、どの旅にも 3 つのエッジがすべて含まれることはありません。 これらのエッジのいずれかを使用するすべてのジャーニーは拒否されなければなりません。 

## アプローチ

 ブルート フォースのアプローチでは、頂点のすべてのペアをテストします。 各ペアについて、パスを見つけ、そのパスに触れたパズルを収集し、触れたすべてのパズルにすべてのエッジが存在するかどうかを確認します。 これは定義に直接従うため、正しいです。 問題は仕事量です。 最大 N^2 のペアがあり、1 回のチェックが一定時間だったとしても、これは約 10^12 回の演算になります。 

有益な観察は、パズルはエッジを接続するだけであるということです。 同じパズルに 2 つのエッジが表示される場合、有効なパスには両方が含まれるか、どちらも含まれない必要があります。 この関係は推移的であるため、相互に依存するすべてのエッジを素集合結合構造を持つグループにマージできます。 

マージ後、すべてのグループは、常に一緒に移動する必要がある一連のエッジを表します。 グループは、そのエッジがツリー内の 1 つの単純なパスを形成する場合にのみ使用できます。 グループが分岐すると、有効なジャーニーはそのグループ内のエッジを使用できないため、それらのエッジは削除されます。 残りのすべてのグループは、重みが元の重みの合計である単一の重み付きエッジに圧縮できます。 

元の問題ははるかに単純になります。 有効なエッジの森があります。 この森の中の道はすべて、元の木の成功した旅に正確に対応します。 答えは、有効なエッジで接続されている頂点のすべてのペアにわたる距離の合計です。 これはツリー DP スタイルの累積によって計算できます。エッジを処理するときに、エッジの片側に`s`頂点とその他の頂点が含まれます`n-s`頂点の場合、そのエッジは、そのエッジを横切るペアの数を乗じた重みに寄与します。 

ブルートフォース手法は、すべてのパスを明示的に検証するため機能します。 パスが多すぎるため失敗します。 グループ化の観察により、どのエッジが有効なパスに参加できるかを見つける問題が軽減され、標準の重み付きツリー寄与計算によってジョブが完了します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) 以上 | O(N) | 遅すぎる |
 | 最適 | O((N + K) α(N)) | O(N + K) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーのエッジ上に素の集合和集合構造を作成します。 すべてのパズルについて、そのパズルに属するすべてのエッジを 1 つのコンポーネントにマージします。 その理由は、これらすべてのエッジはすべての有効な旅において切り離せないからです。 
2. すべてのエッジ コンポーネントについて、元のツリー内の形状を決定します。 コンポーネントが接触した頂点の数と、コンポーネント内の接触した各頂点の次数をカウントします。 接続されたエッジ セットは、次数 1 の 2 つの端点がある場合、または単一のエッジである場合に正確にパスになります。 頂点の次数が 2 を超えるコンポーネントは使用できません。 
3. 使用できないコンポーネントを削除し、使用可能なすべてのコンポーネントを 1 つのエッジに圧縮します。 新しいエッジは古いパスの 2 つの端点を接続し、そのパス内の重みの合計に等しい重みを持ちます。 
4. 残りのフォレスト上でトラバースを実行します。 圧縮されたエッジごとに、カットの片側のサイズを計算します。 エッジに重みがある場合`w`そして分離します`s`からの頂点`N-s`頂点、追加`w * s * (N-s)`答えに。 
5. 累積値のモジュロを出力します。`10^9 + 7`。 

機能する理由: 部分的なコンポーネントではパズルが不完全なままになるため、有効なすべてのジャーニーにはパズルのコンポーネント全体が含まれている必要があります。 マージ後の成功したパスは、まさに圧縮されたフォレスト内のパスになります。 無効なコンポーネントは分岐するため、どのパスにも表示されません。 残りのすべてのエッジについて、そのエッジによって分離されたすべてのペアはそのエッジを 1 回だけ使用するため、その寄与は正確にエッジの重みに交差するペアの数を乗算したものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]

def solve():
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)

    n = int(next(it))
    m = int(next(it))

    edges = []
    adj = [[] for _ in range(n)]
    for i in range(n - 1):
        a = int(next(it)) - 1
        b = int(next(it)) - 1
        w = int(next(it))
        edges.append((a, b, w))
        adj[a].append((b, i))
        adj[b].append((a, i))

    dsu = DSU(n - 1)
    puzzles = []

    for _ in range(m):
        k = int(next(it))
        cur = []
        for _ in range(k):
            cur.append(int(next(it)) - 1)
        if cur:
            first = cur[0]
            for e in cur[1:]:
                dsu.union(first, e)
        puzzles.append(cur)

    comp_edges = {}
    for i in range(n - 1):
        r = dsu.find(i)
        comp_edges.setdefault(r, []).append(i)

    edge_deg = {}
    usable = {}
    weight = {}

    for root, es in comp_edges.items():
        deg = {}
        total = 0
        for e in es:
            a, b, w = edges[e]
            total += w
            deg[a] = deg.get(a, 0) + 1
            deg[b] = deg.get(b, 0) + 1
        ok = True
        ends = []
        for v, d in deg.items():
            if d > 2:
                ok = False
                break
            if d == 1:
                ends.append(v)
        if ok and (len(ends) == 2 or (len(es) == 1 and len(ends) == 2)):
            usable[root] = ends
            weight[root] = total

    new_adj = [[] for _ in range(n)]
    for root, ends in usable.items():
        a, b = ends
        w = weight[root]
        new_adj[a].append((b, w))
        new_adj[b].append((a, w))

    ans = 0
    seen = [False] * n

    for start in range(n):
        if seen[start]:
            continue
        stack = [(start, -1, 0)]
        order = []
        seen[start] = True
        while stack:
            v, p, _ = stack.pop()
            order.append((v, p))
            for u, w in new_adj[v]:
                if u != p:
                    seen[u] = True
                    stack.append((u, v))

        size = {v: 1 for v, _ in order}
        for v, p in reversed(order):
            if p != -1:
                size[p] += size[v]

        for v, p in order:
            if p != -1:
                for u, w in new_adj[v]:
                    if u == p:
                        s = size[v]
                        ans = (ans + (s * (n - s) % MOD) * (w % MOD)) % MOD
                        break

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```依存関係はパズルのピース間にあるため、DSU は頂点ではなくエッジで機能します。 すべてのパズルは、参照されているエッジをマージし、一緒に維持する必要がある最大のグループを作成します。 

コンポーネント検証ステップでは、グループがツリー パスとして表示できるかどうかを確認します。 パスには内部分岐がないため、次数が 2 を超えると、グループは直ちに不可能になります。 端点は、圧縮されたエッジがツリーの残りの部分に接続できる唯一の頂点です。 

最後の走査では、使用可能なエッジのフォレスト内のサブツリーのサイズが計算されます。 各エッジについて、それを使用するペアの数は、その 2 つの辺のサイズの積になります。 乗算は必要な値を法として行われ、Python の整数はオーバーフローの問題を回避します。

 ## 特殊なケース

 単一の必須エッジの場合、アルゴリズムはそのエッジのみを含むコンポーネントを作成します。 これは有効なパスですが、それを使用するすべてのジャーニーにはコンポーネント全体も含める必要があり、これはすでに当てはまります。 貢献度は通常、エッジ交差式によってカウントされます。 

重複するパズルの場合、DSU マージ ステップが間違いを防ぐものです。 1 つのパズルがエッジ A と B をリンクし、別のパズルがエッジ B と C をリンクする場合、コンポーネントには A、B、および C が含まれます。A と B のみを使用するパスは、マージされた依存関係全体が含まれていないため、拒否されます。 

分岐部品については、次数チェックによりあり得ない形状を検出します。 ツリー パスは同じ頂点からの 3 つの分岐を訪問できないため、カウントする前にそのコンポーネント内のすべてのエッジが削除されます。 

分離された有効なコンポーネントの場合、最後のトラバーサルでは、残りの接続された各部分が個別に処理されます。 異なるコンポーネント内のノード間には使用可能なパスがないため、合計に寄与することはありません。
