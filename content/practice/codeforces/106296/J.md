 ## 解決策
 ## 問題の理解

 整数のコレクションが与えられ、ビットごとのルールによって引き起こされる接続性を理解することが求められます。 それぞれの数値は、グラフ内のノードとして考えることができます。 2 つのノードは、それらのビットごとの AND がゼロ以外の場合に接続されています。これは、両方が 1 を持つ少なくとも 1 つのビット位置を共有していることを意味します。 

これらの接続を考慮したら、結果のグラフに含まれる接続コンポーネントの数を決定する必要があります。 

主な難点は、グラフが明示的に構築されていないことです。 入力が大きい場合、すべてのペアをチェックするのは遅すぎるため、ビット パターンから構造を推測する必要があります。 

複雑さの観点から見ると、最大約 2×10^5 の数値がある場合、すべてのペアをチェックする二次解法には約 10^10 の演算が必要になりますが、これは 2 秒での実用的な制限をはるかに超えています。 すべてのエッジを明示的に構築することさえ不可能です。 これにより、ペアごとの推論を回避し、代わりにビット表現の構造を活用することが直ちに強制されます。 

いくつかの特殊なケースは見落とされがちです。 

すべての数値がゼロの場合、設定ビットを共有する 2 つのノードはないため、すべてのノードが分離されます。 たとえば、入力`[0, 0, 0]`3 つのコンポーネントを生成する必要があります。 

すべての数値が同一でゼロでない場合、すべてのノードは他のすべてのノードと少なくとも 1 ビットを共有するため、答えは 1 でなければなりません。 

ゼロとゼロ以外の値が混在している場合、ゼロが何にも接続されることはありませんが、ゼロ以外の値は依然として大きな接続構造を形成する可能性があります。 

微妙なケースは、数値がペアごとに直接重複せず、中間値を介して推移的に接続される場合に発生します。 例えば、`2 (010)`、`4 (100)`、`6 (110)`たとえ単一のコンポーネントを形成していても、`2 & 4 = 0`、両方とも経由で接続するため、`6`。 

## アプローチ

 ブルート フォース ソリューションでは、数値のすべてのペアをチェックし、AND がゼロ以外の場合にエッジを追加することで完全なグラフを構築します。 次に、DFS または BFS が接続されたコンポーネントをカウントします。 これは接続の定義を直接シミュレートするため、これは正しいです。 

ただし、ペアワイズチェックがボトルネックです。 と`n`要素、あります`n(n-1)/2`それぞれの比較にはビット単位の演算が必要です。 のために`n = 2×10^5`、これは大きすぎます。 たとえエッジ構築が可能だったとしても、密なグラフ上でグラフ走査を実行するとコストも高くなります。 

重要な点は、AND 条件が共有ビットのみに依存するということです。 数値を相互に比較する代わりに、数値を含まれるビットごとにグループ化できます。 すべての数値は、設定されたビットごとに 1 つずつ、複数のビット グループに属します。 特定のビットを共有するすべての数値を接続すると、ゼロ以外の AND を持つペアは同じ接続構造になります。 

これにより、問題はペアに関する推論からビットに関する推論に変換されます。 各ビットはハブとして機能します。そのビットを含むすべての数値は同じ共用体に属します。 最終的な連結コンポーネントは、まさにこれらの結合によって形成された連結コンポーネントです。 

素のセット共用体構造を使用してこれを効率的に実装し、特定のビットを共有するすべてのインデックスをマージできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースペアチェック | O(n²) | O(1) 追加 (または O(n²) グラフ) | 遅すぎる |
 | ビット単位の DSU グループ化 | O(n · B α(n)) | O(n + B) | 承認済み |

 ここ`B`値を表すために必要なビット数で、通常は約 20 ～ 30 です。 

## アルゴリズムのチュートリアル

 1. 各数値が独自のコンポーネントで始まる、素のセット共用体構造を初期化します。 これは接続が想定されていない状態を表します。 
2. 0 から最大関連ビットまでの各ビット位置について、番号にそのビットが含まれるインデックスのリストを維持します。 これにより、ノードをペアごとに比較するのではなく、共有された構造的特徴によってグループ化します。 
3. すべてのビットについて、複数の数値が含まれている場合は、DSU 共用体を使用して、それらすべてを 1 つの接続されたグループにマージします。 これを行うには、リストの最初の要素を代表として取り、それを同じリスト内の他のすべての要素と結合します。 
4. すべてのビットを処理した後、個別の DSU ルートがいくつ残っているかを計算します。 各ルートは 1 つの連結成分に対応します。 

各ビット内でのマージが有効である理由は、ビットを共有する 2 つの数値がエッジによって直接接続されることが保証されるためです。 それらがマージされると、union-find の推移性により、共有ビットのチェーンも確実に接続されます。 

### なぜ効果があるのか

 各数値は、少なくとも 1 つの共通ビットを共有するすべての数値に接続されます。 2 つの数値がビットを共有する場合、そのビットのグループ化によってそれらは強制的に同じコンポーネントに組み込まれます。 ビットを直接共有せず、中間番号を介して接続できる場合、それらの中間はチェーンを形成するビットを共有する必要があります。 DSU は、ビット共有関係上でこの推移閉包を正確に保持します。これは、AND 条件で定義されたグラフの接続性と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    dsu = DSU(n)

    bit_to_nodes = [[] for _ in range(32)]

    for i, val in enumerate(a):
        for b in range(32):
            if val & (1 << b):
                bit_to_nodes[b].append(i)

    for b in range(32):
        nodes = bit_to_nodes[b]
        for i in range(1, len(nodes)):
            dsu.union(nodes[0], nodes[i])

    roots = set(dsu.find(i) for i in range(n))
    print(len(roots))

if __name__ == "__main__":
    solve()
```DSU 実装では、サイズによるパス圧縮と結合を使用して、操作を効果的に一定に保ちます。 ビット グループ化ステップにより、エッジを明示的に探索するのではなく、直接的な構造的理由が存在する場合にのみ結合を実行することが保証されます。 

ビットに対するループは固定サイズであるため、主なコストは各ビットに含まれる数値の数に比例し、一般的な制約の下では効率的です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · B α(n)) | 各数値は最大 B ビット リストに寄与し、DSU 結合はほぼ定数時間です。 
| スペース | O(n + B) | DSU アレイとビット バケット |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    class DSU:
        def __init__(self, n):
            self.p = list(range(n))
        def f(self, x):
            while self.p[x] != x:
                self.p[x] = self.p[self.p[x]]
                x = self.p[x]
            return x
        def u(self, a, b):
            a, b = self.f(a), self.f(b)
            if a != b:
                self.p[b] = a

    n = int(input())
    a = list(map(int, input().split()))
    d = DSU(n)
    bits = [[] for _ in range(32)]
    for i, v in enumerate(a):
        for b in range(32):
            if v & (1 << b):
                bits[b].append(i)
    for b in range(32):
        for i in range(1, len(bits[b])):
            d.u(bits[b][0], bits[b][i])
    return str(len({d.f(i) for i in range(n)}))

# minimal
assert run("1\n5\n") == "1"

# all zero
assert run("3\n0 0 0\n") == "3"

# all same non-zero
assert run("4\n7 7 7 7\n") == "1"

# chain connectivity
assert run("3\n2 4 6\n") == "1"

# disjoint bits
assert run("3\n1 2 4\n") == "3"

 ## 特殊なケース

 完全にゼロで構成される入力の場合、ビット グループ化ステップではバケットにインデックスが割り当てられることはありません。 その結果、結合操作は実行されず、各ノードは独自の親のままになります。 DSU ルート数は次のとおりです`n`これは、異なるゼロ間の AND が接続条件を生成しないという事実と一致します。 

すべての数値が同一で非ゼロである入力の場合、すべてのインデックスが同じビット バケットのセットに挿入されます。 各ビット バケットは、すべてのノードを 1 つの代表に折りたたむ結合をトリガーします。 複数のビットにわたって共用体が繰り返されても、DSU は冗長なマージを安全に無視するため、最終的な構造は単一のコンポーネントになります。 

次のようなスパース入力の場合`[1, 2, 4]`、各数値は互いに素なビットバケットをアクティブにします。 どのバケットにも複数のインデックスが含まれていないため、結合はまったく発生しません。 DSU は初期状態のままで、3 つのコンポーネントを正しく生成します。
