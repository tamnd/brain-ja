 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースでは、正の整数のリストから開始します。 1 回の操作で値を選択できます$c$ただし、それが偶数である場合に限り、次のすべての出現を同時に置き換えます。$c$配列内で$c/2$。 

目標は、配列内のすべての数値が奇数になるまで、この操作をできるだけ少ない回数繰り返すことです。 

このプロセスを解釈する便利な方法は、各値が 2 による除算を繰り返すことによって独立して進化するということですが、重要な制限は、個別の位置をターゲットにすることはできず、選択した偶数の値のすべての出現に一度にのみ影響することです。 

制約により、最大で次のことが許可されます。$2 \cdot 10^5$すべてのテスト ケースの合計数であるため、配列全体で各操作を段階的にシミュレートしようとしたり、操作ごとに配列を繰り返しスキャンしたりするソリューションは合格しません。 ソリューションは基本的に、各要素を一定の回数処理するか、テスト ケースごとに繰り返される構造を 1 つのパスに圧縮する必要があります。 

多くの数値が半減チェーン中に重複する中間値を共有する場合、微妙なエッジ ケースが発生します。 例えば、$40$そして$20$相互作用するので$40 \to 20 \to 10 \to 5$その間$20 \to 10 \to 5$。 要素を個別に処理する単純なアプローチでは、慎重に考慮しない限り、共有中間値には個別の操作が必要であることが無視されるため、コストが過小評価されてしまいます。 

## アプローチ

 強引なアイデアは、プロセスを直接シミュレートすることです。 配列内に少なくとも 1 つの偶数値が存在しますが、偶数の値をいくつか選択します。$c$、出現するすべてのを分割します。$c$2 ずつ増やし、すべての値が奇数になるまで繰り返します。 各ステップでは、どの偶数を操作するかを決定するために、値の周波数マップをスキャンまたは維持する必要があります。 最悪の場合、次のような値が発生します。$2^k$半減の長い連鎖が生成され、変換後に複数の異なる値が繰り返し現れる可能性があります。 これは潜在的に次のことにつながります$O(n \log A)$各操作では大規模な構造全体でカウントを更新する必要があるため、処理が遅くなりすぎる場合があります。 

重要な観察は、各数値が奇数になる前に通過する偶数値の「チェーン」に寄与しているということです。 数字の場合$x$、奇数になるまで繰り返し 2 で除算し、パスに沿ったすべての中間の偶数値を記録します。 例えば、$40$連鎖を生み出す$40, 20, 10$。 このチェーン内のそれぞれの個別の値は、ある時点で必要な操作を表します。チェーンに現れる個別の偶数ごとに、少なくとも 1 つの操作を実行する必要があります。 

これで重要な構造が見えてきました。答えは、配列の半分のチェーンのどこかに現れる個別の偶数整数の正確な数です。 このような各値は少なくとも 1 回選択する必要があり、その操作ではすべての要素にわたってその値のすべての出現が同時に処理されるため、一度選択するだけで十分です。 

これにより、問題は、すべての数値にわたる中間の偶数値をすべて収集し、一意の値を数えるという問題に軽減されます。

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、必要な操作に対応する値を格納する空のセットを作成します。 このセットは、半減チェーンに現れるすべての偶数を表します。 
2. 配列内のすべての数値を反復処理します。 
3. 現在の数値が偶数である間に、それをセットに挿入し、2 で割ります。 これは、数字が奇数になるまで数字の軌跡をたどることをシミュレートします。 挿入するたびに、その値を対象とする少なくとも 1 つの操作が必要であることがマークされます。 
4. すべての番号について独立してこのプロセスを続行します。 
5. すべての要素を処理した後、セットのサイズがテスト ケースの答えとなります。 

偶数のみを記録する理由は、奇数はすでに最終的な形式になっており、演算を必要としないためです。 

### なぜ効果があるのか

 各操作は単一の偶数の値をターゲットにし、その発生をすべて同時に減らします。 したがって、要素の半分化プロセスのどの段階でも出現するすべての個別の偶数値は、少なくとも 1 回は削除する必要があります。 逆に、値を一度処理すれば、個別の偶数値ごとに 1 つの操作を実行するだけで十分です。$c$、のすべての出現$c$すぐになる$c/2$処理する必要はありません$c$また。 これにより、遭遇した個別の偶数値と必要な動きの間に 1 対 1 の対応関係が作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        seen = set()
        
        for x in a:
            while x % 2 == 0:
                seen.add(x)
                x //= 2
        
        print(len(seen))

if __name__ == "__main__":
    solve()
```解は各数値を反復処理し、偶数のまま繰り返し 2 で割ります。 中間の各偶数値はセットに格納されるため、配列全体で重複が発生して答えが膨らむことはありません。 最終結果は、単に遭遇した一意の偶数値の数です。 

よくある間違いは、値が最初に出現した時点で停止したり、グローバルではなく要素ごとにカウントしたりすることです。 複数の要素が同じ偶数の祖先を共有する可能性があり、そのような各祖先が 1 つの必要な操作に対応するため、過大カウントまたは過少カウントが発生します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))
            seen = set()
            for x in a:
                while x % 2 == 0:
                    seen.add(x)
                    x //= 2
            out.append(str(len(seen)))
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 重要なエッジケースは、配列に奇数のみが含まれる場合です。 その状況では、ループは決して実行されず、セットは空のままになり、正しくゼロの操作が生成されます。 

もう 1 つのケースは、すべての数値が 2 の累乗である場合です。たとえば、$[1024]$。 チェーンはこうなります$1024 \to 512 \to \dots \to 2$。 このアルゴリズムはすべての中間の偶数値を収集し、各レベルは必要な操作に対応します。 これにより、答えが入力内の最大の 2 のべき乗の指数に等しいことが保証されます。 

最後に、次のような同じ値を繰り返します。$[6, 6, 6]$単一のチェーンのみを提供する$\{6, 3\}$。 3 は奇数であるため、6 のみがカウントされ、このセットにより、繰り返しの作業が過大にカウントされることがなくなります。
