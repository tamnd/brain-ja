 ## 解決策
 ## 問題の理解

 庭園は、`n x n`グリッド。 一部のセルにはすでに花が含まれています。 その過程で、細胞が花を咲かせたり、細胞のペアが地下トンネルで結合したりすることがあります。 花が通常のグリッド隣接または地下トンネルを通じて接続されている場合、花のグループは同じ芽に属します。 

あらゆる芽生えには 2 つの価値観が必要です。 1つ目は`f`、その中にある花細胞の数。 2つ目は`c`、その芽に触れている地下トンネルの数。 この発芽によって提供されるエネルギーは、`max(f - sqrt(c), 0)`。 すべての操作の後、タスクはすべての出芽についてこれらの値の合計を計算することです。 

この制限は、操作のたびに接続構造全体を再構築できるほど十分に小さいです。 グリッドには最大でも`10000`セルがあり、最大でも`1000`操作。 解決策`1000 * 10000`操作は約 1,000 万の基本操作のみであるため、複雑な動的接続構造は必要ありません。 更新のたびにグリッドを最初からスキャンするソリューションは許容できますが、考えられるあらゆる出芽を個別にシミュレートしたり、セルのすべてのペアを繰り返し検索したりするアプローチは、不必要に高価になります。 

実装上の主な落とし穴は、接続とトンネルのカウントに関するものです。 花セルは、一連の地下トンネルまたは隣接する花セルを介して別の花に接続される可能性があるため、直接隣接する花セルをチェックするだけでは間違った結果が得られます。 例えば：```
2 1
10
01
2 0 0 1 1
```トンネルを追加すると、2 つの花が 1 つのつぼみを形成します。 答えは`2 - sqrt(1)`、 ない`2`、地下接続が貢献するため、`c`。 

もう 1 つの微妙なケースは、繰り返し花が挿入されることです。```
2 1
10
00
1 0 0
```独房にはすでに花が咲いているので、庭は変わりません。 現在の状態を確認せずに花の数を増やす不用意な実装は、過剰にカウントしてしまいます。 

最後のエッジケースは、トンネルは多くても花がほとんどない芽吹きです。```
2 1
10
00
2 0 0 0 1
```土のセルは地下で花のセルに接続されますが、花としてカウントされません。 芽生えは`f = 1`そして`c = 1`、つまり貢献度は`0`。 接続されているすべてのセルを花として数えると、誤った結果が生成されます。 

## アプローチ

 簡単なアプローチは、各クエリの後に庭を維持し、すべての出芽を再計算することです。 すべてのグリッド セルを頂点としてモデル化できます。 隣接するセルは通常のグリッド エッジで接続されており、地下操作により追加のエッジが追加されます。 各更新の後、すべてのセルに対して素セット ユニオンを実行し、隣接するセルとすべてのアンダーグラウンド接続を結合します。 次に、結果として得られるすべてのコンポーネントについて、花を含むセルの数とそれに属する地下エッジの数を数えます。 

これは、セルの数と演算の数が両方とも少ないため、機能します。 最悪のケースではおおよそのパフォーマンスが得られます`1000`再構築します。 それぞれの再構築のタッチ`10000`細胞、について`20000`グリッド隣接性チェック、および最大でも`1000`地下の端。 これは問題なく制限内です。 

より高度な動的接続ソリューションでは、トンネルやフラワーの変更に応じてコンポーネントが維持されますが、ここではその必要はありません。 重要な観察は、状態空間全体が十分に小さいため、再構築がより簡単かつ安全であるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(d * n²) | O(n²) | 繰り返しグラフ検索を実装すると遅すぎる |
 | DSU を再構築する | O(d * (n² + d)) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各セルに現在フラワーがあるかどうかを保存し、追加されたすべての地下接続を保存します。 操作は追加のみであるため、情報を削除する必要はありません。 
2. 各クエリの後に、すべてを含む新しい素セット共用体構造を作成します。`n * n`細胞。 最初はすべてのセルが分離されています。 グリッドの合計サイズが小さいため、再構築します。 
3. 水平方向または垂直方向に隣接するセルのすべてのペアを結合します。 これは通常のグリッド接続を表します。 土のセルを含むすべてのセルを含める理由は、将来の花がどのセルにも現れる可能性があり、地下またはグリッドの接続がセル自体の特性であるためです。 
4. すべてのアンダーグラウンド接続の両方のエンドポイントに参加します。 これにより、Karp の操作によって作成された追加のパスが追加されます。 
5. すべてのセルを調べて、各 DSU コンポーネント内のフラワー セルの数を数えます。 花細胞のみが寄与する`f`。 
6. すべてのアンダーグラウンド接続を横断し、そのコンポーネント内の接続をカウントします。 すべてのアンダーグラウンド エッジはすでに DSU にマージされているため、両方のエンドポイントが同じ代表者を持つため、各エッジは 1 つの芽に正確に属します。 
7. 花を含むすべてのコンポーネントに、`max(f - sqrt(c), 0)`答えに。 結果のエネルギーを出力します。 

これが機能する理由: DSU の不変条件は、2 つのセルが現在利用可能なすべてのパスを介して接続されている場合、正確に同じ代表を持つということです。 すべてのグリッド隣接と地下トンネルはカウントされる前にマージされるため、すべての発芽は 1 つの DSU コンポーネントで表されます。 コンポーネント内の花を数えると正しい値が得られます。`f`、そのコンポーネントの地下エッジをカウントすると、正しい値が得られます。`c`。 最終的な合計では、すべての発芽に独立してエネルギー計算式が適用されるため、結果はまさに必要な庭のエネルギーとなります。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())
    total = n * n

    flowers = []
    for _ in range(n):
        s = input().strip()
        flowers.extend(ch == '1' for ch in s)

    tunnels = []

    def idx(x, y):
        return x * n + y

    def compute():
        parent = list(range(total))
        size = [1] * total

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def union(a, b):
            a = find(a)
            b = find(b)
            if a == b:
                return
            if size[a] < size[b]:
                a, b = b, a
            parent[b] = a
            size[a] += size[b]

        for i in range(n):
            for j in range(n):
                cur = idx(i, j)
                if i + 1 < n:
                    union(cur, idx(i + 1, j))
                if j + 1 < n:
                    union(cur, idx(i, j + 1))

        for a, b in tunnels:
            union(a, b)

        flower_count = [0] * total
        for i, has_flower in enumerate(flowers):
            if has_flower:
                flower_count[find(i)] += 1

        tunnel_count = [0] * total
        for a, b in tunnels:
            tunnel_count[find(a)] += 1

        ans = 0.0
        for i in range(total):
            if flower_count[i]:
                ans += max(flower_count[i] - math.sqrt(tunnel_count[i]), 0.0)

        return ans

    out = []
    for _ in range(d):
        q = list(map(int, input().split()))
        if q[0] == 1:
            flowers[idx(q[1], q[2])] = True
        else:
            tunnels.append((idx(q[1], q[2]), idx(q[3], q[4])))

        out.append(f"{compute():.10f}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`flowers`配列は、フラット化されたインデックスを使用して、すべてのグリッド セルの現在の状態を格納します。 フラット化により、座標ペアの繰り返しの保存が回避され、DSU 操作が直接化されます。 

の`compute`関数は接続を再構築します。 最初の結合ループは通常のグリッド エッジを追加し、2 番目の結合ループはすべての地下トンネルを追加します。 DSU は接続のみを表すため、順序は最終コンポーネントには影響しません。 

花とトンネルは異なる量を表すため、2 つの計数配列は別々です。`flower_count`細胞を数えますが、`tunnel_count`地下接続をカウントします。 これらを混合すると、平方根項に不正確な値が生成されます。 

最後のループでは、少なくとも 1 つの花を持つコンポーネントのみが考慮されます。 土だけでできた部品は芽が出ず、何の役にも立ちません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(d * (n² + d)) | 各クエリは、すべてのセルとすべてのトンネルにわたって DSU を再構築します。 
| スペース | O(n²) | DSU 配列とグリッド状態はそれぞれ、セルごとに 1 つの値を格納します。

 ## 特殊なケース

 花を繰り返し挿しても新しい花は生まれません。 入力で```
2 1
10
00
1 0 0
```細胞`(0,0)`すでに占領されています。 アルゴリズムは値を次のように設定します。`True`再び同じコンポーネント構造を再構築し、エネルギーを生成します`1`。 

以前は分離していた細胞を接続するトンネルは、それらの出芽を融合する必要があります。 のために```
2 1
10
01
2 0 0 1 1
```DSU は 2 つのフラワー セルを結合します。 コンポーネントには地下エッジが 1 つあるため、`f = 2`そして`c = 1`、与える`2 - sqrt(1) = 1`。 

トンネルが土に触れると花の数は増えません。 のために```
2 1
10
00
2 0 0 0 1
```コンポーネントには 1 つの花と 1 つの地下トンネルが含まれています。 値は`max(1 - sqrt(1), 0) = 0`、アルゴリズムは花とトンネルを個別に数えることによって取得します。
