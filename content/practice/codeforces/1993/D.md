 ## 解決策
 ## 問題の理解

 整数の配列とパラメータが与えられます。$k$。 連続する長さの部分配列を繰り返し正確に削除できます。$k$配列から削除して縮小します。 配列の長さが次の値を超えなくなると、$k$、やめます。 私たちの目標は、このプロセスの後に残りの要素の最大中央値を決定することです。 

中央値は、並べ替えられた配列の「中央」の要素です。 たとえば、1 つの要素が残っている場合、その要素は自明のことながら中央値になります。 複数の要素が残っている場合、中央値は位置の要素になります。$\lfloor (n+1)/2 \rfloor$並べ替えると。 

制約により、配列には最大で次のものを含めることができます。$5 \cdot 10^5$要素とその合計$n$すべてのテスト ケースで最大でも$5 \cdot 10^5$。 これは、次のようなソリューションを意味します。$O(n \log n)$テスト ケースごとの値は許容されますが、二次関数は実行不可能です。 各要素の大きさは次のとおりです。$10^9$, そのため、単純なカウントや頻度に基づくトリックは機能しません。 

次の場合、微妙なエッジケースが発生します。$k=1$または$k=n$。 もし$k=1$の場合、単一の要素はいつでも削除できます。つまり、最終的には最大の要素を中央値として残すことができます。 もし$k=n$、削除は不可能であり、中央値は単に元の配列の中央値になります。 これらのニュアンスが欠けていると、誤った結果が生じる可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、有効なサブ配列削除のすべてのシーケンスが考慮され、結果の各配列の中央値が計算されます。 これは原理的には正しいですが、法外に遅いです。 たとえば、次の場合$n=10^5$そして$k=2$、おおよそあります$\binom{n}{k}$考慮すべき一連の操作は天文学的に膨大です。 

重要な洞察は、要素の相対的な位置のみが重要であることを理解することです。 削除を繰り返した後、残りの配列は常に、削除された部分配列の境界にある要素で構成されます。 最大の中央値が必要なので、削除の正確な順序は気にしません。 代わりに、候補の中央値を尋ねます。$x$、十分な要素を削除して、$x$最終配列の「中央」に行き着くのでしょうか？ 

これは当然、二分探索の解決策につながります。 中央値を推測することができます$x$そしてそれが達成可能かどうかを確認します。 これを行うには、配列を +1/-1 シーケンスに変換します: 要素に対して +1$\ge x$、要素の場合は -1$< x$。 次に、問題は、サブ配列の削除戦略により、最終的な配列で +1 と -1 の正のバランスが許容されるかどうかを見つけることに帰着します。 このチェックは線形時間で実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n/k)^n) | O(n) | 遅すぎる |
 | 二分探索 + 接頭辞の合計 | O(n log(max(a))) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 値が中央値になり得るかどうかのみを考慮するため、並べ替えは不要です。 
2. 二分探索境界を初期化します。`lo = 1`、`hi = max(a)`。 
3. その間`lo < hi`、 選ぶ`mid = (lo + hi + 1) // 2`中央値候補として。 
4. 配列を次のように変換します。`b[i] = +1 if a[i] >= mid else -1`。 
5. プレフィックスの合計を計算する`pref[i] = b[0] + ... + b[i]`。 
6. 各インデックスについて`i`ここで、サブ配列の削除を停止し、サイズの現在のウィンドウの左側の最小プレフィックス合計を維持できます。`k`。 
7. いずれかの時点で、プレフィックス合計から最小プレフィックス合計を引いた値が正の場合、候補は`mid`達成可能です。 
8. 可能であれば移動する`lo = mid`。 それ以外の場合は、設定します`hi = mid - 1`。 
9. 二分探索の後、`lo`は達成可能な最大の中央値です。 

機能する理由: +1/-1 変換は、候補中央値が「十分に大きい」かどうかを捕捉します。 正のプレフィックス合計の差により、この中央値が最後まで存続するように部分配列を選択できることが保証されます。 二分探索により、最大中央値を効率的に見つけることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_achieve(a, n, k, x):
    b = [1 if val >= x else -1 for val in a]
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i+1] = pref[i] + b[i]

    min_pref = 0
    for i in range(k, n+1):
        if pref[i] - min_pref > 0:
            return True
        min_pref = min(min_pref, pref[i-k+1])
    return False

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        lo, hi = 1, max(a)
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if can_achieve(a, n, k, mid):
                lo = mid
            else:
                hi = mid - 1
        print(lo)

if __name__ == "__main__":
    solve()
```説明:`can_achieve`関数は、変換された配列のプレフィックスの合計を計算し、次のサイズのスライディング ウィンドウを使用して正の合計が得られるかどうかを確認します。`k`。 二分探索により、実現可能な最大中央値が見つかります。 注意してください。`+1`で`(lo + hi + 1) // 2`次のような場合に検索が停止しないようにします。`lo`そして`hi`隣接している。 での境界処理`min_pref`微妙であり、正確さにとって重要です。 

## 実用的な例

 **例 1:**

 入力:`4 3`配列あり`[3,9,9,2]`候補中央値二分探索は中間値 6、4、3 から始まります。配列を次のように変換します。`mid=4`与える`[-1,1,1,-1]`。 プレフィックスの合計`[0,-1,0,1,0]`。 スライディング ウィンドウ チェックにより、正の合計が存在することが確認されます。`mid=4`達成可能な。 二分探索が進み、最終的な答えが得られます`3`。 

| ステップ | ミッド | 変換された | 接頭語 | 最小プレフ | 達成可能な？ |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 6 | [-1、-1、-1、-1] | [0、-1、-2、-3、-4] | 0 | いいえ |
 | 2 | 4 | [-1,1,1,-1] | [0,-1,0,1,0] | 0 | はい |
 | 3 | 3 | [1,1,1,-1] | [0,1,2,3,2] | 0 | はい |

 これにより、アルゴリズムが最大中央値 3 を正しく識別していることが確認されます。 

**例 2:**

 入力:`5 3`配列あり`[3,2,5,6,4]`二分探索候補`mid=4`変換された収量`[ -1,-1,1,1,1 ]`。 プレフィックスの合計`[0,-1,-2,-1,0,1]`。 スライディングウィンドウはプラスの違いを見つけ、達成可能です。 最終的な答えその４。
