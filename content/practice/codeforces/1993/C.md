 ## 解決策
 ## 問題の理解

 この問題は、複数の部屋があるアパートに関係しており、各部屋の照明が消されている状態から始まります。 各部屋には個別の時間にチップがインストールされ、各チップは部屋の照明を定期的にオンとオフを切り替えます。`k`分。 切り替えはインストール時から始まり、次の間で切り替わります。`k`分と`k`分は無期限にオフになります。 課題は、**すべてのライトが同時に点灯**する最も早い瞬間を特定することです。 そのような瞬間が存在しない場合、答えは次のようになります。`-1`。 

入力は部屋の数と期間を提供します`k`、各部屋の設置時間。 出力は、すべてのライトがオンになった最も早い分を表すテスト ケースごとの 1 つの整数です。 

制約は次のことを示します`n`最大 2×10^5 にすることができ、`t`最大 10^4、合計`n`2×10^5 で区切られたすべてのテスト ケースにわたって。 これは、どのソリューションも **テスト ケースごとに線形またはほぼ線形の時間**で動作する必要があることを意味します。 インストール時間が最大 10^9 に達する可能性があるため、潜在的な分をすべて二次的または徹底的にチェックすることは不可能であり、毎分シミュレーションすることは不可能です。 

明らかではないエッジケースには、異なる部屋のオン期間が**決して一致しない**ように、インストール時間が間隔をあけられている状況が含まれます。 たとえば、2 つのライトの設置時間が 300 以上異なる場合、`k`そしてそれらのシーケンスは決して交差しません、答えは次のようになります。`-1`。 同様に、`k`に比べて非常に大きい`n`、一部の部屋ではめったにオンにならない場合があり、最も早い共通オンタイムに影響を与えます。 

## アプローチ

 素朴なアプローチは、最初の設置後に毎分シミュレーションを行い、どのライトがオンまたはオフになっているかを確認することです。 それは正しいですが、インストール時間は 10^9 にも及ぶ可能性があるため、これは明らかに実行不可能です。`n`最大 2×10^5 まで可能です。 の倍数のみをチェックする最適化を行っても、`k`それぞれから始まる`a_i`、すべてのシーケンスにわたる交差を処理す​​るには、ネストされたループが必要になり、それでも遅すぎます。 

重要な洞察は、各部屋の照明が一定の長さの間隔で点灯していることを認識することで得られます。`k`から始まる`a_i`そして毎回繰り返す`2k`分。 したがって、特定の瞬間にライトが点灯するには`t`、満足する必要があります`t ≥ a_i`そして`(t - a_i) // k % 2 == 0`。 これにより、すべての部屋にわたってこれらの算術シーケンスを調整するという問題が軽減されます。 インストール時間を **降順**で処理し、部屋がオンになっていたすべての以前の部屋に寄与できる最も早い分を表す累積的な「シフト時間」を追跡できます。 各ステップでは、可能な限り早い共通時間を調整するか、制約が満たされない場合は不可能性を検出します。 

これにより、インストール時間を降順に並べ替えた後、線形スイープが行われ、並べ替えによりテスト ケースごとに **O(n log n)** のソリューションが保証されます。これは制約の下で許容可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(max(a_i) × n) | O(n) | 遅すぎる |
 | 算術整列 / 降順スイープ | O(n log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして`k`、次にインストール時間のリスト`a`。 
3. インストール時間を **降順**で並べ替えます。 これにより、最新のチップが搭載された部屋から確実に開始できるようになります。これは、最後に取り付けられたチップがオンになるまでは最も早い共通オンタイムが発生しないため、非常に重要です。 
4. 変数を初期化する`ans`に`0`、すべての部屋がオンになる最も早い時間を表します。 
5. ソートされたインストール時間を繰り返します。 設置時間ごとに`ai`:

 1. この部屋がグローバルな「オールオン」の瞬間に寄与できる最も早い時間を次のように計算します。`ai + k * ans`。 
2.アップデート`ans`完全な期間の数を加算することによって`ceil((ai + k*ans) / k) - ai // k`- 基本的に、累積的なシフトにより、このルームのオン期間が以前のルームと一致するようにします。 
6. すべての部屋を処理した後、累積`ans`部屋の最初のオン期間に違反している場合、印刷`-1`。 それ以外の場合は、計算された最も早い分を出力します。 

機能する理由: 最新のインストールから逆方向に処理することで、累積的なシフトが各部屋のオン期間を確実に尊重します。 維持される不変条件は次のとおりです`ans`常に、これまでに処理されたすべての部屋を満たす最も早い候補時間を表します。 この候補と一致しない部屋がある場合、アルゴリズムは不可能であることを検出します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort(reverse=True)
        ans = 0
        for ai in a:
            # increment ans until ai + k*ans >= ans + 1 for this room
            if ai + k * ans < ans + 1:
                print(-1)
                break
            ans += 1
        else:
            print(ans)

if __name__ == "__main__":
    solve()
