 ## 問題の理解

 整数の配列が与えられているので、そこからちょうど 3 つの要素を選択する必要があります。 唯一の制限は構造的なものです: 要素を位置で選択する場合$i_1 < i_2 < i_3$の場合、連続する各ペアは少なくとも次の値で区切られている必要があります。$d$インデックス、意味$i_{t+1} - i_t \ge d$。 目的は、選択した値の合計を最大化することです。 

重要な問題は、立場が相互作用することです。 大きな値を早期に選択すると、近くにある他の大きな値へのアクセスがブロックされる可能性があるため、局所的に最適な選択が全体的な最適性を破壊する可能性があります。 

制約は大きいです:$n \le 150000$。 これにより、すべてのトリプルまたはすべての有効な組み合わせの 3 次または 2 次の探索が即座に除外されます。 平$O(n^2)$アプローチが遅すぎる。 解決策は本質的に線形または線形でなければなりません。 

値が負の場合、微妙な問題が発生します。 素朴な直感は、「常に次の利用可能な最良の要素を選択する」と示唆するかもしれませんが、わずかに小さい初期のピックが 2 つのはるかに大きな後のピックのロックを解除できるため、それは失敗します。 

たとえば、次のことを考えてみましょう。```
n = 6, d = 2
A = [10, -100, 9, 9, 9, 9]
```欲張った選択をすると、インデックス 1 で 10 が必要になり、次善の間隔に強制される可能性があります。 正しい戦略では、間隔に応じて、後で 2 つまたは 3 つの大きな値を許可するためにこれをスキップする場合があります。 

もう 1 つの失敗例は、ローカル ウィンドウ推論に起因します。 次のことだけを考えるアプローチ$d$または$2d$最適なトリプルは配列全体のグローバル アラインメントに依存するため、位置を独立して指定しても失敗します。 

## アプローチ

 ブルート フォース ソリューションでは、インデックスのすべてのトリプルが試行されます。$i < j < k$、間隔の制約が満たされているかどうかを確認し、合計を計算します。 これは$O(n^3)$、これは完全に不可能です$n = 150000$。 候補となるトリプルの数自体が膨大であるため、有効性チェックを最適化しても役に立ちません。 

ペアの列挙を回避し、代わりに最適な部分構造を再利用する方法が必要です。 重要な観察は、中間要素を修正すると、$j$の場合、問題は 2 つの独立した部分問題に分割されます。左側の最適な有効な選択と右側の最適な有効な選択であり、それぞれに間隔の制約があります。 

これは動的プログラミングを示唆しています。 間隔を考慮しながら、指定されたインデックスまでの 1、2、または 3 つの要素を選択して可能な限り最良の合計を取得する状態を定義します。

間隔を効率的に適用するために、以前のすべての状態をスキャンするのではなく、以前の有効な範囲からの最良の値を維持します。 

遷移は次のようになります。 

- どちらかをスキップします$i$- または使用します$i$最後に選択された要素としてそれを、それ以前で終了する最良の有効な状態と組み合わせます。$i - d$これにより、各状態遷移が次のように減少します。$O(1)$プレフィックス maxima を使用して償却されます。

 ## アルゴリズムのチュートリアル

 3 つの DP レイヤーを構築しますが、それらはプレフィックスベスト トラッキングを使用して 1 回の順方向パスで計算されます。 

1. インデックスまでの最適な dp 値をクエリできるようにするプレフィックス最大配列を事前計算します。$i$。 これにより、スキャンせずに、最も有効な以前のピックを効率的に見つけることができます。 
2. 3 つの DP アレイ、dp1、dp2、dp3 を維持します。 各 dp 状態は、インデックスに取得される正確な数を使用して達成可能な最良の合計を表します。$i$。 トランジションはすでに選択されている要素の数に依存するため、この分離が必要です。 
3. dp1[i] を、i までのこれまでに確認された最良の単一要素として初期化します。 要素が 1 つだけ選択されているため、これは単純にプレフィックスの最大値です。 
4. dp2[i] については、要素 i を 2 番目のピックとして採用することを検討します。 最初の選択は最大でも i ～ d のインデックスから取得する必要があります。 したがって、 dp2[i] は次のように更新されます。 

プレフィックス [1 .. i - d] + A[i] の最適な dp1 値、または dp2[i-1] をキャリーします。 

このステップでは、間隔制約をトランジションに直接エンコードします。 
5. dp3[i] についても、同様に i を 3 番目の選択として考慮します。 i - d までの最良の dp2 値を A[i] と組み合わせるか、dp3[i-1] を運びます。 
6. 最終的な答えは dp3[n] です。 

なぜ効果があるのか:

 すべてのインデックス i、dp1、dp2、dp3 には、i で終わるプレフィックスの最適解が格納されます。 3 つの要素を最適に選択するには、最後の要素 k が必要です。 k が固定されると、残りの 2 つの要素は、k - d までのプレフィックス内で最適で有効な選択を形成します。これは、重複または偏差が最適性と矛盾するためです。 この最適な下部構造により、プレフィックス maxima を使用して段階的にソリューションを構築する際に、より優れた構成を見逃すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, d = map(int, input().split())
    a = list(map(int, input().split()))
    
    NEG = -10**30
    
    # dp arrays
    dp1 = [NEG] * n
    dp2 = [NEG] * n
    dp3 = [NEG] * n

    dp1[0] = a[0]

    # prefix bests for dp1, dp2, dp3
    best1 = [NEG] * n
    best2 = [NEG] * n
    best3 = [NEG] * n

    best1[0] = dp1[0]

    for i in range(1, n):
        # dp1: take best single element
        dp1[i] = max(dp1[i-1], a[i])

        # dp2: either skip or take i as second element
        j = i - d
        best_prev1 = best1[j] if j >= 0 else NEG
        dp2[i] = max(dp2[i-1], best_prev1 + a[i])

        # dp3: either skip or take i as third element
        best_prev2 = best2[j] if j >= 0 else NEG
        dp3[i] = max(dp3[i-1], best_prev2 + a[i])

        # update prefix bests
        best1[i] = max(best1[i-1], dp1[i])
        best2[i] = max(best2[i-1], dp2[i])
        best3[i] = max(best3[i-1], dp3[i])

    print(dp3[n-1])

if __name__ == "__main__":
    solve()
```この実装では、位置 i の正確な DP とプレフィックスの最大値の両方を追跡します。 遷移では常に、制限されたインデックスまでの最適な値が必要となるため、プレフィックス配列は必須です。$i - d$、必ずしも正確に終わるわけではありません$i - d$。 

負のセンチネルは、値を追加する際の偶発的なオーバーフローを避けるために十分な大きさに設定されています。 キャリーオーバー`dpX[i-1]`要素のスキップが常に考慮されるようにします。

 ## 特殊なケース

 重要なエッジケースは、初期の最良の値が、その後のより強力な組み合わせへのアクセスをブロックする場合です。 例えば：```
n = 6, d = 2
A = [100, 1, 1, 1, 100, 100]
```単純なアプローチでは、インデックス 0 で 100 を選択し、残りの選択が遠く離れてしまい、最後に両方の 100 を取得できなくなる可能性があります。 dp2 と dp3 は代替履歴を保存するため、DP は dp2 と dp3 を形成するときに最初の 100 を正しくスキップします。 

もう 1 つのエッジ ケースは、最適なピックが距離 d の境界に厳密に厳密に配置されている場合です。 移行では、`i - d`、 ない`i - d - 1`なので、境界の包含は正しいです。 ここでの off-by-one エラーは、無効な選択を許可するか、誤って有効な選択を禁止するかのいずれかになり、密にパックされた最適なソリューションの正確性を即座に破ってしまいます。
