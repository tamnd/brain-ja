 ## 問題の理解

 2 つの整数間隔が与えられます。1 つの間隔は、次のすべての有効な値を定義します。$x$、もう 1 つは、次のすべての有効な値を定義します。$y$。 目標金額も設けております$n$。 タスクはペアの数を数える事です$(x, y)$そのように存在する$x$その間隔の中にあり、$y$はその区間内にあり、それらの合計は正確に$n$。 

より具体的に言うと、2 つの包括的な数値範囲を想像してください。 最初の範囲から 1 つの数値を選択し、2 番目の範囲から 1 つの数値を選択して、合計すると固定値になるようにしたいと考えています。 出力は、単にこれを行うための有効な方法の数です。 

制約は十分小さいため、両方の範囲は次のとおりです。$10^5$、目標金額も最大です$10^5$。 これにより、最悪の場合、すべてのペアに対して 2 次反復を必要とするものは即座に除外されます。$10^{10}$操作。 代わりに、テストごとに線形または定数時間の推論を目指す必要があります。 

正確さのためには、いくつかの特殊なケースが重要です。 必要な補完がある場合$y = n - x$2 番目の間隔の外にある場合、$x$何も貢献しません。 たとえば、次の場合$l_1 = 1, r_1 = 10, l_2 = 1, r_2 = 10, n = 2$、その後のみ$x = 1, y = 1$は機能するので、答えは 1 です。限界を忘れた素朴なアプローチ$y$次のような無効なペアを誤ってカウントします$x = 2, y = 0$、 それでも$y$範囲外です。 

もう 1 つの微妙な問題は、有効なカウントを独立してカウントしようとした場合のオーバーカウントです。$x$そして$y$合計制約を強制せずに値を計算します。 2 つの変数間の依存関係は厳密であるため、独立して扱うことはできません。 

## アプローチ

 簡単な方法は、可能な限りすべてのことを試すことです$x$その間隔で計算します$y = n - x$、これがあるかどうかを確認してください$y$2番目の区間にあります。 これは、それぞれが固定されているため機能します$x$、候補は最大 1 つです$y$。 条件を直接強制しているため、正しさは即座にわかります$x + y = n$。 

このブルートフォース手法の問題は、実行時間です。 最悪の場合、$x$含まれています$10^5$値、および各チェックは定数時間であるため、次の時間で実行されます。$O(r_1 - l_1 + 1)$、ここでは許容されます。 ただし、反復を完全に削除することでさらに単純化できます。 

重要な観察は、ペアを検索しているのではなく、2 つの制約を同時に交差していることです。$$x \in [l_1, r_1], \quad n - x \in [l_2, r_2]$$2 番目の条件は次のように書き換えることができます。$$l_2 \le n - x \le r_2$$並べ替えると次のようになります。$$n - r_2 \le x \le n - l_2$$それで$x$は 2 つの区間の交点になければなりません。$$[l_1, r_1] \cap [n - r_2, n - l_2]$$この交差を計算すると、すべての整数が$x$内部ではちょうど 1 つの有効な値に対応します$y$、その逆も同様です。 したがって、答えは間隔内の整数を数えるということになります。

 ## アルゴリズムのチュートリアル

 この問題を、2 つの範囲の交差部分にある整数を数える問題に変換します。 

1. 変換された区間を計算します。$x$によって暗示される$y$-制約。 これは$[n - r_2, n - l_2]$。 この手順が必要なのは、次の条件があるためです。$y$という観点から表現する必要があります$x$両方の制約を調整します。 
2. 間の重なりを計算します。$[l_1, r_1]$そして$[n - r_2, n - l_2]$。 交差点の左側の境界は 2 つの左側の端点の最大値であり、右側の境界は 2 つの右側の端点の最小値です。 
3. 結果の左端点が右端点を超える場合、交差点は空であるため、答えはゼロになります。 これは、$x$両方の制約を同時に満たすことができます。 
4. それ以外の場合、交差部分の整数の数は次のようになります。$r - l + 1$、有効な数を直接与えます。$x$、したがって有効なペアになります。 

### なぜ効果があるのか

 有効な各ペア$(x, y)$元の制約を両方とも満たします。 変換により、制約が置き換えられます。$y$同等の制約を持つ$x$、有効なペアと整数の間の 1 対 1 の対応を維持します。$x$交差点で。 二つとして違いはありません$x$値は同じペアを生成し、すべての有効なペアは 1 つだけ生成します。$x$、つまりカウントは有効です$x$値は有効なペアを数えるのと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

l1, r1, l2, r2, n = map(int, input().split())

left = max(l1, n - r2)
right = min(r1, n - l2)

if left > right:
    print(0)
else:
    print(right - left + 1)
```コードは、アルゴリズムで導出された間隔変換を直接適用します。 表現`n - r2`そして`n - l2`の有効範囲を定義する$x$2 番目の間隔によって暗示されます。 取る`max`そして`min`一定時間内に交差点の境界を安全に計算します。 最後の条件は空の交差ケースを処理し、負のカウントが生成されないようにします。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    l1, r1, l2, r2, n = map(int, input().split())

    left = max(l1, n - r2)
    right = min(r1, n - l2)

    if left > right:
        return "0"
    return str(right - left + 1)

# provided sample
assert run("1 10 1 10 20") == "1"

# x-range empty after intersection
assert run("1 2 10 20 5") == "0"

# single solution at boundary
assert run("0 10 0 10 0") == "1"

# multiple solutions
assert run("1 10 1 10 10") == "10"

# shifted ranges
assert run("5 15 1 3 10") == "1"

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、変換された間隔が元の間隔の完全に外側にある場合です。$x$-範囲。 入力用`1 2 10 20 5`、導出される範囲は$x \in [5 - 20, 5 - 10] = [-15, -5]$。 と交差$[1, 2]$左の端点が 1 になり、右の端点が -5 になるため、空の間隔が生成されます。 交差チェックが行われるため、アルゴリズムは正しく 0 を返します。`left > right`トリガー。 

もう 1 つのケースは、交差が単一の値に減少する場合です。 入力用`0 10 0 10 0`、両方の範囲は次のようになります$[0, 10]$、したがって交差点も$[0, 10]$。 アルゴリズムは戻ります$10 - 0 + 1 = 11$、ペアの数と一致します。$x = -y$同じ間隔内 (ゼロを含む)。 

最後の微妙なケースは、すべてが完全に重複している場合です。$x$元の範囲内であれば有効です。 入力用`1 10 1 10 10`、変換された区間も$[0, 9]$、交差すると、$[1, 9]$。 このアルゴリズムは、二重にカウントしたり、エンドポイントを欠落したりすることなく、その交差部分にあるすべての有効な整数を正確にカウントします。
