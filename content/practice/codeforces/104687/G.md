 ## 解決策
 ## 問題の理解

 私たちは鉛筆の列を与えられ、それぞれに値段が付いているので、最終的には正確に購入する必要があります。$k$彼らのうち。 このプロセスは順番に行われます。左から右にスキャンし、各位置でその鉛筆を購入するかどうかを決定します。 

鉛筆を購入するのにかかる費用は、その価格だけではありません。 初めて購入する鉛筆の場合、お支払いいただくのは価格のみです。 それが初めてではない場合、それを購入すると、以前に購入した鉛筆のインデックスに等しい追加の税金を支払うことも強制されます。 一連の最後の鉛筆は購入する必要があり、これも$k$選ばれたアイテムたち。 

したがって、実際のコストは、どの鉛筆を選択するかだけでなく、その位置によって引き起こされる順序にも依存します。 課題は、これらのルールに基づいて総コストを最小限に抑えることです。 

制約により、最大で$n = 10^5$、すべてのサブセットまたはすべての組み合わせを試行するソリューションは直ちに除外されます。$k$選ばれた鉛筆。 平$O(nk)$最悪の場合、動的プログラミングは遅すぎます。 解決策では、問題をソートまたは単一パスの貪欲な選択に近いものに減らす必要があります。 

微妙なエッジケースが現れるのは、$k = 1$。 この場合、最後の鉛筆だけが選ばれ、税金は決して支払われません。 税ルールの単純な解釈では、以前のインデックスに基づいて何かを誤って追加する可能性がありますが、正しい動作は、答えは単純です。$a_n$。 

もう 1 つの失敗例は、単に選択することよりも、選択の順序は重要ではないと仮定した場合です。$k$最小の価格。 税金は指標に依存するため、指標を完全に無視すると、目的に適切に反映されない限り、誤った推論につながります。 

## アプローチ

 強引なアイデアは、あらゆる選択方法をシミュレートすることです。$k$最後の1本を含む鉛筆。 サイズのサブセットごとに$k-1$最初から$n-1$鉛筆の場合、注文書を再構築し、価格と税金の両方を合計することでコストを計算できます。 これは、サブセットが固定されるとプロセスが完全に決定的になるため機能しますが、サブセットの数は$\binom{n-1}{k-1}$、中程度の場合でも天文学的に大きくなります$n$。 このアプローチは大規模化するとすぐに壊れてしまいます。 

重要な観察は、どの鉛筆を購入するかを決定すると、その順序は指数の増加によって強制され、課税構造が加算的になるということです。 選択したインデックスが$i_1 < i_2 < \dots < i_{k-1} < n$、最後を除く選択された各鉛筆は、シーケンス内で 1 回だけ「前の購入」であるため、税金としてそのインデックスを 1 回だけ提供します。 これにより、選択した要素間のすべての相互作用が削除されます。 

コストが選択されたインデックスごとの独立した寄与の合計に分解されると、問題はインデックスの選択になります。$k-1$個々のコストが最小のアイテム。各アイテムには、価格とインデックスへの寄与の両方を含む変更された重みが付けられます。

 | ブルートフォース |$O(\binom{n}{k} \cdot k)$|$O(k)$| 遅すぎる |
 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最後の鉛筆が伸びていることを確認します。$n$は常に含める必要があるため、ソリューションの一部として修正します。 その貢献は常に$a_n$、それに続くものがないため、追加の税金を寄与することはありません。 
2. 残りの選択肢を再定式化します: 正確に選択する必要があります$k-1$からのインデックス$[1, n-1]$。 これらにより、残りの購入シーケンスが決まります。 
3. 選択したインデックスを概念的に、自然に表示されるように昇順に並べ替えます。 この順序付けは左から右へのプロセスによって強制されるため、追加の並べ替えの決定は存在しません。 
4. 選択したセットのコスト寄与を計算します。 選択された各インデックス$i$価格に貢献する$a_i$、そのインデックスにも貢献しています$i$税金として 1 回だけ、それはシーケンス内で前に選択された鉛筆になるためです。 
5. 変換された重みを定義する$w_i = a_i + i$。 総コストは次のようになります。$$a_n + \sum_{i \in S} (a_i + i)$$どこ$S$のセットです$k-1$選ばれたインデックス。 
6. 問題は選択に帰着します$k-1$の最小値$w_i$の間で$i \in [1, n-1]$。 
7. 出力$a_n$これらの合計を加えたもの$k-1$変換された最小の重み。 

### なぜ効果があるのか

 重要な特性は、税条件が以前に選択されたインデックスにのみ依存し、選択された各インデックスが 1 回だけ前の要素になるということです (前に最後に選択された要素を除く)$n$、これでも 1 回カウントされます)。 これにより、税負担は任意の状態間の遷移に依存するのではなく、要素全体にわたって線形になります。 書き換えると、コスト関数は独立したアイテムの重みの単純な合計になるため、最適なソリューションでは相互作用を考慮せずに利用可能な最小の重みを選択する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    if k == 1:
        print(a[-1])
        return
    
    w = []
    for i in range(n - 1):
        w.append(a[i] + (i + 1))
    
    w.sort()
    
    ans = a[-1] + sum(w[:k - 1])
    print(ans)

if __name__ == "__main__":
    solve()
```実装は、変換された定式化に直接続きます。 唯一の特殊なケースは、$k = 1$、何も構築したり並べ替えたりすることを避け、すぐに戻ります。$a_n$。 

インデックスシフト$i + 1$この問題では鉛筆のインデックスは 1 から始まりますが、Python の配列は 0 から始まるため、これは重要です。 このシフトを見逃すと、税金の計算がひっそりと破損するオフバイワンエラーの一般的な原因となります。
