 ## 解決策
 ## 問題の理解

 0 と 1 だけで構成されるバイナリ文字列が与えられます。 私たちは反転を使用して無秩序を測定します。つまり、0 の前に 1 が現れるすべての位置のペアが 1 単位に寄与します。 課題は、隣接する 2 つの文字を交換する操作を最大 1 つまで自由に実行できるようにして、この反転回数をできる限り減らすことです。 

したがって、0 と 1 の固定構成から開始し、オプションで隣接するペアを 1 つ選択し、それを 1 回交換することもできます。そして、何もしないという選択も含め、そのようなすべての選択肢の中で達成可能な最小の反転回数を知りたいと考えています。 

文字列の長さは最大 100 であり、候補演算ごとに 2 次の動作であっても許容されることがすでに示唆されています。 ここでは技術的には 3 次またはそれ以下のものでも問題ありませんが、構造が単純であるため、きれいな 2 次解を目指す必要があります。 

慎重に再計算することなく、ローカル ペアの交換がこれら 2 つの文字を含む反転にのみ明らかな線形の方法で影響を与えると仮定すると、単純な落とし穴が発生します。 たとえば、次のような文字列では、`1010`、真ん中を入れ替える`10`に`01`そのペアによって形成される反転だけでなく、それらのキャラクターが両側の他のキャラクターとどのように相互作用するかも変化します。 過度に局所的なヒューリスティックを使用して反転数を更新しようとするアプローチは、これらの相互作用を見逃す傾向があります。 

もう 1 つの微妙な問題は、スワップをまったく行わないというオプションを忘れていることです。 場合によっては、最初の文字列がすでに最適になっている場合があります。たとえば、`000111`、あらゆる交換は混乱を増大させるだけです。 

## アプローチ

 この問題を考える直接的な方法は、到達できるすべての有効な状態を試してみることです。 元の文字列と、隣接する 1 つのペアを交換して得られるすべての文字列の 2 種類のみです。 このような文字列ごとに、すべてのペアをスキャンし、反転回数をカウントすることで、反転回数を最初から計算できます。`1`の前にある`0`。 

これは制約が小さいため機能しますが、冗長です。 文字列の長さが n の場合、n-1 回の交換が可能です。 1 つの文字列に対して反転を最初から計算するには O(n²) かかるため、合計は O(n³) になります。 これは、n ≤ 100 の場合はまだ許容できる境界線ですが、構造が無駄になります。 

重要な点は、隣接する 2 つの要素を交換しても文字列が全体的に再形成されるわけではないということです。 配列の残りの部分に対する交換された要素の相対的な順序のみが変更されます。 それ以外はすべて同じままです。 つまり、反転寄与がどのように変化するかを慎重に推論するつもりであれば、すべてを最初から再計算する必要はありません。 

ただし、実際には、n ≤ 100 の場合の最もクリーンな実装は、スワップ候補ごとに O(n) または O(n²) で反転を再計算することです。 構造は非常に小さいため、シンプルさが勝ります。

 ## アルゴリズムのチュートリアル

 何も操作を行わない場合と、ある位置で 1 回だけスワップを行う場合との間の最小値として答えを扱います。 

1. 元の文字列の反転回数を計算します。 これが私たちの基本的な答えです。 i < j のすべてのペア (i, j) は、i の文字が 1 で j の文字が 0 の場合に寄与します。 
2. このベースライン値を使用して回答を初期化します。 これは、スワップを実行しないという選択に相当します。 
3. 0 から n − 2 までのすべてのインデックス i について、位置 i と i + 1 で文字を交換することを検討します。この交換後に結果の文字列を構築します。 文字列を明示的に再構築する理由は、n が小さく、正確性が微細な最適化よりも重要であるためです。 
4. スワップされた各構成について、j < k のすべてのペア (j, k) をスキャンし、1 が 0 に先行する場合をカウントすることにより、その反転カウントを最初から計算します。これにより、脆弱な増分推論に依存することなく、そのスワップ選択の正確なコストが得られます。 
5. すべてのスワップ ポジションと元の構成の最小値を使用して答えを更新します。 

最終的に保存される値は、達成可能な最良の反転カウントです。 

### なぜ効果があるのか

 有効な最終構成は、元の文字列であるか、隣接する 1 つの転置だけが元の文字列と異なっています。 このような可能性をすべて列挙し、その正確な反転数を計算するため、到達可能な状態が見逃されることはありません。 逆数カウントは近似ではなく正確に再計算されるため、局所的な仮定による過小カウントや過大カウントのリスクはありません。 このアルゴリズムは、操作制約によって定義された到達可能な状態空間にわたって網羅的です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def inversion_count(s):
    n = len(s)
    cnt = 0
    for i in range(n):
        if s[i] == '1':
            for j in range(i + 1, n):
                if s[j] == '0':
                    cnt += 1
    return cnt

def solve():
    s = input().strip()
    n = len(s)

    best = inversion_count(s)

    s = list(s)
    for i in range(n - 1):
        s[i], s[i + 1] = s[i + 1], s[i]
        best = min(best, inversion_count(s))
        s[i], s[i + 1] = s[i + 1], s[i]

    print(best)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、すべての順序付きペアをスキャンし、`1`続いて`0`。 これは、初期設定とすべてのスワップされたバリアントの両方に使用されます。 

メイン ループは、隣接する各スワップを 1 回だけ試行し、その場で実行し、結果の反転カウントを評価して、元の文字列を復元します。 復元手順は不可欠です。 それを忘れると、複数のスワップが蓄積され、「最大 1 回の操作」という制約が破られてしまいます。

 ## 特殊なケース

 次のような完全にソートされた文字列の場合`000111`、最初の反転カウントはゼロです。 隣接するスワップでは、ローカルなスワップが作成されるため、少なくとも 1 つの反転が発生します。`10`パターン。 アルゴリズムは最初に元の文字列を評価するため、すべてのスワップが悪化したとしても、答えはゼロのままです。 

次のような完全に反転した文字列の場合`111000`、反転は最初に最大化されます。 位置 2 と 3 などの境界付近でのスワップにより、複数のブロック間反転が一度に減少します。 このアルゴリズムは、局所的な効果を仮定するのではなく、各スワップ後に完全な反転カウントを再計算するため、これらの境界スワップを明示的に評価し、改善を捉えます。
