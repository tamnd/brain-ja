 ## 解決策
 ## 問題の理解

 左から右にインデックスが付けられた整数のシーケンスが与えられており、このシーケンス内で正確に 3 つの位置を選択する必要があります。 制約は、選択した 2 つの位置が少なくとも次の距離で区切られている必要があるということです。`d`インデックス、つまりポジションを選択する場合`i < j < k`、 それから`j - i >= d`そして`k - j >= d`。 このようなすべての有効なトリプルの中で、選択した位置の値の可能な最大の合計が必要です。 

値だけよりも入力の構造が重要です。 各インデックスは潜在的な「アンカー ポイント」のように機能し、インデックスを選択すると、残りのピックに対してその周囲の禁止インデックスのウィンドウが制限されます。 タスクは、衝突しないように 3 つのアンカーを配置し、収集される重量の合計が最大になるようにすることです。 

制約`n ≤ 1500`ということを示唆しています$O(n^3)$すべてのトリプルに対するブルート フォースはすでに境界線に達していますが、場合によってはまだ実行可能です。 ただし、追加の内部チェックを使用してすべての組み合わせを調査しようとするアプローチは危険になります。 重要な信号は、選択サイズが 3 に固定されていることです。これは、多くの場合、プレフィックスまたはサフィックスに対する部分的な最適化が可能であることを意味します。 

貪欲に最初に最適な要素を選択してから拡張しようとすると、素朴だが微妙な失敗例が発生します。 たとえば、全体的な最大値が他の強力な要素に近すぎる一方で、わずかに小さな要素によって後でさらに 2 つの大きなピックが可能になるシーケンスを考えてみましょう。 貪欲な「最善のものを優先する」戦略は失敗します。 

入力:```
n = 6, d = 2
A = [100, 1, 1, 90, 1, 90]
```インデックス 1 (値 100) を貪欲に選択すると、距離の制約により両方の 90 がブロックされ、合計は 100 になります。最適解は 100 をスキップし、90 + 90 + 1 = 181 となります。これは、極大値の選択が構造的に無効であることを示しています。 

もう 1 つの落とし穴は、距離を対称的に強制せずに、これを独立した間隔選択として扱うことです。 1 つの要素を修正し、ギャップを強制せずに左側と右側を個別に最大化しようとすると、誤ってパーティション間の不正な隣接を許可してしまう可能性があります。 

実際の構造は、固定間隔の制約されたトリプル選択であり、動的プログラミングまたはプレフィックス/サフィックスの事前計算を強く示唆しています。 

## アプローチ

 ブルートフォースソリューションはインデックスのトリプルをすべて列挙します`i < j < k`そして、両方のギャップが制約を満たしているかどうかを確認します。 有効なトリプルごとに、次のように計算します。`A[i] + A[j] + A[k]`そして最大値を追跡します。 これは問題の定義と直接一致するため、正確性の観点からは簡単です。 

トリプルの数は次のとおりです。$O(n^3)$、これは$n = 1500$約 33 億回の反復が行われます。 最適化されたコードの内部ループが非常にタイトであっても、これは Python の許容限界をはるかに超えており、厳密な時間制約の下では C++ では依然として大きすぎます。 ボトルネックは反復回数だけでなく、繰り返される制約チェックにもあります。 

重要な観察は、トリプルの中央の要素が問題を 2 つの独立した部分 (有効な左の選択と有効な右の選択) に完全に分離しており、どちらも距離によって制限されているということです。`d`。 真ん中のインデックスになったら`j`は固定されているため、最も左側の要素はインデックスから取得する必要があります`≤ j - d`、最適な正しい要素はインデックスから取得する必要があります`≥ j + d`。 これにより、問題は最適なプレフィックス値とサフィックス値の事前計算に変換されます。 

2 つの配列を事前計算します。`best_left[i]`インデックスの最大値を格納します。`i`、 そして`best_right[i]`の最大値を格納します。`i`最後まで。 これらにより、中間インデックスのすべての選択が定数時間評価になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | プレフィックスとサフィックスの最適化 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を事前計算する`best_left`どこ`best_left[i]`の最大値です`A[0..i]`。 これにより、再度スキャンすることなく、任意の中間位置に対して最適な有効な左エンドポイントを即座にクエリできるようになります。 
2. 配列を事前計算する`best_right`どこ`best_right[i]`の最大値です`A[i..n-1]`。 これにより、対称的に、任意の中間位置に対して最適な有効な右エンドポイントが得られます。 
3. すべてのインデックスを反復処理します。`j`これをトリプルの中間要素として扱います。 
4. それぞれについて`j`、有効な左インデックスが存在するかどうかを判断します。 これには必要です`j - d >= 0`。 そうでない場合は、トリプルを形成できないため、この位置をスキップします。 
5. 同様に、チェックして有効な正しいインデックスが存在することを確認します。`j + d < n`。 そうでない場合はスキップしてください。 
6. 最も左の候補を次のように計算します。`best_left[j - d]`そして最適な候補者は`best_right[j + d]`。 
7. これらを組み合わせる`A[j]`そしてグローバル最大値を更新します。 

重要な構造上の考え方は、距離制約によってインデックス範囲が完全に分離されるため、中央が固定されると最適な左右の選択肢が独立するということです。 

### なぜ効果があるのか

 有効なトリプルに対して`(i, j, k)`、制約力`i ≤ j - d`そして`k ≥ j + d`。 そのようなすべての中で`i`、最良の選択は常に次の最大値です。`A[0..j-d]`、右側についても同様です。 インデックス制約により影響の重複が防止されるため、左の選択肢と右の選択肢の間に相互作用は存在しません。 これにより、すべての中間インデックスが 2 つの独立したエンドポイントを持つ独立した最適化問題を引き起こす分解が作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k, d = map(int, input().split())
a = list(map(int, input().split()))

best_left = [0] * n
best_right = [0] * n

best_left[0] = a[0]
for i in range(1, n):
    best_left[i] = max(best_left[i - 1], a[i])

best_right[n - 1] = a[n - 1]
for i in range(n - 2, -1, -1):
    best_right[i] = max(best_right[i + 1], a[i])

ans = -10**18

for j in range(n):
    if j - d < 0 or j + d >= n:
        continue
    left_best = best_left[j - d]
    right_best = best_right[j + d]
    ans = max(ans, left_best + a[j] + right_best)

print(ans)
```実装は完全にプレフィックスとサフィックスの maxima に依存しています。 の`best_left`配列は左から右に構築されるため、各位置はそのインデックスまでの可能な限り最良の値を蓄積します。 の`best_right`配列は同じロジックをミラーリングするために逆に構築されます。 

ループオーバー`j`中間の要素を強制します。 境界チェックは、必要なコンパニオンが両方とも存在することを保証するため、非常に重要です。 微妙な問題はインデックスの確保です`j - d`そして`j + d`は有効な範囲の包括的な境界であり、1 つずつシフトされたものではありません。 

すべての値が負である可能性がある場合を安全に処理するために、最終的な答えは非常に負の数に初期化されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, k, d = map(int, input().split())
    a = list(map(int, input().split()))

    best_left = [0] * n
    best_right = [0] * n

    best_left[0] = a[0]
    for i in range(1, n):
        best_left[i] = max(best_left[i - 1], a[i])

    best_right[n - 1] = a[n - 1]
    for i in range(n - 2, -1, -1):
        best_right[i] = max(best_right[i + 1], a[i])

    ans = -10**18
    for j in range(n):
        if j - d < 0 or j + d >= n:
            continue
        ans = max(ans, best_left[j - d] + a[j] + best_right[j + d])

    return str(ans)

# provided sample
assert run("10 3 2\n-1 4 2 -6 3 3 5 -1 4 -1\n") == "13"

# minimum size valid
assert run("3 3 1\n1 2 3\n") == "6"

# all equal
assert run("5 3 1\n10 10 10 10 10\n") == "30"

# negative values
assert run("5 3 1\n-1 -2 -3 -4 -5\n") == "-6"

# tight spacing
assert run("6 3 2\n1 100 1 100 1 100\n") == "201"
```| テスト入力 | 期待される出力 | 検証内容 |

 | すべて否定的 | -6 | マイナスの場合の正しい最大値 |

 ## 特殊なケース

 有効な中間位置が非常に限られている場合、微妙なエッジケースが発生します。 例えば：```
n = 5, d = 2
A = [10, 100, 1, 100, 10]
```距離 2 の両側に少なくとも 1 つの要素が必要であるため、インデックス 2 のみが有効な中間として機能します。アルゴリズムはチェックします。`j - d`そして`j + d`、だからそれだけ`j = 2`通ります。 計算結果は次のようになります`10 + 1 + 10 = 21`最適な左右の候補は構造によって強制されるため、これは正しいです。 

もう 1 つのケースは、最適なエンドポイントが境界近くにある場合です。 プレフィックス配列とサフィックス配列には境界が正しく含まれているため、`best_left[j - d]`有効な場合は常にインデックス 0 が含まれます。`best_right[j + d]`有効な場合、インデックス n-1 が常に含まれます。 これにより、プレフィックス配列をインデックス 1 から開始したり、範囲を誤ってシフトしたりする実装でよくある間違いである、最適なエッジ ソリューションが誤って除外されることが防止されます。
