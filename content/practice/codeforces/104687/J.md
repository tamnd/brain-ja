 ## アルゴリズムのチュートリアル

 間隔を考慮しながら、指定された数の要素を選択するための最適な合計を追跡する動的プログラミング ソリューションを構築します。 

1. DP テーブルを初期化します。`dp[j][i]`を選択した後に達成可能な最高の合計を表します。`j`要素、`j`-th 要素を位置に配置`i`。 この定式化により、各状態が最後に選択された位置に固定されます。これは、間隔をきれいに強制するために重要です。 
2. 基本ケースを設定します`j = 1`、位置で 1 つの要素を選択します`i`ただ価値を与えるだけ`A[i]`。 以前に選択されていないため、まだ制約は適用されません。 
3. 要素数ごとに`j`2から`k`、位置を反復処理します`i`左から右へ。 位置で`i`にすることを検討しています。`j`- 番目に選択された要素。 
4. ポジションを選ぶなら`i`として`j`- 番目の要素、以前に選択した位置は最大でも次の位置でなければなりません`i - d`。 したがって、有効なものすべてを調べます。`p ≤ i - d`そして最高のものを取る`dp[j-1][p]`。 
5. すべての状態について以前のすべての位置をスキャンすることを避けるために、反復中にローリング最大配列を維持します。`i`。 このプレフィックスの最適化により、状態ごとの線形から一定の償却時間への移行が短縮されます。 
6.アップデート`dp[j][i]`以前の最良の値に加えて`A[i]`。 
7. 表を埋めると、答えはすべての最大値になります。`dp[k][i]`有効な最終ポジションの場合。 

### なぜ効果があるのか

 DP は、選択されたすべてのポジションに少なくとも明確に定義された前任者がいることを強制します。`d`離れて。 最後に選択した位置を中心に状態を構築することで、すべての遷移がギャップ制約を明示的に尊重するため、無効な間隔が発生しないことが保証されます。 プレフィックス最大最適化は、有効な以前の位置の検索を事前に計算された最適な値に圧縮するだけで、最適な部分構造を維持するため、正確性は変わりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, d = map(int, input().split())
    a = list(map(int, input().split()))

    NEG = -10**30

    prev = [NEG] * n
    for i in range(n):
        prev[i] = a[i]

    for j in range(2, k + 1):
        best_prefix = [NEG] * n
        dp = [NEG] * n

        best_prefix[0] = prev[0]
        for i in range(1, n):
            best_prefix[i] = max(best_prefix[i - 1], prev[i])

        for i in range(n):
            if i - d >= 0:
                dp[i] = best_prefix[i - d] + a[i]

        prev = dp

    print(max(prev))

if __name__ == "__main__":
    solve()
```この実装では、メモリを節約するために以前の DP 層のみが保持されます。 各レイヤーは、選択した要素の数を固定することに対応します。 の`best_prefix`配列を使用すると、十分に離れた前の最適な位置を高速に取得できます。 

微妙な点は、大きな負のセンチネルで表される到達不能状態の処理です。 これがないと、無効な遷移が誤って最大値を支配する可能性があります。 もう 1 つの重要な点は、遷移は次の場合にのみ発生するということです。`i - d >= 0`、間隔が厳密に適用されていることを確認します。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です`d`十分に大きいため、非常にまばらな選択のみが可能です。 DP はこれを正しく処理します。`i - d`すぐに負になり、無効な遷移を防ぎます。 たとえば、`n = 5, k = 2, d = 4`、のようなペアのみ`(0,4)`は有効であり、DP はそれらの位置での遷移のみを許可します。 

もう 1 つのエッジ ケースは、最適解が初期の高い値をスキップする場合です。 プレフィックスベースの DP は、初期の最大値に貪欲にコミットせず、それらを将来の組み合わせの候補として保存するだけなので、これが正しく処理されることを保証します。 

最後のエッジ ケースには、負の値が含まれます。この場合、後でより適切な値へのアクセスをブロックする小さな正を多数取得するよりも、大きな負の値を少なくする方が優れています。 DP は常に、次の時点までのグローバルで最良の前の状態を考慮するため、`i - d`、ローカルで貪欲なトラップを自然に回避し、グローバルに最適な構造を維持します。
