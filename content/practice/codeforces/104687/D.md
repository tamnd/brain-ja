 ## 問題の理解

 2 つの整数間隔を使用して作業しています。 1 つの間隔ですべての有効な値が定義されます。$x$、もう 1 つは、次のすべての有効な値を定義します。$y$。 何ペアかを数えるように求められます$(x, y)$次のように形成できます$x$間隔から選択されます。$y$はその間隔から選択され、それらの合計は正確に固定された目標値になります$n$。 

幾何学的には、これは、直線上にある平面内の長方形内の格子点を数えることと考えることができます。$x + y = n$。 すべての有効なペアは、この対角線セグメント上の 1 つの整数点に対応します。 

制約は大きく、エンドポイントは次のとおりです。$10^9$。 これにより、次のすべての値の反復が即座に排除されます。$x$または$y$。 偶数ループするソリューション$10^9$通常の制限時間内では要素をクリアすることは不可能です。 交差点のサイズを一定時間で分析的に計算する方法が必要です。 

素朴な推論が微妙に失敗するケースは、すべての場合に次のように仮定した場合に発生します。$x$で$[l_1, r_1]$、値$y = n - x$にある場合は自動的に有効になります。$[l_2, r_2]$間隔の重複を注意深く追跡しないと、 たとえば、次の場合$n = 20$、$x = 1$力$y = 19$、両方の間隔が個別に大きい場合でも、2 番目の間隔の外側にある可能性があります。 正確さは、エンドポイントごとのソリューションの存在だけではなく、変換された範囲の重複に完全に依存します。 

変換された空間で間隔がまったく交差しない場合には、別の特殊なケースが発生します。 たとえば、可能な限り最小の金額の場合、$l_1 + l_2$すでに超えています$n$、または可能な最大の合計$r_1 + r_2$よりも小さいです$n$の場合、解決策は存在しません。 実現可能性の範囲を考慮しない単純なアプローチでも、ペアを数えようとして誤った正の値が生成される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる可能性を列挙することになります。$x$で$[l_1, r_1]$、計算する$y = n - x$、どうかを確認してください。$y$中にある$[l_2, r_2]$。 これは、すべての制約を直接強制するため、正しいです。 ただし、その実行時間は最初の間隔のサイズに比例し、最悪の場合は次のようになります。$10^9$。 でさえ$10^8$1 秒あたりの操作数は、実際の限界をはるかに超えています。 

重要な観察点は、次の方程式であるということです。$x + y = n$1 つの自由度が削除されます。 一度$x$選ばれて、$y$固定されています。 すべてをスキャンするのではなく、$x$、どれであるかを正確に判断できます。$x$値は有効な値を生成します$y$。 条件$l_2 \le n - x \le r_2$上の不等式として書き直すことができます$x$これにより、問題は 1 次元で 2 つの区間の交点を見つけることに変換されます。 

から$l_2 \le n - x \le r_2$、次のように導出されます。$$n - r_2 \le x \le n - l_2$$とても有効です$x$両方に存在する必要があります$[l_1, r_1]$そしてで$[n - r_2, n - l_2]$。 答えは、これら 2 つの間隔の交差の長さになります。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(r_1 - l_1 + 1)$|$O(1)$| 遅すぎる |
 | 最適 |$O(1)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 条件を変換します。$y$限界に入る$x$書き換えます$y = n - x$内部$l_2 \le y \le r_2$、生産$n - r_2 \le x \le n - l_2$。 この手順により、依存関係が削除されます。$y$、問題を単一の変数に縮小します。 

### 2. 有効な有効間隔を計算します。$x$現在、次の 2 つの制約があります。$x$: 元の間隔$[l_1, r_1]$、および変換された区間$[n - r_2, n - l_2]$。 有効な$x$値は両方を同時に満たす必要があります。 

### 3. 2 つの区間の交点を求めます。 

交差間隔は次のとおりです。$$L = \max(l_1, n - r_2), \quad R = \min(r_1, n - l_2)$$両方の制約が独立しており、同時に保持する必要があるため、このステップは正当化されます。 

### 4. 交点内の整数点を数える

 もし$L \le R$、整数の数は$R - L + 1$。 それ以外の場合は、有効なペアがありません。 

### なぜ効果があるのか

 すべての有効なペア$(x, y)$整数に一意に対応する$x$両方の間隔制約を満たします。 変革$y = n - x$有効なペアと有効なペアの間の全単射です$x$-価値観。 各ステップでは制約の等価性が維持され、制約が単一変数形式に書き換えられるだけであるため、アルゴリズムは値を破棄したり二重にカウントしたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

l1, r1, l2, r2, n = map(int, input().split())

left = max(l1, n - r2)
right = min(r1, n - l2)

if left <= right:
    print(right - left + 1)
else:
    print(0)
```コードは間隔変換を直接実装します。 唯一の微妙な点は、境界演算の慎重な処理です。 表現`n - r2`そして`n - l2`2 番目の間隔の X 軸への有効な投影を定義します。 取る`max`そして`min`両方の制約を同時に尊重することが保証されます。 最後の条件は、空の交差に対応する負の間隔長を防ぎます。

 このソリューションは、入力サイズに関係なく、固定量の整数演算を実行します。 これは、多くのテスト ケースであっても制約内に簡単に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    l1, r1, l2, r2, n = map(int, sys.stdin.readline().split())
    left = max(l1, n - r2)
    right = min(r1, n - l2)
    return str(max(0, right - left + 1))

# provided sample
assert run("1 10 1 10 20\n") == "1"

# minimal case, single point
assert run("0 0 0 0 0\n") == "1"

# no solution case
assert run("1 5 1 5 100\n") == "0"

# full overlap case
assert run("0 10 0 10 10\n") == "11"

# boundary tight intersection
assert run("2 8 3 9 10\n") == "6"
```| テスト入力 | 期待される出力 | 検証内容 |

 | 1 5 1 5 100 | 0 | 実行可能なペアがありません |

 ## 特殊なケース

 エッジ ケースの 1 つは、変換された間隔が元の間隔の完全に外側にある場合です。 たとえば、次のように入力します。```
1 3 10 20 5
```変換された境界を計算します。$5 - 20 = -15$、$5 - 10 = -5$。 とても有効です$x$2 番目の制約からは$[-15, -5]$。 との交差点$[1, 3]$空の範囲を与えるので、$L = 1$、$R = -5$、 そして$L > R$。 アルゴリズムは正しく 0 を出力します。 

もう 1 つのケースは、両方の区間が合計制約を満たす 1 つの点に集約される場合です。```
7 7 13 13 20
```変換された境界は、$20 - 13 = 7$そして$20 - 13 = 7$、したがって両方の間隔は正確になります$[7,7]$。 交差は単一点であり、アルゴリズムは 1 を返します。これにより、縮退区間が特別な分岐なしで自然に処理されることが確認されます。
