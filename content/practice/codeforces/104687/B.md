 ## 解決策
 ## 問題の理解

 整数のシーケンスが与えられ、ソートによってそれを並べ替えることができます。 ソート後、「隣接差分コスト」の合計を計算します。これは、ソートされたシーケンス内の連続する要素のすべてのペア間の絶対差分の合計です。 タスクは、この最終値を出力することです。 

言い換えれば、配列を取得し、非降順に並べ替えて、左から右に移動したときに 1 つの要素から次の要素にどれだけ「伸びる」かを測定します。 これは、ソート後のシングルパス計算です。 

の制約$n$は小さく、最大 100、値は最大 100 です。$10^5$。 これにより、次のことがすぐに分かります。$O(n^2)$または$O(n \log n)$ソリューションは簡単に十分に高速です。 単純な並べ替えでも実行時間に影響を与えるため、許容されます。 

微妙な点は、絶対値合計が順序に大きく依存することです。 ソートを行わないと、隣接する差異は配置に応じて任意に大きくなったり小さくなったりする可能性があります。 並べ替えをスキップする単純なアプローチでは、明らかに誤った結果が生成されます。 

典型的な間違いは、ソートされた配列ではなく元の配列で差分を計算することです。 たとえば、与えられた入力`[3, 1, 2]`、元の合計は`|3-1| + |1-2| = 2 + 1 = 3`、一方、正しくソートされた計算は次のようになります。`|1-2| + |2-3| = 1 + 1 = 2`。 この不一致は、並べ替えがオプションではないことを示しています。 

もう 1 つの特殊なケースは、すべての値が等しい場合です。 ソートされた配列は一定のままであり、結果はゼロでなければなりません。 絶対値の代わりに符号付き差分を誤って使用した実装でも、一部のテストには合格する可能性がありますが、符号混合の場合は失敗します。 

## アプローチ

 強引な解釈では、配列のすべての順列を試し、各順列の隣接する差分の合計を計算し、解釈に応じて最小値または必要な値を取得する可能性があります。 この問題では、ソートが明示的に必要なため、総当りビューは不要になりますが、メンタル モデルとしては依然として役立ちます。シーケンスを簡単に評価できるように構造化する順序付けを探しています。 

すべての置換コストを列挙する$n!$構成と各評価コスト$O(n)$、たとえそれが完全に不可能になります。$n = 10$。 これは要因爆発につながります。 

重要な観察は、この問題では順列にわたる最適化が求められていないということです。 最初に並べ替えるように明示的に指示しています。 配列がソートされると、構造は単調になります。 ソートされた配列で、隣接する差分の合計を計算する最良の方法は、単純に 1 回ウォークスルーすることです。 考慮すべき代替の順序がないため、組み合わせ爆発はなくなります。 

したがって、解決策はソートと線形累積の 2 つの操作に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての順列) |$O(n! \cdot n)$|$O(n)$| 遅すぎる |
 | 並べ替え + スキャン |$O(n \log n)$|$O(1)$または$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ

 1. 整数を読み取る$n$そして配列$a$。 これは単一のテスト ケースなので、一度処理します。 
2. 配列を非降順で並べ替えます。 これにより、隣接する要素の値がグローバルな意味で可能な限り近くなり、任意の順序付けの影響が排除されます。 
3. アキュムレータ変数を初期化する`ans = 0`。 これは、隣接する絶対差の合計を保存します。 
4. インデックスから反復処理する`1`に`n - 1`。 位置ごとに計算します`a[i] - a[i-1]`。 配列はソートされているため、この差は常に負ではないため、絶対値は不要です。 
5. それぞれの違いを追加します`ans`。 
6. 出力`ans`。 

### なぜ効果があるのか

 ソート後、シーケンスは単調非減少であるため、隣接するすべての差は、連続する順序統計間の真のギャップに等しくなります。 他の順序では、より大きなジャンプが発生するか、小さな局所的な違いが複数回複製されることになります。 ソートされた順序により、すべての要素が連続する値間の必要最小限の遷移に正確に参加するため、隣接する差分の合計は一意に決定され、ソートされた配列から直接計算できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    a.sort()
    
    ans = 0
    for i in range(1, n):
        ans += a[i] - a[i - 1]
    
    print(ans)

if __name__ == "__main__":
    solve()
```実装は簡単です。 並べ替えはその場で行われるため、メモリの使用量が最小限に抑えられます。 ループはインデックス 0 の境界チェックを避けるためにインデックス 1 から開始します。配列はソートされているため、絶対差を直接減算に置き換えます。これにより、不要な関数呼び出しが回避され、ロジックが簡素化されます。 

よくある間違いは、並べ替えを忘れたり、計算を忘れたりすることです。`abs(a[i] - a[i-1])`元のアレイ上で。 どちらも、問題で説明されている意図された変換に違反します。

import sys, io

def run(inp: str) -> str:

        ans += a[i] - a[i - 1]

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての要素が同一である場合です。 入力用`[7, 7, 7, 7]`、並べ替えは何も行わず、隣接する差分はすべてゼロになります。 アルゴリズムが生成するのは、`0`それぞれの減算でゼロが得られ、偶発的な累積がないことが確認されるためです。 

もう 1 つのケースは、入力がすでにソートされている場合です。 のために`[1, 2, 3, 4, 5]`、アルゴリズムは構造的な変更を実行せず、スキャンは連続したギャップの合計を直接計算しますが、これは構造上正しいものです。 

3 番目のケースは逆順序です。 のために`[5, 4, 3, 2, 1]`、並べ替えると次のように変換されます`[1, 2, 3, 4, 5]`、その後、計算はすでにソートされたケースと同様に進みます。 これは、アルゴリズムが初期順序に対して不変であり、マルチセット構造のみに依存することを示しています。
