 ## 解決策
 ## 問題の理解

 3 つの整数が与えられ、それぞれが三角形の潜在的な辺の長さを表します。 タスクは、これら 3 つの長さが有効な三角形を形成できるかどうかを判断することです。 

幾何学的には、1 つのセグメントが長すぎて他の 2 つのセグメントで「閉じる」ことができない場合にのみ、3 つのセグメントが三角形を形成します。 代数用語では、これは、任意の 2 つの辺の合計が 3 番目の辺より厳密に大きくなければならないという条件に変換されます。 3 つの値を扱っているため、3 つの順列すべてについてこの条件をチェックする必要があります。 

入力サイズは最小限で、それぞれ 1 から 100 までのちょうど 3 つの整数です。これにより、少数の一定数の条件をスキャンするアプローチでも十分であることがすぐにわかります。 データ構造、広範囲にわたるループ、または最適化に関する懸念は必要ありません。 ここで意味のある複雑さのクラスは定数時間チェックだけです。 

主なエッジケースは、境界線の平等から生じます。 素朴な読者は次のようなケースを誤って受け入れるかもしれません`1 2 3`なぜなら、和は 3 番目の辺に等しいが、等しいから三角形は形成されないからです。 もう 1 つの微妙なケースは、値が並べ替えられていない場合です。 例えば、`3 1 2`最大値が最後の位置にない場合でも、拒否される必要があります。 

## アプローチ

 この問題を考える強引な方法は、定義を直接適用することです。 3 つの不等式をすべてチェックします。`a + b > c`、`a + c > b`、 そして`b + c > a`。 すべてが true の場合、辺は三角形を形成します。 

問題のサイズはすでに一定であるため、これをさらに単純化する意味のある方法はありません。 「単純な」アプローチでも、辺のすべての順序を並べ替えて、並べ替えごとに三角形の妥当性をテストしようとする可能性がありますが、それによって不必要な繰り返しが発生します。 値が 3 つある場合、6 つの順列をチェックすることになり、それぞれに最大 3 つの比較が必要になります。これは依然として定数時間ですが冗長です。 

重要な観察は、三角形の妥当性は残りの辺に対するペアごとの合計にのみ依存するということです。 対称性を認識したら、3 つの条件すべてを直接チェックするか、辺を並べ替えて条件を 1 つの不等式に還元することができます。`x ≤ y ≤ z`、確認するだけで済みます`x + y > z`。 並べ替えると、より明確な構造が得られ、並べ替えについての推論が回避されます。 

どちらのアプローチも有効ですが、競技プログラミングではソートされたバージョンの方が高次元や同様の問題にきれいに一般化できるため、多くの場合好まれます。

 ## アルゴリズムのチュートリアル

 わかりやすくするために、ソートされたアプローチを使用します。 

1. 3 つの入力整数を読み取ります。 
2. リストに保存します。 
3. リストを降順でない順に並べ替えます。 
4. ソートされた値を次のようにします。`x`、`y`、 そして`z`、 どこ`z`一番大きな辺です。 
5. かどうかを確認します。`x + y > z`。 
6. 条件が成立した場合に出力`YES`、それ以外の場合は出力`NO`。 

ソートのステップはパフォーマンスではなく、推論の複雑さを軽減することを目的としています。 最大の要素が分離されると、三角形の条件は 3 つではなく 1 つの不等式に崩壊します。 

### なぜ効果があるのか

 三角形は、1 つの辺が他の 2 つの辺の合計と少なくとも同じ長さの場合にのみ存在できません。 並べ替えにより、常に最大の辺を他の 2 つの合計と比較することが保証されます。 この不等式が厳密に成立する場合、残りの 2 つの不等式は、両方とも少なくとも次の値と同じ大きさの合計が含まれるため、自動的に満たされます。`x + y`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b, c = map(int, input().split())
    sides = [a, b, c]
    sides.sort()

    if sides[0] + sides[1] > sides[2]:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```コードは 3 つの値を 1 行で読み取り、それらをリストに格納し、最大値が最後に来るように並べ替えます。 唯一の決定点は、2 つの小さい値と最大値の間の三角形不等式チェックです。 比較は厳密であり、合計が 3 番目の辺に等しい縮退ケースを正しく拒否します。

import sys, io

def run(inp: str) -> str:

 ## 特殊なケース

 一般的なエッジ ケースは、最大の辺が他の 2 つの辺の合計と正確に等しい場合です。 たとえば、入力`10 10 20`。 

並べ替えると、次のようになります`[10, 10, 20]`。 アルゴリズムチェック`10 + 10 > 20`、次のように評価されます`20 > 20`、 間違い。 出力は正しく行われています`NO`。 これにより、等価性が正しく扱われることが確認され、劣化した「平らな」三角形が防止されます。 

もう 1 つのケースは、入力が順序付けされていない場合です。`3 1 2`。 並べ替えると、これは次のように変換されます`[1, 2, 3]`、同じ不等式チェックでは正しく拒否されます。 これは、正確さが入力順序には依存せず、相対的な大きさのみに依存することを示しています。
