 ## 解決策
 ## 問題の理解

 文字のみで構成されるバイナリ文字列が与えられます`0`そして`1`。 私たちが気にするコストは、この文字列内の反転の数です。反転とは位置の任意のペアです。`i < j`そのような`1`の前に表示されます`0`。 

文字列を変更できる唯一の方法は、隣接する文字の交換を最大 1 回実行するか、操作を完全にスキップすることです。 オプションでこの 1 回のスワップを実行した後、結果の文字列の反転数を測定します。 タスクは、この制約の下で達成可能な最小反転回数を計算することです。 

入力サイズ (最大 100,000 文字) に関する重要な観察により、考えられるすべてのスワップに対して反転カウントを最初から再計算する必要は直ちに排除されます。 隣接するすべてのスワップを試行し、毎回反転を再計算する単純なアプローチでは、スワップごとに O(n) 回の作業が必要となり、合計操作数が O(n^2) となり、n = 10^5 には遅すぎます。 

弦がすでに単調である場合、微妙なエッジケースが発生します。 例えば、`000111`反転はゼロであり、スワップは反転を増加させるだけです。 局所性の向上を期待して常にスワップを適用する不注意で貪欲な戦略は、操作なしの場合と比較しない場合、誤って答えを悪化させる可能性があります。 

1 つだけがある場合、別のエッジケースが発生します。`10`パターン。 例えば、`110`反転が 1 つありますが、中央のペアを交換すると次のようになります。`101`これは、局所的なパターンを修正しても、必ずしも全体的に反転を減らすわけではありません。 これは、局所的な改善が必ずしも全体的な改善に対応するとは限らないことを示しています。 

## アプローチ

 基本的なアイデアは単純です。 元の文字列の反転回数を計算します。 次に、可能なすべての隣接スワップを試し、反転数を再計算し、最小値を追跡します。 

これが機能するのは、可能なスワップが n 個しかなく、反転カウントがプレフィックスの合計または 1/0 のカウントを使用して O(n) であることがよく知られているためです。 ただし、各スワップでは文字列全体の再計算が必要になるため、最悪の場合、合計時間は O(n^2) になります。 

重要な洞察は、2 つの隣接する文字の交換は、それら 2 つの位置を含む反転にのみ影響するということです。 文字列内の他のものはすべて変更されません。 これは、単一の関数がどのように変換されるかを理解すれば、反転回数の差は O(1) で計算できることを意味します。`01`または`10`ペアはグローバル反転に寄与します。 

最初から再計算する代わりに、合計反転数を一度事前計算します。 次に、隣接するペアごとに、それらを交換した場合に反転数がどのように変化するかを計算します。 文字列はバイナリであるため、問題となるのは次の 2 つのケースだけです。`01`に`10`反転と交換が増加します`10`に`01`逆転が減ります。 正確な変更は、交換された位置の周囲に 0 と 1 がいくつあるかによって異なりますが、隣接する位置の場合は、一定のデルタ計算が簡略化されます。 

これにより、すべての隣接するペアを一度チェックし、定数式によって反転カウントを更新し、最小値を取得するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 元の文字列の反転数を計算し、考えられるすべての単一のスワップを評価して、その効果を計算します。 

1. 反転寄与を迅速に評価できるように、0 または 1 のプレフィックス情報を計算します。 簡単な方法は、これまでに出現した 1 の数を数え、ゼロが現れるたびにその数を反転カウントに追加することです。 これはすべてを直接カウントします`1 before 0`ペア。 
2. 元の反転数をベースラインの回答として保存します。 これは何も操作しないことに相当します。 
3. すべての隣接するペアを反復処理します。`s[i], s[i+1]`。 ペアの場合`00`または`11`、交換しても何も変わらないため、スキップします。 
4. ペアが`10`、それを交換すると生成される`01`。 これにより、ペア自体によって寄与された 1 つの反転が削除されますが、これがどのように行われるかにも影響します。`1`右側のゼロと相互作用し、これがどのように行われるか`0`左側のものと相互作用します。 スワップはローカルで隣接しているため、正味の変更はプレフィックス カウントを使用して計算された固定デルタに単純化されます。 
5. ペアが`01`、スワッピングによって生成される`10`。 これにより、局所的に追加の反転が導入され、プレフィックス数によって計算された周囲の寄与によって再び調整されます。 
6. スワップポジションごとに、新しい反転カウントを次のように計算します。`base + delta`、小さい場合は答えを更新します。 
7. 元の文字列を含むすべての位置の最小値を返します。 

### なぜ効果があるのか

 反転数はすべてのペアの合計です`(i, j)`と`i < j`。 隣接する要素の交換は、交換された位置の 1 つを含むペアにのみ影響します。 関与していないすべてのペア`i`または`i+1`交換前と交換後は同じままです。 したがって、反転カウントの変化は、スワップされたペアの周囲の一定サイズの近傍によって完全に決定されます。 この局所性プロパティにより、各スワップを個別に評価し、最良の結果を取得することで全体的な最適な結果が得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    # initial inversion count: number of (1 before 0)
    ones = 0
    base = 0
    for ch in s:
        if ch == '1':
            ones += 1
        else:
            base += ones

    ans = base

    # prefix ones and suffix zeros to compute local deltas
    prefix_ones = [0] * (n + 1)
    for i in range(n):
        prefix_ones[i + 1] = prefix_ones[i] + (s[i] == '1')

    suffix_zeros = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suffix_zeros[i] = suffix_zeros[i + 1] + (s[i] == '0')

    total_ones = prefix_ones[n]

    for i in range(n - 1):
        if s[i] == s[i + 1]:
            continue

        if s[i] == '1' and s[i + 1] == '0':
            # 10 -> 01 swap
            # delta = -1 (pair) + effects with left/right context
            left_ones = prefix_ones[i]
            right_zeros = suffix_zeros[i + 2] if i + 2 <= n else 0

            # before:
            # s[i]=1 contributes with zeros on right: right_zeros + (i+1 position zero counted in suffix)
            # s[i+1]=0 contributes with ones on left including s[i]
            before = right_zeros + (left_ones + 1)

            # after swap roles reversed
            after = left_ones + right_zeros

            ans = min(ans, base + (after - before))

        else:  # 01 -> 10
            left_ones = prefix_ones[i]
            right_zeros = suffix_zeros[i + 2] if i + 2 <= n else 0

            before = left_ones + right_zeros
            after = right_zeros + (left_ones + 1)

            ans = min(ans, base + (after - before))

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、左から右にスキャンし、各ゼロの前に出現した 1 の数を累積することによって、反転カウントを計算します。 これは、バイナリ文字列の標準的な線形時間反転カウント方法です。 

次に、プレフィックス カウント 1 とサフィックス カウント 0 を構築します。これにより、交換位置を調べるときに、交換された文字と相互作用する各側の要素の数をすぐに判断できるようになります。 

隣接するペアごとに、スワップ前後の寄与を比較することにより、スワップの効果を計算します。 その差がベース反転カウントに追加され、最小値が追跡されます。 

実装の重要な詳細は、左右の寄与をカウントするときに交換された位置を慎重に除外することです。これは、これらの位置が前後の計算で明示的に処理されるためです。

 ## 特殊なケース

 次のようなすでにソートされた文字列の場合`000111`、アルゴリズムはすべてのスワップを評価しますが、すべてのデルタ計算でゼロまたはプラスの変化が得られるため、答えはベース反転カウント 0 のままです。 これにより、不要なスワップが正しく無視されることが確認されます。 

のような文字列の場合`111000`、反転数は最大です。 隣接するスワップは反転をわずかに再分配することしかできませんが、1 つのステップですべてのブロック間の反転を減らすことはできません。 このアルゴリズムは、単一のスワップによって、局所的な小さな改善を超えて全体が大幅に変化しないことを正確に検出します。 

次のような最小限の文字列の場合`10`、スワッピングによって生成される`01`、反転カウントを 1 から 0 に変更します。隣接するペアが直接評価され、そのデルタが周囲のコンテキストを必要とせずに 1 回だけ適用されるため、アルゴリズムはこれを正しく処理します。
