 ## 解決策

 ## 問題の理解

 の番号付けを作成するように求められます。$N \times N$以下のすべての整数を使用するグリッド$1$に$N^2$、それぞれ 1 回ずつ。 この番号付けはチェスの駒がどのように動くかを定義しますが、重要な考え方は、動きは恣意的ではないということです。各ステップで、駒は 1 つのチェスの動きで到達可能な未訪問のすべてのセルを調べ、割り当てられた番号が最も小さいものを常に選択します。 そのような移動が存在しない場合は、最も小さい番号の未訪問のセルにテレポートし、コスト 1 を支払います。 

このプロセスを 2 回シミュレートします (1 というラベルの付いたセルから開始して、ルークに対して 1 回、クイーンに対して 1 回)。目標は、ルークが支払うテレポート コストがクイーンよりも厳密に少なくなるようにグリッドを設計することです。 

移動ルールは、ボードを、エッジがピースのタイプに依存する動的に明らかにされるグラフ トラバースに効果的に変換します。 ルークには行と列の可視性のみが表示されますが、クイーンにはさらに対角線が表示されます。 番号付けにより、暗黙的な可視性グラフに対する貪欲なウォークと同様の強制的なトラバース順序が課されます。 

制約により許可されるのは、$N$最大 500 なので、構築は次のようにする必要があります。$O(N^2)$。 それぞれのシミュレーションはすでに完了しているため、多くの候補ボードで両方の部分をシミュレートする試みは不可能です。$O(N^2)$、そしてチェックする代わりに建設的な議論が必要になります。 

微妙な問題が現れるのは、$N = 1$。 セルは 1 つだけで、移動やテレポートがないため、どちらのコストもゼロであり、厳密な不平等は不可能です。 これは即時不可能な唯一のケースです。 

もう 1 つの隠れた問題は、両方の部分が同じセルから開始され、初期の番号の順序が領域内で「スタック」して強制的にテレポートするかどうかに大きく影響することです。 基板の構造が不十分な場合、ほとんどのプロセスで両方の部品が同じように動作するため、コストを分離することができなくなります。 

## アプローチ

 直接的なアプローチは、多くのランダムまたは構造化されたグリッドを試し、ルークとクイーンの両方のプロセスをシミュレートすることです。 各シミュレーションでは、到達可能な未訪問のセルを追跡し、最小ラベルを繰り返し選択する必要があり、これにはすでにコストがかかります$O(N^2 \log N)$優先構造を持っています。 複数の構築を試すことは不可能です$N = 500$、完全なシミュレーションを 1 つ行っても、すでにボーダーラインに達しているためです。 

重要な観察は、ルークとクイーンの違いは完全に接続性から来ているということです。対角線がはるかに多くのセルを接続しているため、クイーンの方が厳密にはより多くのエッジを持っています。 ルークがラベル順序で単一の接続された進行を維持する一方、クイーンが切断された到達可能なコンポーネントに頻繁に分割される状況を強制できれば、クイーンはより頻繁にテレポートすることを強制されます。 

これは、ルークの接続性がラベルの増加とグローバルに一致するグリッドを構築することを示唆していますが、貪欲な順序を妨げる対角制約によりクイーンの接続性が早期に「切断」されます。 これを達成する簡単な方法は、行ごとにヘビのような順序でグリッドを線形化し、ルークの動きがほぼ継続的にそれに追従できるようにする一方で、クイーンの斜めのジャンプは、斜めの隣接性が役に立たないラベル配置によってブロックされることです。 

有効な古典的な構造は、グリッドを行ごとに交互の方向に埋めることです。 これにより、連続する数字が常にルークに隣接することが保証されます。 次のすべての数字が同じ行または隣接する行にあり、ルークが直接表示されるため、ルークはテレポートすることなく常に続行できます。 ただし、女王は、意図したチェーンをスキップする斜めのショートカットを取得し、単調な隣接構造を破壊し、貪欲なルールによってアクセス可能なセルが使い果たされたときに追加のテレポートを強制します。 

この非対称性は、ルークの動きが構築の隣接パスと一致するのに対し、クイーンの動きは貪欲なアクセシビリティ順序を混乱させる代替エッジを導入するために発生します。

 ## アルゴリズムのチュートリアル

 行に沿って数値が増加し、行ごとに方向が変わるようにグリッドを構築します。 

1. 空の状態から始めます$N \times N$グリッドと 1 に初期化されたカウンター。このカウンターは、次に割り当てるラベルを表します。 
2. 行を上から下に繰り返します。 各行について、行インデックスのパリティに基づいてトラバース方向を決定します。 
3. 行インデックスが偶数の場合は、左から右に連続する番号を入力します。 奇数の場合は右から左へ埋めていきます。 これにより、グリッド全体に連続した蛇のパスが作成されます。 
4. 現在のカウンタ値を各訪問セルに割り当て、割り当てのたびに値をインクリメントします。 これにより、1 から 2 までのすべての数値が保証されます。$N^2$は 1 回だけ使用されます。 

方向を交互にする理由は、ルークの移動時に、行内で水平に、またはある行の終わりと次の行の始まりの間で垂直に、連続する数字が常に端に隣接していることが保証されるためです。 

### なぜ効果があるのか

 貪欲なルールによって引き起こされるルークのトラバーサルは、ラベルの自然な単調な増加に従います。 連続する数字のペアはすべて 1 回の移動でルークに到達できるため、ルークは開始領域を出た後にテレポートする必要はありません。 

クイーンは厳密により多くの動きを持っているため、到達可能なセットは各ステップでより大きくなります。 しかし、この利点は貪欲な選択の下では欠点になります。女王はスネークの順序と一致していない領域に斜めにジャンプする可能性があり、これによりきれいな連続的な進行が崩れ、ローカルで到達可能な未訪問のセルが早期に枯渇してしまいます。 これにより、ルークと比較して追加のテレポート イベントが発生します。 

厳密な不平等が達成されるのは、クイーンの追加の移動オプションが強制的な直線チェーンへの干渉を引き起こす一方で、ルークはそれにきれいに従うためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
if n == 1:
    print(-1)
    sys.exit()

grid = [[0] * n for _ in range(n)]
num = 1

for i in range(n):
    if i % 2 == 0:
        for j in range(n):
            grid[i][j] = num
            num += 1
    else:
        for j in range(n - 1, -1, -1):
            grid[i][j] = num
            num += 1

for row in grid:
    print(*row)
```解決策はまず、些細な不可能なケースを処理します$N = 1$、建設の有無によってコストに差が生じることはありません。 

次に、単純なヘビ パターンを使用してグリッドを塗りつぶします。 交互方向は、行境界を越えて連続する番号の隣接性を保証するため、不可欠です。 1 行おきに反転しないと、行間の移行によって大きなジャンプが発生し、ルークの連続性が損なわれてしまいます。 

最後に、グリッドが行ごとに印刷されます。

 ## 特殊なケース

 のために$N = 1$の場合、アルゴリズムはすぐに -1 を出力します。 これは、動きが存在せず、どちらのピースも同じコストがゼロであるという事実と一致するため、厳密な不平等は成り立ちません。 

のために$N = 2$、スネークフィルは、ルークに隣接するセル上に完全なハミルトニアンパスを生成します。 ルークはテレポートせずに移動でき、すべての番号が一意に割り当てられるため、構造は有効なままです。 

大型の場合$N$、交互の行反転により、連続するすべての数字のペアが水平方向または垂直方向にルークに隣接したままになります。 これにより、ルークが貪欲な連鎖を決して切断しないことが保証されるため、必要に応じてルークとクイーンの動作が一貫して分離されるように構成されています。
