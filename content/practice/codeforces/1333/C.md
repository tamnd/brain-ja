 ## 解決策
 ## 問題の理解

 整数のシーケンスが与えられ、このシーケンスのうち、非常に特殊な意味で「堅牢」な連続セグメントがいくつあるかを数えるように求められます。 セグメントは、空ではない連続するサブセグメントの合計がゼロでない場合に有効であるとみなされます。 

同様に、すべてのサブ配列を検索し、内部間隔が完全にゼロに相殺されないサブ配列のみを保持します。 候補セグメント内に 1 つのゼロサム部分配列があるだけで、候補セグメントを失格にするのに十分です。 

入力サイズは最大 200,000 要素に達するため、すべての部分配列を明示的に検査するソリューションは即座に除外されます。 素朴なアプローチでは、O(n²) 個の部分配列を調べ、それぞれの内部ゼロ和構造をチェックすると、O(n³) か、せいぜい O(n² log n) に近づくことになりますが、これは 2 秒間の実行可能な限界をはるかに超えています。 

主な困難は、条件がサブ配列全体だけに関するものではなく、その内部サブセグメントすべてに関するものであることです。 これにより、エンドポイントに対して直接ローカルではないネストされた制約が導入されます。 

いくつかの危険な状況は、早めに切り分ける価値があります。 

完全にゼロフリーのプレフィックス合計構造は、正確性を保証しません。 たとえば、`[1, -1, 2]`、配列全体がゼロ以外の和を持ちますが、次の理由により無効です。`[1, -1]`合計はゼロになります。 単純な「全額をチェックするだけ」というアプローチは、ここでは失敗します。 

もう 1 つの微妙なケースは、キャンセルが重なっていることです。 で`[1, 2, -1, -2]`、プレフィックスもサフィックスも単独では危険に見えませんが、内部構造により複数のゼロサム区間が作成されます。 

本当の課題は、部分配列内で繰り返されるプレフィックス和のペアが部分配列に含まれているかどうかを検出することです。これは、まさにゼロサム部分配列が存在する場合に発生するためです。 

## アプローチ

 ブルートフォース手法は簡単です。 サブ配列ごとに`[l, r]`、その中でプレフィックスの合計を計算し、2 つのプレフィックスの合計が一致するかどうかを確認できます。 一致する場合は、一部の内部セグメントの合計がゼロになることを意味します。 そうでない場合、サブ配列は有効です。 これには、すべての O(n²) 個のサブ配列をスキャンする必要があり、各チェックのコストは O(n) で、O(n³) が生成されます。 重複をより迅速に検出するためにプレフィックス ハッシュを使用したとしても、依然として O(n²) 個のサブ配列と、サブ配列境界管理ごとの O(n) 個の作業が必要となり、依然として遅すぎます。 

重要な観察は、条件を逆転させることです。 部分配列は、ペアが存在する場合にのみ無効です。`(i, j)`その内部では、prefixSum[i] が prefixSum[j] と等しくなります。 これは、すべての無効なサブ配列に、繰り返しのプレフィックスと合計のペアが「強制的に」含まれることを意味します。 

サブ配列の内部繰り返しをチェックする代わりに、プレフィックスの合計がグローバルに繰り返される場所を追跡します。 各位置について、各プレフィックス合計の最後の出現を維持できます。 インデックスにいる場合`r`、その後で始まる任意の部分配列`l <= lastSeen[prefixSum[r]] + 1`繰り返しのプレフィックス合計が含まれるため、予測可能な方法で無効になります。 

これにより、問題は、以前に発生したプレフィックス合計によって引き起こされる競合を回避するサブ配列のカウントに変換されます。 右端点を処理し、有効な最小の左境界を維持できます。 

この問題は古典的な「制約伝播を伴う 2 つのポインター」になります。右側の境界を拡張するときに、プレフィックスの合計の繰り返しがウィンドウ内の条件に違反することを検出するたびに、左側の境界を前方にシフトします。

 ## アルゴリズムのチュートリアル

 接頭辞の合計を使用して、サブ配列の合計を差分としてエンコードします。 

1. プレフィックスの合計を計算する`pref`、 どこ`pref[i]`最初の合計です`i`要素。 これにより、任意の部分配列の合計を次のように表現できるようになります。`pref[r] - pref[l-1]`。 
2. 辞書を管理する`last`各プレフィックス合計値を最新のインデックスにマッピングします。 これは、各累積合計が最後に確認された場所を追跡します。 
3. ポインタを維持する`l`現在の位置で終わるサブ配列の最小の有効な開始インデックスを表します。 当初は、`l = 1`。 
4. 反復する`r`1からnまで。 各ポジションについて:

 1. もし`pref[r]`以前インデックスで見られました`p`、その後、それ以前で始まる任意の部分配列`p`で終わるウィンドウ内で繰り返されるプレフィックスの合計が含まれます。`r`。 したがって、アップデート`l = max(l, p + 1)`。 
2.アップデート`last[pref[r]] = r`。 
5. それぞれについて`r`、で終わるすべてのサブ配列`r`そしてから始まる`l`に`r`有効です。 追加`(r - l + 1)`答えに。 

### なぜ効果があるのか

 ゼロサム部分配列は、その中に 2 つの等しいプレフィックス合計が発生する場合にのみ存在します。 最後の発生を追跡することで、現在のエンドポイントに影響を与える最も制限的な繰り返しを常に把握できます。 左のポインタ`l`は常に、現在のウィンドウ内で禁止された重複プレフィックス合計を作成する位置を超えた位置に留まります。 これにより、カウントされたすべてのサブ配列のすべてのプレフィックス合計が異なることが保証されます。これは、ゼロサム内部セグメントがないのと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pref = 0
    last = {0: 0}
    l = 1
    ans = 0

    for r in range(1, n + 1):
        pref += a[r - 1]

        if pref in last:
            l = max(l, last[pref] + 1)

        last[pref] = r

        ans += (r - l + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、プレフィックスの合計を使用してサブ配列の合計を差分に変換し、ハッシュ マップを使用して各プレフィックスの合計が最後に出現した場所を追跡します。 左ポインタは、繰り返しのプレフィックス合計を含むセグメントを決してカウントしないようにします。 重要な実装の詳細は、プレフィックス合計のインデックスが 1 ベースであるのに対し、配列は 0 ベースであるため、ウィンドウ サイズを計算する際の算術演算がクリーンに保たれることです。 

アップデート`l = max(l, last[pref] + 1)`重要です。 これにより、以前に発生した同じプレフィックス合計がウィンドウに含まれるのを防ぎます。そうしないと、セグメント内にゼロサム部分配列が導入されてしまいます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))

    pref = 0
    last = {0: 0}
    l = 1
    ans = 0

    for r in range(1, n + 1):
        pref += a[r - 1]
        if pref in last:
            l = max(l, last[pref] + 1)
        last[pref] = r

    return str(ans)

 ## 特殊なケース

 内部サブ配列が存在しないため、単一要素の配列は常に有効です。 アルゴリズムが初期化されます`last = {0: 0}`そして数えます`(r - l + 1) = 1`、期待される結果と一致します。 

次のようなプレフィックスの合計が繰り返される配列`[1, -1, 1, -1]`左境界の頻繁なリセットをトリガーします。 毎回のプレフィックスの合計`0`再表示されると、以前のセグメントは除外されます。 実装は正しく更新されます`l`無効な開始位置をスキップして、完全なキャンセルを含むサブ配列が誤ってカウントされないようにします。 

次のような大きな均一配列`[1, 1, 1, ..., 1]`プレフィックスの衝突は決して発生しないため、`l`すべての部分配列は有効であり、答えは次のようになります。`n(n+1)/2`、アルゴリズムが自然に蓄積します。`(r - l + 1)`各ステップで。
