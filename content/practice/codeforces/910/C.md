 ## 解決策
 ## 問題の理解

 文字から作られたいくつかの文字列が与えられます`'a'`を通して`'j'`。 元々、これらの文字列は 10 進数でした。 いたずら者はすべての数字を一意の文字に置き換え、10 桁の間に 1 対 1 の対応関係を作成しました。`0...9`そして10の手紙`a...j`。 

同じ文字は常に同じ数字を表し、異なる文字は異なる数字を表します。 私たちの仕事は、結果として得られるすべての数値が有効になるように、つまり数字で始まる数値が存在しないように、そのようなマッピングを再構築することです。`0`、再構成されたすべての数値の合計は可能な限り小さくなります。 

重要な観察は、個々の数値を独立して再構築しているわけではないということです。 文字への数字の 1 つの割り当ては、すべての文字列にわたってグローバルに機能する必要があります。 

文字列の長さの点では制約は小さいです。 文字列は最大 1000 個あり、各文字列の長さは最大 6 であるため、文字位置の総数は最大 6000 になります。つまり、すべての文字を処理し、位置の寄与を計算する余裕があることを意味します。 個別の文字の数は 10 に固定されており、非常に少ないです。 これら 10 文字の並べ替えや割り当てを伴うアルゴリズムは、基本的に定数時間です。 

魅力的だが危険な間違いは、それぞれの出来事を独立して扱うことです。 文字に割り当てられた数字は、その文字が出現するすべての場所に影響します。 例えば：```
2
aa
a
```もし`a`数字が割り当てられています`9`、合計は`99 + 9 = 108`。 もし`a`数字が割り当てられています`1`、合計は`11 + 1 = 12`。 すべての出現は同時に寄与するため、各文字のすべての位置効果を集約する必要があります。 

もう 1 つの微妙な問題は、先頭のゼロの制限です。 考慮する：```
2
ab
ac
```手紙`a`は複数桁の数字の最初の文字として表示されるため、数字を割り当てる`0`に`a`は違法です。 数字を与えるだけの貪欲な戦略`0`この制約をチェックせずに最も価値の低い文字に変換すると、無効な再構築が生成される可能性があります。 

3 番目の特殊なケースは、文字が先頭文字として表示されない場合に発生します。 このような文字は、数字を受け取ることができる唯一の種類の文字です。`0`。 このステートメントは、有効な割り当てが常に存在することを保証しますが、アルゴリズムは依然として正しいゼロ候補を選択する必要があります。 

例えば：```
1
ab
```ここ`a`ゼロにはできませんが、`b`できる。 割り当てる`b = 0`そして`a = 1`有効な最小数値を与える`10`。 

## アプローチ

 ブルートフォースソリューションでは、数字から文字への可能な割り当てをすべて列挙します。 文字と数字が 10 個あるので、次のようになります。`10! = 3,628,800`全単射。 各割り当てについて、結果の合計を評価し、有効な最小値を維持できます。 

ブルートフォース方式は、考えられるすべてのマッピングをチェックするため、正しい方法です。 問題は仕事量です。 たとえマッピングの評価が非常に低コストであったとしても、数百万の割り当てはすでに 1 秒の制限には多すぎます。 

より良い解決策を見つけるには、合計がどのように形成されるかを調べる必要があります。 

単位の位置に文字が 5 回出現するとします。 数字の割り当て`7`その手紙に貢献します`5 × 7`最終的な金額まで。 同じ文字が 100 の位に 2 回出現する場合、それが影響します。`2 × 100 × 7`。 

手紙のすべての貢献を単一の係数に組み合わせることができます。$$\text{contribution} = \text{digit(letter)} \times \text{weight(letter)}$$どこ`weight(letter)`文字が表示されるすべての位の値の合計です。 

合計額は、$$\sum \text{digit(letter)} \times \text{weight(letter)}$$これで、問題ははるかに明確になりました。 重みは 10 個あり、数字を割り当てる必要があります`0...9`彼らに。 加重合計を最小化するには、小さい桁にはより小さい重みを割り当て、大きい桁にはより大きな重みを割り当てる必要があります。 これは標準的な交換引数です。 

唯一の複雑さは数字です`0`。 複数桁の数字の先頭の文字に割り当てることはできません。 ゼロの対象となるすべての文字の中で、最小の重みを持つ文字を選択する必要があります。ゼロはその重みを完全に削除するためです。 

ゼロ文字を修正した後、残りの 9 文字に数字が入ります`1...9`体重の軽い順に。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(10!・T) | お(1) | 遅すぎる |
 | 最適 | O(T + 10 log 10) | お(10) | 承認済み |

 ここ`T`すべての文字列の合計文字数です。 

## アルゴリズムのチュートリアル

 1. 配列を作成する`weight[10]`、文字ごとに 1 つのエントリ。 
2. すべての文字列を右から左にスキャンします。 右端の位置が貢献します`1`、次は貢献します`10`、 それから`100`、 等々。 
3. 位の値のある位置に文字が出現するたびに`p`、 追加`p`その手紙の重みに。 
4. ゼロになることが禁止されている文字を記録します。 1 を超える長さの文字列の最初の文字として出現する文字は禁止されます。 
5. 禁止されていないすべての文字の中で、最も小さい重みを持つ文字を選択します。 数字の割り当て`0`この手紙に。 
6. 残りの 9 文字を集めて、重さの昇順に並べ替えます。 
7. 数字の割り当て`1, 2, ..., 9`これらの文字をソート順に並べます。 
8. 最終的な答えを次の合計として計算します。`digit(letter) × weight(letter)`10文字全部にわたって。 

### なぜ効果があるのか

 文字の重みは、数字の割り当てとはまったく関係ありません。 重みが判明すると、最終的な合計は重み付けされた一次式になります。 

ゼロを受け取ることが許可されているすべての文字の中で、最小の重みにゼロを割り当てることが常に最適です。 より大きな重みにゼロが割り当てられ、より小さな適格な重みに正の数字が割り当てられた場合、それらの割り当てを交換すると合計が減少します。 

ゼロ文字を修正した後は数字のみ`1...9`残る。 2 つの文字に重みがあると仮定します`w1 ≤ w2`ただし数字を受け取る`d1 > d2`。 数字を入れ替えると合計が変わります$$(w1d2+w2d1)-(w1d1+w2d2) =(w2-w1)(d1-d2)\ge 0$$したがって、元の割り当てが交換された割り当てよりも優れることはありません。 この引数を繰り返し適用すると、重みと桁を同じ方法で順序付けする必要があることがわかります。 したがって、残りの文字を重みでソートし、数字を割り当てます`1...9`昇順で、可能な最小の合計が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    weight = [0] * 10
    leading = [False] * 10

    for _ in range(n):
        s = input().strip()

        if len(s) > 1:
            leading[ord(s[0]) - ord('a')] = True

        place = 1
        for ch in reversed(s):
            weight[ord(ch) - ord('a')] += place
            place *= 10

    zero_letter = -1
    best_weight = None

    for i in range(10):
        if not leading[i]:
            if best_weight is None or weight[i] < best_weight:
                best_weight = weight[i]
                zero_letter = i

    letters = [i for i in range(10) if i != zero_letter]
    letters.sort(key=lambda x: weight[x])

    digit = [0] * 10

    for d, letter in enumerate(letters, start=1):
        digit[letter] = d

    ans = 0
    for i in range(10):
        ans += digit[i] * weight[i]

    print(ans)

solve()
```最初の部分では、すべての文字の位置の重みを計算します。 数値を直接再構成する代わりに、各文字が割り当てられた桁の単位あたりの最終合計にどれだけ寄与するかを累積します。 

の`leading`配列は、どの文字がゼロの受け取りを禁止されているかを追跡します。 複数桁の文字列の最初の文字のみが重要です。 1 桁の数値には先行ゼロがないため、復元後は正当にゼロになる可能性があります。 

の選択`zero_letter`最もデリケートなステップです。 先頭としてマークされていない文字のみを検索し、最小の重みを選択します。 これにより、不必要な寄与が可能な限り最大限に除去されます。 

ゼロ文字を除外した後、残りの文字が重み順に並べ替えられます。 数字の割り当て`1...9`この順序で交換引数の最適化を実装します。 

可能な最大の重みは Python の整数機能の範囲内ですが、Python の整数を使用すると、オーバーフローの問題が自動的に回避されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())

    weight = [0] * 10
    leading = [False] * 10

    for _ in range(n):
        s = input().strip()

        if len(s) > 1:
            leading[ord(s[0]) - ord('a')] = True

        place = 1
        for ch in reversed(s):
            weight[ord(ch) - ord('a')] += place
            place *= 10

    zero_letter = -1
    best_weight = None

    for i in range(10):
        if not leading[i]:
            if best_weight is None or weight[i] < best_weight:
                best_weight = weight[i]
                zero_letter = i

    letters = [i for i in range(10) if i != zero_letter]
    letters.sort(key=lambda x: weight[x])

    digit = [0] * 10
    for d, letter in enumerate(letters, start=1):
        digit[letter] = d

    ans = sum(weight[i] * digit[i] for i in range(10))
    return str(ans)

assert run("1\na\n") == "1"

# only one used letter
assert run("3\na\na\na\n") == "3"

# leading-zero restriction
assert run("1\nab\n") == "10"

# symmetric weights
assert run("2\naa\nbb\n") == "357"
