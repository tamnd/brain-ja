 ## 解決策
 ## 問題の理解

 1 から n までの位置の 1 次元の直線が与えられます。 一部の位置にはユリが含まれており、`1`、その他は空で、 で表されます。`0`。 カエルは位置 1 から開始し、位置 n に到達したいと考えています。 

ユリが存在する任意の位置 x から、カエルは 1 ≤ y − x ≤ d となる任意の位置 y に前方にジャンプできますが、これは位置 y にユリも含まれている場合に限ります。 各ジャンプには正確に 1 つの移動が必要であり、位置 n に到達するために必要なジャンプの最小数が必要です。 n に到達することが不可能な場合、答えは -1 です。 

この構造は本質的にグラフであり、ノードがユリの位置であり、j が距離 d 以内で i から到達可能であれば、i から j への有向エッジが存在します。 タスクは、この暗黙的なグラフ内でノード 1 からノード n までの最短パスを見つけることになります。 

n ≤ 100 という制約は、二次または三次解でも許容できることを直ちに示唆しています。 この範囲ではすべての遷移にわたる完全な BFS は簡単ですが、サイズが小さいため貪欲スキャンでも機能します。 

いくつかの特殊なケースは見落とされがちです。 たとえば、端点を除くすべての位置がゼロの場合、`10000001`、d が小さい場合、カエルは d より大きいギャップを飛び越えることになり、目的地に到達できなくなります。 もう 1 つの微妙なケースは、複数の短いホップが存在するが、最大長の貪欲なジャンプが到達可能なチェーンに到達できない場合です。次のような場合です。```
n = 7, d = 3
1000101
```遠くにジャンプするのは魅力的に見えるかもしれませんが、重要なのは中間のユリの位置だけであり、それらをスキップすると接続が切断されます。 

## アプローチ

 この強引なアイデアは、各ユリの位置をノードとして扱い、可能なすべてのジャンプ シーケンスを試すことです。 位置 i から、ユリを含む [i+1, i+d] 内の到達可能なすべての j を試し、n に到達するまですべてのパスを再帰的に探索できます。 これは有効なルートをすべて列挙するため正しいですが、本質的には指数関数的です。 すべての位置にユリがあり、d が大きい最悪のケースでは、パスの数は深さ n にわたって分岐係数 d のように増加し、n = 100 の場合でもすぐに実行不可能になります。 

重要な観察は、すべてのエッジが等しい重みを持ち、各ジャンプのコストがちょうど 1 であることです。これにより、問題は重み付けされていない最短経路問題に変換されます。 すべてのパスを探索するのではなく、到達可能な各位置に到達するために必要なステップ数は最小限だけです。 これは当然、動的プログラミングまたは BFS を示唆します。 

直接的な DP 解釈は次のとおりです。`dp[i]`位置 i に到達するために必要な最小限のジャンプとして。 dp[1] = 0 を初期化し、遷移を順方向に緩和します。i から、(i+1 から i+d) のすべての j を試します。 j にユリがある場合、dp[j] = min(dp[j], dp[i] + 1) を更新します。 n が小さいため、単純な O(n・d) 緩和で十分です。 

同等の BFS 定式化では、各位置を、ユリを含む次の d 位置へのエッジを持つグラフ内のノードとして表示します。 BFS は、重み付けされていないグラフ内の最短パスを保証します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのパス) | 指数 | O(n) 再帰スタック | 遅すぎる |
 | ポジション上の DP / BFS | O(n・d) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列をブール配列に変換します。これにより、位置にユリが含まれているかどうかをすぐに確認できます。 これにより、遷移中に一定時間の有効性チェックが可能になります。 
2. 距離配列を作成する`dist`サイズ n+1 で、すべての値を大きな数値に初期化します。`dist[1] = 0`、ジャンプゼロの位置 1 から開始するためです。 
3. 1 から n までの位置を繰り返します。 各位置 i について、到達可能な (意味`dist[i]`は無限大ではない）、前方にジャンプしようとします。 
4. 位置 i から、i+1 から min(n, i+d) までの次の位置 j をすべて試します。 位置 j にユリがある場合は、さらに 1 回のジャンプで到達できるため、更新します`dist[j] = min(dist[j], dist[i] + 1)`。 
5. すべての姿勢でこのリラックスプロセスを続けます。 常に既知の最短距離を前方に伝播するため、後の改善でも以前の近似値が改善されます。 
6. 処理後、チェックを行います`dist[n]`。 まだ無限大の場合は、-1 を出力します。 それ以外の場合は出力`dist[n]`。 

重要な考え方は、すべての位置が昇順に処理され、すべての遷移は前方にのみ進むため、i の処理が完了すると、後で i へのより良いパスを見つけることはできないということです。 

### なぜ効果があるのか

 アルゴリズムは次の不変条件を維持します。`dist[i]`有効なユリの位置のみを使用して、i に到達するために必要な最小限のジャンプ数を常に保存します。 i を処理するとき、i に到達するすべての最適な方法はすでに考慮されています。これは、厳密に前方に移動するため、i へのパスはより小さいインデックスから取得する必要があるためです。 到達可能な位置への最後のステップはすべて 1 回だけ検査され、より短いパスが見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())
    s = input().strip()
    
    INF = 10**9
    dist = [INF] * n
    dist[0] = 0  # position 1
    
    for i in range(n):
        if dist[i] == INF:
            continue
        if s[i] == '0':
            continue
        for j in range(i + 1, min(n, i + d + 1)):
            if s[j] == '1':
                if dist[j] > dist[i] + 1:
                    dist[j] = dist[i] + 1
    
    print(dist[n - 1] if dist[n - 1] != INF else -1)

if __name__ == "__main__":
    solve()
```この実装では、0 から始まるインデックスの配列を使用して位置 1 ～ n を表します。 の`dist`配列は、各インデックスに到達するために必要なジャンプの最小数を追跡します。 ネストされたループは、長さが最大 ​​d の可能なすべての前方ジャンプを列挙します。 

微妙なディテールがコンディションです`if s[i] == '0'`。 たとえ位置に計算された距離があったとしても、実際にユリが含まれていない限り、カエルはそこに立つことができないので、その距離は無関係です。 これにより、無効な状態からの遷移の伝播が防止されます。 

内側のループを丁寧に使用`min(n, i + d + 1)`すべての有効なジャンプ長を維持しながら、範囲外のアクセスを回避します。
