 ## 解決策
 ## 問題の理解

 それぞれが次のいずれかで色付けされたボールの列が与えられます。`k`色。 最初は色が 3 回連続で表示されません。 Iahub は指定された色の追加のボールを 1 つ保持しています`x`最初のボールの前や最後のボールの後など、行のどこにでも挿入できます。 同じ色のボールが3つ以上連続すると消えます。 この消滅はカスケードを引き起こす可能性があります。1 つのグループを削除すると、3 つ以上の新しい連続グループが作成され、それも消滅し、グループがなくなるまで繰り返します。 目標は、Iahub のボールを 1 回最適に挿入することで破壊できるボールの最大数を決定することです。 

制約は次のことを教えてくれます`n`最大でも 100 であるため、おおよその範囲で機能するソリューションを検討できます。`n^2`あるいは`n^3`制限時間に達することなくタイムアップ。 なぜなら`k`も小さいため、色の操作と比較は安価です。 小さいもの`n`これは、挿入の可能性をシミュレートすることは可能であることを示唆していますが、カスケード効果を効率的に考慮する必要があります。 

ボールを挿入すると複数の連鎖破壊が発生する可能性があるため、微妙なエッジケースが発生します。 例えばボールの場合`[1, 1, 2, 2, 1, 1]`そして追加の`2`を挿入して、`2`真ん中に`[1, 1, 2, 2, 2, 1, 1]`3人を破壊する`2`s、これにより 4 つの連続した`1`も破壊されました。 即時トリプルのみを考慮する素朴な解決策では、破壊されたボールは 3 つと数えられますが、正しい答えは 6 つです。 挿入されたボール自体がトリプルを形成できない場合、別の特殊なケースが発生します。 その場合、答えはゼロです。 長さ 1 または 2 の小さな配列は、1 回の挿入でボールが破壊される場合と破壊されない場合があるため、慎重に取り扱う必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 私たちはあらゆる可能な位置に Iahub のボールを挿入してみて、そのたびに破壊の連鎖をシミュレートします。 挿入ごとに、同じ色の 3 つ以上の連続したボールのシーケンスをチェックして削除し、シーケンスが存在しなくなるまで繰り返します。 これが機能するのは、すべてのボールがカスケードに参加する可能性があり、そのプロセスをシミュレートすることでゲームが正確に再現されるためです。 最悪の場合には、`n + 1`挿入位置と各シミュレーションはアレイを繰り返しスキャンする可能性があり、おおよその結果が得られます。`O(n^3)`操作。 と`n ≤ 100`、これは許容範囲内ですが、最適化することができます。 

重要な洞察は、同じ色の 3 つ以上が連続した場合にのみボールが消えることに気づくことから得られます。 これにより、行を連続した色のセグメントに圧縮し、色と数の両方を追跡することができます。 ボールを挿入した後は、挿入を含むセグメント (または挿入によって接続されている場合はすぐに隣接するセグメント) のみが、破壊を引き起こすのに十分な大きさに成長することができます。 行をカラーカウントの連続として表すことにより、挿入によって 2 つのセグメントがマージされて 3 つ以上の長さに達するかどうかを効率的に確認できます。 このマージを再帰的に適用すると、配列全体を繰り返しスキャンすることなくカスケード効果がキャプチャされます。 基本的に、この問題は、1 回の挿入によって引き起こされる連続する同じ色のボールの最長のチェーンを見つけることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n) | 機能するが非効率的 |
 | 最適 | O(n²) | O(n) | 効率的で受け入れられる |

 ## アルゴリズムのチュートリアル

 1. まず、元の行を連続した色のランに圧縮します。 例えば、`[1,1,2,2,1,1]`になる`[(1,2),(2,2),(1,2)]`。 各タプルは、色と、その色の連続するボールの数を表します。 
2. 考えられるそれぞれの挿入ポイントを検討します。 これらの点は、セグメントの境界またはセグメントの内部にあります。 各ポイントについて、ボールを挿入すると現在のセグメントにトリプルが作成されるか、挿入部分で同じ色の 2 つのセグメントがマージされるかを確認します。 
3. ボールを挿入した後、破壊を再帰的にシミュレートします。 挿入によってセグメントが 3 つ以上に達する場合は、そのセグメントを削除します。 次に、隣接するセグメントを確認します。 それらが同じ色の場合、それらのカウントは結合され、プロセスが繰り返される場合があります。 破壊されたボールの合計を追跡します。 
4. すべての挿入ポイントの結果を比較し、最大値を選択します。 

機能する理由: ランに圧縮することで、3 つ以上に成長する可能性のあるセグメントのみに焦点を当てることができ、不必要な計算が削減されます。 再帰的破壊はカスケードを正しくモデル化します。これは、各破壊後に行全体ではなく、隣接するセグメントのみをチェックする必要があるためです。 これにより、正確さと効率が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_destroyed(n, k, x, balls):
    # Compress the balls into runs
    runs = []
    for color in balls:
        if runs and runs[-1][0] == color:
            runs[-1][1] += 1
        else:
            runs.append([color, 1])
    
    def simulate(runs, insert_idx, color):
        # Make a deep copy to avoid mutating original runs
        temp = [r[:] for r in runs]
        
        # Determine where the ball goes in runs
        i = 0
        pos = 0
        while pos < insert_idx:
            pos += temp[i][1]
            i += 1
        
        # Insertion inside an existing segment
        if i > 0 and pos > insert_idx and temp[i-1][0] == color:
            temp[i-1][1] += 1
        else:
            temp.insert(i, [color, 1])
        
        # Recursive removal function
        def collapse(arr):
            changed = True
            total = 0
            while changed:
                changed = False
                i = 0
                while i < len(arr):
                    if arr[i][1] >= 3:
                        total += arr[i][1]
                        arr.pop(i)
                        changed = True
                        # Merge neighbors if same color
                        if 0 < i < len(arr) and arr[i-1][0] == arr[i][0]:
                            arr[i-1][1] += arr[i][1]
                            arr.pop(i)
                        break
                    else:
                        i += 1
            return total
        
        return collapse(temp)
    
    max_destroy = 0
    for pos in range(n+1):
        max_destroy = max(max_destroy, simulate(runs, pos, x))
    
    return max_destroy

if __name__ == "__main__":
    n, k, x = map(int, input().split())
    balls = list(map(int, input().split()))
    print(max_destroyed(n, k, x, balls))
```コードは最初に行をランに圧縮します。これにより、スキャンの繰り返しが削減されます。 各挿入ポイントは次のようにシミュレートされます。`simulate`。 内部`simulate`では、セグメント内とセグメント間の挿入の両方を処理します。`collapse`長さが 3 以上のセグメントを再帰的に削除し、必要に応じて隣接セグメントをマージします。 これにより、カスケードが自動的に処理されます。 

## 実用的な例

 サンプル 1:

 | ステップ | 走る | 挿入位置 | アクション | ボールが破壊されました |
 | --- | --- | --- | --- | --- |
 | イニシャル | [(1,2),(2,2),(1,2)] | - | - | 0 |
 | 位置 2 (最初の 1 と 2 の間) に挿入 | [(1,2),(2,3),(1,2)] | トリプルを作成する | 2 を削除し、1 を結合します | 2+4=6 |

 このトレースは、1 回の挿入でカスケードをトリガーできることを示しています。3 つの 2 が削除され、1 の 2 つのセグメントが 4 つにマージされ、それらも削除されます。 破壊された総数は6です。 

カスタム例:

 入力`[1,2,1,2,1]`、エクストラボール`2`。 挿入する`2`位置 3 で次の結果が得られます`[1,2,2,1,2,1]`。 トリプルフォームはありません。 出力 0。これは、トリプルを作成しない挿入をアルゴリズムが正しく無視するかをテストします。 

## 複雑さの分析
