 ## 解決策
 ## 問題の理解

 私たちには単一の番号が与えられています$n$、そして、からの整数の順列を出力する必要があります。$1$に$n$。 ポジションごとに$i$、インデックスとそこに配置された値を乗算して形成される値を計算します。$i \cdot p_i$。 目標は、これらの製品をできるだけ多く区別できるように順列を調整することです。 

あるので$n$これ以上のポジションを持つことはできません$n$独特の製品。 本当の問題は、常にこの上限に到達できるのか、それとも衝突は避けられないのかということです。 

失敗のケースを考えるのに役立つ方法は、2 つの立場が同じ製品を生産する場合です。 たとえば、次の場合$i \cdot p_i = j \cdot p_j$の場合、その構築は 1 つの可能な個別の値を「無駄」にします。 単純なアプローチでは、ランダムな順列や貪欲なスワップを試行する可能性がありますが、特にプロダクトがインデックスと値の両方に依存するため、明白なパターンのない反復プロダクトが誤って作成される可能性があります。 

制約$n \le 2 \cdot 10^5$順列をシミュレートしたり検索したりできないことを示唆しています。 多くの候補者をチェックしたり、割り当てを後戻りしたりするアプローチでは、時間がかかりすぎます。 線形時間内で最大数の異なる積を保証する直接構築が必要です。 

注目に値するエッジケースは、次の小さな値です。$n$、 特に$n = 1$、答えは簡単ですが、非常に大きくなります。$n$、ここではペアごとの衝突に関する二次推論は不可能です。 微妙な落とし穴は、ほとんどの順列が自然に異なる積を生成すると仮定していることですが、これは誤りです。$p_i = n+1-i$多くの場合、繰り返しの値が作成されます。 

## アプローチ

 強引なアイデアは、順列を生成し、配列内に出現する個別の値の数を数えるというものです。$i \cdot p_i$、衝突が見つかったときに要素を交換することで改善しようとしています。 これには、製品を繰り返し再計算し、多くの構成間で競合がないかチェックする必要があります。 最悪の場合、調整ごとにスキャンが必要になる場合があります。$O(n)$これを繰り返し行うことで、少なくとも$O(n^2)$が鈍くなるにもほどがあります。$n = 2 \cdot 10^5$。 

重要な観察は、実際にはポジション間の相互作用を通じて何かを最大化する必要はないということです。 すべてが確実に行われることだけが必要です$n$これは理論上の最大値です。 したがって、問題は、マッピングが次のような順列を構築することに帰着します。$i \mapsto i \cdot p_i$は単射です。 

注入性を保証する簡単な方法は、生成物シーケンス内のすべての構造的対称性を排除することです。 最も直接的な構築は、順列を変更せずに維持することです。$p_i = i$。 この場合、すべての製品は次のようになります。$i^2$、そして関数以来$i^2$正の整数を超えると厳密に増加するため、すべての値は自動的に区別されます。 

これにより、引数のペアリング、貪欲なマッチング、衝突処理の必要がなくなります。 ブルートフォース闘争は、異なるインデックス間の相互作用を管理しようとすることから発生しますが、恒等順列はこれらの相互作用を完全に切り離します。

 ## アルゴリズムのチュートリアル

 1. 長さの順列を構築する$n$ここで、位置の値は$i$は$i$。 これは、単純に数値を出力することを意味します。$1$に$n$順番に。 その動機は、各製品が相互作用するペアではなく単一の変数に依存するようにすることです。 
2. 概念的に積を計算します。$i \cdot p_i = i \cdot i$。 実際にそれらを保存する必要はありませんが、このステップにより、各位置が完全な正方形にマップされることが明確になります。 
3. 構築された順列を直接出力します。 

### なぜ効果があるのか

 構築されたシーケンスが生成物を生成します$1^2, 2^2, 3^2, \dots, n^2$。 機能以来$i^2$整数に対して厳密に増加しています$i \ge 1$、2 つのインデックスが同じ製品を生成することはできません。 これにより、すべてのことが保証されます。$n$製品は他と区別され、最大限の価値を実現します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    print(*range(1, n + 1))

if __name__ == "__main__":
    solve()
```この解決策は、恒等順列を出力することに依存しています。 重要な実装の詳細は、追加の配列や計算が必要ないことです。 出力形式は順列要件を直接満たします。 

Python ではオフバイワンの問題は発生しません。`range(1, n+1)`必要なインデックスを正確に自然に生成します。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    return " ".join(map(str, range(1, n + 1)))

# provided samples (identity is also valid output)

 ## 特殊なケース

 のために$n = 1$、この構造は単一要素の置換を出力します。$[1]$、製品セットに含まれるもののみ$1$、それは自明のことです。 

のために$n = 2$、出力$[1, 2]$製品を生産する$1$そして$4$、これらは異なり、最小ではない場合でも調整なしで機能することが確認されています。 

大型用$n$、各積はそのインデックスのみに依存するため、構造は安定したままであり、位置間の相互作用から隠れた衝突が現れる可能性はありません。
