 ## 解決策
 ## 問題の理解

 このツリーは、各ノードが 1 から N までの値を所有するノードの階層を示します。すべてのノードについて、そのサブツリー内のノードを調べ、そこに格納されている値に関する構造的な質問をします。つまり、それらの値が 1 から始まり、そのサブツリーのサイズまでの連続する整数の順列を正確に形成しているかどうかです。 

より具体的に言い換えると、サブツリーに k 個のノードが含まれる場合、それらのノードに格納されている k 個の値が抽出されます。 これらの k 個の数値が正確に {1, 2, 3, …, k} であり、繰り返しや要素の欠落がないかどうかを知りたいのです。 ツリー構造は、どのノードが一緒に属するかを決定するだけです。 実際の状態は、各サブツリー内の値の複数セットに純粋に依存します。 

制約は最大 200,000 ノードまであり、ノードごとにサブツリーの内容を個別に再計算するソリューションは直ちに除外されます。 サブツリーごとに値を収集して並べ替える単純な DFS は、ツリーが歪んでいると大きなプレフィックスに対して繰り返し作業が発生するため、最悪の場合は 2 次になります。 O(n²) の集約アプローチでも、最悪の場合のオーバーラップではすべてのサブツリーの合計サイズが Θ(n²) になるため、失敗します。 

よくある落とし穴は、「すべての値が異なる」ことをチェックするだけで十分だと思い込むことです。 たとえば、値 {1, 2, 4} を含むサイズ 3 のサブツリーはすべて個別の値を持ちますが、有効な順列ではありません。 もう 1 つの微妙なケースは、範囲条件が十分であると仮定する場合です。サイズ 3 のサブツリー内の {2, 3, 4} も正しい長さを持っていますが、1 から始まっていないため無効です。 

## アプローチ

 直接的なアプローチは、各サブツリーを個別に計算することです。 ノードの場合、そのサブツリーを走査し、すべての値を収集して並べ替え、並べ替えられたリストが 1 ～ k に一致するかどうかを確認します。 これは条件を明示的に検証するため正しいですが、コストが大きすぎます。 星型またはチェーン状のツリーでは、ほぼ同じノードを何度も繰り返し処理し、ソートによっては O(n² log n) またはそれ以上の結果が得られます。 

重要な構造上の観察は、各サブツリーには 3 つの情報のみが必要であるということです。それは、サブツリーのサイズ、サブツリーに含まれる値のセット、およびそれらの値が完全なプレフィックス順列に一致するかどうかです。 セットを最初から再計算する代わりに、ボトムアップでセットを構築し、子を親にマージできます。 

これは必然的にツリー結合手法につながります。 すべてのサブツリーについて、その値を表す動的構造を維持すると、子サブツリーをその親にマージできます。 これを効率的に行う古典的な方法は、ツリー上の DSU またはマルチセットの大規模なマージです。 セットとともに、値の合計、最小値、最大値、サブツリーのサイズなどの集計統計も維持します。 

これらを取得すると、「値が長さ k の順列を形成する」という条件は、各ノードでの 3 つのチェックと同等になります。つまり、サブツリーのサイズは k、最小値は 1、最大値は k、値の合計は k(k+1)/2 に等しくなります。 合計条件は、範囲が正しい場合は、ギャップや重複がないことを保証します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ノードごとのブルート フォース DFS | O(n² log n) | O(n) | 遅すぎる |
 | マルチセット + アグリゲートを備えたツリー上の DSU | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ノード 1 でツリーをルート化し、サブツリーのサイズと隣接構造を計算します。 次に、葉から上に向かって情報を構築する深さ優先検索を実行します。

1. 標準の DFS を使用して各サブツリーのサイズを計算します。 これが必要なのは、最終条件が値とサブツリー サイズの比較に依存するためです。 
2. 各ノードに対して、独自の値のみを含むマルチセットを初期化します。 同時に、現在の合計、現在の最小値、および現在の最大値の 3 つの集計も維持します。 
3. ノードの子を再帰的に処理して、各子がそのサブツリーを表す完全に構築された構造をすでに持っているようにします。 
4. 子から戻るとき、子のマルチセットを現在のノードのマルチセットにマージします。 全体の複雑さを効率的に保つために、常に小さいマルチセットを大きいマルチセットにマージします。 これにより、多くのマージにわたって同じ要素を繰り返し挿入するというコストのかかる作業が防止されます。 
5. マージ中に、積算合計を更新し、マージされた構造の境界値を使用して最小値と最大値を更新します。 マルチセットを使用すると、反復子を介して最小値と最大値に定数時間でアクセスできます。 
6. すべての子がノードにマージされると、構造はそのサブツリーを正確に表すようになります。 この時点で、マルチセットのサイズがサブツリーのサイズに等しい、最小値が 1、最大値がサブツリーのサイズ、合計がサイズ・(サイズ+1)/2 に等しいという条件を比較します。 すべてが当てはまる場合、サブツリーは有効な置換です。 

### なぜ効果があるのか

 各サブツリーは、そのノードからのすべての値を含み、他には何も含まれないマージされた構造として 1 回だけ表されます。 小から大へのマージでは、各値が構造間を O(log n) 回だけ移動することが保証されるため、効率を維持しながら正確性を失うことはありません。 集約条件により、整数のすべての k 要素サブセットの中で集合 {1..k} を一意に特徴付ける代数的制約への置換要件が軽減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class MultisetNode:
    __slots__ = ("s", "mn", "mx", "cnt")
    def __init__(self, val):
        self.s = [val]
        self.mn = val
        self.mx = val
        self.cnt = 1

def merge(a, b):
    if len(a.s) < len(b.s):
        a, b = b, a
    a.s.extend(b.s)
    a.cnt += b.cnt
    a.mn = min(a.mn, b.mn)
    a.mx = max(a.mx, b.mx)
    return a

def solve():
    n = int(input())
    p = [0] + list(map(int, input().split()))
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    sz = [0] * (n + 1)
    ans = [False] * (n + 1)

    def dfs(u, parent):
        sz[u] = 1
        cur = MultisetNode(p[u])
        for v in g[u]:
            if v == parent:
                continue
            child = dfs(v, u)
            cur = merge(cur, child)
            sz[u] += sz[v]
        total = cur.cnt
        if total == sz[u]:
            if cur.mn == 1 and cur.mx == sz[u]:
                expected = sz[u] * (sz[u] + 1) // 2
                if sum(cur.s) == expected:
                    ans[u] = True
        return cur

    dfs(1, -1)

    for i in range(1, n + 1):
        print("YES" if ans[i] else "NO")

if __name__ == "__main__":
    solve()
```DFS は各サブツリーをボトムアップで構築します。 各ノードはシングルトン構造として開始されます。 再帰が戻ると、子が親にマージされ、生の値と要約統計の両方が蓄積されます。 正確性チェックはすべての子が処理された後にのみ実行され、構造がサブツリーを正確に表現していることが保証されます。 

マージ関数は、値のリストと集約メタデータの間の一貫性を維持する役割を果たします。 サムチェックでは、保存されたリストに対して Python の組み込み合計を使用します。 メモリを最も必要とするアプローチではありませんが、境界だけでなく正確なメンバーシップを検証しているという考えが明確に保たれます。 

サブツリー サイズ配列は DFS と並行して計算され、最小、最大、合計を検証するための基準となります。

 ## 特殊なケース

 単一ノード ツリーは、サブツリー条件が単一の値が 1 であるかどうかのチェックに帰着する最も単純なケースです。アルゴリズムは 1 要素の構造を初期化し、最小、最大、合計はすべて自明に整列するため、ノードは値が 1 の場合にのみ正しく YES とマークされます。 

すべてのノードがチェーンを形成する歪んだツリーは、マージ順序が正確さを保っているかどうかをテストします。 各ステップでは、サイズ 1 の構造が成長する構造にマージされ、小から大へのルールは無関係ですが、それでも安全です。 集約は引き続きパス サブツリーを正確に表し、最小条件または合計条件が失敗した場合、無効な置換は拒否されます。 

重複を含むサブツリーは、合計制約の重要性を示しています。 最小値と最大値が妥当であるように見えても、値が繰り返されると合計が必要な三角数を下回り、明示的な周波数追跡を必要とせずにサブツリーが即座に無効になります。
