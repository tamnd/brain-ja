 ## 解決策
 ## 問題の理解

 ツリーには、ノード 1 をルートとする 1 から N までの番号が付けられたノードが含まれます。各ノードには個別のラベルが付けられ、これらのラベルは 1 から N までの番号の順列を形成します。 

すべてのノードについて、ルート化されたサブツリー内のノードを調べ、そのラベルを収集します。 タスクは、この収集されたラベルのセットがサブツリーのサイズに等しい長さの完全な順列を形成しているかどうかを判断することです。 言い換えれば、サブツリーに k 個のノードがある場合、そのラベルが何らかの順序で 1 から k までの数字と正確に一致するかどうかを確認します。 

出力は、ノードごとに 1 つの一連の回答であり、そのノードのサブツリーがこのプロパティを満たすかどうかを示します。 

最大 200,000 の制約 N により、線形または線形に近い解が強制されます。 サブツリー全体を独立して繰り返し検査するアプローチでは、同じ構造が何度も再計算され、許容限界をはるかに超える二次的な動作に向かってドリフトすることになります。 各サブツリーをソートするような操作でも、最悪の場合、ノードごとに総コストがおよそ O(N log N) になることを意味し、チェーン形状のツリーでは O(N^2 log N) にまで縮退します。 

ラベルが世界的に一意であるという事実から、微妙な特殊なケースが生じます。 これにより、サブツリー内の重複に関するあいまいさが解消されますが、重要な問題も隠蔽されます。つまり、繰り返しがなくても、サブツリーの値が 1 から k の範囲に正確に一致しない場合、サブツリーは条件を満たさない可能性があります。 

たとえば、値 {2, 3, 4} を含むサイズ 3 のサブツリーについて考えてみましょう。 サイズが完璧で重複がない場合でも、必要な正規の番号付けと一致しないため、無効になります。 

別のケースは、{1, 2, 4} を含むサイズ 3 のサブツリーです。 これも失敗し、単純な「最小値と最大値のみをチェックする」アプローチは、慎重に検討しなければ誤って合格する可能性があります。 

## アプローチ

 直接的なアプローチは、ノードごとにサブツリー内の値の完全なリストを計算し、それを並べ替えて、それがシーケンス 1 から k に一致するかどうかを検証することです。 これは、テスト対象の条件を明示的に再構築するため、正しいです。 問題はコストです。 各サブツリー抽出のサイズは線形であり、ソートには対数係数が追加されるため、すべてのノードにわたって、多くのサブツリーが重複する大きなツリーでは法外なコストがかかります。 

重要な観察は、実際には値を完全に順序付ける必要はないということです。 すべてのラベルはグローバルに一意であるため、各サブツリーにはすでに k 個の異なる整数が含まれています。 重要なのは、それらの k 個の整数が 1 から k までの間隔を隙間なく正確に満たしているかどうかだけです。 この条件は、サブツリー内の最小値と最大値という 2 つの集約のみを使用して検証できます。 

サイズ k のサブツリーに最小値 1 と最大値 k がある場合、すべての値は [1, k] 内にある必要があり、正確に k 個の個別の値があるため、それらはその範囲内のすべての整数を占める必要があります。 これにより、問題はセットの維持から単純なサブツリー統計の維持に軽減されます。 

したがって、明示的なセットの再計算から、すべてのノードのサブツリー サイズ、最小値、最大値を計算する単一の DFS に切り替えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース（サブツリー抽出＋ソート） | O(N² log N) | O(N) | 遅すぎる |
 | サブツリーの最小、最大、サイズを含む DFS | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーをノード 1 にルートし、後続トラバーサルを実行して、子が親の前に処理されるようにします。

1. ノード 1 から DFS を開始し、ツリーをルートから離れるように扱います。 これにより、各サブツリーがボトムアップ方式で 1 ​​回だけ処理されることが保証されます。 
2. 各ノード u について、そのサブツリー サイズを 1 として初期化し、その最小値と最大値の両方を P[u] に設定します。 これは、u のみを含む自明な部分木を表します。 
3. 無向ツリーへの循環戻りを避けるために、親をスキップして、u の各子 v をトラバースします。 
4. DFS(v) から戻った後、サブツリーの最小値の最小値とサブツリーの最大値の最大値を取得してサイズを追加することにより、v からの情報を u にマージします。 このステップでは、互いに素な子サブツリーを結合して u の完全なサブツリーを作成します。 
5. すべての子が処理されると、u のサブツリーは 3 つの値、sz[u]、mn[u]、mx[u] で完全に表現されます。 
6. mn[u] が 1 に等しいか、mx[u] が sz[u] に等しいかどうかを確認します。 両方が当てはまる場合は、u を有効としてマークし、そうでない場合は無効としてマークします。 

マージ ステップの正確さは、ツリー内のサブツリー分解が互いに素であるという事実に依存します。つまり、各ノードは 1 つの子サブツリーにのみ属するため、子に対する集計では、重複することなく正確な数と値の範囲が保持されます。 

### なぜ効果があるのか

 各サブツリーは、サイズ、最小ラベル、最大ラベルという 3 つの不変条件を通じて、その値の完全な要約を保持します。 すべてのラベルはグローバルに異なるため、これらの要約はチェックされる特定の条件に対して損失がありません。 値が完全に [1, k] 内にあるサイズ k のサブツリーには、その区間内のすべての整数が含まれている必要があります。これは、数値を 1 つでもスキップすると、サイズが小さくなるか、最大境界と矛盾するギャップが生じるためです。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    n = int(input())
    p = [0] + list(map(int, input().split()))
    
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)
    
    sz = [0] * (n + 1)
    mn = [10**18] * (n + 1)
    mx = [0] * (n + 1)
    ans = [False] * (n + 1)
    
    def dfs(u, parent):
        sz[u] = 1
        mn[u] = p[u]
        mx[u] = p[u]
        
        for v in g[u]:
            if v == parent:
                continue
            dfs(v, u)
            sz[u] += sz[v]
            mn[u] = min(mn[u], mn[v])
            mx[u] = max(mx[u], mx[v])
        
        if mn[u] == 1 and mx[u] == sz[u]:
            ans[u] = True
    
    dfs(1, -1)
    
    out = []
    for i in range(1, n + 1):
        out.append("YES" if ans[i] else "NO")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```DFS は、1 回の走査でサブツリー統計を計算します。 各ノードは自身のコントリビューションを初期化し、その子から結果を吸収します。 親パラメータにより、無向隣接リスト内の前のノードに再度アクセスすることができなくなります。 

よくある実装の落とし穴は、子をマージする前にすべてのノードの mn[u] と mx[u] を初期化するのを忘れることです。これにより、以前のテスト ケースまたは再帰呼び出しの値が無関係な計算に漏れてしまいます。 もう 1 つの微妙な点は、再帰の深さです。これは、N = 200,000 のチェーン形状のツリーは、明示的に増加しない限り、Python のデフォルトの制限をオーバーフローしてしまうためです。

 ## 特殊なケース

 単一ノード ツリーが最も単純なシナリオです。 DFS は、sz を 1 に初期化し、mn と mx をノード値に初期化します。 この条件では、mn が 1 に等しいこと、および mx が sz に等しいことがチェックされるため、1 というラベルの付いたノードのみが合格します。 初期化とチェックの両方が同じ再帰フレーム内で発生するため、提供された実装はこれを正しく処理します。 

チェーン状のツリーは再帰の深さを強調します。 各ノードは深い再帰呼び出しになりますが、親ポインターにより再訪が妨げられるため、各ノードは依然として 1 回だけ処理されます。 サブツリー集約はポストオーダー構造を超えた走査順序に依存しないため、アルゴリズムは線形のままであり、正確性が保たれます。 

値がサブツリーのサイズと一致していないケースは、コア ロジックを示しています。 たとえば、値 {2, 3, 4} を含むサイズ 3 のサブツリーは、mn = 2 および mx = 4 を生成します。mx - mn + 1 が 3 に等しい場合でも、mn は 1 ではないため、条件は正しく拒否し、区間ベースの推論だけによる誤検知を防ぎます。
