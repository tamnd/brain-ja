 ## 解決策
 ## 問題の理解

 Unix スタイルの絶対パスが与えられます。 パスは次のようにコンポーネントに分割されます。`/`、すべてのコンポーネントは通常のディレクトリ名またはファイル名を表します。`"."`、 または`".."`。 

通常の名前は、「このディレクトリまたはファイルに移動する」ことを意味します。 

コンポーネント`"."`は「現在のディレクトリに留まる」ことを意味するため、何も変わりません。 

コンポーネント`".."`「親ディレクトリに移動する」という意味です。 

タスクは、最終結果に何も含まれないようにパスを単純化することです。`"."`または`".."`コンポーネント。 ある時点でパスがルート ディレクトリより上に移動しようとすると、パスは無効になるため、出力する必要があります。`-1`。 

パスの長さは最大 1000 文字と非常に小さいです。 おそらく二次方程式の解法でも問題なく通過できるでしょうが、問題の構造は自然に線形時間解法に導きます。 すべてのパス コンポーネントは独立して処理され、現在のディレクトリ スタックにのみ影響するため、左から右への 1 回のパスで問題を解決できます。 

危険なケースはパフォーマンスに関するものではなく、特殊なコンポーネントを正しく解釈するものです。 

次の入力を考えてみましょう。```
/../../a
```最初`".."`すでにルートディレクトリから離れようとしています。 正しい出力は次のとおりです。```
-1
```不注意な実装では、余分な要素が黙って無視される可能性があります。`".."`操作と誤った戻り`/a`。 

もう一つの微妙なケースが区別されます`"."`そして`".."`ドットを含む通常の名前から。 

例えば：```
/.../..hidden/./x
```コンポーネント`"..."`そして`"..hidden"`は通常の名前であり、特別なコマンドではありません。 正しい簡略化されたパスは次のとおりです。```
/.../..hidden/x
```コンポーネントにドットが含まれているかどうかだけをチェックするバグのある実装では、コンポーネントが親ディレクトリの操作として誤って処理されてしまいます。 

ルート ディレクトリ自体も慎重に扱う必要があります。```
/
```結果は正確に残らなければなりません`/`。 コンポーネントを盲目的に結合して答えを再構築すると、代わりに誤って空の文字列が生成される可能性があります。 

## アプローチ

 ブルートフォース手法では、パス内で次のような問題が発生するかどうかを繰り返し検索します。`"."`そして`".."`、文字列を書き換えて、特別なコンポーネントがなくなるまで続けます。 

たとえば、次のような場合`/a/b/../c`に書き換えることができます。`/a/c`。 見たら`/./`、それを削除します。 この方法は、文字列自体のパスの単純化を直接シミュレートするため、概念的に単純です。 

問題は、書き換えのたびに文字列内の文字が移動することです。 パスに多くのネストされたディレクトリが含まれている場合、`".."`操作では、各書き換えに線形的な時間がかかる可能性があり、線形的に多くの書き換えを実行する可能性があります。 パス長が`n`、これは次のように悪化する可能性があります`O(n²)`操作。 

重要な点は、パスの正規化は現在アクティブなディレクトリ コンポーネントの順序のみに依存するということです。 ディレクトリを入力すると、それが現在のパスに追加されます。 出会ったとき`".."`、最新のディレクトリを削除します。 この動作はまさにスタックです。 

これにより、問題は「文字列を繰り返し書き換える」から「コンポーネントを左から右に一度処理する」に変わります。 

各コンポーネントについて:

 そうであれば`"."`、無視します。 

そうであれば`".."`では、スタックから 1 つのディレクトリをポップします。 スタックがすでに空の場合、パスは無効です。 

それ以外の場合、コンポーネントは通常の名前であるため、スタックにプッシュします。 

最終的に、スタックにはすでに正規パス コンポーネントが順番に含まれています。 We simply join them with`/`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 受け入れられるが非効率的 |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力パスを文字列として読み取ります。 
2. パスを分割します`/`。 

パスは常に次から始まるため、`/`の場合、最初の分割コンポーネントは空の文字列になります。 処理中に空のコンポーネントを単に無視します。 
3. 空のスタックを作成します。 

スタックは、ルートから現在のディレクトリまでの現在の正規パスを表します。 
4. 各コンポーネントを左から右に処理します。 

これは、ファイルシステム内をナビゲートする実際の動作と一致します。 
5. コンポーネントが空である場合、または`"."`、スキップしてください。 

パスが次で始まるため、空のコンポーネントが表示されます。`/`。 コンポーネント`"."`「ここにいてください」という意味なので、何も変わりません。 
6. コンポーネントが`".."`、スタックから最後のディレクトリを削除してみます。 

スタックが空の場合は、すでにルート ディレクトリに到達しているため、上に移動することはできません。 印刷する`-1`そしてやめてください。 
7. それ以外の場合、コンポーネントは通常のディレクトリまたはファイル名です。 

それをスタックにプッシュします。 
8. すべてのコンポーネントを処理した後、正規パスを再構築します。 

スタックが空の場合、正規パスは次のようになります。`/`。 

それ以外の場合は、すべてのスタック要素を次のように結合します。`/`先頭にスラッシュを 1 つ追加します。 

### なぜ効果があるのか

 最初の処理後`k`コンポーネントの場合、スタックは常にそれらのコンポーネントに対応する正確な正規パスを表します。`k`コンポーネント。 

通常の名前をプッシュすることは、ディレクトリを入力することと同じです。 ポッピングオン`".."`親ディレクトリに戻ると一致します。 無視する`"."`同じディレクトリ内にあるものと一致します。 

すべての操作でファイル システム セマンティクスの要求どおりにスタックが更新されるため、最終的なスタック状態はパスの一意の正規バージョンになります。 唯一の無効な状況は、空のスタックからポップしようとすることです。これは、まさにルート ディレクトリの上に移動することに相当します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    path = input().strip()

    stack = []

    for part in path.split('/'):
        if part == '' or part == '.':
            continue

        if part == '..':
            if not stack:
                print(-1)
                return
            stack.pop()
        else:
            stack.append(part)

    if not stack:
        print('/')
    else:
        print('/' + '/'.join(stack))

solve()
```このソリューションは、スタックベースのシミュレーションに直接従います。 

への呼び出し`split('/')`パスを個々のコンポーネントに変換します。 入力パスは常に次で始まるため、`/`の場合、最初のコンポーネントは空の文字列になります。 このようなコンポーネントは無視します。 

スタックには、現在アクティブなディレクトリが保存されます。 すべての一般的な名前が追加されます。 毎`".."`最新のディレクトリを削除します。 

最も重要な実装の詳細は、呼び出す前にスタックが空かどうかを確認することです。`pop()`。 このチェックを忘れると、クラッシュするか、誤ってルート ディレクトリより上の移動が許可されてしまいます。 

もう 1 つの微妙な点は、最終的な答えを再構築することです。 スタックが空になった場合、正しい正規パスは次のとおりです。`/`、空の文字列ではありません。 その特殊なケースは個別に処理する必要があります。 

条件:```
if part == '' or part == '.':
```も重要です。 完全一致のみ`"."`そして`".."`特別です。 ような文字列`"..."`または`"..a"`通常のパス名のままにする必要があります。

# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    path = input().strip()

    stack = []

    for part in path.split('/'):
        if part == '' or part == '.':
            continue

        if part == '..':
            if not stack:
                print(-1)
                return
            stack.pop()
        else:
            stack.append(part)

    if not stack:
        print('/')
    else:
        print('/' + '/'.join(stack))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

       "/usr/share/tomcat6/conf/server.xml", "sample 1"

# minimum-size input

# names containing dots are ordinary names

 ## 特殊なケース

 無効な上向きトラバーサルの場合を考えてみましょう。```
/../../a
```アルゴリズムは空のスタックから始まります。 最初のコンポーネントは`".."`。 スタックは空であるため、戻る親ディレクトリはありません。 アルゴリズムはすぐに出力します`-1`。 

これはファイルシステムのセマンティクスと正確に一致します。 この操作を無視すると、ルート外のパスが誤って許可されてしまいます。 

ここで、ドットを含む名前を考えてみましょう。```
/.../..hidden/./x
```コンポーネントは次のとおりです。```

```アルゴリズムは完全一致のみを扱います。`"."`そして`".."`特別として。 それで`"..."`そして`"..hidden"`are pushed normally onto the stack. の`"."`コンポーネントは無視され、`"x"`が追加されます。 

最終的なスタックは次のようになります。```

```これは次のように再構築されます。```
/../..hidden/x
```最後に、ルートに完全に戻るパスを考えてみましょう。```
/a/b/../..
```スタックは次のように進化します。```
["a"]
["a", "b"]
["a"]
[]
```最後にはスタックは空になります。 アルゴリズムは出力します`/`空の文字列の代わりに、これがルート ディレクトリの正しい正規表現です。
