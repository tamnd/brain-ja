 ## 解決策
 ## 問題の理解

 すべての行に複数の文字列フィールドが含まれるテーブルがあり、最初の入力行で各列の名前が示されます。 別の行では、行をどのように並べるかを説明します。 各ルールの形式は次のとおりです。`COLUMN_NAME ASC`または`COLUMN_NAME DESC`。 

並べ替えはデータベースとまったく同じように動作します`ORDER BY`句。 最初のルールが最も優先されます。 そのルールに従って 2 つの行が等しい場合は、2 番目のルールを使用してそれらを比較し、以下同様に続きます。 すべてのルールが 2 つの行を等しいとみなす場合、元の順序は変更されない必要があります。 最後の要件は、ソートが安定している必要があることを意味します。 

テーブルのサイズは、競技プログラミングの標準からすると小さいです。 行数と列数はどちらも最大 100 です。`O(n^2)`または`O(n^2 log n)`ここでのソリューションは完全に安全です。 コストがかかる部分は行数ではなく、安定性を維持しながら方向の異なる複数のソートキーを処理することです。 

難しいのはパフォーマンスではなく、正確さです。 不注意に実装すると、順序付けルールを簡単に破ってしまう可能性があります。 

次の例を考えてみましょう。```
A B
A ASC, B DESC
x 1
x 3
x 2
```正しい出力:```
x 3
x 2
x 1
```最初のキーだけでソートすると`A`の場合、すべての値が等しいため、行は変更されません。 2 番目のキーは依然として重要です。 

もう 1 つの微妙なケースは安定性です。```
A
A ASC
x
x
x
```正しい出力:```
x
x
x
```安定した並べ替えでは、等しい要素の元の順序が保持されます。 一部のカスタム コンパレータ実装では、一貫性のない結果が返されるため、誤って等しい行の順序が変更されます。 

方向が混在していることもバグの一般的な原因です。```
A B
A DESC, B ASC
1 z
2 y
2 x
```正しい出力:```
2 x
2 y
1 z
```最初のキーは降順ですが、2 番目のキーは昇順です。 各キーを個別に処理するのではなく、比較結果全体を逆にすると、順序が間違ってしまいます。 

最後に、ルール行の解析には注意が必要です。 ルールは次のように区切られています。`", "`、カンマだけではありません。 分割を誤ると、フィールド名または方向に余分なスペースが付加される可能性があります。 

## アプローチ

 最も直接的な解決策は、行を手動で比較することです。 行のペアごとに、行が異なるフィールドが見つかるまでルールを 1 つずつ検査します。 現在のルールが昇順の場合は、通常の辞書編集順が使用されます。 降順の場合は、比較を逆にします。 すべてのルールが一致する場合、行は等しいとみなされ、元の順序は変更されません。 

このアプローチはステートメントを正確に反映しているため、概念的に単純です。 このようなコンパレータを並べ替えアルゴリズムに組み込むことができます。 最大 100 行であれば、バブル ソートのような二次安定ソートでも快適に通過します。 最悪のケースが近づいている`100^2 * 100`、これはわずか 100 万件のフィールド比較です。 

それでも、Python はすでに安定した並べ替えアルゴリズムである TimSort を提供しています。 これを適切に使用すると、実装がよりクリーンになり、エラーが発生しにくくなります。 

重要な観察は、安定した並べ替えにより、ルールを最低優先度から最高優先度まで処理できるということです。 ルールが次のとおりであるとします。```
A ASC, B DESC, C ASC
```まず次の基準で並べ替えます`C`、その後、`B`、その後、`A`。 

なぜこれが機能するのでしょうか? で並べ替えた後、`C`、行は優先度の最も低いキーによって正しく順序付けされます。 後で並べ替えると、`B`、異なる行`B`値は正しく並べ替えられますが、値が等しい行は`B`以前のものを保持する`C`Python のソートは安定しているため、順序付けが行われます。 このプロセスを繰り返すと、最終的には、必要な正確な辞書編集上の複数キーの順序が生成されます。 

これにより、カスタム コンパレータが完全に不要になります。 各並べ替えパスでは単一のフィールドと単純なフィールドが使用されます。`reverse=True/False`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース コンパレータ ソート | O(r² × k) | お(1) | 承認済み |
 | 安定したマルチパスソート | O(k × r log r) | O(r) | 承認済み |

 ここ、`r`は行数であり、`k`並べ替えルールの数です。 

## アルゴリズムのチュートリアル

 1. 列名を読み取り、各列の位置を辞書に保存します。 

これにより、フィールド名を次のように変換できます`"AGE"`一定時間内にその列インデックスに格納されます。 
2. ルール行を読み、次のように分割します。`", "`。 

それぞれの作品はこんな感じ`"FIELD ASC"`または`"FIELD DESC"`。 
3. すべてのルールを 2 つの値 (列インデックスと順序が降順かどうか) に解析します。 

例えば、`"AGE DESC"`になる`(2, True)`もし`AGE`3列目です。 
4. 残りの行をすべてテーブル行として読み取ります。 

各行は文字列のリストとして保存されます。 
5. 逆の順序でルールを処理します。 

後の安定した並べ替えでは以前の同点決定が保持されるため、最も重要度の低いルールを最初に適用する必要があります。 
6. ルールごとに、対応する列をキーとして使用して行を並べ替えます。 

使用`reverse=True`降順の場合と`reverse=False`昇順の場合。 
7. 最終的な順序で行を印刷します。 

### なぜ効果があるのか

 最後のルールを処理した後、行は最も優先度の低い条件に従って正しく順序付けされます。 

位置からルールを処理した後、`i + 1`それ以降、行は優先度の低いすべてのルールに従ってすでに正しく順序付けされています。 安定してルールでソートすると`i`、ルールの値が異なる行`i`正しい相対順序に移動します。 ルールの値が等しい行`i`ソートは安定しているため、以前の順序を維持します。 この保存された順序は、優先度の低いすべてのルールをすでに満たしています。 

帰納法により、すべてのルールを処理した後、行は問題で必要とされる完全な辞書編集順序を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    columns = input().split()

    pos = {}
    for i, name in enumerate(columns):
        pos[name] = i

    rules_line = input().strip()
    rules_raw = rules_line.split(", ")

    rules = []

    for rule in rules_raw:
        field, order = rule.split()
        rules.append((pos[field], order == "DESC"))

    rows = []

    for line in sys.stdin:
        line = line.strip()

        if not line:
            continue

        rows.append(line.split())

    for col, rev in reversed(rules):
        rows.sort(key=lambda row: row[col], reverse=rev)

    for row in rows:
        print(*row)

solve()
```最初の部分では、列名からインデックスへのマッピングを構築します。 これにより、ルールがフィールドを参照するたびに線形検索が繰り返されることが回避されます。 

ルールはペアとして保存されます`(column_index, is_descending)`。 すべてを早期にインデックスに変換すると、並べ替えループが単純になります。 

行数が明示的に指定されていないため、EOF が入力形式と自然に一致するまで行を読み取ります。 

最も重要な実装の詳細は反復処理です。`reversed(rules)`。 それらを元の順序で処理すると、以前に確立された優先順位の高い順序が破壊されます。 

電話の内容:```
rows.sort(key=lambda row: row[col], reverse=rev)
```Python のソートは安定しているため、機能します。 等しい要素は、以前の順序を自動的に保持します。 

すべての比較は、ステートメントで要求されているとおりに、辞書編集上の文字列比較です。 値を整数に変換することはありません。

 ## 特殊なケース

 すべてのルールの下で行が等しいとみなします。```
A B
A ASC, B DESC
x 1
x 1
x 1
```アルゴリズムはまず次の基準で並べ替えます。`B DESC`すべての値が等しいため、何も変わりません。 次に、次の基準で並べ替えます`A ASC`、これも何も変わりません。 Python のソートは安定しているため、元の順序が正確に保持されます。 

次に、相反する方向について考えてみましょう。```
A B
A DESC, B ASC
2 z
2 x
1 y
```アルゴリズムはまず次の基準で並べ替えます。`B ASC`:```
2 x
1 y
2 z
```次に、次のように並べ替えます`A DESC`:```
2 x
2 z
1 y
```行の間で、`A = 2`、前の`B ASC`2 番目のソートは安定しているため、順序付けは存続します。 

最後に、辞書編集上の動作を考慮します。```
A
A ASC
2
10
9
```文字列の比較は次のようになります。```
10
2
9
```なぜなら`"10"`前に来る`"2"`辞書順に。 アルゴリズムは文字列を数値に変換しないため、これを自動的に処理します。
