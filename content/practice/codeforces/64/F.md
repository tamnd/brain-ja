 ## 解決策
 ## 問題の理解

 指定された文字列が、単純化された一連のルールの下で有効なドメイン名として解釈できるかどうかを判断する必要があります。 

文字列には、英小文字、数字、ドットのみを含めることができます。 ドットは文字列をセグメントに分割します。 文字列をドットで開始したり、ドットで終了したりすることはできません。また、2 つのドットを連続して使用することもできません。 ドットで分割した後の最終セグメントの長さは正確に 2 または 3 でなければなりません。 

入力の長さは最大 100 であり、非常に小さいです。 非効率なソリューションであっても、制限時間内であれば快適に実行できます。 本当の課題は最適化ではなく、コーナーケースを見逃さずにすべてのルールを注意深く実装することです。 

よくある間違いは、ドットを含む構造上の制約を忘れて、許可された文字だけをチェックすることです。 たとえば:

 入力:```
abc..com
```正しい出力:```
NO
```文字列には有効な文字のみが使用されますが、連続したドットは空のセグメントを作成するため、これは禁止されています。 

もう 1 つの簡単なバグは、ドメインをドットで開始または終了できないことを忘れていることです。 

入力：```
.google
```正しい出力:```
NO
```分割ベースのソリューションを不用意に行うと、次のような問題が発生する可能性があります。`["", "google"]`そして思わず受け入れてしまいます。 

最後のセグメントの長さの制限も、微妙な障害の原因となります。 

入力：```
abc.c
```正しい出力:```
NO
```最後のセグメントの長さは 1 ですが、長さ 2 と 3 のみが許可されます。 

同様に:

 入力:```
abc.comm
```正しい出力:```
NO
```最後のセグメントの長さは 4 です。 

もう 1 つの罠は大文字です。 このステートメントでは小文字のみを使用できます。 

入力：```
Codeforces.com
```正しい出力:```
NO
```を使用した解決策`isalnum()`直接的に大文字を誤って受け入れてしまう可能性があります。 

## アプローチ

 最も直接的な強引なアイデアは、定義を正確にシミュレートすることです。 文字列を 1 文字ずつスキャンし、すべてのルールを個別に検証します。 

まず、すべての文字が許可されたセットに属していることを確認できます。 次に、文字列がドットで始まり、ドットで終わっていないことを確認します。 次に、隣接する文字のペアに 2 つのドットが含まれていないことを確認します。 最後に、文字列をドットで分割し、最後のセグメントの長さを調べます。 

各パスが文字列に 1 回接触するため、これはすでに線形時間で実行されます。 長さが最大 ​​100 であれば、文字列を繰り返しスキャンしても無視できるほどです。 

別の可能な総当たり解釈は、文字列をドメイン セグメントに分割する可能なすべての方法を生成し、手動で妥当性をチェックすることです。 このアプローチは不必要に複雑になり、ポジションの数が増えるにつれて指数関数的に増加します。 制約が十分小さいので通過できるとしても、問題の構造により、より明確なルートが得られます。 

重要な観察は、すべてのルールがローカルであるということです。 許可される文字は個々の位置に依存し、連続ドットの有効性は隣接する文字にのみ依存し、接尾辞の条件は最後のセグメントにのみ依存します。 グローバル検索や解析は必要ありません。 1 回の左から右へのスキャンと 1 回の最終サフィックス チェックを組み合わせることで、有効性が完全に判断されます。 

そのため、最適なソリューションは単純に直接バリデーターとなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 徹底分割・検索 | O(2^n) | O(n) | 不必要に遅い |
 | 直接検証スキャン | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列を読み取ります。 
2. 文字列がドットで始まるかドットで終わるかを確認します。 

有効なドメインの先頭または末尾に空のセグメントを含めることはできません。 
3. 文字列内のすべての文字をスキャンします。 

文字が小文字、数字、またはドットではない場合、その文字列は直ちに拒否されます。 
4. 同じスキャン中に、隣接する文字をチェックします。 

連続する 2 つの文字が両方ともドットである場合は、空のセグメントが作成されるため、文字列を拒否します。 
5. ドットを区切り文字として使用して文字列を分割します。 
6. 最後のセグメントを取り出し、その長さを確認します。 

長さは 2 または 3 でなければなりません。 
7. すべてのチェックに合格したら、印刷します。`"YES"`。 それ以外の場合は印刷します`"NO"`。 

### なぜ効果があるのか

 このアルゴリズムは、有効なドメインの定義からのすべての条件を直接エンコードします。 文字スキャンにより、禁止記号が表示されないことが保証されます。 境界チェックにより、先頭または末尾に空のセグメントが存在することが防止されます。 連続ドットチェックにより、途中の空のセグメントが防止されます。 ドットで分割すると最終セグメントが露出するので、その長さの制約を正確に検証できます。 すべてのルールが明示的にチェックされ、ルールが失敗すると即座に拒否されるため、アルゴリズムは有効なドメイン名を正確に受け入れ、無効なドメイン名をすべて拒否します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    if s[0] == '.' or s[-1] == '.':
        print("NO")
        return

    for i, ch in enumerate(s):
        valid = (
            ('a' <= ch <= 'z') or
            ('0' <= ch <= '9') or
            ch == '.'
        )

        if not valid:
            print("NO")
            return

        if i > 0 and s[i] == '.' and s[i - 1] == '.':
            print("NO")
            return

    parts = s.split('.')
    last_len = len(parts[-1])

    if last_len == 2 or last_len == 3:
        print("YES")
    else:
        print("NO")

solve()
```最初の条件は境界ドットを即座に処理します。 これにより、分割後に空の先頭または末尾のセグメントが誤って受け入れられることが回避されます。 

メインループは 2 つのチェックを 1 つのパスに結合します。 まず、次のようなヘルパーの代わりに明示的な範囲比較を使用して文字を検証します。`isalnum()`。 それは重要です、なぜなら`isalnum()`誤って大文字が許可されてしまいます。 

隣接性チェックは次の場合にのみ開始されます。`i > 0`、最初の文字での範囲外アクセスを防ぎます。 

検証後、文字列はドットで分割されます。 連続ドットと境界ドットはすでに拒否されているため、すべてのセグメントが空ではないことが保証されます。 残りの唯一の条件は、最後のセグメントのサイズです。 

この実装では、分割結果を超える追加のデータ構造は決して使用されず、すべての操作は文字列長において線形です。

import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    def solve():
        s = input().strip()

            return "NO"

            valid = (
                ('a' <= ch <= 'z') or
                ('0' <= ch <= '9') or
                ch == '.'
            )

                return "NO"

        parts = s.split('.')
        last_len = len(parts[-1])

        if last_len == 2 or last_len == 3:
            return "YES"

        return "NO"

    return solve()

 ## 特殊なケース

 次の入力を考えてみましょう。```
.google
```アルゴリズムは最初の文字を直ちにチェックし、それがドットであることを確認します。 分割が発生する前に文字列を拒否します。 これにより、空の最初のセグメントを誤って受け入れることがなくなります。 

次に、次のことを考えてみましょう。```
abc..com
```スキャン中、アルゴリズムが 2 番目のドットに到達すると、それを前の文字と比較して検出します。`".."`。 文字列は即座に拒否されます。 後の処理でこの失敗を無効にすることはできません。 

入力の場合:```
abc.c
```すべての文字とドット構造のチェックは成功します。 分割後の最後のセグメントは、`"c"`、長さは 1 です。長さ 2 と 3 のみが受け入れられるため、アルゴリズムは次のように出力します。`"NO"`。 

最後に、次のことを考慮してください。```
Codeforces.com
```最初の文字をスキャンするとき`'C'`、小文字の範囲チェックは失敗します。`'C'`外にいる`'a'`に`'z'`。 アルゴリズムは文字列を即座に拒否し、小文字のみのルールを正しく適用します。
