 ## 解決策
 ## 問題の理解

 与えられた整数 _n_ の周囲に最も近い素数を見つけるように求められます。 具体的には、_a_ ≤ _n_ ≤ _b_ であり、_a_ と _b_ が両方とも素数であるような 2 つの数値 _a_ と _b_ が必要です。 _n_ を含むすべての素数区間の中で、長さ _b - a_ が最も短いものが優先されます。 複数の間隔の長さが同程度である場合、問題は区別されないため、最も短い間隔を返すことが有効です。 

入力は、2 ～ 10,000 の単一の整数 _n_ です。 この境界は十分小さいため、_n_ の周囲の素数を直接検索することが可能です。 適度な範囲内に _n_ 以下の素数と _n_ 以上の素数が常に存在するため、各出力の存在が保証されます (10,000 までの数値の場合、連続する素数間のギャップが 100 を超えることはありません)。 

エッジ ケースには、_n_ 自体が素数であるか、_n_ が最小の素数 (2) に非常に近いことが含まれます。 たとえば、_n_ = 2 の場合、最小セグメントは [2,3] になります。 不用意に実装すると、2 未満を検索しようとして失敗したり、無効な負の数が返されたりする可能性があります。 もう 1 つの微妙なケースは、次の素数が 97 である 89 付近の素数ギャップです。単純な off-by-one 検索では上限を見逃す可能性があります。 

## アプローチ

 最も明白な方法は総当りです。_n_ から開始して下方向にスキャンして最も近い小さいか等しい素数を見つけ、次に上方向にスキャンして最も近い大きいか等しい素数を見つけます。 どちらの検索も、最も近い素数までの距離が線形です。 

これが機能するのは、数値が小さく、素数が過度にまばらではないためです。 _n_ = 10,000 の場合、最も近い下位素数は 27 ステップ離れた 9973、最も近い上位素数は 7 ステップ離れた 10,007 です。 これらのスキャンの各数値を単純に除算するには、その平方根までの割り算をチェックする必要があり、候補ごとにおよそ O(√n) が得られます。 これに最悪の場合の検索距離 ~100 を掛けると、最大 1,000 回の操作が得られ、2 秒の制限内に十分収まります。 

効率性を高めるための重要な洞察は、エラトステネスのふるいを使用して、すべての素数を合理的な最大値まで事前に計算することです。 10,000 までのすべての素数のリストを取得したら、最も近い下位素数と上位素数を見つけるには、ソートされたリストでの小さな線形スキャンまたは二分探索が必要になります。 これにより、繰り返しの割り算チェックが不要になり、エッジケースの処理が簡素化されます。 

ブルートフォースアプローチはシンプルで正しいですが、ふるいベースのアプローチはよりクリーンで高速です。 また、ふるいを使用すると、素数を見逃すことがなくなり、素数に等しい _n_ の処理が簡単になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(√n * ギャップ) | お(1) | 受け入れられるが冗長 |
 | ふるい+検索 | O(n log log n + log n) | O(n) | クリーン、受け入れ済み |

 ## アルゴリズムのチュートリアル

 1. ブール配列を作成する`is_prime`_n_ よりもわずかに高い制限までの数値を表し、最初は 2 以上のすべての数値を素数としてマークします。 エラトステネスのふるいを使用して、各素数の倍数を非素数としてマークします。 ふるいはそれを保証します`is_prime[x]`は`True`_x_ が素数である場合に限ります。 
2. 下限 _a_ を見つけるには、_n_ から開始して下方向にスキャンして、`is_prime[a]`は`True`。 これにより、_n_ 以下の最大の素数が見つかります。 
3. 上限 _b_ を見つけるには、_n_ から開始して上向きにスキャンして、`is_prime[b]`は`True`。 これにより、_n_ 以上の最小の素数が見つかります。 
4. _a_ と _b_ を出力します。 ふるいが必要な範囲をカバーし、スキャンによって _n_ からの最小距離が保証されるため、このペアの存在が保証されます。 

機能する理由: ふるいにより、素数を誤って識別することがなくなります。 _a_ については下方向にスキャンし、_b_ については上方向にスキャンすると、_n_ の周囲に最も近い素数が保証され、最小のセグメント長が生成されます。 10,000 未満の素数ギャップは常に小さいため、アルゴリズムはすぐに終了します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAX_N = 11000  # Slightly larger than the max n to handle upper bound

# Sieve of Eratosthenes
is_prime = [True] * (MAX_N + 1)
is_prime[0] = is_prime[1] = False
for i in range(2, int(MAX_N**0.5) + 1):
    if is_prime[i]:
        for j in range(i*i, MAX_N + 1, i):
            is_prime[j] = False

n = int(input())

# Find closest prime <= n
a = n
while not is_prime[a]:
    a -= 1

# Find closest prime >= n
b = n
while not is_prime[b]:
    b += 1

print(a, b)
```ふるいの事前計算により、次のことが保証されます。`is_prime`11,000 までのすべての数値の素数を正確に反映します。 下向きおよび上向きのスキャンは、_n_ 自体が素数である場合を含む、エッジ ケースを処理します。 わずかに高い MAX_N を選択すると、上方への検索で配列の境界を超えることがなくなります。 11,000 未満の連続する素数間の最大ギャップは小さいため、ループは安全です。

 ## 特殊なケース

 n = 2 の場合、下向きスキャンは 2 を下回ることはできません。アルゴリズムはすぐに 2 を素数として識別するため、`a = 2`。 同様に、上方向にスキャンすると 2 が見つかり、[2,2] が生成されます。 n = 10,000 の場合、下向きスキャンでは 9973 が見つかり、上向きスキャンでは 10,007 が見つかります。 MAX_N = 11,000 を使用することで、インデックスの範囲外エラーを回避し、上限に近いまれな素数ギャップを正しく処理します。 これらの例は、アルゴリズムが最小入力と最大入力、n の素数、および通常のケースを一貫して処理することを確認します。
