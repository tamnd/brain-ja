 ## 問題の理解

 入力は、3 文字の文字列として記述された小さな算術式です。 最初と 3 文字目は次の数字です。`0`に`9`、中央の文字は次のいずれかです`+`または`-`。 タスクは、式を評価し、結果の整数を出力することです。 

たとえば、入力`1-5`引き算を表します`1 - 5`したがって、正しい出力は次のようになります。`-4`。 入力`7+2`を表します`7 + 2`したがって、出力は次のようになります`9`。 

式は常に固定長であるため、制約は非常に小さくなります。 ライブラリ、トークン化、再帰、または式ツリーの解析は必要ありません。 3 文字を読み取って 1 回の算術演算を適用するだけなので、一定の作業量で十分です。 

唯一の微妙な部分は、結果が負になった場合に引き算を正しく処理することです。 すべての出力が非負であると仮定する不用意な実装は、次のような入力で失敗します。```
1-5
```正しい出力は次のとおりです。```
-4
```もう 1 つの簡単な間違いは、文字を操作する前に文字を整数に変換することを忘れることです。 たとえば、文字コードを直接減算した場合、結果は無意味になります。 入力あり:```
9-2
```整数の減算を計算する必要があります`9 - 2 = 7`、ASCII 値間の違いではありません。 

3 番目のエッジ ケースはゼロです。 次のような表現:```
0-0
```以下を正しく生成する必要があります。```
0
```一部のバグのある実装では、誤って特殊な場合の減算が行われ、等しいオペランドが誤って処理されます。 

## アプローチ

 最も直接的なアプローチは、演算子の文字を検査し、それに応じて結果を計算することです。 式の長さは常に 3 であるため、最初の桁、演算子、およびインデックスによって 2 番目の桁にアクセスできます。 数字を整数に変換した後、加算または減算を行います。 

ここでは、ブルートフォーススタイルのソリューションであっても、事実上一定時間になります。 考えられるすべての式を手動でチェックすることもできます。`0+0`を通して`9-9`、それらをルックアップ テーブルに保存し、一致した結果を出力します。 可能な式は 200 しかないため、それでも数百の操作しか必要ありません。 すべての有効な入力がこの有限セットに属しているため、このアプローチは正しいですが、不必要に厳密であり、可読性が低くなります。 

より明確な観察は、入力がすでにすべてを直接エンコードしているということです。 中央の文字によって、どの算術演算を適用するかが完全に決まります。 2 桁を整数に変換すると、評価は 1 回の加算または減算になります。

 ## アルゴリズムのチュートリアル

 1. 入力文字列を読み取ります。 

式には常に次の形式があります。`digit operator digit`, そのため、長さは 3 文字に固定されています。 
2. 最初の桁、演算子、および 2 番目の桁を抽出します。 

最初の桁はインデックスにあります`0`、インデックスの演算子`1`、インデックスの 2 桁目`2`。 
3. 数字文字を整数に変換します。 

文字の算術演算が正しくないため、次を使用して文字を変換する必要があります。`int()`。 
4. オペレーターを確認します。 

オペレーターが`+`、合計を計算します。 それ以外の場合は、差を計算します。 
5. 結果を印刷します。 

### なぜ効果があるのか

 式の形式では、演算子が 1 つと 1 桁のオペランドが 2 つあることが保証されます。 アルゴリズムはこれら 3 つのコンポーネントを直接読み取り、対応する算術規則を適用します。 加算と減算は式で定義されたとおりに実装されるため、生成される値は常に数学的結果と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

a = int(s[0])
op = s[1]
b = int(s[2])

if op == '+':
    print(a + b)
else:
    print(a - b)
```プログラムは、式文字列を読み取り、末尾の改行を次のように削除することから始まります。`strip()`。 

最初と 3 番目の文字はすぐに整数に変換されます。 これにより、文字を直接操作することによる間違いを回避できます。 中央の文字は演算子として保存されます。 

条件は、演算子が以下であるかどうかをチェックします。`'+'`。 true の場合、プログラムは合計を出力します。 それ以外の場合、残っている唯一の有効な演算子は`'-'`, したがって、減算結果を出力します。 

入力形式では式に正確に 3 文字が含まれることが保証されているため、境界の問題はありません。 Python の整数は負の値も安全に処理できるため、次のような場合は`1-5`自然に働きます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    s = input().strip()

    a = int(s[0])
    op = s[1]
    b = int(s[2])

    if op == '+':
        print(a + b)
    else:
        print(a - b)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    backup_stdout = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup_stdout
    return out.getvalue()

# provided sample
assert run("1-5\n") == "-4\n", "sample 1"

# custom cases
assert run("0+0\n") == "0\n", "minimum values"

assert run("9-0\n") == "9\n", "subtraction with zero"
assert run("0-9\n") == "-9\n", "negative result boundary"
assert run("5-5\n") == "0\n", "equal operands"

0
```このケースでは、両方のオペランドが等しい場合に、減算によって誤って符号エラーが発生しないことが検証されます。
