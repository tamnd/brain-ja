 ## 解決策
 ## 問題の理解

 テーブルボウリングトーナメントの最終順位が与えられました。 すべての参加者は一意の名前と整数のスコアを持っています。 このタスクは、プレイヤーを並べ替えるだけでなく、実際のトーナメントで使用されるスタイルでランキング ラベルを割り当てることも必要です。 

プレーヤーは主にスコアの降順で順序付けされます。 2 人のプレイヤーが同じスコアを持っている場合、その名前によって辞書順に順序が決まります。 分類した後、各参加者をその場所とともに出力する必要があります。 

難しいのは、タイを正しく処理することです。 複数のプレイヤーが同じスコアを共有する場合、同じ範囲の順位も共有します。 たとえば、3 人のプレーヤーが 5、6、7 位を占めている場合、全員のスコアが 100 であるため、全員がラベルを受け取る必要があります。`5-7`。 

入力サイズが小さいです。 参加者は最大 100 人であるため、二次解法であっても完全に安全です。 単純な並べ替えで、問題のほとんどすべてがすでに解決されています。 本当の課題は、ランキング間隔を正しくフォーマットすることです。 

危険なエッジケースはすべてネクタイに関連しています。 

次の入力を考えてみましょう。```
3
alice 10
bob 10
carol 10
```3 人のプレーヤー全員がポジション 1 ～ 3 を共有しているため、正しい出力は次のようになります。```
1-3 alice
1-3 bob
1-3 carol
```不注意に実装すると、代わりに次のように出力される可能性があります。```
1 alice
2 bob
3 carol
```これにより、同点のスコアに異なるランクが誤って割り当てられてしまいます。 

もう 1 つの微妙なケースは、テーブルの中央で同点が発生した場合に現れます。```
5
anna 100
bella 90
claire 90
diana 80
eva 70
```正しい出力は次のとおりです。```
1 anna
2-3 bella
2-3 claire
4 diana
5 eva
```同点後の次のランクは、実際に占有されているポジションから継続する必要があります。 2 位と 3 位が共有されると、次の参加者は 3 位ではなく 4 位を受け取ります。 

オフバイワンのミスを引き起こすもう 1 つのケースは、最後に同点になることです。```
4
a 5
b 4
c 1
d 1
```正しい出力は次のとおりです。```
1 a
2 b
3-4 c
3-4 d
```グループ化されたスコアを処理するときは、間隔の境界を慎重に計算する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 まず、すべての参加者をスコアの降順と名前の昇順で並べ替えます。 次に、参加者ごとに配列全体をスキャンして、何人のプレーヤーが同じスコアを共有しているかを数え、そのスコア グループの最初と最後の位置を決定します。 

制約が小さいため、これは機能します。 最大でも 100 人のプレイヤーがいる場合、`O(n^2)`スキャンでは、最悪の場合でも約 10,000 件の比較のみが実行されます。 

それでも、繰り返しの再スキャンは不要です。 並べ替えると、同じスコアが連続します。 この観察により、問題は「一致するスコアをグローバルに検索する」から「連続するグループを処理する」に変わります。 

配列がソートされたら、左から右に順番に見ていきます。 インデックスを仮定します`i ... j`全員が同じスコアを共有します。 その後、これらの選手がポジションを占めます`i + 1 ... j + 1`ランキングは 1 から始まるため、ランキングに含まれます。 

もし`i == j`、プレーヤーには固有のランクがあるため、単一の番号を出力します。 それ以外の場合は、グループ全体で間隔を共有します`i+1 - j+1`。 

このグループ化が機能する理由は、並べ替えによって 2 つのプロパティが同時に保証されるためです。 スコアはランキング順に表示され、同じスコアが 1 つの連続したブロックを形成します。 つまり、結合されたすべてのグループを 1 つのパスで独立して処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 承認済み |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての参加者を配列に読み取ります。`(name, score)`ペア。 
2. 2 つのキーを使用して配列を並べ替えます。 

- スコアは降順で表示されます
 - 辞書編集上の昇順の名前

 これにより、ステートメントに必要な正確な出力順序が生成されます。 
3. インデックスを初期化する`i = 0`。 
4. ながら`i < n`、同じスコアを持つプレイヤーの最大セグメントを見つけます。 

別のポインタを開始する`j = i`、その後移動します`j`forward while the next participant has the same score.
 5. インデックスのプレーヤー`i ... j`ランキングの地位を占める`i + 1 ... j + 1`。 

ランキングは 1 ベースなので、配列インデックス 0 は 1 位に対応します。 
6. もし`i == j`、印刷:```
place name
```それ以外の場合は、次のように出力します。```
start-end name
```グループの参加者全員に。 
7.セット`i = j + 1`次のスコア グループの処理を続行します。 

### なぜ効果があるのか

 並べ替え後、より高いスコアを持つすべての参加者が配列の先頭に表示されます。 スコアが等しい参加者は、主並べ替えキーで同等に比較されるため、連続して表示されます。 

インデックスを占有するグループの場合`i ... j`、 その通り`i`参加者は厳密に高いスコアを持っているため、最初の有効な場所は次のとおりです。`i + 1`。 その通り`j + 1`参加者は少なくとも同じスコアを持っているため、最後に占有された場所は`j + 1`。 

グループのすべてのメンバーは、トーナメントのランキング定義に一致する同じ間隔を受け取ります。 すべての参加者は 1 つの連続したスコア グループに属しているため、アルゴリズムによってすべてのプレーヤーに正しい順位が割り当てられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    players = []
    
    for _ in range(n):
        name, score = input().split()
        players.append((name, int(score)))
    
    players.sort(key=lambda x: (-x[1], x[0]))
    
    ans = []
    
    i = 0
    
    while i < n:
        j = i
        
        while j + 1 < n and players[j + 1][1] == players[i][1]:
            j += 1
        
        left = i + 1
        right = j + 1
        
        for k in range(i, j + 1):
            name = players[k][0]
            
            if left == right:
                ans.append(f"{left} {name}")
            else:
                ans.append(f"{left}-{right} {name}")
        
        i = j + 1
    
    print("\n".join(ans))

solve()
```最初のステージでは、すべての参加者をペアのリストに読み込みます。 タプルを使用すると、並べ替えと処理中に名前とスコアの両方が一緒に保持されます。 

注目すべきはソートキーです。 まず高いスコアが必要なので、スコアは無効になります。 名前は通常の昇順のままで、タイは辞書順に自動的に解決されます。 

メインループは一度に 1 つのスコア グループを処理します。 ポインタ`i`は現在のグループの始まりを示します。`j`同じスコアを共有する最後の参加者に展開されます。 

ランキング間隔はインデックスから直接得られます。 ランキングは 0 ではなく 1 から始まるため、両方の境界によりインデックスに 1 が追加されます。 

条件`left == right`固有のランクを共有範囲から区別します。 このチェックがないと、単一のプレーヤーが次のような出力を誤って受け取ることになります。`3-3 alice`。 

ついに、`i = j + 1`次の未処理のスコア グループに直接ジャンプします。

 ## 特殊なケース

 すべての参加者が同じスコアを持つ場合を考えてみましょう。```
4
dan 50
anna 50
mike 50
bob 50
```等しいスコア内で辞書順に並べ替えた後:```
anna 50
bob 50
dan 50
mike 50
```アルゴリズムは次から始まります`i = 0`そして拡大します`j`それまで`j = 3`すべてのスコアが一致するからです。 間隔は`1-4`、これは参加者ごとに印刷されます。```
1-4 anna
1-4 bob
1-4 dan
1-4 mike
```これにより、1 つの大きなスコア ブロックが正しく処理されることが確認されます。 

ここで、最初だけが同点であることを考えてみましょう。```
4
alice 100
bob 100
carol 90
dave 80
```最初のグループはインデックスを占有します`0..1`, したがって、両方のプレイヤーが受け取ります`1-2`。 次の参加者はインデックスから開始します`2`、場所に対応します`3`。 

出力：```
1-2 alice
1-2 bob
3 carol
4 dave
```これは、ランキングが最初の順位の後ではなく、同グループのフルサイズ以降も継続していることを検証します。 

最後に、タイ内の辞書編集上の順序を考慮します。```
3
zack 10
anna 10
mike 10
```すべてのスコアは等しいため、名前によって順序が決まります。```
anna
mike
zack
```アルゴリズムは次を出力します。```
1-3 anna
1-3 mike
1-3 zack
```名前による 2 番目の並べ替えがないと、ランキング間隔自体は正しくても、出力順序が不正確になります。
