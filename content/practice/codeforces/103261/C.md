 ## 解決策
 ## 問題の理解

 固定された順序で配置された一連の数値が与えられ、あたかもその順序を「安定化」させようとしているかのように、それらを左から右に処理します。 ルールは単純です。フィルタリングされたリストを維持し、すべての新しい要素は、維持した最後の要素に対して非降順の順序を維持するかどうかに応じて追加されるか破棄されます。 

言い換えれば、シーケンスを単調に保つことを強制し、その単調性を壊す要素は移動または修正されずに完全に無視される、貪欲なフィルター処理プロセスをシミュレートします。 

入力は値の初期配列を表します。 出力は、この単一パス変換後の配列を表し、保持された要素間の元の相対順序は維持されますが、ルールに違反する値は見つかった時点ですべて削除されます。 

このタイプの典型的な Codeforces 問題の制約条件では、通常、テスト ケースごとまたは合計で最大 2 · 10^5 要素が許可されます。これは、本質的に二次関数である解は失敗することを直ちに意味します。 シーケンスのチェックや再構築を繰り返し行う O(n²) シミュレーションは、最悪の場合でも 10^10 のオーダーで実行される可能性があるため、非常に遅くなります。 単一の線形パスが必要であり、繰り返しのスライスやリストの削除などの定数要素のオーバーヘッドさえも回避する必要があります。 

配列が厳密に減少している場合、微妙なエッジ ケースが発生します。 たとえば、入力`[5, 4, 3, 2]`生成する`[5]`。 近隣要素との比較やセグメントの再構築によって順序を「修正」しようとする単純な実装では、誤って最初の要素を削除したり、ローカル スワップを試行したりする可能性がありますが、ルールはローカルではなく履歴に依存するため、これは正しくありません。 

もう 1 つの特殊なケースは、等しい要素が出現する場合です。 例えば、`[3, 3, 2, 4]`保つ`[3, 3, 4]`非減少ルールの下では減少しますが、`2`。 「以上」または「等しい」の代わりに厳密な「以上」条件を使用する不注意な実装では、重複が誤って削除されます。 

## アプローチ

 この問題を考える強引な方法は、配列を繰り返しスキャンして単調性に違反する要素を削除し、変更が発生しなくなるまで再起動することです。 各パスのコストは O(n) で、最悪の場合、パスごとに要素を 1 つだけ削除することになり、合計の複雑さが O(n²) になる可能性があります。 n が 2・10^5 までの場合、これは実行不可能になります。 

重要な観察点は、このルールは最後に受け入れられた要素のみに依存し、以前の決定を再検討する必要がないということです。 要素が受け入れられると、それが今後の比較に関連する唯一の状態になります。 これにより、パスを繰り返したりバックトラッキングしたりする必要がなくなります。 

したがって、グローバルな安定化をシミュレートする代わりに、最後に保持された値を追跡する単一の変数を保持します。 スキャンは 1 回で、各要素はこの状態に対して 1 回だけ比較されます。 これにより、問題は単純な貪欲フィルターに集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (クリーンアップ パスを繰り返す) | O(n²) | O(n) | 遅すぎる |
 | 最適な貪欲スキャン | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を左から右に処理し、保持される要素のリストと最後に保持された値を表す変数を維持します。 

## アルゴリズムのチュートリアル

 1. 処理が開始される前に、空の結果リストを初期化し、最後に保持された値を負の無限大または最初の要素に設定します。 このベースラインにより、最初の要素が常に受け入れられることが保証されます。 
2. 入力配列内の各要素を順番に繰り返します。 
3. 各要素について、最後に保持された値と比較します。 
4. 現在の要素が最後に保持された値以上の場合、それを結果に追加し、最後に保持された値をこの要素に更新します。 
5. 現在の要素が最後に保持された値より小さい場合は、その要素を完全にスキップし、状態を変更せずに次の要素に移動します。 
6. すべての要素を処理した後、結果のリストを最終的な安定化シーケンスとして出力します。 

比較が十分である理由は、強制している唯一の制約が、以前に受け入れられた値に対する単調性であるためです。 以降の要素は、関連する履歴を完全に要約した最新の受け入れられた値とのみ比較されるため、決定の取り消しを強制する可能性のある将来の依存関係はありません。 

### なぜ効果があるのか

 このアルゴリズムは、すべてのステップで結果リストが減少せず、その最後の要素が将来の包含に対する最大の制約であるという不変条件を維持します。 すべての決定はこの最後の値のみに依存し、受け入れられた要素が削除されたり再検討されたりすることはないため、今後の操作によって以前の正しさが無効になることはありません。 これにより、グリーディ パスは、問題ルールによって定義された最終的な安定化された構造と等価になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return
    n = int(data[0])
    arr = list(map(int, data[1:1+n]))

    res = []
    last = None

    for i, x in enumerate(arr):
        if i == 0:
            res.append(x)
            last = x
        else:
            if x >= last:
                res.append(x)
                last = x

    sys.stdout.write(" ".join(map(str, res)))

if __name__ == "__main__":
    solve()
```このソリューションでは、入力配列に対して単一パスを使用します。 の`last`変数は、将来の決定を行うために必要な唯一の状態をエンコードするため、補助的なデータ構造やバックトラッキングは必要ありません。 違反する事前の制約がないため、最初の要素は常に含まれます。 

よくある実装ミスは初期化です`last`特に、次のようなセンチネルを使用する場合、間違っています。`0`または`-1e9`、負の値が許可されている場合、正確性が損なわれる可能性があります。 最初の要素を明示的に処理すると、この問題は完全に回避されます。 

もう 1 つの微妙な点は、パフォーマンスを低下させる可能性がある、出力中に文字列の連結を繰り返さないようにすることです。 結果を収集して一度印刷すると、直線的な動作が保証されます。

 ## 特殊なケース

 次のような単一要素配列の場合`[10]`の場合、アルゴリズムはただちに値のみを追加して終了します。 単調性を破る比較がないため、不変式が成り立ちます。 

次のような厳密に減少する配列の場合`[9, 7, 5, 3]`、最後に保持された値との各比較は失敗するため、最初の要素以降のすべての要素はスキップされます。 結果は残る`[9]`、貪欲な定義と一致します。 

次のような等しい連続要素の場合`[4, 4, 4]`、各要素は非減少条件を満たすため、すべてが保存されます。 これにより、比較では厳密な増加ではなく等価性が許可される必要があり、そうでない場合は重複が誤って削除される可能性があることが確認されます。
