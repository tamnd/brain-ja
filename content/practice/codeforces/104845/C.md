 ## 解決策
 ## 問題の理解

 私たちには、エッジが「隣人」関係を表すレストランのネットワークが与えられています。 一部のレストランは開始時にすでにティムールと協力しています。 これらの初期採用者から協力が広がる可能性があります。少なくとも以下の条件が満たされれば、どのレストランも協力することを決定するでしょう。$k$近隣諸国はすでに協力している。 

これは一度限りの決定ではありません。 より多くのレストランが協力を開始すると、さらに多くのレストランが閾値を超える可能性があるため、新しいレストランがアクティブ化されなくなるまでこのプロセスが続きます。 

課題は、最初のセットから始めて、この伝播が安定した後に最終的にどのレストランが協力することになるかを判断することです。 

グラフには最大で次のものを含めることができます$2 \cdot 10^5$したがって、どのソリューションもエッジの数が線形に近くなければなりません。 すべてのステップですべてのノードにわたる 2 次シミュレーションは非常に遅すぎます。これは、隣接ノードを繰り返しスキャンすることになるためです。$O(nm)$密集した場合の動作。 

微妙なエッジケースが現れるのは、$k = 0$。 この状況では、隣接するレストランに関係なく、すべてのレストランが即座に資格を取得するため、最終的な答えは自明のことながらすべてのノードになります。 伝播をシミュレートしようとする実装では、これを慎重に処理する必要があります。そうしないと、過度に複雑になったり、カウントが間違ったりする可能性があります。 

注目に値するもう 1 つのケースは、初期セットが空の場合です。 その場合、アクティブ化された隣人がいるレストランは存在しません。$k = 0$、何もアクティブ化できません。 

## アプローチ

 このプロセスについて単純に考えると、すべてのレストランを繰り返しスキャンし、各レストランがすでに「少なくとも」という条件を満たしているかどうかを確認することになります。$k$それを満たす新しいレストランを見つけるたびに、それをアクティブにしてスキャンを再開します。 

これはルール定義を直接反映しているため、これは正しいです。 ただし、問題はパフォーマンスです。 すべてのノードにわたる各スキャンのコスト$O(n + m)$近隣住民のチェックをカウントすると、最悪の場合、一度に 1 つのレストランをアクティブにする可能性があり、その結果、$O(n)$ラウンドします。 これにより、$O(n(n + m))$、これは大きすぎます$n, m \le 2 \cdot 10^5$。 

重要な観察は、完全な近隣カウントを最初から再計算する必要がないということです。 重要なのは、各レストランに現在すでにアクティブな隣人が何人いるかです。 これは、ノードごとに実行中のカウンターを維持し、近隣ノードがアクティブになったときにそれを段階的に更新することを示唆しています。 

このように見ると、プロセスはグラフ上の標準的な伝播になります。 最初にアクティブなすべてのノードから開始し、それらをキューにプッシュし、アクティブ化するたびにその隣接ノードを更新します。 ネイバーのアクティブ数が到達するたびに$k$、アクティブになり、キューにもプッシュされます。 

これにより、プロセスが幅優先スタイルの拡張に変わり、1 つのエンドポイントがアクティブになった場合にのみ各エッジが処理されます。

 | 最適な BFS 伝播 |$O(n + m)$|$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 グラフを隣接リストとして解釈します。 各ノードは、すでにアクティブになっている隣接ノードの数を追跡するカウンターを維持します。 

1. 入力エッジからグラフの隣接リストを作成します。 これは、ノードがアクティブになったときに隣接ノードを効率的に通過できるようにするために必要です。 
2. 配列を作成する`cnt`すべてのノードでゼロに初期化されます。 これにより、各ノードが現在アクティブなネイバーの数を保存します。 
3. ブール配列を初期化する`active`どこ`active[i]`レストランの場合は true$i$開始時にすでに協力しています。 これらのノードは、伝播の最初のフロンティアを形成します。 
4. 最初にアクティブだったすべてのノードをキューに挿入します。 これらは、他のノードに即座に影響を与えることができる唯一のノードです。 
5. キューが空でない間に、アクティブなノードを 1 つ抽出します$u$。 すべての隣人のために$v$の$u$、増分`cnt[v]`さらに 1 つ隣接するものがアクティブになったため、1 つずつ増えます。 
6. もし`cnt[v]`正確に届く$k$そして$v$まだアクティブではありません。マークしてください$v$アクティブとしてキューにプッシュします。 こうなった瞬間、$v$近隣諸国への新たな影響力の源となる。 
7. キューがなくなるまで続行します。 その時点で、非アクティブなノードはもう閾値に達していないため、プロセスは安定しています。 

### なぜ効果があるのか

 このアルゴリズムは、すべてのノードに対して次の不変条件を維持します。`cnt[v]`常に近傍の数と等しくなります$v$プロセスの現在の時点ですでにアクティブ化されているもの。 すべてのアクティベーション イベントは、これらのカウンターを増加させるだけで、減少させることはなく、拡散ルールの単調な性質に一致します。 

ノードは、アクティブな隣接ノードの実際の数が少なくとも次の数に達するとアクティブになります。$k$。 隣接ノードがアクティブ化されるとすぐにカウンタが更新されるため、適格なノードが見逃されることはなく、途中でアクティブ化されるノードもありません。 キューは、アクティベーションが正しい因果順序で伝播することを保証します。これは、固定点に到達するまで元のルールを繰り返し適用するのと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, k = map(int, input().split())
    
    adj = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)
    
    initial = list(map(int, input().split()))
    if len(initial) == 1 and initial[0] == 0:
        initial = []
    
    if k == 0:
        print(n)
        print(*range(1, n + 1))
        return
    
    active = [False] * (n + 1)
    cnt = [0] * (n + 1)
    
    q = deque()
    
    for x in initial:
        if not active[x]:
            active[x] = True
            q.append(x)
    
    while q:
        u = q.popleft()
        for v in adj[u]:
            if active[v]:
                continue
            cnt[v] += 1
            if cnt[v] >= k:
                active[v] = True
                q.append(v)
    
    res = [i for i in range(1, n + 1) if active[i]]
    
    print(len(res))
    print(*res)

def main():
    solve()

if __name__ == "__main__":
    main()
```隣接リストは標準的な方法で構築され、グラフは無向であるため、各エッジが 2 回保存されることが保証されます。 の`cnt`アレイは、しきい値条件に向けた進行状況を追跡する中心的なメカニズムです。 

キューには、アクティブになったばかりのノードが正確に含まれます。 各ノードは 1 回処理され、アクティブ化は永続的であるため、一度処理されるとキューに再入力されることはありません。 これにより線形の複雑さが保証されます。 

実装の小さな詳細は、初期の処理です。$k = 0$これにより、不必要なグラフ処理が完全に回避されます。 もう 1 つの微妙な点は、すでにアクティブなノードを再追加しないようにすることです。そうしないと、カウントが誤って増大してしまいます。

 ## 特殊なケース

 重要なエッジケースは、$k = 0$。 この状況では、グラフの構造に関係なく、すべてのレストランが即座に条件を満たします。 このアルゴリズムは、グラフを処理せずにすべてのノードを直接出力することでこれを処理します。 たとえば、任意の入力グラフと$k = 0$、出力は常に完全なセットである必要があります$1 \ldots n$、BFS をスキップすると、不必要な作業が防止されます。 

別のケースは、正の値を持つ空の初期セットです。$k$。 このシナリオでは、どのノードもアクティブな隣接ノードを取得できないため、キューは空で開始され、プロセスはすぐに終了します。 すべてのカウンタがゼロのままであり、しきい値に到達しないため、不変条件が成り立ちます。 

最後に、次数が より小さいノードを考えます。$k$。 このようなノードは、最初にアクティブになっていない限り、アクティブにすることはできません。 カウンタメカニズムはこれを自然に強制します。`cnt[v]`その程度を超えることは決してできないので、決して到達することはできません$k$もし$k$の方が大きいです。
