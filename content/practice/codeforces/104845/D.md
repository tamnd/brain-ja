 ## 問題の理解

 私たちは、インデックス付きの非常に大きな配列を維持しています。$10^9$、ただし最初だけ$n$位置は最初はゼロではありません。 残りの位置はすべて暗黙的にゼロになります。 各位置は 30 ビットの整数を保持します。 

操作は2つあります。 まず、単一の位置を新しい値に更新できます。 次に、負でない整数がいくつあるかを数えるように求められます。$x$グローバルなビット単位の制約を満たす: すべての配列要素のビット単位の OR を次のようにとった場合$x$、結果は指定された境界を超えません$z$。 

重要な観察は、すべての配列要素に対する OR により、構造全体が 1 つの値に折りたたまれるということです。 定義すると$$S = a_1 \,|\, a_2 \,|\, \cdots \,|\, a_n,$$この場合、追加のゼロ要素はすべて何も寄与しないため、グローバル OR は正確に次のようになります。$S$。 追加後$x$の状態になります。$$S \,|\, x \le z.$$制約は大きく、最大で$10^5$更新とクエリ、値は 30 ビット以内に収まります。 クエリごとに OR を最初から再計算するソリューションは、すべての要素にアクセスするとコストがかかるため、遅すぎます。$O(nq)$、それは約です$10^{10}$最悪の場合の運用。 

微妙な点は、更新は最大で任意のインデックスで発生する可能性があることです。$10^9$ただし、最初に提供されたインデックスのみが重要です。 他の位置は永久にゼロであるため、初期セットを参照しない限り、初期セットの外にある更新は概念的に無視できます。$n$または、より一般的な解釈でアクティブ セットを拡張します。 

エッジケースは、ビットがキャンセルまたは再出現するときに発生します。 

すべての値がゼロになると、条件は次のようになります。$x \le z$、与える$z+1$ソリューション。 もし$S$すでに超えています$z$の値はありません$x$上位ビットを修正できる$S$, したがって、答えはゼロです。 

## アプローチ

 直接的なアプローチでは、配列全体が維持され、タイプ 2 のすべてのクエリの OR が再計算されます。これは正しいです。OR は結合的で可換的であるため、最初から再計算すると常に正しい結果が得られます。$S$。 ただし、各クエリでは最大で次のスキャンが必要になります。$n$要素、$O(nq)$仕事。 と$n,q \approx 10^5$が鈍くなるにもほどがあります。 

構造上の重要な洞察は、OR がビットごとに単調に動作するということです。 各ビットはグローバル状態に存在するか存在しないかのいずれかであり、固定セット内のトグル ビットのみを更新します。 クエリ タイプ 2 の個々の要素を知る必要はなく、現在のグローバル OR だけを知る必要があります。$S$。 

したがって、単一のビットマスクを維持します$S$。 アップデートの場合は調整が必要です$S$要素が変更されたとき。 値が置き換えられた場合、その値がそれらのビットの最後の寄与者であった場合、一部のビットが OR から消える可能性があります。 これには、現在含まれている要素の数をビットごとに追跡する必要があります。 

ビット数に対してサイズ 30 の周波数配列を維持します。 要素を更新するときは、古い値のカウントをデクリメントし、新しい値のカウントをインクリメントします。 グローバル OR は、カウントが正になるとビットをセットし、ゼロになるとビットをクリアすることによって更新されます。 

一度$S$既知であれば、各クエリはカウントに減ります$x$そのような$$S \,|\, x \le z.$$これは古典的なビット制約カウントの問題です。 どこでも少しでも$S$1 がある場合、結果はすでに 1 になっています。$x$。 もし$z$その位置に 0 がある場合、それは不可能です。 それ以外の場合、それらのビットは強制されます。 ビットについては、$S$0があり、$x$によって課された制限内に留まらなければなりません$z$、そしてカウントは、次の位置でのみ自由に選択するように減少します。$z$1 と$S$有効な数は 0 です。$x$したがって、次のようになります。$$2^{\text{count of bits } i \text{ where } S_i = 0 \text{ and } z_i = 1}$$すべてのビットがどこにある場合$S_i = 1$満足する$z_i = 1$、それ以外の場合はゼロ。 

これにより、各クエリが次のように削減されます。$O(30)$。

 ## アルゴリズムのチュートリアル

 アクティブな配列を最初のものとしてのみ扱います$n$他の位置はゼロで無関係であるため、要素。 

1. 初期配列を読み取り、30 ビットの周波数配列を計算します。`cnt`どこ`cnt[b]`現在ビットを持っている数値の数です$b$セット。 これにより、配列をスキャンせずにグローバル OR を再構築できます。 
2. 初期 OR マスクを構築する$S$ビットを設定することで$b$もし`cnt[b] > 0`。 これにより、配列状態全体が 1 つの整数に圧縮されます。 
3. 更新クエリごとに$1\ i\ v$、位置の古い値を取得します。$i$。 ビットごとに$b$、古い値に設定されている場合はデクリメントします。`cnt[b]`。 次に、新しい値に対して、対応するビットをインクリメントします。 カウントを調整した後、影響を受けるビットのみを再計算します。$S$： 少し$b$に設定されています$S$もし`cnt[b] > 0`。 これにより、$S$常にすべての要素の真の OR を反映します。 
4. 各クエリについて$2\ z$、最初に実現可能性を確認します。$(S \& \sim z) \ne 0$、その後、いくつかのビットが必要になります$S$しかし禁止されている$z$、したがって答えはゼロです。 
5. それ以外の場合は、すべてのビットを反復処理します。$S$はゼロです。 そのようなビットごとに$b$、 もし$z$ビットがある$b$、それは無料であり、1 つの自由度に貢献します。 答えは$2^{k}$、 どこ$k$はそのような空きビットの数です。 

### なぜ効果があるのか

 アルゴリズムは不変条件を維持します。`cnt[b] > 0`ビットの場合に限り$b$少なくとも 1 つのアクティブな配列要素に存在します。 したがって、維持されたマスクは$S$は常に、現在のすべての要素の正確なビット単位の OR です。 

一度$S$は固定されており、各ビット位置は$x$独自に貢献しています。 少し定着しました$S$同じビットを強制的に挿入します$z$1であること。 そうでなければ解決策は存在しません。 ビットどこ$S$0 は下限を課さず、次によってのみ制約されます。$z$。 このような各ビットは自由に選択できるため、$x$、ビットの独立性により、純粋な 2 の累乗カウントが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    MAXB = 30
    cnt = [0] * MAXB
    
    for v in a:
        for b in range(MAXB):
            if v >> b & 1:
                cnt[b] += 1
    
    S = 0
    for b in range(MAXB):
        if cnt[b] > 0:
            S |= (1 << b)
    
    for i in range(n):
        pass  # placeholder; a is used directly
    
    for _ in range(int(input())):
        tmp = input().split()
        t = int(tmp[0])
        
        if t == 1:
            i = int(tmp[1]) - 1
            v = int(tmp[2])
            old = a[i]
            
            for b in range(MAXB):
                if old >> b & 1:
                    cnt[b] -= 1
                if v >> b & 1:
                    cnt[b] += 1
            
            a[i] = v
            
            S = 0
            for b in range(MAXB):
                if cnt[b] > 0:
                    S |= (1 << b)
        
        else:
            z = int(tmp[1])
            
            if S & ~z:
                print(0)
                continue
            
            free_bits = 0
            for b in range(MAXB):
                if not (S >> b & 1) and (z >> b & 1):
                    free_bits += 1
            
            print(1 << free_bits)

if __name__ == "__main__":
    solve()
```コア構造は、状態の維持をクエリの評価から分離します。 配列`cnt`ビットごとのプレゼンスを追跡しますが、`S`更新のたびにそこから再計算されます。 これにより、操作は純粋に OR ベースであるため、複雑なセグメント構造を維持する必要がなくなります。
