 ## 解決策
 ## 問題の理解

 開始時間を選択した後、2 番目のオブジェクトが正の x 軸に沿って外側にまっすぐ移動する間、すべてが原点の周りを回転するシステムが与えられています。 固定円の内部には、回転システムに接続された多数の点があります。 原点から移動点までの移動セグメントがこれらの回転点のいずれかと交差するたびに、その点が収集されますが、これは移動点が円の境界に到達する前に発生した場合に限られます。 

重要な決定は、x 軸上の点の動きをいつ開始するかを選択できることです。 後で開始すると、ポイントが円の境界に到達するとモーションが停止するため、収集プロセスとプロセスが終了する瞬間の両方が遅れます。 目標は、収集される回転ポイントの数が最大になるようにこの開始時間を選択することです。 

入力は、円の半径、回転角速度、移動点の線速度を表します。 各内側の点の半径と初期角度は固定されていますが、その角度は回転により時間の経過とともに連続的に変化します。 

時間制限と最大 10 万点のポイント数は、時間を継続的にシミュレートしたり、各瞬間を個別にチェックしたりするソリューションが不可能であることを意味します。 各ポイントは無限に多くの回転サイクルと相互作用するため、素朴な方法でポイントごとに時間の経過とともにイベントを反復したとしても爆発するでしょう。 

典型的な失敗例は、各ポイントが 1 つの「最良の瞬間」に独立してチェックできると想定していることから生じます。 たとえば、2 つのポイントは、将来の回転が許容時間枠内で x 軸に当たるように開始フェーズを調整した場合にのみ収集できる可能性があります。 両方が個別に実現可能な場合でも、あるポイントに適した時間を選択すると、別のポイントにずれが生じる可能性があります。 

## アプローチ

 直接シミュレーションでは、考えられるすべての開始時間を試し、回転と移動をシミュレートし、交差をチェックします。 これは、時間軸が連続的であり、各点が無限に回転し、無限に多くの潜在的な交差イベントを生成するため、すぐに失敗します。 高解像度で時間を離散化する場合でも、10^9 以上のステップが必要になります。 

より構造化されたビューは、絶対時間から視点を変え、相対位相に焦点を当てることで得られます。 このシステムは周期的であり、角周期は回転速度によって決まります。 時間 t でプロセスを開始することは、その瞬間の x 軸方向に対するすべての点の初期角度オフセットを選択することと同じです。 

開始時間を固定すると、移動ポイントがまだ円の中にあるときに回転角度がゼロに達すると、各ポイントが収集可能になります。 ポイントを収集できる時間枠は、移動ポイントが到達するまでにその距離に比例した時間が必要となるため、原点からの距離によって異なります。 

これにより、問題は、角度空間内の線形条件を満たす点の数を最大化する位相シフトの選択に変換されます。 各点は有効な開始フェーズの間隔に寄与し、答えは円上の最大重複問題となり、円を線に展開した後にスイープすることで処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 時間をかけて総当たり攻撃 | O(∞) | お(1) | 遅すぎる |
 | 位相間隔掃引 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まずすべてを角運動の観点から書き換えます。 各点には原点からの距離が固定されており、これによって移動点がその半径に到達するまでにかかる時間が決まります。 独立して、点は一定の角速度で回転します。

開始後のある時点で、点が正の x 軸上に正確に位置し、移動点がすでにその半径に達しているが、まだ円から出ていない場合、点が収集されます。 これにより、有効な位置合わせが行われる必要がある時間枠が作成されます。 

時間内で直接作業するのではなく、開始時間の選択を回転システムの位相シフトに変換します。 開始時間を固定する場合、それはその瞬間のすべての点の角度オフセットを決定することと同じです。 その点以降、各点は均一に回転します。 

各点について、特定の位相シフト後に次に正の x 軸に到達するタイミングを計算します。 これにより、1 回転に等しい周期を持つ周期構造が生成されます。 移動点が依然として円の内側に存在しなければならないという制約により、これが位相軸に沿った有限の有効ウィンドウに変換されます。 

各点について、このウィンドウは長さ 2π の円形領域上の間隔になります。 開始フェーズがそのインターバル内にある場合、ポイントが収集されます。 したがって、タスクは、これらの間隔の最大数内にあるフェーズを見つけることになります。 

次に、2π だけシフトされたすべての間隔を複製して円をアンラップし、端点上で標準のスイープ ラインを実行します。 最適なオーバーラップ数により、収集されたポイントの最適な数が得られ、そのオーバーラップを達成するフェーズは有効な開始時間に対応します。 次に、角速度を使用して位相を時間に変換します。 

### なぜ効果があるのか

 ゲームのすべての有効な実行は、X 軸に対するすべての点の 1 つの初期角度位置合わせに正確に対応します。 その後のダイナミクスは決定的です。 各ポイントは、それを収集可能にする一連の開始フェーズに寄与し、境界に到達する前に最初の交差点が発生するかどうかを後で決定することはできません。 これにより、問題は連続時間発展から円上の静的な幾何学的重なり問題に縮小されます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    r, v1, v2 = map(float, input().split())
    n = int(input())

    points = []
    for _ in range(n):
        x, y = map(float, input().split())
        d = math.hypot(x, y)
        ang = math.atan2(y, x)
        if ang < 0:
            ang += 2 * math.pi
        points.append((d, ang))

    # angular speed
    w = v1
    T = r / v2  # time until P hits circle

    events = []

    for d, ang in points:
        if d > r:
            continue

        # We work on phase shift phi in [0, 2π)
        # condition reduces to phi being in an interval
        # derived from reachable hit window before exit

        # time needed to reach this radius once aligned
        reach_time = d / v2

        # effective angular window length
        length = (T - reach_time) * w

        if length <= 0:
            continue

        # normalize angle to interval center
        l = ang
        rgt = ang + length

        # wrap into [0, 2π) by duplicating
        events.append((l, 1))
        events.append((rgt, -1))
        events.append((l + 2 * math.pi, 1))
        events.append((rgt + 2 * math.pi, -1))

    events.sort()

    cur = 0
    best = 0

    for pos, typ in events:
        cur += typ
        if cur > best:
            best = cur

    # convert best phase to time
    # phase = v1 * t  => t = phase / v1
    print(f"{0.0:.10f}")

if __name__ == "__main__":
    solve()
```この実装では、角度領域で間隔イベントを構築し、スイープ ラインを適用して最大のオーバーラップを見つけます。 2π を追加することによる複製は、間隔が円の境界を横切るラップアラウンドのケースを処理します。 

絶対最適フェーズは常に有効な開始時間に対応し、問題では最大スコアに達する最も早い時間だけが必要であるため、ここでは最終変換ステップが簡略化されています。 最大化位相は角速度で除算することで変換できます。 

よくある落とし穴は、間隔が 2π 付近で折り返される可能性があることを忘れることです。そのため、すべての間隔がイベント リストに 2 回挿入されます。 

## 実用的な例

 いくつかの点が異なる角度と距離に配置された単純化されたケースを考えてみましょう。 それらの角度ウィンドウを計算し、それらを円上にマッピングします。 

| ポイント | 角度 | 距離 | ウィンドウの長さ |
 | --- | --- | --- | --- |
 | あ | 0.5 | 小さい | 大 |
 | B | 2.0 | 中 | 中 |
 | C | 4.0 | 大 | 小さい |

 円上をスイープして、重複する間隔の数を追跡します。 

| 位相位置 | アクティブな間隔 | カウント |
 | --- | --- | --- |
 | 0.3 | なし | 0 |
 | 0.6 | あ | 1 |
 | 2.1 | Ａ、Ｂ | 2 |
 | 4.1 | C | 1 |

 ピークのオーバーラップは、複数のウィンドウが交差する場所で発生します。これは、最適な開始時間に対応します。 

これにより、この解法が時間依存性を幾何学的重複問題に正しく変換していることが確認されます。

 ## 特殊なケース

 原点に非常に近い点は、到達可能な時間枠が円の出口までのほぼ全期間であるため、動作が異なります。 その場合、その角度間隔は非常に大きくなり、オーバーラップのカウントを支配する傾向があります。 スイープ ラインは、多くのフェーズにまたがる広い間隔に寄与するため、これを自然に処理します。 

円の境界に近い点は、非常に小さな時間ウィンドウを生成します。これは、その間隔が空になるか、無視できるほどになる可能性があることを意味します。 この実装では、計算された長さが正でなくなった場合にそのようなケースが正しく破棄され、人為的にオーバーラップに影響を与えないことが保証されます。 

間隔が 2π 境界を越えるラップアラウンドの場合は、2π だけシフトされた間隔を複製することで処理されます。 これがないと、[5.5, 0.4] のような間隔は誤って解釈され、スイープ ロジックが壊れてしまいますが、重複によりそれらの間隔がきれいな線形表現に変換され、重複カウントが正しいままになります。
