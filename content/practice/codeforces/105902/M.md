 ## 問題の理解

 いくつかの特別な着地点を持つラインが与えられ、それぞれの着地点は開始位置からある程度の距離にあります。 KP は位置 0 から開始し、これらのポイントの最も遠いところに到達したいと考えています。 

移動は 2 つの方法で行われます。 通常のジャンプは常に正確に移動します`x`数メートル前進するだけで、費用はかかりません。 必殺技の動きが正確に動く`y`メートル前進しますが、スキルの使用を 1 回消費します。 KP は、すべての動きがライン上で前進し続ける限り、これらの動きを任意の順序で組み合わせることができます。 

目標は、すべてのポイントを訪問することではなく、KP がすべての指定された位置の中で最も遠いポイントに正確に着地できるかどうかを判断すること、そして着地できた場合、高価なスキルの使用回数を最小限に抑えることだけです。 

この制約は、ポイントの数は少ないですが、距離は最大 100 万まで大きくなる可能性があることを示しています。 これは、最終的な到達可能性の問題では最大座標のみが重要であるため、足場のすべてのサブセットを反復処理したり、足場ごとにパスをシミュレートしたりする必要がないことを直ちに示唆しています。 コアの計算は、その最大値に基づいた純粋な算術演算です。 

KP がすべての足場に順番に着地しなければならないと考えるのは単純な間違いです。 たとえば、ポイントが次のような場合`3 10 20`そして`(x, y) = (6, 7)`すべてのポイントを順番に訪問することを強制しようとするかもしれませんが、問題は到達することだけを考慮します。`20`。 

別の微妙な失敗例が現れるのは、`x`または`y`はゼロです。 もし`x = 0`, KPはスキルを使用してのみ移動できます。 もし`y = 0`, KPは通常ジャンプしか使えません。 これらのケースを同じ一般的な式で扱うと、除算エラーや不正確なモジュラー チェックが発生する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは、目標距離に到達するか、目標距離を超えるまで、考えられるすべての一連の動きをシミュレートすることです。 各状態は現在の位置であり、そこから次のいずれかに分岐します。`x`または追加`y`。 私たちは、費やしたスキルの使用回数を追跡し、目標に到達したときにそれを最小限に抑えるように努めます。 これはプロセスを正確にモデル化していますが、各ステップが 2 つの可能性に分岐し、位置が最大 100 万に及ぶ可能性があるため、到達可能な位置の数は急速に増加します。 多くの異なるシーケンスが異なるコストで同じ位置に到達するため、重複を枝刈りしても依然として大きな状態空間が残ります。 

重要な観察は、動きの順序は重要ではないということです。 有効なパスは、通常のジャンプを使用した回数とスキルを使用した回数によって完全に説明されます。 使用する場合`a`通常のジャンプと`b`スキル使用、最終位置は正確に`a * x + b * y`。 問題は、足場の最大距離を見つけるかどうかに帰着します。`D`その形式で表すことができ、その場合は最小化されます。`b`。 

これにより、問題はグラフ検索から 1 つの変数に対する単純な算術実行可能性チェックに変換されます。 パスを探索する代わりに、可能なスキル使用回数を繰り返し、残りの距離が次の数で割り切れるかどうかを確認します。`x`。

 ## アルゴリズムのチュートリアル

 まずターゲットの距離を特定します`D`, これはすべての足場の中で最大です。 

1. もし`x`がゼロの場合、スキルなしでは移動できません。 この場合、到達できるのは次の倍数の位置のみです。`y`。 かどうかを確認します`D`で割り切れます`y`。 「はい」の場合、答えは次のとおりです`D // y`、そうでないと無理です。 
2. もし`y`がゼロの場合、スキルの移動は進行に何の役にも立ちません。 サイズのジャンプのみを使用します`x`。 かどうかを確認します`D`で割り切れます`x`。 「はい」の場合、答えは次のとおりです`D // x`、そうでないと無理です。 
3. 両方の場合`x`そして`y`ポジティブであることを表現しようとします`D`として`a * x + b * y`。 可能な値を反復処理します。`b`、ゼロから始まり、各単位は`b`コストは直接増加するため、最小限に抑えたいと考えています。 
4. 各候補者について`b`、残りの距離を計算します`D - b * y`。 これがマイナスになると、さらに増加するため停止します。`b`悪化させるだけです。 
5. 残りの距離が負ではなく、次の値で割り切れる場合`x`を使用して構築を完了できます。`a = (D - b * y) / x`、そして現在`b`は有効な答えです。 
6. そうでない場合`b`が見つかった場合、ターゲットには到達できません。 

正確さは、すべての有効なパスがペアに正確に対応するという事実に基づいています。`(a, b)`負でない整数。 どちらの操作もライン上の純粋な加算ステップであるため、一連の移動は最終位置を変更せずに並べ替えることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x, y = map(int, input().split())
    arr = list(map(int, input().split()))
    D = max(arr)

    if D == 0:
        print(0)
        return

    if x == 0 and y == 0:
        print(-1)
        return

    if x == 0:
        if D % y == 0:
            print(D // y)
        else:
            print(-1)
        return

    if y == 0:
        if D % x == 0:
            print(0)
        else:
            print(-1)
        return

    best = None
    max_b = D // y

    for b in range(max_b + 1):
        rem = D - b * y
        if rem < 0:
            break
        if rem % x == 0:
            best = b
            break

    print(best if best is not None else -1)

if __name__ == "__main__":
    solve()
```中間の足場は実現可能性に影響を与えないため、このソリューションでは最初に最も遠いターゲットを抽出します。 ステップ サイズの 1 つがゼロである特殊なケースは、無効な算術演算を回避し、使用できる動作タイプが 1 つだけであることを反映するために、個別に処理されます。 

メインループはスキルの使用回数を列挙します。 このループは安全です。スキルの使用回数を増やすと残りの距離が確実に減少するため、最初に見つかった有効な解決策が自動的に最適化されます。

 ## 特殊なケース

 両方のとき`x`そして`y`がゼロの場合、まったく移動できません。 アルゴリズムは除算が発生する前にこれを明示的に拒否し、無効な算術演算を防ぎます。
