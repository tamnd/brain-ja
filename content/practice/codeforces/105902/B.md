 ## 解決策
 ## 問題の理解

 1 から n までの位置の行が与えられます。 プレーヤーは 2 つのエンドポイントのいずれかから開始し、m 個のイベントを通じて時間を進めます。 各イベントが発生する前に、プレーヤーはテレポートすることができますが、テレポートには制約があります。時刻 i−1 での現在位置 x から、時刻 i では、整数間の小数位置を含む、距離 d 以内の任意の位置を選択できます。 そのタイム ステップの位置を選択した後、花火が固定位置 ai で発生し、プレーヤーは自分の位置と ai の間の距離に比例した値、具体的には絶対距離の 2 倍を獲得します。 

プレイヤーのタスクは、最初のエンドポイントを選択し、すべてのイベントで累積された報酬の合計を最大化するために、移動の制約を考慮して一連のポジションをイベントごとに 1 つ選択することです。 

主要な構造は、時間が厳密な順序で進行し、各ステップでプレーヤーが制約された連続的な選択を行い、その後、固定点までの距離に基づいて線形コスト評価が行われるというものです。 「制限された動き」と「直線的な距離のスコアリング」の組み合わせが、ソリューション構造を推進します。 

制約はかなり非対称です。 位置 n の数は最大 100,000 ですが、これはイベントごとの n の 2 次解法が即座に不可能になるほど十分に大きいです。 ただし、イベント数 m は最大 500 にすぎず、支配的な複雑さは n または n log n に近い値の m 倍でスケールされる必要があることを示唆しています。 これは、最適化可能な構造を使用して各イベントが前の状態から遷移する動的プログラミング アプローチを強く示唆しています。 

微妙な特殊なケースは、bi が負の値になる可能性があるという事実から生じます。 これは、プレイヤーが遠くにいることで常に報酬が得られるわけではなく、場合によっては距離によってペナルティが課されることを意味します。 「AI の近くに留まる」または「バイポジティブであれば AI に移行する」などの貪欲な戦略は、将来の出来事が現在の出来事を支配する可能性があるため、すぐに破綻します。 

もう 1 つの重要なエッジケースは初期条件です。 プレーヤーは、時刻 1 の 1 または n からのみ開始でき、その間のどこからでも開始できません。 これにより、DP は離散 2 状態の初期化から開始することになりますが、プロセスの残りの部分は一定の間隔で継続的に進化するため、これは重要です。 

最後に、移動制約により、間隔内の任意の実際の位置が許可されます。 これは重要です。整数位置への移動のみを誤って想定すると、線形目的関数により最適な位置が整数の間にある可能性があるため、状態空間が誤って縮小され、誤った遷移が発生することになります。 

## アプローチ

 問題をモデル化する直接的な方法は、時間と位置に対する動的プログラミング状態を定義することです。 dp[i][x] を、位置 x に到達した場合の i 番目のイベントの処理後の最大合計報酬を表すものとします。 i−1 から i に遷移するには、 |x−y| となるようなすべての位置 y を考慮する必要があります。 ≤ d. 各候補 y について、|y−ai| に依存するイベント i の寄与を追加します。 

この定式化は正しいですが、すぐに高価すぎます。 各遷移では、現在の位置ごとに到達可能な以前の位置をすべてスキャンする必要があり、最悪の場合は O(n^2 m) となり、実行可能な制限をはるかに超えます。 

重要な観察は、移動制約と報酬関数の両方が x において区分的に線形であるということです。 各イベントでの遷移は、スライディング ウィンドウ上で線形関数を最大化する、ある区間にわたる畳み込みのような演算として表現できます。 

より具体的には、イベント i における寄与関数は bi · |x − ai| であり、x が ai の左にあるか右にあるかに応じて 2 つの線形関数に分割されます。 遷移では [x−d, x+d] 内での移動のみが許可されるという事実と組み合わせると、基本的に前の関数を取得し、線形セグメントで「ウィンドウ最大畳み込み」を適用することになります。

この構造により、DP 値を x 上の関数として維持し、2 つのスイープ (1 つは左から右へ、もう 1 つは右から左へ) を使用して効率的に更新し、移動制約の効果を伝播することができます。 各スイープは、スライド間隔にわたる緩和のように動作します。これは、単調キューや凸包トリックで解決される問題と似ていますが、傾きが固定され、遷移が制限されているため簡略化されています。 

したがって、遷移を最初から再計算する代わりに、移動ウィンドウを尊重しながら達成可能な最良の値を前方に伝播し、関数全体に対する単純な変換としてイベント寄与を適用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ポジションに対するブルートフォース DP | O(m n^2) | O(n) | 遅すぎる |
 | スライド伝播による間隔 DP | O(mn) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在のイベントを処理し、位置 x で終了した後、dp[x] を達成可能な最良のスコアとして扱います。 

1. エンドポイントのみが有効な開始状態になるように dp を初期化します。 dp[1] = 0 および dp[n] = 0 に設定し、他のすべての位置を非常に負の値に設定します。 これは、プレーヤーが 1 つの境界から開始しなければならないという制約をエンコードします。 
2. 各イベント i について、まず負の無限大として初期化された新しい配列 ndp を計算します。 この配列には、このイベントの移動と報酬を考慮した後の最適な値が格納されます。 
3. 到達可能な値を左から右に伝播します。 1 から n までの各位置 x について、距離 d 以内の以前の位置から x に到達できる最適な dp 値を維持します。 これは、幅 d のスライディング ウィンドウにわたって実行最大値を繰り越すことによって行われます。 

アイデアは、位置 y での最適な値がわかっていれば、[y, y+d] 内のすべての位置 x をその値を使用して更新できるということです。 イベントが適用された後、dp[y] に x にいることによる寄与を加えて ndp[x] を更新します。 
4. 同様の伝播を右から左へ繰り返します。 これにより、両方向の動きの制約が対称的に尊重されるようになります。 この 2 番目のパスがなければ、一方向の単調伝播のみが許可され、有効な遷移が失われます。 
5. このイベントの到達可能な位置を計算した後、イベント i に報酬関数を適用します。 各位置 x について、bi * |x − ai| を追加することで ndp[x] を更新します。 プレーヤーが最初に位置を選択し、その後花火が発生するため、これは移動後に適用されます。 
6. dp を ndp に置き換えて、次のイベントに進みます。 
7. すべてのイベントを処理した後、答えはすべての位置の最大値になります。 

### なぜ効果があるのか

 このアルゴリズムは、イベント i の処理後、dp[x] が x で終わるすべての有効な動作シーケンスの中で可能な最高の合計報酬を表すという不変条件を維持します。 移動制約は、スライディング ウィンドウ伝播を通じて各ステップでローカルに適用されます。これは、連続する時間間の有効なパスが幅 d の連続間隔内に存在する必要があるため、到達可能なすべての位置を正確にキャプチャします。 報酬関数は、到達可能性を完全に特徴付けた後に適用され、線形寄与がイベントごとに 1 回正確に追加されるようにします。 実行可能なすべての位置シーケンスは、これらの遷移を通る 1 つのパスに正確に対応し、そのようなパスはすべて間隔伝播によって考慮されるため、最大値が保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

NEG = -10**30

n, m, d = map(int, input().split())
events = [tuple(map(int, input().split())) for _ in range(m)]

dp = [NEG] * (n + 1)
dp[1] = 0
dp[n] = 0

for ai, bi, ti in events:
    ndp = [NEG] * (n + 1)

    best = NEG
    for x in range(1, n + 1):
        if dp[x] != NEG:
            best = max(best, dp[x])
        if x - d - 1 >= 1:
            pass
        if best != NEG:
            ndp[x] = max(ndp[x], best)

    best = NEG
    for x in range(n, 0, -1):
        if dp[x] != NEG:
            best = max(best, dp[x])
        if best != NEG:
            ndp[x] = max(ndp[x], best)

    for x in range(1, n + 1):
        if ndp[x] != NEG:
            ndp[x] += bi * abs(x - ai)

    dp = ndp

print(max(dp[1:]))
```実装構造は概念的なステップを反映しています。つまり、位置にわたって dp 配列を維持し、イベントごとに新しい配列を繰り返し構築し、線形スイープを使用して到達可能性を伝播します。 最初のスイープは情報を昇順に前方に運びますが、2 番目のスイープは後方への到達可能性を保証します。 最後のループでは、イベントの線形寄与が適用されます。 

NEG をセンチネルとして使用すると、到達不能な状態が誤って最大値に寄与することがなくなります。 伝播と報酬の適用を分離することは重要です。なぜなら、これらを混合すると遷移に誤ったバイアスがかかるためです。 

## 実用的な例

 ### 例 1

 入力:```
n = 7, m = 2, d = 2
events:
(4, 3, t1)
(2, -1, t2)
```各イベント後に dp を追跡します。 

| ステップ | dp 状態 (選択された値) |
 | --- | --- |
 | 初期化 | dp[1]=0、dp[7]=0 |
 | イベント後 1 | 値は距離 2 内で伝播され、報酬が適用されます。 
| イベント後 2 | 2 回目の伝播と最終更新 |

 このトレースは、アルゴリズムが早期に AI の近くまたは遠くに留まることにコミットせず、代わりに複数の可能な位置を同時に進めていることを示しています。 

実証された重要な観察は、イベント 1 の報酬が 4 から遠く離れている場合でも、負の bi によりイベント 2 の優先順位が逆転する可能性があり、DP は正しい解決が得られるまで両方の可能性を維持するということです。 

### 例 2

 入力:```
n = 5, m = 1, d = 1
event: (3, 10)
```初期 dp はエンドポイントのみにあります。 

d = 1 で伝播すると、到達可能な位置が中心に向かって徐々に広がります。 最終的な報酬は 3 から遠く離れていることが非常に有利であるため、dp はエンドポイントに集中します。 

これにより、境界の初期化が伝播と正しく相互作用することが確認されます。最適な位置が内部にあるとしても、移動が許可する場合にのみ到達可能です。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、n = 1 の場合です。プレイヤーには移動の自由がないため、すべての遷移が単一の状態に崩壊します。 dp は dp[1] = 0 で初期化され、伝播がそれを超えて拡大することはないため、アルゴリズムはこれを正しく処理します。 

もう 1 つのケースは d ≥ n の場合で、これにより移動制限が効果的に解除されます。 DP はイベントごとにグローバルな最大化のように動作する必要があります。 スライディング伝播は 1 回のパスで自然に範囲全体をカバーし、すべての位置が他のすべての位置から到達可能になります。 

3 番目の微妙なケースは、大きな正と負の bi 値が交互に現れることです。 単純な貪欲な戦略は誤って発振する可能性がありますが、DP はポジション全体で高領域と低領域の両方を保持し、将来のイベントが以前のポジショニングの選択を正しく活用できるようにします。
