 ## 解決策
 ## 問題の理解

 同じタスクを完了するための 3 つのルートまたは計画の候補が与えられ、それぞれに時間コストが関連付けられています。 目的は、3 つのオプションの中から最も速いオプションを選択し、その時間を出力することだけです。 

各入力は、正確に 3 つの整数で構成されます。 これらは、同じ副問題を解決するための 3 つの競合する戦略と考えることができ、各戦略には既知の固定コストがあります。 タスクは、これら 3 つの値のうち最小のものを選択し、それを出力することになります。 

制約は非常に小さく、各値は 1 ～ 60 です。これにより、不必要に重いものであっても、あらゆるソリューションが一定時間で実行されることがすぐに分かります。 前処理、大きな構造のソート、繰り返しの計算は必要ありません。 各値を 1 回でも検査するアルゴリズムは、すでに最適化されています。 

シーケンスや範囲に関連する難しい構造上のエッジケースはありませんが、このタイプの問題でよく現れる正確性に関する微妙な懸念が 1 つあります。それは、等価性が正確性に影響を与えないようにすることです。 2 つ以上の値が等しく最小である場合、それらのいずれかが有効であるため、実装では、一意性を前提とした厳密な比較または早期終了により、有効な最小候補を誤って破棄してはなりません。 

たとえば、入力が次の場合、`1 1 45`、最初の 2 つのオプションはどちらも最適です。 正しい解決策は依然として出力される必要があります`1`。 バグのあるアプローチでは、誤って一意の最小値を想定し、等しい値をスキップする可能性がありますが、ここでは等しいことが正確さの一部です。 

## アプローチ

 直接的なアプローチは、3 つの値を手動で比較することです。 一連の比較によって、3 つのうちのどれが最も小さいかを確認できます。 たとえば、最初の値が答えであると仮定して開始し、次にそれを 2 番目の値と比較し、必要に応じて更新し、その後 3 番目の値と再度比較することができます。 入力サイズは固定されているため、これで十分です。 

これが機能するのは、問題が本質的に 3 つの要素のセットの最小値を計算することであるためです。 値間に依存関係はなく、変換も必要なく、選択のみが必要です。 

3 つの値を並べ替えて最初の要素を取得するなど、より一般的なアプローチを検討することもできます。 これも機能しますが、このような小さな固定サイズの入力の推論と実装の両方で不要なオーバーヘッドが発生します。 3 つの要素にわたるループも有効ですが、やはりサイズが一定の構造体にとっては不必要な複雑さになります。 

重要な観察は、構造が固定されており、小さいことです。 ブルート フォースと最適解の複雑さは事実上同じです。 唯一の違いは明瞭さと直接性です。

 ## アルゴリズムのチュートリアル

 1. 入力から 3 つの整数を読み取ります。 これらは 3 つの候補計画のコストを表します。 
2. 変数を初期化する`ans`最初の値を使用します。 これにより、デフォルトで有効なベースライン候補が得られます。 
3. 比較する`ans`2 番目の値を使用します。 2 番目の値が小さい場合は更新します`ans`2 番目の値に。 これにより、これまでに確認された最良のオプションを常に維持できるようになります。 
4. 比較する`ans`3 番目の値を使用します。 3 番目の値が小さい場合は更新します`ans`また。 これにより、3 つの値すべてを処理した後、`ans`すべての候補の最小値を保持します。 
5. 出力`ans`。 

### なぜ効果があるのか

 すべてのステップで、変数は`ans`これまでに処理されたすべての要素の最小値を格納します。 最初のステップの後、それは最初の要素の最小値になります。 2 回目の比較の後、最初の 2 つの要素の最小値になります。 3 回目の比較の後、それは 3 つの要素すべての最小値になります。 この不変条件により、すべての候補が現在の最良のものと明示的に比較されるため、より小さい値が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a, b, c = map(int, input().split())

ans = a
if b < ans:
    ans = b
if c < ans:
    ans = c

print(ans)
```このソリューションは、1 行で 3 つの整数を読み取り、変数に格納します。 変数`ans`有効な開始点を確立するために、最初の値で初期化されます。 後続の各比較の更新`ans`厳密に小さい値が見つかった場合にのみ、値が等しい場合でも正確性が維持されます。 

条件では使用されるため、等しい値に対して特別な処理は必要ありません。`<`それよりも`<=`これにより、正確さに影響を与えることなく、最初に遭遇したものが自然に最小限に保たれます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    a, b, c = map(int, input().split())
    ans = a
    if b < ans:
        ans = b
    if c < ans:
        ans = c
    return str(ans)

# provided samples
assert run("14 12 18") == "12", "sample 1"
assert run("1 1 45") == "1", "sample 2"

# custom cases
assert run("1 2 3") == "1", "increasing order"
assert run("3 2 1") == "1", "decreasing order"
assert run("5 5 5") == "5", "all equal"
assert run("60 1 60") == "1", "minimum in middle"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 2 3 | 1 | 昇順の正確性 |
 | 3 2 1 | 1 | 逆順の正しさ |
 | 5 5 5 | 5 | 等価性の処理 |
 | 60 1 60 | 1 | 中間位置の最小値 |

 ## 特殊なケース

 ### すべての値が等しい

 入力:`7 7 7`アルゴリズムは次から始まります`ans = 7`、次に 2 番目と 3 番目の値と比較します。 どちらも厳密には小さいため、どちらの更新もトリガーされません。 最終出力はそのまま残ります`7`すべてのオプションが同等であるため、これは正しいです。 

### さまざまな位置での最小値

 入力:`9 2 8`アルゴリズムは最初に設定します`ans = 9`。 その後、次のように更新されます`2`2 番目の値と比較した後。 3 回目の比較では変化しません。 出力`2`位置に関係なくグローバル最小値を正確に反映します。 

### 厳密に降順

 入力:`10 6 1`アルゴリズムは段階的に更新されます`ans`各ステップで、繰り返される改善が正しく処理されていることを実証します。 最終結果`1`早期に決定を下さなければ、後の修正が妨げられることを確認します。
