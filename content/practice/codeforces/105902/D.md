 ## 解決策
 ## 問題の理解

 一緒に旅行する 3 人が与えられ、各人が旅行中に一連の請求書を支払います。 各テスト ケースには、正の量の 3 つのリスト (1 人につき 1 つのリスト) が提供されます。 目標は、すべての送金の後、最終的に 3 人全員がまったく同じ合計金額を寄付するように、各ペアの間で資金を送金する方法を決定することです。 

入力は複数のテスト ケースとして構造化されています。 それぞれのケースで、浮動小数点値の 3 つの配列を読み取ります。 各配列の合計が、その人が支払った合計金額になります。 私たちが本当に気にするのは、個々の請求書ではなく、3 つの合計金額です。 

出力には、3 人の間の順序付きペアごとに 1 つずつ、合計 6 つの直接転送を記述する必要があります。 OC が KP に送信する量、OC から XW に送信する量、KP から OC に送信する量、KP から XW に送信する量、XW から OC に送信する量、そして XW から KP に送信する量を出力する必要があります。 これらの転送の数は最小限または最適である必要はありません。 等しい最終残高を達成する有効な再分配は受け入れられます。 送金金額は決してマイナスであってはなりません。つまり、指定された方向に流れる資金のみを明示的に指定します。 何も送信しない場合は、ゼロを出力します。 

テスト ケースあたり最大 1000、テスト ケース最大 100 個の制約 n、m、p は小さいです。 主な作業は浮動小数点数の読み取りと合計であるため、テスト ケースごとのソリューションは O(n + m + p) で十分です。 

主な微妙な点は浮動小数点の精度です。 値の小数点以下の桁数は最大 2 桁で、許容される絶対誤差は 1e-2 であるため、残高の符号が変化したり、ゼロであるはずのわずかに負の変換値が生成されたりするような丸め誤差の蓄積を避けるように注意する必要があります。 

エッジ ケースは、合計が浮動精度内ですでに等しいかほぼ等しい場合、1 人が何も支払わない場合、または 1 人がほぼ全額を支払う場合に発生します。 

たとえば、OC、KP、XW の合計がすべて同一の場合、すべての転送はゼロでなければなりません。 任意の丸めを使用して「ペアごとに分割」しようとする単純な解決策では、正確性を損なう 0.01 のような小さな非ゼロ転送が発生する可能性があります。 

もう 1 つのエッジ ケースは、1 人が 0 を支払い、他の人が全額を支払った場合です。 その場合、その人は他の人両方からお金を受け取らなければなりません。 浮動エラーにより計算された赤字がわずかに負になる場合、単純な実装では誤って負の転送や誤った方向を出力する可能性があります。 

## アプローチ

 直接的だが間違ったアプローチは、ペアごとの調整の観点から考えることです。つまり、各ペアについて、どちらがより多く支払ったかを計算し、その差額を直接解決しようとすることです。 これは、3 つすべてが同じ目標合計に達する必要があるというグローバル制約を無視しているため、すぐに矛盾します。 ペアごとのバランシングは推移性を保証するものではなく、すべての転送後に不均衡が残る可能性があります。 

正しい見方は、問題を 2 つの段階に分けることです。 まず全員の支払い総額の合計を計算します。 これから、合計を 3 で割った目標均等シェアを導き出します。 次に、この目標に対する各人の純残高を計算します。 プラスの残高は、その人がお金を受け取る必要があることを意味します。 マイナスの残高は、支払う必要があることを意味します。 

これら 3 つの正味価値が得られると、問題は 3 つのノード間での黒字から赤字への単純な再分配になります。 任意の送金が許可されており、運用を最小限に抑える必要がないため、固定の決定論的パターンで資金をルーティングすることができます。たとえば、すべての余剰金を最初に OC から KP に、次に XW に送金し、その他にも同様に送金することができます。 正味残高を尊重する構築はすべて有効です。 

重要な洞察は、構造が多数の個別の請求書からわずか 3 つの数字に崩壊し、潜在的に複雑な決済グラフから 3 つのノードと一定の総供給と需要によるフローの問題に崩壊するということです。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートペアワイズバランシング | O(n²) 概念的 / 一貫性がない | お(1) | 不正解 |
 | 合計 + 純残高の構築 | O(n + m + p) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 テストケースごとに作業します。 

1. 各人が支払った合計金額を個別に計算します。 OC のリスト、KP のリスト、XW のリストのすべての値を合計します。 これにより、入力が 3 つの配列から 3 つのスカラーに減ります。 
2. 3 つの合計を加算して総計を計算します。 これは、システムで費やされた全額を表します。 
3. 総計を 3 で割った目標シェアを計算します。これは、各人が実際に支払わなければならない金額です。 
4. 各人について、支払額から目標額を差し引いた純残高を計算します。 正の値は、支払いが過剰であり、お金を受け取る必要があることを意味します。 負の値は、支払いが不足しているため、送金する必要があることを意味します。 
5. 次に、ペア間の転送を構築します。 私たちは単純な貪欲な再分配を維持します。つまり、各ペア (A、B) について、A と B のネットバランスの比較に基づいて転送を割り当てます。 Aが過剰でBが不足の場合、A→Bはmin(過剰、-不足)の量です。 それに応じて、残りの不均衡を軽減します。 これをペアの固定順序で繰り返し、すべての不均衡が解消されます。 
6. 6 つの有向転送を必要な順序で出力します。 

これが機能する理由は、過剰の合計が赤字の合計と等しいため、黒字のすべての単位が赤字の単位と一致する必要があるためです。 ノードが 3 つしかないため、黒字と赤字のペア間の貪欲なマッチングで十分です。 

### なぜ効果があるのか

 どの時点でも、すべての人々の残りの純残高の合計がゼロであることが不変です。 転送のたびに、この不変条件が維持されたまま、1 つのプラスの残高と 1 つのマイナスの残高が同じ量だけ減ります。 常に利用可能な黒字または赤字の範囲内でのみ転送するため、オーバーシュートすることはありません。 最終的にはすべての残高がゼロになります。これは、すべての人が目標のシェアに正確に到達したことを意味します。 トランザクション数を最小限に抑えることには制約されず、実現可能性を達成することのみに制約されるため、転送の順序は重要ではありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, p = map(int, input().split())

        a = list(map(float, input().split())) if n else []
        b = list(map(float, input().split())) if m else []
        c = list(map(float, input().split())) if p else []

        sa = sum(a)
        sb = sum(b)
        sc = sum(c)

        total = sa + sb + sc
        target = total / 3.0

        bal = [sa - target, sb - target, sc - target]

        # balances: positive = should receive, negative = should pay
        # we will build transfer matrix trans[i][j]
        trans = [[0.0] * 3 for _ in range(3)]

        # greedy settlement among 3 people
        for i in range(3):
            for j in range(3):
                if bal[i] > 1e-12 and bal[j] < -1e-12:
                    x = min(bal[i], -bal[j])
                    trans[j][i] += x
                    bal[i] -= x
                    bal[j] += x

        print(f"{trans[0][1]:.2f} {trans[0][2]:.2f} {trans[1][0]:.2f} {trans[1][2]:.2f} {trans[2][0]:.2f} {trans[2][1]:.2f}")

if __name__ == "__main__":
    solve()
```このソリューションは、各人の支払いを合計することから始まり、入力全体が 3 つの値に圧縮されます。 グローバル目標を計算した後、各人の公平性からの逸脱は次の場所に保存されます。`bal`。 正のエントリはその人が受け取るべきお金を表し、負のエントリは送金すべきお金を表します。 

転送マトリックス`trans[i][j]`iからjへ流れるお金を蓄えます。 ネストされたループは、利用可能な余剰と不足を貪欲に照合します。 イプシロンしきい値は、ゼロ付近の浮動小数点ノイズによる不安定性を回避します。 

最後に、出力では、必要な 6 つの有向エッジが指定された順序どおりに印刷されます。 

## 実用的な例

 OC が 100、KP が 50、XW が 50 を支払った単純なケースを考えてみましょう。 

合計は 200 なので、目標は 66.6667 です。 OCは+33.3333、KPとXWはそれぞれ-16.6667です。 

| ステップ | OCバランス | KPバランス | XWバランス | 転送 |
 | --- | --- | --- | --- | --- |
 | 開始 | +33.33 | -16.67 | -16.67 | なし |
 | OC→KP | +16.66 | 0 | -16.67 | 16.67 |
 | OC→XW | 0 | 0 | 0 | 16.66 |

 これは、OC がすべての残高がゼロになるまで余剰を他の両方に分配することを示しています。 

次に、完全にバランスの取れたケース、OC = 30、KP = 30、XW = 30 を考えてみましょう。 

| ステップ | OCバランス | KPバランス | XWバランス | 転送 |
 | --- | --- | --- | --- | --- |
 | 開始 | 0 | 0 | 0 | なし |

 転送は作成されず、出力はすべてゼロになります。 これにより、不均衡が存在しない場合、アルゴリズムが人為的な動きを導入しないことが確認されます。

 ## 特殊なケース

 3 人全員がまったく同じ合計額を支払う場合、計算される目標は各個人の合計額と等しくなります。 バランス配列はすべてゼロになるため、貪欲ループは転送をトリガーしません。 出力は 6 つのゼロであり、要件と一致します。 

1 人がすべてを支払う場合、たとえば OC が 100 を支払い、他の人が 0 を支払う場合、目標は 33.33 になります。 OC の残高はプラス、その他はマイナスです。 貪欲マッチングでは、両方の不足が満たされるまで、最初に OC → KP、次に OC → XW が送信されます。 常にバランスを保ったままクランプするため、マイナスの転移は生じません。 

浮動小数点値によって小さな丸め誤差が生じる場合 (残高が 0 ではなく 1e-15 になるなど)、イプシロン チェックによって偶発的な転送が防止されます。 このガードがないと、アルゴリズムは非常に小さな値を移動させようとし、不安定な出力を生成する可能性があります。
