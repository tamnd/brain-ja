 ## 問題の理解

 一連の木の高さが与えられています。 私たちは正確に実行しなければなりません$s$各操作により、正確に 1 つのツリーの高さが 1 単位ずつ減ります。 すべての操作を行った後、カットをどのように分散するかに応じて、一部の木は依然として正の高さを持ち、他の木はゼロになるか、または正のままになる可能性があります。 

最終評価では、高さがゼロのすべてのツリーが無視されます。 残りの正の高さについては、標準的な統計的な意味での分散、つまり平均からの二乗偏差の平均を計算します。 

目標は、各ステップでどの木を伐採するかを選択することです。$s$合計の減少量に応じて、残りの正の高さの分散は可能な限り小さくなります。 

制約は大きく、最大で$2 \cdot 10^5$すべてのテスト ケースにわたるツリー$10^9$操作。 これにより、操作を 1 つずつシミュレートするアプローチは即座に排除されます。 平$O(s)$または$O(s \log n)$方法は不可能です。 段階的なシミュレーションではなく、全体的な構造の変化について推論する必要があります。 

このステートメントの微妙だが決定的な結果は、すべての$a_i > s$。 これにより、ツリーをゼロに減らすことができないことが保証されます。 カットをどのように分配するかに関係なく、すべての木はポジティブなままです。つまり、残りの木のセットは常に完全なセットになります。$n$木々。 これにより、変更の複雑さが解消されます。$k$、分散に寄与する要素の数。 分散は常に全体にわたって計算されます$n$要素。 

よくある間違いは、積極的に伐採すれば小さな木がなくなり、分散が減少するのではないかと考えることです。 ここでは、単一のツリーを完全に削除するのに十分な総カット数がないため、これは不可能です。 

## アプローチ

 最初の直感は、問題を動的に考えることです。各操作で 1 つの要素が減り、配列の「バランス」を維持しようとします。 自然な貪欲な考えは、常に現在の最大のツリーを削減することです。これは、大きな値を削減する方が、小さな値を削減するよりも効果的にスプレッドを削減する傾向があるためです。 これは正しいですが、直接実装すると遅すぎます。 

単純なシミュレーションでは、優先度キューを使用します。つまり、最大値を繰り返し抽出し、1 つずつ減らし、それを押し戻します。 これは正しいです。値が可能な限り等しい場合に分散が最小限に抑えられ、各減少は最大の要素に適用される場合に最も効果的に不均衡を軽減します。 ただし、これには次のことが必要です$s$ヒープ操作は実行不可能です$s = 10^9$。 

重要な点は、個々の減少をシミュレートする必要がないということです。 このプロセスは、それぞれの高さが別の高さに達するまでに何回減少するかによってのみ決まります。 操作の観点から考えるのではなく、高さの「レベル」の観点から考え、次のレベルと結合する前に最大レベルをどこまで下げることができるかを考えます。 

これにより、問題は、次の個別の値に到達するまで、値の最も高いブロックを繰り返し平坦化し、操作を一括で消費することに変わります。 残りのバジェットがレベルを完全に平坦化するには不十分な場合、残りの減分を現在の最大ブロック全体にできるだけ均等に分配します。 

すべてのリダクションが適用されると、合計が正確に減少するため、最終的な配列の平均は固定されます。$s$、ディストリビューションとは独立しています。 これは、分散を最小化することは、最終的な配列の二乗和を最小化することと同じであることを意味します。

 ## アルゴリズムのチュートリアル

 最大要素を繰り返し削減する効果を、集約された形式でシミュレートしたいと考えています。 

### 1. 同一の値を並べ替えてグループ化する

 まず、同じ高さをグループ化します。 これにより、配列を、それぞれが周波数を持つ一連の値ブロックとして扱うことができます。 

### 2. 値ブロックの最大構造を維持する

 ブロックは最も高い値から下に向かって処理されます。 いつでも、価値のある最も高いブロックを考慮します$v$そして数えます$c$。 

次に低い値と比較します$u$。 全部持っていくのにかかる費用$c$からの要素$v$まで$u$は$(v - u) \cdot c$。 

もし$s$十分な大きさなので、このブロックを完全に平らにします。$u$、カウントを結合して続行します。 

### 3. ハンドルの部分的な平坦化

 もし$s$完全に減らすには十分ではありません$v$に$u$、残りの操作を全体に分散します。$c$要素:

 私たちは計算します$s // c$、これは、上部ブロックの各要素を均一にどれだけ削減できるかを示します。 次に計算します$s \% c$これは、1 つの追加デクリメントを取得する要素の数を示します。 

これにより、いくつかの要素が高さにある最終的な分割が生成されます。$v - t$そして残りは$v - t - 1$。 

このステップの後は、すべての操作が使い尽くされるため、それ以上のグローバル マージは必要ありません。 

### 4. 最終的な二乗和を計算します。 

最終的な値がグループ化された形式で決定されたら、計算します。$\sum b_i^2$。 その場合、分散は次のようになります。$$\frac{1}{n} \sum b_i^2 - \left(\frac{\sum b_i}{n}\right)^2$$合計$\sum b_i$単純に$\sum a_i - s$, したがって、平均は固定されます。 

### なぜ効果があるのか

 すべてのステップで、常に現在の最大値グループに削減を適用します。これは、より大きな値を削減する方が、より小さな値を削減するよりも二乗和が減少するためです。 値を減少させる限界の変化$x$1によって$(x-1)^2 - x^2 = -2x + 1$、これは大きいほどマイナスになります。$x$。 これにより、最適な戦略では常に最大の要素が優先されることが保証され、貪欲な「最初に最高レベルを平坦化する」プロセスが最適化されます。 

グループが等しくなった場合にのみグループを圧縮するため、配列が常にソートされた値ブロックとして表現され、有益な再分配がスキップされないという不変条件が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, s = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort(reverse=True)

        # build value blocks: (value, count)
        blocks = []
        i = 0
        while i < n:
            j = i
            while j < n and a[j] == a[i]:
                j += 1
            blocks.append([a[i], j - i])
            i = j

        # merge downward
        k = 0
        while k < len(blocks) - 1 and s > 0:
            v, c = blocks[k]
            u, c2 = blocks[k + 1]

            gap = (v - u) * c

            if s >= gap:
                blocks[k + 1][1] += c
                s -= gap
                k += 1
            else:
                dec = s // c
                rem = s % c

                new_v = v - dec
                # split c into rem and c-rem
                blocks[k] = [new_v, c - rem]
                blocks.insert(k + 1, [new_v - 1, rem])
                s = 0
                break

        # compute variance
        total_sum = sum(v * c for v, c in blocks)
        mean = total_sum / n

        var = 0.0
        for v, c in blocks:
            var += c * (v - mean) * (v - mean)
        var /= n

        out.append(f"{var:.10f}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは、個々の要素ではなく周波数を操作できるように、同じ高さをブロックに圧縮することから始まります。 メイン ループは、最上位のブロックを次のブロックにマージしようと繰り返し試行し、操作を一括で消費します。 

操作が完全なマージを完了するには不十分な場合は、残りのバジェットを現在のブロック全体に均一に分配し、最大 1 つの分割を 2 つの隣接する値に生成します。 

最後に、分散は標準の公式を使用してグループ化された周波数から直接計算され、配列全体を再構成する必要がなくなります。 

実装の微妙な点は、部分リダクション中に整数の除算と剰余を正しく処理することです。これは、分布が不均一になる唯一の点だからです。

 ## 特殊なケース

 エッジケースの 1 つは、すべての値が同一である場合です。 アルゴリズムはレベル間のギャップがゼロであることを即座に認識するため、マージは発生せず、すべての操作が 1 つのブロック内で均一に分散されます。 一様削減後もすべての要素は等しいままであるため、分散はゼロのままです。 

予算が小さすぎて次のレベルに到達できない場合にも、別のエッジケースが発生します。 この状況では、最上位のブロックのみが影響を受け、最大 2 つの隣接する値に分割されます。 実装では、これを整数の除算と剰余によって明示的に処理し、値が論理下限を下回らないようにします。 

最後のエッジ ケースは、マージを繰り返すと、操作が使い果たされる前に単一のブロックが生成される場合です。 その場合、残りのすべての操作はすべての要素に均等に分散され、ほぼ均一性が維持され、必要に応じて差異が最小限に抑えられます。
