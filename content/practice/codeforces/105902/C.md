 ## 解決策
 ## 問題の理解

 時間の経過とともに変化する配列が与えられ、それに対する 2 種類のクエリに答える必要があります。 1 つのクエリは単一の位置を変更し、もう 1 つのクエリは配列の選択された連続セグメントに非常に特殊なプロパティがあるかどうかを尋ねます。 

プロパティ自体は間接的に定義されます。 セグメントの場合、その値を取得して並べ替え、並べ替えられた値がギャップのない完全な連続整数シーケンスを形成しているかどうかを確認することを想像します。 言い換えれば、並べ替え後、隣接するすべてのペアは 1 つだけ異なっている必要があります。 

したがって、セグメントは、その中のすべての値が個別であり、次のような完全な整数間隔をカバーする場合にのみ有効です。$[k, k+1, \dots, k + m - 1]$。 

主な問題は、配列が動的であることです。 更新ではどこでも値が変更される可能性があり、クエリでは任意の範囲について問い合わせることができるため、ポイント更新と範囲チェックの両方を効率的にサポートする必要があります。 

制約は大きく、最大で$10^5$要素と$10^5$テスト ケースごとの操作。すべてのテスト ケースの合計が次の範囲内に含まれます。$2 \cdot 10^5$。 これにより、クエリごとにセグメントを再構築または並べ替えるアプローチは即座に除外されます。 単一の長さのセグメントでもソート$n$費用$O(n \log n)$、これは次のようになります$10^{10}$最悪の場合、操作が不可能になり、実行できなくなります。 

この問題は本質的に、範囲にわたってマルチセットを維持し、すべての要素が個別であること、および範囲が連続した間隔を形成するという 2 つの条件を迅速に検証できるデータ構造を要求することです。 

セグメント内に重複が存在する場合、微妙なエッジケースが発生します。 たとえば、セグメントが$[1, 1, 2]$、ソートすると、$[1, 1, 2]$、隣接する差異はすべて 1 つではありません。 単純なアプローチでは、最小値と最大値をチェックするだけで十分であると誤って想定する可能性があります。最小値が 1 で最大値が 2 であるため、ここでは失敗しますが、重複すると条件が破られます。 

もう 1 つのエッジ ケースは、数値が連続しているものの、値の範囲内で連続していない場合です。 例えば、$[2, 3, 5]$には最小値 2 と最大値 5 がありますが、4 がないため無効です。 どのソリューションでも、ギャップと重複の両方を同時に検出する必要があります。 

## アプローチ

 単純な解決策は、セグメントを抽出し、並べ替えて、隣接するそれぞれの差異が正確に 1 つであるかどうかを確認することによって、各タイプ 2 クエリを処理します。 これは定義と直接一致するため、正しいです。 ただし、長さのセグメントを抽出すると、$O(n)$整理にはコストがかかります$O(n \log n)$、そしてこれを行うのは$10^5$クエリは壊滅的なランタイムにつながります。 

ボトルネックは、同じローカル構造の繰り返しの再計算です。 重要な観察は、「並べ替えられた値が連続したシーケンスを形成する」という条件が、順序付けの下で安定する 2 つの単純な不変式、つまり最小値、最大値、および個別の要素の数に還元できるということです。 セグメントに重複が含まれず、その最大値から最小値を引いた値がその長さから 1 を引いた値に等しい場合、そのセグメントは完全に連続した間隔である必要があります。 

これにより、ソート順序の維持から範囲にわたる集計統計の維持までの問題が軽減されます。 次に、最小値、最大値、および個別のカウントの更新と範囲クエリをサポートすることが課題になります。 

更新時に個別のカウントを処理するために、各値の位置を維持します。 セグメントごとの完全な周波数配列を追跡する代わりに、各インデックスがプレフィックス内のその値の最後の出現である場合に 1 を寄与する位置に対してフェンウィック ツリーまたはセグメント ツリーを使用し、アクティブな出現を維持するために値ごとのハッシュまたは順序構造と組み合わせます。 より単純で標準的なアプローチは、各ノードが最小値、最大値を格納するセグメント ツリーを維持し、周波数マップを回避することです。 代わりに、最後の出現位置を介して重複を追跡する 2 番目の構造を維持します。 

実際に使用されるより直接的でクリーンなアプローチは、3 つのセグメント ツリーを維持することです。1 つは最小値、もう 1 つは最大値、もう 1 つは位置が「新しい出現」に寄与しているかどうかを追跡して重複をカウントします。 各値については、その最後の位置が維持されます。 ポジションを更新するときは、各ポジションが一意の代表であるかどうかが構造に正しく反映されるように、最後の出現箇所もそれに応じて更新します。 

これにより、各クエリは次のように変換されます。$O(\log n)$操作。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n \log n)$クエリごと |$O(n)$| 遅すぎる |
 | 最適 |$O(\log n)$クエリごと |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 配列インデックスに対して 3 つのセグメント ツリーを維持します。 1 つは範囲内の最小値を格納し、もう 1 つは最大値を格納し、もう 1 つはインデックスがその値の最後の出現であるかどうかを示すバイナリ マーカーを格納します。 

また、各値を最新の値のインデックスにマップする辞書も維持します。 

### ステップ

 1. 最小値、最大値、および最後の出現のブール配列のセグメント ツリーを初期化します。 最初は、各位置がその値の最後の出現であるため、対応するマーカーを 1 に設定し、そのインデックスをマップに記録します。 これにより、重複が最初から正しく追跡されることが保証されます。 
2. 位置でのポイント更新の場合$x$、まず古い貢献を削除します。$a[x]$。 もし$x$がその値の最後の出現であった場合、そのマーカーを 0 に設定し、値が以前に出現した場合は、前の出現を新しい最後に昇格させ、そのマーカーを更新します。 これにより、「最後に出現した」不変条件の正確さが維持されます。 
3. 古い値を削除した後、新しい値を割り当てます。$y$位置にある$x$。 それを値リストに挿入し、マークを付けます。$x$新しい最後の出現として、必要に応じて以前の最後の出現を更新します。 
4. 範囲クエリの場合$[l, r]$、セグメントツリーを使用して最小値と最大値を計算します。 
5. また、最終出現マーカー ツリーを使用して、範囲内に個別の要素がいくつあるかを計算します。 合計が終わりました$[l, r]$そのセグメント内の個別の値の数を示します。 
6. セグメントは、最大値から最小値を引いた値が長さから 1 を引いた値に等しく、個別の要素の数がセグメントの長さと等しい場合にのみ有効です。 これら 2 つの条件を組み合わせることで、連続性と重複がないことが保証されます。 

### なぜ効果があるのか

 正確さは、連続するシーケンスをギャップと重複のないセットとして特徴付けることに依存します。 すべての要素が個別であり、最小値から最大値までにわたる場合、正確に取得する唯一の方法は$r - l + 1$その間隔内の要素は、それらがその間のすべての整数を形成しているかどうかを表します。 セグメント ツリーは、更新時に最小値、最大値、個別カウントが常に正しいことを保証します。これは、各更新が最後に出現した構造内の 2 つの位置と値ツリー内の 1 つの位置にのみ影響し、グローバルな不変条件が維持されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n, func, default):
        self.n = n
        self.func = func
        self.default = default
        self.size = 1
        while self.size < n:
            self.size *= 2
        self.data = [default] * (2 * self.size)

    def build(self, arr):
        for i in range(len(arr)):
            self.data[self.size + i] = arr[i]
        for i in range(self.size - 1, 0, -1):
            self.data[i] = self.func(self.data[2*i], self.data[2*i+1])

    def update(self, i, v):
        i += self.size
        self.data[i] = v
        i //= 2
        while i:
            self.data[i] = self.func(self.data[2*i], self.data[2*i+1])
            i //= 2

    def query(self, l, r):
        l += self.size
        r += self.size
        res_l = self.default
        res_r = self.default
        while l <= r:
            if l % 2 == 1:
                res_l = self.func(res_l, self.data[l])
                l += 1
            if r % 2 == 0:
                res_r = self.func(self.data[r], res_r)
                r -= 1
            l //= 2
            r //= 2
        return self.func(res_l, res_r)

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    INF = 10**18
    seg_min = SegTree(n, min, INF)
    seg_max = SegTree(n, max, -INF)
    seg_cnt = SegTree(n, lambda x, y: x + y, 0)

    seg_min.build(a)
    seg_max.build(a)

    last = {}
    for i, v in enumerate(a):
        seg_cnt.update(i, 0)
        if v in last:
            seg_cnt.update(last[v], 0)
        last[v] = i
        seg_cnt.update(i, 1)

    out = []

    for _ in range(q):
        t = list(map(int, input().split()))
        if t[0] == 1:
            x, y = t[1] - 1, t[2]

            seg_min.update(x, y)
            seg_max.update(x, y)

            old = a[x]
            if last.get(old, -1) == x:
                seg_cnt.update(x, 0)
                prev = -1
                for i in range(x - 1, -1, -1):
                    if a[i] == old:
                        prev = i
                        break
                if prev != -1:
                    seg_cnt.update(prev, 1)
                    last[old] = prev
                else:
                    last.pop(old, None)

            a[x] = y
            if y in last:
                seg_cnt.update(last[y], 0)
            last[y] = x
            seg_cnt.update(x, 1)

        else:
            l, r = t[1] - 1, t[2] - 1
            mn = seg_min.query(l, r)
            mx = seg_max.query(l, r)
            cnt = seg_cnt.query(l, r)

            if mx - mn == r - l and cnt == r - l + 1:
                out.append("YES")
            else:
                out.append("NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、範囲の最小値と最大値のセグメント ツリーに依存して、値の間隔の迅速な境界チェックをサポートします。 3 番目の構造は、各インデックスが現在その値の最後の出現であるかどうかを追跡し、個別のカウントを範囲の合計として計算できるようにします。 

最もデリケートな部分は、更新時に正確さを維持することです。 値が上書きされるときは、その値の直前の最後の出現を慎重に更新する必要があります。 提供されているコードのリニア スキャンは簡略化したものです。 完全に最適化されたバージョンでは、値ごとにバランスの取れた構造がそれを置き換えますが、概念的な不変条件は変更されず、個別の値ごとにアクティブなマーカーが 1 つだけ存在します。 

## 実用的な例

 配列を考慮してください$[1, 1, 2]$そして全範囲に対するクエリ。 

| ステップ | 分 | マックス | 個別のカウント | 状態 |
 | --- | --- | --- | --- | --- |
 | イニシャル | 1 | 2 | 2 | mx - mn = 1、3 つの要素が必要 |

 範囲の長さは 3 なので、mx - mn = 2 および個別カウント = 3 が必要です。重複が存在するため、条件は失敗し、NO が生成されます。 これにより、重複が適切に除外されたことが確認されます。 

ここで考えてみましょう$[2, 3, 4]$。 

| ステップ | 分 | マックス | 個別のカウント | 状態 |
 | --- | --- | --- | --- | --- |
 | クエリ | 2 | 4 | 3 | mx - mn = 2、cnt = 3 |

 両方の条件が成立するため、セグメントは有効です。 これは、値が 1 から始まっていない場合でも、このメソッドが連続する間隔を正しく識別していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(q \log n)$| 各更新とクエリは、対数の数のセグメント ツリー ノードに影響します。 
| スペース |$O(n)$| セグメント ツリーと補助マップはインデックスごとに 1 つのエントリを保存します。

 ## 特殊なケース

 サイズ 1 の最小セグメントは、ソート後にギャップのないシーケンスを自明に形成するため、常に有効です。 min が max に等しく、個別カウントが 1 であるため、両方の条件が成立するため、アルゴリズムはこれを処理します。 

すべての値が等しいセグメントは失敗します。これは、最小値が最大値と等しいにもかかわらず、個別カウントが 1 である一方で長さが 1 より大きく、必要な等価性が崩れているためです。 カウントのセグメント ツリーは、最小値と最大値のチェックだけでは誤って合格した場合でも、この不一致を正確に捕捉します。 

ほぼ連続しているが重複しているセグメント。たとえば、$[1, 2, 2, 3]$、個別カウントがセグメント長より小さいため、失敗します。 min と max は有効な間隔を示していますが、重複したマーカー構造により誤検知が防止されます。
