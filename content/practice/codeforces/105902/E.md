 ## 問題の理解

 私たちには番号が与えられています$n$、そしてすべての整数に対して$i$から$0$に$n$、全体を見ます$i$パスカルの三角形の - 番目の行。 その行の各エントリに対して、二項係数を取得します。$\binom{i}{j}$、それを法 2 で減らし、それらの値をすべて合計します。 最後に、この数量をすべての行で合計します。$0$に$n$。 

したがって、タスクは、各 Pascal 行に現れる奇数のエントリの数を計算することです。$n$、それらのカウントを加算し、結果のモジュロを出力します。$998244353$。 

制約によって次のことが明らかになります。$n$と同じ大きさにすることができます$10^{18}$、最大で$3 \cdot 10^5$テストケース。 すべての値を反復しようとするソリューション$n$単一のテスト ケースでも最大で$10^{18}$操作。 意図したソリューションは、次のバイナリ表現のみに依存する必要があります。$n$、最大 60 ビットです。 

「」の意味から微妙な問題が生じます。$\binom{i}{j} \mod 2$”。二項係数自体を合計するのではなく、そのパリティだけを合計します。これにより構造が完全に変わります。値は 0 または 1 に崩壊し、問題は算術ではなく組み合わせになります。もう 1 つの潜在的な落とし穴は、二項係数または階乗を直接計算しようとすることですが、これは大規模なシステムでは実行不可能です。$i$そして不必要でもあります。 

## アプローチ

 直接解釈すると、それぞれについて次のように計算されます。$i$、 全て$i+1$二項係数をモジュロ 2 で減らし、奇数の数を数えます。 これにはすでに費用がかかります$O(i)$行ごと、およびすべての行にわたって$n$それはなる$O(n^2)$、たとえ小さなものであっても、実現可能な限界をはるかに超えています。$n$。 

重要な単純化は、二項係数が奇数になる場合を理解することから生まれます。 底 2 のルーカスの定理による、二項係数$\binom{i}{j}$すべてのビットが設定されている場合に限り、奇数になります$j$にも設定されています$i$。 言い換えれば、行内の奇数エントリの数$i$の設定ビットのサブセットの数に等しい$i$、つまり$2^{\mathrm{popcount}(i)}$。 

これにより問題がコンピューティングに変換されます$$\sum_{i=0}^{n} 2^{\mathrm{popcount}(i)}.$$これで構造がより明確になりました。 各数値は、そのバイナリ表現に出現する数値の数にのみ応じて値を与えます。 これは、値を反復処理するのではなく、ビットを処理することを示唆しています。 

この総当たりのアイデアは、次の値までのすべての数値を列挙するため失敗します。$n$しかし、関数がビット数のみに依存しているという観察により、設定された最高ビットによって範囲を分割し、問題を再帰的に軽減することができます。 

完全なブロック内のすべての番号という ID を使用します。$2^k$値はビットごとに独立して寄与し、完全なブロックの閉じた形式と残りのプレフィックスの再帰関係を与えます。

 ## アルゴリズムのチュートリアル

 関数を定義します$S(x)$必要な金額として$0$に$x$、 意味$S(x) = \sum_{i=0}^{x} 2^{\mathrm{popcount}(i)}$。 

1. もし$x = 0$、唯一の数値が 0 であり、ポップカウントが 0 であるため、1 を返します。$2^0 = 1$。 
2. を超えない最大の 2 の累乗を求めます。$x$、 言う$2^k$。 これにより範囲が分割されます$[0, x]$2 つの部分に分割: からの数値$0$に$2^k - 1$、およびからの数字$2^k$に$x$。 
3. フルブロックの場合$[0, 2^k - 1]$、すべての数値は正確に$k$-ビット番号。 各ビットは独立して 0 または 1 のいずれかに寄与し、設定されたビットは重みの係数 2 に寄与します。 これにより、合計貢献度は次のようになります。$(1 + 2)^k = 3^k$。 
4. の数字については、$[2^k, x]$、すべての数値には最高位のビットが設定されており、固定係数 2 に寄与します。そのビットを削除すると、より小さい数値が残ります。$[0, x - 2^k]$, したがって、貢献度は次のようになります。$2 \cdot S(x - 2^k)$。 
5. 両方の部分を組み合わせます。$$S(x) = 3^k + 2 \cdot S(x - 2^k).$$6. 3 のべき乗と 2 のべき乗を最大 60 ビットまで事前計算し、テスト ケースごとの再帰を評価します。 

### なぜ効果があるのか

 すべての数値がその最上位の設定ビットと残りのサフィックスに一意に分解されるため、再帰は有効です。 貢献$2^{\mathrm{popcount}(i)}$最上位ビットからの固定寄与と下位ビットからの独立した寄与に因数分解します。 全範囲は 2 のべき乗に整列した互いに素なブロックにきれいに分割されるため、値が 2 回カウントされることも、値が見逃されることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

pow3 = [1] * 61
for i in range(1, 61):
    pow3[i] = pow3[i - 1] * 3 % MOD

def solve_one(n: int) -> int:
    if n == 0:
        return 1

    # find highest bit
    k = n.bit_length() - 1
    highest = 1 << k

    # full block [0, 2^k - 1]
    res = pow3[k]

    # remainder
    res += 2 * solve_one(n - highest)
    return res % MOD

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        print(solve_one(n) % MOD)

if __name__ == "__main__":
    main()
```機能`solve_one`再帰的分解が直接続きます。 事前に計算された`pow3[k]`完全な貢献を与える$k$-ビットスペース。 再帰呼び出しは、最上位ビットを削除した後に残りのサフィックスを処理します。 

よくある間違いは、セグメント内の最上位ビットが常に 1 であるため、サフィックスが同じ構造で寄与しており、係数 2 でスケールされただけであることを忘れていることです。 

## 実用的な例

 検討してください$n = 3$。 私たちは計算します$S(3)$。 

| ステップ | n | k | 3^k の貢献 | 再帰部分 | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 3 | 1 | 3 | S(1) | 3+2・S(1) |
 | 2 | 1 | 0 | 1 | S(0) | 1 + 2・1 |

 今$S(1) = 3$、 それで$S(3) = 3 + 2 \cdot 3 = 9$。 

これは直接列挙に一致します。$1 + 2 + 2 + 4 = 9$。 

ここで考えてみましょう$n = 5$。 

| ステップ | n | k | 3^k の貢献 | 再帰部分 | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 5 | 2 | 9 | S(1) | 9+2・S(1) |
 | 2 | 1 | 0 | 1 | S(0) | 1 + 2・1 |

 それで$S(5) = 9 + 2 \cdot 3 = 15$。 

これにより、再帰によって範囲が 2 のべき乗で正しく分割され、重み構造が維持されることが確認されます。

## テストケース```python
import sys, io

MOD = 998244353

pow3 = [1] * 61
for i in range(1, 61):
    pow3[i] = pow3[i - 1] * 3 % MOD

def solve_one(n: int) -> int:
    if n == 0:
        return 1
    k = n.bit_length() - 1
    highest = 1 << k
    return (pow3[k] + 2 * solve_one(n - highest)) % MOD

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(sys.stdin.readline())
    out = []
    for _ in range(t):
        n = int(sys.stdin.readline())
        out.append(str(solve_one(n) % MOD))
    return "\n".join(out)

 ## 特殊なケース

 のために$n = 0$、再帰は直ちに終了する必要があります。 この関数は 1 を返し、空のポップカウントのみが寄与するという事実と一致します。

次のような 2 のべき乗の場合$n = 8$、分割により、完全なブロックとゼロのサフィックスが生成されます。 接尾辞の再帰は正しく 1 を返す必要があります。 そうしないと、より深い再帰レベルでは、最も高いセグメントの寄与が 2 の係数で過小評価されてしまいます。
