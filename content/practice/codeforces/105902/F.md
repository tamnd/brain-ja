 ## 解決策
 ## 問題の理解

 開き括弧と閉じ括弧で構成される文字列が与えられます。 文字を 1 つずつ変更することができ、変更するたびに括弧が反対の種類に変わります。 このような変更をいくつか実行した後、結果として得られる文字列の空ではないサブシーケンスをすべて調べます。 要件は、これらのサブシーケンスのいずれも「バランスがとれていない」ことです。バランスがとれているとは、挿入後に有効な括弧表現として解釈できることを意味します。`+`そして`1`これは、正しい括弧シーケンスの通常の概念と同等です。 

タスクは、空でないすべてのサブシーケンスがバランスの取れた括弧シーケンスとして無効になるように、必要な単一位置の変更の最小数を計算することです。 

入力サイズはテスト ケース全体で合計 200,000 文字に達するため、どのソリューションもテスト ケースごとに直線的な時間で実行する必要があります。 すべてのサブシーケンスのチェックやサブセットごとの変換のシミュレーションなどの 2 次的なことは、サブシーケンスの数が指数関数的に増加するため、直ちに実行できなくなります。 

微妙な点は、サブシーケンスのバランスが取れていることが何を意味するかということです。 最小の平衡部分列は次のとおりです。`"()"`、必要なのは 1 つだけです`'('`そして1つ`')'`と`'('`の前に現れる`')'`元の文字列で。 これにより、重要な構造上の制約が生じます。最終的な文字列に両方のタイプのかっこが存在する場合、長さ 2 の有効なサブシーケンスが常に可能になります。 

単純な推論を混乱させることが多いエッジケースは、次の観察から得られます。 

文字列が`"()"`の場合、すでにバランスのとれたサブシーケンスが含まれているため、サブシーケンスの完全なセットには有効なサブシーケンスが含まれるため、ゼロ操作は受け入れられません。 正解するには、少なくとも 1 文字を変更する必要があります。 

文字列が`"((("`、閉じ括弧がないため、バランスの取れたサブシーケンスを形成する方法はまったくありません。 この場合、すべてのサブシーケンスは自動的に不均衡になります。 

文字列が`")))"`、同じ推論が対称的に適用されます。 

これらの例は、両方のタイプのブラケットが存在する場合にのみ危険な状況が発生することを示唆しています。 

## アプローチ

 ブルートフォース戦略では、文字列を変更するためにあらゆる方法を試し、候補文字列ごとにすべてのサブシーケンスを列挙し、それらのいずれかがバランスがとれているかどうかを確認します。 単一の文字列のチェックにはすでに指数関数的な数のサブシーケンスが含まれており、変更される可能性のある文字列の数も、変更される位置の数が指数関数的に増加します。 枝刈りを行ったとしても、このアプローチは入力制限の下では破綻します。 

重要な単純化は、`'('`そしてどれでも`')'`有効なサブシーケンスを即座に保証します`"()"`。 これは、「すべての空でないサブシーケンスは不均衡である」というプロパティ全体が、最終文字列に両方のタイプのかっこを同時に含めてはならないという、より単純な条件と同等であることを意味します。 

したがって、ターゲット構成は非常に制限されています。最後の文字列は、次のいずれかである必要があります。`'('`またはすべて`')'`。 どの混合物も自動的に失敗します。 

これが理解されると、問題は、必要な均一文字列を選択し、それを達成するために反転する必要がある位置の数を数えるということになります。 両方の可能性を試して、最小限のものを採用します。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 何個数えるか`'('`そして`')'`文字列に現れます。 これにより、文字列が均一からどの程度離れているかが完全に説明されます。 
2. 文字列全体をすべての文字列に変換するコストを計算します。`'('`。 このコストはまさに次の数です。`')'`それぞれの文字を反転する必要があるためです。 
3. 文字列全体をすべての文字列に変換するコストを計算します。`')'`。 このコストはまさに次の数です。`'('`文字。 
4. どちらのターゲット構成でも、サブシーケンスに両方のタイプのかっこを含めることができないことが保証されるため、これら 2 つの値の最小値を返します。 

均一な文字列のみを選択する背後にある理由は、混合構成には必ず少なくとも 1 つの文字列が含まれるためです。`"()"`その後、`'('`の左側にある`')'`すでに有効なバランスの取れたサブシーケンスを形成しています。 

### なぜ効果があるのか

 文字列に両方の括弧タイプが含まれるとすぐに、その文字列は要件を満たしません。これは、サブシーケンスが 1 つの括弧タイプで構成されるためです。`'('`そしてもう一つ後`')'`すでにバランスが取れています。 したがって、そのようなサブシーケンスをすべて削除することは、ブラケット タイプの 1 つが完全に存在しないことを確認することと同じです。 均一な文字列はこの条件を満たしますが、均一でない文字列はこの条件に違反します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input().strip())
    s = input().strip()

    open_cnt = s.count('(')
    close_cnt = n - open_cnt

    # make all '(' or all ')'
    print(min(open_cnt, close_cnt))
```この解決策は、文字の頻度をカウントすることだけに依存します。 重要な実装の詳細は、サブシーケンスや変換をシミュレートする試みを避けることです。 答えはグローバル カウントによって完全に決定されるため、単一のリニア スキャン (または Python の組み込みスキャンでも)`count`）で十分です。 

唯一の微妙な点は、両方の変換方向が考慮されていることを確認することです。 多数派の文字が異なる場合、1 つの方向のみを選択すると間違っている可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()
        open_cnt = s.count('(')
        close_cnt = n - open_cnt
        out.append(str(min(open_cnt, close_cnt)))
    return "\n".join(out)

# provided samples
assert run("2\n3\n())\n7\n)()()((\n") == "1\n3"

# all same characters
assert run("2\n3\n(((\n3\n)))\n") == "0\n0"

# single imbalance mix
assert run("1\n2\n()\n") == "1"

# already uniform
assert run("1\n5\n(((((\n") == "0"

# alternating structure
assert run("1\n6\n()()()\n") == "3"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`(((`| 0 | すでに安全なユニフォームケース |
 |`)))`| 0 | 対称ケース |
 |`()`| 1 | 最小限の混合ケース |
 |`()()()`| 3 | 最悪の場合の交互の反転 |

 ## 特殊なケース

 重要なエッジ ケースは、次のように文字列が括弧の間で交互に現れる場合です。`"()()()"`。 構造的に複雑に見えるかもしれませんが、それでも両方が含まれています。`'('`そして`')'`、つまりサブシーケンス`"()"`常に存在します。 このアルゴリズムは両方のタイプをカウントし、一方のタイプを完全に除去するために必要なフリップの数を正確に返します。 

もう 1 つのエッジ ケースは、文字列がすでに均一である場合です。たとえば、`"(((("`。 ここで、カウントは閉じ括弧がゼロであることを示しているため、答えはゼロです。 アルゴリズムは特別な分岐を行わずにこれを自然に処理します。 

最後に、最小の重要な入力`"()"`構造が重要ではない理由を強調しています。たとえそれが有効な完全なシーケンスであっても、長さ 2 のバランスの取れたサブシーケンスが含まれているため、直ちに失格となります。 計算は依然として 1 回のフリップに減り、均一化ロジックに一致します。
