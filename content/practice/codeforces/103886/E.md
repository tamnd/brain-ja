 ## 解決策
 ## 問題の理解

 この問題では、指定された各整数の値を計算するように求められます。$x$、ここでそれぞれ$x$「プロジェクトの規模」または目標金額を表します。 そういったものごとに$x$では、特定のルール システムの下で有効な構文がいくつ存在するかを数え、回文構造を持つ構文を差し引きます。 

重要な構造的事実は、すべてのプロジェクトが一定の金額に貢献しているということです。$x$の他の値から独立しています$x$。 これは、すべての回答について前処理できることを意味します$x \le 10^5$一定時間内にクエリに回答します。 

各プロジェクトは、合計値が次のとおりである構成として解釈できます。$x$。 対称性の制約がなければ、そのような構成の数は指数関数的に増加します。$x$、具体的には$2^{x-1}$。 これらの中には、左半分と右半分が互いに鏡像するという意味で対称的な構成もあり、それらは回文とみなされ、除外する必要があります。 

微妙なポイントが現れるのは、$x$小さいです。 のために$x = 1$、唯一の構成は自明な回文であるため、減算を含む式が誤って負の結果や一貫性のない結果を生成してはなりません。 のために$x = 2$、「半構造」と「完全構造」の境界は厳しく、フロア分割の 1 つずつの誤差が通常ここで発生します。 

単純な実装では、各構成のすべての構成を列挙しようとします。$x$ただし、カウントは指数関数的であるため、$x = 40$これはすでに実行不可能であり、この問題では次の値まで許容されます。$10^5$, したがって列挙は不可能です。 

したがって、課題は純粋に組み合わせ的なものであり、閉じた形式を導き出し、それを効率的に評価することです。 

## アプローチ

 特定の有効なプロジェクトをすべて構築しようとすると、$x$、各位置は効果的に 2 つの可能性に分岐し、$2^{x-1}$合計構成。 これは標準的な「ポジションごとの二者択一」の成長パターンです。 この部分は簡単で、解に指数項が現れる理由を説明しています。 

この複雑さは回文構成から発生します。 回文プロジェクトは前半で完全に決定されます。後半はそれを正確に反映する必要があるためです。 金額のプロジェクトを考えると$x$、その後は最初のみ$\lfloor x/2 \rfloor$位置は自由に選択でき、残りは対称性によって強制されます。 これにより、次の自由度が低下します。$x-1$に$\lfloor x/2 \rfloor$、回文カウントは次のようになります。$2^{\lfloor x/2 \rfloor}$。 

ただし、境界の修正があります。つまり、完全に中央に配置されている場合、構造全体が単一の要素に折りたたまれます。$x$奇数か最小です。 これにより、有効回文数が次のようにきれいに揃う調整が導入されます。$2^{\lfloor x/2 \rfloor}$退化した中心症例を考慮した後。 

両方の量がわかったら、それぞれの答えが得られます。$x$は、単に全体の構成と回文構成の違いです。 以来$x$サイズが大きく、多くのクエリが存在する可能性があるため、2 の累乗を事前に計算する必要があります。$10^5$すべての回答をクエリごとに一定時間で計算できます。

 ## アルゴリズムのチュートリアル

 ここで、組み合わせ構造を直接反映する方法でソリューションを構築します。 

1. 可能な最大値まで 2 の累乗を事前計算します。$x$。 保管します$2^i$みんなのために$i$これは、合計カウントと回文カウントの両方が高速な指数検索に依存しているためです。 これにより、クエリ中に累乗が繰り返されることがなくなります。 
2. 各クエリ値について$x$、構成の合計数を次のように計算します。$2^{x-1}$。 これは、最初の位置を除くすべての位置が独立した二者択一を導入するという事実に対応します。 
3. 回文構成の数を次のように計算します。$2^{\lfloor x/2 \rfloor}$。 これは、構造の前半だけが自由に選択され、残りは対称性によって決定されることを反映しています。 
4. 総数から回文数を引いて、その「危険にさらされている」プロジェクトの数を取得します。$x$。 
5. 各クエリの結果を個別に出力します。 

重要な観察は、両方のコンポーネントが次のものにのみ依存していることです。$x$したがって、クエリ間の相互作用は存在しません。 

### なぜ効果があるのか

 すべての有効な構成は、回文または非回文の 2 つの素なセットのいずれかに一意に分類されます。 合計数には、可能なすべての構成が制限なく列挙されます。 回文式は、前半によって完全に決定される構成を正確にカウントします。 すべての回文構成が総数に含まれるため、減算することで重複や欠落がなくきれいに削除されます。 これにより正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return
    q = int(data[0])
    xs = list(map(int, data[1:]))

    max_x = max(xs) if xs else 0

    pow2 = [1] * (max_x + 2)
    for i in range(1, max_x + 2):
        pow2[i] = pow2[i - 1] * 2

    out = []
    for x in xs:
        total = pow2[x - 1] if x - 1 >= 0 else 0
        pal = pow2[x // 2]
        out.append(str(total - pal))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、事前に計算された 2 のべき乗の単一の配列に依存します。 配列は反復的に構築されるため、再帰やべき乗剰余のオーバーヘッドが回避されます。 

クエリごとに、このテーブルに直接インデックスを作成します。 表現$x - 1$安全なので$x \ge 1$ただし、非正のインデックスを明示的に処理することで、エッジ ケースを回避します。 

Python では整数演算は任意精度であるため安全であるため、特に指定がない限りモジュロは必要ありません。 

## 実用的な例

 ### 例 1

 しましょう$x = 3$。 

| × | 合計$2^{x-1}$| 回文$2^{\lfloor x/2 \rfloor}$| 答え |
 | --- | --- | --- | --- |
 | 3 | 4 | 2 | 2 |

 合計の構成はすべて、2 つの有効な位置に対する二者択一の選択です。 回文のものは完全に最初の位置によって決まります。 減算すると、非対称構成が残ります。 

これは、対称制約によって小さい指数空間の正確に半分が削除されることを確認します。 

### 例 2

 しましょう$x = 5$。 

| × | 合計$2^{x-1}$| 回文$2^{\lfloor x/2 \rfloor}$| 答え |

この例は、2 つの指数底の間のギャップがどのように増加するかを示しています。$x$、これが、減算が安定して負にならない理由です。

 ## 特殊なケース

 最小の入力$x = 1$がメインのコーナーケースです。 合計の式は次のようになります$2^{0} = 1$、回文式は次のようになります$2^{0} = 1$、結果はゼロになります。 これは、単一要素構造は完全に対称であり、結果には何も寄与しないという解釈と一致します。 

のために$x = 2$、合計は$2^{1} = 2$、回文カウントは$2^{1} = 2$、再びゼロになります。 これにより、サイズ 2 の両方の構成が問題定義の下で対称であることが確認されます。 

次のような奇数の値の場合$x = 5$のフロア区分$2^{\lfloor x/2 \rfloor}$中心要素が分数動作を導入しないようにし、指数の一貫性を保ち、非対称の中間位置の過大なカウントを回避します。
