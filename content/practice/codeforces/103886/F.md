 ## 解決策
 ## 問題の理解

 整数の配列と、それを正確に k 個の連続するサブ配列に分割するという要件が与えられます。 このようなパーティションの場合、各サブ配列にはその要素間で計算された OR 値があります。 その後、これらすべてのサブ配列 OR 値の AND を計算し、パーティションの品質を表す 1 つの数値を生成します。 

タスクは、この最終的な AND 値が最大になるようにパーティションを選択することです。 

目標について考えるもう 1 つの方法は、k 個のサブ配列すべてでどのビットが生き残ることができるかを決定することです。 ビットは、すべての部分配列にそのビットを含む要素が少なくとも 1 つある場合にのみ、最終的な答えに寄与します。 サブ配列が 1 つでも欠けている場合、そのビットは最後の AND によって削除されます。 

値の制約は最大 10^9 まであり、関連するビットは最大 30 ビットに制限されます。 通常、要素の数は十分に大きいため、O(n^2) など、パーティションを繰り返し試行するものは実行できません。 線形に近いもの、またはビットあたりの係数が小さい線形なものが必要です。 

素朴な考えによる微妙な失敗例は、ビットが一度頻繁に出現すると、調整なしで使用できると仮定することです。 たとえば、k が大きい場合、ビットが何度も出現する可能性がありますが、クラスタリングによりすべてのセグメントにそのビットが存在することを保証することは依然として不可能です。 もう 1 つの注意が必要な状況は、1 ビットの貪欲なセグメンテーションが上位ビットの実現可能性を破壊する場合です。 

## アプローチ

 強引なアイデアは、配列を k 個のセグメントに分割するあらゆる方法を試し、その結果得られるセグメント OR の AND を計算することです。 C(n-1, k-1) 個の可能な分割が存在するため、これはすぐに組み合わせ的に爆発しますが、n が小さい場合でも実行不可能です。 

視点を逆転させる必要があります。 最初にセグメントを選択するのではなく、各セグメントにどのビットを強制的に表示できるかを尋ねます。 最終的な答えに必要なビットを表す候補ビットマスク x を修正するとします。 次に、各セグメントの OR に x のすべてのビットが含まれるように、配列を少なくとも k 個のセグメントに分割できるかどうかを確認します。 

これにより、問題はビットマスクごとの実現可能性チェックに変換されます。 重要な観察は、ビットが実現可能性の点で独立しているということです。答えを最大化しようとすると、最上位ビットから最下位ビットまで貪欲に x を構築できます。 これが機能するのは、最終的な整数の結果では上位ビットが辞書編集的に優先されるため、下位ビットの組み合わせのために上位ビットを決して犠牲にしたくないからです。 

固定 x の実現可能性をチェックするには、現在のセグメントの OR 値を累積しながら左から右にスキャンします。 現在のセグメントに x のすべてのビットが含まれたら、切り取って新しいセグメントを開始します。 このようなセグメントを少なくとも k 個形成できれば、x は実現可能です。 

カットを遅らせることは決して役に立たないため、この貪欲なカットは機能します。 セグメントがすでに x を満たしている場合、それを拡張しても余分な OR ビットが追加されるだけで、既存のビットは削除できないため、後でより有効なセグメントを形成する能力が向上することはありません。

 ## アルゴリズムのチュートリアル

 最上位ビットから最下位ビットまで少しずつ答えを構築します。

1. 応答マスク x を 0 として初期化します。これは、最初はビットが必要ないことを意味します。 実現可能性を保ちながら、ビットを 1 つずつオンにしてみます。 
2. 29 から 0 までのビットを繰り返します。各ビット i に対して、ビット i を設定した候補マスク x' = x を作成します。 これは、ビット i が最終的な答えの一部である可能性があるという仮説を表します。 
3. すべてのセグメントに x' のすべてのビットが含まれるように、配列を少なくとも k 個の有効なセグメントに分割できるかどうかを確認します。 これを行うには、現在のセグメントの実行中の OR を維持しながら配列をスキャンします。 
4. スキャン中に、実行中の OR を各要素で更新します。 実行中の OR に x' のすべてのビットが含まれる場合は常に、現在のセグメントを閉じて実行中の OR をリセットします。 セグメント数も増やします。 
5. スキャン終了後、形成されたセグメントの数が少なくとも k であれば、x' は実行可能であるため、x を x' に永続的に更新します。 それ以外の場合は、ビット i を破棄し、x を変更しないままにします。 
6. すべてのビットを処理した後、x は達成可能な最大マスクになります。 

重要な点は、実現可能性チェックで k 個を超えるセグメントを形成できることです。 これは重要です。なぜなら、k 個以上のセグメントを形成できれば、マージでは OR が増加するだけで、x 内のすべてのビットの存在が維持されるため、有効性を失うことなく隣接するセグメントを常にマージできるからです。 

なぜ効果があるのか:

 正しさは 2 つの特性に基づいています。 まず、固定マスクの貪欲なセグメンテーションは、常に可能な限り早い時点でカットされるため、有効なセグメントの数を最大化するという点で最適です。 第 2 に、実現可能性が単調であるため、ビット単位の構築は安全です。つまり、マスク x が実現可能であれば、任意のサブマスクも実現可能です。 これにより、上位ビットが一度拒否されると、後から下位ビットが追加されて有効になることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(mask, a, k):
    cnt = 0
    cur = 0
    full = mask
    for v in a:
        cur |= v
        if (cur & full) == full:
            cnt += 1
            cur = 0
    return cnt >= k

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    ans = 0
    for b in range(29, -1, -1):
        cand = ans | (1 << b)
        if can(cand, a, k):
            ans = cand

    print(ans)

if __name__ == "__main__":
    solve()
```実装では、実現可能性チェックがヘルパー関数に分離されます。 条件`(cur & full) == full`これは、必要なビットがすべて現在のセグメントに存在することを確認するクリーンな方法です。 

貪欲なリセット`cur = 0`OR はビットを蓄積するだけであるため、セグメントが有効になると、その後のセグメントの作成にはいかなる拡張も役に立たないため、安全です。 

外側のループは、ビットの重要性よりも辞書編集上の最適性を確保しながら、少しずつ答えを改善しようとします。 

## 実用的な例

 k 個のセグメントを形成しようとする配列を考えて、貪欲なカットがどのように動作するかを観察します。 

### 例 1

 入力:

 n = 5、k = 2

 a = [1, 2, 1, 4, 2]

 建設中に候補マスクを追跡します。 

| ビット | 候補マスク | セグメント数 | 実現可能 | 選ばれたマスク |
 | --- | --- | --- | --- | --- |
 | 2 | 4 | 1（2回到達不可） | いいえ | 0 |
 | 1 | 2 | 2 | はい | 2 |
 | 0 | 3 | 2 | はい | 3 |

 最終的な答えは 3 です。 

これは、実現可能性が、複数の互いに素なセグメントで必要なビットを繰り返し「収集」できるかどうかに依存していることを示しています。 

### 例 2

 入力:

 n = 6、k = 3

 a = [3、1、2、3、1、2]

 マスク 3 (ビット 0 および 1) のテスト:

 | セグメントビルド | または | アクション |
 | --- | --- | --- |
 | [3] | 3 | カット |
 | [1,2] | 3 | カット |
 | [3,1,2] | 3 | カット |

 3 つのセグメントが得られるので、マスク 3 は実現可能です。 

これは、貪欲な切断により常に可能な限り早いセグメント境界が生成され、有効なセグメントの数が最大化されることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    def can(mask):
        cnt = 0
        cur = 0
        for v in a:
            cur |= v
            if (cur & mask) == mask:
                cnt += 1
                cur = 0
        return cnt >= k

    ans = 0
    for b in range(29, -1, -1):
        cand = ans | (1 << b)
        if can(cand):
            ans = cand

    return str(ans)

# simple sample-like cases
assert run("5 2\n1 2 1 4 2\n") == "3"
assert run("6 3\n3 1 2 3 1 2\n") == "3"

# minimum case
assert run("1 1\n7\n") == "7"

# all equal
assert run("4 2\n1 1 1 1\n") == "1"

# k larger than possible segments for strong mask
assert run("3 2\n1 2 4\n") in ["0", "1", "2", "4"]

# alternating bits
assert run("5 1\n1 2 4 2 1\n") == "7"

 | 6 3、3 1 2 3 1 2 | 3 | フルビットパッキングを繰り返す |

 ## 特殊なケース

 重要なエッジ ケースは、k が 1 に等しい場合です。この場合、配列全体が 1 つのセグメントであるため、答えは単純にすべての要素の OR になります。 実行可能なビットマスクはすべて単一セグメント チェックに合格するため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、k が n に対して大きい場合です。 k がマスク 0 であっても形成できるセグメントの最大数を超える場合、実行可能性チェックはゼロ以外のすべてのマスクに対して正しく失敗し、結果は 0 になります。たとえば、n = 3 および k = 4 の場合、0 以外のマスクは 4 つの有効なセグメントを生成できません。 

より微妙なケースは、ビットがクラスター化されている場合です。 上位ビットが配列の単一領域にのみ現れると仮定します。 貪欲セグメンテーションでは、そのビットを含むセグメントが最大 1 つ作成されるため、たとえ合計で何度も出現したとしても、そのビットのチェックは失敗します。 要件はグローバルな頻度ではなくセグメントごとであるため、これは正しいです。
