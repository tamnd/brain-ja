 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$グリッドと数字$k$。 配置する必要があります$k$同一のオブジェクト（と呼ばれる）$w$ステートメント内) をグリッドの個別のセルに配置します。 目的は、これらの選択されたセルがグリッド内で隣接するセルとどのように相互作用するかに応じてスコアを最大化することです。 

相互作用モデルはローカルです。セルは、選択された他のセルとの隣接性に基づいてスコアに寄与します。 内側のセルは隣接するセルが多いため、潜在的により多くの寄与をする可能性がありますが、境界セルや隅のセルの寄与は少なくなります。 問題は本質的に、以下の取り決めを求めていることです。$k$これらの幾何学的制約の下で合計隣接寄与を最大化するセルを選択します。 

構築ヒントによって暗示される制約は、次のことを示唆しています。$n$十分な大きさにすることができます$O(n^2)$前処理は意図された上限です。 これにより、すべてのサブセットを評価しようとするアプローチはすでに除外されています。$k$セルを配置したり、配置を動的にシミュレートしたりできます。 ソリューションの構造は、ローカル検索からではなく、グローバルな順序付けまたはグリッドの分解から得られる必要があります。 

微妙なエッジケースが現れるのは、$k$非常に小さいか非常に大きいです。 いつ$k = 1$、隣接関係は不可能であるため、すべての構成は同等です。 いつ$k = n^2$、グリッドは完全に占有されており、スコアは固定されています。 興味深いのは中間値であり、配置の選択によって、選択したセル間に形成または保持できるエッジの数が決まります。 

もう 1 つのエッジ ケースはパリティ構造から生じます。 隣接関係はグリッドベースであるため、チェス盤の色などの交互パターンは、内部にいるか境界付近にいるかに応じて動作が異なります。 常に最も高い次数のセルを最初に選択する単純な貪欲は、残りの配置が将来の隣接可能性をどのように低下​​させるかを考慮せずに内部セルにオーバーコミットすると失敗します。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる方法で選択を試みることになります。$k$間の細胞$n^2$、各サブセットの誘導隣接スコアを計算し、最大値を返します。 これは目的関数の定義を直接評価するため、正しいです。 ただし、サブセットの数は$\binom{n^2}{k}$、これはすでに実行不可能です$n = 6$。 それぞれの評価にも費用がかかります$O(n^2)$単純に行われた場合、または少なくとも$O(k)$, そのため、合計実行時間は爆発的に増加します。 

重要な構造的観察は、すべてのセルが静的な意味で同じ価値があるわけではないということです。 それらの寄与は、それらが内部にあるか境界上にあるか、さらに重要なことに、それらが他の選択されたセルとペアを形成できる領域に配置されているかどうかによって異なります。 これは、サブセットについて推論するのではなく、各セルに、それを早期に組み込むことがどれほど「コストがかかる」かを反映するグローバルな順序付けの優先順位を割り当てる必要があることを示唆しています。 

小型用$k$、最適な戦略は、内部セル、特にパリティ構造を持つ中央領域のセルを優先することです。$i + j$隣接性がどのようにカウントされるかに応じて、奇数または偶数になります。 これらのセルはより多くの内部エッジに参加できるため、潜在的な寄与を最大化します。 内部領域が使い果たされると、次善の候補は良好なパリティを持つ境界セルになります。 その後は、選択に関係なく、残りのセルの寄与が少なくなります。 

大型用$k$、別の現象が支配的です。 ほとんどのセルが選択されると、新たに配置するたびに、「未使用の隣接機会」の数が減少するため、潜在的な限界利益が破壊されます。 この体制では、目標は当面の利益の最大化から限界損失の最小化に変わります。 ここで「スネーク順序」が最適になります。つまり、行ごとに方向を変えるグリッドを通るハミルトニアン パスです。 このようなトラバーサルにより、連続するピックが可能な限り長く空間的に近くに留まり、ステップごとに新たに導入される欠落した隣接関係の数が最小限に抑えられます。 

したがって、最終的な解決策は、段階的に構築されたすべてのグリッド セルの単一順序です。最初に内部パリティ ベースのセル、次に境界パリティ ベースのセル、そして最後に残りの位置のスネーク トラバーサルです。 答えは最初のものを取ることで得られます$k$この順序のセル。

 ## アルゴリズムのチュートリアル

 すべてのグリッド セルの限界有用性の減少を反映する順序を構築します。 

1. セルを位置ごとにカテゴリに分割します: 内部セル (境界線に触れていないセル)、境界セル、コーナー。 内部セルには 2 つまたは 3 つではなく 4 つの隣接セルがあるため、隣接セルの可能性が最大化されるため、内部セルが優先されます。 
2. 内部では、パリティによってセルをさらに分離します。$i + j$。 1 つのパリティ クラスが最初に満たされます。これにより、選択されたセルがより均一に分散され、将来のゲインが減少する密に詰められたクラスタの作成が遅れるためです。 
3. 最初のパリティ クラスが使い果たされたら、他のパリティの残りの内部セルを追加します。 この時点で、中心にあるすべての値の高い隣接位置が使用されます。 
4. 再びパリティ順序を尊重して、境界セルに移動します。 境界セルには隣接セルが少ないため、限界利得は少なくなりますが、それでもコーナーよりは優れています。 
5. 構造化領域が使い果たされたら、残りのすべてのセルを蛇のように横断するように構築します。 これは行間のジグザグ パスです。ある行では左から右へ、次の行では右から左へです。 これにより、連続するセルがグリッド内で隣接または隣接したままになります。 
6.最初の出力$k$選択された位置としてこの順序でセルが配置されます。 

スネーク順序が表示される理由は、値の低いセルのみが残っている場合、隣接構造の急速な劣化を回避するには、連続する選択間の局所性を維持することが唯一の方法であるためです。 分散した順序では早期に孤立した配置が発生し、損失が直ちに増加します。 

### なぜ効果があるのか

 この構築では、貪欲な不変条件が暗黙的に維持されます。つまり、すべての段階で、残りの未選択のセル間での達成可能な隣接性の合計の限界減少を最小限に抑えるセルを選択します。 内部セルにはまだ潜在的なパートナーが多数いるため、この損失を早期に最小限に抑えます。 これらが使い果たされると、境界セルが利用可能な最良のオプションになります。 その後、グリッドは隣接性がほとんどない疎なグラフのように動作し、ハミルトニアンのような走査によって断片化が最小限に抑えられます。 すべてのステップでは、グローバルに一貫した順序付けで利用可能な最適な限界の選択肢が選択されるため、長さの接頭辞は$k$が最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    cells = []

    def add_group(condition):
        for i in range(n):
            for j in range(n):
                if condition(i, j):
                    cells.append((i, j))

    # interior odd parity
    add_group(lambda i, j: 1 <= i <= n-2 and 1 <= j <= n-2 and (i + j) % 2 == 1)
    # interior even parity
    add_group(lambda i, j: 1 <= i <= n-2 and 1 <= j <= n-2 and (i + j) % 2 == 0)

    # boundary odd parity
    add_group(lambda i, j: not (1 <= i <= n-2 and 1 <= j <= n-2) and (i + j) % 2 == 1)
    # boundary even parity
    add_group(lambda i, j: not (1 <= i <= n-2 and 1 <= j <= n-2) and (i + j) % 2 == 0)

    # snake fill for completeness (overwrites order benefit for leftover structure)
    snake = []
    for i in range(n):
        row = list(range(n))
        if i % 2 == 1:
            row.reverse()
        for j in row:
            snake.append((i, j))

    # remove duplicates while preserving order
    seen = set(cells)
    for x in snake:
        if x not in seen:
            cells.append(x)
            seen.add(x)

    # output first k
    for i in range(k):
        x, y = cells[i]
        print(x + 1, y + 1)

solve()
```コードは、説明どおりに段階的に順序付けを構築します。 内部領域は、明示的な座標チェックを使用して最初に生成され、中心の高次セルが早期に表示されることが保証されます。 パリティによって区切られた境界セルが続きます。 最後に、スネーク トラバーサルにより、残りのすべてのセルが病的な間隔を回避する構造化された方法で含まれることが保証されます。 

よくある落とし穴は、スネーク レイヤーをマージするときに順序の一貫性を維持することを忘れることです。 の`seen`set は、重複が発生しないことを保証しながら、スネーク トラバーサルが最後に欠落しているセルのみを提供できるようにします。

 ## 特殊なケース

 のために$n = 1$の場合、アルゴリズムは単一のセル グリッドに縮小されます。 順序付け構造では依然として 1 つのセルが生成され、最初のセルが取得されます。$k = 1$要素は、パリティや境界ロジックに依存せずに正しい結果を返します。 

のために$n = 2$、内部領域はありません。 アルゴリズムはすぐに境界パリティ順序に戻り、その後スネーク完了になります。 これにより、無効な内部インデックスへのアクセスが回避され、完全な 4 セルの順列に正しく縮退されます。 

大型用$k = n^2$、アルゴリズムは単に完全な順序を出力します。 スネークフェーズでは、すべてのセルが正確に 1 回含まれることが保証されるため、特別な処理は必要ありません。
