 ## 解決策
 ## 問題の理解

 複数の行と列を含む長方形のグリッドが与えられます。 このグリッドの各セルには風船または爆弾が含まれています。 2 人のエージェントがグリッド内を行ごとに移動し、各行でその行内の位置を選択して風船を収集します。 ボムの存在により、特定の遷移で行のどのセグメントを安全に使用できるかが制限されます。 

このタスクは、列全体で位置を固定して「維持」するか、爆弾で囲まれた安全な間隔内でアクティブな位置を「移動」するかによって決まる動的移動ルールに基づいて、すべての列で収集できる風船の最大数を計算することです。 

各行はセグメント化された線のように動作します。爆弾は行を独立した連続した安全な間隔に分割します。 各間隔内では、動きと寄与は独立して計算できますが、行間の遷移は爆弾によって引き起こされる構造を尊重する必要があります。 

ソリューション構造によって暗示される制約は、グリッド サイズが十分に大きいため、$O(nm)$または$O(nm \log m)$解決策が期待されており、列に対する行ごとの二次アプローチは遅すぎます。 これにより、連続する行間の位置のすべてのペアに対する単純な再計算が即座に排除されます。 

孤立したセルを除いて列が爆弾によって完全にブロックされた場合、微妙なエッジケースが発生します。 このような場合、有効な間隔の長さは 1 つの位置まで縮小する可能性があり、遷移では無効な範囲を前方に持ち越すのではなく、寄与を正しくリセットする必要があります。 

爆弾が境界にある場合、別のエッジケースが発生します。 たとえば、最初または最後の列に爆弾が含まれている場合、安全な間隔の境界がシフトし、これらの境界の計算時に 1 つずつずれると、不正確な DP 遷移が発生します。 

## アプローチ

 ブルート フォース アプローチでは、有効な位置構成をすべて維持しながら、2 人のエージェントが行間を移動できるすべての可能な方法をシミュレートしようとします。 行ごとに 1 つの「ピボット」位置だけを追跡したとしても、各状態は次のように遷移するため、これはすぐに爆発します。$O(m)$次の行に可能性があります。 以上$n$これは行になります$O(nm^2)$、これは大規模なグリッドでは実現できません。 

重要な点は、実際には両方のエージェントを明示的に追跡する必要がないということです。 いつでも、一方の位置をトランジションを固定するピボットとして扱うことができ、もう一方の位置はその周囲の可能な限り最良のセグメントに基づいて貢献します。 これにより、状態空間が行ごとに 1 つの位置に折りたたまれ、DP 状態が生成されます。$dp[i][j]$、ピボットが列にあるときの最高スコアを意味します$j$並んでいる$i$。 

ここから、2 種類のトランジションが現れます。 まず、ピボットを固定したまま垂直方向に拡張し、その行の最大安全な水平セグメントから寄与を収集します。$j$。 2 番目に、ピボットを切り替えることができます。これにより、爆弾のないセグメント内で水平方向にどれだけ移動するかに応じてトランジションが導入されます。 この 2 番目の遷移は、次の線形式のみに依存する構造を持っています。$j$、プレフィックス/サフィックスの最大値を使用した最適化が可能になります。 

ブルート フォースは、列のペアごとに遷移を再計算するため、時間がかかります。 最適化されたソリューションが機能するのは、爆弾のない間隔内では、寄与がフォームの式の最大化に減少するためです。$dp[i-1][k] - k + j$、これは実行最大値を使用して維持できます。

 ## アルゴリズムのチュートリアル

 列全体の DP 配列を維持しながら、グリッドを行ごとに処理します。 

1. 最初の行の DP 配列を初期化します。 各列について、そのセルのみからの最良の寄与を計算し、それを最初のピボットとして扱います。 これにより、前の行制約が存在しない基本状態が設定されます。 
2. 後続の各行について、まず安全な間隔を特定します。 行をスキャンして列ごとに計算します$j$、左右に最も近い爆弾。 これによりセグメントが定義されます$[l, r]$有効な動きはすべて$j$この間隔内にとどまる必要があります。 
3. 「垂直拡張」遷移を計算します。 ピボットを列に置いた場合$j$、前の値を拡張し、周囲にある最大の連続した爆弾のないセグメントの寄与を追加します。$j$。 これは、ステップ 2 で決定された間隔の長さにのみ依存します。 
4. 各安全セグメント内の左から右への遷移を計算します。 現在の最大値を維持します$dp[i-1][k] - k$。 移動中$j$セグメント内を左から右に向かって、この最大値を更新し、次の形式の候補値を計算します。$max(dp[i-1][k] - k) + j$。 これはピボット位置を切り替えるケースを捉えています。 
5. 右から左への遷移も同様に計算します。 これにより、最良の先行者が右側にある場合が保証されます。$j$も線形化された形式を使用してカバーされています$dp[i-1][k] + k + j$適当に変換しました。 
6. 両方向の処理が完了したら、ファイナライズします。$dp[i][j]$垂直方向の拡張とピボットスイッチのトランジションの最大値として。 
7. すべての行に対してこれを繰り返し、最後の DP 行の最大値を返します。 

### なぜ効果があるのか

 DP 状態は、すべての構成を行ごとに 1 つのアクティブな列に圧縮します。これは、2 番目の位置がボムによって境界付けられた連続した間隔を通じて寄与していると解釈できるためです。 爆弾のないセグメント内では、すべての有効な遷移は列インデックスの線形関数に変換されます。 これにより、遷移の最適な選択が常に極端に存在するか、プレフィックスまたはサフィックスの最大値によって捕捉できることが保証されます。 各行はこれらの最大値に関して独立して処理されるため、グローバル構造が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    dp = [0] * m

    for i in range(n):
        left_bomb = [-1] * m
        right_bomb = [m] * m

        last = -1
        for j in range(m):
            if grid[i][j] == '#':
                last = j
            left_bomb[j] = last

        last = m
        for j in range(m - 1, -1, -1):
            if grid[i][j] == '#':
                last = j
            right_bomb[j] = last

        new_dp = [0] * m

        j = 0
        while j < m:
            if grid[i][j] == '#':
                j += 1
                continue

            l = j
            while l > 0 and grid[i][l - 1] != '#':
                l -= 1
            r = j
            while r < m - 1 and grid[i][r + 1] != '#':
                r += 1

            best = 0

            max_left = -10**18
            for k in range(l, r + 1):
                max_left = max(max_left, dp[k] - k)
                best = max(best, max_left + k + (r - k + 1))

            max_right = -10**18
            for k in range(r, l - 1, -1):
                max_right = max(max_right, dp[k] + k)
                best = max(best, max_right - k + (k - l + 1))

            for k in range(l, r + 1):
                best = max(best, dp[k] + max(k - l + 1, r - k + 1))

            for k in range(l, r + 1):
                new_dp[k] = best

            j = r + 1

        dp = new_dp

    print(max(dp))

if __name__ == "__main__":
    solve()
```実装は行ごとの DP 構造に従います。 配列`left_bomb`そして`right_bomb`計算されますが、主にセグメンテーションを理解するために使用されます。 実際のセグメンテーションは、簡素化のために間隔ごとにローカルに再計算されます。 連続する爆弾のない各セグメントが抽出され、その中で、左から右へのピボット切り替え、右から左へのピボット切り替え、および垂直方向の拡張という 3 つの寄与を評価します。 

実装の微妙な詳細は、未訪問の各セルから拡張することによって安全なセグメント境界を直接再計算することです。 これにより、マージ間隔でのエラーが回避され、複数の分離されたセグメントが存在する場合でも正確さが保証されます。 

線形最大値の計算`dp[k] - k`そして`dp[k] + k`変換された遷移式に直接対応し、各候補ピボットが効率的に考慮されるようにします。

 ## 特殊なケース

 完全に爆撃された行は、DP が無効な遷移を正しく回避するかどうかをテストします。 このような場合、すべての列が到達不能になり、セグメントをリセットまたは分離しない実装では値が誤って伝播されます。 

列 0 または列 m-1 の境界ボムは、区間拡張におけるオフバイワンエラーをテストします。 正しい動作は、安全な間隔が適切に縮小し、グリッドを超えて拡張しようとしないことです。 

行全体にわたる単一の長いセグメントは、プレフィックス/サフィックスの最大値がクロスポジションの遷移を二重にカウントすることなく正しくキャプチャしているかどうかをチェックします。
