 ## 解決策
 ## 問題の理解

 一列に並んで座っているレッサー パンダのシーケンスが与えられます。各パンダには整数の ID が付いています。 私たちが関心を持っているプロセスでは、これらの ID を値の昇順に繰り返し調べます。現在の行に特定の ID が表示されるたびに、その時点で残っているパンダの数に応じて、その ID を持つすべてのパンダが答えに貢献します。 ID を処理した後、その ID を持つすべてのパンダが行から削除され、残りの ID を使用してプロセスが続行されます。 

出力は、ID が削除される前にまだ存在していたパンダの数に基づいて、各 ID からの貢献をカウントする単一の累積値です。 

重要な制約は、ID が以下によって制限されることです。$10^6$、典型的なものよりもはるかに小さい$n$これらの問題では。 これは、すべての要素を繰り返し反復することが不可能であっても、値の範囲を反復することが実行可能である可能性があることを直ちに示唆しています。 

素朴な解釈では、配列またはリスト上で直接削除をシミュレートすることになります。 それが失敗するのは、$n$リストから要素を繰り返し削除すると、操作ごとに線形になり、二次的な動作が発生するため、この値は大きくなります。 

ID が繰り返されると、微妙なエッジケースが発生します。 すべての要素が同じ ID を共有する場合、1 つずつ削除する単純なシミュレーションは論理的に機能しますが、不必要に遅くなります。 別のエッジ ケースは、ID がまばらだが大きい場合、たとえば ID に単一の要素がある場合に発生します。$10^6$他のすべては小さな値です。 固定境界ではなく最大要素までのみをスキャンするソリューションは引き続き機能しますが、より狭い範囲の密な ID を想定した不注意な実装は機能しません。 

## アプローチ

 ブルートフォース手法では、ラインを直接シミュレートします。 各ステップで、現在のリストをスキャンし、ソートされた順序で次の ID の出現をすべて検索し、リストの現在の長さに基づいてそれらの寄与を計算し、それらを削除し、繰り返します。 プロセス定義を正確に反映しているため、正確性は簡単です。 

問題は、削除するたびにスキャンが必要になり、サイズのリストを変更する可能性があることです。$n$。 最大で繰り返し実行すると、$n$異なる ID の場合、最悪のケースは次のようになります。$O(n^2)$これは、一般的な制約に対して遅すぎます。 

重要な観察は、実際には、進化するリストを明示的に維持する必要がないということです。 重要なのは、各 ID の要素がいくつ存在するか、および特定の ID を処理する前に要素がいくつ残っているかです。 頻度を事前に計算すると、構造内でまだ「生きている」要素の数を表す単一の変数を追跡できます。 次に、ID を昇順にスイープすると、各 ID は、削除される前に、その頻度に残りの要素の数を乗算したものになります。 

これにより、問題は動的な除去から値空間にわたる静的なスイープに変換されます。

 ## アルゴリズムのチュートリアル

 考えられるすべての ID にわたる頻度配列と、行内にまだ残っている要素の数を表す変数を維持します。 

1. すべての ID を読み取り、頻度配列での出現数をカウントします。 これにより、元の順序を必要とせずに、各値が何回出現するかを正確に知ることができます。 
2. 変数を初期化する$remaining = n$、削除が行われる前にまだ存在しているパンダの数を表します。 
3. 回答アキュムレータを初期化する$ans = 0$。 
4. 1 から 2 までのすべての可能な ID を繰り返します。$10^6$。 プロセスでは ID が昇順で削除されるため、これを昇順で実行します。これは、この行の概念的な進化と一致します。 
5.IDごと$v$、その頻度がゼロの場合、何も寄与せず、状態を変更しないため、スキップします。 
6. 頻度がゼロ以外の場合、残りのすべてのパンダがまだ存在している間、この ID を持つすべてのパンダが貢献します。 追加します$remaining \times freq[v]$答えに。 
7.ID処理後$v$を減らすことで、すべての出現を論理的に削除します。$remaining$による$freq[v]$。 

重要な考え方は、ID に到達したら$v$、以下のすべての ID$v$すでに処理され削除されているため、$remaining$現在および将来の ID の貢献ベースのみを正しく反映します。 

### なぜ効果があるのか

 スイープのどの時点でも、変数$remaining$ID がまだ処理されていない要素の総数に等しくなります。 ID を昇順に処理するため、これは、現在の ID を削除する直前にシミュレートされた行にまだ存在する要素の数と正確に一致します。 特定の ID のすべての要素は一度だけ貢献し、その ID が処理された瞬間にのみ貢献します。 の乗算$remaining$は、各出現が現在削除されていないすべての要素と相互作用するという事実を捕らえ、その頻度を削除すると、将来のステップのために不変式が保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 10**6

n = int(input().strip())
arr = list(map(int, input().split()))

freq = [0] * (MAXV + 1)

for x in arr:
    freq[x] += 1

remaining = n
ans = 0

for v in range(1, MAXV + 1):
    if freq[v] == 0:
        continue
    ans += remaining * freq[v]
    remaining -= freq[v]

print(ans)
```この解決策は、入力を読み取り、周波数配列を構築することから始まります。これにより、構造全体が値ごとのカウントに圧縮されます。 これにより、順序を維持したり、削除をシミュレートしたりする必要がなくなります。 

変数`remaining`中央の状態トラッカーです。 これは常に、スイープ内でまだ「考慮されていない」要素の数を表します。 値を処理するたびに`v`、投稿後にそのすべての出現が削除されると想定します。 

掛け算`remaining * freq[v]`重要な計算ステップです。 値が発生するたびにそれを捕捉します`v`現在残っている構造と相互作用します。 この寄与を加算した後、減算します`freq[v]`なぜなら、それらの要素は将来のインタラクションの一部ではなくなるからです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    MAXV = 10**6

    n = int(input().strip())
    arr = list(map(int, input().split()))

    freq = [0] * (MAXV + 1)
    for x in arr:
        freq[x] += 1

    remaining = n
    ans = 0

    for v in range(1, MAXV + 1):
        if freq[v] == 0:
            continue
        ans += remaining * freq[v]
        remaining -= freq[v]

    return str(ans)

# custom cases
assert run("1\n5\n") == "1", "single element"
assert run("3\n1 1 1\n") == "9", "all equal values"
assert run("4\n4 3 2 1\n") == "20", "already decreasing order"
assert run("5\n2 3 2 3 2\n") == "21", "repeated mixed values"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一要素 | 1 | 最小限の大文字と小文字の正確性 |
 | すべて等しい値 | 9 | 繰り返しIDの処理 |
 | 降順 | 20 | 独立性を注文する |
 | 混合反復 | 21 | 複数の周波数の相互作用 |

 ## 特殊なケース

 次のような単一要素入力の場合`n = 1, arr = [7]`、周波数配列にはゼロ以外のエントリが 1 つだけあります。 アルゴリズムセット`remaining = 1`、プロセスID 7、追加`1 * 1 = 1`これにより、相互作用が不可能な最小状態での正しさが確認されます。 

すべての値が同一である場合、たとえば、`n = 4, arr = [3, 3, 3, 3]`の場合、スイープではアクティブな ID が 1 つだけ検出されます。 その瞬間、`remaining = 4`、つまり貢献度は`4 * 4 = 16`、すべての要素が削除されます。 これは、位置シミュレーションを必要とせずに、同一 ID のグループ化が正しく処理されていることを示しています。 

次のような疎な大きな ID の場合`arr = [1, 1000000]`の場合、アルゴリズムは最初に ID 1 を処理し、次に ID 1000000 に直接ジャンプします。ゼロ頻度エントリをスキップすると、次の不変式が保持されるため、中間値が存在しないことは正確さに影響しません。`remaining`常に未処理の要素のみを反映します。
