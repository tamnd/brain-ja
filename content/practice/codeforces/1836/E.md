 ## 解決策
 ## 問題の理解

 各テスト ケースに対して一連の整数が与えられ、このシーケンスの連続したセグメントを調べることができます。 どのセグメントについても、その値をその内部のすべての要素のビット単位の XOR として定義します。 タスクは、XOR 値が同一である 2 つの互いに素なセグメントを見つけることができるかどうかを判断し、見つかった場合はそのようなセグメントのペアを出力することです。 

入力の構造は意図的に制限されています。特に、配列の長さは常に 2 のべき乗です。$2^{k+1}$、各要素は次によって囲まれます。$4^k$。 これが重要なのは、サブ配列の XOR 値がプレフィックス XOR の差のように動作し、これだけ多くのセグメントが利用可能な場合、すべての間隔を単純に列挙すると、$O(n^2)$候補が多すぎる場合、$n$到達できる$2^{18}$。 

単純なアプローチでは、部分配列のすべてのペアに対して XOR を計算し、素性を確保しながらすべてのペアが等しいかどうかを比較します。 これはすぐに発生します$O(n^4)$直接実行された場合の動作、または$O(n^3)$プレフィックスの最適化を行っても、上限に達すると使用できなくなります。 

主な困難は、XOR を効率的に計算することではなく、すべてのセグメントのペアを明示的に比較しないように検索を編成することです。 

単純な思考を打ち破るエッジ ケースには、すべての要素が同一である配列、すべての部分配列の XOR が小さな値のセットに折りたたまれる場合、一致するセグメントが存在するものの重なりが大きく、素性を慎重に処理する必要がある場合などがあります。 たとえば、次のような定数配列では、$[0,0,0,0]$、すべてのセグメントの XOR は 0 であるため、結合していない 2 つのセグメントは有効ですが、不注意に実装すると重複するセグメントが誤って選択されたり、間隔を正しく区別できなかったりする可能性があります。 

## アプローチ

 開始点としては、プレフィックス XOR を使用してすべてのセグメント XOR を書き直すと便利です。 定義すると$p[i]$最初の XOR として$i$要素、次にセグメントの XOR$[l, r]$単純に$p[r] \oplus p[l-1]$。 これにより、セグメントの比較がプレフィックス値間の関係に変換されます。 

ここで問題は、インデックスを見つけることです。$a < b < c < d$そのような$$p[b] \oplus p[a-1] = p[d] \oplus p[c-1]$$ばらばらな間隔で。 並べ替えると次のようになります。$$p[b] \oplus p[d] = p[a-1] \oplus p[c-1]$$したがって、同じ XOR 差を生成する 2 つの素のプレフィックス インデックスのペアを探します。 

ブルートフォースアプローチでは、すべてが列挙されます。$O(n^2)$サブ配列の XOR を計算して保存し、同じ値を持つ 2 つの互いに素な配列があるかどうかを確認します。 サブ配列の数がおよそであるため、これは失敗します。$n^2/2$、そしてそれらを比較することは再び二次関数であり、少なくとも次のようになります$O(n^4)$実際の行動。 

重要な構造的洞察は、実際にはすべてのサブ配列を個別に考慮する必要がないということです。 代わりに、制限された値空間と、XOR がプレフィックスの違いに対して線形であるという事実を利用します。 これを圧縮する古典的な方法は、プレフィックス XOR 状態を調べ、構造化スイープで繰り返される構成を検索することです。 

XOR 値から最古および最新の出現までのハッシュ マップを維持しながらプレフィックス XOR を処理しますが、等しいセグメント XOR ではなく、同一のプレフィックス値のみが得られるため、それだけでは不十分です。 重要な改良点は、1D プレフィックス空間で 2 つの等しい差分を効果的に探していることを認識することです。これは、変換された状態空間で 2 つの等しいエンドポイントのペアを見つけるのと同じです。 

これは、次の形式の値間の衝突を検出するものとして再構成できます。$$(p[i], i)$$そして、互いに素な間隔で繰り返される XOR 関係を検索します。 意図したソリューションでは、中間結合スタイルのパーティションを使用します。つまり、配列を 2 つの半分に分割し、それぞれの半分ですべてのサブ配列 XOR を列挙し、自動的に素性を確保しながら半分間で同一の XOR 値を照合します。 

左半分のすべてのサブ配列と右半分のすべてのサブ配列を格納することにより、慎重なインデックスの順序付けを使用して、半分全体または半分内で一致させるだけで済みます。 各半分には最大サイズがあります$2^{k}$、したがって、半分あたりの部分配列は次のようになります。$O(2^{2k})$ただし、テスト ケース間の制約の合計により、これは管理可能に保たれます。 

XOR グループが収集されたら、少なくとも 2 つの互いに素なセグメントに出現する XOR 値を検出するだけで済みます。これは、それが 1 つの半分に 2 回、または各半分に 1 回出現する場合に保証されます。

 ## アルゴリズムのチュートリアル

 1. プレフィックス XOR 配列を構築する$p$、 どこ$p[i]$最初の XOR を格納します$i$要素。 これにより、任意のセグメントに対して定数時間の XOR クエリが可能になります。 
2. 配列を中間点で左右に 2 つに分割します。 分割する理由は、サブ配列の生成を可能にするために列挙を制限するためです。 
3. 左半分の内側にあるすべてのサブ配列を列挙します。 各サブ配列について、プレフィックス XOR を使用して XOR を計算し、XOR 値をキーとするハッシュ マップに間隔を格納します。 
4. 右半分に対して同じ列挙を実行し、同じ構造に間隔を追加します。 
5. 各 XOR 値について、互いに素な間隔が少なくとも 2 つあるかどうかを確認します。 間隔はエンドポイントとともに保存されるため、エンドポイントを並べ替えて、ある間隔が別の間隔が開始する前に終了するかどうかを確認することによって、強制的に非結合性を保つことができます。 
6. 有効な XOR バケットが見つかった場合は、2 つの互いに素な間隔を出力して停止します。 そのようなペアがバケットに含まれていない場合は、-1 を出力します。 

### なぜ効果があるのか

 すべてのサブ配列はプレフィックス インデックスのペアによって一意に表され、XOR の等価性はそれらのプレフィックス状態の違いのみに依存します。 XOR 値でサブ配列をグループ化することで、構造化セット内の重複の検出の問題を軽減します。 間隔はエンドポイントとともに明示的に保存されるため、順序付け情報が失われることはなく、各 XOR バケット内でローカルに素性を検証できます。 有効なソリューションはこれらのバケットのいずれか内に存在する必要があるため、正確さを保証するにはすべてのバケットをスキャンするだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(k, arr):
    n = len(arr)
    p = [0] * (n + 1)
    for i in range(n):
        p[i + 1] = p[i] ^ arr[i]

    mid = n // 2

    buckets = {}

    def add(l, r):
        xr = p[r] ^ p[l - 1]
        if xr not in buckets:
            buckets[xr] = []
        buckets[xr].append((l, r))

    for i in range(1, mid + 1):
        for j in range(i, mid + 1):
            add(i, j)

    for i in range(mid + 1, n + 1):
        for j in range(i, n + 1):
            add(i, j)

    for xr, segs in buckets.items():
        if len(segs) < 2:
            continue
        segs.sort()
        best_r = -1
        best_l, best_r2 = None, None

        for l, r in segs:
            if best_r < l:
                if best_l is not None:
                    return best_l, best_r2, l, r
                best_l, best_r2 = l, r
            else:
                if r > best_r:
                    best_l, best_r2 = l, r
                    best_r = r

        if best_l is not None and best_r2 is not None:
            for l, r in segs:
                if r < best_l:
                    return l, r, best_l, best_r2

    return -1

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        k = int(input())
        arr = list(map(int, input().split()))
        res = solve_case(k, arr)
        if res == -1:
            out.append("-1")
        else:
            out.append(" ".join(map(str, res)))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは、セグメント XOR を定数時間で計算できるように、プレフィックス XOR を構築することから始まります。 配列は 2 つの半分に分割され、各半分内のすべてのサブ配列が明示的に列挙されます。 各部分配列は、元の間隔を維持しながら、XOR 値をキーとする辞書に挿入されます。 

グループ化後、各 XOR クラスが個別にチェックされます。 ソートのステップにより、重複しない 2 つのセグメントを貪欲に選択できることが保証されます。 貪欲スキャンは、これまでに確認された最良の候補間隔を維持し、間隔が終了した後に次の間隔が始まるかどうかをチェックして、非結合性を保証します。 

重要な点は、任意のペアをグローバルに比較しないことです。 同一の XOR バケット内でのみ比較するため、検索スペースが大幅に削減されます。

 ## 特殊なケース

 配列の要素が 1 つだけの最小入力では、2 つの互いに素なセグメントを生成することはできず、アルゴリズムは少なくとも 2 つの有効な間隔を持つバケットを正しく形成することはありません。 

完全にゼロの配列では、考えられるすべてのセグメントが同じ XOR クラスに属します。 XOR ゼロのバケットは非常に大きくなりますが、ソートされた間隔にわたる貪欲スキャンでは、次のような 2 つの互いに素なセグメントがすぐに見つかります。$[1,1]$そして$[2,2]$、最大の衝突下での正しさを示します。 

XOR キャンセルが発生する交互パターンでは、有効なペアは半分にまたがってのみ存在する可能性があります。 分割およびグループ構造により、両方の半分が候補を同じ XOR バケットに提供できるため、境界を越えた推論は必要ありません。
