 ## 解決策
 ## 問題の理解

 次の形式の有効な方程式をすべて列挙するように求められます。`a + b = c`ただし、桁長には厳密な制約があります。`a`正確に持っている必要があります`A`数字、`b`その通り`B`数字と`c`その通り`C`数字。 どの数値もゼロで始めることはできず、3 つの値はすべて正の整数でなければなりません。 

このようなすべての有効なトリプルの中で、概念的には各方程式を次のような単一の文字列として記述します。`a + b = c`これらの文字列を辞書順に並べます。 タスクは、この順序で k 番目の文字列を返すか、存在する有効な方程式が k 個未満であることを報告することです。 

重要な問題は、k が 10¹² まで大きくなる可能性がある一方で、桁の長さが小さい (最大 6) ことです。 これにより、すべての有効なトリプルが明示的に生成されなくなります。 最悪の場合でも、候補の数は変数あたり約 9·10⁵ で、(a, b) の組み合わせは約 10¹⁷ となり、合計制約によるフィルタリング後でも、総当たりの列挙は実行できません。 

2 番目の微妙な点は、辞書編集順が数値タプルではなく、書式設定された文字列に対して行われることです。 これは、順序付けが主に次の桁によって行われることを意味します。`a`、 それから`b`、 それから`c`、固定長フォーマットを含む。 例えば、`"10 + 2 = 12"`そして`"2 + 10 = 12"`数値の大きさではなく、文字の比較に基づいて順序付けされます。 

素朴なソリューションを壊すエッジケースには、次のような状況が含まれます。 

最小限の`a`そして`b`すでに可能な最大値を超えています`c`、解決策が存在しないことを意味します。 例えば、`A = B = C = 2`最小値を与える`a = b = 10`、 しかし`10 + 10 = 20`有効です。 ただし、場合`C = 1`、その後最大`c = 9`、したがって解決策は存在しません。 

もう 1 つの失敗モードは、辞書編集上の順序を無視し、代わりにトリプルを番号順に生成することです。`(a, b, c)`、文字列の順序とは異なるシーケンスが生成されます。 例えば、`"1 + 10 = 11"`前に来る`"2 + 1 = 3"`文字比較のため辞書順に。 

最後に、微妙な問題は、固定桁長にわたってキャリー制約が適切に処理されない場合に、桁 DP または組み合わせ計数を使用するときに、有効な合計が過大にカウントされたり欠落したりすることです。 

## アプローチ

 ブルートフォースアプローチでは、有効なすべてのデータに対して反復処理が行われます。`a`そして`b`桁の範囲で計算します`c = a + b`、どうかを確認してください`c`まさに`C`数字を入力し、すべての有効なトリプルを保存します。 それらを収集した後、それらを文字列としてソートし、k 番目の要素を選択します。 

これは正しいですが、すぐに遅すぎます。 たとえ`A = B = C = 6`、それぞれに最大 10⁶ の値を持つことができます。`a`そして`b`、10¹²ペアを生成します。 一部のみが有効な場合でも、列挙することはできません。 

重要な観察は次のとおりです`A, B, C ≤ 6`, そのため、数字を列挙するのではなく、数字ごとに数えたり、解決策を構築したりする余裕があります。 加算制約は次の桁を結合します。`a`そして`b`したがって、値を反復する代わりに、問題を位置に対する数字の DP として扱います。 

キャリーを追跡しながら、最上位桁から最下位桁まで数値を構築します。 各位置で、次の数字を選択します。`a`そして`b`先行ゼロ制約と一致し、結果の桁を計算します。`c`。 この構造により、特定のプレフィックスに存在する補完の数を数えることができます。 接尾辞の補完をカウントできるようになると、桁を順番に固定してカウントを減算することで、k 番目の辞書編集ソリューションを貪欲に構築できます。

 | 数字 DP + 貪欲な構築 | テストごとに O(A・B・C・10・キャリー) | O(状態) | 承認済み |

 ## アルゴリズムのチュートリアル

 各数値を固定長の数字配列として扱い、先頭のゼロは禁止されています。 各位置の有効な桁の範囲を事前に計算します。 

1. DP 関数を定義する`dp(i, carry)`これは、数字からポジションを埋めることができる方法が何通りあるかを数えます`i`前のそれほど重要ではない位置からのキャリーが与えられた場合、最後まで。 この機能は数字の選択に依存します`da`そして`db`位置にある`i`、数字を生成します`dc`そして次は運ぶ。 
2. 最下位桁から最上位桁まで DP を計算します。 状態ごとに、すべての数字のペアを反復処理します。`(da, db)`先行ゼロ制約の下で有効であり、遷移を累積します。 これにより、各接尾辞の有効な補完の数がわかります。 
3. DP テーブルの構築後、最初に有効な方程式の総数をチェックします。 もし`k`この合計を超えると、出力します`-1`。 
4. それ以外の場合は、最上位桁から最下位桁まで貪欲に答えを構築します。 各ステップで、候補となる数字のペアを試します`(da, db)`辞書順に並べ、DP カウントを使用して各選択肢で有効な補完の数を決定します。 
5. 候補の選択肢が以下の場合`k`完了した場合は、それを差し引きます`k`そしてそれをスキップします。 k 番目の解を含む選択肢が見つかったら、それらの数字を修正して先に進みます。 
6. すべての桁を埋めた後、次のように再構築します。`a`、`b`、 そして`c`そしてそれらを文字列としてフォーマットします。 

機能する理由: DP は、以前の選択とは関係なく、すべてのプレフィックス状態について、有効なサフィックス補完がいくつ存在するかを正確に把握できるようにします。 これにより、ソリューション空間の一貫したパーティションが得られます。 貪欲選択では、辞書順で目的の k 番目の解がブロックに含まれる最初の桁の選択肢が常に選択されます。DP カウントは有効な継続の数と正確に一致するため、解がスキップされたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(A, B, C, k):
    # dp[pos][carry] -> number of ways from pos to end
    # pos goes from 0 (most significant) to max(A,B,C)-1
    n = max(A, B, C)

    # pad lengths
    def get_digit(x, pos, length):
        # position from left
        if pos < n - length:
            return 0, True  # leading zero not allowed if pos == first real digit
        return None, False

    # We instead explicitly handle allowed digit ranges per position
    dp = [[0] * 2 for _ in range(n + 1)]
    dp[n][0] = 1

    for i in range(n - 1, -1, -1):
        for carry in range(2):
            total = 0
            a_start = 1 if i == 0 else 0
            for da in range(10):
                if i < n - A and da != 0:
                    continue
                if i == n - A and da == 0:
                    continue

                for db in range(10):
                    if i < n - B and db != 0:
                        continue
                    if i == n - B and db == 0:
                        continue

                    s = da + db + carry
                    dc = s % 10
                    nc = s // 10

                    if i < n - C and dc != 0:
                        continue
                    if i == n - C and dc == 0:
                        continue

                    total += dp[i + 1][nc]
            dp[i][carry] = total

    if dp[0][0] < k:
        return "-1"

    a_digits = []
    b_digits = []
    c_digits = []
    carry = 0

    for i in range(n):
        for da in range(10):
            if i < n - A and da != 0:
                continue
            if i == n - A and da == 0:
                continue

            for db in range(10):
                if i < n - B and db != 0:
                    continue
                if i == n - B and db == 0:
                    continue

                s = da + db + carry
                dc = s % 10
                nc = s // 10

                if i < n - C and dc != 0:
                    continue
                if i == n - C and dc == 0:
                    continue

                cnt = dp[i + 1][nc]
                if cnt < k:
                    k -= cnt
                else:
                    a_digits.append(str(da))
                    b_digits.append(str(db))
                    c_digits.append(str(dc))
                    carry = nc
                    break
            else:
                continue
            break

    a = ''.join(a_digits)
    b = ''.join(b_digits)
    c = ''.join(c_digits)
    return f"{a} + {b} = {c}"

t = int(input())
for _ in range(t):
    A, B, C, k = map(int, input().split())
    print(solve_case(A, B, C, k))

構築中、候補を辞書編集上の桁順に繰り返します。 それぞれについて`(da, db, dc)`キャリーによって暗示される、私たちは使用します`dp[i+1][nc]`このプレフィックスで始まる完全なソリューションがいくつあるかを判断します。 そのブロックに k 番目の解が含まれていない場合は、減算して次に進みます。 それ以外の場合は、その数字をコミットして先に進みます。 

最もデリケートな部分は、固定桁長を正しく適用することです。 条件`i < n - A`、`i == n - A`先頭の数字がゼロ以外になるように強制し、埋め込まれたグリッドに無効な短い表現が埋め込まれないようにします。

 ## 特殊なケース

 いつ`A = B = C = 1`、DP は、数字のトリプルの小さな列挙に縮退します。`(1,1,2)`を通して`(9,9,18)`は有効であり、辞書編集的な順序付けは単純な数字の順序付けと一致します。 キャリーが常に 0 または 1 の場合でも DP カウントが計算され、プレフィックスの選択が一貫しているため、アルゴリズムはこれを正しく処理します。 

いつ`C`よりもはるかに大きいです`A`そして`B`、有効な合計には先頭にゼロが必要です`c`十分な数字が生成されるまで。 DP は位置チェックを通じて先頭桁の制約を明示的に適用するため、無効な構造がカウントに影響することはありません。 

k が非常に大きい場合、最初のチェックは`dp[0][0] < k`あらゆる建設作業を妨げます。 これにより、ソリューション空間が空の場合の不必要な貪欲なトラバーサルが回避されます。
