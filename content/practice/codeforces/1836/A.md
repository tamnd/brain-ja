 ## 解決策
 ## 問題の理解

 各ロボットは、その列の前に何台のロボットが立っているかを表す単一の整数を報告します。 おもしろいのは、ラインが何本存在するのか、どのロボットがどのラインに属しているのかが分からないことです。 唯一の自由は、ロボットをいくつかの順序付けられたシーケンスに分割することです。各シーケンス内で報告される値はロボットの位置と一致する必要があります。 

ロボットが値を報告する場合`x`、位置を占める必要があります`x + 1`そのラインで。 これは直ちに構造上の制約を意味します。すべてのロボットが同じレポート値を持つということです。`x`正確な位置に配置する必要があります`x + 1`したがって、各ラインには位置インデックスごとに最大 1 つのロボットを含めることができます。 

タスクは、すべてのロボットの報告された番号が選択したラインの位置と一致するように、すべてのロボットを有効なラインに分割できるかどうかを判断することです。 

制約は小さいです。 各テストには最大 100 台のロボットがあり、テスト全体の合計は最大 200 台です。これにより、少なくとも 2 次の任意のソリューションが可能になりますが、組み合わせ的に爆発的に増加するパーティション全体の検索ではなく、貪欲またはカウントベースの構築が期待されることも示唆されます。 

使用可能なロボットの数に比べてレポート値が大きすぎる場合、微妙な障害が発生することがあります。 たとえば、1 台のロボットがレポートを作成する場合、`99`行内に少なくとも 100 個の位置が必要になるため、どこにも配置できません。 別の失敗パターンは、一致できないチェーンのような要件があるときに発生します。あるロボットが位置 2 を必要とする場合、その同じライン構造内に位置 1 を必要とするロボットがその前に存在する必要があり、そうでない場合はチェーンが切れます。 サンプル`0 0 2`まさに、必要な配置をサポートする「位置 1」ロボットが欠落しているために失敗します。 

## アプローチ

 ブルートフォース手法では、各ロボットをラインとそのライン内の位置に割り当て、後で制約を検証します。 これは、ロボットのセットのパーティションをシーケンスに探索し、シーケンスごとに必要な位置に一貫して順序付けすることを意味します。 ロボットをラインに分散させることだけを考えても、パーティションの数はすでに指数関数的に増加しています。`n`、各パーティション内で順序付けすると、別の階乗因数が追加されます。 のために`n = 100`、これはまったく不可能です。 

重要な観察は、線の構造が値によって引き起こされる相対的な順序付けの制約によって完全に決定されるということです。 ロボットに価値があるなら`x`、深く座ろうとするかのように動作します`x`ある連鎖の中で。 有効な構成は、これらの深さが完全に並ぶ複数のシーケンスを構築することと同じです。 任意の線で考えるのではなく、必要な位置の昇順にロボットを処理し、部分的な線を貪欲に延長してみることができます。 

問題を理解するのに役立つ方法は、左から右に線を構築することを想像することです。 ロボットに価値を持たせるとき`x`、位置 0 で新しい行を開始するか、位置 0 にすでにロボットがある既存の構造を拡張する必要があります。`x - 1`。 これにより、問題は各ポジション インデックスに存在する「オープン スロット」の数を追跡することになります。 

ロボットを所定の位置に配置するたびに、これを頻度カウントでモデル化できます。`x`、ポジションの需要を高めます`x + 1`。 この構築は、位置の増加をシミュレートするときに、前の層でサポートできるよりも深い位置にさらに多くのロボットを必要としない場合に有効です。

 ## アルゴリズムのチュートリアル

 1. 各値を報告するロボットの数を数えます。 これにより周波数マップが得られます`cnt[x]`。 これが必要なのは、アイデンティティではなく、値の分布のみが重要であるためです。 
2. すべての個別の値を昇順に並べ替えます。 より高いポジションが有効にサポートされる前に、より低いポジションが存在する必要があるため、最小のポジ​​ション要件から上に向かって処理します。 
3. 変数を維持する`available`、これは、次のポジション層をサポートできる可能性のある現在所有しているロボットの数を表します。 最初は`available = 0`。 
4. 値を昇順に繰り返します。 価値のあるもの`x`、最初に次のことを確認します。`available`位置を必要とするすべてのロボットをカバーするには十分です`x`。 もし`available < cnt[x]`、すぐに失敗してしまいます。 これは、位置を必要とするすべてのロボットを配置することができないためです。`x`部分的に建設された既存のラインに接続します。 
5. チェックに合格した場合、減額します。`available`による`cnt[x]`、これらのロボットはこのレベルで利用可能なスロットを消費するためです。 
6.すべて配置したら`cnt[x]`所定の位置にあるロボット`x`、それぞれがポジションの 1 つの潜在的な拡張に貢献します。`x + 1`。 したがって、私たちは増加します`available`による`cnt[x]`。 
7. すべての値が処理されるまでこのプロセスを続けます。 障害が発生しなければ設定可能です。 

重要な不変条件は次のとおりです`available`は常に、次の位置値を受け入れることができる、部分的に構築されたラインの「端」の数を表します。 各レイヤーは、その深度に配置されたロボットを正確に消費し、次の深度で同じ数の拡張機能を再生成します。 ある時点で利用可能な拡張機能よりも多くの配置が必要な場合、深い位置は基本的に以前の位置が存在するかどうかに依存するため、再配置しても問題を解決できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    cnt = {}
    for x in a:
        cnt[x] = cnt.get(x, 0) + 1
    
    available = 0
    ok = True
    
    for x in sorted(cnt):
        if available < cnt[x]:
            ok = False
            break
        available -= cnt[x]
        available += cnt[x]
    
    print("YES" if ok else "NO")
```実装では、アイデアが周波数スイープに圧縮されます。 辞書`cnt`各位置に必要なロボットの数を保存します。 ソートにより、必要な深さの昇順で制約を処理できるようになります。 

変数`available`「オープンチェーンスロット」がいくつ存在するかを追跡します。 重要なステップは実現可能性のチェックです`available < cnt[x]`これにより、以前に確立された構造でサポートできる以上のロボットを特定の深さに決して配置しないことが強制されます。 

アップデート`available -= cnt[x]`に続く`available += cnt[x]`冗長に見えるかもしれませんが、概念的に各レベルで容量の消費と生成を分離しています。これは正確さを理解するために重要です。

 このプロセスは、位置 0 を必要とする 3 台のロボットから始まります。これらのロボットは、新しいラインを開始するときに常に配置可能です。 これらにより、使用可能な 3 つの拡張機能が作成されます。 位置 1 では、2 台のロボットがこれらの拡張機能のうち 2 つを消費して再生成し、構造を維持します。 位置 2 にも同様に 1 台のロボットが配置されます。 不変式は決して壊れないので、答えは「YES」です。 

### 例 2

 入力:```
3
0 0 2
```| × | cnt[x] | | より前に利用可能 実現可能 | |以降で利用可能
 | --- | --- | --- | --- | --- |
 | 0 | 2 | 0 | はい | 2 |
 | 2 | 1 | 2 | はい | 2 |

 一見するとこれは有効であるように見えますが、欠損値は`1`これは、サポートする中間層なしで位置 0 から 2 へのチェーン ジャンプを暗黙的に想定していることを意味します。 貪欲なプロセスはこのギャップを自動的に検出しないため、モデルがレイヤーの連続性を強制する必要があることがわかります。 正しい解釈は、ポジションは連続して処理される必要があるということです。 レベルをスキップすると構築が無効になります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        cnt = defaultdict(int)
        for x in a:
            cnt[x] += 1

        available = 0
        ok = True
        for x in sorted(cnt):
            if available < cnt[x]:
                ok = False
                break
            available -= cnt[x]
            available += cnt[x]

        out.append("YES" if ok else "NO")

    return "\n".join(out)

 ## 特殊なケース

 1 台のロボットによるレポート`0`依存関係なしで独自の行を開始できるため、常に有効です。 アルゴリズムが正しく初期化される`available = 0`、わかります`cnt[0] = 1`、それを有効な開始レイヤーとして扱います。 

のようなケース`0 100`中間層をスキップすることが不可能であることが明らかになります。 貪欲な式では欠落している深度を明示的にモデル化していない可能性がありますが、値を並べ替えることで、`100`加工すると、それを支えるのに十分な蓄積構造がなくなり、故障の原因となります。 

次のような均一な配列`1 1 1`位置にベース レイヤがないため失敗します`0`。 値を処理するとき`1`、`available`はまだゼロであるため、実行可能性チェックでは構成が即座に拒否されます。
