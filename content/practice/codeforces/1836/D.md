 ## 解決策
 ## 問題の理解

 すでにあります`n`参加者はそれぞれ範囲内の番号を持っています`[0, m]`。 次に、新しい参加者である Bytek が最後に参加し、自分の番号を選択します。 

ランダムなターゲット整数`t`～から均一に引き出されます`[0, m]`。 その後、距離に応じて勝者が選ばれます。`t`: の`k`最も近いチケットが勝ちます。 2 枚のチケットの距離が等しい場合`t`、小さいインデックスが最初に勝ち、事実上、同点の早い参加者に優先順位が与えられます。 

Bytek は、ターゲット値の数を最大化する値を選択したいと考えています`t`で`[0, m]`彼をそのうちの一人にするだろう`k`勝者。 すべての最適な選択肢の中で、彼は最小の値を望みます。 

出力は、勝利ターゲットの最大数と、それを達成するチケットの最小値の 2 つの数値です。 

制約により、すべてに対して強引な操作が行われます`m + 1`不可能な目標を達成するとき`m`と同じくらい大きいです`10^{18}`。 すべてのターゲットを反復することすら問題外です。 どのようなソリューションでも、範囲全体のスキャンを避け、その代わりに Bytek のチケットが範囲内にある間隔を考慮する必要があります。`k`一番近い。 

単純なアプローチでは、考えられる Bytek 値ごとに、`x`、すべてのターゲットをシミュレートします`t`、すべてのチケットまでの距離を計算し、Bytek が上位にランクされているかどうかを確認します`k`。 それは遅すぎます。`O(m * n log n)`さらに悪いことに、それは完全に不可能です。 

同点が重要な場合には、より微妙な失敗例が現れます。 たとえば、Bytek が自分の番号を既存のチケットと同じにすると、インデックスが高いため、そのチケットに対してタイブレークに負けることになります。 正しい解決策は、平等性を厳密に Bytek にとって悪いものとして慎重に扱う必要があります。 

## アプローチ

 ブルートフォースの観点は簡単です: Bytek の価値を修正する`x`次に、すべてのターゲットについて`t`、すべての距離を計算します`|a_i - t|`そして`|x - t|`、並べ替えまたは部分的に選択します。`k`最小値を選択し、Bytek が表示されるかどうかを確認します。 これはルールを直接シミュレートするため、これは正しいです。 ただし、それぞれ`t`少なくとも費用がかかる`O(n log n)`または`O(n)`、そして、あります`m + 1`ターゲット。 積極的な最適化を行ったとしても、これは天文学的に大きすぎます。 

重要な構造的観察は、Bytek の番号の固定選択についてです。`x`、「Bytek は t に最も近い k の中にある」という条件は、既存の点がどれだけ近くにあるかによってのみ決まります。`t`よりも`x`そうです。 未満の場合`k`既存のチケットは厳密には以下に近いです`t`Bytek よりも大きい場合は、Bytek が含まれます。 

そこで、個々のターゲットについて考えるのではなく、既存のチケットごとに視点を逆転させます。`a_i`のセットを決定します。`t`どこに近いですか`t`Bytekよりも。 このような各条件は、数直線上の間隔を定義します。 数えることができれば、それぞれについて`t`、どれだけの間隔がカバーされているか、Bytekがトップにあるかどうかがわかります`k`。 

したがって、固定の場合`x`、既存の各点は次の間隔に寄与します。`t`距離の比較で Bytek を上回っているところ:$$|a_i - t| < |x - t|$$この不等式は、数直線上の連続するセグメントを定義します。 このようなセグメントをすべて変換した後、スイープ ラインまたは差分配列を使用してカバレッジをカウントできます。 Bytek が勝利`t`カバレッジの場合`< k`。 

2 番目のステップは最適化です`x`。 すべてをテストするのではなく、`x`で`[0, m]`、構造が変化する重要な点、通常は既存の値の周囲とそれらの間の中間点のみを考慮する必要があります。 これにより、候補者は次のように減ります。`O(n)`ポジション。 

各候補者を評価します`x`カバレッジ構造を構築することで、`O(n log n)`または`O(n)`実装に応じて。 それから最高のものを選びます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m · n log n) | O(n) | 遅すぎる |
 | 間隔 + 候補 x 削減 | O(n² log n) (または最適化されたバリアント) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 候補値を確定する`x`Bytek の場合、ターゲットの数を計算します`t`Bytekをその中に入れる`k`一番近い。 

1. 既存のチケットごとに`a_i`、ターゲットのセットを決定します`t`どこ`a_i`厳密には～に近いです`t`よりも`x`。 この地域は、`|a_i - t| < |x - t|`。 

この不等式は、以下に応じて場合を拡張することで線形区間に書き直すことができます。`t`～の左側または右側にある`x`そして`a_i`。 
2.それぞれ`a_i`最大でも 1 つの連続間隔に寄与します`[0, m]`。 このような間隔はすべてイベントに変換されます。つまり、開始時に +1、終了後に -1 になります。 
3. 現在のリージョンを支配している既存のチケットの数を維持しながら、すべてのイベント境界をソートされた順序でスイープします。 連続するイベント ポイント間では、この値は一定であるため、次のイベント ポイントの数を計算できます。`t`そのセグメント内で条件を満たします。 
4. 優勢カウントが存在する各セグメントについて`< k`、 全て`t`このセグメントではBytekが勝っている。 
5. 最適な値を見つけるには`x`、支配構造の変化はこれらのポイントの周囲でのみ発生するため、既存のチケット値とその隣接する整数から導出された候補位置のみをテストします。 
6. 最大勝利数を追跡し、同点の場合は最小数を維持します。`x`。 

### なぜ効果があるのか

 重要な不変条件は、固定された`x`、任意の比較`a_i`Bytek は、次の相対的な順序にのみ依存します。`t`、`a_i`、 そして`x`、そしてこの関係は次の場合にのみ変化します。`t`間の中間点を横切ります`a_i`そして`x`。 これにより、支配構造が区間にわたって区分的に一定であることが保証されるため、カウントを点ごとのシミュレーションではなく区間集計に減らすことができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_intervals(a, x, m):
    intervals = []
    for v in a:
        if v == x:
            continue
        if v < x:
            # solve |v - t| < |x - t|
            # breakpoint is midpoint: t < (v + x) / 2
            L = 0
            R = (v + x - 1) // 2
        else:
            # v > x => t > (v + x) / 2
            L = (v + x + 1) // 2
            R = m
        if L <= R:
            intervals.append((L, R))
    return intervals

def count_good(intervals, k, m):
    events = {}
    for l, r in intervals:
        events[l] = events.get(l, 0) + 1
        if r + 1 <= m:
            events[r + 1] = events.get(r + 1, 0) - 1

    points = sorted(events.keys())
    cur = 0
    prev = 0
    res = 0

    for p in points:
        if prev <= p - 1:
            length = p - prev
            if cur < k:
                res += length
        cur += events[p]
        prev = p

    if prev <= m:
        if cur < k:
            res += m - prev + 1

    return res

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))

    candidates = set(a)
    candidates.add(0)
    candidates.add(m)

    best_cnt = -1
    best_x = 0

    for x in candidates:
        intervals = build_intervals(a, x, m)
        cnt = count_good(intervals, k, m)

        if cnt > best_cnt or (cnt == best_cnt and x < best_x):
            best_cnt = cnt
            best_x = x

    print(best_cnt, best_x)

if __name__ == "__main__":
    solve()
```このコードは、候補 Bytek 値ごとに、距離の点で既存のチケットが優勢であるすべての領域を構築します。 各領域は、次の中点条件から導出されます。`x`そして既存の価値。 これらの領域はスイープ ラインを介してマージされるため、Bytek が上位にランクされるターゲットの数を数えることができます。`k`。 

候補セットの制限は重要な最適化です。 勝利の構造は次の場合にのみ変化します。`x`既存の値または境界を超えるため、最適値を取得するにはそれらの位置のみをテストするだけで十分です。 

中間点の丸めには注意が必要です。距離は整数で比較が厳密であるため、左側と右側は非対称に処理する必要があります。

 ## 特殊なケース

 Bytek が既存のチケットと等しい値を選択した場合、重大なエッジ ケースが発生します。 その場合、距離が同点のターゲットでは、Bytek の方がインデックスが高いため負けます。 インターバル構造は等価性を完全にスキップすることでこれを処理し、Bytek が誤って同点勝利を記録することがないようにします。 

もう一つの微妙なケースは次のような場合です。`m = 0`。 その後、問題全体が単一のターゲットに集約されます。 このアルゴリズムは単一の間隔評価を正確に生成し、Bytek がその 1 つのターゲットを獲得するか、獲得しないかのどちらかです。 

最後に、すべての既存のチケットが片側に集まっている場合、次のようになります。`[0,0,0,...]`、選択する`x`反対側の端近くでは、Bytek が他のすべての端よりも厳密に近い領域が最大化されます。 間隔の定式化は、この構成のほぼすべてのターゲットをカバーするように自然に拡張され、特別なケースを使用しなくても正確さが確認されます。
