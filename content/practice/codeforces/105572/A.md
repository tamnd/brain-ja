 ## 解決策
 ## 問題の理解

 接続された非循環グラフを意味するツリー状の構造と、開始ノードにトークンを配置し、それをターゲット ノードに向かって移動しようとするプロセスが与えられます。 移動ルールは任意の最短経路移動ではなく、エッジに沿ったランダムな遷移であり、目的は、このプロセスの予想される動作について推論することです。 入力は、グラフ構造と、プロセスの開始と終了を定義する 2 つの区別される頂点を記述します。 

出力は、ランダム プロセス自体のシミュレーションではありません。 代わりに、グラフの構造から導出される決定論的な値、通常はツリーのトポロジのみに依存する予想されるステップ数または確率を計算するように求められます。 

制約が十分に大きいため、歩行をシミュレートしたり、パスを列挙しようとするメソッドは直ちに除外されます。 このタスクの一般的なジム バージョンでは最大約 2 × 10^5 ノードがあり、テスト ケースごとに O(n^2) の推論を行っても遅すぎます。 ツリーの構造は、サイクルが存在せず、依存関係が固有のパスに沿って伝播するため、解決策がグラフを独立した部分問題に分解することに依存する必要があることも示唆しています。 

ランダム ウォークを文字通りに解釈しようとすると、素朴な誤解が生じます。 たとえば、星形の木の場合、中心から葉までの可能なすべてのパスをシミュレートし、それらの長さを平均化しようとします。 これは、n = 20 の場合でも組み合わせ的に爆発的に増加します。これは、基礎となる構造が単純であるにもかかわらず、可能な軌道の数がステップとともに指数関数的に増加するためです。 

もう 1 つの一般的なエッジ ケースは、開始が終了と等しい場合に発生します。 この状況では、期待されるステップ数はゼロですが、少なくとも 1 つの移動を想定する単純な再帰では、誤ってゼロ除算が導入されたり、近傍を介して期待値を不必要に伝播しようとしたりします。 

2 番目の微妙なケースは、ノードの次数が 1 である場合に発生します。次数で分割する再帰では、その時点でランダム ウォークが決定的になるため、リーフを慎重に処理する必要があります。 

## アプローチ

 ブルートフォース解釈では、ランダムプロセスをノード上のマルコフ連鎖として明示的にモデル化します。 各状態はノードにあることに対応し、遷移は隣接するノードに均一に進みます。 ターゲットに到達するまでの予想時間は、ノードごとに 1 つの方程式を含む線形方程式系を解くことによって計算できます。 

マルコフ連鎖はプロセスを完全に捉えるため、これは理論的には正しいです。 ただし、ガウス消去法を使用してサイズ n の線形システムを解くには O(n^3) のコストがかかり、最適化されたスパース ソルバーであっても実際にはおよそ O(n^2) または O(n√n) に低下します。 n が 200,000 までの場合、このアプローチは完全に実行不可能です。 

重要な点は、グラフがツリーであるため、エッジを削除するとグラフが独立したコンポーネントに分割されるということです。 ターゲット ノードをルートとして固定すると、すべてのノードはターゲットに向かう一意の親方向を持ちます。 これにより、循環依存関係が削除され、期待値を子のみの関数として表現できるようになります。 

グローバル システムを解決する代わりに、ツリー上で動的プログラミングを使用して値をボトムアップで計算します。 各ノードの期待値は、ターゲットから遠く離れた隣接ノードの期待値のみに依存するため、クリーンな再帰構造が作成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | マルコフ連鎖システム | O(n^3) | O(n^2) | 遅すぎる |
 | ターゲット ルートからのツリー DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. ターゲット ノードでツリーをルートします。 これにより、問題はルートに向かって予想されるヒット時間を計算することに変わり、すべてのエッジが、視点に応じて確率の流れを暗黙的に上または下に向けます。 これが役立つ理由は、ターゲットが期待値 0 の吸収状態になり、循環依存関係が排除されるためです。 
2. DFS または BFS を実行して親子関係を計算し、隣接関係をルート形式で保存します。 このステップでは、すべてのノードの値がルート化されたツリー内のその子のみに依存する部分順序を確立します。 
3. dp[v] を、ノード v からターゲットに到達するために必要な予想ステップ数として定義します。ターゲット自体の場合、dp[target] = 0。 
4. 各非ターゲット ノード v について、その近傍ノードに関して dp[v] を表現します。 ウォークでは近傍を一様にランダムに選択するため、期待値は平均方程式を満たす: dp[v] は 1 にすべての近傍 u の平均 dp[u] を加えたものに等しい。 
5. 近傍ベースの方程式をルート付きツリー形式に変換します。 隣人の 1 人が親で、残りは子です。 これにより、dp[v] が dp[parent[v]] と dp[child] に依存する線形方程式が得られます。 逆の順序で処理すると、再配置により親の依存関係が削除されます。 
6. すでに計算された子の値を使用して dp[v] を計算しながら、葉から上に向かって後順にノードをトラバースします。 各計算では O(deg(v)) 演算のみが使用され、ツリー全体で合計は O(n) になります。 
7. 開始ノードからターゲットまでの予想されるステップ数を表す dp[start] を出力します。 

微妙な点は、再帰には近傍すべての平均が含まれますが、ツリー構造により、値がボトムアップで計算されると、連立方程式を必要とせずに各方程式が局所的に解けるようになることが保証されます。 

### なぜ効果があるのか

 正確さは、マルコフ連鎖の予想ヒット時間が、各状態がその直近の状態にのみ依存する線形システムを満たすという事実に基づいています。 ツリー上でターゲット ノードをルートとして削除すると、すべてのサイクルが削除され、ルート化後にこのシステムが三角形の依存構造に変わります。 これにより、リーフから上に向かってノードを処理するときに、すべての依存関係がすでに解決されていることが保証されるため、各 dp 値はすでに正しいサブ結果から 1 回だけ計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    # Example assumes last line gives start and target
    s, t = map(int, input().split())
    s -= 1
    t -= 1

    parent = [-1] * n
    order = []
    stack = [t]
    parent[t] = t

    while stack:
        v = stack.pop()
        order.append(v)
        for u in g[v]:
            if u == parent[v]:
                continue
            parent[u] = v
            stack.append(u)

    dp = [0.0] * n

    for v in reversed(order):
        if v == t:
            dp[v] = 0.0
            continue

        deg = len(g[v])
        total = 0.0
        for u in g[v]:
            total += dp[u]

        dp[v] = 1 + total / deg

    print(dp[s])

if __name__ == "__main__":
    solve()
```ターゲットをルートとする DFS は、すべてのノードがその子孫の後に処理されるように処理順序を確立します。 dp の計算は、期待値の線形性に直接基づいて行われます。つまり、常に 1 つのステップが実行され、次の状態が隣接する状態の間で均一に選択されるため、それらの期待値を平均します。 

一般的な実装上の落とし穴は、平均化中に親が隣接リストにまだ含まれていることを忘れることです。 厳密に根を張った定式化では、親を除外するか、正しく補正します。 両方のアプローチを混合すると、誤った次数正規化が発生します。 

## 実用的な例

 1 が開始点、3 がターゲットである 3 つのノードからなる小さなチェーンを考えてみましょう。 

隣接関係を 1-2-3 として構築し、ルートを 3 に設定します。 

| ステップ | ノード | 子供の dp 合計 | 学位 | dp値 |
 | --- | --- | --- | --- | --- |
 | 3 | 3 | 0 | 2 | 0 |
 | 2 | 2 | 0 + dp[3] = 0 | 2 | 1 |
 | 1 | 1 | dp[2] = 1 | 1 | 2 |

 開始ノードの期待値は 2 であり、長さ 2 の決定論的パスを通過する必要があるという直観的な事実と一致します。 

ここで、ノード 2 を中心とし、リーフ 1、3、4 を持つスターがあり、ターゲットが 2 であると考えます。 

| ステップ | ノード | 子供の dp 合計 | 学位 | dp値 |
 | --- | --- | --- | --- | --- |
 | 2 | 2 | 0 | 4 | 0 |
 | 1 | 1 | dp[2] = 0 | 1 | 1 |
 | 3 | 3 | dp[2] = 0 | 1 | 1 |
 | 4 | 4 | dp[2] = 0 | 1 | 1 |

 これは、葉は常に中心に直接ジャンプするため、すべての葉の期待値が 1 であることを示しています。

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 start が target と等しい単一ノード グラフの場合、遷移が存在しないため、アルゴリズムは直ちに dp[target] = 0 を割り当て、再帰なしで戻ります。 少なくとも 1 つの近傍を想定する実装では、誤ってゼロ除算が試行されます。 

ターゲットではないリーフ ノードの場合、その唯一の近傍がその親であるため、反復は dp[v] = 1 + dp[parent] に減少します。 これにより、空の子セットの平均化が回避され、ツリーを介して上方向にパス長が正しく伝播されることが保証されます。
