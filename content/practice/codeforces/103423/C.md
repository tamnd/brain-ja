 ## 解決策
 ## 問題の理解

 いくつかのコインのスタックが与えられ、各スタックは初期高さが固定された山を表します。 2 人のプレイヤーがこれらの山から開始してターンベースのゲームをプレイします。 各ターンで、プレイヤーはいくつかのスタックを選択し、そこからコインを取り除きます。 唯一の制限は、その移動中に合計で少なくとも 1 枚のコインを取り除かなければならないことですが、関与するスタックの数や、選択した各スタックから取り出されるコインの数に制限はありません。 

ゲーム全体は、初期構成から始まり、最終的にオールゼロの構成に至るまで、各移動後のすべてのスタックの状態のシーケンスによって完全に決定されます。 ゲームの長さは、すべてが空になるまでの手数です。 タスクは、正確に K 回の手で終了するゲームを生み出す、有効な手の個別のシーケンスの数を数えることです。 

各移動により、少なくとも 1 つの座標においてスタック高さのベクトルが 1 つの非負の整数ベクトルから別の厳密に小さい整数ベクトルに変更され、すべての中間構成は非負のままでなければなりません。 異なる中間構成は異なるゲームを表すため、初期ベクトルを K 個の連続する「減分レイヤー」に分解する方法の数を効率的に数えています。各レイヤーは各パイルを負でない量だけ減少させ、すべてのレイヤーで少なくとも 1 つのパイルが厳密に減少します。 

この制約は、N と K の両方が、ゲーム状態に対する指数関数的な探索が不可能になるほど十分に大きい可能性があることを意味します。 中程度の値であっても、可能な移動シーケンスの数はコインの総数との組み合わせで増加するため、すべての可能な移動または状態に分岐するソリューションはすぐに制限時間を超えます。 

一部のスタックがゼロから始まる場合、微妙なエッジケースが発生します。 たとえば、最初にスタックのコインがゼロの場合、それは変更されることはなく、事実上ゲームから消えます。 正しい解決策は、そのようなスタックを移動へのアクティブな貢献者ではなく固定制約として扱う必要があります。そうしないと、マイナスまたは不必要な削減が考慮される無効な分解が過大評価されてしまいます。 

## アプローチ

 直接的な総当たりアプローチでは、考えられるすべてのゲームがシミュレートされます。 現在の状態から、各スタックから負でない量を減算するあらゆる方法を列挙し、少なくとも 1 つのスタックが確実に削減されるようにし、すべてのスタックがゼロになるまで再帰します。 単一の状態からであっても、各スタックがどれだけ減らすかに独立して寄与するため、可能な移動数は (a_i + 1) の積のオーダーになります。 これにより、K 層にわたって分岐プロセスが作成され、そのサイズは K とコインの合計の両方で指数関数的になります。 各ステップで状態の数が劇的に増加するため、たとえ小さな入力であっても、これはすぐに実行不可能になります。 

重要な構造上の観察は、ゲームを状態ごとではなく列ごとに見ることができるということです。 時間の経過とともにスタックが減少するという観点から考えるのではなく、各スタック内の個々のコインに、それが削除される「ターン番号」が割り当てられるという観点から考えます。 すべてのコインは 1 回だけ削除する必要があり、各移動はスタック全体で一連のコインを削除することに対応します。 移動ごとに少なくとも 1 枚のコインが削除されるという制約は、すべてのターンが空ではないことを要求することになります。 

これにより、問題はすべてのコインを K 個の順序付けされたレイヤーに分配することに変換されます。レイヤー j には、移動 j で削除されたコインが正確に含まれます。 各スタック i は、その a_i コインを、合計が a_i となる K 個の非負の部分に分配する必要があります。 すべてのスタックにわたって、すべてのレイヤーはどこかから少なくとも 1 つのコインを受け取る必要があります。 したがって、座標方向の合計が初期構成と一致し、完全にゼロになるベクトルがないように、移動ごとに 1 つずつ、K 個のベクトルを選択する方法の数を数えています。

この構造は古典的な「空の列を除外したスターとバー」の状況ですが、スタックごとに独立して適用され、その後、すべてのレイヤーが空ではないという要件と結合されます。 この結合を解決するきれいな方法は、まず空でない制約を無視してすべての分布をカウントし、次に空の移動に対する包含を使用して無効なケースを減算することです。 これにより、スタックごとに、そのコインが K 個の動きにどのように分割されるかを計算し、ターンのサブセットにわたる標準の包含/除外によってグローバルに空の手が存在しないように強制する、DP または組み合わせの定式化が行われます。 

ブルート フォースはすべての移動シーケンスを直接探索するため機能しますが、各移動が巨大な分岐要素を作成するため失敗します。 各スタックが K 回の移動にわたってその値の構成に独立して寄与するという観察により、問題は構成をカウントし、次に列全体にわたるグローバルな非空性を強制することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | K の指数と a_i の合計 | 指数 | 遅すぎる |
 | 分布 + 包含-除外にわたる組み合わせ DP | 実装に応じて O(NK + K^2) または O(NK) | O(K) | 承認済み |

 ## アルゴリズムのチュートリアル

 このプロセスを、各スタックの各単位コインに 1 から K までの移動インデックスを割り当てるものとして再解釈します。スタック i の場合、各移動で取り除かれるコインの数を選択することは、a_i を K 部分に分割する弱い構成を選択することに対応します。 

各スタックについて独立して、a_i 個の同一のコインを K 個のラベル付きビンに分配する方法の数は C(a_i + K - 1, K - 1) です。 ただし、これはすべてのスタックにわたって一部のビンが空である可能性がある分布をカウントします。これは、一部の手が何も行わない無効なゲームに相当します。 

すべての移動で少なくとも 1 つのコインがグローバルに削除されるようにするために、一連の移動に対して包含と除外を適用します。 

以下のように進めていきます。 

1. 各スタック i について、K 回の移動にわたる構成の係数が a_i 項目を K ビンに分配する組み合わせ論によって暗黙的に取得される多項式のような寄与を計算します。 
2. 各動きに割り当てられたコインの数に対する畳み込みの意味で、スタックの寄与を乗算することにより、すべてのスタックを結合します。 これにより、空でない手を強制することなく、K 個の手にコインを割り当てる方法が何通りあるかのグローバルなカウントが構築されます。 
3. 移動のサブセットに対して包含/除外を適用します。 t 個の動きのサブセットを空になるように修正すると、K が K - t 個の動きに事実上削減されます。 どの手が空であるかを選択するので、符号を交互に変えてすべての t を合計し、C(K, t) を掛けます。 
4. 縮小された各 K - t について、C(a_i + (K - t) - 1, (K - t) - 1) の i 上の積としてスタック全体の分布の数を計算します。 
5. すべての寄与を 1e9+7 を法として集計します。 

重要な計算タスクは、多くの値の二項係数を効率的に評価することであり、これは事前に計算された階乗とモジュラー逆関数を使用して処理されます。 

### なぜ効果があるのか

 各有効なゲームは、すべてのインデックスが少なくとも 1 回使用されるという制約付きで、{1..K} の移動インデックスへのすべての単位コインの割り当てに正確に対応します。 割り当てはスタックごとに独立しているため、それらを積み重ねることで積構造が得られます。 包含-排他は、一部の移動インデックスが使用されていない割り当てを削除することにより、過剰カウントを修正します。 移動の空性はスタック全体にわたるグローバルな特性であるため、移動サブセットの包含と排他により、スタック間の結合がきれいに分離されます。 これにより、有効なゲームとカウントされた割り当ての間の 1 対 1 の対応が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    maxv = max(a + [0])
    # we only need factorials up to maxv + k
    
    maxn = maxv + k + 5
    
    fact = [1] * (maxn)
    invfact = [1] * (maxn)
    
    for i in range(1, maxn):
        fact[i] = fact[i - 1] * i % MOD
    
    invfact[maxn - 1] = modinv(fact[maxn - 1])
    for i in range(maxn - 2, -1, -1):
        invfact[i] = invfact[i + 1] * (i + 1) % MOD
    
    def C(n, r):
        if n < 0 or r < 0 or r > n:
            return 0
        return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD
    
    # inclusion-exclusion over empty moves
    ans = 0
    for empty in range(0, k + 1):
        sign = -1 if empty % 2 else 1
        ways_choose_empty = C(k, empty)
        kk = k - empty
        if kk == 0:
            continue
        
        ways = ways_choose_empty
        for x in a:
            ways = ways * C(x + kk - 1, kk - 1) % MOD
        
        ans = (ans + sign * ways) % MOD
    
    print(ans % MOD)

if __name__ == "__main__":
    solve()
```包含-除外のすべての項には複数の組み合わせが必要であるため、コードは、高速な二項係数評価をサポートする階乗事前計算から始まります。 C 関数は、負のインデックス付けや無効な組み合わせの解釈を避けるために、無効なパラメーターが慎重に保護されています。 

メインループは、強制的に空にする手が何回あるかを繰り返します。 どの手を空にするかを選択すると C(K, empty) が与えられ、残りの K - 空の手がすべてのコインの割り当てを受け取る必要があります。 各スタックは星と棒の項 C(a_i + kk - 1, kk - 1) を介して独立して寄与し、スタックはコインの独立したソースであるため、これらは増加します。 

よくある微妙な失敗点は、kk = 0 の場合をスキップするのを忘れることです。ゼロ手へのコインの分配は、すべての a_i が 0 の場合にのみ有効であり、これはすでに暗黙的に処理されているためです。 

## 実用的な例

 ### 例 1

 入力:

 2 2

 2 3

 k = 2 の分布を計算します。 

| 空の動き | ｋｋ | 空を選択 | スタック 1 ウェイ C(2+kk-1,kk-1) | 2 通りのスタック C(3+kk-1,kk-1) | 合計 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 2 | 1 | C(3,1)=3 | C(4,1)=4 | 12 |
 | 1 | 1 | 2 | C(2,0)=1 | C(3,0)=1 | 2 |
 | 2 | 0 | 1 | 無効 | 無効 | 0 |

 ここで、包含-除外により 12 - 2 = 10 が得られます。 

これにより、アルゴリズムが、移動がコインを受け取らないケースをグローバルに正しく区別していることが確認されます。 

### 例 2

 入力:

 1 3

 2

 すべての手が空ではない状態で、3 つの動きに 2 つのコインを分配します。 

| 空の動き | ｋｋ | 空を選択 | 方法 |
 | --- | --- | --- | --- |
 | 0 | 3 | 1 | C(4,2)=6 |
 | 1 | 2 | 3 | C(3,1)=3 → 9 |
 | 2 | 1 | 3 | C(2,0)=1 → 3 |
 | 3 | 0 | 1 | 無効 |

 結果: 6 - 9 + 3 = 0。3 つの手がすべて空でない有効なシーケンスがないことを意味します。 

これは、制約が厳しすぎる場合に、包含-排他によってオーバーカウントがどのように正確にキャンセルされるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(NK + K + max(a_i)) | 階乗事前計算と包含-除外にわたる O(NK) ループ |
 | スペース | O(max(a_i + K)) | 階乗配列と逆階乗配列 |

 K と a_i の境界は線形事前計算にのみ影響し、メイン ループは N と K で線形であるため、ソリューションは制約内に快適に収まります。最大のサブタスクであっても、操作は 0.5 ～ 2 秒間は一般的な制限を十分に下回っています。

    import sys

    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    maxv = max(a + [0])
    maxn = maxv + k + 5

    invfact = [1] * maxn

        fact[i] = fact[i - 1] * i % MOD

        return pow(x, MOD - 2, MOD)
    
    invfact[maxn - 1] = modinv(fact[maxn - 1])
    for i in range(maxn - 2, -1, -1):
        invfact[i] = invfact[i + 1] * (i + 1) % MOD
    
    def C(n, r):
        if n < 0 or r < 0 or r > n:
            return 0
        return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

 ## 特殊なケース

 すべてのスタックが 0 の場合、有効なゲームのみがゼロ手になります。 kk = 0 でない限り、すべての組み合わせ項 C(0 + kk - 1, kk - 1) がゼロになり、包含-排他が単一の有効な構成に崩壊するため、アルゴリズムはこれを処理します。 

K が 1 の場合、可能なシーケンスは 1 回の移動で完全に削除することだけです。 この式は空の手を含まない単一の項に縮小され、各スタックは C(a_i, 0) = 1 に寄与し、有効なゲームが 1 つだけ与えられます。 

K がコインの総数を超えると、星と棒の条件によりゼロが強制されるため、ほとんどの構成が消え、すべての手が空ではない可能性のある不可能な割り当てが包含排他によって正しく排除されます。
