 ## 問題の理解

 信号機の列を分析する必要があります。 車はランダムな実数値の時間に位置 0 からスタートします。 1 秒間に 1 メートル移動するため、ライトに到達する時間は、開始時間にライトの位置を加えたものになります。 信号はそれ自体の繰り返しサイクルに従って赤または青のいずれかになり、車は到着時にすべての信号が正確に青である場合にのみ成功します。 

このタスクは 2 種類の確率を計算することです。 すべての信号について、それが車が停止している最初の信号である確率が必要です。 車がすべての信号を通過する確率も必要です。 

難点は、開始時間の間隔が天文学的に長いことです。 2019年の価値！ が選択されるのは、考えられるすべての明期が約数として含まれているためです。そのため、開始時間の分布は、1 つの完全な結合サイクルにわたってランダムな時間を選択するのとまったく同じになります。 複合サイクル自体は列挙するには大きすぎます。 

ライトの数はわずか 500 個で、各期間は最大でも 100 個です。単一の期間の組み合わせでも膨大になる可能性があるため、長期にわたるシミュレーションは不可能です。 有用な境界は、時間間隔の長さではなく、期間のサイズです。 最大 100 の周期によって作成される可能な周期パターンのみを保持する表現が必要です。 

よくある間違いは、ライトが独立していると考えることです。 そうではありません。 たとえば、期間 4 と 6 の 2 つのライトは、同じ開始時間が両方に影響を与えるため、相関関係があります。 もう 1 つの間違いは、赤色の間隔の終わりに到着したことを誤って扱うことです。 時刻からライトは緑色になります`r`, なので間隔は半開きです。 

たとえば、位置 1 に 1 つのライトがある場合、`r = 1, g = 1`、すべての開始時間の半分は、赤の 2 番目の時間に車が到着し、半分は緑の 2 番目の時間に到着します。 答えは次のとおりです。```
0.5
0.5
```整数の開始時間をサンプリングする方法は、開始時間が連続的であるため、ここでは失敗します。 境界点の確率はゼロであるため、離散的なケースとして扱ってはなりません。 

## アプローチ

 直接的なアプローチは、すべてのライトの完全な繰り返しサイクルを見つけて、そのサイクル内のあらゆる瞬間をスキャンすることです。 交通システムは正確に繰り返されるため、これは正しいです。 ただし、1 から 100 までの期間の最小公倍数は、実現可能なデータ構造よりもはるかに大きいため、このアプローチではタイムラインを構築することさえできません。 

重要な観察は、共通の周期は巨大であるにもかかわらず、関係するすべての周期関数には少数の可能な周波数しかないということです。 周期のある光`p`周波数を伴うフーリエ係数で説明できる`k/p`。 考えられるすべての期間を最大 100 まで結合した後の、個別に換算された分数の数`k/p`たったの3000くらいです。 

タイムライン全体を保存する代わりに、まだ生きている開始時間のセットのフーリエ表現を保存します。 信号の青関数を掛けると、その信号で停止している車が削除されます。 赤の関数を乗算し、定数のフーリエ係数を取得すると、現在の光が最初の故障である確率が得られます。

 ## アルゴリズムのチュートリアル

 1. 可能なすべての削減周波数を事前計算します。`a/b`どこ`b <= 100`。 このようなすべての周波数に整数の識別子を与えます。 また、2 つの周波数を法 1 で加算する方法も事前計算します。 
2. 各信号機について、赤の区間と緑の区間のフーリエ係数を構築します。 時間に合わせて発車するため、ライトの位置により間隔がずれます。`t`いつか光に届く`t + x`。 
3. 以前のすべての光を通過した一連の開始時刻を表すフーリエ マップを維持します。 最初は定数関数 1 です。 
4. 現在のライトを更新する前に、現在の生存関数と現在のライトの赤の関数を掛けます。 周波数ゼロの係数は、この光で最初に失敗した開始時間の正確な割合です。 
5. サバイバー関数に現在のライトの緑色の関数を乗算して続行します。 すべてのライトが点灯した後、ゼロ周波数係数は終点に到達する確率です。 

不変条件は、最初の処理後の`i`ライトが点灯すると、フーリエ表現はまさに、それらを通過する開始時刻の指標関数です。`i`ライト。 赤の乗算は現在の光で失敗したサブセットを抽出しますが、緑の乗算は生き残った回数だけを保持します。 フーリエ乗算は周期関数の乗算を表すため、すべての更新はこの意味を保持します。 

## Python ソリューション```python
import sys
import math
from array import array

input = sys.stdin.readline

freqs = []
freq_id = {}
for d in range(1, 101):
    for a in range(d):
        g = math.gcd(a, d)
        if g == 1:
            key = (a, d)
            freq_id[key] = len(freqs)
            freqs.append(key)
freq_id[(0, 1)] = len(freqs)
freqs.append((0, 1))

m = len(freqs)

add_table = []
for a, b in freqs:
    row = array('H')
    for c, d in freqs:
        num = a * d + c * b
        den = b * d
        num %= den
        if num == 0:
            row.append(freq_id[(0, 1)])
        else:
            g = math.gcd(num, den)
            row.append(freq_id[(num // g, den // g)])
    add_table.append(row)

TWO_PI = 2.0 * math.pi

def make_fourier(x, r, g, red):
    p = r + g
    length = r if red else g
    start = 0 if red else r
    end = start + length
    res = []
    for k in range(p):
        if k == 0:
            val = length / p
        else:
            a = math.cos(-TWO_PI * k * start / p) + 1j * math.sin(-TWO_PI * k * start / p)
            b = math.cos(-TWO_PI * k * end / p) + 1j * math.sin(-TWO_PI * k * end / p)
            val = (a - b) / (2j * math.pi * k)
        if x and k:
            val *= math.cos(TWO_PI * k * x / p) + 1j * math.sin(TWO_PI * k * x / p)
        if abs(val) > 1e-14:
            if k == 0:
                idx = freq_id[(0, 1)]
            else:
                z = k
                d = p
                gg = math.gcd(z, d)
                idx = freq_id[(z // gg, d // gg)]
            res.append((idx, val))
    return res

def multiply(cur, poly):
    nxt = {}
    add = add_table
    for a, va in cur.items():
        row = add[a]
        for b, vb in poly:
            c = row[b]
            nxt[c] = nxt.get(c, 0j) + va * vb
    return nxt

def solve():
    n = int(input())
    lights = []
    for _ in range(n):
        x, r, g = map(int, input().split())
        lights.append((x, r, g))

    cur = {freq_id[(0, 1)]: 1.0 + 0j}
    ans = []
    zero = freq_id[(0, 1)]

    for x, r, g in lights:
        red = make_fourier(x, r, g, True)
        fail = multiply(cur, red)
        ans.append(fail.get(zero, 0).real)
        green = make_fourier(x, r, g, False)
        cur = multiply(cur, green)

    for v in ans:
        print("{:.12f}".format(v))
    print("{:.12f}".format(cur.get(zero, 0).real))

if __name__ == "__main__":
    solve()

フーリエ構築では、間隔インジケーター関数の積分を使用します。 位置シフトにより各周波数に対応する位相係数が乗算され、車が正確に遅く光に到達するという事実と一致します。`x`秒。 

乗算ルーチンはソリューションの中核です。 それは、既存のすべての周波数と現在の光のすべての周波数を組み合わせます。 2 番目のオペランドには最大 100 個のエントリがあるため、演算の数は少ないままです。 

定数係数は、表現された関数の平均値です。 私たちの関数は指標であるため、その平均はまさに必要な確率です。

## 特殊なケース

 赤の時間がないライトは、`r = 0`。 赤いフーリエ関数は空であるため、失敗確率はゼロです。 緑色の関数は定数関数であり、光が生存者の分布に影響を与えないことを意味します。 

青時間がないライトは、`g = 0`。 そこに到達する生き残った車はすべて停止します。 この更新後、赤色の関数がフルインジケーター関数となり、最終生存確率はゼロになります。 

信号が赤から青に変わったときに正確に到着する車は、続行しなければなりません。 区間積分では、`[0, r)`赤と`[r, r+g)`緑の場合、境界点は正しく割り当てられています。 これらの点は確率に影響を与えませんが、閉じた間隔を使用すると、不正確なフーリエ係数が発生する可能性があります。
