 ## 解決策
 ## 問題の理解

 ロードマップは無向グラフです。 行き止まり標識は道路の方向に属するものであり、道路自体に属するものではありません。 方向性のあるストリート`u -> v`から運転した後、標識が必要な場合`u`に`v`、最終的に元に戻る方法はありません。`u`すぐに同じ道を引き返さずに。 

これについて直接的に考えると、標識はグラフの一部につながる道路にのみ表示され、元に戻ることができないということになります。 橋を削除すると、片側がグラフの残りの部分からぶら下がった木になる場合があります。 このような垂れ下がった木の内側のすべての端は、完全な配置では行き止まりですが、中心部に近い別の行き止まり標識がすでにドライバーに警告しているため、これらの標識の多くは不要です。 

入力には最大で次のものを含めることができます`500000`頂点と`500000`エッジ。 パスの検索、接続性のチェック、またはすべてのエッジのペアの処理を繰り返し行うアルゴリズムでは、非常に遅すぎます。 このサイズでは、線形またはほぼ線形のソリューションが必要です。`O(n log n)`すでに実用限界に近づいています。 

主な厄介なケースは、明らかな葉ではありません。 それ自体がツリーであるグラフは、循環コアを持つグラフとは異なる動作をします。 

例えば：```
3 2
1 2
2 3
```正しい出力は次のとおりです。```
2
1 2
3 2
```すべての通りは橋ですが、葉から始まる 2 つの方向だけが残ります。 サイン`2 -> 1`入力した後は冗長になります`3 -> 2`、ドライバーが到達できる`2`そして入力してください`2 -> 1`。 

別の例:```
4 4
1 2
2 3
3 1
1 4
```正しい出力は次のとおりです。```
1
1 4
```三角形は環状コアです。 唯一の行き止まりは、そのコアに取り付けられたリーフであり、有用な標識はコアからリーフの方向を指します。 

よくある間違いは、すべてのブリッジ方向を出力することです。 これにより、コアに接続されたツリー内に冗長な標識が作成され、最小化要件が満たされなくなります。 

## アプローチ

 ブルートフォースソリューションは定義から始めることができます。 すべての有向エッジについて、即時 U ターンの制限を解除し、グラフ検索を実行して、開始頂点に再び到達可能かどうかを確認します。 これにより、すべての行き止まりの方向が正確に識別されます。 その後、標識のペアごとに別の検索を実行して、冗長な標識を削除できます。 

問題は検索数が多すぎることです。 と`m = 500000`、すべてのエッジのチェックにはすでに約約コストがかかります`O(m(n+m))`最悪の場合、限界をはるかに超えてしまいます。 

有益な観察は、行き止まりはまさに各接続コンポーネントの循環部分からぶら下がっている木であるということです。 循環部分は、リーフを繰り返し削除するプロセスでも残ります。 この剪定中に除去されたものはすべて、残りのコアに接続されている木に属します。 

これにより、問題は単純なグラフの剥離プロセスに変わります。 次数 1 の頂点を繰り返し削除します。 環状コアが残っている場合、コア頂点から除去された頂点までのすべてのエッジが必要な符号となります。 コンポーネント全体が消える場合、そのコンポーネントは木であり、元の葉だけが兆候を生成するはずです。 

ピーリングのアイデアでは、ブリッジを明示的に見つけることを避けます。 最終的な答えに関連する構造を直接識別します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m(n+m)) | O(n+m) | 遅すぎる |
 | 最適 | O(n+m) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフを保存し、すべての頂点の次数を計算します。 次数が 1 以下のすべての頂点をキューに入れます。 
2. キューから頂点を繰り返し削除します。 それらを削除済みとしてマークし、近隣の度合いを下げます。 ネイバーがリーフになるたびに、それをキューに追加します。 

この処理の後に残った頂点は、まさにサイクリックコアに属する頂点です。 皮をむくと最終的にすべての頂点が除去されるため、木には芯がありません。 
3. いくつかの頂点が残っている場合は、元のエッジをすべて検査します。 一方のエンドポイントがコア内にあり、もう一方のエンドポイントが削除された場合は常に、コア エンドポイントから削除されたエンドポイントへの方向を出力します。 

垂れ木に進入するとドライバーは戻れなくなるため、これらは唯一の非冗長標識です。 
4. 頂点が残っていない場合、すべての接続されたコンポーネントはツリーになります。 元のグラフを検査し、開始端点が元の次数 1 を持つすべてのエッジを出力します。 

葉はその唯一のエッジに入った後は離れる他に方法がありませんが、内部の木の頂点から始まるすべての標識は葉に近い標識で覆われます。 
5. 結果のペアを最初のエンドポイントで並べ替え、次に 2 番目のエンドポイントで並べ替えてから、印刷します。 

なぜ効果があるのか:

 枝刈りプロセスでは、サイクルに参加できる頂点が正確に保存されます。 削除された頂点は、コアまたは削除された別の頂点のいずれかにアタッチされたツリーに属します。 非ツリー コンポーネントでは、そのようなツリーに入る最初のエッジが重要な唯一の記号です。これは、最初の記号を通過した後にすべての深い記号に到達できるためです。 ツリー コンポーネントにはコアがないため、別の出力ルートを持たない頂点は葉だけです。 したがって、生成されたセットには必要な警告がすべて含まれており、冗長な警告は含まれていません。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    adj = [[] for _ in range(n)]
    edges = []
    deg = [0] * n

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        edges.append((a, b))
        adj[a].append(b)
        adj[b].append(a)
        deg[a] += 1
        deg[b] += 1

    removed = [False] * n
    q = deque()

    for i in range(n):
        if deg[i] <= 1:
            q.append(i)

    while q:
        u = q.popleft()
        if removed[u]:
            continue
        removed[u] = True
        for v in adj[u]:
            if not removed[v]:
                deg[v] -= 1
                if deg[v] == 1:
                    q.append(v)

    ans = []

    if any(not x for x in removed):
        for a, b in edges:
            if removed[a] != removed[b]:
                if not removed[a]:
                    ans.append((a + 1, b + 1))
                else:
                    ans.append((b + 1, a + 1))
    else:
        for a, b in edges:
            if len(adj[a]) == 1:
                ans.append((a + 1, b + 1))
            if len(adj[b]) == 1:
                ans.append((b + 1, a + 1))

    ans.sort()

    out = [str(len(ans))]
    for a, b in ans:
        out.append(f"{a} {b}")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードの最初の部分ではグラフを構築し、元の次数を保持します。 元の次数は、ピーリング後のすべての頂点の次数が 0 になるため、グラフ全体がツリーである特殊な場合にのみ必要になります。 

キューベースの削除はアルゴリズムの中核です。 各頂点はキューに最大 1 回入力され、各エッジは一定の回数検査されるため、線形の複雑さが得られます。 

出力の構造は 2 つのケースを分けます。 コアが存在する場合、答えはコアと削除されたツリーの間の境界エッジによって形成されます。 コアが存在しない場合、グラフは森となり、元の葉のみが符号に寄与します。 

この問題では印刷されたペアの辞書編集的な順序が指定されているため、最終的な並べ替えが必要です。

 ## 特殊なケース

 ツリー コンポーネントの場合、アルゴリズムはすべての頂点を削除します。 コアが存在しない場合、リーフのみのルールがトリガーされます。 パスの例では次のようになります。```
3 2
1 2
2 3
```頂点`1`そして`3`次数 1 から開始するため、最終スキャン出力は次のようになります。`1 2`そして`3 2`。 中央の頂点は、そこから始まるいずれかの記号がすでに葉の記号で覆われているため、決して表示されません。 

サイクルとアタッチされたツリーを含むグラフの場合、枝刈り後の残りの頂点がコアを形成します。 で：```
4 4
1 2
2 3
3 1
1 4
```頂点`4`頂点が削除される`1,2,3`生き残る。 唯一の境界エッジは`1-4`、アルゴリズムは次のように出力します`1 4`。 

孤立した頂点の場合、次数は 0 です。 彼らはピーリングキューに入りますが、エッジがないため、サインに貢献することはありません。 答えは空のままですが、マークする道路がないので正解です。
