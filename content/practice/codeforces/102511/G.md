 ## 解決策
 ## 問題の理解

 入力はルート付き家系図を記述します。 すべての女性は、自分の名前の最初の文字と母親のインデックスだけを保存します。 娘の完全な名前は、母親の完全な名前の前に娘の文字を置くことによって取得されるため、ノードからその親に移動すると、名前の最初の文字が削除されます。 

すべてのクエリ文字列について、完全な名前がその文字列で始まるノードの数が必要です。 課題は、名前が明示的に保存されないことです。 100 万人の女性の連鎖で 100 万の長さの名前を作成できるため、すべての名前を作成するにはすでにコストがかかりすぎます。 

制限により、線形またはほぼ線形の解決策が求められます。 100 万人の女性と合計 100 万のクエリ文字が存在する可能性があります。 すべてのクエリのすべての名前を調べるアプローチでは、次のような問題を回避できます。$10^{12}$キャラクターチェックは長いチェーンで行われ、利用可能な時間をはるかに超えています。 アルファベットは 26 文字しかないため、線形文字列処理を使用したソリューションが可能です。 

厄介なケースは、家系図のさまざまな深さに現れる接頭辞によって引き起こされます。 クエリは完全な名前と同じにすることも、名前よりも短くすることも、一致する名前を持たないこともできます。 

たとえば、入力```
1 3
A 0
A
AA
B
```名前だけがある`A`。 正しい出力は次のとおりです```
1
0
0
```すべてのクエリがフルネームと一致する必要があると想定するソリューションでは、最初のクエリが誤って拒否されます。 

もう 1 つのケースは、いくつかの関連する名前のプレフィックスであるクエリです。```
3 2
S 0
A 1
B 2
A
BA
```名前は次のとおりです。`S`、`AS`、 そして`BAS`。 出力は```
1
1
```クエリ`A`一致のみ`AS`のすべての子孫ではありません。`A`名前は前に文字を追加することで大きくなるからです。 

## アプローチ

 直接的な解決策は、すべての女性の名前を再構築し、それらをすべて保存することになります。 クエリに答えるために、それをすべての名前と比較できます。 これは、必要なプレフィックス関係を正確にチェックするため、正しいです。 問題はコストです。 100 万人の女性の連鎖において、再構築されたすべての名前の合計の長さは約$10^{12}$、クエリをそれらと比較するとさらに大きくなります。 

有益な観察は、家族関係がプレフィックス クエリでは逆であるということです。 娘は母親の名前の先頭に文字を追加することで作成されます。 すべての名前を逆にすると、末尾に文字を追加して娘が作成されます。 家系図は名前を逆にした通常のトライになります。 

かどうかを尋ねるクエリ`s`元の名前の接頭辞であるかどうかという質問になります。`reverse(s)`は、このトライのパス文字列の接尾辞です。 これにより、問題は、多くのトライパスの中から多くのサフィックスを見つけることに変わります。 

すべての逆クエリを Aho-Corasick オートマトンに挿入できます。 ファミリ トライをトラバースしている間、現在の逆の名前を読み取った後、オートマトンの状態を維持します。 訪問した女性全員がその状態に 1 つの出来事をもたらします。 障害リンクはサフィックス関係を表すため、クエリは、その状態がクエリ ノードの障害サブツリー内にある場合に常にその状態と一致します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2 + nk)$|$O(n^2)$| 遅すぎる |
 | 最適 |$O(n + L)$|$O(n + L)$| 承認済み |

 ここ$L$すべてのクエリの合計長です。 

## アルゴリズムのチュートリアル

 1. すべてのクエリ文字列を反転してトライに挿入します。 挿入された各文字列の終端ノードは保存されるため、後で答えを復元できます。 ファミリ構築では反転後に文字が自然に追加されるため、反転は重要な変換です。 
2. Aho-Corasick 構造を使用してトライの障害リンクを構築します。 欠落しているトランジションは失敗したトランジションを使用して埋められ、すべての文字を一定時間で処理できるようになります。 
3. 子リストを使用して家系図を保存します。 現在のアホ・コラシック状態を維持したまま、創始者からトラバースします。 娘に移動するときは、娘のキャラクターをオートマトンに送り込み、結果の状態のカウンターをインクリメントします。 
4. オートマトンの障害リンク ツリーを構築します。 各状態のカウンターをこのツリー内の親に追加し、最も深いノードから最も浅いノードへ処理します。 この伝播の後、各州には、その州によって表される文字列が接尾辞であるファミリー名の数が含まれます。 
5. 各クエリについて、オートマトンの終端ノードに保存されている累積値を出力します。 

これが機能する理由: 反転後、すべての女性はファミリー トライ内の 1 つのルートからノードへの文字列に対応します。 女性を訪問した後に到達したオートマトンの状態は、その逆の名前の接尾辞でもある最長のクエリ接頭辞を表します。 失敗したリンクには、すべての短いサフィックス一致が含まれます。 障害ツリーを介してカウントを伝播すると、各出現箇所がサフィックスであるすべてのクエリ文字列に転送されます。これはまさに元のプレフィックス条件です。 

## Python ソリューション```python
import sys
from collections import deque
from array import array

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    fam_head = array('i', [-1]) * (n + 1)
    fam_to = array('i')
    fam_next = array('i')
    fam_ch = array('b')

    for i in range(1, n + 1):
        c, p = input().split()
        c = ord(c) - 65
        p = int(p)
        if p:
            fam_to.append(i)
            fam_next.append(fam_head[p])
            fam_ch.append(c)
            fam_head[p] = len(fam_to) - 1

    q_terminal = array('i', [0]) * k

    head = array('i', [-1])
    to = array('i')
    nxt = array('i')
    ch = array('b')

    def new_node():
        head.append(-1)
        return len(head) - 1

    for qi in range(k):
        s = input().strip()[::-1]
        cur = 0
        for x in s:
            c = ord(x) - 65
            e = head[cur]
            found = -1
            while e != -1:
                if ch[e] == c:
                    found = to[e]
                    break
                e = nxt[e]
            if found == -1:
                found = new_node()
                to.append(found)
                ch.append(c)
                nxt.append(head[cur])
                head[cur] = len(to) - 1
            cur = found
        q_terminal[qi] = cur

    m = len(head)
    fail = array('i', [0]) * m

    trans = array('i', [-1]) * (m * 26)
    for v in range(m):
        e = head[v]
        while e != -1:
            trans[v * 26 + ch[e]] = to[e]
            e = nxt[e]

    q = deque()
    for c in range(26):
        x = trans[c]
        if x == -1:
            trans[c] = 0
        else:
            q.append(x)

    while q:
        v = q.popleft()
        base = v * 26
        fbase = fail[v] * 26
        for c in range(26):
            u = trans[base + c]
            if u == -1:
                trans[base + c] = trans[fbase + c]
            else:
                fail[u] = trans[fbase + c]
                q.append(u)

    cnt = array('i', [0]) * m
    stack = [(1, 0)]
    while stack:
        v, state = stack.pop()
        e = fam_head[v]
        while e != -1:
            u = fam_to[e]
            ns = trans[state * 26 + fam_ch[e]]
            cnt[ns] += 1
            stack.append((u, ns))
            e = fam_next[e]

    children = [[] for _ in range(m)]
    for i in range(1, m):
        children[fail[i]].append(i)

    order = list(range(m))
    order.sort(key=lambda x: -x)
    for v in order:
        if v:
            cnt[fail[v]] += cnt[v]

    ans = []
    for x in q_terminal:
        ans.append(str(cnt[x]))
    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```2 つの構造は問題の異なる方向を表すため、家系図はオートマトンとは別に保存されます。 ファミリ トラバーサルにより逆の名前が作成され、オートマトンはそれらの名前に対する接尾辞のクエリに応答します。 

クエリの挿入では、反転された文字列が使用されます。 すべての前処理の後、回答がその正確なオートマトン ノードに添付されるため、ターミナル ノードはすぐに保存されます。 

障害リンクの伝播は、子から親に向かって行われます。 クエリ文字列は多くの状態で表されるサフィックスである可能性があるため、障害ツリー内のすべての子孫が寄与するまで最終的な数はわかりません。 

すべてのカウンターは Python 整数に適合します。 ノード数が 100 万に達する可能性があるため、アレイではコンパクトなストレージが使用されます。

 ## 特殊なケース

 走査中にルート女性も訪問されるため、創設者のみに一致するクエリが処理されます。 アルゴリズムは実際のファミリー ノードからカウントを開始するため、名前は`S`サンプルに 1 回貢献します。 

フルネームより短いクエリは、失敗の伝播によって処理されます。 たとえば、チェーンの中で`A`、`BA`、`CBA`、クエリ`A`はすべての逆パスのサフィックスに対応するため、障害ツリーでは 3 つの出現すべてが最終状態に追加されます。 

一致する可能性のないクエリは、いかなる貢献も受け取りません。 そのオートマトン ノードは、ファミリー トラバーサルがそのオートマトン ノードまたは障害ツリー内のその下位の状態に到達しないため、ゼロのままです。
