 ## 解決策
 ## 問題の理解

 ネットワークは、特別な特性を持つ有向グラフです。すべてのステーションには、出力エッジが 1 つだけあります。 駅から`i`、指定された値`d[i]`列車の片行で到達できる唯一の駅です。 

各駅ごとに`A`、到着できる出発駅の数を数える必要があります。`A`せいぜい使用`k`動く。 開始駅自体がカウントされるため、駅は常に独自の回答に含まれます。 

すべての頂点に 1 つの出力エッジがあるグラフは、関数グラフと呼ばれます。 このようなグラフのすべての接続コンポーネントには 1 つの有向サイクルが含まれており、他のすべてのステーションは最終的にそのサイクルにつながるツリーに属します。 

ステーションの数は最大でも可能です`5 * 10^5`。 これにより、すべての開始駅を個別にチェックする必要がなくなります。 すべてのノードからのシミュレーションには最大で次の時間が必要になります。`O(n)`ノードごとに移動するため、`O(n^2)`可能性をはるかに超えた仕事。 

厄介なケースは、サイクルとそこに至る長い連鎖によって引き起こされます。 サイクル ノードには到達する方法が複数あるため、グラフを通常のツリーとして扱うソリューションは失敗します。 

例えば：```
5 3
2
3
1
5
4
```グラフには 2 つのサイクルがあります。`1 -> 2 -> 3 -> 1`そして`4 -> 5 -> 4`。 正しい出力は次のとおりです。```
3
3
3
2
2
```木だけのアプローチではその駅を見逃してしまう`1`駅からアクセスできる`2`そして`3`サイクルを通して。 

もう 1 つのエッジ ケースは、サイクルに入るチェーンです。```
4 2
2
3
4
3
```答えは次のとおりです。```
1
2
4
3
```駅`4`からアクセスできます`1`、`2`、`3`、 そして`4`、しかし、からの距離`1`は 3 脚なので、次の場合は除外されます。`k = 2`。 距離を追跡せずに訪問したステーションのみをマークする不注意な幅優先検索の実装により、距離が誤ってカウントされる可能性があります。 

## アプローチ

 直接的な解決策は、すべてのステーションから検索を開始し、出力エッジを逆方向にたどることです。 これは、目的地に到着する可能性のあるすべての出発点を正確に探索するため、正しいです。 ただし、最悪の場合、グラフには長さの連鎖が含まれる可能性があります。`n`したがって、これをステーションごとに繰り返すと、おおよそのコストがかかります`n * n`操作。 

有用な観察は、関数グラフの構造から得られます。 サイクル ノード間のすべてのエッジを削除すると、すべてのコンポーネントは、ルートがサイクル ノードであるルート付きツリーのコレクションになります。 これらのツリーのいずれかの内部にあるステーションの場合、それに到達できるすべてのステーションは、まさに反転ツリー内のその子孫です。 問題は、深さには最大で何人の子孫が存在するかということです。`k`このノードの下にありますか？ 

このツリー クエリはオフラインで回答できます。 深さ優先探索中に、各ノードにオイラー区間を割り当てます。 ノードのサブツリーは、この順序での 1 つの連続した間隔です。 クエリを最大許容深さで並べ替え、深さが有効になるとフェンウィック ツリーにノードを追加します。 次に、フェンウィック ツリーは、サブツリー間隔ごとにアクティブなノードの数を示します。 

残りの部分はサイクル ノードの処理です。 サイクル ノードには、他のサイクル ノードからアクセスすることもできます。 長さのサイクルに沿って`m`、すべてのサイクル ノードは、その範囲内の他のすべてのサイクル ノードに到達します。`m - 1`ステップなので、サイクル寄与は単純に次のようになります。`min(k + 1, m)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 度数消去を使用してすべてのサイクル ノードを検索します。 次数が 0 になるノードはサイクルの一部になることができないため、ノードを繰り返し削除すると、有向サイクルがそのまま残ります。 
2. ノードから、そのノードを指すすべての非サイクル ノードにエッジを追加して、反転フォレストを構築します。 サイクル間のエッジは個別に処理されるため無視されます。 
3. このフォレスト上で DFS を実行します。 すべてのノードにオイラーの開始時間、終了時間、およびサイクル ルートからの深さを割り当てます。 この走査中に、各深度に存在するノードの数を記録します。 
4. ノードごとに 1 つのクエリを作成します。 クエリは、深さが最大で、オイラー サブツリー内のノードの数を求めます。`depth[node] + k`。 
5. 深さの制限に従ってクエリを並べ替えます。 浅い深さから深い深さまで掃除します。 深さが許可されると、オイラー位置を使用して、その深さを持つすべてのノードをフェンウィック ツリーに挿入します。 クエリの答えは、サブツリー間隔にわたるフェンウィックの合計です。 
6. サイクル ノードごとに、到達可能なサイクル ノードの数を加算します。 一定の長さのサイクルの場合`m`、この値は`min(k + 1, m)`。 

なぜ効果があるのか:

 サイクルの外側にあるすべてのステーションには、サイクルに向かう固有のパスがあります。 エッジを反転すると、考えられるすべての先行ステーションがツリーに変わるため、すべての有効な開始ステーションはまさにそのツリー内の子孫になります。 オイラー間隔プロパティは、サブツリー クエリがそれらの子孫を正確にカウントすることを保証し、深さスイープは、その子孫内のノードのみがカウントされることを保証します。`k`エッジが含まれています。 サイクル ノードは、サイクルの周囲に複数の方向が存在する唯一の場所であり、その寄与は接続されたツリーから独立しているため、個別に追加できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 2)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    n, k = map(int, input().split())
    to = [0] * n
    rev = [[] for _ in range(n)]
    indeg = [0] * n

    for i in range(n):
        x = int(input()) - 1
        to[i] = x
        rev[x].append(i)
        indeg[x] += 1

    from collections import deque

    q = deque()
    for i in range(n):
        if indeg[i] == 0:
            q.append(i)

    removed = [False] * n
    while q:
        x = q.popleft()
        removed[x] = True
        y = to[x]
        indeg[y] -= 1
        if indeg[y] == 0:
            q.append(y)

    cycle = [not removed[i] for i in range(n)]

    children = [[] for _ in range(n)]
    for i in range(n):
        if not cycle[i]:
            children[to[i]].append(i)

    tin = [0] * n
    tout = [0] * n
    depth = [0] * n
    nodes_by_depth = []
    timer = 0

    for root in range(n):
        if cycle[root]:
            stack = [(root, 0, False)]
            depth[root] = 0
            while stack:
                x, idx, exit_flag = stack.pop()
                if exit_flag:
                    tout[x] = timer - 1
                    continue
                tin[x] = timer + 1
                timer += 1
                while len(nodes_by_depth) <= depth[x]:
                    nodes_by_depth.append([])
                nodes_by_depth[depth[x]].append(x)
                stack.append((x, 0, True))
                for c in reversed(children[x]):
                    depth[c] = depth[x] + 1
                    stack.append((c, 0, False))

    queries = [(min(n - 1, depth[i] + k), i) for i in range(n)]
    queries.sort()

    bit = Fenwick(n)
    ans = [0] * n
    ptr = 0

    for limit, node in queries:
        while ptr <= limit and ptr < len(nodes_by_depth):
            for x in nodes_by_depth[ptr]:
                bit.add(tin[x], 1)
            ptr += 1
        ans[node] = bit.range_sum(tin[node], tout[node])

    visited = [False] * n
    for i in range(n):
        if cycle[i] and not visited[i]:
            cur = i
            length = 0
            while not visited[cur]:
                visited[cur] = True
                length += 1
                cur = to[cur]
            add = min(k + 1, length)
            cur = i
            while True:
                ans[cur] += add
                cur = to[cur]
                if cur == i:
                    break

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```イン次数除去フェーズでは、再帰を行わずにサイクル ノードをツリー ノードから分離します。これは、チェーンの長さが異なるために必要です。`500000`Python の再帰制限をオーバーフローする可能性があります。 その分離の後、非サイクルエッジのみが配置されます。`children`したがって、DFS 構造は実際のフォレストです。 

オイラートラバーサルは次のことを与えます`tin`そして`tout`価値観。 間隔`[tin[v], tout[v]]`のノードが正確に含まれます`v`の逆ツリーサブツリー。 フェンウィック ツリーは深度スイープ中に現在アクティブなノードを格納するため、すべてのサブツリー クエリは範囲の合計になります。 

サイクル処理は、ツリー クエリの後に意図的に実行されます。 ツリーの回答にはすでにサイクル ノード自体が含まれているため、追加する必要があるのは他のサイクル ノードのみです。 使用する`min(k + 1, length)`次の場合にオフバイワンエラーを回避します`k`サイクル長よりも大きいです。

 ## 特殊なケース

 最初のサイクルの場合:```
5 3
2
3
1
5
4
```最初の 3 つのステーションは、長さ 3 のサイクルを形成します。 以来`k = 3`、そのサイクル上のすべてのステーションが他のすべてのサイクル ステーションに到達し、それぞれに 3 つの有効なスタートが与えられます。 2 番目のサイクルの長さは 2 であるため、両方のステーションも相互に到達しますが、出力はそのサイクルのサイズによって制限されたままになります。 

チェーンケースの場合：```
4 2
2
3
4
3
```駅に根を張る逆さの木`3`含まれています`1`、`2`、`3`、 そして`4`。 ステーションのツリークエリ`3`深さを数える`0`、`1`、 そして`2`、ただし駅を除く`1`3辺離れているからです。 サイクル貢献は、上のステーションのみを追加します。`3 -> 4 -> 3`最終値を与えるサイクル`1, 2, 4, 3`。 

大型の場合`k`、長さ 5 のサイクルなど`k = 10`、サイクル貢献度はまだわずか 5 です。 の`min(k + 1, length)`この式により、完全な回転後に同じサイクル ノードが複数回カウントされることがなくなります。
