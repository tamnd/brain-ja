 ## 解決策
 ## 問題の理解

 長方形のボード上を移動するロボット、カレル用の小さなインタープリターを構築する必要があります。 ボードにはオープンセルとブロックセルが含まれています。 プログラムには、移動、回転、ユーザー定義プロシージャの呼び出し、分岐、条件が true になるまでの繰り返しなどのコマンドが記述されます。 各実行は特定のセルと方向から開始され、ロボットの最終状態を報告するか、プログラムが永久に実行されるかどうかを判断する必要があります。 

入力により、1 つのボード、一連のプロシージャ定義、および実行する複数の独立したプログラムが提供されます。 プロシージャは、それ自体を含む他のプロシージャを間接的に呼び出すことができます。 プログラムは決定論的です。固定されたロボットの状態から、すべてのコマンドは常に同じ決定を下します。 課題はシミュレーションそのものではなく、決定論的な実行がいつ終了できないかを認識することです。 

ボードには最大 40 x 40 のセルがあるため、可能な位置は最大 1600 個で、方向は 4 つだけです。 完全なロボット状態空間には最大 6400 の状態があります。 プロシージャの数は少なく、各プログラム フラグメントの長さは最大でも 100 文字です。 これらの制限により、何も記憶せずに再帰的プログラムを繰り返し展開するアプローチのみが除外されます。 単純なインタプリタは単純なプログラムに従うことができますが、再帰ループにより実際のシミュレーション制限をはるかに超えた実行が作成される可能性があります。 

微妙なケースは、同じソース コマンドをすぐに目に見えて繰り返さない再帰とループから発生します。 プロシージャは、数回呼び出した後でのみ同じ内部ポイントに戻ることができます。 

たとえば、このプログラムは決して終了しません。```
1 1 1 1
.
A=A
1 1 n
A
```正しい出力は次のとおりです。```
inf
```サイクル検出のない不注意な再帰インタープリタが呼び出しを続ける`A`永遠に。 

もう 1 つの問題は、ブロックされた移動が依然として実行されたコマンドであることです。 次のプログラムは、壁に移動しても状態が変わらないため、移動が 1 回失敗すると停止します。```
1 1 0 1
.
1 1 e
ub(m)
```出力は次のとおりです。```
1 1 e
```境界線への接触を無操作ではなくエラーとして扱うシミュレーターは、間違った答えを生成します。 

3 番目のケースは、ループが方向を含む完全な状態に依存する場合です。```
1 2 0 1
..
1 1 e
u b (m)
```ロボットは 1 回移動し、境界に到達して停止します。 出力は次のとおりです。```
1 2 e
```位置のみを追跡すると、同じセルを維持しながら回転コマンドによって将来の動作が変更される可能性があることがわかりません。 

## アプローチ

 直接的なアプローチは、言語を解析してコマンドを再帰的に実行することです。 これが機能するのは、すべてのコマンドに正確な意味と決定的な結果があるためです。 通常のプログラムの場合、このインタプリタはすべてのコマンドを 1 回訪問した後に終了します。 

この問題は、再帰によって無限の実行が作成される場合に発生します。 のような手順`A=A`自然な停止点はありません。 さらに悪いことに、ループはロボットの状態を変更しながら有限のコードを繰り返し実行する可能性があるため、単純に再帰の深さを制限することは有効な解決策ではありません。 

重要な観察は、ロボットが取り得る状態の数が非常に少ないということです。 最初の実行がまだ完了していない間に、インタプリタが同じロボット状態から同じプログラムフラグメントを 2 回目に実行しようとしている場合、その後の動作は同一でなければなりません。 インタプリタはサイクルに入っているため、結果は無限大になるはずです。 

このアイデアを構文ツリーに直接適用できます。 解析された各ノードは、コマンド シーケンス、条件、ループ、またはプロシージャ本体を表します。 評価中に、ノードとロボットの状態のアクティブなペアを記憶します。 現在の再帰スタックにペアが再び出現すると、実行は終了できません。 また、多くの異なるパスが同じ状態の同じフラグメントに到達する可能性があるため、完了した評価もメモ化します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シミュレーション | 無制限、永久に実行可能 | O(再帰の深さ) | 遅すぎる |
 | 構文ノードでのサイクル検出 | O(ノード数 × ロボットの状態) | O(ノード数 × ロボットの状態) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのプログラムを構文ツリーに解析します。 シーケンスはその子を格納します。`if`ノードはその条件と 2 つの分岐を保存します。`until`ノードにはその状態と本体が保存されます。 プロシージャ呼び出しは、プロシージャ本体への参照として保存されます。 
2. ロボットの状態を行、列、方向で表します。 このような状態は最大 6400 個あり、訪問した実行ポイントを記憶することが可能になります。 
3. 現在のロボットの状態を受け取る関数を使用して構文ツリー ノードを実行します。 ノードを評価する前に、このノードとこの状態で構成されるペアが現在の再帰スタックですでにアクティブであるかどうかを確認してください。 そうである場合は、実行が同じ未完了の状況に戻ったため、無限大を返します。 
4. ノードが正常に終了したら、結果の状態をメモ化テーブルに保存します。 同じ状態からの同じノードの今後の実行では、その結果をすぐに使用できます。 
5. 基本コマンドの場合は、ロボットの状態を直接更新します。 プロシージャ呼び出しの場合は、参照されるプロシージャ本体を評価します。 シーケンスの場合、子を左から右に評価します。 条件文の場合は、ブランチを 1 つ選択します。 For ループでは、条件が true になるまで本体を繰り返し評価します。 
6. 要求された開始状態ごとにインタープリタを実行し、ロボットの最終状態を出力するか、`inf`。 

機能する理由: すべての決定的な実行パスは一連のペアです`(program node, robot state)`。 前の出現が終了する前にペアが繰り返される場合、2 つのポイントの残りの計算はまったく同じになります。 実行は同じ無限サイクルを永遠に繰り返します。 このような繰り返しが発生しない場合、アクティブなペアはすべて一意であり、可能なペアの数は有限であるため、計算は最終的に終了する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    r, c, d, e = map(int, input().split())
    grid = [input().strip() for _ in range(r)]

    nodes = []
    def new_node(t, *args):
        nodes.append((t, *args))
        return len(nodes) - 1

    def parse_program(s, idx=0):
        arr = []
        while idx < len(s) and s[idx] != ')':
            ch = s[idx]
            if ch == 'm':
                arr.append(new_node('m'))
                idx += 1
            elif ch == 'l':
                arr.append(new_node('l'))
                idx += 1
            elif ch.isupper():
                arr.append(new_node('call', ch))
                idx += 1
            elif ch == 'i':
                cond = s[idx + 1]
                idx += 3
                a, idx = parse_program(s, idx)
                idx += 1
                b, idx = parse_program(s, idx)
                idx += 1
                arr.append(new_node('if', cond, a, b))
            elif ch == 'u':
                cond = s[idx + 1]
                idx += 3
                a, idx = parse_program(s, idx)
                idx += 1
                arr.append(new_node('until', cond, a))
        return new_node('seq', tuple(arr)), idx

    proc = {}
    raw = []
    for _ in range(d):
        s = input().strip()
        raw.append(s)
    for s in raw:
        name = s[0]
        proc[name] = parse_program(s[2:])[0]

    dirs = {'n': 0, 'e': 1, 's': 2, 'w': 3}
    dr = [-1, 0, 1, 0]
    dc = [0, 1, 0, -1]

    def cond_ok(ch, state):
        x, y, h = state
        if ch == 'b':
            nx, ny = x + dr[h], y + dc[h]
            return nx < 0 or nx >= r or ny < 0 or ny >= c or grid[nx][ny] == '#'
        return "nesw"[h] == ch

    def run_query(start, root):
        memo = {}
        active = set()

        def dfs(node, state):
            key = (node, state)
            if key in memo:
                return memo[key]
            if key in active:
                return None

            active.add(key)
            typ = nodes[node][0]

            if typ == 'm':
                x, y, h = state
                nx, ny = x + dr[h], y + dc[h]
                if 0 <= nx < r and 0 <= ny < c and grid[nx][ny] == '.':
                    ans = (nx, ny, h)
                else:
                    ans = state

            elif typ == 'l':
                x, y, h = state
                ans = (x, y, (h + 3) % 4)

            elif typ == 'call':
                ans = dfs(proc[nodes[node][1]], state)

            elif typ == 'seq':
                ans = state
                for child in nodes[node][1]:
                    ans = dfs(child, ans)
                    if ans is None:
                        break

            elif typ == 'if':
                _, ch, a, b = nodes[node]
                ans = dfs(a if cond_ok(ch, state) else b, state)

            else:
                _, ch, body = nodes[node]
                cur = state
                while not cond_ok(ch, cur):
                    nxt = dfs(body, cur)
                    if nxt is None:
                        ans = None
                        break
                    cur = nxt
                else:
                    ans = cur

            active.remove(key)
            if ans is not None:
                memo[key] = ans
            return ans

        return dfs(root, start)

    out = []
    for _ in range(e):
        i, j, h = input().split()
        program = input().strip()
        root = parse_program(program)[0]
        ans = run_query((int(i)-1, int(j)-1, dirs[h]), root)
        if ans is None:
            out.append("inf")
        else:
            x, y, h = ans
            out.append(f"{x+1} {y+1} {'nesw'[h]}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```パーサーは文字列をすぐに実行するのではなく、ノードを構築します。 サイクル検出にはプログラム フラグメントの安定した ID が必要であるため、これは重要です。 ネストされた括弧とプロシージャ展開の後は、文字列インデックスだけでは十分ではありません。 

評価者が使用するのは、`(node, state)`メモ化キーとして。 この方向性が含まれるのは、異なる方向を向いて同じセルを 2 回訪問すると、まったく異なる未来が訪れる可能性があるためです。 

移動により次のセルがチェックされ、ターゲットがブロックされた場合は状態が変更されません。 ボードの外側も同じ条件でブロックされたものとして扱われます。 

ループ実装は、条件が false の場合にのみ、その本体を繰り返し実行します。 アクティブ セットは、ループ内またはプロシージャ呼び出しを通じて発生する再帰サイクルを検出します。 

## 実用的な例

 から始まるサンプル実行の場合`(1,1,w)`プログラム付き`G`、プロシージャチェーンは`G -> ub(B)`。 重要な状態は次のとおりです。 

| ステップ | フラグメント | ポジション | 方向 | 結果 |
 | --- | --- | --- | --- | --- |
 | 0 |`G`| (1,1) | 西 | 電話`B`|
 | 1 |`B`| (1,1) | 西 | 条件は境界線を参照 |
 | 2 |`m`| (1,1) | 西 | ブロック、変更なし |
 | 3 | ループチェック | (1,1) | 西 | バリアが存在します。停止 |

 最終的な出力は次のとおりです。```
1 1 w
```これは、失敗した移動が状態を保存する必要がある理由を示しています。 

プロシージャを使用したサンプル実行の場合`I=III`:

 | ステップ | フラグメント | ポジション | 方向 | 結果 |
 | --- | --- | --- | --- | --- |
 | 0 |`I`| (2,2) | 南 | 電話`I`|
 | 1 |`I`| (2,2) | 南 | 電話`I`もう一度 |
 | 2 |`I`| (2,2) | 南 | 繰り返されるアクティブなペア |

 インタプリタは、未完了の同じプロシージャ本体と状態を検出するため、結果は次のようになります。```
inf
```これは、再帰の深さの制限が不要である理由と、正確なサイクル検出で十分である理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(V × S) | 各構文ノードは、ロボットの状態ごとに最大 1 回評価されます。 
| スペース | O(V × S) | メモ化とアクティブな追跡ストアのノードと状態のペア |

 ここ、`V`は解析されたノードの数であり、`S`はロボットの状態の数で、最大 6400 です。入力サイズが小さいため、完全な状態グラフはメモリ制限内に問題なく収まります。

 ## 特殊なケース

 アクティブ セットにはプロシージャ ノードが現在の方向と位置とともに格納されるため、再帰プロシージャのケースが処理されます。 で`A=A`の場合、最初の呼び出しが待機している間に 2 番目の呼び出しはまったく同じペアに到達するため、評価器はすぐに無限大を返します。 

ブロックされたムーブメントのケースは内部で処理されます。`m`指示。 境界線や壁によってプログラムが終了したり、ロボットの状態が変更されたりすることはありません。 これは言語のセマンティクスと一致し、意図的に障害物をテストするプログラムでの誤った回答を防ぎます。 

方向依存の場合は、状態キーに行、列、見出しの 3 つのコンポーネントがすべて含まれているため機能します。 別の方向を向いているときに同じタイルに戻ることは、完全な状態が繰り返されない限り、サイクルとみなされません。
