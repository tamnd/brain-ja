 ## 解決策
 ## 問題の理解

 各プレーヤーはスコアのリストを持っており、ホールごとに 1 つのスコアが表示されます。 不明な制限を適用した後に記憶された値`l`オリジナルのスコアではありません`x`、 しかし`min(x, l)`。 固定の場合`l`、すべてのプレーヤーは、すべてのラージ ホール スコアを`l`。 合計が小さいほど優れており、プレイヤーのランクは、調整された合計がそのプレイヤーのランクより大きくないプレイヤーの数となります。 

課題は、特定の限界を見つけることではありません。 代わりに、次の値を選択することもできます。`l`これにより、各プレイヤーに可能な限り最高の順位が与えられ、その最低達成可能な順位を出力する必要があります。 

プレーヤーの数は最大 500 人、ホール数は最大 50 です。スコアが最大 500 人になる可能性があるため、可能な制限を超える直接シミュレーションは不可能です。`10^9`。 有益な制限は、プレーヤーごとのスコア値の数が少ないことです。 プレイヤーの調整されたスコアは次の場合にのみ変化します。`l`元のホールスコアの 1 つに達するため、興味深いポイントの総数は次のように制限されます。`p * h`、スコア値の大きさではありません。 

難しいのは、1 人のプレイヤーにとっての最適な制限が 2 つのスコア値の間のどこかにある可能性があることです。 入力に現れる制限だけをチェックするソリューションでは、最適値を見逃す可能性があります。 もう 1 つのよくある間違いは、すべての対戦相手に対して個別に最適な制限を見つけることです。 同じ`l`すべての対戦相手に対するプレーヤーの立場を同時に改善する必要があります。 

例えば：```
2 1
5
10
```元の値のみをテストする場合は、`l = 5`そして`l = 10`。 で`l = 5`、両方のプレイヤーのスコアは 5 なので、最初のプレイヤーのランクは 2 になります。`l = 10`、スコアは 5 と 10 なので、最初のプレイヤーのランクは 1 です。答えは 1 です。このケースは、制限間の間隔だけでなく、制限自体が重要である理由を示しています。 

別の境界ケースは次のとおりです。```
2 2
100 100
1 1
```最初のプレイヤーが 2 番目のプレイヤーに勝つことはできません。 あらゆるポジティブなことに対して`l`、2 番目のプレーヤーの合計スコアは最大 2 ですが、最初のプレーヤーの合計スコアは少なくとも 2 であり、厳密にはそれが優れていることはありません。 正しいランクは次のとおりです。```
2 1
```すべてのプレイヤーが最終的にはより良くなることができると想定した不注意な実装`l`ここで成長は失敗します。 

## アプローチ

 簡単なアプローチは、可能なすべての値を試してみることです。`l`、すべての調整されたスコアを計算し、プレーヤーを並べ替えて、最高のランクを記録します。 これは文字通りすべての可能なゲーム調整をチェックするため、これは正しいです。 しかし、`l`と同じ大きさにすることができます`10^9`, したがって、これは機能しません。 

より良い見方は、プレーヤーをペアごとに比較することです。 プレーヤーを修正する`i`。 間隔が分かれば、`l`どこ`i`他のプレイヤーに勝つ`j`、その後のランク`i`同じ制限で倒される対戦相手の数ができるだけ多い場合に最適です。 

2 人のプレーヤーの場合、スコア差は区分的線形関数です。 公式が変わる唯一の場所は、これら 2 人のプレーヤーのホールスコアです。 2 つの連続するそのような値の間では、すべての穴はすでにキャップされているか、まだ等しいかのいずれかです。`l`、したがって、合計スコアは次の一次関数になります。`l`。 これは、重要な範囲をスイープして、プレイヤーがどこにいるかを正確に判断できることを意味します。`i`選手よりも上手くなる`j`、それらの間隔を保存します。 

すべての対戦相手に対するすべての間隔を収集した後、残りの問題は、同じ整数値をカバーする間隔の最大数を見つけることです。`l`。 これは、開始イベントと終了イベントを使用した標準的なスイープ ラインの問題です。 

総当たりアプローチは、スコア関数が固定制限に対して単純であるため機能しますが、可能な制限が多すぎるため失敗します。 スコア関数が区分的に線形であるという観察により、無限の検索空間が小さな間隔の集合に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(限界数 * p * h) | O(p) | 遅すぎる |
 | 最適 | O(p²h log(ph)) | O(ph) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各プレイヤーごと`i`、このプレーヤーの最高ランクを知りたいとします。 他のプレイヤーの数を数えます`i`ある共通の値に対して厳密に勝つことができます`l`。 
2. あらゆる対戦相手に対して`j`、プレイヤーが制限の間隔を構築します。`i`調整された合計スコアがプレーヤーより小さい`j`。 
3. これらのインターバルを構築するには、プレーヤーに属するすべてのホールスコアを収集します`i`そして`j`。 これらの値は、正の整数を、調整されたスコアが両方とも一次関数である範囲に分割します。 
4. 各レンジで、2 人のプレーヤー間の線形差を計算します。 違いには形があるので`a*l+b`、負の整数部分を正確に見つけることができます。 これらの整数は限界です。`i`ビート`j`。 
5. 結果の間隔をスイープ ライン構造に追加します。 開始イベントにより倒された敵の数が増加し、インターバル終了後のイベントにより減少します。 
6. すべての対戦相手を処理した後、同時にアクティブなインターバルの最大数は、対戦相手が倒したプレイヤーの最大数となります。`i`。 最高ランクは`p - maximum_beaten`。 

なぜ効果があるのか:

 固定された対戦相手の場合、2 人のプレーヤー間の比較は、スコア値または 2 つの線形関数が交差する場所でのみ変化します。 インターバル構築では、最初のプレーヤーが優れているすべての制限を正確に見つけます。 次に、スイープ ラインは、それらの間隔によって表されるすべての可能な制限をチェックし、同時に倒すことができる敵の最大数を見つけます。 ランクは正確に、倒されていないプレイヤーの数にプレイヤー自身を加えたものであるため、計算される値は最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def adjusted_diff_coeff(a, b, x):
    m = 0
    c = 0
    for u, v in zip(a, b):
        if x < u:
            m += 1
        else:
            c += u
        if x < v:
            m -= 1
        else:
            c -= v
    return m, c

def intervals(a, b):
    pts = sorted(set(a + b))
    segs = []

    if pts[0] > 1:
        segs.append((1, pts[0] - 1))
    for x in pts:
        segs.append((x, x))
    for x, y in zip(pts, pts[1:]):
        if x + 1 <= y - 1:
            segs.append((x + 1, y - 1))
    segs.append((pts[-1] + 1, None))

    ans = []

    for l, r in segs:
        m, c = adjusted_diff_coeff(a, b, l)

        if r is None:
            if m == 0:
                if c < 0:
                    ans.append((l, None))
            elif m < 0:
                ans.append((l, None))
            continue

        if l == r:
            if m * l + c < 0:
                ans.append((l, l))
            continue

        if m == 0:
            if c < 0:
                ans.append((l, r))
        elif m > 0:
            # m*x+c < 0
            hi = (-c - 1) // m
            if hi >= l:
                ans.append((l, min(r, hi)))
        else:
            # m*x+c < 0, multiply by -1
            lo = c // (-m) + 1
            if lo <= r:
                ans.append((max(l, lo), r))

    return ans

def solve():
    p, h = map(int, input().split())
    scores = [list(map(int, input().split())) for _ in range(p)]

    res = []

    for i in range(p):
        events = []
        for j in range(p):
            if i == j:
                continue
            for l, r in intervals(scores[i], scores[j]):
                events.append((l, 1))
                if r is not None:
                    events.append((r + 1, -1))

        events.sort()
        cur = 0
        best = 0
        k = 0
        while k < len(events):
            pos = events[k][0]
            while k < len(events) and events[k][0] == pos:
                cur += events[k][1]
                k += 1
            best = max(best, cur)

        res.append(str(p - best))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```あるプレーヤーのランクは別のプレーヤーのインターバルに影響を与えないため、main 関数はプレーヤーを一度に 1 人ずつ処理します。 の`intervals`この関数は 1 組のプレーヤーを処理し、最初のプレーヤーが比較に勝つすべての制限を返します。 

ヘルパーさん`adjusted_diff_coeff`固定セグメント上のスコア差の線形表現を計算します。 ホールは一定のオリジナル スコアまたは 1 つのコピーのいずれかに貢献します。`l`したがって、差全体は常に次のように書くことができます。`m*l+c`。 

間隔コードは 3 つのケースを分けます。 単一のポイントで 1 つの正確な制限をチェックします。 有限セグメントは線形不等式を解きます。 無限尾部は上端点がないため、個別に処理されます。 Python の整数は、スコアが到達した場合でもオーバーフローを回避します`10^9`。 

スイープは使用します`r + 1`間隔には整数制限が含まれるため、イベントの終了に使用されます。 この変換を忘れるのは、よくある間違いです。

 ## 特殊なケース

 最初のエッジ ケースは、最適な制限が元のスコアの 1 つではない場合です。 入力の場合:```
2 1
5
10
```間隔`(5,10)`スコア関数がブレークポイント間で線形であるため、比較が変更され、アルゴリズムがそれを検査します。 

2 番目のエッジケースは、他のプレイヤーに決して勝つことができないプレイヤーです。 のために：```
2 2
100 100
1 1
```差分関数が負になることはありません。 インターバル ジェネレーターは勝利インターバルを生成しないため、スイープでは、最初のプレーヤーの場合は 0 人、2 番目のプレーヤーの場合は 1 人の倒された対戦相手がカウントされます。 

3 番目のケースは、多数の同一スコアです。```
3 1
7
7
7
```すべてのペアの比較は常に等しいため、どのプレイヤーにも勝利の間隔はありません。 倒した対戦相手の最大数は 0 で、すべてのランクが 3 になり、同じスコアが同じランクを共有するという定義と一致します。
