 ## 解決策
 ## 問題の理解

 この問題は、一連のグラフの走査として見ることができます。`n`カードの種類。 アリスはカードから始まる`1`そしてカードを取得したい`n`他の 3 人のプレイヤー (クイーン、キング、ジャック) とトレードすることによって。 各プレイヤーには、カードを望ましい順に並べる優先リストがあり、交換はアリスとプレイヤーの両方が交換を希望する場合にのみ許可されます。アリスは、彼女が与えるカードよりも厳密に大きい番号のカードを取得する必要があり、プレイヤーは、自分が与えるカードよりも価値のあるカードを取得する必要があります。 これは、取引が可能なカード間の有向エッジのセットを定義します。 

入力は複数のテスト ケースを提供します。 各テスト ケースは次のように指定します`n`そして次の 3 つの順列`[1,2,...,n]`クイーン、キング、ジャックの好みを表しています。 出力は、カードからの一連の取引で「YES」のいずれかになります。`1`に`n`または、そのようなシーケンスが存在しない場合は「NO」。 各取引には、プレイヤーとアリスが受け取るカードのラベルが付けられます。 

制約は、次の合計に対してほぼ直線的な時間で動作するアルゴリズムが必要であることを意味します。`n`すべてのテスト ケースにわたって、最大 200,000 件になります。 二次解法`n`遅すぎるでしょう。 エッジケースには、中間取引が存在するが、アリスの厳密な優先順序付けのために連鎖できない状況が含まれます。 たとえば、アリスが以下から取引できるとしたら、`1→2`キングと、そしてから`2→4`女王様と一緒ですが、女王様はカードを受け付けません`2`引き換えに`4`、そして到達`n`個人取引が存在しても不可能です。 

取引のすべての順列を再帰的に試行する単純なアプローチは、時間通りに失敗し、アリスの優先制約を尊重するという点でも失敗します。 

## アプローチ

 ブルートフォース手法では、カードから考えられるすべての取引シーケンスをモデル化します。`1`に`n`。 アリスが持っているカードごとに、アリスとプレイヤーの両方の好みを尊重する各プレイヤーとの可能な取引をすべてチェックします。 最悪の場合、それぞれの`n`カード、まであります`3*(n-1)`可能性のある取引を再帰的に探索することで、シーケンスの数が指数関数的に増加します。 これは明らかに実行不可能な場合、`n`は 2×10^5 です。 

重要な観察は、アリスは常に自分のカードの番号を増やしたいと考えており、プレイヤーの優先順位は固定されているということです。 この問題は、ノードがカードでエッジが許可された取引を表す有向グラフとして扱うことができます。 アリスは上方向にのみ移動するため、グラフは非循環であり、小さい番号のカードから大きい番号のカードへのエッジのみが存在します。 これにより、貪欲または動的プログラミング アプローチが可能になります。カードごとに、最も早く到達可能な上位カードと、そこにどの取引がつながるかを記録するだけで済みます。 基本的に、各プレイヤーが各ステージで取引する最高のカードを使用して到達可能な配列を構築し、そこから遡ることができます。`n`に`1`パスを再構築します。 

最適なアプローチには、プレーヤーの好みをポジションにマッピングして高速検索を行うことが含まれます。 カードごとに`i`、最小限のカードを見つけることができます`j>i`各プレイヤーはアリスを与えて、繰り返し次のカードにジャンプします。 これにより、探索が指数関数的なものから線形なものに減少します。`n`プレーヤーごとに 1 回スキャンし、事前に計算された位置を使用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 各テスト ケースをループします。 
2.読む`n`そして、クイーン、キング、ジャックの 3 つの優先順列です。 
3. 各順列を前処理して、`position`そのような配列`position[player][card]`のランクを与える`card`そのプレイヤーの好みで。 これにより、プレイヤーがトレードに応じるかどうかを常に比較することができます。 
4.初期化`current_card = 1`そして空のリスト`trades`。 
5. ながら`current_card < n`、3 人のプレイヤー全員を調べて、アリスに与える意思のある最小限のカードを次のように調べます。`next_card > current_card`そしてプレイヤーが好むのは`current_card`以上`next_card`。 複数の有効な取引が存在する場合は、いずれかを選択します (エッジは上向きのみであるため、貪欲に機能します)。 
6. 有効な取引が存在しない場合は、このテスト ケースに対して「NO」を出力して中断します。 それ以外の場合は追加します`(player, next_card)`に`trades`そして更新します`current_card = next_card`。 
7. もし`current_card = n`、「YES」を出力、長さ`trades`、取引リスト。 

不変条件というのは、`current_card`常に増加し、すべての取引はアリスの好みを尊重します。 カードを減らすことはできないため、サイクルは不可能であり、プロセスが確実に終了します。 事前に計算された`position`配列は、プレーヤーの受け入れチェックが一定時間であることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        perm_q = list(map(int, input().split()))
        perm_k = list(map(int, input().split()))
        perm_j = list(map(int, input().split()))

        # Map card -> position for each player for fast lookups
        pos_q = [0]*(n+1)
        pos_k = [0]*(n+1)
        pos_j = [0]*(n+1)
        for idx, card in enumerate(perm_q):
            pos_q[card] = idx
        for idx, card in enumerate(perm_k):
            pos_k[card] = idx
        for idx, card in enumerate(perm_j):
            pos_j[card] = idx

        current = 1
        trades = []

        while current < n:
            next_trade = None
            # Check Queen
            for card in range(current+1, n+1):
                if pos_q[card] > pos_q[current]:
                    next_trade = ('q', card)
                    break
            # Check King
            for card in range(current+1, n+1):
                if pos_k[card] > pos_k[current]:
                    if next_trade is None or card < next_trade[1]:
                        next_trade = ('k', card)
                    break
            # Check Jack
            for card in range(current+1, n+1):
                if pos_j[card] > pos_j[current]:
                    if next_trade is None or card < next_trade[1]:
                        next_trade = ('j', card)
                    break
            if next_trade is None:
                print("NO")
                break
            trades.append(next_trade)
            current = next_trade[1]
        else:
            print("YES")
            print(len(trades))
            for p, c in trades:
                print(f"{p} {c}")

if __name__ == "__main__":
    solve()
```このソリューションは、O(1) トレード チェックのポジション配列を事前計算し、アリスを上位のカードに繰り返し移動することで、すべてのトレードが両当事者を満足させることを保証します。 すべてのパスは厳密に増加しており、より良い代替手段が存在しないため、許容可能な最小限のカードを貪欲に選択することは安全です。
