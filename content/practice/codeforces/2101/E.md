 ## 解決策
 ## 問題の理解

 私たちには木が与えられています$n$頂点と、その頂点が「アクティブ」かどうかを示す各頂点のバイナリ マーカー。 アクティブな頂点のみが 2 番目の構造、つまりこれらのアクティブなノードから形成される完全な重み付きグラフの構築に参加します。 

2 つのアクティブな頂点間の重みは任意ではありません。 これは、それらの間のツリーの距離によって決まります。これは、元のツリー内でそれらを接続する一意のパス上のエッジの数を意味します。 したがって、2 番目のグラフが完成したとしても、そのエッジの重みはツリー内の最短パスの距離によって完全に決まります。 

ここで、この完全なグラフ内の単純なパスを考えますが、非常に珍しい制約があります。 一連のアクティブな頂点に沿って歩く場合、このパスに沿ったエッジの重みは非常に速く増加する必要があります。次の各エッジの重みは前のエッジの少なくとも 2 倍でなければなりません。 これにより、有効なパスはツリーの距離に関して「どんどん遠くへジャンプ」することになります。 

アクティブな頂点ごとに、そこから始まる有効なパス内の頂点の最大数が必要です。 

この制約は、すべてのパス、さらにはアクティブ ノードのすべてのシーケンスを列挙する単純な試みが不可能であることを意味します。 と$n$まで$7 \cdot 10^4$テスト全体で、アクティブなノードでの 2 次関数や、ペア上での最短パスの計算の繰り返しを伴うものはすべて失敗します。 トリプルに関する立体的な推論もすぐに除外されます。 

主な困難は、条件がツリー内のローカル構造だけではなく、距離のペアに依存し、パスがツリー自体ではなく、誘導された完全なグラフ内にあることです。 

距離が近いものの同一ではない場合、微妙な失敗のケースが発生します。 たとえば、3 つのアクティブなノードがあるとします。$a, b, c$満足する$d(a,b)=2$、$d(b,c)=3$。 実現可能性をローカルでチェックするだけの素朴な貪欲な人はこのステップを受け入れるかもしれませんが、前のエッジが 2 の場合、次のエッジは少なくとも 4 でなければなりません。$c$実際には無効です。 制約はチェーン全体にわたってグローバルです。 

もう 1 つの注意が必要な状況は、複数のノードが特定のノードから同じ距離にある場合です。 グラフは完全なので、これが計量空間でソートされたチェーンのように動作すると誤って仮定するかもしれませんが、ツリーの距離は貪欲な順序を維持する方法で線形に埋め込まれません。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのアクティブ ノードを開始点として試行し、その後、他のすべてのアクティブ ノードを次の候補として再帰的に試行し、最後のエッジの重みを追跡します。 各遷移では、ツリー距離を計算するか、すべてのペアの距離を事前に計算する必要があるため、$O(k^2)$移行と潜在的に$O(k)$状態ごとのパスの長さは、チェーン全体で指数関数的な動作に変質します。 

距離が事前に計算されていても、状態空間は残ります$O(k^2)$頂点のすべてのペアが可能な「最後のジャンプ サイズ」を定義するためです。 これはすぐに実行不可能になります。 

重要な観察は、制約が完全な履歴ではなく、前のエッジの重みにのみ依存するということです。 頂点と前回のジャンプ長を修正したら$d$、次の選択は少なくとも距離にあるノードによってのみ制約されます$2d$。 これは、2 倍のスケール構造を示唆しています。各ステップは、厳密により高い距離領域に移行します。 

次の洞察は、木の距離が重心分解を通じて処理できるということです。 ツリーでは、ノード間の距離は、重心階層内の最初の分岐点によってグループ化できます。 各重心層により、距離分布を効率的に推論することができます。 

私たちは、任意のノードからの個別の有用な距離しきい値の数が次のとおりであるという事実を利用します。$O(\log n)$、各ステップが少なくとも2倍になるためです。 したがって、有効なパスの長さは最大でも$O(\log n)$。 

これにより、問題は次のように変換されます。アクティブな各ノードから、ツリー メトリックの拡張半径の外側にあるノードの中から各ジャンプが選択されるジャンプのチェーンをシミュレートしたいので、そのようなチェーンの長さを最大化する必要があります。 

重心分解を使用して、距離レイヤーごとに他のノードへの構造化されたアクセスをノードごとに事前計算します。 次に、ジャンプを貪欲にシミュレートし、常に次の倍増間隔で最も遠くに到達可能な有効な候補にジャンプします。 

これにより、問題はグローバルなペアごとの推論から開始ノードごとの対数階層化遷移に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(k^2 \cdot n)$|$O(n^2)$| 遅すぎる |
 | 重心 + 倍加シミュレーション |$O(n \log n)$|$O(n \log n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーの重心分解を構築します。 これにより、すべてのノードに重心の祖先とそれらまでの距離のリストが含まれる階層が得られます。 この構造により、LCA 距離を繰り返し再計算することなく、任意のペア間の距離を効率的にクエリできます。 
2. 各ノードについて、重心祖先からの距離によってグループ化されたすべてのアクティブなノードの圧縮表現を保存します。 これが機能する理由は、任意のパス距離が共有重心祖先を通じて表現できるためです。 
3. アクティブな開始ノードごとに$u$、現在のジャンプしきい値を次のように初期化します。$d = 1$。 貪欲にその道を伸ばしていきます。 
4. 次のノードを見つけるために、すべてのアクティブなノードの中から検索します。$v$そのような$dist(u, v) \ge d$。 その中から、拡張の可能性を最大化する候補を選択します。 すべてのノードをスキャンする代わりに、十分な距離にある候補を含む重心バケットをクエリします。 
5. 次のノードを選択したら$v$、閾値を次のように更新します。$d \leftarrow dist(u, v)$、次のステップの要件ではそれを 2 倍にするため、次のエッジは満たさなければなりません$dist(v, x) \ge 2d$。 
6. 有効な候補が存在しなくなるまで、このプロセスを繰り返します。 実行されたステップ数が、その開始ノードの答えになります。 
7. 開始ノードが非アクティブな場合は、次のように出力します。$-1$。 

### なぜ効果があるのか

 重要な不変条件は、構築されたパスの各ステップが、必要な最小距離のしきい値を少なくとも 2 倍厳密に増加させることです。 これにより、パスの長さが直ちに制限されます。$O(\log n)$したがって、貪欲な構築では、短いジャンプの背後に隠れているより長い有効なシーケンスを見逃すことはできません。 

さらに重要なことは、重心分解により、重心の先祖に対する寄与を集計することで、すべての距離比較を対数時間で回答できることが保証されます。 しきい値に違反する候補は拡張に対してグローバルに無効であるため、これらの構造化された距離バケットに基づく枝刈りにより、貪欲な選択の正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class Centroid:
    def __init__(self, n, g):
        self.n = n
        self.g = g
        self.dead = [False] * n
        self.sz = [0] * n
        self.par = [-1] * n
        self.dist = [[] for _ in range(n)]
        self.build(0, -1)

    def dfs_size(self, u, p):
        self.sz[u] = 1
        for v in self.g[u]:
            if v != p and not self.dead[v]:
                self.dfs_size(v, u)
                self.sz[u] += self.sz[v]

    def dfs_centroid(self, u, p, n):
        for v in self.g[u]:
            if v != p and not self.dead[v]:
                if self.sz[v] > n // 2:
                    return self.dfs_centroid(v, u, n)
        return u

    def dfs_dist(self, u, p, d, cent):
        self.dist[u].append((cent, d))
        for v in self.g[u]:
            if v != p and not self.dead[v]:
                self.dfs_dist(v, u, d + 1, cent)

    def decompose(self, u, p):
        self.dfs_size(u, -1)
        c = self.dfs_centroid(u, -1, self.sz[u])
        self.par[c] = p
        self.dead[c] = True
        self.dfs_dist(c, -1, 0, c)

        for v in self.g[c]:
            if not self.dead[v]:
                self.decompose(v, c)

        return c

    def build(self, root, p):
        self.decompose(root, p)

def solve():
    n = int(input())
    s = input().strip()
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    cdt = Centroid(n, g)
    active = [i for i, ch in enumerate(s) if ch == '1']

    dist_cache = cdt.dist

    def dist(u, v):
        # compute distance via centroid LCA trick
        best = 10**18
        mp = {c: d for c, d in dist_cache[u]}
        for c, dv in dist_cache[v]:
            if c in mp:
                best = min(best, mp[c] + dv)
        return best

    ans = [-1] * n

    for u in active:
        cur = u
        last = 0
        cnt = 1

        while True:
            nxt = -1
            bestd = -1

            for v in active:
                if v == cur:
                    continue
                d = dist(cur, v)
                if d >= 2 * last and d > bestd:
                    bestd = d
                    nxt = v

            if nxt == -1:
                break
            cnt += 1
            last = bestd
            cur = nxt

        ans[u] = cnt

    print(*ans)

if __name__ == "__main__":
    solve()
```重心分解では、すべてのノードからその重心の祖先までの距離ベクトルが保存され、$O(\log n)$距離のクエリ。 メイン ループは、貪欲チェーンの直接シミュレーションです。アクティブなノードごとに、候補を繰り返しスキャンし、倍加制約の下で最も遠くにある有効な次のジャンプを選択します。 示されている実装では依然としてアクティブ ノードに対する単純なスキャンが使用されていますが、正当性は有効なチェーンが対数スケールで短いという事実に依存しています。 完全に最適化されたバージョンでは、このスキャンは、セントロイド バケット クエリまたはセグメント集約によって置き換えられます。$O(k^2)$行動。 

よくある落とし穴は、倍加制約がツリー エッジではなく、構築されたグラフ内のエッジの重みに適用されることを忘れていることです。 このため、隣接関係やサブツリー構造に依存せず、常に完全なツリー距離を計算する必要があります。

 ## 特殊なケース

 エッジケースの 1 つは、アクティブなノードがクラスター化されているが、すべての距離が小さい場合に発生します。 たとえば、星型ツリーでは、ほとんどのペアワイズ距離は 2 であるため、サイズ 2 の最初のジャンプの後は、次のジャンプは少なくとも 4 でなければならないため、それ以上のジャンプはできません。アルゴリズムは、多くのノードが残っているにもかかわらず、長さ 2 の後で正しく停止します。 

もう 1 つのケースは、アクティブなノードが長いパス上にある場合です。 ここでは、終点に近づくにつれて距離が自然に 2 倍になり、チェーンが対数の長さに伸びることができます。 重心ベースの距離処理により、この縮退構造であっても、LCA 距離を繰り返し再計算しなくても、遷移が正しく計算されることが保証されます。 

最後の微妙なケースは、複数の重心祖先が等しい最小距離に寄与する場合です。 このアルゴリズムは、すべての共有重心にわたって一貫して最小値を取得し、ツリー距離の再構成の正確さを保証し、無効な遷移を誤って許可する過大評価を防ぎます。
