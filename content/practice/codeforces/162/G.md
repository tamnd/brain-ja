 ## 解決策
 ## 問題の理解

 2 から 36 までの任意の基数で書かれたいくつかの整数が与えられます。9 より上の数字は大文字で表されるため、基数 16 では数字のシーケンスは次のように続きます。`A, B, C, D, E, F`、そしてより大きな拠点では、それは最大まで続くかもしれません`Z`。 

タスクは、すべての数値の合計を計算し、その結果を同じ基数で出力するだけです。 

興味深いのは、入力数値が 10 進数で書かれていないことです。 指定された基数に従って各桁を正しく解釈し、加算を実行して、最終的な 10 進数値を同じ記数法に変換し直す必要があります。 

制約は非常に小さいです。 数字は最大 10 個あり、それぞれに最大 5 桁が含まれます。 最大基数であっても、1 つの数値の最大値は次のとおりです。$$36^5 - 1 = 60,\!466,\!175$$合計は標準の整数型内に簡単に収まり、Python の整数はいずれにしてもはるかに大きな値を処理します。 これは、ここでは効率が課題ではないことを意味します。 本当の課題は、塩基変換を正しく実装することです。 

いくつかのエッジケースでは、不注意な実装が静かに破壊される可能性があります。 

よくある間違いは、先頭のゼロを誤って処理することです。 考慮する：```
2
10
0012
0008
```正しい出力は次のとおりです。```
20
```先頭のゼロは入力表現の一部のみです。 数値には影響しません。 

もう 1 つの簡単な間違いは、9 より上の数字が文字であることを忘れることです。 例えば：```
2
16
A
1
```正しい出力は次のとおりです。```
B
```ソリューションがのみを使用して文字を変換する場合`'0'`に`'9'`、16 進形式の数字では失敗します。 

Base 2 では、変換のバグもすぐに明らかになります。```
2
2
1111
1
```正しい出力は次のとおりです。```
10000
```これにより、ターゲット ベースへの変換中にキャリーが正しく処理されるかどうかがチェックされます。 

もう 1 つの微妙なケースは、合計がゼロの場合に現れます。```
3
8
0
00
000
```正しい出力は次のとおりです。```

```値が正である間に繰り返し除算を行う変換ループでは、誤って代わりに空の文字列が出力される場合があります。`"0"`。 

## アプローチ

 最も直接的な解決策は、数値体系の変換を手動でシミュレートすることです。 

各入力文字列について、左から右に数字をスキャンし、位置表記の動作とまったく同じ方法でその 10 進値を評価できます。$$(((d_1)\cdot radix + d_2)\cdot radix + d_3)\cdots$$すべての 10 進数値を取得したら、それらを加算します。 

最後に、剰余モジュロを繰り返し取得して、結果の 10 進数をターゲットの基数に変換します。`radix`。 それぞれの余りが 1 つの出力桁になります。 

すべての数値は最大 5 桁であり、最大でも 10 個の数値があるため、完全に手動で実装しても実行される操作はわずか数百です。 

ブルートフォースの代替手段は、ターゲットベースで直接桁ごとに加算し、キャリーを使用して教科書の加算をシミュレートすることです。 弦が細いのでこれも効果的です。 すべての数値を最下位桁で整列し、各列を合計し、キャリーを伝播して、答えを作成します。 

Python はすでに任意のサイズの整数を安全に処理しているため、手動の基数変換アプローチはより簡単です。 すべてのベースに加算ロジックを実装する代わりに、タスクを次のように削減します。 

1. 入力されたすべての数値を 10 進数に変換します。 
2. 通常どおり追加します。 
3. 最終値を逆変換します。 

位置記数体系の構造により、この縮約は自然になります。 数値が整数として解釈されると、算術演算は元の表現に依存しなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース ディジット シミュレーション | O(n * L) | O(L) | 承認済み |
 | 最適な変換アプローチ | O(n * L) | O(L) | 承認済み |

 ここ、`L`最大桁数は 5 です。 

## アルゴリズムのチュートリアル

 1.読む`n`そして`radix`。 
2. 桁変換用のヘルパー関数を作成します。 

キャラクター`'0'`を通して`'9'`値にマッピングする`0`を通して`9`、 その間`'A'`を通して`'Z'`にマップします`10`を通して`35`。 
3. 各入力文字列を 10 進形式に変換します。 

値から開始`0`。 すべてのキャラクターについて:$$value = value \times radix + digit$$これは位置表記の定義に従います。 
4. 変換されたすべての値を 1 つの整数に加算します。`total`。 
5. 特殊なケースに対処する`total == 0`。 

出力`"0"`すぐに。 そうしないと、変換ループによって空の文字列が生成されます。 
6.変換`total`ターゲット基地に戻ります。 

繰り返し:

 - 取る`total % radix`- 残りを文字表現に変換します
 - 追加します
 - 分割する`total //= radix`最下位桁を最初に抽出するため、桁は逆の順序で表示されます。 
7. 収集した数字を反転し、結果を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、数値体系の位置定義に依存しています。 

数値を桁ごとに読み取る場合、現在の値に基数を乗算すると、前のすべての桁が 1 桁左にシフトされます。 新しい数字を追加すると、次に最下位の数字が挿入されます。 文字列全体を処理した後、計算された整数は、元の表記法で表される数学的値と等しくなります。 

逆変換も位置表記に従います。 モジュロを取る`radix`上位の桁はすべて基数で割り切れるため、最下位桁が抽出されます。 除算を繰り返すと、表現全体が再構築されるまで、処理された数字が 1 つずつ削除されます。 

どちらの変換も数値を正確に保持するため、最終的に出力される文字列は元の基数での正しい合計を表します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

DIGITS = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ"

def char_to_value(c):
    if '0' <= c <= '9':
        return ord(c) - ord('0')
    return ord(c) - ord('A') + 10

def to_decimal(s, radix):
    value = 0
    for ch in s:
        value = value * radix + char_to_value(ch)
    return value

def from_decimal(x, radix):
    if x == 0:
        return "0"

    result = []

    while x > 0:
        result.append(DIGITS[x % radix])
        x //= radix

    return ''.join(reversed(result))

def solve():
    n = int(input())
    radix = int(input())

    total = 0

    for _ in range(n):
        s = input().strip()
        total += to_decimal(s, radix)

    print(from_decimal(total, radix))

solve()
```解は 2 つの独立した変換関数に分割されます。`to_decimal`指定された基数で文字列を解釈します。 乗算ステップでは、手作業で数値を作成するのとまったく同じように、以前に処理された数字を 1 つの基本位置だけ左にシフトします。`from_decimal`逆変換を実行します。 剰余演算では、最下位から最上位の順に数字が抽出されるため、収集されたリストは最後に反転する必要があります。 

の`DIGITS`string は、数値から文字への明確なマッピングを提供します。 索引`10`になる`'A'`、 索引`15`になる`'F'`、 等々。 

ゼロに対する特別な処理は不可欠です。 これがなければ、変換ループは決して実行されません。`x == 0`の代わりに空の文字列を生成します。`"0"`。 

Python の整数はすでに任意精度をサポートしているため、オーバーフローが心配されることはありません。

import io

    if '0' <= c <= '9':
        return ord(c) - ord('0')
    return ord(c) - ord('A') + 10

def to_decimal(s, radix):
    value = 0
    for ch in s:
        value = value * radix + char_to_value(ch)
    return value

def from_decimal(x, radix):
    if x == 0:
        return "0"

    result = []

    while x > 0:
        result.append(DIGITS[x % radix])
        x //= radix

    return ''.join(reversed(result))

def solve():
    input = sys.stdin.readline

    n = int(input())
    radix = int(input())

    total = 0

    for _ in range(n):
        total += to_decimal(input().strip(), radix)

    print(from_decimal(total, radix))

    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output
