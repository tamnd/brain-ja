 ## 解決策
 ## 問題の理解

 単一の整数が与えられ、それが非常に具体的な素数特性を満たすかどうかを判断する必要があります。 

左端の数字を繰り返し削除して形成されたすべての接尾辞がまだ素数である場合、その数値は切り捨て可能であるとみなされます。 たとえば、から始めて、`9137`、次のことを確認します。`9137`、`137`、`37`、`7`4 つの数字はすべて素数なので、答えは次のようになります。`"YES"`。 

番号には数字を含めることもできません`0`。 のような値`103`定義では明示的にゼロが禁止されているため、一部の接尾辞がたまたま素数であっても、ただちに失敗します。 

入力制限は最大です`10^7`、これは十分に小さいため、直接の素数性テストは完全に実用的です。 1 つの数値の平方根素数チェックには約`O(sqrt(n))`操作。 までの番号なので、`10^7`最大 8 桁の場合、テストする必要があるのは最大 8 つのサフィックスのみです。 最悪の場合でも、これは数万回の算術演算にすぎず、制限時間を大幅に下回ります。 

難しい部分はパフォーマンスではなく、すべてのサフィックスを正しく生成して検証することです。 

簡単な間違いの 1 つは、1 桁の接尾辞も素数でなければならないことを忘れることです。 

考慮する：```
19
```接尾辞は次のとおりです。`19`、`9`それでも`19`それ自体がプライムであり、`9`ではないので、正しい答えは`"NO"`。 

もう 1 つのよくあるバグは、ゼロの制限を無視することです。 

考慮する：```
1013
```接尾辞は次のとおりです。`1013`、`13`、`3`それらはすべて素数ですが、その数値にはゼロが含まれているため、依然として失敗します。 正しい答えは、`"NO"`。 

3 番目の微妙な問題は治療です`1`プライムとして。 

考慮する：```
11
```接尾辞は次のとおりです。`11`、`1`以来`1`は素数ではありません。答えは次のようになります。`"NO"`。 

誤った素数性テストを使用する不注意な実装により、誤って素数性テストが受け入れられる可能性があります。 

## アプローチ

 最も直接的な解決策は、すべてのサフィックスを生成し、それが素数であるかどうかを個別にテストすることです。 

数値が文字列として表現されているとします。 最初の文字を繰り返し削除できます。```
9137
137
37
7
```値ごとに素数性テストを実行します。 接尾辞が複合である場合、または元の数値にゼロが含まれている場合は、すぐに応答します。`"NO"`。 

この強引なアイデアは、入力が小さいため、すでに十分に高速です。 までの数値`10^7`接尾辞は最大 8 個です。 各素数性テストのコストは最大でも`O(sqrt(n))`、それは約です`3162`最悪の場合は繰り返し。 これらを掛け合わせても、実行時間は非常に短くなります。 

ふるい、前処理、確率的素数テストは必要ありません。 制約は、単純な試行分割が快適に通過できるように設計されています。 

重要な観察は、接尾辞の数が非常に少ないということです。 多くの候補番号を検索する代わりに、最大 8 つの値からなる 1 つのチェーンのみを検証します。 これにより、問題は素数チェックの繰り返しに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | n までの単純な除数チェックを使用したブルート フォース | サフィックスあたり O(n) | お(1) | 概念的には遅すぎる |
 | 平方根素数性テストを使用した最適化 | O(d × sqrt(n)) | お(1) | 承認済み |

 ここ、`d`は最大 8 桁の桁数です。 

## アルゴリズムのチュートリアル

 1. 整数を文字列として読み取ります。 

文字列を使用すると、サフィックスの生成が簡単になり、数字抽出ロジックの繰り返しを回避できます。 
2. 文字列に数字が含まれているかどうかを確認します`'0'`。 

そうなった場合はすぐに印刷してください`"NO"`切り捨て可能な素数にはゼロを含めることができないためです。 
3. 数値のすべての接尾辞を生成します。 

インデックス用`i`、接尾辞は`s[i:]`。 
4. 各接尾辞を整数に変換し、それが素数であるかどうかをテストします。 

次の場合、数値は素数になります。 

- 少なくとも 2 です
 - からの整数はありません`2`に`sqrt(x)`それを分割します
 5. サフィックスが素数でない場合は、次のように出力します。`"NO"`そしてやめてください。 
6. すべてのサフィックスが素数の場合、出力します。`"YES"`。 

### なぜ効果があるのか

 このアルゴリズムは、切り捨て可能な素数の定義と直接一致します。 

有効なサフィックスはすべて 1 回だけチェックされます。 ゼロ制限は、素数性テストの前に適用されます。 素数性テストは正しく拒否します`1`そしてすべての合成数。 

答えは`"YES"`すべてのサフィックスが主条件を満たす場合のみ、そして`"NO"`それ以外の場合、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_prime(x):
    if x < 2:
        return False

    d = 2
    while d * d <= x:
        if x % d == 0:
            return False
        d += 1

    return True

def solve():
    s = input().strip()

    if '0' in s:
        print("NO")
        return

    for i in range(len(s)):
        value = int(s[i:])

        if not is_prime(value):
            print("NO")
            return

    print("YES")

solve()
```サフィックスは自然にこの方法で表現されるため、解決策は数​​字を文字列として読み取ることから始まります。 文字列スライスを使用すると、先頭の数字を削除するための手動計算が不要になります。 

ゼロチェックは即時失格となるため、最初に行われます。 数値が既に定義に違反している場合、素数性テストに時間を費やす理由はありません。 

の`is_prime`関数は平方根までの標準的な試算除算を使用します。 合成数が存在する場合、少なくとも 1 つの因数は最大でも`sqrt(x)`なので、それ以降のチェックは不要です。 

条件`x < 2`重要です。 それがなければ、接尾辞`1`誤って素数として扱われてしまいます。 

ループはすべての接尾辞を反復します。`s[i:]`。 1 つのサフィックスが失敗すると、アルゴリズムは早期に終了します。`"NO"`。 これにより、実装がシンプルかつ効率的に保たれます。

import io

def run(inp: str) -> str:

    def is_prime(x):
        if x < 2:
            return False

        d = 2

            if x % d == 0:
                return False
            d += 1

        return True

        if '0' in s:
            return "NO"

        for i in range(len(s)):
            if not is_prime(int(s[i:])):
                return "NO"

        return "YES"

    return solve()
