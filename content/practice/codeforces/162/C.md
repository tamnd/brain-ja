 ## 解決策
 ## 問題の理解

 正の整数を取り、それを素数の積として表現し、各素数が因数分解で出現する回数を示すように求められます。 たとえば、数値 245 は 5 と 7 を 2 回乗算して表現できるため、出力は 5_7_7 になります。 入力は 2 ～ 10000 の範囲に制限された単一の整数 n です。出力は非減少順の素因数であり、多重度は各因数の繰り返し出力によって反映されます。 

n の上限が 10000 であるため、時間制限に達することなく最大約 10^6 の演算を実行するアルゴリズムを検討できるため、単純な試行除算アプローチが実現可能です。 ただし、不用意に実装すると、素数自体、素数の完全二乗である数、または複数の小さな因数が繰り返される数などの小さな特殊なケースで問題が発生する可能性があります。 たとえば、n = 13 は空の因数分解を生成せずに 13 を出力する必要があり、n = 16 は素因数のみが必要であるため、2_8 や 4*4 だけでなく 2_2_2_2 を出力する必要があります。 

## アプローチ

 最も簡単なアプローチは、2 から n までを繰り返し、n を均等に割れる任意の数で繰り返し割ることです。 各分割は、その因子の 1 つの発生に対応します。 この強引な方法が機能するのは、最終的には n までのすべての整数を試し、すべての素因数を捕捉できるからです。 n = 10000 の場合、最悪の場合、10000 回の反復が必要になる可能性があり、各反復で除算が繰り返されるため、複雑さがおよそ O(n) になる可能性があります。 n ≤ 10000 の場合はこれで問題ありませんが、さらに改善できる可能性があります。 

重要な洞察は、n の平方根までの約数をチェックするだけでよいということです。 √n より大きい因数は小さい因数と組み合わせる必要があるため、小さい因数をすべて分割したら、残りの n 自体が素数になる必要があります。 これにより反復回数が大幅に削減され、潜在的な O(n) アプローチが O(√n) に変わります。これははるかに高速であり、n ≤ 10000 の場合でも実装は簡単です。 

最適なアプローチは、√n までの試行除算と、その後の残りの素数の処理を組み合わせたものです。 各因子が見つかったらすぐに出力することで、必要な非減少順序が自然に維持されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | n ≤ 10000 の場合は受け入れられます |
 | 最適 (√n 試行分割) | O(√n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力から整数 n を読み取ります。 これは因数分解する必要がある数値です。 
2. 変数 d を、現在の候補除数を表す 2 に初期化します。 2 が最小の素数であるため、2 から始めます。 
3. d*d ≤ n の場合、n が d で割り切れるかどうかを確認します。 n % d == 0 の場合、d を出力 (または保存) し、n を d で割ります。 n が d で割り切れなくなるまで、この手順を繰り返します。 これにより、因数分解における d のすべてのべき乗が取り込まれます。 
4. d を 1 だけインクリメントし、ステップ 3 を繰り返します。√n より大きい係数には、対応する小さい係数がすでに除算されているため、√n まで上げる必要があるだけです。 
5. ループの後、n > 1 の場合、残りの素因数として n を出力します。 これは、n 自体が素数であるか、大きな素因数が残っている場合を処理します。 

機能する理由: 各ステップで、利用可能な最小の素因数を割り出します。 不変条件は、n が常にまだ因数分解されていない数値の残りの部分であり、d 未満のすべての素数がすでに完全に除算されていることです。 これにより、因子を見逃さず、因子が非降順で出力されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
d = 2
factors = []

while d * d <= n:
    while n % d == 0:
        factors.append(str(d))
        n //= d
    d += 1

if n > 1:
    factors.append(str(n))

print('*'.join(factors))
```コードはアルゴリズムに従って段階的に実行されます。 '*' で結合しやすいように、因子のリストを文字列として保持します。 内側の while ループにより、各素数のすべての累乗が確実に捕捉されます。 d をインクリメントすると、√n までのすべての可能な約数が確実にテストされます。 最後に、1 より大きい場合に n を追加すると、√n より大きい残りの素数がカバーされます。 よくある間違いは、この最終チェックを忘れることです。素数や大きな素因数を持つ数値に対して誤った結果が得られてしまいます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(√n) | 外側のループは最大 √n まで繰り返し、内側のループは各素数のべき乗を分割します。 n ≤ 10000 の場合、これは数百回の反復になります。 |
 | スペース | O(log n) | 因子のリストを保存します。 最小の素因数は 2 であるため、因数の最大数は O(log n) であり、2 で n を除算できる回数は log2(n) です。 |

 この複雑さは、3 秒の制限と 256 MB のメモリ制限の範囲内に十分収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    d = 2
    factors = []

    while d * d <= n:
        while n % d == 0:
            factors.append(str(d))
            n //= d
        d += 1

    if n > 1:
        factors.append(str(n))

    return '*'.join(factors)

# Provided sample
assert run("245\n") == "5*7*7", "sample 1"

# Custom cases
assert run("16\n") == "2*2*2*2", "all 2s"
assert run("13\n") == "13", "prime number"
assert run("10000\n") == "2*2*2*2*5*5*5*5", "mixed small primes"
assert run("9973\n") == "9973", "large prime"
assert run("72\n") == "2*2*2*3*3", "small composite with multiple primes"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 16 | 2_2_2*2 | 小さな素因数を繰り返した |
 | 13 | 13 | 素数の処理 |
 | 10000 | 2_2_2_2_5_5_5*5 | 繰り返される素数の組み合わせ |
 | 9973 | 9973 | 大きな素数 |
 | 72 | 2_2_2_3_3 | 複数の異なる小さな素数 |

 ## 特殊なケース

 13 のような素数の場合、√13 までの約数をループ チェックしても何も除算されません。 ループの後、n はまだ 13 であるため、これを追加することで素数が正しくキャプチャされることが保証されます。 16 のような単一の素数の累乗の場合、内側のループは 2 を 4 回除算し、繰り返される因数が正しくカウントされていることを示します。 10000 のように、小さい素数と大きい素数の両方を含む数値の場合、アルゴリズムは、要素を見逃すことなく、2 と 5 の複数の出現を正確に捕捉します。 この方法は、最初の因数の後で停止したり、√n を超える残りの素数の処理を忘れたりするなどのよくある間違いを回避します。
