 ## 解決策
 ## 問題の理解

 単一の正の整数が与えられ、その表現を基数 2 で出力する必要があります。つまり、数値を 10 の累乗として表現する代わりに、数字のみを使用して 2 の累乗として表現します。`0`そして`1`。 

たとえば、10 進数`5`になる`101`なぜなら：$$5 = 1 \cdot 2^2 + 0 \cdot 2^1 + 1 \cdot 2^0$$制約は非常に小さいです。 の値`n`せいぜい`10^6`これは、次の理由により、バイナリ表現に含まれるビット数が 20 ビット未満であることを意味します。$$2^{20} = 1,\!048,\!576$$非効率なソリューションであっても、制限内であれば快適に実行できます。 ここでは、すべての可能なビット位置にわたる線形スキャンはすでに簡単です。 

間違いの主な原因は、出力を正しくフォーマットすることです。 2 進数表記には先頭にゼロを含めることはできません。 

次の入力を考えてみましょう。```
1
```正しい出力は次のとおりです。```
1
```常に固定数のビット (32 ビットなど) を出力する不注意な実装では、次のような結果が生成されます。```
00000000000000000000000000000001
```それは間違っています。 

2 で割ることを繰り返すと、別の微妙なケースが現れます。 剰余は最下位ビットから最上位ビットの順に生成されるため、印刷する前に反転する必要があります。 

例えば：```
6
```分割シーケンス:

 | 現在の番号 | 残り |
 | --- | --- |
 | 6 | 0 |
 | 3 | 1 |
 | 1 | 1 |

 集められたビットは、`011`ですが、正解は次のとおりです。```
110
```コレクション順にビットを出力すると、反転した 2 進数が自動的に生成されます。 

## アプローチ

 最も直接的な総当り攻撃のアイデアは、すべての 2 の累乗をテストし、そのビットが数値に存在するかどうかを判断することです。 最大値以下なので`2^20`、最上位ビットからゼロまで反復して出力できます。`1`または`0`対応する累乗が数値に寄与するかどうかに応じて。 

これが機能するのは、すべての整数が独自のバイナリ分解を行うためです。 各位置について、残りの値に 2 の累乗が含まれるかどうかを尋ねます。 

32 ビット位置または 64 ビット位置をすべてチェックしたとしても、実行時間は事実上一定のままです。 問題はパフォーマンスではなく、実装の明確さです。 先頭のゼロも慎重にスキップする必要があります。 

もう 1 つの古典的なアプローチでは、数値を 2 で割って余りを記録します。 各余りは 1 つの 2 進数になります。 最初の剰余は最下位ビットに対応し、次の剰余は次のビットに対応します。 

これが機能する理由は位置表記法に直接関係しています。 2で割る場合:$$n = 2q + r$$どこ`r`どちらかです`0`または`1`。 その余りは正確に現在の 2 進数です。 

除算のアプローチは、2 の累乗について手動で推論することなく、自然に 1 桁ずつバイナリ表現を抽出するため、より簡単です。 

除算ごとに数値がおよそ半分になるため、反復回数は答えのビット数と等しくなります。

 | ブルートフォース | O(log n) | お(1) | 承認済み |
 | 最適 | O(log n) | O(log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`。 
2. 空のリストを作成する`bits`2進数を保存します。 
3. その間`n`ゼロより大きい場合、計算します`n % 2`そして結果を追加します`bits`。 

残りは、現在の最下位ビットが`0`または`1`。 
4. 交換する`n`と`n // 2`。 

整数の除算では、既に処理した 2 進数の最下位桁が削除されます。 
5. ループが終了したら、収集した数字を反転します。 

最初に抽出された剰余は最下位ビットに対応しますが、2 進表記は最上位ビットから最下位ビットに書かれます。 
6. 数字を文字列に結合し、結果を出力します。 

### なぜ効果があるのか

 各反復では、現在の数値が次のように分解されます。$$n = 2q + r$$どこ`r`どちらかです`0`または`1`。 その余りは正確に次の 2 進数の最下位桁です。`n`。 

整数除算でその桁を削除した後、同じロジックが商に適用されます。 このプロセスを繰り返すと、すべての 2 進数が 1 回だけ抽出されます。 

商がゼロになるとアルゴリズムは停止します。これは、すべての 2 進位置が処理されたことを意味します。 収集した数字を逆にすると、正しい左から右の順序が復元されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

bits = []

while n > 0:
    bits.append(str(n % 2))
    n //= 2

bits.reverse()

print("".join(bits))
```プログラムは、標準入力から整数を読み取ることから始まります。 

の`while`ループは次を使用して最下位ビットを繰り返し抽出します。`n % 2`。 以来`% 2`生産することしかできない`0`または`1`、各剰余は有効な 2 進数です。 

数字を記録した後、コードは整数を 2 で除算します。 これにより、処理されたビットが破棄され、数値が 2 進数で 1 桁右にシフトされます。 

除算を繰り返すと最下位ビットが最初に現れるため、数字は逆の順序で収集されます。 印刷する前にリストを反転すると、正しい表現が復元されます。 

リスト内で文字列を使用すると、結合中に整数から文字列への変換が繰り返されることがなくなります。 

ループ条件`while n > 0`問題が保証されているため機能します`n`はポジティブです。 ゼロが許可される場合、出力するには特別なケースが必要になります。`"0"`。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    n = int(input())

    bits = []

    while n > 0:
        bits.append(str(n % 2))
        n //= 2

    bits.reverse()

    print("".join(bits))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run("5\n") == "101", "sample 1"

# minimum input
assert run("1\n") == "1", "minimum value"

# power of two
assert run("8\n") == "1000", "single set bit"

# mixed bits
assert run("13\n") == "1101", "general binary conversion"

# maximum constraint region
assert run("1000000\n") == "11110100001001000000", "large value"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`8`|`1000`| 2 の累乗の正しい処理 |
