 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、`n`ノード。それぞれに整数のラベルが付けられます。 重要な重要なプロパティは、任意の単純なパス (ノードを再訪問しないパス) に沿った数値の XOR です。 すべての単純なパスにゼロ以外の XOR がある場合、ツリーは「良好」です。 頂点の数値を任意の正の整数に何度でも置き換えることができます。 目標は、ツリーを良好なものにするために必要な交換の回数を最小限に抑えることです。 

ツリーはエッジによって定義され、接続された非循環グラフを形成します。 入力数値の範囲は次のとおりです。`2^30`これにより、整数のオーバーフローを心配することなく、それらを 30 ビット整数として安全に扱うことができます。 

この制約は、すべてのパスのブルートフォース探索が不可能であることを意味します。 と`n`まで`2*10^5`、潜在的にあります`O(n^2)`ツリー内の単純なパスは、`10^10`XOR を単純に計算しようとした場合の操作。 したがって、線形または線形に近いアプローチが必要です。`n`。 

エッジケースは微妙です。 たとえば、すべてのノードが 1 に等しいツリーには、パスの長さが偶数であれば、XOR 0 を持つパスが多数あります。 すぐ隣をチェックするだけの単純なアプローチでは、これらの長いパスを見逃してしまう可能性があります。 もう 1 つのエッジ ケースは単一ノード ツリーです。この場合、数値がゼロ以外の場合、ツリーは自明ながら良好です。 

## アプローチ

 ブルート フォース アプローチでは、すべての単純なパスを列挙し、それらの XOR を計算します。 DFS を使用すると、各ノードから始まるすべてのパスを生成し、XOR を計算し、XOR 0 でパスをカウントできます。これは論理的には正しいですが、次のことが必要です。`O(n^2)`パスチェックが失敗する`n = 2*10^5`。 

重要な観察は、XOR が結合的であり、次のプロパティがあることです。`x ^ x = 0`。 プレフィックスとサフィックスの XOR が等しい場合、パスの XOR は 0 になります。 これは、XOR 0 を持つパスがないことを保証するには、サブツリー内で累積 XOR が繰り返されることを避ける必要があることを意味します。 言い換えると、ルートからノードへの XOR が`u`ルートからノードまでの XOR に等しい`v`、次にからのパス`u`に`v`XOR 0 があります。 

この洞察により、**サブツリー XOR セット** の観点から問題を組み立てることができます。 DFS 順にツリーを走査します。 各ノードでは、そのサブツリーに含まれるすべての XOR のセットを維持します。 2 つのサブツリーをマージすると重複した XOR が発生する場合、XOR 0 のパスが存在することがわかり、ノードを変更してそれを「切断」する必要があります。 ノードを変更すると XOR がリセットされるため、変更の最小数はそのような競合の最小数と同じになります。 

したがって、このアルゴリズムは、セット マージ ヒューリスティックを備えた DFS であり、「ツリー上の DSU」と呼ばれることもあります。 子サブツリーをマージするときは、複雑さをほぼ線形に保つために、常に小さいセットを大きいセットにマージしてください。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n^2) | 遅すぎる |
 | ツリー上の DSU / XOR セット | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーの任意のルートを選択します。 便宜上、ノード 1 を選択します。ルートから DFS を初期化します。 
2. 各ノードで、独自の値を含むセットを作成します。 このセットは、このノードから始まるパスのすべての XOR を蓄積します。 
3. 各子を再帰的に調べます。 子を処理した後、その XOR セットを現在のノードのセットにマージしようとします。 子セット内のいずれかの値が現在のノードのセットに既に存在する場合、ゼロ XOR パスが存在し、操作カウンターを 1 つインクリメントします。この場合、現在のノードのセットをリセットして、ノード自身の値のみを含め、ノードを事実上「変更」して競合を解消します。 
4. マージの効率を維持するには、常に小さいセットを大きいセットにマージします。 これにより、ツリー全体での挿入の合計数が確実に増加します。`O(n log n)`。 
5. すべてのノードが処理されるまで DFS を続行します。 蓄積されたカウンターは、必要な最小限の変更数です。 

機能する理由: XOR パスは、ルートからの累積 XOR によって完全に決定されます。 重複した累積 XOR は、対応するノード間にゼロ XOR パスが存在することを示します。 DFS 中にこれらの重複を貪欲に「解除」することで、最小限の変更を使用してすべてのゼロ XOR パスを防止します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**6)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    tree = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        tree[u-1].append(v-1)
        tree[v-1].append(u-1)

    ans = 0

    def dfs(u, parent):
        nonlocal ans
        xor_set = {a[u]}
        for v in tree[u]:
            if v == parent:
                continue
            child_set = dfs(v, u)
            if len(child_set) > len(xor_set):
                xor_set, child_set = child_set, xor_set
            conflict = xor_set & child_set
            if conflict:
                ans += 1
                xor_set = {a[u]}
            else:
                xor_set |= {x ^ a[u] for x in child_set}
        return xor_set

    dfs(0, -1)
    print(ans)

if __name__ == "__main__":
    solve()
```DFS 関数は、各ノードから到達可能な XOR のセットを返します。 マージでは、設定された交差を使用して競合を検出します。 再帰では、ゼロ XOR パスが検出されたときにセットがリセットされ、ノード値の置換がモデル化されます。 パフォーマンスを維持するには、小さいセットを大きいセットにマージする際には細心の注意が必要です。 また、子値を追加する前に現在のノードと XOR を実行し、各セットにサブツリーのルートからの累積 XOR が含まれるという特性を保持します。
