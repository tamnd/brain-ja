 ## 解決策
 ## 問題の理解

 私たちには 3 つのドアが与えられ、それぞれに 1 から 3 までの固有の錠番号が付いています。また、私たちは手に鍵を持っていますが、各ドアの後ろには別の鍵があるか、何もない場合があります。 2 つの鍵がドアの後ろに隠されており、1 つの鍵は私たちの手にあります。 各キーは、一致する番号のドアを正確に開くことができます。 課題は、手に持った鍵から始めて、3 つのドアすべてを順番に開け、途中で残りの鍵を取得できるかどうかを判断することです。 

入力は多数のテスト ケースで構成されます。 各テスト ケースでは、手元の鍵の番号と、それぞれドア 1、2、3 の後ろにある鍵を表す 3 つの整数のリストを受け取ります。 ゼロは、そのドアの後ろに鍵がないことを示します。 ちょうど 1 つのキー番号が手の中に表示され、残りの 2 つのキー番号はドアの後ろにありますが、3 番目のドアにはキーが含まれていません。 

制約は非常に小さく、テスト ケースは最大 18 個で、キーは 1 ～ 3 に制限されています。これにより、パフォーマンスに関する懸念はすぐに排除されます。 この問題は純粋に論理的なものです。解決策に必要なのは、ドアのロックを解除して鍵を取得するプロセスを正しくモデル化することだけです。 

エッジケースは、手元のキーが、必要な 2 番目のキーを含むドアのロックを直接解除できない場合に発生します。 たとえば、キー 2 から開始し、ドアの後ろのキーが`[1, 3, 0]`の場合、ドア 1 を開くにはキー 1 が必要なため、キー 1 に到達できず、デッドロックが発生します。 この場合の正しい出力は「NO」です。 単純なアプローチでは、この依存関係が無視され、すべてのドアが開くことができると誤って想定される可能性があります。 

## アプローチ

 最も単純なアプローチはブルートフォースです。手持ちのキーと取得したキーを使用して、ドアのロックを解除するすべてのシーケンスを試します。 ドアが 3 つしかなく、シーケンスの数が少ない (3! = 6) ため、総当たりのシミュレーションは機能しますが、やりすぎでロジックがわかりにくくなります。 

重要な洞察は、問題を 2 段階のチェックに減らすことができるということです。まず、手元の鍵を使用して対応するドアを開けます。 次に、そのドアの後ろに鍵がある場合はそれを取り出し、残りのドアのいずれかのロックが解除できるかどうかを確認します。 最初の鍵で 2 番目の鍵が含まれるドアを開けた場合、残りのドアはいつでも 2 番目の鍵で開けることができます。 そうしないと、残りの鍵が私たちが持っている鍵では開けられないドアの後ろにある場合に行き詰まってしまう可能性があります。 

これを単純なシーケンスとして形式化できます。`current_key`鍵を手に持ってください。 番号のドアを開けてください`current_key`。 そのドアの後ろに鍵がある場合 (0 以外)、次のように設定します。`current_key`その鍵にアクセスし、その番号のドアを開けます。 私たちが所有していない鍵を必要とするドアを開けようとした場合、答えは「NO」です。 2 つのドアを開けて最後の鍵を取得できた場合、残りのドアはいつでも最後の鍵で開けることができます。

 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. テストケースごとに、手元にあるキーを読み取ります`x`そしてリスト`[a, b, c]`ドア 1、2、3 の後ろの鍵を表します。 
3. ドアと鍵を、ドア番号からその背後にある鍵へのマッピングとして扱います。 つまり、ドア 1 には鍵があります`a`、ドア2には鍵があります`b`、ドア3には鍵があります`c`。 
4. キーを手に持って開始します。`current_key`。 その番号のドアを確認してください。 その背後にあるキーが 0 の場合、開いていない残りのドアには最後のキーがなければならず、それはすでに持っています。 「はい」と印刷します。 
5. ドアの後ろにキーがある (0 以外) 場合は、そのキーを取り出し、そのキーに対応するドアを確認します。 そのドアに 0 (鍵なし) が含まれている場合でも、開くことができます。 鍵が入っている場合は、それが最後のドアである必要があります。 これが最後に残っているキーと一致することを確認します。 
6. 必要な鍵が、鍵を持っていて開けられないドアの後ろにある場合は、「NO」と印刷してください。 それ以外の場合は、「YES」を出力します。 

機能する理由: 不変条件は、各ステップで、手元の鍵が次の鍵を提供するドアのロックを解除できるか、またはキーのないドアのロックを解除できるかということです。 ドアが 3 つしかなく、ドアの後ろでちょうど 1 つの鍵が欠けているように鍵が分散されているため、すべてのドアにアクセスできるかどうかを判断するには、この 2 段階のシミュレーションで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    x = int(input())
    a, b, c = map(int, input().split())
    doors = {1: a, 2: b, 3: c}

    current_key = x
    first_door_key = doors[current_key]

    if first_door_key == 0:
        print("NO")
    else:
        second_door_key = doors[first_door_key]
        if second_door_key == 0:
            print("YES")
        else:
            print("NO")
```このソリューションはテスト ケースを読み取り、ドア番号からその背後にある鍵までの辞書マッピングとしてドアを表します。 鍵を手に持った状態から始めて、対応するドアを開けるシミュレーションを行います。 ドアに鍵がある場合は、その鍵を使って次のドアを開けようとします。 2 番目のドアの後ろに鍵がない場合は、すべてのドアが開くことができるため、「YES」と出力します。 そうでなければ行き詰まってしまい、答えは「NO」です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t) | 各テスト ケースには、最大 2 つの辞書検索が含まれます。 
| スペース | お(1) | テスト ケースごとに 3 つのドアのみを保存します。 

与えられた`t <= 18`、これは自明に速く、2 秒の制限内に収まります。 メモリ使用量は最小限です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        x = int(input())
        a, b, c = map(int, input().split())
        doors = {1: a, 2: b, 3: c}
        current_key = x
        first_door_key = doors[current_key]
        if first_door_key == 0:
            print("NO")
        else:
            second_door_key = doors[first_door_key]
            if second_door_key == 0:
                print("YES")
            else:
                print("NO")
    return output.getvalue().strip()

# Provided samples
assert run("4\n3\n0 1 2\n1\n0 3 2\n2\n3 1 0\n2\n1 3 0\n") == "YES\nNO\nYES\nNO"

# Custom cases
assert run("1\n1\n0 2 3\n") == "NO", "cannot open first door to get next key"
assert run("1\n2\n1 0 3\n") == "YES", "first door has next key"
assert run("1\n3\n1 2 0\n") == "YES", "first door has next key"
assert run("1\n1\n2 0 3\n") == "NO", "first door leads to door with no key"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1\n1\n0 2 3 | いいえ | 最初のキーで空のドアが開くと先に進めません |
 | 1\n2\n1 0 3 | はい | 通常の場合、2 番目のドアには次のキーが入っています。 
| 1\n3\n1 2 0 | はい | 最後のドアには鍵がありませんが、まだ成功しています |
 | 1\n1\n2 0 3 | いいえ | 最初の鍵は後ろに鍵のないドアにつながります |

 ## 特殊なケース

 微妙なエッジケースは、手の中にある鍵が後ろに鍵のないドアに対応する場合に発生します。 たとえば、次の場合`x = 1`そしてドア =`[0, 2, 3]`、鍵1から始めてドア1を開けますが、何も見つかりません。 鍵 2 と 3 はドア 2 と 3 の後ろにあります。
