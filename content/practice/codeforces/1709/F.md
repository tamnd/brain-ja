 ## 解決策
 ## 問題の理解

 最大の長さのすべてのバイナリ文字列を考える`n`深さの完全なバイナリ トライのノードとして`n`。 

ルートを除くすべてのノードが容量を受け取ります`c_s`間`0`そして`k`。 正確な長さのバイナリ文字列のマルチセット`n`すべてのリーフに何らかの多重度を割り当てます。 任意のトライノードに対して`s`、そのサブツリー内の多重度の合計は次を超えることはできません。`c_s`。 

容量の固定割り当ての場合は、美しいマルチセットの最大サイズを定義します。 課題は、その最大値を見つけることではありません。 代わりに、最大値を生み出す容量割り当ての数を正確にカウントする必要があります。`f`。 

トライには以下が含まれます$$2^1+2^2+\cdots+2^n=2^{n+1}-2$$容量のあるノード。 たとえ`n = 15`、これは 65534 個の変数なので、直接列挙することは絶望的です。 

バウンド`n ≤ 15`小さいですが、`k`そして`f`と同じくらい大きい`2·10^5`。 これは、興味深い状態はトライ構造そのものではなく、各サブツリーが寄与できる値であることを強く示唆しています。 すべての容量割り当ての状態を維持するソリューションは不可能ですが、複雑さがほぼ多項式になるソリューションは不可能です。`k`そして直線的に`n`実現可能です。 

微妙なエッジケースが現れるのは、`f`達成可能なあらゆる答えを超えています。 

例えば：```
n = 1
k = 1
f = 3
```各リーフの容量は最大で`1`したがって、美しいマルチセットの最大サイズは最大でも`2`。 正しい答えは、`0`。 までの分布のみを計算するソリューション`k`ルートが次の値に到達できるという事実を誤って見逃してしまいます。`2k`。 

もう 1 つの簡単な間違いは、遷移時に等価の場合を誤って処理することです。 

サブツリーの子が正確に貢献できると仮定します。`j`。 次に、あらゆる容量の選択`c ≥ j`サブツリー値を生成します`j`。 がある`k-j+1`そのような能力ではなく、`k-j`。 この追加の可能性を逃すと、分布全体が変化します。 

## アプローチ

 ブルートフォース解釈は簡単です。 

間の値を割り当てます。`0`そして`k`すべてのトライノードに。 割り当てごとに、美しいマルチセットの最大サイズを計算し、それが等しいかどうかを確認します。`f`。 

トライには以下が含まれます`2^{n+1}-2`ノードがあるため、割り当ての数は次のようになります。$$(k+1)^{2^{n+1}-2}.$$たとえ`n=15`そして`k=1`、これは天文学的な大きさです。 

重要な観察は、サブツリーが 1 つの数値で要約できることです。 

させて`val(v)`ノードをルートとするサブツリー内に配置できる文字列の最大数になります。`v`。 

葉っぱに関しては、$$val(v)=c_v.$$内部の非ルート ノードの場合、$$val(v)=\min(c_v,\; val(l)+val(r)).$$子どもたちが一緒に供給できるのはせいぜい`val(l)+val(r)`ただし、ノードの容量によってはより厳しい制限が課される場合があります。 

これは、サブツリーの結果の値がわかってしまえば、ノード以下の容量の正確な配置は無関係であることを意味します。 考えられる各値を生成する代入の数を数えるだけで済みます。 

高さの部分木の分布がわかっている場合`h-1`の場合、2 つの子を結合するには、値の合計が次になるすべてのペアをカウントする必要があります。`t`。 まさに畳み込みですね。 

以来`k`到達する`2·10^5`、単純な二次畳み込みはコストが高すぎます。 問題は一連の多項式畳み込みになりますが、NTT を使用して高速化できます。 

結果として得られる動的プログラミングは、大まかに実行されます。`O(n k log k)`。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | DP+NTT | O(nk log k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 しましょう`dp[h][x]`高さの非ルート完全バイナリ サブツリーの容量割り当ての数を示します。`h`最大貢献度が正確に等しい`x`。 

身長`0`葉という意味です。 

### 1. リーフ分布を初期化する

 リーフの値はその容量と同じです。 

あらゆる人にとって`0 ≤ x ≤ k`:$$dp[0][x]=1.$$### 2. 2 つの子サブツリーを結合します。 

身長の分布はすでにわかっていると仮定します`h-1`。 

させて$$H[t] = \sum_{a+b=t} dp[h-1][a]\cdot dp[h-1][b].$$

`H[t]`2 つの子が合計値に寄与する割り当てをカウントします。`t`。 

これは、NTT を使用して計算された多項式の畳み込みです。 

### 3. ノード容量を適用する

 固定子金額の場合`t`、親の値は$$\min(c,t).$$それぞれの結果の値を取得する方法の数が必要です`j`。 

もし`t=j`、その後任意の容量`c≥j`動作します。 がある`k-j+1`選択肢。 

もし`t>j`、その後、値を取得する唯一の方法`j`選択しています`c=j`。 

したがって、$$dp[h][j] = (k-j+1)H[j] + \sum_{t>j} H[t].$$書き換え:$$dp[h][j] = (k-j)H[j] + \sum_{t\ge j} H[t].$$接尾辞の合計は、`H`この遷移を線形時間で許可します。 

### 4. 深さに到達するまで繰り返します`n-1`すべての非ルート レベルは、前の遷移を使用して処理されます。 

### 5. ルートを処理する

 根には容量がありません。 

その価値は単純に、$$val(root)=val(left)+val(right).$$したがって、最終的な答えの分布は、高さのもう 1 つの畳み込みです。`n-1`それ自体での配布。 

の係数`f`が答えです。 

### なぜ効果があるのか

 すべてのサブツリーについて、先祖が必要とする唯一の情報は、そのサブツリー内に配置できる文字列の最大数です。 再帰式$$val(v)=\min(c_v,\; val(l)+val(r))$$は、ノードの下の内部構造が、この単一の値を通じてのみ上位レベルに影響を与えることを示しています。 

DP は、考えられる各サブツリー値を生成する容量割り当ての数を正確にカウントします。 畳み込みでは、子の値のすべてのペアが列挙されます。 容量遷移は、子の合計を特定の親の値に変換するすべての容量を列挙します。 すべての割り当ては各レベルで 1 回だけカウントされるため、ルートでの最終的な分布は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
G = 3

def mod_pow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def ntt(a, invert):
    n = len(a)

    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            a[i], a[j] = a[j], a[i]

    length = 2
    while length <= n:
        wlen = mod_pow(G, (MOD - 1) // length)
        if invert:
            wlen = mod_pow(wlen, MOD - 2)

        for i in range(0, n, length):
            w = 1
            half = length >> 1
            for j in range(i, i + half):
                u = a[j]
                v = a[j + half] * w % MOD

                a[j] = (u + v) % MOD
                a[j + half] = (u - v) % MOD

                w = w * wlen % MOD

        length <<= 1

    if invert:
        inv_n = mod_pow(n, MOD - 2)
        for i in range(n):
            a[i] = a[i] * inv_n % MOD

def convolution(a, b):
    need = len(a) + len(b) - 1
    n = 1
    while n < need:
        n <<= 1

    fa = a[:] + [0] * (n - len(a))
    fb = b[:] + [0] * (n - len(b))

    ntt(fa, False)
    ntt(fb, False)

    for i in range(n):
        fa[i] = fa[i] * fb[i] % MOD

    ntt(fa, True)

    return fa[:need]

def solve():
    n, k, f = map(int, input().split())

    dp = [1] * (k + 1)

    for level in range(1, n):
        h = convolution(dp, dp)

        m = len(h)
        suf = [0] * (m + 1)
        for i in range(m - 1, -1, -1):
            suf[i] = (suf[i + 1] + h[i]) % MOD

        ndp = [0] * (k + 1)
        for j in range(k + 1):
            ndp[j] = ((k - j) * h[j] + suf[j]) % MOD

        dp = ndp

    root = convolution(dp, dp)

    if f >= len(root):
        print(0)
    else:
        print(root[f] % MOD)

solve()
```基本分布は葉に対応します。 各内部レベルは最初に畳み込みを実行し、子の合計の分布を生成します。 その後、suffix-sum 遷移により親容量が適用されます。 

表現```
(k - j) * h[j] + suf[j]
```実装する$$(k-j)H[j]+\sum_{t\ge j}H[t].$$ルートには容量制限がないため、別個に扱われます。 

見落としがちな実装の詳細の 1 つは、最大値の範囲です。 内部サブツリー値が超えることはありません`k`ですが、ルートはそのような 2 つの値の合計であるため、最終的な分布は次のようになります。`2k`。 だからこそチェックしなければならないのです`f >= len(root)`インデックス作成前。

 ## 特殊なケース

 次のことを考慮してください。```
1 1 3
```各リーフの容量は最大で`1`したがって、ルート値は最大でも`2`。 最後の畳み込みには合計の係数のみが含まれます`0,1,2`。 インデックス以来`3`存在しない場合、アルゴリズムは戻ります`0`。 

次に、次のことを考えてみましょう。```
2 2 1
```子の合計が正確に等しいと仮定します`1`。 あらゆる容量の選択`c=1`または`c=2`親の値を生成します`1`。 移行は貢献します`k-j+1 = 2`可能性。 使用する`k-j`代わりに、そのうちの 1 つだけがカウントされ、不正確な分布が生成されます。 suffix-sum 式には、等価の場合が正しく含まれています。 

最後に、次のことを考慮してください。```
1 3 6
```唯一の順序付きペアの合計は`6`は`(3,3)`。 インデックスのルート畳み込み係数`6`まさに`1`、アルゴリズムが上限を正しく処理していることを確認します。`2k`。
