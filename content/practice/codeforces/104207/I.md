 ## 解決策
 ## 問題の理解

 ちょうど 1 サイクルの接続された無向グラフが与えられます。これは、エッジの数が頂点の数と等しいことを意味します。 各エッジには色があります。 時間の経過とともに、個々のエッジの色が変化するため、変化するたびに、各色がどの程度「断片化」されるかについての全体的な尺度を計算する必要があります。 

重要なオブジェクトは頂点ではなく、色ごとにグループ化されたエッジです。 固定色の場合は、現在その色でペイントされているエッジのみを考慮します。 このような 2 つのエッジは、少なくとも 1 つの端点頂点を共有する場合、接続されているとみなされます。 これにより、エッジを越えて接続されたコンポーネントが生成され、そのような各コンポーネントは色付き領域と呼ばれます。 各更新後の最終的な答えは、すべての色を合計したこれらのコンポーネントの合計数です。 

したがって、タスクは、エッジの再色操作の下で、共有エンドポイントを通じて隣接関係が定義されるエッジ誘発グラフの動的コレクション内の接続コンポーネントの数を維持することです。 

制約は大きく、テスト ケースあたりの頂点とエッジの数は最大 20 万、更新数は最大 20 万です。 すべてのテスト ケースの合計も大きいため、更新ごとに二次関数を実行することは直ちに不可能になります。 更新ごとの対数であっても慎重に管理する必要があり、各操作後に接続を最初から再計算するアプローチでは、すべてのエッジを繰り返し走査する必要があり、$O(NM)$、これは実現可能な限界をはるかに超えています。 

微妙な点は、接続が頂点ではなく、色ごとにグループ化されたエッジ上で行われ、隣接関係が頂点を介して間接的に行われることです。 頂点上の標準的な動的グラフ接続の単純なメンタル モデルは、直接適用されません。 

単純なアプローチを破るエッジケースは、通常、エッジの色を頻繁に変更することで発生します。 たとえば、更新ごとに同じエッジの色を前後に変更する場合、更新ごとに構造を再構築するソリューションでは、たとえ 1 つのエッジのみが変更されたとしても、グラフ全体が繰り返し再処理されることになります。 

もう 1 つの注意が必要なケースは、多くのエッジが頂点を共有する場合です。 同じ頂点と同じ色に属するすべてのエッジが 1 つのステップで相互に接続されるため、すべての入射エッジを適切に結合できない不適切な実装では、コンポーネントが過小評価される可能性があります。 

## アプローチ

 直接的なブルート フォース ソリューションでは、更新のたびに答えが再計算されます。 色ごとに、その色でエッジのサブグラフを構築し、エッジ上でグラフの走査を実行し、エッジをノードとして扱い、頂点を共有する場合はエッジを接続します。 これは領域の定義と正確に一致するため、これは正しいです。 

ただし、更新のたびにこれらの構造を再構築するとコストがかかります。 各再計算ではすべてのエッジがスキャンされ、隣接関係が再構築されるため、コストがかかります$O(N)$最悪の場合、クエリごとに色ごとに。 まで$M$アップデートすると、こうなります$O(NM)$のオーダーです。$10^{10}$、遅すぎます。 

重要な観察は、接続性はローカル頂点の発生によってのみ駆動されるということです。 特定の色の新しいエッジが表示されると、その端点に接する同じ色のエッジとのみ相互作用します。 これは、色のすべてのエッジをスキャンする必要はなく、2 つの端点に関連するエッジのみをスキャンする必要があることを意味します。 

このローカル相互作用構造は、エッジ上の結合検索スタイルの表現を示唆しています。エッジは、素のセット構造内のノードであり、2 つのエッジが頂点を共有する場合に結合が発生します。 問題は、エッジの色も変化し、削除が発生することです。 標準の Union-Find ではマージを元に戻すことができないため、時間認識バージョンが必要です。 

これは、古典的なオフライン手法につながります。つまり、各エッジ カラーの割り当てを時間間隔として扱い、ロールバック可能な DSU を使用して、時間のセグメント ツリーにわたってすべての結合を処理します。 各時間間隔は、アクティブな存続期間中のみユニオン操作に影響します。 DSU には、再帰ツリーを上に移動するときに変更を元に戻す機能が強化されています。 

これにより、動的問題が時間の経過とともに結合演算の静的コレクションに変換され、それぞれが関連する場合にのみ適用されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに再計算 |$O(NM)$|$O(N)$| 遅すぎる |
 | 一定の時間間隔でロールバックを行う DSU |$O((N+M)\log M)$|$O(N+M)$| 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を時間間隔活性化問題に変換します。 各エッジには時間の経過に伴う一連の色の割り当てがあり、各割り当ては、そのエッジが特定の色に属する連続的な間隔を形成します。 

次に、操作のタイムライン上でセグメント ツリーを使用して、そのようなすべての間隔を処理します。 

1. 各エッジに識別子を割り当て、初期グラフ記述を使用して時間ゼロでの現在の色を追跡します。 これにより、時間 0 から始まる各エッジ色のペアの最初のアクティブな間隔が作成されます。 
2. 更新を処理する際、各操作により 1 つのエッジの色が変更されます。 そのエッジについては、現在の時刻で前の色の間隔を閉じ、その時刻から始まる新しい色の新しい間隔を開きます。 
3. すべての操作を処理した後、開いている間隔は、最終時刻に 1 を加えた時点で閉じられます。 これにより、すべてのエッジ カラーの割り当てが、互いに素な時間セグメントのセットとして表現されるようになります。 
4. 時間軸に沿ってセグメント ツリーを構築します。 各間隔は、その存続期間を完全にカバーするすべてのセグメント ツリー ノードに挿入されます。 各ノードは、その時間範囲に関連するエッジ アクティベーションのリストを保存します。 
5. セグメントツリーの深さ優先の走査を実行します。 各ノードで、そのノード内のすべてのエッジ アクティベーションをロールバック可能な素セット構造に適用します。 
6. 各エッジのアクティベーションは、色を認識した方法でエンドポイントを接続します。 特定の色について、接続されたコンポーネントのカウンターを維持します。 エッジが追加されると、その色の新しいコンポーネントとして開始され、どちらかのエンドポイントを共有する同じ色の既存のエッジとマージされます。 結合が成功するたびに、その色のコンポーネント数が減ります。 
7. 現在のセグメント ツリー ノードを処理して子に伝播した後、兄弟ブランチがクリーンな状態から開始できるように、このノードで行われたすべての DSU 変更をロールバックします。 
8. セグメント ツリーのリーフ ノードに到達すると、その時点の答えとしてすべての色の成分数の合計を記録します。 

重要な考え方は、DSU が削除を永続的にサポートする必要がないということです。 代わりに、すべての結合は時間間隔に対してローカルであり、その間隔を離れると元に戻されます。 

正確性は、どのセグメント ツリー ノードにおいても、DSU がその時間範囲でアクティブなエッジのセットを正確に反映し、すべての接続性の決定が、そのタイム スライスを個別に処理した場合に発生する結合操作と一致するという不変条件に依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSURollback:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.changes = []

    def find(self, x):
        while self.parent[x] != x:
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            self.changes.append((-1, -1, -1))
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.changes.append((b, self.parent[b], self.size[a]))
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

    def snapshot(self):
        return len(self.changes)

    def rollback(self, snap):
        while len(self.changes) > snap:
            b, pb, sa = self.changes.pop()
            if b == -1:
                continue
            pa = self.parent[b]
            self.size[pa] = sa
            self.parent[b] = pb

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        n, m = map(int, input().split())

        edges = []
        edge_id = {}
        for i in range(n):
            x, y, c = map(int, input().split())
            x -= 1
            y -= 1
            edges.append([x, y])
            edge_id[(x, y)] = i
            edge_id[(y, x)] = i

        ops = []
        for _ in range(m):
            x, y, c = map(int, input().split())
            x -= 1
            y -= 1
            ops.append((x, y, c))

        # compress edge index
        def get_e(x, y):
            return edge_id[(x, y)]

        # time intervals per (edge, color)
        intervals = []

        cur_color = [0] * n
        last_time = [0] * n
        for i in range(n):
            cur_color[i] = edges[i][2] if len(edges[i]) > 2 else 0
            last_time[i] = 0

        for t, (x, y, c) in enumerate(ops, start=1):
            e = get_e(x, y)
            old = cur_color[e]
            intervals.append((last_time[e], t - 1, e, old))
            cur_color[e] = c
            last_time[e] = t

        for e in range(n):
            intervals.append((last_time[e], m, e, cur_color[e]))

        # map colors locally
        color_map = {}
        for _, _, _, c in intervals:
            if c not in color_map:
                color_map[c] = len(color_map)

        # DSU over edges
        dsu = DSURollback(n)

        # per vertex-color representative edge
        rep = {}

        # segment tree
        seg = [[] for _ in range(4 * (m + 2))]

        def add(node, l, r, ql, qr, val):
            if ql <= l and r <= qr:
                seg[node].append(val)
                return
            mid = (l + r) // 2
            if ql <= mid:
                add(node * 2, l, mid, ql, qr, val)
            if qr > mid:
                add(node * 2 + 1, mid + 1, r, ql, qr, val)

        for l, r, e, c in intervals:
            if l <= r:
                add(1, 0, m, l, r, (e, c))

        comp = [0] * (m + 5)
        ans = [0] * (m + 1)

        def apply(edge, c):
            u, v = edges[edge][0], edges[edge][1]
            key1 = (u, c)
            key2 = (v, c)

            if key1 not in rep:
                rep[key1] = edge
                comp[c] += 1
            else:
                if dsu.union(edge, rep[key1]):
                    comp[c] -= 1
                rep[key1] = dsu.find(edge)

            if key2 not in rep:
                rep[key2] = edge
                comp[c] += 1
            else:
                if dsu.union(edge, rep[key2]):
                    comp[c] -= 1
                rep[key2] = dsu.find(edge)

        def dfs(node, l, r):
            snap_dsu = dsu.snapshot()
            snap_rep = len(rep)

            for e, c in seg[node]:
                apply(e, c)

            if l == r:
                if l > 0:
                    ans[l] = sum(comp)
            else:
                mid = (l + r) // 2
                dfs(node * 2, l, mid)
                dfs(node * 2 + 1, mid + 1, r)

            while len(rep) > snap_rep:
                rep.popitem()

            dsu.rollback(snap_dsu)

        dfs(1, 0, m)

        out = []
        for i in range(1, m + 1):
            out.append(str(ans[i]))

        print(f"Case #{tc}:")
        print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、各エッジの色履歴を時間間隔に変換することに重点を置いています。 各間隔は、セグメント ツリーの走査が対応する時間ウィンドウに到達した場合にのみ適用される結合操作のバッチになります。 

DSU ロールバック構造により、関連のない時間セグメント間で結合がリークしないことが保証されます。 カラーごとのコンポーネント カウンタは、頂点に新しい孤立エッジが現れると増加し、結合が以前に分離したコンポーネントをマージする場合は減少することによって維持されます。 

微妙な点は、エッジの隣接性が (頂点、色) ごとに代表的なエッジを使用して頂点を通じて間接的にモデル化されることです。 これにより、隣接関係リストのスキャンが回避され、接続候補への常時アクセスが保証されます。 

## 実用的な例

 三角形を形成する 3 つの頂点と、最初に異なる色が付けられた 3 つの辺を持つ小さなグラフを考えてみましょう。 1 回の更新で 1 つのエッジの色が変更されます。 

時間 1 では更新が行われていないため、各色には 1 つのエッジがあり、各エッジは独自のコンポーネントを形成します。 

| 時間 | 操作 | コンポーネントの変更 | 合計 |
 | --- | --- | --- | --- |
 | 0 | イニシャル | 3 片刃コンポーネント | 3 |
 | 1 | エッジの色を変更 | 1 つの色が 2 番目のエッジ接続を取得するか、グループ化が変更されます。 更新されました |

 これは、答えが再着色されたエッジによって引き起こされるローカル接続の変化のみに敏感であることを示しています。 

2 番目の例は、多くのエッジが中心ノードで交わるスター グラフです。 すべてのエッジが同じ色を共有している場合、それらはすべて 1 つのコンポーネント内にあります。 エッジを 1 つずつ異なる色に再色付けすると、削除ごとに 1 つのコンポーネントが色ごとに新しい分離コンポーネントに分割され、コンポーネント数が共有頂点に大きく依存することがわかります。

 ## 特殊なケース

 重要なエッジ ケースは、同じエッジの再カラーが繰り返されることです。 アルゴリズムは、エッジの色が変わるたびに間隔を閉じたり再び開いたりすることでこれを処理します。 各セグメントはセグメント ツリー内で独立して処理されるため、トグルを繰り返しても完全な再計算が繰り返されることはありません。 

もう 1 つのケースは、多くのエッジが 1 つの頂点を共有する場合です。 頂点ごと、色ごとの代表メカニズムにより、その頂点に属するすべてのエッジが単一のコンポーネントにマージされ、過小カウントが防止されます。 

最後の微妙なケースは、エッジがその色の唯一のメンバーである場合です。 その状況では、正確に 1 つのコンポーネントを提供する必要があり、実装では、最初の代表がその頂点と色のペアに割り当てられるときにコンポーネント数をインクリメントすることでこれを保証します。
