 ## 問題の理解

 一桁が与えられています$D$とターゲット整数$N$。 数字のコピーのみを使用する$D$では、連結や、加算、減算、乗算、除算、階乗、否定などの標準演算と、括弧や指数のような繰り返し規則などのいくつかの単項ラッパーを使用して算術式を構築できます。 すべての式には、その桁の数倍のコストがかかります。$D$が使用され、目標は値を構築することです$N$可能な最小限の桁数で。 

重要な点は、式自体を構築することは求められず、最小限の数だけを構築することだけが求められるということです。$D$表すために必要な数字$N$これらのルールの下で。 

制約は小さいです。$N \le 100$そして$D \in [1,9]$したがって、合理的に制限された桁数で到達可能なすべての値を探索するソリューションは実行可能です。 これは、貪欲な式や純粋に建設的な式ではなく、値とカウントに対する動的プログラミング アプローチを即座に示唆しています。 

微妙なエッジ ケースとして、階乗や除算などの演算では、使用される桁数に直接制限されない値が生成される可能性があるため、単純な連結や算術閉包に限定することはできません。 もう 1 つの落とし穴は、除算が正確であるため、分数の中間値が後で整数を生成する場合にのみ許可されることです。つまり、構築中は式を実数値として扱う必要がありますが、DP 状態を格納する場合は整数の結果のみを受け入れる必要があります。 

## アプローチ

 ブルートフォース解釈では、最大で以下を使用してすべての可能な式を構築します。$k$の桁$D$、それらを評価し、$N$が表示されます。 式の各ペアは 5 つの演算と単項ラッパーと組み合わせることができるため、これは非常に高速に拡張されます。 中程度の場合でも$k$、式ツリーの数が組み合わせ的に増加するため、このアプローチは実行不可能になります。 

重要な観察は、唯一意味のある状態は、式が評価された数値と、それが消費した桁数であるということです。 すべての式は、演算によって結合された 2 つの小さな式に分解できます。 これにより、使用される桁数に応じて動的プログラミングが自然に形成されます。 

セットを定義します$S[k]$正確に使用して到達可能なすべての整数値として$k$数字のコピー$D$。 これらのセットを段階的に構築します。 パーティションごとに$k = i + j$からのすべての値を組み合わせます。$S[i]$そして$S[j]$許可されたバイナリ演算を使用します。 また、以下を連結して形成された値も注入します。$D$繰り返された$k$回、有効な場合は階乗や否定などの単項演算を適用します。 

なぜなら$N \le 100$、制限された範囲内の値のみを考慮します。 中間値が増加する可能性があっても、妥当な範囲をはるかに超えたものは無視しても問題ありません。 

解決策は最小値を見つけることになります。$k$そのような$N \in S[k]$。

 ## アルゴリズムのチュートリアル

 セットのリストを管理します$S[1], S[2], \dots, S[8]$8 部以上のコピーを使用する必要がないため、$N \le 100$この建設スペースで。 

### ステップ

 1. それぞれの初期化$S[k]$空集合として。 これらのセットには、正確に到達可能なすべての値が格納されます。$k$のコピー$D$。 
2. それぞれについて$k$、数字の繰り返しで形成された連結番号を挿入します$D$その通り$k$回。 これは次のような表現をキャプチャします$D$、$DD$、$DDD$、 等々。 
3. 各分割について$k = i + j$、すべてのペアを組み合わせます$(a, b)$どこ$a \in S[i]$そして$b \in S[j]$、の結果を挿入します$a+b$、$a-b$、$b-a$、$a \cdot b$、正確な場合は除算。 
4. 単項変換を適用します。$a \in S[k]$負でない整数です。挿入します$a!$それが安全な範囲内にある場合。 も挿入します$-a$。 
5. 完全に構築したら$S[k]$、どうかを確認してください$N \in S[k]$。 「はい」の場合は、戻ります$k$答えとして。 
6. そうでない場合$k \le 8$動作すると、フォールバック境界として 8 を返します (この問題の制約に対して安全です)。 

### なぜ効果があるのか

 すべての有効な式は、葉が数字ブロックで内部ノードが演算であるバイナリ ツリーに対応します。 使用される桁数は葉の総重量と同じです。 DP は、分割によって可能なすべてのバイナリ ツリー分解を列挙します。$k$の中へ$i+j$、単項演算では、桁コストを増加させることなく到達可能性が維持されます。 したがって、構成可能なすべての値は、いくつかの形式で表示されます。$S[k]$、そして最初の$k$含む$N$定義上最小限です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import factorial

def concat(d, k):
    return int(str(d) * k)

def solve_case(D, N):
    MAXK = 8
    S = [set() for _ in range(MAXK + 1)]

    for k in range(1, MAXK + 1):
        S[k].add(concat(D, k))

    for k in range(1, MAXK + 1):
        for i in range(1, k):
            j = k - i
            for a in S[i]:
                for b in S[j]:
                    S[k].add(a + b)
                    S[k].add(a - b)
                    S[k].add(b - a)
                    S[k].add(a * b)
                    if b != 0 and a % b == 0:
                        S[k].add(a // b)

        to_add = set()
        for a in S[k]:
            if a >= 0 and a <= 10:
                try:
                    to_add.add(factorial(a))
                except OverflowError:
                    pass
            to_add.add(-a)

        S[k] |= to_add

        if N in S[k]:
            return k

    return 8

def main():
    T = int(input())
    for tc in range(1, T + 1):
        D, N = map(int, input().split())
        ans = solve_case(D, N)
        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    main()
```この実装は DP 構造を直接反映しています。 連結は文字列の繰り返しによって明示的に処理されます。$N \le 100$これで安全になります。 二項演算はすべてのパーティションに適用されます。$k$。 非整数の導入を避けるために、除算は正確な場合に制限されます。 

爆発を避けるために、階乗は負でない小さな整数にのみ適用されます。 より大きな階乗はすぐにターゲット範囲を超え、対象範囲を超えてしまうため、この範囲は十分です。$N \le 100$。 

最後のループでは、各桁数を昇順にチェックし、最小性を確保します。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$N$連結によって直接表現できます。 例えば、$D=7, N=777$。 DP はこれを次の場所に挿入します。$k=3$したがって、組み合わせは必要なく、より高度な操作を探索することなく答えが見つかります。 

もう 1 つのケースは、除算または階乗により予期しない中間値が作成される場合です。 たとえば、階乗は値を迅速に爆発させることができますが、DP はメンバーシップを照合してチェックするため、$N$各ステップで、無関係な大きな値は正確さに影響しません。 

最後のエッジケースは、減算により初期に負の値が生成される場合です。 DP では負の値が明示的に許可されているため、次のような値が使用されます。$1-4$はまだ保存されており、後で有効な正の値に結合できるため、状態空間の完全性が保証されます。
