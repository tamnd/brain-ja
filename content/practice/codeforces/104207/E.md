 ## 解決策
 ## 問題の理解

 一連の絵画コンペティションに向けて、制作のサイズ調整を依頼されます。 各コンテストには既知の参加者数がおり、各参加者は正確に 1 つのスケッチパッドを消費します。 それに加えて、各競技会は、安全緩衝材として、その競技会の参加者の 10% に相当する追加のスケッチパッドも受け取る必要があります。 

入力により、いくつかの独立したテスト ケースが得られます。 各テスト ケースについて、競技会の数が与えられ、その後に各競技会の参加者数が続きます。 タスクは、すべての競技会で必要なスケッチパッドの総数を計算することです。各競技会は独自の要件を個別に提供します。 

重要な点は、「10% の追加料金」が競技会間で共有されないことです。 これは競合ごとに適用されるため、丸め動作はグローバルではなく値ごとに発生します。 

制約は十分小さいため、テスト ケースごとの線形スキャンでも簡単に十分です。 テスト ケースごとに最大 1000 の競合と 100 のテスト ケースがある場合、テスト ケースごとの直接 O(N) ソリューションは制限内で快適に実行されます。 

主な微妙な点は、結果が整数でない場合に 10% の追加をどのように解釈するかです。 スケッチパッドは離散的であるため、小数点以下の値は存在できず、余分な部分は切り上げる必要があります。 ここで、多くの素朴な解決策が失敗します。整数の除算や浮動小数点の切り捨てを使用すると、不正確な合計が生成されます。 

典型的な失敗シナリオは、参加者の数が少ない場合に発生します。 たとえば、コンテストの参加者が 1 人の場合、10% は 0.1 であり、切り上げた後に追加のスケッチパッド 1 枚になる必要があります。 次のような単純な計算`a // 10`誤って 0 を返します。 

## アプローチ

 この強引なアイデアは、各競合を個別に計算し、浮動小数点演算を使用して必要なスケッチパッドを計算し、すべてを合計することです。 この要件は競技全体で加算されるため、これは原則として正しいです。 ただし、特に浮動小数点乗算や整数へのキャストを使用する場合、精度の問題や誤った丸めが発生する危険があります。 

より堅牢なブルート フォースでは、各値の 10% の上限を明示的に計算しますが、それでも不注意な実装により、off-by-one エラーが発生することがよくあります。 

重要な観察は、各競争が独立しており、正確に貢献しているということです。`a_i + ceil(0.1 * a_i)`スケッチパッド。 これにより、問題は単純な要素ごとの変換とその後の合計に変換されます。 

天井項を書き換えることにより、浮動小数点を完全に回避します。 表現`ceil(a / 10)`次のように計算できます`(a + 9) // 10`。 これにより、精度エラーが回避され、すべての整数入力の正確さが保証されます。 

これが認識されると、解決策は単一の直線パスになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (浮動小数点数 + 丸め) | O(N) | お(1) | 危険 / 失敗する可能性があります |
 | 最適 (整数の上限演算) | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 最適なアルゴリズム

 1. 各テスト ケースについて、競技会の数と参加者数のリストを読み取ります。 これにより、処理する独立したユニットが確立されます。 
2. アキュムレータを初期化する`total = 0`。 これには、必要なスケッチパッドの最終的な数が保存されます。 
3. 各競争値について`a`、このコンテストによって提供された必要なスケッチパッドを計算します。 基本的な要件は`a`、各参加者には 1 つのスケッチパッドが必要であるためです。 
4. バックアップ要件を次のように計算します。`ceil(a / 10)`これにより、常に少なくとも 10% の追加分が切り上げられます。 これを次のように計算します`(a + 9) // 10`。 +9 により、整数で除算するときに 10 の倍数以外の値が正しく切り上げられます。 
5. 両方の部分を累計に加算します。 
6. すべての競技を処理した後、累積合計を必要な形式で出力します。 

### なぜ効果があるのか

 各競技会は独立しているため、合計要件は競技会ごとの要件の合計となります。 唯一重要な部分は、線形分数の上限を正しく計算することです。 アイデンティティ`(a + 9) // 10`完全に一致します`ceil(a / 10)`すべての整数に対して`a >= 1`。 すべての項は独立して計算され、相互作用なしで合計されるため、競合間での相互汚染がなく、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        n = int(input())
        arr = list(map(int, input().split()))
        
        total = 0
        for a in arr:
            total += a + (a + 9) // 10
        
        print(f"Case #{tc}: {total}")

if __name__ == "__main__":
    solve()
```このソリューションは、各テスト ケースを個別に読み取り、リストを 1 回のパスで処理します。 表現`(a + 9) // 10`重要な実装の詳細です。 それを次のように置き換えます`int(a * 0.1)`または`a // 10`天井ではなく切り捨てのため、両方とも不正確になります。 

フォーマット手順は、必要な出力構造に正確に従います。

 ## 特殊なケース

 最も重要なエッジケースは次のような場合です`a < 10`。 その体制では、`a / 10`は 1 未満ですが、実際にはまだゼロではないため、上限は 1 を返す必要があります。 

たとえば:

 入力:```
1
1
7
```アルゴリズムは以下を計算します。`7 + (7 + 9) // 10 = 7 + 1 = 8`。 

を使用した単純な実装`7 // 10`生み出すだろう`7`、必要な追加のスケッチパッドが完全に欠落しています。 これはまさに、大きな入力では正しいように見えても、制約の多い小さなテストでは失敗する、サイレントアンダーカウントバグの一種です。 

もう 1 つのエッジ ケースは、正確に 10 の倍数です。`a = 20`、`(20 + 9) // 10 = 2`、一致する`ceil(2.0)`その通り。 次のような浮動小数点丸めを使用しようとする試み`int(a * 0.1 + 0.5)`特に大きな値の場合、浮動小数点精度による誤った動作の危険性があるため、整数式はそのクラス全体のエラーを回避します。
