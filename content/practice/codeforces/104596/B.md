 ## 解決策
 ## 問題の理解

 私たちには、交差点がジャンクションであり、誘導道路がそれらを接続する道路ネットワークが与えられています。 各道路には移動時間と、開始点の交差点での幾何学的方向があります。 重要な難点は、新しい道路に曲がるには角度制限があるため、移動にはどのジャンクションにいるかだけでなく、そのジャンクションに入った方向も関係することです。 

旅は常に特別なハブとして機能するジャンクション 1 から始まります。バイオステーションは完全に回転できるため、そこからオリーは往路を自由に選択できます。 そこから、彼は特定の分岐点に到達する必要があります`d`その後、ジャンクション 1 に戻ります。旋回制約は各ジャンクションへの到着方向に依存するため、復路は独立していません。したがって、往路と復路は状態を通じて相互作用します。 

各道路は、そのソースジャンクションで固定の出方向角度を持っています。 オーリーが何らかの道路を経由して交差点に到着するとき、進入道路の方向と退出道路の方向との間の角度は、所定の旋回制限内になければなりません。 重要なのは、問題ステートメントで回転がどのように解釈されるかに応じて、異なる回転制約に対応する 2 つの制限 α1 と α2 があることです。 実際には、これは、入力方向のエッジから出力エッジに遷移するときに、特定の角度の差のみが許可されることを意味します。 

タスクは、これらの制約の下でノード 1 からノード d まで、そしてノード 1 に戻る往復の最小合計時間を計算するか、そのような有効な往復が存在しないと判断することです。 

グラフのサイズは最大 1000 ノードで、各ノードには最大 5 つの下り道路があります。 これは、状態拡張された最短パスが実行可能であることを強く示唆しています。 重要な点は、コストはノードへの入力方法によって異なるため、ノードだけでは状態として十分ではないということです。 状態はノードと受信方向の両方をエンコードする必要があります。 

微妙なエッジケースが開始ノードで発生します。 自由な回転が許可されているため、初期状態では入ってくる方向が定義されていません。 もう 1 つの微妙な点は、道路には方向があり、移動時間が非対称になる可能性があるため、可逆性を想定できないことです。 

方向性を無視した素朴なアプローチは、単純なケースでは失敗する可能性があります。 たとえば、2 つの下り道路が存在するが、進入方向に応じて 1 つのみが有効であるジャンクションを考えてみましょう。 ノード上の最短パスのアプローチでは、両方が使用可能であると誤って想定され、無効なルートが生成されます。 

もう 1 つの失敗ケースは、最適なフォワード パスによって特定のエントリの向きが強制的に変更される場合です。`d`, しかし、その向きでは復路が不可能になります。 ノードのみの最短パスでは、この相互作用が完全に失われます。 

## アプローチ

 ブルートフォースアプローチでは、これまでに使用された方向のシーケンス全体を記憶しながら最短経路を実行しようとするか、同等の方法ですべての可能な経路を列挙し、途中で方向転換の制約を検証します。 これは正しいですが、すべてのジャンクションには複数の方法で入ることができ、各エントリによって可能な出口が変わるため、組み合わせ的に爆発します。 各ノードの発信エッジが最大 5 つであっても、可能な方向履歴の数はパスの長さに応じて指数関数的に増加し、実行可能な制限をすぐに超えます。 

重要な観察は、ジャンクションで重要な唯一の履歴情報は、そのジャンクションに入るために最後に使用された道路であるということです。 入力エッジがわかれば、すべての有効な出力遷移は純粋にローカル ジオメトリによって決定されます。 これにより、問題が拡張された状態のグラフに変換されます。`(junction, incoming road index)`。 

この状態拡張では、すべての動きが標準の重み付きエッジとなり、ダイクストラのアルゴリズムを適用できます。 唯一の追加の注意は、事前方向制約なしですべての外向き道路に効果的に接続する開始ノードの処理です。 

往復要件は、この拡張されたグラフ上で最短パスを実行することによってきれいに処理できます。 一般的なアプローチは、開始点からすべての状態までの最短距離、およびすべての状態から開始点に戻る最短距離を計算することです (または同等のエッジを反転してダイクストラを実行します)。 答えは、次の時点でのフォワード状態の最適な組み合わせです。`d`そして逆方向に戻ります`1`。

 | 国家拡張されたダイクストラ | O((N+E) log E) | お(え) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、各方向の道路を固有のエッジとしてモデル化し、道路上にあることを状態の一部として扱います。 各状態は、特定の入力エッジを介してジャンクションに到着するか、または定義された入力エッジなしで開始点に到達するかに対応します。 

1. 入力内のすべての誘導道路に識別子を割り当てます。 各ジャンクションについて、その出向き道路を目的地、時間コスト、出向き角度とともに保存します。 
2. 各州が方向付けられた道路に対応するグラフを作成します。つまり、「道路 e 経由でジャンクション u に到着しました」を表します。 
3. 何らかの進入道路を経由してジャンクション u に到着することに対応する状態から、u からのすべての退出道路を考慮します。 候補となる各往路について、進入方向と退出方向の間の回転角度を計算します。 この角度が α1 または α2 制約を満たす場合、その道路のコストに等しい追加の移動時間を伴い、その往路に対応する状態への遷移が許可されます。 
4. 開始ノード (ジャンクション 1) では、バイオステーションが任意の初期方向を許可しているため、方向転換制約をチェックせずにすべての外向き道路への移行を許可します。 
5. コスト 0 でジャンクション 1 のすべての下り道路に接続する仮想開始ノードからダイクストラを実行します。 
6. すべての州で最短距離を維持します。 ターゲットはジャンクションに到達する任意のステートです`d`。 
7. 往復を完了するには、次の場所から戻る必要があります。`d`に`1`同じ制約の下で。 これは、反転した状態グラフで 2 番目のダイクストラを実行するか、すべての状態から開始する距離を同等に計算することで処理します。 最終的な答えはすべての州の最小値です`s`ジャンクションで`d`の`dist_start[s] + dist_back[s]`。 

### なぜ効果があるのか

 正確さは、実行可能な経路が一連の方向付けられた道路遷移に一意に分解され、各遷移が前の道路にのみ依存するという事実に基づいています。 これにより、問題は道路州のレベルでマルコフ式になります。 ダイクストラは、そのようなすべての状態シーケンスをコストの昇順に探索します。すべての有効な物理的動作は 1 つの状態遷移に正確に対応するため、有効なパスがスキップされることはありません。 ラウンドトリップ分解は有効です。なぜなら、`d`復路に必要な進入方向を完全に把握します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def angle_diff(a, b):
    d = abs(a - b)
    return min(d, 360 - d)

def ok(in_ang, out_ang, a1, a2):
    d = angle_diff(in_ang, out_ang)
    return d <= a1 or d <= a2

def solve():
    n, d, a1, a2 = map(int, input().split())
    
    adj = [[] for _ in range(n + 1)]
    edges = []

    for i in range(1, n + 1):
        arr = list(map(int, input().split()))
        m = arr[0]
        idx = 1
        for _ in range(m):
            to = arr[idx]
            t = arr[idx + 1]
            ang = arr[idx + 2]
            idx += 3
            eid = len(edges)
            edges.append((i, to, t, ang))
            adj[i].append(eid)

    E = len(edges)

    # build reverse transitions between edge states
    rev_adj = [[] for _ in range(E)]

    # transitions
    for eid1, (u1, v1, t1, a_in) in enumerate(edges):
        for eid2 in adj[v1]:
            u2, v2, t2, a_out = edges[eid2]
            if ok(a_in, a_out, a1, a2):
                rev_adj[eid2].append((eid1, t2))

    # forward dijkstra from start node 1 to all edges
    INF = 10**18
    dist = [INF] * E
    pq = []

    for eid in adj[1]:
        u, v, t, ang = edges[eid]
        dist[eid] = t
        heapq.heappush(pq, (t, eid))

    while pq:
        dcur, eid = heapq.heappop(pq)
        if dcur != dist[eid]:
            continue
        u, v, t, ang = edges[eid]
        for eid2 in adj[v]:
            u2, v2, t2, ang2 = edges[eid2]
            if ok(ang, ang2, a1, a2):
                nd = dcur + t2
                if nd < dist[eid2]:
                    dist[eid2] = nd
                    heapq.heappush(pq, (nd, eid2))

    # reverse dijkstra: from start node backwards
    dist2 = [INF] * E
    pq = []

    for eid in adj[1]:
        dist2[eid] = 0
        heapq.heappush(pq, (0, eid))

    while pq:
        dcur, eid = heapq.heappop(pq)
        if dcur != dist2[eid]:
            continue
        for prev, cost in rev_adj[eid]:
            nd = dcur + cost
            if nd < dist2[prev]:
                dist2[prev] = nd
                heapq.heappush(pq, (nd, prev))

    ans = INF
    for eid, (u, v, t, ang) in enumerate(edges):
        if v == d:
            if dist[eid] < INF and dist2[eid] < INF:
                ans = min(ans, dist[eid] + dist2[eid])

    print("impossible" if ans == INF else ans)

if __name__ == "__main__":
    solve()
```この実装では、それぞれが道路とそのジオメトリを表す有向エッジのリストを構築します。 ヘルパー関数`angle_diff`最小角距離を計算し、ラップアラウンドの正確性を保証します。 

最初のダイクストラは、バイオステーションから開始して各有向エッジ状態に到達するための最小コストを計算します。 初期化では、開始時に受信方向の制約がないため、ノード 1 のすべての送信エッジがプッシュされます。 

2 番目のダイクストラは、逆遷移グラフを実行し、各エッジ状態から最初に戻るための最小コストを計算します。 この対称性により、1 つのパスで完全な往復を明示的にシミュレートする必要がなくなります。 

最後に、答えは宛先ノードで終了するすべてのエッジ状態をチェックします。`d`、フォワードコストとバックワードコストを組み合わせたものです。

 ## 特殊なケース

 エッジ ケースの 1 つは、最適な順方向パスが宛先に到達するが、その方向のみがすべての発信遷移をブロックする場合です。 このような場合でも、前方ダイクストラは有限のコストを割り当てますが、後方ダイクストラは決してその状態に到達しないため、最終的な答えから除外されます。 

別のエッジ ケースは、複数の下り道路が存在する開始ノードで発生します。 それらはすべて優先キューにシードされる必要があります。 そうしないと、有効な初期方向が削除され、有効なルートが存在する場合でも、問題が誤って不可能としてマークされる可能性があります。 

最後の微妙なケースは、旅行が非対称である場合です。 一方向に最適な道路でも、中間ノードでの方向転換の制約により、逆方向には使用できない場合があります。 状態ベースの表現では、逆遷移が想定されるのではなく明示的に検証されるため、この非対称性が確実に尊重されます。
