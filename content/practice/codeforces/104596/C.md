 ## 解決策
 ## 問題の理解

 私たちは数種類の原材料、具体的にはさまざまなチーズを与えられますが、それぞれポンド単位で数量限定で入手可能です。 これに加えて、チーズブレンドなどの最終製品の可能性もいくつかあります。 各ブレンドは固定レシピによって定義されます。ブレンド 1 ポンドごとに、各チーズの種類を一定の割合で使用する必要があります。 各ブレンドには販売時のポンド当たりの固定利益も含まれます。 

課題は、総利益を最大化しながら、どの種類のチーズでも利用可能な供給量を超えないよう、各ブレンドを何ポンド生産するかを決定することです。 私たちが生産するブレンドの各単位は、そのレシピに従って複数の種類のチーズを部分的な量で消費するため、これは単純な割り当て問題ではなく、ブレンドが部分的な量で生産される連続的な割り当て問題です。 

制約は小さく、チーズの種類とブレンドの数は両方とも最大 50 です。これは、ブレンドの量を強引に決めるのではなく、多項式時間の最適化手法が期待されることをすぐに示唆しています。 ただし、主な問題点は、生産が継続的であり、複数の共有リソースによって制約されるため、組み合わせ検索空間ではなく、実行可能なソリューションの幾何学的配置が作成されることです。 

各ブレンドの可能なすべての生産レベルを試してみるという単純な考えがありますが、各ブレンドの量は原理的には連続であるため、小さなステップで離散化してもすぐに爆発的に増加します。 別の単純な試みとしては、ポンドあたりの利益を貪欲に求めることも考えられますが、異なる配合の共有チーズをめぐって異なるブレンドが競合するため、これは失敗します。 

高利益のブレンドでは希少なチーズを大量に消費する一方、低利益のブレンドでは豊富なチーズのみを使用する場合、微妙なエッジケースが現れます。 貪欲な戦略は利益の高いブレンドを選択し、ボトルネックのリソースを使い果たし、総利益をより多く生み出す低利益のブレンドの組み合わせをブロックします。 もう 1 つのエッジ ケースは、2 つのブレンドの利益は同じだがリソース プロファイルが異なる場合に発生します。この場合、最適なソリューションは、局所的な優先順位ではなく、制約の全体的な相互作用に完全に依存します。 

この構造は、線形計画法による定式化を強く示唆しています。つまり、線形制約の下で線形目標を最大化しています。 

## アプローチ

 直接的な強引なアプローチでは、各ブレンドを、生産するポンド数を表す変数として扱います。 生産量を少しずつ離散化すると、生産レベルのすべての組み合わせを列挙できます。 1 ポンドのような粗いステップ サイズであっても、最大 50 のブレンドのそれぞれが独立して最大数百単位の範囲に及ぶ可能性があるため、状態空間は巨大になります。 これはおおよそ次のことにつながります$500^{50}$最悪の場合は可能性もありますが、それは完全に不可能です。 

重要な観察は、制約と目的の両方が線形であるということです。 チーズの種類ごとにブレンド変数に対して線形不等式が生じ、利益はそれらの変数の一次関数になります。 これはまさに線形計画問題の構造です。 

離散的な選択肢を探索する代わりに、線形計画の最適解が実行可能領域の極端な点で発生するという事実に頼ることができます。 これにより、シンプレックス法または標準の LP ソルバーを適用できるようになります。 変数と制約の次元が小さい (どちらも 50 で制限されている) ことを考慮すると、慎重に実装されたシンプレックス アルゴリズムで十分であり、このクラスの問題の競技プログラミング設定では標準的です。 

各ブレンドを変数としてモデル化します$x_j$、生産されたポンドを表します。 チーズの種類ごとに$i$、すべてのブレンドにわたる合計使用量が利用可能な供給量を超えないという制約を課します。 各ブレンドの消費量$p_{ij} / 100$ポンドのチーズ$i$生産された1ポンドあたり。 目標は合計を最大化することです$t_j x_j$。

 ## アルゴリズムのチュートリアル

 私たちは、生成する各ブレンドの量を変数で表す線形プログラムとして問題を解決します。 

1. 各ブレンドを変数に変換します$x_j$、そのブレンドのポンドを表します。 この再定式化により、問題は、組み合わせによる決定ではなく、連続変数に対する最適化に変わります。 
2. チーズの種類ごとに$i$、利用可能な在庫を超えないことを保証する制約を構築します。 合計使用量は、$\sum_j (p_{ij}/100) x_j \le w_i$。 これは、消費の物理的な実現可能性を直接強制します。 
3. 目的関数を最大化として定義します。$\sum_j t_j x_j$利益は生産量に比例するためです。 
4. すべての制約をシンプレックスに適した標準線形計画法形式に変換し、不等式にスラック変数を導入します。 これにより、実行可能領域がポリトープに変換されます。 
5. 元の実現可能解から開始してシンプレックス アルゴリズムを実行します。 各反復で、目的を改善するポリトープのエッジに沿って移動します。 
6. 改善ピボットが存在しない場合は終了します。 現在の解は、線形プログラムにとって最適であることが保証されている実行可能領域の頂点に対応します。 

これが機能する理由: 線形不等式によって定義される実行可能領域は凸多面体であり、目的はその領域上で線形です。 局所的な改善方向はエッジに沿って進み、最適性は頂点で発生する必要があります。 シンプレックス法では、目標値が増加する頂点を系統的に走査します。頂点の数は有限であるため、より良い状態を再検討することなく、最終的には最適な頂点に到達します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

EPS = 1e-9

def simplex(A, b, c):
    # maximize c^T x subject to A x <= b, x >= 0
    n = len(c)
    m = len(b)

    # tableau: m constraints + objective
    N = n + m
    M = m + 1

    tab = [[0.0] * (N + 1) for _ in range(M)]

    # constraints
    for i in range(m):
        for j in range(n):
            tab[i][j] = A[i][j]
        tab[i][n + i] = 1.0
        tab[i][-1] = b[i]

    # objective row
    for j in range(n):
        tab[m][j] = -c[j]

    def pivot(r, c_):
        inv = tab[r][c_]
        tab[r] = [v / inv for v in tab[r]]
        for i in range(M):
            if i != r:
                factor = tab[i][c_]
                if abs(factor) > EPS:
                    tab[i] = [tab[i][k] - factor * tab[r][k] for k in range(N + 1)]

    while True:
        col = -1
        for j in range(N):
            if tab[m][j] < -EPS:
                col = j
                break
        if col == -1:
            break

        row = -1
        best = 0
        for i in range(m):
            if tab[i][col] > EPS:
                val = tab[i][-1] / tab[i][col]
                if row == -1 or val < best:
                    best = val
                    row = i

        if row == -1:
            break

        pivot(row, col)

    return tab[m][-1]

行列 A[i][j] は、ブレンド j のポンド当たりに使用されるチーズ i の量であり、pi / 100 です。ベクトル b は、wi から入手可能です。 目標 c はポンドあたりの利益です。 

シンプレックス実装では、スラック変数が未使用のチーズを表すタブローを維持します。 ピボットは、実現可能性を維持しながら、非基本変数 (ブレンド量) を基底に交換します。 このアルゴリズムは、負の削減コストを持つ変数を繰り返し選択し、最小比率テストを実行して実現可能性を維持します。 

パーセンテージ値と利益では 10 進数の演算が導入されるため、浮動小数点の比較には注意が必要です。 EPS は、ピボット選択の不安定性を回避するために使用されます。

 ## 特殊なケース

 重要なエッジケースは、1 つの種類のチーズがどのブレンドにも使用されない場合です。 その場合、対応する制約は冗長であり、実現可能性に影響を与えることはありません。 シンプレックス定式化では、行が緩んだままで拘束されることがないため、これを自然に処理できます。 

別のエッジケースは、複数のブレンドの利益は同じだが、消費ベクトルが異なる場合に発生します。 アルゴリズムは、目標値を変更せずにそれらの間でピボットすることができます。 このような頂点はすべて最適であり、同等の解を表すため、これは安全です。 

最後の微妙なケースは、制約全体で 0.1 や 0.3 などのパーセンテージが累積した場合の浮動小数点の不安定性です。 EPS しきい値により、ゼロに近いピボット要素が確実に無視され、実現可能性を侵害する誤った基底スワップが防止されます。
