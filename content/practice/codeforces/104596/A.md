 ## 解決策
 ## 問題の理解

 私たちは平面上で、裁判官、タール保管庫、羽毛倉庫という 3 つのグループのポイントを与えられています。 各ジャッジは、厳密に 1 つのリポジトリおよび 1 つのストアハウスとペアになる必要があります。 ペアリング ルールは貪欲かつ逐次的です。つまり、任意のジャッジに最も近い利用可能なリポジトリを繰り返し見つけ、そのリポジトリをそのジャッジに割り当て、その後の検討から両方を削除し、すべてのジャッジが割り当てられるまで継続します。 タールの割り当てが完了したら、羽毛倉庫ごとに同じプロセスを個別に繰り返します。 

距離は点間の標準ユークリッド距離です。 出力は、両方のフェーズで使用されるすべての距離の合計です。 

重要な構造は、両方のフェーズが 2 つのポイント セットと固定のジャッジ セットの間の独立した貪欲マッチング問題であるということです。 タイブレークルールは、距離が一致した場合に決定論を強制します。最初にインデックスの低いジャッジ、次にインデックスの低い施設が続きます。 

制約により、すべてのセットの上限は 1000 ポイントになります。 これにより、$O(n^2)$または$O(n^2 \log n)$受け入れられるアプローチ。 すべてのペアごとの距離を繰り返し再計算するアプローチは依然として実行可能ですが、割り当てごとにヒープ メンテナンスを繰り返すことも問題ありません。 

複数のリポジトリの距離が等しい場合、微妙な障害が発生します。 タイブレークを無視した単純な実装では、必要とは異なるジャッジが割り当てられ、除去の合計順序が変更され、異なる最終合計が生成される可能性があります。 たとえば:

 入力:```
2 2 0
0 0
0 1
1 0
1 1
```すべての距離の構造は同一ですが、タイブレークにより決定的なペアリングが強制されます。 「インデックスが最も低いジャッジを最初に」を強制しない実装では、一貫性のない割り当てが生成されます。 

## アプローチ

 この強引なアイデアは、残りのすべてのジャッジとリポジトリのペアを繰り返しスキャンし、距離を計算し、最小のものを選択し、両方のポイントを割り当て、削除することです。 これはまさにこの声明が説明していることです。 これは、貪欲ルールを直接シミュレートするため、正しいです。 

このアプローチのコストは、縮小するセットに対する最小距離を再計算することから発生します。 最大 1,000 人の審査員と 1,000 のリポジトリを使用すると、1,000 回の反復ごとに最大 100 万ペアがスキャンされ、$10^9$フェーズごとの距離計算。これは境界線にありますが、最適化された言語ではまだ許容可能であり、Python では限界です。 

重要な点は、この構造ではグローバル プライオリティ キューを維持する必要がないことです。 制約が小さいため、再計算がより簡単かつ安全になり、微妙なヒープ タイブレークの問題が回避されます。 同じロジックが tar とフェザーの割り当てに個別に適用されます。 

したがって、最適なアプローチは、反復ごとに新しいスキャンを使用して貪欲なプロセスを明示的にシミュレートし、割り当てられた要素を削除することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各ステップのブルート フォース スキャン |$O(n^2 m + n^2 p)$最悪の場合 |$O(n+m+p)$| 承認済み |
 | 最適化されたヒープ シミュレーション |$O((nm+np)\log(nm))$|$O(nm)$| 承認済み |

 ## アルゴリズムのチュートリアル

 タールフェーズとフェザーフェーズに分けて、説明どおりに貪欲なマッチングを正確にシミュレートします。 

### ステップ

 1. ジャッジ、タール リポジトリ、および倉庫の座標を読み取ります。 

各セットにはインデックスが付けられているため、タイブレークを決定的に強制できます。 
2. ジャッジとリポジトリ間のすべての距離を事前計算します。 

最小限の繰り返し抽出が可能な構造で保管してください。 
3. ジャッジまたはリポジトリがすでに割り当てられているかどうかをマークするブール配列を維持します。 
4. すべての審査員が一致するまで繰り返します。 

すべての未割り当てのジャッジとリポジトリのペアをスキャンします。 

最小距離のペアを選択します。 

複数のペアが同じ距離を共有する場合は、ジャッジ インデックスが最小のものを選択し、次にリポジトリ インデックスが最小のものを選択します。 
5. その距離を累計に加算し、両方のエンドポイントを割り当て済みとしてマークします。 
6. ジャッジとストアハウスに対して同じ手順を独立して繰り返します。 
7. 合計を出力します。 

### なぜ効果があるのか

 貪欲ルールは純粋にローカルです。各ステップでは、現在利用可能な最小距離のみが問題となります。 ペアを削除しても以前に計算された距離には影響しないため、最初から再計算すると正確さが保たれます。 タイブレークにより、独自の決定論的な削除シーケンスが保証されるため、シミュレーションは意図したプロセスと正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def solve():
    n, m, p = map(int, input().split())

    judges = [tuple(map(int, input().split())) for _ in range(n)]
    repos = [tuple(map(int, input().split())) for _ in range(m)]
    stores = [tuple(map(int, input().split())) for _ in range(p)]

    def run_match(A, B):
        usedA = [False] * len(A)
        usedB = [False] * len(B)
        total = 0.0

        remainingA = len(A)

        while remainingA:
            best = None
            best_d = 1e100
            best_i = best_j = -1

            for i in range(len(A)):
                if usedA[i]:
                    continue
                xi, yi = A[i]
                for j in range(len(B)):
                    if usedB[j]:
                        continue
                    xj, yj = B[j]
                    dx = xi - xj
                    dy = yi - yj
                    d = math.hypot(dx, dy)

                    if d < best_d or (abs(d - best_d) < 1e-12 and (i < best_i or (i == best_i and j < best_j))):
                        best_d = d
                        best_i = i
                        best_j = j

            usedA[best_i] = True
            usedB[best_j] = True
            total += best_d
            remainingA -= 1

        return total

    ans = run_match(judges, repos) + run_match(judges, stores)
    print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```機能`run_match`貪欲な選択ルールを直接実装します。 ネストされたループにより、「利用可能なすべてのペア間の最小距離」というステートメントの定義が厳密に遵守されます。 タイブレーク条件はインデックスを使用して明示的にエンコードされます。 私たちが使用するのは`math.hypot`ユークリッド距離を安全かつ正確に計算します。

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    import math

    def solve():
        n, m, p = map(int, input().split())
        J = [tuple(map(int, input().split())) for _ in range(n)]
        R = [tuple(map(int, input().split())) for _ in range(m)]
        S = [tuple(map(int, input().split())) for _ in range(p)]

        def match(A, B):
            usedA = [False]*len(A)
            usedB = [False]*len(B)
            total = 0.0

            for _ in range(len(A)):
                best = 1e100
                bi = bj = -1
                for i in range(len(A)):
                    if usedA[i]: continue
                    for j in range(len(B)):
                        if usedB[j]: continue
                        d = math.hypot(A[i][0]-B[j][0], A[i][1]-B[j][1])
                        if d < best:
                            best = d
                            bi, bj = i, j
                usedA[bi] = True
                usedB[bj] = True
                total += best
            return total

        ans = match(J, R) + match(J, S)
        return f"{ans:.6f}"

    return solve()

 ## 特殊なケース

 When multiple candidate pairs have identical distances, the tie-breaking rule forces selection by lowest judge index first. この実装では、距離が等しくなった後でインデックスを明示的に比較し、幾何学的対称性により複数の有効な貪欲なステップが可能になる場合でも、決定的な選択を保証します。 

When all points coincide, every distance is zero. このアルゴリズムは、辞書編集上利用可能な最小のペアを繰り返し選択し、両方のフェーズを通じて合計はゼロのままとなり、必要な出力と一致します。 

いつ$m = n$または$p = n$、すべてのジャッジは正確に 1 回一致し、ループ構造により正確に一致した後の終了が保証されます。$n$フェーズごとに貪欲に選択し、一致しないポイントが残ることはありません。
