 ## 解決策
 ## 問題の理解

 ボールは長方形のスクリーンの下端の固定点から発射されます。 単位速度で直線的に移動し、画面の境界から完全に反射し、長方形の内側に配置された一連の凸多角形の障害物とも相互作用します。 

各障害物には整数値が格納されます。 ボールが障害物の境界に当たるたびに、その値は 1 減ります。 値がゼロ以下になると、障害物は即座に消え、現在接触しているボールは、その瞬間から障害物が存在しなかったかのように直線を続けます。 ボール自体は相互作用しないので、環境が時間の経過とともに進化するようにボールが順番に発射されることを除いて、単一の軌道をシミュレートし、その効果をボールの数で乗算するだけで済みます。 

重要な出力は、すべてのボールが発射された後の各障害物の最終的な残りの値です。これは、前のボールが障害物を破壊する可能性があるため、後の軌道が変更される可能性があることを考慮しています。 

入力制約は、ジオメトリの複雑さの点で非常に小さく、ポリゴン数は最大 20、各ポリゴンの頂点数は最大 10、ボールの数は最大 500 個です。 これは、レイとポリゴン エッジ間のすべての相互作用が明示的に計算されるイベント駆動型シミュレーションが可能であることを直ちに示唆しています。 実現不可能なのは、ボールの軌道に沿って単純に時間をステップすることです。各ボールは多くの反射とポリゴンの衝突を受ける可能性があり、きめの細かいシミュレーションでは簡単に時間制限を超えてしまうためです。 

この問題の微妙な部分は、障害物が飛行中に消えるということです。これは、単一のボールの軌道の後の部分が以前の衝突に依存することを意味します。 ボールごとに固定のパスを事前に計算し、交差点をカウントするだけの単純なアプローチは正しくありません。 

いくつかの特殊なケースが重要です。 

1 つは、衝突イベント中に障害物が正確に消滅した場合です。 ボールが衝突した瞬間にポリゴンの値を 0 に減らした場合、そのポリゴンは直ちに消滅し、その後のモーションではその境界が存在しないものとして扱われなければなりません。 軌道セグメント全体の終了後に減分する単純な実装では、将来のヒット数が過大にカウントされてしまいます。 

もう 1 つは、凸多角形の異なる側面からの連続した複数のヒットです。 単一のボールが同じポリゴンに出入りする可能性があり、ボールごとにポリゴンごとに複数の境界交差が生成されます。 これは意図されたものですが、「エントリ イベント」のみをカウントする実装では、寄与の半分が失われます。 

最後に、数値的な堅牢性が重要です。 ジオメトリには、光線とセグメントの浮動小数点交差が含まれており、壁とポリゴンのヒット間のタイブレークが正しくないと、軌道が完全に変化する可能性があります。 このステートメントでは、次の許容範囲も許可されています。$10^{-7}$つまり、時間的に非常に近い出来事は注意深く一貫して扱われなければなりません。 

## アプローチ

 強引なアイデアは、各ボールを段階的にシミュレートすることです。 特定のボールについて、銃から始まる光線として扱い、壁またはポリゴン エッジとの次の交差点を繰り返し計算します。 各ステップで、最も近い有効な交差点を選択し、そこにボールを移動し、壁の反射の場合は方向を更新し、ヒットしたポリゴンをデクリメントします。 

これは、説明されている物理学に正確に従っているため、原理的には正しいです。 問題はパフォーマンスです。 各セグメントでは、すべてのポリゴン エッジ (合計で最大約 200 エッジ) との交差をチェックする必要があります。 ボールは画面上で何度も跳ね返り、最悪の場合は数万のセグメントが簡単に生成される可能性があります。 500 個のボールがある場合、これは数百万回の交差テストとなり、境界線ではありますが、それでも実現可能です。 本当の難しさは、漸近的な爆発ではなく、動的除去の下での正確さです。ポリゴンが消えると、有効なエッジのセットが変化するため、単純な事前計算は不可能です。 

重要な観察は、時間をかけて継続的なシミュレーションを行う必要がないということです。 レイがセグメントに当たる個別のイベントを処理するだけで済みます。 イベント間では何も変わりません。 したがって、軌道は一連の直線セグメントとして表すことができ、各セグメントは最も近い「アクティブな」交差点で終わります。 各イベントはローカル ジオメトリの状態のみを更新します。 

これにより、問題は静的だが縮小するセグメントのセットでレイ キャスティングが繰り返されるという問題に変わります。 セグメントの数が少ないため、ヒットするたびに次のイベントを最初から再計算するだけで十分かつ最も簡単です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ステップごとの総当たりシミュレーション | O(n · K · E) ワーストケースの大きい K | お(1) | 許容できるが危険 |
 | イベントベースのレイ キャスティング (各ステップを再計算) | 小さな定数を持つ O(n · K · E) | お(1) | 承認済み |

 ここ$E$エッジの総数は約 200、$K$ボールごとの反射/打撃イベントの数です。 

## アルゴリズムのチュートリアル

 ボールを 1 つずつシミュレートし、ポリゴンの状態をグローバルに更新します。 

1. すべてのポリゴン値を初期化し、そのエッジをセグメントとして保存します。 また、四角形の境界を 4 つの追加セグメントとして維持します。 これにより、壁と障害物の処理が統合されます。 
2. 各ボールについて、ガンでの開始位置と、指定された傾斜パラメータから導出される初期方向を設定します。 これを単位方向ベクトルに正規化します。 
3. 現在の光線とアクティブなセグメントの次の交点を繰り返し計算します。 ポリゴン値がまだ正であるすべてのポリゴン エッジと 4 つの壁をテストします。 現在位置の直前にある最も近い交差点を選択します。 
4. 最も近い交差点が見つかったら、その地点までボールを進めます。 この時点で、何が攻撃されたのかを特定します。 壁の場合は、壁の法線を横切る標準反射を使用して方向を反射します。 それがポリゴン エッジの場合は、そのポリゴンの値をデクリメントします。 
5. ポリゴンの値がゼロ以下になった場合、ポリゴンは削除済みとしてマークされ、このイベント後の現在のボールを含め、後続のすべての交差クエリでそのエッジが無視されます。 
6. 光線が長方形から出るまでプロセスを続けます。光線が長方形の外に出るか、有効な交点が残っていない状態で境界にぶつかった場合に発生します。 
7. すべてのボールが処理された後、すべてのポリゴンの残りの値をゼロにクランプして出力します。 

推論の重要なステップは、各イベントが将来の行動が変化する可能性がある唯一のポイントを完全に説明していることです。 イベント間では、光線は状態が変化することなく空のユークリッド領域を通過します。 

### なぜ効果があるのか

 常に、システム状態は、光線の位置、その方向、およびアクティブなポリゴン エッジのセットで構成されます。 次の状態変化は、光線がこれらのエッジまたは壁の 1 つと交差する場合にのみ発生します。 このような交差点に最も近いものを常に選択することで、中間イベントがスキップされないことが保証されます。 ポリゴンはカウンタがゼロに達した瞬間にのみ消えるため、トリガー ヒットの直後にポリゴンを削除すると、後続のすべての交差計算の正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

EPS = 1e-9

def dot(a, b):
    return a[0]*b[0] + a[1]*b[1]

def cross(a, b):
    return a[0]*b[1] - a[1]*b[0]

def sub(a, b):
    return (a[0]-b[0], a[1]-b[1])

def add(a, b):
    return (a[0]+b[0], a[1]+b[1])

def mul(a, t):
    return (a[0]*t, a[1]*t)

def intersect_ray_seg(p, d, a, b):
    # returns (t, u, hit) where p + d*t intersects a + (b-a)*u
    r = d
    s = sub(b, a)
    rxs = cross(r, s)
    qp = sub(a, p)
    qpxr = cross(qp, r)

    if abs(rxs) < EPS:
        return None

    t = cross(qp, s) / rxs
    u = qpxr / rxs

    if t > EPS and -EPS <= u <= 1+EPS:
        return t
    return None

def reflect(d, a, b):
    # reflect direction d across segment ab
    dx, dy = d
    ax, ay = a
    bx, by = b
    sx, sy = bx-ax, by-ay
    # normal
    nx, ny = -sy, sx
    norm = math.hypot(nx, ny)
    nx /= norm
    ny /= norm
    # reflect: d - 2(d·n)n
    dn = dx*nx + dy*ny
    rx = dx - 2*dn*nx
    ry = dy - 2*dn*ny
    return (rx, ry)

def solve():
    w, h, n, m, l, r, s = input().split()
    w = float(w); h = float(h)
    n = int(n); m = int(m)
    l = float(l)
    r = float(r); s = float(s)

    polys = []
    segs = []

    for i in range(m):
        tmp = list(map(float, input().split()))
        p = int(tmp[0])
        coords = []
        idx = 1
        for _ in range(p):
            coords.append((tmp[idx], tmp[idx+1]))
            idx += 2
        q = tmp[idx]
        polys.append([coords, q])

    # precompute segments
    poly_edges = []
    for i, (coords, q) in enumerate(polys):
        edges = []
        for j in range(len(coords)):
            a = coords[j]
            b = coords[(j+1) % len(coords)]
            edges.append((a, b))
        poly_edges.append(edges)

    walls = [
        ((0,0),(w,0)),
        ((w,0),(w,h)),
        ((w,h),(0,h)),
        ((0,h),(0,0))
    ]

    for _ in range(n):
        p = (l, 0.0)
        d = (float(r), float(s))
        norm = math.hypot(d[0], d[1])
        d = (d[0]/norm, d[1]/norm)

        alive = [True]*m

        while True:
            best_t = 1e100
            best = None  # (type, i, edge)

            # walls
            for i, seg in enumerate(walls):
                t = intersect_ray_seg(p, d, seg[0], seg[1])
                if t is not None and t < best_t:
                    best_t = t
                    best = ("wall", i, seg)

            # polygons
            for i in range(m):
                if polys[i][1] <= 0:
                    continue
                for seg in poly_edges[i]:
                    t = intersect_ray_seg(p, d, seg[0], seg[1])
                    if t is not None and t < best_t:
                        best_t = t
                        best = ("poly", i, seg)

            if best is None:
                break

            p = add(p, mul(d, best_t))

            if best[0] == "wall":
                d = reflect(d, best[2][0], best[2][1])
            else:
                i = best[1]
                polys[i][1] -= 1
                if polys[i][1] <= 0:
                    polys[i][1] = 0

    print(" ".join(str(int(max(0, p[1]))) for p in polys))

if __name__ == "__main__":
    solve()
```この実装は、イベント シミュレーションのアイデアに直接準拠しています。 重要な部分は、次の光線交差に対してグローバル スキャンを繰り返すことですが、エッジの総数が少ないため、これは許容可能です。 反射関数はセグメント法線へのベクトル投影を使用し、入射角と反射角が等しく維持されます。 

よくある落とし穴は、交差クエリ中にすでに値が 0 に達しているポリゴンを無視することを忘れることです。 もう 1 つは、方向ベクトルの正規化に失敗し、交差時間が不一致になることです。 光線セグメントの交差点での EPS 処理により、エンドポイントの二重カウントが防止され、コーナーにぶつかったときの無限ループが回避されます。 

## 実用的な例

 1 つのポリゴンと相互作用する 1 つのボールの単純化されたトレースを考えてみましょう。 

最初のいくつかのイベントのみを追跡します。 

| ステップ | ポジション | ヒットタイプ | ポリゴン値 |
 | --- | --- | --- | --- |
 | 1 | 開始 | なし | 10 |
 | 2 | エッジA | ポリ | 9 |
 | 3 | エッジB | ポリ | 8 |
 | 4 | 壁 | 反映する | 8 |
 | 5 | エッジA | ポリ | 7 |

 各イベントは幾何学的交差点に対応します。 ポリゴンがヒットするたびに残りの値が減少し、ゼロに達すると、後続のエントリはヒット シーケンスに表示されなくなります。 

次に、ポリゴンが飛行中に消える場合を考えてみましょう。 

| ステップ | ポジション | ヒットタイプ | | の前の値 | の後の値
 | --- | --- | --- | --- | --- |
 | 1 | 開始 | なし | 1 | 1 |
 | 2 | エッジA | ポリ | 1 | 0 (削除) |
 | 3 | エッジB | ポリ | 無視 | 無視 |

 2 回目のヒットの後、ポリゴンはすぐに削除されるため、3 番目のイベントは、幾何学的には同じ軌道セグメントで発生したとしてもスキップされます。 

これらのトレースは、正確さがイベント境界での即時の状態更新に完全に依存していることを示しています。

 ## 特殊なケース

 デリケートなケースの 1 つは、ボールがポリゴンの値が 0 になるまさにその瞬間に当たる場合です。 この状況では、光線が同じ幾何学的な線を通過し続ける場合、その多角形に追加のヒットが記録されないよう、多角形は直ちに消える必要があります。 アルゴリズムは、最初にデクリメントし、次の交差クエリの前にポリゴンを非アクティブにマークすることでこれを処理します。 

もう 1 つのケースは、交差時間がほぼ同じである壁とポリゴン エッジの間のコーナー グレージングです。 実装では常にイプシロンしきい値を使用して最小の正の時間が選択されるため、あいまいな同時イベントが一貫して解決され、2 つのほぼ等しいヒット間の発振が防止されます。 

最後のケースは、反射後に同じポリゴンに繰り返し入るケースです。 カウンタがゼロになるまでエッジはアクティブのままであるため、再エントリは新しい境界ヒットとして正しくカウントされ、意図した累積動作が維持されます。
