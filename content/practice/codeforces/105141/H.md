 ## 問題の理解

 人々のグループが与えられ、それぞれが最終的な目標値を持っています$a_i$。 誰しも最初はゼロからのスタートです。 段階的に適用されるグローバル操作があります。グループが「ショットを撮る」たびに、全員が同じルールを使用して現在の値を更新します。 各ショットの後、その人に現在価値がある場合$x$、になります。$(x + k) \bmod (a_i + 1)$、 どこ$k$弾性率はすべてのショットで固定されていますが、弾性率は個人によって異なります。 

各人は、自分自身の値を法として効果的に「循環」させることができます。$a_i + 1$。 ある程度の数のグローバルショットを撮影することが許可されており、すべての人が同時に目標値で正確に終了することを望んでいます。$a_i$。 課題は、これを達成する最小のショット数を決定するか、それが不可能であると報告することです。 

重要な点は、全員に同じ数の演算が適用されるが、係数は各人で異なるということです。 したがって、同じステップ数を共有する複数の独立したモジュラー線形進行を同期しています。 

制約は次のとおりです$n = 10^5$、および値$a_i$そして$k$までです$10^5$。 考えられるすべてのショット数を試すソリューションは、各チェックですべてのショット数をスキャンする必要があるため、すぐには実行不可能です。$n$人々、与えること$O(n \cdot \max a_i)$あるいはさらに悪いことに。 平$O(n \sqrt{A})$最悪の場合、アプローチが遅すぎます。 

素朴な推論による微妙な失敗例は、異なる人が互換性のないサイクルを必要とするときに現れます。 たとえば、ある人がモジュラス 2 を持ち、もう 1 人がモジュラス 3 を持っている場合、たとえそれぞれが個別に到達可能であっても、両方のターゲットに同時に着地する単一の歩数は存在しない可能性があります。 各人を個別に解決してから答えを組み合わせようとするアプローチは、モジュールの一貫性を考慮しない限り、ここでは失敗します。 

## アプローチ

 後$t$ショットを繰り返し、人は0から進化していく$k$モジュロ$a_i + 1$。 だから人にとっては$i$、状態は次によって完全に決定されます。$$x_i(t) = (t \cdot k) \bmod (a_i + 1)$$私たちが望んでいるのは:$$(t \cdot k) \bmod (a_i + 1) = a_i$$以来$a_i \equiv -1 \pmod{a_i + 1}$、この条件は次のようになります。$$t \cdot k \equiv -1 \pmod{a_i + 1}$$したがって、それぞれについて$i$、変数の線形合同を解いています。$t$:$$k t \equiv -1 \pmod{m_i}, \quad m_i = a_i + 1$$次の単一の値$t$これらすべての合同式を同時に満たさなければなりません。 これは古典的な同時合同システムです。 ブルートフォースの方法では、増加を試みます$t$0 から上に移動し、毎回すべての制約をチェックします。 各小切手にかかる費用$O(n)$、そして最悪の場合には$t$のオーダーになる可能性があります$10^5$以上の場合、$O(n \cdot t)$が遅すぎます。 

重要な構造的単純化は、各制約には解決策がないか、強制力がないことです。$t$に応じて換算係数を法として剰余クラスに変換します。$\gcd(k, m_i)$。 各制約は、独立して次の形式の合同に縮小できます。$$t \equiv r_i \pmod{m_i'}$$解決可能であれば。 すべての制約が軽減されると、一貫性を追跡し、最小の非負の解を維持しながら、中国剰余定理スタイルの結合を使用して合同式を結合する問題になります。

 ## アルゴリズムのチュートリアル

 1. それぞれについて$i$の後の条件を書き換えます$t$モジュラー方程式としてのショット$k t \equiv -1 \pmod{a_i+1}$。 これにより、未知のものは標準的な線形合同式に分離されます。 
2. しましょう$m = a_i + 1$。 コンピューティング$g = \gcd(k, m)$。 もし$g > 1$、どうかを確認してください$-1$で割り切れます$g$。 以来$-1$決して何によっても割り切れない$g > 1$、これはすぐにそれが不可能であることを意味します$i$。 このステップにより、満たされない制約を継続することが防止されます。 
3. すべてを次の式で割って合同性を小さくします。$g$。 得られるものは次のとおりです。$$\frac{k}{g} t \equiv \frac{-1}{g} \pmod{\frac{m}{g}}$$縮小後、係数と係数は互いに素であるため、逆数が存在します。 

1. モジュラー逆関数を計算します。$k/g$モジュロ$m/g$。 両辺を乗算して分離します$t \equiv r_i \pmod{m/g}$。 これにより、各制約が標準の剰余条件に変換されます。 
2. すべての合同式を段階的にマージします。 現在のソリューションを維持する$t \equiv x \pmod{M}$。 新しい制約ごとに$t \equiv r \pmod{m'}$、 解決する：$$x + M \cdot p \equiv r \pmod{m'}$$これも次の線形合同式です。$p$、gcdで除算した後、逆モジュラーを使用して解くことができます。 アップデート$x$有効な最小値と$M$LCM のような結合係数に変換します。 

1. すべての制約を処理した後、結果を出力します。$x$、これは、すべてのメンバーを同時に満足させる、負ではない最小ショット数です。 

なぜそれが機能するのか: 人それぞれ制約がある$t$周期的な等差数列に。 実現可能条件は、各数列を約数を法とする剰余クラスに還元します。$a_i+1$。 マージ ステップでは、現在のソリューション セットがすべての処理された制約の正確な交差であるという不変条件が保存されます。 各マージは交差クラスの最小代表を計算するため、最終結果は有効な最小値になります。$t$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ext_gcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x1, y1 = ext_gcd(b, a % b)
    return g, y1, x1 - (a // b) * y1

def mod_inv(a, mod):
    g, x, _ = ext_gcd(a, mod)
    if g != 1:
        return None
    return x % mod

def merge_congruence(a1, m1, a2, m2):
    g, p, q = ext_gcd(m1, m2)
    diff = a2 - a1
    if diff % g != 0:
        return None, None

    lcm = m1 // g * m2
    step = m2 // g

    t = (diff // g) * p % (m2 // g)
    res = (a1 + m1 * t) % lcm
    return res, lcm

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    # initial congruence: t ≡ 0 mod 1
    x, m = 0, 1

    for ai in a:
        mod = ai + 1
        g = __import__("math").gcd(k, mod)

        if (-1) % g != 0:
            print(-1)
            return

        mod //= g
        kk = k // g

        inv = mod_inv(kk % mod, mod)
        if inv is None:
            print(-1)
            return

        r = (inv * (-1 // g)) % mod

        x, m = merge_congruence(x, m, r, mod)
        if x is None:
            print(-1)
            return

    print(x)

if __name__ == "__main__":
    solve()
```このソリューションは、各人の要件をショット数に関するモジュール式の条件に変換することから始まります。 拡張 gcd ルーチンは、モジュール逆行列と 2 つの合同式を 1 つの一貫した合同式にマージする場合の両方に使用されます。 

機能`merge_congruence`コアとなる CRT スタイルのコンバイナーです。 2 つの等差数列の交差を解決し、これまでのすべての有効な解を表す新しい基本値と係数を返します。 

よくある落とし穴は、合同式を縮小するときに実現可能性のチェックを忘れることです。右辺が gcd で割り切れない場合、その人には解が存在せず、続行すると後で誤ったマージが発生することになります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    def solve():
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        def ext_gcd(a, b):
            if b == 0:
                return a, 1, 0
            g, x1, y1 = ext_gcd(b, a % b)
            return g, y1, x1 - (a // b) * y1

        def mod_inv(a, mod):
            g, x, _ = ext_gcd(a, mod)
            if g != 1:
                return None
            return x % mod

        def merge(a1, m1, a2, m2):
            g, p, q = ext_gcd(m1, m2)
            diff = a2 - a1
            if diff % g != 0:
                return None, None
            lcm = m1 // g * m2
            t = (diff // g) * p % (m2 // g)
            return (a1 + m1 * t) % lcm, lcm

        x, m = 0, 1
        for ai in a:
            mod = ai + 1
            g = math.gcd(k, mod)
            if (-1) % g != 0:

            if inv is None:
                return "-1"
            r = (inv * (-1 // g)) % mod
            x, m = merge(x, m, r, mod)
            if x is None:
                return "-1"

        return str(x)

    return solve()

 ## 特殊なケース

 主なエッジケースは次のような場合です$\gcd(k, a_i + 1) > 1$。 たとえば、次の場合$k = 4$そして$a_i = 5$、 それから$m = 6$そして$\gcd(4,6)=2$。 目標となる条件は、$4t \equiv 5 \pmod{6}$、左側は常に偶数 mod 6 ですが、右側は奇数であるため、解はありません。 アルゴリズムは、可算性チェックを通じてこれを即座に検出します。$-1$、失敗して戻ります$-1$マージが行われる前に。 

すべてが揃った場合、別のエッジケースが発生します。$a_i = 0$。 この場合、すべての法は 1 になり、すべての制約は自明に満たされ、答えは常に 0 になります。実装では、各制約が自明な合同式に正しく還元され、保存されます。$t=0$すべてのマージを通して。
