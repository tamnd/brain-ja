 ## 解決策
 ## 問題の理解

 スロットマシンの列が与えられ、それぞれにいくつかの石が含まれています。 l から r までインデックスが付けられたマシンの連続したセグメントでは、そのセグメント上で 2 人用ゲームがプレイされます。 

移動は、セグメント内の任意のマシンを選択し、マシンに十分な石がある限り、そこから 1 ～ k 個の石を削除することで構成されます。 プレイヤーは交互に手を動かし、正当な手を打てなかったプレイヤーが負けます。 追加の工夫が 1 つあります。プレイヤーがちょうど x 個の石を取り、前の動きでも x 個の石を取った場合、現在のプレイヤーは即座に負けます。 

すべてのセグメント [l, r] について、両方のプレーヤーが最適にプレーし、開始プレーヤーがそのゲームに負けるかどうかを判断する必要があります。 タスクは、開始プレイヤーが負けているセグメントの数を数えることです。 

この制約により、私たちはセグメントごとのシミュレーションから大きく遠ざけられます。 n が最大 100 万の場合、すべてのセグメントを列挙するとすでに約 10^12 の候補が存在することになるため、どのような解決策でも問題を線形または線形に近い時間で処理できるものに減らす必要があります。 k の値は小さく、最大でも 100 であり、これが非自明な削減に利用できる唯一のパラメータです。 

素朴な考え方による微妙な失敗例は、前の手のサイズを繰り返すというグローバル ルールから生じます。 たとえば、k = 2 で、セグメントがサイズ 3 の単一の山で構成されている場合、単純な引き算ゲームの直感では、最初のプレーヤーが勝つことがわかります。 ただし、「連続して 2 回同じ手はない」というルールは、山ごとにローカルに解釈されると、この推論を妨げるように見える可能性があります。 主な難点は、制限がマシンごとではなく、プレイ履歴全体にわたってグローバルであるため、単純な分解が疑わしいことです。 

もう 1 つのよくある落とし穴は、移動はどの山でも行われるため、すぐに杭の独立性を仮定してしまうことです。 最後の手の制限が最適なプレイとどのように相互作用するかを理解するまで、その仮定は明らかに有効ではありません。 

## アプローチ

 最も直接的なアイデアは、セグメント [l, r] ごとにゲームをシミュレートすることです。 固定セグメントの場合、すべての杭の現在の構成と最後の移動値として状態をモデル化します。 それぞれの動きは、最大 n 個のパイルの選択肢と k 個の除去量の選択肢に分岐します。 メモ化を行ったとしても、状態空間はすべての ai 値に依存し、セグメントの長さに応じて指数関数的に増加します。 すべての O(n^2) セグメントに対してこれを繰り返すことは完全に不可能です。 

重要な簡素化は、ゲーム内の唯一のグローバル メモリが最後に取得された量 x の値であることを認識することから生まれます。 これは、ゲームが減算ゲームのように動作することを示唆しており、移動オプションは 1 から k までの色でラベル付けされており、唯一の制約は同じ色を 2 回連続して使用できないことです。 

次に、最適なプレイが実際にどのようなことを行うかを観察してください。 サイズ x の手を打った後、対戦相手は x の使用を強制されません。k ≥ 2 である限り、対戦相手は常に [1, k] 内の少なくとも 1 つの代替 y にアクセスできるからです。k が少なくとも 2 であるため、基礎となる減算構造でその位置自体が既に負けている場合を除き、「禁止された反復」制約によって非終端位置からすべての正当な手が削除されることはありません。 

これにより、勝ち負けの状態に関して制限が不活性になります。基礎となるゲームの価値は、山が 1 から k までの手による古典的な減算ゲームのように動作するかどうかにのみ依存します。 

サイズ a の単一の山の場合、その古典的な結果は、mod (k + 1) = 0 のときに正確に位置が失われることを示しています。これにより、各マシンに単純なローカル ラベルが与えられます。 

このルールに基づいて各マシンがバイナリ結果に還元されると、マシン間の相互作用はその間隔にわたって XOR のようなものになります。つまり、セグメント上のこれらのローカル値の XOR が 0 である場合に限り、セグメントは失われます。 これにより、標準的なプレフィックス頻度の問題である、ゼロ XOR を持つサブ配列をカウントする作業が軽減されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | セグメントごとのブルート フォース シミュレーション | O(n^2 · 状態) | O(n) 以上 | 遅すぎる |
 | 減算ゲーム + プレフィックス XOR カウントに減らす | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各マシンを独立した減算ゲームとして勝敗を捉えるコンパクトな値に変換します。 

1. 各位置 i について、bi = ai mod (k + 1) を計算します。 このステップでは、パイルを 1 から k までの移動による古典的なテイクアウェイ ゲームの同等の位置に変換します。 これが機能する理由は、そのゲームでは、動きを完全に制御できるため、位置が k + 1 ごとに繰り返されるためです。 
2. bi を i 番目のマシンのゲーム価値として解釈します。ここで、bi = 0 は負けの位置に対応し、bi ≠ 0 は勝ちの位置に対応します。 
3. これらの値に対してプレフィックス XOR 配列を計算します。ここで、pref[i] = b1 XOR b2 XOR ... XOR bi。 これは、任意のセグメント [l, r] を単一の値 pref[r] XOR pref[l - 1] に変換します。 
4. セグメントは、XOR 値が 0 の場合に正確に損失を示します。これは、pref[r] が pref[l - 1] と等しい場合に正確に発生します。 
5. 等しいプレフィックス値のペアが何組存在するかを数えます。 これは、左から右にスキャンしながら周波数マップを維持することによって実行できます。 

正しさは、各マシンが最適なプレイの下で独立した公平なゲーム コンポーネントに貢献するという事実にかかっています。 コンポーネント間の唯一の相互作用は、同等の単一パイル結果の XOR 合成によるものです。 

### なぜ効果があるのか

 最適なプレイ結果の観点から最終手の制限が無視されると、セグメント全体のゲーム状態は独立した減算ゲームの合計のように動作します。 各パイルは、周期 k + 1 の周期的な負けパターンに減少します。k ≥ 2 の場合、プレーヤーは常に前の手とは異なる代替手を持っているため、グローバル制限はグランディ構造を変更する最適な戦略の移行を排除しません。 したがって、各位置はバイナリの Grundy 値に寄与し、完全なセグメント値はそれらの XOR になります。 ゼロ XOR は、開始プレイヤーの負け状態を正確に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    freq = {0: 1}
    pref = 0
    ans = 0

    mod = k + 1

    for x in a:
        v = x % mod
        pref ^= v
        ans += freq.get(pref, 0)
        freq[pref] = freq.get(pref, 0) + 1

    print(ans)

if __name__ == "__main__":
    main()
```この実装では、最初にモジュロ k + 1 を使用してすべてのパイルを削減します。これが重要な構造の簡素化です。 次に、これらの削減された値の実行中の XOR を維持します。 プレフィックス XOR が繰り返されるたびに、XOR がゼロのセグメントを示します。これは、開始プレイヤーの負け位置に対応します。 ハッシュ マップは、各プレフィックス値が出現する頻度を追跡します。 

pref[r] 自体が 0 の場合、インデックス 1 から始まるセグメントは有効であるため、ゼロの最初のプレフィックス XOR が 1 回カウントされることに注意する必要があります。

 ### 例 1

 入力:```

```k + 1 = 3 であるため、mod 3 の値を計算します。

 ここで、最初の 0 を含む等しいプレフィックス XOR ペアをカウントします。 

周波数の進化:

 | 私 | 都道府県 | 前の頻度 | 追加しました |

これにより、1 つの間隔だけが損失構成に崩壊することが確認されます。

## テストケース```python

def run(inp: str) -> str:

 ## 特殊なケース

 重要なエッジ ケースは、すべての山が個別に位置を失っている場合です。これは、すべての ai が k + 1 で割り切れることを意味します。この状況では、すべての bi が 0 になるため、配列全体ですべてのプレフィックス XOR が 0 のままになります。 次に、アルゴリズムはプレフィックスのすべてのペアをカウントし、すべてのセグメントが失われているため、正しく n(n + 1)/2 セグメントを生成します。 

もう 1 つの特殊なケースは、単一要素の配列です。 ai mod (k + 1) がゼロ以外の場合、プレフィックス XOR はゼロ以外となり、セグメントはカウントされません。 これがゼロの場合、セグメントが 1 つだけ存在し、損失していることになります。これは、初期周波数シードによって正しく処理されます。 

さらに微妙なケースは、プレフィックス XOR 状態の繰り返しを引き起こす交互の値です。 セグメントの有効性は配列のローカル構造ではなく、プレフィックス状態の同等性のみに依存するため、アルゴリズムはこれを均一に処理します。これにより、パターンが非常に不規則な場合でも一貫性が保証されます。
