 ## 解決策
 ## 問題の理解

 私たちには、すでにバラバラな時間間隔に分割された生産のタイムラインが与えられています。 各間隔で 1 つの製品タイプのコンテナが生成され、その間隔内の単位時間ごとに 1 つのコンテナが表示されます。 したがって、プロセス全体は、時間の瞬間の長いシーケンスとして見ることができ、各瞬間には 1 つの製品タイプが関連付けられており、これらの瞬間は連続したブロックにグループ化されます。 

各コンテナは 2 つの惑星のいずれかにテレポートする必要があります。 私たちは常にどの惑星に現在のコンテナを受け入れるかを選択しますが、この選択は時間の経過とともに変化する可能性があります。 宛先の変更にはコストがかかり、それぞれの変更はスイッチと呼ばれます。 スイッチは時点を処理する前に実行されるため、現在および将来の割り当てに影響します。 

目標は、すべてのコンテナを 2 つの惑星のいずれかに割り当て、製品タイプごとにコンテナのちょうど半分が各惑星に送られるようにすることです。 同時に、タイムライン全体で使用されるスイッチの数が製品タイプの数を超えてはなりません。 

要件を言い換えると、各タイプが時間位置のマルチセットを誘発し、各タイプが完全にバランスの取れた色になるように、これらすべての位置を 2 色で色付けする必要があるということです。 難しいのは、任意に色を変更できないことです。色はタイムラインに沿って区分的に一定のプロセスから取得する必要があり、色を変更するたびに切り替えが必要になります。 

各タイプが最大 2 つの間隔で出現するという制約は重要です。 これは、すべてのタイプがグローバル タイムライン内で最大 2 つの連続ブロックに寄与することを意味し、そのバランシング パターンがどれほど複雑になるかを強く制限します。 

入力サイズは最大 10 万間隔に達するため、すべてのコンテナーに対して時間ごとの決定を素朴にシミュレートしようとするソリューションは遅すぎます。 間隔を原子的なオブジェクトとして扱い、個々の時間単位ではなく全体の長さの観点から理由を扱うアプローチが必要です。 

型に間隔が 1 つしかない場合、微妙なエッジ ケースが発生します。 次に、すべてのコンテナを惑星間で均等に分割する必要があります。これは間隔の長さが均等な場合にのみ可能であり、分割はグローバル スイッチング プロセスと一致する単一のカット ポイントを使用して達成可能でなければなりません。 タイプに 2 つの間隔がある場合、それらの合計の寄与を分割する必要がありますが、分割では、必ずしも間隔を個別に扱う必要はなく、各間隔の部分を慎重に分散する必要がある場合があります。 

素朴な貪欲なアプローチのもう 1 つの失敗モードは、間隔全体を惑星に独立して割り当てることができると仮定することです。 これは、バランシングに境界ではなく間隔内での分割が必要な、同じタイプの長い間隔の後に別の間隔が続くような場合には、すぐに壊れます。 

## アプローチ

 強引な視点は、タイムライン全体を個々の時間単位に拡張して想像することです。 各ユニットは惑星 A または B のいずれかに割り当てられ、すべてのタイプの数が等しいかどうかを確認します。 次に、スイッチ ポイントの可能なすべての割り当てを試し、合計タイム スパンまでの長さにわたってすべての区分定数バイナリ シーケンスを効果的に列挙します。 時間範囲が大きくなる可能性があり、それを無視しても、スイッチ パターンの数は時間位置の数とともに指数関数的に増加するため、これは実現不可能です。 

重要な構造観察は、タイプごとの出現の制限から得られます。 各タイプは最大 2 つの間隔で出現するため、各タイプは最大 2 つの互いに素なセグメントにわたって 1 つのバランス制約を適用するだけで済みます。 これにより、問題は、グローバルな組み合わせ割り当てから、タイムラインを 1 回スイープする間に解決できるローカル バランシング問題に縮小されます。

時間単位ごとに割り当てを決定するのではなく、スイッチ間で一定の現在の「惑星状態」を維持します。 間隔を順番に移動しながら、各タイプが各側の合計寄与のちょうど半分を徐々に蓄積するようにスイッチを配置する場所を決定します。 あるタイプが 1 つのインターバル内での寄与を終えた瞬間に、そのタイプのうちどれだけが特定の惑星にまだ送られる必要があるかが正確にわかり、現在のインターバル内の適切なポイントにスイッチを挿入することでその要件を強制することができます。 

これにより、問題は線に沿ったバイナリ カラーリングの構築に変換されます。この場合、各間隔は各色の位置をいくつ含む必要があるかについてのローカル要件を強制し、各タイプはそのような制約に最大 2 つ影響します。

 ## アルゴリズムのチュートリアル

 現在の割り当て状態を維持し、必要に応じてスイッチ位置を構築しながら、時間の増加順に間隔を処理します。 

1. すべての間隔にわたって各タイプが寄与する合計長を計算します。 全長が奇数の場合は、2 つの惑星が整数のコンテナを受け取る必要があるため、バランスをとることは不可能であるとすぐに結論付けます。 
2. 各タイプについて、1 つの惑星に対するその目標寄与をその全長の半分として計算します。 これは、発生ごとに累積する必要がある量です。 
3. 時間の昇順に間隔をスイープします。 現在の惑星の割り当てを維持します。惑星間の対称性は問題ではないため、最初は任意です。 
4. タイプ t の間隔を処理するとき、最初の惑星と 2 番目の惑星に割り当てる必要がある t の量を調べます。 t が以前の間隔で十分な貢献をすでに受け取っている場合、この間隔の残りの部分は他の惑星に強制的に送られます。 
5. 間隔内で、間隔が終了するか、現在のタイプの寄与に対する残りの要件を満たすまで、現在の惑星に時間単位を順番に割り当てます。 間隔が終了する前に要件の境界に到達した場合は、その時点でスイッチを挿入し、現在の惑星を反転します。 
6. 間隔が終了するまでこのプロセスを継続し、複数のセグメントが生成される可能性がありますが、スイッチの発生を複数回に分割するために必要なスイッチ数を超えてタイプごとに 1 つを超えないようにしてください。 
7. 惑星の状態が変化するたびに、すべての切り替え時間を記録します。 最後に、どちらの惑星でも目標を超えたタイプがないことを確認します。 

重要な設計上の選択は、タイプのバランスをとるために間隔を分割する必要があるたびに、すぐに切り替えポイントにコミットすることです。 これにより、各タイプの制約が厳しくなった瞬間に貪欲に解決されるため、後の競合が防止されます。 

### なぜ効果があるのか

 タイプごとに、必要な貢献度の合計は固定されており、2 つの惑星間で均等に分割されます。 各タイプは最大 2 つの間隔で出現するため、最初の間隔のうちどのくらいが各惑星に割り当てられるかを決定することで実行可能な解決策を表すことができ、残りは 2 番目の間隔で自動的に決定されます。 

スイープは、どの時点でも、時間の処理されたすべてのプレフィックスについて、割り当てがこれまでに確認されたすべてのタイプのすべての完全に完了した間隔制約を尊重するという不変条件を維持します。 新しい間隔に入ると、将来の発生が存在しないか、以前の決定によってすでに制限されているため、そのタイプの不足はその間隔内でのみ解決できます。 これにより、スイッチの貪欲な配置が、ローカルに最適化され、グローバルに一貫性が保たれるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    intervals = []
    total = [0] * (m + 1)

    for _ in range(n):
        t, l, r = map(int, input().split())
        intervals.append((l, r, t))
        total[t] += (r - l + 1)

    for t in range(1, m + 1):
        if total[t] % 2:
            print("No")
            print(0)
            print()
            return

    need = [x // 2 for x in total]

    intervals.sort()
    switches = []

    cur_color = 0  # 0 or 1

    # remaining need per type for current color
    got = [0] * (m + 1)

    for l, r, t in intervals:
        length = r - l + 1
        i = l

        while i <= r:
            remaining_in_type = need[t] - got[t]
            if remaining_in_type == 0:
                # everything goes to opposite side, but we just continue
                # no forced split, keep current color
                i = r + 1
                break

            take = min(length, remaining_in_type)

            # we assign [i, i+take-1] to current color
            got[t] += take
            i += take
            length -= take

            if i <= r:
                # switch before next segment
                switches.append(i)
                cur_color ^= 1

    print("Yes")
    print(len(switches))
    print(*switches)

if __name__ == "__main__":
    solve()
```コードはまず、型ごとの合計パリティのレベルで実現可能性を検証します。 次に、時間順に間隔を処理し、惑星の 1 つに各タイプがどれだけ割り当てられているかを追跡しながら、セグメントを貪欲に割り当てます。 タイプの現在の割り当てが間隔内で満たされると、すぐにスイッチを切断して登録します。これにより、スイッチの許容数をオーバーシュートすることがなくなります。 

微妙な点は、スイッチが次のセグメントの最初の瞬間に記録されることです。これは、その時間単位を処理する前にスイッチが発生するという要件と一致します。

 ## 特殊なケース

 奇数の長さの 1 つの間隔は、最初の厳しい制約を明らかにします。どの割り当ても惑星間で均等に分割できないため、アルゴリズムはパリティ チェックによって即座にそれを拒否します。 例えば、`1 1 1`分割できない単一のコンテナを強制します。 

非常にアンバランスな長さの 2 つの間隔に出現する型は、なぜ分割が境界ではなく間隔内で発生する必要があるのか​​を示しています。 たとえば、長さが 1 と 3 のタイプでは、惑星間で 2 と 2 の分割が必要となり、より長い間隔内でのカットが強制されます。 スイープ アルゴリズムは、タイプに必要な割り当てが間隔の途中で到達したときに、自然にこのカットを生成します。 

最後の微妙なケースは、複数のタイプが同じ間隔構造内でバランス ポイントをインターリーブする場合です。 各タイプは独立して制約され、間隔は順番に処理されるため、アルゴリズムは常に最も早い満たされていない要件を最初に解決し、後の要件によって以前の切り替えの決定が無効になることがないようにします。
