 ## 解決策
 ## 問題の理解

 各セルが有向システムのように動作する長方形のグリッドが与えられます。 ほとんどの細胞は正常です。つまり、細胞に足を踏み入れると、移動ごとに 1 時間のコストがかかります。 一部のセルにはワームホールが含まれており、これにより、上、右、下、左の 1 つの固定方向に瞬間的に移動するようになります。 

タスクは、左上隅から右下隅まで移動することです。 移動には 2 つの異なるコストが重なり合います。 隣接するセルへの通常のステップには 1 時間かかります。 ワームホールを使用すると、時間を消費せずに、すぐに船をその方向の次のセルに輸送します。 ただし、ワームホールは危険です。ワームホールはセルごとに 1 回の操作を犠牲にして削除され、そのセルが通常のセルに変わり、強制ジャンプが無効になる可能性があります。 

目標は辞書編集的に構造化されています。 まず、除去するワームホールの数を最小限に抑えます。 最小限の撤去数を達成するすべてのソリューションの中で、移動に費やす合計時間を最小限に抑えます。 

この制約は、最大 100 万の頂点と最大 200 万の暗黙的なエッジ (4 方向の隣接性とセルごとに最大 1 つのワームホール エッジ) を持つグラフを意味します。 状態全体にわたる単純な最短パス アルゴリズムは、それがほぼ線形な時間で実行される場合にのみ実現可能です。 状態ごとの大量の再計算や複数のグラフ構築を伴うアプローチは 10^6 スケールを通過しますが、グリッド サイズで 2 次のものは直ちに不可能です。 

微妙な問題は、ワームホールがコストゼロのチェーンを形成する可能性があることです。 ワームホールのあるセルは別のワームホールにつながり、長時間にわたる瞬間的な伝播を引き起こす可能性があります。 もう 1 つのエッジ ケースは、グリッドの外側を指すワームホールです。これは無効であり、削除しない限り使用できないものとして扱う必要があります。 

単純なアプローチは、次のような場合に失敗することがよくあります。 

入力:```
1 3
R.R
```すべての動きをコスト 1 として扱う単純な BFS は、ワームホールを使用するとテレポートできることを無視するため、最初のセルが正しい動きを強制すると認識せず、距離 2 を誤って計算します。 

別の失敗例:```
2 2
R.
..
```ここでワームホールは範囲外を指しています。 検証せずにワームホールの遷移を盲目的に追跡するアルゴリズムは、クラッシュしたり、グラフが誤って拡張されたりする可能性があります。 

## アプローチ

 ブルートフォース手法では、各ワームホール セルを削除するか保持するかの決定を明示的にモデル化します。 ワームホールのサブセットごとに、結果のグラフを構築し、BFS 経由で最短パスを計算します。 これはすぐに O(2^k · nm) にまで爆発しますが、これは小さなグリッドでも実行不可能です。 

より構造化されたブルートフォースのアイデアは、ワームホールのある各セルを、削除されたか削除されていない 2 つの状態を持つものとして扱い、拡張された状態空間上で最短パスを実行することです。 これにより、サイズ O(nm · 2) のグラフが作成されますが、遷移では依然として削除の決定を分岐する必要があり、最悪の場合は指数関数的なパスが発生します。 

重要な観察は、パス ステップごとに削除を個別に決定しているのではなく、最終パスで使用されるすべての強制遷移が有効で有益であるように、無効にするワームホールのセットをグローバルに選択していることです。 これは視点を反転することを示唆しています。最初に除去を選択する代わりに、ワームホールを許可し、それらを無視することを選択した場合にのみペナルティを支払います。 

これは当然、2 つのコストを伴う最短経路の問題につながります。1 番目の優先事項はワームホールをバイパスする (つまり、ワームホールを除去したものとして扱う) 回数であり、2 番目は移動時間です。 これは辞書編集上の最短経路問題であり、状態がペア コストを負う修正 BFS またはダイクストラで解決できます。 

各セルは自由有向エッジ (ワームホール) またはコスト 1 エッジ (手動移動) を介して遷移し、無効なワームホールは移動前にコスト 1 の「除去」が必要なものとして扱われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(2^{nm} · nm) | O(nm) | 遅すぎる |
 | 0-1 BFS / 辞書編集上の最短パス | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 各セルをグラフ内のノードとしてモデル化します。 各ノードから、有効であれば削除コスト 0 でワームホールの遷移を追跡することも、ワームホールを「削除」し、代わりに時間コスト 1 で 4 つの方向のいずれかに移動することもできます。 

この構造は、エッジにコスト (0 または 1) がある両端 BFS バリアントを使用して処理するのが最適ですが、2 次元では辞書編集的なひねりが加えられています。 

1. 各セルが最大 5 つのオプションに接続するグラフを暗黙的に構築します。ワームホールのターゲット (有効な場合) とコスト (除去 0、時間 0)、およびその 4 つの隣接セル (ワームホールをオーバーライドするかどうかに応じて除去 0 または 1、時間 +1) です。 
2. 各状態がペア (削除、時間) を格納する距離配列を定義します。 辞書順にペアを比較します。 
3. デキューを使用して、辞書編集比較に拡張された 0-1 BFS を実装します。 トランジションのコストが (0, 0) の場合、前に押します。 タイムや除去が増えたら後ろに押します。 
4. 開始セルを (除去数 0、時間 0) で初期化します。 
5. リラクゼーション中に、ワームホールがグリッドの外側を指している場合は、除去コストを支払わない限り、その方向を使用できないものとして扱い、代わりに通常の移動を考慮します。 
6. 各隣接遷移について、新しいペアが保存されているペアよりも辞書編集上小さい場合にのみ状態を更新します。 
7. 答えは、宛先セルに保存されているペアです。 

重要な実装の詳細は、ワームホールをグローバルに明示的に削除しないことです。 代わりに、ワームホールによって無効な移動または次善の移動が発生するたびに、それをコスト増分としてローカルで考慮します。 これにより、組み合わせ選択問題が最短経路問題に変換されます。 

### なぜ効果があるのか

開始から終了までのすべてのパスは、ワームホールを尊重するか、ワームホールをオーバーライドするかという一連の決定に対応します。 各オーバーライドは除去数に 1 つだけ寄与します。 有効なソリューションはどれも同じコストでこのグラフのパスにマッピングでき、このグラフのパスは有効な変更戦略に対応します。 すべてのエッジは同じコスト構造を尊重するため、辞書編集的な順序に基づいた最短パスによって最適なペアが得られます。 BFS 緩和により、最小のペア コストで状態が確定されると、その後の更新ではエッジの単調性と矛盾することなく状態を改善できることが保証されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

INF = (10**18, 10**18)

def solve():
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    # distance: (removals, time)
    dist = [[INF] * m for _ in range(n)]

    # directions
    dirs = {
        'U': (-1, 0),
        'D': (1, 0),
        'L': (0, -1),
        'R': (0, 1)
    }

    dq = deque()
    dist[0][0] = (0, 0)
    dq.append((0, 0))

    def relax(x, y, nd):
        if nd < dist[x][y]:
            dist[x][y] = nd
            dq.append((x, y))

    while dq:
        x, y = dq.popleft()
        cd = dist[x][y]

        # 1. wormhole move (cost 0,0 if valid)
        c = g[x][y]
        if c in dirs:
            dx, dy = dirs[c]
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m:
                relax(nx, ny, cd)

        # 2. normal moves (cost (0 or 1), +1 time)
        for dx, dy in dirs.values():
            nx, ny = x + dx, y + dy
            if not (0 <= nx < n and 0 <= ny < m):
                continue

            if g[x][y] in dirs:
                # we remove wormhole: +1 removal +1 time
                nd = (cd[0] + 1, cd[1] + 1)
            else:
                # normal move: +1 time only
                nd = (cd[0], cd[1] + 1)

            relax(nx, ny, nd)

    print(dist[n-1][m-1][0], dist[n-1][m-1][1])

if __name__ == "__main__":
    solve()
```この実装では、辞書編集上の最小のペアを格納する 2D 距離テーブルが保持されます。 緩和関数は単調な改善を強制します。 ワームホールの移行は時間や除去を消費しないため、最初に処理されます。 次に、標準的な隣接関係を調査します。コストは、現在のセルのワームホールが無視されるかどうかによって異なります。 

微妙な点は、ワームホールの動作を使用しないことにした場合、エッジごとではなくセルごとに削除が課金されることです。 これが、通常の移動によってワームホール セルを離れる場合にコストの増加が伴う理由です。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    INF = (10**18, 10**18)

    def solve():
        n, m = map(int, input().split())
        g = [input().strip() for _ in range(n)]

        dist = [[INF] * m for _ in range(n)]
        dirs = {'U':(-1,0),'D':(1,0),'L':(0,-1),'R':(0,1)}

        dq = deque()
        dist[0][0] = (0,0)
        dq.append((0,0))

        def relax(x,y,nd):
            if nd < dist[x][y]:
                dist[x][y] = nd
                dq.append((x,y))

        while dq:
            x,y = dq.popleft()
            cd = dist[x][y]

            c = g[x][y]
            if c in dirs:
                dx,dy = dirs[c]
                nx,ny = x+dx,y+dy
                if 0<=nx<n and 0<=ny<m:
                    relax(nx,ny,cd)

            for dx,dy in dirs.values():
                nx,ny = x+dx,y+dy
                if not (0<=nx<n and 0<=ny<m):
                    continue
                if g[x][y] in dirs:
                    nd = (cd[0]+1, cd[1]+1)
                else:
                    nd = (cd[0], cd[1]+1)
                relax(nx,ny,nd)

        return dist[n-1][m-1]

    return str(solve())

 ## 特殊なケース

 グリッドの外側を指しているワームホールは、最も脆弱なケースです。 アルゴリズムはそれを使用不可能なものとして扱い、動きは通常のエッジを通じて処理されることを強制します。 例えば：```
1 2
R.
```(1,1) から開始して、ワームホールは (1,2) に移動することを提案します。これは有効ですが、次の点に注意します。```
1 1
.
```まったく動きがなく、アルゴリズムは距離を正確にゼロに保ちます。 

もう 1 つの特殊なケースは、ワームホールの連鎖です。 ワームホール遷移は時間や除去コストを費やすことなく即座に適用されるため、繰り返される緩和は単一の BFS ウェーブ内の長いチェーンを通じて自然に伝播します。 

最後に、ワームホールのないグリッドは、グリッド グラフ内の標準の最短パスに縮小されます。 このアルゴリズムは、単位コストを伴うマンハッタン エッジ上の BFS にきれいに縮退し、古典的な動作との一貫性を確認します。
