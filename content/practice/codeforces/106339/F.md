 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられた配列が与えられます。各位置 i には値 h[i] が含まれます。 この配列のほかに、複数のクエリがあります。 各クエリはセグメント [L, R] と値 K を与え、このセグメント内のインデックス i が i と h[i] の両方を含む割り算条件を満たす個数を数えるように求めます。 

条件は、gcd(h[i], i) が K で割り切れるということです。これは、インデックスの構造とそのインデックスに格納されている値を結び付けるため、単に等しいか単純な gcd しきい値をチェックするよりも強力です。 

重要な構造的帰結は、gcd の性質に由来します。 K が gcd(h[i], i) を除算する場合、K は h[i] と i の両方を個別に除算する必要があります。 これにより、最初は数理論条件のように見えたものが、インデックスに対する純粋な可分性フィルタリング問題に変換されます。 

このタイプの問題の制約により、通常、同様の数のクエリで n が約 10^5 以上に押し上げられます。 これにより、クエリごとにすべてのインデックスの gcd を再計算することは直ちに除外されます。これは、クエリごとに O(n) となり、最悪の場合は 10^10 の演算に爆発的に増加するためです。 クエリごとに完全な O(n log n) ソリューションを実行したとしても、遅すぎます。 

微妙な問題は、条件がインデックスと配列値の両方に依存するため、純粋に h[i] について何かを事前計算するだけでは十分ではないことです。 多くの異なる K 値について、動的に定義されたインデックスのサブセットにわたる高速範囲カウントをサポートする必要があります。 

単純な実装では、重要なエッジ ケース (K が n より大きい、またはすべての h[i] より大きい) も見逃される可能性があります。 この場合、K で割り切れる i を満たすインデックスは存在しないため、答えは常に 0 になります。たとえば、n = 5、h = [2, 4, 6, 8, 10]、K = 7 の場合、すべてのクエリは 0 を返す必要があります。範囲を正しく処理せずに不完全な割り算リストを盲目的にスキャンまたは保存するアプローチは、引き続き正しく動作する可能性がありますが、非効率的な前処理により、不要な値を反復することで時間を無駄にする可能性があります。 

別の失敗ケースは、K = 1 の場合に発生します。 gcd(h[i], i) は常に 1 で割り切れるため、ここではすべてのインデックスが条件を満たします。正しいソリューションでは、特別なケースを使用せずにこれを自然に処理する必要がありますが、K から始まる倍数のみを反復する不適切な前処理ループは、慎重に設計されていないとスキップしたり、K = 1 を誤って処理したりする可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 各クエリについて、[L, R] 内のすべてのインデックス i を反復処理し、gcd(h[i], i) を計算し、K で割り切れるかどうかを確認します。これは、定義に直接従うため、正しいです。 ただし、クエリごとにすべてのインデックスの gcd を計算する必要があり、gcd には対数時間がかかるため、クエリあたり O(n log n) になります。 クエリが多いと、これでは非常に遅くなります。 

ボトルネックは、クエリ間で同じ構造チェックを繰り返すことから発生します。 この条件は L と R に複雑に依存しません。 それは、インデックスが K によって定義された事前計算可能なセットに属しているかどうかのみに依存します。K が i と h[i] の両方を除算する場合に限り、K が gcd(h[i], i) を除算することが理解できれば、前処理をクエリから切り離すことができます。 

この観察により、視点を逆転させることができます。 配列に対して各クエリをチェックする代わりに、可能なすべての K について、i と h[i] の両方が K で割り切れるようなインデックス i のリストを事前計算します。インデックスを昇順に処理するため、そのような各リストは自然にソートされます。 次に、各クエリは並べ替えられたリスト上の範囲カウントの問題に帰着し、二分探索を使用して答えることができます。 

残りの最適化は前処理中です。 すべての K についてすべての i をチェックする必要はありません。代わりに、固定 K の場合、K で割り切れる i を満たす可能性があるのはそれらのインデックスだけであるため、K の倍数に対してのみ反復処理します。これにより、n にわたる調和系列 (O(n log n)) への構築コストが削減されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q · n log n) | お(1) | 遅すぎる |
 | 最適 | O(n log n + q log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 可分性構造に従ってインデックスを整理することでソリューションを構築します。 

1. データ構造 (通常は辞書またはベクトル配列) を作成し、考えられる K ごとに有効なインデックスのリストを保存します。 この構造は、問題空間に現れるすべての潜在的な約数に対する答えを蓄積します。 
2. K を 1 から n まで繰り返します。 各 K について、その倍数 i のみをスキャンします。つまり、i = K、2K、3K など、n まで続きます。 K で割り切れないインデックスは決して条件を満たすことができないため、この制限は有効です。 
3. 各候補インデックス i = mK について、h[i] も K で割り切れるかどうかを確認します。 h[i] mod K が 0 に等しい場合は、両方の必須条件が成立するため、i を indices[K] に追加します。 これにより、有効なポジションのみが保存されることが保証されます。 
4. すべての K 値を前処理した後、複数のスキャン中に昇順に i を追加するため、すべての indices[K] リストはすでにソートされています。 
5. 各クエリ (L、R、K) について、間隔内にあるインデックス [K] の値の数を数えます。 リストはソートされているため、 lower_bound を使用して最初の位置 >= L を見つけ、upper_bound を使用して最初の位置 > R を見つけ、それらの位置を減算してカウントを取得します。 
6. このカウントをクエリごとに出力します。 

それが機能する理由は、条件の直接の等価変換に基づいています。 要件 K | gcd(h[i], i) は、gcd の両方の引数を K で割ったものと同等です。 これにより、実行時の計算から gcd が完全に削除されます。 前処理により、すべての有効なインデックス i が、i と h[i] の両方を分割する K 値のリストに正確に格納され、無効なインデックスが挿入されないことが保証されます。 インデックスは K ごとに昇順に挿入されるため、各リストはソートされたままになり、バイナリ検索範囲のカウントの正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    h = [0] + list(map(int, input().split()))

    indices = [[] for _ in range(n + 1)]

    for k in range(1, n + 1):
        for i in range(k, n + 1, k):
            if h[i] % k == 0:
                indices[k].append(i)

    for _ in range(q):
        l, r, k = map(int, input().split())
        if k > n:
            print(0)
            continue

        arr = indices[k]

        # binary search
        lo, hi = 0, len(arr)
        while lo < hi:
            mid = (lo + hi) // 2
            if arr[mid] >= l:
                hi = mid
            else:
                lo = mid + 1
        left = lo

        lo, hi = 0, len(arr)
        while lo < hi:
            mid = (lo + hi) // 2
            if arr[mid] > r:
                hi = mid
            else:
                lo = mid + 1
        right = lo

        print(right - left)

if __name__ == "__main__":
    solve()
```前処理ループは、核となる変換ステップです。 各インデックスを個別に処理するのではなく、除数構造によってインデックスをグループ化します。これにより、クエリ間での再利用が可能になります。 

二分探索は、外部ライブラリへの依存を回避し、境界条件を完全に制御するために手動で実装されます。 最初の検索では L 以上の最も古いインデックスが検索され、2 番目の検索では厳密に R より大きい最初のインデックスが検索されます。 

微妙な実装の詳細はガードです`if k > n`。 k が n を超える場合、インデックス i は k で割り切れる i を満たすことができないため、ルックアップをスキップすると不必要な作業が回避され、空の配列のエッジの動作が誤って解釈されるのを防ぎます。 

## 実用的な例

 n = 6、h = [2, 3, 6, 8, 12, 9]、およびクエリ (2, 6, 2) を考えてみましょう。 

2 の倍数をチェックしてインデックス [2] を構築します。 

| 私 | h[i] | i%2 | h[i] % 2 | 含まれています |
 | --- | --- | --- | --- | --- |
 | 2 | 3 | 0 | 1 | いいえ |
 | 4 | 8 | 0 | 0 | はい |
 | 6 | 9 | 0 | 1 | いいえ |

 したがって、インデックス[2] = [4]となります。 

クエリ (2, 6, 2) の場合、[4] 内の 2 ～ 6 の値を検索し、1 つの要素を生成します。 

ここで、別のクエリ (1, 5, 1) を考えてみましょう。 

k = 1 はすべてを除算するため、i と h[i] は両方とも 1 で割り切れるため、すべてのインデックスが有効になります。 

| 私 | インデックスに含まれています[1] |
 | --- | --- |
 | 1 | はい |
 | 2 | はい |
 | 3 | はい |
 | 4 | はい |
 | 5 | はい |
 | 6 | はい |

 1 から 5 までのすべてのインデックスが含まれるため、クエリ (1, 5, 1) は 5 を返します。 

これらの例では、前処理が割り算の制約を正しく捉えていること、および並べ替えられたリストの範囲カウントが期待どおりに動作することを確認しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + q log n) | 各 k は n/k の倍数を処理し、n | にわたる調和系列に合計します。 
| スペース | O(n log n) | 各インデックスは複数の除数リストに現れる可能性があります。 

各インデックスはその約数を介してのみアクセスされ、そのようなアクセスの総数は可算性の調和構造によって制限されるため、前処理コストは許容範囲内に収まります。 クエリ処理は、事前に計算された並べ替えられたリストに対する二分探索により対数処理され、大きな q に対しては十分効率的です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q = map(int, input().split())
    h = [0] + list(map(int, input().split()))
    indices = [[] for _ in range(n + 1)]

    for k in range(1, n + 1):
        for i in range(k, n + 1, k):
            if h[i] % k == 0:
                indices[k].append(i)

    out = []
    for _ in range(q):
        l, r, k = map(int, input().split())
        if k > n:
            out.append("0")
            continue
        arr = indices[k]

        lo, hi = 0, len(arr)
        while lo < hi:
            mid = (lo + hi) // 2
            if arr[mid] >= l:
                hi = mid
            else:
                lo = mid + 1
        left = lo

        lo, hi = 0, len(arr)
        while lo < hi:
            mid = (lo + hi) // 2
            if arr[mid] > r:
                hi = mid
            else:
                lo = mid + 1
        right = lo

        out.append(str(right - left))

    return "\n".join(out)

# minimum size
assert run("1 1\n5\n1 1 1") == "1"

# all equal values
assert run("5 2\n2 2 2 2 2\n1 5 2\n1 5 3") == "2\n0"

# boundary K > n
assert run("4 1\n1 2 3 4\n1 4 10") == "0"

# single valid index
assert run("5 1\n1 2 3 4 5\n2 5 2") == "2"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1、5、1 1 1 | 1 | 最小限の大文字と小文字の正確性 |
 | すべて 2 | 2 / 0 | 複数の K の動作 |
 | K > n | 0 | 範囲外の除数の処理 |
 | 混合 | 2 | 割り算によるフィルタリング |

 ## 特殊なケース

 K が n より大きい場合、前処理構造には有効なインデックスが含まれないため、クエリは配列をスキャンせずに正しく 0 を返します。 

K = 1 の場合、i と h[i] は両方とも常に 1 で割り切れるため、すべてのインデックスが有効になります。前処理ループには当然、すべてのインデックスが indices[1] に含まれるため、クエリは完全なインデックス リストに対する単純な範囲カウントに減ります。 

h[i] の値が K より小さい場合、h[i] % K はゼロにならないため、割り算チェックによって前処理中に自動的に除外されます。 これにより、インデックスが K の倍数である場合でも、誤った包含が防止されます。
