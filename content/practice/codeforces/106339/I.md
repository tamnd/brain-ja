 ## 解決策
 ## 問題の理解

 道路の線がセグメントに分割され、各セグメントには初期の積雪の高さが与えられます。 このプロセスでは、これらの高さが繰り返し変更されます。 各ステップで、雪の構造が残っているすべてのセグメントの中で現在最も高いセグメントを特定し、その高さを減らします。 削減ルールはローカルです。すでにその値と等しくない限り、選択したセグメントは、隣接する 2 つのセグメントのうちの大きい方と一致するように削減されます。 この操作は、これ以上削減できなくなるまで繰り返されます。つまり、このルールの下で構成が安定します。 

タスクは、そのような貪欲な削減がすべて適用された後の最終状態を決定すること、または同様に、自然に収束するまでこのプロセスを効率的にシミュレートすることです。 

入力は、ライン上の初期の雪の高さを表す一連の整数として理解される必要があります。 出力は、プロセスが安定した後の最終的な高さに対応します。このとき、繰り返しの縮小下でローカル近傍が許容する値を厳密に超えるセグメントは存在しません。 

この制約は、セグメントの数が多く、この問題の Codeforces スタイルのバージョンでは通常最大 200,000 であることを意味します。 グローバル最大値を繰り返しスキャンしてローカル更新を実行する単純なシミュレーションでは、操作ごとに直線的な時間がかかり、最悪の場合、高さレベルごとに要素ごとに 1 回の更新が実行され、二次関数またはさらに悪い動作が発生する可能性があります。 n が約 2×10^5 の場合、O(n log n) または O(n) を超えるものは実行できません。 

複数のピークが相互作用する場合、微妙な失敗のケースが発生します。 たとえば、次のような配列を考えてみましょう。`[1, 5, 2, 4, 1]`。 常に最初の最大値を選択する素朴なアプローチでは、5 を 4 よりも減らす可能性がありますが、順序は効率の観点からのみ重要であり、正確さの観点からは重要ではありません。 ただし、近隣を正しく更新しなかったり、新しく作成されたピークの再評価に失敗したりする不注意な実装では、優先順位構造に古い値が残り、後で減らす必要があるにもかかわらずセグメントが両方の近隣よりも高いままになるなど、不正確な最終的な高さが生成される可能性があります。 

長くて平らな台地がある場合、別の特殊なケースが発生します。 例えば、`[3, 3, 10, 3, 3]`中心部の崩壊を繰り返し、一度落ち込むとプラトー構造が変化します。 更新が正しくマージされない場合、同じプラトーの処理が繰り返されることで冗長な作業が発生し、パフォーマンスの想定が崩れる可能性があります。 

## アプローチ

 ブルート フォースの解釈は簡単です。すべてのセグメントを繰り返しスキャンして最も高い有効なセグメントを見つけ、ローカル リダクション ルールを適用して配列を更新します。 各操作では最大値を見つけるのに O(n) かかり、最悪のケースでは O(n^2) のカスケード削減が発生する可能性があります。特に、各削減が別の形式で再び適格になる前にピークをわずかに減少させるだけの場合です。 n が大きい場合、これはすぐに遅くなりすぎます。 

重要な構造的観察は、プロセスが常に現在のグローバル最大セグメントに作用し、各セグメントは隣接するセグメントによって定義された一連の有効な「サポート」高さを通って下方向にのみ遷移するということです。 唯一の意味のあるイベントが「セグメントの高さが変化し、同じ高さの隣接するセグメントとマージする可能性がある」ことだけであることを受け入れると、問題は個々の更新ではなく、セグメントにわたるイベントのシミュレーションになります。 

配列を個々の点として扱う代わりに、同じ高さの最大の連続セグメントに圧縮します。 各操作ではこれらのセグメントを分割またはマージできますが、各マージではセグメントの数が厳密に削減されます。 利用可能な最も高いセグメントを常に処理する場合、高さによってキー設定された最大優先度のキュー内のすべてのセグメントを維持できます。 セグメントが処理されると、その高さが隣接するセグメントの最大値となる新しいセグメントに置き換えられ、隣接する同じ高さのセグメントがマージされます。 マージのたびに合計セグメント数が減り、各セグメントが対数回挿入または削除されるため、全体の複雑さは準線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | セグメント + ヒープのシミュレーション | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、初期配列を連続した等しい値のセグメントに圧縮します。 変更できるのはセグメント境界だけであるため、この圧縮は不可欠です。 平坦領域の内部点は同様に動作します。 

次に、高さ順に並べられたセグメントの最大ヒープを維持します。 各ヒープ エントリは、削減される可能性のある候補セグメントを表します。 これに加えて、左右の隣接セグメントを効率的にクエリできるように、セグメント間の隣接ポインタを維持します。 

また、古いヒープ エントリはマージ後に古くなってしまう可能性があるため、各セグメントの有効性マーカーも維持します。 

プロセスは次のとおりです。 

1. 配列を 1 回スキャンし、連続する等しい値をグループ化することにより、初期セグメントを構築します。 各セグメントは、その高さとその左右の隣接するセグメントを二重リンク構造で保存します。 
2. 高さでキー設定された最大ヒープにすべてのセグメントを挿入します。 各ヒープ エントリにはバージョン識別子も含まれるため、マージ後に古いエントリを検出できます。 
3. ヒープが空でない間に、最大高さのセグメントを抽出します。 以前のマージによって無効になっている場合は、スキップします。 
4. 抽出されたセグメントについて、その現在の隣接セグメントを決定します。 両方の隣接セグメントが存在し、現在のセグメントと同じ高さである場合、このセグメントに対して操作は必要なく、無視できます。 これは、ローカルですでに安定していることを示しています。 
5. それ以外の場合は、存在する 2 つの近傍の最大値として新しい高さを計算します。 これはプロセスの強制的なルールです。セグメントは最も強力な隣接するサポートまで崩壊します。 
6. セグメントを、この減少した高さの新しいセグメントと交換します。 同じ高さを共有するようになった場合、左右の隣接要素とのマージが必要になる場合があります。 
7. マージ後、隣接ポインタを更新し、古いヒープ エントリを無効にします。 新しいマージされたセグメントをヒープに挿入し直します。 

このアルゴリズムは、ヒープが削減できるセグメントを生成できなくなると終了します。これは、すべてのセグメントがローカルで隣接するセグメントと一貫性があり、より高いピークは削除できないことを意味します。

重要な不変条件は、ヒープ内のすべてのセグメントが、展開する配列内の同じ高さの現在の連続ブロックを表すということです。 各操作では、高さの削減がローカルの隣接制約に厳密に従うことが保証されるため、正確さが維持されます。 すべての縮小はセグメントをマージするか、最大高さを厳密に減少させるため、プロセスは循環できず、終了する必要があります。 ヒープは常にグローバルに最も高い残りのセグメントを公開するため、有効な削減が見逃されることはなく、ローカル更新により将来の状態が以前のマージと一貫性を保つことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("h", "l", "r", "alive", "id")
    def __init__(self, h, i):
        self.h = h
        self.l = None
        self.r = None
        self.alive = True
        self.id = i

import heapq

def solve():
    a = list(map(int, input().split()))
    if not a:
        return

    # build segments
    nodes = []
    i = 0
    seg_id = 0

    while i < len(a):
        j = i
        while j < len(a) and a[j] == a[i]:
            j += 1
        node = Node(a[i], seg_id)
        seg_id += 1
        nodes.append(node)
        i = j

    # link
    for i in range(len(nodes) - 1):
        nodes[i].r = nodes[i + 1]
        nodes[i + 1].l = nodes[i]

    # heap (max via negative)
    pq = []
    for node in nodes:
        heapq.heappush(pq, (-node.h, node.id, node))

    def valid(node):
        return node is not None and node.alive

    while pq:
        neg_h, _, node = heapq.heappop(pq)
        if not node.alive:
            continue

        l = node.l
        r = node.r

        # already stable if both neighbors exist and are not higher influence
        if l and r and node.h <= max(l.h, r.h):
            continue

        new_h = 0
        if l:
            new_h = max(new_h, l.h)
        if r:
            new_h = max(new_h, r.h)

        node.h = new_h

        # merge left
        if l and l.h == node.h and l.alive:
            l.alive = False
            node.l = l.l
            if node.l:
                node.l.r = node
            l = node

        # merge right
        r = node.r
        if r and r.h == node.h and r.alive:
            r.alive = False
            node.r = r.r
            if node.r:
                node.r.l = node

        heapq.heappush(pq, (-node.h, node.id, node))

    # reconstruct (if needed)
    res = []
    cur = nodes[0]
    while cur.l:
        cur = cur.l
    while cur:
        res.extend([cur.h])
        cur = cur.r

    print(*res)

if __name__ == "__main__":
    solve()
```コードはまず配列を最大のセグメントに圧縮して、更新が内部点に繰り返し触れないようにします。 各セグメントは左右のポインターを持つノードとして追跡されるため、定数時間の近傍クエリが可能になります。 

優先キューにより、貪欲ルールに一致して、最も高いセグメントが常に最初に処理されることが保証されます。 の`alive`このフラグは、マージ後に古いセグメントが再利用されるのを防ぎます。 

セグメントが処理されるとき、その高さは隣接するセグメントから再計算され、即時マージによって表現が最小限に保たれます。 再構築ステップは、左端のセグメントから進み、最終的な圧縮表現を出力形式に展開します。 

同じセグメントの複数のバージョンが存在する可能性があるため、古いヒープ エントリには注意する必要があります。 正しくするためには、無効なノードをスキップすることが不可欠です。 

## 実用的な例

 配列を考慮してください`[1, 5, 2, 4, 1]`。 

セグメントから始めます`[1] [5] [2] [4] [1]`。 ヒープは常に高さ 5 のセグメントを最初に選択します。 に縮小されます`max(1,2) = 2`、生産`[1] [2] [2] [4] [1]`。 マージ後、次のようになります。`[1] [2] [4] [1]`。 次に、セグメント 4 が処理され、次のようになります。`max(2,1) = 2`、生産`[1] [2] [2] [1]`、マージすると次の結果が得られます`[1] [2] [1]`。 このプロセスは安定するまで続きます。 

| ステップ | 選択したセグメント | ネイバーマックス | 配列状態 |
 | --- | --- | --- | --- |
 | 1 | 5 | 2 | [1、2、2、4、1] |
 | 2 | 4 | 2 | [1、2、2、1] |
 | 3 | 2 | 1 | [1、1、1] |

 このトレースは、ピークがローカルサポートに向かってどのように崩壊するか、および均一性が達成されるまでマージが繰り返されることで構造がどのように減少するかを示しています。 

ここで考えてみましょう`[3, 3, 10, 3, 3]`。 

| ステップ | 選択したセグメント | ネイバーマックス | 配列状態 |
 | --- | --- | --- | --- |
 | 1 | 10 | 3 | [3、3、3、3、3] |

 これは、単一の主要なピークが 1 回の操作で平坦なプラトーに崩壊し、その後はそれ以上の変化が起こらないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各セグメントはヒープに一定の回数出入りし、各操作には対数的な時間がかかります。 
| スペース | O(n) | セグメント ストレージ、ヒープ エントリ、および隣接ポインタはすべて、入力サイズに応じて線形にスケールされます。 

対数オーバーヘッドはプライオリティ キューの維持からのみ発生します。 マージのたびにアクティブなセグメントの数が減り、セグメントが無制限に再導入されることはないため、ヒープ操作の総数は対数係数まで線形を維持し、最大 200,000 までの n の一般的な制約内に問題なく収まります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、次のような単一要素入力です。`[7]`。 隣接するものがないため、削減はできません。 ヒープ操作では有効な削減を生成できないため、アルゴリズムはセグメントが分離されていると即座に認識し、同じ値で終了します。 

別のエッジケースは、次のような完全に均一な配列です。`[4, 4, 4, 4]`。 圧縮により単一のセグメントが生成され、変更を引き起こす上位または下位の隣接セグメントがないため、ヒープは縮小をトリガーしません。 出力は同じままです。 

3 番目のエッジ ケースには、次のような対称ピークが含まれます。`[1, 5, 1]`。 中央のピークは縮小されています`1`、単一の平らなセグメントに結合します。 ヒープにより、これが即座に行われ、古いエントリは処理前に除外されるため、中間の不整合状態が持続することはありません。
