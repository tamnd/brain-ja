 ## 解決策
 ## 問題の理解

 ココア カップのコレクションが与えられ、それぞれが熱量に関連付けられています。 一定の速度で時間の経過とともに温度を均一に下げる冷却プロセスもあります。 重要な観察は、飲酒は瞬間的なものであるため、唯一の本当の制約は、カップを検討する時点までに、その温度が一貫した地球規模の冷却タイムラインの目標レベルまで低下していることを確認することです。 

各カップの冷却を個別に考えるのではなく、プロセスをグローバルに再解釈します。すべてのカップが同じ速度で冷却されるため、熱による相対的な順序は決して変わりません。 唯一意味のある量は最大初期熱量です。そのカップは、指定された目標しきい値に最後に到達するためです。 

このタスクは、一定の冷却速度を前提として、最も熱いカップが開始時の熱から必要なレベルまで冷却されるまでにどのくらいの時間がかかるかを決定することに帰着します。 

一般的な Codeforces 設定によって暗示される制約から、最大約 10^5 以上の値が予想されます。 これにより、カップごとの冷却の二次シミュレーションが即座に除外されます。 正しいソリューションは、テスト ケースごとに線形時間以上で実行する必要があり、理想的にはアレイ上の 1 回のパスで実行する必要があります。 

最大熱量がすでに必要なしきい値を下回っている場合、微妙なエッジ ケースが発生します。 このような状況では、冷却時間はまったく必要ありません。 除算を含む式をやみくもに計算する単純な実装では、負の時間または無意味な時間が生成される可能性があります。 

たとえば、最大熱量が 3 で、必要な熱量が 5 であるとします。すべてがすでに十分に冷えているため、正解は 0 です。 (cmax - h + d - 1) // d のような不用意な計算は負の値を生成しますが、これは時間の観点からは無効です。 

## アプローチ

 ブルートフォースアプローチでは、離散時間ステップにわたる冷却をシミュレートします。 各ステップで、すべてのカップの熱を冷却速度で下げ、すべてのカップが目標の状態に達したかどうかを確認します。 n 個のカップがあり、冷却の差が潜在的に大きい場合、O(n × t) 回の操作にまで低下する可能性があります。ここで、t は必要なタイム ステップ数です。 最悪の場合、n 値と heat 値の両方が大きい場合、これは実行できなくなります。 

重要な構造観察は、すべてのカップが時間の経過とともに同様に影響を受けるということです。 これは、個々の軌跡を追跡する必要がないことを意味します。 代わりに、最も遅い冷却カップが合計時間を決定するため、どのカップがボトルネックであるかを知る必要があるだけです。 

そのボトルネックは常に最大の初期熱を持つカップです。 1 杯おきに、より早く、または同時に閾値に到達します。 問題を 1 つの値に落とし込むと、計算は単純な算術式になります。最も熱いカップが目標を超えてどれだけの「過剰熱」を持っているかを計算し、冷却速度で割って切り上げます。これは、部分時間単位では依然としてフル ステップが必要であるためです。 

最大熱量がすでにしきい値を下回っている場合、冷却は必要ないため、所要時間はゼロになります。

 | ブルートフォースシミュレーション | O(n・t) | お(1) | 遅すぎる |
 | Max ベースの算術 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての発熱量を読み取り、その中の最大発熱量を特定します。 このステップでは、最終的な答えを決定できる可能性がある唯一のカップを分離します。 
2. ターゲットの熱閾値と冷却速度を読み取ります。 これら 2 つの値は、システムが目標状態に向かってどれだけ早く移行するかを定義します。 
3. 過剰な熱を cmax − h として計算します。 これは、最も熱いカップが必要なレベルをどれだけ超えているかを測定します。 
4. この超過値がゼロ以下の場合は、すぐに 0 を返します。 これは、すべてのカップがすでに要件を満たしているため、冷却が必要ない場合に対処します。 
5. それ以外の場合は、必要な完全冷却ステップの数を (excess + d − 1) // d として計算します。 これにより、天井分割が実行されるため、残りの冷却の一部がフルタイム単位で 1 つ消費されるようになります。 
6. この値を答えとして出力します。 

重要なアイデアは、すべてのカップは時間の経過とともに同様に進化するため、システムの実現可能性は最悪の開始位置によって完全に決定されるということです。 

### なぜ効果があるのか

 すべてのカップは同じ一定の割合で熱が減少するため、相対的な順序は決して変わりません。 初期熱が最大のカップが、指定されたしきい値に最後に到達したままになります。 このプロセスは、カップがターゲットに到達したときに正確に終了するため、合計時間は個々の冷却軌道によって完全に決まります。 天井分割は、部分的な進行に完全な単位時間を必要とする離散時間ステップを正確に考慮します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, input().split()))
    # Depending on formatting, assume:
    # first value is n, last two are h and d, middle are heats
    n = data[0]
    arr = data[1:1+n]
    h = data[1+n]
    d = data[2+n]

    cmax = max(arr)
    excess = cmax - h

    if excess <= 0:
        print(0)
    else:
        print((excess + d - 1) // d)

if __name__ == "__main__":
    solve()
```実装は、最大要素への削減の直後に続きます。 この解釈ではすべての値が単一行から消費されるため、唯一の微妙な点は入力解析を正しく処理することです。 重要な計算は天井除算であり、浮動小数点演算を回避するために標準の整数トリック (x + d − 1) // d を使用して実装されます。 

条件付き分岐により、最大熱量が既にしきい値を下回っている場合に発生する負の時間を出力することがなくなります。

import sys, io

def run(inp: str) -> str:

    import sys

 ## 特殊なケース

 すべてのカップがすでにしきい値以下の熱を持っている場合でも、最大値は依然として h を下回ります。 のような入力の場合`[2, 3, 1]`h = 5 の場合、計算された超過値は負になります。 アルゴリズムはこれを明示的にチェックし、すぐにゼロを返し、誤った負の時間値を防ぎます。 

単一のカップの場合、最大値はそのカップ自体であるため、解決策は直接の天井分割に減ります。 たとえば、熱`[11]`、h = 4、d = 3 は超過 7 を与え、3 つのステップを答え、直接シミュレーションと一致します。 

超過分が d で正確に割り切れる場合、上限公式は標準の割り算と同じように動作します。 たとえば、超過 6 と d 3 は正確に 2 ステップを生成し、完全な除算の場合には 1 ずつずれた補正が導入されないことを示しています。
