 ## 解決策
 ## 問題の理解

 私たちには、一連の労働者が雪だるま式に次々と処理する直線的な生産パイプラインが与えられています。 各ワーカーは 1 つの雪玉を処理するのに一定の時間を要し、すべての雪玉は完了する前にすべてのワーカーを順番に通過する必要があります。 

このタスクは、すべての雪玉を直接シミュレートすることではなく、指定された制限時間内に完全な雪玉がいくつ生成されるかを判断することです。 各雪玉はチェーン内を流れるのに時間を費やし、パイプラインがいっぱいになると、生産が定期的に行われます。 

入力は、チェーン内のすべてのワーカーの処理時間と制限時間で構成されます。 出力は、その時点までに生成された完成した雪玉の数です。 

素朴な解釈では、すべてのワーカーを通るすべての雪玉の動きをシミュレートすることを示唆していますが、ワーカーの数と期間の両方が大きい場合、これはすぐに実行不可能になります。 各雪玉を個別に追跡しようとすると、事実上、ワーカー数と雪玉の数を掛けたサイズのグリッドをシミュレートすることになり、最悪の場合は二次関数的に増加します。 

重要な制約の意味は、プロセスが厳密に線形で決定論的であるということです。これは、システムが最初の遅延の後に安定したリズムに落ち着くはずであることを示唆しています。 これにより、雪だるまごとのシミュレーションが不要になります。 

制限時間が最初の雪玉を生成するのに必要な時間よりも短い場合、微妙なエッジ ケースが発生します。 その場合、答えはゼロでなければなりません。 単純なシミュレーションを破るもう 1 つのケースは、パイプラインのブロックを考慮せずに、各ワーカーが一定の間隔で個別に雪玉を生成すると仮定することです。これは過剰カウントにつながります。 

## アプローチ

 直接シミュレーションでは、すべてのワーカーの中を移動する各雪玉を追跡します。 各雪玉について、ワーカーがいつ対応可能になるか、および前のワーカーが終了するかに基づいて、各段階での完了時間を更新します。 このアプローチはすべての依存関係を尊重するので正しいですが、時間単位が T でワーカーが n 個ある場合、操作の数は処理される状態の数に比例して増加し、最悪の場合は簡単に 10^10 に達する可能性があるため、遅すぎます。 

重要な洞察は、パイプラインがいっぱいになると、システムが雪玉間の個々の相互作用に応じて停止し、代わりに周期的なマシンのように動作するということです。 最初の雪だるま式では、すべてのワーカーで完全なレイテンシーが発生し、これが初期遅延を形成します。 その後、チェーン内で最も遅いワーカーが指定する一定の間隔で新しい雪だるまが完了します。これは、そのワーカーがボトルネックとなり、より速いワーカーによる出力の加速が妨げられるためです。 

これにより、プロセス全体が 2 つの量に減ります。 1 つ目は、最初の雪だるまが完了するまでの時間であり、すべてのワーカー時間の単純な合計です。 2 つ目は、完了間の一定の間隔であり、作業者の最大時間です。 これらが分かれば、制限時間内に何回完了するかを数えるのは単純な等差数列になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(T・n) | O(n) | 遅すぎる |
 | プレフィックスの合計 + ボトルネックの推論 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、作業者の時間から 2 つの基本的な値を計算します。 1 つ目は、1 つの雪玉がチェーン全体を通過するのに必要な合計時間であり、すべての処理時間の合計です。 これは、最初の雪玉の完成時間を表します。 

2 番目の値は、すべてのワーカーの最大処理時間です。 これはパイプラインの最も遅いステージを表すため、システムが安定した後に新しい雪だるまを出力できる頻度が決まります。

これら 2 つの値が分かれば、生産を一連の完了時間として解釈します。 最初の完了は合計に等しい時間に発生します。 後続のすべての完了は、ワーカーの最大時間に等しい追加の固定遅延の後に行われます。 

この構造では、指定された制限時間と最初の完了時間を比較します。 制限が小さい場合は、雪だるまが完成していないため、答えはゼロになります。 それ以外の場合は、最初の完了後の残り時間に完全な間隔がいくつ収まるかを計算し、最初の雪だるま式に 1 を追加します。 

### なぜ効果があるのか

 パイプラインは、単一のボトルネックを持つ線形システムのように動作します。 最初の雪だるまが終了する前に、すべてのワーカーが継続的にパイプラインを埋めるため、依存関係が重要になります。 その時点を過ぎると、すべてのワーカーが継続的にビジー状態になり、最も遅いワーカーが全体的なスループットを決定します。 より高速なステージはボトルネック ステージを待つだけであるため、他のワーカーは出力周波数を増やすことができません。 これにより、最初の遅延の後に完了時間が厳密な等差数列になり、カウント式が正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = input().strip().split()
    if not data:
        return
    n = int(data[0])
    a = list(map(int, data[1:]))

    if len(a) != n:
        a = []
        while len(a) < n:
            a.extend(map(int, input().split()))

    total = sum(a)
    bottleneck = max(a)

    t = int(input().strip())

    if t < total:
        print(0)
        return

    print((t - total) // bottleneck + 1)

if __name__ == "__main__":
    solve()
```この実装では、最初にワーカー時間を読み取り、入力が複数行にまたがる場合でも堅牢な解析を保証します。 合計時間は単純な合計として計算されますが、ボトルネックは最大スキャンを使用して計算されます。 

重要な決定点は、制限時間と最初の完了時間の比較です。 最初の雪だるまに時間が足りない場合は、すぐにゼロを返します。 それ以外の場合は、最初の完了時間を減算してタイムラインをシフトし、サイクル長で割って追加の完了が何回発生するかをカウントします。 

この除算は整数除算であり、残りの時間に完全な生産間隔がどれだけ収まるかを直接モデル化します。 最終的な答えには、最初の雪だるまが明示的に含まれています。 

## 実用的な例

 ### 例 1

 作業者の時間を考慮する`[1, 2, 3]`時間制限付き`t = 10`。 

合計とボトルネックを計算します。 

| ステップ | これまでの合計 | これまでのボトルネック |
 | --- | --- | --- |
 | 1を読んだ後 | 1 | 1 |
 | アフター2 | 3 | 2 |
 | アフター3 | 6 | 3 |

 したがって、最初の完了は時間 6 で発生し、サイクルは 3 になります。 

| 数量 | 値 |
 | --- | --- |
 | 最初の完了 | 6 |
 | サイクル | 3 |

 ここで、最初の完了後の残り時間を計算します: 10 − 6 = 4。これにより、4 // 3 = 1 個の追加の雪玉が許可されるため、合計は 2 になります。 

これは、パイプラインが初期化から定常状態の運用にどのように移行するかを示しています。 

### 例 2

 労働時間`[4, 4, 4]`、制限時間`t = 20`。 

| ステップ | 合計 | ボトルネック |
 | --- | --- | --- |
 | 結局のところ労働者 | 12 | 4 |

 最初の完了は 12 で、サイクルは 4 です。 

残り時間は 8 なので、8 // 4 = 2 回追加で完了します。 

合計は 3 つの雪玉で、時刻 12、16、20 に発生します。 

これは、すべてのワーカーが同一である場合の純粋な等差数列の動作を示しています。

 ## 特殊なケース

 制限時間がすべてのワーカー時間の合計より小さい場合、パイプラインは最初の雪だるまを完了していません。 入力用`3 5 6 7`と`t = 10`、合計は 18 であるため、正しい出力は 0 です。アルゴリズムは比較することによってこれを正しく処理します。`t < total`そしてすぐに戻ります。 

すべてのワーカーの処理時間が同一の場合、ボトルネックは各ワーカーの時間と等しくなり、システムは完全な周期プロデューサーになります。 のために`3 2 2 2`そして`t = 14`、合計は 6、サイクルは 2、次のようになります。`(14 − 6) // 2 + 1 = 5`。 これは、明示的な完了時間 6、8、10、12、14 と一致します。 

次のようなボトルネックが最初のワーカーである場合`3 10 1 1`と`t = 30`、システムは依然として最大ステージ遅延を尊重します。 合計は 12、ボトルネックは 10 であるため、完了は 12、22、32 で発生します。時間 30 まで、完了はちょうど 2 つあり、数式は正しく生成します。
