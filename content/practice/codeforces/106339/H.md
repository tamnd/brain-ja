 ## 解決策
 ## 問題の理解

 ラインに沿って利用可能な雪の量を表す非負の整数のシーケンスが与えられます。 タスクは、このシーケンスの 3 つの連続する部分または重複しない部分を選択し、s1 ≤ s2 ≤ s3 になるように並べ替えた後、そのサイズが s1、s2、および s3 で示される 3 つの雪玉に割り当てることです。 この制約は任意ではありません。構造は、中央の雪玉が最小の雪玉の少なくとも 2 倍、最大の雪玉が中央の雪玉の少なくとも 2 倍であるという成長条件を満たさなければなりません。 

根本的な問題は、単に任意の 3 つのセグメントを選択することではなく、配列の互いに素な範囲を使用しながら、これらの乗法制約を尊重する方法で、利用可能な雪を 3 つの部分に分割することです。 出力は、これらのルールに基づいて達成可能な最良の構成であり、通常は問題ステートメントにエンコードされた暗黙の目的に従って最適化されます。これは、倍加制約の下で実現可能性を最大化する有効な分割を見つけることになります。 

入力サイズは、最大約 100,000 要素の配列を意味します。 すべての 3 つのカット位置を直接試行するアプローチは、分割点上での 3 次または 2 次の動作を伴うため、すぐに遅すぎます。 2 つのカット位置にわたる O(n^2) スキャンでも、各チェックが線形であるか再計算が必要な場合は境界線になります。 

主要な構造上のエッジ ケースは、雪が不均一に分布している場合、貪欲な分割または局所的な分割が失敗することです。 たとえば、ほとんどの雪が早期に集中している場合、単純な試みでは有効な小さな s1 と s2 が形成されますが、わずかにずらした分割が成功したとしても、s3 ≥ 2s2 に対して不十分な残留質量が残る可能性があります。 逆に、s1 を大きくしすぎると、後で有効な構成が存在する場合でも、s2 ≥ 2s1 を満たすことができなくなる可能性があります。 

最小の失敗例は、[1, 1, 100, 100, 100] のような配列です。 単純な貪欲な分割では、s1 = 1、s2 = 1 を選択し、s3 = 300 を残す可能性があります。これは、異なるグループ化によって有効な配置が存在する場合でも、1 ≥ 2 が false であるため、s2 ≥ 2s1 に違反します。 

## アプローチ

 ブルートフォース手法では、2 つのカット ポイント i および j を固定し、セグメント [1..i]、[i+1..j]、[j+1..n] をすべての可能な順列で s1、s2、s3 に割り当てます。 各パーティションについて、セグメントの合計を計算し、それらを並べ替えた後に 2 倍化制約が維持されるかどうかを確認します。 これには (i, j) の O(n^2) 個の選択が必要で、セグメント合計の計算はプレフィックス合計を使用して O(1) で実行できるため、合計時間は O(n^2) になります。 ただし、制約によりセグメント サイズ間に単調な関係が強制されるため、問題の構造は任意のパーティションよりも制限的になります。 

重要な観察は、1 つの雪だるまの境界候補を固定すると、たとえば s1 がどこで終わるか、s3 が始まるかを決めると、残りの実現可能性チェックが単調になるということです。 セグメントのサイズを大きくすると、次のセグメントに必要なしきい値は予測可能な方向に移動します。 この単調性により、線形にスキャンするのではなく、セグメントのエンドポイントにわたる二分探索が可能になります。 

接頭辞の合計を利用して、任意のセグメントの合計を O(1) で計算できます。その後、固定分割点 l について、中間セグメントが 2 倍制約を満たすように次の境界 r を二分探索できます。 対称的な引数は 3 番目のセグメントに適用されます。 配列に沿って s1、s2、s3 の有効な順序が複数あるため、配列を逆にして同じロジックを再適用することによって、すべての順列を暗黙的に考慮します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | プレフィックス + 二分検索 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

任意の間隔の合計を一定時間で計算できるように、プレフィックスの合計を使用します。 次に、最初に選択したセグメントの終端を定義する境界 l の選択を繰り返します。 この l は、1 つの雪玉が終了し、次の雪玉が始まる候補場所を表します。 

各固定 l について、プレフィックス [1..l] を潜在的な雪だるまサイズとして扱い、[l+1..n] で有効な 2 番目の境界 r を検索します。 この 2 番目の境界の目的は、次のセグメントが最初のセグメントに対する 2 倍の制約を満たすのに十分な大きさであることを確認することです。 r が増加するとセグメントの合計が増加するため、実現可能性は r に関する単調な述語になります。 

r に対して二分探索を使用して、現在モデル化している雪だるま式順序に応じて、制約を満たす最小または最大の位置を見つけます。 r が固定されると、残りの接尾辞によって 3 番目の雪だるまが決定され、それが最終制約を満たすかどうかを確認します。 

この問題では s1、s2、s3 のすべての順列を考慮する必要があるため、すべての論理的な役割の割り当てに対して同じ手順を繰り返します。 6 つの順列を明示的に列挙する代わりに、配列を逆にすることで、「プレフィックスベース」と「サフィックスベース」の役割を交換し、対称的なケースを効果的にカバーできることがわかります。 

考えられるすべての l をスキャンし、r に二分探索を適用した後、有効な構成が存在するかどうかを追跡します。 

### なぜ効果があるのか

 正確さは、プレフィックス合計の単調な動作に依存します。 セグメント境界を延長しても、セグメントの合計が減少することはありません。 これにより、s2 ≥ 2s1 または s3 ≥ 2s2 のような制約が検索空間全体で単調な述語になることが保証されます。 ある r で構成が有効になると、それ以降のすべての拡張はその特定の不等式の方向に対して有効なままになります。これにより、まさに二分探索で遷移点を分離できるようになります。 l の反復と反転対称によってすべての役割がカバーされるため、有効なパーティションが失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    def get(l, r):
        return pref[r] - pref[l]

    def check(arr):
        n = len(arr)
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + arr[i]

        def seg(l, r):
            return pref[r] - pref[l]

        for l in range(1, n + 1):
            s1 = seg(0, l)
            
            lo, hi = l + 1, n - 1
            while lo <= hi:
                mid = (lo + hi) // 2
                s2 = seg(l, mid)
                s3 = seg(mid, n)

                if s2 >= 2 * s1:
                    hi = mid - 1
                else:
                    lo = mid + 1

            if lo < n:
                s2 = seg(l, lo)
                s3 = seg(lo, n)
                if s2 >= 2 * s1 and s3 >= 2 * s2:
                    return True

        return False

    if check(a) or check(a[::-1]):
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```この実装では、O(1) 範囲クエリのプレフィックス合計が構築されます。 の`check`関数は配列の 1 つの方向をテストしますが、逆の呼び出しは対称的な配置をカバーします。 

各プレフィックス エンドポイント l について、最初のセグメントの合計として s1 を計算します。 次に、2 番目のカット ポイントを二分探索します。 二分探索で使用される述語は最初の不等式を強制し、s2 が s1 に対して十分に大きいことを保証します。 候補の分割を見つけた後、s3 に関係する 2 番目の不等式を含む両方の制約を明示的に検証します。これは、その制約が正確な分割に依存するためです。 

制約の構造には方向性があるため、反転ステップは非常に重要です。 これがないと、有効な構成の半分しか到達できなくなります。 

## 実用的な例

 入力配列 [1、2、8、16、40] を考えてみましょう。 

まずプレフィックスの合計 [1, 3, 11, 27, 67] を計算します。 

l = 1、s1 = 1 の場合、r を二分探索します。 r = 2 から s2 = 2 が得られ、2 ≥ 2 が成立しないと仮定します。したがって、展開します。 r = 3、s2 = 10 で、有効になりました。 この場合、s3 = 56 となり、56 ≥ 20 を満たすため、この構成は機能します。 

| l | r (見つかった) | s1 | s2 | s3 | s2 ≧ 2s1 | s3 ≧ 2s2 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 3 | 1 | 10 | 56 | はい | はい |

 これは、初期の分割は失敗しますが、中央のセグメントをわずかに大きくすることで実現可能性が回復するケースを示しています。 

次に [5, 5, 5, 5] を考えてみましょう。 

任意の l について、s1 は、考えられる s2 および s3 に比べて急速に増大します。 バランスの取れた分割を選択した場合でも、倍加制約はすぐに失敗します。 

| l | r | s1 | s2 | s3 | 有効 |
 | --- | --- | --- | --- | --- | --- |
 | 2 | 3 | 10 | 5 | 5 | いいえ |

 これは、単調検索が無効なパーティションを誤って受け入れることなく、すべての可能性を正しく網羅していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 エッジ ケースの 1 つは、最初のセグメントが残りのセグメントに比べて極端に小さい場合であり、複数の有効な r 値が作成される可能性があります。 述語が単調なままであるため、二分探索はこれを正しく処理します。s2 がしきい値を超えると、r が大きくなっても有効なままであるため、最小の実現可能な境界を見逃すことはありません。 

もう 1 つのエッジ ケースは、最適な分割でサフィックスが頻繁に使用される場合です。そのため、配列を反転する必要があります。 入力 [100, 1, 1, 1, 1] の場合、正しい構成では、大きい値が s3 として最後に配置されます。 逆配列でアルゴリズムを実行すると、同等のプレフィックスベースの構造が明らかになり、同じ二分探索ロジックで実現可能性が特定されます。 

最後のエッジ ケースは、境界が l = n - 2 などの極端な位置にあるときに発生します。この場合、バイナリ検索空間は最小限ですが、アルゴリズムは特別なケーシングを必要とせずに、最後の 2 つのセグメントが制約を満たすかどうかを正しくチェックします。
