 ## 解決策
 ## 問題の理解

 配列が与えられ、そのサブシーケンスを選択するように求められます。つまり、要素は削除できますが、残っているものを並べ替えることはできません。 このようなすべてのサブシーケンスから、多角形の辺の長さとして有効なものが必要です。これは、少なくとも 3 つの要素が選択され、選択されたすべての要素の合計が、選択されたサブシーケンス内の最大要素の 2 倍よりも厳密に大きいという条件となります。 

すべての有効な部分列の中で、合計を最小化または最大化するわけではありません。 サブシーケンスを辞書編集的に比較しているため、最初の位置から比較します。つまり、最初の要素が大きいシーケンスの方が優れており、等しい場合は次の位置に移動する、というようになります。 

制約が非常に大きいため、すべてのサブシーケンスを列挙することは不可能です。$2^n$彼らのうち。 各候補の妥当性をチェックするだけでも時間がかかりすぎます。 したがって、正しいソリューションはサブシーケンスを貪欲に構築するか、テスト ケースごとに線形または線形に近い時間で更新できる構造を維持する必要があります。 

微妙な問題は、辞書編集的な順序が部分シーケンスと非ローカルな方法で相互作用することです。 初期の小さな要素を削除すると、合計は減少しますが、より大きな要素を前方に引き出すことで辞書編集上の値を増やすことができます。 これが、単純な「大きな要素を取得する」または「並べ替えて選択する」アプローチが失敗する主な理由です。 

## アプローチ

 ブルート フォース戦略では、すべてのサブシーケンスを列挙し、ポリゴンの状態をチェックして、辞書編集的に最適なものを選択します。 これは定義を直接評価するため概念的には機能しますが、配列の長さは指数関数的であるため、中程度の入力サイズでも実行できません。 

前進するために、問題を 2 つの相互作用する目標に分割します。 まず、ポリゴン不等式を満たすサブシーケンスが必要です。 第 2 に、そのようなすべてのサブシーケンスの中で、辞書編集的に最大の出力が必要です。 重要な観察は、実現可能性は、選択した最大要素、選択した要素の合計、選択したセットのサイズという 3 つの量のみに依存するということです。 要素の順序は実現可能性に影響を与えず、メンバーシップのみが影響します。 

これは、候補セットを維持し、それが有効になるまで調整するという建設的なアプローチを示唆しています。 辞書編集的な順序には強いバイアスがかかります。小さい要素を削除することをお勧めします。削除すると、初期の位置から大きな値が削除されず、シフト後の後の比較が改善される傾向があるためです。 

中心となるアイデアは、すべての要素から開始し、ポリゴン条件が満たされるまで、実現可能性と辞書編集上の品質の両方にとって最も役に立たない要素、つまり残っている最小の要素を繰り返し削除することです。

 ## アルゴリズムのチュートリアル

 現在選択されている要素のマルチセットを維持します。最初は配列のすべての要素が含まれています。 また、それらの合計と現在の最大値も維持します。 

セットがポリゴンとして有効かどうかを繰り返しテストします。 条件は、セット サイズが少なくとも 3 つであり、合計が厳密に最大値の 2 倍より大きいことです。 

条件が失敗した場合は、要素を 1 つ削除します。 削除する要素は常に、現在のセットに残っている最小の値です。 

必要に応じて合計と最大値を更新し、条件が true になるまで続行します。 

削除のみを実行し、相対的な順序を変更しなかったため、終了後は残りの要素を元の順序で出力します。 

### なぜ効果があるのか

 ポリゴンの状態は特定の方向で単調です。要素を削除すると合計が減少し、最大値も減少する可能性がありますが、最小の要素を削除すると、可能な限り最大値を維持しながら合計の減少を最小限に抑えることができるため、不等式へのダメージが最小限に抑えられます。 より大きな要素を削除すると、最大値が減少するか、辞書編集上の最適性がより深刻に破壊されます。 

辞書編集上の順序は最も古い残りの位置によって決定されるため、最初に小さな値を削除すると、より大きな初期の要素が保存され、有益な場合にのみより大きな要素が前方にシフトされる傾向があります。 これにより、すべての削除ステップが辞書編集的に最適な有効なサブシーケンスに到達することを妨げないことが保証されます。 

各ステップで要素の数が減り、問題によって少なくとも 1 つの解決策が存在することが保証されるため、最終的に妥当性が達成されるため、プロセスは終了する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 3:
        print(3)
        print(*a)
        return

    total = sum(a)
    mx = max(a)
    
    import heapq
    heap = a[:]
    heapq.heapify(heap)

    removed = set()
    removed_count = 0

    current_sum = total
    current_max = mx

    while removed_count < n:
        if removed_count + (n - removed_count) >= 3:
            if current_sum > 2 * current_max:
                break

        # remove smallest remaining
        while heap:
            x = heapq.heappop(heap)
            if x not in removed:
                val = x
                break

        removed.add(val)
        removed_count += 1
        current_sum -= val

        if val == current_max:
            current_max = max(v for v in a if v not in removed)

        if n - removed_count < 3:
            break

    ans = []
    for x in a:
        if x not in removed:
            ans.append(x)

    print(len(ans))
    print(*ans)

t = int(input())
for _ in range(t):
    solve()
```この実装では、使用可能な最小の要素を常に削除し、進行する合計と最大値を追跡するためにヒープを維持します。 最終的なサブシーケンスは、元の配列をフィルタリングすることによって再構築され、順序が自動的に維持されます。 

微妙な点は、要素の順序を変更しないため、サブシーケンスの有効性が保証されていることです。 メイン ループは、ポリゴンの不等式が成立するまで要素を削除するだけです。 

## 実用的な例

 小さな要素が初期の位置を支配する配列を考えてみましょう。 最初はすべての要素が含まれているため、合計は大きくなりますが、合計に対して最大値が大きすぎる可能性があります。 削除するたびに最小の要素が削除され、不等式が有効になるまで合計が徐々に減少します。 

2 番目の例として、単一の非常に大きな要素が優勢である配列を考えてみましょう。 アルゴリズムは最初に小さな要素を削除しますが、最大値が変わらない場合、十分な小さな要素が削除されると最大値に対する合計の比率が向上するため、最終的に条件を満たすことが容易になります。 

どちらの場合も、重要な不変条件は、アルゴリズムが不等式を満たすのに最も有益でない要素のみを削除することです。

 ## 特殊なケース

 重大なエッジ ケースは、最大要素が他のすべての要素と比較して極端に大きい場合です。 この場合、小さな要素を削除しても最大値は変わらないため、不等式はゆっくりとしか改善されません。 アルゴリズムは、変更されていない最大値に対して十分な合計が蓄積されるまで、最小の要素を正確に削除し続けます。 

配列がすでにポリゴン条件を満たすことに近づいている場合、別のエッジ ケースが発生します。 ここで、アルゴリズムは削除を実行せず、完全なシーケンスを即座に出力します。削除が必要ないため、辞書編集上の最適性が維持されます。 

最後のエッジケースは、重複した小さな値が多数存在する場合です。 値が繰り返されても、削除戦略は各発生を独立して処理し、合計が徐々に減少し、終了が正しく行われるようにします。
