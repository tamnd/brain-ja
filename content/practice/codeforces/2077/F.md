 ## 問題の理解

 2 つの配列が与えられています。`a`そして`b`、同じ長さの`n`、最大値までの非負の整数を含む`m`。 目標は、要素に対して最小限のインクリメント操作を実行することです。`a`または`b`結果のペアは`(a, b)`問題で定義された意味で「良好」になります: 2 つの異なるインデックスを選択する一連の操作の場合`i`そして`j`および非負の整数`x`、更新できます`c_i := c_i & x`そして`c_j := c_j | x`最終的に配列を変換する`c`配列に入れる`d`。 

簡単に言うと、これは、各ビットが`b`の構成から OR/AND 演算を介して到達可能である必要があります。`a`。 重要な洞察は、ペアの場合、`(c, d)`良く言えば配列`c`に設定されているすべてのビットを「カバー」できなければなりません`d`これらの AND/OR 演算を通じて。 に設定されているビットに対して`d`しかし、中にはありません`c`の何らかの要素を増やす必要があります。`c`そのビットが設定されるまで。 

入力では複数のテスト ケースが可能で、合計`n`そして`m`すべてのテストで 2·10^6 を超えない。 これは、`O(n·log m)`テストごとのアルゴリズムは許容されますが、二次関数は何でも可能です`n`または`m`遅すぎるでしょう。 

明らかではないエッジケースが発生するのは次の場合です。`a`そして`b`すべての要素にすでに同じビットがあります。 たとえば、次の場合`a = [0, 1, 2]`そして`b = [0, 1, 2]`、移動は必要ありません。 もう 1 つのエッジ ケースは、単一の要素が`b`要素が含まれていない上位ビットが設定されています`a`複数の増分なしで到達できます。たとえば、`a = [1, 1]`、`b = [8, 1]`。 増加する素朴なアプローチ`a`または`b`任意に最小の動きを見つけられない可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる可能な増分が考慮されます。`a`または`b`そして、結果のペアが適切かどうかをシミュレーションします。 数値は最大 2・10^6 に達する可能性があり、組み合わせの数は指数関数的に増加するため、これは明らかに非現実的です。 

重要な観察は、少しずつ推論することです。 の各要素について`b`、少なくとも 1 つの要素が必要です`a`そのビットは AND/OR 演算を介して変換でき、設定されているすべてのビットをカバーします。`b`。 これを達成するための最小限の方法は、いくつかの値を作成するために必要な最小の増分数を見つけることです。`a[i] | b[j] == b[j]`のすべての要素に対して`b`。 これにより、要素ごとに問題がチェックされるようになります。`a[i]`、そのために必要な最小増分はいくらですか?`a[i] | b[j]`等しい`b[j]`みんなのために`j`。 可能なターゲット マスクを反復処理することで、`a[i]`必要な増分を数えることで、最小の合計移動数を効率的に見つけることができます。 

したがって、最適な解決策は、AND/OR 演算を直接シミュレートすることを回避します。 代わりに、ビット単位のプロパティを利用して、1 つの要素を許可する最小の増分を見つけます。`a`の特定の要素をカバーする`b`。 これにより、問題は指数関数的な検索からビット操作による線形スキャンに軽減されます。

 ## アルゴリズムのチュートリアル

 1. テストケースごとに配列を読み取ります。`a`そして`b`そして最大要素を計算します`m`。 これは、最小増分を考慮する数値の範囲を定義するために使用されます。 
2. 変数を初期化する`min_moves`多数に。 これにより、必要な最小合計増分が保存されます。 
3. 潜在的なすべての増分を反復処理します。`x`から`0`に`m`追加できるもの`a[i]`。 それぞれについて`x`、どうかを確認してください`(a[i] + x) | b[j]`等しいことができます`b[j]`みんなのために`j`。 その場合、必要な移動数は、`x`必要な増分を加えたもの`b`ターゲットに合わせて。 
4. すべての全体にわたってグローバルミニマムを維持する`i`および可能な増分`x`。 
5. すべての可能性を確認した後、出力します。`min_moves`そのテストケースに対して。 

機能する理由: アルゴリズムは、各要素に対して次のことを保証します。`b`、少なくとも 1 つの要素が存在します。`a`OR 演算を通じてアクセスできます。 可能な増分を反復することにより、このビットごとのカバレッジを満たす最小の動きのセットが見つかることを保証します。これがまさに「良い」ペアを定義するものです。 リニア スキャンとビット単位の演算を組み合わせることにより、これより小さい手のセットは不可能であることが保証され、カウントされたすべての手が成功に貢献します。`(a, b)`良い。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        res = float('inf')
        # we try to find minimal increments for 'a'
        for add_a in range(m+1):
            # apply increment to all a[i]
            valid = True
            total_moves = add_a
            for i in range(n):
                if (a[i] + add_a) | b[i] != b[i]:
                    valid = False
                    break
            if valid:
                res = min(res, total_moves)
        print(res)

if __name__ == "__main__":
    solve()
```コードは複数のテスト ケースを読み取り、それぞれをループし、可能な増分を試行します。`a`。 増分ごとに、`(a[i] + add_a) | b[i] == b[i]`。 この条件がすべての要素に当てはまる場合、最小移動数が更新されます。 ループオーバー`0..m`不必要な AND/OR 演算をシミュレートすることなく、必要なすべての増分を確実に考慮します。
