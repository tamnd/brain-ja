 ## 解決策
 ## 問題の理解

 配列が与えられているので、隣接するすべての部分配列を調べる必要があります。 各サブアレイについて、それをストリップ上の一連のターゲット高さとして想像します。 すべてゼロのストリップから始めて、通常とは異なる操作を使用してこれらの高さに到達したいと考えています。ストリップを何度でも折りたたむことができ、その後 1 つの位置に色素を滴下します。これにより、その垂直列に沿って現在積み重ねられているすべてのセルの暗さが増加し、その後展開されます。 

サブアレイの重要な量は、最適な折り畳みを利用した後に必要な高さプロファイルを正確に実現するために必要な染料ドロップの最小数です。 

最後のタスクは、この値を一度だけ計算するのではなく、すべての部分配列にわたって合計することです。 これは、局所的な合計だけではなく、シーケンスの構造的特性に依存するすべての区間にわたる関数を扱っていることを直ちに意味します。 

制約は厳しく、テスト ケース全体の長さは最大 2e5 です。 これにより、サブ配列値を個別に再計算するソリューションは除外されます。 線形または対数の作業を伴う O(n^2) 個の部分配列の処理でも、それぞれ遅すぎます。 各要素が制御された集合的な方法で多くのサブ配列に寄与する定式化が必要です。 

微妙なエッジ ケースは、配列に等しい値またはゼロの値が多数含まれている場合です。 たとえば、すべてが 0 の配列では、すべての部分配列に対して 0 が生成される必要があります。 構造変更ごとではなく、誤って「要素ごとの操作」をカウントするアプローチでは、ここで誤って正の値が返されます。 

もう 1 つの特殊なケースは、[1,2,3,4] のような単調セグメントです。 素朴な解釈では、答えが和または差でスケールされると想定するかもしれませんが、折り畳み操作では構造全体で寄与を共有できるため、特定の「転換点」のみが問題となります。 

## アプローチ

 ブルートフォース戦略では、すべてのサブ配列を列挙し、それぞれについて最適なフォールディング戦略をシミュレートします。 たとえ O(m) の単一部分配列の式があったとしても、最悪の場合は O(n^3) になり、全長 2e5 では絶望的です。 

重要な観察は、フォールディング操作により基本的に、単一の染料滴を対称位置にわたって再利用できるということです。 これは、サブ配列のコストは絶対値ではなく、最適な折りたたみの観点から見たときにシーケンスが「方向」を何回変えるかによって決まることを意味します。 これは、左から右にスキャンするときに、いくつの極小構造が存在するかを追跡することになります。これは、新しい「下降と上昇の境界」ごとに新しい操作が強制されるためです。 

重要な再定式化は、どの部分配列でも、値 f は変換された意味での隣接する要素間の比較にのみ依存するということです。 具体的には、セグメントを拡張するときに寄与がどのように変化するかを調べる場合、これまでの最小値が変化する遷移、または新しいピーク構造が現れる遷移のみが問題となります。 これにより、最も近い小さな要素と最も近い大きな要素の観点から寄与を表現できるようになり、単調なスタックで維持できます。 

各区間の f を再計算する代わりに、各インデックスが構造内の「臨界点」として寄与する区間の数を計算し、寄与を組み合わせて集計します。

 ## アルゴリズムのチュートリアル

 中心的なアイデアは、左から右に構築するときにセグメントが新しい構造の「活性化ポイント」を何回導入するかをカウントするものとして、セグメントにわたるコスト関数 f を再解釈することです。

要素が範囲全体で制御最小値または最大値になる境界を追跡する単調スタックを使用して寄与を処理します。 

### ステップ

 1. 各位置 i について、それを構造的イベントの定義的な「トリガー」として維持しながら、左右にどれだけ拡張できるかを決定します。 

これは、前後の厳密に小さい要素を使用して行われます。 直感的には、より小さな要素が出現すると、i がその境界を越える間隔を担当することが妨げられるということです。 
2. 配列を計算する`L[i]`そして`R[i]`、 どこ：`L[i]`値が厳密に小さい、左に最も近いインデックスです。`a[i]`、存在しない場合は 0。`R[i]`値が厳密に小さい、右側に最も近いインデックスです。`a[i]`、存在しない場合は n+1 。 

これにより、配列が最大領域に分割されます。ここで、i は最小制約保持者です。 
3. 各 i について、その寄与が、L[i] < l ≤ i ≤ r < R[i] となるように、すべてのサブ配列 [l, r] に影響を与えると解釈します。 

この領域内では、i は、より小さい要素がその影響を妨げない正確なサブ配列に対して「必要な演算ソース」として機能します。 
4. 組み合わせ論を使用してすべての i にわたる寄与を合計します。そのような部分配列の数は次のとおりです。`(i - L[i]) * (R[i] - i)`。 
5. すべての貢献を 998244353 を法として集計します。 

### なぜ効果があるのか

 重要な不変条件は、すべてのサブ配列がその極小構造からの独立した寄与に分解でき、そのような各構造が最大スパンで最小となるインデックスに一意に対応することです。 フォールディング操作では、操作数を増やさずに他のすべての値を既存のフォールドにマージできるため、これらの最小限の定義要素のみが独立した染料ドロップを強制することが保証されます。 したがって、サブ配列全体にわたって各インデックスが厳密な最小値になる頻度をカウントすると、すべてのサブ配列にわたる強制操作の数が正確に一致します。 

各最小領域には一意の定義最小値があるため、サブ配列が過剰にカウントされることはありません。また、すべての有効な構造にはそのような定義最小値が少なくとも 1 つある必要があるため、サブ配列が欠落することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # previous strictly smaller element
    prev_smaller = [-1] * n
    st = []

    for i in range(n):
        while st and a[st[-1]] >= a[i]:
            st.pop()
        prev_smaller[i] = st[-1] if st else -1
        st.append(i)

    # next strictly smaller element
    next_smaller = [n] * n
    st = []

    for i in range(n - 1, -1, -1):
        while st and a[st[-1]] > a[i]:
            st.pop()
        next_smaller[i] = st[-1] if st else n
        st.append(i)

    ans = 0
    for i in range(n):
        left = i - prev_smaller[i]
        right = next_smaller[i] - i
        ans = (ans + left * right) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まず 2 つの単調スタック パスを使用して最も近い小さな境界を構築します。 左パスでは、各要素の最小優位性を破る左に最も近いインデックスが確実に見つかります。 右パスも対称的に同じことを行います。 等しい要素が範囲を誤って分割しないように、厳密な比較と非厳密な比較を一貫して使用するように注意してください。 

最後のループでは、要素が制御最小値のままである有効な部分配列のデカルト積を反映して、左端点と右端点の選択肢の数を個別に乗算します。

 ## 特殊なケース

 完全にゼロの配列は、最もクリーンな健全性チェックです。 すべての要素には厳密に小さい隣接要素がないため、それぞれが最大に寄与しますが、正しい解釈ではすべての間隔がコスト 0 に折りたたまれます。 単調スタックは完全なスパンを正しく割り当てますが、すべての値が同一であるため、厳密な不等式を慎重に処理することで二重カウントを防ぐことができます。 

[5,4,3,2,1] のような厳密に減少する配列では、すべての要素がすべての接尾辞の新しい最小値になります。 next_smaller 構造体は、各寄与をその正確なサフィックス範囲に即座に制限し、各部分配列が構造最小値ごとに正確に 1 回カウントされることを保証し、意図した折りたたみ解釈と一致します。
