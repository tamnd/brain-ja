 ## 解決策
 ## 問題の理解

 文字列のすべての文字は、次のいずれかに影響します。`+1`または`-1`。 

定義すると$$w(c)= \begin{cases} +1,&c='1'\\ -1,&c='0' \end{cases}$$次に、バイナリ文字列の任意のセグメントに対して、関数$F$は、そのセグメントにわたるこれらの値の単純な合計です。 

バイナリ文字列の場合$v$、 させて$$d=\#1-\#0$$完全に不均衡になります。 

のスコア$v$文字列をプレフィックスとサフィックスに分割し、最大化することで取得されます。$$F(\text{prefix})\cdot F(\text{suffix}).$$バイナリ文字列が与えられます$s$。 反転操作のたびに、現在の文字列の空でないすべてのサブシーケンスのスコアの合計を計算する必要があります。 

制約から最初に観察されるのは、文字列の長さとクエリの数がそれぞれ次の値に達する可能性があるということです。$2\cdot 10^5$、すべてのテスト ケースの合計も$2\cdot 10^5$。 サブシーケンスを明示的に調べる解決策は、次のような長さの文字列であるため不可能です。$2\cdot 10^5$もっている$2^{200000}$後続。 たとえ$O(n)$クエリごとの再計算はコストがかかりすぎます。$O(nq)$。 

答えは、フリップ後に更新できる非常に少量の情報にのみ依存する必要があります。 

微妙なエッジケースは、長さ 1 のサブシーケンスです。 

例えば：```
v = "1"
```唯一可能なスプリットは空のサイドを使用するため、スコアは次のようになります。$0$。 両側が空ではないと仮定した導出では、誤って正の値が得られます。 

もう 1 つの簡単な間違いは、パリティを正しく処理しないことです。 

のために```
v = "111"
```我々は持っています$d=3$。 スコアはそうではありません$d^2/4=9/4$。 実際の答えは$$\left\lfloor \frac d2\right\rfloor \left\lceil \frac d2\right\rceil = 1\cdot2 = 2.$$パリティ補正は、ソリューション全体の重要なステップです。 

3 番目のトラップは空のサブシーケンスです。 この問題では空ではないサブシーケンスが求められますが、最終的な式では当然すべてのサブシーケンスがカウントされます。 幸いなことに、空のサブシーケンスには不均衡があります$0$そしてスコア$0$, したがって、それを含めても何も変わりません。 

## アプローチ

 ブルートフォースソリューションでは、すべてのサブシーケンスを列挙し、その不均衡を計算し、そのスコアを決定し、その結果を加算します。 

For a string of length$n$、これは調べる必要があります$2^n$後続。 たとえ$n=60$、それはすでに実現可能性をはるかに超えています。 と$n=2\cdot10^5$、それはまったく不可能です。 

重要な観察は、サブシーケンスのスコアはその不均衡のみに依存するということです。$$d=\#1-\#0.$$サブシーケンス内の文字の順序には依存しません。 

サブシーケンスに不均衡があると仮定します$d$。 選択したプレフィックスの不均衡を次のようにします。$x$。 この場合、接尾辞の不均衡は次のようになります。$d-x$、したがって、分割ごとに次の結果が生成されます。$$x(d-x).$$この 2 次式は、2 つの部分が可能な限り近づくと最大化されます。 最大値は、$$\left\lfloor \frac d2\right\rfloor \left\lceil \frac d2\right\rceil = \frac{d^2-(d\bmod 2)}4.$$ここで問題は次のようになります。$$\sum_{\text{subsequence}} \frac{d^2-(d\bmod2)}4.$$その後の順序は完全に消えました。 

させて$R$現在の文字列内の 1 の数になります。 その後、すべてのクエリは変更されるだけです$R$による$\pm1$。 

残りのタスクは、次の合計を計算することです。$d^2$すべてのサブシーケンスにわたってパリティ補正を減算します。 一様にランダムな部分列の確率的解釈を使用すると、両方の量が閉じた形式を許容します。 単純化すると、答えは次の条件のみに依存します。$n$そして$R$:$$\boxed{ 2^{\,n-4} \left((2R-n)^2+n-2\right) } \pmod{998244353}.$$以来$n$決して変化せず、フリップのみが変化します$R$、各クエリは次のように答えることができます。$O(1)$。 

この式の導出については次のセクションで説明します。

 | 最適 |$O(1)$クエリごと |$O(n)$文字列の場合 | 承認済み |

 ## アルゴリズムのチュートリアル

 ### スコア計算式の導出

 しましょう$$d=\#1-\#0.$$プレフィックスの不均衡が次のようなスプリットの場合$x$、$$\text{value}=x(d-x).$$この放物線は次のときに最大になります。$x$に最も近い$d/2$。 

したがって、$$\text{score}(v) = \left\lfloor\frac d2\right\rfloor \left\lceil\frac d2\right\rceil = \frac{d^2-(d\bmod2)}4.$$### すべてのサブシーケンスの合計を求める

 すべてのサブシーケンスを、各位置が含まれるかどうかを独立して選択するものとして解釈します。 

確率変数を定義します。$$X_i= \begin{cases} 1,&s_i=1\text{ and chosen}\\ -1,&s_i=0\text{ and chosen}\\ 0,&\text{otherwise} \end{cases}$$それから$$d=\sum_i X_i.$$させて$R$1の数になり、$Z=n-R$。 

我々は持っています$$E[d] = \frac{R-Z}{2} = \frac{2R-n}{2}.$$また$$\operatorname{Var}(X_i)=\frac14,$$それで$$\operatorname{Var}(d) = \frac n4.$$したがって$$E[d^2] = \operatorname{Var}(d)+E[d]^2 = \frac{(2R-n)^2+n}{4}.$$あるので$2^n$サブシーケンス、$$\sum d^2 = 2^nE[d^2] = 2^{n-2}\big((2R-n)^2+n\big).$$スコアには以下が含まれます$$\frac{d^2-(d\bmod2)}4.$$パリティ補正は残ります。 

サブシーケンスの長さが奇数の場合、まさにその不均衡が奇数になります。 すべてのサブシーケンスのちょうど半分が奇数の長さです。$$2^{n-1}.$$したがって$$\sum (d\bmod2) = 2^{n-1}.$$すべてをまとめると:$$\text{Answer} = \frac14 \left( 2^{n-2}\big((2R-n)^2+n\big) - 2^{n-1} \right).$$因数分解後:$$\boxed{ 2^{n-4} \left( (2R-n)^2+n-2 \right) }.$$### 更新を処理しています

 1. 現在の 1 の数を数えます$R$。 
2. 2 のべき乗モジュロを事前計算する$998244353$。 
3. クエリごとに、選択した文字を反転します。 
4.アップデート$R$による$+1$または$-1$。 
5. コンピューティング$$x=2R-n.$$1. 出力$$2^{n-4}(x^2+n-2) \pmod{998244353}.$$のために$n<4$、要因$2^{n-4}$モジュロで解釈される$998244353$モジュラー逆関数を使用する$2$。 

### なぜ効果があるのか

 重要な不変条件は、すべての部分列がその不均衡によってのみ寄与するということです。$d$。 スコアが次のように書き換えられると、$$\frac{d^2-(d\bmod2)}4,$$サブシーケンスに関するすべての構造情報が消えます。 

の合計$d^2$すべてのサブシーケンスにわたる確率は、ランダムな不均衡変数の最初の 2 つのモーメントによって完全に決定されます。 パリティ補正は、奇数の不均衡を持つサブシーケンスの数 (奇数長のサブシーケンスの数に等しい) にのみ依存します。 両方の量は次のもののみに依存します$n$そして現在の 1 の数$R$。 

すべてのクエリは変更のみを行います$R$したがって、更新後に閉じたフォームを評価します$R$必要な合計を正確に生成します。 

導出はスコア定義から直接続き、すべてのサブシーケンスを正確に 1 回カウントするため、正確さが証明されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAXN = 200000

pow2 = [1] * (MAXN + 1)
for i in range(1, MAXN + 1):
    pow2[i] = pow2[i - 1] * 2 % MOD

inv2 = (MOD + 1) // 2

def power_two_shift(n):
    if n >= 4:
        return pow2[n - 4]
    return pow(inv2, 4 - n, MOD)

t = int(input())

for _ in range(t):
    n, q = map(int, input().split())
    s = list(input().strip())

    ones = s.count('1')
    coef = power_two_shift(n)

    for _ in range(q):
        pos = int(input()) - 1

        if s[pos] == '1':
            s[pos] = '0'
            ones -= 1
        else:
            s[pos] = '1'
            ones += 1

        x = 2 * ones - n
        ans = coef * ((x * x + n - 2) % MOD)
        ans %= MOD

        print(ans)
```実装は数式を直接反映しています。 

値$2^{n-4}$特別な注意が必要な場合$n<4$。 モジュラー算術では、これは次のべき乗を乗算することを意味します。$2^{-1}$したがって、コードは 2 の逆モジュラーを使用します。 

係数は以下にのみ依存します。$n$、テスト ケース内では決して変更されないため、一度計算されます。 

各フリップは一定時間内に 1 の数を更新します。 すべてのクエリの後に文字列全体を再カウントすると、複雑さが次のように増加します。$O(nq)$、これは不要です。 

表現$(2R-n)^2$Python の整数に簡単に適合するため、オーバーフローの心配はありません。
