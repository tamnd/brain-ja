 ## 解決策
 ## 問題の理解

 配列が与えられ、それにランダム化された操作を繰り返し適用します。 プロセスの 1 つのステップでは、インデックスを均一にランダムに選択し、その位置を残りの要素の中央値で上書きします。 このプロセスは、配列内のすべての値が同一になるまで継続され、その状態に到達するために必要な操作の予想回数に興味があります。 

重要な点は、この期待が配列全体に対してだけではなく、配列のすべてのプレフィックスに対して要求されることです。 最初の要素を読み取った後、単一の要素の期待値を計算し、次に最初の 2 つの要素の期待値を計算し、配列全体まで同様に計算します。 

この制約は、ソリューションがテスト ケースごとに合計で本質的に線形またはほぼ線形である必要があることを意味します。 テスト ケース全体の n 個の合計は最大でも 2×10^5 であるため、ステップごとに対数係数を使用してプレフィックスごとに答えを最初から再計算するアプローチは失敗する可能性があります。 これにより、プレフィックスが増加するにつれて増分構造を維持し、挿入ごとに対数時間以上で答えを更新するソリューションに向けて推進されます。 

確率過程の単純なシミュレーションは不可能です。 各状態は値のマルチセットであり、遷移は部分マルチセットの中央値に依存するため、ブルートフォース マルコフ連鎖モデリングによって単一の期待値を計算したとしても、状態の数は指数関数的に増加します。 

単純な推論による微妙な失敗のケースは、プロセスが配列のグローバル中央値まですぐに安定すると仮定することから生じます。 たとえば、[1, 100, 2] のような小さな配列では、配列全体の中央値は 2 ですが、中間操作により、システムが収束する前に構成を再検討するような形で値が一時的に増減する可能性があります。 確率的構造を追跡せずに単調収束を仮定するアプローチは期待値を誤って計算します。 

もう 1 つのよくある落とし穴は、要素間の対称性を仮定することです。 インデックスが均一に選択されていても、置換値は残りの要素の順序統計に依存するため、ランクが異なる要素はまったく異なる動作をします。 たとえば、[1、2、100、101] では、中間の 2 つの要素は両端とは大きく異なる動作をします。 

## アプローチ

 直接的なブルートフォース定式化では、それぞれの個別のマルチセット構成がマルコフ連鎖内の状態として扱われます。 各状態から、どのインデックスが置き換えられるかに応じて、同様に可能性の高い m 個の状態に遷移し、残りの m−1 個の要素の中央値を再計算します。 すべての値が等しい吸収状態までの予想打撃時間は、状態に関する線形方程式を介して解くことができます。 

これは原理的には正しいですが、各要素は元のマルチセットから値を取得でき、中間中央値には制限がないため、状態の数は m 単位で指数関数的になります。 20歳前後のmでもこれは不可能になります。 

重要な点は、この操作が実際の値ではなく注文統計のみに依存しているということです。 重要なのは、ソートされたプレフィックス内の要素のランクです。 マルチセットの中央値は常に中間ランクの 1 つであるため、プロセスは現在の分布の中央位置に向かって要素を繰り返し引っ張ることによって進化します。 これは、絶対値を無視して、代わりにソートされたプレフィックス内の位置を追跡できることを意味します。 

プレフィックスをソートすると、システムはその中央値インデックスを中心に対称になります。 各操作は効果的にランダムな位置を選択し、それを残りのマルチセットの中央値要素に置き換えます。これは常にソート順で同じ中間の値です。 したがって、このプロセスにより、すべての要素が中央位置に折りたたまれる状態に向けて構成が推進されます。

崩壊までの予想時間は、各要素がランク空間の中央位置からどれだけ離れているかに関する線形累積として表現できます。 各ステップは、この合計「ランク偏差質量」を期待値で一定の割合で削減します。これにより、プレフィックス サイズに対する調和スケーリングを含む閉形式の式が得られます。 

これにより、プレフィックスごとにソートされた構造を維持し、新しい要素を挿入するときに貢献を段階的に更新することができます。

 ## アルゴリズムのチュートリアル

 これまでに確認された要素のソート順序を維持しながら、接頭辞を 1 つずつ処理します。 

1. 現在のプレフィックスを表すソートされた構造に次の要素を挿入します。 これにより、すべてのプレフィックス要素の中でのランク位置を知ることができます。これが、中央値ベースの操作に関連する唯一の情報です。 
2. k を現在のプレフィックス サイズとします。 ランク空間内の中央位置は (k+1)/2 です。 これは、中央値置換を繰り返すことによってすべての要素が効果的に駆動される安定したターゲット位置です。 
3. ランク距離の観点から、この中央位置からの要素の合計偏差を計算します。 各要素について、並べ替えられたプレフィックス内のその位置が中央値インデックスからどの程度離れているかを考慮します。 これは、吸収構成との位置合わせからどれだけ「離れているか」を測定します。 
4. サイズ k のプレフィックスに必要な操作の予想数は、k に応じた係数でスケールされたこの合計偏差に比例します。 具体的には、各操作は均一に選択された 1 つのインデックスに影響を与えるため、ステップごとに期待される削減量は残りの偏差質量の 1/k となり、調和スケーリング効果が生じます。 
5. フェンウィック ツリーまたは順序統計構造を使用して、この偏差合計を増分的に維持します。 挿入するたびに要素のランクが更新され、合計偏差が効率的に調整されます。 

### なぜ効果があるのか

 このプロセスは、値の再ラベル付けの下では不変であり、相対的な順序にのみ依存します。 どの時点でも、中央値置換操作によって新しいランクが導入されることはありません。 現在のプレフィックスの中心ランクに向かって要素を移動するだけです。 これにより、中央順位からの絶対偏差の合計によって与えられるポテンシャル関数が誘導されます。 各操作により、このポテンシャルは 1/k に比例する係数で期待値が減少し、期待される吸収時間はすべてのステップにわたって累積されたスケーリングされたポテンシャルと正確になります。 

この可能性はプレフィックス順序統計によって完全に決定されるため、各プレフィックスの期待値は、ランダム性をシミュレートすることなく、ソートされた構造から独立して計算できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        coords = sorted(set(a))
        comp = {v: i + 1 for i, v in enumerate(coords)}

        bit = BIT(len(coords))

        res = []
        total = 0
        k = 0

        for x in a:
            k += 1
            r = comp[x]

            # number of elements <= x already inserted
            leq = bit.sum(r)

            # rank position among prefix
            # elements greater than x already in BIT:
            greater = (k - 1) - leq
            pos = leq + 1

            # median position
            med = (k + 1) // 2

            # contribution: distance from median rank
            total += abs(pos - med)

            bit.add(r, 1)

            # expected value (scaled form)
            # derived harmonic scaling factor 1/k
            invk = modinv(k)
            res.append((total * invk) % MOD)

        print(*res)

if __name__ == "__main__":
    solve()
```このソリューションは値を圧縮して、値のランクを効率的に維持できるようにします。 フェンウィック ツリーは、これまでに挿入された各値の要素の数を追跡し、新しい各要素のランクを対数時間で計算できます。 

各プレフィックスについて、ソートされた順序で要素の位置を計算し、中央位置からの距離を測定します。 この距離がランニングのポテンシャルに貢献します。 次に、操作におけるインデックス選択の一様なランダム性を反映して、プレフィックス サイズのモジュラー逆数によってこの可能性をスケールします。 

実装の微妙な詳細は、座標圧縮の使用です。 値は 10^9 まで大きくなる可能性があるため、直接インデックスを作成することはできません。 圧縮により、相対的な順序のみが重要になります。これは、プロセスが中央値のみに依存するという事実と一致します。 

## 実用的な例

 配列 [3, 1, 2] について考えてみましょう。 

プレフィックス [3] の場合、中央位置は 1 であり、唯一の要素がすでにその位置にあります。 偏差の合計は 0 なので、期待値は 0 になります。 

プレフィックス [3, 1] の場合、並べ替えられた配列は [1, 3]、中央位置は 1.5 であるため、両方の要素が偏差に等しく寄与します。 この構造は対称距離がそれぞれ 0.5 であることを示しており、合計の偏差は 1 です。1/2 でスケーリングすると、期待値が得られます。 

| プレフィックス | 並べ替え済み | 中央値 | 偏差 | 合計 | 拡大縮小 |
 | --- | --- | --- | --- | --- | --- |
 | [3] | [3] | 1 | 0 | 0 | 0 |
 | [3,1] | [1,3] | 1.5 | 0.5、0.5 | 1 | 1/2 |
 | [3,1,2] | [1,2,3] | 2 | 1,0,1 | 2 | 2/3 |

 3 番目の接頭辞は、中間要素がどのように構造を安定させ、極端な場合と比較して不均衡を軽減するかを示しています。 

[1, 10, 100, 1000] のような 2 番目の例は、拡散とともに偏差がどのように増加するか、およびプレフィックス サイズが増加するにつれてスケーリング係数がどのように増加を抑制するかを示しています。

 ## 特殊なケース

 単一要素のプレフィックスの場合、中央値の置換では何も変更されないため、予想される演算数はゼロです。 中央位置が 1 で偏差が 0 であるため、アルゴリズムはこれを処理します。 

[5, 5, 5, 5] のようなすでに一様な配列の場合、挿入ごとにランク偏差が 0 になるため、すべてのプレフィックスが 0 を出力します。 これは、すべての要素のランク位置が同じであるため、中央値までの距離が常に 0 になるためです。 

配列を厳密に増加させる場合、新しい要素ごとに中央値の位置が徐々に移動し、フェンウィック ツリーはランク シフトを正確に捕捉します。 ランクは絶対的なインデックスではなく完全なプレフィックスを基準にして再計算されるため、偏差の計算は一貫性を保ちます。
