 ## 解決策
 ## 問題の理解

 私たちは敵の位置と観察者の位置を数直線上で与えられます。 各観察者について、私たちは自分たちから特定の距離範囲内にある敵を気にします。 

位置にある各観察者`b`2 つの半径を定義します。 最大でも遠くにいる敵`L`交戦するには近すぎると見なされ、敵はせいぜい距離にあります`R`が見える。 このタスクは、観察者からの距離が厳密に以下の敵にのみ関係します。`L`そしてせいぜい`R`。 各観測者に対して、この距離範囲内に入る敵の数と、観測者までの距離の合計という 2 つの値を報告する必要があります。 

重要な問題は、両方とも`n`そして`q`最大 200,000 に達する可能性があるため、すべてのオブザーバーに対してすべての敵をチェックするソリューションは遅すぎます。 二重ループでは、最悪の場合でも約 4e10 回の距離チェックが実行されますが、これは Python の 2 秒の実行時間の制限をはるかに超えています。 

条件の構造も重要です。 各クエリは絶対距離のみに依存し、絶対距離は各観測者の周囲の 2 つの独立した領域 (左側の敵と右側の敵) に自然に分割されます。 単純な間違いは、間隔をインデックス空間内の単一の連続した範囲として扱おうとすることです。これは、変換が次のように行われるため失敗します。`|a - b|`対称的であり、分割しないと順序が保持されません。 

微妙なエッジケースが現れるのは、`L = 0`。 その場合、観測者の位置に居る敵は射程内であっても除外されます。`R`。 もう一つのケースは、敵がすべて外にいる場合です。`R`、答えがあるはずです`0 0`、プレフィックス合計ベースのソリューションでは、無効な範囲へのアクセスを回避する必要があります。 

## アプローチ

 直接的なアプローチでは、すべての敵をスキャンし、距離を計算することで、各監視者を個別に評価します。 これは文字通り定義に従っているため、正しいです。つまり、敵ごとに、`|a[i] - b[j]|`それが次の場所にあるかどうかを確認します`(L, R]`、その場合はカウントと合計を累積します。 問題は、これが実行されることです`n * q`距離の計算。 どちらも最大 200,000 件なので、400 億件の操作が必要となり、時間内に完了することはできません。 

状態の構造は別の観点を示唆しています。 距離の観点から考える代わりに、制約を数直線に置き換えることができます。 不平等`L < |a - b| ≤ R`は 2 つの互いに素なセグメントに相当します。`[b - R, b - L)`左側と`(b + L, b + R]`右側にあります。 これにより、絶対値が完全に削除され、問題は静的にソートされた配列の範囲カウントに軽減されます。 

敵の位置が分類されたら、二分探索を使用して、任意の間隔内に何人が横たわっているかを答えることができます。 距離の合計を効率的に計算するために、ソートされた位置にわたってプレフィックス合計配列を維持します。 これにより、任意のセグメントにわたる合計の定数時間計算が可能になり、各クエリを対数の境界検索と定数演算に変換します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | ソート + 二分検索 + 接頭辞の合計 | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 最初に敵の位置の配列を並べ替えて、線上の連続するセグメントを推論できるようにします。 並べ替えは、幾何学的距離制約を間隔クエリに変換する重要な変換です。 

次に、ソートされた位置に対してプレフィックス合計配列を構築します。 これにより、境界を見つけた後、一定時間内に部分配列の合計を計算できます。 

ウォッチャーポジションごとに`b`、条件を翻訳します`L < |a - b| ≤ R`並べ替えられた軸上の 2 つの間隔に分割されます。 左側の間隔はすべて敵です`[b - R, b - L)`、そして適切な間隔はすべての敵です`(b + L, b + R]`。 両方を独立してクエリします。 

区間ごとに、二分探索を使用して、要素が少なくとも左側の境界にある最初のインデックスと、要素が右側の境界を超える最初のインデックスを見つけます。 これにより、ソートされた配列内に連続したセグメントが得られます。 

プレフィックス合計配列を使用して、各セグメントの値のカウントと合計の両方を計算します。 ただし、必要な出力は座標の合計ではなく距離の合計であるため、それに応じて変換します。 右側の区間の場合、各寄与は次のようになります。`a[i] - b`、合計は`sum(a[i]) - count * b`。 左側の区間の場合、各寄与は次のようになります。`b - a[i]`、合計は`count * b - sum(a[i])`。 

最後に、両側からの寄与を加算し、結合されたカウントと距離の合計を出力します。 

### なぜ効果があるのか

 正確さは、絶対距離が各クエリ点に対してラインを 2 つの単調領域に分割するという事実に依存します。 ソート後、フォームの任意の条件`a[i] ≤ x`または`a[i] ≥ x`連続したブロックに相当します。 この変換により、幾何学的フィルターが互いに素な配列スライスのペアに変換され、プレフィックス合計により、これらのスライスにわたってカウントと集計の両方が正確になることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def lower_bound(arr, x):
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] < x:
            lo = mid + 1
        else:
            hi = mid
    return lo

def upper_bound(arr, x):
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] <= x:
            lo = mid + 1
        else:
            hi = mid
    return lo

n, q, L, R = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

a.sort()

pref = [0] * (n + 1)
for i in range(n):
    pref[i + 1] = pref[i] + a[i]

out = []

for x in b:
    cnt = 0
    dist_sum = 0

    left_l = x - R
    left_r = x - L
    l = lower_bound(a, left_l)
    r = lower_bound(a, left_r)
    c = r - l
    if c > 0:
        s = pref[r] - pref[l]
        cnt += c
        dist_sum += c * x - s

    right_l = x + L
    right_r = x + R
    l = upper_bound(a, right_l)
    r = upper_bound(a, right_r)
    c = r - l
    if c > 0:
        s = pref[r] - pref[l]
        cnt += c
        dist_sum += s - c * x

    out.append(f"{cnt} {dist_sum}")

print("\n".join(out))
```この実装は、代わりに明示的なバイナリ検索に依存します。`bisect`境界の動作を透明にします。 重要な点は、左右の間隔で異なる包含ルールを使用していることです。 左側では半開間隔を使用します`[b - R, b - L)`、したがって両方の境界は使用します`lower_bound`。 右側で使用するのは`(b + L, b + R]`ので、適用します`upper_bound`両端にあります。 

距離変換ステップでは、実装上のミスが最も多く発生します。 接頭語の合計は座標の合計を示しますが、この問題では絶対差の合計が求められます。 コードはこれらを注意深く次の線形式に変換します。`b`。 

## 実用的な例

 最初のサンプル入力について考えてみましょう。 

我々の陣地には敵がいる`[4, 5, 6]`、そして2人のウォッチャー`1`そして`10`、 と`L = 4`そして`R = 5`。 

ウォッチャー向け`1`、有効な距離は、位置が敵です。`[ -4, -3 ]`左側と`[5, 6]`右側が翻訳後です。 右側のみが寄与します。 間隔`(1 + 4, 1 + 5] = (5, 6]`のみが含まれます`6`。 

| ウォッチャー | 左の間隔 | 右の間隔 | カウント | 距離の合計 |
 | --- | --- | --- | --- | --- |
 | 1 | 空 | [6] | 1 | 5 |

 これにより、メカニズムが空間を正しく分割していることが確認できます。 

ウォッチャー向け`10`、間隔を計算します`[1, 6)`そして`(14, 15]`。 左側のみが寄与します。`4, 5, 6`。 

| ウォッチャー | 左の間隔 | 右の間隔 | カウント | 距離の合計 |
 | --- | --- | --- | --- | --- |
 | 10 | [4,5,6] | 空 | 3 | 9 |

 これは、次を使用してすべての距離が正しく累積されていることを示しています。`10 - a[i]`。 

## 複雑さの分析

 | --- | --- | --- |
 | 時間 | O((n + q) log n) | 並べ替えとクエリごとに 2 つのバイナリ検索 |
 | スペース | O(n) | ソートされた位置に対するプレフィックス合計配列 |

 この制約では最大 200,000 個の要素が許可されるため、クエリごとの対数係数は制限内に収まります。 プレフィックス合計の構築は線形であり、ソートに比べて無視できます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q, L, R = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    a.sort()

    pref = [0]
    for x in a:
        pref.append(pref[-1] + x)

    def lb(x):
        lo, hi = 0, n
        while lo < hi:
            mid = (lo + hi) // 2
            if a[mid] < x:
                lo = mid + 1
            else:
                hi = mid
        return lo

    def ub(x):
        lo, hi = 0, n
        while lo < hi:
            mid = (lo + hi) // 2
            if a[mid] <= x:
                lo = mid + 1
            else:
                hi = mid
        return lo

    res = []
    for x in b:
        cnt = 0
        s = 0

        l1, r1 = lb(x - R), lb(x - L)
        c = r1 - l1
        cnt += c
        s += c * x - (pref[r1] - pref[l1])

        l2, r2 = ub(x + L), ub(x + R)
        c = r2 - l2
        cnt += c
        s += (pref[r2] - pref[l2]) - c * x

        res.append(f"{cnt} {s}")

    return "\n".join(res)

 ## 特殊なケース

 すべての敵が正確な距離にあるとき`L`、それらは除外する必要があります。 たとえば、敵がいる場合、`[0, 5]`、`L = 5`、そしてウォッチャー`0`、両方の点が離れています`5`, したがって、どちらも貢献しません。 左側の間隔で使用されるため、アルゴリズムはこれを処理します。`[b - R, b - L)`適切な間隔で使用するのは`(b + L, b + R]`の境界を明示的に除外します。`L`。 

いつ`L = 0`, ウォッチャーと同じ位置にいる敵は除外されます。 敵単体に対して、`0`そして監視者`0`、左の間隔は次のようになります`[0, 0)`そして正しい間隔は次のようになります`(0, R]`、つまり、次の点です。`0`はカウントされず、厳密な不等式要件に一致します。 

中に敵が入ってこないとき`[b - R, b + R]`、両方のバイナリ検索で空のセグメントが生成され、カウントと合計は両方ともゼロのままです。 同一の境界では差分がゼロになるため、接頭辞の合計構造は空の間隔を自然にサポートします。
