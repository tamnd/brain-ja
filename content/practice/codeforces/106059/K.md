 ## 解決策
 ## 問題の理解

 私たちは、学生ごとに 1 つずつ、各学生が寮の場所をどの程度評価しているかを表す数値評価のリストを渡されます。 上部のみ`m`宣言された価値に応じて学生は寮の権利を受け取ります。 このメカニズムは、`m`-番目と`(m+1)`- 番目に高い評価。 この価格は、すべての学生の合計お金の流れのバランスを保つ方法で、受賞者が支払う金額と非受賞者が受け取る金額を計算するために使用されます。 

この理想的な分割支払いシステムを計算した後、この問題により、整数トランザクションのみが許可されるという実際的な制約が導入されます。 したがって、システムは四捨五入され、四捨五入によって生じる不均衡は大学が吸収します。 

必要な出力は、各勝者が支払う整数の金額、各非勝者が受け取る整数の金額、および大学がカバーする必要がある絶対的な不均衡の 3 つの値で構成されます。 

制約により最大 200,000 人の学生が許可されるため、どのソリューションも少なくとも`O(n log n)`またはそれ以上です。 フルソートは許容されますが、二次関数は最悪の場合 400 億回の演算が必要になるため、直ちに実行不可能になります。 

単純な間違いは、ランクを繰り返し再計算したり、転送を明示的にシミュレートしたりすることです。 たとえば、上部を繰り返し選択しようとすると、`m`並べ替えを行わない要素の場合、選択ごとに直線的な時間がかかる可能性があり、`O(nm)`両方が大きい場合、動作は非常に遅くなります。 

Another subtle issue is precision. The core formulas involve averages like`m * v / n`、通常は分数です。 浮動小数点演算を使用して処理すると、小さな精度の誤差によって下限値と上限値の結果が反転し、不正確な整数出力が生成される可能性があります。 

最後に、次のような場合に簡単なエッジケースが発生します。`m`に非常に近いです`n - 1`。 この場合、非勝者は 1 人だけとなり、不均衡は多数の小さな丸め誤差の合計に依存するため、丸めの違いは非常に敏感になります。 

## アプローチ

 ブルート フォース ビューは、考えられる各候補の評価しきい値に対して勝者と非勝者を明示的に識別することから始まり、毎回価格定義を再計算します。 サブセットを繰り返しソートしたり、各学生に正確な端数の支払いを割り当ててからすべてを合計したりすることで、振込システムを直接シミュレートすることを想像することもできます。 

システムは純粋にソートされた順序統計の観点から定義されているため、これは概念的に機能します。そのため、ソートされた配列がわかれば、すべてを正確に計算できます。 ただし、部分的なランキングを再計算したり、生徒ごとの貢献度を再計算したりすると、配列全体を繰り返しスキャンすることになります。 と`n`1つでも20万まで`O(n^2)`この方法では数十億回の操作が必要になります。 

重要な観察は、メカニズム全体がソートされた配列内の 2 つの値のみに依存しているということです。`m`- 番目に大きい、そして`(m+1)`- 番目に大きい要素。 配列がソートされると、残りのすべてはこれら 2 つの境界値に基づく演算になります。 残りの要素に関するこれ以上の構造情報は重要ではありません。 

したがって、問題は 3 つのステップに分かれます。ソート、2 つの境界値の抽出、いくつかの算術式の計算、そして最後に整数の丸めと一貫性補正の適用です。 

並べ替えは複雑さを軽減し、ソリューションを効率的にします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォースシミュレーション | O(n²) | O(n) | 遅すぎる |
 | ソート + 直接式 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. すべての値を降順に並べ替えます。 

まず、順序統計が直接インデックスになるように配列をソートします。 これにより、`m`-番目と`(m+1)`定数時間内で 2 番目に大きい値。 

### 2. 境界値の抽出

 しましょう`a[m-1]`になる`m`- 番目に大きい値と`a[m]`になる`(m+1)`- 番目に大きい値。 これらは重要な価格の中間点を定義します。 

端数価格を計算します。$$v = \frac{a_{m-1} + a_m}{2}$$### 3. システムの合計値を計算する

 システムでは合計値が次のように定義されます。$$m \cdot v$$概念的にはこれを有理式として保存しますが、実装では浮動小数点を避けます。 

### 4. 1 人当たりの公平な分配を計算する

 各生徒は以下を効果的に得ることができます。$$\frac{m \cdot v}{n}$$この値も小数であるため、慎重に扱う必要があります。 

### 5. 生の支払いを計算する

 勝者が支払うもの:$$v - \frac{m \cdot v}{n}$$非勝者は以下を受け取ります:$$\frac{m \cdot v}{n}$$次に、これらを整数に変換します。 

-`P = floor(winner payment)`-`Q = ceil(non-winner payment)`この丸めステップは、整数転送のみが許可されるという制約を強制するため、不可欠です。 

### 6. 計算の不均衡

 勝者から集めた総額は、`m * P`。 非当選者への分配総額は`(n - m) * Q`。 学校は絶対的な差を吸収します。$$R = |mP - (n - m)Q|$$### なぜ効果があるのか

 このシステムは、勝者と非勝者の分け方に関する注文統計によって完全に決定されます。 しきい値が固定されると、導出されるすべての量は、これら 2 つの数値の線形変換になります。 並べ替えにより、これらの順序統計の正確さが保証され、後続のすべてのステップは決定論的な算術演算となります。 丸めは分類の正確さに影響を与えず、制御されたグローバルな不均衡を導入するだけであり、これは明示的に修正されます。`R`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    v = list(map(int, input().split()))
    
    v.sort(reverse=True)
    
    # boundary values
    vm = v[m - 1]
    vmp1 = v[m]
    
    # work in rational form using integers
    # v = (vm + vmp1) / 2
    # m*v = m*(vm + vmp1)/2
    mv_num = m * (vm + vmp1)
    mv_den = 2
    
    # fair share = (m*v)/n
    # = mv_num / (mv_den * n)
    # winner payment = v - share
    # = (vm+vmp1)/2 - mv_num/(2n)
    # we compute directly as fraction:
    
    # convert everything to common denominator 2n
    winner_num = n * (vm + vmp1) - m * (vm + vmp1)
    winner_den = 2 * n
    
    # non-winner share
    nonwinner_num = m * (vm + vmp1)
    nonwinner_den = 2 * n
    
    # convert to integers
    P = winner_num // winner_den
    Q = (nonwinner_num + nonwinner_den - 1) // nonwinner_den
    
    # imbalance
    R = abs(m * P - (n - m) * Q)
    
    print(P, Q, R)

if __name__ == "__main__":
    solve()
```実装は導出の構造に従います。 ソートにより、分割ポイントを正確に識別できます。 境界値は直接抽出されます。 すべての計算は、floor と ceil が明示的に適用される最終ステップまで除算を遅らせることにより、整数演算で維持されます。 

微妙な点は、勝者の式とそうでない式が同じ分子構造を共有しているため、浮動小数点演算を完全に回避していることです。 の天井`Q`によって扱われます`(x + d - 1) // d`これにより、割り算が正確であるかどうかにかかわらず、正確さが保証されます。

 ## 特殊なケース

 すべての値が等しい場合、重要なエッジ ケースが 1 つ発生します。 この場合、境界値は同一であるため、計算された価格は 1 つの数値に縮小され、小数点の差はすべて消えます。 並べ替えによって隣接性と両方が維持されるため、アルゴリズムは引き続き正しく動作します。`vm`そして`vmp1`は等しいので、一貫したゼロ分散転送が生成されます。 

もう一つのケースは次のような場合です。`m = 1`。 最上位の生徒だけが勝者であるため、全体の不均衡は 1 つのフロアの操作に依存します。 勝者セットのサイズが 1 であってもすべての公式が有効なままであり、非勝者に対する上限演算が均等に分散されるため、アルゴリズムは引き続き機能します。 

いつ`m = n - 1`、優勝者以外の生徒は 1 名だけです。 このシナリオでは、`(n - m) * Q`単一の項に折りたたまれるため、丸め誤差は生じません。`Q`学校の報酬が直接決定されます。 不均衡は生徒ごとではなく全体的に計算されるため、アルゴリズムはこれを正しく処理し、四捨五入後の正確な保全会計を保証します。
