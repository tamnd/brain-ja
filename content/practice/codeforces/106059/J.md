 ## 解決策
 ## 問題の理解

 複数の整数セットが与えられており、それらを自由に並べ替えることができます。 順序を選択した後、各値は 1 から n までのインデックスが付けられた位置に配置されます。 要件は、位置の値をそのインデックスと結合します。つまり、すべての位置 i について、配置された値と i の合計が完全な正方形を形成する必要があります。 

したがって、各位置は、特定の数値のみがその位置を占めることができるという制約のように動作します。 数値 x は、x + i = k² となる整数 k が存在する場合にのみ、位置 i に移動できます。 並べ替えると、これは x = k² − i と等価です。 

タスクは、すべての配列要素を個別の位置に割り当てて、すべての位置がこの条件を満たすかどうかを判断することです。 

制約は十分小さく、n は最大 1000 ですが、値は 10⁹ まで大きくすることができます。 これは、およそ n² または n√V スケールの前処理と、その後の多項式マッチング アルゴリズムを実行できるはずであることを直ちに示唆しています。 すべての順列を直接考慮しようとするものはすべて爆発するでしょう。 n = 20 の場合でも完全に実行不可能です。 

複数の数値が同じ場合、微妙な問題が発生します。 これらは順列プロセスにおいても依然として別個の項目であるため、それぞれの出現を個別に処理する必要があります。 もう 1 つのエッジ ケースは、一部の位置で有効な値がまったく受け入れられない可能性があり、グローバル割り当てを試みる前であっても即座に失敗することになります。 

単純な間違いは、各位置を独立して割り当てることによって問題を貪欲に扱うことです。 たとえば、位置 1 に有効な数値を選択すると、初期の別の選択が成功したとしても、後ですべての有効な割り当てがブロックされる可能性があります。 依存関係はローカルではなくグローバルです。 

## アプローチ

 ブルートフォースの観点は、配列のすべての順列を試し、すべてのインデックスで二乗条件を満たす順序が存在するかどうかを確認することです。 これは正しいですが、n! になるほど増加します。これは、n = 15 の場合にすでに約 10¹5 回の操作となり、実用的な制限をはるかに超えています。 実現可能性はグローバルな割り当ての一貫性に依存するため、個々の位置の有効性に基づいて枝刈りを行っても保存されません。 

重要な観察は、実際には順序を気にするのではなく、インデックスと値の間の完全な一致を気にするということです。 各インデックス i は、その位置で許可される値のセットを定義し、各値はインデックスのサブセットに入ることができます。 これは当然のことながら 2 部グラフです。一方の側は配列要素を表し、もう一方の側は位置を表し、合計条件が満たされる場合にはエッジが存在します。 

このように再定式化すると、タスクは、サイズ n ≤ 1000 の 2 部グラフに完全な一致が存在するかどうかをチェックするようになります。固定値 a に対して、有効な位置 i は a + i が正方形であることを満たすため、グラフは十分に疎です。 各 a について、i は連続する正方形によって引き起こされる短い間隔内に存在する必要があるため、ノードごとの候補エッジの数は少なくなります。 

考えられる平方根 k を反復処理するか、同様に各値を反復して制限された範囲内で k をスキャンすることにより、グラフを効率的に構築できます。 隣接リストを構築した後は、制約があれば、標準の拡張パス マッチング (クーンのアルゴリズム) で十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | お(ん!) | O(n) | 遅すぎる |
 | 二部マッチング (Kuhn) | 実際の O(n²√V) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 各配列要素を左側のノードとしてモデル化し、1 から n までの各位置を右側のノードとしてモデル化します。

1. 各配列要素値 a について、a + i が完全な正方形となるようにすべての位置 i を決定します。 i は 1 と n の間にある必要があるため、k² が [a + 1, a + n] の範囲内にある整数 k を反復処理することでこれを行います。 このような k ごとに、 i = k² − a を計算し、この要素から位置 i までのエッジを作成します。 このステップでは、すべての有効なプレースメントを構築します。 
2. すべてのエッジが構築されたら、すべての要素を一意の位置に割り当てようとします。 どの要素が現在位置 i に割り当てられているかを示す配列 match_pos[i] を維持します。 
3. 要素ごとに、深さ優先検索を使用して割り当てを見つけようとします。 すべての隣接する位置を試みます。 ポジションに空きがある場合は、すぐに割り当てられます。 すでに占有されている場合は、現在の要素を別の位置に再割り当てしようと再帰的に試みます。 これは標準的な拡張パスのアイデアです。現在の割り当てのためのスペースを空けるために、以前の割り当てを移動することがあります。 
4. すべての要素に対してこのプロセスを繰り返します。 最後にすべての要素が一致した場合は、YES を出力します。 それ以外の場合は「いいえ」です。 

### なぜ効果があるのか

 どの段階でも、要素と位置の間の部分的な一致が維持されます。 DFS ステップでは、新しい要素を割り当てるときは常に、代替の有効な位置が存在する場合に、以前に配置された要素を再割り当てする可能性を維持することによってのみ割り当てを行うことが保証されます。 これにより、行き止まりの構成に早まってコミットすることがなくなります。 完全なマッチングが存在する場合、要素の配置に失敗するたびに、マッチング サイズが増加する到達可能な代替パスを示すため、繰り返しの拡張によって最終的にそのマッチングが構築されます。これはまさにクーンのアルゴリズムが利用する構造です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))

    adj = [[] for _ in range(n)]

    max_val = 10**9

    import math

    for i in range(n):
        val = a[i]
        start_k = math.isqrt(val + 1)
        if start_k * start_k < val + 1:
            start_k += 1

        end_k = math.isqrt(val + n)

        for k in range(start_k, end_k + 1):
            sq = k * k
            pos = sq - val
            if 1 <= pos <= n:
                adj[i].append(pos - 1)

    match_pos = [-1] * n

    sys.setrecursionlimit(10000)

    def dfs(u, vis):
        for v in adj[u]:
            if vis[v]:
                continue
            vis[v] = True
            if match_pos[v] == -1 or dfs(match_pos[v], vis):
                match_pos[v] = u
                return True
        return False

    for i in range(n):
        vis = [False] * n
        if not dfs(i, vis):
            print("NO")
            return

    print("YES")

if __name__ == "__main__":
    solve()
```構築フェーズでは、各値から得られる制限された範囲内の平方根のみをスキャンすることによって、すべての有効な配置を計算します。 これにより、位置に対するブルートフォース検索が回避されます。 

一致する配列は、どの要素が各位置を占めるかを表します。 DFS 関数は、指定された要素の配置を試行し、すでに位置が取られている場合は、以前に割り当てられた要素の再配置を試みます。 訪問されたアレイにより、1 回の拡張試行中の循環が防止されます。 

最後のループでは、すべての要素が正常に配置されることが保証されます。 いずれかのステップで失敗した場合は、完全な一致が存在しないことを意味します。 

## 実用的な例

 複数の配置が可能なほど値が十分に小さい入力を考えてみましょう。 3 つの要素があるとします: [2, 3, 6]。 

有効な方程式 x + i = k² に基づいて隣接関係を構築します。 

| 要素インデックス | 値 | 候補者のポジション |
 | --- | --- | --- |
 | 0 | 2 | 2+i が正方形である位置 |
 | 1 | 3 | 3+i が正方形になる位置 |
 | 2 | 6 | 6+i が正方形になる位置 |

 グラフを構築した後、マッチング プロセスにより一意性を尊重した方法で位置が割り当てられます。 有効な結果の 1 つは、各要素が正方形の条件を満たす個別の位置を見つけ、アルゴリズムが YES を返すことです。 

ここで、一様な配列 [4, 4, 4, 4] を考えてみましょう。 すべての要素には同一の隣接リストがあります。 これらの値全体で有効な位置が 2 つだけの場合、マッチング中に最初のいくつかの要素がすべての可能な位置を占め、残りの要素は拡張パスを見つけることができません。 サイズ 4 の完全な一致は存在できないため、アルゴリズムは正しく NO を返します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · √V + n²) | 各要素は正方形の境界のある範囲にわたって候補を生成し、各 DFS マッチングでは O(n) 個のエッジを探索する可能性があります。 
| スペース | O(n²) | 隣接リストと一致する配列 |

 n ≤ 1000 の場合、√V は約 31623 であるため、これは時間とメモリの両方の制限内に快適に収まりますが、各ノードは狭い間隔のみを探索するため、実際のエッジ数は管理可能になります。

 ## 特殊なケース

 サイズ 1 の最小配列は、単一の値が位置 1 の二乗条件をすでに満たしている可能性を実装が正しく処理しているかどうかをテストします。 a = k² − 1 に k の整数解がない場合、エッジが作成されず、DFS が唯一のノードと一致できないため、アルゴリズムは失敗を正しく報告します。 

多くの同一の値を持つ配列の場合、隣接リストはすべてのノードで同一になります。 次に、マッチング プロセスにより、正方形制約を通じて到達可能な利用可能な位置の数が十分であるかどうかが明らかになります。 そうでない場合、DFS は最終的に最後の要素の拡張パスの検索に失敗し、ローカルの貪欲な割り当てによって引き起こされる誤った YES を正しく防止します。 

多くの k 値が複数の要素の有効な位置を生成する密なケースでは、再帰を多用するマッチング ステップが強調されます。 そのシナリオでも、訪問配列により、各 DFS の試行は要素ごとに各位置を最大 1 回探索することが保証され、プロセスの安定性が維持され、無限再帰サイクルが回避されます。
