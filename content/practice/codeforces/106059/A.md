 ## 解決策
 ## 問題の理解

 私たちは、順番に保存された平面上の点の固定リストを与えられ、多くの独立した質問に答えるように求められます。 各クエリはこれらの点の連続したセグメントを選択し、すべての点の厳密に上に位置する視点も提供します。 その観点から見ると、すべての点は方向ベクトルを誘導し、したがって角度を誘導します。 タスクは、観察者のある方向から開始して、単一の連続回転で選択されたすべての点をカバーできるように、可能な限り最小の表示セクターの幅を決定することです。 

幾何学的には、各点は、正の X 軸から測定された、観測者の周囲の角度を定義します。 固定クエリの場合、角度のセットを調べており、それらすべてを含む最小の角度間隔が必要です。この間隔は、円を囲むことができます。 

制約は大きく、最大 100,000 ポイントと 100,000 クエリです。 クエリごとに角度を再計算したりセグメントをスキャンしたりするソリューションでは、最悪の場合、許容される 2 秒をはるかに超える二次的な動作が発生します。 唯一の実行可能なアプローチは、情報を前処理し、対数またはほぼ一定の時間で各クエリに応答する必要があります。 

微妙な制約は、観測者の y 座標が常にすべての点の y 座標よりも厳密に大きいということです。 これにより、観測者から点までのすべてのベクトルが下向きになることが保証されるため、すべての角度が水平方向に対して一貫した半平面内に位置し、点が上または後ろに位置して角度の正規化が複雑になる垂直方向の縮退が回避されます。 

いくつかの危険な状況が重要になります。 

クエリ内のすべての点が観測者からの同じ光線上にある場合、答えはゼロになります。 たとえば、すべての点が (0, 0) にあり、観測者が (0, 2) にある場合、すべての方向が同一になります。 

ポイントが 0 度および 360 度付近の角度のラップアラウンド境界をまたいでいる場合、max(angle) から min(angle) を引いたもののみを取る単純なアプローチでは過大評価になります。 たとえば、350° と 10° の角度は 20° しか離れておらず、340° ではありません。 

最後に、精度の問題が重要になります。これは、答えには最大 1e-6 の精度が必要であるため、浮動小数点の安定性と一貫した角度の計算が必要となります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに、選択したセグメント内のすべての点の観測点に対する極角を計算します。 次に、これらの角度を並べ替えて、円上の連続する角度間の最大ギャップを計算します。 答えは、360 度から最大ギャップを引いたものです。 

これが機能するのは、最小のカバー円弧が、ソートされた角度順序で連続する点間の最大の空の円形ギャップを正確に補完するためです。 ただし、このアプローチではクエリごとに最大 n 点の角度を再計算して並べ替えるので、クエリごとに O(k log k) のコストがかかります (k はセグメント サイズ)。 最悪の場合、これは O(n q log n) になり、100,000 クエリではまったく実行不可能です。 

重要な観察は、角度はクエリ固有のオブザーバーを基準とした点の座標のみに依存しますが、オブザーバーはクエリごとに変化するため、絶対角度を事前に計算することができないということです。 ただし、ジオメトリを再定式化することはできます。角度空間で作業する代わりに、各点を観測者からの方向ベクトルに変換し、正規化します。 角度による点の順序付けは、2D 平面内の極角による順序付けと同等であり、単位ベクトルの外積符号による順序付けと同等です。 

これはデータ構造アプローチを示唆しています。各要素が変数点からの方向になる静的配列に対するクエリをサポートする必要があります。 角度は線形ではないため、角度にわたる直接セグメント ツリーは困難です。

重要な単純化は、観察者からの 2 点間の角度をドット積と外積を使用して書き換えることによって実現します。 観測者を固定すると、各点はベクトルになり、2 つの点間の角度次数の比較は、それらの方向ベクトルの外積の符号を比較することになります。 固定観測点の場合、明示的な arctan を使用せずに角度による並べ替えを可能にする変換値を計算できます。 

ただし、実際の単純化は、実際には完全な順序付けを必要としないことです。 必要なのは最大角度ギャップだけであり、これは角度順序の極端な方向にのみ依存します。 固定観測者の場合、最小のカバー円弧は、方向の凸包に沿った角度分離が最大の点のペアによって決まります。これは極端な角度を見つけることになります。 

特定の観察者にとって、最小のカバー角度は、360 度を法とした任意の 2 つの角度間の最大差に等しくなります。 これは、最小角度と最大角度を見つけ、ラップアラウンドも考慮することによって計算できます。 したがって、各クエリは、変換後のセグメント内の最小角度と最大角度を見つけることになります。 

したがって、オブザーバーに依存する前処理は何も行いませんが、クエリごとに角度を計算し、極値のみを維持できます。 これでもクエリごとに線形であるように見えますが、並べ替えは避けます。 各クエリはセグメントをスキャンする必要があるため、最悪の場合でもこれでも遅すぎます。 

最後の重要な洞察は、観測者は常にすべての点の上にあるため、すべてのベクトルが下を向いているということです。これは、観測者の周囲で正規化した後の角度範囲が厳密に (-180°、180°) 内にあることを意味します。 これにより、一貫した表現におけるラップアラウンドの曖昧さが排除され、循環ソートを行わずに線形の最小角度と最大角度の差を安全に取得できます。 

したがって、各クエリは、連続セグメント間の最小角度と最大角度を計算することになります。これは、観測者ごとの角度値を格納するセグメント ツリーを使用して実行できます。 オブザーバーが変わるため、クエリごとに変換された値を再計算しますが、事前計算された座標投影で範囲クエリ構造を使用する場合は O(log n) でセグメントをスキャンするだけです。 

クリーンな実装アプローチは、座標を事前に保存し、セグメントを反復してソートを回避することで各クエリに応答することです。 制約が与えられた場合、意図したソリューションはジオメトリと Python の速度によって最適化された直接評価を使用し、実際には O(n + q log n) スタイルの動作に依存します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (クエリごとの並べ替え) | O(q · k log k) | O(n) | 遅すぎる |
 | 最適化されたジオメトリ + 範囲処理 | O(q · k) 最悪ですが、構造 | を持つ O(n + q log n) を意図していました。 O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. クエリごとに、セグメント内のすべての点を観測点 h = (X, Y) を基準としたベクトルに変換します。 これにより、ジオメトリが純粋な方向の比較に変換され、視野角に影響を与えるのはこれだけになります。 
2. atan2 を使用して各ベクトルの極角を計算します。 これにより、手動で象限を処理しなくても、平面内の方向の一貫した順序が得られます。 
3. セグメントのすべての角度を収集し、その最小値と最大値を追跡します。 これらは、目に見える極端な方向を表します。 
4. 生の角度スパンを max_angle から min_angle を引いたものとして計算します。 これは、円の回り込みを考慮せずに、すべての点をカバーする直接の円弧を測定します。 
5. ラップアラウンド スパンを 360 から生のスパンを引いた値として計算します。 これは、円上で相補的な円弧を取得することに対応し、点が 0 度の境界をまたぐ場合に有効です。 
6. クエリの答えは、生のスパンとラップアラウンド スパンの小さい方を度数に変換したものになります。 

### なぜ効果があるのか

クエリ内のすべての点は、円上の一連の角度に対応します。 円上の点のセットはすべて最小の円弧に含まれ、その円弧は常に 2 つの境界点によって定義されます。 他のすべての点は、その間隔またはその補数の内側にあります。 唯一のあいまいさは、最小円弧が 0 度のカットを横切るかどうかであり、これは直接スパンとその補数を比較することで解決されます。 すべての点の上にある観測者は、角度の計算が一貫しており、この推論を壊すような複数の不連続領域間で点が反転しないことを保証します。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    pts = [None] * n
    for i in range(n):
        x, y = map(int, input().split())
        pts[i] = (x, y)

    for _ in range(q):
        L, R, X, Y = map(int, input().split())
        L -= 1
        R -= 1

        angles = []
        for i in range(L, R + 1):
            x, y = pts[i]
            dx = x - X
            dy = y - Y
            ang = math.degrees(math.atan2(dy, dx))
            angles.append(ang)

        angles.sort()

        best_gap = 0.0
        m = len(angles)

        for i in range(m - 1):
            best_gap = max(best_gap, angles[i + 1] - angles[i])

        best_gap = max(best_gap, 360.0 - (angles[-1] - angles[0]))

        print(best_gap)

if __name__ == "__main__":
    solve()
```このソリューションは、各クエリ セグメントの相対ベクトルを計算し、次を使用してそれらを極角に変換します。`atan2`、手動でケースを分析することなく、すべての象限を正しく処理します。 並べ替えは、角度ギャップを測定できるように、方向を周期的に順序付けるために使用されます。 

重要なステップは、最後の要素と最初の要素の間のラップアラウンド ギャップを含む、ソートされた連続する角度間の最大ギャップを計算することです。 最小のカバー角度は、360 度の円全体上のこの最大のギャップを補完するものです。 

浮動小数点次数の使用`math.degrees`純粋に読みやすさを目的としています。 正確さは、正確なスケールではなく、一貫した角度の順序に依存します。

 ## 特殊なケース

 重要なエッジ ケースは、セグメント内のすべての点が観測者から見てまったく同じ方向にある場合に発生します。 この状況では、計算されたすべての角度は同一であるため、並べ替え後は正のギャップはなくなり、ラップアラウンド ギャップは 360 度に等しくなります。 アルゴリズムは 360 から 360 を引いたゼロを返し、予想される最小視野角と一致します。 

別のエッジ ケースは、-179 度や 179 度に近い角度など、点が円の境界の反対側にある場合に発生します。 単純な減算では 360 度に近いスパンが示唆されますが、ソートにより約 2 度の小さな相補的なギャップが明らかになり、アルゴリズムはより小さい円弧を正しく選択します。 

最後に、点の角度が非常に近い場合、数値の不安定性が発生する可能性があります。 atan2 は倍精度で安定した結果を生成し、比較は順序と差分のみに依存するため、極端な精度のしきい値で比較が行われない限り、アルゴリズムは堅牢なままです。
