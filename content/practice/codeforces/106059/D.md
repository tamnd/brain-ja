 ## 解決策
 ## 問題の理解

 ツリーが与えられています。これは、任意の 2 つのノード間には単純なパスが 1 つだけ存在することを意味します。 各クエリは 2 つの独立した通信リクエストを提供します。1 つは a から b へ、もう 1 つは c から d です。 ノードをアクティブ化するとは、そのノードが選択された 2 つのパスのうちの少なくとも 1 つに存在することを意味します。 すべてのクエリについて、2 つのパスの和集合上に異なる頂点がいくつあるかを計算する必要があります。 

重要な出力は、パスの長さやオーバーラップに関する直接的なものではなく、2 つのツリー パスによってカバーされる一意のノードの数に関するものです。 

制約は最大 100,000 ノードおよび 100,000 クエリまでです。 これにより、クエリごとにパスを明示的に再計算することが直ちに除外されます。 クエリごとに両方のパスを構築する単純なアプローチでは、最悪の場合、クエリあたりすでに O(n) のコストがかかり、O(nq) となり、あまりにも大きすぎます。 

パスが部分的に重なる場合、微妙な問題が発生します。 たとえば、両方のパスが長いセグメントを共有する場合、ノードを二重にカウントしてはなりません。 パスの長さを合計するだけの単純な実装では、交差が正しく処理されない限り、過度にカウントされてしまいます。 

典型的な失敗シナリオは、エンドポイントを除いて両方のパスがほぼ一致するスター型またはチェーン ツリーです。 たとえば、a = 1、b = n、c = 1、d = n の場合、正解は n ですが、単純に長さを加算すると 2n からオーバーラップを引いた値が得られるため、これを慎重に減算する必要があります。 

## アプローチ

 直接的なアプローチは、親ポインターまたは DFS を使用して両方のパスを明示的に抽出し、それらのノードをセットに格納し、和集合を取得することです。 結合はアクティブ化されたノードを正確に表すため、これは論理的に正しいです。 ただし、クエリごとに O(n) で各パスを構築すると遅すぎて、O(nq) になります。 

重要な洞察は、実際には完全なパスは必要ないということです。 パスとそのペアの交差点のサイズのみが必要です。 ツリーでは、パス長は最小共通祖先 (LCA) を使用して表現できます。 任意の 2 つのノード u および v について、ノード内の距離は Depth[u] + Depth[v] - 2 * Depth[lca(u, v)] + 1 です。 

したがって、各クエリはコンピューティングに帰着します。 

サイズ(パス(a,b)) + サイズ(パス(c,d)) - サイズ(交差点)

 重要な部分は、2 つのツリー パスの交差部分を計算することです。 重要な構造上の事実は、ツリー内の 2 つの単純なパスの交差部分自体が空か単一のパスであるということです。 これにより、交差エンドポイントを両方のパスのエンドポイントとその LCA から抽出された候補として表すことができます。 6 つの重要なポイントのうち、次のことが判明しました。 

a、b、c、d、lca(a,b)、lca(c,d)

 交差点の端点は小さな候補セットから得られる必要があり、標準的な「パス上に点がある」条件を使用して、どの候補ペアが両方のパス上にあるかをテストできます。 

dist(u,x) + dist(x,v) = dist(u,v) の場合に限り、ノード x は path(u,v) 上にあります。 

したがって、問題を、一定数の候補セグメント端点をチェックし、LCA 距離を使用してそれらの重複長を計算することに縮小します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (明示的なパス) | クエリごとに O(n) | O(n) | 遅すぎる |
 | LCA + パス計算 | クエリあたり O(log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノード 1 でツリーをルートし、LCA クエリの深さとバイナリ リフティング祖先を前処理します。 これにより、距離と LCA を O(log n) で計算できます。 
2. LCA を使用して 2 つのノード間の距離を計算するヘルパー関数を定義します。 

dist(u, v) = 深さ[u] + 深さ[v] - 2 * 深さ[lca(u, v)]。 
3. ID を使用してノード x が path(u, v) 上にあるかどうかを確認する関数を定義します。 

dist(u, x) + dist(x, v) == dist(u, v)。 

これにより、木のパスに対して一定時間の幾何学的テストが行​​われます。 
4. クエリごとに、次を計算します。 

L1 = パス(a, b)、L2 = パス(c, d)

 エンドポイントのペアを使用します。 
5. ユニオンのサイズは次のとおりです。 

|L1| + |L2| - |L1 ∩ L2|

|L1| を計算します。 と |L2| 距離公式プラス 1 を直接使用します。 
6. 交差サイズを計算するには、どの交差パスにも端点 a、b、c、d と (a,b) および (c,d) の LCA で構成される「関連する頂点」のセットから選択された端点がなければならないことに注意してください。 このセット内の各候補ノード x について、パス メンバーシップ条件を使用して、それが両方のパス上にあるかどうかをテストします。 
7. 有効な候補エンドポイント (x、y) のすべてのペアのうち、両方が両方のパス上にある場合、それらの間の距離を計算します。 このような有効な最大距離は、交差点の経路長に対応します。 
8. 両方のパスの長さの合計から交差の長さを引きます。 

### なぜ効果があるのか

 重要な不変条件は、ツリー内の 2 つの単純なパスの交差点自体が単純なパス (おそらく空) であるということです。 単純なパスはその終点によって一意に決定され、この交差点の終点は、LCA によって定義された 2 つの元のパスの終点または分岐点のうちの少なくとも 1 つに存在する必要があります。 これにより、連続的な幾何学的問題が一定サイズの候補検索に縮小されます。 LCA ベースの距離関数は、メンバーシップ テストとセグメント長の計算の両方の正確さを保証し、パス再構築における組み合わせ爆発を防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(200000)

n, q = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

LOG = 18
up = [[0] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)

def dfs(v, p):
    up[0][v] = p
    for to in g[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        dfs(to, v)

dfs(1, 1)

for i in range(1, LOG):
    for v in range(1, n + 1):
        up[i][v] = up[i - 1][up[i - 1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for i in range(LOG):
        if diff >> i & 1:
            a = up[i][a]
    if a == b:
        return a
    for i in reversed(range(LOG)):
        if up[i][a] != up[i][b]:
            a = up[i][a]
            b = up[i][b]
    return up[0][a]

def dist(a, b):
    c = lca(a, b)
    return depth[a] + depth[b] - 2 * depth[c]

def on_path(a, b, x):
    return dist(a, x) + dist(x, b) == dist(a, b)

for _ in range(q):
    a, b, c, d = map(int, input().split())

    dab = dist(a, b) + 1
    dcd = dist(c, d) + 1

    cand = [a, b, c, d, lca(a, b), lca(c, d)]

    best = 0
    m = len(cand)

    for i in range(m):
        for j in range(i, m):
            x, y = cand[i], cand[j]
            if on_path(a, b, x) and on_path(a, b, y) and on_path(c, d, x) and on_path(c, d, y):
                best = max(best, dist(x, y) + 1)

    ans = dab + dcd - best
    print(ans)
```実装は、LCA の標準バイナリ リフティング前処理から始まります。 深さテーブルと祖先テーブルは O(n log n) で埋められます。 距離とパス上のチェックは、LCA ベースの公式を直接適用します。 

クエリごとに、両方のパスの全長を即座に計算します。 次に、エンドポイントと LCA を含む一定サイズの候補セットを構築します。 候補に対する二重ループはクエリごとに一定の作業になります。 

正確性の重要な点は、交差パスの端点がこれらの候補の中に出現する必要があるため、すべてのペアをチェックするだけで十分です。 

## 実用的な例

 小さなツリー上の単一のクエリをトレースします。 

ツリー:

 1-2-3

 |

 4

 クエリ: (2,4) および (3,1)

 次のように計算します。 

| ステップ | a-b パス | c-dパス | 候補者 | 最高の交差点 |
 | --- | --- | --- | --- | --- |
 | 初期化 | 2-4 | 3-1 | {2,4,3,1,lca(2,4)=2,lca(3,1)=1} | 0 |
 | チェックペア | フルスキャン | フルスキャン | 有効なエンドポイント {1,2,3,4} | 2 |

 パス(2,4) = {2,3,4}

 パス(3,1) = {3,2,1}

 交差 = {2,3} サイズ 2

 したがって、答え = 3 + 3 - 2 = 4

 これにより、候補エンドポイントによる交差抽出が共有セグメントを正しくキャプチャしていることが確認されます。

 ## 特殊なケース

 エッジケースの 1 つは、両方のパスが同一である場合です。 この状況では、交差部分は完全なパスに等しくなければならず、答えは 1 つのパスのサイズに減ります。 すべての候補エンドポイントが両方のパス上にあり、最大交差部分が正確に完全なパス長になるため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、パスが 1 つのノードでのみ交差する場合です。 次に、最良の候補ペアは距離 0 + 1 を生成し、交差サイズ 1 が正しく生成され、和集合は和から 1 を引いたものとなり、単一の頂点を共有する 2 つのセットの和集合と一致します。 

最後のケースは、ツリーの異なるブランチにあるパスが互いに分離している場合です。 その場合、両方のパス上に同時に存在するという条件を満たす候補ペアは存在しないため、最良の値はゼロのままであり、和集合は単に両方のパスの長さの合計になります。
