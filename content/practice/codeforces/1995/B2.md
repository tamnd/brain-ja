 ## 解決策
 ## 問題の理解

 いくつかの独立したシナリオが与えられています。 各シナリオにはさまざまな花の種類があり、それぞれの花びらの値と供給量が限られています。 すべての花には、その花びらの価値がコインで正確に支払われ、予算も固定されています。 

2 つの制約の下で花束を作りたいと考えています。 まず、予算を超えることはできません。 第 2 に、選択したすべての花の花びらの数が、最大 2 つの連続する整数のサイズのウィンドウ内に収まる必要があります。つまり、値を混合できるのは 5 と 6、または 10、11、そして場合によっては 10 のような値だけですが、5 と 7 のような値を一緒にすることはできません。 

各テスト ケースでは、これらの制約の下で購入できる花びらの合計を最大化する必要があります。 

制約は十分に大きいため、どのソリューションでも花の種類の総数に対してほぼ直線またはほぼ直線の時間ですべてのテスト ケースを処理する必要があります。 並べ替えは許容されますが、花の数のすべての組み合わせをシミュレートしようとしたり、合計を最初から繰り返し再計算したりするアプローチは失敗します。 

微妙な失敗のケースは、周波数制限を無視した場合に発生します。 「違いは最大 1 つ」という制約を無視して常に最大の花びらを最初に取得する素朴な貪欲さは、効率的に「ウィンドウを満たす」ためにわずかに小さい花が必要な入力で違反します。 

たとえば、花びらがあるとします。`[10, 9, 1]`大量の量と適度な予算の場合、最初に 10 をすべて取ると、実現可能性のために 9 を追加する必要がある状況が残る可能性がありますが、単純な戦略ではその組み合わせが無視され、次善の組み合わせまたは無効な組み合わせが生成される可能性があります。 

別のエッジ ケースは、値による局所的に最適なウィンドウが、数量の不均衡により全体的に最適ではない場合に発生します。 たとえば、非常に価値の高い花は少量しか存在しない一方、わずかに小さい花は大量に存在し、予算の使用量を支配します。 

## アプローチ

 ブルートフォース解釈では、連続する値ウィンドウの有効な選択肢をすべて試してから、各タイプの花の数を決定します。 各候補ウィンドウについて、予算がなくなるまでウィンドウ内でコストの降順に花を持ち込むことをシミュレーションします。 これは正しいです。有効なブーケは 2 つの連続する整数のサイズのウィンドウ内に存在する必要がありますが、ウィンドウ内のサブセットのすべての組み合わせを試行すると、再計算が繰り返されることになります。 

最悪の場合、各テスト ケースですべてのウィンドウを調べ、各ウィンドウですべての花の種類を反復処理し、テスト ケースごとに二次的な動作が発生する可能性があります。 合計要素数が最大 200,000 であるため、これでは遅すぎます。 

重要な観察は、妥当性が花びらの値のソート順での隣接性にのみ依存するということです。 並べ替えると、問題は次のようになります。単一の値 x またはペア (x, x+1) を選択し、予算の制約の下でこれら 2 つのバケツからできるだけ多くの花を取り出します。 各ウィンドウ内では、最適な選択はコストによって貪欲に行われますが、コストは値に等しいため、プレフィックスの合計を事前計算し、2 つのポインターを使用して O(1) または O(log n) で各ウィンドウを処理できます。 

これにより、ソートされた配列をスキャンし、常に差分制約を尊重するスライディング ウィンドウを維持するという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | シミュレーションによるブルート フォース ウィンドウ列挙 | O(n²) | O(n) | 遅すぎる |
 | ソート + 2 つのポインター + プレフィックス集約 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. すべての花の種類を花びらの値で並べ替えます。 これにより、有効なブーケは、この並べ替え順序で 1 つの値または隣接する 2 つの値のいずれかから取得される必要があります。 
2. 個別の花びらの値とそれらの利用可能な合計数の配列を構築します。 
3. コスト加重量のプレフィックス合計を事前計算して、隣接するセグメントからどれだけの量を取得できるかを迅速に評価できるようにします。 
4. ソートされた一意の値に対して 2 ポインタのスライディング ウィンドウを使用します。 花びらの最小値と最大値の差が最大 1 になるウィンドウを維持します。 
5. 有効なウィンドウごとに、可能な限り最高の花束を計算します。最初に高い花びらの値からできるだけ多くの花を取得しようとします (コストと価値が等しいため、値が高いほどアイテムごとの合計に大きく貢献しますが、予算の消費も早くなります)。次に、低い値で埋めます。 
6. すべての有効なウィンドウにわたって達成可能な最大合計を追跡します。 

重要な実装の詳細は、各ウィンドウ内で項目ごとの選択をシミュレートする必要がないことです。 各花にはその価値に等しい固定コストがあるため、固定ウィンドウ内での最適な戦略は決定的であり、常により価値の高い花を優先します。 

### なぜ効果があるのか

 有効な花束はすべて、連続する花びらの値を 1 つまたは 2 つだけ使用する必要があります。 並べ替えると、これらが値空間内で連続したセグメントとして表示されるようになります。 このようなセグメントでは、グループ内のすべての項目が同一のコスト構造を持ち、予算消費を超える相互作用がないため、予算内での最適な選択は貪欲になります。 したがって、すべての有効なウィンドウを評価することで、すべての実行可能なソリューションがカバーされ、各ウィンドウ内で最適なパッキングが計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        c = list(map(int, input().split()))

        pairs = sorted(zip(a, c))

        vals = []
        cnt = []

        for v, k in pairs:
            if vals and vals[-1] == v:
                cnt[-1] += k
            else:
                vals.append(v)
                cnt.append(k)

        # prefix sums for counts and cost contributions
        # cost contribution inside window is handled greedily

        ans = 0
        j = 0

        for i in range(len(vals)):
            while j < len(vals) and vals[j] <= vals[i] + 1:
                j += 1

            # window is [i, j)
            total = 0
            rem = m

            # we always take from higher value first
            for k in range(j - 1, i - 1, -1):
                take = min(cnt[k], rem // vals[k])
                total += take * vals[k]
                rem -= take * vals[k]

            ans = max(ans, total)

        print(ans)

if __name__ == "__main__":
    solve()
```コードは、単一のリソース プールとして動作するため、最初に同一の花びら値を集計します。 次に、並べ替えられた値に対してスライディング ウィンドウを使用し、有効なウィンドウのみが考慮されるようにします。 各ウィンドウ内では、花びらの最大値から下に向かって貪欲に予算が消費され、使用されるコインあたりの最大の貢献が保証されます。 

唯一の微妙な点は、ウィンドウ処理の前に集計を正しく処理することです。 同一の値をマージしないと、不正確なウィンドウ境界と過剰カウントが発生します。 

## 実用的な例

 ### 例 1

 入力:```
n = 3, m = 10
a = [1, 2, 3]
c = [2, 2, 1]
```グループ化された値を形成します。 

| 値 | カウント |
 | --- | --- |
 | 1 | 2 |
 | 2 | 2 |
 | 3 | 1 |

 ウィンドウをテストします。 

ウィンドウ [1,2]:

 2 を使用してから 1 を使用できます。 

値 2 から 2×2 = 4 を取り出し、残りは 6 になります。 

次に、値 1 から 2×1 = 2 を取り出し、残りは 4 になります。 

合計 = 6。 

ウィンドウ [2,3]:

 最初に 3 を取る: 1×3 = 3、残り 7。 

次に 2 秒: 2×2 = 4、残り 3。 

合計 = 7。 

ウィンドウ[3]:

 3 秒のみ: 1×3 = 3。 

最大は 7 です。 

これにより、最適なソリューションが常に 1 つまたは 2 つの値のウィンドウ内に収まることが確認されます。 

### 例 2

 入力:```
n = 2, m = 10000000000
a = [11, 12]
c = [1, 1]
```ウィンドウ [11,12]:

 最初に 12 を選択します。1 × 12 = 12、残りの予算は膨大ですが、在庫はもうありません。 

すると 11: 1×11 = 11 となります。 

合計 = 23 ですが、それぞれ 1 つしか存在しないため、答えは 23 になります。 

これは、数量が少ない場合でも、貪欲な充填が可用性と予算を同時に考慮していることを示しています。

 ## 特殊なケース

 主なエッジ ケースは、花びらの値が 1 つだけ存在する場合です。 その場合、最適解は単純に min(余裕のある総コスト、利用可能な数量と値の積) であり、スライディング ウィンドウが誤って拡大しようとしてはなりません。 

もう 1 つのケースは、値が連続しているものの、数量的に非常に不均衡な場合です。 アルゴリズムは、価値の高い花をすべて取り除いてから価値の低い花を取得することによって、価値の低い花が豊富にある場合にはより多くの合計に寄与する可能性があるという事実を無視しないようにする必要があります。 

最後のエッジケースは、総供給量に比べて予算が極端に大きい場合です。 アルゴリズムは、在庫制限を超えて過剰に消費しようとするのではなく、利用可能なアイテムの合計を正しく制限する必要があります。
