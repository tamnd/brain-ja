 ## 解決策
 ## 問題の理解

 いくつかの独立した配列が与えられ、それぞれに対して非常に特殊な操作を使用して要素を変更することができます。つまり、インデックスを選択し、その位置の値をその平方で置き換えます。 同じインデックスに対してこの操作を複数回繰り返す場合があります。 私たちの目標は、そのような操作をできるだけ少なくして配列全体を非減少にし、その最小数を報告するか、それが不可能であると判断することです。 

重要な問題は、二乗によって値が非常に非線形に変化することです。 小さな数値は、その大きさに応じてゆっくりと速く増加する可能性があり、値が増加すると、隣接する数値との順序が簡単に崩れる可能性があります。 要素を自由に並べ替えることはできないため、すべての操作はグローバルな順序制約に影響を与えながら、ローカルで 1 つの位置のみを変換します。 

制約は大きく、すべてのテスト ケースにわたる要素の合計数は 2 · 10^5 に達する可能性があります。 これにより、要素ごとに可能なすべての二乗シーケンスをシミュレートしようとしたり、状態を明示的に探索しようとしたりするソリューションは即座に除外されます。 どのアプローチも、テスト ケースごとに線形または線形に近いものでなければなりません。 各要素は複数回二乗される可能性があるため、実際の複雑さは配列サイズだけでなく、値の増加動作も複雑になります。 

二乗法がまったく役に立たない場合、微妙な問題が発生します。 たとえば、[5, 4] のような減少するペアがある場合、4 を 2 乗すると 16 が得られ、ローカル反転が修正されますが、より長いチェーンでは以前の制約が破られる可能性があります。 さらに悪いことに、どの二乗シーケンスも依存関係の順序付けにおける矛盾を解決できない場合があり、これを早期に検出する必要があります。 

もう 1 つの重要なエッジ ケースは、数値がすでに大きい場合です。 隣接する要素と比較して要素が大きくなりすぎる場合、さらに二乗すると悪化するだけであり、実現可能性が損なわれる可能性があります。 常に「局所的な反転を貪欲に修正する」という単純なアプローチでは、ある領域を簡単に平滑化しすぎて別の領域を壊す可能性があります。 

## アプローチ

 ブルートフォース解釈では、各インデックスは可能な値の無限のシーケンスを持つものとして扱われます。 

a[i]、a[i]^2、a[i]^(2^2)、a[i]^(2^3) など。 各位置を何回二乗するかというすべての選択肢を検索し、結果として得られる配列が減少していないかどうかをチェックし、合計の演算を最小限に抑えることを想像することもできます。 

これは原理的には正しいですが、完全に実行不可能です。 要素ごとの二乗数を小さな定数、たとえば最大 60 に制限したとしても (値がすぐに爆発するため)、最悪の場合、状態空間は 60^n になりますが、これは不可能です。 各位置は以前の可能な値の無制限の範囲に依存するため、位置に対する動的プログラミングも失敗します。 

重要な観察は、各要素が任意の方法で独立しているわけではないということです。 固定要素の場合、すべての二乗累乗を盲目的に考慮する必要はありません。 代わりに、要素が少なくとも以前に選択された値と同じ大きさになるために必要な二乗の最小数が重要です。 要素を二乗する回数を決定すると、その最終値は固定され、制約を前方にのみ伝播します。 

これは、欲張りな左から右への構築を示唆しています。 各位置で、前の位置で許可された最小値を維持します。 現在の要素については、非減少順序を満たすのに十分な大きさになるまで二乗を適用しようとします。 ただし、将来の要素が追いつくことが不可能になるようなオーバーシュートがないようにする必要もあります。

重要な構造は単調増加です。2 乗は常に値を増加させ (整数 ≥ 2 の場合)、非常に速く増加します。 これは、各要素が将来のすべての制約を超える前に、意味のある状態が非常に少数しか存在しないことを意味します。 したがって、要素ごとに、しきい値に到達するために必要な二乗の最小数をシミュレートし、そのしきい値を前方に伝播することができます。

 ## アルゴリズムのチュートリアル

 選択した変換後の前の要素から導出された、現在の位置の最小許容値を維持しながら、配列を左から右に処理します。 

1. 操作用のカウンターを初期化し、現在必要な下限を最初の要素として設定します。 最初の要素には事前の制約がないため、調整の必要はありません。 
2. 次の各要素について、現在の下限と比較します。 すでに十分に大きい場合は、何も操作せずにそれを受け入れ、下限をこの値に更新します。 
3. 下限より小さい場合は、少なくとも下限と等しくなるまで繰り返し 2 乗します。 各二乗は 1 回の操作としてカウントされます。 
4. このプロセス中に値の変化が止まったり、増加が遅すぎて必要な限界 (たとえば、0 または 1 の場合) に達しない場合は、不可能であると結論付けます。 
5. 要素が調整されたら、新しい下限をこの調整された値に設定して続行します。 

微妙な点は、二乗は直線的な成長ではないということです。 私たちは「正確に一致させる」ことを決して試みません。 私たちは敷居を越えることだけを気にします。 必要な二乗の数は、二乗を繰り返したときに値がどれだけ速く増加するかによって一意に決定されます。 

### なぜ効果があるのか

 このアルゴリズムは、位置 i の処理後、i までの非減少順序を満たしながら、許可された操作の下で達成可能な最小値である a[i] の有効な変換値を選択したという不変条件を維持します。 必要以上に大きな値を選択すると、将来の制約を満たすことが難しくなるだけであるため、これは非常に重要です。 

各ステップにおいて、以前の決定を見直すことは決してありません。 これは安全です。以前の要素はその最終値によってのみ将来の要素を制約し、その最終値を増加させると後の位置の難易度が増加するだけだからです。 したがって、局所的な最小の実現可能性は、全体的な最適性を意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        ops = 0
        prev = a[0]
        
        for i in range(1, n):
            x = a[i]
            
            if x >= prev:
                prev = x
                continue
            
            # try squaring until it reaches prev
            cnt = 0
            while x < prev:
                if x <= 1:
                    x = float('inf')
                    break
                x = x * x
                cnt += 1
            
            if x < prev:
                print(-1)
                break
            
            ops += cnt
            prev = x
        else:
            print(ops)

if __name__ == "__main__":
    solve()
```このコードは、貪欲戦略の直接シミュレーションに従っています。 変数`prev`最後に選択された値を変換された配列に保存します。 各要素について、順序付けの制約がすでに満たされている場合は、すぐにそれを受け入れます。 それ以外の場合は、交差するまで繰り返し平方します。`prev`、途中で操作を数えます。 

実装の微妙な詳細は、値 0 と 1 の処理です。二乗しても値が増加しないため、必要な上限に到達することはできません。そのため、状況を直ちに不可能としてマークします。 この問題の制約では、値は正ですが、停滞を防ぐことで拡張バリアントでの正確性が保証されます。 

ループは Python を使用します`else`for ループの句を使用して、成功した完了と不可能による早期終了を区別します。

 ## 特殊なケース

 重要なエッジ ケースは、値が 1 になる場合です。1 の 2 乗は 1 のままであるため、1 より大きい要件があるとインスタンスは不可能になります。 たとえば、入力`[1, 2]`それはいいけど、`[2, 1, 2]`不適切に拘束すると中間要素が成長できないため、伝播によっては失敗する可能性があります。 

もう 1 つの微妙なケースは、初期の大きな 2 乗によってオーバーシュートが発生する場合です。 たとえば、`[2, 3, 2]`の場合、操作を慎重に最小化しないと 2 番目の要素が不必要に 2 乗される可能性があり、その結果、3 番目の要素が複数回強制的に 2 乗されます。 貪欲な戦略では、各ステップで必要な最小限の二乗を常に選択することでこれを回避します。 

3 番目のケースは、次のような長期減少チェーンです。`10010 ... 10000`。 これらのストレスは二乗カウントを繰り返しますが、指数関数的な増加により安全なままであり、要素あたりの少数のステップでの終了が保証されます。
