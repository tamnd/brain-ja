 ## 解決策
 ## 問題の理解

 それぞれの花には、花びらの数と価格という、実際には同じ数の 2 つのプロパティがあります。 と花`k`花びらの価格は正確です`k`コイン。 

店内で入手可能な花の一部を購入する場合があります。 花束は、選択した 2 つの花の花びらの数の差が最大 1 枚である場合にのみ有効です。 この簡単なバージョンではすべての花が個別のオブジェクトであるため、それぞれの花を取得することも、取得しないこともできます。 

目標は、最大の費用をかけて花びらの総数を最大化することです。`m`コイン。 

有益な観察結果がすぐに現れます。コストはすべての花の花びらに等しいため、予算内で花びらを最大化することは、総コストを最大に抑えながら総コストを最大化することとまったく同じです。`m`。 

花びらの違いに対する制約が、この問題を興味深いものにしています。 花束に花が含まれている場合`x`花びらの場合、他のすべての花は次のいずれかを持っている必要があります`x`または`x + 1`花びら。 これより大きなギャップは条件に違反します。 

すべての合計`n`テストケース全体では最大でも`2 · 10^5`。 つまり、`O(n^2)`解決策には大まかに必要になります`4 · 10^10`限界をはるかに超えた最悪の場合の操作。 各テスト ケースを並べ替えてから線形処理を実行することは完全に実現可能です。`O(n log n)`以上`2 · 10^5`要素の操作はわずか数百万回です。 

いくつかの特殊なケースでは、不用意なソリューションが簡単に壊れてしまう可能性があります。 

考慮する：```
n = 3, m = 10
flowers = [2, 2, 2]
```答えは`6`。 常に予算全体を使おうとするソリューションでは、総コストが誤って求められてしまいます。`10`、たとえ`6`花びらは入手可能です。 

考慮する：```
n = 3, m = 7
flowers = [2, 2, 3]
```答えは`7`、すべての花を使用しています。 花びらの値が 1 つだけの花だけを考慮するソリューションでは、最適な花束を見逃してしまいます。 

考慮する：```
n = 4, m = 8
flowers = [1, 3, 3, 3]
```答えは`6`、3枚の花びらを持つ2つの花から得られます。 1枚の花びらを持つ花と3枚の花びらを持つ花を一緒に摂取することは、その差が2であるため違法となります。 

これらの例は、予算制約と花びら差制約の両方を同時に適用する必要があることを示しています。 

## アプローチ

 ブルートフォース ソリューションでは、花のすべてのサブセットを列挙し、その総コストを計算し、花びらの値の違いが最大 1 つであるかどうかを確認し、最も有効な答えを保持します。 

これが機能するのは、有効な花束の定義を直接テストするためです。 残念ながら、`2^n`サブセット。 たとえ`n = 50`これは絶望的ですが、実際の限界は`2 · 10^5`。 

重要な観察は、花を花びらの数で並べ替えた後、すべての有効な花束が、最小値と最大値の違いが最大 1 である連続したセグメントに対応するということです。 

並べ替えが役立つのはなぜですか? 花びらの数を並べ替えるとします。 選択した花に値のみが含まれている場合`x`そして`x + 1`、その後、そのような花がすべて並べ替えられた順序で一緒に表示されます。 その領域の外にある花は、次の値よりも小さい値になります。`x`またはそれより大きい`x + 1`。 

次に、目的について考えてみましょう。 すべての花にはプラスのコストがあるため、セグメントが有効であっても、その合計コストが次の値を超えている場合、`m`、左側から花を削除することによってのみ実現可能性を高めることができます。 これはまさに、2 ポインターとも呼ばれるスライディング ウィンドウが優れた設定です。 

窓口を整備しております`[l, r]`ソートされた配列内。 ウィンドウは次の 2 つの条件を満たす必要があります。 

まず、最大値と最小値の違いは最大 1 です。 

次に、ウィンドウ内の値の合計が以下を超えないこと。`m`。 

これらの条件のいずれかが違反されるたびに、両方が再び真になるまで左ポインタを前方に移動します。 すべての有効なウィンドウは実行可能な花束を表し、花びらの合計数はその合計に等しくなります。 

最大有効ウィンドウ合計が答えです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 最適な 2 つのポインタ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 花びらの数を並べ替えます。 
2. 2 つのポインタを初期化する`l = 0`そして`r = 0`、実行ウィンドウの合計とともに。 
3. 移動してウィンドウを拡張します`r`左から右へ。 追加`a[r]`累計に。 
4. ウィンドウが無効な間に移動します。`l`前進と減算`a[l]`累計から。 
5. 次のいずれかの場合、ウィンドウは無効になります。`a[r] - a[l] > 1`、つまり、花束には 1 つ以上異なる花びらの数が含まれています。 

累計が超過している`m`、つまり花束の値段が高す​​ぎるということです。 
6. ウィンドウが再び有効になったら、現在のウィンドウの合計で答えを更新します。 
7. すべての位置が正しいエンドポイントとして使用されるまで続行します。 
8. 見つかった最大の有効な合計を出力します。 

### なぜ効果があるのか

 常に、ウィンドウにはソートされた配列の連続した範囲が含まれます。 最初の条件は、ウィンドウ内のすべての花の花びら数の違いが最大 1 枚であることを保証します。 2 番目の条件は、花束が予算内に収まることを保証します。 

ウィンドウが無効になった場合、有効なアクションは左側から花を削除することだけです。 すべての花のコストはプラスであるため、ウィンドウをさらに拡大しても過剰な金額を修正することはできません。 同様に、花びらの範囲が大きすぎる場合、最小値を削除すると、まさにその範囲が縮小されます。 

有効な連続セグメントはすべてスイープ中にウィンドウとして表示され、アルゴリズムは実行可能なすべてのセグメントの合計を記録します。 答えは実現可能な最大の合計であるため、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        
        a.sort()
        
        l = 0
        cur_sum = 0
        ans = 0
        
        for r in range(n):
            cur_sum += a[r]
            
            while l <= r and (a[r] - a[l] > 1 or cur_sum > m):
                cur_sum -= a[l]
                l += 1
            
            ans = max(ans, cur_sum)
        
        print(ans)

if __name__ == "__main__":
    solve()
```最初のステップは花を選別することです。 ソート後、値のみを使用するすべての有効なブーケ`x`そして`x + 1`連続したセグメントになります。`cur_sum`花びらの合計を格納します。これは、現在のウィンドウの合計コストでもあります。 これにより、一定時間での予算チェックが可能になります。 

の`while`ループはソリューションの核心です。 両方の制約が同時に成立するまで、左側が縮小し続けます。 単一ではなくループを使用する`if`1 回の削除では有効性を回復できない可能性があるため、これは必須です。 

答えは、ウィンドウが有効になった後にのみ更新されます。 すべての有効なウィンドウは 1 回だけ考慮されるため、記録された最大合計が最適なブーケ値となります。 

Python の整数は、次の値まで自動的に処理します。`10^18`したがって、特別なオーバーフロー処理は必要ありません。
