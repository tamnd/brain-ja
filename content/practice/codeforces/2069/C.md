 ## 解決策
 ## 問題の理解

 すべての要素が 1、2、または 3 である配列内の「美しい」サブシーケンスの数を数えるように求められます。美しいサブシーケンスには少なくとも 3 つの要素が必要で、最初の要素を除くすべての要素の左側に小さな要素があり、最後の要素を除くすべての要素の右側に大きな要素がなければなりません。 言い換えれば、サブシーケンスは、単調にならないように、どこかで増加し、どこかで減少する必要があります。 入力は複数のテスト ケースを提供し、それぞれが配列と配列自体の長さを指定します。 出力は、998244353 を法とする美しいサブシーケンスの数です。 

この制約により、1 つの配列で最大 200,000 個の要素が許可され、すべてのテスト ケースで合計 200,000 個の要素が許可されます。 これにより、考えられるすべてのサブシーケンスを明示的に調べるアプローチは不可能になります。これは、最大 2^200,000 の操作が必要となり、これは実行不可能であるためです。 要素が 1、2、または 3 のみであるという事実は、この小さな値の範囲を利用した解決策が可能であることを示唆しています。 エッジ ケースには、最小長 3 の配列、美しい部分列がないすべての同じ値を持つ配列、単一の増加/減少パターンのみが存在する配列が含まれます。 

たとえば、配列が次の場合、`[1, 1, 1]`の場合、最初の要素より大きい要素がないため、正しい出力は 0 になります。そのため、どのサブシーケンスも美しさの条件を満たすことができません。 左が小さい条件と右が大きい条件をチェックせずにサブシーケンスをカウントする単純なアプローチでは、これらを誤ってカウントします。 

## アプローチ

 ブルートフォース手法では、長さ 3 以上のすべてのサブシーケンスを反復し、それぞれの条件をチェックして、条件を満たすものをカウントします。 すべてのサブシーケンスを明示的に生成するには O(2^n) 時間がかかり、それぞれの美しさをチェックするには最大 O(n) 回の操作が必要です。 n = 200,000 の場合、これは遅すぎます。 

重要な洞察は、値が 1、2、3 に制限されているため、各数値で終わるシーケンスの数と、美しいシーケンス条件を尊重しながらそれらを拡張する方法を追跡することでサブシーケンスをモデル化できるということです。 具体的には、美しい部分列には、どこかに少なくとも 1 つ、2、3 が順番に含まれている必要があります。 これにより、配列をスキャンしながら長さ 1、2、および 3 のサブシーケンスの数を追跡する動的プログラミング アプローチが可能になります。 各要素は、その値に基づいて既存のサブシーケンスを拡張したり、新しいサブシーケンスを開始したりできます。 これにより、問題は指数関数的な複雑さから、テスト ケースごとの n 単位の線形の複雑さに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(2^n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 3 つのカウンターを初期化します。`count1`1 で終わる部分列の場合、`count12`1 を見た 2 で終わるサブシーケンスの場合、`count123`1 と 2 が存在する 3 で終わるサブシーケンスの場合。すべては 0 から始まります。 これらのカウンターは、部分的な美しいシーケンスを形成する方法の数を表します。 
2. 配列内の各要素を反復処理します。 要素が 1 に等しい場合、増分します。`count1`1 で始まる新しいサブシーケンスをここで開始できるため、1 ずつ増加します。 要素が 2 の場合、増分します。`count12`による`count1`1 で終わる各サブシーケンスは、この 2 によって拡張できるためです。要素が 3 に等しい場合、増分します。`count123`による`count12`なぜなら、形式 1→2 の各サブシーケンスをこの 3 で拡張して、美しさの条件を満たすサブシーケンスを形成できるからです。 
3. アレイのスキャンを続行し、上記のようにカウントを更新します。 各カウンターは、完全なサブシーケンス リストではなく、前のカウンターのみに依存します。 モジュロ演算により、カウントがオーバーフローしないことが保証されます。 
4. アレイをスキャンした後、`count123`この配列内の美しいサブシーケンスの総数を保持します。 

これが機能するのは、カウンターがすべての有効なサブシーケンスを増分的に追跡し、要素がサブシーケンスを拡張する順序によって暗黙的に左が小さい条件と右が大きい条件が保証されるためです。 長さ 3 以上のすべての美しいサブシーケンスは、この方法でより小さなサブシーケンスを拡張することによって説明されます。 追加の要素を追加する方法がカウンターに蓄積されるため、3 つを超えるシーケンスは自動的にカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        count1 = 0
        count12 = 0
        count123 = 0
        
        for x in a:
            if x == 1:
                count1 = (count1 + 1) % MOD
            elif x == 2:
                count12 = (count12 + count1) % MOD
            elif x == 3:
                count123 = (count123 + count12) % MOD
        
        print(count123)

if __name__ == "__main__":
    solve()
```カウンターは、不変を維持する方法で更新されます。`count1`2 だけ拡張できるシーケンスをカウントします。`count12`3 だけ拡張できるシーケンスをカウントし、`count123`完成した美しいサブシーケンスをカウントします。 モジュロ演算によりオーバーフローが防止されます。 3 つの整数のみを使用すると、O(1) のスペースが確保されます。

## 特殊なケース

 完全に 3 で構成される配列の場合、`[3,3,3]`、カウンターは残ります`count1=0`、`count12=0`、`count123=0`、したがって、出力は 0 です。2 で始まる配列の場合、`[2,3,1]`、`count1`1 が表示されるまで増加しないため、間違って開始されたシーケンスはカウントされません。
