 ## 解決策
 ## 問題の理解

 次のサイズの長方形グリッドが与えられます。$n \times m$ここで、各セルは整数で表される色を持ちます。 ペイント操作を実行することで、1 回のステップで見知らぬセルのセット (つまり、どのセルも同じ面を共有していない) を選択し、すべて同じ色を選択し、すべてのセルを選択した新しい色で再ペイントすることができます。 目標は、グリッド全体を単一色にするために必要な最小ステップ数を決定することです。 

問題は、操作自体ではなく、多数の操作を要求することです。 重要な観察は、エッジを共有していないセルは見知らぬものとみなされ、斜めに隣接するセルを一緒にペイントできることです。 これは、見知らぬ人のセットが、エッジが側に隣接するセルを接続する隣接グラフ内の独立したセットを形成するセルのセットに対応することを意味します。 

この制約は、効率的なソリューションが必要であることを示唆しています。 と$n, m \le 700$そして最大まで$10^4$テスト ケースでは、セルのすべてのサブセットを反復処理することは不可能です。 すべてのテスト ケースにわたるセルの合計数は次のように制限されます。$5 \cdot 10^5$、だからどれでも$O(n m)$テスト ケースごとの解決策は許容されますが、二次関数は何でも構いません。$n m$遅すぎます。 

明らかではないエッジ ケースには、単一セル グリッド、すべてのセルが最初は同じ色であるグリッド、各色が孤立した位置に表示される市松模様のようなパターンを持つグリッドが含まれます。 たとえば、$1 \times 1$グリッドはステップを必要としませんが、$2 \times 2$チェッカーボードでは、隣り合う 2 つのセルを同時にペイントできないため、すべてのセルを同じ色にするには少なくとも 2 つの手順が必要です。 

## アプローチ

 素朴なアプローチは、プロセスをシミュレートすることです。つまり、見知らぬ同じ色のセルのセットを繰り返し選択し、それらをペイントし、すべてのセルが同じ色になるまで繰り返します。 これは原理的には正しいですが、見知らぬ人の有効なセットを列挙することは組み合わせであるため、遅すぎます。 

重要な観察は、グリッドの隣接構造が 2 部グラフを形成しているということです。 セルを市松模様 (黒と白) で色付けできます。 2 つの黒セルがエッジを共有することはなく、2 つの白セルがエッジを共有することもありません。 したがって、単一色の見知らぬ人の最大セットは、最大でもその色のすべての黒セルまたはすべての白セルになります。 これにより、問題は、黒の正方形と白の正方形に各色のセルが何個あるかを数えるということになります。 次に、ステップを最小限に抑えるために、ターゲット カラーを選択し、黒または白の部分にあるすべての非ターゲット カラーのセルを 1 つのステップで再ペイントできます。 

正式には、色ごとに、その色を持つ黒と白のセルの数を計算します。 特定のターゲットカラーに対して$c$、非の合計数に等しいステップが必要です。$c$黒い四角のセルと非$c$白い正方形のセル。 すべての可能なターゲット色の中で、最小の合計が答えを与えます。 実際には、グリッド上に実際に表示される色のみを考慮する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(nm)) | O(nm) | 遅すぎる |
 | 最適 (チェッカーボード数) | テスト ケースあたり O(nm) | O(nm) または O(固有の色) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、グリッドの寸法を読み取ります。$n$そして$m$そしてグリッド自体。 
2. 各セルに行と列のインデックスに基づいてパリティを割り当てます。$(i + j) \% 2$。 同じパリティを持つセルは、見知らぬセルのセットを形成します。 
3. 黒と白のセルにある各色の出現数を個別に数えます。 2 つの辞書または配列を維持します。`black_count[color]`そして`white_count[color]`。 
4.各色ごとに$c$グリッドに表示される、選択した場合に必要なペイント ステップの数を計算します。$c$ターゲットカラーとして。 式は、黒のセルの合計数から色の黒のセルを引いたものです。$c$プラス白セルの総数から色の白セルを差し引いたもの$c$。 
5. すべての色の中で、計算された最小ステップ数を選択します。 
6. テスト ケースのこの最小値を出力します。 

機能する理由: ストレンジャー制約に違反することなく、セルの各パリティ セットを 1 つのステップでペイントできます。 各パリティ内の各色のセルを数えることで、すべてをどの色に変換するかを最適に選択できます。 同じパリティの 2 つのセルは横に隣接していないため、それらを一緒にペイントすることが常に許可され、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        grid = [list(map(int, input().split())) for _ in range(n)]
        
        black_count = {}
        white_count = {}
        total_black = total_white = 0
        
        for i in range(n):
            for j in range(m):
                color = grid[i][j]
                if (i + j) % 2 == 0:
                    black_count[color] = black_count.get(color, 0) + 1
                    total_black += 1
                else:
                    white_count[color] = white_count.get(color, 0) + 1
                    total_white += 1
        
        colors = set(black_count.keys()) | set(white_count.keys())
        min_steps = n * m
        for color in colors:
            steps = (total_black - black_count.get(color, 0)) + (total_white - white_count.get(color, 0))
            if steps < min_steps:
                min_steps = steps
        
        print(min_steps)

if __name__ == "__main__":
    solve()
```このコードは、まず黒と白のセルの合計数を計算し、次に各パリティに各色が何個出現するかをカウントします。 これらのカウントを使用して、グリッド全体を各候補色に変換するために必要なステップを計算し、最小値を選択します。 使用する`get(color, 0)`パリティにない色が KeyError を引き起こさないようにします。 使用する`(i + j) % 2`グリッドを 2 つの素なセットに正しく分割します。

これは、パリティ ベースのグループを正しくカウントする方法と、最小値がどのように決定されるかを示しています。
