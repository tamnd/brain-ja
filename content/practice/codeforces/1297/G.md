 ## 問題の理解

 目標値が与えられている$m$そして、桁が正確に乗算されるすべての正の整数を考慮するように求められました。$m$。 これらの整数は一般に無限セットを形成し、このセットを数値の昇順にソートして、$k$- 番目の要素。 

キーオブジェクトは単なる数字ではなく、数字の並びです。 有効な各数値は 1 から 9 までの一連の数字であり、その積は次のとおりです。$m$。 数字の 0 は、積を強制的にゼロにするため不可能であり、正の値と一致することはできません。$m$。 このようなすべてのシーケンスの中で、これらを整数として比較します。これは、値の増加に合わせて数値比較を行う辞書編集順を意味します。 

この制約により、組み合わせ生成の問題が発生します。 以来$m \le 10^9$そして$k \le 10^9$、すべての有効な数値を総当たり的に列挙することは不可能です。 場合によっては、有効な因数分解の数が少ない場合でも、桁の置換と長さの増加によって指数関数的に爆発的に増加する可能性があります。 枝刈りをせずにすべての候補、あるいはすべての因子の組み合わせを明示的に構築するアプローチは失敗します。 

微妙な問題は、同じ複数の数字セットが並べ替え後に多数の異なる数字を生成することです。 たとえば、数字$[2, 2, 6]$生産する$226, 262, 622$。 これらはすべて個別にカウントし、正しく並べ替える必要があります。 もう 1 つのエッジケースは次のような場合です$m$桁数が 2 ～ 9 に制限されているため、7 より大きい素因数が含まれています。$m$係数が 11 や 13 の場合、すぐには解は存在しません。 

再帰的に因数分解を試みる素朴なアプローチ$m$数値に変換してすべての順列を保存すると、時間やメモリ、またはカウントが間違って複製されることによって、暗黙のうちに失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。1 から 9 までのすべての数字のシーケンスを生成し、それらの積を計算し、次と等しいものを収集します。$m$。 次に、リストを並べ替えて、$k$- 番目の要素。 これは原理的には正しいですが、完全に実行不可能です。 長さを 10 桁に制限しても、$9^{10}$シーケンスをチェックし、それぞれをチェックすることは限界をはるかに超えています。 

構造上の観察によると、桁上の乗算は制約されており、因数分解可能です。 有効な各数値は、その積が次のような複数の桁セットに対応します。$m$。 したがって、数値を直接構築する代わりに、まず分解します。$m$数字 2 から 9 を使用して、考えられるすべての数字と因数の組み合わせに変換します。数字 1 は、積を変更せず、順序と長さにのみ影響するため、特別です。 

因子のマルチセットを取得したら、第 2 段階では、有効な数値を形成するその桁の順列の数を数えます。 これにより、問題は因数分解の列挙に縮小されます。$m$数値自体を列挙するのではなく、許可された数字に変換してから順列を数えます。 

に答えるには、$k$- 番目のクエリでは、すべての数値をリストする必要はありません。 辞書編集上の昇順で因数分解を生成し、それぞれが寄与する順列の数をカウントできます。 からカウントを引きます$k$正しい構造が見つかるまで、実際の数値を辞書編集順に貪欲に構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | 指数 | 指数 | 遅すぎる |
 | 因子 DP + 組み合わせ論 + 構築 |$O(\log^2 m + S)$|$O(S)$| 承認済み |

 ここ$S$有効な桁マルチセットの数ですが、2 ～ 9 桁への因数分解の制約により小さくなります。 

## アルゴリズムのチュートリアル

 ### ステップ 1: 主要な実現可能性を抽出する

 分裂を繰り返す$m$9 から 2 までの数字で計算します。$[2..9]$、残りの値が 1 でない場合、解は存在しません。 これにより、有効な数字の因数分解のみを扱うことが保証されます。 

### ステップ 2: 桁の複数集合の因数分解を構築する

 再帰的に因数分解します$m$9 から 2 までの数字を使用します。各ステップで数字を選択します。$d$現在の剰余を除算し、再帰的に実行します。$m / d$。 成功したパスごとに、その積が次のような複数セットの数字が生成されます。$m$。 このようなマルチセットをすべて保存します。 

すべての有効な数値は、順序を無視して複数の桁セットに一意に対応するため、この手順は正しいです。 

### ステップ 3: 各マルチセットの順列を数える

 カウントのあるマルチセットの場合$c_1, c_2, \dots$、順列の数は次のとおりです。$$\frac{(\sum c_i)!}{\prod c_i!}$$これを使用して、各因数分解が寄与する数値の数を計算します。 

### ステップ 4: 因数分解を辞書順に並べ替える

 数字のマルチセットを、ソートされた数字リストの辞書順に並べ替えます。 これにより、数値をトラバースするときに、最小表現の昇順で暗黙的に数値をトラバースすることが保証されます。 

### ステップ 5: k 番目の構造を特定する

 ソートされた因数分解を繰り返し、順列カウントをから引きます。$k$。 いつ$k$がブロック内にある場合、答えはこの数字のマルチセットから得られることがわかります。 

### ステップ 6: マルチセット内の k 番目の数値を構築する

 数字を一桁ずつ構築していきます。 各位置で、利用可能な各桁を昇順に配置して、どれだけの順列が残っているかを計算します。 カウントが未満の場合$k$、スキップします。 それ以外の場合は、その数字を修正して続行します。 標準的な組み合わせランキングです。 

### なぜ効果があるのか

 すべての有効な数値は、正確に 1 つの桁のマルチセットとそのマルチセットの 1 つの順列に対応します。 このアルゴリズムは、解空間全体をマルチセットで定義された互いに素なブロックに分割します。 各ブロック内で、順列ランキングが決定論的に実行されます。 どちらのレベルでも辞書編集的な順序が維持されるため、数値がスキップされたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import factorial
from collections import Counter
from functools import lru_cache

# precompute factorials up to reasonable size
fact = [1] * 50
for i in range(1, 50):
    fact[i] = fact[i - 1] * i

def perm_count(cnt):
    total = sum(cnt.values())
    res = fact[total]
    for v in cnt.values():
        res //= fact[v]
    return res

# generate all factorizations of m into digits 2..9
def gen(m, start=9):
    res = []

    def dfs(x, start, cur):
        if x == 1:
            res.append(tuple(sorted(cur)))
            return
        for d in range(start, 1, -1):
            if x % d == 0:
                cur.append(d)
                dfs(x // d, d, cur)
                cur.pop()

    dfs(m, start, [])
    return list(set(res))

def kth_from_multiset(multiset, k):
    cnt = Counter(multiset)
    digits = sorted(cnt.keys())

    total_len = len(multiset)

    res = []
    for _ in range(total_len):
        for d in digits:
            if cnt[d] == 0:
                continue
            cnt[d] -= 1
            ways = perm_count(cnt)
            if ways < k:
                k -= ways
                cnt[d] += 1
            else:
                res.append(str(d))
                break
    return ''.join(res)

def solve():
    m, k = map(int, input().split())

    factorizations = gen(m)

    # sort lexicographically
    factorizations.sort()

    for fac in factorizations:
        cnt = Counter(fac)
        cnt_ways = perm_count(cnt)
        if k > cnt_ways:
            k -= cnt_ways
        else:
            return kth_from_multiset(fac, k)

    return "-1"

print(solve())
```因数分解ジェネレーターは、すべての有効な桁分解を構築します。 ソートにより、候補構造の決定論的な走査が保証されます。 次に、順列ランキング関数は、貪欲なカウントを使用して、選択された構造内の正確な k 番目の数値を構築します。 

微妙な点は、`Counter`各桁の配置後に順列カウントを再計算します。 これが必要なのは、各部分割り当てにより、使用可能な順列が非線形に減少するためです。
