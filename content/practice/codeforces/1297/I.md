 ## 解決策
 ## 問題の理解

 一定の長さの 1D ボード上に次々に到着する一連の水平セグメントが与えられます。$d$。 各セグメントは、地面に接触するか、以前に配置されたブロックの上部に接触するまで垂直に落下するブロックを表します。 一度何かに触れると、永続的に付着するか、連鎖反応を引き起こして既存のブロックを消去する可能性があります。 

重要なルールは幾何学的包含に依存します。 ブロック$a$ブロックを完全にカバーすると言われています$b$もし$a$スーパーセット区間にわたる：$l_a \le l_b \le r_b \le r_a$。 新しいブロックが着地すると、まず既存の何かに触れるまで落下します。 接触の瞬間、2つのケースは分岐します。 覆われていないブロックに触れると、そこにくっついて構造の一部になります。 代わりに、接触したすべてのブロックが完全に覆われている場合、それらの覆われたブロックは消去され、落下するブロックは再び付着するか消去を続けるまで下降し続けます。 

微妙なのは、「コンタクト」は純粋に垂直方向の積み重ねであるのに対し、「カバレッジ」は純粋に水平方向であることです。 ブロックは他の多くのブロックと幾何学的に重なることができますが、その間隔に完全に含まれているブロックのみが蒸発の対象となります。 

ブロックをオンラインで処理する必要があります。 挿入するたびに、合計でブロックが何個残っているかが報告されます。 

制約$n, d \le 10^5$いかなる解も線形に近いか、または$O(n \log n)$。 新しいブロックと既存のすべてのブロックの間の相互作用をシミュレートするアプローチは、ブロックが更新中に他の多くのブロックと相互作用する可能性があるため、二次的な動作を直接リスクにさらします。 私たちが実行する操作は、高速範囲クエリと一定間隔での更新をサポートする必要があります。 

すべての既存のブロックを明示的に追跡し、どのブロックがタッチまたはカバーされているかを繰り返しチェックする単純なシミュレーションは、すべての新しいブロックが範囲の大部分に及ぶとすぐに失敗します。これは、挿入のたびにアクティブなブロックの大部分がスキャンされる可能性があるためです。 

素朴な貪欲推論による自明ではない失敗例は、ブロックが既存の構造と部分的に重なる場合に発生します。 たとえば、ブロックの場合、$A=[1,3]$、 それから$B=[2,4]$、 それから$C=[1,4]$、素朴な直観は次のように示唆するかもしれません。$C$常に重なっているものをすべて削除します。 しかし、$C$接触の瞬間に実際にカバーしているブロックを蒸発させるだけであり、接触が地面で起こるか中間ブロックで起こるかによって相互作用が変化します。 「ファーストコンタクト」への依存により、局所的な推論が不十分になります。 

## アプローチ

 主要な問題は、間隔を挿入するたびに既存の構造の範囲が変更され、現在のレイヤー化されたジオメトリに依存する可能性があることです。 ただし、垂直プロセスは、より簡単な方法で再解釈できます。 

落下する物理をシミュレートする代わりに、各操作後の現在の安定したスタックを表す一連の素の「アクティブ ブロック」として最終構造を追跡します。 各ブロックは、最終構造の一部として存続するか、そのブロックを完全にカバーする後続のブロックによって削除されますが、接触の連鎖を通じてそのブロックに到達することもできます。 

重要な観察は、重要なのは垂直方向の積み重ねの履歴ではなく、新たに挿入された間隔が露出した接触点によってブロックされることなく既存の構造を「橋渡し」できるかどうかであるということです。 ブロックは、それをカバーし、カバーされていない障害物に遭遇することなくブロックに到達できる後の間隔までに完全に除去されない場合にのみ存続します。 

これは、「最上位のアクティブ層」を追跡し、区間が完全にきれいにカバー可能かどうかを効率的に判断するセグメントにわたる動的構造の維持に変換できます。 

これを解決する標準的な方法は、位置が現在アクティブなブロックによってカバーされているかどうかを格納するセグメント ツリーを座標軸上に維持することと、同じブロック ID によってカバーされるという点で間隔が均一であるかどうかを識別できる構造を維持することです。 現在、間隔全体が同じブロック (または空) でカバーされている場合、新しいブロックでそれを上書きできます。 そうしないと、付着して停止します。 

同様に、各位置をカバーする現在の「トップ ブロック ID」を格納するセグメント ツリーを遅延伝播で維持します。 新しいブロックの場合$[l, r]$では、その間隔内のすべての位置が現在同じ先頭ブロック ID を持っているかどうかをクエリします。 「はい」の場合、それは均一に接続され、その領域を上書きできることを意味します。 そうでない場合は、不均一な構造に遭遇するため、最初の接触で固着し、欠失に寄与しないことを意味します。 

また、生き残ったブロックの数も維持します。 ブロックが領域を完全に上書きすると、上書きされた ID に対応する個別の生き残るブロックの数が減ります。 

重要な洞察は、蒸発は新しいブロックが領域を完全かつ均一に支配する場合にのみ発生するということです。 混合接触はさらなる下方伝播を防ぎ、相互作用を単純な付着に減らします。 

これにより、セグメント ツリーに対する範囲クエリと範囲割り当ての問題が軽減されます。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(n^2)$|$O(n)$| 遅すぎる |
 | 遅延伝播を使用したセグメント ツリー |$O(n \log d)$|$O(d)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 座標範囲にわたってセグメント ツリーを構築します。$[1, d]$ここで、各ノードは、間隔が単一のブロック ID によって均一にカバーされているか、混合されているかを格納します。 これは、新しいブロックが既存の構造ときれいに相互作用するかどうかを迅速に検出するために必要です。 
2. 受信ブロックごとに$[l_i, r_i]$、セグメント ツリーをクエリして、間隔全体のカバレッジが現在均一であるかどうかを判断します。 これにより、ブロックが下方に伝播するか (均一)、最初の接触ですぐに停止するか (不均一) がわかります。 
3. 間隔が不均一な場合は、初接触でブロックが付着したものとして扱います。 この場合、完全に覆われた構造は削除されないため、生き残ったブロックの数は変わりません。 
4. 間隔が均一である場合、その間隔をカバーする現在のブロック ID を特定します。 つまり、新しいブロックがその領域を完全に上書きします。 古いブロックは完全に消去されているため、その古いブロック (存在する場合) の生存数をデクリメントします。 
5. 次に、セグメント ツリーを更新します。$[l_i, r_i]$、新しいブロック ID を間隔全体のトップ カバー ID として割り当てます。 これは、蒸発後の新しい安定層を表します。 
6. 各ブロックを処理した後、現在残っているブロックの数を出力します。 

重要な不変条件は、各セグメント ツリー ノードが、そのセグメントをカバーする最上位のブロックの ID を正確に表すこと、またはそのセグメント内で複数のブロックが異なる場合は混合状態を表すことです。 これにより、ある間隔にわたるクエリがその間隔が均一かどうかを正確に反映するようになります。 均質性はまさに、ブロックが完全に下方に相互作用し、前のブロックを蒸発させる可能性があるために必要な条件です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.tree = [0] * (4 * n)
        self.lazy = [0] * (4 * n)

    def push(self, v):
        if self.lazy[v]:
            self.tree[v*2] = self.lazy[v]
            self.tree[v*2+1] = self.lazy[v]
            self.lazy[v*2] = self.lazy[v]
            self.lazy[v*2+1] = self.lazy[v]
            self.lazy[v] = 0

    def update(self, v, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            self.tree[v] = val
            self.lazy[v] = val
            return
        self.push(v)
        m = (l + r) // 2
        if ql <= m:
            self.update(v*2, l, m, ql, qr, val)
        if qr > m:
            self.update(v*2+1, m+1, r, ql, qr, val)

        if self.tree[v*2] == self.tree[v*2+1]:
            self.tree[v] = self.tree[v*2]
        else:
            self.tree[v] = -1

    def query(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.tree[v]
        self.push(v)
        m = (l + r) // 2
        res = None
        if ql <= m:
            res = self.query(v*2, l, m, ql, qr)
        if qr > m:
            right = self.query(v*2+1, m+1, r, ql, qr)
            if res is None:
                res = right
            elif res != right:
                return -1
            elif res == -1:
                return -1
        return res if res is not None else -1

def solve():
    n, d = map(int, input().split())
    st = SegTree(d)
    alive = set()
    res = []

    for i in range(1, n+1):
        l, r = map(int, input().split())
        cur = st.query(1, 1, d, l, r)

        if cur == -1:
            res.append(len(alive) + 1)
        else:
            if cur != 0:
                alive.discard(cur)
            alive.add(i)
            st.update(1, 1, d, l, r, i)
            res.append(len(alive))

    print("\n".join(map(str, res)))

if __name__ == "__main__":
    solve()
```セグメント ツリーは、各間隔にわたって最上位のブロックの ID を維持します。 値 0 は空のグラウンドを表し、正の整数はそのセグメントを完全に割り当てた最後のブロックの ID を表します。 クエリ関数は、間隔が均一であるかどうかをチェックします。 均一でない場合は何も削除せずにブロックを貼り付けます。 

セット`alive`どのブロック ID が現在生き残っているかを追跡します。 ブロックが領域を上書きすると、以前の均一所有者は削除されます。 更新により、間隔全体にわたって新しいブロック ID が割り当てられ、今後のクエリで正しい上位構造が参照されるようになります。 

微妙な点は、完全に均一な間隔のみが削除をトリガーすることです。 混合間隔は最初の接触ブロッキングに対応し、蒸発を完全に防ぎます。

 ## 特殊なケース

 主なエッジケースは、すべての間隔が同一である場合です。 その状況では、新しいブロックごとに以前の構造が完全に上書きされます。 セグメント ツリーは常に均一なカバレッジを報告するため、挿入ごとに古いブロックを 1 つだけ削除し、それを置き換えます。 システムは、全体を通じて単一の生き残ったブロックを正しく維持します。 

もう 1 つのエッジ ケースは、間隔が次のような階段パターンを形成する場合です。$[1,2], [2,3], [3,4], \dots$。 新しいブロックはそれぞれ、以前のブロックと部分的にのみ重複するため、不均一なカバレッジ クエリが生成されます。 スパン全体で完全に均一な間隔はないため、アルゴリズムはここでは削除を実行しません。 これにより、すべてのブロックが正しく保存されます。 

最後のエッジケースは、次のような完全にネストされたシーケンスです。$[1,10], [2,9], [3,8], \dots$。 新しい各ブロックは、アクティブ領域が縮小されるまで均一なカバレッジを示します。 セグメント ツリーにより、各上書きの一貫性が保証され、部分的な不一致が防止されるため、時間の経過とともにネストが単一の主要なブロックに崩壊します。
