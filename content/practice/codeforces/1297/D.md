 ## 解決策
 ## 問題の理解

 各従業員には固定の基本給があり、全従業員の合計ボーナスが正確に一致するように追加の整数ボーナスを分配することができます。`k`。 ボーナスを追加した後の各従業員の最終給与は、元の給与に割り当てられたボーナスを加えた金額となります。 

分布を形成する 3 つの構造要件があります。 まず、給与による従業員の順位が変わってはなりません。そのため、ある従業員がもともと他の従業員よりも給与が高かったとしても、ボーナス後も厳密に給与が高くなる必要があります。 第二に、すべての最終給与は区別されなければなりません。 第三に、すべての有効な分配のうち、最終給与の最高額をできるだけ小さくしたいと考えています。 

重要な点は、ボーナスは自由に割り当てることができるが、順序を維持し、衝突を避け、最終的な最大値を最小限に抑えながら合計を固定予算にまとめる必要があるということです。 

制約は、最悪の場合の解決策を示唆します。$O(n \log n)$テストケースごとに。 まで$10^5$従業員の合計、$O(n^2)$または要素ごとにリニアスキャンを繰り返すと遅すぎます。 並べ替えは許可されますが、ネストされた調整や候補値ごとの実行可能性チェックの繰り返しを伴うものは、最悪の場合の入力では失敗します。 

厳密な順序付けと一意性の組み合わせにより、微妙な問題が発生します。 2 人の従業員の調整値が 1 であっても近すぎる場合、「すべて異なる」条件は破棄されます。 もう 1 つの失敗モードは、順序は尊重するが合計のグローバルな実現可能性を無視する貪欲な割り当てです。`k`、必要な合計を簡単にオーバーシュートまたはアンダーシュートする可能性があります。 

## アプローチ

 直接的なアプローチは、制約を維持しながらボーナスを任意に分配することを考えることです。 次の最終給与が前回よりも少なくとも 1 つ多いことを常に確認しながら、最高給与から順にボーナスを割り当てようとする場合があります。 これにより、順序と一意性が維持されますが、合計は制御されません。 次に、正確にヒットするように値を調整しようとすると、`k`、ローカルな変更がグローバルに伝播するという複雑なバランスの問題に陥ります。 

もう 1 つの強引な視点は、最終給与を元の給与よりも大きくなる厳密な増加シーケンスとして考えることです。 最終的な給与の最高額を推測してみることもできます`M`そして、その下に最小の有効な値を貪欲に割り当てます。 固定の場合`M`、実現可能性のチェックは直線的です。 でも全部試してみると`M`値を指定すると検索空間が大きくなり、単純な二分探索でもシーケンスを慎重に構築する必要があります。 

重要な洞察は、視点を逆転させることです。ボーナスを直接分配する代わりに、最終給与を下限によって制約された厳密な増加シーケンスとして扱います。`a_i`。 従業員を分類すると、`a_i`、最終値は厳密に増加する必要があり、少なくともそれぞれが増加する必要があることを強制します。`a_i`。 これは問題を、合計制約の下で辞書編集上最小限の実現可能な増加シーケンスを構築し、それを均一に上方にシフトして正確に消費するように変換します。`k`。 

建設は 2 段階で行われます。 まず、順序付けと一意性を満たす最小限の有効な最終配列を構築します。 次に、差異を維持しながらすべての最終値を制御された方法で増加させることで、制約を破ることなく残りの予算を最後から後方に均等に分配できることがわかります。 この場合、構造は組み合わせではなく直線的かつ貪欲になります。

 ## アルゴリズムのチュートリアル

 独自の指標を追跡しながら、まず従業員を基本給で並べ替えます。 

1.従業員を次の基準で並べ替えます`a_i`昇順で。 最終的な順序は元の順序と一致する必要があるため、これにより、必要な最終的な順序が修正されます。 
2. 暫定的な最終アレイの構築を開始します`b`、 どこ`b[i]`は、i 番目に小さい従業員の最終給与を表します。 初期化する`b[0] = a[0]`。 
3. 次の従業員ごとに、`b[i] = max(a[i], b[i-1] + 1)`。 これにより、元の順序に誰も違反しないことと、すべての最終値が厳密に増加し続けるという 2 つのことが同時に保証されます。 

これが機能する理由は、並べ替えると順序制約が単純な単調な要件になり、一意性が直接の「+1 ギャップ」制約になるためです。 

1. 必要な基本合計の合計を計算します。`S = sum(b[i] - a[i])`。 これは、制約の下で可能な最小限のボーナス配分です。 
2. もし`S > k`、インスタンスは不可能ですが、問題は実現可能性を保証します。 
3. しましょう`rem = k - S`。 次に、制約を破ることなく、この残りの量を分配する必要があります。 
4. 最後の従業員から逆方向に繰り返します。 各ポジションで安全に増やすことができます`b[i]`より厳密に大きい限り`b[i-1] + 1`違反されていません。 実際には増やすことができます`b[i]`隣接するものに対して有効である限り、順序付けには影響しません。 

より単純な見方は、後の要素を増やしても最大値が上方に押し上げられるだけであり、前の制約には影響しないということです。 そこで配布します`rem`貪欲に右から左へ。 

1. 最後に計算します`d[i] = b[i] - a[i]`元の順序で。 

### なぜ効果があるのか

 ソートされた構造により、順序性と区別性を満たす最小限の構造が強制されます。 要素を減らすと下限に違反するため、有効なソリューションは、少なくともこの貪欲なベースラインと同じ大きさの最終値を持たなければなりません。`a_i`または厳密な順序を破ります。 このベースラインが固定されると、残りの自由度は、順序を維持しながら要素を均一に増加させることだけになります。これは、将来の制約に影響を与えないため、常に右側から適用するのが最も安全です。 これにより、正確に到達することが保証されます`k`単調性や独自性を損なうことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    order = sorted(range(n), key=lambda i: a[i])
    pos = [0] * n
    
    b = [0] * n
    b[0] = a[order[0]]
    
    pos[order[0]] = 0
    
    for i in range(1, n):
        idx = order[i]
        prev_idx = order[i-1]
        pos[idx] = i
        b[i] = max(a[idx], b[i-1] + 1)
    
    # compute minimal required bonus
    base = sum(b[i] - a[order[i]] for i in range(n))
    rem = k - base
    
    # distribute remaining from right to left
    for i in range(n-1, -1, -1):
        if rem == 0:
            break
        if i == 0:
            add = rem
        else:
            # we can safely increase without breaking ordering
            add = rem
        
        b[i] += add
        rem -= add
    
    ans = [0] * n
    for i in range(n):
        ans[order[i]] = b[i] - a[order[i]]
    
    print(*ans)

t = int(input())
for _ in range(t):
    solve()
```この解決策は、すべての制約がローカルの近隣関係に限定されるように従業員を分類することから始まります。 の建設`b`元の給与を超える最小の有効な厳密な増加シーケンスを強制します。 残りの予算は、将来の要素を制約しないため、右端の位置に押し込まれます。 

重要な実装の詳細は、元のインデックスへのマッピングを維持することです。 これがないと、構築されたシーケンスと必要な出力順序との間の対応が失われます。 

## 実用的な例

 ### 例 1

 入力:```
n=4, k=1
a = [3, 1, 4, 2]
```ソート順は、`[1, 2, 3, 4]`値による → インデックス`[1, 3, 0, 2]`。 

私たちは最小限のものを構築します`b`:

 | ステップ | 従業員 | | 前の b | 計算された b |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 1 | - | 1 |
 | 1 | 3 | 2 | 1 | 2 |
 | 2 | 0 | 3 | 2 | 3 |
 | 3 | 2 | 4 | 3 | 4 |

 したがって、最小限のボーナスは`[0,0,0,0]`、合計は 0、rem = 1。 

最後の要素に 1 を追加 → 最終`b = [1,2,3,5]`ソートされた順序で。 逆マッピングすると有効な分布が得られます。 

これにより、右端の要素が順序を壊すことなく残りを吸収することが確認されます。

最小限のビルド`b`:

 | ステップ | | 前へ | b |
 | --- | --- | --- | --- |

 基本ボーナスは 0、レム = 3 です。 

最後の要素に 3 を追加します。`b = [2, 13]`。

import sys, io

def run(inp: str) -> str:

    input = sys.stdin.readline

    def solve():

        return " ".join(map(str, ans))

    t = int(input())

    for _ in range(t):
        out.append(solve())
    return "\n".join(out)

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です`n = 1`。 アルゴリズムは即座にボーナス全額をその従業員に割り当てますが、順序付けの制約が存在しないため、この構造は依然として有効です。 

もう1つのケースは、給与が逆の順序である場合です。 ソートされた構造により、常に昇順で処理されるため、極端な入力の順列であっても、きれいな単調シーケンスに減ります。 最後のマッピング手順では、元の位置が正しく復元されます。 

最後の微妙なケースは次のような場合です。`k = 0`。 ベースラインの構築はすでに最小限の条件を満たしているため、再分配は発生しません。 結果は単純に全従業員のボーナスがゼロになり、すべての制約が満たされたままになります。
