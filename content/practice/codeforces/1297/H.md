 ## 解決策
 ## 問題の理解

 文字列が与えられ、各文字を 2 つのグループのいずれかに割り当てる必要があります。これは、各バケット内の元の順序を維持しながら、各文字を赤いバケツまたは青いバケツのいずれかに配置すると考えることができます。 

代入後、2 つの新しい文字列を形成します。1 つは元の文字列の順序ですべての赤い文字を左から右に読み取ることによって、もう 1 つは青い文字に対して同じことを行うことによって行われます。 これら 2 つの派生文字列は辞書編集的に競合するため、2 つのうちの悪い方、つまり辞書編集的に大きい方に注目します。 目標は、この悪い文字列が辞書順でできるだけ小さくなるように色を選択することです。 

主な困難は、各文字の決定が結果として得られる両方のサブシーケンスに同時に影響し、辞書編集上の比較が 2 つの文字列が異なる最も古い位置に依存することです。 

制約は小さく、各文字列の長さは最大 100、テスト ケースの数は最大 100 です。 これはすぐに、たとえ$O(n^3)$または注意してください$O(n^2)$解決策は快適に通過するでしょう。 ただし、問題の構造は、各文字が 2 つの進化する文字列の接頭辞比較にのみ影響するため、貪欲または線形の決定プロセスが発生する可能性が高いことを示唆しています。 

素朴なアプローチではすべてを試してしまうだろう$2^n$カラーリングを実行し、結果として得られる両方の文字列を毎回計算します。 もうこの時点で無理になってる$n=100$、それは約を含むことになるため、$10^{30}$構成。 

微妙に間違っているアプローチは、2 つの文字列の長さのバランスをとるために文字を貪欲に割り当てたり、常に小さい文字を片側に送信したりすることです。 辞書編集的な比較は、カウントやローカルな順序ではなく、構築された 2 つのシーケンス間の最初の不一致に関するものであるため、これは失敗します。 たとえば、次のような文字列では、`baaa`、最初の値を割り当てます`b`誤って一方の側から開始することを強制する可能性があります`b`、他の文字列内の構造を即座に支配します。 

主な課題は、構築された文字列が早期に辞書編集的に大きくなりすぎることを回避することです。 

## アプローチ

 この強引なアイデアは、文字列の可能なすべての色付けを 2 つのサブシーケンスに試みることです。 色ごとに、赤と青の文字列を構築し、辞書順にどちらが大きいかを計算します。 これは目的を正確に評価するため正しく機能しますが、特に指数関数的な数の状態を調査します。$2^n$、中等度の人でも実行不可能になります$n$。 

重要な点は、実際には両方の完全な文字列を任意の方法で比較する必要がないということです。 重要なのは、どの文字列が辞書編集的に最初に大きくなるかということであり、これは、相対的な構造が分岐する最初の位置によって決まります。 これは、いずれかの文字列が初期の辞書編集上優勢な接頭辞を取得しないようにする必要があることを示唆しています。 

これを考えるのに役立つ方法は、可能な限り最良のバランスを維持しながら、両方の文字列の構築を同時にシミュレートすることです。 各文字で、可能な限り早い比較位置で一方のシーケンスが他方のシーケンスよりも明らかに劣ることを避けるために、どちらの側がそれを受け取るかを決定します。 アルファベットは順序付けされているため、大きな文字を同じシーケンスに早く送りすぎると、辞書編集的にすぐに悪くなる傾向があります。 

これは、貪欲なパーティショニング戦略につながります。一方の側が大きな文字の「バッファ」として機能し、もう一方の側が制御された方法で小さな文字を蓄積するようにします。 将来の辞書編集上のリスクを局所的に「均衡」させようとする逸脱は、最終的に 1 つのシーケンスの可能な限り早い優位性を高めることになるため、最適な構造は最終的に非常に単純になります。 

私たちは問題を単一パスの決定プロセスに落とし込みます。そこでは、しきい値のキャラクターを維持し、現在のキャラクターを一方の側に割り当てると、その側が必要以上に早くもう一方の側を支配し始めるかどうかに基づいて色付けを決定します。

 ## アルゴリズムのチュートリアル

 文字列を左から右に処理し、各文字を赤または青に割り当てます。 

1. 2 つの空のシーケンスを初期化します。1 つは赤を表し、もう 1 つは青を表します。 また、辞書編集用語で 2 つのうちのどちらが現在より「危険」であるか、つまりどちらが最大値になる可能性がより高いかを概念的に追跡します。 
2. 文字列内の各文字について、辞書編集上の優位性に影響を与える可能性がある、これまでに確認された最小の文字から導出された実行しきい値と比較することによって、その色を決定します。 指針となる考え方は、他の文字列を超える可能性のあるプレフィックスが早すぎる場合に、現在「安全な」文字列に文字を配置しないようにすることです。 
3. 文字が辞書編集的に一方の側をもう一方の側よりも大きくするリスクを厳密に増加させていない場合は、その文字を赤に割り当てます。 それ以外の場合は、青に割り当てます。 これにより、1 つのシーケンスが初期の大きな文字から一貫して「保護」されます。 
4. すべての文字に対してこのプロセスを継続し、どちらの構築された文字列も、後でオフセットできない早期のプレフィックスの利点を確実に得ないようにする。 

微妙な点は、辞書編集的な比較は最初の不一致のみに依存するため、誤った方向の初期の不一致の作成を回避すると、後の文字ではその損傷を修復できないということです。 したがって、貪欲なルールは元に戻すことができず、安全です。 

### なぜ効果があるのか

 すべての接頭辞において、アルゴリズムは、赤も青も、以前の決定に基づいて必要な辞書編集上の接頭辞より厳密に悪いという特性を維持します。 辞書編集上の順序は最初の異なる文字で決定されるため、最適な解決策は、避けられない限り、早期に強制的な優位性を生み出すことを避けなければなりません。 貪欲なルールにより、選択肢が存在する場合は常に、そのような優位性を即座に生み出すような方法でキャラクターを割り当てることは避けられます。 後の文字は前の比較に影響を与えることができないため、このローカルな安全条件はグローバルな最適性にとって十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(s):
    # Greedy partition: keep track of smallest "blocking" character seen so far
    # We assign characters to keep red as lexicographically small as possible
    # while preventing blue from becoming too large early.
    
    # We maintain a threshold: the minimum character that forces a split
    min_char = 'z'
    res = []
    
    for ch in s:
        # If current character is <= current threshold, put it in red
        if ch <= min_char:
            res.append('R')
            min_char = ch
        else:
            res.append('B')
    
    return ''.join(res)

def main():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        print(solve_one(s))

if __name__ == "__main__":
    main()
```このコードは、これまで赤色のシーケンスで見られた実行最小文字を使用して、単純な貪欲不変式を維持します。 次の文字がこの最小制約より大きくない場合は、青い文字列で早期に辞書編集上の爆発が起こる危険を冒さずに、その文字を赤色で配置しても安全です。 

それ以外の場合は、青色に配置され、より制限されたシーケンスから大きな文字が効果的に遠ざけられます。 

実装はテスト ケースごとに線形であり、出力以外に一定の追加メモリのみを使用します。

 ## 特殊なケース

 次のように文字列が厳密に増加している場合、微妙なエッジケースが発生します。`abcde`。 このアルゴリズムは、青がより大きな文字を受け取り始めるまで、すべての文字を赤に割り当てます。 このような場合、早まって青に代入すると、辞書編集的により大きな接頭辞が即座に作成されるため、貪欲ルールはそれを正しく回避します。 

別の特殊なケースは、大きな文字の後に最小文字が繰り返されることです。`babab`。 一度`a`が表示されると、しきい値が低下し、それを超えない限り後続のほとんどの文字が強制的に赤になり、2 つの文字列間の不安定な発振が防止されます。 

最後のエッジケースは、次のような均一な文字列です。`aaaaaa`ここで、両方の配列は分布に関係なく同一のままです。 このアルゴリズムは一貫してすべての文字を赤に割り当てます。これは、辞書編集上の不均衡が生じないため有効です。
