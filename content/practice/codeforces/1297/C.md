 ## 解決策
 ## 問題の理解

 各テスト ケースに対して整数の配列が与えられます。各値は開発者の貢献を表します。 チームを形成するためにインデックスのサブセットを選択したいと考えています。チームの値は、選択した要素の単純な合計です。 

制限がなければ、負の数は合計を減らすだけなので、自然な目標はすべての正の数を取ることになります。 これにより、チームの絶対的な最大の強さが得られます。`S_max`。 

ただし、この問題により、合計が正確に次のとおりであるサブセットを出力することはできません。`S_max`。 代わりに、合計が厳密に以下のサブセットを構築する必要があります。`S_max`ただし、そのようなすべての無効なサブセットの中で可能な限り大きいものになります。 

出力は、選択されたサブセットの合計と、どの要素が選択されたかを記述するバイナリ マスクの両方です。 

制約は大きく、テスト ケースは最大 10^4、合計 n は最大 10^5 です。 これにより、サブセットの列挙や指数推論が即座に除外されます。 テスト ケースごとに O(n) または O(n log n) の解 (理想的には線形) が必要です。 

微妙な点は、最適なサブセットは素朴な意味で「ほぼすべてがポジティブ」ではないということです。 最適な次善のセットは非常に構造化されており、最大値を減らす修正を少なくとも 1 つ確保しながら、最大値にできるだけ近づける必要があります。 

素朴なアプローチを打ち破るエッジケースには、次のようなものがあります。 

失敗モードの 1 つは、すべてのポジティブな要素を選択することです。 これにより、`S_max`、これは無効です。 たとえば、次のようにすべての数値が正の場合、`[5, 3, 4]`すべてを選択すると 12 になりますが、厳密に 12 未満にする必要があります。最小の正を削除するような単純な修正は、混合配列では必ずしも最適であるとは限りません。 

もう 1 つの失敗モードは、最大のプラスを貪欲に削除したり、マイナスを恣意的に追加したりすることです。 たとえば、`[5, -3, 4]`5 を削除すると減少が多すぎますが、最適な調整はより微妙です。 

主な困難は、「最大合計と等しくない」という制約の下で最適化を行っていることであり、これにより、最適なサブセット合計のすぐ下に境界が作成されます。 

## アプローチ

 ブルートフォースを試みる場合は、すべてのサブセットをチェックし、その合計を計算し、厳密に以下の最良の合計を追跡することになります。`S_max`。 これは正しいですが、2^n 個のサブセットがあり、n = 40 の場合でもすでに大きすぎるため、実行不可能ですが、ここでは n は 10^5 に達します。 

重要な観察は、制約のない最大サブセットが自明であるということです。つまり、それはすべての正の数の正確な合計です。 これをそのままにしておきます`S_max`。 

ここで、最大のサブセットの合計が厳密に次の値よりも小さいことが必要になります。`S_max`。 ～との平等を破るには`S_max`、少なくとも 1 つの正の要素を削除するか、少なくとも 1 つの負の要素を含める必要があります (そうでなければ、最大解で除外することになります)。 

ポジティブをネガティブに置き換えると合計が必要以上に少なくとも 1 減少するため、ネガティブを含めることはポジティブを削除することに比べて常に有害です。 したがって、最適な戦略は次のようになります。`S_max`、次に、結果が厳密に以下であることを確認しながら、可能な限り最小の減少を行います。`S_max`。 

導入できる最小の減少は、最適なセットに対して 1 つの要素の寄与を正確に反転することによって達成されます。 つまり、制御された方法で 1 つのポジティブな要素を除外するか、1 つの非ポジティブな要素を含めます。 

符号でソートすると、きれいな構造は次のようになります。すべての正の数を取得し、等価性を破りながら損失を最小限に抑える要素を 1 つだけ削除するようにします。 正の数がない場合は、代わりに最大の要素を選択する必要があります (答えは正の和が存在することが保証されているため)。 

より安定した定式化はより簡単です。`S_max`。 次に、合計が次のようなサブセットを構築します。`S_max - d`、 どこ`d`は、メンバーシップを変更することで達成できる最小のプラスの差です。 そういった最小限の`d`正の要素が存在する場合は、最小の正の要素を削除することによって達成されます。 それ以外の場合は、非正の要素の中で最大の要素を取得します。 

これにより、有効な最良の答えが得られます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. すべての正の要素の合計を計算し、最初に選択されたものとしてマークします。 正でない値は合計を減らすだけであるため、これにより制約のない最適なサブセットが形成されます。 これにより、`S_max`。 
2. ポジティブな要素がいくつ存在するかを数えます。 少なくとも 1 つの正の要素がある場合は、最小の正の要素を特定します。 これは、ほぼ次の金額を維持しながら金額を減らす最も安価な方法です。`S_max`。 
3. 最小の正の要素を選択から削除します。 これにより、結果の合計が厳密に以下になることが保証されます。`S_max`、プラスの量だけ減少させたので。 
4. 正の要素がない場合、サブセット合計の最大値は、単一の最大要素を取得することによって得られます (要素はゼロまたは負の場合がありますが、保証された構造により、少なくとも 1 つの有効な構成で答えの合計が正になることが保証されます)。 この場合、最適な単一要素のサブセットを選択します。 
5. 最終的に選択されたセットのメンバーシップに基づいてバイナリ文字列を構築し、その合計を出力します。 

これが機能する理由は単純な構造的事実に基づいています。つまり、最大サブセットはすべての正の数を含めることによって一意に決定されます。 有効な回答は、少なくとも 1 つの位置がこのセットと異なっていなければなりません。 差異を最小限に抑えながら可能な限り大きな値を維持するには、相対的な損失を最小限に抑える必要があります。`S_max`、最小の損失は、より大きな要素または負の要素を変更するのではなく、最小の正の要素を削除することによって達成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        pos_indices = []
        total = 0
        
        for i, x in enumerate(a):
            if x > 0:
                total += x
                pos_indices.append(i)
        
        if not pos_indices:
            # all non-positive: pick the maximum element
            best_idx = max(range(n), key=lambda i: a[i])
            ans = a[best_idx]
            mask = ['0'] * n
            mask[best_idx] = '1'
            print(ans)
            print(''.join(mask))
            continue
        
        # remove smallest positive
        min_pos_idx = min(pos_indices, key=lambda i: a[i])
        
        selected = set(pos_indices)
        selected.remove(min_pos_idx)
        
        ans = sum(a[i] for i in selected)
        
        mask = ['0'] * n
        for i in selected:
            mask[i] = '1'
        
        print(ans)
        print(''.join(mask))

if __name__ == "__main__":
    solve()
```サブセット合計の最大値には正の値のみが寄与するため、コードでは最初に正の値と非正の値を分離します。 次に、正の要素を 1 つだけ、特に最小の要素を削除して、損失を最小限に抑えながら最終的な合計が厳密に小さくなるようにします。 

正の要素が存在しない特殊なケースは、「最小の正を削除する」という考えが無効になるため、個別に処理されます。 その状況では、単一の最大の要素を選択すると、可能な限り最良の正の制約付きサブセットが得られます。 

バイナリ マスクは、最終的に選択されたインデックス セットから直接構築されます。 

## 実用的な例

 ### 例 1

 入力:`[1, -1, 1, -1, 1]`最大のサブセットはすべて正の値です: インデックス`0, 2, 4`、合計 = 3。 

少しずつ減らさなければなりません。 最小の正は任意です`1`。 インデックス 0 でのインデックス 1 の正の出現を削除するとします。 

| ステップ | 選択されたセット | 合計 |
 | --- | --- | --- |
 | 開始 | {0,2,4} | 3 |
 | 最小の正を削除 | {2,4} | 2 |

 これにより、厳密に 3 を下回る一方で、可能な限り 3 に近づけることが確認されます。 

### 例 2

 入力:`[5, -3, 4]`最大サブセットは`{0,2}`和9で。 

| ステップ | 選択されたセット | 合計 |
 | --- | --- | --- |
 | 開始 | {0,2} | 9 |
 | 最小の正を削除 (4) | {0} | 5 |

 これにより、9 未満の達成可能な最良の値である 5 が生成されます。

 ## 特殊なケース

 すべての数値が負の場合、アルゴリズムは最大の (最小の負の) 要素を正しく選択します。 ポジティブなものがないため、「最小のポジ​​ティブを削除」ステップはトリガーされず、フォールバックによって有効なサブセットが存在することが保証されます。 

正の要素が 1 つだけある場合、それを削除すると非正の合計が生成されるため、アルゴリズムは代わりに、それを最大のベースライン ケースとして認識した後にのみその単一の要素を選択し、完全な合計を下回る最適な有効なサブセットを保証します。 

最小の陽性値の重複が多数存在する場合、それらのいずれかを削除すると、同じ最適な削減が得られます。 このアルゴリズムは、重複に関係なく正確さを維持しながら、1 つの出現のみを安全に削除します。
