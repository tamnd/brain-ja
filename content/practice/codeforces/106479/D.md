 ## 解決策
 ## 問題の理解

 一連の整数が与えられ、その積の符号に従って部分配列を数えるように求められます。 すべてのインデックスのペア$(l, r)$は連続したセグメントを定義し、各セグメントに対して概念的にその中のすべての数値を乗算します。 製品自体は計算しません。 負であるか、ゼロであるか、正であるかだけを気にし、各カテゴリに分類されるセグメントの数を数えなければなりません。 

入力サイズは最大で数十万要素まで大きくなる可能性があります。 すべての部分配列を列挙してそれらを直接乗算しようとするアプローチでは、大まかに次のものが必要になります。$O(n^2)$セグメントを増やすと、さらに悪化する可能性があります。 セグメントごとのリニアスキャンですらすでに遅すぎるため、それ以上のものは$O(n \log n)$または$O(n)$テストごとに除外されます。 

主な問題点は、積がセグメントの 3 つの相互作用するプロパティに依存していることです。つまり、セグメントにゼロが含まれるかどうか、負の数値がいくつ含まれるか、その他には何も依存しません。 素朴な解決策の微妙な失敗モードは、ゼロを単なる別の記号として扱うことです。 

たとえば、次のように考えてみましょう`[-1, 0, -1]`。 サブアレイ`[1, 3]`2 つのマイナスが含まれているにもかかわらず、積はゼロであり、プラスではありません。 マイナスのみをカウントする単純なパリティ ベースのアプローチでは、2 つのマイナスが相殺されるため、誤ってプラスとラベル付けされてしまいます。 

もう 1 つの特殊なケースは、複数のゼロです。 で`[0, 1, 2, 0]`、ゼロと交差する部分配列には積ゼロがなければなりませんが、ゼロが明示的に分離されていない場合、単純な前置符号カウントでは誤って正または負のカウントに含まれる可能性があります。 

したがって、問題は乗算ではなく、ゼロがハード境界として機能するセグメントに配列を構造化し、各セグメント内で符号パリティのみを追跡することです。 

## アプローチ

 ブルートフォース手法ですべての部分配列を列挙する$(l, r)$、負の数をカウントし、ゼロが存在するかどうかを確認し、結果を分類します。 これは正しいですが、パフォーマンスは約$n(n+1)/2$サブ配列と各チェックは最大でスキャンできます$O(n)$、につながる$O(n^3)$最悪の場合。 実行カウントを維持するために内部スキャンを最適化しても、まだ問題が解決されません。$O(n^2)$が遅すぎる$2 \cdot 10^5$。 

ゼロを区切ると問題の構造は完全に変わります。 少なくとも 1 つのゼロを含む部分配列には積ゼロがあり、ゼロは配列を独立したブロックに分割します。 ゼロのないブロック内では、すべての要素がゼロではないため、積の符号は負の数のパリティのみに依存します。 これは、各ゼロフリーセグメント内でプレフィックス情報を維持することを示唆しています。 

各部分配列を再計算する代わりに、負の数のパリティによってプレフィックスの数を維持できます。 クリーンなセグメント内では、各プレフィックス状態によって、特定の点で終了するサブ配列の数が正または負であることが決まります。 これにより、問題は状態集約による線形スキャンに軽減されます。

 ## アルゴリズムのチュートリアル

 ゼロフリーのセグメントごとに情報を個別に保持しながら、配列を左から右に処理します。 

1. 負、ゼロ、および正の合計サブ配列のカウンターを初期化します。 また、現在のセグメント内のプレフィックス パリティ状態のカウンターも維持します。 

この考え方は、セグメントを拡張するたびに、この位置で終了する新しいサブ配列の数がすぐにわかるということです。 
2. ゼロに遭遇すると、現在のセグメントが終了します。 

このゼロを含むすべてのサブ配列はゼロ カウントに寄与し、どのサブ配列もゼロと交差できないため、セグメントの状態をリセットします。 
3. セグメント内で、偶数または奇数のマイナスを持つプレフィックスの数を追跡します。 

インデックスで終わるプレフィックス$i$で終わるサブ配列を決定します$i$: プレフィックスパリティが偶数の場合、サブ配列は正になります。 奇数の場合は負です。 
4. ゼロ以外の要素ごとに、パリティ状態を更新します。 

要素が負の場合、パリティを反転します。 それ以外の場合はパリティは変更されません。 次に、以前に確認したプレフィックス数を使用して答えを更新します。 
5. 配列が終了したら、上記と同じ方法で最後のアクティブセグメントを処理します。 

これが機能する理由は、すべてのサブ配列が位置で終わるためです。$r$開始位置によって一意に識別されます$l$、ゼロのないセグメント内では、積の符号は、間の負の数が次のとおりであるかどうかによってのみ決定されます。$l$そして$r$偶数または奇数です。 プレフィックス パリティは、この範囲プロパティをポイント プロパティに変換し、要素ごとの定数時間のカウントを可能にします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    neg_even = 1  # empty prefix has even parity
    neg_odd = 0

    cur_parity = 0

    pos = neg = 0
    zero = 0

    for x in a:
        if x == 0:
            zero += n  # will adjust later conceptually via segmentation

    neg_even = 1
    neg_odd = 0
    cur_parity = 0

    zero_total = 0
    total_pos = 0
    total_neg = 0

    for x in a:
        if x == 0:
            zero_total += (n * (n + 1)) // 2  # placeholder reset logic idea
            neg_even = 1
            neg_odd = 0
            cur_parity = 0
            continue

        if x < 0:
            cur_parity ^= 1

        if cur_parity == 0:
            total_pos += neg_even
            total_neg += neg_odd
            neg_even += 1
        else:
            total_pos += neg_odd
            total_neg += neg_even
            neg_odd += 1

    total = n * (n + 1) // 2
    zero_total = total - (total_pos + total_neg)

    print(total_neg, zero_total, total_pos)

if __name__ == "__main__":
    solve()
```この実装は、各ゼロフリー セグメント内のプレフィックス パリティに依存します。 配列`neg_even`そして`neg_odd`現在のセグメントでこれまでに出現した各パリティのプレフィックス状態の数を数えます。 新しい要素を処理するとき、パリティが負の場合は反転し、プレフィックス カウントを使用して、この位置で終わるサブ配列の数が正または負であるかを累積します。 

有効なサブ配列がゼロを横切ることができないため、ゼロはセグメント状態をリセットすることによって処理されます。 

よくある間違いは、ゼロ部分配列を独立して直接カウントしようとすることです。 部分配列の合計を計算し、ゼロ以外の寄与を差し引いた方がよりクリーンです。

 ## 特殊なケース

 次のような単一のゼロ入力`[0]`すべての部分配列を強制的にゼロにします。 アルゴリズムはすぐにリセットされ、正または負の寄与はカウントされず、最後の減算ステップまですべてのサブ配列がゼロとして分類されたままになります。 

のような長い交互シーケンス`[1, -1, 1, -1, ...]`パリティ切り替えを強調します。 このアルゴリズムは、マイナスになるたびに状態を正しく反転し、プレフィックス パリティによってすでに完全な履歴がエンコードされているため、以前の要素を再検討する必要なく寄与を蓄積します。 

のような否定のみの配列`[-1, -1, -1]`繰り返されるパリティ フリップをテストします。 プレフィックス パリティは決定論的に交互し、サブアレイ カウントは偶数長 (正) セグメントと奇数長 (負) セグメントにきれいに分割され、パリティ ベースの符号判定の理論的な期待と一致します。
