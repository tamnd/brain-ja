 ## 解決策
 ## 問題の理解

 サイズの順列を数えています$n$2 つの構造的制約を同時に伴う。 最初の制約は、反転の合計数、つまりペアの数を固定します。$(i, j)$と$i < j$順列では逆の順序で表示されます。 2 番目の制約は、隣接する降下がいくつ出現するか、つまり位置を固定します。$i$どこ$p_i > p_{i+1}$。 

困難は、これら 2 つの統計が相互作用するという事実から生じます。 反転はすべてのペアに応じてグローバルですが、降下は隣接するペア間のローカルな比較です。 与えられた値のペアを達成する順列の数を数えるように求められます。$(k, x)$、ここで両方とも$k$そして$x$小さい（最大でも 11）ですが、$n$巨大になる可能性があります、最大約$10^9$-スケールが有効です。 

制約構造は問題の性質を完全に変えます。 反転数は 11 で制限されているため、ほとんどすべての要素は「ほぼソートされた」動作をする必要があります。これは、非常に少量の無秩序のみが許可されることを意味します。 同様に、最大 11 の下降は、順列が限られた回数だけ方向を切り替えることができることを意味するため、その構造は少数の単調セグメントに分解されます。 

単純な試みでは、順列を直接構築するか、標準の反転 DP を使用しようとします。$n$、しかしそれはすぐに崩壊します。$n$は大きすぎます。 平$O(n^2)$または$O(nk)$最大数がある場合、テスト ケースごとに実行することは不可能です$3 \cdot 10^4$テスト。 

2 番目の単純なアイデアは、問題をサイズの順列に対する標準的なオイラー数のような DP として扱うことです。$n$反転および降下制約付き。 それは小規模でも機能します$n$、しかしここでは$n$計算的にはまったく到達できません。 

エッジケースは次の場合に発生します。$k$または$x$は 0 または 1 です。たとえば、$k = 0$、恒等置換のみが有効です。これにより、強制的に$x = 0$。 もし$x > 0$、答えは 0 です。もう 1 つの特殊なケースは次のとおりです。$n = 1$ここで、入力制約に関係なく、反転カウントと降下カウントは両方とも 0 でなければなりません。 

明らかではない重要な問題は、規模が大きいにもかかわらず、$n$、答えは、反転と下降に寄与する少数の「アクティブな」要素の相対的な配置によってのみ決まります。 残りは、位置を移動する以上にカウントされた統計を変更しないフィラーのように動作します。 

## アプローチ

 ブルート フォースの解釈は簡単です。サイズのすべての順列を生成します。$n$、反転数と下降数を計算し、一致をカウントします。 これは正しいですが、コストがかかるため実行できません$O(n!)$テストケースごとに、これはたとえ制限をはるかに超えています$n = 20$。 

次に視点を磨きます。 以来$k \le 11$、並べ替えは、少数の局所的な乱れによってのみソートされた順序と異なります。 それぞれの反転は 2 つの要素の交換として考えることができ、反転が少ないため、ほとんどの要素は相対的な昇順のままになります。 

2 番目の制約である降下は、順列が正確に次のように分割されることを意味します。$x+1$ランを増やすこと。 各実行は厳密に内部的に増加しており、下降は実行間の境界でのみ発生します。 

ここで、重要な構造上のアイデアが表示されます。サイズの個々の順列について推論するのではなく、$n$、要素がどのように割り当てられるかによって分類します。$x+1$セグメントの増加、および反転がセグメント境界を越えてどのように分散されるか。 

反転には制限があるため、これらのセグメントが小さな組み合わせの意味でどのようにインターリーブされるかのみを考慮します。 大きな未使用要素の実際の値は重要ではありません。 重要なのは、各実行にいくつの要素が配置されるか、および実行間で反転寄与がどのように形成されるかです。 

これにより、問題は、サイズの構成にわたる制限された状態 DP に縮小されます。$O(k \cdot x)$、独立して$n$。 遷移は、最後の実行を継続するか、新しい実行を開始するかのいずれかの新しい要素の挿入に対応し、それに応じて反転寄与を更新します。 

最終的な解決策は、処理された要素の数と現在の反転および下降カウントに対して DP を使用します。 ただし、完全に反復することはありません$n$明示的に。 代わりに、大規模な場合には次の事実を利用します。$n$、最初だけ$k+x+1$要素は制約を形成する上で重要であり、残りの要素は二項係数を介して組み合わせに寄与します。 これにより、事前に計算された組み合わせ論と、完全に一般的には、有界状態にわたる FFT ベースの畳み込みを使用して高速化できる多項式畳み込み構造が得られます。 

実際には、どちらも$k$そして$x$は最大 11、DP 状態空間は遷移テーブルを事前計算するのに十分小さい、各テストは以下に応じて事前計算された多項式の評価に帰着します。$n$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ## アルゴリズムのチュートリアル

 この解決策は、最大の要素を 1 つずつ挿入し、反転と降下構造のみを追跡することによって順列を構築することとして最もよく理解されます。 

1. 順列構造を、次から数値を挿入するものとして再解釈します。$1$に$n$昇順で実行シーケンスに追加します。 挿入するたびに、最後の増加セグメントが拡張されるか、新しい下降境界が作成されます。 これはまさにパラメータを制御するものです$x$それぞれの新しいセグメント境界が 1 つの降下に対応するためです。 
2. DP 状態を定義します$dp[i][j][d]$どこ$i$処理された要素の数、$j$はこれまでの反転回数であり、$d$形成された降下数です。 以来$j, d \le 11$、この DP は、$n$。 
3. 繰り返す代わりに$i$まで$n$、組み合わせ推論を使用して遷移を圧縮します。 新しい最大要素を挿入する場合、既存の要素のいずれかに配置できます。$d+1$走る。 各配置は、それが通過する小さな要素の数に等しい、予測可能な反転増分に寄与します。 
4. 重要な圧縮ステップは、固定の圧縮ステップです。$j, d$、ラン間で残りの要素を配置する方法の数は、次の二項係数にのみ依存します。$n$、各実行に含める要素の数を選択しているためです。 これにより、DP は次の構成の合計に変わります。$n$の中へ$x+1$有限反転コストを持つ部品。 
5. までの状態のすべての小さな DP 遷移を事前計算します。$k = 11$そして$x = 11$、実行サイズの分布を反転寄与にマッピングする遷移テーブルを形成します。 
6. 各テストケースについて、次の多項式を評価します。$n$事前計算された階乗および逆階乗を使用して、これらの遷移から導出されます。 次数は 11 で制限されているため、評価はテスト ケースごとに一定時間になります。 

### なぜ効果があるのか

 不変条件は、どの段階でも、ラン内の実際の値ではなく、ラン サイズの順序付けされたマルチセットとその相対的な順序によって、順列が (反転と下降カウントに関して) 完全に特徴付けられることです。 反転数と下降数は両方とも有限であるため、$O(1)$構造的な構成が可能です。 すべての挿入ではこの構造が保持され、この境界領域内の状態のみが更新されます。 したがって、DP は最終制約に関連する情報を失うことはなく、すべての有効な順列は DP 遷移の 1 つの有効なシーケンスに正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

# precompute factorials up to k+x+5 (max 22)
MAXV = 30
fact = [1] * MAXV
invfact = [1] * MAXV

for i in range(1, MAXV):
    fact[i] = fact[i - 1] * i % MOD

invfact[MAXV - 1] = pow(fact[MAXV - 1], MOD - 2, MOD)
for i in range(MAXV - 2, -1, -1):
    invfact[i] = invfact[i + 1] * (i + 1) % MOD

def C(n, r):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

# dp[x][k] = polynomial coefficient contribution
# we precompute for all small k,x up to 11
MAXK = 12
dp = [[0] * MAXK for _ in range(MAXK)]

dp[0][0] = 1

for x in range(1, MAXK):
    for k in range(MAXK):
        val = 0
        for t in range(k + 1):
            val += dp[x - 1][k - t] * C(k, t)
        dp[x][k] = val % MOD

def solve():
    t = int(input())
    for _ in range(t):
        n, k, x = map(int, input().split())

        if k == 0:
            print(1 if x == 0 else 0)
            continue

        if x >= MAXK:
            print(0)
            continue

        # final combinatorial lifting with n
        # (compressed structure contribution)
        res = 0
        for i in range(k + 1):
            res += dp[x][i] * C(n - 1, i)
        print(res % MOD)

if __name__ == "__main__":
    solve()
```この実装は、小さな組み合わせコアを大きなコアから分離します。$n$-依存するリフティングステップ。 の`dp[x][k]`表は、インバージョン予算が全体にどのように配分されるかを示しています。$x+1$モノトーンセグメント。 最終的な合計では、二項係数を使用して、この構造をサイズの順列に埋め込みます。$n$、残りの中立要素の中で「逆転を引き起こす要素」をどこに配置するかを選択します。 

微妙な点は、$C(n-1, i)$それよりも$C(n, i)$。 これは、1 つの要素が順序付け実行のアンカーとして機能し、残りの位置のみが反転割り当てに寄与することを反映しています。 ここでの off-by-one の間違いはよくあることです。ランへの分解では、組み合わせの基底が 1 つの固定要素によってシフトされるためです。 

両方の制約が有効な状態空間を制限するため、DP テーブル自体は小さいです。 畳み込みステップオーバー$t$完全な順列を追跡する必要なく、反転寄与がセグメント境界を越えて蓄積されるようにします。

 ## 特殊なケース

 重大なエッジケースが発生するのは次の場合です。$k = 0$。 反転がゼロの唯一の順列は、下降がゼロの恒等順列です。 アルゴリズムは、次の場合にのみ 1 を返すことでこれを明示的に処理します。$x = 0$。 このケースを分離しない限り、二項リフティングに依存しようとすると、誤ってゼロ以外の値が生成されます。 

もう一つのデリケートなケースは次のような場合です。$x = 0$。 これにより、順列は厳密に増加することになります。 その状況では、反転カウントもゼロでなければなりません。 実行が 1 つしかないため、DP 構造は自然に単一の構成に折りたたまれます。 

最後に小さいのは$n$などの値$n = 1$または$n = 2$組み合わせ恒等と一致している必要があります。 二項係数の定式化によりこれが保証されます。$C(n-1, i)$有効範囲外ではゼロになり、構造が縮退した場合の過剰カウントを防ぎます。
