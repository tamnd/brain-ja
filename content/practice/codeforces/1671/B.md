 ## 解決策
 ## 問題の理解

 すでに昇順にソートされた数直線上の一連の点が与えられます。 各点は最大 1 単位で「小刻みに動く」ことができます。つまり、その最終位置は元の座標、つまり 1 ステップ左または 1 ステップ右になります。 

すべての動きの後、ポイントが隙間や重なりのない、完全に満たされた整数セグメントを占めるようにしたいと考えています。 言い換えれば、もしあれば、$n$ポイント、その最終位置は正確に連続した整数でなければなりません$l, l+1, \dots, l+n-1$。 

タスクは、そのような各点の再割り当てがその範囲内で行われるかどうかを決定することです。$[-1, 0, +1]$柔軟性の範囲により、連続したブロックを作成できます。 

制約は厳しく、すべてのテスト ケースにわたる合計ポイント数は次のとおりです。$2 \cdot 10^5$したがって、すべての動きの組み合わせを探ろうとする解決策は、直ちに実行不可能になります。 各ポイントには 3 つの独立した選択肢があるため、総当たり状態空間は次のように拡大します。$3^n$、これは計算の限界をはるかに超えています。 

より微妙な制約は、入力がソートされることです。 この構造が重要なのは、点を独立したオブジェクトとして扱うのではなく、順番に割り当てを推論できるからです。 

素朴で貪欲な推論では見逃しがちな失敗例がいくつかあります。 1 つは、バックトラックすることなく、各ポイントを常に最も近い利用可能な整数スロットに貪欲に割り当てることができると仮定することです。 たとえば、点が次のように不等間隔に配置されている場合、`1 2 3 7`、貪欲な割り当てでは、1 ～ 3 付近のスロットが早々に消費され、有効なシフトが存在する場合でも 7 の有効な配置が残らない場合や、順序の選択によってはその逆の場合があります。 もう 1 つの落とし穴は、シフトによってギャップが増加することも減少することもあるということを忘れていることです。そのため、元のギャップについてのみ推論するだけでは不十分です。 最後に、最終位置が別個である必要があるという要件は、たとえ両方が個別にそこに着地できるとしても、2 つのポイントを同じ整数に割り当てることができないことを意味します。 

## アプローチ

 ブルートフォース解釈では、各ポイントに 3 つの値のいずれかを割り当て、結果のセットが連続した整数シーケンスを形成しているかどうかをチェックします。 これは正しいですが、探索するため実行不可能です。$3^n$テストケースごとの構成。 たとえ$n = 30$、これはすでに天文学的な規模になります。 

重要な観察は、開始位置を固定すると、必要な最終構造は非常に剛体になるということです。$l$、すべてのポイントには、そのインデックスによって決定されるターゲット スロットがあります。 ポイントがどこに移動するかという観点から考える代わりに、ソートされたポイントを理想的な連続テンプレートに一致させるという観点から考えることができます。 

最終的な配列は厳密に増加しておりギャップがないため、最終的に選択された位置を並べ替える場合、それらはシフトされた ID シーケンスと正確に一致する必要があります。 これにより、貪欲な位置合わせ戦略が可能になります。つまり、各入力ポイントを仮想セグメント内のターゲット位置に順番に割り当てようとします。 

重要な単純化は、これを各点とターゲット インデックスの間のマッチング問題として扱い、各割り当てが確実にその範囲内に収まるようにすることです。$[x_i - 1, x_i + 1]$。 両方のシーケンスは順序付けされているため、バックトラックすることなく左から右に貪欲に位置合わせして実現可能性をチェックできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(3^n)$|$O(n)$| 遅すぎる |
 | 貪欲なマッチング |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 さまざまな実現可能なオフセットから開始して最終セグメントを構築しようとしますが、それらを明示的に列挙することはしません。 代わりに、各ポイントを連続する整数スロットに割り当てることを直接シミュレートします。 

1. 最後のセグメントが何らかの値で始まると仮定します。$l$、しかし修正するのではなく$l$では、概念的に最初の点をその範囲内の実行可能なスロットに位置合わせします。 これにより、明示的に推測する必要がなくなりました$l$。 
2. ポイントを昇順に処理し、割り当て可能な最小の整数を維持します。 のために$i$- 番目のポイント、目的のスロットは$i$- 連続したシーケンスに依存します。 
3. 各ポイントについて$x_i$、現在の希望ポジションを考慮します$pos$。 もし$pos$中にある$[x_i - 1, x_i + 1]$、ウェブ割り当て$x_i$に$pos$。 これを遅らせたり早めたりしても将来の柔軟性が低下するだけであるため、これが唯一の賢明な割り当てです。 
4. もし$pos < x_i - 1$、増やします$pos$に$x_i - 1$。 This ensures we do not try to place the point too far left of what it can reach.
 5. もし$pos > x_i + 1$の場合、現在のポイントが連続した構造内の残りの有効なスロットに到達できないため、すぐに失敗します。 
6. 点に位置を割り当てた後、インクリメントします。$pos$そして続けます。 

すべてのポイントを正常に割り当てることができれば、最終的な答えは「YES」になります。 

### なぜ効果があるのか

 このアルゴリズムは、仮想的な連続シーケンスで実行中の「次に必要なスロット」を維持します。 すべてのステップで、現在のポイントをそのスロットに合わせるか、スロットを前方に移動して実現可能範囲内に留まります。 重要な不変条件は、$i$- 番目のポイントでは、有効な部分連続セグメントを構築し、すべての処理されたポイントがこのプレフィックスを拡張する有効な最終セグメントに埋め込まれることができることを確認しました。 入力構造とターゲット構造はどちらも単調であるため、局所的な障害 (必要なスロットに到達できないポイント) は、以前の割り当てを中断することなく後で修正することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        x = list(map(int, input().split()))

        pos = -10**18
        ok = True

        for i in range(n):
            # desired slot for i-th element in consecutive segment
            if pos < x[i] - 1:
                pos = x[i] - 1

            if pos > x[i] + 1:
                ok = False
                break

            pos += 1

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```ソリューションはポインタを保持します`pos`最後の連続セグメント内で占有したい次の整数を表します。 各ポイントについて、小さすぎて実行不可能な場合は、このポインターを上方に調整します。 ポイントの最大到達可能位置を超えると、設定が不可能になります。 

増分`pos += 1`スロットが割り当てられると、次のポイントはセグメント内の次の整数を占有する必要があるため、これは必須です。 微妙な詳細が初期化中です`pos`非常に小さな値に設定すると、最初のポイントは許容範囲内で自由に配置を選択できます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdin
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n = int(input())
            x = list(map(int, input().split()))

            pos = -10**18
            ok = True
            for i in range(n):
                if pos < x[i] - 1:
                    pos = x[i] - 1
                if pos > x[i] + 1:
                    ok = False
                    break
                pos += 1
            out.append("YES" if ok else "NO")
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 任意の点を移動して長さ 1 のセグメントを形成できるため、最小の単一要素の入力は常に成功します。 アルゴリズムが初期化されます`pos`最初のチェックが常に成功するほど十分に低く、ループは競合のない唯一のスロットを割り当てます。 

のようなケース`1 10 11`最初の大きなギャップによって必要な位置が前方に進みすぎて、最終的に最後のポイントの到達可能範囲を超えてしまうという失敗を示しています。 実行中、`pos`超えて進む`x[i] + 1`ギャップを埋めることができない最初の要素については、即座に拒否がトリガーされます。 

次のようなぎっしり詰まったシーケンス`2 5 6`は、アルゴリズムが許容範囲内で以前のポイントを自然に上向きに「拡張」し、明示的なバックトラックなしで有効な連続セグメントに位置合わせする方法を示しています。
