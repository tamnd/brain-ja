 ## 解決策
 ## 問題の理解

 複数のショップから連続して砂糖パックを購入し、各ショップが 1 日に 1 パックを販売するというシナリオがあります。 各ショップにはパックの初期価格があり、毎日価格が1ずつ上がります。 1日の予算は決まっており、翌日にお金を繰り越すことはできません。 目標は、すべてのパックが 1 日の予算を超えるまで購入できるパックの合計数を決定することです。 

入力は店舗数です`n`、1 日の予算`x`、および配列`a`各ショップの初期パック価格を表します。 出力は各テスト ケースの単一の整数です。つまり、手頃な価格のパックがなくなる前に購入できるパックの合計です。 

制約は重要です。`n`最大 2·10^5 まで可能です。`x`そして`a_i`最大 10^9 と次の合計`n`すべてのテスト ケースで ≤ 2·10^5 です。 これは、極端な場合には日数が最大 10^9 になる可能性があるため、各店舗の毎日の総当たりシミュレーションが遅すぎることを意味します。 毎日を個別にシミュレーションすることを避けるアプローチが必要です。 

エッジケースは、最も安いパックが初日にすでに 1 日の予算を超えている場合に発生します。 たとえば、次の場合`x = 5`そして最も安い`a_i = 6`、パックを購入することはできません。 もう 1 つの微妙なケースは、複数の安価なパックで何日も繰り返し購入できる場合に発生します。`a = [1, 1]`莫大な予算をかけて`x = 1000`。 単純な 1 日あたりのシミュレーションでは、不必要に何千回も反復されてしまいます。 この繰り返しを効率的に圧縮する方法が必要です。 

## アプローチ

 簡単な強引なアプローチでは、毎日をシミュレートします。毎日、すべてのパックの現在の価格を計算し、予算内でできるだけ多く購入し、次の日に移動してすべての価格を 1 つ上げます。 これは問題の説明に文字通り従っているので、これは正しいです。 ただし、最悪の場合、`n = 2·10^5`価格が非常に低く、予算が高い場合、シミュレーションには数日間にわたって数十億回の反復が必要になる可能性があり、これは 2 秒の制限をはるかに超えています。 これでは実用的ではありません。 

重要な点は、毎日シミュレーションする必要がないということです。 パックを初期価格で並べ替える場合、最も安いパックが常に最初に考慮されます。 いつでも買えるなら`k`予算内でパックを購入し続けることができる日数`k`予算を超えずに連続的にパックすることは数学的に計算できます。 具体的には、`k`最安パックプラス`k*d`（どこ`d`は連続日数) のまま ≤`x`、それなら買えます`k`のためのパック`d`一度に何日も。 これにより、1 日あたりのシミュレーションがグループごとの計算に変換され、問題が O(n log n) 個の並べ替えと O(n) 個の算術演算に軽減されます。 

ブルート フォースは問題を文字通りモデル化するため機能しますが、数十億回の反復が行われる可能性があるため失敗します。 連続購入に関する観察により、ソートされた価格の特定のプレフィックスを購入できる最大日数を事前に計算することができ、反復的な計算を 1 つの算術ステップにまとめることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * 最大日数) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして`x`、配列を読み取ります`a`。 
3. 配列をソートする`a`昇順で。 並べ替えにより、常に最も安いパックを最初に購入するようになり、購入されるパックの数が最大化されます。 
4.初期化`total_packs = 0`。 これにより、全日にわたって購入されたすべてのパックが蓄積されます。 
5. 配列を反復処理する`a`インデックス付き`i`現在のプレフィックスの最後のパックを表します。 プレフィックスごとに`a[0..i]`、合計を計算します`prefix_sum`このうち`i+1`要素。 この合計は、0 日目にこのプレフィックス内のすべてのパックを購入するコストを表します。 
6. 連続何日かを決定する`d`このプレフィックスを超過することなく購入できます`x`。 整数除算を使用する:`d = (x - prefix_sum) // (i+1) + 1`。 0 日目が含まれるため、1 を追加します。 もし`d <= 0`、このプレフィックスをスキップします。 
7. インクリメント`total_packs`による`(i+1) * d`。 これは購入の理由になります`i+1`毎日パックする`d`日々。 
8.減らす`x`必要に応じて次の反復のために使用しますが、私たちのアプローチでは、実際には変更する必要はありません。`x`各プレフィックスは独立して日数を計算するため、プレフィックスごとに計算されます。 
9. ループが終了したら、印刷します。`total_packs`現在のテストケースの場合。 

機能する理由: 並べ替えにより、常に最も安いパックが最初に考慮されるようになります。 連続した日数を数学的に計算することで、毎日シミュレーションすることなく、可能な限り最大の購入を保証します。 プレフィックスの合計と日の計算では、価格が毎日正確に 1 ずつ増加するという不変条件が尊重されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()
        total = 0
        prefix_sum = 0
        for i in range(n):
            prefix_sum += a[i]
            if prefix_sum > x:
                break
            days = (x - prefix_sum) // (i + 1) + 1
            total += days * (i + 1)
        print(total)

if __name__ == "__main__":
    solve()
```コードは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 パックの価格を分類すると、より安いパックを最初に購入することが保証されます。`prefix_sum`現在のプレフィックスの累積コストを追跡し、`(x - prefix_sum) // (i + 1) + 1`このプレフィックスを許容できる連続日数を計算します。 乗算`(i + 1)`このプレフィックスの合計パックを示します。 ループはすぐに壊れます`prefix_sum > x`このプレフィックスでは、初日に手頃な価格のパックがないためです。
