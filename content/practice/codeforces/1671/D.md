 ## 解決策
 ## 問題の理解

 整数の配列が与えられます`a`および追加の整数のセット`{1, 2, …, x}`。 タスクは、これらすべての追加の整数を`a`先頭または末尾を含め、任意の順序および任意の位置で。 挿入後、新しい配列の連続する要素間の絶対差の合計を計算します。 目標は、この合計を最小限に抑えることです。 

言い換えれば、問題は、ある数字から次の数字へ移動する合計「距離」ができるだけ小さくなるように、数字を直線上に配置することですが、同時に、そこからすべての数字が移動することを確認することです。`1`に`x`シーケンスのどこかに表示されます。 シーケンス`a`この範囲の数値がすでに含まれている可能性があるため、その数値がすでに存在する場合は、一部の挿入は不要な場合があります。 

制約が示すのは、`n`そして`x`それぞれまで上がることができます`2 * 10^5`と合計`n`すべてのテストケースにわたって、`2 * 10^5`。 これにより、より複雑なソリューションは効果的に排除されます。`O(n + x)`テストケースごとに。 挿入位置のすべての順列を試みると指数関数的になるため、総当りの挿入チェックは問題外です。 エッジケースには、すでに完全にカバーされているシーケンスが含まれます。`[1, x]`範囲、長さ 1 の配列、最小値または最大値が繰り返される配列。 

扱いにくいシナリオの例としては、単一要素の配列があります。`a = [10]`そして`x = 5`。 最適な挿入方法は、`[1, 2, 3, 4, 5, 10]`、合計を求める`9`。 単純な解決策では、先頭または末尾に追加の数値を任意に追加するだけで、より大きな合計が得られる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、それぞれの`x`あらゆる可能な位置にある追加の数字`a`、絶対差の結果として得られる合計を計算し、最小値を選択します。 挿入ごとに考慮すべき配列の数が増加するため、これは明らかに実行不可能です。 小さいものでも`n`、複雑さは階乗的に増加します`x`に到達する可能性があります`2 * 10^5`。 

より効率的な解決策を導き出す重要な観察は、新しい数値を既存の数値にできるだけ近づけて配置すると、絶対差の合計が最小化されるということです。 追加の数値については、極端な場合のみ-`1`そして`x`- 現在の配列と大きな違いが生じる可能性があります。 の最小要素と最大要素の間の任意の数`a`最も近い値の隣に配置することで常に「カバー」でき、その寄与を最小限に抑えることができます。 これは、貪欲な洞察につながります。絶対差の合計は、現在の配列境界と、この範囲外の極端な数値とのギャップによって最も影響を受けます。 

形式化するには、次のことを考慮する必要があります。 

1. すでに存在する差異の合計`a`。 
2. 最小値より小さい数値の場合`a`の場合、最適な戦略は、最小の追加数値を先頭に追加するか、それを最も近い要素に付加して、最小限の追加を選択することです。 
3. 同様に、最大値より大きい数値の場合、`a`、既存の最大の要素に追加するか、最後に配置することを検討してください。 

これにより、問題は次の 4 つの値を計算することになります。`1`(まだ入っていない場合は`a`)、カバーするコスト`x`、および既存のシーケンスの差の合計。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n+x)!) | O(n+x) | 遅すぎる |
 | 最適 | O(n + x) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列内の絶対差の現在の合計を計算します。`a`連続するすべてのペアを反復処理します。 これは避けては通れない基本コストです。 
2. 配列の最小値と最大値を特定する`a`。 以下の任意の数値`min(a)`以上`max(a)`コストが増加します。 させて`mn`そして`mx`現在の最小値と最大値になります`a`。 
3. 数値を「カバーする」ためのコストを計算する`1`。 もし`1 < mn`、挿入`1`どちらの側でも実行できます。コストは`mn - 1`。 もし`1`すでに最小要素よりも小さいですが、等しくありません。挿入します`1`最適な位置にある場合は、ブリッジングのコストも含まれる場合があります`1`最も近い既存の値に設定します。 シーケンスの場合、`1`すでに以下です`mn`、追加費用は`min(a[0] - 1, mn - 1, a[-1] - 1)`; 最小限のものを選びます。 
4. 対称的に、カバーするコストを計算します。`x`。 もし`x > mx`、費用は`x - mx`または最も近い端を経由してブリッジします。 
5. 最小合計額は、元の金額にカバーする最小コストを加えたものです。`1`そして`x`。 間のすべての数字`1`そして`x`等しくない`mn`または`mx`は、合計を増やすことなく、常に最も近い値の隣に挿入できます。 

重要な不変条件は、極値が最適にカバーされると、それらの間にすべての中間数値を挿入しても、極値のコストを超えて合計が増加することはないということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_insert_cost(a, x):
    n = len(a)
    total = 0
    for i in range(1, n):
        total += abs(a[i] - a[i-1])
    
    mn = min(a)
    mx = max(a)
    
    # Cost to cover 1
    add1 = 0
    if 1 < mn:
        add1 = min(abs(a[0]-1), abs(a[-1]-1), mn-1)
    
    # Cost to cover x
    addx = 0
    if x > mx:
        addx = min(abs(a[0]-x), abs(a[-1]-x), x-mx)
    
    return total + add1 + addx

t = int(input())
for _ in range(t):
    n, x = map(int, input().split())
    a = list(map(int, input().split()))
    print(min_insert_cost(a, x))
```配列に対するループにより、元の差分の合計が計算されます。 の`mn`そして`mx`テスト ケースごとに 1 回追跡されます。 最小限のブリッジコストは、`1`そして`x`の最初、最後、最小/最大値を使用して計算されます。`a`最小の追加寄与を見つけることを保証するためです。 これにより、配列の中央のより良い位置を見逃すことがなくなります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        def min_insert_cost(a, x):
            n = len(a)
            total = sum(abs(a[i]-a[i-1]) for i in range(1, n))
            mn, mx = min(a), max(a)
            add1 = 0
            if 1 < mn:
                add1 = min(abs(a[0]-1), abs(a[-1]-1), mn-1)
            addx = 0
            if x > mx:
                addx = min(abs(a[0]-x), abs(a[-1]-x), x-mx)
            return total + add1 + addx
        output.append(str(min_insert_cost(a,x)))
    return "\n".join(output)
