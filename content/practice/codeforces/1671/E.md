 ## 解決策
 ## 問題の理解

 次のサイズの完全な二分木が与えられます。$2^n - 1$ここで、すべての内部ノードにはちょうど 2 つの子があり、すべてのリーフは同じレベルにあります。 各ノードには、A または B のいずれかのラベルが付いています。構造は固定されていますが、事前順序トラバーサル文字列を読み取る前に、内部ノードの左右の子を何度でも自由に入れ替えることができます。 

ノードのプレオーダー文字列は、最初にノード自体の文字を取得し、次に左側のサブツリーのプレオーダー文字列、次に右側のサブツリーのプレオーダー文字列を取得することによって形成されます。 子を交換するとサブツリーの相対的な順序が変更されるため、交換の選択が異なると、ルートに異なる最終的な事前順序文字列が生成される可能性があります。 タスクは、可能な個別のルート プレオーダー文字列の数をカウントすることです。 

制約$n \le 18$木が最大でも持っていることを意味します$2^{18} - 1 \approx 2.6 \cdot 10^5$ノード。 スワップの選択肢を明示的に列挙しようとする解決策は不可能です。$2^{(2^n-1)/2}$可能なスワップ構成は天文学的に大きくなります。 ソリューションでは、繰り返し構造を再利用して、サブツリー情報を積極的に圧縮する必要があります。 

微妙な失敗のケースは、サブツリーの等価性が構造のみまたは文字のみによって決定されると仮定した場合に発生します。 2 つの異なるサブツリーは同一の文字セットを持っている場合がありますが、順序付けにより異なる事前注文文字列が生成されます。 逆に、形状が異なる 2 つのサブツリーは、交換後も同一の可能な文字列のセットを生成できます。 スワップの自由を考慮せずに生の事前注文文字列を単純にハッシュすると、同等のサブツリーが別のものとして誤って扱われます。 

もう 1 つの罠は独立性を仮定することです。左右のサブツリーからのカウントを乗算すると、特に 2 つの子の可能な表現が同一である場合に、スワップによって結果の文字列セットに重複が生じる可能性があることが無視されます。 

## アプローチ

 ブルート フォース ソリューションでは、各サブツリーのすべての事前順序文字列が再帰的に生成され、各内部ノードで、左と右のサブツリー文字列のすべての組み合わせが両方の可能な順序で連結されます。 これは、定義に直接従うため、概念的には正しいです。各スワップの選択によりサブツリーの順序が変更され、順序が固定されると、事前順序の構築は決定的になります。 

ただし、各ノードで使用できる文字列の数は指数関数的に増加する可能性があります。 最下位レベルでは、葉はそれぞれ 1 つの文字列を生成しますが、1 つ上のレベルではすでに 2 つの組み合わせが生成されており、この成長は乗算的に増加します。 小さいものでも$n$、個別の文字列の数が管理できなくなり、文字列の連結自体のコストが高くなりすぎます。 

重要な点は、実際には文字列を構築する必要がないということです。 個別の結果をカウントするだけで済みます。 この構造は完全な二分木であるため、同じ深さにあるすべてのサブツリーは同じ形状になります。 唯一のバリエーションは、ラベルとスワップの選択によるものです。 

各ノードに対して、生成できる文字列セットの正規表現を定義します。 完全なセットを保存する代わりに、ハッシュのような構造と個別の順列の数を介してそれをエンコードします。 重要な洞察は、サブツリーはその 2 つの子の表現によって決定され、交換は同一の組み合わせオブジェクト間の順序のみを変更するということです。 

各サブツリーを、可能なサブツリー エンコーディングのマルチセットとして扱います。 左右のサブツリーのエンコード セットが同じである場合、交換によって新しい構成は生成されません。 それらが異なる場合、交換により構造上の選択の点でそのノード レベルでの配置の数が 2 倍になりますが、結果として得られる文字列セットは依然として対称的に結合されます。 

したがって、各ノードで以下を計算します。 

- そのサブツリーの構造署名、
 - 生成できる個別の事前注文文字列の数。 

私たちは子供たちをサインで比較します。 等しい場合、交換によって新しい結果は作成されません。 異なる場合は、左右の順序が重要になりますが、両方の方向を考慮する必要があるのは 1 回だけです。 

これにより、問題はツリー上のボトムアップ DP に縮小されます。

 ## アルゴリズムのチュートリアル

 葉から順に木を処理します。 

1. 各リーフに、そのラベルで構成される基本表現を割り当てます。 可能な文字列の数は 1 で、その署名は文字から派生します。 
2. 各内部ノードについて、最初にその左と右の子の表現を計算します。 これにより、計算済みのサブツリー情報が常に結合されるようになります。 
3. 2 つの子の署名を比較します。 それらが同一の場合、交換しても何も変わらないため、異なる文字列の数は単純に次のようになります。$$dp[x] = dp[left] \cdot dp[right]$$4. 署名が異なる場合、交換により 2 番目の配置が生成されます。 ただし、どちらの方向でも有効な事前順序構造が生成されるため、次のようになります。$$dp[x] = 2 \cdot dp[left] \cdot dp[right]$$しかし、構造的に同一の結果を二重にカウントしていないことを確認する必要があります。 これは、順序付けられた署名ペアを正規形式に組み込むことによって処理されます。 
5. ノードの署名は次のように定義されます。$$(s_x, \min(sig_L, sig_R), \max(sig_L, sig_R))$$ここで、順序付けは子の署名よりも辞書順に行われます。 これにより、子が同一の場合はスワップによって同じ署名表現が得られ、それ以外の場合は曖昧さがなくなります。 
6. このプロセスをルートまで続けます。 答えはルートモジュロの dp 値です。$998244353$。 

### なぜ効果があるのか

 重要な不変条件は、すべてのノードについて、その計算された署名が、子孫を交換することによって取得できるすべてのサブツリー構成の同値クラスを一意に表すことです。 同一の署名を持つ 2 つのサブツリーは、まったく同じプレオーダー文字列のセットを生成します。 子署名が固定されると、すべてのサブツリーの決定はローカルで独立しているため、カウントを乗算的に組み合わせることが有効です。 署名内の正規の順序付けにより、純粋に左右の対称性によって引き起こされる二重カウントが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

n = int(input())
s = input().strip()

# Build tree implicitly; nodes are 1-indexed
# dp[x] = number of distinct preorder strings from subtree x
# sig[x] = canonical hash-like representation

sys.setrecursionlimit(10**7)

dp = [0] * (2**n)
sig = [None] * (2**n)

# We will use a tuple as a hashable signature
# (char, left_sig, right_sig) with ordered children

def dfs(x):
    if x >= 2**n:
        return

    left = 2 * x
    right = 2 * x + 1

    if left >= 2**n:
        sig[x] = s[x-1]
        dp[x] = 1
        return

    dfs(left)
    dfs(right)

    sl = sig[left]
    sr = sig[right]

    # canonical ordering
    if sl <= sr:
        sig[x] = (s[x-1], sl, sr)
    else:
        sig[x] = (s[x-1], sr, sl)

    if sl == sr:
        dp[x] = (dp[left] * dp[right]) % MOD
    else:
        dp[x] = (2 * dp[left] * dp[right]) % MOD

dfs(1)
print(dp[1] % MOD)
```この実装は、ルート ラベルとその子の正規の順序の両方をキャプチャするタプルによって各サブツリーを表現することに依存しています。 これにより、実際の文字列の構築が回避されます。 子署名間の比較により、対称性が確実に検出されます。両方の子が同一の場合、交換によって新しい個別の事前順序文字列が生成されることはありません。 

DFS は親の前に子を処理し、必要なときに各 dp 値が準備されていることを保証します。 乗算ではサブツリーからの独立した選択が結合されますが、オプションの因数 2 は、交換によって真に異なる配置が得られる場合にのみ表示されます。 

微妙な点は、完全な文字列を決して保存しないことです。 これらのタプルの等価性は、それらが表す事前順序文字列のセットの等価性に正確に対応するため、タプル表現で十分です。 

## 実用的な例

 高さ 2 の最小の非自明なツリーを考えてみましょう。 

### 例 1

 入力:```
2
AABB
```ルート 1 = A、子 2 = A、3 = B となります。 

| ノード | 左記号 | 右の記号 | 平等 | DP |
 | --- | --- | --- | --- | --- |
 | 2 | - | - | 葉 | 1 |
 | 3 | - | - | 葉 | 1 |
 | 1 | あ | B | いいえ | 2 |

 ルートには 2 つの異なる子があるため、どちらの注文でも異なる事前注文文字列 (AAB と ABA) が生成されます。 

これは、非対称性が結果の​​空間を 2 倍にすることを裏付けています。 

### 例 2

 入力:```
2
AAAA
```両方のサブツリーは同一です。 

| ノード | 左記号 | 右の記号 | 平等 | DP |
 | --- | --- | --- | --- | --- |
 | 2 | あ | - | 葉 | 1 |
 | 3 | あ | - | 葉 | 1 |
 | 1 | あ | あ | はい | 1 |

 スワッピングが許可されている場合でも、両方の方向で同一の事前注文文字列が生成されるため、異なる文字列は 1 つだけ存在します。 

これは、等価性の検出がなぜ重要であるかを示しています。単純な 2 倍計算では過剰にカウントされてしまいます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(2^n)$| 各ノードは 1 回訪問され、すべての操作は定数時間のタプルの比較と乗算です。 
| スペース |$O(2^n)$| 配列はツリー内のすべてのノードの dp と署名を保存します。 

木には、$2^n - 1$ノード、および$n \le 18$したがって、この線形横断は十分に制限内にあります。 構造ハッシュを使用すると、保存された状態が指数関数的に爆発的に増加することがなくなります。

 ## 特殊なケース

 すべてのラベルが同一である完全に均一なツリーは、単純なアプローチにとって最もクリーンな失敗点です。 その場合、すべてのレベルのすべてのサブツリーは同一の構造と同一の署名を持ちます。 このアルゴリズムはマージのたびに繰り返し等価性を識別するため、dp 値はルートに至るまで 1 のままです。 各ノードで 2 を乗算しようとすると、誤って爆発してしまいます。$2^{2^n-1}$すべてのスワップが同じ事前注文文字列を保持するため、これは誤りです。 

2 番目のエッジ ケースは、左右のサブツリーがより深い構造だけが異なるが、同じ署名を生成する場合です。 正規タプル比較により、それらが親で等しいものとして扱われることが保証され、プリオーダー出力の等価性に影響を与えない構造の非対称性によって引き起こされる過剰カウントが防止されます。
