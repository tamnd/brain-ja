 ## 解決策
 ## 問題の理解

 ゼブラのような数値は正の整数であり、そのバイナリ表現は次のようになります。`1`、`101`、`10101`、`1010101`、 ...

 言い換えれば、ビットは交互に配置され、最下位ビットは`1`。 

させて$$z_1=1,\quad z_2=5,\quad z_3=21,\quad z_4=85,\dots$$まさにゼブラのような数字です。 

正の整数の場合$x$、そのゼブラ値は、合計が次のようなゼブラ状の数値の最小数です。$x$。 

あらゆるクエリに対して$[l,r]$そして$k$、その区間内で正確にゼブラ値を持つ整数がいくつあるかを数えなければなりません$k$。 

間隔のエンドポイントは次のように大きくできます。$10^{18}$したがって、数値を反復処理することは不可能です。 インターバルを 1 回通過するだけでも、最大で$10^{18}$操作。 ソリューションは、クエリごとにおよそ多対数時間で機能する必要があります。 

最初の明らかではない観察は、以下にシマウマのような数字がほとんどないことです。$10^{18}$。 彼らは満足します$$z_{i+1}=4z_i+1,$$したがって、それらは指数関数的に成長します。 中には30個くらいしか入らない$10^{18}$。 

2 番目の罠は、ゼブラ値が通常のコイン両替 DP で計算できると仮定していることです。 コインの価値は次のとおりです$10^{18}$, したがって、合計を超えるDPは不可能です。 

3 番目の罠は、同じ数値の異なる分解で異なる数値のゼブラ状加数が使用される可能性があることです。 例えば、$$21 = z_3$$ゼブラ値があります$1$、 それでも$$21 = 5+5+5+5+1$$5 つの加数を使用します。 最適な分解について直接推論する必要があります。 

クエリを検討してください```
1 1 1
```答えは`1`なぜなら$1$それ自体がゼブラ状です。 誤って少なくとも 2 つのゼブラ数の合計のみをカウントするアプローチは、ここでは失敗します。 

考慮する```
2 10 100
```答えは`0`。 それでも$k$と同じくらい大きいかもしれない$10^{18}$までの番号はありません$10^{18}$これに近いゼブラ値を持つことができます。 このようなケースには早期に対処することが重要です。 

## アプローチ

 ブルートフォースアプローチでは、すべての数値が生成されます。$[l,r]$、ゼブラ値を計算し、一致をカウントします。 

何らかの方法で一定時間内にゼブラ値を計算したとしても、間隔の長さは次のようになります。$10^{18}$。 これはまったく実現不可能です。 

重要なのは、数字そのものについて考えるのをやめ、代わりにゼブラのような数字の構造を研究することです。 

させて$$z_i=\frac{4^i-1}{3}.$$これらは満足します$$z_{i+1}=4z_i+1.$$最適な分解には、いくつかのコピーが少なくとも 5 つ含まれていると仮定します。$z_i$。 

のために$i>1$、$$5z_i=z_{i+1}+4z_{i-1}.$$右側では同じ数の加数が使用されます。 この変換を繰り返すと、4 より大きいすべての係数が削除されます。 

その結果、すべての数値が最適に分解されます。$$x=\sum c_i z_i,$$と$$0\le c_i\le 4.$$2 番目の削減は次のとおりです。$$z_{i+1}=4z_i+1.$$何らかの係数があれば$c_i=4$その下に正の係数がある場合は、置き換えることができます$$4z_i+1$$による$$z_{i+1},$$加数の数を減らします。 したがって、最適な分解では、数字が$4$と表示される場合は、下位の桁はすべてゼロでなければなりません。 

これにより、正規表現が得られます。$$x=\sum c_i z_i,$$すべての数字が間にあるところ$0$そして$4$、最初の数字の後に等しい$4$、下位の桁はすべてゼロです。 

ゼブラ値は単純に$$\sum c_i.$$ここで問題は、奇妙な記数法における桁 DP の問題になります。 限界を超えない表現をカウントします$N$桁の合計が次の値に等しい$k$。 

ゼブラ桁は約 30 個しかないため、DP は小さいです。

 ## アルゴリズムのチュートリアル

 ### 事前計算

 1. シマウマのような数字をすべて生成する$z_i\le 10^{18}$を使用して$$z_{i+1}=4z_i+1.$$2. そのような番号は約 30 個しかありません。 

### 境界をゼブラ数字に変換する

 1. 与えられた条件に対して$N$、基底でその貪欲な表現を計算します$\{z_i\}$。 
2. ゼブラ番号を最大から最小の順に処理します。 各位置で、可能な最大の係数を取得します。 
3. 結果の数字は常に次の範囲にあります。$0$そして$4$。 

再発$z_{i+1}=4z_i+1$貪欲な分解により DP で使用される正規の数字システムが生成されることを保証します。 

### 桁 DP

 1. しましょう`digits[i]`の係数になります$z_i$の表現で$N$。 
2. 位置を最も重要なものから最も重要でないものの順に処理します。 
3. 4 つの DP パラメータを維持します。 

- 現在の位置
 - まだ厳しいかどうか$N$- 現在の桁の合計
 - 数字かどうか$4$すでに登場しています
 4. 数字の場合$4$がすでに出現している場合、残りのすべての桁はゼロでなければなりません。 これにより、正規表現条件が強制されます。 
5. それ以外の場合は、次のすべての数字を試します。$0$許容限度まで。 
6. 選択した桁を現在の桁の合計に加算します。 
7. 最後に、桁の合計が次と等しい状態を数えます。$k$。 

### 範囲クエリ

 1. しましょう$F(N,k)$整数になる$x\le N$ゼブラ値が次と等しい$k$。 
2. の答え$[l,r]$は$$F(r,k)-F(l-1,k).$$### なぜ効果があるのか

 すべての最適な分解は、すべての係数が次の値に属するまで変換できます。$\{0,1,2,3,4\}$。 数字を含むあらゆる表現$4$の 1 つのコピーがあるため、正のより低い係数を併用することは最適ではありません。$z_{i+1}$交換できます$4z_i+1$そして加数の数を減らします。 

したがって、すべての数値は次を満たす固有の正規表現を持ちます。$$0\le c_i\le 4,$$最初の桁が次と等しい場合$4$、下位の桁はすべてゼロです。 

ゼブラ値はこれらの数字の合計に等しくなります。 数字 DP はこれらの正規表現を正確に列挙し、数字の合計が次のとおりであるものをカウントします。$k$。 すべての有効な表現は正確に 1 つの整数に対応し、その逆も同様であるため、DP によって返されるカウントは正確です。 

## Python ソリューション```python
import sys
from functools import lru_cache

input = sys.stdin.readline

Z = [1]
while True:
    nxt = Z[-1] * 4 + 1
    if nxt > 10**18:
        break
    Z.append(nxt)

M = len(Z)

def count_upto(n, k):
    if n <= 0:
        return 0

    if k > 4 * M:
        return 0

    digits = [0] * M
    rem = n

    for i in range(M - 1, -1, -1):
        digits[i] = rem // Z[i]
        rem %= Z[i]

    @lru_cache(None)
    def dfs(pos, tight, s, locked):
        if s > k:
            return 0

        if pos < 0:
            return 1 if s == k else 0

        if locked:
            d = 0
            if tight and d > digits[pos]:
                return 0
            ntight = tight and (d == digits[pos])
            return dfs(pos - 1, ntight, s, 1)

        limit = digits[pos] if tight else 4

        ans = 0
        for d in range(limit + 1):
            ntight = tight and (d == limit if tight else False)

            if tight:
                ntight = (d == digits[pos])

            ans += dfs(
                pos - 1,
                ntight,
                s + d,
                locked or (d == 4)
            )

        return ans

    return dfs(M - 1, 1, 0, 0)

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        l, r, k = map(int, input().split())

        if k > 4 * M:
            out.append("0")
            continue

        ans = count_upto(r, k) - count_upto(l - 1, k)
        out.append(str(ans))

    sys.stdout.write("\n".join(out))

solve()
```最初のセクションでは、ゼブラのような数値をすべて構築します。$10^{18}$。 Only about thirty values exist, which is why the later DP remains tiny.

 機能`count_upto`計算する$F(N,k)$。 まず変換します$N$貪欲なゼブラ数字表現に変換します。 これらの数字は、標準数字 DP で 10 進数字が果たすのと同じ役割を果たします。 

状態変数`locked`微妙な部分です。 1桁に1回`4`と表示される場合は、残りの下位桁はすべてゼロでなければなりません。 この制限を忘れると、最適でない表現がカウントされ、不正確なゼブラ値が生成されます。 

剪定の様子`s > k`状態空間を小さく保ちます。 可能な最大桁数の合計はわずか約であるため、$120$、DPは依然として非常に速いです。 

最後に、すべてのクエリは標準のプレフィックスカウント手法を使用して回答されます。$$[l,r] = [1,r] - [1,l-1].$$## 実用的な例

 ### 例 1

 入力:```
1 100 3
```関係するゼブラ番号は次のとおりです。$$1,\;5,\;21,\;85.$$貪欲なシマウマの表現$100$は:

 | ゼブラ番号 | 係数 |
 | --- | --- |
 | 85 | 1 |
 | 21 | 0 |
 | 5 | 3 |
 | 1 | 0 |

 それで$100 = 1\cdot85 + 0\cdot21 + 3\cdot5 + 0\cdot1$。 

DP は、これらの桁を超えないすべての正規表現を調査し、桁の合計でそれらをカウントします。$3$。 

結果は次のとおりです。```
13
```この例は、ゼブラ値が完全に正規表現の桁合計によって決定されることを示しています。 

### 例 2

 入力:```

```関連するゼブラ番号:$$1,\;5,\;21.$$ゼブラ値のある区間内の数値$2$は：$$26=21+5,$$
