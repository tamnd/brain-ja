 ## 解決策
 ## 問題の理解

 1 から n までの整数の順列が与えられます。これは、その範囲内のすべての数値がサイズ n の配列に 1 回だけ現れることを意味します。 次に、一連のクエリを実行します。各クエリでは、配列の特定の要素をゼロに置き換えます。 各位置はすべてのクエリを通じて 1 回だけ置き換えられるため、n 回のクエリの後、配列全体はゼロで構成されます。 

各クエリの後に、現在の配列を 1 から n までの整数の有効な並べ替えに戻すために必要な最小操作数を計算することがタスクとなります。 許可される操作は単純です。インデックス i を選択し、そのインデックスの値を i に置き換えます。 この操作は、そのインデックスの要素が置換において正しくなることが保証され、任意のインデックスに独立して適用できます。 

この制約は、n が 10^5 に達する可能性があり、すべてのテスト ケースにわたる n の合計が 2・10^5 を超えないことを示しています。 2 秒の制限があると、テスト ケースあたり O(n^2) の解は遅すぎます。 制限内に収まるためには、テスト ケースごとにおよそ O(n) 個の値が必要です。 

微妙なエッジ ケースは、順列が最初に昇順または降順で並べ替えられる場合です。 たとえば、n=3、順列 [3,2,1]、クエリ [3,2,1] を考えてみましょう。 最初のクエリの後、位置 3 のみがゼロになります。 インデックス 3 を 3 に設定するとその要素が修正されるため、順列を復元するための最小操作は 1 回です。 2 番目のクエリの後、位置 3 と 2 はゼロであり、最小操作は 2 です。 不注意な解決策では、ゼロが常に末尾または並べ替えられた順序で現れると想定する可能性がありますが、これは真実ではありません。 

もう 1 つのエッジ ケースは、正しく配置された連続した数値のシーケンスがゼロによって分割される場合です。 たとえば、最初と最後の要素がゼロでも、中間の要素がすでに正しい場合は、配列内のギャップを考慮する必要があり、必要な操作の数に直接影響します。 

## アプローチ

 ブルートフォース手法では、各クエリの影響をシミュレートします。p[d_i] をゼロに置き換えた後、配列を反復処理して、間違っている要素の数を数えます。 不正な要素ごとに、すでにゼロである (1 回の操作が必要) か、間違っている (1 回の操作が必要) かのいずれかです。 これは機能しますが、配列を n 回走査することになるため、最悪の場合 O(n^2) 時間がかかりますが、これは n が 10^5 までの場合には遅すぎます。 

重要な観察は、許可された操作により、インデックス i に任意の数値 i を直接配置できるということです。 これは、問題が、操作なしで正しい状態を維持できる位置 1 から n の最大のプレフィックスをカウントすることに帰着することを意味します。 削除された要素のセットを維持し、すでに正しい端から最も高い連続ブロックを追跡できます。 具体的には、クエリを逆に反復して、ポジションのゼロ化を「元に戻す」ことができます。 各ステップで、最初から n までのすべての数値が既に含まれている最大の接尾辞の長さを追跡します。 各クエリの後に必要な最小限の操作は、このサフィックスの外側の位置の数と同じです。これは、他のすべての位置を修正するために 1 回の操作が必要になるためです。 この観察により、複雑さが O(n^2) から O(n) に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を作成する`pos`サイズ n+1 で、各数値を順列のインデックスにマップします。 これにより、O(1) 時間であらゆる数値をすばやく見つけることができます。 
2. 配列を初期化する`removed`どの位置がゼロ化されたかを追跡するためのサイズ n+1 。 最初はすべて False に設定します。 
3. 変数を初期化する`suffix_max`nに。 これにより、操作を必要としない連続したサフィックスの現在の最大数が追跡されます。 
4. 最後のクエリから最初のクエリまで、逆の順序でクエリを繰り返します。 基本的に配列を逆方向に構築しているため、クエリごとに位置を元の値に「復元」します。 
5. 数字が表示されている間、`suffix_max`復元された (つまり、削除されていない)、デクリメント`suffix_max`。 このステップでは、すでに正しい数値の最大の連続接尾辞を見つけます。 
6. このクエリの後の最小限の操作を次のように記録します。`suffix_max`。 その理由は、すべての数値が より大きいためです。`suffix_max`すでに正しく配置されており、以下のすべての数値`suffix_max`それぞれ1回の操作が必要です。 
7. すべてのクエリを逆に処理した後、結果の配列を逆にして元のクエリの順序と一致させます。 

なぜ機能するのか: 不変条件は、各ステップで、`suffix_max`は、すべての数値が以下になるような最大の数値を表します。`suffix_max`すでに正しい位置にいます。 許可された操作は、対応するインデックスで任意の数値を直接修正するため、以下のすべての数値が修正されます。`suffix_max`個別に修正する必要がありますが、これは最小限の操作に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        d = list(map(int, input().split()))
        
        pos = [0] * (n + 1)
        for idx, val in enumerate(p):
            pos[val] = idx
        
        removed = [False] * n
        ans = [0] * n
        suffix_max = n
        # process queries in reverse
        for i in range(n - 1, -1, -1):
            removed[d[i]-1] = False  # restore element
            while suffix_max > 0 and not removed[pos[suffix_max]]:
                suffix_max -= 1
            ans[i] = suffix_max
            removed[d[i]-1] = True  # mark removed for next iteration
        
        print(" ".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```コードはまず、`pos`配列を使用して、任意の数値のインデックスへの O(1) アクセスを許可します。 の`removed`配列は、ゼロ化された位置をマークするために使用されます。 操作を必要としないサフィックスのサイズを決定できるように、クエリを逆に処理します。 微妙な部分は、`removed`デクリメント前後のフラグ`suffix_max`正しい帳簿を維持するため。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各クエリは 1 回処理され、suffix_max は合計で最大 n 回減少します。 
| スペース | O(n) | 配列 pos、removed、および ans にはそれぞれ O(n) スペースが必要です。 

すべてのテスト ケースの合計時間は O(n の合計) = O(2·10^5) であり、2 秒の制限内に十分収まります。 スペース使用量は n に比例し、512 MB の制限内では許容されます。
