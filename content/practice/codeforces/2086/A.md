 ## 解決策
 ## 問題の理解

 ジャムは同量のベリーと砂糖を混ぜ合わせて作られ、調理中に総質量の 25% が蒸発することを前提として、一定数のジャム瓶を製造するのに何キログラムのクラウドベリーが必要かを判断するよう求められました。 入力はいくつかのテスト ケースの瓶の数を示し、出力はそれぞれに必要なベリーのキログラム数になります。 

より簡単な言葉で言い換えると、ジャムの各瓶の最終質量は 3 キログラムに固定されています。 これを製造するには、同じ質量のベリーと砂糖を混ぜます。25％が蒸発するため、合計すると3kg以上になります。 代数的に言うと、`x`kgのベリーと`x`kg の砂糖、最終的な質量は`3x/2`蒸発後。 これを瓶あたり 3 kg に等しくする必要があります。 解決中`3x/2 = 3`与える`x = 2`瓶あたりベリーのキログラム。 したがって、問題は、必要なベリーを取得するために瓶の数を 2 倍することになります。 

制約は穏やかです。テスト ケースは最大 10^4 個、テスト ケースあたり最大 10^8 個の jar です。 これは、すべての解がテスト ケースごとに O(1) でなければならないことを直ちに示唆します。 反復的またはシミュレーションベースのアプローチは不必要であり、非常に時間がかかりすぎます。 エッジケースには、最小限の数の jar が含まれます (`n = 1`) および可能な最大数 (`n = 10^8`)、ただし、計算は単純な乗算のままであり、標準の 64 ビット整数をオーバーフローすることはありません。 

単純な間違いは、蒸発率を誤って計算したり、瓶の数を掛けるのを忘れたりすることです。 たとえば、コンピューティング`(3 * n) * 0.75`浮動小数点と丸めのため、大きなサイズの場合は 1 つずれのエラーが発生する可能性があります。`n`。 正しいアプローチは純粋に整数演算です。`2 * n`。 

## アプローチ

 強引なアプローチでは、ベリーと砂糖を繰り返し混合し、25% の蒸発を適用することで、各瓶の製造をシミュレートしようとします。 のために`n = 10^8`jar、これは完全に非現実的です。 この問題を数学的に観察すると、直接的な公式が明らかになります。各瓶にはちょうど 2 kg のベリーが必要です。 これが特定されたら、最適な解決策は単純に jar の数を 2 倍にすることです。 

重要な洞察は、問題が線形であるということです。つまり、蒸発係数は一定で、各ジャーは独立しているということです。 jar 間の依存関係や利益の逓減はありません。 これにより、潜在的な反復シミュレーションから、テスト ケースごとに 1 回の乗算に解決策が削減されます。 浮動小数点演算は不要です。 整数演算で十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | テスト ケースあたり O(n) | お(1) | n が大きいと遅すぎます |
 | 直接乗算 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、jar の数を読み取ります。`n`。 
3. 必要なベリーの数を次のように計算します。`2 * n`。 
4. 結果を印刷します。 

これが機能する理由: 各瓶には 2 kg のベリーが必要です。これは次の式から導き出されます。`final_mass = 3/4 * total_mass`、解決します`total_mass / 2 * 2/3 = 1`1つの瓶から2kgのベリーが得られます。 各瓶は独立しているため、合計は線形になります。`n`。 整数演算により、丸め誤差のない正確な答えが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    print(2 * n)
```このソリューションでは高速 I/O を使用します。`sys.stdin.readline`ただし、この問題では標準です`input()`十分でしょう。 各テスト ケースは独立して処理され、瓶ごとに必要なベリーを考慮するには 2 を乗算するだけで十分です。 

## 実用的な例

 | n | 計算 | 結果 |
 | --- | --- | --- |
 | 1 | 2*1 | 2 |
 | 3 | 2*3 | 6 |

 のために`n = 1`、1つの瓶には2 kgのベリーが必要です。 のために`n = 3`, 3瓶で合計6kg必要です。 トレースにより、次の式が確認されます。`2 * n`あらゆる場合に必要な質量を正確に計算します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t) | テスト ケースごとに 1 つの乗算 |
 | スペース | お(1) | テスト ケースごとに追加のメモリは必要ありません。 

これは、入力制約を考慮すると最適です。次のようになります。`t`ケースをテストし、それぞれの結果を出力します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        n = int(input())
        print(2 * n)
    sys.stdout = sys.__stdout__
    return output.getvalue().strip()

# Provided samples
assert run("2\n1\n3\n") == "2\n6", "sample tests"

# Custom cases
assert run("1\n10\n") == "20", "ten jars"
assert run("1\n100000000\n") == "200000000", "max jars"
assert run("3\n1\n2\n5\n") == "2\n4\n10", "multiple small cases"
assert run("1\n0\n") == "0", "zero jars"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 2 | ゼロ以外の最小の jar |
 | 3 | 6 | 少数の瓶 |
 | 100000000 | 200000000 | jar の最大数、大きな整数の処理をチェックする |
 | 0 | 0 | 瓶ゼロのエッジケース |
 | 複数の小さい | 2、4、10 | 複数のテスト ケース |

 ## 特殊なケース

 のために`n = 1`、計算`2 * 1 = 2`正の最小数の jar を正しく処理します。 のために`n = 10^8`、`2 * 10^8`は 64 ビット整数の制限内にあるため、オーバーフローは発生しません。 ゼロジャー事件`n = 0`生成する`0`、ベリーが必要ないことを正しく反映しています。 これらにより、式が問題領域全体にわたって堅牢であることが確認されます。
