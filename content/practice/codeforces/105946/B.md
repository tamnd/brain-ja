 ## 解決策
 ## 問題の理解

 配列と、サブ配列に対する多くの演算が与えられます。 各クエリは、ランダム化された「吸収」プロセスから得られる値を要求し、更新によりセグメント全体が固定パターンに置き換えられます。 

吸収プロセス自体は、2 つの隣接する要素を繰り返しマージします。インデックスが選択され、右側の要素が左側に吸収され、加算と乗算の両方を含む非線形な方法で左側の値が増加します。 このプロセスは要素が 1 つだけ残るまで続き、その最後の数値がスコアとなります。 

一見すると、ランダム性は、指数関数的に多くのマージ シーケンスに対する期待値を計算する必要があることを示唆しています。 ただし、演​​算の重要な構造は、そのランダム性ではなく、その代数形式の中に隠されています。 

入力サイズは 20 万要素と 20 万操作に達するため、クエリごとにマージをシミュレートしたり期待値を再計算したりするソリューションは直ちに不可能になります。 たとえ$O(n \log n)$クエリごとの再計算が遅すぎる可能性があります。 これにより、各操作がほぼ一定時間または対数時間でセグメントを変更または応答し、吸収プロセスが単純な範囲統計に分解される必要がある解決策が強制されます。

 微妙な落とし穴は、マージ順序が異なると結果も異なると想定していることです。 単純な実装では、ランダムな隣接マージをシミュレートし、一定期間にわたるモンテカルロ推定または動的プログラミングを試みますが、どちらも失敗します。 間隔構造は履歴に応じて変化し、すべてのセグメントにわたるステートフル DP は組み合わせ的に爆発します。 

## アプローチ

 ブルートフォース解釈は、ゲームの文字通りのルールに従います。つまり、ランダムな隣接マージを何度もシミュレートし、結果を平均します。 各シミュレーションの費用$O(n)$安定した精度を達成するには、クエリごとに多くの繰り返しが必要になり、絶望的な複雑さにつながります。 

間隔にわたる正確な DP さえも誤解を招きます。 すべての部分配列に対して期待される結果を計算しようとするかもしれませんが、マージ操作は単純な間隔の独立性を破壊する形で隣接関係の変化に依存します。 

重要な観察は、マージ操作を代数的に再解釈することです。 値の単一のマージを拡張すると$x$そして$y$、結果として得られる貢献度は$$x + y + xy.$$この式は次のように因数分解されます。$$(x+1)(y+1) - 1.$$この変換により、プロセスが複雑な確率的結合操作からきれいな乗算構造に変換されます。 

変換された値を定義すると$v_i = a_i + 1$、その後、マージごとに、隣接する 2 つの値がその積で置き換えられます。$$v_{\text{new}} = v_i \cdot v_{i+1}.$$乗算は結合的かつ可換的であるため、最終結果はマージのランダムなシーケンスとは独立しています。 すべての可能なゲームは同じ最終値を生成します。 

したがって、期待値は決定論的な値に等しく、問題はシフトされた値の範囲積を計算することに帰着します。 

範囲の更新によりセグメントが次のいずれかに置き換えられます$1,2,3,\dots,m$または$m,m-1,\dots,1$。 変換後、両方とも同じマルチセットを生成します$\{2,3,\dots,m+1\}$, したがって、どちらも同じ製品です。 これにより、更新が非常に簡単になります。セグメントが既知の製品で上書きされます。

 ## アルゴリズムのチュートリアル

 このソリューションは、変換された配列に対してセグメント ツリーを維持します。$v_i = b_i + 1$ただし、完全な構造を保存する代わりに、各ノードはそのセグメントの積のみを保存します。 

1. 各値を置き換えて初期配列を変換します。$b_i$と$b_i + 1$。 これは、吸収マージ ルールを乗算に直接エンコードします。 
2. 各ノードがそのセグメントのモジュロ 998244353 の積を格納するセグメント ツリーを構築します。リーフ ノードは単一の変換された値を格納し、内部ノードは子を乗算します。 
3. 範囲に関するクエリの場合$[l, r]$、の製品を返品します。$v_l \cdots v_r$、結果から 1 を減算します。 これは最終的な吸収スコアに正確に対応します。 
4. 一定の長さのセグメントの更新の場合$m = r - l + 1$、セグメントに割り当てられた新しい値を計算します。 セグメントは次の順列になるため、$1 \dots m$、変換された値は次のようになります。$2 \dots m+1$、その製品は$(m+1)!$。 この製品をセグメント ツリー内のセグメントに直接割り当てます。 
5. 範囲の割り当てには遅延伝播を使用します。セグメントが上書きされると、以前の構造は破棄され、格納されている積がその長さに対応する事前計算された階乗値に置き換えられます。 
6. 階乗を事前計算します。$n+2$一定時間内に更新に応答します。 

これが機能する主な理由は、すべての操作が互いに素なセグメントに対する乗算集計に帰着し、更新によって常にセグメントが内部配置が無関係な値に置き換えられるためです。 

### なぜ効果があるのか

 吸収作戦こそが正体$$x + y + xy = (x+1)(y+1) - 1.$$これにより、すべての要素が乗算の重みに変換されます。$v_i = a_i + 1$。 隣接する要素を繰り返しマージするプロセスは、すべての要素を繰り返し乗算することになります。$v_i$、順序に関係なく。 乗算は結合的かつ可換的であるため、どのマージ シーケンスでも同じ最終積が生成されます。 したがって、ランダム性は結果に影響を与えず、重要なのは変換された配列の積だけです。 範囲の更新はセグメントを固定マルチセットに置き換えるだけであり、そのマルチセットには順序に関係なく既知の積があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

MAXN = 200000 + 5

fact = [1] * (MAXN + 5)
for i in range(1, MAXN + 5):
    fact[i] = fact[i - 1] * i % MOD

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.prod = [1] * (4 * self.n)
        self.lazy = [None] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, v, l, r, arr):
        if l == r:
            self.prod[v] = arr[l] % MOD
            return
        m = (l + r) // 2
        self.build(v * 2, l, m, arr)
        self.build(v * 2 + 1, m + 1, r, arr)
        self.prod[v] = self.prod[v * 2] * self.prod[v * 2 + 1] % MOD

    def apply(self, v, l, r):
        if self.lazy[v] is None:
            return
        self.prod[v] = self.lazy[v]
        if l != r:
            self.lazy[v * 2] = self.lazy[v]
            self.lazy[v * 2 + 1] = self.lazy[v]
        self.lazy[v] = None

    def update(self, v, l, r, ql, qr, val):
        self.apply(v, l, r)
        if qr < l or r < ql:
            return
        if ql <= l and r <= qr:
            self.lazy[v] = val
            self.apply(v, l, r)
            return
        m = (l + r) // 2
        self.update(v * 2, l, m, ql, qr, val)
        self.update(v * 2 + 1, m + 1, r, ql, qr, val)
        self.prod[v] = self.prod[v * 2] * self.prod[v * 2 + 1] % MOD

    def query(self, v, l, r, ql, qr):
        self.apply(v, l, r)
        if qr < l or r < ql:
            return 1
        if ql <= l and r <= qr:
            return self.prod[v]
        m = (l + r) // 2
        return (self.query(v * 2, l, m, ql, qr) *
                self.query(v * 2 + 1, m + 1, r, ql, qr)) % MOD

n = int(input())
b = list(map(int, input().split()))

a = [(x + 1) % MOD for x in b]
st = SegTree(a)

q = int(input())
for _ in range(q):
    tmp = input().split()
    if tmp[0] == '?':
        l, r = int(tmp[1]) - 1, int(tmp[2]) - 1
        ans = st.query(1, 0, n - 1, l, r)
        print((ans - 1) % MOD)
    else:
        l, r = int(tmp[1]) - 1, int(tmp[2]) - 1
        m = r - l + 1
        val = fact[m + 1]
        st.update(1, 0, n - 1, l, r, val)
```このコードは、すべてのノードが積のみを格納するという事実に依存しているため、クエリは単純な範囲の乗算になります。 更新では、セグメント内の個々の値は再構築されません。 セグメント全体を 1 つの事前計算された積で上書きします。ダウンストリームの操作は集約された積にのみ依存するため、これで十分です。 

クエリでの 1 の減算は、変換を逆にすることによって直接行われます。$v_i = a_i + 1$。 

## 実用的な例

 初期配列を考慮してください$[3, 6, 2]$。 変革後、私たちは協力します$[4, 7, 3]$。 

| ステップ | 操作 | セグメント製品 |
 | --- | --- | --- |
 | 開始 | フルレンジ |$4 \cdot 7 \cdot 3 = 84$|
 | クエリ | 出力 |$84 - 1 = 83$|

 これは、マージがどのように行われたとしても、結果は変換された値の積にのみ依存することを示しています。 

次に、長さ 3 のセグメントを昇順に置き換えて更新することを考えます。 セグメントは次のようになります$[1,2,3]$なので、変換された値は次のようになります。$[2,3,4]$、その製品は$24$。 このセグメントに対する今後のクエリは、製品 24 を含む単一のブロックとして扱われます。 

これにより、変換が適用されると内部順序が無関係であることが確認されます。

 ## 特殊なケース

 重要なエッジケースは、フルレンジのアップデートです。 アルゴリズムは内部パターンを無視し、セグメントを単一の事前計算された積に置き換えます。 さまざまな長さの場合$m$、昇順更新と降順更新の両方で、同一の変換されたマルチセットが生成されるため、格納された積の一貫性が保たれます。 

もう 1 つの特殊なケースは、上書きが繰り返されることです。 各更新では以前の値が完全に置き換えられるため、履歴的な依存関係は残らず、セグメント ツリーには、基礎となる配列を再構築する必要がなく、常に最新の製品状態が反映されます。 

最後に、単一要素の範囲は正しく動作します。$a_i + 1$長さ 1 のセグメントが単に独自の値を格納することを保証し、その更新ルールを$m = 1$の積を正しく割り当てます$2!$。
