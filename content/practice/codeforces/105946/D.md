 ## 問題の理解

 ここで説明するプログラムは、整数配列を取得し、縦棒グラフに変換する前に簡単なフィルター処理を実行します。 正でない値はすべて破棄され、残りの値は元の順序を維持します。 このフィルタリングに何も残っていない場合、プロセスは直ちに失敗します。 それ以外の場合、残りの各値はグリッド内の列の高さになり、グリッドはこれらの高さを下から上に積み上げられたブロックとして視覚化します。 

重要な考え方は、最終出力が任意の ASCII アートではないということです。 これは、正の整数のシーケンスから描画されたヒストグラムを表す必要があります。 各列はフィルタリングされた配列の 1 つの要素に対応し、各列は下から上に埋められます。`#`その値と正確に等しい行数に対して。 上記のすべては、`.`。 

グリッドが与えられ、それがそのようなプロセスで生成された可能性があるかどうかを尋ねられます。もしそうであれば、最小長の有効な元の配列を再構築する必要があります。 

制約は小さく、どちらの次元も最大 100 です。これは、O(r・c) または O(r・c log c) の再構成で十分であることを示唆しています。 本当の難しさはパフォーマンスではなく、解釈の正しさです。グリッドは、下部に整列した連続ブロックの完全に垂直な列を含む暗黙のヒストグラムである構造に対してチェックする必要があります。 

単純ですがよくある失敗例は、下部の配置ルールを読み間違えることです。 たとえば、次のような列```
.#
#.
```起こり得ない理由は、`#`常に下から上に連続している必要があります。 もう 1 つの微妙な失敗は、列が独立していることを忘れていることです。高さがソートまたは単調である必要はありません。 

## アプローチ

 ブルートフォースの観点では、長さ c のすべての可能な配列 (各エントリが 0 から r の間) を推測し、それらのヒストグラムがグリッドと一致するかどうかを確認することになります。 前処理ステップ (正でない値を削除する) を無視したとしても、これですでに次の結果が得られます。$(r+1)^c$これは c = 100 の場合でも天文学的に大きくなります。 

グリッドを列ごとに確認すると、問題の構造からあいまいさがすべて取り除かれます。 最終的な画像の各列は、配列内に存在する必要がある値を一意に決定します。これは、連続する画像の高さが異なるためです。`#`下からのセルがまさにその値です。 配列の順序が保持されることを除いて、列間の相互作用はありません。 

残る唯一の複雑な問題は有効性です。各列には単一の連続したブロックが必要です。`#`一番下にあり、その上には何もありません。 いずれかの列がこれに違反すると、配列はそれを生成できなくなります。 有効になると、再構築された配列は単なる列の高さのリストになります。 

元のプログラムの「クリーニング」ステップでは、正でない値のみが削除されます。 出力グリッドには次のものしか含まれていないため、`#`そして`.`、有効な列は厳密に正の整数に対応する必要があるため、削除された要素を明示的に再構築する必要はありません。 最小長の要件は自動的になります。有効な列はすべて、正の数値を 1 つだけ提供する必要があり、追加の要素を導入する理由はありません。

 ## アルゴリズムのチュートリアル

 グリッドを c 個の独立した垂直列として解釈します。 

1. 各列 j について、連続する数を計算します。`#`下の行から上に向かって表示されます。 この数は、この列を生成できるバーの唯一可能な高さです。 そのブロックを超えると、その列は直ちに無効になります。 
2. 上方向にスキャンしているときに、`#`すでに見た後`.`、柱は構造的に不可能です。 これは、ヒストグラムの定義には次のすべてが必要であるためです。`#`セルを下から連続して接尾辞を形成します。 
3. 各列の計算された高さを配列に保存します。 列にゼロがある場合`#`の場合、その高さはゼロになりますが、クリーニング後には正の整数のみが残るため、最終的に再構築された配列では許可されません。 ただし、そのような列は完全に空である限り許容されます。 これは単純に、前処理中に削除されたことを意味しますが、出力にはグリッドを生成する最小限の正の配列が必要であるため、慎重に再解釈しない限り、これを無効として扱います。実際には、列はゼロです。`#`は高さ 0 を意味しますが、配列をクリーンアップすると正以外の値が削除されるため、そのような列はまったく表示されません。 したがって、すべてドットの列では答えは不可能になります。 
4. すべての列を処理した後、すべてが正で有効であれば、高さの配列を出力します。 

### なぜ効果があるのか

 出力グリッドの各列は、単一の整数の高さによって完全に決定されます。 ヒストグラムの構造には列間の結合がないため、グリッドはすべての列が次の接尾辞である場合にのみ有効です。`#`ある程度の正の長さ。 したがって、再構成は単射的です。つまり、列ごとに可能な値が 1 つだけ存在し、有効な解はこれらの値と一致する必要があります。 隣接性の侵害または孤立したものの存在`#`セルは下揃えスタッキングの定義に矛盾するため、拒否は正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

r, c = map(int, input().split())
grid = [input().strip() for _ in range(r)]

heights = []

for col in range(c):
    h = 0
    seen_dot = False

    for row in range(r - 1, -1, -1):
        if grid[row][col] == '#':
            if seen_dot:
                print("No")
                sys.exit(0)
            h += 1
        else:
            seen_dot = True

    if h == 0:
        print("No")
        sys.exit(0)

    heights.append(h)

print("Yes")
print(len(heights))
print(*heights)
```このソリューションは、列方向の再構成を直接エンコードします。 下向きのスキャンが選択されるのは、ヒストグラムの定義が下揃えであり、下から数えることで余分な変換を回避できるためです。 

の`seen_dot`フラグは連続性を強制します。`#`この地域、私たちは決して他の地域に会ってはなりません`#`。 これは、有効なヒストグラムと任意のパターンを区別する重要な構造上の制約です。 

小切手`h == 0`最終的にクリーン化された配列には正の整数のみが含まれるという要件への準拠が保証されます。つまり、生き残ったすべての列が少なくとも 1 つの整数を提供する必要があります。`#`。
