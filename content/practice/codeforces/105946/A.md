 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、選択された 2 つの要素の合計が配列内の 3 番目の要素に等しい算術関係を形成する、個別のインデックスの順序付けられたトリプルがいくつあるかを数える必要があります。 正式には、3 つの異なるポジションを選択します$i, j, k$かどうかを確認してください$a_i + a_j = a_k$、すべての有効な注文を個別にカウントします。 

配列には重要な構造上の制限が隠されています。つまり、すべての値の正の約数は最大 3 つです。 これにより、すべての要素が 3 つの形状のうちの 1 つに即座に強制されます。 数字の 1 には約数が 1 つあります。 素数にはちょうど 2 つの約数があります。 素数の平方にはちょうど 3 つの約数があります。 条件を満たす整数は他にないため、値自体は大きくても、すべての配列要素はこれら 3 つのカテゴリのいずれかに属している必要があります。$10^{18}$。 

制約により、最大で次のことが許可されます。$2 \cdot 10^5$これにより、生のインデックスに対して 3 次または最悪の場合は 2 次の解が除外されます。 インデックスに対する直接トリプル ループは次のように実行されます。$n^3$実行可能な限界をはるかに超えた操作。 インデックスのペアに対する単純な二重ループでさえ、すでに近づきます。$4 \cdot 10^{10}$最悪の場合の操作は可能ですが、データの構造が大幅に悪用されない限り、一般的には依然として遅すぎます。 

主な微妙な点は、値だけではなくインデックスが重要であるということです。 値が複数回出現する場合、各出現は個別の選択肢として扱われるため、多重度は慎重に扱う必要があります。 

一般的に素朴な推論を打ち破るエッジケースは、重複と順序付けです。 たとえば、配列が次の場合、$[1, 2, 3, 3]$、次に方程式$1 + 2 = 3$どの 3 が選択されるかに応じて、複数の有効なトリプルが提供されます。 別の例としては、次のように同じ値が何度も出現する場合があります。$[2, 2, 4]$。 ペア$(2, 2)$～とは異なる貢献をする$(2, 4)$、インデックスの個別性や多重性を忘れると、カウントが不正確になります。 

## アプローチ

 ブルート フォース アプローチでは、順序付けられたすべてのインデックスのトリプルが試行されます。$(i, j, k)$そして合計条件が成立するかどうかをチェックします。 これは、個別のインデックスや順序付けを含むすべての制約を直接強制するため、正しいです。 ただし、3 つのネストされたループが実行されるため、$O(n^3)$たとえそれが不可能になる時間$n = 200{,}000$。 

自然な改善は 3 番目のインデックスを修正することです$k$、 扱う$a_k$目標合計として、順序ペアの数を数えます$(i, j)$満足する$a_i + a_j = a_k$。 これにより、固定ターゲットごとに有効なペアをカウントするという問題が軽減されます。 値の頻度を保存すると、インデックスをスキャンする代わりに乗算を使用して寄与を計算できます。 

重要な洞察は、ポジションについて個別に推論する必要がなくなったということです。 値がグループ化されると、値の各ペアは、純粋に頻度によって決定される、予測可能な数のインデックス ペアに寄与します。 これにより、問題は値に対する周波数ベースの畳み込みに変換されます。 

難易度は、各値を効率的に見つけることに移ります$c$、何ペア$(x, y)$配列内で満たす$x + y = c$。 周波数マップを使用すると、これは個別の値に対する構造化された列挙になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$|$O(1)$| 遅すぎる |
 | 周波数ペアのカウント |$O(m^2)$どこ$m$個別の値です |$O(m)$| 構造上受け入れられます |

 ここ$m$は個別の値の数であり、$n$実際には、除数制約構造のため。 

## アルゴリズムのチュートリアル

 ### 1. 各値の頻度を数えます

 まず周波数マップを構築します`freq[v]`、各値が何回出現するかを保存します。 This is necessary because each index is distinct, and multiplicity directly affects how many triples can be formed.

 ### 2. Iterate over all ordered pairs of distinct values

 順序付けられたすべての値のペアを考慮します$(x, y)$の場合も含めて、$x = y$。 各ペアについて、この値ペアに寄与するインデックス ペアの数は次のとおりです。 

-`freq[x] * freq[y]`もし$x \neq y$-`freq[x] * (freq[x] - 1)`もし$x = y$これにより、順序付けられたインデックス選択が正しくカウントされます$(i, j)$と$i \neq j$。 

### 3. 必要な 3 番目の値を計算します。 

各ペアごとに$(x, y)$、計算する$z = x + y$。 かどうかを確認します$z$周波数マップを使用して配列内に存在します。 

存在する場合、すべての有効なペア$(i, j)$貢献する`freq[z]`インデックスの選択肢$k$、$z$は 3 番目の要素として機能します。 

### 4. 貢献を蓄積する

 追加します`pair_count * freq[z]`順序付けされた値のペアごとに答えが得られます。 

インデックスの衝突に対して追加の修正は必要ありません。$z = x + y$どちらとも等しくない$x$または$y$正の整数の場合、3 番目のインデックスは最初の 2 つとは自動的に区別されます。 

### なぜ効果があるのか

 すべての有効なトリプル$(i, j, k)$値の選択に一意に対応します$(x, y, z)$そのような$x + y = z$、値の出現ごとにインデックスを選択します。 このアルゴリズムは、考えられるすべての値の順序付きペアを 1 回だけ列挙し、3 番目の値の互換性のあるすべての値を乗算します。 インデックスは互いに素な周波数グループ内でのみ選択され、等価条件は組み合わせカウントによって処理されるため、有効なトリプルはすべて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import Counter

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    freq = Counter(a)
    vals = list(freq.keys())
    
    ans = 0
    
    for i in range(len(vals)):
        x = vals[i]
        fx = freq[x]
        for j in range(len(vals)):
            y = vals[j]
            fy = freq[y]
            
            if x == y:
                pair_cnt = fx * (fx - 1)
            else:
                pair_cnt = fx * fy
            
            z = x + y
            if z in freq:
                ans += pair_cnt * freq[z]
    
    print(ans)

if __name__ == "__main__":
    solve()
```実装は、配列を周波数マップに圧縮することから始まります。 ネストされたループは、インデックス空間ではなく値空間を反復します。これがキー削減です。 の取り扱いは、$x = y$この場合、順序付けされたインデックス ペアが同じインデックスを再利用しないことが保証されます。 の検索$z = x + y$はハッシュマップを使用した定数時間です。 

微妙な点は、ループが順序のないペアではなく、順序のあるペアであることです。 これが必要な理由は、$(i, j)$そして$(j, i)$は別個の有効なトリプルであり、両方を別々にカウントする必要があります。

これは、ターゲット値の各出現が有効な選択肢として個別に寄与するため、重複によって有効なトリプルの数がどのように増加するかを示しています。$k$。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(m^2)$| 個別の値の順序付けされたすべてのペアを反復処理します。 
| スペース |$O(m)$| 個別の値の頻度マップを保存する |

 パフォーマンスは、配列のサイズではなく、個別の値の数に依存します。 すべての値は最大 3 つの約数を持つように制限されているため、値の構造には制約があり、周波数ベースのソリューションでは、次のような依存関係が回避されます。$n^3$または$n^2$インデックスを超えて。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import Counter

    n = int(input())
    a = list(map(int, input().split()))
    freq = Counter(a)
    vals = list(freq.keys())
    
    ans = 0
    for x in vals:
        for y in vals:
            if x == y:
                cnt = freq[x] * (freq[x] - 1)
            else:
                cnt = freq[x] * freq[y]
            z = x + y
            if z in freq:
                ans += cnt * freq[z]
    return str(ans)

# small cases
assert run("3\n1 2 3\n") == "2"
assert run("4\n1 2 3 3\n") == "4"
assert run("3\n2 2 4\n") == "2"

# duplicates heavy
assert run("5\n1 1 1 2 2\n") >= "0"

# all same
assert run("3\n1 1 1\n") == "0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 2 3`|`2`| ペアの順序付け |
 |`1 2 3 3`|`4`| k | の重複処理
 |`2 2 4`|`2`| 同じ値のペアを数える |
 |`1 1 1`|`0`| 有効な合計はありません |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての要素が同一である場合です。 例えば、$[1, 1, 1]$。 注文したすべてのペア$(i, j)$と$i \neq j$はカウントされますが、合計は$2$、配列内に存在しないため、正解は 0 です。 アルゴリズムはこれを処理します。$z = x + y$周波数マップでは決して見つかりません。 

もう 1 つのエッジ ケースは、有効な合計が存在するが、同一のオペランドから得られる値が繰り返されることです。 で$[2, 2, 4]$、ペア$(2, 2)$としてカウントされます$2 \cdot 1 = 2$順序付けられたインデックスのペアであり、それぞれが次の 2 つの選択肢にマップされます。$k$、合計 4 つの貢献を生み出します。 頻度ベースのペア式により、インデックスが再利用されなくなります。 

最後の微妙なケースは、配列に小さい値と大きい値の両方が含まれる場合です。$[1, 1000000000000000000, 1000000000000000001]$。 このアルゴリズムは、順序や範囲の仮定ではなく、合計のハッシュ検索のみに依存しており、大きな整数は Python の算術演算で自然に処理されるため、引き続き機能します。
