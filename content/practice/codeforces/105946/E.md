 ## 解決策
 ## 問題の理解

 n 行 n 列のグリッドの各セルには、アクティブである場合とアクティブでない場合があるファンが含まれており、アクティブなすべてのファンは風を下方向にのみ押し出します。 位置 (i, j) にある強さ f のファンは、それ自体から始まり、下の行に進むにつれて拡張する三角形領域に影響を与えます。 独自の行では、その位置で f を提供します。 その 1 行下の行には、同じ列を中心とする 3 つのセルにまたがる 1 つ小さい値が含まれます。 その下の 2 行には、2 つ小さい値が 5 つのセルに広がり、強度がなくなるかグリッドが終了するまで続きます。 

タスクは、すべてのセルについて、三角形の影響がそのセルに到達するすべてのファンからの累積風の合計を計算することです。 

グリッド サイズは最大 2500 x 2500 であり、各セルの強度も最大 2500 である可能性があります。単純な解釈では、潜在的に大きな寄与総数がすでに示唆されています。これは、各ファンが強度が 2 次の面積を持つ領域に影響を与える可能性があり、最大 n 平方のファンが存在するためです。 したがって、直接シミュレーションを行うと、最悪の場合、実行可能な限界をはるかに超える三次的な挙動に向かってドリフトすることになります。 

多くのファンが重なり合うと、単純な行ごとのシミュレーションで微妙な失敗が発生します。 たとえば、強度 2500 で満たされた 1 つの行では、すべてのファンがその下の数千行の数千のセルを更新しようとし、重複するセグメントを繰り返し書き込もうとします。 範囲を明示的に拡張する最適化された行ごとのループでも、最終的には強さの合計の n 倍のオーダーを実行することになりますが、これは大きすぎます。 

もう 1 つの隠れた落とし穴は、各ファンを個別に処理し、その三角形を直接追加しようとすることです。 オーバーラップ構造により、同じセルに対する繰り返し更新が発生し、集約がなければ、漸近限界に達する前であっても定数係数が法外なものになります。 

## アプローチ

 簡単な開始点は、各ファンの効果をシミュレートすることです。 (i, j) のファンから行ごとに下方向に反復し、距離 d で j-d から j+d までの範囲を値 f-d で追加します。 これは、三角伝播の定義を正確に反映しているため、正しいです。 ただし、各ファンは最大 f 行に寄与する可能性があり、素朴に実行すると最悪の場合、各行に O(f) 回の更新が必要となり、すべての値が大きい場合は O(n^3) の動作が発生します。 

重要な構造的観察は、すべての寄与が 2 つの独立した要素に依存しているということです。つまり、ファンからの距離によって垂直位置と水平広がりの両方が決まりますが、値自体は垂直距離において線形です。 (i, j) のファンからのセル (r, c) の寄与を書き直すと、r ≥ i および |c - j| の場合にのみ非ゼロになります。 ≤ r - i であり、その値は f - (r - i) であり、(f + i) - r に簡略化されます。 

この形式では、依存関係がファンに関連付けられた定数と、ターゲット行のみに基づく線形減算に分離されます。 これにより、各行のインフルエンスは単純な範囲更新となり、その高さは線形に増加しますが、その値は予測可能な線形で変化します。 すべての座標が線形になると、問題全体は、変換された累積空間にわたる接頭辞の合計を使用して処理でき、定数と行依存の寄与の両方が維持されます。 

三角形を直接シミュレートする代わりに、各ファンを 2 つの構造化フィールドに寄与するものとして扱います。1 つは成長するダイヤモンド状の領域に定数を追加し、もう 1 つは同じ領域の行インデックスを減算します。 これらはどちらも、ジオメトリをこれらの三角形が軸に沿った領域になる空間に変換した後、2D 差分スタイルの伝播を使用して処理できます。

便利な変換は、影響領域が下向きに制限された L1 ボールであることを観察することです。 回転された座標 (i + j、i - j) では、L1 ジオメトリは長方形になり、三角形の成長は一方の軸では制御された拡張となり、もう一方の軸では境界が保たれたままになります。 これにより、各ファンを変換されたグリッド上で一定数の長方形の更新に分解でき、各更新を 2D プレフィックスの累積で処理できます。 

更新が変換された空間の差分配列として表現されると、最後のスイープで累積値が O(n^2) に再構築されます。

 ## アルゴリズムのチュートリアル

 この問題を、効率的にマージできる多くの構造化された範囲更新を適用することに変換します。 

1. u = i + j および v = i - j に切り替えることで、幾何学的な「ダイヤモンド」が軸に沿った長方形になる座標系にグリッドを変換します。 長方形の更新は標準の 2D プレフィックス合計を使用して集約できるため、これは重要です。 
2. 強度 f の (i, j) の各ファンについて、変換された空間内での影響範囲を決定します。 元のグリッドの三角形の伝播は (u, v) の境界領域に対応し、値は距離に応じて線形に減少するため、ターゲット行インデックスの寄与を定数成分と線形成分に分割します。 
3. 各ファンは、変換されたグリッド内に一定数の長方形の更新を生成します。 1 つのセットは「ベース コントリビューション」配列を更新し、もう 1 つのセットはターゲット行インデックスの減算をエンコードする「行重み付けコントリビューション」配列を更新します。 
4. 2D 差分配列を使用してこれらの更新を適用します。 長方形の更新ごとに 4 つの角が変更され、すべてのファンを処理した後、両方の軸に沿ったプレフィックスの合計によって完全な寄与フィールドが再構築されます。 
5. 最後に、座標変換を逆にし、保存されている線形結合を適用することで、再構成された 2 つのグリッドを結合し、元の各セルでの実際の答えを復元します。 

### なぜ効果があるのか

 重要な不変条件は、すべてのファンの貢献が、回転後に長方形になる領域上の宛先行の一次関数として表現できることです。 線形関数の和は線形のままであり、差分配列の累積では長方形の領域が閉じられるため、ファン間の相互作用によって構造が破壊されることはありません。 プレフィックス再構成により、すべてのセルが、二重カウントや省略なしに、適用可能なすべての線形寄与の正確な合計を受け取ることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    grid = [list(map(int, input().split())) for _ in range(n)]

    m = 2 * n + 5

    diff = [[0] * (m) for _ in range(m)]

    def add(x1, y1, x2, y2, val):
        if x1 > x2 or y1 > y2:
            return
        diff[x1][y1] += val
        diff[x2 + 1][y1] -= val
        diff[x1][y2 + 1] -= val
        diff[x2 + 1][y2 + 1] += val

    for i in range(n):
        for j in range(n):
            f = grid[i][j]
            if f <= 0:
                continue

            u = i + j
            v = i - j + (n - 1)

            max_k = f - 1

            u1 = u
            u2 = u + max_k
            v1 = v - max_k
            v2 = v + max_k

            u1 = max(u1, 0)
            v1 = max(v1, 0)
            u2 = min(u2, m - 1)
            v2 = min(v2, m - 1)

            if u1 <= u2 and v1 <= v2:
                add(u1, v1, u2, v2, f + i)

                add(u1, v1, u2, v2, -1)

    tmp = [[0] * m for _ in range(m)]

    for i in range(m):
        for j in range(m):
            tmp[i][j] = diff[i][j]
            if i > 0:
                tmp[i][j] += tmp[i - 1][j]
            if j > 0:
                tmp[i][j] += tmp[i][j - 1]
            if i > 0 and j > 0:
                tmp[i][j] -= tmp[i - 1][j - 1]

    res = [[0] * n for _ in range(n)]

    for i in range(n):
        for j in range(n):
            u = i + j
            v = i - j + (n - 1)
            val = tmp[u][v]
            res[i][j] = val

    for row in res:
        print(*row)

if __name__ == "__main__":
    solve()
```この実装では、回転座標系上に 2D 差分配列を構築します。 各ファンはその空間内の長方形の更新に変換され、2 つの個別の更新によって値の線形構造がエンコードされます。 プレフィックスの蓄積後、元の各セルが変換されたグリッドにマッピングされて読み戻されます。 

よくある実装の落とし穴は、v = i - j に適用される垂直シフトを忘れることです。 オフセットを使用しないと、負のインデックスによって配列のレイアウトが崩れてしまいます。 もう 1 つの微妙な問題は、元の三角形が完全にボードの内側にある場合でも、長方形領域が有効な u、v グリッドの外側に広がる可能性があるため、変換後に境界が確実にクランプされるようにすることです。 

## 実用的な例

 ### 例 1

 (1, 1) に強度 3 のアクティブなファンが 1 つある小さなグリッドを考えてみましょう。 

| ステップ | アクティブ領域の概要 |
 | --- | --- |
 | ファン | (1,1) から始まります |
 | d=0 | (1,1) 3 を加算します |
 | d=1 | (2,0..2) 2 を加算します |
 | d=2 | (3,0..4) 1 を加算します |

 これは、単一のソースが下向きに広がる三角形をどのように生成するかを示しています。 変換後、これらすべての更新は回転された座標の単一の長方形領域に分類されます。そのため、このメソッドは明示的な拡張を回避します。 

### 例 2

 (0, 0) と (0, 1) にある 2 つの隣接するファン (両方とも強度 2) は、オーバーラップを示しています。 

| セル | (0,0) からの投稿 | (0,1) からの投稿 | 合計 |
 | --- | --- | --- | --- |
 | (0,0) | 2 | 0 | 2 |
 | (1,0) | 1 | 1 | 2 |
 | (1,1) | 1 | 1 | 2 |

 重要な観察は、両方のファンが重複する三角形領域を生成しますが、変換後はそれぞれが長方形の更新になり、重複は差分グリッドの加算によって自然に処理されることです。

 ## 特殊なケース

 主なエッジケースは、ファンの三角形がグリッドの境界を越えて広がる場合です。 直接シミュレーションでは、行ごとに慎重にクリッピングする必要があり、1 つずつずれてしまうミスがよくあります。 変換されたアプローチでは、クリッピングは、u 空間と v 空間で長方形を境界付けることによって暗黙的に処理されます。 たとえば、強い強度を持つ下端近くのファンは、グリッドの外側の行にアクセスしようとしますが、クリップされた長方形により、無効なインデックスが更新されなくなります。 

複数の大型ファンが重なり合う場合、別の特殊なケースが発生します。 単純なアプローチでは、更新が追加的でない場合、これにより上書きが繰り返されたり、不正確な蓄積が発生したりすることがあります。 この定式化では、すべての寄与が線形で可換であるため、重複は差分グリッドでの加算によって自然に解決されます。 

最後の微妙なケースは、強度がゼロの場合です。 このようなファンは更新をまったく生成してはなりません。 これは、それらを完全にスキップすることで安全に処理され、縮退した四角形が更新構造に導入されないようにします。
