 ## 問題の理解

 隠れた整数を扱っています$n$これは開始時に固定されており、1 ～ 10,000 の間のどこかにあります。 それに関する情報を得る唯一の方法は、「は$n$で割り切れる$x$？"、 どこ$x$1 ～ 10,000 の任意の整数です。 各クエリは単純な「はい」または「いいえ」の答えを返します。十分な推論の後、次の正確な値を出力する必要があります。$n$。 

これは標準入力の問題ではなく、対話型の問題です。 プログラムは、外部の審査員との対話中にプログラムがどのように動作するかによって判断されるため、正確かどうかは、有益なクエリを実行し、最終的には正確な値をコミットするかどうかに依存します。 

制約$n \le 10^4$重要な構造上の制限です。 それは次のことを意味します$n$多重度で数えた場合、素因数は最大でも約 4 つで、すべての素因数は最大でも 100 です。これにより、ランダム化テストや大規模な事前計算などの高度な技術の必要性が即座に排除されます。 およそ数百のクエリで機能するものは、1500 クエリの制限内であれば安全です。 

素朴だが誘惑に駆られる間違いは、推測してみることである$n$直接、またはクエリによってすべての候補をスキャンします。$n$は候補値で割り切れます。 割り算チェックでは倍数を一意に区別できないため、このアプローチは失敗します。 たとえば、次の場合$n = 36$の場合、6、12、18、24、30 をクエリすると、すべてさまざまな方法で Yes が返されますが、構造化された分解を行わないと 36 を一意に分離できません。 

本当に難しいのは、割り算は次の素因数分解の射影であるということです。$n$、そして数値そのものではなく完全な因数分解を再構築する必要があります。 

## アプローチ

 強引な戦略はすべての候補者を試すことになる$x$1 から 10,000 までを指定し、一致するかどうかを判断します。$n$割り算クエリを使用します。 ただし、この方法で数値を一意に識別するには、割り算だけでは不十分です。 かどうかをテストして候補者を排除しようとしても、$n$は慎重に選択した値で割り切れますが、多くの約数を共有する数値を区別する必要があります。 最悪の場合、これは、クエリ バジェットの下では確実に解決できない大規模な候補セットに変質します。 

重要な構造的観察は、10,000 までのすべての整数はその素因数分解によって完全に決定され、すべての素因数は最大でも 100 であるということです。$n$直接的には、各素数の指数を独立して再構築できます。 

固定素数の場合$p$、何回かを決定できます$p$分割する$n$かどうかを繰り返し尋ねることで、$n$で割り切れます$p, p^2, p^3, \dots$。 答えが「いいえ」になると、正確な指数がわかります。$p$因数分解で。 100 までのすべての素数に対してこれを繰り返すと、完全に決定されます。$n$。 

これにより、問題がグローバルな識別から素数に対する独立したローカルな測定に変換されます。これがまさにクエリ バジェット内に収まる理由です。

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 100 までのすべての素数を生成する

 まず、単純なふるいまたは事前に計算された定数リストを使用して、100 までのすべての素数をリストします。 10,000 までの整数はそれ自体が素数でない限り 100 を超える素因数を持つことができず、そのような素数は直接検出されるため、これで十分です。 

### ステップ 2: 各素数について、その指数を決定します。$n$素数ごとに$p$かどうかをクエリすることから始めます。$n$で割り切れます$p$。 答えが「いいえ」の場合、$p$因数分解には寄与しないので次に進みます。 

答えが「はい」の場合は、より高い累乗を試します。$p^2, p^3, p^4$、クエリを発行するたびに。 答えが「いいえ」になった時点で終了します。 最後に成功したパワーにより、次の正確な指数が得られます。$p$で$n$。 

各ステップは次のように割り切れるため機能します。$p^k$少なくとも$k$のコピー$p$因数分解で。 

### ステップ 3: 数値を再構成する

 すべての指数がわかったら、再構成します$n$乗算して$p^{e_p}$すべての素数にわたって。 範囲が狭いため、この製品は安全に範囲内に収まります。 

### ステップ 4: 答えを出力する

 最後に、再構成された値を必要な形式で出力します。 

### なぜ効果があるのか

 このアルゴリズムは、各素数について、任意の時点で次のような不変条件に依存します。$p$かどうかを正しく判断しました。$p^k \mid n$テストされたすべての人にとって$k$。 割り算は単調なので、$k$、クエリが「いいえ」を返すと、より上位のパワーもすべて無効になります。 これにより、各指数を正確に復元できます。また、素因数分解は一意であるため、再構成された数値は等しくなければなりません。$n$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Precompute primes up to 100
def sieve(n=100):
    is_prime = [True] * (n + 1)
    is_prime[0] = is_prime[1] = False
    primes = []
    for i in range(2, n + 1):
        if is_prime[i]:
            primes.append(i)
            for j in range(i * i, n + 1, i):
                is_prime[j] = False
    return primes

primes = sieve()

def ask(x):
    print("?", x)
    sys.stdout.flush()
    return input().strip()

def main():
    factors = {}

    for p in primes:
        if p > 10000:
            break

        # check first power
        if ask(p) == "No":
            continue

        exp = 1
        power = p

        # try higher powers
        while True:
            if power > 10000 // p:
                break
            power *= p
            if ask(power) == "Yes":
                exp += 1
            else:
                break

        factors[p] = exp

    # reconstruct n
    n = 1
    for p, e in factors.items():
        for _ in range(e):
            n *= p

    print("!", n)
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```ふるいは、最大 100 までの候補素数のセットを構築します。`ask`関数はインタラクションをラップし、クエリごとにフラッシュを保証します。これはインタラクティブな問題では必須です。 

メインループは各素因数を独立して分離します。 指数の検出では同じ素数の二乗を繰り返しますが、10,000 を超えないように慎重に上限が設定されています。 これにより、正確性を確保しながら、不必要なクエリを防止します。 

境界により Python の整数容量を超えるオーバーフローが発生しないことが保証されているため、再構築のステップは単純な乗算です。

 ## 特殊なケース

 のために$n = 1$の場合、すべての割り算クエリは「No」を返します。 このアルゴリズムは素因数を決して記録せず、積を 1 として再構築しますが、これは正しいことです。 

次のような素数の場合$n = 97$の場合、1 つのクエリのみが「Yes」を返し、他のクエリはすべて即座に失敗します。 このアルゴリズムは指数 1 を正しく割り当て、より高い累乗を試みることなく数値を再構成します。 

次のような最大値の場合$n = 10000$に等しい$2^4 \cdot 5^4$、両方の素数が完全な指数連鎖までテストされます。 乗算が 10,000 を超える前に慎重に制限されるため、より強力なクエリはそれぞれ範囲内に留まります。
