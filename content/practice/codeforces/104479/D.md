 ## 解決策
 ## 問題の理解

 1 から n までのラベルが付いた頂点上に有向完全グラフを構築しています。 頂点 u と v のすべてのペアについて、それらの間に 1 つの有向エッジが作成されます。 方向はランダムですが偏っています。u が v より小さい場合、u から v へのエッジは確率 a/b で現れます。そうでない場合、エッジは v から u へ確率 1 − a/b で進みます。 すべてのペアは独立して決定されます。 

すべてのエッジが修正されると、グラフはトーナメントになります。 タスクは、このトーナメントに有向サイクルが含まれていない確率、つまりエッジが頂点の一貫した順序を形成している確率を計算することです。 

すべてのエッジがその順序で前方を向くような頂点の順序が存在する場合、トーナメントはまさに非周期的です。 言い換えれば、ランダムな方向性が偶然に全体の順序を生み出すに違いありません。 

制約は大きく、n は最大 10^6 です。 n^2 個のエッジのペアが暗黙的にすでに存在しているため、これにより、n の二次関数は直ちに除外されます。 エッジを越える O(n^2) 推論ですら不可能であるため、解法ではすべてのペアの寄与を閉じた形式または線形時間で評価できる積に圧縮する必要があります。 

順列を直接シミュレートしたり数えたりしようとすると、微妙な失敗例が発生します。 答えは一貫した確率のすべての順列の合計ですが、順列の列挙は階乗的であり、自明なサイズを超える小さな n の場合でも完全に実行不可能です。 

もう 1 つの隠れた落とし穴は、すべてのトーナメントを一律に扱うことです。 a = b/2 の場合、対称性は既知の結果をもたらしますが、ここではバイアスが固定ラベル順序に依存するため、頂点を反転または名前変更すると、均一ではなく構造化された方法で確率が変化します。 

## アプローチ

 まず確率を無視すると、非巡回トーナメントの構造は単純です。すべての非巡回トーナメントは、頂点の 1 つの合計順序に正確に対応します。 頂点の順列を修正する場合、すべてのエッジをその順列に一貫して配置する方法が 1 つだけあります。 

これは、総当たりのアプローチを示唆しています。つまり、頂点のすべての順列を反復し、ランダムなプロセスによって正確にその方向が生成される確率を計算し、すべての寄与を合計します。 固定順列の場合、頂点の各ペアは、方向が順列順序と一致するかどうかに応じて、a/b または 1 − a/b の係数に寄与します。 これは正しいですが、n 個あるためすぐに失敗します。 順列が大きすぎます。 

重要な観察は、順列の確率は、自然順序 1 から n に対してどれだけの反転があるかによってのみ依存するということです。 各ペア u < v は、置換によって u が v の前に維持されるか、またはそれらが逆転するかによって、寄与度が異なります。 これは、順列にわたる合計を、反転カウントに対する古典的なマホニアン生成関数に変換します。 

このオブジェクトは積として美しく因数分解されることが知られています。 

(1 + q)(1 + q + q^2)...(1 + q + ... + q^{n−1})、

 ここで、q はエッジ確率から導出される比率です。 これにより、指数合計が線形時間積に分解されます。 

残りの作業は代数正規化です。エッジの数に累乗した確率基数 p に対応する定数項を因数分解し、すべてをきれいなモジュラー式に変換します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 置換に対するブルートフォース | O(n! · n) | O(n) | 遅すぎる |
 | 因数分解反転生成関数 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 p = a / b と表し、順序のない頂点の各ペアを考慮します。 すべてのペアについて、プロセスは方向を独立して選択します。

1. 問題を頂点のすべての順列の合計に変換します。 各順列は、トーナメントの候補トポロジー順序を表します。 トーナメントは、そのエッジが何らかの順列と一致する場合にのみ非周期的になります。 
2. 順列 σ を固定し、その確率を計算します。 頂点 u と v のすべてのペアについて、エッジは σ の次数と一致する必要があります。 σ が u を v の前に置く場合、u → v が必要です。 それ以外の場合は、v → u が必要です。 
3. ラベルの順序が u < v であるペア (u, v) の場合、寄与は σ がこの自然な順序を維持するか逆転するかによってのみ依存することに注目してください。 σ が v の前に u を保持する場合、確率寄与は p です。 σ がそれらを逆転すると、寄与は 1 − p になります。 
4. 自然順序に対して σ だけ反転したペアが何個あるかを数えます。 この数値を inv(σ) と呼びます。 合計 C = n(n−1)/2 のペアがあります。 この場合、σ の確率は p^{C − inv(σ)} (1 − p)^{inv(σ)} となります。 
5. すべての項から p^C を因数分解します。 確率の合計は、((1 − p)/p)^{inv(σ)} の順列の合計を p^C に乗算したものになります。 
6. q = (1 − p) / p を導入します。 残りの合計は、まさにサイズ n の順列に対する反転生成関数です。 これはマホニアン分布の合計であり、(1 + q + q^2 + ... + q^{i−1}) の 1 から n までの i にわたる積に等しい。 
7. この製品を繰り返し評価します。 各因数 (1 + q + ... + q^{i−1}) が前の値から O(1) 時間で計算できるように、q のべき乗を維持します。 
8. 最終的な積に p^C を乗算し、除算の逆剰余を使用して結果の剰余 998244353 を返します。 

### なぜ効果があるのか

 すべての非巡回トーナメントは、頂点の 1 つの順列に正確に対応し、固定トーナメントを生成する確率は、自然なラベル付けに対する反転構造にのみ依存します。 これにより、問題全体が、重みが反転数のみに依存する順列にわたる重み付きカウントに縮小されます。 反転数はマホニアン分布の基礎となる同じ統計量であるため、合計は既知の q 階乗積に因数分解され、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

n, a, b = map(int, input().split())

p = a * modinv(b) % MOD
one_minus_p = (b - a) * modinv(b) % MOD

C = n * (n - 1) // 2

# q = (1-p)/p
q = one_minus_p * modinv(p) % MOD

# compute product (1 + q + ... + q^{i-1})
prod = 1
cur_sum = 1   # q^0
cur_pow = 1   # q^0

for i in range(2, n + 1):
    cur_pow = cur_pow * q % MOD
    cur_sum = (cur_sum + cur_pow) % MOD
    prod = prod * cur_sum % MOD

ans = pow(p, C, MOD) * prod % MOD
print(ans)
```コードはまずエッジ バイアスから確率比 q を構築します。 次に、q の累乗を繰り返し維持し、幾何学的な接頭辞を累積することによって、q アナログ階乗を構築します。 最後に、エッジの総数に累乗した p を乗算します。これは、常に順方向を選択する基本確率寄与を説明します。 

よくある間違いは、b による正規化を忘れることです。これにより、モジュラー演算で間違ったスケーリングが発生します。 もう 1 つの微妙な点は、モジュロ演算では直接除算ができないため、逆モジュラを使用して q を安全に計算することです。 

## 実用的な例

 ### 例 1

 入力:

 n = 3、a = 1、b = 3

 ここで p = 1/3 であるため、各前方エッジは後方エッジよりも可能性が低くなります。 

合計 C = 3 つのエッジを計算します。 

比率 q = (1 − p)/p = 2。 

私たちは製品を構築します:

 i = 1:1

 i = 2: 1 + q = 3

 i = 3: 1 + q + q^2 = 7

 したがって、積 = 3 × 7 = 21 となります。 

次に、p^3 = (1/3)^3 = 1/27 を掛けます。 

最終確率 = 21/27 = 7/9。 

これは、順方向の可能性は低いものの、複数の順列では非環状構造が依然として存在する可能性があるという事実に対応しています。 

### 例 2

 入力:

 n = 2、a = 1、b = 2

 エッジが 1 つあります。 方向に関係なく非周期的です。 

C = 1、p = 1/2、q = 1。 

積 = (1 + 1) = 2。 

最終結果 = (1/2) × 2 = 1。 

これは、2 つの頂点がある場合、すべての結果が DAG であることを確認します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、n = 1 の場合です。エッジがないため、グラフは自明に非周期的になります。 アルゴリズムは C = 0 を生成するため、p^C = 1 となり、積は空であり、1 となり、正しい答えが得られます。 

もう 1 つのエッジ ケースは、a が b に非常に近く、q が小さくなる場合です。 この場合、q の累乗は体を法としてすぐに消失しますが、各項は乗算の前に累積されるため、実行中の幾何学和は安定したままになります。 

a = 1 で b が大きく、p が非常に小さくなる場合、より微妙なケースが発生します。 p^C の直接累乗は、逆モジュラを使用して慎重に実行する必要があります。そうしないと、b による除算が失われます。 この実装では、累乗の前にモジュロ演算で p を明示的に構築し、正確さを保ちます。
