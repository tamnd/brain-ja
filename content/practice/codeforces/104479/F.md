 ## 解決策
 ## 問題の理解

 時間をかけて育む森林を整備しています。 最初は n 個の孤立した頂点があります。 タイプ 1 の各更新は、以前に切断されていた 2 つの頂点を接続するため、すべてのコンポーネントは常にツリーのままになります。 

この進化する森の上で、確率ゲームのクエリを繰り返し実行します。 与えられた開始頂点 x に対して、アリスは、グラフを見た後、ボブの選択について何も知る前に、エッジに沿って最大 m ステップ歩くことができます。その際、最適な歩行を選択します。 ボブは独立して k 個の異なる頂点を均一にランダムに選択し、それらを特別なマークを付けます。 アリスは、歩行中に訪問する少なくとも 1 つの頂点に特別な頂点が存在する場合に勝ちます。 x 自体が特別であれば、アリスは即座に勝ちとなるため、訪問済みセットには常に x が含まれます。 

タスクは、各クエリの後で、最適なプレイを仮定して、アリスが勝つ確率に答えることです。 

制約は大きく、最大 2・10^5 頂点と 5・10^5 クエリ、m は 10^9 までです。 これにより、散歩をシミュレートしたり、クエリごとに近隣を探索したり、ツリー構造を最初から再計算したりするアプローチは即座に除外されます。 各クエリは、前処理後にほぼ対数時間または定数時間で応答される必要があり、更新は償却定数に近い必要があります。 

重要な問題は、グラフは動的であるものの、森としてしか成長しないことです。その確率は、アリスが最適な歩行でどれだけ多くの個別の頂点を強制的に訪問できるかによって決まります。 

アリスの歩行が x の周りの半径 m の「ボール」を探索すると仮定すると、微妙な落とし穴が現れます。 ウォークはツリーの横断ではありません。ノードを再訪問する可能性がある単一のパスであるため、分岐することはできません。 たとえば、m=2 の x を中心とする星では、アリスは x のすべての近傍を訪問することはできず、1 つの近傍と x ともう 1 つのステップのみを訪問します。 これを BFS レイヤーとして扱うと、到達可能なカバレッジを過大評価し、不正確な確率が生成されます。 

もう 1 つの問題は、ランダム性が局所的に構造と相互作用すると仮定することです。 確率は、アリスが歩行に含めることができる個別の頂点の数にのみ依存し、頂点の配置には依存しません。 

## アプローチ

 最適なプレイを無視すると、単純なシミュレーションでは、x から最大で m の長さのすべてのウォークを列挙し、各ウォークの訪問頂点の結合を計算して、最良のものを取得しようとします。 ツリーの場合でも、分岐係数が大きくなり、m が 10^9 になる可能性があるため、これは指数関数的に爆発的に増加し、直ちに実行不可能になります。 

アリスが実際に何を最大化しようとしているかを観察することで、問題を単純化できます。 訪問頂点の固定セット S の場合、ボブの選択は、それが S と交差するかどうかによってのみ重要になります。ボブが n から一様にランダムに k 個の頂点を選択した場合、勝利確率は |S| にのみ依存します。 

アリスが負ける確率は、選ばれた k 個の頂点がすべて S の補数にある確率、つまり C(n−|S|, k) / C(n, k) です。 

したがって、アリスの勝利確率を最大化することは、アリスが有効な歩行に含めることができる個別の頂点の数を最大化することと同じです。 

さて、木の中を歩く構造が重要です。 頂点を再訪しても役に立たないため、最適な戦略は、x から始まり長さが最大でも m の単純なパスです。 したがって、アリスは x から単一のパスを選択し、それを一方向にどれだけ延長できるかを最大化したいと考えています。 

これにより、問題は、各ノード x について、x からその接続コンポーネント内の任意のノードまでの最大距離を計算することになります。 これはまさに、ツリー内の x の離心率です。 ただし、アリスは m ステップに制限されているため、必ずしも完全な偏心率を使用できるわけではありません。 したがって、個別の訪問頂点の数は min(m+1, ecc(x)+1) になります。 

残るのは、ダイナミックに成長する森林の中で偏心状態を維持することです。 各クエリは、以前に切断されていた 2 つのコンポーネント間にエッジを追加します。 距離クエリをサポートし、ユニオン操作で直径を効率的に維持する必要があります。

木のよく知られた事実が解決策を導き出します。どの木でも、節点の離心率は、その節点から木の直径のいずれかの端点までの最大距離に等しいということです。 したがって、各コンポーネントの直径の端点を維持すると、2 つの距離クエリのみを使用して x の離心率を計算できます。 

残りのタスクは、結合操作の下で動的フォレスト内の距離を維持することです。 エッジはコンポーネント間にのみ追加されるため、コンポーネントごとにルート表現を維持し、エッジの重みを含む親ポインターを保存できます。 2 つのコンポーネントをマージする場合、1 つのルートを他のコンポーネントのノードの下に接続し、距離オフセットを伝播します。 これにより、重み付きの DSU スタイルのパス圧縮を使用して、任意の 2 つのノード間の高速距離クエリがサポートされます。

 ## アルゴリズムのチュートリアル

 1. 各コンポーネントが選択されたルートを持つツリーであり、各ノードがその親とその親までの距離を格納する素セット構造を維持します。 パス圧縮を使用して親ポインターをたどる場合、累積距離によってコンポーネント ルートまでの距離が求められます。 この構造により、同じコンポーネント内のノード間の距離クエリをほぼ一定時間で実行できます。 
2. タイプ 1 エッジ (u、v) が追加された場合、両方のコンポーネントの根を見つけます。 最初のコンポーネントのノード u の下に 2 番目のルート Rb を接続すると仮定します。 parent[Rb] = u を設定し、2 番目のコンポーネント内の距離がアタッチ後に一貫性を保つようにエッジの重みを割り当てます。 これにより、2 つのツリーを接続する際に、既存の内部距離がすべて維持されます。 
3. 各コンポーネントについて、その直径の端点 (a、b) を維持します。 2 つのコンポーネントをマージする場合は、直径を再計算する必要があります。 新しい直径は、両方のコンポーネントの古い直径の最大値であり、一方のコンポーネントの端点ともう一方のコンポーネントの端点の間の距離です。 各コンポーネントは 2 つの候補のみを提供するため、DSU 距離関数を使用して 4 つの交差距離を評価します。 
4. 各ノード x について、その離心率は max(dist(x, a), dist(x, b)) として計算されます。ここで、a と b はそのコンポーネントの直径の端点です。 
5. クエリ (x, m, k) の場合、アリスが訪問できる個別の頂点の最大数を s = min(m + 1, ecc(x) + 1) として計算します。 
6. これを確率に変換します。 ボブは n 個の頂点から均等に k 個の頂点を選択します。 アリスは、k 個の頂点すべてが S の外側にある場合にのみ負けます。方法の数は C(n − s, k) であるため、勝つ確率は 1 − C(n − s, k) / C(n, k) となります。 階乗と逆剰余を使用して、この剰余 998244353 を計算します。 

### なぜ効果があるのか

 重要な不変条件は、各コンポーネントが常に、保存されている親ポインターと一致する、明確に定義された距離メトリックを持つツリーであるということです。 重み付けされた DSU により、パス圧縮操作で正確な距離が確実に保持されます。 直径の端点は現在のツリーに対して常に有効であり、ツリー内では x から最も遠いノードが直径の端点の 1 つである必要があるため、離心率クエリはこれらの端点までの距離を比較することになります。 アリスの最適戦略は常に x から始まる単一の単純なパスのサイズを最大化することに帰着し、ツリー内の任意の単純なパスは偏心によって制限されるため、計算された s はまさに最適です。 確率の式はセットのサイズのみに依存するため、s が正しければ、答えは正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

MAXN = 200000 + 5

fact = [1] * MAXN
invfact = [1] * MAXN

for i in range(1, MAXN):
    fact[i] = fact[i - 1] * i % MOD

invfact[MAXN - 1] = pow(fact[MAXN - 1], MOD - 2, MOD)
for i in range(MAXN - 2, -1, -1):
    invfact[i] = invfact[i + 1] * (i + 1) % MOD

def C(n, r):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

parent = list(range(MAXN))
dist = [0] * MAXN  # distance to parent

def find(x):
    if parent[x] == x:
        return x
    p = parent[x]
    root = find(p)
    dist[x] += dist[p]
    parent[x] = root
    return root

def get_dist(x, y):
    find(x)
    find(y)
    return dist[x] - dist[y]

diam_a = list(range(MAXN))
diam_b = list(range(MAXN))

def union(u, v):
    ru = find(u)
    rv = find(v)
    if ru == rv:
        return

    du_a = diam_a[ru]
    du_b = diam_b[ru]
    dv_a = diam_a[rv]
    dv_b = diam_b[rv]

    best_a = du_a
    best_b = du_b
    best_d = 0

    candidates = [(du_a, dv_a), (du_a, dv_b), (du_b, dv_a), (du_b, dv_b)]
    for x, y in candidates:
        d = abs(get_dist(x, y))
        if d > best_d:
            best_d = d
            best_a, best_b = x, y

    parent[rv] = ru
    dist[rv] = 1

    da = abs(get_dist(u, best_a))
    db = abs(get_dist(u, best_b))

    if da > db:
        diam_a[ru], diam_b[ru] = u, best_a
    else:
        diam_a[ru], diam_b[ru] = u, best_b

q = int(input())
n = 200000

last = 0

for _ in range(q):
    tmp = list(map(int, input().split()))
    t = tmp[0]

    if t == 1:
        u = tmp[1] ^ last
        v = tmp[2] ^ last
        union(u, v)

    else:
        x = tmp[1] ^ last
        m = tmp[2] ^ last
        k = tmp[3] ^ last

        rx = find(x)
        a = diam_a[rx]
        b = diam_b[rx]

        ecc = max(abs(get_dist(x, a)), abs(get_dist(x, b)))
        s = min(m + 1, ecc + 1)

        ans = (1 - C(n - s, k) * pow(C(n, k), MOD - 2, MOD)) % MOD
        if ans < 0:
            ans += MOD

        print(ans)
        last = ans
```DSU 構造には、各ツリーのルート表現が格納されます。 の`dist`配列はエッジの重みを蓄積するため、パス圧縮後も各ノードの代表までの距離が正しいままになります。 任意のノード間の距離クエリは一貫した累積に依存するため、これは非常に重要です。 

直径の維持では、新しい直径は既存の直径のエンドポイントを結合して得られる必要があるという事実を利用するため、コンポーネントを結合するときにテストする候補のペアは 4 つだけです。 

最後の確率計算では、事前に計算された階乗とモジュラー逆数を使用してモジュラー除算を慎重に処理します。 

## 実用的な例

 エッジがチェーン 1-2-3-4 を形成する小さなツリーを考え、m = 1 および k = 1 で x = 2 からクエリを実行します。 

| ステップ | × | ecc(x) | s | 確率 |
 | --- | --- | --- | --- | --- |
 | 距離を評価する | 2 | 2 | 2 | 計算された |
 | m による制限 | 2 | 2 | 2 | 1 - C(n-2,1)/C(n,1) |

 これは、離心率が 2 であっても、アリスの頂点は合計 2 に制限されているため、カバー範囲が小さいことを示しています。 

次に、1 を中心とし、葉が 2、3、4、5、x = 1、m = 1 である星を考えます。 

| ステップ | × | ecc(x) | s |
 | --- | --- | --- | --- |
 | センターノード | 1 | 1 | 2 |

 アリスは 1 つのリーフにしか移動できないため、多くのノードが存在しても、ウォーク サイズは厳密に m に制限されます。 

これらのトレースは、解がグラフ サイズではなくパス長に依存することを示しています。

 ## 特殊なケース

 クリティカルなエッジ ケースは、m がコンポーネント内のどのパスよりも大きい場合です。 行 1-2-3-4 では、非常に大きな m を使用して x = 2 をクエリすると、アリスは偏心制限領域全体を効果的にカバーできるようになり、解は m ではなく ecc(x) を使用してキャップする必要があります。 

もう 1 つのエッジ ケースは、直径の端点が変化する新たに接続されたノードです。 クロスペアによる再計算を行わずに古いエンドポイントを誤って再利用すると、両方のコンポーネントにまたがる長い直径を見逃してしまう可能性があります。 結合ステップでは、すべてのエンドポイントの組み合わせを明示的にチェックし、両方のコンポーネントが単一ノードまたは非常に不均衡なツリーである場合でも、正確さを保証します。
