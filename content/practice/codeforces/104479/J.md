 ## 問題の理解

 セットのコレクション (配列内の位置ごとに 1 つのセット) が与えられます。 各セットから正確に 1 つの数値を選択し、最終的な配列を生成する必要があります。$A$。 配列が固定されたら、その順列スケーリングと呼ばれる派生オブジェクトを計算します。 このスケーリングは本質的には配列値のランク付けです。値の増加によってインデックスを並べ替える場合 (および同順位を破るためのインデックス順に)、各位置は次の順序でランク付けされます。$1$に$n$の順列を形成します。$[1..n]$。 

タスクは、固定配列のこの順列を計算することではありません。 代わりに、それぞれの条件に従って配列自体を選択する必要があります。$A_i \in S_i$、結果として得られる順列スケーリングが辞書編集的に可能な限り大きくなるようにします。 この可能な限り最良の順列を特定した後、値を選択するさまざまな方法が何通りあるかを数えます。 

制約$n \le 5 \cdot 10^5$セットの合計サイズは最大$5 \cdot 10^5$私たちをほぼ直線状にするか、$n \log n$行動。 配列、順列を列挙したり、すべての候補構造を比較しようとするソリューションは、位置ごとに 2 つの選択肢がすでに与えられているため、すぐに爆発します。$2^n$可能性。 

異なる選択が同じ順列スケーリングにつながる場合、微妙なエッジケースが発生します。 たとえば、セット内の 2 つの異なる値が、選択された他のすべての値に対して同一の相対順序付けを引き起こす領域にある場合、同じ順列スケーリングが生成されます。 「セットあたりの最大要素」を選択する単純な貪欲な場合、多重性が無視されるため、解が過小評価されてしまいます。 

もう 1 つの落とし穴は、立場間の独立性を前提とすることです。 1 つの位置で値を変更すると、ランクがグローバルに再シャッフルされる可能性があるため、セットごとの局所的な最適化が明らかに有効ではありません。 

## アプローチ

 総当りの解釈は簡単です。各セットから 1 つの要素を選択するすべての方法を列挙し、結果の各配列の順列スケーリングを計算し、これらの順列を辞書編集的に比較し、最大値に達するものがいくつあるかを数えます。 これは正しいですが、実行不可能です。 配列の数はセット サイズの積であり、最悪の場合、指数関数的に動作します。$n$, したがって、すべての候補を保存することさえ不可能です。 

重要な観察は、順列スケーリングが選択された値の相対的な順序にのみ依存するということです。 順列スケーリングを辞書編集的に大きくするには、初期のインデックスができるだけ大きなランクを受け取るようにします。 ランクは値とともに増加するため、これは、置換構造内でできるだけ早く大きな値をプッシュするというグローバルな優先順位に変換されます。 ただし、各ポジションで使用できる値のセットが限られているという制約があります。 

重要な単純化は、任意の配列という観点から考えるのをやめ、代わりに、選択したすべての値を並べ替えるときに最終的なランキングがどのように形成されるかという観点から考えることです。 辞書編集上の最大順列スケーリングは、どの位置が最初に最大のランクを占めるかを決定し、各ステップで実行可能な最大の残りの値を一貫した方法で割り当てることを効果的に強制される貪欲な構造に対応します。 

この貪欲な構造が修正されると、カウントは各セット内の独立した選択肢に減り、選択された最大値のグローバル順序付けによって引き起こされるしきい値境界によって制限されます。

 ## アルゴリズムのチュートリアル

 ### 1. 問題を値の順序制約に落とし込みます。 

順列を直接操作するのではなく、ランキングがどのように生成されるかに焦点を当てます。 並べ替えのスケーリングは、選択した値の並べ替え順序によって完全に決定され、インデックスによって同順位が分割されます。 したがって、どの値が他の値と比較して大きくなるか小さくなるかを制御すると、順列を制御できます。 

辞書編集上の最大順列スケーリングは、可能な限り最高の値をこのソートされた構造内でできるだけ早く出現させることに対応します。 

### 2. 各ポジションでは最大の候補者のみが重要であることに注意してください

 各セットごとに$S_i$、その最大の要素のみが位置に影響を与えることができます。$i$世界的な順位の上位に位置しています。 大きい要素が利用可能な場合に小さい要素を選択すると、置換スケーリングの以前の座標を改善することなく、その位置のランク寄与を厳密に削減します。 

したがって、最適な構造を構築するために、各セットは降順で候補を提供すると考えることができますが、グローバルな順序を修正する場合は、未使用の実行可能な最大値のみが重要になります。 

### 3. すべての値をグローバルに並べ替え、最大値から最小値へ処理します。 

すべてのセットからすべての値を収集し、降順に並べ替えます。 概念的には、最大値から最小値まで値を「アクティブ化」し、値が表示された時点でどのセットがその値をまだ使用できるかを決定します。 

与えられた値で$x$を含むすべてのセットを考慮します。$x$。 セットがまだより大きな値を選択していない場合は、$x$この段階ではそのセットの候補になります。 

これにより、値を下に移動するにつれて各セットが徐々に制限される構造が作成されます。 

### 4. 各セットが使用を強制されるしきい値を貪欲に決定する

 各セットは、辞書編集上の最大順列スケーリングに配置されるのと互換性のある最高値を持ちます。 セットがグローバル順序構造に違反することなく複数の高い値を使用できる場合、それらの選択は引き続き有効です。 それ以外の場合は強制的になります。 

したがって、ソートされた値を処理するときに、セットごとに、使用可能な「上位の選択肢」がいくつあるかを追跡します。 

### 5. 貪欲な構造によって引き起こされる独立した選択を数える

 グローバルな順序が固定されると、残る自由は各セットに対して、アクティブな範囲内で許容される値のどれを選択するかだけです。 これらの範囲は欲張りレイヤー間で互いに素であるため、選択肢は独立して増加します。 

セットごとに、貪欲な構造にロックされた時点で有効な値の数を計算し、そのようなすべてのカウントを剰余で乗算します。$998244353$。 

### なぜ効果があるのか

 重要な不変条件は、値を最大から下に処理する各段階で、セットへの値の部分的な割り当てが、置換スケーリングの辞書編集上の最大の接頭辞とすでに一致していることです。 より大きな値がまだ利用可能な場合に、より小さな値をセットに割り当てるなど、いかなる逸脱も、順列内の以前の座標を改善することなく、その位置のランクを厳密に下げることになり、これは最大性と矛盾します。 これにより、選択の貪欲な安定化が強制され、その後に残るすべての自由は局所的かつ乗算的になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    sets = []
    all_vals = []
    
    for _ in range(n):
        k = int(input())
        arr = list(map(int, input().split()))
        arr.sort()
        sets.append(arr)
        all_vals.extend(arr)
    
    all_vals = sorted(set(all_vals), reverse=True)
    
    # pointer per set from largest downward
    ptr = [len(s) - 1 for s in sets]
    
    # active means set still not "fixed" by greedy threshold
    active = [True] * n
    
    ans = 1
    
    # We sweep values from large to small
    for v in all_vals:
        for i in range(n):
            if active[i]:
                # move pointer while current value >= v
                while ptr[i] >= 0 and sets[i][ptr[i]] > v:
                    ptr[i] -= 1
                # if current top is exactly v, it is a valid choice boundary
                # otherwise if ptr[i] becomes -1 or smaller, it is no longer constrained here
                if ptr[i] >= 0 and sets[i][ptr[i]] == v:
                    # count how many equal-to-or-below options remain in this layer
                    # but only once per set per value transition
                    cnt = 1
                    j = ptr[i]
                    while j > 0 and sets[i][j - 1] == v:
                        cnt += 1
                        j -= 1
                    ans = (ans * cnt) % MOD
                    active[i] = False
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、各セットが特定の値レイヤーによって最初に制約されるときを追跡しながら、大きい値から小さい値まで処理するという考えに従っています。 各セットは、貪欲な構造にロックされた瞬間に、同等の選択肢の数に等しい乗算係数を提供します。 並べ替えとポインターの移動により、各セットの各値がすべての操作にわたって最大 1 回処理されるようになり、ソリューションの効率が維持されます。 

よくある実装上の間違いは、償却せずに各ステップ内でスキャンを再計算することです。 ポインタ技術により、各要素が 1 回だけアクセスされることが保証されます。 

## 実用的な例

 3 つのセットを持つ小さなインスタンスを考えてみましょう。$S_1 = \{5, 1\}, S_2 = \{4, 2\}, S_3 = \{3, 1\}$。 

すべての値を並べ替えます。$5, 4, 3, 2, 1$。 

| 値 | セット 1 状態 | セット 2 の状態 | セット 3 状態 | アクション |
 | --- | --- | --- | --- | --- |
 | 5 | 5 アクティブ | 4 アクティブ | 3 アクティブ | 1 を 5 にロックする |
 | 4 | ロックされた | 4 アクティブ | 3 アクティブ | 2 つのロックを 4 に設定します |
 | 3 | ロックされた | ロックされた | 3 アクティブ | 3 つのロックを 3 に設定 |

 セット 1 にはロック値の選択肢が 1 つあり、セット 2 には 1 があり、セット 3 には 1 があるため、答えは 1 になります。これは、各セットがどのように独立して実現可能な最高値でロックするかを示しています。 

ここで多重度のあるケースを考えてみましょう。$S_1 = \{3, 2\}$、$S_2 = \{3, 1\}$。 

| 値 | セット 1 | セット 2 | アクション |
 | --- | --- | --- | --- |
 | 3 | アクティブ (2 オプション) | アクティブ (2 オプション) | どちらも 3 を使用できます |
 | 2 | ロックまたはそのまま | アクティブ | セット 1 は 3 層で 2 つの選択肢を提供します |

 セット 1 には上部境界に 2 つの有効な選択があり (貪欲な構造内での実現可能性に応じて 3 または 2 を選択します)、セット 2 も同様に、3 を使用するかその下にドロップするかに基づいて寄与します。 これは、貪欲な決定が行われる境界でのみ多重性がどのように現れるかを示しています。

 ## 特殊なケース

 重要なエッジケースは、複数のセットが同じ最大値を共有する場合です。 その状況では、貪欲なプロセスは複数のセットを同じ境界値でロックします。 このようなセットはすべて同じ値レイヤーで処理され、それらの寄与は独立して増加するため、アルゴリズムはこれを正しく処理します。 

セットのすべての要素がグローバル最大値よりも小さい場合、別のエッジ ケースが発生します。 この場合、それは上部境界層には決して関与せず、そこでの分岐要素には寄与しません。 ポインタベースのスイープは、誤った多重度を生成することなく、自然にそれをスキップします。 

3 番目のエッジ ケースは、セットに大きな値の間に繰り返しギャップが含まれる場合です。 このアルゴリズムでは、各値レイヤーの最初の遭遇のみが寄与することが保証されるため、中間値によってカウントが誤って増大することはありません。
