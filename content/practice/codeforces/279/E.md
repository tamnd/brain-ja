 ## 解決策
 ## 問題の理解

 美しい数とは、どちらかの符号を伴う 2 のべき乗のことです。 言い換えれば、すべての加数は次のいずれかでなければなりません。$$\pm 2^0,\ \pm 2^1,\ \pm 2^2,\dots$$正の整数が与えられます$n$、ただし 10 進数形式ではありません。 代わりに、そのバイナリ表現は、長さが 100 万文字に達する文字列として提供されます。 私たちは、合計が次の値に等しい美しい数値の最小数を見つけなければなりません。$n$。 

この問題を別の見方で見ると、次のようになります。$$n=\sum_i d_i 2^i$$ここで、各係数は$d_i$から選ばれます$\{-1,0,1\}$。 ゼロ以外のすべての係数は 1 つの美しい数値に寄与するため、目標は、次の位置の数を最小限に抑えることです。$d_i \neq 0$。 

最も顕著な制約は入力長です。 バイナリ文字列には次のものが含まれる場合があります$10^6$ビット、つまり次の値$n$それ自体が天文学的な大きさです。 整数に変換することは不可能です。 どのソリューションもバイナリ表現に対して直接機能する必要があります。 

二次アルゴリズムは直ちに除外されます。 平$O(|s| \log |s|)$入力自体にすでに 100 万文字が含まれている場合は不要です。 目標は、ビットごとに一定の追加作業のみを行う線形スキャンです。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

次の入力を考えてみましょう。```
1
```その番号はすでに$2^0$、したがって、答えは次のようになります。```
1
```すべての表現に少なくとも 1 つのキャリー伝播ステップが必要であると想定したソリューションでは、誤ってより大きな値が生成される可能性があります。 

考慮する：```
111
```それは$7$。 

単純なバイナリ表現では、次の 3 つのべき乗を使用します。$$7=2^2+2^1+2^0$$しかし、より良い分解は$$7=2^3-2^0$$2 つの加数のみを使用します。 設定されたビットを単純にカウントするアプローチでは、正解の 2 ではなく 3 が返されます。 

もう 1 つの微妙なケースは、長期にわたるものです。```
111111
```バイナリの重みは 6 ですが、$$63=64-1$$必要な加数は 2 つだけです。 最適解ではキャリーを意図的に作成できなければなりません。そうすることで非ゼロ係数の総数が減少することが多いからです。 

## アプローチ

 最も直接的なアイデアは、考えられるすべての係数の割り当てを検索することです。$-1$、$0$、 そして$1$2 のべき乗を計算し、どの組み合わせの合計が次になるかを確認します。$n$。 すべての有効な分解がそのような割り当てに対応するため、これは正しいです。 

残念ながら、$m$ビット、おおよそあります$3^m$可能性。 と$m$100万人までは、これは完全に不可能です。 

次の観察は、係数がどのように相互作用するかが 2 進演算によってすでにわかっているということです。 数値を最下位ビットから上に向かって処理するとします。 どの位置でも、下位ビットから重要な情報は、現在の位置にキャリーが入ったかどうかだけです。 

つまり、問題全体は 2 つの状態のみを持つ動的プログラムとして表現できます。$$\text{carry} = 0 \quad \text{or} \quad \text{carry} = 1$$ちょっと$b$、私たちは価値を知っています$$x = b + \text{carry}.$$数字を選択する必要があります$d \in \{-1,0,1\}$そして新しいキャリーなので、$$x = d + 2 \cdot \text{new\_carry}.$$毎回$d$がゼロ以外の場合は、1 つの美しい数値が使用されます。 

重要な洞察は、将来はキャリーのみに依存し、以前の選択には依存しないということです。 これにより、指数関数検索が、バイナリ文字列を 1 回スキャンされる 2 状態の DP に変わります。

 ## アルゴリズムのチュートリアル

 1. バイナリ文字列を反転して、ビットが最下位から最上位の順に処理されるようにします。 
2. 2 つの DP 値を維持します。$$dp[0]$$現在のサフィックスをキャリー 0 で処理した後の最小コストです。$$dp[1]$$現在のサフィックスをキャリー 1 で処理した後の最小コストです。 
3. 初期化します。$$dp[0]=0,\quad dp[1]=\infty$$なぜなら、ビットを処理する前にはキャリーが入ってこないからです。 
4. 各ビットについて$b$:

 1. 新しいアレイを作成する$ndp$。 
2. キャリー状態ごとに$c\in\{0,1\}$、計算する$$x=b+c.$$3. 有効な分解をすべて列挙します。$$x=d+2\cdot nc$$どこ$d\in\{-1,0,1\}$。 
4. コストを追加する$1$もし$d\neq0$、それ以外の場合は追加します$0$。 
5. 対応する状態を緩和する$ndp[nc]$。 
5. すべてのビットが処理された後も、最後のキャリーがまだ存在する可能性があります。 
6. 終了キャリーが 0 の場合、追加の桁は必要ありません。 
7. 終了キャリーが 1 の場合、もう 1 つの係数を表します。$+1$次の 2 のべき乗で、追加の加数が 1 つ追加されます。 
8. 有効な最終コストの最小値を計算します。 

### なぜ効果があるのか

 処理された位置ごとに、DP は、残りの上位ビットに指定された桁上げを残しながら、数値のすでに見た部分を正確に生成できる、ゼロ以外の符号付き桁の最小数を保存します。 

遷移では、現在のビット方程式を満たすためのあらゆる可能な方法が考慮されます。$$b+\text{carry}=d+2\cdot\text{new\_carry}.$$有効な符号付きバイナリ表現は除外されず、すべての表現はそのようなローカル選択の一意のシーケンスに対応します。 DP は常に各キャリー状態の最小コストを維持するため、最終的な答えは正確に美しい加数の最小数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    INF = 10**18
    dp0, dp1 = 0, INF

    for ch in reversed(s):
        b = ord(ch) - ord('0')

        ndp0 = INF
        ndp1 = INF

        # carry = 0
        if dp0 < INF:
            x = b

            if x == 0:
                ndp0 = min(ndp0, dp0)
            else:  # x == 1
                ndp0 = min(ndp0, dp0 + 1)  # d = 1
                ndp1 = min(ndp1, dp0 + 1)  # d = -1

        # carry = 1
        if dp1 < INF:
            x = b + 1

            if x == 1:
                ndp0 = min(ndp0, dp1 + 1)  # d = 1
                ndp1 = min(ndp1, dp1 + 1)  # d = -1
            else:  # x == 2
                ndp1 = min(ndp1, dp1)      # d = 0

        dp0, dp1 = ndp0, ndp1

    answer = min(dp0, dp1 + 1)
    print(answer)

if __name__ == "__main__":
    solve()
```実装は DP に正確に従います。 

ペア`(dp0, dp1)`キャリー状態ごとに最適なコストを保存します。 状態が 2 つしかないため、入力に 100 万ビットが含まれている場合でも、メモリ使用量は一定のままです。 

遷移ロジックは解決策から直接得られます。$$x=d+2\cdot nc.$$可能な値は 3 つだけです$x$: 0、1、および 2。それぞれには少数の有効な分解があるため、各ビットには一定の作業のみが必要です。 

最後の表現```
min(dp0, dp1 + 1)
```残ったキャリーを処理します。 1 のキャリーは追加の係数を意味します$+1$次の 2 のべき乗では、さらに 1 つの加数がかかります。
