 ## 解決策
 ## 問題の理解

 原点から目標点まで螺旋に沿って移動するときに馬が何回回転しなければならないかを数えるように求められます$(x, y)$。 螺旋は無限であり、パターンで外側に向かって成長する軸に沿ったセグメントで構成されています。右、次に上、左、そして下に移動し、完全に回転するたびに距離が増加します。 各セグメントはデカルト平面上の整数点を接続し、方向が変わるたびに回転が発生します。 

入力は 2 つの整数で構成されます。$|x|, |y| \le 100$、目的点を表します。 出力は、そのポイントに到達するまでに行われたターン数です。 

境界が小さい場合、スパイラルに沿った強引なシミュレーションが実現可能です。 ただし、エッジケースには細心の注意が必要です。 たとえば、ターゲットがオリジン自体の場合$(0, 0)$、動きは起こらないので、正解はゼロです。 もう 1 つの微妙な点は、馬が同じ方向に一歩を踏み出したときではなく、馬が方向を変えたときのみターンがカウントされることです。 目的地に到達したかどうかを確認せずに単にセグメントの遷移をカウントする単純な実装では、ターン数が過剰にカウントされる可能性があります。 

## アプローチ

 ブルートフォースアプローチはスパイラルを明示的にシミュレートします。 原点から開始して、現在の方向とセグメントの長さを追跡し、らせんに沿って段階的に移動します。 方向変更が発生するたびに、ターンカウンターがインクリメントされます。 この方法は正しいことが保証されていますが、スパイラルが到達する前にはるかに伸びる場合は非効率になる可能性があります。$(x, y)$。 ただし、$|x|$そして$|y|$が最大 100 の場合、スパイラルはどの方向にも 201 ステップを超えて成長する必要はありません。 それは大まかに与えます$O(n^2)$最悪の場合の操作ですが、制約を考慮すると許容範囲です。 

最適なアプローチはスパイラルの構造を活用します。 螺旋の各「層」は、前の層の周囲に正方形を形成します。 回転のパターンを観察すると、馬がセグメントの終わりに到達するたびに回転することがわかります。 絶対座標の最大値を取得することで、目的地が存在するレイヤーの数を計算できます。 完全なレイヤーごとに 4 ターンが追加されます。 ポイントがレイヤー内のセグメント上にある場合、そのセグメントに到達するまでのターンのみがカウントされます。 これにより、すべてのステップをシミュレーションすることなく問題が単純な式に削減されますが、制約を考慮すると、ステップバイステップのシミュレーションの方が単純で十分に高速です。

## アルゴリズムのチュートリアル

 1.現在位置を初期化します。$(0, 0)$、初期方向を「右」、初期セグメント長を 1 に設定します。また、ターン カウンタを 0 に初期化します。 方向シーケンスは右、上、左、下であり、周期的に繰り返されます。 
2. 現在位置が目的地に到着するまで繰り返します$(x, y)$:

 1. 現在の方向に沿って、現在のセグメントの長さだけ移動します。 
2. 目的地が現在のセグメント上にある場合は、目的地で移動を停止します。 この時点を超えて余分な回転を追加しないでください。 
3. セグメントが終了したら、ターン カウンターをインクリメントします。 
4. 右→上→左→下→右の順に方向を変え、循環させます。 
5. 2 回転ごとにセグメントの長さを 1 ずつ増やします。 これはスパイラルの成長ルールと一致します。右と上では同じ長さが使用され、左と下では長さが増加します。 
3. 現在位置が等しい場合$(x, y)$、ターンカウンターを返します。 

機能する理由: アルゴリズムは、完成した各セグメントが 1 回転に対応するという不変条件を維持し、セグメントの長さはスパイラル パターンに従って正しく増加します。 ターンをカウントする前に、目的地が現在のセグメント上にあるかどうかを確認するため、オーバーカウントすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

x, y = map(int, input().split())

if x == 0 and y == 0:
    print(0)
    exit()

# direction vectors: right, up, left, down
dx = [1, 0, -1, 0]
dy = [0, 1, 0, -1]

cur_x, cur_y = 0, 0
dir_idx = 0
length = 1
turns = 0

while True:
    nx, ny = cur_x + dx[dir_idx] * length, cur_y + dy[dir_idx] * length
    
    # Check if destination is on current segment
    if dx[dir_idx] != 0:  # horizontal move
        if min(cur_x, nx) <= x <= max(cur_x, nx) and cur_y == y:
            print(turns)
            break
    else:  # vertical move
        if min(cur_y, ny) <= y <= max(cur_y, ny) and cur_x == x:
            print(turns)
            break
    
    # Move to end of segment
    cur_x, cur_y = nx, ny
    turns += 1
    dir_idx = (dir_idx + 1) % 4
    if dir_idx % 2 == 0:
        length += 1
```このコードは、競技プログラミングのための高速 I/O を処理します。 方向は単純なリストにエンコードされ、垂直方向と水平方向のペアが完成した後でのみセグメントの長さを増分します。 セグメントの途中で目的地に到達したときのオフバイワンエラーを避けるために、目的地が現在のセグメント上にあるかどうかを注意深くチェックします。

 ## 特殊なケース

 起源`(0,0)`は特殊な場合です。 アルゴリズムは開始時にこれをチェックし、すぐにゼロを出力します。 最初のセグメントの目的地については、ターンを増やす前に、ターゲットが現在の座標と次の座標の間にあるかどうかを確認します。 これにより、1 つずれたエラーが防止され、馬がすでに目標に到達したときに「方向転換」することがなくなります。 最小値と最大値の比較で方向が考慮されるため、負の座標は自然に処理されます。
