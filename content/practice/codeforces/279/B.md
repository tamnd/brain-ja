 ## 解決策
 ## 問題の理解

 本が並んでいて、それぞれの本を読むのに必要な時間がわかっています。 ヴァレラはどの位置からでも始めて、右に連続して本を読むことができます。 彼は本をスキップすることができず、完全に読み終えるのに十分な時間が残っている場合にのみ本を読み始めます。 

このタスクは、合計読書時間が利用可能時間を超えない連続した本の最大数を見つけることです。`t`。 

入力により、すべての本の読書時間がわかります。 出力は単一の数値、つまり合計が最大で次の連続セグメントの最大長です。`t`。 

制約はソリューションを推進するものです。 到達できる本の数`100000`したがって、すべての可能なセグメントを明示的にチェックするアルゴリズムは遅すぎます。 おおよそあります`n² / 2`連続セグメントは約 50 億`n = 100000`。 プレフィックス合計を使用してセグメント合計を効率的に計算しても、依然として問題が残ります。`O(n²)`2 秒の制限に収まる範囲をはるかに超えています。 

線形または線形に近い解決策が必要です。 すべての読み取り時間は正であるため、問題はスライディング ウィンドウ アプローチを可能にする便利な単調構造を持っています。 

見逃しやすい特殊なケースとしては、1 冊の本でも利用可能な時間を超過した場合があります。 

入力：```
3 2
3 4 5
```出力：```
0
```有効なセグメントが存在しません。 少なくとも 1 冊の本が読めることを常に前提とする不注意な実装では、次のような結果が返されます。`1`。 

最適なセグメントが中央から始まる場合、別のエッジ ケースが発生します。 

入力：```
5 5
10 1 1 1 1
```出力：```
4
```1冊目からは無理ですが、2冊目からなら4冊読めます。 プレフィックスのみを考慮する貪欲なアプローチは失敗します。 

3 番目のケースは、ウィンドウを繰り返し縮小する必要がある場合です。 

入力：```
5 5
2 2 2 2 2
```出力：```
2
```長さ 3 の各セグメントの合計は 6 になります。 合計が大きくなりすぎるときに左側から書籍を正しく削除しない実装では、オーバーカウントが発生します。 

## アプローチ

 最も直接的な解決策は、すべての開始位置を試し、合計読み取り時間が超えるまで右に拡張することです。`t`。 開始する本ごとに、1 冊ずつ本を追加していきます。 

このアプローチは、考えられるすべての連続セグメントを明示的に評価するため、正しいです。 問題はその実行時間です。 最悪の場合、読み取り時間がすべて終わった場合など、`1`、各開始位置では、残りのほぼすべての本を調べることができます。 合計作業量は次のようになります。```
n + (n - 1) + (n - 2) + ... + 1 = O(n²)
```と`n = 100000`、これは大きすぎます。 

重要な観察は、すべての読書時間がプラスであるということです。 合計がすでに超過しているセグメントがあるとします。`t`。 さらに延長しても合計は増加するだけで、減少することはありません。 つまり、セグメントの左境界は前方にのみ移動し、後方には移動しません。 

この特性により、スライディング ウィンドウが可能になります。 窓口を整備しております`[left, right]`その合計は継続的に追跡されます。 移動してウィンドウを拡張します`right`。 合計が大きくなりすぎると移動します`left`合計が再び有効になるまで前進します。 

各インデックスはウィンドウに 1 回入り、1 回ウィンドウから出るため、合計作業量は線形です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適な引き違い窓 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`left = 0`、`current_sum = 0`、 そして`answer = 0`。 
2. 反復する`right`から`0`に`n - 1`。 
3. 現在の本の読書時間を`current_sum`。 
4. もし`current_sum`を超える`t`、繰り返し移動します`left`それらの本を転送してから差し引きます`current_sum`合計が最大になるまで`t`。 

このステップにより、現在のウィンドウが有効なセグメントであり、その合計読み取り時間が利用可能な時間内に収まるという不変条件が復元されます。 
5. 現在のウィンドウの長さは次のとおりです。`right - left + 1`。 
6.アップデート`answer`これまでに確認された最大のウィンドウ長です。 
7. すべての書籍を処理した後、印刷します`answer`。 

### なぜ効果があるのか

 あらゆる瞬間において、ウィンドウは 位置で終了する最長の有効なセグメントを表します。`right`その合計が超えないもの`t`。 合計が大きくなりすぎる場合、すべての読書時間は正であるため、左側から書籍を削除することがセグメントを再び有効にする唯一の方法です。 

以来`left`前方にのみ進むため、右のエンドポイントが処理されるときに、考えられるすべての最大有効ウィンドウが正確に考慮されます。 このアルゴリズムは候補セグメントを決して見逃さず、`answer`それらすべての中で最大の有効なウィンドウ長を記録します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, t = map(int, input().split())
    a = list(map(int, input().split()))

    left = 0
    current_sum = 0
    answer = 0

    for right in range(n):
        current_sum += a[right]

        while current_sum > t:
            current_sum -= a[left]
            left += 1

        answer = max(answer, right - left + 1)

    print(answer)

if __name__ == "__main__":
    solve()
```変数`current_sum`現在のウィンドウの合計読み取り時間を保存します。 右の境界が拡張されるたびに、新しいブックが合計に追加されます。 

の`while`ループは重要な部分です。 1 回の除去だけでは必ずしも十分とは限りません。 たとえば、ウィンドウ合計が`t`、セグメントが再度有効になる前に、数冊の書籍を削除する必要がある場合があります。 

ウィンドウの長さは、縮小プロセスの終了後に計算されます。 その時点で、セグメントは制限時間を満たすことが保証されます。 

Python の整数には制限がないため、たとえオーバーフローの心配はありません。`t`到達できる`10^9`ウィンドウサムが一時的に大きくなる場合があります。 

実装では内部で 0 から始まるインデックスが使用され、長さの式が維持されます。`right - left + 1`率直な。

import sys
import io

def solve():
    input = sys.stdin.readline

    n, t = map(int, input().split())
    a = list(map(int, input().split()))

    left = 0
    current_sum = 0
    answer = 0

    for right in range(n):
        current_sum += a[right]

        while current_sum > t:
            current_sum -= a[left]
            left += 1

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return result

# provided sample

# minimum size

# no readable book

# all equal values
assert run("5 5\n2 2 2 2 2\n") == "2", "uniform values"

# optimal segment in the middle
assert run("5 5\n10 1 1 1 1\n") == "4", "skip large prefix"

# boundary exact sum
assert run("4 10\n1 2 3 4\n") == "4", "sum equals limit"
