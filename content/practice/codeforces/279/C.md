 ## 解決策
 ## 問題の理解

 整数の 1 次元配列とクエリのリストが与えられ、それぞれが配列の連続したサブセグメントを指定します。 すべてのクエリについて、サブセグメントが「はしご」を形成しているかどうかを判断する必要があります。 ラダーとは、ある時点までは単調増加 (非減少) し、その時点以降は単調減少 (非増加) するシーケンスです。 これは、シーケンスが完全に非減少であるか、完全に非増加であるか、または非減少から非増加に移行する単一のピークを持つ可能性があることを意味します。 サブセグメントがラダーの場合、出力は「Yes」、それ以外の場合は「No」になります。 

この制約により、配列サイズとクエリ数の両方が 100,000 に達する可能性があることがわかります。 クエリごとに各サブセグメントを個別にスキャンする単純なアプローチでは、最悪の場合、最大 10^10 の要素を調べる必要があり、これは 2 秒で実行できる範囲をはるかに超えています。 これは、クエリに一定時間または対数時間で答えるために配列を前処理するアプローチが必要であることを意味します。 

エッジ ケースは、シーケンスが平坦、単一要素、または厳密に増加または減少している場合に発生します。 たとえば、配列`[5, 5, 5]`明らかに非減少でも非増加でもあるため、サブセグメントに対して「はい」を返す必要があります。 単一要素のサブセグメント`[7]`はしごでもあります。 不注意な実装により、厳密ではない比較ではなく厳密な増加または減少が想定される場合に問題が発生します。 

## アプローチ

 ブルート フォース アプローチでは、各クエリを反復処理し、対応するサブセグメントを直接チェックします。 各サブセグメントについて、左から右にスキャンして最長の非減少プレフィックスを見つけてから、最後からスキャンして最長の非増加サフィックスを見つけます。 これら 2 つの領域がサブセグメント全体をカバーする場合、それははしごです。 このアプローチは正しく機能しますが、最悪の場合、時間計算量は O(n * m) となり、指定された制約に対して遅すぎます。 

最適化するための重要な洞察は、配列を 1 回前処理して、インデックスごとに、非減少セグメントと非増加セグメントがどこまで広がっているかを知ることができることです。 具体的には、各位置について、減少せずに右に移動することで到達可能な最も遠いインデックスを計算できます (`up[i]`) および非増加中に右に移動することで到達可能な最も遠いインデックス (`down[i]`）。 それでは、ご質問に対して`[l, r]`、 もし`down[up[l]] >= r`、セグメントははしごを形成します。 これが機能する理由は、`up[l]`から始まる最初の非減少部分の終わりを見つけます。`l`、 そして`down[up[l]]`そこから非増加部分を延長します。 前処理は線形時間で実行され、各クエリは一定時間で応答されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m) | お(1) | 遅すぎる |
 | 最適 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`up`長さの`n`非減少シーケンスによって各位置から到達可能な最も遠いインデックスを格納します。 最後から 2 番目の要素から開始して左に移動し、更新します`up[i]`に`i+1`もし`a[i] <= a[i+1]`、 さもないと`up[i] = i`。 
2. 配列を初期化する`down`長さの`n`非増加シーケンスによって各位置から到達可能な最も遠いインデックスを格納します。 最後から 2 番目の要素から開始して左に移動し、更新します`down[i]`に`i+1`もし`a[i] >= a[i+1]`、 さもないと`down[i] = i`。 
3. クエリごとに`[l, r]`、どうかを確認してください`down[up[l-1]] >= r-1`。 Python の配列インデックスは 0 から始まるため、1 を減算します。 true の場合、「Yes」を出力します。 それ以外の場合は、「いいえ」を出力します。 これが機能する理由は、`up[l-1]`から始まる非減少セグメントの終点を与えます。`l-1`、 そして`down[up[l-1]]`そのピークから増加しない部分を延長します。 到達または通過した場合`r-1`、サブセグメントははしごです。 

なぜ機能するのか: 不変条件は次のとおりです。`up[i]`で始まる非減少シーケンスの最大範囲を正確に識別します。`i`、 そして`down[i]`非増加シーケンスに対しても同じことを行います。 これら 2 つの事前計算された配列を組み合わせることで、各要素を繰り返しスキャンすることなく、サブセグメントがラダーのプロパティを満たすかどうかを一定時間で検証できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = list(map(int, input().split()))

up = [0] * n
down = [0] * n

up[-1] = n - 1
for i in range(n - 2, -1, -1):
    if a[i] <= a[i + 1]:
        up[i] = up[i + 1]
    else:
        up[i] = i

down[-1] = n - 1
for i in range(n - 2, -1, -1):
    if a[i] >= a[i + 1]:
        down[i] = down[i + 1]
    else:
        down[i] = i

for _ in range(m):
    l, r = map(int, input().split())
    l -= 1
    r -= 1
    if down[up[l]] >= r:
        print("Yes")
    else:
        print("No")
```最初のループは次のように構成されます`up`右から左にスキャンすることで、各インデックスが到達可能な最も遠い非減少セグメントを認識できるようにします。 The second loop constructs`down`非増加シーケンスについても同様です。 クエリ処理では、これらの配列を直接使用して、クエリごとに一定時間でラダーの有効性を判断します。 0 から始まる Python 配列のインデックス調整はエラーの一般的な原因ですが、ここでは`l-1`そして`r-1`適切に処理してください。 

## 実用的な例

 ### サンプル 1

 入力:`1 2 1 3 3 5 2 1`、クエリ:`[1, 3]`| 私 | a[i] | アップ[i] | ダウン[i] |
 | --- | --- | --- | --- |
 | 0 | 1 | 1 | 2 |
 | 1 | 2 | 1 | 2 |
 | 2 | 1 | 2 | 2 |`up[0] = 1`2を指します。`down[1] = 2`2 >= 2 なので、答えは「はい」です。 

クエリ`[2, 4]`:`up[1] = 4`(5まで拡張)、`down[4] = 4`（3で止まります）。 4 < 3 は偽なので、答えは「いいえ」です。 これは、非ラダー セグメントが正しく検出されたことを示しています。 

### 単一要素セグメント

 入力:`[7]`、クエリ:`[1,1]`。`up[0] = 0`、`down[0] = 0`。 以来`down[up[0]] = 0 >= 0`の場合、出力は「はい」になります。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 配列の前処理`up`そして`down`O(n) を取ります。 各クエリは O(1) で回答されます。 |
 | スペース | O(n) | 配列`up`そして`down`要素ごとに 1 つの整数を格納します。 |
