 ## 解決策
 ## 問題の理解

 隠れたグリッドを通過した後に各列に何個のボールが入るかを記述する長さ C の単一の配列が与えられます。 最初は、上部の各列に 1 つのボールがドロップされるため、正確に C 個のボールが存在します。 各ボールは、グリッドを通る決定的なパスをたどります。そのセルには、ボールが下に移動するときにボールを 1 列左または右に押す直線タイルまたは斜めタイルが含まれます。 

ストレート セルはボールを真下に送り、バックスラッシュ タイルはボールを下と右に移動し、フォワード スラッシュ タイルはボールを下と左に移動します。 グリッドの両側には空の境界列があり、一番下の行にはランプがありません。 また、バックスラッシュ タイルがスラッシュ タイルのすぐ左側に表示されないようにする制約もあります。これにより、隣接する列が同じ行内で互換性のない方法で交差しようとすることがなくなります。 

最終的な観察は完全なパスの説明ではなく、単なるヒストグラムです。つまり、各列について、底に到達した後にその列で終了するボールの数です。 タスクは、この最終的な分布と一致するグリッドが存在するかどうかを判断し、存在する場合は可能な限り最小限の行数を使用してグリッドを構築することです。 

制約の合計 Bi = C は、すべてのボールがどこかで終了する必要があり、ボールが失われたり複製されたりしないことを意味します。 列の数は最大 100 であるため、O(C²) または O(C log C) の構築は簡単に十分高速ですが、グリッド上の指数関数的な構築はそうではありません。 

素朴なアプローチでは、グリッドを推測してすべてのボールの軌道をシミュレートしようとしますが、高さ H の単一のグリッドでも 3^{C・H} 通りの可能性があり、これはまったく実行不可能です。 固定グリッドのパスをシミュレートすることさえ簡単ですが、グリッド全体の検索は難しい部分です。 

微妙な失敗例は、グローバルな動きを調整せずに、ローカルで貪欲にボールを「プッシュ」しようとした場合に発生します。 たとえば、すべてのボールを列 1 から列 C に移動する必要がある場合、たとえ有効なグローバル配線が存在していても、局所的に貪欲に対角線を配置すると、すぐにパスがトラップされたり、矛盾する交差制約が作成されたりします。 

## アプローチ

 重要な変化は、グリッドをジオメトリとして考えるのをやめ、代わりに隣接するスワップの層状システムとして見ることです。 

グリッドの各行は、隣接する列に対する一連の素な操作として独立して動作します。 2 つの隣接するセルが「」の後に「/」が続くパターンを形成している場合、2 つのボールは 1 行下に移動しながら列を交換します。 他のすべての構成では、直線移動または相互作用しない対角線のいずれかになります。 「/」のすぐ左側にある「」を禁止する制約により、同じ行内のスワップは重複したり干渉したりすることができないため、各行は互いに素な隣接するスワップの正確な一致となります。 

これは、グリッド全体が、ボールの初期順序に適用される一連の並列スワップ レイヤーと同等であることを意味します。 各ボールは位置 i から始まり、ある位置 j で終了する必要があります。各列 j は、最終目的地間で正確に Bj 回出現します。 したがって、問題は次のようになります。各開始位置をターゲット位置に割り当て、隣接するスワップを使用して各アイテムをルーティングし、スワップ レイヤーの数を最小限に抑えます。 

本来の強引な方法は、カウントと一致するターゲットを任意に割り当ててから、貪欲にスワップをシミュレートすることですが、可能な割り当ての数は組み合わせによって異なります。 重要な構造は、ルーティングのコストは各アイテムがどれだけ移動するかによってのみ決まるということです。 各行は項目を最大 1 位置移動するため、行数は少なくとも開始位置とターゲット間の最大変位である必要があります。 

これにより、問題は、最大の |i − target(i)| が得られるように、初期インデックス 1..C とターゲット列のマルチセットの間のマッチングを選択することになります。 最小化されます。 これを行う最適な方法は、両方のシーケンスを並べ替えて直接ペアにすることです。これにより、絶対差の最大値が最小限に抑えられます。

最小変位 D がわかったら、D 層のスケジュールを構築できます。 各レイヤーは、左側のアイテムが依然として右に移動する必要があり、右側のアイテムが依然として左に移動する必要がある場合、隣接する位置間で現在可能なすべての競合しないスワップを実行します。 これは、すべての反転を層ごとに解決する並列バブル ソートのように動作し、D ステップで正確に完了に達します。

 ## アルゴリズムのチュートリアル

 各列を、開始インデックスから最終的なヒストグラムによって決定されるターゲット インデックスまで移動する必要があるトークンとして扱います。 

1. ターゲット分布を長さ C のリスト T に拡張します。ここで、各列 j は正確に Bj 回出現します。 これはすべてのボールの最終的な位置を表します。 
2. 列はすでに左から右の順序になっているため、ターゲット リストを構成によって暗黙的に並べ替えます。 
3. 各開始位置 i をターゲット T[i] に割り当てます。 このペアリングにより、順序どおりにマッチングするとペアの要素間の最大絶対偏差が最小化されるため、最大変位が最小化されます。 
4. 必要な行数 D を |i − T[i]| の最大値として計算します。 全体的に私は。 各行はボールを最大 1 列移動できるため、これは下限です。 
5. D ステップのグリッドを行ごとに構築します。 すべてのボールの現在の位置を維持します。 
6. 各行について、列を左から右にスキャンし、隣接する交換が必要かどうかを判断します。 左のボールがまだ右に移動する必要がある場合 (現在のインデックス < ターゲット インデックス)、右のボールがまだ左に移動する必要がある (現在のインデックス > ターゲット インデックス) 場合、位置 i と i+1 の間の交換が実行されます。 スワップが発生した場合、グリッドを i で ''、i+1 で '/' としてマークし、シミュレーションで 2 つのボールをスワップします。 
7. ある位置で交換できない場合は、両方のセルに「.」のマークを付けます。 
8. D 列の後、すべてのボールがターゲットになければならないため、シミュレーションは有効な構築で終了します。 

重要な不変条件は、各列の後、すべてのボールがラインに沿ってマンハッタンの距離でターゲットに一歩近づいたことです。 より正確には、ボールが位置 x にあり、そのターゲットが t である場合、各層の後の絶対距離 |x − t| は次のようになります。 は最大で 1 減少し、スワップ ルールにより、2 つの隣接するボールが反対方向にずれた場合は必ず、互いをブロックすることなく目的地に向かって同時に移動します。 これにより、D 層の後に変位が残らず、追加の行が必要ないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []
    
    for tc in range(1, T + 1):
        C = int(input())
        B = list(map(int, input().split()))
        
        targets = []
        for i, b in enumerate(B, start=1):
            targets.extend([i] * b)
        
        if len(targets) != C:
            out.append(f"Case #{tc}: IMPOSSIBLE")
            continue
        
        # optimal pairing: identity since targets already sorted by construction
        target = targets
        
        # compute displacement
        D = 0
        for i in range(C):
            D = max(D, abs((i + 1) - target[i]))
        
        # initial positions
        pos = list(range(1, C + 1))
        
        grid = []
        
        for _ in range(D):
            row = ['.'] * C
            i = 0
            while i < C - 1:
                if pos[i] < target[i] and pos[i + 1] > target[i + 1]:
                    # swap
                    row[i] = '\\'
                    row[i + 1] = '/'
                    pos[i], pos[i + 1] = pos[i + 1], pos[i]
                    i += 2
                else:
                    i += 1
            grid.append(''.join(row))
        
        # validate (optional safety)
        if pos != target:
            out.append(f"Case #{tc}: IMPOSSIBLE")
            continue
        
        out.append(f"Case #{tc}: {D}")
        grid = ['.' * C] * (1 if D == 0 else D) if D == 0 else grid
        for r in grid:
            out.append(r)
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードはまず、ヒストグラムを明示的なターゲット宛先に変換します。 次に、各ボールに順番に目的地を割り当て、交差の不一致を回避します。 

シミュレーションでは、行ごとに左から右への貪欲なスキャンが使用されます。 必要な動きに関して 2 つの隣接するボールが「向かい合っている」場合は常に、その列内でボールが交換されます。 スワップ後に 2 つスキップすることを選択すると、スワップが重複しないことが保証されます。これは、スワップが素のセルのペアを使用するという制約を尊重するために不可欠です。 

グリッドは行ごとに構築され、各行は必要なシンボルに直接変換されます。

D は最大 (|1-2|, |2-2|, |3-3|) = 1 です。

これにより、最大ディスプレイスメントが 1 の場合、単一のスワップ レイヤーがすべての反転を 1 つのステップで解決できることが確認されます。 

### 例 2

 入力:

 C = 6、B = [3、0、0、2、0、1]

 ターゲットは [1,1,1,4,4,6] に拡張されます。 

初期位置は [1..6] です。 

最大変位は 3 なので、D = 3 となります。 

| ステップ | 鍵の交換 | 状態の概要 |

これは、層の数が必要な最大移動距離と一致していることを示しています。

 ## 特殊なケース

 特殊なケースとしては、すべてのボールが 1 つの列で終了する必要がある場合があります。 この状況では、ターゲット リストは一定になり、最大変位は大きくなります。 このアルゴリズムは、隣接する要素を中心に向かって繰り返し交換することにより、すべてのボールを内側にルーティングします。 各行は、すべての要素が収束し、行数が任意の開始位置からターゲット列までの最大距離に等しくなるまで、有効な素スワップを実行し続けます。 

分布がすでに一様である場合、つまりすべての i について Bi = 1 である場合、別のエッジ ケースが発生します。 ターゲットの割り当ては恒等式と一致するため、変位はゼロになります。 アルゴリズムは正しくゼロ行を出力し、グリッドにはスワップ構造が含まれていないため、移動が必要ないという要件が満たされます。 

最後の微妙なケースは、中央の 1 列に複数のボールが送られるなど、交互に激しい集中が行われる場合です。 多くのボールが収束しても、各行は互いに素な隣接する交換のみを実行するため、スワップが競合することはありません。 どのポジションも行ごとに複数のスワップに参加しないという不変条件により、最大の輻輳下でも正確さが保証されます。
