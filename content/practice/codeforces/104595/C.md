 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$N \times N$各セルに整数が含まれるグリッド。 絶対値は「色」を表し、符号は「材質」を表します。 したがって、すべてのセルは、結合された単一のラベル、つまり符号付き整数をエンコードします。 

まったく同じ符号付き値を保持する 2 つのセルが同じ行または同じ列に存在する場合、構成は無効とみなされます。 目標は、変更後に同じ符号付き値が複数回含まれる行または列が存在しないように、変更するセルをできるだけ少なくすることです。 

変更によりセルを他の有効な符号付き値に変えることができ、色と材質の両方を変更しても 1 回の操作としてカウントされます。 タスクは、変更する必要があるセルの最小数を計算することです。 

重要な制約は、$N \le 100$したがって、グリッドには最大でも$10^4$テスト ケースごとのセル。 これは、二次関数に近いアプローチはすべて、$N^2$あるいは、セルあたり数千回の操作でも問題ありませんが、セル数が指数関数的に増加するものは問題です。 

多くの同一の値が同じ行と列に密集している場合、微妙なエッジ ケースが発生します。 たとえば、値のすべての出現が 1 行にある場合、1 つのみを変更せずに残すことができ、他の値はすべて変更する必要があります。 もう 1 つのエッジ ケースは、オカレンスが分散しているにもかかわらず、構造化された方法で共有された行と列を通じて競合する場合です。これでは、貪欲な「行ごとに 1 つを維持する」は正しくありません。 

重要な問題は、競合が行ごとまたは列ごとに独立してローカルに発生するのではなく、値ごとに同時に行と列の制約のペアに依存することです。 

## アプローチ

 単純な考えは、行と列の繰り返しを避けながら、各値を独立して処理し、出現を貪欲に保持することです。 値の出現をすべてスキャンし、行と列がまだ使用されていないものを選択してみるかもしれません。 これは順序に依存させることができますが、順序が異なると異なる結果が生じる可能性があり、最適性を保証するものはありません。 根本的な問題は、オカレンスを選択するとその行と列の両方がブロックされ、今後の選択が不必要に制限される可能性があることです。 

固定値について考える正しい方法は、固定値を完全に分離することです。 値を修正する$x$を含むすべてのセルを考慮します。$x$。 行や列を共有する 2 つが存在しないように、それらをできるだけ多く保持したいと考えています。 これはまさに 2 部のマッチング問題です。一方は行、もう一方は列、そしてそれぞれの出現は$x$行と列の間のエッジです。 共有エンドポイントのないエッジの最大セットが必要です。 

この最大一致を各値に対して個別に計算すると、保持されているすべてのセルは安全になり、その他のセルはすべて変更する必要があります。 これらを合計すると答えが得られます。 

重要な構造的洞察は、値が互いに相互作用しないということです。 競合は同一の値内でのみ発生するため、問題は独立したマッチングの問題にきれいに分解されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 値ごとの貪欲な選択 |$O(N^2)$しかし間違っています |$O(N)$| 間違った答え |
 | 値ごとの 2 部マッチング |$O(\sum E_v \cdot N)$|$O(N^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. すべてのグリッド位置を符号付きの値でグループ化します。 それぞれの値について$x$、すべてのペアを集めます$(i, j)$それが現れる場所。 これにより、すべての競合が値ごとに 1 つの構造に分離されます。 
2. 各値について$x$、左側が行を表し、右側が列を表す 2 部グラフを作成します。 あらゆる出来事に対して$(i, j)$、行からエッジを追加します$i$列へ$j$。 これにより、問題は競合しないものを選択することに変わります。 
3. このグラフの最大 2 部マッチングを計算します。 一致した 2 つのエッジが行または列を共有しないため、一致した各エッジは変更せずに保持できるセルを表します。 
4. しましょう$k_x$value の出現数になります$x$、そしてさせてください$m_x$の最大一致サイズになります$x$。 この値によって寄与される必要な変更の数は次のとおりです。$k_x - m_x$。 
5. グリッド内のすべての値に対してこの数量を合計し、結果を出力します。 

照合ステップは唯一重要な部分です。 各値には最大サイズの行と列のみが含まれるため、$N$の場合、標準の DFS ベースの拡張パス アルゴリズムで十分です。 

### なぜ効果があるのか

 固定値の場合、有効な構成は、行または列が複数回使用されないようにオカレンスを選択することに正確に対応します。 これはまさに 2 部グラフでのマッチングの定義です。 したがって、最大一致では、その値に対して変更されていないセルの可能な最大のセットが保存されます。 異なる値が互いに干渉することはないため、それらを個別に最適化しても、値間の競合は発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_bipartite_matching(edges, n):
    match_to = [-1] * n
    g = [[] for _ in range(n)]
    for u, v in edges:
        g[u].append(v)

    def dfs(u, seen):
        for v in g[u]:
            if seen[v]:
                continue
            seen[v] = True
            if match_to[v] == -1 or dfs(match_to[v], seen):
                match_to[v] = u
                return True
        return False

    match_size = 0
    for u in range(n):
        seen = [False] * n
        if dfs(u, seen):
            match_size += 1
    return match_size

def solve():
    t = int(input())
    for tc in range(1, t + 1):
        n = int(input())
        pos = {}

        for i in range(n):
            row = list(map(int, input().split()))
            for j, x in enumerate(row):
                pos.setdefault(x, []).append((i, j))

        answer = 0

        for x, cells in pos.items():
            k = len(cells)

            rows = sorted(set(i for i, _ in cells))
            cols = sorted(set(j for _, j in cells))

            r_id = {r: idx for idx, r in enumerate(rows)}
            c_id = {c: idx for idx, c in enumerate(cols)}

            edges = []
            for i, j in cells:
                edges.append((r_id[i], c_id[j]))

            match_size = max_bipartite_matching(edges, len(cols))
            answer += k - match_size

        print(f"Case #{tc}: {answer}")

if __name__ == "__main__":
    solve()
```この解決策は、すべてのポジションを符号付きの値でグループ化することから始まります。 次に、相対的な構造のみが重要となるため、各グループは圧縮された行インデックスと圧縮された列インデックスの間の 2 部グラフに変換されます。 マッチング ルーチンは、古典的な DFS ベースの拡張パス手法を使用します。これは、値ごとのノードの総数が次の制限を受けるため、これで十分です。$N$、すべての値にわたるエッジの合計数は最大で$N^2$。 

よくある実装の落とし穴は、行インデックスと列インデックスを値ごとに圧縮するのを忘れることです。 圧縮しないと、配列が不必要に大きくなり、マッチングが遅くなります。 もう 1 つの微妙な問題は、DFS 呼び出し間で訪問済みの配列を誤って再利用することです。これにより、拡張パス検索の正確性が損なわれてしまいます。 

## 実用的な例

 小さなグリッドを考えてみましょう。 

入力:```
2
1 1
2 1
```発生したものをグループ化します。 

値 1 は (0,0)、(0,1)、(1,1) に表示されます。 値 2 は (1,0) に表示されます。 

値 1 の場合、エッジを構築します。 

行 {0,1}、列 {0,1}、エッジは (0,0)、(0,1)、(1,1) です。 最大一致サイズは 2 です (たとえば、(0,0) と (1,1))。 したがって、2 を維持し、1 を変更します。 

値 2 の場合、出現は 1 つだけ存在するため、一致するサイズは 1 で、変更は 0 です。 

| 値 | 出来事 | 適合するサイズ | 変更点 |
 | --- | --- | --- | --- |
 | 1 | 3 | 2 | 1 |
 | 2 | 1 | 1 | 0 |

 合計の答えは 1 です。 

これは、競合が値ごとに独立して解決される方法と、構造的な行と列の競合のみが問題となる理由を示しています。 

次に、密集衝突の場合を考えてみましょう。```
2
1 1
1 1
```4 つのセルはすべて値 1 です。二部グラフは 2 行と 2 列の間で完成しているため、最大一致は 2 です。2 つのセルを保持し、2 を変更します。どの解でも行と列全体で対称性を破る必要があり、一致により最適なペアが捕捉されます。

 ## 特殊なケース

 完全に均一なグリッドは、アルゴリズムが重複を過剰にカウントするのではなく、マッチングの問題に正しく帰着するかどうかをテストします。 同じ値で埋められた 2x2 グリッドでは、4 つのセルすべてが 1 つの 2 部グラフ内で競合します。 マッチングでは 2 つの独立した行と列のペアが正確に検出され、2 つの変更が残ります。 貪欲なアプローチでは、多くの場合、両方の制約を同時に調整せずに、行または列ごとに 1 つだけを誤って想定し、次善の結果が得られます。 

2 番目のエッジ ケースは、値の出現が完全な対角パターンを形成する場合です。 この場合、行または列を共有する 2 つのセルはないため、一致するサイズは完全な頻度と等しくなり、変更はゼロになります。 これにより、入力がすでに有効である場合、アルゴリズムが不必要な変更を導入しないことが確認されます。
