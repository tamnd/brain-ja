 ## 問題の理解

 グリッドには、`H`行と`W`列。 時間と柱は一緒に進んでいくので、時間になると`t`ターディスは列にあります`t`。 垂直座標は最大で変化する可能性があります`K`連続する列間で、垂直方向に行から循環的に折り返す`H`漕ぐ`1`そして列から`1`漕ぐ`H`。 

各サイバーマンは同時に固定の列と行から開始します`1`。 サイバーマンは決して列を変更しません。 代わりに、後続のタイム ステップごとに、対応する文字によって決定され、すべて同じ方向に 1 行移動します。`S`。 したがって、サイバーマンが列でスタートした場合、`r`列で`c`、その後、TARDIS がコラムに達したとき`c`、サイバーマンは接頭辞によってシフトされています。`S`最初に対応する`c - 1`動く。 複数のサイバーマンが同じセルを占有することができますが、TARDIS にとって重要なのはセルがブロックされているという事実だけです。 公式声明とコンテスト資料はこの解釈を使用し、3 つのサンプルと出力を提供しています。`4`、`72`、 そして`600000`。 

入力により得られるのは、`H`、`W`、`K`、 そして`N`、続いて`N`サイバーマンの初期位置とその後の長さの文字列`W - 1`。 出力は、列の空いているセルで始まる TARDIS 座標の個別のシーケンスの数です。`1`、タイム ステップごとに 1 つの移動を実行し、占有されているセルには決して入らず、列のどこかで終了します。`W`。 答えはモジュロで計算されます`10^9 + 7`。 

寸法`H`そして`W`せいぜい`1000`したがって、グリッド セルごとにおよそ 1 つの操作を含むソリューションになります。`O(HW)`、簡単に実践できます。 の値`K`せいぜい`10`、これはまた、`O(HWK)`動的プログラムは原理的には実現可能ですが、さらにクリーンなプログラムもあります。`O(HW)`スライディング ウィンドウを使用した移行。 あり得る`5000`サイバーマンなので、すべてのサイバーマンを調べてすべての列を再構築することは、繰り返し実行すると無駄になります。 各サイバーマンは、その列の垂直方向のシフトがわかった後で 1 回だけ処理する必要があります。 

最初のエッジ ケースは、占有された開始セルです。 例えば、```

1 1
1 2
U
```最初の列の両方のセルがブロックされているため、正しい答えは次のとおりです。`0`。 すべての最初の列の状態を初期化する不用意な実装`1`サイバーマン内から始まるパスをカウントします。 

2 番目のエッジ ケースは垂直ラッピングです。 考慮する```
5 2 1 1
2 5
U
```列で`2`、サイバーマンは列から移動します`5`漕ぐ`1`。 他の 4 つのセルは使用可能です。 列内のすべての行から`1`の場合、TARDIS は周期的に 3 つの連続する行に到達できるため、許可された 4 つの宛先のそれぞれに 3 つの可能な先行者があります。 答えは、`12`。 行を通常の間隔として扱う実装では、行の前後の遷移が誤って処理される可能性があります。`1`そして`5`。 

3 番目のエッジ ケースは、サイバーマンの移動が時間に依存し、サイバーマンが移動した列の数には依存しないということです。 例えば、```

```列で`1`、 行`1`ブロックされ、最初の列に DP が与えられます`[0,1,1,1,1]`。 列で`2`、両方のサイバーマンは一度昇格しているため、サイバーマンは最初は`(2,1)`行を占有します`2`。 したがって、2 番目の列には DP が含まれます。`[2,0,3,3,3]`、合計で`11`。 カラム`3`にはサイバーマンがいないため、合計は次のようになります`33`。 動作プレフィックスを忘れたり、命令を 1 タイム ステップ早く適用した実装では、異なる結果が得られます。 

## アプローチ

 最も直接的な解決策は、問題をパスをカウントする動的プログラムとして扱うことです。 させて`dp[r]`行に到達する方法の数になります`r`現在の列にあります。 宛先行の場合`r`、からの巡回距離がある前のすべての行`r`せいぜい`K`新たな価値の創造に貢献します。 これらの合計を計算した後、ブロックされたセルはゼロに設定されます。 

ブルートフォース実装では、考えられるすべての TARDIS パスを再帰的に列挙することで、動的プログラミングを完全に回避できます。 これは正しいです。すべての正当なパスは 1 回だけ生成され、すべての違法なパスは占有セルに到達するとすぐに拒否されるためです。 問題はパスの数です。 最悪の場合、障害物がない場合でも、`H = 1000`そして`K = 10`、すべての行には`21`個別の到達可能な行。 最初の列には、`1000`選択肢、その後に続く`21`残りのそれぞれの選択肢`999`列、与える`1000 * 21^999`可能なパス。 それはおおよそです`10^1321`, したがって、列挙は完全に不可能です。 

最初の有益な観察は、完全なパスを記憶する必要がないということです。 TARDIS が特定のセルに到達すると、それまでのすべての選択は、そのセルに到達したパスの数によってのみ重要になります。 これにより、標準の列ごとの DP が得られます。 

2 番目の観測では、移動する障害物を扱います。 すべてのサイバーマンは同じ信号に従って移動するため、その後の垂直変位は`c - 1`動きは接頭辞からわかります`S`。 すべての列の変位を事前に計算できます。 当初はサイバーマンだった`(c, r)`次に、列内の 1 行だけをブロックします`c`、つまり、適切にシフトされたバージョン`r`。 DP を実行する前に、これらのセルを 1 回マークできます。 

残りの移行は最初は`O(HK)`各宛先は最大でも検査するため、列ごとに`2K + 1`前の行。 これらの制約の下では、それはすでに受け入れられるでしょう。`H,W <= 1000`そして`K <= 10`, しかし、トランジションにはさらに多くの構造があります。 連続する宛先行の場合、その先行間隔は両側で 1 行だけ異なります。 現在の周期間隔の合計を維持し、一定時間で更新できます。 これにより、DP 遷移が減少します。`O(H)`列ごとに。 

いつ`2K + 1 >= H`、すべての行は、循環グリッド上の他のすべての行に到達できます。 その場合、すべての宛先は同じ合計パス数、つまり前の DP 配列の合計を受け取ります。 このケースを個別に処理すると、スライディング ウィンドウを作成するときに同じ循環行を複数回カウントすることが回避されます。 

公式コンテストの社説では、同じ基礎となる列 DP について説明しており、距離内のすべての前の行を合計する遷移が含まれています。`K`。

 ## アルゴリズムのチュートリアル

 1. すべてのサイバーマンの位置と動きの文字列を読み取ります。 すべての列のプレフィックス ディスプレイスメントを構築します。 させて`shift[c]`時間におけるサイバーマンの垂直変位になります`c`最初の行を基準にして。 したがって`shift[0] = 0`、以降の各値は次のように変化します。`+1`のために`U`または`-1`のために`D`。 行に対するモジュロ演算により、循環ラッピングが行われます。 
2. ブロックセル配列を作成します。`W`列。 最初に列にいたすべてのサイバーマンに対して`c`そして漕ぐ`r`、適用して得られた行にマークを付けます。`shift[c - 1]`に`r`。 サイバーマンは列に残る`c`, したがって、その列にのみ寄与します。 これが障害物の動きと TARDIS の動きの重要な違いです。 
3. 列の DP を初期化します。`1`。 ブロックされていないすべての行には開始セルになる方法が 1 つだけありますが、ブロックされたすべての行には 0 通りの方法があります。 この時点で`prev[r]`行で終わるすべての有効なパスを表します`r`現在の列にあります。 
4. 列を処理します。`2`を通して`W`。 各列について、次の合計を計算します。`prev[r']`すべての行にわたって`r'`宛先行からの循環距離`r`せいぜい`K`。 宛先がブロックされている場合、その DP 値は、先行する合計に関係なく 0 になります。 
5. もし`2K + 1 >= H`、すべてのソース行はすべての宛先行に到達できます。 コンピューティング`total = sum(prev)`一度、この値をブロックされていないすべての宛先に割り当てます。 これにより、同じ循環行を複数回含むウィンドウの構築が回避されます。 
6. それ以外の場合は、周期的なスライディング ウィンドウを正確に維持します。`2K + 1`個別のソース行。 概念的なシーケンスを構築する`prev[H-K], ..., prev[H-1], prev[0], ..., prev[H-1], prev[0], ..., prev[K-1]`。 

最初のウィンドウは宛先行に対応します`0`。 次の宛先行に移動するときは、ウィンドウから出るソース行を減算し、ウィンドウに入るソース行を追加します。 したがって、すべての目的地の合計には一定の時間がかかります。 
7. 交換`prev`新しく計算された DP 配列を使用して次の列に進みます。 列の後`W`処理されました。すべてのエントリを合計します。`prev`。 生き残ったすべてのエントリは、その行で終了するパスを表し、考えられるすべての最終行が受け入れられます。 

### なぜ効果があるのか

 不変条件は、列を処理した後のものです。`c`、`prev[r]`現在の位置が次である正当な TARDIS パスの数と正確に等しくなります。`(c,r)`。 すべての空き開始セルは 1 つのパスに寄与し、すべてのブロックされたセルは何も寄与しないため、初期化はこれを満たします。 への移行に向けて`(c,r)`、すべての正当なパスは、循環距離内のちょうど 1 つの行から来ている必要があります。`K`したがって、対応する以前の DP 値を合計すると、すべての法的延長が 1 回だけカウントされます。 ブロックされた宛先はゼロに寄与し、サイバーマンに侵入する可能性のあるパスを正確に削除します。 スライディング ウィンドウは、連続するウィンドウ間の重複を再利用することによってのみ、直接反復と同じ先行合計を計算します。 したがって、不変条件はすべての列に対して true のままであり、最終的な DP 配列を合計すると、必要なパスの数が正確に得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    H, W, K, N = map(int, input().split())

    cybermen = [tuple(map(int, input().split())) for _ in range(N)]
    S = input().strip()

    # shift[c] is the vertical displacement at column c + 1,
    # using 0-based column indices.
    shift = [0] * W
    for c in range(1, W):
        shift[c] = shift[c - 1] + (1 if S[c - 1] == 'U' else -1)

    # blocked[c][r] == 1 means row r (0-based) is occupied
    # in column c (0-based).
    blocked = [bytearray(H) for _ in range(W)]

    for c, r in cybermen:
        row = (r - 1 + shift[c - 1]) % H
        blocked[c - 1][row] = 1

    # DP for the first column.
    prev = [0 if blocked[0][r] else 1 for r in range(H)]

    # If one move can reach every row, every destination gets
    # the same predecessor sum.
    all_rows_reachable = 2 * K + 1 >= H

    for c in range(1, W):
        if all_rows_reachable:
            total = sum(prev) % MOD
            cur = [
                0 if blocked[c][r] else total
                for r in range(H)
            ]
        else:
            # Cyclic sliding window.
            ext = prev[-K:] + prev + prev[:K]
            width = 2 * K + 1

            window = sum(ext[:width]) % MOD
            cur = [0] * H

            for r in range(H):
                if not blocked[c][r]:
                    cur[r] = window

                if r + 1 < H:
                    window += ext[r + width]
                    window -= ext[r]
                    window %= MOD

        prev = cur

    print(sum(prev) % MOD)

if __name__ == "__main__":
    solve()
```の`shift`アレイはサイバーマンの累積的な動きを記録します。 コラム用`c`、ターディスは時間通りにそこに到着します`c`、まさにそのとおりです`c - 1`信号文字はすべてのサイバーマンに影響を与えました。 表現`(r - 1 + shift[c - 1]) % H`元の 1 から始まる行を 0 から始まる巡回行に変換します。 

の`blocked`配列は 1 つを使用します`bytearray`列ごとに。 これはコンパクトであり、目的地が一定時間内に占有されているかどうかをテストできます。 複数のサイバーマンが同じセルに入った場合、割り当て`1`再び効果はありませんが、これはまさに私たちが必要としているものです。 

最初の DP 配列には、`0`そして`1`, 最初の列に入る前に動きがないためです。 2 番目の列以降、遷移は前の DP 配列にのみ依存するため、2 つの完全な DP 層を保存する必要はありません。 

の`all_rows_reachable`ブランチは、次の小さな値を処理します。`H`。 たとえば、次のようなとき`H = 5`そして`K = 3`、任意の 2 行間の循環距離は最大で`2`したがって、すべての行が他の行に到達します。 長さのある素朴な円形の窓`7`一部の行は 2 回カウントされます。 合計を使用すると、その問題が直接回避されます。 

通常の場合、`ext`～の先頭と末尾の十分なコピーが含まれています`prev`すべての循環先行間隔を通常の連続スライスに変換します。 最初のウィンドウは宛先行に対応します`0`。 その行を処理した後、1 つの古い値がウィンドウから出て、1 つの新しい値がウィンドウに入ります。 これらの更新の順序は次のように選択されます。`cur[r]`目的地にウィンドウを正確に使用します`r`、目的地ではありません`r + 1`。 

すべての算術は剰余を縮約されます`10^9 + 7`。 Python の整数はオーバーフローしませんが、ローリング合計を制限することで不必要な増加を防ぎ、実装の効率を維持します。

 ## 特殊なケース

 最初の列全体がブロックされると、初期 DP ベクトルはすべて 0 になります。 のために```
2 2 1 2
1 1
1 2
U
```両方の行は初期化前にマークされるため、`prev = [0, 0]`。 その後のすべての遷移でもゼロが生成され、答えは次のようになります。`0`。 初期の DP 定義がすでにこの状況をキャプチャしているため、アルゴリズムはこの状況に対して特別なケースを必要としません。 

垂直方向のラッピングについては、次のことを考慮してください。```
5 2 1 1
2 5
U
```コラムのサイバーマン`2`、 行`5`上に移動して列を作ります`1`、それでコラム`2`ブロック行`1`。 カラム`1`DPあり`[1,1,1,1,1]`。 利用可能な宛先は行です`2`、`3`、`4`、 そして`5`。 それぞれの前身ウィンドウは、`{1,2,3}`、`{2,3,4}`、`{3,4,5}`、 そして`{4,5,1}`、それぞれに 3 つのパスが含まれています。 最終的なベクトルは`[0,3,3,3,3]`、与える`12`。 

動く障害物については、次のことを考慮してください。```
5 3 1 2
1 1
2 1
UU
```最初の列は行をブロックします`1`したがって、初期DPは次のよ​​うになります。`[0,1,1,1,1]`。 2番目のサイバーマンは列から始まります`2`、 行`1`、しかし時間とともに`2`上に移動して漕ぎました`2`。 したがって、2 番目の列には行が含まれます。`2`ブロックされました。 循環先行の合計は次のようになります。`[2,0,3,3,3]`、その合計は`11`。 カラム`3`には障害物がなく、各宛先は 3 つの先行行を受け取り、合計で`33`。 これは、信号プレフィックスがサイバーマンの開始列履歴に従ってではなく、TARDIS の時間に従って適用されていることを確認します。 

最後に、複数のサイバーマンが同じセルを占有している場合でも、ブロックされるのは 1 つのセルだけです。 で```
5 3 1 5
2 1
2 1
2 1
2 1
2 1
UU
```サイバーマン5人全員が列に並ぶ`2`列内`2`。 ブロックされた配列はそのセルを 1 回記録します。 カラム`1`5 つの開始行すべてが利用可能であるため、列`2`それぞれ 3 つの先行行を持つ 4 つの使用可能な行があり、次のようになります。`12`パス。 カラム`3`障害物がないので合計は`36`。 各サイバーマンを個別の障害物として扱うと、同じセルが誤って複数回削除されてしまいますが、bytearray 表現では自然に重複が処理されます。
