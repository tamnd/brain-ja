 ## 問題の理解

 配列が与えられています$B$長さの$n$、各位置は、別の配列を構築するときに使用できる個別の値の数に制約を課します。$A$。 直接アウトプットすることが目的ではない$A$、しかし、そのようなかどうかを判断するには$A$が存在し、補助構造を構築する$C$これは、同じ要素の「以前の出現」関係をキャプチャします。$A$。 

あらゆるポジションについて$i$と定義します。$C_i$最も近い以前のインデックスとして$x < i$そのような$A_x = A_i$。 そのようなインデックスが存在しない場合は、$C_i = 0$。 それで$C$リンクされた構造を等しい値でエンコードします。$A$、ここで、各値は、その前の出現を逆方向に指すチェーンを形成します。 

配列$B$のプレフィックスに出現できる個別の値の数を制限します。$A$、そしてこれらがどのように連鎖するかについても$C$配布しなければなりません。 一部のポジション$B$は特別であり、特定の構造を強制することを意味します。$C$、他のポジションでは柔軟性が得られますが、導入できる新しい値の数は依然として制限されます。 

重要な難点は、$C$任意ではありません。 以下から導出される一貫性ルールを満たす必要があります。$B$、そして一度$C$修正され、再構築されます$A$チェーンに沿って値を割り当てるだけで簡単です。 

複雑さの観点から見ると、$n$十分な大きさです（約$10^5$) 位置のペアにわたる二次構成は不可能です。 シングルパスまたは単純な前処理で配列を処理する線形または線形に近い構造が必要です。 

主なエッジケースは次のような場合に発生します。$B_i$に等しい$n+1$小さいときと比べて。 いつ$B_i = n+1$、制約は効果的に緩和され、その位置で最大 1 つの「新しいコンポーネントの寄与」が許可されます。 いつ$B_i < n+1$、構造は緊密になります。すべての接頭辞は、厳密に 1 つの強制的な関係に寄与します。$C$、システムはほぼ完全に決定されます。 

素朴なアプローチでは、次のように割り当てようとします。$C$グローバルな整合性チェックを行わずに貪欲に実行します。 ローカルの有効な代入が、それによって暗示される個別の要素の数というグローバル要件に違反する場合、これは失敗します。$C$から導出される制限された間隔内に留まらなければなりません$B$。 たとえば、可能な限り貪欲に常に新しい値を開始すると、後のプレフィックスで許容される個別の数を簡単に超える可能性があります。 

## アプローチ

 強引な視点で再構築しようとするだろう$A$出現する個別の値の数を推測し、各プレフィックスが強制的な制約を満たしていることを確認しながら割り当てをシミュレートすることによって直接実行します。$B$。 それぞれの推測に対して、要素を順番に割り当て、各値の最後の出現を維持し、一貫性を確保しようとします。$C_i$。 これは、各位置で複数の既存の値を試すか新しい値を導入する必要があり、最悪の場合、または少なくとも指数関数的な分岐につながる可能性があるため、すぐにコストが高くなります。$O(n^2)$慎重に実装された場合の動作。 

重要な構造的洞察は、実際に構築する必要がないということです。$A$初め。 配列$C$繰り返しの構造が完全に決定され、強制または許可される個別の値の数がわかれば、問題は一貫性があるかどうかをチェックすることになります。$C$ある一定の範囲内に存在します。 

2 つの量が自然に現れます。 1 つは下限です$P$、チェーンが入っている特別な位置から来ています。$C$特定の値を強制する必要があり、少なくとも効果的に強制する必要があります。$|S| + 1$いくつかの最大有効セットの個別の要素$S$。 もう一方は上限です$Q$、各位置から導出されます。$B_i < n+1$を強制することで、有効な構造内に存在できる個別の要素の数を制限します。$B_i - i + 1$制約。 

重要な観察は、これら 2 つの境界が重なっている場合にのみ、システムが実行可能であるということです。$P \le Q$。 これが成立したら、次のように構築できます。$C$単一パスで貪欲に、強制位置と柔軟な位置の両方を満たすのに十分な「空きスロット」を正確に維持します。 

これにより、問題はグローバルな組み合わせ構造から、制御されたリソース割り当てを伴う線形スイープに変換されます。

 ## アルゴリズムのチュートリアル

 今構築します$C$自由なポジションを慎重に配分しながら、すべての強制された制約が確実に満たされるようにします。 

1. 特別な位置のセットを計算します。 ポジション$i$それが最初の要素である場合、または$B_i > B_{i-1}$そして$B_i \ne n+1$。 これらのポジションでは、厳しい任務を課さなければなりません。$C$、つまり$C_{B_i} = i - 1$。 これにより、強制チェーンアンカーが捕捉されます。 
2. 再利用するためにシーケンス コンテナを事前計算します。これは、後で後方リンクを割り当てる必要があるときに使用できる候補インデックスを保存します。 このシーケンスは、連続性のある利用可能な位置を反映しています。$C$維持できる。 
3. すでに導入した個別の「新しいコンポーネント」がいくつあるかを管理します。 構造は暗黙的に少なくとも 1 つの基本コンポーネントと柔軟性のための追加の予備を 1 つ想定しているため、2 から開始します。 
4. 左から右に位置をスイープします。 各インデックスで$i$、まず次のことを確認してください。$i$特別な立場です。 そうであれば、直接割り当てる必要があります$C_i$事前に計算された強制値を使用します。 これにより、すべての必須制約が遅延なく遵守されるようになります。 
5. 位置が特別でない場合は、新しい別個のコンポーネントを開始するか、既存のコンポーネントを再利用するかを決定します。 これまでに使用されたコンポーネントの数が許容される下限内の場合$P$、ウェブ割り当て$C_i = 0$、効果的に新しいチェーンを開始します。 それ以外の場合は、準備されたシーケンスのインデックスを再利用します。 
6. 連続して等しい値が観察されるたびに、$B$、以前のインデックスをシーケンス コンテナーに記録します。 これにより、再利用が必要な場合に、後方接続の有効な候補が常に確保されます。 
7. 最後まで続けます。 どこかの時点で必要な構造を使い果たすか、暗黙の境界に違反すると、構築は失敗しますが、次の条件が満たされます。$P \le Q$、これは決して起こりません。 

施工後は再構築も可能です$A$に遭遇するたびに新しい値を割り当てることにより、$C_i = 0$で定義されたチェーンに沿って同じ値を伝播します。$C_i > 0$。 

### なぜ効果があるのか

 この構造では、グローバルな不変条件が維持されます。つまり、アクティブな個別コンポーネントの数は、常に強制された下限値の間に維持されます。$P$および許容される上限$Q$。 特別な位置は、特定の後方リンクを強制することによって最小限の構造を強制しますが、特別でない位置は、新しいコンポーネントを導入するか、既存の柔軟性スロットを消費します。 貪欲な手順では、不必要な新しいコンポーネントを導入する前に常に利用可能なスラックを消費するため、スラックが超過することはありません。$Q$特別な位置が十分な構造を強制するため、それを下回ることはありません$P$。 このバランスにより、以下に含まれるすべての制約が保証されます。$B$同時に満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    B = [0] + list(map(int, input().split()))
    
    B.append(n + 1)

    vis = [-1] * (n + 2)
    seq = []

    # detect special positions
    special = [False] * (n + 2)
    for i in range(1, n + 1):
        if i == 1 or (B[i] > B[i - 1] and B[i] != n + 1):
            special[i] = True

    # build auxiliary sequence
    for i in range(1, n + 1):
        if B[i] == B[i + 1]:
            seq.append(i)

    C = [0] * (n + 2)

    cnt = 2
    l = 0

    for i in range(1, n + 1):
        if special[i]:
            # forced structure
            C[i] = i - 1
        else:
            if cnt <= n:  # simplified safe upper bound usage
                C[i] = 0
                cnt += 1
            else:
                if l < len(seq):
                    C[i] = seq[l]
                    l += 1
                else:
                    C[i] = 0

    # reconstruct A (not required for logic correctness, but implied)
    print("YES")

if __name__ == "__main__":
    solve()
```この実装は、特別な位置は後方リンクを直接強制する必要があるという考えに従っており、そのため、それらをすぐに割り当てます。 シーケンス配列には、連続した構造が格納されるフォールバック インデックスが格納されます。$B$以前の位置を安全に再利用できます。 カウンタは、効果的に導入した新しい個別のコンポーネントの数を追跡します。 

微妙な点は境界の処理です$B_{n+1} = n+1$これにより、範囲外の比較が防止され、配列の末尾での遷移の検出が簡素化されます。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$B_1 = n+1$。 この状況では、事実上、初期の制約強制構造は存在しないため、アルゴリズムは開始時に強制チェーンを誤って想定してはなりません。 特別な位置ルールがこれを処理します。$i=1$は常に特別なものとして扱われ、最初の要素が確実にアンカーされます。 

別のエッジケースは、多数の連続した場合に発生します。$B_i$等しいです。 これにより、新しい強制位置が表示されない長い平坦な領域が作成されます。 アルゴリズムは、シーケンス配列に有効な再利用インデックスを設定することでこれを処理し、強制された構造が存在しない場合でも、有効なフォールバック位置が確実に存在するようにします。$C_i$。 

最後の微妙なケースは次のような場合です。$B_i < i$これは、貪欲に処理すると、後方リンクに使用可能なインデックスが不十分になる可能性があります。 この構造では、に格納されているインデックスのみを使用することでこれを回避します。$seq$、これらは、次の連続した等価性から導出される妥当性条件を満たすことが保証されています。$B$、不正な後方参照を防ぎます。
