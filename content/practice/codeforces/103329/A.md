 ## 解決策
 ## 問題の理解

 整数値に関する複数の独立したクエリに答えるように求められます$x$。 それぞれについて$x$、短い整数間隔を構築する必要があります$[l, r]$その区間内のすべての整数の合計が素数になるようにします。 すべての有効な間隔のうち、条件を満たすものを出力できますが、構築は決定的かつ効率的である必要があります。 

キー操作は区間合計です。 どれについても$[l, r]$、合計は等差数列になります。$$S(l, r) = \frac{(l + r)(r - l + 1)}{2}$$したがって、問題は、この式が素数に評価されるように整数のエンドポイントを選択することになります。 

制約（約まで）$10^7$素数性をチェックする必要がある値の大きさ）は、クエリごとに単純に素数性をテストできないことを意味します。 代わりに、約までの素数を前処理する必要があります。$2 \cdot 10^7$、ふるいにすっぽり収まります。 各クエリは、候補構造の数を一定数に減らす必要があります。 

微妙な問題が現れるのは、$l$は非陽性です。 その領域では、区間構造によって和式のパリティ動作が変化し、単純な対称性の議論が失敗する可能性があります。 もう 1 つのよくある落とし穴は、長い間隔でも素数が生成される可能性があると想定していることです。 これは誤りです。なぜなら、合計は 2 つの整数に因数分解され、長さが少なくとも 3 の場合、因数の 1 つが合成になるか、不可避の因数分解構造が生成され、素数性が不可能になるからです。 

素朴な推論による失敗例は、周囲のすべての間隔を試すことです$x$。 たとえば、すべてにチェックを入れると、$[x - k, x + k]$各チェックでは合計の計算と素数のテストが必要になるため、クエリが多数ある場合は、クエリごとにある程度の制限までは遅すぎます。 

## アプローチ

 ブルートフォースのアイデアは単純明快です: 各クエリに対して$x$、可能なペアを列挙します$(l, r)$その周り$x$、合計を計算し、ふるい検索または直接素数テストを使用して素数かどうかをテストします。 すべての候補を網羅的に検索しているため、正しさは明らかです。 

問題は間隔の数です。 許可する場合$l, r$さまざまなサイズに変化する$O(N)$、各クエリは次のようになります$O(N^2)$最悪の場合、それは完全に不可能です。 

構造的な洞察は、有効な間隔が非常に制限されているということです。 合計式では、強力な因数分解制約が強制されます。 長さが少なくとも 3 の区間の場合、等差数列の和は常に少なくとも 1 つの乗法コンポーネントに複合構造を導入するため、素数は非常に短い区間からのみ発生します。 

これにより、問題全体が、それぞれの周囲の一定数の間隔形状のみをチェックすることになります。$x$、さらに時々次の素数を探します$y$または数字$z$そのような$2z - 1$プライムです。 これらの検索は、事前に計算された素数テーブルと単純な上向きスキャンを使用して実行できます。 

この問題は、ローカルなケース処理と最近接素数クエリの組み合わせとなり、すべて sieve によってサポートされます。

 ## アルゴリズムのチュートリアル

 素数を安全限界よりもわずかに高い値まで事前に計算します。$2 \cdot 10^7$、次のような式があるため、$2z - 1$または$y$その大きさに達することができます。 

### ステップ

 1. エラトステネスのふるいを最大まで構築します。$2.001 \cdot 10^7$、ブール配列を格納する`is_prime`。 これにより、後で O(1) の素数チェックが可能になります。 
2. 各クエリ値について$x$かどうかに応じて 2 つのケースに分かれます。$x \le 0$または$x > 0$有効な間隔の構造がゼロ付近で変化するためです。 
3. もし$x > 0$、まず最も単純な有効な構造を試してください。 間隔$[x, x]$の場合は有効です$x$和は次のとおりであるため、それ自体が素数です。$x$。 これが最も直接的な候補です。 
4. 次に検討します。$[x, x+1]$。 その合計は$2x+1$、プライムかもしれないし、チェックするのは安いです。 
5. こちらも検討してください$[x-1, x]$、その合計は$2x-1$。 これにより、近くの奇数が素数であるケースがよく捉えられます。 これら 3 つのチェックは、次の点を中心とする長さ 1 および長さ 2 のすべての間隔をカバーします。$x$。 
6. これらのどれも機能しない場合は、間隔が非正の領域に交差する非対称構造に切り替えます。 最小の素数を探します$y \ge x$そして出力$[-y+1, y]$。 この間隔の合計は次のとおりです$y$対称キャンセルではエンドポイントの寄与が正確に残るためです。 
7. それでも当てはまらない場合は、最小値を検索します。$z \ge x$そのような$2z - 1$は素数であり、出力$[-z+2, z]$。 この構造は、合計が次の形式に折りたたまれるように設計されています。$2z - 1$。 
8. もし$x \le 0$、自明な正中心のケースをスキップし、2 つの非対称パターンを直接使用します。1 つは主要なエンドポイントをターゲットとします。$y$、および形式の素数をターゲットとするもの$2z - 1$、調整された下限により、間隔構造の正確性が保証されます。 

### なぜ効果があるのか

 正しさは、素数和を生成する有効な区間は、正の領域では長さが 2 以下でなければならないという構造的制約に基づいています。 間隔が長くなると、算術合計に因数分解が導入され、素数性が妨げられます。 したがって、すべての有効な解は、単一点区間または隣接するペア、または合計を制御された代数形式に強制的に変換する特別に構築された対称区間のいずれかに帰着します。$y$または$2z - 1$。 

私たちがテストするすべての候補は、和の公式で素数を生成できる唯一の代数的に有効な形式の 1 つに正確に対応します。 各形式で最も近い適切な素数を検索するため、有効な区間が存在する場合は常に有効な区間を見つけることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXN = 2_000_100

is_prime = [True] * (MAXN + 1)
is_prime[0] = is_prime[1] = False

for i in range(2, int(MAXN ** 0.5) + 1):
    if is_prime[i]:
        step = i
        start = i * i
        for j in range(start, MAXN + 1, step):
            is_prime[j] = False

def next_prime(x):
    while x <= MAXN and not is_prime[x]:
        x += 1
    return x

def solve_case(x):
    if x > 0:
        if is_prime[x]:
            return x, x
        if 2 * x + 1 <= MAXN and is_prime[2 * x + 1]:
            return x, x + 1
        if 2 * x - 1 >= 0 and is_prime[2 * x - 1]:
            return x - 1, x

        y = next_prime(x)
        if y <= MAXN:
            return -y + 1, y

        z = x
        while z <= MAXN and (2 * z - 1 > MAXN or not is_prime[2 * z - 1]):
            z += 1
        return -z + 2, z

    else:
        y = next_prime(1 - x)
        return -y + 1, y

def main():
    t = int(input())
    for _ in range(t):
        x = int(input())
        l, r = solve_case(x)
        print(l, r)

if __name__ == "__main__":
    main()
```sieve は素数テーブルを 1 回作成します。これは、すべての候補間隔で定数時間の素数チェックが必要なため、非常に重要です。 の`next_prime`関数は線形スキャンを実行しますが、値が前方に移動し、検索スペースが制限されているため、すべてのクエリにわたって高速なままです。 

各クエリについて、まず 3 つのローカル間隔パターンを試します。$x$。 これらは、アンカーされた長さ 2 までのすべての間隔に正確に対応します。$x$。 どれも機能しない場合は、次の適切な素数パターンまたは準素数パターンの発見に依存するグローバルに構造化された構築に切り替えます。 

マイナスの扱い$x$代数構造によってすでに解が対称形式に強制されているため、不要なローカル チェックが直接回避されます。

## 複雑さの分析

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MAXN = 2_000_100
    is_prime = [True] * (MAXN + 1)
    is_prime[0] = is_prime[1] = False
    for i in range(2, int(MAXN ** 0.5) + 1):
        if is_prime[i]:
            for j in range(i * i, MAXN + 1, i):
                is_prime[j] = False

    def next_prime(x):
        while x <= MAXN and not is_prime[x]:
            x += 1
        return x

    def solve(x):
        if x > 0:
            if is_prime[x]:
                return (x, x)
            if 2 * x + 1 <= MAXN and is_prime[2 * x + 1]:
                return (x, x + 1)
            if 2 * x - 1 >= 0 and is_prime[2 * x - 1]:
                return (x - 1, x)
            y = next_prime(x)
            return (-y + 1, y)
        else:
            y = next_prime(1 - x)
            return (-y + 1, y)

    out = []
    t = int(input())
    for _ in range(t):
        x = int(input())
        l, r = solve(x)
        out.append(f"{l} {r}")
    return "\n".join(out)

 ## 特殊なケース

 のために$x = 1$、アルゴリズムはすぐにチェックします$[1,1]$。 合計は 1 であり、素数ではないため、次のようになります。$[1,2]$和は素数である 3 になります。 コードは明示的にチェックするため、これを正しくキャプチャします。$2x+1$。 

のために$x = 0$、ネガティブスタイル構築がトリガーされます。 最小の素数を計算します$y \ge 1$、これは 2 であり、戻り値$[-1, 2]$。 合計は$2$、正しく素数化され、これにより、ゼロ付近の無効な単一要素推論が回避されます。 

次のような負の値の場合$x = -5$の場合、アルゴリズムはローカル間隔の列挙を試みません。 代わりに、次の素数を直接計算します。$y \ge 6$、これは 7 を返します。$[-6, 7]$。 これにより、周囲が周囲にある場合でも正確さが保証されます。$x$構築は局所密度に依存しないため、有用な局所構造は含まれません。
