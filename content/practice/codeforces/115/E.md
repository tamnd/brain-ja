 ## 解決策
 ## 問題の理解

 私たちは、直線的につながった王国の潜在的な種族からの利益を最大化することが求められています。 各レースは連続した一連の道路を占有し、使用するすべての道路が修復された場合に支払いが行われます。 各道路には修復費用があり、利益は開催されたレースからの支払い総額から、レースに必要な道路の修復費用を差し引いたものとして定義されます。 入力は道路の数で構成されます`n`、レース数`m`、各道路の修理費用、および各レースの左右の終点とその支払い。 出力は単一の整数、つまり達成可能な最大利益です。 

制約は大きいです。 と`n`そして`m`200,000 までの場合、道路のすべての可能なサブセットを明示的に検査するアルゴリズムは不可能です。 道路の考えられるすべての組み合わせをチェックしようとする素朴な試みには、`2^n`天文学的な規模のオペレーションです。 各ロードのすべてのレースをネストされた方法で反復した場合でも、200,000 × 200,000 = 4×10^10 の操作に達する可能性があり、これでは遅すぎます。 これは、O(n log n + m log n) の解は合理的ですが、O(n・m) の解は失敗することを意味します。 

エッジケースには、すべてのレースが修復コストに比べて高すぎるため、道路を修復しないことが最適であるシナリオ、またはすべての道路の修復コストがゼロで、すべてのレースが利益を生むシナリオが含まれます。 たとえば、1 つの道路の修理費用が 10 で、その道路を使用する 1 つのレースの費用がわずか 5 である場合、最良の選択は何も修理せず、利益をゼロにすることです。 不用意に実装すると、自動的にすべての種族が含まれ、利益が過大評価される可能性があります。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 道路の考えられるすべてのサブセットについて、どのレースが実行できるかを計算し、利益を計算します。 これはあらゆる可能性をチェックするため正しいですが、n=200,000 の場合は実行不可能になります。 演算回数はおよそ O(2^n · m) であり、非常に多くなります。 

より高速な解決策を実現するための重要な洞察は、問題をインターバル動的プログラミングの変形として、またはセグメントベースの意思決定問題としてモデル化することです。 すべての道路は修復することもできないこともでき、レースは区間内のすべての道路が修復された場合にのみ価値を発揮します。 「潜在的な利益」をレースの支払総額から道路の修復費用を差し引いたものと想像すると、問題はどの連続する部分区間を修復するかを決定することであると考えることができます。 視点を逆にして、「この道路を修復することで得られる利益」を考慮すると、この問題は古典的な最大合計セグメント問題に変換できることがわかります。各道路には、その道路を必要とするレースによって定義された正味価値があり、その修繕コストを差し引いた値があり、合計正味価値を最大化するために連続する道路のサブセットを選択したいと考えています。 ただし、レースは複数の道路にまたがる可能性があるため、寄付を効率的に処理する必要があります。 

最適なソリューションでは、スイープ ライン手法とセグメント ツリー手法を組み合わせて使用​​します。 レースをプレフィックスサム配列への追加として表すことができるため、各道路は参加するレースの合計値を知ることができます。その後、各道路について、修理された場合の純利益は、それに関係するレースの合計値から修理コストを差し引いたものになります。 問題は、純利益がプラスになる道路を選択することに帰着します。 純利益がマイナスの道路は総計を減らすことになるため、修復すべきではありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n・m) | O(n + m) | 遅すぎる |
 | 最適 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`road_value`サイズ n+2 からゼロまで。 この配列には、最終的に、各道路をカバーするすべてのレースからの支払いの合計が含まれます。 
2. 各レースを繰り返します。 道路をまたぐレースに向けて`lb`に`ub`支払いあり`p`、増分`road_value[lb]`による`p`そして減少します`road_value[ub+1]`による`p`。 これは、範囲に値を効率的に適用するための標準的なプレフィックス合計差分配列のトリックです。 
3. 差分配列を道路ごとの実際の値に変換します。 1からnまで繰り返して累積します`road_value[i] += road_value[i-1]`。 この後、`road_value[i]`ロードをカバーするすべてのレースからの潜在的な利益の合計が含まれています`i`。 
4. 各道路の純利益を次のように計算します。`net[i] = road_value[i] - repair_cost[i]`。 純利益がマイナスの場合は、ゼロに設定します。 このステップにより、総利益を減少させるような道路の修復が決して行われないことが保証されます。 
5. すべての道路の純利益を合計します。 この合計が達成可能な最大利益です。これは、純寄与がプラスの道路のみを修復すると、それらの道路をカバーするすべてのレースで総利益が増加することが保証されるためです。 

機能する理由: 各レースは、そのレースが通るすべての道路に支払いを寄付します。 修繕費を差し引くことで、総利益に対する各道路の貢献度を直接測定します。 正味価値がマイナスになる道路は総利益が減少するため、無視するのが安全です。 レースは必要なすべての道路が修復された場合にのみ実行されるため、スイープライン プレフィックスサムのアプローチにより各道路の支払総額が正しく計算され、プラスの寄与を合計することで最適なサブセットが選択されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
repair_cost = [0] + [int(input()) for _ in range(n)]

road_value = [0] * (n + 2)

for _ in range(m):
    lb, ub, p = map(int, input().split())
    road_value[lb] += p
    if ub + 1 <= n:
        road_value[ub + 1] -= p

for i in range(1, n + 1):
    road_value[i] += road_value[i - 1]

profit = 0
for i in range(1, n + 1):
    net = road_value[i] - repair_cost[i]
    if net > 0:
        profit += net

print(profit)
```最初のセクションでは入力を読み取り、修理コストの配列を構築します。 1 ベースのインデックスの場合、インデックス 0 にゼロを埋め込みます。 2 番目のセクションでは、差分配列を初期化して、各レースが範囲全体で支払いをどのように追加するかを追跡します。 差分配列をプレフィックス合計に変換すると、道路ごとの潜在収益の合計が得られます。 修理費を差し引いてプラスを合計すると、最終的な利益が得られます。 Off-by-One エラーは、1 ベースのインデックス付けと n+2 サイズの配列を慎重に使用して境界の増分を安全に処理することで防止されます。
