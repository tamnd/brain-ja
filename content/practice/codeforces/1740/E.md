 ## 解決策
 ## 問題の理解

 各ノードがカードを表すルート付きツリーが与えられます。 カード 1 はルートとして固定され、他のすべてのカードは 1 つ前のカードからぶら下がっており、すべてのノードが 1 つの親を持ち、エッジが常に小さいインデックスを指す構造を形成します。 

まず、1 から n までの整数の順列をノードに割り当てる必要があります。これは、各カードが個別のラベルを受け取ることを意味します。 その後、葉を一枚一枚取り除いていく作業を繰り返します。 リーフを削除するたびに、その現在の値をシーケンスに追加します。 さらに、ノードを削除するときに、親が現在より大きな値を保持している場合は、その値をその親に「プッシュダウン」することができ、削除イベントに沿って値が上方に効果的に伝播できるようになります。 

最終的なシーケンスはノードが削除される順序ですが、追加された各値は前の伝播ステップの影響を受ける可能性があります。 目標は、この結果として得られるシーケンスの最長の非減少サブシーケンスの長さを最大化するように、最初の順列とリーフの削除順序を選択することです。 

この制約により、最大 100,000 ノードが許可されます。 構造の構築と最適な戦略の計算の両方が線形または線形に近い必要があるため、およそ O(n log n) より悪い解は合格しません。 これにより、すべての順列をシミュレートしたり、サブシーケンスを直接評価しようとするソリューションは即座に除外されます。 

微妙な難しさは、ノードに書き込まれる値が固定されていないという事実から生じます。 親は、削除される前に、子からの値によって複数回上書きされる可能性があります。 これは、削除時のノードの値はどの子が以前に処理されたかによって決まり、最終的なシーケンスは単に静的ラベルの走査順序ではないことを意味します。 

素朴な考えを打ち破るエッジ ケースの 1 つは、ノード 1 が中心である星形のツリーです。 すべてのノードが 1 に直接接続されている場合、リーフの削除順序はノード 1 が上書きされる頻度に大きく影響するため、シーケンスが大幅に再形成される可能性があります。 ツリー構造だけによる素朴な貪欲な順序付けは、値の伝播効果を無視するため失敗します。 

もう 1 つの失敗例はパスです。 ツリーがチェーンの場合、削除するたびに単一方向の伝播が強制され、最適な戦略は深さに沿って順列がどのように割り当てられるかに密接に関係することになりますが、これはサブツリーに依存しない単純な推論では捉えられません。 

## アプローチ

 ブルートフォースアプローチでは、すべての順列を割り当て、すべての有効なリーフ削除順序をシミュレートしようとします。 シミュレーションごとに、結果のシーケンスを計算し、標準的な O(n log n) LIS アルゴリズムを使用してその最長の非減少サブシーケンスを計算します。 んがあるから！ 順列と有効な削除命令が指数関数的に多くなる場合、これは非常に小さい n の場合でも完全に実行不可能です。 順列を修正したとしても、有効な葉削除シーケンスの数はツリーのすべてのトポロジー次数に対応し、そのサイズはすでに指数関数的になります。 

重要な観察は、この操作が「リーフを取得し、その値が小さければその値を親に伝播する可能性がある」ということです。エッジに沿った局所最小化プロセスのように動作します。 最終的に、親はそれ自体の間で最小値を保持し、削除されたすべての子孫は削除される前に処理されます。 これは、最終シーケンスに対する各ノードの効果的な寄与は、元に割り当てられた値ではなく、削除の瞬間にそのサブツリーに見られる最小値であることを示唆しています。

これにより、問題は、各ノードがそのサブツリー内のいくつかの割り当てられたラベルの最小値と考えられる値に寄与するシーケンスを構築することに変換され、順列と削除順序を選択することでこれらの最小値を自由に制御できます。 重要な構造はツリーの順序付けになります。基本的に、各サブツリーが親にいつ「折りたたまれる」かを決定します。 

次の洞察は、視点を逆転させることです。 削除することを考えるのではなく、上向きに構築することを考えます。 各サブツリーは、完全に処理されると、正確に 1 つの「代表値」を提供します。この代表値は、小さい値ほど早く上方に伝播する傾向があるという事実と一致する必要があります。 

これは貪欲なアイデアにつながります。つまり、長い非減少サブシーケンスをサポートするために、シーケンス内でより大きな値がより長く存続するようにしたいということです。 したがって、ツリーの奥深くに小さな値を割り当て、ルートに近い大きな値を割り当てると同時に、各サブツリー内で処理順序によって制御された方法で値が伝播できるようにして、増加ができるだけ頻繁に維持されるようにしたいと考えています。 

最適な解決策は、各ノードのサブツリーのサイズを計算し、DFS ベースの DP を使用して、サブツリーが最適な順序でマージされるときに、非減少サブシーケンスに配置できる要素の数を決定することになります。 マージ順序は、より小さい「チェーン」が最初に吸収され、より大きなサブツリーからのより長い単調チェーンが保存されるように、常に計算された寄与の昇順で子を処理することに似ています。 

有用な類似点は、LIS を最大化するためにソートされたシーケンスをマージすることです。常に小さい構造を最初に結合すると、結果のシーケンスで増大する構造の連続性が損なわれることを回避できます。

 ## アルゴリズムのチュートリアル

 1. 各ノードがその子を認識できるように、親配列からルート付きツリーを構築します。 これにより、値が上方にどのように伝播するかを決定する構造が確立されます。 
2. DFS をルートから実行して、各サブツリーを個別に処理します。 目的は、すべてのノードについて、最終的な非減少サブシーケンスに対するサブツリーの達成可能な最良の寄与を計算することです。 
3. 各ノードについて、すべての子の結果を結合する前に再帰的に計算します。 各子は、そのサブツリー内で達成可能な最適な構造を表す値を返します。 
4. ノードの子を結合する前に、計算された値で昇順に並べ替えます。 この順序により、より小さな下部構造が最初に吸収されることが保証され、より大きな増加パターンの早期の中断が防止されます。 
5. 子コントリビューションを順番にマージします。 マージ中は、値に互換性がある場合に現在のシーケンスを拡張できるブロックとして各サブツリー結果を効果的に処理することで、可能な限り最良の非減少構造を維持します。 
6. 現在のノードの計算値をその親に返します。これは、このサブツリーがユニットとして扱われる場合に達成可能な最良の寄与を表します。 

中心的な不変条件は、DFS がすべてのノードに対して、最適な内部順序付けと値の割り当ての下でサブツリーから達成可能な非減少サブシーケンスの最大長を返すということです。 子は寄与度の昇順にマージされるため、より大きなサブツリーがすでに形成されている最適チェーンを強制的に減少させることはなく、各ノードでの局所的な最適性がルートでのグローバルな最適性となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    p = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for i, parent in enumerate(p, start=1):
        g[parent - 1].append(i)

    dp = [0] * n

    def dfs(u):
        for v in g[u]:
            dfs(v)

        child_vals = [dp[v] for v in g[u]]
        child_vals.sort()

        cur = 0
        for x in child_vals:
            if x >= cur:
                cur += 1

        dp[u] = cur + 1

    dfs(0)
    print(dp[0])

if __name__ == "__main__":
    solve()
```プログラムは、各ノードがその子に直接アクセスできるように、隣接リストを使用してツリーを構築します。 DFS は結果をボトムアップで計算し、各サブツリーが親の計算で使用される前に完全に解決されていることを確認します。 

各ノード内のリスト`child_vals`すべての子供たちから寄付を集めます。 これらの値を並べ替えることは、より小さな構造的寄与を最初に組み合わせることが保証されるため、不可欠です。 変数`cur`子サブツリーを 1 つずつ統合しながら、維持できる最適な非減少チェーンの長さを追跡します。 現在のチェーンを拡張できる子の値が見つかるたびに、チェーンの長さを増加させます。 

最後に、各ノードはそれ自体を考慮して 1 を加算します。これは、すべてのサブツリーが少なくともノード自体を有効な構築に寄与しているためです。

 ## 特殊なケース

 ディープ チェーンは、DP が兄弟からの干渉なしに単一のパスを介して正しく伝播するかどうかをテストします。 このような場合、各ノードには子が 1 つだけあるため、並べ替えは何も行われず、DP はレベルごとに増加し、n に等しい答えが生成されます。 

星型ツリーは、アルゴリズムが多数の独立した子を正しく処理するかどうかをテストします。 すべての子は等しい最小値を提供するため、ソートによって子が安定に保たれ、ルートが完全に増加するチェーンを蓄積できるようになります。 

n=2 の最小ケースは、基本ケースが単一のリーフとその親の寄与を過小評価していないことを検証します。
