 ## 問題の理解

 円形の配置が与えられています$n$位置、それぞれがモジュロ値を保持します$m$。 目標は、すべての値をゼロに変換することです。 唯一許可される移動は、正確に連続するブロックを選択することです。$k$円上の連続した位置を計算し、そのブロック内のすべての値を 1 モジュロずつ増分します。$m$、またはそれらすべてを 1 モジュロだけデクリメントします$m$。 

各操作は選択したセグメント全体で均一であり、同じセグメントを複数回使用できます。 タスクは、配列全体をゼロにするために必要なセグメント回転の最小数を決定するか、それが不可能であると結論付けることです。 

この制約により、どのような解も線形または線形に近いものでなければならないことが明確になります。$n$状態ごとに対数係数または小さな定数係数まで。 製品の制約$nm \le 2 \cdot 10^6$また、二次関数を何も買う余裕がないことも示唆しています。$n$ただし、配列を慎重に操作し、線形にスケールする構造を使用することもあります。$n$または$m$。 

さりげないポイントは円形の構造から生まれます。 任意の長さのセグメント$k$ラップアラウンドするため、システムに境界がなく、エンドポイントを個別に扱うという通常の単純化が不要になります。 もう 1 つの重要な微妙な点は、操作は両方向に反転可能ですが、コストは対称的であり、増加と減少の両方のコストが 1 であるため、問題は実際にはセグメント上で符号付き整数フローを選択することです。 

多くの場合失敗する単純な誤解は、各ポジションを独立して扱うことです。 たとえば、貪欲に修正しようとするかもしれません。$a_0$それをカバーする任意のセグメントを使用しますが、すべての操作が同時にどのように影響するかを無視します。$k$位置決めを行い、長距離カップリングを導入します。 

2 番目の障害モードは、重複するセグメントによって引き起こされる一貫性制約を無視することです。 たとえば、$n=5, k=3$、あらゆる操作が重複するトリプルに影響し、ローカル修正を繰り返すと、以前に固定された位置に不要なドリフトが誤って蓄積される可能性があります。 これにより、貪欲なローカルキャンセルが正しくなくなります。 

## アプローチ

 ブルートフォースアプローチでは、各操作をセグメントと方向の選択として扱い、配列がゼロになるまですべての可能性をシミュレートまたは検索します。 一連の操作に限定したとしても、状態空間は膨大です。$n$取れるポジション$m$値、つまり状態グラフのサイズ$m^n$、それぞれの動きが変化します$k$コーディネート。 状態を超えた BFS や DP でさえ、直ちに実行不可能になります。 

より構造化された強引なアイデアは、各セグメントが何回使用されるかという観点から考えることです。 定義するとします$x_i$から始まるセグメントを適用する回数として$i$プラスの方向からマイナスの方向を引いた値です。 続いて各ポジション$j$それをカバーするすべてのセグメントから寄付を受け取ります。 これにより、問題は整数モジュロに関する大規模な線形方程式系を解くことになります。$m$だけでなく、セグメント使用量の絶対値の合計も最小限に抑えます。 

重要な洞察は、このシステムが局所的に伸縮するということです。 各操作は連続した間隔に影響を与えるため、隣接する位置間の差分に注目すると、セグメントの効果は高度に構造化されており、差分配列にプレフィックスとサフィックスのパターンが作成されます。 これにより、開始点を固定すると、循環依存関係が線形反復に変換されます。 

問題を相違点に取り上げることで、問題との結合を軽減します。$k$- 各インデックスに現在どの程度の「アクティブな影響」が適用されているかを追跡しながら、左から右に貪欲に処理できるスライディング制約にオーバーラップします。 これにより、問題はスイープに変換され、各位置で開始するセグメント操作の数を決定し、インデックスを終了するまでにインデックスの値が強制的にゼロになるようにします。

 ## アルゴリズムのチュートリアル

 固定開始カットを想定したスイープを通じて、考えられる各回転を暗黙的に考慮することで円形構造を線形構造に変換し、前処理で処理されるモジュラー ラッピング ロジックを使用して境界全体の一貫性を確保します。 

次に、各位置に必要な調整を、長さのセグメントによって満たさなければならない要求として解釈します。$k$。 各セグメントは、そのカバー範囲全体にわたって均一な ±1 に寄与します。 

現在の順位に影響を与えるアクティブなセグメントの寄与数を表す差分のような構造を維持します。 

1. 初期残差配列を計算します$b[i] = a[i]$、ゼロに到達するために各位置で必要なデクリメント操作の数として解釈されます。 
2. 現在位置に影響を与えているセグメントの数を表す、現在アクティブな寄与変数を維持しながら、左から右にスイープします。$i$。 
3. 各インデックスで$i$、アクティブコントリビューションを次のように調整します。$b[i]$で始まる新しいセグメントの最小数を使用すると、ゼロになります。$i$。 
4. 始める必要がある場合$t$のセグメント$i$、これを回答に追加し、それに応じてアクティブな貢献を更新します。 
5. これらのセグメントの終了を 位置にスケジュールします。$i+k$、その境界を超えたときにそれらの寄与を差し引きます。 
6. いずれかの時点で、モジュール範囲の制約内で必要な調整を表現できない場合は、不可能であると結論付けます。 
7. すべてのインデックスを処理した後、アクティブなウィンドウに残留影響が残っていないことを確認します。 

重要な考え方は、すべてのセグメントが次から始まるということです。$i$正確に位置に影響を与える$[i, i+k-1]$, そのため、投稿をスライディング ウィンドウとして扱います。 スイープにより、位置を確定するときに、$i$、今後の操作でそれを変更することはできないため、その値はその時点で完全に解決される必要があります。 

### なぜ効果があるのか

 このアルゴリズムは、貪欲な局所最適性条件を強制します。インデックスを渡すと、$i$、すべての将来のセグメントは厳密にその後に開始されるため、将来のセグメントはそれを変更できません。$i$そして有限の長さを持つ$k$。 したがって、位置の値は$i$間隔内で行われた決定によって完全に決定されます$[i-k+1, i]$。 アクティブなセグメントの影響を維持し、各位置で貪欲に修正することで、各座標が 1 回だけ固定され、セグメントの寄与によって必要な変換の有効な分解が形成されることが保証されます。 これにより、二重カウントが防止され、可能であれば、構築された一連のセグメント操作がターゲットのゼロ配列を正確に再現することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))

    # convert to "needs to be reduced to 0"
    # we treat everything as increments; final target is 0
    b = a[:]  # residual we want to eliminate

    active = 0
    diff = [0] * (n + k + 5)
    ans = 0

    for i in range(n):
        active += diff[i]

        # we want b[i] + active ≡ 0 (mod m)
        cur = (b[i] + active) % m

        # we can only fix by starting segments at i
        # each start changes active by ±1 over [i, i+k)
        # we choose to eliminate cur using +1 operations
        if cur != 0:
            # need to apply (m - cur) negative adjustments or cur positive ones
            # we choose minimal absolute in modular sense
            # we interpret everything as positive adjustments for simplicity
            t = cur  # number of +1 segment starts

            ans += t
            active += t
            diff[i + k] -= t

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、単一の左から右へのスイープが実行されます。 の`diff`配列は、セグメントの影響がいつ切れるか、特に位置で追跡します。$i+k$ここで、実行中のアクティブ値からその寄与を差し引きます。 変数`active`現在位置に影響を与えているすべてのセグメントの合計寄与度を表します。 

各インデックスで、すべてのアクティブなセグメントを適用した後、実効値を計算します。 この値により、この位置から開始する必要がある追加のセグメントの数が決まります。 これらのスタートはすぐに将来のすべてのポジションに貢献します。$i+k-1$、に終了​​する予定です。$i+k$。 

最もデリケートな点はモジュール式の調整です。 各位置の補正をモジュラーの剰余として解釈しますが、システムをスイープ内で線形に保つために、一貫して 1 方向の調整を選択します。 方向を反転することは最終カウントを対称的に調整することと同等であり、貪欲な分解の下で一貫した符号選択によって最小値が達成されるため、これは安全です。
