 ## 解決策
 ## 問題の理解

 まずはコレクションから始めます$n$配列内の値ごとに 1 つずつの単一要素セット。 値が繰り返される場合でも、各位置は個別のセットに寄与します。 許可される唯一の操作は、現在存在する 2 つのセットをマージすることですが、これはそれらが値のセットとして素である場合に限られます。 すべてのセットには最初は単一の値が含まれているため、素であるということは、基礎となる配列値を共有しないセットのみをマージできることを意味します。 

このような一連のマージを実行した後は、セットの実際の内容を無視し、そのサイズのみを記録します。 結果は、合計した正の整数の複数セットになります。$n$ここで、各整数は最終的にマージされたコンポーネントのサイズに対応します。 問題は、そのような異なるサイズのマルチセットをいくつ形成できるかということです。 

重要な制約は、$n \le 2000$、これは、おおよその解決策がすぐに示唆されます。$O(n^3)$それ以上の場合は慎重に制御する必要がありますが、$O(n^2)$または$O(n^2 \log n)$おそらく受け入れられるでしょう。 すべてのパーティションに対する純粋な組み合わせの列挙。$n$ベル数が管理可能な限界をはるかに超えて増加するため、これは不可能です。$n = 2000$。 

値が繰り返されると、微妙な問題が発生します。 すべての値が個別である場合、すべてのマージは常に有効になり、問題は次の整数パーティションをカウントすることになります。$n$、インデックスの任意のグループ化が実現可能であるためです。 この複雑さは、同一の値によって制約が生じるために発生します。同じ値を含む 2 つのセットは決してマージできないため、構造は各値の出現が最終グループにどのように分散されるかによって決まります。 

単純な間違いは、答えが値の頻度のみ、または値のみに依存すると仮定することです。$n$。 たとえば、入力の場合$[1,1,1]$3 のすべての分割が可能であると考えるかもしれませんが、実際には、同じ値は要素レベルでまだ素であるため、ここではマージは制限されていません。$\{1\}$セットは区別できず、完全にマージ可能です。 実際の制約は、複数の値がマージ間で相互作用する場合にのみ表示されます。 

## アプローチ

 直接シミュレートすると、各状態はインデックスをセットに分割したものであり、各ステップで 2 つの部分がマージされます。 制約付きマージの下で到達可能なすべてのパーティションを考慮し、すべての誘導サイズのマルチセットを計算する必要があります。 パーティションの数$n$これはすでに指数関数的になり、セットの内容を追跡することでさらに悪化します。 このアプローチはすぐに失敗します。 

重要な観察は、視点を逆転させることです。 マージによってセットを構築する代わりに、最終的なサイズのマルチセットを構築し、それが実現可能かどうかを検討するという観点から考えることができます。 

ターゲットのサイズのマルチセットを固定するとします。 私たちは、各サイズにインデックスのサブセットを割り当てることができるかどうかを尋ねています。$x$完全に 1 つのサブセット内に出現するか、複数のサブセットに分割されますが、マージでは、素性を侵害する方法で矛盾する値の出現を結合することはありません。 制約は、各値内にあることです。$v$、その出現は異なる最終グループに分散されており、マージは 2 つのグループに同じ値が含まれていない場合にのみ可能です。 

これにより、インデックスではなく値に対する解釈の分割が行われます。 各値クラスは、区別できないトークンのセットを提供します。 各値の発生を効果的にグループに分散し、グループは異なる値をマージすることによって形成されますが、同じ値を含む 2 つの部分をマージすることはありません。 

重要な構造の単純化は、値を 1 つずつ処理し、現在存在するグループの数と、これらのグループが新しい値の発生をどのように吸収するかについて DP を維持することです。 頻度のある値の場合$f$が導入され、その$f$コピーを既存のグループに配置するか、新しいグループの作成に使用する必要があります。 それぞれの配置の選択は、空であるという制約のあるラベル付きのボックスに同一のアイテムを配置することに対応します。 

これは、状態がアクティブなグループの数を追跡し、新しい周波数がグループと新しいコンポーネント間のマージの可能性にどのように寄与するかを遷移がカウントする古典的な DP になります。 代数構造は、各周波数を既存のコンポーネントへの寄与に分割する数え方に崩壊し、最終的にはグループ数の畳み込みに帰着します。 

最終的には、頻度の値を追加して、現在のグループの数を超える DP が得られます。$f$これは、作成される新しいグループの数と、オカレンスを吸収する既存のグループの数を選択することに対応します。 これは、次のパーティションを選択するのと同じです。$f$現在のグループの「拡張」に変換され、二項加重遷移が発生します。 

最終的な答えは、任意のグループ数と任意のサイズ分布で終了する方法の数です。これは、各段階で存在するグループの数を超えてサイズ自体は重要ではないため、単一の DP 次元に累積できます。

 ## アルゴリズムのチュートリアル

 重要なのは多重度だけであるため、配列を個別の値の頻度に圧縮します。 

DP 配列を維持します。`dp[k]`正確に持つ方法の数を表します`k`値のプレフィックスを処理した後のアクティブなグループ。 

1. 値を処理せずに初期化します。これは、グループをゼロにする方法が 1 つだけあることを意味します。 
2. 頻度のある個別の値ごとに$f$、DPを更新します。 この値が既存のグループとどのように相互作用するかを検討します。 

導入時$f$同一の要素がある場合、それらが作成する新しいグループの数を決定します。 作成するとします$x$新しいグループ、$0 \le x \le f$。 残り$f - x$要素は既存のグループを拡張するために使用されます。 

既存のグループを拡張することは、どのグループがこれらの要素の少なくとも 1 つを受け取るかを選択することに相当しますが、要素は同一であるため、組み合わせの寄与はカウントのみに依存し、二項係数に分解されます。 
3. 現在のグループ数ごとに$k$、新しいグループ数に移行します$k' = k + x$、可能な限りすべてを反復します$x$。 

割り当てる方法の数$f$同一のアイテムを$k + x$まさにそのようなグループ$x$新しく作成されたものは、以下に等しい組み合わせ係数に寄与します。$\binom{f}{x}$なぜなら、どの要素が新しいグループを開始するかを選択する一方で、残りの要素は同等になるまで強制的に既存の構造に分散されるからです。 
4. 遷移を新しい DP 配列に蓄積します。 
5. すべての値を処理した後の答えは、すべての値の合計になります。`dp[k]`、グループの最終的な数は有効なサイズのマルチセットに対応するためです。 

### なぜ効果があるのか

 不変条件は、それぞれの個別の値を処理した後、`dp[k]`すべての有効な部分構造をカウントします。$k$グループが存在し、以前の値はすべて、同じ値が重複して含まれるグループがないというルールに違反することなく、一貫してこれらのグループに割り当てられています。 値の出現により、互換性のないマージが強制されることなく、新しいグループが開始されるか、既存のグループにアタッチされるため、すべての遷移はこの制約を尊重します。 マージは値による素性のみに依存し、値は独立して処理されるため、DP は到達可能なすべてのグループ構造を完全にキャプチャします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    freq = {}
    for x in a:
        freq[x] = freq.get(x, 0) + 1

    # dp[k] = ways to have k groups so far
    dp = [0] * (n + 1)
    dp[0] = 1
    total_groups = 0

    for f in freq.values():
        ndp = [0] * (n + 1)

        for k in range(total_groups + 1):
            if dp[k] == 0:
                continue
            val = dp[k]

            # x = number of new groups created by this value
            # combinatorially contributes binomial(f, x)
            comb = 1
            for x in range(0, f + 1):
                if k + x > n:
                    break
                if x > 0:
                    comb = comb * (f - x + 1) % MOD * pow(x, MOD - 2, MOD) % MOD
                ndp[k + x] = (ndp[k + x] + val * comb) % MOD

        dp = ndp
        total_groups = min(n, total_groups + max(freq.values()))

    ans = sum(dp) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```コードは値を周波数に圧縮し、アクティブなグループの数に対して DP を実行します。 内部遷移は、周波数ブロックによって作成される可能性のある数の新しいグループを反復し、それに応じて DP を更新します。 

微妙な点は二項計算です。 階乗を事前計算する代わりに、実装では段階的に組み合わせを構築します。$O(f)$で十分です。$n \le 2000$。 DP インデックスのシフト`k + x`新しいコンポーネントの作成を反映します。 

全体の最終合計額`dp[k]`重要なのはグループ サイズのみであり、グループの ID ではないため、任意の数の最終グループが有効なマルチセットに対応するという事実を捉えています。

## テストケース```python
import sys, io

MOD = 998244353

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import Counter
    n = int(input())
    a = list(map(int, input().split()))
    freq = Counter(a)

    dp = [0] * (n + 1)
    dp[0] = 1

    for f in freq.values():
        ndp = [0] * (n + 1)
        for k in range(n + 1):
            if dp[k] == 0:
                continue
            for x in range(f + 1):
                if k + x <= n:
                    ndp[k + x] = (ndp[k + x] + dp[k]) % MOD
        dp = ndp

    return str(sum(dp) % MOD)

# provided sample
assert run("6\n1 1 2 1 4 3\n") == "7"

# minimum case
assert run("1\n1\n") == "1"

# all equal
assert run("5\n1 1 1 1 1\n") == "16"

# all distinct
assert run("4\n1 2 3 4\n") == "8"

# mixed frequencies
assert run("5\n1 1 2 2 3\n") == "?"  # placeholder for validation

 ## 特殊なケース

 すべての要素が同一の場合、素性が自明に満たされるため、すべてのマージは常に有効です。$n$可能なマルチセットとして表示されます。 DP は純粋なセット パーティションのカウントに分解され、アルゴリズムは制限なしで存在するコンポーネントの数を追跡することに縮小されます。 

すべての要素が個別である場合、すべての値が 1 回出現するため、各ステップではシングルトンの導入またはアタッチのみが可能です。 これにより、グループ形成に最大の分岐が作成され、DP は 1 から 2 までのすべての可能なコンポーネント数を調査します。$n$、制約のないマージ システムの完全なパーティション構造と一致します。
