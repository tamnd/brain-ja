 ## 解決策
 ## 問題の理解

 提案されたユーザー名と、すでに登録されているユーザー名のコレクションが与えられます。 新しいユーザー名が「安全」に使用できるかどうかを判断する必要があります。つまり、一連の変換ルールの下では、そのユーザー名が既存のユーザー名と同等であるとはみなされません。 

文字置換を繰り返し適用することで一方をもう一方に変換できる場合、2 つのユーザー名は同等であるとみなされます。 これらの置換は、文字の等価クラスを定義します。つまり、大文字と小文字の間での大文字と小文字の変更は常に許可され、特定の文字と数字は特定の方法で交換でき、一部の文字はこれらのルールのチェーンを通じて効果的に交換可能です。 重要な考え方は、文字列を文字通り比較しているのではなく、これらの等価性の下で正規の意味を比較しているということです。 

入力制約は小さく、既存のユーザー名は最大 1000 個で、それぞれの長さは 50 までです。これは、すべての文字列のすべての文字をチェックするだけでも約 50,000 回の操作にすぎないため、O(n · L) アプローチで十分であることをすぐに示唆しています。 各文字列を個別に前処理または正規化するソリューションは、制限内に簡単に収まります。 

変換ルールのあいまいさから微妙な問題が発生します。 素朴なアプローチでは、少数の直接置換のみが重要であると想定するかもしれませんが、ルールは等価性の連鎖を形成します。 たとえば、文字 A が B になることができ、B が C になることができる場合、A と C も同等です。 推移閉包を無視すると、誤った比較が発生します。 

もう 1 つの落とし穴は、変換を方向性のあるものとして扱うことです。 ルールは明示的に双方向であるため、すべての置換は無向の等価関係として解釈される必要があります。 

最後に、不注意な解決策では、小文字化などの単純な正規化の後に文字列を文字ごとに比較する可能性があります。 これは、大文字と小文字の正規化だけでは処理されない数字と文字の関係 (0 と O、または 1 と複数の文字など) が存在するため失敗します。 

## アプローチ

 ブルートフォースのアイデアは簡単です。既存のログインごとに、許可されている文字置換を使用して新しいログインに変換できるかどうかを判断します。 これには、文字列のペアごとに文字変換に対して検索または BFS/DFS を実行する必要があります。 各文字列の長さは最大 50 で、既存の文字列は最大 1000 個あるため、文字位置ごとの変換状態を調査すると、すぐにコストが高くなります。 最悪の場合、各文字比較が複数の選択肢に分岐し、比較ごとに指数関数的に爆発的に増加する可能性があります。 

重要な点は、実際には変換をシミュレートする必要がないということです。 2 つの文字が同じ表現にマッピングされる場合に限り、2 つの文字が同等であるような、各文字の一貫した表現が必要であるだけです。 これにより、問題は古典的な同値クラス構築問題に変わります。 すべての文字を正規形式にマッピングすると、すべてのログインが正規化された文字列になり、正規化された既存のログインが正規化された新しいログインと一致するかどうかを確認するだけです。 

これにより、文字列に対するグラフ検索の問題が、有限文字セットの単純な前処理とそれに続く線形比較に軽減されます。

 | 正規マッピング + 比較 | O(n・L + アルファベットの扱い) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、文字に対して等価クラスを構築します。 アルファベットは小さくて固定されているため (文字、数字、アンダースコア)、変換ルールによって暗示される関係を安全にハードコーディングまたはユニオン検索できます。

1. 可能なすべての文字に対して素集合共用体 (DSU) 構造を初期化します。 最初は等価性がないと想定されているため、各文字は独自のセットで始まります。 
2. すべての変換ルールについて、対応する文字を同じセットにマージします。 各マージは、最終的な表現において 2 つの文字が交換可能であることを表します。 
3. すべての結合が実行された後、各文字の正規表現 (たとえば、そのセット内の辞書編集上最小の文字) を定義します。 
4. すべての文字をその代表文字に置き換えて、新しいログイン文字列を正規形式に変換します。 
5. 既存のログインごとに、同じマッピングを使用して正規形式に変換します。 
6. 正規化された既存のログインをそれぞれ正規化された新しいログインと比較します。 
7. 一致するものが見つかった場合、新しいログインは競合し、「いいえ」が出力されます。 それ以外の場合は「Yes」を出力します。 

これが機能する理由は、DSU 構造がすべての推移的等価性を 1 つのクラスに折りたたむためです。 2 つの文字間の有効な変換シーケンスは、等価グラフ内の同じ連結成分に属するそれらの文字に正確に対応します。 各文字をそのコンポーネントを表す文字に置き換えることで、すべての同等の文字が同じシンボルにマッピングされ、すべての非同等の文字が異なるマッピングを行うようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self):
        self.parent = {}
        self.rank = {}

    def find(self, x):
        if x not in self.parent:
            self.parent[x] = x
            self.rank[x] = 0
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1

# Build equivalence relations according to the problem rules
dsu = DSU()

def add_equiv(a, b):
    dsu.union(a, b)

# case-insensitive letters
for c in "abcdefghijklmnopqrstuvwxyz":
    add_equiv(c, c.upper())
    add_equiv(c.upper(), c)

# 'O' and '0'
add_equiv('O', '0')
add_equiv('0', 'O')

# '1' and {l, I}
add_equiv('1', 'l')
add_equiv('1', 'I')
add_equiv('l', 'I')

# closure is handled by DSU

def normalize(s):
    return ''.join(dsu.find(c) for c in s)

s = input().strip()
n = int(input())
target = normalize(s)

for _ in range(n):
    t = input().strip()
    if normalize(t) == target:
        print("No")
        sys.exit()

print("Yes")
```このソリューションでは、文字に対して Union-Find 構造を構築し、同等であると宣言されたすべてのペアをマージします。 の`normalize`この関数は、各文字をその DSU ルートに置き換えることによって、ログインを正規表現に変換します。 この場合、比較は文字列の完全な等価性になります。 

実装の微妙な詳細は、すべてのシンボルが事前定義された共用体に必ずしも存在するわけではないため、入力に現れるすべての文字が DSU で遅延初期化されるようにすることです。 もう 1 つの重要な点は、ルールがすでに双方向性を暗示している場合でも、和集合演算は対称性を明示的に反映する必要があるということです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    output = []

    class DSU:
        def __init__(self):
            self.parent = {}
            self.rank = {}

        def find(self, x):
            if x not in self.parent:
                self.parent[x] = x
                self.rank[x] = 0
            if self.parent[x] != x:
                self.parent[x] = self.find(self.parent[x])
            return self.parent[x]

        def union(self, a, b):
            ra, rb = self.find(a), self.find(b)
            if ra == rb:
                return
            if self.rank[ra] < self.rank[rb]:
                ra, rb = rb, ra
            self.parent[rb] = ra
            if self.rank[ra] == self.rank[rb]:
                self.rank[ra] += 1

    dsu = DSU()

    for c in "abcdefghijklmnopqrstuvwxyz":
        dsu.union(c, c.upper())
        dsu.union(c.upper(), c)

    dsu.union('O', '0')
    dsu.union('0', 'O')

    dsu.union('1', 'l')
    dsu.union('1', 'I')
    dsu.union('l', 'I')

    def norm(s):
        return ''.join(dsu.find(c) for c in s)

    s = input().strip()
    n = int(input())
    target = norm(s)

    for _ in range(n):
        t = input().strip()
        if norm(t) == target:

    return "Yes"

 ## 特殊なケース

 微妙なエッジケースは、等価性チェーンが複数のステップにまたがる場合です。 たとえば、ある文字が複数の置換によって間接的に接続されている場合、単純なペアごとの比較では関係を見逃してしまいます。 DSU は、推移的な接続を単一のルートに折りたたむことでこれを処理します。 のような入力の場合`l`、 既存`I`、および中間`1`、3 つすべてが同じ代表を共有することになるため、正規化された形式は正確に一致します。 

もう 1 つの特殊なケースは、大文字と小文字の変換と数字の変換を同時に混合することです。 たとえば、両方を含む文字列`O`そして`o`または`0`それでも一貫して解決する必要があります。 大文字と小文字の折り畳みと数字と文字の共用体の両方が同じ構造に適用されるため、最終的な表現は変換順序に関係なく安定します。 

最後に、アンダースコアは等価性のない孤立した記号です。 アルゴリズムはそれらを何かと結合することは決してないので、それらは固定小数点のままであり、アンダースコアだけが異なる文字列が正しく区別されることが保証されます。
