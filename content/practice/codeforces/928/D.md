 ## 解決策

 ## 問題の理解

 小文字、スペース、句読点、改行で構成される全文が与えられます。 Arcady は、テキスト エディターでこのテキストを左から右に入力します。 通常、各文字には 1 回のキー押下が必要であり、目標は、最小限のキー押下でテキスト全体を入力することです。 

エディターには、Arcady が単語を入力しているときにアクティブになる特別な機能があります。 単語は、最大連続した小文字のシーケンスです。 ユーザーが単語内にいて、その単語の空ではない接頭辞をすでに入力している場合、編集者は、その接頭辞がテキスト内にすでに出現しているすべての単語の中から 1 つの単語を一意に識別する場合に限り、前に見た単語へのその接頭辞の自動補完を提案することがあります。 

Arcady が提案を受け入れると、単語の残りの接尾辞全体が即座に挿入され、1 回のクリックが必要になります。 余分なスペースや句読点は挿入されません。 Arcady はキャラクターを削除したり、後戻りしたりすることができないため、すべての決定はローカルであり、取り消しはできません。 

タスクは、オートコンプリートをいつ受け入れるかを最適に選択しながら、テキスト全体を入力するために必要なキーの最小押下回数を計算することです。 

この制約により、最大 300,000 文字が許可されます。 これにより、以前に確認されたすべての単語に対して単語ごとにすべての接頭辞を明示的にシミュレートしようとするソリューションが除外されます。 各接頭辞と過去のすべての単語を単純に比較すると、文字数が二次関数的に変化します。 

一意性条件に微妙な問題が生じます。 オートコンプリートは、以前に出力された 1 つの単語が現在のプレフィックスを共有する場合にのみ使用できます。 これは、単語が存在するかどうかだけでなく、各接頭辞を通過する単語の数を継続的に維持する必要があることを意味します。 

エッジケースは、同一の単語が複数出現する場合に発生します。 たとえば、「code」という単語が 2 回出現する場合、「co」と入力しても、有効な単語と一致しても一意ではないため、オートコンプリートはトリガーされません。 もう 1 つのエッジ ケースは、プレフィックスが複数の単語で共有されているが、1 つの継続のみが関連する場合に後で再び一意になる場合であり、静的なセットではなく動的な追跡が必要になります。 

## アプローチ

 ブルートフォース戦略では、テキストを単語ごとに処理します。 単語ごとに、考えられるすべての接頭辞を試し、その接頭辞が以前に見た単語を一意に決定するかどうかを確認します。 これには、プレフィックス チェックごとに、以前に挿入されたすべての単語をスキャンする必要があります。 最悪の場合、長い単語と多くの繰り返し接頭辞があると、増加する単語セット間で部分文字列の比較が繰り返されるようになり、およそ O (合計文字の 2 乗) 個の動作が発生します。 

重要な観察は、この問題は完全に、挿入された単語の動的セット間の接頭辞の一意性に関するものであるということです。 まさにこれがトライの目的です。 以前に完了した単語をすべてトライに保存すると、各ノードは自然に、通過した単語の数を追跡します。 次に、プレフィックスが一意であるかどうかのチェックは、ノードごとの定数時間プロパティになります。つまり、ノード数がちょうど 1 に等しい場合、プレフィックスは一意です。 

テキストを順番に処理し、完成した単語のトライを維持します。 現在の単語を入力するときに、すでに入力された文字に従ってトライもたどりますが、これは接頭辞が独自の方法でトライに存在する場合に限ります。 どの時点でも、入力を続ける方がコストが安くなるのか、それともオートコンプリートをすぐに受け入れた方がコストを節約できるのかを決定します。 

プレフィックスが一意でなくなると、それ以上のプレフィックス拡張では一意性を復元できないため、この移行は貪欲です。 この単調性により、常に最も早い有益なポイントでオートコンプリートを実行できるようになります。

## アルゴリズムのチュートリアル

 テキストを文字以外の文字で区切られた一連の単語として扱います。 各単語は独立して処理されますが、以前に完了したすべての単語の共有トライを使用します。 

1. 各ノードが通過した単語数のカウンターを格納する空のトライを構築します。 
2. テキストを反復処理して単語を抽出します。 単語を読み終わるたびに、次のように処理します。 
3. 現在の単語について、トライのルートから 1 文字ずつ入力することをシミュレートします。 現在のトライ ノードと単語内の位置を追跡します。 
4. 各キャラクターで、可能であればトライで移動します。 パスが存在しない場合は、以前に見た単語がこの接頭辞を共有しないため、これ以降オートコンプリートは不可能になります。 
5. トラバース中に、ノード数を確認します。 ノードでのカウントがちょうど 1 の場合、現在のプレフィックスが前の単語を一意に識別することを意味するため、オートコンプリートがすぐに使用可能になります。 
6. オートコンプリートが位置 i で利用可能な場合、コストを比較します。 さらに入力すると残りの文字が消費されますが、オートコンプリートの場合は 1 回のクリックが必要です。 有効になるとすぐにオートコンプリートを選択します。 
7. 一意の接頭辞に到達できない場合は、単語全体を手動で入力します。 
8. (入力またはオートコンプリートによって) 単語を終了したら、単語全体をトライに挿入し、そのパスに沿ってカウントを増やします。 

### なぜ効果があるのか

 トライには、各接頭辞を共有する完成した単語の数が正確に保存されます。 したがって、「ちょうど 1 つ前の単語にこのプレフィックスがある」という条件は、「このトライ ノードのカウントは 1 である」と同等です。 プレフィックスが一意になると、それを拡張してもその数を増やすことはできないため、一意性は永続的に持続または消失しますが、失われた後は改善されません。 これにより、遅延は新たな機会を生み出すことなく入力コストが増加するだけであるため、最も早い有効なオートコンプリート位置が最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("next", "cnt")
    def __init__(self):
        self.next = {}
        self.cnt = 0

class Trie:
    def __init__(self):
        self.root = Node()

    def insert(self, word):
        node = self.root
        node.cnt += 1
        for ch in word:
            if ch not in node.next:
                node.next[ch] = Node()
            node = node.next[ch]
            node.cnt += 1

    def traverse_unique_prefix(self, word):
        node = self.root
        for i, ch in enumerate(word):
            if ch not in node.next:
                return len(word)
            node = node.next[ch]
            if node.cnt == 1:
                return i + 1
        return len(word)

def solve():
    text = sys.stdin.read().rstrip("\n")

    trie = Trie()
    i = 0
    n = len(text)
    clicks = 0

    def is_letter(c):
        return 'a' <= c <= 'z'

    while i < n:
        if not is_letter(text[i]):
            clicks += 1
            i += 1
            continue

        j = i
        while j < n and is_letter(text[j]):
            j += 1

        word = text[i:j]

        best = trie.traverse_unique_prefix(word)
        if best == len(word):
            clicks += len(word)
        else:
            clicks += best + 1

        trie.insert(word)
        i = j

    print(clicks)

if __name__ == "__main__":
    solve()
```トライは、子とパススルー カウンターを格納する明示的なノードを使用して実装されます。 挿入により、すべてのプレフィックスに沿ってカウンタが増加します。これにより、一定時間の一意性チェックが可能になります。 

機能`traverse_unique_prefix`現在の単語に従ってトライを歩きます。 接頭辞が前の単語の中で一意に識別される最も古い位置を返します。 そのような点が存在しない場合は、全長を返します。 

メインループでは、単語を文字以外の文字から分離します。 すべての区切り文字には、すぐに 1 回のクリックがかかります。 単語の場合、入力とオートコンプリートの間で可能な限り最適な分割を計算し、それに応じて総コストを更新します。 

よくある実装の落とし穴は、オートコンプリートが単語の残りの部分を完全に置き換えることを忘れていることです。つまり、残りの文字ごとに 1 回ずつではなく、接頭辞の後に正確に 1 回のクリックを追加する必要があります。

 ## 特殊なケース

 重要なエッジケースは、同じ単語が繰り返されることです。 入力「a a a」の場合、最初の挿入後にすべてのプレフィックスのトライ数が 1 より大きくなるため、オートコンプリートは不可能になります。 トライは各ノードでカウントを正しく保持し、一意性が誤って現れることがないことを保証します。 

もう 1 つのケースは、単語が前の単語と接頭辞の一部のみを共有しているものの、早い段階で分岐している場合です。 たとえば、「code」と「coder」によりプレフィックス「code」は非一意になりますが、分岐後もより深いノードには依然として正しいカウントが反映されます。 このアルゴリズムにより、すべての深さで一意性がチェックされるため、オートコンプリートが誤って早すぎるタイミングでトリガーされることはありません。 

最後の微妙なケースは、単語の直後の句読点です。 区切り文字は常に 1 回のクリックで済み、トライ ロジックと相互作用しないため、セグメンテーションにより、誤って境界を越えて単語を結合することがなくなります。
