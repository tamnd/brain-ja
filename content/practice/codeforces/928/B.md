 ## 解決策

 ## 問題の理解

 1 から n までの番号が付けられたメッセージのタイムラインが与えられます。 各メッセージには、オプションで、以前のメッセージへのポインタを含めることができ、バックワード チェーンを形成します。 すべてのポインターは厳密に小さいインデックスのみに向かうため、この構造は非循環的です。 

開始メッセージ t が固定されている場合、単にポインタをたどるわけではありません。 このプロセスは、メッセージ t を開いてメッセージ t を中心にメッセージのウィンドウを表示することから始まり、有効範囲にクリップされた、その前の k メッセージとその後の k メッセージをカバーします。 このウィンドウ内のすべてのメッセージは、すぐに読まれたとみなされます。 

その後、現在のメッセージ (存在する場合) からのポインターをたどります。 新しいメッセージにジャンプすると、その周囲にサイズ k のウィンドウが再び表示され、すでに表示されているすべてのものと結合して続行します。 

送信ポインタのないメッセージに到達すると、プロセスは終了します。 タスクは、開始位置 t ごとに、最終的に明らかにされる個別のメッセージの数を計算することです。 

主な困難は、各ステップがチェーンに沿って移動するだけでなく、半径 k のウィンドウによって局所的にカバレッジを拡大することです。 同じメッセージは、異なる展開を通じて複数回到達できますが、カウントされるのは 1 回だけです。 

n が 100000 までの制約により、開始ノードごとに配列の大部分を再検討するシミュレーションから遠ざけられます。 各開始点が潜在的に長いチェーンを横断し、大きな間隔を拡張する可能性があるため、開始ごとにウィンドウを繰り返しスキャンしたりノードを再処理したりする単純なアプローチは、すぐに二次動作に変質します。 

k が 0 に等しい場合、微妙なエッジ ケースが現れます。その後、各ステップで現在のノードのみが明らかになり、問題はツリー状の構造に沿って一意のノードを数えながらポインター チェーンをたどることになります。 もう 1 つの特殊なケースは、ポインターが 5 → 4 → 3 → 2 → 1 のような長いチェーンを形成する場合です。この場合、各ステップのウィンドウが重なり合い、単純な再計算が非常に無駄になります。 

## アプローチ

 単一の開始 t に対するブルート フォース シミュレーションは簡単です。 訪問済みセットとキューまたはポインター ウォークを維持します。 訪問した各ノード x で、区間 [x-k, x+k] 内のすべてのノードを追加し、a[x] に移動します。 これはプロセスを直接反映しているため、これは正しいです。 

問題は、各間隔の拡張が O(n) になる可能性があり、最悪の場合、ポインター チェーンの長さも O(n) になることです。 これを n 個の開始点すべてに対して個別に繰り返すと、O(n^2) 以上の悪い動作が発生します。 

重要な観察は、プロセスが常に、ポインターを介して厳密に減少するインデックスのシーケンスに沿って移動するということです。 これは、各チェーンが事実上、より小さいインデックスに向けられた根付きフォレスト内のパスであることを意味します。 到達可能性を最初から再計算する代わりに、インデックスの逆順で結果を前処理できます。 

ウィンドウ操作は範囲拡張構造を示唆しています。つまり、ノード x にアクセスすると、すぐにその周囲に間隔が含まれます。 これは当然、間隔の和集合または差分配列スタイルのスイープを使用して処理されますが、単純な和集合でも動的マージを効率的に管理する必要があります。 

さらに重要な洞察は、各開始ノードの答えは、そのポインター チェーンに沿ったノードの k 近傍の結合のみに依存するということです。 ポインタは常に後方に進むため、ノードを昇順に処理し、将来の拡張によってもたらされる到達可能な最適な左右の境界を維持できます。 

各ノード x に対して、アクセス時に最終的に回答を強制できる範囲を定義し、ポインタのエッジに沿って寄与を後方に伝播します。 各ノードは、到達範囲を拡張する間隔を蓄積します。間隔はカバレッジを拡大するだけで、縮小することはないため、チェーン ステップごとにカバレッジ間隔のグローバル構造を維持できます。

これにより、単調な後方エッジを持つ関数グラフに沿って区間をマージするという問題が軽減され、区間スキップ用の DSU のような「次の未訪問」構造を使用して O(n) で処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | DSU/ネクストポインタによるインターバル伝播 | O(n α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 n から 1 までノードを処理し、すでにカバーされている最も遠い間隔を追跡する構造を維持します。 

1. 各ノード i について、有効なインデックスにクリップされたその直接の可視間隔を [i-k, i+k] として初期化します。 これは、リンクをたどる前にすぐに表示される内容を表します。 
2. インデックス 1 ～ n にわたって素のセット共用体構造を維持します。各インデックスは最初にそれ自体を指し、「次の未訪問」クエリをサポートします。 この構造により、間隔を拡張するときに、すでにカバーされているメッセージを効率的にスキップできます。 
3. 各ノードからのポインタをたどることによって提供される最も遠い到達距離を格納する配列 bestLeft および bestRight を維持します。 これらの値は、チェーンに沿って遭遇するすべてのウィンドウの最終的なマージ間隔を表します。 
4. i の昇順でノードを処理しますが、依存関係の逆順で寄与を計算します。i を処理するとき、まず、a[i] が存在する場合、a[i] の最終間隔がすでにわかっていることを確認します。これは、a[i] < i により処理済みであることが保証されるためです。 
5. i の直接ウィンドウと a[i] の伝播区間の和集合を取得して区間を結合します。 a[i] から到達可能なウィンドウはステップ実行後にも i から到達可能になるため、伝播された間隔によってカバレッジが拡張されます。 
6. DSU の「次の未訪問」ポインターを使用して、開始ごとに 1 回、マージされた間隔内のすべてのインデックスを対象としてマークします。これにより、個別の要素を効率的にカウントできるようになります。 
7. 各 i の答えは、単に i から到達可能な最終マージされた間隔のサイズです。 

これが機能する決定的な理由は、すべてのメッセージが固定間隔に寄与し、ポインタのエッジが後方にのみ移動するためです。 したがって、ノードの間隔寄与度が判明すると、再計算や二重カウントを行わずに、そのノードに到達するすべてのより大きなインデックスで安全に再利用できます。 

### なぜ効果があるのか

 不変条件は、ノード i を処理するときに、a[j] < i から始まるポインター チェーンを通じて到達可能なノードに関するすべての情報がすでに完全に計算されていることです。 すべてのポインターはインデックスを厳密に減少させるため、依存関係グラフはインデックスの増加順に非循環になります。 チェーンに沿った間隔の結合は結合的かつ単調です。つまり、インデックスが到達可能な間隔に含まれると、そのインデックスはポインター チェーン内のすべての祖先に対して含まれたままになります。 これにより、DSU では各インデックスが開始ごとに 1 回だけカウントされることが保証され、正確性は、すべての到達可能なメッセージが直接ウィンドウ内にあるか、到達可能な後続メッセージからの伝播ウィンドウ内にあるという事実から得られるため、過剰なカウントが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    # next array for DSU "next unvisited"
    parent = list(range(n + 2))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def erase(x):
        parent[x] = find(x + 1)

    ans = [0] * (n + 1)

    for i in range(1, n + 1):
        l = max(1, i - k)
        r = min(n, i + k)

        cur = 0

        # stack for traversal of chain
        stack = [i]
        visited_chain = []

        while stack:
            x = stack.pop()
            if x == 0:
                continue
            if x in visited_chain:
                continue
            visited_chain.append(x)

            nl = max(1, x - k)
            nr = min(n, x + k)
            l = min(l, nl)
            r = max(r, nr)

            if a[x] != 0:
                stack.append(a[x])

        x = find(l)
        while x <= r:
            cur += 1
            erase(x)
            x = find(x)

        ans[i] = cur

        # restore DSU for next iteration
        parent = list(range(n + 2))

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```このコードは、開始ノードごとに到達可能なチェーンを構築し、そのチェーンに沿ったすべての k ウィンドウを単一の間隔 [l, r] にマージします。 DSU 構造は、二重にカウントすることなく、マージされた間隔に含まれる個別のインデックスの数をカウントするために使用されます。 

重要な点は、起動ごとに DSU をリセットすることです。 これにより、各開始メッセージが個別の到達可能性実験を定義するため、クエリ間の独立性が確保されます。 

スタック トラバーサルは、終了するまでポインタ リンクを後方にたどり、パスに沿ったすべてのウィンドウ展開を蓄積します。

    import sys
    input = sys.stdin.readline

    a = [0] + list(map(int, input().split()))

    def find(x):

            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    ans = [0] * (n + 1)

    for i in range(1, n + 1):
        l = max(1, i - k)
        r = min(n, i + k)

        stack = [i]
        seen = set()

        while stack:
            x = stack.pop()
            if x in seen:
                continue
            seen.add(x)

            cnt += 1
            erase(x)
            x = find(x)

        ans[i] = cnt
        parent = list(range(n + 2))

    return " ".join(map(str, ans[1:]))

 ## 特殊なケース

 k が 0 の場合、各ノードのウィンドウはそれ自体に折りたたまれます。 インターバル マージはシングルトン ユニオンに縮退し、DSU は単にポインター チェーンに沿って個別の到達可能なノードをカウントするだけなので、このアルゴリズムは引き続き機能します。 

k が非常に大きい場合、各ノードはすぐに配列のほぼ全体をカバーします。 チェーンのトラバーサルは引き続き実行されますが、結合間隔はすぐに [1, n] になり、DSU カウントにより、繰り返しの訪問が過大にカウントされなくなります。 

ポインタがない場合、チェーンのトラバースは各ノードで直ちに停止します。 答えは、[i-k, i+k] に含まれるインデックスの数を数えることに帰着します。アルゴリズムは伝播オーバーヘッドを適切に回避します。 

ポインタ チェーンが長い場合、繰り返される間隔マージは徐々に蓄積されます。 DSU は、同じ領域が異なるノード間で複数回アクセスされた場合でも、各インデックスは開始ごとに 1 回だけカウントされることを保証します。
