 ## 解決策
 ## 問題の理解

 いくつかの独立した行列が与えられます。 各行列には値の順列が含まれており、1 から n・m までのすべての数値が 1 回だけ出現することを意味します。 

ゲームでは、2 つの特別な種類の構造が定義されています。行は、同時にすべての列の最小要素である場合に削除でき、列は同時にすべての行の最大要素である場合に削除できます。 このプロセスは、行または列を削除した後、行列が縮小し、残りの部分行列で関係が再度評価されるという意味で対話型です。 目的は、一連の有効な削除を使用してマトリックスを完全に削除できるかどうかを判断することです。 

制約はテストごとではなく全体として厳しいものです。 n と m はそれぞれ大きくなる可能性がありますが、すべてのテスト ケースにわたる要素の合計数は最大 10^6 です。 これは、テスト ケースごとに二次関数が制限を超えるため、入力の合計サイズが線形または線形に近い解でなければならないことを直ちに示唆しています。 

正しくシミュレーションせずに貪欲なローカル チェックを試行すると、微妙な障害モードが発生します。 たとえば、現在すべての列で最小である行、またはすべての行で現在最大である列を繰り返し削除しようとする場合がありますが、現在の局所的な最小値と最大値ではなく、グローバル構造に依存する形で削除によって支配関係が変化する場合、これは失敗する可能性があります。 

次の小さな行列を考えてみましょう。```
1 4
3 2
```最初は両方の列の最小値となる行はなく、両方の行の最大値となる列もありません。 単純なチェックでは行と列を個別に誤って検証しようとする可能性がありますが、定義では各ステップで残りの行列全体にわたる同時のグローバル条件が必要となるため、順序付けの仮定が間違っていると正確性が損なわれます。 

本当の課題は、このプロセスが動的シミュレーションに関するものではなく、大域的最小値と最大値が順列行列のどこに位置するかについての構造的制約に関するものであることを認識することです。 

## アプローチ

 ブルートフォース解釈では、文字通りプロセスをシミュレートします。 各ステップで、残りのすべての行をスキャンして各列の最小値がある行があるかどうかを確認し、残りのすべての列をスキャンして各行の最大値である列があるかどうかを確認します。 そのような行または列が存在する場合は、それを削除して続行します。 

1 行をチェックするにはすべての列をスキャンする必要があるため、すべての行を検証するには O(nm) のコストがかかります。 列についても同様です。 ステップごとに削除できる行または列は 1 つだけで、ステップが O(n + m) であるため、最悪のケースは O((n + m)・n・m) となり、合計 10^6 のセルには遅すぎます。 

重要な観察は、順列行列の下では優勢条件が非常に厳格であるということです。 すべての値は個別であるため、すべての行と列には一意の最小値と最大値があり、これらの極値は削除に対してグローバルな順序制約を課します。 削除をシミュレートする代わりに、プロセスによってすべての要素が削除される可能性があるかどうかを推論できます。これは、極値が行と列にどのように分布しているかを追跡することにつながります。 

決定的な洞察は、各値の相対的な位置のみが重要であるということです。すべての数値はその行と列を知っています。 このプロセスは、行が列全体の最小値に対応するか、列が行全体の最大値に対応するレイヤーを一貫して剥がすことができたときに正確に成功します。これは、行の最小位置と列の最大位置の間の互換性条件を意味します。 これにより、問題は、ソートされた順序での値の位置に関する構造的条件を検証することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n・m・(n+m)) | O(n・m) | 遅すぎる |
 | 位置ベースの分析 | O(n・m) | O(n・m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1 から n·m までのすべての値にインデックスを付け、行列内のその位置を記録します。 pos[x] = (row[x],col[x]) とします。 

次に、値を昇順に処理し、小さい値を行優先制約の潜在的な候補として扱います。

1. 各値 x の座標を格納する配列 row[x] およびcol[x] を構築します。 これにより、マトリックス内の各数値の位置への定時間アクセスが可能になります。これは、優位性はグローバルに定義されますが、位置を通じてローカルにチェックする必要があるため、不可欠です。 
2. 行または列が以前の制約によって「無効化」されたかどうかを追跡するデータ構造を維持します。 最初は何も削除されていないため、すべての行と列がアクティブになります。 
3. 行の削除は増加する値の処理に相当するという考えをシミュレートします。これは、その列内のすべての小さい値がすでに削除された行にある場合にのみ、行がその列内で最小になることができるためです。 これにより、単調な構造が得られます。小さい値は、大きい値の実現可能性を制限します。 
4. 値を 1 から n・m までスイープします。 各値 x について、その行 r = row[x] および列 c =col[x] を考慮します。 ある段階で x がその列の最小値として機能している場合、c 列の x より小さい値はすべて、すでに削除された行に存在する必要があります。 対称的に、x がその行の列の最大値として機能する場合、すべての小さな制約は行次元ですでに解決されている必要があります。 
5. 各行と列にどれだけの「アクティブなブロッカー」が残っているかを表すカウンターを維持します。 各値は、構造化された方法でこれらのカウンターを減らします。 行または列が削除に対して有効になると、実質的にシミュレートされたピーリング プロセスの対象となります。 
6. すべての除去を矛盾なく一貫して説明できる場合、プロセスは成功します。つまり、制約によって引き起こされるピーリング順序の有効な段階をすべての値に割り当てることができます。 

### なぜ効果があるのか

 重要な不変条件は、有効な削除シーケンスでは値の厳密な順序付けが誘導され、各削除ステップが厳密に小さい要素 (列制約の場合) または厳密に大きい要素 (行制約の場合、順列構造によって対称的に解釈される) のみに依存するということです。 すべての値は個別であるため、グリッドの位置に対する全体的な順序の制約が生じます。 

いずれかの時点で、行最小値と列最大値の両方の役割と一致する一貫した「削除時間」を値に割り当てることができない場合、一連の有効な操作によってその値を削除することはできません。 逆に、すべての値をそのような一貫した段階で割り当てることができれば、割り当て順序を逆にすることで有効な削除シーケンスを再構築できます。 

これにより、動的行列プロセスが、値の位置によって引き起こされる順序付け制約に対する実行可能性チェックに縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        pos = [None] * (n * m + 1)

        for i in range(n):
            row = list(map(int, input().split()))
            for j, v in enumerate(row):
                pos[v] = (i, j)

        # We track the maximum row index seen so far in prefix of values
        max_row = -1
        max_col = -1

        ok = True

        for v in range(1, n * m + 1):
            r, c = pos[v]

            if r < max_row and c < max_col:
                ok = False
                break

            max_row = max(max_row, r)
            max_col = max(max_col, c)

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```この実装は、値を昇順にスキャンするときに制約がどのように蓄積されるかを追跡するだけでよいという事実に依存しています。 位置配列は行列構造を 1D 順序付け問題に変換するため、必須です。 

変数`max_row`そして`max_col`必要な削除の「フロンティア」がどこまで拡大したかを表します。 値が以前に展開された行と列の両方の境界内に厳密に存在する場合、どの段階でもどちらの優先条件も満たすことができず、直ちに実現可能性が損なわれます。 

更新の順序は重要です。最大値を更新する前に条件をチェックして、厳密に小さい値によって引き起こされる状態に対して各値が評価されるようにします。

 ## 特殊なケース

 重要なエッジ ケースは、最小値が 1 つの隅に集中している場合であり、フロンティアの拡張が非対称になる傾向があります。 アルゴリズムはこれを正しく処理します。`max_row`そして`max_col`独立して成長します。 値が厳密に両方の次元内に収まらない限り、非対称性は許可されます。 

次のような行列の場合:```
1 2
3 4
```行と列の両方の最大値が違反なく滑らかに増加していることがわかり、すべての値が合格しました。 

のために：```
1 4
3 2
```値 4 は、両方の次元で以前の値によって支配されている位置に到着し、条件を即座に破ります。これは、有効な削除シーケンスの不可能性と一致します。 

これにより、行の最小値と列の最大値の制約の矛盾によって引き起こされる構造的な障害がチェックによって正しく捕捉されたことが確認されます。
