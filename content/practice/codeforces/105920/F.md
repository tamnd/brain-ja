 ## 解決策
 ## 問題の理解

 私たちは、各「サイクル」がレアなイベントを取得するまで描画し、その後リセットするというランダムな繰り返しプロセスをモデル化しています。 各抽選には 6 つ星の結果が出る確率がありますが、この確率は固定されていません。 これは、ある基本レートで開始され、現在のサイクルで失敗した試行のしきい値に達した後、確実に達するまで直線的に増加します。 

具体的には、最後に星6を獲得した後、再び引き始めます。 新しいサイクルの最初の数回のプルは、すべて同じ成功確率をパーセントで共有します。 c 回連続して引いて 6 スターを獲得できなかった場合、次の引きから開始して、c を超えて失敗するたびに成功確率が b パーセントずつ増加し、上限は 100 パーセントになります。 成功するとすぐにプロセスがリセットされ、基本確率で再び開始されます。 

タスクは、2 つの連続した成功の間の予想されるプル数、つまり 1 つのそのようなサイクルの予想される長さを計算することです。 

制約は小さく、a、b、c はすべて最大 100 で、テスト ケースの数は最大 1000 です。 これは、最大数百の状態にわたる一定サイズのステート マシンまたは直接期待値 DP を含むあらゆる解決策が実現可能であることを直ちに示唆しています。 テスト ケースごとに 2 次関数以上のものは原則として許容されますが、無制限の時間にわたるシミュレーションや、テスト ケースごとに多くのステップにわたる反復収束を伴うものは危険です。 

主なエッジケースの構造は、極端な確率から生まれます。 a が 100 の場合、すべてのプルは即座に成功するため、答えは自明に 1 になります。 a が非常に小さく、c が大きい場合、プロセスは、残念ランプが開始される前に平坦確率フェーズで長い時間を費やす可能性があります。 もう 1 つの微妙なケースは、b が十分に大きく、c の前または直後に確率が 100 に達し、事実上尾部が切り捨てられる場合です。 

単純な間違いは、プロセスを直接シミュレートすることです。 各サイクルの期待値は短いにもかかわらず、稀にロングテールが発生するとモンテカルロが不安定になり、厳密な精度保証内での収束が遅くなります。 

## アプローチ

 期待値について考える強引な方法は、1 サイクルのプロセスを繰り返しシミュレートすることです。 失敗ゼロから開始し、その確率が現在の一連の失敗に依存するベルヌーイ試行を繰り返しサンプリングし、成功したときに停止します。 これを何度も繰り返して平均することで、期待値の推定値が得られます。 

これは概念的には正しいですが、精度が保証された決定的な答えは得られません。 ある程度大きな深さでシミュレーションを切り詰めて期待値を計算しようとしても、a が小さい場合、裾の確率は無視できず、増加率メカニズムにより収束が大幅に遅れる可能性があります。 中心的な問題は、プロセスの長さが原則的に無制限であることです。 

重要な観察は、確率が 100% になるまで「最後の成功以降の失敗回数」を追跡すると、システムには有限数の異なる状態しか存在しないということです。 成功するとすべてがリセットされるため、マルコフ連鎖で吸収されるまでの予測ヒット時間を計算するだけで済みます。 

各状態は失敗カウント i に対応します。i の範囲は 0 から始まります。 各 i について、成功確率 p(i) がわかります。 状態 i からは、成功して終了するか、失敗して i + 1 に移動します。これは標準的な期待の繰り返しです。 

E[i] = 1 + (1 - p(i)) * E[i + 1]

 そして、成功が確実になるため、p(last) = 1 の場合、終了条件は E[last] = 1 になります。 

確率が 100% に達するとチェーンの拡張を停止するため、状態の数には制限があります。 a、b、c ≤ 100 であるため、確率は c を超えて最大約 100 ステップ後に決定的になります。 したがって、州の数を数百に制限しても問題ありません。 

解決策は、最後の状態から逆方向に有限線形再帰を計算することになります。

 ## アルゴリズムのチュートリアル

 最後の 6 つ星以降の連続失敗の数によって州のインデックスを作成します。 

1. 各失敗回数 i の成功確率を計算します。 i ≤ c の場合、確率は c を超えた後でのみ、a + 0・b、a + 1・b などとなります。 実際には、p(i) = min(100, a + max(0, i - c) * b) と定義します。 これにより、同情ルールが状態に関する決定論的な関数に変換されます。 
2. p(L) が 100 になるカットオフ インデックス L を決定します。その状態以降、次のプルは常に成功するため、E[L] = 1 となります。 
3. 配列 E を初期化します。ここで、E[i] は、障害状態 i から開始して必要となる予想されるプル数を表します。 
4. 漸化式 E[i] = 1 + (1 - p(i)) * E[i + 1] / 100 を使用して、L - 1 から 0 まで配列を逆方向に埋めます。100 による除算は、パーセンテージ確率を実数確率に変換することで行われます。 
5. 出力 E[0]。これは、成功直後に開始される予想されるプル数です。 

逆方向 DP が機能する理由は、各状態が次の状態にのみ依存するためです。 以前の状態への分岐がないため、E[i + 1] が判明すると、E[i] は直接計算になります。 

### なぜ効果があるのか

 このプロセスは 1 次元の吸収マルコフ連鎖であり、状態 i は i + 1 (失敗) または吸収 (成功) にのみ遷移します。 すべてのパスは最終的に成功するか、確率 1 の状態に到達し、終了が保証されます。 漸化式は、最初のステップに条件付けられた完全期待の法則を正確にエンコードしています。 すべての依存関係は i 内で前方に進むため、後方計算によりシステムの一意の固定点が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b, c = map(int, input().split())

        # build probabilities until they reach 100
        p = []
        i = 0
        while True:
            if i <= c:
                val = a
            else:
                val = a + (i - c) * b

            if val >= 100:
                p.append(1.0)
                break

            p.append(val / 100.0)
            i += 1

        n = len(p)
        E = [0.0] * n

        # terminal state: guaranteed success
        E[n - 1] = 1.0

        for i in range(n - 2, -1, -1):
            E[i] = 1.0 + (1.0 - p[i]) * E[i + 1]

        print(E[0])

if __name__ == "__main__":
    solve()
```実装では、吸収境界として機能する確実性に達するまで確率シーケンスを構築します。 これにより、状態数の明示的な上限についての推論が回避されます。 

逆方向 DP は再帰を直接変換したものです。 重要な点は、確率が [0, 1] 浮動小数点数に正規化されていることと、常に即座に成功するため、最終状態が正確に 1.0 の予想ステップに設定されていることです。

 ## 特殊なケース

 a が 100 の場合、吸収状態は i = 0 ですぐに到達します。DP 配列には p(0) = 1 の単一状態が含まれるため、E[0] は直接 1 に設定されます。これにより、ゼロによる除算や不要な遷移が防止されます。 

a が非常に小さく、c が大きい場合、同情が発動する前に多くの状態が蓄積されます。 各 E[i] は E[i + 1] のみに依存し、近似は導入されないため、DP はこれを正しく処理します。 

b が十分に大きいため、p(i) が c に到達する前に 100 にジャンプする場合、チェーンは早期に終了します。 構築ループは val ≥ 100 になるとすぐに停止し、不必要な状態が割り当てられず、最終条件が正確であることが保証されます。
