 ## 問題の理解

 以下の整数に対して範囲式を評価するように求められます。$l$に$r$。 それぞれの番号について$x$この間隔で、次のビットごとの XOR を計算します。$x$固定整数で$y$、結果を値として解釈し、それらの結果を範囲全体にわたって集計します。 最後に、全体の合計が係数でスケールされます。$k$および縮小モジュロ$10^9 + 7$。 

問題を直接読むと、次の形式の関数を計算する必要があるということになります。$$\sum_{x=l}^{r} f(x \oplus y)$$どこ$f(t)$単純に$t$、最終的な答えは次のように乗算されます。$k$。 したがって、中心となるタスクは実際には、広い範囲にわたる XOR 値の合計と、線形スケーリングです。 

制約により、その間隔での反復が即座に除外されます。 範囲は次のように大きくなります。$10^9$、それぞれを処理するあらゆるアプローチを意味します。$x$独立して必要となるのは、$10^9$2.5 秒の制限をはるかに超えた操作。 平$O(r-l)$テストごとには不可能です。 

重要な構造は、XOR がビット単位であり、ビットごとに独立して動作するということです。これは、合計を整数ごとに計算するのではなく、ビット全体に分解できることを示唆しています。 

ここでよく見られる単純な間違いは、各 XOR 値を計算して直接合計することです。 たとえば、$l=1, r=10, y=1$、明示的に次のように計算することもできます。$$(1 \oplus 1) + (2 \oplus 1) + \cdots + (10 \oplus 1)$$これは小さな入力には問題ありませんが、ビットがどのように独立して寄与するかという構造を無視するため、大規模な場合はすぐに壊れます。 

ビット寄与を慎重に処理せずに XOR のプレフィックス合計を使用しようとすると、別の微妙な失敗ケースが発生します。 XOR は順序を保持しないため、範囲にわたる算術加算のように扱うと、少しずつ分解しない限り、誤った集計が発生します。

重要な観察は、XOR が各ビットに対して独立して動作するということです。 固定ビット位置に注目すると$i$、最終的な合計に対するそのビットの寄与は、$i$-番目のビット$x$そして$y$異なる。 それらが異なる場合、ビットが寄与します$2^i$結果に対して。 それ以外の場合は寄与はゼロになります。 これにより、問題は、$y$。 

数値を反復処理する代わりに、接頭辞関数を計算します。$F(n)$、の合計$x \oplus y$みんなのために$x \le n$、バイナリ表現上で数字 DP を使用します。 最終的な答えは次のようになります。$$k \cdot (F(r) - F(l-1)) \bmod (10^9+7)$$DP は数値を最上位ビットからビットごとに処理します。 各ステップで、現在のサブツリーに有効な数値がいくつ存在するか、およびそれらの XOR 寄与が何であるかを追跡し、ビットが固定されるにつれて寄与を累積します。

## アルゴリズムのチュートリアル

 関数を計算します$F(n)$の合計を求めます。$x \oplus y$全体$0 \le x \le n$。 これがわかったら、答えは次のとおりです。$k \cdot (F(r) - F(l-1))$。 

### ステップ

 1.変換$n$そして$y$最上位ビットまでのバイナリ配列に変換します (最大の制約の場合は約 30 ビット)$10^9$）。 
2. 数字の DP 状態を次のように定義します。$(pos, tight)$、 どこ$pos$は現在決定中の部分であり、$tight$プレフィックスが$x$はすでに次のプレフィックスと等しくなります$n$。 これにより、決して超過しないことが保証されます$n$。 
3. 各状態について、この状態からの有効な完了の数と、それらすべての完了からの XOR 寄与の合計という 2 つの値を計算します。 両方を追跡する理由は、上位ビットが下位ビットに乗算的に影響を与えるため、寄与を正しくスケールするにはカウントが必要になるためです。 
4. 各ビット位置で、割り当てを試みます。$x_{pos} = 0$そして$x_{pos} = 1$、厳しい制約を尊重します。 選択肢ごとに、次の式で XOR ビットを決定します。$y_{pos}$。 XOR 結果ビットが 1 の場合、寄与します。$2^{pos}$すべての有効な継続の最終合計に加算されます。 
5. 子ステートからの結果を結合します。合計合計は、子の合計に現在のビットの寄与を加え、その分岐の下で有効な完了の数を乗算したものになります。 
6. 状態をメモ化してそれぞれの状態を確認する$(pos, tight)$ペアは 1 回計算されます。 
7. コンピューティング$F(r)$そして$F(l-1)$、その差を計算し、乗算します。$k$、モジュロ演算を適用します。 

### なぜ効果があるのか

 正確さは、XOR がビットごとに分離可能であり、各数値が各ビット位置で独立して寄与するという事実に基づいています。 DP は、すべての有効な$x$範囲内の値は 1 回だけカウントされ、それぞれについて$x$、その XOR 寄与は、次の正しい重み付けでビットごとに再構築されます。$2^i$。 完了数を使用して寄与度を集計するため、ビット間の依存関係が失われることはなく、二重カウントは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve(n, y):
    bin_n = list(map(int, bin(n)[2:]))[::-1]
    bin_y = list(map(int, bin(y)[2:]))[::-1]
    L = max(len(bin_n), len(bin_y))
    bin_n += [0] * (L - len(bin_n))
    bin_y += [0] * (L - len(bin_y))

    from functools import lru_cache

    @lru_cache(None)
    def dp(pos, tight):
        if pos == -1:
            return (1, 0)

        limit = bin_n[pos] if tight else 1

        total_cnt = 0
        total_sum = 0

        for xb in (0, 1):
            if xb > limit:
                continue
            ntight = tight and (xb == limit)

            cnt, sm = dp(pos - 1, ntight)

            yb = bin_y[pos]
            xor_bit = xb ^ yb

            total_cnt += cnt
            total_sum += sm + cnt * xor_bit * (1 << pos)

        return (total_cnt, total_sum % MOD)

    return dp(L - 1, True)[1] % MOD

l, r, y, k = map(int, input().split())

def F(x):
    if x < 0:
        return 0
    return solve(x, y)

ans = (F(r) - F(l - 1)) % MOD
ans = ans * (k % MOD) % MOD
print(ans)
```このコードは、バイナリ表現上で数字 DP を実装します。 DP 状態は、有効なプレフィックスがいくつ存在するかを追跡し、各ビットが独立して寄与するという観察を使用して XOR 寄与を蓄積します。$2^i$そのビットの XOR が 1 の場合。 

の`tight`フラグは上限を超えないことを保証します$n$。 再帰では、最下位ビットから上に向かって答えが構築されますが、ビット位置によって重み付けされた寄与が格納されます。 最終的なスケーリング$k$範囲の合計を計算した後に適用されます。 

## 実用的な例

 検討してください$l=1, r=5, y=1, k=2$。 XOR 値を計算します。 

| × | x ⊕ y | 貢献 |

 | 2 | 3 | 3 |

 | 4 | 5 | 5 |
 | 5 | 4 | 4 |

 それで$F(5) = 14$、$F(0)=0$、そして最終的な答えは$2 \cdot 14 = 28$。

これらのトレースは、DP が明示的な XOR 計算と同じビット単位の寄与を効果的に再構築していることを確認しますが、それぞれを列挙する必要はありません。$x$。

 ## 特殊なケース

 いつ$l = r$の場合、アルゴリズムは次の 1 つの評価に減ります。$x \oplus y$、DP はバイナリ ツリー内の 1 つのパスを正確にカウントし、正しい寄与を生成します。 

いつ$y = 0$、XOR が恒等になるため、DP は効率的に計算します。$\sum x$。 各ビットが寄与するため、ビット単位の寄与ロジックは引き続き機能します。$2^i$ビットが設定された時点で、算術和分解と一致します。 

いつ$l = 1$、接頭辞の減算には計算が必要です$F(0)$。 DP ハンドル$n = 0$ゼロ構成のみが有効であり、すべての寄与が消えて、減算のクリーンな基本ケースが得られるため、正しくなります。
