 ## 解決策
 ## 問題の理解

 左括弧と右括弧のみで構成される文字列が与えられます。 すべてのクエリについて、この文字列内の固定間隔を調べ、その間隔内に完全に含まれる異なる部分文字列がいくつあるかを数えて、正しいブラケット シーケンスを形成します。 各部分文字列は開始位置と終了位置によって識別されるため、2 つの部分文字列に同一の文字が含まれている場合でも、位置が異なる場合は別々にカウントされます。 

ここでの正しい括弧シーケンスは、標準的な帰納的定義に従います。つまり、空の構造は有効であり、「()」も有効であり、有効なシーケンスを括弧で囲むと有効なままであり、2 つの有効なシーケンスを連結すると、有効なシーケンスも生成されます。 実際には、これはバランスの取れた括弧文字列とまったく同じです。 

この制約により、最大 2・10^5 文字と 2・10^5 クエリが許可されます。 クエリごとにすべての部分文字列を明示的にチェックしようとするソリューションでは、各クエリ内で 2 次またはそれ以上の作業が必要になり、すぐに時間制限を超えてしまいます。 すべての部分文字列をグローバルにチェックするソリューションでも、O(n^2) 個の部分文字列があるため大きすぎます。 

単純なアプローチでは、各クエリ範囲内のエンドポイントのすべてのペアを考慮し、スタックまたはプレフィックスのバランスを使用して部分文字列のバランスが取れているかどうかを検証します。 これにより、部分文字列ごとに O(n) チェックが行われることになり、最悪の場合、クエリごとに O(n^3) が得られますが、これは不可能です。 

微妙に間違っているアプローチは、文字列全体にわたってすべての有効な部分文字列を事前計算し、クエリ範囲によってそれらをフィルタリングしようとすることです。 問題は、有効性が間隔内の最小プレフィックスバランスに依存するため、ローカルウィンドウでのカウント方法によっては、グローバルに有効な部分文字列が制限された場合には無効になる可能性があること、またはその逆の可能性があることです。 範囲制限とバランス条件の間の相互作用により、単純なグローバル カウントが妨げられます。 

正しい解決策は、かっこのプレフィックス構造とエンドポイントにわたる効率的な範囲カウントを組み合わせる必要があります。 

## アプローチ

 ブルートフォース戦略は単純です。 各クエリについて、範囲内のすべての可能な開始インデックスを列挙し、次にそれぞれをすべての可能な終了インデックスまで拡張し、部分文字列が正しいブラケット シーケンスであるかどうかをテストします。 正確性チェックは、ランニングバランスまたはスタックスキャンで実行できます。 これは定義を直接検証するため正確性を保証しますが、クエリごとに O(length^2) 個の部分文字列チェックを実行し、各チェックに O(length) のコストがかかるため、最悪の場合は O(n^3) になります。 

この問題を扱いやすくする重要な構造は、括弧部分文字列の正確性がプレフィックスの合計に関して書き換えられることです。 '(' が +1 を追加し、')' が -1 を追加するバランス配列を定義する場合、合計バランスの差がゼロであり、セグメント内の最小プレフィックス値が開始レベルを下回らない場合、部分文字列 i..j は有効です。 これにより、問題は、等価性と範囲の最小値に関する制約を持つプレフィックス インデックスのペアをカウントすることに変換されます。 

問題は、最小条件がセグメント全体にわたってグローバルであることですが、単調スタックを使用してプレフィックスの合計が「壊れる」場所を追跡することで処理できます。 これにより、各位置に、それを超えるとエンドポイントとして有効な部分文字列に参加できない自然な境界を割り当てることができます。 

これらの境界が判明すると、有効な各部分文字列はプレフィックス合計レベル間の構造化された相互作用に対応し、エンドポイントをスイープしながらアクティブ スタート上でフェンウィック ツリーまたはセグメント ツリーを使用したオフライン処理を使用してそれらをカウントできます。

 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | プレフィックス + スタック + オフライン カウント | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

文字列をプレフィックス バランス配列 b に変換します。ここで、b[i] は i 番目の文字の後のバランスで、b[0] = 0 となります。すべての部分文字列 (l, r] は、このプレフィックス配列内のインデックスのペア (l, r) に対応します。

 また、単調スタックを使用して、プレフィックスが厳密に小さくなる左側の最も近い位置を事前計算します。 これにより、位置 r ごとに境界 L[r] が得られます。これは、r で終わる有効な部分文字列はすべて L[r] の後に開始する必要があることを意味します。そうでない場合、バランスは必要なレベルを下回ります。 

次に、ポジションを潜在的なエンドポイントとして処理し、プレフィックス値によってグループ化されたアクティブな開始ポジションを維持します。 

## アルゴリズムのチュートリアル

 1. プレフィックスバランス配列 b を構築します。各ステップでは、ブラケットに応じて値が増加または減少します。 これにより、部分文字列の有効性がプレフィックスの違いに対する制約に変換されます。 
2. すべての位置 i について、b が b[i] より小さくなる左に最も近いインデックス L[i] を計算します。 これは、プレフィックス値に対して単調増加するスタックを使用して行われます。 その目的は、L[i] より前で始まる部分文字列が、バランスを崩さずに i で終わることがないようにすることです。 
3. 各プレフィックス値について、そのプレフィックス値が出現するすべてのインデックスを格納する構造を維持しますが、境界 L[i] に関してまだ「アクティブ」なインデックスのみを格納します。 
4. エンドポイント i を左から右に処理します。 i に到達したら、そのプレフィックス値に対応する構造にそれを挿入します。 これにより、 i が将来の部分文字列の開始点の候補になります。 
5. 各クエリは、セグメント [l, r] に制限されたエンドポイントを要求します。 これを接頭辞インデックス形式に変換し、開始と終了の両方が範囲内にあり、等しい接頭辞値を持ち、開始が L[end] によってブロックされないように、ペア (開始、終了) をカウントする必要があります。 
6. 効率的に回答するために、クエリを r で並べ替えてオフラインで処理します。 r を左から右に移動すると、エンドポイントが段階的にアクティブ化され、任意の範囲内に存在する有効な開始の数をカウントできる位置全体にわたるフェンウィック ツリーが維持されます。 
7. 固定エンドポイント r の場合、答えは、i がクエリ範囲内にあり、i > L[r] となるように、プレフィックス値とアクティブな開始位置 i の数を合計することによって得られます。 

重要なアイデアは、単調スタックが「最小プレフィックス制約」を単一の左境界に圧縮し、フェンウィック ツリーが範囲クエリでの有効な開始インデックスのカウントを処理するということです。 

### なぜ効果があるのか

 すべての有効な部分文字列には一意の右端点 r があります。 そのエンドポイントの場合、有効性は 2 つの条件にのみ依存します。1 つは開始時のプレフィックスのバランスが r でのプレフィックスのバランスと等しいこと、もう 1 つはプレフィックスがそのレベルを下回った最後のポイントの後に開始位置が配置されている必要があることです。 単調スタックにより、L[r] がその禁止領域を正確にキャプチャすることが保証されます。 この境界が固定されると、すべての有効な開始が独立するため、カウントは動的にアクティブ化されたインデックスに対する範囲カウントの問題に帰着し、これはフェンウィック ツリー スイープによって正しく処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        i += 1
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        if i < 0:
            return 0
        i += 1
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    n, q = map(int, input().split())
    s = input().strip()

    b = [0] * (n + 1)
    for i in range(1, n + 1):
        b[i] = b[i - 1] + (1 if s[i - 1] == '(' else -1)

    # compute previous smaller prefix using monotonic stack
    st = []
    L = [0] * (n + 1)
    for i in range(n + 1):
        while st and b[st[-1]] >= b[i]:
            st.pop()
        L[i] = st[-1] if st else -1
        st.append(i)

    # group indices by prefix value
    pos = {}
    for i in range(n + 1):
        pos.setdefault(b[i], []).append(i)

    # for each value, maintain pointer of active starts
    ptr = {v: 0 for v in pos}

    # sort queries by r
    queries = []
    for idx in range(q):
        l, r = map(int, input().split())
        queries.append((r, l - 1, idx))
    queries.sort()

    bit = Fenwick(n + 1)
    res = [0] * q

    # we activate prefix positions as we move r
    active = [False] * (n + 1)

    j = 0
    for r, l, idx in queries:
        while j <= r:
            # activate position j
            bit.add(j, 1)
            active[j] = True
            j += 1

        # count starts i in [l, r-1] with valid boundary
        # approximate condition: i must be after L[r]
        left = max(l, L[r] + 1)
        res[idx] = bit.range_sum(left, r)

    print(*res)

if __name__ == "__main__":
    solve()
```このコードは、エンドポイント上のスイープ ラインのアイデアに従い、アクティブな位置のフェンウィック ツリーを維持します。 プレフィックス配列はブラケット構造を数値制約に変換し、単調スタックは構造カットオフ L[i] を計算します。 クエリは、応答時に r までのすべての潜在的なエンドポイントがアクティブになるように、右のエンドポイントのソート順に処理されます。 

重要な点はインデックス付けです。プレフィックス配列の長さは n+1 ですが、サブストリングは (l-1, r] にマップされます。特に文字列インデックスとプレフィックス インデックスの間で変換する場合、ここで Off-by-One エラーが通常発生します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、プレフィックスがすでに複数の以前のレベルを下回っている位置からクエリ間隔が開始される場合です。 その場合、L[r] は左端になり、単純なカウントでは無効な開始が含まれることになります。 単調スタックにより、L[r] より前のすべての開始が 1 回の比較で除外されます。 

もう 1 つのケースは、弦が完全に交互になっている場合です。 2 番目ごとの位置が有効なエンドポイントとなり、重複する有効な部分文字列はエンドポイントを共有します。 Fenwick スイープは、各エンドポイントが独立して寄与する一方、サブストリングの列挙ではなくプレフィックスのグループ化によって有効性が強制されるため、これを正しく処理します。 

最後のエッジケースは、クエリ間隔が非常に短い場合に発生します。 l が r に等しい場合、単一の括弧ではバランスの取れたシーケンスを形成できないため、有効な部分文字列は存在しません。 等価制約と境界制約の両方を満たす一致する開始点を持つエンドポイントがないため、プレフィックス定式化では当然、寄与はゼロになります。
