 ## 解決策
 ## 問題の理解

 1 から 100000 までの数直線上にいくつかの隠れた位置が与えられます。これらの位置はホタルのグループの位置を表します。 位置は分からず、異なる地点に複数のグループが存在する可能性があります。 

許可される唯一の操作は、座標 x を選択し、x からすべての隠れた位置までの合計距離に等しい応答を受け取ることです。 各応答は、x とすべての隠れた点の間の絶対差の合計です。 目標は、テスト ケースごとに最大 40 個のこのようなクエリを使用して、隠れた位置の少なくとも 1 つを特定することです。 

重要な構造の詳細は、応答関数が整数に対して凸関数のように動作することです。 線に沿って x を移動すると、合計距離は点の分布の「中心」に到達するまで減少し、その後増加します。 この中心は、隠れた位置のマルチセットの中央値に対応します。 すべての点が離散線上の整数であるため、この問題では中央位置が実際の座標の 1 つであることが保証されます。 

この制約は、n がテスト ケースごとに最大 10000 まで大きくなり、最大 1000 のテスト ケースが存在できることを意味しますが、n の合計には制限があります。 座標範囲は 100000 に固定されています。これは、すべての点を明示的に再構築したり、すべての位置をクエリしたりするようなアプローチは不可能であることを意味します。 代わりに、絶対距離関数の構造を使用して、座標空間で対数クエリを実行して各テストを解決する必要があります。 

単純な誤解は、単一のクエリを直接「反転」できると想定することです。 1 つのクエリではグローバル集計のみが得られ、ローカル構造は明らかにされません。 最小応答点がすべてのケースで一意であると仮定すると、別の微妙な失敗ケースが発生します。 すべての点が同一の場合、すべてのクエリは同じ座標を答えとして返しますが、二分探索は傾斜ノイズに依存せずに正しく収束する必要があります。 

## アプローチ

 ブルートフォース的な考え方では、1 から 100000 までのすべての座標 x を調べて、応答を計算しようとします。 これにより、関数の最小値が明確に識別され、その最小値は中央位置に対応します。 ただし、これにはテスト ケースごとに 100,000 のクエリが必要であり、40 クエリの制限をはるかに超えているため、複数のテスト ケースを検討する前でさえすぐに失敗します。 

重要な観察は、絶対距離の合計として定義された関数 f(x) には予測可能な離散導関数があるということです。 x から x+1 に移動するときに f がどのように変化するかを見ると、各隠れ点は x または x の左側にある場合は +1 に寄与し、x の右側にある場合は -1 に寄与します。 これは、差 f(x+1) − f(x) を、x の各辺にいくつの点があるかを直接エンコードする量に変換します。 

これは、関数の 2 回の評価のみを使用して、x までのポイントのプレフィックス カウントを回復できることを意味します。 ≤ x である隠れ点の数を評価できたら、この数が少なくとも (n+1)/2 (中央位置) に達するように最小の x を二分探索できます。 その座標は、隠れたホタルの位置の 1 つと一致する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての x をブルート フォース スキャンする | O(100000) クエリ | お(1) | 遅すぎる |
 | 傾き回復を使用した二分探索 | O(log 100000) クエリ | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 距離関数の差を使用してプレフィックス数を計算できるという事実に依存しています。

1. インタラクターにクエリを実行し、すべての隠れた点までの距離の合計を返す関数 f(x) を定義します。 これをブラックボックス評価として扱います。 
2. 任意の x について、f(x) と f(x+1) を計算します。 これら 2 つの値から、単位 count_le(x) = (f(x+1) − f(x) + n) / 2 を使用して、x 以下の隠れ点の数を計算します。これは、各点が x のどちら側にあるかに応じて、差に +1 または -1 のいずれかに寄与するため機能します。 
3. 座標範囲 [1, 100000] を二分探索して、count_le(x) が少なくとも (n+1)//2 となる最小の x を見つけます。 これにより、中央値のしきい値に確実に到達します。 
4. 二分探索中、各中間点には 2 つのクエリ (mid に 1 つと Mid+1 に 1 つ) が必要なので、40 クエリの制限を超えないよう慎重に確認します。 
5. 二分探索が収束したら、その座標を答えとして出力します。 

これが機能する理由は、関数 f(x) が凸関数であり、その離散導関数が x が隠れ点のソートされたリストを通過するにつれて負から正に単調に変化するためです。 差分から抽出されるプレフィックス数は単調であるため、二分探索が有効になります。 中央値のしきい値により、ホタルのグループ間の幾何学的な中心ではなく、少なくとも 1 つのホタルのグループが実際に占有する点に着陸することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        def query(x):
            print("?", x)
            sys.stdout.flush()
            return int(input())

        def pref_le(x):
            fx = query(x)
            fx1 = query(x + 1)
            return (fx1 - fx + n) // 2

        lo, hi = 1, 100000
        target = (n + 1) // 2

        while lo < hi:
            mid = (lo + hi) // 2
            if pref_le(mid) >= target:
                hi = mid
            else:
                lo = mid + 1

        print("!", lo)
        sys.stdout.flush()

if __name__ == "__main__":
    solve()
```このソリューションは、グローバルな距離クエリをローカルな構造信号に変換することを中心に構築されています。 関数 pref_le は、対話型呼び出しを 2 回だけ使用して、位置の左側に隠れた点がいくつあるかを再構築します。 これは、問題を単調な述語に対する標準的な二分探索に変える重要な変換です。 

ソートされた位置のリストにアクセスできないため、二分探索はインデックスではなく座標ドメインに対して行われます。 x ではプレフィックス数が単調であるため、各決定ステップは有効です。そのため、一度中央値のしきい値を超えると、それを下回ることはありません。 

クエリ関数は、すべての対話の直後にフラッシュが確実に行われるように分離されています。これは、対話型の問題におけるアイドル状態エラーを回避するために必要です。 

## 実用的な例

 これは対話型であるため、固定の非表示配列を使用してアイデアをシミュレートします。 

隠れた位置が [1、5、10、8、9、6、13] であると仮定すると、n = 7、中央値は位置 8 になります。 

二分探索が概念的にどのように進行するかを示します。 

| ステップ | そうだ | こんにちは | ミッド | プレフ_ル(中間) | 決定 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 100000 | 50000 | 小 (7) | 左に行く |
 | 2 | 1 | 50000 | 25000 | 小さい | 左に行く |
 | 3 | 1 | 25000 | 12500 | 小さい | 左に行く |
 | ... | ... | ... | ... | ... | ... |
 | k | 1 | 10 | 5 | 3 | 右に行きます |
 | k+1 | 6 | 10 | 8 | 4 | 停止 |

 x = 8 では、プレフィックス数は少なくとも 4、つまり (n+1)//2 = 4 に達するため、検索は 8 で安定します。 

このトレースは、すべての点を明示的に見つける必要がないことを示しています。 必要なのは、中央値のしきい値の交差を識別するのに十分な解像度だけです。 

2 番目のシナリオは、すべてのポイントが等しい場合です ([42, 42, 42] など)。 すべてのクエリは、42 を中心とする対称線形関数を返します。プレフィックス数は x = 42 で 0 から 7 にジャンプするため、二分探索は曖昧さなく正確に 42 に収束します。

## テストケース

 これは対話型の問題であるため、距離のクエリに答えるローカル オラクルをシミュレートします。```python
import sys, io

def make_solver(hidden):
    def run(inp: str) -> str:
        data = inp.strip().split()
        t = int(data[0])
        idx = 1
        out_lines = []

        for _ in range(t):
            n = int(data[idx]); idx += 1

            def f(x):
                return sum(abs(v - x) for v in hidden)

            def pref_le(x):
                fx = f(x)
                fx1 = f(x + 1)
                return (fx1 - fx + n) // 2

            lo, hi = 1, 100000
            target = (n + 1) // 2

            while lo < hi:
                mid = (lo + hi) // 2
                if pref_le(mid) >= target:
                    hi = mid
                else:
                    lo = mid + 1

            out_lines.append(str(lo))

        return "\n".join(out_lines)

    return run

# custom tests
run = make_solver([5])
assert run("1\n1\n") == "5"

run = make_solver([1, 5, 10])
assert run("1\n3\n") == "5"

run = make_solver([42, 42, 42])
assert run("1\n3\n") == "42"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | シングルポイント | 同じ値 | 基本的な正確性 |
 | 複数のスプレッドポイント | 中央値の選択 | 中央値ロジックの正しさ |
 | すべての等しい点 | その値 | フラット関数での安定性 |

 ## 特殊なケース

 すべての隠れ点が同一である場合、関数 f(x) はその座標を中心とする単純な V 字型の関数になります。 差 f(x+1) − f(x) がまさにその時点で負から正にジャンプするため、接頭辞の再構築は引き続き機能します。 したがって、二分探索は振動することなく収束します。 

n が偶数の場合、古典的な意味では中央値が 2 つありますが、どちらもこの問題設定の隠れ点間の有効な座標に対応します。 このアルゴリズムは、(n+1)//2 を介してより低い中央値をターゲットにし、有効な答えへの決定論的な収束を保証します。 

すべての点が境界 1 または 100000 の近くにある場合でも、クエリは境界内に留まり、接頭辞関数の単調性がエッジでも維持されるため、二分検索は依然として正しく動作します。
