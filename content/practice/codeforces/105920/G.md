 ## 問題の理解

 単一の配列が与えられます`f`サイズの`n`。 この配列は、から開始された Disjoint Set Union 構造の最終状態であると主張されています。`f[i] = i`すべての要素に対して、最大でも`n`に電話をかける`merge(u, v)`手術。 

DSU の実装はわずかに非対称です。 各マージでは、次の代表者が見つかります。`u`そして`v`、次にルートを設定します`u`のルートを指すように設定されています`v`。 サイズやランクによる結合やバランス調整ロジックはありません。 唯一の圧縮は、`find`、保存された親配列には影響しません。`f`。 したがって、与えられる配列は文字通り、ルートの有向接続を繰り返すことによって作成される親ポインター フォレストです。 

タスクは、最大でも何らかのシーケンスが存在するかどうかを判断することです。`n`まさにこの親配列を生成できるマージです。 「はい」の場合、マージ操作の有効なシーケンスを 1 つ出力する必要があります。 それ以外の場合は出力します`-1`。 

制約は大きいです: 合計`n`テスト全体での上限は`4 · 10^5`。 これにより、ほぼ線形または線形時間の構築が強制されます。 任意のシーケンスをシミュレートしたり、可能性を探索しようとするアプローチは、遅すぎるでしょう。 

微妙な問題は、`f`有効な DSU 状態のツリーであることは保証されません。 たとえば、次のようなサイクル`0 → 1 → 0`DSU の親は常に根の生えた木の森を形成するため、これは直ちに不可能です。 もう 1 つの問題は、複数のノードが同じ親を指す可能性があるが、ルートは明確に定義され、非循環でなければならないことです。 

無効なケースの最小限の例は次のとおりです。`n = 3, f = [1, 2, 0]`。 これはサイクルを形成し、DSU の親ポインタは常にルートに向かって厳密に深さを減少させるため、一連のマージから得られるものではありません。 

より微妙な無効なケースは、2 つのノードに、単一のルート構造からは誘導できない競合するマージ方向を暗示する親ポインターがある場合です。 たとえば、ノードがそれ自体がどのマージ順序とも一致しない非ルート ノードを指している場合、構築順序の制約が破られます。 

重要な課題は、まさにこのフォレストを作成した可能性のある有向結合操作の順序が存在するかどうかを再構築することです。 

## アプローチ

 強引なアイデアでは、DSU の構築を逆方向または前方向にシミュレートしようとします。 フォワード シミュレーションとは、考えられるすべてのマージ シーケンスを試し、到達できるかどうかを確認することを意味します。`f`。 たとえせいぜい以下に限定したとしても`n`操作では、可能なマージ シーケンスの数は、ペアを繰り返し選択するオーダーで天文学的に大きくなり、これは指数関数的になります。`n`。 単一のシーケンスを検証することさえ線形であるため、これは直ちに実行不可能です。 

マージを再解釈すると、問題の構造がより明確になります。 各マージ操作は 1 つのルートを別のルートに接続します。つまり、2 つのコンポーネント間に 1 つの有向エッジが作成され、接続されたコンポーネントごとに 1 つのルートで終わるフォレストが徐々に構築されます。 

したがって、最終的な配列は`f`各ノードがその親を指し、ルートがノードである有向グラフをエンコードします。`f[i] = i`。 有効な DSU 構造では、すべてのノードが最終的にルートにつながり、すべての非ルートのセットが別のセットにマージされる瞬間に選択される親が 1 つだけ存在するフォレストを生成する必要があります。 

重要な点は、マージの順序を自由に選択できるということです。 つまり、葉から上に注意してノードを処理すれば、構造が有効であればいつでも構築をシミュレーションできるということです。 ルートを除く各ノードは 1 回だけ「接続」する必要があるため、両方のエンドポイントが現在のコンポーネントのルートになった時点ですべての有向エッジが確実に実現されるようにしたいと考えています。 

これにより、問題は、フォレストである必要がある関数グラフの検証と、子から親への添付ファイルのトポロジに似た順序付けを生成することに変わります。 

重要な単純化は、最終構造を次のように定義される根付きフォレストとして扱うことです。`f`。 最初にそれが有効であることを検証します。すべてのノードは最終的に固定点に到達する必要があります。`f[i] = i`、自己ループ以外のサイクルがあってはなりません。 次に、リーフからルートまで逆のトポロジー順序でノードを処理することにより、マージを再構築できます。 

各ノードの親を最終的にアタッチする必要があるコンポーネントとして表示すると、子がすでに解決されているノードを処理できるようになり、より小さいコンポーネントを常に構築済みのコンポーネントにマージできるようになります。

 ## アルゴリズムのチュートリアル

 最終的な親配列を有向フォレストとして扱い、ボトムアップで構築することにより、DSU 操作を再構築します。 

1. まず、すべてのインデックスをチェックしてどのノードがルートであるかを特定します`i`そのような`f[i] = i`。 これらのノードはコンポーネントの最終的な代表を表します。 ノードがそれ自体を誤って指している場合、またはサイクルに参加している場合は、後で検出します。 
2. 逆隣接リストを作成します。`children[x]`すべてのノードが含まれます`i`そのような`f[i] = x`。 これにより、親ポインター表現が明示的なツリー構造に変換されます。 
3. 子供の数を計算します (逆グラフの入次数)。 子がゼロのノードはすべてフォレスト内のリーフであり、最初に安全に処理できることを意味します。 
4. すべてのリーフを使用してキューを初期化します。 これらは、その下にサブツリーが構築されるのを待つ必要のないノードです。 リーフは後でマージされることに何も依存しないため、早期にリーフをアタッチできるという考えです。 
5. キューが空でない間に、ノードを削除します。`v`そしてその親を考えてみましょう`p = f[v]`。 もし`p == v`、これはルートであり、最終コンポーネントのアンカーとして保持する以外は何も行いません。 
6. もし`p != v`、間のマージ操作を記録します。`v`そして`p`。 この瞬間、`v`完全に構築されたサブツリーを表し、`p`は、それが属するコンポーネントを表すため、これらをマージすると DSU の動作と一貫性が保たれます。 
7.加工後`v`の残りの子の数をデクリメントします。`p`。 もし`p`未解決の子が残っていないため、処理できるようになり、キューにプッシュします。 
8. プロセスが完了したら、すべてのノードを一貫して処理できたかどうかを確認します。 サイクルがある場合、一部のノードはリーフにならず、未処理のままになり、不可能であることを示します。 

### なぜ効果があるのか

 この構築は、サブツリー内のすべてのノードが処理された後にのみノードを処理するという不変条件に依存します。 これにより、マージ操作を適用するときに、`(v, f[v])`、両方のエンドポイントがすでに形成された DSU コンポーネントに対応しているため、マージは、以前の構造に違反することなく、1 つの完全なコンポーネントを別の完全なコンポーネントに接続するものとして解釈できます。 サイクルが存在する場合、そのサイクル内のノードはリーフになることができないため、アルゴリズムは正常に失敗します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())
    f = list(map(int, input().split()))
    
    children = [[] for _ in range(n)]
    deg = [0] * n
    
    for i in range(n):
        if f[i] == i:
            continue
        children[f[i]].append(i)
        deg[f[i]] += 1
    
    q = deque(i for i in range(n) if deg[i] == 0)
    ans = []
    
    while q:
        v = q.popleft()
        p = f[v]
        
        if v != p:
            ans.append((v, p))
            deg[p] -= 1
            if deg[p] == 0:
                q.append(p)
    
    # check if all nodes were processed structurally
    # nodes in cycles or invalid structure won't be fully resolved
    if len(ans) > n:
        print(-1)
        return
    
    # additional validation: ensure forest consistency
    # (if cycles exist, some nodes never got processed)
    visited = set()
    for v, p in ans:
        visited.add(v)
        visited.add(p)
    
    if len(visited) != n:
        print(-1)
        return
    
    print(len(ans))
    for u, v in ans:
        print(u, v)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```実装は、親配列の逆構造を構築し、各ノードが持つ直接の子の数をカウントすることから始まります。 子がゼロのノードは、逆構築プロセスで最初に安全に「切り離す」ことができるリーフを表すため、最初はキューに入れられます。 

ノードをポップするたびに、ノードがまだルートでない場合はその親に接続します。 これは、概念的な DSU 構築順序を逆にすることに対応します。つまり、葉が最初に取り付けられ、根は最後まで残ります。 

キューベースの削減により、すべての子孫が処理された後でのみノードが処理されることが保証されます。これは、最終的な DSU の暗黙の構造に違反する早期のマージを回避するために重要です。 

最後の検証では、すべてのノードが考慮されているかどうかがチェックされます。これは、一部のノードが未解決の子をゼロに到達することがサイクルによって妨げられるためです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    
    t = int(sys.stdin.readline())
    out = []
    
    def solve():
        n = int(sys.stdin.readline())
        f = list(map(int, sys.stdin.readline().split()))
        
        children = [[] for _ in range(n)]
        deg = [0] * n
        
        for i in range(n):
            if f[i] != i:
                children[f[i]].append(i)
                deg[f[i]] += 1
        
        q = deque(i for i in range(n) if deg[i] == 0)
        ans = []
        
        while q:
            v = q.popleft()
            p = f[v]
            if v != p:
                ans.append((v, p))
                deg[p] -= 1
                if deg[p] == 0:
                    q.append(p)
        
        visited = set()
        for u, v in ans:
            visited.add(u); visited.add(v)
        
        if len(visited) != n:
            out.append("-1")
        else:
            out.append(str(len(ans)))
            out.extend(f"{u} {v}" for u, v in ans)
    
    for _ in range(t):
        solve()
    
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースは、サイクルが混在する自己ループの多い構成です。 例えば、`f = [1, 2, 0]`長さ 3 のサイクルを作成します。 このアルゴリズムでは、すべてのノードに少なくとも 1 つの入力エッジがあるため、どのノードも 0 度に到達することはありません。 キューは空のままで、操作は生成されず、最後に訪問したセットがすべてのノードをカバーしていないため、`-1`。 

もう 1 つのケースは、複数の独立したルートを持つ有効なフォレストです。`f = [0, 0, 2, 2]`。 ここで、ノード 1 と 3 はリーフであるため、最初に処理され、マージが生成されます。`(1,0)`そして`(3,2)`。 その後、すべてのノードが一貫して解決され、有効なシーケンスが生成されます。 

繊細なケースは長いチェーンのように`f = [1,2,3,4,4]`。 リーフは下から上に向かって処理され、マージごとに完全に形成されたサブツリーがその親に接続され、最終的にルートに到達します。 これは、逆の処理順序が DSU 構築の制約と正確に一致していることを示しています。
