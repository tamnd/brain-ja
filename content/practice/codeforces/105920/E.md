 ## 解決策
 ## 問題の理解

 私たちは、時間の経過とともに変化する動的な文字列のセットを維持します。 更新のたびに、現在セット内にある個別の単語の順序付けされたペアが、一方の単語が他方の単語の接尾辞であるという特性を持っているペアがいくつあるかを計算する必要があります。 

言い換えれば、各瞬間に文字列のコレクションが存在します。 A が B の最後に出現し、A が B に等しくなく、両方が同時に存在するようなすべてのペア (A, B) を数えたいと考えています。 セットは挿入や削除によって変更されるため、操作のたびに最初から再計算することは避けなければなりません。 

この制約は、合計入力サイズがほぼ線形になるソリューション (最大 100,000 の操作と最大 1000,000 の文字列長) を目指します。クエリごとに文字列のすべてのペアを比較するソリューションは、アクティブな文字列の数が二次関数に低下するため、すぐに失敗します。 更新ごとに完全なサフィックス比較を構築する場合でも、高度に構造化されていない限り、時間がかかりすぎます。 

複数の文字列がサフィックス構造を共有する場合、微妙なエッジケースが発生します。 たとえば、「a」、「aa」、「aaa」がある場合、答えは隣接する長さをカウントするだけでなく、短い文字列が長い文字列の末尾に一致するすべての順序付きペアをカウントすることになります。 もう 1 つの注意が必要なケースは削除です。文字列を削除すると、関係をサフィックスするために必要なすべての要素が即座に削除されなければなりません。 

多くの文字列が異なる長さの同一のサフィックスを共有している場合も、単純なアプローチは失敗します。 たとえば:

 入力:

 -
 -ああ
 - ああ

 3 番目の操作後の正しい動作は 3 です。理由は次のとおりです。 

(a, aa)、(a, aaa)、(aa, aaa) はすべて接尾辞条件を満たします。 

総当りの再計算では、慎重にフィルタリングしないと、方向性の維持やペアの二重カウントが失われる可能性があります。 

## アプローチ

 直接的な解決策では、文字列のセットを維持し、更新のたびに、すべての順序付けされたペアを反復処理し、接尾辞の関係をテストします。 A が B のサフィックスであるかどうかを確認するには O(|A|) がかかるため、1 回の再計算に O(k^2 * L) のコストがかかります。ここで、k はアクティブな文字列の数です。 k が 100000 までの場合、これは完全に不可能です。 

主要な問題は、すべての更新が他のすべての文字列との関係を変更する可能性があることであるため、ペア チェックを改善しても十分な効果はありません。 

重要な観察は、接尾辞の関係が逆転する可能性があるということです。 A が B の接尾辞であるかどうかを尋ねる代わりに、B から開始してセット内に存在する B のすべての接尾辞を調べるという観点から考えることができます。 単語を挿入または削除するたびに、その単語の接尾辞として存在する単語がいくつあるか、またはその接尾辞として存在する単語がいくつあるかを考慮するだけで済みます。 

これは、サフィックス クエリを効率的にサポートする構造内のすべての文字列のカウントを維持することを示唆しています。 逆向きの文字列に基づいて構築されたトライは、接尾辞の関係を接頭辞の関係として取得します。 各単語は、反転された文字に続くルートからのパスに対応します。 すべての逆向きの文字列をトライに挿入すると、単語のすべての接尾辞がその挿入パスに沿ったノードに対応します。 

動的なカウントをサポートするために、トライ内の各ノードは、そのノードで現在終了している単語の数を維持します。 次に、特定の単語について、そのすべての接尾辞の一致がその逆のパスに沿ったノードに対応し、そのパスに沿って検出されたエンドポイントの数を累積することができます。 

挿入と削除は、逆トライの単一のルートからリーフへのパスに沿った更新になります。 単語の寄与を問い合わせることは、その経路をたどり、頻度を合計することになります。 

これにより、各操作が O (単語の長さ) に削減されますが、操作全体の長さの制限があるため、これは許容範囲内です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2・L) | O(nL) | 遅すぎる |
 | カウント付きの逆転トライ | O(Σ | s | ) |

 ## アルゴリズムのチュートリアル

 反転した文字列に対するトライとグローバルな答えを維持しながら、操作を 1 つずつ処理します。

1. すべての文字列を反転して、トライ内の接尾辞クエリが接頭辞クエリになるようにします。 この変換は、「A は B のサフィックス」を「reverse(A) は reverse(B) のプレフィックス」に変換します。 
2. 各ノードがそのノードで正確に終わる単語の数を格納するトライを維持します。 これにより、そのノードで終わる特定の接頭辞に一致する既存の単語の数を数えることができます。 
3. また、現在セット内にある各単語について、削除によって寄与を効率的に減算できるように、トライ内のそのパス ノードを維持します。 
4. 単語 s を挿入するには、トライ内のその逆のパスをたどります。 歩いている間、訪問するすべてのノードは、セット内にすでに存在する s の接尾辞を表します。 これらの各単語は s と有効なペアを形成するため、これらのノードで終わる単語の数を累積します。 
5. s の接尾辞である既存の単語の数を計算した後、この値をグローバルな答えに追加します。 
6. 次に、最後のノードの端末カウンターをインクリメントして、トライに s を挿入します。 
7. 削除するには、まず s の逆のパスを再度たどります。 パスに沿ったすべてのノードは、s が接尾辞であるセット内の単語に対応します。 それに応じて、グローバルな答えから s の寄与を差し引きます。 
8. 最後に、エンドポイント ノードのターミナル カウンタをデクリメントし、構造から を効果的に削除します。 

なぜ効果があるのか:

 反転文字列のトライは、すべての接尾辞関係を接頭辞の重複としてエンコードします。 すべての有効なペア (A、B) は、reverse(B) のパスが reverse(A) の終端ノードを通過する点に対応します。 トラバーサル パスに沿って終端カウントを合計することにより、接尾辞の一致に対応する位置で終わるすべての単語を正確にカウントします。 各ペアは、長い単語の挿入時に 1 回だけカウントされ、削除時に 1 回だけ削除されます。 不変条件は、トライ ノードの終端カウントが常に現在アクティブな語彙を表すため、すべての走査が有効な接尾辞エンドポイントの正確なセットを反映することです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("next", "end")
    def __init__(self):
        self.next = {}
        self.end = 0

def add(root, s, delta):
    node = root
    nodes = [root]
    for ch in s:
        if ch not in node.next:
            node.next[ch] = Node()
        node = node.next[ch]
        nodes.append(node)
    node.end += delta
    return nodes

def query(root, s):
    node = root
    res = 0
    for ch in s:
        if ch not in node.next:
            break
        node = node.next[ch]
        res += node.end
    return res

def solve():
    n = int(input())
    root = Node()
    active = {}
    ans = 0
    out = []

    for _ in range(n):
        op, s = input().split()
        rs = s[::-1]

        if op == '+':
            nodes = []
            node = root
            tmp_nodes = []
            for ch in rs:
                if ch not in node.next:
                    node.next[ch] = Node()
                node = node.next[ch]
                tmp_nodes.append(node)

            cnt = 0
            for node in tmp_nodes:
                cnt += node.end

            ans += cnt

            node = root
            for ch in rs:
                node = node.next[ch]
            node.end += 1

            active[s] = rs

        else:
            rs = active.pop(s)

            node = root
            tmp_nodes = []
            for ch in rs:
                node = node.next[ch]
                tmp_nodes.append(node)

            cnt = 0
            for node in tmp_nodes:
                cnt += node.end

            ans -= cnt

            node = root
            for ch in rs:
                node = node.next[ch]
            node.end -= 1

        out.append(str(ans))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```この実装では、反転された文字列のトライが維持されます。 各ノードの`end`フィールドは、そのノードで正確に終了するアクティブな単語の数をカウントします。これは、元の向きでその正確な接尾辞を持つ単語の数に対応します。 

挿入中に、反転した文字列をトラバースして合計します。`end`パスに沿った値。 各訪問ノードは挿入された単語の接尾辞を表すため、そのノードで終わるすべての格納された単語が 1 つの有効なペアに寄与します。 寄与を計算した後、ターミナル ノードをインクリメントして新しい単語を登録します。 

削除は挿入をミラーリングします。同じ逆のパスをたどり、すべての接尾辞一致の寄与を差し引いてから、ターミナル カウンタをデクリメントします。 の`active`削除は正確な逆表現を知る必要があるため、辞書が必要です。 

答えは段階的に更新されるため、完全なセットに対する再計算は必要ありません。 

## 実用的な例

 次の順序を考えてみましょう。```
+ ever
+ never
+ forever
```「reve」、「reven」、「rev erof」という反転した文字列を追跡します。 

| ステップ | 挿入されました | 反転 | 接尾辞の一致が見つかりました | 実行中の答え |
 | --- | --- | --- | --- | --- |
 | 1 | これまで | レーヴ | なし | 0 |
 | 2 | 決して | レビュー | 「ever」は「never」の接尾辞です | 1 |
 | 3 | 永遠に | レヴェロフ | 「ever」と「never」は接尾語です。 3 |

 各挿入の後、トライ パスに沿って検出されたすべての既存のサフィックス エンドポイントからの寄与が蓄積されます。 3 番目の挿入は、重複する接尾辞構造を示しています。つまり、前の両方の単語が異なる接尾辞の位置に一致します。 

ここで削除を検討してください。```
+ a
+ aa
+ aaa
- aa
```| ステップ | 操作 | アクティブセット | 答え |
 | --- | --- | --- | --- |
 | 1 | + a | {a} | 0 |
 | 2 | +aa | {a、aa} | 1 |
 | 3 | +ああ | {ああ、ああ、ああ} | 3 |

 「aa」を削除すると、それに関係するペア (a, aa) と (aa, aaa) が正確に削除され、直ちに正確さが復元されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、単一の単語が複数の長い単語に寄与する構造的な重複が繰り返されることです。 例えば：```
+ a
+ aa
+ aaa
+ aaaa
```新しく挿入するたびに、サフィックスとして表示される以前の文字列の数だけ答えが増加します。 このトライにより、「aaaa」を挿入すると、トラバーサルが「a」、「aa」、および「aaa」に対応するノードにヒットし、すべての有効な一致が 1 つのパスに蓄積されます。 

もう 1 つのエッジ ケースは、深くネストされたサフィックス コントリビュータの削除です。```
+ abc
+ bc
+ c
- bc
```「bc」を削除する場合、「abc」と「c」への寄与を 1 回だけ削除する必要があります。 削除中のトラバーサルでは、「bc」を含むすべてのペアが、挿入中に追加された方法と対称的に減算されることが保証されます。
