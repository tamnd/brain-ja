 ## 解決策
 ## 問題の理解

 私たちには、独立して稼働する複数の印刷機が与えられていますが、少なくとも同じものを生産するという同じ共通の目標に貢献します。$k$文書の合計コピー数。 各プリンターは、単純な直線的な方法で長期間一定の速度で動作するわけではありません。 代わりに、サイクルに従います。 各サイクルで、毎回 1 つのコピーが作成されます。$t_i$固定バースト長の場合は秒$l_i$コピーした後、しばらくシャットダウンします$w_i$同じ行動を繰り返す数秒前。 

したがって、各プリンターはアクティブ段階と冷却段階を交互に行います。 アクティブフェーズ中に、出力します。$l_i$1 人あたり 1 部の一定の速度でコピーします。$t_i$秒、かかる$t_i \cdot l_i$合計秒数。 その後、一時停止します$w_i$秒後、パターンが繰り返されます。 

すべてのプリンタは時間ゼロから同時に動作します。 目標は最小時間を決定することです$T$すべてのプリンタが時間ごとに作成した部数の合計が$T$少なくとも$k$。 

この制約により、強引なシミュレーションは不可能になります。 プリンターの台数は最大100台ですが、必要な部数は$k$と同じ大きさにすることができます$10^9$、時間パラメータも到達できます$10^9$。 これにより、単純な方法で 1 秒ごと、さらにはイベントごとにシミュレーションすることは直ちに排除されます。 どのようなアプローチでも、生産を長期にわたって総合的に評価する必要があります。 

よくある微妙な失敗のケースは、部分的なサイクルの処理を誤ったことに起因します。 プリンターは、アクティブ段階またはアイドル段階の途中である可能性があります$T$、完全なサイクルのみをカウントすると過少カウントにつながります。 

たとえば、プリンターに$t=2, l=3, w=10$、その後 7 秒経過しても最初のアクティブ フェーズ (6 秒かかります) が終了していないため、コピーが 3 つ生成されます。 単純なサイクルのみの計算では、時間 7 が 0 完全なサイクルを生成し、したがって 0 コピーが生成されるものとして誤って処理される可能性がありますが、これは誤りです。 

もう 1 つの失敗例は、線形レートを仮定することから生じます。 ダウンタイムにより実効速度は一定ではないため、$\frac{l_i}{t_i l_i + w_i}$乗算$T$は近似値を与えるだけであり、境界を決定するのに必ずしも十分正確であるとは限りません。 

## アプローチ

 直接的なアプローチは、時間をシミュレートすることです。 各プリンターについて、そのサイクル位置を追跡し、それまでに何部印刷されたかをカウントします。$T$。 固定の場合$T$で出力を計算できます。$O(n)$慎重に実行すればプリンターごとに実行できますが、その場合は可能な限りすべての回数を試す必要があります。 以来$T$非常に大きくなる可能性があるため、これは実行不可能になります。 

重要な構造的洞察は単調性です。 いつか$T$少なくとも生成するには十分です$k$コピーする場合は、それより長い時間でも十分です。 この単調な特性により、時間の経過に伴う検索を二分探索に置き換えることができます。 

残りのタスクは、一定時間の計算です。$T$、各プリンターが印刷する部数。 各プリンターは長さのサイクルを繰り返します$c_i = t_i l_i + w_i$。 各完全なサイクルで、正確に生成されます。$l_i$コピー。 完全なサイクルが何回当てはまるかを数えることができます。$T$、乗算します$l_i$次に、時間がなくなるまでにアクティブなフェーズのコピーをいくつ完了できるかを確認して、残りの時間を処理します。 

これにより、候補時間の評価が、潜在的に複雑なシミュレーションからプリンタごとの直接の算術計算に削減されます。

 ## アルゴリズムのチュートリアル

 最小の時間を見つけたい$T$生産されたコピーの総数が少なくとも$k$。 

1. 関数を定義する$f(T)$すべてのプリンターが時間内に何部印刷するかを計算します$T$。 各プリンターについて、最初にその全サイクル長を計算します。$c_i = t_i l_i + w_i$。 これにより、稼働期間と冷却期間の両方がキャプチャされます。 
2. 各プリンタについて、完全なサイクルが何回収まるかを計算します。$T$として$q = T // c_i$。 それぞれの完全なサイクルが正確に寄与します$l_i$コピーなので、フルサイクルの貢献は$q \cdot l_i$。 
3. 残り時間を計算する$r = T \% c_i$。 この残りのセグメントの間、プリンタはまだアクティブ段階にある可能性があります。 アクティブフェーズは、以下を生成することで構成されます。$l_i$コピー、それぞれを取る$t_i$秒。 したがって、追加コピー数は次のようになります。$\min(l_i, r // t_i)$。 
4. すべてのプリンタからの寄与を合計して、$f(T)$。 この機能は単調です$T$、つまり、次のように減少することはありません。$T$が増加します。 
5. 時間をかけて二分探索を実行します。 下限は 0 です。上限は次のように安全に設定できます。$\min\_time \cdot k$、 どこ$\min\_time$最小です$t_i$なぜなら、最速のプリンタだけでもその時間内にすべてのコピーを作成できるからです。 
6. 各中間点で$mid$、 評価する$f(mid)$。 少なくともそれであれば$k$、上限を左に移動します。 それ以外の場合は、下限を右に移動します。 
7. 最終的な下限は、要件を満たす最小時間です。 

### なぜ効果があるのか

 正確さは、時間の経過に伴う各プリンタの出力が段階的に減少しない関数であるという事実に基づいています。 これはアクティブ段階では増加し、ダウンタイム中は一定のままですが、減少することはありません。 このような関数を合計すると、単調性が維持されます。 これにより、述語が「少なくとも$k$時間ごとにコピーする$T$」は、時間の経過とともに連続する領域を定義し、二分探索で境界を正確に見つけることができるようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(t, printers, k):
    total = 0
    for ti, li, wi in printers:
        cycle = ti * li + wi
        full = t // cycle
        total += full * li

        rem = t % cycle
        total += min(li, rem // ti)

        if total >= k:
            return True
    return total >= k

def solve():
    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        printers = [tuple(map(int, input().split())) for _ in range(n)]

        lo, hi = 0, 10**18

        while lo < hi:
            mid = (lo + hi) // 2
            if can(mid, printers, k):
                hi = mid
            else:
                lo = mid + 1

        print(lo)

if __name__ == "__main__":
    solve()
```機能`can`一定時間のコア評価を実装します。 完全なサイクルと部分的なサイクルを慎重に分離します。 全サイクルは単純な乗算ですが、残りはアクティブな位相のみにクリップする必要があります。 早期終了により、次の場合の速度が向上します。$k$に達します。 

二分探索では大きな上限が使用されます$10^{18}$、生産が極端に遅くなる最悪のシナリオを安全にカバーします。 単調チェックにより、この緩やかな境界でも正確さが保証されます。 

実装の微妙な詳細は、サイクルと残りの生産の両方に整数除算を使用することです。 浮動小数点のアプローチでは精度の問題が発生し、大きな入力では失敗します。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$T$サイクル内にありますが、アクティブフェーズの外にあります。 仮定する$t=2, l=3, w=10$そして$T=7$。 プリンターは 16 秒で 1 サイクルを完了するため、$T=7$それはまだ活動段階にあります。 それは生産しました$3$それ以降のコピー$7 // 2 = 3$。 アルゴリズムは、剰余ロジックを使用してこれを正しく取得します。 

もう 1 つのエッジケースは次のような場合です$T$はまさにサイクル境界上にあります。 もし$T = k \cdot (t_i l_i + w_i)$の場合、剰余はゼロになり、寄与率は正確に$k \cdot l_i$。 この式により、二重カウントや部分的な作業の欠落が回避されます。 

最後のエッジケースは次のような場合です$k$は非常に大きいため、最も高速なプリンターのみが重要です。 実行可能性チェックが総出力に比例してスケールされ、Python の大きな整数によってオーバーフローが回避されるため、二分探索は引き続き正しく収束します。
