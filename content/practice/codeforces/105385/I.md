 ## 解決策
 ## 問題の理解

 文字列が与えられているので、それを一定の位置だけ左に循環的に回転させることができます。 による左シフト$d$位置から始まる部分文字列を取得することを意味します$d$最後にプレフィックスを付けます$0 \dots d-1$最後に。 

それぞれの回転の後、回転された文字列の最初と最後の文字だけが調べられます。 回転量を最小限にしたい$d \ge 0$これら 2 つの文字が等しくなるようにします。 回転を行わないと最初と最後の文字が一致する場合は、次のように出力します。$-1$。 

これを再構成する便利な方法は、円上の文字列を考えることです。 すべてのローテーションでは開始インデックスを選択するだけです$i$、結果の文字列は次から始まります$i$そしてで終わります$i-1$モジュロ$n$。 したがって、実際に求めているのは最小のインデックスです$i$そのような$s[i] = s[i-1]$循環的な意味で、そして私たちは戻ります$i$シフト量として。 

この制約により、文字列の合計の長さは次のようになります。$5 \times 10^5$これにより、すべての回転を試行し、エンドポイントを再計算したり、シフトごとに文字列をスキャンしたりするソリューションは除外されます。 合計入力サイズが 2 次のものは明らかに失敗します。 

すべての文字が区別できる場合、微妙なエッジケースが表示されます。 たとえば、入力`"abc"`循環的な意味でも隣接する等しい文字のペアがないため、回転によって端点が等しくなることはなく、答えは次のようになります。$-1$。 ラップアラウンドを考慮せずに線形隣接性のみをチェックする単純なアプローチでは、最後の文字と最初の文字の間の遷移を誤って見逃したり、逆に、シフト後に一致が存在すると誤って想定したりする可能性があります。 

もう 1 つのエッジ ケースは、文字列が既に同じ文字で始まり同じ文字で終わる場合です。 のために`"abca"`、答えは$0$また、どのアルゴリズムでも、他の一致が存在するという理由だけで誤ってより大きな回転を返さないようにする必要があります。 

## アプローチ

 ブルートフォースアプローチはあらゆる可能なシフトを試みます$d$から$0$に$n-1$。 シフトごとに、概念的には文字列を回転し、最初と最後の文字を比較します。 回転された文字列の構築コスト$O(n)$たとえ構築を避けてモジュロにインデックスを付けるだけだったとしても$n$、エンドポイントのチェックは$O(1)$, だからこの部分は大丈夫です。 本当の問題は、すべてを考慮して正しさを判断する必要があるということです。$d$、つまり$O(n)$テストケースごとのチェック。 

ただし、重要な点は、回転によって最初の文字になるインデックスが変わるだけであるということです。 開始インデックスを選択した場合$i$の場合、最後の文字は常に$s[i-1]$。 したがって、「最初と最後が等しい」という条件は純粋にローカルな条件になります。$s[i] = s[i-1]$。 

これにより、問題全体が最小のインデックスを見つけることに分解されます。$i$循環文字列内の隣接する文字が一致するようにします。 文字列を 1 回スキャンして、すべてのペアをチェックできます$(i-1, i)$、そしてラップアラウンドペアも$(n-1, 0)$。 そのような最小のインデックス$i$が答えです。 何も存在しない場合は、出力します$-1$。

 | 円形隣接の線形スキャン |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 最後の文字と最初の文字の間の境界が有効になる最も早い回転ポイントを特定したいと考えています。 

1. 考えられる各ローテーションを開始インデックスの選択として扱います。$i$。 回転後の最初の文字は、$s[i]$そして最後は$s[i-1]$循環インデックスで。 この再定式化により、回転をシミュレートする必要がなくなります。 
2. すべてのインデックスを確認する$i$から$0$に$n-1$。 それぞれについて$i$、 比較する$s[i]$と$s[i-1]$、ここでインデックス$-1$に対応する$n-1$。 このステップでは、回転かどうかを直接テストします。$i$「美しい」文字列を生成します。 
3. 最小のインデックスを維持する$i$それは等式を満たします。 左から右にスキャンするため、最初の有効な$i$は自動的に最小限になります。 
4. 条件を満たすインデックスがない場合は、リターンします。$-1$。 

### なぜ効果があるのか

 左シフト後$i$、回転された文字列はまさに循環的な再ラベル付けです。$0$元のインデックスに対応します$i$そして位置$n-1$元のインデックスに対応します$i-1$。 したがって、有効な答えの条件は、元の循環配置内の 1 つの隣接関係のみに依存します。 考えられるすべての回転文字列は、まさに 1 つのそのような隣接性チェックに対応し、2 つの異なるシフトによってこの境界ペアを超えて異なる比較が生成されることはありません。 この 1 対 1 マッピングにより、すべての円形隣接関係をスキャンすることで、可能なすべての回転が省略や重複なく実行されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    if n == 1:
        print(0)
        return

    for i in range(n):
        if s[i] == s[i - 1]:
            print(i)
            return

    print(-1)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```この解決策は、各位置を 1 回スキャンし、その左隣を円形でチェックすることに依存しています。 表現`s[i - 1]`Python の負のインデックスがマップされるため、ラップアラウンドの場合も自然に処理されます。`-1`インデックスに正確に対応する最後の文字まで$n-1$。 

特別な場合$n=1$単一文字列は回転時に常に美しいため、個別に処理されます。$0$、それ以外の場合、ループは引き続き正しく動作しますが、明示的なケースにより意図が明確になり、不必要な反復が回避されます。

 2 つの入力に対する循環隣接チェックをトレースします。

 最初の有効なインデックスは 3 です。つまり、3 だけ左に回転すると、最初と最後の文字が一致する文字列が生成されます。 これは、3 で始まる部分文字列が同じ文字で始まり同じ文字で終わる動作例と一致します。 

### 例 2:`"abcdcba"`| 私 | s[i] | s[i-1] | 一致 | 決定 |

これらの例は、完全な文字列をシミュレートしようとするのではなく、回転を境界チェックとして正しく解釈していることを確認します。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    def solve_all():
        t = int(input())
        for _ in range(t):
            s = input().strip()
            n = len(s)
            if n == 1:
                print(0)
                continue
            for i in range(n):
                if s[i] == s[i - 1]:
                    print(i)
                    break
            else:
                print(-1)

    solve_all()
    return out.getvalue().strip()

# provided sample

assert run("1\nabcdcba\n") == "0"
assert run("1\nx\n") == "0"

# custom cases
assert run("1\naab\n") == "1", "adjacent match after shift"
assert run("1\nbaaa\n") == "1", "wrap-around and internal equality"
assert run("1\nabab\n") == "-1", "no equal adjacent circular pair"
assert run("1\naa\n") == "0", "minimum length repeated characters"

 ## 特殊なケース

 のような文字列の場合`"abab"`、円形であっても、すべての文字は隣の文字とは異なります。 スキャンではすべてのインデックスがチェックされます。 

i = 0 で比較します。`a`最後と`b`、一致しません。 i = 1 の場合、`b`対`a`、一致しません。 i = 2 では、`a`対`b`、一致しません。 i = 3 では、`b`対`a`、一致しません。 アルゴリズムは有効なインデックスを見つけられずに終了し、出力が返されます。$-1$回転では端点を揃えることができないため、これは正しいです。 

のために`"aa"`、i = 0 で比較します。`a`と`a`これにより、明示的な回転シミュレーションを必要とせずに、円形隣接が回転境界条件を正しく捉えていることが確認されます。
