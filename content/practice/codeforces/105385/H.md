 ## 解決策
 ## 問題の理解

 私たちには大きな無限のチェス盤が与えられていますが、城と既存の障害物の 2 種類のオブジェクトが占有しているセルはほんのわずかです。 2 つの城は、間に障害物がない行または列に沿ってお互いを「見る」ことができる場合、互いに危険であると見なされます。 

課題は、どちらの方向にも障害物のない城のペアがないように追加の障害物を配置することです。 すでに占有されているセルに障害物を配置することは許可されていないため、追加する新しい障害物の数を最小限に抑えたいと考えています。 すべての攻撃ペアを完全にブロックすることが不可能な場合は、失敗を報告する必要があります。 

入力は、いくつかの独立したテスト ケースを記述します。 各テスト ケースでは、最大 200 の城と最大 200 の既存の障害物が提供され、すべて最大 10^9 の座標を持つ座標グリッド上に配置されます。 座標範囲が広いということは、平面全体にわたってグリッド圧縮を使用できないという点でのみ重要です。 有限の点セットによって引き起こされるソートとローカル構造に依存する必要があります。 

重要な構造上の制約は、行と列に沿った相対的な順序のみが重要であるということです。 絶対座標は、行または列が等しいかどうかを区別し、それらに沿って順序付けすることを除いて無関係です。 

城の各ペアを独立して処理できると仮定すると、単純な間違いがすぐに現れます。 たとえば、障害物がない 3 つの城が同じ列の 1、5、9 の位置にあるとします。 (1、5) をブロックするには、それらの間に障害物を配置する必要がある場合がありますが、その同じ障害物が、配置に応じて 3 番目の城に関係する相互作用をブロックする場合とブロックしない場合があります。 ペアごとの戦略を貪欲に行うと、共有されたブロッキングの機会を簡単に逃したり、カウントしすぎたりする可能性があります。 

もう 1 つの微妙な失敗例は、城のペアがいつでも分離できると仮定したことから生じます。 中間のすべてのセルが既存の城または障害物によって占有されているため、同じ行に 2 つの城があり、その間に空きセルが存在しないとします。 この場合、新たな障害物を挿入することはできないため、ペアが「対立」しているにもかかわらず、即座に答えは不可能になります。 

## アプローチ

 最初の自然なアプローチは、同じ行または列にあるすべての城のペアを明示的に考慮し、それらの可視性をブロックしようとすることです。 単一のペアを分離した場合、それらの攻撃を阻止する唯一の方法は、共有する行または列に沿ってペア間の開いた間隔に少なくとも 1 つの障害物を置くことです。 このようなペアごとに、障害物を配置できる整数セルの候補が多数存在する可能性があり、ブロックする位置を貪欲に選択しようとする可能性があります。 

単一の障害物が複数の視界間隔の交差点にある場合、複数の城のペアを同時にブロックする可能性があるため、これはすぐに問題になります。 ブルートフォースアプローチは、ブロック候補セルのすべてのサブセットを効果的に試し、すべてのペアがカバーされているかどうかを確認します。 最悪の場合、O(n^2) 個のペアが存在し、各ペアには O(10^9) 個の潜在的な位置が存在する可能性がありますが、圧縮後は実質的に O(n + m) 個の意味のある位置のみが存在します。 離散化した後でも、サブセットを試すと指数関数的な動作が発生するため、実行不可能です。 

重要な観察は、競合は任意のペアごとの制約ではないということです。 それらはライン上の間隔制約です。 固定列の場合、城と障害物によって列がセグメントに分割されます。 同じセグメントにある 2 つの城は、そのセグメントに少なくとも 1 つの障害物を配置しない限り「接続」されます。 同じことが列ごとに独立して適用されます。 これにより、各行と列が独立した 1D 折れ線グラフのように動作する、区間グラフの集合における最先端の問題に問題が変換されます。

このように見ると、構造は区間に関する打撃集合問題になりますが、重要な単純化が必要です。各行または列内で、端点をソートし、連続する占有点間の隣接性を考慮すると、区間は互いに素になります。 すべてのペアを考慮する代わりに、並べ替えられた順序で連続して表示される城が分離されていることを確認するだけで済みます。 

これにより、問題は各行と列を個別にスキャンし、間に既存の障害物がない連続した城の最大セグメントを特定し、連続する占有セル間のギャップに障害物を挿入できるかどうかを判断することに軽減されます。 

全体的な問題は、セグメントごとの実現可能性をチェックし、セグメント間にブロッカーがない 2 つの城が含まれていることを確認するために必要な最小カット数をカウントすることになります。 必要な各カットは、特定の開いたギャップに少なくとも 1 つの障害物を配置することに対応し、行と列にわたる重なり合う制約を一貫して解決する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ペアごとのブルート フォース ブロッキング | O(n^2・k) | O(n + m) | 遅すぎる |
 | 貪欲なカットによる行/列のセグメンテーション | O((n + m) log(n + m)) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 この解決策は、行と列を独立して扱いながら、共有占有点を注意深く考慮する場合に最も理解しやすくなります。 

まず、占有されているすべてのセルを行と列ごとにグループ化します。 各行内で、すべてのポイント (城と障害物) を列インデックスで並べ替えます。 同じことが行インデックスによって列ごとに行われます。 

次に、各行に沿って可視性をシミュレートします。 

1. 各行について、城または障害物を含むすべての列を収集します。 並べ替えてください。 
2. ソートされたリストをスキャンして、間に障害物がない連続した城を特定します。 このフィルタリングされたシーケンスで 2 つの城が連続している場合、つまりそれらの間に厳密に障害物がない場合、それらは現在互いに攻撃しているため、そのセグメントをブロックする必要があります。 
3. 連続するこのような競合するペアごとに、それらの間の間隔を少なくとも 1 つの新しい障害物の配置が必要であるとマークします。 

同じプロセスが各列に対して繰り返され、垂直方向に必要なブロック間隔のセットが生成されます。 

この時点で、制約を統一する必要があります。 各ブロック要件は、特定の行間隔または列間隔内に少なくとも 1 つの空のセルが必要であることに対応します。 単一の配置された障害物が複数の間隔の交差点にある場合、複数の要件を満たすことができます。 したがって、各要件をグリッド セルの間隔として扱いますが、まだ占有されていない候補セルに限定します。 

1. 各行と列の連続する占有点の間にあるすべての空きセルを列挙します。 このような自由セルはそれぞれ、ブロッカーとして機能する可能性があります。 
2. ブロッキング要件と空きセル候補の間に二部関係を構築します。候補セルは、要件の間隔内にある場合に要件をカバーします。 
3. 次に、この 2 部構造の最小打撃集合を解きます。 この構造は間隔ベースで小規模 (合計ポイント ≤ 400) であるため、カバーされていない要件の最大数をカバーするセルを貪欲に選択し、最も残っている競合を解決するセルを常に選択できます。 
4. すべての要件が満たされるか、有効なセルが残りの要件を満たすことができないまで続行します。その場合、回答は不可能です。 

すべての要件が直線上の間隔であり、その中にある候補点が占有位置のソート順によって引き起こされる層状構造を形成するため、貪欲な方法が機能します。 各選択は、カバーされていない間隔を単調に減少させ、普遍的に最良の候補を遅らせる必要のある最適解はありません。 

### なぜ効果があるのか

各攻撃は、障害物を取り除くことによって引き起こされる可視性グラフ内で隣接する 2 つの城に対応します。 有効なソリューションでは、すべての隣接間隔内に少なくとも 1 つのブロッキング ポイントを挿入する必要があります。 これらの間隔は、行または列に沿った連続した占有点によって純粋に定義されます。 実行可能な解決策は、許可された空のセルを使用して、これらの間隔にわたって正確にヒット セットを実行することです。 

貪欲な選択は、1D 順序付けから継承された構造化された方法でのみ間隔が重なり、要素の数が十分に少ないため、局所的に最適なカバレッジの決定が全体的な最適性を破壊しないため、有効です。 維持される不変条件は、各配置の後、すべての未解決の競合は残りのカバーされていない構造上の間隔として表現可能であり、将来の選択は間隔の範囲を超えた過去の任意の決定に依存しないということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        castles = []
        for _ in range(n):
            r, c = map(int, input().split())
            castles.append((r, c))

        m = int(input())
        obstacles = set()
        for _ in range(m):
            r, c = map(int, input().split())
            obstacles.add((r, c))

        row = defaultdict(list)
        col = defaultdict(list)

        for r, c in castles:
            row[r].append(c)
            col[c].append(r)

        bad_intervals = []

        for r, cols in row.items():
            cols.sort()
            occupied = set()
            for c in cols:
                occupied.add(c)

            # check consecutive castles with no obstacle between
            k = len(cols)
            for i in range(k):
                for j in range(i + 1, k):
                    c1, c2 = cols[i], cols[j]
                    ok = False
                    for c in occupied:
                        if c1 < c < c2 and (r, c) in obstacles:
                            ok = True
                            break
                    if not ok:
                        bad_intervals.append((r, c1, c2))

        for c, rows in col.items():
            rows.sort()
            occupied = set()
            for r in rows:
                occupied.add(r)

            k = len(rows)
            for i in range(k):
                for j in range(i + 1, k):
                    r1, r2 = rows[i], rows[j]
                    ok = False
                    for r in occupied:
                        if r1 < r < r2 and (r, c) in obstacles:
                            ok = True
                            break
                    if not ok:
                        bad_intervals.append((c, r1, r2, "col"))

        # collect candidate empty cells (simple bounded set)
        candidates = set()
        for r, c in castles:
            pass
        for r, c in obstacles:
            pass

        # try all cells between consecutive occupied points in rows/cols
        # (simplified construction for small constraints)
        for r, cols in row.items():
            pts = sorted(set(cols))
            for i in range(len(pts) - 1):
                c1, c2 = pts[i], pts[i + 1]
                if c2 - c1 > 1:
                    for c in range(c1 + 1, c2):
                        if (r, c) not in obstacles and (r, c) not in set(castles):
                            candidates.add((r, c))

        for c, rows in col.items():
            pts = sorted(set(rows))
            for i in range(len(pts) - 1):
                r1, r2 = pts[i], pts[i + 1]
                if r2 - r1 > 1:
                    for r in range(r1 + 1, r2):
                        if (r, c) not in obstacles and (r, c) not in set(castles):
                            candidates.add((r, c))

        bad = set()
        for x in bad_intervals:
            bad.add(x)

        used = []
        bad = list(bad)

        covered = [False] * len(bad)

        def covers(cell, interval):
            r, a, b = interval[:3]
            if len(interval) == 3:
                return cell[0] == r and a < cell[1] < b
            else:
                return cell[1] == r and a < cell[0] < b

        candidates = list(candidates)

        while True:
            best = -1
            best_cell = None

            for i, cell in enumerate(candidates):
                cnt = 0
                for j, interval in enumerate(bad):
                    if not covered[j] and covers(cell, interval):
                        cnt += 1
                if cnt > best:
                    best = cnt
                    best_cell = cell

            if best <= 0:
                break

            used.append(best_cell)
            for j, interval in enumerate(bad):
                if covers(best_cell, interval):
                    covered[j] = True

        if not all(covered):
            print(-1)
        else:
            print(len(used))
            for r, c in used:
                print(r, c)

for _ in range(1):
    pass

```コードはまず行と列で城を分離し、次に既存の障害物によって分離されていない城のペアを検出します。 有効なブロッカーはそのようなギャップ内に存在する必要があるため、占有座標間のギャップのみから候補セルを構築します。 最後に、すべてが満たされるか、進行が不可能になるまで、最も未解決のブロッキング要件をカバーするセルを貪欲に選択します。 

重要な点は、連続する占有座標によって引き起こされる間隔に注目を限定することで、候補の生成で 10^9 グリッド全体が回避されることです。 もう 1 つの重要な点は、空のセルのみが許可されるため、城と既存の障害物の両方を明示的に除外することです。 

## 実用的な例

 ### 例 1

 列 1、4、8 に城があり、障害物がない行を考えてみましょう。 

最初はすべてのペアが競合する可能性があります。 

| ステップ | 間隔セット | 選ばれた候補者 | 残りの競合 |
 | --- | --- | --- | --- |
 | 1 | (1,4)、(4,8)、(1,8) | (r,5) | (4,8) のみ |
 | 2 | (4,8) | (r,6) | なし |

 最初に選択されたセルは、左側のセグメントが 1 と 4 の間にあり、また 1 と 8 の間にあるため、左側のセグメントに関係するすべての競合をブロックします。その後、右側のセグメントだけが残るため、別のカットが必要になります。 

これは、貪欲なカバレッジが機能する理由を示しています。中央のギャップ セルを選択すると、重複する複数の間隔を一度に除去できます。 

### 例 2

 2 行:

 行 1: (1,1)、(1,3) の城

 行 2: (2,2)、(2,4) に城、(2,3) に障害物

 行 1 には競合間隔 (1,1,3) があります。 (2,3) がすでに可視性をブロックしているため、行 2 には競合はありません。 

| ステップ | 不正な間隔 | 候補者 | 結果 |
 | --- | --- | --- | --- |
 | 1 | (1,1,3) | (1,2) | 解決済み |

 行 2 は何も寄与しないため、必要な障害は 1 つだけです。 

これは、既存の障害物が可視構造に完全に統合されており、新しい配置の必要性を排除できることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2 + m^2 + C log C) | 行/列ごとのペア スキャンと候補の列挙 |
 | スペース | O(n + m + C) | グループ化された座標、間隔、および候補のストレージ |

 この制約により、n と m が十分小さく保たれるため、各テスト ケースの 2 次スキャンが実際に許容されます。 主な要因は行および列ごとに競合を列挙することですが、テスト ケース全体の合計入力サイズには上限があり、ソリューションが制限内に収まることが保証されます。

 ## 特殊なケース

 重要なエッジ ケースは、城が並べ替えられた順序で隣接しているが、占有点が介在しているためにそれらの間に空の整数セルがない場合に発生します。 この場合、候補セルは存在せず、区間に利用可能なヒット ポイントがないため、アルゴリズムは不可能であることを正確に識別します。 

もう 1 つのケースは、複数の競合が単一の最適なブロック位置を共有する場合です。 たとえば、(r,1)、(r,5)、(r,9) にある城は重複する間隔を生成しますが、そのセルが空いていれば (r,5) に単一の障害物を配置することですべて解決できます。 貪欲な選択では、当然そのような高カバレッジのセルが最初に優先され、選択されると、そのセルを横切るすべての間隔が同時に解決済みとマークされ、最適な動作に一致します。 

最後の微妙なケースは、行と列の制約が同じセルに対して競合する場合です。 同じ候補セルが水平間隔と垂直間隔の両方に対して評価されるため、両方のタイプの競合を同時に満たすことができます。 カバレッジ機能は両方を対称的に扱い、単一の配置で重複することなく混合方向の脅威を解決できるようにします。
