 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースは数直線上の一連の閉じたセグメントで構成されており、各セグメントに k 色のいずれかを割り当てる必要があります。 制限は、2 つのセグメントが同じ色を共有する場合、それらは線上のどの点でも交差してはいけないということです。 言い換えれば、同じ色のセグメントは、互いに素な間隔の集合を形成する必要があります。 

このタスクは、有効なカラーリングがいくつ存在するかをカウントすることです。少なくとも 1 つのセグメントに異なるカラーが割り当てられている場合、2 つのカラーリングは異なるものとみなされます。 

条件を再解釈する便利な方法は、エッジが重なりを表すグラフ内の頂点としてセグメントを考えることです。 有効なカラーリングは、この間隔グラフ内で各カラー クラスが独立したセットとなるようにカラーを割り当てます。 

制約は大きく、すべてのテスト ケースにわたるセグメントの合計数は最大 5 × 10^5 であり、k は 10^9 に達する可能性があります。 これにより、セグメントごとに色を列挙したり、重複部分に対して指数関数や二次関数のチェックを実行しようとするソリューションは即座に除外されます。 O(n^2) のオーバーラップ検出でも遅すぎるため、問題をソートと線形または線形に近いスキャンに軽減する構造が必要です。 

セグメントがチェーンで重なっている場合、素朴な微妙な落とし穴が現れます。 たとえば、セグメント A は B と重なり、B は C と重なりますが、A は C と重なりません。不注意なアプローチでは、各重なりを独立して扱い、ローカル制約で十分であると仮定して有効な割り当てを過剰にカウントする可能性がありますが、実際には色の制約が接続された重なりコンポーネントを通じて伝播します。 

もう 1 つのエッジ ケースは、複数のセグメントが同じエンドポイントを共有しているか、ネストされている場合です。 たとえば、[1,10]、[2,3]、[4,5] は入れ子構造を形成しており、ペアごとの重複を単純にカウントすると実際の禁止構造が誤って表現されます。 正しい解決策は、ローカルのペアごとの競合だけではなく、グローバル構造に依存します。 

## アプローチ

 総当り攻撃を試みる場合は、n 個のセグメントのそれぞれに 1 から k までの色を割り当て、合計で k^n 個の割り当てを与えます。 割り当てごとに、色を共有するセグメントのすべてのペアをチェックし、それらが重複していないことを確認する必要があります。 重複をチェックするには、割り当てごとに最悪の場合 O(n^2) 回の比較が必要となるため、総コストは O(k^n · n^2) になりますが、これは小さな n の場合でも完全に実行不可能です。 

重要な観察は、制約の構造が線に沿ってセグメントがどのように重なるかによって完全に支配され、エンドポイントをソートするとこの構造が単純になるということです。 セグメントを左の端点でソートすると、アクティブな重なり合うセグメントを維持しながら、左から右にスイープできます。 どの時点でも、重複するセグメントのセットは区間グラフ内でクリークを形成します。これは、セグメントがすべて異なる色を受け取る必要があることを意味します。 

これにより、問題は動的制約に変わります。つまり、セグメントの開始時に、現在アクティブなすべてのセグメントとは異なる色を選択する必要があります。 セグメントが終了すると、色が解放されます。 したがって、各セグメントの有効な選択肢の数は、現在そのセグメントと重なっているセグメントの数にのみ依存します。 

左端点の昇順にセグメントを処理し、アクティブな右端点のデータ構造を維持する場合、各ステップでの禁止色の数は、アクティブな重複セグメントの数と正確に一致します。 これにより、カウントが各セグメントでの選択肢の積に変換されます。各項は (k から現在のアクティブなカウントを引いたもの) になります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(k^n · n^2) | O(n) | 遅すぎる |
 | スイープ ラインのカウント | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 左側のエンドポイントの昇順にセグメントを処理し、以前に開始されたセグメントがまだアクティブであることを維持します。

1. すべてのセグメントを左の端点で並べ替えます。 これにより、セグメントが常に数直線上で始まる順序で表示されるようになります。 
2. アクティブなセグメントを正しいエンドポイント順に追跡する構造を維持します。 これにより、現在のセグメントが開始する前にすでに終了したセグメントを効率的に削除できます。 
3. 回答変数を 1 として初期化します。 
4. ソートされた順序でセグメントをスイープします。 セグメント i を処理する前に、右端が左端よりも厳密に小さいアクティブなセグメントをすべて削除します。これは、それらのセグメントが今後何にも重ならないためです。 
5. 現在アクティブなセグメントの数を d とします。 すべてのアクティブなセグメントは以前に開始され、まだ終了していないため、これらはまさに現在のセグメントと重複するセグメントです。 
6. 現在のセグメントは、d 個のすべてのアクティブなセグメントとは異なる色を選択する必要があるため、(k − d) 個の有効な選択肢があります。 998244353 を法として、答えに (k − d) を掛けます。 
7. 現在のセグメントをアクティブな構造に挿入します。 

重要な点は、アクティブ カウントがエンドポイントを通過した場合にのみ変化するため、各セグメントは開始時の状態に基づいて 1 つの乗算係数だけを寄与することです。 

### なぜ効果があるのか

 すべてのアクティブなセグメントは先に開始され、まだ終了していないため、セグメントが処理される時点で、すべてのアクティブなセグメントがセグメントと交差します。 現在のセグメントに割り当てられている色はすべて、アクティブなセグメントと異なっていなければなりません。そうでないと、重なり合う領域で競合が発生します。 

逆に、すでに終了したセグメントは現在のセグメントと重なることができないため、制限はありません。 これは、禁止色のセットがアクティブ セットのサイズによって正確に決定され、他のグローバル履歴は関係ないことを意味します。 有効な選択のすべてのセグメントの積は、すべての有効な割り当てを正確にカウントします。これは、各セグメントの選択が以前の割り当てに基づいて独立して条件付けされており、スイープによってすべての制約が 1 回だけ強制されることが保証されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        segs = [tuple(map(int, input().split())) for _ in range(n)]
        
        # sort by left endpoint
        segs.sort()
        
        # active segments stored as (r)
        import heapq
        active = []
        
        ans = 1
        i = 0
        
        for l, r in segs:
            # remove ended segments
            while active and active[0] < l:
                heapq.heappop(active)
            
            d = len(active)
            ans = ans * (k - d) % MOD
            
            heapq.heappush(active, r)
        
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションはセグメントを並べ替えて、出現の時系列順に処理します。 ヒープには、現在アクティブなセグメントの右エンドポイントが格納されます。 右端が現在の左端よりも小さいセグメントは、重なり合わなくなるため削除されます。 

変数`d`現在のセグメントと重複するセグメントの数を表します。 乗算ステップは、これらすべてのアクティブなセグメントとは異なる色の選択をエンコードします。 モジュロ演算により、制約内に確実に収まるようになります。 

微妙な点は、色を明示的に保存することは決してないということです。 禁止されたセットのサイズは以前の代入によって完全に決定されるため、各ステップに存在する選択肢の数のみをカウントします。 

## 実用的な例

 重複する構造を持つ単純なケースを考えてみましょう。 

入力:

 n = 3、k = 3

 セグメント: [1,4]、[2,5]、[6,7]

 ソート順は変更されません。 

| セグメント | | 前にアクティブ d | 選択肢 (k - d) | | 以降にアクティブになります
 | --- | --- | --- | --- | --- |
 | [1,4] | 0 | 0 | 3 | [1,4] |
 | [2,5] | 1 | 2 | 1 | [1,4],[2,5] |
 | [6,7] | 2 → 0 | 0 | 3 | [6,7] |

 答えは3×1×3＝9となります。 

このトレースは、オーバーラップによって時間的に局所的にのみ制約が増加する様子と、終了セグメントによって制約が完全に削除される様子を示しています。 

次に、ネストされたセグメントについて考えてみましょう。 

入力:

 n = 3、k = 4

 セグメント: [1,10]、[2,3]、[4,5]

 | セグメント | | 前にアクティブ d | 選択肢 | | 以降にアクティブになります
 | --- | --- | --- | --- | --- |
 | [1,10] | 0 | 0 | 4 | [1,10] |
 | [2,3] | 1 | 1 | 3 | [1,10]、[2,3] |
 | [4,5] | 2 | 2 | 2 | [1,10]、[4,5] |

 答え = 4 × 3 × 2 = 24。 

これにより、大きな間隔がすべての内側のセグメントと重なるため、ネストされたセグメントが制約を正しく蓄積していることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | ソートが優先され、ヒープ操作はセグメントごとに O(log n) です。 
| スペース | O(n) | ヒープはアクティブな間隔を保存します。 

この制約では、合計で最大 5 × 10^5 のセグメントが許可されるため、O(n log n) のソリューションで十分です。 各セグメントの挿入と削除が 1 回だけ行われるため、ヒープ操作の効率が維持されます。 

## テストケース```python
import sys, io

MOD = 998244353

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    import heapq
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        segs = [tuple(map(int, input().split())) for _ in range(n)]
        segs.sort()
        
        active = []
        ans = 1
        
        for l, r in segs:
            while active and active[0] < l:
                heapq.heappop(active)
            d = len(active)
            ans = ans * (k - d) % MOD
            heapq.heappush(active, r)
        
        out.append(str(ans))
    
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのセグメントが互いに素である場合です。 [1,2]、[3,4]、[5,6] のような入力の場合、アクティブなオーバーラップは決して発生しないため、すべてのセグメントには常に k 個の選択肢があるはずです。 このアルゴリズムは各ステップでヒープを空に保ち、毎回 d = 0 を与え、k^n を正しく計算します。 

もう 1 つの特殊なケースは、完全なネストです。 セグメント [1,10]、[2,9]、[3,8] の場合、新しいセグメントごとにアクティブ セットが増加し、前のセグメントが期限切れにならなくなり、その後、後のセグメントが処理されます。 ヒープ サイズは単調に増加し、アルゴリズムによって使用可能な色が正しく減少します。 

3 番目のエッジ ケースは、[1,5]、[2,3]、[4,6] など、オーバーラップがインターリーブの開始と終了を行う密な連鎖です。 ヒープは [4,6] を処理する前に [2,3] を正しく削除し、現在アクティブなオーバーラップのみがカウントに影響するようにし、乗算係数は履歴的な制約ではなく真の瞬間的な制約を反映します。
