 ## 解決策
 ## 問題の理解

 0 から n − 1 までのインデックスが付けられた位置の行が与えられます。最初はすべての位置が赤色でマークされます。 時間の経過とともに、1 つのポジションを繰り返し選択し、それを永久に青に反転します。 各フリップの後、センサーと呼ばれる間隔の集合を調べます。 各センサーは固定セグメント [l, r] を監視し、そのセグメント内でその時点でちょうど 1 つの位置がまだ赤である場合にのみアクティブになります。 

主な困難は、各操作の後に、どのセンサーが現在アクティブであるかに応じた値を出力する必要があることです。具体的には、すべてのアクティブなセンサーのインデックスの二乗を合計します。 さらに、反転する位置の順序は直接与えられません。 実際に反転する位置は前の出力値の法 n を使用して計算されるため、各ステップは前の答えに依存します。 

したがって、プロセスは完全にオンラインで自己参照です。すべての操作で状態が変更され、その状態によって次の操作が決定され、変更のたびにすべてのセンサーにわたるグローバルな集計を再計算する必要があります。 

この制約により、私たちは構造主導のソリューションに追い込まれます。 n と m は両方とも最大 5 × 10^5 にすることができ、テスト ケースにわたるそれらの合計も 5 × 10^5 によって制限されます。 これにより、操作ごとにすべてのセンサーを繰り返しスキャンするものは直ちに除外されます。 削除のたびに各センサーの赤カウントを再計算する単純なアプローチでは、O(nm) が必要になりますが、これは実現可能な限界をはるかに超えています。 

さらに微妙な問題は動的な依存関係です。中間の答えが間違っていると、その後のすべての操作が変更されてしまいます。 これは、たとえ小さな非効率や近似誤差であっても、後で反転される誤った位置に連鎖する可能性があることを意味します。 

素朴な考えを打ち破る典型的なエッジケースは、多くのセンサーが重なり合う場合です。 たとえば、すべてのセンサーが範囲全体をカバーしている場合、すべての削除がすべてのセンサーに影響を及ぼし、毎回すべてのカウントを再計算することは致命的になります。 もう 1 つの失敗ケースは、長さ 1 の間隔です。これらのセンサーは、単一の位置がまだ赤である場合にのみアクティブになり、その位置が削除されたときに正確に状態を反転するため、正確さは正確なイベント タイミングに依存します。 

## アプローチ

 直接シミュレーションは概念的には簡単です。 一連の赤色のポジションを維持します。 センサー間隔ごとに、現在含まれている赤色の位置の数を計算します。 すべての操作の後、すべてのセンサーをスキャンし、カウントが 1 に正確に等しいセンサーを確認し、それらのインデックスの 2 乗を合計します。 これは定義に直接従っているため、正しいです。 ただし、1 つの位置を削除した後にすべてのセンサー カウントを更新するには、間隔ごとにチェックする必要があり、総作業量は O(nm) になります。 

ボトルネックは、単一の削除された位置が、その位置を含む間隔に含まれるすべてのセンサーに影響を与えることです。 すべてのセンサーをスキャンするのではなく、特定の位置をカバーするセンサーを正確にすばやく取得する方法が必要です。 

これは視点を逆転させることを示唆しています。 「センサーごとに、センサーに含まれる赤い位置の数を維持する」と考えるのではなく、「位置ごとに、どのセンサーに含まれるかを把握する」と考えます。 位置が削除されると、その位置をカバーするセンサーのみが更新されます。 

これを効率的にするには、範囲包含クエリをサポートする構造が必要です。 位置に関する標準的なセグメント ツリーを使用すると、すべてのセンサー間隔を O(log n) ノードに分解できます。 各ノードは、そのセグメントを完全にカバーするセンサーのリストを保存します。 次に、位置が削除されると、ルートからリーフまで移動し、そのパスに沿ったリストのみを更新します。 すべてのセンサーは O(log n) ノードに保存されるため、各センサーはすべての更新にわたって合計 O(log n) 回処理されます。

各センサーについて、現在の残りの赤色カウントを維持します。 最初は、これは単に間隔の長さです。 ポジションが削除されると、そのポジションをカバーするすべてのセンサーのカウンターがデクリメントされます。 センサーはカウンターが 1 になると正確にアクティブになり、1 から離れるとアクティブを停止します。アクティブなセンサーのインデックスの二乗の累計を維持します。

 | --- | --- | --- | --- |
 | ブルートフォース再計算 | O(nm) | O(m) | 遅すぎる |
 | セグメントツリー間隔分解 | O((n + m) log n) | O(m log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 位置 [0, n − 1] にわたるセグメント ツリーを維持します。 各ノードは、そのノード セグメントを完全にカバーする間隔を持つセンサーのリストを保存します。 各センサー i について、r − l + 1 として初期化された現在の残りの赤カウント cnt[i] も維持します。 

また、センサーが現在アクティブであるかどうかに関するブール条件または暗黙的な条件、つまり cnt[i] == 1 と、すべてのアクティブなセンサーの i^2 の合計であるグローバル値 V も維持します。 

### ステップ

 1. 位置にセグメント ツリーを構築します。 すべてのセンサー間隔 [l, r] について、その間隔が完全にカバーするすべてのセグメント ツリー ノードにそのインデックスを挿入します。 これにより、[l, r] 内のすべての位置がトラバース中にこのセンサーを「認識」するようになります。 
2. 各センサーの cnt[i] = r_i − l_i + 1 を初期化します。 次に、すべてのセンサーを 1 回スキャンして、cnt[i] == 1 ですべてのセンサーに i^2 を加算することで、v0 の初期 V を計算します。 
3. 各操作ステップについて:

 1. (a0_i + v_{i−1}) mod n を使用して実際の位置 a_i を計算します。 
2. 位置 a_i を削除済みとしてマークします。 
3. a_i のルートからリーフまでセグメント ツリー パスをたどります。 
4. 訪問したすべてのノードで、そのノードに保存されているすべてのセンサーを反復処理し、それらの cnt をデクリメントします。 
5. センサーが cnt == 2 から cnt == 1 に変化するたびに、i^2 を V に加算します。 
6. センサーが cnt == 1 から cnt == 0 に変化するたびに、V から i^2 を減算します。 
7. V を v_i として出力します。 

重要な考え方は、カウントを最初から再計算しないということです。 各削除は、削除された位置を実際に含むセンサーのみに触れます。 

### なぜ効果があるのか

 すべてのセンサー間隔は O(log n) 個のセグメント ツリー ノードに分解され、その結合は間隔を正確にカバーします。 したがって、位置が削除されるたびに、その位置をカバーするノードを正確に訪問し、その位置をカバーするすべてのセンサーがそれらのノードの少なくとも 1 つに表示されます。 各センサーは制限された数のノードに保存されるため、すべてのデクリメント操作は影響を受ける削除ごとに 1 回だけ考慮され、センサーが見逃されたり、意図した多重度を超えて誤って二重カウントされることはありません。 不変条件は、cnt[i] がその間隔内の残りの赤色位置の数と常に等しいということです。そのため、条件 cnt[i] == 1 は、各ステップでアクティブなセンサーを正確に特徴付けます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n_max = 5 * 10**5

def solve():
    n, m = map(int, input().split())
    
    seg = [[] for _ in range(4 * n)]

    l = [0] * (m + 1)
    r = [0] * (m + 1)
    cnt = [0] * (m + 1)
    active = [False] * (m + 1)

    def add(node, nl, nr, ql, qr, idx):
        if ql <= nl and nr <= qr:
            seg[node].append(idx)
            return
        mid = (nl + nr) // 2
        if ql <= mid:
            add(node * 2, nl, mid, ql, qr, idx)
        if qr > mid:
            add(node * 2 + 1, mid + 1, nr, ql, qr, idx)

    for i in range(1, m + 1):
        l[i], r[i] = map(int, input().split())
        add(1, 0, n - 1, l[i], r[i], i)
        cnt[i] = r[i] - l[i] + 1

    v = 0
    for i in range(1, m + 1):
        if cnt[i] == 1:
            v += i * i

    a0 = list(map(int, input().split()))
    used = [False] * n

    def remove(pos, node, nl, nr):
        nonlocal v
        for idx in seg[node]:
            if not active[idx]:
                # entering potential state
                pass

            cnt[idx] -= 1

            if cnt[idx] == 1:
                v += idx * idx
                active[idx] = True
            elif cnt[idx] == 0:
                if active[idx]:
                    v -= idx * idx
                active[idx] = False

        if nl == nr:
            return

        mid = (nl + nr) // 2
        if pos <= mid:
            remove(pos, node * 2, nl, mid)
        else:
            remove(pos, node * 2 + 1, mid + 1, nr)

    # v0
    out = [v]

    for i in range(n):
        ai = (a0[i] + v) % n
        remove(ai, 1, 0, n - 1)
        out.append(v)

    print(*out)

T = int(input())
for _ in range(T):
    solve()
```この実装では、各ノードがそのノード間隔を完全にカバーするセンサーを格納するセグメント ツリーを構築します。 削除中、削除された位置に対応するリーフまでのパスをたどり、関連するセンサー リストのみを更新します。 

cnt アレイは、各センサー内に赤い位置がいくつ残っているかを追跡します。 アクティブ ロジックにより、「赤が 1 つだけ」状態への遷移とその状態からの遷移のみが答えに影響を与えることが保証されます。 これにより、すべてのセンサーを繰り返しスキャンする必要がなくなります。 

エンコードされた依存関係は、増分的に維持される前の出力 v を使用して各削除位置を再計算することによって処理されます。

 ## 特殊なケース

 重要なエッジ ケースは、センサー間隔の長さが 1 の場合です。この場合、cnt は 1 から始まり、すぐにアクティブになることを意味します。 その唯一の赤い位置が削除されるとすぐに、cntは0になり、それは答えから削除されなければなりません。 遷移ロジックは cnt の 1 から 0 への変化を減算イベントとして明示的に扱うため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジケースは、全範囲をカバーするセンサーです。 削除されるたびに影響を受けるため、cnt は段階的に減少し、最終的には赤い位置が 1 つだけ残ったときにちょうど 1 回だけ 1 に達します。 セグメント ツリーにより、すべての削除が削除された位置ごとに 1 回だけこのセンサーに触れることが保証されるため、カウンターの一貫性が維持されます。 

最後に、v に対するエンコードされた依存関係は、初期のミスが連鎖することを意味します。 v は操作のたびに段階的に更新されるため、cnt 更新の正確性は将来のすべての a_i 値の正確さを直接保証し、真のプロセスからの逸脱を防ぎます。
