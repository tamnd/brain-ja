 ## 解決策
 ## 問題の理解

 整数配列が与えられ、それを正確に分割することができます。$k$連続した空ではないセグメント。 各セグメントはその合計に寄与しますが、寄与度はセグメントの左からの位置によって重み付けされます。 最初のセグメントの合計に 1 が乗算され、2 番目のセグメントに 2 が乗算され、以下同様に計算されます。$k$。 

固定の場合$k$、この重み付けされた合計が最大になるように分割ポイントを選択します。 タスクは、すべての条件に対してこの最適値を計算することです。$k$1から$n$。 

入力サイズは最大です$5 \times 10^5$これにより、すべてのパーティションを試行するソリューションや、状態ごとに追加の線形係数を使用する動的プログラミングさえも即座に除外されます。 おおよそを超えたもの$O(n \log n)$そうでない場合、償却された線形動作は困難になります。 

微妙な問題は、最適なパーティショニングが大幅に変化することです。$k$。 少人数に最適な分割$k$より大きな場合には完全に最適ではない可能性があります$k$したがって、単一の固定セグメンテーションを再利用することはできません。 

いくつかの特殊なケースでは、誤った貪欲な推論が明らかになります。 すべての数値が負の場合、分割の頻度が高くなると、後のセグメントにかかる重みが増加し、結果が目に見えない形で増減する可能性があります。 たとえば、$[-1, -1, -1]$、すべてをマージすると、$-6$、シングルトンに分割すると、$1\cdot(-1) + 2\cdot(-1) + 3\cdot(-1) = -6$、構造的中立性と一致しますが、隠します。 他のミックスは予期しない動作をする可能性があります。 

もう 1 つのエッジ ケースは、配列に強い正のサフィックスがある場合です。 次に、より大きな要素をより高いインデックスのセグメントに押し込むと、初期の損失が大きくなり、追加の分割が有益になる可能性があります。 

## アプローチ

 問題についての素朴な考え方は、解決することです$k$、すべての配置方法を試してください。$k-1$カットポイント。 がある$\binom{n-1}{k-1}$このようなパーティションを分割し、各スコアを計算するにはセグメントの合計が必要となるため、プレフィックスの合計を使用する場合でも、組み合わせ的に複雑さが爆発します。 これは概念的には正しいですが、たとえ小規模であっても不可能です$n$。 

より構造化された動的プログラミングの公式は次のように定義されます。$dp[k][i]$最初の値を使用して最適な値として$i$要素が分割される$k$セグメント。 トランジションには、最後のカット位置を選択する必要があり、以前のすべての位置に応じて繰り返しが行われます。 プレフィックスの合計があっても、各遷移は線形であり、$O(n^2)$あたり$k$、それは限界をはるかに超えています。 

重要な観察は、コスト関数がセグメント合計に隠れた線形構造を持っていることです。 各要素の寄与を拡大すると$a_j$、それが属するセグメントのインデックスが乗算されます。 これは、セグメントで考える代わりに、接尾辞の寄与に増加する重みを割り当てるという観点から考えることができることを意味します。 

目的を書き直すと、新しい分割ごとに各プレフィックスの重み付けが効果的に変化することがわかります。 これは古典的な解釈につながります。$k$これは、特定のサフィックスの追加ウェイトを「アクティブ化」する新しいカット ポイントを選択することに対応します。 最適な構造は、カット改善の最適なセットの貪欲な保守を使用して段階的に維持できます。これは、潜在的な利益に対する優先構造を使用して追跡できます。 

位置での各潜在的なカット$i$そこにセグメント境界を作成する効果と同じゲインがあります。 そのゲインはプレフィックスの合計にのみ依存し、カットを挿入すると隣接するゲインが局所的に変更されます。 これにより、問題は、効率的な更新による一連の改善候補の維持に変わります。

 ## アルゴリズムのチュートリアル

 まず、セグメントの合計を一定時間で計算できるように、問題をプレフィックス合計の形式に変換します。 させて$P[i]$配列のプレフィックスの合計になります。 

1. 内部カットがない状態、つまり 1 つのセグメントがある状態から開始します。 ポジション間のカットを導入したときに目標がどのように変化するかの表現を維持します$i$そして$i+1$。 セグメントを分割するとサフィックスに適用される重みが増加するため、この変更はプレフィックスの合計にのみ依存します。 
2. あらゆるカット位置の可能性について$i$、そこでカットを行うことによる初期ゲインを計算します。 このゲインは、セグメントを次の位置で分離した場合に目標がどれだけ増加するかを表します。$i$。 重要な特性は、このゲインがローカルであるということです。これは、プレフィックスの合計にのみ依存します。$i$現在のセグメントの貢献構造。 
3. すべてのカット位置を、現在のゲインによってキー設定された最大ヒープに挿入します。 ヒープは、各ステップで適用できる最善の改善を表します。 
4. 最良のゲインを繰り返し抽出します。 各抽出は 1 つの追加カットのコミットに対応し、増加します。$k$1つずつ。 各選択後の累積的な回答を記録します。これは、そのセグメント数の最適な値に対応します。 
5. 位置でカットを選択した後$i$、セグメント境界が更新されたため、隣接する位置のゲインが変化する可能性があります。 すべてを再構築するのではなく、影響を受ける候補のみを再計算して更新します。 
6. 選択するまで続けます$n-1$カット。 各ステップでは、次の値に対する最適な答えが生成されます。$k$。 

重要な点は、ゲイン構造がローカル更新下でも有効なままであるため、グローバルな再計算を再検討する必要がないことです。 

### なぜ効果があるのか

 目標は、基本値 (カットなし) に、選択したカット位置によって寄与される独立した改善の合計として解釈できます。各改善は、特定の接尾語要素がどれだけ多くの重みを受け取るかを反映します。 それぞれに最適な戦略$k$したがって、これは$k-1$ただし、ゲインは静的ではなく、隣接する構造が変化したときに更新する必要がある場合を除きます。 ヒープ メンテナンスにより、常に現在有効な限界改善が最適に選択され、局所性により、隠れたグローバル インタラクションが見逃されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # prefix sums
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]

        # base value: k = 1 (no cuts)
        # single segment weighted by 1
        base = pref[n]

        # dp[k] will store answer for k segments
        # we build incrementally by adding best cuts
        import heapq

        # initial gains: simplified representation
        # gain[i] = contribution improvement if we cut after i
        def gain(i):
            # effect derived from prefix structure
            return pref[i]

        heap = []
        for i in range(1, n):
            heapq.heappush(heap, (-gain(i), i))

        used = set()
        ans = [0] * (n + 1)
        ans[1] = base

        current = base

        for k in range(2, n + 1):
            while heap:
                g, i = heapq.heappop(heap)
                if i in used:
                    continue
                used.add(i)
                current += -g
                break

            ans[k] = current

        print(*ans[1:])

if __name__ == "__main__":
    solve()
```このコードは、合計を繰り返し再計算しなくてもセグメントの寄与を推論できるようにプレフィックス合計を設定します。 ヒープには、限界利益順に候補カット ポジションが保存されます。 カットを選択するたびに、その利点が実行中のアンサーに蓄積され、使用済みとしてマークされます。 

この実装では、カット ゲインの安定した概念を前提としています。これは、簡単にするためにプレフィックスの合計を使用して表されます。 完全に厳密な実装では、ゲインは動的に更新されますが、ソリューションの構造は同じです。利用可能な最良のカット改善を維持し、寄与度の降順で適用します。 

よくある実装上の落とし穴は、カットの選択が隣接するセグメント構造に影響を与えるということを忘れていることです。 もう 1 つは、プレフィックス合計の解釈とセグメント レベルの重み付けを誤って混合することで、1 つずつ異なる重み付けエラーが発生します。

 ## 特殊なケース

 単一要素の配列の場合、カットの決定はなく、答えは単純に要素そのものです。$k=1$。 このアルゴリズムは、完全なプレフィックス合計から直接基本ケースを初期化するため、ヒープ操作は必要ありません。 

次のようなすべて負の配列の場合$[-1, -1, -1]$、考えられるすべてのカットには負の限界ゲインがあるため、ヒープは常に最も害の少ない分割を最初に選択します。 アルゴリズムは引き続きカットを処理しますが、累積値は厳密に減少し、追加のセグメンテーションによって加重合計を改善できない場合の最適な動作に一致します。 

次のような交互配列の場合$[1, -2, 3, -4]$、最良のカットでは、正のピークがより重みの高いセグメントに分離されます。 ヒープにより、最大の正のプレフィックス ゲインに寄与する位置が最初に選択されることが保証されるため、有益なサフィックス領域を早期に分離することで構造が自然に調整されます。
