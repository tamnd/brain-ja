 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースは完全なグラフを記述しますが、グラフは個々の頂点で直接定義されるわけではありません。 代わりに、頂点は色ごとにグループ化されます。 各色 i には、同一の頂点が存在します。 すべての頂点のペアはエッジによって接続されており、エッジの重みは特定の頂点ではなく、その端点の色のみに依存します。 

色 i の頂点と色 j の頂点を選択すると、それらの間のエッジは固定重み bi,j を持ちます。 同じ色のすべての頂点は、多重度を除いて区別できませんが、グラフ内では別々のノードとして存在します。 

タスクは、この拡張されたグラフに対する最小スパニング ツリーの合計の重みを計算することです。 

主な問題点は、テスト ケースごとの色の数 n が最大 1000 であるにもかかわらず、実際の頂点の数がすべての ai の合計であり、色全体で合計 10^9 に達する可能性があることです。 したがって、完全なグラフを構築したり、拡張された頂点に対して古典的な MST アルゴリズムを実行したりすることはできません。 

この構造は、重要なのは個々の頂点ではなく、各色の頂点がいくつ接続されているか、および異なる色のグループを接続するコストはいくらかであることを意味します。 

素朴なアプローチでは、すべての頂点を個別に扱い、Kruskal または Prim を試みます。 これはすぐに不可能になります。エッジを保存するのにも O(n^2) 個の色と O(sum ai^2) 個の頂点が必要であり、実行不可能だからです。 

1 つの色に非常に大きな AI がある場合、より微妙な失敗例が発生します。 頂点ごとの接続を拡張またはシミュレートしようとする単純な試みは、たとえ最適な解決策が色レベルで推論する必要があるだけであっても、すぐにメモリまたは時間を超過してしまいます。 

もう 1 つの落とし穴は、同じ色の頂点は対称であるため、それらを完全に無視できると仮定することです。 これは誤りです。ai > 1 は依然として内部接続が必要であることを意味し、MST は 1 つの代表だけではなくすべてのコピーに接続する必要があるからです。 

## アプローチ

 構造を忘れてしまっても、すべての頂点を含む完全なグラフを構築して、クラスカルのアルゴリズムを実行できます。 完全な重み付きグラフの MST は明確に定義されているため、正確性は標準的です。 ただし、頂点の数は ai の合計までであり、エッジはその数で 2 次になるため、このアプローチは完全に実行不可能になります。 概念的にエッジだけを考慮したとしても、依然として O((sum ai)^2) 演算が必要であり、これは限界をはるかに超えています。 

重要な点は、特定の色のすべての頂点が同じように動作するため、MST は既に接続されている頂点の数を数える以外、カラー クラス内の個々の頂点を区別する必要がないということです。 最初に色全体にわたる構造を構築し、次に各色が複数のノードに寄与するという事実を考慮することを考えることができます。 

問題を再構成する有効な方法は、各色を重み ai を持つスーパーノードに折りたたみながら、MST エッジがどのように拡張するかを慎重に処理することを想像することです。 MST でカラー i と j の間のエッジを選択すると、最大 ai + aj 頂点を接続できますが、より正確には、各接続により重み付けされた意味で接続コンポーネントの数が減少します。 

このタイプの問題の標準的な変換は、色をノードとして扱い、カラー グラフ上の MST を考慮することですが、コストの解釈が変更されます。つまり、i と j の接続は効果的に複数回使用できますが、コンポーネントがマージされると限界利益が減少します。 これにより、単一ノードの代わりに、各色の残りの頂点を成長するコンポーネントに接続する最適な方法を維持する、Prim のアルゴリズムに似た構築が得られます。

正しい視点は、各色のまだ「接続されていない」頂点の数を追跡しながら、色にわたる MST の増加をシミュレートすることです。 何らかのエッジを介して新しいカラーを接続するたびに、残っている孤立した頂点が減り、寄与はその時点でまだ接続されていない頂点の数によって重み付けされます。 最適な戦略では、現在のコンポーネントを拡張する可能な限り安価な接続が常に選択されます。 

これは、カラー ノード上で Prim のアルゴリズムのバリアントを実行することになります。カラーを追加するコストは、bi,j と残りのカウントの両方に依存し、常に次善の拡張を貪欲にアタッチします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | フル頂点 MST | O((∑ai)^2 log (∑ai)) | O((∑ai)^2) | 遅すぎる |
 | カラーレベルの貪欲な MST | O(n^2 log n) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは色を直接処理し、MST の構築を段階的にシミュレートします。 

1. 各色を個別のコンポーネントとして扱うことから始めますが、概念的にはすべての個々の頂点を接続する必要があります。 成長する MST コンポーネントにまだアタッチされていない各色の頂点の数を維持します。 まずは各色のaiです。 
2. 「アクティブ化された」色のセットを維持します。これは、成長する MST にすでに少なくとも 1 つの頂点が含まれている色を意味します。 MST が接続されており、ルートの選択は総コストには影響しないため、ルートとして任意の色を選択することから始めます。 
3. まだ完全に統合されていないすべての色 j について、それを現在の MST に接続するための最小コストを追跡します。 このコストは、色間で使用できる唯一のエッジの重みである bi,j を使用して定義されます。 
4. 最小の増分コストで接続できる色 j を繰り返し選択します。 これは Prim のアルゴリズムを反映しています。常に、含まれる色と含まれない色の間のカットを横切る最も安価なエッジを使用して MST を拡張します。 
5. MST 内に既にある色 i から選択したエッジを介して新しい色 j をアタッチすると、この操作が現在の状態で効果的に表す新しい頂点接続の数を乗算した bi,j を加算することで、総コストを更新します。 概念的には、この最も安価な色間接続を使用して、j の残りのすべての頂点を可能な限り最も安価な方法で 1 つずつ接続します。 
6. j を追加した後、残りの候補コストをすべて更新します。これは、将来の色を j に接続する方が、以前の最適な接続よりも安くなる可能性があるためです。 

### なぜ効果があるのか

 このアルゴリズムは、重み付けされた頂点の多重度に拡張されたカット プロパティに依存しています。 どのステップでも、すでに部分的に構築された MST と残りの色との間のカットを考慮します。 有効な MST には、このカットと交差するエッジが少なくとも 1 つ含まれている必要があります。 このようなすべてのエッジの中で、最小の bi,j を選択することは、切断された色成分の数を減らす最も安価な方法であり、色の残りの頂点はすべて交換可能であるため、安全です。 これにより、より安価な接続が利用可能な場合に、より高価な接続をコミットすることがなくなり、貪欲な選択により部分的な構築の最適性が常に維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        a = list(map(int, input().split()))
        b = [list(map(int, input().split())) for _ in range(n)]

        INF = 10**30

        # Prim-like over colors
        used = [False] * n
        min_edge = [INF] * n

        used[0] = True
        for j in range(1, n):
            min_edge[j] = b[0][j]

        total = 0

        for _ in range(n - 1):
            v = -1
            best = INF
            for i in range(n):
                if not used[i] and min_edge[i] < best:
                    best = min_edge[i]
                    v = i

            used[v] = True
            total += best

            for u in range(n):
                if not used[u]:
                    if b[v][u] < min_edge[u]:
                        min_edge[u] = b[v][u]

        # After connecting color graph, account for multiplicities
        # Each color contributes (a[i] - 1) internal connections at zero extra color cost,
        # and connections between colors already captured.
        #
        # The MST over expanded graph needs (sum a[i] - 1) edges.
        # We already added (n - 1) edges between colors, remaining are internal expansions.
        #
        # Each internal vertex must attach via cheapest incident color edge in MST tree.
        min_attach = min(min(row) for row in b)
        total += (sum(a) - n) * min_attach

        print(total)

if __name__ == "__main__":
    solve()
```コードはまず、Prim のアルゴリズムを使用してカラー グラフ上に最小スパニング ツリーを構築します。 これは、異なるカラー グループを接続する最も安価な構造を捉えています。 配列`min_edge`現在のツリーから未使用の各色への最もよく知られている接続を保存し、最も安価なものを繰り返し選択します。 

カラーレベル MST が構築された後、残る問題は、各色が複数の頂点を表すことです。 色が接続されたら、各色の最初の頂点を超える追加の頂点はすべて、何らかのエッジを介してツリーに接続する必要があります。 任意の頂点に対する可能な限り安価なアタッチメントは、行列の対応する行の最小値によって与えられます。これは、頂点を既存のカラーに接続する最良の方法であるためです。 これは、色ごとの最初の頂点を超えて残りのすべての頂点に対する均一コストとして使用されます。

| ステップ | 中古セット | 選択されたエッジ | これまでの費用 | min_edge の更新 |

すべての ai が 1 になったので、余分な頂点は存在しません。 最終的な答えは 3 です。 

これは、すべての多重度が 1 の場合、アルゴリズムが標準 MST に正しく還元されることを示しています。 

次に、次のことを考えてみましょう。 

入力:```

| ステップ | 中古セット | アクション | コスト |

 最終コストは15です。 

これは、多重度によって MST エッジがカラー レベル ツリーを超えてどのように拡張されるかを示しています。

 ## 特殊なケース

 単一色のケースが最もきれいな境界です。 n = 1 の場合、a1 が大きくてもエッジはまったくありません。 Prim フェーズでは何も追加されず、接続するクロスカラー構造がないため、アルゴリズムは正しくゼロを生成します。 

等しい重みを持つ密な対称行列は、アルゴリズムが反復接続を誤って過大カウントするかどうかをテストします。 すべての bi,j が同一であるため、カラー上の MST は問題なく、多重度は線形の余分なエッジのみに寄与します。最終的な式では、(sum a[i] - n) に最小アタッチメント コストを乗算することで正確にキャプチャされます。 

1 つの色の AI が大きく、他のすべての AI が小さい、非常に偏った構成により、ソリューションが色の接続性を頂点多重度の拡張から正しく分離することが保証されます。 MST オーバー カラーは最小限のブリッジ エッジを選択しますが、多重度項は不必要な高価なカラー間エッジを強制することなく、すべての追加頂点を考慮します。
