 ## 解決策
 ## 問題の理解

 各テストケースには次の期限があります。`n`通常必要な日数とプログラム`d`終わるまでの日数。 

プログラムを実行する前に、`x`それを最適化する日々。 それらを費やした後、`x`日の場合、実行時間は次のようになります。$$\left\lceil \frac{d}{x+1} \right\rceil$$最適化と実行を同時に行うことはできないため、かかる合計時間は次のようになります。$$x + \left\lceil \frac{d}{x+1} \right\rceil$$負でない整数が存在するかどうかを判断する必要があります`x`合計時間が最大で`n`。 

制約が主な課題です。 両方`n`そして`d`と同じ大きさにすることができます`10^9`したがって、可能なすべての値を反復処理します。`x`不可能です。 1 つのテスト ケースでも、数十億の候補をチェックする必要がある場合があります。 最大 50 のテスト ケースを使用して、どのようなソリューションでも`O(d)`全く実現不可能です。 

表現$$f(x)=x+\left\lceil \frac{d}{x+1} \right\rceil$$便利な形をしています。 として`x`が増加すると、第 1 項は拡大し、第 2 項は縮小します。 最小値は、これらの効果が互いにバランスする点の近くで発生します。 その構造を悪用すると問題が簡単になります。 

いくつかの特殊なケースでは間違いが発生する可能性があります。 

考慮する：```
1
1 1
```正しい答えは、`YES`なぜなら選んでいるから`x = 0`合計時間を与える`1`。 の正の値のみをチェックするソリューション`x`失敗するだろう。 

考慮する：```
1
5 11
```答えは`NO`。 最適化は役に立ちますが、`x`合計時間を短縮します`5`それ以下。 「実行時間が小さくなるまで最適化を続ける」などの貪欲な戦略では、最小合計が保証されません。 

考慮する：```
1
1000000000 1000000000
```答えは`YES`。 大きな値を指定するには、慎重な整数演算が必要です。 固定幅の整数を使用する言語は、実装が不注意であるとオーバーフローする可能性があります。 Python はこれを自動的に処理しますが、アルゴリズムは不必要な大規模な計算を回避する必要があります。 

## アプローチ

 最も直接的なアイデアは、可能な限りの最適化量を試してみることです。`x`。 候補ごとに計算します$$x+\left\lceil \frac{d}{x+1} \right\rceil$$それが最大かどうかを確認してください`n`。 

この強引なアプローチは、あらゆる法的選択を検討するため、正しいものです。 問題はその実行時間です。 最悪の場合、`d`できる`10^9`したがって、からのすべての値をチェックします`0`に`d`1 つのテスト ケースに対して約 10 億の評価が必要になります。 それは限界をはるかに超えています。 

何かをより速く見つけるには、関数を見てください。$$f(x)=x+\left\lceil \frac{d}{x+1} \right\rceil.$$天井を少し無視すると、$$x+\frac{d}{x+1}.$$これは古典的な凸型の表現です。 最初は増えてますが、`x`除算項がすぐに低下するので役立ちます。 その後、増えていきます`x`線形項が支配的であるため、問題が発生します。 

最小値は近くで発生します$$x \approx \sqrt d - 1.$$以来`d ≤ 10^9`、 我々は持っています$$\sqrt d \le 31623.$$その観察がすべてを変えます。 最適な値は平方根付近のみであるため、約 1000 までのすべての値をテストするだけで十分です。`√d`。 これにかかるコストは、テスト ケースごとにわずか約 30,000 チェックです。 

別の見方では、Codeforces は単純な数学的な力技を意図していたということです。 もし`x`よりもはるかに大きくなります`√d`、線形項はすでにコストが高すぎるのに対し、除算項は非常にゆっくりと変化します。 最小値は平方根領域から​​遠く離れたところに隠れることはできません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(d) | お(1) | 遅すぎる |
 | 最適 | O(√d) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの場合、まず次のことを確認します。`d ≤ n`。 

プログラムが期限前にすでに終了している場合、最適化は必要なく、すぐに答えが得られます。`YES`。 
2. コンピューティング`limit = ⌊√d⌋ + 2`。 

目的関数の最小値は付近で発生します。`√d`, その点を少し超えたところを確認するだけで十分です。 
3. すべての整数について`x`から`0`に`limit`、計算する$$x+\left\lceil \frac{d}{x+1} \right\rceil.$$上限は整数演算を使用して計算できます。$$\left\lceil \frac{d}{x+1} \right\rceil = \frac{d+x}{x+1}$$整数の除算を使用します。 
4. 候補者が以下の値を出した場合`n`、出力`YES`。 

必要な最適化量は 1 つだけです。 
5. すべての候補が不合格の場合、出力`NO`。 

### なぜ効果があるのか

 機能$$f(x)=x+\left\lceil \frac{d}{x+1} \right\rceil$$増加項と減少項の合計です。 その最小値は、これら 2 つの効果のバランス点付近で達成されます。`√d`。 

より大幅に大きい値の場合`√d`、直線部分`x`はすでに最小値が発生する領域を超えていますが、除算項はわずかに変化します。 すべての値を確認しています`0`大体を通して`√d`最小値またはそれ以下の値に遭遇することを保証します。 実行可能な解決策が存在する場合、それらのチェックされた値の 1 つが期限条件を満たします。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, d = map(int, input().split())

    ok = False
    limit = math.isqrt(d) + 2

    for x in range(limit + 1):
        total = x + (d + x) // (x + 1)
        if total <= n:
            ok = True
            break

    print("YES" if ok else "NO")
```ループオーバー`x`ソリューションの核心です。 考えられるすべての最適化量を調査するのではなく、およそ最大の値のみをチェックします。`√d`。 

表現```
(d + x) // (x + 1)
```天井分割を実装します$$\left\lceil \frac{d}{x+1} \right\rceil.$$よくある間違いは、通常の整数の除算を使用することです。```
d // (x + 1)
```これはフロアを計算し、不可能なスケジュールを誤って受け入れる可能性があります。 

使用する`math.isqrt(d)`浮動小数点精度の問題を回避します。 以来`d`到達できる`10^9`ここではどちらのアプローチでも機能しますが、整数平方根の方がクリーンで正確です。 

問題はそのような値が存在するかどうかを問うだけであるため、アルゴリズムは実行可能な値を見つけるとすぐに停止します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(√d) | 以下の値のみをテストします。`0`くらいまで`√d`|
 | スペース | お(1) | 少数の変数のみが保存されます。 

以来`√10^9 ≈ 31623`、各テスト ケースは数万回の反復のみを実行します。 最大 50 のテスト ケースであれば、制限時間内に簡単に収まり、メモリの使用量も無視できます。 

## テストケース```python
# helper: run solution on input string, return output string
import sys, io, math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    t = int(input())
    ans = []

    for _ in range(t):
        n, d = map(int, input().split())

        ok = False
        limit = math.isqrt(d) + 2

        for x in range(limit + 1):
            total = x + (d + x) // (x + 1)
            if total <= n:
                ok = True
                break

        ans.append("YES" if ok else "NO")

    return "\n".join(ans) + "\n"

# provided samples
assert run("3\n1 1\n4 5\n5 11\n") == "YES\nYES\nNO\n", "sample 1"

# minimum values
assert run("1\n1 1\n") == "YES\n", "minimum case"

# exact boundary where no optimization needed
assert run("1\n10 10\n") == "YES\n", "d equals n"

# impossible case
assert run("1\n1 100\n") == "NO\n", "far beyond deadline"

# maximum values
assert run("1\n1000000000 1000000000\n") == "YES\n", "maximum constraints"

# near optimum around sqrt(d)
assert run("1\n6 11\n") == "YES\n", "minimum total equals 6"
```| テスト入力 | 期待される出力 | 検証内容 |

```最適化を行わない場合:$$0+\left\lceil \frac{10}{1}\right\rceil = 10$$条件はすでに成立しています。 アルゴリズムは実行可能な値を即座に見つけて返します。`YES`。 

考慮する：```

```調べた合計は次のとおりです。$$11,7,6,6,7,\ldots$$最小値は`6`、これはまだより大きいです`5`。 関連するすべての値を大まかにチェックした後、`√11`、アルゴリズムは実行可能なスケジュールが存在しないと正しく結論付け、出力します。`NO`。
