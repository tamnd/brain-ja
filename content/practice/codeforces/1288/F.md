 ## 解決策
 ## 問題の理解

 与えられた 2 部グラフでは、各エッジに赤または青の 2 色のいずれかをオプションで割り当てるか、未使用のままにすることができます。 エッジの色付けは無料ではありません: 赤のコストがかかります`r`、青色のコスト`b`、未使用のままにしておくのには費用はかかりません。 これに加えて、一部の頂点は、入射する赤と青のエッジの数を「優先」しなければならないという方向性の圧力を課します。 

赤い頂点では、それに付随して選択するエッジのうち、赤いエッジの数が青いエッジの数よりも厳密に大きいことが必要です。 青い頂点には反対の不等式が必要です。 色の付いていない頂点には制限がありません。 

タスクは、総コストを最小限に抑えながらすべての頂点制約が満たされるように、どのエッジにどのように色を付けるかを決定することです。 

重要な点は、すべてのエッジに色を付ける必要はなく、制約は完全な隣接リストではなく、選択した色付きエッジのみに依存することです。 したがって、問題は基本的に、グローバルな一貫性条件を備えたエッジの符号付きサブセットを選択することに関するものです。 

制約`n1, n2, m ≤ 200`エッジの色付けに対する指数関数的な列挙を直ちに除外します。 平`3^m`可能性は不可能なので、`3^200`限界をはるかに超えています。 フロー構造または組み合わせ最適化を活用した多項式ソリューションが必要です。 

よくある失敗例は、頂点ごとに独立して貪欲な割り当てを試みた場合に発生します。 たとえば、赤い頂点に 2 つのエッジがある場合、両方のエッジを貪欲に赤に着色すると、青が必要な他のエンドポイントで競合が発生する可能性があります。 エッジは 2 つのエンドポイントに同時に影響を与えるため、ローカルでの決定は安全ではありません。 

もう 1 つの落とし穴は、入射エッジを調整することですべての頂点制約を独立して満たせると想定していることです。 実際には、すべてのエッジが一度に 2 つの制約に寄与するため、実現可能性は一連の独立した不等式ではなく、結合されたシステムになります。 

## アプローチ

 直接的なブルート フォース ソリューションでは、各エッジに 3 つの状態 (未使用、赤、青) のいずれかを割り当ててから、すべての頂点制約をチェックします。 これは正しいですがコストがかかります`O(3^m * (n + m))`、非常に小さな例であっても実行不可能です。`m = 200`。 

重要な構造的観察は、各頂点制約が入射する赤と青のエッジの数に関して線形であることです。 制約を書き直すと、赤い頂点は`deg_red(v) - deg_blue(v) ≥ 1`、青い頂点には次のことが必要です`deg_blue(v) - deg_red(v) ≥ 1`。 これは、符号付きエッジの決定に対する差分制約です。 

各エッジが寄与する`+1`赤の場合は 1 つのエンドポイントに、`-1`青色の場合 (拘束の方向によってはその逆も同様)。 これにより、この問題は、各エッジが署名されたフローの選択肢を運ぶ最小コスト循環問題に似たものになります。 

標準的な削減は、元の各エッジをフロー ネットワーク内の決定ガジェットに変換することです。 すべての頂点がそのタイプに応じて一定の正味の不均衡を蓄積するように強制します。 目標コストは、コストを伴うエッジ依存の容量になります。`r`そして`b`。 

中心となるアイデアは、各エッジを 2 つの方向 (赤または青を表す) のいずれかに送信できるフロー ユニットとしてモデル化すること、または使用しないことです。 頂点での制約は、正味流量の差の下限となり、需要を伴う最小コスト循環を介して強制できます。 

変換されると、コストを最小限に抑えながら頂点の要求を満たす実現可能な循環を見つけることが問題になります。ここで、各エッジには 2 つの可能な有向解釈があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^m・m) | O(m) | 遅すぎる |
 | 最小コストの流量削減 | O(m^3 log m) | O(m^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 このソリューションは、最小コスト循環モデルを通じて実装されます。 

1. 各頂点について、必要な不均衡値を計算します。 赤い頂点には少なくとも +1 の正味の赤マイナス青の寄与が必要なので、その需要を次のように設定します。`+1`。 青い頂点には少なくとも -1 (または同等の青から赤を引いた値 ≥ 1) が必要なので、需要を設定します。`-1`。 無色の頂点には需要がある`0`。 これにより、不平等制約がフローバランス要件に変換されます。 
2. 元の 2 部エッジごとに`(u, v)`では、未使用、赤、青の 3 つの状態を正確に許可する決定構造を作成します。 これを、間のユニットフローのいずれかの方向を運ぶことができるフローエッジを使用してエンコードします。`u`そして`v`、色の割り当てに対応します。 
3. 頂点をスーパー ソースとスーパー シンクに接続して、その要求を満たすようにします。 正の需要頂点は追加の流入を受け取る必要があり、負の需要頂点は流れを送出する必要があります。 これにより、ノードの制約が標準的な循環の実現可能性に変換されます。 
4. コストを選択肢に割り当てます。 一方向にフローを送信することは、エッジを赤く着色することに相当し、コストがかかります`r`。 逆方向への送信は青に相当し、コストがかかります`b`。 エッジを使用しないことは、そのエッジ ガジェットを介してフローを送信しないことに相当します。 
5. 通常、連続する最短の増強パスまたは容量スケーリングの最小コスト最大流量バリアントを使用して、最小コストの実現可能な循環アルゴリズムを実行します。 なぜなら`n, m ≤ 200`、標準`O(m^3)`実装で十分です。 
6. フローを計算した後、ガジェットを通過したフローの量を確認して各エッジの状態を再構築します。正の方向は赤を意味し、負の方向は青を意味し、ゼロは未使用を意味します。 

### なぜ効果があるのか

 この構造により、頂点に必要な不均衡のすべての単位が、流れの 1 つの単位に正確に対応することが保証されます。 赤い頂点が青よりも多くの赤を必要とする場合、構築されたグラフに正味の流入が強制されます。これは、適切な方向の入射エッジを選択することによってのみ満たされます。 各エッジには方向に応じて固定コストがあるため、すべての実行可能な循環にわたる総コストを最小化することは、総着色コストを最小化することと同じです。 フロー保存制約により、すべてのエッジの両方のエンドポイントにわたる一貫性が保証され、割り当ての競合が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

INF = 10**18

class MinCostMaxFlow:
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(n)]

    def add_edge(self, u, v, cap, cost):
        self.adj[u].append([v, cap, cost, len(self.adj[v])])
        self.adj[v].append([u, 0, -cost, len(self.adj[u]) - 1])

    def min_cost_flow(self, s, t, maxf):
        n = self.n
        adj = self.adj
        res = 0
        flow = 0
        pot = [0] * n

        while flow < maxf:
            dist = [INF] * n
            dist[s] = 0
            parent = [(-1, -1)] * n
            inq = [False] * n
            q = deque([s])
            inq[s] = True

            while q:
                u = q.popleft()
                inq[u] = False
                for i, (v, cap, cost, rev) in enumerate(adj[u]):
                    if cap > 0 and dist[v] > dist[u] + cost + pot[u] - pot[v]:
                        dist[v] = dist[u] + cost + pot[u] - pot[v]
                        parent[v] = (u, i)
                        if not inq[v]:
                            inq[v] = True
                            q.append(v)

            if dist[t] == INF:
                break

            for i in range(n):
                if dist[i] < INF:
                    pot[i] += dist[i]

            addf = maxf - flow
            v = t
            while v != s:
                u, i = parent[v]
                addf = min(addf, adj[u][i][1])
                v = u

            v = t
            while v != s:
                u, i = parent[v]
                e = adj[u][i]
                adj[u][i][1] -= addf
                adj[v][e[3]][1] += addf
                v = u

            flow += addf
            res += addf * pot[t]

        return flow, res

def solve():
    n1, n2, m, r, b = map(int, input().split())
    s1 = input().strip()
    s2 = input().strip()

    N = n1 + n2 + 2
    S = n1 + n2
    T = n1 + n2 + 1

    mcmf = MinCostMaxFlow(N)

    demand = [0] * N

    for i, c in enumerate(s1):
        if c == 'R':
            demand[i] = 1
        elif c == 'B':
            demand[i] = -1

    for i, c in enumerate(s2):
        if c == 'R':
            demand[n1 + i] = 1
        elif c == 'B':
            demand[n1 + i] = -1

    for i in range(N):
        if demand[i] > 0:
            mcmf.add_edge(S, i, demand[i], 0)
        elif demand[i] < 0:
            mcmf.add_edge(i, T, -demand[i], 0)

    edge_ids = []
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v = n1 + v - 1

        idx1 = len(mcmf.adj[u])
        mcmf.add_edge(u, v, 1, r)
        idx2 = len(mcmf.adj[v])
        mcmf.add_edge(v, u, 1, b)

        edge_ids.append((u, v, idx1, idx2))

    total_demand = sum(max(0, x) for x in demand)

    flow, cost = mcmf.min_cost_flow(S, T, total_demand)

    if flow < total_demand:
        print(-1)
        return

    ans = ['U'] * m

    for i, (u, v, idx1, idx2) in enumerate(edge_ids):
        if mcmf.adj[u][idx1][1] == 0:
            ans[i] = 'R'
        elif mcmf.adj[v][idx2][1] == 0:
            ans[i] = 'B'
        else:
            ans[i] = 'U'

    print(cost)
    print("".join(ans))

if __name__ == "__main__":
    solve()
```この実装は、削減コストをマイナスにならないように維持する可能性を備えた、標準の最小コスト最大フローに重点を置いています。 需要配列は、頂点制約を供給ノードと需要ノードに直接エンコードします。 元の各エッジは、2 つの有向フロー選択肢に拡張されます。1 つは赤の割り当てを表し、もう 1 つは青の割り当てを表し、両方ともユニット容量を表します。 

微妙な点は、スーパー ソースを通じて正の需要を満たす必要があるだけであるため、ターゲット フローはすべての正の需要の合計になることです。 これにより、循環の対称性が過度に強化されることが回避され、流れの計算が最小限に抑えられます。 

エッジの再構成は、残存容量のチェックに依存します。エッジの保持コストが`r`飽和していて、エッジは赤です。 逆エッジが飽和している場合は青になります。 それ以外の場合は未使用のままになります。

 ## 特殊なケース

 重要なエッジケースは、すべての頂点が色付けされていない場合です。 この場合、すべての需要はゼロになるため、循環には必要な流れがありません。 どのフローもコストを増加させるだけであるため、アルゴリズムはすべてのエッジを未使用として正しく割り当てます。 

別のエッジ ケースは、頂点が複数のエッジによって同時に拘束されているものの、その要求を満たすのに十分な入射容量がない場合に発生します。 フローは総需要に到達できず、アルゴリズムは正しく出力します。`-1`。 

最後の微妙なケースは、エッジの両方の端点が反対方向に強く拘束されている場合です。 フローの定式化により一貫性が確保されます。エッジは一方向でのみ使用できるため、局所的に最適な選択ではなく、グローバルに最も安価な実現可能な方向を選択することで、競合が自然に解決されます。
