 ## 解決策

 ## 問題の理解

 それぞれの長さが m である n 個のベクトルのコレクションが与えられます。 各ベクトルは、オブジェクトの m 個の属性を記述するものと考えてください。 2 つのオブジェクトを選択できます (同じオブジェクトを 2 回選択することもできます)。 それらを選択したら、それらの属性の座標上の最大値を取得して新しいベクトルを構築します。 この結果として得られるベクトルから、その最も弱い座標、つまりその m 個の位置の最小値のみを考慮します。 

目標は、マージ後のこの最も弱い座標ができるだけ大きくなるように、2 つの元のベクトルを選択することです。 言い換えれば、座標上の最大値のうち最小の座標でもできるだけ大きくなるように 2 つの行を選択する必要があります。 

m が非常に小さく、最大 8 であるのに対し、n は最大 300,000 まで非常に大きくなる可能性があることに気づくと、問題の構造が意味を持ちます。 この非対称性が重要なシグナルです。すべてのペアを比較するのではなく、ビットマスクまたは座標に対するサブセット推論を使用して、各配列を圧縮またはエンコードすることが期待されています。 

単純なアプローチでは、配列のすべてのペアを試し、座標上の最大値を計算し、次に最小値を取得して O(n^2 m) を求めますが、n が大きい場合、これは非常に遅すぎます。 

座標ごとの貪欲な最大化を個別に試みると、より微妙な失敗モードが発生します。 たとえば、ある座標で最適な配列と、別の座標で最適な配列を選択しても、マージ後も不十分な最小値が生成される可能性があります。これは、座標が最小操作を通じて相互作用するためです。 

本当の難しさは、優位性が座標ごとに独立して存在しないことです。 あるしきい値を超えるすべての座標を共同でカバーするペアが必要です。 

## アプローチ

 すべてのペア (i, j) を試すと、結合された配列が計算され、その最小値が評価されます。 これは正しいですが、約 n²/2 回の比較が必要であり、各比較には m 回の操作が必要です。 n = 300,000 では、これは不可能です。 

重要な観察は、視点を逆転させることです。 マージされた配列の最小値を直接最大化する代わりに、候補の答え x を推測し、座標上の最大値がすべての座標において少なくとも x である配列のペアが存在するかどうかを尋ねます。 

しきい値 x を固定すると、各配列が長さ m のビットマスクに変わります。ここで、a_{i,k} ≥ x の場合、ビット k は 1 になります。 ここで問題は、ビットごとの OR がすべて 1 に等しい 2 つのビットマスクを選択できるかということです。 

指定された x についてこの存在チェックを解決できれば、配列内の値の範囲にわたって x を二分探索できます。 

単純な二分探索に比べてわずかな改善は、m ≤ 8 であるという事実から来ています。これにより、各マスクを整数として表し、各マスクに対応する配列の数を事前計算することができます。 次に、マスクごとに、マスクを完全にカバーするパートナー マスクが存在するかどうかをテストできます。 

課題は、実現可能性だけでなく、実際の配列のインデックスも返す必要があることです。 したがって、マスクごとに 1 つの代表的なインデックスを保存します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² m) | お(1) | 遅すぎる |
 | マスク + 二分探索 | O(n m log V + 2^m m) | O(2^m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 入力内の可能な値の範囲にわたって、答えの値 x を二分探索します。 これが機能するのは、しきい値 x が達成可能であれば、それより小さなしきい値も達成可能であり、単調な述語が得られるためです。 
2. 固定 x の場合、すべての配列をサイズ m のビットマスクに変換します。k 番目の値が x 以上の場合、k 番目のビットが設定されます。 これにより、各配列が、しきい値 x で満たすことができる座標を正確にキャプチャする構造に圧縮されます。 
3. 配列をマスクごとにグループ化し、マスクごとに少なくとも 1 つのインデックスを保存します。 すべてのペアを列挙する必要はなく、有効なペアを見つけるだけでよいため、これで十分です。 
4. 2 つのマスクのビット単位の OR が (1 << m) - 1 になるように、マスクのすべてのペアをチェックします (または、より効率的には、マスクごとに補数マスクを見つけようとします)。この条件は、すべての座標がしきい値 x で 2 つの配列の少なくとも 1 つによってカバーされることを保証します。 
5. そのようなペアが存在する場合、対応するインデックスを保存し、x を実行可能としてマークします。 そうしないと、x が大きすぎます。 
6. 二分探索が終了したら、実行可能な最大の x に対応する保存されたペアを出力します。 

重要な推論ステップは、実現可能性は、座標が 2 つの配列の少なくとも 1 つによって独立してカバーされるかどうかのみに依存するということです。 ビットマスク削減はこれを正確に捉えます。 

### なぜ効果があるのか

 任意の固定しきい値 x について、レベル x でその座標をカバーするのに十分な場合、配列は座標 k に 1 を与えます。 max を使用してマージされた配列は、これらのマスクのビット単位の OR に正確に対応します。 少なくとも x であるマージされた配列の最小値は、OR 結果に設定されているすべてのビットと同等です。 したがって、問題の解決は、その OR が完全にカバーされる 2 つのマスクを見つけることになります。実行可能性は x において単調であるため、x に対するバイナリ検索により正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(x, a, n, m):
    full = (1 << m) - 1
    cnt = {}
    first_idx = {}

    for i in range(n):
        mask = 0
        row = a[i]
        for j in range(m):
            if row[j] >= x:
                mask |= (1 << j)
        if mask not in first_idx:
            first_idx[mask] = i
        cnt[mask] = cnt.get(mask, 0) + 1

    masks = list(cnt.keys())

    for m1 in masks:
        for m2 in masks:
            if (m1 | m2) == full:
                return first_idx[m1], first_idx[m2]

    return None

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    vals = set()
    for row in a:
        vals.update(row)
    vals = sorted(vals)

    lo, hi = 0, len(vals) - 1
    best_pair = (0, 0)

    def feasible(x):
        res = check(vals[x], a, n, m)
        if res is None:
            return False, None
        return True, res

    l, r = 0, len(vals) - 1
    while l <= r:
        mid = (l + r) // 2
        ok, res = feasible(mid)
        if ok:
            best_pair = res
            l = mid + 1
        else:
            r = mid - 1

    print(best_pair[0] + 1, best_pair[1] + 1)

if __name__ == "__main__":
    solve()
```この実装では、まず、しきい値に応じて各配列をビットマスクに圧縮します。 チェック機能はマスク周波数マップを構築し、マスクごとに 1 つの代表的なインデックスを保存します。 次に、すべてのマスク ペアに対してブルート フォース攻撃を実行します。マスクの数は最大 2^m = 256 であるため、これは実現可能です。 

答えは何らかの座標値と一致する必要があるため、二分探索は入力からのソートされた一意の値に対して実行されます。 これにより、浮動値または任意の値の検索が回避され、実行可能性チェックが個別に保たれます。 

よくある微妙な点は、マスクごとにインデックスを 1 つだけ保存することです。 これは有効なマスク ペアであれば十分であり、複数の代表は必要ないため有効です。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    n, m = map(int, sys.stdin.readline().split())
    a = [list(map(int, sys.stdin.readline().split())) for _ in range(n)]

    vals = sorted({v for row in a for v in row})

    def check(x):
        full = (1 << m) - 1
        first = {}
        masks = set()

        for i in range(n):
            mask = 0
            for j in range(m):
                if a[i][j] >= x:
                    mask |= (1 << j)
            masks.add(mask)
            if mask not in first:
                first[mask] = i

        masks = list(masks)
        for m1 in masks:
            for m2 in masks:
                if (m1 | m2) == full:
                    return first[m1], first[m2]
        return None

    l, r = 0, len(vals) - 1
    ans = (0, 0)
    while l <= r:
        mid = (l + r) // 2
        res = check(vals[mid])
        if res:
            ans = res
            l = mid + 1
        else:
            r = mid - 1

    return f"{ans[0]+1} {ans[1]+1}"

 ## 特殊なケース

 特殊なケースは、1 つの配列がすでに高いしきい値を超えるすべての座標を満たしている場合に発生します。 その場合でも、それ自体とのペアリングは有効であると見なされなければなりません。 フルマスク OR 自体がフルのままであるため、ビットマスク表現はこれを処理します。したがって、アルゴリズムは自然に (i, i) を返します。 

もう 1 つの微妙なケースは、複数の配列が同一のマスクを共有する場合です。 インデックスではなくカウントのみを保存すると、有効なペアを再構築できなくなります。 マスクごとに 1 つの代表的なインデックスを保存すると、正確さに影響を与えることなく再構築が常に可能になります。 

3 番目のケースは、最適解が値の分布が一意ではない 2 つの同一の配列を使用する場合です。 マスク OR 条件でも m1 = m2 が許可されるため、アルゴリズムは個別のインデックスを強制するのではなく、自己ペアを正しく考慮します。
