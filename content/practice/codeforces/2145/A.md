 ## 解決策
 ## 問題の理解

 Monocarp は、一定数のキャンディーを 3 人の甥に均等に分配したいと考えています。 彼は次のように始めます`n`キャンディーがあれば、合計を 3 で割り切れるには、あと何個買わなければならないかを計算する必要があります。 入力は複数のテスト ケースで構成され、それぞれが 1 つの整数を与えます。`n`。 各テスト ケースの出力は最小の非負の整数です。`k`そのような`n + k`は 3 で割り切れます。 

制約は小さいです。`n`最大 100 まで可能で、テスト ケースの数は最大 100 です。 これは、パフォーマンスを心配することなく、テスト ケースごとに非常に単純な算術演算を実行できることを意味します。 複雑なデータ構造やアルゴリズムは必要ありません。 

明らかではないエッジケースが発生するのは次の場合です。`n`はすでに 3 で割り切れます。この場合、Monocarp は追加のキャンディーを購入する必要はありません。 たとえば、次の場合`n = 24`、正解は`0`。 もし`n = 7`、Monocarp のニーズ`2`追加のキャンディーがあるので、`7 + 2 = 9`、これは 3 で割り切れます。 やみくもに固定番号を追加したり、ケースの処理を忘れたりする不用意な解決策`n % 3 == 0`間違った答えが生まれるでしょう。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 それぞれについて`n`、追加のキャンディーをゼロから開始して、段階的にテストすることができます。`n + k`3で割り切れるまで。 これは、最終的には 3 で割り切れる数値に達するため機能しますが、制約が小さい場合でもこれは不要です。 テスト ケースごとに最大 2 つの追加チェックが含まれますが、この問題にとっては些細なことですが、算術的な洞察により、この問題を直接解決することができます。 

重要な観察は、`n`3 で割り切れる場合は、余りを考慮するだけで済みます。`r = n % 3`。 もし`r`がゼロの場合、キャンディーは必要ありません。 もし`r`は 1 つです、私たちには必要です`2`もっとキャンディーがあれば、`r`2つです、必要です`1`もっとキャンディーを。 これは単純なモジュラー算術から来ており、本質的には次のことを解決しています。`(n + k) % 3 == 0`最小の非負の場合`k`。 

したがって、最適なアプローチは、次の剰余を計算することです。`n`3 を法として、剰余が 0 の場合を除き、3 からそれを引きます。 これにより、不必要なループが完全に回避されます。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`、Monocarp が現在持っているキャンディーの数。 
3. 剰余を計算する`r = n % 3`。 
4. もし`r`ゼロです、印刷します`0`。 それ以外の場合は、印刷します`3 - r`。 これにより、合計を 3 で割り切れるように追加するキャンディーの最小数が得られます。 
5. すべてのテスト ケースに対して繰り返します。 

これが機能する理由: 不変条件は、キャンディーの総数が常に 3 で割り切れる必要があることです。 モジュロ演算は、最も近い 3 の倍数からどれだけ離れているかを直接測定します。 追加`3 - r`オーバーシュートすることなく残りを補正します。 これにより、余分なキャンディーの最小数で合計が 3 で割り切れるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    r = n % 3
    print(0 if r == 0 else 3 - r)
```コードは最初にテスト ケースの数を読み取ります。 テスト ケースごとに、次の残りを計算します。`n`3で割ります。 余りがゼロの場合はゼロを出力します。 それ以外の場合は、出力されます`3 - r`。 オフバイワンの問題はありません。`n % 3`常に 0、1、または 2 が生成されます。`3 - r`常に必要な最小限の数のキャンディーを追加するようにします。 

## 実用的な例

 入力用`7`:

 | n | n%3 | r | 3 - r | 出力 |
 | --- | --- | --- | --- | --- |
 | 7 | 1 | 1 | 2 | 2 |

 キャンディーを2つ加えると`9`キャンディー、3 で割り切れるので、甥はそれぞれ 1 つずつもらえる`3`。 

入力用`24`:

 | n | n%3 | r | 3 - r | 出力 |
 | --- | --- | --- | --- | --- |
 | 24 | 0 | 0 | - | 0 |

 キャンディーは必要ないので、`24`すでに 3 で割り切れます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    
    t = int(input())
    for _ in range(t):
        n = int(input())
        r = n % 3
        print(0 if r == 0 else 3 - r)
    
    sys.stdout = sys.__stdout__
    return output.getvalue().strip()

# provided samples
assert run("2\n7\n24\n") == "2\n0", "sample 1"

# custom cases

assert run("2\n100\n99\n") == "2\n0", "large divisible cases"
assert run("1\n0\n") == "0", "zero candies"
assert run("1\n5\n") == "1", "remainder 2 case"

 ## 特殊なケース

 のために`n = 0`、`0 % 3`はゼロであるため、アルゴリズムは正しく出力します。`0`。 のために`n = 1`または`n = 2`、アルゴリズムは次のように計算します。`3 - r`として`2`そして`1`それぞれ、必要な最小限の追加のキャンディーと一致します。 単純なモジュロ計算以外に特別な処理は必要ありません。 のために`n`すでに 3 で割り切れる場合、アルゴリズムはゼロを出力し、オーバーシュートが発生しないようにします。 これらの各エッジケースは、モジュロベースのソリューションが堅牢であることを裏付けています。
