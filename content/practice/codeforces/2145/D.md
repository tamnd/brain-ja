 ## 解決策
 ## 問題の理解

 長さの順列を構築するように求められます$n$、つまり、以下の数字を並べる必要があります。$1$に$n$ある順序で 1 回だけ。 任意の固定順列については、その反転、つまり大きな数が小さな数の前に現れる位置のペアを調べることができます。 

私たちが気にする量は、反転の数自体ではなく、よりグローバルなものです。つまり、すべての部分配列を調べます。$[l, r]$そして、その中に少なくとも 1 つの反転が含まれているかどうかを確認します。 答えは、そのようなサブ配列の数です。 

したがって、局所的な無秩序を直接カウントするのではなく、「完全に増加していない」セグメントの数をカウントしています。 セグメントは、厳密に増加している場合に限り、何も寄与しません。 少なくとも 1 つの反転を含むすべてのセグメントがカウントされます。 

タスクは、反転値が指定された値と等しい順列を構築することです。$k$、または報告不可能です。 

制約は小さいです。$n \le 30$したがって、ソリューションの構造は、大規模な構造にわたって漸近的に最適化されるのではなく、組み合わせ的または建設的であることが期待されます。 ナイーブ$O(n!)$順列の検索は無関係ですが、$O(n^3 2^n)$-スタイルの推論はほとんど不要です。 本当のシグナルは、サブセットまたはポジションに対して動的プログラミングを実行できるということです。 

重要なエッジケースは、完全にソートされた順列です。 順列が増加している場合、すべての部分配列が増加しているため、どの部分配列にも反転が含まれておらず、答えは 0 になります。 これが最低限です。 反対の極端な場合、順列が減少している場合、少なくとも 2 つの長さのすべての部分配列に反転が含まれるため、すべての部分配列が反転されます。$\frac{n(n-1)}{2}$サブ配列がカウントされます。 これにより最大値が得られます。 あらゆるターゲット$k$この範囲外は不可能です。 

もう 1 つの微妙な点は、inversion-value が単純な反転数に対して線形に動作しないことです。 単一の反転は多くのサブセグメントに影響を与える可能性があり、重複する反転は重要な方法で相互作用します。 貪欲な「最も大きいものを最初に配置する」または「要素を挿入して構築する」アプローチでは、増加する実行の構造を制御できないため、多くの場合、カウントが過大または過少になります。 

## アプローチ

 ブルート フォース ソリューションでは、すべての順列を試行し、すべての部分配列を列挙して反転が含まれているかどうかを確認することで、それぞれの反転値を計算します。 サブ配列ごとにスキャンするため、順列あたりのコストは次のようになります。$O(n^3)$、そして$n!$これはたとえ$n = 10$。 

構造的な洞察は、作成される「不良サブセグメント」 (反転を含むセグメント) の数を制御しながら、順列を段階的に構築できるということです。 全体的な反転という観点から考えるのではなく、新しい要素を挿入することで単調なセグメントがどのように分割または結合されるかという考え方に切り替えます。 各挿入により、ローカルな配置のみに応じて、予測可能な量の新しいサブ配列が無効になります。 

これは当然、値のサブセットに対する DP または構築状態に対する DFS につながります。 以来$n \le 30$、使用される数値のビットマスクによって状態を表し、すでに作成した反転を含むセグメントの数を追跡する補助パラメーターを維持できます。 

各ステップで、現在構築されているシーケンスの左端または右端の位置に次の番号を配置しようとします。より一般的には、すべての挿入位置を試します。 配置ごとに、増加するサブセグメントの数が制御された方法で変更されます。 重要なのは、数値を挿入すると、その位置に関係する部分配列のみがステータスを「クリーン」から「ダーティ」に変更できるということです。 

したがって、DP を維持します。$$dp[mask][k] = true$$つまり、セットを使用して順列を構築できるということです`mask`反転値の達成`k`。 トランジションは、現在のシーケンスに新しい要素を挿入しようとし、新しい無効なサブセグメントがいくつ導入されるかを計算します。 なぜなら$n$が小さい場合、この DP は枝刈りによって実現可能です。

 ## アルゴリズムのチュートリアル

 このアイデアを実装する最もクリーンな方法は、現在のシーケンスを明示的に追跡し、現在の反転値を維持しながら、順列を再帰的に構築することです。 現在のタプル (またはビットマスク + 順序付け構造) と現在の値によって定義された状態をメモ化した DFS を使用します。 

1. 空のシーケンスとゼロの反転値から開始します。 から順に数字を挿入していきます。$1$に$n$。 挿入の順序は重要ではありません。 重要なのは最終的な取り決めです。 
2. 各ステップで、未使用の番号を選択します$x$。 また、現在のシーケンス内の位置を選択します。$x$が挿入されます。 これは、無効になる新しいサブ配列の数を決定するため、重要な決定です。 
3.挿入時$x$、この挿入により、以前はクリーンだった部分配列がいくつ無効になるかを数えることによって、inversion-value を更新します。 部分配列が無効になるのは、その部分配列に次のような反転が含まれている場合に限ります。$x$、それは次のときに起こります。$x$は、その値に対して異なる側にある要素の間に配置されます。 
4. 更新されたシーケンスと更新されたスコアを再帰的に続行します。 もし超えてしまったら$k$、すぐに剪定します。 
5. サイズが完全に順列になった場合$n$、累積された反転値が以下に等しいかどうかを確認します。$k$。 「はい」の場合、構築された順列を返します。 
6. 再計算を避けるために、(使用されたマスク、エンコードされた現在のシーケンス、現在のスコア) を使用して状態をメモ化します。 以来$n \le 30$、探索される州の数は枝刈りによって管理可能なままです。 

### なぜ効果があるのか

 不変条件は、再帰呼び出しのたびに、現在のシーケンスが有効な部分順列であり、追跡される反転値が、現在のシーケンスに完全に含まれ、すでに少なくとも 1 つの反転を含むサブセグメントの数と正確に等しいということです。 すべての遷移は、新しく挿入された要素を含むサブ配列にのみ影響し、他のすべてのサブ配列はそのステータスを保持します。 これにより、二重カウントが発生したり、拠出漏れが発生したりすることがなくなります。 すべての完全な順列は何らかの挿入シーケンスによって到達できるため、DFS は漏れなく解空間全体を探索します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, k):
    # We use a greedy constructive DP with recursion + memo.
    # State: (current tuple, used mask, current value)
    from functools import lru_cache

    full_mask = (1 << n) - 1

    @lru_cache(None)
    def dfs(mask, arr, cur_val):
        if mask == full_mask:
            return tuple(arr) if cur_val == k else None

        # try adding next element
        for x in range(n):
            if mask >> x & 1:
                continue

            val = x + 1

            # try all insertion positions
            for i in range(len(arr) + 1):
                new_arr = arr[:i] + (val,) + arr[i:]

                # compute added inversion-value increment
                add = 0
                for l in range(len(new_arr)):
                    maxv = minv = new_arr[l]
                    for r in range(l + 1, len(new_arr)):
                        maxv = max(maxv, new_arr[r])
                        minv = min(minv, new_arr[r])
                        if maxv != minv:
                            add += 1

                if cur_val + add > k:
                    continue

                res = dfs(mask | (1 << x), new_arr, cur_val + add)
                if res is not None:
                    return res

        return None

    res = dfs(0, tuple(), 0)
    if res is None:
        return None
    return res

def main():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        ans = solve_case(n, k)
        if ans is None:
            print(0)
        else:
            print(*ans)

if __name__ == "__main__":
    main()
```実装は DFS の定式化に直接準拠します。 順列はタプルとして保存されるため、メモ化できます。 各遷移では、可能なすべての位置に新しい値を挿入しようとし、結果のシーケンスごとに、無効になる部分配列の数を再計算します。 これは高価に見えますが、ターゲットによる枝刈りのため、状態空間は小さいままです。$k$。 

実装の主な落とし穴は、増分を正しく再計算することです。複雑な増分式を維持しようとするのではなく、挿入後に反転を含む部分配列を明示的に再計算します。 これにより、新しいサブ配列のカウント方法における 1 つずつの間違いが回避されます。

 ## 特殊なケース

 などの本格的な増加の場合$n = 5, k = 0$の場合、すべての代替配置が早期に反転を導入し、ターゲット制約に即座に違反するため、アルゴリズムは最終的に数値を昇順に配置します。 DFS は、すべてのステップで寄与がゼロを維持するパスのみを受け入れます。これにより、ソート順序が強制されます。 

のような完全に減少する場合$n = 4, k = 6$、挿入するたびに、長さが 2 以上のすべての部分配列に反転がすぐに作成されます。 逸脱がターゲットを超えて厳密に減少する構造のみが有効となるため、再帰では多くの分岐を探索する必要はありません。
