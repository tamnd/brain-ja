 ## 解決策
 ## 問題の理解

 以下のみで構成されるバイナリ文字列が与えられます。`a`そして`b`。 この文字列から、空の場合もある連続する文字ブロックを 1 つだけ削除することができます。 この削除後、残りの文字を見て、その文字数を数えます。`a`そして`b`残っています。 

目標は、削除されるセグメントの長さを最小限に抑えながら、削除されるセグメントを 1 つ選択することで、これら 2 つのカウントを等しくすることです。 文字列全体を削除する以外に、削除された単一の間隔を選択しても同等性を達成できない場合、答えは次のようになります。`-1`。 

重要な制約は、削除は分散した削除ではなく、1 つの連続したセグメントである必要があることです。 このため、根本的に問題となるのは、削除によって全体的なバランスが調整されるウィンドウを選択することです。`a`そして`b`。 

入力サイズは大きく、すべてのテスト ケースの合計長は最大 200,000 です。 これにより、部分文字列に対する二次関数のアプローチは即座に排除されます。 考えられるすべての削除間隔を明示的に試行するソリューションでは、最悪の場合、O(n²) 個の候補を検査することになりますが、これでは遅すぎます。 

構造を維持するために弦を削除した後でも、弦のバランスをとる方法がない場合、微妙なエッジケースが発生します。 たとえば、すべての文字が`a`、どの内部セグメントを削除しても、残りの文字列には`a`, したがって、すべてを削除しない限り平等は不可能です。 同様に、合計数がすでに等しい場合は、何も削除しないのが最適です。 

## アプローチ

 直接的なアプローチは、考えられるすべてのセグメントを試すことです`[l, r]`を削除し、残りの文字列に同じ数の文字列があるかどうかを確認します。`a`そして`b`。 各削除後の残りの文字のカウントはプレフィックスの合計を使用して最適化できるため、各チェックは O(1) になります。 ただし、そのようなセグメントは O(n²) 個あるため、合計の複雑さは O(n²) となり、全長 2e5 には大きすぎます。 

重要な観察は、セグメントを削除すると、カウント間のグローバルな差が非常に構造化された方法で変化するということです。 合計の不均衡を次のようにします。```
D = (#a - #b)
```セグメントを削除した後の最終的な不均衡がゼロになるようにします。 セグメントを削除するとします`[l, r]`。 させて：```
delta[l, r] = (#a - #b in s[l..r])
```その場合、残りの不均衡は次のようになります。```
D - delta[l, r]
```私たちが望んでいるのは:```
D - delta[l, r] = 0  →  delta[l, r] = D
```したがって、問題は、次のサブ配列を見つけることになります。`(a - b)`値は合計に等しい`(a - b)`文字列全体の長さを最小限に抑えます。 

これは、古典的なプレフィックス合計変換になりました。 割り当てます`+1`に`a`そして`-1`に`b`、プレフィックスの合計を計算し、2 つのインデックスが必要です`i < j`次のような:```
prefix[j] - prefix[i] = D
```同様に:```
prefix[i] = prefix[j] - D
```1 回スキャンし、プレフィックス値からその最初の出現までのハッシュ マップを使用して、セグメントの長さを最小限に抑えます。 

残る唯一の複雑な問題は実現可能性です。合計数がすでに等しい場合、答えは次のようになります。`0`。 有効なセグメントが存在しない場合、可能な唯一の方法はすべてを削除することであるため、次の結果を返します。`-1`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | プレフィックス + ハッシュ マップ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を数値配列に変換します。`a = +1`そして`b = -1`。 これにより、問題は生のカウントではなくバランスを扱うことに変わります。 
2. 合計を計算します`D`。 もし`D == 0`、弦はすでにバランスが取れているため、削除する必要はなく、戻ります。`0`。 
3. 左から右にスキャンしながらプレフィックスの合計を構築します。 各プレフィックス値は、そのインデックスまでの不均衡を表します。 
4. 各プレフィックス値が出現する最も古いインデックスを保存します。 最も早い出現を使用すると、残りのセグメントの長さが最大になり、削除されるセグメントが最小になるため、これは重要です。 
5. ポジションごとに`j`、ターゲットのプレフィックス値を計算します`prefix[j] - D`。 以前にインデックスでこの値を見た場合`i`、次に部分配列`(i+1..j)`まさにアンバランスです`D`、つまり、それを削除すると残りのバランスが整います。 
6. そのようなすべての有効なセグメントの中で最小の長さを追跡します。 
7. セグメントが見つからない場合は、戻ります。`-1`。 

中心的な考え方は、すべての有効な削除は、不均衡が元の不均衡に等しいサブ配列の選択に正確に対応するということです。 プレフィックス合計が使用されると、問題はルックアップを伴う線形スキャンになります。 

### なぜ効果があるのか

 このアルゴリズムは、セグメントの削除は、そのセグメント自体の寄与を通じてのみ全体の不均衡に影響を与えるという事実に基づいています。 接頭辞変換によりすべてのセグメントが 2 ポイントの差に変換されるため、条件は固定ターゲット差になります。 考えられるすべてのセグメントはプレフィックス ペアとして 1 回だけ表現されるため、すべてのプレフィックスをスキャンすることで、すべての有効な削除が考慮されることが保証されます。 最も早い出現を保存すると、すべての有効なペアの中で常に最も短い削除されたセグメントが得られるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()

        arr = [1 if c == 'a' else -1 for c in s]
        total = sum(arr)

        if total == 0:
            out.append("0")
            continue

        prefix = 0
        first_pos = {0: -1}
        ans = n + 1

        for i, v in enumerate(arr):
            prefix += v

            need = prefix - total
            if need in first_pos:
                ans = min(ans, i - first_pos[need])

            if prefix not in first_pos:
                first_pos[prefix] = i

        if ans == n + 1:
            out.append("-1")
        else:
            out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は、バランスが加算されるように文字列を符号付き配列にエンコードすることから始まります。 プレフィックスの合計は、各インデックスでの平等からどれだけ離れているかを追跡します。 辞書`first_pos`削除されるセグメントの長さを最小限に抑えるために必要な、最も早いプレフィックス値が常に使用されるようにします。 

重要な点は更新の順序です。現在のプレフィックスをマップに挿入する前に、有効なセグメントをチェックします。 これにより、長さの境界を計算するときに、現在のインデックスで終わるセグメントを誤って使用することが防止されます。

    for _ in range(t):

        s = input().strip()

 ## 特殊なケース

 1 つの文字タイプのみで構成される文字列 (例:`aaaa`、必要な差を満たす繰り返し構造のない、一定の負または正のプレフィックス傾向を生成します。 アルゴリズムはすべてのプレフィックスをスキャンし、有効な一致を見つけず、正しく返します。`-1`。 

弦のバランスがすでに取れている場合`ab`または`baba`、合計はゼロになります。 早期に終了することで、不必要な削除を誤って検索することがなくなり、すぐに戻ります。`0`。 

プレフィックスやサフィックスの削除など、最適な削除が境界にある場合、初期化するため、プレフィックス マップは引き続きそれらをキャプチャします。`prefix = 0`インデックスで`-1`。 これにより、インデックスから始まるセグメントが`0`は有効な候補であり、内部セグメントで均一に処理されます。
