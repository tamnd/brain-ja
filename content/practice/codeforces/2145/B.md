 ## 解決策
 ## 問題の理解

 1 から n までの番号が付けられたカードのデッキが与えられ、最初は 1 が上、n が下にソートされます。 Monocarp は、上か下、または曖昧にどちらかの端からカードを削除する一連の k 操作を実行します。 それぞれのカードについて、それが確実に削除されたのか、確実に残っているのか、それとも区別できないのかを判断する必要があります。 

入力では、カードの数 n、アクションの数 k、および長さ k の文字列が与えられます。各文字は除去のタイプを示します。上部は「0」、下部は「1」、両端は「2」です。 各テスト ケースの出力は、文字「+」、「-」、または「?」を含む長さ n の文字列です。 カードごとに順番に。 

この制約により、n は 2×10^5 まで、テスト ケース全体の n の合計は 2×10^5 まで許可されます。 これは、操作ごとにデッキを明示的にシミュレートするアプローチを除外します。単純なシミュレーションでは最大 O(nk) 作業 (潜在的に 4×10^10 操作) を実行できるため、これは大きすぎます。 n と k には線形または線形に近いアプローチが必要です。 

「2」の操作では微妙なエッジケースが発生します。 すべてのアクションが「2」の場合、どちらの端からでもカードを取り除くことができます。 たとえば、n=3 および s="22" の場合、どちらの端が選択されたかわからないため、カードが削除されることは保証されません。 常に上または下から順番に削除する不注意な方法では、一部のカードが誤って削除済みとしてマークされてしまいます。 

## アプローチ

 ブルートフォース手法では、デッキを明示的にモデル化し、指定どおりにカードを表または裏からポップします。 「2」の場合、両方の可能性を考慮する必要があるため、状態の数は指数関数的に増加します。 指数関数的な爆発を無視しても、Python ではリストの前または後ろから削除するのは O(n) であり、遅すぎるため、デッキを線形にシミュレートするだけで操作ごとに O(n) が必要になります。 

重要な観察は、各カードの運命は、それが除去される前に保証された上位除去と下位除去が何回発生するかによってのみ左右されるということです。 s 内の「0」（上位の削除）と「1」（下位の削除）の累積数をカウントできます。 位置がトップの除去の数より少ないカードはすべて除去されなければなりません。 最下位からの距離が最下位の除去の数よりも短いカードはすべて除去されている必要があります。 これらの保証除去外のカードは残り、両端に重なる曖昧な「2」内のカードは「?」としてマークされます。 これにより、問題は単純な算術比較と累積カウントに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nk) | O(n) | 遅すぎる |
 | 最適 | O(n + k) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カウンタの初期化`top_removals`そして`bottom_removals`ゼロに。 これらは各エンドからの保証された除去を追跡します。 
2. 文字列 s を反復処理します。 「0」ごとに増加します`top_removals`。 「1」ごとに増加します`bottom_removals`。 「2」の場合、どちらの端に影響するかは保証できないため、どちらのカウンタもインクリメントしないでください。 
3. すべてのカードが残っていると仮定して、出力配列を「+」で初期化します。 
4. 1 から n までの番号 i が付けられた各カードについて、保証された除去との相対的な位置を確認します。 i ≤ top_removals の場合、先頭から削除されているため、「-」とマークされます。 n-i+1 ≤bottom_removals の場合、下部から削除されており、「-」とマークされます。 
5. どちらの条件も真ではないが、i があいまいな「2」の削除によって影響を受ける可能性のある範囲内にある場合は、「?」をマークします。 これは、i ≤ top_removals + '2' の数、または n-i+1 ≤bottom_removals + '2' の数の場合に発生します。 それ以外の場合は、「+」のままにします。 
6. 配列を文字列に結合して出力します。 

これが機能するのは、既知のアクションからの確実な除去のみを考慮しているためです。 曖昧な除去は残りのデッキ数を予測可能な方法で減らさないので、「？」 不確実性を正確に反映します。 不変条件とは、`top_removals`そして`bottom_removals`両端から何枚のカードが確実に取り除かれたかを常に正確に数えてください。 これらの範囲外にある残りのカードはすべて、確実に存在するか不確実であるかのいずれかであり、アルゴリズムはどちらを正しくマークします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        top = s.count('0')
        bottom = s.count('1')
        ambiguous = s.count('2')
        res = ['+'] * n
        for i in range(1, n+1):
            if i <= top or (n - i + 1) <= bottom:
                res[i-1] = '-'
            elif i <= top + ambiguous or (n - i + 1) <= bottom + ambiguous:
                res[i-1] = '?'
        print(''.join(res))

if __name__ == "__main__":
    solve()
```まず、テスト ケースの数を読み取ります。 各テストケースについて、保証された上位の除去、下位の除去、およびあいまいな除去の数を数えます。 結果をすべて「+」として初期化します。 そして、各カードについて、保証除去の範囲に該当する場合はまず「-」を付けます。 そうでない場合は、あいまいなアクションによって影響を受けた可能性があるかどうかを確認し、「?」をマークします。 それ以外の場合は「+」のままです。 デッキをシミュレートする代わりにカウントを使用すると、直線的な時間が確保され、下位からポジションを計算する際のオフバイワンエラーが回避されます。
