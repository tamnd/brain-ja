 ## 解決策
 ## 問題の理解

 0 から m までの番号が付けられた、非常に長い 1 次元のセルのストリップが与えられます。 チップはセル 0 から開始し、できるだけ少ないターンでセル m に到達したいと考えています。 各ターン、チップはその場に留まるか、右に 1 ステップ移動します。 

難しさの原因は、ターン数に応じて定期的に発動するトラップです。 独立したトラップ システムは n 個あります。 i モジュロ n に一致するターンでは、ターンの終わりに i 番目のシステムがアクティブになり、インデックスが x ≡ b_i (mod a_i) の形式のモジュール条件を満たすすべてのセルをアクティブにします。 そのターンのトラップがチェックされた時点でチップがそのようなセルにある場合、ゲームは終了します。 

微妙なルールはタイミングです。移動が最初に発生し、次にトラップのアクティブ化がターンの終わりに発生しますが、ターンの開始時に危険なセルにいることは、そのセルが同じターンにアクティブ化しようとしている場合にも致命的です。 これにより、位置だけではなく、位置と時間の間に依存関係が生じます。 

出力は、間違ったタイミングで危険になるセルに一度も入ることなくセル m に到達するために必要な最小ターン数を求めます。m に到達することは、到着時だけでなく、セルに到達した時点で安全である場合にのみ有効です。 

制約は問題の性質を劇的に変えます。 位置 m は 10^12 に達する可能性があり、セルごとの移動をシミュレートするアプローチは即座に除外されます。 トラップ タイプの数 n は最大でも 10 であり、システムの実際の状態は小次元であり、周期的な動作が悪用可能であることを示唆しています。 各法 a_i は最大でも 10 であり、これは、すべてのトラップ条件が、管理可能な最大 10 までの最小公倍数で区切られた小さな組み合わせ周期で繰り返されることを意味します。 

素朴な解釈では、チップの位置を追跡し、ターンごとにトラップをチェックしながら、時間を段階的にシミュレートしようとします。 m が巨大であるため、これはすでに失敗しています。 暗黙的に状態について推論するだけであっても、トラップのアクティブ化がターンインデックス法 n に依存するという事実を無視すると、別の障害モードが現れます。 トラップを静的な禁止セルとして扱うと、パスが間違ってしまいます。これは、セルはある時点では安全でも、別の時点では致命的である可能性があるためです。 

具体的な障害ケースは、セルが初期には安全であるが、後で定期的に安全でなくなる場合に発生します。 時間を無視した貪欲な最短パスは、誤ってそのようなセルに永久に侵入してしまいます。 

## アプローチ

 直接的な総当たりアプローチでは、これを時間の経過に伴う最短経路の問題として扱います。 各状態は (位置、時間) となり、各状態から (x+1, t+1) または (x, t+1) に遷移し、その時点で新しい位置が安全かどうかを確認します。 これは、すべての依存関係を明示的にエンコードするため、原則的には正しいです。 

問題は、位置の範囲が膨大であるため、訪問した状態を保存することさえ不可能であることです。 ただし、重要な観察は、周期トラップ構造に対して危険なパターン境界を通過したかどうかを超えて絶対位置を区別する必要がないということです。 各トラップは x mod a_i と time mod n のみに依存するため、制約システム全体は最大でも n × lcm(a_i) のサイズの結合空間内で周期的になります。 

すべての a_i は ≤ 10 であるため、最小公倍数は最大 2520 です。これは、絶対位置を追跡する代わりに、2520 を法とする位置を追跡し、それを n を法とする時間と組み合わせることができることを意味します。 完全な状態空間は制限され、最短パスまたは DP にとって十分に小さくなります。 

私たちは、動きをタイムラインに沿って進むものとして再解釈します。各動きは 1 つの時間単位を消費し、位置は最大 1 ずつ増加します。重要なのは、時刻 t に位置 x にいることの実現可能性は、(x mod L, t mod n) (L = lcm(a_i) の場合) のみに依存するということです。 これにより、無限グリッドが有限層グラフに縮小されます。

次に、この有限グラフ上で最短パスを実行しますが、m までのすべての位置を明示的に列挙する代わりに、貪欲な階層化ジャンプ推論を使用します。つまり、到達可能な状態ごとに、次の制約境界に到達する前に直線運動でどこまで進むことができるかを計算します。 これにより、問題は重み付けされた遷移を含む剰余状​​態のグラフに変わります。 

最終的な解決策は、(時間 mod n、位置 mod L) 状態にわたるダイクストラのような走査であり、エッジは最大の安全な前進セグメントを表します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (時間位置 BFS) | O(m・n) | O(m・n) | 遅すぎる |
 | 周期状態グラフ (LCM 圧縮 + 最短パス) | O(n · L log(nL)) | O(n・L) | 承認済み |

 ## アルゴリズムのチュートリアル

 L をすべての a_i 値の最小公倍数として定義します。 すべて a_i ≤ 10 であるため、L は小さくなります。 

システムを層状グラフとして扱い、各状態が周期構造を法としてどれだけ進歩したかをエンコードします。 

1. すべての a_i 値の最小公倍数として L を事前計算します。 これにより、すべてのトラップ条件が L 個のセルごとに繰り返されることが保証されるため、位置 x および x + L はすべてのトラップに関して同一に動作します。 
2. 状態を (t_mod, x_mod) として定義します。ここで、t_mod は n を法とする時間、x_mod は L を法とする位置です。トラップのアクティブ化はこれらの剰余のみに依存するため、これらのみが必要です。 
3. 状態間の遷移を構築します。 状態から、トラップ起動ルールに関して安全を保ちながら、留まることができるか、前進できるかをシミュレーションします。 遷移は、現在のタイム ステップに対応するトラップ スケジュールの下で、現在の位置と次の位置が同時に無効でない場合にのみ存在します。 
4. 移動ごとにコスト 1 を割り当て (各ターンは時間的に 1 ステップです)、(0, 0) から位置 m を表す任意の状態までの最短経路を計算します。 
5. m が大きいため、絶対位置を追跡する代わりに、ある状態に到達した後に完全な L ブロックをいくつ通過できるかを計算します。 各状態は L を法として合同なすべての位置を暗黙的に表すため、剰余状態に到達するということは、サイクルが許可する場合は L のチャンクに安全にジャンプできることを意味します。 
6. 有限状態空間上でダイクストラを使用します。 各緩和では、周期的制約内に留まるか進むかが考慮され、各残基構成に到達するまでの最小時間が更新されます。 
7. L を法とした m に一致する位置に到達できる最良の時間を追跡し、最後の部分セグメントを個別にチェックすることによって、正確な m での実現可能性を検証します。 

### なぜ効果があるのか

 このシステムは、位置と時間の両方において完全に周期的です。 位置が L を法として削減されると、トラップ条件は長さ L の異なる完全なサイクルを区別できなくなります。すべての相互作用は剰余空間内で局所的であるため、元の無限グラフ内の最適なパスは有限状態グラフ内の有効なパスに投影され、有限グラフ内の任意のパスは元の空間内の一貫したリフティングに対応します。 この全単射により、圧縮下でも最短パスが確実に保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def lcm(a, b):
    from math import gcd
    return a // gcd(a, b) * b

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        L = 1
        for x in a:
            L = lcm(L, x)

        # precompute unsafe positions modulo L for each time class
        bad = [[False] * L for _ in range(n)]
        for ti in range(n):
            for x in range(L):
                if (x % a[ti]) == b[ti]:
                    bad[ti][x] = True

        INF = 10**18
        dist = [[INF] * L for _ in range(n)]
        dist[0][0] = 0

        pq = [(0, 0, 0)]  # time, time_mod, pos_mod

        while pq:
            tcur, tm, xm = heapq.heappop(pq)
            if tcur != dist[tm][xm]:
                continue

            # try staying or moving
            for dx in [0, 1]:
                nt = tcur + 1
                ntm = (tm + 1) % n
                nxm = (xm + dx) % L

                # check safety at start and end of turn
                if bad[tm][xm]:
                    continue
                if bad[ntm][nxm]:
                    continue

                if dist[ntm][nxm] > nt:
                    dist[ntm][nxm] = nt
                    heapq.heappush(pq, (nt, ntm, nxm))

        ans = INF
        for tm in range(n):
            for xm in range(L):
                if dist[tm][xm] == INF:
                    continue
                # try lifting to position m
                base = dist[tm][xm]
                if (m - xm) % L == 0 and m >= xm:
                    ans = min(ans, base + (m - xm))

        print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```コードは最初にすべての位置を L を法とする剰余に圧縮し、時間クラスごとに剰余が危険かどうかを示す事前計算されたテーブルを構築します。 次に、ダイクストラはすべての安全な状態を探索し、開始位置と結果の位置の両方が正しいタイム スライスの下で有効であることを確認します。 

最後のリフティング ステップでは、完全な L ブロックの前進を追加することによって、残留状態を実際のターゲット位置 m に変換します。 

## 実用的な例

 ### 例 1

 n = 2、m = 5、両方のトラップ システムの周期が 2 である小さなケースを考えてみましょう。状態空間は位置法 L = 2 に縮小されます。 

状態を (time_mod, pos_mod) として追跡します。 

| ステップ | 状態 | アクション | コスト |
 | --- | --- | --- | --- |
 | 0 | (0,0) | 開始 | 0 |
 | 1 | (1,1) | 移動 | 1 |
 | 2 | (0,0) | 移動 | 2 |
 | 3 | (1,1) | 移動 | 3 |
 | 4 | (0,0) | 移動 | 4 |
 | 5 | (1,1) | 移動 | 5 |

 これは、パリティ制約によって引き起こされる交互構造を示しています。 最短の有効なパスは、周期的なトラップのアクティブ化を考慮しながら 2 つの残基間を交互に移動します。 

### 例 2

 トラップが特定の時間に特定の残留物を禁止し、待機を強制する場合を考えてみましょう。 

| ステップ | 状態 | アクション | 理由 |
 | --- | --- | --- | --- |
 | 0 | (0,0) | 開始 | 安全 |
 | 1 | (1,0) | 待って | 危険な移動 |
 | 2 | (0,1) | 移動 | 安全な移行 |
 | 3 | (1,2) | 移動 | 続く |

 これは、待機エッジが必要な理由を示しています。目的のセルに通常は到達可能であっても、進行するとすぐに時間依存の制約に違反する場合があります。

 ## 特殊なケース

 重要なエッジ ケースは、宛先セル自体が定期的に安全でなくなる場合に発生します。 アルゴリズムでは、最終到着時間が m でのトラップのアクティブ化と一致しない場合にのみ、m への到達がカウントされるようにする必要があります。 これは、到達可能性を純粋に幾何学的なものとして扱うのではなく、安全な到着に対応する状態のみを通じて実現可能性を検証することによって処理されます。 

もう 1 つの微妙なケースは、セルがほとんどのタイム ステップでは安全であるが、最適なパスがセルを通過するまさにその時点で安全でなくなる場合に発生します。 時間拡張された状態グラフでは、そのような状態への遷移が現在と次回のトラップ条件の両方によってフィルターされるため、そのような状態が確実に除外されます。 

最後のエッジケースは、初期には移動が不可能であるが、待機サイクルの後に可能になる場合に発生します。 状態グラフ (滞在遷移) に自己ループが存在するため、アルゴリズムは特別なケースなしで自然に待機をモデル化し、前進する前に有利なトラップ フェーズと同期できるようになります。
