 ## 解決策
 ## 問題の理解

 長方形のシートが与えられました。$n$行と$m$列、最初は色付けされていません。 私たちの課題は、正確に「美しく」着色できる方法が何通りあるのかを判断することです。$k$色、各操作数ごとに可能な最小限の操作を使用します。$\min(n, m)$に$n+m-1$。 色付けは、行全体または列全体を一度にペイントすることによって行われます。 最初の操作では常に色 1 が使用され、後続の操作では前の色または次の整数の色のいずれかを使用する必要があります。 全てのセルに正確に色が付いていれば発色が綺麗です$k$色が使用され、各色が少なくとも 1 回は表示されます。 

入力により得られるのは、$n, m, k$、出力は 998244353 を法とする一連のカウントで、最小演算カウントが以下の可能な合計に等しい美しい色の数を表します。$\min(n, m)$に$n+m-1$。 

この制約は、すべての色を強引に列挙することは不可能であることを意味します。 と$n, m$2000 までは、すべての行/列の組み合わせを直接試行するアルゴリズムには、少なくとも$2^{2000}$実行不可能な操作。 代わりに、高速多項式乗算や二項係数を活用して大量のカウントを効率的に処理する、組み合わせアプローチまたは動的プログラミングが必要です。 

エッジケースが発生するのは次のような場合です$k = 1$。 ここでは、必要な色は 1 つだけであるため、最小の操作数は次の小さい方になります。$n$または$m$。 盲目的に仮定するアルゴリズム$k \ge 2$失敗します。 同様に、$k = n+m-1$、すべての操作で新しい色を導入する必要があるため、各行または列の選択が重要です。 小さなグリッドのような$2 \times 2$または$2 \times 3$行と列の間で色がどのように重なるかについての微妙な違いが明らかになります。 たとえば、$2 \times 3$2 色のグリッドを使用する場合、行をペイントしてから列をペイントすると、2 行をペイントする場合とは異なる最終的な色になる可能性があります。 重複をチェックせずに一連の操作をカウントする単純なアプローチでは、カウントが過剰になります。 

## アプローチ

 ブルート フォース アプローチでは、行と列の操作のすべてのシーケンスが列挙され、カラーリングがシミュレートされます。 シーケンスごとに、有効な美しい発色が得られるかどうかを確認し、最小限の操作シーケンスをカウントします。 この方法は原理的には正しいですが、検討が必要です$2^{n+m}$シーケンスが大きくなり、ある程度のサイズのグリッドでも実用的ではなくなります$10 \times 10$。 各シーケンスには次のことも必要となる場合があります。$O(nm)$すべてのセルの色を追跡する操作が必要なため、合計実行時間は実現不可能です。 

より迅速な解決策の重要な観察は、問題を配布方法を数えることに帰着できるということです。$k$行と列に沿って色を調整し、各色をシミュレートするのではなく、組み合わせによって重複を考慮します。 各操作により、行または列全体に色が追加されます。 最小限の操作で美しい発色を実現$k$色はまさに$k$すべてのセルをカバーするために必要な追加の行または列の操作の数を加えたものです。 包含-排他を使用すると、各色が少なくとも 1 回表示されるように行と列を選択する方法の数を数えることができ、行と列が重なる部分での過大なカウントを調整できます。 

これにより、事前計算された階乗とモジュラー逆関数を使用して二項係数を効率的に計算するアプローチが得られます。 カウントは、行と列の間で考えられる操作の分割を反復し、各分割の寄与を計算し、重複するセルの二重カウントを避けるために包含/除外を使用して合計することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(n+m) * n*m) | O(n*m) | 遅すぎる |
 | 組み合わせ + 包含-除外 | O(k * min(n,m)) | O(n+m+k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 階乗とモジュラー逆関数を最大で事前計算します。$n + m$高速な二項係数計算を可能にします。 これらは組み合わせカウントで繰り返し使用され、998244353 を法として計算する必要があります。 
2. 可能な最小操作数をすべて反復します。$i$から$\min(n, m)$に$n + m - 1$。 それぞれについて$i$、行に割り当てられる操作の数と列に割り当てられる操作の数を決定します。 与えられた分割について、$r$は行演算の数であり、$c = i - r$列操作の数。 
3. それぞれの選択肢について$r$のうちの行$n$そして$c$列外$m$、美しい発色条件を満たす色の割り当ての数を計算します。 包含/除外を使用して、1 つ以上の色が欠落している構成を減算します。 欠落している色の各サブセットは、サブセットのサイズに応じてプラスまたはマイナスに寄与します。 
4. 分割のためのすべての拠出金を合計します。$r$行と$c$列。 すべての分割を反復処理して、合計が以下になる演算のすべての分布をカバーします。$i$。 
5. それぞれのカウントモジュロ998244353を出力します。$i$。 

不変条件は、各ステップで、割り当てられた操作と色の正確な数を維持することです。 シミュレーションではなく組み合わせ式を使用することで、それぞれの異なる色を正確に 1 回カウントすることが保証されます。 包含/除外により、すべての色が少なくとも 1 回出現するカラーリングのみが含まれることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAX = 4000

# Precompute factorials and inverses
fact = [1]*(MAX+1)
invfact = [1]*(MAX+1)
for i in range(1, MAX+1):
    fact[i] = fact[i-1]*i % MOD
invfact[MAX] = pow(fact[MAX], MOD-2, MOD)
for i in range(MAX, 0, -1):
    invfact[i-1] = invfact[i]*i % MOD

def comb(n, k):
    if k < 0 or k > n:
        return 0
    return fact[n]*invfact[k]%MOD*invfact[n-k]%MOD

n, m, k = map(int, input().split())

min_ops = min(n, m)
max_ops = n + m - 1
res = []

for ops in range(min_ops, max_ops + 1):
    total = 0
    for r in range(max(0, ops - m), min(n, ops)+1):
        c = ops - r
        ways = comb(n, r)*comb(m, c) % MOD
        # Count color assignments using inclusion-exclusion
        count = 0
        for missing in range(k+1):
            sign = -1 if missing % 2 else 1
            count += sign * comb(k, missing) * pow(k - missing, r+c, MOD)
            count %= MOD
        total += ways * count % MOD
        total %= MOD
    res.append(total)

print(" ".join(map(str, res)))
```各係数を繰り返し再計算することを避けるために、組み合わせ計数の階乗と逆数を事前に計算します。 操作数ごとに、行と列の間のすべての有効な分割を繰り返します。 内部の包含/除外ループは、欠落している色を調整します。 オーバーフローを防ぐため、すべての演算は 998244353 を法として行われます。 私たちは慎重に範囲を扱います`r`無効な行数を選択しないようにするためです。
