 ## 解決策
 ## 問題の理解

 さまざまなプレイヤーが保有するカードを表す一連の個別の整数が与えられます。 値 0 の 1 枚のカードから始まる最初の山もあります。プレイヤーは自分のカードをこの山に置きますが、プレイヤーがいつプレイできるかを決定する制限があります。`x`現在の山の一番上が次の場合にのみ配置できます。`y`そしてその違い`x - y`最大でも何らかの固定整数です`d`事前に選択されています。 

すべてのプレイヤーはコミュニケーションをとらずに独立して行動しますが、同じルールに従います。つまり、自分のカードをルールに基づいて配置できる場合は、それを配置します。 複数のプレイヤーが同時に配置できる場合、カードを重ねる順序は任意になります。つまり、最悪の順序でも正確性を保証する必要があります。 

最終的な目標は、最終的にすべてのカードが配置され、その結果として得られる山が下から上に厳密に増加することです。 値が存在するかどうかを判断する必要があります`d`したがって、これらの同時配置の順序に関係なく、プロセスは常にすべてのカードを昇順に配置することに成功します。 そのような場合`d`存在する場合は有効な値を出力し、存在しない場合は 0 を出力します。 

入力サイズは最大 100,000 枚のカードに達するため、どのソリューションも線形または最悪の場合でも線形に近いものでなければなりません。 すべての可能な値に対する二次シミュレーション`d`または、再生順序のすべての並べ替えは不可能です。$10^{10}$最悪の場合の運用。 

素朴な試みは、固定のプロセスをシミュレートすることです。`d`そしてカードの固定順序。 順序が制御されておらず、最悪のケースは同時にプレイ可能なカード間の敵対的なタイブレークに依存するため、これはすでに問題となっています。 もう 1 つの微妙な失敗モードは、貪欲なソート挿入が機能することを想定していることです。配列をソートしたとしても、制約はソート順の隣接する違いだけではなく、進化するスタックの最上部との相対的なギャップに依存します。 

具体的なエッジケースは、2 つの大きなジャンプが近くにあるときに発生します。 たとえば、カードについて考えてみましょう`[1, 4, 8]`。 もし`d = 3`、0 から 1、次に 4 を配置できますが、順序に応じて中間状態が適切に制御されていない場合、4 からは 8 に到達できません。 正確さは、ソート順の隣接性だけでなく、最悪の場合のバッチ挿入でギャップがどのように蓄積するかにも依存します。 

主要な問題は、条件がグローバルな方法で順序と相互作用することです。複数のカードが同時に利用可能になったときに、「ギャップ」を埋めることが不可能にならないようにする必要があります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての値を試します。`d`それぞれのプロセスをシミュレーションします。 固定の場合`d`、残りのカードのセットを繰り返しスキャンし、現在の最大値に対する制約を満たすカードを選択します。 ただし、複数のカードを同時にプレイでき、その内部順序は任意であるため、これらのバッチの可能なすべてのインターリーブをシミュレートする必要があり、最悪の場合は階乗になります。 順序の曖昧さを無視して固定順序を仮定したとしても、各シミュレーションには依然としてコストがかかります$O(n)$、そして可能な限りのことを試みます`d`まで$10^9$不可能です。 

重要な観察は、このプロセスが値の並べ替え順序における隣接するギャップによって完全に駆動されていることです。 配列を並べ替える場合、唯一の重要な制約は、最悪の場合のバッチ処理でルールに違反するギャップに遭遇することなく、各ステップで 1 つの値から次の値に移動できるかどうかです。 敵対的な順序付けは、基本的に、複数の値が適格になるたびに、それらの値が任意の順序で表示される可能性があることを意味します。そのため、ソートされた順序で隣接するすべてのギャップが、中間的なブロックが発生しないように制限されている場合にのみ、システムは安全に動作します。 

これにより、問題は、バッチの順序に関係なく、0 からすべての数値までのチェーンが完了できることを保証しながら、どの程度の大きさのジャンプを許容できるかを特定することに軽減されます。 答えは、ソートされた順序で連続する値間に必要な最大の「ブリッジ ギャップ」によって決まりますが、最初の要素が 0 に接続されているという事実に微妙に依存します。 

ソートされた配列を計算し、違いを調べます。 最適な`d`これは、ソートされたシーケンス内のすべてのステップが、必要な中間状態をスキップすることなく到達可能であることを保証することから導き出されます。 以前に確立された構造に対してギャップが大きすぎる場合、プロセスは中断されます。 正しい構築とは、連続する差異によって引き起こされる最大最小要件を見つけることになります。

 | ソート + ギャップ分析 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、すべてのカードの値を昇順に並べ替えます。 これが必要なのは、最終的なパイルも増加する必要があるためであり、有効なプロセスは最終的にこの順序を尊重する必要があります。 

次に、0 と最小のカードから始まるシーケンスを検討し、次にソートされた順序で連続する各ペアを検討します。 制約`d`大きなギャップを回避できる代替順序がない最悪の場合でも、現在のトップ値から次に選択された値への各遷移が常に許可されるように、この値は十分な大きさでなければなりません。 

0 から最小のカードまでの初期の差を含む、連続する要素間の差を計算します。 重要な点は、ギャップが大きすぎる場合、プロセスが下位のエンドポイントに到達すると、すでに消費されているか、別の順序に配置されている場合、他の小さな中間値は役に立たないということです。 したがって、必要な最大の制約は、このチェーン内の避けられない最大のギャップによって決まります。 

設定しました`d`これらの連続した差の最大値まで。 これにより、次に必要なトランジションが常に許可範囲内にあるため、あらゆる段階で対象となるカードが順序効果によってブロックされなくなることが保証されます。 

この計算された値が有効な場合は、それを出力します。 ギャップの構造が有限でないことを意味する場合、`d`接続性を保証できる (これはルールの縮退解釈でのみ発生します) 場合、0 を出力しますが、この定式化では、最大ギャップが常に有効な答えを提供します。 

### なぜ効果があるのか

 このアルゴリズムは、ソート後、プロセスが 0 からすべての値までの単調なチェーンを構築するとみなすことができるという不変式に依存しており、有効な実行はすべて、最悪の場合でもこの順序を尊重する必要があります。 同時に適格なカード間の敵対的な順序付けでは、ソートされた隣接関係よりも小さい実効ギャップを作成することはできません。これは、「先にスキップ」しようとすると、制限要因としてブリッジできない最大のジャンプが依然として残るためです。 したがって、最大連続差分は、どのような順序付けでもチェーン内のステップが無効にならないことを保証する最も厳しい制約になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort()
    
    # include initial 0
    prev = 0
    ans = 0
    
    for x in a:
        ans = max(ans, x - prev)
        prev = x
    
    print(ans)

if __name__ == "__main__":
    solve()
```この解決策では、配列をソートして、問題内で唯一の意味のある構造順序を強制します。 次に、前の値を 0 から追跡し、連続する値間の最大ギャップを計算します。 その最大ギャップは次の最小値です。`d`これにより、遷移がブロックされることがなくなります。 

よくある実装の落とし穴は、0 から最小要素への初期遷移を含めることを忘れることです。 プロセスは 0 から始まり、これを無視すると必要な処理が過小評価されるため、これは不可欠です。`d`。

 ## 特殊なケース

 微妙なケースの 1 つは、最小要素が 0 よりはるかに大きい場合です。入力の場合:```
3
100 101 102
```ソートされた配列は`[100, 101, 102]`。 アルゴリズムはギャップを計算します。`0→100 = 100`、`100→101 = 1`、`101→102 = 1`。 答えは100です。 

最初の 0 を無視すると、誤って 1 が出力され、0 から始まる最初のカードを合法的に配置することができないため、失敗します。 

初期遷移が同じ最大ギャップ計算に明示的に含まれるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、1 つの遠く離れた外れ値を除いて値が密にクラスター化されている場合です。 のために：```
4
1 2 3 1000
```ソートされたシーケンスは、次の位置で支配的なギャップを生成します。`3→1000 = 997`、アルゴリズムは正しく 997 を返し、順序の曖昧さが最終値に到達する前に早期のブロックを引き起こす可能性がないことを保証します。
