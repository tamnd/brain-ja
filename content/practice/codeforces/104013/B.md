 ## 解決策
 ## 問題の理解

 サイクリストは 2 つの月次自転車レンタル プランから選択しており、固定月における各プランの合計コストを計算する必要があります。 

毎日、サイクリストは合計で自転車を使用します。`T`分。 この時間は通勤時間と帰宅時間に分割されますが、この問題では 1 日の合計としてすでに与えられています。 

最初のプランは月額固定料金がかかります`a`。 このプランでは、毎日 30 分間の無料利用が可能です。 1 日の使用量が 30 分を超える場合、超過分ごとに料金が発生します`x`。 

2番目のプランは月額固定料金がかかります`b`。 このプランでは、毎日 45 分間の無料利用が可能です。 45 分を超えると料金がかかります`y`毎分。 

11 月の営業日はちょうど 21 日あり、日次パターンはすべての日で同一であると想定されます。 タスクは、全 21 日間にわたる各プランの合計コストを計算することです。 

出力は 2 つの整数で、それぞれ最初と 2 番目の計画に基づく合計コストを表します。 

制約は非常に小さく、すべての金銭的価値と`T`これは、計算が定数時間であるため、プランごとの直接演算で十分であることをすぐに示唆しています。 広い範囲にわたるループや最適化テクニックは必要ありません。 

よくある間違いは、「無料分」の境界を誤解することから発生します。 もし`T`無料制限以下である場合、追加コストはマイナスではなくゼロでなければなりません。 もう 1 つの微妙な問題は、超過料金が 1 日ごとに適用され、21 倍する必要があることを忘れていることです。 

たとえば、次の場合`T = 10`どちらのプランにも追加料金はなく、答えは簡単です。`(21 * a, 21 * b)`。 ゼロにクランプせずに減算する単純な実装では、誤って負の電荷が生成されてしまいます。 

## アプローチ

 ブルートフォース解釈では、21 日間をそれぞれシミュレートし、毎日、無料枠を超えて 1 分ごとに反復してコストを累積します。 たとえば、毎日、31 分から 31 分までループできます。`T`最初のプランに追加`x`毎分。 これは正しく機能しますが、内部ループにより不必要に冗長になります。 

最悪の場合、`T = 1440`したがって、内側のループは 1 日あたり約 1410 回の反復を実行します。 21 日間で、これはプランあたり約 30,000 の操作に相当します。これでも問題ありませんが、構造を考えると完全に不要です。 

重要な観察点は、各計画は、その分布ではなく、しきい値を超える分数のみに依存するということです。 計算したら`max(0, T - 30)`そして`max(0, T - 45)`とすると、総コストは単純な直線式になります。 これにより、問題は定数時間の演算に縮小されます。 

ブルート フォースは、分単位のコストを直接累積するため機能しますが、しきい値を超える分すべてのコストが同じであると認識すると、過度の複雑さとして失敗します。 観測により、1 分あたりのループが 1 つの乗算に折りたたまれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(21・T) | お(1) | 受け入れられるが不要 |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 同じ構造を使用して各計画を個別に計算します。 

1. 入力を読み取ります`a, x, b, y, T`。 これらは、固定コスト、分ごとのペナルティ、および毎日の使用量を定義します。 
2. 最初のプランの請求時間数を次のように計算します。`over1 = max(0, T - 30)`。 これにより、無料分に対して料金が請求されることはありません。 
3. 最初のプランの 1 日の合計コストを次のように計算します。`day1 = a + over1 * x`。 固定料金は1日1回必ず含まれます。 
4. 21 を掛けて月額料金を取得します。`total1 = 21 * day1`。 これは 11 月のすべての営業日を反映しています。 
5. 45 分のしきい値を使用して、2 番目の計画に対して同じロジックを繰り返します。`over2 = max(0, T - 45)`。 
6. コンピューティング`day2 = b + over2 * y`その後`total2 = 21 * day2`。 
7. 出力`total1`そして`total2`。 

各ステップは純粋に代数的であり、コスト構造が超過分数に対して線形であるため、反復は必要ありません。 

### なぜ効果があるのか

 各プランは、一定の基本料金と、固定のしきい値を超える使用量の部分にのみ適用される単位あたりの料金を定義します。 毎日は同じなので、総コストは単純に決定的な 1 日あたりの関数の 21 倍になります。 唯一の決定は、`T`しきい値を超え、それが解決されると、残りの計算は超過量に関して線形になります。 日の間、または 1 日のうちの分の間に相互作用は存在しないため、構造を閉じた形式の式に折りたたむと正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a = int(input().strip())
x = int(input().strip())
b = int(input().strip())
y = int(input().strip())
T = int(input().strip())

days = 21

over1 = max(0, T - 30)
day1 = a + over1 * x
total1 = days * day1

over2 = max(0, T - 45)
day2 = b + over2 * y
total2 = days * day2

print(total1, total2)
```このソリューションは 5 つの整数を読み取り、それらをすぐに 2 つの独立したコスト式に変換します。 

の使用`max(0, ...)`マイナスの超過料金は基本料金を誤って引き下げる可能性があるため、必須です。 21 の乗算は日次コストの計算後に行われるため、構造がクリーンに保たれ、日次ロジックと月次ロジックが混在するリスクが軽減されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | お(1) | 固定数の算術演算のみが実行されます。 
| スペース | お(1) | 追加のデータ構造は使用されません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    a = int(input().strip())
    x = int(input().strip())
    b = int(input().strip())
    y = int(input().strip())
    T = int(input().strip())

    days = 21

    over1 = max(0, T - 30)
    total1 = days * (a + over1 * x)

    over2 = max(0, T - 45)
    total2 = days * (b + over2 * y)

    return f"{total1} {total2}"

# provided samples
assert run("10\n1\n20\n2\n40\n") == "420 420"

# minimum case: no overage
assert run("0\n0\n0\n0\n1\n") == "0 0"

# boundary at exact thresholds
assert run("5\n2\n7\n3\n30\n") == f"{21*(5)} {21*(7)}"

# second plan dominates due to lower overage
assert run("10\n10\n100\n1\n100\n") == "14700 11550"

# high T case
assert run("1\n1\n1\n1\n1440\n") == str(21*(1 + 1410)) + " " + str(21*(1 + 1395))
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | T=1、ゼロレート | 0 0 | 超過行為は禁止 |
 | しきい値での T | ベースのみのコスト | 境界の正確性 |
 | 高コストの不均衡 | 異なるスケーリング | 比較の正しさ |
 | 最大 T | 多額の超過料金の処理 | ストレス算術の正確性 |

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です`T`両方のしきい値よりも小さいです。 例えば、`T = 10`。 計算`T - 30`そして`T - 45`マイナスだが当てはまる`max(0, ...)`両方の超過を強制的にゼロにし、コストが発生する`21 * a`そして`21 * b`。 このクランプがないと、計算式は基本料金から誤って金額を差し引き、意味のないマイナスの合計が生成されてしまいます。 

別のエッジ ケースがまさにしきい値で発生します。 もし`T = 30`、最初のプランでは、1 分以上ではなく、0 分の追加料金を請求する必要があります。 表現`max(0, 30 - 30)`正しくゼロを生成し、偶発的なペナルティが発生しないようにします。 

3番目のケースは大きいです`T`上限近く (1440 など)。超過分は大きくなりますが、最大積は`21 * 1440 * 100`、これは 32 ビットの制限内に十分収まります。
