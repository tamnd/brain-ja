 ## 解決策
 ## 問題の理解

 毎日の石油価格のシーケンスが与えられており、少なくとも 3 つの長さのすべての連続する部分配列を検査したいと考えています。 このようなセグメントごとに、その内部の日々の違いを調べます。 これらの違いは、セグメント内で価格がどのように動くかを示す小さな時系列として扱われます。 

これらの違いから 2 つの統計を計算します。 1 つ目は平均差で​​あり、これは連続した変更の平均にすぎません。 2 番目は、同じ変化の標準偏差です。 次に、平均の大きさと変動性を比較することによってセグメントが分類されます。傾向が正であるか負であるかを決定する別の符号条件を使用して、平均の変化が少なくとも P 倍だけ標準偏差を支配しているかどうかを確認します。 

セグメントが正の傾向または負の傾向の不等式を満たす場合、そのセグメントは答えに寄与します。 各カテゴリに分類されるセグメントの数を数えなければなりません。 

d ≤ 3000 という制約により、すべてのサブセグメントの 2 次または 2 次に近い列挙はすでに境界線に達していますが、セグメント長を超える 3 次の列挙は不可能であることが明らかです。 しかし、本当の難しさは単に列挙することではなく、各セグメントに差分に関する浮動小数点統計が含まれており、サブ配列ごとにそれらを単純に再計算すると余分な線形係数が導入され、強引なアプローチをおよそ O(n^3) に押し上げることになり、これでは遅すぎます。 

2 番目の微妙な問題は、数値の安定性です。 この問題は、答えを変えることなく P の小さな摂動を明示的に許可します。これは、導出された式の浮動小数点比較を直接行うことは許容されますが、より安定した二次形式への代数的並べ替えが強く推奨されることを示しています。 

重要なエッジケース:

 エッジ ケースの 1 つは、セグメント内のすべての値が同一である場合です。 この場合、すべての差はゼロになるため、平均と標準偏差は両方ともゼロになります。 この問題は、A = 0 の場合、D = 0 であっても傾向が存在しないため、そのようなセグメントは両方のカウントから除外する必要があることを示しています。 A = 0 を処理せずに不等式のみをチェックする単純な実装では、これらが両方の符号に対して有効であると誤って分類されてしまいます。 

もう 1 つのエッジ ケースは、モノトーン シーケンスです。 たとえば、厳密に増加するシーケンスでは D = 0 が生成されます。A > 0 の場合、任意のべき乗の正の傾向としてカウントされます。 不用意に実装すると、誤ってゼロで除算したり、分散がゼロであるために破棄されたりする可能性があります。 

最後に、非常に小さいセグメント (長さ 3) は、分散計算のサンプルが非常に少なく、プレフィックス処理でのオフバイ 1 エラーがよく発生するため、動作が異なります。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのサブ配列を考慮し、その内部の差分をすべて計算してから、平均と標準偏差を直接計算します。 長さ L の固定部分配列の場合、統計の計算には O(L) かかり、O(n^2) 個の部分配列があるため、合計時間は O(n^3) になります。 n = 3000 の場合、これは約 270 億回の操作に相当しますが、これは現実的ではありません。 

平均と分散の両方が差に対する単純な加算量のみに依存することを観察することで、これを改善できます。 差分配列 b[i] = c[i+1] − c[i] を定義すると、任意のセグメント [l, r] について、必要な統計は b[l..r−1] の合計と同じ範囲の平方和にのみ依存します。 

これにより、プレフィックスの合計を前処理した後、各サブ配列の評価が O(1) に減ります。 重要な変換は、標準偏差が完全に二乗和と合計によって表現され、再計算を回避できることを認識することです。 書き換えると、平均と標準偏差を比較する条件は、接頭語の合計値のみを含む不等式になります。 

したがって、問題はすべての O(n^2) 個の部分配列を一定時間でチェックすることに帰着します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 差分に対するプレフィックスの合計 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 問題を違いの観点から書き直します。 1 から d−1 までの i に対して b[i] = c[i+1] − c[i] とします。 

1. 接頭辞の合計 S[i] = b[1..i] の合計、および接頭辞の二乗 Q[i] = b[1..i]^2 の合計を構築します。 これにより、定数時間の範囲クエリが可能になります。 
2. 元の配列内の長さが 3 以上のすべての部分配列 [l, r] について、その差分範囲 [l, r−1] を考慮します。 k = r − l とすると、k 個の違いがあります。 
3. この範囲にわたる差の合計を sumB = S[r−1] − S[l−1] として計算します。 平均は A = sumB / k です。 
4. 平方和を sumB2 = Q[r−1] − Q[l−1] として計算します。 
5. 分散時間 k は、k * D^2 = sumB2 − (sumB^2 / k) で表されます。 これにより、偏差を明示的に計算することが回避されます。 
6. 平方根をとらずに A と D を比較します。 A / D ≥ P または A / D ≤ −P のみが必要なので、注意深く二乗し、符号の場合を分けます。 

sumB = 0 の場合、A = 0 となり、セグメントを直接拒否します。 

それ以外の場合は、 |A| と同等の二乗不等式を計算します。 ≥ P * D ですが、正と負のトレンドの符号を別々に保持します。 
7. A > 0 で条件が成立する場合、肯定的な応答をインクリメントします。 A < 0 で条件が成立する場合、負の答えをインクリメントします。 

重要な考え方は、すべてがプレフィックス合計の 2 次形式に帰着するため、各部分配列チェックは O(1) になるということです。 

なぜ効果があるのか:

 トレンドの定義で使用されるすべての統計は、セグメント内の差分シーケンスの最初と 2 番目のモーメントのみの関数です。 これらのモーメントは範囲にわたって加算されるため、プレフィックスの合計によって完全に特徴付けられます。 分散の定義から二乗和への変換により、要素ごとの反復への依存がなくなり、最終的な不等式はこれらの集計値の代数的組み合わせのみに依存します。 各セグメントはこれらの集合体の正確な算術を使用して 1 回だけ評価されるため、無視できる浮動小数点誤差を除き、有効なセグメントが誤って分類されることはありません。これは、問題ステートメントで明示的に許容されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    d, P = input().split()
    d = int(d)
    P = float(P)

    c = list(map(int, input().split()))
    n = d

    if n < 3:
        print("0 0")
        return

    b = [c[i+1] - c[i] for i in range(n - 1)]

    m = n - 1
    S = [0.0] * (m + 1)
    Q = [0.0] * (m + 1)

    for i in range(m):
        S[i+1] = S[i] + b[i]
        Q[i+1] = Q[i] + b[i] * b[i]

    pos = 0
    neg = 0

    for l in range(n):
        for r in range(l + 2, n):
            k = r - l
            sumB = S[r] - S[l]
            if sumB == 0:
                continue

            sumB2 = Q[r] - Q[l]

            mean_num = sumB
            # variance numerator: k*D^2 = sumB2 - sumB^2/k
            # we compare |A| >= P * D carefully without sqrt:
            # A^2 >= P^2 * D^2
            # (sumB^2 / k^2) >= P^2 * ((sumB2/k) - (sumB^2/k^2))

            left = sumB * sumB
            right = P * P * (sumB2 * k - sumB * sumB)

            if left >= right:
                if sumB > 0:
                    pos += 1
                else:
                    neg += 1

    print(pos, neg)

if __name__ == "__main__":
    main()
```このコードは、すべてのセグメント統計が加算されるように、最初に価格を差分配列に変換します。 プレフィックス配列 S および Q には、これらの違いの最初と二番目の瞬間が保存され、任意の間隔で O(1) クエリが可能になります。 

二重ループは、すべての有効なセグメントを列挙します。 r ≥ l + 2 という制約により、少なくとも 3 つの元の要素が保証されます。 各セグメントに対して sumB と sumB2 を計算し、A^2 ≥ P^2 D^2 から導出される代数不等式を適用します。 A = 0 はトレンドがないことを意味するというルールを尊重するために、ゼロサムのケースを明示的にスキップします。 

微妙な点は、平方根や標準偏差を直接計算することは決してないということです。 これにより、精度の問題が回避され、不必要な浮動小数点演算も回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    data = inp.strip().split()
    d = int(data[0])
    P = float(data[1])
    c = list(map(int, data[2:]))

    if d < 3:
        return "0 0"

    b = [c[i+1] - c[i] for i in range(d-1)]
    S = [0]
    Q = [0]

    for x in b:
        S.append(S[-1] + x)
        Q.append(Q[-1] + x*x)

    pos = neg = 0
    for l in range(d):
        for r in range(l+2, d):
            k = r - l
            s = S[r] - S[l]
            if s == 0:
                continue
            q = Q[r] - Q[l]
            if s*s >= P*P*(q*k - s*s):
                if s > 0:
                    pos += 1
                else:
                    neg += 1

    return f"{pos} {neg}"

# provided samples
assert run("6 0.2\n100 110 120 30 40 50") == "2 8"
assert run("6 0.7\n100 110 120 30 40 50") == "2 2"

# custom cases
assert run("3 1.0\n1 2 3") == "1 0"  # single increasing segment
assert run("3 1.0\n1 1 1") == "0 0"  # all equal
assert run("4 0.5\n1 3 2 4") != ""   # sanity check non-empty
