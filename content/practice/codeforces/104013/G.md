 ## 解決策
 ## 問題の理解

 相互作用しなければならない 2 つの別個の構造が与えられています。それは、チョムスキー正規形の文脈自由文法と、エッジが小文字でラベル付けされている有向グラフです。 文法は端子の文字列を生成しますが、グラフはエッジに沿って歩き、それらのラベルを連結することによって文字列を生成します。 

タスクは、グラフ内の有向パスに沿って開始頂点 s からターゲット頂点 t まで移動し、そのパスに沿ったエッジ ラベルのシーケンスが文法の開始記号 S から導出できる文字列を形成するようにすることです。そのような有効なパスすべての中で、使用されるエッジの数を最小限にするか、有効なパスが存在しないことを報告する必要があります。 

文法は 2 つのタイプのルールに制限されています。非終端文字は 1 つの終端文字または 1 組の非終端文字のいずれかを生成します。 この制限は、派生が CYK による解析と同様のバイナリ ツリー構造を持つことを意味しますが、固定文字列を解析しているわけではないため、非常に重要です。 代わりに、グラフを移動することによって生成されたすべての文字列を同時に調査します。 

グラフの頂点数は少なく、最大 26 頂点ですが、エッジが密になる可能性があります。 文法には最大 100 個の生成がありますが、非終端文字も大文字に制限されているため、文法記号の状態空間は実質的に 26 で制限されます。 

重要な問題は、文字列が指定されていないことです。 ラベル文字列がコンテキストフリー言語に属する最短パスを発見する必要があります。これは基本的に、グラフ到達可能性と CFG 認識の問題を組み合わせたものです。 

単純なアプローチでは、グラフ内のすべてのパスをある程度の長さまで列挙し、それらのラベル文字列が文法に属しているかどうかをチェックしようとする可能性があります。 n が 26 までであっても、パスの数は長さに応じて指数関数的に増加し、サイクルによって無限の探索が可能になるため、これはすぐに失敗します。 

2 番目の単純なアプローチでは、文法によって生成されたすべての文字列を解析し、それぞれがグラフ内のパスとして実現できるかどうかを確認することが考えられます。 文法が指数関数的に多くの文字列を生成する可能性があるため、これも失敗します。 

両方の構造のサイクルから微妙なエッジケースが発生します。 たとえば、文法では S → SS が許可され、グラフには頂点から頂点自体に戻るサイクルが含まれる場合があります。 文法状態を追跡せずにグラフ状態のみを対象とした単純な BFS では、すべてのパスが同じ頂点に到達すると誤って同等なものとして扱われ、必要な導出コンテキストが失われ、有効な導出が過大にカウントされるか欠落します。 

## アプローチ

 直接的な総当たりのアイデアは、グラフ内の各部分パスを候補文字列として扱い、CYK スタイルの動的プログラムを使用して文法で解析しようとすることです。 パスの長さが L の場合、古典的な形式では解析コストは O(L³) であり、分岐と循環により指数関数的に多くのパスが存在します。 文法の制約により頂点の再検討が必要になる場合があるため、単純なパスに制限しても役に立ちません。 

ターニングポイントは視点を逆転させることです。 文字列を構築して文法のメンバーシップをチェックする代わりに、グラフを歩きながら同時に文法の導出をシミュレートします。 非終端 A は、「2 つの頂点間に A からラベル文字列を導出できるパスが存在する」に相当します。 グラフ頂点と文法の非終端の積空間で到達可能性を計算したいと考えています。 

プロダクションはCNFなので、各ルールはA→BCまたはA→aのいずれかになります。 最終規則は直接的なグラフ エッジを提供します。a というラベルの付いたエッジ u → v とルール A → a がある場合、A は u から v までの長さ 1 のパスを導出できます。バイナリ ルールはより短い導出を組み合わせます。つまり、B が u から中間ノード k に移動でき、C が k から v に移動できる場合、A は u から v に移動できます。

この構造は、層状状態空間上の最短経路問題を示唆しています。 各状態はトリプル (A、u、v) であり、非終端 A が u から v への何らかのパスを導出することを意味します。ただし、各非終端に対してすべてのペア (u、v) を明示的に列挙することはまだ概念的に大きすぎますが、グラフには頂点が 26 しかないため、ペアの数は最大 676 であり、管理可能です。 

これを、遷移が文法生成に対応する最短経路伝播問題として再解釈できます。 ターミナル プロダクションでは、頂点ペア間にコスト 1 のエッジが与えられます。 バイナリ生成は、既知の 2 つの最短導出を組み合わせることに対応し、頂点と非終端によってインデックス付けされた行列に対する閉包演算に似ています。 

最後の重要な洞察は、各非終端を 26×26 の距離行列を定義するものとして扱うことです。ここで、 dist[A][u][v] は、A から導出可能な u から v までの最短パス長です。終端エッジを使用して初期化し、A → BC に繰り返し緩和を適用します。 

dist[A][u][v] = min(dist[A][u][v], dist[B][u][k] + dist[C][k][v]) すべての k に対して。 

これは、有限状態空間にわたる反復緩和となり、複合状態にわたるマルチソース BFS / ダイクストラのような伝播を使用して効率的に処理できます。または、より明確には、各緩和ステップがパス長によってキー設定された優先キューの改善であるグラフ展開を使用して効率的に処理できます。 

すべてのエッジには単位コストがあるため、拡張された状態空間では BFS で十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース パス + 解析 | 指数関数 | 指数関数 | 遅すぎる |
 | 文法状態 BFS over (非終端, u, v) | O(p · n³) 最悪の場合のナイーブ | O(p · n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 (A, u, v) の形式の状態に対する最短パス検索を構築します。これは、非終端 A が特定のコストで u から v へのパスを生成できることを意味します。 

1. すべての端末プロダクションでキューを初期化します。 すべての文法規則 A → a および a とラベル付けされたすべてのグラフ エッジ u → v に対して、距離 1 の状態 (A, u, v) を挿入します。これは、単一の端末が単一のエッジに直接一致する基本的なケースです。 
2. 無限大に初期化された距離テーブル dist[A][u][v] を維持し、最初の端子一致で更新します。 これにより、後でより悪い導出を再計算することがなくなります。 
3. 優先キューから最小距離状態 (A、u、v) を繰り返し抽出します。 これにより、拡張された状態グラフ上でダイクストラの正確性原則を反映して、常に現在最短の既知の導出を最初に拡張することが保証されます。 
4. 抽出された各状態 (A、u、v) について、B → AC および B → CA の形式の文法規則を使用して展開してみます。 考えられる中間頂点 k ごとに、2 番目のコンポーネント (順序に応じて C または A) の有効な導出がすでにわかっている場合は、それらを組み合わせて B のより長い導出を行うことができます。 
5. 具体的には、dist[A][u][x] とルール B → AC がある場合、x から v までのすべての C 導出について、dist[B][u][v] の緩和を試みます。 B → CA についても同様です。 
6. 緩和が成功するたびに、距離が更新された新しい状態がキューに挿入されます。 
7. 到達可能な状態をすべて処理すると、答えは dist[S][s][t] になります。 無限大のままの場合はNOを出力します。 

これが機能する本質的な理由は、CNF 文法のすべての導出がバイナリ解析ツリーに対応しているためです。 各内部ノードは、グラフ パス内の分割点 k に対応します。 アルゴリズムは、すでに検出されたサブパスを結合することによって、これらの分割を暗黙的に列挙します。 常にパス長の増加順に展開するため、後で長い派生を無効にする可能性がある短い派生を見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict, deque
import heapq

INF = 10**18

n_rules = int(input())
rules_term = defaultdict(list)
rules_bin = defaultdict(list)

for _ in range(n_rules):
    parts = input().split()
    lhs = parts[0]
    rhs = parts[2]
    if len(rhs) == 1:
        rules_term[rhs].append(lhs)
    else:
        rules_bin[lhs].append((rhs[0], rhs[1]))

n, m, s, t = map(int, input().split())
s -= 1
t -= 1

edges = defaultdict(list)
for _ in range(m):
    u, v, c = input().split()
    u = int(u) - 1
    v = int(v) - 1
    edges[u].append((v, c))

# dist[A][u][v]
dist = defaultdict(lambda: [[INF]*n for _ in range(n)])
pq = []

# initialize terminal edges
for u in range(n):
    for v, c in edges[u]:
        for A in rules_term[c]:
            if dist[A][u][v] > 1:
                dist[A][u][v] = 1
                heapq.heappush(pq, (1, A, u, v))

# Dijkstra-like expansion
while pq:
    d, A, u, v = heapq.heappop(pq)
    if dist[A][u][v] != d:
        continue

    # try combining A with binary rules
    for B in list(rules_bin):
        for X, Y in rules_bin[B]:
            if X == A:
                # A is left child, need C = Y
                C = Y
                for mid in range(n):
                    if dist[A][u][mid] < INF:
                        for to in range(n):
                            if dist[C][mid][to] < INF:
                                nd = dist[A][u][mid] + dist[C][mid][to]
                                if nd < dist[B][u][to]:
                                    dist[B][u][to] = nd
                                    heapq.heappush(pq, (nd, B, u, to))
            if Y == A:
                # A is right child
                Bc = X
                for mid in range(n):
                    if dist[Bc][mid][u] < INF:
                        for to in range(n):
                            if dist[A][u][to] < INF:
                                nd = dist[Bc][mid][u] + dist[A][u][to]
                                if nd < dist[Bc][mid][to]:
                                    dist[Bc][mid][to] = nd
                                    heapq.heappush(pq, (nd, Bc, mid, to))

ans = dist['S'][s][t]
print(-1 if ans == INF else ans)
```このソリューションは、すべての頂点ペアにわたる各非終端の明示的な最短導出を構築します。 優先キューにより、短い派生が常に最初に展開され、長い中間構造による誤った上書きが防止されます。 重要な実装の詳細は、各緩和が 1 つの文法生成 (端末またはバイナリのいずれか) に正確に対応するため、検索空間が明確に定義され、有限であることです。 

微妙な点は、(u, v) を単純なグラフ状態として決して扱っていないことです。 常に文法記号とペアになります。 これがないと、最短パスは構文上の制約を無視し、無効な文字列を生成します。 

## 実用的な例

 文法に S → AB、A → a、B → b があり、グラフに 1 から 4 までの 2 つのルートを形成する a → b エッジが含まれる簡略化された実行をトレースします。 

### 例 1

 | ステップ | 状態 | 距離 | アクション |
 | --- | --- | --- | --- |
 | 1 | (A,1,2) | 1 | 端子のエッジ |
 | 2 | (B,2,3) | 1 | 端子b端 |
 | 3 | 組み合わせる | 2 | A から B を経由して導出される S |

 これにより、長さ 2 の S パス 1 → 2 → 3 が生成されます。 

これは、アルゴリズムが隣接する終端導出を完全な文法導出に正しく構成していることを確認します。 

### 例 2

 循環文法 S → SS と、両方のエッジに c と j のラベルが付いたグラフ サイクル 1 → 2 → 1 を考えてみましょう。 

| ステップ | 状態 | 距離 | アクション |
 | --- | --- | --- | --- |
 | 1 | (L,1,2) | 1 | Cエッジ |
 | 2 | (R,2,1) | 1 | ジェイエッジ |
 | 3 | (S,1,1) | 2 | S→LR |

 これは、より短い導出が見つかった場合にのみ状態が再検討されるため、サイクルが自然に処理されることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、s が t に等しいが、文法上少なくとも 1 つの端子が必要な場合です。 このアルゴリズムは、実際のエッジから状態を初期化するだけなので、これを正しく処理します。そのため、文法構造を通じて明示的に導出できない限り、空のパスは決して生成されません。CNF はイプシロン ルールなしでこれを禁止しています。 

もう 1 つのケースは、同じ (A、u、v) に対する複数の重複する導出です。 プライオリティ キューにより、最適なキューのみが展開され、古いエントリは距離チェックによって無視されます。 

最後の微妙なケースは、S → SS などの非常に曖昧な文法です。 各状態は (A, u, v) ごとにメモ化されるため、アルゴリズムは組み合わせ的に導出を拡張しません。 これにより、文法が指数関数的に多くの解析ツリーを許容する場合でも、指数関数的な爆発が防止されます。
