 ## 解決策
 ## 問題の理解

 時間間隔のコレクションが与えられ、それぞれが連続した分単位の範囲を占めるテレビ番組を表します。 重要な制約は、1 台のテレビを使用して、間隔が時間的に重なる 2 つの番組を視聴できないことです。 1 つの番組が 2 分から 5 分まで実行され、別の番組が 4 分から 7 分まで実行されている場合、4 分と 5 分が衝突するため、同じテレビに割り当てることはできません。 

各テレビは、割り当てられたすべての番組をカバーする連続した期間にわたってレンタルされます。 テレビを数分から使用する場合`a`分まで`b`、料金は、固定レンタル料金と、期間に比例した分単位の延長料金で構成されます。`x + y * (b - a)`。 

タスクは、総レンタルコストを最小限に抑える方法で、すべての番組をテレビに割り当て、重複しない間隔を同じテレビにグループ化することです。 各 TV は、時間の増加順に視聴する必要がある一連のばらばらの間隔に対応しており、コストは、その TV で使用された最初の 1 分間から最後に使用される 1 分間までの期間にのみ依存します。 

制約が十分に大きいため、考えられるすべての割り当てを比較したり、間隔の分割を列挙しようとしたりするソリューションは不可能です。 最大 100,000 間隔では、おおよそよりも悪いものはありません`O(n log n)`苦労するだろう。 これにより、ブルートフォースグループ化やサブセットに対する動的プログラミングが即座に排除されます。 

いくつかの特殊なケースでは、よくある落とし穴が明らかになります。 すべての間隔が互いに素である場合、単純なアプローチでは依然としてそれらを誤って結合しようとし、TV の数を過小評価する可能性があります。 たとえば、間隔`[1,2]`そして`[3,4]`1台のテレビで互換性がありますが、`[1,3]`そして`[2,4]`エンドポイントが近いにもかかわらず、そうではありません。 もう 1 つの微妙なケースは、間隔が重なりの連鎖を形成する場合です。`[1,10], [2,3], [4,5], [6,7]`。 「エンドポイントが分離しているように見える場合は、すべてを 1 台の TV に詰め込む」という貪欲なアプローチは、長い間隔によって再利用がブロックされるため、ここでは失敗します。 

本当の課題は、新しいテレビの開設コストという 2 つの相反するコストのバランスをとることです。`x`、既存のテレビをより長いスパンで拡張するにはコストがかかりますが、`y`毎分。 以来`y < x`、間隔をより長いスパンにマージすることは多くの場合有益ですが、それはオーバーラップ構造が許可する場合に限られます。 

## アプローチ

 ブルートフォース ソリューションでは、各間隔を TV に割り当て、可能なすべてのグループ化を維持しようとします。 各 TV は重複しない一連の間隔を形成し、割り当てごとに、各グループの最小時間と最大時間に基づいてコストを計算します。 間隔の分割数は指数関数的に増加するため、このアプローチは、`n = 30`、ましてや`10^5`。 

重要な観察は、TV のコストは、内部に含まれるインターバルの数ではなく、割り当てられたインターバルの結合スパンのみに依存するということです。 間隔を開始時間で並べ替えると、それらを順番に処理し、同時にアクティブになっているテレビの数を推論できます。 

どの瞬間においても、重複する間隔の数によって、最低必要なテレビの数が決まります。 ただし、テレビを早めに開けて隙間を通って稼働し続ける方が、新しいテレビごとに固定費がかかるため、新しいテレビを繰り返し開けるよりも安くなる可能性があります。`x`。 

これはスイープラインの視点につながります。つまり、時間が経過するにつれて、間隔が開始および終了し、アクティブな数が維持されます。 現在アクティブなすべてのチェーンを超えてインターバルが開始されるたびに、コストのトレードオフに応じて、既存の TV を拡張するか、新しい TV を開始します。 インターバルがソートされた順序で処理され、互換性のある最も古い TV に割り当てられると、最適な戦略は貪欲になり、タイム スパンの断片化を最小限に抑えます。 

私たちは一連のアクティブな「TV セグメント」を効果的に維持し、その終端が最も近くてもまだ有効な TV に常に新しい間隔を付加します。これにより、無駄なアイドル時間が最小限に抑えられます。 これにより、重複制約を尊重しながら、新しい TV を不必要に開くことが削減されます。

 ## アルゴリズムのチュートリアル

 1. すべての間隔を開始時間で並べ替えます。 これにより、ショーを時系列順に処理することが保証されるため、決定には任意の入力順序ではなく実際の重複構造が反映されます。 
2. 利用可能な TV を追跡するデータ構造を維持し、その TV に割り当てられた最後の番組の最終終了時刻によってインデックスを付けます。 最も早く利用可能になった TV を再利用したいため、ここでは最小ヒープがうまく機能します。 
3. 各間隔で反復します`[l, r]`ソートされた順序で。 
4. 現在の間隔について、最後に割り当てられた間隔がその前または時刻に終了する TV が存在するかどうかを確認します。`l`。 そのようなテレビが存在する場合は、終了時間が最も短いテレビを再利用します。これにより、将来の割り当てに対する柔軟性が向上します。 
5. そのような TV が存在しない場合は、この間隔で新しい TV を開きます。 
6. TV に間隔を割り当てるときに、コスト寄与を更新します。 これがテレビの最初のインターバルである場合、料金にはレンタル期間全体が含まれます。`l`。 それ以外の場合は、既存のスパンを拡張しますが、これはエンドポイントを増やすだけです。 
7. 各テレビの現在の状態を追跡する`[start, end]`最終的なコストは、内部の個々の間隔ではなく、これらの境界のみに依存するためです。 
8. すべての間隔を処理した後、次を使用してすべての TV のコストを合計します。`x + y * (end - start)`それぞれに。 

### なぜ効果があるのか

 最も早く利用可能になったテレビを常に再利用するという貪欲な選択により、将来の柔軟性が維持されます。 互換性のある別の TV を使用する代替割り当てでは、他の場所で断片化が増加することなく、選択した TV のスパンを減らすことはできません。 コストはスパンに比例して増加し、オープニング料金が固定されているため、TV の数とアイドル延長の合計を最小限に抑えることは、最小のスパンで重複しないセグメントのチェーンに間隔を詰め込むことと同じです。 ヒープベースのアーリーフィット戦略により、各チェーンが可能な限り時間内に緊密になり、増加する不必要なギャップを防ぎます。`(end - start)`。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline
MOD = 10**9 + 7

def solve():
    n, x, y = map(int, input().split())
    segs = [tuple(map(int, input().split())) for _ in range(n)]
    segs.sort()

    # each TV: (current_end, start_time)
    # we track active TVs by end time
    heap = []

    # store final segments for cost computation
    tvs = []

    for l, r in segs:
        if heap and heap[0][0] < l:
            end, start = heapq.heappop(heap)
            # extend this TV
            start = min(start, l)
            end = r
            heapq.heappush(heap, (end, start))
        else:
            heapq.heappush(heap, (r, l))

    # compute cost
    res = 0
    while heap:
        end, start = heapq.heappop(heap)
        length = end - start
        res += x + y * length
        res %= MOD

    print(res % MOD)

if __name__ == "__main__":
    solve()
```この実装は、貪欲な連鎖のアイデアに直接準拠しています。 間隔は、処理時に次のようにソートされます。`[l, r]`、以前のすべての間隔はすでに何らかのチェーンに配置されています。 ヒープには、終了時刻をキーとした現在の TV チェーンが保存されます。 最も早く終了するテレビが現在の番組に対応できる場合は、延長します。 それ以外の場合は、新しいチェーンが開始されます。 

微妙な点は、必要なのは`(start, end)`中間構造はコストに関係ないため、テレビごとに。 もう 1 つの重要な詳細は、すべての TV をスキャンするのではなくヒープを使用することです。これにより、アルゴリズムが確実に維持されます。`O(n log n)`。

 ## 特殊なケース

 エッジケースの 1 つは、間隔がちょうど境界に接する場合です。 例えば`[1,2]`そして`[3,4]`それらを 2 から分離する分 3 には重複がないため、マージ可能であるはずです。アルゴリズムはこれを正しく処理します。これは、次の場合に再利用が許可されているためです。`end < l`隣接関係が有効であることを確認します。 

もう 1 つのエッジ ケースは、次のような厳密なオーバーラップ チェーンです。`[1,10], [2,3], [3,4]`。 たとえ短い間隔が互いに融合可能であるように見えても、長い間隔は分離を強制します。 ヒープは、長い間隔が独自のチェーンを確実に占有するようにしますが、短い間隔は順序に応じて結合することができます。 

最後のエッジ ケースは、新しい TV を開くと有益に見えるかもしれないが、既存の TV を拡張する方が安価であるという大きなギャップです。`y < x`。 再利用により常に固定費の蓄積が削減されるため、アルゴリズムは可能な限り自然にスパンを拡張します。
