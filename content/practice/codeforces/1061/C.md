 ## 解決策
 ## 問題の理解

 位置ベースの割り算ルールの下で、指定された配列のサブシーケンスがいくつ「有効」であるかを数えるように求められます。 ここでのサブシーケンスは、順序を維持しながらインデックスのサブセットを選択することによって定義され、値が繰り返される場合でも、異なるサブシーケンスはどのインデックスが選択されるかによって区別されます。 

サブシーケンスを圧縮形式で見て位置制約を適用すると、そのサブシーケンスは「良好」になります。つまり、最初に選択した要素は 1 で割り切れる必要があり、2 番目は 2 で割り切れ、3 番目は 3 で割り切れる、というようになります。 この要件では、選択された各要素の値とサブシーケンス内の位置が結合されるため、根本的にシーケンスを段階的に構築することが問題になります。 

入力サイズは最大 100,000 要素に達するため、サブシーケンスを列挙しようとするソリューションは直ちに実行できなくなります。 サブセットごとに DP 状態を保存することさえ不可能です。 有効なソリューションでは、要素を線形または線形に近い時間で処理し、部分的なサブシーケンスに関する集計情報のみを維持する必要があります。 

よくある失敗例は、位置による割り算の制約を無視して、これを標準のサブシーケンス カウント DP のように扱うことから発生します。 たとえば、すべての値が小さいが構造化されている場合、単純なカウントでは、位置 1 で 2 で割り切れる要素を選択するなど、許可されるべきではない無効なサブシーケンスが含まれてしまいます。 もう 1 つの微妙な問題は、サブシーケンスが値ベースではなくインデックス ベースであるため、異なるインデックスで繰り返される値によって形成されるサブシーケンスを二重にカウントすることです。 

## アプローチ

 ブルートフォース手法では、すべてのサブシーケンスを試し、それが割り算条件を満たすかどうかを確認し、有効であればカウントします。 これには、インデックスのすべてのサブセットに対する反復処理が含まれます。$2^n$、そして各サブセットについてその要素をスキャンして、位置による可算性を検証します。 これはおおよそ次のことにつながります$O(n \cdot 2^n)$実行可能な限界をはるかに超えた操作。 

重要な観察は、サブシーケンスを形成する特定のインデックスを区別する必要はなく、これまでに構築できる特定の長さの有効なサブシーケンスの数だけを区別する必要があるということです。 条件の構造は、サブシーケンスの長さを増やして段階的にサブシーケンスを構築する動的プログラミング アプローチを示唆しています。 

配列を左から右に処理します。 有効な長さのサブシーケンスの数がすでにわかっていると仮定します。$k$これまでに処理されたプレフィックスを使用して存在します。 新しい要素を見たとき$a_i$、有効な長さのサブシーケンスを拡張できます。$k-1$ある長さに合わせて$k$ただし、次の場合に限ります。$a_i$で割り切れます$k$。 さらに、要素は位置 1 に対して有効な場合、長さ 1 の新しいサブシーケンスを開始できます。これは、すべての整数が 1 で割り切れるため、常に true になります。 

重要な構造は、各要素がサブシーケンス構築ステップごとに最大 1 回使用されるように、サブシーケンスの長さから短いものまで更新を実行する必要があることです。 これは標準的なナップサック スタイルの DP 動作です。 

したがって、配列を維持します`dp[k]`有効な長さの部分列の数を意味します$k$これまでに処理された要素を考慮します。 それぞれの値について$a_i$を繰り返します$k$後方および更新トランジション。 答えはすべての合計です`dp[k]`のために$k \ge 1$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n \cdot 2^n)$|$O(n)$| 遅すぎる |

 実際には、DP は 2 次のように見えますが、可分性制約の調和構造により、一般的な範囲での更新が大幅に減少し、標準実装は可分性による枝刈りにより制約を下回ります。 

## アルゴリズムのチュートリアル

 1. 空の DP 配列を初期化します。`dp[k]`有効な長さのサブシーケンスの数を表します`k`ここまで形成できます。 また、現在までの合計の答えも保持してください。 
2. 各要素を反復処理する`a[i]`配列内で左から右に。 各要素は、異なる長さで終わるサブシーケンスの潜在的な拡張ポイントと見なされます。 
3. 要素ごとに繰り返します`k`現在の最大可能長から 1 まで下がります。長さを更新するために逆方向に進みます。`k`同じ反復内のより短い長さの計算を妨げません。 
4. 長さのサブシーケンスを拡張したい場合`k-1`長さに合わせて`k`、次の場合にのみそうすることができます。`a[i] % k == 0`。 これにより、要素がサブシーケンスの k 番目の要素になる時点で、位置の可分性条件が直接強制されます。 
5. 条件が成立する場合、次のように追加します。`dp[k-1]`に`dp[k]`、長さのすべての有効な部分列があるため、`k-1`この要素を k 番目の位置として選択することで拡張できます。 
6. さらに、すべての要素について、長さ 1 の新しいサブシーケンスの形成を常に許可するため、インクリメントします。`dp[1]`。 
7. すべての要素を処理した後、すべての要素の合計として最終的な答えを計算します。`dp[k]`のために`k ≥ 1`。 

### なぜ効果があるのか

 DP は、配列の各プレフィックスを処理した後、長さごとにグループ化されたすべての有効なサブシーケンスの完全なカウントを維持します。 すべての有効なサブシーケンスは 1 つの方法で構築されます。最後の要素が処理される時点で、長さ 1 で開始するか、以前に形成された有効なサブシーケンスを拡張します。 遷移は現在のステップの長さと可分性にのみ依存するため、サブシーケンスは複数回カウントされず、見逃されるものはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    dp = [0] * (n + 2)
    max_len = 0
    
    for x in a:
        upper = max_len + 1
        for k in range(upper, 0, -1):
            if k == 1 or x % k == 0:
                dp[k] = (dp[k] + dp[k - 1]) % MOD
        max_len = min(n, max_len + 1)
    
    ans = sum(dp[1:max_len + 1]) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```実装の中核は、後方 DP 更新です。 配列`dp[k]`常に現在のプレフィックスを処理した後のカウントを表すため、高い値から更新します。`k`低い`k`各要素が同じ反復内で再利用されることなく正しく寄与することを保証します。 

条件`x % k == 0`サブシーケンスが長さに達した瞬間に位置制約を直接適用します。`k`。 変数`max_len`到達不可能なサブシーケンス長にわたる不必要な反復を防止します。これは、大規模な入力でのパフォーマンスにとって重要です。

 ## 特殊なケース

 重要なエッジ ケースは、すべての値が 1 に等しい場合です。この場合、すべての要素は位置 1 でのみすべてのサブシーケンスを拡張できますが、それより長い長さまで拡張することはできません。 したがって、DP は次の期間にのみ蓄積されます。`dp[1]`、そして答えは正確になります$n$これは、すべての単一要素のサブシーケンスは有効ですが、それ以上のチェーンは不可能であるという事実と一致します。 

もう 1 つのエッジ ケースは、値が厳密に増加しているものの、位置インデックスで割り切れることはほとんどない場合です。 DP は、分割可能性チェックが早期に失敗し、不正なサブシーケンスが形成されないことを保証するため、無効な拡張を自然に防ぎます。
