 ## 解決策
 ## 問題の理解

 1 から n までのすべての整数値を含むコインの種類のコレクションが与えられ、これらの値のコインを任意の数だけ使用できます。 タスクは、できるだけ少ないコインを使用して目標合計 S を表すことです。ただし、同じコインの値の繰り返しは制限なく許可されます。 

これは本質的にリソース最小化の問題です。S を範囲 [1, n] の整数のマルチセットに分解し、そのマルチセットのサイズを最小化したいと考えています。 各コインの価値は合計に寄与しており、それを超えることなく正確に S に到達したいと考えています。 

ここでは制約が非常に重要です。 n の値は 100000 まで大きくすることができ、S は 1e9 まで大きくすることができます。 これは、S に依存する状態空間が大きすぎるため、S を介して組み合わせや動的計画法をシミュレートしようとするアプローチを即座に除外します。 O(S) ソリューションですら不可能です。 私たちは、列挙ではなく構造に依存して、テスト ケースごとに定数時間または対数時間で答えを計算するソリューションを余儀なくされています。 

素朴だがよくある間違いは、最大のコインを貪欲に使用すると、S がゼロになるまで min(n, S) を繰り返し取得することで常に機能すると仮定することです。 これは、大きなコインを取った後の残りが少ない場合に微妙に失敗しますが、コインの総数を増やさないと効率的に表現できません。 もう 1 つの誤った直感は、これをナップザック問題として扱い、構成を直接最適化しようとすることです。 これも S のスケールにより失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。値が [1, n] にあり、合計が S であるコインの可能なマルチセットをすべて試して、最小カーディナリティを計算します。 これはすべての有効な分解を調査するため、原則として正しいです。 ただし、このようなマルチセットの数は S とともに非常に急速に増加します。制限されたコイン値に制限したとしても、一般的な設定では、整数の分割数は S の平方根で指数関数的になるため、このアプローチは、指定された制約に達するずっと前に実行不可能になります。 

重要な観察は、コイン セットの構造により、問題が整数分割の制約されたバージョンのように動作し、大きな値が常に好ましいということです。 k 個のコインを使用する場合、k 個のコインで達成できる最良の合計は、n の k 個のコピーを取得し、k・n を与えることによって得られます。 これは、k 個のコインを使用するソリューションは、k・n までの合計しかカバーできないことを意味します。 逆に、S に到達したい場合は、達成可能な最大合計が S に達するのに十分なコインが少なくとも必要です。 

これは、ceil(S / n) の下限を即座に示唆します。 さらに深い問題は、この限界が常に達成可能かどうかです。 それは、より小さいコイン値を使用して常に剰余を表現できるためです。できるだけ多くの n コインを取得すると、残りは厳密に n より小さくなり、その剰余は常に 1 つのコイン (または、組み合わせ調整で最大 1 つの追加コインを使用しますが、構造により実現可能性が保証されます) を使用して表現できます。 これにより、下限が厳しくなります。 

したがって、最適な戦略は単純な除算の議論に帰着します。つまり、できるだけ多くの n 値のコインを使用し、余りがある場合は 1 枚の追加コインでカバーできます。

 ## アルゴリズムのチュートリアル

 この解決策は、目標合計 S をサイズ n のコインの最大貢献額と比較することに依存します。

1. S に収まる完全な n サイズのコインが何枚あるかを計算します。これは、整数除算を使用して S を n で割ったものです。 これは、S を超えずに使用できるラージ コインの最大数を表します。 
2. これらの n サイズのコインを取り出した後の剰余を計算します。 これは S モジュロ n です。 残りは、n 枚のコインではカバーできない残りの量を表します。 
3. 余りがゼロの場合、S は n で完全に割り切れるため、答えは完全に揃ったコインの数になります。 
4. 残りがゼロでない場合、残りの部分をカバーするために追加のコインが 1 枚必要です。 これは、1 から n までの任意の値が利用可能であるため、厳密に n より小さい余りは常に 1 枚のコインで形成できるためです。 

この推論は、コインの価値 1 が常に存在するという事実に依存しているため、複雑さをさらに増すことなく、残りを常に表現できます。 

### なぜ効果があるのか

 重要な不変条件は、値 n のフロア (S / n) コインを取得した後、残りの値は厳密に n より小さいため、利用可能なコイン セットを使用して常に表現できるということです。 カウントを最小限に抑えるためには常に大きなコインを好むため、最適なソリューションでは可能な限り多くの n コインを使用する必要があります。 n コインをより小さなコインに置き換えても、必要なコインの数は決して減りません。 これにより、n サイズのチャンクと残りの部分への貪欲な分解が最適であり、改善できないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, s = map(int, input().split())
    ans = s // n
    if s % n != 0:
        ans += 1
    print(ans)

if __name__ == "__main__":
    solve()
```コードは、除算ベースの推論を直接実装します。 整数の除算は、S に収まる完全な n コインの数を計算します。条件付き増分は、追加のコインを 1 つ必要とする残りの剰余を処理します。 

微妙な点は、実際のコイン セットを構築する必要がないことです。 この問題はコインの最小枚数のみを求めており、構成は求めていないため、算術で十分です。

 ## 特殊なケース

 エッジ ケースの 1 つは、S が n より小さい場合です。 この状況では、S // n はゼロになり、S % n は S に等しくなります。n までの値は 1 枚のコインで表すことができるため、アルゴリズムは正しく 1 を返します。 たとえば、n = 10 および S = 7 の場合、完全なコイン 0 枚と価値 7 のコイン 1 枚を受け取ります。 

もう 1 つのエッジ ケースは、S が n で正確に割り切れる場合です。 たとえば、n = 4 および S = 12 の場合、S // n = 3 および剰余 0 が与えられるため、追加のコインは追加されません。 これは、最大価値のコインのみを使用するという最適な戦略を反映しています。 

最後のエッジ ケースは、n = 1 の場合です。ここではすべてのコインが 1 であるため、S を形成する唯一の方法は S コインを使用することです。 この式では S // 1 = S と剰余 0 が得られ、正解と正確に一致します。
