 ## 解決策
 ## 問題の理解

 私たちには巨大なグリッドが与えられていますが、移動とはセルごとにステップを踏むことではありません。 代わりに、ルークは左下隅から開始し、直線の経路を妨げるものがない限り、行または列全体に沿ってテレポートできます。 

障害には 2 種類あります。 1 つの種類は、特定の垂直境界で 2 つの隣接する列間の移動をブロックし、すべての行のその列境界を越える水平移動を効果的に遮断します。 もう 1 つの種類は、特定の行上の特定の水平線セグメントに沿った動きをブロックし、そのセグメントを垂直に通過するのを防ぎます。 

目標は、左下隅の開始セルから上の行の任意のセルまでのパスが少なくとも 1 つ存在するように、除去する必要がある障害物の最小数を決定することです。 

これを再解釈する有効な方法は、巨大なグリッドのことを忘れて、障壁で区切られた領域間の接続性の観点から考えることです。 垂直呪文は特定の x 座標に配置された垂直壁のように機能し、水平呪文は特定の y レベルで部分的な水平壁のように機能します。 ルークの動きにより、グリッドがグラフに変わり、呪文によって境界がブロックされない限り、各自由な長方形領域が隣接する領域に接続されます。 

制約は大きく、最大垂直呪文は 100,000、水平呪文は 100,000 です。 これにより、グリッドをシミュレートしたり、セルの明示的なグラフを構築したりするソリューションは即座に除外されます。 座標は 10^9 に達するため、すべての領域を明示的に表すことさえ不可能です。 どのような解決策でも、おそらくソートとスキャンを使用して、構造を呪文の数に線形なものに圧縮する必要があります。 

微妙なエッジ ケースは、水平セグメントが互いに重なり合わないが、行をまたがって任意に配置できるという事実から生じます。 これにより、ある種の垂直方向の順序構造が保証されます。これは、投影後に問題を 1 次元のものに変換するために重要です。 

すべての水平ブロックまたはすべての垂直ブロックを個別に削除すれば十分であると考えるのは単純な間違いです。 たとえば、すべての垂直ブロックが削除されたが、単一の水平セグメントがある行の幅全体に広がっている場合、ルークは依然としてその下に閉じ込められている可能性があります。 逆に、水平セグメントだけを削除しても、開始列を分離する垂直パーティションが残る可能性があります。 

誤解を招きやすいもう 1 つのケースは、水平セグメントがまばらであるものの、考えられるすべての垂直ルートが少なくとも 1 つと交差するように戦略的に配置されている場合に発生します。 「最大の」セグメントまたは最も頻繁に使用されるタイプを削除する貪欲なアプローチは失敗する可能性があります。これは、ブロック効果は頻度ではなく到達可能性に関するものであるためです。 

## アプローチ

 プロセスを直接シミュレートしようとすると、すべてのセルをノードとして扱い、ブロックされない限り隣接するセルを接続しようとします。 グリッドは 10^9 x 10^9 であるため、これはすぐに実行不可能になります。 座標を圧縮しても、依然として大きな平面グラフが残り、削除下での最短パスまたは接続にはコストがかかります。 

より有用な視点は、問題を障害物間の一連の「ギャップ」を通る経路を見つけるものとして見ることです。 ルークは左下から始まり、考えられるすべての X 範囲で水平セグメントによって完全に遮断されていない垂直コリドーが少なくとも 1 つある場合にのみ上部に到達できます。 

重要な洞察は、視点を反転することです。 パスを考えるのではなく、「使い続けられる列」を考えます。 柱を完全に覆う水平セグメントによってブロックされることなく、柱内を下から上に垂直に移動できる場合、その柱は使用可能です。 ただし、垂直の呪文は列の切り替えを強制する可能性があるため、垂直の壁で区切られた列の間隔を考慮する必要があります。

これは当然、問題を垂直の壁の間のセグメントに圧縮することになります。 各垂直スペルは、X 軸を独立したセグメントに分割します。 各セグメント内で、ルークは水平方向に自由に移動できます。 したがって、唯一の本当の障害は、そのようなすべてのセグメントが、ある y レベルで垂直方向に完全にブロックされているかどうかです。 

ここで問題は、垂直セグメントごとに、下から上まで完全にブロックするために必要な水平セグメントの数を決定することです。 少なくとも 1 つの垂直セグメントがブロックされないように、削除する呪文の最小限のセットを選択したいと考えています。 

これは、水平セグメントが垂直セグメントを「覆い」、垂直スペルが独立した領域を定義する被覆問題に変わります。 この解決策は、通常は 2 ポインターまたはイベントベースのスイープを使用して、x 座標のソートとスイープを行い、カバレッジ間隔を効率的に評価することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォースグリッドモデリング | O(10^18) | O(10^18) | 不可能 |
 | 座標圧縮 + スイープ | O((n + m) log (n + m)) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての垂直呪文を X 座標で並べ替えます。 これにより、グリッドが連続した垂直ストリップに分割され、ストリップ内には垂直バリアが存在しません。 
2. 各ストリップを下から上への独立した通路として扱います。 ルークはストリップ内を水平方向に自由に移動できるため、移動の制約が問題になるのはストリップ間を移動する場合、または垂直方向にブロックされている場合のみです。 
3. 各ストリップについて、どの水平セグメントが交差するかを決定します。 水平セグメントの X 範囲がストリップの X 間隔と重なる場合、水平セグメントはストリップに影響を与えます。 
4. 各ストリップについて、そのストリップに重なるすべての水平セグメントを避ける y = 1 から y = 10^9 までの「垂直パス」が存在するかどうかを計算します。 水平セグメントは同じ行内で重なり合わないため、異なる高さで独立したブロッカーとして機能します。 
5. ストリップのアクセス可能な X 範囲を横切って左から右へ集合的にバリアを形成する一連の水平セグメントが存在する場合、ストリップがブロックされていることを観察します。 ストリップは独立しているため、それぞれを個別に評価します。 
6. 各ストリップについて、垂直方向に少なくとも 1 つのギャップが残るように、削除する必要がある水平セグメントの最小数を計算します。 これは古典的なインターバル刺し込み最小化になります。少なくとも 1 つのカバーされていない垂直チェーンを確保したいと考えます。 
7. 答えは、すべてのストリップを通過可能にするために必要な除去数の最小値です。 同様に、考えられるすべての垂直方向の通路をブロックする水平セグメントの数を計算し、修正するために最も安価なストリップを選択します。 

### なぜ効果があるのか

 垂直の壁は、平面を独立した x コンポーネントに分割します。 各コンポーネント内では、ルークは水平方向に自由に移動できるため、垂直方向の進行のみが重要になります。 水平セグメントは上方への進行を阻止できる唯一の構造であり、ストリップごとに独立してブロックされます。 ストリップは垂直の壁によって分離されると相互作用しないため、グローバル パスは、少なくとも 1 つのストリップが完全な垂直方向の横断を許可する場合にのみ存在します。 したがって、削除を最小限に抑えることは、最も好ましいストリップの削除を最小限に抑えることになり、これにより、全体的な実行可能なパスが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    vertical = []
    for _ in range(n):
        vertical.append(int(input()))
    vertical.sort()

    horizontal = []
    for _ in range(m):
        x1, x2, y = map(int, input().split())
        horizontal.append((x1, x2, y))

    if n == 0:
        # only one strip [1, INF]
        # we just need to ensure at least one vertical path exists
        return print(m)

    # build strips between vertical walls
    # include boundaries 1 and 1e9+1
    xs = [0] + vertical + [10**9 + 1]

    best = m

    # For each strip, evaluate cost
    for i in range(len(xs) - 1):
        L, R = xs[i], xs[i + 1]

        # count horizontal segments that fully block this strip in some way
        blockers = 0
        for x1, x2, y in horizontal:
            if not (x2 < L or x1 > R - 1):
                blockers += 1

        best = min(best, blockers)

    print(best)

def main():
    solve()

if __name__ == "__main__":
    main()
```この実装は、垂直呪文によって引き起こされるストリップ分解に従います。 垂直位置のリストはソートされ、連続する X 範囲を定義するために使用されます。 各範囲は独立して処理され、その範囲と交差する水平セグメントの数がカウントされます。 このような最小数は、ルークが垂直方向に最も制約されていないストリップを表し、完全なパスを開くには、それらの交差するセグメントを削除するだけで十分です。 

微妙な点は、境界を正しく処理することです。垂直スペルは x と x+1 の間の壁を定義するため、各ストリップは連続する垂直カット間の包括的な整数範囲に対応します。 オフバイワン処理`R - 1`これにより、境界自体を到達可能な領域の一部として誤って含めることがなくなります。

 ## 特殊なケース

 重大なエッジケースは、垂直呪文がない場合です。 その状況では、グリッド全体が単一のストリップを形成するため、答えは水平セグメントが集合的に上向きの動きをブロックするかどうかによってのみ決まります。 アルゴリズムは当然、単一の間隔を評価するように折りたたまれます。 

もう 1 つのエッジ ケースは、垂直方向の呪文が密に詰め込まれ、多くの狭いストリップが作成される場合に発生します。 各ストリップは独立しているため、このソリューションでもこれを処理できます。 たとえほとんどのストリップがブロックされていたとしても、単一の実行可能なストリップが答えを決定します。 

最後の微妙なケースは、異なる行で水平セグメントが重なっていることです。 拘束によって交差していなくても、集合的にストリップをブロックすることができます。 このアルゴリズムは、行間の順序を想定せずに、ストリップごとにそれらを正確にカウントします。
