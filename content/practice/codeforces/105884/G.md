 ## 解決策
 ## 問題の理解

 同じセットに対して 2 つの異なる親関係が与えられています。`n`ポジション。 各関係はルート付きツリーを記述します。最初のノードを除くすべてのノードは、その親である以前のノードを指します。 ツリーの場合、次の値を超えない正の整数を割り当てることができる方法が何通りあるかを数えます。`x`すべての子がその親よりも大きくない値を取得するように、すべてのノードに適用されます。 2 つのカウントの制限比が次のように必要になります。`x`際限なく成長します。 元のタスクはこの有理値モジュロを要求します`998244353`。 

一見すると、カウント関数は次のものに依存します。`x`、非常に大きな値を処理する必要があるようです。 重要なのは、これらのカウントが次の多項式であるということです。`x`。 多項式全体は必要なく、最高次数の係数の比だけが必要です。 制約には次のものがあります。`3 * 10^5`すべてのテストにわたる合計ノード数が多いため、テストごとに 2 次の解法では遅すぎます。 入力サイズは線形に近い値が必要です。 親配列もツリーを形成します。これは、一般的なグラフ アルゴリズムの代わりにツリー固有のプロパティを使用できることを意味します。 

よくある間違いは、次のいくつかの値の計数プロセスをシミュレートすることです。`x`そして限界を推測してみてください。 たとえこれが小さな木で機能したとしても、`x`主要な係数を検出するために必要な係数が大きくなりすぎる可能性があり、少数のサンプルで正確な有理数が明らかになるという保証はありません。 

もう 1 つのエッジ ケースは、2 つのツリーの形状は同じだが、親の番号付けが異なる場合です。 たとえば、両方の入力がチェーンの場合:```
n = 4
a = [-1, 1, 2, 3]
b = [-1, 1, 2, 3]
```答えは`1`。 親配列またはノード インデックスのみを比較するソリューションは、ツリー構造のみが重要であるため、失敗します。 

2 番目のエッジ ケースは、チェーンと比較するとスターです。```
n = 3
a = [-1, 1, 1]
b = [-1, 1, 2]
```答えは`2`。 ルートが固定された後、2 つの子が独立して値を選択できるため、スターにはより有効な割り当てが含まれます。 深さだけを調べるソリューションでは、この違いを見逃してしまいます。これは、両方のツリーが 3 レベルと 2 レベルという同じ最大深さパターンを持っているためです。 

## アプローチ

 直接的なアプローチは、値を増加させるための有効な代入の数を計算することです。`x`そして比率を観察します。 固定の場合`x`、ツリー動的計画法の計算を行うことができます。 ノードの値を固定すると、すべての子サブツリーを独立してカウントできます。 サブツリーをツリーの残りの部分に接続する唯一の制限はそのルートの値であるため、これは正しいです。 ただし、多くの値に対してこれを繰り返すと、`x`実用的ではありません。 操作の数は、選択した範囲に応じて増加します。`x`、制約により、大きな数値パラメーターへの依存は許可されません。 

重要な観察は、主要な係数が何を表しているかを認識することから得られます。 有効な割り当ての数は、ツリーの半順序の順序多項式です。 最高次数係数は、ノードを有効な昇順に配置する方法の数を で割ったものです。`n!`。 言い換えれば、これは、ノードのランダムな順序付けが、すべての親がその子の前に現れるというルールに従う確率です。 

ルート付きツリーの場合、この有効な順序数は簡単な式で決まります。 もし`size[v]`をルートとするサブツリーのサイズです`v`、有効な親-子の順序の数は次のとおりです。```
n! / (size[1] * size[2] * ... * size[n])
```階乗は両方のツリーで同じであるため、比率では消えます。 各ツリーのサブツリー サイズの積のみが必要です。 

ブルートフォースは計数多項式を直接理解しようとするため機能しますが、多項式が巨大になる可能性があるため失敗します。 主要な係数に関する観察により、問題全体をサブツリー サイズの計算と 1 つのモジュラー除算に減らすことができます。

 | --- | --- | --- | --- |
 | ブルートフォース | 選択した x に応じて、O(n^2) | を超える可能性があります。 O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初のツリーと 2 番目のツリーのサブツリー サイズを構築します。 すべての親インデックスはその子インデックスよりも小さいため、入力はルートを持つルート付きツリーをすでに記述しています。`1`、しかしからの逆走査`n`まで`1`子供は常に親の後に現れるので、これで十分です。 
2. すべてのノードのサブツリー サイズを次のように開始します。`1`。 ノードを処理するとき`i`端からルートに向かって、そのサイズを親に追加します。 これが機能するのは、親に到達した時点で、すべての子がすでにそのサブツリー全体を提供しているためです。 
3. 最初のツリーモジュロのすべてのサブツリーサイズの積を計算します。`998244353`。 この値は、主要な係数式の分母部分です。 
4. 2 番目のツリーに対して同じ計算を繰り返します。 
5. 最終的な答えは次のとおりです。```
(product of subtree sizes of second tree)
/
(product of subtree sizes of first tree)
```剰余を取得`998244353`。 

この比率が正しい理由は、2 つの主要な係数が両方とも同じ値で除算されるためです。`n!`。 この問題では分母が反転可能であることが保証されているため、モジュラー除算が可能です。 

なぜ効果があるのか:

 からの値を持つ代入の数`1`に`x`学位です`n`多項式。 最大の係数は、ノードの有効な相対次数の数によって決まります。 有効な相対順序は、まさに、すべての親がそのサブツリー内のすべてのノードの前に現れる順列です。 木のフックの長さの公式では、このカウントは次のように求められます。`n!`サブツリーのサイズの積で割った値。 2 つのツリーのノード数は同じであるため、階乗項はキャンセルされ、サブツリー サイズの積の比率のみが残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def calc(n, parent):
    prod = [1] * (n + 1)

    for i in range(n, 1, -1):
        prod[parent[i]] += prod[i]

    ans = 1
    for i in range(1, n + 1):
        ans = ans * prod[i] % MOD

    return ans

def solve():
    data = list(map(int, sys.stdin.buffer.read().split()))
    ptr = 0
    t = data[ptr]
    ptr += 1
    out = []

    for _ in range(t):
        n = data[ptr]
        ptr += 1

        a = [0] + data[ptr:ptr + n]
        ptr += n

        b = [0] + data[ptr:ptr + n]
        ptr += n

        x = calc(n, a)
        y = calc(n, b)

        out.append(str(y * pow(x, MOD - 2, MOD) % MOD))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`calc`機能はソリューションの中核です。 サブツリーのサイズを配列に直接格納します。 入力された親インデックスは常に子インデックスより小さいため、次から反復されます。`n`まで`2`ノードの子がすでに処理されていることを保証します。 

すべてのサイズが判明した後に製品が蓄積されます。 乗算はモジュロで行われます`998244353`なぜなら、最終的な答えにはモジュラー演算のみが必要だからです。 

最後の除算は、フェルマーの小定理を使用して実装されます。 分数を直接計算する代わりに、分母の逆剰余を乗算します。 この問題は、この逆が存在することを保証します。 

よくある実装上の間違いは、ツリーを順方向に処理することです。 これにより、不完全なサブツリー サイズが親に追加され、間違った製品が生成されます。 もう 1 つの間違いは、内部ノードのみの積を使用していることですが、すべてのノードがサブツリー サイズの葉を含め、フック長の式の 1 つの要素に寄与します。`1`。

 最初のサンプルの場合:```
n = 3

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys
import io

MOD = 998244353

def solve_input(inp):
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = list(map(int, sys.stdin.read().split()))
    sys.stdin = old

    ptr = 0
    t = data[ptr]
    ptr += 1
    ans = []

    def calc(n, p):
        s = [1] * (n + 1)
        for i in range(n, 1, -1):
            s[p[i]] += s[i]
        res = 1
        for v in s[1:]:

        n = data[ptr]
        ptr += 1
        a = [0] + data[ptr:ptr+n]
        ptr += n
        b = [0] + data[ptr:ptr+n]
        ptr += n
        ans.append(str(calc(n, b) * pow(calc(n, a), MOD - 2, MOD) % MOD))

    return "\n".join(ans)

 ## 特殊なケース

 同一のツリーの場合:```
1
2
-1 1
-1 1
```どちらのサブツリー製品も同じです。 アルゴリズムは両方のツリーに対して同じ分母を計算するため、比率は次のようになります。`1`。 これにより、ツリー構造ではなく入力順序を誤って使用するソリューションが捕捉されます。 

スター対チェーンの場合:```
1
3
-1 1 1
-1 1 2
```最初のツリーにはサブツリー サイズがあります`3,1,1`、製品を与える`3`。 2番目にはサイズがあります`3,2,1`、製品を与える`6`。 答えは`6 / 3 = 2`。 分岐はサブツリーのサイズに直接影響するため、アルゴリズムはこれを処理します。 

分岐の違いがさらに大きい場合:```
1
6
-1 1 1 2 2 3
-1 1 1 1 1 1
```逆走査では、最初にすべてのリーフのサイズを計算します。`1`、次にそれらのサイズを上に押し上げます。 最終的な積は有効な親前子の順序の正確な数を表すため、モジュラー比は計数多項式を構築することなく計算されます。
