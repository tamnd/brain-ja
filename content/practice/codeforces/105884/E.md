 ## 解決策
 ## 問題の理解

 重み付けされたエッジと固定数を持つ有向グラフが与えられます。$k$。 単一の道を選択するのではなく、正確に選択する必要があります$k$頂点からの単純なパス$1$頂点へ$n$。 これらのパスは、同一であることも含めて、重なり合うことが許可されます。 

各エッジは、選択したパスがそれを使用する数に応じて高価になります。 エッジの場合$e$使用されています$X_e$選択したすべてのパスにわたって回を繰り返すと、総コストへの寄与は線形ではなくなります。$X_e \cdot f(X_e)$、 どこ$f$は与えられた多項式です。 

目標は、$k$グラフ全体にわたるこれらのエッジ コストの合計が最小になるようにパスを設定します。 

これについて考えるのに役立つ方法は、パスを直接最適化するのではなく、その代わりにエッジの使用数を制御し、それらの数は正確に取得する必要があるという制約を持つということです。$k$有効$1 \to n$パス。 各パスはソースからシンクへの単なる単位フローであるため、すべての有効なソリューションは送信に対応します。$k$ただし、各エッジの輻輳コストは、そこを通過するフローの量の非線形関数です。 

制約は十分小さいので、$n \le 100$、$m \le 200$、 そして$k \le 50$。 これにより、パスまたはパスごとの状態を明示的に列挙しようとするアプローチは即座に除外されます。 すべての単純なパスを保存するだけでも、指数関数的に爆発的に増加します。 しかし、$k$最大でも 50 であるということは、すでにプッシュしたフローのユニット数、または各エッジが最大で何回使用されたかを追跡する状態を維持できるという強力なヒントです。$k$、それは有界のままであるためです。 

微妙なエッジ ケースは、パスのオーバーラップとエッジ コストの間の相互作用から生じます。 素朴な解釈では、パスを均等に分散すると常に効果があると想定するかもしれませんが、$X \cdot f(X)$は一般に正の係数では凸状であるため、流れの集中は多項式の形状に応じて役立つ場合もあれば悪影響を与える場合もあります。 たとえば、すべてのパスがボトルネック エッジを共有する場合、そのエッジのコストは次のようになります。$k \cdot f(k)$、それが答えを支配する可能性があります。 各パスを独立して扱う不注意な戦略は、次のようなグラフでは失敗します。```
1 -> 2 -> n
1 -> 3 -> n
```もし$k = 10$多項式係数に応じて、ルートごとに 5 つのパスを割り当てる方が、10 個の同一のパスを割り当てるよりも悪くなったり良くなったりする可能性があるため、グローバルに推論する必要があります。 

もう 1 つの失敗例は、エッジ コストが走査ごとに加算されると想定している場合です。 間違って交換した場合$X_e \cdot f(X_e)$と$k \cdot f(1)$、結果はパスの相互作用から独立したものになりますが、エッジが再利用されるとすぐに間違ってしまいます。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてを列挙しようとします。$k$-からのパスのタプル$1$に$n$、各タプルのエッジ使用数を計算し、コストを評価します。 単純なパスに限定したとしても、グラフ内のパスの数は指数関数的に増加する可能性があります。$n$、そして選択$k$それらがこの爆発をさらに増幅させます。 これにより、状態空間は次のようになります$O(P^k)$、 どこ$P$は単純なパスの数ですが、これは$k = 2$。 

重要な観察は、選択されたパスに関して重要な唯一のことは、そのアイデンティティではなく、エッジ上にフローをどのように分配するかであるということです。 すべてのパスは次から始まるため、$1$そしてで終わります$n$、それらは価値の流れを形成します$k$。 これにより、エッジ コストが個々のパスではなく、そのエッジ上の整数フロー量にのみ依存することを除いて、問題は最小コスト フロー問題に変わります。 

なぜなら$k \le 50$、プロセスを離散化できます。すべてのフローを一度に送信する代わりに、段階的に構築します。 最適な送信方法を維持します$i$流量の単位と拡張範囲$i+1$。 移行では、エッジの使用量が 1 から増加したときにエッジ コストがどのように変化するかを考慮する必要があります。$X$に$X+1$。 これは、エッジの重みが現在のフローに基づいて動的に更新される最短パス スタイルの拡張を示唆しています。 

この構造は、最も安価な拡張パスを繰り返し見つけることに似ていますが、一工夫があります。エッジを使用するコストは、以前の拡張で既にそのエッジを使用した回数に依存します。 これにより、現在のノードと各エッジがこれまでに使用された回数の両方を含む状態を維持したり、フロー数に関する階層化グラフを使用してよりコンパクトに状態を維持したりすることができます。 

追加の各パスが貪欲に選択されるプロセスを効果的にシミュレートしますが、エッジの重みは限界費用に従って更新されます。$$\Delta_e(x) = (x+1)f(x+1) - x f(x)$$この限界コストは、エッジをもう一度使用することによる真の貢献度を表します。 

このように問題を再定式化すると、次のサイズの拡張状態空間で最短経路の計算を実行することになります。$O(k \cdot m)$ここで、各層は特定の数のパスを使用したことに対応します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべて列挙する$k$-パスのタプル | 指数関数 | 指数関数 | 遅すぎる |
 | 限界費用階層型グラフによるフロー |$O(k m \log n)$または$O(k m)$|$O(k m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 多項式関数を事前計算する$f(x)$みんなのために$x \le k$。 以来$k \le 50$、評価中$f$各整数を直接計算するのは安価です。 これにより、発生したあらゆる使用回数について正確なエッジ コストを計算できます。 
2. エッジの使用量を増やす限界コストを定義します。$x$に$x+1$。 この値は、次のパスを構築するときに重要になります。$x$使用法はすでに修正されており、増分変更のみが新しい決定に影響します。 
3. 階層化グラフを構築します。$k$層。 層$i$送信後の状態を表します$i$パス。 このグラフのノードはペアです$(v, i)$、頂点にいることを意味します$v$すでにコミットした後$i$パス。 
4. 元のエッジごとに$u \to v$では、新しいパスを通過させるかどうかに応じて、同じレイヤー内または次のレイヤーへの遷移を許可します。 遷移の重みには、このエッジが部分解でこれまでに使用された回数に対応する現在の限界コストが使用されます。 
5. 以下から開始して最短経路アルゴリズム (通常はダイクストラ) を実行します。$(1, 0)$。 到達するたびに$(n, i)$、私たちは最も安価に構築する方法を見つけました$i$パス、そして私たちは続くまで続けます$i = k$。 
6. 各増強ステップのコストを累積します。 最終的な答えは、到達するまでの総コストです。$(n, k)$。 

### なぜ効果があるのか

 正確さは、コスト関数がエッジにわたって分解され、使用回数のみに依存するという事実に基づいています。 どのようなソリューションも、一連の段階的な決定として見ることができ、新しいパスのそれぞれは限界費用にのみ影響します。 限界費用は正確に増加分を捉えているため、$X_e \cdot f(X_e)$、以前のフローを固定したまま各拡張ステップを最適化することで、全体的な最適性が維持されます。 これにより、グローバルな組み合わせ選択が変わります。$k$必要なすべての履歴をエンコードする状態空間上の、局所的に最適な拡張のシーケンスへのパス。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n, m, k, d = map(int, input().split())
    c = list(map(int, input().split()))

    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)

    def poly(x):
        res = 0
        p = 1
        for i in range(d + 1):
            res += c[i] * p
            p *= x
        return res

    f = [poly(i) for i in range(k + 2)]

    def marginal(x):
        return (x + 1) * f[x + 1] - x * f[x]

    dist = [[10**18] * (k + 1) for _ in range(n + 1)]
    dist[1][0] = 0
    pq = [(0, 1, 0)]

    while pq:
        cost, v, used = heapq.heappop(pq)
        if cost != dist[v][used]:
            continue
        if v == n and used == k:
            print(cost)
            return
        if used == k:
            continue
        for to in g[v]:
            w = marginal(used)
            nc = cost + w
            if nc < dist[to][used + 1]:
                dist[to][used + 1] = nc
                heapq.heappush(pq, (nc, to, used + 1))

    print(dist[n][k])

if __name__ == "__main__":
    solve()
```コードは最初に多項式を評価して、すべての整数の使用コストを直接利用できるようにし、最短パス内での再計算を回避します。 の`marginal`関数は、エッジをもう一度使用したときに発生する追加コストをエンコードします。これは、増分構築の正しい量です。 

DP 状態`dist[v][used]`頂点に到達するための最小コストを表します`v`コミットした後`used`パス。 優先キューにより、常に最も安価な部分構築が最初に拡張されることが保証されます。これは、限界コストは使用状況に依存しますが、固定レイヤー内では一貫性を保つため、不可欠です。 

ここでよくある間違いは、隣接リスト自体内のエッジ コストを更新することです。 異なるパスが同じエッジを異なる回数使用する可能性があり、コストは 1 回の走査の特性ではなく、グローバルな使用履歴の特性であるため、これは正確性を損ないます。 

## 実用的な例

 ### 例 1

 小さなグラフを考えてみましょう。```
1 -> 2 -> 3
1 -> 3
k = 2
```二次多項式を仮定します$f(x) = x^2$。 

初期状態は`(1, 0)`コスト0で。 

| ステップ | 状態 | エッジが取られました | 中古 | コスト |
 | --- | --- | --- | --- | --- |
 | 1 | (1,0) | 1->3 | 1 | マージナル(0)=1 |
 | 2 | (3,1) | 3->3 (なし) | 1 | 1 |
 | 3 | (1,0) | 1->2 | 1 | 1 |
 | 4 | (2,1) | 2->3 | 2 | marginal(1)=3、合計 4 |

 限界費用が急速に増大する場合、アルゴリズムはフローの分散を優先します。このトレースは、エッジの 2 回目の使用がより高価になることを示しています。 

これは、2 番目のパスが最初のパスから独立していないことを示しています。 

### 例 2```
1 -> 2 -> 4
1 -> 3 -> 4
k = 2
```対称構造により、両方のルートは同等になります。 

| ステップ | 状態 | 選択 | 中古 | コスト |
 | --- | --- | --- | --- | --- |
 | 1 | (1,0) | 1->2 パス | 1 | |
 | 2 | (4,1) | 仕上げ | 1 | |
 | 3 | (1,0) | 1->3 パス | 1 | |
 | 4 | (4,1) | 仕上げ | 2 | 2a |

 どちらのパスも一度使用されるため、エッジ エクスペリエンスによって限界コストが増加することはありません。 

これにより、オーバーラップが不要な場合、アルゴリズムが独立した最短パスを選択するようになることが確認されます。

 ## 特殊なケース

 退化ケースは、すべての場合に発生します。$k$パスは単一のボトルネック エッジを共有する必要があります。 このようなグラフでは次のようになります。```
1 -> a -> n
1 -> b -> n
```もしそうなら`a -> n`存在する場合、すべての有効な解決策がすべてを強制します$k$そのエッジを通るパス。 アルゴリズムは以下を使用してコストを正しく割り当てます。$k \cdot f(k)$なぜなら、限界費用の定式化では使用量が段階的に増加し、正しい非線形ペナルティが蓄積されるからです。 

もう 1 つのエッジ ケースは、複数の互いに素なパスが存在する場合です。 未使用のエッジの限界コストが最も低いため、このアルゴリズムはフローを自然に分散します。そのため、最初のいくつかの拡張では個別のエッジが優先され、明示的なバランシング ロジックを使用せずに最適な分割動作が一致します。
