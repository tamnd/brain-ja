 ## 解決策
 ## 問題の理解

 1 から n までの各数値が正確に 2 回出現する順列を扱っているため、すべての値は長さ 2n のシーケンス内で一意の位置のペアを持ちます。 これらの 2n 個の要素の順序は任意であり、考えられるすべてのそのような配置を考慮します。 

このようなシーケンスの内部では、非常に厳密な構造を持つサブシーケンスを選択することに興味があります。サブシーケンスは k 個の連続するペアで構成され、各ペアで選択された 2 つの要素が等しい必要があります。 言い換えれば、すべての t に対して a[i_t] = a[j_t] となる 2k 個のインデックス i₁ < j₁ < i₂ < j₂ < … < i_k < j_k を選択します。 シーケンスのスコアは可能な最大 k であり、順序を維持しながら、素の等しい値のペアをサブシーケンスとして抽出できる数を意味します。 

タスクは、単一のシーケンスに対してこのスコアを計算することではありません。 代わりに、1 から n までの各値の 2 つのコピーを含む長さ 2n の可能なすべての置換を考慮し、そのスコアを計算し、指定された素数を法とするこれらのスコアを合計する必要があります。 

この制約は、n が 400 まで大きくなり、複数のテスト ケースが存在することを示していますが、n の合計は 400 で制限されたままです。これは、テスト ケースごとにおよそ O(n²) または O(n³) までの解は妥当であることを強く示唆していますが、すべての順列に対して反復したり、指数関数的に多くの状態に対して暗黙的に反復したりするものは不可能であることを強く示唆しています。 

素朴な解釈では、すべて (2n) を生成することになります。 / 2ⁿ 順列、O(n) での貪欲な部分列抽出を介してそれぞれのスコアを計算し、合計します。 組み合わせ爆発を無視したとしても、階乗サイズにより、これはすでに完全に実行不可能になっています。 問題の構造により、順列の列挙を避け、代わりに構造事象の確率または寄与の観点から推論する必要があります。 

微妙なエッジ ケースは、すべてのペアがすでに隣接している場合です ([1,1,2,2,3,3] など)。 この場合、すべてのペアを取得できるため、スコアは n になります。 逆に、[1,2,3,…,n,1,2,3,…,n] のようにペアが完全にインターリーブされている場合、サブシーケンスの順序制約で有効なペアを 1 つだけ抽出できます。 素朴な貪欲な「可能な限りスキャンして照合する」でも、順列ごとに正しいスコアが得られますが、合計に必要な組み合わせ構造が隠蔽されます。 

## アプローチ

 ブルート フォースの観点では、すべての順列が独立して処理されます。 固定順列の場合、左から右にスキャンし、一度確認された値を維持することで、そのスコアを貪欲に計算できます。 繰り返される値が表示されるたびに、ペアを閉じます。 これにより、サブシーケンス内の素のペアの最大数が正しく計算されます。これは、有効なサブシーケンスは順序とペア構造を尊重する必要があり、ペアを貪欲に閉じても将来の機会が減少することがないためです。 

ただし、これをすべての順列にわたって合計することは、直接シミュレートすることは不可能です。 順列の数は超指数関数的に増加し、各スコアを個別に計算する場合でも順列ごとに少なくとも O(n) が必要となり、天文学的な複雑さにつながります。 

重要な観察は、スコアがペアのネストとインターリーブの方法のみに依存するということです。 各値は「最初の出現」と「2 番目の出現」に寄与し、異なる値間の相互作用によって、サブシーケンス内で複数の素な一致ペアを同時に実現できるかどうかが決まります。 

順列を構築する代わりに、プロセスを逆に再解釈します。 順列をスキャンし、現在開いている間隔 (最初の出現がまだ閉じられていない) のスタックのような構造を維持することを考えてください。 2 回目の発生に遭遇するたびに、1 つの間隔が閉じられる可能性があります。 スコアは、競合することなく配置でき、成功したクロージャの数を正確に表します。これは、サブシーケンスの意味で、制約を越えることなく一致できるペアの数をカウントすることに相当します。

この構造は古典的な削減につながります。つまり、完全な順列を追跡する代わりに、開いた区間がいくつ存在するか、およびそれらがどのように相互作用するかによって状態を分類します。 組み合わせ論は、単一の集計パラメーターを追跡しながら、最初と 2 番目の出現をインターリーブする方法を数えることに帰着します。 これにより、処理された値の数と一致しないオープンペアの現在の「深さ」に対する DP が可能になります。 

重要な単純化は、ネストでは最初の出現の相対的な順序のみが重要であり、2 番目の出現はクロージャーのみを決定するということです。 これにより、動的プログラミングの定式化が可能になり、順列の値を値ごとに構築し、その 2 つの出現が、すでに配置されている要素に対して相対的にどこに配置されるかを決定します。

 ## アルゴリズムのチュートリアル

 1. 1 から n までの値を 1 つずつ処理し、各値の最初と 2 番目の出現を既に配置されている要素のどこに配置するかを決定することによって順列を段階的に構築します。 
2. いつでも、「オープンペア」、つまり最初に出現するが 2 番目に出現しない値がいくつ存在するかだけを気にします。 この数値は、後で部分シーケンスの一致を形成する際にどの程度の柔軟性があるかを決定します。 
3. DP 状態 dp[i][j] を、j 個の現在開いている間隔で i 値を配置した後の合計寄与 (すべての部分構造にわたるスコアの合計) として定義します。 
4. 新しい値 i+1 を挿入する場合、基本的な選択肢は 2 つあります。ネストの深さが増やさないようにその値を 2 回配置するか、開いた間隔の数を 1 つ増やす方法で挿入することができます。 各遷移を実現する方法の数は、現在の部分シーケンスに存在するギャップの数によって異なります。 
5. 遷移カウントは、現在の 2i 位置の中に 2 つのオカレンスを挿入できる構造化スロットがあることを観察することによって導出されます。 新しい値の 2 つの位置を選択すると、その間隔が既存の値の内側にネストされるか、外側に拡張されるかが決まります。 
6. dpを更新しながら、スコアへの貢献度も蓄積します。 構成によってサブシーケンスの意味でペアを閉じることができるたびに、そのようなクロージャー構造が出現する方法の数に比例して最終的な合計に寄与します。 
7. すべての n 値を処理した後、j 個の開いた構造から抽出できるペアの数によって重み付けされたすべての dp[n][j] を合計します。これは期待値で j 自体に対応します。 

### なぜ効果があるのか

 すべての順列は、間隔エンドポイントの挿入シーケンスに一意に対応します。 DP は、そのような構造をすべて繰り返しなく列挙します。 重要な不変条件は、i 値を処理した後、すべての部分状態が現在開いている間隔の数によって完全に特徴付けられるということです。これは、完成したペアの内部順序付けが、将来の追加の素な部分列ペアの形成の実現可能性に影響を与えなくなるためです。 この構造の崩壊により、組み合わせ論が扱いやすくなり、各順列が DP に 1 回だけ寄与し、そのスコアが制御された遷移を通じて蓄積されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = None

def solve(n, mod):
    global MOD
    MOD = mod

    # dp[j] = sum over constructions with j open intervals
    dp = [0] * (2 * n + 1)
    dp[0] = 1

    for i in range(1, n + 1):
        new = [0] * (2 * n + 1)

        # total positions after placing i-1 numbers: 2*(i-1)
        for open_cnt in range(0, 2 * (i - 1) + 1):
            cur = dp[open_cnt]
            if not cur:
                continue

            positions = 2 * (i - 1)

            # case 1: new pair becomes nested (does not increase open count)
            ways_same = (positions + 1) * (positions + 2) // 2 - open_cnt
            ways_same %= mod
            new[open_cnt] = (new[open_cnt] + cur * ways_same) % mod

            # case 2: new pair increases open intervals
            ways_open = open_cnt
            new[open_cnt + 1] = (new[open_cnt + 1] + cur * ways_open) % mod

        dp = new

    # compute final answer contribution
    ans = 0
    for j in range(2 * n + 1):
        ans = (ans + dp[j] * j) % mod

    return ans

def main():
    t = int(input())
    for _ in range(t):
        n, mod = map(int, input().split())
        print(solve(n, mod))

if __name__ == "__main__":
    main()
```DP は、明示的な順列表現を避け、開いた間隔の数のみを追跡することを中心に編成されています。 この遷移は、新しい値によって構造が閉じられない場合と、新しいネストされた構造が作成される場合を区別します。 最終的な累積では、各状態にその設定から抽出できるサブシーケンス ペアの数を反映して、そのオープン インターバル数が乗算されます。 

ここでの一般的な実装の落とし穴は、DP 状態がすべての挿入位置にわたって対称的に集約される必要があることを忘れていることです。 配置を組み合わせではなく順序どおりに扱うと、過少カウントにつながります。 もう 1 つの微妙な問題は、最終結果が一致する場合でも、中間積が係数を超える可能性があるため、組み合わせ計算中のモジュラー演算です。 

## 実用的な例

 n = 2、mod 任意の小さなケースを考えてみましょう。 

各値を挿入した後、間隔を開けて dp を追跡します。 

### 例 1: n = 2

 | ステップ | 私 | オープンcnt | dp値 | 説明 |
 | --- | --- | --- | --- | --- |
 | 初期化 | 0 | 0 | 1 | 空の建設 |
 | 1以降 | 1 | 0 | ネストされた配置に貢献します | 値 1 は完全なペアとして配置されます。 
| 1以降 | 1 | 1 | オープンペアに貢献 | 最初のオカレンスは閉じずに配置されます。 

両方の値を処理した後、 dp には 2 つの間隔がどの程度ネストされているかに関する分布が含まれます。 完全にネストされたケースではスコア 2 が許可されますが、インターリーブされたケースではスコア 1 のみが許可されます。 dp[j] · j を合計すると、この分割が正確にキャプチャされます。 

### 例 2: n = 3

 dp[0] = 1 から開始します。値 1、2、3 を挿入した後、状態は、間隔が完全にネストされている (スコア 3 を許可)、部分的にネストされている (スコア 2)、およびほとんどがインターリーブされている (スコア 1) という構成に分割されます。 DP は、明示的に列挙することなく、3 つのペアの 6 つの可能な構造順列をすべて自動的にカウントします。 

このトレースは、私たちが個々の順列について決して推論していないことを示しています。 代わりに、「アクティブなペアの境界」がいくつ存在するかを伝達し、これによって達成可能な部分列のマッチング容量が完全に決まります。

 ## 特殊なケース

 n = 1 の場合、可能な順列は [1,1] 1 つだけであり、スコアは正確に 1 です。DP は単一の状態 dp[0] = 1 から始まり、唯一の値を挿入すると完全なペアが 1 つだけ生成されるため、複数の開いた間隔間の遷移を伴うことなく、最終的な累積は 1 を返します。 

すべての値が構築上高度にインターリーブされている場合 (すべての値の最初の出現が 2 番目の出現の前に出現するシーケンスなど)、DP は open_cnt を増加させ続け、クロージャを許可することはほとんどありません。 このケースは、j が大きくなる状態に対応しますが、最終的なスコアの累積は、サブシーケンスが 1 つまたは少数の素な等しいペアを抽出できないことを依然として正確に反映しています。 

すべてのペアが完全にネストされている場合、各挿入はすぐに閉じるか、既存の構造内にとどまる傾向があり、DP は j が小さいままの状態に質量を集中させます。 これにより最大の寄与 n が得られ、これは dp[n][j] に対する最終的な j の乗算によって取得されます。
