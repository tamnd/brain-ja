 ## 解決策
 ## 問題の理解

 リンクはパラグライダーで湖の上を移動します。 水平方向に移動する唯一の方法はパラグライダーが開いている間であり、最速の水平方向の移動は高速で直線を移動することです。`vh`。 パラグライダーは高速で降下するため、飛行中は身長が低くなります。`vp`ただし、風がより強い風洞の真上にいる場合は別です。`vp`。 そのような洞窟は彼に身長を伸ばすことを可能にします。 

入力により、出発地と目的地の座標、3 つの速度、すべての洞窟の位置と風の強さがわかります。 目標は、高さ 0 を下回らずに目的地に到達するのに必要な最小時間を見つけることです。 

興味深いのは、高さが追加の状態変数である必要があるように見えることです。これにより、問題が継続的かつ困難になります。 制約を見ると、これが意図されたものではないことがわかります。 1 つのケースには最大 4000 個の洞窟があり、すべてのケースの合計洞窟数は 10000 になります。`O(n^2)`このソリューションは、最大の単一ケースに対して約 1,600 万の操作を実行するため、許容可能です。 可能なルートの数は指数関数的に増加するため、すべてのルートを明示的に試行するソリューションは不可能です。 

主なエッジケースは、どの洞窟が重要であるかの誤解から生じます。 風速以下の洞窟`vp`高度を上げることはできないので、充電ポイントとして使用することは決して役に立ちません。 洞窟が目的地に最も近い地点である可能性はありますが、そこに到達するために費やした高度は出発前に回復する必要があるため、そこで停止しても役に立ちません。 もう 1 つのよくある間違いは、開始洞窟は無制限の高さを生成できるが、他の有用な洞窟はすべて、そこに到達した後にのみ重要であることを忘れていることです。 

たとえば、入力が次の場合:```
0 0 10 0
5 4 2
1
0 0 5
5 0 1
```2番目の洞窟には風速があります`1`パラグライダーの落下速度よりも弱いです。`4`。 充電ポイントとしては使用できません。 すべての洞窟を無料で再充電できるグラフ ノードとして扱う解決策は、答えを過小評価することになります。 

A second example is:```
0 0 3 4
5 4 1
0
0 0 5
```答えは`25`。 直線距離は`5`、水平移動には時間がかかります`5 / 1 = 5`秒。 スタート洞窟が猛スピードで上昇`1`、リンクが必要です`20`移動に十分な高さを作り出すには数秒かかります。 

## アプローチ

 最初のアイデアは、各洞窟をグラフ ノードとしてモデル化し、考えられるすべてのルートを試すことです。 移動するたびに、次の洞窟に移動するのに必要な高さを追跡し、登る時間をシミュレートします。 これは正しいです。洞窟を通るルートが移動計画を完全に決定するからです。 ただし、ルートを直接探索することは不可能です。 洞窟が 4,000 個しかないとしても、考えられるシーケンスの数は膨大です。 

重要な点は、高さを状態の一部として保存する必要がないということです。 高さがちょうどゼロの有用な洞窟に到着することを考えてみましょう。 その瞬間から、洞窟は必要なだけの高さを作り出すことができます。 飛行距離に応じて十分な高さを作り出すのに必要な時間`d`現在の洞窟によってのみ決定されます。 

風速のある洞窟`v`より大きい`vp`スピードを上げると高度が上がる`v - vp`。 飛距離`d`かかります`d / vh`秒と消費`vp * d / vh`身長。 したがって、再充電時間は次のようになります。```
(vp * d / vh) / (v - vp)
```実際の飛行時間を加算すると、次のようになります。```
d / vh * v / (v - vp)
```これは、すべての有用な洞窟には、別の有用な洞窟に到達するための固定コストがかかることを意味します。 この問題は、目的地のみが入ることができる最終ノードとして、有用な洞窟上の最短経路の問題になります。 

すべての有効なルートが表現されているため、ブルート フォースは機能しますが、ルートの数が爆発的に増加すると失敗します。 唯一必要な状態は現在有用な洞窟であるという観察により、問題をダイクストラのアルゴリズムに帰着させることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 最適 | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 風速が以下の洞窟のみを保管してください。`vp`。 高度を上げることができる洞窟はこれらだけです。 開始の洞窟は、その風が十分に強いことを保証するステートメントなので、常に含まれます。 
2. 開始洞窟から始めてダイクストラのアルゴリズムを実行します。 洞窟の距離は、高さがゼロの状態でそこに到着するのに必要な最小時間を表します。 
3.洞窟を加工する場合`i`、他の便利な洞窟に移動してみてください。`j`。 それらの水平距離を`d`。 移行コストは次のとおりです。```
d / vh * vi / (vi - vp)
```洞窟だから`i`まず飛行に十分な高さを確保する必要があります。 

1. 現在の洞窟から目的地まで直接飛行することも検討してください。 目的地に風洞がないので同じ計算式が当てはまります。 
2. 目的地に到達するために得られる最小の値が答えになります。 

これが機能する理由: 最短経路計算の不変条件は、保存されたすべての洞窟距離が、高さ 0 でそこに到着することに対応するということです。 ポジティブな風洞は後でいくらでも高さを再構築できるため、これで十分です。 最適な移動は、有用な洞窟間のフライトに分割でき、各フライトにはグラフで使用される正確な移行コストが含まれます。 すべてのエッジの重みが正であるため、ダイクストラは可能な最小の合計時間を見つけます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    t = int(input())
    ans_out = []

    for _ in range(t):
        sx, sy, tx, ty = map(int, input().split())
        vf, vp, vh = map(int, input().split())
        n = int(input())

        caves = []
        for _ in range(n + 1):
            x, y, v = map(int, input().split())
            if v > vp:
                caves.append((x, y, v))

        m = len(caves)
        dist = [float("inf")] * m
        used = [False] * m

        start = 0
        for i, (x, y, v) in enumerate(caves):
            if x == sx and y == sy:
                start = i
                break

        dist[start] = 0.0
        answer = float("inf")

        for _ in range(m):
            u = -1
            best = float("inf")
            for i in range(m):
                if not used[i] and dist[i] < best:
                    best = dist[i]
                    u = i

            if u == -1:
                break

            used[u] = True
            x, y, v = caves[u]

            direct = math.hypot(x - tx, y - ty)
            answer = min(answer, dist[u] + direct / vh * v / (v - vp))

            factor = v / (v - vp) / vh
            for j in range(m):
                if not used[j]:
                    nx, ny, _ = caves[j]
                    d = math.hypot(x - nx, y - ny)
                    nd = dist[u] + d * factor
                    if nd < dist[j]:
                        dist[j] = nd

        ans_out.append("{:.15f}".format(answer))

    print("\n".join(ans_out))

if __name__ == "__main__":
    solve()
```入力ループは、使用できない洞窟をすぐに削除します。 洞窟があるのでこれは安全です`v <= vp`正の高さを提供することは決してないので、ルートを改善することはできません。 

ダイクストラ配列には有用な洞窟のみが保存されます。 必要な精度が高いため、遷移式では浮動小数点値が使用されます。`1e-9`。 Python の整数は任意の精度であるため、座標計算でオーバーフローのリスクはありません。`math.hypot`手動で平方根を計算する必要がなくなります。 

デスティネーションは通常のグラフ ノードとしては挿入されません。 その代わりに、洞窟が優先順位から外されるたびに、その洞窟から目的地までの直行便をテストします。 これにより、不要なエッジの作成が回避されます。

 ## 特殊なケース

 パラグライダーの落下速度とまったく同じ風が吹いている洞窟では、正味の垂直方向の動きはありません。 高さを作成できないため、アルゴリズムはそれを削除します。 たとえば、洞窟に次のようなものがあるとします。`v = vp`、そこで待っていても高度は変わらないため、充電場所として扱うと誤ったショートカットが作成されます。 

目的地近くの弱い洞窟は、最終的な水平距離が短いため、魅力的に見えることがあります。 アルゴリズムは、そのような洞窟が役に立たないことを証明することで、この間違いを回避します。 そこに到達すると、他の場所で生成された高さが消費され、その高さを置き換えることはできません。 考えられる最良の戦略は常に、以前の有用な洞窟からの直行便によって表されます。 

スタート洞窟は必ずプラスの風が吹くので特別です。 アルゴリズムは時刻 0 の洞窟から開始され、遷移式には高さを生成するのに必要な時間がすでに含まれているため、登るための別の初期化ステップは必要ありません。
