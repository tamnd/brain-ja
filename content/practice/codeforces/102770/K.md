 ## 解決策
 ## 問題の理解

 この問題では、同じグラフ タスクを解決する 2 つのアルゴリズムについて説明します。 あらゆる可能な入力サイズに対して`n`、目的のアルゴリズムの実行時間と、より遅い総当たりアルゴリズムの実行時間がわかります。 コンテストの制限時間は、Chenjb が最大入力サイズを削減した後に残る最大のテスト ケースでの、意図したアルゴリズムの実行時間の 3 倍として選択されます。 

選択した最大サイズの場合`n`、テスト データには次のすべてのサイズを含めることができます。`1`に`n`。 意図した解決策は遅くなるため、`n`成長する場合、これらのテストの中で最も遅い意図された実行は、サイズのあるテストです。`n`自体。 その選択のタイムリミットは`3 * a[n]`。 最大でも次のサイズのテスト ケースが存在する場合、ブルート フォース ソリューションはその入力サイズで失敗します。`n`実行時間がこの制限を超えている場合。 

入力では最大 50 個の可能なサイズが得られます。 両方の実行時間配列はすでに降順でない順序でソートされています。 制限が小さいということは、すべてのサイズを直接スキャンしても十分であることを意味します。 高度なデータ構造や対数検索は必要ありません。 重要な観察は、答えはブルート フォース アルゴリズムが遅すぎるテスト ケースの最も早いプレフィックスに関するものであり、同じインデックスのみの比較に関するものではないということです。 

よくある間違った実装では、次のことがチェックされます。`b[n] > 3 * a[n]`そしてそこで止まります。 これにより、より小さなテスト ケースがすでに制限を突破しているケースが見逃されます。 例えば：```
1
4
1 2 7 20
2 5 30 40
```正しい出力は次のとおりです`3`。 のために`n = 3`、制限時間は`21`。 サイズの総当たり時間`3`は`30`、したがって失敗します。 での比較`n = 4`可能な限り小さい値が必要なので、 は必要ありません。 

もう 1 つのエッジ ケースは、ブルート フォース アルゴリズムが常に適合する場合です。 例えば：```
1
3
2 3 3
5 7 8
```出力は`-1`。 最大予定時間は`3`ですので、制限時間は`9`。 すべてのブルートフォース時間は最大でも`9`つまり、入力サイズが許可されていないと失敗します。 

最終的なエッジ ケースは、可能な単一のサイズです。```
1
1
10
31
```出力は`2`? この入力は無効です。理由は、`m = 1`したがって、有効な出力は次のいずれかのみです。`1`または`-1`。 正しい推論は、制限時間は`30`、総当たり時間は`31`したがって、出力は次のようになります。```
1
```2 番目の要素からのみチェックを開始するソリューションでは、この境界ケースを誤って見逃してしまいます。 

## アプローチ

 簡単なアプローチは、Chenjb の意思決定プロセスをシミュレートすることです。 あらゆる可能な最大入力サイズに対して`n`、制限時間を次のように計算します。`3 * a[n]`。 次に、サイズからすべてのテストケースを確認します`1`に`n`ブルート フォース時間がこの制限を超えているかどうかを確認します。 これは通過の定義に正確に従います。 

ブルート フォース手法は、ブルート フォース ソリューションが通過するために必要なすべての条件を直接チェックするため、正しいです。 ただし、多くの比較を繰り返します。 と`m`サイズ、すべてのプレフィックスを個別にチェックすると、最大で`1 + 2 + ... + m`比較、つまり`O(m^2)`。 最大`m`はわずか 50 なので、これでも十分速いです。 

より良い観察は、総当たり時間がソートされていることです。 固定最大サイズの場合`n`、すべてのテスト ケースの中で最大のブルート フォース実行時間です。`1`に`n`単純に`b[n]`。 最大予定実行時間も`a[n]`。 これにより、プレフィックスをスキャンする必要がなくなります。 

条件は次のようになります。```
b[n] > 3 * a[n]
```この条件を満たす最初のインデックスは、まさにブルート フォース ソリューションが通過できない最初の入力サイズです。 配列を 1 回スキャンし、条件が満たされたときにすぐに停止できます。

 | ブルートフォース | O(㎡) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのサイズの意図された解決時間と総当たりの解決時間を以下から読み取ります。`1`に`m`。 

配列はすでに順序付けされているため、位置の値は`i`で終わるプレフィックス内の最も遅いケースを説明します。`i`。 
2.各サイズについて`i`から`1`に`m`、制限時間を次のように計算します。`3 * a[i]`。 

Chenjb が入力サイズを許可する場合、`i`、最大のテストケースにはサイズがあります`i`, そのため、予定された実行時間が制限時間を決定します。 
3. かどうかを確認します。`b[i]`この制限時間を超えています。 

ブルートフォース時間は減少していないため、`b[i]`までのすべてのサイズの中で最悪のブルート フォース ケースです。`i`。 制限を超えると、そのプレフィックスに対するブルート フォース ソリューションは失敗します。 
4. 条件が true である最初のインデックスを出力します。 

スキャンは小さいサイズから大きいサイズに進むため、最初の失敗は最小限の答えとなります。 
5. そのようなインデックスが見つからずにスキャンが終了した場合は、印刷します。`-1`。 

これは、ブルート フォース ソリューションが、許可されているすべての入力サイズを処理できることを意味します。 

なぜ効果があるのか:

 選択した最大サイズに対して`i`、コンテストには、最大で次のサイズのテスト ケースが含まれます。`i`。 これらの中で、意図したソリューションの実行が最も遅いものは次のとおりです。`a[i]`、制限を与えます`3 * a[i]`。 これらの中でブルートフォース ソリューションの実行が最も遅いのは次のとおりです。`b[i]`配列がソートされているためです。 ブルートフォースソリューションは、次の場合に正確に合格します。`b[i] <= 3 * a[i]`。 アルゴリズムは、可能な限りこの正確な条件をチェックします。`i`昇順なので、最初に見つかった失敗が最小の有効な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        m = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        res = -1
        for i in range(m):
            if b[i] > 3 * a[i]:
                res = i + 1
                break

        ans.append(str(res))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```入力は一度に 1 つのテスト ケースごとに処理されます。 配列は Python でゼロベースのインデックスを使用しますが、問題のサイズは次から始まります。`1`、したがって、答えは次のとおりです`i + 1`故障が見つかったとき。 

このループは、各サイズでのブルート フォース時間を、同じサイズでの意図した時間の 3 倍と比較します。 両方の配列がソートされているため、プレフィックス スキャンは必要ありません。そのため、現在の位置はすでにプレフィックス内の最悪のケースを表しています。 

の乗算`3`最大値が非常に小さいため安全です。 初期の`break`最初の失敗したサイズが検出された後の不必要なチェックを回避します。
