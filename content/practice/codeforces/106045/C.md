 ## 解決策
 ## 問題の理解

 配列と固定整数があります$m$、呪いの番号と呼ばれます。 

2 種類の操作をオンラインで処理する必要があります。 更新により、1 つの配列要素が新しい値に置き換えられます。 クエリは部分配列と値を調べます$k$、次に、その部分配列の要素の数が _k-good_ であるかを尋ねます。 

定義は少し間接的です。 数値が次の値で割り切れない場合、その数値は良好であるとみなされます。$m$。 数字$x$追加した後であればOKです$k$何度でも、それは常に良いままです。 言い換えれば、どの値も$$x,\; x+k,\; x+2k,\; x+3k,\dots$$いつかは割り切れるかもしれない$m$。 

入力には最大で次のものが含まれます$10^4$テスト ケースですが、重要な制約は、合計$n$そして合計$q$すべてのテストケース全体で最大でも$10^5$。 あらゆる解決策$O((n+q)\log n)$テストケースごとの速度は簡単に十分に速くなります。 すべてのクエリに対してサブ配列を二次スキャンすると、単一のテストにすでに$10^5$操作。 

主な困難は、k-good 状態を理解することです。 これを単純化すると、問題はダイナミック レンジのカウントの問題になります。 

間違った推論につながりやすい状況をいくつか考えてみましょう。 

もし$m=8$、$k=12$、 そして$x=1$、次にシーケンスモジュロ$8$は$$1,5,1,5,\dots$$決して届かない$0$、 それで$x$いいですね。 

もし$m=8$、$k=12$、 そして$x=4$、次にモジュロ$8$私たちは得ます$$4,0,4,0,\dots$$第 2 項は次のように割り切れます。$8$、 それで$x$良くないよ。 

よくある間違いは、次のことだけをテストしてしまうことです。$x$それ自体は次のように割り切れます$m$。 この定義では、将来の追加もすべてチェックする必要があります。 

別の微妙なケースが現れるのは、$k$の倍数です$m$。 例えば、$m=10$、$k=20$。 追加$k$剰余剰余を変更しない$m$。 次に、数値が k-good であるのは、それが次の値で割り切れない場合です。$10$。 すべての値を処理するソリューション$k$検査せずに一律に$\gcd(k,m)$この動作を見逃すことになります。 

## アプローチ

 ブルートフォース解釈は定義に直接従います。 すべてのクエリについて、部分配列の各要素を検査し、追加が繰り返されていないかどうかを判断します。$k$の倍数を生み出すことができます$m$。 

それを行う 1 つの方法は、モジュロを使用することです$m$。 から始まる$a_i \bmod m$を繰り返し追加します$k \bmod m$シーケンスが繰り返されるまで。 しかないので、$m$残差、これにはかかります$O(m)$要素あたりの時間。 

と$m \le 5000$、長さの範囲に関するクエリ$10^5$おおよそ必要になる可能性があります$$10^5 \cdot 5000$$まったく実行不可能な操作です。 

重要な観察はモジュラー演算から得られます。 

何か存在するかどうか知りたい$t \ge 0$そのような$$a_i + t k \equiv 0 \pmod m.$$この線形合同式は次の場合にのみ解決策を持ちます。$$\gcd(k,m) \mid a_i.$$させて$$g = \gcd(k,m).$$それから：$$a_i \text{ is k-good}
\iff g \nmid a_i.$$複雑な定義全体は、単純な割り算テストにまとめられます。 

クエリは次のようになります。 

要素を数える$[l,r]$**で割り切れない**$g$。 

以来$m$決して変わらない、そして$g$の約数でなければなりません$m$、の約数のみ$m$クエリに出現する可能性があります。 任意の整数の約数の数。$5000$規模は小さく、せいぜい数十人です。 

あらゆる約数について$d$の$m$、現在どの位置に割り切れる数値が含まれているかを保存するフェンウィック ツリーを維持します。$d$。 

それから：$$\text{answer}
=
(r-l+1)
-
\#\{\text{elements divisible by } g\}.$$更新では 1 つの位置が変更されるため、すべての除数ツリーを 1 回更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O((r-l+1)\cdot m)$クエリごと |$O(1)$| 遅すぎる |
 | 最適 |$O(D\log n)$操作ごと |$O(Dn)$| 承認済み |

 ここ$D$は約数の数です$m$。 

## アルゴリズムのチュートリアル

 1. すべての約数を計算します。$m$。 
2. 約数ごとに 1 つのフェンウィック ツリーを作成します$d$。 
3. 配列の位置ごとに$i$、値を挿入$1$除数ツリーに$d$もし$a_i$で割り切れます$d$。 
4. アップデートについて`1 i x`、すべての除数ツリーから古い値の寄与を削除し、新しい値の寄与を追加します。 

約数の数が少ないため、すべての約数をタッチするのは低コストです。 
5. お問い合わせの場合`2 l r k`、計算する$$g=\gcd(k,m).$$6. 除数に対応するフェンウィックツリーを使用する$g$の値の数を数える$[l,r]$で割り切れます$g$。 
7. その数を次のようにします`bad`。 k-good 要素の数は次のとおりです。$$(r-l+1)-bad.$$8. 結果を出力します。 

### なぜ効果があるのか

 重要な特性は、古典的な線形合同の結果です。$$a + tk \equiv 0 \pmod m$$解決策があるのは次の場合に限られます$$\gcd(k,m)\mid a.$$もし$g=\gcd(k,m)$分割する$a$、将来の項は次のように割り切れます。$m$, したがって、この数値は k-good ではありません。 

もし$g$分けない$a$、等差数列全体のどの項も以下で割り切れることはできません。$m$, したがって、数値は k-good です。 

したがって、すべてのクエリは正確に、次の値で割り切れない値をカウントすることになります。$g$、フェンウィック ツリーは更新時にこれらの割り算数を正しく維持します。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, idx, delta):
        n = self.n
        bit = self.bit
        while idx <= n:
            bit[idx] += delta
            idx += idx & -idx

    def sum(self, idx):
        bit = self.bit
        res = 0
        while idx > 0:
            res += bit[idx]
            idx -= idx & -idx
        return res

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        divisors = []
        for d in range(1, m + 1):
            if m % d == 0:
                divisors.append(d)

        idx_of = {d: i for i, d in enumerate(divisors)}

        trees = [Fenwick(n) for _ in divisors]

        for pos, val in enumerate(a, start=1):
            for j, d in enumerate(divisors):
                if val % d == 0:
                    trees[j].add(pos, 1)

        q = int(input())

        for _ in range(q):
            query = list(map(int, input().split()))

            if query[0] == 1:
                _, i, x = query
                old = a[i - 1]

                for j, d in enumerate(divisors):
                    old_div = (old % d == 0)
                    new_div = (x % d == 0)

                    if old_div != new_div:
                        trees[j].add(i, 1 if new_div else -1)

                a[i - 1] = x

            else:
                _, l, r, k = query

                g = gcd(k, m)
                tree = trees[idx_of[g]]

                divisible = tree.range_sum(l, r)
                ans = (r - l + 1) - divisible

                out.append(str(ans))

    sys.stdout.write("\n".join(out))

solve()
```最初の部分では、次のすべての約数を計算します。$m$。 考えられるすべてのクエリでは$g=\gcd(k,m)$、およびそのようなものすべて$g$の約数でなければなりません$m$、これらは私たちが必要とする唯一の可分性クラスです。 

各フェンウィック ツリーには、1 つの約数が格納されます$d$、各位置に現在次の倍数が含まれているかどうか$d$。 範囲の合計により、次の倍数がすぐに得られます。$d$任意の間隔内で。 

更新操作では、すべての約数の新旧の割り算ステータスが比較されます。 ステータスが変化した場合にのみ、フェンウィック ツリーを変更します。 これにより、不必要な更新が回避されます。 

クエリ操作で計算されるのは、$g=\gcd(k,m)$、対応するフェンウィック ツリーを見つけ、次の倍数をカウントします。$g$範囲内で、間隔の長さから減算します。 

すべての算術演算は Python 整数内に快適に収まるため、オーバーフローの心配はありません。

                self.bit[i] += v
                i += i & -i
