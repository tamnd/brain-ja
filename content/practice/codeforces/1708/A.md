 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 唯一許可される操作は、ある位置を選択することです`i > 1`そして置き換えます`a[i]`と`a[i] - a[i-1]`。 

この演算は 1 つの要素にのみ影響し、常にそのすぐ左側の現在の値が減算されます。 操作は任意の回数、任意の順序で実行できます。 目標は、最初の要素を除くすべての要素をゼロにすることです。 

テスト ケースごとに、そのような一連の操作が存在するかどうかを判断する必要があります。 

制約は非常に小さいです。 配列の長さは最大 100 で、テスト ケースの数は最大 100 です。 比較的非効率なアプローチであっても、制限内に問題なく収まります。 本当の課題は、変換がいつ可能になるかを完全に特徴づける数学的特性を認識することです。 

微妙な点は、操作がまったく変わらないことです。`a[1]`。 最初の要素がどのような値で始まっても、それは永久に保持されます。 他のすべての要素は、左から値を繰り返し減算することによって最終的にゼロになる必要があるため、最初の要素は、後続のすべての要素と互換性がなければならない「単位」として機能します。 

簡単な間違いの 1 つは、すべての要素を独立してゼロにできると考えることです。 

考慮する：```
1
2
5 7
```正しい答えは次のとおりです。```
NO
```7 から始めて、5 の減算を繰り返すと 2、次に -3 が得られ、正確に 0 に達することはありません。各要素が少なくとも前の要素であるかどうかだけをチェックする不用意な解決策では、誤って YES と答えてしまいます。 

もう 1 つのよくある間違いは、隣接する可分性に焦点を当てることです。 

考慮する：```
1
3
2 4 6
```答えは次のとおりです。```
YES
```6 は 4 で割り切れませんが、まず 2 を 2 回減算して 4 を 0 に変えることができ、変更されていない最初の要素の値 2 を使用して 6 を減らすことができます。隣接する要素間の関係は重要なプロパティではありません。 

3 番目のエッジ ケースは、すべての要素がすでに等しい場合に発生します。```
1
4
7 7 7 7
```答えは次のとおりです。```
YES
```最初以外の各要素は、7 を 1 回だけ減算することでゼロに減らすことができます。 

## アプローチ

 ブルートフォースの観点は、プロセスをシミュレートすることです。 位置ごとに、値がゼロになるか、左の近傍よりも小さくなるまで、現在の左の近傍を繰り返し減算できます。 ゼロに達すると、その位置は解決されます。 そうでなければ答えは不可能です。 

これが機能するのは、減算を繰り返すことがまさに演算の動作であるためです。 問題は、値が次のように大きくなる可能性があることです。`10^9`。 もし`a[1] = 1`の値を減らします。`10^9`10億回の操作が必要になる可能性があります。 実際の操作シーケンスはシミュレーションするには大きすぎます。 

重要な観察は、最初の要素が決して変更されないということです。 

最初の要素が等しいと仮定します`x = a[1]`。 

作るには`a[2]`ゼロになると引き算を繰り返します`x`。 これは次の場合にのみ可能です`a[2]`で割り切れます`x`。 

次に、後の位置を検討します。 改造しても`a[2]`、`a[3]`、など、位置がゼロになると、ゼロを減算しても何も変わらないため、ゼロのままになります。 最終的には、以前のすべての要素をゼロに減らすことができ、残りの要素は残ります。`a[1] = x`変わらない。 

どのポジションでも`i > 1`、それを減らすのに役立つ唯一のゼロ以外の値は依然として`x`。 による減算の繰り返し`x`まさにそのときゼロに達する`a[i]`で割り切れます`x`。 

したがって、問題全体は、すべての要素が最初の要素で割り切れるかどうかを確認することに帰着します。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、最初の要素を次のように格納します。`x = a[1]`。 
2. 2 番目の位置から最後までのすべての要素を確認します。 
3. 各要素について`a[i]`、計算する`a[i] % x`。 
4. 剰余がゼロでない場合は、次のように出力します。`"NO"`引き算を繰り返すので、`x`その値を正確にゼロに減らすことはできません。 
5. すべての要素が次の要素で割り切れる場合`x`、印刷`"YES"`。 

### なぜ効果があるのか

 最初の要素は、操作中に変更されることはありません。 その値を次のようにします`x`。 

どのポジションでも`i > 1`、影響を与えるすべての操作`a[i]`そこから何らかの値を差し引きます。 正確にゼロで終了するには、減算される合計金額が元の値と等しくなければなりません`a[i]`。 

以前のすべてのポジションが削減された後、左側で利用可能な永続的なゼロ以外の値は次のとおりです。`x`。 削減するたびに、`a[i]`効果的に減算を繰り返すことにより、`x`。 数値は、引き算を繰り返すことでゼロに減らすことができます。`x`それが次の倍数である場合に限り、`x`。 

したがって、すべての位置が満たさなければなりません`a[i] % x == 0`。 この条件がすべての位置に当てはまる場合、各要素を独立してゼロに減らすことができます。 1 か所でも失敗すると、目的の構成は不可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        x = a[0]
        
        ok = True
        for v in a[1:]:
            if v % x != 0:
                ok = False
                break
        
        print("YES" if ok else "NO")

solve()
```この解決策は、最初の要素を保存することから始まります。これは、この要素がプロセス全体を通じて決して変更されない唯一の値であるためです。 

残りの要素に対するループは、証明で導出された割り算条件をチェックします。 割り切れない要素が見つかった瞬間、答えは次のとおりであることがすでにわかっています。`"NO"`, そのため、ループが早期に終了する可能性があります。 

すべての算術演算では Python 整数が使用されます。 Python は任意精度の整数をサポートしているため、指定された境界はすでに標準の 64 ビット整数に対して十分に小さいにもかかわらず、オーバーフローの懸念はありません。 

最初の要素は個別に処理され、その後の要素はすべて同じ条件を満たす必要があるため、インデックス付けは簡単です。

## 特殊なケース

 次のことを考慮してください。```
1
2
5 7
```アルゴリズムセット`x = 5`そして小切手`7 % 5 = 2`。 余りがゼロでないので出力します。`"NO"`。 

一連の操作を試してみると、これが確認できます。 値 7 は、1 回減算すると 2 になり、その後、次の減算で負になります。 ゼロは到達不可能です。 

考慮する：```
1
3
2 4 6
```アルゴリズムは以下をチェックします。```
4 % 2 = 0
6 % 2 = 0
```そして出力`"YES"`。 

これは、すべての要素は直前の要素で割り切れる必要があるという考えに対する有用な反例です。 実際の不変式は最初の要素のみに依存します。 

考慮する：```
1
4
7 7 7 7
```アルゴリズムは 7 で割り切れるすべての要素を見つけて出力します。`"YES"`。 

最初以外の各要素は 1 回の操作でゼロに減らすことができ、等しい配列が常に有効であることが確認されます。
