 ## 解決策
 ## 問題の理解

 平面内の一連の点が与えられます。 各ポイントはレーザー発生器として機能し、発生器の各ペアは直線のレーザー セグメントによって接続されます。 したがって、n 点について、システムは、すべてのエッジが 2 つの指定された座標間のセグメントである完全な幾何学的グラフを形成します。 

私たちは原点からスタートして、第 1 象限の遠くの目的地に到達したいと考えています。 ジェネレータ ポイントまたはジェネレータ ポイントを接続するセグメントに触れない限り、平面内での動きは完全に自由です。 パスを実行可能にする唯一の方法は、ジェネレーター ポイントの一部を削除することです。 ジェネレーターを削除すると、それに付随するすべてのセグメントも削除されます。 

タスクは、残りのセグメントや点と交差しない、原点から目的地までの連続曲線が少なくとも 1 つ存在するように、削除する必要があるジェネレーターの最小数を計算することです。 

この制約は、テスト ケース全体で n が最大 10^6 になる可能性があることを意味しているため、すべての点のペアを検査する解決策は不可能です。 エッジの数が O(n^2) であり、これは中程度の n の場合でも天文学的に大きいため、すべてのセグメントの二次構成もすぐに除外されます。 

幾何学的に重要な問題は、セグメントが平面内に密な障害物を形成することです。 ただし、動きには制限がなく、トポロジカルな分離のみが重要であるため、この構造は、これらの点がどのように平面を領域に分割するのか、および原点の領域を第 1 象限の無限大に接続するにはどのような最小限の削除が必要かを理解することに帰着します。 

単純なアプローチでは、すべてのセグメントの配置を明示的に構築し、出発地と目的地が平面サブディビジョンの同じ面にあるかどうかを計算しようとします。 この配置には二次的な複雑性があるため、これは計算的にも概念的にも失敗します。 

より微妙な故障モードは、出発点と目的地の「間」にある点のみが重要であると仮定することから生まれます。 たとえば、点が原点の周囲に凸状のバリアを形成する構成は、開始点と終了点の間のセグメント上に直接存在しない場合でも、すべての避難ルートをブロックします。 

## アプローチ

 ブルートフォースメンタルモデルは、各セグメントを障害物として扱い、すべてのセグメントの補完における接続性をチェックしようとするものです。 交差点によって引き起こされる完全な平面グラフを構築し、領域接続テストを実行することを想像できます。 この問題は 2 つの点が平面配置の同じ面にあるかどうかを問うものであるため、これは概念的には正しいです。 

ただし、O(n^2) セグメント間のすべての交差を構築することは不可能です。 それらを保存することすら不可能であり、面上で BFS を実行するには、配置の複雑さに比例した時間がかかり、交差点と面では最悪の場合 Θ(n^4) に達します。 

重要な点は、実際には完全な取り決めは必要ないということです。 セグメントはすべて点によって決定され、「密閉された」障害物を作成する唯一の方法は、原点の周囲でトポロジー的な分離を強制する構成を使用することです。 問題は、そのようなすべての囲み構造を削除すると破壊される点の最小セットを特定することに帰着します。 

重要な再定式化は、原点の周りのすべての点の角度順序を考慮することです。 2 点間のすべてのセグメントは、原点からの方向間の角度スイープと交差します。 角度位置が「広がりすぎている」一連の点を保持すると、それらの間の完全なグラフによって、原点を凸包構造で囲むバリアが作成されます。 したがって、障害物は、残りのポイントが原点の周りを完全に囲わない領域に位置するように、削除する必要があるポイントの数によって決まります。

これにより、問題は、原点から見て開いた半平面内に配置できる点の最大のサブセットを選択することになります。 同様に、角度座標が厳密に π より小さい長さの区間にある点の最大数を維持したいと考えています。 他のすべてを削除すると、どのセグメントも原点を完全に囲んで分離することができなくなります。 

したがって、答えは n から原点の周りの半円に収まる点の最大数を引いたものになります。 これは古典的な循環スイープ問題であり、角度をソートし、2 倍の配列に対して 2 ポインター ウィンドウを使用することで解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | セグメントの総当り配置 | O(n^2) 以上 | O(n^2) | 遅すぎる |
 | 角度スイープ + 2 つのポインター | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 原点に対するすべての点の極角を計算します。 これにより、幾何学的位置が、距離よりも方向が重要となる循環順序付け問題に変換されます。 
2. 角度を昇順に並べ替えます。 並べ替えにより、円形ドメインに線形構造が与えられます。これは、スライディング ウィンドウを適用するために必要です。 
3. 各角度に 2π を加えて、ソートされた角度リストを複製します。 これはラップアラウンド間隔を処理するため、円形ウィンドウを線形セグメントとして扱うことができます。 
4. 2 つのポインタ l と r を使用して、角度差が厳密に π 未満となるウィンドウを維持します。 条件が成立している間は貪欲に r を拡張します。 
5. 各 l について、到達可能な最大 r を計算します。 すべての開始位置にわたる最大ウィンドウ サイズを追跡します。 このウィンドウは、半円に含まれる点の最大のサブセットを表します。 
6. 最終的な答えは、n からこの最大ウィンドウ サイズを引いたものになります。 

2 ポインター展開が機能する理由は、角度がソートされると、角度の差に関する条件が単調になるためです。 r を増加しても角度スパンは増加するだけなので、各ポインターは最大で n 回移動します。 

### なぜ効果があるのか

 原点に関して開いた半平面内に完全に収まる点のセットは、原点の周囲に閉じた角度のラップを形成できません。 したがって、これらの点の間に誘導されたすべてのセグメントは、原点を完全に取り囲んでいない領域内にとどまり、無限に続く連続したエスケープ パスが残ります。 逆に、点がどの半円にも含まれていない場合、その完全なグラフは必然的に、単調なエスケープ方向を防ぐカバーを作成します。 したがって、半円の内側に保持されるセットを最大化すると、すべての周囲の構造を破壊するために必要な除去の数が直接最小化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        angles = []
        for _ in range(n):
            x, y = map(int, input().split())
            angles.append(math.atan2(y, x))

        angles.sort()
        m = len(angles)

        ext = angles + [a + 2 * math.pi for a in angles]

        ans = 0
        r = 0
        for l in range(m):
            while r < l + m and ext[r] - ext[l] < math.pi:
                r += 1
            ans = max(ans, r - l)

        print(n - ans)

if __name__ == "__main__":
    solve()
```この解決策は、すべての象限とエッジ ケースを正しく処理する atan2 を使用して、各点をその角度表現に変換することから始まります。 並べ替えると、これらの方向が円上に配置されます。 2π シフトした複製を追加して配列を拡張すると、モジュラー演算を行わずにラップアラウンド間隔を処理できるようになります。 

2 ポインター ループは、厳密に π 未満の有効な角度スパンを維持します。 左側の境界ごとに、右側のポインタを可能な限り進めます。 差 r - l は、その半円ウィンドウ内にいくつの点があるかを表します。 このような最大値は、存続可能な最大のサブセットです。 

これを n から引くと、必要な最小削除数が得られます。

 ### 例 1

 入力:```

```角度を計算します。 

| ポイント | 角度 |
 | --- | --- |
 | (1,0) | 0 |
 | (0,1) | π/2 |
 | (-1,-1) | -3π/4 |

 ソートされた角度はおよそ次のようになります。 

-3π/4、0、π/2

 拡張すると、2π だけシフトされた 2 番目のコピーが得られます。 

幅 < π のウィンドウをスライドさせます。 

| l | r | ウィンドウサイズ |
 | --- | --- | --- |
 | 0 | 2 | 2 |
 | 1 | 3 | 2 |
 | 2 | 4 | 2 |

 最大ウィンドウ サイズは 2 なので、答えは 3 - 2 = 1 となります。 

これにより、完全な角度の広がりを避けるために少なくとも 1 つの点を削除する必要があることが確認されます。

 ## 特殊なケース

 複数の点が半円の π 境界の非常に近くにある場合、微妙なエッジ ケースが発生します。 スライディング ウィンドウ条件では、角度差に関する厳密な不等式を使用し、正反対の点が両方とも含まれないようにします。 2 つの点が正確に π だけ異なる場合、それらは両方とも有効な開いた半円ウィンドウに属することはできず、アルゴリズムはそのペアを正しく除外します。 

もう 1 つのエッジ ケースは、ポイントが原点とほぼ同一線上にある場合です。 その状況では、すべての角度が密集し、2 ポインター ウィンドウがセット全体をカバーし、回答ゼロの除去が得られます。 角度差が π よりかなり下に留まるため、アルゴリズムはこれを自然に処理します。そのため、r はすべての点にわたって拡張されます。 

最後のエッジケースはラップアラウンドで、最適な半円が -π から π の境界を横切ります。 配列が複製されると、この間隔が連続したセグメントとして表現されるようになり、スライディング ウィンドウは特別なケースを使用しなくても正しい最大値を見つけることができます。
