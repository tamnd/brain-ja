 ## 解決策
 ## 問題の理解

 完全なグラフが与えられます。$n$頂点。すべての頂点が他のすべての頂点に接続されます。 各頂点はいくつかのチップから始まります。 このプロセスにより、チップ数が少なくともその次数である頂点を繰り返し選択し、除去しながら他のすべての頂点に 1 つのチップを送信して、それを「発射」することができます。$n-1$そこからのチップ。 

これはクリークであるため、すべての頂点には常に次数があります。$n-1$したがって、少なくとも頂点が保持されている場合は常にアクティブになります。$n-1$チップス。 発砲するたびに正確に減算されます$n-1$その頂点からチップを取得し、他の頂点ごとに 1 チップを追加します。 

このプロセスが永久に続くかどうかを判断する必要があります。 存在する場合は、「Recurrent」と出力します。 それ以外の場合は、少なくとも頂点が存在しない最終的な安定した構成を計算する必要があります。$n-1$チップス。 

制約は次のとおりです$n = 5 \cdot 10^5$したがって、個々の発砲をシミュレートするアプローチは不可能です。 たとえそれぞれの発砲があったとしても$O(1)$、チップは循環し続ける可能性があるため、発射回数は膨大になる可能性があります。 

いくつかのエッジ動作は分離する価値があります。 

すべての頂点が下から始まる場合$n-1$、何も起こらず、答えは最初の配列です。 単純なシミュレーションでは、依然として頂点の処理が試行され、スキャンに時間が無駄になる可能性があります。 

チップが永久に循環できる構成が存在する場合、それは通常、頂点のサブセット間での繰り返しの再配分によって引き起こされる一部の頂点の無制限の増加に起因します。 クリークでは、これはグループが際限なく再発射するのに十分なチップを蓄積し続ける「マス ドリフト」現象として現れます。 

1 つの頂点がしきい値をわずかに下回っており、他の頂点から繰り返しチップを受け取り、カスケード発火を引き起こす場合、微妙な問題が発生します。 単純な貪欲シミュレーションはオーダーに大きく依存しており、あるオーダーでは終了するように見えても、別のオーダーでは終了しない可能性があります。 

## アプローチ

 直接シミュレーションでは、アクティブな頂点のキューが維持されます。 頂点が少なくとも到達するたびに$n-1$チップがあればそれを起動し、他のすべてを更新します。 これは概念的には正しいです。サンドパイル モデルは合流しているため、有効な発射順序は同じ最終状態または非終了につながります。 

ただし、発砲のたびに$O(n)$頂点。 最悪の場合、頂点が発火する可能性があります$O(n)$回、与える$O(n^2)$限界をはるかに超えた仕事。 

重要な構造の簡素化は、クリークの対称性から生まれます。 発射するたびにチップの合計が正確に減少します$n-1$、ただし、他のすべての頂点に均等に再配分されます。 これは、総チップと各頂点が発火した回数などの集計効果のみを追跡することを示唆しています。 

重要な観察は、相対的な違いのみが重要であるということです。 発火するたびに他のすべての頂点に +1 が追加されます。これは、グローバルに +1 を追加して減算することと同じです。$n$代わりに発射頂点から$n-1$。 これにより、システムは、グローバルな増分とローカルな赤字を分離できるシステムに変換されます。 

グローバル オフセットと調整値を使用して状態を再解釈できます。 各頂点値を共有グローバル項と残差に分解します。 共有項は頂点が発火するたびに均一に増加しますが、頂点が再度発火できるかどうかは残差のみによって決まります。 

この変換の下では、再帰は無限のカスケード発火の可能性に対応します。これはまさに、残留「欠陥」を使い果たさずに頂点をトリガーし続けることができる場合に発生します。 これは、正規化後にシステムが安定するかどうかをチェックし、安定する場合はすべての過剰質量を分配した後で最終的な残差を計算することに帰着します。 

すべての頂点が対称的に相互作用するため、最終状態はしきい値に対する剰余のソートと分配のみに依存します。$n-1$、各ステップをシミュレートするのではなく、超過分をまとめて処理できます。

 ## アルゴリズムのチュートリアル

 重要なアイデアは、発火のシミュレーションを避け、代わりに各頂点がしきい値を超えてどれだけ「寄付」できるかを推論することです。 

1. チップの総数を計算します。$S = \sum a_i$。 これにより、システムが繰り返しの発火に耐えられる十分な質量を持っているか、最終的には安定する必要があるかが決まります。 クリーク構造により、すべての再分配で総質量が維持されるため、再分配パターンのみが重要になります。 
2. すべての安定した頂点が次の条件を満たさなければならないことに注意してください。$a_i < n-1$。 少なくとも$n-1$チップは少なくとも 1 回は発射されている必要があります。 概念的には、繰り返し減算することで各頂点を削減します。$n-1$, しかし、発火は相互作用するため、これを独立して行うことはできません。 
3. 各発火は、発火頂点から他のすべての頂点に 1 つのチップを効果的に転送するというアイデアを導入します。これは、すべての頂点に対する +1 のグローバルな増分と次の減算として書き換えることができます。$n$発射された頂点から。 この再定式化により、すべての頂点が共有するグローバル成長項が分離されます。 
4. グローバルカウンターを追跡する$g$「全頂点に+1」効果が蓄積された回数を表します。 各頂点の実効値は次のようになります。$a_i + g - c_i \cdot n$、 どこ$c_i$頂点の何倍ですか$i$発砲した。 
5. 頂点は、実効値が少なくとも$n-1$。 段階的にシミュレーションするのではなく、調整された値をしきい値と比較することで、各頂点が何回発火できるかを計算します。 
6. この推論中に、システムが無制限の継続的なアクティベーションを許可していることが判明した場合、それを再発として分類します。 クリークでは、すべての頂点が同時にしきい値制約を下回らずに余剰を無期限に再分配し続けることができる場合に、これが発生します。 
7. それ以外の場合は、すべての集計された発火を適用し、累積的なグローバル効果を減算することによって最終値を計算します。 

### なぜ効果があるのか

 このプロセスでは、発火頂点の不足を除いて質量を均一に再配分しながら、総チップ数を維持します。$n$。 この対称性は、システムの進化が発火の順序ではなく、各頂点がしきい値を横切った回数のみに依存することを意味します。 すべての更新をグローバルな増分と局所的な減算の組み合わせとして書き直すと、変換された空間ではダイナミクスが単調になり、最終的にすべての余分な質量が使い果たされるか、無限に循環します。 クリークは構造的なボトルネックがないことを保証するため、再発は、一部の頂点をしきい値より上に無期限に維持する無制限の能力からのみ発生します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # In a clique, degree is n-1
    deg = n - 1
    
    # Total sum check is not sufficient alone, but helps structure reasoning
    total = sum(a)
    
    # If even one vertex can keep firing forever, process is recurrent.
    # For clique sandpile, recurrence happens when total is large enough
    # to avoid all vertices stabilizing below deg simultaneously.
    
    # We simulate in a reduced form using "excess over threshold"
    # Each vertex contributes max(0, a[i] - (n-2)) as potential instability mass.
    
    excess = 0
    for x in a:
        if x >= deg:
            excess += x - (deg - 1)
    
    # If excess is large enough relative to structure, declare recurrent.
    # For clique, any unbounded activation cycle corresponds to positive excess loop.
    if excess > 0 and total >= n * (n - 1):
        print("Recurrent")
        return
    
    # Otherwise compute stabilized state via redistribution
    # We repeatedly reduce vertices by multiples of deg-1
    res = a[:]
    changed = True
    while changed:
        changed = False
        add = 0
        for i in range(n):
            if res[i] >= deg:
                cnt = res[i] // deg
                res[i] -= cnt * deg
                add += cnt
                changed = True
        if add:
            for i in range(n):
                res[i] += add
    
    print(*res)

if __name__ == "__main__":
    solve()
```この実装では、バッチ削減を使用して、繰り返しの起動を圧縮しようとします。 アイデアは、次の倍数を減算することです。$n-1$各頂点から累積された「グローバル増分」をすべての頂点に一括して伝播します。 

ループ構造は、一段階の発火を避けるように設計されています。 一度に 1 つの頂点をシミュレートするのではなく、1 つのパスで各頂点からできるだけ多くの完全な発火を削除し、それらの寄与を蓄積してから、それらをグローバルに適用します。 これは、各発火が他のすべての頂点に等しく寄与するクリーク対称性を反映しています。 

真の無限ダイナミクスは有限の安定化ステップでは解決できないため、反復チェックは高速拒否条件として意図的に分離されています。

 ## 特殊なケース

 重要なエッジケースは、ちょうどその位置にある頂点を除き、すべての頂点がしきい値より下で始まる場合です。$n-1$。 その場合、最初は 1 つの発火のみが発生しますが、その発火により他の発火がしきい値を超える可能性があり、カスケード更新が発生します。 このアルゴリズムは、単一のチェーンに従うのではなく、すべての発火をまとめてバッチ処理することでこれを処理するため、カスケードは 1 つの還元フェーズで吸収されます。 

もう 1 つのエッジ ケースは、すべての頂点が同一で、しきい値をわずかに下回る場合です。 最初はアクティブな頂点が 1 つもありませんでしたが、再配分を繰り返すと、単純なシミュレーションですべての頂点が同時に上昇する可能性があります。 バッチ削減では、グローバルな増分を 1 つのステップで考慮することで発振を防止し、システムがすぐに安定するか、再発として識別されるようにします。
