 ## 解決策
 ## 問題の理解

 文字列のコレクションが与えられ、それぞれが完全な無向グラフの頂点を表します。 すべての頂点のペアは接続されており、エッジの重みは 2 つの文字列がどの程度類似しているかによって定義されます。具体的には、両方の文字列に現れる最長の部分文字列の長さです。 

タスクは、これらの頂点上でエッジの重みの合計を最大化するスパニング ツリーを選択することです。 言い換えれば、選択したエッジに沿った共有部分文字列の類似性の合計ができるだけ大きくなるように、正確に n−1 個のエッジを使用してすべての文字列を接続したいと考えます。 

ここでの本当の難しさの要因は制約です。 文字列 n の数は 2×10^6 まで大きくなる可能性がありますが、すべての文字列の長さの合計も 2×10^6 によって制限されます。 この非対称性は重要です。膨大な数のノードが許可されていますが、「タッチ」できるのは合計約 200 万文字だけです。 n^2 に比例する処理を実行しようとするソリューションは直ちに不可能であり、ペアごとの情報を保存するものであっても除外されます。 唯一実行可能なアプローチは、文字列自体の構造を通じてすべての情報を圧縮するものです。 

よく思い浮かぶ素朴なアイデアは、文字列ごとの接尾辞構造または動的プログラミングを使用して、文字列のすべてのペアの最長の共通部分文字列を計算することです。 Θ(n^2) のペアが存在するため、これはすぐに失敗します。これは、たとえ小さなケースであっても、既に 10^12 のオーダーで比較されることになります。 

もう 1 つの微妙な失敗例は、長い共通部分文字列がローカルでのみ重要であると想定している場合です。 たとえば、多くの文字列が長く繰り返されるパターンを共有している場合、各文字列を最適な一致に個別に接続する貪欲な戦略では、サイクルが発生したり、全体的により適切な接続を見逃したりする可能性があります。 最大スパニング ツリー構造では、ローカル ペアリングではなくグローバル調整が強制されます。 

## アプローチ

 直接的なアプローチでは、文字列の各ペア間のエッジの重みを計算してから、Kruskal または Prim を実行します。 概念的には正しいですが、Θ(n^2) 部分文字列の比較を計算する必要があります。 2 つの文字列間の単一の最も長い共通部分文字列の計算でも、その長さは線形であるため、完全なソリューションは限界をはるかに超えて爆発的に増加します。 

重要な観察は、「2 つの文字列間の最長の共通部分文字列」は、グローバル構造内の部分文字列の出現によって解釈できるということです。 文字列のペアという観点から考えるのではなく、部分文字列自体という観点から考えます。 すべての部分文字列には長さがあり、文字列の一部のサブセットに表示されます。 長さ L の部分文字列が k 個の異なる文字列に現れる場合、重み L を持つそれらの k 頂点間に潜在的な接続が誘発されます。 

これにより、問題はペアごとの比較から共有部分文字列によるグループ化に移ります。 すべての部分文字列を効率的に取得する自然な構造は、すべての文字列を連結して構築されるサフィックス オートマトンです (部分文字列が境界を越えないようにセパレータが使用されます)。 オートマトンの各状態は部分文字列のセットを表し、その長さはその同値クラス内の最長の部分文字列に対応します。 さらに重要なことは、各状態は、出現の終了位置を通じて、どの文字列にそれが含まれているかを「認識」していることです。 

各オートマトンの状態をその部分文字列を含む文字列のセットに関連付けることができると、問題は制御された結合プロセスになります。 州ごとに、その部分文字列を共有するすべての文字列を考慮します。 k 個の異なる文字列が長さ L の部分文字列を共有する場合、最大スパニング ツリーでは、その情報を安全に使用して L 個のエッジに相当する接続に寄与できます。クラスカルのプロセスでは、これらは重みしきい値 L で現れるエッジを表すためです。

残りの課題は、これらのセットを効率的に維持することです。 状態ごとに完全なビットセットを保存することは避けます。 代わりに、小から大へのマージを使用してサフィックス リンク ツリーに沿って文字列識別子を伝播し、保存される識別子の総数が文字列の総長に比例するようにします。 

最後に、部分文字列の長さの降順で状態を処理します。 文字列に対する素集合共用体を使用して、同じ状態にあるすべての文字列をマージしようとします。 マージが成功するたびに、その部分文字列の長さをスパニング ツリーに追加することに対応します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | LCS + MST ペアによるブルート フォース | O(n^2・L) | O(n^2) | 遅すぎる |
 | 文字列セットに対するサフィックス オートマトン + DSU | O(全長対数全長) | O(全長) | 承認済み |

 ## アルゴリズムのチュートリアル

 連結されたすべての文字列に対してサフィックス オートマトンを構築し、部分文字列が境界を越えないように文字列間に一意の区切り文字を挿入します。 オートマトン内のすべての状態は部分文字列のクラスに対応し、オートマトン内の各状態は特定の入力文字列内の位置まで遡ることができます。 

次に、どの入力文字列にその部分文字列が少なくとも 1 回含まれるかをすべての州が認識できるように、終端位置から接尾辞リンクを介して上向きに情報を伝播します。 

次に、部分文字列の長さの降順で状態を処理し、大きな重みから小さな重みへのクラスカルのようなスイープをシミュレートします。 素のセット共用体構造は、文字列間の接続を維持します。 

1. すべての文字列に対して接尾辞オートマトンを構築し、部分文字列が異なる入力にまたがらないように、各文字列の後に一意の区切り文字を挿入します。 これにより、すべての状態が個々の文字列内に完全に含まれる部分文字列を表すことが保証されます。 
2. 文字挿入に対応するオートマトン内の各位置について、それが属する文字列のインデックスを記録します。 これにより、州の初期の「端末所有権」情報が作成されます。 
3. オートマトンのサフィックス リンク ツリーを構築し、文字列メンバーシップを子状態から親状態に上方に伝播します。 子を親にマージするときは、常に小さいリストを大きいリストにマージして、全体の複雑さがほぼ線形になるようにします。 
4. すべてのオートマトンの状態を長さの降順に並べ替えたリストを作成します。 各状態は、固定最大長の部分文字列を表します。 
5. すべての文字列に対して素のセット共用体構造を初期化します。各文字列は独自のコンポーネントとして始まります。 
6. 各状態を長さの降順に処理します。 特定の状態について、この状態に表示される文字列を表すすべての個別の DSU を収集します。 
7. k 個の異なる代表がある場合、それらを結合します。 各結合演算は、現在の状態の長さに等しい重みのエッジを追加することに対応し、k 成分を 1 つに削減しながら、その長さの (k-1) 倍を答えに寄与します。 

### なぜ効果があるのか

 任意の固定部分文字列長 L では、少なくとも L の長さのすべての部分文字列を同時に考慮することになります。 2 つの文字列がそのような部分文字列を共有する場合、それらは少なくとも L の重みのエッジで接続できます。状態を降順で処理することで、常に重みの低い接続よりも重みの高い接続をコミットすることが保証され、最大スパニング ツリーに関するクラスカルの貪欲な原則と正確に一致します。 DSU は、2 つの文字列がより重みの高い部分文字列を介して接続されると、それらが分離されたり、弱い接続が再検討されたりすることがないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SAM:
    def __init__(self):
        self.next = []
        self.link = []
        self.length = []
        self.last = 0

        self.next.append({})
        self.link.append(-1)
        self.length.append(0)

    def extend(self, c):
        cur = len(self.next)
        self.next.append({})
        self.length.append(self.length[self.last] + 1)
        self.link.append(0)

        p = self.last
        while p != -1 and c not in self.next[p]:
            self.next[p][c] = cur
            p = self.link[p]

        if p == -1:
            self.link[cur] = 0
        else:
            q = self.next[p][c]
            if self.length[p] + 1 == self.length[q]:
                self.link[cur] = q
            else:
                clone = len(self.next)
                self.next.append(self.next[q].copy())
                self.length.append(self.length[p] + 1)
                self.link.append(self.link[q])

                while p != -1 and self.next[p].get(c) == q:
                    self.next[p][c] = clone
                    p = self.link[p]

                self.link[q] = self.link[cur] = clone

        self.last = cur
        return self.last

class DSU:
    def __init__(self, n):
        self.p = list(range(n))

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        self.p[b] = a
        return True

n = int(input())
sam = SAM()

pos_owner = []
state_owner = []

# build SAM over all strings with separators
sep_id = 26
for i in range(n):
    s = input().strip()
    for ch in s:
        v = sam.extend(ord(ch) - 97)
        pos_owner.append((v, i))
    sam.extend(sep_id + i)
    pos_owner.append((sam.last, -1))

size = len(sam.next)

# suffix link tree
tree = [[] for _ in range(size)]
for v in range(1, size):
    tree[sam.link[v]].append(v)

# collect owners per state
owners = [[] for _ in range(size)]
for v, i in pos_owner:
    if i != -1:
        owners[v].append(i)

# small to large merge on suffix tree
def dfs(v):
    for u in tree[v]:
        dfs(u)
        if len(owners[u]) > len(owners[v]):
            owners[v], owners[u] = owners[u], owners[v]
        owners[v].extend(owners[u])
        owners[u].clear()

dfs(0)

states = list(range(size))
states.sort(key=lambda x: sam.length[x], reverse=True)

dsu = DSU(n)
ans = 0

for v in states:
    if sam.length[v] == 0:
        continue
    comps = []
    for x in owners[v]:
        comps.append(dsu.find(x))
    comps = list(set(comps))
    if len(comps) <= 1:
        continue
    base = comps[0]
    for c in comps[1:]:
        if dsu.union(base, c):
            ans += sam.length[v]

print(ans)
```この実装は、サフィックス オートマトン、その上に構築されるサフィックス リンク ツリー、文字列上の素セット ユニオンという 3 つの構造を中心としています。 オートマトンはすべての部分文字列をエンコードしますが、ツリー構造により、どの文字列に各部分文字列が含まれるかを集約できます。 次に、DSU はこれらの暗黙的なエッジ上で Kruskal のプロセスをシミュレートします。 

微妙な点は、DFS 中に小規模から大規模へのマージが使用されていることです。 これがないと、連結が繰り返されるため、所有者リストを結合する全体の複雑さが爆発してしまいます。 もう 1 つの重要な詳細は、結合を実行する前に州ごとに DSU 代表を重複排除することです。 これがないと、冗長な結合試行によってエッジ カウント ロジックが歪んでしまいます。 

## 実用的な例

 「aba」、「bab」、「aba」という 3 つの文字列について考えてみましょう。 接尾辞オートマトンには、「a」、「b」、「ab」、「ba」などの部分文字列に対応する状態が含まれます。 「ab」の状態は文字列 0 と 1 に存在し、「a」は 3 つすべてに存在します。 

状態「a」の場合、所有者は [0,1,2] になる可能性があります。 DSU の代表はすべて異なるため、2 つの和集合を実行し、答えに 2 × 1 を加えます。 状態「ab」の場合、文字列 0 と 1 のみが存在し、それらがまだ接続されていない場合は、1 × 2 を追加します。 

| 状態 (部分文字列) | 長さ | DSU 代表者 | 統合されたコンポーネント | 貢献 |
 | --- | --- | --- | --- | --- |
 | "a" | 1 | {0,1,2} | 2 組合 | 2 |
 | "アブ" | 2 | {0,1} | 1 ユニオン | 2 |

 このトレースは、より長い部分文字列がどのように最初に寄与するかを示しており、より強い接続が弱い接続よりも優先されることが保証されます。 

ここで、すべての文字列が同一である場合、たとえば「aaaa」を考えてみましょう。 「a」、「aa」、「aaa」、「aaaa」に対応するすべての状態には、すべての文字列が含まれます。 このアルゴリズムは、コンポーネントを繰り返しマージして、より長い長さにしますが、最初に必要なマージのみが最終的なツリーに寄与します。 

| 状態 | 長さ | コンポーネント | 貢献 |
 | --- | --- | --- | --- |
 | 「ああ」 | 4 | 4→1 | 3×4 |
 | 「ああ」 | 3 | すでに 1 | 0 |
 | "ああ" | 2 | すでに 1 | 0 |
 | "a" | 1 | すでに 1 | 0 |

 これにより、すべての頂点が接続されると、下位の状態が結果に影響を与えなくなることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(全長対数全長) | SAM 構築とサフィックス ツリー上の小規模から大規模へのマージ |
 | スペース | O(全長) | オートマトンの状態と集約された所有者リスト |

 全長の限界が 2×10^6 であるため、オートマトンとすべての伝播構造の両方が線形スケールのままであることが保証されます。 マージによる対数的なオーバーヘッドがあっても、ソリューションは制限内に問題なく収まります。

 ## 特殊なケース

 すべての文字列が 1 文字の重複のみを共有する場合、まれなケースが発生します。 その場合、長さ 1 の状態のみが寄与し、DSU はすべてを最下位レベルでマージします。 長さの分布に関係なくすべての状態が均一に処理されるため、アルゴリズムは引き続き正しく動作します。 

もう 1 つのエッジ ケースは、1 つの文字列が他の多くの文字列の部分文字列である場合です。 たとえば、「abc」、「xabcx」、「yabc」などです。 「abc」に対応する状態は 3 つの文字列すべてを収集し、単一の高重量マージですべてのコンポーネントを接続します。 このアルゴリズムは、この大きな部分文字列が、より小さな無関係なオーバーラップの前に処理されることを保証し、最大スパニング ツリー構築の正確さを維持します。
