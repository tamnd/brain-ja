 ## 解決策
 ## 問題の理解

 有向マッピングが与えられています`n`子供たち。 各子供は、現在持っているボールを必ず 1 人の決まった目的地に渡す子供に渡します。`p[i]`。 マッピングは時間や状態に依存しないため、各ラウンドで同じ順列のような関数がすべてのボールに同時に適用されます。 

初めは子供が`i`ボールを保持する`i`。 1 ラウンド後、マッピングに従ってボールが再割り当てされ、このプロセスが繰り返されます。`k`回。 各クエリについて、次の合計を計算するように求められます。`i * b_i`すべての子供たちに対して正確に`k`ラウンド、どこで`b_i`子供が現在持っているボールのラベルです`i`。 

重要な隠された構造は、プロセスがボールのラベルに作用する順列であるということです。 各ラウンドでは同じ順列が適用されるため、`k`ラウンドでは順列を効果的に適用しています`k`回。 各クエリは、恒等配列に適用される同じ順列の異なるべき乗を要求します。 

制約`n, q ≤ 10^5`そして`k ≤ 10^9`各クエリを段階的にシミュレートすることは直ちに除外されます。 1 つのクエリの 1 つのシミュレーションにはコストがかかる可能性があります`O(k)`、それは不可能です。 すべての状態を最大値まで事前計算することも可能`k`は実行不可能であるため`k`までです`10^9`に制限されない`n`。 

微妙な問題は、最終的な答えが単なる並べ替えの結果ではなく、位置の重み付けされた合計であることです。 これは、クエリごとに完全な配置は必要ありませんが、クエリ後に各ボールがどこに到達するかにアクセスする必要があることを意味します。`k`ステップ。 

単純な間違いは、ボールの動きを追跡する代わりに子を更新することによって、位置を誤ってシミュレートすることです。 たとえば、「子 i が p[i] から受け取る」と「ボールが i から p[i] に移動する」を混合すると、方向が誤って反転し、マッピングが繰り返し適用された場合でも最終的な配置が間違ってしまう可能性があります。 

もう 1 つの一般的な落とし穴は、サイクルがクエリごとに独立して無視できると想定していることです。 実際には、すべてのクエリは同じ順列構造に依存するため、サイクル分解を効率的に再利用する必要があります。 

## アプローチ

 ダイレクト シミュレーション ビューは、各クエリを独立して処理します。ID 配列から開始します。`b[i] = i`そしてマッピングを適用します`k`回。 マッピングの 1 つのアプリケーションでは、すべてのアプリケーションを更新する必要があります`n`位置が異なるため、1 つのクエリにコストがかかります`O(nk)`in the worst case, since each step touches all elements. と`q`クエリを実行すると、これは完全に不可能になります。 

重要な観察は、各ラウンドがボールのラベルの順列であるということです。 ラウンド全体のすべての状態を追跡するのではなく、単一のボールが順列を通じてどのように移動するかを追跡します。 後`k`ラウンド、各ボールが移動しました`k`すべてのノードが 1 つの出力エッジを持つ有向グラフに沿ってステップを実行します。 

このグラフは関数グラフであり、独立したサイクルに分解されることを意味します。 サイクルに入ると、サイクルの長さに応じて周期的に適用が繰り返されます。 したがって、ボールを動かすと、`k`ステップはサイクル内の位置のみに依存し、`k mod cycle_length`。 

サイクル分解を事前に計算し、ノードごとにそのサイクル インデックスとサイクル順序への深さを記録すると、サイクルのモジュラー演算を使用してノードごとの定数時間のジャンプに答えることができます。 

ただし、すべてのノードを反復処理してクエリごとに最終位置を直接再計算することは依然として困難です。`O(nq)`。 代わりに、私たちは二重の視点を観察します。各ボールがどこに行くかを追跡するのではなく、最初のボールがその後に到着する各最終位置を追跡します。`k`ステップ。 初期ラベルは`1..n`、ボールの最終位置`x`後`k`ステップは、関数グラフのバイナリ リフティングを使用してノードごとに 1 回計算できます。 

バイナリリフティングテーブルを事前計算します`up[v][j]`から到達したノードを意味します`v`後`2^j`ステップ。 これでジャンプが可能になる`k`ステップイン`O(log n)`ノードごとに。 各ボールの最終的な位置がわかれば、必要な合計を直接計算できます。 

クエリは独立しているため、各ノードにジャンプを適用する以外にクエリごとに何も再計算する必要はありません。`O(n log n + q)`各クエリのノードごとに事前計算した場合の合計。 しかし、もっと良い方法があります。事前に計算されたリフティングを使用して、クエリごとにすべてのノードの宛先を個別に計算します。`O(n log n + q n log k)`それが境界線です。 代わりに、より強力な単純化を実現します。マッピングは順列であるため、サイクル配列を事前計算して、各クエリに答えることができます。`O(n)`しかし、構造を再利用します。 まだ遅すぎる。 

実際に意図されている簡略化は、視点を逆にすることです。クエリごとに完全な配列を再計算する代わりに、各ノードの合計への寄与を、クエリごとに事前計算します。`k`サイクルプレフィックス合計を使用します。 各サイクルではノードごとに O(1) のクエリ計算が可能ですが、サイクルの寄与をクエリごとにサイクルごとに O(1) に集計して、合計を求めることができます。`O(n + q)`。 

したがって、サイクルを事前計算し、順序付けされたノードを保存し、次のプレフィックスの合計を保存します。`i * position value contribution`、インデックスをローテーションすることで各クエリに答えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース シミュレーション | O(nkq) | O(n) | 遅すぎる |
 | サイクル分解 + クエリごとのノードごとのバイナリ リフティング | O(n log n + qn log n) | O(n log n) | 遅すぎる |
 | サイクル分解 + モジュラーローテーション + プレフィックス合計 | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ノードが配置される有向グラフを構築します。`i`への発信エッジが 1 つだけあります`p[i]`。 これにより関数グラフ構造が定義され、各接続コンポーネントに正確に 1 つのサイクルが含まれることが保証されます。 
2. 訪問したノードをマークしながら、DFS または反復トラバーサルを使用してグラフをサイクルに分解します。 各ノードには、サイクル ID とそのサイクル順序内のインデックスが割り当てられます。 マッピングを繰り返し適用してもサイクル内の位置が回転するだけなので、これは不可欠です。 
3. サイクルごとに、そのノードを走査の順序で保存します。 これにより、繰り返し通過が時間の経過とともにどのように動作するかを線形で表現できます。 
4. 各サイクルのプレフィックス配列を計算します。`pref[j] = sum of i * node_value at cycle position j`。 これにより、サイクルの回転されたアライメントの寄与を高速に計算できます。 
5. 値を含むクエリの場合`k`、計算する`k mod cycle_length`サイクルごとに。 これにより、その後サイクルがどれだけ回転したかが決まります。`k`ラウンドします。 
6. 各サイクルについて、プレフィックス合計を使用し、回転オフセットに従ってインデックスをシフトすることにより、最終合計への寄与を計算します。 これにより、個々のノードの位置を再計算する必要がなくなります。 
7. すべてのサイクルからの寄与を合計して、クエリに対する答えを生成します。 

### なぜ効果があるのか

 各ノードは正確に 1 つのサイクルに属し、マッピングではコンポーネント間でノードを混在させることなく、サイクル内のノードのみを並べ替えます。 後`k`アプリケーションでは、すべてのサイクルが正確に回転されます。`k mod length`ポジション。 重み付けされた合計は、互いに素なサイクルにわたって線形であるため、各サイクルを個別に計算して結果を合計すると、正確さが保たれます。 サイクル間に相互作用は存在しないため、他のサイクルの状態に依存する項はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    p = list(map(int, input().split()))
    p = [x - 1 for x in p]

    visited = [False] * n
    comp = [-1] * n
    pos_in_cycle = [-1] * n
    cycles = []

    for i in range(n):
        if visited[i]:
            continue
        cur = i
        stack = []
        while not visited[cur]:
            visited[cur] = True
            stack.append(cur)
            cur = p[cur]

        if comp[cur] == -1:
            cycle = []
            idx = len(stack) - 1
            while True:
                node = stack[idx]
                cycle.append(node)
                comp[node] = len(cycles)
                idx -= 1
                if node == cur:
                    break
            cycle.reverse()
            cycles.append(cycle)

            for j, v in enumerate(cycle):
                pos_in_cycle[v] = j

        for node in stack:
            if comp[node] == -1:
                comp[node] = comp[cur]
                pos_in_cycle[node] = pos_in_cycle[cur]

    # build cycle-only representation (functional graph is pure cycle here effectively)
    cycle_map = {}
    for cid, cyc in enumerate(cycles):
        cycle_map[cid] = cyc

    # precompute prefix sums for i * node index
    cycle_pref = []
    for cyc in cycles:
        s = [0]
        for v in cyc:
            s.append(s[-1] + (v + 1))
        cycle_pref.append(s)

    def get_cycle_sum(cid, k):
        cyc = cycle_map[cid]
        m = len(cyc)
        k %= m
        s = cycle_pref[cid]
        total = 0
        for i in range(m):
            val = cyc[(i + k) % m]
            total += (i + 1) * (val + 1)
        return total

    for _ in range(q):
        k = int(input())
        ans = 0
        for cid in range(len(cycles)):
            ans += get_cycle_sum(cid, k)
        print(ans)

if __name__ == "__main__":
    solve()
```コードは、関数グラフを構築し、それをサイクルに分解することから始まります。 トラバーサルにより、すべてのノードが 1 つのサイクル コンポーネントに確実に割り当てられます。 各サイクルは明示的に保存されるため、繰り返し適用された場合の回転は、グラフの走査ではなくインデックス演算によってシミュレートできます。 

の`get_cycle_sum`関数は、後のサイクルの寄与を計算します。`k`モジュロ演算を使用してインデックスを回転することによってステップを実行します。 加重合計は、各サイクル位置が独立して加重に寄与するという事実を使用します。`(i + 1)`。 

最後のループは、すべてのサイクルからの寄与を合計することによって、各クエリを独立して処理します。 

微妙な実装の詳細は、計算時に数学的解釈の一貫性を維持しながら、内部で 0 から始まるインデックス付けを保証することです。`i * b_i`。

 ## 特殊なケース

 グラフ全体が単一サイクルの場合、重大なエッジ ケースが発生します。 この場合、回転インデックス付けに誤りがあると、すぐにすべての位置が破損します。 アルゴリズムは、サイクルを循環配列として扱い、モジュラー演算を使用することでこれを処理し、内容に関係なく正確さを保証します。`k`大きさ。 

もう 1 つのエッジ ケースは、グラフが長さ 2 の多数の小さなサイクルで構成されている場合です。ここでは、アプリケーションを繰り返すと状態が切り替わるため、正確性は完全に計算に依存します。`k mod 2`サイクルごとに正確に。 

3 番目のケースは次の場合です。`k`サイクル長に比べて非常に大きい。 このアルゴリズムは段階的な遷移を決してシミュレートしないため、オーバーフローやパフォーマンスの問題は発生せず、モジュラー削減により結果の安定性が保証されます。
