 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列を含む円形配列が与えられます。 バッファーの「可視」部分、具体的には常に最初の k 個の位置を表す、サイズ k の固定ウィンドウがあります。 1 から n まで昇順に数値を「収集」したいのですが、数値はこの表示ウィンドウ内にある場合にのみ収集できます。 

許可される唯一の操作は、配列全体を 1 ステップずつ左または右に回転することです。 各回転には 1 ユニットのコストがかかります。 一連のローテーションの後、その値が次に必要な値である限り、現在表示されている数値を昇順に収集できます。 

タスクは、1 から n までを順番に正常に収集できるように、必要な最小合計回転数を決定し、値 x に到達したときに、その値が何らかの瞬間に表示されるプレフィックスに取り込まれていることを常に確認することです。 

すべてのテスト ケースにわたる n が最大 10^6 という制約は、テスト ケースごとの線形またはほぼ線形の解を意味します。 回転を明示的にシミュレートしたり、次の位置を繰り返し検索したりするアプローチは、各回転が O(n) であり、必要な調整が O(n) 回あり、結果として O(n^2) になる可能性があるため、遅すぎます。 

素朴な考え方による微妙な失敗例は、次の数字がすぐに表示されるように常に貪欲に回転できると仮定してから次に進むことです。 これは、1 つの数値を固定するために回転すると、以前に表示された数値またはスキップされた数値の初期の位置合わせを混乱させる可能性があるという事実を無視しています。 

たとえば、n = 5、k = 2 を考えてみましょう。 

入力:

 2 5

 2 3 4 5 1

 単純な貪欲な戦略では、1 が表示されるまで回転し、その後 2 に焦点を当てる、というようにする可能性がありますが、単一の回転フェーズの後に複数の連続したターゲットがすでにウィンドウ内に収まっている可能性があるため、これでは回転が過大にカウントされます。 

主な問題は、回転がすべての位置に同時に影響するため、移動ウィンドウに対して各値がどのように位置合わせされるのかを全体的に把握する必要があることです。 

## アプローチ

 強引な解釈では、プロセスを段階的にシミュレートします。 現在の配列の状態と、次に必要な値へのポインタを維持します。 その値がすでに表示されているプレフィックスに含まれている場合は、その値を収集済みとしてマークします。 それ以外の場合は、プレフィックスに表示されるまで、左と右の両方の回転を試みます。 その後、より良い方向を選択して続行します。 

これは常にルールを尊重するため概念的には機能しますが、問題は、各欠損値を揃えるために O(n) 回の回転が必要な場合があり、n 個の値が存在するため、O(n^2) 個の最悪の場合の動作が発生することです。 

重要な洞察は、実際には配列をシミュレートする必要がないということです。 重要なのは、最初の順列における各値の位置です。 回転は、すべてのインデックスを n を法とする定数オフセットでシフトすることと同じです。 したがって、配列の移動について考える代わりに、時間の経過とともに変化するポインターのオフセットについて考えます。 

次に、値 x を固定することを考えます。 それはある位置 pos[x] にあります。 グローバル シフトの後、pos[x] が円上の長さ k の移動区間内にある場合、x が表示されます。 各 x について、pos[x] がウィンドウに入るように現在の配置からどれだけ回転する必要があるかだけを考慮します。 x が収集されると、ウィンドウの位置はさらに移動する可能性がありますが、全体の動きは最小限に抑えたいと考えています。 

重要な構造上の観察は、最適な戦略では要素ごとの任意の回転を考慮する必要がないということです。 代わりに、次に必要な値が表示されるようにウィンドウが調整されるトランジションのみを考慮します。 このようなイベント間では、複数の連続する値がすでにウィンドウ内に存在する可能性があり、これはコストが発生しないことを意味します。

したがって、問題を、円上で現在の「ウィンドウ間隔」を維持し、昇順の値ごとに、その位置をその間隔に収めるための最小回転距離を計算することに変換します。 回転はサイクル上で対称であるため、常に最も近い方向 (左または右) を選択します。 

これにより、問題は円上の位置の追跡とスライディング ウィンドウの更新に軽減され、モジュラー演算を使用して線形時間で実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | 位置 + 円形ウィンドウ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. アレイを構築する`pos`どこ`pos[x]`値 x のインデックスを順列に格納します。 これにより、O(1) 内の各値の位置にアクセスできるようになります。 その理由は、進化する配列全体ではなく、各数値がどこにあるかだけを考慮しているからです。 
2. 変数を維持する`shift`配列が初期状態からどれだけ回転されたかを表します。 配列を物理的に回転させるのではなく、このシフトに関連してすべてを解釈します。 
3. このシフトされた座標系で現在の可視ウィンドウを維持します。 シフトが s の場合、表示セグメントはインデックスに対応します。`[s, s + k - 1]`モジュロn。 これは、値が現在収集可能かどうかを確認するための直接的な条件を与えます。 
4. x を 1 から n まで繰り返します。 各 x について、シフトの下での現在の有効位置を計算します。`(pos[x] - shift) mod n`。 これにより、x が現在の座標系のどこにあるかがわかります。 
5. x がすでに表示ウィンドウ内にある場合は、コストを追加せずに続行します。 追加のローテーションを行わなくても連続した値を収集できるようになるため、これは重要です。 
6. x が表示されない場合は、x をウィンドウに表示するために必要な最小回転数を計算します。 左または右に回転できるため、円の意味でウィンドウの最も近い境界までの距離を計算し、そのコストを答えに追加します。 その後、アップデートしてください`shift`したがって、次のステップで x が表示されるようになります。 
7. x を収集した後、更新されたシフトを使用して x + 1 に進みます。 不変条件は、以前に収集されたすべての要素が以前の時点では有効であり、x 内でのみ前進するということです。 

### なぜ効果があるのか

 いつでも、システムの状態は 1 つの回転オフセットによって完全に記述されます。 すべての操作ではこのオフセットのみが変更され、可視性は円上の固定間隔によって決まります。 順列は固定されているため、各値は決定的な位置を持ち、唯一の自由はウィンドウをどのようにシフトするかだけです。 次に必要な値を可視化するのに十分なだけシフトするという貪欲な決定が最適です。追加のシフトは、後で必要な操作を減らす方法で将来の柔軟性を拡張することなく、コストを増加させるだけだからです。 これは、収集順序が固定されており、ローテーション履歴とは無関係であるという事実の直接的な結果です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(a):
        pos[v] = i

    shift = 0
    ans = 0

    for x in range(1, n + 1):
        cur = (pos[x] - shift) % n

        if cur < k:
            continue

        # need to rotate so that cur enters [0, k-1]
        # best move is to bring it to k-1
        target = (cur - (k - 1)) % n
        ans += target
        shift = (shift + target) % n

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、すべての回転を単一のモジュール式オフセット変数に圧縮することに依存しています。 重要な点は、配列を物理的に回転させるのではなく、シフトされた座標系で可視性を解釈することです。 

表現`(pos[x] - shift) % n`固定位置を現在のフレームに変換します。 小切手`cur < k`これは、値がすでに表示されているプレフィックス内にあるかどうかをテストすることと同じです。 そうでない場合は、要素がウィンドウの右側の境界に揃うように十分な回転を行い、無駄な動きを最小限に抑えます。 

のアップデート`shift`回転を蓄積し、将来の要素間の一貫性を確保します。

## テストケース```python
import sys, io

def solve_case(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        pos = [0] * (n + 1)
        for i, v in enumerate(a):
            pos[v] = i

        shift = 0
        ans = 0

        for x in range(1, n + 1):
            cur = (pos[x] - shift) % n
            if cur >= k:
                add = (cur - (k - 1)) % n
                ans += add
                shift = (shift + add) % n

        return str(ans)

    return solve()

 ## 特殊なケース

 エッジケースの 1 つは、k が n と等しい場合です。 この場合、ウィンドウは常にバッファ全体をカバーするため、回転することなくすべての数値をすぐに収集できます。 アルゴリズムはこれを処理します。`cur`は常に k より小さいため、シフトは追加されません。 

もう 1 つのエッジ ケースは、k が 1 に等しい場合で、単一の位置のみが表示されます。 この場合、すべての値を位置 0 に個別に整列させる必要があります。アルゴリズムは各要素に必要な最小円周距離を正確に累積し、ステップごとに最適な整列を効果的にシミュレートします。 

3 番目のエッジケースは、順列がすでにソートされている場合です。 この場合、最初はすべての値が 0 から n-1 の位置で昇順になっており、k に応じて、最初の位置合わせの後、多くの連続する値がすでに表示されるプレフィックスに含まれます。 初期の回転により冗長な操作を行わずに可視性が前方に伝播されるため、シフトベースの表現はこれを自然に捉えています。
