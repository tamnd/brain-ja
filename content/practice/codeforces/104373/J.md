 ## 解決策
 ## 問題の理解

 段階的にツリーを構築しています。 この構造は 1 つのノードから始まり、各操作によって重み付けされたエッジを使用して既存のノードに新しいノードが接続されるか、既存のノードの色が変更されます。 すべての操作の後、異なる色の 2 つのノード間の最大可能距離を報告する必要があります。 

重要なオブジェクトは単なる木ではなく、その上に施されたダイナミックなカラーリングです。 距離は重み付きツリー上の標準の最短パス距離であるため、各ペアは一意のパスを持ちます。 難しさは、トポロジと色の両方がオンラインで変化するという事実から来ており、更新のたびに答えが必要になります。 

制約は合計 5 × 10^5 の演算に達するため、各クエリの後に多くのペア間の距離を再計算するソリューションは直ちに実行不可能になります。 挿入のたびに新しいノードから既存のすべてのノードまでの距離が変化するため、すべてのペアの情報を維持することさえ不可能です。 

単純なアプローチでは、すべての操作の後に、異なる色のノードのすべてのペアを反復処理し、LCA または親ポインターを使用して距離を計算します。 つまり、クエリあたり O(n^2) であり、n については 2 × 10^5 付近ですでに失敗します。 さらに微妙なことに、色の変更により以前は最適だったペアが非局所的な方法で無効になる可能性があるため、「一部の」ペアのみを再計算しても依然として壊れます。 

最も遠いペアが色が頻繁に変更されるノードにまたがる場合、あまり明らかではない障害ケースが発生します。 たとえば、直径のエンドポイントが繰り返し色を交換する場合、色ごとまたはコンポーネントごとに単一の最良のペアをキャッシュするソリューションは不正確になります。これは、最良のクロスカラー ペアが突然ツリーのまったく異なる部分に移動する可能性があるためです。 

本当の課題は、ツリーの漸進的な成長をサポートしながら、動的なカラー反転の下でグローバルな極限構造を維持することです。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのノードが保持され、クエリのたびに答えが再計算されます。 各ノード u について、異なる色のすべてのノード v と比較し、事前に計算された LCA 構造を使用してツリーの距離を計算します。 すべての有効なペアを直接チェックするため、これは正しいですが、最悪の場合、クエリごとに O(n^2) の距離評価が必要になります。 5 × 10^5 の演算では、これは制限をはるかに超えています。 

重要な観察は、任意のペアが要求されるのではなく、色の制約によって制限されたツリー内の最大距離が要求されるということです。 ツリーでは、距離のグローバル極値は直径の端点に強く結びついています。 色を無視すると、最も遠いペアは常に木の直径の端点の 1 つになります。 色が導入された場合でも、「異なる色」を尊重する最適なペアは、ノードのサブセットによって引き起こされる直径のような構造上に存在する必要があります。 

これは、すべてのノードではなく、少数の候補「極端なノード」のセットを維持することを示唆しています。 各色は、最も遠くまで届く少数の代表者を通じて、ツリーの残りの部分と相互作用します。 

ツリー上の動的な「2 つのセット間の最大距離」問題を処理する標準的な方法は、維持されている少数のエンドポイントのセットからの最も遠い距離に答えることができる構造を維持することです。 重要な考え方は、ツリーでは距離が凸性の特性を満たすということです。つまり、候補となる極値ノードのセットを維持する場合、更新後の新しい最適なペアには、一定数の極値端点の 1 つが含まれている必要があります。 

したがって、色によって引き起こされる関連セットごとに 2 つのグローバル直径エンドポイントを維持し、これらのエンドポイントのみを使用して「最適な色間距離」に答えることができるグローバル候補構造を維持します。 各更新では最大 1 つの色クラスが変更されるため、少数の維持された候補を更新し、制限されたプールから最良の答えを再計算できます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(クエリごとに n^2) | O(n) | 遅すぎる |
 | 木の直径候補のエンドポイント保守 | O(log n) 償却 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ルート付きツリーを維持し、LCA と距離のバイナリ リフティングを事前計算します。 ノードは順番に追加されるため、ノード 1 をルートとして扱い、親ポインターと深さを段階的に計算できます。 

色ごとに、少数の「極端な代表者」を維持します。 実際的で正しい選択は、直径を維持するのと同様に、カラー クラスごとに最も遠いノードを 2 つまで維持することです。各カラー c について、単独で考慮した場合にそのカラー クラス内のペアごとの距離を最大化する 2 つのノードを保存します。 

また、さまざまな色の代表を組み合わせて形成された回答候補を追跡するグローバル構造も維持しています。 最適なクロスカラー ペアは、それぞれのカラー分布内で極端なノード間に存在する必要があるため、代表的なエンドポイント間の距離を考慮するだけで十分です。 

ノードの色が変わると、そのノードを古い色の候補セットから削除して新しい色の候補セットに挿入し、色ごとに最大 2 つの極値代表を更新します。 各更新は、現在の代表者までの距離を確認することで実行できます。 

色ごとの代表を維持した後、すべての色にわたって保存されているすべての代表間の距離のみをチェックすることによって、全体的な答えを再計算します。 色ごとの代表者の数は制限されているため、これは高速です。 

中心的な考え方は、各色クラスが動的なセットのように動作し、その直径の端点が他の色との関連するすべての相互作用を要約するというものです。 

### これが機能する理由

 正確さは、ツリー内では、任意の集合から最も遠い点が常にその集合の境界点の端に到達し、それらの境界点は一定サイズの要約 (直径端点) として維持できるという事実にかかっています。 直径の端点に向かって移動しても、ツリー メトリックで達成可能な最大分離を減らすことができないため、異なる色の最適なペアは、距離を減らすことなく、それぞれの色クラス内の端点に「プッシュ」できます。 

したがって、色はノードを動的に分割しますが、各分割は大域的最大化に必要なすべての距離情報を保持する最大 2 つの点で表すことができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LOG = 20

def dist(u, v, depth, up, dist_up):
    if depth[u] < depth[v]:
        u, v = v, u
    res = 0
    diff = depth[u] - depth[v]
    i = 0
    while diff:
        if diff & 1:
            res += dist_up[u][i]
            u = up[u][i]
        diff >>= 1
        i += 1

    if u == v:
        return res

    for i in range(LOG - 1, -1, -1):
        if up[u][i] != up[v][i]:
            res += dist_up[u][i] + dist_up[v][i]
            u = up[u][i]
            v = up[v][i]

    res += dist_up[u][0] + dist_up[v][0]
    return res

def update_color_rep(rep, node, depth, up, dist_up):
    if node is None:
        return rep

    if len(rep) == 0:
        return [node]

    if len(rep) == 1:
        a = rep[0]
        if dist(node, a, depth, up, dist_up) >= 0:
            return [a, node]
        return [a]

    a, b = rep
    # try replacing to maintain best diameter
    cand = [a, b, node]

    best_pair = (a, b)
    best_dist = dist(a, b, depth, up, dist_up)

    for i in range(3):
        for j in range(i + 1, 3):
            u, v = cand[i], cand[j]
            d = dist(u, v, depth, up, dist_up)
            if d > best_dist:
                best_dist = d
                best_pair = (u, v)

    return list(best_pair)

def main():
    T = int(input())
    for _ in range(T):
        q, C = map(int, input().split())
        n = 1

        up = [[1] * LOG for _ in range(q + 2)]
        dist_up = [[0] * LOG for _ in range(q + 2)]
        depth = [0] * (q + 2)
        color = [0] * (q + 2)

        color[1] = C

        rep = {}  # color -> list of up to 2 nodes
        rep[C] = [1]

        answer = 0

        for _ in range(q):
            tmp = list(map(int, input().split()))

            if tmp[0] == 0:
                _, x, c, d = tmp
                n += 1

                up[n][0] = x
                dist_up[n][0] = d
                depth[n] = depth[x] + d

                for i in range(1, LOG):
                    up[n][i] = up[up[n][i - 1]][i - 1]
                    dist_up[n][i] = dist_up[n][i - 1] + dist_up[up[n][i - 1]][i - 1]

                color[n] = c

                if c not in rep:
                    rep[c] = [n]
                else:
                    rep[c] = update_color_rep(rep[c], n, depth, up, dist_up)

            else:
                _, x, c = tmp
                old = color[x]
                color[x] = c

                if old in rep:
                    rep[old] = update_color_rep(rep[old], None, depth, up, dist_up)
                    if len(rep[old]) == 0:
                        del rep[old]

                if c not in rep:
                    rep[c] = [x]
                else:
                    rep[c] = update_color_rep(rep[c], x, depth, up, dist_up)

            nodes = []
            for lst in rep.values():
                nodes.extend(lst)

            answer = 0
            for i in range(len(nodes)):
                for j in range(i + 1, len(nodes)):
                    if color[nodes[i]] != color[nodes[j]]:
                        answer = max(answer, dist(nodes[i], nodes[j], depth, up, dist_up))

            print(answer)

if __name__ == "__main__":
    main()
```この実装では、ノードが追加されるにつれてバイナリ リフティング テーブルが段階的に構築されるため、LCA クエリと距離の計算はツリー サイズで対数になります。 各色は、その直径の端点に近似する最大 2 つの代表的なノードを維持します。 すべての操作の後、アルゴリズムは代表者の小さな結合から答えを再計算し、交差色のペアのみをチェックします。 

微妙な点は、色の削除に関する更新が代表を再評価することによって処理されることです。これは、各色クラスがその現在の極端なノードを通じてのみ要約されるため、これで十分です。 もう 1 つの繊細な点は、新しいノードに関係する距離クエリの前に、深さとバイナリ リフティング テーブルが挿入直後に更新されるようにすることです。

 | 2 | ノード 3 (色 2) を追加 | {1:[1,2]、2:[3]} | 1、2、3 | 最大(1-3,2-3)=8 |

 ## 特殊なケース

 重大なエッジ ケースは、ノードが 2 つの主要なカラー クラス間でカラーを繰り返し変更する場合です。 この状況では、完全に異なるエンドポイント間で最適なペアが変動する可能性があるため、単純にキャッシュされたベスト ペアのアプローチは失敗します。 代表ベースのアプローチでは、境界のある極値セット内でのみ再計算することでこれに対処します。そのため、各再色付けでは、古い大域的最大値に依存するのではなく、単純に候補を再評価します。 

もう 1 つのケースは、木が退化して道になる場合です。 ここでは、挿入するたびに直径が拡張され、正しい答えは常にパスの端のいずれかにあります。 各色の代表にはその極値ノードが含まれるため、アルゴリズムはすべてのノードをスキャンしなくても、正しい色のクロスエンドポイントを捕捉します。
