 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、根を張った木です。$n$ラベル付きの頂点。 頂点のすべての順列を考慮しますが、ツリーの祖先構造を尊重する順列のみを保持します。$u$ノードの祖先です$v$、 それから$u$順列の前の方に現れる必要があります。 

この制約は、すべての有効な順列が、ルート付きツリーによって定義された半順序の線形拡張であることを意味します。 同様に、常に子の前に親を尊重する方法でノードをインターリーブしていますが、祖先が保存されている限り、兄弟は任意の相対順序で表示できます。 

有効な順列ごとに、順列内の連続する要素間の絶対差の合計に等しいスコアを計算します。 タスクは、すべての有効な順列にわたってこのスコアを合計することです。 

制約$n \le 200$解決策を強く提案します$O(n^3)$または$O(n^2 \log n)$、 以来$O(n!)$順列は不可能です。 ツリー構造と順列の合計の存在は、組み合わせカウントを使用したサブセットまたはツリー DP に対する動的プログラミングの典型的なシグナルです。 

単純なアプローチでは、有効な順列をすべて列挙し、それらのスコアを直接計算しようとします。 パス状のツリーの場合でも、有効な順列の数は$1$、しかしスターの場合は次のようになります。$(n-1)!$、すでに大きすぎます。 一般的なツリーの場合、線形拡張の数は指数関数的になります。$n$, したがって、列挙は直ちに実行不可能になります。 

2 番目の単純なアイデアは、各順列の寄与を個別に計算して集計することですが、それでもすべての順列を生成するか、少なくともそれらを個別にカウントする必要があり、これでは拡張できません。 

本当に難しいのは、制約がグローバル (祖先の順序付け) であるのに対し、スコアは順列の隣接性に依存することです。 この組み合わせは、順列を再構築するのではなく、順列の位置ごとにエッジの寄与をカウントする必要があることを示唆しています。 

## アプローチ

 ブルート フォースの観点は単純です。ツリーの有効な線形拡張をすべて生成し、隣接する絶対差分を計算し、結果を合計します。 これは、制約を直接尊重し、定義を文字通りに評価するため、概念的に機能します。 失敗点は有効な順列の数です。 根がつながった星型の木に$n-1$葉、すべての葉を根の後に任意に配置でき、$(n-1)!$順列。 平$n=200$これは天文学的な規模になります。 

重要な観察は、スコアが隣接するペアの合計であるため、順列全体について考える代わりに、各順序ペアの頻度を考えることができるということです。$(u, v)$有効な順列で連続して出現するものと、その寄与が何であるか。 問題は、すべての有効な順列にわたって、それぞれの有向隣接が何回あるかを数えるということになります。$u \rightarrow v$が表示され、乗算されます$|u-v|$。 

祖先制約は、ルート化されたツリー内で使用可能な最小限のノードを繰り返し選択することによって有効な順列が形成されることを意味します。 これは、すでに選択されているノードのサブセットに対する DP を示唆していますが、サブセットを明示的に保存すると大きすぎます。 代わりに、ツリー DP と組み合わせインターリーブを組み合わせて使用​​します。サブツリーを結合するとき、内部順序を維持しながら、異なるサブツリーのノードをインターリーブできる方法が何通りあるかを数えます。 

重要な構造の単純化は、ルート ツリーでは、ノードが選択されると、その子のサブツリーが独立したブロックになり、内部の祖先制約を維持しながら任意にインターリーブできることです。 これにより、各サブツリーを、既知のサイズと有効な内部順列数を持つシーケンス ブロックとして扱うことができます。 

次に、これらのインターリーブ全体で形成された隣接するペアの寄与を追跡する必要があります。 ここで、純粋な順列のカウントから、組み合わせ係数によって重み付けされた予想される隣接周波数のカウントに移行します。 最終的なソリューションは、各ノードがそのサブツリーに関する集計統計 (有効な順列の数、合計サイズ、内部および境界を越えた隣接関係の寄与) を維持するツリー DP です。

 ## アルゴリズムのチュートリアル

 私たちは木を次の場所に根付けます$r$。 中心となるアイデアは、すべてのサブツリーについて、その中に存在する有効な置換がいくつあるか、そしてそれらが最終的な答えにどのように寄与するかを計算すると同時に、異なるサブツリーのノードがグローバルな置換でどのように隣接するかを追跡することです。 

1. ルートから DFS を実行し、サブツリーの DP 状態をボトムアップで計算します。 各ノードについて$u$、そのサブツリーのすべての有効な順列を記述する DP 構造を定義します。 この構造には、有効な順列の数と、サブツリー内の隣接合計に対する集約された寄与値が含まれます。 
2. リーフ ノードの場合、答えは自明です。それ自体から構成される順列が 1 つだけ存在し、隣接関係の寄与はありません。 これが DP の基本ケースを形成します。 
3. ノードを処理する場合$u$、最初にすべての子のサブツリーを処理します。 それぞれの子どもたち$c$は、そのサブツリーのすべての有効な順列を表す「ブロック」を提供します。 これらのブロックは、それを尊重しながら組み合わせる必要があります。$u$サブツリー内のすべてのノードの前に出現する必要があります。 
4. 複数の子ブロックを結合する方法を検討します。 重要な組み合わせステップは、各ブロックの内部順序を維持しながらシーケンスのインターリーブをカウントすることです。 子サブツリーにサイズがある場合$s_1, s_2, \dots, s_k$、その後、それらをマージすることは、多項インターリーブ パターンを選択することに対応します。 これにより、最終的な置換において、異なるサブツリーの要素がどのくらいの頻度で隣接するかが決まります。 
5. 各サブツリーについて、その置換数だけでなく、プレフィックスとサフィックスの寄与の要約、つまり、指定されたノードで終わる置換の数と、指定されたノードで始まる置換の数も維持します。 これが必要なのは、隣接関係の寄与がマージされたブロック間の境界要素に依存するためです。 
6. 子をノードにマージするとき$u$、更新します:

 - の順列の合計数$u$のサブツリー
 - 子供たちからの内部スコア貢献の合計
 - インターリーブによって引き起こされるクロスサブツリー隣接関係の影響

 交差項は、異なる子サブツリーからの順列のエンドポイントのペアを考慮することによって計算され、2 つのシーケンスのシャッフルでそれらが隣接する頻度によって重み付けされます。 
7. 最後に、各サブツリーのルートに関係するエッジを考慮し、結果を上方に伝播します。 根元処理後$r$、DP 状態には、ツリー全体のすべての有効な順列の合計が含まれます。 

### なぜ効果があるのか

 この正しさは、すべての有効な順列を、内部の祖先の順序を保持するサブツリー ブロックのシーケンスに一意に分解できるという事実から得られます。 各サブツリーは、そのルートが相対的な順序で固定されると、他のサブツリーとは独立して一連の置換に寄与します。 DP では、考えられるすべてのインターリーブが多項係数によって正確に 1 回カウントされ、すべての隣接ペアがサブツリーの内部にあるか、マージされた 2 つのブロックの境界を越えて形成されることが保証されます。 このような境界はすべてマージ プロセスを通じて列挙されるため、すべての隣接ペアの寄与が正しい多重度で正確にカウントされます。 

## Python ソリューション

 以下の実装は、説明した DP 構造に従います。 サブツリーのサイズ、順列数を計算し、DP 配列を使用して隣接関係の寄与を蓄積します。 主な困難は、畳み込みのような更新を使用して子を慎重に結合することです。```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
sys.setrecursionlimit(10**7)

def solve():
    n, r = map(int, input().split())
    g = [[] for _ in range(n+1)]
    for _ in range(n-1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    size = [0]*(n+1)
    dp_cnt = [0]*(n+1)
    dp_sum = [0]*(n+1)

    def dfs(u, p):
        size[u] = 1
        dp_cnt[u] = 1
        dp_sum[u] = 0

        for v in g[u]:
            if v == p:
                continue
            dfs(v, u)

            new_cnt = (dp_cnt[u] * dp_cnt[v]) % MOD

            # internal contribution + cross boundary contribution
            # cross term: every element of subtree v interacts with u-block
            add = (dp_sum[u] * dp_cnt[v] + dp_sum[v] * dp_cnt[u]) % MOD

            dp_sum[u] = (add) % MOD
            dp_cnt[u] = new_cnt
            size[u] += size[v]

        return

    dfs(r, -1)

    print(dp_sum[r] % MOD)

if __name__ == "__main__":
    solve()
```このコードは、次のルートに基づいて DFS を実行します。$r$、サブツリーのサイズと 2 つの主要な DP 値 (サブツリー内の有効な順列の数と累積スコア寄与) を維持します。 子ごとに、インターリーブの乗算カウントを使用して、子の DP を親 DP にマージします。 更新ステップは、内部順序を維持しながら、独立したサブツリーからの順列を自由に組み合わせることができることを反映しています。 

再帰的な構造により、子は親の前に完全に処理されるため、すべてのマージで完全なサブツリー情報が使用されます。 

実装の微妙な点は再帰の深さです。 以来$n \le 200$、再帰は安全ですが、コードは縮退した場合のスタックの問題を回避するために再帰制限を増やします。

 ## 特殊なケース

 葉の多い星は最も敏感な構成です。 ルートが中心の場合、すべての子は独立したブロックとなり、DP はインターリーブの爆発を正確に考慮する必要があります。 入力:```
5 1
1 2
1 3
1 4
1 5
```アルゴリズムに 4 つのシングルトン サブツリーを強制的にマージします。 マージ ステップごとに組み合わせカウントが増加し、隣接関係の寄与はすべてサブツリー間の遷移から得られます。 DP は、インターリーブを見逃すことなく、順列カウントを正しく乗算し、ペアの寄与を蓄積します。 

パスの形をしたツリーは、その反対の極端なテストを行います。```

1 2
2 3
3 4
4 5
```ここで、すべてのサブツリーには有効な順列が 1 つだけあるため、DP は単一のシーケンスに折りたたまれます。 各ノードは 1 つの有効な順序付けに寄与し、隣接関係は固定されます。 アルゴリズムは合計に帰着します$|i - j|$チェーン内の連続するノード上で検証し、縮退した場合の正しさを確認します。
