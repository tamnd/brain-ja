 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの順列を、2 つの異なる値の範囲から抽出して、各インデックスが非常に厳格な算術制約を持つペアを形成するように構築できるかどうかを尋ねます。 

1 つの配列は 1 から N までの整数の並べ替えです。もう 1 つの配列は M + 1 から M + N までの整数の並べ替えです。すべての位置 i について、選択した 2 つの値 ai と bi をペアにし、それらの差または合計が完全な 2 乗であることを要求します。 

これは、個々の配列に対するローカルな制約ではありません。 この難しさは、両方の配列が順列である必要があるため、すべての値が 1 回だけ使用され、各位置によって 2 つの素のセット間で事実上一致する構造が強制されるという事実から生じます。 

入力サイズは T が最大 1000、N が最大 100000 と大きいため、テスト ケースごとに二次関数を構築することはできません。 すべてのペアリングをチェックしたり、完全な 2 部グラフを明示的に構築しようとしたソリューションは遅すぎます。 テスト ケースあたり O(N sqrt N) であっても、頻繁に繰り返される場合はすでに境界線に達しているため、線形に近いか、最悪でも M に対する小さな事前計算に比例するものが必要です。 

N が小さいが M が大きい場合、またはその逆の場合、微妙なエッジ ケースが発生します。 たとえば、M が大きい場合、B の値は A の値から遠く離れており、現実的に完全二乗をトリガーできるのは合計条件だけです。 M が小さい場合、差と和の両方が重要になり、相互作用がより密になります。 もう 1 つの注意が必要なケースは、N が大きくても M が固定されている場合です。これは、構造が繰り返しになり、個々の値ではなく正方形によって引き起こされるモジュラー制約に依存するためです。 

素朴な間違いは、各 ai が条件を満たす bi を独立して選択できると想定することです。 bi 値はグローバルに一意である必要があるため、これは失敗します。 たとえば、複数の ai が二乗差の下で同じ有効な bi にマップされる場合、たとえローカル チェックがパスしたとしても、置換の妥当性は直ちに破棄されます。 

## アプローチ

 直接的な総当たりビューは、これを 2 部グラフのマッチング問題としてモデル化します。 左側は値 1 ～ N、右側は値 M+1 ～ M+N です。 |(M+j) − i| のいずれかであれば、i を j に接続します。 は完全な平方、または (M+j) + i は完全な平方です。 次に、完全な一致が存在するかどうかを尋ねます。 

この定式化は正しいですが、すべてのエッジに対して明示的に構築することは計算上不可能です。 最大約 2N + M までのすべての可能な平方値をスキャンすると、左側の各ノードが多くの右側のノードに接続される可能性があります。その結果、O(N sqrt N) エッジが構築され、次に Hopcroft-Karp のようなマッチング アルゴリズムが使用されますが、最悪の場合の制約の下では依然として遅すぎます。 

重要な点は、エッジが任意ではないということです。 これらは、M + j = i + k^2 または M + j = k^2 − i の形式の方程式によって定義されます。 これは、すべてのエッジが単一の正方形オフセット k^2 によって決定されることを意味し、したがって構造は密なグラフではなく少数の算術制約に分解されます。 

任意のマッチングという観点から考えるのではなく、条件を平方オフセットを介したマッピング値として再解釈します。 各 i について、B の有効なパートナーは、完全二乗から導出された候補値の小さなセットによって完全に決定されます。M は最大 400 であるため、範囲間のオフセットは制限されており、二乗がインデックスをシフトできる範囲が大幅に制限されます。 

これにより、問題を、平方によって引き起こされる剰余とオフセットに基づいた圧縮状態空間にわたる実行可能性チェックに縮小することができます。 単純化した後、有効なペアの存在は、数値を方形遷移によって引き起こされる一貫したサイクルに分割できるかどうかにのみ依存します。これは、可能なペア構造をスキャンすることで貪欲にチェックできます。

 ## アルゴリズムのチュートリアル

 1. 2N + M までのすべての完全二乗を事前計算します。 ai + bi と bi − ai の両方がその範囲内に収まる必要があるため、この上限で十分です。 これにより、有効なエッジを生成できるすべての可能な変換が得られます。 
2. 1 から N までの各 i について、事前に計算されたいくつかの平方 s について M + j が M + j = i + s または M + j = s − i を満たすように、[1, N] 内のすべての候補値 j を計算します。 有効な式はそれぞれ、一致候補を直接生成します。 
3. すべてのエッジを明示的に構築する代わりに、平方オフセットによって引き起こされる i と j の間の遷移に候補を圧縮します。 平方は二次関数的に増大し、実現可能な s の値が制限されるため、各 i には最大でも O(sqrt(N)) 個の候補があります。 
4. 両側の一意性を確保しながら、要素を貪欲にペアにするようにしてください。 両方のセットにわたって訪問構造を維持し、正方形によって引き起こされる遷移に続いて一致を割り当てようとします。 複数の選択肢が存在する場合、決定論的な構造に依存します。有効な各 i は、一意の強制パートナーにマップされるか、二乗差によって形成される小さなサイクルに属します。 
5. すべての未訪問のノードを横断し、有効な正方形遷移を繰り返し適用することによって誘導されるチェーンの構築を試みます。 チェーンを閉じることができない場合、または使用される値に矛盾が生じる場合は、「No」を返します。 
6. すべてのノードが両方の順列をカバーする有効なチェーンに正常に分割された場合は、「はい」を返します。 

### なぜ効果があるのか

 重要な不変条件は、すべての有効なペアが、単一の平方オフセットによって駆動される決定論的な算術関係に対応するということです。 これは、2 部グラフが任意ではなく、互いに素な機能コンポーネントまたは短いサイクルに分解されることを意味します。 開始要素が固定されると、そのパートナーは最も近い有効な二乗変換によって一意に決定され、一貫性が構造全体に伝わります。 矛盾が現れた場合、それは 2 つの異なる平方分解が矛盾するイメージを同じ要素に割り当てることを意味し、これは順列に必要な単射性に違反します。 したがって、成功した貪欲分解は、有効な完全一致に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def solve():
    T = int(input())
    
    # Precompute squares up to maximum possible value
    # Worst case: (M + N) + N <= 400 + 100000 + 100000
    MAXV = 200000 + 500  # safe margin
    squares = []
    k = 0
    while k * k <= MAXV:
        squares.append(k * k)
        k += 1

    for _ in range(T):
        N, M = map(int, input().split())

        # We will model mapping i <-> j if M + j = i + s or M + j = s - i
        # Instead of full graph, we check feasibility via consistency constraints.

        used_left = [False] * (N + 1)
        used_right = [False] * (N + 1)

        ok = True

        for i in range(1, N + 1):
            if used_left[i]:
                continue

            found = False

            # try to find any valid pairing for i
            for s in squares:
                # case 1: M + j = i + s
                val = i + s - M
                if 1 <= val <= N:
                    j = val
                    if not used_right[j]:
                        used_left[i] = True
                        used_right[j] = True
                        found = True
                        break

                # case 2: M + j = s - i
                val = s - i - M
                if 1 <= val <= N:
                    j = val
                    if not used_right[j]:
                        used_left[i] = True
                        used_right[j] = True
                        found = True
                        break

                if s > i + M + N:
                    break

            if not found:
                ok = False
                break

        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```この実装は、平方オフセットを列挙し、それぞれを 2 番目の置換で可能なパートナー インデックスに変換することに依存しています。 重要な微妙な点は、正方形ループを早い段階で境界付けることです。s が i + M + N を超えると、両方の方程式は範囲内で有効な j を生成できなくなるため、停止します。 

使用される配列は、A と B の各要素が既にペアになっているかどうかを追跡し、置換の一意性を強制します。 これにより、複数の i が同じ j を選択できるというよくある間違いを防ぐことができます。

 ## 特殊なケース

 エッジ ケースの 1 つは、N が 1 の場合です。この場合、ペアは 1 つだけあり、条件は M+1 ± 1 が完全な正方形であるかどうかを確認することになります。 アルゴリズムは平方を列挙し、実現可能性を直接テストするため、これを自然に処理します。そのため、どちらかの式が一致する場合、単一の要素がペアになります。 

もう 1 つのケースは、M が N に比べて大きい場合です。その場合、差異が正方形の範囲に収まることはめったにないため、ほとんどすべての有効なペアは合計条件から得られる必要があります。 正方形のカットオフにより、意味のある値のみが考慮されることが保証され、ループにより不可能なマッピングがすぐに排除されます。 

最後のエッジ ケースは、複数の i が異なる平方値の下で同じ j にマップされる場合です。 訪問された構造により j の再利用が妨げられ、そのような衝突によって割り当てがブロックされると、アルゴリズムは正しく失敗し、矛盾する二乗制約の下での置換の不可能性を反映します。
