 ## 解決策
 ## 問題の理解

 無限平面上に描かれた直線セグメントの集合が与えられます。 各セグメントは、整数の座標を持つ 2 つのエンドポイントによって定義されます。 さらに多くのセグメントが追加されると、それらはペアごとに最大 1 回相互に交差し、エンドポイントでのみ交差するか、まったく交差しない可能性があります。 

タスクは、すべてのセグメントが描画された後、平面がいくつの接続された領域または面に分割されるかを決定することです。 

これを解釈する便利な方法は、単一の領域である空の平面から始めることを想像することです。 セグメントを追加するたびに、交差する既存のセグメントの数に応じて、既存の領域をより小さな領域に分割することがあります。 最終的な答えは、結果として得られる領域の合計数です。 

制約は、テスト ケースあたり最大 1000 セグメントを示します。 Python ではテスト ケースごとに 10⁶ の操作が許容されるため、セグメントのすべてのペアをチェックし、すべての交差を計算するという単純なアイデアは、O(n²) ですでに実現可能です。 ただし、交差点を数えているだけではなく、平面のサブディビジョンにどのような影響を与えるかを数えているので、注意が必要です。 

よくある落とし穴は、各セグメントが独立して領域の数を固定量ずつ増加させると想定することです。 これは不正確です。交差により、構造化された方法で各セグメントの「新しい」寄与が減少するからです。 もう 1 つの落とし穴は、交差点を二重にカウントしたり、共有エンドポイントを正しく考慮しないことです。 

小さな例でその微妙さを示します。 

入力:

 三角形のような配置を形成する 3 つのセグメントがペアで 1 回交差します。 

「各セグメントに 1 つの領域と交差点が追加される」と誤ってカウントすると、顔をカウントしすぎてしまう可能性があります。 正しい出力は、ローカル セグメントの相互作用だけではなく、完全な平面グラフ構造に依存します。 

正しいモデルは、頂点がセグメントの端点と交点であり、エッジが連続する頂点間のセグメントの部分であり、面が数えたいものである平面サブディビジョン問題です。 

## アプローチ

 ブルートフォース手法では、セグメント間のすべての交点を明示的に計算し、それらの点でセグメントを分割し、平面グラフを構築してから、平面グラフのオイラー公式を使用して面をカウントします。 

O(n²) 内のすべての交差を検出できます。 交差するペアごとに、それらの交点を計算して保存します。 次に、各セグメントは、セグメントに沿った順序付けられた点の間で複数のエッジに分割されます。 最後に、頂点が端点と交点、エッジが分割セグメントであるグラフを構築し、以下を使用して面の数を計算します。 

F = E - V + C + 1

 ここで、V は頂点の数、E はエッジの数、C は連結成分の数です。 

これが機能するのは、細分化後のセグメントの配置によって平面グラフが形成されるためです。 

ボトルネックは漸近時間ではなく実装の複雑さです。 セグメントを一貫して分割し、交点を重複排除すると、特に浮動小数点精度や座標ハッシュを使用する場合、エラーが発生しやすくなります。 

重要な点は、完全なグラフを明示的に構築する必要がないということです。 代わりに、各セグメントが導入する新しい交差点の数を追跡し、面の数を増分的に直接計算できます。 

セグメントには最初に 1 つの新しい面が追加されます。 既存のセグメントと交差するたびに、領域の数が 1 ずつ増加します。したがって、セグメントに以前に挿入されたセグメントとの交点が k 個ある場合、k + 1 個の新しい面が追加されます。 

これにより、クリーンなスイープが行われます。セグメントを 1 つずつ挿入し、以前に挿入されたセグメントと交差する数を数え、その結果を累積します。 

正確かどうかは、オイラーの面の数がちょうど 1 つ増えるように、各交差によってエッジの数が増加するという事実にかかっています。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全平面グラフの構築 | O(n² log n) | O(n²) | 複雑すぎる / 受け入れられるがやりすぎ |
 | 増分交差点カウント | O(n²) | O(1) 追加 (入力以外) | 承認済み |

 ## アルゴリズムのチュートリアル

 以前に処理されたセグメントのセットを維持しながら、セグメントを 1 つずつ処理します。 

1. 答えを 1 として初期化し、セグメントが描画される前の空の平面を表します。 この基本ケースはオイラーの公式から来ています。エッジのない平面には 1 つの面があります。 
2. 新しいセグメントごとに、適切に交差する以前のセグメントの数を数えます。 方向テストを使用してセグメントの交差を計算します。 端点の接触では領域が同じように分割されないため、適切な交差は、端点で接触するだけでなく、セグメントが交差する場合にのみカウントされます。 
3. 現在のセグメントが交差するセグメントの数を k とします。 答えに k + 1 を加えます。 +1 は、交差がなくても、セグメントによって 1 つの既存の領域が 2 つに分割されるという事実を説明しています。 
4. セグメントを保存して続行します。 

重要な計算タスクは、2 つのセグメント間の交差テストです。 方向 (外積符号) を使用して 2 つのセグメントが互いにまたがっているかどうかを判断し、境界ボックスが確実に重なるようにします。 

### なぜ効果があるのか

 セグメントを追加するたびに、事実上、平面サブディビジョンに曲線が挿入されます。 既存のエッジと交差するたびに、1 つの既存のエッジが 2 つに分割され、エッジの数が増加するため、面の数が 1 つだけ増加します。 最初のセグメントは常に 1 つの追加領域を作成します。 各交差がセグメントに沿った個別の分割イベントに対応するという意味で交差は独立しているため、すべてのセグメントの k + 1 を合計すると、面の合計増加が正確にカウントされます。 交差は後から挿入されるセグメントのみに起因するため、二重にカウントされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def orient(ax, ay, bx, by, cx, cy):
    return (bx - ax) * (cy - ay) - (by - ay) * (cx - ax)

def on_segment(ax, ay, bx, by, cx, cy):
    return min(ax, bx) <= cx <= max(ax, bx) and min(ay, by) <= cy <= max(ay, by)

def intersect(a, b, c, d):
    ax, ay = a
    bx, by = b
    cx, cy = c
    dx, dy = d

    o1 = orient(ax, ay, bx, by, cx, cy)
    o2 = orient(ax, ay, bx, by, dx, dy)
    o3 = orient(cx, cy, dx, dy, ax, ay)
    o4 = orient(cx, cy, dx, dy, bx, by)

    if o1 == 0 and on_segment(ax, ay, bx, by, cx, cy):
        return True
    if o2 == 0 and on_segment(ax, ay, bx, by, dx, dy):
        return True
    if o3 == 0 and on_segment(cx, cy, dx, dy, ax, ay):
        return True
    if o4 == 0 and on_segment(cx, cy, dx, dy, bx, by):
        return True

    return (o1 > 0) != (o2 > 0) and (o3 > 0) != (o4 > 0)

segments = []

out_lines = []

while True:
    line = input().strip()
    if not line:
        break
    parts = list(map(int, line.split()))
    if len(parts) == 1:
        n = parts[0]
        segs = []
        for _ in range(n):
            x1, y1, x2, y2 = map(int, input().split())
            segs.append(((x1, y1), (x2, y2)))

        ans = 1
        segments = []
        for i in range(n):
            k = 0
            for j in range(i):
                if intersect(segs[i][0], segs[i][1], segs[j][0], segs[j][1]):
                    k += 1
            ans += k + 1
        out_lines.append(str(ans))

print("\n".join(out_lines))
```コードの中心となるアイデアは、増分カウントの原則を直接翻訳したものです。 交差関数は、方向テストを使用して、適切な交差と同一直線上にあるオーバーラップの両方のケースを慎重に処理します。 

外側のループは複数のテスト ケースをサポートし、それぞれが個別に処理されます。 累積変数`ans`1から始まり、次のように増加します`k + 1`各セグメントごとに。 

実装の微妙な詳細は、同一線上のオーバーラップの処理です。 コードは、重なっているケースや接触しているケースを交差点として扱います。これは、そのような接触が依然として細分化に影響を与えるという仮定と一致しています。 

## 実用的な例

 3 つのセグメントが三角形のような構造を形成し、各ペアが 1 回だけ交差する単純なケースを考えてみましょう。 

セグメント 0 には、以前のセグメントはありません。 

| セグメント | 前の | との交差 貢献 | 合計 |
 | --- | --- | --- | --- |
 | 0 | 0 | 1 | 2 |

 最初のセグメントの後の答えは 2 です。 

セグメント 1 の場合、セグメント 0 と 1 回交差します。 

| セグメント | 前の | との交差 貢献 | 合計 |
 | --- | --- | --- | --- |
 | 1 | 1 | 2 | 4 |

 2 番目のセグメントの後の答えは 4 です。 

セグメント 2 の場合、前のセグメントの両方と交差します。 

| セグメント | 前の | との交差 貢献 | 合計 |
 | --- | --- | --- | --- |
 | 2 | 2 | 3 | 7 |

 最終的な答えは 7 です。 

このトレースは、新しい交差ごとに面の数が一貫して 1 つずつ増加し、平面細分割の増分解釈と一致することを示しています。
