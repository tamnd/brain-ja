 ## 解決策
 ## 問題の理解

 私たちは道路で結ばれた都市のネットワークを与えられており、その構造は木を形成しています。 どの都市にも複数の ACMers が含まれている可能性があり、各人は 1 つの都市で開催される集会に参加したいと考えています。 個人の移動コストは、ツリー内の固有のパスに沿って、自分の都市から選択した会議の都市までの距離です。 

目標は、全員の移動距離の合計が最小限になるように、集合場所として 1 つの都市を選択することです。 複数の人が同じ都市に住むことができるため、各都市はその人口の重みを距離の計算に効果的に寄与します。 

出力は、最適な会議都市のインデックスと、距離の最小可能な加重合計です。 

制約は非常に具体的な意味で重要です。 テストごとに最大 10,000 の都市があり、テストは最大 10 個あるため、合計で最大約 100,000 のノードが表示される可能性があります。 候補都市ごとに距離を最初から再計算するソリューションでは、ノードごとに完全なツリー トラバーサルを実行する必要があり、最悪の場合、テストごとにおよそ O(n^2) の操作が必要になります。 それは遅すぎます。 

素朴な解決策を打ち破ることが多い微妙な問題は、重みを考慮せずに距離を誤って再計算することです。 たとえば、各都市を AI の人々ではなく 1 人の人間として扱うと、間違った目的が与えられます。 もう 1 つの問題は、ルートごとの BFS による最短パスの再計算が機能することを想定していることです。これは正しいですが、大規模にすると遅すぎます。 

小さな失敗例としては、ライン ツリーが挙げられます。 BFS を使用してすべてのノードからの距離を再計算するとします。 これは論理的には正しいですが、O(n^2) になります。 n = 10000 の場合、これはテストごとにすでに約 1 億回のエッジ緩和であり、Python の制約の下では境界線か、それよりも悪い値です。 

## アプローチ

 この強引なアイデアは簡単です。すべての都市について、それを集合場所として扱い、他のすべての都市までの加重距離の合計を計算します。 これは、各候補ノードからの DFS または BFS を使用して実行でき、距離と人口を累積します。 これは正しいです。ツリーによって任意の 2 つのノード間の一意のパスが保証され、最短パスが明確に定義されるからです。 

問題はパフォーマンスです。 各走査のコストは O(n) で、すべてのルート候補に対してそれを繰り返すと、O(n^2) になります。 最大 10000 ノードでは、これは遅すぎます。 

重要な洞察は、ルートごとにすべてを最初から再計算する必要がないということです。 エッジを越えてミーティング ポイントを移動すると、そのエッジの一方の側からの寄与だけが増加し、もう一方の側からの寄与は減少します。 これは、ツリー上で動的プログラミングのアプローチを再ルートすることを示唆しています。 

まず、ルートがノード 1 に固定されている場合のコストを計算します。次に、この情報をエッジ全体に伝播します。 重み w のエッジを越えてルートを u から v に移動すると、v のサブツリー内のすべてのノードは w だけ近くなり、外側のすべてのノードは w だけ遠くなります。 この変化は、事前に計算できるサブツリーの人口にのみ依存します。 

これにより、問題は 2 つの DFS パスに変換されます。1 つは人口と初期コストで重み付けされたサブツリー サイズを計算するパス、もう 1 つはエッジあたり O(1) でリルートして答えを更新するパスです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | DP を再ルートする | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 人口をノードに付加された重みとして扱い、ツリー上で再ルート動的プログラミングを実行します。 

### ステップ

1. ノード 1 でツリーをルートし、隣接リストを構築します。 これは単なる参照点です。 どのルートでも機能しますが、ルートを 1 つ修正すると計算が簡素化されます。 
2. DFS を実行して、ノードごとに 2 つのことを計算します。サブツリー内の総人口と、ノード 1 がミーティング ポイントである場合の初期コストです。 再帰から戻るときに、サブツリーの人口を上向きに集計します。 これは、後のリルート遷移が各サブツリーに何人の人がいるかによって決まるため、必要です。 
3. 同じ DFS 中に、子からの寄与を追加してコストを累積します。子 v が u から距離 w にある場合、u がルートのとき、すべての a[v] 人がコストに w より多く寄与します。 
4. ノード 1 で初期コストを計算した後、2 番目の DFS を実行してツリーを再ルートします。 重み w のエッジを介してルートを u から子 v に移動するとき、距離がどのように変化するかから導出される直接式を使用してコストを更新します。 

v のサブツリー内のノードは w だけ近くなり、総人口に比例して減少に寄与しますが、他のすべてのノードは w だけ遠くなります。 
5. 再ルート中も最適な回答を維持します。 複数のノードが同じ最小コストを達成する場合は、最小のインデックスを選択します。 

### なぜ効果があるのか

 重要な不変条件は、再ルート中のすべてのノード u で、u がルートであると仮定して正しい合計加重距離を維持することです。 すべてのノードが子のサブツリー内または子サブツリーの外にあり、両方のグループが反対方向にちょうど w の均一な距離変化を経験するため、親と子の間の遷移は正確です。 サブツリーの母集団の合計は正確であるため、コストの更新も正確であり、ノードが二重にカウントされたり欠落したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        a = [0] + list(map(int, input().split()))

        g = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v, w = map(int, input().split())
            g[u].append((v, w))
            g[v].append((u, w))

        sub = [0] * (n + 1)
        cost0 = 0

        def dfs1(u, p):
            nonlocal cost0
            sub[u] = a[u]
            for v, w in g[u]:
                if v == p:
                    continue
                dfs1(v, u)
                sub[u] += sub[v]
                cost0 += sub[v] * w

        dfs1(1, -1)

        ans_node = 1
        ans_cost = cost0

        def dfs2(u, p, cur):
            nonlocal ans_node, ans_cost
            if cur < ans_cost or (cur == ans_cost and u < ans_node):
                ans_cost = cur
                ans_node = u

            for v, w in g[u]:
                if v == p:
                    continue
                # reroot from u -> v
                nxt = cur + (sub[1] - 2 * sub[v]) * w
                dfs2(v, u, nxt)

        dfs2(1, -1, cost0)

        print(ans_node, ans_cost)

if __name__ == "__main__":
    solve()
```最初の DFS はサブツリーの母集団を計算し、ノード 1 が選択された場合のコストも計算します。 微妙な点は、子サブツリーの処理が完了するたびに、`sub[v] * w`これは、そのサブツリー内のすべての人々が親よりもルート 1 から正確に w 離れていることに対応します。 

2 番目の DFS は再ルートを実行します。 移行式`cur + (total_population - 2 * sub[v]) * w`正確なシフトをキャプチャします。サブツリー v 内のノードが w だけ近くなり、`sub[v] * w`、他のすべてのノードは w だけ遠くなり、`(total_population - sub[v]) * w`。 

同点の場合、問題では最適な解の中で辞書編集的に最小限の解が必要となるため、最良のコストと最小のインデックスの両方を追跡します。

これにより、リルートによって対称的な距離の変化が正しくキャプチャされることが確認されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テストあたり O(n) | 各エッジは各 DFS で 1 回処理され、ツリー全体を線形に走査します。 
| スペース | O(n) | 隣接リスト、サブツリー配列、再帰スタック |

 テスト全体のノードの総数には制限があるため、ソリューションは制限内に問題なく収まります。 各操作は定数時間の算術更新であるため、n = 10000 の場合でも効率的です。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf

    input = sys.stdin.readline

    def solve():
        T = int(input())
        for _ in range(T):
            n = int(input())
            a = [0] + list(map(int, input().split()))
            g = [[] for _ in range(n + 1)]
            for _ in range(n - 1):
                u, v, w = map(int, input().split())
                g[u].append((v, w))
                g[v].append((u, w))

            sub = [0] * (n + 1)
            cost0 = 0

            def dfs1(u, p):
                nonlocal cost0
                sub[u] = a[u]
                for v, w in g[u]:
                    if v == p:
                        continue
                    dfs1(v, u)
                    sub[u] += sub[v]
                    cost0 += sub[v] * w

            dfs1(1, -1)

            total = sub[1]
            ans_node, ans_cost = 1, cost0

            def dfs2(u, p, cur):
                nonlocal ans_node, ans_cost
                if cur < ans_cost or (cur == ans_cost and u < ans_node):
                    ans_node, ans_cost = u, cur
                for v, w in g[u]:
                    if v == p:
                        continue
                    nxt = cur + (total - 2 * sub[v]) * w
                    dfs2(v, u, nxt)

            dfs2(1, -1, cost0)
            return ans_node, ans_cost

        return solve()

""") == (2, 34), "sample"

    # chain

 ## 特殊なケース

 重要なエッジケースは、すべての都市の人口が等しいにもかかわらず、ツリーが大きく偏っている場合です。 その場合、最適なノードは重心のようなバランス点です。 サブツリーの合計が不均衡を正しく反映しているため、再ルート式は引き続き機能します。 

もう 1 つのエッジ ケースは、単一ノード ツリーです。 最初の DFS はコスト 0 を計算し、再ルートしても何も変わりません。 アルゴリズムはノード 1 を正しく出力します。 

最後のエッジケースは、複数のノードが同じコストを生み出す場合です。 実装は明示的にチェックします`u < ans_node`コストが等しい場合でも、DFS トラバーサル中に最小のインデックス選択が保持されるようにします。
