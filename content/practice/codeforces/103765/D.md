 ## 問題の理解

 私たちに与えられたシナリオは、$n$同じバナナと$m$猿。 すべてのサルは少なくとも 1 本のバナナを受け取らなければなりません。そのため、私たちは実際にバナナを配布しています。$n$の中へ$m$正の整数$a_1, a_2, \dots, a_m$総額固定で。 

このような分布では、バナナのカウント値がサル間で複数回出現する可能性があります。 私たちが気にする量は、まったく同じ量のバナナを摂取するサルの最大数です。 異なる分布が可能であるため、繰り返しを避けるために最も有利な方法で分布が選択されていると仮定し、それでも避けられないものは何か、つまり、この「最大繰り返し回数」の可能な最小値はいくらであるかを尋ねます。 

言い換えれば、最小の整数を求めています。$k$そのため、私たちがどれだけ賢く選択したとしても、$m$正の整数の合計$n$、少なくとも出現するバナナは常に一定数存在します。$k$回。 

制約は非常に大きいです。$n$まで可能です$10^{18}$そして$m$まで$10^9$、最大 1000 のテスト ケース。 これにより、明示的に分布を構築したり、可能な値を反復したりするアプローチは即座に除外されます。 すべての解はテスト ケースごとに対数または定数である必要があります。 

微妙なエッジケースが現れるのは、$n$繰り返しを強制できるかぎり十分な大きさです。 たとえば、次のようなとき$m=3$、$n=3$、可能な唯一の分布は$(1,1,1)$、したがって、答えは次のとおりです$3$。 いつ$n=6$、$m=3$、使用できます$(1,2,3)$、したがって、答えは次のようになります$1$。 これは、答えが純粋に依存していないことを示しています$m$、だけでなく、合計がどのくらい「広がる」かについても$n$許可します。 

主な問題は、固定配列内の繰り返しをカウントしていないことです。 私たちは合計制約の下で考えられるすべての整数分割について推論し、達成可能な最適なバランスを求めます。 

## アプローチ

 強引な観点としては、考えられる分割方法をすべて列挙することです。$n$の中へ$m$正の整数を取得し、パーティションごとに任意の値の最大頻度を計算します。 これは概念的には正しいですが、パーティションの数は指数関数的に増加するため、完全に実行不可能です。$n$。 

これを回避するために、視点を変えます。 個々の分布について考える代わりに、「繰り返しを避ける」とはどういうことかを考えます。 それ以上の値を表示したくない場合は、$k$そうすると、同じバナナの数を共有できるサルの数が制限されます。 この制限により、構造パターンが強制されます。値はグループ化する必要があり、各グループのサイズは最大でも次のとおりです。$k$。 問題は、バナナの数をこれらのグループに割り当てて、すべてのグループが同じになるようにできるかどうかです。$m$猿は総額を尊重して補償される$n$。 

重要な点は、繰り返しをできるだけ少なくするには、許可される限り多くの個別の値を使用し、それらをキャップの下にできるだけ均等に詰め込む必要があるということです。$k$。 固定システムにとって最も満足するのが難しい状況$k$を使用しながら合計を最小化しようとするときです$m$サルを尊重し、それ以上に使用される値はないということを尊重します。$k$回。 この最小限の構築さえ超えれば$n$、 それから$k$不可能です。 それ以外の場合は達成可能です。 

これにより、問題は最小のものを見つけることに減ります。$k$この制約の下で可能な最小合計は最大で$n$。

 ## アルゴリズムのチュートリアル

 答えを二分探索します$k$、バナナ数の最大許容頻度。 

確定候補者の場合$k$、配布時に達成可能な最小の合計を計算します。$m$サルをグループに分けます。各グループは同じバナナの数を共有し、最大でもサイズが異なるサルを表します。$k$。 

1. サイズの完全なグループの数を計算します。$k$次のように形成できます。$t = \lfloor m / k \rfloor$、および残り$r = m \bmod k$。 
2. 合計を最小化するために、最小のバナナ数を最大のグループに割り当てます。 これは、概念的には、サイズを使用して値の昇順にグループを埋めることを意味します。$k, k, \dots, k, r$。 
3. この構造の最小達成可能な合計は、値を割り当てることによって取得されます。$1, 2, 3, \dots$これらのグループに。 合計は加重合計になります。$$\text{cost}(k) = k(1 + 2 + \dots + t) + r \cdot (t+1)$$4. もし$\text{cost}(k) \le n$とすると、それ以上に値が現れない分布を実現することができます。$k$回。 
5. 最小値を二分探索します$k$満足のいく実現可能性。 

### なぜ効果があるのか

 有効な割り当ては最大頻度で行われるため、構造は厳密です。$k$サルを最大でもサイズのグループに割り当てなければなりません$k$。 合計を最小限に抑えるために、常に可能な限り最小のバナナ値を最大のグループに割り当てます。 そうしないと、値を交換しても、実行可能性が向上せずに合計が増加するだけになります。 この貪欲な階層化により、制約の下で達成可能な絶対最小合計が生成されるため、$n$かどうかを正しく判断します。$k$で十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def feasible(n, m, k):
    t = m // k
    r = m % k

    # cost = k * (1 + 2 + ... + t) + r * (t + 1)
    cost = k * t * (t + 1) // 2 + r * (t + 1)
    return cost <= n

def solve_case(n, m):
    lo, hi = 1, m
    while lo < hi:
        mid = (lo + hi) // 2
        if feasible(n, m, mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

def main():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        print(solve_case(n, m))

if __name__ == "__main__":
    main()
```の`feasible`関数は、バナナの数がこれ以上出現しないという仮定の下で、可能な最小の総和を計算します。`k`回。 二分探索では、そのような最小のものを見つけます。`k`。 重要な実装の詳細は、三角和に 64 ビットの安全な算術演算を使用することです。$n$と同じ大きさにすることができます$10^{18}$。 

## 実用的な例

 検討してください$n = 6, m = 3$。 

テストします$k = 1$。 それから$t = 3, r = 0$ですので、コストは$1 + 2 + 3 = 6$。 これは実現可能なので、$k = 1$動作します。 

ここで考えてみましょう$n = 3, m = 3$。 

のために$k = 1$、コストは再び$6$を超える$n$、 それで$k=1$不可能です。 試してみます$k=2$： 今$t=1, r=1$、費用は$2 \cdot 1 + 1 \cdot 2 = 4$、まだ大きすぎます。 のために$k=3$:$t=1, r=0$、費用は$3$、一致します$n$。 したがって、答えは次のとおりです$3$。 

これらの例は、周波数制限を厳しくすると、構築がより少ないグループに分割され、それにより最小達成可能な合計が増加する方法を示しています。

 ## 特殊なケース

 いつ$n$に非常に近いです$m$、アルゴリズムは大きな値を返す傾向があります$k$値を分散させる余地がほとんどないからです。 このような場合、コスト関数は急激に増大し、二分探索はすぐに次のように収束します。$k=m$つまり、極度の圧縮ではすべてのサルが同じ値を共有する必要があります。 

いつ$n$に比べて大きいです$m$、コスト条件はすぐに満たされます。$k=1$これは、繰り返しを強制せずに厳密に増加する値を割り当てることができることを反映しています。 コストの三角構造は、$n$。 

これら 2 つの極端な結果は、モデルが特別なケースなしで「すべてが同一」と「すべてが異なる」の間をスムーズに移行することを裏付けています。
