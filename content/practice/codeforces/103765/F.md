 ## 問題の理解

 オレンジ果樹園に関するいくつかの独立したシナリオが与えられています。 各シナリオには、$n$木々、そして$i$-th ツリーには次の内容が含まれます$a_i$オレンジ。 各木から、間にある整数個のオレンジを摘むことができます。$0$そして$a_i$、他の木とは独立して。 すべての木を選択した後、摘み取ったオレンジの総数を取得します。 

固定番号もあります$m$、チームメイトを代表します。 有効な摘み取り計画とは、摘み取られたオレンジの総数をチームメイト全員で均等に分けることができるもの、つまり、選択されたすべての値の合計が次の値で割り切れる計画です。$m$。 タスクは、この可算条件を満たすさまざまな摘み取り計画がいくつあるかを数えることであり、少なくとも 1 本の木が摘み取ったオレンジの数が異なる場合、2 つの計画は異なります。 

各ツリーは合計に寄与する有界変数のように動作し、合計が特定の合同クラスの法に収まるようにこれらの変数を選択する方法が何通りあるかを数えています。$m$。 

制約が意味するのは、$n$まで可能です$10^5$テストスイートごとに、$m \le 50$。 テストケースの数は多く、最大で$10^3$、しかし合計$n$すべてのテストにわたって、次の制限もあります$10^5$。 これは、線形に近い解決策を強く示唆しています。$n$テストごとに、条件に応じて追加の要素を追加$m$, 一方、二次関数は何でも$n$不可能です。 

すべての選択肢を単純に列挙すると、次のようになります。$\prod (a_i + 1)$この構成は、中程度の入力であっても天文学的に大きくなります。 すべての合計を保存したり反復したりすることすら不可能です。 

すべての場合に、より微妙なエッジケースが現れます。$a_i$大きくて、$m = 1$。 この場合、すべての選択が有効になるため、答えは次のようになります。$\prod (a_i + 1)$モジュロ$998244353$。 合計カウントを考慮せずに残基のみを追跡するメソッドでは、この動作を維持する必要があります。 

もう 1 つの特殊なケースは、すべてが$a_i = 0$。 何も選択しない方法は 1 つだけあり、その合計は$0$、これは常に次で割り切れます。$m$。 答えは常にこうあるべきです$1$、独立して$m$。 

## アプローチ

 直接的なアプローチは、各ツリーが小さな多項式に寄与すると考えることです。$i$、選ぶことができます$0,1,\dots,a_i$、したがって、母関数への寄与は次のようになります。$x^0 + x^1 + \dots + x^{a_i}$。 有効なウェイの総数は、指数が次で割り切れるすべての単項式の係数の合計です。$m$これらすべての多項式の積で求められます。

重要な観察は、正確な合計は気にせず、その値の剰余値のみを気にするということです。$m$。 これにより、状態空間が潜在的に崩壊します。$10^5 \cdot n$可能な合計は次のとおりです$m \le 50$残留クラス。 これは、剰余に対する動的計画法を直ちに示唆します。 

DP 配列を維持します。`dp[r]`に一致する合計を達成する方法が何通りあるかを数えます。$r \bmod m$。 当初は、`dp[0] = 1`。 各ツリーについて、それが各剰余クラスにどのように寄与するかを計算し、それをグローバル DP と畳み込みます。 

値を持つ単一のツリーの場合$a$、 定義する`cnt[t]`整数の数として$[0,a]$に一致するもの$t \bmod m$。 これは、等差数列カウントを使用して剰余ごとに一定時間で計算できます。 次に、ツリーは剰余に対する小さな多項式を提供し、モジュロに対する畳み込みで DP を更新します。$m$。 

各ツリーの更新コスト$O(m^2)$、合計を与える$O(n m^2)$、これは許容されます。$m \le 50$そして合計$n \le 10^5$。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. サイズの DP 配列を初期化します。$m$、すべての値がゼロである`dp[0] = 1`。 これは、ツリーを選択する前に、達成可能な合計が 0 のみであることを表します。 
2. それぞれの木について$i$、整数がいくつあるかを計算します。$[0, a_i]$各剰余クラスのモジュロに分類される$m$。 これを行うには、最初に次のように書きます。$a_i = q \cdot m + r$。 各残基が正確に表示されます$q$回と剰余$0$を通して$r$さらにもう1回登場します。 これにより周波数配列が得られます`cnt`。 

このステップは、組み合わせ情報を失うことなく、広い範囲を剰余全体のコンパクトな表現に圧縮するため、重要です。 
3. 新しい DP アレイを作成します`ndp`ゼロに初期化されます。 このツリーを処理した後、以前の合計から新しい合計への遷移を計算します。 
4. 残基ごとに$j$現在の DP 状態とすべての剰余$k$現在のツリーの貢献から、以下を追加します。$$ndp[(j+k)\bmod m] += dp[j] \cdot cnt[k]$$これは剰余を含む部分和を選択することを表します$j$、次に残差を含む現在のツリーからの選択肢を追加します$k$。 
5.充填後`ndp`、 交換する`dp`と`ndp`。 
6. すべてのツリーが処理されると、答えは次のようになります。`dp[0]`で割り切れる合計だけが必要なので、$m$。 

正確さは、剰余ごとにグループ化されたすべての部分和を追跡することにかかっています。 あらゆる段階で、`dp[r]`に一致する和を得る方法の数を正確に数えます。$r$。 有効な部分構成の拡張はすべて 1 回だけカウントされ、剰余加算 mod が計算されるため、遷移ではこの不変条件が維持されます。$m$クラスを正しく更新します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        dp = [0] * m
        dp[0] = 1

        for x in a:
            q, r = divmod(x, m)

            cnt = [q] * m
            for i in range(r + 1):
                cnt[i] += 1

            ndp = [0] * m
            for j in range(m):
                if dp[j] == 0:
                    continue
                for k in range(m):
                    if cnt[k] == 0:
                        continue
                    ndp[(j + k) % m] = (ndp[(j + k) % m] + dp[j] * cnt[k]) % MOD

            dp = ndp

        print(dp[0] % MOD)

if __name__ == "__main__":
    solve()
```DP アレイ`dp`達成可能な残基のカウントを保存します。 各ツリーの配列`cnt`選択範囲を剰余周波数に圧縮します。 ネストされたループは、モジュロ クラスに対する畳み込みを実装します。 係数は、オーバーフローを回避し、必要な出力形式に一致させるために、遷移中に適用されます。 

微妙な点は扱い方`cnt`: 常に合計は次のようになります$a_i + 1$したがって、ウェイの合計数は遷移全体で保持されます。 モジュロ演算は、選択カウント構造自体には適用されず、最終剰余インデックスにのみ適用されます。

 ## 特殊なケース

 いつ$m = 1$、すべての合計は次で割り切れます。$m$したがって、DP はすべての可能な選択を効果的にカウントする必要があります。 アルゴリズムはこれを処理します。`cnt`常に合計は次のようになります$a_i + 1$、 そして`dp`には状態が 1 つしかないため、残差が混合されることなく、すべての寄与が正しく乗算されます。 

いつすべて$a_i = 0$、 それぞれ`cnt`配列には`cnt[0] = 1`他のすべてのエントリはゼロです。 DP は初期状態から変化しないため、`dp[0]`は 1 のままで、何も選択しない方法が 1 つだけあるという事実と一致します。 

いつ$n$大きいですが、すべて$a_i < m$、内部の分布`cnt`は高度にスパースになりますが、すべての剰余を明示的に反復し、ゼロ エントリを保持するため、畳み込みは引き続き正しく機能します。
