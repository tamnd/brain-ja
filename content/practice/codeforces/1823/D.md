 ## 解決策
 ## 問題の理解

 長さの文字列を構築するように求められます`n`文字列の特定のプレフィックスに、指定された数の固有の回文部分文字列が正確に含まれるようにします。 各プレフィックスは長さによって定義されます`x_i`、それに含まれる一意の回文の数は次のとおりです。`c_i`。 これらの条件をすべて満たす文字列を生成するか、それが不可能であると判断する必要があります。 

回文は、前から見ても後ろから読んでも同じ部分文字列です。 固有の回文は、繰り返しの出現を 1 回だけカウントします。 たとえば、文字列では`ababa`、ユニークな回文は次のとおりです。`a`、`b`、`aba`、`bab`、 そして`ababa`、合計5つになります。 

制約により、いくつかの有益な洞察が得られます。 文字列の長さ`n`最大 200,000、テスト ケースの数は最大 10,000 に達する可能性があります。 全部の合計だから`n`テスト ケース全体の数も 200,000 に制限されているため、各文字を線形時間で個別に処理する余裕があります。 条件の数`k`は最大 20 であり、これは小さいため、パフォーマンスの問題なく条件ごとの分析が可能です。 一意の回文の目標数`c_i`最大約 10^9 と非常に大きくなる可能性がありますが、小規模な場合の実現可能性のみを検証する必要があります。`n`したがって、高い数値は主に理論上の上限です。 

単純なアプローチでは、接頭辞のすべての部分文字列を列挙して回文をカウントしようとしますが、部分文字列の数は O(n^2) であり、これでは遅すぎます。 エッジケースには、要求された状況が含まれます。`c_i`たとえば、4 文字の文字列内に 5 つの一意の回文を要求するなど、プレフィックスの長さを考えると不可能です。 連続する条件に小さな違いがある場合、別の注意が必要なケースが発生します。`c_i`; 増加が大きすぎて、文字ごとに 1 つの新しい一意の回文を追加するだけでは満足できない場合、その文字列は不可能になります。 

## アプローチ

 ブルート フォース アプローチでは、すべての候補文字列を生成し、O(n^2) 個の部分文字列チェックまたは Manacher のようなアルゴリズムを使用して各プレフィックスに対して一意の回文を計算します。 理論的には正しいですが、テスト ケースあたりの最悪の場合の操作数は約 2 · 10^10 であり、2 秒の時間制限では許容範囲をはるかに超えているため、これは実行不可能です。 

重要な洞察は、新しい文字で文字列を拡張するにつれて、一意の回文の数がゆっくりと増加するということです。 接頭語の最後の文字が新しいもので、以前の回文の一部ではない場合、最大 1 つの新しい回文 (単一の文字自体) が導入される可能性があります。 文字を注意深く繰り返すと、前の文字にまたがる回文を作成できます。 なぜなら`k`が小さく、有効な文字列が 1 つだけ必要な場合は、貪欲に問題にアプローチできます。 

連続する 2 つの条件の間で一意の回文の数を増やすことは、次の長さの文字列に注目することで実現可能であることを確認できます。`m`、次で導入できる新しい一意の回文の最大数`delta = x_{i+1} - x_i`文字は`delta`。 もし`c_{i+1} - c_i > delta`、その条件は不可能です。 実現可能性が検証されたら、必要に応じて文字を交互に配置して偶発的な回文を回避したり、文字を繰り返して制御された回文を導入したりする文字列を構築できます。 

アプローチを要約すると次のようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (部分文字列を列挙) | O(n^2) | O(n^2) | 遅すぎる |
 | 貪欲な建設 (実現可能な増分) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。`n`そして`k`、次に配列`x`そして`c`プレフィックスの長さと必要な一意の回文数を表します。 
2. 変数を初期化する`possible = True`実現可能性を追跡します。 
3. 最初から各条件をループします。 差を計算する`delta_len = x[i] - x[i-1]`（と`x[0] = 0`） そして`delta_p = c[i] - c[i-1]`（と`c[0] = 0`）。 
4. もし`delta_p < 0`または`delta_p > delta_len`、 マーク`possible = False`。 これにより、一意の回文の数が減っていないこと、および利用可能な位置を超える新しい一意の回文が必要ないことが確認されます。 
5. 可能であれば、文字列を貪欲に構築します。 から始める`'a'`そして文字を繰り返して回文を紹介します。 新しい長さのセグメントごとに`delta_len`、 導入`delta_p`新しい文字 (それぞれに 1 つの新しい回文が追加されます)、余分な一意の回文の追加を避けるために、文字を繰り返して残りの位置を埋めます。 簡単なアプローチは、次のことを交互に行うことです。`'a'`そして`'b'`。 
6. すべての条件が満たされている場合は、「YES」と構築された文字列を出力します。 それ以外の場合は、「NO」を出力します。 

これが機能する理由は、より大きな回文を形成するために慎重に繰り返さない限り、各キャラクターが導入できる新しい固有の回文は最大 1 つであるためです。 新しい文字の導入と繰り返しの文字の導入を制御することで、各接頭辞が正確に終わるという不変条件を維持します。`c_i`ユニークな回文。 最初に実現可能性を検証するため、可能な場合には確実に建設が成功します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    x = list(map(int, input().split()))
    c = list(map(int, input().split()))
    
    prev_len = 0
    prev_count = 0
    possible = True
    for xi, ci in zip(x, c):
        delta_len = xi - prev_len
        delta_p = ci - prev_count
        if delta_p < 0 or delta_p > delta_len:
            possible = False
            break
        prev_len = xi
        prev_count = ci

    if not possible:
        print("NO")
        continue

    res = []
    last_char = 'a'
    used_chars = 0
    for i in range(k):
        start = x[i-1] if i > 0 else 0
        end = x[i]
        delta_len = end - start
        delta_p = c[i] - (c[i-1] if i > 0 else 0)
        
        # Add delta_p new letters to create new palindromes
        for j in range(delta_p):
            res.append(chr(ord('a') + used_chars % 26))
            used_chars += 1
        # Fill remaining positions by alternating 'a' and 'b'
        for j in range(delta_len - delta_p):
            res.append('a' if (len(res) % 2 == 0) else 'b')
    
    print("YES")
    print(''.join(res))
```コードは最初に、各プレフィックスが一意の回文の必要な増加に対応できるかどうかをチェックすることで実現可能性を検証します。 工事中は、`delta_p`新しい文字は、必要な新しい回文を正確に導入するために追加されます。 残りの位置は、意図しない新しい回文を防ぐために交互の文字で埋められます。 これにより、各プレフィックスがそのターゲットと一致することが保証されます`c_i`。
