 ## 解決策
 ## 問題の理解

 正の整数の配列と多くの範囲クエリが与えられます。 クエリごとに`[l, r]`、それらの位置間の部分配列のみを見て、値の数を数えます。`x`非常に特殊な条件を満たします。 

その部分配列内の値は、`x`正確に表示されます`x`回。 

たとえば、部分配列では```
[3, 1, 2, 2, 3, 3, 7]
```周波数は次のとおりです。```
1 -> 1
2 -> 2
3 -> 3
7 -> 1
```価値観`1`、`2`、 そして`3`それぞれがそれぞれの値と同じ回数出現するため、答えは次のようになります。`3`。 

配列の長さとクエリの数は両方とも次のとおりです。`100000`。 すべてのクエリの頻度を再計算する単純な解決策は直ちに除外されます。 たとえ`O(length of range)`クエリごとのソリューションには大まかに必要となります`10^10`最悪の場合の運用。 

値自体は次のように大きくできます。`10^9`。 これは、値によって直接インデックス付けされた周波数構造を構築できないことを意味します。 配列内に実際に現れる値のみを考慮します。 

微妙な観察ですが、これより大きい値はすべて`n`決して答えに貢献することはできません。 値は正確に表示される必要があります`x`ただし、どの範囲内の周波数もこれを超えることはできません。`n`。 もし`x > n`、一致周波数`x`不可能です。 

考慮する：```
n = 5
array = [100, 100, 100, 100, 100]
```の頻度`100`は`5`、 ない`100`, したがって、決して貢献しません。 

もう 1 つの簡単な間違いは、値を修飾する代わりに出現回数を数えることです。 例えば：```
array = [2, 2]
query = [1, 2]
```価値`2`は正確に 2 回出現するため、答えは次のようになります。```
1
```ない```
2
```位置ではなく、条件を満たす値をカウントするためです。 

3 番目の落とし穴は、範囲を拡大または縮小しているときに周波数がターゲット値を超える場合に発生します。 

現在の値の周波数を仮定します`3`変更:```
2 -> 3 -> 4
```届いたら`3`、答えは 1 つ増えるはずです。 となると`4`、答えは 1 つ減るはずです。 これらの遷移の 1 つを忘れると、不正確な結果が生じます。 

## アプローチ

 ブルート フォース ソリューションは、各クエリを個別に処理します。 お問い合わせの場合`[l, r]`、部分配列全体をスキャンし、ハッシュ マップを使用して頻度を計算し、次を満たす値の数を数えます。```
frequency[value] == value
```これは定義を直接実装しているため、これは正しいです。 

残念ながら、クエリは配列のほぼ全体をカバーする可能性があります。 と`100000`クエリと長さの範囲`100000`、作業は大まかに次のようになります。```
100000 × 100000 = 10^10
```それは制限時間をはるかに超えています。 

重要な観察は、クエリが多くの重複する範囲について尋ねることです。 連続したクエリは、いくつかの要素だけが異なることがよくあります。 すべての周波数を最初から再計算すると、作業が無駄になります。 

これはまさに Mo のアルゴリズムが光る設定です。 現在の範囲が徐々に変化するように、クエリを特別な順序で並べ替えます。 あるクエリから次のクエリに移動する際、現在の範囲に少数の要素を追加または削除するだけです。 

課題は、周波数が変化しても動的に答えを維持することになります。 

値を仮定する`v`現在周波数があります`cnt[v]`。 

頻度を増やす前に、それがすでに寄与しているかどうかを確認します。 もし：```
cnt[v] == v
```その場合、その等式を削除すると、答えが減少するはずです。 

頻度を更新した後、再度確認します。 新しい周波数が次の場合`v`、値が寄与し始め、答えが増加します。 

各追加/削除操作は次のようになります。`O(1)`、Mo の注文は約についてのみ保証します。`O((n+m)√n)`合計範囲の調整。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n) | 遅すぎる |
 | 最適 (Mo のアルゴリズム) | O((n+m)√n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列とクエリを読み取ります。 
2. 以下の値をすべて置き換えます。`n`特別な無関係な値を持つ。 

そんな価値観は決して満たされない`frequency = value`したがって、回答ロジックでそれらを追跡する必要はありません。 
3. 各クエリを元のインデックスとともに保存します。 
4. 以下にほぼ等しいブロック サイズを選択します。`√n`。 
5. Mo の順序付けを使用してクエリを並べ替えます。 

同じ左側のブロック内のクエリは、右側のエンドポイントによって順序付けされます。 これにより、ポインタの動きが最小限に抑えられます。 
6. 電流範囲を維持する`[curL, curR]`。 

最初は範囲は空です。 
7. 周波数配列を維持する`cnt`。`cnt[x]`何倍の値を保存するか`x`現在の範囲に表示されます。 
8. 変数を維持する`answer`。 

これは、頻度が現在その値と一致する値の数に等しくなります。 
9. 付加価値を付ける場合`v`:

 まず次のことを確認してください`cnt[v] == v`。 true の場合、デクリメントします`answer`平等が崩れようとしているからです。 

増加`cnt[v]`。 

かどうかをもう一度確認してください`cnt[v] == v`。 true の場合、インクリメントします`answer`。 
10. 値を削除する場合`v`:

 まず次のことを確認してください`cnt[v] == v`。 true の場合、デクリメントします`answer`。 

減少`cnt[v]`。 

かどうかをもう一度確認してください`cnt[v] == v`。 true の場合、インクリメントします`answer`。 
11. Mo 順序の各クエリに対して、次のように移動します。`curL`そして`curR`現在の範囲がクエリ範囲と一致するまで。 
12. 現在の値を保存します`answer`そのクエリの結果として。 
13. 元のクエリの順序で回答を出力します。 

### なぜ効果があるのか

 あらゆる瞬間に、`cnt[x]`値の頻度に等しい`x`Mo のアルゴリズムによって維持される現在の範囲内です。 

変数`answer`次を満たす値を正確にカウントします。```
cnt[x] = x
```周波数が変更されるたびに、1 つの値のみが影響を受けます。 追加/削除ルーチンの更新`answer`まさに、その値が等価条件に入るとき、または等価条件から出るときです。 

Mo のアルゴリズムは最終的にすべてのクエリ範囲を正確に訪問し、維持される頻度は現在の範囲に対して常に正しいため、各クエリに対して保存される回答は、その値と同じ回数だけ出現する値の数となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    # Values > n can never satisfy freq == value
    a = [x if x <= n else 0 for x in a]

    block = int(n ** 0.5) + 1

    queries = []
    for idx in range(m):
        l, r = map(int, input().split())
        l -= 1
        r -= 1
        queries.append((l, r, idx))

    queries.sort(key=lambda q: (q[0] // block, q[1]))

    cnt = [0] * (n + 1)
    answers = [0] * m
    current_answer = 0

    def add(pos):
        nonlocal current_answer
        v = a[pos]

        if v == 0:
            return

        if cnt[v] == v:
            current_answer -= 1

        cnt[v] += 1

        if cnt[v] == v:
            current_answer += 1

    def remove(pos):
        nonlocal current_answer
        v = a[pos]

        if v == 0:
            return

        if cnt[v] == v:
            current_answer -= 1

        cnt[v] -= 1

        if cnt[v] == v:
            current_answer += 1

    cur_l = 0
    cur_r = -1

    for l, r, idx in queries:
        while cur_l > l:
            cur_l -= 1
            add(cur_l)

        while cur_r < r:
            cur_r += 1
            add(cur_r)

        while cur_l < l:
            remove(cur_l)
            cur_l += 1

        while cur_r > r:
            remove(cur_r)
            cur_r -= 1

        answers[idx] = current_answer

    sys.stdout.write("\n".join(map(str, answers)))

if __name__ == "__main__":
    solve()
```最初の前処理ステップでは、次の値より大きい値をすべて置き換えます。`n`と`0`。 周波数がこれを超えることはできないため、そのような値は決して寄与できません。`n`。 これにより、条件を決して満たすことができない周波数を維持するために時間を無駄にすることがなくなります。 

の`cnt`配列には、次の値の周波数のみが格納されます。`1`に`n`。 価値`0`完全に無視されます。 

最もデリケートな部分は更新ロジックです。 周波数が変化する場合、カウントを変更する前に古い寄与を削除し、その後新しい寄与を追加する必要があります。 この順序を逆にすると、周波数が目標値を超えるたびにオフバイワンエラーが発生します。 

Mo のアルゴリズムによって維持される範囲には、両端が含まれます。 実装は空の範囲から始まります`[0, -1]`、各クエリと一致するまで拡大または縮小します。

 ## 特殊なケース

 次のことを考慮してください。```
3 1
100 100 100
1 3
```以来`100 > n`、値が正確に表示されることはありません`100`回。 前処理により、すべてのエントリが次のように変換されます。`0`、更新ルーチンはそれらを無視し、維持された答えは残ります`0`。 

考慮する：```
2 1
2 2
1 2
```価値の頻度`2`まさに`2`。 挿入中にカウントは次のように変化します。```
0 -> 1 -> 2
```届いたら`2`、答えは1つ増えます。 最終的な出力は次のとおりです。```
1
```値だけなので、これは正しいです`2`資格があります。 

考慮する：```
4 1
3 3 3 3
1 4
```周波数の遷移は次のようになります。```
0 -> 1 -> 2 -> 3 -> 4
```周波数で`3`、値が寄与します。 周波数で`4`、貢献を停止します。 更新ロジックは、カウントを増やす前に寄与を削除し、その後も等価性が維持される場合にのみ寄与を復元します。 最終的な答えは次のとおりです。```
0
```これは定義と正確に一致します。
