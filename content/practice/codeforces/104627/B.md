 ## 問題の理解

 私たちに与えられているのは、$n \times n$グリッドは空から始まり、2 人のプレイヤーが交互にトークンを列にドロップします。 それぞれの動きによって列が選択され、コネクト フォーの重力のように、トークンはその列の利用可能な最も下のセルに落ちます。 

面白いのは、ゲームを最初からシミュレートすることを求められるのではなく、すでにプレイされた一連の動きの後の状態を再構築し、誰かがすでに長さの勝ち筋を形成しているかどうかを判断することです。$k$。 勝ちラインとは、$k$同じ色のトークンを水平、垂直、または斜めのいずれかの方向に並べます。 

入力によりグリッド サイズが与えられます$n$、手数$m$、およびターゲットの長さ$k$、各移動の列の選択肢が続きます。 プレイヤー 1 (あゆみ) は奇数手で配置し、プレイヤー 2 (文治) は偶数手で配置します。 出力では、プレイヤーがアクションを完了する最初の動きインデックスを識別する必要があります。$k$-line、またはそのような行が表示されないことを報告します。 

制約により許可されるのは、$n$300までと$m$まで$n^2$したがって、すべての動きの後にボードを完全にスキャンすることは境界線にありますが、慎重に実行すれば実行可能です。 フルグリッドスキャンによる移動ごとの単純な再計算では、大まかに次の結果が得られます。$O(m \cdot n^2)$、最悪の場合には遅すぎます。$n=300$、$m=90000$。 

正確さには、いくつかのエッジの状況が重要です。 1 つの手で複数の勝ち方向が同時に作成される可能性があり、いずれかの方向が長さに達する最も早い手$k$それは答えであり、最終状態ではありません。 また、積み重ねにより勝利が垂直方向になる可能性がありますが、これは水平方向のラインだけをチェックしている場合に最もありがちな間違いです。 

小さな例:$n=3, k=3$、動きます$1,1,1$。 すべてのトークンは列 1 にスタックされ、プレーヤー 1 が 3 番目の移動で垂直方向に勝ちます。行のみをチェックするソリューションでは、誤って「勝者なし」と出力されます。 

もう 1 つの微妙なケースは、単一の配置から複数のラインを同時に作成する場合、特に新しいセルで交差する対角線です。 新しく配置されたすべてのトークンから 4 つの方向すべてがチェックされていることを確認する必要があります。 

## アプローチ

 ブルート フォース アプローチは、ドロップ プロセスをシミュレートし、完全なグリッドを維持します。 各移動の後、ボード全体をスキャンし、可能性のあるすべての開始点をチェックします。$k$- 4 方向の長さの線。 それぞれのスキャンは、$O(n^2)$、そして私たちはそれをします$m$回、生産$O(mn^2)$操作。 と$n=300$、これは周りに届くことができます$9 \cdot 10^4 \times 9 \cdot 10^4$、これは大きすぎます。 

重要な観察は、最後に配置されたトークンのみが新しい勝ちラインを作成できるということです。 他のすべてのセルは前の手順ですでにチェックされており、最新の列位置に沿ったものを除いて以前の構成は変更されていません。 これにより、チェックを最後の移動位置を通過するラインに制限することができます。 

配置された各トークンから 4 方向に展開し、連続する同じ色のトークンを数えるだけです。 各方向は独立しており、セルの両側からのカウントを合計します。 これにより、各移動が次のように減少します。$O(n)$、各方向スキャンは最大で拡張できるため、$n$ステップ。 

ブルートフォースは各移動後にグリッドを静的に扱うため機能しますが、変更されていない領域を再チェックするのに時間がかかります。 最適化されたアプローチにより、新しいトークンに関する局所的な更新の問題が軽減され、グローバルな再計算が増分検証に変わります。

 ## アルゴリズムのチュートリアル

 グリッドを維持し、重力を利用してトークンを列に配置しながら、動きを 1 つずつシミュレートします。 

1. を初期化します。$n \times n$空のセルを含むグリッドと、下から次に利用可能な行を追跡するための各列の高さポインター。 これにより、トークンが配置されるたびに下方向にスキャンする必要がなくなります。 
2. 各移動を順番に処理し、選択した列の現在の高さを読み取ることによってトークンが着地する行を決定します。 動きのパリティに応じて、プレイヤー 1 またはプレイヤー 2 のマーカーを配置します。 
3. トークンを配置した後、このセルを勝ちラインを新たに作成できる唯一の位置として扱います。 存在する勝ちラインには、このセルが含まれている必要があります。 
4. このセルでは、水平、垂直、対角線 ()、および反対角線 (/) の 4 つの方向にスキャンします。 各方向について、セルに同じプレイヤーのトークンが含まれている間に、正と負の両方の方向に外側に拡張します。 
5. 現在のセルを含む、その行の連続するトークンの合計を数えます。 いずれかの時点でカウントが到達または超過した場合$k$、現在の手のインデックスと現在のプレイヤーを勝者として記録し、それ以降の手の処理を停止します。 
6. どの手が勝ちラインを生成しない場合は、勝者がいないことを出力します。 

これが機能する理由は、新しい勝利構成は、最後に配置されたトークンを介して既存の整列セグメントを拡張することによってのみ表示されるためです。 新しいトークンを含まない行はこの移動の前にすでに存在していたので、より早く検出されたはずです。 この不変式により、最新のセルのみをチェックするだけで正確性が十分であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(grid, n, r, c, player, k):
    dirs = [(0, 1), (1, 0), (1, 1), (1, -1)]
    
    for dr, dc in dirs:
        cnt = 1
        
        rr, cc = r + dr, c + dc
        while 0 <= rr < n and 0 <= cc < n and grid[rr][cc] == player:
            cnt += 1
            rr += dr
            cc += dc
        
        rr, cc = r - dr, c - dc
        while 0 <= rr < n and 0 <= cc < n and grid[rr][cc] == player:
            cnt += 1
            rr -= dr
            cc -= dc
        
        if cnt >= k:
            return True
    
    return False

def solve():
    n, m, k = map(int, input().split())
    cols = list(map(int, input().split()))
    
    grid = [[0] * n for _ in range(n)]
    height = [0] * n
    
    for i in range(m):
        c = cols[i] - 1
        r = height[c]
        height[c] += 1
        
        player = 1 if i % 2 == 0 else 2
        grid[r][c] = player
        
        if check(grid, n, r, c, player, k):
            if player == 1:
                print("Ayumi", i + 1)
            else:
                print("Bunji", i + 1)
            return
    
    print("No winner")

if __name__ == "__main__":
    solve()
```グリッドは行優先形式で保存され、行 0 がボードの底部に対応します。これにより、高さカウンターを使用して各列が上向きに埋められるため、重力の処理が簡素化されます。 これにより、空のスロットを繰り返し検索することがなくなります。 

の`check`関数は中心となる正確性コンポーネントです。 新しく配置されたセルから 4 方向のみを検査し、外側に対称に拡張します。 重要な点は、順方向と逆方向の両方が個別にチェックされ、新しいトークンを横切る行が完全にカウントされていることです。 

移動ループは、問題定義から直接続く移動インデックスのパリティを使用してプレイヤーを交代します。

 ## 特殊なケース

 エッジケースの 1 つは、まさにグリッドの境界で勝利が得られることです。 たとえば、$k=3$行が一番上の行で終わっている場合でも、チェックはグリッドの端に達したときではなく、インデックスが範囲外になったときにのみ停止するため、展開は引き続き機能します。 

もう 1 つのケースは、水平線と交差する対角線など、同じ動きで形成される重なり合う線です。 このアルゴリズムは、4 つの方向すべてを個別に評価し、どの方向でトリガーされたかに関係なく、最初の成功ですぐに戻るため、これを正しく処理します。 

最後のケースは、ボード上の他の場所にラインが存在するにもかかわらず、最後の手が勝ちラインの一部ではない場合です。 正しいプレイでは、以前の動きがすでに検出をトリガーしているため、これは起こりません。 ただし、このアルゴリズムは最終状態の排他性を決して想定せず、常に現在の手を直接チェックするため、安全に動作します。
