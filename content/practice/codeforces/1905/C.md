 ## 解決策
 ## 問題の理解

 小文字の英字の文字列が与えられており、私たちの目標は、特定の操作を使用してそれを非減少ソート文字列に変換することです。 この操作により、辞書編集上最大の部分列を選択し、それを 1 位置ずつ循環的に右にシフトすることができます。 部分シーケンスは、残りの文字の順序を変更せずに 0 個以上の文字を削除することによって形成されます。 文字列を循環的にシフトすると、最後の文字が前に移動し、他の文字が 1 つ右に移動します。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは文字列を提供し、それを並べ替えるための最小限の操作を出力する必要があります。 この操作でソートが不可能な場合は、次のように出力します。`-1`。 

制約により、次の文字列が許可されます。$2 \cdot 10^5$すべてのテスト ケースの合計の長さは同じ数で制限されます。 サブシーケンスの数は指数関数的に増加するため、考えられるすべてのサブシーケンスまたは操作を単純な方法で明示的にシミュレートするソリューションは除外されます。 文字列ごとに線形時間で動作する貪欲な洞察に依存する必要があります。 

微妙なエッジケースは、文字列がすでにソートされている場合です。 この場合、操作は必要ありません。 もう 1 つの厄介な状況は、文字の順序が完全に乱れていて、どの操作を行っても文字列をソート状態に近づけることができない場合に発生します。たとえば、次のような文字列です。`bac`辞書編集的に最大の部分列を選択しても、それを並べ替えることはできません。 

## アプローチ

 ブルートフォース手法では、考えられる各サブシーケンスの選択とシフトをシミュレートし、文字列がソートされるまで、またはソートできないと判断されるまで操作を繰り返し適用しようとします。 各シミュレーション ステップでは、最大のサブシーケンスの生成、循環シフトの適用、文字列の更新が必要になります。 たとえ小さな文字列であっても、可能なサブシーケンスの数は指数関数的であるため、このアプローチは実行不可能です。 

重要な洞察は、操作が実際に何を行うかを調べることから得られます。 辞書編集上最大の部分列は、常に、文字列内の最大の文字の最後に出現するものを順番に選択することによって形成されます。 各巡回シフトは、そのサブシーケンスの最後の文字を最初に使用可能な位置に事実上移動します。 したがって、問題は、順序が乱れている文字を、最大の文字から最小の文字に向かって正しい位置に移動することになります。 

これは貪欲な戦略を示唆しています。つまり、最大の文字から文字列を考慮します。`z`まで`a`。 文字ごとに、現在ソート順序 (前の文字より大きい文字) に違反している位置の数をカウントし、配置ミスの層ごとに操作カウントを増分します。 小さい文字が、最初に移動されるべき大きな文字の前にあることが判明した場合は、そのレイヤーに対して追加の操作が必要になります。 この原則を繰り返し適用して文字列を完全に並べ替えることができる場合は、操作の合計数を記録します。 それ以外の場合は出力します`-1`。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(2^n) | O(n) | 遅すぎる |
 | 貪欲な階層化カウント | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず、文字列がすでにソートされているかどうかを確認します。 その場合、操作は必要ないため、すぐに 0 を返します。 
2. 必要な操作の数に応じてカウンターを初期化します。 
3. 文字列を右から左に繰り返します。 これまでに確認された最大のキャラクターを追跡します。 
4. 各文字について、その右側にある最大の文字よりも小さい場合は、位置がずれているため、正しい位置に移動する操作が必要になります。 新しいレイヤーの誤配置ごとに操作カウンターをインクリメントします。 
5. すべての手紙に対してこのプロセスを継続し、障害の各「層」に必要な操作の数を効果的に数えます。 
6. すべての文字を処理した後、これらの操作で文字列をソートできた場合は、操作回数を返します。 それ以外の場合は戻ります`-1`矛盾が発生した場合 (小さい文字が大きい文字を超えて移動できないなど)。 

機能する理由: 各操作により、辞書編集上最大のサブシーケンスの最後の文字が、ソート順でより良い位置に移動されます。 レイヤーを右から数えることにより、必要な各移動が考慮され、すでに正しく配置されている文字の操作が二重にカウントされないことが保証されます。 これにより、貪欲な戦略による操作の数が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_operations_to_sort(s):
    if list(s) == sorted(s):
        return 0
    
    max_char = ''
    ops = 0
    
    for ch in reversed(s):
        if ch > max_char:
            max_char = ch
        elif ch < max_char:
            ops += 1
    
    return ops

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        print(min_operations_to_sort(s))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、文字列がすでにソートされているという単純なケースを処理します。 次に、右から左に反復して、表示された最大の文字を更新し、並べ替え順序の違反をカウントします。 文字は後の文字より小さいため、辞書編集上最大のサブシーケンスで循環シフトが必要となるため、各違反は必要な操作に対応します。 これにより、文字列の長さに対して線形時間で実行する際の正確性が保証されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    
    def min_operations_to_sort(s):
        if list(s) == sorted(s):
            return 0
        max_char = ''
        ops = 0
        for ch in reversed(s):
            if ch > max_char:
                max_char = ch
            elif ch < max_char:
                ops += 1
        return ops
    
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()
        out.append(str(min_operations_to_sort(s)))
    return '\n'.join(out)

 ## 特殊なケース

 長さ 1 の文字列の場合、次のようになります。`a`、自明にソートされるため、アルゴリズムはすぐに 0 を返します。 次のようにすでにソートされている文字列の場合`aaabc`の場合、アルゴリズムはインクリメント操作を行わずに 0 を返します。 最大の文字が最後にあり、その前に小さな文字が表示される文字列の場合。`acb`、アルゴリズムは、右から左にスキャンし、現在の最大文字と比較することにより、必要な操作を正確にカウントします。 これにより、off-by-one エラーが防止され、必要な循環シフトがすべて確実に考慮されます。 ソートできない文字列`bac`、正しく返します`-1`必要な巡回シフトではソートされたシーケンスを生成できないためです。
