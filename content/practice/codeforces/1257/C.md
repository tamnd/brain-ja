 ## 解決策
 ## 問題の理解

 いくつかの配列が与えられており、それぞれについて、厳密に多数の要素を持つ最も短い連続セグメントを見つける必要があります。 セグメントに少なくとも 2 つの要素が含まれており、セグメント内の頻度が他のすべての値の頻度よりも厳密に大きい値が存在する場合、セグメントは有効であるとみなされます。 

この条件は、セグメントに固有の最も頻繁な値があり、その値が競合他社よりも厳密に頻度が高いと言うのと同じです。 そのようなセグメントが存在しない場合は、-1 を返します。 

入力サイズはテスト ケース全体で大きく、要素の総数は最大 200,000 です。 これにより、すべての部分配列を明示的に検査するソリューションは即座に除外されます。 二次または三次アプローチでは、n² または n³ 個のセグメント チェックが試行されますが、これでは、単一の大規模テストですら遅すぎます。 

重要な問題は、支配とは重複が存在することだけではないということです。 のようなセグメント`[1, 2]`両方の要素が異なる場合でも無効です。`[3, 3]`1 つの値が厳密に支配的であるため、これは有効です。 さらに微妙なのは、次のようなセグメントです。`[3, 2, 3, 2, 3]`複数の値が繰り返される場合でも、3 が他のどの値よりも多く出現するため、これは有効です。 

よくある間違いは、重複があればすぐに長さ 2 の有効な答えを意味すると仮定することです。重複が遠く離れている場合、または複数の値が短いセグメント内で同等に競合する場合、これは失敗します。 もう 1 つの失敗例は、最適なセグメントが値の最も近い繰り返しによって決定されることを認識せずに、ウィンドウを貪欲に拡張または縮小しようとすることから発生します。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのサブ配列を列挙し、その中の頻度を数え、ある値の頻度が他の値よりも厳密に大きいかどうかを確認します。 周波数マップを増分的に維持する場合でも、テスト ケースごとに O(n²) 個のサブ配列があり、支配性の更新またはチェックには O(1) から O(n) のコストがかかり、最悪の場合は O(n³) になります。 総要素数が 200,000 であるため、これは完全に不可能です。 

重要な観察は、最大合計や最長のプロパティ ウィンドウのようなグローバル構造を検索しているわけではないということです。 私たちが気にするのは、すでに厳密な多数派を強制している最小のセグメントだけです。 値は少なくとも 2 回出現しないと支配的になることができないため、その最小の構造は、ある値が繰り返されるとすぐに出現する必要があります。 値の優位性を強化する最短の方法は、その値の隣接する 2 つの出現を取得し、それらの間にあるすべてを含めることです。 最適なセグメントの候補は、2 つの等しい要素間の何らかの間隔内に含まれている必要があります。 

これにより、問題は、すべての値について、2 つの連続する出現の間の最小距離を追跡することになります。 値が位置 i と j に現れる場合、セグメントは`[i, j]`が候補であり、その長さは`j - i + 1`。 すべての値の中で、そのような間隔が最も小さいものが答えになります。 

これが機能するのは、どの優勢セグメントにもその中に少なくとも 2 回出現する値が含まれている必要があるためです。 そのセグメントが、その支配的な値の最初の出現と最後の出現の間にまたがるまで縮小しても、支配を壊すことはできず、長さが減少するだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 各値が出現した最後のインデックスを保存する辞書を維持します。 これにより、値が繰り返し出現するたびにそれを検出できるようになります。 
2. 配列を左から右にスキャンしながら、値 x を持つ位置 i ごとに、x が以前に見られたかどうかを確認します。 存在する場合、i と前の出現との間の距離を計算します。 
3. この距離に 1 を加えた値は、x が少なくとも 2 回出現するセグメントを表すため、候補の答えになります。 
4. そのようなすべてのペアにわたって最良の回答を更新します。 
5. 最後に確認された x の位置を i に更新します。 
6. スキャンの終了後、繰り返し値が見つからなかった場合は、-1 を返します。 それ以外の場合は、候補の最小長を返します。 

重要な考え方は、すべての有効な支配セグメントには少なくとも 1 つの繰り返し値が含まれている必要があり、その値に最適なセグメントは常に 2 つの連続する出現の間にあるということです。 この範囲外の追加要素は、優位性を高めることなく長さを増やすだけです。 

### なぜ効果があるのか

 支配的なセグメントを考えてみましょう。 v をその支配的な値とします。 v はそのセグメント内の他の値よりも厳密に頻度が高いため、少なくとも 2 回出現する必要があります。 そのセグメント内の最初と最後の v を取得します。 それらの間の部分配列には、少なくともこれら 2 つの v の出現が依然として含まれており、外側の要素を削除しても、その縮小された間隔内の v に対する競合頻度を増やすことはできません。 したがって、v の最適なセグメントは常に何らかの出現ペアによって取得され、等しい値の隣接するペアをすべてチェックするだけで全体的な最適値を見つけるのに十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        a = list(map(int, input().split()))

        last = {}
        ans = float('inf')

        for i, x in enumerate(a):
            if x in last:
                ans = min(ans, i - last[x] + 1)
            last[x] = i

        print(-1 if ans == float('inf') else ans)

if __name__ == "__main__":
    solve()
```このソリューションは、テスト ケースごとに 1 つのパスに依存します。 辞書`last`各値の最新のインデックスを保存します。 繰り返しが見つかると、候補セグメントの長さがすぐに計算されます。 の`+1`インデックスは長さではなく差を定義するため、これは必須です。 

よくある実装上の間違いは、答えを無限大に初期化するのを忘れ、目に見えないケースを誤って有効なものとして扱うことです。 もう 1 つの微妙な問題は、候補を計算した後に最後の出現を更新できないことです。これにより、隣接する出現ではなく、連続しない出現が誤って比較されます。

 最初の繰り返しは、最後に値 1 が再び現れるときに発生します。 インデックス 0 から 5 までのセグメントには 1 が 2 回含まれており、最良の候補になります。
