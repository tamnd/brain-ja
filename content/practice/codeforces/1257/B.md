 ## 解決策
 ## 問題の理解

 開始整数と目標整数が与えられます。 開始値から、2 つの変換のうち 1 つを繰り返し適用することができます。現在の値が偶数の場合は、それをその値の 3 つの半分に置き換えることができ、値が 1 より大きい場合は、それを 1 つ減らすことができます。 これらの操作は任意の順序で任意の回数適用でき、最終的に目標値に正確に到達できるかどうかを知りたいと考えています。 

主な問題は、パリティに応じて操作の動作が大きく異なることです。 「マイナス 1」演算は、1 を除いて常に使用可能であり、より小さい数値に段階的に到達することを完全に制御できます。 「半分を 3 つ掛ける」演算は偶数にのみ適用され、値を迅速に増やすことができますが、整数の限られたサブセットにのみ適用されます。 決定論的な減少と条件付き成長操作の間の相互作用により、単純な方法で単調ではない状態空間が作成されます。 

各テスト ケースは独立しており、どちらの数値も 10 億に達する可能性があります。 これにより、考えられるすべての状態をシミュレートしようとする検索戦略は即座に除外されます。 最大 10,000 のテスト ケースにわたって分岐を繰り返すと、整数にわたる BFS または DFS が実行できなくなるため、分岐係数がわずかであっても爆発的に増加します。 

単純なアプローチでは、これをグラフ到達可能性の問題として扱い、x から BFS を実行しようとする可能性があります。 これは失敗します。遷移によって値が無制限に増加する可能性があるため、状態空間は明らかに有限ではありません。 たとえば、2 から開始して 3 に進み、次に 2 に戻り、再び 3 にというようにサイクルを形成することができます。このサイクルは、慎重に制限しない限り、単純な BFS が無限に探索することになります。 

もう 1 つの微妙な問題は、「3/2 を掛ける」演算が単純な整数を保持する方法では元に戻せないことです。 y から x にプロセスを逆にしようとすると、あいまいさに直面します。多くの値が異なるパスの下で同じターゲットにマップされる可能性がありますが、整数制約の下ではすべてが有効な先行値であるわけではありません。 

正しい解決策は、構造が十分に制御されているため、y からの貪欲な逆推論が可能であるという観察に依存しますが、それは、成長が有利になる時期と減少が優勢になる時期を理解している場合に限ります。 

## アプローチ

 ブルートフォース手法では、各整数をノードとしてモデル化し、遷移をエッジとしてモデル化します。 x から、該当する場合は両方の操作を試し、y を検索します。 各ノードは最大 2 つの近傍を生成でき、値が増加する可能性があります。つまり、より深い洞察がなければ検索スペースをしっかりと制限することはできません。 人為的に値を max(x, y) の数倍などに制限したとしても、病的なケースでは + と - の長い交互の操作が強制される可能性があります。 これにより、実際には総当たりアプローチが効果的に指数関数的に増加します。 

重要な洞察は、視点を逆転させることです。 x を前進させる代わりに、前の状態から y をどのように取得できたのかを尋ねます。 デクリメント演算は逆に「+1」となり、常に有効です。 乗算演算は「1.5 で除算」になりますが、これは結果の値が整数であり、前方条件 (偶数) が満たされる場合に限られます。 これにより、後方分岐が即座に大幅に制限されます。ほとんどの数値には有効な乗法先行関数が 1 つしかありません。 

ただし、y から逆方向に直接シミュレーションすることは依然として扱いにくいです。順方向の減分により任意の微調整が可能になるためです。つまり、システムが純粋に乗算的ではないことを意味します。 重要な構造上の観察は、デクリメントによって、選択した「ピーク」よりも下の整数の間で完全な到達可能性が得られる一方、乗算演算が大幅に上方にジャンプする唯一の方法であるということです。 したがって、問題は、x からの制御された上方拡張によって生成される到達可能な区間内に y が存在する状態に到達できるかどうかを確認することに帰着します。

これを確認するためのより操作的な方法は、x から順方向にシミュレートしますが、積極的にプルーニングします。値が y を超える場合は、それ以上の乗算は値をさらに増加させるだけであるため、デクリメントのみが役に立ちます。 したがって、意味のある唯一の上向き遷移は、y をあまりオーバーシュートしない遷移であり、y を超えると、減少することしかできません。 これにより、問題は、y からの距離に関して単調な、有界到達可能性プロセスに変換されます。 

したがって、生産的な範囲内に留まっている場合は乗算を繰り返し適用し、それ以外の場合は y に向かう減分に依存するという制御された検索を実行できます。 状態空間が小さくなるのは、およそ 2y を超える数値は役に立たないためです。これは、1.5 で繰り返し割っても、すでに直接調整に相当する長い減分チェーンを通過することなしに効率的に戻すことができないためです。

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、x から y への制御された変換をシミュレートします。 

1. x がすでに y に等しい場合、操作は必要ないため、すぐに YES を返します。 
2. x が y より大きい場合は、デクリメント演算を使用するだけで済みます。 1 を繰り返し減算できるため、y までのすべての整数に到達できるため、YES を返します。 
3. x が y より小さい場合、有益な場合は常に乗算演算を使用して x を y に向かって拡大しようとします。 
4. x は厳密に y より小さいですが、x が偶数であるかどうかを確認します。 そうであれば、乗算演算を適用した結果を計算します。 その結果が y をあまり積極的にオーバーシュートしない場合は、それを適用します。 それ以外の場合は、逆推論によって y に向かってインクリメントする方法に戻ります (順シミュレーションでは、繰り返しの構造縮小に対応します)。 
5. x が奇数で y より小さい場合、精神的に唯一利用可能な順方向演算を適用します。これは、より高度に構築された状態から減分するものです。 実装面では、奇数の状態はデクリメント シーケンスから得られるという事実に依存しているため、段階的に調整することで最も近い偶数の構造に近づきます。 
6. x が y に達するまで、またはこれ以上乗算しても修正の可能性がなく y から離れるだけであると判断するまで続行します。 

重要な基本原則は、デクリメントによって下方向への完全な接続が提供されるということです。そのため、重要な唯一の決定は、y に正確に到達する乗算展開のシーケンスを生成できるか、またはデクリメントによって y に到達可能な領域を通過できるかどうかです。 

### なぜ効果があるのか

 このシステムには方向の非対称性があります。デクリメントでは隣接する整数間の移動が可能ですが、乗算は偶数に対してのみ動作し、状態空間が拡張されます。 到達可能性を変えることなく、デクリメントの最後のブロックの前にすべての乗算ステップが発生するように、操作のシーケンスを再配置できます。 これは、デクリメント演算では、順序を無効にする方法で以前は不可能だった新しい乗算の機会が決して可能になることがないためです。 結果として、乗算を使用して x から何らかの中間値 x' に到達できるかどうか (x' ≥ y および x' が y に還元できるかどうか) を判断するだけで済みます。 y を超えるすべての整数は y に到達できるため、問題は、許可された乗法遷移を使用して y より大きい値に到達できるかどうかを確認することになります。 これにより、検索が小規模な限定された拡張プロセスに削減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x, y = map(int, input().split())

        if x >= y:
            print("YES")
            continue

        # work forward from x while possible
        seen = set()
        stack = [x]

        ok = False

        while stack:
            v = stack.pop()
            if v == y:
                ok = True
                break
            if v > y * 2:
                continue
            if v in seen:
                continue
            seen.add(v)

            # operation 1: if even, 3v/2
            if v % 2 == 0:
                stack.append(v * 3 // 2)

            # operation 2: v - 1
            if v > 1:
                stack.append(v - 1)

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```このコードは、y に対して大きくなりすぎる値を除去しながら、x から制限付き DFS を実行します。 条件`v > 2*y`これにより、過度の線形デクリメント シーケンスがなければ、乗法的な増加によりリターンが不可能になる領域を探索しないことが保証されます。 訪問済みセットは、2 と 3 などの状態間の循環を防ぎます。 

2 つの遷移は、許可された操作を直接エンコードします。 終了条件は、探索中に y に到達したかどうかをチェックします。 

## 実用的な例

 検索がどのように進化するかを理解するために 2 つのケースを追跡します。 

まず、x = 2、y = 3 を考えます。

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        t = int(input())
        for _ in range(t):
            x, y = map(int, input().split())
            if x >= y:
                print("YES")
                continue

            seen = set()
            stack = [x]
            ok = False

            while stack:
                v = stack.pop()
                if v == y:
                    ok = True
                    break
                if v > 2 * y:
                    continue
                if v in seen:
                    continue
                seen.add(v)

                if v % 2 == 0:
                    stack.append(v * 3 // 2)
                if v > 1:
                    stack.append(v - 1)

            print("YES" if ok else "NO")

    solve()
    return sys.stdout.getvalue().strip()

 ## 特殊なケース

 重大なエッジケースは、x がすでに y より大きい場合です。 デクリメントを繰り返すと常に正確な降下が可能になるため、アルゴリズムはすぐに YES を返します。 たとえば、入力`10 3`は 7 減分で自明に解くことができ、アルゴリズムは最初の比較チェックでこれを捕捉します。 

もう 1 つのエッジ ケースは、x = 1 の場合です。1 からは、乗算が適用できないため、唯一の可能な手は事実上制限されます。 y が 1 より大きい場合、他のパスからの順方向の成長に完全に依存する必要がありますが、1 から開始することは不可能です。BFS は 1 から 1 を超える値を生成しないため、アルゴリズムはこれを正しく処理します。 

3 番目のケースは、繰り返した乗算が y に正確に到達せずに y の周囲で変動する場合です。 たとえば、2 から開始して 3 を取得すると、デクリメントせずに 2 に戻ることはできません。注意深く追跡することで、訪問セットが原因で 2 と 3 の間を無限にループすることがなくなります。
