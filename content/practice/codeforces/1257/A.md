 ## 解決策
 ## 問題の理解

 1 から n までの番号が付けられた生徒の列があります。 その中で、aとbの位置に位置する2人の学生はライバルです。 体育教師は、これら 2 人の生徒間の距離を最大化したいと考えています。ここで、距離とは単に位置の絶対的な違いです。 最大 x 回のスワップを実行でき、各スワップで 2 人の隣接する学生が交換されます。 課題は、これらの交換後にライバル間で達成可能な最大距離を決定することです。 

制約を見ると、n は最大 100、x は最大 100、テスト ケースは最大 100 個あります。 これは十分に小さいため、テスト ケースごとのソリューションが O(n) または O(1) であっても非常に高速です。 複雑なデータ構造や最適化のコツは必要ありません。 ただし、どの動きが実際に距離を伸ばすかについては、慎重に検討する必要があります。 

微妙な点は、スワップでは生徒を一度に 1 つの位置だけ移動させることです。 したがって、生徒を任意の位置に即座に配置することはできません。 距離の最大増加は、利用可能なスワップの数によって制限されます。 たとえば、n = 5、x = 1、a = 3、b = 2 の場合、スワップは 1 回しか許可されないため、生徒を位置 1 と 5 に配置するだけの単純なアプローチは不可能です。 最大距離を計算するときは、スワップ制限を考慮する必要があります。 

もう 1 つのエッジ ケースは、x = 0 の場合に発生します。この場合、移動は不可能であり、距離は現在の絶対差 |a - b| にすぎません。 同様に、生徒がすでに端にいて、x が大きい場合、n - 1 がライン内の物理的な最大距離であるため、n - 1 を超えて距離を増やすことはできません。 

## アプローチ

 ブルートフォースアプローチは、考えられるすべてのスワップシーケンスをシミュレートすることです。 各テスト ケースについて、1 人の生徒を左または右に移動させ、もう 1 人の生徒を右または左に移動させて、最大 x 個のスワップ シーケンスのあらゆる組み合わせを試してみることができます。 各シーケンスの後、距離を計算します。 このアプローチは正しいですが、非常に非効率的です。シーケンスの数は x とともに指数関数的に増加します。 x = 100 の場合、これは明らかに非現実的です。 

重要な観察は、学生の正確な中間位置を気にしていないということです。 2 人のライバル間の距離のみを考慮し、スワップでは操作ごとに生徒を 1 ステップずつ移動させます。 したがって、達成できる最大距離は、利用可能なスワップの数 x と、ライン内の最大物理距離 (n - 1) の 2 つの要素によって制限されます。a と b の間の初期距離が d = |a - b| の場合、最大で x だけ増加できますが、n - 1 を超えることはできません。これにより、最適解の簡単な式が得られます。```
max_distance = min(n - 1, |a - b| + x)
```これが機能するのは、交換するたびに距離が最大で 1 増加する可能性があるためです。生徒を線の反対側に移動させることだけを考慮する必要があります。 個々のスワップをシミュレートする必要がないため、テスト ケースごとのソリューションは O(1) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^x) | O(n) | 遅すぎる |
 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケース t の数を読み取ります。 各テスト ケースは、n、x、a、b の 4 つの整数で構成されます。 
2. 各テスト ケースについて、ライバル間の現在の距離を次のように計算します。`d = abs(a - b)`。 
3. スワップ後に達成可能な最大距離を計算します。 スワップごとに距離は最大 1 増加する可能性があるため、現在の距離に x を追加します。`new_distance = d + x`。 
4. 長さ n の直線の絶対最大距離は n - 1 です。`new_distance`これを超える場合は上限を設定します。`max_distance = min(new_distance, n - 1)`。 
5. 出力`max_distance`テストケースごとに。 

機能する理由: 不変条件は、スワップごとにライバル間の距離が最大 1 だけ増加することです。初期位置から開始すると、達成可能な最大距離は、ラインの長さによって制限される、まさに初期距離とスワップの数を加算したものになります。 これにより、式があらゆるシナリオで最適な結果を取得することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, x, a, b = map(int, input().split())
    d = abs(a - b)
    max_distance = min(n - 1, d + x)
    print(max_distance)
```このソリューションでは、まずテスト ケースの数を読み取ります。 次に、それぞれのケースについて、絶対距離を計算します。`d`二人のライバルの間。 スワップ数を加算します`x`そして結果を次のようにキャップします`n - 1`行の長さを尊重するため。 結果を直接出力すると、テスト ケースごとに O(1) の作業が保証されます。 使用には細心の注意が払われています`abs(a - b)`そして`min(...)`すべてのエッジケースを正しく処理します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        n, x, a, b = map(int, input().split())
        d = abs(a - b)
        max_distance = min(n - 1, d + x)
        print(max_distance)
    return output.getvalue().strip()

 ## 特殊なケース

 x = 0 の場合、アルゴリズムは初期距離を正しく返します。 例えば、`n = 6, x = 0, a = 2, b = 3`与える`abs(2-3) = 1`。 スワップはできないので距離は伸びません。 1 < n - 1 = 5 であるため、min 関数は値を変更しません。 

初期位置が両端にある場合、`n = 100, x = 50, a = 1, b = 100`、距離はすでに 99 で最大になっています。x を追加すると 149 になりますが、min 関数の上限は 99 です。これは、アルゴリズムがラインの物理的制約を尊重していることを示しています。 

最低限のラインとしては、`n = 2, x = 0, a = 1, b = 2`、距離は 1 です。スワップは不可能であり、距離は n - 1 = 1 を超えることはできません。出力は期待どおりです。 

これらすべてのチェックでは次の式が示されます。`min(n - 1, abs(a - b) + x)`特別な条件ロジックを使用せずに、エッジケースを正しく処理します。
