 ## 解決策
 ## 問題の理解

 整数の固定配列が与えられます。 単一の整数を選択できます`x`XOR を使用してそれをすべての要素に適用します。 この変換後、それぞれの元の値は`a_i`になる`b_i = a_i XOR x`。 

目標は、結果の数値を等しくすることではなく、より弱くすることです。結果の数値すべてが、バイナリ表現で同じ数の設定ビットを持つようにしたいのです。 つまり、すべての要素に同じ XOR シフトを適用した後、すべての数値のポップカウントが同じになる必要があります。 

タスクは、そのようなかどうかを判断することです。`x`存在し、存在する場合は有効なものを出力します。 

主な問題は、XOR がポップカウントに関して非常に非線形な方法でビットを変更することです。 単一ビットの反転`x`さまざまな影響を与える`a_i`結果として得られるポップカウントは加算的でも単調的でもありません。 

制約は十分に厳しいので、慎重に縮小された構造に対してのみ指数関数的な検索を強制できます。 と`n ≤ 100`最大 30 ビットの値、すべてをテストしようとするアプローチ`x`値は存在するため不可能です`2^30`候補者たち。 一つ一つチェックしても`x`必要`O(n)`、とても強引です`x`実行不可能です。 

多くの数値がすでに同様の構造を持っているものの、XOR によるポップカウントのシフトがわずかに異なる場合、より微妙なエッジ ケースが発生します。 単純なアイデアは、各数値を個別にターゲットのポップカウントに合わせることです。しかし、それは同じであるというグローバルな制約を無視します。`x`すべての要素に対して同時に機能する必要があります。 

## アプローチ

 直接的な総当たり攻撃はあらゆる可能性を試みるでしょう`x`で`[0, 2^30)`そしてすべてを計算します`b_i = a_i XOR x`、すべてのポップカウントが等しいかどうかを確認します。 これは正しいですが、遅すぎます。候補は最大約 10 億あり、各チェックには最大 100 回の操作が必要となり、結果として`10^11`操作。 

重要な点は、検索する必要がないということです。`x`直接。 代わりに、条件をペアごとに書き換えることができます。 すべての最終数値が同じポップカウントを持つ場合、どのペアでも`(i, j)`私たちは次のものを持たなければなりません:`popcount(a_i XOR x) = popcount(a_j XOR x)`。 

これは、参照要素を選択したら、次のようになります。`a_0`、他のすべての要素は変換後に一致する必要があります。 したがって、条件は次のようになります。`popcount(a_i XOR x) = popcount(a_0 XOR x)`みんなのために`i`。 

この考えを整理すると、構造的な解釈が得られます。私たちは、`x`すべての数値を関数の同じレベルのセットにマッピングします`f_x(a) = popcount(a XOR x)`。 

重要な単純化は、答えが数値間の絶対値ではなく、数値間の相対的な変換のみに依存するということです。`x`。 ペア間で変換されたマスクを定義すると、中間一致法または数値間の差異から導出された候補のサブセットのハッシュを使用して検索スペースを縮小できます。 

より具体的で実装可能な観点は、結果として得られるポップカウント値の候補を修正することです。`k`変換された配列の場合。 それからそれぞれ`a_i`～に制約を課す`x`:`popcount(a_i XOR x) = k`。 固定用`a_i`、のセット`x`これを満たすものは構造化されており、30 ビット以上のビット DP を使用して効率的に列挙できますが、これをすべてに対して実行します。`i`同時に交差する制約も必要になります。 

高次元の制約を直接交差させる代わりに、視点を反転して、次のように構築しようとします。`x`少しずつですが、グローバルなポップカウントの依存関係により、これも複雑になります。 意図したソリューションは代わりにそれを利用します`n`は小さいため、解決策を 1 つの要素に固定し、問題をポップカウントの等価性の下での相対的な XOR の差の一貫性をチェックすることに変換できます。 

固定ピボットの場合`a_0`、 定義する`d_i = a_i XOR a_0`。 それから：`popcount(a_i XOR x) = popcount((a_0 XOR x) XOR d_i)`。 

させて`y = a_0 XOR x`。 すると条件は次のようになります。`popcount(y XOR d_i)`全体的に一定である`i`。 

ここで問題は次のとおりです。`y`固定マスクを使用して XOR を適用するなど`d_i`すべてのポップカウントを等しくしますか? 以来`d_0 = 0`、私たちは必要とします`popcount(y)`等しい`popcount(y XOR d_i)`みんなのために`i`。 これは最大 100 ビットマスクにわたる対称制約となり、マスクのペアごとの差から導出される候補変換を列挙することで解決できます。 中間者会議のアイデアは有効です`y`すべてではなく、これらの制約によって引き起こされる小さな構造化セット内に存在する必要があります。`2^30`可能性。

 ## アルゴリズムのチュートリアル

 固定参照要素を使用して、変換された条件に基づいて構築します。 

1. 最初の要素を選択します`a_0`すべての差分マスクを計算します`d_i = a_i XOR a_0`。 これにより、問題は単一の値を見つけることに変換されます。`y`すべてがそうであるように`popcount(y XOR d_i)`等しいです。 この正規化により、絶対値への依存が排除されます。 
2. この条件では、変換された値のすべてのペアが等しいことが必要であることがわかります。 どれについても`i, j`、私たちは持っている必要があります`popcount(y XOR d_i) = popcount(y XOR d_j)`。 これは、関数が`f_i(y) = popcount(y XOR d_i)`すべて同じです`i`。 
3. すべての制約を一度に適用するのではなく、インデックスを 1 つ選択します。`j`そしてそれとの平等を強制します。 これにより、状態が次のように減少します。`popcount(y XOR d_i) = popcount(y XOR d_j)`みんなのために`i`、これはペアごとの制約のシステムになります。 
4. それぞれの等式を構造上の制約に変換します。`y`。 固定ペアの場合`(d_i, d_j)`、等価性はビットのみに依存します。`d_i`そして`d_j`異なる。 これにより、完全な整数ではなく、ビット位置に対して段階的に制約を構築できるようになります。 
5. ビットを 2 つの半分に分割することにより、30 ビット空間でミートインザミドルを使用します。 半分の割り当てごとに、すべての割り当ての誘導署名を計算します。`popcount(y XOR d_i)`寄付はその半分に制限されます。 半分の署名をハッシュ マップに保存します。 
6. 後半では、相補的な署名を計算し、前半から一致する署名が存在するかどうかを確認します。 一致は完全に一致します`y`すべての制約を満たしていること。 
7. 有効になったら`y`見つかった、回復する`x = a_0 XOR y`そしてそれを出力します。 

### なぜ効果があるのか

 この変換により、問題はビットマスクを見つけることだけになります。`y`関数のコレクションを等化する`popcount(y XOR d_i)`。 それぞれのビット`y`XOR がそれぞれにどのように影響するかに独立して寄与します。`d_i`したがって、ビットスペースを分割すると、部分的な寄与の一貫性が維持されます。 最終的な等価条件は集計されたポップカウントの寄与のみに依存し、素のビット セット間で加算されるため、中間一致が機能します。 有効なグローバル ソリューションはすべて、分割全体で一貫して分解する必要があるため、半角スペースを検索することで完全性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

base = a[0]
d = [x ^ base for x in a]

# split bits: 15 + 15 (since 30 bits total)
L = 15
R = 30 - L

left_map = {}

def get_signature(mask, y):
    # compute popcount(y XOR mask)
    return (y ^ mask).bit_count()

# enumerate left half
for yL in range(1 << L):
    sig = tuple(get_signature(d[i], yL) for i in range(n))
    left_map.setdefault(sig, yL)

ans = -1

# enumerate right half
for yR in range(1 << R):
    sig = tuple(get_signature(d[i], yR) for i in range(n))
    if sig in left_map:
        yL = left_map[sig]
        y = yL | (yR << L)
        x = base ^ y
        if all((ai ^ x).bit_count() == (a[0] ^ x).bit_count() for ai in a):
            ans = x
            break

print(ans)
```実装では、最初に差分マスクを構築し、すべてをアンカーします。`a[0]`。 中間者を満たすステップでは、部分的な割り当てに基づいて署名を構築します。`y`。 各署名は、部分的な`y`固定マスクに関連するすべてのポップカウントに影響します。 辞書には左半分の署名が保存され、右半分がそれと照合されます。 

理論的には署名の衝突が発生する可能性があるため、最後の検証ステップが必要です。 正確性を確保するために完全な条件を再計算します。

小さな値を試してみる:

 | y | ポップカウント(y) | y XOR 5 | ポップカウント(y XOR 5) |
 | --- | --- | --- | --- |
 | 0 | 0 | 5 | 2 |
 | 1 | 1 | 4 | 1 |

 私たちは見つけます`y = 1`動作します。 それから`x = 7 XOR 1 = 6`。 ただし、有効な解決策はどれでも受け入れられます。 サンプル出力`1`、これはグローバルに適用された場合にも条件を満たします。 

このトレースは、一定の数値に等しいことを強制しているのではなく、すべての要素にわたる一貫性だけを強制していることを示しています。 

### 例 2

 入力:```
3

```修理`a0 = 1`、 それで`d = [0, 3, 5]`。

これは、このメソッドが値を強制するのではなく、構造的に互換性のない構成を拒否することを示しています。

 ## 特殊なケース

 重要なエッジケースは、すべての数値が同一である場合です。 その状況では、いずれにしても、`x`同一の変換値が生成されるため、正しい出力には次のものが含まれます。`0`。 ゼロ以外の変換を常に検索する単純なソルバーは、ここで失敗する可能性があります。 

数値が 1 ビットだけ異なる場合、別の特殊なケースが発生します。 例えば`a = [0, 1]`。 に応じて`x`、両方とも整列している場合も整っていない場合もあり、候補マスクの不適切な枝刈りにより、有効なソリューションが誤って削除される可能性があります。 このアルゴリズムは、ローカル ビット アライメントではなく完全な署名の一貫性を考慮するため、これを処理します。 

最後のエッジケースは、複数の異なる場合に発生します。`y`値により、中間分割の半分で同一の署名の衝突が発生します。 このため、回答を受け入れる前に完全な状態を最終的に確認する必要があります。
