 ## 解決策
 ## 問題の理解

 単一の文字列として表される通りが与えられます。 各文字は 1 つの駐車スロットを表します。 ダッシュはスロットが空いていることを意味し、X はスロットがすでにブロックされており使用できないことを意味します。 

車両は連続した空きスロットにのみ配置できます。 各自動車はちょうど 1 つのスロットを占有し、SUV はちょうど 2 つの隣接するスロットを占有し、トラックはちょうど 4 つの隣接するスロットを占有します。 車両は重なり合わず、ブロックされた位置を使用できません。 タスクは、これら 3 つの車両タイプを使用して、すべての空きスロットを何回完全に埋めることができるかを数えることです。 

重要な点は、シーケンス内でどの特定の車両が到着するかを選択していないということです。 代わりに、空きスロットのすべての最大の連続セグメントをサイズ 1、2、または 4 のタイルでタイル表示します。少なくとも 1 つのスロットが異なるタイプの車両によって占有されている場合、2 つの充填は異なります。これは、長さ 1、2、および 4 への異なるセグメント化に相当します。 

入力には、このような街路の説明が複数含まれる場合があり、それぞれが別の行にあり、行ごとに 1 つの整数、つまりその行の有効な構成の数を出力する必要があります。 

各行が最大 70 文字であるという制約は、複雑さに関する主なシグナルです。 長さ 70 の空きセグメントでも膨大な数のパーティションが存在するため、すべてのプレースメントに対する単純な指数関数的な検索は爆発してしまいます。 代わりに、セグメントごとに線形または最悪の場合でも二次動的計画法が必要です。 70 は小さいため、1 行あたり O(n²) であっても安全ですが、構造は標準的な線形再帰で十分であることを示唆しています。 

主なエッジケースは、ブロックされたセルが問題をどのように分割するかです。 文字列全体を 1 つのセグメントとして扱う単純なアプローチでは、車両が X 境界を越えることが誤って許可されてしまいます。 

たとえば、次のように考えてみましょう`-X-`。 各辺が独立しており、各セグメントにはセルが 1 つだけあるため、正解は 1 です。 文字列全体に対する単純な DP は、X を横切って長さ 2 の車両を誤って配置しようとする可能性がありますが、これは無効です。 

もう 1 つの微妙なケースは、セグメントが 4 より短い場合です。たとえば、`----`複数の可能性がありますが、`---`トラックを配置できないため、より小さな組み合わせのみが重要になります。 どのソリューションもセグメント境界を厳密に尊重する必要があります。 

## アプローチ

 ブルートフォース ソリューションでは、すべての自由な位置から開始して車両を再帰的に配置しようとし、適合するたびにサイズ 1、2、または 4 の選択肢に分岐します。 これは、有効なタイリングをすべて直接列挙するため、正しいです。 ただし、長さ n のセグメントでは、各位置の分岐係数は最大 3 であり、最悪の場合、およそ O(3ⁿ) 個の状態になります。 メモ化を使用しても、不用意に実装すると、部分的に満たされた構成の大きな状態空間が探索されることになります。 

重要な観察は、問題がその線に沿って最適な部分構造を持っているということです。空きセグメントの最初の部分がどのように埋められるかを修正すると、残りの接尾辞は独立します。 これにより、問題は 1 次元のタイリング数に変わります。 長さ i のプレフィックスに関して重要なのは、正確に i で終わる有効なタイル サイズを使用してプレフィックスを何通り形成できるかということだけです。 

これにより、各空きセグメントが単純な動的プログラミングの繰り返しに縮小されます。 f[i] を長さ i の空きセグメントを満たす方法の数とする。 最後に配置された車両の長さは 1、2、または 4 でなければならないため、最後のステップは、これらのインデックスが有効な場合は常に f[i−1]、f[i−2]、または f[i−4] から取得されます。 これにより、指数関数的な分岐が線形スキャンに折りたたまれます。 

次に、通り全体を X ブロックごとに分割します。 各最大空きセグメントは独立して解決され、異なるセグメントでの選択は相互作用しないため、最終的な答えはセグメント結果の積となります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 配置に対するブルート フォース再帰 | セグメントあたり O(3ⁿ) | O(n) 再帰スタック | 遅すぎる |
 | 1D 再発によるセグメント DP | セグメントあたり O(n) | O(n) または O(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列を最大の連続ブロックに分割します。`-`。 X セルは車両が通過できないハードセパレータとして機能するため、各ブロックは独立したサブ問題です。 
2. 長さ L のブロックごとに、サイズ 1、2、および 4 のビークルを使用してブロックをタイル化する方法の数を計算します。 dp[i] が長さ i のプレフィックスを埋める方法の数を表す DP 配列を定義します。 
3. dp[0] = 1 を初期化します。これは空のプレフィックスを表し、有効な構成が 1 つだけあります。 
4. 1 から L までの各 i について、最後に配置された車両を考慮して dp[i] を計算します。 車を配置すると、スロットが 1 つ消費され、dp[i−1] が寄与します。 SUV を配置すると、2 つのスロットが消費され、dp[i−2] が寄与します。 トラックを配置すると、4 つのスロットが消費され、dp[i−4] が寄与します。 負のインデックスを持つ用語は無効な配置に対応するため、無視されます。 
5. このセグメントの結果を全体的な答えに乗算します。 セグメントは独立しているため、構成の総数はすべてのセグメントの DP 結果の積になります。 
6. 各入力ラインの最終結果を出力します。 

### なぜ効果があるのか

 正確さは、すべての有効なタイリングが各プレフィックス内に一意に定義された最後の車両を持っているという事実から得られます。 長さ i のタイリングは、許可されている車両サイズのいずれかで終わる必要があり、その最後の車両を削除すると、より小さなプレフィックスの有効なタイリングが残ります。 これにより、長さ i の完全なタイリングと、最終的な 1 つの配置によって拡張された長さ i-1、i-2、および i-4 のタイリングの結合との間に全単射が作成されます。 どの車両も X を横切ることができないため、セグメント間の独立性が続き、あるセグメントの構成が別のセグメントに影響を与えることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(s: str) -> int:
    MOD = None  # no modulo in problem; values fit in 1e18

    n = len(s)
    ans = 1

    i = 0
    while i < n:
        if s[i] == 'X':
            i += 1
            continue

        j = i
        while j < n and s[j] == '-':
            j += 1

        length = j - i

        if length == 0:
            i = j
            continue

        dp = [0] * (length + 1)
        dp[0] = 1

        for k in range(1, length + 1):
            total = 0
            total += dp[k - 1]
            if k >= 2:
                total += dp[k - 2]
            if k >= 4:
                total += dp[k - 4]
            dp[k] = total

        ans *= dp[length]

        i = j

    return ans

def main():
    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue
        print(solve_case(line))

if __name__ == "__main__":
    main()
```この実装では、セグメンテーション ロジックが直接反映されます。 外側のループは空きブロックを分離し、無効なブロック間配置が発生しないようにします。 各ブロック内の DP は、許可された車両サイズにわたる反復を直接変換したものです。 前述のように、最終的な答えは 10^18 以内に収まることが保証されているため、乗算ステップは安全です。 

よくある実装上の間違いは、セグメントごとに DP をリセットするのを忘れることです。これにより、独立したブロック間の状態が誤って混合されてしまいます。 もう 1 つは、k < 4 の場合に dp[k−4] のような遷移を誤って許可してしまうことであり、これは明示的に保護する必要があります。 

## 実用的な例

 ### 例 1:`--`長さ 2 の単一セグメントがあります。 

| k | dp[k-1] | dp[k-2] | dp[k-4] | dp[k] |

 | 1 | dp[0]=1 | - | - | 1 |
 | 2 | dp[1]=1 | dp[0]=1 | - | 2 |

 このセグメントは、2 台の乗用車または 1 台の SUV の 2 つの構成に貢献します。 

セグメントが 1 つしかないため、出力は 2 になります。 

このトレースは、プレフィックスの再利用によって重複する選択肢がどのように自然に蓄積されるかを示しています。 

### 例 2:`---`セグメントの長さは 3 です。 

| k | dp[k] |
 | --- | --- |
 | 1 | 1 |
 | 2 | 2 |
 | 3 | 3 |

 3 つの構成は、3 台の車、1 台の SUV といずれかの順序で車 1 台です (2 つの配置)。 トラックは4スロット必要なので不可。 

この例では、繰り返しにより無効な大きなプレースメントが自動的に除外されることを確認します。

 ## 特殊なケース

 次のような完全にブロックされた文字列の場合`XXXX`、空きセグメントがないため、アルゴリズムは 1 を生成します。そのため、ゼロ セグメントの積は 1 のままです。これは、何もしない方法が 1 つだけあるという解釈と一致します。 

のような文字列の場合`-X--X---`の場合、アルゴリズムはそれを長さ 1、2、および 3 のセグメントに分割します。それぞれは独立して解決され、最終的な答えは DP 結果の積になります。 これにより、セグメンテーションにより DP 内の制約ではなく構造的に正確さが強制されるため、偶発的な境界を越えた配置が回避されます。
