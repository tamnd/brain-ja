 ## 解決策
 ## 問題の理解

 タスクは、トレプ ルールを使用して二分探索ツリーを維持することです。 各ノードには、検索ツリー内での位置を決定するキーと、優先順位のように機能する高さの値があります。 高さは常にルートに近くなければならないため、すべての親の高さは子よりも低くなります。 

入力は、最初は空のツリーに適用される一連のコマンドです。 挿入により新しいキーと高さが与えられ、treap ルールが必要とする場所にノードを正確に配置する必要があります。 削除では、残りの構造を維持したままキーが削除されます。 印刷操作では、必要な再帰表現を使用してツリーが出力され、すべてのノードが次のように表示されます。`key/height`そしてその子を再帰的に表示します。 

重要な問題は、通常の二分探索ツリーの挿入では十分ではないことです。 葉にノードを追加すると高さの順序に違反する可能性があるため、挿入ではツリーの一部を再構築する必要があります。 この制約により、最大のキーを使用して多くの操作が可能になります。$10^5$までの高さ$10^9$。 更新ごとにすべてのノードをウォークスルーするソリューションは、多くのコマンドが処理されると二次的になります。 各変更はツリーの高さのみを変更する必要があります。ツリーの高さは高い確率でバランスが保たれるため、対数的になることが予想されます。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

挿入されたノードの高さが最も小さい場合、それがルートになります。 例えば：```
ADD 5 10
ADD 3 1
PRINT
```出力は次のとおりです。```
3/1(,5/10)
```常にキーで挿入するソリューションでは、誤って保持されてしまいます。`5`根として。 

2 つの子を持つノードを削除するには、単にノードを削除するだけでなく、残りの 2 つの側面を結合する必要があります。 例えば：```
ADD 2 2
ADD 1 1
ADD 3 3
DEL 2
PRINT
```正しい出力は次のとおりです。```
1/1(,3/3)
```不注意に削除すると、無効なツリーが残ったり、1 つのサブツリーが失われる可能性があります。 

分割操作にも境界条件があります。 キーによる分割`k`鍵を置かなければなりません`k`それ自体が左の結果にあります。 比較が次から変更された場合`<=`に`<`、既存のキーの周囲に挿入や削除を行うと、間違ったツリーが生成されます。 

## アプローチ

 直接的な解決策では、ツリーを通常の二分探索ツリーとして保存し、すべての操作を再帰的にシミュレートします。 キーによる検索が簡単で、挿入するとノードをリーフとして配置できます。 問題は、リーフの挿入で高さが無視されることです。 一連のキーの増加と高さの増加によってチェーンが作成されます。```
1
 \
  2
   \
    3
     \
      4
```後$n$挿入では、単一の操作が横断する可能性があります$O(n)$ノード、与える$O(n^2)$すべてのコマンドを処理します。 

重要な観察は、高さの値がノードが属する場所をすでに示しているということです。 トレプ内の高さが最も小さいノードがルートである必要があります。 小さいキーを持つすべてのノードは左側のサブツリーに属し、大きいキーはすべて右側のサブツリーに属します。 これは、2 つの基本的な操作を組み合わせることによって treap を変更できることを意味します。`split`トリープをキーを中心とした 2 つの有効なトリープに分割します。`join`最初のすべてのキーが 2 番目のすべてのキーよりも小さい 2 つの有効な treap を結合します。 再帰呼び出しごとにツリーの片側が破棄されるため、どちらの操作も 1 つのパスを再帰的に移動します。 期待されるトレプの高さは対数であるため、これらの操作は効率的です。 

挿入は新しいキーを中心に分割され、新しい単一ノードが作成されてから、それらの部分が再び結合されます。 削除はターゲット ノードを分離する 2 つの分割になり、その後、残りの部分が 1 つ結合されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | Treap 分割/結合 | O(q log n) が期待されます | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノードを挿入するには`(k, h)`、現在のトレプを次のように分割します。`k`。 左側のツリーには、以下のすべてのキーが含まれます。`k`、右側のツリーには、より大きなキーがすべて含まれています。 これにより、二分探索木に必要な正しい分離が作成されます。 
2. のみを含む新しいトレプを作成します。`(k, h)`。 左側の部分をこのノードと結合し、その結果を右側の部分と結合します。 結合操作では高さを使用してルートが選択されるため、高さの条件が自動的に復元されます。 
3. キーを削除するには`k`、ツリーを分割します`k`、最大のキーを含む左側の部分を生成します。`k`そして右側の部分には大きなキーが含まれています。 
4. 左側の部分を次のように分割します。`k - 1`。 2 番目の分割では、キーを持つ単一のノードからすべての小さいキーを分離します。`k`。 
5. 孤立したノードを破棄し、残りの 2 つのツリーを結合します。 左側のツリーのすべてのキーは右側のツリーのすべてのキーよりも小さいため、結果は有効なトリープになります。 
6. 印刷の場合、現在のノードを再帰的に印刷します。 子が欠落している場合は、空の位置を出力します。 それ以外の場合は、子サブツリーを括弧内に出力します。 

なぜ効果があるのか:

 不変条件は、すべてのサブツリーが常に両方の treap プロパティを満たすことです。つまり、キーは二分探索ツリーの順序に従い、高さはヒープの順序に従います。`split`は、影響を受けるパスを再帰的に再構築するときに親子関係のみを変更するため、これを保持します。`join`ルートは 2 つの入力ツリーの中で最も高さが低いノードである必要があり、再帰呼び出しは残りのサブツリーに対して同じ推論を継続するため、これを保持します。 挿入と削除はこれらの有効な操作のみで構成されるため、すべての中間ツリーと最終ツリーは正しいツリーのままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("key", "height", "left", "right")

    def __init__(self, key, height):
        self.key = key
        self.height = height
        self.left = None
        self.right = None

def join(a, b):
    if a is None:
        return b
    if b is None:
        return a

    if a.height < b.height:
        a.right = join(a.right, b)
        return a
    else:
        b.left = join(a, b.left)
        return b

def split(root, key):
    if root is None:
        return None, None

    if root.key <= key:
        left_part, right_part = split(root.right, key)
        root.right = left_part
        return root, right_part
    else:
        left_part, right_part = split(root.left, key)
        root.left = right_part
        return left_part, root

def add(root, key, height):
    left, right = split(root, key)
    return join(join(left, Node(key, height)), right)

def delete(root, key):
    middle, right = split(root, key)
    left, _ = split(middle, key - 1)
    return join(left, right)

def build_string(root):
    if root is None:
        return ""

    value = f"{root.key}/{root.height}"

    if root.left is None and root.right is None:
        return value

    return value + "(" + build_string(root.left) + "," + build_string(root.right) + ")"

def solve():
    root = None
    out = []

    for line in sys.stdin:
        if not line.strip():
            continue

        cmd = line.split()

        if cmd[0] == "ADD":
            root = add(root, int(cmd[1]), int(cmd[2]))
        elif cmd[0] == "DEL":
            root = delete(root, int(cmd[1]))
        else:
            out.append(build_string(root))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`Node`クラスには、treap プロパティに必要な情報のみが格納されます。 すべての変更が影響を受けるパスを再帰的に再構築できるため、親ポインターや追加のメタデータは必要ありません。`split`is the core operation. 現在のノードが左側の結果に属している場合、より大きなキーを右側の結果に移動する必要がある可能性があるため、その右側の子をさらに分割する必要があります。 対称の場合は、分割キーより大きいノードを処理します。`join`最小の高さがルートになる必要があるため、高さを比較します。 負けた側はそのルートの下に再帰的に接続されます。 比較の方向は誤って逆転しやすく、必要な最小ヒープではなく最大ヒープが作成されてしまいます。 

削除の用途`split(root, key)`に続く`split(left_side, key - 1)`。 キーは整数であり一意であるため、これにより 1 つのノードが正確に分離されます。 使用する`key`2 番目の分割では、削除されたノードが誤って保持されてしまいます。 

Python の整数はオーバーフローしないため、高さの値が大きくても安全です。 トレプは高い確率でバランスが保たれているため、再帰の深さは対数のままであると予想されます。 

## 実用的な例

 次のことを考慮してください。```
ADD 1 23
ADD 2 19
ADD 4 95
ADD 6 13
```状態は次のように変化します。 

| 操作 | ルート | 左のサブツリー | 右のサブツリー |
 | --- | --- | --- | --- |
 | 1 23 を追加 | 1/23 | 空 | 空 |
 | 2 19 を追加 | 2/19 | 1/23 | 空 |
 | 4 95 を追加 | 2/19 | 1/23 | 95/4 |
 | 6 13 を追加 | 6/13 | 2/19 | 空 |

 最後の挿入場所`6`高さが最も低いため根元にあります。 前のルートは左側のサブツリーの一部になります。これは、すべての小さいキーがそ​​の側に残らなければならないためです。 

別の例:```
ADD 1 74
ADD 2 23
ADD 3 91
ADD 4 43
DEL 2
```| 操作 | ルート | 重要な変更 |
 | --- | --- | --- |
 | 1 74 を追加 | 1/74 | 初期ノード |
 | 2 23 を追加 | 2/23 | New smaller height becomes root |
 | 3 91 を追加 | 2/23 | 右側に追加 |
 | 4 43 を追加 | 2/23 | Height 43 moves above 3/91 |
 | デル2 | 4/43 | Left and right parts are joined |

 これは、削除によってノードが恣意的に置き換えられるわけではないことを示しています。 結合操作は、両方の順序付けルールを満たす唯一のツリーを再構築します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q log n) が期待されます | すべての分割と結合は 1 つの treap パスに従い、各コマンドは一定数の treap パスを使用します。 |
 | スペース | O(n) | 各ノードは 1 回保存され、予期される対数スタック スペースを使用した再帰が行われます。 |

 The constraints require avoiding linear scans. treaps の予想される対数動作により、すべてのコマンドが入力サイズに対して十分に効率的になります。

 ## 特殊なケース

 新しいノードの高さが最も低い場合、既存のすべてのノードはその下に移動する必要があります。 入力の場合:```
ADD 5 10
ADD 3 1
PRINT
```最初の分割では、古いツリーを新しいキーの位置から分離します。 新しいノードには高さがあります`1`、 それで`join`それを根元にします。 出力は次のとおりです。```
3/1(,5/10)
```2 つの子を持つノードを削除する場合、残りの両方の側が存続する必要があります。 のために：```
ADD 2 2
ADD 1 1
ADD 3 3
DEL 2
PRINT
```最初の分割では、ルートと右側が分離されます。 2 番目の分割により、左側の子が分離されます。 残りのツリーを結合すると、以下が作成されます。```
1/1(,3/3)
```このアルゴリズムは手動で置換を選択することはないため、高さの順序が崩れるのを防ぎます。 

よくある 1 つ違いの間違いは、削除中の 2 番目の分割です。 コマンド:```
DEL 2
```キーのみを削除する必要があります`2`、すべてのキーが次の値に達するわけではありません`2`。 2 番目の分割では、`key - 1`、左側のツリーにすべての小さなキーを残し、ターゲット ノードだけを分離します。 これにより、すべてのキーが保存され、最終的な結合が有効に保たれます。
