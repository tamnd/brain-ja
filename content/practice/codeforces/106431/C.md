 ## 解決策
 ## 問題の理解

 この問題では、一連のコマンドが実行されている間、二分探索ツリーを維持することが求められます。 ツリーは空から始まります。 挿入コマンドは、通常の二分探索ツリー規則に従って新しいキーを正しいリーフ位置に配置しますが、キーがすでに存在する場合は操作を無視します。 削除コマンドは、キーが存在する場合、標準の BST 削除ルールを使用してキーを削除します。つまり、ノードをその順序の先行者によって 2 つの子に置き換えます。 print コマンドは、再帰的な括弧で囲まれた表現を使用して現在のツリーを出力するように要求します。 

入力は、単一の静的ツリーではなく、操作のストリームです。 各操作により、後の操作で観察される構造が変更されます。 すべての印刷要求後の出力はツリーの正確な形状であるため、キーのセットを保存するだけでは十分ではありません。 親子関係は維持する必要があります。 

制約はシミュレーションを中心に設計されています。 操作の数が非常に大きくなり、コマンドごとにツリー全体を再構築するのは無駄になる可能性があります。 約 100,000 の操作がある場合、すべての操作に対してすべての既存のノードをスキャンするアプローチでは、最悪の場合でも約 10^10 の操作に達する可能性があり、これは一般的な 1 秒の制限をはるかに超えています。 意図されたアプローチは、各ツリーの変更をツリーの現在の高さに比例させることです。 二分探索ツリーはチェーンになる可能性があるため、最悪の場合の高さは O(n) ですが、実際の制限要因はコマンドの総数であり、余分な完全な走査を避ける必要があります。 

扱いにくいケースは、主に削除と印刷に関するものです。 たとえば、リーフを削除するには、そのノードを正確に削除する必要があります。```
ADD 5
ADD 3
DEL 3
PRINT
```出力は次のとおりです。```
5
```ノードを削除済みとしてマークするだけで、親ポインターを切断しない不注意な実装でも、古い子が出力される可能性があります。 

2 つの子を持つノードを削除することもよくある間違いです。```
ADD 5
ADD 3
ADD 7
ADD 4
DEL 5
PRINT
```正しい出力は次のとおりです。```
4(3,7)
```5 の前任者は 4 なので、5 は 4 に置き換えられます。代わりに後続者を選択する実装では、別のツリーが作成されます。 

空のツリーも可能です。```
DEL 10
PRINT
```出力は次のとおりです。```

```キーが存在しないため、削除しても何も行われません。 空のツリーを出力すると、特別なマーカーではなく、空の行が生成されます。 

## アプローチ

 直接的な解決策は、すべてのノードをそのキーと左右の子へのポインタで表すことです。 挿入の場合は、ルートから開始して、空の子の位置が見つかるまで、新しいキーと現在のノードを繰り返し比較します。 これはまさに BST の定義方法なので、手順は正しいです。 削除の場合、ノードを検索し、子がない、子が 1 つ、または子が 2 つの 3 つのケースを処理します。 印刷は、必要な形式に従った単なる再帰的な走査です。 

強引なアプローチは、すべてのキーを配列に保存し、コマンドによってツリーが変更されるたびにツリーを再構築することです。 同じキーを同じ順序で挿入すると同じ BST が再構築されるため、これは依然として正しいと考えられます。 ただし、コマンドごとに再構築するには O(n) の作業量がかかります。 最大 100,000 回の操作では、これはおよそ O(n²) になる可能性があり、これでは遅すぎます。 

重要な点は、BST 操作では、ルートから影響を受けるキーまでのパスを検査するだけでよいということです。 ツリーの残りの部分はすでに有効な状態にあるため、変更する必要はありません。 ノードを削除しても、削除されたノードの周囲の少数のリンクが変更されるだけです。 これにより、すべての更新が高さのトラバースに減少します。 

残る課題は印刷です。 構造全体を出力する必要があるため、print コマンドはすべてのノードを訪問する必要があります。 出力自体にツリー全体が含まれるため、このコストは避けられません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合の O(q²) | O(n) | 遅すぎる |
 | 最適 | O(qh + 印刷されたノードの合計) | O(n) | 承認済み |

 ここで、q はコマンドの数、h は現在のツリーの高さです。 

## アルゴリズムのチュートリアル

 1. キーとその左右の子への参照を含むノードを使用してツリーを保存します。 ルート ノードへの参照を保持します。 ツリー構造自体は、将来の操作に必要な情報です。 
2. ADD 操作の場合は、ルートから開始して、新しいキーを訪問した各ノードと比較します。 左に移動するとキーが小さくなり、右に移動するとキーが大きくなります。 次の子ポインタが空の場合は、そこに新しいノードをアタッチします。 検索中にキーが見つかった場合は、重複は無視されるため停止します。 
3. DEL 操作の場合、親ノードを記憶しながらターゲット キーを検索します。 鍵を紛失した場合はすぐにご返却ください。 ノードに子がない場合は、対応する親ポインタを削除します。 子が 1 つある場合は、親をその子に直接接続します。 
4. 削除されたノードに 2 つの子がある場合は、その左側のサブツリーで右端のノードを見つけます。 このノードは削除されたキーよりも小さい最大のキーであるため、削除されたノードをそれに置き換えることで BST の順序付けが有効に保たれます。 前の場所から前のノードを削除し、子を再接続します。 
5. PRINT 操作の場合、表現を再帰的に生成します。 ノードが欠落していると、空の文字列が返されます。 リーフはそのキーのみを提供します。 他のノードは、そのキーに続いてその子の表現を提供します。 

これが機能する理由: 不変条件は、すべての変更の後でも、すべてのノードが依然として二分探索ツリーの順序付けルールを満たしていることです。 新しいノードは最初の有効な空の位置に正確に配置されるため、挿入ではそのノードが保持されます。 2 つの子ノードをその順序の先行ノードと置き換えると、すべての左側のサブツリー値が小さくなり、すべての右側のサブツリー値が大きくなるため、削除によってこのノードが保存されます。 印刷では維持された構造が読み取られるだけなので、出力には常に現在のツリーが記述されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

class Node:
    __slots__ = ("key", "left", "right")
    def __init__(self, key):
        self.key = key
        self.left = None
        self.right = None

root = None

def add(key):
    global root
    if root is None:
        root = Node(key)
        return

    cur = root
    while True:
        if key == cur.key:
            return
        if key < cur.key:
            if cur.left is None:
                cur.left = Node(key)
                return
            cur = cur.left
        else:
            if cur.right is None:
                cur.right = Node(key)
                return
            cur = cur.right

def delete(key):
    global root
    parent = None
    cur = root

    while cur is not None and cur.key != key:
        parent = cur
        if key < cur.key:
            cur = cur.left
        else:
            cur = cur.right

    if cur is None:
        return

    if cur.left is None:
        child = cur.right
        if parent is None:
            root = child
        elif parent.left is cur:
            parent.left = child
        else:
            parent.right = child
    elif cur.right is None:
        child = cur.left
        if parent is None:
            root = child
        elif parent.left is cur:
            parent.left = child
        else:
            parent.right = child
    else:
        pred_parent = cur
        pred = cur.left
        while pred.right is not None:
            pred_parent = pred
            pred = pred.right

        cur.key = pred.key

        if pred_parent.left is pred:
            pred_parent.left = pred.left
        else:
            pred_parent.right = pred.left

def build(cur):
    if cur is None:
        return ""
    if cur.left is None and cur.right is None:
        return str(cur.key)
    return str(cur.key) + "(" + build(cur.left) + "," + build(cur.right) + ")"

def solve(data):
    global root
    root = None
    ans = []

    for line in data.splitlines():
        if not line:
            continue
        parts = line.split()
        if parts[0] == "ADD":
            add(int(parts[1]))
        elif parts[0] == "DEL":
            delete(int(parts[1]))
        else:
            ans.append(build(root))

    return "\n".join(ans)

data = sys.stdin.read()
print(solve(data))
```の`Node`クラスには、BST に必要な 3 つの情報のみが格納されます。 反復的な挿入と削除を使用すると、ツリーがチェーンになったときの再帰の深さの問題を回避できます。 

挿入ルーチンは、欠落しているポインターが見つかるまでツリーを下っていきます。 等価性チェックは移動前に行われるため、重複したキーが挿入されるのを防ぎます。 

削除は最もデリケートな部分です。 ツリーを変更するには、削除されたノードにつながるポインターを変更する必要があるため、検索では親が保持されます。 2 人の子の場合、前任者は、一度左に移動してから、できるだけ右に移動することによって見つかります。 先行者は正しい子を持つことができないため、そのキーを削除されたノードにコピーした後、0 または 1 つの子ケースと同様に削除できます。 

要求された形式は当然再帰的であるため、印刷機能は再帰的です。 空の文字列の処理により、非リーフ ノード内の欠落している子が正しく表示されるようになります。`5(3,)`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(qh + P) | 各更新は、ルートからリーフへの 1 つのパスに従います。 印刷コスト P、つまりすべての印刷コマンドにわたって書き込まれたノードの数です。 |
 | スペース | O(n) | 既存の各キーは 1 つのノードを占有します。 |

 このソリューションはツリーを再構築しないため、制約に適合します。 完全な走査は、出力が構造全体を明示的に必要とする場合にのみ発生します。

 ## 特殊なケース

 空のツリーの場合、入力は```
DEL 10
PRINT
```ルートなしで始まります。 削除検索はすぐに失敗するため、ルートは空のままになります。 印刷すると、欠落しているノードで再帰関数が呼び出され、空の文字列が返されます。 

2 つの子の削除については、次のことを考慮してください。```
ADD 6
ADD 2
ADD 9
ADD 4
DEL 6
PRINT
```ノード 6 には両側に子があります。 このアルゴリズムは、左側のサブツリーの右端のノードとして 4 を見つけ、そのキーをルートにコピーし、古い 4 の位置を削除します。 出力は次のようになります。```
4(2,9)
```単純に 6 を削除するソリューションでは、両方のサブツリーが失われます。 

重複して挿入する場合は、次の点を考慮してください。```
ADD 5
ADD 5
PRINT
```2 番目の挿入はキー 5 を持つ既存のノードに到達し、停止します。 木は残ります:```
5
```重複を挿入すると、削除ロジックが依存しているすべてのキーが 1 回出現するという前提が崩れてしまうため、これは重要です。
