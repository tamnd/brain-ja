 ## 解決策
 ## 問題の理解

 このタスクは、大きすぎてほとんどのプログラミング言語で使用できる通常の整数型に収まらない整数に対して算術演算を実行することです。 入力には 10 進数文字列として書き込まれた 2 つの非負の整数が含まれており、出力は 10 進数形式で書き込まれたそれらの合計です。 

文字列には多くの数字が含まれる可能性があるため、文字列を組み込みの整数型に変換することは有効な方法ではありません。 64 ビット整数は、10 進数約 19 桁までの値しか格納できませんが、大きな整数の問題は、桁数がさらに大きくなるように設計されています。 

入力のサイズによってアルゴリズムが決まります。 数字に次のものが含まれている場合`n`そして`m`数字、読み取りにはすでにコストがかかります`O(n + m)`したがって、受け入れられた解決策はどれも同じ桁で機能する必要があります。 数値全体を繰り返し変換しようとしたり、すべての桁のペアに対して演算を実行したりする方法は、桁数が増えると遅くなりすぎます。 

主なエッジケースは、手動による追加の仕組みに由来します。 よくある間違いは、最後のキャリーを忘れることです。 たとえば、入力```
9
1
```生成する```
10
```最後の数字を追加すると新しい数字が作成されるためです。 

もう 1 つの間違いは、両方の数値が同じ長さであると想定していることです。 例えば、```
999
1
```生産しなければならない```
1000
```短い数字には先頭の数字が欠落しており、ゼロのように動作し、キャリーは短い文字列の終わりを超えて続きます。 

不注意に実装すると、ゼロ値が誤って処理される可能性があります。 例えば、```
0
0
```出力する必要があります```
0
```答えには不要な先行ゼロを含めないでください。 

## アプローチ

 簡単なアプローチは、言語の整数型に依存し、入力文字列を数値に解析することです。 通常の整数型のビット数は固定されているため、これは値が十分に小さい場合にのみ機能します。 入力にその型が格納できる桁数を超える桁が含まれると、実際の加算が行われる前に変換がオーバーフローするか失敗します。 

手動でのシミュレーションが必要です。 10 進加算には便利なローカル特性があります。つまり、ある位置の桁は、その位置の 2 桁と、前の位置からのキャリーにのみ依存します。 これは、数値全体を 1 つのマシン整数として表す必要がないことを意味します。 

この考え方は、紙に数字を追加するときに使用されるプロセスと同じです。 最下位桁から開始し、対応する桁と現在の桁上げを加算し、結果の桁を保存し、新しい桁上げを次の位置に渡します。 1 つの数字が終わると、欠落した桁はゼロとして扱われます。 すべてのポジションが処理された後、残っているキャリーが新しい先頭の桁になります。 

ブルート フォース アプローチと最適なアプローチは、数学的な作業という点では事実上同じですが、最適なアプローチでは不可能な変換ステップが回避されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 組み込み整数を使用したブルート フォース | O(n) | O(n) | 数値が整数の制限を超えると失敗します。 
| 手動での数字の追加 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 両方の数値を整数ではなく文字列として読み取ります。 文字列はすべての桁を保持し、オーバーフローを回避します。 
2. 両方の文字列の最後の文字にポインタを設定し、キャリーをゼロに初期化します。 小数桁上げは下位から上位に移動するため、加算は右から開始されます。 
3. ポインタが文字列内にあるか、キャリーが残っている間に、存在する場合は各数値から現在の桁を取得し、存在しない場合はゼロを使用します。 2 桁とキャリーを加算します。 
4. 合計の最後の桁を現在の結果の桁として保存し、10 による整数除算を使用してキャリーを更新します。 これにより、現在の位置に属する桁が、次の位置に転送される値から分離されます。 
5. 両方のポインタを左に移動し、すべての桁が処理されるまで続けます。 
6. 加算は数値の末尾から開始されるため、生成される数字は逆の順序になります。 結果を印刷する前に反転してください。 

なぜ効果があるのか:

 アルゴリズム中に維持される不変条件は、ポジションの処理後に保存された結果には、すでに処理されたすべてのポジションの正確な桁が正確に含まれており、キャリーには次のポジションに追加する必要がある量が正確に含まれていることです。 各小数点位置は、その入ってくるキャリーが判明すると独立するため、位置を右から左に処理することで通常の加算手順が再現されます。 最後のポジションの後、欠落する可能性がある唯一の寄与は最後のキャリーであり、これもループで処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def add_bigints(a, b):
    i = len(a) - 1
    j = len(b) - 1
    carry = 0
    result = []

    while i >= 0 or j >= 0 or carry:
        digit_a = ord(a[i]) - ord('0') if i >= 0 else 0
        digit_b = ord(b[j]) - ord('0') if j >= 0 else 0

        total = digit_a + digit_b + carry
        result.append(chr(ord('0') + total % 10))
        carry = total // 10

        i -= 1
        j -= 1

    result.reverse()
    answer = ''.join(result)

    answer = answer.lstrip('0')
    return answer if answer else "0"

def solve():
    data = sys.stdin.read().split()
    if len(data) < 2:
        return

    print(add_bigints(data[0], data[1]))

if __name__ == "__main__":
    solve()
```機能`add_bigints`桁ごとに全体のシミュレーションを実行します。 ポインタ`i`そして`j`各入力数値に追加されている現在の桁を表します。 これらは、キャリーが自然に伝播する方法と一致して、最下位桁から最上位桁に向かって移動します。 

数値の長さは異なる場合があるため、条件付きの数値抽出は重要です。 ポインタが文字列の先頭より前に移動すると、欠落した桁はゼロとして扱われます。 

最初に計算された桁が単位の桁であるため、結果は逆方向に構築されます。 最後に反転すると、通常の 10 進数の順序に戻ります。 先頭のゼロを最終的に削除すると、答えを維持しながら入力表現に不要なゼロが含まれるケースが処理されます。`0`有効。

## テストケース```python
import sys
import io

def add_bigints(a, b):
    i = len(a) - 1
    j = len(b) - 1
    carry = 0
    result = []

    while i >= 0 or j >= 0 or carry:
        x = ord(a[i]) - ord('0') if i >= 0 else 0
        y = ord(b[j]) - ord('0') if j >= 0 else 0
        s = x + y + carry

        carry = s // 10
        i -= 1
        j -= 1

    return ans if ans else "0"

    data = inp.split()
    return add_bigints(data[0], data[1]) + "\n"

 ## 特殊なケース

 のために`9 + 1`、アルゴリズムは最初に数字のみを処理します。 合計は 10 なので、0 が格納され、1 が保持されます。 両方の文字列が終了していますが、キャリーによってループが実行され続け、先頭の桁が作成されます。 出力は次のようになります`10`。 

次のような異なる長さの数値の場合:```
999
1
```2 番目の数値は、最初の位置以降で桁が不足します。 アルゴリズムは欠落している数字をゼロに置き換えるため、残りの加算は次のようになります。`9 + 0 + carry`。 これはキャリーが消えるまで続き、`1000`。 

ゼロ値の場合:```
0
0
```アルゴリズムは結果の数字 0 を作成します。 先頭のゼロを削除すると空の文字列が生成されるため、最後の条件で次のように置き換えられます。`"0"`。 これにより、表現が有効に保たれます。
