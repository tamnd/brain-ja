 ## 解決策
 ## 問題の理解

 このタスクは、配列をソートされた順序に再配置することですが、許可されるスワップには制限があります。 一連の整数が与えられ、少なくとも 1 つが「幸運な」数字、つまり 10 進表現が数字 4 と 7 だけで構成されている場合にのみ 2 つの要素を交換できます。 

目的は、ソートされた配列自体を見つけることではなく、このルールに従って配列がソートできるかどうかを判断し、ソートできる場合は、それを達成する一連のスワップを出力することです。 スワップの数は配列サイズの 2 倍まで許可されますが、その範囲内で有効なシーケンスを自由に出力できます。 

入力は単一の配列です。 出力は、インデックス間のスワップ操作のリスト、または制約の下で並べ替えが不可能な場合は -1 になります。 

少なくとも 1 つの幸運な数字を含む交換のみが許可されるという制約により、すぐに構造上の制限が生じます。幸運ではない要素は、要素間で直接交換できません。 彼らは、幸運な要素を「ルート」できる場合にのみ移動できます。 

複雑さの観点から見ると、配列サイズは最大約 10^5 になる可能性があります。 これにより、スワップの O(n^2) シミュレーションや単純なバブル ソート スタイルのアプローチが即座に除外されます。 有効なソリューションはすべて、O(n log n) または O(n) の前処理と、線形数のスワップ操作に依存する必要があります。 

ラッキーナンバーがまったくない場合、微妙な失敗例が現れます。 たとえば、配列が次の場合、`[3, 2, 1]`、すべての交換には少なくとも 1 つの幸運な数字が必要であるため、どの要素も他のものと交換することはできません。 正しい出力は次のとおりです`-1`配列がすでにソートされていない限り。 

もう 1 つの特殊なケースは、幸運な数字が存在するものの、順列構造を接続するのに十分ではない場合です。 たとえば、幸運な要素が 1 つだけ存在する場合、それは単一のハブのように機能し、すべての非幸運な要素はそこを経由して移動する必要があります。 「少なくとも 1 つの幸運な数字があれば十分である」という素朴な考えは、実現可能性に関しては正しいですが、それはインデックスの制約を破ることなく実際にスワップをルーティングできる場合に限られます。 

## アプローチ

 ブルートフォースの観点は、スワップを直接シミュレートすることから始まります。 選択ソートやバブル ソートなどの標準的なソート アルゴリズムを実行してみることもできますが、スワップを有効なペアに制限することもできます。 2 つの要素の順序が間違っていることが見つかるたびに、許可されている場合はそれらを交換しようとします。 

このアプローチは、既知の正しい並べ替え手順を模倣しているため、精神的には正しいです。 問題はスワップの制限です。 両方の要素が非ラッキーな場合、直接のスワップは禁止されるため、ラッキーな要素を介した中間スワップが必要になります。 これを単純にシミュレートすると、要素を何度も前後に移動させる可能性があり、最悪の場合、各反転修復には O(n) 回の操作が必要となり、合計で O(n^2) 個のスワップが発生する可能性があります。 

重要な観察は、幸運な要素が普遍的な仲介者のように機能するということです。 少なくとも 1 つの幸運な要素が存在する場合、それをバッファとして使用し、一定数の許可されたスワップを使用して任意の位置間のスワップを実装できます。 これにより、問題は制約付き並べ替え問題から、固定された「ヘルパー ノード」を使用した標準的な並べ替え並べ替え問題に変わります。 

幸運なインデックスが少なくとも 1 つある場合は、そのようなインデックスを 1 つ選択します`h`。 その後、任意の交換`(i, j)`以下を使用してシミュレートできます。 

スワップ(i, h)、スワップ(j, h)、スワップ(i, h)。 これが機能するのは、個々のスワップには幸運な要素が含まれるためです。`h`、制約を満たします。 

任意のスワップが可能になると、問題はインデックスの順列による配列のソートに集約されます。ターゲットのソート順序を計算し、順列をサイクルに分解します。 各サイクルは、ヘルパー インデックスとのスワップを使用して修正できます。 これにより保証されるのは、最大でも`n + cycles`スワップ、下に簡単に収まります`2n`縛られた。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 直接拘束シミュレーション | O(n²) | O(n) | 遅すぎる |
 | ラッキーピボットによるサイクル分解 | ソートによる O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ラッキーナンバーを含むすべてのインデックスを特定します。 存在しない場合は、配列がすでにソートされているかどうかを確認します。 ソートされていない場合、スワップは正当ではないため、タスクを完了できません。 このステップでは、問題の唯一の構造的障害を分離します。 
2. 幸運のインデックスを 1 つ選択します`h`ヘルパーピボットとして。 このインデックスは、すべてのスワップを仲介するために使用されます。 すべての交換では、少なくとも 1 つの要素が幸運であることだけが必要であるため、選択は正確さに影響しません。`h`これに関連するすべての操作についてこれが満たされます。 
3. 配列のソートされたバージョンを作成し、各値をターゲット位置にマップします。 また、現在の各インデックスがソート順でどこに移動するかを記述する順列も構築します。 これにより、問題は順列を恒等に再配置することに変換されます。 
4. この順列をサイクルに分解します。 各サイクルは、正しい位置に到達するために相互に回転する必要があるインデックスのグループを表します。 長さのサイクル`k`必要`k-1`標準の並べ替えロジックを交換します。 
5. サイクルごとに、ヘルパー インデックスを使用します。`h`通常はサイクルメンバー間で行われるスワップをシミュレートします。 要素を繰り返し正しい位置に配置します。`h`、サイクルを効果的に所定の位置に回転させます。 
6. シミュレートされた各スワップをインデックスのペアとして記録します。 各論理スワップは、実際に許可される一定数のスワップに拡張されます。`h`、制約の下で合法性を確保します。 

### なぜ効果があるのか

 ヘルパーインデックス`h`スワップ制約を満たす保証された仲介者として機能します。 ルールに違反するスワップは、2 つの要素を交換する効果を維持する有効なスワップの固定シーケンスに置き換えられます。 サイクル分解では、すべてのサイクルを解決するとソートされた順列が生成されることが保証され、各サイクルは有効なスワップ シミュレーションのみを使用して解決できるため、プロセスがスタックすることはありません。 不変条件は、各サイクルの処理後、それまでに配置されたすべての要素がすでに最終的なソート位置にあり、再度移動されることはないということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_lucky(x):
    s = str(x)
    return all(c in "47" for c in s)

n = int(input())
a = list(map(int, input().split()))

sorted_a = sorted(a)

# find any lucky index
lucky_idx = -1
for i, v in enumerate(a):
    if is_lucky(v):
        lucky_idx = i
        break

if lucky_idx == -1:
    if a == sorted_a:
        print(0)
    else:
        print(-1)
    sys.exit()

# build value -> sorted positions (handle duplicates carefully)
pos = {}
for i, v in enumerate(sorted_a):
    pos.setdefault(v, []).append(i)

target = [0] * n
for i, v in enumerate(a):
    target[i] = pos[v].pop()

visited = [False] * n
ops = []
h = lucky_idx

for i in range(n):
    if visited[i] or target[i] == i:
        visited[i] = True
        continue

    cycle = []
    cur = i
    while not visited[cur]:
        visited[cur] = True
        cycle.append(cur)
        cur = target[cur]

    # fix cycle using helper h
    for j in range(1, len(cycle)):
        u = cycle[j]
        v = cycle[0]
        if u == h or v == h:
            ops.append((u + 1, v + 1))
        else:
            ops.append((u + 1, h + 1))
            ops.append((v + 1, h + 1))
            ops.append((u + 1, h + 1))

print(len(ops))
for x, y in ops:
    print(x, y)
```解決策は、幸運な要素が存在するかどうかを確認することから始まります。幸運な要素がなければ交換は不可能だからです。 存在しない場合、配列がすでにソートされている場合にのみソートが可能です。 

その後、配列は、各要素がソートされた順序でどこに配置されるかを記述する順列にマップされます。 このステップは、問題を直接の値操作ではなくサイクル解決に変換するため、不可欠です。 

サイクル処理ループにより、各インデックスが 1 回だけアクセスされることが保証されます。 その後、ヘルパー インデックスを使用して各サイクルが修復されます。 スワップの拡張は、重要な実装の詳細です。目的のスワップのどちらのエンドポイントもヘルパーではない場合、3 つの操作でそれをルーティングします。 これにより、記録されたすべてのスワップが問題の制約の下で有効であることが保証されます。 

最終出力は許可されたスワップのシーケンスであり、サイズ k の各サイクルで O(k) 操作が生成されるため、その長さは許可された範囲内に残ります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def is_lucky(x):
        return all(c in "47" for c in str(x))

    n = int(input())
    a = list(map(int, input().split()))
    sorted_a = sorted(a)

    lucky_idx = -1
    for i, v in enumerate(a):
        if is_lucky(v):
            lucky_idx = i
            break

    if lucky_idx == -1:
        return "0\n" if a == sorted_a else "-1\n"

    pos = {}
    for i, v in enumerate(sorted_a):
        pos.setdefault(v, []).append(i)

    target = [0] * n
    for i, v in enumerate(a):
        target[i] = pos[v].pop()

    visited = [False] * n
    ops = []
    h = lucky_idx

    for i in range(n):
        if visited[i]:
            continue
        cur = i
        cycle = []
        while not visited[cur]:
            visited[cur] = True
            cycle.append(cur)
            cur = target[cur]

        for j in range(1, len(cycle)):
            u, v = cycle[j], cycle[0]
            if u == h or v == h:
                ops.append((u, v))
            else:
                ops.append((u, h))
                ops.append((v, h))
                ops.append((u, h))

    out = [str(len(ops))]
    out += [f"{x+1} {y+1}" for x, y in ops]
    return "\n".join(out) + "\n"

# custom cases
assert run("2\n4 7\n") == "0\n"
assert run("3\n4 2 1\n") != "", "basic cycle case"
assert run("3\n1 2 3\n") == "0\n"
assert run("3\n3 2 1\n") != "-1\n"

 ## 特殊なケース

 幸運な数字がない場合、アルゴリズムは配列がすでにソートされているかどうかを直ちにチェックします。 のような入力の場合`[3,2,1]`、チェックは失敗し、出力は次のようになります。`-1`、スワップは合法ではないためです。 

幸運な要素が 1 つだけある場合、`[47, 5, 1]`、その要素が唯一のヘルパーになります。 順列は通常どおりに分解され、すべてのスワップはインデックス 0 を介してルーティングされます。ラッキー要素がスワップに参加している場合でも、サイクル構造により、サイクルの終わりまでに正しい位置に戻ることが保証されます。 

すべての要素が幸運であれば、すべてのスワップが直接有効になります。 このアルゴリズムは引き続き機能しますが、ヘルパーを介したルーティングの必要がなく、標準的なサイクル ソートに縮退します。
