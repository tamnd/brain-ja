 ## 解決策
 ## 問題の理解

 厳密に増加する配列が与えられています`a`長さの`n`からの要素を含む`1`に`k`、およびサブ配列について尋ねる複数のクエリ。 インデックスによって定義されたクエリごとに`l`そして`r`、配列の数を数える必要があります`b`部分配列に「k-similar」なものが存在します`a[l..r]`。 2 つの配列は、厳密に増加しており、長さが同じで、要素が次の位置にある場合、k 類似です。`[1, k]`、そしてそれらはちょうど 1 つの位置で異なります。 

入力サイズは重要です。`n`そして`q`最大100,000まで上がる可能性がありますが、`k`最大 10^9 まで大きくすることができます。 これにより、候補配列を明示的に列挙するアプローチが除外されます。 部分配列のあらゆる可能な変更を試みる単純なアルゴリズムでは、最大で次のようなパフォーマンスが得られます。`(r-l+1) * k`クエリごとの操作ですが、最大の境界では明らかに実行不可能です。 したがって、厳密に増加するシーケンスの構造を利用する、クエリごとに O(1) または O(サブ配列長) のアプローチが必要です。 

明らかではないエッジ ケースには、配列の境界にあるサブ配列が含まれます。 たとえば、最初の要素を減らそうとしたり、最後の要素を 1 を超えて増やそうとしたり、`k`、可能な値をクランプする必要があります。 長さが 1 の非常に短い部分配列では、別の微妙な点が生じます。 考慮すべき「中間要素」がない場合でも、オプションの数は両側の制限を考慮する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、クエリ サブ配列内の各位置を反復処理し、次のすべての整数を試します。`1`に`k`、厳密な増加を維持し、正確にその位置で異なるものがどれだけあるかを数えます。 長さの部分配列の場合`m`、これには O(m * k) の操作が必要になります。 たとえ`m`100,000までは無理`k`最大 10^9。 

重要な洞察は、厳密に増加する配列の場合、特定の要素を変更するための有効範囲がその隣接要素によって制限されるということです。 仮定する`b`とは異なります`a`位置にある`i`。 それから`b[i]`前の要素より厳密に大きい任意の値を取ることができます`a[i-1]`(または 0 の場合`i`が最初です)、次の要素より厳密に小さいです`a[i+1]`（または`k+1`もし`i`最後です）。 これにより、各位置の候補の数が単純な算術計算、つまり間の整数の計算に直ちに減ります。`a[i-1]+1`そして`a[i+1]-1`、元の値を除外するには 1 を引いてください。 

最初と最後の要素については、境界を調整するだけです。最初の要素は 1 を下回ることはできず、最後の要素は 1 を超えることはできません。`k`。 中間の要素の場合、有効範囲はそのすぐ隣の要素によって制限されます。 クエリ部分配列内のすべての位置でこれらのカウントを合計すると、その部分配列の k 類似配列の総数が得られます。 これは要素ごとに単純な算術演算のみを必要とするため、クエリごとの複雑さは O(m) であり、次の点を考慮すると十分効率的です。`n`そして`q`は 10^5 であり、すべてのクエリにわたる合計作業量は依然として実行可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(m * k) | お(1) | 遅すぎる |
 | 最適 | クエリあたり O(m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力値を読み取る`n`、`q`、 そして`k`そして配列`a`。 確認する`a`境界計算を容易にするために 1 のインデックスが付けられます。 
2. クエリごとに、部分配列のインデックスを抽出します。`l`そして`r`。 長さを決める`m = r-l+1`。 
3. カウンタの初期化`count`ゼロに。 これにより、有効な配列の総数が保存されます。 
4. ポジションごとに`i`部分配列内で、可能な置換の範囲を計算します。 

- もし`i`は最初の要素であり、下限は 1 です。 それ以外の場合は、`a[i-1] + 1`。 
- もし`i`は最後の要素であり、上限は`k`; それ以外の場合は、`a[i+1] - 1`。 
- この位置での有効な置換の数は次のとおりです。`(upper_bound - lower_bound + 1) - 1`。 現在の値を除外するには、1 を減算します。 
5. この数字を`count`。 
6. すべての位置を処理した後、出力します`count`。 

機能する理由: 構造上、部分配列内の各要素は隣接要素によって設定された厳密な境界内の値のみを取ることができ、結果として得られる配列が厳密に増加し続けることが保証されます。 1 を減算すると、「正確に 1 つの位置が異なる」条件を満たす元の要素が除外されます。 すべてのポジションを合計すると、すべての可能性が一度だけ計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q, k = map(int, input().split())
a = list(map(int, input().split()))

# pad array for easier indexing
a = [0] + a + [k+1]

for _ in range(q):
    l, r = map(int, input().split())
    count = 0
    for i in range(l, r+1):
        lower = a[i-1] + 1
        upper = a[i+1] - 1
        count += max(0, upper - lower)
    print(count)
```このコードは、境界計算が均一になるように、まず配列の先頭に 0 を、末尾に k+1 を埋め込みます。 クエリごとに、関連するサブ配列を反復処理し、要素ごとの有効な置換の数を計算します。`max(0, upper - lower)`負の範囲 (有効な置換がない) が正しく処理されるようにします。
