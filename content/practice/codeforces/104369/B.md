 ## 解決策
 ## 問題の理解

 1 から n までの位置の列が与えられます。各位置には基地局を構築するためのコストがかかります。 私たちは基地局を建設するために位置のサブセットを選択することができ、そのコストの合計を支払います。 目標は、コストを自由に最小化することだけではなく、一連のカバレッジ制約を満たすことです。各制約は間隔です。$[l_i, r_i]$、そのようなすべての間隔には、少なくとも 1 つの選択された基地局が含まれている必要があります。 

言い換えれば、すべての間隔は、少なくとも 1 つの選択されたインデックスによって「ヒット」する必要があります。 これは、指定されたすべてのセグメントと交差するように点が選択され、コストが位置によって重み付けされる古典的なカバー問題です。 

入力サイズは大きく、n と m は最大です。$5 \times 10^5$テストケース全体で。 これにより、間隔または位置に関する二次関数のアプローチが即座に除外されます。 平$O(nm)$または、選択ごとに間隔を繰り返しスキャンするものは失敗します。 テスト ケースごとに線形または線形対数に近い時間が必要です。 

微妙な問題は、間隔が重なり合い、順序付けられていない可能性があることです。 インターバルを個別に処理する単純な貪欲なアプローチは失敗します。 たとえば、間隔ごとに最も安いポイントを個別に選択すると、多くの冗長なステーションが選択される可能性があります。 

もう 1 つの失敗例は、グローバル構造を無視したことに起因します。 

間隔を考慮する$[1,3]$そして$[2,4]$コスト付き:```
i:   1 2 3 4
a:   5 1 1 5
```単純な戦略では、各間隔の最小値を個別に選択し、最初の間隔で 2、2 番目の間隔で 3 を選択し、コストが 2 になる可能性があります。これがここでは最適です。 ただし、最小値が異なるわずかに変更されたケースでは、区間ごとの貪欲な選択により、共有された最適なポイント構造が見逃され、過剰選択される可能性があります。 

本当の難しさは、決定がグローバルに結合されていることです。つまり、点を選択すると複数の間隔が同時に満たされることになります。 

## アプローチ

 ブルート フォース ソリューションでは、位置のすべてのサブセットを試し、すべての間隔に選択した位置が少なくとも 1 つ含まれているかどうかを確認し、最小コストを計算します。 これは$O(2^n \cdot m)$、30歳くらいのnでも全く無理。 

より良いアイデアは、視点を「ポイントの選択」から「制約を満たす」に変えることです。 各間隔には、その中に少なくとも 1 つの選択されたポイントが必要です。 ソートされた順序で間隔を処理すると、制約を段階的に適用することができます。 

重要な洞察は、正しいエンドポイントによって間隔を並べ替えることです。 間隔を処理するとき$[l, r]$、少なくとも 1 つの選択された位置がこの間隔内にあることを確認したいと考えています。 以前に選択したステーションによって間隔がすでに満たされている場合は、何も行いません。 それ以外の場合は、その中の位置を選択する必要があります。 

コストを最小限に抑えるには、将来の制約を満たすために有効な、可能な限り安価なポジションを常に選択する必要があります。 「範囲内の最小コスト」を求める効率的なクエリをサポートする自然な構造は、セグメント ツリーまたはインデックス上のバランスの取れたツリーです。 

ただし、さらに重要な観察があります。位置を選択すると、その位置が含まれるすべての間隔を満たすことができるということです。 したがって、正しいエンドポイントの昇順に間隔を処理する場合、強制的に最適な選択は、間隔内の最小コストの位置を選択することです。これは、現在の間隔をカバーし、将来の使用のためにできるだけ安価であるためです。 

これにより、範囲最小クエリを使用した貪欲な戦略と、間隔が以前に選択された位置によってすでに満たされているかどうかを知るための簿記構造が得られます。 選択した位置を追跡するデータ構造を維持し、間隔ごとに、選択した位置がその中にあるかどうかを確認します。 そうでない場合は、その間隔内の最小コストの位置を照会し、それを選択します。 

高速チェックをサポートするために、選択したポイント上にフェンウィック ツリーまたはセグメント ツリーを維持できます。 各間隔のクエリは次のようになります。「[l, r] に選択された点は存在しますか?」 そうでない場合は、その範囲内のコストの argmin を選択し、構造を更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot m)$|$O(n)$| 遅すぎる |
 | 最適 (貪欲 + セグメント ツリー/フェンウィック) |$O((n+m)\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 すでに選択されている一連の位置を維持しながら、間隔制約を段階的に強制するものとして問題を扱います。 

1. すべての間隔を右端点の増加順に並べ替えます。 これにより、間隔を処理するときに、将来の間隔が以前の決定より早く開始したり、以前の決定と比較して制御された方法で重複したりすることがなくなります。 
2. 選択されたポジションが範囲内にあるかどうかを確認することと、範囲内の最小コストのポジションをクエリするという 2 つの操作をサポートするポジションの構造を維持します。 セグメント ツリーは両方に対して自然に機能し、「選択したポイント」と「最小コスト インデックス」の両方を保存します。 
3. ソートされた順序で間隔を繰り返します。 しばらくの間$[l, r]$, まず、すでに満たされているかどうかを確認します。 これは、選択されたポジションの合計または数が次のとおりであるかどうかを確認することを意味します。$[l, r]$はゼロより大きいです。 
4. 間隔がすでに満たされている場合は、次に進みます。 これが安全である理由は、追加の選択を行っても実現可能性が向上することなくコストが増加するだけだからです。 
5. 間隔が満たされていない場合は、その間隔内の位置を選択する必要があります。 総コストを最小限に抑えるために、インデックスを選択します。$[l, r]$最小限のコストで$a_i$。 このポジションを選択済みとしてマークし、そのコストを回答に追加します。 
6. この位置が現在選択されていることを反映するようにデータ構造を更新します。これにより、今後の間隔で効率的に位置を検出できるようになります。 

### なぜ効果があるのか

 どのステップでも、区間に選択されたポイントがない場合にのみ動作します。 私たちが行動するとき、その間隔を固定するできるだけ安価なポジションを選択します。 実行可能なソリューションでは、現在のポイントを含め、すべての間隔内で少なくとも 1 つのポイントを選択する必要があります。 したがって、最適なソリューションは、総コストを増加させることなく、最初のカバーされていない区間内の最小コスト ポイントを使用するように変換できます。 間隔は右側の端点を増加させて処理されるため、この交換引数は、以前に満たされた制約を破ることなく、順次適用できます。 これにより、貪欲な構築がグローバルに最適な状態を保つことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.arr = arr
        self.tmin = [0] * (4 * self.n)
        self.tcnt = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1)

    def build(self, v, l, r):
        if l == r:
            self.tmin[v] = self.arr[l]
            self.tcnt[v] = 0
            return
        m = (l + r) // 2
        self.build(v * 2, l, m)
        self.build(v * 2 + 1, m + 1, r)
        self.tmin[v] = min(self.tmin[v * 2], self.tmin[v * 2 + 1])
        self.tcnt[v] = 0

    def update(self, v, l, r, pos):
        if l == r:
            self.tcnt[v] = 1
            return
        m = (l + r) // 2
        if pos <= m:
            self.update(v * 2, l, m, pos)
        else:
            self.update(v * 2 + 1, m + 1, r, pos)

    def query_has(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.tcnt[v]
        m = (l + r) // 2
        res = 0
        if ql <= m:
            res |= self.query_has(v * 2, l, m, ql, qr)
        if qr > m:
            res |= self.query_has(v * 2 + 1, m + 1, r, ql, qr)
        return res

    def query_min(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.tmin[v]
        m = (l + r) // 2
        res = float('inf')
        if ql <= m:
            res = min(res, self.query_min(v * 2, l, m, ql, qr))
        if qr > m:
            res = min(res, self.query_min(v * 2 + 1, m + 1, r, ql, qr))
        return res

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        m = int(input())
        seg = SegTree(a)
        intervals = []
        for _ in range(m):
            l, r = map(int, input().split())
            intervals.append((r, l))
        intervals.sort()

        total = 0

        for r, l in intervals:
            if not seg.query_has(1, 0, n - 1, l - 1, r - 1):
                # need to pick one
                # find minimum cost in range
                # then locate position (simple scan for clarity)
                best_val = seg.query_min(1, 0, n - 1, l - 1, r - 1)
                for i in range(l - 1, r):
                    if a[i] == best_val:
                        seg.update(1, 0, n - 1, i)
                        total += a[i]
                        break

        print(total)

if __name__ == "__main__":
    solve()
```セグメント ツリーは 2 つの役割で使用されます。 1 つはポジションが選択されているかどうかを追跡し、もう 1 つはコストに対する範囲最小クエリをサポートします。 更新操作により、位置が選択されたものとしてマークされます。 「has」のクエリにより、現在の間隔がすでにカバーされているかどうかが判断されます。 

最小コストインデックスを見つけるために使用される線形スキャンは、概念的には受け入れられますが、最適ではありません。 完全に最適化されたバージョンでは、セグメント ツリーには最小値とそのインデックスの両方が保存され、スキャンが回避されます。 間隔内で最小コストを達成するインデックスのみが必要なため、ロジックは正しいままです。 

一般的な実装上の落とし穴は、間隔を変換するときに 1 ベースのインデックス付けと 0 ベースのインデックス付けを混合することです。 すべての間隔は、以下を使用して一貫して変換されます。$l-1$そして$r-1$。

 ## 特殊なケース

 エッジ ケースの 1 つは、多くの間隔が同一であるか、ネストされている場合です。 たとえば、間隔$[1,5]$、$[1,5]$、$[1,5]$。 初めて処理するときは、全範囲の中で最も安い位置を選択します。 その後、残りの間隔はすべて満たされており、追加のコストは発生しません。 セグメント ツリーは選択した位置を正確に記憶するため、間隔が繰り返されても選択が繰り返されることはありません。 

もう 1 つのケースは、間隔により配列の両端で選択が強制される場合です。 例えば、$[1,2]$そして$[4,5]$重複なしで。 最初の間隔を処理した後は 2 番目の間隔にポイントが存在しないため、アルゴリズムはそれぞれを独立して選択します。 これにより、構造が素の制約を誤って結合していないことが確認されます。 

微妙なケースは、最も安いポイントがすべての初期の間隔の外側にあるが、後の間隔で必要になる場合です。 間隔は右側のエンドポイントを増加させながら処理されるため、右端にある安価なポイントは、必要でない限り、早期に選択されません。 これにより、時期尚早な貪欲な選択が防止され、コストが全体的に最小限に抑えられます。
