 ## 解決策
 ## 問題の理解

 最初の年に始まる年次イベントを検討しています`y1`。 その年以降、コンテストは年に 1 回開催される予定です。 ただし、コンテストが開催されなかった例外的な年のリストもいくつかあります。 

テスト ケースごとに、開始年、コンテストが行​​われなかった「スキップされた」年のソートされたリスト、および目標年が与えられます。`y2`。 タスクは、年から実際に開催されたコンテストの数を数えることです。`y1`年間を通じて`y2`、両方のエンドポイントを含みます。 

問題を再構成する有効な方法は、年間隔を考えることです。`[y1, y2]`いくつかの特定の年がこのカウントから削除されることを除いて、毎年、正確に 1 つの潜在的なコンテストに貢献する連続シーケンスとして。 したがって、答えは単純に、間隔内の合計年数から、その間隔内に含まれるスキップされた年数を差し引いたものになります。 

の制約`n`これは、テスト ケースごとの操作が数百までは簡単であることをすぐに示唆しています。 スキップされたリストの線形スキャンはすでに十分です。 

微妙なエッジ ケースは、スキップされた年にクエリ範囲外の値が含まれている場合です。 たとえば、次の場合`y1 = 2000`、`y2 = 2005`、スキップされた年は`1999`または`2010`、それらは答えに影響を与えるべきではありません。 もう 1 つの重要な詳細は、`y2`はスキップされた年ではないことが保証されているため、カウントと除外の両方からそれを減算するという曖昧さを処理する必要はありません。 

## アプローチ

 この問題についての素朴な考え方は、年ごとにシミュレーションすることです。 から始まる`y1`まで繰り返します`y2`、そして毎年、それがスキップされたリストに含まれているかどうかを確認します。 そうでない場合は、開催されたコンテストとしてカウントされます。 これはプロセスの定義に直接従うため、正しいです。 

ただし、このアプローチでは不必要な作業が行われます。 間の年数`y1`そして`y2`最大約 10,000 件までの大きなデータになる可能性があり、毎年最大でスキャンすることがあります。`n = 100`スキップされた値。 これにより、テスト ケースごとに約 1,000,000 回の操作が必要になります。これはまだ問題ありませんが、概念的には無駄であり、推論するのが困難です。 

重要な点は、実際には毎年繰り返す必要はないということです。 コンテストは、明示的に削除された年を除き、毎年開催されます。 したがって、答えは純粋に組み合わせです。範囲内の合計年数から、同じ範囲内に含まれるスキップされた年の数を引いたものになります。 

これにより、問題は、最大 100 個の要素からなる小さなリストをフィルタリングし、その中に含まれる要素をカウントするだけになります。`[y1, y2]`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O((y2 - y1 + 1) · n) | お(1) | 許容できるが不要 |
 | 範囲内でスキップされた年をカウントする | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 開始年を読む`y1`、スキップされた年数`n`、およびスキップされた年のリスト。 スキップされた年はすでにソートされているため、指定されたとおりに保存しますが、ソートは必須ではありません。 
2. 目標年を読む`y2`。 
3. 間隔内の合計年数を計算します。`[y1, y2]`。 これは単純に、`y2 - y1 + 1`、何もスキップされなかった場合、考えられるすべてのコンテスト年をカウントします。 
4. スキップされた各年を反復します。`s`。 それぞれについて`s`、間隔内にあるかどうかを確認します`[y1, y2]`。 存在する場合は、合計数から 1 を減算します。 間隔外にスキップされた年は、質問される範囲に影響を与えないため、無視します。 
5. 結果のカウントを出力します。 

安全に直接減算できる理由は、スキップされた各年がちょうど 1 つの欠落したコンテストに対応しており、この問題により重複がないことが保証されているため、過剰カウントの修正は必要ないためです。 

### なぜ効果があるのか

 カウントプロセスは、全間隔の分割に基づいています。`[y1, y2]`コンテストが行​​われる年と行われない年という、2 つの素なセットに分けられます。 この期間内の各年は、スキップ リストに含まれるかどうかのどちらかです。 間隔内の年の完全なカウントから開始し、スキップとマークされて間隔内にある年を正確に削除するため、有効なコンテストの年はすべて 1 回だけカウントされたままとなり、無効な年はすべて 1 回だけ削除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        parts = input().split()
        y1 = int(parts[0])

        # next line: n followed by n skipped years
        parts = input().split()
        n = int(parts[0])
        skipped = list(map(int, parts[1:]))

        y2 = int(input())

        total = y2 - y1 + 1

        for s in skipped:
            if y1 <= s <= y2:
                total -= 1

        print(total)

if __name__ == "__main__":
    solve()
```実装はアルゴリズムに直接に従います。 注目に値する唯一の詳細は入力解析です。スキップされた年は同じ行にあるためです。`n`、行全体を読んで分割します。 これにより、テスト ケースごとの可変長入力の問題が回避されます。 

計算には単純なアキュムレータが使用されます`total`、完全な間隔サイズとして初期化され、関連するスキップされた年についてのみ減分されます。 

## 実用的な例

 次の場合を考えてみましょう`y1 = 2000`、スキップされた年は、`[2002, 2004]`、 そして`y2 = 2005`。 

| ステップ | 合計年数 | 処理をスキップしました | 現在の合計 |
 | --- | --- | --- | --- |
 | イニシャル | 2005 - 2000 + 1 = 6 | なし | 6 |
 | 2002年 | 範囲内 | 1 を引く | 5 |
 | 2004年 | 範囲内 | 1 を引く | 4 |

 最終的な答えは 4 で、2000 年、2001 年、2003 年、2005 年に対応します。 

ここで、スキップされた年が範囲外にある場合を考えてみましょう。`y1 = 2010`、`y2 = 2013`、スキップしました`[2009, 2011, 2015]`。 

| ステップ | 合計年数 | 処理をスキップしました | 現在の合計 |
 | --- | --- | --- | --- |
 | イニシャル | 4 | なし | 4 |
 | 2009年 | 範囲外 | 無視 | 4 |
 | 2011年 | 範囲内 | 1 を引く | 3 |
 | 2015年 | 範囲外 | 無視 | 3 |

 これにより、クエリされた間隔内でスキップされた年のみが結果に影響を与えることが確認されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    T = int(input())
    out = []
    for _ in range(T):
        y1 = int(input())
        parts = list(map(int, input().split()))
        n = parts[0]
        skipped = parts[1:]

        for s in skipped:
            if y1 <= s <= y2:
                total -= 1
        out.append(str(total))
    return "\n".join(out) + "\n"

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です`y1 == y2`、つまり、間隔にはちょうど 1 年が含まれます。 アルゴリズムは合計を 1 に設定し、その年がスキップされたリストに含まれている場合にのみ 1 を減算します。 問題が保証されているため、`y2`はスキップされた年ではないため、結果は常に 1 のままになります。たとえば、`y1 = y2 = 2020`2020 を含まないスキップされたリストでは出力 1 が生成されますが、2020 がスキップされた場合は制約と矛盾します。 

もう 1 つのエッジ ケースは、スキップされた年がすべてクエリ間隔の外側にある場合です。 この場合、減算は行われず、結果は間隔全体の長さのままになります。 フィルタリング条件`y1 <= s <= y2`これらの値が完全に無視されるようにします。 

最後の微妙なケースは、スキップされた年が密集しているものの、まだ境界がある場合です。`n ≤ 100`。 たとえ全部が中に横たわっていても`[y1, y2]`、アルゴリズムは正しく正確に減算します`n`合計から計算し、順序付けやセット構造を必要とせずに正しい残りカウントを生成します。
