 ## 解決策
 ## 問題の理解

 長さのシーケンスが与えられます$n$、最初はゼロで埋められます。 私たちも持っています$m$操作。 各操作で 2 つの位置が選択されます$l_i < r_i$そして値を割り当てます$x_i$そして$y_i$それらの位置に移動し、現在そこにあるものを上書きします。 

重要な点は、指定された順序で操作を適用する必要がないことです。 代わりに、それらを任意に並べ替えることができますが、すべての操作は 1 回だけ適用する必要があります。 すべての操作が選択した順序で実行された後、各位置には、最後に接触した操作によって書き込まれた値が入ります。 目標は、すべての配列要素の最終合計を最大化することです。 

この難しさは、各操作が 2 つの位置に影響を及ぼし、後の操作で以前の操作が上書きされる可能性があるという事実から生じます。 したがって、各インデックスの最終値は、それに触れる順列の最後の操作によってのみ決定されます。 

制約は大きく、$n, m$まで$5 \cdot 10^5$テストケース全体で。 これにより、演算または位置のペアに対する二次推論が除外されます。 どのようなソリューションも、テスト ケースごとに基本的に線形または線形に近いものでなければなりません。 

単純なアイデアは、演算のすべての順列を試すか、すべての候補を試しながら貪欲な選択を動的にシミュレートすることです。 操作間の依存関係の観点から考えると、操作とインデックスにわたるグラフが示唆されますが、順列ごとの明示的な状態追跡はすぐに実行不可能になります。 

2 つの操作が同じインデックスで重複する場合、微妙なエッジ ケースが発生します。 たとえば、両方の操作が位置 5 に影響を与える場合、その位置では後の操作のみが重要になります。 誤って操作ごとに貢献度を個別に合計すると、二重にカウントされてしまいます。 たとえば:

 入力:```
n = 1, m = 2
(1, 1, 1, 2)
(1, 2, 1, 1)
```操作 1 を適用してから 2 を適用すると、最終値は 1 になります。逆の場合、最終値は 2 になります。両方の寄与を合計する単純なアプローチでは、上書きが無視され、すぐに失敗します。 

したがって、中心的な問題は、最終書き込みの寄与を最大化する方法で、重複する間隔間の競合を解決するグローバル順序を選択することです。 

## アプローチ

 重要な観察は、各操作が正確に 2 つの位置に書き込み、各位置は影響を与える操作の中でどの操作が最後であるかのみを考慮するということです。 したがって、すべてのインデックス$i$は、値を 1 つだけ提供します。それは、それに触れる最新の操作によって書き込まれた値です。 

これにより、問題はインデックスごとに、どの操作が「勝者」になるかを制御することに変わります。 

次に、単一の操作を見てみましょう$i$。 値を配置しようとします$x_i$そして$y_i$ポジションについて$l_i$そして$r_i$。 この操作を両方のエンドポイントに影響を与える最後の操作にしたい場合は、$x_i + y_i$。 しかし、異なる運用が共有インデックスで競合するため、これは世界的に不可能です。 

重要な構造は、各操作がエンドポイントを共有する操作間に依存関係の制約を作成するということです。 2 つの操作がエンドポイントを共有する場合、どちらか遅いほうがそのインデックスを決定します。 したがって、重要なインデックスに対して「より良い」割り当てが後で行われるように操作を順序付けしたいと考えています。 

操作ごとに考えるのではなく、視点を反転して、それぞれの位置を確認します。$i$最終的には、それをカバーするすべての操作の最後に配置された操作によって制御される必要があります。 したがって、インデックスごとに「勝ち操作」を割り当てたいと考えますが、同じ操作が 2 つのインデックスで同時に勝つことができるのは、両方に触れるすべての操作の中で最後である場合に限られます。 

これは、既に選択された決定によって引き起こされる順序付け制約との一貫性を確保しながら、インデックスを左から右に処理し、各位置に対してどの操作がそれを担当するかを決定することを示唆しています。 

より具体的には、操作と位置の間に 2 部構成の制約システムを構築することになりますが、実際の単純化では、各位置をカバーする操作の順序を決定すると、各位置を独立して解決できるようになります。 各操作は 2 つのエンドポイントにのみ影響するため、未解決のエンドポイントがどれだけ残っているかに基づいて、次に配置しても安全な操作を繰り返し選択することで、グローバルな順序を導き出すことができます。 

最終的に実行可能な洞察は、各ポジションを「最終オーナー操作」が必要なものとして扱うことです。 各エンドポイントでどの操作が最後になるかを決定するプロセスをシミュレートし、最終的な寄与がより高い操作を常に遅らせる優先順位構造を使用して、それらの決定と一致する順序を構築します。 

これは貪欲な戦略につながります。つまり、潜在的な利益に基づいて作戦に優先順位を付け、達成可能な最大の貢献を持った作戦が各ポジションを確実に獲得できる順序で作戦を割り当てます。 

実際には、これは、競合が一貫して解決されるように構造を維持することと組み合わせて、操作を遅らせることがどれほど有益であるかを反映する慎重に導出されたキーによる並べ替え操作に帰着します。

 ## アルゴリズムのチュートリアル

 この解決策は、各操作をエンドポイント上の 2 つの「クレーム」として解釈し、最終的な注文で各ポジションに最適なクレームが勝利するようにすることに依存しています。 

1. すべての操作について、その固有の値を計算します。$s_i = x_i + y_i$。 これは、両方のエンドポイントで最後の操作になった場合に生成できる合計ゲインです。 この値は、順序付けを決定するための優先度の尺度として機能します。 
2. 各操作を 2 つのエンドポイントに関連付けます。 各エンドポイントは、それを含むすべての操作の中で最大の寄与を与える操作を優先すると考えることができます。 このローカルな設定は、グローバルな順序付けをガイドします。 
3. 高価値の操作を後からエンドポイントに表示することと一致するグローバルな順序を決定できる構造を構築します。 重要な考え方は、操作の価値が高い場合は、同じエンドポイントをめぐって競合する操作よりも後に配置する必要があるということです。 
4. 操作を降順に並べ替えます$s_i$。 これにより、共有エンドポイントで競合が発生した場合、より多くの合計値に寄与する操作が後で処理され、より弱い操作が上書きされることが保証されます。 
5. このソート順を実行順序として出力します。 最終的な配列は、この順序でシミュレーションすることによって決定されます。各操作は 2 つのエンドポイントを上書きします。 

明らかではない部分ですが、なぜ並べ替えを行うのかというと、$x_i + y_i$で十分です。 その理由は、各エンドポイントが独立して寄与しており、全体としてより強力な操作を後で配置しても決して有害ではないためです。その利点は、より弱い操作によって上書きされた場合にのみ減少するためです。 すべての位置は最終値のみに寄与するため、ローカル エンドポイント値の最大化は合計の最大化と一致します。 

### なぜ効果があるのか

 各位置には、最終的に、その位置に触れる最後の操作の値が割り当てられます。 合計の大きい操作を後から配置することで、エンドポイントが競合するたびに、より多くの合計値に貢献する操作がそのエンドポイントを支配する機会が得られるようになります。 より小さい合計の演算が後で配置される反転では、他のエンドポイントを増やすことなく、少なくとも 1 つのエンドポイントでの寄与のみを減らすことができます。これは、より大きい合計の演算の方が、それが接触する両方の位置に対して厳密に優れた最終コントローラーとなるためです。 したがって、合計貢献度による並べ替えにより、すべてのエンドポイント競合のグローバルに最適な解決が強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        ops = []
        for i in range(m):
            l, x, r, y = map(int, input().split())
            ops.append((x + y, i + 1, l, r, x, y))

        ops.sort(reverse=True)

        order = [op[1] for op in ops]

        # simulate final array
        arr = [0] * (n + 1)
        for _, _, l, r, x, y in ops:
            arr[l] = x
            arr[r] = y

        print(sum(arr[1:]))
        print(*order)

if __name__ == "__main__":
    solve()
```実装は、すべての操作を読み取り、その合計寄与度を計算することから始まります。$x_i + y_i$。 次に、操作はこの値の降順に並べ替えられ、実行順序が生成されます。 

シミュレーション ステップでは、単純に操作をその順序で適用し、エンドポイントを上書きします。 リスト内の後の操作はより強力な合計寄与に対応するため、当然のことながら最終値を支配します。 

微妙な点の 1 つは、中間の一貫性や部分的な代入状態を決して維持しようとしないことです。 順序付けによって最終的な優位性がすでにエンコードされているため、これは安全です。 シミュレーションは結果の配列のみを抽出します。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての操作が共有エンドポイントで大きく重複する場合です。 このような場合、アルゴリズムは最大合計の演算を最後に配置し、競合の激しいインデックスの最終値が最も価値のある演算から得られるようにします。 多くの上書きが発生しても、インデックスごとに重要になるのは最後の割り当てだけであるため、以前の弱い割り当ては最終的な合計には影響しません。 

もう 1 つの特殊なケースは、操作が切り離されている場合です。 ここでは、エンドポイントをめぐって競合する操作がないため、合計による並べ替えはコンポーネント間で干渉しません。 各操作は明確に独自の貢献をします$x_i + y_i$、そして順序は正確さとは無関係になり、一貫性のみが重要になります。 

最後のエッジケースは、複数の演算の合計が等しい場合です。 共有エンドポイントではどちらも厳密に他方を支配しないため、それらの間の順序は有効です。 アルゴリズムは任意に同点を解消し、等重み演算間の交換ではエンドポイントの最大値が変更されないため、最終的な合計は変更されません。
