 ## 解決策
 ## 問題の理解

 1 から m までのインデックスが付けられた家の列が与えられ、n 人を個別の家に配置する必要があります。 2 人は、隣接するハウス インデックスを占有している場合にのみ隣人とみなされます。 各人は合計スコアに対して 2 つの可能な貢献を持っています。少なくとも 1 人の隣人がいる場合は ai に貢献し、そうでない場合は bi に貢献します。 

課題は、全員の貢献度の合計が最大化されるように、全員のポジションを選択することです。 問題の構造は、実際には単一の線を超えた幾何学に関するものではありません。 重要なのは、人々をどのように連続したブロックにグループ化するかということです。なぜなら、隣接性は連続して居住されている家によってのみ決定されるからです。 

この制約により、あらゆる組み合わせ割り当てアプローチが即座に除外されます。 テスト全体で n が最大 5×10^5、m が最大 10^9 であるため、配置をシミュレートしたり順列を試行したりすることはできません。 どのような解決策であっても、問題を人​​々の線形または線形に近いスキャン、理想的には O(n log n) または O(n) に減らす必要があります。 

微妙な点は、m は大きいですが、グループを分離するのに十分な空きスペースを提供すること以上には無関係であるということです。 すべての家を埋めることを強制されることはありません。そのため、重要なのは、n 人をライン上のどこかに配置された連続したセグメントにどのように分割するかです。 

正確な家の位置を選択しなければならないと考えるのは単純な間違いです。 これにより、m を超える配置 DP が困難になります。 代わりに、実際の構造は、誰が配置されるかではなく、誰が隣接するかによってのみ決まります。 

重要なエッジケース:

 n = m の場合、全員が完全に満たされたセグメントに強制的に入れられるため、おそらく端を除いてすべての人が隣接者になります。 たとえば、n = 2 および m = 2 の場合、優先順位に関係なく両方が隣接するため、すべてに対して ai + aj を取る必要があります。 

m が n に比べて非常に大きい場合、全員を分離できます。これは、すべての寄与が 2 であることを意味します。 たとえば、n = 3、m = 100 の場合、合計 bi のベースライン答えが得られ、有益な場合は隣接グループを選択的に作成します。 

重要な緊張は、誰かを隣人にする（bi の代わりに ai を採用する）価値があるかを判断することです。これにより、他の人にも影響を与える可能性のある構造的なグループ化が強制されるからです。 

## アプローチ

 ブルートフォースの観点から始めます。 人々を家に明示的に割り当て、すべての有効な配置を評価しようとするとします。 正確な位置を無視して隣接パターンのみを考慮したとしても、線に沿ってどのペアが隣接するかを選択することになります。 これは、n 人をセグメントに分割することに相当します。長さ k の各セグメントは、そのセグメントのすべてのメンバーに対して ai に寄与し、長さ 1 のセグメントは bi に寄与します。 

したがって、問題は一連の人々のセグメントを選択することになります。 ブルートフォース DP は、dp[i] を最初の i 人にとっての最良の値とみなして、以前のカット ポイントをすべて試します。 これにより、O(n^2) 個の遷移が発生しますが、5×10^5 までの n では不可能です。 

重要な洞察は、各人の選択を孤立に対する利益に変えることです。 全員が孤立した場合、基本スコアは sum bi になります。 少なくとも 2 人のサイズのグループの中に人を置くと、ai - bi が得られます。 ただし、グループの形成には少なくとも 1 つの隣接エッジも必要であり、隣接関係は 2 人の間で共有されます。 隣接する各ペアは、両方のエンドポイントを少なくとも 1 つの近傍を持つものとして効果的に「アクティブ化」します。 

これは問題を再構成します。n 人の人のラインに沿って一連の隣接エッジを選択しています。 選択された各エッジ (i, i+1) は、i と i+1 の両方が非シングルトン コンポーネントの一部になることを意味します。 サイズ k の連結コンポーネントはすべての k メンバーの sum(ai) に寄与し、孤立した頂点は bi に寄与します。 

これで、構造はセグメントを開始するか延長するかを決定する古典的な 1D DP になりますが、さらに単純化することもできます。位置ごとに、グループに参加するか孤立したままにするかを決定し、グループはサイズが少なくとも 2 の連続した間隔になります。

現在グループ内にいるかどうかを維持しながら、左から右にスキャンする DP を定義します。 グループが開始されると、それを拡張すると常に両方のエンドポイントに対称的に影響を与えるため、遷移はローカルの決定のみに依存します。 

最後の単純化は、最適な解決策は、隣接する人々のペアリングの利得が合計でプラスになる場合はどこでも貪欲にグループを形成することであるということです。 i と i+1 を接続することで純利益が得られるかどうかを評価します。 

(ai + a(i+1)) - (bi + b(i+1)) を両方を分離したままにする場合と比較します。 

したがって、各隣接エッジは重み wi = (ai - bi) + (a(i+1) - b(i+1)) を持ちます。 選択したすべてのエッジがメリットをもたらすように、重なり合わないエッジのセットを選択したいと考えていますが、隣接するエッジを選択すると人物が重なり、コンポーネントがマージされます。 これは、パス上の古典的な最大重みマッチングに帰着します。これは、O(n) の DP によって解決できます。 

最初に i 人を考慮した場合、 dp[i] が最良の答えであるとします。 次に:

 dp[i] = max(dp[i-1], dp[i-2] + wi-1)

 これは、直線上の正確な重み付けマッチングです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | セグメント上のブルート フォース DP | O(n^2) | O(n) | 遅すぎる |
 | パス DP / 重み付けマッチング | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての人を孤立したものとして扱い、すべての bi の合計に等しいベースライン スコアを計算します。 これは、隣接関係がまったくない構成を表します。 
2. 隣接するペア i および i+1 ごとに、それらを接続することによる追加の利点を計算します。 両方がグループの一部になる場合、bi + b(i+1) を ai + a(i+1) に置き換えるので、ゲインは (ai + a(i+1)) - (bi + b(i+1)) となります。 
3. 動的プログラミング配列 dp を定義します。ここで、dp[i] は、隣接エッジを形成するか分離したままにするかを考慮して、最初の i 人のみを使用して達成可能な最大の追加ゲインを表します。 
4. 1 人では隣接関係の利点を得ることができないため、dp[0] = 0 および dp[1] = 0 を初期化します。 
5. 2 から n までの各 i について、i で終わるグループを形成しない (dp[i] = dp[i-1] を維持する) か、i-1 と i でグループを形成する (エッジ ゲインに寄与し、重複を避けるために i-2 をスキップして dp[i-2] + ゲイン(i-1) を与える) かを決定します。 
6. 答えは、bi と dp[n] のベースライン合計です。 

これが機能する理由: 最終的な配置内のすべての接続コンポーネントは、線上で互いに素なパスを形成する一連のエッジに対応します。 選択された各エッジは、正確に 2 人の隣接する人々を「隣接者存在」状態にアクティブ化し、最適な構成は一般性を失うことなく、重なり合わないエッジに分解できます。 DP は、エッジの重なりを防止することでこの構造を強制し、各人が孤立しているか、または 1 つの隣接関係の一部として一貫してカウントされるようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = []
    b = []
    base = 0

    for _ in range(n):
        ai, bi = map(int, input().split())
        a.append(ai)
        b.append(bi)
        base += bi

    if n == 1:
        print(base)
        return

    gain = [(a[i] - b[i]) + (a[i+1] - b[i+1]) for i in range(n - 1)]

    dp_prev2 = 0
    dp_prev1 = max(0, gain[0])

    for i in range(2, n):
        dp_cur = max(dp_prev1, dp_prev2 + gain[i - 1])
        dp_prev2, dp_prev1 = dp_prev1, dp_cur

    extra = dp_prev1
    print(base + extra)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```実装では、ソリューションがベースライン部分とゲイン最大化部分に分離されます。 ベースライン合計により、すべての人が分離された構成から開始できるようになります。 その後、DP は隣接関係の改善のみを処理します。 

配列ゲインは、考えられる各エッジを、その隣接関係をアクティブにする利点を表す単一の値に圧縮します。 ローリング DP 変数 dp_prev2 および dp_prev1 は、制約を考慮すると必要となる O(n) 配列の割り当てを回避します。 

微妙な点は、隣接関係が存在せず、DP 式が無効なインデックスにアクセスするため、n = 1 を個別に処理することです。

 | 1 | 1 | 100 | 100 | 1 | 1 |

 DP の進行:

 | 私 | dp_prev2 | dp_prev1 | 決定 | DP |

 追加ゲイン = 198、合計 = 103 + 198 = 301。 

このトレースは、利益の高い隣接エッジが孤立した選択肢をどのように支配しているかを示しています。

 ## 特殊なケース

 1 つのエッジ ケースは n = 1 です。隣接関係が存在せず、DP が完全にバイパスされるため、アルゴリズムはベースライン合計 bi を正しく返します。 

もう 1 つのエッジ ケースは、すべてのゲインが負の場合です。 その状況では、dp[i-2] + ゲインはスキップよりも常に悪いため、DP はエッジを選択しません。 出力は bi の合計のままであり、グループ化が有益ではないという解釈と一致します。 

最後のエッジケースは、高い値と低い値が交互に現れることであり、最適なペアリングは連続的ではなく選択的です。 DP はエッジが重ならないように強制するため、隣接関係の制約に違反することなく、より高い総ゲインが得られる場合には、自然に 1 つおきのエッジを選択します。
