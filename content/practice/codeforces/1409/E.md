 ## 解決策
 ## 問題の理解

 2D 平面上の一連の点が与えられ、それぞれに座標が与えられます。$(x_i, y_i)$、および固定長の 2 つの水平プラットフォーム$k$。 プラットフォームは、ラインに沿ってどこにでも配置できます。$x$-任意の軸$y$-座標ですが、水平を保つ必要があります。 ポイントが垂直に「落ちる」とき、プラットフォームに触れると止まります。 私たちの目標は、どちらかのプラットフォームによって停止されるポイントの数を最大化することです。 

入力により提供されるのは、$n$、ポイント数、および$k$、各プラットフォームの長さ。 次に、点の座標が続きます。 テスト ケースごとに、2 つのプラットフォームを最適に配置することで節約できるポイントの最大数を出力する必要があります。 

制約は厳しいです:$n$到達できる$2 \cdot 10^5$すべてのテストケースにわたって、$x_i$そして$y_i$と同じ大きさにすることができます$10^9$、そして私たちは最大まで持っています$2 \cdot 10^4$テストケース。 これは、単純なグリッド上で考えられるすべてのプラットフォーム配置を反復するソリューションは非常に遅すぎることを意味します。 ほぼ直線的にスケールするものが必要です。$O(n \log n)$テストケースごとに。 

明らかではないエッジケースには、複数のポイントが同じであるシナリオが含まれます。$x$- 座標、ポイントが広範囲に分散しているか、プラットフォームが多くのポイントをカバーできるような方法でポイントがクラスター化されていますが、最適なカバー範囲には両方のプラットフォームをオーバーラップする必要があります。 たとえば、次の場合$x = [1, 2, 10]$そして$k = 1$に 1 つのプラットフォームを配置します。$x=1$1 ポイントを獲得しますが、2 番目のプラットフォームは次の時点で遠く離れている必要があります。$x=10$最後のポイントを捉えるために。 連続した間隔を想定した不用意なアプローチは、ここでは失敗します。 

## アプローチ

 ブルートフォースアプローチでは、最初のプラットフォームのすべての可能な位置を試し、次にそれぞれについて 2 番目のプラットフォームのすべての位置を反復してポイントをカウントします。 だけを使って位置を離散化しても、$x$- 点の座標。この結果は次のようになります。$O(n^2)$テスト ケースごとの操作。これは受け入れられません。$n \sim 2 \cdot 10^5$。 

重要な洞察は、ある点で開始または終了しない場所にプラットフォームを移動してもカバレッジを拡大できないため、プラットフォームを既存のポイントに合わせるだけでよいということです。 したがって、問題は 2 つの長さの区間を見つけることになります。$k$に沿って$x$- 最大数のポイントを集合的にカバーする軸。 ポイントを並べ替え、2 ポインターまたはスライディング ウィンドウ アプローチを適用すると、1 つの区間の最大カバレッジを効率的に計算し、この情報を組み合わせて 2 つの区間を処理できます。 

この問題構造により、各位置で終了する 1 つの間隔でカバーされるポイントの最大数を事前計算し、右から左にスイープして 2 番目の間隔との最適な組み合わせを計算できます。 結果として生じる複雑さは、$O(n \log n)$ソートによりテストケースごとに実行されますが、これは十分に高速です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | スライディングウィンドウ / 2 つの間隔 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのポイントをその順に並べ替えます$x$-座標。 これにより、効率的な間隔計算が可能になります。 
2. 2 ポインター ウィンドウを初期化して、1 つの長さの区間でカバーされるポイントの最大数を計算します。$k$。 左ポインタごとに、次のように右ポインタをできるだけ遠くに移動します。$x_{\text{right}} - x_{\text{left}} \le k$。 各ポイントから始まる間隔でカバーされるポイントの数を保存します。 
3. 右端から配列を計算します。`max_from_right[i]`位置以降で始まる任意の間隔でカバーできるポイントの最大数を表します。`i`。 この配列により、第 1 間隔と第 2 間隔を最適に組み合わせることができます。 
4. 左から右にスイープします。 位置から始まる間隔について`i`、 使用`max_from_right[j]`どこ`j`厳密に現在の間隔の後の最初のポイントです。 現在の間隔のポイントの合計と`max_from_right[j]`が解決策の候補です。 
5. すべてのポジションの最大合計を追跡します。 その合計がテスト ケースの答えになります。 

機能する理由: このアルゴリズムは 2 つの不変条件を維持します。 まず、スライディング ウィンドウは、最大でも各長さの間隔内のすべてのポイントを正確にカウントします。$k$。 2番、`max_from_right`2 番目の間隔が最初の間隔に対して最適に配置されることを保証します。 最初の間隔のすべての開始位置を反復し、その右側にある可能な限り最良の 2 番目の間隔と組み合わせることで、重複を見逃すことなくすべての組み合わせを徹底的に検討します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        xs = list(map(int, input().split()))
        ys = list(map(int, input().split()))
        
        points = sorted(xs)
        n = len(points)
        
        # Sliding window: max points in one interval starting at i
        left = 0
        count = [0] * n
        for right in range(n):
            while points[right] - points[left] > k:
                left += 1
            count[left] = max(count[left], right - left + 1)
        
        # Compute max_from_right
        max_from_right = [0] * (n + 1)
        for i in range(n - 1, -1, -1):
            max_from_right[i] = max(max_from_right[i + 1], count[i])
        
        # Find maximum sum of two non-overlapping intervals
        ans = 0
        left = 0
        for right in range(n):
            while points[right] - points[left] > k:
                left += 1
            current = right - left + 1
            if right + 1 < n:
                current += max_from_right[right + 1]
            ans = max(ans, current)
        print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、$x$- 2 ポインターのスライディング ウィンドウを調整および使用して、各間隔がカバーできるポイントの数を計算します。 次に、2 番目のプラットフォームを効率的に処理するために、最適なカバレッジを右から左に伝播します。 最後のスイープでは、最初と 2 番目の間隔のすべての組み合わせが確実に考慮されます。 スライディング ウィンドウにより不必要な再計算が回避され、`max_from_right`最初の間隔のサイズとは無関係に 2 番目の間隔を最大化します。
